FHIR-50605: Align DetectedIssue medicationClass comment

Issue request:
FHIR-50605 was an Applied/Persuasive CDS change request for R6 asking to add DetectedIssue.medicationClass as an optional 0..* CodeableConcept representing the medication class responsible for the detected issue. The approved resolution also requested comment text giving duplicate therapy class alert and allergy class alert examples.

Initial application:
The issue was initially applied by HL7/fhir PR #3864, merged as 31c3058e643ebd3eb5598a427ec64c0c482e9f38, with implementation commit 137b3650abab5916cd74dc32adcacbfaba7bfd41 adding DetectedIssue.medicationClass plus the example CodeSystem and ValueSet. The element is present in the active DetectedIssue resource, but the applied comment said "duplicate therapy or an alergy alert," which both misspelled allergy and broadened the approved duplicate-therapy-class example.

Additional context:
source/fhir.ini actively includes detectedissue=DetectedIssue and assigns detectedissue to CDS, so source/detectedissue/structuredefinition-DetectedIssue.xml is in current build scope. CDS meeting minutes for 2025-06-25 record the motion to approve the proposed resolution. Targeted Zulip searches found no conflicting community discussion. A later Triaged issue, FHIR-55063, discusses possible THO migration for DetectedIssue terminology but does not finally require moving the experimental medicationClass example terminology and is not decided here.

AutoFHIR reconciliation:
This commit updates only the DetectedIssue.medicationClass comment to match the voted Jira resolution: duplicate therapy class alert or allergy class alert, with both medications belonging to the medication class. The element cardinality, type, definition, and example binding already matched the issue and were left unchanged.

Keep this commit as-is. It completes the narrow FHIR-50605 reconciliation in current FHIR core source; revisit only if FHIR-55063 or another later final terminology decision changes where the example medication class CodeSystem/ValueSet should live.
