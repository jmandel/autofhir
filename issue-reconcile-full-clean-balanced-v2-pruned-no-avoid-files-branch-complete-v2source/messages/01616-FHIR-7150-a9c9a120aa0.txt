FHIR-7150: Align component absent-reason guidance

Issue request:
FHIR-7150 was Published with a Persuasive with Modification resolution for DSTU1. It objected to using "test not done" as an Observation result value and requested guidance that cancelled or not-performed tests should use Observation.status="cancelled" with the specific detail represented as a coded value or dataAbsentReason, with an example such as a provider cancellation or unsatisfactory specimen.

Initial application:
The issue was substantially applied by historical commits 61688c8b3e7 and a63c54dd45, which added cancelled/not-performed Observation notes, replaced the top-level dataAbsentReason example value with "specimen unsatisfactory", registered a specimen reject example, and added source/observation/observation-example-unsat.xml. Later source refactors carried the top-level Observation.dataAbsentReason wording and example forward into source/observation/structuredefinition-Observation.xml.

Additional context:
Observation is active in source/fhir.ini, so source/observation/structuredefinition-Observation.xml and source/observation/observation-notes.xml are current build inputs. The current Observation notes already contain the requested cancelled/not-performed guidance and link to the specimen reject example. Later Applied issue FHIR-51640 extended that same note family for tests that will not or were not performed and added parallel DiagnosticReport and diagnostics-module text. While checking parallel Observation definitions, the component dataAbsentReason comment still carried the pre-FHIR-7150 "test not done" example and use-case-agreement sentence, unlike the already-correct top-level dataAbsentReason comment.

AutoFHIR reconciliation:
This commit updates only Observation.component.dataAbsentReason's comment in source/observation/structuredefinition-Observation.xml to match the corrected top-level dataAbsentReason guidance: the example is now "specimen unsatisfactory", the stale "test not done" result-value example is removed, and the alternate path explicitly refers to the component value element.

Recommendation:
Keep this source fix. It closes a remaining active-definition inconsistency from the FHIR-7150 change without changing cardinality, bindings, examples, or broader not-performed guidance; FHIR-51640 can be reconciled separately if an audit commit is desired for its later multi-page clarification.
