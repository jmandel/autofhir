FHIR-37858: Align date search parameter descriptions

Issue request:
FHIR-37858 was Published/Persuasive for R5. It asked to separate CanonicalResource.date from publication date semantics by defining it as the date the {{title}} was last significantly changed, to add comment guidance that date may be present before publication, and to add a publication-date mechanism for MetadataResource, including the artifact-publicationDate extension suggested in the Jira comment.

Initial application:
Git 378fe392dd102168828a322355a66656eff4d1bb changed CanonicalResource.date and the publishable pattern element definition/comment from publication-date wording to last-significant-change wording. Git 49b86f8a6978650d8f8a6d36d27dee0433e455bc retained that wording while adding localization guidance links and recorded Jira FHIR-37858, but the checked-in date search parameter sources still described {{name}}.date and implementing resources' date parameters as publication dates.

Additional context:
The 2022 FHIR-I minutes record the FHIR-37858 persuasive vote. The FHIR-37858 Zulip thread shows uncertainty over first versus last publication and whether a core MetadataResource.publicationDate interface element implied changes to all implementations, ending with a note that this part needed to go back to committee. A later Extension Pack decision, FHIR-51512, added the artifact-publicationDate extension with date datatype for any Metadata Resource and related resources. The core fhir.ini lists CanonicalResource and MetadataResource as active interfaces and maps MetadataResource.date to CanonicalResource.date; the edited search parameter bundle files are active checked-in search parameter sources for those date elements.

AutoFHIR reconciliation:
Updated the publishable search-parameter template and all checked-in date search parameter bundle descriptions that still called .date a publication date. The descriptions now identify the date search parameter as the last significant change date, matching the current CanonicalResource.date semantics. This commit intentionally does not add a core MetadataResource.publicationDate element because the community thread left that core-interface addition unresolved and the current publication-date mechanism lives in the FHIR Extension Pack.

Recommendation:
Keep this source fix. It removes the remaining core conformance-surface contradiction without reopening the separate question of a first/last publication date core element. If a work group still wants MetadataResource.publicationDate as a core element, that should be handled as a new committee decision alongside any implementation propagation rules; otherwise use the Extension Pack artifact-publicationDate extension.
