FHIR-31861: Clarify master-file search parameter

Issue request:
FHIR-31861 was Published with resolution Not Persuasive with Modification. The requester asked why MedicinalProduct masterFile was a DocumentReference rather than a registry-like Endpoint, and the BRR resolution said a master file in this context is an actual document, physical or electronic, so DocumentReference is correct and the text should make that clear.

Initial application:
The issue was initially applied in e640618988bdd140aaead008402a3a4d95a2b963, which updated MedicinalProductDefinition.masterFile to say that drug master files are documents submitted to regulatory agencies. The Jira comment later records "change applied". The active search-parameter bundle for MedicinalProductDefinition.masterFile still carried the older short description, including the pre-existing "for to" wording and no document clarification.

Additional context:
MedicinalProductDefinition is the active current-build resource in source/fhir.ini, replacing the older MedicinalProduct artifact mentioned by the R4-era Jira. FHIR-25195 introduced the master-file search parameter as a way to search the attached DocumentReference; it is useful background for why the search parameter exists but does not require a separate decision here. Jira, Zulip, and Confluence searches found no later or conflicting decision changing the FHIR-31861 interpretation.

AutoFHIR reconciliation:
Updated source/medicinalproductdefinition/bundle-MedicinalProductDefinition-search-params.xml so the MedicinalProductDefinition-master-file SearchParameter description now carries the same document/DMF clarification as the element definition. The DocumentReference target in the element definition was left unchanged because it already matches the published BRR decision.

Recommendation:
Keep this source fix as-is. No further core FHIR change is indicated for FHIR-31861 unless BRR later chooses to revise the masterFile modeling itself.
