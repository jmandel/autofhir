FHIR-39632: Point UsageContext bindings to THO

Issue request:
FHIR-39632 was an Applied/Persuasive CDS change request to remove duplicate CodeSystem definitions from the base FHIR specification for Evidence-related terminology already defined in THO, including certainty-rating, attribute-estimate-type, statistic-type, synthesis-type, and usage-context-type.

Initial application:
The main application happened before this reconciliation in caa1fb75adbcca96f92873c7d958e31f547124bb and the later PR 3468 merge 39d4fef037998a7441d5fd37f4faa0a3c6c6ddbe. Those commits removed the core Evidence CodeSystem/ValueSet source files that duplicated THO and rewired Evidence, ArtifactAssessment, and examples to THO terminology URLs, with follow-up commits restoring only build-needed artifacts outside this issue's requested CodeSystem move.

Additional context:
Community discussion before the Jira recorded that duplicated CodeSystems, including certainty-rating, synthesis-type, attribute-estimate-type, statistic-type, and usage-context-type, needed to be moved to or reconciled with THO. A later source commit for FHIR-45507 added source/datatypes/UsageContext-additional-bindings.xml after PR 3468 and used the old core CodeSystem URL http://hl7.org/fhir/usage-context-type in the conditional usage codings. UsageContext is an active metadatatypes datatype in source/fhir.ini, and FHIR-49931 later confirms that new usage-context-type codes are maintained in the THO CodeSystem.

AutoFHIR reconciliation:
This commit updates the UsageContext additional-binding source fragment so each UsageContext.code conditional coding uses http://terminology.hl7.org/CodeSystem/usage-context-type. Current source searches found no remaining active target CodeSystem definition resources for the FHIR-39632 CodeSystems; remaining Evidence and ArtifactAssessment bindings and examples already point at THO.

Recommendation:
Keep this commit as-is. It closes the only current source inconsistency found in the FHIR-39632 evidence trail without reintroducing core definitions or editing unrelated OID registry lines that do not define current CodeSystem resources.
