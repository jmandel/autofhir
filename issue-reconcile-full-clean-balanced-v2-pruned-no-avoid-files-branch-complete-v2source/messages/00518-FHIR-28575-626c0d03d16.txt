FHIR-28575: Fix patient-reported prescription example

Issue request:
FHIR-28575 was a Published Pharmacy change request, resolved Persuasive with Modification, asking for guidance on how to represent prescription information reported by a patient. The accepted resolution said to use MedicationRequest with intent=plan, reported=true, informationSource=Reference(Patient), and otherwise populate the request with the information the patient supplied; the work group also specifically asked for a patient-reported MedicationRequest example.

Initial application:
The issue appears to have been initially applied by commit bb4b0e41393b1023027fc45c9e53d5d941c95ff3, which added source/medicationrequest/medicationrequest0340.xml as the patient-reported prescription example. That application did not add the example to the MedicationRequest examples list/header, so the current built examples page does not link to it. The current MedicationRequest source is in build scope because source/fhir.ini lists medicationrequest as an active resource.

Additional context:
Later Applied issue FHIR-47855 clarified MedicationRequest.informationSource to say it is used when prescription details are reported by someone other than the requester and is normally paired with .isRecordOfRequest=true. Later issue FHIR-49863, currently Resolved - change required rather than Applied/Published, renamed MedicationRequest.reported to MedicationRequest.isRecordOfRequest; commit 847a0103fdb2abb340ba286ddbd765b5328a4cac updated the example's opening element but left the closing tag as </reported>, making the source XML invalid. The originating Zulip thread confirms the distinction between a patient reporting what was prescribed and MedicationStatement use for what the patient is taking.

AutoFHIR reconciliation:
This commit fixes the malformed patient-reported MedicationRequest example by using the current </isRecordOfRequest> closing tag, and adds the example to both the MedicationRequest examples List source and examples-page header so the requested example is discoverable from the built resource examples page.

Recommendation:
Keep this fix. It restores the example requested by FHIR-28575 without changing the later MedicationRequest semantics. Do not decide FHIR-49863 in this default run; its broader modifier/rename work remains outside the Applied/Published seed scope even though this commit repairs the stale example tag it introduced.
