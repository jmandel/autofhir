FHIR-27755: Align SearchParameter code search description

Issue request:
FHIR-27755 was Published/Persuasive with Modification for R5. It asked to clarify that CapabilityStatement.rest.resource.searchParam.name is the URL search-parameter label used by a particular system, SHOULD usually match SearchParameter.code, may differ for disambiguation, and has no correspondence to SearchParameter.name. It also requested matching SearchParameter.code and SearchParameter page wording.

Initial application:
Git 6df2ea0b1c457cb097cb9ea324fad912356a0d2f applied the main source changes to CapabilityStatement.rest.resource.searchParam.name, SearchParameter.code, and the SearchParameter introduction. Current source still contains those requested definitions. The remaining incomplete application was that source/searchparameter/bundle-SearchParameter-search-params.xml, an active checked-in search-parameter bundle for the SearchParameter resource, still described SearchParameter-code as "Code used in URL".

Additional context:
The originating Zulip thread confirms the intent: CapabilityStatement.rest.resource.searchParam.name is the query parameter string clients use, normally matching SearchParameter.code but allowed to differ when necessary. FHIR-I minutes on 2021-04-12 record the FHIR-27755 Persuasive with Modification vote. The analogous operation-name issue FHIR-34234 is already separately represented on the combined branch; later FHIR-46110 edits searchParam comments about true SearchParameters but does not alter this naming/code distinction.

AutoFHIR reconciliation:
Updated source/searchparameter/bundle-SearchParameter-search-params.xml so the SearchParameter-code search parameter description now says "Recommended name for parameter in search url", matching the current SearchParameter.code short description and removing the remaining active source occurrence of the old wording.

Recommendation:
Keep this source fix. It completes the already-approved clarification on the active SearchParameter conformance surface without changing the broader CapabilityStatement semantics.
