FHIR-16371: Mark vital signs profiles Trial Use

Issue request:
FHIR-16371 was Published with resolution Not Persuasive with Modification. It asked that normative Observation not require a non-normative Vital Signs profile until the profile became normative. The accepted decision kept the SHALL requirement, removed an obsolete note claiming approved profile changes were unapplied, and said the profile should remain non-normative with FMM 5.

Initial application:
No current git commit explicitly names FHIR-16371. The relevant historical source change appears in 2ebd7c6f7f, a July 2018 GForge batch that removed the stale STU note from the vital signs profile introduction while leaving the SHALL-conform requirement in place. The active source no longer contains that note.

Additional context:
Later applied issues FHIR-33145, FHIR-39446, and FHIR-39448 reaffirmed that the vital-signs profile page/profile set should be Trial Use rather than informative or normative while still carrying mandatory requirements. The active Observation resource is in source/fhir.ini, and source/observation/implementationguide-Observation-vitalsigns.xml is a core-use IG that references the Vital Signs base and specific profiles. A later QA commit, 9a5f0357ef, changed the vital-signs IG and all vital-signs StructureDefinition standards-status values from trial-use back to normative without a Jira key, causing the current drift from those decisions.

AutoFHIR reconciliation:
This commit changes only the standards-status metadata for the active Observation Vital Signs IG and the Vital Signs base/specific profile StructureDefinitions from normative to trial-use. It intentionally leaves the SHALL-conform prose and existing FMM values unchanged: the requirement was retained by FHIR-16371, and later FMM/profile maturity adjustments are outside this seed's proven scope.

Recommendation:
Keep this source fix. It restores the non-normative Trial Use status required by FHIR-16371 and later applied vital-signs page/status decisions without weakening the interoperability requirement that supported vital-sign observations conform to the applicable profiles.
