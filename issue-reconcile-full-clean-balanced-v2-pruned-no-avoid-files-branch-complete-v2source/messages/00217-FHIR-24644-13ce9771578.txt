Issue request:
FHIR-24644 was a Published/Persuasive InM change request for MessageDefinition, applied for R5, asking that MessageDefinition.url no longer read as a business identifier and that MessageDefinition.identifier no longer read as a server primary key. The requested replacement short descriptions were "url: The cannonical URL for a given MessageDefinition" and "identifier: Business Identifier for a given MessageDefinition".

Initial application:

That application left the URL short with the misspelling "cannonical", and later generated mapping-exception source preserved the same resource text.

Additional context:
MessageDefinition is active in the current build through source/fhir.ini resource, work group, maturity, and standards-status entries. The current source already has MessageDefinition.identifier.short as "Business Identifier for a given MessageDefinition", so there is no remaining identifier change for this issue. The URL and identifier full definitions were not changed because the Jira's old and new strings correspond to the short descriptions, and the broader differences from the Definition pattern are explicitly tracked in the MessageDefinition mapping-exception file. Confluence references show FHIR-24644 was discussed by InM and later cited as background for FHIR-31055, but no Zulip or Confluence search result changed the seed issue interpretation.
