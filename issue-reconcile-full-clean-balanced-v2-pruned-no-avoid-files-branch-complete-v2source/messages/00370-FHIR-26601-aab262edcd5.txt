FHIR-26601: Complete PaymentReconciliation patient-payment scope

Issue request:
FHIR-26601 was Published/Persuasive with Modification for R5 and asked to keep the PaymentReconciliation resource name while expanding the resource to cover patient payments. The approved change added payment source/workflow/payment-method elements, renamed paymentDate/paymentAmount/detail to date/amount/allocation, replaced allocation.request with allocation.target, made allocation.type optional, narrowed allocation.response to ClaimResponse, added allocation account/encounter search parameters, and requested descriptive text and examples for the expanded scope.

Initial application:
The issue appears to have been partially applied by untagged PaymentReconciliation source updates in August 2022, especially ffa7a1ee67 and 161b0f1ce1. Those commits added most structure changes, the payment issuer/kind terminology, patient and related-person payment issuers, account/encounter allocation search parameters, and example renames from detail/request to allocation/target. They left the current narrative focused on insurer/payor bulk payments, left PaymentReconciliation.allocation.target at 0..1 even though the approved request made it 1..1, and did not add the target search parameter requested by the allocation.request to allocation.target rename.

Additional context:
FHIR-15126 records a later no-change decision saying the R5 PaymentReconciliation changes from FHIR-26601 addressed payment posting needs. Zulip implementer discussion and PA minutes confirm FM was expanding PaymentReconciliation to cover patient payments and credit-card/online-payment use cases. FHIR-40279 later removed Person as a paymentIssuer choice but preserved Patient and RelatedPerson. FHIR-53869 is a later Triaged R6 request about additional capitation support and is not final enough to decide here. ChargeItem was removed from the current build in 71567db3ee, and Statement is not an active current resource, so this reconciliation does not re-add those historical target choices.

AutoFHIR reconciliation:
This commit updates current build-scope PaymentReconciliation source. It makes PaymentReconciliation.allocation.target 1..1, adds the PaymentReconciliation target search parameter for allocation.target while clarifying the existing request search parameter description, updates the Scope/Usage and Boundaries text to include insurer/payor and patient-collected payments, adds a patient-payment example, registers it in the resource example list, and gives the existing example's advance allocation an Account target so examples conform to the corrected target cardinality.

Recommendation:
Keep this commit as-is. It completes the remaining source-visible pieces of the published FHIR-26601 decision without reintroducing inactive ChargeItem/Statement references. If FM later wants capitation-specific subject/characteristics support, handle that under a final disposition of FHIR-53869 or a successor issue.
