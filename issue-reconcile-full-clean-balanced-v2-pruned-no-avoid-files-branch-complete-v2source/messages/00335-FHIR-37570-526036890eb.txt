FHIR-37570: Fix CanonicalResource context-reference search parameter

Issue request:
FHIR-37570 was a Published/Persuasive CDS change request to add a standard `context-reference` Reference search parameter for `Library.useContext.valueReference`, with the accepted resolution saying to define it generally on CanonicalResource and reflect it through canonical resources.

Initial application:
The issue was initially applied by git commit 2804a4350a363475f42bfa15540df04a84a4cd68, merged through HL7/fhir#2288, which added `CanonicalResource-context-reference` to `source/canonicalresource/bundle-CanonicalResource-search-params.xml`. The contemporaneous committers Zulip thread confirmed that defining the parameter on the CanonicalResource interface was intended to inherit to implementing canonical resources rather than requiring a separate Library-local entry. However, that source entry used a malformed standards-status extension URL, omitted the build path extension, and used the untyped choice expression `{{name}}.useContext.value`; current generated evidence showed the other CanonicalResource context parameters in `search-parameters.json` but not `context-reference`, while the CanonicalResource page displayed an empty path for it.

Additional context:
`source/fhir.ini` keeps CanonicalResource as an active interface resource and Library as an active concrete resource, so this source bundle is in the current build path and is the right scope for the issue. Later Jira FHIR-53850 records a broader R6 work-group decision to improve propagation of CanonicalResource search parameters for all resources where underlying elements exist; that broader Resolved - change required issue is related context but is not decided in this commit.

AutoFHIR reconciliation:
This commit repairs the issue-added CanonicalResource search parameter by correcting the standards-status extension URL, adding the build path `{{name}}.useContext.valueReference`, and narrowing the expression to `({{name}}.useContext.value.ofType(Reference))`. It intentionally does not duplicate the parameter in `source/library/bundle-Library-search-params.xml` because the accepted application path is CanonicalResource interface inheritance.

Recommendation:
Keep this source fix as the FHIR-37570 reconciliation. Handle the broader FHIR-53850 propagation audit separately if and when that R6 change-required issue enters the applied/published source-edit scope.
