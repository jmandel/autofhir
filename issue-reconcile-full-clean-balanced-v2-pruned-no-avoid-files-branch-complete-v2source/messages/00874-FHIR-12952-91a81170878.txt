FHIR-12952: Clarify ActivityDefinition version artifact wording

Issue request:
FHIR-12952 was Published/Persuasive for DSTU2 and asked that ActivityDefinition element definitions stop referring ambiguously to "assets" when they meant the specific activity definition resource.

Initial application:
The issue was applied at SVN 12593, now git commit febf675fdf9c598ca6efe1dcb2976ac9ad268f52, which changed the old ActivityDefinition and PlanDefinition spreadsheet wording for usage, jurisdiction requirements, contributor, relatedArtifact requirements, and library from asset/assets to activity definition/plan definition language. That application left the ActivityDefinition.version note saying a version is required for non-experimental active assets.

Additional context:
ActivityDefinition is an active current-build resource in source/fhir.ini. Later source refactors converted ActivityDefinition to structuredefinition-ActivityDefinition.xml and removed the old contributor element in favor of author/editor/reviewer/endorser. Current neighboring knowledge-artifact resources use "non-experimental active artifacts" for the same version note, while the broader "knowledge assets" DSS reference remains a term of art also used by peer resources. Jira, Zulip, and Confluence searches found no later contrary decision for FHIR-12952.

AutoFHIR reconciliation:
This commit changes the remaining stale ActivityDefinition.version phrase from "active assets" to "active artifacts" in the authoritative StructureDefinition source and the matching checked-in ActivityDefinition diagram title, preserving the rest of the version guidance.

Recommendation:
Keep this commit as-is. It finishes the narrow clarification requested by FHIR-12952 without changing conformance semantics beyond aligning the ActivityDefinition wording with the current canonical artifact terminology.
