FHIR-10254: Align AuditEvent model metadata names

Issue request:
FHIR-10254 was Published with a Persuasive resolution for DSTU2. It requested that AuditEvent value set and binding names follow the renamed AuditEvent.agent and AuditEvent.entity model, replacing old Participant/Object wording such as AuditEventObjectType with Agent/Entity terminology.

Initial application:
The issue was initially applied by commit 4624d8d894d087e492887dc4d59146e36907cb41, which changed the AuditEvent spreadsheet binding names and definitions from AuditEventParticipantNetworkType, AuditEventObjectType, AuditEventObjectRole, and AuditEventObjectLifecycle to the corresponding AuditEventAgent/Entity names. Current primary AuditEvent source already carries the entity wording in the remaining in-core value sets and StructureDefinition binding names. The active Library QUICK model-info example and source/bindings.ini registry still retained the old AuditEvent Participant/Object binding and element names.

Additional context:
source/fhir.ini keeps auditevent and library in the active build, source/library/list-Library-examples.xml lists the QUICK model-definition Library example, and publish.ini publishes source/library/library-quick-model-definition-content.xml directly. The FHIR model-definition Library content already uses AuditEvent.agent, AuditEvent.entity, and AuditEventAgentNetworkType, so the QUICK model-info file was inconsistent with the adjacent active model-definition surface. Later AuditEvent work removed AuditEvent.entity.type from core (FHIR-32467) and moved lifecycle to an extension now maintained in the Extension Pack (FHIR-32470), so this reconciliation updates the active metadata names without reintroducing removed core elements or changing extension-pack source. FHIR-32468 later changed AuditEvent.entity.role to an example binding and explicitly did not require value set content changes. Searches found no Zulip or Confluence discussion that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit updates source/library/library-quick-model-definition-content.xml so the active QUICK model-definition example exposes AuditEvent.agent, AuditEvent.entity, QUICK.AuditEvent.Agent, QUICK.AuditEvent.Entity, AuditEventAgentNetworkType, AuditEventEntityType, AuditEventEntityRole, and AuditEventEntityLifecycle instead of the obsolete participant/object names. It also updates source/bindings.ini registry entries for the AuditEvent binding names changed by the original application while preserving the unchanged legacy AuditEventObjectIdType entry that is not part of current AuditEvent source.

Recommendation:
Keep this commit as-is. It completes the Published FHIR-10254 application on the active Library model-definition and binding registry surfaces while preserving existing canonical terminology URLs such as ValueSet/object-role-example and CodeSystem/object-role, which remain DICOM-derived identifiers and were not renamed by the later value set binding decision.
