FHIR-45876: Clarify Medication.code can carry a name

Issue request:
FHIR-45876 was an Applied FHIR-core Pharmacy change request raised for R6 asking to add Medication.name because product names carried in Medication.code were not obvious and could differ from coding displays. The final Not Persuasive with Modification resolution rejected a new first-class name element and instead required Medication.code short text and definition text to state that code.text can convey the medication name.

Initial application:
The issue-tagged source commit bed717e6e72e62a6beeefc607a5ee938434a88ac updated source/medication/structuredefinition-Medication.xml to remove "if no code is available" from the definition and add the code.text medication-name sentence. It did not update the Medication.code short text, which remained "Codes that identify this medication".

Additional context:
Medication is an active resource in source/fhir.ini, so source/medication/structuredefinition-Medication.xml is in current build scope. Pharmacy WG January 2025 minutes mirror the Jira discussion and record the 8-0-0 vote for the same short-description adjustment. Broader Jira/Zulip/Confluence searches found no later final core decision that reverses the chosen code.text approach.

AutoFHIR reconciliation:
This commit updates the Medication.code short text to "Code and/or name that identifies this medication", completing the approved source change while leaving the already-applied definition text unchanged.

Recommendation:
Keep this commit as-is. It is a narrow source-scope completion of an Applied R6 clarification and does not add Medication.name or change product-pattern structure.
