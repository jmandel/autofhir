FHIR-43088: Fix MeasureReport countQuantity reconciliation

Issue request:
FHIR-43088 was Applied/Persuasive for R6 MeasureReport. It asked CQI to support decimal-valued population counts by adding MeasureReport.group.population.countQuantity and MeasureReport.group.stratifier.stratum.population.countQuantity, adding a count/countQuantity invariant, adding a temporary trial-use ballot note about the backwards-compatible option, and adding a patient-level linear-combination composite example. Later Jira comments clarified that the invariant should make count and countQuantity mutually exclusive, not require equality.

Initial application:
The issue was partially applied before this reconciliation. Commit 3446e427f6 added both countQuantity elements and the temporary trial-use ballot note; commit f07af5959c added mrp-3/mrp-4 constraints; commit bb4c4fbda7 added invariant-test files. The active current source retained the countQuantity elements, and later FHIR-50702 work removed the temporary option ballot note. However, the constraints used count.exists() xor countQuantity.exists(), which also rejects populations with neither optional count element present, the invariant tests misspelled countQuantity and used non-FHIR XML for count, and no countQuantity example was present in the MeasureReport examples list.

Additional context:
FHIR-41226 is the background FHIR-us-qm issue that supplied the patient-level linear-combination composite use case with a decimal numerator count. Later R6 ballot dispositions FHIR-50273, FHIR-50563, and FHIR-50702 confirmed CQI's decision to keep option 2: a new countQuantity element rather than changing count itself to Quantity. FHIR-50702 is already represented on the combined branch by an empty audit commit and is not re-decided here.

AutoFHIR reconciliation:
This commit fixes the authoritative MeasureReport StructureDefinition constraints to express true mutual exclusion with count.empty() or countQuantity.empty(), corrects the stratum invariant typo, repairs the mrp-3/mrp-4 failing invariant tests so they actually contain both count and countQuantity, adds passing invariant tests for countQuantity-only and neither-count cases, and adds a MeasureReport example/list entry showing a patient-level linear-combination composite report with decimal-valued countQuantity populations.

Recommendation:
Keep this source fix. It completes the FHIR-43088 application while preserving the later option-2 decision; no further core source change is recommended unless CQI later chooses a breaking change to generalize count itself.
