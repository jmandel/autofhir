FHIR-40300: Align DeviceMetric device search URL

Issue request:
FHIR-40300 was Published with resolution Persuasive with Modification for R5. The final decision changed the original request to make DeviceMetric.source and DeviceMetric.parent required: remove DeviceMetric.source, rename DeviceMetric.parent to DeviceMetric.device, make the renamed element 1..1, and update the short description and definition.

Initial application:
No git commit explicitly mentioning FHIR-40300 was found. The practical application appears in git commit 9a661e74e3fc31b1a0e5e8f0f41312d475646362, whose message says FHIR-39322 but whose body changes the DeviceMetric structure definition and search parameters to remove source and change parent to device 1..1. Current source now has DeviceMetric.device at 1..1 and no DeviceMetric.source or DeviceMetric.parent element. Later FHIR-51443 language cleanup further refined the current DeviceMetric.device short display, definition, and comment.

Additional context:
DeviceMetric is an active core resource in source/fhir.ini, and the search-parameter bundle under source/devicemetric feeds the current resource search parameters. Zulip and Confluence evidence around February-March 2023 confirms the WG was discussing removal of DeviceMetric.source and migration to DeviceMetric.device. The current search parameter had already been renamed in id, code, path, and expression, but the canonical build URL still ended in DeviceMetric-parent, leaving one stale source location from the parent-to-device rename.

AutoFHIR reconciliation:
Updated source/devicemetric/bundle-DeviceMetric-search-params.xml so the DeviceMetric device search parameter URL is http://hl7.org/fhir/build/SearchParameter/DeviceMetric-device, matching its id, code, path, expression, and the applied FHIR-40300 rename. No other DeviceMetric source changes were made because the resource element itself and later R6 wording are already aligned with the Jira decision.

Recommendation:
Keep this source fix as-is. Do not separately reconcile the related historical issues here: FHIR-25240 and FHIR-39332 are background to the parent/source discussion, FHIR-39322 was a broader resource-boundary issue whose commit appears to have carried this implementation work, and FHIR-51443 is a later applied wording cleanup already reflected in the current source.
