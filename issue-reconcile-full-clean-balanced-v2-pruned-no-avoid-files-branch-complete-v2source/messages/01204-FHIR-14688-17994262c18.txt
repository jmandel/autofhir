FHIR-14688: Clarify ValueSet expansion code version short

Issue request:
FHIR-14688 was Published with resolution Persuasive with Modification. It asked whether ValueSet.expansion.contains.version should be 0..* because the existing wording, "Version in which this code/display is defined", was unclear about whether the version was the first code-system version, any version, or multiple versions.

Initial application:
The issue was applied in git-svn commit 40be6cb27713195324b576ca019afbea271aed52 / SVN revision 14638 by changing the ValueSet spreadsheet definition to the approved Coding.version-derived text while leaving the short description unchanged. The current StructureDefinition source already retained max=1 and the approved detailed definition.

Additional context:
ValueSet is an active current-build resource in source/fhir.ini and is owned by the vocabulary work group. Earlier related issues FHIR-3535 and FHIR-13810 established the optional expansion.contains.version element and conditional version-reporting guidance; neither supports changing the current cardinality to 0..*. Confluence Vocab minutes record the 2018-07-12 Persuasive with Modification ballot disposition and 15-0-1 vote for this block.

AutoFHIR reconciliation:
Updated source/valueset/structuredefinition-ValueSet.xml so ValueSet.expansion.contains.version.short now says "Code system version used for this code". This keeps the approved 0..1 cardinality and detailed definition intact while removing the stale short wording that repeated the original ambiguity.

Recommendation:
Keep this commit. It is a narrow current-build source clarification that completes the published issue without changing the element cardinality or the approved normative definition.
