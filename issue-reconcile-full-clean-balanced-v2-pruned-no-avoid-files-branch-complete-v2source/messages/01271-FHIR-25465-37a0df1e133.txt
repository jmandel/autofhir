FHIR-25465: Clarify notification response wording

Issue request:
FHIR-25465 was Published as Persuasive with Modification for the FHIR-core messaging page. It asked to change the Message Exchange Patterns text so request messages only typically have response messages and to clarify that some notification scenarios may be satisfied by a bare HTTP response, with the accepted modification naming an HTTP response such as 200 possibly accompanied by an OperationOutcome.

Initial application:
Commit 6fc70e07455baeec9c2f599e9d1d1dc03edd308c applied the main messaging-page change in source/messaging.html by replacing the absolute one-or-more response-message requirement with typical response-message wording. That application also added the notification HTTP/OperationOutcome sentence, but it omitted the accepted "e.g. 200" example and left the sentence grammatically unclear as "it reasonable to only expect either only an http response".

Additional context:
The messaging page is active current-build narrative through source/hierarchy.xml. Later response-message decisions, including FHIR-40518 and FHIR-27544, moved the surrounding messaging model further toward zero-or-more message responses while preserving the same core distinction established by FHIR-25465 and FHIR-25252: an HTTP-level acknowledgement can be enough when no message Bundle payload is needed. No direct Zulip discussion for FHIR-25465 was found; the FHIR-I minutes and later Zulip response-message discussion support the same interpretation.

AutoFHIR reconciliation:
This commit updates the active messaging-page notification sentence to say it is reasonable to expect only an HTTP response (e.g. 200), possibly accompanied by an OperationOutcome. The change preserves the existing response-message rules and only fixes the remaining divergence from the accepted FHIR-25465 wording.

Recommendation:
Keep this commit as a narrow source fix. It aligns the current messaging narrative with the published Jira disposition and does not require additional changes to the later zero-or-more response-message wording.
