FHIR-41524: Complete communication language definition fix

Issue request:
FHIR-41524 was Applied/Persuasive with Modification for the PA work group. It requested updating the communication language definition/comment for Patient, Person, Practitioner, RelatedPerson, and PractitionerRole so the spec no longer implies only ISO-639-1 alpha-2 language codes are allowed when the binding supports broader IETF/BCP-47 language tags, including sign-language tags.

Initial application:
Commit f818fedafb4a0c3f32d1ac80ce251ad583425279 applied the Jira wording to Patient.communication.language, Person.communication.language, Practitioner.communication.language, and RelatedPerson.communication.language. It did not update PractitionerRole because the current resource has a direct PractitionerRole.communication CodeableConcept rather than a PractitionerRole.communication.language child, and it left the active ParticipantLiving logical pattern plus checked-in mapping/diagram support files with the old alpha-2 wording.

Additional context:
source/fhir.ini lists Patient, Person, Practitioner, PractitionerRole, and RelatedPerson as active resources and lists participantliving as an active logical pattern. The Zulip origin thread and PA stream confirm the problem was that the old definition conflicted with the all-languages/BCP-47 binding and incorrectly suggested sign-language codes were unavailable. The PA R6 updates thread also records the implementer's observation that PractitionerRole does not have the same nested communication.language shape, which explains why the source fix has to land on PractitionerRole.communication instead.

AutoFHIR reconciliation:
Updated PractitionerRole.communication's comment to use the approved broader language-tag wording while preserving its role-specific guidance. Updated the active ParticipantLiving.communication pattern definition/comment and the Patient/RelatedPerson mapping-exception expectations that reference that pattern. Updated the checked-in Patient and RelatedPerson SVG titles so their diagram tooltips no longer display the obsolete alpha-2-only definition; these SVG edits accompany the authoritative XML/spreadsheet source fixes.

Recommendation:
Keep this commit as-is. It completes the applied Jira decision in active build inputs without changing unrelated language preference semantics; a future full publication build may regenerate equivalent diagram output from the corrected source.
