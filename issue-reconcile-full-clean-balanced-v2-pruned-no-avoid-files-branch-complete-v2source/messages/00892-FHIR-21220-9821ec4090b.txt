FHIR-21220: Remove stale Contributor model metadata

Issue request:
FHIR-21220 was an Applied/Not Persuasive with Modification FHIR-I request to add publisher to the contributor type value set. The approved resolution rejected the new role because metadata resources already have publisher and stated that the Contributor metadata type was being removed.

Initial application:
Commit 606d18ae40 removed the Contributor datatype from the metadata types page and related documentation. Later commit 03893addeb fully removed source/datatypes/contributor.xml and the active fhir.ini datatype/status/flag registrations, but the current source still exposed Contributor and ContributorType through the FHIR ModelInfo and FHIRHelpers library surfaces and retained two stale fhir.ini page/workgroup mappings.

Additional context:
FHIR-10684 is the earlier change family that split Contributor into explicit author/editor/reviewer/endorser ContactDetail elements. Current active metadata and knowledge-artifact StructureDefinitions no longer define Contributor, and publish.ini explicitly publishes source/library/library-fhir-model-definition-content.xml, so leaving Contributor in ModelInfo would continue to advertise a removed type. Out-of-build historical surfaces such as ServiceDefinition and OID reservations were not changed.

AutoFHIR reconciliation:
Removed Contributor from the FHIR ModelInfo choice lists, removed the Contributor and ContributorType class infos and ContributorType conversion metadata, removed the matching FHIRHelpers ToString overload, refreshed the embedded Library payloads for those two library resources, and removed stale fhir.ini contributor page/workgroup mappings.

Recommendation:
Keep this source fix. If the model-info files are regenerated by tooling later, regenerate from the current definitions and confirm Contributor does not reappear.
