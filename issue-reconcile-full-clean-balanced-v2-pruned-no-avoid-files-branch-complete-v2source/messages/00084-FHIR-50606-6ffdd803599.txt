FHIR-50606: Include processing-error in DetectedIssue status ValueSet

Issue request:
FHIR-50606 is an Applied/Persuasive CDS change request for R6 asking to add a Detected Issue Status value "processing-error", defined as an error occurring in evaluation of the proposed action and distinct from unknown or entered-in-error.

Initial application:
The issue was partially applied by git commit 905e7a8ef4133ee52222a28eb35fb061cf9e0599 from PR 3809, which added the CodeSystem concept and updated DetectedIssue.status short/comment text. A follow-up QA commit 46a47e604d2492e8e74a315907263b2fe2590667 updated the Event mapping exception. The ValueSet compose, however, still included only "mitigated" from http://hl7.org/fhir/detectedissue-status, so the required DetectedIssue.status binding did not actually permit processing-error.

Additional context:
DetectedIssue is an active current-build resource in source/fhir.ini. The CodeSystem already defines processing-error and the StructureDefinition already describes it, but the ValueSet is a restricted compose that enumerates concepts from both ObservationStatus and detectedissue-status, so adding the CodeSystem code alone was insufficient. Jira, Zulip, and Confluence searches found no related final decision or community discussion that changes the Applied request.

AutoFHIR reconciliation:
This commit adds processing-error to source/detectedissue/valueset-detectedissue-status.xml under the existing detectedissue-status include, matching the existing CodeSystem display and making the required ValueSet binding include the applied code.

Recommendation:
Keep this source change. It completes the Applied issue in the authoritative current-build terminology source; no further core follow-up was identified beyond the ordinary generated artifact refresh performed by the build.
