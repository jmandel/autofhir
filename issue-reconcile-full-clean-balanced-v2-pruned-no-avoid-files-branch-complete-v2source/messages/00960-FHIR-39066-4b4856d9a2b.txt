FHIR-39066: Remove SupplyRequest from workflow combine question

Issue request:
FHIR-39066 was a Published/Persuasive with Modification R5 Orders and Observations change request for SupplyRequest. It asked to keep SupplyRequest and DeviceRequest separate and remove the SupplyRequest ballot comment requesting input on whether they should be combined, because SupplyRequest is logistics/inventory while DeviceRequest is clinical/patient-specific device use.

Initial application:
The issue was explicitly applied in commit f87697e57c2a24078879a665e23995a4d6ec73b0, which removed the SupplyRequest page ballot-note item asking whether to combine SupplyRequest and DeviceRequest. Later source work also added SupplyRequest narrative clarifying logistics-only use, inventory management, and patient-focused requests going to DeviceRequest or MedicationRequest.

Additional context:
SupplyRequest has since moved out of the active core resource build: current source/fhir.ini has no active supplyrequest resource entry, and later source history redirects core links to the HL7 OO Incubator SupplyRequest. The OO Incubator SupplyRequest page content also lacks the removed combination note and includes the logistics/inventory boundary text. However, current active core source/workflow.html still carried an Open Issues item saying SupplyRequest, DeviceRequest, and VisionPrescription overlap and asking whether they should remain distinct resources. That active workflow note conflicted with the final FHIR-39066 decision for the SupplyRequest/DeviceRequest portion, while the separate DeviceRequest/VisionPrescription question is covered by other issue history.

AutoFHIR reconciliation:
This commit removes SupplyRequest from the active workflow Open Issues distinct-resources question, leaving the existing DeviceRequest/VisionPrescription wording intact. It intentionally makes no edit to source/supplyrequest because that retained local SupplyRequest source is no longer an active core build input and already lacks the removed ballot note.

Recommendation:
Keep this source change. It resolves the remaining current-core contradiction for FHIR-39066 without deciding the separate DeviceRequest/VisionPrescription overlap topic or dormant/external SupplyRequest source ownership questions.
