FHIR-32975: Correct ResearchStudy TitleType code

Issue request:
FHIR-32975 was Published with a Persuasive with Modification resolution for R5. It asked to change Citation.citedArtifact.title.type from 0..1 to 0..* and to replace the shared TitleType code system/value set with the approved code list, using duplicate-uid instead of duplicate-pmid.

Initial application:
The issue was explicitly applied in commit 962e0153096274c9ebbb137280dfe78a3bb9a07b, which changed Citation.citedArtifact.title.type to 0..* and replaced the Citation-owned TitleType codes. ResearchStudy was coupled to the same terminology by FHIR-32312 in commit 0f18a0191c450d2a3bdef6286d38f786cdefed61, but its element short text carried the non-approved spelling auto-translated while the approved TitleType code is autotranslated.

Additional context:
Citation has since been removed from the current core build, so there is no current core Citation source to edit for the cardinality half of the issue. The TitleType code system/value set is now owned at terminology.hl7.org, and the current THO CodeSystem still contains the FHIR-32975 code set, including autotranslated and duplicate-uid. ResearchStudy remains active in source/fhir.ini and still binds ResearchStudy.label.type to http://terminology.hl7.org/ValueSet/title-type, so its visible short code list is current build-scope source and should not advertise a non-existent code.

AutoFHIR reconciliation:
This commit updates source/researchstudy/structuredefinition-ResearchStudy.xml so ResearchStudy.label.type lists autotranslated, matching the approved/current TitleType code. It intentionally does not recreate Citation or core TitleType terminology files because Citation is out of the current core build and TitleType's source of truth is THO.

Recommendation:
Keep this source fix as-is. If future TitleType definitions need changes, handle them in the terminology source of truth; do not restore retired core Citation terminology files unless the work group re-adds Citation to core.
