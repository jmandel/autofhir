FHIR-35863: Correct EpisodeOfCare diagnosis example

Issue request:
FHIR-35863 is a Published/Persuasive PA R5 change request asking EpisodeOfCare.reason and EpisodeOfCare.diagnosis to be harmonized with the updated Encounter structure approved through FHIR-16148. The final resolution required the new EpisodeOfCare reason backbone, the diagnosis backbone with CodeableReference Condition, removal of the old diagnosis rank/role shape, and use of the updated diagnosis-use terminology instead of the old diagnosis-role value set.

Initial application:
The issue appears to have been applied upstream by commit 084c723e14093f9463b52edae50c08bfd1194da5, merged in PR #2650 as 3ac1ab47ddeb0af54d88da1547d572e399f3956f. That commit added EpisodeOfCare.reason, changed EpisodeOfCare.diagnosis.condition to 0..* CodeableReference(Condition), renamed EpisodeOfCare.diagnosis.role to EpisodeOfCare.diagnosis.use, removed EpisodeOfCare.diagnosis.rank, and bound diagnosis.use to http://hl7.org/fhir/ValueSet/encounter-diagnosis-use. It also renamed the active example's diagnosis.role element to diagnosis.use, but left the coding as the old diagnosis-role#CC Chief complaint code.

Additional context:
FHIR-16148 is the matching Encounter decision that split expected reasons from medical conditions addressed during the encounter. Later FHIR-38784 and FHIR-48869 changed the related use cardinalities to repeat, and those applied decisions are already reflected in current EpisodeOfCare source. FHIR-38807 is already represented on the combined branch and corrected Encounter prose while treating FHIR-35863 as same-change-family context. source/fhir.ini actively lists EpisodeOfCare, and source/episodeofcare/list-EpisodeOfCare-examples.xml actively references EpisodeOfCare/example, so the checked example is build-scoped source rather than stale generated output. PA minutes show FHIR-35863 was discussed in May 2022 and voted Persuasive on 2022-07-20.

AutoFHIR reconciliation:
This commit updates the active EpisodeOfCare example so EpisodeOfCare.diagnosis.use uses the current EncounterDiagnosisUse code system with code working. It intentionally leaves the EpisodeOfCare StructureDefinition unchanged because the authoritative current source already contains the requested diagnosis backbone, condition cardinality/type, diagnosis.use binding, and later repeating use cardinality.

Recommendation:
Keep this source fix. Future work should not reintroduce the old diagnosis-role Chief Complaint coding under EpisodeOfCare.diagnosis.use; if the example is expanded to demonstrate chief-complaint semantics, that should be represented through EpisodeOfCare.reason.use instead of diagnosis.use.
