Issue request:
FHIR-27754 is a Published/Persuasive MnM technical correction raised against the R4 ContactPoint integrated example and applied for R5. It asks that the ContactPoint iso21090-TEL-address example use valueUrl instead of valueUri.

Initial application:

The next-day RatioRange edit b9fd58139d35c8aa90083ae99a279c8a6d3dd854 restored valueUri in the same source file, and later commit e9e4e5f34c8d0b40d680c26f92acfa19b5f714a6 added the JSON ContactPoint example with valueUri, so the current source again had the stale value type in both serializations.

Additional context:
The MnM 2020-09-01 minutes list FHIR-27754 as a technical correction. In core, source/fhir.ini keeps ContactPoint in the active datatype list and routes datatype pages through the datatypes page set, and source/datatypes-examples.html is the active Datatype Examples source page linked from the datatype pages.

AutoFHIR reconciliation:
Updated source/datatypes-examples.html so the ContactPoint iso21090-TEL-address XML and JSON examples both use valueUrl. No extension-pack edit was needed because the extension definition already has the correct url value type.

Recommendation:
Keep this source correction as-is. Future extension-pack syncs should preserve valueUrl in the core example unless the extension's value type is formally changed.
