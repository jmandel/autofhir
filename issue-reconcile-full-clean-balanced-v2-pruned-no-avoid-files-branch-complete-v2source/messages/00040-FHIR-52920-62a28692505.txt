FHIR-52920: Clarify Composition cmp-3 section warning

Issue request:
FHIR-52920 was Applied/Persuasive with Modification for R6 by Structured Documents. It requested a warning invariant on Composition.section so sections should contain section.text unless they consist only of sub-sections, narrowed by resolution to apply when Composition.attester exists using text.exists() or section.exists().

Initial application:
Commit 160c286be6 initially added cmp-3 at the Composition root with an attester.empty() expression, and 0cb437f657 added pass/fail invariant fixtures. After Benjamin Flessner noted that the invariant needed the %resource.attester prefix and belonged on Composition.section, commit 1c94be2020 moved cmp-3 to Composition.section and changed the expression to %resource.attester.exists() implies(text.exists() or section.exists()). The remaining problem was that the human-readable warning still described the old root-level interpretation: the Composition needing text or a section.

Additional context:
source/fhir.ini lists Composition as an active resource, so source/composition/structuredefinition-Composition.xml feeds the current build. The current source already has cmp-3 as a warning on Composition.section, includes condition references on Composition.attester and Composition.section, and has cmp-3 invariant fixtures. A Jira neighborhood check found FHIR-50934 about signature canonicalization and excluding Narrative elements such as Composition.section.text, but that separate Applied issue does not change the section-level warning requested by FHIR-52920. Zulip and Confluence searches for FHIR-52920 and the Composition section/attester terms found no conflicting community evidence.

AutoFHIR reconciliation:
This commit changes only the cmp-3 human text in source/composition/structuredefinition-Composition.xml so the displayed warning now says that, when the Composition has attesters, each section should contain text or sub-sections. It preserves the already-correct FHIRPath expression, severity, placement on Composition.section, and invariant fixtures.

Recommendation:
Keep this commit as-is. It completes the FHIR-52920 application by aligning the implementer-facing warning text with the approved section-level rule without changing the intended warning semantics.
