FHIR-46492: Align Subscription filter references

Attribution note: surfaced while reviewing FHIR-39033, but direct Jira backing for this change is FHIR-46492.

Issue request:
FHIR-39033 was Published/Persuasive with Modification for R5. It asked whether Subscription.filterBy.resourceType was redundant with the resource on the matching SubscriptionTopic filter, and the work group decided to retain the filter resource discriminator because subscriptions can trigger on multiple resource types and some filters apply only to selected resources.

Initial application:
The issue was applied by c7be29dba236b8d76eba270510768fc0095a3313, which added multi-resource topic guidance to the Subscriptions Framework page plus links/guidance on the Subscription and SubscriptionTopic resource pages. That application preserved the discriminator and explained server behavior when it is omitted.

Additional context:
FHIR-41197 later renamed Subscription.filterBy.resourceType to Subscription.filterBy.resource, and that reconciliation is already represented on the combined branch. FHIR-46492 later collapsed SubscriptionTopic resourceTrigger and eventTrigger into trigger and moved canFilterBy under trigger. Current source otherwise has the FHIR-39033 framework and resource-page guidance in active build inputs, but the authoritative Subscription.filterBy element definitions still pointed to the old pre-FHIR-46492 SubscriptionTopic.canFilterBy paths.

AutoFHIR reconciliation:
This commit updates the active Subscription StructureDefinition definitions for Subscription.filterBy.resource and Subscription.filterBy.filterParameter so they reference SubscriptionTopic.trigger.canFilterBy.resource and SubscriptionTopic.trigger.canFilterBy.filterParameter. The change keeps the FHIR-39033 semantics intact while aligning the cross-references with the current SubscriptionTopic model.

Recommendation:
Keep this commit as-is. It is a narrow current-source correction to preserve the published FHIR-39033 guidance after later SubscriptionTopic refactoring; no additional core source change is indicated for this issue.
