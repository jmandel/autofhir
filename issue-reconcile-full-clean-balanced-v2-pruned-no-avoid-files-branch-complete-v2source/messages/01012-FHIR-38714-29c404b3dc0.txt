FHIR-38714: Correct markdown tag escaping guidance

Issue request:
FHIR-38714 was a Published FHIR-core datatype issue, resolved Persuasive with Modification for R5, asking the markdown datatype definition to clarify that FHIR markdown is based on CommonMark/GFM while disallowing inline raw HTML so embedded tags cannot influence rendering.

Initial application:
The issue was applied in source by commit f4a553b24dfdf2d497cb6f526867c90dcb7bfbd1, which updated source/datatypes.html to say that inline HTML is not supported and that processors SHALL treat embedded XML tags as string content. That application accidentally used the greater-than character in the escaping example, even though the Jira resolution and tag syntax require escaping less-than characters.

Additional context:
source/fhir.ini routes datatypes through the active datatypes page, so source/datatypes.html is in the current build scope for the markdown datatype. The linked Zulip thread and FHIR-I minutes confirm that this issue was about the markdown datatype in resource content, not .md page files, and that processors should handle embedded XML/HTML-like tags as text. Later Published markdown issues FHIR-40387 and FHIR-40555 added safety guidance about escaping plain strings and string-to-markdown conversion without reversing the no-inline-HTML decision.

AutoFHIR reconciliation:
This commit corrects the processor guidance in source/datatypes.html so the example says to escape "<" as "\<" before markdown processing. Escaping ">" does not prevent tag-like content from being parsed as an HTML/XML tag, so the prior text was semantically inconsistent with the WG decision.

Recommendation:
Keep this source fix as-is. The broader markdown datatype text already conveys the intended CommonMark/GFM-without-inline-HTML rule, and no further FHIR-core source change is needed for FHIR-38714 beyond correcting the escaping character.
