FHIR-7788: Clarify IG artifact authority

Issue request:
FHIR-7788 was Published with a Persuasive with Modification resolution for the DSTU1 question of what constitutes the normative description of a profile or implementation guide. The resolution said that all representation forms are equally normative and that the set of files is defined by the publication form of the implementation guide, with the specification to be updated to clearly state the first point.

Initial application:
The issue was initially applied in svn revision 6819, now git commit 36ec73fea49b49d1b4007a8ecdc79cc1752e3754, by adding text to source/iglist.html saying that implementation guides include representations generated from conformance resources and that all representation forms are equally normative. Lloyd's later QA commit 35568981225e4cb9d74984a9f6af59b523bc3c6e retained the explicit "All the representation forms are equally normative" wording.

Additional context:
The old source/iglist.html page was deleted in 2017 by 8b16115d880b33726d98fd973da248d688742494. Current build scope has ImplementationGuide as an active resource in source/fhir.ini, and the current active narrative in source/implementationguide/implementationguide-notes.xml now describes implementation guides as FHIR packages containing computer-processible resources and human-readable documentation, including conformance expectations that are not directly testable. The package specification also says FHIR specifications are published as HTML for humans and NPM packages for machines, and describes implementation guide packages and composition. Later FHIR-18407 added the current human-readable narrative guidance, so the right place for the lost FHIR-7788 clarification is the current ImplementationGuide notes section, not the deleted IG list page.

AutoFHIR reconciliation:
This commit adds a focused paragraph to the active ImplementationGuide notes stating that the publication form defines which artifacts are part of an implementation guide, that multiple representation formats of the same definitional artifact are equally authoritative, and that examples remain illustrative unless the implementation guide explicitly says otherwise.

Recommendation:
Keep this source change. It restores the published FHIR-7788 rule in current build-scope source without reintroducing obsolete DSTU1 implementation-guide list wording or changing the current package-based model. No separate decision is needed for FHIR-18407 because it only supplies adjacent later context for where this clarification belongs.
