FHIR-46548: Clarify source rule FHIRPath context

Issue request:
FHIR-46548 was Applied/Persuasive for R6 and asked the FHIR Mapping Language Source Content section to clarify the three source-rule FHIRPath expressions, `where`, `check`, and `log`: they are evaluated in order, the expression context is the selected context.element/source element rather than the broader `context` identifier, an `as` alias is available when declared, and `log` records entries that passed the earlier stages.

Initial application:
The Jira-tagged commit faa06571e3 added a `log` bullet and a paragraph explaining that `where`, `check`, and `log` execute in order and that aliases are mapped before these FHIRPath statements run. That partially applied the decision, but the local bullet definitions still said the expressions were evaluated "on the context", leaving the exact ambiguity the issue identified in the active mapping-language page.

Additional context:
The mapping-language page is in current build scope through source/hierarchy.xml and is linked from the implementation-support and documentation pages. The referenced Zulip thread records the discussion that the same-rule alias should be available before the where clause, and that `where` filters the source list before `check` and `log`. FHIR-I minutes on 2024-09-09 record the formal Persuasive 13-0-0 vote. Focused Jira searches found no separate final issue governing this same clarification.

AutoFHIR reconciliation:
This commit updates the `where`, `check`, and `log` bullets in source/mapping-language.html to say that the FHIRPath context is the candidate or passed source element, that aliases are available, and that `check` and `log` are evaluated only for source elements that passed the preceding expressions. The existing sequencing paragraph is retained.

Recommendation:
Keep this commit as-is. It completes the Applied clarification without changing the mapping language mechanics; if an implementation wants different alias timing in the future, that should be raised as a separate substantive tracker.
