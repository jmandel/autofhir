FHIR-36858 + FHIR-48391: Align supportingInfo example with current type binding

Attribution note: surfaced while reviewing FHIR-36858, but direct Jira backing for this change is FHIR-36858 + FHIR-48391.

Issue request:
FHIR-36858 was a Published FHIR-core O&O change request, resolved Persuasive with Modification for R5. It asked for a mechanism for Procedure or DiagnosticReport to reference relevant prior/comparison studies and reports; the approved resolution made DiagnosticReport.supportingInfo a backbone element with a required type and reference, initially binding type by example to HL7 v2 Table 0936.

Initial application:
The issue was applied before this reconciliation. Commit f897eb6959c75fabf78584f94981bafac6e94fca added DiagnosticReport.supportingInfo, DiagnosticReport.supportingInfo.type, DiagnosticReport.supportingInfo.reference, a one-code local diagnosticreport-supportinginfo-type terminology, and a gingival-biopsy example using the local historical code. Commit 3c4e05e24c0aba397e142f44a8f9688e8ab0f683 then completed the Jira-commented application by changing DiagnosticReport.supportingInfo.type to the requested v2-0936 example binding and deleting the local ValueSet, but it left the local CodeSystem file and example code behind.

Additional context:
source/fhir.ini keeps DiagnosticReport active in the current build, and source/diagnosticreport/list-DiagnosticReport-examples.xml includes the gingival-biopsy example, so both the StructureDefinition and example are build-scoped. Later applied work refined, rather than reversed, the FHIR-36858 mechanism: FHIR-48391 replaced the v2-0936 binding with the current DiagnosticReport relevant-information value set derived from v2-0936/v2-0937 and added PHX for patient history; FHIR-48389 added DiagnosticReport.comparison for comparison-study lists and clarified that supportingInfo should not duplicate resources referenced elsewhere such as comparison. Both later issues are already represented on the combined branch.

AutoFHIR reconciliation:
This commit removes the stale diagnosticreport-supportinginfo-type CodeSystem source and updates the active gingival-biopsy supportingInfo example to use the current diagnosticreport-relevant-information-types PHX code with an explicit system/display. The authoritative DiagnosticReport structure already contains the requested supportingInfo backbone/reference and the later comparison guidance, so no structural change is needed.

Recommendation:
Keep this source fix. It preserves the applied FHIR-36858 mechanism while eliminating the obsolete one-code terminology and example code that no longer match the current supportingInfo.type binding. Do not decide FHIR-55950 here; that later comparison-model proposal is still Triaged and non-final.
