FHIR-22710: Support identity-copy shortcut in grammar

Issue request:
FHIR-22710 was a Published FHIR-core/FHIR-I change request, resolved Persuasive with Modification for R5, asking the mapping-language DSL to support a compact identity conversion syntax such as `src -> tgt: type, subtype, action, recorded;` so unchanged fields are easy to see and differences stand out.

Initial application:
The issue appears to have been partially applied by git commit 14d597bbd5fc2322a7137393c5fb72efa365837f, which added the "Simple Form: Identity transform" narrative to `source/mapping-language.html`. That commit did not update the formal ANTLR grammar, so the current published grammar artifact still did not accept the documented colon-separated identity-copy property list.

Additional context:
The mapping-language page is current build source, links directly to `mapping.g4`, and `publish.ini` includes `mapping.g4`, so `images/mapping.g4` is a published grammar artifact rather than an unrelated diagram. Zulip and FHIR-I minutes show the original discussion and later WGM review of this syntax. Later ballot issues FHIR-54477 and FHIR-54480 are still Triaged and confirm the grammar/resource-representation gap, but they are not final decisions and also request broader documentation/resource-model work beyond this seed.

AutoFHIR reconciliation:
This commit updates `images/mapping.g4` so a rule block can begin with one optional identity-copy shortcut matching the already-published DSL text: source identifier, target identifier, colon, and a comma-separated property list. Keeping it as `mapIdentityCopy? mapRule*` matches the narrative statement that this syntax is allowed as the first entry in the rules section.

Recommendation:
Keep this source fix as the bounded FHIR-22710 reconciliation. Leave unresolved follow-up questions from FHIR-54477/FHIR-54480, such as heading reorganization or preserving the shortcut with StructureMap annotations, for separate work-group disposition.
