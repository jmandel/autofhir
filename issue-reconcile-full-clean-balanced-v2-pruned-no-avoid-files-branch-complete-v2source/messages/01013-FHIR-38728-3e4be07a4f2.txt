FHIR-38728: Link resource search pages to search registry

Issue request:
FHIR-38728 was Published/Persuasive for R5 and asked that each resource search page and each resource content-page search section mention the SearchParameter registry, with pointers to common parameters and search-result modifiers that apply across resources.

Initial application:
The issue was initially applied in git commit b7e37c11e1a1480180a2265381dac9c31e443ce1, which changed the two resource search templates to add introductory search guidance and extension-registry links. The current templates retained common-parameter guidance and extension-link placeholders, but they did not directly link readers from resource search sections to the SearchParameter registry.

Additional context:
FHIR-20762 is a related Published/Persuasive-with-Modification search-parameter discoverability issue; its comments asked for SearchParameter resources to be easier to find, while its later comment said the URL exposure had been handled. FHIR-I minutes for 2022-12-12 record the FHIR-38728 Persuasive motion. The core search chapter already states that common and resource-specific SearchParameters are listed in the search parameter registry, so this reconciliation keeps the resource-page wording aligned with that central guidance instead of adding new conformance rules.

AutoFHIR reconciliation:
Updated tools/templates/template.html and tools/templates/template-search.html, which generate the resource content-page search section and resource-specific search pages, to link to searchparameter-registry.html and to mention search result parameters alongside the existing common-parameter guidance.

Recommendation:
Keep this source fix. It is a narrow template-only correction for active resource pages and preserves the existing extension-registry and common-search links while satisfying the published Jira request.
