FHIR-18815: Clarify FHIRPath Patch Bundle-local resolve

Issue request:
FHIR-18815 was a Published/Persuasive FHIR-core change request asking the FHIRPath Patch page to clarify four rules: add may add another occurrence when cardinality allows, insert must specify an index, missing paths are errors except for delete, and FHIRPath expressions must not refer outside the patched resource except that resolve() may refer to contained resources or, for Bundles, resources within the same Bundle.

Initial application:
Jira comment GH#e04b204635 corresponds to git commit e04b204635956d32e6009669b760f411b43e2b00, which added the add, insert, delete, missing-path, sequencing, and resolve() guardrail text to source/fhirpatch.html. That application carried forward the contained-resource allowance but did not include the approved Bundle-local resolve() allowance, leaving current wording stricter than the Jira resolution for patching Bundles.

Additional context:
Later FHIRPath Patch page commits such as FHIR-34214 changed headings and introductory wording, and existing AutoFHIR FHIR-26324 work clarified move indexes, but neither revisited the FHIR-18815 resolve() scope rule. Current Bundle reference-resolution source defines how references resolve within a Bundle, and source/fhirpatch.html is an active build input via publish.ini and source/hierarchy.xml. Zulip and Confluence searches found no FHIR-18815-specific discussion or later decision that removes the Bundle exception.

AutoFHIR reconciliation:
This commit updates the FHIRPath Patch base rule so resolve() is prohibited from crossing outside the resource being patched, but is expressly allowed to resolve contained resources or, when the patched resource is a Bundle, resources within the same Bundle. It also narrows the server safety sentence to resources outside the nominated target so Bundle entries are not accidentally excluded when the Bundle is the patch target.

Recommendation:
Keep this source correction as-is. It completes the published FHIR-18815 resolution without changing the other already-applied patch rules; any future decision to forbid Bundle-local resolve() in FHIRPath Patch should be handled as a new work-group change because it would reverse the published Jira text.
