FHIR-32381: Clarify QuestionnaireResponse source search description

Issue request:
FHIR-32381 was a Published/Persuasive with Modification FHIR-core QuestionnaireAnswers change request for R5. It asked that QuestionnaireResponse.author avoid saying only a person could receive and record answers, that QuestionnaireResponse.source allow Device, and the accepted resolution added both Device and Organization as source while adding author/source guidance that Device is only appropriate when it directly determined the answers rather than merely serving as a capture tool.

Initial application:
The issue was previously applied by commit 6d8abde43d00d13caff672213153f3cf9426174f and merged via PR #1283 in commit 6e63552ba58c6e4fdd4477a479d107d3df246bba. That application updated the active QuestionnaireResponse StructureDefinition: author/source definitions now say individual or device, source now allows Device and Organization, and both author and source include the requested Device/Provenance guidance. The active QuestionnaireResponse source search parameter description, however, still described only "The individual" providing the information.

Additional context:
QuestionnaireResponse is active in source/fhir.ini, so source/questionnaireresponse/structuredefinition-QuestionnaireResponse.xml and source/questionnaireresponse/bundle-QuestionnaireResponse-search-params.xml feed the current build. Later FHIR-41407, already represented on the combined branch, added bounded Group support for QuestionnaireResponse.author and source; that later change reinforces that the source search parameter description should not be limited to a single individual actor. Confluence SDC minutes on 2021-06-03 record FHIR-32381 as Persuasive with Modification, and no relevant Zulip discussion was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit keeps the already-correct StructureDefinition content and updates the active QuestionnaireResponse-source SearchParameter description from "The individual" to "The individual or entity" so the search surface no longer conflicts with Device, Organization, and later bounded Group source references.

Recommendation:
Keep this commit as-is. It is a narrow current-build source fix that completes the published FHIR-32381 intent across the related search parameter surface without reopening the already-applied StructureDefinition semantics.
