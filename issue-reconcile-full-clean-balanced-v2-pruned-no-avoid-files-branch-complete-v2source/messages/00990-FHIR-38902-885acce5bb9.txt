FHIR-31563 + FHIR-56063: Align DeviceDefinition consistency details

Attribution note: surfaced while reviewing FHIR-38902, but direct Jira backing for this change is FHIR-31563 + FHIR-56063.

Issue request:
FHIR-38902 was Published as Persuasive with Modification for OO. It asked to clarify Device versus DeviceDefinition differences, including the specialization/conformance model, DeviceDefinition.link, and DeviceDefinition value-set consistency for property.type and version.type. The Jira resolution linked the work to FHIR-39084 and FHIR-39322.

Initial application:
No commit was found that directly mentioned FHIR-38902. The main applied work was split across FHIR-39084-tagged commits for specialization-to-conformsTo and FHIR-39322-tagged commits for static Device/DeviceDefinition property wording and DeviceDefinition.property.type binding. Current source already includes those major changes, and FHIR-39084 has also been separately reconciled on this run's combined branch.

Additional context:
DeviceDefinition is an active current-build resource in source/fhir.ini. FHIR-31563 originally added DeviceDefinition.link and specified that DeviceDefinition.link.relation describes the related device to the defined device, but the current source still said device instance. FHIR-40488 later renamed DeviceDefinition.version to DeviceDefinition.deviceVersion, and FHIR-56063 later confirmed that DeviceDefinition.deviceVersion.type still needs the same example binding to device-versiontype as Device.deviceVersion.type. January 2023 DEV/OO meeting notes show the Device/DeviceDefinition consistency and property work were tracked together.

AutoFHIR reconciliation:
This commit updates the authoritative DeviceDefinition StructureDefinition source. It changes DeviceDefinition.link.relation short and definition text from device instance to defined device, and it adds the missing example binding for DeviceDefinition.deviceVersion.type to http://hl7.org/fhir/ValueSet/device-versiontype. No other Device or DeviceDefinition content was changed.

Recommendation:
Keep this source fix. It applies the concrete current-build leftovers from the published FHIR-38902 consistency request while leaving broader or still-pending related issues, including FHIR-39322 and FHIR-56063 as independent Jira items, for their own audit trail if needed.
