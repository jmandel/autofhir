FHIR-38652: Fix DeviceDefinition UML overlaps

Issue request:
FHIR-38652 was Published as Persuasive for OO and requested that the R5 DeviceDefinition UML diagram be updated so classes do not overlap or extend beyond the frame.

Initial application:
The issue was previously applied in DeviceDefinition layout metadata by b385b2ff, which moved DeviceDefinition.packaging from 775,0 to 750,0, and follow-up 8254a1c, which restored DeviceDefinition.deviceName to 0,0 after an intermediate rebuild. The source-side generated SVG was later deleted by 3bdc4bf. The current checked-in DeviceDefinition SVGs were reintroduced by f964cdd as a broad UML-diagram tidy-up, but the current diagram again had DeviceDefinition.udiDeviceIdentifier.marketDistribution defaulted to 0,0 and overlapping DeviceDefinition.deviceName.

Additional context:
source/fhir.ini lists DeviceDefinition as an active resource, so source/devicedefinition/structuredefinition-DeviceDefinition.xml and the source/devicedefinition diagram artifacts are in current build scope. The current StructureDefinition had no build SVG coordinate for DeviceDefinition.udiDeviceIdentifier.marketDistribution, which explains the default 0,0 diagram placement. The combined branch already contains FHIR-49741, which restored DeviceDefinition.additive without a UML coordinate; this reconciliation adds an explicit coordinate for that current backbone so future generated UML does not introduce another default-position overlap.

AutoFHIR reconciliation:
This commit adds explicit build SVG coordinates for DeviceDefinition.udiDeviceIdentifier.marketDistribution and DeviceDefinition.additive in the authoritative DeviceDefinition StructureDefinition. It also moves the visible marketDistribution class and its linkage in the checked-in DeviceDefinition SVG copies so the current source-side UML artifacts no longer overlap DeviceDefinition.deviceName. No DeviceDefinition structural element semantics, cardinalities, bindings, or definitions are changed.

Recommendation:
Keep this source fix. If the project later regenerates all UML diagrams, regenerate the checked-in SVGs from the StructureDefinition coordinates and consider whether the duplicate source/devicedefinition/svg.svg artifact should remain, but do not revert the explicit coordinates because they prevent the layout from defaulting classes to 0,0.
