FHIR-32507: Align Procedure onBehalfOf summary text

Issue request:
FHIR-32507 was Published with resolution Persuasive with Modification for R5. It asked Procedure.performer.onBehalfOf not to provide another way to say a Practitioner is acting for an Organization because PractitionerRole is the intended representation. The final resolution required the Procedure.performer.onBehalfOf comment and definition to identify the non-Practitioner actor types and required an invariant allowing onBehalfOf only when performer.actor is not Practitioner or PractitionerRole.

Initial application:
The request was initially applied in commit 12c0383ef875059f3622e2c076afe35997217b74, which updated Procedure.performer.onBehalfOf definition/comment and added constraint prc-1. Commit 44eb023f8ef6470c85eba821dceccfa284f1a693 then moved/fixed the invariant so it is evaluated on Procedure.performer. Current source already had the required definition, comment, actor target profiles, and invariant, but the active ElementDefinition.short and requirements still referred to a practitioner acting on behalf of an organization.

Additional context:
source/fhir.ini actively includes Procedure, so source/procedure/structuredefinition-Procedure.xml is current build input. Patient Care WGM minutes for January 2023 record review and voting on FHIR-32507. A search found no Zulip discussion that changes the Jira/source conclusion. FHIR-33394 shared the original implementation commit but concerns Procedure.focus/Specimen, not Procedure.performer.onBehalfOf.

AutoFHIR reconciliation:
This commit updates the active Procedure StructureDefinition short and requirements text for Procedure.performer.onBehalfOf so they no longer imply onBehalfOf is appropriate for Practitioner. It leaves the already-correct definition, comment, and prc-1 invariant unchanged.

Recommendation:
Keep this source fix. It removes the remaining contradictory Practitioner wording from the authoritative StructureDefinition while preserving the WG-approved invariant and allowed actor semantics. No related core issue needs a separate decision from this investigation.
