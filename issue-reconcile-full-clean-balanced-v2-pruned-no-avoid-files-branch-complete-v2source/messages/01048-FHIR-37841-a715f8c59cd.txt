FHIR-37841: Propagate metadata topic keyword wording

Issue request:
FHIR-37841 was a Published/Persuasive FHIR-I change request for R5 asking that MetadataResource.topic descriptions make clear that topic captures keywords as well as categories. The Jira text noted that vocabulary metadata resources already had this wording and asked that it be propagated to the rest of the metadata resources.

Initial application:
The explicit application commit 44fbd855db updated source/metadataresource/structuredefinition-MetadataResource.xml but did not update the active resource StructureDefinitions that redeclare topic locally. A later FHIR-40406 alignment also carried the keyword wording into source/definition/definition-spreadsheet.xml, but ActivityDefinition, EventDefinition, Library, and PlanDefinition still retained local topic definition and requirements text limited to topical categorization/search.

Additional context:
source/fhir.ini lists MetadataResource as an active interface and lists ActivityDefinition, EventDefinition, Library, and PlanDefinition as active resources. FHIR-38841 later deprecated MetadataResource.topic and added migration guidance to the topic comments, so the local comments should remain deprecation notes rather than restoring the older explanatory comment prose from FHIR-37841. Vocabulary metadata resources CodeSystem, ValueSet, NamingSystem, and ConceptMap already contain the keyword wording.

AutoFHIR reconciliation:
This commit updates the active ActivityDefinition.topic, EventDefinition.topic, Library.topic, and PlanDefinition.topic definition and requirements text to include keywords and keyword searches, matching the FHIR-37841 intent while preserving later FHIR-38841 deprecation guidance in the comments.

Recommendation:
Keep this source change. No further core FHIR action is needed for FHIR-37841 unless a work group separately decides to revisit the deprecated topic element or the older Publishable logical pattern outside this MetadataResource reconciliation.
