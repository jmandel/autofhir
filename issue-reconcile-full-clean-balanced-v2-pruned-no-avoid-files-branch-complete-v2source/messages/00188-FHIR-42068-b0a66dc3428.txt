FHIR-42068: Add APD classification for PhPID

Issue request:
FHIR-42068 was Applied/Persuasive for BRR and asked for a place on AdministrableProductDefinition to carry PhPID and similar classifications without treating PhPID as an identifier. The final Jira resolution changed the original code proposal to add AdministrableProductDefinition.classification as CodeableReference [0..*] targeting AdministrableProductDefinition, and the issue text also required the PhPID mapping and examples to stop implying that real APDs carry PhPID in identifier.

Initial application:
The issue appears to have been partially applied by fc82f5ce7ebbb03cf27788dbf277cb3ec50ef547, a combined FHIR-43019/FHIR-42068 commit. That commit correctly clarified AdministrableProductDefinition.identifier as an instance identifier and removed the PhPID IDMP mapping from identifier, but it added AdministrableProductDefinition.code as Coding [0..*] rather than the final resolved classification CodeableReference, and it left the active APD example and invariant test using a PhPID-valued identifier.

Additional context:
AdministrableProductDefinition is an active BRR resource in source/fhir.ini. The Zulip discussion that led to FHIR-42068 shows the progression from APD.code to repeatable CodeableReference and explicitly records agreement that PhPID is a classification and should support references to parent APDs. BRR minutes on 2024-10-22 record the 15-0-0 vote for FHIR-42068 alongside related MedicinalProduct issues. FHIR-43019 only shared the original implementation commit and concerns property.value[x] Range, so it is not decided here.

AutoFHIR reconciliation:
This commit changes the authoritative AdministrableProductDefinition StructureDefinition from code/Coding to classification/CodeableReference with targetProfile AdministrableProductDefinition, keeps the PhPID IDMP mapping on the new classification element, and updates the active APD example plus the apd-1 invariant test fixture so their placeholder PhPID is represented as classification.concept instead of identifier. It leaves generated-looking diagram artifacts for normal regeneration rather than hand-editing them.

Recommendation:
Keep this source fix. A normal publication/build regeneration can update derived schema, JSON, and diagram artifacts; no further work-group review is needed unless BRR wants to revisit the example binding used for coded APD classifications.
