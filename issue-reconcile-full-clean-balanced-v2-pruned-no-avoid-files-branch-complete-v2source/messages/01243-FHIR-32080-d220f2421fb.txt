FHIR-32080: Complete Device category terminology

Issue request:
FHIR-32080 was a Published/Persuasive with Modification FHIR-core Device change request for machine-understandable high-level Device categorization. The final decision called for bringing over Device.type/category example tables and linking to the scope categories from the FHIR-20574 Device scope/boundary work; the Jira comment listed active, communicating, durable medical equipment, home use, implantable, InVitro diagnostics, patient use, personal health, point-of-care, single use, re-usable, and software.

Initial application:
The current source already has Device.category as a 0..* CodeableConcept bound to ValueSet/device-category, and Device is active in source/fhir.ini. The terminology appears to have been added by git commit 14e5c20f1f34a491dd0b8af3b9f1bf8bc1082b2c, whose subject references a different Jira key; that commit added the Device.category element, CodeSystem/device-category, and ValueSet/device-category, but left patient-use commented out, omitted personal-health, used the incorrect display "Maintenance" for home-use, and copied an association-state description into the category value set.

Additional context:
The FHIR-20574 scope/boundary decision and the Device Scope-Boundary-Relationships Confluence page supply the category vocabulary and detailed descriptions, including patient-use and Personal Health Device. The later Published FHIR-35984 decision preserved the Device category example sentence with personal health and software, confirming that category examples remain part of the current Device scope text. Zulip searches for FHIR-32080 and Device category wording found no conflicting discussion.

AutoFHIR reconciliation:
This commit updates the authoritative Device category terminology source. It corrects home-use to display as Home Use, aligns its definition with the approved scope wording, adds patient-use and personal-health concepts, and corrects the ValueSet/device-category description so it describes Device category rather than association state.

Recommendation:
Keep this source fix. It completes the seed issue's high-level category terminology without changing unrelated Device behavior. FHIR-20574 remains a broader same-family issue because its search-parameter and DeviceDefinition-category aspects would require separate bounded review.
