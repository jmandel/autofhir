FHIR-8479: Clarify Observation coded value guidance

Issue request:
FHIR-8479 was a Published/Persuasive OO change request from DSTU1 asking to remove the example binding from Observation.value[x] because it caused profiling problems for choice-type values, while preserving the intent in narrative text.

Initial application:
The issue was applied by git commit 861e258d1a, which removed the ObservationValue binding from the Observation spreadsheet/source and added guidance to Observation notes. The current StructureDefinition source still has no binding on Observation.value[x], so the formal binding removal remained applied.

Additional context:
FHIR-8477 explains the underlying profiling problem for bindings on choice-type elements, and FHIR-22801 later touched only a typo in the same Observation notes sentence. The active source/fhir.ini resources list includes observation=Observation, so source/observation/observation-notes.xml feeds the current Observation resource narrative. Community searches for FHIR-8479 and the binding wording found no conflicting Zulip or Confluence evidence.

AutoFHIR reconciliation:
This commit keeps the formal binding absent and changes the remaining narrative sentence from saying valueCodeableConcept “is bound” to saying coded values can come from SNOMED CT or local result codes. That preserves the explanatory intent without implying a base ElementDefinition binding that no longer exists.

Recommendation:
Keep this source change. It aligns the narrative with the already-applied StructureDefinition state and avoids reintroducing the choice-type binding confusion that FHIR-8479 and FHIR-8477 were addressing.
