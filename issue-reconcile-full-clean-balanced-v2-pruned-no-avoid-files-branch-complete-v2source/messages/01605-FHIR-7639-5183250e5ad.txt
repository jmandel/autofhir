FHIR-7639 + FHIR-7517: Replace removed Observation has-component filter examples

Attribution note: surfaced while reviewing FHIR-7639, but direct Jira backing for this change is FHIR-7639 + FHIR-7517.

Issue request:
FHIR-7639 was a Published/Persuasive with Modification Observation issue asking whether the old ObservationRelationshipType distinction between has component and has member should remain. The final resolution pointed to FHIR-7517, whose motion removed the has-component related-type code and restored Observation.component as the inline structure for code/value components.

Initial application:
The 2015 application was commit 348f096acfd2c65b60b6ba759f214f756d403709, which reintroduced Observation.component, changed examples away from has-component related relationships, and cited FHIR-7639 in the subject. Commit 571342326cf07bc094b7310286c8a51133c1daf5 then adjusted Observation text for the same issue. The current Observation resource source already has distinct Observation.hasMember and Observation.component elements and explanatory grouping guidance, but the active _filter page still contained old examples using Observation.related[type eq has-component].

Additional context:
FHIR-10118 later replaced Observation.related with direct inline elements such as hasMember and derivedFrom, and current source defines the normative Observation-has-member SearchParameter. The _filter page is in the active hierarchy under RESTful API/Search, so stale examples there can still mislead implementers. The legacy ObservationRelationshipTypes value set was not changed because no current Observation element or search example binds to it, and broader cleanup of that historical standalone terminology artifact is outside this seed's bounded fix.

AutoFHIR reconciliation:
Updated source/search_filter.html to replace the removed Observation.related[type eq has-component] examples with equivalent current Observation: has-member _filter examples using the existing has-member reference search parameter.

Recommendation:
Keep this commit. It fixes the active stale guidance left behind by the FHIR-7639/FHIR-7517 change while preserving the current Observation.component versus Observation.hasMember distinction and avoiding a broader terminology cleanup that should be reviewed separately if desired.
