FHIR-16115: Clarify requirements CapabilityStatement expectation guidance

Issue request:
FHIR-16115 was a Published FHIR-core Conformance change request, resolved Persuasive with Modification, asking what it means when a CapabilityStatement used to define expectations lacks the capabilitystatement-expectation extension. The approved resolution was to add guidance that requirement-style CapabilityStatements list potentially relevant capabilities and rely on documentation or the existing extension to state the degree of expectation, plus an example using the extension.

Initial application:
The issue was initially applied by git-svn commit fd720e51a17d9ec14fd784c730cd97810dfd9ad1 / SVN revision 14436, which added the requested paragraph to source/capabilitystatement/capabilitystatement-introduction.xml and added capabilitystatement-expectation extension uses to the terminology-server CapabilityStatement example. A later link-maintenance commit replaced the old core extension URL with the current [%extensions-location%] StructureDefinition link.

Additional context:
CapabilityStatement remains an active resource in source/fhir.ini, so the introduction page is in the current build. The current CapabilityStatement.kind code is requirements, not requirement. FHIR-24698 later rewrote the terminology-server CapabilityStatement as an instance-kind example while preserving expectation extension uses, so restoring that example to requirements-kind would conflict with later published terminology-service work. The capabilitystatement-expectation StructureDefinition now lives in the FHIR Extension Pack, and the current narrative link points there through [%extensions-location%]. Zulip discussion for the original tracker confirms the question was about how requirement CapabilityStatements communicate expectation levels, and no Confluence evidence was found that changes this conclusion.

AutoFHIR reconciliation:
Updated the existing FHIR-16115 paragraph to refer to CapabilityStatements of kind <code>requirements</code> instead of type "requirement", aligning the guidance with the actual CapabilityStatement.kind code used by the current source. No new example was added because the active terminology-server example already demonstrates the expectation extension and its current instance kind is governed by later FHIR-24698 requirements.

Recommendation:
Keep this commit. It preserves the applied resolution while removing a current-code ambiguity in the guidance; no further FHIR-core source work is needed for FHIR-16115 unless the work group wants a new standalone requirements-kind example separate from the later terminology-server example.
