FHIR-48363: Remove obsolete Bundle reference-search note

Attribution note: surfaced while reviewing FHIR-13592, but direct Jira backing for this change is FHIR-48363.

Issue request:
FHIR-13592 was Published/Persuasive with Modification for STU3. It asked for documentation that a reference search parameter could search directly nested Resource elements, using Bundle 'message' and 'composition' as examples, because those parameters originally pointed at Bundle.entry[0].resource rather than a Reference element.

Initial application:
The Jira application record cites SVN revision 12841, and the current git history does not contain a FHIR-13592-tagged commit. Before this reconciliation, source/search.html still contained the requested reference-search paragraph, while current Bundle search parameter source no longer matched the premise of that paragraph.

Additional context:
FHIR-48363 is a later Applied/Persuasive FHIR-I decision for the same Bundle search parameters. It defined a new resource search parameter type, documented its intended chaining behavior for directly embedded resources, and changed Bundle-composition and Bundle-message from reference to resource. The FHIR-I 2024-10-21 minutes record the persuasive vote for adding the resource type and documenting R4/R5 usage. FHIR-50493 is only Triaged, so it is not decided here, but it identifies the same stale reference-section paragraph as a consequence of FHIR-48363.

AutoFHIR reconciliation:
Removed only the obsolete paragraph in source/search.html#reference that said reference search parameters can search Resource elements and used Bundle 'message' and 'composition' as examples. The authoritative Bundle search parameter source is in build scope through the active Bundle resource in source/fhir.ini and now uses type resource; source/search.html already has a Resource Parameters section and an R5-and-earlier implementation note from FHIR-48363.

Recommendation:
Keep this commit as-is. It reconciles FHIR-13592 with the later applied FHIR-48363 model without pre-deciding unresolved FHIR-50493; if FHIR-50493 later needs additional editorial wording, it should be handled under that tracker.
