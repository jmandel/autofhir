FHIR-14679: Warn on attachment content validation

Issue request:
FHIR-14679 was a Published FHIR-core security change request resolved Persuasive with Modification. The original request asked for a security tag warning about executable attachments; the accepted resolution instead required placing the existing Binary security warning on Attachment.data and Attachment.url.

Initial application:
No FHIR-14679-tagged source commit was found in the relevant Attachment or Binary history, and the current active Attachment datatype rows still lacked the requested warning on Attachment.data and Attachment.url. The referenced Binary warning already existed in source/binary/binary-notes.xml from earlier security work, so the issue appears not to have been fully carried into the current Attachment datatype source.

Additional context:
source/fhir.ini lists Attachment as an active datatype and Binary as an active resource, so source/datatypes/attachment.xml and source/binary/binary-notes.xml are in current build scope. Follow-up Jira/community searches found only FHIR-14679 and no later Zulip or Confluence record reversing or narrowing the accepted security warning.

AutoFHIR reconciliation:
Updated source/datatypes/attachment.xml comments for Attachment.data and Attachment.url to warn that inline or referenced attachment content is not constrained to safe content types and therefore must be validated against malicious or malformed content before processing.

Recommendation:
Keep this source-changing commit. It applies the published Security WG disposition directly to the authoritative active Attachment datatype source without adding a separate tag mechanism or broader security policy changes.
