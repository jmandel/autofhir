FHIR-37795: Point Flag narrative to supportingInfo

Issue request:
FHIR-37795 was Applied/Persuasive by Patient Care for R5, asking to elevate the flag-detail extension into the Flag base resource as Flag.supportingInfo 0..* with references to Condition, Procedure, AllergyIntolerance, Observation, and RiskAssessment plus explanatory examples.

Initial application:
The main application landed in git commit 937fb2c6f5f1b380f51a516f39b528920877c4e9, which added Flag.supportingInfo to source/flag/structuredefinition-Flag.xml with the requested short display, definition, comments, and initial target profiles. A later Applied issue, FHIR-56379, extended that same element to DocumentReference and DiagnosticReport in commit 377796869b1517d83a3a9a7a7a898dbddf244508. However, source/flag/flag-introduction.xml still told current-build readers that a common extension links a Flag to supporting detail.

Additional context:
The Flag resource is active in source/fhir.ini, so source/flag/flag-introduction.xml feeds the current resource narrative. FHIR-41366 and the linked Zulip discussion explain that the old extension should remain available for earlier FHIR versions while R6 should guide implementers to the new base element. The FHIR Extension Pack currently notes that flag-detail will be replaced by Flag.supportingInfo in R6, matching that migration path.

AutoFHIR reconciliation:
This commit updates the Flag boundaries narrative to point current readers to Flag.supportingInfo and to describe flag-detail as the earlier-version mechanism, removing the stale current-build implication that the extension is the appropriate linkage in R6.

Recommendation:
Keep this source change. It completes the already-applied base-resource elevation without changing the element definition or the Extension Pack; related extension lifecycle issues should remain tracked in their own repositories and Jira issues.
