FHIR-20807: Correct ETSI proof-of-approval code

Issue request:
FHIR-20807 was Published/Persuasive for R5 by the Security work group and asked FHIR-core signatures to add the ETSI digital signature commitment types as a new ETSI CodeSystem, then include that vocabulary alongside the existing ASTM signature types in the Signature.type value set.

Initial application:
The request was pre-applied in git commit 591b6b1e2a, which added source/datatypes/codesystem-etsi-signature-type.xml and included http://uri.etsi.org/01903/v1.2.2 in source/datatypes/valueset-signature-type.xml. Follow-up commits fixed the XML header and OID metadata, and commit 8e5295fb added an active Provenance example using the ETSI approval code. The remaining application defect was that the case-sensitive ProofOfApproval URI fragment from the Jira request and ETSI vocabulary had been entered as ProofOfapproval in both the CodeSystem and the example.

Additional context:
source/fhir.ini actively includes Signature as a datatype and the ETSI CodeSystem under [codesystems], while Provenance is an active resource and list-Provenance-examples.xml includes the diagnostic report signature example. The value set already includes both ETSI and ASTM systems, so no additional value set or Signature binding change is needed. Zulip and Confluence searches found no later discussion or meeting record changing the Jira/source conclusion.

AutoFHIR reconciliation:
This commit corrects the case-sensitive ETSI approval concept code to ProofOfApproval in source/datatypes/codesystem-etsi-signature-type.xml and updates the active Provenance signature example to use the corrected code. The hunk is necessary because the current CodeSystem declares caseSensitive=true and the lower-case "approval" spelling creates a different code from the ETSI URI fragment requested by the issue.

Recommendation:
Keep this source fix as-is. It completes the original ETSI commitment-type application without broadening the issue scope; no follow-up is needed unless the work group later decides to add additional ETSI commitment types beyond the six listed in the Jira description/comment.
