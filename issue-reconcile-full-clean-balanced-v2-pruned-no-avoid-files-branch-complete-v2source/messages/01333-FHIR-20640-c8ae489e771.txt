FHIR-20640: Add _type to search summary table

Issue request:
FHIR-20640 was a Published/Persuasive FHIR-I change request raised against STU3/R4 search documentation. It noted that search.html#_type implied _type was a universal search parameter, but search.html#table omitted it and the definitions file did not include a SearchParameter. The accepted resolution was to add _type to search.html#table and define it as a SearchParameter for R5, without backporting to R4 unless a tooling or implementation issue required that.

Initial application:
No git commit explicitly tagged FHIR-20640 was found in the relevant source history. The substantive definition was nevertheless applied before R5: commit ddecc63591d23dab5767aa2888c985a7c75964b6 added Resource-_type to source/resource/bundle-Resource-search-params.xml and expanded the search page's _type narrative. Later, commit 6de659813447c8357c3c567cc7a730264c2741e6 replaced the old summary table, which had listed _type, with the current detailed common-parameters table but did not carry _type forward.

Additional context:
source/search.html is an active built page under the RESTful API hierarchy, and Resource is an active infrastructure resource in source/fhir.ini. The existing Resource-_type SearchParameter source is in build scope and current generated output uses the canonical http://hl7.org/fhir/SearchParameter/Resource-type with a resource-search.html#Resource-type anchor. A Zulip discussion for FHIR-20640 confirms the implementer conclusion that _type should remain a special SearchParameter because it has no reliable path expression, while its value is constrained like a token over resource types. Confluence searches found no direct FHIR-20640 minutes or conflicting decision.

AutoFHIR reconciliation:
Added the missing _type row to source/search.html#table with special type, no path expression, and the generated Resource-type canonical URL. No change was needed to source/resource/bundle-Resource-search-params.xml because the SearchParameter definition is already present and consistent with the FHIR-20640 implementation discussion.

Recommendation:
Keep this commit as-is. It completes the original issue request by restoring _type to the built summary table while preserving the already-applied SearchParameter definition and current special-type treatment.
