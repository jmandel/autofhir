FHIR-14403: Correct URI above example ancestor

Issue request:
FHIR-14403 was a Published FHIR-core search page change request, resolved Persuasive for STU3. It asked to clarify the uri search parameter examples so the base ValueSet.url example was clearly an exact match, the second example used the :below modifier, and a third ValueSet.url:above example showed how URI hierarchy matching works.

Initial application:
The issue was applied by git-svn commit 8c37215b0cdde1516a112073fb5b88b3c29d0285, matching Jira's svn revision 13075 comment. That commit changed source/search.html by adding the ValueSet?url:below and ValueSet?url:above examples and replacing the ambiguous paragraph with line-by-line explanatory text. The examples survived the later 2022 search page restructuring in commit 83529ed121dc9fc1d9aeb117b0fe8a6293f9f0c9.

Additional context:
The original community.fhir.org thread confirms the confusion was that a plain ValueSet?url example was described as if it performed prefix matching, and the reporter also asked how :above should work. Later source text for the dedicated "above with uri" section says URI matching is based on URL path segments and lists http://acme.org/fhir/ValueSet/123 as an ancestor of http://acme.org/fhir/ValueSet/123/_history/5. The shorter uri section still listed http://acme.org/ValueSet/123, omitting the /fhir path segment and contradicting that later, more explicit source. A separate combined-branch audit for FHIR-26657 mentions FHIR-14403 only as background and does not carry an Issue-Reconcile-Key for FHIR-14403.

AutoFHIR reconciliation:
This commit changes only source/search.html, the direct source for the current search page, to make the uri section's :above explanation name http://acme.org/fhir/ValueSet/123 as the matched ancestor. No new examples or broader modifier wording were added because the current source already contains the requested :below/:above examples and detailed modifier sections.

Recommendation:
Keep this source fix as-is. It completes the original FHIR-14403 clarification while avoiding broader changes to search modifier semantics, which are governed by later issues and should be handled separately if needed.
