FHIR-23709: Remove duplicate ActivityDefinition kind search parameter

Issue request:
FHIR-23709 was a Published/Persuasive CDS change request from STU3, applied for R5, asking to add `kind` as a search parameter for the ActivityDefinition resource because knowledge vendors use ActivityDefinition.kind to classify protocol, order set, and recommendation definitions.

Initial application:
The requested parameter was applied in Jira-tagged source history. Commit 774eccb4c1 added `ActivityDefinition-kind` in the sorted ActivityDefinition search-parameter bundle, and commit 1f7ca3b620, later included through PR #2288, added the same `ActivityDefinition-kind` search parameter again near the end of the same bundle. Before this reconciliation the current source therefore had the requested parameter but duplicated the same id, URL, code, type, and expression.

Additional context:
`activitydefinition=ActivityDefinition` is an active resource in `source/fhir.ini`, and `source/activitydefinition/bundle-ActivityDefinition-search-params.xml` is the resource search-parameter bundle. Neighboring resource bundles such as OperationDefinition, NamingSystem, and StructureDefinition each define their `kind` search parameter once. No Zulip or Confluence discussion was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit removes only the redundant appended `ActivityDefinition-kind` entry and leaves the existing sorted `kind` search parameter in place, preserving the requested search capability while eliminating a duplicate SearchParameter definition from active source.

Recommendation:
Keep this commit as-is. It is a narrow source cleanup of the FHIR-23709 implementation, requires no new work-group decision, and keeps ActivityDefinition.kind searchable exactly once.
