FHIR-37549: Restore DocumentReference event XDS reference mapping

Issue request:
FHIR-37549 was Published/Not Persuasive with Modification for R5 DocumentReference. The issue noted that Composition had an event backbone with no corresponding DocumentReference mapping and asked for support for XDS DocumentEntry.referenceIdList; the OO resolution clarified that DocumentReference.event already existed as a CodeableReference and should be mapped to referenceIdList.

Initial application:
The Jira comment points to commit a31aac85a1e6913e8593606957711b98db1c7ec3, which added DocumentEntry.referenceIdList to the XDS mapping for DocumentReference.event in the active DocumentReference StructureDefinition. A later 2024 DocumentReference mapping update, d63adb6a17972d47bde74e7377febe531b104a9a, moved referenceIdList onto the new DocumentReference.related element while leaving DocumentReference.event mapped only to eventCodeList.

Additional context:
DocumentReference is in current build scope through source/fhir.ini, and its active StructureDefinition still has DocumentReference.event as a CodeableReference mapped to Composition.event.detail. FHIR-43408 and its 2024 OO minutes later reviewed the broader XDS mapping and continued to list event as mapping to DocumentEntry.referenceIdList, while also discussing a separate related/referenceIdList catch-all. FHIR-53824/FHIR-53550 later refined DocumentReference.related into a coded backbone for non-lifecycle associations not already represented elsewhere; that does not reverse the FHIR-37549 event mapping.

AutoFHIR reconciliation:
This commit restores DocumentEntry.referenceIdList to the XDS mapping value for DocumentReference.event, preserving the existing eventCodeList mapping and leaving the separate DocumentReference.related referenceIdList mapping in place for other related-resource use cases.

Recommendation:
Keep this source fix. It is a narrow build-scope correction that restores the Published FHIR-37549 decision without changing the later related backbone design; any broader review of the full DocumentReference/XDS mapping table should remain tied to the already represented FHIR-43408 work.
