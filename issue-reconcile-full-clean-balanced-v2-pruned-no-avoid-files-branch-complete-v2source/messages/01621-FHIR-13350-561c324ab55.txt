FHIR-13350: Correct extension context invariant example

Issue request:
FHIR-13350 was Published/Persuasive for STU3 and asked for examples showing how FHIRPath should deal with extensions, using an Address.line extension scenario as the motivating case.

Initial application:
The issue was applied in git-svn revision 13456, preserved as commit 2d851a5728d58782324e3841286fb5e9172629e4, which added the Context Invariants section to source/defining-extensions.html and clarified StructureDefinition.contextInvariant semantics. That application left the current example inconsistent: it links to the house-number extension but described an implicit FHIRPath condition for the street-name extension, and it used line.exists() even though the contextInvariant focus is the element that holds the extension.

Additional context:
source/defining-extensions.html is current build narrative for the extensibility pages: source/fhir.ini maps extension pages to the extensibility module and source/extensibility.html links to defining-extensions.html. The current StructureDefinition source says contextInvariant rules are only evaluated when the extension is present and the FHIRPath focus is the element holding the extension. The current Extension Pack house-number definition has context Address.line, so the example should test the primitive value of that Address.line element rather than naming a different extension URL.

AutoFHIR reconciliation:
Updated the existing FHIR-13350 example in source/defining-extensions.html to say that the Address.line element carrying the house-number extension needs a value, changed the example contextInvariant to hasValue(), and replaced the stale implicit street-name antecedent with wording that matches the current contextInvariant focus semantics.

Recommendation:
Keep this commit. It is a narrow correction to the already-applied FHIR-13350 documentation example and avoids misleading implementers about which extension is being tested and what node a contextInvariant expression evaluates against.
