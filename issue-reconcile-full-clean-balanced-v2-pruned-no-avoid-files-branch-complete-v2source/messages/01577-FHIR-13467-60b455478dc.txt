FHIR-13467: Remove stale DeviceComponent example labels

Issue request:
FHIR-13467 was a Published/Persuasive STU3 OO change request asking for Observation.device to support DeviceComponent in addition to Device and DeviceMetric, so Personal Health Device observations would not need a surrogate DeviceMetric solely to identify a DeviceComponent.

Initial application:
The request was applied in the STU3-era source by commits 2bc0950a1e354c2a99db1fca80954166c25bc241 and 74e12971113562df83d5022257947a15f0b27cdb, which changed the Observation.device spreadsheet type to Reference(Device|DeviceComponent|DeviceMetric), added a spirometry example referencing DeviceComponent, and adjusted the related Observation.device comment.

Additional context:
DeviceComponent is no longer an active current-build resource: source/fhir.ini comments out devicecomponent and records DeviceComponent as dropped, while Device, DeviceMetric, and Observation remain active. The R4 device rework removed DeviceComponent from the build and folded that modeling into Device/DeviceDefinition; commit 7fbb1fff1d9f70f28eb68f4d1251aa670bc889bc then removed DeviceComponent from Observation.device and from the spirometry example. Current Observation.device correctly references only Device and DeviceMetric, but two active Observation example labels still said the spirometry example referenced DeviceComponent.

AutoFHIR reconciliation:
This commit does not re-add DeviceComponent to Observation.device because DeviceComponent is outside the current FHIR build. It removes the stale DeviceComponent wording from the active Observation example list and example header so the rendered example metadata no longer advertises a retired resource reference that the example and current StructureDefinition do not contain.

Recommendation:
Keep this commit as-is. The seed issue was correctly applied for STU3, then superseded by the later DeviceComponent removal; the remaining current-spec fix is this narrow cleanup of stale Observation example labels. Any future support for DeviceComponent would require a new work-group decision to restore or replace that retired resource, not a reconciliation change for this issue.
