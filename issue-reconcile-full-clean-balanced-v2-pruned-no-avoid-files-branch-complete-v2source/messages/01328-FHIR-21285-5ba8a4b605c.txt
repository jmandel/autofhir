FHIR-21285: Correct subscription pull actor

Issue request:
FHIR-21285 was Published/Persuasive for R5. It asked that the behavior for omitted subscription payloads be made more visible outside the REST-hook-specific example, and that the guidance use the appropriate re-query parameter once the _since versus _lastUpdated discussion was resolved.

Initial application:
No explicit git commit mentioning FHIR-21285 was found. The issue appears to have been applied as part of the R5 topic-based Subscription redesign: the FHIR-23738 Jira comment and later Zulip R5 feedback table both identify FHIR-21285 as covered by the new empty-payload guidance, and git history shows the Subscription notes gaining empty-payload re-query prose before FHIR-22099 changed the example from _since to _lastUpdated.

Additional context:
The current Subscription resource notes already describe empty, id-only, and full-resource notification content and tell subscribers receiving an empty notification to query based on the SubscriptionTopic and filters, optionally using _lastUpdated. FHIR-22099 and the linked Zulip discussion establish that _since is not a search parameter and that Subscription guidance should use _lastUpdated. However, the active Exchange table-of-contents includes source/exchanging-subscription.html, whose pull-notification paragraph still said the data source would subsequently query, which reverses the client/server actor for the omitted-payload retrieval flow.

AutoFHIR reconciliation:
Updated source/exchanging-subscription.html so the pull-notification overview says the data consumer subsequently queries the data source, while preserving the existing explanation that the data source applies its normal authorization, audit, permission, and consent mechanisms. No change was needed in source/subscription/subscription-notes.xml because the authoritative Subscription resource guidance is already correct and uses _lastUpdated.

Recommendation:
Keep this source fix. It removes a misleading actor inversion from an active overview page while leaving the already-applied R5/R6 Subscription payload guidance intact. No additional FHIR core change is recommended for FHIR-21285.
