FHIR-3758: Prevent reactions on not-done Immunization

Issue request:
FHIR-3758 is a Published/Persuasive DSTU1 FHIR-core Immunization issue. It asked to add two invariant constraints to the then-current refusedIndicator model: when an immunization was administered, explanation.refusalReason had to be absent; when an immunization was not administered, reaction and explanation.reason had to be absent.

Initial application:
The original source application was commit 64fbbf28ef27948a7944954073c8df878bac2bc9, whose subject explicitly included #3758. That commit added the two old spreadsheet invariants against Immunization.wasNotGiven, while also applying the tightly related FHIR-3762/FHIR-5351 not-given rename. Jira comments later noted that the base Immunization schematron carried those invariants.

Additional context:
Later Immunization source history replaced the DSTU1 wasNotGiven/reasonNotGiven representation with the current status = not-done plus statusReason model. FHIR-3762 is already represented on the combined branch as a no-change audit for the rename, and FHIR-54325 is already represented as the current statusReason invariant allowing statusReason only for not-done or entered-in-error. FHIR-14377 and FHIR-14374, plus the later workflow Zulip discussion, show that current Immunization.reason/statusReason semantics are more nuanced than the DSTU1 explanation.reason rule: a resource can have a reason for the immunization and a statusReason explaining why it was not done. The old no-reason clause is therefore not safe to reinstate as a current invariant without a new work-group decision. The old no-reaction clause still maps cleanly because Immunization.reaction is defined as a reaction associated in time to an immunization that occurred.

AutoFHIR reconciliation:
This commit adds imm-3 to the active Immunization StructureDefinition, requiring reaction to be absent when status is not-done, and adds matching pass/fail invariant test bundles. It intentionally leaves Immunization.reason unrestricted for not-done records because later Event-pattern and Immunization statusReason context supersedes the original DSTU1 explanation.reason constraint.

Recommendation:
Keep this source fix. If the work group wants to forbid Immunization.reason when status is not-done, handle that as a new current-version decision because the later reason/statusReason evidence supports more than one valid interpretation.
