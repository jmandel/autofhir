FHIR-37485: Align PlanDefinition subject prose

Issue request:
FHIR-37485 was Published/Persuasive for R5 by the CDS work group. It reported that PlanDefinition.subjectCanonical named non-canonical product definition resources such as MedicinalProductDefinition, causing IG Publisher errors, and resolved to move non-canonical targets from subjectCanonical to subjectReference.

Initial application:
Git commit 3cef25612a applied the structural part of the decision by moving MedicinalProductDefinition, SubstanceDefinition, AdministrableProductDefinition, ManufacturedItemDefinition, and PackagedProductDefinition targetProfiles from the canonical type to the Reference type and leaving canonical limited to EvidenceVariable. The active source prose and diagram tooltip still described those product definitions as canonical-reference targets.

Additional context:
PlanDefinition is an active, approved resource in source/fhir.ini. The same source directory includes definition-mapping exceptions and a checked-in diagram that mirror the element definition text. OO Catalog minutes record FHIR-37485 as a residual build-error issue in July 2022 and as approved/applied in August 2022. Later related issues did not reverse the subjectReference/canonical split.

AutoFHIR reconciliation:
This commit updates the active PlanDefinition StructureDefinition, matching mapping-exception metadata, and checked-in diagram tooltips so product definition resources are described as Reference targets and canonical subject references are described as limited to EvidenceVariable. It also removes the same stale product-definition canonical sentence from PlanDefinition.action.subject[x], whose type does not list those non-canonical product resources.

Recommendation:
Keep this commit as-is. It completes the FHIR-37485 application by aligning implementer-visible PlanDefinition prose with the already-correct formal type definitions; no further core source work is needed for the seed issue.
