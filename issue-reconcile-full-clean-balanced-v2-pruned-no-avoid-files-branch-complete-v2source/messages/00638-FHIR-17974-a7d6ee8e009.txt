FHIR-17974: Mark EOB identifier as summary

Issue request:
FHIR-17974 is Published/Persuasive with Modification for ExplanationOfBenefit and asked to add identifier, patient, created, billingPeriod, provider, insurer, and error to the EOB summary list, with the resolution also requiring any required items to be in the summary list.

Initial application:
The issue was partially applied in 2018 by 89bb47c31d84c7cc3fb753e5408806226f62d395 and 47922328a9dde56d50550ccb72f1cf7ed7551e49. Those commits marked the then-required top-level fields, patient, created, insurer, provider, outcome/insurance, and billablePeriod as summary, but left ExplanationOfBenefit.identifier without a summary flag.

Additional context:
ExplanationOfBenefit is an active current-build resource in source/fhir.ini, and source/explanationofbenefit/structuredefinition-ExplanationOfBenefit.xml is the authoritative current StructureDefinition input. Later FHIR-43309 renamed the root patient element to subject and preserved its summary status. Later FHIR-40763 added the EOB error backbone from ClaimResponse; the current source has summary flags on error.code and error.expression while keeping the backbone itself aligned with ClaimResponse, so adding a top-level error summary flag would broaden the imported error structure rather than complete FHIR-17974.

AutoFHIR reconciliation:
Added isSummary="true" to ExplanationOfBenefit.identifier. The other still-current requested fields are already summarized under their current names or through the later error child summary flags.

Recommendation:
Keep this source fix. It completes the remaining current-build FHIR-17974 gap without changing later ClaimResponse-aligned EOB.error semantics; no separate work is recommended for this issue.
