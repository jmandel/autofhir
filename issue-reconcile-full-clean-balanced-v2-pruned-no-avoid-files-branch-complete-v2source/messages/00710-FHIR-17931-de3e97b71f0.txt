FHIR-17931: Complete ClaimResponse summary flags

Issue request:
FHIR-17931 was Published/Persuasive with Modification for the FM ClaimResponse resource. It requested adding ClaimResponse.identifier, patient, created, billingPeriod, provider, insurer, and error to the summary view, with the resolution also adding total, total.category, and total.amount.

Initial application:
The 2018 Jira-tagged batch commit afb5ec66f6 applied part of the request in the then-active ClaimResponse spreadsheet by marking patient, created, insurer, total, total.category, and total.amount as summary, but identifier, the provider/requestor element, and the error backbone were still not marked as summary. The current XML StructureDefinition inherited that partial state through the source conversion and later refactors.

Additional context:
ClaimResponse is an active current-build resource in source/fhir.ini. Later source refactors renamed patient to subject and map the older requestProvider/provider family to the current ClaimResponse.requestor element; the current resource has no ClaimResponse.billingPeriod or ClaimResponse.billablePeriod element to mark. Later source history added summary flags to ClaimResponse.error.code and ClaimResponse.error.expression, which supports making the error backbone itself a summary element rather than adding unrelated error children.

AutoFHIR reconciliation:
Marked ClaimResponse.identifier, ClaimResponse.requestor, and ClaimResponse.error with isSummary=true in source/claimresponse/structuredefinition-ClaimResponse.xml. Existing summary flags already covered subject, created, insurer, total, total.category, and total.amount.

Recommendation:
Keep this source fix. It completes the Published FHIR-17931 request for the current ClaimResponse element names without reintroducing removed/non-current elements or broadening unrelated summary content.
