FHIR-20912: Fix version-parameter conversion text

Issue request:
FHIR-20912 was Published/Persuasive with Modification for the HTTP FHIR Version Parameter. It requested replacing the absolute error on different Accept and Content-Type fhirVersion values with an exception for operations specifically defined to perform version conversion, such as $convert, and fixing the $convert examples plus the nearby typo.

Initial application:
The issue was initially applied in commit 639dbcd2848776be444488fe66b23438c581256d, which changed source/http.html to allow the version-conversion exception and corrected the $convert request example. A later operation-representation cleanup split the $convert request and response examples into separate active example files, while a later wording commit touched the same HTTP sentence without resolving the remaining typo or broken parenthetical.

Additional context:
The current source/http.html page is the authoritative HTTP narrative in the build, and the Resource resource is active in source/fhir.ini. The $convert examples are referenced by source/resource/operationdefinition-Resource-convert.xml through build example extensions. Zulip discussion and FHIR-I minutes confirm the intended policy: mixed versions are exceptional and allowed only for operations that define version conversion, with $convert as the known core example and possible future operations requiring their own definition.

AutoFHIR reconciliation:
This commit fixes the remaining Jira-reported typo in the HTTP version-parameter paragraph, closes the $convert parenthetical so the exception sentence is syntactically correct, and changes the $convert response example comment from the nonexistent "Content-Header" to "Content-Type header".

Recommendation:
Keep this source-changing commit. It does not broaden the policy beyond the published FHIR-20912 decision; it only completes the applied wording and example cleanup in build-scope source.
