FHIR-50863: Align resourceDefinition migration wording

Issue request:
FHIR-50863 was Applied with a Persuasive with Modification resolution for FHIR-core BaseResource. It asked what should happen to the JSON resourceDefinition property and XML resourceDefinition attribute when an additional resource moves into core. The final decision was that resourceDefinition is no longer needed once the resource is a standard core resource, may remain for backwards compatibility, SHOULD NOT be added, and if present SHALL have a version correct for the published core FHIR version.

Initial application:
The issue appears to have been applied by git commit 09b9a4c718f6db95ad354a42fede0090b80dfce8, which added the migration rule to source/resource/resource-introduction.xml. The original additional-resource support was introduced by 931df6ae329dd3d7f44df8358b5affdd2b95e757. The application did not update source/json.html or source/xml.html, which still said resourceDefinition is not present whenever the resource/resourceType is defined in this specification.

Additional context:
FHIR-I minutes for 2025-07-21 confirm the vote and rationale: when a resource is promoted to core, resourceDefinition is not needed, but the group did not want to say it must be absent; if present, its version must be corrected to the core FHIR version. FHIR-55447 later submitted a broader request about allowing resourceDefinition to point to normative or trial-use versions of core resources, but that issue is unresolved and does not change the applied FHIR-50863 rule. The edited format pages are direct top-level source pages, and source/fhir.ini lists Resource as an active normative resource, so the Resource introduction and format pages are in current build scope.

AutoFHIR reconciliation:
This commit completes the applied decision by aligning the format pages with the Resource migration rule. It clarifies the Resource introduction to refer to the JSON property and XML attribute, and it updates both source/json.html and source/xml.html so the otherwise-absent resourceDefinition rule has the approved exception for resources that moved from additional-resource status into core.

Recommendation:
Keep this commit as-is for FHIR-50863. Revisit only if the work group later resolves FHIR-55447 or another tracker to change the broader version policy for resourceDefinition on core resources.
