FHIR-45450: Align Consent policy basis wording with URI

Issue request:
FHIR-45450 was Applied/Persuasive for FHIR-core Consent. It asked to change Consent.policyBasis.url back to Consent.policyBasis.uri with datatype uri because policy identifiers such as XACML policy URIs are not always valid URL values.

Initial application:
The issue was initially applied by HL7/fhir PR #3169. Commit 3d1b229bce7a416387e9f5b3de46054e2545d7c8 renamed the child element from Consent.policyBasis.url to Consent.policyBasis.uri and changed its datatype from url to uri, but it left the active Consent.policyBasis parent definition and the checked-in Consent diagram tooltip describing the choice as a Reference or URL.

Additional context:
FHIR-32817 introduced the policyBasis structure with URL wording before FHIR-45450 narrowed this correction. Current source/fhir.ini keeps migration aliases from Consent.policy.uri and Consent.policyBasis.url to Consent.policyBasis.uri, so the old paths remain intentional compatibility metadata. tools/history/release5/profiles-resources.xml still records R5 history and is not current build source. FHIR-48988 is a later Triaged XACML example request and is not final enough to decide here, but it reinforces that XACML policy identifiers are URI-based. No directly relevant Zulip or Confluence discussion was found.

AutoFHIR reconciliation:
Updated the active Consent StructureDefinition parent definition from Reference or URL to Reference or URI, and made the matching checked-in Consent diagram tooltip change. The existing child element name, child short, child definition, datatype, and fhir.ini migration alias were already correct and were left unchanged.

Recommendation:
Keep this source fix. It completes the applied FHIR-45450 URL-to-URI correction on the active Consent definition while preserving compatibility aliases and release-history records. Do not treat FHIR-48988 as resolved by this commit; it remains an unresolved example request.
