FHIR-18351: Split modifier-extension datatype rule

Issue request:
FHIR-18351 was a Published/Persuasive STU3 technical correction for the FHIR-core extensibility page. It asked to change "Other data types, or elements inside data types SHALL NOT have modifier extensions, and extensions..." to make the first two subjects conjunctive and to make the extension-internal prohibition a separate sentence.

Initial application:
The issue appears to have been partially applied by git commit 7bf7397f4a965784698e0d343f8a96789cdf4942, the 2018 "Additional typos" commit, which changed "Other data types, or elements inside data types" to "Other data types and elements inside data types". That captured the "or" to "and" correction but left the requested comma-and before the extension clause.

Additional context:
The current source file is in the active build surface because source/fhir.ini maps the Extension datatype page to extensibility. The adjacent FHIR-18350 correction was later applied directly to the preceding sentence, and FHIR-25431 later standardized "data type" to "datatype" in this paragraph. This reconciliation therefore preserves the current "datatypes" terminology while completing the older FHIR-18351 sentence split. Direct Zulip and Confluence searches found no FHIR-18351 discussion or conflicting community guidance.

AutoFHIR reconciliation:
This commit completes the requested non-substantive wording cleanup in source/extensibility.html by replacing the remaining comma-and join with a period and capitalized "Extensions" sentence.

Recommendation:
Keep this source change as-is. It is a narrow correction on an active current-build page, preserves later terminology changes, and does not alter the conformance rule that modifier extensions are unavailable on other datatypes, datatype-contained elements, or internally within extensions except for the listed reusable structures.
