FHIR-5232: Clarify datatype category scope

Issue request:
FHIR-5232 is a Published/Persuasive Jan 2015 ballot comment for the FHIR-core datatypes page. It asked MnM to clarify the opening datatype-category sentence because "simple / primitive types, imported from XML schema, and complex types" could read as three categories rather than two; MnM approved the recommendation, and the Jira comments noted the sentence had already been rewritten for other problems.

Initial application:
The old wording was initially addressed before publication by commit 8778bd12c1463e489868f342bb4b938870bc34fc, which removed the "imported from XML schema" appositive from source/datatypes.html and described simple/primitive types as single elements. Later datatype-page reorganizations replaced the two-category sentence with a list; commit 4652397b3f33fa5641bf58d760a47b3084417e2a changed that list from four categories to five by adding the base abstract types, but left the follow-on sentence referring to categories 1 and 2.

Additional context:
The current datatypes page is in the active build scope: source/fhir.ini maps the default datatype type page to datatypes, and source/datatypes.html now lists primitive datatypes as category 2 and general-purpose complex datatypes as category 3. No Zulip or Confluence searches for FHIR-5232 or the datatypes/category wording found conflicting community evidence.

AutoFHIR reconciliation:
This commit updates source/datatypes.html so the follow-on sentence says the page describes the primitive and general-purpose complex datatypes, categories 2 and 3. That preserves the prior applied clarification and fixes the current category-number drift without broadening the issue scope.

Recommendation:
Keep this source change as-is. It is a narrow build-scope clarification for the same datatypes introductory category text covered by FHIR-5232, and no additional related Jira decisions are needed.
