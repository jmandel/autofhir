FHIR-16547: Add DeviceAlert to clinical-code registry

Issue request:
FHIR-16547 was Published/Persuasive for STU3 and asked why the common search parameters code and patient appeared twice in the FHIR-core search parameter registry. The accepted resolution was to work through the search parameter definitions and remove spurious differences that caused duplicate common registry rows.

Initial application:
The issue was initially applied in git commit c7f72fcc93572b3d78aeea773248f02394791522, corresponding to svn revision 14050 cited in Jira. That commit moved the Medication code, identifier, and patient bases into the common clinical-* SearchParameter entries and commented out the separate medications-* common entries.

Additional context:
Later registry work continued the same pattern. FHIR-36674 was Published/Persuasive for R5 and is already represented on the combined branch by commit 2310ecd8cf8f53c5906d2c13180e606cd841a927, which added newer patient outliers such as DeviceAlert to clinical-patient while leaving resource-level SearchParameter definitions in place for generation. DeviceAlert is an active resource in source/fhir.ini, and its active DeviceAlert-code SearchParameter is the primary token search over DeviceAlert.code, but DeviceAlert was not listed under clinical-code.

AutoFHIR reconciliation:
This commit adds DeviceAlert as a base of source/searchparameter/common-search-parameters.xml clinical-code. The source file is the authoritative common registry input used by the search parameter registry, and this hunk is needed so the current registry aggregates the active DeviceAlert code parameter with the existing common code row instead of exposing it as the remaining spurious code outlier.

Recommendation:
Keep this source fix. It is a narrow continuation of the original Published/Persuasive FHIR-16547 decision and the later FHIR-36674 registry-alignment pattern; no separate related issue needs to be republished for this seed.
