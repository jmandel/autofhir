FHIR-39181: Use typed choice ids in vital-sign profiles

Issue request:
FHIR-39181 was Published/Persuasive for R5 and asked that core profiles stop using renamed choice-type element ids and paths such as Observation.valueQuantity, GuidanceResponse.moduleUri, Observation.effectiveDateTime, and ArtifactAssessment.citeAs/artifact. The requested representation for typed choice constraints is the sliced choice form, e.g. Observation.value[x]:valueQuantity.

Initial application:
No git commit in the current repository history explicitly mentions FHIR-39181. The current source had been partly corrected or superseded by later profile work: the BP component slices already use Observation.component:<slice>.value[x]:valueQuantity, the vital-signs base profile uses Observation.component.value[x]:valueQuantity, and several listed profiles have since been removed. However, eight active single-value vital-sign Observation profiles still used the obsolete Observation.valueQuantity id/path.

Additional context:
source/fhir.ini lists Observation as an active resource, so the StructureDefinition profile XML files in source/observation feed the current build. Later history removed the diagnostic-report cholesterol/triglyceride profiles, DeviceMetricObservation, CDS Hooks GuidanceResponse, and EBMRecommendation profile from current source, so there was no current profile source to edit for those Jira-listed artifacts. FHIR-I minutes for 2022-11-14 record the FHIR-39181 Persuasive vote and note that it might be a tooling issue; no direct Zulip mention of FHIR-39181 was found.

AutoFHIR reconciliation:
Updated the remaining active single-value vital-sign profiles (bmi, bodyheight, bodytemp, bodyweight, headcircum, heartrate, oxygensat, and resprate) from Observation.valueQuantity to Observation.value[x]:valueQuantity, set the path to Observation.value[x], added sliceName=valueQuantity, and declared the Quantity type. This matches the current BP and vital-signs typed-choice pattern and removes the obsolete profile element ids/paths from current source.

Recommendation:
Keep this source fix. No further core edits are indicated for the Jira-listed profiles that are no longer present in current source; if those profiles are reintroduced later, use the same value[x]:valueQuantity representation.
