FHIR-24862: Restore Consent policy URI search

Issue request:
FHIR-24862 was Published/Persuasive for FHIR-core Consent. It requested adding Consent.policy.uri to the Consent search parameters so implementers can find consents for a particular policy or policy version, with guidance that the URI should be versioned and/or dated because the URI element itself does not necessarily carry separate version metadata.

Initial application:
The issue was initially applied by commit e8cfbf5b5db69f3876c3bee18cbb0a484a12118c, which added a Consent-policy-uri search parameter for the then-current Consent.policy.uri path. After later Consent model changes, commit 6c429ba35c61fd2dd5a24c2c9eb90b848b133d05 commented the parameter out because Consent.policy.uri had become an orphaned path that failed search-parameter validation; commit 3d15d8f10db9fb3f2f57469a3fa986e3baebc1f0 then removed the commented-out search parameter while refactoring the policy structure.

Additional context:
Consent is an active resource in source/fhir.ini, and source/consent/bundle-Consent-search-params.xml is the active current search-parameter bundle. Later FHIR-45450 restored the current policy identifier child as Consent.policyBasis.uri with datatype uri, and a previous reconciliation commit already aligned the parent definition with URI wording. FHIR-31568 is related background because it tracked Consent search-parameter example coverage, including policy-uri when that parameter existed historically; it is already represented separately on the combined branch.

AutoFHIR reconciliation:
This commit restores the Consent policy URI search parameter against the current Consent.policyBasis.uri path, preserving the original policy-uri search code and the version/date guidance in the description. It also adds a policyBasis.uri value to the OrgToOrg Consent example so the restored active search parameter has current example coverage.

Recommendation:
Keep this commit as-is. It completes the published FHIR-24862 intent on the current Consent model without reopening the already-decided FHIR-45450 URI element work or the separate FHIR-31568 example-cleanup audit.
