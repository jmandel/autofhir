FHIR-12433: Use core patient religion extension in examples

Issue request:
FHIR-12433 was Published/Persuasive for DSTU2 and asked to remove the US Realm-specific us-core-religion extension because the Patient religion concept had become a core extension. The decisive resolution was that the US Realm Steering Committee found no further need for a US Realm-specific religion extension once it was included in FHIR core.

Initial application:
No source commit explicitly mentions FHIR-12433. The same application family appears in FHIR-12384 history, where commit 77cd788 removed the active us-core profile entry from source/fhir.ini and commit 207716e restored it the same day for build reasons. In the current source, source/fhir.ini leaves the old us-core and cda profile inputs commented out, so their remaining legacy references are not current build fixes. A later Measure change, commit 1ce7bae, added active Measure operation examples that still used the retired us-core-religion URL.

Additional context:
FHIR-11248 promoted the religion extension to a standard/core extension, and FHIR-19806 later recorded that US Core did not need to add a separate religiousAffiliation extension because http://hl7.org/fhir/StructureDefinition/patient-religion was already the standard FHIR extension. FHIR-37517 and PA minutes later updated the patient-religion binding to preferred, matching the current Extension Pack source. The Measure resource is active in source/fhir.ini and the Measure operation definitions include the edited JSON examples, so those examples are in build scope.

AutoFHIR reconciliation:
This commit updates the active Measure $submit-data and $collect-data example Patient resources to use http://hl7.org/fhir/StructureDefinition/patient-religion instead of http://hl7.org/fhir/us/core/StructureDefinition/us-core-religion. It intentionally leaves the disabled legacy cda.profile.xml reference untouched because source/fhir.ini comments that profile out of the current build.

Recommendation:
Keep this commit as-is. It removes the stale US Core religion extension URL from active core examples while preserving out-of-build legacy profile source; any future packaging or availability issue for patient-religion should be handled in the FHIR Extension Pack rather than by reintroducing a US Core-specific URL in core examples.
