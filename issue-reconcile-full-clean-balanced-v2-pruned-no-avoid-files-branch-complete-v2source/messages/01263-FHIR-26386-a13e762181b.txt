FHIR-26386: Clarify logical reference aggregation text

Issue request:
FHIR-26386 was a Published FHIR-core StructureDefinition clarification asking how profiles can express whether a Reference may be populated by Reference.identifier rather than Reference.reference. The final Not Persuasive with Modification resolution said Reference datatype constraints belong in ElementDefinition.profile, aggregationMode concerns computable resolution, identifier-only logical references are not expected to be computably resolvable, and the aggregation guidance should be read as applying only when the literal reference element is present.

Initial application:
The aggregation rule itself was already present from GF#14402, stating that when aggregationMode is present the Reference.reference element must be present and populated. The Jira-tagged application commit 50302bfe36 added the logical references clarification in source/references.html, but left the final aggregation sentence grammatically incomplete as "nor does ... aggregation restrictions."

Additional context:
FHIR-I minutes from 2020-07-06 record the 12-0-0 decision that aggregation mode is about how references resolve and should be explained with logical references. A 2022 Zulip implementation thread for FHIR-26386 confirms that the existing aggregation section already covered the aggregationMode part, so only the logical-reference clarification needed application. source/fhir.ini actively maps Reference to references.html and ElementDefinition to elementdefinition.html, so the edited page is in current build scope.

AutoFHIR reconciliation:
This commit fixes the malformed logical-reference sentence so it now states that aggregation restrictions do not apply to identifier-only logical references. No broader ElementDefinition change was made because the existing aggregation section already states the required Reference.reference rule and the implementation thread explicitly treated that part as already present.

Recommendation:
Keep this commit as-is. It preserves the approved semantics while correcting the only remaining defect in the applied wording; no additional work is needed unless FHIR-I wants to revisit the broader aggregationMode rule.
