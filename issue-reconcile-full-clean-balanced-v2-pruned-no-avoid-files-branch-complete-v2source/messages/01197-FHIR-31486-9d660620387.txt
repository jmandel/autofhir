FHIR-31486: Allow primitive type table cells to wrap

Issue request:
FHIR-31486 was a Published/Persuasive FHIR-I technical correction for R5 reporting that the long dateTime regex in the primitive types table forced horizontal scrolling and obscured the Value Domain, XML Representation, and JSON Representation columns. The requested correction was to allow the regex expressions in that table to wrap.

Initial application:
No prior current-tree reference or issue-tagged source commit for FHIR-31486 was found. The current datatypes source still renders the primitive types table as table class="list", and the current CI fhir.css table.list td rule lacked any wrapping behavior.

Additional context:
source/fhir.ini routes primitive datatype pages through datatypes, and source/datatypes.html is the active source for the reported primitive types table. A related already-published AutoFHIR fix for FHIR-38736 added the same overflow-wrap/word-wrap behavior to generated dictionary tables, but it did not cover the table.list primitive types table. Zulip and Confluence searches for FHIR-31486 found no conflicting community or minutes evidence.

AutoFHIR reconciliation:
Added overflow-wrap:anywhere and word-wrap:break-word to table.list td in both active FHIR stylesheet copies, source/fhir.css and tools/templates/fhir.css, so long regex tokens such as dateTime can wrap within list-table cells instead of widening the table. This is a non-substantive presentation fix and does not change datatype definitions or conformance content.

Recommendation:
Keep this source fix. It directly implements the Published technical correction, aligns list-table behavior with the existing dictionary-table wrapping rule, and should be carried forward with no additional work unless the project later consolidates the duplicated stylesheet sources.
