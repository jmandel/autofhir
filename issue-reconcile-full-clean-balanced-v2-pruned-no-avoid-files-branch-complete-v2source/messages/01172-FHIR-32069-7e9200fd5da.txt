FHIR-32069: Use fhir-types in Consent example

Issue request:
FHIR-32069 is Published/Persuasive for R5 and asks to remove abstract Resource and DomainResource style codes from the ResourceType code system, with affected terminology bindings such as CapabilityStatement.rest resource types, Care Plan Activity Kind, AuditEventEntityType, Consent Content Class, Subject type, FHIRDefinedType, and FHIRAllTypes using concrete-only resource type sets where appropriate.

Initial application:
The issue was initially applied by e7b4eba11e, which introduced the generated CodeSystem/fhir-types source, made ValueSet/resource-types the concrete resource-type value set over fhir-types, added all-resource-types for abstract-inclusive use cases, and converted several affected value sets and examples away from the obsolete resource-types code system URL. Later commit 3d15d8f10d reworked Consent.provision.class into documentType and resourceType and reintroduced http://hl7.org/fhir/resource-types as a Coding.system in the SMART-on-FHIR Consent example.

Additional context:
Current source keeps Consent in the active [resources] section of source/fhir.ini, and source/consent/list-Consent-examples.xml includes Consent/consent-example-smartonfhir. Consent.provision.resourceType is bound to http://hl7.org/fhir/ValueSet/resource-types, while source/terminologies/valueset-resource-types.xml defines that value set as concrete FHIR Resource Types drawn from http://hl7.org/fhir/fhir-types. Source search found no remaining active CodeSystem/resource-types definition, so the example's Coding.system was stale and inconsistent with the current terminology split.

AutoFHIR reconciliation:
Changed source/consent/consent-example-smartonfhir.xml so the MedicationRequest resourceType coding uses http://hl7.org/fhir/fhir-types, matching the active fhir-types code system and the concrete resource-types value set expansion.

Recommendation:
Keep this source fix. It preserves the FHIR-32069 terminology model and removes the only current source reference to the obsolete resource-types code system URL; no additional core source change was found necessary.
