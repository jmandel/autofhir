FHIR-15786: Allow multiple adjudication reasons

Issue request:
FHIR-15786 was a Published/Persuasive with Modification FM change request for STU3. It asked for a header-level adjudication backbone on ExplanationOfBenefit so claim-level adjudication amounts would not need to be forced into information or extensions; the final resolution also said to place the new adjudication element after addItem on ExplanationOfBenefit and ClaimResponse and to change the cardinality of adjudication.reason to 0..*.

Initial application:
The header-level adjudication portion was applied historically across old spreadsheet commits and then preserved by the later StructureDefinition-source migration. Commit 89bb47c31d84c7cc3fb753e5408806226f62d395 explicitly mentioned GF#15786 while touching the ExplanationOfBenefit spreadsheet, commit 47922328a9dde56d50550ccb72f1cf7ed7551e49 introduced ExplanationOfBenefit.adjudication, and commit afb5ec66f68641293bb7950b6e0eeb118fa1444a introduced ClaimResponse.adjudication. Those historical rows and the migrated current XML left the shared item.adjudication.reason definition at 0..1, so the cardinality part of the published resolution was not fully applied.

Additional context:
ClaimResponse and ExplanationOfBenefit are active current-build resources in source/fhir.ini. In the current source, both root-level adjudication elements sit after addItem and use contentReference to the item.adjudication backbone, so changing the shared item.adjudication.reason cardinality is the source-level way to make the line-item, add-item, and header-level adjudication structures allow multiple reasons consistently. Jira, Zulip, and Confluence searches found no later FHIR-core decision reversing the FHIR-15786 cardinality requirement; the nearby hits were external IG/profile discussions rather than core changes.

AutoFHIR reconciliation:
This commit changes ExplanationOfBenefit.item.adjudication.reason and ClaimResponse.item.adjudication.reason from 0..1 to 0..* in the active StructureDefinition XML, and updates the checked-in resource SVG diagrams for the same two reason rows so the visible diagrams do not contradict the authoritative source.

Recommendation:
Keep this fixed commit as-is. It completes the previously omitted cardinality portion of FHIR-15786 while preserving the already-applied header-level adjudication elements; no further core FHIR source change is needed unless FM later chooses a new adjudication-reason policy.
