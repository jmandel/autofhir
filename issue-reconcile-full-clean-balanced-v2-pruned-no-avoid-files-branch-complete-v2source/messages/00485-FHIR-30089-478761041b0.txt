FHIR-30089: Clarify patientCharacteristic combinations

Issue request:
FHIR-30089 was a Published/Persuasive MedicationKnowledge change request for R5. It asked that MedicationKnowledge patientCharacteristic.value[x] support age and weight intervals by using full Quantity instead of SimpleQuantity and by adding Range; the accepted Jira comment also requested guidance that same-type repeated characteristics are alternatives while different-type characteristics are cumulative.

Initial application:
The R5 work was initially applied in git commit 1683ac64141af807564d62a28932d70133142fb3, which changed the relevant MedicationKnowledge patientCharacteristic.value[x] from SimpleQuantity-profiled Quantity to unrestricted Quantity and added Range. That application covered the datatype part of FHIR-30089 but did not add the accepted interpretive comment for repeated patientCharacteristic entries.

Additional context:
MedicationKnowledge is active in source/fhir.ini, and the current authoritative source is source/medicationknowledge/structuredefinition-MedicationKnowledge.xml. Later same-family MedicationKnowledge changes renamed and nested the original administrationGuideline location as MedicationKnowledge.indicationGuideline.dosingGuideline.patientCharacteristic. Confluence catalog minutes record the MedicationKnowledge changes including FHIR-30089 as accepted and applied by Pharmacy, and a later Zulip implementer thread confirms that the R5 remodel was intended to support age-range patient characteristics.

AutoFHIR reconciliation:
This commit adds the missing ElementDefinition.comment to MedicationKnowledge.indicationGuideline.dosingGuideline.patientCharacteristic, preserving the already-correct Quantity and Range value[x] choices. No generated diagram/SVG edits were made because the authoritative StructureDefinition source is the build input that needed the semantic clarification.

Recommendation:
Keep this source-changing commit. It completes the part of the accepted FHIR-30089 disposition that was not represented in current source while leaving the already-applied datatype changes untouched.
