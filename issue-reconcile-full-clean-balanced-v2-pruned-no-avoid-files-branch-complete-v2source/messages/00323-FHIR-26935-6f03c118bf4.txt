FHIR-26935: Add Extension to open type usage list

Issue request:
FHIR-26935 was Published/Persuasive for R5 by MnM. It asked to change the datatypes open-type section from "open references" to "open types" and to update the listed places where open types are used, because ElementDefinition and Extension were missing from the R4-era list of Parameters, StructureMap, and Task.

Initial application:
Commit d621ab0bda61832d87d16ee8fa98261bf403a9da changed the phrase in source/datatypes.html from "Open references" to "Open types" as part of a mixed MnM batch that mentioned FHIR-26935. That commit did not make the usage list complete; the current source still relied solely on [%dtusage *%], and Marc Duteau's Jira comment recorded that the first part was complete while Extension and StructureMap still appeared absent from the generated list.

Additional context:
The active build scope includes source/datatypes.html as the page for wildcard "*" types and includes Extension as an active infrastructure type whose page is extensibility.html. Current source/datatypes/extension.xml still defines Extension.value[x] with type "*", while current StructureMap source no longer uses a wildcard for StructureMap.group.rule.target.parameter.value[x]. The current CI build rendered the datatypes open-type usage list with ElementDefinition, DosageCondition, Claim, ClaimResponse, ExplanationOfBenefit, Parameters, and Task, but still omitted Extension.

AutoFHIR reconciliation:
This commit updates the active datatypes source to explicitly include a link to Extension before the generated [%dtusage *%] list. It does not edit generated artifacts and does not re-add StructureMap, because the current StructureMap definition is not an open type use.

Recommendation:
Keep this source fix. A future publisher/tooling improvement could make [%dtusage *%] include active infrastructure datatypes automatically, but until then the datatypes page would otherwise continue omitting the current Extension open-type use.
