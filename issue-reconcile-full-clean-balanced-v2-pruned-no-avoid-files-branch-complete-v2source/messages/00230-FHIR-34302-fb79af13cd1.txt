FHIR-34302: Align Consent verification comment with grantor decision

Issue request:
FHIR-34302 was a Published/Persuasive R5 technical correction for FHIR-core Consent. It reported that Consent.verification.verifiedBy incorrectly described verification of the Grantee decision and requested the typo be corrected to Grantor, consistent with Consent.grantor and Consent.grantee definitions.

Initial application:
The issue was partially applied by git commit 74cd341f56, which changed Consent.verification.verifiedBy from Grantee decision to Grantor decision in source/consent/structuredefinition-Consent.xml. Current source still had an adjacent Consent.verification.type comment, originating before that application and later carried through the verificationType-to-type rename, that described RelatedPerson verification of the Grantee decision.

Additional context:
Consent is an active resource in source/fhir.ini, so source/consent/structuredefinition-Consent.xml is in current build scope. The linked Zulip thread confirms the grantor/grantee wording was a typo in Consent.verification, and no Confluence reference or conflicting community evidence was found. Later Consent history renamed verificationType to type but did not reverse the grantor correction.

AutoFHIR reconciliation:
Updated the Consent.verification.type comment in source/consent/structuredefinition-Consent.xml so both the verification-type comment and the verifiedBy definition consistently refer to verification of the Grantor decision.

Recommendation:
Keep this source fix. It completes the non-substantive typo correction without adding redundant prose or changing unrelated Consent semantics.
