FHIR-41590: Root ImplementationGuide example in example.org

Issue request:
FHIR-41590 was an Applied FHIR-I change request for the ImplementationGuide example. The reporter found that the example's global Patient profile referenced US Core and caused validator warnings when the R4 examples package was loaded indirectly; the final Persuasive with Modification decision was to root the example in example.org instead of leaving real DAF/US Core canonical references.

Initial application:
The issue appears to have been partially applied by commit ddd2773b64b4d3ed0fa3fd98ca74ee0dfa2d86bd, which changed only ImplementationGuide.dependsOn.uri from the US Core IG URL to an example.org IG URL. Current source still retained the DAF IG canonical URL, DAF package id, DAF rendering URL, and three US Core Patient profile references, including the global profile that was the source of the validator warning.

Additional context:
The source file is in build scope because source/fhir.ini lists ImplementationGuide as an active approved resource and list-ImplementationGuide-examples.xml includes ImplementationGuide/example. The cited Zulip thread reproduces the validator warning and identifies ImplementationGuide/example's global profile as the trigger. FHIR-I minutes for 2023-09-25 record the accepted FHIR-41590 motion as changing the profile to example.org, confirming that the intended fix was not only the dependsOn URI.

AutoFHIR reconciliation:
Updated source/implementationguide/implementationguide-example.xml so the example's canonical URL, package id, rendering URL, global Patient profile, definition resource profile, and manifest resource profile all use example.org values rather than real DAF or US Core identifiers. This keeps the global element available as an ImplementationGuide example while avoiding a real unresolved US Core profile assertion from the examples package.

Recommendation:
Keep this source fix as-is. It completes the Applied decision without removing the global element; if FHIR-I later wants the example to stop demonstrating ImplementationGuide.global entirely, that should be a separate work-group decision.
