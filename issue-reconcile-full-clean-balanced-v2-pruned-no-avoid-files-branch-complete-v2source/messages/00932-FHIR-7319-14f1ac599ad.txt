FHIR-7319: Clarify diagnosis sequence identifiers

Issue request:
FHIR-7319 was a Published/Persuasive FM change request for FHIR-core Claim. The original request asked how diagnosis ordering works and whether the first diagnosis should be primary; the later application comment clarified that diagnosis.type had overtaken ordering, because diagnosis.type identifies admitting, discharge, primary, secondary, and similar roles, so the diagnosis list should be treated as a referenceable list and descriptions should remove the concept of diagnosis order.

Initial application:
No explicit FHIR-7319-tagged source commit was found. The 2016-12-09 Claim spreadsheet commit 15de009ec2 changed the Claim diagnosis definitions in the requested direction by removing "Ordered list" from Claim.diagnosis, removing the sequence definition/requirement language that said sequence orders diagnoses, and expanding diagnosis.type examples to include primary, secondary, and discharge. A later 2021 source rework commit 33b409a4b6 introduced the current StructureDefinition XML files with copied diagnosis-sequence order language, and a 2023 QA commit only adjusted punctuation, leaving the semantic conflict in place.

Additional context:
Claim is active in source/fhir.ini, and ExplanationOfBenefit is also an active FM resource with the same copied diagnosis-sequence wording and diagnosis.type role/ranking element. Current Claim.diagnosis.type already expresses the primary/secondary role, while Claim.diagnosis.sequence and ExplanationOfBenefit.diagnosis.sequence still said the list order conveyed expected importance. Jira and community searches found no later core decision reversing the FHIR-7319 application.

AutoFHIR reconciliation:
This commit updates the active Claim and ExplanationOfBenefit StructureDefinition sources so diagnosis.sequence is described as a local identifier for references from claim details, not as a primary/secondary ranking mechanism, and points readers to diagnosis.type for that purpose. No generated diagram-only artifact was edited.

Recommendation:
Keep this source fix as-is. It restores the applied FHIR-7319 intent in the current build and keeps the active Claim-family definitions consistent; normal publication tooling can regenerate any derived narrative or diagrams.
