FHIR-27532: Allow legacy .as() in simple FHIRPath

Issue request:
FHIR-27532 was a Published/Persuasive with Modification FHIR-I change request for R5. It noted that the FHIRPath simple subset allowed ofType(type), while ElementDefinition.slicing.discriminator.path still mentioned as(type), and the approved resolution was to add .as as an allowed simple FHIRPath function for backwards compatibility only and remove the local ElementDefinition comment.

Initial application:
The issue appears to have been partially applied in two historical commits from 2022-08-26. Commit f9efe6933fb710ac641f9588487238d6b094d059 reserialized source/datatypes/elementdefinition.xml and removed the local ElementDefinition.slicing.discriminator.path comment that said only as(type), resolve(), and extension(url) were allowed. Commit 84a650b04be0fcabffb180bb88c24ef8211da93f added general as(type) alias prose to source/fhirpath.html and updated many search-parameter expressions from as() to ofType(), but the current restricted subset list at fhirpath.html#simple still omitted .as(type).

Additional context:
FHIR-I minutes for 2020-08-31 record the accepted scope as supporting .as as an allowed function for legacy purposes and removing the ElementDefinition comment. ElementDefinition is an active datatype in source/fhir.ini, and the current ElementDefinition source now only links to fhirpath.html#simple with no duplicate allowed-functions comment. The remaining current defect was therefore confined to the active source/fhirpath.html narrative page's restricted subset list.

AutoFHIR reconciliation:
This commit adds .as(type) to the restricted simple FHIRPath function list in source/fhirpath.html, explicitly identifying it as a legacy alias for .ofType(type) for backwards compatibility only. It leaves source/datatypes/elementdefinition.xml unchanged because the requested local comment removal is already present there.

Recommendation:
Keep this source fix as-is for FHIR-27532. No further core source change is needed unless the work group later decides to remove legacy .as support from the simple subset; avoid reintroducing a local ElementDefinition allowed-functions comment because the centralized simple-subset page is now authoritative.
