FHIR-32064: Include warning in ClinicalUseDefinition root definition

Issue request:
FHIR-32064 was Published with a Persuasive with Modification resolution for R5. It asked ClinicalUseIssue, now ClinicalUseDefinition, to minimally support warnings by adding a warning backbone with description/code, removing the old generic description element, adding warning to Scope and Boundaries, and constraining instances to one of the five issue types.

Initial application:
The change was applied across several Jira-tagged source commits: 07fb4bd added the warning backbone and removed ClinicalUseDefinition.description, 62ca66a added the warning type value set binding, c5e2a5b added the narrative text, and f4592866 completed warning text and type/value-set updates. The current source already has the active ClinicalUseDefinition resource, warning type code, warning backbone, example warning instance, Scope and Boundaries warning text, and later type/backbone invariants, but the differential root element short/definition still described only indication, contraindication, interaction, and undesirable effect.

Additional context:
FHIR-31847 renamed ClinicalUseIssue to ClinicalUseDefinition before application. OO Catalog minutes in August 2021 tracked the FHIR-32064 application and specifically noted remaining Scope and Boundaries work, which is now present. Zulip discussion confirms the intended warning use cases, and a later BRR/Pharmacy-model thread describes the warning backbone as having description and code. FHIR-48893 later refined the type/backbone invariants and preserves warning as the fifth supported type.

AutoFHIR reconciliation:
This source-changing commit updates the ClinicalUseDefinition root element short and definition in source/clinicalusedefinition/structuredefinition-ClinicalUseDefinition.xml so the generated differential no longer contradicts the applied warning support. The file is in build scope because source/fhir.ini actively lists ClinicalUseDefinition as a resource, assigns it to BR&R, and marks it normative.

Recommendation:
Keep this commit as-is. No broader core change is needed for FHIR-32064: the warning structure, example, terminology, narrative, and constraints are already present, and this commit closes the remaining stale root-definition omission.
