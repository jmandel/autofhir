FHIR-5996: Align _summary search table values

Issue request:
FHIR-5996 was a Published FHIR-core change request, resolved Persuasive with Modification, asking not to add a new _narrative REST parameter but instead to document _summary for read as well as search and add text (narrative-only) and data (data-only) _summary values.

Initial application:
The issue was applied in git commit 074d2c031a94ff1de85a5ef50c2755f2c40b1b33, whose message says "#5996 - note about _summary on read, and define new values." That commit added read-interaction prose to source/http.html and added text/data/count/false rows to the main _summary section in source/search.html. It did not update the search control parameter summary table that had been added earlier in commit 32fcb82713a3958004db6576b951288ec8958c7a.

Additional context:
Current source/http.html already documents _summary on read and lists true, false, text, count and data. Current source/search.html already defines the detailed semantics for true, text, data, count and false. Later published issues FHIR-18094, FHIR-9416 and FHIR-33002 refined read wording and _summary=text semantics and are already represented on the combined branch, so this reconciliation does not duplicate them.

AutoFHIR reconciliation:
This commit updates the built source page source/search.html so the Search Control Parameters table lists text, data and count in addition to true and false for _summary. The hunk is necessary because the same source page's authoritative _summary section allows those values, while the summary table previously showed only true and false and could mislead implementers.

Recommendation:
Keep this commit as-is. It is a narrow completion of the original FHIR-5996 application in current build-scope source and does not require further work unless the work group later changes the allowed _summary value set.
