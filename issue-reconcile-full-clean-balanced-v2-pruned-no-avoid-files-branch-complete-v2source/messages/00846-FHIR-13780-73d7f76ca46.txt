FHIR-13780: Clarify stopped MedicationRequest status

Issue request:
FHIR-13780 is Published/Persuasive with Modification for STU3 MedicationRequest status definitions. Pharmacy decided not to force Task support and requested clearer MedicationRequest status definitions, specifically that stopped means some but not all administrations have occurred and cancelled means no administrations have occurred.

Initial application:
The issue appears to have been applied in historical commit eddae4c6adc0a38d7c292dfa6f82cc15e75e194e, titled "GF #13943, GF #13879, GF #13871, GF #13780, GF #13999 - Pharmacy Resource changes". That commit changed the old MedicationRequest spreadsheet so cancelled became "withdrawn before any administrations have occurred" and stopped became "before all of the administrations occurred". Commit 7373e742ee4ae5907dc0d8b0779cadb0cb0892f0 later migrated those definitions into the current standalone MedicationRequest status CodeSystem.

Additional context:
MedicationRequest is an active current-build resource in source/fhir.ini, and the current status CodeSystem is the authoritative terminology source for the required MedicationRequest.status binding. Later status wording work, including FHIR-32859 on the combined branch, changed prescription/order lifecycle wording to request wording but did not change the stopped/cancelled administration boundary. Confluence and Zulip searches found no community record that changes the Jira/source conclusion.

AutoFHIR reconciliation:
Updated the stopped code definition in source/medicationrequest/codesystem-medicationrequest-status.xml to say actions are halted after some, but before all, administrations have occurred. The existing cancelled definition already says the request was withdrawn before any administrations occurred, so no additional source change was needed.

Recommendation:
Keep this commit as-is. It completes the original Pharmacy WG intent by removing the remaining semantic overlap between stopped and cancelled while leaving unrelated MedicationRequest status wording to already-decided later issues.
