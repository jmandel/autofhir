FHIR-32523: Add QuestionnaireResponse linkId length warning

Issue request:
FHIR-32523 was Published with a Persuasive with Modification resolution. The issue requested a maximum length for linkId, specifically calling out Questionnaire, QuestionnaireResponse, and related linkId references; the final resolution was to define a best-practice warning that linkId length should be under 256 characters and should avoid whitespace characters.

Initial application:
The Jira comment cites Git Questionnaire-fixes 5ffa1f49eb. That commit added the best-practice length warning only to Questionnaire.item.linkId. In the current source, Questionnaire.item.linkId has the que-15 length warning and later whitespace constraint, while QuestionnaireResponse.item.linkId had the later qrs-3 whitespace constraint but still lacked the FHIR-32523 length warning.

Additional context:
source/fhir.ini lists both Questionnaire and QuestionnaireResponse as active resources in the current build. FHIR-46191 later added the whitespace constraint for both Questionnaire and QuestionnaireResponse, so this reconciliation does not change whitespace behavior. A bounded check found analogous Measure/MeasureReport linkId history under FHIR-38832, but that is a separate CQI resource family and not a safe opportunistic decision for this FHIR-I QuestionnaireAnswers seed.

AutoFHIR reconciliation:
This commit adds a qrs-5 best-practice warning on QuestionnaireResponse.item.linkId using the same elementdefinition-bestpractice pattern and "$this.length() <= 255" FHIRPath expression already used for Questionnaire.item.linkId, and adds a matching invariant test fixture with a 256-character linkId.

Recommendation:
Keep this commit as-is. It completes the missing QuestionnaireResponse half of the published FHIR-32523 decision without broadening the issue into unrelated linkId families; any MeasureReport symmetry question should be handled separately by CQI if desired.
