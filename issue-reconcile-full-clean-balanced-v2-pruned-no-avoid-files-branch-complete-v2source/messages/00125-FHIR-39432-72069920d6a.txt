FHIR-39432: Align DeviceMetric model metadata

Issue request:
FHIR-39432 was Applied with a Persuasive with Modification resolution for R5. It asked whether DeviceMetric.category and DeviceMetric.calibration.type could really use exhaustive required value sets, noted stale DeviceObservation terminology, and resolved to make category and calibration.type CodeableConcept elements with extensible bindings while cleaning short/definition wording.

Initial application:
The implementation was merged in HL7/fhir#3137 as merge commit 557e1a17a2f2c1b454c784ec4d2d89d85f838601. That PR changed source/devicemetric/structuredefinition-DeviceMetric.xml so DeviceMetric.category and DeviceMetric.calibration.type use CodeableConcept, extensible bindings, and the revised definition punctuation; a follow-up commit in the PR intentionally differentiated the final short descriptions. The active CQL model-definition library examples, however, still exposed those two elements as primitive code wrapper types and still carried helper/conversion metadata for those removed wrapper classes.

Additional context:
source/fhir.ini keeps both DeviceMetric and Library in the active current build. The later FHIR-55085 DeviceMetric terminology migration issue is only Resolved - change required and should not be applied opportunistically in this default Applied/Published run; it does not reverse the FHIR-39432 CodeableConcept decision. The PR body and an intermediate commit mention FHIR-39462, but Jira FHIR-39462 is an unrelated SDC issue, so that appears to be a typo rather than a related DeviceMetric decision. Community searches found no Zulip discussion that changes the Jira/source conclusion; Confluence only surfaced the January 2023 DEV meeting page that references the DeviceMetric tracker list.

AutoFHIR reconciliation:
This commit fixes the remaining in-scope source by aligning the active FHIR and QUICK model-definition content with DeviceMetric.category and DeviceMetric.calibration.type as CodeableConcept/System.Concept, removing the obsolete DeviceMetricCategory and DeviceMetricCalibrationType wrapper classes from those model definitions, removing their FHIRHelpers ToString/conversion metadata, and resynchronizing the embedded FHIR model-definition Library data.

Recommendation:
Keep this commit as-is. It completes the applied source change on the parallel Library model-definition surfaces without changing the already-correct DeviceMetric StructureDefinition. Handle FHIR-55085 separately when its terminology migration is applied/published or when a broader resolved-change-required run is prepared.
