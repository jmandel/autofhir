FHIR-13722: Add Appointment.description title alias

Issue request:
FHIR-13722 was Published with a Persuasive with Modification resolution for STU3 Appointment. The PA decision was to map Appointment.description to iCalendar SUMMARY, map Appointment.comment to iCalendar DESCRIPTION, add alias "title" to Appointment.description, and add patientInstructions for patient-facing details.

Initial application:
Git commit d777ec203416f644c5658bf99deb6c89dd2cd31b explicitly applied GF#13722 by changing the Appointment spreadsheet iCalendar mappings and adding Appointment.patientInstruction. That commit did not add the approved title alias to Appointment.description, and the current StructureDefinition still lacked the alias before this reconciliation.

Additional context:
Appointment is active in source/fhir.ini, so source/appointment/structuredefinition-Appointment.xml is current build input. Later published Appointment issues changed the surrounding field names and types: FHIR-19521 changed Appointment.comment to Appointment.note, FHIR-27849 changed patientInstruction from 0..1 string to 0..* CodeableReference(DocumentReference, Binary, Communication), and FHIR-40254 corrected Appointment.description to refer to the note field. Those later decisions supersede the older comment/string wording but do not remove the title-alias requirement.

AutoFHIR reconciliation:
Added the missing <alias value="title"/> to Appointment.description. No other Appointment wording or cardinality was changed because the iCalendar mappings, note wording, and patientInstruction datatype/cardinality already reflect FHIR-13722 plus later PA decisions.

Recommendation:
Keep this source fix. It completes the one missing durable part of the FHIR-13722 resolution while preserving later published Appointment changes.
