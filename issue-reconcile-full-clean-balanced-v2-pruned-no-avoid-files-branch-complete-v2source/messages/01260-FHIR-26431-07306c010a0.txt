FHIR-26431: Generalize CapabilityStatement scope wording

Issue request:
FHIR-26431 was Published/Persuasive for R5 after FHIR-I accepted that CapabilityStatement introductory text must not describe only FHIR servers, because clients can also publish CapabilityStatements and CapabilityStatement.rest.mode includes client.

Initial application:
The historical FHIR-26431 source commit 93cf3cf32e changed the root CapabilityStatement description and definition from "FHIR Server" to "FHIR Server or Client". That applied the main label change, but the same authoritative sentences still said "actual server functionality" and "required or desired server implementation", and the root comment still said "the server will have multiple statements".

Additional context:
CapabilityStatement is an active current-build resource in source/fhir.ini and belongs to the conformance chapter. The current narrative introduction already describes actual software, applications, and desired systems, and CapabilityStatement.rest.mode is explicitly "client | server". Confluence FHIR-I minutes record the 2020-07-13 persuasive vote, and targeted Zulip/Confluence searches found no conflicting community rationale.

AutoFHIR reconciliation:
Updated the active CapabilityStatement StructureDefinition description and root definition to use "system" functionality/implementation rather than server-only wording, and changed the multiple-version root comment from "the server" to "the system". No terminology-server wording was changed because TerminologyCapabilities is specifically server-scoped and outside this issue.

Recommendation:
Keep this source change. It completes the accepted clarification without adding redundant narrative prose or changing REST-specific server/client rules elsewhere in CapabilityStatement.
