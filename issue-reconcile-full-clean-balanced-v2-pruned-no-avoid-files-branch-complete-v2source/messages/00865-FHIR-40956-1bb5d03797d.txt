FHIR-40956: Clarify Questionnaire item type value set

Issue request:
FHIR-40956 was an Applied/Persuasive FHIR-core Questionnaire change request asking whether Questionnaire needed to prevent Questionnaire.item.type from using the R5 non-selectable item-type code "question".

Initial application:
The issue was applied in git commit ab6c5dc46b83b18ec448260d6b9d2759b4993c30, which first excluded the code "question" from the Questionnaire item-type value set. A later cleanup commit, 96361f6c04af0565a4c3d453debfe32a2d2cb8ec, moved the enforced binding on Questionnaire.item.type to the new http://hl7.org/fhir/ValueSet/item-type-useable value set that includes all item-type codes but excludes "question".

Additional context:
The originating Zulip thread and FHIR SDC minutes both support the narrow decision to keep "question" out of the required Questionnaire.item.type binding. The current CI build renders ValueSet/item-type-useable and binds Questionnaire.item.type to it, so the build has the intended enforcement. A later related issue, FHIR-55181, is still Resolved - change required and concerns separate future guidance for unsupported answer types; it does not reopen use of the non-selectable "question" code.

AutoFHIR reconciliation:
This commit leaves the applied binding model intact and corrects the new value set's description so it names Questionnaire.item.type and the actual excluded non-selectable code "question", rather than the nonexistent Questionnaire.type element and nonexistent "questionnaire" code.

Recommendation:
Keep this commit as-is. The current source already enforces the requested exclusion through a required binding to ValueSet/item-type-useable; this small text correction prevents the value set description from contradicting that implementation.
