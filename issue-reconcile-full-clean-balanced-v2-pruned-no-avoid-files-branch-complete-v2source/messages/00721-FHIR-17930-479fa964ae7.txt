FHIR-17930: Move ClaimResponse fundsReserve after payeeType

Issue request:
FHIR-17930 is Published/Persuasive for FHIR-core ClaimResponse. It requested renaming ClaimResponse .reserve/.reserved to fundsReserve to match Claim and relocating the element to follow the payee information.

Initial application:
The 2018-11-05 FM batch commit afb5ec66f68641293bb7950b6e0eeb118fa1444a explicitly listed 17930 and renamed the spreadsheet row from ClaimResponse.reserved to ClaimResponse.fundsReserve, with the R3/R4 rename map later recording ClaimResponse.reserved=ClaimResponse.fundsReserve. That application did not complete the placement part: the spreadsheet, the 2021 StructureDefinition source rework, R5, and the current source all kept fundsReserve after ClaimResponse.payment.

Additional context:
ClaimResponse is an active current-build resource in source/fhir.ini, so source/claimresponse/structuredefinition-ClaimResponse.xml is the authoritative source for the built ClaimResponse StructureDefinition. The current resource has payeeType rather than a root payee backbone, making payeeType the current root element corresponding to the issue's payee placement request. Searches found no later Jira, Zulip, or Confluence decision that supersedes the requested placement. Later FHIR-53057 changed FM resource bindings, so the existing preferred fundsReserve binding was preserved unchanged.

AutoFHIR reconciliation:
Moved the existing ClaimResponse.fundsReserve element block in source/claimresponse/structuredefinition-ClaimResponse.xml from after ClaimResponse.payment.identifier to immediately after ClaimResponse.payeeType. No element definition, type, cardinality, binding, or narrative text was changed; only the source element order was corrected.

Recommendation:
Keep this commit as-is. It completes the remaining applied issue scope in an active authoritative source file while preserving later binding changes and avoiding edits to generated-looking diagram artifacts.
