FHIR-41175: Harmonize translate terminology service example

Issue request:
FHIR-41175 was Applied/Persuasive for R6 by the Vocabulary work group. It asked to harmonize ConceptMap $translate source-side input naming by changing the `system` and `version` input parameters to `sourceSystem` and `sourceVersion`, documenting the old names, and updating examples that still used `code` instead of `sourceCode`.

Initial application:
The Jira-tagged implementation commit 1b72c2ec36 updated the authoritative ConceptMap $translate OperationDefinition and the generated operation-page request examples, but it did not touch the active Terminology Service narrative page. That page still listed `system` beside `sourceCode` for ConceptMap-translate and still showed a $translate request using `system`, `code`, `source`, and `target`.

Additional context:
The Terminology Service page is part of the current build via publish.ini and source/hierarchy.xml. The October 2024 Zulip thread records the compatibility concern that led to documenting old names as still acceptable aliases, while the January 2025 Vocabulary minutes and Jira resolution confirm the work group decision to use the source-prefixed names for R6.

AutoFHIR reconciliation:
Updated source/terminology-service.html so the ConceptMap-translate required-parameter summary and example use `sourceSystem`, `sourceCode`, `sourceScope`, and `targetScope`, matching the current OperationDefinition and operation example source.

Recommendation:
Keep this commit as-is. It completes the current-core application of FHIR-41175 for the active Terminology Service page without changing compatibility notes or unrelated $translate behavior.
