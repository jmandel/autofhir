FHIR-17380: Exclude deprecated fasting status code

Issue request:
FHIR-17380 was Published/Persuasive with Modification for the OO work group. It asked to add patient fasting status to Specimen.collection as a 0..1 choice of CodeableConcept bound extensibly to HL7 v2 table 0916, excluding the deprecated concept, or Duration, and to document that Observation precoordination or component representation is possible but not recommended.

Initial application:
The issue was initially applied by git commit 1e393840340e8a3496634052422cf0e9018e7d9b, which added Specimen.collection.fastingStatus[x] to the then-authoritative Specimen spreadsheet with CodeableConcept|Duration, the FastingStatus binding, and the Observation modeling guidance. The later source rework in 33b409a4b6d544598262f2f074ebb4b6dc466157 carried the element into source/specimen/structuredefinition-Specimen.xml. Current source retained the element, choice types, extensible binding, and guidance, but the binding still targeted the full THO v2-0916 value set rather than excluding deprecated code FNA.

Additional context:
Specimen is an active core resource in source/fhir.ini, and the checked-in StructureDefinition and companion diagram feed the current build. THO 6.5.0 marks v2-0916 code FNA as deprecated while ValueSet/v2-0916 composes the full code system, so binding directly to the THO value set does not implement the Jira/minutes requirement to exclude the deprecated concept. A 2025 terminology Zulip thread confirms the practical issue: Specimen.collection.fastingStatus currently exposed both unknown-style codes NG and deprecated FNA through the v2-0916 value set.

AutoFHIR reconciliation:
This commit adds a Specimen Fasting Status value set in the Specimen source folder that imports THO ValueSet/v2-0916 and explicitly excludes CodeSystem/v2-0916 code FNA. It changes Specimen.collection.fastingStatus[x] to bind to that local value set and updates the checked-in Specimen diagram link/text so the build-facing diagram no longer points at the unfiltered THO value set.

Recommendation:
Keep this source fix as-is. It preserves the already-applied element and guidance while completing the unresolved deprecated-code exclusion from the published OO decision; no broader fasting-status or Observation modeling change is supported by the evidence.
