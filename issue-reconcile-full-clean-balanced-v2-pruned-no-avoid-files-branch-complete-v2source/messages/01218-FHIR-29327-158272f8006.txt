FHIR-29327: Point IG example at existing Patient

Issue request:
FHIR-29327 was a Published/Persuasive FHIR-I technical correction for the ImplementationGuide example. The reported Resources > RelativePath row linked to patient-test.html#patient-test and referenced Patient/test, producing a 404; the final resolution was to refer to a Patient example instance that actually exists, with Patient/pat1 offered as an example.

Initial application:
The issue was partially applied by commit 9b6c763d4300e7daab3fb6ba1ffa4d1141e8b2ed, which changed the manifest relativePath and page anchor from patient-test.html#patient-test to patient-example.html but left both definition and manifest resource references as Patient/test. That kept the active example pointing at a non-existent Patient resource.

Additional context:
The original Zulip report and FHIR-I minutes both confirm that the problem was a link/reference to a resource that does not exist and that the example should point to a real Patient example in the core spec. The source file is in build scope because source/fhir.ini lists ImplementationGuide as an active resource and list-ImplementationGuide-examples.xml includes ImplementationGuide/example. Later FHIR-41590 reconciliation moved the example's DAF/US Core profile identifiers to example.org, so this reconciliation should not restore the older US Core profile assumption; it should only fix the stale Patient/test reference. Patient/example is an existing core Patient example and matches the already-applied patient-example.html relativePath.

AutoFHIR reconciliation:
Updated source/implementationguide/implementationguide-example.xml so both ImplementationGuide.definition.resource.reference and ImplementationGuide.manifest.resource.reference point to Patient/example instead of Patient/test. No other source was changed.

Recommendation:
Keep this source fix as-is. It completes the remaining FHIR-29327 intent while preserving the later example.org profile changes from FHIR-41590; if FHIR-I later prefers the exact Patient/pat1 example mentioned in Jira, both the reference and relativePath should be changed together in a separate review.
