FHIR-22824: Clarify continuous-variable score type

Issue request:
FHIR-22824 was Published/Persuasive for R5 and asked MeasureReport measureScore elements to support dateTime, CodeableConcept, Period, Range, and Duration results for system-health metrics. Its resolution also called for promoting the Quality Measure IG aggregateMethod extension to Measure and documenting that a continuous-variable report score's type is determined by the aggregate method operation result type.

Initial application:
Commit ee73226e8c (J#22824) changed both MeasureReport.group.measureScore and MeasureReport.group.stratifier.stratum.measureScore to choice elements and added the requested dateTime, CodeableConcept, Period, Range, and Duration choices. Commit 2ddef90c0a (J#28936) separately promoted aggregateMethod to Measure.group.population.aggregateMethod, matching the extension-promotion part of the resolution. The current source/fhir.ini keeps Measure and MeasureReport as active resources, so these StructureDefinition sources are in the current build.

Additional context:
Later MeasureReport changes added boolean and Ratio score choices without removing the FHIR-22824 choices. FHIR-41272 later incorporated broader quality-measure scoring guidance into the Quality Reporting topic, but the current text still did not explicitly say which measureScore[x] choice type is reported for continuous-variable measures. A Zulip thread about DEQM alternate score values confirms FHIR-22824 was the intended R5 solution for non-Quantity score value types; Confluence and additional Zulip searches found no conflicting WG guidance.

AutoFHIR reconciliation:
This commit keeps the existing score choices and adds the missing type-selection clarification to both MeasureReport measureScore[x] element comments and the continuous-variable-measures guidance in clinicalreasoning-quality-reporting.html. The new text states that the reported measureScore[x] type is the result type produced by applying aggregateMethod to the individual Measure Observation results.

Recommendation:
Keep this source fix. It completes the still-missing documentation portion of FHIR-22824 without changing the already-applied score choice set or reopening related extension/backport questions such as FHIR-28077.
