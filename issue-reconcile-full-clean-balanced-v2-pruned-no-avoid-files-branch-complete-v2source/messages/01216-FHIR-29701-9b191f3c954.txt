FHIR-29701: Add Group member-active search parameter

Issue request:
FHIR-29701 is a Published/Persuasive FHIR-I change request for FHIR-core Group. It asked for a way to search Groups by active members after inactive:not=true did not work; the approved resolution says to add a member-active search parameter that works like the existing member parameter but only includes Groups where the specified member has Group.member.inactive = false or Group.member.inactive is omitted.

Initial application:
No Jira-tagged source commit for FHIR-29701 was found in the current repository history. The current Group source already had the ordinary Group-member search parameter and later active-membership narrative, but the active Group search parameter bundle did not contain member-active, so the Jira resolution was not fully applied to the current build source.

Additional context:
Group is an active resource in source/fhir.ini, and source/group/bundle-Group-search-params.xml is the active Group search-parameter bundle that feeds the resource search parameter registry. FHIR-I minutes for 2020-12-07 record the same vote and member-active wording. Later FHIR-37846 added Group membership guidance around active members and _in behavior, but it did not replace or conflict with the narrower FHIR-29701 request to add a reference search parameter filtered by inactive=false or omitted.

AutoFHIR reconciliation:
Added Group-member-active to source/group/bundle-Group-search-params.xml with the same path basis and reference type as Group-member, code member-active, and a FHIRPath expression selecting Group.member.entity only when inactive is empty or false. No narrative change was made because the existing Group membership section already explains active-member semantics; the missing conformance surface was the search parameter itself.

Recommendation:
Keep this source-changing commit. If the work group later wants member-active to incorporate time-period membership testing as well as inactive status, that should be handled as a separate explicit tracker because FHIR-29701's approved resolution was specifically scoped to inactive=false or omitted.
