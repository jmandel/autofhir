FHIR-39596: Separate characterization from structure terminology

Issue request:
FHIR-39596 was Published/Persuasive with Modification for R5. It asked BRR to add a SubstanceDefinition.characterization backbone rather than continuing to carry characterization details under SubstanceDefinition.structure, to use the comment-specified attributes/cardinalities/data types including markdown description text, and to remove characterization remnants such as HPLC from the structure technique terminology.

Initial application:
The current source had already added SubstanceDefinition.characterization and the approved technique, form, description, and file children through pre-application commits and follow-up wording cleanup. It also removed characterization wording from the structure and representation element definitions. However, the characterization technique still reused the SubstanceStructureTechnique binding, and the active substance-structure-technique value set/code system still included the characterization-specific HPLC code and a value set description saying "structure or characterization."

Additional context:
SubstanceDefinition is active in source/fhir.ini, so source/substancedefinition files are current-build inputs. Earlier related issues FHIR-26635, FHIR-26940, and FHIR-32115 explain how characterization wording previously entered structure.technique and representation.type, while the 2022 BRR minutes for FHIR-39596 approve moving the finalized characterization details into their own backbone. Zulip and broader Confluence searches found no conflicting community discussion.

AutoFHIR reconciliation:
This commit removes the StructureTechnique value-set binding from SubstanceDefinition.characterization.technique, removes HPLC from the SubstanceStructureTechnique code system, and narrows the substance-structure-technique value set description to structure only. It leaves the characterization technique as an unbound CodeableConcept with the approved HPLC textual example because the Jira decision did not approve a separate core characterization terminology.

Recommendation:
Keep this source fix. If BRR later wants standardized characterization technique codes, open a separate terminology change for a dedicated characterization value set/code system instead of reusing the structure technique value set.
