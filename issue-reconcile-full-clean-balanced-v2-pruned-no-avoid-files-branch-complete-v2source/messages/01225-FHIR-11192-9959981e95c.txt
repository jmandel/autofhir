FHIR-11192: Clarify Specimen processing method wording

Issue request:
FHIR-11192 was a Published FHIR-core Specimen change request with a Persuasive with Modification resolution. It said the DSTU2 `Specimen.treatment` name and "Treatment and processing step details" wording could be confused with clinical treatment, requested `processingDetails`, and was finally resolved as "change .treatment to .processing".

Initial application:
The historical Jira-tagged implementation commit 29f4601440af8375fc9f1e19f0d38727cd29aec4 renamed the Specimen backbone and example/spreadsheet rows from `Specimen.treatment` to `Specimen.processing`, including the parent short and time wording. That same patch left the child procedure short as "Indicates the treatment step  applied to the specimen", which survived in the current generated StructureDefinition as `Specimen.processing.method`.

Additional context:
`source/fhir.ini` actively lists `specimen=Specimen`, so `source/specimen/structuredefinition-Specimen.xml` is in current build scope. Current source already has `Specimen.processing` and no remaining `Specimen.treatment` path under `source/specimen`; later Specimen processing issues changed separate details such as time duration and bindings, not this residual clinical-treatment wording. Targeted Zulip and Confluence searches found no community evidence requiring the old wording to remain.

AutoFHIR reconciliation:
This commit updates the active `Specimen.processing.method` short description from "Indicates the treatment step  applied to the specimen" to "Indicates the processing step applied to the specimen". The hunk is necessary because the remaining short description appears in the same processing backbone that FHIR-11192 renamed specifically to avoid clinical treatment ambiguity.

Recommendation:
Keep this source fix as-is. No further core source work is needed for FHIR-11192 unless a work group later wants broader editorial cleanup of the Specimen processing definitions.
