FHIR-23851: Clarify StructureMap transform map parameters

Issue request:
FHIR-23851 was Published/Persuasive with Modification for R5. It asked StructureMap.$transform to allow a StructureMap resource to be passed directly, in addition to the existing canonical URI input, and proposed both a direct resource parameter and a Reference parameter. The final resolution accepted passing the StructureMap resource but declined adding a Reference parameter absent a separate strong use case.

Initial application:
The issue was applied in 014ed815 by adding the sourceMap input parameter of type StructureMap and updating the source URI parameter wording, then in d0a1c4d by adding supportingMap and srcMap parameters for dependency maps and mapping-language text. Those commits are contained in v5.0.0, and the current operation definition is listed by source/structuremap/list-StructureMap-operations.xml.

Additional context:
The Jira-linked PR 2615 identifies FHIR-23851 as part of the R5 update set, and the Jira-linked Zulip thread discussed the same ValueSet.$expand-style pattern, dependency maps, and text-map support. FHIR-27761 later marked sourceMap as type-scoped on the combined branch. The current source intentionally uses the published parameter name sourceMap rather than the issue's proposed structureMap name, but two descriptions still referred to structureMap, which is not a current parameter name.

AutoFHIR reconciliation:
Updated source/structuremap/operationdefinition-StructureMap-transform.xml so the source URI documentation points to sourceMap and the srcMap documentation says it is the mapping-language form of sourceMap rather than referring to a nonexistent structureMap parameter. No Reference parameter was added because the final resolution explicitly deferred that to a future tracker.

Recommendation:
Keep this source fix. The substantive direct-StructureMap input requested by FHIR-23851 is already present, and this commit removes the remaining misleading cross-reference while preserving the published sourceMap parameter name and the no-Reference decision.
