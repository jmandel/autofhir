FHIR-22765: Add Encounter length duration invariant

Issue request:
FHIR-22765 was Published/Not Persuasive with Modification for R5. It requested removal of Encounter.length because recalculated duration could be stale, but the approved resolution kept Encounter.length as the actual duration and required clearer wording, a PV2-11 mapping, an estimated-duration approach outside this element, and an invariant ensuring length does not exceed the period when computable.

Initial application:
The historical application commit 7ac7c3010e5c7c604804b1a8831b7df36add8a03 changed source/encounter/structuredefinition-Encounter.xml so Encounter.length is explicitly actual, added the missing-value and low-precision clarification, and updated the v2 mapping to include PV2-11. That commit did not add the requested invariant. Later reconciliation commit 55b6972198ad1e12d56bfb6615d9df709a4f152b aligned the FHIR-22765 length comment from the old Encounter.period name to Encounter.actualPeriod after FHIR-32351.

Additional context:
Encounter is an active resource in source/fhir.ini, so source/encounter/structuredefinition-Encounter.xml feeds the current build. FHIR-32351 later renamed Encounter.period to Encounter.actualPeriod and separated planned dates, so the FHIR-22765 period comparison now needs to use actualPeriod. Targeted Jira searches found no later Encounter.length issue reversing the Published FHIR-22765 decision. Zulip and Confluence evidence shows the original removal concern and PA scheduling/deferral context but no conflicting final decision.

AutoFHIR reconciliation:
This commit adds root invariant enc-4 to Encounter. The invariant passes when length or the actualPeriod bounds are absent, passes when the period comparison cannot be computed, and otherwise requires actualPeriod.start plus length to be less than or equal to actualPeriod.end. This completes the remaining conformance part of the published resolution without changing generated SVG output.

Recommendation:
Keep this source fix as-is. It is a narrow completion of the published FHIR-22765 resolution; future work should only revisit it if PA wants a different computability rule for partial dateTime precision or non-comparable duration units.
