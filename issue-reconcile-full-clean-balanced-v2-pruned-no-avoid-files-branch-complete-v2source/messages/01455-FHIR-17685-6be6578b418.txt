FHIR-17685: Align remaining useContext definitions

Issue request:
FHIR-17685 was a Published/Persuasive FHIR-I change request for STU3 asking to clarify what "context" means for Questionnaire.useContext. The approved resolution added the usage-context-type code "program", allowed UsageContext.value[x] references to PlanDefinition, ResearchStudy, InsurancePlan, HealthcareService, Group, Location, and Organization, updated the Questionnaire.useContext definition to distinguish general categories from references to specific programs, and requested that this clarified definition be applied across conformance resources and the UsageContext datatype.

Initial application:
The issue was initially applied by git commit 46401227c3 ("GF#17685 - extend definition of use context"), which changed the UsageContext datatype spreadsheet and the then-current metadata resource spreadsheet. Current source still has UsageContext in source/fhir.ini, retains the added "program" usage-context-type code and the expanded UsageContext.value[x] reference choices, and carries the clarified definition on CanonicalResource.useContext and most derived resources.

Additional context:
The linked Zulip discussion shows the ambiguity that prompted the issue: participants distinguished keyword-like categories from references to specific programs or studies. Later FHIR-38841 reused the clarified useContext wording while moving topic/jurisdiction guidance into UsageContext, so it did not reverse the FHIR-17685 interpretation. A current source sweep found two active top-level resource useContext definitions that still had the older "These terms" wording; SubscriptionTopic also incorrectly referred to "code system definitions." SpecimenDefinition and SubscriptionTopic are active source/fhir.ini resources, so these source files are in the current build scope.

AutoFHIR reconciliation:
This commit updates SpecimenDefinition.useContext and SubscriptionTopic.useContext to include the FHIR-17685 clarified categories/programs wording, using resource-specific endings. It also removes the now-obsolete SubscriptionTopic definition-mapping exception because the resource definition now matches the Definition.useContext pattern for that semantic text.

Recommendation:
Keep this commit as-is. The remaining changes are narrow, source-backed, and align active current resources with the published FHIR-17685 decision without changing unrelated local nested useContext elements such as DeviceDefinition guideline or charge item contexts.
