FHIR-16140: Clarify Glasgow QuestionnaireResponse example

Issue request:
FHIR-16140 was a Published OO change request with Persuasive with Modification resolution. It asked how QuestionnaireResponse can be a member of Observation.hasMember and requested clarification with examples or removal. The accepted resolution pointed to the Glasgow QA example and said to add language that a system may calculate questionnaire answers or another resource into a final score or measurement represented as an Observation.

Initial application:
The 2018-07-24 GF#16140 batch commit 2ebd7c6f7fc99b6938d5a223685af7907288d11c added the hasMember comment that now appears in the generated/current Observation StructureDefinition, while the Glasgow QA example and QuestionnaireResponse reference were already present. The 2021 source rework commit 33b409a4b6d544598262f2f074ebb4b6dc466157 carried that applied text into source/observation/structuredefinition-Observation.xml.

Additional context:
Observation and QuestionnaireResponse are active resources in source/fhir.ini, so the Observation resource page, examples, and example List entries are in current build scope. Current Observation.hasMember still permits QuestionnaireResponse and includes the accepted clarification. The Glasgow QA Observation references QuestionnaireResponse/gcs using derivedFrom, and the QuestionnaireResponse/gcs source example exists. Later core issues FHIR-44836 and FHIR-48420 narrowed the vital-signs profile use of hasMember/derivedFrom, but they do not remove the base Observation QuestionnaireResponse references.

AutoFHIR reconciliation:
This commit updates the Glasgow QA example title/description and inline example comments to say QuestionnaireResponse and derived-from instead of obsolete QuestionnaireAnswer/related wording. It intentionally leaves the base Observation.hasMember reference targets and accepted clarification unchanged.

Recommendation:
Keep this commit as-is. It completes the published clarification with a low-risk source cleanup on the linked example; any future decision to remove or further constrain QuestionnaireResponse references in base Observation should be handled by a separate work-group issue.
