FHIR-24898: Clarify Consent unknown status scope

Issue request:
FHIR-24898 was Published/Persuasive with Modification for FHIR-core Consent. It requested changing the required Consent.status value set by removing `proposed` and `rejected`, adding `unknown`, and adding a note that `unknown` can only be used with formerly active consents.

Initial application:
No commit explicitly mentioning FHIR-24898 was found. Commit 2da480ca69 appears to be the initial application despite listing adjacent GF tickets: it changed the Consent spreadsheet status short list from `draft | proposed | active | rejected | inactive | entered-in-error` to include `unknown` and remove `proposed`/`rejected`. Follow-up 2019 commits fixed the short-list spacing and binding/status-code build fallout. The active-only note was present only as a spreadsheet committee note, which was not published into the current CodeSystem definition, and the Consent.status element comment still named the removed `rejected` code.

Additional context:
Consent is active in the current build via source/fhir.ini, and codesystem resources are also active build inputs. Later same-family decisions affect wording but not the active-only rule: FHIR-31377 and FHIR-31769 clarify that ConsentState describes the Consent resource rather than the patient's consent itself, while FHIR-36263 adds the later `abandoned` status for pre-active consent requests that expire. Zulip and Confluence searches found no later decision broadening `unknown` beyond the FHIR-24898 active-only scope.

AutoFHIR reconciliation:
Updated the authoritative Consent state CodeSystem so the `unknown` definition publicly carries the active-only note using current resource-scoped wording. Also removed stale `rejected` wording from the active Consent.status element comment and the matching Event mapping exception, aligning both with the current status code set and modifier reason.

Recommendation:
Keep this source fix. It completes the published FHIR-24898 semantics while preserving later Consent status-family decisions; any future decision to broaden `unknown` beyond formerly active Consent resources should be handled as a separate terminology change.
