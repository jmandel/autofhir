FHIR-22655: Enforce decimal mantissa digit limit

Issue request:
FHIR-22655 was Published with a Persuasive resolution for FHIR-core datatypes. It asked whether FHIR decimal values were otherwise unbounded outside the XML and JSON representation notes, and the approved resolution was to change the decimal description and regex to say a decimal cannot have more than 18 digits and a decimal point.

Initial application:
The issue was partially applied by d621ab0bda, which added the 18-digit statement to source/datatypes.html. Commit baee733e3e then attempted to update the decimal regex in source/datatypes/primitives.xml, but it introduced an extra closing brace and still allowed up to 18 digits before the decimal point plus up to 17 after it. FHIR-53492 later removed the extra brace but intentionally left the leading-zero requirement in place.

Additional context:
source/datatypes.html is the active datatypes narrative page, source/datatypes/primitives.xml is the active primitive datatype spreadsheet source used for generated primitive metadata and regex substitution, source/xml.html gives the decimal pattern for implementers who choose an xs:string schema override, and source/datatypes-examples.html is linked from the datatypes page and navigation. Current source still had a high-precision pi example with far more than 18 mantissa digits and an XML pattern/example regex that matched decimals exceeding the approved limit.

AutoFHIR reconciliation:
This commit clarifies the decimal narrative as an 18-digit mantissa limit, updates the primitive spreadsheet definition and regex so the regex permits no more than 18 mantissa digits while preserving the existing exponent branch and leading-zero requirement, aligns the XML schema override pattern with that regex, and shortens the primitive decimal examples so they remain valid high-precision examples under the limit.

Recommendation:
Keep this commit. It completes the published FHIR-22655 change in the active datatype sources and examples while preserving the later FHIR-53492 decision not to allow decimals such as .5.
