FHIR-7123 + FHIR-6129: Use Procedure.code in notes example

Attribution note: surfaced while reviewing FHIR-7123, but direct Jira backing for this change is FHIR-7123 + FHIR-6129.

Issue request:
FHIR-7123 was Published/Persuasive with Modification for DSTU1 Procedure and asked to clarify the difference between Procedure.category and the then-named Procedure.type by renaming type/name on Procedure and ProcedureRequest, adding examples for category versus the specific procedure, and adding notes that related details such as category, bodySite, and indication/reason can sometimes be inferred from the procedure name.

Initial application:
The historical application was commit 77c0aa01f08d8517bcba177c89b296095491221d, which explicitly cited #6129 and #7123 and renamed Procedure.type to Procedure.code, updated examples and profiles, and changed the Procedure binding from ProcedureType to ProcedureCode. Current Procedure source already has Procedure.category as a high-level classification with the "Surgical Procedure" example and Procedure.code as the specific procedure with the "Laparoscopic Appendectomy" example.

Additional context:
Related FHIR-6129 was later Published/Persuasive and changed the intermediate Procedure.name direction to Procedure.code for Procedure and ProcedureRequest. ProcedureRequest is no longer in the current build and is represented by ServiceRequest, whose category and code definitions are already consistent with the resolved distinction. Procedure is an active current resource in source/fhir.ini, and procedure-notes.xml is the active Procedure notes source. The only discovered current-source drift was the notes example still saying "name=amputation" even though the current element is Procedure.code. Zulip and Confluence searches found no relevant conflicting community discussion.

AutoFHIR reconciliation:
Updated source/procedure/procedure-notes.xml so the nonsensical-combination example uses "code=amputation" instead of the obsolete "name=amputation" wording. This keeps the note aligned with the current Procedure.code element while preserving the intended FHIR-7123 warning about inconsistent combinations of procedure code/name, body site, and other inferred details.

Recommendation:
Keep this commit as-is. It is a narrow source fix to active Procedure narrative and no further core source work is needed for FHIR-7123 unless a work group wants a broader editorial refresh of Procedure notes.
