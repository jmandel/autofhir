FHIR-27113: Correct REST trailing slash example

Issue request:
FHIR-27113 was Published/Persuasive with Modification for R5. It asked the RESTful HTTP specification to clarify handling of resource type endpoints with a trailing slash, such as [base]/Patient/, and the accepted resolution says servers SHALL support both trailing-slash and non-trailing-slash forms if they support either, should not redirect merely to canonicalize the query URL, and may choose their preferred convention for self links.

Initial application:
The issue was initially applied by PR HL7/fhir#1124 and commit 819e92b2ed43d416fd6f01342543e90fc4eb3245, which added the required paragraph to source/http.html. That application captured the SHALL, redirect, and canonicalization semantics, but the non-trailing example was malformed as [base]/type].

Additional context:
source/http.html is in current build scope as the RESTful API page listed in source/hierarchy.xml. The Zulip thread linked from Jira supports the intended equivalence/dropped-slash behavior, and the FHIR-I 2020-08-17 minutes record the Persuasive with Modification vote. Searches for later Jira decisions about permanent redirects, canonical query URL, or HTTP identity/trailing slash found no final follow-up changing this rule.

AutoFHIR reconciliation:
This commit keeps the approved normative behavior unchanged and corrects the malformed non-trailing URL example to [base]/[type], with light punctuation cleanup in the same sentence so the two examples are parallel and unambiguous.

Recommendation:
Keep this source fix as-is. It is a narrow correction to the original application in an active build page and does not reopen the policy question about whether servers should redirect or canonicalize trailing-slash resource-type requests.
