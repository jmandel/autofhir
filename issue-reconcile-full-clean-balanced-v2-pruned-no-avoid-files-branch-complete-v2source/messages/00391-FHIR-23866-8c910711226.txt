FHIR-23866: Replace stale BodyStructure laterality example code

Issue request:
FHIR-23866 was Published/Persuasive with Modification for FHIR-core ValueSet content. It reported that the left/right concepts in the laterality value set were inactive SNOMED CT concepts 419161000 and 419465000, and requested replacement with active concepts 7771000 Left and 24028007 Right.

Initial application:
No explicit FHIR-23866 commit was found in the current git history. Later source history corrected the closely related BodyStructure relative-location value set under FHIR-29810/FHIR-32889, and FHIR-45256a later split BodyStructure.includedStructure.laterality into its own bodystructure-laterality value set containing 7771000 Left and 24028007 Right. The current value set source is therefore already semantically aligned with FHIR-23866.

Additional context:
FHIR-31571 is a duplicate report of the same inactive bodysite-laterality concepts. Jira comments on FHIR-23866 and the linked Zulip thread show that ImagingStudy moved away from a FHIR-managed bodysite-laterality value set toward DICOM canonical value sets, while the current core build now has BodyStructure as an active resource with BodyStructure.includedStructure.laterality bound to http://hl7.org/fhir/ValueSet/bodystructure-laterality. Two active BodyStructure examples still used 419161000 for laterality, which would continue to publish the inactive code even though the current value set uses the approved replacement.

AutoFHIR reconciliation:
Updated source/bodystructure/bodystructure-example.xml and source/bodystructure/bodystructure-example-skin-patch.xml to use SNOMED CT 7771000 with display Left for the laterality coding, matching the active replacement already used by the current value set and by the DICOM-derived BodyStructure example. No changes were made to generated SVG artifacts.

Recommendation:
Keep this commit. The authoritative value set is already correct, and this narrowly removes the remaining in-build example use of the inactive left-laterality concept. No follow-up is required for core unless the work group wants to audit other non-core packages that may still publish the old bodysite-laterality value set.
