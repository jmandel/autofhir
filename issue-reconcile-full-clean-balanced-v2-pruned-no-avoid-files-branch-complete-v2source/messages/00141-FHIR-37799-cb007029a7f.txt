FHIR-37799: Align Consent provision search descriptions

Issue request:
FHIR-37799 was Published/Persuasive with Modification for FHIR-core Consent. It asked to remove ambiguity by renaming Consent.dateTime to Consent.date with date type and fully executed date semantics, changing Consent.provision.period to "Timeframe for this provision", and replacing provision element definitions that used "rule" with "provision".

Initial application:
No source commit message explicitly mentioned FHIR-37799. Git history shows commit 89587cb0d9612f16695f4451d6653a53e300d846 changed Consent.dateTime to Consent.date, made the element type date, updated provision element text from rule to provision, and updated Consent examples. Current source/fhir.ini also maps the old Consent.dateTime name to Consent.date. The initial application did not update three active Consent search parameter descriptions copied from the old provision element shorts.

Additional context:
Consent is active in the current build through source/fhir.ini. Later Consent work already represented on the combined branch changed the provision model and search parameters, including FHIR-39597, FHIR-53188, FHIR-41456, and FHIR-39394, but it did not supersede the FHIR-37799 wording requirement. Current StructureDefinition/Consent already contains the approved Consent.date and provision element definitions. Generic consent narrative and terminology references to rules were left alone because the Jira resolution targeted provision element wording, and the current Consent narrative still intentionally describes policy rules as a concept.

AutoFHIR reconciliation:
This commit updates source/consent/bundle-Consent-search-params.xml so the active Consent action, period, and purpose search parameter descriptions use "provision" instead of the old "rule" wording. This aligns the conformance search-parameter surface with the authoritative Consent.provision element definitions.

Recommendation:
Keep this commit as the bounded FHIR-37799 source fix. No further core source change is needed for the seed unless the work group separately approves a broader terminology or narrative rewrite of generic "rule" language.
