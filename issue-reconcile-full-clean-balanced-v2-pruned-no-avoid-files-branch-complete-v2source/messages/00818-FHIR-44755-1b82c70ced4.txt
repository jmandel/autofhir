FHIR-44755: Remove duplicate Specimen accession identifiers

Issue request:
FHIR-44755 is Applied/Persuasive with Modification for FHIR-core Specimen. It asked OO to treat Specimen.accessionIdentifier as an Identifier, guide implementers to use Identifier.type ACSN for accession identifiers, require any accessionIdentifier value to also appear in Specimen.identifier, and request ballot feedback on when accessionIdentifier should be removed.

Initial application:
The issue was applied in the jdlnolen FHIR-44755 branch family. Commits including 5c58797949e400d0fd9a158d995f47d63ce33011, f4eaf8b4bf43efa46aec119ce485743e3d885d0b, 798efcf14a11e242caf2fbffc7a5775a9b0290c0, and 42131285033ba6d789e32191b1fdba888f2443f0 added ACSN-typed Specimen.identifier examples, added/refined the spm-2 accessionIdentifier-to-identifier invariant, and adjusted Specimen text. The Jira comment cited PR #3496 commit f4b98d0134e3065b4ac2161585346169b46c7c1d, which is a merge commit rather than the direct source hunk.

Additional context:
FHIR-53092 is a later Applied/Persuasive R6 decision for the same Specimen accessionIdentifier family. It removed the trial-use Specimen.accessionIdentifier element, the spm-2 invariant, and the accession search parameter, while retaining the ACSN guidance on Specimen.identifier. A prior combined-branch reconcile commit for FHIR-53092 already removed remaining accessionIdentifier uses outside source/specimen, so this commit does not duplicate that issue. source/fhir.ini lists Specimen as an active resource; the remaining fhir.ini Specimen.accessionIdentifier lines are R4/R5-to-R6 migration notes, not active element definitions.

AutoFHIR reconciliation:
Removed exact duplicate ACSN-typed Identifier blocks from the active Specimen examples for isolate, pooled-serum, and urine. Each affected Specimen instance now carries the accession number once in Specimen.identifier with Identifier.type code ACSN, matching FHIR-44755's model without implying duplicate accession identifiers.

Recommendation:
Keep this fix as-is. FHIR-53092 should remain represented by its existing combined-branch commit; future example updates should avoid reintroducing duplicate identifiers when demonstrating the ACSN replacement for accessionIdentifier.
