FHIR-7795: Correct IG global profile reference

Issue request:
FHIR-7795 was a Published / Persuasive FHIR-core change request from DSTU1 asking for a better way to constrain resource references so profile authors would not need to create a fan-out network of profiles just to require references to profiled resources. The approved resolution was to add the ImplementationGuide resource, with default package/profile behavior, and to let conformance/capability declarations identify implementation guides.

Initial application:
The issue was explicitly applied in the legacy SVN-imported history. Commit 729187b0fe3060973603330b99a00c0e74a19f92, matching Jira's recorded SVN revision 5523, pre-applied the ImplementationGuide resource and added it to source/fhir.ini and the resource list. Follow-up commits 3747b014f93d542c6f8daaa989d89e4d29578f57 and fd41a51bfc1801d23779d03aa36983c88b101c15 completed the IG infrastructure and defined ImplementationGuide.global plus default-profile narrative.

Additional context:
source/fhir.ini actively lists both ImplementationGuide and CapabilityStatement, so the checked StructureDefinition sources changed and inspected here are in current build scope. Current ImplementationGuide source still defines ImplementationGuide.global as profiles all resources covered by the IG must conform to, and the IG notes still explain that default profiles avoid exhaustively profiling every resource type just to profile every reference to a resource type. Related FHIR-7796 is the same 2015 profile-reference family but is not decided here; FHIR-9374 later confirmed the ImplementationGuide.global solution while rejecting broader server-wide reference constraints. FHIR-39433 later clarified CapabilityStatement.implementationGuide, but its applied text referred to non-existent Implementation.global definitions when the active target element is ImplementationGuide.global.

AutoFHIR reconciliation:
This commit corrects the active CapabilityStatement.implementationGuide comment to refer to ImplementationGuide.global. No other source change is needed because the current active ImplementationGuide resource, its global element, default-profile narrative, and CapabilityStatement implementationGuide element already preserve the approved FHIR-7795 mechanism.

Recommendation:
Keep this source fix. It preserves the long-applied FHIR-7795 design and removes a misleading element reference from the current build-scope CapabilityStatement text; no further core change is needed for FHIR-7795 unless the work group later redesigns default profiles or IG-wide conformance semantics.
