FHIR-7592: Restore extensible binding gap guidance

Issue request:
FHIR-7592 was a Published/Persuasive with Modification FHIR-core Vocabulary issue from the 2015 May ballot. It asked to clarify extensible binding behavior so that alternate codings or text remain possible only when no suitable value-set code applies, and to say that identified value-set gaps should be submitted to the organization administering the value set.

Initial application:
The issue was initially applied by svn revision 5710, now git commit 3cadeb2ffced5a33ea077113bc975cf9114bb86e, which added CodeableConcept and Coding-specific extensible-binding guidance and the sentence that identified value-set gaps should be submitted. Current source retained and later refined the alternate-code/text mechanics, and the CodeableConcept page already explains that CodeableConcept can be represented by text and that text is a preferred source of meaning when no coding is user-selected.

Additional context:
Later extensible-binding work, especially FHIR-16333, FHIR-17402, and FHIR-29968, substantially rewrote the same terminology section. FHIR-29968 was reviewed by Vocabulary, MnM, and FHIR-I in May 2022 and replaced the older prose with a clearer three-case algorithm for extensible bindings. That rewrite removed the original FHIR-7592 value-set-gap submission sentence, but the later Jira and meeting evidence focus on clarifying conformance behavior and do not supersede the seed's value-set curation guidance.

AutoFHIR reconciliation:
Restored a narrow version of the value-set-gap submission sentence in source/terminologies.html immediately after the current extensible-binding decision algorithm. The file is active terminology narrative source, and the hunk is necessary because the current text allowed alternate concepts/text but no longer conveyed the seed issue's instruction that value-set gaps should be fed back to the administering organization.

Recommendation:
Keep this commit. It preserves the later FHIR-29968 conformance algorithm and only restores the seed issue's durable curation guidance; no additional CodeableConcept source change is needed because current datatype text already supports text for human-readable/selected meaning.
