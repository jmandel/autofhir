FHIR-32050: Set AllergyIntolerance FMM to normative

Issue request:
FHIR-32050 is an Applied FHIR-core Patient Care change request asking to update AllergyIntolerance's FHIR Maturity Level to Normative. The final resolution is Persuasive: in alignment with the September 2025 Thursday Q1 Patient Care WGM vote, AllergyIntolerance is planned to go normative in R6.

Initial application:
No prior commit on the combined issue-reconcile branch carried Issue-Reconcile-Key: FHIR-32050, and git history did not show a FHIR-32050-tagged source commit. The current source had been partially aligned by b0795b968d, which removed trial-use status from AllergyIntolerance.type and AllergyIntolerance.reaction, and 5c20769cc7, which changed the AllergyIntolerance StructureDefinition standards-status from trial-use to normative. However, source/fhir.ini and the AllergyIntolerance StructureDefinition fmm extension still said 3.

Additional context:
AllergyIntolerance is an active current-build resource in source/fhir.ini and has FMG approval. FHIR versions.html defines FMM 6 as synonymous with normative standards status. The cited September 2025 Patient Care WGM minutes record the Patient Care normative-resource discussion, including AllergyIntolerance concerns and a 31-0-1 motion to support the documented feedback to FMG. Zulip discussion also records that AllergyIntolerance was expected to be normative in R6 and that Patient Care could resolve old maturity ballot comments based on the intended normative direction. Co-listed maturity issues for Condition and Procedure are the same Patient Care family but concern separate resources and were not decided here.

AutoFHIR reconciliation:
Updated the active AllergyIntolerance resource maturity metadata to FMM 6 in source/fhir.ini and source/allergyintolerance/structuredefinition-AllergyIntolerance.xml. This commit intentionally does not broaden the change to AllergyIntolerance-owned terminology artifacts or generated output because the Jira request and resolution are specifically about the AllergyIntolerance resource maturity level.

Recommendation:
Keep this source fix as-is for R6. If Patient Care wants separate AllergyIntolerance terminology artifact maturity changes, handle those as separate terminology-artifact decisions rather than expanding this resource-level Jira.
