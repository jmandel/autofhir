FHIR-31655: Clarify _elements returned element expectations

Issue request:
FHIR-31655 was Published as Persuasive with Modification for R5. It asked who is responsible for ensuring mandatory and modifier elements are returned when a client uses _elements, because the search page said only listed elements are returned and clients SHOULD list mandatory/modifier elements while also saying servers SHOULD return mandatory elements. The approved resolution replaced the client-side "Only elements" and "Clients SHOULD list" wording with an expectation that returned elements will generally be explicitly requested elements, mandatory elements, or modifier elements with values, while preserving servers' right to return more than requested.

Initial application:
The issue was partially applied by commit 181332c6aeedcdd4d32c68a53fd3438041e6556c, titled "FHIR-31655". That commit added the expected-elements list to source/search.html, but it did not remove the two sentences the Jira resolution said to replace. The current source therefore still contained both the old client-side responsibility language and the newer server-discretion language.

Additional context:
FHIR-27812 is the same _elements mandatory/modifier guidance family and added modifier elements to the server-side SHOULD sentence; this reconciliation preserves that guidance. FHIR-43354 later removed "always" from that server SHOULD sentence and added the note that _elements can be used outside search; the combined branch already contains that later wording and this reconciliation leaves it intact. The FHIR-I minutes for 2021-07-19 record the FHIR-31655 Persuasive with Modification vote, and a later implementers Zulip thread confirms that _elements is a request to filter, not an absolute promise of the minimal possible payload.

AutoFHIR reconciliation:
This commit changes the active FHIR-core search page source, source/search.html, in the _elements section. It removes the obsolete "Only elements that are listed" and "Clients SHOULD list" wording, keeps the approved expectation list, corrects the local "explicity" typo while editing that sentence, and keeps the later REST API note and server SHOULD guidance unchanged.

Recommendation:
Keep this source fix. No separate source change is needed here for FHIR-27812 or FHIR-43354; revisit only if a future work-group decision changes the conformance level or safety guidance for mandatory/modifier elements returned by _elements.
