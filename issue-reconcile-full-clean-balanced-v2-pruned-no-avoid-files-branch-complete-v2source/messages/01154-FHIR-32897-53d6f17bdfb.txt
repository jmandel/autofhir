FHIR-32897: Document display for canonical references

Issue request:
FHIR-32897 was Published with resolution Not Persuasive with Modification. It asked for the workflow instantiates relationship to be able to carry a Reference because sometimes only a display name is available; the final decision was not to add Reference for that reason, but to use the display extension and document that canonical values may legitimately carry a display extension without a primitive value.

Initial application:
The Jira application comment points to Git master 2ee637a94c. That commit removed the old Request/Event instantiatesCanonical and instantiatesUri pattern elements, split the workflow relationship into more specific extensions, and added workflow-extension guidance that mentions the display extension. The canonical primitive datatype row itself still only linked to canonical-reference guidance and did not state the display-extension/no-value rule requested by the issue.

Additional context:
FHIR-29261 and FHIR-29665 were applied in the same 2ee637a94c workflow-extension commit and explain why the old instantiates shape was replaced rather than broadened. The current Extension Pack definitions contain the display extension with context canonical and contain the replacement workflow extensions, including Reference and uri value options where the later workflow model supports them. Confluence minutes for the 2021-06-21 FHIR Workflow call record the FHIR-32897 Not Persuasive with Modification tracker decision, and no conflicting Zulip discussion was found.

AutoFHIR reconciliation:
Updated source/datatypes/primitives.xml, the checked-in primitive datatype source for the canonical row, so the canonical datatype comments now mention http://hl7.org/fhir/StructureDefinition/display and explicitly allow conveying a human-readable canonical target name when the element has extensions but no value. No workflow-extension definition was changed because the current replacement extension definitions already handle computable Reference/uri cases in the Extension Pack.

Recommendation:
Keep this source fix. It completes the missing canonical-datatype documentation required by the published issue while preserving the work group's decision not to use FHIR-32897 to reintroduce or broaden the old instantiates element.
