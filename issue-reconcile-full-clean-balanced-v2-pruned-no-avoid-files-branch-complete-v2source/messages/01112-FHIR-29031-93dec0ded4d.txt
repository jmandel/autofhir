FHIR-29031: Align Observation subject definition

Issue request:
FHIR-29031 was Published with a Persuasive with Modification OO resolution for R5. The original request asked to add Medication and Substance to Observation.subject; the final motion broadened the target list to Medication, Substance, NutritionProduct, and BiologicallyDerivedProduct, with the Medication and Substance use understood as instance-level resources.

Initial application:
The conformance targetProfiles were applied before this reconciliation through the subject-expansion history rather than one complete seed-labeled patch. FHIR-29930 commit 11b15d7ecc added Medication and Substance to Observation.subject, commit c72dfcf4e1 added BiologicallyDerivedProduct, and the FHIR-29031 Jira application comment points to 6f1e492ad5, which added NutritionProduct via PR #1448. Current source/fhir.ini keeps Observation as an active built resource.

Additional context:
OO minutes for 2020-10-15 confirm that FHIR-29031 focused on extending Observation.subject to include Medication, Substance, NutritionProduct, and BiologicallyDerivedProduct, and also record the instance clarification for Medication and Substance. FHIR-29266 and FHIR-29930 handled the closely related DiagnosticReport/subject alignment path separately; FHIR-29930 already has a no-change audit on the combined branch. Zulip searches for the issue key and subject/product terms found no conflicting discussion.

AutoFHIR reconciliation:
This commit updates the authoritative Observation.subject definition in source/observation/structuredefinition-Observation.xml so the prose enumerates the same Medication, Substance, BiologicallyDerivedProduct, and NutritionProduct targets already present in the type list. It also updates source/observation/observation-event-mapping-exceptions.xml, which is in the active Observation source folder and repeats the resource definition for Event.subject mapping divergence, so generated mapping context does not preserve the stale narrower wording.

Recommendation:
Keep this source fix. The targetProfiles already represented the final WG decision, and the remaining reconciliation gap was stale element-definition prose that could mislead readers despite the correct conformance type list. DiagnosticReport-related follow-up should remain with its separate Jira family rather than be folded into FHIR-29031.
