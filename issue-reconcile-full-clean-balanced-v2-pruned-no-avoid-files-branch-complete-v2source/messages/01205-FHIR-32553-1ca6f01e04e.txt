FHIR-32553: Clarify Device UDI issuer examples

Issue request:
FHIR-32553 was a Published, Persuasive with Modification OO change request asking how implementers should determine Device.udiCarrier issuer and jurisdiction URIs. The accepted resolution updated Device.udiCarrier.issuer and Device.udiCarrier.jurisdiction definitions with example issuer and jurisdiction NamingSystem URIs, including non-US examples.

Initial application:
The issue was applied for R5 by the FHIR-32553 source commit a98f426dc9 and merge cc51b0a9, changing source/device/structuredefinition-Device.xml. The current source retained the jurisdiction example, but the issuer definition still said "US FDA issuers" even though the accepted text added an EU IFA example, misspelled ICCBBA as ICCBA in one list item, and collapsed the IFA example into item 4 with a literal # instead of rendering it as its own example.

Additional context:
Device is an active resource in source/fhir.ini and source/device/structuredefinition-Device.xml is the authoritative current Device StructureDefinition; source/device/device.svg carries a checked-in diagram tooltip copied from that definition. Later FHIR-35973 changed the cardinality of Device.udiCarrier.issuer to 1..1 and is already represented on the combined branch. Later FHIR-51533 and Zulip discussion identify unresolved THO/NamingSystem registration and validation questions for these URIs, but FHIR-51533 is still Waiting for Input, so this reconciliation intentionally does not rename, replace, bind, or register the URI values.

AutoFHIR reconciliation:
This commit corrects the applied FHIR-32553 issuer definition so the examples are no longer described as only US FDA issuers, restores ICCBBA spelling for the other-devices issuer, and renders IFA as example item 5. The parallel SVG tooltip was updated with the same wording to avoid leaving the checked-in Device diagram inconsistent with the authoritative StructureDefinition.

Recommendation:
Keep this source correction as-is. The remaining question of whether these URI values should resolve as formal NamingSystems, move to THO, or be represented differently should continue under FHIR-51533 or another explicit OO/terminology decision rather than being inferred from FHIR-32553.
