FHIR-19470: Align MedicationStatement adherence search path

Issue request:
FHIR-19470 was a Published/Persuasive Pharmacy change request for R5 asking to replace the prior MedicationUsage.takenAsOrdered compliance attribute with a CodeableConcept adherence attribute and to rename takenAsOrdered to adherence.

Initial application:
The issue was first partially applied in 2019 by ec284380a4, then substantially applied in 2021 by f351511a95 for FHIR-19468/FHIR-19470/FHIR-28593, which renamed MedicationUsage.takenAsOrdered to MedicationUsage.adherence in the StructureDefinition and search parameter expression. The 2023 FHIR-38682 rename-back commit b2032629f2 converted MedicationUsage references to MedicationStatement but left the search-parameter path extension as MedicationStatement.takenAsOrdered.

Additional context:
FHIR-19468 is the paired decision that removed not-taken semantics from status and moved taking/not-taking representation to the adherence element. FHIR-31573 later corrected MedicationStatement.effective[x] to refer to adherence and is already represented on the combined branch. FHIR-39271, also already represented on the combined branch, confirms the current model: status records the statement state, while adherence carries taking/not-taking information.

AutoFHIR reconciliation:
This commit updates the active MedicationStatement adherence SearchParameter path metadata from MedicationStatement.takenAsOrdered to MedicationStatement.adherence. The SearchParameter id, code, URL, description, and expression already name adherence, and source/fhir.ini lists MedicationStatement as an active resource, so this source file feeds the current build.

Recommendation:
Keep this commit. It is a narrow source correction that completes the already-applied FHIR-19470 rename in the current MedicationStatement search-parameter metadata; no broader MedicationStatement status or adherence redesign is attempted here.
