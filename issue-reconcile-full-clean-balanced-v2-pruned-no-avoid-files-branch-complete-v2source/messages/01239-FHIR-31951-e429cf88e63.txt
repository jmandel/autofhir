FHIR-31951: Correct iterative include example

Issue request:
FHIR-31951 was a Published FHIR-core search clarification resolved as Not Persuasive with Modification for R5. It asked that the iterative include example stop using MedicationRequest:performer, use MedicationRequest:requester instead, and describe the included resources as prescribers rather than Practitioner-only resources because PractitionerRole should also be possible and an explicit target type filter is unnecessary.

Initial application:
No current git commit found with an explicit FHIR-31951 reference. The surrounding _include:iterate text was rewritten in ddecc63591d23dab5767aa2888c985a7c75964b6 and c4676c38e6615ece7697c1c120a80342ede36b2c under FHIR-31939/FHIR-31491; that history changed MedicationRequest:performer to MedicationRequest:requester, but left the Practitioner-only prose and introduced a GET-side Medication:prescription typo while the POST example still used MedicationDispense:prescription.

Additional context:
source/search.html is the current FHIR search narrative page, and source/fhir.ini keeps MedicationRequest, MedicationDispense, Practitioner, PractitionerRole, and SearchParameter active in the build. The MedicationRequest.requester element can reference PractitionerRole and other requester types, while the current MedicationDispense prescription search parameter is MedicationDispense:prescription. FHIR-31939 is the same _include:iterate wording family. FHIR-54054 later noticed the Medication:prescription typo in this example, but it is still Triaged and is not decided separately here.

AutoFHIR reconciliation:
Updated source/search.html so the example says the iterative include returns MedicationRequest resources and their prescribers, and so the GET and POST examples consistently use _include=MedicationDispense:prescription followed by _include:iterate=MedicationRequest:requester. These edits are necessary because the previous prose and GET query could mislead implementers about valid requester targets and the correct first include search parameter.
