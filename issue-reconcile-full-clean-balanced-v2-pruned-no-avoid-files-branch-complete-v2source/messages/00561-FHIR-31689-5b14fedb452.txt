FHIR-31689: Align ResearchSubject ModelInfo status

Issue request:
FHIR-31689 was a Published/Persuasive BRR change request for R5 asking that ResearchSubject.status no longer use the large research-subject progress/state code set and instead be limited to publication status.

Initial application:
The issue was initially applied by 85a2ee09a39be6c5ae5b6a97eec3d21f46970051, which changed the authoritative ResearchSubject StructureDefinition status element to PublicationStatus and updated the status-code table row to draft, active, retired, and unknown. That application did not update the active FHIR model-info Library artifacts, which still exposed ResearchSubject.status as FHIR.ResearchSubjectStatus and retained the corresponding model-info conversion and FHIRHelpers ToString function.

Additional context:
FHIR-31657 approved the ResearchSubject progress attribute and explicitly noted that status should refer just to publication status, which supports the FHIR-31689 interpretation. FHIR-31690 was applied in the same ResearchSubject edit family but concerns progress endDate and is already represented on the combined branch. ResearchSubject and Library are active in source/fhir.ini, source/library/library-fhir-model-definition-content.xml is copied by publish.ini and linked from the Library examples page, and the Library XML resources embed the same content as base64, so these model-info surfaces are current build input rather than out-of-scope generated leftovers.

AutoFHIR reconciliation:
Updated the FHIR model-info content and its embedded Library resource so ResearchSubject.status uses FHIR.PublicationStatus. Removed the stale ResearchSubjectStatus ClassInfo, conversionInfo, and FHIRHelpers ToString helper, and synchronized the embedded Library data values with the edited content files. No standalone ResearchSubject terminology artifact was retired because the issue concerns the status element binding/type and no discovered WG decision requires retiring the unused legacy terminology here.

Recommendation:
Keep this source fix. If model-info artifacts are regenerated, ensure ResearchSubject.status remains typed as FHIR.PublicationStatus and that no generated helper reintroduces FHIR.ResearchSubjectStatus for this status element.
