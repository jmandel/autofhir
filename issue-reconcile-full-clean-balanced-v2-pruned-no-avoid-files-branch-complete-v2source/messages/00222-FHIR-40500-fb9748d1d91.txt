FHIR-40500: Finish removing PC instantiates references

Issue request:
FHIR-40500 is Applied/Persuasive with Modification. Patient Care requested removal of the ambiguous instantiatesCanonical and instantiatesUri elements from CarePlan, Communication, FamilyMemberHistory, and Procedure, relying instead on the more precise workflow extensions after the extension contexts were updated.

Initial application:
The issue was partly applied in core by 6089508bef, which removed the four top-level resource elements, their search parameters, and several examples. Extension Pack commits 1207b93 and d08f9c0 updated the workflow extension contexts and then reverted the rejected shallComplyWith context additions. No prior Issue-Reconcile-Key commit for FHIR-40500 was present on the combined branch. Current source still had an active Procedure example using Procedure.instantiatesUri and the checked-in FHIR ModelInfo Library content still exposed the removed elements for all four PC resources.

Additional context:
FHIR-29261 introduced the replacement workflow extension family because the old instantiates relationship carried conflicting meanings. Patient Care minutes from 2023-02-23 record the question of removing instantiates from CarePlan, Communication, FamilyMemberHistory, and Procedure after the pattern dropped those elements, and 2025-01-16 minutes record that shallComplyWith changes could not be applied. The fhir.ini entries for the removed elements are migration/deletion metadata and were left intact; commented invariant-test examples were not active resource content.

AutoFHIR reconciliation:
Removed the stale instantiatesUri element from the active Procedure ambulation example and removed instantiatesCanonical/instantiatesUri from the FHIR ModelInfo type definitions for Procedure, CarePlan, Communication, and FamilyMemberHistory. These are build-scoped source artifacts: Procedure examples are listed in source/procedure/list-Procedure-examples.xml and the ModelInfo content is published via publish.ini.

Recommendation:
Keep this commit as-is. The core conformance, search-parameter, example, and ModelInfo surfaces now align with the applied Patient Care decision; the related Extension Pack context work is already represented outside this core checkout.
