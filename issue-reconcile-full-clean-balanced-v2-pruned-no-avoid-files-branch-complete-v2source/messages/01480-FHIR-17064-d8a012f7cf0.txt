FHIR-17064: Restore outcome in search mode wording

Issue request:
FHIR-17064 was a Published/Persuasive FHIR-core Feed change request from the 2018-May Core Norm ballot asking the Bundle.entry.search.mode definition to explain all three reasons for search.mode. The requested correction was to say search.mode can indicate a match, an _include result, or information/warning information about the search process.

Initial application:
The Jira comment says the change was "already done" before publication. No current Git commit explicitly mentions FHIR-17064, but same-family FHIR-17096 was applied in svn 14400 / git c03e0817b9b9dffd6ca6dfea6d19f262e5f8f653, which updated the former Bundle spreadsheet so Bundle.entry.search.mode had the short "match | include | outcome - why this is in the result set" and the requested information/warning definition text. The later source rework preserved that wording in the generated StructureDefinition before a subsequent cleanup dropped outcome from the short.

Additional context:
The Bundle resource is active in source/fhir.ini, so source/bundle/structuredefinition-Bundle.xml and source/bundle/bundle-notes.xml are current build inputs. The current StructureDefinition definition, binding description, CodeSystem, and ValueSet already contain the requested third reason, and search.html plus the search-set Bundle profile still describe OperationOutcome entries with search.mode outcome. Later Jira FHIR-50491 asks whether those outcome references should move to Bundle.issues, but it is Triaged/unresolved and is not a final decision for this reconciliation.

AutoFHIR reconciliation:
This commit restores outcome to the Bundle.entry.search.mode short and updates the Bundle search-set notes so the local narrative no longer describes search.mode as only match/include. No change was made to the already-correct definition, binding description, CodeSystem, ValueSet, or the unresolved Bundle.issues deprecation question.

Recommendation:
Keep this source fix as-is. It closes the remaining stale Bundle wording for FHIR-17064 while preserving the unresolved FHIR-50491 question for future work-group action.
