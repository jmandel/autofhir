FHIR-47279: Remove proactive subscription wording

Issue request:
FHIR-47279 was an Applied FHIR-core R6 Subscriptions issue with resolution Persuasive with Modification. The reporter objected that Subscriptions are not proactive because they react to events, and the approved wording says Subscriptions establish a request for event or change notifications from a FHIR server to another system.

Initial application:
The issue was explicitly applied by git commit 7b84f997d6583c78a484900ae9fac156c9f3a0f1, "FHIR-47279 - proactive language improvement," which updated the opening paragraph in source/subscriptions.html. That left the same rejected "proactive event notifications" wording in source/subscription/subscription-introduction.xml and source/exchange-module.html.

Additional context:
The Subscription resource is active in source/fhir.ini, and source/hierarchy.xml lists both the Subscription resource page and the Exchange module pages, so the remaining occurrences feed current built content. FHIR-I minutes for 2025-03-31 approved the R6 Subscriptions block vote including FHIR-47279 by 17-0-0. A Zulip search found the matching block-vote announcement and no separate conflicting rationale. FHIR-47281, from the same block vote, separately handled FHIR application/server actor wording and is already represented on the combined branch, so this reconciliation removes only the rejected proactive wording.

AutoFHIR reconciliation:
This commit updates the active Subscription resource introduction and Exchange module summary to use "a request for event or change notifications," matching the applied source/subscriptions.html wording and eliminating the remaining subscription-specific proactive-notifications phrase from source.

Recommendation:
Keep this source change. It completes the applied clarification without reopening the separate subscription actor terminology decisions; no further core source follow-up is needed for FHIR-47279 unless the work group wants a broader editorial pass over Exchange module actor wording.
