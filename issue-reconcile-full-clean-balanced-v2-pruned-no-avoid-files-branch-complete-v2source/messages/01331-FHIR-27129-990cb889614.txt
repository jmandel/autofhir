FHIR-27129: Clarify SubscriptionStatus event count increments

Issue request:
FHIR-27129 was a Published/Persuasive R5 FHIR-I change request to harmonize client subscription status checks after SubscriptionStatus refactoring. It asked to move Subscription.error to SubscriptionStatus.error, rename SubscriptionStatus.notificationType to SubscriptionStatus.type, add a status-query value, and update event count descriptions so event counts are incremented/included only for event notifications.

Initial application:
The issue was substantially applied by FHIR#27129 commits in 2020: 004593e639 moved Subscription.error and its terminology/example to SubscriptionStatus.error; 31d6f9fa7a renamed notificationType to type and added the current query-status notification type; dcaf7d3291 and 89b7b1fd0e added query-status documentation and examples. The final source intentionally uses query-status rather than the issue's draft status-query wording.

Additional context:
Subscription and SubscriptionStatus are active resources in source/fhir.ini. FHIR-27130 was approved in the same FHIR-I meeting to add Subscription/$status so clients could dynamically retrieve SubscriptionStatus resources instead of reading/searching transient SubscriptionStatus instances. Later SubscriptionStatus work removed the obsolete eventsInNotification element, added query-event, added self-contained constraints, and linked the $status operation to the query-status guidance, so the remaining source check is the current authoritative SubscriptionStatus definition rather than the removed element or generated diagrams.

AutoFHIR reconciliation:
Updated the SubscriptionStatus.eventsSinceSubscriptionStart definition in source/subscriptionstatus/structuredefinition-SubscriptionStatus.xml to state that event-notification counts are inclusive of the current notification and that handshake, heartbeat, query-status, and query-event notifications do not increment the count. No Subscription.error, notificationType, status-query, or eventsInNotification non-SVG source references needed changes.

Recommendation:
Keep this source change. It preserves the already-applied model and later query-status/query-event decisions while fixing a stale authoritative element definition that could otherwise imply query status/event responses might increment the subscription event count. No further core follow-up is needed for FHIR-27129.
