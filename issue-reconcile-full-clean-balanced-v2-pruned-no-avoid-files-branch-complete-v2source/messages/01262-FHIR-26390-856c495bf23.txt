FHIR-26390: Align Parameters limited-use boundaries

Issue request:
FHIR-26390 was Published with resolution Persuasive with Modification. It asked FHIR-I to replace the broad FHIR-26368 relaxation with explicit limited Parameters use: operations including messaging, no persistence or references except as described, usage notes for limited persistence/use cases, and specific allowance text on selected Resource/Reference elements.

Initial application:
The issue was partly applied by the Jira-tagged commits listed on the ticket: e6dd5ff updated Parameters, ce61932 updated Bundle.entry.resource, 0003f88 updated MessageHeader.focus, 0b644b1 updated TestScript.fixture.resource, 6bf1629 updated AuditEvent.entity.what, and 91f576c updated DomainResource.contained. Current source retained the Parameters usage notes and the named allowance text, but the active Parameters narrative still said the resource had "no other use than for operation parameters," and the root Parameters element definition omitted the exception text even though the resource description included it.

Additional context:
FHIR-26368 was the original Published request to allow Parameters in messaging, and the linked 2020 Zulip discussion and FHIR-I minutes show why FHIR-26390 narrowed that into explicit limited-use allowances rather than a blanket permission. FHIR-57354 is a later Resolved - change required request to remove only the Bundle.entry.resource guardrail; it is not Applied/Published in this default run scope, so this commit does not apply that later change. The historical TestScript edit is not revisited because TestScript source is not present in the current build checkout.

AutoFHIR reconciliation:
Updated source/parameters/parameters-introduction.xml, an active Parameters narrative source file under the current resource-infrastructure entry, so Boundaries and Relationships no longer contradict the approved limited-use guidance. Updated source/parameters/structuredefinition-Parameters.xml so the root Parameters definition carries the same "except as described" qualifier as the resource description. These hunks are necessary because both locations feed implementer-facing current-spec text and previously implied a blanket prohibition that conflicted with FHIR-26390's accepted exceptions.

Recommendation:
Keep this source fix as-is for FHIR-26390. Handle FHIR-57354 separately when the workflow is ready to apply Resolved - change required issues, because that later decision only targets the Bundle.entry.resource sentence and should not reintroduce stale blanket Parameters prohibitions.
