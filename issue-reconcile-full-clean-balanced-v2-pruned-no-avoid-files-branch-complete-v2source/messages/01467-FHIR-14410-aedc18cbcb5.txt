FHIR-14410: Restore CapabilityStatement messaging/document trial-use markers

Issue request:
FHIR-14410 was a Published/Persuasive STU3 FHIR-I change request asking whether CapabilityStatement.messaging and CapabilityStatement.document had enough implementation experience to go normative. The accepted resolution said these parts were not ready to go normative and should be marked as such.

Initial application:
The issue was applied in migrated svn revisions 13047 and 13048, now git commits 94ddb5e6ea93bcefdd16c33a02bdc60d0fb9129d and c4f5b955188866b4924aa5d7707c411239bf6fe2. The first commit added trial-use status in the sheet text for CapabilityStatement.messaging and CapabilityStatement.document, and the second regenerated the then-authoritative spreadsheet XML with trial-use status cells. The 2021 source migration carried those element-level status markers into structuredefinition-CapabilityStatement.xml.

Additional context:
CapabilityStatement is active in the current build via source/fhir.ini and is now a normative conformance resource, so element-level standards-status extensions are needed when specific parts remain trial-use. A later broad status cleanup, 5c20769cc74459a8c1057d2747418dc4340f4244, removed many CapabilityStatement trial-use extensions, including messaging and document. That cleanup also removed the rest.security marker later restored by the FHIR-15646 reconciliation, and no discovered Jira, Zulip, or Confluence evidence supersedes the specific FHIR-14410 decision. The existing FHIR-14444 audit concerns broader rest/resource and mixed-content guidance and intentionally did not decide this seed.

AutoFHIR reconciliation:
This commit restores the ElementDefinition standards-status extension with value trial-use on CapabilityStatement.messaging and CapabilityStatement.document in the active CapabilityStatement StructureDefinition. It makes no broader changes to CapabilityStatement status policy or child elements.

Recommendation:
Keep this source fix. It preserves the specific published FHIR-14410 decision in the current build; revisit only if FHIR-I/FMG makes an explicit current-version decision that CapabilityStatement messaging and document sections are normative or adopts a different mechanism for trial-use content inside normative resources.
