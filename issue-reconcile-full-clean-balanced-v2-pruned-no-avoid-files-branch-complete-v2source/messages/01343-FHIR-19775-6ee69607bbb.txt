FHIR-19775: Link Bundle security label guidance

Issue request:
FHIR-19775 was Published/Persuasive with Modification. It asked for Bundle usage notes to explain Bundle.meta.security as the policy-specific high-water/security label summary for Bundle contents and to point readers to Security WG guidance for the details.

Initial application:
Commit d1672bb7c2 added the Bundle note for FHIR-19775 by saying Bundle.meta.security is generally influenced by entry meta.security values, but it left a raw pointer to http://hl7.org/fhir/security.html. The Bundle page is in current build scope because source/fhir.ini has an active [resources] entry for bundle=Bundle.

Additional context:
Later Security WG issue FHIR-53884 refined the current security-labels.html#core guidance to explicitly distinguish Bundle.meta.security, Request Context, and Resource.meta.security, and it describes the high water mark, purposeOfUse, clearance, Refrain, and Obligations that matter for Bundle.meta.security. The general security.html page now mostly points onward to the security labels page and does not contain that detailed guidance. FHIR-19781 is in the same high-water family for the Composition $document operation, but it concerns a different artifact and work group and is not decided here.

AutoFHIR reconciliation:
Updated the active Bundle notes source so Bundle.meta.security and meta.security render as code and the note links directly to security-labels.html#core, preserving the applied rule while connecting it to the current authoritative guidance. This fixes the stale/incomplete raw security.html pointer without broadening the rule.

Recommendation:
Keep this source fix as-is. No further FHIR core source work is recommended for FHIR-19775 unless the Security WG changes the semantics in the security-label guidance.
