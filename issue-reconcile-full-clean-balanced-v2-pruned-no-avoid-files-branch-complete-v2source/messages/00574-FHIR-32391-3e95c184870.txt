FHIR-32391: Restore Encounter event-order grouping

Issue request:
FHIR-32391 was Published/Persuasive for R5. It asked why Encounter.serviceProvider and Encounter.partOf were at the bottom of the Encounter element list and resolved that, based on the Event pattern, the order should be basedOn, then partOf below basedOn, then serviceProvider below partOf.

Initial application:
The issue was applied in git commit a9d012838c4d8b931a463eb4ff3a3f869aeee6e0, which moved Encounter.partOf and Encounter.serviceProvider from the end of source/encounter/structuredefinition-Encounter.xml up below Encounter.basedOn. A later FHIR-23843 implementation commit added Encounter.careTeam between Encounter.basedOn and Encounter.partOf, leaving the current source with basedOn, careTeam, partOf, serviceProvider.

Additional context:
FHIR-23843 was also Published/Persuasive and required adding Encounter.careTeam 0..* Reference(CareTeam) between basedOn and participant. That later decision does not require careTeam to be immediately after basedOn, so it can remain between basedOn and participant without interrupting the FHIR-32391 basedOn/partOf/serviceProvider sequence. The Event pattern source lists Event.basedOn before Event.partOf, and Encounter.serviceProvider maps to Event.performer.actor.

AutoFHIR reconciliation:
This commit moves the existing Encounter.careTeam element block to follow Encounter.serviceProvider. That restores the approved Encounter order to basedOn, partOf, serviceProvider while preserving the FHIR-23843 placement of careTeam before participant. The edited file is in build scope because source/fhir.ini has an active encounter=Encounter resource entry.

Recommendation:
Keep this source fix as-is. No further Encounter source change is indicated for FHIR-32391; FHIR-23843 remains represented separately on the combined branch and its substantive CareTeam reference is preserved.
