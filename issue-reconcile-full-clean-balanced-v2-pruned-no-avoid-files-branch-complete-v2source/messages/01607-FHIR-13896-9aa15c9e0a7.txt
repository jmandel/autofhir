FHIR-13896: Link type mappings to mapping status

Issue request:
FHIR-13896 was Published/Persuasive for STU3 and asked for a general FHIR page explaining that resource and content mapping pages are instructive/informative rather than normative or executable, with a comment requesting links to that page from mapping pages.

Initial application:
The issue was applied in svn revision 13429, now git commit db3234082a6ae6418a1d99f1a9df495fb401d54b, which added source/mappings.html and linked several then-current hand-written mapping pages to it. The current source still contains that general page and the original informative/non-authoritative guidance.

Additional context:
Later source growth added source/types-mappings.html for the active type framework, but that page did not carry the same link while the resource, logical, profile, extension templates and other hand-written mapping pages did. The edited file is in current build scope because the active type framework pages link to types-mappings.html, and its mappings page is an implementer-facing mapping page covered by the original request. A 2025 Zulip discussion also supports the same distinction: core mappings are definitional/high-level, not operational transforms.

AutoFHIR reconciliation:
Updated source/types-mappings.html to link to source/mappings.html using the established "Mappings to Other Standards" phrasing so the type framework mappings page now exposes the same status and caveat page as the other mapping pages.

Recommendation:
Keep this source fix. It is a narrow consistency correction for the only current mapping-page source checked in this pass that lacked the FHIR-13896 link, and no additional Jira issue needs a separate decision.
