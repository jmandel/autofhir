FHIR-22995: Clarify AdverseEvent severity handling

Issue request:
FHIR-22995 was Published/Persuasive with Modification for the Patient Care AdverseEvent resource. It asked to remove the event-level AdverseEvent.severity element because severity belongs on signs, symptoms, or resulting conditions rather than on the adverse event itself, and to clarify AdverseEvent.seriousness with examples contrasting severity and seriousness.

Initial application:
The issue was partially applied in 2019 by 05acdd8, which removed AdverseEvent.severity from the then-authoritative AdverseEvent spreadsheet/example and updated the AdverseEvent.seriousness definition/comment, and by 26b3f60, which removed the severity search parameter. The current source no longer defines an AdverseEvent.severity element or search parameter, and source/fhir.ini actively builds AdverseEvent while mapping the removed R4 severity element to Condition.severity via AdverseEvent.resultingEffect.

Additional context:
Later AdverseEvent changes renamed resultingCondition to resultingEffect (FHIR-34316) and then changed resultingEffect to CodeableReference (FHIR-48833). After those changes, the current seriousness comment referred to a non-existent AdverseEvent.resultingEffect.severity path, and the active Scope and Usage narrative still said adverse events are characterized by capturing unqualified severity, preserving the ambiguity FHIR-22995 intended to remove.

AutoFHIR reconciliation:
This commit updates the active AdverseEvent StructureDefinition source so the seriousness comment says AdverseEvent.resultingEffect can reference a Condition that has Condition.severity, rather than implying resultingEffect itself has a severity child. It also updates the active AdverseEvent introduction to describe capturing resulting effects on the subject, rather than unqualified event severity. The remaining references to severity are either unrelated contributing-factor wording, legacy unused terminology artifacts, or the intended Condition.severity contrast.

Recommendation:
Keep this source change as-is. It preserves the published FHIR-22995 decision, aligns the examples with the current resultingEffect model, and avoids reopening broader questions about unused legacy adverse-event-severity terminology that is no longer bound by AdverseEvent.
