FHIR-42765: Move Address use guidance to use comment

Issue request:
FHIR-42765 was an Applied FHIR-core datatypes issue, resolved as Not Persuasive with Modification for R6. The reporter asked for a birth value in the required Address use/type value set because the birthPlace extension uses Address. FHIR-I decided not to add a birth code because birth place should be conveyed by the patient-birthPlace extension, and instead approved adding guidance to Address.use explaining that use is relevant when choosing among multiple addresses and is typically omitted when an element or extension already implies the address purpose.

Initial application:
The issue appears to have been applied by git commit b9dde86c67e28be13aec78419f01633b1501d2d0, which rewrote source/datatypes/address.xml and introduced the approved guidance text. Current source inspection showed that the guidance existed, but it was attached to the Address.type Comments cell rather than the Address.use Comments cell. The Address datatype is in build scope through the active Address entry in source/fhir.ini [types] and the default datatypes type page mapping.

Additional context:
FHIR-I minutes for 2024-03-18 record the same decision, including the reason not to add a birth use code and the exact instruction to add the guidance as a comment on use. The patient-birthPlace extension now lives in the FHIR Extension Pack as an Address-valued extension, supporting the decision that birth purpose is implicit in the extension rather than represented by Address.use. No directly relevant or conflicting Zulip discussion was found in bounded searches for the issue and address/birth/use terms.

AutoFHIR reconciliation:
Moved the approved guidance into the Address.use Comments cell and removed it from the Address.type Comments cell, leaving the Address.type comment focused on postal versus physical address semantics. No birth code was added to AddressUse, consistent with the Jira resolution.

Recommendation:
Keep this source change. It corrects the prior application location without changing the work group decision, and no additional core or extension-pack change is indicated by the inspected evidence.
