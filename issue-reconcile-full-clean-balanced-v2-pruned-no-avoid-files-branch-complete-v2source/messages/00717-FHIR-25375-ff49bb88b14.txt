FHIR-25375: Update Location mode note for contact

Issue request:
FHIR-25375 was Published/Persuasive with Modification for R5. It asked for a way to associate role-specific, time-bounded contacts with Location; the final disposition replaced Location.telecom with Location.contact 0..* ExtendedContactDetail, using the new datatype from FHIR-29035, while later application retained Location.address as the physical address.

Initial application:
The main source changes were applied before this reconciliation. Commit 40bf32a7e76caced2ee4c60adf96d1a5d201e09a added Location.contact as ExtendedContactDetail and initially deprecated Location.telecom and Location.address; commit 4269773e276ec446f4b72a6e63ea938daf59d564 removed the Location.address deprecation because the element remains the physical location address; commit e1320848bd2700338a2a11b634693d52f9fb8ad1 removed Location.telecom and updated Location examples to the new contact element. One active narrative note still named the removed Location.telecom element.

Additional context:
FHIR-29035 established ExtendedContactDetail with purpose, name, telecom, address, organization, and period, and PA minutes on 2021-12-01 explicitly reopened FHIR-25375 to use that datatype. The Location resource is active in source/fhir.ini, so source/location/location-notes.xml is current resource narrative. The remaining Location.telecom references outside this fix are the intended cross-version rename map in source/fhir.ini and an out-of-build CDA profile entry whose fhir.ini profile line is commented out.

AutoFHIR reconciliation:
Updated source/location/location-notes.xml so the list of Location elements relevant only for instance-mode locations refers to Location.contact instead of the removed Location.telecom. No other source changes were made because the authoritative StructureDefinition already has Location.contact 0..* ExtendedContactDetail, no Location.telecom element, and a retained physical Location.address.

Recommendation:
Keep this source fix. It removes the only active stale Location.telecom narrative reference discovered during reconciliation while preserving the deliberate R5 model: role/purpose/effective-period contact details live in Location.contact, and Location.address remains the physical address.
