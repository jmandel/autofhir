FHIR-27056: State missing authoritative means false

Issue request:
FHIR-27056 was Published/Persuasive for R5 and asked to add NamingSystem.uniqueId.authoritative as a 0..1 boolean, with missing values defaulting to false, plus a constraint allowing only one authoritative identifier for each type/period combination.

Initial application:
Git commit 25159ea161 added NamingSystem.uniqueId.authoritative and nsd-3 as part of the Vocab R5 NamingSystem changes, but the authoritative element did not carry the requested missing-value semantics. Later cleanup moved nsd-3 to the resource-level constraints and FHIR-43169 corrected the FHIRPath boolean comparison from string 'true' to boolean true.

Additional context:
source/fhir.ini actively includes NamingSystem, so source/namingsystem/structuredefinition-NamingSystem.xml is in the current core build. FHIR-40608 remains Triaged and unresolved for the separate question of whether nsd-3 should detect overlapping periods, so this reconciliation does not preempt that pending work-group decision.

AutoFHIR reconciliation:
Added meaningWhenMissing to NamingSystem.uniqueId.authoritative so the source now states that an omitted value means the identifier is not authoritative, matching the FHIR-27056 default-false requirement without changing the unresolved nsd-3 overlap behavior.

Recommendation:
Keep this commit. Handle any future rewrite of the nsd-3 FHIRPath expression under FHIR-40608 after the work group adopts a proposed resolution and test suite.
