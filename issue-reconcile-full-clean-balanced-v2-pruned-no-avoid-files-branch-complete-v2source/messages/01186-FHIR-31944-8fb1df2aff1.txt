FHIR-31944: Clarify POST search parameter equivalence

Issue request:
FHIR-31944 was a Published/Persuasive with Modification FHIR-core issue asking the HTTP search documentation to stop mixing a POST search pattern with example headers and body text, to make POST examples show real application/x-www-form-urlencoded body content, and to clarify that servers SHALL support POST body parameters, MAY support URL query parameters on POST, may restrict or ignore unsupported URL parameters, SHALL treat accepted URL and body parameters uniformly, and SHALL express the self link with parameters in the URL.

Initial application:
No git commit explicitly mentioning FHIR-31944 was found. The issue family was partially applied through later search-page work: commit 7415a1eb0824ba59d977db335205d71eed004312 added server-wide, typed, and compartment POST search examples and summary-table rows while applying FHIR-35859, and commit e441170220c19e992f803667b245e63dcdd508cf moved the HTTP transport-protocol guidance from source/search.html to source/http.html while applying FHIR-39137. Current source/http.html already required POST body parameter support and allowed URL query parameters on POST, and source/search.html already required self links to be GET-style URLs, but the HTTP page no longer explicitly stated that accepted URL and body parameters have the same semantics or that unsupported URL parameters may be ignored with the self link reflecting actual processing.

Additional context:
FHIR-I WGM minutes from September 2021 record the FHIR-31944 motion and specifically state that servers SHALL support body parameters, MAY support URL parameters, MAY set URL-parameter rules, and SHALL treat split URL/body parameters uniformly. FHIR-31943 is the companion GET/POST method-support issue; FHIR-33220 later made the POST-search self-link point explicit; FHIR-38744 was retracted and does not weaken the body-parameter SHALL; and the later FHIR-51506 self-link clarification is consistent with using the self link to disclose the parameters actually used.

AutoFHIR reconciliation:
This commit updates active source/http.html narrative in the REST (HTTP) search section. It adds the missing equivalence rule for accepted POST URL/body parameters and expands the existing URL-parameter restriction note to allow either rejecting or ignoring unsupported URL parameters, with the self link reflecting the parameters actually used.

Recommendation:
Keep this source-changing commit. It completes the remaining semantic clarification from FHIR-31944 without changing the already-correct POST example forms or duplicating the self-link rule maintained on the Search page.
