FHIR-22653: Add Bundle search parameter constraints

Issue request:
FHIR-22653 was Published/Persuasive for FHIR-I. It asked to add a SearchParameter attribute holding a FHIRPath constraint that describes when a SearchParameter applies, motivated by Bundle-composition and Bundle-message needing Bundle.type-specific applicability conditions.

Initial application:
The issue was initially applied by HL7/fhir#2144, merged as 435d9997524b26dd3a648c0237dcae1fe7f4a834. The implementation commit 76ce0e716b7f3a31f6573fe90b24ee0443e77707, despite the subject typo "FHIR-22635 add SearchParameter.constraint", added SearchParameter.constraint to source/searchparameter/structuredefinition-SearchParameter.xml and added SearchParameter/example-constraint. It did not add constraint values to the active Bundle-composition or Bundle-message search parameter definitions.

Additional context:
FHIR-I minutes and the linked Zulip thread confirm that the work group wanted the document/message applicability condition called out explicitly instead of burying it inside SearchParameter.expression. Later FHIR-31664 narrowed the Bundle-composition and Bundle-message expressions to Composition and MessageHeader, and FHIR-48363 converted them from reference to the new resource search type for embedded-resource chaining; neither later change made the Bundle.type applicability condition machine-readable. source/fhir.ini keeps both bundle and searchparameter in the current build.

AutoFHIR reconciliation:
This commit adds SearchParameter.constraint values to source/bundle/bundle-Bundle-search-params.xml for Bundle-composition and Bundle-message, preserving the existing resource-type expressions while adding the approved document/message Bundle.type applicability tests.

Recommendation:
Keep this commit as-is. It completes the published issue in the current active source without revisiting later resource-type/chaining decisions; broader SearchParameter FHIRPath validation or tooling policies should remain separate work.
