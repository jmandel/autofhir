FHIR-36401: Align single vital-sign invariant keys

Issue request:
FHIR-36401 was Applied/Persuasive with Modification for R6. It asked that simple vital-sign observations require either Observation.value[x] or Observation.dataAbsentReason, rather than allowing the measured result to be represented only in Observation.component, with related guidance that components may qualify but should not carry the simple vital-sign result.

Initial application:
The issue was applied in the 2025 vital-signs profile work. Commit 67e77c9134 added the value-or-dataAbsentReason invariant to the single-value vital-sign profiles and adjusted Vital Signs Panel cardinality; commit d654aec30a moved the new constraints to the profile contexts where they apply; af5373801d and 51f56178b6 then disambiguated vital-sign constraint names and value[x]/component.value[x] profiling. The current source contained the intended invariant expression and conditions, but the single-value profile invariant keys remained `vs-4` while their value[x] and dataAbsentReason elements referenced `vsp-4`.

Additional context:
Observation is an active current-build resource in source/fhir.ini, so the profile XML files under source/observation feed the current build. FHIR-47136 and FHIR-23070 are part of the same vital-signs cleanup family; FHIR-42815, FHIR-44836, and FHIR-44721 were already represented on the combined branch and were not republished here. Confluence minutes confirm the OO discussion and later block-vote trail for FHIR-36401; no directly relevant Zulip thread changed the Jira/source conclusion. The broader future-consideration item about result/qualifier/supplemental component roles was explicitly deferred in Jira rather than safely actionable as a current core source edit.

AutoFHIR reconciliation:
This commit changes the FHIR-36401 invariant key from `vs-4` to `vsp-4` in the active BMI, body height, body temperature, body weight, head circumference, heart rate, oxygen saturation, and respiratory rate profiles. That aligns each invariant with the existing `condition value="vsp-4"` references and with the `vsp-*` naming pattern used by the current Vital Signs Base and blood-pressure profiles, without changing the approved FHIRPath expression.

Recommendation:
Keep this source fix as-is. It completes the current-spec application by making the formal condition references resolve to the intended simple vital-sign invariant; any future component-role taxonomy should remain a separate work-group decision.
