FHIR-46311: Clarify canonical version search matching

Issue request:
FHIR-46311 is Applied/Persuasive for R6 and asks whether canonical version searches using the version parameter or [canonical]|[version] default to semantic/hierarchy matching or exact matching. The accepted decision says default canonical version search is a token search (exact match), and callers wanting version hierarchy searches should use :below.

Initial application:
The issue was applied by PR #3967 in git commit 2007d0bc3811bb1444904a1709781768d3766cb9, which added a paragraph to source/search.html. That paragraph made ordinary versioned canonical searches use the target resource's versionAlgorithm when known and fall back to exact only when unknown, leaving the default behavior different from the Jira and minutes decision.

Additional context:
The linked July 2024 Zulip thread shows implementers reported exact matching in HAPI, Google, Firely, and Aidbox, and FHIR-I minutes on 2024-07-29 record a 7-0-0 decision for exact token default with hierarchy through :below. Later FHIR-52895 clarified general canonical reference version matching in source/references.html, so this commit only changes the search-specific default in active source/search.html.

AutoFHIR reconciliation:
Updated source/search.html, the active source for the Search page cited by the Jira related URL, to state that an unmodified [canonical]|[version] search matches the version exactly using token semantics, and that versionAlgorithm-based hierarchy matching requires a supported modifier such as :above or :below.

Recommendation:
Keep this source fix. It aligns the active search narrative with the Applied FHIR-I decision while preserving the separate canonical reference matching guidance.
