FHIR-23876: Use protocol in PlanDefinition example

Issue request:
FHIR-23876 is an Applied/Persuasive CDS change request for PlanDefinition. It asked to change the PlanDefinition type code name from clinical-protocol to protocol so the concept also covers lab, technical, study, and other non-clinical protocols; later Jira comments clarified that this should be implemented by adding a protocol code through UTG rather than by changing/removing the existing code in place.

Initial application:
The issue appears to have been mostly applied by ceedc43fb48fa41b06d58d9a70d58c3fb3454c87, whose subject names FHIR-23876. That commit changed the active PlanDefinition.type short description from clinical-protocol to protocol, moved the binding to the THO plan-definition-type value set, and deleted the duplicate local PlanDefinition type value set. UP-655 then implemented the terminology addition in UTG/THO. However, the active PlanDefinition protocol example still used clinical-protocol as its coded type.

Additional context:
FHIR-15163 had previously removed a generic protocol code and introduced clinical-protocol; FHIR-23876 and UP-655 are the later decisions that add protocol back for broader protocol semantics. The current build scope includes PlanDefinition in source/fhir.ini, and source/plandefinition/list-PlanDefinition-examples.xml includes PlanDefinition/protocol-example as a built example. Source and community searches found no later conflicting decision; Confluence references corroborate CDS sponsorship, TI approval movement, and THO 6.3.0 publication for UP-655.

AutoFHIR reconciliation:
This commit updates source/plandefinition/plandefinition-protocol-example.xml so the built protocol example's coded PlanDefinition.type uses protocol, and its generated narrative type line matches. No core CodeSystem or ValueSet source is changed because the authoritative PlanDefinition type terminology is now in THO and UP-655 has already added the protocol code there.

Recommendation:
Keep this source fix as-is. Historical release snapshots under tools/history still reflect old releases and should remain unchanged; any further terminology maintenance belongs in THO/UTG rather than the core FHIR source checkout.
