FHIR-30206: Correct FHIRHelpers canonical URLs

Issue request:
FHIR-30206 was Published/Persuasive and asked for the FHIRHelpers and FHIR-ModelInfo Library resources to have names and URLs that resolve from the core FHIR specification for CQL dependency references.

Initial application:
The Jira comment says the change was applied to R4B in HL7/fhir#1134. Git history shows commit 25a73e1e3e applied the canonical FHIRHelpers and FHIR-ModelInfo ids, Library.url values, and dependency correction on the R4B line, followed by 7ef45c317e fixing the example-list references. The current build-source branch had regressed to library-fhir-helpers/library-fhir-model-definition ids, no canonical Library.url values, and stale dependency/list references.

Additional context:
FHIR-29829 is the earlier Published issue for the same URL problem and its Jira comment says the R4B work still needed application to master. The Library resource is active in source/fhir.ini, so source/library Library examples feed the current build. A Zulip IG creation thread shows downstream IGs observed unresolved FHIRHelpers and FHIR-ModelInfo canonicals, supporting that these URLs must resolve from core rather than from each IG.

AutoFHIR reconciliation:
This commit restores the current source to the intended canonical identifiers: FHIRHelpers now has id FHIRHelpers, url http://hl7.org/fhir/Library/FHIRHelpers, and a dependency on http://hl7.org/fhir/Library/FHIR-ModelInfo; FHIR-ModelInfo now has id FHIR-ModelInfo, url http://hl7.org/fhir/Library/FHIR-ModelInfo, and name FHIR. The Library example list and the active MMI suicide-risk example dependencies now point at those resolving core Library ids/canonicals.

Recommendation:
Keep this source change. It applies the published technical correction to the current core Library build inputs and avoids leaving generated/example references that still point to the stale non-resolving Library ids.
