FHIR-20670: Use timing roots in Timing examples

Issue request:
FHIR-20670 was a Published/Persuasive technical correction for the FHIR-core datatypes examples page. It noted that the Timing example snippets used root nodes named <schedule> rather than <timing>; Lloyd McKenzie recorded that this was not technically wrong, but would be less confusing if fixed.

Initial application:
The issue appears to have been initially applied in commit b1a191ea63c373039d54c387aced8a9f11daea24, whose message says "Changes made as per FHIR-20670" and changed the Timing XML example roots from <schedule> to <timing>. The next-day RatioRange datatype commit b9fd58139d35c8aa90083ae99a279c8a6d3dd854 reintroduced <schedule> roots while editing the same page, so the current combined branch no longer reflected the Jira-tagged fix.

Additional context:
The active build still includes Timing in source/fhir.ini's [types] list and uses source/datatypes-examples.html for the datatype examples page. Later commit e9e4e5f34c8d0b40d680c26f92acfa19b5f714a6 added JSON datatype examples after the schedule roots had returned, so the same root-name correction is needed for the JSON fragments as well as the XML fragments. Direct Zulip and Confluence searches found no community record that conflicts with the Jira/source/history conclusion.

AutoFHIR reconciliation:
This commit updates the active Timing examples in source/datatypes-examples.html so all six XML snippets use <timing> roots and all six corresponding JSON snippets use "timing" as the root property. This restores the published FHIR-20670 intent and keeps the later JSON examples consistent with the corrected XML examples.

Recommendation:
Keep this source-changing commit. It is a narrow correction to an active datatype examples page, restores the previously applied Jira decision, and does not require work-group review unless editors intentionally want the examples to use contextual element names rather than the datatype name.
