FHIR-5572: Clarify FHIR code case sensitivity exceptions

Issue request:
FHIR-5572 was a Published/Persuasive FHIR-core issue asking the terminology pages to say that FHIR code systems, like v2 and v3 code systems, are case sensitive. The Jira comments record the accepted application as a validation rule requiring FHIR-defined code systems to declare caseSensitive=true and narrative saying FHIR-defined codes are case sensitive.

Initial application:
The current terminology narrative already carried the original rule, saying that all codes defined by FHIR itself are case sensitive and SHALL be used in the provided case. Git history shows this rule was carried forward in source/terminologies.html after the early SVN-era application; the companion FHIR-5571 case-sensitivity cleanup is already represented on the combined branch.

Additional context:
The current build now has active, FHIR-hosted color code systems listed in source/fhir.ini with caseSensitive=false, added later for DeviceMetric color work. Those CodeSystems explicitly say CSS color names and RGB codes are case-insensitive. Later DeviceMetric issues make clear that these color terminology resources are intentional current build content even though further R6 work may move them to THO. Community search did not find a FHIR-5572-specific contradiction, but related Zulip discussion supports using the underlying code-system semantics for case sensitivity.

AutoFHIR reconciliation:
This commit updates source/terminologies.html so the terminology overview still states the FHIR default case-sensitive rule, while recognizing that a FHIR-defined CodeSystem can explicitly declare otherwise. The edit is limited to the active terminology page and does not change any CodeSystem definitions.

Recommendation:
Keep this commit as-is. It preserves the FHIR-5572 default rule and removes a current semantic contradiction with active color CodeSystems. Do not separately decide FHIR-5571 here because the combined branch already contains an audit commit for it; do not decide the DeviceMetric color issues from this seed because they are separate terminology/resource decisions.
