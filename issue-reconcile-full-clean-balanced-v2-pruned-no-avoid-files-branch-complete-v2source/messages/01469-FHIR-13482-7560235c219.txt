FHIR-13482: Restore IG example default

Issue request:
FHIR-13482 was Published/Persuasive for STU3 and asked that ImplementationGuide.package.resource.example stop being mandatory while retaining a default of false, because there is no useful unknown state for whether a listed IG resource is an example.

Initial application:
The issue was applied in historical git-svn commit 9ac87a33556212faffb63475f323c4fab59090b2 / svn revision 12721, which changed ImplementationGuide.package.resource.example from 1..1 to 0..1 and added Default Value = False in the spreadsheet source. In the current source the cardinality had survived on the renamed successor fields, but the formal default was absent.

Additional context:
Current source/fhir.ini lists ImplementationGuide as an active build resource, maps the R3 package.resource path to ImplementationGuide.definition.resource, and maps the later example[x] paths to isExample. FHIR-23965 later changed exampleBoolean/exampleCanonical to isExample/profile for R5 and FHIR-I minutes approved that rename/split, but neither source nor community evidence found a decision to remove the false default.

AutoFHIR reconciliation:
This commit restores defaultValueBoolean=false on the current ImplementationGuide.definition.resource.isExample successor and on the parallel ImplementationGuide.manifest.resource.isExample flag so both current IG resource listings preserve the approved false default while staying 0..1.

Recommendation:
Keep this source fix. It restores a previously approved computable default that was lost through later refactoring, without changing the later FHIR-23965 isExample/profile model.
