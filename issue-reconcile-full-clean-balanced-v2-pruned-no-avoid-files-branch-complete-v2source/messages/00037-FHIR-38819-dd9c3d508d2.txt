FHIR-38819: Align Period.end missing meaning

Issue request:
FHIR-38819 was Published with a Persuasive with Modification resolution for the R5 datatype page. It asked to replace the Period.end "Meaning if Missing" statement that a missing end means the period is ongoing with the approved meaning that no end date/time was known or planned when the instance was created.

Initial application:
The earlier FHIR-16979 application changed the Period.end definition in source/datatypes/period.xml via git commit 7c492b45fee8c935cf6a287629425e4107f6102b, but it left the Period.end missing-meaning cell and the datatypes narrative saying or implying that absence meant ongoing. No source-history commit mentioning FHIR-38819 was found before this reconciliation.

Additional context:
source/fhir.ini maps datatype pages to datatypes.html, and source/datatypes/period.xml is the authoritative spreadsheet source for the Period datatype. FHIR-I Methodology/Data Types minutes for 2023-02-15 record the FHIR-38819 persuasive-with-modification vote. A 2022 Zulip thread independently identified the same contradiction and no direct Zulip discussion of FHIR-38819 or conflicting later decision was found.

AutoFHIR reconciliation:
This commit updates Period.end's missing-meaning cell to the approved no-known-or-planned-end wording, changes the short description so it no longer implies that an absent end is equivalent to ongoing, and aligns the datatype narrative with the same rule while preserving the guidance for an explicit planned future end.

Recommendation:
Keep this source fix as-is. It implements the final Jira decision in the current build inputs and removes the remaining implementer-facing contradiction without introducing a broader Period semantics change.
