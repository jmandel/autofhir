FHIR-37359: Remove stale Questionnaire regex extension

Issue request:
FHIR-37359 was Published with a Not Persuasive with Modification resolution for R5. The issue asked how a Questionnaire regex validation extension user could supply a user-facing error message. FHIR-I resolved to remove the core regex extension and direct users to ElementDefinition.constraint or the equivalent SDC Questionnaire.item constraint mechanism instead.

Initial application:
The issue was initially applied by acd5de4a3e, which removed regex from the active element-extensions profile list and hid the extension row. The current core source no longer defines StructureDefinition/regex in the active element extensions profile, and source/fhir.ini keeps element-extensions and Questionnaire as active build inputs.

Additional context:
A later Applied Questionnaire change, FHIR-46191, reintroduced one active reference to http://hl7.org/fhir/StructureDefinition/regex on Questionnaire.item.linkId while also adding the que-16 ElementDefinition.constraint with the same regular expression and a human error message. The FHIR Extension Pack preserves StructureDefinition/regex only as a retired/deprecated compatibility artifact, and Zulip follow-up discussion around FHIR-37359 points implementers to the constraint/invariant mechanism for custom messages.

AutoFHIR reconciliation:
Removed the stale regex extension instance from source/questionnaire/structuredefinition-Questionnaire.xml. The que-16 constraint remains in place, so the intended linkId whitespace rule and its user-facing message continue to be represented through ElementDefinition.constraint rather than the removed core regex extension.

Recommendation:
Keep this source fix. It completes the FHIR-37359 reconciliation in core without changing the FHIR-46191 linkId rule; extension-pack compatibility content and SDC guidance should remain separate from this core cleanup.
