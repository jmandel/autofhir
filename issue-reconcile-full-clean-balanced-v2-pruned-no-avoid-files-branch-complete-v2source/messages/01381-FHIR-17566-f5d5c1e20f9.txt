FHIR-17566: Remove invalid AdministrativeGender v3 mapping

Issue request:
FHIR-17566 is Published/Persuasive and reports that cm-administrative-gender-v3 maps FHIR AdministrativeGender unknown to target code UNK even though UNK is not in the target v3 AdministrativeGender value set. The Jira comments clarify that after the tooling validation concern, the map itself still needed correction by removing the unknown mapping or moving it to an unmapped entry with a comment.

Initial application:
No git commit was found that explicitly mentions FHIR-17566, and the current source still preserved the original spreadsheet mapping of unknown to AdministrativeGender.UNK. The AdministrativeGender mapping row originated in the long-standing bindings spreadsheet history and later terminology cleanups/reworks preserved the invalid target rather than applying this issue.

Additional context:
The current build-scope terminology input is source/terminologies/bindings.xml, whose AdministrativeGender binding row declares the v3 target value set and whose administrative-gender worksheet generates the cm-administrative-gender-v3 ConceptMap. The current CI build still renders unknown as equivalent to UNK in that map, while the current THO v3 AdministrativeGender CodeSystem contains only F, M, and UN. FHIR-16189 and FHIR-24899 discuss nearby AdministrativeGender concept-map rendering/relationship issues, but neither supersedes the specific invalid UNK target correction.

AutoFHIR reconciliation:
Removed the v3 target cell for the FHIR AdministrativeGender unknown row in source/terminologies/bindings.xml. This keeps the valid male, female, and other mappings unchanged and prevents the generated v3 ConceptMap from asserting a target code that is outside http://terminology.hl7.org/CodeSystem/v3-AdministrativeGender.

Recommendation:
Keep this commit as-is. If the work group wants a future explicit unmapped/comment entry for unknown rather than omitting the mapping, that can be added with human-reviewed generator syntax, but the current source must not publish unknown -> UNK as a valid v3 AdministrativeGender mapping.
