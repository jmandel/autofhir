FHIR-11130: Clarify ServiceRequest performerType standalone use

Issue request:
FHIR-11130 was a Published, Persuasive with Modification DSTU2 clarification asking whether DiagnosticRequest.performerType directly modified performer or could stand alone. The resolution said to make clear in comments that performerType can be used on its own and to keep the element name.

Initial application:
The issue was applied in the broad workflow commit 839bf586d6, which updated the Request logical model performerType comment to say that if performerType is specified without performer, the performer must be of the specified type. DiagnosticRequest is no longer an active resource in the current build, and the active Request logical model still contains the standalone-use clarification.

Additional context:
Current source/fhir.ini keeps the Request logical model in scope and lists ServiceRequest as an active resource, while DiagnosticRequest appears only in removed resources. ServiceRequest is the current service-order resource carrying performerType mapped to Request.performerType, but its element comment omitted the standalone-use clarification, and the ServiceRequest request-pattern mapping exception recorded that divergent comment. No directly relevant Zulip or Confluence evidence was found, and Jira search found only the seed as the directly matching issue.

AutoFHIR reconciliation:
This commit adds the missing standalone-use sentence to ServiceRequest.performerType and updates the ServiceRequest request-pattern mapping exception so the resource comment stays synchronized with the active source definition. The change is limited to active ServiceRequest source and does not alter cardinality, binding, search parameters, examples, or generated diagram artifacts.

Recommendation:
Keep this commit as-is. It preserves the already-applied Request logical model decision and restores the same implementer-facing clarification on the active ServiceRequest element that inherited the request performerType concept after DiagnosticRequest left the current build.
