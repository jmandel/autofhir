FHIR-26638: Clarify Group $everything version references

Issue request:
FHIR-26638 was Published as Persuasive with Modification for R5. It asked whether $everything should follow version-specific references and resolved to add that servers SHOULD resolve version-specific references by returning the explicitly named version.

Initial application:
The issue was initially applied by commit 4bca361455ad0d5cf3a467b64e43d4915745da8c to source/patient/operationdefinition-Patient-everything.xml, adding the approved sentence to the Patient/$everything OperationDefinition description. That Patient operation was later moved out of core, but the same patient-compartment return wording remains in the active core Group/$everything OperationDefinition without the approved clarification.

Additional context:
Zulip discussion for FHIR-26637 and FHIR-26638 agreed that _include and $everything should explicitly follow version-specific references, with SHOULD rather than SHALL. FHIR-I minutes record the 12-0-0 vote for FHIR-26638. Current core links Patient/$everything to the Admin IG, whose published XML still contains the approved sentence, so this reconciliation does not reintroduce Patient/$everything in core. The Group resource is active in source/fhir.ini and source/group/list-Group-operations.xml references OperationDefinition/Group-everything, so the Group operation is current build scope.

AutoFHIR reconciliation:
Added the approved version-specific reference sentence to source/group/operationdefinition-Group-everything.xml immediately after the existing rule to return patient-compartment resources and referenced resources.

Recommendation:
Keep this commit. It preserves the original FHIR-I clarification for the remaining in-core $everything operation that uses the same patient-compartment return rule, while leaving the externally maintained Patient/$everything definition alone.
