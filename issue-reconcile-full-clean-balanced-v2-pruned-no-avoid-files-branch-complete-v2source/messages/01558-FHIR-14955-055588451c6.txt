FHIR-14955: Correct missing modifier summary

Issue request:
FHIR-14955 was Published/Persuasive for the FHIR-core search page. It reported that examples in the Handling Missing Data section still used the undefined :exists modifier and asked that they be corrected to :missing.

Initial application:
The issue was originally applied in SVN revision 13398, imported as git commit d3e942d297a66854a8caa2e77e25be969013947a, which changed the AllergyIntolerance examples in source/search.html from clinical-status:exists=false to clinical-status:missing=true and changed the nearby prose from :exists to :missing. Current source no longer contains literal :exists usages.

Additional context:
The current source/search.html page is the authoritative source for the FHIR-core search narrative named by the Jira issue. Later modifier-page refactoring added a summary table row for the missing modifier whose true/false description was inverted relative to both the detailed missing section and the original :exists-to-:missing rename. The related FHIR-13348 decision and current detailed prose confirm that :missing=true means the matching value is absent or lacks a value, while :missing=false means the value is present. A Zulip thread immediately after the original fix records that :exists was renamed to :missing to get the default and inverse semantics correct.

AutoFHIR reconciliation:
Updated only the missing modifier summary row in source/search.html so it says the value is absent when the supplied parameter value is true and present when the supplied parameter value is false. No other wording or examples were changed.

Recommendation:
Keep this commit. It preserves the original applied :exists-to-:missing correction and removes a current contradiction that could otherwise make implementers read :missing with :exists semantics.
