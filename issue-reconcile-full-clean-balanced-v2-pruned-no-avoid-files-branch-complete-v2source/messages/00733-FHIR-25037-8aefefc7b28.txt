FHIR-25037: Correct Encounter date-end search code

Issue request:
FHIR-25037 was Published/Persuasive for the PA work group and asked that Encounter support precise start and end searches and sorting for Encounter.actualPeriod. The accepted resolution said to add the two date search parameters date-start and date-end.

Initial application:
The issue was initially applied in git commit 610257357ddcca8b07c65fc961702fa2cafca5f3, which added Encounter.actualPeriod.start and Encounter.actualPeriod.end SearchParameter entries. That commit correctly used Encounter-date-start/date-start for the start parameter and Encounter-date-end as the end parameter id/url, but the end parameter's SearchParameter.code was published as end-date, leaving the current source internally inconsistent with the approved date-end naming.

Additional context:
The February 2020 PA/FHIR-I WGM minutes record the naming approach as using the same search parameter name with X-start or X-end for period boundaries, which for Encounter.date means date-start and date-end. Encounter is an active current-build resource in source/fhir.ini, and source/encounter/bundle-Encounter-search-params.xml feeds the current Encounter search parameter definitions. Later FHIR-34866 added SearchParameter.aliasCode specifically so renamed search parameters can keep backward-compatible alternative codes.

AutoFHIR reconciliation:
This commit makes date-end the primary Encounter actualPeriod end SearchParameter code, adds end-date as an aliasCode for compatibility with the published R5 code, and updates the Encounter compartment date-end reference so current source metadata uses the same primary name.

Recommendation:
Keep this fix. It aligns the current build source with the FHIR-25037 resolution and existing Encounter-date-end canonical id while preserving the previously published end-date query name as an alias. No related issue needs an independent reconciliation commit from this investigation.
