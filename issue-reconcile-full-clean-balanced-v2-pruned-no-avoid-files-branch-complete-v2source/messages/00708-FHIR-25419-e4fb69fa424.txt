FHIR-25419: Fix Appointment date-or-req-period search

Issue request:
FHIR-25419 is Published/Persuasive with Modification for Appointment search. The request was to support one search for booked appointments with Appointment.start and proposed appointments with Appointment.requestedPeriod; the approved resolution introduced a new date-or-req-period search parameter using (start | requestedPeriod.start).first(), introduced a requestedPeriod/requested-period search parameter, and explicitly left the existing date search parameter unchanged.

Initial application:
Git commit ab4f934ab55e8d49013bee2756041fa2c6078d53 applied FHIR-25419 by changing the existing Appointment-date expression from Appointment.start to (start | requestedPeriod.start).first(), which conflicted with the resolution's instruction to leave date unchanged. The requested-period search parameter was then added by the tightly related FHIR-20532 commit 6879287a594dd95d4c49d2962b1791dc0fdd4824, leaving the combined date-or-req-period search parameter missing.

Additional context:
Appointment is active in source/fhir.ini, and source/appointment/bundle-Appointment-search-params.xml is the current Appointment search parameter source. The origin Zulip thread records the implementer need to search booked and proposed appointments together. PA WGM minutes record the FHIR-25419 persuasive-with-modification vote. A later requested-period Zulip thread described date as comparing to Appointment.start and requested-period as comparing to Appointment.requestedPeriod, with no conflicting later Jira decision found in bounded searches.

AutoFHIR reconciliation:
This commit restores Appointment-date to Appointment.start and adds the missing Appointment-date-or-req-period search parameter with code date-or-req-period and the approved expression over Appointment.start and Appointment.requestedPeriod.start. The existing requested-period search parameter remains unchanged because it already satisfies the related requestedPeriod search need.

Recommendation:
Keep this source fix. It aligns the current build-scope Appointment search parameter bundle with the final PA decision without changing unrelated Appointment search parameters.
