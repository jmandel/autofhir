FHIR-41197: Finish Subscription filter resource rename

Issue request:
FHIR-41197 was Applied/Persuasive for R5 and asked to rename Subscription.filterBy.resourceType to Subscription.filterBy.resource because the resourceType element name caused issues with JSON serializers/parsers and had been missed when matching SubscriptionTopic elements were renamed.

Initial application:
The issue was partially applied by dc74cb37a2095621b5fd69bd1eb0217f7d381c18, which renamed the authoritative Subscription StructureDefinition element and two examples. The current source still had live Subscription narrative, framework guidance, a negative invariant test instance, and the checked-in Subscription UML SVG using the old resourceType name.

Additional context:
FHIR-28490 introduced Subscription.filterBy.resourceType as the filter resource discriminator for multi-resource subscriptions, and FHIR-39033 later confirmed the discriminator should remain because filters may apply only to some triggering resources. FHIR-41197 changes the element name, not that semantics. The active fhir.ini resources entries include Subscription and SubscriptionTopic, and source/hierarchy.xml includes subscriptions.html, so these narrative and resource files feed the current build; fhir.ini also retains an explicit old-to-new alias for Subscription.filterBy.resourceType.

AutoFHIR reconciliation:
This commit updates the remaining current-build Subscription references from resourceType to Subscription.filterBy.resource, updates the invariant failure fixture to use the valid renamed element while still failing scr-1 for comparator-plus-modifier, and aligns the checked-in Subscription SVG label/link with the authoritative StructureDefinition.

Recommendation:
Keep this commit as-is. It completes the applied rename without changing the Subscription filter semantics preserved by FHIR-39033; no further core source change is indicated beyond normal regeneration if the build rewrites diagrams.
