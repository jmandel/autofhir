FHIR-34453: Add RatioRange to manual choice lists

Issue request:
FHIR-34453 was Published with resolution Not Persuasive with Modification for R5 after being raised against R4B. The request identified RatioRange and CodeableReference as missing from the listed allowed choice datatypes and called out the generated datatype/extensibility lists plus manually enumerated Task input/output choices; the accepted modification was to avoid permitting the new datatypes in R4B extensions or Parameters for R4 substitutability, while still treating the new datatypes as valid choice types where appropriate.

Initial application:
The Jira snapshot and Zulip discussion indicate the generic list was pre-applied for R4B/R5. In this checkout, the only Jira-keyed implementation commit found is ebcc25884913c9995b6d443c563378c5fad79466 on origin/R4B, which added the R4B contained-resource warning invariant rather than current-main choice-list entries. Current source/fhir.ini already lists both CodeableReference and RatioRange, and datatypes.html/extensibility.html use generated type-list macros. A later untagged current-main update fad1b9cf84ef652e88947e1a13b026c62f95334e added CodeableReference to the manual Parameters and Task choice lists but left RatioRange omitted.

Additional context:
The FHIR-I minutes and Zulip thread clarify the R4B compatibility distinction: the new types should be choice types, but should not be extension/Parameters values in R4B because R4B needed to remain substitutable for R4. The current 6.0.0 source is not the R4B compatibility branch, and Parameters plus Task are active build-scope artifacts in source/fhir.ini. A bounded scan found no other CodeableReference-plus-Ratio choice list omitting RatioRange after this change.

AutoFHIR reconciliation:
Added RatioRange immediately after Ratio in Parameters.parameter.value[x], Task.input.value[x], and Task.output.value[x]. No change was made to datatypes.html or extensibility.html because their current lists are generated from the authoritative datatype list, which already includes RatioRange and CodeableReference.

Recommendation:
Keep this source fix as-is. It closes the stale manual-list gap while preserving the R4B-specific compatibility decision in its historical branch; follow-up is only needed if FHIR-I later decides Task and Parameters should intentionally exclude RatioRange in current releases.
