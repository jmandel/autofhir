FHIR-20972: Correct Account balance source

Issue request:
FHIR-20972 was Published with a Persuasive with Modification resolution for R5 to add Account.balance 0..* with aggregate, term, estimate, amount, and calculatedAt subelements so servers may expose calculated balance information on Account.

Initial application:
The change was initially applied by git commit 4929a4c049aed8232988ff0619032aa5c694af73, which added Account.balance, the account aggregate and balance-term terminology, and matching value sets. That application left Account.balance.calculatedAt with an ElementDefinition.path of Account.calculatedAt, left the Account introduction saying a balance property was still future work, and associated the balance-term CodeSystem with a non-existent account-payment-terms value set URL.

Additional context:
The Account resource is active in source/fhir.ini, and the edited files are under the active source/account resource directory. The linked Zulip discussion and PA/FM minutes show the original concern that balances are volatile, followed by WG acceptance of reintroducing the balance concept with a timestamp. Later Account.balance tickets FHIR-53831 and FHIR-53832 concern future aggregate/coverage refinements and are not final Applied/Published source-edit decisions for this run.

AutoFHIR reconciliation:
This commit fixes the calculatedAt path to Account.balance.calculatedAt, updates the Account introduction to describe optional calculated balances without requiring servers to expose them directly, corrects the AccountBalanceTerm CodeSystem.valueSet URL, and keeps the checked-in Account SVG aligned with the corrected balance child.

Recommendation:
Keep this commit as-is for FHIR-20972. Future work on Account.balance.aggregate or coverage-specific balance attribution should be handled under later applied Jira decisions, not folded into this reconciliation.
