FHIR-20698: Clarify SUBSETTED meta.tag guidance

Issue request:
FHIR-20698 was Published/Persuasive with Modification for R5. It asked for the special SUBSETTED marker used for _summary and _elements responses to have a predictable system and final placement; the adopted resolution added v3-ObservationValue/SUBSETTED to the Common Tags value set used for Meta.tag and changed the search guidance to say servers SHOULD mark resources by populating meta.tag with the SUBSETTED code using the current THO link.

Initial application:
Commit 8ea9cdd184a4864604469b328d340fe471894c8c added SUBSETTED to source/datatypes/valueset-common-tags.xml and updated source/search.html, and commit 57319124bb1723e443ac213e6cec95cc1fbd4e9a changed the search links to deep-link into THO. Current source/datatypes/valueset-common-tags.xml still includes v3-ObservationValue/SUBSETTED and the Meta datatype binding points at valueset-common-tags, but the current _summary sentence in source/search.html had become malformed as "mark the by populating meta.tag resources", and the parallel _elements sentence still said only "with the tag SUBSETTED" rather than the resolved meta.tag placement.

Additional context:
The original implementer discussion asked how generators could know which code system to use, and Lloyd McKenzie pointed to adding the code to the Common Tags value set. Later Security and Privacy Zulip discussion and Security WG minutes clarified that operational subsetting from _summary or _elements belongs in meta.tag, while meta.security is appropriate when subsetting is driven by security or privacy policy. FHIR-5694 and FHIR-48778 are already represented on the combined branch and support the same source shape: SUBSETTED remains available from the external v3 terminology, while Meta.tag now prefers common-tags.

AutoFHIR reconciliation:
Updated source/search.html, an active top-level search narrative page, to use the adopted "by populating meta.tag with the code SUBSETTED" wording for both _summary and _elements. This preserves the existing THO deep link and leaves the already-correct Common Tags value set and Meta binding unchanged.

Recommendation:
Keep this commit as-is. It completes the remaining current-core source correction for FHIR-20698 without reopening the settled meta.tag versus meta.security distinction; future generated outputs should be regenerated from the corrected source page.
