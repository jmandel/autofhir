FHIR-39219: Align SPCU OID registry URLs

Issue request:
FHIR-39219 is a Published FHIR-core Patient Administration change request with a Not Persuasive with Modification resolution. It objected that the Sex for Clinical Use data element and value set wording was discriminatory, and the approved disposition renamed the concept to Sex Parameter for Clinical Use, updated the extension definition/name to the new SPCU language, and left fuller usage guidance to the Gender Harmony Implementation Guide.

Initial application:
The issue was initially applied in core by 7a59cfb6be, which renamed the local SFCU CodeSystem/ValueSet canonicals to sex-parameter-for-clinical-use, and by 996823f8d5, which aligned the Patient example to the renamed extension and CodeSystem. The terminology definitions were then removed from core by f3c0d3659c when Gender Harmony terminology moved out of the core repository. Current core Patient source is in build scope through the active Patient resource entry in source/fhir.ini and already references Sex Parameter for Clinical Use and the external extension/THO CodeSystem. One core source location was missed: source/oids.ini, the permanent OID registry source, still recorded the old sex-for-clinical-use URLs for the same assigned OIDs.

Additional context:
The FHIR Extension Pack contains the patient-sexParameterForClinicalUse extension with the approved SPCU title/description, and current THO hl7.terminology 6.5.0 publishes the CodeSystem and ValueSet as sex-parameter-for-clinical-use with the same OIDs that source/oids.ini tracks. Confluence minutes for the Gender Harmony and PA block votes confirm that most explanatory language was intentionally moved to the Gender Harmony IG and only necessary extension text remained in FHIR R5. Duplicate ballot comments FHIR-39220 through FHIR-39225 are part of the same SFCU/SPCU concern family but are duplicate/background issues rather than independent source-edit decisions.

AutoFHIR reconciliation:
This commit updates source/oids.ini so the active ValueSet OID entry and the commented external CodeSystem OID entry use the current sex-parameter-for-clinical-use canonicals. No Patient narrative, example, extension, or terminology definition was changed because those current sources already use the approved SPCU naming and delegate the authoritative terminology/extension details outside this core checkout.

Recommendation:
Keep this source fix. Because source/oids.ini is the permanent OID record and its header calls for FHIR product director review, a human reviewer should specifically confirm the registry update, but it aligns the core registry with the applied FHIR-39219 rename and current THO identifiers.
