FHIR-25744: Restore shared SearchParameter normativity guidance

Issue request:
FHIR-25744 was a Published/Persuasive with Modification FHIR-I change request asking why Pharmacy resource search parameters appeared normative even though Pharmacy had not approved normative content. The approved resolution said to clarify the versioning page that a normative shared SearchParameter makes the SearchParameter definition normative, while non-normative resource targets/usages remain non-normative and may change; it also called for tooling support for status flags.

Initial application:
The issue was initially applied in source by d390dda8cc and 7da9facca1, which added and refined the shared SearchParameter note in source/versions.html. Related FHIR-25744 commits fede0a9351 and 3c92acb6d1 adjusted SearchParameter standards-status metadata in resource search-parameter bundles after the kindling/tooling follow-up noted in Jira.

Additional context:
source/versions.html is the active Change Management and Versioning page in source/hierarchy.xml. Later readability issue FHIR-47046 preserved the shared SearchParameter note while consolidating the surrounding notes list, but later commit 7466cfc63c removed the whole Mixed Normative notes block and unintentionally removed the FHIR-25744 clarification as collateral. Current source/fhir.ini still lists the Medication, MedicationAdministration, MedicationDispense, MedicationRequest, MedicationStatement, and MedicationKnowledge resources as active with non-normative maturity/status values, while their current search-parameter bundles still include normative SearchParameter definitions, so the original ambiguity remains relevant. No Zulip search result or later Jira evidence was found that reverses FHIR-25744.

AutoFHIR reconciliation:
This commit restores only the missing FHIR-25744 clarification as a short paragraph immediately after the standards-status table note in source/versions.html. It does not reintroduce the broader removed Mixed Normative section and does not alter SearchParameter metadata beyond the authoritative versioning guidance.

Recommendation:
Keep this source fix. It preserves the published FHIR-I decision in the active version policy page with minimal text and avoids reopening the broader trial-use note cleanup; future tooling-specific work, if any, should be handled separately in the publisher/kindling codebase.
