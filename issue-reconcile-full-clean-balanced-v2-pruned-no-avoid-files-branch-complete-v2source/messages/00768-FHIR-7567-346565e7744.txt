FHIR-7567: Correct Provenance PROV mapping preamble

Issue request:
FHIR-7567 was a Published FHIR-core Security change request, resolved Persuasive with Modification, objecting that the Provenance W3C PROV mapping text overstated alignment by saying all parts were formally mapped to PROV-O and transformable to a W3C PROV equivalent. It also raised concerns that Provenance.entity.role was mapped to derivation/revision concepts rather than W3C role semantics and that Provenance lacked a named activity element comparable to Act.code. The final resolution says the issue was resolved through other change proposals and nothing more remained to resolve.

Initial application:
No source commit explicitly mentioning FHIR-7567 was found in the relevant Provenance or mapping-space history. Other Provenance change proposals did add or refine the activity/reason area noted in Jira comments, and the current active Provenance StructureDefinition now has Provenance.activity, authorization/why elements for why the event occurred, and W3C mappings including Provenance.entity.role to Entity.role. However, source/mappingSpaces.xml still carried the exact older W3C PROV mapping preamble that FHIR-7567 quoted, introduced before the issue by git commit 0b3734f9dc.

Additional context:
Provenance is an active current-build resource in source/fhir.ini, and source/mappingSpaces.xml defines the published W3C PROV mapping-space preamble used for the Provenance mappings page. Current Provenance narrative already says the resource is tailored to FHIR use cases and distinguishes FHIR Provenance generation from AuditEvent usage. Related reconciliation commits already on the combined branch cover FHIR-7750's Provenance/AuditEvent separation audit and later W3C/Provenance clarifications in FHIR-23065 and FHIR-55410. Direct Zulip and Confluence searches for FHIR-7567 found no conflicting community evidence.

AutoFHIR reconciliation:
This commit updates the W3C PROV mapping-space preamble in source/mappingSpaces.xml to say the Provenance model is informed by W3C Provenance, tailored to FHIR use cases, and that mappings identify corresponding W3C PROV concepts where appropriate rather than asserting a lossless PROV-O transformation for every FHIR Provenance detail. No StructureDefinition change was made because the current active Provenance definitions already contain the activity and role alignment relevant to this issue.

Recommendation:
Keep this source fix. It removes the stale overclaim that directly matched the FHIR-7567 complaint while preserving the WG's later, narrower FHIR/W3C Provenance positioning; no further FHIR-core work is needed for this issue unless Security reopens broader W3C alignment questions.
