FHIR-15709: Remove stale Composition retracted wording

Issue request:
FHIR-15709 was Published/Persuasive with Modification for the STU3 Composition page. It reported that the Composition Status Codes narrative listed preliminary, final, appended, amended, and retracted while Composition.status was required-bound to CompositionStatus values that used entered-in-error rather than retracted, and the accepted resolution was to update the narrative and remove the hand-written status-code table.

Initial application:
The issue was initially applied by svn 14514 / git b1e621c777, which replaced the hand-written table in source/composition/composition-introduction.xml with the generated composition-status codelist and changed explicit status references from retracted to entered-in-error. That application left two nearby plain-text references to "retracted compositions" in the active status narrative.

Additional context:
Composition is an active current-build resource in source/fhir.ini, and source/composition/composition-introduction.xml is the authoritative narrative source for the Composition page. Later FHIR-37403 expanded CompositionStatus to align with DiagnosticReport and is already represented on the combined branch, so the current narrative should defer the code list to the generated codelist and avoid resurrecting the obsolete retracted wording.

AutoFHIR reconciliation:
This commit updates the remaining Composition status narrative references from "retracted compositions" to compositions marked entered-in-error, preserving the issue's accepted correction without changing the current codelist or later CompositionStatus value-set decisions.

Recommendation:
Keep this source fix as-is. It removes a stale code-like term from the active Composition status section while leaving later status-code changes and generated terminology content intact.
