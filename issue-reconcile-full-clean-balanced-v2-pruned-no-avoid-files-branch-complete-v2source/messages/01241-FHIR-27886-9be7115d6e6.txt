FHIR-27886: Map product workflow elements to product

Issue request:
FHIR-27886 was Published as Persuasive with Modification. It asked whether CodeableReference should apply to workflow Event.code; the accepted resolution kept Request/Event/Definition.code as the action/service concept and added a 0..1 CodeableReference product element to Request, Event, and Definition for resources whose focus is a supplied or manipulated product.

Initial application:
The Jira-tagged implementation commit 0583fe1e3ff39c208fab14d6dad951c311c4fc8e added product to the Definition, Request, and Event pattern spreadsheets, added Definition.code, and updated workflow extension sources. That initial application did not finish all current resource workflow mappings: several active product-like CodeableReference elements still mapped to Request.code or Event.code, and DeviceDispense.device still had a duplicate Event.code mapping despite already mapping to Event.product.

Additional context:
source/fhir.ini lists definition, event, and request as active logical models and keeps the workflow pattern extension spreadsheets active. The current source already contains the intended product pattern rows and code usage notes. Confluence FHIR Workflow minutes for 2020-07-13 record FHIR-27886 as persuasive with modification, and Zulip searches found no contrary community discussion.

AutoFHIR reconciliation:
This commit remaps clear product elements to the workflow product element: MedicationAdministration.medication, MedicationDispense.medication, MedicationStatement.medication, Immunization.administeredProduct, and NutritionIntake.nutritionItem.nutritionProduct now map to Event.product, while MedicationRequest.medication now maps to Request.product. It also removes the stale duplicate Event.code mapping from DeviceDispense.device, leaving its existing Event.product mapping. The corresponding mapping exception files were updated so the product pattern comparison and unmapped code entries match the authoritative StructureDefinition mappings.

Recommendation:
Keep this commit as the bounded completion of FHIR-27886 for current core source. Broader CodeableReference service/action mappings such as ServiceRequest.code, Appointment.serviceType, and Encounter.serviceType remain on Request/Event.code because they describe the requested or performed service rather than a supplied product.
