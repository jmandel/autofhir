FHIR-7549: Clarify shared Dosage method guidance

Issue request:
FHIR-7549 was Published/Persuasive with Modification for the Pharmacy WG. It asked to clean up dosage.method definitions because the old note that method is often pre-coordinated with route or form did not say whether method, route, site, or form should be duplicated. The accepted resolution required clearer dosage.method text across MedicationAdministration, MedicationOrder, MedicationDispense, and MedicationStatement.

Initial application:
SVN r6688, imported as git commit d0e67474395d30f30ce638f3645578f4c9a7cc39, applied the FHIR-7549 wording to the then-current MedicationAdministration, MedicationDispense, and MedicationStatement spreadsheets. Current MedicationAdministration.dosage.method still carries the clarified definition and comment. Later source refactoring introduced the active shared Dosage datatype used by current medication dosage instructions, and that active Dosage.method row still had the terse pre-coordination comment.

Additional context:
source/fhir.ini lists Dosage as an active datatype and MedicationAdministration, MedicationDispense, MedicationRequest, and MedicationStatement as active resources. MedicationOrder has since become MedicationRequest, and current MedicationRequest, MedicationDispense, and MedicationStatement dosage elements use DosageDetails/Dosage-family datatype source rather than their old resource-specific dosage.method rows. FHIR-19913 later corrected the Dosage.method examples to "inject, swallow, or chew"; that later example correction is already represented on the combined branch and should be preserved.

AutoFHIR reconciliation:
Updated source/datatypes/dosage.xml so the active shared Dosage.method definition and comment now carry the FHIR-7549 guidance about method usually not being populated when route or form pre-coordinate the method, while retaining the later FHIR-19913 examples. No MedicationAdministration edit was needed because its active resource-specific definition already contains the same guidance.

Recommendation:
Keep this source fix. It closes the remaining current-build gap created by later dosage datatype refactoring without reverting later Pharmacy WG example wording.
