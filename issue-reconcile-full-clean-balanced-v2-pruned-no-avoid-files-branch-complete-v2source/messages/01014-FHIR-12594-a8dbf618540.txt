FHIR-12594: Relax Patient match-grade requirement

Issue request:
FHIR-12594 is a Published/Persuasive Patient Administration change request against FHIR-core Patient. It asked that Patient $match results not be required to carry the match-grade extension because not all MPIs produce grading and the search score already conveys match certainty. The accepted resolution was to relax the matchgrade extension requirement so systems that do not grade are not required to include it.

Initial application:
The issue was partially applied by git commit 276058c0c9, which changed source/patient/patient-notes.xml from "All patient records SHALL have a score" to "All patient records should have a score". The current Patient OperationDefinition source still contained the old mandatory sentence in both the generated-page footer and the OperationDefinition.comment, so the application was incomplete for the operation definition artifact.

Additional context:
Patient is an active resource in source/fhir.ini, OperationDefinition is part of the active metadata resources, and source/patient/list-Patient-operations.xml references OperationDefinition/Patient-match. The current Patient narrative already has the relaxed "should" wording, while the OperationDefinition still said "SHALL". FHIR-40911 later noted, while updating the moved match-grade extension in the FHIR Extension Pack, that FHIR-12594 still needed to be re-applied in core; that broader extension ticket is not decided by this core commit.

AutoFHIR reconciliation:
Updated source/patient/operationdefinition-Patient-match.xml in both the build footer valueMarkdown and the OperationDefinition.comment so the Patient $match score/match-grade sentence says patient records "should" have the score and extension instead of "SHALL". This preserves the existing example and extension link while removing the stale conformance requirement.

Recommendation:
Keep this source change. It completes the original FHIR-12594 relaxation in the active Patient $match OperationDefinition and aligns it with the already-updated Patient narrative. No additional core source change is recommended for this issue; FHIR-40911 remains a separate FHIR-extensions issue.
