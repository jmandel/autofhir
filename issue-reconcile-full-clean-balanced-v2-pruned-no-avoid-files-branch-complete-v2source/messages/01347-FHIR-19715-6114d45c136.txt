FHIR-19715: Align mapping syntax examples

Issue request:
FHIR-19715 was Published/Persuasive for the FHIR-core StructureMap artifact and requested concrete syntax improvements to the FHIR mapping language: remove the old rule-leading 'for', replace 'make' with the arrow form, separate rules with semicolons, use Pascal-style group parameters, use <<types>>/<<type+>> stereotypes, and use braces for group bodies.

Initial application:
The Jira comment points to commit 6929c27a9da3693998c3f74779e048b423fad51d, which updated source/mapping-language.html to the new group and rule syntax. Current StructureMap is active in source/fhir.ini, and the mapping-language and mapping-tutorial pages are current documentation pages linked from the StructureMap introduction and source/hierarchy.xml.

Additional context:
Later documentation commits reintroduced or left small pre-FHIR-19715 syntax fragments: FHIR-25376 added a source-statement example with the obsolete leading 'for', and the tutorial still described <<types>> as 'group for types' plus one nested rule with the obsolete leading 'for' and one rule lacking the required semicolon. FHIR-29210 later added ActivityDefinition mapping snippets with broader historical syntax; those belong to the separate ActivityDefinition/CDS issue and need a bounded follow-up review rather than being silently rewritten under this StructureMap syntax seed.

AutoFHIR reconciliation:
Updated source/mapping-language.html to remove the obsolete leading 'for' from the source-statement example and add required semicolons to examples. Updated source/mapping-tutorial.html to describe the current <<types>> stereotype, remove the obsolete leading 'for' from the nested rule, and end the final tutorial rule with the required semicolon using the HTML-escaped arrow.

Recommendation:
Keep this source fix as-is for FHIR-19715 because it aligns the core mapping-language documentation and tutorial with the published syntax decision. Consider a separate FHIR-29210 follow-up for the later ActivityDefinition mapping snippets, since those examples are a different artifact and include broader historical syntax and domain-specific mappings.
