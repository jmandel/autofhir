FHIR-42924: Correct R6-to-R5 cross-version package label

Issue request:
FHIR-42924 was an Applied/Persuasive with Modification FHIR-core compatibility correction asking to fix errors in the cross-version extension formal definitions table, including wrong row text, broken-looking package links, and adding R6 coverage.

Initial application:
The issue was applied by commit e89e89caca55, which replaced the older extension package names with the hl7.fhir.uv.xver-* guide/package matrix and added R6 rows and columns. That application mostly corrected the table, but the R6 Extensions row still displayed the R5 Package entry as hl7.fhir.uv.xver-r6.r6 even though the href and row/column position identify the package as xver-r5.r6.

Additional context:
FHIR-42923 clarified that the URL pattern uses the defining version, and FHIR-44615 later asked about using cross-version extensions across multiple FHIR versions. Current source/versions.html is an active core compatibility page and its package matrix is the main current FHIR-core pointer for choosing the correct cross-version extension package.

AutoFHIR reconciliation:
This commit changes only the displayed package label for the R6 Extensions / R5 Package cell from hl7.fhir.uv.xver-r6.r6 to hl7.fhir.uv.xver-r5.r6, matching the existing href and the row/column semantics. No other table entries were changed.

Recommendation:
Keep this source fix as-is. It completes the table correction without reopening the broader cross-version extension package design, and it prevents implementers from reading the R5 target package cell as a self-targeting R6 package.
