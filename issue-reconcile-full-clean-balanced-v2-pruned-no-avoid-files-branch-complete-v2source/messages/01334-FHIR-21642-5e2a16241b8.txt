FHIR-21642: Correct StructureMap const element definitions

Issue request:
FHIR-21642 was a Published/Persuasive FHIR-core mapping-language change request for R5. It asked for a reusable constant construct in mapping files; the approved resolution chose a top-level statement named `let`, whose value may be a constant or an expression using other constants.

Initial application:
The issue was applied in commit cfe0c27ccf77885830ace90028056c9567b969d1, which added a Constants section to source/mapping-language.html with `let [name] = [fhirpath expression];` and added StructureMap.const, StructureMap.const.name, and StructureMap.const.value to source/structuremap/structuredefinition-StructureMap.xml. That initial application left StructureMap.const.name with a copied import definition, and StructureMap.const.value still described the value as a variable with a misspelled short description.

Additional context:
source/mapping-language.html is active in source/hierarchy.xml, and StructureMap is active in source/fhir.ini. The later FHIR-43178 clarification changed only constant evaluation/context wording in the mapping-language page and is already represented on the combined branch, so it does not require a second decision here. Focused Jira, Zulip, and Confluence searches found no conflicting community decision for FHIR-21642.

AutoFHIR reconciliation:
This commit corrects the active StructureMap abstract syntax so StructureMap.const.name defines the name by which a constant is referred to in the mapping language, and StructureMap.const.value consistently describes a FHIRPath expression value for the constant. No grammar, cardinality, or mapping-language-page behavior was changed.

Recommendation:
Keep this commit as-is. It completes the FHIR-21642 application by aligning the generated StructureMap element definitions with the approved `let` constants feature without reopening the later FHIR-43178 evaluation clarification.
