FHIR-34100: Enforce Encounter subject participant constraint

Issue request:
FHIR-34100 was Published with resolution Not Persuasive with Modification for R5. The Jira requested removal of Group as an Encounter participant, but the final PA decision kept Patient and Group as possible participant actors while adding guardrails: Patient/Group participants must not carry participant.type and any Patient/Group participant actor must also be the Encounter.subject.

Initial application:
The issue was initially applied by commit 49ef4a005163617c3019647acedd1eaab45b175d, merged by PR #2391, which added Encounter.participant guidance and invariant enc-2 preventing participant.type for Patient/Group actors. That commit did not add the second requested enforceable constraint requiring the Patient/Group actor to match Encounter.subject; current source only carried that rule as prose in Encounter.participant.comment.

Additional context:
source/fhir.ini actively lists encounter=Encounter, so source/encounter/structuredefinition-Encounter.xml and its invariant-tests directory feed the current build. FHIR-54316 is related later context, but it is still Waiting for Input and concerns explanatory comments for existing invariants, so it is not a separate source-edit decision in this run. PA 2026 WGM minutes also record that the last FHIR-34100 constraint was not applied, confirming the omission rather than reversing the original decision.

AutoFHIR reconciliation:
This commit adds Encounter invariant enc-3 requiring a Patient or Group participant actor to have the same reference as Encounter.subject, marks Encounter.participant.actor with the new condition, and adds a failing invariant test where a contained Patient participant is not the Encounter.subject.

Recommendation:
Keep this source change. It completes the Published FHIR-34100 resolution in an active Encounter build source without implementing non-final FHIR-54316 comment wording; revisit FHIR-54316 separately if PA finalizes that clarification.
