FHIR-7927: Correct conditional delete support note

Issue request:
FHIR-7927 was a Published FHIR-core HTTP change request asking to remove conditional delete support. The final Not Persuasive with Modification resolution kept conditional delete and required explanatory language that transactions and conditional operations are complex and not expected on every server.

Initial application:
The issue appears to have been applied by svn/git commit 51d2438efb (#7928), which added the shared complexity note to conditional update, conditional delete, conditional create, and transaction sections. The FHIR-7927 Jira comments explicitly point to the same resolution as FHIR-7928 and state that the change was already applied.

Additional context:
The current built RESTful API page is source/http.html, linked from source/documentation.html. Later commit 8d445f4fd52 (GF#14495) changed the conditional delete note from referring to unsupported conditional delete to unsupported conditional update while standardizing the error/OperationOutcome language. FHIR-7926 and FHIR-7928 are the same conditional-operation family.

AutoFHIR reconciliation:
This commit changes only the conditional delete section's unsupported-interaction sentence from "conditional update" to "conditional delete". It preserves the resolved decision to keep conditional delete support and to warn that conditional operations are not universally implemented.

Recommendation:
Keep this source fix. It restores the intended local wording without reopening the 2015 decision to retain conditional delete as an optional interaction.
