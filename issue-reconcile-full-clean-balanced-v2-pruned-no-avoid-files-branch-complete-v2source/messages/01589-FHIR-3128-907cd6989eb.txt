FHIR-3128: Fix old extension encoding in example

Issue request:
FHIR-3128 was a Published/Persuasive FHIR-core technical correction for Questionnaire-era extension examples, asking that examples using the older extension XML format be corrected. Jira records the application for DSTU1 and comments identifying svn revision 3066.

Initial application:
The original application is git-svn commit 679da6f1e2cd95e4fd2f1aa3cd4ad157891298fc, which corresponds to svn build revision 3066 and changed source/extensibility.html from a modifierExtension containing a child <url value="..."/> element to a modifierExtension with a url attribute. The current Extensibility page still uses the corrected attribute form in its modifier extension examples.

Additional context:
Questionnaire remains an active resource, and the historically fixed Extensibility page remains active through source/fhir.ini. A current whole-source check for extension or modifierExtension elements that still carried a child url found one later-introduced instance in source/plandefinition/plandefinition-example-episode-of-care.xml. PlanDefinition is an active resource in source/fhir.ini, so the XML example source is in current build scope even though this particular stale encoding was introduced after the original 2014 application.

AutoFHIR reconciliation:
This commit changes the PlanDefinition episode-of-care example's primitive extension from the obsolete <extension><url value="cqf-expression"/>...</extension> shape to the current <extension url="cqf-expression">...</extension> XML shape, preserving the same cqf-expression extension and valueExpression content.

Recommendation:
Keep this commit as a source fix. It completes the same old-format extension example correction in current source without changing semantics; no work-group review is needed unless a full build later identifies additional obsolete extension encodings outside the searched source tree.
