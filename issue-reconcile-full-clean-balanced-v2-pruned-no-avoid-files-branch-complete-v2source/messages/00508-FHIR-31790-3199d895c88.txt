FHIR-31790: Require coded medication-definition statuses

Issue request:
FHIR-31790 was Published/Persuasive with Modification for R5. It asked that status elements not be CodeableConcept, but instead be required code values bound to the standard draft/active/retired/unknown publication-status value set, with cardinality 1..1 and isModifier=true; the resolution also explicitly included ClinicalUseDefinition.

Initial application:
No source commit in this checkout directly applied FHIR-31790. Earlier FHIR-26658 work added PackagedProductDefinition.status as an optional CodeableConcept, and FHIR-31780 later applied the required code/PublicationStatus pattern to AdministrableProductDefinition, ManufacturedItemDefinition, and Ingredient, but the active MedicinalProductDefinition, PackagedProductDefinition, and ClinicalUseDefinition status elements still remained optional CodeableConcept fields with preferred PublicationStatus bindings.

Additional context:
The R4 MedicinalProduct and MedicinalProductPackaged artifacts are represented in the current build by MedicinalProductDefinition and PackagedProductDefinition. source/fhir.ini lists MedicinalProductDefinition, PackagedProductDefinition, and ClinicalUseDefinition as active BRR resources with normative/approved status. BRR Confluence minutes record the FHIR-31790 vote and tie it to the same status/canonical-resource discussion as FHIR-31780 and FHIR-31830. FHIR-31830 has already been reconciled on the combined branch for SubstanceDefinition and uses the same required code/PublicationStatus pattern.

AutoFHIR reconciliation:
This commit changes MedicinalProductDefinition.status, PackagedProductDefinition.status, and ClinicalUseDefinition.status to 1..1 code elements with required bindings to ValueSet/publication-status, common-binding metadata, and retained modifier semantics. It updates the corresponding checked-in status search parameter descriptions, removes obsolete ClinicalUseDefinition pattern-mapping divergences for status cardinality/type/binding, and adds active status values to all checked-in example or invariant-test instances of these resources that would otherwise violate the new required cardinality.

Recommendation:
Keep this source fix. It completes the published BRR decision for the current build and keeps examples/search-parameter source consistent with the changed conformance definitions. FHIR-31780 and FHIR-31830 are the same change family but affect separate resources and should remain separate audit decisions.
