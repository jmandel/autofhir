FHIR-17355: Align Group membership wording

Issue request:
FHIR-17355 is Published/Persuasive for FHIR-core MeasureReport. It asked whether MeasureReport population patient collections should use Group instead of List, and the final disposition was to support Group as the containing/reporting resource and support Group-defined populations in Measure, with later Jira comments clarifying that MeasureReport should still use List for lists of individual MeasureReports and that group-specified and group-reported measures are limited to cases where the population basis matches the populations.

Initial application:
The issue was explicitly applied by 8bffead9c7e4fa14f41c966fea114be9b8e8eadd, which added Measure.group.population.groupDefinition, Measure.group.stratifier.groupDefinition, Measure.group.stratifier.component.groupDefinition, MeasureReport.group.population.subjects, and MeasureReport.group.stratifier.stratum.population.subjects. It also kept MeasureReport subjectResults as Reference(List) and clarified that this List contains individual-level MeasureReport resources, not patients.

Additional context:
Measure and MeasureReport are active resources in source/fhir.ini. FHIR-23724 had already replaced the old Group.actual boolean with Group.membership, whose current required codes include definitional and enumerated. The current FHIR-17355 application still used the retired actual-vs-definitional wording, which made the MeasureReport Group requirement less directly implementable against the current Group resource. The linked Zulip discussion supports the same distinction: Measure can use Group in a definitional role, while MeasureReport needs an enumerated collection of subjects.

AutoFHIR reconciliation:
This commit changes the authoritative Measure and MeasureReport StructureDefinition comments to name the current Group.membership values: Measure groupDefinition references SHALL use membership `definitional`, and MeasureReport subjects references SHALL use membership `enumerated`. No generated SVGs were edited.

Recommendation:
Keep this source change. It preserves the applied FHIR-17355 model while aligning the normative comments with the current Group resource terminology; no further core source work was identified for this issue.
