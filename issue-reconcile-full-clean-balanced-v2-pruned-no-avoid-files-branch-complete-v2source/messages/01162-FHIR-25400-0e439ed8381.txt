FHIR-25400: Correct DeviceDefinition version example

Issue request:
FHIR-25400 was Published as Persuasive for OO and asked to change DeviceDefinition.version from a simple string to a structured version element with type and value details like Device.

Initial application:
The issue was initially applied by git commit b1671782cb, whose message lists 25400 and whose patch changed DeviceDefinition.version from string to BackboneElement and added version.type, version.component, and version.value. Later source evolution left the current main definition semantically correct, but the active DeviceDefinition example still serialized the current top-level version using the old complex shape.

Additional context:
FHIR-40488 later renamed the device/software version backbone from DeviceDefinition.version to DeviceDefinition.deviceVersion so DeviceDefinition could follow the CanonicalResource pattern and use DeviceDefinition.version as the business version string. That later issue is already represented on the combined branch, so this commit does not decide it again. DeviceDefinition is an active current-build resource, and its examples list includes devicedefinition-example.xml.

AutoFHIR reconciliation:
This commit updates the active DeviceDefinition example so the CanonicalResource business version is serialized as the primitive XML element <version value="1.0.0"/> while the typed device/software version remains under <deviceVersion> with type and value.

Recommendation:
Keep this source fix. It preserves the current FHIR-40488 naming while completing the current-state application of FHIR-25400 in the example surface; no further core source change is recommended for this issue.
