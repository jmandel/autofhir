FHIR-55973: Require distinct repeated Questionnaire answers

Issue request:
FHIR-55973 is an Applied/Persuasive FHIR-I change request for FHIR-core Questionnaire. It asked whether repeats=true questions with answer lists may select the same item more than once, and the approved resolution required a QuestionnaireResponse.item invariant prohibiting duplicate answers plus Questionnaire.item.repeats wording that says repeated question answers are distinct.

Initial application:
The Jira comment links HL7/fhir#4074, whose implementation branch contains commit b1e5d1f adding the distinct-answer wording and qrs-4 invariant. That pull request remains open and the current build-scope source on this branch still had the older "multiple answers" wording and no duplicate-answer invariant, so the applied issue was not yet represented in the current source.

Additional context:
source/fhir.ini lists Questionnaire and QuestionnaireResponse as active resources, so the edited StructureDefinition source files feed the current build. The originating Zulip thread records the UI/modeling concern and Lloyd McKenzie's statement that duplicate selections should not be supported. FHIR SDC minutes for 2026-02-26 record FHIR-55973 as Persuasive. FHIR-55921 and FHIR-55975 appeared on the same minutes page only; they are separate Resolved - change required issues and were not decided here.

AutoFHIR reconciliation:
Updated Questionnaire.item.repeats to describe multiple distinct answers and moved the group/question representation note to the start of the comment. Added qrs-4 to QuestionnaireResponse.item requiring answer.value.isDistinct().allTrue(), with a condition reference on QuestionnaireResponse.item.answer, so repeated answers for one question cannot repeat the same value.

Recommendation:
Keep this source-changing commit as the core reconciliation for FHIR-55973. No further core source change is needed for this issue beyond the normal publication/build process that regenerates rendered artifacts from these StructureDefinition inputs.
