FHIR-37955: Align CarePlan based-on search description

Issue request:
FHIR-37955 was Published/Persuasive for R5 and asked to loosen CarePlan.basedOn so a CarePlan can be based on higher-level requests beyond another CarePlan. The approved resolution added ServiceRequest, RequestOrchestration, and NutritionOrder targets and changed the element short display to "Fulfills plan, proposal or order" with a matching broader definition.

Initial application:
The main CarePlan StructureDefinition was applied by 7a6201070b574b69afe13a68407f9dcdee16be95, merged by PR #2437, and the current source still has the broadened target profiles plus the approved short display and definition. That commit did not update the active CarePlan-based-on SearchParameter source, which still described the search parameter as "Fulfills CarePlan".

Additional context:
CarePlan is active in source/fhir.ini, and source/careplan/bundle-CarePlan-search-params.xml is an active source artifact for the CarePlan search parameters. FHIR-38867 is a duplicate/same-change-family issue whose resolution explicitly points to FHIR-37955 and the same implementation commit. Confluence Patient Care minutes record FHIR-37955 as discussed in September 2022 and included in the October 2022 drafted resolutions; no Zulip evidence was found that conflicts with the Jira/source conclusion.

AutoFHIR reconciliation:
Updated the CarePlan-based-on SearchParameter description from the stale "Fulfills CarePlan" wording to "Fulfills plan, proposal or order" so the active search-parameter source no longer contradicts the broadened CarePlan.basedOn element semantics already present in the StructureDefinition.

Recommendation:
Keep this commit as-is. The authoritative element definition and target profiles were already correct; this commit fixes the remaining active source inconsistency without adding redundant narrative or changing unrelated CarePlan artifacts.
