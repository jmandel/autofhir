FHIR-25260: Allow multiple ExampleScenario profiles

Issue request:
FHIR-25260 was Published/Persuasive for R5 and asked ExampleScenario instances to identify both the version of the instantiated structure and any profile/template/ruleset the instance follows. The recorded resolution said to add structureVersion as string 1..1 and profile as uri 0..*.

Initial application:
The relevant fields were added in the ExampleScenario source by the August 2022 implementation history, chiefly commits 022f97b17f (FHIR-37895 partial) and de7f5831c6 (Remainder of FHIR-37195, FHIR-22855, FHIR-25260, FHIR-37895). That history introduced structureVersion and structureProfile[x], but left structureProfile[x] at 0..1.

Additional context:
FHIR-37895 is a later Published/Persuasive with Modification decision that explicitly revisited FHIR-25260: it made structureVersion optional for same-version FHIR structures with an invariant and meaningWhenMissing, and changed the profile element to structureProfile[x] with uri|canonical support. No searched later Jira/Zulip/Confluence evidence changed the FHIR-25260 requirement that the profile element support a set of profiles. source/fhir.ini lists ExampleScenario as an active resource and includes active element mapping for ExampleScenario.instance.structureProfile[x], so the StructureDefinition source and checked-in diagram are in current build scope.

AutoFHIR reconciliation:
This commit changes ExampleScenario.instance.structureProfile[x] from 0..1 to 0..* in source/examplescenario/structuredefinition-ExampleScenario.xml and updates the checked-in ExampleScenario SVG diagram cardinality to match. It intentionally leaves structureVersion at 0..1 with the existing invariant and meaningWhenMissing because that part of FHIR-25260 was superseded by FHIR-37895.

Recommendation:
Keep this commit. It completes the remaining FHIR-25260 profile cardinality requirement while preserving later approved ExampleScenario design changes from FHIR-37895.
