FHIR-22118: Remove stale ImagingStudy identifier accession mapping

Issue request:
FHIR-22118 was Published/Persuasive with Modification for R5. It asked the Imaging Integration work group to undo the overbroad R4-era treatment of accession number as an ImagingStudy.identifier value, to store accession as an ImagingStudy.basedOn Reference.identifier with identifier.type ACSN, and to update the related mapping, example, narrative, and search-parameter text.

Initial application:
The Jira-tagged commit b650c1dd54d447dcbc8aa5fbbab7cacf81972898 applied the main FHIR-22118 changes before R5 by removing the ACSN identifier from the XR example, adding an ACSN Reference.identifier under ImagingStudy.basedOn, moving accession guidance into the notes, updating the based-on and identifier search parameter descriptions, and removing accession from the DICOM identifier mapping. Current source already retains those main changes, but the active StructureDefinition still had a RIM mapping for ImagingStudy.identifier that included an ACSN inbound relationship.

Additional context:
Later Applied issues briefly changed and then restored this policy. FHIR-48644 moved accession back to ImagingStudy.identifier in 2024, but FHIR-49675 superseded that direction in 2025 after the identifier-scope discussion and restored accession to ImagingStudy.basedOn; FHIR-56033 then removed a remaining accession reference from ImagingStudy.identifier comments in 2026. ImagingStudy is active in source/fhir.ini, so source/imagingstudy/structuredefinition-ImagingStudy.xml is build-scoped authoritative source.

AutoFHIR reconciliation:
This commit removes the obsolete ACSN portion of the RIM mapping for ImagingStudy.identifier, leaving it mapped to .id only. It leaves the current basedOn requirements, Accession Number implementation note, based-on search parameter, XR example, and DICOM basedOn mapping unchanged because those already express the final FHIR-22118/FHIR-49675/FHIR-56033 direction.

Recommendation:
Keep this commit as-is. It resolves the remaining build-scoped mapping contradiction without reopening the later work-group decision that accession number guidance belongs under ImagingStudy.basedOn rather than ImagingStudy.identifier.
