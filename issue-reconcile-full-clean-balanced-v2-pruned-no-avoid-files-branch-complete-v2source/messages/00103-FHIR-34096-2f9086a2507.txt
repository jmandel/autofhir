Initial application:

The current source retained the resource, event[x], and reason mappings but no longer retained an Event.performer.actor mapping for the surviving sender concept.

Additional context:
Later MessageHeader work, especially FHIR-41269 and FHIR-32403, moved sender under MessageHeader.source.sender and removed author and responsible for R6. Commit 21db7ce856 applied that refactor and removed the old Event.performer.actor exception entries without adding the corresponding workflow mapping to MessageHeader.source.sender. MessageHeader is in the active build scope via source/fhir.ini, and no Zulip or Confluence search result for FHIR-34096 changed the Jira/source conclusion.

AutoFHIR reconciliation:

It does not reintroduce mappings for author or responsible because those elements were intentionally removed by later applied decisions.

Recommendation:
Keep this commit as-is. It restores the surviving part of the FHIR-34096 Event pattern mapping after the later MessageHeader refactor while respecting the later decision to remove author and responsible. Any non-workflow mappings for MessageHeader.source.sender should be reviewed separately under the issues that moved the sender element.
