FHIR-25387: Restore Consent policy guidance

Issue request:
FHIR-25387 was Published/Persuasive with Modification for FHIR-core Consent. It requested removing the ppc-1 invariant that required either Consent.policy or Consent.policyRule, while adding guidance that a Consent without discrete policy/policyRule data must still include the policy being agreed to or complied with, that computable policy data should be populated as soon as practical, and that profiles or implementation guides may require those elements for narrower scopes.

Initial application:
The issue was applied in commit ef9cfd82f064d240af8c68721cd8be34aa582177 and merged by d2ce402b659ea2cec4b59333b27050d9a43f2711. That change disabled the old "policy exists" invariant in source/consent/consent-spreadsheet.xml and added the Jira guidance as a comment on the old Consent.policy row. The current source no longer has an active policy/policyRule invariant, but commit 3d15d8f10db9fb3f2f57469a3fa986e3baebc1f0 later removed the retired Consent.policy/Consent.policyRule block and dropped the guidance along with it.

Additional context:
Consent is active in the current build through source/fhir.ini, and the current R4 mapping records Consent.policy and Consent.policyRule as moved to Consent.policyBasis and Consent.policyText. The current source also splits the old Consent.source[x] into Consent.sourceAttachment and Consent.sourceReference, so the guidance needs current element names rather than the retired R4 names. FHIR-13360 is the earlier Resolved - No Change request for the same invariant; FHIR-25387 is the later final decision that superseded that outcome. FHIR-25557 was applied in the same historical commit but only fixed quote syntax in another Consent invariant. Zulip and Confluence searches found no conflicting community record.

AutoFHIR reconciliation:
This commit updates source/consent/structuredefinition-Consent.xml, an active build input for the Consent resource, by adding an ElementDefinition comment to Consent.policyBasis. The comment restores the missing guidance using current element names: policyBasis/policyText for the retired policy/policyRule concepts and sourceReference/sourceAttachment for the possible source of the policy text. No invariant is reintroduced.

Recommendation:
Keep this commit as the bounded FHIR-25387 fix. If the work group later wants stronger conformance behavior for specific consent scopes, handle that in a separate profile or implementation-guide decision as the original resolution suggested.
