FHIR-12866: Match item-subject search to true marker

Issue request:
FHIR-12866 was a Published/Persuasive with Modification FHIR-core Questionnaire issue for DSTU2. It asked to remove QuestionnaireResponse.item.subject, add boolean isSubject extensions for Questionnaire.item and QuestionnaireResponse.item, allow the Questionnaire.item marker only on reference questions, and define a reference SearchParameter item-subject for QuestionnaireResponses by items with isSubject=true.

Initial application:
The Jira application comment cites svn revision 13986, represented in git as b6facb155a295bc977faa219f300c573aeb8034f. That commit disabled QuestionnaireResponse.item.subject in the QuestionnaireResponse spreadsheet and added isSubject rows to the then-current Questionnaire and QuestionnaireResponse extension spreadsheets. Later source refactors replaced those spreadsheets with the current active StructureDefinition and search-parameter bundle sources.

Additional context:
Questionnaire and QuestionnaireResponse remain active resources in source/fhir.ini, and the current QuestionnaireResponse StructureDefinition no longer contains QuestionnaireResponse.item.subject. FHIR-19527 later moved questionnaire-isSubject and questionnaireresponse-isSubject out of core to SDC, and the combined branch already has the FHIR-19527 fix that points the item-subject search parameter at http://hl7.org/fhir/uv/sdc/StructureDefinition/sdc-questionnaireresponse-isSubject. FHIR-31479 corrected the old invalid hasExtension(...) function to extension(...).exists(), and FHIR-49784 later made the item traversal recursive; neither later decision changed the FHIR-12866 requirement that the search parameter select items where the boolean marker is true.

AutoFHIR reconciliation:
Updated source/questionnaireresponse/bundle-QuestionnaireResponse-search-params.xml so the active QuestionnaireResponse-item-subject SearchParameter keeps the SDC canonical URL and recursive traversal, but filters on extension(...).value = true instead of extension(...).exists(). No core extension definition was restored because the isSubject definitions now belong in SDC.

Recommendation:
Keep this commit. It preserves the later SDC move and recursive search behavior while making the active core search parameter match the original isSubject=true semantics; any future changes to the extension definitions themselves should be made in the SDC IG, not by reintroducing core extension definitions.
