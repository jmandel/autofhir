FHIR-46579: Remove superseded Observation status code

Issue request:
FHIR-46579 was an OO FHIR-core Observation change request, currently Applied with Jira resolution recorded as Persuasive, about HL7 v2 OBX-11 "cannot be obtained" not mapping cleanly to Observation.status. The final Jira comments and OO minutes show the work group reversed the earlier status-code addition: the core Observation.status and Observation.dataAbsentReason updates were to be dropped, and the result should instead be handled in v2-FHIR mapping guidance by mapping OBX-11=X to Observation.status=cancelled with the original/alternate value extension on Observation.status.

Initial application:
Commit ae3460e91f30bdfd55e6aa6805552527db820ee0 applied the earlier superseded FHIR-46579 direction by adding cannot-be-obtained to source/observation/codesystem-observation-status.xml, adding it to the Observation.status short description in source/observation/structuredefinition-Observation.xml, and adding it to source/observation/observation-event-mapping-exceptions.xml. The later Jira comments explicitly say this update was to the wrong code system, no update to Observation.status or Observation.dataAbsentReason was needed, and the core update could be dropped.

Additional context:
Observation is active in source/fhir.ini, so the Observation StructureDefinition and companion Observation source files are in current build scope. The 2024-10-04 OO minutes record the same reopened decision and the concern that "cannot be obtained" is too broad for a status/data-absent reason code. A later Applied issue, FHIR-50536, changed the v2 mapping text for Observation.status in commit e0109df825a and was left intact here because it is the separate mapping guidance path that FHIR-46579 ultimately pointed to. FHIR-54459 is a later Triaged, unresolved R6 issue about the same stale status code; it supports the concern but is not a final decision and is not decided by this commit.

AutoFHIR reconciliation:
Removed the superseded cannot-be-obtained status code from the active Observation status code system, removed it from Observation.status short text, and removed the parallel mapping exception value. No v2 mapping prose was changed because the later FHIR-50536 mapping text is independently applied and consistent with using an extension rather than a new core Observation.status code.

Recommendation:
Keep this commit as-is. It reconciles the current core source with the final FHIR-46579 disposition while preserving the later v2 mapping clarification. Do not use this commit to close FHIR-54459; if the work group wants additional dataAbsentReason or mapping guidance, that should be handled through a final decision on that separate issue or in the v2-FHIR mapping source.
