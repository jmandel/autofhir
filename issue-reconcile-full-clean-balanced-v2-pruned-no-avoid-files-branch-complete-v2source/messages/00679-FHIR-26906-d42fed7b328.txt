FHIR-26906: Correct Location form search code

Issue request:
FHIR-26906 was Applied with a Persuasive with Modification resolution for the PA Location resource. The issue asked how to support finding/counting beds at a location; the final resolution said Location.form identifies a bed and that new search parameters would be added for both Location.form and Location.mode, while not attempting to represent available beds.

Initial application:
Commit 3bcf58592991dce0f3e27051f0c3009890f3bacc added Location-form and Location-mode SearchParameter entries to source/location/bundle-Location-search-params.xml. That implementation correctly added the Location.form entry, URL, path, description, token type, and expression, but copied the search code from Location.characteristic, leaving the new Location.form SearchParameter published under code "characteristic" instead of "form". Later history only changed standards-status values and did not repair the code.

Additional context:
source/fhir.ini actively includes location=Location, so source/location/bundle-Location-search-params.xml is in the current build scope for the Location resource. Location.mode already has code "mode", and the neighboring Location.characteristic SearchParameter remains code "characteristic". PA Confluence minutes for 2023-04-05 reference FHIR-26906 and defer the formal vote details to the ticket, matching the Jira snapshot. Searches found no Zulip discussion or later Applied/Published Jira decision that changes the requested Location.form/Location.mode search-parameter behavior. FHIR-55300 is a later Resolved - change required value-set migration issue for Location and does not decide the Location.form search parameter code.

AutoFHIR reconciliation:
Corrected the Location.form SearchParameter code from "characteristic" to "form" in source/location/bundle-Location-search-params.xml. No other Location search parameters or element definitions were changed.

Recommendation:
Keep this source fix. It completes the applied FHIR-26906 search-parameter work by making the discoverable search code match the Location.form path, id, URL, expression, and Jira resolution.
