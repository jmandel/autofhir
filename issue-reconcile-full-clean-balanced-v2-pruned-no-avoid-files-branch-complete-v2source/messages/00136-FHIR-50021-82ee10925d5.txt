FHIR-50021: Add Measure reporting frequency maximum binding

Issue request:
FHIR-50021 was an Applied/Persuasive CQI change request for R6 asking that Measure.reportingFrequency Quantity units be constrained to frequency units, with an extensible common UCUM frequency value set and a maximum binding covering all units convertible to frequency.

Initial application:
The Jira-linked implementation landed in d8b0a226358a5c7640c2d9fce9b57a881ddb00b3 as part of HL7/fhir#3932, adding source/measure/valueset-frequency-unit.xml and an extensible binding on Measure.reportingFrequency. The follow-up QA commit bb249227bb4d48f209f0852b08b574452fb8dc71 corrected the value set URL from frequency-units to frequency-unit. That application did not add the second maximum/all-frequency binding requested in the Jira resolution.

Additional context:
Measure is active in source/fhir.ini and source/measure/structuredefinition-Measure.xml is the build-scope source for Measure.reportingFrequency. Current FHIR source has no existing additional binding with purpose maximum, and CodeSystem/additional-binding-purpose marks maximum as deprecated and equivalent to required, so the reconciliation uses a required additional binding to represent the maximum allowed set without introducing deprecated source.

AutoFHIR reconciliation:
Added source/measure/valueset-all-frequency-units.xml for all UCUM units whose canonical unit is /a, and added it to Measure.reportingFrequency as a required additional binding while preserving the existing extensible common-frequency binding.

Recommendation:
Keep this source fix. It completes the Jira resolution without changing the existing common extensible binding; a future publisher-generated refresh may update rendered diagrams or generated artifacts if they display additional bindings.
