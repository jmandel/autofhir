FHIR-21643: Complete mapping list mode documentation

Issue request:
FHIR-21643 was Published with a Persuasive with Modification resolution for the FHIR mapping language. It asked to document target list modes, rename the target list mode code collate to single, and update the ANTLR grammar so share carries the extra id represented by StructureMap.group.rule.target.listRuleId.

Initial application:
Commit 8bf663efea9f377e93c88ed8eda187f7c08b00d6 partially applied the issue for R5 by changing the grammar code collate to single and renaming the CodeSystem concept. It did not document the list modes on mapping-language.html, did not allow share:<id> in the grammar, and accidentally gave single the share definition instead of preserving the old collate behavior.

Additional context:
The edited artifacts are in the current build scope: source/fhir.ini lists StructureMap as an active resource, source/hierarchy.xml includes mapping-language.html under Implementation Support, and publish.ini includes both mapping-language.html and mapping.g4. FHIR-20324 was later retracted after confirming the Java reference implementation supports share/listRuleId. FHIR-57216 and FHIR-57219 raise later R6 questions about target list mode cardinality and meaning, but they are only Submitted and do not supersede the Published FHIR-21643 decision.

AutoFHIR reconciliation:
This commit completes the FHIR-21643 application by documenting first/share/last/single target list modes, linking share:<listRuleId> to StructureMap.group.rule.target.listRuleId, changing the ANTLR targetListMode rule to require share ':' ID, aligning the share CodeSystem definition with the Jira resolution, restoring the single definition to the old collate semantics, and clarifying the StructureMap listRuleId element definition.

Recommendation:
Keep this commit as-is for FHIR-21643. Treat the later Submitted FHIR-57216 and FHIR-57219 issues as separate future work if the work group decides to change target list mode cardinality or remove/deprecate any modes.
