FHIR-7055: Align NKA List emptyReason guidance

Issue request:
FHIR-7055 was Published/Persuasive with Modification for the DSTU1 AllergyIntolerance page. It asked that "No Known Allergies" guidance refer to the List resource and that the "Negating Allergies & Intolerances" section accepted for FHIR-7550 explain where List fits.

Initial application:
The seed was initially applied by git commit 0eea1114d50dfb349fa07d20c74b64aba76bb94c, whose message explicitly says "#7055/7550 - Negation allergies usage notes and value set." That commit expanded source/allergyintolerance/allergyintolerance-notes.xml with List.emptyReason and negated AllergyIntolerance guidance. Later source history retained the section and FHIR-26410's commit a793a6b7db286814f69c9de8908c1f77bbfec526 clarified that AllergyIntolerance.code is the generally preferred way to express "No known allergies" while List.emptyReason remains allowed but discouraged for the full-list case.

Additional context:
FHIR-7550 is the same change family and established the broader explicit-negation section that FHIR-7055 asked to expand. FHIR-11101 recorded support for using CodeableConcept/AllergyIntolerance.code with no source action. FHIR-26410 later clarified the exact wording and added an inline NKA example. Current source/fhir.ini lists both AllergyIntolerance and List as active resources. Current List source binds emptyReason to http://hl7.org/fhir/ValueSet/list-empty-reason, which composes http://terminology.hl7.org/CodeSystem/list-empty-reason, and checked-in List examples use code nilknown. The AllergyIntolerance List.emptyReason prose example and the linked List notes still taught the obsolete special-values/nil-known form.

AutoFHIR reconciliation:
Updated source/allergyintolerance/allergyintolerance-notes.xml so the discouraged List.emptyReason NKA example uses http://terminology.hl7.org/CodeSystem/list-empty-reason with code nilknown. Updated source/list/list-notes.xml so the active List resource notes name the same nilknown code instead of nil-known. These are current-build source files and the changes are limited to keeping the FHIR-7055 List guidance semantically aligned with the current List terminology.

Recommendation:
Keep this source-changing commit. The current AllergyIntolerance guidance already covers the requested List-vs-AllergyIntolerance distinction after the FHIR-7550 and FHIR-26410 history; the remaining reconciliation need was the stale List.emptyReason code/system in the source that implementers would copy from the page.
