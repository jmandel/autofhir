FHIR-8303: Clarify ValueSet $expand valueSet input

Issue request:
FHIR-8303 was Published/Persuasive for the ValueSet $expand operation. It asked why valueSet can be supplied as an input parameter when the client already has the value set, and the accepted resolution was to add: "This parameter is used when the client wants the server to expand a value set that is not stored on the server".

Initial application:
The Jira comment says SVN revision 5482 applied the requested sentence, and git commit 71896e54b3 imported that revision as "#8303 - clarification of Valueset.Expand parameter". Inspecting the patch shows the sentence was added to the old spreadsheet row for validate-code.valueSet, while expand.valueSet remained unchanged. The later source rework and R4B split preserved that state: the active $expand OperationDefinition lacked the clarification, and the active $validate-code OperationDefinition still described its valueSet input as asking the server to expand a value set.

Additional context:
ValueSet is an active resource in source/fhir.ini, and source/valueset/list-ValueSet-operations.xml references both OperationDefinition/ValueSet-expand and OperationDefinition/ValueSet-validate-code, so these XML files are authoritative current-build inputs. Searches for FHIR-8303 and the key valueSet/expand/not-stored terms found no relevant Zulip or Confluence discussion and no later Jira decision superseding the Published resolution.

AutoFHIR reconciliation:
This commit adds the accepted clarification to source/valueset/operationdefinition-ValueSet-expand.xml for the $expand valueSet input. It also changes the directly related $validate-code valueSet sentence from "expand a value set" to "validate a coded value against a value set" so the historical wrong-row application no longer leaves misleading operation-specific wording in the current source.

Recommendation:
Keep this source-changing commit as-is. It applies the Published FHIR-8303 clarification to the active $expand definition and fixes the adjacent artifact of the original misapplication without changing operation cardinalities, parameter names, or conformance mechanics.
