FHIR-34293: Clarify medication detected issue retrieval

Issue request:
FHIR-34293 was Published/Persuasive with Modification for R5. It asked to remove MedicationRequest.detectedIssue because DetectedIssue already points to implicated therapies and FHIR should not create bidirectional links; the resolution also required removal from MedicationDispense and Medication Module guidance for accessing associated detected issues.

Initial application:
Commit 26e2a82259 removed MedicationRequest.detectedIssue and MedicationDispense.detectedIssue from their StructureDefinitions and removed sample detectedIssue references from MedicationRequest and MedicationDispense examples. Current source still has no direct MedicationRequest.detectedIssue or MedicationDispense.detectedIssue element. That historical commit did not change source/medications-module.html, leaving the Medication Module guidance part unapplied.

Additional context:
MedicationRequest and MedicationDispense are active resources and source/medications-module.html is the active Medications module page in source/hierarchy.xml. DetectedIssue.implicated and the DetectedIssue-implicated search parameter already define the reverse association. Later FHIR-39018 resolved Not Persuasive and reaffirmed that references are not bidirectional, that DetectedIssue should point to implicated resources, and that the DetectedIssue search parameter is the retrieval path. Existing DetectedIssue notes also describe created-second linking and containment, but the Medication Module did not point medication implementers to that pattern.

AutoFHIR reconciliation:
Added one Common Use Cases bullet to source/medications-module.html explaining that MedicationRequest and MedicationDispense do not point directly to DetectedIssue, that DetectedIssue.implicated carries the association, and that clients can use DetectedIssue?implicated=MedicationRequest/[id], DetectedIssue?implicated=MedicationDispense/[id], or _revinclude=DetectedIssue:implicated. The bullet also preserves the contained-resource option when the detected issue has no independent lifecycle and does not need direct search.

Recommendation:
Keep this commit as-is. It completes the explicit Medication Module guidance from FHIR-34293 without reintroducing bidirectional resource elements and aligns with FHIR-39018.
