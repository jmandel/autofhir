FHIR-46049: Clarify ValueSet expand version parameters

Issue request:
FHIR-46049 was Applied/Persuasive for R6 by Vocabulary. It asked the core ValueSet $expand operation to add value-set-specific canonical input parameters for dependent value set version selection: valueset-version, check-valueset-version, and force-valueset-version.

Initial application:
The current source already contained the three parameters on ValueSet $expand, with the approved editorial rename from valueset-version to default-valueset-version. Git history shows commit 4cd9f00b61 added them as part of a broader ValueSet operation-parameter commit, but the commit did not mention FHIR-46049 and the copied descriptions still used code-system-oriented wording for the value-set canonical and cross-references.

Additional context:
The linked Zulip discussion and the 2025-03-13 TI minutes confirm the editorial rename to default-valueset-version. FHIR-48979 is the CRMI counterpart and explicitly points to the FHIR-46049 resolution, but it is outside this core checkout. FHIR-51090 and FHIR-54108 are later unresolved proposals for broader terminology operation wording cleanup, so this reconciliation stays limited to the concrete FHIR-46049 wording defects rather than redesigning the parameter family.

AutoFHIR reconciliation:
Updated source/valueset/operationdefinition-ValueSet-expand.xml so the three value-set version parameters describe canonical values as [url]|[version], and so default-valueset-version and check-valueset-version point to the matching system-version and check-system-version parameters rather than force-system-version. Also clarified the force-valueset-version override sentence to name dependent value sets and the overridden value-set version explicitly.

Recommendation:
Keep this source fix. It preserves the WG-approved parameter set and editorial rename while removing misleading copy-paste wording; broader parameter-description harmonization should remain with unresolved follow-up issues such as FHIR-51090 and FHIR-54108.
