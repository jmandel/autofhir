FHIR-34462: Clarify targetProfile allowed types

Attribution note: surfaced while reviewing FHIR-13500, but direct Jira backing for this change is FHIR-34462.

Issue request:
FHIR-13500 was a Published/Persuasive STU3 FHIR-core change request asking to constrain ElementDefinition.type.targetProfile so it was not allowed on arbitrary type codes. The resolution accepted the request because Reference was then the only datatype that could reference another resource.

Initial application:
The issue was applied by svn-backed commit f72d0b9673237211ead8d337c3c4d779faf2ed20, "#13500 - constraint on ElementDefinition", at build revision 12733, adding eld-17 with a Reference-only targetProfile expression. Later history broadened the same area: FHIR-17433/commit 30f92b7806 clarified targetProfile for canonical, and FHIR-34462 plus issue-tagged R4/R4B commits updated eld-17 for CodeableReference.

Additional context:
ElementDefinition is an active normative datatype in source/fhir.ini, so source/datatypes/elementdefinition.xml feeds the current build. The current eld-17 constraint already allows targetProfile when the type code is Reference, canonical, or CodeableReference, and the combined branch already contains a FHIR-34462 commit aligning the eld-17 summary. The remaining ElementDefinition.type.targetProfile definition text still described only Reference/canonical targets, which left reader-facing guidance narrower than the executable constraint and later published decisions.

AutoFHIR reconciliation:
Updated the targetProfile short definition and definition text in source/datatypes/elementdefinition.xml to include CodeableReference alongside Reference and canonical. This keeps the original FHIR-13500 guardrail while reflecting later published expansions of the allowed targetProfile type codes.

Recommendation:
Keep this source fix. It is a narrow consistency update in an active source spreadsheet; no separate related issue should be published from this worker because FHIR-34462 is already represented on the combined branch and FHIR-17433 only supplies historical context.
