FHIR-16769: Qualify CDS/CQI canonical targets

Issue request:
FHIR-16769 was Published/Persuasive with Modification for STU3 by the CDS work group. It asked whether canonicals should be handled as a special case of Reference after CDS/CQI references were replaced by canonical URLs, and the resolution recorded that canonical specifications were supported by tooling and that canonical usages in CDS and CQI resources should specify target types.

Initial application:
The issue was initially applied in SVN revision 14073, preserved as git commit 3dc81b908557, whose subject explicitly says GF#16769/GF#16765 ensured canonical references use qualifiers in knowledge resources. The current ActivityDefinition source already has targetProfile qualifiers for all of its canonical elements, showing the original ActivityDefinition application survived later refactoring.

Additional context:
FHIR-16949 is the same canonical-qualification family and says unqualified canonical is appropriate only when all knowledge/structure resources are intended targets. Later source evolution left two active CDS/CQI elements with clear non-broad semantics unqualified: FHIR-28432 and FHIR-37485 leave PlanDefinition.action.subject[x] with a canonical subject choice parallel to the EvidenceVariable-only PlanDefinition.subjectCanonical correction, and FHIR-49922 added Measure.group.component.measure as a canonical whose definition says it references a Measure. Other currently unqualified canonical elements in GuidanceResponse.module[x], RequestOrchestration.instantiatesCanonical, and ArtifactAssessment.artifact[x] describe broader or less bounded target sets, so this reconciliation does not narrow them.

AutoFHIR reconciliation:
This commit adds targetProfile="Measure" to Measure.group.component.measure, adds targetProfile="EvidenceVariable" to the canonical type on PlanDefinition.action.subject[x], and updates the PlanDefinition definition-mapping exception so its recorded extra type matches the formal canonical target. These files are active source inputs for approved PlanDefinition and Measure resources in source/fhir.ini.

Recommendation:
Keep this commit as-is. It completes the bounded current-source cleanup required by FHIR-16769 without over-constraining canonical elements whose intended target set is broad or ambiguous; any future narrowing of GuidanceResponse.module[x], RequestOrchestration.instantiatesCanonical, or ArtifactAssessment.artifact[x] should be handled by a targeted work-group decision.
