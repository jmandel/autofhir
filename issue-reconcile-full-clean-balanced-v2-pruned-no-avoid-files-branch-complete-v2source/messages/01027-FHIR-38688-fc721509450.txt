FHIR-38688: Complete locale warnings for search text

Issue request:
FHIR-38688 was Published/Persuasive for R5 and asked FHIR-I to warn that case-insensitive text searching and sorting can be locale-dependent. The accepted resolution said to add the proposed guidance to the string search type and relevant modifiers.

Initial application:
The issue was initially applied in git commit f4141be15d0815858d609ebdb4b463f9b23c7dd7, which added locale warning prose to source/search.html for code-text, contains, exact, and the base string search type. The current source retained those additions, but the Jira-related text modifier, text-advanced modifier, and sorting sections still described case-insensitive behavior without the warning; the exact modifier also retained a warning that was not applicable because exact matching includes casing.

Additional context:
source/search.html is the authoritative source for the build.fhir.org search page named in the Jira. FHIR-I minutes on 2022-11-28 record the 12-0-0 persuasive vote, and the 2022-11-21 minutes show the issue was deferred to that vote. Later search-page cleanup and conformance-language commits did not add the missing locale guidance to these related sections.

AutoFHIR reconciliation:
This commit adds the locale/implementation-dependent warning to the text modifier, text-advanced modifier, and string sorting paragraphs, and removes the misplaced case-insensitive warning from the exact modifier paragraph. The existing warnings for code-text, contains, and the base string search type are left intact.

Recommendation:
Keep this source change. It completes the published clarification across the Jira-related case-insensitive search and sort sections without changing search semantics beyond the intended implementation-dependent warning.
