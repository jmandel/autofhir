FHIR-50614: Allow resource type filter modifiers

Issue request:
FHIR-50614 is Applied/Persuasive with Modification for R6 and asks how SubscriptionTopic.trigger.canFilterBy.modifier and Subscription.filterBy.modifier can express the search :type modifier when the value is the target resource type, such as Patient, rather than the literal code type. The accepted resolution was to expand the search modifier value-set coverage to include extended resource types.

Initial application:
The issue-tagged source commit 584ea5fadb47d6ef43add3666481a61e7733c133 added ValueSet/search-modifier-all-codes, which composes search-modifier-code with ValueSet/extended-resource-types, and switched SearchParameter.modifier to that broader value set. Follow-up commits 926c1640e358deb6e9f306569fb474261b372770 and ac7f9d06d91a4955834ac69f9bfcee1185e23ce5 registered and case-corrected the original search-modifier-code value-set file, but Subscription and SubscriptionTopic still bound their modifier elements to the narrower search-modifier-code value set.

Additional context:
FHIR-I minutes from 2025-12-08 record the FHIR-50614 decision as adding codes to the normative value set, and a June 2025 minute shows the issue had been assigned for review because R6/backport handling differed. Current build.fhir.org output still showed Subscription.filterBy.modifier and SubscriptionTopic.trigger.canFilterBy.modifier using search-modifier-code while SearchParameter.modifier used search-modifier-all-codes. The edited StructureDefinition files are active resource sources under source/fhir.ini, and source/search.html is the active search narrative. Generated SVG diagrams still reference the old link but were not edited because they are generated artifacts.

AutoFHIR reconciliation:
This commit completes the already-applied all-codes approach by binding Subscription.filterBy.modifier and SubscriptionTopic.trigger.canFilterBy.modifier to ValueSet/search-modifier-all-codes, updating the SearchParameter/Subscription/SubscriptionTopic definitions and binding descriptions to say resource type codes are allowed for :type, and correcting search.html to link to the broader value set with a concrete subject:Patient example.

Recommendation:
Keep this commit. It aligns the two issue-named subscription elements with the prior SearchParameter.modifier implementation and the accepted FHIR-I decision without changing unrelated search modifier code-system semantics. A later full publication build should regenerate the affected diagrams and rendered artifacts from these source changes.
