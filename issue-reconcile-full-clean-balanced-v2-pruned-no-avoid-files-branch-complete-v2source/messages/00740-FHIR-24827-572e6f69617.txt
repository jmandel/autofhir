FHIR-24827: Require InsurancePlan product reference

Issue request:
FHIR-24827 was Applied/Persuasive for the Patient Administration work group. The final resolution replaced the original parent-link proposal with a split of the former InsurancePlan model: create InsuranceProduct for the product-level content, move the old .plan backbone content into a new InsurancePlan resource, add a 1..1 InsurancePlan.product reference to InsuranceProduct, make Coverage.insurancePlan refer to the new InsurancePlan, and update administrative-module descriptions and diagrams.

Initial application:
The split was partially applied in the December 2023 source history. Commit b9ef5a8515 added the InsuranceProduct resource source, commit 2028e3df2d split InsurancePlan and added InsuranceProduct to the administration module, and PR 2999 repeated the 1..1 InsurancePlan-to-InsuranceProduct requirement. The new InsurancePlan.product element was not added by that split commit; it was added immediately afterward in commit 3a93debb82 as 0..1 while adding the InsurancePlan-product search parameter, and commit a66f52b70 updated the search parameter bundle. That left the active source with the intended reference target but the wrong cardinality.

Additional context:
FHIR-24694 is the duplicate issue that describes the same 2019 PA/FM refactor need. The Confluence Insurance Plan and Product Representation page records the same two-resource approach, with InsurancePlan containing the former plan-level content and a .product property linking to InsuranceProduct. FHIR-33272 was applied in the same restructuring family and assumes the InsurancePlan/InsuranceProduct split, but its resolution concerns InsuranceProduct.related and does not supersede the FHIR-24827 product cardinality. Later applied narrative clarifications in FHIR-47649/FHIR-47650 explain the plan/product relationship and do not approve making InsurancePlan.product optional. FHIR-49710 records later unresolved work to improve examples, so this reconciliation only keeps existing examples valid for the corrected cardinality.

AutoFHIR reconciliation:
This commit changes the active InsurancePlan StructureDefinition source so InsurancePlan.product is 1..1 Reference(InsuranceProduct), matching the applied FHIR-24827 resolution. It also adds product references to the current InsurancePlan example XML files so the examples remain valid when the required element is enforced. The edited StructureDefinition and examples are in build scope through active source/fhir.ini entries for InsurancePlan and InsuranceProduct; no generated SVG/diagram artifacts were edited.

Recommendation:
Keep this source fix. If the work group now wants InsurancePlan.product to be optional, that would be a new substantive decision because it reverses the explicit FHIR-24827 applied cardinality and is not established by the later narrative-only clarification issues.
