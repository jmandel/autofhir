FHIR-12148: Point base search link to current guidance

Issue request:
FHIR-12148 was a Published/Persuasive with Modification FHIR-core search issue for DSTU2. It asked to support cross-resource search by making SearchParameter.base repeatable, performing such searches at the base endpoint with _type limiting the selected resources, defining common or closely related cross-resource search parameters, and documenting that parameters cannot be used against resource types where they are not defined, with a 400 response recommended.

Initial application:
The Jira comments cite svn revisions 10192 and 10244. In git history these are 7bd765da23bd1c47772f2a37f802afbdd6b5857f, which added base-endpoint cross-resource search examples and a draft bundle of common multi-base search parameters, and 83efd116df9f0f4fa900322b07721b8a355d3aec, which added the error guidance for parameters used with resource types not listed in SearchParameter.base.

Additional context:
Later search issues refined but did not reverse the FHIR-12148 outcome. FHIR-12956 clarified the SearchParameter.base comment to say a parameter applies to at least one resource type and is usable in cross-type searches; that issue is already represented on the combined branch. FHIR-36347 later moved detailed allowed-parameter rules out of the HTTP page and into search.html#type, and clarified that multiple-type searches may use parameters commonly referenced by server name/code/alias rather than only identical SearchParameter.base definitions; that issue is also already represented on the combined branch. Current source/fhir.ini lists SearchParameter as an active resource, and the current Search page and HTTP page already describe base-endpoint _type searches and the no-type/single-type/multiple-type parameter rules. The remaining stale artifact was the SearchParameter.base comment still linking readers to the obsolete http.html#xres-search anchor even though the current authoritative section is search.html#type.

AutoFHIR reconciliation:
This commit updates the SearchParameter.base comment link from the obsolete Cross Resource Search target at http.html#xres-search to the current Searching Multiple Resource Types section at search.html#type. No cardinality or search semantics were changed: SearchParameter.base remains 1..*, preserving the later/current requirement that each search parameter applies to at least one resource type while allowing multiple bases.

Recommendation:
Keep this source change as-is. It is a narrow build-scope correction that connects the active SearchParameter.base definition to the current search guidance without reopening the later FHIR-36347 semantics or duplicating already-audited related issues.
