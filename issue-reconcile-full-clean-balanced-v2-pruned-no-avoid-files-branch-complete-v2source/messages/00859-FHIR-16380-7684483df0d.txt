FHIR-16380: Align MonetaryComponent model surfaces

Issue request:
FHIR-16380 was a Published/Persuasive Patient Administration change request for R5 asking that the reusable PriceComponent structure become a metadata type. The final resolution created MonetaryComponent, made it usable as an extension value, and listed ChargeItem.unitPriceComponent, ChargeItem.totalPriceComponent, ChargeItemDefinition.propertyGroup.priceComponent, Invoice.lineItem.priceComponent, and Invoice.totalPriceComponent as users of the new type.

Initial application:
Commit 5c52eddab2 added source/datatypes/monetarycomponent.xml and registered monetarycomponent as a metadata type; commit ee6690b2be changed the active Invoice StructureDefinition priceComponent elements from local backbone/contentReference modeling to MonetaryComponent. ChargeItem and ChargeItemDefinition were later removed from active core resource inputs, and the combined branch already contains FHIR-21001 commit da0a54d378 aligning ChargeItem ModelInfo with MonetaryComponent. The remaining missed application was in active Library examples: FHIR-ModelInfo and FHIRHelpers still exposed Invoice.PriceComponent, ChargeItemDefinition.PriceComponent, and InvoicePriceComponentType.

Additional context:
source/fhir.ini keeps monetarycomponent, Invoice, and Library in the active core build, while ChargeItem and ChargeItemDefinition are no longer active core resources and are linked to the Administrative Incubator IG. The current Administrative Incubator CI StructureDefinitions for ChargeItem and ChargeItemDefinition also use MonetaryComponent for the pricing elements. Later FHIR-44610/duplicate FHIR-37946 work refined PriceComponentType code definitions but did not reverse the FHIR-16380 decision to use the shared type.

AutoFHIR reconciliation:
Updated source/library/library-fhir-model-definition-content.xml so Invoice.lineItem.priceComponent, Invoice.totalPriceComponent, and ChargeItemDefinition.propertyGroup.priceComponent now use FHIR.MonetaryComponent, and removed the stale local PriceComponent class infos plus InvoicePriceComponentType conversion metadata. Updated source/library/library-fhir-helpers-content.cql to expose ToString for FHIR.PriceComponentType. Refreshed the checked-in Invoice SVG label and links for the displayed price component box so it no longer points at removed Invoice child definitions or the retired invoice-specific value set.

Recommendation:
Keep this commit. Future ChargeItem and ChargeItemDefinition structural work should happen in the Administrative Incubator source, but the active core Library and Invoice diagram surfaces needed this reconciliation to avoid publishing stale invoice-specific price-component model metadata.
