FHIR-23565: Align ValueSet expand version return wording

Issue request:
FHIR-23565 was Published/Persuasive with Modification for R5 by Vocabulary. It asked that when a ValueSet expansion is created, the resulting ValueSet include the definition ValueSet.version when that element exists; the final resolution also carried ValueSet.status and used "SHALL be returned in" wording for the expansion resource.

Initial application:
The issue was partially applied by commit ffdf5bcf1e0eed2f1d026c3b87eea4fc587146b7, which changed source/valueset/valueset-notes.xml from "persisted to" to "returned in" and updated the expansion parameter prose. The same stale "persisted to" phrase remained in source/valueset/operationdefinition-ValueSet-expand.xml, which feeds the active ValueSet $expand operation page.

Additional context:
The ValueSet resource is active in source/fhir.ini and source/valueset/list-ValueSet-operations.xml includes OperationDefinition/ValueSet-expand, so the operation definition footer is current build input. Confluence Vocab minutes and the Jira comments confirm the intended rule was not limited to persisted expansions. Later ValueSet $expand parameter work such as FHIR-41589 and FHIR-46049 affects neighboring parameter descriptions but does not reverse this return requirement.

AutoFHIR reconciliation:
Updated source/valueset/operationdefinition-ValueSet-expand.xml so the $expand operation footer says ValueSet.status and ValueSet.version SHALL be returned in the ValueSet resource instance containing the expansion, matching the current ValueSet expansion notes and the FHIR-23565 resolution.

Recommendation:
Keep this source fix. It closes the remaining stale wording in an active operation source without changing the later expansion-parameter refinements.
