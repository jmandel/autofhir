FHIR-32766: Bind MedicationKnowledge indication codes

Issue request:
FHIR-32766 was Published/Persuasive for R5 and reported that CodeableReference elements, specifically Ingredient.item, were missing example value-set bindings. The final resolution required an example binding for Ingredient.item to SNOMED CT medication codes and also called out MedicationKnowledge IndicationGuideline.indication as needing correction.

Initial application:
The Jira-tagged commit 3eb5717dff added the medication-codes example binding to Medication.ingredient.item, which remains present in the active Medication source. Git blame/history showed MedicationKnowledge.indicationGuideline.indication was introduced by the FHIR-30093/FHIR-30090 MedicationKnowledge work and later retargeted from ClinicalUseIssue to ClinicalUseDefinition, but it never received an example binding.

Additional context:
Pharmacy WGM minutes for May 2021 record the FHIR-32766 vote, note the Ingredient.item binding based on Medication.code, and say MedicationKnowledge still had to be addressed after checking other pharmacy resources. source/fhir.ini keeps Medication and MedicationKnowledge in the active build. The same MedicationKnowledge indication semantics are represented inside ClinicalUseDefinition.indication.diseaseSymptomProcedure, which already uses the DiseaseSymptomProcedure example value set for a symptom, disease, or procedure.

AutoFHIR reconciliation:
This commit adds the missing example binding to MedicationKnowledge.indicationGuideline.indication using the existing DiseaseSymptomProcedure binding and value set. No change was needed for Medication.ingredient.item because the previously applied medication-codes binding is already present.

Recommendation:
Keep this source fix. It completes the unapplied MedicationKnowledge portion of FHIR-32766 while preserving the existing Medication.ingredient.item application and avoiding out-of-scope changes to inactive copied artifacts such as FormularyItem.
