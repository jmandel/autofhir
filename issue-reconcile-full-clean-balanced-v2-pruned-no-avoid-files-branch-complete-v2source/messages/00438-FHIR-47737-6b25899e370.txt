FHIR-47737: Require Requirements actor keys

Issue request:
FHIR-47737 was Applied as Persuasive with Modification for FHIR-core Requirements. It asked to support actor links at the individual Requirements.statement level by changing Requirements.actor from a canonical element to a backbone element with key 1..1 id and reference 1..1 canonical children, adding Requirements.statement.actor 0..* id values that refer to actor keys, adding an invariant requiring statement actor values to match Requirements.actor.key, and updating the actor comment to say statements must explicitly identify relevant actors when not all top-level actors apply.

Initial application:
Commit 88c7b5ba applied most of the decision by adding Requirements.actor.reference, Requirements.actor.key, Requirements.statement.actor, the actor-key uniqueness and statement-actor constraints, and example updates. The application left Requirements.actor.key at 0..1, contrary to the final key 1..1 disposition, and left Requirements-example2 with an actor that had no key.

Additional context:
The 2024-10-28 FHIR-I minutes record the same approved disposition with actor key 1..1 and also explain that a mistaken reopen discussion was dismissed for FHIR-47737; the ticket remained as previously addressed. Requirements is an active current-build resource in source/fhir.ini, and the R5/R6 change list includes Requirements.actor.key, Requirements.actor.reference, and Requirements.statement.actor. FHIR-53690 is a later Triaged ballot comment asking why Requirements.actor.key is optional; because it is unresolved, this commit does not decide that issue separately, but it confirms the incomplete application symptom for the applied seed.

AutoFHIR reconciliation:
Changed the active Requirements StructureDefinition source so Requirements.actor.key has min 1, and updated Requirements-example2 so its actor supplies a key. No generated diagram/SVG artifact was manually edited.

Recommendation:
Keep this source fix. It completes the applied FHIR-47737 cardinality decision in the authoritative source and keeps active examples valid. Do not treat this commit as a separate resolution of FHIR-53690 unless the work group later decides that ballot issue should be closed as already addressed by this seed reconciliation.
