FHIR-27789: Require absolute canonical URL regex

Issue request:
FHIR-27789 was Published/Persuasive for R5 and asked FHIR-core to make clear that canonical URLs are absolute, specifically that CanonicalResource.url SHALL be an absolute URI and that the computable regex require a colon in addition to the no-spaces URI baseline.

Initial application:
The Jira-tagged source commit 356b6a87ae updated the CanonicalResource.url short description from "URI" to "absolute URI", while the definition already said "An absolute URI". A later related commit, 5c702608fa for FHIR-30697, added the cnl-1 canonical URL invariant across CanonicalResource.url and inherited canonical-resource URL elements, but that invariant only excluded '|', '#', and spaces and still allowed relative values without a URI scheme colon.

Additional context:
FHIR-I WGM minutes for the FHIR-27789 vote explicitly say canonicals must be absolute URIs rather than relative URLs, that OID URNs remain valid, and that the regex should require a colon. The current datatype narrative already says canonical URLs are never relative, and later CanonicalResource/MetadataResource refactors did not reverse the absolute-URI decision.

AutoFHIR reconciliation:
Updated CanonicalResource.url and the active canonical-resource URL element definitions that carry the cnl-1 invariant so the regex now requires a URI scheme and colon while preserving the existing exclusions for '|', '#', and spaces. Also aligned the stale concrete-resource short descriptions from "represented as a URI" to "represented as an absolute URI" where those elements inherit the CanonicalResource canonical URL semantics. These source files are active build inputs through source/fhir.ini resource/interface entries and the checked source StructureDefinitions.

Recommendation:
Keep this source-changing commit. It completes the missing computable portion of the published FHIR-27789 decision without changing the existing allowance for URN-based canonical URLs.
