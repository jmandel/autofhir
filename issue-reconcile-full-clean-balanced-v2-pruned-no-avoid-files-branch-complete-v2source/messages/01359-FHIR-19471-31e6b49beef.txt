FHIR-19471: Stamp versions on source-owned conformance examples

Issue request:
FHIR-19471 was Published/Persuasive for FHIR-core conformance resources. It requested that FHIR-defined conformance artifacts such as StructureDefinitions, ValueSets, and OperationDefinitions expose their release in the version element so canonical references and downstream expectations work consistently; the resolution directed tooling to stamp FHIR-managed artifacts for R4 and later publications while excluding UTG-defined and other externally maintained artifacts.

Initial application:
The Jira comment points to upstream commit e3380a32e009716cc82a1036faa0d5f91e5e37da, which added version stamping and validation to the historical Java publisher/tooling for generated StructureDefinitions, ValueSets, CodeSystems, ConceptMaps, SearchParameters, OperationDefinitions, and base CapabilityStatements. Current built definitions are already stamped: the build.fhir.org definitions package scan found no FHIR-canonical conformance resources missing version.

Additional context:
The current source tree no longer contains the historical Java publisher code, so remaining publication-version gaps must be reconciled in source-owned XML inputs or left to external publisher behavior. A current build scan found a small bounded set of source-owned FHIR-core conformance example artifacts in the examples package with FHIR canonical URLs but no root version. DeviceDefinition examples were not edited because their version element is not the canonical conformance-resource release field for this issue. The SDC Questionnaire example under http://hl7.org/fhir/us/sdc was not edited because the Jira resolution explicitly excluded externally maintained artifacts. The old generated StructureDefinition/example-composition package artifact is also not edited here because current source has already removed source/structuredefinition/structuredefinition-example-composition.xml under a later profile cleanup.

AutoFHIR reconciliation:
This commit adds the current publication version, 6.0.0-ballot4, to the root version element of the source-owned FHIR-core conformance examples that were missing it: CapabilityStatement, CompartmentDefinition, EventDefinition, MessageDefinition, NamingSystem, Questionnaire, Requirements, SearchParameter, StructureDefinition, and TerminologyCapabilities examples. These files are active source examples for current resources and feed the examples package, so adding the root version directly fixes the current published conformance surface without changing external artifacts or unrelated example-specific version fields.

Recommendation:
Keep this source-changing commit. It closes the bounded current-source gap left after the original tooling application while preserving the exclusion for externally maintained artifacts. Future publication tooling should continue stamping generated definitions automatically; if publisher behavior changes, re-scan the definitions and examples packages for FHIR canonical resources without root version.
