FHIR-25225: Clarify of-type modifier matching

Issue request:
FHIR-25225 was Published with a Persuasive resolution for R5. It asked FHIR-I to clarify the token :of-type modifier wording because the old definition said the system and code "match if any of the type codes match," did not explicitly say the value part matches Identifier.value, and needed a complete sentence.

Initial application:
Git history shows commit 72b489cb7de6b73ca07e959f64be25c369c37b48 applied a first pass to source/search.html by adding the intended Identifier.type.coding and Identifier.value matching explanation. The active search-modifier-code CodeSystem source still retained the older ambiguous definition, so the computable terminology page remained inconsistent with the clarified search-page text.

Additional context:
source/fhir.ini actively includes the search-modifier-code value set, and source/search.html links to the search-modifier-code CodeSystem, so the CodeSystem definition is in current build scope and visible to implementers. Related Published issues FHIR-26062 and FHIR-36683 already have reconciliation commits on the combined branch for the of-type code spelling and type-property mapping; they do not update this stale definition. FHIR-I minutes for 2020-04-13 record the unanimous FHIR-25225 Persuasive motion, and local Zulip searches found no issue-key discussion that changes the Jira/source conclusion.

AutoFHIR reconciliation:
Updated source/searchparameter/codesystem-search-modifier-code.xml so the of-type definition now says the system and code parts match by the Identifier.type.coding system|code token and the value part matches Identifier.value. Also removed the duplicated "the" in the corresponding source/search.html paragraph that came from the initial application.
