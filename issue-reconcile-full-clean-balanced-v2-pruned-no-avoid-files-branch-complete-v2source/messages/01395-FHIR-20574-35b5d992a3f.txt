FHIR-20574: Add Device category search parameter

Issue request:
FHIR-20574 was a Published/Persuasive with Modification FHIR-core Device change request raised from STU3 and applied for R5. The original request asked for a high-level Device.category, a token search parameter named category, and initially similar DeviceDefinition category support for API-relevant distinctions such as implantable devices, durable medical equipment, personal health devices, reusable devices, prosthetics, point-of-care devices, and software.

Initial application:
Git commit 3c23148747a7d0fead21ff9afaab2fc3bb65eae9, titled "apply #20574", applied the later Device scope/boundary resolution by updating Device and DeviceDefinition narrative and related Device scope text, but it did not add a Device category search parameter. Git commit 14e5c20f1f34a491dd0b8af3b9f1bf8bc1082b2c later added Device.category as a 0..* CodeableConcept bound to ValueSet/device-category, and the combined branch already includes 76fc66224becc78b5b0432e9e02e7c9d5f42bf0f for FHIR-32080 to complete the Device category terminology. Before this reconciliation, source/device/bundle-Device-search-params.xml still had no Device-category search parameter.

Additional context:
The approved Device Scope-Boundary-Relationships Confluence page and the current Device narrative say devices may be associated with one or more categories and list the high-level category examples. FHIR-32080 is a same-change-family Published Device categorization issue that references the FHIR-20574 scope/boundary category work, while FHIR-35984 later kept the category examples in the Device scope text. FHIR-55253 may later move Device category terminology to THO, but it is only Resolved - change required and does not remove the current Device.category element or the need for search while the element remains in core. No relevant Zulip or Confluence search result was found that rejected a Device.category search parameter. The earlier DeviceDefinition.category proposal was not carried into the final scope/boundary resolution and would be a broader model change, so this commit does not add a DeviceDefinition element.

AutoFHIR reconciliation:
This commit adds the missing source search parameter entry in source/device/bundle-Device-search-params.xml: id Device-category, code category, token type, expression Device.category, and the standard path metadata. Device is active in source/fhir.ini and the search-parameter bundle is the authoritative source for built Device search parameters, so this is a build-scoped source fix rather than generated-output cleanup.

Recommendation:
Keep this commit as-is. It completes the API-facing portion of FHIR-20574 now that Device.category and its terminology already exist, without reopening the broader and unsupported DeviceDefinition.category model question. Future THO migration from FHIR-55253 can update the binding target if and when that later issue is applied.
