FHIR-5907: Clarify Contract term actions

Issue request:
FHIR-5907 was a Published/Persuasive with Modification Contract change request. It objected that Contract.action and Contract.actionReason were too vague and potentially overlapped Contract.term or valuedItem, and its final resolution required Contract.term actions to have a clear definition based on the topic and offer.topic contents.

Initial application:
No direct FHIR-5907 or GF#5907 implementation commit was found. Later Contract history, especially GF#13403, reworked Contract for Ricardian concepts and left the current Contract.term.action structure in the active resource, but the root Contract.term.action text still described an actor/entity being assigned responsibility rather than an action tied to the term topic. Current source also retained stale references to removed Contract.action/Contract.action.reason and Contract.topic.term paths in Contract subject/topic prose and mapping exception text.

Additional context:
Contract is active in source/fhir.ini for the current build. The old ConsentDirective profile still contains Contract.term.actionReason, but source/fhir.ini marks ConsentDirective as having become Consent and has no active profile entry for that file, so it was not edited. A 2025 #financial Zulip thread independently noted that the current Contract.term.action description was weird because an action cannot be an entity. FHIR-55563 later proposes removing Contract from the R6 normative specification and has an implementation branch, but that issue is only Resolved - change required and its removal commit is not on the current worker HEAD, so this reconciliation fixes the active core source rather than deciding the broader removal.

AutoFHIR reconciliation:
Updated the authoritative Contract StructureDefinition so Contract.term.action is defined as an action required or prohibited by the Contract term, explicitly tied to Contract.term.topic[x] or Contract.term.offer.topic, and explained how type, doNotPerform, and reason specify the action. Replaced stale removed-path references with current Contract.term.action, Contract.term.action.reason, Contract.term.topic[x], and Contract.term.asset.valuedItem paths in the Contract subject/topic requirements and the Event/Request mapping exception source. Updated the checked-in Contract SVG tooltip for the edited action node to keep the generated-looking diagram text consistent with the authoritative source change.

Recommendation:
Keep this source-changing commit for the current active Contract resource. If FHIR-55563 is later applied to remove or relocate Contract, that separate broader decision should supersede this local cleanup; until then, the current build should not describe Contract.term.action as an entity or refer implementers to removed Contract.action paths.
