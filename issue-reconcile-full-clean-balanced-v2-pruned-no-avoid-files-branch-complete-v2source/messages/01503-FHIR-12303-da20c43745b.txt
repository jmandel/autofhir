FHIR-12303: Fix vaccine-code expansion

Issue request:
FHIR-12303 was a Published/Persuasive FHIR-core Immunization correction from DSTU2. It reported that the vaccine-code value set page could not render its Expansion section because publication tooling encountered a code system unknown to the build tooling.

Initial application:
Jira records the issue as auto-approved and fixed in 2017, but no Jira-tagged source commit was found. Historical release expansion bundles for R3/R4/R5 contain a successful vaccine-code expansion with CVX plus 73 Australian ACIR concepts, so the issue appears to have been handled through generated expansion/cache state rather than a durable current source definition.

Additional context:
Immunization is an active current-build resource. FHIR-5444 created the international example vaccine-code value set and examples, so removing ACIR entirely would undo the accepted multi-system example intent. FHIR-31774 later recorded that the ACIR system is no longer used/replaced and that vaccine-code is only an example binding, which supports keeping the fix bounded to the historical ACIR example concepts rather than trying to define or update a complete authoritative Australian code system. The current build.fhir.org page reproduced the expansion failure because tx.fhir.org could not find CodeSystem urn:oid:1.2.36.1.2001.1005.17.

AutoFHIR reconciliation:
This commit adds a build-scoped ACIR CodeSystem fragment in source/immunization and changes the vaccine-code value set's ACIR include from an unbounded include-all reference to the 73 ACIR concepts present in the R3/R4/R5 generated expansions. The value set still includes CVX from the terminology server and still carries the Australian example codes used by Immunization examples, but expansion no longer depends on tx.fhir.org having an unavailable external ACIR code system.

Recommendation:
Keep this source fix. If PHER wants to replace ACIR with a current Australian code system or retire the ACIR examples altogether, that should be a separate work-group decision because it would change the example value set's international coding guidance beyond the expansion failure fixed here.
