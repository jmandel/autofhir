FHIR-17484: Use ex-benefitcategory in Claim example

Issue request:
FHIR-17484 was a Published/Persuasive Financial Management STU3 change request for Claim, ClaimResponse, and ExplanationOfBenefit. It asked to remove BenefitSubCategory, consolidate benefit category and subcategory into a single benefitCategory concept, and replace the old benefit-subcategory value set with the example ex-benefitcategory value set containing both high- and low-level concepts.

Initial application:
The issue appears to have been applied in historical commit 10ac2496c7fa29fe458c13a1ef3f7edb89485acc, whose message lists tracker 17484. That commit changed the Claim, ClaimResponse, and ExplanationOfBenefit spreadsheet sources from BenefitSubCategory to BenefitCategory bindings and created the ex-benefitcategory CodeSystem/ValueSet source. Later source refactors carried those bindings into the current XML StructureDefinition sources.

Additional context:
source/fhir.ini lists Claim, ClaimResponse, and ExplanationOfBenefit as active approved resources. The current StructureDefinition sources already bind the relevant category elements to http://hl7.org/fhir/ValueSet/ex-benefitcategory, and the CI terminology page for ex-benefitcategory expands the THO CodeSystem http://terminology.hl7.org/CodeSystem/ex-benefitcategory with both broad and detailed codes including F6 Vision Coverage. The active Claim examples list still includes the 3-tier vision glasses example, and that built example still used the obsolete http://example.org/fhir/CodeSystem/benefit-subcategory system in its category codings. Unreferenced legacy benefit-category/subcategory terminology source files remain under source/explanationofbenefit, but their corresponding CI pages return 404 and no active Claim/ClaimResponse/ExplanationOfBenefit binding depends on them.

AutoFHIR reconciliation:
This commit updates the active Claim 3-tier vision glasses example so each item/detail/subDetail category coding uses http://terminology.hl7.org/CodeSystem/ex-benefitcategory. That preserves the example's F6 Vision Coverage code while aligning the current built example with the FHIR-17484 consolidation and the active ex-benefitcategory binding. It intentionally does not delete legacy unpublished terminology source files because the necessary current-spec semantic fix is in the active built example.

Recommendation:
Keep this source fix as-is. The active conformance definitions already reflect FHIR-17484, and this change removes the remaining active example-level reference to the obsolete benefit-subcategory code system without broad source cleanup.
