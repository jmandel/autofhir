FHIR-49741: Restore DeviceDefinition additive backbone

Issue request:
FHIR-49741 was an Applied/Persuasive with Modification OO change request for R6. It asked for additive 0..* backbones on both DeviceDefinition and Device so Specimen.container.device can represent container additives, with additive.type 1..1 CodeableReference(Substance) and additive.quantity 0..1 SimpleQuantity; the Device-specific performer/performed fields were part of the original resolution.

Initial application:
The issue was initially applied by ead1000d9e and merged by PR #3424, adding Device.additive and DeviceDefinition.additive plus FiveWs mapping exceptions. Current Device source still has additive.type and additive.quantity, but DeviceDefinition.additive disappeared from the active StructureDefinition after PR #3432 merged a DeviceDefinition branch that lacked the newly added element.

Additional context:
Device and DeviceDefinition are active current-build resources in source/fhir.ini. FHIR-50160 was later Applied/Persuasive with Modification and intentionally removed Device.additive.performer and Device.additive.performed, replacing those details with Procedure guidance; this reconciliation therefore does not restore those Device sub-elements. FHIR-49881 discusses a broader future approach for Device/DeviceDefinition additives, but it remains Waiting for Input and is not a final superseding decision.

AutoFHIR reconciliation:
This commit restores DeviceDefinition.additive, DeviceDefinition.additive.type, and DeviceDefinition.additive.quantity in the active DeviceDefinition StructureDefinition, aligned with the current Device.additive shape using CodeableReference(SubstanceDefinition) and SimpleQuantity. It also restores the FiveWs mapping exception for the repeating additive backbone and adds R5-to-R6 fhir.ini change entries for the new DeviceDefinition elements.

Recommendation:
Keep this commit as the bounded completion of FHIR-49741 for current core source. Revisit the additive modeling only when FHIR-49881 or another final work-group decision replaces this applied R6 structure; do not reintroduce Device.additive.performer or Device.additive.performed because FHIR-50160 already removed them.
