FHIR-42900 + FHIR-39389: Correct DeviceDefinition URL search text

Attribution note: surfaced while reviewing FHIR-26310, but direct Jira backing for this change is FHIR-42900 + FHIR-39389.

Issue request:
FHIR-26310 was Published/Persuasive for R5 and asked to remove DeviceDefinition.url, or clarify another purpose, because the then-current element described a network address for an actual device instance. The accepted rationale was that only actual devices, not device definitions, can have addressable endpoints.

Initial application:
The original endpoint-style DeviceDefinition.url existed in early R4B/R5 source as "Network address to contact device". The R4/R5 conversion notes now record "DeviceDefinition.url= Removed - only instances have addressable endpoints", and git history shows the element absent immediately before the later canonical-resource change.

Additional context:
Later DeviceDefinition modeling decisions, especially FHIR-39389 and FHIR-42900, changed DeviceDefinition to specialize CanonicalResource. That deliberately reintroduced DeviceDefinition.url as a canonical identifier, not as an addressable device endpoint, and DeviceDefinition is active in source/fhir.ini. The active DeviceDefinition URL search parameter, added with that canonical-resource work and later marked normative/active by FHIR-53212, still had a copy/paste description saying it identified a code system.

AutoFHIR reconciliation:
This commit keeps the current canonical DeviceDefinition.url element and changes only the active DeviceDefinition-url search parameter description from "code system" to "device definition" so the remaining URL surface no longer conflicts with FHIR-26310's endpoint concern.

Recommendation:
Keep this source fix as-is. Do not remove the current DeviceDefinition.url element for FHIR-26310; any further canonical-modeling changes belong with the later FHIR-39389/FHIR-42900 family.
