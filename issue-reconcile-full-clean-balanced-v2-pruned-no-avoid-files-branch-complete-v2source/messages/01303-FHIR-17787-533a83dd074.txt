FHIR-17787: Clarify ObservationDefinition appliesTo conjunction

Issue request:
FHIR-17787 was Published with a Persuasive with Modification resolution for STU3. It asked whether multiple Observation.referenceRange.appliesTo values mean logical AND or OR and noted the same ambiguity for ObservationDefinition.qualifiedInterval.appliesTo. The accepted rule was that repeated Observation.referenceRange instances are OR alternatives, while repeated appliesTo values inside one range/interval are an AND intersection of the target population.

Initial application:
The Jira comment identifies commit 49ecb8feb51079b5eb5e34a2f8639078a5d2c3ea as the initial application. That commit added the OR wording to Observation.referenceRange and the AND wording to Observation.referenceRange.appliesTo in the old spreadsheet source. Current Observation source still carries both clarifications.

Additional context:
ObservationDefinition is active in the current build: source/fhir.ini lists ObservationDefinition as a draft resource, maps the observationdefinition folder to the resource, and maps the old ObservationDefinition.qualifiedInterval.appliesTo path to the current ObservationDefinition.qualifiedValue.appliesTo path. A 2021 ObservationDefinition refactor changed qualifiedInterval to qualifiedValue and left the current appliesTo definition without the AND clarification, so the ObservationDefinition side of the published issue was no longer fully represented. FHIR-18240 is a duplicate background issue asking the same Observation.referenceRange.appliesTo AND/OR question, but it is not an independent decision here.

AutoFHIR reconciliation:
Updated source/observationdefinition/structuredefinition-ObservationDefinition.xml to say that multiple ObservationDefinition.qualifiedValue.appliesTo values are interpreted as an AND of the target populations, using the same African American female example already present on Observation.referenceRange.appliesTo. No other source was changed because Observation.referenceRange and Observation.referenceRange.appliesTo already express the accepted OR/AND distinction.

Recommendation:
Keep this commit as-is. It restores the published OO decision to the active renamed ObservationDefinition element without changing the accepted Observation wording or opening a broader policy question about declaring cardinality combination semantics elsewhere.
