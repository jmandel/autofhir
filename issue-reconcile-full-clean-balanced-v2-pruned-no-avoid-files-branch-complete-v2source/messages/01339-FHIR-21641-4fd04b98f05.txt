FHIR-21641: Document source path shortcut

Issue request:
FHIR-21641 was a Published/Persuasive FHIR-I change request for the FHIR mapping language page. It asked to allow a source statement such as `src.c.p as p` to walk deeper than one child and to document the feature as a syntactical shortcut, including the formal expansion of that shortcut and FHIRPath-like flattening of repeating intermediate children.

Initial application:
The Jira-tagged implementation commit 487c535a31df0e73e45f52d64b20f2fd8c8f6c88 changed `source/mapping-language.html`, but placed the shortcut text under the Target Transform section. The current Source Content section still described only `context.element`, so the applied source did not document the requested source statement syntax.

Additional context:
The mapping-language page is current build input linked from `source/documentation.html` and the implementation support module, and StructureMap remains an active resource in `source/fhir.ini`. Later FHIR-54476 is a Resolved - change required R6 ballot issue for a broader non-compatible representation change to make source and target element properties ordered multi-cardinality; it confirms this area is still being refined, but it is not Applied/Published and is not decided by this commit.

AutoFHIR reconciliation:
This commit updates the Source Content grammar and prose to document `context.element(.subElement)` for source statements, adds the `src.c.p` expansion and repeat-flattening semantics requested by the issue, and removes the misplaced source-specific expansion example from the Target Transform prose while leaving the existing target subElement statement intact.

Recommendation:
Keep this source fix as the R5/R6 reconciliation for FHIR-21641. Revisit StructureMap source/target element representation separately when FHIR-54476 is applied, because that later issue proposes a broader resource-model change beyond this published source-statement shortcut.
