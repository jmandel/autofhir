FHIR-51725: Clarify extension references in compartments

Attribution note: surfaced while reviewing FHIR-5816, but direct Jira backing for this change is FHIR-51725.

Issue request:
FHIR-5816 was Published/Persuasive for DSTU1 and asked the specification to document that servers decide whether resources belong with a compartment when the reference establishing that relationship is carried by an extension.

Initial application:
Jira records svn 4610 as adding the requested note to extras.html. In the git history, commit 4981f29411d5822e11c377e2f276548abf43d35a added the exact note in source/extras.html, and later compartment refactors carried it into the active CompartmentDefinition notes source.

Additional context:
CompartmentDefinition is an active resource in source/fhir.ini, so source/compartmentdefinition/compartmentdefinition-notes.xml is in current build scope. Later applied issue FHIR-51725, supported by the 2025-11-03 FHIR-I minutes and the preceding Zulip thread, clarified that formal compartment membership is determined by CompartmentDefinition resource.param search parameters; resources outside the compartment may still be returned by _include or local convention at server discretion. The Zulip thread specifically called out the old FHIR-5816 sentence as needing revised wording because such resources are made available rather than being formally in the compartment.

AutoFHIR reconciliation:
Updated the active CompartmentDefinition notes to preserve the FHIR-5816 server-discretion guidance while avoiding a stale implication of formal compartment membership. The note now says extension-based references may make resources available through compartment-based retrieval operations, and that those resources are formally part of the compartment only when the CompartmentDefinition identifies a search parameter for the relationship.

Recommendation:
Keep this source change. It is a narrow current-build correction that reconciles the original FHIR-5816 guidance with the later applied CompartmentDefinition semantics from FHIR-51725. No separate decision is made here for FHIR-51603 or FHIR-51725 because those issues are related context rather than this seed's audit target.
