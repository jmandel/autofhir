FHIR-53546: Correct conditional-create transaction warning

Issue request:
FHIR-53546 was Applied with a Persuasive with Modification resolution for R6. It asked the RESTful API conditional create section to warn that If-None-Exist searches are not fully transactionally enforceable for arbitrary criteria, and that servers may check multiple such creates within a transaction for possible collisions.

Initial application:
The issue was initially applied by git commit ee0c7145162a37e8e7b66727df796b9f2caf028a, which added the requested dragon warning to source/http.html. That commit preserved the resolution text's misspelled phrase "if-non-exist creates", leaving the new warning inconsistent with the actual If-None-Exist header used throughout the same section.

Additional context:
The HTTP page is active current-spec source for the RESTful API page and is linked from the documentation and exchange module pages. FHIR-I minutes for 2025-12-01 record the discussion about race conditions and the 6-0-0 Persuasive with Modification motion. Zulip implementer discussions about If-None-Exist race conditions support the same practical concern and did not reveal a conflicting rule.

AutoFHIR reconciliation:
This commit keeps the already-applied dragon warning and narrows the reconciliation to the source defect left by the initial application: the collision-check sentence now refers to multiple conditional creates using <code>If-None-Exist</code> headers. It also removes trailing whitespace on the immediately preceding warning sentence.

Recommendation:
Keep this commit as-is. The substantive warning is already in the active HTTP source, and this correction makes the newly added text use the canonical header name without broadening the work-group decision.
