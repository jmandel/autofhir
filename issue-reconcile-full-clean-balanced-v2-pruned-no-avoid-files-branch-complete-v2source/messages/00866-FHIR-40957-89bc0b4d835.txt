FHIR-40957: Clarify REST interaction wording

Issue request:
FHIR-40957 was an Applied/Persuasive with Modification FHIR-core Conformance change request asking that CapabilityStatement.rest.interaction documentation and related RESTful API page wording use "interaction" instead of the confusing term "operation" where the REST interaction concept is meant.

Initial application:
The issue was initially applied by git commit a1b0f9752317574b96f42761f140bb7c730de0cd, which updated many CapabilityStatement.rest.resource.interaction and RESTful API occurrences. That application missed the CapabilityStatement.rest.interaction definition itself, left parallel RESTful-interaction ValueSet/SVG wording stale, and introduced or left several REST page wording problems.

Additional context:
FHIR Infrastructure WGM minutes for 2023-09 include the tracker discussion and specifically note that the RESTful page also had instances where "operation" should be "interaction". No relevant Zulip discussion was found for this exact tracker, so the decision rests on Jira, the meeting note, current source, and the explicit application commit.

AutoFHIR reconciliation:
This commit changes the active CapabilityStatement source definition for CapabilityStatement.rest.interaction to "restful interactions", synchronizes the checked-in CapabilityStatement SVG title and companion RESTful-interaction ValueSet descriptions, and corrects the RESTful API page where REST interactions were still called operations or where the prior application left ungrammatical/wrong wording. It preserves true OperationDefinition and JSON Patch operation references.

Recommendation:
Keep this source-changing commit. It completes the applied Jira clarification in current core source while avoiding broader changes to genuine operations framework text.
