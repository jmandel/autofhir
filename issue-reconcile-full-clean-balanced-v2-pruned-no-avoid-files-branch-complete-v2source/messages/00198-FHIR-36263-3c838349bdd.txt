FHIR-36263: Add abandoned to Consent.status

Issue request:
FHIR-36263 was Published/Persuasive for FHIR-core Consent in R5. It requested adding the Resource Status `abandoned` code to the Consent.status value set for consent requests that expire without ever being accepted or declined.

Initial application:
The request was initially applied in commit 27635dd16f, which added an abandoned-state Consent status concept but used a local code value instead of `abandoned`. Commit e757a816b1 then corrected that concept to `not-done`, updated the Consent.status short description, and updated status-codes.xml; commit 91ff45e541 later normalized the source. The current source and R5 publication therefore conveyed the abandoned state as `not-done` with display `Abandoned`, but did not include the requested `abandoned` code in the Consent state code system.

Additional context:
Consent is active in the current build via source/fhir.ini. The ValueSet/consent-state-codes source includes the whole Consent state CodeSystem, so adding the code system concept adds the code to the value set. The current `not-done` code is already published and is retained; this reconciliation is additive to avoid removing an existing published code. Searches found no later Jira, Zulip, or Confluence decision reversing or narrowing FHIR-36263.

AutoFHIR reconciliation:
Added `abandoned` to source/consent/codesystem-consent-state-codes.xml with the same abandoned-consent definition used by the existing concept, aligned the active Consent.status short text, Consent status search parameter description, Event mapping exception, and status-codes matrix so the current build surfaces the requested code consistently.

Recommendation:
Keep this additive fix. It satisfies the Published Jira request while preserving the published `not-done` code; if the work group later wants only one code for this state, that cleanup should be a separate terminology decision because removing or renaming `not-done` would be breaking.
