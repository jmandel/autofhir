FHIR-13860: Correct lastn code grouping wording

Issue request:
FHIR-13860 was a Published/Persuasive STU3 Observation change request asking to clarify the Observation `$lastn` operation based on connectathon implementation experience: how CodeableConcept group equivalence works, that unfiltered results include `entered-in-error`, that effective-time ties can return more than `max`, and that text-only CodeableConcepts group by text.

Initial application:
The issue appears to have been applied in 2017 by commits b6ad40bbc2f5218d7e9e1f848ed862a726753c49 and 29d523c8173d2ffd355d5606e88092c6917df0f5, which updated the then-authoritative Observation spreadsheet source with the requested `$lastn` description. That source was later migrated into the active `source/observation/operationdefinition-Observation-lastn.xml` OperationDefinition.

Additional context:
Observation is an active resource in `source/fhir.ini`, and `source/observation/list-Observation-operations.xml` references `OperationDefinition/Observation-lastn`, so the edited XML is in current build scope. Later FHIR-41448 clarified group ordering and tie wording while preserving the same equivalence model, and FHIR-16439 already corrected a separate text-only table typo on the combined branch. The linked 2017 Zulip thread confirms the intended grouping rule: Coding equality is by system/code, CodeableConcept grouping is by non-empty coding intersection/transitive closure, and text-only concepts use exact text.

AutoFHIR reconciliation:
This commit keeps the applied `$lastn` semantics and fixes two remaining source typos in the central grouping clarification: `coding.value` is corrected to `coding.code`, and the example group `[a.c]` is corrected to `[a,c]`.

Recommendation:
Keep this commit as-is. It is a narrow correction to the active OperationDefinition source that makes the already-applied FHIR-13860 clarification use the actual FHIR Coding element name and an unambiguous example group label.
