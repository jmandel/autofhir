FHIR-34485: Activate resource list tab hashes

Issue request:
FHIR-34485 was Published/Persuasive for R5 as a non-substantive correction asking that direct links such as resourcelist.html#tab-7 open the Resource Type Index and activate the target sub-tab, especially the Security Category tab.

Initial application:
The Jira-tagged August 2022 commits d78907197b3fbbbafead95cc5d551aded6e3435c and 33f2b54394c0ef1ebe1260789bd3fc1567275624 implemented hash-addressable tabs for generated resource pages using #tt-* anchors. The current resource list page itself still initialized its tabs from sessionStorage or tab 0 and did not let a resourcelist.html#tabs-7 URL override that state.

Additional context:
source/hierarchy.xml and publish.ini include resourcelist.html in the current build, and source/security.html currently links to resourcelist.html#tabs-7 for the Security Category tab. jQuery UI only auto-selects a location hash when the active option remains null; the resource list script always supplied an active option, so the current source could still ignore direct tab hashes. Zulip evidence confirms the original implementation announcement covered resource-page #tt-* tabs rather than this resourcelist.html tab family, and no Confluence reference was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:
Updated source/resourcelist.html so its tab initialization first maps window.location.hash to the matching Resource Type Index tab, with compatibility for the issue's #tab-* form by normalizing it to #tabs-*. The script now falls back to the stored tab index only when the URL does not name a resource-list tab.

Recommendation:
Keep this source fix. It is limited to the active Resource Type Index page and makes existing links such as source/security.html's Security Category link behave as the Published Jira requested without changing resource content or unrelated tab templates.
