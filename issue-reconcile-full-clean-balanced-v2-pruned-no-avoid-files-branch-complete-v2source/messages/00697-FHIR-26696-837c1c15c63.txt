FHIR-26696: Correct action relationship mappings

Issue request:
FHIR-26696 is Published with a Persuasive with Modification resolution applied for R5. It asked to clarify ActionRelationshipType by adding the before/concurrent/after hierarchy, adding an optional end relationship element bound to the same code system, updating the relationship element documentation so it applies to the start time of the action, and adding start-relationship-type and end-relationship-type ConceptMaps to v3 ActRelationshipType.

Initial application:
The issue was implemented in PR HL7/fhir#2635 through J#26696 commits. Commit e43568d added the ActionRelationshipType hierarchy, PlanDefinition.action.relatedAction.endRelationship, the PlanDefinition start-time wording, and both ConceptMaps, but the ConceptMaps introduced target codes SCWS and ECWE. Commit f02760a normalized PlanDefinition short-code ordering. Commit f21a979 added RequestOrchestration.action.relatedAction.endRelationship and matching short-code ordering but left RequestOrchestration.action.relatedAction.relationship with the older generic definition.

Additional context:
source/fhir.ini has active PlanDefinition and RequestOrchestration resource entries, so their StructureDefinitions and related terminology files are in the current build scope. The Jira comment points to v3 ActRelationshipType timing codes, and the current THO v3 ActRelationshipType source contains SCW, SCWE, ECW, and ECWS but does not define SCWS or ECWE. PlanDefinition and RequestOrchestration are the only current source StructureDefinitions with relatedAction.relationship/endRelationship, making the RequestOrchestration wording a directly parallel missed application. Confluence Workflow minutes from 2020-04-06 record the relationship-code clarity discussion and creation of FHIR-26696; an exact Zulip search for FHIR-26696 found no conflicting thread.

AutoFHIR reconciliation:
This commit changes start-relationship-type so concurrent-with-start maps to SCW, changes end-relationship-type so concurrent-with-end maps to ECW, and changes RequestOrchestration.action.relatedAction.relationship to say it is the relationship of the start of this action to the related action.

Recommendation:
Keep this commit as-is. It fixes two invalid v3 target codes and a missed parallel documentation update without reopening the issue design or editing generated diagram artifacts.
