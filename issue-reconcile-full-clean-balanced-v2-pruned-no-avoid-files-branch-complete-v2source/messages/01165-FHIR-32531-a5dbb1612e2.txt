FHIR-32531: Correct SearchParameter.chain wildcard syntax

Issue request:
FHIR-32531 was Published/Persuasive with Modification for FHIR-core SearchParameter after R4. It asked the specification to clarify how SearchParameter.chain values document deep chaining support, including avoiding full prefixed strings or leading dots and identifying the syntax for unlimited chaining.

Initial application:
The issue was initially applied by git commit fd644df3b2651732b68e2713b0599dd4197d0f6c, which replaced the old SearchParameter.chain comment with the requested bullet list. That commit carried the correct overall clarification but rendered the approved unlimited-chaining sentinel as a trailing dot, "practitioner.", instead of the Jira resolution's "practitioner.*". A later SearchParameter change, 3625f3cd1975c798b2051bf5216f946563265678, reformatted the file and preserved that incorrect syntax.

Additional context:
SearchParameter is an active resource in source/fhir.ini, owned by FHIR-I and approved in the current build metadata, so source/searchparameter/structuredefinition-SearchParameter.xml is in current build scope. The Zulip thread linked from the Jira issue records the ambiguity being discussed, including whether a listed chain means one hop or unlimited deeper chaining. The WGM minutes record the accepted resolution that "* means all search types" and that without the wildcard implementers must enumerate each supported chain. A broader Jira search found no later FHIR-core decision reversing this syntax; FHIR-26538 is an earlier no-change issue about defining a custom deep-chain SearchParameter and does not supersede FHIR-32531's declaration syntax.

AutoFHIR reconciliation:
This commit changes only the SearchParameter.chain comment's unlimited-chaining bullet from a trailing dot sentinel to the approved `.*` sentinel and updates the example from `practitioner.` to `practitioner.*`.

Recommendation:
Keep this commit as-is. It fixes a semantic documentation error in the active SearchParameter StructureDefinition and aligns the current source with the published Jira resolution and FHIR-I minutes without adding broader or redundant prose.
