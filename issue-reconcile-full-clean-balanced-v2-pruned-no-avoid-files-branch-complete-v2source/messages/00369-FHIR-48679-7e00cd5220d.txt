FHIR-48679: Remove short-form Signature MIME allowance

Issue request:
FHIR-48679 was an Applied/Persuasive FHIR-core correction for invalid MIME type bindings. It requested consistent handling of the short-form `xml`, `json`, and `ttl` codes and resolved to create a new Supplemented MIME Types value set for `CapabilityStatement.format` while not allowing those short-form codes everywhere MIME types are used.

Initial application:
The issue was applied in git commit 41d77c5f67ad438536eeb1701cfefffe3688d7d4, which added `source/terminologies/valueset-supplemented-mimetypes.xml`, added `source/terminologies/codesystem-simple-format-codes.xml`, registered them in `source/fhir.ini`, and changed `CapabilityStatement.format` from the plain MIME Types binding to the new supplemented value set. Commit bc59d0544649eb13759bcabaafe1b644cda880d8 later populated OIDs/identifiers for those new terminology artifacts.

Additional context:
FHIR-20617 is the earlier Published issue that made `CapabilityStatement.format` accept `xml`, `json`, and `ttl`; FHIR-48679 revisits that family because those short-form codes are not valid BCP-13 MIME codes. Current source correctly keeps `CapabilityStatement.format` on `ValueSet/supplemented-mimetypes`, whose active value set includes BCP-13 plus the active `simple-format-codes` CodeSystem. However, the active normative Signature datatype spreadsheet still carried the copied comment on `Signature.targetFormat` saying `xml`, `json`, and `ttl` are allowed even though that row remains bound to the plain `MimeType` binding. FHIR-I minutes and the post-implementation Zulip discussion both support keeping the short forms scoped rather than adding them globally to all MIME type uses.

AutoFHIR reconciliation:
Removed the stale `Signature.targetFormat` comment that allowed the short-form codes. `source/datatypes/signature.xml` is in build scope because `source/fhir.ini` marks `Signature` as an active normative datatype, and the hunk is necessary because the prior comment contradicted FHIR-48679's final instruction not to allow these codes at other MIME-typed elements.

Recommendation:
Keep this source fix. It preserves the applied `CapabilityStatement.format` supplemented binding and removes the remaining misleading Signature guidance; no broader MIME binding changes are recommended.
