FHIR-33947: Remove fragment authority-only publication rule

Issue request:
FHIR-33947 was an Applied, Persuasive with Modification Vocabulary change request for CodeSystem fragments. The approved resolution removed the rule that fragments can only be published by the code system authority or an authority-defined process, moved the remaining clarity warning out of the fragment rule list, updated the ContentMode fragment description, and added a rule that the intent, bounds, and consequences of fragmentation be clearly documented.

Initial application:
Commit 7f35afd61a applied most of the Jira resolution by updating the CodeSystem ContentMode fragment definition, splitting the former final fragment bullet, and adding the new intent/bounds/consequences rule. That commit did not remove the authority-only publication bullet from source/codesystem/codesystem-notes.xml, leaving a substantive contradiction with the approved resolution and the reopened Jira comment asking that both the summary page text and concept description be updated.

Additional context:
source/fhir.ini lists CodeSystem as an active resource, so source/codesystem/codesystem-notes.xml and source/codesystem/codesystem-codesystem-content-mode.xml are in current build scope. FHIR-48959 is a later related ValueSet fragment issue, but it remains Resolved - change required and concerns expansion behavior rather than this CodeSystem publication rule. FHIR-51110 is a separate Applied content-mode clarification for the example code and does not supersede the FHIR-33947 fragment rule change. Zulip and Confluence searches found discussion confirming the old authority-only sentence was controversial and that FHIR-33947 was the ticket for relaxing fragment restrictions; no conflicting final decision was found.

AutoFHIR reconciliation:
Removed the stale authority-only fragment publication bullet from source/codesystem/codesystem-notes.xml. The already-applied ContentMode fragment definition and the new intent/bounds/consequences fragment rule were left unchanged.

Recommendation:
Keep this commit as-is. It completes the approved FHIR-33947 source change in the active CodeSystem narrative without taking on the separate, not-yet-applied ValueSet fragment work from FHIR-48959.
