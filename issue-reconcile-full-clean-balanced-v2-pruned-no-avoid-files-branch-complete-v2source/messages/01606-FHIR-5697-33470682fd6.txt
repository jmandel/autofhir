FHIR-5697: Remove stale core meta-operation remnants

Issue request:
FHIR-5697 was a Published/Persuasive DSTU1 FHIR-core change request to replace the special `_meta` REST interactions with operations using Parameters/Meta payloads, with references from the meta section and HTTP summary table to the new operations.

Initial application:
The Jira comments cite svn revisions 4114 and 4391. In git history, commit c0957939fb45c745c858c8cafda2c43d2c19ae30, "#5697 - define $meta operations", added Resource Operations links and operation-list meta notes, while nearby DSTU1 work later split the meta-change operation into `$meta-add` and `$meta-delete`.

Additional context:
Current R6 core source no longer defines Resource `$meta`, `$meta-add`, or `$meta-delete`: source/resource/list-Resource-operations.xml lists only validate, convert, and graphql, and the R6 cleanup commit 270e0ceb7b029dad4ca0fc5ccf5296ff370888cd deleted the core meta OperationDefinitions while ballot-intro.html lists those Resource meta operations as moved artifacts. A later final issue, FHIR-17258, removed operations on historical resource versions, and the combined branch already has an audit commit for that decision. FHIR-56393 now flags one remaining meta-operation note as stale, but it is still Submitted and is treated here only as supporting evidence that the stale text is recognized.

AutoFHIR reconciliation:
This commit removes the current core statements that still implied Resource meta operations are defined by core or can modify historical versions: the HTTP history note no longer says past-version metadata can be modified, the HTTP summary note no longer says Resource Operations include direct access to meta, and the operations list no longer says special meta operations operate on previous versions.

Recommendation:
Keep this commit as-is. It reconciles the historical FHIR-5697 application with the later R6 removal of core meta OperationDefinitions and the final FHIR-17258 historical-operation decision. Future work on FHIR-56393, FHIR-53185, or the API Incubator should decide whether and how to reference external `$meta` operations once those definitions and links are stable.
