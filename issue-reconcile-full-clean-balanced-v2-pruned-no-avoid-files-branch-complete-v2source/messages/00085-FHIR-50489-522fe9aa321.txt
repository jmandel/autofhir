FHIR-50489: Allow optional stratifier criteria in $evaluate

Issue request:
FHIR-50489 was Applied with a Persuasive with Modification resolution for R6. It asked Measure $evaluate to accept additional multi-part stratifier parameters and to require MeasureReport.inputParameters when input stratifiers are supplied. The approved parameter definition included stratifier.component.criteria as 0..1.

Initial application:
PR HL7/fhir#3811 was applied in commit 7386aa83a9, adding the stratifier parameter to source/measure/operationdefinition-Measure-evaluate.xml and the MeasureReport.inputParameters statement to source/measurereport/structuredefinition-MeasureReport.xml. A follow-up nested multi-part cleanup in 4cb65bc7ea put component subparts under stratifier.component. Later FHIR-53139 and FHIR-53433 commits added and clarified the stratifier.component.criteria documentation in the operation, but left that operation parameter stricter than the Jira-approved structure and the corresponding Measure.group.stratifier.component.criteria element.

Additional context:
Measure and MeasureReport are active resources in source/fhir.ini, and source/measure/list-Measure-operations.xml references OperationDefinition/Measure-evaluate, so the edited XML is build-scope source. FHIR-50488 is the same Measure $evaluate enhancement family for supplementalData and was applied in nearby commits, but it is a separate supplemental-data request and is not decided by this commit. Later FHIR-50484, FHIR-53139, FHIR-53433, and FHIR-51028 changed the same operation or related stratifier wording/bindings, but none records a work-group decision to make the additional stratifier component criteria mandatory.

AutoFHIR reconciliation:
Changed only source/measure/operationdefinition-Measure-evaluate.xml so stratifier.component.criteria is 0..1, matching the applied FHIR-50489 resolution and the corresponding Measure element while preserving the existing criteria documentation and all later clarifications.

Recommendation:
Keep this commit as a narrow source fix. Future work should decide FHIR-50488 or broader DEQM composition proposals separately, because they affect supplementalData or future operation design rather than this approved stratifier cardinality.
