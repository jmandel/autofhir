FHIR-22151: Restore Consent grantee service caution

Issue request:
FHIR-22151 was a Published/Persuasive FHIR-core Consent change request from the STU3 issue pool. It asked whether Consent.performer should allow CareTeam or HealthcareService as parties to the agreement and resolved to add CareTeam and HealthcareService, with an element comment warning that some HealthcareService instances may not be appropriate grantees depending on service type and whether the service can be treated as an eligible independent or dependent entity.

Initial application:
The issue appears to have been applied by untagged git commit f42fe3d576, which added CareTeam and HealthcareService to the Consent.performer reference targets in source/consent/consent-spreadsheet.xml and added the requested HealthcareService/grantee suitability note to the element comment. The spreadsheet-to-StructureDefinition migration in 33b409a4b6 preserved both the targets and the note in source/consent/structuredefinition-Consent.xml.

Additional context:
FHIR-31906 later converted Consent.performer into Consent.grantor and Consent.grantee for R5, and source/fhir.ini maps the old Consent.performer path to Consent.grantee. That refactor carried the CareTeam and HealthcareService targets into the current elements but replaced the old performer comment with a new grantee/grantor usage note, dropping the FHIR-22151 HealthcareService suitability warning. FHIR-27779 has already restored the separate statement-preference/not-in-force sentence to the current grantee comment, and FHIR-31906 is already represented on the combined branch.

AutoFHIR reconciliation:
Updated the active Consent StructureDefinition source so Consent.grantee retains the current grantee/grantor usage note and the FHIR-27779 preference sentence while also restoring the FHIR-22151 warning for HealthcareService grantees. No target-profile change was needed because CareTeam and HealthcareService are already present in current build-scope source.

Recommendation:
Keep this source fix. It restores a previously applied CBCC warning that was lost during the performer-to-grantor/grantee refactor, without changing cardinality, allowed reference targets, or the later R5 grantor/grantee model.
