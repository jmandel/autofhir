FHIR-12321: Remove stray carriage returns from encounter location definitions

Issue request:
FHIR-12321 is a Published/Persuasive FHIR-core vocab technical correction. It reported stray "\r\r" separators in CodeSystem code definitions emitted in valuesets.json and asked that the sentence breaks be replaced with spaces for http://hl7.org/fhir/resource-types MedicationStatement and http://hl7.org/fhir/encounter-location-status active/completed.

Initial application:
The Jira comments say the issue was already fixed, but no Jira-keyed source commit was found. In the current source, MedicationStatement no longer has the reported carriage-return pair; its resource definition uses line-feed escapes instead. The encounter-location-status CodeSystem source, however, still contained the two reported double carriage-return escapes after the 2021 source rework/R4B import path.

Additional context:
The current checkout does not contain a checked-in valuesets.json, so the authoritative reconciliation target is the terminology source that feeds generated terminology artifacts. source/fhir.ini lists Encounter and MedicationStatement as active resources, and source/encounter/codesystem-encounter-location-status.xml is the current CodeSystem source for the referenced encounter-location-status terminology. FTS-safe Zulip and Confluence searches found no community/minutes evidence that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit replaces the two `&#xD;&#xD;` separators in the active and completed encounter-location-status code definitions with single spaces. It intentionally leaves MedicationStatement unchanged because the current source no longer contains the reported carriage-return pair there.

Recommendation:
Keep this source fix as-is. It restores the published technical correction for the remaining current-source regression without changing terminology meaning; follow-up is only needed if downstream generated terminology artifacts are regenerated separately.
