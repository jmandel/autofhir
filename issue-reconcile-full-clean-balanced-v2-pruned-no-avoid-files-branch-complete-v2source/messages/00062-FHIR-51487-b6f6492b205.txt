FHIR-51487: Correct Measure evaluate return docs

Issue request:
FHIR-51487 was Applied/Persuasive for R6 and asked CQI to replace the Measure $evaluate return parameter description with Bundle-per-subject wording, explicit 1..* MeasureReport contents, a link to Bundle-organization guidance, and a Parameters response note for the multi-cardinality return parameter. A Jira comment also requested applying the same clarification to the overall operation description.

Initial application:
The Jira-tagged implementation commit 9aafebcbaf1bf483be501112cc5fdca132848446 from PR #3932 updated source/measure/operationdefinition-Measure-evaluate.xml by adding the Bundle guidance link and Parameters response note to the return parameter. That initial application did not fully replace the requested return wording, left OperationDefinition.comment saying the operation returned a MeasureReport resource directly, and did not update the retired Measure-evaluate-measure OperationDefinition that is still listed by the active Measure operations list.

Additional context:
FHIR-37571 created the new Measure/$evaluate operation and marked Measure/$evaluate-measure retired, while FHIR-50486 confirms the old operation is intentionally deprecated rather than removed. source/fhir.ini keeps Measure in the current build and source/measure/list-Measure-operations.xml still references both OperationDefinitions, so both operation sources feed current generated artifacts. FHIR-50487 also depends on the Bundle-organization guidance added by FHIR-50487/FHIR-50484-family work, and the cited Zulip thread confirms the old direct-resource response note is wrong for a 0..* return parameter.

AutoFHIR reconciliation:
Updated source/measure/operationdefinition-Measure-evaluate.xml so the footer, OperationDefinition.comment, and return parameter documentation consistently describe Bundle-per-subject results, 1..* MeasureReport resources, subsequent evaluated resources, and Parameters wrapping for the multi-cardinality return. Applied the same return/overall-description clarification to source/measure/operationdefinition-Measure-evaluate-measure.xml because that retired operation remains in the active Measure operation list and otherwise retained the exact stale wording from the issue.

Recommendation:
Keep this commit. It completes the applied CQI clarification without changing operation parameters or behavior, and it avoids leaving contradictory conformance text on either the current $evaluate operation or the retained retired $evaluate-measure page.
