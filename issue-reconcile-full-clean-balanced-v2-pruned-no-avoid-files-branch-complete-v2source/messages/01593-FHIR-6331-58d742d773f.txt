FHIR-6331: Remove leading slashes from Bundle request examples

Issue request:
FHIR-6331 was a Published/Persuasive with Modification DSTU1 FHIR-core Feed clarification asking whether Bundle.entry.transaction.url and conditional fields include the server base. The accepted resolution says Bundle.entry.transaction.url is interpreted relative to the address where the transaction is submitted with no leading slash, Bundle.entry.transaction.ifNoneExist is only the query portion without a leading question mark, and examples should be made consistent.

Initial application:
The issue was applied in SVN revision 5811, now git commit 10e3baaa817af6c499e71a912a6b7d0c80db6547, which updated the old Bundle spreadsheet definition, changed ifNoneExist examples to query-only values, and adjusted transaction guidance. Later refactoring moved the element to Bundle.entry.request.url and preserved the query-only ifNoneExist definition.

Additional context:
Bundle is an active resource in source/fhir.ini, and source/bundle/list-Bundle-examples.xml includes bundle-request-simplesummary and bundle-request-medsallergies as Bundle examples. Current source/bundle/structuredefinition-Bundle.xml says Bundle.entry.request.url is relative to the root, and SubscriptionTopic comments still cite Bundle.entry.request.url as having no leading slash. Direct Jira/Zulip/Confluence searches found no later decision allowing leading slashes in these example values.

AutoFHIR reconciliation:
This commit removes the leading slash from every Bundle.entry.request.url value in the two in-build batch request examples. It intentionally leaves the authoritative Bundle definition and ifNoneExist text unchanged because those already express the accepted rule.

Recommendation:
Keep this source fix. It aligns checked-in examples with the final FHIR-6331 decision and the current Bundle.entry.request.url convention; no further core source changes were found for this issue.
