FHIR-36830: Clarify DeviceDefinition relation types

Issue request:
FHIR-36830 was Published with resolution Persuasive with Modification for R5. It asked to update the DeviceDefinition.link.relation value set to gateway, replaces, and previous, remove container/connected-style relationship codes, revise the code definitions for device definitions, and rename/define the linked-device element so it clearly referred to a DeviceDefinition.

Initial application:
The issue was partly applied in historical commits 39e7d269b9 and 5a10cc173a. Those commits removed obsolete relation codes, but the current DeviceDefinition relation CodeSystem still kept the old gateway/replaces/previous definitions, pointed its CodeSystem.valueSet at the Device value set instead of the DeviceDefinition value set, and left the DeviceDefinition link element prose saying only "device".

Additional context:
DeviceDefinition is an active current resource in source/fhir.ini, so the DeviceDefinition XML, CodeSystem, and ValueSet files are in current build scope. The paired Device cleanup from FHIR-36828 replaced the Device.link backbone with Device.gateway, so this reconciliation does not alter the now-unbound Device relation type files. Later DeviceDefinition work in FHIR-39389 and applied FHIR-41597 kept the element name as DeviceDefinition.link.relatedDevice[x] while changing it to canonical(DeviceDefinition) or CodeableConcept, so this commit preserves that later model rather than reviving the older FHIR-36830 rename to relatedDeviceDefinition.

AutoFHIR reconciliation:
Updated the active DeviceDefinition relation CodeSystem and ValueSet descriptions, fixed the CodeSystem.valueSet canonical to ValueSet/devicedefinition-relationtype, revised gateway/replaces/previous definitions to describe device definitions, and clarified DeviceDefinition.link, link.relation, and link.relatedDevice[x] prose to refer to linked device definitions while retaining the later relatedDevice[x] choice name.

Recommendation:
Keep this source fix. If FHIR-55255 or a future THO migration lands, revisit only the terminology ownership/location then; the current core source should continue to state the correct DeviceDefinition relationship semantics until that migration is applied.
