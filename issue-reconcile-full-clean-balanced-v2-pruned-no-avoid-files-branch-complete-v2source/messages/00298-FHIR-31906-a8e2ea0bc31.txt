FHIR-31906: Replace stale Consent performer references

Issue request:
FHIR-31906 was Published/Persuasive with Modification for R5 Consent. It asked how Consent should represent the party to whom consent is granted and resolved to convert Consent.performer into Consent.grantee and Consent.grantor, with a usage note that fully computable consents list those parties as provision actors while grantee/grantor are present for easier search.

Initial application:
The issue appears to have been applied by nearby untagged Consent commits in May 2021. Commit 632f4b8497 replaced Consent.performer with Consent.grantor and Consent.grantee in structuredefinition-Consent.xml, and commit 731c1d67fe changed the former consentor/performer search parameter to Consent.grantee. Later source already contains Consent.manager and Consent.controller from the related FHIR-27778 split of Consent.organization.

Additional context:
Current source/fhir.ini keeps Consent in the active build and maps the old R4 Consent.performer to Consent.grantee. The authoritative Consent StructureDefinition, diagram, and search-parameter bundle already use grantor/grantee/controller/manager, but two Consent source artifacts still carried obsolete performer/organization terminology: the signed consent example used a removed <performer> element and consent-notes.xml described accountability as "organization or performer" even though neither is a current Consent element in that role. Later FHIR-34302 evidence reinforces the grantor/grantee definitions.

AutoFHIR reconciliation:
This commit updates the signed Consent example to use <grantee> instead of the removed <performer> element and updates the active Consent notes accountability bullet to name the current grantee/controller concepts. It intentionally does not add a new grantor search parameter because the existing applied source and later normative search-parameter curation include Consent-grantee, manager, and controller but not Consent-grantor.

Recommendation:
Keep this source fix. It completes the performer-to-grantor/grantee cleanup in current build-scope Consent source without broadening search-parameter behavior beyond the applied and later-curated source.
