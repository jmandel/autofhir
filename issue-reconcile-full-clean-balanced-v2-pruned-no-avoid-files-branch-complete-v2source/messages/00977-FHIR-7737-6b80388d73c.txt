FHIR-7737: Clarify MedicationRequest titration dosage guidance

Issue request:
FHIR-7737 was a Published Pharmacy change request, resolved Persuasive, asking to add more information to the MedicationPrescription.dosageInstruction comment. The accepted wording added institutional IV titration, such as adjusting a medication dose to maintain a stated hemodynamic value or range, as another example of changing dose/rate instructions.

Initial application:
The issue was initially applied by git commit 6fa885f693, whose message is #7737 and whose patch added the requested titration sentence to the then-current medication order dosageInstruction spreadsheet comment. The exact historical wording no longer appears in current source because MedicationPrescription/MedicationOrder became MedicationRequest and later dosage refactors replaced repeated Dosage instructions with a single DosageDetails structure.

Additional context:
source/fhir.ini keeps MedicationRequest in the active resource list and records that MedicationPrescription became MedicationRequest. Current MedicationRequest.dosageInstruction is 0..1 DosageDetails and had no local comment carrying the FHIR-7737 clarification, while nearby MedicationRequest timing text and example descriptors still referred to multiple dosageInstruction lines. The already-published FHIR-8502 reconciliation on the combined branch aligned related rate-change guidance in the reusable Dosage datatype and MedicationDispense with the current R6 DosageDetails model, but it intentionally did not audit FHIR-7737. Current dosage narrative says DosageDetails steps/components represent complex dosage regimes and renderedInstruction carries the full dosage intent.

AutoFHIR reconciliation:
This commit reapplies the FHIR-7737 clarification to the active MedicationRequest.dosageInstruction element in R6 terms: dose/rate changes, including IV titration to maintain a specified hemodynamic value or range, are represented through DosageDetails and must have the full intent in renderedInstruction. It also updates the adjacent MedicationRequest.effectiveTiming definition and the MedicationRequest example list/header descriptions so they refer to multiple DosageDetails steps rather than impossible multiple dosageInstruction lines.

Recommendation:
Keep this source fix. It preserves the accepted FHIR-7737 clarification without restoring obsolete repeated-dosageInstruction wording or the original typo, and it keeps MedicationRequest aligned with the current DosageDetails model and the prior FHIR-8502 reconciliation.
