FHIR-17953: Add missing CoverageEligibilityRequest summary fields

Issue request:
FHIR-17953 is Published/Persuasive and asked for EligibilityRequest/CERq identifier, purpose, patient, created, provider, and insurer to be included in the summary view.

Initial application:
The issue was partially applied in November 2018. Commit f369c813fb40 named GF#17953 in a broad financial resource update, and commit 6e9080dd54 named GF #17953 while updating the CoverageEligibilityRequest spreadsheet. That historical state showed purpose, patient, created, and insurer as summary elements, but left identifier and provider without the summary marker.

Additional context:
The current build uses CoverageEligibilityRequest as the active successor for the old EligibilityRequest/CERq resource: source/fhir.ini lists coverageeligibilityrequest as an active resource and records the EligibilityRequest rename. A prior AutoFHIR commit for FHIR-19491 already completed related current cardinality work on provider and insurance but listed FHIR-17953 only as background, so this issue was still not represented on the combined branch. Jira, Zulip, and Confluence searches found no later decision to exclude identifier or provider from the summary view.

AutoFHIR reconciliation:
Updated source/coverageeligibilityrequest/structuredefinition-CoverageEligibilityRequest.xml to add isSummary=true to CoverageEligibilityRequest.identifier and CoverageEligibilityRequest.provider. The other requested summary elements were already marked isSummary=true in the active StructureDefinition.

Recommendation:
Keep this source fix. It completes the published summary-field decision in the active current resource without changing out-of-build legacy EligibilityRequest spreadsheet files.
