FHIR-28415: Correct Duration drt-1 expression

Issue request:
FHIR-28415 is a Published/Persuasive technical correction for FHIR-core datatypes. It reported that Duration invariant drt-1 said a code is required when a value is present, but the FHIRPath expression instead only constrained instances when code was present.

Initial application:
The issue was applied in git commit 0fa9bbb48c1eb0f222045bc1f95b20b217e47894, which changed source/datatypes/duration.xml to value.exists() implies ((system = %ucum) and code.exists()). That commit is present on R4B-related branches but is not an ancestor of the current reconciliation branch. The current active Duration spreadsheet still carried the older inverse expression, while the R4B history bundle already showed the corrected expression.

Additional context:
source/fhir.ini maps datatype spreadsheets into the active datatypes build through the [types] section and *=datatypes. FHIR-47129 later noted the same mismatch for R6 and explicitly said FHIR-28415 had been resolved in R4B but not carried forward; that issue is Resolved - change required and is cited as context rather than separately decided in this default Applied/Published run. FHIR-34465 confirms the corrected drt-1 expression affected examples, and the current PackagedProductDefinition example already includes value, unit, system, and code.

AutoFHIR reconciliation:
This commit updates source/datatypes/duration.xml so Duration drt-1 uses the applied expression value.exists() implies ((system = %ucum) and code.exists()), aligning the active source with the Jira resolution and R4B-applied expression.

Recommendation:
Keep this commit as-is. It is a focused source correction to the active Duration datatype spreadsheet; no separate FHIR-47129 decision was made because that related issue is outside the default Applied/Published decision scope.
