FHIR-50108: Clarify Bundle response ETag format

Issue request:
FHIR-50108 was Applied as Persuasive with Modification for R6 after the reporter found that Bundle.entry.response.etag wording and examples did not make clear whether the value should be the full HTTP ETag header value or only the version id. The accepted resolution says the value needs to match the full ETag in the header, e.g. W/"1", and to add an example to the Bundle.entry.response.etag element comments.

Initial application:
The prior Jira-tagged source commit e6ba174bce4567f0c9bb8b3b13adfd31a0878b00 changed only source/bundle/structuredefinition-Bundle.xml and added an example as W/'1'. That retained the old ambiguous wording about matching Resource.meta.versionId and did not correct the batch response examples identified by the Jira issue.

Additional context:
The linked Zulip discussion records Gino Canessa confirming that Bundle.entry.response.etag should match the ETag header value, not just the opaque/version portion, and that examples should be corrected. FHIR-I minutes on 2025-03-31 record the motion to clarify matching eTag in Bundle and put an example in the comments. Bundle is an active source/fhir.ini resource, and source/bundle/list-Bundle-examples.xml plus source/http.html link the edited response examples into the current build.

AutoFHIR reconciliation:
This commit updates Bundle.entry.response.etag's source comment to say the element carries the full ETag header value, including weak marker and quoted version id, while still explaining the relationship to Resource.meta.versionId when a resource is included. It also changes the active meds/allergies and simple summary batch response examples from W/1 to W/&quot;1&quot; so the examples no longer contradict the clarification.

Recommendation:
Keep this source fix. It completes the applied clarification without broadening the issue beyond Bundle response ETags; no additional related Jira decision was found that needs a separate reconciliation commit.
