FHIR-17661: Correct Observation encounter privacy guidance

Issue request:
FHIR-17661 was a Published/Persuasive STU3 OO change request to change Observation.context back to Observation.encounter, narrow the element from Reference(Encounter|EpisodeOfCare) to Reference(Encounter), update the Observation search parameter, and provide an event/workflow episode-of-care extension for 0..* EpisodeOfCare linkage.

Initial application:
The change was pre-applied in commit 096d9cd98c16d6b06712455ca04ece365fb5bddc, which renamed historical Observation source/example references from context to encounter. Current Observation source keeps Observation.encounter as 0..1 Reference(Encounter), and the Observation encounter search parameter uses code encounter with expression Observation.encounter.

Additional context:
The original Zulip discussion confirms the intended model: a single Encounter reference belongs on Observation, while one or more EpisodeOfCare references are handled by an extension. The former event-episodeOfCare extension now appears in the FHIR Extension Pack as workflow-episodeOfCare, with Observation in both the extension context list and workflow-EpisodeOfCare search parameter bases. Later FHIR-33166, already represented on the combined branch, reaffirmed this approach by adding explicit workflow-episodeOfCare guidance to Observation.encounter rather than reverting Observation back to context. FHIR-17662, also already represented on the combined branch, is the same change family for other OO resources.

AutoFHIR reconciliation:
This commit fixes the only current-source miss found for the seed: the active Security and Privacy module still described Observation.context as a reference to Encounter or EpisodeOfCare. The narrative now points to Observation.encounter, the workflow-episodeOfCare extension, and Observation.performer, matching the authoritative Observation definition and extension-pack ownership. The Security and Privacy module is in build scope through source/hierarchy.xml and multiple current module links.

Recommendation:
Keep this source fix. No further core source change is needed for Observation.encounter, the encounter search parameter, or the episode-of-care extension unless a future work-group decision reverses the current Observation/FHIR-33166 model.
