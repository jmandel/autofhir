FHIR-15136: Clarify conditional Dosage definitions

Issue request:
FHIR-15136 was Published with a Persuasive with Modification resolution for R5. It asked FHIR-core datatypes to support conditional doses, including examples such as insulin sliding scale, doses based on INR, and doses based on blood pressure. The final resolution was to add an extension and examples.

Initial application:
No current git commit explicitly names FHIR-15136. Git history shows cb366d831c added source/datatypes/dosage-extensions-spreadsheet.xml in January 2019 with the message "added an extension to Dosage datatype to handle conditional dosing", matching the issue's extension-based resolution. Pharmacy Confluence minutes from late 2019 also tracked FHIR-15136 as "Conditional Dosages" and called for CDS/oncology/NCPDP examples. Later extension-specific work, including FHIR-26899, was applied separately, and that legacy extension source is no longer active in current core fhir.ini.

Additional context:
Current source/fhir.ini actively lists Dosage, DosageDetails, DosageSafety, and DosageCondition as datatypes and maps them to the dosage page under the Pharmacy work group. The later R6 dosage rework around FHIR-51540 introduced an active DosageCondition datatype and dosage examples, but the new DosageCondition source retained copied RelativeTime wording, wrong/duplicated value set metadata, a stale ConditionDetails path, and an example using the invalid code fragment "if needed" instead of "if-needed". A 2026 Zulip thread about R6 DosageCondition vs. the dosage-conditions extension independently called out the same documentation and binding-label problems while treating broader R6 semantics as still needing use-case-driven review.

AutoFHIR reconciliation:
This commit fixes the active current-core conditional dosage artifacts. It updates Dosage.condition and DosageCondition definitions so they describe dosage applicability rather than RelativeTime anchors, corrects the DosageCondition code binding definition and value[x] wording, gives dosage-condition-code/details value sets distinct and accurate metadata, fixes the CodeSystem property path, and aligns the conditional dosage example and note with the actual if-needed code. These files are in build scope through the active datatype and dosage page entries in source/fhir.ini.

Recommendation:
Keep this source fix. It resolves obvious current-spec defects that would mislead implementers using the active DosageCondition datatype. Do not treat this as deciding the broader FHIR-51540 R6 dosage redesign or the already-audited FHIR-26899 Extension Pack follow-up; those remain separate work if Pharmacy wants additional semantic changes such as step-level conditions or legacy extension migration.
