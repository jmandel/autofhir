FHIR-15582: Remove stale Group exclude modifier wording

Issue request:
FHIR-15582 was a Published/Persuasive FHIR-I change request from the STU3 cycle asking for an IsModifierReason on Group.characteristic.exclude after the Patient-related modifier-reason work was split out.

Initial application:
The Jira application comment records svn 14467 as adjusting Group.characteristic.exclude so it was not a modifier because the definitions were unclear. The corresponding git-svn commit efaa2e373a removed the modifier marker from the old Group spreadsheet and adjusted the characteristic wording. The current StructureDefinition source preserved the non-modifier state, but a later source migration/cleanup left a stale comment saying the element was labeled as Is Modifier.

Additional context:
Group is an active resource in source/fhir.ini, and source/group/structuredefinition-Group.xml is the current built StructureDefinition source. The current Group narrative explains exclude as a required include/exclude flag without saying it is a modifier, while neighboring true modifier elements such as Group.characteristic.offset have explicit isModifierReason entries. FHIR-16613 and FHIR-16614 are the Patient.deceased and Patient.link split-out issues referenced by the seed comments and are already represented on the combined branch. Zulip and Confluence searches found no directly relevant contrary work-group discussion.

AutoFHIR reconciliation:
This commit keeps Group.characteristic.exclude as a non-modifier and removes only the stale "This is labeled as Is Modifier" wording from its comment, preserving the warning that excluded members must not be interpreted as included.

Recommendation:
Keep this source fix as-is. It matches the published application decision, avoids adding an unnecessary IsModifierReason to a non-modifier element, and removes a misleading contradiction from the current built source.
