FHIR-26674: Correct ServiceRequest asNeeded examples

Issue request:
FHIR-26674 is Applied/Persuasive with Modification. It asked OO to clarify ServiceRequest.asNeeded versus ServiceRequest.reason by replacing the ServiceRequest.asNeeded[x] choice with separate ServiceRequest.asNeeded (0..1 boolean) and ServiceRequest.asNeededFor (0..*) elements, adding the asn-1 invariant, updating element definitions, and adding examples showing asNeeded/asNeededFor with reason.

Initial application:
The issue was initially applied through HL7/fhir#3230, including commit 0fe699b16df0d6ec738db9253849043f8140cef9 and merge 75b721ec04. That application updated structuredefinition-ServiceRequest.xml, added the asn-1 invariant, renamed the elements, updated ServiceRequest.reason wording, and added glucose examples. The current active ServiceRequest example list includes those new examples and still includes the older physiotherapy example.

Additional context:
source/fhir.ini actively lists servicerequest=ServiceRequest and includes ServiceRequest.asNeededFor in the element status table, so source/servicerequest examples are current build inputs. Zulip and OO minutes show the approved distinction: reason explains why the order exists, while asNeeded/asNeededFor describes the trigger or criteria for performing it. Related FHIR-40765 was Resolved - No Change because FHIR-26674 had already addressed the ServiceRequest distinction. The checked-in ServiceRequest SVG still has generated-looking stale asNeeded[x] text; this reconciliation intentionally fixes authoritative XML examples and leaves diagram regeneration to the normal publisher/diagram process.

AutoFHIR reconciliation:
This commit fixes two active ServiceRequest examples that were semantically inconsistent with the applied StructureDefinition. The glucose example now represents ServiceRequest.asNeededFor as a CodeableConcept directly, rather than using a CodeableReference concept wrapper. The physiotherapy example now uses ServiceRequest.asNeeded plus ServiceRequest.asNeededFor instead of the removed asNeededCodeableConcept choice element.

Recommendation:
Keep this commit as-is. It completes the applied FHIR-26674 source update for active examples without broadening into the cross-resource alignment question from FHIR-40765. If checked-in SVG diagrams are treated as authoritative build inputs, regenerate the ServiceRequest diagram from the corrected StructureDefinition rather than hand-editing it here.
