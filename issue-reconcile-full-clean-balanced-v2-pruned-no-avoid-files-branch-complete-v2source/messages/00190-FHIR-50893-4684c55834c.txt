FHIR-50893: Complete additional binding purpose definitions

Issue request:
FHIR-50893 was Applied/Persuasive with Modification for R6. It asked FHIR-I to add the current-extensible additional binding purpose, update the current binding purpose wording, add a best-practice binding purpose, and add an abstract open grouper for non-conformance binding purposes after TI discussion.

Initial application:
The issue was partially applied by git commit 8684e35f85, which added current-extensible, best-practice, and open to source/datatypes/codesystem-additional-binding-purpose.xml and made preferred/ui/starter/component children of open. A later commit, fe420c6da2, updated ElementDefinition.binding.additional.purpose's fixed code list to include current-extensible and best-practice. The code system still retained the old current wording, gave current-extensible a weaker required-like definition, left open with a generic definition, and did not make candidate a specialization of open.

Additional context:
The active source/fhir.ini mapping publishes datatypes and ElementDefinition from source/datatypes, and ElementDefinition binds AdditionalBindingPurpose to valueset-additional-binding-purpose, which includes the additional-binding-purpose code system. May 2025 VOC and FHIR-I minutes confirm the TI discussion that led to a hierarchy of purpose codes and FHIR-I's vote on FHIR-50893. FHIR-56020 later submitted a proposal to remove several additional binding values, but it is unresolved and does not supersede the Applied FHIR-50893 decision.

AutoFHIR reconciliation:
This commit completes the source application by replacing the current and current-extensible definitions with the approved semantics, replacing the abstract open definition with the approved grouper wording, and moving candidate under open with the other non-formal-conformance purpose codes. No generated output was edited.
