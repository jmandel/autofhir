FHIR-40422: Complete group-level Measure subject support

Issue request:
FHIR-40422 was Applied/Persuasive for R5. It asked to allow a measure subject to be specified per group by relaxing Measure.library to 0..*, adding Measure.group.subject, Measure.group.library, Measure.group.rateAggregation, adding matching MeasureReport.group.subject, constraining library/subject/rateAggregation to appear either at the root or on all groups exclusively, adding overview guidance, updating $evaluate-measure, $collect-data, and $care-gaps to accept multiple subjects with individual-vs-population mode rules, and ensuring the composite-measure reuse context stayed aligned.

Initial application:
The explicit application commit c35d5cc2cf2596d936c47abfbe37c538a8abaa85 added Measure.group.subject, Measure.group.library, Measure.group.rateAggregation, and MeasureReport.group.subject, and the current Measure.library cardinality is already 0..*. That commit did not add the requested exclusivity invariants, did not update the operation subject cardinalities, and left quality-reporting guidance saying Measures should reference only one Library.

Additional context:
Measure and MeasureReport are active resources in source/fhir.ini, and the Measure operation list actively includes $evaluate, the retired/deprecated $evaluate-measure, $collect-data, and $care-gaps. FHIR-37571 later introduced $evaluate as the current replacement for $evaluate-measure, so the same subject-multiplicity rule needs to be reflected there as well as on the deprecated operation. FHIR-49945 later listed FHIR-40422 as still needing application during Measure review, supporting that the structural additions alone were incomplete. No Zulip or Confluence evidence was found that narrows or reverses the Jira decision.

AutoFHIR reconciliation:
This commit completes the missing source application. It adds Measure constraints requiring library, subject, and rateAggregation to be specified either at the measure level or on every group, but not both; updates Measure overview and quality-reporting guidance so multiple/group-level libraries and group-level declarations are described consistently; and changes the subject/subjectGroup input cardinalities and documentation for $evaluate, $evaluate-measure, $collect-data, and $care-gaps to support multiple subject inputs with the Jira-specified individual/population mode rules.

Recommendation:
Keep this commit as-is. It fixes the remaining conformance and guidance gaps in active core Measure source while preserving later R6 changes, including the $evaluate replacement operation. FHIR-40256's broader composite-measure example remains background and should be handled separately if more detailed example content is desired.
