FHIR-53824: Align DocumentReference related target wording

Issue request:
FHIR-53824 is an Applied/Persuasive with Modification R6 DocumentReference issue. It asked to distinguish DocumentReference.relatesTo lifecycle links from DocumentReference.related non-lifecycle associations, turn related into a backbone with code and target, bind code to the requested relatedArtifactType subset, and update search parameters for the changed backbone.

Initial application:
The issue was applied through PR history including 3800384a0c, which converted related from Reference(Any) to a BackboneElement with code and target and added implementation-note guidance; 27bd95ec53, which cleaned the related comment, removed the erroneous relatesTo modifier comment, and adjusted the binding URL; and 092a94f821, which added the document-related-artifact-type value set and updated the binding name to AssociatedReferenceType. These edits are in the active DocumentReference resource folder; source/fhir.ini lists documentreference as an active resource and OO work-group artifact, so the edited StructureDefinition and value set feed the current core build.

Additional context:
FHIR-53550 is the same change family and records that the FHIR-53824 disposition fulfills its request for a coded related backbone. The linked Zulip thread and OO minutes confirm the concern was missing relationship semantics for a flexible Reference(Any), not a document-only relationship. Current source mostly matched that decision, but the new related.code binding description and related.target definition still used document-to-document wording, which conflicted with the Jira target wording and the Reference(Any) design. The newly added value set also retained trailing spaces in its machine name/title from the application commit.

AutoFHIR reconciliation:
This commit corrected the authoritative StructureDefinition text so DocumentReference.related.code describes the relationship between the document reference and the related resource, and DocumentReference.related.target is defined as the reference to the related resource. It also removed the trailing spaces from the new AssociatedReferenceType value set metadata. The existing related search parameter already points at DocumentReference.related.target, so no search-parameter source change was needed.

Recommendation:
Keep this commit as-is. It is a narrow source correction that aligns the current build with the Applied disposition without changing broader DocumentReference behavior or generated diagram artifacts.
