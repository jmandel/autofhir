FHIR-3536: Replace stale DeviceRequest Schedule datatype wording

Issue request:
FHIR-3536 was Published with a Persuasive with Modification resolution to rename the old Schedule data type to Timing so PA could use Schedule as the resource name, with related element renames handled for DSTU1.

Initial application:
Jira records the change as applied on 2014-09-28 in SVN revision 2920. The current source already has Timing as an active datatype, Schedule as an active resource, and a history entry that cites FHIR-3536/FHIR-3236 for the Schedule-to-Timing rename. No current combined-branch audit commit for FHIR-3536 existed before this reconciliation.

Additional context:
FHIR-3236 is the same datatype rename family and confirms Timing as the approved replacement name. FHIR-3848, already audited on the combined branch, covers the dependent Availability-to-Schedule resource rename. FHIR-17428, also already audited, covered the same obsolete Schedule-datatype wording in Dosage. A bounded sweep found one remaining active-source occurrence in DeviceRequest plus its mapping exception and checked-in SVG tooltip; broader Schedule references were current resource references, historical changelog text, or unrelated schedule terminology.

AutoFHIR reconciliation:
Updated DeviceRequest.occurrence[x] to say the Timing data type allows many expressions, and aligned the matching Request mapping exception and checked-in DeviceRequest SVG tooltip. DeviceRequest is active in source/fhir.ini, so the StructureDefinition and mapping exception are current build inputs; the SVG was edited only to keep the derived diagram text consistent with the authoritative source change.

Recommendation:
Keep this source fix. No further core change is needed for FHIR-3536 unless a future full build regenerates DeviceRequest diagrams differently, in which case the generated SVG should continue to reflect the Timing wording.
