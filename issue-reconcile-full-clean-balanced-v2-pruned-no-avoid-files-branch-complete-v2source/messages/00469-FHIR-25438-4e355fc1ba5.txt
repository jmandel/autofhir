FHIR-25438: Remove clinical-only Composition wording

Issue request:
FHIR-25438 was Applied/Persuasive with Modification for R6 and asked to clarify the scope of Composition because descriptions implied FHIR documents must carry clinical attestation. The accepted resolution replaced clinical attestation language with author traceability and changed workflow/clinical status wording to workflow status.

Initial application:
Commit e34a8ff638 applied the issue to the base Composition StructureDefinition description/definition and one binding description. It did not update all active parallel descriptions, the Composition.status definition, the status CodeSystem/ValueSet descriptions, the mapping exception source, or the active catalog profile.

Additional context:
The SDWG 2021-01-26 minutes record a 9-0-0 motion accepting the FHIR-25438 disposition. FHIR-13426 is the earlier same-artifact issue that generalized Composition from document to package wording; this reconciliation has already restored that package/context wording before this follow-up clinical-attestation cleanup.

AutoFHIR reconciliation:
This commit removes the remaining clinical-only attestation/status wording from active Composition source inputs: the narrative intro, base StructureDefinition short and status definition, catalog profile root descriptions, Composition status CodeSystem/ValueSet descriptions, and the Event mapping exception text. The generated-looking composition.svg still contains stale wording, but the authoritative source inputs now carry the corrected text.

Recommendation:
Keep this source change. If generated diagrams are refreshed as part of the normal publication process, the stale SVG title should be regenerated from the updated authoritative StructureDefinition rather than hand-maintained here.
