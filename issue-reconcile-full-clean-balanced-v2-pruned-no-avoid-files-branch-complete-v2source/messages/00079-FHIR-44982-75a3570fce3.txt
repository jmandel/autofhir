FHIR-44982: Align immunization dose metadata with CodeableConcept

Issue request:
FHIR-44982 was Applied with a Persuasive with Modification resolution to change doseNumber and seriesDoses in Immunization, ImmunizationEvaluation, and ImmunizationRecommendation from string to CodeableConcept, without creating example value sets, and to update the comments to say coded concepts or free text may be used.

Initial application:
The Jira-tagged source commit 184c07f820c755a95cc4bc0c6b0f9483cc36b707 changed the three then-current StructureDefinition files and updated the Immunization comments and binding metadata. Current Immunization structure source already had CodeableConcept, but the protocol example still used primitive XML values and the active FHIR model-definition Library attachment still exposed doseNumber and seriesDoses as positiveInt/string choices.

Additional context:
Immunization is an active core resource in source/fhir.ini. ImmunizationEvaluation and ImmunizationRecommendation were later removed from the core resource list and now appear as external/additional resources, so this reconciliation did not restore deleted core resource source. The Library resource remains active and its FHIR model-definition example still contains classes for those immunization artifacts, so its stale type metadata needed to be kept consistent with the applied FHIR-44982 data type decision. Zulip and PHWG/FHIR-I minutes support the CodeableConcept direction and show no later reversal of the doseNumber/seriesDoses type change.

AutoFHIR reconciliation:
This commit fixes the remaining in-scope source: the Immunization protocol example now represents doseNumber and seriesDoses as CodeableConcept text, the Immunization committee-note metadata records the later FHIR-44982 CodeableConcept decision instead of only the older string restriction, and the FHIR model-definition content plus its embedded Library attachment now expose doseNumber and seriesDoses as FHIR.CodeableConcept for Immunization, ImmunizationEvaluation, and ImmunizationRecommendation entries.

Recommendation:
Keep this commit as-is. The current core resource definition already carries the intended type and comments; this commit removes stale parallel source that would otherwise mislead example validation and CQL model-definition users. Any broader cleanup of deleted ImmunizationEvaluation/ImmunizationRecommendation model-info entries belongs to the later resource-removal work rather than this issue.
