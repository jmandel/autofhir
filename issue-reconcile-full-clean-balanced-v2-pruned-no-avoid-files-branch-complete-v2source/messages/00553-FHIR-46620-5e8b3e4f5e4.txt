FHIR-46620: Clarify Resource extension context expansion

Issue request:
FHIR-46620 was Applied/Persuasive for R6 and asked the StructureDefinition extension context documentation to clarify that a context expression of Resource means resources where extensions are allowed, not every Resource specialization such as Bundle. The approved resolution specifically called out both defining-extensions.html#context and the ExtensionContextType ValueSet expansion as places where this clarification should appear, while preserving Resource as an allowed context for future-compatible use.

Initial application:
The upstream application commit a7c5cdf36fbcffa521c8011b4242a3688117a22a renamed the local section to Extension Context, added the Resource caveat to source/defining-extensions.html, and added a cross-reference to that section from source/structuredefinition/codesystem-extension-context-type.xml. That left the ValueSet expansion's terminology definition dependent on the reader following the cross-reference for the specific Resource caveat.

Additional context:
Earlier applied clarifications FHIR-41633 and FHIR-43364 explain that element contexts include assigned types and resource roots where extensions are actually allowed. The linked Zulip thread and FHIR-I WGM minutes support the same interpretation: Resource is not forbidden as an extension context, but use on a concrete target is constrained by whether that target can carry extensions.

AutoFHIR reconciliation:
This commit updates the ExtensionContextType CodeSystem element definition, which feeds the valueset-extension-context-type.html expansion, so the expansion directly states that Resource specialization logic is limited to matching resources where extensions are allowed, such as DomainResource and descendants, and excludes resources that do not allow root extensions.

Recommendation:
Keep this source fix. It completes the approved non-substantive clarification without changing the extension context model, adding validator behavior, or broadening the narrative beyond the applied work-group decision.
