FHIR-35842: Align Subscription admission filter parameter

Issue request:
FHIR-35842 was Published/Persuasive for R5 and asked to rename Subscription.filterBy.searchParamName to filterParameter so Subscription instances use the same filter label element name as the definitional SubscriptionTopic canFilterBy element.

Initial application:
The change was initially applied in 365b52222b9aeb872817b317cd6e620955291d56, which renamed the authoritative Subscription StructureDefinition element and the main Subscription example while also applying related FHIR-32752 SubscriptionTopic filterParameter work. Jira was then updated with an "Already applied" comment. Current authoritative definitions already use Subscription.filterBy.filterParameter and SubscriptionTopic.trigger.canFilterBy.filterParameter, but the tracked Subscription admission JSON example still contained the obsolete searchParamName property.

Additional context:
source/fhir.ini lists Subscription and SubscriptionTopic as active resources, and source/subscription/list-Subscription-examples.xml includes the Subscription/admission example. The XML admission example already uses filterParameter. Later FHIR-41197 work, already represented on the combined branch, touched the same JSON example for the resourceType-to-resource rename but did not address the old filter field. FHIR-I minutes corroborate the 13-0-1 vote for FHIR-35842, and no conflicting Zulip or Confluence discussion was found.

AutoFHIR reconciliation:
This commit changes source/subscription/subscription-admission.json from searchParamName to filterParameter, aligning the remaining stale example source with the current StructureDefinition and SubscriptionTopic terminology. It intentionally leaves unrelated example content unchanged.

Recommendation:
Keep this commit as-is. It completes the published FHIR-35842 rename across the remaining current source occurrence; any broader modernization of the admission JSON example should be handled under a separate issue.
