FHIR-20672: Correct SUBSETTED tag wording

Issue request:
FHIR-20672 was a Published/Persuasive FHIR-I correction for the REST read interaction. It asked that the _summary paragraph stop referring to SUBSETTED as a "Simple Tag" because the linked Resource page defines Tags, not a separate "Simple Tag" concept.

Initial application:
The historical FHIR-20672 application commit cb8df9fa71848ce2c859378ab59f36b97cd08fd6 only removed an extra Resource page anchor and did not change the REST read paragraph. The current source therefore still had the disputed "Simple Tag" wording and linked to resource.html#simple-tags.

Additional context:
FHIR-12524 originally moved SUBSETTED from a security label recommendation to Resource.meta.tag, so the semantic requirement remains that SUBSETTED is carried in meta.tag. The current Resource notes already expose resource.html#tags as the Tags, Profiles, and Security Labels section and the specific subsection is titled "Tags". A later Zulip implementers thread independently confirmed that "Simple Tag" was confusing and not a defined term.

AutoFHIR reconciliation:
Changed source/http.html so the _summary read guidance says the SUBSETTED code is used as a tag and links to resource.html#tags. This is the active REST (HTTP) source page referenced by source/navigation.xml, and the hunk is limited to removing the undefined label while preserving the FHIR-12524 meta.tag semantics.

Recommendation:
Keep this source fix as-is. It completes the Published Jira request without altering conformance expectations; no separate FHIR-12524 reconciliation is needed because that earlier decision is only background for why SUBSETTED remains a Resource.meta.tag value.
