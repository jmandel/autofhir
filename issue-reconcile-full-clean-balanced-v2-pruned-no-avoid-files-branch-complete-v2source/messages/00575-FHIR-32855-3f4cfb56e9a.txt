FHIR-32855: Remove stale ConceptMap2 translation

Issue request:
FHIR-32855 was a Published/Persuasive FHIR-core ConceptMap change request from the Vocabulary WG for R5. It requested that the temporary ConceptMap2 resource replace ConceptMap and then be discarded from the specification, including the resource list; Jira records that ConceptMap2 had replaced ConceptMap in the CI build and was later updated to Applied.

Initial application:
No explicitly Jira-tagged source commit for FHIR-32855 was found. The effective source application was commit 8623473ddf, which moved ConceptMap2 source files and definitions into the active ConceptMap resource and removed the active conceptmap2 resource entry from source/fhir.ini. Earlier commits created ConceptMap2 and its interim redirect/warning. Git history also showed the ConceptMap2 translation entry was added in 9e9b97453f and was not touched by the replacement commit, leaving one stale published implementation-file reference after the main resource transition.

Additional context:
The active resource list now contains conceptmap=ConceptMap and no conceptmap2 entry. The source/conceptmap folder carries the current ConceptMap resource, while source/conceptmap2 is absent. However, publish.ini publishes implementations/translations.xml as translations.xml and source/downloads.html links that file as a public translation file for common FHIR names and messages, so a ConceptMap2 entry there remains part of the current published source surface rather than merely historical residue. Vocab minutes and Zulip discussion confirm the work group understood by July/August 2022 that ConceptMap2 no longer existed as a separate resource after this transition.

AutoFHIR reconciliation:
This commit removes the orphaned ConceptMap2 item from implementations/translations.xml. No other ConceptMap source change is needed because the active ConceptMap StructureDefinition and resource list already reflect the ConceptMap2-to-ConceptMap replacement.

Recommendation:
Keep this source fix as-is. It removes the last discovered current-source ConceptMap2 reference from a published implementation file and does not reopen the already-applied structural ConceptMap redesign. Related precursor or cleanup tickets should remain separate audits unless they are independently reconciled.
