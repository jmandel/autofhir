FHIR-7289: Fix document stylesheet security note link

Issue request:
FHIR-7289 was a Published/Persuasive FHIR-core documents issue from the 2015May ballot asking that security risks identified in CDA stylesheet use be verified and addressed where the FHIR document stylesheet guidance told applications to use document-specified stylesheets.

Initial application:
The issue was initially applied in svn revision 6211, represented in git by 816144fbce3040b9ed59cb9ec01f23298275bd8b, which added a stylesheet security paragraph to source/security.html and added a "security note" link from source/documents.html. That application covered the requested CDA/XSLT-versus-CSS security substance, but the documents-page link used security.html#stylesheet while the security-page anchor created by the same commit was named stylesheets.

Additional context:
The current build-scoped source still includes source/documents.html and source/security.html in the main specification hierarchy/navigation, and the current security note warns that document stylesheets are CSS rather than executable CDA XSLT while still requiring safety checks for external CSS links and identifying/session information leaks. Targeted Zulip and Confluence searches for FHIR-7289 and the linked C-CDA security article found no directly relevant community evidence that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit changes the document presentation guidance link from security.html#stylesheet to security.html#stylesheets so readers following the FHIR-7289-applied security note reach the existing stylesheet security guidance.

Recommendation:
Keep this source fix. It preserves the already-applied substantive guidance and corrects the broken cross-reference that could otherwise prevent implementers from seeing the security note required by FHIR-7289.
