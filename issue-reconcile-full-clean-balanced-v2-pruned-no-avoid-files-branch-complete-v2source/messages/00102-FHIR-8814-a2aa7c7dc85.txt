FHIR-8814: Clarify XML comment handling

Issue request:
FHIR-8814 was Published/Persuasive for DSTU2. It asked to remove the JSON comments mechanism and to add XML guidance that systems handling resources MAY ignore or reject instances containing comments, and that other systems SHALL NOT expect comments to be preserved or to affect behavior.

Initial application:
The JSON half of the request appears to have been applied through the same change family as FHIR-10656: commit 75b64c909d removed the `fhir_comments` property text from source/json.html, and the current JSON format page now says comments SHALL NOT be in JSON instances. The requested explicit XML handling rule was not found in git history; the current XML page only said XML comments, processing instructions, and formatting are not part of resource contents.

Additional context:
FHIR-10656 records the later Published/Persuasive JSON-specific removal and svn revision 10171, matching commit 75b64c909d. FHIR-8666 was resolved No Change after the work group concluded comments were no longer supported in FHIR JSON. Zulip community discussion around the FMM5 JSON change found no blocking objection and later clarified that `fhir_comments` was withdrawn while ordinary XML comments can still appear in XML. publish.ini lists both json.html and xml.html as active pages, so the format-page source is in current build scope.

AutoFHIR reconciliation:
Updated source/xml.html to preserve the existing rule that XML comments are not resource contents and add the missing handling rule: receivers may ignore or reject instances with XML comments, and senders cannot expect comments to be preserved or alter behavior. No JSON source change was needed because source/json.html already forbids JSON comments.

Recommendation:
Keep this source change as-is. It completes the XML half of the Published decision without reviving `fhir_comments` or changing the already-correct JSON guidance.
