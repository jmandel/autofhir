FHIR-22823: Clarify Specimen container nesting

Issue request:
FHIR-22823 was a Published/Persuasive with Modification OO change request raised against STU3 and applied for R5. It asked for arbitrary nesting of specimen containers, removal of the old "Direct" container wording and the statement that recursive containers were not addressed, and the final resolution kept Specimen.container while adding a Device reference; if a container is in a holder, the referenced Device points to its parent Device.

Initial application:
The original PR #1889 history includes Jira-linked commit 29192683e49ddd240fe9cf6620eaf7c80f2104e4 and structural commit 4d596144595f5c42835f097054592c5fffb8babd, later merged as 18485e915a. That application removed Specimen.container.identifier, Specimen.container.description, and Specimen.container.type and added Specimen.container.device, but it left active Specimen definition and introduction text saying the container was "Direct" and that recursive containers were not addressed.

Additional context:
Specimen and Device are active current-build resources in source/fhir.ini, so source/specimen/structuredefinition-Specimen.xml, source/specimen/specimen-introduction.xml, and Device.parent/Device.location are current core source. OO minutes and Zulip discussion show the WG moved away from a recursive Specimen.container backbone toward Device-based container/holder modeling. Later FHIR-36029 and FHIR-40559 decisions stayed in the same direction by keeping container details and location under the container Device rather than restoring direct Specimen.container fields.

AutoFHIR reconciliation:
This commit updates the authoritative Specimen StructureDefinition short/definition and the Specimen introduction so they no longer say nesting is unsupported. The new text points implementers to Specimen.container.device[x] and, for referenced Device instances, Device.parent and Device.location for holder hierarchy and location. The generated-looking source/specimen/specimen.svg still contains the old tooltip text and was intentionally not hand-edited; it should be refreshed by the normal build if generated artifacts are updated.

Recommendation:
Keep this source fix as the bounded FHIR-22823 reconciliation. No further core source change is needed for the seed unless the work group wants a broader example specifically demonstrating nested specimen container Devices.
