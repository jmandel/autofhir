FHIR-20607: Restore Request replaces terminal guidance

Issue request:
FHIR-20607 was a Published/Not Persuasive with Modification FHIR-core Request-pattern issue for R5. It asked to align Request immutability wording by removing inappropriate narrative uses of "immutable" while preserving Request.intent as the element that is expected to be immutable, and it also directed clearer wording in the related basedOn/replaces section.

Initial application:
Jira records Git 193d552d63 as the application commit. That commit removed the improper immutable wording from the compound-request narrative and added the requested "will not change over the lifetime" guidance, but in the basedOn/replaces paragraph it replaced the existing terminal-state sentence with the new same-intent sentence instead of adding the same-intent sentence after it.

Additional context:
source/fhir.ini lists request as an active logical pattern, so source/request/request-spreadsheet-notes.xml is current build input. Later FHIR-38868 changed the same narrative from requisitionId to groupIdentifier, and later RequestStatus cleanup replaced the historical cancelled status with current ended/completed/revoked terminology. The current Request.intent element comment still carries the intended immutable guidance, and Request.replaces is defined as completed or terminated request(s), so the remaining gap was the narrative contrast between basedOn and replaces.

AutoFHIR reconciliation:
Restored the omitted terminal-state guidance in source/request/request-spreadsheet-notes.xml using current RequestStatus terminology: a replaced target is no longer in force and should have an ended status such as completed or revoked, or another terminal state supported by that resource. The existing same-intent guidance is left in place immediately after it, matching the Jira resolution's requested ordering.

Recommendation:
Keep this source fix as-is. It completes the previously partial application without changing the resolved Request.intent immutability rule or reopening broader RequestStatus wording.
