FHIR-30697: Apply canonical URL warning to remaining resources

Issue request:
FHIR-30697 was Published / Persuasive with Modification for R5. It asked for canonical-resource URL handling to be clarified by adding an invariant to CanonicalResource.url, and to all resources inheriting that URL, warning that the canonical URL should not contain unencoded '|' or '#'. It also requested canonical URL construction text and a wording cleanup in the canonical reference section.

Initial application:
Commit 5c702608fa34803bf6ac3e88219d1774e50166f8 added the cnl-1 warning to CanonicalResource.url and to many then-current canonical resource URL elements. The canonical reference section already now shows the canonical format as {{CanonicalResource.url}}|{{CanonicalResource.version}} and uses the corrected "canonical URL reference" wording. Later canonical/metadata resource refactoring in 49b86f8a6978650d8f8a6d36d27dee0433e455bc left ObservationDefinition.url, SpecimenDefinition.url, and SubscriptionTopic.url without the cnl-1 constraint even though they are active current resources with canonical URL elements.

Additional context:
FHIR-I minutes from 2021-04-26 record the approved resolution as a warning invariant that the URL should not have '|' or '#', so this reconciliation keeps the existing warning severity and "should not" wording rather than strengthening it. source/fhir.ini lists ObservationDefinition, SpecimenDefinition, and SubscriptionTopic as active build resources, and an audit of active CanonicalResource/MetadataResource StructureDefinitions found these three as the remaining URL elements missing cnl-1. Related Zulip discussion about url search parameters did not identify a conflicting later decision for this invariant.

AutoFHIR reconciliation:
Added the existing cnl-1 warning constraint to ObservationDefinition.url, SpecimenDefinition.url, and SubscriptionTopic.url using the same FHIRPath expression and CanonicalResource source declaration used by parallel resource definitions.

Recommendation:
Keep this source fix as-is. Further changes to the uri search parameter type, canonical URL search behavior, or the invariant severity would be separate work-group decisions and are not supported by this reconciliation evidence.
