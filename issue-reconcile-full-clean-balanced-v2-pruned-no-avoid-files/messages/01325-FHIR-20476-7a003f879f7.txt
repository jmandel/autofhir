FHIR-20476: Fix Subscription admission channel type example

Issue request:
FHIR-20476 was Published/Persuasive for R5 and asked to make the Subscription.channel.type value set binding extensible so custom subscription delivery methods could be experimented with without non-conforming Subscription resources. The accepted resolution also changed the channel type element to Coding because translations/text were not needed.

Initial application:
Jira records a8762c404cabbf352bfaa710016d436b85b757b9 and d6b6a5e68bbfc8eb086c2bf82744432d6af9e788 as implementation commits. Those commits moved Subscription toward the Argonaut/R5 channel model and d6b6a5e made the admission JSON channel value a Coding-shaped object, but that JSON example retained the old channel property and used the value set URL as Coding.system.

Additional context:
FHIR-23738 is the same Subscription redesign family and explicitly lists FHIR-20476 among the Argonaut branch changes, including flattening Subscription.channel and changing Subscription.channelType to Coding. Current source/fhir.ini keeps Subscription active, and source/subscription/list-Subscription-examples.xml includes the Subscription/admission example. The authoritative StructureDefinition already has Subscription.channelType as Coding with an extensible binding to ValueSet/subscription-channel-type, and the XML admission/example sources already use channelType. FHIR-I minutes record the original 7-0-0 vote, and Zulip discussion around the model changes and later channel.type questions aligns with the R5 extensible-channel interpretation.

AutoFHIR reconciliation:
This commit updates source/subscription/subscription-admission.json from the obsolete channel object to channelType as a Coding object, matching the current Subscription StructureDefinition and the parallel XML examples. It removes the incorrect ValueSet URL from Coding.system rather than introducing a new system value, keeping the JSON example aligned with the existing XML examples that carry only the rest-hook code.

Recommendation:
Keep this commit as-is. It completes FHIR-20476 in a current-build example while preserving the already-correct authoritative Subscription.channelType definition; any broader decision to add CodeSystem.system values to all Subscription channel examples should be handled separately.
