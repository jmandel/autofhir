FHIR-39635: Restore SubscriptionTopic message definition events

Issue request:
FHIR-39635 is Applied/Persuasive with Modification for R6. It asked to allow SubscriptionTopic as a FHIR message event, with the final resolution to update MessageHeader.event[x] and MessageDefinition.event[x] to Coding | uri | canonical(EventDefinition, SubscriptionTopic) so subscription notifications can identify a SubscriptionTopic as the triggering event.

Initial application:
Commit b06ee38f43 ("FHIR-39635 and FHIR-32750") added EventDefinition and SubscriptionTopic canonical targetProfiles to MessageHeader.event[x] and to a MessageDefinition StructureDefinition copy, and updated MessageDefinition.event[x] wording. Current MessageHeader source still reflects that application. Current MessageDefinition source did not: a later merge/cleanup path left two MessageDefinition StructureDefinition copies and f94ad6ff73 removed the duplicate copy that contained the FHIR-39635 MessageDefinition event changes, leaving the older active copy with only Coding and uri.

Additional context:
MessageHeader and MessageDefinition are active InM resources in source/fhir.ini. INM minutes from 2023-11-07 record the approved harmonization as Coding|uri|canonical(EventDefinition|SubscriptionTopic). The originating Zulip thread shows the request came from subscription notification use cases. FHIR-32750 was implemented in the same historical commit but concerns MessageDefinition.parent and is not decided here.

AutoFHIR reconciliation:
Restored the FHIR-39635 MessageDefinition.event[x] change in the active source by adding canonical targetProfiles for EventDefinition and SubscriptionTopic and updating the short/definition text. Also updated the active MessageDefinition-event search parameter expression to include canonical values, matching the already-current MessageHeader-event search parameter behavior so canonical message events are searchable rather than silently ignored.

Recommendation:
Keep this source fix. It restores the approved R6 harmonization for MessageDefinition and keeps the search surface consistent with the new event type; no further core source change was identified for FHIR-39635.
