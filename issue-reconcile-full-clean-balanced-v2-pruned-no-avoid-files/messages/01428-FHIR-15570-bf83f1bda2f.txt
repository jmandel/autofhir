FHIR-15570: Remove stale contextType intro mention

Issue request:
FHIR-15570 was Published/Persuasive for STU3 and asked to remove StructureDefinition.contextType after implementer discussion concluded the separate contextType element was not needed as a standalone StructureDefinition element.

Initial application:
The issue was applied by ea10008f8ad516fe2dacc51b1ccc5fae4ef3dab5, which reorganized extension context from separate contextType/context fields into repeating StructureDefinition.context entries with type and expression. Current authoritative StructureDefinition source already has StructureDefinition.context, StructureDefinition.context.type, and StructureDefinition.context.expression, with no StructureDefinition.contextType element.

Additional context:
A later documentation change left the StructureDefinition introduction metadata table labeled "contextType & context" even though the active resource source and the defining-extensions guidance now describe StructureDefinition.context.type. Other remaining contextType strings are outside this issue scope: StructureMap contextType mappings, model-library content, and a commented-out CDA profile entry in fhir.ini.

AutoFHIR reconciliation:
This commit updates the active StructureDefinition introduction table to refer to context only, removing the stale contextType label while preserving the existing link to Defining Extensions for the current context.type/expression model.

Recommendation:
Keep this source fix as-is. It aligns the narrative overview with the already-applied StructureDefinition model and does not require changes to StructureMap or disabled legacy profile sources.
