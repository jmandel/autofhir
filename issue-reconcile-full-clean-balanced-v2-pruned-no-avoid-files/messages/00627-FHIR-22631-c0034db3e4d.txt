FHIR-22626 + FHIR-22630 + FHIR-41412: Align CommunicationRequest provider notes

Attribution note: surfaced while reviewing FHIR-22631, but direct Jira backing for this change is FHIR-22626 + FHIR-22630 + FHIR-41412.

Issue request:
FHIR-22631 was a Published/Persuasive Patient Care change request asking that CommunicationRequest.sender, renamed to CommunicationRequest.informationProvider by the related GF#22626 work, allow multiple disclosing sources. The final resolution was to change CommunicationRequest.informationProvider cardinality to 0..*.

Initial application:
The issue was initially applied by git commit 98ffe585bc9d5fa3f398e0cfe65b1cab8c5e9527, which changed the then-authoritative CommunicationRequest spreadsheet cardinality from 0..1 to 0..* and added GF#22631 to the element notes. The 2021 source rework preserved the change in the current StructureDefinition, where CommunicationRequest.informationProvider now has max="*".

Additional context:
CommunicationRequest is active in source/fhir.ini, so source/communicationrequest is in current build scope. The related GF#22626 rename from sender to informationProvider is also reflected in the StructureDefinition, and later applied changes added Endpoint and Group as provider/recipient target types and clarified multiple information providers. However, the active communicationrequest-notes.xml page still described CommunicationRequest.sender and had an older target-type list. Corrected Zulip and Confluence searches for FHIR-22631 and CommunicationRequest informationProvider found no conflicting community discussion.

AutoFHIR reconciliation:
This commit updates source/communicationrequest/communicationrequest-notes.xml to name CommunicationRequest.informationProvider instead of the obsolete CommunicationRequest.sender and aligns the provider and recipient target-type lists with the current StructureDefinition. It intentionally leaves the authoritative cardinality unchanged because CommunicationRequest.informationProvider already has max="*".

Recommendation:
Keep this source correction. The seed issue's cardinality is already correctly applied in the authoritative StructureDefinition, and this commit removes the remaining stale narrative wording that could direct readers to the retired sender element. No further core change is recommended for FHIR-22631.
