FHIR-13003: Clarify Condition diagnosis encounter guidance

Issue request:
FHIR-13003 is a Published/Persuasive Patient Care change request raised and applied for DSTU2. It followed the removal of the HL7 v2 DG1-6 Diagnosis Type mapping from Condition.clinicalStatus and asked for Condition documentation explaining how to represent diagnosis type through Encounter context, specifically Encounter.diagnosis.role for uses such as admission diagnosis and Encounter.diagnosis.rank for primary diagnosis ranking.

Initial application:
The predecessor mapping change appears in commit 8da21fd1e4, which removed DG1-6 from the then-authoritative Condition.clinicalStatus v2 mapping. The FHIR-13003 application itself appears in commit bd3f8a7ba5, which added a Condition note pointing implementers to Encounter.diagnosis.role and Encounter.diagnosis.rank. Later source refactors preserved that narrative, and the already-published FHIR-19285 reconciliation commit 88d048feea updated the stale role/rank links to current Encounter.diagnosis.use and Account.diagnosis.sequence.

Additional context:
Later Encounter and Account decisions changed the current model that the 2017 note must describe. FHIR-16148 redesigned Encounter.reason and Encounter.diagnosis: admitting diagnosis is now represented as an Encounter.reason value with an Encounter.reason.use code, diagnoses addressed during the encounter use Encounter.diagnosis, and billing-related rank is documented on Account. FHIR-19285 moved ranked billing diagnosis data to Account.diagnosis.sequence, FHIR-23764 confirmed DG1-6 maps to Encounter.diagnosis.use, and FHIR-20484/FHIR-38784/FHIR-38807 already audit the later Encounter diagnosis-use cardinality and wording changes. FHIR-50827 is a later Triaged issue about broader diagnosis-role/value-set gaps, so it is context but not a final source-edit decision for this seed.

AutoFHIR reconciliation:
This commit updates the active Condition narrative note to include the current location for an admitting diagnosis: Encounter.reason.value with Encounter.reason.use. It leaves the already-correct current guidance for diagnoses addressed during an encounter, via Encounter.diagnosis.use, and billing-related numeric rank, via Account.diagnosis.sequence. Condition, Encounter, and Account are active resources in source/fhir.ini, so this Condition narrative is current build-scope source and the added sentence prevents the old FHIR-13003 admission-diagnosis example from being lost after the Encounter.reason redesign.

Recommendation:
Keep this source fix. It completes FHIR-13003 for the current model without reopening the broader PA diagnosis-use/value-set work; any remaining questions about discharge diagnosis, comorbidities, pre/post-op diagnosis, or reusable THO value sets should continue under FHIR-50827 and related PA/THO tickets.
