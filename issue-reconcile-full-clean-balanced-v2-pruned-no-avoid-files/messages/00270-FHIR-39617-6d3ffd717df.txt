FHIR-39617: Clarify Endpoint payload advertising paths

Issue request:
FHIR-39617 was Applied/Persuasive for R6 to clarify how Endpoint.connectionType, Endpoint.payload.type, and Endpoint.payload.mimeType interact for FHIR, IHE/XCA, and HL7v2-style endpoints. The approved resolution called for a Payload Advertising notes section and examples showing semantic content in payload.type, exchange format in payload.mimeType, exchange method in connectionType, and detailed profiles in the payload profile fields.

Initial application:
FHIR-39616 first added the build-scoped Endpoint.payload.profileCanonical and Endpoint.payload.profileUri elements in source/endpoint/structuredefinition-Endpoint.xml. FHIR-39617 was then applied by commit 7e0862e5d9b6f369ff12cf0d82d07d14b1c0b5b2, which added the Payload Advertising notes section, and commit cf768fcaf240a59e23bc9215108e7c97b5892df0, which added the three Endpoint examples and registered them in list-Endpoint-examples.xml.

Additional context:
The current fhir.ini actively includes endpoint=Endpoint and marks Endpoint approved, so source/endpoint/endpoint-notes.xml is part of the active Endpoint resource material. Confluence records show the PA group worked FHIR-39617 through the Endpoint Payload project page, revisited the examples at the September 2024 WGM, and resolved the remaining CCDA example question by January 2025. FHIR-25393 and the linked IHE Zulip thread explain why payload.type needed clarification for REST and IHE endpoints, but they do not require additional source changes here.

AutoFHIR reconciliation:
This commit fixes the remaining malformed wording in the applied Payload Advertising notes. The section now names Endpoint.payload.mimeType, Endpoint.connectionType, Endpoint.payload.profileCanonical, and Endpoint.payload.profileUri explicitly, instead of referring to bare mimeType/connectionType and non-existent top-level Endpoint.profileCanonical/profileUri elements.

Recommendation:
Keep this source fix. It is a narrow correction to the already-applied FHIR-39617 notes and aligns the narrative with the current Endpoint StructureDefinition and examples; no further core source work was found for this issue.
