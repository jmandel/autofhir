FHIR-15657: Replace stale ClaimResponse total fields

Issue request:
FHIR-15657 is a Published/Persuasive FHIR-core ClaimResponse change request for STU3. It asked to replace ClaimResponse totalCost, unallocated/unallocDeductable, and totalBenefit with repeating ClaimResponse.total entries containing category and amount, to use the submitted adjudication code instead of total, and to add unallocdeduct to the adjudication code set.

Initial application:
The change was substantially applied before this reconciliation. Git commit 39b2cdba02 pre-adopted the same repeating total pattern in ExplanationOfBenefit examples and changed the then-core adjudication code system from total to submitted while adding unallocdeduct. Git commit e50c083cdf, explicitly titled Tracker #15657, replaced ClaimResponse example totalCost/totalBenefit/unallocDeductable content with repeating total entries and updated the then-authoritative ClaimResponse spreadsheet. Current ClaimResponse source and regular examples already use ClaimResponse.total with category and amount and no longer expose the old fixed total elements.

Additional context:
ClaimResponse, Claim, and Library are active resources in source/fhir.ini. The Claim $submit operation is active and references source/claim/$submit-response.txt as its response example; that example still used the retired ClaimResponse totalCost and totalBenefit elements. The Library examples page and publish.ini also publish library-quick-model-definition-content.xml; its QUICK.ClaimResponse model still exposed totalCost, unallocDeductable, and totalBenefit even though the parallel FHIR model-definition content already has ClaimResponse.total and ClaimResponse.Total. ProcessRequest has a similar old response example, but ProcessRequest is commented out of the current resources list and was not edited. The current core source no longer owns the adjudication CodeSystem content after UTG/THO migration; the active adjudication ValueSet composes from http://terminology.hl7.org/CodeSystem/adjudication.

AutoFHIR reconciliation:
Updated the active Claim $submit response example to use two ClaimResponse.total entries categorized as submitted and benefit, and updated the active QUICK Library model-info example to replace the three stale fixed total fields with a repeating total element and a QUICK.ClaimResponse.Total backbone carrying category and amount.

Recommendation:
Keep this source fix. The primary ClaimResponse resource was already correct, and these two active parallel artifacts were the remaining source locations that could teach implementers or CQL tooling the retired total fields. No core source follow-up is recommended for the adjudication code system unless a separate THO/UTG issue identifies a terminology defect.
