FHIR-3861: Clarify ElementDefinition path examples

Issue request:
FHIR-3861 was Published with a Persuasive with Modification resolution asking for examples in the ElementDefinition.path detailed description that explain how to populate the path for resource, datatype, and extension definitions. The reported ambiguity was that the definition only said the path began with the name of the resource or extension, while extension examples were rooted at Extension.

Initial application:
The Jira comment records svn revision 4525. In the git import, commit f16595324f39903eda2d89de8c2e30744b13e8ff at the same timestamp corrected extension examples and added ElementDefinition page extension-path guidance, including Extension and Extension.value[x]. Later commit 49dcd3b5343a466e9e1aa3bac05b1a1a20bd29a6 reorganized the ElementDefinition narrative into the current path/type context table. However, the active ElementDefinition datatype spreadsheet still retained the original detailed-definition text without resource/datatype/extension examples.

Additional context:
Current source/fhir.ini actively includes ElementDefinition as a datatype, so source/datatypes/elementdefinition.xml feeds the generated ElementDefinition detailed descriptions. The current narrative page already contains broader context for resources, datatypes, and defined extensions. Later related Jira decisions confirm the direction of the wording: FHIR-9421 clarified that ElementDefinition.path can be rooted in a logical model's structure rather than only a resource or datatype, FHIR-8542 corrected extension value examples to use Extension.value[x], and FHIR-9284 added broader extension-definition guidance on the ElementDefinition interpretation page.

AutoFHIR reconciliation:
This commit updates source/datatypes/elementdefinition.xml so ElementDefinition.path begins with the root of the structure definition and includes concrete resource, datatype, and extension examples: Patient.birthDate, HumanName.family, Extension.value[x], and Extension.extension. This fixes the remaining authoritative detailed-description source without duplicating or rewriting the already-correct narrative guidance.

Recommendation:
Keep this source fix. It applies the published FHIR-3861 request in the build-scope datatype source while preserving later guidance for logical models and extension structure definitions. No additional core source change is recommended for FHIR-3861.
