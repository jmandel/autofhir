FHIR-39174: Clarify submit-data MeasureReport type

Issue request:
FHIR-39174 was an Applied/Persuasive with Modification CQI change request for R5/R6 MeasureReport and Measure operations. It asked to prevent the $evaluate-measure reportType parameter from accepting the measure-report-type code data-exchange by creating an evaluation-specific ValueSet, binding $evaluate-measure reportType to it, and adding a $submit-data OperationDefinition note that the submitted MeasureReport is expected to use the data-exchange report type.

Initial application:
The issue was marked applied after FHIR-33004 was applied. The Jira-tagged implementation commit 287186099c created source/measure/valueset-measure-report-evaluation-type.xml and bound source/measure/operationdefinition-Measure-evaluate-measure.xml reportType to that ValueSet, and later source also binds the current Measure-evaluate operation to the same ValueSet. That initial application covered the evaluation-side binding and excluded data-exchange, but it did not add the requested $submit-data note.

Additional context:
FHIR-33004 is the same-change-family technical correction for the evaluation reportType binding, and FHIR-39174 comments describe the seed as effectively a duplicate once FHIR-33004 was applied. Later FHIR-50487 aligned $submit-data with DEQM and changed the input to a Bundle, while DEQM STU 5 describes those Bundles as containing Data Exchange MeasureReports. Measure is active in source/fhir.ini and source/measure/list-Measure-operations.xml references OperationDefinition/Measure-submit-data, so the edited OperationDefinition feeds the current build.

AutoFHIR reconciliation:
This commit updates the active Measure $submit-data bundle parameter documentation to say that each submitted MeasureReport is of type data-exchange. It leaves the already-correct evaluation ValueSet and bindings unchanged and does not add a submit-data-specific ValueSet because the current operation input is Bundle, not a direct MeasureReport code parameter.

Recommendation:
Keep this commit as-is. It completes the remaining FHIR-39174 source note narrowly, without changing the later FHIR-50487 Bundle input shape or strengthening the Jira wording into a new formal binding.
