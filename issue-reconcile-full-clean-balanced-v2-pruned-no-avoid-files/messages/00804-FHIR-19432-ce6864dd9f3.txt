FHIR-19432: Correct InsurancePlan identifier example URIs

Issue request:
FHIR-19432 is an Applied/Persuasive with Modification FHIR-core Patient Administration change request. It asked whether commercial plan and group numbers belong in InsurancePlan.identifier and requested clearer examples; the final resolution, after the FHIR-24827 InsurancePlan refactor, selected post-refactor InsurancePlan.identifier for both plan and group IDs and directed updates to the element definition and comments.

Initial application:
The issue was applied in git commit 1b597e8ee07c2c0df02ae2ab2483daddcf1ba808, which changed source/insuranceplan/structuredefinition-InsurancePlan.xml to define InsurancePlan.identifier as plan/group identifiers and add the two-resource Boilermakers/Aviation example. That application covered the substantive Jira decision, but three of the example Identifier.system URI strings were imported with spaces inside the URI, and the current rendered build still exposed those invalid example strings.

Additional context:
InsurancePlan is active in source/fhir.ini and owned by PA, so source/insuranceplan/structuredefinition-InsurancePlan.xml is in current build scope. The relevant context is the FHIR-24827 split of InsuranceProduct and InsurancePlan, which made post-refactor InsurancePlan.identifier the right target. The FHIR-24641 Coverage.class issue cited in the Jira resolution concerns patient-specific coverage details and has already been separately audited; it does not supersede the InsurancePlan publication use case. Confluence searches found PA minutes for the discussion path and no contrary instruction, and Zulip searches found no directly conflicting discussion.

AutoFHIR reconciliation:
This commit leaves the accepted definition and example structure unchanged and corrects only the malformed example Identifier.system values to valid URI strings: https://insurance-payer.com/plan-numbers and https://insurance-payer.com/group-numbers.

Recommendation:
Keep this source fix as-is. It preserves the work-group decision while preventing implementers from copying invalid Identifier.system examples from the current InsurancePlan.identifier comment.
