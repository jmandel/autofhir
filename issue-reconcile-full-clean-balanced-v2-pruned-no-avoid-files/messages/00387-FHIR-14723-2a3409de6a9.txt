FHIR-14723: Clarify Catalog profile Composition content

Issue request:
FHIR-14723 was Published/Persuasive for STU3 and requested that Composition no longer say it does not contain content. The accepted text says Composition defines structure and narrative content for a document, and that a Composition may contain only Composition.section.text narrative with no Composition.section.entry.

Initial application:
The Jira comment cites svn revision 13034, represented in git by d79d11f1ba, which added the narrative-only note in source/composition/composition-notes.xml. Current source/composition/structuredefinition-Composition.xml already carries the accepted replacement wording for the base resource, but source/composition/structuredefinition-profile-catalog.xml retained the older no-content sentence.

Additional context:
The Catalog profile is in current build scope through the active source/fhir.ini composition=Composition resource, source/composition/list-Composition-packs.xml, and source/composition/implementationguide-Composition-core.xml reference to StructureDefinition/catalog. FHIR-7379 introduced the earlier no-content wording, and duplicate FHIR-14235 identified the same contradiction with Composition.section.text; no Zulip or Confluence search found a later conflicting decision.

AutoFHIR reconciliation:
Updated the active Catalog profile's root Composition differential definition to use the FHIR-14723 accepted wording. This source fix removes the stale profile text that contradicted the current base Composition definition and could mislead implementers viewing the Catalog profile.

Recommendation:
Keep this fix. No additional core source change is needed because the base Composition definition and Composition notes already reflect FHIR-14723, and the only remaining current-source stale wording was in the active Catalog profile.
