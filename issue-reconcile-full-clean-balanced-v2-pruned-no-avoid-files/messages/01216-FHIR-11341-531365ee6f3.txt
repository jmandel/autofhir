FHIR-11341: Correct ServiceRequest status comment

Issue request:
FHIR-11341 was Published/Persuasive for DSTU2 and asked that DiagnosticRequest.status stop saying the requester sets the status to "requested", because requested was no longer in the DiagnosticRequest status value set. The approved resolution was to replace that text with the request-pattern status comment, including links to Event Pattern and Task.

Initial application:
The seed was applied in historical commit ccaebaf262, which changed source/diagnosticrequest/diagnosticrequest-spreadsheet.xml and .sheet.txt from the obsolete "requested" wording to the request-pattern comment. No current combined-branch commit already represented FHIR-11341 before this reconciliation.

Additional context:
FHIR-12254 supplied the shared _Request.status replacement wording. Later FHIR-11119 merged DiagnosticRequest into ProcedureRequest, and the current build lists ServiceRequest as the active successor resource while DiagnosticOrder/DiagnosticRequest and ProcedureRequest are retired or merged in source/fhir.ini. FHIR-20563 and later request-status work changed the current ServiceRequest vocabulary from cancelled/suspended wording to revoked/on-hold and added the ended parent status. The current RequestStatus CodeSystem does not include requested or competed.

AutoFHIR reconciliation:
This commit updates the active ServiceRequest.status comment from "competed" to the valid current status word "completed" and updates the matching ServiceRequest request-pattern mapping-exception resource text. The obsolete requested wording was already gone, but this one-word fix keeps the same authoritative status comment from introducing another non-code status term.

Recommendation:
Keep this source fix. It preserves the historical FHIR-11341/request-pattern intent in the current ServiceRequest successor and avoids a misleading status term while leaving broader request-pattern and status-code policy decisions to the already separate related issues.
