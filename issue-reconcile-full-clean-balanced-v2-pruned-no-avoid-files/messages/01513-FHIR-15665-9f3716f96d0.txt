FHIR-15665: Enforce Questionnaire enableWhen comparison types

Issue request:
FHIR-15665 was Published/Persuasive with Modification for STU3 Questionnaire enableWhen logic. It asked to drop hasAnswer, introduce a required operator with exists, comparison, equality, and inequality codes, and constrain <, >, <=, and >= to integer, decimal, date, dateTime, time, and Quantity answers.

Initial application:
The issue was initially applied in svn revision 13258, represented in git by 651aa532af, which replaced Questionnaire.item.enableWhen.hasAnswer with operator, made answer[x] required, and added the QuestionnaireItemOperator codes. Later source refactoring moved the active definition into source/questionnaire/structuredefinition-Questionnaire.xml. The current source retained the operator and codes but did not retain a constraint prohibiting comparison operators on non-comparable answer types.

Additional context:
Questionnaire is an active build resource in source/fhir.ini, and the authoritative current StructureDefinition source is in source/questionnaire. Later FHIR-26317 corrected copied enable-operator definitions without changing the allowed operator/type rule. Later FHIR-55921, currently Resolved - change required rather than Applied/Published, independently confirms the same comparison-operator type restriction while also requesting broader R6 guidance and a referenced-question type rule; this reconciliation does not decide or fully apply that later issue.

AutoFHIR reconciliation:
Added que-20 to Questionnaire.item.enableWhen to enforce that <, >, <=, and >= only appear with integer, decimal, date, dateTime, time, or Quantity answer[x] values, marked operator and answer[x] with the new condition, and added passing/failing invariant examples for the new rule.

Recommendation:
Keep this source fix as the missing part of the published FHIR-15665 decision. Handle FHIR-55921 separately when Resolved - change required items are in scope, because its additional comparison guidance and referenced-question typing rule go beyond the seed issue.
