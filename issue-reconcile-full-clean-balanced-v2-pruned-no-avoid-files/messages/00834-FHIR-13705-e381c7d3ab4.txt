FHIR-13705: Point Communication about guidance to reason

Issue request:
FHIR-13705 was Published/Persuasive with Modification for STU3 and asked Patient Care to clarify Communication.topic, add Communication.about and CommunicationRequest.about for resources that pertain to a communication, and remove CommunicationRequest.topic so the subject-line concept did not overlap with reason/payload semantics.

Initial application:
The issue was initially applied by commit 32b35437cc8daef171fb42950801c6a39d6f918b, which updated the then-authoritative Communication and CommunicationRequest spreadsheets, changed the financial attachment example from topic to about, added Communication.topic as a 0..1 CodeableConcept with the requested subject-line definition and comment, added both about elements, and removed CommunicationRequest.topic. Later source refactoring in 33b409a4b6d544598262f2f074ebb4b6dc466157 converted the spreadsheets into the current StructureDefinition XML and preserved the FHIR-13705 content, but the about comments still named the old reasonReference element even though the current resources use Communication.reason and CommunicationRequest.reason.

Additional context:
source/fhir.ini lists Communication and CommunicationRequest as active current-build resources and records that the old reasonCode/reasonReference elements were merged into reason, with reasonReference mapping to reason.reference. The original Zulip discussion distinguished why a communication occurred from what it was about; that intent still applies, but in the current model the more-specific element is reason, not reasonReference. Confluence searches found no conflicting minutes beyond the Jira-recorded Patient Care vote and comments.

AutoFHIR reconciliation:
This commit updates the current Communication.about and CommunicationRequest.about comments to point implementers to reason instead of the removed reasonReference element. It also updates the CommunicationRequest Request-pattern mapping exception text in lockstep so the pattern exception source mirrors the authoritative StructureDefinition comment.

Recommendation:
Keep this commit as-is. It preserves the already-applied FHIR-13705 semantic model and removes a stale element name introduced by later source evolution; no further Communication.topic or CommunicationRequest.topic change is needed for this issue.
