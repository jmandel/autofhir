FHIR-41229: Add lenient display validation to CodeSystem

Issue request:
FHIR-41229 was Applied/Persuasive for R6 by Vocabulary and asked to add an optional lenient-display-validation input parameter to $validate-code so clients can request that an invalid display string be reported as a warning instead of making result false. The accepted resolution explicitly applies the parameter to both CodeSystem and ValueSet $validate-code.

Initial application:
The issue appears to have been partially applied by commit 4cd9f00b61, which added lenient-display-validation to source/valueset/operationdefinition-ValueSet-validate-code.xml along with other ValueSet operation parameters. That commit did not change source/codesystem/operationdefinition-CodeSystem-validate-code.xml, leaving the CodeSystem operation without the approved parallel parameter.

Additional context:
Both CodeSystem and ValueSet are active resources in source/fhir.ini, and source/codesystem/list-CodeSystem-operations.xml includes OperationDefinition/CodeSystem-validate-code. Confluence Vocabulary WGM minutes for 2023-05-10 list FHIR-41229 among the terminology-service trackers discussed with FHIR-I and point readers to the Jira resolutions. No Zulip search result directly contradicted the Jira resolution or the partial source-history finding.

AutoFHIR reconciliation:
This commit adds the lenient-display-validation input parameter to CodeSystem/$validate-code, using the same cardinality, type, and documentation already present on ValueSet/$validate-code. This completes the accepted two-operation scope without changing unrelated operation behavior or examples.

Recommendation:
Keep this source change. It is the missing half of the applied FHIR-41229 resolution and keeps CodeSystem/$validate-code aligned with ValueSet/$validate-code for display validation severity control.
