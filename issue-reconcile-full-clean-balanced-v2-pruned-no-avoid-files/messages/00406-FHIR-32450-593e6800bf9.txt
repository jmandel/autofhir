FHIR-32450: Model media example as an AuditEvent entity

Issue request:
FHIR-32450 was Published/Persuasive with Modification for R5. It asked that AuditEvent.agent.location, agent.policy, agent.media, and agent.network stop reading like event-wide attributes: location and policy should be agent-specific, agent.media should be removed in favor of AuditEvent.entity.agent for persistence media, network should describe the agent endpoint, and the DICOM mappings should reflect entity.agent and network[x].

Initial application:
The issue was initially applied by 3d204189e2, which updated source/auditevent/structuredefinition-AuditEvent.xml to make agent.location and agent.policy agent-specific, replace the old agent.network backbone with agent.network[x], remove agent.media, add AuditEvent.entity.agent, and map entity.agent/network[x] to the relevant DICOM concepts. That implementation left source/auditevent/audit-event-example-media.xml as an active example that still modeled the destination media itself as an AuditEvent.agent and included a TODO to convert the old media detail into an entity.agent pattern.

Additional context:
AuditEvent is active in source/fhir.ini, and list-AuditEvent-examples.xml includes audit-event-example-media, so the example is part of the current build surface. FHIR-32459, handled in the same block-vote family, further changed network to network[x] with Reference(Endpoint), uri, or string; the current StructureDefinition already reflects that later network shape. FHIR-32456 supports the same media/network distinction by clarifying media as persistent data at rest rather than transport.

AutoFHIR reconciliation:
This commit fixes the active media example only. It removes the top-level media-as-agent entry, adds the destination media as an AuditEvent.entity, preserves the DICOM Destination Media role and DVD media type as entity role/detail, and shows the human user responsible for the media use under entity.agent. No StructureDefinition edit is needed because the authoritative definitions and mappings already match the Jira resolution.

Recommendation:
Keep this source fix. It completes the remaining example-level application for FHIR-32450 without reopening the already-applied agent.location, agent.policy, agent.network[x], or entity.agent definitions. Related issues FHIR-32456 and FHIR-32459 should be audited separately if their own reconciliation workers require independent per-issue decisions.
