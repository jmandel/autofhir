FHIR-7538: Fix XML whitespace anchor

Issue request:
FHIR-7538 was a Published/Persuasive with Modification ITS change request from the 2015 May core ballot. It asked the XML format page to clarify whitespace handling for value attributes, specifically whether XML schema whitespace processing applies or whether implementations should strip leading/trailing whitespace when writing and reading.

Initial application:
The Jira resolution directed a Postel's-law note saying implementers should trim whitespace before writing and when reading. Jira records svn revision 6674, and git-svn commit a8566ea065d07d44c6a49ebb58bdd6e478b1a8a0 added that note to source/xml.html. Later commit a5c90c3db3cc87902faf8b096c1fdc5f179853fc added a datatypes.html link to xml.html#whitespace and changed the XML note to include an anchor, but the anchor was misspelled as "whitepace".

Additional context:
The current source still contains the requested XML whitespace guidance and a related datatype note pointing readers to xml.html#whitespace. source/xml.html is a current core XML format page linked from the active documentation and resource-format pages, and source/datatypes.html is the current datatype narrative. No relevant Zulip or Confluence discussion was found, and the combined branch did not already contain an Issue-Reconcile-Key: FHIR-7538 audit commit.

AutoFHIR reconciliation:
This commit corrects the XML whitespace note anchor from "whitepace" to "whitespace" so the current datatypes.html link reaches the guidance originally added for FHIR-7538. It does not change the normative wording, because the requested clarification is already present.

Recommendation:
Keep this source fix as-is. No work-group review or broader source change is needed unless a future link checker identifies additional unrelated anchors.
