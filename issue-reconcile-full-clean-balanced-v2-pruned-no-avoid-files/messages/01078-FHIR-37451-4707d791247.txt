FHIR-37451: Correct _sort text modifier example

Issue request:
FHIR-37451 is a Published/Persuasive FHIR-core search change request for R5. It asked that _sort explicitly allow the :text modifier for reference and token search parameters, with examples such as _sort=code:text and _sort=-code:text.

Initial application:
The request was initially applied in git commit a5f28ac2c00aed2da477f844c769d91bc5ad88a6, which added the intended _sort text-modifier note to source/search.html but used the malformed negative-sort example _sort:-code:text. Later commit a3766ac36c61fa3448d53aca0519dcbd874cfc93 for FHIR-37753 retagged and clarified conformance language in the same sentence but preserved the malformed example.

Additional context:
The linked Zulip thread shows the original implementer question and product-name sorting use case. FHIR-I minutes for 2022-05-23 record the 8-0-0 persuasive vote. A later Triaged technical-correction issue, FHIR-50266, and its Zulip thread independently identify the same typo, but that issue is unresolved and is not being separately decided in this default applied/published reconciliation run. The authoritative current source is source/search.html, the FHIR-core search narrative page; source/fhir.ini also treats search.html as the page whose summary table is maintained alongside search rules.

AutoFHIR reconciliation:
This commit changes source/search.html so the descending sort example reads _sort=-code:text, matching the FHIR-37451 resolution and the surrounding _sort syntax where the optional '-' prefix is part of the _sort value after '='.

Recommendation:
Keep this source fix as-is. It completes the FHIR-37451 application by correcting a misleading example without changing the approved behavior; FHIR-50266 can likely be closed by humans as already satisfied by this reconciliation rather than published as a separate AutoFHIR decision.
