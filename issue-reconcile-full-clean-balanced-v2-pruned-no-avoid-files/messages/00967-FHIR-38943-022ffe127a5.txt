FHIR-38943: Complete Bundle profile registration

Issue request:
FHIR-38943 was Published as Persuasive with Modification for R5. The approved resolution was to define standard informative profiles for Bundle types that manifest the rules for each Bundle use, so downstream profiles can derive from them instead of reinterpreting Bundle-page prose and invariants.

Initial application:
The issue was initially applied by HL7/fhir#2513, merged as cb9053fbfc160b5fd5af05d413a9251370a7e521. That PR added Bundle profile StructureDefinitions and a Bundle-core ImplementationGuide, but the final PR head left the existing message-bundle profile out of the Bundle-core IG and left batch-bundle with Bundle.type constrained to the non-code value `bundle` rather than the Bundle type code `batch`.

Additional context:
The Bundle resource is active in source/fhir.ini, source/bundle/list-Bundle-packs.xml includes ImplementationGuide/Bundle-core, and that IG is the build-scope package entry that publishes these Bundle profiles. The current Bundle type CodeSystem defines `batch` and `message` as valid Bundle.type codes, while `bundle` is not a valid Bundle.type code. No later Jira, Zulip, or Confluence evidence found in this bounded search superseded the Published FHIR-38943 decision; Confluence minutes instead confirm the vote and later request for Lloyd review of Bas' profiles.

AutoFHIR reconciliation:
This commit adds StructureDefinition/message-bundle to source/bundle/implementationguide-Bundle-core.xml so the existing message Bundle profile is included with the other Bundle profiles, and changes source/bundle/structuredefinition-profile-batch-bundle.xml so batch-bundle constrains Bundle.type to `batch`. It does not add a collection-bundle profile because the current collection type definition imposes no special processing obligations or behavioral rules beyond the base Bundle rules, so there are no type-specific rules to manifest for that code under the Persuasive-with-Modification scope.

Recommendation:
Keep this source fix. It completes the already-published Bundle profile application without broadening the issue into new profile design work; any future collection-specific profile should come from an explicit work-group decision if the WG wants a type-fixing profile even when no additional collection rules exist.
