FHIR-52810: Use fragment target for embedded Bundle signatures

Issue request:
FHIR-52810 was Applied with resolution Persuasive with Modification. It asked that embedded Bundle signatures stop using Provenance.target = Bundle/[id], because Bundle.id can change as a document moves between servers, and the approved resolution required pointer-based fragments using the fragment identifier '#/' plus matching updates to the page rules and worked examples.

Initial application:
The issue appears to have been only partially applied through HL7/fhir#4028. That PR merged as 66cbbee5f9e678f6c702807682f9bf0a064e9456 and added a ballot note claiming FHIR-52810 was clarified, while the Jira-linked signature history also changed nearby counter-signing wording in 9f8597f0a551bb5fcf4b3db6cd8071f8845de9d8. No commit message specifically applied FHIR-52810, and the active signatures page still required Bundle/[id] in the normative Signing Bundles rule and used Bundle/signed in the Provenance worked example.

Additional context:
The Zulip thread linked from Jira confirms the rationale that non-repudiation signatures for document Bundles should not depend on mutable Bundle ids. FHIR-53810 later noted that FHIR-52810 had not been updated in the ballot version, and FHIR-57443 independently reports the same Bundle/[id] confusion, but both are unresolved/Triaged context rather than separate decisions for this worker. FHIR-52811 and FHIR-53914 raise broader unresolved clarity/rewrite questions for the same page and do not reverse the applied FHIR-52810 decision.

AutoFHIR reconciliation:
This commit updates source/signatures.html, an active FHIR core narrative page linked from the security, documentation, datatypes, and documents pages. The Signing Bundles rule now requires Provenance.target.reference exactly '#/', described as the pointer-based fragment identifier for the root Bundle, and the worked Provenance example now uses '#/' instead of Bundle/signed. No broader self-signing or canonicalization wording was changed because those topics remain governed by unresolved related issues.

Recommendation:
Keep this source fix as-is for FHIR-52810. Future work on FHIR-52811, FHIR-53914, or FHIR-57443 may further rewrite the Signing Bundles section, but it should preserve the FHIR-52810 outcome that embedded Bundle signatures identify the root Bundle with '#/' rather than a mutable Bundle id.
