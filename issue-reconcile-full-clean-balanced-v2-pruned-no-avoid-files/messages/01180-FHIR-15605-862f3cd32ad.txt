FHIR-15605: Align Media type wording and constraints

Issue request:
Published/Persuasive OO issue FHIR-15605 reopened the duplicate FHIR-14145 disposition. The accepted request was to change the old media code photo to image, keep the element named Media.type, make it 0..1 CodeableConcept with an extensible Media Type binding, and describe it as filtering what is retrieved and displayed.

Initial application:
Commit 17a86882a2 applied the original GF#14145 approach by changing Media.type to category and adding the image code. Commit e6e73a2910 then applied GF#15605 by restoring Media.type and wiring the CodeableConcept MediaType binding and type search parameter, but the current source still retained a Media introduction that said the element became category and retained type-related wording/constraints from the old primitive photo/audio code model.

Additional context:
FHIR-14145 is a Duplicate explicitly deferred to FHIR-15605. FHIR-13533 is the same change family for the photo-to-image code and the current Media type code list already uses image. The Zulip Media.code thread explains why the final shape kept a simple audio/video/image type with an extensible CodeableConcept rather than a repeatable category. source/fhir.ini keeps Media active in the current build, so the Media spreadsheet and introduction are build-scope source.

AutoFHIR reconciliation:
Updated source/media/media-introduction.xml so the STU note says the required type became an optional Media.type rather than category. Updated source/media/media-spreadsheet.xml so Media.type filters media rather than observations, image-related text no longer uses photo as the type category, and the height/width/frames/duration invariants test Media.type.coding against the media-type CodeSystem instead of comparing the CodeableConcept element to primitive photo/audio strings.

Recommendation:
Keep this source fix. It completes the FHIR-15605 application in the current Media source without changing the value set canonical or reopening the duplicate FHIR-14145. FHIR-13533 can be handled as a separate no-change audit if needed, but its requested value set code is already image in this source.
