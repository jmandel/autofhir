FHIR-33341: Correct Appointment virtual-service datatype reference

Issue request:
FHIR-33341 was Published as Persuasive with Modification. PA asked for standards support for video-meeting details such as URLs, phone numbers, and PINs on Appointment, and the adopted resolution added virtual-service support for Appointment and Location using a virtual service contact detail structure.

Initial application:
The request was applied by git commits 7cf46b9270d28e976d4882ee79f337e119904879 and 41dc13b3838dc242a1979fa7c92274665ade655d, which added Appointment.virtualService, the VirtualServiceDetail datatype source, and refined Appointment and Location documentation. The current Appointment element already has type VirtualServiceDetail, but the participant-specific guidance still named the obsolete VirtualServiceContactDetail.

Additional context:
source/fhir.ini actively includes Appointment, Location, and VirtualServiceDetail, and current source has no VirtualServiceContactDetail definition in core or the Extension Pack. FHIR-33231 is the same change family for Encounter and is reconciled separately because it copied the same guidance. PA minutes record the FHIR-33341 approval and later note wide support for keeping the new datatype in the ballot after MnM asked for more discussion.

AutoFHIR reconciliation:
This commit updates only the Appointment.virtualService comment so the participant-level extension guidance refers to VirtualServiceDetail, matching the actual active datatype and the element type.

Recommendation:
Keep this source fix. It preserves the approved virtual-service model while removing a stale datatype name that could mislead implementers looking for the extension value type.
