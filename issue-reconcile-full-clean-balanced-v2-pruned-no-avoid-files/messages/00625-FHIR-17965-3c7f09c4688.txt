FHIR-17965: Mark remaining CoverageEligibilityResponse summary elements

Issue request:
FHIR-17965 was a Published/Persuasive Financial Management change request for the STU3 EligibilityResponse/CoverageEligibilityResponse artifact asking to add identifier, purpose, patient, created, provider, insurer, and inforce to the summary view.

Initial application:
The historical omnibus commit f369c813fb for GF#/FHIR-17965 changed the CoverageEligibilityResponse spreadsheet and made purpose, patient, created, and insurer summary elements, but left the spreadsheet Summary column blank for identifier, requestor/request-provider, and insurance.inforce. The later R4B source conversion commit c69d71aa21 carried those same omissions into the current StructureDefinition XML.

Additional context:
The current build uses CoverageEligibilityResponse as the successor alias for EligibilityResponse, with active fhir.ini entries for the resource, FM work group, patient security category, acronym, and approved status. The old provider/request-provider concept is now represented in this resource as CoverageEligibilityResponse.requestor; insurance.inforce remains the current path for the inforce indicator. No Zulip or Confluence evidence was found that narrows or reverses the Jira request.

AutoFHIR reconciliation:
This commit adds isSummary=true to CoverageEligibilityResponse.identifier, CoverageEligibilityResponse.requestor, and CoverageEligibilityResponse.insurance.inforce. The other requested elements, CoverageEligibilityResponse.purpose, patient, created, and insurer, were already correctly marked summary in current source.

Recommendation:
Keep this source fix as-is. It completes the published Jira request on the active current resource without changing unrelated Financial Management resources or generated diagram artifacts.
