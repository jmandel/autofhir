FHIR-38817: Remove broken-link page from TOC hierarchy

Issue request:
FHIR-38817 was a Published/Persuasive R5 correction for the 2022Sep Table of Contents, where toc.html linked to broken-link.html at section 1.11. The approved resolution was to fix the tooling/source path so the broken-link page does not show in the ToC or consume a section number.

Initial application:
No prior commit in this repository explicitly mentions FHIR-38817. The broken-link page was introduced by a41e7958c85a2583535192048e11abfbfdf13be4 ("ballot QA") on 2022-09-08, which added source/broken-link.html, publish.ini's page entry, and a source/hierarchy.xml child under toc.html; that hierarchy entry is what made the page eligible for the ToC and section numbering.

Additional context:
FHIR-I minutes for 2022-10-24 record FHIR-38817 as a tooling change and state that the "broken link" page is not supposed to be in TOC. Current build.fhir.org/toc.html and the published R5 toc.html no longer contain broken-link.html, while the 2022Sep ballot toc.html did, so the remaining source reconciliation is to remove the stale hierarchy entry without deleting the page itself.

AutoFHIR reconciliation:
Removed the Broken Link Page entry from source/hierarchy.xml. The broken-link.html entry remains in publish.ini and source/broken-link.html remains available so example broken-reference redirects can still resolve to the explanatory page, but the page no longer participates in the source hierarchy that drives the TOC and section numbering.

Recommendation:
Keep this source change as-is. It is a non-substantive correction aligning current source with the Published/Persuasive decision and with current published output; no broader TOC or link-checking change was indicated.
