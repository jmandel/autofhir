FHIR-50533: Correct Observation code binding labels

Issue request:
FHIR-50533 is Applied with a Persuasive with Modification resolution for R6 Observation. It asked to create a LOINC value set excluding Order-only LOINC codes by including ORDER_OBS Observation/Obs only and Both, and to bind that value set as an example binding to Observation.code and Observation.component.code.

Initial application:
The Jira comment says the issue was applied in commit 47058c274e. That commit created source/observation/valueset-observation-codes-observationorboth.xml and changed both Observation.code and Observation.component.code from http://hl7.org/fhir/ValueSet/observation-codes to http://hl7.org/fhir/ValueSet/observation-codes-observationorboth. Later PR #3963/FHIR-53279 extended the same canonical value set to ObservationDefinition, moved the older all-LOINC observation-codes value set to DeviceAlert for build reachability, and made the binding names distinct, but it left the Observation binding-name metadata reversed.

Additional context:
source/fhir.ini lists observation as an active resource, so source/observation/structuredefinition-Observation.xml and the referenced value set source are in current build scope. The current value set has the intended LOINC ORDER_OBS filters for Observation and Both. Confluence OO minutes for 2025-10-07 record the approving vote and specifically say the LOINC constraints apply to both .code and component.code. Later Jira issues FHIR-54595 and FHIR-54887 discuss possible broader handling for panels/organizers, but their workflow status is Triaged rather than Applied or Published, so they do not supersede this applied R6 source state.

AutoFHIR reconciliation:
This commit keeps the existing value set URL and LOINC filters, and corrects only the Observation binding-name labels so Observation.code is labeled ObservationCode and Observation.component.code is labeled ObservationComponentCode, matching the element being bound and the parallel ObservationDefinition source.

Recommendation:
Keep this commit. The substantive FHIR-50533 value set application is already present, and this narrow metadata correction removes a directly related inconsistency introduced during later cleanup without implementing unresolved panel/organizer proposals.
