FHIR-32440 + FHIR-32439 + FHIR-32441: Align AuditEvent binding note

Attribution note: surfaced while reviewing FHIR-32440, but direct Jira backing for this change is FHIR-32440 + FHIR-32439 + FHIR-32441.

Issue request:
FHIR-32440 was Published/Not Persuasive with Modification for the Security work group. It asked whether AuditEvent.subType should merge into AuditEvent.type because multiple codings could express different granularities; the final disposition did not merge them directly and instead pointed to redesigned example bindings and the related FHIR-32443 type/subtype to category/code change.

Initial application:
The issue was applied together with FHIR-32443 and FHIR-32451 in a4a8e4475ffed8a639ac458dba61b68da343891e. That commit moved AuditEvent type/subtype toward the R5 category/code model and updated related AuditEvent narrative. Separate same-block commits changed the type and subtype bindings from extensible to example, and later QA work wired the example ValueSet URLs.

Additional context:
FHIR-44746 is a later Applied/Persuasive with Modification Security decision that reversed the R5 category/code model back to AuditEvent.type and AuditEvent.subtype for DICOM and broader audit-standard compatibility. The current active AuditEvent StructureDefinition preserves type/subtype, has example bindings for both elements, and points to the audit-event-type-example and audit-event-sub-type-example ValueSets. AuditEvent is active in source/fhir.ini, so the AuditEvent notes page is in current build scope. FHIR-32443 and FHIR-32441 are already represented on the combined branch; FHIR-32439 is a related type-binding issue that was not decided here.

AutoFHIR reconciliation:
This commit updates source/auditevent/auditevent-notes.xml so its coded-value guidance refers to example bindings instead of the former extensible bindings. No type/subtype merge is made because the final FHIR-32440 disposition and the later FHIR-44746 decision support the current type/subtype model.

Recommendation:
Keep this source fix. It removes stale conformance wording while preserving the later-approved AuditEvent type/subtype structure; handle FHIR-32439 in its own audit if that issue is selected separately.
