FHIR-30092: Add MedicationKnowledge treatment intent rules

Issue request:
FHIR-30092 was a Published/Persuasive Pharmacy change request for MedicationKnowledge raised against R4 and applied for R5. It requested a new administrationGuideline treatment intent CodeableConcept, a constraint requiring indication when treatmentIntent is used, and an example binding to children of SNOMED CT 262202000 Therapeutic Intents.

Initial application:
Commit 1683ac64141af807564d62a28932d70133142fb3 applied a group of MedicationKnowledge trackers including FHIR-30092 by adding treatmentIntent while simultaneously applying the FHIR-30093/FHIR-28597 refactor from administrationGuideline to indicationGuideline/dosingGuideline. That commit and the current source include MedicationKnowledge.indicationGuideline.dosingGuideline.treatmentIntent as 0..1 CodeableConcept, but they did not include the approved treatmentIntent binding or the indication constraint.

Additional context:
FHIR-30093 explains why the original administrationGuideline wording now maps to MedicationKnowledge.indicationGuideline.dosingGuideline: the model was inverted so indicationGuideline contains indication and dosingGuideline. Pharmacy WGM minutes from January 2021 explicitly record the FHIR-30092 approval with the same constraint and 262202000 example value set. FHIR-33219 is a later no-change MedicationRequest request that notes MedicationKnowledge.treatmentIntent was not yet bound; it does not reverse the FHIR-30092 MedicationKnowledge requirement.

AutoFHIR reconciliation:
This commit adds invariant mkn-1 on MedicationKnowledge.indicationGuideline so any dosingGuideline.treatmentIntent requires indication on the same indicationGuideline, marks the participating indication and treatmentIntent elements with that condition, and adds the approved example binding to the SNOMED CT implicit value set http://snomed.info/sct?fhir_vs=isa/262202000. The edited StructureDefinition is active in source/fhir.ini for the current build.

Recommendation:
Keep this source fix. It completes the published Pharmacy decision without changing the refactored R5/R6 element path or adding unrelated MedicationRequest/FormularyItem behavior; future broader alignment should use separate Jira decisions.
