FHIR-48325: Add descriptive binding strength to CodeSystem source

Issue request:
FHIR-48325 was Applied with resolution Persuasive with Modification. It asked that ElementDefinition bindings be able to carry descriptive guidance when no valueSet is present; the approved resolution added a new BindingStrength code, "descriptive", required valueSet to be omitted when that strength is used, and updated binding terminology guidance.

Initial application:
Commit 4eefbe2059 added the descriptive short text to ElementDefinition.binding.strength, added the ElementDefinition invariant, added the descriptive row to source/terminologies/bindings.xml, and updated OperationDefinition.binding.strength's short display. That application left source/operationdefinition/codesystem-binding-strength.xml without the new CodeSystem concept and had a typo in the invariant's human-readable message.

Additional context:
FHIR-I and Vocabulary/TI minutes from January 2025 confirm the work group chose a new binding strength rather than changing ElementDefinition.binding.strength cardinality, because FHIR versioning did not allow lowering the existing minimum cardinality. source/fhir.ini has OperationDefinition as an active resource entry, and the CodeSystem source lives in that active resource folder alongside other operation terminology resources. FHIR-46350 and FHIR-48479 are related binding/additional-binding documentation decisions, but they concern separate policy and page-organization work and were not decided here.

AutoFHIR reconciliation:
This commit adds the missing descriptive concept to source/operationdefinition/codesystem-binding-strength.xml using the approved definition, keeping the canonical BindingStrength CodeSystem aligned with the terminology spreadsheet, terminology page, and profile short text. It also corrects the ElementDefinition invariant message typo from "ve" to "be" while leaving the already-correct FHIRPath expression unchanged.

Recommendation:
Keep this source fix. No further FHIR-48325 core change is needed unless the work group later decides that OperationDefinition.parameter.binding should also allow valueSet omission for descriptive bindings, which would be a separate semantic decision.
