FHIR-50539: Align DetectedIssue expectedOnsetType binding

Issue request:
FHIR-50539 was an Applied/Persuasive CDS change request for R6 asking to add DetectedIssue.expectedOnsetType as an optional CodeableConcept. The voted resolution required a 0..1 element whose definition distinguishes rapid onset within 24 hours from delayed onset after 24 hours, with an extensible binding to an expected-onset value set including the available SNOMED CT delayed and sudden onset concepts and noting that a rapid-onset concept has been requested.

Initial application:
The issue was initially applied by HL7/fhir PR #3841, with implementation commit 61b717c66b48fbfff6cfdb706e24c08332c645e9 adding DetectedIssue.expectedOnsetType and source/detectedissue/valueset-detectedissue-expected-onset-type.xml. That application added the correct element, cardinality, CodeableConcept type, definition, and SNOMED CT sudden/delayed concepts, but left the element binding as example. Later QA commits added the SNOMED copyright and binding description, and e3c3d0fe2024cda7a6f1da9a3934c1c2bc135804 removed the XML comment that had recorded the requested rapid-onset concept, so the current rendered source no longer carried that part of the resolution.

Additional context:
source/fhir.ini actively includes detectedissue=DetectedIssue and marks DetectedIssue approved for the CDS work group, so the edited StructureDefinition and co-located value set are in current build scope. CDS Confluence agendas show discussion of how to request a SNOMED CT Rapid Onset code on 2025-09-10, a request for documentation of the rapid value on 2025-10-01, and the 2025-10-08 motion approving the FHIR-50539 resolution 15-0-0. Targeted Zulip searches found no conflicting discussion. A later Triaged issue, FHIR-55063, proposes moving several DetectedIssue value sets, including detectedissue-expected-onset-type, to THO; it is not Applied/Published and is not decided here.

AutoFHIR reconciliation:
This commit changes the DetectedIssue.expectedOnsetType binding strength from example to extensible and updates the binding description accordingly. It also moves the rapid-onset pending-code note into the ValueSet description so it remains visible in the rendered value set after the XML comment was removed. It intentionally does not change the canonical to terminology.hl7.org because the THO migration is covered by non-final FHIR-55063 and the current THO site does not publish this value set.

Recommendation:
Keep this commit as-is to complete the source-level FHIR-50539 reconciliation in current FHIR core. Revisit the value set location only through FHIR-55063 or another final terminology/THO decision, because moving the canonical before the external value set exists would be a separate source-of-truth change.
