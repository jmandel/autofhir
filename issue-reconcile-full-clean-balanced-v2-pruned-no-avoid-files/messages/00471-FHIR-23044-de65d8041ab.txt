FHIR-23044: Use MoneyQuantity constraint id prefix

Issue request:
FHIR-23044 was Published/Persuasive as a non-substantive technical correction for the FHIR core datatypes page. It reported that the MoneyQuantity alternate-representation table listed the SimpleQuantity constraint id sqty-1 and asked for the MoneyQuantity constraint id mqty-1 instead.

Initial application:
The current datatypes page source no longer hard-codes the displayed constraint id; it renders [%dt.constraints MoneyQuantity%]. Historical R4B source shows the intended application as a fhir.ini TLA change from MoneyQuantity=mtqy to MoneyQuantity=mqty, but the current master/combined source still had the active MoneyQuantity TLA as mtqy, so generated current content would still use mtqy-1 rather than the published issue's target id.

Additional context:
MoneyQuantity is an active datatype restriction sourced from source/datatypes/quantity.xml, and source/fhir.ini is the active build configuration for datatype abbreviations used in generated invariant keys. Searches of Jira, Zulip, and Confluence found no later or conflicting decision about mqty/mtqy/sqty for MoneyQuantity.

AutoFHIR reconciliation:
This commit changes the active source/fhir.ini TLA entry for MoneyQuantity from mtqy to mqty. The datatypes page's existing MoneyQuantity constraint include and the MoneyQuantity restriction source will then generate the requested mqty-1 constraint id without editing generated history artifacts.

Recommendation:
Keep this commit as-is. A future full publisher build should regenerate the rendered datatypes page and generated StructureDefinition artifacts from the corrected source abbreviation.
