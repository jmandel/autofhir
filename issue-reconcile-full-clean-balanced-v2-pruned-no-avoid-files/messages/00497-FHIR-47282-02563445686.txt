FHIR-47282: Use Subscription Provider actor in notification text

Issue request:
FHIR-47282 is Applied/Persuasive with Modification for R6. It asked to replace wording that made a Subscription resource appear to send notifications with wording that says the Subscription Provider relies on Bundle and SubscriptionStatus for notifications related to active Subscriptions.

Initial application:
The issue was initially applied in git commit 63e647c48f287395f2ee0e9921c9333cc41aac47 and linked from Jira through HL7/fhir#3967. That commit removed the clearly wrong "While active, a Subscription relies..." wording, but the resulting sentence still said "The <code>Subscription</code> provider", formatting Subscription as the resource rather than using the actor term established for this page.

Additional context:
FHIR-47280 was approved in the same Subscriptions block vote and added the Subscription terminology disambiguation glossary. That page defines "Subscription Provider" as the actor that implements the Subscription Framework and sends notifications, and says role names are capitalized. The current source page is in the active Subscriptions framework narrative linked from the core specification and sits alongside active Subscription, SubscriptionStatus, and SubscriptionTopic resources in the build.

AutoFHIR reconciliation:
This commit changes the Boundaries and Relationships sentence in source/subscriptions.html to say "The Subscription Provider relies..." while preserving the existing Bundle and SubscriptionStatus links and the active-subscriptions qualifier.

Recommendation:
Keep this source change. It completes the applied clarification without broadening the issue into a full FHIR-47280 terminology sweep; any remaining lower-case actor references should be handled under a separate terminology reconciliation if needed.
