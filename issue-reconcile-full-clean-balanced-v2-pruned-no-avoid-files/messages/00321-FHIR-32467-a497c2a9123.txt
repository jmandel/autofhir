FHIR-32467: Remove stale AuditEvent entity.type guidance

Issue request:
FHIR-32467 was Published/Persuasive for R5 and asked to remove AuditEvent.entity.type as redundant with AuditEvent.entity.what, noting that a Reference can convey the target resource type and that the DICOM mapping should still express ParticipantObjectTypeCode.

Initial application:
The Jira-tagged commit 1495aa7007 removed the AuditEvent.entity.type element from source/auditevent/structuredefinition-AuditEvent.xml and moved the DICOM ParticipantObjectTypeCode mapping onto AuditEvent.entity.what. Later cleanup removed another entity.type reference from the entity.query comment, but the AuditEvent notes page still told implementers to populate entity.type for OperationOutcome examples.

Additional context:
AuditEvent is an active resource in source/fhir.ini, and source/auditevent/auditevent-notes.xml is the resource notes source used for the current build. Security WG Confluence minutes and the linked Zulip block-vote thread list FHIR-32467 in the September 2021 AuditEvent block vote as Persuasive. Current source no longer defines AuditEvent.entity.type, so the remaining notes paragraph was stale rather than a deliberate later decision.

AutoFHIR reconciliation:
This commit updates the OperationOutcome guidance in auditevent-notes.xml to say that entity.what is a reference to the OperationOutcome and removes the paragraph instructing use of the deleted entity.type element. No StructureDefinition edit was needed because the element removal and DICOM mapping are already present there.

Recommendation:
Keep this commit. It completes the published FHIR-32467 application in the current core source by removing misleading narrative guidance while preserving the existing OperationOutcome example pattern.
