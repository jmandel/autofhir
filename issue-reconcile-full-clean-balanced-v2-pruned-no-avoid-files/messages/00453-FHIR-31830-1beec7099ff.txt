FHIR-31830: Require coded SubstanceDefinition statuses

Issue request:
FHIR-31830 was Published/Persuasive with Modification for R5. It asked that SubstanceSpecification/SubstanceDefinition status elements, including SubstanceDefinition.status, code.status, name.status, and name.official.status, use the standard draft/active/retired/unknown status codes instead of local CodeableConcept values, with 1..1 cardinality and isModifier=true.

Initial application:
No source commit in this checkout explicitly names FHIR-31830 or converts the SubstanceDefinition status elements. The R5 history and current source still carried these fields as optional CodeableConcept elements with preferred PublicationStatus bindings, so the published issue was not fully applied to the active SubstanceDefinition source.

Additional context:
SubstanceSpecification is represented in the current build as SubstanceDefinition; source/fhir.ini lists substancedefinition as an active BRR resource with approved status. BRR minutes record the FHIR-31830 vote, and related BRR status issues FHIR-31780 and FHIR-31790 establish the same required code/PublicationStatus pattern for neighboring medication-definition resources, but those separate artifacts were not decided in this commit.

AutoFHIR reconciliation:
This commit changes the four SubstanceDefinition status elements to required code values bound to ValueSet/publication-status with required strength and common-binding metadata, marks the nested status elements as modifiers, and updates the SubstanceDefinition example to use code-valued active statuses.

Recommendation:
Keep this source fix. It directly completes the applied FHIR-31830 decision for the current build; handle FHIR-31780/FHIR-31790 separately if their remaining medication-definition artifacts still need reconciliation.
