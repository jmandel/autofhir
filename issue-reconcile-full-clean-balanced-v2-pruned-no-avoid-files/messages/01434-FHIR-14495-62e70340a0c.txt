FHIR-14495: Require OperationOutcome for failed transaction

Issue request:
FHIR-14495 was a Published/Persuasive FHIR-core HTTP page change request asking for consistent conformance language around when OperationOutcome can, should, or shall accompany non-2xx responses. The approved resolution made conditional-operation unsupported responses MAY include OperationOutcome, search failures SHALL use 4xx/5xx with OperationOutcome language later refined by follow-up issues, and failed transactions SHALL return a single OperationOutcome instead of a Bundle.

Initial application:
The historical application is git-svn commit 8d445f4fd5 (svn revision 14109), which changed the conditional-operation and search-failure wording but did not update the failed-transaction sentence in the Batch/Transaction Response section to use SHALL. Later commits corrected the conditional delete/create labels and search-failure wording, leaving the failed-transaction conformance verb as the remaining seed-level mismatch.

Additional context:
FHIR-8992 is the earlier same-change-family issue establishing that a failed transaction response is a single OperationOutcome rather than a response Bundle. FHIR-27051 and FHIR-30240 later clarified that search-failure OperationOutcome guidance should not make OperationOutcome mandatory for every generic 4xx/5xx response, which explains the current SHOULD wording for FHIR-aware search failures. Current source/http.html is a checked-in source page for the HTTP/RESTful API and is in the current build source tree.

AutoFHIR reconciliation:
Changed source/http.html in the Batch/Transaction Response section so the failed transaction sentence now says the server SHALL return a single OperationOutcome instead of a Bundle.

Recommendation:
Keep this source fix. It is narrow, restores the approved conformance strength for failed transactions, and does not disturb later clarifications that made OperationOutcome optional or SHOULD-level for other HTTP error contexts.
