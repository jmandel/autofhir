FHIR-19248: Split TOC into summary and detail tabs

Issue request:
FHIR-19248 was Published with resolution Persuasive with Modification. It asked whether the long Code Systems and Value Sets sections in the FHIR core table of contents could be collapsible or removed, and the final resolution was to split the TOC into two tabs: Summary, exposing only the content tree to the second level, and Detail, showing the existing full table of contents.

Initial application:
No git commit that mentions FHIR-19248 was found in the source history, and the current source/toc.html still rendered a single generated <%toc%> table under a "Full Table of Contents" heading. The current CI and R5 rendered TOC pages likewise showed one full tree with the 4.3 Code Systems and 4.4 Value Sets descendants expanded in the detail hierarchy. Older source history shows an unrelated #7785 Documentation/Resources tab split that was removed in 2016, but that does not implement the FHIR-19248 Summary/Detail resolution.

Additional context:
FHIR Infrastructure minutes from 2019-12-02 confirm the 7-0-0 decision to keep a complete TOC while adding a second, shorter view showing only the first two levels. publish.ini lists toc.html as an active special page, so source/toc.html is in current build scope. No Zulip discussion or later Confluence result was found that changed this Jira/minutes decision.

AutoFHIR reconciliation:
This commit updates source/toc.html to introduce Summary and Detail tabs around the generated TOC. The Summary view is built progressively from the generated Detail table by cloning it and removing entries deeper than level 2 based on the leading section number, while the Detail tab preserves the full generated TOC and remains the no-JavaScript fallback.

Recommendation:
Keep this source fix. After the next publisher run, review toc.html visually to confirm the Summary tab opens by default and the Detail tab still contains the complete generated hierarchy.
