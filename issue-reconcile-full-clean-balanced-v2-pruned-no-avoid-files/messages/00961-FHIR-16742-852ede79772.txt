FHIR-16742: Clarify CodeSystem count defaults

Issue request:
FHIR-16742 was Published with a Persuasive with Modification resolution for the CodeSystem.count wording raised against STU3. It asked to avoid saying that compositional code systems count "base (primitive) concepts," because SNOMED CT and UCUM make that system-specific, and resolved to say the system steward specifies the count while adding a comment that the count is usually the total number of enumerated codes published as part of the code system.

Initial application:

In the current build-scope source, source/fhir.ini actively lists codesystem as the CodeSystem resource, and source/codesystem/structuredefinition-CodeSystem.xml already contained the steward-defined definition for CodeSystem.count. However, the requested "usually enumerated codes" comment was absent, and the checked-in source/codesystem/codesystem.svg title still carried the pre-resolution "base (primitive) concepts" wording.
