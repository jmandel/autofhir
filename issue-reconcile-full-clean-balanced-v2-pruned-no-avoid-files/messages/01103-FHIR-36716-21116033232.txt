FHIR-36716: Clarify non-versioned reference matching

Issue request:
FHIR-36716 was a Published FHIR-I change request, resolved Persuasive for R5, asking search.html to clarify that a reference search using a non-versioned relative reference such as Patient/example should also match an instance whose searched Reference contains Patient/example/_history/1234.

Initial application:
The search page was already updated in the same change family: db46f9d2d9 added the FHIR-36715 version-specific reference search syntax, 56eda89182 applied FHIR-36716 by adding the matching note and examples to source/search.html, and 723edd9268 later added the FHIR-22103 References and Versions rule that unversioned reference searches match versioned and unversioned references. The current source retained the intended examples and later rule, but the FHIR-36716 conformance sentence itself remained grammatically broken.

Additional context:
The referenced Zulip thread shows the work group discussion converging on the rule that an unversioned reference search should return resources whose references point to any version of the same resource, while a version-specific search value should match the specified version. FHIR-I minutes from 2022-04-11 record the 15-0-0 Persuasive vote for FHIR-36716. FHIR-22103 is a supporting earlier Provenance/search decision for the same independent-of-version behavior.

AutoFHIR reconciliation:
This commit updates the active search page source, source/search.html, to make the FHIR-36716 conformance sentence parseable and explicit: a non-versioned relative reference search parameter value SHOULD match instances whose searched reference contains a versioned reference to the same target resource. No other search semantics or examples were changed.

Recommendation:
Keep this commit as-is. It preserves the published FHIR-I decision and existing examples while removing ambiguity from the normative/conformance wording; no additional work-group decision is needed for this narrow clarification.
