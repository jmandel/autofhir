Issue request:
FHIR-17986 was a Published/Persuasive STU3 Financial Management change request asking to add PaymentNotice.payee as 1..1 Reference(Practitioner|PractitionerRole|Organization), "The party receiving the payment."

Initial application:
The broad 2018 application commit f369c813fb added PaymentNotice.payee to the PaymentNotice spreadsheet and example, including the requested target types and payee description, but the spreadsheet row used 0..1. The 2021 new-build conversion preserved that optional cardinality in the current StructureDefinition source.

Additional context:
PaymentNotice is an active current-build resource in source/fhir.ini. Current source already had the requested payee element, target profiles, example content, and later FHIR-17988 summary flag, but the min cardinality still conflicted with the final FHIR-17986 request. FHIR-45962 is a later Triaged R6 request to broaden payee/recipient target types and add search parameters; it is not final enough for this applied/published reconciliation and does not supersede the FHIR-17986 cardinality.

AutoFHIR reconciliation:
Updated source/paymentnotice/structuredefinition-PaymentNotice.xml so PaymentNotice.payee has min 1 and therefore remains 1..1 with the existing max 1 and requested target profiles.

Recommendation:
Keep this source fix unless the work group intentionally wants PaymentNotice.payee optional; in that case, record that as a new final Jira decision. Do not fold in the broader FHIR-45962 person-target changes until that issue is final and applied.
