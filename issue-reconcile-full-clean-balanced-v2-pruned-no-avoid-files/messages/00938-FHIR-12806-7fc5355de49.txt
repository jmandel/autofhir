FHIR-12806: Add centimeter to Distance units

Issue request:
FHIR-12806 was Published/Persuasive with Modification for DSTU2. It requested actual unit bindings for the Quantity-derived Age, Duration, and Distance constraints, with extensible common-unit bindings and maximum value set bindings. The accepted modification excluded imperial distance units and required maximum value sets to use UCUM canonical properties rather than enumerating every code.

Initial application:
The original application is git commit 61ad12d35fc9ba1cbb1c1905840dacd7d3f46861, imported from svn revision 12715 with subject "#12806 - bindings on quantity variations". It added AgeUnits, DurationUnits, and DistanceUnits extensible bindings and introduced all-time/all-distance maximum value sets. The DistanceUnits value set, however, omitted centimeter even though the issue's proposed metric distance set included nm, um, mm, cm, m, and km and the accepted modification only excluded imperial units.

Additional context:
Current build-scope evidence shows Distance is an active datatype, DistanceUnits is an extensible binding to valueset-distance-units with maximum valueset-all-distance-units, and valueset-all-distance-units uses the UCUM canonical=m filter. Later FHIR-40607 work adjusted Duration display values and all-time expansion behavior but did not reverse or narrow the Distance metric common-unit request. Jira, Zulip, and Confluence searches found no later decision intentionally removing cm from DistanceUnits.

AutoFHIR reconciliation:
This commit adds UCUM code cm with display "centimeters" to source/datatypes/valueset-distance-units.xml, preserving the existing metric-only common Distance units and leaving the Age, Duration, and maximum canonical-filter bindings unchanged.

Recommendation:
Keep this source fix. It completes the applied FHIR-12806 Distance binding without reopening the excluded imperial units or making unrelated duration-display changes already covered by FHIR-40607.
