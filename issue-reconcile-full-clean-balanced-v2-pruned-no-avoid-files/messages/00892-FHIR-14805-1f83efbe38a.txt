FHIR-14805: Move provider follow-up note to appointment type

Issue request:
FHIR-14805 was a Published/Not Persuasive with Modification PA change request asking for an Appointment type code for practitioner-to-practitioner discussions. The work group decided not to add a new code because Appointment.appointmentType has a preferred binding that permits local or alternate value sets, but directed that appointmentType should note that the existing FOLLOWUP code may be appropriate for provider-to-provider appointments about a patient previously seen.

Initial application:
The issue appears to have been applied by historical git commit 44f50d8edb765049e92019be6595649ba3f284b8, whose GF#14805 message said it added a clarifying comment to Appointment.serviceType. That commit placed the FOLLOWUP guidance on serviceType instead of appointmentType, and later source refactors retained that placement in source/appointment/structuredefinition-Appointment.xml.

Additional context:
Appointment is an active resource in source/fhir.ini. The current Appointment.appointmentType element is bound, with preferred strength, to the v2-0276 appointment type value set where FOLLOWUP belongs; current two-doctor Appointment examples also use appointmentType FOLLOWUP. FHIR-15023 is the same Appointment example family and has already been represented on the combined branch, and FHIR-22696 later refined the patient-not-present model by adding Appointment.subject without changing the appointmentType guidance. Zulip and Confluence searches found no conflicting community direction.

AutoFHIR reconciliation:
This commit moves the existing provider-to-provider FOLLOWUP comment from Appointment.serviceType to Appointment.appointmentType. This keeps the already-approved wording but attaches it to the element and preferred binding named by the Jira resolution and used by the examples.

Recommendation:
Keep this source fix. It corrects a historical application placement error without adding a new code, changing binding strength, or reopening the later subject/participant modeling decisions.
