FHIR-17617: Add missing resource category metadata

Issue request:
FHIR-17617 was Published/Persuasive for STU3 and asked for a core StructureDefinition extension indicating the display group/category of core resource definitions so clients such as Forge can mirror the official resource list grouping.

Initial application:
The issue was applied in SVN revision 14551, now Git commit 687407e2959b695e71aeea5a80596c5b225b36da, which added resource-category capture around the resource list categories. Current source already has the structuredefinition-category extension on almost all active resource definitions, and the extension definition itself has since moved out of core into the FHIR Extension Pack.

Additional context:
Current source/fhir.ini lists NutritionIntake and DeviceAssociation as active core resources, and source/resourcelist.html places them under Clinical.Care Provision and Clinical.Request & Response respectively. Both current StructureDefinition XML files were missing the same structuredefinition-category extension used by the rest of the active resource set. No Zulip or Confluence search result was found that narrows, reverses, or conflicts with the Jira/source interpretation.

AutoFHIR reconciliation:
Added structuredefinition-category extensions to NutritionIntake and DeviceAssociation, matching their current official resource index categories. This keeps the authoritative resource profile metadata complete for all active fhir.ini resources while leaving the Extension Pack definition untouched.

Recommendation:
Keep this source fix. Follow-up is only needed if the work group later changes the resource index categories themselves; otherwise the metadata now aligns with the active core build and the current Extension Pack definition.
