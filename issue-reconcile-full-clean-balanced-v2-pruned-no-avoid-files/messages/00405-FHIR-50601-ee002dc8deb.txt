FHIR-50601: Make DiagnosticReport recommendation a Reference

Issue request:
FHIR-50601 was Applied/Persuasive with Modification for R6 after the reporter noted that DiagnosticReport.recommendation was a CodeableReference with no value set for its codeable side. The OO decision was to change the element from CodeableReference to Reference and constrain the reference targets to request-like follow-up resources.

Initial application:
FHIR-45290 originally added DiagnosticReport.recomendation as CodeableReference(Any). The FHIR-50601 implementation commit 8668f53 narrowed the targetProfile list from Resource to specific follow-up resources, but it left the datatype as CodeableReference. FHIR-54163 later fixed the element spelling to DiagnosticReport.recommendation.

Additional context:
OO WGM minutes for 2025-05-12/15 record the FHIR-50601 motion as "change the datatype to reference". Later commit e073fb45 removed ImmunizationRecommendation from the active core resource list and from DiagnosticReport references, so this reconciliation does not restore that now-out-of-build target. The active DiagnosticReport source is in scope through source/fhir.ini.

AutoFHIR reconciliation:
Changed DiagnosticReport.recommendation from CodeableReference to Reference in the authoritative StructureDefinition source and updated the checked-in DiagnosticReport SVG so the resource diagram no longer shows the stale CodeableReference type.

Recommendation:
Keep this commit. It completes the explicit FHIR-50601 datatype decision while preserving the current targetProfile list after later resource-scope changes. Any broader expansion of recommendation targets, such as adding other request-pattern resources not present in the final Jira-applied list, should be handled as separate OO work.
