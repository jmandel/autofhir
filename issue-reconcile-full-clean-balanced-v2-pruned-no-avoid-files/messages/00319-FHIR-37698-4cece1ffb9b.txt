FHIR-37698: Correct device participant example

Issue request:
FHIR-37698 was an Applied CDS change request asking how an ActivityDefinition can represent a device to be used, such as for medication administration. The accepted resolution said this can be done with typeReference for a specific Device, or a DeviceDefinition resolved during apply, and asked for an example illustrating the usage.

Initial application:
The issue appears to have been applied by commit 2d711ff3b0b74bdd990e87221db5c7ed2c305d8d from PR #3914, which added explanatory text to the active Clinical Reasoning definitional resources page. That text was present on the combined branch, but it used the non-existent ActivityDefinition path action.typeCanonical and showed only a bare typeCanonical fragment.

Additional context:
The current ActivityDefinition source models device participants through ActivityDefinition.participant: typeReference can target Device, while typeCanonical can target DeviceDefinition. Later participant modeling work, including FHIR-44034 and broader DeviceDefinition canonical-resource discussions, means the current DeviceDefinition example should use participant.typeCanonical rather than re-adding DeviceDefinition to participant.typeReference.

AutoFHIR reconciliation:
This commit corrects the active Clinical Reasoning narrative example so it points to participant.typeReference for a specific Device and participant.typeCanonical for a DeviceDefinition, and shows the typeCanonical inside a participant with type="device". The page is in build scope through source/hierarchy.xml and the Clinical Reasoning module links.

Recommendation:
Keep this source fix as-is. It preserves the applied issue's intent while aligning the example with the current ActivityDefinition structure and avoiding a broader, unresolved sweep of DeviceDefinition canonical-reference modeling.
