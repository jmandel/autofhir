FHIR-53092: Remove remaining Specimen accessionIdentifier uses

Issue request:
FHIR-53092 is Applied/Persuasive for R6. It asked OO to remove the trial-use Specimen.accessionIdentifier element, add guidance that accession identifiers use Identifier.type code ACSN on Specimen.identifier, remove the spm-2 constraint and accession search parameter, and clean examples that still carried the removed element.

Initial application:
The issue was initially applied in HL7/fhir PR #3791. Commit d34d0958debfb4fefda774fc79f0d3236fbecfce removed Specimen.accessionIdentifier, spm-2, Specimen-accession, and the listed source/specimen examples, while the Jira comment cited merge commit d726f88c688f34d9e59087c6fee92a7e2a5a7b36. That application did not touch active Specimen instances outside source/specimen or the Library model-info examples.

Additional context:
source/fhir.ini lists diagnosticreport, library, specimen, and specimendefinition as active resources, so their examples and Library content are current-build inputs. The remaining fhir.ini Specimen.accessionIdentifier entries are R4/R5-to-R6 change-map notes and intentionally document migration to Specimen.identifier, not current element definitions. OO Confluence minutes and the Jira vote confirm the R6 ballot/block-vote context and do not add a conflicting decision.

AutoFHIR reconciliation:
Removed remaining Specimen.accessionIdentifier elements from the DiagnosticReport GHP example bundle and the SpecimenDefinition $apply response example source, where each specimen already carries the accession number as an ACSN-typed identifier. Removed accessionIdentifier from the FHIR and QUICK model-info Library content and refreshed the embedded FHIR model-info attachment so the example model metadata no longer exposes a removed Specimen element.

Recommendation:
Keep this source fix as-is. If a future model-info generator is run, ensure it continues to derive Specimen from the current StructureDefinition and does not reintroduce accessionIdentifier.
