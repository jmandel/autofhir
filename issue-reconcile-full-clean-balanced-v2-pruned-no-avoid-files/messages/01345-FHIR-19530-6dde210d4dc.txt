FHIR-19530: Clarify Questionnaire expression name collisions

Issue request:
FHIR-19530 was Published/Persuasive for FHIR core and asked that variables created by the Questionnaire variable and questionnaire-context mechanisms document how they are referenced from FHIRPath, including that they use the normal percent-prefixed variable syntax and that name collisions in the same scope are errors.

Initial application:
No core commit explicitly tagged FHIR-19530 was found. The Jira comment points to HL7/sdc commit c5e291e, which applied the requested percent-prefixed access and collision-error wording to the SDC expressions page. Later core work for FHIR-33539 added SDC-derived QuestionnaireResponse FHIRPath guidance to core, including percent-prefixed access, but omitted the collision-error rule.

Additional context:
The active core FHIRPath page is in build scope through publish.ini and links readers to QuestionnaireResponse for resource-specific FHIRPath variable guidance. QuestionnaireResponse is an active resource in source/fhir.ini. The historical questionnaire-context wording is now represented in current guidance by the SDC launchContext name; SDC guidance and the later FHIR-33539 Zulip discussion both describe these named expressions as variables injected into FHIRPath evaluation.

AutoFHIR reconciliation:
This commit updates the build-scope QuestionnaireResponse notes to restore the missing collision rule: same context names defined within the same containing element are an error, while descendant items can define the same name for their own scope.

Recommendation:
Keep this commit as-is. It completes the FHIR-19530 core clarification without duplicating the detailed SDC examples or moving unrelated SDC-only expression guidance into core.
