FHIR-34195: Set MedicationRequest missing-value meaning

Issue request:
FHIR-34195 was a Published/Persuasive Pharmacy change request for R5 asking that the non-mandatory boolean MedicationRequest.reported have a meaningIfMissing. The approved resolution was to say that, if missing, the request is assumed to be the original record and not reported.

Initial application:
Commit 886f421a86f818e31e5eb518a478fcffae6c71db added the approved sentence to MedicationRequest.reported, but it added it as an ElementDefinition.comment rather than the structured missing-value field. That made the human-readable text visible, but did not encode the Jira's requested missing-value semantics in ElementDefinition.meaningWhenMissing.

Additional context:
MedicationRequest is active build input in source/fhir.ini, assigned to Pharmacy, and the current fhir.ini R5/R6 mapping records MedicationRequest.reported[x] as MedicationRequest.isRecordOfRequest. Later commit 7ede8c1b57bc3c9238e2c3c8d530b7697ad3a39d for FHIR-49863 renamed reported to isRecordOfRequest and preserved the same sentence on the renamed element. FHIR-49863 is only Resolved - change required, so it is treated here as current-source context rather than a related issue decision. Focused Zulip and Confluence searches found no community evidence that changed the Jira/source conclusion.

AutoFHIR reconciliation:
Moved the approved missing-value sentence on source/medicationrequest/structuredefinition-MedicationRequest.xml from comment to meaningWhenMissing on MedicationRequest.isRecordOfRequest. This keeps the current element name and approved text while encoding the missing-value meaning in the field intended for optional element semantics.

Recommendation:
Keep this source fix. It completes the applied FHIR-34195 decision in the active MedicationRequest StructureDefinition source without reopening the later isRecordOfRequest naming/modifier questions.
