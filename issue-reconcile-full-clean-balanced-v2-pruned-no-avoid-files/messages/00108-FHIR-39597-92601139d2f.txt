FHIR-39597: Remove remaining Consent base-provision wording

Issue request:
FHIR-39597 was Published/Persuasive for FHIR-core Consent. It requested eliminating provision zero, moving Consent.provision.type to Consent.decision, changing Consent.provision to 0..*, and adjusting notes so the base permit/deny decision is no longer described as a root or zero-th provision.

Initial application:
The issue was initially applied through PR #2616. Commit e8f77ac72e93779d5ff23eda48ac3445f8a0e64c moved Consent.provision.type to Consent.decision, changed Consent.provision from 0..1 to 0..*, and updated Consent examples and introductory text. Commit 41247a9aec0715d6216405dbdcd9367fe0d1a230 then revised the Provisions narrative to describe Consent.decision as the default decision. The PR was merged as cdd3f8411032f745848622236e70b0129ba83bce.

Additional context:
Consent is an active current-build resource in source/fhir.ini. The current StructureDefinition and Provisions narrative already contain Consent.decision and the 0..* provision cardinality, and current source no longer contains provision-zero/root-provision language except for two authoritative stale references. FHIR-34322 is the earlier same-family provision-model documentation issue whose root-provision wording was superseded by FHIR-39597. FHIR-55728 is a later R6 Resolved - change required issue about making Consent.decision mandatory when provisions exist; because it is not Applied or Published in this default run, it is context only. A Zulip prompt announced the proposed FHIR-39597 structural change, and no Confluence reference was found.

AutoFHIR reconciliation:
This commit updates source/consent/consent-notes.xml so the Optimal Searching guidance directs readers to Consent.decision for the base permit/deny decision associated with Consent.policyBasis. It also updates source/consent/structuredefinition-Consent.xml so Consent.provision.period no longer says consent-wide effective time belongs in a base provision; the comment now points to Consent.period for the consent-wide period and treats provision.period as provision-specific. Generated-looking consent.svg text was not edited.

Recommendation:
Keep this commit as the bounded FHIR-39597 source fix. If the later FHIR-55728 decision is brought into this branch, handle it separately because it changes conditional cardinality behavior rather than merely removing provision-zero remnants.
