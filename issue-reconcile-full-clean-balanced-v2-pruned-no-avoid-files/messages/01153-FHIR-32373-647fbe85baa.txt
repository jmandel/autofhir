FHIR-32373: Correct DataRequirement valueFilter types

Issue request:
FHIR-32373 was a Published/Persuasive with Modification FHIR-core change request for R5 DataRequirement. It asked to add a valueFilter element modeled after codeFilter/dateFilter, with path, searchParam, and value[x] choices for Quantity, string, boolean, integer, Range, Ratio, and originally SampledData; the final resolution accepted the change except that SampledData should not be a value choice.

Initial application:
The source was first changed by git commit 9d8ab07d9596453036e89cc2915f82e6d9cda56c, "J#32373: Added valueFilter element to DataRequirement". That commit added DataRequirement.valueFilter and related path/searchParam/comparator/value[x] rows in source/datatypes/datarequirement.xml, but the value[x] row copied the dateFilter type list and short description, leaving valueFilter.value[x] constrained to dateTime, Period, and Duration instead of the approved non-code/non-date value types.

Additional context:
source/fhir.ini actively lists DataRequirement as a datatype, maps datarequirement to the metadatatypes page, and marks DataRequirement normative, so source/datatypes/datarequirement.xml feeds the current build. The FHIR Extension Pack cqf-valueFilter definition uses boolean, string, integer, Quantity, Ratio, and Range, matching the FHIR-32373 requested set after removing SampledData. Later FHIR-53984 is a Resolved - change required R6 issue that confirms the date/time type list is a mistake and proposes further R6 work, including RatioRange and a path/searchParam invariant, but that issue is not Applied/Published and is left for separate reconciliation. FHIR-I May 2022 minutes record the FHIR-32373 persuasive vote, and direct Zulip/Confluence searches found no conflicting community evidence.

AutoFHIR reconciliation:
Updated the active DataRequirement spreadsheet so DataRequirement.valueFilter.value[x] allows boolean|string|integer|Quantity|Ratio|Range and its short description names those types. This commit intentionally leaves dateFilter unchanged and does not add RatioRange or new invariants from FHIR-53984, because those changes belong to the later unresolved application item rather than this published R5 issue.

Recommendation:
Keep this source-changing commit. It completes the missing FHIR-32373 semantic correction in current build scope; handle FHIR-53984 separately if the R6 RatioRange/invariant resolution is brought into an Applied/Published or broader reconciliation run.
