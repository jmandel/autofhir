FHIR-40770: Align CodeSystem displayLanguage validation

Issue request:
FHIR-40770 was an Applied/Persuasive Vocab change request asking for the $validate-code displayLanguage input parameter to repeat so validation can accept a display that matches any one requested language. The Jira resolution says to change displayLanguage from 0..1 to 0..* and replace the old description with text clarifying that a display only needs to match one displayLanguage for validation to return true.

Initial application:
The Jira-tagged implementation commit 39f96b21ce8d65b5b086b3ee61a455e47a359a98 applied the cardinality and wording update only to source/valueset/operationdefinition-ValueSet-validate-code.xml. The current ValueSet operation source already has max="*" and the new documentation, but the parallel CodeSystem $validate-code OperationDefinition still had max="1" and the old wording.

Additional context:
Jira comments and the September 2023 Terminology Infrastructure minutes show the work group explicitly considered CodeSystem alongside ValueSet and voted 21-0-0 that repeated displayLanguage should mean validation succeeds when the display matches at least one requested language. CodeSystem and ValueSet are active resources in source/fhir.ini, and the CodeSystem operation list references OperationDefinition/CodeSystem-validate-code, so the edited XML is in current build scope. A later Zulip discussion and submitted FHIR-57437 discuss broader Accept-Language/fallback semantics but are not final decisions that reverse FHIR-40770.

AutoFHIR reconciliation:
This commit applies the already-approved FHIR-40770 displayLanguage cardinality and wording to CodeSystem/$validate-code so both validate-code operation definitions convey the same display validation semantics.

Recommendation:
Keep this source fix. Future work on Accept-Language syntax, fallback warnings, or reverting displayLanguage cardinality should proceed through a separate final Vocab decision rather than blocking this applied reconciliation.
