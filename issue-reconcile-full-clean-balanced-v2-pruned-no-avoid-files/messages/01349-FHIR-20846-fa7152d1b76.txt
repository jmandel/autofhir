FHIR-20846: Align StructureMap factory FHIRPath references

Issue request:
FHIR-20846 was Published/Persuasive with Modification for FHIR-core StructureMap and the mapping-language page. It asked to align StructureMap target transform functions with FHIRPath by documenting that StructureMap execution needs integrated FHIRPath support, cross-checking transform functions against FHIRPath functions, and defining factories for common FHIR datatypes on the FHIRPath page.

Initial application:
Git commit 662229e4296562444046aeac9c485f03292d1a34 applied the issue for R5 by adding the FHIRPath implementation requirement to the mapping language and StructureMap introduction, adding a FHIRPath-equivalent column to the target-transform table, adding the FHIRPath Type Factory section, and adding a fhirpath property to CodeSystem/map-transform. That application left several factory-transform CodeSystem properties as n/a even though the mapping-language table points to the matching %factory methods, and it introduced small but implementer-visible factory documentation defects in the same added text.

Additional context:
The active build includes source/hierarchy.xml entries for fhirpath.html, mapping-language.html, and the StructureMap resource, with source/fhir.ini listing StructureMap as an active resource. Later FHIR-40645 work changed the same mapping-language table and transform CodeSystem for date/time operations but did not supersede the FHIR-20846 factory alignment. FTS-safe Zulip and Confluence searches found only generic block-vote/list mentions of FHIR-20846 and no substantive community direction that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit completes the applied alignment by making the map-transform CodeSystem fhirpath properties for cc, c, qty, id, and cp match the factory equivalents already documented on the mapping-language page. It also fixes the directly adjacent factory documentation defects introduced by the same issue application: broken factory links in the mapping-language table, the quantity text typo, incorrect HumanName.family wording, an invalid Coding example, Extension factory casing, and misleading general factory examples.

Recommendation:
Keep this source-changing commit. It preserves the existing FHIR-20846 design while making the active narrative and conformance source consistently point implementers to the FHIRPath factory API. Future work should only revisit the exact factory signatures if FHIR-I changes the draft factory API itself.
