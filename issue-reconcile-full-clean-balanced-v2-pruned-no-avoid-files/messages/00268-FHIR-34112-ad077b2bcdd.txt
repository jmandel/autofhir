FHIR-34112: Align collect-data request examples

Issue request:
FHIR-34112 was an Applied/Persuasive with Modification CQI change request for R6. It asked to clarify the Measure/$collect-data measure input when invoked on the Measure type versus a Measure instance; the final resolution broadened that request to align base $collect-data with the DEQM pattern, including measure input/output handling and examples.

Initial application:
The issue was applied by PR HL7/fhir#3440 and commit 70da68c569ba2bfa3e43bf9869e844059b0f4841, which added DEQM-style measureId, measureIdentifier, measureUrl, measureResource, and measure inputs, changed the operation to allow instance invocation, and added request examples using those parameters. Later applied commits for FHIR-51066, FHIR-55967, and FHIR-40422 changed the active operation signature to type-level only with required repeatable measureUrl plus reporter/location and multi-subject inputs, but the request example include still advertised removed parameters.

Additional context:
Measure is active in source/fhir.ini, and source/measure/operationdefinition-Measure-collect-data.xml includes $collect-data-request.txt as the built request example, so the edited file is in build scope. FHIR-49856 records the related CRMI adoption of the R6/DEQM simplified single canonical URL pattern. FHIR-51066, FHIR-55967, and FHIR-40422 are already represented on the combined branch and are treated here as later context rather than additional decisions.

AutoFHIR reconciliation:
Updated source/measure/$collect-data-request.txt so every displayed GET example uses parameters declared by the current Measure/$collect-data OperationDefinition. The examples now use measureUrl instead of removed measureId/measureIdentifier inputs, and use reporter/location instead of removed organization/practitioner inputs. No OperationDefinition change was made because the current signature reflects later applied decisions.

Recommendation:
Keep this source fix. It preserves the later R6/DEQM operation signature while removing stale examples left from the original FHIR-34112 application; no separate source change is recommended for the already-decided related trackers.
