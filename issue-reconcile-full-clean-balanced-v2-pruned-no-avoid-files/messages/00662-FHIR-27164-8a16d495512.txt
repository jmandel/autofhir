FHIR-27164: Correct Practitioner user identity guidance

Issue request:
FHIR-27164 was Applied/Persuasive with Modification for R6. It asked for guidance on representing user identities in FHIR resources: add Administration module guidance, discourage using .telecom as the formal user identity location, and add identifier guidance using type='USER' on Patient, RelatedPerson, Practitioner, and Person, with SMART fhirUser context that can also refer to PractitionerRole.

Initial application:
The Jira-tagged source commit f0c1061b32 added the Administration module section and most resource comments, but the Practitioner identifier guidance was accidentally inserted on Practitioner.qualification.identifier instead of Practitioner.identifier. Current source already contains the Patient, Person, RelatedPerson, Practitioner.telecom, Administration module, and later Security module guidance.

Additional context:
FHIR-40405 records the related FHIR-I decision to define a USER Identifier.type code rather than a core Identifier profile, and the January 2025 PA minutes record the final 8-0-0 motion for FHIR-27164 plus creation of the Security follow-up FHIR-50838. FHIR-50838 later added Security module guidance that formal user identity mapping belongs in .identifier while values such as email may also appear in .telecom for communication purposes. PractitionerRole was kept as context rather than edited here because FHIR-27164's final resource-level identifier comment request names Practitioner, not PractitionerRole.identifier.

AutoFHIR reconciliation:
Moved the FHIR-27164 user identity comment from Practitioner.qualification.identifier to the active, resource-level Practitioner.identifier element. This fixes the implementer-facing semantic mistake without adding broader guidance beyond the approved issue scope.

Recommendation:
Keep this commit. The correction aligns the active Practitioner StructureDefinition source with the Jira disposition and avoids misleading implementers into placing user identifiers on qualification identifiers. Any broader PractitionerRole or Security-page refinements should remain with their own trackers, especially FHIR-50838 or future WG decisions.
