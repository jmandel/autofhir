FHIR-38868: Align Request text with groupIdentifier

Issue request:
FHIR-38868 was a Published/Persuasive FHIR-core Request-pattern correction for R5. It asked that the compound-request text in section 12.4.10.1 stop referring to Request.requisitionId and use Request.groupIdentifier instead.

Initial application:
The original Jira-tagged source commit 8fa6462acf changed the explicit Request.requisitionId token in source/request/request-spreadsheet-notes.xml to Request.groupIdentifier. That left the same active notes section with element-like requisitionId prose and a code-styled requisitionId reference, so the applied correction was incomplete for readers of the Request pattern page.

Additional context:
source/fhir.ini lists request as an active logical pattern, and source/request/request-spreadsheet.xml defines Request.groupIdentifier with requisition as a business synonym/context rather than as a separate Request.requisitionId element. FHIR Workflow minutes for 2022-11-21 record the issue as Persuasive, and searches found no Zulip or later Jira/Confluence evidence changing the intended correction.

AutoFHIR reconciliation:
Updated source/request/request-spreadsheet-notes.xml so the compound-request option is described as a shared group identifier and the remaining element-like requisitionId references now say groupIdentifier or group identifier. The wording still preserves requisition/prescription/form identifiers as the business concept represented by Request.groupIdentifier.

Recommendation:
Keep this source change as-is. No external-repository work or further related Jira decision is needed for this bounded correction.
