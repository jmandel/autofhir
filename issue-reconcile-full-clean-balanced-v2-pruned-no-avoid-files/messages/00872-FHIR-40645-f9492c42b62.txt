FHIR-40645: Define StructureMap date-time transforms

Issue request:
FHIR-40645 is Applied/Persuasive with Modification for the FHIR-core mapping-language page. It asked to replace the undocumented dateOp target transform parameters with defined date/time parsing operations: separate target-type transforms such as toDate, toTime, toDateTime, plus a parallel Unix-offset family, using a Java-style format argument constrained to features shared with .NET.

Initial application:
The predecessor FHIR-23937 was Published for R5 but explicitly deferred the actual dateOp parameter definition to a new R6 tracker; git commit 8d9c57d215 only adjusted nearby FHIRPath-context wording. FHIR-40645 was then applied by PR HL7/fhir#3967, including commit dbd826d767, which removed the narrative dateOp placeholder and added toDateTime/unixToDateTime, toDate/unixToDate, and toTime/unixToTime rows in source/mapping-language.html. Commit ed4b1fdd32 followed with mapping-language consistency edits adding the source argument, but the required StructureMap transform CodeSystem still exposed only the obsolete dateOp concept and the narrative still omitted the instant target type named in the original request and WGM minutes.

Additional context:
FHIR-I WGM minutes for 2024-01-30 record the same issue scope: converting arbitrary-formatted strings into date, time, dateTime, or instant values, using a format string, defining individual functions instead of a return-type parameter, and covering integer Unix-offset formats. The Zulip thread linked from Jira supplied the community discussion on source formats and confirmed the FHIR Mapping Language use case. The edited files are in build scope: source/hierarchy.xml lists mapping-language.html as the Mapping Language page, source/fhir.ini has the StructureMap resource active, StructureMap.group.rule.target.transform has a required binding to ValueSet/map-transform, and that value set includes the complete CodeSystem/map-transform.

AutoFHIR reconciliation:
This commit completes the applied issue by adding toInstant and unixToInstant to the Mapping Language transform table and by replacing the stale CodeSystem dateOp placeholder with the eight concrete date/time transform codes and their parameters: toDateTime, unixToDateTime, toInstant, unixToInstant, toDate, unixToDate, toTime, and unixToTime. It also fixes the directly adjacent typo in the newly added date/time format-code paragraph.

Recommendation:
Keep this source-changing commit. It aligns the narrative and required conformance CodeSystem with the Applied Jira resolution and WGM vote; revisit only if FHIR-I intentionally wants to exclude instant from the date/time transform family despite the issue/minutes naming it.
