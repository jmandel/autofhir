FHIR-23843: Correct EpisodeOfCare careTeam reference

Attribution note: surfaced while reviewing FHIR-6957, but direct Jira backing for this change is FHIR-23843.

Issue request:
FHIR-6957 was a Published/Persuasive with Modification PA change request from the 2015 May ballot asking to change the old EpisodeOfCare.CareTeam.member cardinality from 0..1 to 0..*, because an episode can involve multiple care teams. The final resolution did not keep the nested EpisodeOfCare team-member backbone; it said the functionality is now covered by the CareTeam resource and that EpisodeOfCare can reference multiple CareTeam resources.

Initial application:
No explicit FHIR-6957 source commit was found in the current git history or source. The current build already has active CareTeam and EpisodeOfCare resources, EpisodeOfCare.careTeam is 0..* Reference(CareTeam), and CareTeam supports multiple participants, so the cardinality model requested by the issue has been structurally applied through the CareTeam resource. A later FHIR-23843 commit renamed EpisodeOfCare.team to EpisodeOfCare.careTeam, but one active EpisodeOfCare.managingOrganization comment still referenced the old EpisodeOfCare.team path.

Additional context:
FHIR-23843 is already represented on the combined branch, so this reconciliation does not publish a duplicate FHIR-23843 commit. FHIR-44683 later confirmed that repeating EpisodeOfCare.careTeam is intentional and added explanatory text describing different teams by CareTeam.period or CareTeam.category. Focused Zulip and Confluence searches found no direct FHIR-6957 discussion or conflicting community evidence; Confluence did surface later PA discussion around CareTeam/EpisodeOfCare work, consistent with the current model.

AutoFHIR reconciliation:
Updated the active EpisodeOfCare source comment on EpisodeOfCare.managingOrganization to reference EpisodeOfCare.careTeam instead of the retired EpisodeOfCare.team name. This keeps the current built specification aligned with the FHIR-6957 resolution that EpisodeOfCare references multiple CareTeam resources, while leaving the authoritative 0..* EpisodeOfCare.careTeam cardinality and CareTeam participant modeling unchanged.

Recommendation:
Keep this commit. The remaining source now consistently points implementers to the current EpisodeOfCare.careTeam element; no separate FHIR-23843 commit should be created in this run because that issue already has an Issue-Reconcile-Key commit on the combined branch.
