FHIR-15879: Use display extension for canonical rendering

Issue request:
FHIR-15879 was Published with resolution Persuasive with Modification. It asked how canonical references should carry a human-readable name for rendering when the URL alone is not appropriate. The final decision was to define a common extension for canonical references and add Canonical URLs rendering guidance that references the extension, discusses lookup and stale-narrative challenges, and explains why canonical uses an extension while Reference has a display element.

Initial application:
The Jira application comment points to svn revision 13877, represented in git as 48f836df16eaf44ee379e6160e479843703fc01f. That commit added the current Rendering References in Resource Narratives section and covered reference resolution and stale narrative concerns, but it told canonical users to use the Rendered Value extension. Later source already incorporated the canonical display extension in the primitive datatype row through the FHIR-32897 reconciliation, so the remaining core source problem was this stale rendered-value recommendation in source/references.html.

Additional context:
FHIR-40915 was Published / Persuasive for the Extension Pack and explicitly concluded that rendered-value should not include canonical because canonical display already exists. Extension Pack commit c72b0548f8b06e830675ec35d7fc101ded26e65a removed canonical from rendered-value, while the display extension remains scoped to canonical. The source/references.html page is active build source: source/documentation.html links to references.html and source/fhir.ini maps Reference and CodeableReference type pages to references.

AutoFHIR reconciliation:
Updated source/references.html so the canonical rendering guidance points to the display extension, explains that canonical remains a primitive URL-valued type rather than a complex reference, and aligns the extension's purpose with Reference.display. No Extension Pack definitions were changed because the current external definitions already reflect the later rendered-value/display decision.

Recommendation:
Keep this source fix. It resolves the stale core narrative guidance and aligns the current build with the original FHIR-15879 intent plus later FHIR-32897 and FHIR-40915 decisions; no additional core follow-up is needed.
