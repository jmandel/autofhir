FHIR-53917: Complete Provenance removal targeting rules

Issue request:
FHIR-53917 was Applied/Not Persuasive with Modification for FHIR-core Provenance. The Security WG rejected relaxing Provenance.target for deletes and instead decided that removals must be represented in both Provenance.target and Provenance.entity.what, with an invariant tying removal entities back to targets, target definition wording that includes removals, a renamed removal/replace section, and delete/replace examples.

Initial application:
The issue was initially applied through HL7/fhir#4028, merged as 66cbbee5f9e678f6c702807682f9bf0a064e9456. The Jira-tagged commit bb74e6feffedb048c2a7339e6203b7d2201b10fa renamed the removal section and changed the delete example entity role to removal; later commits in the same PR added the correction replacement example and example list entry. That application left the active Provenance StructureDefinition target definition saying only generated or updated, did not add the approved invariant, and left the replacement example targeting only the replacement resource rather than both the removed and replacement resources.

Additional context:
The Zulip discussion linked from Jira shows the consensus concern that target should remain queryable as the set of resources affected by create, update, or delete activity. The Security WGM agenda/minutes page records FHIR-53917 as resolved. source/fhir.ini actively lists provenance=Provenance, and source/provenance/implementationguide-Provenance-core.xml references the relevant-history profile, so the edited StructureDefinition, examples, mapping-exception source, notes, and profile are current build inputs. Later Provenance wording reconciliations such as FHIR-55409/FHIR-55410 do not conflict with this removal/target rule.

AutoFHIR reconciliation:
This commit completes the applied decision by updating Provenance.target and adjacent Provenance.patient wording to include removed resources, adding invariant prov-5 plus a negative invariant test, aligning the W3C map and mapping-exception source, making the correction replacement example target both the removed and replacement resources, pointing the removal guidance at the invariant, and updating the active relevant-history profile target definition so deletes are not described as only created history.

Recommendation:
Keep this source fix. It completes the approved FHIR-53917 semantics in the active conformance source and examples; no separate source change for FHIR-53783 is implied because that issue's correction example already exists and is only adjusted here to satisfy the FHIR-53917 removal/replace rule.
