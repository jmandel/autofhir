FHIR-18824: Align Appointment waitlist invariant text

Issue request:
FHIR-18824 was Published/Persuasive for STU3 and asked to add a waitlist concept to Appointment.status, define it, update invariant app-3 so waitlisted appointments may omit start/end, and add waitlist narrative.

Initial application:
Historical GF#18824 commits 29089ed28e and 7fab7533d1 added the waitlist status source and waitlist narrative. Current source already has waitlist in the Appointment status CodeSystem, the required AppointmentStatus ValueSet, Appointment.status short text, the app-3 FHIRPath expression, and the waitlist workflow narrative.

Additional context:
Appointment is in current build scope through source/fhir.ini. PA minutes for the 2018 Baltimore WGM confirm the work group chose to address this tracker directly by adding the waitlist status and updating the appointment state table and invariant, without adding further waitlist structures at that time. Later FHIR-37515 clarified that app-2 still requires start/end to appear together, and FHIR-54225 found the current waitlist-flow narrative sufficient; FHIR-54399 is a later triaged request about additional waitlist relationship guidance and is not final applied work for this reconciliation.

AutoFHIR reconciliation:
Updated source/appointment/structuredefinition-Appointment.xml so app-3's human-readable invariant text includes waitlisted appointments, matching the existing FHIRPath expression that already permits status='waitlist'. No other source changes were needed.

Recommendation:
Keep this commit. It fixes the remaining misleading app-3 display text while preserving the already-applied code, narrative, and app-2 rule. Track future waitlist relationship guidance under FHIR-54399 rather than broadening this STU3 reconciliation.
