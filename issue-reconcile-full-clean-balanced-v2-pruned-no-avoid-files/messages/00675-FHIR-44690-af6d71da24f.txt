FHIR-44690: Clarify OperationDefinition targetProfile resource use

Issue request:
FHIR-44690 is Applied/Persuasive for R6 and requested updating the opd-3 FHIRPath expression from http://hl7.org/fhir/ValueSet/resource-types to http://hl7.org/fhir/ValueSet/all-resource-types. The Jira comments also required fixing the OperationDefinition.parameter.targetProfile definition and clarifying how this behavior differs in OperationDefinition.

Initial application:
The issue was partially applied by git commit 5d68211faaefeb2476f0484dd6155adb5e01abbd, which changed only the opd-3 expression in source/operationdefinition/structuredefinition-OperationDefinition.xml. The current source already used all-resource-types in the constraint, but the targetProfile short/definition still described Reference/canonical use and the literal Resource type, leaving concrete resource parameter types and the OperationDefinition-specific profile behavior unclear.

Additional context:
FHIR-26411 established that OperationDefinition.parameter.targetProfile should also apply to inline resources, and FHIR-39345 updated opd-3 for that R5 decision but used the narrower resource-types ValueSet. The Feb 2024 Zulip thread that led to FHIR-44690 clarified that type Resource and concrete resource types such as Patient are all supposed to be valid with targetProfile, and that OperationDefinition intentionally differs from ElementDefinition by using targetProfile where ElementDefinition would use type.profile. FHIR-I minutes on 2024-04-08 approved the all-resource-types expression correction.

AutoFHIR reconciliation:
Updated the build-scoped OperationDefinition StructureDefinition source so OperationDefinition.parameter.targetProfile now says resource parameter types use targetProfile to identify allowed profiles for inline resource parameter values. The definition now explicitly calls out the OperationDefinition-specific behavior corresponding to ElementDefinition.type.profile rather than ElementDefinition.type.targetProfile. The already-correct opd-3 all-resource-types expression was left unchanged.

Recommendation:
Keep this source fix as-is for FHIR-44690. Any future attempt to harmonize OperationDefinition with ElementDefinition profile/targetProfile naming would be a separate work-group design change rather than part of this correction.
