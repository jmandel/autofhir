FHIR-43530: Complete MessageHeader actor targets

Issue request:
FHIR-43530 was an Applied/Persuasive with Modification R6 InM change request asking to extend MessageHeader.destination.receiver and MessageHeader.source.sender so they could reference additional real-world actor resources. The final resolution and January WGM vote required sender targets Practitioner, PractitionerRole, Device, Organization, Patient, and RelatedPerson; receiver targets Patient, RelatedPerson, Practitioner, PractitionerRole, Organization, CareTeam, and Device; and excluded Group and Person because they are not actors in this context. A Jira comment also directed removal of the stale "Proposing to remove and rely on Task" sender text.

Initial application:
The issue was initially applied by commit ae7a52d477, merged by 07abbd7189. That commit updated source/messageheader/structuredefinition-MessageHeader.xml, but it only added Patient to source.sender and did not add RelatedPerson there; it added Device, Organization, Patient, and RelatedPerson to destination.receiver but did not add CareTeam. The stale source.sender comment sentence also remained. MessageHeader is an active resource in source/fhir.ini, so this StructureDefinition source is in current build scope.

Additional context:
The 2024-01-30 InM WGM minutes record the same 3-0-0 motion reflected in Jira: sender should include Patient and RelatedPerson, and receiver should include Patient, Device, RelatedPerson, and CareTeam in addition to the existing actor targets, while Group should not be included. A later applied issue, FHIR-44633, resolved overlap with Device by removing MessageHeader.destination.target rather than removing Device from destination.receiver; that issue is already represented on the combined branch and does not supersede the missing FHIR-43530 target additions. Jira and Zulip searches found no later conflicting decision about dropping CareTeam from receiver or RelatedPerson from sender.

AutoFHIR reconciliation:
This commit completes the build-scoped MessageHeader source by adding CareTeam to MessageHeader.destination.receiver, adding RelatedPerson to MessageHeader.source.sender, and removing only the stale "Proposing to remove and rely on Task" sentence from the sender comment. It does not add Person or Group, and it does not add redundant Device guidance because the later FHIR-44633 decision handled the target/receiver overlap by removing destination.target.

Recommendation:
Keep this source-changing commit as-is. It aligns the authoritative MessageHeader StructureDefinition with the applied Jira resolution and WGM minutes; no follow-up is needed unless InM later decides to add separate explanatory guidance for Device use.
