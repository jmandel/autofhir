FHIR-7941: Align ServiceRequest timing examples

Issue request:
FHIR-7941 was Published/Persuasive with Modification for DSTU1 ReferralRequest.fulfillmentTime. It asked to clarify the Period field requirements: not-before dates use Period.start, must-before dates use Period.end, and bounded windows use start and end.

Initial application:
The issue was applied in git commit a7344a39aa35eeb8f52cb6d13a8e63eabd6105b2, which updated ReferralRequest.fulfillmentTime requirements to reference Period.start and Period.end. No prior Issue-Reconcile-Key commit existed on the combined branch.

Additional context:
Later Patient Care workflow alignment renamed ReferralRequest.fulfillmentTime to ReferralRequest.occurrence[x], and FHIR-13196 merged ReferralRequest into the request resource lineage that is now ServiceRequest. source/fhir.ini lists ServiceRequest as an active current resource and records that ReferralRequest became ServiceRequest, while current ServiceRequest.occurrence[x] is dateTime|Period|Timing. ActivityDefinition and PlanDefinition are active resources, and their example lists include the edited examples, so stale fulfillmentTime references in those examples are current-build source rather than retired ReferralRequest source.

AutoFHIR reconciliation:
This commit updates current ActivityDefinition and PlanDefinition examples, matching invariant-test copies, the clinical reasoning narrative snippet, and the $apply response example to use current ServiceRequest.occurrence[x] names. It changes the interval-valued dynamic value from occurrenceDateTime to occurrencePeriod so the example preserves the original Period.start not-before semantics in the current ServiceRequest choice element.

Recommendation:
Keep this commit as a source fix. Remaining fulfillmentTime strings are legacy QUICK/CQL names or cross-version mapping metadata and should not be changed under this ReferralRequest wording issue without a separate clinical reasoning/model-definition review.
