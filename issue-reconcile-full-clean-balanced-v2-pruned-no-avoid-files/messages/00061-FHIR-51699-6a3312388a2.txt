FHIR-51699: Align DeviceAlert value set metadata

Issue request:
FHIR-51699 was Applied/Persuasive with Modification for R6 DeviceAlert vocabulary cleanup. It asked that DeviceAlert CodeSystem and ValueSet URLs use the appropriate canonical shape, statuses be active, publisher metadata identify the Devices work group, publisher contact URLs point to the Devices WG page, and the misspelling "announciated" be corrected.

Initial application:
The upstream application commit 5a348482d4 and PR #3629 made the DeviceAlert CodeSystems active, updated their publisher/contact metadata, corrected activationState spelling, made DeviceAlert ValueSets active, and updated the DeviceAlert resource contact plus the condition ValueSet contact. It intentionally did not add /CodeSystem to core CodeSystem canonicals after the #committers discussion with Grahame. However, most DeviceAlert ValueSets still retained generic FHIR Project publisher/contact metadata.

Additional context:
The active source/fhir.ini resource entry confirms source/devicealert is part of the current build, and the [wg-info] entry for dev now names the work group "Devices" after FHIR-55949. FHIR-51952 records the corresponding extension-pack URL-alignment concern but is still Submitted and belongs to FHIR-extensions, so it is evidence rather than a core issue reconciled here. Later DeviceAlert terminology movement work in FHIR-53238 is Resolved - change required, not yet Applied/Published in this run scope, so the current core artifacts still need correct metadata while they remain in core.

AutoFHIR reconciliation:
Updated all ten core DeviceAlert ValueSet source files to use publisher "HL7 International / Devices" and the Devices WG contact URL, matching the current WG name and completing the FHIR-51699 metadata request. No CodeSystem URL changes were made because the Jira application comment and Zulip discussion explicitly kept core CodeSystem canonicals in the existing http://hl7.org/fhir/devicealert-* form.

Recommendation:
Keep this commit. It completes the missed ValueSet publisher/contact portion of FHIR-51699 without changing canonical URLs or pre-empting unresolved extension-pack or THO migration work.
