FHIR-38991: Correct HTTP header table metadata

Issue request:
FHIR-38991 was Published/Persuasive with Modification for R5. It asked for the RESTful API HTTP Headers reference table to add response headers Location and Content-Location, link to the Custom Headers table, add the same metadata columns to the Custom Headers table, and add X-Forwarded-Proto, X-Forwarded-Port, and X-Forwarded-Prefix.

Initial application:
The issue was initially applied by git commit d1399f74f158a7e810db07f8f79052c9b3ecd721, which added the Location and Content-Location rows, linked to the Custom Headers table, expanded the Custom Headers table columns, and added the requested X-Forwarded rows. That application left Location's displayed RFC section as "§37.1.2", omitted MDN links for the two standard response headers, and marked the new X-Forwarded routing headers as "both" even though the neighboring X-Forwarded-For and X-Forwarded-Host rows are request headers.

Additional context:
source/http.html is the active RESTful API page source, mapped from publish.ini as http.html = http. FHIR-I minutes for 2022-10-24 record the FHIR-38991 vote and the summary "Will add Location and Content-Location." Jira and community searches found no later issue or discussion changing the requested HTTP header table semantics.

AutoFHIR reconciliation:
This commit edits source/http.html to complete the table metadata: Location and Content-Location now have MDN links, Location's RFC label matches RFC 7231 section 7.1.2, and X-Forwarded-Proto, X-Forwarded-Port, and X-Forwarded-Prefix are marked as request headers consistent with the adjacent X-Forwarded rows and their routing metadata descriptions.

Recommendation:
Keep this commit as-is. It finishes the narrow metadata correction directly attributable to FHIR-38991 without changing the broader RESTful API semantics; any future move from RFC 7231 references to newer HTTP RFCs should be handled consistently across the whole page under a separate tracker.
