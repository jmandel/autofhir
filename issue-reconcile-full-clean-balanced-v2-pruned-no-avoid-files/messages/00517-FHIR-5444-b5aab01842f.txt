FHIR-5444: Clarify vaccine-code value set description

Issue request:
FHIR-5444 was a Published/Persuasive PHER change request from the January 2015 ballot. It objected that the old VaccineType code system lacked the needed granularity and asked to make Immunization vaccine coding an example binding, remove the VaccineType value set from the FHIR value-set list, create a new example value set stressing multiple international code systems, and update examples to use different international codes.

Initial application:
The issue was explicitly applied in historical commit fc6c7631c4d5ab06ea8d8e6768b857f210769fa2, whose subject references #5444 and whose svn id matches Jira comment svn 4396. That commit added the new Immunization vaccine value set with CVX and Australian ACIR systems, adjusted Immunization examples to use CVX/ACIR-style codes, and excluded the old v3 VaccineType entry. Later commit 4e6d62c69367e6e3fcb59d84d016df913d35607e renamed the artifact family from vaccineType/vaccinetype to vaccineCode/vaccine-code for FHIR-6128.

Additional context:
Immunization remains an active current-build resource in source/fhir.ini, while ImmunizationRecommendation no longer has an active resource source folder in the current build after the immunization split. Current source/immunization/structuredefinition-Immunization.xml already describes Immunization.vaccineCode as an example binding that may carry codes at different levels of granularity from multiple systems. Current tools/tx/v3/valuesets.ini keeps VaccineType in the [Exclude] list. No directly relevant Zulip or Confluence evidence was found.

AutoFHIR reconciliation:
This commit makes one build-scoped source change in source/immunization/valueset-vaccine-code.xml. The value set text and compose already list both USA CVX and Australian ACIR, but the machine-readable description still said only "CVX codes". The description now states that this is an example value set for vaccine substances and includes CVX and Australian ACIR, aligning the ValueSet metadata with the Jira decision and the existing compose content.

Recommendation:
Keep this focused source fix. No broader FHIR-core follow-up is needed for FHIR-5444 unless a future terminology decision replaces or expands the example vaccine-code value set itself.
