FHIR-48778: Prefer common-tags for Meta.tag

Issue request:
FHIR-48778 was Applied/Persuasive with Modification for R6. It reported that Meta.tag was example-bound to common-tags even though common-tags includes codes with conformance language, and the adopted resolution was to make common-tags and its code system non-experimental while changing the Meta.tag binding strength from example to preferred.

Initial application:
Commit d9397aed3bcbc96ab2e4f64cdf5a97e2ab11ed38 applied part of the Jira by changing source/datatypes/valueset-common-tags.xml experimental from true to false. The current Meta datatype spreadsheet still had the Tags binding row set to example, and no Jira-tagged core commit was found that applied the binding-strength change.

Additional context:
source/fhir.ini actively lists Meta as a datatype and marks it normative, so source/datatypes/meta.xml feeds the current build and the hunk changes a normative structure. The current published HL7 Terminology common-tags CodeSystem and ValueSet both report experimental=false, and the CodeSystem is hosted under terminology.hl7.org rather than this core source checkout. FHIR-I minutes from 2025-02-10 record the Persuasive with Modification vote for FHIR-48778, and no Zulip hit for FHIR-48778 was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:
Changed the Tags binding row in source/datatypes/meta.xml from example to preferred while leaving the already non-experimental core ValueSet source unchanged.

Recommendation:
Keep this commit as-is. It completes the remaining current-core source change for FHIR-48778; any future concern about the external terminology artifacts should be handled in the terminology source of truth, which already publishes both common-tags artifacts with experimental=false.
