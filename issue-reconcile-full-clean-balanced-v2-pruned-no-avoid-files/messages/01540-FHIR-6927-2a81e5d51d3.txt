FHIR-6927: Correct slicing example terminology

Issue request:
FHIR-6927 was a Published FHIR-core Change Request, resolved Not Persuasive with Modification, asking to remove the old ElementDefinition eld-5 rule that made nameReference and fixed[x] mutually exclusive because the reporter thought it prevented constraining child elements of a named slice. The accepted decision kept the rule but required an example showing how to express the desired sliced-element constraints.

Initial application:
The issue was applied in git commit 8e041a80dbcf7621980d5cc620e88cf9554fc4bb, imported from svn revision 6519, whose message explicitly included #6927 and added/updated the blood-pressure slicing example in source/profiling.html. That example was later carried forward into the current profiling guidance and the detailed source/profiling-examples.html StructureDefinition snippet, using sliceName and child element ids such as Observation.component:systolic.code rather than the obsolete nameReference pattern.

Additional context:
The original nameReference element has since become ElementDefinition.contentReference, and the current invariant eld-5 applies to contentReference in specializations rather than to slice child constraints in profiles. The current R6 profiling examples already show the intended approach, but the short narrative in source/profiling.html still had obsolete wording from older Observation.related/name terminology, referring to an Observation name and a target resource even though the current example slices inline Observation.component entries by component code.

AutoFHIR reconciliation:
This commit keeps the existing example-based resolution and surgically corrects the stale narrative in source/profiling.html so the blood-pressure slicing description consistently talks about Observation.component, component code, and components representing systolic/diastolic slices. No new example was added because the active profiling example and profiling-examples page already convey the requested profiling pattern.

Recommendation:
Keep this commit as-is. It preserves the original work-group decision not to remove eld-5 while making the example that implements the decision accurate for the current build; no additional FHIR-6927 source work is recommended.
