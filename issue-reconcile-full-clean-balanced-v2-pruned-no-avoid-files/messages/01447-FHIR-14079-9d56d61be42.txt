FHIR-14079: Anchor RESTful reference regex

Issue request:
FHIR-14079 was a Published/Persuasive STU3 FHIR-I correction for the References page RESTful URL regex. It reported that the STU3 absolute-URL prefix failed common hostnames such as https://my-server.com/fhir, used literal // in a way the reporter challenged, and lacked an explicit start-of-string anchor; the accepted resolution was to add '-' to valid hostname characters, not use // literally, and make sure the regex start matches the string start.

Initial application:
The issue was initially applied in svn revision 14244, represented in git by c51bffe9cbffd3b25097ebd472f9162262027e5d, which added '-' to the URL-prefix character class in source/references.html. Earlier same-day history for related FHIR-17172 changed the scheme separator to escaped slashes and required slash-delimited URL segments. Before this reconciliation, the current source had the hyphen allowance and escaped slashes, but it still did not include the requested start anchor.

Additional context:
source/references.html is the active References page source for the FHIR-core-references page, and source/fhir.ini maps the Reference type page to references. Later Published issue FHIR-34405 appended the optional contained-resource fragment suffix to the same regex and did not supersede the FHIR-14079 start-anchor request. A current combined-branch AutoFHIR commit for FHIR-17172 tightened the first URL segment while preserving the FHIR-14079 hyphen allowance, but explicitly left FHIR-14079's separate anchoring wording undecided. Zulip and Confluence searches for FHIR-14079 found no conflicting community record.

AutoFHIR reconciliation:
This commit adds the missing ^ start anchor to the active References page regex and leaves the already-applied hyphen allowance, escaped slashes, host-segment fix, and optional fragment suffix unchanged.

Recommendation:
Keep this source fix. It completes the remaining explicit FHIR-14079 resolution item without broadening the regex or revisiting later related issues that have already been reconciled separately.
