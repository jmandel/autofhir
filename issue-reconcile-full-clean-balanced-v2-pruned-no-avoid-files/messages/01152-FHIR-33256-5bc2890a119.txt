FHIR-33256: Correct fhirPatch extension example

Issue request:
FHIR-33256 was a Published/Persuasive FHIR-core clarification requesting fhirPatch documentation and examples for adding extensions, after implementers could not tell how to represent an extension in a FHIRPath Patch Parameters resource. The accepted resolution was to create test cases and update the specification with examples.

Initial application:
The issue was initially applied by git commit 147147842e3fd0e1fce396e212dead752d91869c, which added an "Extension Example" section to source/fhirpatch.html. That page is in the current build navigation through source/hierarchy.xml and is linked from the HTTP PATCH guidance, so it is the authoritative narrative source for this clarification.

Additional context:
The linked Zulip thread confirms the intended shape: represent the extension as nested parts of the anonymous value, use a full extension URL, and prefer the extension before the ordinary child elements. The FHIRPath Patch profile requires the operation type parameter to be valueCode, and normal FHIR XML Reference.reference encoding uses a nested <reference value="..."/> element. The current applied example instead used valueString for the operation code, labeled XML snippets as JSON, placed the extension after the non-extension parts, and showed malformed/wrong Reference XML.

AutoFHIR reconciliation:
This commit keeps the existing FHIR-33256 example but corrects the copy/paste defects: the operation type is now valueCode, the snippets are marked as XML, extension parts precede description/time, and both the patch Parameters example and resulting Specimen use <reference value="Device/1"/>.

Recommendation:
Keep this commit as-is. It is a narrow correction to the already-approved FHIR-33256 source text and avoids leaving implementers with an invalid example for the very scenario the issue asked to clarify.
