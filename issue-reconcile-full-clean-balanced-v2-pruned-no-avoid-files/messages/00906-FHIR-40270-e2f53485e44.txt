FHIR-40270: Align FHIRPath ofType wording

Issue request:
FHIR-40270 is Applied/Persuasive with Modification for R6. It asked the FHIR core FHIRPath page to stop presenting as() as an ofType() alias, because as is FHIRPath operator syntax with singleton behavior, and to align the ofType() signature and explanatory wording with the base FHIRPath specification.

Initial application:
The current source already removed the stray as()/alias function content through the FHIR-53208 cleanup, and FHIR-41595 had already corrected the polymorphism example from as to ofType. However, the remaining active ofType() section in source/fhirpath.html still showed the signature as "type : type specifier" and contained the awkward phrase "This is as defined as in the base FHIRPath specification," so the FHIR-40270 wording update was only partially applied.

Additional context:
source/hierarchy.xml lists fhirpath.html as the built FHIRPath page, so source/fhirpath.html is in current build scope. FHIR-I minutes for 2025-10-27 record that as() had already been removed from the core spec, that the function belongs in the base FHIRPath spec, and that the approved remaining work was to remove as and change the ofType wording. No directly relevant Zulip thread for FHIR-40270 was found.

AutoFHIR reconciliation:
Updated the active ofType() heading to use "type: type specifier" and changed the relationship sentence to "This is as defined in the base FHIRPath specification," preserving the FHIR-specific guidance that follows.

Recommendation:
Keep this source fix as-is. It completes the approved core-page wording without reintroducing redundant as() documentation or changing FHIRPath semantics.
