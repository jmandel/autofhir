FHIR-22725: Clarify maximum binding translations

Issue request:
FHIR-22725 was a Published/Persuasive FHIR-core change request asking whether elementdefinition-maxValueSet prevents additional or translation Codings in CodeableConcept instances. The accepted resolution clarified maxValueSet as an overall required binding layered over a less restrictive binding, and the Jira discussion explicitly said one Coding must satisfy the bound value set while other Codings or text are not prohibited.

Initial application:
The issue was initially applied in git commits 3bedd026de and cc4787a878, which updated the ElementDefinition maxValueSet extension spreadsheet from the old "additional codes can be taken from" wording to the accepted "overall 'required' binding" wording. Later git commit dd468d4f17 removed core extension definitions for R5, so the old extension definition is no longer active in this core checkout.

Additional context:
Confluence minutes for the 2021-09-13 FHIR-I call, apparently under a mis-keyed tracker entry but matching the maxValueSet discussion and Jira vote, record that maxValueSet was not intended to limit translations and that preferred bindings could also use maxValueSet in rare cases. Later FHIR-43156 and FHIR-46445 deprecated the moved Extension Pack min/max value set extensions, and FHIR-46350 deprecated the maximum additional-binding purpose as equivalent to required. The current core source therefore needs to clarify the active replacement narrative, not revive the removed extension definition.

AutoFHIR reconciliation:
Updated source/terminologies.html, a published terminology page listed in publish.ini, so the maximum additional-binding row now says the element satisfies the maximum value set using required-binding semantics. The text explicitly states that for CodeableConcept and CodeableReference this requires one Coding from the maximum value set and does not itself prohibit translation Codings or text representing the same concept.

Recommendation:
Keep this source fix. It aligns the current R6 terminology narrative with the accepted FHIR-22725 clarification, the required-binding rules already on the same page, and the later deprecation policy that treats maximum as equivalent to required.
