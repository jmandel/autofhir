FHIR-43648: Align actor type OID registry URLs

Issue request:
FHIR-43648 is an Applied FHIR-core FHIR-I change request with a Persuasive with Modification resolution. It asked to move the ExampleScenario actor-type ValueSet to ActorDefinition and rename it to http://hl7.org/fhir/ValueSet/actordefinition-actor-type; the approved resolution also required renaming the CodeSystem while preserving instance compatibility.

Initial application:
PR #3354 was merged as 8e71abb11c5737e3f165c33fdea01e2b90184f35 and moved the CodeSystem and ValueSet source files into source/actordefinition, renamed their canonical URLs, and updated ActorDefinition.type and ExampleScenario.actor.type bindings. That application did not update source/oids.ini, so the active OID registry still assigned the existing OIDs to the old examplescenario-actor-type canonical URLs.

Additional context:
The 2024-01-22 FHIR Workflow minutes record FHIR-43648 as persuasive with modification. A 2025 Zulip implementation thread explicitly asked whether the renamed code system and value set should keep the existing OIDs; Lloyd McKenzie said that was fine. Later FHIR-50087 changes the actor type value set content and adds ActorDefinition.category context, but it leaves the actordefinition-actor-type canonical in place and is not final Applied/Published scope for this reconciliation. Recent FHIR source history for other canonical renames updates source/oids.ini URLs while retaining the assigned OID values.

AutoFHIR reconciliation:
Updated source/oids.ini so the existing ValueSet and CodeSystem OIDs now point to http://hl7.org/fhir/ValueSet/actordefinition-actor-type and http://hl7.org/fhir/actordefinition-actor-type. The edited file is active build input for oids.html via source/oids.html and publish.ini, and this hunk is necessary so the current build's OID registry matches the renamed authoritative terminology source. The stale ExampleScenario SVG link was not edited because it is a generated-looking diagram artifact and the authoritative XML source is already correct.

Recommendation:
Keep this source fix. Human/product-director review remains appropriate for any OID registry change, but the change follows the work group's rename decision, the Zulip OID guidance, and existing source-history practice of retaining OID values across canonical URL renames.
