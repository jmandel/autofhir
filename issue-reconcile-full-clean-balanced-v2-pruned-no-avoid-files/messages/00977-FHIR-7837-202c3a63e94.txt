FHIR-7837: Remove MedicationStatement PID-3 mapping

Issue request:
FHIR-7837 was a Published/Persuasive Pharmacy change request from the DSTU1 QA cycle asking to blank the HL7 v2 mapping for MedicationStatement.patient/subject by removing "PID-3-Patient ID List" because MedicationStatement is not a v2 transaction-domain concept and mapping from a v2 message that carries a patient was not expected to be a likely scenario.

Initial application:
The 2015 Pharmacy v2-mapping batch commit 5bb461af1063efe577bac2b8b17b6992be7560bf explicitly listed tracker item 7837, but inspection of the MedicationStatement spreadsheet before and after that commit showed that MedicationStatement.patient still retained the PID-3 v2 mapping while adjacent RXA/RXR/RAS mappings were removed. Later MedicationStatement/MedicationUsage refactors carried the PID-3 mapping forward into StructureDefinition XML, and the 2022 commit b9257918056a31ebdc080627432cc94db78637e0 only normalized the punctuation from "PID-3-Patient ID List" to "PID-3 Patient ID List" while applying unrelated MedicationUsage changes.

Additional context:
MedicationStatement is active in source/fhir.ini and assigned to Pharmacy, so source/medicationstatement/structuredefinition-MedicationStatement.xml is current build-scope source. Before this reconciliation, the only element-level HL7 v2 mapping left in the current MedicationStatement source was the subject mapping to PID-3, which contradicted FHIR-7837's final request while the rest of the old MedicationStatement v2 mapping cleanup had already been preserved or separately audited. Corrected Jira, Zulip, and Confluence searches found no later decision or community record that reintroduced or justified the PID-3 MedicationStatement mapping.

AutoFHIR reconciliation:
This commit removes the v2 mapping block from MedicationStatement.subject in the active StructureDefinition source. The top-level v2 mapping identity is left in place because other current StructureDefinition sources also retain mapping namespace declarations without element rows; the semantic fix is the removal of the subject row's PID-3 map value.

Recommendation:
Keep this source fix. It completes the Published FHIR-7837 request in the current core build and does not require broader MedicationStatement v2 mapping policy work unless Pharmacy decides to revisit that mapping surface separately.
