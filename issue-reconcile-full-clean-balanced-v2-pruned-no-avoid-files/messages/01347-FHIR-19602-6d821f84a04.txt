FHIR-19602: Align Identifier URI-system details

Issue request:
FHIR-19602 was a Published/Persuasive with Modification FHIR-I change request for STU3. It reported that the Identifier guidance for OID, UUID, and URI values was too restrictive and asked that urn:ietf:rfc:3986 be required only when no more specific identifier system, such as urn:dicom:uid, exists. The final resolution added a clarifying sentence explaining that naturally globally unique identifiers are those for which no system has been assigned and whose values are reasonably expected not to be reused.

Initial application:
The issue was applied by git commit b7c51c4130, which added the resolved datatypes.html sentence and updated DICOM examples to use urn:dicom:uid with plain UID values. Later same-area edits, especially FHIR-45479, refactored the narrative into the current rule that an Identifier.system may be established by an assigner or community and that urn:ietf:rfc:3986 is the fallback when no system is assigned. The active Identifier datatype spreadsheet still contained the older blanket Identifier.value comment saying any full URI value SHALL use urn:ietf:rfc:3986.

Additional context:
source/fhir.ini lists Identifier as an active datatype, so source/datatypes/identifier.xml is build-scope source rather than stale history. The original Zulip discussion and the later FHIR-45479 issue/thread both confirm the intended model: specific identifier systems can be used for globally unique OID/UUID/URI-shaped values, while urn:ietf:rfc:3986 applies when no identifier system has been assigned. FHIR-41478 raised a similar clarification and was merged with FHIR-45479, which is already represented on the combined branch.

AutoFHIR reconciliation:
Updated source/datatypes/identifier.xml so the Identifier.value detailed comment no longer states that every full URI value forces Identifier.system to urn:ietf:rfc:3986. It now says Identifier.system SHALL identify the assigned identifier system for a globally unique identifier expressed as a URI, and SHALL be urn:ietf:rfc:3986 only when no identifier system has been assigned. No narrative edit was needed because source/datatypes.html already contains the later accepted wording.

Recommendation:
Keep this source fix. It aligns the active generated-definition source with the 2018 FHIR-19602 clarification and the later FHIR-45479 clarification without reopening the normative SHALL or adding redundant narrative text.
