FHIR-13542: Allow servers to page remaining $everything results

Issue request:
FHIR-13542 was Published/Persuasive for STU3 and asked that $everything not require an unpaged, single-bundle response when a server judges paging necessary. The accepted resolution was to document paging for $everything, including performance issues, and to consider descending last-updated ordering.

Initial application:
The Jira comment pointed to the 2018 SVN application window; git history shows 3e2924dc7e9eef23cf97085a8cb3491ad5ec8781 (svn build@13071) titled "document paging on $everything operation" adding _count and the paging/performance discussion to Patient, Encounter, and Group $everything spreadsheet sources. Later source refactors generated standalone OperationDefinition XML and preserved the new paging discussion, but the old opening bullet still said the server returns the entire result set in one bundle unless the client asks otherwise.

Additional context:
Patient, Encounter, and EpisodeOfCare $everything were subsequently updated by FHIR-44604/FHIR-43373 and FHIR-44816 to remove the single-bundle requirement and describe the key difference as client freedom from choosing included resources. Those PA-scoped changes did not cover the current core Group and MedicinalProductDefinition operation definitions, which are active resources in source/fhir.ini and are referenced by their resource operation lists. A Zulip HAPI thread independently illustrates that implementers read the old sentence as conflicting with server-enforced paging.

AutoFHIR reconciliation:
This commit removes the stale single-bundle/client-controls-paging bullet from the active Group and MedicinalProductDefinition $everything OperationDefinition footer/comment text, using the same semantic pattern as the later Patient/Encounter/EpisodeOfCare fixes. It leaves the existing _count parameter, server-required paging allowance, performance discussion, and sorting guidance in place.

Recommendation:
Keep this commit as-is. It is a bounded source correction for current core artifacts that still carried the obsolete single-bundle sentence; the related PA issues are useful context but were not separately audited here because their scoped Patient/Encounter/EpisodeOfCare edits are already represented in source history and those operations are no longer the remaining core mismatch.
