FHIR-37802: Align GenomicStudy linkage guidance

Issue request:
FHIR-37802 was a Published, Persuasive with Modification R5 change request from Orders & Observations. It asked core DiagnosticReport and Observation to be able to reference GenomicStudy; the final resolution added DiagnosticReport.study as a 0..* Reference to ImagingStudy or GenomicStudy, and added GenomicStudy to Observation.partOf and Observation.derivedFrom.

Initial application:
The request was initially applied before this reconciliation by the GenomicStudy PR/history trail: c408ff2 added GenomicStudy references to DiagnosticReport and Observation, 77cb02a renamed the DiagnosticReport element to study and added guidance, and 385f838 adjusted the GenomicStudy guidance wording. The current source still contained narrative text from that application even though later source changes removed GenomicStudy from the active core reference target lists.

Additional context:
DiagnosticReport and Observation are active current-build resources in source/fhir.ini, while GenomicStudy has no active fhir.ini entry. Later commits 3b38b80 and fad1b9c removed GenomicStudy from active core configuration and from DiagnosticReport/Observation target profiles as part of moving additional resources to incubator IGs. FHIR-54164 records the resulting DiagnosticReport.study mismatch and says GenomicStudy text/references should be removed now that the resource is in the incubator Additional Resources IG. FHIR-57361 later kept the generic DiagnosticReport.study name for future extensibility while noting GenomicStudy had moved to Incubator. FHIR-46394 had added GenomicStudy to DiagnosticReport.supportingInfo, but that issue is already represented on the combined branch and the later incubator move removed that core target.

AutoFHIR reconciliation:
This commit updates the active DiagnosticReport introduction so it no longer says genomic metadata is referenced through DiagnosticReport.study, and instead points to the Clinical Genomics incubator GenomicStudy resource. It also updates the active Observation notes so they no longer say Observation.partOf or Observation.derivedFrom directly reference GenomicStudy in base core; the remaining guidance keeps DocumentReference as the in-core derivedFrom option and directs additional linkage patterns to the linked GenomicStudy guidance.

Recommendation:
Keep this source change. Do not restore GenomicStudy target profiles in core unless a later work-group decision brings GenomicStudy or an explicit external dependency back into the active core build. If generated SVG diagrams are regenerated separately, they should follow the authoritative StructureDefinition target lists and this narrative.
