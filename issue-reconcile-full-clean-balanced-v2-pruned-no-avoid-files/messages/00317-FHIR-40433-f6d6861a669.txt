FHIR-40433: Remove stale implicit ValueSet warning

Issue request:
FHIR-40433 was Published with a Persuasive resolution for R5. It asked that the implicit ValueSet and ConceptMap notes stop saying implementers SHOULD NOT create explicit resources whose canonical URI matches a known implicit value set or concept map, and instead say that any such explicit resource SHALL conform to the implicit definition pattern, with server handling left to server discretion and only an implementation-note discouragement when the relevant server already supports the implicit form.

Initial application:
The old ValueSet SHOULD NOT sentence came from the earlier FHIR-39255 clarification and the parallel ConceptMap sentence came from FHIR-39266. Commit 9f780149387dc652bec02aa7744e52774acddbc9 added the FHIR-40433 replacement text and implementation notes to both pages and removed the old ConceptMap paragraph, but it accidentally left the old ValueSet SHOULD NOT paragraph immediately after the new implementation note.

Additional context:
source/fhir.ini actively lists valueset=ValueSet and conceptmap=ConceptMap under [resources], so these notes are in current build scope. The current ConceptMap source already carries the FHIR-40433 replacement wording without the old SHOULD NOT paragraph. VOC minutes for 2023-02-20 record FHIR-40433 as resolved, and searches found no Zulip or Confluence evidence that later narrowed or reversed the published Jira decision.

AutoFHIR reconciliation:
This commit removes only the stale ValueSet paragraph that still said implementers SHOULD NOT create ValueSet resources matching known implicit value-set URI patterns. It leaves the already-applied replacement ValueSet text, implementation note, and ConceptMap text unchanged.

Recommendation:
Keep this source-changing commit. It completes the published FHIR-40433 decision in the active ValueSet notes while preserving the intended discouragement as an implementation note and avoiding redundant ConceptMap edits.
