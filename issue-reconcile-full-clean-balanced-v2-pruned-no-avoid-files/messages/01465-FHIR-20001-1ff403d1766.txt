FHIR-20001: Capitalize string :text search operator example

Issue request:
FHIR-20001 was a Published FHIR-core search change request with a Persuasive with Modification resolution. It reported that the string search discussion around the :text modifier and text-search examples were circular/confusing, and the accepted resolution specifically required examples using uppercase AND: GET [base]/Condition?_text=(bone OR liver) AND metastases and GET [base]/Patient?name:text=(kramer OR broek) AND wouter.

Initial application:
The explicit application commit e1834a99c8 ("Apply FHIR-20001") changed the _text example from lowercase "and" to uppercase "AND" in source/search.html. Later search-page refactoring introduced and retained a string :text example using Composition?section:text=(bone OR liver) and metastases, so the same accepted capitalization rule was not reflected in that active example.

Additional context:
The active source/search.html page is the normative Search page. Related Jira FHIR-17461 and its linked Zulip thread confirm that string :text remained an intentional modifier distinct from the _text search parameter, so this reconciliation does not remove or redefine :text. Later FHIR-32673 split advanced token/reference text searching into :text-advanced while leaving the string :text advanced-search semantics in place, so the current Composition example is the relevant successor surface for the FHIR-20001 string :text example.

AutoFHIR reconciliation:
Updated the GET and POST string :text example in source/search.html to use uppercase AND, matching the FHIR-20001 resolution and the already-correct _text example. No other wording or modifier semantics were changed.

Recommendation:
Keep this commit as-is. It completes the remaining source-level application of the accepted example capitalization without reopening the broader :text versus _text design, which later Jira and Zulip evidence show is intentional.
