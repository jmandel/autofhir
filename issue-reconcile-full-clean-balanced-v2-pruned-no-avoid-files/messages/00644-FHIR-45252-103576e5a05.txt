FHIR-45252: Clarify non-Reference search references

Issue request:
FHIR-45252 was an Applied/Persuasive FHIR-I R6 clarification request for the Search page. It asked that chaining, includes, reverse includes, and the [type] modifier stop saying non-Reference references such as canonical elements cannot be used, and instead explain that the behavior is not defined by the base specification while servers may choose to support it with implementation-specific resolution rules.

Initial application:
The issue was initially applied by commit 50ef95a57642a2038880bbf9f7433c803efc3a1e, later merged in HL7/fhir#3967, which changed source/search.html to add canonical include guidance and some chaining/type modifier clarification. That application did not fully reconcile the current source: the active Search narrative still contained the old prohibitive reference-search paragraph, the old [type] modifier external-reference note, the canonical identifier heading was attached to resource identifier text, the new canonical include section was missing from the local table of contents, and the requested canonical chaining example/notes were incomplete.

Additional context:
The Zulip thread linked from the Jira shows the intended distinction: the base specification should not require servers to resolve canonicals, but it also should not prohibit servers from supporting canonical chaining or includes. The FHIR-I 2024-04-15 minutes approved the issue as Persuasive and explicitly noted that the change was new optional support, not a new SHALL. FHIR-43073 is background because it introduced/reviewed the reference-search wording that prompted the later canonical chaining clarification.

AutoFHIR reconciliation:
This commit updates the active source/search.html narrative. It replaces stale "not supported"/"cannot" wording with "not defined" plus server discretion, updates the [type] modifier paragraph to permit implementation restrictions based on instance contents, splits the resource identifier and canonical identifier headings/anchors, adds the canonical include section to the table of contents, and adds the requested canonical chaining notes and QuestionnaireResponse-to-Questionnaire example. The source file is in build scope as the top-level Search narrative and is the same file changed by the Jira-tagged implementation commit.

Recommendation:
Keep this commit as the FHIR-45252 reconciliation. It completes the applied clarification without adding mandatory canonical resolution behavior; future work should only revisit if FHIR-I decides to normatively define canonical chaining semantics beyond optional server support.
