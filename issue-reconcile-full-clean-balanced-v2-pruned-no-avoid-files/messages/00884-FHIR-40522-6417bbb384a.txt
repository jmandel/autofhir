FHIR-40522: Align Definition subject path references

Issue request:
FHIR-40522 was Published as Persuasive with Modification for R5. It asked that the Definition pattern's subject[x] be repeatable because a definition can apply to multiple subject types; the accepted resolution was to change the pattern element to 0..* CodeableReference so resources can constrain to a concept or Group as needed.

Initial application:
The issue was initially applied by 125f3872df557d874280700b0c21c07d93dc2fc4, which changed Definition.subject[x] to Definition.subject with type CodeableReference(Group), and by 780848422c95aecca553449ce3f3f82fced81cf4, which changed the cardinality from 0..1 to 0..*. Current source retained that core element change. However, the same logical-model spreadsheet still used the old choice-type search paths Definition.subjectCodeableConcept and Definition.subjectReference, and active PlanDefinition.topic and Questionnaire.subjectType workflow mappings still pointed to the obsolete Definition.subject[x] path.

Additional context:
The Definition logical model is in the active [logical] build list in source/fhir.ini, and PlanDefinition and Questionnaire are active resources. Confluence Workflow minutes for 2023-02-27 record the FHIR-40522 Persuasive with Modification decision in a pattern-mapping discussion, which makes stale pattern mapping references part of the intended application. No directly relevant Zulip discussion or later conflicting Jira issue was found.
