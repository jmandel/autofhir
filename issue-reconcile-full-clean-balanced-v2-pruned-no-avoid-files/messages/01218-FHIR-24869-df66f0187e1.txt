FHIR-20203 + FHIR-24869: Restore operation response output wording

Attribution note: surfaced while reviewing FHIR-24869, but direct Jira backing for this change is FHIR-20203 + FHIR-24869.

Issue request:
FHIR-24869 was a Published/Persuasive FHIR-I clarification for operations.html#response asking the Operations Framework to explain zero-output operations while preserving that a Parameters response contains one or more output parameters when a response body is present.

Initial application:
The issue was applied by git commit 1c5be8bd4b, which added the zero-output response guidance to source/operations.html but accidentally left the sentence reading "ne or more output parameters" instead of "one or more output parameters".

Additional context:
source/hierarchy.xml includes operations.html in the RESTful API section of the current build, so source/operations.html is an active narrative source page. The later FHIR-28292 application in commit 61cdda43d3 updated the same sentence to require a single 0..1 Resource return value to be returned directly, but it preserved the pre-existing typo rather than intentionally changing the FHIR-24869 rule.

AutoFHIR reconciliation:
This commit changes the active Operations Framework source from "ne or more output parameters" to "one or more output parameters" and leaves the FHIR-28292 SHALL/no-wrapping rule and the FHIR-24869 zero-output guidance unchanged.

Recommendation:
Keep this small source fix as-is. It corrects an obvious typo in the active operations response narrative and does not change conformance semantics beyond restoring the intended published wording.
