FHIR-48422: Correct additional reference guidance

Issue request:
FHIR-48422 was Applied as Not Persuasive with Modification for R6. The request asked whether Basic should be implicitly accepted as a target for all Reference and Resource uses; FHIR-I instead decided that the alternate-reference extension is the mechanism and that References.html should gain an "Additional References" section before canonical references.

Initial application:
Commit 4c62878beb7f314514c3f68dd936bbdc510dc25a added the requested Additional References section to source/references.html. The current combined branch already contains that application, but it used the nonexistent name additional-reference in the migration paragraph and left a stray closing quote.

Additional context:
FHIR-I Madrid minutes record the same decision and identify alternate-reference as the extension for pointing to Basic or additional resources. The FHIR Extension Pack defines StructureDefinition/alternate-reference, while no core or extension-pack source defines an additional-reference extension. source/fhir.ini maps the Reference type page to references.html, so the edited narrative is in current build scope.

AutoFHIR reconciliation:
This commit corrects the migration paragraph to refer to alternate-reference and removes the stray quote. It does not change the resolved policy: ordinary Reference target restrictions remain meaningful, and out-of-target references use the alternate-reference extension.

Recommendation:
Keep this commit as-is. It preserves the applied FHIR-48422 resolution while removing misleading source text that would otherwise point implementers to a nonexistent extension name.
