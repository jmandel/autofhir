FHIR-50619: Clarify SubscriptionTopic create/delete query examples

Issue request:
FHIR-50619 was Applied/Persuasive for R6 by FHIR-I. It asked that the SubscriptionTopic Trigger Interaction: Create and Delete sections resolve ambiguity around the examples pairing resultForCreate/resultForDelete with requireBoth, add passing/failing clarification, and use the Criteria Not Exists Behavior binding values instead of boolean true/false for resultForCreate/resultForDelete.

Initial application:
PR HL7/fhir#3967 merged commit c808fb34d6, which added a query-criteria behavior table and links from the create/delete sections to the Query (Search) Trigger Definitions section. That initial application left the original local create/delete example sentences saying resultForCreate/resultForDelete and requireBoth should both be set to true or false, even though resultForCreate/resultForDelete are now bound code values.

Additional context:
SubscriptionTopic is an active current-build resource in source/fhir.ini, and source/subscriptiontopic/subscriptiontopic-notes.xml is the authoritative narrative source for the cited sections. The SubscriptionTopic StructureDefinition binds resultForCreate and resultForDelete to Criteria Not Exists Behavior values test-passes/test-fails, while requireBoth remains boolean and its comment already explains the paired behavior.

AutoFHIR reconciliation:
Updated the create and delete queryCriteria paragraphs to name the correct pairs: resultForCreate/resultForDelete = test-passes with requireBoth = true, or resultForCreate/resultForDelete = test-fails with requireBoth = false. This preserves the WG intent that either same-result pairing makes create/delete criteria testable across interactions, while removing the stale boolean wording for the bound code elements.

Recommendation:
Keep this source change. It completes the applied clarification without changing the broader behavior table or adding redundant guidance, and no community evidence was found that conflicts with the Jira/Confluence/source conclusion.
