FHIR-47622: Complete Medication serial-number mapping

Issue request:
FHIR-47622 was Applied/Persuasive for R6. It asked for a dedicated Medication serial-number location because Medication.identifier was ambiguous between medication-kind identifiers and physical-instance identifiers. The resolution renamed Medication.batch to Medication.instance, added Medication.instance.identifier 0..* Identifier for the physical instance, added a serial-number example, and required existing examples not to carry serial numbers in Medication.identifier.

Initial application:
The issue was initially applied through HL7/fhir PR 3896. Local Jira-tagged commits afb9b405cb, 35383bc5c4, 958e04e179, and 01530390fc renamed the core BackboneElement, added Medication.instance.identifier, updated many Medication examples, and fixed the new element path typo. Those commits left the main Medication definition mostly correct but missed some parallel search-parameter and contained-example surfaces.

Additional context:
source/fhir.ini actively lists Medication as a current resource, so source/medication/structuredefinition-Medication.xml and source/medication/bundle-Medication-search-params.xml are build inputs. The remaining Medication.batch entries in fhir.ini are old-to-new migration aliases, not current element definitions. No FHIR-47622-specific Zulip or Confluence decision evidence was found; older Zulip hits about Medication instance identifiers were background and did not alter the Jira resolution.

AutoFHIR reconciliation:
This commit removes the stale Medication.identifier comment that still directed serial numbers to the general medication identifier; retargets the Medication serial-number search parameter to Medication.instance.identifier; fixes the Medication lot-number search-parameter path extension to Medication.instance.lotNumber; and updates contained Medication examples in MedicationRequest, MedicationDispense, MedicationAdministration, and MedicationStatement from the removed batch element to instance.

Recommendation:
Keep this source-changing commit as the reconciliation for FHIR-47622. It completes the applied Jira resolution in active source while leaving the intentional fhir.ini compatibility aliases alone.
