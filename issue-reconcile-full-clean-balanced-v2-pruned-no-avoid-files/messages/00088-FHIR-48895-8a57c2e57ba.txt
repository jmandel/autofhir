FHIR-48895: Align DeviceAlert component definition

Issue request:
FHIR-48895 was an Applied/Persuasive Devices change request for R6 asking DeviceAlert to support compound metrics by identifying which Observation component caused an alert, originally also suggesting a corresponding Device-alertDetection component.

Initial application:
The issue was applied by PR #3533, merged as d12386c96669661f8c6a55672865ac7522f2279e, with implementation commit 4f7d26af1e36cfaccd8f4834948f3475e9bc8eeb. That implementation reorganized DeviceAlert.derivedFrom into a BackboneElement, renamed the original reference to derivedFrom.observation, added derivedFrom.component as Coding 0..1, and updated the derived-from search parameter to target DeviceAlert.derivedFrom.observation. Later commits for FHIR-51472 and FHIR-53371 touched the same element for markdown and conformance-language cleanup but did not change the 0..1 cardinality.

Additional context:
Jira comments and Devices WG minutes show the final approach moved away from ignorable extensions/targetElement/targetPath toward a DeviceAlert backbone element, and a later Jira comment records that Device-alertDetection did not need a component because it refers to the generated alert code, not the triggering condition. source/fhir.ini lists DeviceAlert as an active current-build resource, while the device-alertDetection definition is maintained in the FHIR Extension Pack and remains outside this core source edit. The current DeviceAlert source already carried the intended component element, but its definition still said repetitions of that 0..1 element could indicate additional components.

AutoFHIR reconciliation:
This commit removes the impossible repetition guidance from DeviceAlert.derivedFrom.component and fixes the matching grammar, preserving the 0..1 Coding model approved and applied for FHIR-48895. It also aligns the checked-in DeviceAlert SVG title text with the authoritative StructureDefinition so the visible diagram does not continue to advertise repetitions for a non-repeating element.

Recommendation:
Keep this commit as-is. No core DeviceMetric or Extension Pack source change is indicated for FHIR-48895 unless the Devices WG later decides that alertDetection should describe triggering submetrics rather than the generated alert code.
