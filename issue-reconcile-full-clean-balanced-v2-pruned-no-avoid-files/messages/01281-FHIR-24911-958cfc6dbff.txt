FHIR-24911: Clarify inherited constraints in profile template

Issue request:
FHIR-24911 was a Published/Persuasive FHIR-core change request for R5 asking that the Presenting Profiles snapshot tab documentation say inherited invariants are omitted. The accepted resolution said to add the note in both the core specification and the standard IG template.

Initial application:
The historical FHIR-24911 application commit ab57a6ec66 updated source/profiling.html so the Full Structure row says the view is comprehensive "though inherited constraints are not presented." That commit did not update tools/templates/template-profile.html, whose generated profile-page snapshot descriptions still lacked the same caveat.

Additional context:
FHIR-I minutes from 2020-03-23 record the 7-0-0 decision to add the clarification to both core spec and IG template. The originating Zulip thread explains that hiding inherited constraints was a rendering choice to avoid overwhelming snapshot tables, while the generated StructureDefinition snapshot can still carry those constraints.

AutoFHIR reconciliation:
Updated the current profile-page template so both the Full Structure tab and the All view snapshot paragraph state that inherited constraints are not presented in that rendered view.

Recommendation:
Keep this source change. It completes the template-side part of the accepted clarification in the current FHIR checkout; no further core narrative change is needed because source/profiling.html already contains the note.
