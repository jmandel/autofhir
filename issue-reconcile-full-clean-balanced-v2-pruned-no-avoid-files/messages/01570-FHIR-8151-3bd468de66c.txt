FHIR-8151: Point site links to active spec search

Issue request:
FHIR-8151 was a Published/Persuasive FHIR-I change request from the 2015May DAF ballot asking to provide search capability across the FHIR DSTU and FHIR Continuous build sites so implementers and ballot reviewers could find content more easily. The Jira resolution accepted the request, and Grahame Grieve later commented that it was already done.

Initial application:
No source commit explicitly tagged FHIR-8151 was found. Current history shows the build later gained an active CI search page in source/search-build.html using a DuckDuckGo iframe, and the shared navbar already resolves its search icon through the publisher-provided search-location variable. However, the home page still sent its "search this specification" link to search.cfm, and the shared footer still relied on search-footer output that currently renders as the obsolete search.cfm target.

Additional context:
The current source includes search-build.html in publish.ini and the page hierarchy, so it is part of the built specification. Live checks showed build.fhir.org/search-build.html contains the active search iframe, while build.fhir.org/search.cfm is only the old "Still under development" stub and hl7.org/fhir/search.cfm is not found. Jira phrase searches found the same request in Published issues FHIR-7712 and FHIR-6849 plus Duplicate FHIR-7748; those are recorded as same-change-family context but are not independently decided by this commit.

AutoFHIR reconciliation:
This commit updates the home page and shared footer template to use [%search-location%], matching the navbar. That keeps CI links pointed at the active CI search page and lets published builds resolve to their configured release-specific search page instead of hard-coding the obsolete search.cfm path.

Recommendation:
Keep this source fix. It preserves the intended site search capability with a small build-scope link correction and avoids duplicating release-specific search URLs in page prose and footer markup.
