FHIR-17995: Align payment issuer search description

Issue request:
FHIR-17995 was Published/Persuasive with Modification for STU3 and asked to change PaymentReconciliation.organization to an issuer element. The approved resolution was to change .organization to paymentIssuer.

Initial application:
The Jira-tagged GF#17995 commit f369c813fb renamed the PaymentReconciliation example and spreadsheet source from organization to paymentIssuer. Current source retained the active PaymentReconciliation.paymentIssuer element, example usage, and the fhir.ini compatibility alias from PaymentReconciliation.organization to PaymentReconciliation.paymentIssuer, but the active payment-issuer SearchParameter still described the target as "The organization which generated this resource."

Additional context:
PaymentReconciliation is an active current resource in source/fhir.ini, and the search parameter bundle is current source for the built resource search parameters. Later FHIR-26601 expanded PaymentReconciliation to patient-payment scenarios and current paymentIssuer targets Organization, Patient, and RelatedPerson, so the old organization wording is now both a remnant of the pre-rename model and too narrow for current source. Direct Zulip and Confluence searches for FHIR-17995 found no contrary community discussion.

AutoFHIR reconciliation:
This commit changes the active PaymentReconciliation payment-issuer SearchParameter description to refer to the party generating the payment, matching the paymentIssuer element and avoiding stale organization-only wording. It does not touch historical release snapshots, unrelated resources with organization search parameters, or generated diagram artifacts.

Recommendation:
Keep this commit as-is. It completes the remaining current-source wording gap from the published FHIR-17995 rename while staying consistent with later patient-payment scope.
