FHIR-49440: Align NutritionOrder requester sources

Issue request:
FHIR-49440 is Applied/Persuasive for R6 NutritionOrder. The approved motion was to rename NutritionOrder.orderer to NutritionOrder.requester and rename the NutritionOrder search parameter from provider to requester so NutritionOrder follows the workflow request pattern and shared order searches can use the same requester parameter.

Initial application:
The current StructureDefinition already has NutritionOrder.requester mapped to Request.requester, and the NutritionOrder search parameter bundle already has id/code/expression NutritionOrder-requester/requester/NutritionOrder.requester. Git history shows commit de8f14ac79 changed those core definition and search parameter fields on 2025-02-25, but it did not update active examples, ActivityDefinition mapping text, or the workflow-warning suppression file that still referred to NutritionOrder.orderer.

Additional context:
source/fhir.ini actively includes nutritionorder and activitydefinition in the build. list-NutritionOrder-examples.xml lists the edited example instances as active NutritionOrder examples. nutritionorder-request-mapping-exceptions.xml already records the remaining legitimate requester type divergence as NutritionOrder.requester missing Organization, Patient, RelatedPerson, and Device, so the stale suppression for a different element name and old type text no longer matched the current source. Jira/community searches found no related final decision that narrows or reverses FHIR-49440.

AutoFHIR reconciliation:
This commit completes the requester rename across build-scope source by changing NutritionOrder examples from <orderer> to <requester>, updating the ActivityDefinition NutritionOrder mapping and rendered notes from tgt.orderer to tgt.requester, changing the search parameter description to requester, and removing/updating stale workflow-warning suppressions that still described NutritionOrder.orderer.

Recommendation:
Keep this commit as the completion of FHIR-49440. The authoritative element and search parameter were already renamed; these additional edits remove the remaining stale build-scope references without changing unrelated NutritionOrder semantics or the intentional fhir.ini compatibility aliases for prior-version diffs.
