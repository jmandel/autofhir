FHIR-37443: Correct Composition category mapping

Issue request:
FHIR-37443 was Applied/Persuasive for R5 by Structured Documents and requested that Composition mappings to DocumentReference be updated because DocumentReference had significantly changed. The issue specifically treated the DocumentReference-to-Composition mapping as the accurate source and asked for the Composition-to-DocumentReference mapping to mirror it.

Initial application:
The issue was discussed by SD in June 2022 and approved in January 2023. It appears to have been applied in HL7/fhir#2862, merged as 52710896cbe7dc61de095019446c49460bb05f28, which updated many Composition and DocumentReference reciprocal mapping rows. The current source still left Composition.category mapped to the misspelled target DocumenttReference.category, while DocumentReference.category correctly maps back to Composition.category.

Additional context:
Composition and DocumentReference are active resources in source/fhir.ini, so their StructureDefinition source files feed the current build. SD also created FHIR-40263 from the same meeting discussion for broader DocumentReference basedOn/relatesTo changes, but O&O resolved that issue as Not Persuasive/No Change; that later decision does not change the category mirror mapping. No relevant Zulip discussion was found for FHIR-37443.

AutoFHIR reconciliation:
This commit fixes only the stale Composition.category fhirdocumentreference mapping in source/composition/structuredefinition-Composition.xml, changing DocumenttReference.category to DocumentReference.category. No broader mapping changes were made because the PR-applied rows otherwise align with the current DocumentReference mapping or involve inherited/document-bundle fields that are not represented as Composition differential elements.

Recommendation:
Keep this source fix as-is. Future mapping cleanup, if desired, should be tracked separately and respect FHIR-40263's no-change decision for DocumentReference basedOn/relatesTo structure.
