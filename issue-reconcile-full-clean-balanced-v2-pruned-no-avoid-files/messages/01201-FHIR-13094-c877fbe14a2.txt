FHIR-13094: Finish DataElement collapse cleanup

Issue request:
FHIR-13094 was a Published/Persuasive with Modification OO change request from the DSTU2 ballot. It asked to eliminate the DataElement resource, use StructureDefinition logical models in its place, and add narrative describing how logical models are used to describe data elements; the final resolution was to remove DataElement and replace it with StructureDefinition logical models.

Initial application:
The issue was initially applied in source history by d0802c9b75, which explicitly cited #13094 and removed DataElement references from many current pages while updating the StructureDefinition context. The follow-up removal commit 29576ed0ef commented DataElement out of active fhir.ini resource/work-group/TLA entries and changed history links to point readers to StructureDefinition instead. Current source also has no source/dataelement resource directory.

Additional context:
Current build scope confirms StructureDefinition, the 11179 ElementDefinition profile, and the Coding and Quantity extension profiles are active in source/fhir.ini, while DataElement remains commented out. Current logical-model narrative already explains that logical models are StructureDefinitions with StructureDefinition.kind = logical, that they contain ElementDefinitions for the actual data elements, and that projects can use them as data dictionaries. A 2020 implementers Zulip thread confirms the intended post-removal interpretation: a data element is either a stand-alone logical model or a reference to an element in a resource, data type, profile, or logical model. Remaining DataElement strings in history, old-type registries, external LOINC example URLs, QUICK model content, and legacy SDC value set names were not changed because they are historical, external, or not the stale current-build guidance fixed here.

AutoFHIR reconciliation:
This commit removes DataElement from the active conformance hierarchy so it is no longer presented as a current resource. It also corrects active profile spreadsheet metadata that still described Coding and Quantity extensions as being for DataElement, and updates the active ISO 11179 ElementDefinition profile search paths from DataElement.element.mapping to ElementDefinition.mapping.

Recommendation:
Keep this source fix. It completes the current-build cleanup for FHIR-13094 without reopening historical or external references. Any future renaming of legacy SDC value set labels or external DataElement-looking canonical URLs should be handled as a separate terminology/content decision.
