FHIR-11609 + FHIR-53203: Align ActivityDefinition bodySite mapping

Attribution note: surfaced while reviewing FHIR-11609, but direct Jira backing for this change is FHIR-11609 + FHIR-53203.

Issue request:
FHIR-11609 is a Published/Persuasive CDS change request from DSTU2 asking that ActivityDefinition support bodySite for non-medication activities, specifically ProcedureRequest. The approved resolution was that bodySite would be added to support ProcedureRequest.

Initial application:
The issue was initially applied by SVN #10174, now git commit a0306a202b, which added ActivityDefinition.bodySite to the historical ActivityDefinition spreadsheet source. Later source refactors preserved ActivityDefinition.bodySite in source/activitydefinition/structuredefinition-ActivityDefinition.xml, and source/fhir.ini has active ActivityDefinition and ServiceRequest resource entries, so this source remains in current build scope.

Additional context:
ProcedureRequest has since been merged into ServiceRequest, and later OO decisions changed the target body-location model. FHIR-50355 clarified that ServiceRequest.bodyStructure is preferred over ServiceRequest.bodySite, and FHIR-53203 applied the R6 bodyStructure-as-CodeableReference direction for OO resources. Current ServiceRequest source now exposes ServiceRequest.bodyStructure as CodeableReference(BodyStructure) and no longer exposes ServiceRequest.bodySite, leaving the ActivityDefinition ServiceRequest mapping and bodySite comment stale.

AutoFHIR reconciliation:
This commit keeps ActivityDefinition.bodySite, because that is the seed issue's requested CDS capability, but updates its current ServiceRequest references. The element comment now points to ServiceRequest.code rather than nonexistent ServiceRequest.type, and the ServiceRequest ActivityDefinition mapping in both the .fhirmap source and rendered notes snippet now maps ActivityDefinition.bodySite into ServiceRequest.bodyStructure.concept instead of the removed ServiceRequest.bodySite.

Recommendation:
Keep this commit as-is. A broader review of the ActivityDefinition mapping snippets may still be useful because unrelated mappings such as locationReference also appear dated, but that is outside the FHIR-11609 bodySite reconciliation and should be handled under a separate issue or work-group review.
