FHIR-32445: Document AuditEvent outcome DICOM mapping

Issue request:
FHIR-32445 was Published/Persuasive with Modification for R5 after asking why AuditEvent.outcome used unusual numeric outcome codes. The final resolution required the AuditEvent outcome value set to use OperationOutcome issue-severity codes, the old AuditEvent outcome code system to retain only success, and the AuditEvent.outcome comment to document the DICOM numeric mapping: 0 to success, 4 to warning, 8 to error, and 12 to fatal.

Initial application:
Commit 04aebbe0d4 was explicitly tagged FHIR-32445 and changed the old AuditEvent outcome code system/value set by removing the minor, serious, and major numeric concepts and adding issue-severity to the value set. That initial application did not update source/auditevent/structuredefinition-AuditEvent.xml with the requested DICOM EventOutcomeIndicator mapping note. Later FHIR-39622 commits added success to issue-severity and removed the remaining separate AuditEvent success-code include, so the active value set now depends only on issue-severity.

Additional context:
source/fhir.ini actively maps auditevent=AuditEvent, so the edited StructureDefinition and AuditEvent outcome value set are current build inputs. The combined branch already contains FHIR-32447, which corrected the current outcome backbone/code model and required binding, and FHIR-32446, which audited the related minor/serious definition issue as resolved by FHIR-32445. Those related decisions support using the current issue-severity codes, not restoring DICOM numeric codes. No conflicting Zulip or Confluence evidence was found; Security block-vote/minutes evidence lists FHIR-32445/FHIR-32446 as approved/persuasive.

AutoFHIR reconciliation:
Updated the active AuditEvent StructureDefinition comments for AuditEvent.outcome and AuditEvent.outcome.code to include the missing DICOM AuditMessage EventOutcomeIndicator mapping note. No terminology source was changed because the current outcome value set already composes issue-severity, which now includes success, and the old numeric AuditEvent outcome code system is no longer an active source file.

Recommendation:
Keep this commit as-is. It completes the only remaining FHIR-32445 source gap in the current build while preserving the later issue-severity/success terminology model; do not reintroduce the old numeric AuditEvent outcome codes.
