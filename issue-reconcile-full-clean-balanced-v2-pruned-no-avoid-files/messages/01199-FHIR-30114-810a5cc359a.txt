FHIR-42946 + FHIR-42949: Align recommendation evidence extension usage

Attribution note: surfaced while reviewing FHIR-30114, but direct Jira backing for this change is FHIR-42946 + FHIR-42949.

Issue request:
FHIR-30114 was a Published/Persuasive FHIR-core change request asking to expand the context of use for cqf-strengthOfRecommendation and cqf-qualityOfEvidence beyond Attachment, with the approved resolution to support application on PlanDefinition.action.repeat().

Initial application:
The issue was applied to core by HL7/fhir PR #1143 and commit d639867be1, which changed source/profiles/clinicalreasoning-extensions-spreadsheet.xml so both extensions used Resource/* context rather than Resource. The current core checkout no longer defines these two extension StructureDefinitions in that active spreadsheet; the clinical reasoning pages instead link to the extension-pack definitions through [%extensions-location%].

Additional context:
The current FHIR Extension Pack owns the StructureDefinitions and, after Published/Persuasive FHIR-42946 and FHIR-42949, constrains both extension contexts to PlanDefinition.action. The core supporting-documentation topic remained broader than that current context: it illustrated cqf-qualityOfEvidence on an Attachment/documentation document and described qualityOfEvidence on DocumentReference and strengthOfRecommendation on RequestOrchestration.action. A Zulip thread that led to FHIR-30114 also supports the PlanDefinition-action interpretation: Bryn Rhodes explained that the ratings moved to PlanDefinition because they are aspects of the recommendation.

AutoFHIR reconciliation:
This commit updates built core narrative only. It changes the supporting-documentation example so the extensions appear on a PlanDefinition action and narrows the explanatory paragraph to recommendation evidence on PlanDefinition actions. It also narrows the clinical reasoning module extension descriptions and common-use-case row to PlanDefinition actions. These pages are in build scope through source/hierarchy.xml and the module page, and the edits are necessary because the current extension-pack definitions no longer allow the broader Attachment, DocumentReference, or RequestOrchestration examples.

Recommendation:
Keep this commit as-is. Do not re-expand the extension contexts in core; any future change to the allowed contexts belongs in the FHIR Extension Pack and should account for FHIR-42946 and FHIR-42949.
