FHIR-26065: Bind $versions output version codes

Issue request:
FHIR-26065 was Published/Persuasive for the R5 $versions operation. It requested correcting the output examples from valueString to valueCode, correcting the version-description language, and adding an explicit binding for the code-valued output versions.

Initial application:
Commit 556e177ba0, explicitly tagged FHIR-26065, added a required FHIR-version binding only to the default output parameter. It did not bind the repeated version output parameter. The valueCode example correction was later applied by FHIR-35928, and the source examples now already use valueCode.

Additional context:
FHIR-26067 and FHIR-35168 later changed the version terminology from publication.major/minor language to the current major.minor.patch-label model and added major.minor release-line codes to the FHIR-version code system. Therefore restoring the old FHIR-26065 wording target of publication.major would now conflict with current versioning guidance; the current major.minor wording is consistent with http.html and versions.html.

AutoFHIR reconciliation:
Added the same required http://hl7.org/fhir/ValueSet/FHIR-version binding to the $versions operation's repeated version output parameter that was already present on the default output parameter. The CapabilityStatement and OperationDefinition sources are active in source/fhir.ini, so this operation definition is in current build scope. No example or terminology wording change was made because those parts are already satisfied by later applied work.

Recommendation:
Keep this commit. If the work group wants a separate two-part-only value set rather than the existing FHIR-version value set plus major.minor documentation, handle that as a focused terminology decision; this reconciliation completes the missing binding in the current operation definition without reopening broader FHIR-version terminology.
