FHIR-14272: Reference ElementDefinition interpretation guidance

Issue request:
FHIR-14272 was Published with a Persuasive with Modification resolution for STU3. It asked to replace the broad statement that modifier elements or min=1 elements must be summary elements with wording scoped to resource and data type definitions, to avoid treating constraining profiles as independently changing isSummary, and to add a reference from ElementDefinition.isSummary to the ElementDefinition interpretation table. The resolution also said not to add a FHIRPath invariant and not to change the min cardinality wording to >=1.

Initial application:
The issue was initially applied by git-svn commit 0ee58a1919478a7b1de01e3dbe29b649b13080f6, "GF#14272 - improve wording", corresponding to svn revision 14311. That commit replaced the old broad sentence in source/datatypes/elementdefinition.xml with the scoped resource/data type definition rule, but it did not add the requested cross-reference to the interpretation table.

Additional context:
ElementDefinition is in current build scope through active source/fhir.ini entries for elementdefinition and ElementDefinition. source/datatypes/elementdefinition.xml feeds the ElementDefinition detailed descriptions, and source/elementdefinition.html contains the #interpretation section with the isSummary row and the dagger note that constraint definitions must match the base definition. The direct Zulip thread for the tracker confirms the intent: the rule applies to base definitions and profiles cannot change isSummary. Later issues FHIR-35855, FHIR-33148, and FHIR-46364 refined the same ElementDefinition.isSummary comments; this reconciliation preserves their current wording and only adds the missing cross-reference.

AutoFHIR reconciliation:
Added a short "See also" sentence to ElementDefinition.isSummary comments linking to elementdefinition.html#interpretation, so readers of the detailed description can find the table that explains how isSummary is interpreted in type and constraint definitions. No invariant or semantic rule change was added.

Recommendation:
Keep this source fix as-is. It completes the omitted cross-reference from FHIR-14272 while preserving later FHIR-I decisions about isSummary wording and exceptions; no separate action is needed for the related later issues from this reconciliation.
