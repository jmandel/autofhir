FHIR-12198: Clarify default slice discriminator constraints

Issue request:
FHIR-12198 was a Published/Persuasive FHIR-core StructureDefinition issue for DSTU2. It asked for a profiling section describing default slices, identified by slice name "@default", allowed only with closed slicing, reusable through re-slicing, and prohibited from declaring a fixed value or value set binding for discriminator elements.

Initial application:
The issue appears to have been applied by svn revision 11245 / git commit 26c5c91f72f705df49bc8b70965ba2889cb78926, which added the Default Slice section to source/profiling.html and the @default re-slicing note. That commit implemented the section, @default naming, closed-slicing requirement, and no-fixed-discriminator wording, but it omitted the resolution's value set binding prohibition.

Additional context:
The active profiling page is in build scope through source/hierarchy.xml and many current page references. Later discriminator guidance, especially the FHIR-25206 family already represented on the combined branch, now defines value/pattern slicing in terms of fixed[x], pattern[x], or required value set bindings. That makes the original omission semantic rather than cosmetic: a default slice should be the residual "all others" bucket and must not itself constrain discriminator values using the same mechanisms that identify ordinary value slices.

AutoFHIR reconciliation:
This commit updates the Default Slice rule in source/profiling.html to prohibit fixed[x], pattern[x], or a required value set binding on discriminator elements. The hunk is intentionally limited to the existing default-slice rule and does not duplicate adjacent slicing or binding guidance.

Recommendation:
Keep this source fix. No broader StructureDefinition or ElementDefinition source change is needed for FHIR-12198; related later discriminator issues remain separately audited and should not be duplicated here.
