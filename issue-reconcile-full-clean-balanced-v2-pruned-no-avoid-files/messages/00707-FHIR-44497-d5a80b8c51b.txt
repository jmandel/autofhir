FHIR-44497: Use sequence for ExampleScenario step labels

Issue request:
FHIR-44497 is an Applied/Persuasive FHIR-I change request asking ExampleScenario.process.step.number to say "The sequence number of the step, e.g. 1.2.5." instead of "The sequential number of the step, e.g. 1.2.5." because "sequential" implies ordering that is not required.

Initial application:
Jira records the application as Git master ae433960ed. That commit changed the ElementDefinition definition in source/examplescenario/structuredefinition-ExampleScenario.xml, but left the same element's short label as "Sequential number of the step" and left the checked-in examplescenario.svg title with the old definition wording.

Additional context:
source/fhir.ini actively includes examplescenario as the ExampleScenario resource, marks ExampleScenario normative, and lists ExampleScenario.process.step.number in the resource element mappings, so the XML source is in current build scope. FHIR Workflow minutes from 2024-03-11 record FHIR-44497 as Persuasive, matching the Jira vote. Direct Zulip and Confluence full-text searches found no conflicting discussion. The SVG is generated-looking, but this commit updates it only to keep the checked-in diagram title aligned with the independently necessary authoritative XML fix.

AutoFHIR reconciliation:
Changed ExampleScenario.process.step.number's short label from "Sequential number of the step" to "Sequence number of the step" and updated the checked-in examplescenario.svg tooltip from the stale definition text to "The sequence number of the step, e.g. 1.2.5." The definition line already matched the Jira-proposed wording.

Recommendation:
Keep this commit as-is. It completes the applied terminology clarification across the active authoritative ExampleScenario source and the adjacent checked-in diagram artifact without broadening the issue beyond the accepted wording change.
