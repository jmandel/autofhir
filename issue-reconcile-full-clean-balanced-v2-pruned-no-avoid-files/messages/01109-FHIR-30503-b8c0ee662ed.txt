FHIR-30503: Restore DeviceDefinition packaging scope

Issue request:
FHIR-30503 was Published/Persuasive with Modification for R5. It requested a recursive DeviceDefinition.packaging backbone with identifier, type, count, distributor, UDI device identifier, and nested packaging; it also required DeviceDefinition scope text clarifying that custom repackaging is out of scope and packaging for kits belongs at the kit level, while root DeviceDefinition.quantity and root DeviceDefinition.distributor should not remain.

Initial application:
The issue was initially applied by git commit f662eb0f7a, which added the recursive packaging backbone and a Scope and Usage sentence about kit-level packaging and custom repackaging. The structural elements have since been refined by later DeviceDefinition packaging tickets, but the package-scope sentence was overwritten when the broader FHIR-24936 DeviceDefinition scope text was applied in commit 578361a900.

Additional context:
The current build includes DeviceDefinition as an active resource in source/fhir.ini. The current StructureDefinition already has DeviceDefinition.packaging 0..*, DeviceDefinition.packaging.packaging as a contentReference back to DeviceDefinition.packaging, packaging.count as integer, packaging.distributor only under packaging, and no root DeviceDefinition.quantity or root DeviceDefinition.distributor. FHIR-29727 was withdrawn as superseded by FHIR-30503, and FHIR-25036 is relevant only as background because FHIR-30503 explicitly limited distributor to the packaging/logistics context.

AutoFHIR reconciliation:
This commit restores only the missing Scope and Usage clarification for DeviceDefinition.packaging. It does not alter the already-correct structural packaging elements or generated-looking diagram artifacts.

Recommendation:
Keep this commit as-is. It preserves the later DeviceDefinition scope rewrite while restoring the FHIR-30503 packaging boundary that implementers need in the current built source.
