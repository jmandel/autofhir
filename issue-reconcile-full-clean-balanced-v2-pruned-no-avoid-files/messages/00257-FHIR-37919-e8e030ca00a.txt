Issue request:
FHIR-37919 was a Published/Persuasive BR&R R5 change request to make "status" a search parameter for AdministrableProductDefinition, ClinicalUseDefinition, Ingredient, and ManufacturedItemDefinition because each medication-definition resource has a status element.

Initial application:
Commit 298af2883c636f13c57d78e8e7e366caa5d46548 added the requested status search parameters to the four resource search-parameter bundles. Current source retained those entries and source/fhir.ini actively lists all four resources, but the ClinicalUseDefinition entry had a ClinicalUseDefinition-status id/path/expression paired with the ManufacturedItemDefinition-status canonical URL.

Additional context:
BR&R minutes for 2022-08-16 record the motion to approve FHIR-37919 with a 16-0-0 vote. Community searches found no relevant Zulip discussion changing the Jira/source conclusion. The same historical source commit also mentioned FHIR-37881 for a ManufacturedItemDefinition name search parameter, but that is a separate issue and is not decided here.

AutoFHIR reconciliation:
Changed source/clinicalusedefinition/bundle-ClinicalUseDefinition-search-params.xml so the ClinicalUseDefinition status SearchParameter URL matches its id, path extension, and expression. The other three status search parameters were left unchanged because their id, URL, and expression already match their resources.

Recommendation:
Keep this source fix as-is. It completes the applied FHIR-37919 search-parameter change in current core source; no additional core source edits were found for this issue.
