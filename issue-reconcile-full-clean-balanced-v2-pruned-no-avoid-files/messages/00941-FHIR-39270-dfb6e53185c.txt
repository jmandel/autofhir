FHIR-39270: Clarify canonical version form uniqueness

Issue request:
FHIR-39270 was Published/Persuasive with Modification for R5. It asked for conformance language that canonical resources with the same url and version remain materially the same apart from logical id, and that the resource type + url + version combination is normally unique while allowing defined multiple-form exceptions.

Initial application:
The Jira comment records application in commit 49b86f8a69. That commit added canonicalresource.html localization guidance and links from CanonicalResource and MetadataResource elements with local-usage implications, but the current source did not retain the requested paragraph about resource type + url + version uniqueness and multiple same-version forms.

Additional context:
Later source changes kept the localization guidance and added status-specific clarification in FHIR-47235 and canonical-version terminology in FHIR-47363. FHIR-52895 later expanded references.html canonical version matching guidance but still described two resources with a full version as generally erroneous. FHIR-48958 is an unresolved broader R6 request for detailed rules around canonical version uniqueness, so this reconciliation stays within the already-published FHIR-39270 clarification and does not attempt to define per-resource source-of-truth or computable/executable form policy.

AutoFHIR reconciliation:
Added the missing canonicalresource.html paragraph stating that resource type + canonical URL + version is usually unique on a server, while ValueSet expansions, generated StructureDefinition snapshots, assembled/unassembled Questionnaires, and similar forms can legitimately share a canonical version when their meaning and definition remain identical. Updated references.html so the canonical matching guidance treats duplicate full versions as an error only when meaning or definition changes, and links back to the canonical resource localization guidance for legitimate generated or assembled forms.

Recommendation:
Keep this commit. FHIR-39270 is now represented in the current build-scope canonical resource narrative and the neighboring canonical reference guidance, while the broader unresolved FHIR-48958 policy work should remain a separate future work-group decision.
