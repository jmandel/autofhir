FHIR-15566: Fix Device UDI mapping link

Issue request:
FHIR-15566 was a Published/Persuasive FHIR-core Device issue for STU3. It reported that section 8.14.1 Scope and Usage had a nonfunctional hyperlink to the Unique Device Identifier (UDI) material, and the approved resolution was to fix the link.

Initial application:
The issue was pre-applied in git commit 801c2d12ffb45831ef24eb630cd668446346d300, which changed the old Scope and Usage UDI href from the invalid device.html# 8.14.3.2.3 target to #udi and added the corresponding udi anchor in the Device notes. Current source no longer contains the old invalid 8.14.3.2.3 or 5.11.3.2.2 Device UDI anchors.

Additional context:
Device is active in the current build through source/fhir.ini. The current Scope and Usage source in source/device/device-introduction.xml links Unique Device Identifier (UDI) to device.html#udi, and source/device/device-notes.xml defines the udi anchor. While checking the same build-scoped Device UDI narrative, reconciliation found an adjacent malformed Device UDI Mapping link in source/device/device-notes.xml: the href included a trailing parenthesis as device-mappings.html#udi), while the parallel Device StructureDefinition comment already used the correct device-mappings.html#udi target. Related link-family issues FHIR-13398 and FHIR-15774 concern the older inactive Device UDI section anchors; FHIR-15774 is already represented on the combined branch.

AutoFHIR reconciliation:
This commit fixes the remaining build-scoped Device UDI narrative hyperlink by changing source/device/device-notes.xml from device-mappings.html#udi) to device-mappings.html#udi. It leaves the already-correct Scope and Usage link and udi anchor unchanged.

Recommendation:
Keep this source fix as-is. It is a narrow non-substantive correction in the same active Device UDI link family, and no further FHIR-core change is needed for FHIR-15566 unless a full generated-link check finds another Device UDI hyperlink problem.
