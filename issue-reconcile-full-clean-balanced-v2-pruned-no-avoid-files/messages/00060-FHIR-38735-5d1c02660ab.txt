FHIR-38735: Align dateTime offset comment

Issue request:
FHIR-38735 was a Published/Persuasive R5 technical correction for the dateTime primitive regex. The reported R5 ballot regex rejected date-only dateTime values such as 1990-01-01 unless a timezone suffix was present; the final Jira comment confirmed that timezone is only permitted when a full time is specified and that the earlier attachment's regex direction should be used.

Initial application:
Commit c5ab3c3dec1d1498d8ea238a596046692a38c501 applied the issue by changing source/datatypes/primitives.xml so date-only and partial-date values no longer required a timezone suffix. That application did not update the dateTime row's Comments cell, which still said that UTC offset was allowed for dates and partial dates.

Additional context:
FHIR-I minutes for January 2023 record the issue first as a technical correction needing the correct regex and then as auto-approved. Later Applied/Persuasive issue FHIR-52878 and commit 65790c792003e57c5c12a0b1243f4539922fa008 moved the offset group into the time portion of the regex, so current source permits date-only values and rejects timezone offsets on date-only and partial-date values. The related Zulip discussion for FHIR-52878 also records Grahame's clarification that the regex need not enforce every dateTime rule, which explains why this reconciliation should not further tighten the optional timezone-on-full-time behavior.

AutoFHIR reconciliation:
Updated only the active primitive datatype spreadsheet comment for dateTime from saying UTC offset is allowed for dates and partial dates to saying it is allowed only when a time is specified. The current regex and datatype narrative already express the issue's main correction, so no regex or prose expansion was needed.

Recommendation:
Keep this commit. It removes the remaining stale source-level contradiction while preserving the later applied FHIR-52878 regex behavior; no further core source work is recommended for FHIR-38735 unless the work group decides separately to make the regex enforce timezone presence whenever a time is present.
