FHIR-36017: Clarify Endpoint entered-in-error status

Issue request:
FHIR-36017 was Applied/Persuasive with Modification for Endpoint.period. It requested Endpoint notes clarifying planned lifecycle period versus transient availability, a new Endpoint.availability element, 0..1 Availability cardinality on HealthcareService/Location/PractitionerRole, Endpoint.status wording cleanup including removal of test from the short display, and a generic entered-in-error definition that is not specific to a patient's medical record.

Initial application:
The main application was commit 738b6742876f6eb046705eccefc9a5a7ea812a59, merged by 0cf428e3e2873b4d65e42acfdd11e7e6f083edd9. It added Endpoint notes, Endpoint.availability, updated Endpoint.status definition/comment text, and changed the Availability cardinalities on HealthcareService, Location, and PractitionerRole. That commit did not update source/endpoint/codesystem-endpoint-status.xml, so the entered-in-error code still said the instance should not have been part of a patient's medical record.

Additional context:
Endpoint is an active current-build resource in source/fhir.ini. FHIR-32824 supplied the earlier status-versus-temporary-downtime distinction, FHIR-25381 supplied the Availability datatype used by this resolution, and FHIR-27934 removed the test status into Endpoint.environmentType. The May 2023 PA WGM minutes confirm that FHIR-36017 would add Endpoint.availability, clarify Endpoint.period and Endpoint.status, and correct related Availability cardinalities. A Zulip outreach message found feedback context but no conflicting decision.

AutoFHIR reconciliation:
This commit changes the active Endpoint CodeSystem definition for entered-in-error to say that the endpoint record should not have been created and should not be considered valid. This is the only remaining semantic gap found in the current source; the other FHIR-36017 changes are already present in active resource definitions, and generated-looking SVG cardinality artifacts were not edited.

Recommendation:
Keep this source fix. It directly completes the Applied Jira resolution without reopening the broader Endpoint.period policy or making optional editorial changes.
