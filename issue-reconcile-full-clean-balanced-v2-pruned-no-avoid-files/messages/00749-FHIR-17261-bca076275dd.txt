FHIR-17261: Move eligibility preauth reference under insurance

Issue request:
FHIR-17261 was Published/Persuasive for STU3. It asked that, because EligibilityResponse may include multiple coverages for the same or downstream payors, PreAuthRef and Authorization information move from the response root to the insurance level alongside Coverage.

Initial application:
The Jira-tagged tracker commit 10ac2496c7 applied the multi-coverage restructuring in the old EligibilityResponse spreadsheet: inforce moved under insurance and authorization details moved under insurance detail, but preAuthRef was only reordered and remained EligibilityResponse.preAuthRef. FHIR-16936 later renamed the resource through b165b5fdd3, carrying the same root preAuthRef forward as CoverageEligibilityResponse.preAuthRef. FHIR-17473 then renamed insurance.detail to insurance.item, leaving the authorization detail elements correctly under insurance.item.

Additional context:
The current build actively includes CoverageEligibilityResponse, while the old EligibilityResponse spreadsheet is out of build scope. Current source already has repeatable CoverageEligibilityResponse.insurance entries and per-item authorization details, but the single root CoverageEligibilityResponse.preAuthRef was still ambiguous when more than one coverage is returned. Jira, Zulip, and Confluence searches found no later decision reversing the per-coverage placement; the only related Zulip context confirmed preAuthRef as a string used in preauthorization workflows rather than a resource Reference.

AutoFHIR reconciliation:
Moved preAuthRef into CoverageEligibilityResponse.insurance as CoverageEligibilityResponse.insurance.preAuthRef, preserving its 0..1 cardinality and mappings while making it specific to the coverage/insurance entry. Updated the CoverageEligibilityResponse diagram and the checked-in FHIR model definition so the build-visible supporting artifacts match the authoritative StructureDefinition source.

Recommendation:
Keep this commit as-is. It completes the published tracker intent without changing the already-correct authorizationRequired, authorizationSupporting, and authorizationUrl placement under insurance.item.
