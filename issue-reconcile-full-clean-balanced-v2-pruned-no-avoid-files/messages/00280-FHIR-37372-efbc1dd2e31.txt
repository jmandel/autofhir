FHIR-37372: Clarify MedicationStatement effective timing

Issue request:
FHIR-37372 was a Published Pharmacy change request, resolved Not Persuasive with Modification for R5, asking how to record both a MedicationUsage usage period and the last administration time when effective[x] has cardinality 0..1. The accepted resolution was to represent those facts as two separate medication usage statements and update the effective[x] comments with guidance.

Initial application:
The historical application commit 0e463239a18c2754e691aecf97c70119c5891b41 was tagged with FHIR-37372, FHIR-35899, and FHIR-36001, but the visible MedicationUsage source changes added partOf and schema metadata rather than updating the effective[x] comment requested by FHIR-37372. In the current source, MedicationUsage has been normalized back to the active MedicationStatement resource, and MedicationStatement.effective[x] still had the older period-focused comment with no guidance for simultaneously recording a usage period and a last administration time.

Additional context:
FHIR-35899, resolved and published the day before FHIR-37372, asked how to store the last time a medication was given and established that effectiveDateTime should be used for the last time the medication was taken or administered. Pharmacy WGM minutes reference that decision. FHIR-37372 was created while resolving FHIR-35899 and adds the coupled case where both a usage period and a last administration time must be recorded. The active build scope is MedicationStatement, as source/fhir.ini lists medicationstatement=MedicationStatement and the resource abbreviation MedicationStatement=mst.

AutoFHIR reconciliation:
Updated the authoritative MedicationStatement StructureDefinition effective[x] comment to describe effectiveDateTime, effectivePeriod, and effectiveTiming use, to retain the effectivePeriod.end guidance, and to explicitly say that a usage period plus a distinct last administration date/time requires two separate MedicationStatement resources. Updated the MedicationStatement Event mapping exception copy of the same comment so the resource mapping metadata remains consistent with the StructureDefinition.

Recommendation:
Keep this source-changing commit. It directly applies the published Pharmacy clarification in the current active MedicationStatement source and avoids adding a redundant element or changing effective[x] cardinality.
