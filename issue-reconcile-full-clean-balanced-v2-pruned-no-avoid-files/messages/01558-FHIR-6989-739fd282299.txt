FHIR-6989: Correct search response HTTP headers

Issue request:
FHIR-6989 was a Published/Persuasive FHIR-core change request for the 2015May Developer Overview search-response example. It reported that, unlike adjacent examples, the Search Response example lacked associated HTTP headers and asked to add them for completeness and consistency.

Initial application:
The Jira comment records svn revision 6416, and git-svn commit d39898a62fc28e007c72230a4001d4bac8f0503f (#6989) added HTTP/1.1, Content-Length, Content-Type, Last-Modified, and blank-line header rows to source/overview-dev.html. The current source retained those rows, but the Content-Type still advertised XML while the example body is JSON, and the Last-Modified header date no longer matched the Bundle.timestamp described by the immediately following notes.

Additional context:
source/overview-dev.html is in the current build scope: publish.ini includes overview-dev.html and source/hierarchy.xml lists it as the Developer Introduction page. Later work in the same example, including FHIR-7272, corrected line references after the header-bearing example evolved, but did not address the stale header values. Jira, Zulip, and Confluence searches found no later decision saying the search-response headers should remain inconsistent with the JSON body or timestamp.

AutoFHIR reconciliation:
Updated only the Search Response header values in source/overview-dev.html: Content-Type now uses application/fhir+json for the JSON Bundle example, and Last-Modified now uses Tue, 19 Aug 2014 15:49:30 GMT to match the Bundle.timestamp line that the notes describe as matching the HTTP header.

Recommendation:
Keep this source fix. It completes the historical #6989 header addition without changing the example structure or reopening the neighboring overview-dev line-number issues.
