FHIR-18030: Update VisionPrescription patient search wording

Issue request:
FHIR-18030 was a Published FHIR-core Change Request for VisionPrescription, resolved Persuasive with Modification, asking that VisionPrescription.dispense be renamed because the old name implied an order or instruction to dispense rather than a reusable authorization. The approved resolution was to change .dispense to .lensSpecification.

Initial application:
The main rename was applied in git commit 9c9403324df70351bf59981a05828a59d6b2b723, whose message included GF#18030 and changed VisionPrescription examples and the then-authoritative spreadsheet from dispense to lensSpecification. Follow-on R3/R4 mapping commits preserved the old VisionPrescription.dispense.base name only as an explicit historical mapping alias.

Additional context:
The current build has VisionPrescription active in source/fhir.ini, and the current StructureDefinition and examples already use VisionPrescription.lensSpecification. The active VisionPrescription search-parameter bundle still described the patient search parameter as listing "dispenses," even though the search expression is VisionPrescription.patient and the resource now represents vision prescriptions/authorizations rather than dispense events. Later work, including FHIR-51718, continued to update this same search-parameter bundle, confirming it is current source rather than obsolete output. Zulip and Confluence searches found no conflicting community record.

AutoFHIR reconciliation:
This commit updates the VisionPrescription patient SearchParameter description in source/visionprescription/bundle-VisionPrescription-search-params.xml from "list dispenses" to "list vision prescriptions," removing the remaining stale wording from active conformance source while leaving the intentional R3/R4 mapping alias alone.

Recommendation:
Keep this commit as-is. No broader VisionPrescription rename work is needed in core source; future reviewers should treat the fhir.ini VisionPrescription.dispense.base entry as historical version mapping, not current resource wording.
