FHIR-36684: Align not-in modifier type summary

Issue request:
FHIR-36684 was Published/Persuasive with Modification for R5. It asked FHIR-I to clarify which search-parameter types support `:missing`, fix the `combination` typo to `composite`, define general modifier behavior including server support for non-standard type/modifier combinations, state that special search parameters must define their own allowed modifiers and meanings, and show the modifier/type matrix for all defined modifiers.

Initial application:
The modifier clarifications were applied to `source/search.html` through a series of 2022 search-page editor commits rather than one clean key-only patch: the current page has the general modifier rules, the explicit `special` rule, the corrected `composite` terminology, the modifier/type summary table, and detailed per-modifier sections including `:missing`. An explicit Jira-tagged commit, 7c3f73fb1f51cbbb40b332c19799a40dbab2bfaf, exists in the history but touched adjacent search/reference wording rather than the core modifier matrix checked here.

Additional context:
FHIR-22690 had introduced draft reference-search `:in` behavior for Group/List membership, which is why FHIR-36684's original matrix included reference support for `in` and `not-in`. FHIR-37846 later superseded that approach by replacing reference-search membership modifiers with the standard `_in` search parameter while retaining `_list`; the combined branch already contains a separate FHIR-37846 reconciliation commit, so this seed commit does not republish that issue. After those later decisions, the current detailed `not-in` section correctly limited `:not-in` to token ValueSet membership, but the FHIR-36684 summary table still said `not-in` was also allowed for reference parameters.

AutoFHIR reconciliation:
This commit updates the active FHIR core search page's modifier/type summary row for `not-in` from `reference, token` to `token`. That makes the FHIR-36684 summary table consistent with the detailed `not-in` prose and with the later FHIR-37846 `_in` membership model, avoiding a misleading implication that reference search parameters still support `:not-in`.

Recommendation:
Keep this commit as-is. The change is a narrow consistency correction in the authoritative search page; do not reintroduce reference support for `:in` or `:not-in` unless FHIR-I makes a new decision to move membership behavior away from `_in`.
