FHIR-18357: Clarify modifier extension warning

Issue request:
FHIR-18357 was a Published/Persuasive STU3 technical correction for the FHIR-core extensibility page asking to improve the wording of the sentence that called a constructed primitive value "a bad idea" and noted that the result would be a disallowed modifier extension.

Initial application:
The request appears to have been partially applied in git commit 7bf7397f4a965784698e0d343f8a96789cdf4942, which changed the sentence from "both a bad idea, and a modifier extension, which is not allowed on data types" to "both a bad idea as well as a modifier extension, which is not allowed on simple data types." That captured the intended simple-datatype scope but left the awkward "both ... as well as" construction and the less direct "which" wording.

Additional context:
The current source file is in the active build surface because source/fhir.ini maps the Extension datatype page to extensibility. A later Published issue, FHIR-25431, globally standardized "data type" to "datatype" and commit 8592e1207273b786db340efb927bb6d1dc9756c9 applied that spelling to this sentence, so this reconciliation preserves "simple datatypes" rather than reverting to the exact 2018 proposed spelling. Direct Zulip and Confluence searches found no FHIR-18357 discussion or conflicting community guidance.

AutoFHIR reconciliation:
This commit completes the requested non-substantive wording cleanup in source/extensibility.html by removing the redundant "both" and naming modifier extensions directly: "modifier extensions are not allowed on simple datatypes."

Recommendation:
Keep this source change as-is. It is a narrow narrative correction on an active current-build page, preserves the later datatype terminology decision, and does not change conformance semantics.
