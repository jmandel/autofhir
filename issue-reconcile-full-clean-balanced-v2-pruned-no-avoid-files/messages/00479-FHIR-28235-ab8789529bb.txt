FHIR-28235: Align Communication scope timing wording

Issue request:
FHIR-28235 was an Applied Patient Care change request for Communication. It asked to clarify confusing Communication introduction text, especially the statement that the resource is a record even when communication is planned or failed and the explanation of whether Communication can represent an actual exchange. The final Persuasive with Modification resolution approved wording that Communication records a communication that has occurred or where the communication process has at least initiated, and that it need not represent the actual flow but may do so for some use cases such as secure provider-patient messaging.

Initial application:
Commit 40aa5c88300a803dc5d821194e74821ab60e2340 applied FHIR-28235 together with FHIR-40214 by updating the active Communication Boundaries and Relationships paragraph to the approved process-initiated and actual-flow wording. The current source still retained the older Scope and Usage sentence, "This resource is a record of a communication even if it is planned or has failed," so the issue was only partially applied across the same built narrative page.

Additional context:
FHIR-40214 and duplicate background issues FHIR-30393/FHIR-34111 established that Communication may represent correspondence occurring with an interaction, while FHIR-28235 narrowed the first sentence away from future "will occur" wording to communication that has occurred or at least initiated. FHIR-40760 previously touched the same Boundaries paragraph; a prior AutoFHIR reconciliation restored the same final FHIR-28235/FHIR-40214 wording there. The original Zulip thread confirms the confusion came from trying to model clinical-email-style Communication content and not transport-layer mechanics. source/fhir.ini lists communication=Communication as an active resource, so source/communication/communication-introduction.xml is current build input.

AutoFHIR reconciliation:
This commit updates the remaining Scope and Usage sentence in source/communication/communication-introduction.xml to the final FHIR-28235 process-initiated wording, removing the stale suggestion that merely planned communications are in scope while preserving support for communications whose process has started but may fail.

Recommendation:
Keep this source fix. It completes the applied Jira decision on the authoritative Communication narrative page and avoids a contradiction between Scope and Usage and Boundaries and Relationships. No generated artifacts or external repositories need separate updates.
