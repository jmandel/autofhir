FHIR-32447: Require AuditEvent outcome code

Issue request:
FHIR-32447 was Published/Persuasive with Modification for R5 after asking why AuditEvent.outcome used an extensible outcome binding. The accepted resolution replaced the old outcome CodeableConcept with an outcome backbone containing a mandatory primitive code with required binding to the AuditEvent outcome value set and repeatable outcome detail CodeableConcept entries with an example binding.

Initial application:
No explicit FHIR-32447-tagged source commit was found. Commit a4a8e4475f applied nearby AuditEvent structural work and implicitly changed AuditEvent.outcome to a backbone with code/detail children, but it left the old outcome binding path in place. Commit d7fdf7acfe then changed that binding from extensible to preferred, so the required binding and primitive-code datatype from FHIR-32447 were still not applied in the current source.

Additional context:
source/fhir.ini actively maps auditevent=AuditEvent, so the AuditEvent StructureDefinition, examples, value set source, and checked-in diagram are current build inputs. FHIR-32445 and FHIR-39622 later moved AuditEvent outcome terminology away from DICOM numeric outcome codes to the issue-severity code system with success included; that supports using success/error primitive codes in examples and does not override FHIR-32447's required binding decision. Security block-vote evidence lists FHIR-32447 in the approved September 2021 AuditEvent block, and no conflicting Zulip or Confluence discussion was found.

AutoFHIR reconciliation:
Changed AuditEvent.outcome.code from Coding/preferred to primitive code/required, updated the outcome value set metadata so it is no longer labeled as an example value set, removed stale DICOM binding metadata from that outcome binding, and corrected outcome/detail prose that still pointed to nonexistent outcome.text or details.text paths. Updated all AuditEvent examples that populate outcome.code to use success/error primitive codes from the current issue-severity value set. Updated the checked-in AuditEvent SVG only to keep its displayed datatype, binding strength, detail link, and tooltip aligned with the authoritative StructureDefinition change.

Recommendation:
Keep this commit as-is. It completes the final FHIR-32447 model decision in the active AuditEvent source and keeps examples consistent with the later outcome terminology decisions; any broader review of AuditEvent outcome terminology should be handled under a separate issue.
