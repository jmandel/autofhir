FHIR-25431: Normalize datatype spelling in narrative pages

Issue request:
FHIR-25431 is a Published/Persuasive FHIR-I technical correction, raised in R4 and applied for R5, asking the datatype page and possibly related pages to pick one spelling for "datatype" versus "data type" and use it consistently.

Initial application:
The explicit Jira-tagged application was git commit 8592e1207273b786db340efb927bb6d1dc9756c9 on 2022-08-31. That commit changed the datatype page title from "Data Types" to "Datatypes" and normalized many source HTML narrative pages from "data type(s)" to "datatype(s)". Later edits to active narrative pages reintroduced isolated two-word forms.

Additional context:
FHIR-I minutes from 2020-01-13 contain a shorthand note for FHIR-25431 saying `Using "data type" Will auto approve`, but the later published source application chose `datatype(s)` and R5 published datatypes.html uses "Datatypes" in the page title and summary. No later source history found a reversal of that applied/published convention. The remaining exact two-word hits in current source/*.html after this reconciliation are an external IG title and a generic patient-facing phrase, not references to the core FHIR datatype term.

AutoFHIR reconciliation:
This commit normalizes active narrative source pages that still used the FHIR term as "data type(s)" to the applied/published "datatype(s)" convention. The changes are wording-only across source/datatypes.html, source/metadatatypes.html, source/dosage.html, source/fhirpatch.html, source/elementdefinition.html, source/rdf.html, source/operations.html, source/search.html, source/history.html, source/terminologies.html, and source/exchanging.html.

Recommendation:
Keep this source-changing correction as-is to preserve the R5-applied spelling convention. If the work group now wants the two-word spelling instead, that should be a separate human editorial-policy decision because it would reverse the published FHIR-25431 application rather than merely completing it.
