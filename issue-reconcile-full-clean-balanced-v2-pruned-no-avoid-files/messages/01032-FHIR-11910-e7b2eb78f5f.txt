FHIR-11910: Mark CodeSystem value sets immutable

Issue request:
FHIR-11910 was a Published/Persuasive vocabulary issue asking whether a ValueSet whose content logical definition is all codes in a code system should be immutable. The accepted resolution narrowed that rule: when a ValueSet is referred to from CodeSystem.valueSet, it SHALL be immutable and SHALL only reference that code system; otherwise immutable remains at the author's discretion.

Initial application:
The Jira comments record the original application as SVN revision 10165. That pre-git application is preserved in the current CodeSystem.valueSet comment, and FHIR-15587 later applied the explicit "all codes from this code system and only codes from this code system, and it SHALL be immutable" wording in SVN revisions 13127/13130. Current git history does not contain a commit that mentions FHIR-11910, but commit 27b184d047 later refined the same CodeSystem.valueSet text for FHIR-36837 without removing the immutability requirement.

Additional context:
The Zulip Task 11910 thread confirms the work group deliberately rejected making every "all codes" CLD immutable and instead limited the SHALL to the CodeSystem.valueSet case. source/fhir.ini places the edited resource folders in the active [resources] set, and fivews in the active [logical] set. Current build spot checks showed active CodeSystem.valueSet pairs such as task-business-status and resource-status still published with immutable false or absent on the referenced all-codes ValueSet, so the rule text and individual conformance resources had diverged.

AutoFHIR reconciliation:
This commit marks 62 active, local, all-codes ValueSet sources as immutable. Each edited ValueSet is the local target of a CodeSystem.valueSet declaration, its compose has a single include for that CodeSystem.url with no concepts, filters, or nested value sets, and the source file is in current build scope. The change only adds missing <immutable value="true"/> elements or changes existing false values to true; it does not edit disabled, archived, out-of-build, external, generated-only, or non-all-code ValueSet cases.

Recommendation:
Keep this commit. It restores consistency between the normative CodeSystem.valueSet rule and the current conformance resources, while preserving the FHIR-11910/FHIR-15587/FHIR-36837 scope that immutable is mandatory only for ValueSets nominated by CodeSystem.valueSet. Future terminology generation or validation should enforce this check so newly added CodeSystem.valueSet pairs do not regress.
