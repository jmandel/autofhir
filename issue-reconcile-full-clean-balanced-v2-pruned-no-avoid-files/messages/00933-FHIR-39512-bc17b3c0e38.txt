FHIR-39512: Align Transport with event semantics

Issue request:
FHIR-39512 was Applied with a Persuasive with Modification resolution for R6. It asked that Transport be treated as an Event resource rather than a Request resource: keep instantiatesCanonical renamed as instantiates, remove instantiatesUri, restrict basedOn to the approved request/Task targets, remove intent and priority, and remove Request-pattern statements and mappings that implied Transport spans both request and event worlds.

Initial application:
Commit 747bf88902d857ee5e0f9dd4df216cccc62b5949 renamed Transport.instantiatesCanonical to Transport.instantiates, removed Transport.instantiatesUri, removed Transport.intent and Transport.priority, and restricted Transport.basedOn target profiles. Later Transport commits for FHIR-50911, FHIR-51849, and FHIR-53052 removed additional request elements and Request workflow mappings. Current source still retained stale request-pattern prose in Transport.basedOn and the Transport narrative, and still published the orphaned TransportIntent CodeSystem/ValueSet that had only supported the removed Transport.intent element.

Additional context:
Transport is active in source/fhir.ini for the current build. OO minutes for 2024-11-08 record the FHIR-39512 persuasive-with-modification vote and the follow-up need to examine performer handling on event resources. Later Jira issues and OO minutes explicitly treated FHIR-39512 as the decision that removed request-related Transport content, so the remaining request prose and Transport intent terminology should not be preserved as current R6 source. The OID registry entries are left intact, matching existing repository practice for removed terminology canonicals.

AutoFHIR reconciliation:
This commit updates Transport.basedOn and its Event mapping-exception source so the definition describes authorizing requests fulfilled by a transport event and no longer names Transport as a request resource. It updates transport-introduction.xml so Transport records movement events linked to authorizing requests rather than being used as the request, and it quotes the existing image width attribute so the edited XML is well-formed. It deletes the orphaned source/transport/codesystem-transport-intent.xml and source/transport/valueset-transport-intent.xml files because Transport.intent no longer exists and active source no longer references TransportIntent.

Recommendation:
Keep this source-changing commit. It completes the seed reconciliation without needing to reopen the later Transport clean-up issues; those later issues can remain separate audit items if encountered, but they support rather than contradict this fix.
