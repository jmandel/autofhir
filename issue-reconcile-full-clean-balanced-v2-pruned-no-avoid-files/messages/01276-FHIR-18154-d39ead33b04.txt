FHIR-18154 was Published/Persuasive for the OO work group. The ballot asked about duplicate modifier-reason wording on Observation.status, and the final resolution was to fix it by removing the note from the comments field rather than duplicating the modifier reason.

Initial application:
The issue was applied in PR #1496. Commit 94d95ddcd62bba94ce71bd4c98ac52a8d914da70 removed the redundant Observation.status comment, and merge commit 2e944b47f380f4c881f6e05551d17c1b470ce72a brought that change into the main history.

Additional context:
Observation is an active current-build resource in source/fhir.ini. A later unrelated FHIR-35853 commit, 680ce0a481a9d96d1981ce1f4ff0b0310f155900, reintroduced the same Observation.status comment as part of miscellaneous Observation cleanup while implementing ElementDefinition.type.code binding work. FHIR-22635 supports documenting that Observation.status is a modifier in conformance-rule examples, but it does not require duplicating the modifier reason in the Observation.status comment. No relevant Zulip or Confluence evidence was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:

Recommendation:
Keep this source fix as-is. The current build should carry the modifier rationale through isModifierReason, not as a duplicate comment on Observation.status.
