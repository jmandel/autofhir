FHIR-3692: Remove stale narrative idref wording

Issue request:
FHIR-3692 was a Published/Persuasive FHIR-core change request from DSTU1 asking to remove the FHIR `idref` type, including the CarePlan use of that type and narrative cross-linking guidance based on id/idref.

Initial application:
The historical application is git-svn commit fec6a041a5ecd56ef155b58bb6153669f1adb4ce for svn revision 3285 (`{#3087}: rework link narrative, and remove type idref`). It changed the CarePlan spreadsheet type from `idref` to `uri`, updated datatype links from `references.html#idref` to `references.html#id`, and removed the old commented narrative/data idref examples. Current source no longer defines a FHIR `idref` type; the remaining core source problem was one built Narrative page sentence still saying XML `id`/`idref` attributes mediate references.

Additional context:
`source/narrative.html` is in build scope through `source/hierarchy.xml`. Later Published issues FHIR-13154 and FHIR-37792 intentionally preserved an Internal Id References section and added narrativeLink/originalText guidance, so this reconciliation should not delete the whole section. Later R6 issues FHIR-48338 and FHIR-54755 are Resolved - change required, while FHIR-54604 and FHIR-57374 are still Submitted; they confirm that XHTML `idref` is not valid and that broader textLink-oriented narrative guidance is still being worked through, but those issues are not final Applied/Published core work for this default run.

AutoFHIR reconciliation:
Updated `source/narrative.html` to remove the stale `idref` mechanism from the Internal Id References prose and to describe the current id-based representation: FHIR element ids are XML `id` attributes and JSON `id` properties. No textLink rewrite or section move was made.

Recommendation:
Keep this commit as the narrow FHIR-3692 reconciliation. Handle broader narrative/data linking consolidation under the later R6 tickets once they are applied or published, especially FHIR-48338, FHIR-54755, and FHIR-57374.
