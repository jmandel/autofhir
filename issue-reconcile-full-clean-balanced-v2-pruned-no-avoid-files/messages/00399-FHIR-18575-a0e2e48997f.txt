FHIR-18575: Align ValueSet designation wording

Issue request:
FHIR-18575 was Published/Persuasive with Modification for FHIR-core ValueSet. It asked whether the implied designation.use value "primary code/designation" was really in the designation-use value set, and its resolution changed the wording to an implied designation.use meaning "primary designation".

Initial application:
Git commit 4907f9bcb0b710cb2837a93a20c4b23210a37249 was the recorded application for FHIR-18575, but the patch only changed "of" to "meaning" in the narrative and left "primary code/designation" in place. Later refactors left the active ValueSet narrative with "primary code" and the ValueSet.compose.include.concept.designation StructureDefinition comment with the same stale meaning.

Additional context:
FHIR-18637 is the CodeSystem duplicate of this same STU3 ballot issue. FHIR-38834 later resolved the CodeSystem element comment by using "primary designation", and this reconciliation applies the same final wording to the active ValueSet sources. FHIR-51614 is a later Triaged issue asking for broader guidance about translating codes and designations; this commit does not decide that broader request.

AutoFHIR reconciliation:
This commit changes source/valueset/valueset-notes.xml and source/valueset/structuredefinition-ValueSet.xml from "primary code" wording to "primary designation". ValueSet is active in source/fhir.ini, so both files feed current built ValueSet guidance/definitions.

Recommendation:
Keep this source fix as the bounded completion of FHIR-18575's accepted wording change. Leave broader guidance on when to put translations in CodeSystem supplements versus ValueSets to the still-open FHIR-51614 work-group discussion.
