FHIR-30343: Clarify $validate-code abstract default

Issue request:
FHIR-30343 was Published/Persuasive for FHIR-core CodeSystem and ValueSet. It asked that the optional $validate-code input parameter abstract state that omission has the same behavior as abstract=true, and it also asked to correct the object-oriented wording in the abstract-terminology explanation.

Initial application:
The Jira-tagged implementation commit ade907ca5b1bc08efb093bc524c5b00bdc7fa5ac applied FHIR-30343 only to source/valueset/operationdefinition-ValueSet-validate-code.xml. A later typo commit bfb362f11250684baf6710d3a95ca5ddd1f7c4a0 fixed the misspelled parameter wording there, but source/codesystem/operationdefinition-CodeSystem-validate-code.xml still omitted the default behavior and retained the stale object-oriented text.

Additional context:
source/fhir.ini lists CodeSystem and ValueSet as active resources, and their operation lists reference OperationDefinition/CodeSystem-validate-code and OperationDefinition/ValueSet-validate-code, so both operation definition sources feed the current build. Jira neighborhood searches found no later issue changing the omitted-abstract behavior. Vocabulary WG minutes from 2021-06-09 record that FHIR-30343 was discussed and voted on, and Zulip search found no conflicting discussion.

AutoFHIR reconciliation:
This commit updates the CodeSystem $validate-code abstract parameter documentation so omitted abstract is treated as true and false excludes abstract codes. It also corrects the object-oriented/abstract-entities wording in CodeSystem and the remaining object-orientated spelling in ValueSet, aligning both active operation definitions with the published Jira decision.

Recommendation:
Keep this source fix as-is. It completes the already-approved R5 technical correction in the active core source and does not require follow-up outside this repository.
