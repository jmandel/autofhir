FHIR-50488: Correct supplementalData evaluate wording

Issue request:
FHIR-50488 was Applied with a Persuasive resolution for R6. It asked the Measure $evaluate operation to accept additional supplementalData input parameters so a caller can request supplemental data in the MeasureReport without creating a new Measure. The approved parameter set was supplementalData 0..* with code, usage, description, and criteria parts.

Initial application:
PR HL7/fhir#3811 applied the issue in source/measure/operationdefinition-Measure-evaluate.xml. Commit 7590be91ee added the supplementalData multi-part parameter with the approved code, usage, description, and criteria parts, and commit 701d4e6c70 added measureUrl scoping so supplemental data can target specific measures when multiple measures are evaluated. The current source had the needed parameter structure, but the measureUrl documentation still used copy/pasted stratifier wording and the top supplementalData documentation contained the Jira typo "same was".

Additional context:
Measure is an active resource in source/fhir.ini, and source/measure/list-Measure-operations.xml references OperationDefinition/Measure-evaluate, so the edited XML is build-scope source. The current Measure.supplementalData source confirms the approved core parts and cardinalities used by the operation. FHIR-50489 is the same Measure $evaluate enhancement family for stratifiers but is a separate issue already represented on the combined branch. FHIR-56320 later proposes replacing inline DEQM evaluate stratifier/supplementalData parameters with $compose-measure, but it is Triaged and not a final FHIR-core decision.

AutoFHIR reconciliation:
Changed only source/measure/operationdefinition-Measure-evaluate.xml. The commit preserves the applied supplementalData parameter structure, corrects "same was" to "same way", and changes supplementalData.measureUrl documentation so it consistently describes supplemental data rather than stratifiers.

Recommendation:
Keep this narrow source fix. Do not add valueSet/unit or remove the inline parameter without a later final work-group decision; if FHIR-56320 or a corresponding FHIR-core issue is applied in the future, revisit the operation design then.
