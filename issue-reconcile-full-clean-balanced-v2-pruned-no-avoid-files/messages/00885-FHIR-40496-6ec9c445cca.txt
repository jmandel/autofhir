FHIR-40496: Restore capabilities 404 endpoint sentence

Issue request:
FHIR-40496 was Applied/Persuasive for R6 and asked that the capabilities interaction say servers SHOULD check the fhirVersion MIME-type parameter as a general part of processing the metadata request, not only after the 404 Not Found guidance. The approved resolution also kept the ETag guidance separate and retained the 404 sentence saying that FHIR or the specified version is not supported on the nominated service URL.

Initial application:
The issue was applied by HL7/fhir#3442 in commit 08e2ca9544, which moved the fhirVersion and ETag guidance into separate paragraphs in source/http.html. That commit also accidentally truncated the following 404 Not Found sentence after "not supported on the", leaving the current source grammatically incomplete and missing the nominated service URL conclusion.

Additional context:
FHIR Infrastructure minutes from 2024-12-09 record the approved scope: checking the MIME type should be general to the capabilities request, and the MIME type checking and ETag header should be separate statements above the 404 sentence. source/http.html is the authoritative source page for the REST API/capabilities interaction and is linked from the core module navigation as the REST API page.

AutoFHIR reconciliation:
This commit restores the missing phrase "nominated service URL" to the 404 Not Found paragraph while preserving the already-applied fhirVersion and ETag paragraph ordering.

Recommendation:
Keep this source fix. It completes the applied Jira resolution without changing the approved semantics or expanding the issue scope.
