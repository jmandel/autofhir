FHIR-17638: Correct PurposeOfUse code system reference

Issue request:
FHIR-17638 was Published/Persuasive with Modification for STU3. It reported that the v3 PurposeOfUse value set expansion exposed the abstract/root "PurposeOfUse" concept as if it were an implementable code, especially for bindings such as Consent.purpose. The approved resolution was to exclude the abstract code from that value set and pursue the broader R5 question of how abstract/not-selectable codes should be identified and rendered in expansions.

Initial application:
No git commit explicitly mentioning FHIR-17638 was found. The historical v3 MIF source now has includeHeadCode="false" for the PurposeOfUse value set in tools/tx/v3/source.xml, which excludes the head PurposeOfUse code while including descendants. Conformance and MnM minutes from late 2018 record the harmonization approvals for dropping the abstract root from the value set display and treating the value set as based on the ActReason PurposeOfUse code.

Additional context:
Core FHIR no longer owns the current published THO v3 value set expansion. Current core bindings point to http://terminology.hl7.org/ValueSet/v3-PurposeOfUse, while the THO package defines that value set over http://terminology.hl7.org/CodeSystem/v3-ActReason and marks the PurposeOfUse concept notSelectable. The later implemented UTG proposal UP-528 and its Zulip discussion deliberately removed the old value-set exclusion after marking PurposeOfUse not selectable, so hierarchy could be rendered; core's $expand operation now documents excludeNotForUI for notSelectable concepts. The remaining core-source problem was that the active Security Labels narrative still named the nonexistent code system http://terminology.hl7.org/CodeSystem/v3-PurposeOfUse.

AutoFHIR reconciliation:
This commit changes source/security-labels.html so the Purpose of Use section identifies the coding system as http://terminology.hl7.org/CodeSystem/v3-ActReason while keeping the link to the PurposeOfUse value set. The page is linked from source/documentation.html and is therefore current build-scope narrative. The hunk is necessary because the stale standalone code-system URI could lead implementers to construct invalid codings and conflicts with both the original ActReason-based value-set correction and the current THO source.

Recommendation:
Keep this core-source fix. Do not reintroduce a core-owned v3 expansion change here; if the work group wants the current THO default expansion to omit notSelectable roots despite UP-528, that follow-up belongs in THO/UTG terminology governance rather than this FHIR-core checkout.
