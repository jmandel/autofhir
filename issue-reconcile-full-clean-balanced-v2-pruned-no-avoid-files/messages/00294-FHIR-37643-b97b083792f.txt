FHIR-37643: Correct ImagingSelection instance DICOM mapping

Issue request:
FHIR-37643 was Published/Persuasive for R5 ImagingSelection. It requested optional Series Number and Instance Number support: add top-level seriesNumber, add an optional unsignedInt instance number under instance with a note distinguishing instance and frame numbers, and add DICOM mappings to Series Number and Instance Number respectively.

Initial application:
The elements were initially added in commit 90f061e0ab31e4e1212985e90c3561d2f2adb361 as part of ImagingSelection July updates. That commit added ImagingSelection.seriesNumber and ImagingSelection.instance.number with the requested cardinalities and note, but the instance number DICOM mapping used (0020,0011), which is the Series Number tag, instead of the DICOM Instance Number tag.

Additional context:
ImagingSelection is an active build resource in source/fhir.ini. Later Applied issues refined nearby ImagingSelection text without changing the seed intent: FHIR-45044 confirmed the element path as ImagingSelection.instance.number with alias InstanceNumber and requirement text, and FHIR-48106 added the seriesNumber presence rule and fixed seriesUid spelling. FHIR-47520 updated ImagingStudy DICOM tag mappings and shows the parallel ImagingStudy.series.instance.number mapping as Instance Number (0020,0013), but it did not touch ImagingSelection.

AutoFHIR reconciliation:
Updated source/imagingselection/structuredefinition-ImagingSelection.xml so ImagingSelection.instance.number maps to DICOM Instance Number (0020,0013). The top-level seriesNumber mapping remains Series Number (0020,0011), and the existing instance/frame distinction note is unchanged.

Recommendation:
Keep this commit. It is a narrow authoritative-source fix for the remaining semantic mismatch in the Published FHIR-37643 application; no broader ImagingSelection or generated diagram edits are needed.
