FHIR-13999: Move MedicationRequest instance-order under order

Issue request:
FHIR-13999 was a Published/Persuasive STU3 pharmacy issue asking that the medication request intent hierarchy make instance-order a child of order instead of a sibling, matching the request-intent hierarchy.

Initial application:
No commit tagged FHIR-13999 was found on the current history. The MedicationRequest-specific intent CodeSystem was introduced in git 7373e742ee with the order-related codes still at the top level, then git 886f421a86 applied FHIR-34218 by adding an order hierarchy but left instance-order nested under filler-order.

Additional context:
MedicationPrescription is now MedicationRequest in the active build, and source/fhir.ini lists medicationrequest as an active resource. FHIR-34218 clarified the MedicationRequest instance-order definition for MAR scheduling, but did not require instance-order to be filler-specific. The later Published FHIR-20499 decision moved generic Request.intent instance-order out from under filler-order to a direct child of order because instance orders can be created by placing as well as filling systems.

AutoFHIR reconciliation:
Updated source/medicationrequest/codesystem-medicationrequest-intent.xml so instance-order is a sibling of filler-order inside the order concept. The value set already includes the complete MedicationRequest intent CodeSystem, so no ValueSet compose change was needed.

Recommendation:
Keep this source fix. It reconciles the original STU3 pharmacy hierarchy request with the later R5 workflow clarification while preserving the MedicationRequest-specific instance-order wording approved by FHIR-34218.
