FHIR-37525: Clarify SubscriptionStatus lacks REST endpoint

Issue request:
FHIR-37525 was Published/Persuasive for R5 and asked to state that SubscriptionStatus is returned in notifications and through the $status method without an expectation that it has a REST endpoint. The approved resolution was to add language similar to Parameters and OperationOutcome saying there is no expectation to expose this resource as a RESTful endpoint.

Initial application:
Commit 1e5fcb4c2b3221ff721865ac75190c4faa9d502d applied FHIR-37525 by adding that SubscriptionStatus is not persisted to the resource description and that it is not persisted or allowed to be referenced by other resources in the introduction. That captured the transient-resource part of the decision but left the REST endpoint expectation implicit.

Additional context:
The linked Zulip discussion shows Bas van den Heuvel asking whether SubscriptionStatus has a REST endpoint and Gino Canessa explaining that it is intended to be transient, with $status preserving server implementation freedom. The active fhir.ini resource entry confirms source/subscriptionstatus/subscriptionstatus-introduction.xml feeds the current SubscriptionStatus resource page. Later SubscriptionStatus notes still direct clients to the $status operation, so the reconciliation must distinguish that operation from a resource-level RESTful endpoint for creating, updating, or querying SubscriptionStatus instances.

AutoFHIR reconciliation:
This commit adds a narrow Scope and Usage paragraph to the active SubscriptionStatus introduction explaining that SubscriptionStatus is generated for notifications and the $status operation rather than representing a persistent server resource, and that servers are not expected to expose a RESTful endpoint for SubscriptionStatus instances. No generated artifacts or out-of-build files were changed.

Recommendation:
Keep this source change. It completes the published tracker intent without changing the $status operation guidance or adding broader constraints on how servers internally track subscription state.
