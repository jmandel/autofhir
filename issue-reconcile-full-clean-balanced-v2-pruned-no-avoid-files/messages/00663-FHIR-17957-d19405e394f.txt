FHIR-17957: Normalize CoverageEligibilityRequest priority codes

Issue request:
FHIR-17957 was a Published/Persuasive Financial Management change request for the STU3 EligibilityRequest artifact asking that the .priority terminology description use the code value "stat" instead of "STAT".

Initial application:
The issue appears to have been applied in the large GF#17957 spreadsheet update f369c813fb, which changed the CoverageEligibilityRequest.priority element definition away from the older "Immediate (STAT), best effort (NORMAL), deferred (DEFER)" wording. That application left the ProcessPriority binding description as "STAT, normal, Deferred", and the later structured XML conversion preserved that stale wording.

Additional context:
EligibilityRequest itself is no longer an active current-build resource; source/fhir.ini records that EligibilityRequest/Response became CoverageEligibilityRequest/Response, while CoverageEligibilityRequest is active and approved in the current build. Parallel active Claim and ExplanationOfBenefit priority bindings already use the lower-case code-list wording "stat, normal, deferred", and no Zulip or Confluence evidence was found that conflicts with the Jira/source conclusion.

AutoFHIR reconciliation:
Updated the active CoverageEligibilityRequest StructureDefinition binding description for ProcessPriority to list the lower-case code values "stat, normal, deferred". The retained legacy EligibilityRequest spreadsheet still contains historical STU3 text but is out of current build scope, so it was intentionally left unchanged.

Recommendation:
Keep this source fix as-is. It corrects the active current resource definition to match the Published Jira request and the parallel FM artifacts without editing retired source or generated diagram artifacts.
