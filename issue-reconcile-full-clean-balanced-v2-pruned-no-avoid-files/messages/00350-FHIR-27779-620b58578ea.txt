FHIR-27779: Restore Consent preference comment

Issue request:
FHIR-27779 was a Published/Persuasive R5 FHIR-core Consent clarification. It asked what a Consent means when the old Consent.performer element is empty, and the final resolution directed the element comment to state that a Consent without performer is a statement of preference by the subject and is not in force.

Initial application:
The issue was originally applied by git commit 374f01bb8e, which added that statement to the Consent.performer comment in source/consent/consent-spreadsheet.xml. The spreadsheet-to-StructureDefinition source migration preserved the Consent.performer concept for a time, but the later Consent refactor removed the old performer element and the FHIR-27779 sentence was not carried forward.

Additional context:
FHIR-31906, also Published/Persuasive with Modification for R5, converted Consent.performer into Consent.grantor and Consent.grantee and added the current grantee comment saying both actors appear in a fully computable Consent and that the elements support search. Consent remains an active resource in source/fhir.ini, so source/consent/structuredefinition-Consent.xml is current build source. FHIR-11061 is background support for the grantor/grantee party distinction; no Zulip or Confluence record was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:
Updated the active Consent.grantee comment to carry the FHIR-27779 meaning in the current model: a Consent without any listed grantor or grantee may be used as a subject preference statement and is not in force. The same edit also fixes the double space in the existing grantee/grantor sentence on that comment line.

Recommendation:
Keep this source fix. It restores a previously applied R5 clarification after the performer-to-grantor/grantee refactor without changing cardinalities or adding a new computability constraint.
