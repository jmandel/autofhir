FHIR-17473: Align coverage eligibility request scope

Issue request:
FHIR-17473 was a Published/Persuasive with Modification FM change request for STU3 that asked to adapt EligibilityRequest for Da Vinci CRD coverage-requirements discovery. The accepted resolution used CoverageEligibilityRequest.purpose for the request type, broadened the resource scope to validation, discovery, benefits, and authorization requirements, renamed/detail-neutralized service items, added item.detail references, and added supporting information with item-level linking.

Initial application:
The issue was applied in historical commits 5fc36d59f7 and 5ca058130a. Those commits changed the old spreadsheet source to add purpose values, supportingInformation, item/detail structure, billcode naming, and the expanded CoverageEligibilityRequest introduction. Later source refactoring generated the current StructureDefinition XML, renamed EligibilityRequest to CoverageEligibilityRequest, and maps the old billing-code/service names to current productOrService naming.

Additional context:
source/fhir.ini lists CoverageEligibilityRequest as an active current build resource and records CoverageEligibilityRequest=EligibilityRequest in the name-change map. The current source already has the required purpose, supportingInfo, supportingInfo.appliesToAll, item.supportingInfoSequence, item.productOrService, and item.detail elements. However, the current StructureDefinition description and eClaim relationship-table copies still used the older eligibility-only wording about validity and insurance details. Zulip and Confluence searches found no conflicting work-group record; a Da Vinci Zulip thread only confirms the contemporaneous CRD profiling context.

AutoFHIR reconciliation:
This commit updates the active CoverageEligibilityRequest StructureDefinition description/root definition and the related CoverageEligibilityRequest/CoverageEligibilityResponse narrative table rows so they describe validation, discovery, benefits, and preauthorization requirements. It intentionally leaves the already-correct purpose, supporting information, item detail, and current productOrService naming unchanged.

Recommendation:
Keep this commit as-is. It completes the remaining source-level scope wording from FHIR-17473 without reopening the later-approved current element names or duplicating guidance beyond the stale descriptions that could mislead implementers.
