FHIR-12358: Use CodeableConcept for EOB supportingInfo reason

Issue request:
FHIR-12358 is Published/Persuasive. FM asked to use CodeableConcept rather than Coding in financial resources where appropriate because secondary-use billing workflows may submit text or multiple codings for human processing.

Initial application:
The issue appears to have been applied by 2016 commits 37303c8e87 and 7fc33d1f03, which converted many financial-resource Coding elements to CodeableConcept. The application was incomplete for the current ExplanationOfBenefit supportingInfo reason lineage: the old ExplanationOfBenefit.information.reason row remained Coding, and the 2021 source rework carried that forward as ExplanationOfBenefit.supportingInfo.reason.

Additional context:
The current build includes Claim, ClaimResponse, Coverage, CoverageEligibilityRequest, CoverageEligibilityResponse, EnrollmentRequest, EnrollmentResponse, ExplanationOfBenefit, PaymentNotice, PaymentReconciliation, and VisionPrescription; ProcessRequest and ProcessResponse are commented out. The parallel Claim.supportingInfo.reason and ClaimResponse.supportingInfo.reason elements already use CodeableConcept with the same MissingReason binding, and no Zulip or Confluence search result indicated a later contrary decision. Related FHIR-10064 records the same FM policy that most financial Codings were replaced with CodeableConcept.

AutoFHIR reconciliation:
Changed source/explanationofbenefit/structuredefinition-ExplanationOfBenefit.xml so ExplanationOfBenefit.supportingInfo.reason uses CodeableConcept instead of Coding. This is an active build source file for an active resource, and the hunk removes the only remaining Coding type in the active financial resource StructureDefinitions inspected for this issue.

Recommendation:
Keep this source fix. Let generated diagrams or downstream artifacts refresh through the normal build rather than manually editing the checked-in SVG. FHIR-10064 was treated as supporting context only, not independently decided by this commit.
