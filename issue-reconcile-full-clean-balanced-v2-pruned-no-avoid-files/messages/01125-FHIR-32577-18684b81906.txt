FHIR-32577: Clarify DocumentReference category display

Issue request:
FHIR-32577 was a Published/Persuasive with Modification Orders and Observations issue for R5. It reported that the DocumentReference.category example binding was too document-specific for a resource that can index documents, media, and other referenced content; the accepted resolution renamed the old document-classcodes value set to referenced-item-category and changed the short display name to "Categorization of referenced record".

Initial application:
The code content was partly applied before this reconciliation. Git commit cebeac615e0c434ff755a1aa763781d2cf61c8c2 broadened the old document-classcodes value set by adding the media-category code system and filtering LOINC by DOC scale, and git commit 1e542148c2d27a0394c2798fa8a1a78014db1b4d renamed the value set file, id, url, name, and title to referenced-item-category and updated the DocumentReference.category binding URL/name. The application missed the requested short display name and left the local binding/value set descriptions saying "document".

Additional context:
DocumentReference is active in the current build through source/fhir.ini, and the value set is referenced directly from the active DocumentReference category element. FHIR-24671 later treated the referenced-item-category value set content as already applied and records that DocumentReference category values are broader than Composition category values. Confluence OO minutes for 2022-03-31 record the FHIR-32577 block-vote approval matching the Jira vote. No direct Zulip discussion for FHIR-32577 was found.

AutoFHIR reconciliation:
This commit updates the active DocumentReference.category short display to "Categorization of referenced record", aligns its binding description with referenced records, updates the checked-in DocumentReference category SearchParameter description, broadens the referenced-item-category ValueSet description to media plus LOINC DOC content, and updates the Event mapping exception companion source so pattern-mapping checks keep matching the element short. It intentionally does not edit historical release files or generated-looking diagrams.

Recommendation:
Keep this source fix. It completes the accepted FHIR-32577 display/description change without changing the example binding strength or the value set membership; any future change to Composition.category wording or category value-set content should be handled as separate OO/SD work.
