FHIR-19694: Clarify MedicationRequest reason goal references

Issue request:
FHIR-19694 was a Published/Persuasive Pharmacy change request, raised against STU3 MedicationPrescription and applied for R5, asking that MedicationRequest.reasonCode/reasonReference guidance distinguish diagnosis/problem/condition reasons from therapeutic goal target values. The final resolution said to clarify that the reason reference attribute is intended for condition/diagnosis/problem support and is not to express or reference a goal.

Initial application:
The issue was applied in Pharmacy commit cdb9b15432 and merged by ec284380a4 in PR #517. That application added the explicit MedicationRequest.reasonReference comment that it was a reference to a condition or observation, was not intended to reference a goal, and that coded-only reasons should use reasonCode. Later R5/R6 refactoring and the FHIR-25929 CodeableReference migration merged reasonCode and reasonReference into MedicationRequest.reason; the formal targetProfile list continued to exclude Goal, but the explicit "not Goal" explanatory sentence was no longer present on the current reason element.

Additional context:
source/fhir.ini lists medicationrequest=MedicationRequest as an active resource and records that MedicationRequest.reasonCode and reasonReference are now mapped to MedicationRequest.reason.concept and reason.reference. FHIR-25929 is already represented on the combined branch and updated the stale reasonReference wording to reason.reference. Later Pharmacy decisions FHIR-40785, FHIR-40462, and FHIR-51148 broadened MedicationRequest.reason references to DiagnosticReport, Procedure, and AllergyIntolerance, while still not adding Goal. Direct Zulip searches found no FHIR-19694 or MedicationRequest.reasonReference/Goal discussion, and Confluence hits were agenda/reference mentions without conflicting guidance.

AutoFHIR reconciliation:
This commit restores the approved clarification in the current CodeableReference model by adding "The reference is not intended to refer to a Goal" to MedicationRequest.reason in the active StructureDefinition source. It also updates the MedicationRequest Request-pattern mapping exception mirror so the generated mapping comparison remains aligned with the resource comment.

Recommendation:
Keep this source-changing commit. It preserves the original FHIR-19694 implementer guidance after the reasonCode/reasonReference merge without changing the later approved reference target list; the related CodeableReference and added-target-profile issues are already represented separately on the combined branch.
