FHIR-7317: Clarify Claim item diagnosis order

Attribution note: surfaced while reviewing FHIR-7318, but direct Jira backing for this change is FHIR-7317.

Issue request:
FHIR-7318 was a Published/Persuasive FM change request for FHIR-core Claim. It asked that the diagnosis link id at a line item have a priority order relative to that line item, and its recorded resolution proposed replacing diagnosisLinkId 0..* integer with a diagnosis backbone carrying linkId and sequence children.

Initial application:
No explicit FHIR-7318-tagged source commit was found. Historical Claim source started with Claim.item.diagnosisLinkId as a repeated integer, later added diagnosis.type and removed global diagnosis-list ordering language, and then the FHIR-14254 Claim refactor renamed diagnosisLinkId to diagnosisSequence without adding the proposed backbone or any line-item order semantics. Current Claim.item.diagnosisSequence therefore preserved the reference list but did not expose the approved priority-order meaning.

Additional context:
FHIR-7317 is the same change family and its later Published/Persuasive with Modification resolution narrowed the applied approach: Claim.item.diagnosisLinkId and EOB.item.diagnosisLinkId should remain lists but be created in order of decreasing relevance, with element definitions updated. FHIR-7319 separately clarified that Claim.diagnosis.sequence is only a local reference identifier and that diagnosis.type carries global primary/secondary diagnosis roles, so item-specific diagnosis pointer ordering does not reintroduce global diagnosis-list ranking.

AutoFHIR reconciliation:
This commit adds orderMeaning to the active Claim StructureDefinition element Claim.item.diagnosisSequence, stating that diagnosis sequence references are listed in order of decreasing relevance to the service or product. Claim is active in source/fhir.ini, and source/fhir.ini maps the historical Claim.item.diagnosisLinkId name to Claim.item.diagnosisSequence, so the hunk is both in build scope and targeted at the current representation of the requested element.

Recommendation:
Keep this source fix. It applies the later narrowed issue-family decision to the current Claim model without adding a now-unapproved backbone; normal publication tooling can regenerate derived narrative and diagrams.
