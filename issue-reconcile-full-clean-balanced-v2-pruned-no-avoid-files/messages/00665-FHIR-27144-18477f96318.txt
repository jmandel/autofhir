FHIR-27144: Align required binding strength definition

Issue request:
FHIR-27144 was Published/Persuasive for R5 and asked to clarify that required bindings are evaluated against the expansion of the bound value set, not an undefined static list of concepts.

Initial application:
The issue was applied by commit 0bb0f8f90b, which updated the Required Binding Strength narrative in source/terminologies.html to say the data element SHALL contain one of the values in the expansion of the bound value set. The formal binding-strength CodeSystem source and the backing terminology spreadsheet still retained the older "concept in this element" wording.

Additional context:
The binding-strength CodeSystem source under source/operationdefinition and the binding-strength worksheet in source/terminologies/bindings.xml are active sources for the same binding-strength terminology artifact. FHIR-29968 is the parallel extensible-binding clarification in the same artifact family and is reconciled separately.

AutoFHIR reconciliation:
This commit updates the required concept definition in source/operationdefinition/codesystem-binding-strength.xml and the matching source/terminologies/bindings.xml worksheet row to match the already-applied narrative wording.

Recommendation:
Keep this commit. It completes the existing R5 clarification on the machine-readable binding-strength artifact without changing the surrounding required-binding guidance.
