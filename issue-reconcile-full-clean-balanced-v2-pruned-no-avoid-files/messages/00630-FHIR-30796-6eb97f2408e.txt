FHIR-30796: Align Substance ownership metadata

Issue request:
FHIR-30796 is a Published/Persuasive R5 BR&R change request recording the joint OO/BRR decision to transfer Substance resource ownership from Orders and Observations to Biomedical Research and Regulation.

Initial application:
The Jira-tagged commit ef7cfcb850 changed source/fhir.ini from substance=oo to substance=brr but did not update the checked-in Substance StructureDefinition. A later QA commit standardized its publisher text while leaving OO as publisher/contact, and the Substance category value set already carried the brr workgroup code but still named the OO workgroup as publisher.

Additional context:
The WGM minutes linked from Jira state the action was to change ownership in the FHIR build and migrate open Jira tickets. The linked Zulip topic confirms source/fhir.ini is the build-level place for resource ownership and that StructureDefinition metadata should reflect/regenerate from that ownership. source/fhir.ini actively includes substance=Substance and assigns substance=brr, so the Substance folder is in current build scope; StructureDefinition/Substance and the category value set are active source for the built resource and its bound terminology.

AutoFHIR reconciliation:
Updated source/substance/structuredefinition-Substance.xml to use the brr workgroup extension, BR&R publisher, and BR&R committee contact. Removed the stale OO publisher/contact from source/substance/valueset-substance-category.xml, using the FHIR Project publisher/contact pattern used by neighboring BR&R-owned Substance terminology value sets while preserving the already-correct brr workgroup extension.

Recommendation:
Keep this source fix. It completes the applied ownership transfer in active source metadata without changing resource semantics; no further core source work was found for FHIR-30796.
