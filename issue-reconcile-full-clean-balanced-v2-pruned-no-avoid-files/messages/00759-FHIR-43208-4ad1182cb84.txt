FHIR-43208: Correct less-precise date range examples

Issue request:
FHIR-43208 was Applied with resolution Persuasive with Modification for R6. The issue asked that the search prefix range examples clarify less precise dates, especially whether range-below and range-above behavior for dates uses the start or end of the implied date interval. The approved resolution was to split quantity and time examples so the date examples would not inherit confusing numeric range wording.

Initial application:
The issue was initially applied in git commit a88a8175b5cf23acf8cf55bf44fbfc4834d90833, which split the decimal and date/time rows in source/search.html. That application left two copied/stale month-date boundaries in the less precise date example: the month precision range for 2015-08 started at 2015-08-12 instead of 2015-08-01, and the range-below example used the invalid boundary 2015-08-00.

Additional context:
The source file source/search.html is the current FHIR-core Search page for the Jira related page FHIR-core-search. Nearby current date search notes state that a year-month date starts at the first instant of the first day of the month and ends on the last instant of the last day of the month, which supports using 2015-08-01 as the lower boundary and 2015-09-01 as the upper exclusive boundary for the 2015-08 example. Confluence FHIR-I minutes from 2024-04-22 confirm the 8-0-0 motion and the split-quantity/time-example disposition. No Zulip discussion or Jira issue about the invalid 2015-08-00 text was found.

AutoFHIR reconciliation:
This commit corrects only the two stale less precise date examples in source/search.html: the month precision range now begins at 2015-08-01T00:00:00.0000, and the range-below example now uses 2015-08-01T00:00:00.000000000000000 instead of the invalid 2015-08-00 boundary.

Recommendation:
Keep this source fix. It completes the already-applied FHIR-43208 clarification without changing the broader prefix semantics or reopening related search-prefix cleanup tickets.
