FHIR-18652: Point implicit code system link at CodeSystem

Issue request:
FHIR-18652 was Published/Persuasive for STU3 as N-Term #44. The reporter said the CodeSystem page's "Implicit Code Systems" link went to conceptmap.html#implicit, a ConceptMap section that did not define implicit code systems and was out of context; the Jira resolution text was terse ("filter"), but the comment trail identified the wrong ConceptMap link as the problem.

Initial application:
The issue was applied in terminology batch commit 4907f9bcb0b710cb2837a93a20c4b23210a37249, which added a CodeSystem implicit code systems section and removed a CodeSystem-page "For further information, see conceptmap.html#implicit" reference. Current source still had the same problem shape in active ConceptMap narrative: source/conceptmap/conceptmap-introduction.xml linked "implicit" code system to conceptmap.html#implicit even though the ConceptMap implicit-code-system section is now commented out.

Additional context:
FHIR-39265 later removed the earlier draft CodeSystem implicit code systems section for R5 while acknowledging further discussion. FHIR-40432 then restored an authoritative R6 CodeSystem implicit code systems section at codesystem.html#implicit-code-systems, and FHIR-23038 removed only an unclear subsetting parenthetical from that section. FHIR-40432 and FHIR-23038 are already represented on the combined branch, so this reconciliation does not duplicate them; it uses their current source outcome as the target for the remaining stale ConceptMap cross-reference. source/fhir.ini lists both ConceptMap and CodeSystem as active resources in the Vocabulary chapter.

AutoFHIR reconciliation:
This commit changes the active ConceptMap introduction link from conceptmap.html#implicit to codesystem.html#implicit-code-systems, so readers land on the current CodeSystem definition of implicit code systems. It intentionally leaves the commented historical ConceptMap block untouched.

Recommendation:
Keep this commit as-is. It is a narrow source fix for the same wrong-link condition identified by FHIR-18652, aligned with the later FHIR-40432 restoration and without reopening the broader implicit code system policy discussion.
