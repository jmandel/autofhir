FHIR-32580: Align DocumentReference practiceSetting invariant warning

Issue request:
FHIR-32580 was Published/Persuasive with Modification for the R5 DocumentReference request to drop facilityType and practiceSetting. The final OO decision instead kept both elements, added warning invariants so Encounter context is not used alongside facilityType and/or practiceSetting, and considered search support for both mechanisms if possible.

Initial application:
The source was initially changed by git 699aab03f786df039dafae1781e7e79d05746538, which added docRef-1 and docRef-2 warning invariants to DocumentReference. Git c3e4b3cd829b31ddad2570de39731870182d7597 refined both FHIRPath expressions to test only Encounter context, and git 55512f8e09be7228efab289f8bf660242d29654d later attached the invariant conditions to context, facilityType, and practiceSetting. The active DocumentReference resource and existing context/facility/setting search parameters are present in current source.

Additional context:
OO minutes on 2022-08-09 record the accepted disposition to keep the elements and add an invariant. Current DocumentReference.context can reference Appointment, Encounter, or EpisodeOfCare, so docRef-2's human text saying practiceSetting is allowed only when context is not present was broader than the approved Encounter-specific rule and broader than its current expression. No directly relevant Zulip discussion was found that changes the Jira and OO-minutes conclusion.

AutoFHIR reconciliation:
This commit changes only the docRef-2 human-readable warning text from "context is not present" to "context is not an encounter" so it matches the approved rule, the parallel docRef-1 wording, and the actual FHIRPath expression. It intentionally leaves the invariant expression and search parameter definitions unchanged.

Recommendation:
Keep this source fix as-is. It corrects implementer-visible validation text without changing the invariant behavior; any future cross-resource search enhancement for Encounter-derived metadata would need a separate work-group decision because the current base search parameters already cover DocumentReference.context, DocumentReference.facilityType, and DocumentReference.practiceSetting directly.
