FHIR-54848: Clarify Dosage.site BodyStructure guidance

Issue request:
FHIR-54848 was an Applied/Persuasive Pharmacy change request for R6 asking that Dosage.site move from CodeableConcept to CodeableReference(BodyStructure), while keeping the existing binding on the CodeableConcept part, so laterality and other BodyStructure details can be represented.

Initial application:
Commit b33db10cfc changed source/datatypes/dosage.xml so Dosage.site has type CodeableReference(BodyStructure) and added a FHIR-54848 changelog entry. That applied the structural part of the decision, but the same Dosage.site row still described the site as coded-only and told implementers to use the bodySite extension when a BodyStructure-style location was needed.

Additional context:
Dosage is an active datatype in source/fhir.ini and the spreadsheet row is the current build-scope source for Dosage.site. Pharmacy's 2026-03-02 minutes record the 8-0-0 vote to change Dosage.site to CodeableReference(BodyStructure) and close FHIR-54332 as a duplicate. Focused Jira, Zulip, and Confluence searches found no later conflicting decision.

AutoFHIR reconciliation:
Updated the Dosage.site requirements and comment cells in source/datatypes/dosage.xml to describe a coded or referenced site and to explain that the element may carry a summary code, a BodyStructure reference with laterality/location qualifiers, or both. This keeps the existing CodeableConcept binding untouched and removes stale guidance that would send implementers to the extension path instead of the new CodeableReference capability.

Recommendation:
Keep this source fix as the completion of FHIR-54848 in core. Do not publish a separate FHIR-54332 reconciliation commit from this worker because it was explicitly closed as a duplicate of this same change.
