FHIR-5942: Remove stale stableDate terminology

Issue request:
FHIR-5942 was a Published/Persuasive vocab change request for DSTU1 asking to rename ValueSet.stableDate to ValueSet.lockedDate and fix the associated descriptions so the resource used the VSD "Locked Date" terminology rather than overlapping with binding stability terms.

Initial application:
The main ValueSet resource rename was applied in git-svn commit 29e0f369d9 (#5942 - ValueSet: rename "stableDate" to "lockedDate"). Current active ValueSet source now defines ValueSet.compose.lockedDate, but the active version-management narrative still contained later-introduced references to a "stable date" and "StableDates".

Additional context:
Later published ValueSet lockedDate issues refined the semantics and definition, especially FHIR-5982's context-dependent interpretation and FHIR-18702's VSD-aligned definition. Those later decisions support preserving the current lockedDate element and wording while removing obsolete stableDate terminology. No directly relevant Zulip or Confluence records were found.

AutoFHIR reconciliation:
Updated source/versions.html to refer to a linked locked date and to "Locked dates" in the value set/code system versioning policy. The historical source/history.html release note that says stableDate was renamed to lockedDate was intentionally left unchanged.

Recommendation:
Keep this commit as the current-spec reconciliation for FHIR-5942. The active ValueSet definition already uses lockedDate, and this removes the remaining non-historical stableDate terminology discovered in build-scope source.
