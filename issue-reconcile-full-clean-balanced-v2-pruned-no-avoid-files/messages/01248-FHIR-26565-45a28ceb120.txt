FHIR-26565: Allow empty Parameters through ele-1

Issue request:
FHIR-26565 was Published/Persuasive for FHIR-core Parameters after the generated Schematron global-1 rule applied to every FHIR XML element and rejected an otherwise empty Parameters resource. The approved resolution was to make the correction as a technical correction, recorded for R4/R4B and applied for R5.

Initial application:
The change was applied on the R4B line by commit 3d8b755ddc, which added an empty Parameters exception to the ele-1 human text, FHIRPath expression, and generated-Schematron XPath source. That commit is not an ancestor of the current branch, and the current source/datatypes/element.xml still had the generic ele-1 expression and XPath without the Parameters exception.

Additional context:
FHIR-I minutes for 2020-05-11 record the 14-0-0 decision that the Schematron was wrong and needed technical-correction treatment. The originating Zulip thread includes Grahame Grieve stating that empty Parameters resources can be valid and later confirming the global Schematron was wrong. FHIR-31733 subsequently noted the same R4B ele-1 Parameters exception and explicitly said to make sure it was reflected in R5. FHIR-43103 later clarified the ele-1 human text to say "or both"; this commit preserves that later clarification while restoring the Parameters exception.

AutoFHIR reconciliation:
Updated the active datatype spreadsheet source source/datatypes/element.xml, which feeds the build's common Element invariant definitions through source/fhir.ini's active datatype configuration. The ele-1 human text now mentions the empty Parameters exception, the FHIRPath expression allows `$this is Parameters`, and the XPath used for generated Schematron allows `self::f:Parameters`.

Recommendation:
Keep this source fix. It restores a voted and previously implemented technical correction on the current branch without undoing the later FHIR-43103 wording clarification; generated outputs should be regenerated by the normal FHIR build pipeline.
