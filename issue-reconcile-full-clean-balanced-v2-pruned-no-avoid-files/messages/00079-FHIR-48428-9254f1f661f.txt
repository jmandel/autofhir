FHIR-48428: Bind dataType property values

Issue request:
FHIR-48428 was Applied with a Persuasive with Modification resolution to add the dataType property to http://hl7.org/fhir/concept-properties, add that property to each defined concept property, and bind the dataType property values. The final Jira comments and TI follow-up replaced the initially proposed new value set with the existing http://hl7.org/fhir/ValueSet/concept-property-type value set.

Initial application:
Git commit 2bc7ab59c65b2fabdf8631bc3af22d997763853a added the dataType property and populated dataType concept-property values in source/codesystem/codesystem-concept-properties.xml. That application also added the codesystem-property-valueset extension, but because it was inserted on the following CodeSystem.property block it bound the existing status property to concept-property-type instead of binding the new dataType property. Later source history refined some dataType values to dateTime and added additional concepts without changing that misplaced binding.

Additional context:
source/fhir.ini actively includes concept-properties under [codesystems], so source/codesystem/codesystem-concept-properties.xml is in the current build scope. The codesystem-property-valueset extension definition is scoped to CodeSystem.property and is intended to identify the permitted values for a coded property. The existing concept-property-type value set is already in the CodeSystem.property.type binding and contains the current dataType values, so no new CoreConceptPropertyDataTypes value set is needed. FHIR-45679 is an earlier duplicate/background report about the comment property's type, and FHIR-53549 is later Triaged text discussion; neither changes this applied source fix.

AutoFHIR reconciliation:
Moved the codesystem-property-valueset extension from the status property definition onto the dataType property definition, leaving the existing dataType concept values and the existing concept-property-type value set unchanged.

Recommendation:
Keep this source commit as-is. It corrects the only remaining semantic mismatch from FHIR-48428 by making tools read the value-set restriction from dataType rather than from status; no further core change is needed unless a future work-group decision changes the concept-property-type value set or CodeSystem property datatype wording.
