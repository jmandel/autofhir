FHIR-20500: Document constraint suppression in profiling

Issue request:
FHIR-20500 was Published as Persuasive for R5. It asked FHIR-I to let derived implementation guides suppress context-sensitive guidance or warning constraints, by adding ElementDefinition.constraint.suppress as a 0..1 boolean for non-error constraints, documenting that it is for spurious or incorrect warnings/good-practice guidance in derived profiles, adding an invariant that errors cannot be suppressed, and updating profiling guidance.

Initial application:
Core commit d92793b398246ecee92d54bbff49bfac2e34c0d0 added ElementDefinition.constraint.suppress to source/datatypes/elementdefinition.xml, added the approved definition and usage note, added the FHIRPath invariant `(severity = 'error') implies suppress.empty()`, and added a suppress row to source/conformance-rules.html. The active ElementDefinition datatype is in build scope through source/fhir.ini, and ConstraintSeverity currently contains only error and warning codes, so the error-only invariant covers the active error severity model.

Additional context:
ElementDefinition.constraint.xpath is now marked removed in source/fhir.ini, so the legacy XPath typo left in the spreadsheet invariant row is not part of the current ElementDefinition constraint surface. A later AutoFHIR FHIR-31406 profiling-page fix added language saying the tools do not support suppressing constraints while documenting a different ElementDefinition-suppress extension for removing inherited descriptive properties; read literally, that sentence obscured the FHIR-20500 ability to suppress warning or best-practice constraint messages in a derived profile.

AutoFHIR reconciliation:
Updated source/profiling.html, an active profiling narrative page, to retain the accurate snapshot-generation point that inherited constraints remain in snapshots while explicitly documenting that a derived profile can set ElementDefinition.constraint.suppress on a warning or best-practice constraint to suppress the corresponding message instead of removing the constraint.

Recommendation:
Keep this source fix. It completes the profiling-page documentation requested by FHIR-20500 without changing the already-correct ElementDefinition datatype definition, invariant, or conformance-rules description.
