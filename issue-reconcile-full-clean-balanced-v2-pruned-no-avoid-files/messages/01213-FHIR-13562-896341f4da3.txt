FHIR-34068: Align DiagnosticReport media search description

Attribution note: surfaced while reviewing FHIR-13562, but direct Jira backing for this change is FHIR-34068.

Issue request:
FHIR-13562 was a Published/Persuasive OO change request raised for STU3. It said DiagnosticReport.image and its description incorrectly implied a single still image even though the element type supported broader Media content, and its accepted resolution was to rename DiagnosticReport.image to DiagnosticReport.media.

Initial application:
The change was initially applied in Jira-tagged commit 17a86882a2828780d4c4f2bd3155b8434c7af17f, which changed the DiagnosticReport spreadsheet element names and the ultrasound example from image to media and updated nearby notes text. Later build refactors moved the active source into structuredefinition-DiagnosticReport.xml and bundle-DiagnosticReport-search-params.xml, and source/fhir.ini retains DiagnosticReport.image only as a legacy alias to DiagnosticReport.media.

Additional context:
DiagnosticReport is an active current-build resource in source/fhir.ini. The current StructureDefinition already uses DiagnosticReport.media and image-or-data wording for DiagnosticReport.media, media.comment, and media.link, including the later FHIR-34068 broadening of media.link from image-only to image-or-data. A related FHIR-33105 audit on the combined branch confirmed other stale image/imaging element wording had already been reconciled. The remaining in-build mismatch found for this seed was the DiagnosticReport media search parameter description, which still said "A reference to the image source." despite code="media" and expression="DiagnosticReport.media.link".

AutoFHIR reconciliation:
This commit updates source/diagnosticreport/bundle-DiagnosticReport-search-params.xml so SearchParameter/DiagnosticReport-media now says "A reference to the image or data source." This keeps the active search parameter surface aligned with the authoritative DiagnosticReport.media.link definition and removes the last current source wording found that could still imply the renamed media search parameter is image-only.

Recommendation:
Keep this source fix as-is. No further core follow-up is needed for FHIR-13562 unless future generated output diverges from the corrected source; the fhir.ini DiagnosticReport.image alias should remain as a compatibility mapping, not as active element guidance.
