FHIR-13609: Clarify SMART CapabilityStatement extension location

Issue request:
FHIR-13609 was Published/Persuasive for STU3 and asked the core FHIR specification to formally define the SMART on FHIR extensions used on CapabilityStatement.

Initial application:
Jira records application in an SVN revision. Source history shows the applied change in git-svn commit fc9f4585b4, which added the smart-app-launch profile entry, introduction page, and spreadsheet-backed definitions for the capabilities and oauth-uris CapabilityStatement.rest.security extensions. R4 published those extension definitions from core.

Additional context:
Later R5 source history removed the SMART extension rows from the core spreadsheet in dd468d4f17 while leaving the smart-app-launch profile page active in source/fhir.ini. The current FHIR Extensions Pack now owns the formal StructureDefinition sources for http://fhir-registry.smarthealthit.org/StructureDefinition/capabilities and http://fhir-registry.smarthealthit.org/StructureDefinition/oauth-uris, and its IG configuration lists those URLs as special extension URLs. The current core page therefore should not imply that this empty core profile still publishes the formal definitions.

AutoFHIR reconciliation:
Updated the active core smart-app-launch introduction to direct readers to the FHIR Core Extensions Registry pages for capabilities and oauth-uris and to the SMART App Launch IG for the launch specification. This keeps the current core build accurate without reintroducing extension definitions that now belong in the Extension Pack.

Recommendation:
Keep this commit. Further changes to the extension definitions themselves should be made in HL7/fhir-extensions; any decision to remove the historical core landing page entirely should be handled as a separate work-group/editorial decision.
