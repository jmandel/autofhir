FHIR-14642: Document email subscription subject parameter

Issue request:
FHIR-14642 is a Published/Persuasive FHIR-core Subscription issue from STU3 asking to document that when the email subscription channel is used, the channel header value sets the email subject. The request was non-substantive documentation for the Subscription email channel.

Initial application:
The request was initially applied in SVN revision 13401, represented in git as 73cab4d6f35939116870402fb00b3717d6177a2f, by adding text to source/subscription/subscription-notes.xml saying that Subscription.channel.header sets the subject of the email. Later Subscription redesign work rewrote the channel documentation and removed that exact sentence.

Additional context:
Subscription is active in the current build via source/fhir.ini, and source/subscription/subscription-notes.xml is the current Subscription resource narrative. The R5 Subscription redesign flattened Subscription.channel into top-level channel fields, and FHIR-39034 later replaced the string-valued Subscription.header with the key/value Subscription.parameter backbone. The current email channel remains a core channel, while the current source only defined REST-hook parameter behavior and did not carry forward the email subject mapping. Community searches found no Zulip or Confluence decision reversing FHIR-14642.

AutoFHIR reconciliation:
This commit adds a narrow paragraph to the Email channel section documenting the current-model equivalent of the original rule: a Subscription.parameter whose name is Subject sets the email notification subject line to the supplied value. The change is limited to the active Subscription narrative and does not edit generated diagrams or obsolete proposal text.

Recommendation:
Keep this commit. It preserves a previously published email-channel rule after the header-to-parameter model change, without broadening Subscription.parameter semantics beyond the specific email Subject parameter needed for FHIR-14642.
