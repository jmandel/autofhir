FHIR-5899: Align HumanName name search wording

Issue request:
FHIR-5899 was a Published FHIR-core Patient change request with a Persuasive with Modification resolution. It asked for the Patient "name" search parameter to include HumanName.text, and the final PA resolution expanded the clarification to all name-based search parameters on Patient, Practitioner, RelatedPerson, and Person so servers could use a server-defined, free-text style search across name properties.

Initial application:
The Jira comments identify SVN revision 9027 as the applied change. In git history this is bd0f9cdf485f62a9fc72955669fbd73479777edd, which changed the then-active Patient, Practitioner, RelatedPerson, and Person spreadsheet search descriptions from narrower name-part wording to the HumanName string-field wording that includes text. The original applied wording also contained an inherited typo, "give", and duplicate "suffix" entries.

Additional context:
The current build uses the active resource folders listed in source/fhir.ini for Patient, Practitioner, RelatedPerson, and Person. Current Patient-name was later corrected by e6a9a72025eeda3b1b5e3ee29af2c350f5809762 while applying FHIR-25446, and FHIR-20003/FHIR-39454 confirm the Patient-specific typo cleanup is already represented on the combined branch. The parallel Practitioner, RelatedPerson, and Person search-parameter bundles still had the same stale typo/duplicate wording even though their intended FHIR-5899 semantics matched Patient. Direct Confluence and Zulip searches for FHIR-5899 found no contrary community decision.

AutoFHIR reconciliation:
This commit keeps the FHIR-5899 HumanName.text behavior intact and changes only the active Practitioner-name, RelatedPerson-name, and Person-name SearchParameter descriptions from "family, give, prefix, suffix, suffix, and/or text" to "family, given, prefix, suffix, and/or text". Patient-name already had this wording and was left unchanged.

Recommendation:
Keep this source fix. It completes the seed's expanded all-name-resource clarification without changing search expressions or broadening behavior beyond the already approved FHIR-5899 rule.
