FHIR-25036: Fix Device distributor path

Issue request:
FHIR-25036 was Published as Persuasive with Modification for FHIR-core Device. It asked whether Device.manufacturer really identifies the manufacturer versus a labeler or other legally responsible party; the final decision left Device.manufacturer as-is and added Device.distributor with name and organizationReference children.

Initial application:
The Jira application comment points to PR/commit 949e41e, whose underlying source commit c1f487b940 added Device.distributor to source/device/structuredefinition-Device.xml. That source application created the requested backbone and children, but accidentally placed the human description in the element path attribute instead of the canonical path, leaving Device.distributor without a valid path.

Additional context:
Device is an active resource in source/fhir.ini, so source/device/structuredefinition-Device.xml is in current build scope. Device.manufacturer already says it may be the manufacturer or entity legally responsible for the device. The related DeviceDefinition distributor discussion was handled separately: FHIR-29727 was withdrawn/duplicate, and FHIR-30503 later added DeviceDefinition.packaging.distributor while explicitly avoiding a top-level DeviceDefinition.distributor.

AutoFHIR reconciliation:
This commit corrects the Device.distributor path to Device.distributor and preserves the misplaced descriptive text as the element short description. It does not change DeviceDefinition or re-open the manufacturer naming decision.

Recommendation:
Keep this source fix as-is. It repairs the conformance source for the already-approved Device.distributor element without broadening FHIR-25036 beyond the published resolution or conflicting with the later DeviceDefinition packaging decision.
