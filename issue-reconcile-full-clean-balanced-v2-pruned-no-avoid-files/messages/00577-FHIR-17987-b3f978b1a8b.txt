FHIR-17987: Make PaymentNotice amount optional

Issue request:
FHIR-17987 was a Published/Persuasive FM change request for PaymentNotice from the STU3 ballot cycle. It asked to add `amount 0..1 Money` for the amount of the payment.

Initial application:
The 2018 application commit f369c813fb added PaymentNotice.amount to the PaymentNotice spreadsheet and example, but the spreadsheet row applied it as `1..1` rather than the Jira-requested `0..1`. The source was later refactored into `source/paymentnotice/structuredefinition-PaymentNotice.xml`, preserving the required cardinality.

Additional context:
PaymentNotice is active in the current build through `source/fhir.ini`, and the current authoritative StructureDefinition carries the added Money element. Later published R4/R5 surfaces and current source still showed amount as `1..1`. A 2021 #implementers Zulip thread raised exactly this optionality problem, and Paul Knapp confirmed a use case where the payment amount is not required and suggested changing the cardinality to `0..1`. Searches found no later final Jira or Confluence decision requiring amount to remain mandatory.

AutoFHIR reconciliation:
This commit changes only `PaymentNotice.amount` from min `1` to min `0` in the active PaymentNotice StructureDefinition, preserving the Money type, max `1`, definition, requirements, and summary flag.

Recommendation:
Keep this source fix. It aligns the current build with the final Jira request and later implementer discussion, while avoiding unrelated PaymentNotice changes already covered by separate issues.
