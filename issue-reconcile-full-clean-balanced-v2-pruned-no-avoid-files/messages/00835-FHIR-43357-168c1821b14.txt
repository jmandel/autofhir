FHIR-43357: Align Observation.focus device metric guidance

Issue request:
FHIR-43357 was Applied/Persuasive with Modification for R6 by Orders and Observations. The original request asked to allow Observation.subject to reference DeviceMetric, but the approved resolution intentionally used Observation.focus instead: keep the device as the subject, use the DeviceMetric as the focus, and capture the observing device in Observation.device.

Initial application:
The issue was partially applied before this reconciliation. Commit bec50cdfef6eccfa3ed3a0de2ebc6d630641cd88 changed Observation.focus from patient-of-record to subject-of-record and replaced the old focus comment with examples, and commit 8e8cc5d46abce6d51e0c9831a1936af36cc63746 normalized those XML values. However, the resulting definition still described the focus as associated with the patient, and the comment omitted the approved implanted-device example while narrowing the device-metric example to a patient-attached device.

Additional context:
The linked Zulip device-settings discussion and later Jira comments show why the work group chose focus instead of expanding Observation.subject: a setting value can be about the subject Device while the specific DeviceMetric identifies the setting, and Observation.device can still identify the measuring or calibrating device. OO minutes on 2024-03-05 captured the action as adding DeviceMetric rationale to Observation.focus, and the Jira resolution records the 2024-05-23 OO vote. Observation is active/normative in source/fhir.ini, and Device and DeviceMetric are active approved resources, so source/observation/structuredefinition-Observation.xml is in current build scope. FHIR-50017 is a related later example issue already represented on the combined branch and is not decided again here.

AutoFHIR reconciliation:
This commit updates the authoritative Observation StructureDefinition source so Observation.focus now uses the approved subject-general definition and comment examples. It removes the residual patient-specific focus definition, restores the implanted-device example, and states the approved device-settings pattern: device subject, DeviceMetric focus, and observing device in .device. It intentionally does not add DeviceMetric to Observation.subject because the final issue decision rejected that direct subject-reference approach in favor of focus.

Recommendation:
Keep this source fix as-is. No additional core FHIR change is needed for FHIR-43357 unless the work group later decides to reopen the larger modeling question of allowing DeviceMetric directly in Observation.subject.
