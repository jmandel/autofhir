FHIR-11124: Add signedOn alias to ServiceRequest authoredOn

Issue request:
FHIR-11124 was Published with resolution Not Persuasive with Modification. It asked whether DiagnosticRequest.authored should use a more generic/signed-oriented name, and the final resolution was to rename the element to authoredOn and add signed on as an alias.

Initial application:
The named workflow application commit 839bf586 included #11124 and changed the generic Request pattern from Request.authored to Request.authoredOn with aliases createdOn and signedOn. DiagnosticRequest was later merged into ProcedureRequest by FHIR-11119 and then carried forward into the active ServiceRequest lineage, where the element remained authoredOn and was described as the date the request was signed/transitioned to actionable.

Additional context:
The current build no longer contains DiagnosticRequest as an active resource; source/fhir.ini lists DiagnosticRequest under removed resources and lists ServiceRequest as active. The current Request pattern still carries the signedOn alias, and the ServiceRequest authoredOn element maps to Request.authoredOn, but ServiceRequest itself only retained the old orderedOn alias. The FHIR-11119 Jira and related Zulip discussion confirm DiagnosticRequest and ProcedureRequest were intentionally combined before the later ProcedureRequest-to-ServiceRequest rename.

AutoFHIR reconciliation:
Added signedOn as an alias on ServiceRequest.authoredOn in source/servicerequest/structuredefinition-ServiceRequest.xml. This is in current build scope through the active ServiceRequest resource entry, and the hunk is limited to the active successor of the retired DiagnosticRequest element so the resource-level ElementDefinition now preserves the seed issue's explicit alias decision as well as the request-pattern source.

Recommendation:
Keep this commit as-is. No broader request-resource sweep is recommended because FHIR-11124 was specific to DiagnosticRequest and the generic Request pattern already contains signedOn; this commit only fixes the active successor that would otherwise omit the seed's requested alias.
