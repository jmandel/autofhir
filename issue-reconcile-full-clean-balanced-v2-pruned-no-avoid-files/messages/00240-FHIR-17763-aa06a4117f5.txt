FHIR-17763: Remove obsolete Immunization SNOMED notice

Issue request:
FHIR-17763 was Published with a Persuasive with Modification resolution for the Immunization status reason value set: remove the redundant SNOMED CT vaccine-refusal descendants, include all eight v3 ActReason/C-CDA codes, and keep the Immunization.statusReason binding as example.

Initial application:
Commit 8386871f82a95342647f6f39d9e145d17dd4f980 applied the value-set composition change by deleting the SNOMED CT include and adding PHILISOP, RELIG, VACEFF, and VACSAF to the existing four v3 ActReason concepts. The old SNOMED copyright/license notice was left behind and later metadata normalization continued to carry it even though the value set no longer included SNOMED content.

Additional context:
source/fhir.ini actively lists immunization as a built resource, and Immunization.statusReason still binds to http://hl7.org/fhir/ValueSet/immunization-status-reason with example strength. Later work such as FHIR-54325 updated the statusReason description for entered-in-error use but did not reintroduce SNOMED content or change the example binding. The CarePlan aggregate status-reason value set still legitimately carries a SNOMED notice because one of its other included value sets contains SNOMED CT concepts; that aggregate is not changed here.

AutoFHIR reconciliation:
Removed the obsolete SNOMED copyright/license notice from source/immunization/valueset-immunization-status-reason.xml. The value set now contains only the eight v3 ActReason concepts required by the Jira resolution and no longer tells implementers that this specific Immunization value set includes SNOMED CT content.

Recommendation:
Keep this source fix. It completes the intended FHIR-17763 removal by aligning the value set metadata with its current non-SNOMED composition; no further core source change is recommended for this issue.
