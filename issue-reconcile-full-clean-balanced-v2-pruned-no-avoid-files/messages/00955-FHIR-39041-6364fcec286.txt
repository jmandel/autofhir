Issue request:
FHIR-39041 was Published/Persuasive with Modification for R5 Subscription $events. The ballot comment asked to correct the content parameter's value set reference from the backport content value set to http://hl7.org/fhir/ValueSet/subscription-payload-content, while also considering whether to remove the content parameter. The final resolution kept the content parameter because query-time overrides can be useful and directed only the value set reference correction.

Initial application:

That application left the parameter documentation text from the original R4B/backport import, still saying "Codes from backport-content-value-set".

Later FHIR-50623 re-raised the stale backport wording and a broader question about whether clients should request a different content level, but it remains Triaged/Unresolved and is not independently decided here.
