FHIR-32985: Complete MeasureReport location support

Issue request:
FHIR-32985 was Published with a Persuasive with Modification resolution for R5. It asked to stop treating the reporting location as part of MeasureReport.reporter, add a first-class MeasureReport.location element that can reference a Location or an Organization representing where the report is from, and add a public health indicator example sent from multiple locations.

Initial application:
The issue was partially applied in source history. Commit 692a0961542b67f199286eb41cd512ee69ade637 added MeasureReport.location and removed Location from MeasureReport.reporter, but the new element allowed only Reference(Location) and therefore missed the approved Organization target. Commit af54eae034891419e6713e7ed99a72d67b666569 added the MeasureReport-location search parameter. The current HIV indicators example was listed as a public health data example, but it did not actually populate MeasureReport.location.

Additional context:
MeasureReport is active in the current build through source/fhir.ini, and the edited StructureDefinition, search parameter bundle, and listed example are all source files under the active resource folder. Later applied issue FHIR-40416 intentionally changed MeasureReport.location from 0..1 to 0..*, with Zulip implementer consultation and no discovered objection, so this reconciliation preserves the later 0..* cardinality rather than reverting to the original FHIR-32985 cardinality. No Confluence reference or conflicting Zulip discussion for FHIR-32985 was found.

AutoFHIR reconciliation:
This commit updates the authoritative MeasureReport StructureDefinition so MeasureReport.location can reference either Location or Organization, updates the matching location search parameter description and target metadata, and updates the HIV indicators public health MeasureReport example to include two contained Location resources referenced through repeated location elements. The checked-in SVG remains a generated-looking diagram artifact and was not hand-edited; the authoritative XML now carries the corrected semantics for regeneration.

Recommendation:
Keep this commit. It completes the missed semantic part of FHIR-32985 while respecting FHIR-40416's later cardinality change; no further core source action is indicated beyond normal generated artifact refresh during the build.
