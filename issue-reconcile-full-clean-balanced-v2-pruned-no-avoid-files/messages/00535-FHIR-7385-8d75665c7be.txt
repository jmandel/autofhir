FHIR-7385: Clarify contained resources do not inherit context

Issue request:
FHIR-7385 was Published / Not Persuasive with Modification for a DSTU1 ballot comment asking whether omitted subject values on contained resources could always be inferred from the container. The approved resolution was the opposite: rewrite the contained-resource guidance to explicitly say contained resources do not inherit values from their context because that uncertainty is unsafe.

Initial application:
The issue was applied in git-svn revision 5814, now commit 6bb9d508d3, which changed source/references.html to say contained resources do not "inherit" context from their parent resource. That application left an earlier sentence from aaf83231c2 saying contained resources were the "only exception" to the no-inheritance/non-conduction statement in the page introduction, so the current page still had conflicting guidance.

Additional context:
FHIR-7366 is the linked companion Published issue with the same approved resolution. Earlier FHIR-3691 and FHIR-5223 explain the original context-conduction concern, while the later unresolved FHIR-50639 independently reports that the current introduction contradicts the contained-resource section. The page is in current build scope because source/fhir.ini maps the Reference type page to references.html.

AutoFHIR reconciliation:
This commit changes the introductory sentence from saying contained resources are an exception to saying they follow the same no-inheritance rule, matching the existing contained-resource section and the Published FHIR-7385 resolution without adding broader new requirements.

Recommendation:
Keep this source correction. A future audit can decide FHIR-7366 separately as the same-change-family companion if desired; FHIR-50639 should remain a separate unresolved tracker rather than being represented by this commit.
