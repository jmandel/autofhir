FHIR-13702: Correct Encounter status subjectStatus reference

Attribution note: surfaced while reviewing FHIR-22726, but direct Jira backing for this change is FHIR-13702.

Issue request:
FHIR-22726 was Published/Persuasive for R5. It asked for clearer Encounter guidance around Encounter period start/end timing where billing or documentation close-out can differ from clinical arrival, discharge, or completion, and its resolution specifically added a discharged Encounter.status code plus Status Management guidance relating discharged/completed to subjectStatus and administrative processing.

Initial application:
The issue was initially applied in d80fcb1ea0598fcaa22158a24d8db793657ccda7, which added the discharged code and definition to the Encounter status CodeSystem, added discharged to Encounter.status, and added Status Management text for post-care administrative completion. Commit 5524e4a36dc7976d2dae9ca4806ec1ee9030d2b0 carried the same status-code list into the then-current statusHistory source. The current source retains the discharged CodeSystem concept, the required Encounter.status binding through ValueSet/encounter-status, and the Status Management discussion.

Additional context:
Encounter is active in source/fhir.ini, so source/encounter/structuredefinition-Encounter.xml, source/encounter/codesystem-encounter-status.xml, source/encounter/valueset-encounter-status.xml, source/encounter/encounter-introduction.xml, and source/encounter/encounter-event-mapping-exceptions.xml are build-scope source. Later Encounter work renamed Encounter.period to Encounter.actualPeriod and added plannedStartDate/plannedEndDate, while FHIR-13702/FHIR-32343 introduced and refined Encounter.subjectStatus. Those later changes support keeping the FHIR-22726 timing/status guidance but revealed one current-source defect: Encounter.status said the patient-specific state was subjectState, which is not an Encounter element, instead of subjectStatus.

AutoFHIR reconciliation:
This commit fixes the build-scope Encounter.status definition and the matching Event mapping exception to refer to Encounter.subjectStatus. No other source changes were needed because the discharged status, its definition, the required value-set include, and the Status Management guidance already express the FHIR-22726 decision. The generated-looking encounter.svg still contains the old text and is intentionally left alone because authoritative XML source should drive regenerated diagrams.

Recommendation:
Keep this source fix as-is. It removes a wrong element-name reference in the exact status/subjectStatus guidance area covered by the issue without re-litigating later R6 Encounter status-management work; handle any broader FHIR-54098/FHIR-54491 narrative rewrites separately if that Resolved - change required scope is included.
