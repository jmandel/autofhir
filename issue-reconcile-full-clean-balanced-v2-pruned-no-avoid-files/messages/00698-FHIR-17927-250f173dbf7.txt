FHIR-17927: Enforce Claim related reference requirement

Issue request:
FHIR-17927 is a Published/Persuasive Financial Management change request for FHIR-core Claim, raised and applied for STU3, asking that each Claim.related entry provide either related.claim or related.reference.

Initial application:
Historical commit afb5ec66f6 mentioned tracker 17927 in a broad Claim/ClaimResponse spreadsheet update, but inspection of the old Claim spreadsheet and the current StructureDefinition history did not find a carried-forward invariant for Claim.related. The current source/claim/structuredefinition-Claim.xml Claim.related backbone came from the 2021 source rework without this constraint.

Additional context:
Claim is an active core resource in source/fhir.ini. Current source defines Claim.related.claim, Claim.related.relationship, and Claim.related.reference as optional children, which allowed a related entry containing only relationship. Jira searches found no later FHIR-core decision reversing this Claim constraint, and Zulip/Confluence searches found no directly relevant conflicting community discussion.

AutoFHIR reconciliation:
Added an error invariant on Claim.related, clm-2, requiring claim.exists() or reference.exists(). This keeps relationship optional but prevents a related entry that lacks both the Claim reference and alternate case/file identifier required by the published Jira decision.

Recommendation:
Keep this source-changing commit. The edit is limited to the active authoritative Claim StructureDefinition and restores the published constraint without changing unrelated Claim semantics.
