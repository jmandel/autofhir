FHIR-31843: Remove stale jurisdictional authorization surfaces

Issue request:
FHIR-31843 was a Published/Persuasive with Modification BRR change request for R5. It asked why MedicinalProductAuthorization/RegulatedAuthorization needed a jurisdictionalAuthorization link from a country-level authorization to state or territory authorizations; the approved resolution said there were no current-system use cases tracking sub-jurisdiction authorizations and that the linkage would be removed.

Initial application:
The issue was explicitly applied before this reconciliation. Commit 3cd1c587c1503cb86541f9f13a94dcff69bb9850 removed RegulatedAuthorization.jurisdictionalAuthorization from the StructureDefinition and converted the example element to an XML comment. Commit 08d35148dd0fa3866502882e1805fe34cb107da4 also removed the StructureDefinition element and deleted the example element entirely. Current HEAD already lacks RegulatedAuthorization.jurisdictionalAuthorization in the authoritative StructureDefinition, but still retained the commented example block from the R4B-side application and retained the element/type in the active FHIR ModelInfo Library.

Additional context:
source/fhir.ini keeps RegulatedAuthorization active and maps the old MedicinalProductAuthorization name to RegulatedAuthorization; it also keeps Library active/approved. source/regulatedauthorization/list-RegulatedAuthorization-examples.xml lists the edited example, and source/library/list-Library-examples.xml lists Library/library-fhir-model-definition as a current example. BRR minutes for 2021-07-27 confirm FHIR-31843 was approved as persuasive with modification 18-0-0. Zulip and Confluence full-text searches found no conflicting discussion. The FHIR ModelInfo Library still has broader legacy MedicinalProductAuthorization naming, but this reconciliation only removes the specific jurisdictionalAuthorization surface approved by FHIR-31843.

AutoFHIR reconciliation:
Removed the stale commented jurisdictionalAuthorization block from source/regulatedauthorization/regulatedauthorization-example.xml, removed the stale jurisdictionalAuthorization element and MedicinalProductAuthorization.JurisdictionalAuthorization class from source/library/library-fhir-model-definition-content.xml, and refreshed the embedded base64 attachment in source/library/library-fhir-model-definition.xml so the Library resource and linked ModelInfo content stay synchronized.

Recommendation:
Keep this source fix. It completes the current-build removal required by FHIR-31843 without expanding into the separate legacy ModelInfo resource-name cleanup for MedicinalProductAuthorization versus RegulatedAuthorization.
