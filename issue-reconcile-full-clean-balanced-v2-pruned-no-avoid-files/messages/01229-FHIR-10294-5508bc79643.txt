FHIR-10294: Restore request workflow notes

Issue request:
FHIR-10294 is a Published/Persuasive OO change request for DSTU2 asking that DeviceUseRequest, DiagnosticRequest, NutritionRequest, and Supply request-resource introductions state that the resource is a FHIR workflow request resource and link to workflow.html#request.

Initial application:
Commit ba3dfa8e added the workflow request note to DeviceUseRequest, DiagnosticRequest, NutritionRequest, and SupplyRequest introductions in 2016. The current ServiceRequest lineage still retained the DiagnosticRequest/ProcedureRequest request-resource note, but current DeviceRequest and NutritionOrder had later lost the note, and SupplyRequest is no longer an active core resource.

Additional context:
Current source/fhir.ini lists DeviceRequest, NutritionOrder, and ServiceRequest as active core resources; SupplyRequest was removed from the core resource list by 3b38b80 and current workflow pages point to the external OO incubator artifact. Later ballot-note edits ce624b1f and 157f87dd removed the previously applied request workflow paragraph from DeviceRequest and NutritionOrder while adding R6 ballot notes. No direct Zulip or Confluence record was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:
Added the request workflow note with workflow.html#request links back to the active DeviceRequest and NutritionOrder introductions, and updated the retained ServiceRequest note to link directly to the request workflow anchor. No source change was made to the stale/out-of-build SupplyRequest source directory.

Recommendation:
Keep this commit. It restores the approved workflow classification note for the current active core successors of the DSTU2 resources without editing out-of-build SupplyRequest material; if the external OO incubator SupplyRequest artifact lacks the same note, handle that in the owning external specification.
