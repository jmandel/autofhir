FHIR-44836: Clarify Vital Signs Panel hasMember wording

Issue request:
FHIR-44836 was Applied with a Persuasive with Modification disposition for the Observation Vital Signs Panel. The approved changes were to remove QuestionnaireResponse and MolecularSequence from the panel hasMember reference choices, clarify that the panel represents vital signs such as those listed in the table rather than only the listed rows, and replace old "related links (type=has-member)" wording with explicit Observation.hasMember wording for panel members.

Initial application:
The Jira application comment cites git b6f4cd5560, which updated source/observation/observation-vitalsigns-profile-introduction.xml so the vital signs table now says "This represents a panel of vital signs, e.g. those listed in this table" and "In this panel, Observation.valueQuantity is not present... it uses Observation.hasMember". The current active vitalspanel profile derives from the vitalsigns profile, and the vitalsigns profile constrains Observation.hasMember to Reference(Observation), so the non-Observation targets named in the issue are no longer permitted through this profile family.

Additional context:
The linked Zulip thread shows the reporter filed FHIR-44836 because implementers read the R4 table and vitalspanel profile inconsistently about whether only table-listed vital signs could be panel members. OO WGM minutes for 2024-09-23/27 record the final direction that other codes can be added to the LOINC panel and the 18-0-0 persuasive-with-modification motion. The active Vital Signs implementation guide includes StructureDefinition/vitalspanel, so the profile root definition is build-scope source, not an out-of-build artifact.

AutoFHIR reconciliation:
This commit fixes the remaining stale profile definition in source/observation/structuredefinition-profile-vitalspanel.xml. It now says the panel has no Observation.value[x] and uses Observation.hasMember to reference member Observations, replacing the obsolete "related links (with type=has-member)" wording that survived the initial table-only application.

Recommendation:
Keep this commit. It completes the FHIR-44836 clarification in an active source definition while leaving the already-correct table text and inherited hasMember target constraint unchanged. A separate reconciliation can handle unrelated vitalspanel summary cardinality wording from FHIR-36401 if that issue is selected.
