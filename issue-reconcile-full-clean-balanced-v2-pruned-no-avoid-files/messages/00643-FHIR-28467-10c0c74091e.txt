FHIR-28467: Correct direct endpoint format code system

Issue request:
FHIR-28467 was a Published/Persuasive R5 Patient Administration change request for Endpoint. It asked that the Endpoint.payloadType example vocabulary use the full FormatCode value set already used for DocumentReference.content.format, rather than manually including selected codes from the IHE OID code system.

Initial application:
The request was explicitly applied in git commit 5fc677fa57632c25c76d2acac93f5d333b10dcb3, which removed the long copied list from source/endpoint/valueset-endpoint-payload-type.xml and imported http://terminology.hl7.org/ValueSet/v3-HL7FormatCodes instead. Current source still has that include, and Endpoint.payload.type binds to the active endpoint-payload-type example value set.

Additional context:
Endpoint is active in source/fhir.ini, and endpoint-example-direct is listed in the active Endpoint examples list. Later FHIR-40247 moved payloadType under Endpoint.payload but preserved the Direct example's old IHE OID coding.system for the HL7 C-CDA format-code URI. FHIR-39617 then added a parallel XCA C-CDA example using http://terminology.hl7.org/CodeSystem/v3-HL7DocumentFormatCodes, and the current THO CodeSystem confirms urn:hl7-org:sdwg:ccda-structuredBody:1.1 belongs to that HL7 document format code system.

AutoFHIR reconciliation:
This commit updates source/endpoint/endpoint-example-direct.xml so the Direct endpoint example uses http://terminology.hl7.org/CodeSystem/v3-HL7DocumentFormatCodes for its C-CDA format code. No value-set source was changed because the FHIR-28467 value-set include is already present.

Recommendation:
Keep this source fix. Future changes to the content or expansion of the FormatCodes value set should be handled in THO/IHE/UTG unless a separate FHIR-core issue changes the Endpoint binding or example set.
