FHIR-15837: Align Administration patient-link search guidance

Issue request:
FHIR-15837 was a Published/Persuasive PA change request raised against STU3 and applied for R5. It asked for the Patient compartment text to clarify that records associated with a linked Patient are not returned from a compartment search for the current Patient, and are returned only by searching the linked Patient's own compartment.

Initial application:
The issue was explicitly applied by commit 70018974761c29e31793ae3e4ad9960e85ccd1f9, which updated source/compartments.xml with the resolved Patient Compartment Identity wording for linked and merged patients. Current source/compartments.xml still contains that wording. However, source/administration-module.html retained an older active implementer note from 2016 saying the specification did not define whether searches should follow linked patients and was seeking feedback.

Additional context:
The Administration module page is in the current build hierarchy, and the active CompartmentDefinition resource is in source/fhir.ini. The original Zulip thread confirmed that the old linked-patient wording needed clarification. PA minutes and related issue FHIR-19687 later distinguish linking from merging: link behavior remains separate/cross-system or client-side, while merge behavior moves references/data to the target Patient. Existing combined-branch audits for FHIR-17487 and FHIR-19687 support the same linked-versus-merged interpretation and do not supersede the FHIR-15837 clarification.

AutoFHIR reconciliation:
This commit updates the active Administration module note so it no longer says the behavior is undefined or solicits feedback. The replacement text points readers to the Patient compartment definition and states the current rule: compartment searches for a Patient do not return records associated with a linked Patient; those require a separate compartment search for the linked Patient resource.

Recommendation:
Keep this source fix. It removes a stale contradiction from an active module page while leaving the authoritative Patient compartment wording unchanged. No further core source change is needed for FHIR-15837 unless PA later revises the linked-versus-merged Patient search model.
