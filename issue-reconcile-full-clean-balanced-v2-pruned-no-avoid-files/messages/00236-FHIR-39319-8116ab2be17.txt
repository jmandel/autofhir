FHIR-39319 + FHIR-54014: Clarify Dosage.text as complete SIG text

Attribution note: surfaced while reviewing FHIR-39319, but direct Jira backing for this change is FHIR-39319 + FHIR-54014.

Issue request:
FHIR-39319 was Published/Persuasive for R5 by Pharmacy. It asked whether Dosage.text was intended to be additional free text or a text representation of the entire dosage; the accepted resolution says Dosage.text is intended as a complete free-text representation of the dosage, commonly called the SIG, with requirements text saying it SHOULD represent the structured SIG data when structured data exists.

Initial application:
No git commit explicitly mentioning FHIR-39319 was found in the FHIR source history. The current Dosage spreadsheet and checked-in R5 history still retained the older short/definition/requirements that described free text as mainly for instructions too complex to code and did not say it was a complete representation.

Additional context:
The original Zulip thread and Pharmacy meeting records show the UK use case for a complete string representation and Pharmacy's agreement that the Dosage.text description needed clarification. FHIR-13222 is earlier supporting context for putting administration/preparation details in Dosage.text. Later R6 work in FHIR-54014 introduced DosageDetails.renderedInstruction as the required full human-readable representation for MedicationRequest.dosageInstruction, so the MedicationRequest narrative needed to stop repeating the obsolete Dosage.text wording.

AutoFHIR reconciliation:
Updated source/datatypes/dosage.xml so Dosage.text short, definition, and requirements state that it is a complete free-text dosage/SIG representation and should reflect the current structured Dosage fields when those fields exist. Updated source/medicationrequest/medicationrequest-notes.xml to align MedicationRequest dosage guidance with the active R6 DosageDetails.renderedInstruction model while still noting that individual Dosage entries can carry complete Dosage.text SIG text.

Recommendation:
Keep this source fix. It applies the published Pharmacy decision to active build inputs and preserves the later R6 renderedInstruction redesign without making unrelated NutritionOrder or generated-artifact changes.
