FHIR-14238: Remove stale AdverseEvent suspect entity examples

Issue request:
FHIR-14238 was Published/Persuasive with Modification for STU3. It asked for AdverseEvent.suspectEntity.instance to support Immunization, and the final resolution expanded the target set to Reference(Immunization|Procedure|Substance|Medication|MedicationAdministration|MedicationStatement|Device).

Initial application:
The issue was applied in git commit b88fc91916 by changing the legacy AdverseEvent spreadsheet target type from Reference(Substance|Medication|MedicationAdministration|MedicationStatement|Device) to Reference(Immunization|Procedure|Substance|Medication|MedicationAdministration|MedicationStatement|Device). The later StructureDefinition source rework preserved the broader targetProfiles, but the element definition still retained the old narrower examples.

Additional context:
AdverseEvent is an active resource in source/fhir.ini, so source/adverseevent/structuredefinition-AdverseEvent.xml is in the current build scope. Later Immunization discussions, including FHIR-15124 and the related Zulip thread, restored/kept Immunization.reaction for documenting the reaction itself, but did not reverse the approved ability for AdverseEvent.suspectEntity.instance to reference Immunization when AdverseEvent is the appropriate reporting/causality resource.

AutoFHIR reconciliation:
This commit keeps the existing targetProfile list, including Immunization and Procedure, and removes the stale non-exhaustive examples from the AdverseEvent.suspectEntity.instance definition so the prose no longer implies the element is limited to substance, medication, medication administration, medication statement, or device.

Recommendation:
Keep this source fix. No broader change to Immunization.reaction or AdverseEvent guidance is needed for FHIR-14238 because those workflow questions were handled separately by FHIR-15124 and current source already carries the permitted reference targets.
