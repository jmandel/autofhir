FHIR-37567: Split ActivityDefinition PRN reason elements

Issue request:
FHIR-37567 was a Published CDS change request for R5 asking ActivityDefinition to capture PRN activities by adding asNeeded 0..1 boolean and asNeededFor 0..* CodeableConcept elements, with an example such as ibuprofen as needed for pain or fever. The Persuasive resolution agreed to add the elements and include an example.

Initial application:
PR HL7/fhir#2288 merged the original implementation. Commit 608ae761fb52456eb6fb54054ed0bccf719ba8da added an ActivityDefinition.asNeeded[x] boolean-or-CodeableConcept choice, added a parallel PlanDefinition.asNeeded[x] element and PlanDefinition overlap note, but did not add an ActivityDefinition example. The current source retained the choice element, so it could not represent asNeeded=true together with multiple PRN reasons as requested.

Additional context:
source/fhir.ini lists ActivityDefinition as an active resource with CDS ownership and FMG approval, so source/activitydefinition/structuredefinition-ActivityDefinition.xml and the examples list are in current build scope. FHIR-34325 is a supporting published PRN decision that split Dosage.asNeeded[x] into separate asNeeded and 0..* asNeededFor elements with any-condition semantics for multiple reasons, and it is already represented on the combined branch. Focused Jira searches found no separate PlanDefinition asNeededFor issue, so this reconciliation stays scoped to ActivityDefinition rather than broadening the seed to PlanDefinition or other request resources. Focused Zulip and Confluence searches found no seed-specific discussion that changes the Jira/source conclusion.

AutoFHIR reconciliation:
Changed ActivityDefinition.asNeeded[x] to ActivityDefinition.asNeeded boolean plus ActivityDefinition.asNeededFor 0..* CodeableConcept, added the asNeededFor/asNeeded invariant, preserved the medication-as-needed-reason example binding, added an ibuprofen-as-needed ActivityDefinition example with pain and fever reasons, registered that example in the ActivityDefinition examples list, and updated the checked-in ActivityDefinition diagram label to match the authoritative source.

Recommendation:
Keep this source fix. It completes the published ActivityDefinition request without deciding separate PRN consistency issues for PlanDefinition, DeviceRequest, or ServiceRequest; those should remain separate work if a work group wants broader alignment.
