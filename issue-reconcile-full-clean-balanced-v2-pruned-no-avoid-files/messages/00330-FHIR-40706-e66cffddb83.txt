FHIR-40706: Stop using deprecated valueset special status

Issue request:
FHIR-40706 was an Applied/Persuasive FHIR-core Vocabulary issue asking what to do with http://hl7.org/fhir/StructureDefinition/valueset-special-status after the submitter could not identify a useful definition or alignment with related workflow-status extensions. The approved resolution was to deprecate valueset-special-status because there did not appear to be any use for it.

Initial application:
No core commit explicitly mentioned FHIR-40706. The relevant extension definition has moved to the FHIR Extension Pack, where commit 2d8d674 marked valueset-special-status deprecated, d0ac764 added the deprecation rationale to its description, and ea2d7b0 made the StructureDefinition status retired with a standards-status reason. The core FHIR checkout no longer defines the extension, but it still used the deprecated extension on source/terminologies/codesystem-fhir-types.xml.

Additional context:
The September 2023 Terminology Infrastructure minutes confirm the vote to deprecate valueset-special-status and to create separate tickets for related extensions such as codesystem-workflowStatus. FHIR-45254 later handled codesystem-workflowStatus in the FHIR Extension Pack. Zulip discussion shows the fhir-types note existed to warn implementers that this normative CodeSystem is generated and can change contents across FHIR versions, so the reconciliation should preserve that warning rather than silently drop it.

AutoFHIR reconciliation:
Removed the valueset-special-status extension instance from the active core CodeSystem fhir-types source and moved the same normative/generated-content warning into CodeSystem.description. This eliminates the stale use of the deprecated extension while preserving the implementer-facing meaning in a standard element. The OID registry entry for the extension canonical was left intact because it records the canonical/OID assignment rather than an active use.

Recommendation:
Keep this commit as-is. The extension definition remains deprecated/retired in the FHIR Extension Pack, the only active core use has been removed, and the fhir-types warning remains available without depending on the deprecated extension. No FHIR-45254 commit is published here because that related issue belongs to the FHIR Extension Pack and was already applied there.
