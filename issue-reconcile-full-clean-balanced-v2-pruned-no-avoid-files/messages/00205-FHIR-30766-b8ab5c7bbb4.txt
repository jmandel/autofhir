FHIR-30766: Clean CDA Bundle identifier wording

Issue request:
FHIR-30766 was Published/Persuasive for R5 by Structured Documents. It asked to replace the CDA comparison text saying Bundle.id is equivalent in function to ClinicalDocument.id with wording that Bundle.identifier is equivalent to ClinicalDocument.id.

Initial application:
The issue was initially applied in PR #1953. Commit 3e8cd2b05fc54febc626fb78bfcfb344b93ef72c changed the Composition CDA note from Bundle.id to Bundle.identifier. Commit ad98b08fee0ad580d40e0647f1f87858b231629b later updated the same FHIR-30766 sentence with code formatting and the Bundle.meta.security to ClinicalDocument.confidentialityCode mapping, but left the sentence with a duplicated "where the".

Additional context:
The Composition resource is active in source/fhir.ini, so source/composition/composition-introduction.xml feeds the current build. Structured Documents minutes and the implementers Zulip thread both support the same mapping: CDA ClinicalDocument.id belongs with Bundle.identifier rather than Bundle.id. FHIR-32532 is a related Composition.identifier cardinality issue from the same discussion, but its Jira comments explicitly say the Bundle.identifier mapping moved forward under FHIR-30766.

AutoFHIR reconciliation:
This commit makes the current application clean by removing the duplicated "where the" from the active Composition CDA narrative while preserving the applied Bundle.identifier, Bundle.meta.security, ClinicalDocument.id, and ClinicalDocument.confidentialityCode mappings.

Recommendation:
Keep this source correction as-is. The FHIR-30766 mapping is already represented in the current source and this commit only fixes the malformed sentence left by the historical application; no additional FHIR-core follow-up is needed for this issue.
