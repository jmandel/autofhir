Issue request:
FHIR-51941 was Applied/Persuasive for R6 by the Devices work group. It asked that DeviceAlert and DeviceMetric workflow/FiveWs mapping exceptions be corrected where appropriate, or explicitly justified, including structural DeviceAlert changes such as acknowledgement actor support and summary/mapping updates.

Initial application:
PR HL7/fhir#3858 was merged as a9dbcddfee853c4ab66ceea5995f97eb4b83a650, with source commit 01bbb9c148540bff89dd84b48b212afb3dfef0e8 addressing DeviceAlert and DeviceMetric mapping exceptions for FHIR-51941. A later cleanup commit e096e0eaf5bc66a35bdee31cfb007ececf819efd moved the new DeviceAlert.acknowledgedBy element but preserved its workflow mapping as Event.actor.

Additional context:
source/fhir.ini lists DeviceAlert and DeviceMetric as active resources, so the StructureDefinition and mapping-exception files are in current build scope. Devices minutes from 2025-10-20 and 2025-10-22 show the WG reviewed the mapping exceptions, approved FHIR-51941's structural changes 6-0-1, and discussed the closely related DeviceMetric tickets FHIR-52930 and FHIR-52931. Current source already contains the broad FHIR-51941 application, but Event.actor is not an Event pattern path used elsewhere in the source; current Event mappings use Event.performer.actor.

AutoFHIR reconciliation:
This commit changes DeviceAlert.acknowledgedBy's workflow mapping from the invalid Event.actor path to Event.performer.actor and updates devicealert-event-mapping-exceptions.xml so the Event performer actor deviation is documented as the acknowledgedBy mapping instead of incorrectly remaining an unmapped performer actor.

Recommendation:
Keep this source fix. It is a narrow correction to the already-applied FHIR-51941 work and aligns the authoritative DeviceAlert StructureDefinition and mapping-exception rationale with the approved acknowledgement actor change.
