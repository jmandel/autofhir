FHIR-28491: Document Subscription.topic canonical lookup

Issue request:
FHIR-28491 was Published/Persuasive for R5 and requested that Subscription.topic reference SubscriptionTopic by canonical URL. The approved request also asked for client-facing documentation that clients needing the SubscriptionTopic can search SubscriptionTopic resources and/or try to resolve the canonical, but might not be able to retrieve the SubscriptionTopic directly.

Initial application:
The main model change was applied before this reconciliation: git commit 4f3fcec039 changed Subscription.topic in the then-authoritative subscription spreadsheet from Reference(SubscriptionTopic) to canonical(SubscriptionTopic), and Jira later recorded commit 70355f13b2 as a broader Subscription documentation/application commit for this tracker family. After the source refactor, the current active StructureDefinition already had type canonical targeting SubscriptionTopic, but the Subscription.topic element still lacked the requested direct guidance about lookup versus direct retrieval.

Additional context:
The Subscription resource is active in source/fhir.ini, so source/subscription/structuredefinition-Subscription.xml feeds the current build. FHIR-I meeting minutes and the originating Zulip discussion confirm the intent: canonical references should not prevent discovery, clients can use GET/Search on SubscriptionTopic, and a canonical topic can be unresolvable or not backed by a locally hosted definition. Later Subscription documentation says topics are referenced by canonical URL, and general canonical-reference documentation describes canonical search/resolution, but the element-specific note requested for Subscription.topic was still missing.

AutoFHIR reconciliation:
This commit adds a Subscription.topic comment explaining that clients can look for the corresponding SubscriptionTopic by searching the server's SubscriptionTopic resources, such as with the url search parameter, and/or try direct canonical resolution, while direct retrieval might not be supported.

Recommendation:
Keep this commit as-is. It completes the remaining documentation part of the published decision at the element definition where the Jira linked, without changing the already-correct canonical type or adding unrelated Subscription behavior.
