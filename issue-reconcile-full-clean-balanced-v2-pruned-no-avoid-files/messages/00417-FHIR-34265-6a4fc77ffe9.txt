FHIR-34265: Add RequestOrchestration apply operation

Issue request:
FHIR-34265 was Published/Persuasive for R5 and asked RequestGroup actions to support the definitional and dynamic aspects of PlanDefinition.action: input, output, definition, dynamicValue, and transform. The accepted resolution also directed that RequestGroup/$apply be defined to mirror PlanDefinition/$apply.

Initial application:
The issue was partially applied in git commit d9a4d4c599, which added the requested action input, output, definition, transform, and dynamicValue elements to the active RequestOrchestration structure definition. That implementation did not add a RequestGroup/RequestOrchestration $apply OperationDefinition, and the active RequestOrchestration operations list remained empty.

Additional context:
The current build maps legacy RequestGroup to RequestOrchestration in source/fhir.ini, so the current source location for this issue is source/requestorchestration. Later PlanDefinition $apply decisions, especially FHIR-46313, relaxed the expected output to a Bundle containing any appropriate Request resources, including CarePlan, RequestOrchestration, and individual request resources. No direct Zulip or Confluence evidence for FHIR-34265 was found that changed the Jira resolution.

AutoFHIR reconciliation:
Added source/requestorchestration/operationdefinition-RequestOrchestration-apply.xml and referenced it from source/requestorchestration/list-RequestOrchestration-operations.xml. The new operation follows the current PlanDefinition $apply shape for type and instance invocation, accepts the RequestOrchestration plus the same core application-context parameters, and returns one Bundle per input subject with Request resources produced from applicable actions.

Recommendation:
Keep this source fix. It completes the missing operation-definition half of the published Jira resolution while preserving the already-applied RequestOrchestration action elements and aligning the operation text with later PlanDefinition $apply output guidance.
