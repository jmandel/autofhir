FHIR-12449: Correct HumanName ISO qualifier examples

Issue request:
FHIR-12449 was a Published/Persuasive DSTU2 change request asking to fix Scandinavian HumanName examples that used an invalid iso21090-EN-qualifier extension URL and represented the qualifier as Coding instead of code.

Initial application:
The issue was recorded in Jira as already fixed, and git history shows commit 857e4c9172 corrected the first Scandinavian example's extension URL and code system in 2019. The current source still had valueCoding in that example, and later examples plus JSON fragments added by the FHIR-19608 work still contained the obsolete URL and Coding representation, so the application was incomplete in the current build source.

Additional context:
The current datatypes examples page is included in source/hierarchy.xml under the DataTypes page. The iso21090-EN-qualifier StructureDefinition now lives in the FHIR Extension Pack and constrains Extension.value[x] to code with a required binding to name-part-qualifier, where MID is the Scandinavian mellannamn/mellomnavn code. Zulip discussion around the HumanName/ISO 21090 examples led to FHIR-12351 but did not supersede the need for these examples to use the registered extension and valueCode.

AutoFHIR reconciliation:
Updated the Scandinavian HumanName XML and JSON examples in source/datatypes-examples.html to use http://hl7.org/fhir/StructureDefinition/iso21090-EN-qualifier with valueCode MID. The JSON fragments now align primitive _given entries with the given array positions so the MID extension annotates the intended name part.

Recommendation:
Keep this commit. It is a source correction on an active narrative examples page and aligns the examples with the current extension definition without changing the broader HumanName modeling guidance.
