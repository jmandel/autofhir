FHIR-40607: Use singular Duration UCUM displays

Issue request:
FHIR-40607 was Applied/Persuasive with Modification for R6. It asked FHIR Infrastructure to make the duration-related UCUM value set displays internally consistent with ucum-common by using singular displays such as "day", and to correct all-time-units so it expands for time units rather than remaining empty.

Initial application:
No FHIR-40607-tagged source commit was found on this checkout. The active Duration datatype binding still pointed at valueset-duration-units as the extensible value set and valueset-all-time-units as the maximum value set, but valueset-duration-units still carried plural explicit displays. The all-time-units source still used a UCUM canonical filter value of "a", which tx.fhir.org expands to zero concepts.

Additional context:
The ucum-common source already uses singular displays for the same UCUM duration codes. FHIR-I minutes for 2023-03-27 confirm that UCUM displays are generated by tooling, that all-time-units could not be expanded in R5, and that the accepted target was the singular form "day". Later FHIR-39153/FHIR-44735/UP-481 terminology-migration work is related but not part of this Applied seed: FHIR-44735 is still Resolved - change required and says all-time-units should be retained/migrated because it is used as a maximum binding.

AutoFHIR reconciliation:
This commit changes the explicit concepts in source/datatypes/valueset-duration-units.xml to singular displays matching ucum-common. It also changes source/datatypes/valueset-all-time-units.xml from canonical "a"/year to canonical "s"/second so the UCUM terminology expansion is non-empty for time-duration units.

Recommendation:
Keep this source fix for FHIR-40607. Do not enumerate all possible all-time-units concepts in core; if FHIR-44735 is later applied, handle the THO migration of all-time-units and related value sets as that separate issue.
