FHIR-39318: Remove stale named-query parameter comments

Issue request:
FHIR-39318 was Published with a Persuasive with Modification resolution for R5 named-query clarifications. It asked to replace the old named-query return prose with a single output parameter named "result" of type Bundle, add an invariant, remove the redundant OperationDefinition.parameter comment, clarify standard/resource search-parameter scope and CapabilityStatement implications, state that named queries are searches invoked through _query rather than $operation, document parameter ordering/repetition, and compare named queries with SearchParameter.

Initial application:
The issue was mostly applied by git commit 0c731f1d46ea8b8785e84141832ec9f570a92a26, which added the named-query narrative, boundary text, invariant opd-7, and invariant examples. That commit did not remove the existing OperationDefinition.parameter comment; the same stale comment also remained on OperationDefinition.parameter.part.

Additional context:
source/fhir.ini actively lists operationdefinition=OperationDefinition, so source/operationdefinition/structuredefinition-OperationDefinition.xml is in the current core build. The current source already has the FHIR-39318 narrative and invariant: operationdefinition-notes.xml says named queries are searches with a single Bundle result parameter, parameter ordering does not matter, parameters can repeat as allowed, standard/resource search parameters are in scope but not necessarily supported, and named queries cannot be invoked as $operations; operationdefinition-introduction.xml distinguishes custom queries from SearchParameter. FHIR-I minutes record the 21-0-0 Persuasive with Modification vote, and the originating Zulip thread confirms the ambiguity came from the old return-bundle prose and parameter comment.

AutoFHIR reconciliation:
This commit removes the stale OperationDefinition.parameter and OperationDefinition.parameter.part comments that still said query definitions only have one output parameter named "result". The authoritative constraint and narrative now carry the rule, including the Bundle type, without leaving redundant definitions-tab comments behind.

Recommendation:
Keep this source fix. No further core FHIR change is recommended for FHIR-39318 unless the work group wants a broader editorial rewrite of the already-applied named-query explanation, which was not needed to satisfy the published resolution.
