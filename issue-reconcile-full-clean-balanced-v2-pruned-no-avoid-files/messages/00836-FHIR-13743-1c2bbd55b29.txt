FHIR-13743: Restore CarePlan allergy address guidance

Issue request:
FHIR-13743 was a Published Patient Care change request raised for STU3 asking to add AllergyIntolerance, Observation, RiskAssessment, List, and possibly other resources to CarePlan.addresses. The final Not Persuasive with Modification resolution kept CarePlan.addresses constrained to Condition rather than broadening it, and instead required both Condition boundaries text and CarePlan.addresses text explaining that allergy/intolerance diagnoses can use Condition and AllergyIntolerance but decision support needs an AllergyIntolerance representation.

Initial application:
The issue was initially applied in git commit 32b35437cc8daef171fb42950801c6a39d6f918b, which added the allergy/intolerance decision-support sentence to the old CarePlan spreadsheet comment and refined the same guidance in Condition boundaries. The current Condition boundaries page still carries that wording. During the later source rework to StructureDefinition XML, CarePlan.addresses was converted into the current source form with CodeableReference guidance, and the FHIR-13743 allergy/intolerance sentence was no longer present in the CarePlan.addresses comment.

Additional context:
CarePlan and Condition are active current-build resources in source/fhir.ini. Current CarePlan.addresses is a CodeableReference whose reference targets are Condition, Procedure, and MedicationAdministration after later work such as FHIR-32512; this later expansion does not add AllergyIntolerance as a direct CarePlan.addresses target or remove the need for the allergy/intolerance decision-support guidance. Searches of Zulip and Confluence for FHIR-13743 and the CarePlan/allergy terms found no conflicting community record.

AutoFHIR reconciliation:
This commit restores the missing FHIR-13743 guidance to the current CarePlan.addresses comment while preserving the later CodeableReference/concept-vs-reference guidance and target profiles. It also updates the parallel CarePlan Request mapping-exception resource text so the source metadata remains consistent with the StructureDefinition comment.

Recommendation:
Keep this source fix as-is. If Patient Care later wants CarePlan.addresses to directly reference AllergyIntolerance, that would be a separate substantive change; FHIR-13743 explicitly chose clarification rather than broadening the reference list.
