FHIR-36213: Correct Device operation status reason descriptions

Issue request:
FHIR-36213 was Published/Persuasive with Modification for R5. It requested an example value set for Device.operation.statusReason, replacing Device.operationalStatus.reason, with the approved MDC-derived example codes 3::6728, 3::6678, 3::462, 3::6708, 3::694, 3::724, 3::120, 3::132, and 3::410.

Initial application:
Commit 50f4a45ebb2b applied the issue by adding source/device/codesystem-device-operation-status-reason.xml, adding source/device/valueset-device-operation-status-reason.xml, and binding Device.operation.statusReason to http://hl7.org/fhir/ValueSet/device-operation-status-reason. The approved code list survived in current source, but the new CodeSystem and ValueSet descriptions were copied as "availability status reason" even though the artifact and Jira issue are for operation/operational status reason.

Additional context:
FHIR-32409 is the earlier Device binding issue that led to example reason/status terminology work. FHIR-36208 created the companion Device.operation.status value set. FHIR-37545 later renamed operationalState/operationalStatus terminology toward operation-specific names, and FHIR-38904 later removed the Device.operation status/statusReason/operator backbone content from the active Device structure. Current Device is active in source/fhir.ini, but XML parsing finds no active Device.operation element; the operation-status-reason terminology remains as a built terminology artifact with the approved FHIR-36213 code list. OO Confluence minutes from 2022-04-11 reference FHIR-36213 and the Jira vote, while targeted Zulip searches found no conflicting discussion.

AutoFHIR reconciliation:
This commit updates only the authoritative CodeSystem and ValueSet descriptions for device-operation-status-reason so the standalone terminology now describes the current operational status reason of the device. It intentionally does not reintroduce Device.operation.statusReason or change the code list, because later applied Device modeling decisions removed that backbone from the active current StructureDefinition and the Jira-approved codes are already present.

Recommendation:
Keep this source fix. No further core change is needed for FHIR-36213 unless the work group separately decides to retire or repurpose the now-unbound Device operation status-reason terminology after later Device modeling changes.
