FHIR-27149: Clarify SubscriptionTopic registry discovery

Issue request:
FHIR-27149 was a Published FHIR-core Subscription change request, resolved Not Persuasive with Modification. It asked for a registry of known SubscriptionTopics so implementers could find reusable topic definitions; the accepted resolution was that registry.fhir.org would automatically support this, but the subscriptions documentation should point readers there and explain how to search it.

Initial application:
No git commit explicitly mentions FHIR-27149. The same 2020-05-18 FHIR-I meeting handled adjacent subscription tracker FHIR-27148, and commit 77b1c1d6, whose subject cites FHIR#27148, added the original Finding Subscription Topics section with a registry.fhir.org link. Later SubscriptionTopic resource-page work also encouraged publishing and checking topic definitions in the registry. Those changes pointed readers to the registry, but the current section had lost the stable finding-topics anchor used by later Jira context and did not explain the registry filtering step.

Additional context:
source/fhir.ini actively lists Subscription and SubscriptionTopic, so both edited source pages are in current build scope. FHIR-43508 later revisited the same registry-discovery experience after implementers had difficulty finding topics; the work group concluded registry support was functioning and added the current early-adoption note explaining that few topics may exist yet. A 2022 Zulip thread similarly found no conflict with the registry direction, only scarcity of published SubscriptionTopic resources.

AutoFHIR reconciliation:
This commit restores the finding-topics anchor, updates the Subscriptions framework page to use the HTTPS registry link, and adds concise search guidance: search by a topic title or canonical URL and filter matching registry contents to FHIR resource instances of type SubscriptionTopic. It also links the SubscriptionTopic resource notes back to the Finding Subscription Topics section instead of duplicating the guidance.

Recommendation:
Keep this source fix. It completes the original FHIR-27149 documentation request without changing subscription semantics; revisit only if the work group wants a stable registry deep link or registry-owned user documentation instead of spec-page guidance.
