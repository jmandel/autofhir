FHIR-18473: Require one RDF tree root

Issue request:
FHIR-18473 was a Published/Persuasive STU3 FHIR-core RDF issue asking why multiple tree roots were permitted when the RDF page said multiple tree roots meant "it cannot be determined how to parse them as a single resource." The approved resolution requires systems responding to a FHIR operation with a FHIR resource, including a FHIR Bundle, to have exactly one node marked as a tree root.

Initial application:
The exact Jira comment reference GH#e2e131ac42 is not resolvable as a commit in the current checkout, but the RDF page was already in active build scope and the November 2018 xml-and-rdf history contained the multi-treeRoot ambiguity sentence. Later RDF page rewrites and usability work preserved the treeRoot concept but did not preserve the Jira-approved SHALL requirement.

Additional context:
The current RDF page is an active Resource Definitions subpage through source/hierarchy.xml. Current source explained fhir:nodeRole/fhir:treeRoot but weakened the multiple-root case to "may be impossible" and described the focal resource as the one not contained in another resource, which is insufficient for Bundles because bundled entry resources are not contained resources. Jira and community searches found no later decision reversing FHIR-18473.

AutoFHIR reconciliation:
This commit updates source/rdf.html to state the FHIR-18473 requirement directly, including Bundles, and restores the deterministic parse consequence when more than one node is marked as fhir:treeRoot.

Recommendation:
Keep this source fix. It aligns the active RDF narrative with the published Jira disposition and avoids a conformance ambiguity for RDF serializations with bundled resources or multiple apparent roots.
