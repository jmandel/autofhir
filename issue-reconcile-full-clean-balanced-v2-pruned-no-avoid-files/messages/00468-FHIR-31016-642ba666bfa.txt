FHIR-31016: Clarify MedicationDispense request wording

Issue request:
FHIR-31016 was Published with resolution Persuasive with Modification for R5. It requested that MedicationDispense no longer say a dispense is always the result of an order, and the approved wording was: "The medication dispense can be the result of a pharmacy system responding to a medication request."

Initial application:
The only direct source-history application found was commit 7453f87bfcb5eeba6020113412508cb95e5d4f0a, an aggregate Pharmacy commit for FHIR-31017, FHIR-31016, and other issues. It changed the MedicationDispense introduction from "is" to "can" but left "medication order" and did not update the root StructureDefinition description/definition. A later FHIR-44999 invariant fix touched the same root element and restored the pre-existing stale definition after an accidental replacement, but it did not address this wording decision.

Additional context:
MedicationDispense is active current-build source through source/fhir.ini, and the stale sentence existed in both the narrative introduction and the authoritative StructureDefinition root description/definition. Targeted Zulip and Confluence searches for FHIR-31016 found no relevant community record that narrowed or reversed the Jira resolution.

AutoFHIR reconciliation:
Updated source/medicationdispense/medicationdispense-introduction.xml and source/medicationdispense/structuredefinition-MedicationDispense.xml so the current build consistently uses the approved "can ... medication request" wording for the MedicationDispense resource summary. No authorizingPrescription-specific "medication order" text was changed because that element wording is a separate concept and not the sentence resolved by this issue.

Recommendation:
Keep this commit as-is. It completes the published Jira resolution in active MedicationDispense source without broadening the change beyond the approved sentence.
