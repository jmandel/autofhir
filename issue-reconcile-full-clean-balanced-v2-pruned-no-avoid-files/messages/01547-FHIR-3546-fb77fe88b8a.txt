FHIR-3546: Correct StructureDefinition element names

Issue request:
FHIR-3546 was Published/Persuasive for a DSTU1 Profile.Definition element named "formal" whose name confused ontology users because "formal definition" implies a definition represented in a formal language. MnM agreed on 2014-11-05 to rename it to "definition".

Initial application:
The original Profile resource change had already been applied before this reconciliation: the Jira comments record that the DSTU2 Profile resource no longer contained the "formal" element. No FHIR-3546-tagged source commit was found in the current git history.

Additional context:
The current build no longer has an active Profile resource; source/fhir.ini lists Profile only under removed resources and has StructureDefinition as an active resource. While checking the successor StructureDefinition source, the active notes page still referred to old ElementDefinition names element.formal and element.comments, even though current ElementDefinition defines ElementDefinition.definition and ElementDefinition.comment.

AutoFHIR reconciliation:
This commit updates the active StructureDefinition notes source so the explanatory list uses the current ElementDefinition names element.definition and element.comment. The hunk is necessary because the current page otherwise preserves the exact confusing old "formal" terminology FHIR-3546 was meant to remove from implementer-facing definitions.

Recommendation:
Keep this source fix. It is a narrow correction to active StructureDefinition narrative, aligns with the published FHIR-3546 decision, and does not require broader work-group review.
