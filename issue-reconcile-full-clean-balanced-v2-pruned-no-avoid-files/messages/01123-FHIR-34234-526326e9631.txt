FHIR-34234: Fix OperationDefinition operation code wording

Issue request:
FHIR-34234 was a Published/Persuasive FHIR-core Conformance and OperationDefinition clarification, raised for R4 and applied for R5, asking that CapabilityStatement.rest.[resource.]operation.name be clarified as the invocation name and normally match OperationDefinition.code, while OperationDefinition.code should be described as the recommended operation invocation URL name.

Initial application:
The issue was explicitly applied by git commit df39949a59ceb5924608a99ba9f3251679b12166. That commit correctly expanded CapabilityStatement.rest.resource.operation.name, but the OperationDefinition.code half appears to have been copied from the SearchParameter precedent: it said "search url" and referred to disambiguating multiple SearchParameters instead of operations.

Additional context:
FHIR-27755 supplied the SearchParameter precedent that FHIR-34234 intentionally mirrored. FHIR-36559 separately clarified the same CapabilityStatement operation.name comment to point to OperationDefinition.code and is already represented on the combined branch, so this commit does not duplicate that issue. Zulip discussion confirms the intended model: operations work like search parameters, with OperationDefinition.code as the default and CapabilityStatement.operation.name as the server-advertised invocation token when disambiguation is needed. FHIR-34235 is the companion Bulk Data IG issue and is outside this FHIR-core checkout.

AutoFHIR reconciliation:
This commit corrects the active OperationDefinition source so OperationDefinition.code is the recommended name for the operation invocation URL and refers to multiple OperationDefinitions rather than SearchParameters. It also updates the OperationDefinition definition-mapping exception that mirrors this element text, and the checked-in OperationDefinition SVG tooltip alongside the authoritative XML so the resource diagram does not retain stale generated wording.

Recommendation:
Keep this fixed commit as-is. No additional FHIR-core source change is needed for CapabilityStatement.operation.name, because the current active CapabilityStatement source already contains the intended OperationDefinition.code relationship and OperationDefinition.name non-correspondence note.
