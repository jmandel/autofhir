FHIR-9433: Align DiagnosticReport issued example

Issue request:
FHIR-9433 was a Published FHIR-core OO change request for Observation.issued and DiagnosticReport.issued. The final Persuasive with Modification disposition approved the 2017-05-23 wording package and added a link clarifying the relationship to the resource update time, so the issued elements describe when this version was made available rather than an original release date.

Initial application:
The issue was applied upstream in commit 2bc0950a1e354c2a99db1fca80954166c25bc241, whose message included #9433. That commit changed the DiagnosticReport and Observation spreadsheet sources: DiagnosticReport.issued moved from "released from the source diagnostic service" to "made available to providers" and Observation.issued gained "this version" plus the lastUpdated/update-time clarification. The current authoritative StructureDefinition sources preserve those base-resource changes.

Additional context:
DiagnosticReport, Observation, and StructureDefinition are active resources in source/fhir.ini. Later FHIR-31956 changed DiagnosticReport.issued from instant to dateTime and explicitly concluded that the existing DiagnosticReport.issued definition and comment adequately address the remaining guidance question; that issue is already represented on the combined branch and is not decided again here. The active StructureDefinition example at source/structuredefinition/structuredefinition-example.xml still had the pre-FHIR-9433 DiagnosticReport.issued short and definition, while invariant-test copies are negative test fixtures rather than current spec narrative.

AutoFHIR reconciliation:
This commit updates the active StructureDefinition/example DiagnosticReport.issued short and definition to match the current DiagnosticReport.issued wording. It intentionally leaves the authoritative Observation and DiagnosticReport base definitions unchanged because they already reflect FHIR-9433 and later FHIR-31956 context.

Recommendation:
Keep this source fix. It removes the remaining build-scoped stale example wording without broadening the issue into unrelated invariant-test fixtures or adding redundant DiagnosticReport guidance that OO later considered adequate.
