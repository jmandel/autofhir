FHIR-49751: Remove Specimen device bindings

Issue request:
FHIR-49751 was Applied/Persuasive with Modification for R6 after the OO work group voted to update all Specimen device elements to a codeable reference form for Device or DeviceDefinition, with no defined binding, and to update the related search parameters.

Initial application:
The change was initially applied in the FHIR-49751 implementation commits and PR trail: 49f1e8a changed collection, processing, and container device typing toward CodeableReference(Device|DeviceDefinition); 5fbd7fd and 0ca2e2b adjusted search parameter expressions for the changed device shape; d3b73a added DeviceDefinition to the remaining collection device target. That application did not remove the collection device example binding, and later source work reintroduced example bindings on processing and container device.

Additional context:
Specimen is an active core resource in source/fhir.ini, so source/specimen/structuredefinition-Specimen.xml is in current build scope. FHIR-39389 later recast DeviceDefinition references toward canonical modeling, so the current Specimen source represents these elements as device[x] choices with CodeableConcept, Reference(Device), and canonical(DeviceDefinition), which preserves the Device-or-DeviceDefinition intent after that later modeling work. FHIR-51695 added device code and reference search parameters, and FHIR-51580 later removed the reference parameters; the remaining code search parameters still target the CodeableConcept choice. FHIR-54488 separately raises a non-final binding mismatch concern for collection.device[x], but its Triaged status means it should not override the final no-binding instruction in FHIR-49751 here.

AutoFHIR reconciliation:
This commit removes the example binding blocks from Specimen.collection.device[x], Specimen.processing.device[x], and Specimen.container.device[x]. It does not change the current choice typing or search parameters because those already reflect the combined FHIR-49751/FHIR-39389/FHIR-51695/FHIR-51580 source state.

Recommendation:
Keep this commit as the FHIR-49751 reconciliation. If OO later applies FHIR-54488 or another final issue to intentionally add device-code example bindings, that later issue should reintroduce the approved binding/value set choices explicitly.
