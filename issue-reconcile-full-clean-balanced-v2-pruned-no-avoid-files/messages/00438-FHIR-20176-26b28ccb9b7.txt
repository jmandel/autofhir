FHIR-20176: Enforce bodySite BodyStructure subSite rule

Issue request:
FHIR-20176 was Published with a Persuasive with Modification resolution for the FM Claim family. It requested replacing the older bodySite/subSite overlap with a repeating bodySite backbone containing site[x] as either a coded site or Reference(BodyStructure), retaining subSite as coded detail, and adding the business rule that subSite must not be present when a BodyStructure reference is used.

Initial application:
Commit acb64eec3ca82f9a8d18d4091f2416029ee45dcd applied the structural part for R5 by changing Claim.item.bodySite, ExplanationOfBenefit.item.bodySite, ExplanationOfBenefit.addItem.bodySite, and ClaimResponse.addItem.bodySite to a BackboneElement with a repeating CodeableReference(BodyStructure) site plus bodySite.subSite. The current source still had that structure but did not have the requested invariant, and the combined reconciliation branch had no existing FHIR-20176 commit.

Additional context:
Claim, ClaimResponse, and ExplanationOfBenefit are active resources in source/fhir.ini, so their StructureDefinition XML files are authoritative build inputs. The current model uses CodeableReference rather than literal site[x] child names, so the Jira siteReference condition maps to site.reference in FHIRPath. ExplanationOfBenefit.addItem.bodySite is included because the original FHIR-20176 implementation converted it with the same pattern and it has the same BodyStructure-reference/subSite ambiguity. Later FHIR-38849 and FHIR-54843 discussions mention the same BodyStructure/subSite family but do not supersede the FM rule being reconciled here.

AutoFHIR reconciliation:
Added error invariants to the active Claim, ExplanationOfBenefit, and ClaimResponse bodySite backbone elements so site.reference.exists() implies subSite.empty(). This completes the missing business rule while preserving the already-applied CodeableReference structure and existing coded dental subSite examples.

Recommendation:
Keep this source fix. It is a narrow completion of the Published FHIR-20176 resolution; broader BodyStructure guidance and OO-owned bodyStructure cardinality work should remain with their later Jira issues rather than expanding this FM reconciliation.
