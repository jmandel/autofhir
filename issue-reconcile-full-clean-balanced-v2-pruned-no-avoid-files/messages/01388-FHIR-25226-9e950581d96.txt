FHIR-25226: Include Identifier type coding display in :text docs

Issue request:
FHIR-25226 was a Published/Persuasive FHIR-core search-page issue for R5. It asked for the token `:text` modifier description, which already named CodeableConcept.text, Coding.display, and Identifier.type.text, to also include Identifier.type.coding.display for consistency.

Initial application:
No direct Jira-tagged source commit was found for FHIR-25226, and a pickaxe search for `Identifier.type.coding.display` in the active search sources found no prior application. Before this reconciliation, the current search page and search-modifier-code CodeSystem included Identifier.type.text plus later Identifier.assigner.display and Reference.display context, but still omitted Identifier.type.coding.display from each parallel `:text`/`:text-advanced` definition.

Additional context:
The originating Zulip discussion confirms the omission was not intentional: when Paul Church asked why Identifier.type.coding.display was not included, Grahame Grieve answered that it had simply not been considered. FHIR-31708 later resolved no-change because Identifier.type matching was already established normative behavior. FHIR-35812, already represented on the combined branch, broadened the Identifier clarification and FHIR-32673, also already represented, made `:text-advanced` the advanced-processing counterpart to token `:text`; those decisions support keeping the same textual target examples aligned across both modifiers.

AutoFHIR reconciliation:
Updated source/search.html so the token/reference `:text` summary row, detailed `:text` prose, `:text-advanced` summary row, and detailed `:text-advanced` prose all list Identifier.type.coding.display. Updated source/searchparameter/codesystem-search-modifier-code.xml so the active `text` and `text-advanced` search modifier concept definitions list the same Identifier.type.coding.display target.

Recommendation:
Keep this commit as-is. It completes the approved FHIR-25226 correction across the active core search-page and search-modifier-code source surfaces without reopening the already-settled Identifier.type search behavior or duplicating the separate FHIR-35812/FHIR-32673 audit commits.
