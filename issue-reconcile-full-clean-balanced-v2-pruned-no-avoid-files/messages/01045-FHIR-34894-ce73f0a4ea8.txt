FHIR-34894: Restore Observation body site invariant

Issue request:
FHIR-34894 is a Published/Persuasive OO R5 change request asking Observation to add a 0..1 BodyStructure reference and an invariant making it mutually exclusive with Observation.bodySite.

Initial application:
The Jira comment points to PR #1916. Local history shows e48bf23f3e added Observation.bodyStructure as Reference(BodyStructure) plus obs-8, e90ce92f2e added its RIM mapping, and d6dedaf6fc merged the PR. The generated R5 history also contains obs-8 and condition markers on both Observation.bodySite and Observation.bodyStructure.

Additional context:
Observation and BodyStructure are active resources in source/fhir.ini. Later Applied issue FHIR-53203 converted Observation.bodyStructure to CodeableReference(BodyStructure) and deprecated Observation.bodySite, but its request did not approve using both elements together; the existing FHIR-53203 audit commit records the CodeableReference/deprecation application as no-change and leaves broader unresolved harmonization to later issues. FHIR-55603 later proposed a different two-element pattern with an invariant but was Resolved - No Change because further discussion was needed, while FHIR-54843 is Resolved - change required and not yet Applied/Published in this run scope. None of those later decisions supersedes the original mutual-exclusion rule for the current two Observation elements.

AutoFHIR reconciliation:
This commit restores the obs-8 constraint to the active Observation StructureDefinition, restores condition references on Observation.bodySite and Observation.bodyStructure, and adds invariant examples proving that an Observation with both elements fails while either element alone passes. The edit is in build scope because source/fhir.ini lists bodystructure=BodyStructure and observation=Observation in the active [resources] section.

Recommendation:
Keep this fix. Future applied work such as FHIR-54843 may revisit cardinality or broader bodyStructure guidance, but until such a change is applied the current specification should continue to prohibit simultaneous Observation.bodySite and Observation.bodyStructure use.
