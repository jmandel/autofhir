FHIR-31082: Require Expression language for executable content

Issue request:
FHIR-31082 was a Published/Persuasive with Modification FHIR-core R5 change request about Expression.language being required while Expression.expression and Expression.reference were optional. The final resolution was to make Expression.language 0..1, require language when Expression.expression or Expression.reference is present, and clarify that when both expression and reference are present, expression may name content within the referenced material.

Initial application:
FHIR-31082 was explicitly touched by commits 3d9ca6b48c19375838c5828d401259b44d9fea3a and 21448ecd9ec6a665f914564d2dac103c1e341a73. Those commits added the expression/reference clarification text but still left Expression.language effectively required through the old invariant. Commit 272e3fb71ea5f6b0f3be0fbf318c3f3f8e081d5e later applied the related FHIR-27029 cardinality and authoring guidance by changing Expression.language to 0..1, but the invariant sheet still required expression or reference instead of implementing the FHIR-31082 language rule.

Additional context:
Expression is in current build scope through source/fhir.ini as an active metadata datatype, metadata type-page entry, normative type, and abbreviation. FHIR-27029 is a closely related Published/Persuasive issue explaining why Expression must allow authoring-time description-only content. FHIR-49968 is a later same-artifact issue about Expression.expression/reference wording, but it is still Waiting for Input and is not a final source-edit decision for this run.

AutoFHIR reconciliation:
Updated source/datatypes/expression.xml so the first Expression invariant now says a language must be present when expression or reference is present, with matching FHIRPath and XPath. Also corrected the adjacent name invariant XPath so the removed expression/reference requirement does not remain in the XPath column under the wrong invariant.

Recommendation:
Keep this commit. It completes the missing conformance part of FHIR-31082 while preserving the already-applied language cardinality and expression/reference clarification. Handle the broader wording changes proposed in FHIR-49968 only after that tracker reaches a final Applied/Published state.
