FHIR-40310: Correct Transport reason prose

Issue request:
FHIR-40310 was an Applied/Persuasive-with-Modification OO change request for R6 asking to rename Transport.reason because it was confusing next to Transport.reasonCode and to fix missing TransportReason codes. The final decision was not to rename the element because reasonCode no longer exists, and to create an example TransportReason ValueSet from the suggested codes.

Initial application:
The Jira application comment points to commit a8f7c81ebc, which added source/transport/valueset-transport-reason.xml and bound Transport.reason to http://hl7.org/fhir/ValueSet/transport-reason. That applied the missing ValueSet portion, but the current Transport.reason source still described only a resource reference and still told readers to use Transport.reasonCode for uncoded text even though Transport.reasonCode had already been removed.

Additional context:
FHIR-39141 previously replaced Transport.reasonCode and Transport.reasonReference with Transport.reason CodeableReference, and this worker published a separate FHIR-39141 commit for the missed repeatable cardinality before this seed commit. FHIR-50649 is already represented on the combined branch and confirms that TransportReason is the remaining Transport ValueSet work after later Transport cleanup removed input/output. OO Confluence minutes for 2025-10-20 match the Jira resolution: no rename, because reasonCode was gone, and create an example ValueSet from HL70003/v2-0003 comments.

AutoFHIR reconciliation:
This commit updates the active Transport.reason definition to say the CodeableReference may carry a code or resource reference, updates the free-text guidance to point to Transport.reason.concept.text instead of the removed Transport.reasonCode, and keeps the Transport/Event mapping exception in sync with the corrected resource wording.

Recommendation:
Keep this source fix. The TransportReason ValueSet and binding are already present, and these prose corrections remove the remaining stale reasonCode guidance without changing the WG's decision to keep the Transport.reason element name.
