FHIR-16297: Update constrained datatype examples to MoneyQuantity

Issue request:
FHIR-16297 was Published with resolution Persuasive with Modification for FHIR-core datatypes. It asked to stop representing routine financial amounts with the heavy Quantity-based Money profile, introduce a lighter Money datatype with value and currency elements, and rename the existing Quantity profile to MoneyQuantity for cases such as Ratio where a Quantity representation is still needed.

Initial application:
The issue was explicitly applied by commit f6a1e8b33374575365609b3ab02dbed98b77133a, which added MoneyQuantity=Quantity to source/fhir.ini, added the MoneyQuantity Quantity restriction, created the Money datatype page content, and added Money guidance to source/datatypes.html. Current source/datatypes/money.xml already defines Money with only value and currency, both 0..1. Current source/datatypes/quantity.xml already defines MoneyQuantity as the Quantity-based constraint.

Additional context:
FHIR-22657 later clarified the same Money-versus-MoneyQuantity distinction for the Quantity variations section. That related issue is already represented on the combined branch by commit 944c8172dbcb92f00fd33da54ff49cd9e74bf84c, and current source/datatypes.html now lists MoneyQuantity with SimpleQuantity as Quantity constraints while leaving Money as a datatype. Two active guidance pages still carried pre-FHIR-16297 examples that described Money, linked to money.profile.xml.html, and showed StructureDefinition/Money as a constrained datatype.

AutoFHIR reconciliation:
This commit updates the stale constrained datatype examples in source/elementdefinition.html and source/structuredefinition/structuredefinition-notes.xml from Money to MoneyQuantity, including the profile links and StructureDefinition url/name in the example JSON. Both files are in current build scope: ElementDefinition is an active datatype page, and StructureDefinition is an active resource in source/fhir.ini.

Recommendation:
Keep this source-changing commit as-is. It completes the seed issue's rename semantics in nearby active conformance guidance without altering the already-correct Money datatype or MoneyQuantity constraint definitions.
