FHIR-20502: Fix ElementDefinition LOINC field-name mapping

Issue request:
FHIR-20502 was Published/Persuasive for FHIR-core ElementDefinition. It asked to change ElementDefinition LOINC mapping headings from "LOINC Code" to "LOINC Field Name" and to document why ElementDefinition mappings point to the LOINC table structure, because the values are LOINC table field names rather than LOINC term codes.

Initial application:
The issue appears to have been applied by git commit 1c4ff67fd8b1a5860f9fb1d6984eaab094137340, which changed the LOINC mapping-space column name and expanded the ElementDefinition mappings-page explanation. That application missed the active ElementDefinition spreadsheet heading in source/datatypes/elementdefinition.xml and left the mapping-space title saying "LOINC code for the element". The current rendered mappings page consequently lists LOINC in the summary table but has no generated LOINC mapping section.

Additional context:
ElementDefinition is an active datatype in source/fhir.ini, so source/datatypes/elementdefinition.xml feeds the current build. FHIR-16996 is an earlier same-family clarification that removed a misleading LOINC mapping from ElementDefinition.requirements and introduced the general ElementDefinition mappings-page context; it supports keeping the documentation on that page rather than adding unrelated prose elsewhere. Zulip and Confluence searches found no conflicting community guidance.

AutoFHIR reconciliation:
This commit changes the active ElementDefinition spreadsheet column heading to "LOINC Field Name", changes the LOINC mapping-space title to "LOINC field name for the element", and tightens the ElementDefinition mappings-page LOINC description to state that the displayed values are LOINC table field names rather than LOINC term codes.

Recommendation:
Keep this commit as-is. It completes the requested non-substantive clarification in the active source inputs and should restore generation of the LOINC mapping section with an accurate field-name label.
