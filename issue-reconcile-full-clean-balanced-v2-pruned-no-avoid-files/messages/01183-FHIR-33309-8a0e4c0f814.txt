FHIR-33309: Clarify include wildcard support scope

Issue request:
FHIR-33309 was Published/Persuasive for FHIR-core-search section 3.1.1.5.4. It requested a clarification that wildcard _include/_revinclude does not mean every reference search parameter a server supports for ordinary search; it means the reference search parameters supported for _include/_revinclude.

Initial application:
Git commit 01625dddcaabfbbe98974ea9eb5563a2e6b2979f ("FHIR-33309 First Pass") updated the syntax bullets in source/search.html to say wildcard references are supported by the server and to note that the list of search parameters supported for _include/_revinclude is not the same as the overall list of supported search parameters. That initial application did not update the later paragraph that directly repeated the issue's quoted ambiguous sentence.

Additional context:
The originating Zulip thread #implementers > _include=* records the same ambiguity and the filing of J#33309, and FHIR-I minutes from 2021-11-29 record approval to add the proposed clarification. Later Applied issue FHIR-50714 updated the same search-page area to include the newer resource-type search parameter concept and rewrote the later wildcard paragraph, but it still left the support-for-_include/_revinclude qualification out of that paragraph.

AutoFHIR reconciliation:
This commit updates the later wildcard paragraph in source/search.html so the wildcard includes only reference or resource type search parameters that are supported for _include or _revinclude. It preserves the later FHIR-50714 addition of resource-type search parameters and leaves the already-clarified syntax bullet unchanged.

Recommendation:
Keep this commit as-is. It completes the FHIR-33309 clarification in the current authoritative search page while preserving later search-parameter scope changes; no broader related issue needs to be decided here.
