FHIR-32752: Clarify SubscriptionTopic filter parameter definition

Issue request:
FHIR-32752 was Published/Persuasive with Modification for R5. It observed that server-local search parameter names can vary and that SearchParameter.url is the stable semantic identifier. The final resolution kept SubscriptionTopic.canFilterBy.filterParameter as a required human-readable, computation-friendly name used from Subscription.filterBy.searchParamName, added filterDefinition 0..1 uri for the canonical SearchParameter URL or other shared filter concept URI, and required modifier support to align with the referenced SearchParameter when filterDefinition points to one.

Initial application:
The issue was partially applied before this reconciliation. Commits 1e09c04ba5a8aea591fa44ca2adef226b1888aed and 365b52222b9aeb872817b317cd6e620955291d56 made filterParameter 1..1, added filterDefinition as a uri, and included the SearchParameter modifier rule; 4007af52e0ae46dcc02c846f1ad73dcebc20611f later refined Subscription.filterBy wording. However, the SubscriptionTopic filterParameter ElementDefinition still described filterParameter itself as either a canonical SearchParameter URL or topic-defined parameter, duplicating the meaning that FHIR-32752 assigned to filterDefinition.

Additional context:
SubscriptionTopic is an active current-build resource in source/fhir.ini. Later FHIR-46492 work moved canFilterBy under SubscriptionTopic.trigger, and source/fhir.ini maps the old canFilterBy path to the current trigger.canFilterBy elements, so the current trigger.canFilterBy definitions are the authoritative source to reconcile. The SubscriptionTopic narrative already says filterParameter is a context-local name and filterDefinition links it to a canonical or other complete definition. FHIR-35842 is the same change family and is already represented on the combined branch; FHIR-50618 is a later Triaged typo issue in the same narrative area but is not a final decision and does not change this source fix.

AutoFHIR reconciliation:
This commit updates the authoritative SubscriptionTopic.trigger.canFilterBy.filterParameter definition to describe a context-local filter name used by Subscription.filterBy.filterParameter, leaving the canonical URL/shared URI meaning on filterDefinition. It also updates the checked-in SubscriptionTopic SVG tooltip so the rendered diagram does not continue to show the stale canonical-URL wording.

Recommendation:
Keep this commit as-is. It completes the semantic split required by FHIR-32752 in the current R6 SubscriptionTopic source without changing unrelated examples or open editorial typo items.
