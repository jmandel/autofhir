FHIR-25622: Clarify integer64 RDF datatype support

Issue request:
FHIR-25622 was Published/Persuasive for FHIR core in R5. It asked for RDF generator and ShEx tooling support for the integer64 datatype, mapping it into the XML Schema integer datatype family and treating it like the existing integer primitive, with possible range-constraint discussion deferred.

Initial application:
No source commit explicitly tagged FHIR-25622 was found. The integer64 primitive itself had already entered the datatype source through the integer64 datatype work, and current R5/current generated ShEx and RDF ontology artifacts include integer64. Before this reconciliation, source/rdf.html still described the allowed fhir:v XSD datatype list without mentioning derived integer datatypes such as xsd:long, even though the generated integer64 ShEx and ontology use xsd:long.

Additional context:
The related FHIR-25208 audit already on the combined branch concluded that current core integer64 semantics are signed 64-bit with xs:long/JSON string representation. R5 and current generated ShEx define integer64 with fhir:v xsd:long plus the signed 64-bit min/max range, and the ontology defines the integer64 value restriction with xsd:long. Since xsd:long is an XML Schema datatype derived from xsd:integer, retaining xsd:long preserves the established 64-bit range instead of weakening validation to unbounded xsd:integer.

AutoFHIR reconciliation:
This commit updates source/rdf.html, the current RDF representation source page, so its list of possible fhir:v XSD datatypes explicitly includes integer-derived datatypes such as xsd:int, xsd:long, and xsd:positiveInteger. This aligns the narrative RDF guidance with the generated ShEx/RDF surfaces without changing the authoritative integer64 range semantics or generated artifacts.

Recommendation:
Keep this source fix. Do not change integer64 from xsd:long to bare xsd:integer unless FHIR-I explicitly decides to weaken the RDF/ShEx range constraint; future generator-specific changes should be handled in the Kindling/publisher code path if generated artifacts ever diverge.
