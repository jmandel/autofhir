FHIR-7133: Clarify ServiceRequest placer/filler codes

Issue request:
FHIR-7133 was Published with resolution Persuasive with Modification. The issue asked to differentiate DiagnosticOrder.identifier values that correspond to HL7 V2 placer and filler order numbers by adding an Identifier.type note, giving the exact identifier type codes, and coordinating the related terminology work through FHIR-8186.

Initial application:
The issue was initially applied in git commit 88d679f466 (#7133), which added DiagnosticOrder notes and spreadsheet text naming PLAC for the Placer Identifier and FILL for the Filler Identifier. FHIR-8186 then created the PLAC/FILL identifier type codes, and later terminology cleanup in 935f74cd0e moved the Identifier.type value set to use v2-0203 now that those codes were defined there.

Additional context:
DiagnosticOrder and DiagnosticRequest are now removed resources, with DiagnosticOrder explicitly recorded in source/fhir.ini as subsumed into ServiceRequest; ServiceRequest is the active current-build request resource. Later FHIR-11119 work merged DiagnosticRequest and ProcedureRequest, and subsequent source refactors carried forward a ServiceRequest.identifier comment but left it pointing to a ServiceRequest notes section that no longer contains the promised identifier discussion or exact codes. A later R6 DiagnosticReport issue, FHIR-54545, concerns whether placer/filler identifiers belong on DiagnosticReport.identifier; it is not applied/published in this run's source-edit scope and does not change that ServiceRequest is the request/order location for the PLAC/FILL guidance.

AutoFHIR reconciliation:
This commit updates the authoritative ServiceRequest StructureDefinition comment and the matching Request mapping-exception source to state the current rule directly: Identifier.type can distinguish identifiers assigned by the orderer/requester from those assigned by the producer/fulfiller, and the HL7 V2 placer/filler identifier type codes are PLAC and FILL. It removes the stale pointer to nonexistent ServiceRequest notes detail without changing cardinality, bindings, examples, or unrelated DiagnosticReport guidance.

Recommendation:
Keep this source fix as-is. It restores the exact code signpost requested by FHIR-7133 on the active successor resource and keeps the mapping-exception source synchronized; handle FHIR-54545 separately if OO applies the later DiagnosticReport-specific decision.
