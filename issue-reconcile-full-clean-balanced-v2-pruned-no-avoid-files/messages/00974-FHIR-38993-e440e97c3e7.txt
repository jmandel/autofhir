FHIR-38993: Add search-compartment to type interactions

Issue request:
FHIR-38993 was a Published/Persuasive with Modification FHIR-core issue asking for the restful-interaction CodeSystem to include the missing search-compartment code and for http://hl7.org/fhir/ValueSet/type-restful-interaction to include that code as well.

Initial application:
The initial Jira-tagged application was git commit 9246025c8cb3f9289e4d5b4af9a59cda65312d0f, which added search-compartment under the search hierarchy in source/codesystem/codesystem-restful-interaction.xml. That commit did not update source/capabilitystatement/valueset-type-restful-interaction.xml, leaving the required CapabilityStatement.rest.resource.interaction binding unable to use search-compartment.

Additional context:
CapabilityStatement is an active resource in source/fhir.ini and CapabilityStatement.rest.resource.interaction has a required binding to ValueSet/type-restful-interaction, so the value set source feeds current conformance expectations. FHIR Infrastructure minutes from 2022-10-24 record the FHIR-38993 approval vote, and the earlier FHIR-35859 Zulip discussion explains how adding compartment search to REST summary tables exposed the missing RESTful-interaction code. Later same-file history only changed wording such as operation versus interaction and did not add the missing code to the type value set.

AutoFHIR reconciliation:
This commit adds search-compartment to the narrative table and compose.include concepts in source/capabilitystatement/valueset-type-restful-interaction.xml, using the CodeSystem definition text already added for FHIR-38993.

Recommendation:
Keep this source-changing commit. It completes the applied Jira resolution in the active type-level REST interaction value set without changing unrelated system-level interaction codes or broader REST search semantics.
