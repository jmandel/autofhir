FHIR-12740: Fix datatype extension links

Issue request:
FHIR-12740 was a Published/Persuasive FHIR-core DSTU2 change request asking datatype pages to include links to pages listing extensions relevant to each datatype, analogous to resource extension links.

Initial application:
Jira comments say the request had been done, and no git commit explicitly mentioning FHIR-12740 was found. The current source already contains datatype and base-type "Extensions" navigation links, and c5a1cbe moved those links to the external FHIR Extension Pack with per-datatype anchors. A later navigation-row change regressed the datatype mappings page so most datatype "Extensions" links pointed to the primitive datatype extension section instead of the datatype-specific section.

Additional context:
The current build routes datatypes through source/fhir.ini and the edited datatype pages are active source pages. The datatype extension-list pages now live in the FHIR Extension Pack; its source uses #primitives for the primitive datatype group and title-case datatype anchors such as #Identifier and #Attachment. The Extension Pack source currently lacks a RelativeTime section even though a RelativeTime extension definition exists there, so that external page should be reviewed separately.

AutoFHIR reconciliation:
This commit updates the active datatype definitions, profiles, and mappings source so primitive and Identifier extension links use the Extension Pack anchors that exist today. It also restores each datatype mappings navigation row to link to its own extension-list anchor instead of #primitive, and restores the adjacent conversion link label to "R4 Conversions" so the extension link is unambiguous.

Recommendation:
Keep this core source fix. Separately review the FHIR Extension Pack pagecontent for RelativeTime so the existing core links to extensions-datatypes.html#RelativeTime have a matching external anchor/list.
