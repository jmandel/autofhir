FHIR-17836: Align reason-not-given value set description

Attribution note: surfaced while reviewing FHIR-9552, but direct Jira backing for this change is FHIR-17836.

Issue request:
FHIR-9552 was Published/Persuasive with Modification for DSTU2 by Pharmacy. It suggested additional SNOMED CT reasons for MedicationAdministration reason-not-given and the approved resolution changed the example ValueSet to a union of 406149000 Medication Refused, 371900001 Medication Not Administered, and 242990004 Non Administration of necessary drug or medicine, without renaming the ValueSet.

Initial application:
The issue was initially applied by git commit 055e6c67af51c6ea21726fe2c7ed0539dc1fdd4d, whose message explicitly lists 9552/9298 and which changed source/medicationadministration/valueset-reason-medication-not-given-codes.xml from the old local FHIR reason-not-given CodeSystem include to the three approved SNOMED CT hierarchy filters.

Additional context:
FHIR-9298 records the same Pharmacy vote and same three-hierarchy resolution for this ValueSet. A later Published Pharmacy decision, FHIR-17836, superseded that broad compose and changed MedicationAdministration.statusReason to only 182895007 Drug declined by patient and 242990004 Drug not available for administration; the combined branch already contains audit commit a0986d196aceecf4d131274f95bd2bbb6342d026 for FHIR-17836. MedicationAdministration is an active approved resource in source/fhir.ini, and its StructureDefinition still binds statusReason to source/medicationadministration/valueset-reason-medication-not-given-codes.xml. The current compose already has the later two SNOMED CT filters, but the ValueSet description still described the superseded three-hierarchy union.

AutoFHIR reconciliation:
This commit updates the build-scope ValueSet description so it no longer says the ValueSet includes all medication refused, medication not administered, and non-administration codes. It now describes the current FHIR-17836 compose: drug declined by patient and drug not available for administration codes from SNOMED CT. The compose itself is intentionally unchanged because re-adding the FHIR-9552/FHIR-9298 hierarchies would reverse the later published Pharmacy decision.

Recommendation:
Keep this source fix. Do not re-add 406149000 or 371900001 for FHIR-9552 unless Pharmacy explicitly reopens the later FHIR-17836 decision; if broader medication-not-given coverage is desired, handle it as a new terminology issue against the current R6 MedicationAdministration.statusReason binding.
