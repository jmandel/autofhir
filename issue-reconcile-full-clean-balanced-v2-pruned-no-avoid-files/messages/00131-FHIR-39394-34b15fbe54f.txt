FHIR-39394: Clarify Consent provision filters

Issue request:
FHIR-39394 was Published/Persuasive with Modification for FHIR-core Consent. It asked to clarify Consent.provision.code as clinical-code filtering with an example LOINC binding excluding document-scale codes, rename Consent.provision.class to Consent.provision.documentType with a preferred document-type binding, and add Consent.provision.resourceType for FHIR resource-type filtering with 0..* cardinality.

Initial application:
No source commit message explicitly mentioned FHIR-39394, but git history shows PR #2450 from HL7/Consent-Jira-39394. Commit 3d15d8f10db9fb3f2f57469a3fa986e3baebc1f0 renamed Consent.provision.class to documentType, added resourceType, kept code at 0..*, changed documentType to a preferred consent-content-class binding, added the resource-types binding for resourceType, removed the misleading .code comment, and split the LOINC value sets. Commit 064d2b030b55d6565b49bc9d153799d2f7a13cb9 later corrected the LOINC SCALE_TYP filter values to use LP32888-7 for document-scale codes.

Additional context:
Consent is an active current-build resource in source/fhir.ini, and source/fhir.ini maps the old R4 Consent.provision.class element to Consent.provision.resourceType. Later applied Consent QA/search-parameter work did not supersede the FHIR-39394 split. FHIR-41456 added a provision-code search parameter and is already represented on the combined branch. FHIR-54632 is a later Triaged question about the documentType value set, but it is unresolved and does not authorize changing this issue's approved split.

AutoFHIR reconciliation:
This commit updates source/consent/structuredefinition-Consent.xml only. It replaces the documentType short description that still advertised resource/profile values, removes profile/document-type wording from resourceType so it matches the resource-types value set, changes code to the approved clinical-code description, and removes stale binding prose that still said an "exception" applies.
