FHIR-40327: Align repeated given search examples

Issue request:
FHIR-40327 was Published/Persuasive for R5 and asked the Search page's "Searching Multiple Values (joining with AND or OR)" section to include an example of repeating the same search parameter, such as Patient?given=valueGivenA&given=valueGivenB, and to explain that this is an AND across both given-name matches.

Initial application:
The current Search page already contains the requested repeated-parameter paragraph and GET/POST examples. Git history shows that this text was introduced in commit 6941dfafeb121ffee973cdaae30102b8fd8566f0, whose subject references FHIR-39373 rather than FHIR-40327, as part of broader search guidance work. That application left the embedded Patient JSON/XML examples using valueA/valueB while the surrounding query and prose use valueGivenA/valueGivenB.

Additional context:
FHIR-39373 is a closely related Published/Persuasive-with-Modification issue about repeating search parameters in this same section; its resolution explicitly called for a given-name example and broader repeated-element guidance. FHIR-I minutes from 2023-03-06 record the 13-0-0 motion for FHIR-40327. A later Zulip implementer thread quoted this repeated-parameter text and confirmed the intended AND behavior across multiple name elements, with no conflicting community evidence found.

AutoFHIR reconciliation:
This commit keeps the existing repeated-parameter guidance intact and changes only the directly adjacent illustrative Patient JSON/XML example values from valueA/valueB to valueGivenA/valueGivenB so the example resources match the repeated given-name search and explanatory prose.

Recommendation:
Keep this commit as-is. The authoritative source/search.html page is in the current FHIR source tree, and the edit is a narrow consistency correction to the example requested by FHIR-40327 rather than a broader rewrite of search semantics.
