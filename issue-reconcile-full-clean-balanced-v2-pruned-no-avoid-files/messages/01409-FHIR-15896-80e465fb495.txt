FHIR-15896: Clarify narrative image source guidance

Issue request:
FHIR-15896 is a Published/Persuasive FHIR-core narrative issue for STU3. It requested replacing the ambiguous sentence that said essential narrative images should "always be embedded as a data: url, in an attachment or a contained resource" with wording that says they should either be embedded in XHTML using the "data" URL scheme or reference a contained Binary resource or Attachment datatype.

Initial application:
The historical GF#15896 commit 1699882a6eae0e6e28f9088a0e8ce9ca2c07801f was recorded as the application event, but inspection of its patch shows it only changed whitespace and removed final punctuation in source/narrative.html. The active current source therefore still carried the old ambiguous sentence before this reconciliation.

Additional context:
source/hierarchy.xml lists narrative.html as the active Narrative page and publish.ini includes narrative.html, so source/narrative.html feeds the current build. FHIR-12288 had already recorded implementer confusion about the same sentence. Later FHIR-54765 is a 2026 Resolved - change required issue about fullUrl references in document bundles, and FHIR-54749 remains Submitted for Attachment path expressions; those are separate later/unapplied requests and did not justify broadening this fix.

AutoFHIR reconciliation:
This commit updates only source/narrative.html to clarify the FHIR-15896 options: essential images should either be embedded in the XHTML using the data URL scheme or have their source reference a contained Binary resource or an Attachment datatype in the resource content. It also links Binary and Attachment to the local spec pages.

Recommendation:
Keep this commit as-is for FHIR-15896. Handle FHIR-54765/FHIR-54749 separately if and when their later decisions enter the current build scope.
