FHIR-33956: Include caregiver descendants in CareTeam participant roles

Issue request:
FHIR-33956 was Published with resolution Persuasive with Modification for R5. It asked to restore unpaid CareTeam participant role concepts after the broader Person hierarchy had been removed, with 429577009 Patient advocate (person) and 116154003 Patient (person) added without children, and 133932002 Caregiver (person) added with descendants.

Initial application:
The issue was partially applied by git commit 63992ae434885cd5c252c61ad1c73c890e0620d2, merged by PR #2294. That commit added all three requested SNOMED CT concepts to source/careteam/valueset-participant-role.xml, but left 133932002 as a single enumerated concept instead of adding a descendant include, and left the value set description from the earlier FHIR-20566 cleanup that mentioned only Healthcare professional and Services.

Additional context:
FHIR-20566 intentionally removed the broad is-a 125676002 Person include from this same value set, creating the narrower baseline that FHIR-33956 later amended. Patient Care and LHS minutes confirm the FHIR-33956 scope: unpaid participant role concepts should be retained, and caregiver descendants such as primary caregiver and informal caregiver should be included. CareTeam is an active resource in source/fhir.ini, and source/careteam/valueset-participant-role.xml is the active CareTeam participant-role value set source.

AutoFHIR reconciliation:
This commit completes the published decision by changing the Caregiver entry from a single concept to an is-a 133932002 include, preserving the no-children concept entries for Patient advocate and Patient and the existing Healthcare professional and Services filters. It also updates the ValueSet description so the narrative definition matches the compose.

Recommendation:
Keep this source fix. Further work is only needed if Patient Care or terminology reviewers later choose additional person-role concepts or a different SNOMED CT hierarchy expression for caregiver roles.
