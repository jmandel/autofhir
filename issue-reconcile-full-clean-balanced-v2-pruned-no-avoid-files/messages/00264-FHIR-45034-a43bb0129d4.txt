FHIR-45034: Restore ImagingSelection study link requirement

Issue request:
FHIR-45034 is an Applied/Persuasive FHIR-core ImagingSelection change request from the Imaging Integration work group. It asked how ImagingSelection.studyUid and ImagingSelection.derivedFrom relate when both are present; the final resolution changed ImagingSelection.derivedFrom to 0..1 and required studyUid, if present, to match an identifier of the referenced ImagingStudy when derivedFrom references an ImagingStudy.

Initial application:
PR 3221 / commit 3f26655a0d9c9b69dc90dba10dc5a89ed7f8c2fa applied the issue by changing ImagingSelection.derivedFrom max from * to 1 and adding the studyUid/derivedFrom matching requirement to source/imagingselection/structuredefinition-ImagingSelection.xml. The current source still had the cardinality change, but later FHIR-48101 history removed the whole studyUid requirements field and thereby dropped the FHIR-45034 matching guidance.

Additional context:
ImagingSelection is in current build scope through active source/fhir.ini entries. FHIR-48101 later replaced confusing studyUid/seriesUid required-unless prose with invariants and a narrower seriesUid requirement, so this reconciliation does not reintroduce the removed required-unless wording. FHIR-40273 remains the supporting published decision for keeping DocumentReference as an ImagingSelection.derivedFrom target, and FHIR-54814 later clarified that ImagingSelection.derivedFrom references an ImagingStudy when images were selected from it. The checked-in imagingselection.svg still shows stale generated-looking derivedFrom cardinality, but this commit intentionally changes only the authoritative StructureDefinition source.

AutoFHIR reconciliation:
Restored a focused ImagingSelection.studyUid requirements value stating that when ImagingSelection.derivedFrom references an ImagingStudy, the studyUid value, if present, must match an identifier of that ImagingStudy.

Recommendation:
Keep this source fix. It restores the seed issue's substantive consistency rule while preserving later FHIR-48101 invariants and FHIR-40273 DocumentReference support; any generated diagram refresh should be handled by the normal publishing process or a separate generated-artifact decision.
