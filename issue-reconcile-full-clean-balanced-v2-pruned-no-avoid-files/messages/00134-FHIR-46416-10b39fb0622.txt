FHIR-46416: Remove packageSize invariant

Issue request:
FHIR-46416 was Applied/Persuasive with Modification for R6 Medication package-size support. It replaced Medication.totalVolume with Medication.packageSize, containing numberOfItems and amountPerItem for cases where the medication code does not specify the package size.

Initial application:
The issue was first applied by e39a9c04e3, which changed the active Medication StructureDefinition from totalVolume to packageSize and added the two child elements. A later issue-tagged commit, 3b18dbf82e, added med-1 requiring either numberOfItems or amountPerItem. The active fhir.ini resource entries show Medication is in the current build, and the R5-to-R6 mapping records the new packageSize elements and removed totalVolume.

Additional context:
FHIR-45877 is a duplicate that asked for medication.packSize and was folded into this issue. FHIR-46902 records that totalVolume wording concerns were overtaken by the packageSize change. After the invariant was added, the 2025-11-03 Pharmacy meeting minutes and the final Jira comment explicitly agreed that the invariant was unnecessary because the two children are the only normal contents, and extension-only cases should not be blocked.

AutoFHIR reconciliation:
This commit removes the med-1 constraint from source/medication/structuredefinition-Medication.xml and leaves the packageSize backbone and its child definitions intact. The edited file is the authoritative active source for the built Medication resource; no generated diagram-only artifact was changed.

Recommendation:
Keep this commit as-is. It preserves the applied packageSize structure while aligning the current source with the later WG decision that the invariant should not constrain extension-based or otherwise intentionally sparse packageSize representations.
