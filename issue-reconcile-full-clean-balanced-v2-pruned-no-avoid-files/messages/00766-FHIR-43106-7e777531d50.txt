FHIR-43106: Align Bundle fullUrl search exceptions

Issue request:
FHIR-43106 was Applied with a Persuasive with Modification resolution for R6. It asked to correct the Bundle.entry.fullUrl rule because the FHIR-31354 application inverted the intended search/history exception; fullUrl should be required unless the Bundle is a batch or transaction request or response and the entry is a create, a non-single-resource operation, or a search/history invocation or response/result.

Initial application:
FHIR-31354 was initially applied in a026c2f242, which changed Bundle.entry.fullUrl to say fullUrl was absent "except when" create/operation/search-history cases applied. The FHIR-43106 wording was later applied in c3a11dc9db, alongside FHIR-43101, to the Bundle.entry.fullUrl ElementDefinition, changing that definition to the current "unless the Bundle is a batch or transaction request or response" form.

Additional context:
The Bundle resource is active in source/fhir.ini, and source/bundle/structuredefinition-Bundle.xml and source/bundle/bundle-notes.xml feed the current Bundle build. The ElementDefinition already had the applied FHIR-43106 wording, but the nearby Bundle narrative still described only the older request.method = POST omission case and bdl-15 still carried the old POST-specific human/expression logic. Zulip and Confluence searches found the original FHIR-31354 review thread and the FHIR-I 2023-11-13 vote for FHIR-43106, with no later conflicting FHIR-43106-specific Zulip evidence.

AutoFHIR reconciliation:
Updated the Bundle narrative to point to the Bundle.entry.fullUrl exceptions instead of restating the stale POST-only exception. Updated bdl-15 so it enforces fullUrl for non-batch/non-transaction Bundles and no longer treats request.method = POST as a standalone exception outside the FHIR-43106 batch/transaction scope. Removed the bdl-15 condition from Bundle.entry.request.method because request.method is no longer part of that invariant.

Recommendation:
Keep this commit. It completes the applied FHIR-43106 correction across the authoritative Bundle definition, invariant, and narrative sources without editing generated-looking bundle.svg output. If a future work group wants machine enforcement of the more granular batch/transaction entry exceptions, that should be a separate FHIRPath design decision because the current prose exceptions distinguish create, operations, search, and history semantics that are not fully encoded in bdl-15.
