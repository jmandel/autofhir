FHIR-23764: Map Encounter diagnosis condition to DG1-3

Issue request:
FHIR-23764 is Published/Persuasive for FHIR-core Encounter mappings. It asked Patient Administration to update the HL7 v2 mapping table so DG1-3 (Diagnosis Code) maps to Encounter.diagnosis.condition, DG1-6 (Diagnosis Type) maps to Encounter.diagnosis.use, and DG1-15 (Diagnosis Priority) maps to Encounter.diagnosis.rank.

Initial application:
The Jira-tagged source commit cce27af6a4 added the DG1-6 mapping to Encounter.diagnosis.use and the then-valid DG1-15 mapping to Encounter.diagnosis.rank, but it left Encounter.diagnosis.condition with an older generic Encounter.indication/Condition-or-Procedure v2 mapping instead of the requested DG1-3 mapping.

Additional context:
Encounter is an active current resource in source/fhir.ini, so source/encounter/structuredefinition-Encounter.xml is in build scope. Later Encounter/Account decisions changed the current model: FHIR-16148 made Encounter.diagnosis.condition a CodeableReference to Condition and directed billing diagnoses with ranking to Account, and FHIR-19285 added Account.diagnosis.sequence for ranked billing diagnoses. The current fhir.ini migration table records Encounter.diagnosis.rank as moved to Account.diagnosis.sequence, so restoring Encounter.diagnosis.rank or its v2 mapping would be wrong for the current build.

AutoFHIR reconciliation:
This commit replaces the stale v2 mapping on Encounter.diagnosis.condition with DG1-3 (Diagnosis Code). The existing DG1-6 mapping on Encounter.diagnosis.use is retained, and no DG1-15 mapping is restored on Encounter because that element no longer exists in the current source.

Recommendation:
Keep this commit as-is for FHIR-23764. It completes the remaining current Encounter mapping correction while respecting the later PA decisions that moved ranked billing diagnosis information to Account; broader Account v2 mapping coverage, if desired, should be handled as a separate Account mapping decision.
