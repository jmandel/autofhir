FHIR-42712: Limit alternative expression comments to Expressions

Issue request:
FHIR-42712 was Applied with resolution Not Persuasive with Modification. Instead of changing Measure.group.population.criteria to 0..*, CQI decided to point Measure expression-valued elements at the existing cqf-alternativeExpression extension for alternate equivalent formulations.

Initial application:
The issue was applied in git commit 8bae5aee21a8aa28c28e7bdcca4f7a5f42974fdd, referenced from the Jira comment via HL7/fhir#3423. That commit added cqf-alternativeExpression guidance to the intended Expression-valued Measure criteria elements, but it also appended the same sentence to Measure.group.stratifier.groupDefinition and Measure.group.stratifier.component.groupDefinition, which are Reference(Group) elements rather than Expression elements.

Additional context:
Measure is an active current-build resource in source/fhir.ini. The cqf-alternativeExpression extension now lives in the FHIR Extension Pack and has context Expression, so the core Measure comments should not imply that it can be used directly on Reference(Group) groupDefinition elements. FHIR-29815 is the earlier published core decision that introduced cqf-alternativeExpression as the alternative to changing criteria cardinalities. FHIR-42907 and FHIR-42711 are external IG follow-ups/background and are not current core source edits for this worker.

AutoFHIR reconciliation:
Removed the cqf-alternativeExpression sentence from the two Measure groupDefinition comments whose elements are Reference(Group). Left the existing guidance in place on the Expression-valued Measure criteria elements, including Measure.group.population.criteria, Measure.group.stratifier.criteria, Measure.group.stratifier.component.criteria, and Measure.supplementalData.criteria.

Recommendation:
Keep this source correction. It preserves the applied no-cardinality-change resolution while preventing implementers from reading an Expression-only extension as applicable to Reference(Group) elements. Any profile-specific allowance in Quality Measure or SANER should be handled in those IG repositories, not by broader core Measure changes.
