FHIR-40504: Fix ConceptMap example link

Attribution note: surfaced while reviewing FHIR-16764, but direct Jira backing for this change is FHIR-40504.

Issue request:
FHIR-16764 was Published/Persuasive for the STU3 ConceptMap ballot. It objected that the ConceptMap target.product wording was abstract enough to require an example, and the approved resolution was to add an example in the dependent mapping section using an existing ConceptMap example resource.

Initial application:
Jira records application in svn revision 14770. In git, f82e3c73be (svn @14770) cites GF#16764 with other ConceptMap clarifications, while the companion FHIR-16761 commit 729b697c1b (svn @14763) added the original mapping dependencies section and example that also explained the product converse. Later ConceptMap source revisions kept and expanded that section.

Additional context:
ConceptMap is active in source/fhir.ini, so its StructureDefinition, notes, and example list are current-build source. The current target.dependsOn and target.product notes already include an explanatory table plus real links to the Specimen Type Mapping and Message ADT A04 to Bundle examples. After the R5/R6 ConceptMap refactors, the StructureDefinition's ConceptMap.additionalAttribute comment also pointed to the specimen example, but the Markdown link was malformed and rendered as literal bracketed text on the definitions page instead of an example link.

AutoFHIR reconciliation:
Fixed the malformed Markdown link in source/conceptmap/structuredefinition-ConceptMap.xml so the current ConceptMap.additionalAttribute definition links to the specimen ConceptMap example. No new example prose was added because the active dependent-mapping section already conveys the approved dependency/product example guidance.

Recommendation:
Keep this source fix. It preserves the existing ConceptMap model and example section while repairing the current broken example pointer; no further core-source change is needed for FHIR-16764.
