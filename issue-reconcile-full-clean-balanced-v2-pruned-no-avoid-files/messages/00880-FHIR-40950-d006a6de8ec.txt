FHIR-40950: Reconcile Specimen processing duration

Issue request:
FHIR-40950 was an Applied/Persuasive FHIR-core OO change request for R6 asking to add duration to Specimen.processing.time and remove the redundant specimen-processingTime extension.

Initial application:
The core application commit 2e47a771ff78f16314747f5451f30a1f80317784 added Duration as a type for Specimen.processing.time[x], but it left the element short/definition describing only date/time/period semantics and left the processingTime row in source/specimen/specimen-extensions-spreadsheet.xml. Jira later recorded that the change was applied to the build, but the redundant core extension source remained.

Additional context:
Specimen is an active resource in source/fhir.ini, and source/specimen/structuredefinition-Specimen.xml plus the resource extension spreadsheet are current source inputs. FHIR-44932 requested the same duration choice as part of FHIR-44361 and is already represented on the combined branch, so this commit does not duplicate that issue. The FHIR Extension Pack still carries specimen-processingTime for pre-R6/version-specific use, with later FHIR-52827 context restoring it to active/version-tagged status until R6 is published; that does not require the current core Specimen resource to keep a redundant extension row. The historical OID entry is left in place because parallel extension-pack-only definitions still retain core OID registry entries.

AutoFHIR reconciliation:
Updated the authoritative Specimen.processing.time[x] short and definition so the current R6 element explicitly covers time, period, and duration, and cleared the processingTime row from the active Specimen extension spreadsheet so core no longer defines the redundant specimen-processingTime extension. Generated-looking diagram output was not edited.

Recommendation:
Keep this source fix. The current core build should expose Duration directly on Specimen.processing.time[x] and should not define a redundant core specimen-processingTime extension; the Extension Pack remains the right home for historical/pre-R6 handling.
