FHIR-35859: Clarify POST compartment search examples

Issue request:
FHIR-35859 was a Published/Persuasive FHIR-core issue asking for POST-based search to be defined consistently with GET search. The approved resolution required server-wide POST search at [base]/_search and compartment POST search at [base]/[compartment]/[id]/_search, with those interactions included in the HTTP summary tables and in search.html documentation and examples.

Initial application:
The Jira-tagged application was git commit 7415a1eb0824ba59d977db335205d71eed004312, which updated source/http.html with server-root, typed, compartment, and compartment-plus-type POST search forms and added search-system/search-compartment rows to the REST summary tables. It also updated source/search.html with the server-root POST form and a typed compartment POST example, but the Search page still did not show the all-resource compartment POST form [base]/[compartment]/[id]/_search requested by the resolution.

Additional context:
Current source/http.html already contains the requested POST [base]/_search, POST [base]/[compartment-type]/[compartment-id]/_search, and POST [base]/[compartment-type]/[compartment-id]/[resource-type]/_search examples, plus summary table rows for search-system and search-compartment. The Search page is active narrative source for the current build and is linked from the HTTP page as the search-context reference, so leaving the all-resource compartment POST form out of source/search.html creates a real documentation inconsistency. A 2022 Zulip thread shows the FHIR-35859 application raised the related search-compartment RESTful-interaction terminology question; the later FHIR-38993 reconciliation already handled that terminology issue separately on the combined branch.

AutoFHIR reconciliation:
This commit updates source/search.html only. It changes the compartment search context wording from "perhaps with" to "with or without" a resource type and shows both the all-resource compartment form and the typed compartment form for GET and POST, including POST [base]/[compartment]/[id]/_search next to POST [base]/[compartment]/[id]/[type]/_search.

Recommendation:
Keep this source-changing commit. It completes the narrow search.html documentation/example portion of the published FHIR-35859 resolution while preserving the already-correct HTTP page summary tables and avoiding a duplicate decision for the related FHIR-38993 terminology work.
