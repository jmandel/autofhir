FHIR-34542: Restore Device.status record short

Issue request:
FHIR-34542 was a Published OO change request, resolved Persuasive with Modification for R5, asking that Device.status stop using the literal status-code list as the attribute short and instead use "The status of the Device Record." The same resolution also required the device-status ValueSet definition to describe the Device record status rather than device availability.

Initial application:
The issue was partly applied in commit 0cd35c3c18, which changed Device.status to the requested record-status short and updated the binding wording while also applying FHIR-32557 Device status/availability work. Commit 7e1bcb46e5 immediately reverted the Device.status short back to the status-code list, and commit 428be56a05 was the Jira-linked PR commit but only made a whitespace adjustment in the same area. The current source therefore retained the corrected CodeSystem/ValueSet descriptions but not the requested attribute short.

Additional context:
Device is an active current-build resource in source/fhir.ini. FHIR-32557 explains the related separation between Device.status as record status and Device.availabilityStatus as device availability. Later Applied issue FHIR-53243 re-added the unknown code to the Device status CodeSystem/ValueSet for R6, but it did not supersede FHIR-34542's direction that the Device.status short should be descriptive rather than a literal value list.

AutoFHIR reconciliation:
This commit restores the Device.status short in source/device/structuredefinition-Device.xml to "The status of the Device record." It also updates the active Device status SearchParameter description and Participant mapping-exception source copy that had inherited the stale status-value list, while preserving the later FHIR-53243 unknown code in source/device/codesystem-device-status.xml and source/device/valueset-device-status.xml.

Recommendation:
Keep this source fix. It implements the Published FHIR-34542 decision without reversing the later FHIR-53243 value-set change. No further core-source change is recommended for this issue unless the work group later changes the intended wording of Device.status itself.
