FHIR-47904: Link Device in DeviceDefinition scope

Issue request:
FHIR-47904 was an Applied FHIR-core DeviceDefinition R6 ballot change request with a Persuasive with Modification resolution. The ballot comment said the DeviceDefinition Scope and Usage section confusingly began by explaining Device rather than DeviceDefinition. The approved direction was to rework the Scope and Usage flow in light of FHIR-47905, with DEV/Jira follow-up text starting from DeviceDefinition and linking to Device when contrasting the actual instance resource.

Initial application:
The first source application appears in commit 3cf635fa2b606d038462a683a53338e39b3f30e3, a March 31, 2025 multi-issue Device text update that listed FHIR-47904 and FHIR-47905 and moved the detailed category content into DeviceDefinition, but still left the paragraph starting with general Device text. Commit a1e510e9cde9d0054e9e8743f91a30f13dc77180, merged by PR #3667 as 57b4355f3952b8294374881370fd3a04977e5d2d, applied the later FHIR-47904 replacement wording so Scope and Usage starts with DeviceDefinition and then contrasts Device. That application omitted the requested Device hyperlink.

Additional context:
FHIR-47905 is the same change family and explains why the device type/category material now lives under DeviceDefinition; it already has a no-change reconciliation audit on the combined branch. Current source/fhir.ini lists DeviceDefinition as an active resource and OO-owned artifact, so source/devicedefinition/devicedefinition-introduction.xml is current build source. OO/DEV Confluence minutes confirm FHIR-47904 was discussed with FHIR-47905 and voted Persuasive with Modification. Targeted Zulip searches found no conflicting community discussion.

AutoFHIR reconciliation:
This commit updates the first Device mention in source/devicedefinition/devicedefinition-introduction.xml from plain text to a link to device.html. The rest of the applied wording is already correct, so no broader Scope and Usage rewrite is needed.

Recommendation:
Keep this source fix as-is. It completes the narrow FHIR-47904 application without disturbing the already-applied FHIR-47905 category relocation or later DeviceDefinition narrative work.
