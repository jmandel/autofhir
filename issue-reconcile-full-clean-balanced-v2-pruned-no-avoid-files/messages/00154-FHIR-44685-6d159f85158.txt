FHIR-44685: Remove LegacyNamePart from name part types

Issue request:
FHIR-44685 is Applied with a Persuasive with Modification resolution. It asked to remove FullName from http://hl7.org/fhir/medicinal-product-name-part-type because the full medicinal product name belongs in MedicinalProductDefinition.name.productName, and the final resolution also required removing LegacyNamePart because neither code is an actual name part type.

Initial application:
Commit 467870db39278e10611017291c3e495e320706d2 applied the Jira key by removing the FullName concept from source/medicinalproductdefinition/codesystem-medicinal-product-name-part-type.xml, but LegacyNamePart remained in the same active CodeSystem.

Additional context:
source/fhir.ini has medicinalproductdefinition as an active resource, and MedicinalProductDefinition.name.part.type binds to the medicinal-product-name-part-type ValueSet that includes the complete CodeSystem. The BRR 2024-10-15 minutes record the 16-0-0 vote for FHIR-44685, and the originating Zulip thread supports the rationale that full-name-like entries should not be used as name part types.

AutoFHIR reconciliation:
Removed the remaining LegacyNamePart concept from source/medicinalproductdefinition/codesystem-medicinal-product-name-part-type.xml. FullName was already absent, and the ValueSet continues to include the complete CodeSystem so the binding surface follows the corrected source.

Recommendation:
Keep this commit as-is. It completes the already-applied FHIR-44685 terminology change in active core source and does not require separate changes to MedicinalProductDefinition or the ValueSet include.
