FHIR-41195: Correct QuestionnaireResponse quantity path

Issue request:
FHIR-41195 is Applied/Persuasive with Modification. It asked to finish the Questionnaire SimpleQuantity correction by changing the item-type quantity description away from the impossible valueSimpleQuantity element name and by constraining Questionnaire.item.initial.value[x] and Questionnaire.item.enableWhen.answer[x] quantity answers to SimpleQuantity.

Initial application:
The Jira comment cites git master 8e89009a73, which updated source/questionnaire/codesystem-item-type.xml and changed Questionnaire.item.enableWhen.answer[x] and Questionnaire.item.initial.value[x] from Quantity to SimpleQuantity in source/questionnaire/structuredefinition-Questionnaire.xml. The earlier FHIR-37468 commit 28dd25d341 had already made QuestionnaireResponse.item.answer.value[x] SimpleQuantity and changed the original item-type text to mention valueSimpleQuantity.

Additional context:
Questionnaire and QuestionnaireResponse are active resources in source/fhir.ini, so their source folders and search parameter bundles feed the current build. Later Applied issue FHIR-41549 added QuestionnaireResponse answer search parameters after FHIR-41195, including an answer-quantity path extension that used QuestionnaireResponse.item.answer.valueSimpleQuantity. That element name is the exact representation FHIR-41195 said should not appear; the current StructureDefinition type remains SimpleQuantity while the choice element path is valueQuantity. FHIR-41549 is already represented on the combined branch by a separate reconciliation commit, so this commit does not re-decide it.

AutoFHIR reconciliation:
This commit updates the authoritative QuestionnaireResponse answer-quantity SearchParameter path from QuestionnaireResponse.item.answer.valueSimpleQuantity to QuestionnaireResponse.item.answer.valueQuantity, preserving the FHIRPath expression over Quantity because SimpleQuantity is the constrained quantity type rather than a separate choice element name. No generated diagram or history files were edited.

Recommendation:
Keep this source fix. It completes the current-spec representation intended by FHIR-41195: implementers see quantity answers as valueQuantity elements whose type is constrained to SimpleQuantity, and the current build no longer exposes the impossible valueSimpleQuantity path.
