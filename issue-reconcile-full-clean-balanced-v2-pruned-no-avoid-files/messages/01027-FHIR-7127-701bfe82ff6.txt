FHIR-7127: Update Procedure reason note

Issue request:
FHIR-7127 was a Published Patient Care change request resolved as Persuasive with Modification. It asked to simplify Procedure by removing Procedure.relatedItem, renaming indication to reason[x] with CodeableConcept|Reference(Condition), and representing caused-by relationships as an extension while excluding MedicationDispense, CarePlan, and Condition from that old relatedItem space.

Initial application:
The visible Jira-tagged source application was git commit dad2eb90486c (#7511 - individual, 7127 - reason[x]), which changed Procedure.indication to Procedure.reason[x] in the old Procedure spreadsheet and examples. That same application introduced Procedure narrative notes, but the notes still described inferring "indication" even though the element name had changed.

Additional context:
Procedure is an active current-build resource in source/fhir.ini. Current Procedure source has Procedure.reason as a CodeableReference that includes Condition and has no Procedure.relatedItem element; this preserves the FHIR-7127 indication/reason direction after later datatype refactoring. The caused-by extension no longer belongs in core after extensions were moved out of the R5 source, and the Extension Pack contains http://hl7.org/fhir/StructureDefinition/procedure-causedBy with Procedure context and a Reference value. FHIR-8261 is the related CarePlan/request decision explicitly anticipated by the FHIR-7127 resolution.

AutoFHIR reconciliation:
Updated source/procedure/procedure-notes.xml so the Procedure properties note refers to inferring "reason" rather than the obsolete "indication" property. No structural Procedure or extension source change was needed because Procedure.relatedItem is absent and procedure-causedBy is maintained in the Extension Pack.

Recommendation:
Keep this commit as-is. It removes the only discovered current-core stale wording tied to FHIR-7127 while leaving later Procedure.reason and Extension Pack ownership decisions intact.
