FHIR-5471: Show multiple requests in GHP example

Issue request:
FHIR-5471 was a Published/Persuasive OO ballot comment for FHIR-core DiagnosticReport. The reporter asked how requests, results, and specimens relate when they appear at the same level, and the final resolution was to extend the DiagnosticReport examples so at least one shows more than one request, specifically diagnosticreport-example-ghp.

Initial application:
The issue appears to have been pre-applied by git commit be15b4bd48b0f4a6958edb6e43fd73a33c47d55a, which added the GHP DiagnosticReport example with multiple specimens and panels. Current history shows that example was later migrated into a Bundle and kept current through many DiagnosticReport example refactors, but before this reconciliation the current GHP example had no DiagnosticReport.basedOn references and no bundled ServiceRequest resources, so the multiple-request part of the approved request was still not represented.

Additional context:
DiagnosticReport is an active resource in source/fhir.ini, and source/diagnosticreport/list-DiagnosticReport-examples.xml actively lists diagnosticreport-example-ghp. The current DiagnosticReport.basedOn definition is 0..* and targets ServiceRequest among other request resources, while ServiceRequest.requisition describes the current way to link multiple independent requests ordered together. A 2020 Zulip thread about the GHP example also points to ServiceRequest as the right order-level structure for preserving panel grouping. No Confluence reference for FHIR-5471 was found.

AutoFHIR reconciliation:
This commit adds three basedOn references from the GHP DiagnosticReport to separate ServiceRequest resources for the chemistry panel, CBC, and urinalysis entries in the same example Bundle. Each ServiceRequest has its own placer identifier and shares a common requisition, showing multiple requested panels on the same report while preserving the existing specimen and result structure. The DiagnosticReport examples list description now states that the GHP example covers multiple specimens, requests, and panels.

Recommendation:
Keep this source fix. It completes the published FHIR-5471 example request using current DiagnosticReport.basedOn and ServiceRequest.requisition modeling without changing unrelated DiagnosticReport semantics.
