FHIR-26989: Allow missing manufactured dose form

Issue request:
FHIR-26989 is Published/Persuasive for R5 and asked BR&R to make AdministrableProductDefinition.administrableDoseForm optional because some product records have only the dispensed form while still needing licensed routes. The Jira comment on the same issue explicitly extended the same rationale to ManufacturedItemDefinition.manufacturedDoseForm, saying it should not be mandatory when only a unit of measure is needed and the form is known at product level.

Initial application:
No prior git commit mentioning FHIR-26989 was found in the AdministrableProductDefinition or ManufacturedItemDefinition source history. The current active AdministrableProductDefinition source already had administrableDoseForm as 0..1, but the active ManufacturedItemDefinition StructureDefinition still had manufacturedDoseForm as 1..1, leaving the comment-scoped part of the Published issue unapplied.

Additional context:
Both ManufacturedItemDefinition and AdministrableProductDefinition are active resources in source/fhir.ini and owned by BR&R in the current build. Jira searches for administrableDoseForm/manufacturedDoseForm neighbors found no later final decision reversing the optional cardinality; the older FHIR-23920 issue is background about mandatory manufactured item details but was resolved through a simpler Ingredient link rather than a base cardinality rule. Zulip and Confluence searches for FHIR-26989 and the relevant dose-form terms found no community record that changes the Jira/source conclusion.

AutoFHIR reconciliation:
Changed source/manufactureditemdefinition/structuredefinition-ManufacturedItemDefinition.xml so ManufacturedItemDefinition.manufacturedDoseForm has min 0 instead of min 1. This matches the Published FHIR-26989 decision, aligns ManufacturedItemDefinition with the already-optional administrableDoseForm, and avoids changing generated diagrams or adding redundant narrative because no current source prose still says the element is mandatory.

Recommendation:
Keep this source fix as-is and let the normal FHIR publisher regenerate derived artifacts. No separate related issue commit is recommended from this investigation because the other discovered issues were background, profile/value-set/text changes, unresolved, or no-change decisions rather than the missed base cardinality change.
