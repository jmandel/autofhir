FHIR-25290: Remove stale CareTeam patient-specific wording

Issue request:
FHIR-25290 was a Published/Persuasive with Modification Patient Care issue for the CareTeam Boundaries and Relationships section. It asked to remove or clarify text saying CareTeam was specific to a particular Patient because the Scope and Usage section already allows a CareTeam for an event before a subject is identified.

Initial application:
The Jira comment linked HL7/fhir pull request 776 and commit 5a16cc2e3c5b3246e8bae97a2021cebee781354a, which updated source/careteam/careteam-introduction.xml by removing the patient-specific CareTeam sentence, removing the patient-independent Group phrasing, and changing actors to participants. The current CareTeam page still has that applied wording. The same rejected wording, however, remained in the active Group resource's CareTeam boundary bullet.

Additional context:
source/fhir.ini lists careteam=CareTeam and group=Group as active resources, so both introduction files feed the current build. FHIR-46553 later clarified the CareTeam page wording to say "the Group resource" but preserved the FHIR-25290 semantics. A 2019 Zulip thread shows the issue origin: Lloyd McKenzie confirmed the patient-specific CareTeam text was wrong and asked for the change request that became FHIR-25290. A Confluence reference places FHIR-25290 on the Patient Care 2019-12-12 call agenda/minutes, and no later decision found in the checked source history reinstates the patient-specific CareTeam rule.

AutoFHIR reconciliation:
This commit updates source/group/group-introduction.xml so the active Group page no longer repeats the stale CareTeam-specific-to-Patient sentence. The Group page now mirrors the CareTeam boundary wording by describing Group as an undifferentiated target set and CareTeam participants as the individual members or organized group of individuals. No source change was needed in source/careteam/careteam-introduction.xml because it already contains the requested FHIR-25290 wording.

Recommendation:
Keep this fix. It removes a stale parallel contradiction from active current-build source while preserving later CareTeam and Group boundary clarifications.
