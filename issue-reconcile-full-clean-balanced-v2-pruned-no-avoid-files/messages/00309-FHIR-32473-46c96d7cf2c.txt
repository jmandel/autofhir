FHIR-32473: Align AuditEvent DICOM query guidance

Issue request:
FHIR-32473 was a Published Security WG change request for AuditEvent, resolved Persuasive with Modification for R5. It asked to remove the invariant prohibiting both entity name and query, and instead add soft guidance that DICOM AuditMessage compatibility avoids populating both.

Initial application:
Git commit b4165b6d58 removed the sev-1 invariant and the name/query conditions from source/auditevent/structuredefinition-AuditEvent.xml, and added a DICOM compatibility note to AuditEvent.entity.query. The initial application did not leave the invariant in current source.

Additional context:
The immediately related Published R5 issue FHIR-32472 removed AuditEvent.agent.name and AuditEvent.entity.name in commit 8a350024ed because their content moved to Reference.display. Current source/fhir.ini actively includes AuditEvent, and current AuditEvent.entity.query still referred to the removed .name element even though the current name-like location is AuditEvent.entity.what.display / DICOM ParticipantObjectName.

AutoFHIR reconciliation:
Updated the active AuditEvent StructureDefinition source so the DICOM compatibility note appears on the current name-equivalent element, AuditEvent.entity.what, and so AuditEvent.entity.query no longer points readers at the removed .name element. The invariant remains removed.

Recommendation:
Keep this commit as-is. It preserves the WG's no-invariant decision while making the DICOM compatibility guidance accurate for the current AuditEvent structure; no broader DICOM mapping review was found necessary for this issue.
