FHIR-7903 + FHIR-4872: Align Encounter communication boundary

Attribution note: surfaced while reviewing FHIR-7903, but direct Jira backing for this change is FHIR-7903 + FHIR-4872.

Issue request:
FHIR-7903 was a Published Patient Care change request for FHIR-core Communication. It asked to clarify the boundary between a phone Encounter and a phone Communication. The final Persuasive with Modification resolution required Boundaries and Relationships text explaining that Communication records transfer of information, which may or may not occur as part of an Encounter, while Encounter is the coming together, in person or virtually, of a Patient with a Practitioner; Communication does not represent call duration.

Initial application:
The seed was initially applied in git commit cb0f45f8046d76835cfdb0cdb337b059ac8d9762, which added the requested "Communication and Encounter" subsection to source/communication/communication-introduction.xml. That wording remains in the current active Communication source, with only the later editorial "may" to "might" change from FHIR-13564. The same 2015 issue family also included FHIR-4872/FHIR-7886 phone-call guidance.

Additional context:
source/fhir.ini lists both communication=Communication and encounter=Encounter under active [resources], so both narrative files feed the current build. While the Communication page already carried the seed decision, the active Encounter Boundaries and Relationships page still said Communication resources are used for a simultaneous practitioner/patient interaction, a sentence introduced for FHIR-4872 even though that issue's Published resolution said practitioner/patient direct simultaneous interactions are Encounters and Communication applies where there is no such simultaneous interaction. FHIR-7886, explicitly referenced from FHIR-7903, added the matching Communication-page phone-call note. Later Communication scope work such as FHIR-13389 did not reverse this Encounter boundary.

AutoFHIR reconciliation:
This commit updates source/encounter/encounter-introduction.xml so the Encounter page now states that direct practitioner/patient interactions, including virtual phone calls, are Encounters, and links to Communication for cases with no practitioner/patient simultaneous interaction such as a phone message or correspondence transmission. The Communication page was left unchanged because it already contains the seed resolution.

Recommendation:
Keep this source fix. It removes a build-scope contradiction between Encounter and Communication using the final Published boundary decisions, without adding redundant prose to the already-correct Communication page.
