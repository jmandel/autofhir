FHIR-15659: Update stale Provenance choice references

Issue request:
FHIR-15659 was a Published/Persuasive Security change request asking to remove redundant Provenance identifier/reference choice elements such as Provenance.entity.what[x], Provenance.agent.who[x], and Provenance.agent.onBehalfOf[x] after logical references were introduced through Reference.identifier.

Initial application:
The substantive Provenance structure was applied by git commit 6c0a0563b3ac6a188b713f2f1a04ff26229100cf, which changed the Provenance agent and entity elements from Identifier|Reference choices to plain Reference elements and removed the separate entity identifier search parameter. Current source/provenance/structuredefinition-Provenance.xml already has Provenance.agent.who, Provenance.agent.onBehalfOf, and Provenance.entity.what as Reference elements without [x] choice names.

Additional context:
source/fhir.ini shows Meta is an active type, the Resource page is the active type page for Resource and Meta, and Provenance is an active resource, so the stale source/resource and source/datatypes references feed the current build. FHIR-13694 established the Reference.identifier logical-reference behavior that made the old Provenance choices redundant. FHIR-49893 later corrected adjacent Provenance.entity.what wording from whatIdentity to what.identifier and supports keeping the existing Reference.identifier guidance rather than reintroducing a choice element.

AutoFHIR reconciliation:
Updated active source prose in source/resource/resource-notes.xml and source/datatypes/meta.xml so links and text refer to current Provenance.entity.what and Provenance.agent.who element names instead of obsolete Provenance.entity.what[x] and Provenance.agent.who[x] choice names.

Recommendation:
Keep this source fix. It preserves the already-applied Provenance model while removing stale active-source names and a stale generated-definition anchor that could mislead readers into looking for removed choice elements.
