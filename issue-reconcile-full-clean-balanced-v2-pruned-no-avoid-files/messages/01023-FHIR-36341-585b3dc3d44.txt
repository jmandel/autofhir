FHIR-36341: Use OBX-6 in Quantity V2 mappings

Issue request:
FHIR-36341 was a Published/Persuasive OO change request for R5 asking that the Observation V2 mapping table use a hyphen between a v2 segment and field number and reserve dot notation for components. The reported examples included OBX.21, OBR.22, MSH.7, OBX.15, OBX.2, OBX.5, OBX.6, NTE.3, and OBX.7.

Initial application:
The issue was applied in commit 534cae66862aa506b8910ccfdfc561a781efc16f and merged via HL7/fhir#2182, which corrected the direct Observation StructureDefinition V2 map values from dot to hyphen notation. Current source still contained the same reported OBX.6 separator error in the active Quantity datatype V2 mapping cells, which are part of the current build's datatype source and describe the OBX-6 quantity unit/code mapping used by Observation quantity values.

Additional context:
The linked Zulip discussion confirms the general rule: hyphen separates v2 segments from field numbers and dot separates datatype components. OO Confluence minutes show FHIR-36341 was included in and accepted with the April 2022 OO block vote. FHIR-36340 is the same separator-correction family for ServiceRequest and is reconciled separately because it concerns a different artifact.

AutoFHIR reconciliation:
Changed the three active Quantity datatype V2 mapping cells from `(see OBX.6 etc.) / CQ.2` to `(see OBX-6 etc.) / CQ.2`, preserving the correct CQ.2 component notation and leaving historical release snapshots and unrelated resource mappings untouched.

Recommendation:
Keep this source fix. It completes the remaining active-source separator correction tied to FHIR-36341 without broadening the issue to unrelated resources.
