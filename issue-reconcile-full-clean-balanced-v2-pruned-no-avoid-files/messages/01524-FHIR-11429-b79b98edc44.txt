FHIR-11429: Use pick Task wording in workflow patterns

Issue request:
FHIR-11429 was a Published/Persuasive FHIR-core workflow issue asking section 12.1.2.9 to use "PUT Pick Task" rather than "PUT Claim Task" because selecting work from a queue is commonly called picking and avoids confusion with the Claim resource.

Initial application:
Jira comments record application in svn @10162. In git history this is commit 83f1205cc1f012816734622c56ee12d93a24212d, a broad workflow update whose message includes #11429. Later workflow refactoring in 50f4d4fa63 split the workflow page into current workflow-management.html and retained active diagrams, but the current source still carried the stale "claim" wording and "PUT Claim Task" labels.

Additional context:
source/workflow-management.html is in the current build through publish.ini and source/hierarchy.xml, and its Option F and Option H images are active assets referenced by the page and listed in publish.ini. The draw.io XML files are the maintained diagram sources for those PNG assets. Searches of Jira, Zulip, and Confluence found no later decision reversing FHIR-11429; the broader Task status "claim" language comes from later Task-resource state-machine work and was left outside this workflow-page fix.

AutoFHIR reconciliation:
Changed the Workflow Management Pattern text so open Tasks may be "picked" rather than "claimed", and updated the active Option F and Option H diagram sources and PNG assets from "PUT Claim Task" to "PUT Pick Task".

Recommendation:
Keep this source-changing commit as-is. It applies the published clarification to the current workflow page and active diagrams without changing unrelated Task-resource status terminology.
