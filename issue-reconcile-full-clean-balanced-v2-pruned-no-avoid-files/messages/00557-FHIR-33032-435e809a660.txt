FHIR-33032: Add id type to ConceptMap dependencies

Issue request:
FHIR-33032 was Published/Persuasive for R5 and requested adding the FHIR id data type to ConceptMap dependsOn/product values after FHIR-28284 added choice-typed values but omitted ids. The use case was SNOMED CT descriptionIds, which are ids rather than concepts.

Initial application:
No current git commit explicitly mentions FHIR-33032. Related history shows FHIR-28284 introduced the dependsOn/product choice-type work, and the later ConceptMap2-to-ConceptMap commit included id in the older dependsOn/product value surfaces; the FHIR-28284 Jira comments also note that FHIR-33032 added id.

Additional context:
ConceptMap is an active resource in source/fhir.ini, and source/conceptmap/list-ConceptMap-operations.xml includes OperationDefinition/ConceptMap-translate. FHIR-39151 later refactored ConceptMap property/additionalAttribute definitions and narrowed the current additionalAttribute/dependsOn value type list to code, Coding, string, boolean, and Quantity, leaving the Published FHIR-33032 decision missing from the current resource and some $translate parameters.

AutoFHIR reconciliation:
Added id to ConceptMap.additionalAttribute.type documentation and complete CodeSystem, to ConceptMap.group.element.target.dependsOn.value[x] so product inherits it through the contentReference, and to the $translate dependency.value and match.product.value allowedType lists.

Recommendation:
Keep this source fix. It restores the Published FHIR-33032 decision on the active ConceptMap resource and associated $translate operation without changing unrelated ConceptMap property types or generated diagram artifacts.
