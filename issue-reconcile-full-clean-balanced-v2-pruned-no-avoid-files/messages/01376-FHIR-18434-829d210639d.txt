FHIR-18434: Correct XML declaration terminology

Issue request:
FHIR-18434 was Published with resolution Persuasive. It reported that the XML declaration syntax at the start of an XML document is not a processing instruction and approved changing the XML page wording from "a <?xml encoding=\"UTF-8\" ?> processing instruction" to "an XML declaration (<?xml encoding=\"UTF-8\" ?>)".

Initial application:
The original XML page request was applied in git commit 93a1e518122819664527632651511d587a93dad4, which edited source/xml.html under GF#18432, GF#18434, and GF#18435. The current source/xml.html still uses the approved "XML declaration" wording for the UTF-8 declaration guidance.

Additional context:
A later signature-page rewrite in commit dcf53a8af6d730f886918f45af2510e990a986eb moved current XML canonicalization guidance into source/signatures.html and introduced the same technical mislabeling by saying to include the XML processing instruction for <?xml version="1.0" encoding="UTF-8"?>. FHIR-18445's already-published combined-branch audit confirms source/signatures.html is the active signature canonicalization page and that the declaration requirement should remain; FHIR-18434 only corrects the XML terminology used for that declaration.

AutoFHIR reconciliation:
This commit changes source/signatures.html to call the canonicalization prolog an XML declaration, preserving the required declaration text and leaving the already-correct source/xml.html wording unchanged. The edited page is in current build scope because the documentation and format pages link to source/signatures.html for signature guidance.

Recommendation:
Keep this source fix. It completes the applied FHIR-18434 terminology correction across current authoritative XML-related narrative without reopening the broader signature-scope decision already audited for FHIR-18445.
