FHIR-41448: Align lastn rendered footer wording

Issue request:
FHIR-41448 was an Applied/Persuasive with Modification OO change request to clarify that `$lastn` groups based on equivalent `Observation.code` values do not have a specified relative order, while observations within each group are ordered from most recent to oldest. The accepted resolution also revised the explanatory comparison with `_count`/`_sort` to say `$lastn` returns the last N resources for each code group.

Initial application:
The change was applied through HL7/fhir#3671, merged as 1a244dd786df52310f38d2395b38b1a3e60fb723, with source commits c0e13d1b638f9408b97b7a0426c547e66e3e3f7f and 7b72de4bc9dfb2ba8fdb156ea1988705a19ea173. Those commits updated the OperationDefinition description and `comment`, including the explicit "ordering of the equivalent code groups is not specified" bullet, but left the rendered `build/StructureDefinition/footer` copy with the old "last N resource grouped by code" wording.

Additional context:
`source/fhir.ini` lists Observation as an active resource and `source/observation/list-Observation-operations.xml` references `OperationDefinition/Observation-lastn`, so the OperationDefinition source is in current build scope. The #implementers `$lastn grouping` discussion confirms the desired model of code groups with no required ordering between groups, and OO minutes record review of the branch plus the 2025-10-27 Persuasive with Mod vote.

AutoFHIR reconciliation:
Updated the `Observation-lastn` footer `valueMarkdown` to match the already-updated `comment` text, removing the stale rendered wording and making the operation page's explanatory footer consistent with the approved issue resolution.

Recommendation:
Keep this commit as-is. The fix is limited to the rendered duplicate source text required by the Jira resolution; any broader editorial cleanup of `$lastn` wording should be handled as a separate work-group decision.
