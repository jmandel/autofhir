FHIR-51486: Fix DeviceAlert type example coding

Issue request:
FHIR-51486 was an Applied/Persuasive with Modification R6 DeviceAlert change request asking whether several code elements should instead carry coding-system information. The final resolution left DeviceAlert.status unchanged and changed DeviceAlert.type, DeviceAlert.priority, DeviceAlert.signal.activationState, and DeviceAlert.signal.presence to CodeableConcept with extensible bindings.

Initial application:
The Jira comments point to HL7/fhir#3695 and merge commit c0d69e61555228b39aeb4092cc5dfdcf564314a7. The underlying implementation commit 819e689141ca71ac8a78ec920e55b6e1515b7d17 updated source/devicealert/structuredefinition-DeviceAlert.xml for the four target elements and converted the example priority and signal state elements, but left source/devicealert/devicealert-example.xml with DeviceAlert.type serialized as primitive code.

Additional context:
DeviceAlert is an active core resource in source/fhir.ini, so both the StructureDefinition and example are in the current build scope. Later Device WG discussion and the 2025-09-24 minutes explain the reopened decision to use extensible rather than required bindings. The corresponding Extension Pack issue, FHIR-51936, was handled separately in HL7/fhir-extensions and does not require another core change.

AutoFHIR reconciliation:
This commit updates source/devicealert/devicealert-example.xml so DeviceAlert.type is represented as a CodeableConcept coding from http://hl7.org/fhir/devicealert-type. This keeps the example consistent with the current DeviceAlert.type definition and with the final FHIR-51486 resolution.

Recommendation:
Keep this source fix as-is. No further FHIR-core change is needed for FHIR-51486 unless a future work-group decision changes the DeviceAlert coding model; Extension Pack alignment remains covered by FHIR-51936.
