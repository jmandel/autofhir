FHIR-24939: Align specialization derivation wording

Issue request:
FHIR-24939 was Published with resolution Persuasive with Modification for R5. It asked to clarify StructureDefinition.derivation so that a specialization can add rules about existing content, with the final wording using "additional rules to the base type" and matching the type-derivation-rule code system.

Initial application:
Commit fa31a7252f9a4a5c380431628b78a3cd1e4faf7d applied FHIR-24939 to the StructureDefinition resource and the type-derivation-rule CodeSystem. The CodeSystem specialization definition already used "additional rules to the base type", but the StructureDefinition.derivation comment retained "additional rules to an existing concrete type", leaving the two authoritative source surfaces inconsistent with the approved wording.

Additional context:
StructureDefinition is an active resource in source/fhir.ini, and source/structuredefinition/structuredefinition-StructureDefinition.xml is the authoritative resource source. FHIR-I minutes for 2020-03-23 record acceptance of FHIR-24939 and the intent to update the code system as well. A later Zulip thread about logical model derivation confirms that the R5 wording is understood to allow specialization StructureDefinitions to constrain inherited/base content, while raising separate ElementDefinition-table questions that had no final Jira follow-up found in this bounded search.

AutoFHIR reconciliation:
Updated StructureDefinition.derivation's comment so specialization differentials add new elements and optionally additional rules to the base type, matching the published Jira resolution and the current CodeSystem specialization definition. No generated artifacts or broader profiling-table text were changed.

Recommendation:
Keep this source fix as-is. It closes the remaining wording mismatch for FHIR-24939; any broader rules about which ElementDefinition constraint mechanisms are allowed in specializations should be handled only through a separate work-group decision.
