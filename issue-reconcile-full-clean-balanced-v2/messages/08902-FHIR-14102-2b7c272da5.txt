FHIR-14102: Audit Task priority code summary

Issue request:
FHIR-14102 was a Published/Persuasive STU3 change request for FHIR-core Task. It reported that the Task.priority description on task.html listed the codes "normal | urgent | asap | stat" even though the Request Priority value set uses the code "routine" rather than "normal".

Initial application:
The issue was applied in SVN/git history by a65352cbd0da82a126e7fc79d91ba77cdf075d9d, "Fix task priority short description 14102", which changed the Task spreadsheet short description from "normal | urgent | asap | stat" to "routine | urgent | asap | stat". Later source rework removed the spreadsheet and introduced source/task/structuredefinition-Task.xml while preserving the corrected short description.

Additional context:
Task is still active in the current build configuration, and the current Task.priority element is bound to http://hl7.org/fhir/ValueSet/request-priority. The current request-priority code system defines routine, urgent, asap, and stat; the old literal short description with normal no longer appears in the current source tree. Community searches found no conflicting Confluence or direct FHIR-14102 Zulip evidence; one 2018 Connectathon Zulip message independently observed the same R3 rendering problem before the corrected source was reflected downstream.

AutoFHIR reconciliation:
This commit intentionally makes no source change because the current build-scope Task source already contains the corrected Task.priority short value, and the bound terminology confirms routine is the valid code.

Recommendation:
Keep this no-change audit commit as-is. No further core FHIR source work is needed for FHIR-14102 unless a future publication surface regresses the generated Task.priority summary.
