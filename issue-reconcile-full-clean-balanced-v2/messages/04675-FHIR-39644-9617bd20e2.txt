FHIR-39644: Audit bundled aggregation definition

Issue request:
FHIR-39644 was Published with a Persuasive with Modification resolution for R5. It asked that the AggregationMode bundled definition clarify what it means when the resource described by a profile is not actually in a Bundle, resolving to: "When the resource is in a Bundle, the resource the reference points to will be found in the same bundle as the resource that includes the reference."

Initial application:
The issue was applied before this reconciliation by commit ff9dc14a8178578051a896b9d09f14ee4c3a2101, which changed source/datatypes/elementdefinition.xml from the unconditional bundled definition to the resolved conditional wording. The current source still contains that wording at source/datatypes/elementdefinition.xml:8648, and source/fhir.ini maps elementdefinition to the active ElementDefinition datatype page.

Additional context:
The linked Zulip thread records the original implementer question and Grahame's interpretation that if the resource is not bundled, then the references do not have to be bundled. FHIR-I meeting minutes record the Persuasive with Modification vote. Earlier related issues FHIR-14402 and FHIR-26386 supply adjacent aggregation/reference-resolution guidance, but they do not change the FHIR-39644 target wording or require another edit for this seed.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active ElementDefinition source already matches the exact published Jira resolution, and the R5 generated history contains the same definition.

Recommendation:
Keep this no-change audit commit as-is. No further core source work is needed for FHIR-39644 unless the work group wants to reopen the broader aggregation guidance rather than the bundled code definition resolved here.
