FHIR-55372: Audit Device.name.display modifier removal

Issue request:
FHIR-55372 was an Applied/Persuasive OO change request for R6 asking that Device.name.display not be a modifier because ignoring the preferred-display flag does not make interpretation of the instance wrong.

Initial application:
The change was applied before this reconciliation by f22405098ca56696b5de3ef2359acb6e4333a661, which removed the <isModifier value="true"/> and isModifierReason lines from source/device/structuredefinition-Device.xml. The same work was merged through HL7/fhir#4006, whose PR body listed FHIR-55372.

Additional context:
Device is an active resource in source/fhir.ini, so source/device/structuredefinition-Device.xml is in current build scope. FHIR-54320 is a later Applied/Persuasive duplicate/same-change-family issue whose resolution explicitly says the modifier is being removed with FHIR-55372. FHIR-54963 is still Waiting for Input and concerns 5Ws display of Device.name mappings, so it is background only; the current FiveWs mapping exceptions already record that Device.name.display diverges from the FiveWs.status modifier expectation. A checked-in generated-looking source/device/device.svg tooltip still says the element modifies other elements, but the authoritative StructureDefinition source is correct and this workflow should not manually edit only a generated SVG artifact.

AutoFHIR reconciliation:
This empty audit commit makes no source change. Current source/device/structuredefinition-Device.xml defines Device.name.display as a boolean summary element with no isModifier or isModifierReason, which is the requested state.

Recommendation:
Keep this audit commit as-is. If the stale SVG tooltip matters to the rendered build, regenerate generated diagrams from the corrected StructureDefinition source rather than hand-editing the SVG.
