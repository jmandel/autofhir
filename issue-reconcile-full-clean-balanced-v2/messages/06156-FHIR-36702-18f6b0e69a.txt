FHIR-36702: Audit inter-version extension guidance

Issue request:
FHIR-36702 was a Published/Persuasive with Modification FHIR-I change request asking for clearer guidance that inter-version extensions are not limited to missing elements, but can also cover missing datatypes, target resource differences, and cardinality changes, plus Basic-resource and version-selection expectations.

Initial application:
The request was applied for R5 by commit 7e0b2667, which updated source/versions.html with target-resource handling, vocabulary-binding context, and simple-type mapping wording. The Basic STU note requested by the resolution was added the same day in commit 0d7712a. Later current-source checks show source/basic/basic-introduction.xml still contains that Basic note.

Additional context:
Current source/versions.html was intentionally refactored by commit f45505e5 to remove detailed cross-version tables/examples from core and point to individual cross-version definition packages. The active core page still states that cross-version packages define the extension URL pattern and that extensions are defined for elements that cannot be represented directly, including elements that do not exist, elements with datatypes that do not exist, and maximum-cardinality changes. Later related work added canonical Basic guidance (FHIR-44664) and cardinality/FHIRPath guidance (FHIR-48379). FHIR-44616 is only Resolved - change required and was used as context, not decided in this default Applied/Published run.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding the removed detailed table or bullets to core would partially undo the later R6 content move and duplicate guidance now delegated to the XVer package/FAQ surface. The current FHIR-core source preserves the seed issue's implementer-facing scope, and remaining detail should be maintained with the cross-version packages rather than as a FHIR-36702 core fix.

Recommendation:
Keep this audit commit as-is. If FHIR-I wants the removed target-resource/simple-type details made more explicit again, handle that as follow-up work in the cross-version definition package guidance or FAQ, not as a belated core source reconciliation for FHIR-36702.
