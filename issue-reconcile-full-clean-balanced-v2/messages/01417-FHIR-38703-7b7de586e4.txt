FHIR-38703: Audit preferred-pharmacy extension ownership

Issue request:
FHIR-38703 is Applied/Persuasive with Modification. It asked for a standard complex preferred-pharmacy extension, raised from the Netherlands Patient use case, with final PA/PC scope on Patient, Encounter, PractitionerRole, Organization, and Location. The approved structure is a repeatable preferred-pharmacy extension with a required pharmacy Reference(Organization) sub-extension and an optional type CodeableConcept sub-extension.

Initial application:
No core FHIR commit or current core source file applies this issue. The implementation was made in the FHIR Extension Pack by commit 35b70862edf52d742720448aff998c91de6782b7, which added input/definitions/Patient/StructureDefinition-patient-preferredPharmacy.xml with the approved contexts and a repeatable extension. A later Extension Pack QA commit only changed the definition status from draft to active.

Additional context:
The Extension Pack source states that globally defined FHIR extensions moved out of the core specification starting with R5, and its ImplementationGuide includes input/definitions/* as built definition input. Current core source/fhir.ini still has active legacy extension spreadsheets, but searches of the current core source found no preferred-pharmacy or patient-preferredPharmacy definition. The Extension Pack definition now appears to be the authoritative source for this extension. However, its current type slice has min=1, while the Jira resolution says extension:type is 0..1 and 2024 PA minutes clarified that the example value set can be left open/unbound.

AutoFHIR reconciliation:
This is an empty external-repo audit commit. No core source was changed because the only remaining correction belongs in the FHIR Extension Pack, not this HL7/fhir checkout: change Extension.extension:type in StructureDefinition-patient-preferredPharmacy.xml from min=1 to min=0 while leaving the CodeableConcept value required when the optional slice is present.

Recommendation:
Keep this core audit commit as-is. Follow up in HL7/fhir-extensions to align patient-preferredPharmacy with the Applied FHIR-38703 resolution by making the type slice optional; no core FHIR source edit is indicated unless extension ownership policy changes.
