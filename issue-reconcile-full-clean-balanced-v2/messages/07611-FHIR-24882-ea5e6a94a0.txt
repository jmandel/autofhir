FHIR-24882: Clarify async interaction outcomes

Issue request:
FHIR-24882 was a Published/Persuasive FHIR-core change request for the Async page. It asked to extend the async/bulk-data pattern beyond GET/export-style pulls so clients could use an analogous asynchronous pattern for PUT and POST requests. The approved resolution said to clarify that async can be used for any valid RESTful operation, including POST, PUT, and PATCH, and to provide examples or clarity about the successful result for POST/PUT.

Initial application:
No source commit explicitly mentioning FHIR-24882 was found. The current source already had a high-level Asynchronous Interaction Request entry on source/async.html from the FHIR-35936 async-page split, and the FHIR-24882 Jira comment says that build.fhir.org/async described that pattern by August 2022. Before the R6 normative cleanup, source/async-bundle.html contained the detailed interaction pattern: normal HTTP methods and URLs, 202 Accepted kick-off response, and a completion Bundle whose first entry carried the underlying interaction status, outcome, location, and response body. Commit 270e0ceb7b later deleted source/async-bundle.html and source/async-bulk.html and changed the active async overview to external API Incubator links, leaving the current core page with the pattern name and a Bundle result but without the explicit POST/PUT/PATCH and success-outcome clarification requested by this issue.

Additional context:
FHIR-I minutes from 2020-03-23 record the 7-0-0 persuasive vote for FHIR-24882. The linked Zulip implementers thread documents the non-bulk async CRUD use cases that motivated the Asynchronous Interaction Request pattern, including async PUT/POST requests and the reason for wrapping the final response semantics in a Bundle entry. Later FHIR-42769 clarified 202 Accepted for create by linking to the Asynchronous Interaction Request pattern, and FHIR-47271 restored _outputFormat disambiguation on the same active async overview after the detail pages were removed. The current source/http.html and source/exchange-module.html link to source/async.html, and the current CI async page renders from this source; the referenced API Incubator async-bulk and async-bundle URLs currently return 404, so relying only on those external detail links would not preserve this issue's clarification in the current core build.

AutoFHIR reconciliation:
This commit adds a focused paragraph to the active source/async.html overview stating that the Asynchronous Interaction Request pattern applies to any valid RESTful request the server supports, including create (POST), update (PUT), and patch (PATCH). It also restores the essential successful-result rule from the deleted detail page: the initial response is 202 Accepted, and when processing completes, the polling response returns a Bundle whose first entry carries the final outcome of the original interaction, including status, OperationOutcome, resource location, and response body when applicable.

Recommendation:
Keep this source change. It restores the seed issue's approved clarification in current core build scope without reintroducing the deleted async detail pages or trying to resolve the broader broken API Incubator links. A separate follow-up may still be appropriate for the external async detail-page URLs.
