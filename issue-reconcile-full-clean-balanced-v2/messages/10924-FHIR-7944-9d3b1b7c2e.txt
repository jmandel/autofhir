FHIR-7944: Audit async operation callback request

Issue request:
FHIR-7944 was a Published/Persuasive with Modification FHIR-core change request raised against the DSTU1 operations page. It proposed replacing the old message-based asynchronous operation execution description with a callback URL pattern, but the approved resolution instead said to move section 2.2.0.6 to the messaging page, refer to it from the asynchronous section, and rewrite the note accordingly.

Initial application:
No current git commit explicitly names FHIR-7944, but the Jira comment records svn revision 5657. Git-svn commit 8b801ae887a7ed1c4e58cb57c30a8379b50cf157 is build@5657 and reworked operations and messaging: it removed the detailed "Executing an Operation Asynchronously using Messages" instructions from source/operations.html, left a DSTU note pointing to the messaging page and ongoing async discussion, and added the operation-via-message material to source/messaging.html. This matches the modified resolution rather than the originally proposed callback-URL design.

Additional context:
FHIR-6336 is the duplicate/same-change-family issue and confirms the intent to remove the under-documented operations-page async section; its comments say the content was removed to messaging and operations was left with a reference for further discussion. Later final async-pattern decisions superseded the 2015 DSTU note: FHIR-35936 split and updated async.html around Bulk Data and Asynchronous Interaction patterns, FHIR-41202 added operation synchronicity conformance, and FHIR-47271 clarified pattern disambiguation. Current operations source now points operations to the standard RESTful API asynchronous pattern, while the messaging page still separately documents invoking operations via messages.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source no longer contains the old confusing message-based operations async section or the rejected callback proposal. The operations page directs asynchronous operation execution to the current RESTful async pattern, and the messaging page retains the separate operation-via-message guidance originally moved there.

Recommendation:
Keep this audit commit as-is. Reintroducing callback-URL prose or a legacy operations-page messaging note would conflict with the later async-pattern direction and would add redundant or stale guidance; any future change should come through a new FHIR-I decision about the current RESTful async and messaging pages.
