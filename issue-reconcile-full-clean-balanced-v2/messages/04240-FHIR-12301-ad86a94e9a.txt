FHIR-12301: Audit GuidanceResponse action split

Issue request:
FHIR-12301 was Published/Persuasive for FHIR-core GuidanceResponse. It requested decomposing GuidanceResponse so the elements representing actions to be performed were broken out into a new RequestGroup resource usable as a decision-support response and as optional CarePlan components.

Initial application:
The Jira comments identify SVN #10094, #10095, and #10096 as the application. In git history, 4bd8aa5d9c (SVN 10094) added the RequestGroup resource, 4e3dd7a59f (SVN 10095) removed the superseded ActivityGroup resource, and 97bcb62478 (SVN 10096) removed the GuidanceResponse.action subtree from GuidanceResponse and updated examples/source to use the separated request group model.

Additional context:
The current build no longer uses the RequestGroup name directly: FHIR-24619 renamed it to RequestOrchestration for R5, source/fhir.ini has active GuidanceResponse and RequestOrchestration resource entries, and the old RequestGroup name is recorded as a removed/renamed resource mapped to RequestOrchestration. Later GuidanceResponse work, including FHIR-14179 and FHIR-37891, kept GuidanceResponse relevant and broadened GuidanceResponse.result to point at request resources, including RequestOrchestration, without reintroducing inline action elements.

AutoFHIR reconciliation:
No source change was made. The active GuidanceResponse StructureDefinition contains only response/status/output/result/data-requirement elements and has no GuidanceResponse.action path; GuidanceResponse.result references RequestOrchestration for proposed action sets. The active RequestOrchestration StructureDefinition contains the action backbone requested by the original split.

Recommendation:
Keep this audit commit as-is. The current source preserves the intended split after the RequestGroup-to-RequestOrchestration rename, so adding redundant wording or reintroducing RequestGroup-named source would make the current build less accurate.
