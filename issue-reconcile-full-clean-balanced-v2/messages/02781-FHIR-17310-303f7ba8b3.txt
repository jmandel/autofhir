FHIR-17310: Audit originalText extension ownership

Issue request:
FHIR-17310 was a Published/Persuasive FHIR-core datatypes change request to create a standard extension for preserving the original free text that was later encoded as a date, number, boolean, ratio, or similar datatype value. The Jira resolution says to do this, with the intended context being datatypes that do not already have a native text field.

Initial application:
The Jira comments cite SVN revisions 14075 and 14113, including the canonical URL http://hl7.org/fhir/StructureDefinition/originalText. Git history shows this was applied in core by b6506393954c788390d3f7a5aff8502df8970a6a, which added originalText to source/profiles/general-extensions-spreadsheet.xml as a DataType extension with the requested "what did the user actually see/type" rationale.

Additional context:
FHIR-15840 was the Pharmacy free-text strength use case referenced by the seed and was resolved as a no-change/background decision to use an extension on Ratio. A May 2018 Zulip primitive-extension discussion records the same original-text use case. Current core source no longer contains a local originalText extension definition: source/fhir.ini still has the active general extensions spreadsheet, but source/profiles/general-extensions-spreadsheet.xml has no originalText row. That absence is intentional for current FHIR source ownership because dd468d4f1799dd79819315b211588ef1cf4586e0 removed extensions from the R5 source, and the FHIR Extension Pack repository now contains input/definitions/Element/StructureDefinition-originalText.xml under the hl7.fhir.uv.extensions implementation guide.

AutoFHIR reconciliation:
This is an empty external-repo audit commit. No core source was changed because the current maintained definition is in the FHIR Extension Pack, where originalText has the canonical URL, Element context, 0..1 cardinality, value types string and url, active trial-use status, and text matching the original request. Core source still preserves relevant integration points by linking to [%extensions-location%]StructureDefinition-originalText.html from the datatypes/narrative/element-definition pages and retaining the assigned OID in source/oids.ini.

Recommendation:
Keep this audit as-is for the core combined branch. Future changes to the originalText StructureDefinition should be made in HL7/fhir-extensions, not by reintroducing the extension definition into the core source checkout; only core narrative links or OID references should be edited here if they become inaccurate.
