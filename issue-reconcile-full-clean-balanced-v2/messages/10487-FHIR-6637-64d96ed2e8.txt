FHIR-6637: Audit string contains modifier behavior

Issue request:
FHIR-6637 was a Published/Persuasive FHIR-core search change request from DSTU1 asking that default string search no longer be server-discretionary substring matching. The approved change made unmodified string search match equal-or-starts-with values and added a :contains modifier for matching anywhere within the searched field, with examples and modifier-introduction updates.

Initial application:
The Jira comments record application in svn revision 5815. In git history, git-svn commit 9dc6cbee1e9c67a652e308dd3624e77cdf54d25a is that revision and changed source/search.html to add :contains, change default string matching to equals-or-starts-with, and add examples. The commit subject says #6337, but its svn revision matches the Jira application comment for FHIR-6637.

Additional context:
The current search page has since been reorganized and the modifier table has been generalized, but the relevant behavior remains present: search.html states that default string search matches when a field equals or starts with the supplied value, documents :contains as matching anywhere within the field, and includes normal, :contains, and :exact examples. The search-modifier-code CodeSystem also includes contains with search-param-type string. No Jira, Zulip, or Confluence evidence found in this bounded check indicates a later reversal of the string behavior.
