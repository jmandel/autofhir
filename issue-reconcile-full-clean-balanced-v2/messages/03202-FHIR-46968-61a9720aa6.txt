FHIR-46968: Audit superseded DeviceAssociation operation guidance

Issue request:
FHIR-46968 was an Applied/Persuasive with Modification R6 Orders and Observations change request asking to clarify when DeviceAssociation.operation.operator should be used instead of DeviceAssociation.subject, especially when the subject is a Practitioner or RelatedPerson. The approved clarification said the DeviceAssociation relationship reflects the overall device-subject relationship, while operation reflects shorter-term use and identifies the operator; absence of operation.operator must not imply that the subject is the operator when periods of use matter.

Initial application:
The requested clarification was applied in upstream commit baaf631812b2b2d23fae4d49ffb0071e51a27b85 via HL7/fhir#3532. That commit added the Jira comment text to DeviceAssociation.subject and DeviceAssociation.operation.operator. The application was real, but it targeted the operation/operator backbone that no longer exists in the current DeviceAssociation model.

Additional context:
DeviceAssociation is active in source/fhir.ini. Later Applied/Persuasive with Modification issue FHIR-47604 removed the DeviceAssociation.operation/operator backbone, added DeviceAssociation.focus, and moved operator relationship semantics into DeviceAssociation.relationship, the base period, associationStatus, subject, and focus. The current DeviceAssociation introduction explicitly says the operation backbone was collapsed into other elements, and the current StructureDefinition says subject identifies the operator or similar entity while focus identifies the entity for which the device is being used. Existing combined-branch reconciliation commit 692324e7b3376004c65de20d5ab4781136fdea15 removed the stale FHIR-46968 operation wording from DeviceAssociation.subject after FHIR-47604 made it obsolete. FHIR-51421 later aligned DeviceAssociation.subject references and definition without changing that subject/focus model.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Re-adding the FHIR-46968 operation.operator clarification would be incorrect because DeviceAssociation.operation.operator is not part of the current R6 source. The current source already conveys the post-FHIR-47604 operator relationship model through subject/focus guidance and the R5-to-R6 change note.

Recommendation:
Keep this empty no-change audit. No core source follow-up is needed for FHIR-46968 unless the work group reopens the later DeviceAssociation subject/focus model; any future wording review should proceed through later feedback rather than restoring operation/operator prose.
