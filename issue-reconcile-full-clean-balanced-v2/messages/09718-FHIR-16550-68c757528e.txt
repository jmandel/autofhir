FHIR-16550: Audit date search timezone note

Issue request:
FHIR-16550 was Published/Persuasive with Modification for STU3. It asked to clarify the date search parameter timezone guidance in source/search.html, rejecting a blanket instruction that servers must not correct for timezones and instead resolving to add an implementer note that timezone handling for date search is difficult, still under community discussion, and may receive additional rules in future versions.

Initial application:
The issue was explicitly applied by historical commit 7310bd4a428c5bc66757b810067f16214f84747c, titled "GF#16550 - dragons on timezones" and carrying git-svn-id build@14540, matching the Jira comment "svn 14540 + GF#17630". That commit added the date-search "dragons" implementer note to source/search.html. Later editorial commits preserved and cleaned up the same note.

Additional context:
Current source/search.html is an active Search page linked from source/documentation.html, and the date search section still contains the existing timezone correction guidance plus the FHIR-16550 implementer warning. The R5 follow-up created by this issue is represented by FHIR-17630: commit 77f262f2638f99b947ab5ba72761d95b065b339d added the current Client Timezone guidance in source/http.html, and the combined branch already has a no-change audit commit for FHIR-17630. The linked #implementers Zulip thread confirms the issue was intentionally left as cautionary guidance because timezones, offsets, client context, and clinical-event locality are hard to resolve universally.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build source already contains the implementer note requested by FHIR-16550: "Managing timezones and offsets and their impact on search is a very difficult area" and "Future versions of this specification may impose rules around the use of timezones with dates." The later FHIR-17630 follow-up has also already been reconciled, so changing the date-search rules now would go beyond this applied issue.

Recommendation:
Keep this no-change audit commit. No FHIR-core source edit is needed for FHIR-16550 unless the work group reopens the broader timezone/date-search policy; any future policy change should be handled as a separate tracker rather than by reinterpreting this STU3 clarification.
