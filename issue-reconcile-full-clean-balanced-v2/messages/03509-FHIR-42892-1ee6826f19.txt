FHIR-42892: Audit search paging link relations

Issue request:
FHIR-42892 is an Applied/Persuasive FHIR-core technical correction for the Search page. It asked that the "Other Links - Paging" common link list use the precise previous relation rather than listing only prev, citing FHIR HTTP paging and RFC 5005.

Initial application:
The issue was applied in source/search.html by FHIR-42892 commits 4264607320a718fe87107b675e1b54a335dda02e and a9d09524434be7b5eb57ba6b14aa7488d4241560, which changed the Search page common link list and the _count zero prose from prev to previous. A follow-up FHIR-42892 commit aa86f3b6a30573b01aa943b887da6514f75eb237 made an additional clarification in the same section, listing both prev and previous and saying they are interchangeable.

Additional context:
FHIR-I minutes for 2023-11-06 record FHIR-42892 in a ticket block vote that passed 12-0-0. Current source/search.html now says common paging links include first, last, next, prev, and previous, and explicitly notes that prev and previous are widely-used interchangeable synonyms. The local IANA link-relation code system source includes both prev and previous, with previous defined as a synonym for prev. Later applied paging guidance in FHIR-51428 uses "previous (or prev)" in the paging best-practices text, confirming that retaining the synonym remains intentional current-spec behavior.

AutoFHIR reconciliation:
This is an empty no-change audit commit. The current Search page already satisfies the issue's substantive request by including previous and avoids an overcorrection by preserving the recognized prev synonym. No source file needed a current-spec edit.

Recommendation:
Keep this audit commit as-is. Do not remove prev from the Search page unless FHIR-I makes a new decision to deprecate or forbid the synonym across Bundle.link guidance, the IANA link-relation code system, and paging best practices.
