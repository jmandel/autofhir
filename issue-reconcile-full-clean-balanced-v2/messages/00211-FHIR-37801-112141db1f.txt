FHIR-37801: Audit Composition.subject cardinality

Issue request:
FHIR-37801 was a Published/Persuasive R5 Structured Documents request to change Composition.subject from a single subject to repeatable 0..*, so regulatory documents such as product labels can identify multiple MedicinalProductDefinition or RegulatedAuthorization subjects without List, Group, or section workarounds.

Initial application:
The issue was applied before this reconciliation. Commit d0d4a77daa74ccb388177a1b07ee6709dd0fe1eb changed source/composition/structuredefinition-Composition.xml from <max value="1"/> to <max value="*"/>, and PR merge commit 373eff25e30352565cebf98de6aa209d89af481f brought that FHIR-37801 change into the main history.

Additional context:
Composition is an active current-build resource in source/fhir.ini. SD minutes from 2022-08-04 record the same 17-0-0 motion to accept the cardinality change for multiple product-label subjects. Earlier core issues had already relaxed the minimum cardinality, and a later Clinical Document IG issue noted that R5/R6 core allows multiple subjects but chose not to pre-adopt that behavior in that separate IG. No directly conflicting current core decision was found.

AutoFHIR reconciliation:
No source change was made. The active Composition StructureDefinition already has Composition.subject at min 0 and max *, matching the Published Jira request; changing source would be redundant and could disturb unrelated profiles such as the catalog profile that intentionally constrains subject differently.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed for FHIR-37801 unless a future work-group decision changes Composition.subject cardinality again.
