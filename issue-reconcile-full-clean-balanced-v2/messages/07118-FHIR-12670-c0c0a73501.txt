FHIR-12670: Audit Task intent code alignment

Issue request:
FHIR-12670 was a Published/Persuasive DSTU2 technical correction for Task. It reported that Task.intent displayed "planned" as a valid code even though the bound RequestIntent value set used the actual code "plan"; the Jira resolution was auto-approved and records the correction as previously applied.

Initial application:
Git commit 20e489d0d4577bb13967a5310d208b1857c98687 pre-applied FHIR-12670 by changing the Task spreadsheet short name for Task.intent from "proposed | planned | actionable +" to "proposal | plan | order +". Later source refactoring moved the maintained definition into source/task/structuredefinition-Task.xml while preserving the corrected "plan" code wording.

Additional context:
Task remains in the current build via source/fhir.ini. The current Task.intent element is required-bound to ValueSet/task-intent, the TaskIntent value set explicitly includes RequestIntent code "plan", and the RequestIntent code system defines "plan" rather than "planned". Remaining "planned" strings in Task source are English prose, the separate Task Stage code system, mapping context, or generated diagram text; they do not reintroduce "planned" as a Task.intent code. Zulip and Confluence searches found no human discussion or conflicting work-group evidence.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change because the current active source already conveys the corrected Task.intent code alignment. Editing the remaining prose uses of "planned" would not fix the Jira issue and could make ordinary English descriptions less clear.

Recommendation:
Keep this no-change audit commit as-is. No follow-up source work is needed for FHIR-12670 unless a future work group issue changes the TaskIntent or RequestIntent code systems.
