FHIR-44664: Audit Basic canonical wrapper guidance

Issue request:
FHIR-44664 was an Applied/Persuasive FHIR-I change request for R6 asking the specification to clarify that, when cross-version extensions backport newer canonical resources into older FHIR versions, a Basic instance can be treated as the canonical-resource representation and can be referenced from those cross-version extensions.

Initial application:
The request was applied upstream in commit a791ea16e694364b097e029ed44114f67a717832, which added the active Basic page section "Basic as a Canonical Resource Wrapper" to source/basic/basic-notes.xml. PR HL7/fhir#3967 was merged on 2025-11-09 and included that Jira-tagged commit.

Additional context:
The Basic resource is active in source/fhir.ini, and the added Basic section links to the active cross-version extension guidance in source/versions.html and to the cross-version extension packages. FHIR-I WGM minutes record the 20-0-0 vote and the related discussion about representing newer canonical resources such as ActorDefinition in older versions. The related alternate-canonical helper lives in the FHIR Extension Pack, where FHIR-44663 corrected its value type to url, so no core source edit is needed for that external artifact.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core source already states that Basic can wrap canonical resources that do not exist in the FHIR version being used, that Basic can be treated as a canonical resource for referencing purposes, and that cross-version extension references can use canonical reference patterns. Adding another core paragraph to versions.html would duplicate the Basic-specific rule without changing implementer obligations.

Recommendation:
Keep this audit commit as-is. If future work wants examples in the cross-version extension packages, handle that in the extension-pack or xver IG source rather than by adding redundant Basic-specific prose to the core versions page.
