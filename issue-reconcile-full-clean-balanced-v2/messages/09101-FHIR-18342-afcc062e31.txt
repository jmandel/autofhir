FHIR-18342: Audit extension root exception note

Issue request:
FHIR-18342 was a Published FHIR-I STU3 correction with a Persuasive resolution. It asked to change the extensibility wording from "resource" to "domain resource" because extensions do not appear on all resources. The approved resolution did not make that replacement: it noted that Resource.meta can still be extended, while direct descendants of Resource that do not specialize DomainResource cannot have extensions on the root, and directed adding that detail to the notes.

Initial application:
The Jira comment points to GH#8717c97aa2. Commit 8717c97aa2b58fd58cee885a731fe57ba605819e, "GF#18342 - clarify about extensions", added the extensibility note that resources not specializing DomainResource cannot have extensions on the root element, while extensions can appear elsewhere through the resource.

Additional context:
The current build still includes source/extensibility.html via source/fhir.ini. The current source keeps the FHIR-18342 note and the underlying StructureDefinitions match it: Resource has no root extension element, DomainResource defines extension and modifierExtension, and Bundle is a direct Resource specialization without a root extension. Later FHIR-43364 and FHIR-46620 clarify the same boundary for extension contexts: resource/root contexts only apply where the target structure can actually carry extensions, such as DomainResource and its descendants.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already contains the note requested by the approved resolution, and replacing the introductory "resource" wording with "domain resource" would lose the approved nuance that datatype and Resource child elements such as Meta can still carry extensions.

Recommendation:
Keep this no-change audit commit as-is. No FHIR core follow-up is needed unless FHIR-I later changes the extension-context policy for Resource-root extensions.
