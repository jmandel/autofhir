FHIR-44499: Clarify non-FHIR operation guidance

Issue request:
FHIR-44499 was Applied with a Not Persuasive with Modification resolution. The reporter asked whether ExampleScenario operation type should be CodeableConcept and how to represent non-FHIR operations such as a user authorizing an activity. The final decision kept Coding, noted that type is optional, and asked for guidance on using or omitting a coded operation value.

Initial application:
The Jira records Git master 64f4db6650 as the application commit. That commit added guidance to ExampleScenario.instance.structureType, but left ExampleScenario.process.step.operation.type unchanged. The current source therefore already says operation.type is a 0..1 Coding for a standardized action type, but the applied structureType comment said a 1..1 element could be omitted.

Additional context:
source/fhir.ini keeps ExampleScenario active in the current build. The cited Zulip thread raised the Coding question for both ExampleScenario and TestScript but did not establish a standard OperationDefinition-as-Coding convention. TestScript is no longer an active core resource in this checkout and source/fhir.ini now points to the testing IG, so the current core reconciliation is limited to ExampleScenario. Confluence minutes show the issue was first raised for list discussion and later voted as "will fix" 10-0-1.

AutoFHIR reconciliation:
This commit keeps Coding and the extensible binding, but adds explicit operation.type guidance that non-FHIR actions may use other coding systems and that type should be omitted when no useful coded value exists. It also corrects the structureType guidance so it no longer implies that a mandatory structureType can be omitted within a declared instance; instead, non-data-sharing human actions omit the associated ExampleScenario.instance.

Recommendation:
Keep this commit as-is. It completes the applied resolution in active ExampleScenario source without changing the data model, and it avoids making any speculative TestScript change outside the current core build.
