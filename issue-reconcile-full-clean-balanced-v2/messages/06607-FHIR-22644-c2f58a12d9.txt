FHIR-22644: Audit SpecimenDefinition metadata alignment

Issue request:
FHIR-22644 was a Published OO change request, resolved Persuasive for R5, that originally asked to make SpecimenDefinition conformant to the Definition pattern by adding all properties from that logical model. The decisive later Jira comments narrowed that request: SpecimenDefinition already had sufficient canonical metadata and should not claim Definition-pattern conformance because it defines an entity, not an activity.

Initial application:
The issue was initially pre-applied in commit 5e7e903022d40189ae49e9481df0f7d47a233a31, which updated the old SpecimenDefinition spreadsheet and example while adding Definition-pattern-style metadata such as url, version, derivedFromCanonical, status, date, publisher, description, jurisdiction, purpose, copyright, approvalDate, lastReviewDate, and effectivePeriod. Later source refactoring moved SpecimenDefinition to structuredefinition-SpecimenDefinition.xml, and later canonical metadata work added remaining canonical fields such as versionAlgorithm, name, and copyrightLabel.

Additional context:
The 2021 OO Jira comments and minutes clarified that SpecimenDefinition should not be treated as a Definition-pattern resource. Lloyd McKenzie instead recommended making it a specialization of CanonicalResource. Current source/fhir.ini keeps SpecimenDefinition active, and current SpecimenDefinition specializes MetadataResource, which itself specializes CanonicalResource. Current workflow prose still defines Definition-pattern resources as time- and subject-independent activities, so forcing SpecimenDefinition to claim that pattern would be inconsistent with the later work-group rationale.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build-scope source already gives SpecimenDefinition canonical/metadata-resource behavior without adding an explicit Definition-pattern/interface claim, which matches the final OO interpretation of the issue.

Recommendation:
Keep this audit commit as-is. Do not add redundant Definition-pattern prose or a Definition-pattern claim for SpecimenDefinition unless OO later reopens that modeling decision; future metadata alignment should be handled under more specific canonical/metadata-resource issues.
