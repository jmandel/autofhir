FHIR-16711: Audit Clinical Reasoning expression context example

Issue request:
FHIR-16711 was a Published, Persuasive with Modification CDS change request from the STU3 ballot. It objected that the Clinical Reasoning FHIRPath evaluation-context example used Patient even though Patient does not itself support expression elements, and the final resolution said the text would be updated to reflect the new Expression data type.

Initial application:
No source commit explicitly mentioning FHIR-16711 was found. The exact Patient example was introduced with the Clinical Reasoning content import in GF#14890 and remains in the current Using Expressions page. Related July-November 2018 changes updated the same page to use the new Expression structure and later to state that Clinical Reasoning resources use the Expression datatype, matching Bryn Rhodes's Jira comment that the requested concern had already been effectively applied.

Additional context:
The Jira comments clarify that the Patient example is about a FHIRPath expression evaluated against a Patient resource, not about Patient containing a FHIR Expression element. The current page now separately explains that Clinical Reasoning resources use the Expression datatype, gives ActivityDefinition and PlanDefinition dynamicValue examples, and keeps Patient only as the evaluation context for `%context.name.given`. Related Expression-datatype ballot issues were encountered; FHIR-16783 is already represented on the combined branch, and FHIR-16705/FHIR-16702 were not separately audited here because they require their own full source-scope checks.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Changing the Patient FHIRPath context example to PlanDefinition or ActivityDefinition would blur the distinction between an expression-bearing resource and the resource instance used as evaluation context; the current text already conveys the correct rule after the Expression datatype updates.

Recommendation:
Keep this audit commit as-is. No follow-up source change is recommended for FHIR-16711 unless the work group wants a broader editorial rewrite of the evaluation-context examples independent of this applied ballot issue.
