FHIR-11127: Audit request intent order code

Issue request:
FHIR-11127 is Published/Persuasive with Modification. It reported that the DSTU2 DiagnosticRequest.stage element was required and forced systems that could not distinguish original-order from reflex-order to send potentially wrong data. The accepted resolution was not to make the modifier element optional, but to define a generic order code that subsumes original-order, filler-order, and reflex-order.

Initial application:
The Jira-tagged implementation commit 135effcdc1 renamed DiagnosticRequest.stage to DiagnosticRequest.intent and moved the binding from the old diagnostic-request-stage value set to the required RequestIntent value set. That commit still showed original-order and reflex-order in the then-current DiagnosticRequest spreadsheet, but later workflow/request-pattern history replaced DiagnosticRequest/DeviceUseRequest with the active ServiceRequest and DeviceRequest model and centralized request-intent terminology.

Additional context:
Related stage-name decisions FHIR-11190 and FHIR-12052 explicitly kept the element required as intent and allowed resource-specific detailed codes to map under proposal, plan, or order. The current build has ServiceRequest and DeviceRequest active in source/fhir.ini, with ServiceRequest.intent and DeviceRequest.intent still 1..1 and bound to http://hl7.org/fhir/ValueSet/request-intent. The authoritative request-intent code system now contains a generic order concept with original-order, reflex-order, filler-order, and instance-order beneath it. Older request-stage terminology XML files still exist in the tree, but they are not listed in the active source/fhir.ini [codesystems] or [valuesets] sections and are not the current binding for the active request resources.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already satisfies the FHIR-11127 resolution by preserving a required modifier intent and providing the generic order code that systems can use when they cannot or should not assert original-order or reflex-order.

Recommendation:
Keep this audit commit as-is. Do not edit the inactive request-stage files for this issue; if a future cleanup wants to remove or retire those stale terminology files, it should be handled separately from FHIR-11127 because they are not the active current-spec source for request intent.
