FHIR-25430: Audit dataelements Quantity duplication

Issue request:
FHIR-25430 was a Published/Persuasive FHIR-core correction requesting that generated dataelements.xml stop publishing multiple StructureDefinition entries with the same de-Quantity.comparator URL and the related Quantity child data element URLs.

Initial application:
No current core source commit explicitly mentions FHIR-25430. The affected dataelements.xml file is generated rather than checked in. The R4 publication surface had three generated entries for http://hl7.org/fhir/StructureDefinition/de-Quantity.comparator, matching the reported problem, while R5 and the current CI build each have exactly one such entry.

Additional context:
The originating Zulip thread asked the reporter to file a change request, and the FHIR-I 2020-01-13 minutes record the Persuasive 7-0-0 decision. The current authoritative datatype source has a single Quantity.comparator row in source/datatypes/quantity.xml; SimpleQuantity and MoneyQuantity remain profile constraints in the same active datatype source and no longer cause duplicate data element entries in the generated R5/current dataelements.xml output.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current generated specification already reflects the requested correction, and there is no checked-in dataelements.xml source artifact to de-duplicate in this repository.

Recommendation:
Keep this audit commit as-is. If duplicate data element entries reappear in a future generated build, treat that as a core build/kindling generation regression rather than a Quantity datatype source correction.
