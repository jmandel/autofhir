FHIR-19958: Audit Attachment size large-file support

Issue request:
FHIR-19958 was Published/Persuasive with Modification for FHIR-core datatypes. It reported that Attachment.size was an unsignedInt and therefore could not carry byte counts above about 2GB, and the recorded resolution proposed a largeValue extension on integer with decimal value plus an integer-value constraint.

Initial application:
The explicit FHIR-19958-tagged application appears in ec83d5b5057f1402bdeb77453f5d214806de6b8c, which added the largeValue extension definition and floor(value) = value invariant to the core general extensions spreadsheet as part of R5 non-substantive MnM changes. Separately, the earlier R5 datatype work in cbdf7d1e55dc4bfa1dc30fc526edee0491e05782 changed Attachment.size itself from unsignedInt to integer64, directly removing the 2GB limit.

Additional context:
FHIR-25208 added the signed long integer datatype for large counters, and FHIR-26937 later clarified that newer integer types, including integer64, serialize as JSON strings. Current fhir.ini routes datatype definitions into the active datatypes build, and current R5 publication confirms Attachment.size has type integer64. Core extension definitions were later moved out of the R5 source; the largeValue StructureDefinition now lives in the FHIR Extension Pack, where the later unresolved FHIR-56953 asks whether its decimal value should become integer64.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current core source/datatypes/attachment.xml already defines Attachment.size as integer64, source/datatypes.html defines integer64 as a 64-bit signed integer, and source/json.html documents integer64 JSON serialization as a string. Reintroducing or editing largeValue in core would be wrong because the current core datatype no longer has the defect and the remaining extension-pack question is external and not finally resolved.

Recommendation:
Keep this no-change audit commit. Do not change core Attachment.size or restore a core largeValue extension for this issue; if FHIR-56953 reaches a final decision, handle the largeValue extension type/constraint in the FHIR Extension Pack workflow.
