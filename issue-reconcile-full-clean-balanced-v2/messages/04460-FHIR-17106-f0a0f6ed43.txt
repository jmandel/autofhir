FHIR-17106: Audit terminology capabilities metadata endpoint

Issue request:
FHIR-17106 was a Published/Persuasive Vocabulary change request asking for a specific endpoint to retrieve the server-specific TerminologyCapabilities resource, analogous to the CapabilityStatement /metadata endpoint. The resolution was to resolve the request per GF#14444 and document the endpoint against TerminologyCapabilities.

Initial application:
The issue was applied by git commit 8df77e615e, the migrated svn r14742 commit named "GF#17106 - document terminologycapabilities access method," which added the TerminologyCapabilities introduction text for GET [base]/metadata?mode=terminology. The related GF#14444 implementation commit 81544e1ec1 had already added the mode parameter to the RESTful /metadata capabilities interaction, including the terminology mode row.

Additional context:
TerminologyCapabilities is actively in the current build via source/fhir.ini resource and maturity/status mappings. The current RESTful API page still defines GET [base]/metadata{?mode=[mode]} and says mode=terminology returns a TerminologyCapabilities resource, while the TerminologyCapabilities introduction repeats the direct GET [base]/metadata?mode=terminology access method. The original Zulip discussion explored whether a direct endpoint or a CapabilityStatement reference was needed, and later Zulip discussion confirmed that /metadata?mode=terminology had been present since R4; no Confluence evidence was found that changes that conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The build-scoped source already documents the endpoint requested by FHIR-17106 in both the authoritative RESTful API interaction and the TerminologyCapabilities resource introduction, so another edit would be redundant and could create maintenance drift.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed for FHIR-17106 unless a future work group decision changes the /metadata mode contract or the TerminologyCapabilities resource lifecycle.
