FHIR-13229: Audit mapping-column diagnostics

Issue request:
FHIR-13229 was a Published/Persuasive FHIR-Tools-Core change request for STU3 asking the build to report an error when a resource spreadsheet contains an unrecognized mapping column, with Condition's "Workflow Mappings" heading cited as the example typo for the valid "Workflow Mapping" column.

Initial application:
The Jira comment records svn revision 12607. In the git mirror this is commit a444eaf408607d2f8eb0f04508bf5f1675aaf0fa, which added ignored-mapping-column detection to the old spreadsheet parser, stored the resulting messages as ResourceDefn hints, and emitted them through ResourceValidator as informational hints. It also added spreadsheet authoring comments that point editors to source/mappingSpaces.xml.

Additional context:
The current FHIR source checkout no longer carries that Java parser source directly; the current Gradle build depends on org.hl7.fhir:kindling 1.25.5-SNAPSHOT. The cached Kindling class used by this checkout still contains OldSpreadsheetParser.checkIgnoredColumns, compares spreadsheet mapping column headings to the configured MappingSpace column names, and emits ResourceValidator hints for ignored mapping columns with content. Current source/mappingSpaces.xml defines the valid "Workflow Mapping" heading, source/fhir.ini keeps Condition and the workflow extension spreadsheets in active build scope, and current source spreadsheets no longer contain the erroneous "Workflow Mappings" heading.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The historical application is still represented in the current build tooling dependency and the current checked-in spreadsheet inputs do not retain the cited typo, so there is no FHIR-core source correction to make in this checkout.

Recommendation:
Keep this no-change audit as-is for core. If a future work group wants the historical informational hint strengthened into a build-failing error, that follow-up should be handled in the Kindling tooling source/release rather than by changing current FHIR specification source files.
