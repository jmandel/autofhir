FHIR-22694: Audit CapabilityStatement language support

Issue request:
FHIR-22694 was a Published/Persuasive FHIR-I change request asking for CapabilityStatement to let a server declare supported languages and locales for Accept-Language handling. The approved resolution was to add CapabilityStatement.acceptLanguage as a 0..* code element bound to the languages value set.

Initial application:
The issue was applied by commit f6fa2a5f27962062a1939c671d2345adb5cf20ad, which added CapabilityStatement.acceptLanguage to source/capabilitystatement/structuredefinition-CapabilityStatement.xml and example values to source/capabilitystatement/capabilitystatement-example.xml. Later source refactoring preserved the element in the active CapabilityStatement resource definition.

Additional context:
source/fhir.ini lists capabilitystatement as an active resource and places CapabilityStatement in the conformance module, so the inspected StructureDefinition source is in current build scope. FHIR-46074, an Applied/Persuasive with Modification R6 terminology issue, explicitly adopted the existing CapabilityStatement.acceptLanguage approach: a required binding to all-languages with a starter additional binding to languages. This explains why the current source no longer exactly matches the older wording "bound to the languages value set" while still satisfying the intended support for locales.

AutoFHIR reconciliation:
No source change was made. The current source has CapabilityStatement.acceptLanguage with min 0, max *, type code, Accept-Language/default-language guidance, a required binding to http://hl7.org/fhir/ValueSet/all-languages, and a starter additional binding to http://hl7.org/fhir/ValueSet/languages. The general example also includes acceptLanguage values.

Recommendation:
Keep this audit commit as-is. The current build source implements the published issue and the later binding form is supported by subsequent Jira evidence; only an unrelated spelling typo in the existing comment was observed, and it does not justify a source-changing reconciliation for this issue.
