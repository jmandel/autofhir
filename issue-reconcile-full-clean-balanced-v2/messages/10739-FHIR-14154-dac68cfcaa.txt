FHIR-14154: Correct of-type identifier examples

Issue request:
FHIR-14154 was a Published/Persuasive with Modification FHIR-core search issue for STU3 asking for a standard way to search Patient and other resources by Identifier.type plus Identifier.value when Identifier.system is not known. The accepted resolution was to add an identifier type modifier, with the clarification that this modifier is an error on searches other than Identifier search parameters.

Initial application:
The issue was first applied by git-svn commit b539d978bb489a29e7838c2f80d86c9cd3618da8, whose subject is "#14154 - search on identifier type" and whose patch added the :of-type modifier text and Patient identifier example to source/search.html. Later search-page work retained the modifier and expanded the section; FHIR-33422 fixed the original example's identifier:otype typo, and FHIR-36683 aligned the search-modifier-code CodeSystem spelling to of-type.

Additional context:
The current build-scope source already defines the token modifier as of-type, restricts it to Identifier-valued token search parameters, and uses the format [system]|[code]|[value]. The active search modifier terminology now uses the same of-type code. A 2022 Zulip implementers thread that cites FHIR-14154 confirms the intended use case: searching by an identifier type such as MRN or driver's license when the assigning Identifier.system is unknown or absent. While the semantics are present, the current examples in the of-type section were malformed: the JSON showed CodeableConcept.coding as an object instead of an array and omitted the comma before Identifier.system, and the XML used Coding.value instead of Coding.code.

AutoFHIR reconciliation:
This commit keeps the existing modifier semantics and makes a narrow source correction in source/search.html. It fixes the of-type Patient examples so Identifier.type.coding is represented as an array in JSON, the JSON member separator is present, the XML Coding uses <code>, and the explanatory sentence no longer contains the duplicated "of with" wording.

Recommendation:
Keep this commit as the FHIR-14154 reconciliation. The original identifier type search modifier is already applied and later spelling issues are represented by their own Jira history; this commit only corrects the examples that demonstrate the FHIR-14154 behavior.
