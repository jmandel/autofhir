FHIR-17622: Audit Location availability exception handling

Issue request:
FHIR-17622 was Published with a Not Persuasive with Modification resolution. It asked to rename Location.hoursOfOperation to align with HealthcareService/PractitionerRole availableTime and to add the notAvailable structure; PA decided to keep the Location-specific hoursOfOperation name because physical opening hours are different from service or role availability, but to add notAvailable support for closures such as holidays and planned maintenance.

Initial application:
No structural commit explicitly tagged FHIR-17622 was found. The relevant source application happened through 447e89f4, which introduced the Availability datatype and changed Location.hoursOfOperation to use it, and through 7b3274152e, which explicitly tagged FHIR-17622 and added Location notes pointing implementers to hoursOfOperation.notAvailableTime. The current fhir.ini migration notes record Location.hoursOfOperation as changed to a datatype and map the old availabilityExceptions text to Location.hoursOfOperation.notAvailableTime.description.

Additional context:
FHIR-25381 created the shared Availability datatype with availableTime and notAvailableTime, and FHIR-26641 independently requested copying the notAvailable closure structure into Location. FHIR-32500 later added rendering clarification across PractitionerRole, HealthcareService, and Location. Location is active in source/fhir.ini, and Availability is an active metadata datatype, so the current source locations are in build scope.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current source preserves Location.hoursOfOperation as requested by the FHIR-17622 disposition, while the Availability datatype supplies notAvailableTime.description and notAvailableTime.during under Location.hoursOfOperation for the closure use cases named by the issue.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed unless PA chooses a new post-R5 design to rename the element; adding a parallel Location.notAvailable element now would duplicate the active Availability datatype and conflict with the existing migration notes.
