FHIR-12399: Audit Medication abstraction coding guidance

Issue request:
FHIR-12399 was a Published FHIR-core Medication change request with a Not Persuasive with Modification resolution. The request asked for new Medication links from branded or concrete medication concepts to unbranded or more abstract Medication resources. The Pharmacy WG declined new elements and instead pointed to Medication.code codings as the mechanism, specifically the guidance that other codings may be literal translations or lower-granularity codes, while agreeing that this guidance should be clearer.

Initial application:
No source commit was found that explicitly mentions FHIR-12399 or TR 12399. The Jira comments point to commit b0500f8b520d72851aba346483f21d1ded9a86b3, but that commit explicitly applied TR 12764, TR 12394, and TR 12392, not this issue. The lower-granularity Medication.code sentence already came from earlier FHIR-8553 guidance, was omitted during the FHIR-12391 userSelected wording update, and was restored by FHIR-13536 in commit 333047669dbe6165ff81da07eabda57b3f9880e6. Later source refactors carried that text into the current Medication StructureDefinition.

Additional context:
Medication is an active current-build resource in source/fhir.ini. The current build-scoped Medication StructureDefinition has no separate unbrandedMedication or abstraction link element, but Medication.code now explicitly says that non-selected codings can only be literal translations or lower-granularity codes, matching the mechanism cited in the FHIR-12399 resolution. The current examples also distinguish manufactured products from generic formulations, and the later FHIR-13536 audit is already present on the combined branch, so this reconciliation should not republish that related issue. Direct Zulip and Confluence searches found no conflicting community record for FHIR-12399 or the medication abstraction terms.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Adding a new Medication reference element now would contradict the final modified resolution, while adding redundant narrative would not change implementer understanding because the authoritative Medication.code comment already contains the required lower-granularity coding guidance.

Recommendation:
Keep this no-change audit as-is. No FHIR-core follow-up is needed for FHIR-12399 unless Pharmacy opens a new current-version request for computable branded/unbranded or concrete/abstract medication relationships beyond the existing Medication.code coding mechanism.
