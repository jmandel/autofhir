FHIR-21284: Audit target reference extensions

Issue request:
FHIR-21284 was Published with a Persuasive resolution for FHIR-I. It asked to add targetElement and targetPath extensions, originally motivated by Provenance.target, where targetElement carries the target element id as a valueUri and targetPath carries a simplified FHIRPath as a valueString; the accepted resolution also clarified that the extensions should apply to any Reference datatype instance, not only Provenance.target.

Initial application:
Core commit 38993a71efdea21922d51b0ba140af67cc084cec explicitly applied FHIR-21284 by adding the reference extensions spreadsheet and registering it in fhir.ini, including targetElement and targetPath rows for Reference. Commit b84bf92092849d997f7f5edd3a15e75305fe8d55 then added Provenance examples using targetElement and targetPath, and the March 2022 FHIR-I Zulip thread records John Moehrke confirming that the build contained the extension pages and Provenance examples and presuming the application was sufficient.

Additional context:
Commit dd468d4f1799dd79819315b211588ef1cf4586e0 later removed extension definitions from the R5 core source as part of the move to the FHIR Extension Pack. The current Extension Pack owns active targetElement and targetPath StructureDefinitions with the canonical URLs requested by FHIR-21284, Reference context, and the expected uri/string value types. Later FHIR-27877 expanded the same extension family to Reference and canonical context, and related FHIR-23076/FHIR-48368 audit commits on the combined branch already cover Provenance narrative/examples and visibility. Current core Provenance remains active and links to the Extension Pack definitions through [%extensions-location%].

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The current specification state already satisfies FHIR-21284: the authoritative extension definitions live in the Extension Pack, core keeps active OID registrations and build-facing Provenance examples/narrative using those canonical URLs, and adding duplicate core extension definitions would conflict with current extension ownership.

Recommendation:
Keep this no-change audit commit. No core FHIR source change is needed for FHIR-21284; future changes to targetElement or targetPath definitions should be handled in the FHIR Extension Pack unless a work group makes a new core narrative or example request.
