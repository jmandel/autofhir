FHIR-21638: Audit submit-data update guidance

Issue request:
FHIR-21638 was an Applied/Persuasive CQI change request asking whether Measure $submit-data should be stateless or whether a receiver could assume previously submitted data was already present. The applied resolution was to incorporate emerging Data Exchange for Quality Measures guidance, and the 2025 Jira application comment specifically requested $submit-data text explaining MeasureReport.dataUpdateType and linking to the DEQM implementation guide.

Initial application:

The current source still contains that guidance in the active Measure $submit-data OperationDefinition.

Additional context:
The Measure resource is active in source/fhir.ini, and source/measure/list-Measure-operations.xml includes OperationDefinition/Measure-submit-data, so the checked operation definition is in current build scope. Later same-operation work, especially FHIR-50487 and FHIR-39174 already represented on the combined branch, further aligned $submit-data with DEQM and clarified Bundle/MeasureReport usage without removing the FHIR-21638 guidance. MeasureReport.dataUpdateType itself now defines snapshot replacement versus incremental differential update behavior.

AutoFHIR reconciliation:
No source change was made. The current $submit-data description already tells implementers that MeasureReport.dataUpdateType indicates whether submitted data is a snapshot or incremental update and points readers to the Data Exchange for Quality Measures implementation guide, which satisfies the applied Jira instruction without duplicating or altering the later DEQM-aligned operation text.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-21638 in core unless the CQI work group later changes DEQM alignment or the deprecated $submit-data operation is removed/replaced.
