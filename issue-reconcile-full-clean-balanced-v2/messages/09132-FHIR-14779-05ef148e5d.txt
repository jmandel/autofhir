FHIR-14779: Audit workflow cancellation guidance

Issue request:
FHIR-14779 was Published/Persuasive with Modification for the STU3 FHIR-core workflow page. It objected that non-Task request/fulfillment patterns lacked a defined way to cancel an order, making Task seem necessary in most contexts; the accepted resolution said to discuss order cancellation and revision in each scenario, while noting cancellation is not relevant to every order or workflow.

Initial application:
The Jira comment cites SVN #14780, which maps to git-svn commit 2787aa8c73ec559cfd0ca2c2f94104c954592783, "Workflow clarifications: 14778, 14779, 15703". That commit added cancellation limits and capabilities to the ad-hoc and workflow-management pages, including custom operations, Request.status cancellation, missed-cancellation risk with polling/subscription, purpose-specific messages, Task cancellation by the placer, and fulfiller/broker control over whether a Task can be cancelled.

Additional context:
The current workflow pages are still part of the live informative workflow documentation, linked from the documentation index and workflow module page. Later edits reorganized and corrected the workflow pages but retained the cancellation guidance; current management-pattern text also covers request status changes and other updates, and the communication example shows cancelling an existing task and creating a revised referral task. Jira/Zulip/Confluence searches found no direct FHIR-core reversal of FHIR-14779; broader later order-workflow results were in the Clinical Order Workflow area and do not require a core source change for this seed.

AutoFHIR reconciliation:
No source change was made. The current source already gives implementers the issue's intended distinction: Task is useful for workflow management, negotiation, progress, cancellation, and updates, but some non-Task patterns can cancel or revise requests through custom operations, Request updates, purpose-specific messages, or replacement requests, with clear limitations.

Recommendation:
Keep this audit commit as-is. Do not add duplicate wording to the current workflow pages unless a future work-group decision reopens the broader order-workflow model; the existing source is already semantically aligned with the published FHIR-14779 resolution.
