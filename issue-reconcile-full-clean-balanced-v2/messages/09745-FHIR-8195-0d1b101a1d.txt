FHIR-8195: Audit implementer support guidance

Issue request:
FHIR-8195 was a Published FHIR-core/QI-Core change request with resolution Not Persuasive with Modification. It asked for a guide explaining how common clinical data should be represented in FHIR; the accepted modification was not to maintain a dynamic answer list in the specification, but to replace the old Support/Stack Overflow section with a "How to get support?" style support link and route implementers to community/support channels that could include examples of representation questions.

Initial application:
The issue was initially applied in git-svn commit 2390c6129a3e9541dc64e4e18c2ef3fbd6e71d01, whose message was "#8195 - remove support.html" and whose SVN revision matches the Jira comment. That commit deleted source/support.html and changed the home/implementation support entries from a local Stack Overflow-focused page to the FHIR Support Page. A follow-up publishing/build commit added a Support Links entry to the developer overview and changed the general overview to point at the support page; later commits replaced the old implementation page with the Implementation Support module and migrated wiki links to Confluence/community destinations.

Additional context:
The current build-scope source no longer contains source/support.html. The active hierarchy includes source/implsupport-module.html as the Implementation Support module, and that page has a Getting Help section listing Zulip, the FHIR Community Forum, Stack Overflow, and HL7 FHIR documentation, plus a note that most implementer support has moved away from the specification. Current general and developer overview pages link to Confluence Support Links. The current architect overview was introduced after the original 2015 application and is not misleading without duplicating the same support link; adding another support link there would be editorial navigation duplication rather than a necessary spec correction.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source change is needed because the current source has already retired the obsolete local support page/Stack Overflow-only guidance and routes support questions to the active community/support surfaces consistent with the issue resolution.

Recommendation:
Keep this audit as-is. Revisit only if the work group wants a broader redesign of support navigation or the external Implementer Support page, not as a core-spec fix for FHIR-8195.
