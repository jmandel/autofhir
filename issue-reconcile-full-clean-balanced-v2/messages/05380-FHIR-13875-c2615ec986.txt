FHIR-13875: Audit UCUM compositional guidance

Issue request:
FHIR-13875 was a Published/Persuasive STU3 Vocabulary change request asking for general FHIR guidance on whether UCUM curly-brace expressions such as {beats}/min should be used in Quantity.code. The approved resolution was to describe that UCUM is inherently a compositional code system on the Using UCUM with FHIR page.

Initial application:
The issue was applied by git commit e372de1ae6332c01a197b2428d7e0d1a0d55311d, whose message maps to svn revision 13080 and says "GF#13875 - document that UCUM is always compositional". That commit added a UCUM Expressions section to source/ucum.html explaining UCUM compositional syntax, terminology capability documentation for servers that do not support the full grammar, and the common UCUM codes value set fallback.

Additional context:
The current FHIR core build no longer owns source/ucum.html. Later Published issue FHIR-35933 and implemented UTG proposal UP-289 transferred the external code system "Using X with FHIR" pages from FHIR core to HL7 Terminology (THO), deleted source/ucum.html, and changed source/terminologies-systems.html to link to https://terminology.hl7.org/UCUM.html. The current THO language page retains the UCUM Expressions guidance and additionally states that curly braces in the code element are discouraged because they add descriptive text without changing code meaning.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The active FHIR core Code Systems page is in build scope through source/hierarchy.xml and already links UCUM to THO; the local UCUM page was deliberately removed from the core source. Re-adding UCUM prose to FHIR core would reverse the later migration and duplicate authoritative THO content.

Recommendation:
Keep this no-change audit as-is. No FHIR core follow-up is needed for FHIR-13875; future wording updates about UCUM curly-brace use should be made in the HL7 Terminology source for the UCUM page rather than in this core checkout.
