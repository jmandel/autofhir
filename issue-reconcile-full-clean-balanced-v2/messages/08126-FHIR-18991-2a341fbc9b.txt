FHIR-18991: Audit subscription payload MIME handling

Issue request:
FHIR-18991 was a Published / Persuasive with Modification STU3 Subscription issue. It asked to correct the SMS guidance that said payload could be set to false even though Subscription.channel.payload was a string, to change payload to a code bound to Mimetype, and to revise the SMS note so omitted channel.payload means no payload is sent without prohibiting SMS or SMTP payloads entirely.

Initial application:
The Jira comment cites git 80086b8f22b9b182c473fbb7b7a446d7aafbd37c, whose tree already contains the applied Subscription.channel.payload row as 0..1 code with a MimeType binding and the corrected SMS note. The direct source diff appears immediately before that in 7a2e56398d9cb0ad4541c35027c8e855c2b0b764, which changed the old spreadsheet row from string to code/MimeType and revised the SMS note from "payload should be set to false" to guidance that channel.payload will usually be omitted. Commit 80086b8f mainly added the companion FHIR-18989 tracking narrative, so it is relevant as the Jira-tagged application point but not the only payload-specific source change.

Additional context:
Later Subscription redesigns replaced the old Subscription.channel.payload element with Subscription.contentType for MIME selection and Subscription.content for the amount of notification content. The current Subscription resource is active in source/fhir.ini, and its Subscription.contentType element is a code with a required binding to ValueSet/mimetypes. Current Subscription narrative no longer has an SMS channel section; SMS was removed from the narrative in fb3fe3195848fb543677d2135c68a54c6a999a4b, while the current email channel guidance explains text/plain, text/html, FHIR attachments, and PHI limits. Related email/payload issues FHIR-18992 and FHIR-21286 are already represented on the combined branch and were not duplicated here.
