FHIR-36197: Audit ClinicalImpression changePattern

Issue request:
FHIR-36197 was Published with a Persuasive with Modification resolution for R5 Patient Care work on representing improving, deteriorating, or unchanged condition course. The final decision was to add ClinicalImpression.changePattern after ClinicalImpression.problem, cardinality 0..1, with CodeableConcept type, example binding, and SNOMED CT examples for worsening, improving, and no status change.

Initial application:
The issue was applied before this reconciliation by git commit 705001a8305b39afe7a4d59f41055a0f212b301d, which added ClinicalImpression.changePattern and valueset-clinicalimpression-change-pattern.xml. The commit is contained in v5.0.0, and the current checkout still has the R5-era ClinicalImpression source showing the requested element and value set.

Additional context:
FHIR-46596 later renamed ClinicalImpression to ClinicalAssessment for R6 and carried the changePattern element and value set forward. A later core commit, fad1b9cf84ef652e88947e1a13b026c62f95334e, removed ClinicalAssessment from the active core resource list and changed core narrative links to the PC incubator IG. The PC incubator ClinicalAssessment StructureDefinition and ValueSet currently expose the same changePattern definition, 0..1 cardinality, example binding, and three SNOMED CT example codes. Confluence and Zulip evidence confirms the Patient Care discussion and implementer guidance ended with ClinicalImpression.changePattern, with no conflicting final decision found.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Editing the inactive core ClinicalImpression or ClinicalAssessment folders would not affect the current core build, while the historical R5 source and the current external ClinicalAssessment artifact already preserve the issue's approved semantics.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-36197; any future change to the active ClinicalAssessment artifact should be handled in the PC incubator IG or by a new work-group decision.
