FHIR-45064: Audit nutrition value-set alignment

Issue request:
FHIR-45064 was Applied/Persuasive for R6 after the OO Nutrition group agreed to review the NutritionIntake and NutritionProduct value sets and realign them to remove confusing overlap among Diet Codes, Types of Edible Substances, Food Type Codes, and Categories of Nutrition Products.

Initial application:
The issue appears to have been applied through the 2024 nutrition update sequence and later cleanup. Commit a3233204b1 updated NutritionIntake/NutritionProduct terminology and NutritionProduct.category composition; commits 3731dbe4d5 and a218cee747 refined the value-set descriptions and enabled the intended SNOMED inclusions; commit 05e646d74bb93a1c435d884747dc64da94898435 explicitly cited FHIR-45064 while applying related NutritionIntake model cleanup.

Additional context:
The active fhir.ini resource entries include NutritionIntake and NutritionProduct. Current source binds NutritionIntake.code to diet-type for overall diet/regime, NutritionIntake.nutritionItem.type to food-type for item category, NutritionIntake.nutritionItem.nutritionProduct to edible-substance-type for a specific consumable product, NutritionProduct.code to the same edible-substance-type value set so inline codes align with referenced NutritionProduct resources, and NutritionProduct.category to nutrition-product-category for broader product classes. OO minutes on 2024-06-26 record the approval and the same realignment direction; Zulip searches found no conflicting discussion.

AutoFHIR reconciliation:
This audit commit makes no source change because the current build-scope source already distinguishes the semantic levels requested by the Jira. The shared edible-substance-type binding between NutritionIntake.nutritionItem.nutritionProduct and NutritionProduct.code is an intentional alignment for the same product-code concept, not a residual inconsistency, and the category/type value sets now have separate descriptions and compositions.

Recommendation:
Keep this audit commit as-is. Future terminology refinements, if desired by OO, should be filed as new value-set maintenance issues rather than changing this already-applied reconciliation.
