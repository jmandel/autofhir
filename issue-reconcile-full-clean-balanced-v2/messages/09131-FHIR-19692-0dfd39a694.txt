FHIR-19692: Audit search sort discretion note

Issue request:
FHIR-19692 was a Published/Persuasive with Modification FHIR-core search issue asking that sorting on repeated or complex search elements not mandate the unintuitive behavior of sorting Patient.name by the earliest component value such as "Abrams" before "Adam". The final 2022 FHIR-I resolution replaced an earlier orderMeaning-based proposal with a note giving servers discretion for repeated and complex element sorting.

Initial application:

Current source/search.html still contains the resolved discretion note in the search sorting section, including Patient.name examples and the choice between earliest sort-order value and first instance value for multiple given names.
