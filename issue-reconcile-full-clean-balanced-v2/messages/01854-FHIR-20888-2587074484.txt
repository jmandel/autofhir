FHIR-20888: Audit superseded AuditEvent description removal

Issue request:
FHIR-20888 was a Published/Persuasive Security WG change request for R5 asking to remove AuditEvent.entity.description because it had been added under the mistaken assumption that DICOM AuditMessage ParticipantObjectDescription carried a value rather than being only a grouping element.

Initial application:
The issue appears to have been applied in the old AuditEvent spreadsheet/source flow by commit 8f93636e058fa1a4b9ce4240fea41076e10e6760, linked from the Jira as PR 708, which marked AuditEvent.entity.description for removal and updated examples to stop populating entity.description. The current StructureDefinition-based source later no longer depended on that spreadsheet representation.

Additional context:
AuditEvent is an active resource in source/fhir.ini, so the AuditEvent StructureDefinition, notes, examples, and search parameter bundle are in current build scope. A later final Security WG decision, FHIR-48681, explicitly reintroduced AuditEvent.entity.description for R6 as needed for search audits and DICOM AuditMessage compatibility; git commits bf1af0e4c2f135e434714066d1069c0853179c3a and ec08b4da56749da742e5d70f46333eb65c8860e4 added the element and entity-desc search parameter. The combined branch already contains the FHIR-48681 reconciliation commit, so this seed must not undo that later Applied decision.

AutoFHIR reconciliation:
This empty audit commit made no source changes. The current source intentionally contains AuditEvent.entity.description and related search/audit references because FHIR-48681 superseded the older FHIR-20888 removal request; removing the element now would make the current build inconsistent with the later Applied issue.

Recommendation:
Keep this no-change audit as-is. Do not remove AuditEvent.entity.description under FHIR-20888 unless the Security WG separately reopens or reverses FHIR-48681's later decision.
