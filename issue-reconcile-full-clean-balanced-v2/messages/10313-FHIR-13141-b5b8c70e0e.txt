FHIR-13141: Remove include criteria suffixes

Issue request:
FHIR-13141 was a Published/Persuasive FHIR-core search issue asking to remove "&criteria..." from _include and _revinclude examples because the suffix made it look as though criteria could control what resources are included.

Initial application:
The issue was initially applied in svn/git history by 15920d2c6d40113c747a70cb6790d4143a83162c, which removed &criteria... from the basic _include and _revinclude examples. A later search-page rewrite in 83529ed121dc9fc1d9aeb117b0fe8a6293f9f0c9 converted nearby examples to the newer GET/POST display markup and carried &criteria... forward in _include/:iterate examples, leaving the same ambiguity in current source.

Additional context:
The active source/search.html page is the authoritative core search narrative; source/documentation.html links to search.html and source/fhir.ini explicitly ties search rule maintenance to the search.html summary table. Later Jira issues FHIR-13602, FHIR-31951, and FHIR-46944 corrected or clarified the same iterate examples and behavior but did not approve criteria on included resources. FHIR-49638 later proposed conditional inclusions and was retracted, and Zulip discussion confirmed there is no standard way to put additional criteria on included resources.

AutoFHIR reconciliation:
Removed the remaining &criteria... suffixes from the current _include and _include:iterate examples in source/search.html, including both GET and POST displays. No _revinclude examples with this suffix remain in current source.

Recommendation:
Keep this source correction. It restores the final FHIR-13141 decision in the current build page while preserving later iterate wording and example search parameter corrections.
