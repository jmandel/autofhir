FHIR-16551: Audit cardiology PlanDefinition null actions

Issue request:
FHIR-16551 was a Published/Persuasive CDS change request from STU3 reporting that plandefinition-example-cardiology-os.json action.action contained four null children that interfered with parsing and unit-test generation. The approved resolution was to correct the example.

Initial application:
No Jira-keyed source commit for FHIR-16551 was found. Git history shows the same source file was introduced with four placeholder child actions whose only content was XML comments, and commit acadb400a8cb036f9b62a3c595d8790056c0d354 commented out those placeholder action elements shortly after the issue was created. Jira comments later state that the example was corrected.

Additional context:
The PlanDefinition resource is active in source/fhir.ini, and list-PlanDefinition-examples.xml registers plandefinition-example-cardiology-os as a current PlanDefinition example. FHIR-16374 reported the same 2018May cardiology PlanDefinition JSON null action problem and reached the same Published/Persuasive correction outcome. A Zulip implementers thread repeated the same example and line-number symptom; Confluence searches found no conflicting WG minutes.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative XML source has the four old placeholder actions inside XML comments rather than emitted action elements, and a parse check found zero action elements with no XML element children, so the current generated JSON should not contain the reported null action entries.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-16551 unless a future build or validator report shows a new, distinct invalidity in the cardiology PlanDefinition example.
