Issue request:
FHIR-29118 is Published/Persuasive with Modification for FHIR-core Task. It asked to change Task.statusReason from CodeableConcept to CodeableReference so a rejected Task can link to a resource explaining the reason, and the final resolution also required an example value set.

Initial application:
Jira comments point to the R5 build work in the FHIR-29118 branch and PRs. Inspecting that history shows e3205c6627 changed Task.statusReason to CodeableReference, and d23189b362 added the TaskStatusReason value set/code system plus the Task.statusReason binding reference. The current source retains those changes after later formatting and cleanup commits.

Additional context:

OO minutes added the issue to the June block and later accepted the block vote 10-0-4. Later applied core issues refine the same element without reversing FHIR-29118: FHIR-50132 raises Task.statusReason cardinality to 0..*, and FHIR-54564 adds the Any/Resource target for the CodeableReference.
