FHIR-5787: Audit ValueSet expansion controls

Issue request:
FHIR-5787 was a Published Vocab change request asking whether ValueSet expansions needed active/inactive support and explicit support for other code system properties. The accepted resolution was to document inactive-code inclusion as a proper use for the $expand profile parameter rather than adding a separate expansion flag at that time.

Initial application:
The issue was applied by git-svn commit 347cc6c43e2bf9aa38c0dd11d80caa8aacfee646, which updated the old valueset spreadsheet entry for expand.profile to list whether to include inactive concepts as a known profile use. No current source edit is needed to recreate that old wording because the profile parameter no longer exists in current ValueSet source.

Additional context:
FHIR-5788 added the original $expand profile parameter. Later, FHIR-16337 and FHIR-16490 led to commit 0cf4c0c96d333dbe2a5b7a5d158f7e59db4c4b5b, which removed ExpansionProfile/profile guidance and revised expansion documentation so all parameters that affect $expand are recorded with the expansion. The current build-scope ValueSet source now has explicit $expand activeOnly and property parameters, ValueSet.expansion.parameter metadata for expansion controls, ValueSet.expansion.contains.inactive for returned inactive concepts, and ValueSet.expansion.contains.property for returned code system properties.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current specification covers the implementer need behind FHIR-5787 through explicit activeOnly/property controls and expansion metadata rather than the superseded profile parameter mechanism.

Recommendation:
Keep this audit commit as-is. Do not reintroduce $expand.profile for FHIR-5787; any future change should be a new terminology work-group decision about current $expand parameters or ValueSet.expansion property representation.
