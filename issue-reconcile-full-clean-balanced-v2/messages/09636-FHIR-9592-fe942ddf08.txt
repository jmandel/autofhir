FHIR-9592: Audit Device software manufacturer handling

Issue request:
FHIR-9592 was a Published FHIR-core Device change request, resolved Not Persuasive with Modification, asking for a new attribute for a device software manufacturer that might differ from the physical device manufacturer. The OO resolution declined a new attribute and instead pointed to component modeling, then said narrative would be added to the Boundaries section to clarify that software version information belonged with the device component model.

Initial application:
No current source commit found by git history explicitly mentions FHIR-9592. The historical resolution referred to DeviceComponent.productSpecification, but DeviceComponent is now commented out/dropped in source/fhir.ini and is not part of the current build. Later Device work changed the active Device narrative and structure so Device can represent software and can represent a component with a parent relationship; Device and DeviceDefinition now both carry deviceVersion/component/value structures.

Additional context:
The current build actively includes Device and DeviceDefinition. Device.manufacturer remains the manufacturer or legally responsible entity for a Device, and the current Device narrative states that medical devices may include software, non-medical devices may include software applications or algorithms, and a Device may represent a component of an encapsulating device. Device.deviceVersion.component identifies the hardware or software module to which a version applies. A software item that needs a different manufacturer can be represented as its own Device or kind of DeviceDefinition, rather than by adding a software-manufacturer-specific attribute to a physical Device.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Adding a new attribute would contradict the final Not Persuasive with Modification decision, and adding more narrative would be redundant with the current active Device scope/boundaries and version/component elements. The obsolete DeviceComponent.productSpecification path is out of current build scope, so it is not a target for reconciliation edits.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-9592 unless OO reopens the topic and asks for a new current-model data element for software-specific legal manufacturer handling.
