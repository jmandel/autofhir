FHIR-5387: Audit operations usage guidance

Issue request:
FHIR-5387 was a Published FHIR-core change request from the Jan 2015 ballot, resolved Persuasive with Modification, asking for clearer criteria for when operations should be defined beyond the standard RESTful interactions. The accepted resolution directed the operations page to say that operations are used where the server actively formulates the response rather than merely returning existing information, or where the intended purpose is to cause side effects such as modification or creation of resources.

Initial application:
The issue appears to have been applied in git commit 93f0d5532413ab675c739f8f400faea58d0e324a, whose subject is "#5387: Text added on operations page" and whose SVN metadata matches Jira comment @6319. That commit added the requested active-response and side-effect language to source/operations.html. Later operations-page commits reorganized the sentence into an "Operations are appropriately used where" bullet list without removing the approved meaning.

Additional context:
The active current source page is source/operations.html, the root operations framework page linked from the RESTful API and OperationDefinition material. FHIR-28142 later clarified the same side-effects bullet for R5, changing the wording to distinguish persisted resource creation or other out-of-band state changes from simply returning a generated resource; this is a compatible refinement, not a reversal of FHIR-5387. Searches found no Zulip or Confluence discussion for FHIR-5387 or the exact guidance that would change this conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/operations.html already explains that operations are appropriate when the server actively formulates the response and when the intended purpose is side effects, including modification or creation of resources not transmitted as part of the RESTful call or other out-of-scope changes.

Recommendation:
Keep this audit commit as-is. No source follow-up is needed for FHIR-5387 unless a future work-group decision changes the operations criteria; FHIR-28142 already supplied the later clarification now present in the same paragraph.
