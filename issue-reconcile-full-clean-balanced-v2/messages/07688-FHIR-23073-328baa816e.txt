FHIR-23073: Audit reserved-word escaping resolution

Issue request:
FHIR-23073 was a Published/Persuasive with Modification FHIR-core change request for SearchParameter, raised against STU3 and applied for R5. It asked to escape the ValueSet-code search parameter path segment `contains` as `ValueSet.expansion.`contains`.code`, but the final resolution said `contains` was not the remaining problem and instead identified DomainResource dom-6 as the real keyword collision: `text.div.exists()` should be `text.`div`.exists()`.

Initial application:
No FHIR-core commit in the current branch ancestry explicitly mentions FHIR-23073. The current active DomainResource source already has dom-6 as `text.`div`.exists()`, and git history shows the escaped form present when the source was reworked/imported for the R4B/R5-era build. The current ValueSet-code search parameter has also changed since R4 through later source history; it now uses `ValueSet.expansion.repeat(contains).code | ValueSet.compose.include.concept.code`, leaving `contains` unescaped in line with the FHIR-23073 resolution.

Additional context:
source/fhir.ini actively includes DomainResource, ValueSet, and SearchParameter in the current build, so these are the authoritative source checks. Historical snapshots under tools/history/release4 still contain old unescaped `text.div.exists()` copies, but those are release-history artifacts rather than current build inputs and should not be rewritten for this reconciliation. The already-published FHIR-17249 audit is related background because it covers the FHIRPath keyword list that FHIR-23073 cites, and FHIR-49784 is a later source change explaining the current recursive ValueSet-code expression.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already contains the approved dom-6 backtick escaping, the ValueSet-code `contains` segment was not approved for escaping, and changing historical release snapshots would not correct the current specification.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed unless a future FHIRPath decision changes how `contains` is parsed in search parameter expressions or a current-build source file reintroduces unescaped `text.div.exists()`.
