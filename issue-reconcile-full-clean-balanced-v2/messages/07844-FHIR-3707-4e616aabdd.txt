FHIR-3707: Audit NutritionOrder subject rename outcome

Issue request:
FHIR-3707 was Published/Persuasive for DSTU1. It asked to rename NutritionOrder.subject to NutritionOrder.patient because, at that time, the element only allowed Patient and followed the rule that patient should be used when Patient is the only reasonable subject.

Initial application:
The request was applied in the old spreadsheet source by commit 7d67ca802e5a4a4a472dcba2a975d3e1b6b9a230, which changed NutritionOrder.subject to NutritionOrder.patient and added a committee note referencing #3707. No current source-changing commit is needed to repeat that historical application.

Additional context:
The current build has since moved beyond the DSTU1 premise. FHIR-20508 was Published/Persuasive for R5 with a resolution to add Group as a reference choice for the NutritionOrder patient reference; that related issue is already represented on the combined branch by audit commit 30eaad627cb402bead69289b889034469b9fefb8. The implementation commit 1a5062f0a41dca024be7fb527908dcec638166f8 changed NutritionOrder.patient back to NutritionOrder.subject, broadened the definition to a person or set of individuals, added Group, added a subject search parameter, and kept the legacy patient search constrained to Patient.

AutoFHIR reconciliation:
This is an empty no-change audit commit. NutritionOrder is active in source/fhir.ini, and the authoritative StructureDefinition now correctly uses NutritionOrder.subject as Reference(Patient|Group). The old NutritionOrder.patient spelling remains mapped to NutritionOrder.subject for version-diff/rename compatibility, and the patient search parameter continues to work for Patient-only matching. Renaming the current element back to patient would contradict the later Group support and the original naming rule cited by FHIR-3707.

Recommendation:
Keep this audit commit as-is. Do not change current NutritionOrder.subject for FHIR-3707; any future work should be driven by a new OO decision about group-capable NutritionOrder semantics rather than by the superseded DSTU1 patient-only premise.
