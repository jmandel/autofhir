FHIR-13613: Audit ProcessRequest submit operation

Issue request:
FHIR-13613 was a Published/Persuasive FM change request for STU3 asking core to create a $submit operation on ProcessRequest, with the input supplied directly as one request resource or a Bundle rather than wrapping it in Parameters.

Initial application:
The request was applied by historical commit 13d720ccbd ("Tracker #13613"), which added source/processrequest/$submit-request.txt, source/processrequest/$submit-response.txt, and the ProcessRequest spreadsheet Operations row defining submit plus its single in and out Resource parameters.

Additional context:
FHIR-19345 is a later Published/Persuasive FM decision for the same resource family requiring ProcessRequest and ProcessResponse to be removed and their purposes documented using Task. Current source/fhir.ini reflects that later decision: the active ProcessRequest resource, work-group, and compartment entries are commented out, ProcessRequest appears in the deleted resources list, and the retired resource note says "ProcessRequest=approved use Task." Workflow minutes from 2018 also record the desire for ProcessRequest/ProcessResponse to go away.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The dormant ProcessRequest source still contains the historically requested $submit operation, but ProcessRequest is no longer an active current-build resource; restoring or editing its operation would contradict the later removal decision rather than improve the current specification.

Recommendation:
Keep this no-change audit as-is. Do not edit the disabled ProcessRequest operation source for the current build; if a future work group decision resurrects ProcessRequest, re-evaluate the old $submit source in that new context.
