FHIR-7739: Audit MedicationRequest medication choice guidance

Issue request:
FHIR-7739 was Published/Persuasive for the DSTU1 MedicationPrescription medication element. It asked to allow MedicationPrescription.medication[x] as either an inline CodeableConcept or a Reference to Medication, with guidance that systems needing manufacturer, brand, form, packaging, and similar detail should use the full Medication resource. Its resolution says the change was made as part of another tracker and that code-vs-resource clarification would be handled with FHIR-7562.

Initial application:
No commit explicitly tagged FHIR-7739 was found. The historical application appears in commit d406f9a2c017ef95928c6bc4b4ba09a89d2d3852, which updated Pharmacy resources based on ballot resolutions, changed MedicationPrescription.medication to MedicationPrescription.medication[x], allowed CodeableConcept|Reference(Medication), and added guidance to use the Medication resource when more information is required. The later explicit guidance tracker FHIR-10389 was applied by commit 6c59909a7c012358eb432b38e2f8630e5b0923f4, updating MedicationRequest, MedicationAdministration, MedicationStatement, and MedicationDispense comments for code-vs-reference use.

Additional context:
FHIR-7562, named in the FHIR-7739 resolution, ultimately resolved Not Persuasive/No Change after the Medication.code definitions had been rewritten. FHIR-10389 later captured and applied the concrete lot/form guidance across the medication[x] elements. FHIR-25929 then changed Pharmacy choice attributes from CodeableConcept|Reference(Medication) to CodeableReference(Medication) for R5 without removing the ability to provide either coded medication identification or a Medication reference. MedicationRequest is active in source/fhir.ini, so its StructureDefinition source is in current build scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current MedicationRequest.medication element is a CodeableReference targeting Medication and its comment already says that a code should identify a specific product and that the Medication resource is recommended/required when additional details such as form, lot number, compounded, or extemporaneously prepared medication are needed.

Recommendation:
Keep this audit commit as-is. The current core source satisfies FHIR-7739 in the modern MedicationRequest/CodeableReference representation, and an editorial restatement would be redundant unless Pharmacy later asks for new wording.
