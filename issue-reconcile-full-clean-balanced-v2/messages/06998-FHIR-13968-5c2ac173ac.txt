FHIR-13968: Audit vital-sign code inclusion wording

Issue request:
FHIR-13968 was a Published/Persuasive FHIR-core Observation issue from the STU3 vital-signs profile ballot. It asked to clarify the phrase "Other additional codes are allowed" so readers understood that additional codings are allowed in Observation.code, not that the mandatory vital-sign code requirement was loosened.

Initial application:
The issue appears to have been applied by commit 3e18984e30 ("GF#13968 GF#13868 GF#13144"), which changed the then-current source/observation/observation-vitalsigns-profile-spreadsheet.xml. That spreadsheet is no longer present in the current source tree; current vital-signs source is maintained as StructureDefinition XML plus the Observation vital-signs IG narrative.

Additional context:
The current vital-signs IG is still in core build scope: source/igs.xml marks the vitalsigns IG as core, source/fhir.ini lists Observation as an active resource, and source/observation/implementationguide-Observation-vitalsigns.xml includes the vital-signs base and specific profiles. The obsolete exact phrase is absent from active source/observation files and survives only under tools/history/release3/profiles-others.xml. A contemporaneous Zulip thread about BodyTemp profile coding shows the same ambiguity and confirms the intended meaning was additional Coding repetitions/translations, not alternate Observation.code elements or a closed code list.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current profile summaries now say "The code (or codes) for the measurement obtained in Observation.code" and the vital-signs narrative explains that other codes are represented as repetitions of code.coding in Observation.code. That conveys the requested clarification without reintroducing redundant STU3 wording.

Recommendation:
Keep this audit commit as-is. Do not edit archived release history or add redundant prose to the current vital-signs pages unless a future work group decision asks for new current-build guidance about code slicing or pattern style.
