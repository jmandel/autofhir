FHIR-31743: Audit Composition section code text search

Issue request:
FHIR-31743 was Published with a Persuasive resolution for R5. It asked to add a Composition composite search parameter named section-code-text so document text can be searched within the same section identified by a section code.

Initial application:
The issue appears to have been applied together with FHIR-31880 by git commit 586441a2c8, which added Composition-section-code-text to source/composition/bundle-Composition-search-params.xml. The current source keeps code section-code-text, type composite, expression Composition.repeat(section), and components for section.code and section.text. Composition is an active current-build resource in source/fhir.ini.

Additional context:
FHIR-31880 is the companion request for the section-text component search parameter. SDWG May 2021 minutes record approval of both requests in the same quarter. The Zulip implementers thread that led to the Jira issues specifically suggested Composition.section-code-text for searching a code and text in the same section. Later commit 51941173de for FHIR-49784 updated the base expression to Composition.repeat(section), preserving the same-section composite semantics while covering nested sections recursively.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The authoritative current source already defines section-code-text as a composite over Composition.repeat(section), with component expressions section.code and section.text, so the Published Jira request is satisfied.

Recommendation:
Keep this no-change audit commit as-is. No follow-up core source work is needed for FHIR-31743 unless later search-parameter tooling requires a different representation for text components in composite parameters.
