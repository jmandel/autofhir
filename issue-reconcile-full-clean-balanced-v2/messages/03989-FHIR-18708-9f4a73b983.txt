FHIR-18708: Audit ValueSet expression guidance

Issue request:
FHIR-18708 was a Published/Persuasive STU3 vocabulary change request for ValueSet. It asked FHIR to explicitly note that FHIR ValueSet.compose does not support every VSD Syntax-based Content Expression syntax, and to provide guidance and extension support for carrying the syntax reference and expression. The recorded resolution was to add an expression extension, referring to FHIR-18706.

Initial application:
The Jira comments cite git 4907f9bcb0b710cb2837a93a20c4b23210a37249. That terminology ballot documentation commit included GF#18706 in its subject, added the ValueSet expression extension row to the then-current ValueSet extension spreadsheet, and changed ValueSet notes around VSD/compose documentation. No separate FHIR-18708-tagged source commit was found, but the cited commit and the linked FHIR-18706 resolution are the apparent application path.

Additional context:
FHIR-18706 is the same change family and asked specifically for VSD CLDSyntaxReference support. VSDP minutes from 2019 record that valueset-expression represents VSD CLDSyntaxReference and include an action item to determine how GF#18706 was resolved as an extension. Later source history moved ValueSet extension definitions out of core into the FHIR Extension Pack, while core ValueSet narrative remained active and continues to link to the extension through the extensions-location macro.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active ValueSet narrative already explains that ValueSet.compose is the FHIR CLD representation, says that when filter syntax cannot express the definition authors can use the ValueSet.valueset-expression extension, and warns that such expressions can only be evaluated by systems that understand the syntax used. The current FHIR Extension Pack defines the canonical valueset-expression extension with an Expression value, which carries the expression language, expression text, and/or reference.

Recommendation:
Keep this audit commit as a no-change decision. The current core source and Extension Pack definition satisfy the applied tracker; adding more local prose in core would duplicate existing guidance. Any future substantive change to the extension definition should be handled in the Extension Pack or broader VSD/FHIR terminology work.
