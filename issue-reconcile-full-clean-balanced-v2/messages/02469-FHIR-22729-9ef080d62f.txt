Issue request:
FHIR-22729 was a Published Patient Care change request, resolved Persuasive for R5, asking to add an example value set binding for CarePlan.activity.detail.statusReason. The requested value set was to include the existing Procedure not-performed reason, Immunization status reason, and MedicationRequest status reason value sets.

Initial application:
The Jira comment links GH#aeca750. Commit aeca750524eb7dfa7218b4679e4cedf7be4af7c1 updated the then-authoritative CarePlan spreadsheet to bind CarePlan.activity.detail.statusReason to CarePlanActivityStatusReason and added source/careplan/valueset-care-plan-activity-status-reason.xml. The later XML StructureDefinition conversion carried this forward as CarePlan.activity.plannedActivityDetail.statusReason with an example binding to ValueSet/care-plan-activity-status-reason.

Additional context:
CarePlan is active in the current build through source/fhir.ini. A later Published Patient Care decision, FHIR-39101, removed CarePlan.activity.plannedActivityDetail and all of its children and moved planned activity details to CarePlan.activity.plannedActivityReference. The current authoritative StructureDefinition has the old plannedActivityDetail block commented out, while the active CarePlan.activity.plannedActivityReference element already reflects the FHIR-39101 model. FHIR-39101 is already represented on the combined branch by 07f2600fc6e1fc3e56f25e9ab478c13e8627b1c1, and the same historical aeca750 commit's neighboring FHIR-22733 change is already audited by 3c65879050ffb01da778ebcad4b948cd218e523d.
