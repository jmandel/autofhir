FHIR-5200: Correct TEL URI citation

Issue request:
FHIR-5200 is a Published/Persuasive MnM change request from the January 2015 ballot. It asked whether ContactPoint phone/fax values should use IETF RFC 3966 tel URI syntax instead of the human-oriented E.123-style text, and the final resolution kept the base value flexible while defining a standard iso21090-TEL-address extension for a machine-friendly URI form and using it in an example.

Initial application:
The issue was applied in svn revision 4532, mirrored as git commit de9700d3959339348e2f321ebe752a066f12cf28, which added profiles/iso-21090-spreadsheet.xml and a ContactPoint example in source/datatypes-examples.html. That application preserved the non-URI base value but introduced an example paragraph that linked to rfc3966.txt while naming the syntax as RFC 3166, leaving a semantically wrong citation in the current example prose.

Additional context:
The current ContactPoint base text still explains that phone and fax values are not handled as formal URLs because legacy and clerical practices often prevent strict formatting, matching the FHIR-5200 resolution. The iso21090-TEL-address definition now lives in the FHIR Extension Pack, where it is active for ContactPoint and describes an RFC 3966 conformant URI value of type url. FHIR-27754 later corrected the same example's value type to valueUrl and is already represented on the combined branch, so this commit does not duplicate that issue.

AutoFHIR reconciliation:
Updated source/datatypes-examples.html so the ContactPoint ISO 21090 example refers to RFC 3966 syntax, matching the hyperlink, the extension definition, and the FHIR-5200 request/resolution. No extension-pack or ContactPoint base-definition edit was needed.

Recommendation:
Keep this focused source correction as-is. The core example now accurately describes the machine-friendly TEL URI extension while preserving the base ContactPoint flexibility that MnM approved; no further core follow-up is indicated for FHIR-5200.
