FHIR-34314: Audit XHTML datatype definition

Issue request:
FHIR-34314 was a Published FHIR-core change request, resolved Persuasive with Modification for R5, asking that xhtml not be left as an undefined special-purpose datatype. The resolution required PrimitiveType links on datatypes.html to point to types.html, an explicit xhtml section on narrative.html, a statement that xhtml has no intrinsic length limit, guidance that profiles can constrain length, and explanation that xhtml has no extensions while id is represented as xml:id in XML.

Initial application:
The issue was applied by git commit de45347b3f5c7bb159ea4b78ba1efce9cc982485, which moved the Narrative datatype table earlier and added an XHTML Content section to source/narrative.html with xhtml XML/JSON definition links and the no-intrinsic-length statement. A nearby existing type-page mapping in source/fhir.ini routes xhtml datatype references to narrative.html, and the current datatypes.html PrimitiveType reference points to types.html#PrimitiveType rather than datatypes.html.

Additional context:
FHIR-I minutes from 2021-11-29 record the accepted discussion and vote for FHIR-34314, including that xhtml already had generated XML/JSON definition pages and that the group considered id/extension inheritance questions. A 2022 Zulip thread clarified that the PrimitiveType part of the request was specifically about datatypes-page UML diagram/link routing. No later source or community evidence found during this reconciliation reverses or narrows the decision.
