FHIR-13675: Audit processNote.type datatype history

Issue request:
FHIR-13675 was Published/Persuasive for STU3 by FM. It asked to change ClaimResponse.processNote.type, ExplanationOfBenefit.processNote.type, and PaymentReconciliation.processNote.type from CodeableConcept to code because the NoteType binding was required.

Initial application:
The request was applied in three July 2017 Tracker #13675 commits: 4b2964d5d2 changed ClaimResponse spreadsheet source and examples, 4bef5902de changed ExplanationOfBenefit spreadsheet source and examples, and 509ee2161b changed PaymentReconciliation spreadsheet source and examples. Those commits converted processNote.type from CodeableConcept to code and changed example syntax from Coding/CodeableConcept to primitive code values.

Additional context:
The current build no longer has the premise that drove FHIR-13675. ClaimResponse and ExplanationOfBenefit were later changed by FHIR-31678, a Published/Persuasive with Modification R5 FM issue, to CodeableConcept with an extensible NoteType binding because a code was too limiting. PaymentReconciliation was later brought into the same current shape by the applied FHIR-53200 work; the combined branch already contains Issue-Reconcile-Key FHIR-53200 commit 00c8da13bf2c00f4664fbc9580b8e067a47eef75 completing the PaymentReconciliation alignment. All three resources are active in source/fhir.ini.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The active current StructureDefinition sources now consistently define all three processNote.type elements as CodeableConcept with extensible NoteType bindings, which reflects later FM decisions rather than the older STU3 required-code rule.

Recommendation:
Keep this audit commit as-is. Do not reapply the STU3 code/required shape to the current build; any future move back to a required primitive code would need a new FM decision because it would reverse FHIR-31678 and the current FHIR-53200 alignment.
