FHIR-27772: Add TestScript stopTestOnFail to ModelInfo

Issue request:
FHIR-27772 was Published/Persuasive for R5 and requested a TestScript assert control that lets a TestScript author decide whether a failed assert stops the current test execution. The approved resolution was to add the stopTestOnFail boolean as proposed.

Initial application:
The issue was initially applied by commit 21bd35379698eca851fae521b6e1fbd8ab94967f, merged by d9642c66213c47b1bf010cebf380274c6aa1adf1, which added TestScript.setup.action.assert.stopTestOnFail to the TestScript spreadsheet and examples. Commit 33b409a4b6d544598262f2f074ebb4b6dc466157 later migrated the TestScript source to StructureDefinition XML and retained the element, but the active FHIR ModelInfo Library content was not updated and still omitted the TestScript.Assert element.

Additional context:
Commit f9a44787c45071394532c7c2ee94d76f30f47387 removed TestScript, TestReport, and TestPlan as core resources and added the FHIR Testing IG as an additional IG reference. The current external Testing IG package contains TestScript.setup.action.assert.stopTestOnFail, so this reconciliation does not restore the core TestScript resource. However, source/fhir.ini still builds the Library resource, and source/library/library-fhir-model-definition-content.xml is listed as the FHIR model information file used by CQL tooling; that active core surface still exposes TestScript.Assert and therefore needs to include the published element while it continues to expose TestScript.

AutoFHIR reconciliation:
Added stopTestOnFail as a FHIR.boolean element to TestScript.Assert in source/library/library-fhir-model-definition-content.xml, matching the current external TestScript StructureDefinition element order and type. No generated TestScript resource files were restored or edited.

Recommendation:
Keep this commit as-is. If the work group later decides the core FHIR ModelInfo should no longer expose testing resources after the Testing IG move, that should be handled as a separate broader cleanup; while TestScript.Assert remains in the core ModelInfo, omitting stopTestOnFail is a stale semantic gap.
