FHIR-39069: Align ObservationDefinition qualified value model info

Issue request:
FHIR-39069 was a Published/Persuasive with Modification OO correction for R5. It reported that the ObservationDefinition Boundaries and Relationships sentence said each Observation.referenceRange should come from ObservationDefinition.qualifiedInterval even though that field no longer exists, and the approved resolution was to change the sentence to qualifiedValue.

Initial application:
The narrative sentence was previously applied by b65629ffcf5581d70dc1142a904a15858263881e in the HL7/fhir history, with the Jira comment pointing to the PR #2472 build work. The current source/observationdefinition/observationdefinition-introduction.xml already says qualifiedValue in that sentence.

Additional context:
ObservationDefinition is active in source/fhir.ini, and the current StructureDefinition defines ObservationDefinition.qualifiedValue, not ObservationDefinition.qualifiedInterval. The remaining qualifiedInterval entries in source/fhir.ini are intentional R4-to-current rename annotations, but source/library/library-fhir-model-definition-content.xml is separately published via publish.ini and still exposed an active FHIR 6.0.0 model-info surface named qualifiedInterval with the old QualifiedInterval class. FHIR-41949 later added qualifiedValue.interpretation in the authoritative StructureDefinition and is already represented on the combined branch, so this reconciliation uses the current StructureDefinition shape without publishing a duplicate FHIR-41949 decision.

AutoFHIR reconciliation:
Updated source/library/library-fhir-model-definition-content.xml so ObservationDefinition now exposes qualifiedValue using ObservationDefinition.QualifiedValue. The corrected class uses the current qualifiedValue child names and moved value-set members instead of the removed qualifiedInterval, category, gender, and top-level coded value-set model surfaces.

Recommendation:
Keep this commit. It preserves the already-applied narrative fix and closes the remaining active model-info publication surface that would otherwise still tell implementers that ObservationDefinition.qualifiedInterval exists.
