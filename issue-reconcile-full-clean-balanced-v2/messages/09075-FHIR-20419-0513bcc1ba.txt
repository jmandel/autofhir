FHIR-20419: Audit _summary self-link requirement

Issue request:
FHIR-20419 was a Published/Persuasive FHIR-core search clarification asking that search result Bundles include the self link regardless of which _summary option is used, because the self link records the search parameters actually applied by the server.

Initial application:
The issue was applied before this reconciliation in source/search.html. Jira points to HL7/fhir#1428, which included FHIR-20419 and added the self-link clarification. The local history contains duplicate same-day application commits 86fc08e2a4e8042579c108668812aa9dcc4558f3 and 5cced761f83cd4496a0f56549dae76b52efc4149 titled "Fix FHIR-20419" with the requested sentence.

Additional context:
The current search page still contains the rule in the _summary section, now marked as conformance language: the self link in the search result Bundle is important for interpretation and SHALL always be returned regardless of _summary type. FHIR-37753 later tagged conformance statements and changed the original "should" wording to a tagged SHALL without reversing the FHIR-20419 requirement. The linked Zulip discussion confirms the intended answer was that the self link should be returned for _summary=count and _summary=text. Confluence references for FHIR-20419 were not found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build source already implements the published issue in the relevant FHIR-core search page, including stronger conformance wording than the original application.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-20419 unless the work group later decides to weaken or revise the search self-link requirement.
