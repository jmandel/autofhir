FHIR-17976: Audit EOB payment confidentiality guidance

Issue request:
FHIR-17976 was a Published FHIR-core ExplanationOfBenefit change request with resolution Not Persuasive with Modification. It asked for a base EOB constraint so that, when the payee is not the subscriber, only payment.type and payment.date would be permitted to preserve payment confidentiality. The final resolution rejected a blanket base-resource constraint because EOB can also be used for reporting where payment information is required, and instead directed documentation describing how to include the restriction in an implementation guide.

Initial application:
Historical commit 89bb47c31d84c7cc3fb753e5408806226f62d395 mentioned GF#17976 in a broad EOB spreadsheet/example update. The durable current application is commit 96ee4c7ff55abe91e3c9e496f4eda7609be542ba, which explicitly mentioned #17976 and added the EOB introduction note telling profile authors that, for patient-focused EOB exchange, payment details other than date should be excluded when the payee is the provider because those details would leak business confidential information.

Additional context:
ExplanationOfBenefit is active in the current build through source/fhir.ini. The current StructureDefinition still defines payment.adjustment, payment.date, payment.amount, and payment.identifier without a payee-dependent invariant, which is consistent with the Jira modification that core EOB must continue to support reporting/payment use cases while IGs can profile patient-focused exchanges more tightly. Jira, Zulip, and Confluence searches found no later issue-specific or work-group evidence reversing this result; a later CARIN Zulip thread discussed payee/payment example completeness but did not conflict with the core confidentiality guidance.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active EOB introduction already carries the implementation-guide/profile guidance requested by the final resolution, and adding a base invariant or duplicating the same guidance elsewhere would change or overstate the approved scope.

Recommendation:
Keep this audit as-is. Future patient-focused EOB implementation guides that need the privacy rule should profile out payment details other than date when a provider payee would expose confidential payment information; reopen with Financial Management before adding a base core constraint.
