FHIR-34442: Correct List changes mode guidance

Issue request:
FHIR-34442 is Published/Persuasive with Modification for FHIR-core List. It asked to remove the lst-3 restriction that List.entry.date only be used for working lists, or otherwise permit deleted entries on working lists; the final resolution drops both lst-2 and lst-3 and adds guidance for deleted entries on change lists, working lists, and snapshot lists.

Initial application:
Commit f2d052d532 (FHIR-34442 - relax list constraints) removed lst-2 and lst-3 from source/list/structuredefinition-List.xml and added the deleted-flag guidance to source/list/list-notes.xml. The current source therefore already permits List.entry.date outside working lists and List.entry.deleted outside changes lists.

Additional context:
The May 2022 FHIR-I WGM minutes record the decision to remove lst-2 and lst-3 with a 19-0-2 motion. The March 2022 FHIR-I minutes identify FHIR-13986 and FHIR-27083 as related background: FHIR-13986 had earlier introduced the date restriction, while FHIR-27083 clarified the List/Group boundary without requiring List and Group to be merged. The List resource is active in source/fhir.ini, so source/list/list-notes.xml feeds the current build.

AutoFHIR reconciliation:
This commit corrects the added guidance in source/list/list-notes.xml from the non-existent code List.mode = "change" to the defined List.mode = "changes". This is necessary because the FHIR-34442 guidance is the normative replacement for the dropped invariants and must name the actual List.mode code.

Recommendation:
Keep this source fix. No additional source changes are needed for FHIR-34442 unless the work group later chooses to revisit the broader List.entry.deleted date/choice question noted in the May 2022 minutes.
