FHIR-17901: Align workflow encounter references

Issue request:
FHIR-17901 was Published/Persuasive for STU3 and asked the Event and Request workflow patterns to replace the broad context element with encounter as Reference(Encounter) 0..1, while representing EpisodeOfCare through a 0..* workflow extension.

Initial application:
The main application was commit 633021569c4ee210837d89828831cac8764c69bd, later merged by 6b8ca9c61f, which changed Event.context and Request.context to Event.encounter and Request.encounter and created the workflow episodeOfCare extension source. Later source history shows fd1f97ae15 corrected a Claim workflow map to Request.encounter, but 7b44f67dce reintroduced Request.context while making unrelated Claim date changes.

Additional context:
Event and Request are active logical models in source/fhir.ini, Claim is an active resource, and the workflow extension source now lives in the FHIR Extension Pack as StructureDefinition-workflow-episodeOfCare. The later FHIR-42761 no-change decision explicitly declined rolling the pattern back to EpisodeOfCare in core because the extension meets the business requirement with the right cardinality. Observation-specific FHIR-33166 only clarified Observation guidance and does not reverse the Event/Request pattern.

AutoFHIR reconciliation:
This commit corrected remaining current-source references to the removed workflow context element: Event and Request search worksheet paths now point at Event.encounter and Request.encounter, Claim.item.encounter maps to Request.encounter, and workflow warning suppressions no longer name Event.context or Request.context for current pattern checks. Inactive SupplyDelivery/Transport source and fhir.ini historical version maps were left unchanged because they are not current build corrections.

Recommendation:
Keep this source fix. It completes the FHIR-17901 reconciliation in current core while leaving the moved episode-of-care extension in the Extension Pack and preserving later work-group decisions that rejected a core rollback.
