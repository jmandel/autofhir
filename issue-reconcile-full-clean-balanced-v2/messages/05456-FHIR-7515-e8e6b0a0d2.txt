FHIR-7515: Audit medication dosage timing rename

Issue request:
FHIR-7515 was a Published Pharmacy change request, resolved Persuasive with Modification, asking to rename MedicationStatement.dosage.schedule to MedicationStatement.dosage.timing to match the Schedule-to-Timing datatype rename. The final resolution broadened the request to prescription, dispense, and statement dosage elements, changing the name to "Timing" and making the datatype Timing.

Initial application:
The rename appears to have been applied before Jira publication. Lloyd McKenzie's Jira comment says it already looked done, and the git history contains August 2015 application commits for the same change family: 84008f8cc2 renamed MedicationStatement.schedule to timing with the datatype already Timing, a2fbf41966 renamed MedicationPrescription.scheduled[x] to timing and narrowed it to Timing, and 33ed8e5b84 renamed MedicationDispense.dosageInstruction.schedule[x] to timing and narrowed it to Timing. No prior FHIR-7515-specific commit trailer existed on the combined branch.

Additional context:
The current build scope actively includes MedicationStatement, MedicationRequest, MedicationDispense, Timing, Dosage, and DosageDetails in source/fhir.ini. Later releases refactored the medication dosage model: current MedicationStatement.dosage, MedicationRequest.dosageInstruction, and MedicationDispense.dosageInstruction use DosageDetails rather than the old direct DSTU1 dosage substructure, while the active Dosage datatype still has Dosage.timing of type Timing and the active DosageDetails model carries timing semantics for dosage-course steps. Searches of the current medication source found no stale MedicationStatement/MedicationDispense/MedicationRequest schedule element names such as dosage.schedule, dosageInstruction.schedule, scheduledTiming, or schedule[x].

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source no longer contains the obsolete schedule element names targeted by FHIR-7515, and the later current model represents dosage timing through Timing/DosageDetails rather than the exact DSTU1 element path.

Recommendation:
Keep this no-change audit commit as-is. No core source follow-up is recommended for FHIR-7515 unless a future Pharmacy review wants to revisit the later DosageDetails model, which would be a separate tracker rather than completion of the 2015 schedule-to-timing rename.
