FHIR-8765: Audit extension summary rendering

Issue request:
FHIR-8765 was a Published/Persuasive FHIR-core change request asking that extension definition Summary views label the root row with the extension name instead of the generic "extension" label, for both complex and simple extensions, so users can click the meaningful extension name.

Initial application:
The issue was applied in SVN revision 14851, imported as git commit bbf3d10a30e4a5ea53d365619f9121867da4cb6a. That commit changed ProfileUtilities.generateExtensionTable so the non-full extension table uses ed.getName(), while the full structure table continues to show "extension" or "modifierExtension". The old in-repository Java renderer was later removed with the other Java implementation code, so there is no current core renderer source to update for this behavior.

Additional context:
Current core source still carries the extension page template with separate Summary and Full Structure calls, using <%extension-table false%> for Summary and <%extension-table true%> for Full Structure. Published R4 extension pages generated after the application show the intended distinction: the Summary table root row uses names such as birthPlace, wg, and question, while the Full Structure table still uses extension. Many current extension definitions are also represented in the separate FHIR Extensions Pack and rendered by external IG Publisher machinery, which is outside this core checkout and was not changed here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The historical core application is present, the current core source has no remaining FHIR-8765 renderer logic to correct, and adding prose or changing extension StructureDefinition XML would not address the renderer behavior requested by the Jira.

Recommendation:
Keep this audit commit as-is for the core reconciliation. If the work group wants current FHIR Extensions Pack or IG Publisher pages to reproduce the old core Summary-vs-Full Structure labeling, track that separately against the extension-pack/publisher pipeline rather than changing FHIR core source.
