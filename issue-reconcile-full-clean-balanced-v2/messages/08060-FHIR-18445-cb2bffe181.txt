FHIR-18445: Audit signature scope canonicalization

Issue request:
FHIR-18445 was Published with resolution Persuasive. It asked how the scope of a digital signature is determined, especially for Provenance targets, Bundles, extensions, and multiple signed fragments, and the approved resolution required XML and JSON canonicalization wording that explicitly handled each XML instance or fragment in the signed collection and each JSON signed set of fragments.

Initial application:
The issue was applied in git commit 1e7f05f8b99b616f6c03888a4e1ee59b76d36c25, which edited source/xml.html and source/json.html to add the approved collection/fragment canonicalization wording. Commit dcf53a8af6d730f886918f45af2510e990a986eb later rewrote the signatures material, moved the canonicalization details into source/signatures.html, and left source/xml.html and source/json.html pointing to that active page.

Additional context:
FHIR-I WGM and Zulip minutes for 2020-02-07 record the same 6-0-0 decision and explain that a signature blob contains a manifest of what was signed, so validation depends on the signature contents and the signed set ordering. Later signature-page work refined the design for R6: source/signatures.html now defines JSON, JSON-XML, and XML canonicalization methods; states how multiple Provenance targets are ordered for JSON and XML signatures; defines variants that let systems choose what parts of resources matter for the workflow; and, through the already-published FHIR-52810 reconciliation commit, identifies embedded Bundle signatures with the root Bundle fragment '#/' rather than mutable Bundle ids.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current active source already satisfies the FHIR-18445 decision: source/signatures.html contains the current normative canonicalization and scope guidance, while source/xml.html and source/json.html direct readers there. Adding the old wording back to the representation pages would duplicate and potentially conflict with the later consolidated signature guidance.

Recommendation:
Keep this no-change audit commit as-is. Future changes to digital-signature scope or canonicalization should be handled under newer signature-specific trackers rather than reopening FHIR-18445's already-applied R5 clarification.
