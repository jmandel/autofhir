FHIR-40563: Audit string and markdown regex correction

Issue request:
FHIR-40563 was a Published FHIR-core datatypes issue resolved Persuasive with Modification for R5. It reported that the R5 string regex `[ \r\n\t\S]+` rejected a string made only of non-ASCII Unicode whitespace and resolved to simplify the regex and use the same regex for markdown.

Initial application:
No commit explicitly mentioning FHIR-40563 was found. The issue appears to have been applied implicitly by commit b4c3af0a97b6ef5d8db2c49745c9e98ff7ab0341, which replaced the active string regex `[ \r\n\t\S]+` and markdown regex `\s*(\S|\s)*` in `source/datatypes/primitives.xml` with the same `^[\s\S]+$` expression.

Additional context:
The active datatype source is in build scope through `source/fhir.ini` type-page routing to `datatypes`. FHIR-I minutes record the same-call persuasive-with-modification revote. A Zulip follow-up from Grahame Grieve explains that Java did not treat `.+` equivalently for the Unicode whitespace sample while `[\s\S]+` did, supporting the current implementation as the safer expression of the resolution's intended non-empty string/markdown rule. The previous `[ \r\n\t\S]+` regex remains only in historical release snapshots under `tools/history`, not in current active source.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active primitive datatype source already uses the same regex for string and markdown, accepts the all-whitespace Unicode sample that triggered the issue, and no current build-scoped source still uses the rejected R5 regex.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-40563 unless the work group later chooses a different cross-language regex notation for primitive strings.
