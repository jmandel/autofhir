FHIR-14080: Audit ImagingManifest removal

Issue request:
FHIR-14080 is a Published/Persuasive with Modification FHIR-core Imaging Integration issue asking to remove the ImagingManifest resource because the primary MHD-I use case no longer used it and broader imaging object selection should use DICOM Key Object Selection rather than a FHIR resource.

Initial application:
The issue was applied by d21acd48143d1cbe35a35616864c97839b13a361, a 2017 imaging update commit that removed imagingmanifest=ImagingManifest from source/fhir.ini's active [resources] list, added imagingmanifest to [removed-resources], and removed the linked ImagingManifest entry from source/history.html's active resource list.

Additional context:
Current source/fhir.ini still excludes ImagingManifest from the active [resources] list while retaining it in [removed-resources]. Current history.html explicitly lists ImagingManifest as a deleted/removed resource. The tracked source/imagingmanifest files and fhir-old-types/resource-name-tracker references are historical/out-of-build compatibility material, and current source has no active source/imagingmanifest/structuredefinition-ImagingManifest.xml. A later Published issue, FHIR-17183, introduced ImagingSelection for R5 as a separate imaging selection capability without reversing the ImagingManifest removal.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped source already reflects the requested removal: ImagingManifest is not an active resource, is documented as removed, and the remaining references are historical records rather than active resource definitions.

Recommendation:
Keep this audit commit as-is. Do not delete historical source residue or old-type/history records as part of FHIR-14080 unless the build tooling owners separately decide to purge out-of-build legacy source folders.
