FHIR-33385: Audit operation resource-body query parameters

Issue request:
FHIR-33385 was Published/Persuasive with Modification for the FHIR-core Operations page. It reported that the Operation Request text allowed POSTing the single Resource input as the request body only with "no parameters on the url", while the $validate examples used a resource body plus URL/query parameters, and the approved resolution was to allow additional simple URL/query parameters.

Initial application:
Commit f142c025b4ce2f551ca9376d48b3dfa12287d9d4 changed source/operations.html to remove the "no parameters on the url" restriction, allow POST with the input resource as the request body and additional parameters as query parameters, and require servers to support that invocation form.

Additional context:
The current source no longer says "simple parameters" because the later Applied FHIR-41220 reconciliation on the combined branch replaced that undefined phrase in the same paragraph with parameters that have associated search types. FHIR-37983 later repeated the validate-operation query-parameter concern but recorded that this first point was dealt with by the existing tracker. Zulip and FHIR-I minutes support the original problem statement and vote, and no community evidence found a contrary current rule.

AutoFHIR reconciliation:
This empty audit commit makes no source change because source/operations.html, an active built page listed in source/hierarchy.xml, already says that when an operation has exactly one FHIR Resource input and the other submitted parameters have associated search types, the client may POST the resource as the request body with additional query parameters. That preserves the FHIR-33385 behavior after the later FHIR-41220 wording refinement.

Recommendation:
Keep this audit commit as-is. No further core source change is needed for FHIR-33385; future work, if any, should be handled through the later operations-parameter issues rather than reverting to the now-removed "simple parameters" wording.
