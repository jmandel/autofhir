FHIR-3535: Audit ValueSet expansion code version element

Issue request:
FHIR-3535 was Published/Persuasive for DSTU1. It asked to add an optional version field to ValueSet.expansion.contains so expansions can carry the code system version when concept identifiers may be reused or concept permanence is not assured.

Initial application:
The issue was applied on 2014-09-29 in SVN revision 2923 / git-svn commit a6261c4a6c58924f758c3785171a257c9ee917cf, which added ValueSet.expansion.contains.version as a 0..1 string to the ValueSet spreadsheet source with guidance limiting use to code systems without concept permanence.

Additional context:
ValueSet is an active current-build resource in source/fhir.ini, and the current StructureDefinition source retains ValueSet.expansion.contains.version as a 0..1 string. Later related decisions refined the wording without reversing the DSTU1 addition: FHIR-13810 audited broader expansion version guidance as conditional/no-change, and FHIR-14688 fixed only the short description while preserving the optional cardinality and detailed definition.

AutoFHIR reconciliation:
No source change was made. The current active source already contains the requested optional element, with a definition explaining that the version SHOULD be exchanged when code meaning is not guaranteed to be consistent across versions.

Recommendation:
Keep this empty audit commit. FHIR-3535 is already correctly represented in current core source, and additional edits would either duplicate existing guidance or conflict with later decisions that keep per-code expansion version reporting optional.
