FHIR-13196: Align ActivityDefinition mapping targets

Issue request:
FHIR-13196 was Published/Persuasive with Modification for STU3. It asked to clarify the unclear boundary between ProcedureRequest and ReferralRequest, with the accepted direction to merge the resources because no clear boundary was identified and to retain/support categorization and transfer-of-care feedback.

Initial application:
The issue was substantially applied in the historical source: git 463cb5b344 removed ReferralRequest as an active resource and merged its content into ProcedureRequest with an STU note, git 6dc6ae273f added temporary mapping support, and git 06bd9f6ffe later renamed the merged resource to ServiceRequest under the same change family. Current fhir.ini keeps ServiceRequest, Appointment, and ActivityDefinition active and records ProcedureRequest/ReferralRequest as retired or merged.

Additional context:
FHIR-13867 finalized the post-merge name ServiceRequest and explains why wording should use the service-oriented name. FHIR-13195 is the Appointment companion issue and current Appointment.basedOn already references ServiceRequest. Current ServiceRequest already carries referral/transfer-of-care aliases and ServiceRequest.category guidance, but the active ActivityDefinition mapping notes and companion .fhirmap snippets still declared retired ReferralRequest or ProcedureRequest targets in snippets for current request resources.

AutoFHIR reconciliation:
This commit updates the active ActivityDefinition mapping narrative and companion mapping snippets so each `input tgt` declaration uses the current target StructureDefinition named by that snippet, including ServiceRequest rather than retired ReferralRequest/ProcedureRequest. It leaves ServiceRequest and Appointment semantics unchanged because the merge and Appointment.basedOn behavior are already present in current source.

Recommendation:
Keep this source fix. It removes stale retired-resource names from active ActivityDefinition mapping examples while preserving the accepted ServiceRequest merge; future audits of FHIR-13867 can cite this as supporting evidence rather than needing a separate core edit for the same stale snippets.
