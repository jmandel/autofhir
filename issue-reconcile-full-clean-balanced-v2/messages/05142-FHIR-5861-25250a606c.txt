FHIR-5861: Align QUICK medication dosage timing

Issue request:
FHIR-5861 is a Published/Persuasive with Modification Pharmacy issue from the DSTU1 ballot. It reported that MedicationPrescription.dosageInstruction.scheduled[x] and MedicationDispense.dosageInstruction.schedule[x] had the same meaning but inconsistent names; the final resolution was to change prescription, dispense, and statement dosage schedule elements to timing and make them datatype Timing.

Initial application:
The Jira comment says this would be resolved as part of FHIR-8180. Historical #8180 commits a2fbf41966, 33ed8e5b84, and 102f3de87b applied the change to the DSTU-era MedicationPrescription, MedicationDispense, and MedicationStatement source spreadsheets/examples by renaming the schedule/scheduled elements to timing and reducing the prescription/dispense choice types to Timing. Later refactoring migrated MedicationPrescription to MedicationRequest and moved dosage timing into the shared Dosage/DosageDetails model; the current active medication StructureDefinitions no longer expose the old scheduled[x] or schedule[x] dosage paths.

Additional context:
source/fhir.ini lists MedicationDispense, MedicationRequest, MedicationStatement, and Library as active build resources, while documenting that MedicationPrescription became MedicationRequest. The active medication resource source now points dosageInstruction/dosage to DosageDetails, and the current Dosage datatype defines Dosage.timing as Timing. The build-visible QUICK model-definition Library content, however, still exposed the stale DSTU medication dosage names: QUICK.MedicationDispense.Dosage had scheduleDateTime/schedulePeriod/scheduleTiming, QUICK.MedicationStatement.Dosage had schedule, and QUICK.MedicationPrescription.Dosage had scheduledDateTime/scheduledPeriod/scheduledTiming. No relevant Zulip or Confluence evidence was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:
Changed source/library/library-quick-model-definition-content.xml so the three QUICK medication dosage classes each expose a single timing element of type QUICK.Timing. Left the active medication resource definitions, the current Dosage datatype, the FHIR model-definition Library content, and unrelated QUICK schedule/scheduled elements unchanged because they already reflect current source or are outside the medication dosage issue scope.

Recommendation:
Keep this source fix. If the QUICK model-definition example is regenerated, ensure medication dosage schedule metadata continues to follow the historical FHIR-5861/FHIR-8180 resolution by using timing with datatype Timing.
