FHIR-5560: Audit operation in/out rendering

Issue request:
FHIR-5560 is a Published/Persuasive FHIR-I DSTU1 change request asking OperationDefinition rendering to be clearer by separating input and output parameters instead of showing one parameters table with an in/out use column.

Initial application:
The Jira comments record "svn revision 4011". Local git history maps that to commit 31ff840c55ce318c04db44175b92d0a186397d2c, "#5560 - split operation parameter list into 2 tables", which changed the then-core PageProcessor operation-page renderer to emit distinct "In Parameters:" and "Out Parameters:" sections and to omit the Use column for those operation documentation tables.

Additional context:
OperationDefinition and Patient are active current-build resources in source/fhir.ini, and Patient's active operation list references OperationDefinition/Patient-match. The current CI build of the implementer-facing operation page patient-operation-match.html renders the Patient $match parameters with separate In Parameters and Out Parameters sections, matching the applied SVN change's behavior. The generated formal OperationDefinition instance page operation-patient-match.html still uses the generic generated resource narrative table with a Use column, but it explicitly points readers back to the operation documentation page; the renderer source that would control that generic narrative is no longer present in this core checkout.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current FHIR core source and built operation documentation already preserve the FHIR-5560 intent for operation documentation. Editing OperationDefinition XML examples would not change the renderer behavior, and the old PageProcessor renderer source is not part of the current core source tree.

Recommendation:
Keep this audit as-is. If the work group wants the generic generated OperationDefinition instance narrative to also split parameter sections, that should be handled as a separate publisher-tooling follow-up rather than a FHIR core source correction for FHIR-5560.
