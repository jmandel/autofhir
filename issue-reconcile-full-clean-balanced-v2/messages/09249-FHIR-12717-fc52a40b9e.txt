FHIR-12717: Audit TestReport status/result split

Issue request:
FHIR-12717 was a Published/Persuasive FHIR-core change request from the FHIR-I work group asking to resolve the TestReport build warning that every resource needs an entered-in-error status. The Jira resolution records SVN 10900 renaming TestReport.status to TestReport.result, then SVN 10912 re-adding TestReport.status with completed, in-progress, waiting, stopped, and entered-in-error values and updating the example.

Initial application:
The issue was applied in git by f8ac640bcff2d110bf45e55e16ac7b0827c19137 for SVN 10900, which renamed TestReport.status to TestReport.result in the spreadsheet and example, and by 1684c2f3fda22aa108d076d930361a72fac58901 for SVN 10912, which re-added TestReport.status, added the report-status-codes binding, and changed the example to status=completed/result=pass. The last core TestReport StructureDefinition before testing resources were removed retained TestReport.status as a required modifier code bound to completed | in-progress | waiting | stopped | entered-in-error, and TestReport.result as the separate pass | fail | pending result.

Additional context:
Current core no longer has active source/testreport resource definitions. source/fhir.ini points to the HL7 FHIR testing IG in [additional-ig-list], and testreport is absent from the active [resources] list. The current external testing IG StructureDefinition/TestReport still has the issue's intended split: TestReport.status is required, includes entered-in-error, and is a modifier status; TestReport.result is required and carries pass | fail | pending. A related TestReport.result modifier-status audit for FHIR-13069 is already represented on the combined branch and independently confirms the current TestReport ownership move.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The requested fix was applied historically, persisted in the last core TestReport definition, and remains correct in the current external authoritative TestReport definition; the current core checkout has no active TestReport source file to edit for this issue.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-12717 unless TestReport is brought back into the core build or the external testing IG later loses either the required entered-in-error status or the separate result element.
