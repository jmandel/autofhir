FHIR-33220: Audit search self-link GET guidance

Issue request:
FHIR-33220 was Published with a Persuasive with Modification resolution for R5. It asked how Bundle.link[relation='self'] should represent a search invoked through POST /_search with form-encoded body parameters, and the approved resolution required the self link to always be expressed as a GET-style search URL using [base](/[resource])?[params], not [base](/[resource])/_search?[params], even when that GET URL is not itself supported or resolvable.

Initial application:
The current source does not contain a Jira-keyed implementation commit for FHIR-33220, but the search page was rewritten immediately after the January 2022 vote. Commit 36e9fd596f19 added the self-link section with the rule that self links SHALL be expressed as a GET-based search with parameters in the query string and may be non-resolvable when GET search is unsupported. Commit 2a58db6fee40 generalized that to an HTTP GET-based search valid for equivalent searches regardless of HTTP GET, HTTP POST, messaging, etc. Later edits such as a3766ac36c6 wrapped the normative statements in conformance markup without changing the seed rule.

Additional context:
FHIR-31943 and FHIR-31944 were the closely related POST-search issues cited by the FHIR-33220 resolution. They are already represented on the combined branch, so this commit does not duplicate decisions for them. The current search source also says all relevant paging links SHALL be expressed as GET requests, while the HTTP page clarifies POST-search parameter handling and self-link reflection for ignored POST URL parameters. The Zulip thread that led to FHIR-33220 records the same interpretation: the self link is GET-shaped regardless of how search was invoked, with separate discussion about paging links. FHIR-I January 2022 minutes record FHIR-33220 as partially duplicative of FHIR-31943/FHIR-31944 and approved Persuasive with Mod.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is made because source/search.html already conveys the required rule: self links SHALL be HTTP GET-based with relevant parameters in query parameters, the same self link is valid for equivalent GET/POST/messaging searches, and links may be non-resolvable on servers that do not support GET search.

Recommendation:
Keep this audit commit as-is. Future work should avoid restating this rule elsewhere unless a concrete inconsistency appears; related POST-search mechanics are already covered by existing FHIR-31943 and FHIR-31944 reconciliation commits and current HTTP/search source.
