FHIR-47307: Audit directory access control outside core

Issue request:
FHIR-47307 was an Applied/Persuasive with Modification Security work group R6 change request. It said Permission and Consent did not address non-patient access-control use cases such as directory access, and did not cover resource element-level access control.

Initial application:
No git commit explicitly mentions FHIR-47307. The relevant Permission work was already present or applied through the same Security WG Permission example family: the R6 ballot Permission page had SANER and VhDir examples, commit 9befcacddd1d4d69a926fe60c723c90333e3601a added a directory-admin Permission example, and commit 22d828960244ffa5a3d96df71fe1e3e30e410406 added simple-directory, sensitive-directory, and residual Bundle Permission examples to the Permission examples list.

Additional context:
FHIR-23072 is the tightly related applied issue for a patient-agnostic directory/authorization example; its comments record that Security changed the target from Consent to Permission, and its final resolution is the same example set cited for FHIR-47307. FHIR-49908 later clarified Permission's scope to include non-patient use cases, organizational directories, residual policies, base policies for Consent, and Consent provisions encoded in Permission.rule; it already has a separate external-repo audit on the combined branch. After those applications, commit 0e2a8a7f839d5e1a43787523daccf07d958362f3 removed Permission from the core build and changed the Security module to link Permission to the HL7 Data Access Policies IG. Current Data Access Policies source carries the directory and element-level Permission examples, including HDIRECT/HSYSADMIN directory rules and LOCIS element-level sensitivity limits.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. Reintroducing source/permission or adding duplicate Consent prose would be out of current core build scope and would conflict with the later Permission removal. The current home for the requested non-patient and element-level access-control examples is the Data Access Policies IG, which already contains the relevant Permission content.

Recommendation:
Keep this external-repo audit as-is for core reconciliation. If future reviewers need to change these examples or the Permission/Consent relationship, make the Permission example changes in HL7/data-access-policies, and make any Consent change only through a new final work-group decision that accounts for Permission no longer being a core resource.
