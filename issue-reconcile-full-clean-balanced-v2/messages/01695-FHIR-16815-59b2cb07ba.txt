FHIR-16815: Audit Measure CQL and ELM support note

Issue request:
FHIR-16815 was a Published/Persuasive with Modification CQI change request against the STU3 Measure resource. The ballot comment asked whether ELM was no longer supported because the Measure boundaries text referred only to CQL expressions; the approved resolution said ELM is supported, implementations would typically distribute both CQL and ELM, and documentation should note this.

Initial application:
The Jira comment records SVN 14854, and git history maps that to 54b8a14eef22487d912e0ad991ffc0fb28357d6e, "GF#16815: Clarify use of CQL/ELM in Measure". That commit changed source/measure/measure-introduction.xml from "references CQL expressions" to a neutral expression reference and added that expressions are typically provided using a Library resource containing CQL or ELM expressions.

Additional context:
Measure remains an active resource in source/fhir.ini and is approved in the current build. Later Measure introduction refactors preserved the FHIR-16815 substance at source/measure/measure-introduction.xml, and current Clinical Reasoning expression guidance continues to document CQL expression media types and Library-based expression use. Searches found no substantive Zulip or Confluence discussion contradicting the Jira/source outcome; direct Zulip key search only found the bot tracker notification. A broad Jira query surfaced FHIR-35921, but that is a separate Resolved - No Change CDS CapabilityStatement/CQL versioning issue and does not require a Measure source change here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active Measure introduction already states that Measure criteria expressions are provided through Library resources containing CQL or ELM expressions, which resolves the ambiguity that prompted the issue and preserves the approved 2018 application.

Recommendation:
Keep this audit commit as-is. No current FHIR-core source edit is needed for FHIR-16815 unless the CQI work group wants new, broader guidance about packaging both CQL source and translated ELM; that would be a new documentation decision rather than completion of this published STU3 issue.
