FHIR-5454: Audit Device UDI realm guidance

Issue request:
FHIR-5454 was a Published/Persuasive OO change request from the January 2015 DSTU1 ballot. It asked whether Device UDI was US-realm-specific and requested text explaining why a UDI-related element belongs in core if UDI is not universal.

Initial application:
No source commit found in current history explicitly names FHIR-5454. The Jira resolution and comments say the ballot comment was merged with FHIR-5505, and commit 85cad2a017a228c70b358dab887c56b5bfccb18e pre-applied FHIR-5505 with related Device UDI ballot comments before the 2015-03-26 OO block vote by changing Device notes away from GUDID-only wording toward jurisdictional/local repository wording. Commit 966df8c99a9ec454013169646fe4862b168b0b03 later rewrote the active Device UDI section around IMDRF, FDA as a US example, other jurisdictions, DI/PI components, and local repositories.

Additional context:
FHIR-5505 is already represented on the combined branch by commit d7cca4e1f0b5ea99f3986a1eaed82953e17edf57, which audits the merged global-vs-US UDI repository wording. Device is active in the current build through source/fhir.ini. The current Device introduction says UDI is documented where appropriate according to local jurisdictions, the UDI notes cite the IMDRF base specification and say other jurisdictions may produce similar implementation guides, and the Device.udiCarrier definition allows multiple UDIs when sold in multiple jurisdictions. A current-source search did not find the old US-only/GUDID-only consistency rule in authoritative Device source.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active core source already explains that UDI is a global/local-jurisdiction concept rather than only a US/FDA concept, and the merged FHIR-5505 audit on the combined branch covers the source application trail that satisfied FHIR-5454.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-5454; future UDI work should be handled through current Device/DeviceDefinition UDI issues rather than re-opening this merged DSTU1 ballot comment.
