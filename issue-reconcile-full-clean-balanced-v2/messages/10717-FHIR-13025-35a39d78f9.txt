FHIR-13025: Audit Condition relapse code application

Issue request:
FHIR-13025 was a Published/Persuasive Patient Care change request for DSTU2 asking to add relapse to the Condition.clinicalStatus code set and to make both recurrence and relapse children of active, with recurrence clarified as reoccurrence/repeating of a previously resolved condition and relapse as return after improvement or remission.

Initial application:
The request was applied in git commit 8da21fd1e42462d6253f4ce91b89c267bb415801, which added relapse under active, replaced the previous recurrence definition, and updated the Condition.clinicalStatus short display in the then-current Condition spreadsheet. The same historical commit also included separate related Condition changes, including FHIR-13026.

Additional context:
The current build scope includes Condition through source/fhir.ini, and current Condition.clinicalStatus binds to http://hl7.org/fhir/ValueSet/condition-clinical. That value set now includes all codes from http://terminology.hl7.org/CodeSystem/condition-clinical after the UTG/THO terminology move, and the current local THO package has active children recurrence and relapse with later wording from FHIR-26464. Zulip discussion in April 2017 confirms Patient Care had approved GF#13025 for recurrence and relapse as children of active. No Confluence references or conflicting direct community evidence for FHIR-13025 were found.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The authoritative current core source points to the active Condition clinical value set, the Condition resource summary includes relapse, and the referenced terminology code system already contains relapse and recurrence under active with definitions consistent with the original request as refined by later approved wording.

Recommendation:
Keep this no-change audit commit. No FHIR core source edit is needed for FHIR-13025; future terminology wording changes should be handled through the terminology source of truth rather than duplicating code definitions in core.
