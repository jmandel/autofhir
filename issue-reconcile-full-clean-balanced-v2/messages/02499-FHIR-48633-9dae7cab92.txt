FHIR-48633: Audit SampledData search indexing reconciliation

Issue request:
FHIR-48633 was an Applied/Persuasive Orders and Observations change request for R6. It reported that the search page said SampledData is not used in search while Observation quantity search parameters still described and indexed SampledData bounds; the adopted resolution was to drop SampledData from Observation combo-value-quantity, component-value-quantity, and value-quantity descriptions and FHIRPath expressions.

Initial application:
The current source already contains the required application. Commit 4628e558178cb6196743b3cafab9cb255533da6e, although not Jira-tagged, changed source/observation/bundle-Observation-search-params.xml to remove SampledData from the three affected Observation quantity search parameter descriptions and expressions.

Additional context:
Observation is an active current-build resource in source/fhir.ini, and source/search.html still states that SampledData is not used in search. Confluence minutes from FHIR-I and OO record the rationale that core has no SampledData search type and should not allow SampledData in search FHIRPath. Older Zulip discussion confirms the prior inconsistency had been known, but no discovered later decision conflicts with the R6 removal.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the active Observation search parameter source already implements the Jira resolution and is consistent with the search page's SampledData matrix entry.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed unless a future work group defines a dedicated SampledData search type and reopens how Observation SampledData values should be indexed.
