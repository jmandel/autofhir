FHIR-20470: Audit SearchParameter declarations

Issue request:
FHIR-20470 was a Published/Persuasive FHIR-I change request raised against STU3/R4 SearchParameter instances. It asked for the R4 technical-correction behavior of removing automatically declared AND, OR, modifier, and comparator capabilities from published core SearchParameter instances so those base definitions could remain usable for derived/constrained SearchParameters, while leaving R5 methodology for later work.

Initial application:
The issue was applied in HL7/fhir by commit 50c62d61d20d, titled "GF#20470 - remove And/or/modifier from generated search parameters." That commit removed the generator's default multipleAnd/multipleOr settings and commented out automatic modifier population for generated SearchParameters. Current source no longer shows broad automatic comparator or modifier declarations in built search-parameter bundles.

Additional context:
The linked Zulip thread and FHIR-I 2019-02-25 minutes show the concern was the all-or-nothing R4 publication of every possible capability, not a permanent ban on any SearchParameter declaring multiple behavior. FHIR-20471 and FHIR-56196 later approved using capabilitystatement-expectation on SearchParameter.multipleAnd, multipleOr, comparator, modifier, and chain for implementation-community expectations. FHIR-48481 later added derivation guidance that explicitly distinguishes undeclared base behavior from declared base values. Current core has 147 active search-parameter bundle files, with multipleOr/multipleAnd declarations only in Appointment, DeviceAlert, ImagingStudy, and ImagingSelection bundles, and no comparator, modifier, or chain declarations; the remaining explicit multiple declarations trace to later resource-specific decisions such as FHIR-41397 and FHIR-47526.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already reflects the FHIR-20470 correction by not auto-populating every SearchParameter with AND/OR/modifier/comparator capabilities. Removing the few later explicit multipleAnd/multipleOr declarations would overrule separate, later work-group decisions rather than finish FHIR-20470.

Recommendation:
Keep this no-change audit commit as-is. Do not use FHIR-20470 to remove current explicit SearchParameter multipleAnd/multipleOr declarations; review those only under their own later resource-specific Jira issues if they are independently suspected to be wrong.
