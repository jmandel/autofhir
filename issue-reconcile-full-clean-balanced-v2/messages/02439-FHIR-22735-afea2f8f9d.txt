FHIR-22735: Audit AdverseEvent event binding

Issue request:
FHIR-22735 was Published/Persuasive for STU3 AdverseEvent QA. It asked to change the AdverseEvent.event binding from the duplicate AdverseEvent Type value set to http://hl7.org/fhir/ValueSet/clinical-findings and was marked applied for R5.

Initial application:
The Jira comment points to commit 19edc88a0ded155ed3e803b73666a87dc384f4bb. That commit changed the then-authoritative source/adverseevent/adverseevent-spreadsheet.xml binding row for AdverseEvent.event from valueset-adverse-event-type to http://hl7.org/fhir/ValueSet/clinical-findings and tagged the row GF#22735.

Additional context:
A later Published/Persuasive with Modification Patient Care issue, FHIR-22746, intentionally refined the same AdverseEvent.event element: it renamed the element to AdverseEvent.code, updated the short/definition, and narrowed/restored the event-code binding to the AdverseEvent Type value set containing fall plus serious-reportable-event descendants. Commit e07c2ff1ac898dde0686f31a089dd8fb9bbfb14e implemented that later decision by replacing the clinical-findings binding with valueset-adverse-event-type. The current build-scoped XML source preserves that later state: source/fhir.ini lists adverseevent as an active resource, AdverseEvent.code is bound to http://hl7.org/fhir/ValueSet/adverse-event-type, and clinical-findings is now used on AdverseEvent.resultingEffect for the subject impact. FHIR-13312 and a later Zulip thread both support keeping the event/code concept distinct from the resulting harm/effect. FHIR-22746 is already represented on the combined branch, so this commit does not duplicate that related issue.

AutoFHIR reconciliation:
This empty audit commit makes no source change. Reapplying FHIR-22735 literally to the current AdverseEvent.code element would undo the later FHIR-22746 work-group decision and make the current source less correct.

Recommendation:
Keep this no-change audit commit as-is. No follow-up is needed for FHIR-22735 unless Patient Care reopens the AdverseEvent.code value-set scope in a new issue.
