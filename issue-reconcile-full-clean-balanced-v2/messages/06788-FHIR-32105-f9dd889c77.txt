FHIR-32105: Audit fhir-type valueUrl profile instances

Issue request:
FHIR-32105 was Published/Persuasive for R4B/R5. It reported that structuredefinition-fhir-type extension instances in profiles-resources.xml, profiles-types.xml, and profiles-others.xml used valueUri even though the extension definition's value[x] type was url. The final resolution reversed an initial proposal to change the extension to uri and instead kept the long-standing url shape, requiring the profile instances to use valueUrl.

Initial application:
No source commit explicitly tagged FHIR-32105 was found in current history. The retained R4B/R5 profile history artifacts now show the requested applied state: every structuredefinition-fhir-type instance in tools/history/release4b and tools/history/release5 profile XML files uses valueUrl, with zero matching valueUri instances. The likely application was through release/build regeneration rather than a tracker-tagged source edit; later history commits cdc3309868 and ca6943e1dc added those retained artifacts already in the corrected form.

Additional context:
The extension definition itself now lives in the FHIR Extension Pack, where StructureDefinition-structuredefinition-fhir-type.xml constrains Extension.value[x] to code url. Related Published issues FHIR-31733 and FHIR-33161 both point back to FHIR-32105/other trackers for the valueUrl/valueUri part, and FHIR-34449 was closed as a duplicate after a Zulip discussion confirmed the final FHIR-32105 resolution text was the intended one. FHIR-I May 2021 minutes record the initial uri-vs-url motion, the reopen, and the final decision not to break tooling by changing the extension value type.

AutoFHIR reconciliation:
This empty audit commit makes no source change. Current tracked core XML contains 3255 structuredefinition-fhir-type instances using valueUrl and none using valueUri, and the R4B/R5 profile artifacts named by the issue are already corrected.

Recommendation:
Keep this no-change audit as-is. Do not rewrite the extension definition to uri or edit the retained profile artifacts unless future WG action deliberately changes the long-standing url value type.
