FHIR-17251: Audit history Bundle fullUrl guidance

Issue request:
FHIR-17251 was a Published/Not Persuasive with Modification FHIR-I change request raised against STU3 and applied for STU3. The reporter asked what fullUrl values should be used in history Bundles because bdl-8 prohibited version-specific fullUrls while unversioned fullUrls appeared to create duplicates.

Initial application:
No git commit was found that explicitly mentions FHIR-17251. The issue was part of the 2018-07-09 FHIR-I block vote, and nearby history shows the relevant application path: GF#17085 changed the Bundle uniqueness narrative to allow multiple versions of the same resource in a Bundle, and later FHIR-18284 corrected bdl-7 for history delete entries. The bdl-8 restriction itself remained in source.

Additional context:
The Jira resolution phrase "revoke the restriction all together" is ambiguous by itself. A later Zulip clarification from Grahame Grieve explained that the misleading comment referred to revoking the premise that non-version logical ids would necessarily be invalid duplicates, not to dropping bdl-8. FHIR-16518, resolved the same day, explicitly declined to remove or rationalize the ban on version-specific Bundle.entry.fullUrl values. Current source keeps bdl-8, while Bundle notes and bdl-7 now allow multiple versions using the same version-independent fullUrl when meta.versionId differs. Bundle is an active current-build resource in source/fhir.ini, and related bdl-7/fullUrl issues FHIR-18284, FHIR-31986, and FHIR-43106 are already represented on the combined branch.

AutoFHIR reconciliation:
This empty audit commit makes no source change. Current source already gives the necessary current answer for history Bundles: fullUrl remains version-independent, duplicate fullUrls are not inherently prohibited when they refer to different resource versions, and version-specific resolution is handled through resource.meta.versionId rather than by putting /_history/ in Bundle.entry.fullUrl.

Recommendation:
Keep this audit commit as-is. Do not remove bdl-8 for FHIR-17251; that would conflict with the clarified 2018 discussion, FHIR-16518, and later bdl-7 decisions. Any future desire to allow version-specific Bundle.entry.fullUrl values should be raised as a new FHIR-I change request because it would change current conformance behavior.
