FHIR-31908: Loosen Consent actor role binding

Issue request:
FHIR-31908 was Published with resolution Persuasive with Modification for R5. It asked to change the Consent consent-verification and actor-role extensible value-set bindings to Example, while deferring security labels to a separate issue.

Initial application:
Commit bcce19bae5, which explicitly listed FHIR-31908, changed Consent.verification.type from extensible to example but did not change Consent.provision.actor.role. Earlier Consent work in commit 632f4b8497 changed Consent.provision.actor.role to 0..1 and moved it to ParticipationRoleType, but left the binding strength as extensible.

Additional context:
The Consent resource is active in source/fhir.ini, so source/consent/structuredefinition-Consent.xml feeds the current build. FHIR-30759 is a tightly related Published Consent issue whose resolution independently says Consent.provision.actor.role should bind to ParticipationRoleType as an Example binding. FHIR-34220 handled the securityLabel question separately, matching FHIR-31908's instruction not to decide security labels here. No direct Zulip or Confluence hits for FHIR-31908 were found; the linked FHIR-30759 Zulip thread supports the conclusion that actor.role should be relaxed.

AutoFHIR reconciliation:
Changed Consent.provision.actor.role from extensible to example in the authoritative StructureDefinition source and aligned the checked-in Consent SVG binding annotation from Extensible/+ to Example/??. Consent.verification.type was already example, and securityLabel was intentionally left untouched because FHIR-31908 deferred it.

Recommendation:
Keep this commit as-is. It completes the unapplied actor-role portion of FHIR-31908 without expanding into the separately tracked security-label decision; FHIR-30759 can be audited separately if desired, but no further source change is needed for the actor-role binding after this commit.
