Issue request:
FHIR-3029 was a Published/Persuasive FHIR-core-search technical correction for DSTU1. It asked to remove the apostrophe in "it's" from the phrase "irrespective of it's system namespace" and suggested a broader search for contractions.

Initial application:
The issue was applied in git-svn commit da94efd249231db5f75544cea15043da23886859, corresponding to SVN revision 3039, which changed the token-search sentence from "it's system namespace" to "its system namespace" and also changed a reference-search sentence from "by it's absolute location" to "by its absolute location." The Jira application comment explicitly said revision 3039 fixed the issue but did not fix contractions more broadly.

Additional context:
The affected FHIR-core-search narrative is the current source/search.html page. The original token-search sentence has since been rewritten by FHIR-3030 and later search-page refactors, but the current text still avoids the possessive typo by saying the code matches irrespective of the value of the system property. The reference-search wording also still uses "its absolute location." Current remaining "it's" hits on source/search.html are contractions, not the possessive typo, and the original application explicitly left contractions out of scope. Zulip and Confluence searches found no relevant contrary discussion.
