FHIR-17569: Audit Consent exclusive extension gap

Issue request:
FHIR-17569 is a Published, Persuasive with Modification STU3 Consent request to support a Consent rule specific to "this patient and only this patient". The recorded resolution proposed a 0..1 Boolean extension on Consent.provision, named Consent.provision.exclusive, with the meaning "Only share information directly/exclusively about this patient" and a missing value of false, while also noting that the false case needed more exploration.

Initial application:
No durable core-source application of the requested extension was found. Searches for FHIR-17569, GF#17569, Consent.provision.exclusive, and the proposed "Only share information" wording found no active source definition in current core, in the R4/R4B/R5 source branches checked, or in the FHIR Extension Pack. Git history around Consent did not reveal a Jira-tagged implementation commit for this specific request.

Additional context:
Consent is an active current-build resource, but the current resource has evolved since the STU3 request. The active source now includes Consent.provision.data.meaning for interpreting referenced data, Consent.provision.expression for computable FHIRPath-or-other rules, and later R5 Consent redesign work such as FHIR-31029 added broader subject support including Group. Core Consent extension definitions were removed from the R5 source and the Extension Pack currently contains other Consent.provision extensions, but not an exclusive-patient Boolean. Community searches found no Zulip or Confluence record that resolves whether the old Boolean should be recreated, moved, or treated as superseded.

AutoFHIR reconciliation:
This commit intentionally makes no source change and records a human-review decision. Adding a new core extension would be out of step with current extension ownership, and adding an Extension Pack artifact or declaring the old extension superseded requires CBCC/Security work-group confirmation because the original resolution left important semantics unresolved and later Consent mechanisms are broader but not an explicit replacement.

Recommendation:
Keep this audit commit as the current core reconciliation. Ask the responsible work group to decide whether an exclusive-patient Consent.provision extension is still wanted in the FHIR Extension Pack, or whether current Consent.provision.data, Consent.provision.expression, and Permission-based policy mechanisms supersede the STU3 proposal.
