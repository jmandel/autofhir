FHIR-14675: Add Observation instantiates definition link

Issue request:
FHIR-14675 was Published with a Persuasive with Modification resolution for STU3/R5, after noting that ObservationDefinition documentation said Observation.basedOn referenced ObservationDefinition while Observation.basedOn did not permit Reference(ObservationDefinition). The final resolution did not add ObservationDefinition to basedOn; it pointed to the related applied work and comments explaining that a new instantiates element should carry the ObservationDefinition relationship instead of overloading basedOn.

Initial application:
The seed issue itself has no Jira-keyed commit in the local history. The related FHIR-30791 Jira snapshot records applied R5 work in the same Observation/ObservationDefinition family, but the current source still had Observation.basedOn limited to plan/proposal/order resources and had no Observation.instantiates[x] element. The current CI build profile likewise did not expose Observation.instantiates[x].

Additional context:
FHIR-32698 later restated the intended application explicitly: ObservationDefinition is not a plan, proposal, or order, and the Observation-to-ObservationDefinition relationship belongs in Observation.instantiates[x] as canonical(ObservationDefinition) or Reference(ObservationDefinition), per FHIR-14675. FHIR-39201 is background for later naming of instantiates choices in rendered/API form, but it does not supersede the Observation-specific Reference option recorded by OO.

AutoFHIR reconciliation:
This commit adds Observation.instantiates[x] to the active Observation StructureDefinition source with canonical and Reference types constrained to ObservationDefinition. Observation.basedOn is left unchanged because adding ObservationDefinition there would contradict the final Jira interpretation and the existing basedOn definition.

Recommendation:
Keep this source change. It implements the OO resolution path for FHIR-14675 while preserving basedOn semantics; FHIR-32698 should be reviewed separately if a future worker wants a dedicated audit record for that later R6 clarification.
