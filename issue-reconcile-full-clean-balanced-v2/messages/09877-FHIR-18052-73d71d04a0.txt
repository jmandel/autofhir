FHIR-18052: Audit normative-version extension availability

Issue request:
FHIR-18052 is a Published/Persuasive FHIR-I change request against FHIR-core. It followed up on FHIR-16165/GF#16165, which said that once resources are published as normative an extension on the StructureDefinition marks the FHIR version where the resource first became normative. The reporter could not find that extension and asked that it be created if missing; the recorded resolution said this would be done as part of the normative publication.

Initial application:
The Jira comment points to Git commit deeb34d853b02952ec4016b1628737a2a9824653, "GF#18052 - move FHIR to normative footing". That commit changed source/fhir.ini by replacing the older normative list with normative-ballot metadata and adding a [first-normative-version] section for the R4 normative resources and artifacts. Later source refactoring in 33b409a4b6d544598262f2f074ebb4b6dc466157 materialized the structuredefinition-normative-version extension on current StructureDefinition XML such as Resource and StructureDefinition.

Additional context:
FHIR-16165 is the originating version-identification decision and is already represented on the combined branch by a no-change audit commit. FHIR-26671 later widened the same extension's allowed context to ElementDefinition and any canonical resource, and is also already represented on the combined branch. Core extension definitions were intentionally removed from this checkout by dd468d4f1799dd79819315b211588ef1cf4586e0; the current authoritative definition for http://hl7.org/fhir/StructureDefinition/structuredefinition-normative-version lives in the FHIR Extension Pack, where it defines a code value bound to ValueSet/FHIR-version and allows CanonicalResource and ElementDefinition contexts.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current build-scope core source/fhir.ini retains [first-normative-version] entries for Resource, Patient, Observation, StructureDefinition, and other normative artifacts, and current source XML contains the structuredefinition-normative-version extension with value 4.0.0 on representative normative StructureDefinitions. Recreating or editing the extension definition in core would duplicate Extension Pack source that has intentionally moved out of the core checkout.

Recommendation:
Keep this no-change audit as-is. No FHIR core source follow-up is needed for FHIR-18052; any future editorial update to the extension definition's wording should be handled in the FHIR Extension Pack, not as a missing core application of this issue.
