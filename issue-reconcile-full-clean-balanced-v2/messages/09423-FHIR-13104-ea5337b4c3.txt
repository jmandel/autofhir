FHIR-13104: Audit operation documentation support

Issue request:
FHIR-13104 was Published/Persuasive for DSTU2 conformance. It asked to add a 0..1 markdown documentation element to CapabilityStatement.rest.operation so capability statements can describe special operation behavior without forcing a separate OperationDefinition when functionality is unchanged.

Initial application:
No current git commit explicitly names FHIR-13104. The original source history instead shows the closely related FHIR-13106 application: commit 7360889bc386940c5ef3305ee7fafce957a08725 changed CapabilityStatement.rest.operation to reuse the CapabilityStatement.rest.resource.operation backbone, and commit 9e5e6b6148200ba40e05540d1e6f4aefcca3f6e5 added CapabilityStatement.rest.resource.operation.documentation with the requested markdown cardinality and behavior text. The current source preserves that model.

Additional context:
CapabilityStatement is actively included in the current FHIR build. The current XML defines CapabilityStatement.rest.resource.operation.documentation as 0..1 markdown with text covering special behavior for system, type, and instance-level invocation, while CapabilityStatement.rest.operation is a contentReference to CapabilityStatement.rest.resource.operation. FHIR-13106 explicitly requested adding documentation support consistently when splitting resource-level operations, and it is already represented on the combined branch by commit 7b84f4a7395a521def6f77d0376ac5ed4ace4aee. A later Zulip implementer thread has Lloyd McKenzie advising use of CapabilityStatement.rest.operation.documentation for general expectations, confirming that the shared backbone is understood as exposing documentation at the system operation path. Jira, Zulip, and Confluence searches found no later conflicting core decision.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Adding a duplicate explicit CapabilityStatement.rest.operation.documentation element would conflict with the current contentReference representation; the active source already allows the requested documentation through the reused operation backbone.

Recommendation:
Keep this no-change audit commit. The current source satisfies FHIR-13104, and the related FHIR-13106 audit already covers the resource-operation split that explains why the documentation element is authored once on the shared backbone.
