FHIR-13919: Audit moved Patient everything scope

Issue request:
FHIR-13919 was Published/Persuasive for STU3 and asked to clarify Patient/$everything for multiple patients. The accepted resolution relaxed the old single-patient error wording from "should return an error" to "may return an error" and called for notes about bulk data and access to all patients available to the requesting user, such as family records or provider-accessible patients.

Initial application:
The Jira comment records svn revision 12810. In git, e434b7bc7b (#13919 - bulk data documentation) applied that work by updating the Patient $everything spreadsheet text from single-patient language to one-or-more-patient language, changing the no-nominated-patient behavior to "may choose to return an error," and adding asynchronous/bulk-data guidance. Later generated/source OperationDefinition XML carried the same meaning.

Additional context:
Patient remains an active core resource, but the current Patient operations list no longer includes OperationDefinition/Patient-everything. Commit b487fdda4b removed Patient-everything from core and changed active core pages to link to the HL7 Admin Incubator continuous build. The current Admin Incubator Patient/$everything definition is based on https://github.com/HL7/admin-incubator/ and still says the operation covers "one or more patients," the actual list for GET /Patient/$everything is all patients available to the user, the server may return an error instead of all records, and asynchronous/bulk formats may be appropriate. FHIR-44816 is a later same-family issue for Encounter/EpisodeOfCare $everything and is already represented on the combined branch.

AutoFHIR reconciliation:
This audit commit makes no source change in core. The authoritative Patient/$everything definition has moved outside this checkout, and the external current operation already reflects the FHIR-13919 clarification. Reintroducing or duplicating Patient/$everything text in core would be a scope regression rather than a current-spec fix.

Recommendation:
Keep this audit as-is for core. If future Patient/$everything corrections are needed, apply them in HL7/admin-incubator (and update core links only if the external location changes).
