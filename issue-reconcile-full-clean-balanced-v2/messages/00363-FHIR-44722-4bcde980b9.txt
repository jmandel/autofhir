FHIR-44722: Audit migrated ValueSet profile correction

Issue request:
FHIR-44722 is Applied/Persuasive. It asked to correct the PublishableValueSet composeCreationDate slice so that it uses the valueset-compose-creationDate extension instead of valueset-compose-createdBy, and to update the valueset-compose-creationDate extension datatype from string to dateTime.

Initial application:
The core side was previously applied in git commit 53fb1f581d6364050b942d68440eec15913aa66c, which changed the old source/valueset/structuredefinition-profile-publishablevalueset.xml slice reference from valueset-compose-createdBy to valueset-compose-creationDate. The Extension Pack side was previously applied in git commit 325987bdfa8e8191fcb4de32d57d3cd7152a5c19, which changed StructureDefinition-valueset-compose-creationDate.xml away from string, but the current external source uses date rather than the Jira resolution's dateTime. No prior commit on the combined branch carried an Issue-Reconcile-Key trailer for this issue.

Additional context:
FHIR-37959 later removed the Shareable/Publishable/Computable/Executable profiles from the core FHIR specification for R6 and directed that they be maintained outside core. The current combined branch no longer contains source/valueset/structuredefinition-profile-publishablevalueset.xml, and source/fhir.ini has no active publishablevalueset profile entry. Confluence TI minutes for 2024-08-05 record that FMG gave permission to update the obviously wrong datatype and mark FHIR-44722 applied.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The target PublishableValueSet profile is no longer built from this FHIR core checkout, and the remaining datatype mismatch to the Jira wording is in the Extension Pack / migrated profile source rather than in current core source.

Recommendation:
Keep this audit commit as-is for core. A maintainer of the external profile/extension source should confirm whether the intended type is dateTime as stated in FHIR-44722 or date as currently applied in the Extension Pack, and update that external repository if the Jira wording remains authoritative.
