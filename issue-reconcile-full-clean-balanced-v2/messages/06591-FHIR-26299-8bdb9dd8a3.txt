FHIR-26299: Audit DeviceRequest DeviceDefinition choice

Issue request:
FHIR-26299 was a Published/Persuasive R4 change request from Orders and Observations asking DeviceRequest.code to support DeviceDefinition as well as Device, and to use CodeableReference(Device | DeviceDefinition) rather than the older CodeableConcept-or-Device shape.

Initial application:
The Jira comment says the issue was preapplied. The 2020-05-04 OO HCP minutes record a motion to accept the DeviceRequest code reference proposal as preadopted. In git history, commit 33b409a4b6d544598262f2f074ebb4b6dc466157 introduced the new-build DeviceRequest source with DeviceRequest.code typed as CodeableReference targeting both Device and DeviceDefinition.

Additional context:
The current build no longer has DeviceRequest.code as the primary element name: source/fhir.ini maps the old DeviceRequest.code name to DeviceRequest.product[x]. A later DeviceDefinition modeling decision, FHIR-39389, says references to DeviceDefinition should be canonical; commit e3ef4ee44f6a25130aeb63548e9bb2929e103299 changed DeviceRequest.product from CodeableReference(Device | DeviceDefinition) to the current product[x] choice with CodeableConcept, Reference(Device), and canonical(DeviceDefinition). The active fhir.ini resources list includes devicerequest=DeviceRequest, so the inspected source is in current build scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active DeviceRequest StructureDefinition already includes DeviceDefinition as the definitional-device choice via canonical(DeviceDefinition), and the CodeableReference wording from the original issue has been superseded by the later canonical DeviceDefinition representation.

Recommendation:
Keep this audit commit as-is. Do not reintroduce CodeableReference for DeviceRequest.product solely to match the 2020 wording; that would conflict with the later canonical-resource modeling decision for DeviceDefinition. A separate future review could consider whether DeviceRequest needs a canonical search parameter, but that is outside FHIR-26299.
