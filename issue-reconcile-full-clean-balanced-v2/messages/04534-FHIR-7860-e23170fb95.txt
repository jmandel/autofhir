FHIR-7860: Audit Coverage class distinction

Issue request:
FHIR-7860 was a Published Financial Management change request from the DSTU1 ballot asking for Coverage.group and Coverage.plan to be differentiated because the two elements had identical definitions. The approved Persuasive with Modification resolution said group, plan, class, and their subtypes are common insurance-industry terms with insurer-specific usage, and that additional explanatory text would be added.

Initial application:
The request was applied in the historical spreadsheet source by commit 43806174288e821cb06173a72cde96317186412b, a bulk Coverage tracker commit that explicitly included tracker 7860. That commit changed the old Coverage.group child definitions so group identified an employer group and plan identified a collection of benefits provided to employees, with matching subgroup/subplan wording.

Additional context:
The current build no longer has separate Coverage.group and Coverage.plan elements. Coverage is active in source/fhir.ini, the R3-to-current mapping records Coverage.grouping as Coverage.class, and the current source models insurer-specific group, plan, class, and related labels as repeating Coverage.class entries with a required Coverage.class.type and Coverage.class.value. The bound coverage-class terminology supplies the concise current distinctions, including group as an employee group and plan as a specific suite of benefits, while examples use separate group and plan class entries.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source and terminology already preserve the approved distinction in the current Coverage.class model, and adding old group/plan explanatory text to the generic class element would duplicate terminology/exemplar content without changing implementer understanding.

Recommendation:
Keep this no-change audit. Revisit only if Financial Management wants richer definitions in the external coverage-class terminology or in a future Coverage.class narrative redesign; no core source correction is needed for FHIR-7860.
