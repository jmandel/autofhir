FHIR-5740: Audit Questionnaire definition guidance

Issue request:
FHIR-5740 was a Published/Persuasive DSTU1 Questionnaire change request asking the specification to explain the relationship between a question's inline content and external question definitions identified by code/DataElement references. The accepted resolution was to indicate the expected degree of alignment: inline question text, data type, and value set SHOULD still be declared for interoperability, and any inline content should align with the referenced definition, with exact alignment rules left to implementation environments.

Initial application:
The issue was pre-applied as SVN build #4158, represented in git by 8a2625aee3, which added the requested two-paragraph note to source/questionnaire/questionnaire-notes.xml. The current source still contains that guidance, adapted to the current Questionnaire model.

Additional context:
Questionnaire is an active resource in source/fhir.ini, so source/questionnaire/questionnaire-notes.xml is in current build scope. Later source history replaced the obsolete DSTU1 code/deReference/DataElement framing with Questionnaire.item.definition, ElementDefinition, StructureDefinition, and logical-model wording, and FHIR-28305 added the questionnaire-definitionBased extension guidance. Those later edits preserve and refine the same interoperability point rather than reversing it. Zulip and Confluence searches found no directly relevant community record that conflicts with the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Question Definitions section already says that even if a standard question definition is provided, question text, data type, and value set SHOULD still be declared; it also says systems might not be able to resolve external definitions, points to questionnaire-definitionBased for definition-dependent questionnaires, and states that inline content and referenced definitions are expected to align while FHIR does not dictate the required degree of alignment.

Recommendation:
Keep this no-change audit commit as-is. Future changes to definition-based Questionnaire processing should be handled under later issue-specific decisions, not as additional FHIR-5740 work, because the FHIR-5740 request is already represented in active current source.
