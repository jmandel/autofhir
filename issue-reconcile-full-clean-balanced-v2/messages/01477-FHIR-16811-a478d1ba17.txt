FHIR-16811: Audit large-population MeasureReport guidance

Issue request:
FHIR-16811 was Published/Persuasive with Modification for the STU3 MeasureReport guidance. It asked how subject-list reports should behave for very large populations where the List could otherwise contain thousands of references to individual-level MeasureReports; the resolution was to document that implementations can choose an upper limit and report only summary-level information after that point.

Initial application:
The request was applied in git commit b1633598ee8a1c6256a166a585b3a96af299c644, matching the Jira comment for SVN 14853. That commit added guidance to source/clinicalreasoning-quality-reporting.html that very large population results may be limited by returning a too-costly error or a partial response with an explicit indication that it is partial, and it also referenced bulk data feedback.

Additional context:
The current Quality Reporting page is in build scope through source/hierarchy.xml and the active MeasureReport/Clinical Reasoning source links. Later edits moved the guidance into the current Subject-List Reports section, changed patient language to subject language, and extended the sentence so it covers both subjectReport and subjectResults options without changing the large-population rule. Searches of Zulip and Confluence found no directly relevant conflicting community record.

AutoFHIR reconciliation:
This is an empty audit commit. The current source already contains the requested large-population guidance at source/clinicalreasoning-quality-reporting.html, so no source change is needed.

Recommendation:
Keep this audit commit as-is. Future work should only revisit the wording if CQI adopts newer guidance for partial MeasureReport responses or bulk-data-based quality measurement at scale.
