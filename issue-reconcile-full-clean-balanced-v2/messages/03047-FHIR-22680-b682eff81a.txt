FHIR-22680: Audit cqf-calculatedValue Expression migration

Issue request:
FHIR-22680 was Published/Persuasive for FHIR-core and asked the CDS work group to change the cqf-calculatedValue extension so it allowed an Expression value instead of only a string, enabling inline FHIRPath as well as named library expressions for calculated questionnaire constraints.

Initial application:
Core history shows the issue was applied by commit a24a2ffee0e8a76e7d91daea31529517a0d9d1da, whose subject was "J#22680: Changed cqf-initialValue and cqf-calculatedValue to be of type Expression" and whose patch changed the calculatedValue row in source/profiles/clinicalreasoning-extensions-spreadsheet.xml from string to Expression. The row still used Expression immediately before core removed extension definitions. No existing combined-branch commit for Issue-Reconcile-Key: FHIR-22680 was found.

Additional context:
FHIR core no longer owns the authoritative source for this extension. Commit dd468d4f17 removed extension definitions from the R5 core source, and current core only retains the cqf-calculatedValue OID plus links that resolve through the external extensions location. The FHIR Extension Pack includes input/definitions/Element/StructureDefinition-cqf-calculatedValue.xml through input/definitions/* and its current Extension.value[x] type is Expression. Later FHIR-51490 deprecated cqf-calculatedValue in favor of cqf-expression in the Extension Pack without changing the Expression value type; FHIR-49016 and duplicate FHIR-49456 explain the later SDC/extension-family preference for cqf-expression.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR-core source change. The requested semantic change is already present in the current authoritative Extension Pack definition, and the relevant source now belongs outside this FHIR-core checkout.

Recommendation:
Keep this external-repo audit commit as-is. No FHIR-core follow-up is needed for FHIR-22680; any future cqf-calculatedValue maintenance should be handled in the FHIR Extension Pack, where the definition already supports Expression and the later deprecation guidance is applied.
