FHIR-5573: Audit internal code whitespace policy

Issue request:
FHIR-5573 was a Published/Persuasive DSTU1 change request asking HL7 to remove spaces from value set codes defined by FHIR/HL7 where feasible, while acknowledging that externally defined systems such as UCUM may legitimately have codes with spaces.

Initial application:
The issue was applied in historical git-svn commit e995abe5d075934abc6de37f9449f057bcfbb82e (#5573 / svn r4059), which replaced internally defined codes such as "entered in error", "in progress", "on hold", "not in", and "nil known" with hyphenated code forms across the then-current spreadsheets, examples, and status code sources. The Jira comment also records that publication tooling was updated to reject HL7-defined codes with spaces.

Additional context:
Current FHIR source still allows the primitive code datatype to contain single internal spaces, so FHIR-5573 should not be interpreted as a universal ban on spaces in all code values. Later FHIR-18441 and the 2020 Zulip thread about whitespace in the code datatype discuss XML/canonicalization and code primitive whitespace rules, but they do not reverse the narrower policy that HL7-defined terminology codes should avoid spaces. The current build configuration includes active CodeSystem and ValueSet source surfaces, and a current scan of CodeSystem and ValueSet XML found no whitespace-containing concept codes in HL7/FHIR-owned systems.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core source already satisfies the FHIR-5573 policy for in-scope HL7/FHIR-defined terminology; remaining code values with spaces are either external/example code-system values, displays/definitions, or out-of-scope/stale source rather than current HL7-defined concept codes needing correction.

Recommendation:
Keep this audit commit as-is. Future source changes should continue to rely on terminology publication validation for HL7-defined CodeSystem concepts, while preserving the code primitive's existing allowance for single internal spaces because externally and locally defined code systems may use them.
