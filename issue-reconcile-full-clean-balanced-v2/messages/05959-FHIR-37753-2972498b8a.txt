FHIR-37753: Anchor search conformance summary

Issue request:
FHIR-37753 was Applied/Persuasive with Modification for the FHIR-core search page. It requested a way to tag conformance statements in page text and auto-generate a conformance summary for readers/reviewers; the applied Jira comment records the intended fhir-conformance spans and [%conformance-statement-summary%] insertion, followed by the PR #3442 merge note.

Initial application:
The issue was partially mocked up in 2022 with a Conformance Summary table and #conformancesummary contents link, then the manual summary table was removed while the contents link remained. In 2025, commit 80f4b1c added the generated summary token and an initial fhir-conformance span, and commit a3766ac tagged the search page conformance statements. The current source therefore had the generated summary and tagging, but the summary remained under Summary Tables with no #conformancesummary anchor for the contents link.

Additional context:
FHIR-I minutes show the 2022 deferral concern that summary rows could lack context, then the 2023 final persuasive vote. Current source/search.html is the active Search (RESTful API) source page linked from the documentation page, so fixing its section structure is in build scope. Jira and community searches found no later conflicting decision or related issue requiring a separate decision.

AutoFHIR reconciliation:
This commit creates an explicit <a name="conformancesummary"></a> / <h3>Conformance Summary</h3> section for the generated summary token and leaves the existing Summary Tables anchor and tables immediately after it. It does not change any conformance statement text or the set of tagged statements.

Recommendation:
Keep this source fix as-is. Future work, if any, should come from publisher warnings about specific untagged SHALL/SHOULD/MAY statements rather than changing this section structure again.
