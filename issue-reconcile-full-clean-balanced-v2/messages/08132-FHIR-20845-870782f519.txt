FHIR-20845: Audit independent source rule type/cardinality grammar

Issue request:
FHIR-20845 was Published/Persuasive for FHIR-core StructureMap. It asked that StructureMap source-rule type and min/max cardinality be usable independently because the StructureMap resource model permitted separate source.type, source.min, and source.max elements while the mapping-language description and ANTLR grammar made cardinality a sub-clause of type.

Initial application:
The issue was explicitly applied by git commit 82dcb0036150ffbace89845ffad4a43ae3f140d1, which changed source/mapping-language.html and images/mapping.g4. That commit separated the mapping-language syntax line into independent {: type} and {min..max} clauses and split the grammar so sourceCardinality is an optional ruleSource clause rather than part of sourceType.

Additional context:
StructureMap is an active resource in source/fhir.ini, and source/hierarchy.xml and module pages include mapping-language.html in the current build. Later mapping-language and grammar maintenance, including db673c36e89512edf663e0675ab12bbdbb80704e, retained the independent optional typeIdentifier? and sourceCardinality? clauses. Community searches found only block-vote/admin mentions and no Confluence references or conflicting substantive discussion.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current mapping-language page describes type and min..max as separate optional source statement clauses, and the current ANTLR grammar allows typeIdentifier? and sourceCardinality? independently.

Recommendation:
Keep this no-change audit commit as-is. No follow-up source work is needed for FHIR-20845 unless a future work group decision changes StructureMap mapping-language source rule syntax.
