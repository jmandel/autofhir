FHIR-45047: Clarify Meta.lastUpdated population comment

Issue request:
FHIR-45047 was an Applied/Persuasive FHIR-core BaseResource change request for Meta.lastUpdated. The issue asked for the short, definition, and comments to align with FHIR-I's understanding that lastUpdated is server-managed and can be out of sync with visible resource content; the voted resolution changed the Meta.lastUpdated comments to describe the server-population behavior and false-positive/false-negative update scenarios.

Initial application:
FHIR-45012 first added related lastUpdated guidance to source/datatypes/meta.xml in commit 8d7041c700. FHIR-45047 was later applied in commit 993291c03c, also in source/datatypes/meta.xml, but the applied text kept the phrase "it might be populated by the server when data is received or assigned when crafting the instance when constructing a response," which the Jira follow-up comment identified as two half sentences left over from editing. No prior Issue-Reconcile-Key commit for FHIR-45047 was present on the combined branch.

Additional context:
Meta is an active datatype in source/fhir.ini and is marked normative, so source/datatypes/meta.xml is in current build scope. FHIR-I minutes and the cited Zulip thread support the resolved semantics: lastUpdated is server-managed, servers should avoid missed updates, but the value may be out of sync with visible resource changes in either direction unless specified otherwise. FHIR-45012 remains a related FHIR-extensions/change-required issue and is not independently decided here. The search.html _lastUpdated section already points readers to Resource.meta.lastUpdated and remains consistent enough without duplicating the full element comment.

AutoFHIR reconciliation:
This commit makes the applied Meta.lastUpdated comment grammatically coherent by changing the server-population sentence to say that the server might populate the element when data is received or when crafting a response instance. It does not change the short or definition because the final voted resolution targeted the comments, and it does not broaden the edit to related search or extension work.

Recommendation:
Keep this source fix as the FHIR-45047 reconciliation. If future work wants a computable disclosure of lastUpdated guarantees or a separate extension/search parameter, handle that under FHIR-45012 or a successor issue rather than further changing the Meta.lastUpdated comment here.
