FHIR-14199: Audit Task focus handles context use case

Issue request:
FHIR-14199 was a Published/Persuasive STU3 change request asking to open Task.context beyond Encounter/EpisodeOfCare so dispatch Tasks could reference an accident/incident resource and an ambulance/location.

Initial application:
No source commit explicitly tagged FHIR-14199 was found. The approved resolution says the later Task.basedOn and Task.focus additions, both able to reference any resource, handle the use case. The R5 Task source already contained those Reference(Resource) surfaces, and current source retains the ability through Task.basedOn, Task.focus.value[x], and Task.for.

Additional context:
Patient Administration minutes referred the accident-resource question to O&O in 2020, and O&O minutes record the 2022 block-vote acceptance of FHIR-14199. Later Task issues FHIR-29636 and FHIR-31427 clarified the distinction and wording for Task.basedOn and Task.focus without narrowing their Reference(Resource) target. Task is active in source/fhir.ini, so source/task/structuredefinition-Task.xml is the authoritative current build input.

AutoFHIR reconciliation:
This audit commit makes no source change. Current Task no longer has a Task.context element to broaden; instead, Task.focus.value[x] can reference any Resource for the incident/accident being acted on, Task.for can reference any Resource for the beneficiary such as a Location/ambulance, and Task.basedOn can reference any Resource for higher-level authorization.

Recommendation:
Keep this audit commit as-is. Re-opening Task.encounter/context is unnecessary and would conflict with the resolved guidance that focus/for/basedOn cover the requested non-Encounter association.
