FHIR-38798: Audit Endpoint connection type copyright

Issue request:
FHIR-38798 was a Published/Persuasive Patient Administration change request for R5. It reported that the Endpoint connection type value set still carried an IHE copyright statement even though the underlying endpoint-connection-type code system no longer contained IHE codes, and asked that the stale statement be removed.

Initial application:
The issue was applied by source commit f1e78b3363, which removed exactly the IHE copyright line from source/endpoint/valueset-endpoint-connection-type.xml. The current source still lacks that ValueSet-level copyright and continues to compose from http://terminology.hl7.org/CodeSystem/endpoint-connection-type.

Additional context:
FHIR-36589 and UP-344 provide the earlier change family: Endpoint.connectionType was changed to CodeableConcept/example binding and the IHE concepts were moved out of the core R5 terminology. FHIR-39600 and UP-529 later restored the deprecated IHE concepts and the IHE copyright notice in THO for R4/R4B compatibility, but that licensing now belongs to the external THO CodeSystem. The current core build output for http://hl7.org/fhir/ValueSet/endpoint-connection-type still has no ValueSet copyright, while terminology.hl7.org/CodeSystem/endpoint-connection-type contains the IHE copyright.

AutoFHIR reconciliation:
This commit makes no source change. The authoritative core source for the Endpoint value set is in build scope through the active Endpoint resource and already reflects the FHIR-38798 edit; later THO restoration does not require re-adding a core ValueSet copyright statement.

Recommendation:
Keep this no-change audit as-is. If a future licensing review wants copyright propagated from included external code systems onto core ValueSet wrappers, that should be a separate terminology/publication policy decision rather than a FHIR-38798 correction.
