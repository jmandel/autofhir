FHIR-15554: Audit Patient deceased search expression

Issue request:
FHIR-15554 was a Published/Persuasive STU3 Patient Administration change request. It reported that the Patient deceased search parameter expression was `Patient.deceased.exists()`, which incorrectly matched `deceasedBoolean=false`, and requested an expression that only treats `deceasedBoolean=true` or a present death date as deceased.

Initial application:
The issue appears to have been applied in historical commit e4f95ecc3e, whose message says `GF#1554 patient deceased search expression` and whose patch changed the Patient spreadsheet search parameter expression from `Patient.deceased.exists()` to `Patient.deceased.exists() and Patient.deceased != false`. The 2021 new-build-core source refactor commit 33b409a4b6 carried that corrected expression into `source/patient/bundle-Patient-search-params.xml`.

Additional context:
`source/fhir.ini` lists Patient as an active resource, so the Patient search parameter bundle is in current build scope. Later related issue FHIR-37591 challenged the same expression for `:missing` behavior, but PA resolved it Not Persuasive because a fully compatible fix would require deprecating the normative existing search parameter and creating a new one; the linked Zulip thread reached the same conclusion that prior-version override was not available. FHIR-15807 is a duplicate of this same STU3 complaint, and FHIR-23068 concerned the now-removed XPath form rather than a needed FHIRPath change.

AutoFHIR reconciliation:
No source change was made. The current build-scoped Patient search parameter already says `Patient.deceased.exists() and Patient.deceased != false`, which preserves the FHIR-15554 correction by excluding `deceasedBoolean=false` while still matching a present death date.

Recommendation:
Keep this audit commit as-is. Do not add a redundant source change for FHIR-15554; revisit only if PA chooses to introduce a new search parameter for the distinct `:missing` use case from FHIR-37591.
