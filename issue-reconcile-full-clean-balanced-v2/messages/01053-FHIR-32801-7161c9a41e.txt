FHIR-32801: Align MedicationKnowledge metadata semantics

Issue request:
FHIR-32801 was a Published/Persuasive Pharmacy change request for R5 MedicationKnowledge. It asked to change MedicationKnowledge from DomainResource to MetadataResource so medication knowledge could follow canonical and metadata resource patterns, and to remove or replace local identifier, author, and status elements as needed. The decisive Jira comment clarified that the intent was to make all MetadataResource and CanonicalResource data elements available for MedicationKnowledge, not only to require a canonical URL.

Initial application:
The issue appears to have been initially applied by git commit dc170b26ef270aa638b21e96e615b162e17b6d06, which changed only source/medicationknowledge/structuredefinition-MedicationKnowledge.xml from DomainResource to MetadataResource. Later source history partially corrected the same family: FHIR-45285 changed MedicationKnowledge.status to publication-status, author to ContactDetail, and name to max 1; FHIR-45284 added the MetadataResource template marker; FHIR-42901 renamed intendedJurisdiction to jurisdiction and noted that author/status were handled by FHIR-45285. Before this reconciliation, stale pre-metadata wording still described identifier, status, author, name, the status search parameter, and the example name as medication-instance/catalogue semantics rather than metadata/canonical artifact semantics.

Additional context:
MedicationKnowledge is an active current-build resource in source/fhir.ini. MetadataResource templates CanonicalResource, and the current source declares MetadataResource as both template and baseDefinition for MedicationKnowledge. The combined branch already contains a no-change audit commit for FHIR-45285, so this commit does not duplicate that issue; it fixes the residual FHIR-32801 semantic mismatch that remained after the base/interface changes. The checked-in medicationknowledge.svg and obsolete MedicationKnowledge status terminology files still contain old status text, but the SVG is a generated-looking diagram and the status terminology is no longer referenced by the authoritative binding or active fhir.ini terminology entries.

AutoFHIR reconciliation:
This commit updates the authoritative MedicationKnowledge source to match its MetadataResource/CanonicalResource role. It changes the entered-in-error status marker to retired, rewrites retained identifier/status/author/name element text to metadata/canonical artifact semantics, changes the status binding metadata to PublicationStatus, adds the canonical name constraint, updates the identifier and status search parameter descriptions, and changes the example name to a machine-friendly canonical name while leaving the medication display in code.text.

Recommendation:
Keep this source fix. If the publisher still uses source/medicationknowledge/medicationknowledge.svg directly, regenerate that diagram from the updated StructureDefinition rather than hand-editing it. If obsolete MedicationKnowledgeStatus terminology pages are still emitted despite no active binding, handle their retirement as a separate build-scope/terminology cleanup because this issue's authoritative resource semantics are now aligned.
