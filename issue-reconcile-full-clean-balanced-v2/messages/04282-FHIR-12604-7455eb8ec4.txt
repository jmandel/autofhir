FHIR-12604: Audit medication search parameters

Issue request:
FHIR-12604 was a Published Pharmacy change request, resolved Persuasive with Modification for DSTU2, asking to address a MedicationStatement.part-of search parameter warning, fix the part-of search parameter naming, and add patient search parameters for MedicationRequest, MedicationDispense, and MedicationStatement.

Initial application:
The historical implementation is commit a504c1b697fe81488480665b00364efbd46982e6, whose subject explicitly records TR#12604 adding patient search parameters to MedicationRequest and MedicationStatement. In the same historical spreadsheet context, MedicationDispense already had a patient search row, and MedicationStatement's part-of row used the code/name part-of with path MedicationStatement.partOf; generated R3/R4/R4B history carries SearchParameter/MedicationStatement-part-of.

Additional context:
The current build scope still includes MedicationDispense, MedicationRequest, and MedicationStatement as active resources in source/fhir.ini. The current source search parameter bundles contain patient entries for all three resources, expressed against subject filtered to Patient. The current MedicationStatement bundle does not define a part-of search parameter, and neither R5 nor the current build search-parameters.xml expose MedicationStatement-part-of after the R5 MedicationUsage/MedicationStatement refactor family including FHIR-38682. Jira, Zulip, and Confluence searches found no later final decision or community evidence requiring a new restoration of that old resource-specific part-of parameter.

AutoFHIR reconciliation:
This audit commit makes no source change because the current active source already satisfies the patient-search-parameter portion of FHIR-12604, and there is no incorrectly named MedicationStatement part-of search parameter left in the current build to fix.

Recommendation:
Keep this no-change audit. Do not re-add MedicationStatement-part-of from the DSTU2/R4 history as part of FHIR-12604 without a fresh Pharmacy work-group decision, because doing so would add a current search parameter rather than reconcile the published DSTU2 fix.
