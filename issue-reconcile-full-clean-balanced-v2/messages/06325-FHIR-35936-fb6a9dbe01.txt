FHIR-35936: Audit async page split migration

Issue request:
FHIR-35936 was a Published/Persuasive with Modification FHIR-core issue for the async page. It asked to align async.html with Bulk Data IG community work by splitting the async content into a FMM 4 bulk export pattern and a lower-maturity asynchronous interaction pattern, completing the async-bundle content, removing bulk-specific wording from that page, and marking Async-bundle as FMM 1.

Initial application:
The issue was applied by git commit 440a91ad3f, "split and update async page per FHIR-35936." That commit added source/async-bulk.html and source/async-bundle.html, registered both pages in publish.ini, left source/async.html as the overview, marked async-bulk FMM 4, and marked async-bundle FMM 1.

Additional context:
Later R6 source history changed the ownership and build shape for these details. Commit 270e0ceb7b, "normative changes for R6," removed source/async-bulk.html and source/async-bundle.html from publish.ini and source, and changed the active core async overview to link to API Incubator pages while the details are finalized through implementation testing. Related async-bundle R6 issues such as FHIR-47273, FHIR-47276, and FHIR-47278 are already represented on the combined branch as migration/audit commits, and FHIR-47271 has already restored the _outputFormat disambiguation rule into the active overview. FHIR-53868 now tracks the broken API Incubator async-bundle link, but it is still Triaged and unresolved.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The active build-scope core page is source/async.html, and it currently identifies the two async patterns, distinguishes bulk data from asynchronous interaction use cases, links to the API Incubator details, and includes the later _outputFormat disambiguation text. Reintroducing the deleted core detail pages for FHIR-35936 would reverse a later R6 structural change, while the remaining broken external links belong to unresolved follow-up issue FHIR-53868 rather than this Published R5 seed.

Recommendation:

If the API Incubator links should be repaired or the pattern details moved again, handle that through the unresolved link/migration follow-up issues, especially FHIR-53868, after FHIR-I reaches a final decision.
