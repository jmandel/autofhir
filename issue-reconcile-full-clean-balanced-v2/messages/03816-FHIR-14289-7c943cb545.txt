FHIR-14289: Audit ResearchStudy condition separation

Issue request:
FHIR-14289 was a Published/Persuasive FHIR-core ResearchStudy change request from STU3. It asked to update ResearchStudy after condition became a separate element from focus: remove condition from the focus short description, move condition under focus in element order, and update the condition definition away from the old BRIDG-style wording. Jira records that the change was made and published in the Dec 2017 FHIR ballot.

Initial application:
No current git commit explicitly mentions FHIR-14289. The same change family appears in history through the Dec 2017 ResearchStudy ballot work: commit 61b5fa5576 added ResearchStudy.condition directly before ResearchStudy.focus in the old spreadsheet source, and commit a89b85b64a later left focus as "Drugs, devices, etc. under study" while condition remained a separate coded element. The current XML source inherited that separation.

Additional context:
FHIR-14116 is the directly related Published issue that added condition as its own ResearchStudy semantic instead of leaving it inside the general focus element. Later ResearchStudy changes, including FHIR-39083's conversion of focus to CodeableReference, changed focus typing but did not merge condition back into focus. The current build scope still includes ResearchStudy through source/fhir.ini.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. In the active source, ResearchStudy.focus precedes ResearchStudy.condition, focus has the short description "Drugs, devices, etc. under study" without condition, and condition has its own short description, definition, CodeableConcept type, condition-code binding, search parameter, and FiveWs mapping exception.

Recommendation:
Keep this no-change audit. The current build already conveys the requested separation, and adding duplicate narrative would not change implementer understanding.
