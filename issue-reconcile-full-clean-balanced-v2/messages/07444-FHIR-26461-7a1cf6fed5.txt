FHIR-26461: Audit dataelements Bundle uniqueness

Issue request:
FHIR-26461 was a Published/Persuasive FHIR-I change request raised against R4 and applied for R5. The reporter found that site\dataelements.json in fhir-spec.zip was a Bundle of type collection but repeated the same fullUrl plus resource.meta.versionId values for seven de-Quantity entries, apparently violating bdl-7.

Initial application:
No git commit explicitly mentioning FHIR-26461 was found in the FHIR source history. The dataelements.json and dataelements.xml files are generated publication artifacts rather than checked-in source files; the only current source reference is the ElementDefinition page link to the generated XML/JSON data element collections. Published artifact checks show the R4 dataelements.json reproduced the seven duplicate de-Quantity fullUrl/version pairs from the Jira report, while R4B, R5, and the current build have no duplicate fullUrl/version pairs among resource-bearing Bundle entries.

Additional context:
The FHIR-I 2020-04-27 minutes record the motion for FHIR-26461 as "will update in R5" with an 8-0-0 vote. Later Bundle bdl-7 issues refined the invariant itself: FHIR-31986 is already represented on the combined branch with a source fix requiring uniqueness only where resource is present, and FHIR-39476 is already represented with the absent-versionId fallback. Those later decisions are compatible with the current generated dataelements artifact and do not require an additional FHIR-26461 source edit.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current generated dataelements.json no longer has the duplicate fullUrl/resource.meta.versionId pairs that caused FHIR-26461, and the authoritative current Bundle bdl-7 source has already been reconciled through later issue-specific commits.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-26461 unless future generated publication artifacts reintroduce duplicate fullUrl/version pairs in dataelements.json or dataelements.xml.
