FHIR-12435: Replace remaining wire format wording

Issue request:
FHIR-12435 was a Published/Persuasive FHIR-core clarification asking to replace "Wire format" with "Serialization format" in the formats page section 2.21.0.1.4 and elsewhere if necessary because "wire format" was not widely understood outside HL7.

Initial application:
The issue was applied in historical commit 02cee392327706bfee65e3749abfc0762ca9803f, which changed the main formats-related narrative pages and related spreadsheet/XML sources to use "serialization format". Current source no longer had the phrase on the original formats page family, but still had two build-scoped narrative uses in Basic and Signatures.

Additional context:
The Basic occurrence predated the original 2017 application and was missed there; Basic is an active resource in source/fhir.ini. The Signatures occurrence was introduced later during the 2025 signatures rewrite, and signatures.html is included in source/hierarchy.xml. Zulip discussion for the issue confirms the intended replacement term was "serialization format"; Confluence refs search found no conflicting work-group record.

AutoFHIR reconciliation:
This commit replaces the remaining current-source "wire format(s)" wording with serialization-format wording in Basic and Signatures. It leaves historical release cache files and the DefinitionUse code/display "wire-format" untouched because those are historical/generated or code-system content rather than the current narrative wording requested by the issue.

Recommendation:
Keep this commit as-is. It completes the published clarification across current build-scoped narrative without broadening the issue to unrelated uses of "wire" such as "over the wire" transport prose.
