FHIR-25039: Audit quantity translation extension rename

Issue request:
FHIR-25039 was a FHIR-core Published/Persuasive change request raised against STU3 ElementDefinition-related extension content. It asked to replace the opaque iso21090 PQ translation extension/page name with a clearer name such as additionalQuantity or quantityTranslation, and the final resolution was to rename it to extension-quantity-translation.

Initial application:
The rename was applied in core by git commit 2c73520c8c81929f80262da3e04d669c71abcf32, which moved the extension spreadsheet row from the old PQ-translation/iso21090 naming in source/profiles/iso-21090-spreadsheet.xml to extension-quantity-translation with QuantityTranslation/Quantity Translation in source/profiles/general-extensions-spreadsheet.xml. The active source/fhir.ini profile entries still name the general and iso-21090 spreadsheets, but the relevant extension row was later removed from core extension spreadsheets by dd468d4f1799dd79819315b211588ef1cf4586e0.

Additional context:
The current core checkout no longer contains the extension StructureDefinition or stale references to the old iso21090-PQ-translation canonical under source/. Its only matching core source reference is the OID assignment for http://hl7.org/fhir/StructureDefinition/extension-quantity-translation in source/oids.ini. The current Extension Pack checkout owns the active renamed StructureDefinition at input/definitions/datatypes/StructureDefinition-extension-quantity-translation.xml and keeps the old iso21090-PQ-translation StructureDefinition as retired/deprecated with an explicit replacement pointer to the renamed canonical. FHIRI minutes for 2020-04-06 record the rename decision and 15-0-0 vote. Later FHIR-52952 and a 2025 Zulip thread question whether the old iso21090 extensions should remain deprecated, but that issue is Submitted in FHIR-extensions and has not superseded the Published FHIR-25039 rename.

AutoFHIR reconciliation:
This audit commit intentionally makes no core source change. Editing core would either reintroduce extension source that has moved to the Extension Pack or duplicate content that is already represented there. The current core source has no stale old canonical to fix, and the current Extension Pack source already reflects the accepted renamed canonical and old-extension replacement relationship.

Recommendation:
Keep this no-change audit for FHIR-25039. If FHIR-52952 is later resolved to undeprecate or reverse the rename, that follow-up should be handled in the FHIR Extension Pack and any validator/package behavior affected by Extension Pack metadata, not as a retroactive core FHIR source edit for this already-published rename.
