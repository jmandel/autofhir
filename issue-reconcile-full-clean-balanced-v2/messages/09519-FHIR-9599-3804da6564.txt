FHIR-9599: Audit narrative text-blob guidance

Issue request:
FHIR-9599 was Published/Persuasive with Modification for DSTU2. It asked to clarify that DomainResource.text can carry a mostly textual resource when required elements are satisfied, add narrative-page guidance about linking discrete data to narrative and detecting additional narrative content, and revise the Narrative.status code "additional" to say the narrative may contain information not found in structured data.

Initial application:
The issue was applied in SVN revision 8906, now git commit f1f12ca040d73218f6c4c504a7e4623fae8e3676 (#9599 - narrative clarifications). That commit added the text-blob usage note to the DomainResource source, added matching narrative-page prose, and changed the "additional" code definition to use "may" and to state that extra information is not computably detectable except by human inspection. The Jira application comment recorded that the requested standard-extension linking section was not added at that time because no such standard extensions existed.

Additional context:
Current build-scoped source keeps the FHIR-9599 guidance in source/domainresource/structuredefinition-DomainResource.xml and source/narrative.html, with the historical "encoded in formation" typo corrected to "encoded information". The Narrative datatype spreadsheet still defines "additional" with the human-inspection caveat. A later current-source section, added by e9f8d78996d66a0511b02dd92e6e0b60a1615da8 (GF#17336), now documents linking between data and narrative via narrativeLink and originalText, which are maintained in the Extension Pack and referenced from the core narrative page. Basic remains aligned with the related artifact by explaining narrative-only constructs in source/basic/basic-introduction.xml. The later Published issue FHIR-34041 and its Zulip discussion refined narrative safety guidance without reversing FHIR-9599.
