FHIR-43445: Audit DeviceUsage workflow mappings externalized

Issue request:
FHIR-43445 was an Applied/Persuasive with Modification OO change request for R6 asking to align DeviceUsage with the workflow Event pattern by adding mappings for existing elements: DeviceUsage.category to Event.category, DeviceUsage.device to Event.product, DeviceUsage.dateAsserted to Event.recorded, and DeviceUsage.informationSource to Event.reported[x].

Initial application:
The issue was initially applied in core commit f4191d0d3baa2a5f13d40cedb1d0bb69c1203bd0, which added exactly those four workflow mappings to source/deviceusage/structuredefinition-DeviceUsage.xml. The local source file still contains those mappings, including Event.reported[x] alongside the pre-existing informationSource mapping to Event.performer.actor.

Additional context:
DeviceUsage is no longer an active resource in the current core build. Commit 3b38b80cf23f9cbb306fab8fcedb293315478c32 removed DeviceUsage from active source/fhir.ini resource registration and changed module/workflow pages to link DeviceUsage to the OO incubator IG. Current source/device-module.html and source/workflow-module.html point to the OO incubator DeviceUsage page, and the current OO incubator StructureDefinition JSON already carries the FHIR-43445 Event.category, Event.product, Event.recorded, and Event.reported[x] mappings. The related FHIR-51713 DeviceUsage Event.partOf work has already been audited on the combined branch as externalized.

AutoFHIR reconciliation:

Recommendation:
Keep this external-repo audit as-is for core reconciliation. No FHIR core source follow-up is needed for FHIR-43445 unless DeviceUsage is brought back into the active core build; future DeviceUsage mapping corrections should be made in the OO incubator source.
