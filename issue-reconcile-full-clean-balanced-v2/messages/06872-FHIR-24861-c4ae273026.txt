FHIR-24861: Allow coded normal reference ranges

Issue request:
FHIR-24861 was Published/Persuasive with Modification for Observation. It asked for Observation.referenceRange to support a coded reference value instead of forcing qualitative normals such as NEG through referenceRange.text. The approved resolution was to add ReferenceRange.normalValue to Observation as a CodeableConcept.

Initial application:
The R5 application added Observation.referenceRange.normalValue as a CodeableConcept in commit 26dd9e3c28, and later source history added the binding and Observation reference range normal-value terminology. The Jira comment points to PR commit bf05dda, but the current branch history shows 26dd9e3c28 as the content commit that introduced the element. The current source already had the element, terminology binding, and later FHIR-50532 binding-strength relaxation, but the parent obs-3 invariant still required low, high, or text and therefore rejected a referenceRange containing only normalValue.

Additional context:
The original Zulip thread shows the problem was qualitative coded normal values such as NEG for protein or HIV observations, and the OO minutes record the 2022-02-15 vote to add normalValue. FHIR-50532 later relaxed the normalValue binding to Example, which this change preserves. FHIR-55269 is a later Resolved - change required THO-migration proposal for the same normal-value code system, but it is not yet Applied/Published and does not change the invariant needed for FHIR-24861.

AutoFHIR reconciliation:
Updated source/observation/structuredefinition-Observation.xml, which is in build scope through the active fhir.ini Observation=observation resource entry, so obs-3 accepts normalValue as a sufficient referenceRange payload and the normalValue element is marked as satisfying obs-3. Added source/observation/invariant-tests/obs-3.p4.pass.xml alongside the existing obs-3 invariant cases to cover a referenceRange with a coded normalValue and no low/high/text.

Recommendation:
Keep this commit. It completes the applied FHIR-24861 model change without altering the later FHIR-50532 Example binding. Handle FHIR-55269 separately if and when the THO migration is applied.
