FHIR-32858: Clarify MedicationStatement adherence reason

Issue request:
FHIR-32858 was a Published Pharmacy change request with resolution Not Persuasive with Modification. It asked whether MedicationUsage needed additional status capability because R5 status had become record status and some R4 medication-use status scenarios appeared to be missing; the resolution said no new status codes were needed because the listed scenarios can be represented with effectivePeriod, adherence.code, and adherence.reason.

Initial application:
No source commit explicitly mentioning FHIR-32858 was found. The surrounding model had already been applied by earlier Pharmacy changes: FHIR-19468/FHIR-19470/FHIR-28593 introduced the adherence model and narrowed status, FHIR-32060 changed MedicationUsage.status to recorded, entered-in-error, and draft, and later FHIR-38682 renamed the resource back to MedicationStatement. A prior edit moved old statusReason wording onto MedicationUsage.adherence.reason, leaving a stale comment that still described exception statuses and reasonCode.

Additional context:
FHIR-31972 and FHIR-31879 were duplicate/status-scope concerns in the same family. FHIR-39271 later confirmed that status reflects recording status while adherence carries taking/not-taking meaning. FHIR-39329 and FHIR-39333 further clarified that adherence covers medication use or non-use even when no instruction exists and expanded the example adherence codes with on-hold and stopped descendants.

AutoFHIR reconciliation:
This commit updates the active MedicationStatement StructureDefinition text for MedicationStatement.adherence.reason so it no longer describes old statusReason/reasonCode behavior. The short, definition, and comment now identify adherence.reason as the place to explain use, non-use, stopped use, or taking differently than directed, while preserving MedicationStatement.reason as the reason for the statement itself. source/fhir.ini lists medicationstatement as an active resource, so this StructureDefinition feeds the current build.

Recommendation:
Keep this commit. It is the narrow source correction needed for FHIR-32858: the current status/adherence/effective model already has the required representational capability, but the adherence.reason documentation needed to align with the published resolution and avoid sending implementers back to the removed statusReason/reasonCode model.
