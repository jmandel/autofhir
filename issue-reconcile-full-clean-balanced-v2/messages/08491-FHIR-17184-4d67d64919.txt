FHIR-17184: Audit narrative generated-reference guidance

Issue request:
FHIR-17184 was a Published/Persuasive FHIR-core narrative issue raised for STU3. It asked the specification to clarify that a resource narrative may include content looked up from referenced resources while still being considered generated or extensions narrative, with the resolution to handle this in the narrative/references/lookups write-up.

Initial application:
The issue was applied by SVN revision 14336, represented in git as c07a35048a83bbc4670f12f255de95511f59e388. That commit added guidance to source/narrative.html and source/references.html stating that generated narrative may include content from other resources and that narrative containing information derived from other resources is still regarded as generated for Narrative.status.

Additional context:
source/fhir.ini keeps Narrative as an active special datatype/type page and marks it normative, so source/narrative.html is in current build scope. The linked reference-rendering section in source/references.html remains active and directly explains how resolved reference content and Reference.display support generated narrative. Earlier FHIR-9826 and FHIR-17463 context supports the current narrative-page framing, and the 2016 Zulip thread shows the exact generated/extensions-versus-referenced-content question that led to this guidance. Later edits have not removed or contradicted the FHIR-17184 wording.

AutoFHIR reconciliation:
No source change was made. The current source already satisfies the issue through the narrative page, the linked reference-rendering guidance, and the existing Narrative.status definitions.

Recommendation:
Keep this empty audit commit as-is. Reopening the wording would be editorial only unless a future work group decision changes the meaning of generated/extensions narrative that derives summary content from referenced resources.
