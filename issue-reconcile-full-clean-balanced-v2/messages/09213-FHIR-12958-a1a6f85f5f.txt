FHIR-12958: Audit SearchParameter.type definition wording

Issue request:
FHIR-12958 was a Published FHIR-core SearchParameter clarification with Persuasive with Modification resolution. It asked whether SearchParameter.type identifies the type of value entered in a RESTful search URI, and proposed changing the definition from the value a search parameter "refers to" to the value a search parameter "may contain" and how that content is interpreted.

Initial application:
The issue was applied before this reconciliation in git-svn commit dcac844a3c5696060389bf49b6954efd0de46c94, matching Jira comment svn revision 14438. That commit changed source/searchparameter/searchparameter-spreadsheet.xml from "The type of value a search parameter refers to, and how the content is interpreted" to "The type of value that a search parameter may contain, and how the content is interpreted." The later source rework preserved the same wording in the current authoritative StructureDefinition source.

Additional context:
The related Published issue FHIR-12956 clarified SearchParameter.base and was applied separately in git-svn commit 20ea7a67dfd5d0083c9f1446c8d030c9ff6843dd. Current source/fhir.ini lists searchparameter=SearchParameter and SearchParameter=approved, confirming the SearchParameter source is in the current build. Zulip and Confluence searches for the issue keys and SearchParameter terms found no conflicting community record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/searchparameter/structuredefinition-SearchParameter.xml already defines SearchParameter.type as "The type of value that a search parameter may contain, and how the content is interpreted," which implements the Jira-requested clarification in the current build-scope source.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-12958 unless a future work group decision changes the semantics of SearchParameter.type.
