FHIR-23916: Audit preferred extension context

Issue request:
FHIR-23916 was a Published FHIR-core/MnM change request, resolved Not Persuasive with Modification for R5. It asked for a preference indicator on Address and ContactPoint; the accepted resolution was to keep using the existing iso21090-preferred extension but change its context from all elements/data types to Address and ContactPoint.

Initial application:
The issue appears to have been applied in core before this reconciliation. Commit c4807a5165 (MnM changes for R5) changed source/profiles/iso-21090-spreadsheet.xml so the preferred extension context moved from Any to Address;ContactPoint. Related issue FHIR-23069 also records that the incorrect broad context was a build-tool/context bug and had been pre-applied.

Additional context:
FHIR-35835 later published a compatible extension of the same context list to ExtendedContactDetail, and commit b759378e9a applied that change in the same core spreadsheet. Commit dd468d4f17 subsequently removed the extension rows from the R5 core source, and current core source retains only the iso21090-preferred OID. The authoritative current definition is in the FHIR Extension Pack at input/definitions/datatypes/StructureDefinition-iso21090-preferred.xml, where contexts are Address, ContactPoint, and version-gated ExtendedContactDetail. Later FHIR-41565 deprecated/retired the extension in favor of rank, which changes guidance but does not reopen the FHIR-23916 context restriction.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source state already preserves the FHIR-23916 decision, adjusted by the later FHIR-35835 decision, and core no longer owns the active extension definition. Editing core would either duplicate an Extension Pack artifact or reintroduce an out-of-scope definition.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed for FHIR-23916; future preference-guidance changes should be handled against the Extension Pack/rank-extension issues rather than by changing core datatypes source.
