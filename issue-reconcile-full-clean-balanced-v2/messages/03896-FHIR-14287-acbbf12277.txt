FHIR-14287: Audit ResearchStudy primary purpose codes

Issue request:
FHIR-14287 was a Published/Persuasive STU3 BRR change request to remove bio-banking and epidemiologic from the ResearchStudyPrimaryPurposeType value set because those values were not part of the original vetted list. Jira records that the change was made and published in the Dec 2017 FHIR ballot.

Initial application:
The issue was applied in historical commit f09300abf4272bd789b4f6fd15f5fed283c7d38e, whose message explicitly names #14287 and whose patch removed the epidemiological and bio-banking rows from source/researchstudy/researchstudy-spreadsheet.xml and removed those codes from the ResearchStudy primary-purpose short list. The old spreadsheet source has since been refactored, but the current ResearchStudy resource remains in build scope.

Additional context:
Current source has the renamed ResearchStudy.purposeType element with bindingName ResearchStudyPrimaryPurposeType and an example binding to http://terminology.hl7.org/ValueSet/research-study-prim-purp-type. That THO CodeSystem currently contains only treatment, prevention, diagnostic, supportive-care, screening, health-services-research, basic-science, and device-feasibility; it does not contain bio-banking, epidemiologic, or epidemiological. Later decisions changed binding strength, moved the binding to THO, and are considering a future replacement ResearchStudyPurposeType terminology, but the current and proposed code lists do not revive the two removed codes.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active core source delegates the value set to THO, the current THO terminology already reflects the 2017 removal, and current ResearchStudy source contains no references to the removed codes. The only remaining core-source bio-banking hit is unrelated specimen-scope prose, not ResearchStudyPrimaryPurposeType.

Recommendation:
Keep this no-change audit commit as-is. Future work on UP-792 or any successor ResearchStudyPurposeType terminology should be handled as a separate BRR/UTG change and should not be conflated with reintroducing the removed STU3 values.
