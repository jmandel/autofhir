FHIR-17047: Audit Bundle self link count example

Issue request:
FHIR-17047 was a Published FHIR-core/FHIR-core-Feed change request raised against STU3. It asked for the Bundle example self URL to include _count=1; the accepted Persuasive with Modification resolution instead said _count should be 2 because the Bundle says there were 3 matches and only two items appear in the Bundle.

Initial application:
The issue appears to have been applied by svn revision 14366, represented in git as 1ba46476a8ef907374826dd71b9fa50b9157aea4 ("GF#17047 - adjust self link in example"). That commit changed source/bundle/bundle-example.xml so the self link includes &_count=2, and the current source still has that value in the active Bundle resource example.

Additional context:
Bundle is an active current-build resource in source/fhir.ini. The older Feed artifact is now represented by the active Bundle example source. Nearby _count semantics are governed by FHIR-13174, which documented that _count is the maximum number of search results on a page excluding _include/_revinclude and OperationOutcome resources, and by the later FHIR-32017 correction to the current search page wording. Those decisions mean the stale-looking XML comment about returning the first 1 should not be mechanically rewritten to first 2 under this issue, because included resources are not counted by _count. Zulip and Confluence searches found no directly relevant community record changing the Jira/source conclusion.
