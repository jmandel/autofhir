FHIR-18243: Audit CDS Hooks GuidanceResponse profile

Issue request:
FHIR-18243 was a Published/Persuasive CDS change request from STU3 asking the base specification to define a CDSHooksGuidanceResponse profile so GuidanceResponse could support the CDS Hooks response mapping.

Initial application:
The request was applied by git commit 9b36f847bdd7124a47e9dee6fbc4e307f4e0f7c6, which added source/guidanceresponse/guidanceresponse-cdshooks-spreadsheet.xml and updated the GuidanceResponse spreadsheet for the CDS Hooks GuidanceResponse profile.

Additional context:
Later CDS decisions changed the build scope. FHIR-48393 was Applied/Persuasive for R6 and explicitly directed removal of CDSHooksGuidanceResponse, CDSHooksRequestOrchestration, and CDSHooksServicePlanDefinition from the base specification and movement to the Using CDS Hooks with FHIR IG. FHIR-53085 was Applied/Persuasive and moved the CDS-on-FHIR page content, mapping concept maps, and relevant CDS Hooks profiles to the Using FHIR Clinical Reasoning with CDS Hooks IG. Git commit 6abb14540e3fb2242095bca267cd1f48221c5b93 then removed the core GuidanceResponse CDS Hooks implementation guide and structuredefinition-profile-cdshooksguidanceresponse.xml files. Current core source keeps GuidanceResponse itself in build scope, has no GuidanceResponse profile pack entries, and points readers to the external CDS Hooks Clinical Reasoning IG. The external IG currently contains input/resources/structuredefinition/StructureDefinition-cdshooksguidanceresponse.json with the CDSHooksGuidanceResponse profile under the IG canonical URL.

AutoFHIR reconciliation:
This audit intentionally makes no source change. Re-adding the profile to core would reverse later applied CDS work that moved CDS Hooks profiles out of the base specification. The current core source already preserves the relevant GuidanceResponse/CDS Hooks implementer path by linking to the IG, while the actual profile source belongs in the external IG.

Recommendation:
Keep this no-change audit for core. Future changes to the CDSHooksGuidanceResponse profile should be made in HL7/cds-hooks-clinical-reasoning, not by restoring the profile to the FHIR core build.
