FHIR-17073: Audit extension context path rendering

Issue request:
FHIR-17073 was a Published/Persuasive STU3 FHIR-core issue asking that common-extension listings for a resource show the path where each extension applies. The resolution was to do what was possible within presentation space limits.

Initial application:
The Jira application comment points to svn revision 14603. In the git-svn history this is commit ea148b19deac685884ab8a4df69d68ab6924c051, "GF#17073 - improve rendering of extensions", which added a context column to the old resource extension-list renderer and rendered matching StructureDefinition.context expressions such as resource element paths.

Additional context:
The old in-repository PageProcessor renderer was later replaced by the Gradle build's external org.hl7.fhir:kindling dependency. Current core source still contains active extension/profile inputs and links generated resource extension tabs through the extension-location mechanism. Current resource-specific extension listings are now served by the FHIR Extension Pack; the Bundle extension page shows a Context column with paths such as Bundle.entry.response and Bundle.entry.search, sourced from the extension StructureDefinition.context values in the extension-pack repository. A prior combined-branch audit for FHIR-17031 is in the same extension-listing page family, but it concerns Binary/Bundle root extension suppression rather than showing per-extension paths.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The historical application already made the requested renderer change, the current build surface already exposes per-extension context paths, and no current core source file needs a correction for implementers to see where resource extensions apply.

Recommendation:
Keep this no-change audit as-is. Revisit only if the work group wants to change the shared extension-list presentation in Kindling or the FHIR Extension Pack; no FHIR-core source edit is needed for FHIR-17073.
