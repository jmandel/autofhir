FHIR-47357: Audit SubscriptionStatus heartbeat interval clarification

Issue request:
FHIR-47357 was an Applied/Persuasive R6 FHIR-I change request for SubscriptionStatus. It asked whether a heartbeat is still required when an event notification is sent during the heartbeat interval, and the approved resolution replaced the old one-heartbeat-per-interval sentence with an inactivity-based rule: there should not be a period equal to the heartbeat interval without at least one notification, either event-notification or heartbeat.

Initial application:
The issue was already applied in core source before this reconciliation. Jira records PR HL7/fhir#3967, and git commit 3b33a86e93c7826be974191118e4d83c2824b953 changed source/subscriptionstatus/subscriptionstatus-notes.xml from the old per-interval wording to the approved inactivity/any-notification clarification. No prior AutoFHIR reconciliation commit with Issue-Reconcile-Key: FHIR-47357 was present on the combined branch.

Additional context:
source/fhir.ini actively lists subscriptionstatus=SubscriptionStatus, so source/subscriptionstatus/subscriptionstatus-notes.xml is in the current build scope. FHIR-I minutes for 2025-03-31 record the Subscriptions block vote including FHIR-47357 as Persuasive with a 17-0-0 motion, and Zulip search found the matching block-vote announcement but no conflicting substantive discussion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active SubscriptionStatus heartbeat notification section already says servers SHOULD send a heartbeat notification whenever the channel has been inactive for the specified amount of time, and that a 60-second interval means no 60-second period passes without at least one event-notification or heartbeat.

Recommendation:
Keep this empty audit commit as-is. No further core source change is needed for FHIR-47357 unless the work group separately chooses broader editorial cleanup of neighboring subscription channel examples.
