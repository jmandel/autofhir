FHIR-14499: Audit Encounter class wording

Issue request:
FHIR-14499 was a Published/Persuasive PA change request for STU3. It asked to replace the misleading Encounter.class code-list-style definition, "inpatient | outpatient | ambulatory | emergency +", with text that treats ambulatory/outpatient as one concept and notes local variation, and to make the same correction on class history.

Initial application:
Git history shows commit 4fdf85c350a3a25537f1e0ac9dc514feaf42f41a, "GF#14499:Encounter.class description updated GF#14477:Encounter.serviceType binding fixed", changed the old spreadsheet source for Encounter.class from the code list to the requested replacement text. The old classHistory.class text appears to have survived historically until the FHIR-14157 refactor removed Encounter.classHistory from Encounter in favor of EncounterHistory.

Additional context:
The current build source is source/encounter/structuredefinition-Encounter.xml, because source/fhir.ini has an active [resources] entry encounter=Encounter. The current Encounter.class definition already contains the Jira replacement text, and the stale code-list phrase is absent from current Encounter and Appointment sources except for generated SVG titles that mirror the correct source text. Encounter.classHistory is not a current core element; source/fhir.ini records the migration to EncounterHistory, and no source/encounterhistory resource remains in this core checkout. Later Encounter.class work such as FHIR-32341 changed cardinality/binding/value-set policy but did not reintroduce the stale list or conflict with the resolved FHIR-14499 wording. Zulip and Confluence searches found no FHIR-14499-specific discussion that changes this conclusion.
