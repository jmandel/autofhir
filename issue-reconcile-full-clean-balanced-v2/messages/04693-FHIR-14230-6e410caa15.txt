FHIR-14230: Audit Encounter long-stay class decision

Issue request:
FHIR-14230 was a Published PA change request asking for Encounter classification to distinguish long-term stay or extended-stay inpatient/non-acute encounters. The final Persuasive with Modification resolution assumed the request concerned Encounter.class, explicitly declined to add a long-term-care code, and said the issue was addressed by FHIR-32341's preferred binding and refined Encounter.class value set that can grow over time.

Initial application:
No source commit tagged FHIR-14230 was found. The substantive application path is the related FHIR-32341 work: commits 868cd2a065ac80c8aa8e31f2659b1fd690dde6ec and bf06a893cc2a2f5b883600f8790fbf7d01c450ca changed Encounter.class to CodeableConcept 0..*, changed its binding strength to preferred, and moved it to the new EncounterClass/encounter-class value set. FHIR-32342 separately supports the CodeableConcept data type change.

Additional context:
The PA 2022-06-01 minutes repeat the FHIR-14230 decision: adding long-term stay would reintroduce mixed concepts such as expected length of stay, so the group preferred separate/discrete fields over another Encounter.class code. FHIR-32974 later raised the same long-term-care and ambiguity concern and was closed as a duplicate after FHIR-32341. FHIR-39147 subsequently repaired the value set URL to the current http://terminology.hl7.org/ValueSet/encounter-class canonical. Zulip discussion around Epic use of Encounter.class also confirms the R4 value set and 1..1 Coding problems were understood and expected to change in R5.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active build includes Encounter, and the current source has Encounter.class as 0..* CodeableConcept with a preferred binding to http://terminology.hl7.org/ValueSet/encounter-class, preserving local/discrete classification flexibility without adding a long-term-care code contrary to the recorded PA decision.

Recommendation:
Keep this audit commit as-is. Further work to model expected duration, level of care, place of service, or long-term-care classification should be raised as a new PA terminology/modeling issue with a concrete proposal for separate fields or value set expansion rather than by reopening FHIR-14230.
