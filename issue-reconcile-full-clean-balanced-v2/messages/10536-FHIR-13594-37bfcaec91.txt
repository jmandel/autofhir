FHIR-13594: Audit unique Turtle backbone identifiers

Issue request:
FHIR-13594 was a Published/Persuasive FHIR-core technical correction from STU3 asking that fhir.ttl stop using shared BackboneElement class identifiers such as fhir:DiagnosisComponent for different resource-specific inner components. The requested fix was to prefix component names with the resource path so EpisodeOfCare.diagnosis, Claim.diagnosis, ExplanationOfBenefit.diagnosis, Encounter.diagnosis, and similar backbones would not collapse into one hodge-podge class.

Initial application:
The issue appears to have been applied by historical commit 99d996178dbd5412f38eaf881928cbec99441533, whose subject explicitly says it fixes issues 13594 and 13595 and whose FhirTurtleGenerator patch changed backbone class naming to map component names through the base resource name before emitting class definitions. FHIR-I minutes later recorded FHIR-13594 as a tooling issue with a "Will fix" disposition before Jira publication.

Additional context:
The current checkout no longer contains the old FhirTurtleGenerator source, and the fhir.ttl ontology is generated by current publisher tooling from active build-scope resource definitions. source/fhir.ini actively includes Encounter, Claim, ExplanationOfBenefit, and EpisodeOfCare, and their StructureDefinition source files define the diagnosis backbone paths separately. Current build.fhir.org fhir.ttl output uses path-qualified classes such as fhir:EpisodeOfCare.diagnosis, fhir:Claim.diagnosis, fhir:ExplanationOfBenefit.diagnosis, and fhir:Encounter.diagnosis, with no fhir:DiagnosisComponent occurrence in the downloaded ontology.

AutoFHIR reconciliation:
No source change was made. The current generated ontology already avoids the old non-unique BackboneElement identifiers, and the active source model preserves the separate resource-specific backbone paths that feed those generated class names.

Recommendation:
Keep this audit commit as-is. No FHIR source follow-up is needed for FHIR-13594 unless a future RDF/OWL generator refactor reintroduces shared component-only class names for distinct backbone elements.
