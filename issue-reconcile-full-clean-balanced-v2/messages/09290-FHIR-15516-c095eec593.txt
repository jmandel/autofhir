FHIR-15516: Audit Device identifier guidance

Issue request:
FHIR-15516 was Published with a Persuasive with Modification OO resolution for R5. It asked to remove Device narrative that could be read as allowing GTINs, catalog numbers, or reference numbers to be sent in Device.identifier, because Identifier is for actual identifiers of a specific device instance while kind-level concepts belong in coded/type representations.

Initial application:
Commit 63ae64a20a96b5e193e6f0f11f509c1f7cb617bf pre-applied GF#15516 in March 2018 by replacing separate Device Types and Device Identifiers notes with the current Device Identifier and Device Type guidance. That text says Device.identifier is only for actual identifiers for a specific device instance, and that reference numbers, catalog numbers, and GTINs describe a kind of device and are represented through Device.type. Jira later marked the issue Applied/Published after noting the Device/DeviceDefinition separation had put the issue to rest.

Additional context:
The current build actively includes both Device and DeviceDefinition. Current Device narrative further distinguishes Device instances from DeviceDefinition kinds, and the active Device.identifier ElementDefinition comment says barcode strings may identify an instance, local name, or type and that type-identifying values should use Device.type. A later published FHIR-29312 reconciliation clarified related Device and DeviceDefinition identifier relationships without reversing the FHIR-15516 distinction. Related FHIR-15512 was resolved no-change/Not Persuasive for core and sent GTIN terminology-system handling to THO/UTG rather than changing Device source.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current Device source already removes the misleading implication that kind-level codes belong in Device.identifier, and the remaining text is build-scoped, consistent with current Device/DeviceDefinition boundaries, and reinforced by the active StructureDefinition comments.

Recommendation:
Keep this audit commit as-is. Do not add redundant Device text for FHIR-15516; future work should use a new tracker if OO wants to change the broader Device.type versus DeviceDefinition.classification guidance or THO/UTG terminology treatment of GTINs.
