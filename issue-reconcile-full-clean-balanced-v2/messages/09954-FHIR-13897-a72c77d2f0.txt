FHIR-13897: Audit bodyweight category slicing

Issue request:
FHIR-13897 was a Published/Persuasive STU3 OO change request for the Body Weight profile. It noted that bodyweight required the vital-signs Observation.category by invariant rather than by fixed values and asked for the easier fixed-value representation. The accepted resolution said a simple fixed value or pattern would not allow alternative codings without slicing, that the invariant was equivalent to slicing, and that the R4 update should use slicing with a fixed-value discriminator.

Initial application:
No source commit explicitly mentioning FHIR-13897 was found in the current repository history. The current source no longer has the old bodyweight-specific category invariant: bodyweight derives from the active Vital Signs Base Profile, and that base profile carries an open Observation.category slice for the vital-signs category. Historical source checks show the R4B-era vital-signs source introduced the shared category slice inherited by bodyweight, with later R6 vital-signs rework preserving the inherited category-slice approach.

Additional context:
The current bodyweight profile is in build scope through the active Observation resource and the Observation Vital Signs implementation guide. Later vital-signs work, especially FHIR-46418 and FHIR-50705, reworked how specific vital-sign LOINC semantics are represented and moved those semantics back to Observation.code, but the base vital-signs category slice remains. Current bodyweight also has a vsp-4 invariant, but that later invariant is for value-or-dataAbsentReason behavior from FHIR-36401, not the old category invariant described by FHIR-13897.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source satisfies the FHIR-13897 decision by using inherited open slicing on Observation.category with a vital-signs pattern slice rather than a bodyweight-local invariant or a closed fixed coding that would forbid alternate codings.

Recommendation:
Keep this audit commit as-is. Do not duplicate the inherited vital-signs category constraint in the bodyweight differential; doing so would add redundant maintenance surface without changing implementer semantics.
