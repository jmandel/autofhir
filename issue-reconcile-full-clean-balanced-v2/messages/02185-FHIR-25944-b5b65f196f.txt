FHIR-25944: Audit medication package amount clarification

Issue request:
The Published FHIR-25944 Jira was Persuasive with Modification for R5 and asked Pharmacy to clarify whether MedicationKnowledge.amount and MedicationKnowledge.packaging.quantity meant the same thing, with the resolution to rename amount to totalVolume and use the short description "When the specified product code does not infer a package size, this is the specific amount of drug in the product." The related artifacts were Medication and MedicationKnowledge.

Initial application:
The issue appears to have been applied by git commit 6cdd7b792e2241b7191584bd35915d4b0f9841f8, which renamed Medication.amount and MedicationKnowledge.amount to totalVolume and updated the short and definition text to match the Jira resolution. That commit did not leave the old amount element names in the current source.

Additional context:
MedicationKnowledge was refactored shortly after the original application by 6422f2f98a0fcf03140c15fe93bfd6c765fc6377, removing its totalVolume element as part of splitting definitional product content away from MedicationKnowledge. Current MedicationKnowledge instead keeps packaging as pricing/package context and points to PackagedProductDefinition for package details. Later Medication work also changed Medication.totalVolume into Medication.packageSize with numberOfItems and amountPerItem under FHIR-46416; that related issue is already represented on the combined branch, so this audit does not duplicate it. The original Zulip thread confirms the ambiguity that led to FHIR-25944, and no direct Confluence reference to FHIR-25944 was found.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because the current build source has no Medication.amount, Medication.totalVolume, MedicationKnowledge.amount, MedicationKnowledge.totalVolume, or MedicationKnowledge.packaging.quantity element to correct. The active Medication source now uses Medication.packageSize to describe package amount, and active MedicationKnowledge packaging points to PackagedProductDefinition rather than carrying the old ambiguous amount field.

Recommendation:
Keep this audit commit as-is. Do not reintroduce totalVolume or duplicate explanatory prose for FHIR-25944; any remaining package-size design questions belong with the later Medication.packageSize issue family, especially FHIR-46416, which has already been audited separately on the combined branch.
