FHIR-10481: Audit QuestionnaireResponse recursion model

Issue request:
FHIR-10481 was Published with a Not Persuasive with Modification resolution. It asked to collapse QuestionnaireResponse nesting to a single recursion point by eliminating QuestionnaireResponse.item.answer.item; the approved disposition rejected that removal because items must be able to nest under answers for repeating questions and under items for groups, and called for an invariant preventing item and answer from appearing together.

Initial application:
Git 9f82d09805 applied the issue in the historical spreadsheet source by adding the QuestionnaireResponse.item invariant with expression (answer.exists() and item.exists()).not(). The current XML StructureDefinition, produced after later source refactors, still contains qrs-1 with the same rule and applies it to QuestionnaireResponse.item.answer.

Additional context:
Later final issues in the same family did not reverse FHIR-10481. FHIR-12071, FHIR-20768, FHIR-31357, and FHIR-38853 added or refined guidance explaining that item.item is for groups and item.answer.item is for child items under question answers. QuestionnaireResponse remains active in source/fhir.ini, and both the 2016 origin Zulip thread and later Questionnaire stream discussion document the same rationale and confusion addressed by the current guidance.

AutoFHIR reconciliation:
This audit commit makes no source change. The current source preserves both recursion points, carries the qrs-1 invariant required by FHIR-10481, and includes later explanatory guidance that makes the retained model understandable.

Recommendation:
Keep this audit commit as-is. Do not remove QuestionnaireResponse.item.answer.item for FHIR-10481; any future simplification would require a new work-group decision because it would alter the approved nesting semantics for repeated question answers.
