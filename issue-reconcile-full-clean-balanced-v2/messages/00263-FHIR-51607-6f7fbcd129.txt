FHIR-51607: Link published compartment extension

Issue request:
FHIR-51607 was Applied/Persuasive with Modification for R6 and asked FHIR-I to document how compartments are expanded for post-R6 additional resources. The accepted resolution was to use a repeatable additional-resource-compartment extension on StructureDefinition, with component slices for the compartment, membership search parameters, documentation, and $everything start/end parameters.

Initial application:
The issue was initially applied by commit 4de188291bd8efb31b20585b6270ceb8c5d0da94, which added a bullet to the active StructureDefinition additional-resource rules saying that compartments are defined with the additional-resource-compartment extension. That application pointed to the right canonical URL but described the extension as yet to be published.

Additional context:
The StructureDefinition and CompartmentDefinition resources are active in source/fhir.ini, so the StructureDefinition narrative is current build source. The FHIR Extensions Pack now publishes http://hl7.org/fhir/StructureDefinition/additional-resource-compartment as version 5.3.0, and the local extension-pack source contains the extension with the compartment, param, documentation, startParam, and endParam slices. FHIR-50848 is the earlier same-change-family decision that introduced the extension and explains that servers have discretion to support additional resources in compartments until a resource moves into FHIR Core. FHIR-51604 is supporting context for the role of HL7-defined CompartmentDefinition instances.

AutoFHIR reconciliation:
This commit removes the stale "yet to be published" qualifier from the core StructureDefinition narrative and turns the extension name into a canonical link. No CompartmentDefinition instance content was changed, because post-R6 additional-resource compartment membership is represented by the published extension rather than by editing the current core compartment definition instances.

Recommendation:
Keep this commit as-is. The current core source now points to the published extension without stale publication caveats; any future refinements to the extension's detailed cardinalities or context constraints should be handled in the FHIR Extensions Pack/tooling IG source rather than by duplicating those details in core narrative.
