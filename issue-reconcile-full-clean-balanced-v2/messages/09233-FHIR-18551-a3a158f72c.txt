FHIR-18551: Audit search method conformance on Search page

Issue request:
FHIR-18551 was a Published/Persuasive with Modification FHIR-core issue asking to add Search-page conformance text for GET and POST search. It was reopened after the linked Zulip discussion and its final 2021-06-14 resolution said: "A server that supports search SHALL support a POST-based search and SHOULD support a GET-based search. Implementation guides may choose to make GET required where needed."

Initial application:
No historical source-changing commit explicitly naming FHIR-18551 was found. The old pre-reopen proposal would have added "SHALL support both" text to the Search page, but the issue was revised before final disposition. The later R5 search-page work introduced GET/POST examples and self-link guidance, then FHIR-39137 moved transport/protocol conformance guidance from source/search.html to active source/http.html.

Additional context:
FHIR-18551 is part of the same search-method clarification family as FHIR-30577, FHIR-31912, FHIR-31943, and FHIR-31944. Later final issue FHIR-31943 superseded the literal POST-SHALL/GET-SHOULD formulation by deciding that servers SHALL support search via GET and POST while using 405 Method Not Allowed when a specific search cannot be processed with the client-supplied method, and not returning 405 for both methods for the same search parameters. FHIR-31944 clarified POST body/query-parameter handling and self links, while FHIR-38994 and FHIR-39137 aligned and moved the HTTP/Search page guidance. The responsible editor later described FHIR-31943 and FHIR-31944 as superseding FHIR-18551 and FHIR-31912.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active build-scope Search page now points readers to the HTTP Search section for protocol details and contains GET/POST-aware examples and self-link rules, while the active HTTP page carries the current GET/POST plus 405 conformance model and method-choice guidance. Adding the seed's literal POST SHALL / GET SHOULD sentence to source/search.html would duplicate protocol text in the wrong page and conflict with later final work-group decisions already represented on the combined branch.

Recommendation:
Keep this audit commit as-is. Future changes to whether GET or POST is required for FHIR search should be handled under a new FHIR-I decision rather than by restoring FHIR-18551's superseded wording to the Search page.
