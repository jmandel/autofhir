FHIR-33319: Audit CodeSystem supplement invariant

Issue request:
FHIR-33319 was a Published/Persuasive FHIR-core CodeSystem technical correction asking for an error invariant so CodeSystem.content = supplement implies CodeSystem.supplements exists, enforcing a supplement rule that previously appeared only in narrative for R4 and earlier.

Initial application:
The change was explicitly applied in git commit 918445a81d8ed5d643fda00b2db872c5901630db, which added csd-4 to source/codesystem/structuredefinition-CodeSystem.xml. A same-day cleanup in e522c99cebff40f73a3dc10a5673ee5ed6e5b2b8 quoted the 'supplement' literal in the FHIRPath expression, and later QA work added a csd-4 failure fixture.

Additional context:
The originating Zulip thread was about CodeSystem supplement wording and led directly to the Jira. Vocab minutes from 2022-04-25 and the May 2022 WGM confirm the rule was considered straightforward: if a resource says it is a CodeSystem supplement, it must say which CodeSystem it supplements. CodeSystem is active in source/fhir.ini, so structuredefinition-CodeSystem.xml is current build source. Nearby FHIR-14356 and FHIR-34326 concern broader supplement maturity and ShareableCodeSystem/content policy and do not alter this invariant.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already has csd-4 as an error constraint with expression "CodeSystem.content = 'supplement' implies CodeSystem.supplements.exists()", marks both CodeSystem.content and CodeSystem.supplements with condition csd-4, retains the narrative supplement rule, and includes a failing invariant-test fixture for supplement content without supplements.

Recommendation:
Keep this no-change audit commit as-is. No core FHIR follow-up is needed for FHIR-33319 unless a future work group decision changes the supplement rule itself.
