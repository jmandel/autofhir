FHIR-49908: Audit Permission scope wording outside core

Issue request:
FHIR-49908 was an Applied FHIR-core Change Request for the Security work group, resolved Persuasive with Modification for R6. It requested clearer Permission scope and boundary wording: Permission holds rules for data and access-request context, expresses who has rights to specific data under specific conditions, can include security labels, requester/user/application/location/organization/purpose/data-sensitivity/timeframe/authorship/Consent status, can permit or deny with residual obligations or filtering, and has a clarified relationship to Consent and security labels.

Initial application:
The requested core source change was applied before this reconciliation. GitHub PR HL7/fhir#3405, merged as d184c744863121ac3e8506c61633e10238e604f2, included FHIR-49908 in its PR body. Its implementation commit 8866264bc8b086d26fb7c53ad0a71e2887e2ee9c changed source/permission/permission-introduction.xml to add the requested Scope and Usage and Boundaries and Relationships language while Permission was an active core resource listed in source/fhir.ini.

Additional context:
Permission is no longer an active resource in this FHIR core checkout. Later commit 0e2a8a7f839d5e1a43787523daccf07d958362f3 removed source/permission, removed Permission from source/fhir.ini, hierarchy.xml, and resourcelist.html, and changed Security module links to the HL7 Data Access Policies IG. The external HL7/data-access-policies source carries the FHIR-49908 scope and boundary wording in input/pagecontent/StructureDefinition-Permission-intro.xml.
