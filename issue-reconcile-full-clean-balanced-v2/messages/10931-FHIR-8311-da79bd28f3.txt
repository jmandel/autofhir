FHIR-8311: Audit primitive StructureDefinition profiles

Issue request:
FHIR-8311 was a Published/Persuasive DSTU1 correction for FHIR-core StructureDefinitions. It reported that primitive StructureDefinition snapshots such as integer were missing inherited Element content, then just id, and that primitive value elements used an unqualified path value instead of the rooted path such as integer.value.

Initial application:
The Jira comment records svn revision 5495. The imported git history includes aa96a27941fb80451355fa2a0ccceaea9ab9f8bd, "#8311 - fix errors in primitive type profiles", which changed the historical ProfileGenerator to add the primitive id snapshot element and to set both differential and snapshot value paths to type.getCode()+".value" instead of "value".

Additional context:
The historical generator path no longer exists in the current checkout, and the datatype hierarchy has since been refactored so primitive datatypes now specialize PrimitiveType or derived primitives rather than Element directly. The active build configuration still includes the primitive/datatype infrastructure and routes PrimitiveType to the current types page. Current generated release history and the live build profiles show primitive snapshots with rooted id and value paths, for example integer.id with base Element.id and integer.value with path integer.value. No Zulip or Confluence evidence was found that changes or reopens this old correction.

AutoFHIR reconciliation:
This audit commit makes no source change because the current specification already preserves the semantic correction requested by FHIR-8311: primitive snapshots include the inherited id element and their value elements are rooted under the primitive type name.

Recommendation:
Keep this no-change audit commit as-is. No core source follow-up is needed unless a future generator or package validation run shows a regression in primitive StructureDefinition snapshot generation.
