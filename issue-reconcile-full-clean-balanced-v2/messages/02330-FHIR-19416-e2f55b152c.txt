FHIR-19416: Add RatioRange denominator constraint

Issue request:
FHIR-19416 was a Published/Persuasive MnM change request raised against STU3 and applied for R5. It requested a datatype for ranges of ratios, using the motivating dose-rate and medicinal-product ingredient use cases, and the final resolution agreed to add RatioRange with lowNumerator, highNumerator, and denominator properties, a shared denominator for the low and high numerators, Range-like low/high ordering, and a Ratio-like rule that the denominator cannot be zero.

Initial application:
The main datatype was applied before this reconciliation. Commit b9fd58139d35c8aa90083ae99a279c8a6d3dd854 added the RatioRange datatype source, fhir.ini datatype entry, datatype narrative, and diagrams. Subsequent commits such as aa11acd4e322ff53f1d98f256f0f975871947ee2, 5e0f53f34a6259fd30253c7d3bca9f09a8fe4bc1, and c4c4334aa5b75c83e90e586565baa5a2e83d3aa4 added RatioRange to Ingredient strength locations for related BRR work. The current source already had lowNumerator, highNumerator, denominator, a numerator/denominator presence invariant, and a low/high ordering invariant, but it did not carry the accepted non-zero denominator constraint.

Additional context:
RatioRange is active current build source through source/fhir.ini, not a retired or generated-only artifact. FHIR-34454 later corrected the RatioRange presence invariant and invariant id prefix; that issue is already represented on the combined branch as a no-change audit and does not supersede the non-zero denominator part of FHIR-19416. FHIR-32404 added examples clarifying RatioRange use, including the strength-range use case. The original Zulip Dose rate thread confirms the shared-denominator range-of-ratios motivation, and the Confluence MnM minutes only identify FHIR-19416 as substantive R5 work; no community evidence was found that rejects the denominator constraint.

AutoFHIR reconciliation:
This commit updates the active RatioRange datatype spreadsheet source by adding a third RatioRange invariant, "Denominator SHALL be non-zero if present", with matching FHIRPath and XPath expressions. It also marks RatioRange.denominator as governed by that invariant, alongside the existing presence invariant. No generated history or diagram-only files were edited.

Recommendation:
Keep this source fix. It completes the accepted FHIR-19416 datatype definition while leaving later, already-audited RatioRange invariant repairs untouched; no additional core issue needs to be decided in this commit.
