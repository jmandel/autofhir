FHIR-15901: Audit inherited narrative link handling

Issue request:
FHIR-15901 was a Published/Persuasive STU3 FHIR-core change request for FHIR-I. It asked the IG Publisher to detect relative hyperlinks inherited in descriptions, comments, and similar narrative elements and rewrite them, for example by adding {{site.data.fhir.path}}, so derived IGs would not produce broken links.

Initial application:
The Jira comments say "already fixed" and no current or historical source commit explicitly mentions FHIR-15901. The local history does show the requested mechanism and related tooling work: commit 1c9659e5d6d32dee144d638e833580eac52524b9 changed generated conformance narrative from ../ to {{site.data.fhir.path}}, and the current CapabilityStatement narrative XSLT retains that setting. A later 2018 IG Publisher link-handling commit touched renderer link context, but it was not issue-tagged and is only supporting evidence that this was tooling behavior rather than profile-page prose.

Additional context:
The current FHIR checkout has no tracked Java IG Publisher sources, so any remaining implementation behavior is outside current core source. The source tree intentionally still uses relative links in many XML narrative fragments; a current check found 327 XML files with 2147 relative .html hrefs. That pattern confirms the issue was not asking to rewrite all core source links. FHIR-I minutes for 2018-08-06 record FHIR-15901 as Persuasive in the block vote, and community searches found no substantive later discussion changing the conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change.
