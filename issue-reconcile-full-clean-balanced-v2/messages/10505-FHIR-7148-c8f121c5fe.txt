FHIR-7148: Audit Observation grouping examples

Issue request:
FHIR-7148 was a Published OO change request with Persuasive with Modification resolution for DSTU1. The issue said the old Observation note about Apgar having both a value and related observations was unclear, and the accepted resolution was to clarify the Observation resource Notes section and point to the existing Glasgow example rather than relying on the unclear Apgar wording.

Initial application:
The issue was applied in 2015 by Observation commits d4505c43ef, 65be721ff9, and 5ed5b573f8, which rewrote the Observation notes/introduction around grouping, related observations, components, and Glasgow/Apgar examples. The final 2015 note text explicitly described assessment scores such as Apgar or Glasgow as observations with both a value and supporting observations/answers, and pointed to the Glasgow coma score example.

Additional context:
Observation is active in source/fhir.ini, so the Observation resource narrative, StructureDefinition source, and examples are current build inputs. Later Observation refactors replaced the old Observation.related model with the current component, hasMember, and derivedFrom guidance. Current source no longer contains the obsolete "Apgar store"/ambiguous related-observation text from the issue. It now explains Observation.component for inseparable component results, including a newborn Apgar score as one Observation with five components, and separately explains hasMember/derivedFrom for independent supporting observations. The Observation introduction still lists clinical assessment tools such as APGAR and Glasgow Coma Score, and the current Glasgow example demonstrates a total score with component measurements. Jira search found only FHIR-7148 for the Apgar/Glasgow grouping query; no Zulip or Confluence references to FHIR-7148 were found, and later community/minutes hits did not reveal a conflicting decision.

AutoFHIR reconciliation:

The current build-scoped Observation source already conveys the clarified distinction that the original tracker requested, with later terminology and modeling updates folded in; adding the old Glasgow prose back into the Notes section would duplicate current guidance and risk contradicting the current component/hasMember/derivedFrom model.

Recommendation:
Keep this audit commit as-is. No follow-up source edit is needed for FHIR-7148 unless OO wants a new, current-cycle change to the Observation component versus hasMember/derivedFrom examples.
