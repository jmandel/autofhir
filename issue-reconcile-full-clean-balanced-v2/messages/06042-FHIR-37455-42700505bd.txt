FHIR-37455: Align conformance resource title metadata

Issue request:
FHIR-37455 is a Published/Persuasive FHIR-I R5 change request asking to add the CanonicalResource-style title property to GraphDefinition and CompartmentDefinition. The accepted resolution agreed to add title to both resources as an editorial choice, while noting that implementing the CanonicalResource pattern did not itself require those resources to define title.

Initial application:
Commit 90d07939a987bed043576d57ff8c79993c06d6e7, titled "FHIR-37455 - Conformance Resource "Title" property missing", added CompartmentDefinition.title and GraphDefinition.title to the resource StructureDefinitions. That application left CompartmentDefinition.title with copied CapabilityStatement definition text, and it did not update the active FHIR ModelInfo Library sidecar used by CQL tooling.

Additional context:
CompartmentDefinition remains active in source/fhir.ini. GraphDefinition no longer has an active core resource source: commit 270e0ceb7b029dad4ca0fc5ccf5296ff370888cd deleted source/graphdefinition, source/fhir.ini has no GraphDefinition resource entry, and the conformance module now points GraphDefinition readers to the API Incubator. The Library examples page and publish.ini make source/library/library-fhir-model-definition-content.xml an active publication surface, and that ModelInfo file still carried CompartmentDefinition and GraphDefinition type entries without title. FHIR-I minutes from 2022-08-01 confirm the 14-0-0 persuasive motion for FHIR-37455; no conflicting Zulip or Confluence discussion was found.

AutoFHIR reconciliation:
Corrected the active CompartmentDefinition.title element definition so it describes a compartment definition rather than a capability statement. Added title to the FHIR ModelInfo class entries for CompartmentDefinition and for the retained GraphDefinition model entry, then refreshed the embedded Library/FHIR-ModelInfo base64 payload so it matches the sidecar content file.

Recommendation:
Keep this commit. It completes the applied FHIR-37455 decision across the current core build surfaces that still carry these resource models, without reopening the broader R6 decision that moved GraphDefinition's authoritative StructureDefinition out of core. Any cleanup of the remaining GraphDefinition ModelInfo entry as an out-of-core type should be handled under a separate issue and evidence trail.
