FHIR-41232: Audit ChargeItem.reason externalization

Issue request:
FHIR-41232 was an Applied/Persuasive PA change request for R6 asking that ChargeItem.reason become 0..* CodeableReference(Condition | DiagnosticReport | Observation | ImmunizationRecommendation | Procedure), while retaining the existing example ICD-10 value set binding.

Initial application:
The request was applied in core by commit 54ef8dc2ad6dbfe5ed6bcbf08e03e3f05812041e, which changed source/chargeitem/structuredefinition-ChargeItem.xml from CodeableConcept to CodeableReference and added the five requested target profiles while keeping the ICD-10 example binding.

Additional context:
ChargeItem is no longer an active resource in this core checkout. Current source/fhir.ini has no ChargeItem entry in the active [resources] list, and the core module pages now link ChargeItem to the Admin Incubator build. Commit 71567db3ee039ac6977be5f96a7e013896569a36 removed the remaining ChargeItem and ChargeItemDefinition source files from core as part of moving immature resources to incubator IGs. The residual library model-definition example uses FHIR 4.0.0 content and is not the current R6 ChargeItem source.

AutoFHIR reconciliation:
No core source was changed. The current Admin Incubator StructureDefinition-ChargeItem.json already defines ChargeItem.reason as CodeableReference with target profiles for Condition, DiagnosticReport, Observation, ImmunizationRecommendation, and Procedure, and keeps the example ICD-10 binding.

Recommendation:
Keep this audit commit as-is. Future ChargeItem.reason changes should be made in the Admin Incubator source rather than reintroducing ChargeItem resource source into FHIR core; no follow-up is needed for this Jira because the external artifact already reflects the applied resolution.
