Issue request:
FHIR-27805 was a Published/Persuasive Vocabulary change request for R5 asking to remove the UMLS note from the FHIR core Terminologies/Code Systems page because HTA agreed the note should no longer tell implementers to mint UMLS-based system URIs for unregistered code systems.

Initial application:
The request appears to have been applied by git commit 2e0905373f66c2bab9a4ad5e396b3b72f804aec7, "Removed UMLS note from terminologies-systems.html", which deleted the exact UMLS Note paragraph from source/terminologies-systems.html and explicitly named FHIR-27805/FHIR-25030. No prior Issue-Reconcile-Key commit for FHIR-27805 was present on the combined branch.

Additional context:
FHIR-25030 is the same removal request from the same page, and Jira comments on the two issues call them duplicates of each other. Vocabulary WG minutes for the 2020-09 WGM record a 17-0-0 motion to approve and apply FHIR-27805 by following the suggested action. The current terminology module links to terminologies-systems.html, so that source page remains in current build scope. Current source still contains legitimate UMLS-hosted URLs for RxNorm and MED-RT table rows, but not the removed guidance note or its Multum example.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already implements the requested removal, and removing the remaining RxNorm/MED-RT UMLS URLs would exceed the issue scope because those are actual external code-system rows rather than the deprecated note.

Recommendation:
Keep this no-change audit commit as-is. No FHIR core source follow-up is needed for FHIR-27805; any broader external terminology authority cleanup should proceed through separate terminology/THO work rather than this resolved note-removal issue.
