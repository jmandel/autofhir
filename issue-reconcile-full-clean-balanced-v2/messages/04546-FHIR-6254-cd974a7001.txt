FHIR-6254: Audit DeviceRequest/SupplyRequest boundary

Issue request:
FHIR-6254 was Published with a Not Persuasive with Modification resolution for the CDS work group. The issue asked whether DeviceUseRequest should be rolled up into the newly created SupplyRequest resource; the approved resolution kept the resource separate and said to add DeviceUseRequest boundaries text explaining that patient-focused device-use requests differ from supply requests for inventory.

Initial application:
The issue was applied in SVN 11310, represented in git as d69f02bc8a0dd13372985d7782a9d00309ad526d. That commit added a DeviceRequest Boundaries and Relationships paragraph distinguishing patient-focused device use and use instructions from SupplyRequest inventory management. DeviceUseRequest had already been renamed to DeviceRequest in 7bf0f7e00f13fcfaec67c9e17d8c89e75f3cf08a, and source/fhir.ini now lists DeviceUseRequest only as a removed resource.

Additional context:
DeviceRequest is still an active current-build resource in source/fhir.ini. The current DeviceRequest introduction describes patient use of a device, explains that getting the device to the patient and fulfillment are handled outside DeviceRequest, and mentions DeviceRequest/SupplyRequest/DeviceDispense/SupplyDelivery only for purchase-date searches. A later Published issue, FHIR-24936, deliberately rewrote healthcare-product scope and boundary text: commit 578361a9000ef12bb67e86de2e5fb27ea52bd79a removed the original FHIR-6254 paragraph from DeviceRequest while keeping the same patient-focus versus inventory-management distinction on the SupplyRequest page. Later commit 3b38b80cf23f9cbb306fab8fcedb293315478c32 removed SupplyRequest from the active core resource list while retaining the source files as inactive evidence.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active DeviceRequest source still conveys the core FHIR-6254 decision that DeviceRequest is a patient-focused device-use request, not a rolled-up inventory supply request, and the missing exact 2017 paragraph is explained by later FHIR-24936 boundary refactoring plus SupplyRequest's removal from the active core build. Re-adding the old paragraph to DeviceRequest would duplicate or partially undo later resource-boundary work rather than correct a current semantic defect.

Recommendation:
Keep this no-change audit. If the work group wants renewed cross-resource guidance now that SupplyRequest is outside the active core build, handle that as a new DeviceRequest/SupplyRequest boundary issue rather than replaying the DSTU1 wording from FHIR-6254.
