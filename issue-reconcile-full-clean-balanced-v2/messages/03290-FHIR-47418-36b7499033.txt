FHIR-47418: Audit unresolved Device conformsTo source

Issue request:
FHIR-47418 was an Applied FHIR-core Device change request with a Persuasive with Modification disposition. It asked why DeviceDefinition.conformsTo has a .source sub-element while Device.conformsTo does not, and the approved resolution was to create a 0..* RelatedArtifact extension named device-conformsTo-source rather than adding a core Device element.

Initial application:
The core source was first updated by 3cf635fa2b606d038462a683a53338e39b3f30e3, which mentioned FHIR-47418 and added Device narrative saying a future Extension Pack extension named device-conformsTo-source would represent the source of the specification. The Extension Pack then added a dedicated Device conformsTo/source extension in 111e802281e2d905a2ef9b01afb0c9521814643b, but that extension was later deleted by 851bff493d798ea321e33df2c5c99e152fe9d927 as incorrectly implemented and not yet published.

Additional context:
Later Extension Pack ballot issues changed the interpretation. FHIR-52946 removed the overlapping Device-conformsTo extension, and FHIR-52979 added core Device notes saying Device.conformsTo could use artifact-relatedArtifact for FHIR R5 and later. FHIR-56072 then reopened and closed that artifact-relatedArtifact approach as Not Persuasive because RelatedArtifact could make the meaning of conformsTo ambiguous. The follow-up core issue FHIR-56683 is still Triaged and explicitly asks the work group to choose between a dedicated conformsTo-source extension and a direct Device.conformsTo.source element.

AutoFHIR reconciliation:
This is an empty human-review audit commit. Device and DeviceDefinition are active core resources, and the current source still has divergent text: DeviceDefinition.conformsTo.source exists, Device.conformsTo has no source child, Device notes point to artifact-relatedArtifact, and Device introduction still names device-conformsTo-source. Updating the core source now would require choosing one of the unresolved FHIR-56683 options or removing guidance without an approved replacement.

Recommendation:
Keep this audit commit as a marker that FHIR-47418 is not safely reconcilable by automation. The work group should resolve FHIR-56683, then update the core Device notes/release text and the Extension Pack consistently so implementers have one approved way to represent the source supporting Device.conformsTo.
