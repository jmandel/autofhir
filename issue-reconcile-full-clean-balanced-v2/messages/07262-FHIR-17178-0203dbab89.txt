FHIR-17178: Audit DocumentReference generate operation

Issue request:
FHIR-17178 was a Published/Persuasive FHIR-core DocumentReference change request. It objected that the old DocumentReference generate behavior was described as a GET named query using _query=generate even though generating a new resource can affect server state, and it requested a formal DocumentReference $generate OperationDefinition that only supports POST plus removal of the old _query narrative.

Initial application:
The issue appears to have been applied for R5. Commit 3c56ef94e5 commented the old DocumentReference "Generating a Document Reference" narrative as moved to a formal operation, and subsequent R5 source produced an OperationDefinition/DocumentReference-generate with kind=operation, affectsState=true, code=generate, resource=DocumentReference, and a POST example. The old GET _query=generate text remains only inside an XHTML comment in documentreference-notes.xml.

Additional context:
Later published issues FHIR-34043 and FHIR-39624 refined the same $generate OperationDefinition parameters; both already have reconciliation commits on the combined branch and current source reflects their fixes with persist:boolean and return:Bundle. The current R6 ballot intro and commit 3b38b80cf2 also record that DocumentReference.$generate has been moved out of the core specification/API surface toward the API incubator, and the current DocumentReference operations list no longer lists DocumentReference-generate.

AutoFHIR reconciliation:
This commit intentionally makes no source change. In the current core source, there is no active DocumentReference GET _query=generate guidance to remove, the historical R5 OperationDefinition satisfies the POST-only semantics through affectsState=true and the general operations rules, and re-adding DocumentReference-generate to the current DocumentReference operation list would conflict with the later explicit move out of core.

Recommendation:
Keep this audit as-is for FHIR-17178. If the R6 API-incubator move is revisited, handle that as a separate current-scope issue; do not use FHIR-17178 to restore the core operation list entry or to edit the commented historical narrative.
