FHIR-25086: Remove stale special designation ModelInfo

Issue request:
FHIR-25086 was Published/Persuasive for R5 and asked BR&R to remove MedicinalProductDefinition.SpecialDesignation because orphan/special designation is a special case of RegulatedAuthorization, with narrower details such as species, indication, and intendedUse handled there or by extensions.

Initial application:
The issue was explicitly applied in commit d017cd22c28c50b2e285e0a2b5dc87edcc6dbb71, which removed the MedicinalProductDefinition.specialDesignation spreadsheet rows alongside FHIR-25067 product cross-reference work. The current authoritative MedicinalProductDefinition StructureDefinition no longer contains specialDesignation, while RegulatedAuthorization exposes subject, type, indication, and intendedUse and the regulated authorization type codes include Orphan Drug Authorization.

Additional context:
source/fhir.ini keeps MedicinalProductDefinition, RegulatedAuthorization, and Library in the current build, and publish.ini plus the Library example list publish Library/FHIR-ModelInfo and its readable XML content. Neighboring AutoFHIR commits have treated this FHIR 6.0.0 ModelInfo payload as an active computable specification surface. Before this reconciliation, that surface still exposed the old MedicinalProduct.specialDesignation member and MedicinalProduct.SpecialDesignation backbone type, even though the current resource definition had already removed the special designation concept. No Zulip or Confluence search found a conflicting community decision.

AutoFHIR reconciliation:
Removed the stale specialDesignation member and MedicinalProduct.SpecialDesignation type from source/library/library-fhir-model-definition-content.xml, and refreshed the embedded base64 payload in source/library/library-fhir-model-definition.xml so the active ModelInfo Library no longer advertises the removed special designation surface.

Recommendation:
Keep this source fix as-is. It completes FHIR-25086 in the active ModelInfo publication surface without attempting broader legacy MedicinalProduct* ModelInfo renaming or reconstruction that is outside this issue's requested special-designation removal.
