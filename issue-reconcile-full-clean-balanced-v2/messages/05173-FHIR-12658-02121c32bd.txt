FHIR-12658: Clarify Account coverage priority ordering

Issue request:
FHIR-12658 was a Published FHIR-core Account change request from Patient Administration, resolved Persuasive with Modification for DSTU2. It asked to replace Account's direct 0..* Coverage reference with a 0..* Account.coverage BackboneElement containing Account.coverage.coverage 1..1 Reference(Coverage) and Account.coverage.priority 0..1 positiveInt, using the v2/alias concept "coordination of benefit priority" and applying the lowest value first; it also requested renaming coveragePeriod to period.

Initial application:
The historical Jira-tagged commit bbaf6a813fd0003b8dc83473640dc4a5392adee8 ("Tracker# 12658 (and other Account QA issues)") applied the backbone shape in the spreadsheet-era Account source and changed examples from a direct Coverage reference to nested coverage plus priority. The later source-generation/refactor commits preserved Account.coverage, Account.coverage.coverage, and Account.coverage.priority in source/account/structuredefinition-Account.xml. However, the applied element text carried the priority element and examples but did not preserve the resolution's explicit "lowest value first" ordering rule.

Additional context:
Account is an active current-build resource in source/fhir.ini. FHIR-14813 later renamed the FHIR-12658-era Account.period element to Account.servicePeriod and is already represented on the combined branch, so the current servicePeriod name is a deliberate later PA decision rather than a FHIR-12658 miss. Later FM issue FHIR-27107 and applied issue FHIR-43028 discuss Coverage.order versus Account.coverage.priority; FHIR-43028 is already represented on the combined branch and confirms that Account.coverage.priority is the use-case-dependent account-context ordering point. Direct Zulip and Confluence searches for FHIR-12658 found no conflicting community record.

AutoFHIR reconciliation:
This commit updates the active Account StructureDefinition source so Account.coverage.priority says lower values are applied first. No generated diagram-only files were edited; the change is limited to the authoritative source element definition needed to carry the approved ordering semantics.

Recommendation:
Keep this source fix. It completes the missed semantic detail from FHIR-12658 while preserving later Account.servicePeriod and Coverage.order decisions; no further FHIR core follow-up is needed unless PA/FM later changes the Account/Coverage ordering model.
