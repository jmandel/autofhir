FHIR-7609: Audit Patient care provider clarification

Issue request:
FHIR-7609 was a Published/Persuasive Patient Administration change request from the DSTU1 ballot asking what "nominated care provider" meant on Patient.careProvider and whether it meant the primary care provider. The accepted disposition clarified that the property represents patient-selected/nominated/chosen care provider(s), including a primary care provider in a GP context, a nominated care manager in community/disability settings, or an organization, and said the definition and detailed description would be updated.

Initial application:
The issue appears to have been applied in git commit 58cf0bc95a, titled "Tracker# 7558, 7609, 7610 Ballot recon." That commit added the detailed description/comment explaining primary care provider, nominated care manager, and organization use cases to the Patient careProvider row, while leaving the compact definition text as "Patient's nominated care provider."

Additional context:
Current source/fhir.ini lists Patient as an active resource, so source/patient/structuredefinition-Patient.xml is in the current build. Later PA decisions refined the same element family: FHIR-8315 narrowed the element away from general care-team membership and toward primary care provider(s); FHIR-7963, already represented on the combined branch, renamed Patient.careProvider to Patient.generalPractitioner while retaining careProvider as an alias; and FHIR-14442 added current guidance for multiple GPs. The current element short says "Patient's nominated primary care provider," the comment gives the FHIR-7609 examples and excludes CareTeam use, and the target types include Organization, Practitioner, and PractitionerRole.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Although the standalone definition remains concise, the build-scoped element now carries the approved clarification in the same ElementDefinition comment and the later approved rename/short/comment make the current implementer meaning clear without duplicating more prose into the definition.

Recommendation:
Keep this no-change audit as-is for FHIR core. If Patient Administration wants the formal ElementDefinition.definition text itself to restate the comment, that would be an editorial follow-up, but the current specification already conveys the FHIR-7609 rule and later PA narrowing decisions.
