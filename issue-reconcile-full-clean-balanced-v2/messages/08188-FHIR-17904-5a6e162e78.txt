FHIR-17904: Audit Parameters Schematron invariant

Issue request:
FHIR-17904 was a Published/Persuasive STU3 technical correction for the Parameters resource. It reported that the generated Schematron/XPath for Parameters.parameter inv-1 did not mention part and did not handle value[x], despite the invariant requiring exactly one of value, resource, or part.

Initial application:
The Jira comment records GH#77ddcee8c1, and commit 77ddcee8c196f3bef6272633211decb7b5bafac7 changed the old source/parameters/parameters-spreadsheet.xml XPath cell from the resource/value-only expression to an expression that referenced resource, part, and value[x] choice elements.

Additional context:
Parameters is still in current build scope through source/fhir.ini, where parameters=concrete,Parameters appears under resource-infrastructure. The old spreadsheet source was replaced by source/parameters/structuredefinition-Parameters.xml in the 2021 source refactor. The current StructureDefinition keeps the correct FHIRPath invariant and has no xpath element for inv-1 because commit 88a1f3d6bd60f7618ae140179b008ac5686e8a08 removed XPath usage from ElementDefinition constraints. A later Zulip R4 Schematron thread noted that published R4 Schematron downloads still had malformed generated assertions, but no current Parameters Schematron file or current XPath source remains in this checkout.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The authoritative current Parameters source has the inv-1 FHIRPath expression and no obsolete Schematron/XPath expression to correct, so editing current source would be redundant and editing historical generated Schematron downloads is outside this current-build reconciliation.

Recommendation:
Keep this no-change audit. If historical STU3/R4 downloadable Schematron artifacts need correction, handle that as an archive erratum or publication-maintenance task rather than a current core source edit.
