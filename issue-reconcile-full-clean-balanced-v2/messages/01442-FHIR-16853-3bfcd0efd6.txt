FHIR-16853: Audit MeasureReport pending result guidance

Issue request:
FHIR-16853 was a Published/Persuasive CQI change request from STU3 asking that $evaluate-measure support returning a reference to where a MeasureReport is stored, with the accepted resolution to document that the operation result may have status Pending when the report is still being generated.

Initial application:
The issue was applied by git commit a4108a4527ee7c42c72d30079f4db07690281cfd, "GF#16853: Clarify asynchronous behavior of MeasureReport", which added current-quality-reporting guidance that implementations may return a MeasureReport with status pending and clients can poll until it becomes complete. Jira also records SVN 14856 for the application.

Additional context:
The current build-scope Measure and MeasureReport sources still carry the resolved behavior. The clinical reasoning Quality Reporting page is listed from source/hierarchy.xml and says a MeasureReport may be returned with status pending while evaluation is in progress. MeasureReport.status includes the pending code and defines pending as an in-progress report that should later become complete or error. Later issue FHIR-37988 changed $evaluate-measure results from a single MeasureReport to Bundles containing MeasureReports, and later issue FHIR-51487 refocused the operation return documentation on Bundle structure while linking to the Quality Reporting guidance that retains the pending-status rule.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current specification already conveys the accepted FHIR-16853 rule through active narrative and the MeasureReport.status definition, and adding another pending-status sentence to the operation return parameter would duplicate nearby guidance after later return-shape corrections.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-16853 unless CQI decides that the operation parameter text should redundantly restate the pending-status polling behavior despite the existing Quality Reporting guidance.
