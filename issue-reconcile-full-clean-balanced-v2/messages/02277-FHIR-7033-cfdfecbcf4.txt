FHIR-7033: Audit Composition document signature note

Issue request:
FHIR-7033 was a Published/Persuasive with Modification DSTU1 Composition issue asking for more documentation of the `$document` operation's `cert` parameter, noting that it represented a keychain/private key capability and recommending that signature generation be handled by the client or moved out of core. The final resolution was to remove the parameter and leave a note that document signature generation remained an open issue for DSTU 2.

Initial application:
The issue appears to have been applied in svn revision 6194, preserved in git as 82c930a9240ac787a4ba7d7c36c4b1a2977280cf. That commit removed the `document.cert` and `document.pword` rows from the Composition operation spreadsheet and added a note that the operation does not resolve how document signatures are created.

Additional context:
Composition is in the active build (`source/fhir.ini` lists `composition=Composition`, `Composition=cmp`, and `Composition=approved`), and the current operation source is active through `source/composition/list-Composition-operations.xml`. Later refactors moved the operation from the spreadsheet to `source/composition/operationdefinition-Composition-document.xml` while preserving the signature-generation note; `source/composition/composition-notes.xml` also carries the same current trial-use note. Searches found no Zulip or Confluence discussion that changes the Jira/source conclusion.

AutoFHIR reconciliation:
No source change was made. The current `$document` OperationDefinition has only `persist`, `graph`, and `return` parameters, with no `cert`, `pword`, keychain, private-key, or passphrase parameter. The current source still tells implementers that document signature generation is unresolved, which satisfies the applied resolution without reintroducing server-side keychain handling.

Recommendation:
Keep this audit commit as-is. Any future decision about fully specifying document signature generation should be handled as a new work-group issue rather than as a FHIR-7033 reconciliation fix.
