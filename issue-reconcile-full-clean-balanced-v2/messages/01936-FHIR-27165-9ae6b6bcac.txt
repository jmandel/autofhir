FHIR-27165: Restore MedicationRequest combo-date search parameter

Issue request:
FHIR-27165 is Published with resolution Persuasive. The Pharmacy WG approved fixing the MedicationRequest date search parameter so that it searches both MedicationRequest.dosageInstruction.timing.event and timing.repeat.boundsPeriod, matching the original implementer discussion that a single parameter should cover a specific administration time or a period.

Initial application:
The issue was applied in git commit a9dffd224e0795a95e525dd761215701cecf804b, which changed the old MedicationRequest date search parameter to combo-date and changed its source path from only dosageInstruction.timing.event to dosageInstruction.timing.event plus dosageInstruction.timing.repeat.boundsPeriod. The later search-parameter bundle source preserved that R5 expression when the build source was reworked.

Additional context:
MedicationRequest is active in source/fhir.ini, and source/compartments.xml still names combo-date as MedicationRequest's compartment date search parameter. Later R6 dosage changes introduced MedicationRequest.effectiveTiming[x] and the DosageDetails datatype, where component Dosage instances now carry timing. During that refactor, commit bc7ac9db4e24a9da9eb639008e70d1dc76b74886 XML-commented out the combo-date entry rather than updating it, leaving the current active source without the search parameter even though the compartment definition still references it.

AutoFHIR reconciliation:
Restored the MedicationRequest-combo-date SearchParameter entry and updated its build path and expression to the current R6 structure: MedicationRequest.effectiveTiming.ofType(Period), MedicationRequest.dosageInstruction.step.component.timing.event, and MedicationRequest.dosageInstruction.step.component.timing.repeat.bounds.ofType(Period). This preserves the FHIR-27165 event-or-boundsPeriod rule while accounting for the later DosageDetails/effectiveTiming refactor.

Recommendation:
Keep this commit as-is. If Pharmacy later changes the R6 dosage model again, review MedicationRequest-combo-date at the same time; otherwise this is the smallest current-source correction that keeps the published FHIR-27165 behavior and the compartment search-parameter reference consistent.
