Issue request:
FHIR-37772 was a Published/Persuasive FHIR-core technical correction raised against R4B after Implementation Guides showed resource.id as datatype string rather than id, with US Core AllergyIntolerance cited as the example. The accepted resolution was that Grahame would include a fix in IG Publisher.

Initial application:
No FHIR-core commit explicitly mentions FHIR-37772. Current core source for Resource.id already carries the FHIR-specific type marker as id while retaining the underlying FHIRPath System.String code used for primitive string-compatible values; the relevant source history shows this representation was present on the current line of development before the Jira was raised, with a later 2022 correction changing the fhir-type extension value element from valueUri to valueUrl.

Additional context:
FHIR-28121, the earlier US Core version of the same observation, was Resolved - No Change because the id element is defined by the IG Publisher and not by US Core profiles, and the commenter was directed to IG Publisher/Zulip. FHIR-I minutes for 2022-08-01 list FHIR-37772 as a technical correction. The current published US Core AllergyIntolerance definitions page now renders AllergyIntolerance.id with Type id, matching the requested display behavior.
