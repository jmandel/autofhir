FHIR-5497: Audit superseded note guidance

Issue request:
FHIR-5497 was a Published/Persuasive DSTU1 MnM ballot issue asking for consistent naming and explanation of free-text comment/note fields across resources, including how those fields differ from Resource.text and whether clinical resources should use a singular note element for additional information.

Initial application:
No source commit explicitly mentioning FHIR-5497 was found. The Jira resolution says the original methodology proposal was superseded by FHIR-7622. FHIR-7622 was later applied in git-svn commit e86f20cfb9b7f9336b4463ff3ee5f44691a937bf, which added the Annotation datatype and active source/fhir.ini registration.

Additional context:
FHIR-7622 replaced the older free-text/string convention with a structured Annotation datatype and note/comment naming guidance. Current source/fhir.ini actively lists Annotation as a datatype, marks it normative, and tracks historical plural-to-singular renames such as Condition.notes to Condition.note and Procedure.notes to Procedure.note. Current source/datatypes/annotation.xml carries the requested narrative-related usage guidance, and representative clinical resources now expose singular note elements as 0..* Annotation. The combined branch already contains a separate FHIR-7622 audit commit, so this seed should not republish that superseding issue.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build source is already correct for FHIR-5497 when interpreted through its superseding FHIR-7622 decision; adding the older methodology text to the Narrative page now would duplicate or partially revive superseded DSTU1 wording rather than fix a current semantic problem.

Recommendation:
Keep this no-change audit as-is. Do not make broad source edits under FHIR-5497; future changes to individual note/comment fields should be handled under element-specific work-group trackers or the already represented FHIR-7622 family.
