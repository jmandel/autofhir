FHIR-13096: Audit DocumentReference non-indexing support

Issue request:
Published FHIR-13096 was a Persuasive with Modification DSTU2 change request for DocumentReference to support use cases beyond indexing, including stand-alone document description. It requested making DocumentReference.indexed and DocumentReference.type optional and adding an unknown DocumentReference.status code; the final decision accepted the indexed/type relaxation and rejected adding unknown because more explanation was needed.

Initial application:
The issue appears to have been applied in git commit 94e532a611046fcdc40df2d7d28457eeb7dad3a6, whose San Diego WGM block-vote message explicitly lists GF#13096. That commit changed the then-authoritative DocumentReference spreadsheet so DocumentReference.type went from 1..1 to 0..1 and DocumentReference.indexed became DocumentReference.date with cardinality 0..1 and an indexed alias. It did not add unknown to DocumentReference.status, consistent with the FHIR-13096 resolution.

Additional context:
DocumentReference is active in source/fhir.ini, and the current source is source/documentreference/structuredefinition-DocumentReference.xml after later source refactoring. It preserves the accepted FHIR-13096 behavior: type is 0..1 and date, carrying the indexed alias, is 0..1. Current status includes unknown, but that comes from later FHIR-55265 R6 work and commit 7cd1e9566c6725346ce5cd318894c8bbabbf6df8, not from FHIR-13096. Related same-change-family issues FHIR-13447 and FHIR-13281 are already represented on the combined branch, so this commit does not duplicate them.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change because the current build source already reflects the accepted FHIR-13096 changes. Removing unknown would be wrong for this seed because the current unknown code is attributable to a later separate work-group decision, not an unapplied part of FHIR-13096.

Recommendation:
Keep this audit commit as-is. No FHIR-13096 follow-up is needed in FHIR-core; any review of the later unknown status code should be handled under FHIR-55265 or its publication workflow, not by reopening this DSTU2 reconciliation.
