FHIR-38048: Audit Device system type wording

Issue request:
FHIR-38048 was Published as Persuasive with Modification for OO. It asked to fix the Device.specialization.systemType descriptions because the R5 ballot text reused the Device.property wording; the accepted resolution was to describe a code for the system that identifies the specific standard that the device adheres to.

Initial application:
The wording was first preapplied in commit 0d858aae58, replacing the copied Device.property text with specialization-specific wording, and then refined in commit 5e493f88ee to the Jira comment's short and definition. Later Device refactoring kept that applied definition while renaming the element family.

Additional context:
OO minutes for 2022-09-12 record the persuasive-with-modification vote and note the proposal was not perfectly clear but should be synchronized with the R5 ballot. Later Published issues FHIR-39084 and FHIR-39242 renamed Device.specialization to Device.conformsTo and systemType to specification so the current build no longer has Device.specialization.systemType as an element. The combined branch already has separate audit/fix commits for FHIR-39084, FHIR-39242, and the nearby FHIR-38109 Device QA issue.

This commit intentionally makes no source change. Recommendation:
Keep this audit commit as-is. No additional core source edit is needed for FHIR-38048 unless a future work group decision reopens the broader Device conformsTo wording.
