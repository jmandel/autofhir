FHIR-33950: Audit DeviceDefinition marketDistribution cardinalities

Issue request:
FHIR-33950 was Published/Persuasive for R5 by OO. It complemented FHIR-32976 and requested that the DeviceDefinition.udiDeviceIdentifier.marketDistribution sub-elements marketPeriod and subJurisdiction have minimum cardinality 1, because a marketDistribution should always identify at least a starting period and a sub-jurisdiction.

Initial application:
FHIR-32976 first introduced marketDistribution with marketPeriod and subJurisdiction as optional sub-elements. Git commit f8cefe81c5c2e493801523aa01875296c7e79243, titled "Fix #33950", then changed the current source for DeviceDefinition.udiDeviceIdentifier.marketDistribution.marketPeriod and .subJurisdiction from min 0 to min 1. Current blame still attributes those min lines to that commit.

Additional context:
DeviceDefinition is active in source/fhir.ini, so source/devicedefinition/structuredefinition-DeviceDefinition.xml is in current build scope. The current packaging.udiDeviceIdentifier element uses a contentReference to #DeviceDefinition.udiDeviceIdentifier, so the mandated marketDistribution child cardinalities are inherited rather than repeated in a separate packaging child subtree. FHIR-34840 later corrected the marketDistribution definition text without changing these cardinalities. OO Confluence minutes from 2021-10-01 and 2021-10-08 confirm that marketDistribution itself should remain 0..* while marketPeriod and subJurisdiction should be 1..1, and Zulip searches found no conflicting discussion.

AutoFHIR reconciliation:
No source change was made. The active current source already has marketPeriod and subJurisdiction at min 1/max 1 under DeviceDefinition.udiDeviceIdentifier.marketDistribution, matching the published Jira request, and packaging inherits the same backbone through contentReference.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-33950 in core unless a separate future issue changes the DeviceDefinition UDI or packaging contentReference model.
