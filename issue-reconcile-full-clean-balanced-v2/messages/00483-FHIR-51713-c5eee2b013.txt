FHIR-51713: Audit DeviceUsage partOf externalized

Issue request:
FHIR-51713 was an Applied/Persuasive OO change request for R6 asking to add DeviceUsage.partOf from the Event pattern: 0..* Reference(DeviceUsage), summary=true, short "Part of referenced device usage", definition text for a larger event of which the usage is one part, and a workflow mapping to Event.partOf.

Initial application:
The request was initially applied in core commit f1b8e124e66f8a524a5d8a47e41f0ed78554c31d, which added DeviceUsage.partOf and its workflow mapping to source/deviceusage/structuredefinition-DeviceUsage.xml. A follow-up core commit aeef91f4a000aa7905ce0bb6b99d42b90fc622f0 updated source/deviceusage/deviceusage-event-mapping-exceptions.xml so Event.partOf is mapped to DeviceUsage.partOf rather than remaining unmapped. Later FHIR-43445 workflow-mapping work treated the partOf mapping as already present while adding other DeviceUsage workflow mappings.

Additional context:
DeviceUsage is no longer an active resource in the current core build. Commit 3b38b80cf23f9cbb306fab8fcedb293315478c32 removed deviceusage from source/fhir.ini resource/workgroup/FMM registration and changed core module pages to link DeviceUsage to the OO incubator IG. Current source/device-module.html and source/workflow-module.html link DeviceUsage externally, and https://build.fhir.org/deviceusage.html is not a current core page. The OO incubator continuous-build StructureDefinition JSON already contains DeviceUsage.partOf with the requested cardinality, Reference(DeviceUsage) target, summary flag, short/definition, and Event.partOf mapping.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The authoritative current core build no longer owns DeviceUsage, and the external OO incubator artifact that core points to already carries the FHIR-51713 element and mapping.

Recommendation:
Keep this external-repo audit as-is for the core reconciliation. Any future DeviceUsage edits should be made in the OO incubator source; no FHIR core source follow-up is needed for FHIR-51713 unless DeviceUsage is brought back into the active core build.
