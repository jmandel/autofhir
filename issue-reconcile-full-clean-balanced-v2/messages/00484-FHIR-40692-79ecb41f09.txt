FHIR-40692: Audit MedicationDispense status codes

Issue request:
FHIR-40692 was an Applied/Persuasive Pharmacy change request for R6 asking to evaluate MedicationDispense status codes after comparison with BiologicallyDerivedProductDispense. The final resolution required the MedicationDispense status CodeSystem to describe in-progress as ready for pickup, cancelled as not and not going to be picked up by the patient, and to replace the stopped code with unfulfilled while preserving the lifecycle meaning.

Initial application:
The current branch already contains Jira-tagged application commits for this issue. Commit 9899efa3e6 changed source/medicationdispense/codesystem-medicationdispense-status.xml from stopped/Stopped to unfulfilled/Unfulfilled, commits 16f693d1d7 and f8000b7c6b updated MedicationDispense examples to use status unfulfilled, and commit 4a6179e9e2 updated MedicationDispense.status short text to include unfulfilled. The active MedicationDispense resource entry in source/fhir.ini confirms these files are in the current build scope.

Additional context:
Pharmacy minutes from 2023-03-27 record the original status mapping discussion that led to FHIR-40692. Pharmacy minutes from 2025-11-03 revisited the applied wording, discussed the distinction between cancelled and stopped/unfulfilled, and agreed with the application of the name change to unfulfilled. Later Jira items FHIR-54366 and FHIR-54372 discuss related not-performed reason and timestamp guidance, but they are not Applied/Published source-edit decisions for this default reconciliation and do not reverse the FHIR-40692 status code application. No directly relevant Zulip discussion was found.
