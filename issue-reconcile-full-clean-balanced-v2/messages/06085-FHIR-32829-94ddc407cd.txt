FHIR-32829: Audit DeviceUsage adherence scope

Issue request:
FHIR-32829 was a Published R5 OO change request asking to rename DeviceUseStatement/DeviceUsage.usageReason to usageStatusReason because it explained the usage-status value rather than the clinical reason element. The approved Persuasive with Modification resolution instead created a DeviceUsage.adherence backbone with code and reason children and example adherence code/reason value sets.

Initial application:
The issue was applied in source history by commit 41cf190393, which added DeviceUsage.adherence, DeviceUsage.adherence.code, and DeviceUsage.adherence.reason to source/deviceusage/structuredefinition-DeviceUsage.xml. The Jira comment cites PR commit 734790a30b, which then adjusted the new backbone by removing isSummary from DeviceUsage.adherence. The older usageStatus/usageReason elements remained in the R5 DeviceUsage source and publication.

Additional context:
FHIR-26308 is a related background ticket for earlier pre-applied DeviceUseStatement/DeviceUsage changes, including the same usageReason naming concern, and was later accepted as pre-applied. Current core source no longer builds DeviceUsage: source/fhir.ini has no active DeviceUsage resource entries, build.fhir.org/deviceusage.html returns 404, and commit 3b38b80cf2 removed DeviceUsage from core build metadata while changing current DeviceAssociation narrative to link to the OO incubator DeviceUsage artifact. The incubator artifact still has the R5-style fields, so any future correction belongs in that IG rather than in inactive core source/deviceusage files.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Editing source/deviceusage/structuredefinition-DeviceUsage.xml would only alter an out-of-build core file, while the current core build points implementers to the external OO incubator DeviceUsage artifact.

Recommendation:
Keep this audit commit as-is for core FHIR. If the remaining usageReason/adherence duplication should be revisited, file or reconcile that work against the OO incubator IG source that now owns DeviceUsage, not against the current core build.
