FHIR-5337: Audit AuditEvent agent location

Issue request:
FHIR-5337 was Published/Persuasive for the DSTU1 AuditEvent/SecurityEvent ballot and asked to add a 0..1 location reference to SecurityEvent.Participant to support Record Lifecycle Events without a corresponding Provenance resource.

Initial application:
The issue appears to have been applied by commit 8e3bf13ba666e95767275e11df012bf9e4d7ceba, which added AuditEvent.participant.location as 0..1 Reference(Location) to the AuditEvent spreadsheet source. Later source refactoring replaced the spreadsheet with source/auditevent/structuredefinition-AuditEvent.xml and retained the element under the current AuditEvent.agent name.

Additional context:
The current build uses AuditEvent as an active resource, and source/fhir.ini records the historical R2 rename from AuditEvent.participant to AuditEvent.agent. Jira issue FHIR-5335 is the referenced ballot comment #216 context, and FHIR-5336 was applied in the same AuditEvent record-lifecycle family, but neither changes the location decision. No relevant Zulip or Confluence evidence was found that would reverse or narrow the applied change.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change because the active current source already contains AuditEvent.agent.location with cardinality 0..1 and targetProfile Location, satisfying the original participant-location request after the participant-to-agent rename.

Recommendation:
Keep this no-change audit commit as-is. Revisit only if a future work-group decision changes whether AuditEvent agents should carry a location reference.
