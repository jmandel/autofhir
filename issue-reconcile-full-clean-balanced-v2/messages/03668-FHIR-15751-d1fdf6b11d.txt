FHIR-15751: Audit TriggerDefinition parameter extensions

Issue request:
FHIR-15751 was a Published/Persuasive FHIR-core CDS change request raised against STU3 and applied for R5. It asked for TriggerDefinition to represent CDS Hooks-style expected parameters, with the final resolution calling for cqf-parameterDefinition as a 0..* ParameterDefinition extension usable on TriggerDefinition and cqf-isPrefetchToken as a 0..1 boolean extension usable on ParameterDefinition to mark prefetch-token parameters.

Initial application:
The issue was applied by d647c65b3b (J#15751) in PR #2288, which added parameterDefinition and isPrefetchToken extension rows to the active clinical reasoning extensions spreadsheet and added both rows to the Clinical Reasoning module page. The PR was merged as 13fb5889ec. Later maintenance moved the extension links to Extension Pack-style URLs and 39f090d04c fixed the isPrefetchToken module link so it points to StructureDefinition-cqf-isPrefetchToken rather than the parameterDefinition page.

Additional context:
In the current build, core still includes the Clinical Reasoning module page and active clinicalreasoning-extensions profile source, and it retains OID assignments for both canonical extension URLs. The current module page links to cqf-parameterDefinition and cqf-isPrefetchToken through [%extensions-location%], while the metadata type profile page sends TriggerDefinition and ParameterDefinition extension listings to the Extension Pack. The authoritative extension definitions now live in /home/jmandel/work/fhir-extensions, where cqf-parameterDefinition has TriggerDefinition context and ParameterDefinition value type, and cqf-isPrefetchToken has ParameterDefinition context and boolean value type. No Zulip or Confluence search result was found that changes this conclusion.

Recommendation:
