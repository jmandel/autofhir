FHIR-32454: Confirm agent actor alignment

Issue request:
FHIR-32454 was Published as Persuasive with Modification for R5. It asked whether AuditEvent subjects should be represented as agents and whether AuditEvent/Provenance agent.who should include Group, CareTeam, and HealthCareService-like actors. The approved resolution clarified that subjects are recorded as entities unless they actively participate, and that .agent.who should recognize all Event pattern performer.actor types.

Initial application:
The issue appears to have been applied by git commit 8209c17a869cab7d8ebb44b093fd235edf90c1c6, which changed both source/auditevent/structuredefinition-AuditEvent.xml and source/provenance/structuredefinition-Provenance.xml and added Event actor target profiles, including CareTeam, to agent.who. It did not mention Group or HealthcareService at that point because the Event pattern actor list then in source/event/event-spreadsheet.xml did not include those later actor-policy additions.

Additional context:
AuditEvent and Provenance are active current-build resources in source/fhir.ini. The current Event pattern performer.actor source lists Practitioner, PractitionerRole, Organization, CareTeam, Patient, Device, and RelatedPerson. Current AuditEvent.agent.who and Provenance.agent.who include all of those types. Later agent-policy work, especially FHIR-49304/FHIR-49672 and commits 390878350715eca86888de3f0cfe40e5cec1200c and 7e693f8d597308c8f606d1725c0542c03b0d2240, added or confirmed additional agent types such as Group, HealthcareService, and DeviceDefinition where applicable. The subject/patient question raised during FHIR-32454 was separated into FHIR-33155, which later added a .patient element to both resources; that separate issue is not re-decided here.

AutoFHIR reconciliation:
No source change was made. The authoritative StructureDefinition sources already include all Event performer.actor types on AuditEvent.agent.who and Provenance.agent.who, and they also include the later current-source actor additions relevant to the Jira examples. Adding duplicate prose or changing the target profiles would not improve conformance and could conflict with later actor-policy decisions.

Recommendation:
Keep this empty audit commit as-is. Future changes to Group, HealthcareService, DeviceDefinition, or broader actor policy should be handled through the later workflow/security issues that govern those actor lists, not by reopening this R5 reconciliation.
