FHIR-34135: Audit Device subject Person exclusion

Issue request:
FHIR-34135 was Published/Persuasive for R5 and asked to remove Person from Device.subject, with explanatory wording that people using devices outside a healthcare setting, such as fitness trackers, are still represented as Patient rather than Person.

Initial application:
The Jira comment points to commit 5dfb107768496eb70edb269449cf60cef14a5088, which removed the Person target from Device.subject and added the Patient/fitness-tracker explanatory sentence to the Device.subject definition. Later Device work moved then removed Device.subject/Device.association from Device as part of the DeviceAssociation reconciliation.

Additional context:
FHIR-30243 originally broadened Device.patient to Device.subject and included Person; FHIR-34135 corrected that choice. FHIR-32570 then superseded Device.subject with an association subject, and FHIR-38904/FHIR-39009 resolved the overlapping Device subject work by creating DeviceAssociation and removing patient-identifying association data from Device. In the current build, DeviceAssociation is an active resource, Device has no active Device.subject, and DeviceAssociation.subject includes Patient, Practitioner, PractitionerRole, RelatedPerson, and other non-Person targets but not Person. DeviceAssociation narrative also lists Patient activity trackers and other subjects without using FHIR Person.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because the current in-scope source no longer exposes Device.subject and the active replacement subject element does not allow Person; the use of Patient for activity trackers is already conveyed in DeviceAssociation narrative.

Recommendation:
Keep this audit commit as-is. Future DeviceAssociation changes should continue to avoid adding StructureDefinition/Person as a subject/focus target unless a later explicit work-group decision reverses the general Person-participant rule.
