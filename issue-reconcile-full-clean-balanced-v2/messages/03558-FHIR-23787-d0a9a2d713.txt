FHIR-23787: Audit regex code filter guidance

Issue request:
FHIR-23787 is a Published FHIR-core Vocab change request resolved Persuasive with Modification for R5. It asked to clarify which property/filter name to use with ValueSet compose filters when op=regex is intended to match concept codes, add a code/regex row to the CodeSystem filters table with server-determined regex flavor, and retitle/refine the terminology service Standard Properties table as Standard $lookup Properties.

Initial application:
No prior AutoFHIR reconcile commit for FHIR-23787 was present on the combined branch. The historical source application is split across two commits: 43c2e8c783 directly cites FHIR-23787 and updates source/terminology-service.html, while f43f55953f is titled for FHIR-39262 but adds the CodeSystem filters code/regex row matching the FHIR-23787 resolution.

Additional context:
The originating Zulip thread confirms the problem was whether op=regex should use code and what regex flavor applies. The 2023-02-06 Vocab minutes record the work group distinction that code is a filter name for ValueSet.compose.include.filter.property, not a new standard $lookup concept property, and that the regex flavor is determined by the server. Current build-scope source includes CodeSystem as an active resource and references terminology-service.html through the built hierarchy/module pages.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current CodeSystem notes already define the code/regex filter row with the requested definition and server-determined regex flavor, and the current terminology service page already has the Standard $lookup Properties heading, concept-oriented display/designation wording, lang.X parenthesis fix, and removal of the deprecated system sentence from name.

Recommendation:
Keep this audit commit as-is. Further edits would only restate wording already present in build-scope source; any future change to the boundary between CodeSystem filters and $lookup properties should be handled as a separate terminology work-group decision.
