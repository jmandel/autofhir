FHIR-31480: Audit DeviceUseStatement subject scope

Issue request:
FHIR-31480 was Published/Persuasive for R5. It asked to remove Group from the DeviceUseStatement.subject reference choices because known use cases did not justify Group, while explicitly leaving open possible reintroduction if clear use cases appeared later.

Initial application:
The issue was applied in core by commit dd762a0d5230470982fdf5f7bfa8b9e00dfa1a14, which removed the Group targetProfile from source/deviceusestatement/structuredefinition-DeviceUseStatement.xml. DeviceUseStatement was later carried forward as DeviceUsage, with source/fhir.ini retaining an old-to-new mapping from DeviceUseStatement to DeviceUsage.

Additional context:
The current core build no longer has active DeviceUseStatement or DeviceUsage resource entries. source/fhir.ini omits DeviceUsage from the active [resources] list, and source/device-module.html links DeviceUsage to the OO Incubator IG rather than a core page. A later final OO decision, FHIR-41413, intentionally reintroduced Group for DeviceUsage.subject for family/household care in R6, added the limiting comment, and is already represented on the combined branch by an external-repo audit commit. The current OO Incubator build exposes DeviceUsage.subject as Reference(Patient|Group) with the family/household comment and subject/patient search parameters.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. Removing Group from the remaining inactive core DeviceUsage XML would edit out-of-build source, contradict the later FHIR-41413 decision, and not change the current authoritative DeviceUsage artifact.

Recommendation:
Keep this external-repo audit commit as-is for core reconciliation. If the work group wants to revisit whether current DeviceUsage.subject should allow Group, handle that in the OO Incubator source and explicitly account for FHIR-41413 rather than changing inactive core resource files.
