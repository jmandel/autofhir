FHIR-34294: Audit DetectedIssue status binding

Issue request:
FHIR-34294 was a Published/Persuasive with Modification CDS change request for R5. It said the old reuse of ObservationStatus allowed DetectedIssue.status codes that did not make sense and requested a DetectedIssueStatus value set containing preliminary, final, and entered-in-error.

Initial application:
PR 2237 applied the issue in commits 1e5b1dbaebe602d4385b71d10ab032ed4d1aa1be and 3267a3fdd04a00eb32e46c6bc801d122c3fbb175 by changing DetectedIssue.status from ValueSet/observation-status to ValueSet/detectedissue-status and creating the new value set with preliminary, final, and entered-in-error. This source is in current build scope because DetectedIssue is an active resource in source/fhir.ini.

Additional context:
The current value set intentionally no longer has only those three codes. Published issue FHIR-24675 was applied immediately after FHIR-34294 for R5 in commit 5af0772e4846b965dd7d88afb05b442a8fcdd321, adding the DetectedIssue-specific mitigated code to support searching for unmitigated detected issues. Later Applied R6 work added unknown under FHIR-30808 and processing-error under FHIR-50606; FHIR-50606 is already represented on the combined branch by commit 5081fb11193f2091200d1f1ee2ea668ce7428d5b, which completed the value set compose entry for processing-error. Community searches found no directly relevant Zulip or Confluence discussion that overrides the Jira/source history.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current source still satisfies the core FHIR-34294 correction by using a DetectedIssue-specific required binding instead of reusing all ObservationStatus codes, and the extra current codes are explained by later or same-family accepted changes rather than by a missed FHIR-34294 application.

Recommendation:
Keep this audit as-is. Do not narrow DetectedIssue.status back to only preliminary, final, and entered-in-error without reopening the later accepted decisions that added mitigated, unknown, and processing-error.
