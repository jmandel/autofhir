FHIR-35855: Audit isSummary guidance reconciliation

Issue request:
FHIR-35855 was a Published/Persuasive FHIR-core ElementDefinition issue. It asked to harmonize the ElementDefinition.isSummary usage note with the interpretation table/tooling by removing the clause ", so servers might not support per-profile use of the isSummary flag" from the sentence about servers pre-caching summarized resources.

Initial application:
The issue appears to have been applied in commit f5817c6375, which changed source/datatypes/elementdefinition.xml to remove exactly that clause from the ElementDefinition.isSummary comment. Current source still has the shortened pre-cache sentence and no active current source match for the removed clause.

Additional context:
source/fhir.ini lists ElementDefinition as an active datatype and maps elementdefinition to the ElementDefinition page, so source/datatypes/elementdefinition.xml and source/elementdefinition.html are in current build scope. The interpretation table still marks isSummary in constraint definitions as optional with the dagger note requiring the value to match the base definition. The same ElementDefinition.isSummary comment was later expanded by FHIR-33148 in commit 0b49068f00, retaining the FHIR-35855 removal while adding more detailed summary-selection guidance. Older tools/history release snapshots still contain the clause, but those are historical release artifacts, not current source to edit.

AutoFHIR reconciliation:
No source change was made. The current build-source wording already implements the requested removal and remains consistent with the interpretation-table rule that profiles cannot change the inherited isSummary value.

Recommendation:
Keep this empty audit commit as-is. No follow-up source edit is needed for FHIR-35855 unless a future work group decision changes the broader isSummary/profile behavior.
