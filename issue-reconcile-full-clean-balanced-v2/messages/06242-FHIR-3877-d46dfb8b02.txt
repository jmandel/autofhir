FHIR-3877: Audit Flag.code CodeableConcept

Issue request:
FHIR-3877 was a Published/Persuasive with Modification Patient Care change request raised against DSTU1 Alert/Flag. It asked to change Alert.note from string to CodeableConcept so alert text and coded alert pick-list values could both be represented, with CodeableConcept.text covering narrative-only use and CodeableConcept.coding covering coded use.

Initial application:
The change appears to have been applied during the Alert-to-Flag rewrite. Commit db4ace37c6615c9732f958d34d6286fe739fc657, dated 2015-03-28, cites {#3877} along with other PC-approved change requests and renamed Alert to Flag. In that commit the example moved from Alert.note to Flag.code, and the source spreadsheet defined Flag.code as 1..1 CodeableConcept with the definition "The coded value or textual component of the flag to display to the user." No separate later source commit was needed to reapply the seed issue.

Additional context:
Flag is an active current-build resource in source/fhir.ini, while the deleted-resource note records that Alert became Flag. Current source/flag/structuredefinition-Flag.xml contains Flag.code as 1..1 CodeableConcept, with a comment directing non-coded values to CodeableConcept.text and an example binding to ValueSet/flag-code. Related Published issues FHIR-3523 and FHIR-3292 were earlier same-family requests about Alert.note cardinality and a coded alert representation; FHIR-8560 later added an example value set for Flag.code; FHIR-11202 later aligned the short description with machine-readable and human-readable Flag.code use. Exact Zulip and Confluence searches found no directly relevant or conflicting community record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative current Flag source already satisfies the seed by representing the former alert note/message as required Flag.code CodeableConcept, and no current Alert.note or Flag.note element remains to fix.

Recommendation:
Keep this audit commit as-is. Do not reintroduce Alert.note or add a parallel note element for FHIR-3877; future changes to Flag.code binding, cardinality, or display guidance should be handled under a new applied/published tracker.
