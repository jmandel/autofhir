FHIR-17479: Audit required binding profile narrowing

Issue request:
FHIR-17479 was a Published/Persuasive STU3 vocabulary change request for FHIR-core terminologies section 4.1.4.1. It asked that the Required Binding Strength text make clear that profiling a resource can exclude codes from a required value set, not only state unspecified business rules, while still not allowing profiles to add codes.

Initial application:
The Jira comment identifies git 66ae1e40f1bc02283363c872db14035fc795f8f7. That commit explicitly included GF#17479 in a terminology ballot reconciliation batch and changed source/terminologies.html so the derived-profile sentence said profiles may state rules including removing codes from allowed use, but cannot specify new or additional codes.

Additional context:
The current build-scope terminology source remains source/terminologies.html, with source/fhir.ini mapping resourceType to the terminologies page. A later Published vocabulary issue, FHIR-17480, replaced broader Required Binding Strength wording for R5 and preserved the same behavior, changing the sentence only to say profiles cannot specify additional codes. The originating Zulip discussion in #implementers confirmed that excluding a required-bound code through profiling was allowed and adding codes was not; later messages in the same thread continue to confirm that required bindings cannot be extended by profiles.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/terminologies.html already says derived profiles may state rules on which codes can be used, including removing codes from allowed use, but cannot specify additional codes for these elements, which satisfies FHIR-17479 after the later FHIR-17480 wording refresh.

Recommendation:
Keep this audit commit as-is. No further core source work is needed for FHIR-17479 unless the Vocabulary work group later decides to revisit required-binding narrowing semantics.
