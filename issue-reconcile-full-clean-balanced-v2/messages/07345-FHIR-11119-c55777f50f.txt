FHIR-11119: Audit DiagnosticRequest merge

Issue request:
FHIR-11119 was Published with resolution Persuasive after a January 2017 OO/PC discussion and vote. It asked whether ProcedureRequest and DiagnosticRequest should remain separate, called out misaligned parallel element names such as occurrence[x] versus scheduled[x], and the final decision was to combine DiagnosticRequest and ProcedureRequest using the broader ProcedureRequest name with a superset of both resources' elements.

Initial application:
The issue was applied in source history by git-svn commits carrying [#11119], especially e9a85998b0dbe25b03abd0045bfa30e67ce56b36, ad1050b14bb5ec8a8c29b5448d991ef09bca5b2a, 37f014c2b7d4e85beace7c89e30b0308975d91ae, 6798563c36e0143ed1ca837b2a9bd1ee22254d97, and 2fa71284c7cb0518c0d71318cc883f828b33c1bc. Those commits removed the active DiagnosticRequest resource from fhir.ini, deleted the DiagnosticRequest source folder, moved or merged diagnostic examples and value sets into ProcedureRequest, updated ProcedureRequest narrative/boundaries, and tagged the merged ProcedureRequest elements with #11119. Later commit 06bd9f6ffe08096694a3424721006e5fdcd82d3a applied FHIR-13867 by renaming ProcedureRequest to ServiceRequest while preserving the old-name mappings.

Additional context:
The current build scope is ServiceRequest, not ProcedureRequest or DiagnosticRequest. source/fhir.ini actively lists servicerequest=ServiceRequest, records DiagnosticOrder as subsumed into ServiceRequest and ProcedureRequest as merged into ServiceRequest, and keeps historical mappings from ServiceRequest.orderedOn to authoredOn and ServiceRequest.scheduled to occurrence. Current ServiceRequest source describes a broad request for diagnostic investigations, treatments, or operations, includes diagnostic request as an alias, and has aligned elements such as category, code, occurrence[x], authoredOn, performer, reason, supportingInfo, and bodyStructure with committee notes tracing back to #11119. Zulip discussion before and after the vote confirms the merge was intentional and announced as a breaking STU3 change; Confluence searches found no contrary minutes. Several more granular ProcedureRequest/DiagnosticRequest follow-up issues are already represented on the combined branch and do not require duplicate commits here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current source already reflects the issue's semantic outcome after later renaming: DiagnosticRequest and ProcedureRequest are no longer independent current resources, and their combined successor ServiceRequest covers diagnostic and procedure service requests with aligned request-pattern element names. Remaining DiagnosticRequest or ProcedureRequest strings are historical notes, old-type terminology, fhir.ini migration notes, or unrelated example comments rather than active conformance definitions that need editing for FHIR-11119.

Recommendation:
Keep this no-change audit as-is. Future changes to the merged request artifact should be handled as ServiceRequest-specific issues, not as a reapplication of FHIR-11119, unless a work group explicitly decides to split or rename the current ServiceRequest scope.
