FHIR-5788: Audit retired $expand profile parameter

Issue request:
FHIR-5788 was Published/Persuasive with Modification for FHIR-core ValueSet. It asked to add a ValueSet/$expand input parameter named `profile`, a URI reference to an external definition of additional expansion configuration, with a VSAC documentation placeholder and no formal FHIR resource yet.

Initial application:
The Jira comment says the change was applied in svn 4364. In git history, da0f89e775d2cf65f97788b4fcfa6a1eab98a752 is that application: it added `expand.profile` to the then-authoritative ValueSet spreadsheet and included the VSAC note. The current branch no longer has that spreadsheet-derived `profile` operation parameter because later terminology work changed the model.

Additional context:
FHIR-10277 reconsidered the proposed ExpansionProfile resource and resolved that the relevant controls had already been added as explicit $expand parameters. FHIR-16337 and FHIR-16490 then made the decisive R4-era Vocab change: remove ExpansionProfile, redraft $expand behavior, and keep specific controls such as force-system-version as operation parameters. FHIR-17558 later removed stale ValueSet ExpansionProfile references and is already represented on the combined branch. Current build-scoped source registers ValueSet and its operations, and the active ValueSet/$expand OperationDefinition has explicit parameters such as excludeNested, excludeNotForUI, excludePostCoordinated, force-system-version, version controls, manifest, and tx-resource, but no generic `profile` parameter or VSAC/ExpansionProfile text. Community searches found no seed-specific conflict; a 2019 implementers thread also described ExpansionProfile as removed in R4 with most former elements represented as input parameters.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding the 2015 generic `profile` URI parameter would reverse later published Vocab decisions that removed ExpansionProfile and replaced the generic profile mechanism with explicit $expand parameters and later manifest-style mechanisms.

Recommendation:
Keep this no-change audit. Do not reintroduce `profile` into core ValueSet/$expand without a new Vocab/TI decision; handle any future profile-like expansion configuration through current explicit parameters, manifest/CRMI mechanisms, or a new tracker.
