FHIR-23700: Audit valueset-unclosed extension scope

Issue request:
FHIR-23700 was a Published/Persuasive with Modification FHIR-core ValueSet tracker. It asked to change the valueset-unclosed extension text so the extension SHALL only be used when post-coordinated codes are allowed or codes have a grammar and no practical expansion can be produced, and to add a comment clarifying that practical-size limitations are handled by ValueSet.expansion offset and total rather than this extension.

Initial application:
The issue was applied in core by commit 4be2307113446802c0b34b84a74c39a4742ba9c1, which changed source/valueset/structuredefinition-extension-valueset-unclosed.xml differential Extension.definition and Extension.comment. That application left the top-level StructureDefinition.description with the older wording, which later meeting notes and FHIR-40718 identified as a disconnect between the main extension page and the detailed definition.

Additional context:
Core commit dd468d4f1799dd79819315b211588ef1cf4586e0 removed the ValueSet extension definitions from the R5 source, including valueset-unclosed, and the current core ValueSet implementation guide no longer lists that extension definition. The authoritative current StructureDefinition is in the FHIR Extension Pack. Later Applied issue FHIR-40718 deliberately revised the extension definition and description in the Extension Pack to allow technical limitations as well as post-coordinated/grammar cases, and to require client opt-in before returning an incomplete expansion. The current core $expand operation still references valueset-unclosed in the unbounded/post-coordination context and has a later handle-unclosed-expansion parameter, but FHIR-23700's extension-definition source is no longer in this checkout.

AutoFHIR reconciliation:
This is an empty external-repo audit commit. It makes no FHIR-core source change because the FHIR-23700 core wording was historically applied, the relevant StructureDefinition source moved out of core, and the current external definition has intentionally been superseded by FHIR-40718 rather than needing the old FHIR-23700 wording restored in core.

Recommendation:
Keep this audit commit as-is for FHIR-23700. Do not reintroduce the removed core extension source or revert the current Extension Pack wording under this issue; any future changes to the valueset-unclosed definition or client opt-in behavior should be handled in the FHIR Extension Pack or in the later FHIR-40718/FHIR-49701 issue family.
