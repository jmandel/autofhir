FHIR-19302: Audit resource security categories

Issue request:
FHIR-19302 was Published with a Persuasive Security WG decision for STU3/R4 ballot work. It asked to add a security.html section describing five security/privacy treatment buckets for FHIR resources, assign a category for all FHIR resources, and expose each resource's category in the resource header with a link back to the security discussion.

Initial application:
The issue was applied in two Jira-linked implementation steps. PR HL7/fhir#88 merged 1621ba352f5c3c15aca09ba4b94b5b17425f7e75, adding the Security and Privacy Considerations section to source/security.html. Grahame's Jira comment then points to 116321853ea87df5239ffc93f4e52f6aefb862e8, which added the source/fhir.ini security-categorization map, the Resource List Security Category tab hook, the structuredefinition-security-category extension definition, and publisher/tooling support for displaying the category.

Additional context:
Later category-family issues refined but did not reverse the seed decision. FHIR-20002, already represented on the combined branch, confirmed the Resource List link and dominant-category wording and renamed the narrative heading to No Dominant Category. FHIR-20533 aligned the Individual Sensitive narrative with the resource list. FHIR-54173 later confirmed that the not-classified code remains valid while the Extension Pack vocabulary display is No Dominant Category. No discovered Zulip or Confluence evidence changes the original application conclusion.

AutoFHIR reconciliation:
This audit intentionally makes no source change. On the current combined branch, source/security.html still contains the Security and Privacy Considerations category section and links to the Resource Types Security Category tab; source/resourcelist.html still contains the Security Category tab and generated <%res-list-security%> hook; source/fhir.ini has active security-categorization entries for every active [resources] entry; and every active resource StructureDefinition source has the structuredefinition-security-category extension. The CI build resource header also renders the Security Category link/value, confirming the current source surface satisfies the original request.

Recommendation:
Keep this no-change audit commit as-is. No core FHIR follow-up is needed for FHIR-19302; future changes to category labels or individual resource classifications should be handled under their own later Jira issues or, for the category vocabulary itself, in the FHIR Extension Pack source of truth.
