FHIR-27148: Audit subscription notification payload guidance

Issue request:
FHIR-27148 was a Published/Persuasive with Modification R5 FHIR-I change request asking for a way to prefer subscription notifications that carried just a URL versus request/response details. The approved resolution was narrower: document when just the fullUrl is sufficient and when full request/response information is useful.

Initial application:
The issue appears to have been applied by git commit 77b1c1d6b76c2c274a8cdb6209d1b21ced96ccd1, "FHIR#27148", which expanded Subscription payload documentation. That historical text described empty, id-only, and full-resource notifications, discussed id-only resource URLs in Bundle.entry.fullUrl/request/response, and pointed to the then-current Subscription.notificationUrlLocation element for URL placement behavior.

Additional context:
FHIR-I minutes for 2020-05-18 confirm the approved scope was documentation, not necessarily a new permanent preference mechanism. Later published URL-location issues in the same family are already represented on the combined branch, and FHIR-36081 superseded the old placement mechanism by removing Subscription.notificationUrlLocation and making SubscriptionStatus.notificationEvent.focus the fixed location for event resource references. FHIR-47353 later clarified the current Subscription.content wording and is also already represented on the combined branch. Subscription remains an active current-build resource in source/fhir.ini.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/subscription/subscription-notes.xml already explains empty, id-only, and full-resource notification content, including when clients retrieve resources by references/URLs and when full-resource notifications use entry.resource or, if the resource cannot be included, entry.request and/or entry.response. Current source/subscription/structuredefinition-Subscription.xml links Subscription.content to that Notification Content guidance. Reintroducing a preference or notificationUrlLocation wording would conflict with the later published FHIR-36081 cleanup.

Recommendation:
Keep this audit commit as-is. The current core source satisfies the final FHIR-27148 documentation intent when read with the later URL-location and content-level decisions; no follow-up core change is needed for this issue.
