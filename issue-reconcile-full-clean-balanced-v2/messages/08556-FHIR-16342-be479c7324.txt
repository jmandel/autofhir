FHIR-16342: Audit CapabilityStatement custodian

Issue request:
FHIR-16342 was a Published/Persuasive with Modification FHIR-I change request raised for STU3. It asked for a way to express the organization associated with the data served by a server-mode instance, and the accepted resolution added CapabilityStatement.implementation.custodian as Reference(Organization) 0..1 with the definition "The organization responsible for the management of the instance and oversight of the data within" and an STU flag for R4.

Initial application:
The issue was applied in historical git commit 5b7c6d6d2e, which added CapabilityStatement.implementation.custodian to the then-authoritative CapabilityStatement spreadsheet as Reference(Organization) 0..1, summary=true, definition text matching the Jira resolution, and standards status trial-use. The 2021 source rework commit 33b409a4b6 preserved that element and trial-use marker in structuredefinition-CapabilityStatement.xml.

Additional context:
CapabilityStatement is an active current-build resource in source/fhir.ini, and the current StructureDefinition still contains CapabilityStatement.implementation.custodian with the requested cardinality, Reference(Organization) target, short description, and management/oversight definition. The only apparent mismatch is that current source no longer carries the element-level trial-use marker. That marker was intentionally removed later by R6 normative-status cleanup in commit 5c20769cc7, and the already-published FHIR-40493 reconciliation on the combined branch documents why those R5-era trial-use markers should not be reintroduced without a new FMG/FHIR-I decision.
