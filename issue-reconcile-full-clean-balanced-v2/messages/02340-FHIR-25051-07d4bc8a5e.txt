FHIR-25051: Audit overall dosage instruction text

Issue request:
FHIR-25051 was Published/Persuasive for R5 by Pharmacy. It asked for a way to convey the overall set of dosage instructions spanning multiple Dosage items for MedicationRequest, MedicationDispense, and MedicationStatement/MedicationUsage, with the resolved change to add a renderedDosageInstruction name to be finalized wherever the relevant Dosage datatype was used.

Initial application:
The issue comments say Melva Peters added renderedDosageInstruction to MedicationRequest, MedicationDispense, and MedicationUsage and cite commit 80c2f73ea490c414129d8406d6d00d4e94af04c0. That commit added resource-level renderedDosageInstruction elements to MedicationRequest, MedicationDispense, and MedicationUsage alongside their Dosage-valued dosageInstruction/dosage elements.

Additional context:
The current build no longer uses those resource-level renderedDosageInstruction elements as the authoritative model. Active fhir.ini entries include DosageDetails on the dosage page and active MedicationRequest, MedicationDispense, and MedicationStatement resources. Their current StructureDefinitions use a single DosageDetails for MedicationRequest.dosageInstruction, MedicationDispense.dosageInstruction, and MedicationStatement.dosage. DosageDetails.renderedInstruction is now 1..1 and is defined as the full representation of the dosage instructions. R6 ballot notes in all three resource pages explicitly state that renderedDosageInstruction was removed from the resource and placed in DosageDetails.renderedInstruction. Later FHIR-54014 strengthened that element by making it required. The remaining resource-level renderedDosageInstruction hits are fhir.ini R5-to-R6 mapping lines and generated-looking SVG diagrams; the authoritative StructureDefinitions and datatype source convey the current rule.

AutoFHIR reconciliation:
This is an empty no-change audit commit. Adding a new source element or reverting to the old resource-level renderedDosageInstruction would conflict with the current DosageDetails model and with later Pharmacy decisions. No source hunk is needed for FHIR-25051 in the current build.

Recommendation:
Keep this audit commit as-is. If the checked-in medication SVG diagrams are still used by the build, regenerate or review them as a diagram maintenance task because they still mention the retired resource-level renderedDosageInstruction, but do not treat that as a FHIR-25051 source fix while the authoritative definitions already point to DosageDetails.renderedInstruction.
