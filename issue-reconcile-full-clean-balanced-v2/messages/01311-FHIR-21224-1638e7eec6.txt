Issue request:
FHIR-21224 was a Published/Persuasive FHIR-core Consent change request asking to allow multiple Consent sources. The approved resolution was to move sourceAttachment and sourceReference to the Consent root, remove source[x], and make both new elements 0..*.

Initial application:
No current-branch commit was found that explicitly mentions FHIR-21224. The relevant source state was introduced into the current branch by 33b409a4b6, which created the current Consent StructureDefinition source with root-level Consent.sourceAttachment and Consent.sourceReference, each with max="*". A separate R4B history commit, c69d71aa21, still shows the older Consent.source[x] 0..1 shape, confirming the model changed across the R4/R5-era source transition.

Additional context:
source/fhir.ini actively lists consent=Consent, so source/consent/structuredefinition-Consent.xml is in the current build scope. The original 2019 Zulip thread confirms the use case was multiple sources and notes that a repeating choice element could not simply remain source[x]. A 2023 Security and Privacy Zulip thread links back to FHIR-21224 as the reason for the R5 sourceAttachment/sourceReference split. Confluence searches found no conflicting work-group record. Adjacent Jira hits about Consent source search parameters, SDOH profiles, and later clarification requests are separate decisions or outside the current FHIR-core source-edit scope.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build-scoped Consent StructureDefinition already has Consent.sourceAttachment 0..* and Consent.sourceReference 0..*, and Consent.source[x] no longer exists there. The active Consent source-reference SearchParameter also targets Consent.sourceReference, consistent with the split source model.

Recommendation:
Keep this audit commit as-is. No current FHIR-core source edit is needed for FHIR-21224; future work on clarifying semantics of multiple sourceAttachment/sourceReference values should be handled under a newer Consent clarification issue rather than reopening this cardinality change.
