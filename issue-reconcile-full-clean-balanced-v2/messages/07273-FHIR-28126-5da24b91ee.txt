FHIR-28126: Audit optional fixed-pattern clarification

Issue request:
FHIR-28126 was Published/Persuasive for R5. It asked FHIR-I to clarify ElementDefinition behavior when min = 0 and a fixed or pattern value is supplied: the fixed or pattern value constrains the element only if that optional element is present.

Initial application:
The issue was explicitly applied by git commit 1736091b56105ca469a08c4d7a91976dfe2346e8, "FHIR-28126 Clarify the meaning of a fixed/pattern value when min=0", which added the min/max bullet to source/elementdefinition.html and updated the build-scoped ElementDefinition spreadsheet definitions. A later source commit, 343a3ba4e9d0644658fd45f04c0218edcdd0dcac, strengthened the same bullet with the statement that an omitted element is not treated as though the fixed value or pattern had been specified.

Additional context:
The originating Zulip thread reached consensus on option #1: validators should ignore fixed/pattern validation when the optional element is absent, aside from cardinality. FHIR-I minutes from 2020-11-09 record the 11-0-0 persuasive vote. ElementDefinition is an active normative datatype in source/fhir.ini, with elementdefinition.html as its active page mapping, so the inspected files are in current build scope. Related pattern wording audits FHIR-33316 and FHIR-36700 are already represented on the combined branch and do not change this min=0 rule.

AutoFHIR reconciliation:
No source change was made. The latest combined branch already says that when min = 0 and a fixed or pattern value is present, the fixed or pattern applies only when the element is actually present, and that omission is not treated as specifying the fixed value or pattern. The ElementDefinition.fixed[x] and pattern[x] definitions also use present/value-qualified wording consistent with that rule.

Recommendation:
Keep this no-change audit commit. The current build-scoped source conveys the approved FHIR-28126 clarification; further edits would be redundant unless FHIR-I reopens the substantive semantics of optional fixed or pattern constraints.
