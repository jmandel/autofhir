FHIR-43646: Audit ActorDefinition description alignment

Issue request:
FHIR-43646 was an Applied/Persuasive with Modification R6 clarification for FHIR-core ActorDefinition. The Jira asked that the ActorDefinition description no longer describe only an application that exchanges data; the voted resolution was to change it to "A human or system that exchanges data."

Initial application:
The issue was initially applied by commit 53dc7647943a1bff90d2177ccf6c2d070c8e75d5 from PR #3192. That commit changed the root ActorDefinition short description from "An application that exchanges data" to "A human or system that exchanges data," but nearby longer description text still used the older human/application wording until later same-family work.

Additional context:
FHIR-43805, also Applied, explicitly asked which ActorDefinition wording should be authoritative and was resolved as the same as FHIR-43646. FHIR-43469 and FHIR-44475 later refined the ActorDefinition actor taxonomy from human/system to system, individual, non-system device, or collective. The combined branch already contains commit 8c1e1ee2bf9c90a8713a262de86b3e9c6edec8be for FHIR-43805, which aligned the active StructureDefinition.description with that current taxonomy. ActorDefinition is active in source/fhir.ini, and the current source no longer contains the stale application-only or human/application wording in the resource description.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build-scope ActorDefinition source already satisfies FHIR-43646 after the initial FHIR-43646 application, the later FHIR-43469/44475 taxonomy refinement, and the already-published FHIR-43805 reconciliation commit are considered together.

Recommendation:
Keep this audit commit as-is. No additional core source edit is needed for FHIR-43646; future ActorDefinition wording changes should be handled under a new tracker or the specific later issue that changes the actor taxonomy.
