FHIR-11129: Audit request performer clarification

Issue request:
FHIR-11129 was a Published FHIR-core change request with a Not Persuasive with Modification resolution. It asked whether DiagnosticRequest.performer should be renamed requestedPerformer and whether multiple requested performers should be possible; the approved disposition kept the element naming but required a usage note that a request does not capture actual execution details such as actual performer, actual code, or execution time, which belong on a separate fulfillment resource pointing back to the request. The resolution also asked Lloyd to check that the complex performer preference extension exists.

Initial application:
Historical commit 839bf586d6c1cf9a322e122852f0cc49bcfed263, "FHIR Workflow changes," explicitly included #11129 and added the Request pattern fulfillment/execution note in source/request/request-spreadsheet-notes.xml. Later commit 1969c8b3ae178206663d635eb0287be95d6e2316 refined the same paragraph to the current wording without changing the requested-vs-actual meaning.

Additional context:
DiagnosticRequest is no longer an active current-build resource, while ServiceRequest is active and the request logical pattern is listed in source/fhir.ini. Current ServiceRequest.performer is still named performer, but its short label is "Requested performer," its definition says it is the desired performer, its cardinality allows multiple performers, and its comment points to the request-performerOrder extension when preference order is needed. That extension now lives in the FHIR Extension Pack and is scoped to ServiceRequest.performer. FHIR-11130 is the adjacent performerType question from the same 2016 workflow family and already has its own combined-branch audit commit.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active Request pattern and ServiceRequest source already preserve the Jira decision: request resources do not record actual fulfillment performers, and ServiceRequest.performer expresses requested performer choices with extension support for ordering preferences.

Recommendation:
Keep this no-change audit commit as-is. No FHIR core source follow-up is needed for FHIR-11129 unless the work group reopens the broader performer naming model; the historical DiagnosticRequest page is out of current build scope.
