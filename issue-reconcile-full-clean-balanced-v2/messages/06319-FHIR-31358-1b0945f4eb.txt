FHIR-31358: Audit DiagnosticReport ImagingStudy support

Issue request:
FHIR-31358 was an Applied FHIR-core DiagnosticReport change request from OO, resolved Persuasive with Modification for R6. The issue asked for a way to distinguish the use of referenced imaging studies, and the final resolution was to add ImagingStudy as a valid DiagnosticReport.supportingInfo.reference target; the implementation discussion also distinguished DiagnosticReport.study for studies the report is about from supporting information used as background.

Initial application:
The issue was applied before this reconciliation. Commit 1049a3eebe875f2724cab72cd94ac9352531018b added http://hl7.org/fhir/StructureDefinition/ImagingStudy to the DiagnosticReport.supportingInfo.reference targetProfile list, and merge commit ebc006438a142400baa260e51ba9f292c36049e5 linked that work back to FHIR-31358. No separate explanatory narrative was added in that application commit.

Additional context:
source/fhir.ini actively includes diagnosticreport in the current build, so source/diagnosticreport/structuredefinition-DiagnosticReport.xml is authoritative build-scoped source. The current source still contains the FHIR-31358 ImagingStudy target under DiagnosticReport.supportingInfo.reference and still contains DiagnosticReport.study for imaging studies that are part of the diagnostic investigation. Later applied DiagnosticReport issues changed the surrounding model: FHIR-45132 broadened supportingInfo.reference targets and has already been audited on the combined branch, while FHIR-48389 added DiagnosticReport.comparison and clarified that supportingInfo should only be used for resources not referenced elsewhere in the same DiagnosticReport. That later comparison element now carries the prior/comparison-study use case that the FHIR-31358 discussion originally used as an example.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current source already implements the final FHIR-31358 action by allowing ImagingStudy in DiagnosticReport.supportingInfo.reference, and adding new prose saying that prior comparison imaging studies belong in supportingInfo would conflict with the later applied DiagnosticReport.comparison design.

Recommendation:
Keep this audit commit as-is. No core source change is needed for FHIR-31358. Future work, if any, should happen through later comparison-model issues rather than by reintroducing pre-FHIR-48389 guidance that treats supportingInfo as the preferred place for comparison studies.
