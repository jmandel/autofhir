FHIR-6215: Audit CarePlan activity note rollover

Issue request:
FHIR-6215 was a Published Patient Care change request with resolution Persuasive with Modification. The issue asked whether CarePlan.activity.detail.note should be rolled up into CarePlan.activity.notes; the final decision instead kept the two concepts distinct by renaming CarePlan.activity.notes to CarePlan.activity.progress, clarifying that progress is for adherence/status/progress rather than describing the planned activity, changing the detail note short display, and renaming CarePlan.notes to CarePlan.note.

Initial application:
The Jira comment cites SVN #6766. In the git-svn history, commit d6c4981fa8fe7d58cc3e1cc393aa8cc0b6a83c54 is build@6766 and changed the then-authoritative CarePlan spreadsheet from CarePlan.activity.notes to CarePlan.activity.progress, changed its short display and definition, changed CarePlan.activity.detail.note to CarePlan.activity.detail.description with the requested short display, and renamed CarePlan.notes to CarePlan.note. The current XML StructureDefinition source was later produced by source refactors and still carries the substantive FHIR-6215 outcome.

Additional context:
CarePlan is an active current-build resource in source/fhir.ini. Later FHIR-39101 removed CarePlan.activity.plannedActivityDetail and its children from the active model, so the old detail.note/detail.description location is no longer part of current CarePlan. Later FHIR-48415 re-reviewed CarePlan.activity.progress and updated its comment to say that activity descriptions occur in the resource referenced by CarePlan.activity.plannedActivityReference, matching the post-FHIR-39101 model. Searches found no Zulip or Confluence record for FHIR-6215 that conflicts with Jira/source/git evidence.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active CarePlan StructureDefinition already has CarePlan.activity.progress with the status/progress short display and adherence/status/progress definition, retains a comment preventing it from being used to describe the activity to be performed, and has CarePlan.note rather than CarePlan.notes. The remaining old detail.note wording belongs only to historical context; current source has no active CarePlan.activity.notes, CarePlan.activity.detail.note, or CarePlan.notes occurrence needing correction.

Recommendation:
Keep this audit commit as-is. No follow-up core source edit is warranted for FHIR-6215 unless a future Patient Care decision reintroduces inline planned activity details or changes the boundary between activity progress notes and the referenced planned activity resource.
