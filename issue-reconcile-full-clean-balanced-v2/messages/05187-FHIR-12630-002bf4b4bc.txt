FHIR-12630: Audit Encounter subject rename

Issue request:
FHIR-12630 was a Published/Persuasive PA change request for DSTU2 Encounter. It asked to rename Encounter.patient to Encounter.subject, change the type from Reference(Patient) to Reference(Patient|Group), keep cardinality 0..1, add an Encounter subject search parameter, keep the patient search parameter as patient-only, and document group-style use cases such as anonymous group therapy and herds of animals.

Initial application:
The issue appears to have been applied by git commit a9b565f2261bcc91380512d34e139b86683f33d5, whose subject explicitly references Tracker #12630 and whose patch renamed Encounter examples and the then-authoritative Encounter spreadsheet from patient to subject, changed the subject type to Reference(Patient|Group), and added the subject search parameter while retaining a patient search parameter on Encounter.subject. Later source refactors moved the authoritative definition into structuredefinition-Encounter.xml and bundle-Encounter-search-params.xml.

Additional context:
Encounter remains an active resource in source/fhir.ini, so source/encounter is in the current build. The current Encounter StructureDefinition has Encounter.subject at 0..1 with Reference targets Patient and Group, an alias of patient, and comments covering anonymous group therapy and veterinary herd treatment. The current search parameter bundle has Encounter-patient constrained to Encounter.subject.where(resolve() is Patient) with target Patient, and Encounter-subject on Encounter.subject. Jira and community searches found the original Jira and implementation notification but no Confluence reference or later final decision that reverses this seed request.
