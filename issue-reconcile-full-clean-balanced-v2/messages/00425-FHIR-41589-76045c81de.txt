FHIR-41589: Align expansion parameter documentation

Issue request:
FHIR-41589 was an Applied/Persuasive vocab Change Request for R6 asking the ValueSet $expand documentation to clarify that ValueSet.expansion.parameter entries in a returned ValueSet are not merely the operation input parameters. The accepted adjusted resolution kept the guidance as SHOULD and identified the minimum categories as client-provided input parameters used by the server, server-defaulted input parameter values, and terminology artifacts used in the expansion.

Initial application:
Commit 39f96b21ce8d65b5b086b3ee61a455e47a359a98 applied the FHIR-41589 narrative change to source/valueset/valueset-notes.xml, but it did not update the active ValueSet/$expand operation output parameter documentation or the active ValueSet.expansion.parameter element comment. Later commit 4cd9f00b61b02c28e614ef3268a899e8610b9242 applied FHIR-41639 by adding the used-system, used-supplement, and used-valueset expansion response parameter table beneath the FHIR-41589 narrative.

Additional context:
Terminology Infrastructure WGM minutes for 2023-09-13 record that FHIR-41639 handled the terminology-artifact accounting portion of the discussion and that FHIR-41589's remaining question was whether to change SHOULD to SHALL; the work group accepted an adjusted resolution because parameters should not be required by default. The current source/fhir.ini has an active valueset=ValueSet resource entry, so the ValueSet resource source files and operation definition in source/valueset are in current build scope.

AutoFHIR reconciliation:
This commit updates the ValueSet/$expand return parameter documentation and the ValueSet.expansion.parameter comment so the active generated operation page and element definition match the applied narrative: expansion parameters SHOULD include used input parameters, defaulted input parameter values, and CodeSystems, CodeSystem Supplements, and ValueSets used in the expansion, with a link to the ValueSet Expansion Parameters section.

Recommendation:
Keep this source fix. It preserves the accepted SHOULD guidance, avoids duplicating the full narrative table in the operation definition, and removes stale pre-FHIR-41589 summaries from active build inputs.
