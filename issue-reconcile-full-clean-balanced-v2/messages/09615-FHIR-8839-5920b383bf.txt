FHIR-8839: Audit ElementDefinition requirements table

Issue request:
FHIR-8839 was a Published/Persuasive technical correction against FHIR-core StructureDefinition. It reported that the ElementDefinition interpretation table said requirements were optional on the first ElementDefinition while sdf-9 forbade requirements on that root element, and the final resolution was to fix the table typo.

Initial application:
The issue was applied in SVN revision 7142, imported as git commit c38c9a8edc, which changed source/elementdefinition.html so the requirements/comments/alias row was prohibited for base and constraint first elements instead of optional. Later refactors split that combined row, but preserved requirements as prohibited on root ElementDefinitions.

Additional context:
FHIR-13721 and FHIR-15803 made later sdf-9 expression and grammar corrections and are already represented on the combined branch. FHIR-48326 later relaxed sdf-9 by removing code and label from the invariant while explicitly retaining requirements because ElementDefinition.requirements overlaps StructureDefinition.purpose. The current table mirrors that later scope: label and code are optional on root elements, while requirements remain prohibited.

AutoFHIR reconciliation:
This audit commit makes no source change. The active StructureDefinition resource source contains sdf-9 as a requirements-only root-element invariant, and source/elementdefinition.html now says requirements are prohibited for both type-definition and constraint-definition root elements, so the inconsistency reported by FHIR-8839 is already resolved in current source.

Recommendation:
Keep this empty audit commit as-is. No FHIR-core source follow-up is needed for FHIR-8839; future work should not reintroduce the old code/label prohibition unless FHIR-I reverses FHIR-48326.
