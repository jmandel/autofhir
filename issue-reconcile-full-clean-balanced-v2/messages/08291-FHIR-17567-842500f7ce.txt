FHIR-17567: Audit targetProfile wording

Issue request:
FHIR-17567 was a Published/Persuasive FHIR-core OperationDefinition request to improve the poor OperationDefinition.parameter.targetProfile detailed description and address an example that appeared wrong because a Reference parameter had no targetProfile.

Initial application:
The issue was applied in git-svn commit 7918c8dc0cfb27ce1ab1504e6cfa043771ab2695, matching Jira's svn revision 14534 comment. That commit changed the OperationDefinition spreadsheet from the old "If the type is Reference" wording to optional Reference/canonical target wording and added the one-way opd-3 invariant that a targetProfile, when present, is only allowed on appropriate parameter types. It did not add targetProfile values to the example because the corrected rule does not require targetProfile for every Reference parameter.

Additional context:
OperationDefinition is an active current-build resource in source/fhir.ini. Later same-element decisions FHIR-17725, FHIR-26411, FHIR-39345, and FHIR-44690 refined this area by recognizing inline-resource/profile use and correcting opd-3 through the current all-resource-types expression. The checked-in SVG still has older tooltip-like wording, but it is a generated-looking diagram artifact and the authoritative XML source has the current rule.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current source removes the original poor wording, keeps targetProfile optional, constrains targetProfile only when present, and therefore leaves operationdefinition-example.xml valid even though its Reference parameters do not declare targetProfile.

Recommendation:
Keep this audit commit as-is. No core source fix is needed for FHIR-17567; future work should handle any stale generated diagram tooltip or unrelated example typing issue under a separate tracker rather than reopening this applied STU3 targetProfile wording issue.
