FHIR-5206: Audit EpisodeOfCare status history guidance

Issue request:
FHIR-5206 was a Published/Persuasive DSTU1 ballot comment for EpisodeOfCare asking for clearer guidance on the statusHistory sub-component, including why it exists instead of requiring servers or clients to rely on FHIR resource version history and how status periods should be understood.

Initial application:
The issue was applied in git commit 8b7f2a91125c5387861132e44199814238044938, which explicitly named Tracker# 5206 and expanded EpisodeOfCare notes with status-management examples, leave handling, active-day reporting, and period-oriented workflow guidance. That same change family also updated the EpisodeOfCare example narrative and status-code material for FHIR-5833 and FHIR-5834. The 2021 source rework carried the relevant statusHistory definition into source/episodeofcare/structuredefinition-EpisodeOfCare.xml.

Additional context:
EpisodeOfCare is active in the current build via source/fhir.ini and remains approved. The current StructureDefinition defines EpisodeOfCare.statusHistory as the past status list, states that it avoids requiring processing the resource history, and defines a required period for each history entry. The current notes page still contains a Status Management section with an intake workflow, leave-handling guidance, and active-day reporting derived from status history. The example instance includes multiple statusHistory entries with periods, including the current active period. Later Jira hits FHIR-55295/FHIR-55296 concern adding an unknown escape-valve code to the status value set and do not change the FHIR-5206 guidance question; FHIR-55295 is only Resolved - change required and is outside this default Applied/Published source-edit scope.

AutoFHIR reconciliation:
This audit commit makes no source change. The current active source already preserves the required clarification: statusHistory is documented as a status list independent of resource-version history, each history status has a required period, and the narrative/example show how status transitions and periods support implementer use cases.

Recommendation:
Keep this no-change audit as-is. Do not add redundant prose for FHIR-5206 unless PA later decides to revise EpisodeOfCare status guidance more broadly; handle FHIR-55295/FHIR-55296 separately if the run scope includes Resolved - change required issues.
