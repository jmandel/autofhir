FHIR-32582: Audit DocumentReference sourcePatientInfo migration

Issue request:
FHIR-32582 was Published/Persuasive for R5 and asked to remove DocumentReference.sourcePatientInfo because the XDS-specific source patient metadata should be represented as an extension rather than a core resource element.

Initial application:
The implementation landed in HL7/fhir via commit 82d7ae7918d657b4dcd4534d3c244163aca850a9 and merge f2d7b07e50c2811a7ede6ce944f5cb33ecb12a98, which removed DocumentReference.sourcePatientInfo from structuredefinition-DocumentReference.xml, changed the two DocumentReference examples to use http://hl7.org/fhir/StructureDefinition/documentreference-sourcepatient, and added the extension definition in the DocumentReference source area.

Additional context:
source/fhir.ini keeps DocumentReference active in the current build and maps the old R4 DocumentReference.context.sourcePatientInfo element to the documentreference-sourcepatient extension. The extension definition is no longer in this core checkout; the current Extension Pack checkout defines http://hl7.org/fhir/StructureDefinition/documentreference-sourcepatient for DocumentReference with a Patient reference value. Confluence OO minutes on 2022-07-12 confirm the 3-0-0 motion to accept FHIR-32582 as proposed. No relevant Zulip conflict was found.

AutoFHIR reconciliation:
No source change was needed. The current core resource no longer contains DocumentReference.sourcePatientInfo, active examples use the extension, and the extension's current source of truth is in the FHIR Extension Pack rather than core.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed for FHIR-32582; future changes to the extension definition should be made in the FHIR Extension Pack if requirements change.
