FHIR-17144: Audit enableWhen expression handling

Issue request:
FHIR-17144 was a Published/Persuasive FHIR-core Questionnaire change request from STU3 asking how to express more complex enableWhen conditions than repeated simple enableWhen clauses. The approved resolution deprecated the old cqif-condition approach and called for a questionnaire enableWhen expression extension on Questionnaire.item, with use only when the item has no enableWhen elements.

Initial application:
The Jira comment records SVN revision 13896, and the imported git history shows b89387a2a19a73a179674e028fd5f93bc3826dad as the FHIR-17144-era commit that deprecated cqif-condition. Current core source no longer contains an active cqif-condition definition; the remaining core Questionnaire source references enableWhenExpression as the escape valve for logic more complex than repeated enableWhen answers.

Additional context:
FHIR-19527 later moved complex Questionnaire/QuestionnaireResponse extensions from core into the SDC IG and specifically renamed questionnaire-enableWhen to questionnaire-enableWhenExpression. The current SDC source defines the active sdc-questionnaire-enableWhenExpression extension for Questionnaire.item, constrains it to 0..1 Expression, comments that it is only permitted when the containing item has no enableWhen elements, and the SDC behavior profile has an invariant prohibiting simultaneous enableWhen and enableWhenExpression. The existing combined branch already contains a FHIR-19527 reconciliation commit, so this audit does not duplicate that related issue.

AutoFHIR reconciliation:
No source change was made. The current FHIR core build-scope Questionnaire source conveys the base enableWhen behavior and points complex logic to enableWhenExpression, while the extension definition and detailed behavior now intentionally live in the SDC source rather than the core checkout.

Recommendation:
Keep this audit commit as-is. Do not reintroduce the extension definition in core; any future changes to the extension body or SDC guidance should be handled in the SDC IG, while core should only be revisited if its Questionnaire wording becomes misleading about the existence or intended use of enableWhenExpression.
