FHIR-14274: Audit Appointment status value set

Issue request:
FHIR-14274 was a Published/Persuasive PA change request for STU3 Appointment asking to update the `arrived` appointment status definition and add a new checked-in status meaning that pre-encounter administrative work is complete and the encounter may begin.

Initial application:
The issue was applied by historical commit 68f28a21fd1626040d70a0c958e427e1368726ca (`GF#14274: Changes to the appointment-status value set`), which changed the old Appointment spreadsheet from `arrived` = "Some of the patients have arrived." to the plural-safe waiting-to-be-seen definition and added `checked-in` with the requested pre-encounter definition. Later source rework moved this terminology into the current XML CodeSystem/ValueSet sources without losing those concepts.

Additional context:
`source/fhir.ini` actively includes Appointment as a current resource, and the active `Appointment.status` element has a required binding to `ValueSet/appointmentstatus`. Earlier FHIR-3462 established the Appointment-specific status set; later FHIR-18824 added the separate `waitlist` status and is already represented on the combined branch. Exact-key Zulip and Confluence searches found no discussion that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope Appointment status CodeSystem has `arrived` defined as "The patient/patients has/have arrived and is/are waiting to be seen." and has `checked-in` defined as "When checked in, all pre-encounter administrative work is complete, and the encounter may begin. (where multiple patients are involved, they are all present)." The required-bound Appointment status value set includes that CodeSystem, and the `Appointment.status` short description lists `checked-in`.

Recommendation:
Keep this no-change audit commit as-is. The current source already preserves the approved semantics; changing wording to match the Jira prose exactly would be editorial only and could reduce the current plural-safe phrasing.
