FHIR-3073: Audit re-identification typo correction

Issue request:
FHIR-3073 was a Published/Persuasive technical correction for the Managing Resource Identity page. It asked to replace the erroneous explanation "re-identified (i.e. assigned a new resource)" with wording that explained re-identification as assignment of a new URL and possibly a logical id.

Initial application:
The issue was applied in git-svn commit 5d8665e4d9a8a91b10228af3182583faf645139b, matching Jira's svn revision 3046 note. That commit removed the nonsensical "assigned a new resource" wording from source/managing.html and replaced it with "assigned a new logical resource id."

Additional context:
The current source/managing.html page is in the built source tree through source/hierarchy.xml and links from current narrative pages. Later Published issues FHIR-16470 and FHIR-16466 reworked this same section: FHIR-16470 removed the potentially confusing "re-identification" terminology in favor of "Assigning new Ids," and FHIR-16466 made the page informative while moving broader resource identity terminology to resource.html#id. Those later decisions explain why the current wording does not literally match the original requested phrase.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source no longer contains the erroneous "assigned a new resource" phrase, and the active Managing Resource Identity text now says resources may need new logical resource ids while the surrounding paragraphs separately explain replacing the Base URL and keeping the logical id when appropriate.

Recommendation:
Keep this audit commit as-is. FHIR-3073 is already substantively applied in the current specification; changing the current wording back toward the original Jira suggestion would duplicate or disturb later FHIR-16470/FHIR-16466 editorial decisions.
