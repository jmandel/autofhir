FHIR-3030: Use system terminology in token search docs

Issue request:
FHIR-3030 was Published/Persuasive for DSTU1 and asked that search parameter documentation replace token and quantity forms using [namespace] with [system] and with code/value wording where Identifier.value is involved.

Initial application:
Jira records svn revision 3077. The corresponding git-svn commit f97b8d01162ec11b7e54111d7e77f323b52df814 changed source/search.html token syntax from [namespace]|[code] to [system]|[code] and changed the quantity syntax from [namespace] to [system]. The current source had retained or later reintroduced namespace wording in adjacent token documentation and in the linked _filter token page.

Additional context:
source/search.html is the active Search (RESTful API) source page, and source/fhir.ini's search-rules note explicitly treats search.html as the summary table authority for search type updates. source/search_filter.html is an active _filter Parameter source page linked from source/search.html and source/exchanging.html. Later source edits substantially refactored the search text, so the current correct application is semantic consistency with system/code or system/value terminology rather than literal [code/value] placeholder syntax everywhere. Zulip and Confluence searches found no directly relevant discussion changing the Jira/source conclusion.

AutoFHIR reconciliation:
This commit updates the current active token prose to say searches are performed against the system and code/value pair, changes the escaping note from namespace URI/code to system URI/code-value, changes the boolean-token note to refer to the code system, and aligns the linked _filter token wording to system/full system URI. No quantity hunk was needed because current quantity search syntax already uses [system].

Recommendation:
Keep this source fix as-is. It completes the old Published issue against the current build by removing the remaining misleading namespace terminology in token-related search documentation without changing the mature token placeholder syntax or unrelated namespace uses.
