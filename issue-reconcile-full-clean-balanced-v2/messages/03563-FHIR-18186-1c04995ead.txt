FHIR-18186: Audit PlanDefinition definitionUri support

Issue request:
FHIR-18186 was a Published/Persuasive CDS change request for PlanDefinition asking that an action definition be able to reference a URI for a non-FHIR definition, not only a canonical reference to a FHIR definitional resource.

Initial application:
The Jira comment points to GH#03255f090f. Commit 03255f090f changed the then-authoritative PlanDefinition spreadsheet from PlanDefinition.action.definition to PlanDefinition.action.definition[x] and changed the type from canonical(ActivityDefinition|PlanDefinition|Questionnaire) to canonical(...) | uri. Commit 72f0fdf2f4 immediately followed by updating PlanDefinition examples from the pre-choice definition element to definitionCanonical where they referenced FHIR resources.

Additional context:
The current build no longer uses that spreadsheet as the active source, but source/fhir.ini includes PlanDefinition as an active resource and the current source/plandefinition/structuredefinition-PlanDefinition.xml preserves PlanDefinition.action.definition[x] with both canonical and uri type choices. Later applied issue FHIR-48981 clarified the purpose of definitionUri and added matching RequestOrchestration behavior; the current PlanDefinition and RequestOrchestration source contains that clarification, so it reinforces rather than reverses FHIR-18186.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because the active PlanDefinition StructureDefinition already allows definitionUri in addition to definitionCanonical and includes current explanatory text for the uri case.

Recommendation:
Keep this no-change audit as-is. The core FHIR source already implements the published FHIR-18186 decision; FHIR-48981 was reviewed only as later context and can be reconciled independently if needed.
