FHIR-8319: Audit Bundle request URL wording

Issue request:
FHIR-8319 was a Published/Persuasive DSTU1 FHIR-core Feed clarification asking to adjust the old Bundle.entry.transaction.url wording because it could be read as requiring conditional-update search parameters rather than describing the request URL itself.

Initial application:
The issue was applied in SVN revision 5480, now git commit 1b2b7f4995d43a82c2ea1c53ca1d095b08cc46f9, which changed the old Bundle spreadsheet definition from a search-URL description to a general transaction URL relative to the root. Later source refactoring carried the concept forward to Bundle.entry.request.url in source/bundle/structuredefinition-Bundle.xml.

Additional context:
FHIR-6329 raised the same old wording and was later marked as overtaken by replacement of the element text. FHIR-6331 clarified the adjacent base/leading-slash rules for the same URL family. Current source/fhir.ini has Bundle as an active resource, and current Bundle.entry.request.url says the URL is relative to the root while the transaction example shows search parameters only where a conditional update actually needs them. No relevant Zulip or Confluence record was found that reverses this interpretation.

AutoFHIR reconciliation:
This empty audit commit makes no FHIR-8319 source change because the current source no longer contains the misleading search-URL-only wording and the current transaction example still demonstrates conditional-update search parameters in the URL when appropriate.

Recommendation:
Keep this audit as-is for FHIR-8319. The seed issue is already represented correctly; the separate FHIR-6331 reconciliation handles stale no-leading-slash examples discovered while checking the same URL family.
