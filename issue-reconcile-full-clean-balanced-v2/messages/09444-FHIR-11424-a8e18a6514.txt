FHIR-11424: Audit Request requester organization handling

Issue request:
FHIR-11424 was Published/Persuasive with Modification for DSTU2. It asked for Request.requester to support identifying both the requesting practitioner/device/agent and the organization, with the final resolution changing Request.requester from one Reference to a backbone with requester.agent 1..1 and requester.onBehalfOf 0..1 Organization plus an invariant limiting onBehalfOf to Practitioner or Device agents.

Initial application:
The 2016 workflow batch commit 839bf586d6c1cf9a322e122852f0cc49bcfed263 applied the resolution by adding Request.requester.agent and Request.requester.onBehalfOf and the onBehalfOf invariant to source/request/request-spreadsheet.xml. Later workflow-pattern history intentionally replaced that backbone: FHIR-13159/SVN#12374 in commit 5064224bd079b7f4ef4023d3ead9111b57bd8bff dropped agent/onBehalfOf and made Request.requester a direct Reference including PractitionerRole, and commit 14b69a1c6dd33918b20d53ffd6cfbab523f840ba removed the stale onBehalfOf invariant.

Additional context:
source/fhir.ini lists request as an active logical model, so source/request/request-spreadsheet.xml is the relevant current build input. Current Request.requester is 0..1 Reference(Practitioner|PractitionerRole|Organization|Patient|RelatedPerson|Device), which preserves the practitioner-plus-organization use case through PractitionerRole rather than the old onBehalfOf backbone. Related final decisions FHIR-13159 and FHIR-15128 are already represented on the combined branch: FHIR-13159 audits the PractitionerRole replacement, and FHIR-15128 declined bringing onBehalfOf back to workflow patterns and fixed the remaining stale requester search path.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because the current Request pattern already supports identifying a practitioner acting for an organization via PractitionerRole, and later Published workflow decisions intentionally superseded the original FHIR-11424 backbone representation.

Recommendation:
Keep this audit as-is. Do not restore Request.requester.agent/onBehalfOf without a new work-group decision reversing the later PractitionerRole-based workflow pattern; no current FHIR-core follow-up is needed for FHIR-11424.
