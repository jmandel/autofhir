FHIR-3090: Audit conformance search parameter support

Issue request:
FHIR-3090 was a Published/Persuasive FHIR-core search issue asking for stronger conformance search-parameter expression: clarify the meaning of Conformance.rest.resource.searchParam.chain, add an invariant that chain is only present for reference search parameters, and add a standard extension for supported search parameter combinations with required and optional members.

Initial application:
The Jira records application for DSTU1 and a comment identifying svn revision 6019. In git, commit 7da5e20e76 (#3090 - chain search parameter improvements) added the expanded chain definition and chain/type invariant to the Conformance spreadsheet. Later commit de92e40608 (#7996 - move things from CapabilityStatement to SearchParameter) moved chain, comparators, modifiers, and targets from CapabilityStatement/Conformance searchParam declarations to the standalone SearchParameter resource while preserving the FHIR-3090 chain wording and invariant semantics.

Additional context:
CapabilityStatement and SearchParameter are active current-build resources in source/fhir.ini. The current CapabilityStatement searchParam definition points implementers to linked SearchParameter definitions and extension elements for additional behavior. The supported-parameter-combination extension is no longer a core source file because commit dd468d4f17 removed extension definitions from the R5 core source; the same extension now exists in the FHIR Extension Pack as capabilitystatement-search-parameter-combination, scoped to CapabilityStatement.rest.resource with required and optional child slices. FHIR-7996 is a supporting later change because it explains the relocation of the chain details from CapabilityStatement to SearchParameter, but it is a separate tracker and is not decided by this audit.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core source already carries the chain documentation and the chain-only-for-reference invariant on SearchParameter, CapabilityStatement remains wired to SearchParameter and extension-based behavior descriptions, and the search parameter combination extension is maintained outside the core checkout in the Extension Pack.

Recommendation:
Keep this audit commit as-is. Do not reintroduce the extension definition into core merely to match the older Conformance-era Jira wording; future changes to the combination extension should be made in the FHIR Extension Pack, while core should continue to keep the SearchParameter.chain definition and spd-2 invariant aligned.
