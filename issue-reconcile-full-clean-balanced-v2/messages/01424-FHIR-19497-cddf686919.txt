FHIR-19497: Audit PaymentReconciliation attribute updates

Issue request:
FHIR-19497 is a Published/Persuasive FHIR-core PaymentReconciliation change request, raised and applied for STU3. It asked to rename PaymentReconciliation.total to paymentAmount, add PaymentReconciliation.paymentIdentifier as Identifier 0..1, align detail.submitter reference targets with Claim.provider, and add Practitioner and PractitionerRole to detail.payee targets.

Initial application:
The issue was initially applied in commit f369c813fb, whose message explicitly included GF#19497 among a batch of Financial Management changes. That commit updated the then-authoritative PaymentReconciliation spreadsheet and example to use paymentAmount, added paymentIdentifier, changed detail.submitter to Reference(Practitioner|PractitionerRole|Organization), and changed detail.payee to Reference(Practitioner|PractitionerRole|Organization).

Additional context:
PaymentReconciliation is an active current resource in source/fhir.ini. Later Published PaymentReconciliation work in FHIR-26601 intentionally renamed paymentAmount to amount and detail to allocation for the current build; the current version mapping records PaymentReconciliation.total to paymentAmount and paymentAmount/detail.* to amount/allocation.*. FHIR-26601 is already represented on the combined branch, so this audit does not duplicate that later source-changing decision.

AutoFHIR reconciliation:
No source change was made. Current build-scope source has PaymentReconciliation.amount as the total payment amount, PaymentReconciliation.paymentIdentifier as Identifier 0..1, PaymentReconciliation.allocation.submitter with the same Practitioner, PractitionerRole, and Organization targets as Claim.provider, and PaymentReconciliation.allocation.payee with Practitioner, PractitionerRole, and Organization targets.

Recommendation:
Keep this empty audit commit as-is. The current source preserves the FHIR-19497 semantics under later approved element names, and reintroducing the old paymentAmount/detail names would conflict with FHIR-26601 and the current version mapping.
