FHIR-25038: Audit update response header optionality

Issue request:
FHIR-25038 was a Published/Persuasive with Modification FHIR-I clarification for the FHIR-core HTTP update interaction. It asked that update success wording stop implying a SHALL requirement for ETag, and the approved resolution also clarified that Last-Modified was not intended to be SHALL; where the server supports FHIR versioning, the headers should be SHOULD-level guidance.

Initial application:
No explicit source commit mentioning FHIR-25038 was found. The current application appears to have occurred implicitly in c32a2adb0774d63553808f9e2b551292292e7fed, a 2022-05-11 HTTP update response change for FHIR-26358 that split the old SHALL sentence and replaced the ETag/Last-Modified requirement with separate SHOULD wording. Jira was then updated on 2022-05-16 to say build.fhir.org/http.html#update already showed the requested update.

Additional context:
publish.ini maps http.html to the built HTTP page, so source/http.html is in current build scope. FHIR-I minutes from 2020-03-23 confirm the FHIR-25038 decision, including that this was a clarification to poorly written normative wording. Later FHIR-39117 addressed the same optionality principle in the HTTP interaction summary table by changing ETag/Last-Modified from required to optional, and that issue is already represented on the combined branch. FHIR-26358, whose source commit carried the effective wording change, is also already represented on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped update interaction text says successful update/create responses SHALL use the correct 200/201 status and SHALL return Location, but separately says servers SHOULD return an ETag with versionId when versioning is supported and a Last-Modified header. This preserves the Jira-approved clarification that ETag and Last-Modified are not mandatory update response headers.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-25038 unless FHIR-I later wants a broader editorial restatement of the existing SHOULD wording.
