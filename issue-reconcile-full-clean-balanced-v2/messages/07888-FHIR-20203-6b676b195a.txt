FHIR-20203: Audit operations parameter count wording

Issue request:
FHIR-20203 was a Published/Persuasive FHIR-I change request for the Operations page. It pointed out that the execution overview first said an operation returns a Parameters resource with one or more output parameters but then summarized operations as returning zero or more result parameters, and the approved resolution changed the overview to distinguish zero-or-more input parameters from one-or-more output parameters, with a special unwrapped Resource return case.

Initial application:
The issue was applied by git commit 7aa4b98258, which updated source/operations.html to say that operations take zero or more input parameters, return a Parameters resource containing one or more output parameters, and may return a bare Resource when the single output parameter is named 'return'.

Additional context:
source/hierarchy.xml lists operations.html as the Operations page in the current build. Later Published/Persuasive issues in the same paragraph refined the seed text: FHIR-24869 added the zero-output response rule that the body may be omitted, and FHIR-28292 changed the single Resource return rule from MAY to SHALL when the return output has maximum cardinality 1. The combined branch already contains reconciliation commits for FHIR-24869 and FHIR-28292, so this seed audit should not duplicate those decisions.

AutoFHIR reconciliation:
This is an empty audit commit. The current active Operations source already preserves the FHIR-20203 distinction: operations take zero or more input parameters, a Parameters response body contains one or more output parameters when present, a zero-output result may omit the body, and the later single Resource return SHALL/no-wrapping rule is retained.

Recommendation:
Keep this audit commit as-is. No FHIR-20203 source change is needed; future edits should only revisit the paragraph if the work group wants broader editorial cleanup beyond the published parameter-count decisions.
