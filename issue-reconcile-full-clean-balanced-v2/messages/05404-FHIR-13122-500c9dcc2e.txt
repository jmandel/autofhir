FHIR-13122: Audit DICOM value set OIDs

Issue request:
FHIR-13122 was a Published/Persuasive DSTU2 vocabulary issue asking FHIR core to fix three DICOM OIDs: add 1.2.840.10008.2.16.4 to the DICOM Controlled Terminology code system, use 1.2.840.10008.6.1.908 for DICOM CID 405 media type, and use 1.2.840.10008.6.1.811 for Instance Availability.

Initial application:
The issue was applied by SVN/git commit 760cb60ceb (svn 14623), which added the DICOM code system identifier and corrected the CID 405 and Instance Availability value set OIDs in the then-active hand-maintained source files.

Additional context:
Later Published/Persuasive work in FHIR-24908 intentionally removed the hand-written DICOM value sets from core and switched affected resources to DICOM-authored terminology. Commit 26f1439636 removed the local CID 405 file as no longer necessary, and commit b3994b69a3 removed the local DICOM code system because it now comes from DICOM directly. Current source therefore has no stale FHIR-owned DICOM OID file to edit; only the DICOM import/fixup inputs remain in scope.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The original OID corrections are present in historical generated R4 artifacts, and the current build no longer owns the affected DICOM code system/value set definitions as editable core source.

Recommendation:
Keep this audit commit as-is. Do not reintroduce local FHIR copies of DICOM terminology for this historical issue; any future correction to the current DICOM terminology content should be handled through the DICOM-authored terminology/package path rather than by editing removed core source files.
