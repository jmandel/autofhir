FHIR-32456: Audit AuditEvent media distinction

Issue request:
FHIR-32456 was a Published, Persuasive with Modification Security WG issue for AuditEvent. It asked for Email and URI not to be treated as media because network addresses/protocols are captured separately; the final resolution tied the requested correction to FHIR-32450 and FHIR-32459 and clarified media as persistence media, with protocols that can be either persistence or transport left to implementer choice.

Initial application:
No prior source commit explicitly mentioning FHIR-32456 was found. The application appears to have been made through the related implementation commit 3d204189e23e03f0b4f11d03d491bc1d868e399b for FHIR-32450 and FHIR-32459, which removed AuditEvent.agent.media, replaced AuditEvent.agent.network.address/type with AuditEvent.agent.network[x], and added AuditEvent.entity.agent with persistence-media wording.

Additional context:
FHIR-32450 directed removal of .agent.media and addition of .entity.agent similar to Provenance.entity.agent, with a persistence-media definition and DICOM mapping. FHIR-32459 directed replacing the network type/address backbone and network-type value set with network[x] as Reference(Endpoint), uri, or string. The 2021-08-23 Security minutes discuss FHIR-32456 with FHIR-32450 and FHIR-32459, recording that media is used for persistent methods, email might be persistence or network, network is used for communication media and unclear persistent nature, and media may be better modeled as an entity with an entity.agent relationship. The 2021-09-13 Security block vote approved FHIR-32456 with the same related issues.

AutoFHIR reconciliation:
No source change was made. AuditEvent is active in source/fhir.ini, and the current build-scope source already expresses the resolved model: AuditEvent.agent.network[x] captures endpoint references, URIs, or strings; AuditEvent.entity.agent describes persistence media as the entity attributed to an agent; and fhir.ini migration mappings direct old AuditEvent.agent.media and old network address/type elements to the current model. The only remaining audit-media-type/network-type references found are OID registry entries, not active AuditEvent bindings or built element definitions.

Recommendation:
Keep this empty audit commit as-is. No core source follow-up is needed for FHIR-32456; related FHIR-32450 may be audited separately, while FHIR-32459 is already represented on the combined branch.
