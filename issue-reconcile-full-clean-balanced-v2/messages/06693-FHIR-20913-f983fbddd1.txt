FHIR-20913: Audit DeviceUsage negative-use support externally owned

Issue request:
FHIR-20913 was a Published OO change request for STU3/R5 DeviceUseStatement asking for a way to say that a patient does not use or does not have a type of device, such as no hearing aid or visual aid. The approved Persuasive with Modification resolution added DeviceUseStatement.usageStatus 0..1 CodeableConcept with example values such as always, sometimes, and never, plus DeviceUseStatement.usageReason 0..* CodeableConcept with example values such as forgot, lost, stolen, and broken, while keeping the statement lifecycle status separate.

Initial application:
The request was applied in February 2020 by commit ce5720447c, which explicitly lists FHIR-20913 and added DeviceUseStatement.usageStatus and DeviceUseStatement.usageReason to the DeviceUseStatement spreadsheet. The later source refactor to StructureDefinition XML and the FHIR-31478 rename carried these fields forward as DeviceUsage.usageStatus and DeviceUsage.usageReason.

Additional context:
FHIR-26308 later accepted the broader set of pre-applied DeviceUseStatement/DeviceUsage updates that included FHIR-20913. FHIR-25798 asked whether usageStatus/usageReason should become Event pattern elements and was resolved No Change, so the approved scope stayed local to use/usage resources rather than becoming a global Event edit. FHIR-32829 later added a DeviceUsage.adherence backbone related to the same usage-status/reason semantics and is already represented on the combined branch. Most importantly for current core reconciliation, commit 3b38b80cf2 removed DeviceUsage from active source/fhir.ini build metadata and redirected current core DeviceUsage links to the OO Incubator IG; build.fhir.org/deviceusage.html now returns 404, while the incubator DeviceUsage StructureDefinition is live and contains usageStatus and usageReason.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The retained source/deviceusage files still show the historical FHIR-20913 elements, but DeviceUsage is no longer an active current core resource; editing those inactive files would not change the current core specification, and any future DeviceUsage structural correction belongs in the OO Incubator artifact/source path.

Recommendation:
Keep this external-repo audit for core FHIR. Do not edit inactive core source/deviceusage files for FHIR-20913 unless DeviceUsage is reactivated in source/fhir.ini; if the ongoing DeviceUsage model needs cleanup, reconcile that work against the OO Incubator IG that now owns the published artifact.
