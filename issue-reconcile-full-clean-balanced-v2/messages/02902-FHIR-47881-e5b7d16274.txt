FHIR-47881: Audit Device software wording

Issue request:
FHIR-47881 was an Applied/Persuasive R6 OO change request to clarify the Device software section by replacing "The Device resource is intended to represent..." with "The Device resource can represent..." because Device is not intended only to represent software. The OO vote on 2024-11-18 was 7-0-0 and the issue was marked Applied.

Initial application:
The request appears to have been applied in git commit 3cf635fa2b606d038462a683a53338e39b3f30e3, "Text updates for Devices - R6 Info3", which explicitly lists FHIR-47881 and removed the old Software subsection paragraph containing "The Device resource is intended to represent an instance of a software component or application." It replaced the category prose with a more general sentence listing software as one possible Device category. A later source cleanup left that sentence as "Devices may be categorized..." and the current source no longer contains the misleading requested phrase.

Additional context:
source/fhir.ini has an active [resources] entry device=Device, so source/device/device-introduction.xml is build-scoped for the current Device page. The current Scope and Usage text already says medical devices may include some software and that non-medical devices may include software applications or algorithms, then lists software as one category. OO Confluence minutes for 2024-11-18 record the same Software section disposition, and no Zulip hit was found for FHIR-47881.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The exact problematic sentence is absent from the current source, and the remaining Device prose communicates that software is included as an example/category rather than defining Device as software-only.

Recommendation:
Keep this no-change audit commit. No follow-up is needed for FHIR-47881 in core unless the work group wants to restore a longer software-specific explanatory section, which would be a new editorial decision rather than applying this tracker.
