FHIR-8807: Audit Resource base definition

Issue request:
FHIR-8807 was a Published/Persuasive FHIR-core correction for the DSTU1 BaseResource artifact. It reported that the StructureDefinition for the Resource base resource had a malformed base of http://hl7.org/fhir/StructureDefinition/ and said Resource should not have a base; the approved technical correction was applied for DSTU2.

Initial application:
No Git commit in the current checkout mentions FHIR-8807, which is consistent with the Jira comment that the fix had already been made in an earlier SVN revision. The current Git-era Resource source was introduced by 33b409a4b6d544598262f2f074ebb4b6dc466157 and models Resource as a specialization of http://hl7.org/fhir/StructureDefinition/Base, not as deriving from the malformed empty StructureDefinition URL named in the issue.

Additional context:
source/fhir.ini keeps Resource in the active resource-infrastructure build set and lists it in the normative infrastructure package. The current CI build publishes both StructureDefinition/Resource with baseDefinition StructureDefinition/Base and the abstract StructureDefinition/Base itself, so the later Base root model is part of the current specification surface. Searches found no remaining source occurrence of the malformed empty base URL and no Zulip or Confluence discussion that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This empty audit commit makes no source change. Removing Resource.baseDefinition would incorrectly undo the current valid Base specialization model, while the original invalid empty base has already been removed.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-8807 unless the work group separately decides to revisit the current Base root model.
