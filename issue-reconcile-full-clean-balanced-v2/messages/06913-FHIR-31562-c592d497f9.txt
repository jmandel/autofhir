FHIR-31562: Audit iterative include capability guidance

Issue request:
FHIR-31562 was a Published/Persuasive with Modification FHIR-I change request for R5 CapabilityStatement. It asked for a structural way to say which `_include:iterate` parameters SHALL be supported, with the accepted resolution pointing to the CapabilityStatement2 feature approach and to extending the SHALL/SHOULD/MAY expectation extension scope to that feature structure.

Initial application:
No standalone source commit exactly implemented a new CapabilityStatement2 feature structure for this issue. The relevant current application came through the same CapabilityStatement searchInclude rule family: FHIR-36051 commit 3b6e443e496f907801189a895636c924267804eb added guidance that recursive include support is declared in the root resource type's `CapabilityStatement.rest.resource.searchInclude`, and commit a2e0206d1d15324a318ed83dd5d55c65be16e584 explicitly named FHIR-31562 while changing that guidance from the obsolete `_include:recurse` wording to the current `_include:iterate` modifier. The R5 history bundle contains the iterative searchInclude comment.

Additional context:
CapabilityStatement is active in the current core build through source/fhir.ini, and source/capabilitystatement/structuredefinition-CapabilityStatement.xml is the authoritative current source for its element definitions. The current comment on `CapabilityStatement.rest.resource.searchInclude` says iterative include support is communicated by listing the iterative include values supported by the server in the `searchInclude` element of the root resource type; `searchRevInclude` delegates to that comment. Core narrative links to the `capabilitystatement-expectation` extension, and the current FHIR Extension Pack definition of that extension includes contexts for `CapabilityStatement.rest.resource.searchInclude` and `CapabilityStatement.rest.resource.searchRevInclude`, which covers the SHALL/SHOULD/MAY expectation part for include/revinclude values. Zulip follow-up from the applying editor states that FHIR-36051 was the separate tracker for this point and that it was applied there, then fixed to use `:iterate` terminology.

AutoFHIR reconciliation:
This is an empty no-change audit commit. The current core source and the current extension definition together provide the structural path needed for FHIR-31562: list iterative include values in `CapabilityStatement.rest.resource.searchInclude`, and use the expectation extension on those elements when formal conformance strength is needed. Adding a new source edit in core would duplicate or destabilize the already-published guidance, and the relevant extension source now lives in the FHIR Extension Pack rather than this core checkout.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-31562 unless FHIR-I later revives a broader CapabilityStatement2 feature model; any future change to the expectation extension definition should be handled in the FHIR Extension Pack.
