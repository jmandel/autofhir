FHIR-17185: Audit logical model terminology application

Issue request:
FHIR-17185 was Published/Persuasive for STU3 and asked whether StructureDefinition.kind=logical-model should be clarified or replaced because the term "Logical Model" was confusing. The final resolution kept logical as a kind because core tooling needed it, but required clearer kind definitions, an extensible keyword binding to known uses, improved keyword wording, removal of sdf-7, and narrower sdf-19/sdf-21-style constraints so non-HL7-originated StructureDefinitions were not wrongly rejected.

Initial application:
The issue was explicitly applied before this reconciliation by git commit 926384dea351e7ec4743590f452b9873a9e3c5be (svn revision 13873, "GF#17185 - remove logical models"). That commit created definition-use terminology, changed StructureDefinition.keyword from an example profile-code binding to an extensible definition-use binding, improved keyword wording, removed sdf-7 from the then-authoritative spreadsheet, and changed the custom-type/default-value constraints away from blanket logical-model-only checks. Later source refactors, especially commit 33b409a4b6, moved the relevant StructureDefinition content into source/structuredefinition/structuredefinition-StructureDefinition.xml while preserving the FHIR-17185 substance.

Additional context:
The active current build includes StructureDefinition as a resource in source/fhir.ini. Current StructureDefinition.kind still has the required logical code, with terminology that distinguishes complex types from resources and says resources aggregate other types into identifiable entities. Current StructureDefinition.keyword is now deprecated by the later Published FHIR-33100 decision, but it still carries the FHIR-17185 extensible binding to ValueSet/definition-use and wording that describes the use/content of the structure definition. Related logical-model constraint issues such as FHIR-19762, FHIR-21622, and FHIR-33065 are already represented on the combined branch and do not reopen FHIR-17185.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped source already satisfies the FHIR-17185 applied resolution: sdf-7 is absent, sdf-19 is scoped to HL7 canonical StructureDefinition URLs, the default-value rule has been split so FHIR-owned models are checked separately, keyword has the requested extensible definition-use binding and categorization wording, and the kind terminology already explains complex/resource/logical distinctions.

Recommendation:
Keep this empty audit commit as-is. No FHIR-core source follow-up is needed for FHIR-17185; future changes to logical-model terminology or the deprecated StructureDefinition.keyword element should be handled under newer focused trackers rather than reworking this STU3 issue.
