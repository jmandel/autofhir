FHIR-7086: Audit Patient contact preference support

Issue request:
FHIR-7086 was a Published FHIR-core Patient change request, resolved Persuasive with Modification, asking whether Patient communication should include a preferred method such as sign language, Braille, email, or telephone. The recorded resolution says the ContactPoint datatype had been updated with a rank property that permits ordering contact points by preference; Jira comments also noted that Patient.communication already had a preferred flag and that the remaining concern was likely Patient.telecom/contact-point preference.

Initial application:
No historical commit message was found that explicitly mentions FHIR-7086 or the 2015May core #145 label. The substantive source application appears to be the closely related ContactPoint rank work: FHIR-7626 requested ContactPoint.rank for ordering communication modalities, and git commit d45b815efc6c29cd65295e44bf82863887c82875 added ContactPoint.rank to source/datatypes/contactpoint.xml. That related issue is already represented on the combined branch by commit ced4ab500919bbc63ab62fd9734aca1962b5db9c, so this audit does not duplicate it.

Additional context:
Patient is an active current resource and ContactPoint is an active normative datatype in source/fhir.ini. Current Patient source still defines Patient.telecom as ContactPoint and Patient.communication.preferred as the language preference indicator; the language comment includes sign-language examples. Current ContactPoint source defines ContactPoint.rank as 0..1 positiveInt and says lower rank values are more preferred. Later final Jira decisions FHIR-16984, FHIR-38824, and FHIR-12593 kept ContactPoint.rank and clarified its semantics rather than reversing it; FHIR-31615 later declined a broader ambiguous preferred-method extension request.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped Patient and ContactPoint sources already satisfy FHIR-7086's final resolution: language preference remains on Patient.communication.preferred, and preference among telephone/email/contact points is expressed by ContactPoint.rank through Patient.telecom.

Recommendation:
Keep this audit commit as-is. No core source edit is needed for FHIR-7086 unless a future PA or MnM decision changes the preferred-contact model beyond the existing Patient.communication.preferred and ContactPoint.rank mechanisms.
