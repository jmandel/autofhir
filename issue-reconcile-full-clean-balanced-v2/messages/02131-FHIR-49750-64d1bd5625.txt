FHIR-49750: Audit Device.property.type value set

Issue request:
FHIR-49750 was an Applied/Persuasive OO change request for R6. It reported that Device.property.type was example-bound to a value set of device types rather than property types, and the accepted resolution was to remove the old binding content and create a new example CodeSystem and ValueSet for device property types.

Initial application:
The issue was applied before this reconciliation. Commit 0c804fd03064bf99a83505160fd04ae559a14f12 added source/device/codesystem-device-property-type.xml, renamed the ValueSet computable name to DevicePropertyType, removed the ISO 11073/GMDN/SNOMED device-type includes, and made the ValueSet include http://hl7.org/fhir/device-property-type. Commit 8a1913129feaee34ab3d20614b4eca0d7f21d233 updated the CodeSystem and ValueSet descriptions to say the codes are for example purposes only, and commit 3bf923f62edfec86ce552a981852a744e47f4e39 updated both titles to "Device Property Type (Example only)".

Additional context:
The active fhir.ini resources list includes device=Device, so source/device is current build input. Device.property.type and DeviceDefinition.property.type now both bind to http://hl7.org/fhir/ValueSet/device-property-type with bindingName DevicePropertyType. Later related Jira issues FHIR-55253 and FHIR-55255 are Resolved - change required, not Applied/Published; they separately propose marking this example CodeSystem/ValueSet experimental=true, so they do not require changing this Applied seed audit.

AutoFHIR reconciliation:
No source change was made. The current source already contains the dedicated example device-property CodeSystem, the ValueSet composes only that CodeSystem, and the Device.property.type binding points to that ValueSet.

Recommendation:
Keep this audit commit as-is for FHIR-49750. Handle any future experimental=true update under FHIR-55253/FHIR-55255 or another explicit issue-reconcile task rather than conflating it with the already-applied property-type replacement.
