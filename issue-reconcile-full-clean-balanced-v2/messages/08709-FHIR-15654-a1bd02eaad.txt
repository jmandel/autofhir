FHIR-15654: Audit NamingSystem nsd-1 collection fix

Issue request:
FHIR-15654 was a Published/Persuasive FHIR-core NamingSystem technical correction for STU3. It reported that uniqueId is a collection and that the then-current nsd-1 expression read opposite to the human rule, proposing that root NamingSystems imply uniqueId.all(type != 'uuid').

Initial application:
Jira records the application as svn revision 13363. The current Git history has no explicit FHIR-15654 commit; pickaxe searches for the corrected expression find later quote-normalization and OID-handling commits where the collection-safe expression was already present.

Additional context:
FHIR-13991 is a same-invariant predecessor that asked for the direction fix. FHIR-15654 supplied the collection-safe refinement needed for a repeated uniqueId element. NamingSystem is active in the current build configuration, and the invariant is attached to NamingSystem.kind, NamingSystem.uniqueId, and NamingSystem.uniqueId.type.

AutoFHIR reconciliation:
This audit commit makes no source change. The active NamingSystem StructureDefinition already contains the equivalent FHIRPath expression kind != 'root' or uniqueId.all(type != 'uuid'), so a root NamingSystem fails if any uniqueId has type uuid and non-root NamingSystems are unaffected.

Recommendation:
Keep this no-change audit as-is. The current core source is correct for FHIR-15654; further work would only be needed if the work group intentionally changes the root-system uuid policy.
