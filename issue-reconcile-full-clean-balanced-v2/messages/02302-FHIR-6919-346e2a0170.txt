FHIR-6919: Audit Composition context-flow wording

Issue request:
FHIR-6919 was a Published/Persuasive Structured Documents change request for the Composition resource asking to add wording that, unlike CDA, FHIR Composition context applies to the Composition itself and does not flow to contained or referenced resources; each referenced resource must express its own context so clinical content can be safely extracted.

Initial application:
The issue appears to have been applied by git-svn commit 7612479cd11d1208dd4461ea4be3a94f7c667716, whose subject is "#6919 - add note to composition about context conduction not existing in FHIR" and whose git-svn id records build@6189, matching the Jira comment "svn revision 6189". Later editorial commits adjusted capitalization and punctuation, and FHIR-30766 removed confidentiality from the parenthetical list while preserving the no-context-flow rule.

Additional context:
Composition is an active current-build resource in source/fhir.ini and is assigned to the Structured Documents work group. Current source/composition/composition-introduction.xml retains the requested CDA-aware note, now saying the subject, author, event, event period, and encounter apply to the Composition and not specifically to resources referenced from section.entry; each referenced resource expresses its own individual context. The omission of confidentiality is consistent with current Composition structure, where there is no Composition.confidentiality element and the CDA comparison now maps confidentiality to Bundle.meta.security. Jira search found FHIR-7105 as a duplicate of the same ballot request, and no separate source decision is needed for that duplicate. A later Zulip discussion clarified the distinction between context flow and explicit references without identifying a need to change the Composition note.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active Composition narrative already carries the semantic rule requested by FHIR-6919, and later wording changes are consistent with current resource structure rather than an unapplied part of the old request.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-6919 unless the Structured Documents work group opens a new tracker to revise the broader wording about context flow versus references.
