FHIR-31347: Audit itemControl CodeableConcept note migration

Issue request:
FHIR-31347 was Published/Persuasive for FHIR-core Questionnaire and asked for a note explaining why the questionnaire-itemControl extension uses CodeableConcept, including that CodeableConcept.text alone should not be used because the extension is intended to provide computable rendering guidance.

Initial application:
The issue was applied in core by commit 22d02daa69, which added requirements text to source/questionnaire/structuredefinition-extension-questionnaire-itemControl.xml explaining that CodeableConcept supports additional codings for finer-grained or environment-specific controls and that text alone should not be sent.

Additional context:
The questionnaire itemControl extension definition was later removed from the current FHIR core source by dd468d4f17 as part of moving extensions out of the R5 source. The current core source has no active fhir.ini entry or source definition for questionnaire-itemControl. The maintained FHIR Extension Pack source at input/definitions/multiple/StructureDefinition-questionnaire-itemControl.xml contains the same requirements text, with later non-conflicting cleanup to SDC links and metadata.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR core source change. The requested explanatory note is already present in the current Extension Pack source, and the authoritative extension definition is no longer maintained in this core checkout.

Recommendation:
Keep this audit commit as-is for core reconciliation. Future changes to questionnaire-itemControl should be made in the FHIR Extension Pack rather than reintroducing a core extension definition.
