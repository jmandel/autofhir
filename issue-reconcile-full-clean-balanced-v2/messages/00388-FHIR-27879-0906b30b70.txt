FHIR-27879: Audit ImmunizationEvaluation workflow protocol contexts

Issue request:
FHIR-27879 was a Published FHIR-core/Public Health change request raised against R4 and applied for R5. It asked how ImmunizationEvaluation should identify the protocol used for an evaluation; its final Not Persuasive with Modification resolution chose adding ImmunizationEvaluation as context for the workflow-adheresTo and workflow-generatedFrom standard extensions instead of adding instantiatedCanonical/instantiatedURI elements.

Initial application:
The issue was applied in core by commit e4ec3c0aee74abe0018e5bc2080eed7663ffd430, merged by 77fdb9999044b49afffef3ac1498e7f84c6e1927, which added ImmunizationEvaluation to the generatedFrom and adheresTo rows in source/profiles/workflow-extensions-spreadsheet.xml.

Additional context:
FHIR-27016 first added instantiatesCanonical/instantiatesUri to Immunization and ImmunizationRecommendation while explicitly deferring ImmunizationEvaluation. FHIR-32392 later removed those instantiates elements in favor of common workflow extensions. PHWG minutes on 2022-08-18 approved FHIR-27879's proposal 28-0-0, and the Zulip workflow thread records Lloyd McKenzie's confirmation that adheresTo/generatedFrom are appropriate. Core commit dd468d4f1799dd79819315b211588ef1cf4586e0 then removed these extension definitions from the R5 core source, and the current Extension Pack source now contains the authoritative workflow-adheresTo and workflow-generatedFrom StructureDefinitions with ImmunizationEvaluation contexts.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The current core checkout no longer owns the workflow extension StructureDefinitions, and the read-only Extension Pack checkout already contains ImmunizationEvaluation as a context for both workflow-adheresTo and workflow-generatedFrom, preserving the applied decision.

Recommendation:
Keep this audit commit as-is. No FHIR-core edit is needed unless the workflow extension definitions are moved back into core or a future issue changes the intended extension contexts; no Extension Pack follow-up is indicated by this reconciliation because the relevant contexts are already present there.
