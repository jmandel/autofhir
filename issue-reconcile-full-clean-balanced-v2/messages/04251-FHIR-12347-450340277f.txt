FHIR-12347: Audit Medication package container terminology

Issue request:
FHIR-12347 was Published with a Persuasive with Modification resolution for the DSTU2 Medication.package.container example binding. The submitter asked to move away from SNOMED CT qualifier-value package codes, initially suggesting the SNOMED CT Physical Object hierarchy, but the final Pharmacy decision was to create an exemplar value set using EDQM package terms.

Initial application:
The issue was applied in commit 491a59353e4244177fb0b6cd8a2de31e46f7f448. That commit changed the MedicationContainer binding in the Medication spreadsheet from the old valueset-medication-package-form-codes reference to a local #medication-package-form code list, added EDQM-sourced package/container codes, and added a committee note that the exemplar value set used EDQM as its source. The same commit also applied FHIR-12758 by moving Medication batch details under the package backbone.

Additional context:
Later Medication modeling changes removed the affected Medication.package.container path from the current resource. Commit 2559032b9b1cd17a3f528abbe59749fff309ed69 removed Medication.package.container and related package-content search/source rows as part of GF #13879, and current source now exposes Medication.packageSize rather than Medication.package.container. More recent applied issues FHIR-46408 and FHIR-46416 refined the current combination-package and package-size guidance. Full packaging/container structure is now represented by PackagedProductDefinition.packaging.type, bound to the current packaging-type value set. An obsolete-looking source/medication/valueset-medication-package-form-codes.xml file still exists, but it is not referenced by the current Medication structure, fhir.ini valueset/codesystem lists, or current package-container bindings.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The requested DSTU2 binding change was applied historically, and the current build no longer has the element/binding that FHIR-12347 targeted. Editing the old unreferenced SNOMED package-form ValueSet would not change current implementer-facing conformance for Medication.package.container and would be a separate cleanup decision.

Recommendation:
Keep this audit commit as-is. If Pharmacy or tooling owners want to remove or quarantine stale unreferenced historical Medication value-set files, handle that as a separate cleanup issue rather than as FHIR-12347 reconciliation.
