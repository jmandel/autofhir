FHIR-12287: Audit v3 component relationship rendering

Issue request:
FHIR-12287 was Published/Persuasive for DSTU2 and asked that code-system rendering expose alternative relationships such as the component hierarchy because the old v3 AddressPartType page showed the subsumption hierarchy but not the component hierarchy.

Initial application:
The issue was applied in git-svn commit ce3aad59b773b1c5c8cba55ef9066014e83350be, which corresponds to svn build r10050 noted in Jira. That commit updated the historical ValueSetImporterV3 converter to detect the MIF ComponentOf relationship, add a partOf/ComponentOf concept property, and render a PartOf column for affected v3 code systems.

Additional context:
FHIR-5947 is the earlier terminology-family decision that clarified child-code hierarchy meaning need not always be subsumption and specifically discussed AddressPartType/ComponentOf. Current core source no longer contains the historical ValueSetImporterV3 converter or a v3-AddressPartType source artifact; active core source instead defines the general CodeSystem.hierarchyMeaning model and the reusable concept-properties partOf property. The current published THO AddressPartType page is outside this core checkout and already renders ComponentOf as a code-system property and as a concept-table column, including examples such as ADL component-of AL. A 2019 UTG Zulip thread confirms that the remaining v3 relationship/property work was being handled in UTG/THO rather than as core source.

AutoFHIR reconciliation:
This is an empty external-repo audit commit. No FHIR core source was changed because the seed's requested rendering was historically applied in removed core tooling, and the current v3 AddressPartType artifact is maintained and rendered in HL7 Terminology/UTG rather than this core build.

Recommendation:
Keep this audit commit as-is. If the AddressPartType modeling itself is revisited, such as changing hierarchyMeaning versus retaining ComponentOf as a concept property, that follow-up belongs in THO/UTG and should be reviewed by terminology stakeholders, not patched in the current FHIR core checkout.
