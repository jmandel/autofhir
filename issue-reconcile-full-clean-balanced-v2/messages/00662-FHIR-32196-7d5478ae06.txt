FHIR-32196: Audit Invoice.type terminology deferral

Issue request:
FHIR-32196 is Applied/Persuasive with Modification for R6. It asked to create an invoice-type code system with proforma, initial, interim, final, and adjustment concepts and to bind Invoice.type as a 0..1 CodeableConcept to VS-invoice-type with extensible strength.

Initial application:
The explicit FHIR-32196 implementation commit 7478d9bdc4 added a second Invoice.type differential element, but did not create an invoice-type CodeSystem, ValueSet, or binding on the active Invoice.type element. A later source commit, fe420c6da27, commented that duplicate element out after the problem was called out in the committers Zulip stream. The current build-scoped Invoice resource still has only the original active Invoice.type element and no invoice-type terminology source files or fhir.ini references.

Additional context:
Invoice is an active resource in source/fhir.ini, so source/invoice/structuredefinition-Invoice.xml is build-scoped. The FHIR-32196 Jira comments say terminology handling moved to FHIR-53202. FHIR-53202 specifically addresses the terminology creation for FHIR-32196, but it is Deferred/Considered for Future Use with the resolution to address it in the FM incubator. No Confluence references were found for either issue.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Adding a core invoice-type CodeSystem, ValueSet, or binding now would override the later deferred/incubator decision in FHIR-53202. The inactive duplicate Invoice.type comment is not build output and does not justify a current-spec source fix for this issue.

Recommendation:
Keep this audit commit as-is. If FM decides the invoice-type terminology should return to core, advance FHIR-53202 or a successor issue to an applied/published source-change state and add the CodeSystem, ValueSet, fhir.ini entries, and Invoice.type binding then.
