FHIR-14702: Audit ValueSet expansion limited indicator

Issue request:
FHIR-14702 was a Published Vocab STU3 change request, resolved Persuasive with Modification, originally asking to add a ValueSet.expansion.isLimited indicator because the then-current ValueSet $expand limitedExpansion text described an incomplete expansion without a reliable indicator. The final updated block-vote resolution did not require adding isLimited; it said the limitedExpansion parameter was being removed by another ballot item and replaced with a recommendation to use count.

Initial application:
The issue was pre-applied in SVN revision 13351, represented in git by d90f55e1cb, which changed the old ValueSet spreadsheet wording for the limitedExpansion operation input to mention an indicator for incomplete expansion using OperationOutcome plus ValueSet.expansion.total when known. That was an interim application only, because the final resolution was subsequently governed by the connected FHIR-16449 change.

Additional context:
FHIR-16449 was the same ValueSet $expand change family and removed the limitedExpansion input parameter in af02669d42, updating the documentation around count instead. That issue is already represented on the combined branch by 3731ea54fec8bf1099c9605ea448e0d33c80963f, so this commit does not duplicate it. FHIR-14703 and FHIR-40717 are also already represented on the combined branch and provide related expansion/server-capability and too-costly/unclosed-expansion context. In the current build, source/fhir.ini actively includes ValueSet as a resource, and the authoritative source has migrated from the historical spreadsheet to source/valueset/structuredefinition-ValueSet.xml and source/valueset/operationdefinition-ValueSet-expand.xml.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source has no ValueSet.expansion.isLimited or limitedExpansion parameter, and that matches the final FHIR-14702/FHIR-16449 outcome. The current $expand operation text tells servers they may return too-costly for overly large expansions, tells clients to use offset/count paging or count for a limited subset, and distinguishes unbounded incomplete expansions with valueset-unclosed. ValueSet.expansion.total and ValueSet.expansion.offset already describe how a partial page view exposes the total and offset.

Recommendation:
Keep this empty audit commit as-is. Do not add ValueSet.expansion.isLimited for FHIR-14702; the current source reflects the later accepted count/offset/total approach. Any future work to represent an incomplete-but-returned expansion for too-costly reasons should be handled under the later valueset-toocostly/unclosed-expansion issue family, not by reopening this STU3 ballot item.
