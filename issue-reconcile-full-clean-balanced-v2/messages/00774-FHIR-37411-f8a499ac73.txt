FHIR-37411: Audit ImagingSelection UID type alignment

Issue request:
FHIR-37411 was a Published/Persuasive with Modification R5 Imaging Integration change request asking ImagingSelection UID elements that had been modeled as oid to align with ImagingStudy's id-valued Series and SOP Instance UIDs. The accepted resolution was to apply the linked Confluence changes, which converted the relevant UID element types and examples while keeping SOP Class as oid.

Initial application:
The issue was applied before this reconciliation. Jira comment evidence points to merge commit 471fbc468b8fd5427fcebad076569e16590ac707, and the issue-keyed implementation commit 5c5a620527e102650cad53df57ff594d1706fe2a changed ImagingSelection.studyUid, seriesUid, frameOfReferenceUid, and instance.uid from oid to id, removed urn:oid: from those id examples, and removed the separate instance.observationUid oid element as part of the same ImagingSelection update.

Additional context:
ImagingSelection is an active current-build resource in source/fhir.ini. Later ImagingSelection refactors changed requirements and added identifier guidance, but they did not reverse the FHIR-37411 UID type decision. Current source still keeps instance.sopClass as oid with urn:oid examples, and current notes intentionally use urn:oid only when a DICOM UID is represented in Identifier.value with system urn:dicom:uid, which is outside the id-valued UID element request.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped StructureDefinition already has id types and plain id examples for ImagingSelection.studyUid, ImagingSelection.seriesUid, ImagingSelection.frameOfReferenceUid, and ImagingSelection.instance.uid; instance.observationUid no longer exists; and current examples do not put urn:oid: in those UID-valued elements.

Recommendation:
Keep this no-change audit commit as-is. No follow-up core source change is needed for FHIR-37411 unless a future Imaging WG decision reopens the broader Identifier.value urn:oid guidance, which is governed by later ImagingSelection/ImagingStudy identifier guidance rather than this issue.
