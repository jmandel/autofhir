FHIR-18371: Audit modifier extension wording removal

Issue request:
FHIR-18371 was Published/Persuasive for FHIR-core defining-extensions after a 7-0-0 2018-10-08 vote. It requested removing the statement that HL7 does not generally define modifier extensions because HL7 had already defined modifier extensions and expected to define more.

Initial application:
The issue was applied by commit 3969e526fb4fe6b3fe212fb1bbf130d6faef646d, whose Jira comment records GH#3969e526fb. That commit removed the disputed sentence from source/defining-extensions.html while preserving the surrounding explanation that HL7 publishes extensions to keep base resources concise.

Additional context:
The current source/hierarchy.xml lists defining-extensions.html under the Extensibility page, so the checked source is in build scope. Later modifier-extension documentation issues FHIR-36738 and FHIR-37903 are already represented on the combined branch and do not reintroduce the removed generalization; current extensibility guidance instead explains how isModifier designates a modifier extension.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current Publishing Extension Definitions section says HL7 publishes extensions, including as part of the specification, and no longer contains the false statement that HL7 does not generally define modifier extensions.

Recommendation:
Keep this commit as-is. No follow-up core source change is needed for FHIR-18371; any future modifier-extension guidance should be handled under its own tracker rather than by restoring the removed statement.
