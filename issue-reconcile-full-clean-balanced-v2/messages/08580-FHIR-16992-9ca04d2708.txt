FHIR-16992: Audit defaultValue cleanup constraints

Issue request:
FHIR-16992 was a Published FHIR-core/fhir-i STU3 change request about cleanup after removing defaultValues. The issue asked whether default values had been removed, suggested adding a constraint limiting defaultValue to local/logical models if still allowed, and asked to update ElementDefinition missing-element text. The final Persuasive with Modification resolution was to add a constraint ensuring default values only exist in non-FHIR content; the Jira comment says this had already been done under another task.

Initial application:
No current git commit explicitly mentions FHIR-16992. The evidence trail points to the broader defaultValue cleanup in FHIR-15121: Jira FHIR-15121 records the exact policy that defaultValue cannot be used for FHIR resources but can still be used for logical models, with enforcement by invariant, and git-svn commit 7ac081b0b845064c90c4a9038178aa64a80e5790 cites GF#15121 while updating the ElementDefinition missing-elements/defaultValue narrative. The current StructureDefinition source later carries the enforcement as active constraints sdf-21 and sdf-22.

Additional context:
source/fhir.ini actively includes both the ElementDefinition type page and the StructureDefinition resource, so source/elementdefinition.html, source/datatypes/elementdefinition.xml, and source/structuredefinition/structuredefinition-StructureDefinition.xml are current build inputs. Current ElementDefinition text says the FHIR specification defines no default values for resources or datatypes and preserves defaultValue only for logical models. Current StructureDefinition constraints prohibit defaultValue in HL7 FHIR StructureDefinition URLs and prohibit defaultValue in constraints/profiles. Searches found no Zulip or Confluence discussion that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The requested constraint is already present in the active StructureDefinition source, and the ElementDefinition narrative already distinguishes FHIR resources/datatypes from logical models. Adding redundant text or changing the remaining defaultValue element would be broader than the FHIR-16992 resolution and would risk contradicting FHIR-15121's decision to keep defaultValue for logical models.

Recommendation:
Keep this no-change audit commit as-is. No core source follow-up is needed for FHIR-16992 unless a future work group decision changes the defaultValue policy for logical models or FHIR-defined StructureDefinitions.
