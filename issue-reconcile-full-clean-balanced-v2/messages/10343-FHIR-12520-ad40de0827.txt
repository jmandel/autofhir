FHIR-12520: Audit _include documentation corrections

Issue request:
FHIR-12520 was a Published/Persuasive FHIR-core-search change request for DSTU2. It asked for clearer _include documentation: wildcard handling, a typo in the wildcard warning, the correct Bundle.entry.search.mode location for included results, and behavior when a requested include target is absent or cannot be retrieved.

Initial application:
The issue was applied in SVN revision 11226, now git commit 1e8d3ba8d2706c6ca91643ee60a17e47f7c17048 (#12520 - notes about _include). That commit changed the include-result paragraph from Bundle.entry.status to Bundle.entry.search.mode, added omission/no-error behavior when no referenced resource can be included, and fixed the reported duplicated-word typo in the wildcard warning. It did not fully settle wildcard syntax because later issues changed that area.

Additional context:
source/search.html is an active core narrative page under the RESTful API section in source/hierarchy.xml. Current combined-branch source already contains the FHIR-12520 corrections: _include/_revinclude syntax bullets, entry.search.mode=include, omitted missing/unretrievable references with no error, and corrected wildcard-warning wording. Later Published issues explain differences from the original DSTU2 wording: FHIR-13602 renamed :recurse to :iterate and clarified that includes run only from initial matches by default; FHIR-24888 later added support for _include=* and _revinclude=*; and FHIR-33309 clarified that wildcard includes apply only to search parameters supported for _include/_revinclude.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build-scope search page already conveys the requested rule and later approved semantics, so adding redundant prose or reverting wildcard/iterate wording would be incorrect.

Recommendation:
Keep this audit commit as-is. Any future editorial cleanup of adjacent wording should be handled separately from FHIR-12520 unless it changes implementer understanding of _include behavior.
