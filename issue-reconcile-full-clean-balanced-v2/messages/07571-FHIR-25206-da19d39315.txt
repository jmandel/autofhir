FHIR-25206: Audit slicing discriminator merge

Issue request:
FHIR-25206 was a Published/Persuasive FHIR-core change request for R5. It asked to merge the value and pattern slicing discriminator semantics, deprecate one discriminator type because both were already normative, allow fixed[x], pattern[x], and required value set bindings under the same slicing discriminator type, make the deprecated pattern discriminator work the same as value, and add a good-practice warning that pattern[x] is generally preferable to fixed[x].

Initial application:
No historical commit tagged with FHIR-25206 was found in the relevant profiling or ElementDefinition source history. The current source nevertheless contains the requested application through later and adjacent edits: profiling.html now says value discrimination is by a fixed value, pattern value, or required value set binding and that pattern means the same as value for backward compatibility; the ElementDefinition discriminator type source omits pattern from the primary type list while recording that pattern is deprecated and equivalent to value; the discriminator-type code system marks pattern deprecated; and ElementDefinition has the requested best-practice warning against fixed[x].

Additional context:
The linked Zulip threads show the original ambiguity and use case: implementers could not mix pattern slices and required binding slices cleanly, and Grahame Grieve and Lloyd McKenzie converged on merging the discriminator semantics while warning about fixed[x]. FHIR-I minutes for 2020-03-02 record the formal decision to deprecate pattern and document that value allows slicing by pattern. Later FHIR-34152 work, already represented on the combined branch, strengthened the fixed[x] versus pattern[x] explanation and links without reversing FHIR-25206.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active build-scoped sources already convey the required rule and warning, and adding more prose would duplicate existing profiling and ElementDefinition guidance rather than change implementer understanding.

Recommendation:
Keep this no-change audit commit. No FHIR core source follow-up is needed for FHIR-25206 unless the work group later chooses to remove or rewrite remaining example/profile uses of the deprecated but still valid pattern discriminator.
