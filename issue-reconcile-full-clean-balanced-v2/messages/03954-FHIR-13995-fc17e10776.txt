FHIR-13995: Audit Attachment hash signature clarification

Issue request:
FHIR-13995 is a Published FHIR-core/MnM STU3 change request resolved Persuasive. It asked to clarify Attachment.hash by removing language that implied SHA-1 hashes support signatures, saying instead that the hash lets applications detect accidental content changes such as storage rot, transport glitches, or incorrect versions, and adding that Attachment.hash is not intended to support digital signatures.

Initial application:
The request was applied by git commit d8debd983e29b4dc6fb6db0cef9a8d0409bc91cb, whose subject is "#13995 - remove note about signatures on hash". That commit changed source/datatypes/attachment.xml from the old signature-implying rationale to the technical-failures rationale and added the first "not intended to support digital signatures" note. The same source area was later refined by FHIR-14123 in c4d708b33f435bffb8b22d81c7cd1db1579a5ce0, which added the Provenance.signature guidance, and by b3786937571301e32dccd31961299bb576d2af10, which corrected the typo introduced in the new rationale.

Additional context:
Attachment is active in the current build through source/fhir.ini's datatype mapping and Attachment type entry, and the datatype is marked normative. The current authoritative spreadsheet source for Attachment.hash says the hash is included to detect technical failures and explicitly says it is not intended to support digital signatures; the current datatypes narrative also says the hash is for detecting content changes at a URL and points malicious-threat protection to Provenance.signature. The Jira-linked Zulip thread confirms the rationale: SHA-1 is acceptable for accidental integrity checks, while non-repudiation and malicious alteration protection require digital signatures such as Provenance.signature. Later Attachment.hash work does not undo this conclusion: FHIR-14123 is already audited on the combined branch, FHIR-55422 is already audited there as an external Extension Pack alternate-hash issue, and FHIR-51236 is only Resolved - change required in this default Applied/Published run scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped source already conveys the FHIR-13995 decision and the later same-family refinements, so editing it again would be redundant and risk drifting from the maintained datatype source.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-13995; separate newer Attachment.hash issues should remain under their own reconciliation records.
