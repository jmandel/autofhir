FHIR-17642: Audit Device specialization description

Issue request:
FHIR-17642 was Published as Persuasive with Modification for OO. It asked to clarify the Device specialization element so it represented a detailed device function and the standard or requirements to which the device conforms, especially PHD/PoCD 11073 specialization codes and an applicable standard version, rather than a manufacturer-supplied alternate device name.

Initial application:
The original request was applied in history by commit b9623f940a, which updated the then-authoritative source/device/device-spreadsheet.xml description for Device.specialization with the PHD blood pressure and 11073 nomenclature explanation from the issue. That spreadsheet source was later removed from the current build source path. Jira and OO minutes later recorded that FHIR-17642 was considered applied based on the more current FHIR-36154 Device.specialization work.

Additional context:
FHIR-36154 reintroduced Device.specialization for R5 with a clearer standards-conformance model, and that issue already has a no-change audit commit on the combined branch. Later Published issue FHIR-39084 renamed Device.specialization to Device.conformsTo and broadened the model from IEEE 11073 specializations to standards, specifications, formal guidance, regulations, and certification schemes; it already has a source-fixing reconciliation commit on the combined branch. Device is active in source/fhir.ini, the old Device.specialization migration aliases now point to Device.conformsTo, current Device.conformsTo has category/specification/version subelements, and current examples/value sets still cover ISO/IEEE 11073 10101 PHD specialization codes.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding the old specialization prose or the literal Device.specialization element would conflict with later Published decisions; the current Device.conformsTo source preserves the implementer-relevant meaning of FHIR-17642 while using the current R5/R6 model.

Recommendation:
Keep this audit commit as-is. If future work wants additional PHD examples or broader conformance vocabulary, handle it through the Device.conformsTo/value-set issue family rather than restoring obsolete Device.specialization wording.
