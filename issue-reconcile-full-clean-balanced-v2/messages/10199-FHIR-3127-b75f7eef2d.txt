FHIR-3127: Audit existing build-status infrastructure

Issue request:
FHIR-3127 was a Published/Persuasive FHIR-core documentation enhancement asking for a FHIR build status page, ideally backed by continuous integration that builds after every commit.

Initial application:
No commit with an explicit FHIR-3127 key was found on the current repository history or combined reconciliation branch. The issue was marked done in Jira by Grahame Grieve in October 2014, and the closest source-history application is the April 2014 SVN-origin commit by Josh Mandel that added Travis CI wiring, README build documentation, and build.sh support for a "Continuous Integration Build" published at build.fhir.org.

Additional context:
The build-status mechanism has since evolved from the original Travis/SVN-era files to Azure pipelines. The current README exposes CI build badges and links to build.fhir.org, while master and pull-request pipeline definitions run the publisher, upload successful builds to build.fhir.org or branch-specific build.fhir.org locations, and post success/failure notifications to the Zulip "FHIR Build Status" topic. The live build.fhir.org current build, QA page, and branch list are reachable.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current repository and live build infrastructure already provide CI build status, current build publication, QA output, branch build publication, and build-result notifications; adding more source prose would be redundant and could drift from the actual pipeline configuration.

Recommendation:
Keep this audit commit as-is. Future work on notification formatting, badge targets, or pipeline monitoring should be handled as infrastructure maintenance issues, not as remaining FHIR-3127 source reconciliation work.
