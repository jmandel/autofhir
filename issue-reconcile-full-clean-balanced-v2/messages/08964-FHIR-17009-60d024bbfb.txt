FHIR-17009: Audit versioned API support

Issue request:
FHIR-17009 was Published/Persuasive with Modification after asking how a server should support multiple FHIR specification versions, including whether one endpoint can return a non-default FHIR version. The accepted resolution pointed to the broader versioning write-up and asked to add the 2018 Versioned API scenario 2, including how the default version is specified.

Initial application:
The Jira comment records SVN revision 14055. In Git history this maps to 8600af31, which added the core versioning guidance and the CapabilityStatement $versions operation. The implementation chose the WG-approved approach rather than changing CapabilityStatement.fhirVersion into an array: same-endpoint support uses the fhirVersion MIME parameter, and clients discover supported/default versions through $versions.

Additional context:
Later same-family work such as FHIR-18671 clarified that one CapabilityStatement describes one FHIR version and that multi-version servers can expose multiple statements; that issue is already represented on the combined branch. FHIR-35928 later adjusted $versions examples and is also already represented on the combined branch. Current build-scoped source still links versioning.html from the core hierarchy, lists the CapabilityStatement $versions operation, and keeps CapabilityStatement as an active resource.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/versioning.html says servers SHOULD use version-specific endpoints but MAY use the same endpoint with mandatory fhirVersion MIME parameters, and it points clients to $versions. Current source/capabilitystatement/operationdefinition-CapabilityStatement-versions.xml defines $versions as returning supported versions plus the default version used when no fhirVersion parameter is present. Current CapabilityStatement text continues to make one fhirVersion mandatory for each statement, consistent with the modified resolution and later clarifications.

Recommendation:
Keep this audit commit as-is. No FHIR core source change is needed for FHIR-17009 unless the work group wants a new policy beyond the already-applied versioned API guidance.
