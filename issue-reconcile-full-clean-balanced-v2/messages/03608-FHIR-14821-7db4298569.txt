FHIR-14821: Audit Condition clinical status rule

Issue request:
FHIR-14821 was a Published Patient Care change request for STU3 Condition. It asked whether Condition.clinicalStatus cardinality could be changed to 1..1 because clinical and verification status were treated as mandatory. The Not Persuasive with Modification resolution kept clinicalStatus optional for entered-in-error cases and asked to add an invariant: Condition.clinicalStatus SHALL NOT be present if verificationStatus is entered-in-error.

Initial application:
The issue was applied in b88fc91916, which added the Condition invariant row "No clinicalStatus when entered in error" to source/condition/condition-spreadsheet.xml and associated both clinicalStatus and verificationStatus with that invariant. The invariant later flowed into generated StructureDefinition source and was still visible in the R4B-era Condition structure before later R5 work.

Additional context:
Later published Patient Care decisions changed the same rule family. FHIR-28458 removed the no-clinicalStatus-when-entered-in-error Condition invariant while clarifying refuted Condition guidance. FHIR-29409 then required Condition.clinicalStatus 1..1, removed the prior con-3 dependency on problem-list-item category, loosened Condition.category binding, and added the current comment explaining that clinicalStatus is required because it is a modifier element. The active current build includes source/condition through source/fhir.ini, and the current StructureDefinition has clinicalStatus min=1, verificationStatus min=0, no entered-in-error clinicalStatus prohibition, and only the later Condition constraints.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Reinstating the FHIR-14821 invariant would conflict with later applied/published decisions for R5/R6 Condition and with the current mandatory clinicalStatus design.

Recommendation:
Keep this audit commit as-is. Future work on entered-in-error Condition semantics should be handled as a new Patient Care decision rather than by reviving FHIR-14821's superseded invariant.
