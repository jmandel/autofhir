FHIR-25274: Audit ElementDefinition fhir-type guidance

Issue request:
FHIR-25274 was a Published/Persuasive with Modification FHIR-I change request raised against R4 and applied for R5. It reported that Resource.id used http://hl7.org/fhirpath/System.String with structuredefinition-fhir-type value string instead of id, and it requested explanatory ElementDefinition guidance for FHIRPath simple types plus the structuredefinition-fhir-type extension.

Initial application:
The Resource.id type correction was handled by the closely related FHIR-25262 work: Resource.id entered the current source era as System.String with fhir-type id, briefly regressed to fhir-type string in an R4B draft source import, and was restored to the current valueUrl id representation by commit 73080e5. The FHIR-25274-specific documentation was applied explicitly in commit a60a9ee, which added the ElementDefinition notes describing FHIRPath simple types and the fhir-type extension.

Additional context:
source/fhir.ini keeps Resource in the active infrastructure build scope and maps the elementdefinition page as the active ElementDefinition narrative page. The 2019 Zulip discussion linked from Jira confirms the intended model: Resource.id is represented as FHIRPath System.String in the StructureDefinition, but conceptually carries FHIR id constraints through structuredefinition-fhir-type value id. FHIR-I minutes from 2020 and 2022 record that the primary type request was already agreed/fixed and that FHIR-25274 should add guidance, matching the current source.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Resource source already has Resource.id as http://hl7.org/fhirpath/System.String with structuredefinition-fhir-type valueUrl id, and source/elementdefinition.html already contains the accepted guidance explaining when FHIRPath System.String is used and how the fhir-type extension further constrains the string value.

Recommendation:
Keep this audit commit as-is for FHIR-25274. Do not duplicate the ElementDefinition prose or change Resource.id away from System.String; future work on generated inherited snapshots or FHIRPath type-test behavior should remain with their later dedicated trackers.
