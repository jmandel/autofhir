FHIR-15520: Audit HealthcareService endpoint wording

Issue request:
FHIR-15520 was a Published/Persuasive PA change request for STU3 HealthcareService.endpoint. It recorded confusion about endpoint context when a HealthcareService has multiple locations and asked to update the wording to something like "Technical endpoints providing access to electronic services operated for the healthcare service".

Initial application:
The issue was applied in git commit bd89a75a69, which explicitly included "GF#15520 HealthcareService.endpoint description wording clarified". That commit changed the HealthcareService endpoint short text from the Location-oriented wording to the requested healthcare-service wording, while leaving the longer definition text unchanged. The later source rework commits 33b409a4b6 and c69d71aa21 carried the same short/definition split into the current XML source and generated search-parameter bundle.

Additional context:
HealthcareService is active in source/fhir.ini, and the current authoritative StructureDefinition short text plus the HealthcareService endpoint SearchParameter description exactly use the Jira-requested wording. The remaining longer definition says the endpoints provide access to services operated for the specific healthcare services defined at this resource, which preserves the same service-level semantics and does not imply that the endpoint belongs only to an individual Location. PA's later FHIR-35805 guidance, already represented on the combined branch, separately clarifies when endpoint details should be modeled on HealthcareService versus Location for single/multiple-location cases.

AutoFHIR reconciliation:
No source files were changed. The current build-scope source already carries the requested short/search wording, and changing the longer definition or checked-in SVG tooltip would be an optional editorial normalization rather than a necessary semantic fix for FHIR-15520.

Recommendation:
Keep this audit commit as-is. Revisit only if PA wants a broader editorial pass to make all endpoint long definitions match their short descriptions verbatim; that would be outside the narrow FHIR-15520 reconciliation.
