FHIR-20191: Audit Device manufacturer naming clarification

Issue request:
FHIR-20191 was a Published/Persuasive FHIR-core Device change request asking whether Device.manufacturer and Device.deviceName.name with type manufacturer-name were duplicate ways to represent a manufacturer, and requesting clarification if they were not.

Initial application:
The issue appears to have been preapplied in the Device updates merged by HL7/fhir#802 (commit f2409b3c69, containing a7f2575daa), which listed FHIR-20191 among preapplied Device changes. That application updated the then-spreadsheet Device source. The later FHIR-20639 Device name-type work replaced and clarified the same value-set area that FHIR-20191 identified.

Additional context:
Device is an active current-build resource in source/fhir.ini. The current source has renamed Device.deviceName to Device.name, and Device.name.type no longer has a manufacturer-name code. FHIR-20639 replaced the old set with registered-name, user-friendly-name, and patient-reported-name definitions, and later Device-name decisions such as FHIR-39162 and FHIR-47605 adjusted the Device.name surface without reintroducing manufacturer-name. Current Device.manufacturer remains a string for the manufacturer or legally responsible entity, while Device.name and the Device Name Type CodeSystem describe names of the device itself, including manufacturer-assigned or brand-family names.

AutoFHIR reconciliation:
No source change was made. Adding the original Acme/Pulse-Ox example wording now would restate a distinction already resolved by the current structure and terminology, and would be misleadingly anchored to a manufacturer-name code that no longer exists in the current build.

Recommendation:
Keep this audit commit as-is. The current source already satisfies FHIR-20191 after the later Device name-type redesign; any future work should be handled under a new issue if implementers need additional examples for the remaining Device.name.type codes.
