FHIR-5987: Audit summary flag documentation

Issue request:
FHIR-5987 was a Published/Persuasive with Modification FHIR-core issue, raised from OO feedback in DSTU1, asking to remove ElementDefinition.isSummary from Resource definitions because the flag felt too coarse without user context. The accepted resolution did not remove isSummary; it required improved documentation about the purpose of the summary flag.

Initial application:
The issue was explicitly applied by git-svn commit f5a7b8e9ec6d5e936ddf974d53ac8faa73c91fc8, "#5987 - improve documentation of summary elements", matching Jira's svn revision 6358 comment. That commit edited source/search.html to add the purpose of the summary form, explain that it supports quickly selecting a resource from a large result set, and preserve the performance rationale for precomputed summary forms.

Additional context:
The current build-source state preserves and refines that documentation. source/search.html still explains the _summary performance intent, the user-selection purpose, and pre-stored summary forms. source/datatypes/elementdefinition.xml still defines ElementDefinition.isSummary and now contains later FHIR-I refinements about _summary=true serialization, datatype exceptions, and interpretation context. Active source/fhir.ini entries keep ElementDefinition in build scope, and the search page remains the authoritative core search narrative. Later related decisions such as FHIR-15742, FHIR-14272, FHIR-33148, FHIR-35855, and FHIR-46364 refined _summary/isSummary behavior without reversing FHIR-5987's decision to document rather than remove the flag; those issues are already represented separately on the combined branch.

AutoFHIR reconciliation:

Recommendation:
