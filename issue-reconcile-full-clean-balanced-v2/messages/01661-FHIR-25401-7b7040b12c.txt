FHIR-25401: Audit no-fixed-address extension ownership

Issue request:
FHIR-25401 was Published/Persuasive for FHIR-core. It asked for a standard no-fixed-address extension on the Address datatype, reusing the Australian extension structure with an HL7 FHIR URL.

Initial application:
PA approved the request at the 2021 May WGM, and core commit 0bcf5a628352f8e84a7dc1d3fac6fa9bca0cbe1b added source/patient/structuredefinition-extension-no-fixed-address.xml plus a StructureDefinition/no-fixed-address entry in source/patient/implementationguide-Patient-core.xml. That same application commit also mentioned FHIR-35923.

Additional context:
Core commit dd468d4f1799dd79819315b211588ef1cf4586e0 later removed extension definitions and Patient extension IG entries from the R5 core source. Current core source no longer owns a no-fixed-address StructureDefinition, aside from retaining the canonical OID assignment in source/oids.ini. The FHIR Extension Pack states that globally defined extensions moved out of core starting with R5, and its current input/definitions/datatypes/StructureDefinition-no-fixed-address.xml contains the active Address-scoped extension. FHIR-53014 later removed "Patient" from the extension name and title, confirming the intended Address datatype scope.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR core source change. The requested extension is represented in the current FHIR Extension Pack checkout rather than in the current FHIR core build.

Recommendation:
Keep this external-repo audit commit. Do not re-add the extension definition or Patient extension listing to core; future changes to the no-fixed-address extension should be made in HL7/fhir-extensions.
