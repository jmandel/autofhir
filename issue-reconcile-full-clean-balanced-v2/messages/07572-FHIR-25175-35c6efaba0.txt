FHIR-25175: Audit CapabilityStatement include examples

Issue request:
FHIR-25175 was a Published/Persuasive FHIR-I change request for the CapabilityStatement examples. The reported problem was that searchInclude values used only a resource name or resource.search-parameter form instead of the _include/_revinclude search string syntax with colon separators, and the resolution required searchInclude and searchRevInclude to match the search strings being allowed.

Initial application:
The issue appears to have been applied by git commit 3f6c293e99, which changed source/capabilitystatement/capabilitystatement-example.xml and the then-present source/capabilitystatement/$subset-response.txt from Organization/Person to Patient:organization/Person:patient. Later source refactoring, including f87870f372, preserved the corrected include values in the current active CapabilityStatement example; the old $subset-response.txt file is no longer present in the current source tree.

Additional context:
The linked Zulip thread confirms implementer confusion over whether CapabilityStatement.rest.resource.searchInclude should use a path-like value or the actual _include value. FHIR-I minutes for 2020-04-06 record the 15-0-0 decision to clarify that searchInclude and searchRevInclude must match the allowed search string using colon syntax. The current CapabilityStatement definition also gives colon-form examples for include values, and a later FHIR-46381 change only clarified wildcard semantics without reversing the colon-syntax rule.

AutoFHIR reconciliation:
No source change was made. source/fhir.ini lists capabilitystatement as an active resource, source/capabilitystatement/list-CapabilityStatement-examples.xml includes CapabilityStatement/example, and the active source/capabilitystatement/capabilitystatement-example.xml now uses Patient:organization and Person:patient. A current-source search excluding historical release snapshots found no active searchInclude/searchRevInclude values still using the old resource-only or resource.search-parameter forms.

Recommendation:
Keep this audit commit as-is. The current build source already implements the Published Jira decision, and editing historical release snapshots or adding redundant prose would not improve the current specification.
