FHIR-13707: Audit OperationDefinition profile rendering

Issue request:
FHIR-13707 was a Published/Persuasive FHIR-core Tools-IG change request raised against STU3. It asked that an OperationDefinition parameter table show the profile for a profiled output Bundle parameter, either in the Type column or in a dedicated Profile column.

Initial application:
No exact FHIR-13707/GF#13707 source commit was found in the current git history. The issue was accepted in the 2018-08-06 FHIR-I block vote, but the affected behavior was OperationDefinition table rendering rather than a missing conformance source element. Later OperationDefinition profile/targetProfile source work is already represented by separate reconciliations on the combined branch.

Additional context:
OperationDefinition is active current-build source in source/fhir.ini. Current OperationDefinition source defines parameter.targetProfile for Reference, canonical, and resource-typed parameters, keeps an old-path mapping from OperationDefinition.parameter.profile to OperationDefinition.parameter.targetProfile, and current CI-rendered operation pages include both a Profile column and Type-cell profile/target rendering such as Resource(CodeSystem | ValueSet). Grahame Grieve's 2022 Jira comment characterized any remaining problem as an old tooling issue to raise against the IG Publisher rather than as a core source issue.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build-scoped core source supplies the targetProfile data needed for operation parameter profiles, and the current built specification already exposes that information in OperationDefinition parameter tables.

Recommendation:
Keep this no-change audit commit. Do not add duplicate core prose or attempt to restore removed in-repository renderer code; if a future IG still fails to render operation parameter profiles, file a focused IG Publisher tooling issue.
