FHIR-20582: Fix Request encounter placeholder

Issue request:
FHIR-20582 was Published/Persuasive with Modification for R5. It asked the Request and Event pattern encounter short descriptions to stop saying "Encounter created as part of" because that sounded as if the Encounter was created by the request or event, and its resolution chose "Encounter the {{title}} is tied to" plus a clearer Request encounter comment using "encounter during which the request was created".

Initial application:
Jira records Git 193d552d63 as the application commit. That commit changed Request.encounter to the resolved short description and rewrote the Request comment, but the rewritten templated sentence contained a malformed "{{title}s" placeholder. Later checked-in request mapping exception files inherited the same malformed placeholder in their pattern-side comments.

Additional context:
The Event pattern side should not be changed back to the FHIR-20582 wording now because later Published issue FHIR-28543 specifically revisited Event.encounter, decided that "tied to" was too loose for Event, and changed the short description to "Encounter the {{title}} is part of" in Git 37f00fcff9. The current request pattern and the affected request-derived resource folders are active build inputs in source/fhir.ini. No Zulip or Confluence record for FHIR-20582 was found that changes the Jira/source conclusion; Confluence minutes only confirm the later FHIR-28543 Event decision.

AutoFHIR reconciliation:
This commit fixes the malformed Request pattern placeholder from "{{title}s" to "{{title}}s" and synchronizes the request mapping exception pattern comments with concrete resource plurals for the active request-derived resources that carried the broken generated text. It intentionally leaves the later Event wording and resource-specific MedicationRequest short override unchanged because those are governed by later or resource-specific context rather than the FHIR-20582 Request pattern application defect.

Recommendation:
Keep this fix. It is a narrow correction to the applied FHIR-20582 Request comment so the current build no longer exposes a malformed placeholder. If a work group wants Product.encounter or resource-specific MedicationRequest.encounter short descriptions to follow the same phrasing policy, handle that as separate human-reviewed tracker work rather than broadening this reconciliation.
