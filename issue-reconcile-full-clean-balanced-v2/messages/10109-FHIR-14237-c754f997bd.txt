FHIR-14237: Audit token ContactPoint guidance

Issue request:
FHIR-14237 was a Published FHIR-core search-page change request, resolved Persuasive with Modification for STU3. It asked for examples and guidance on token search use for ContactPoint, uri, and boolean, with final resolution that pipe syntax is an error for those target datatypes and that ContactPoint token searches may use server-specific handling such as ignoring punctuation or partial phone matching.

Initial application:
The issue was applied by commit 43a29baf1630997360326c7e79c7ca11b7e40def, whose message records GF#14237 and svn revision 13072. That commit changed source/search.html to forbid pipe syntax for ContactPoint, uri, and boolean token targets, removed system columns for those datatypes, and added the ContactPoint special-handling narrative.

Additional context:
source/search.html is the active FHIR-core search narrative named by the Jira related page, and source/fhir.ini has active [search-rules] entries mapping boolean, uri, and ContactPoint to token behavior. The Jira comment that the ContactPoint special-handling point was a subcase of FHIR-8121 is consistent with the current broader search prerogative text. Later FHIR-37990 extended the same no-pipe note to id-valued token targets and is already represented on the combined branch, so the current mention of id is not an over-application of FHIR-14237. Direct Zulip and Confluence searches found no conflicting community evidence.

AutoFHIR reconciliation:
No source change was made. The current source/search.html token section already says the URI/system portion is not used for uri, boolean, ContactPoint, and id token targets; its conformance note says token parameters on ContactPoint, uri, and boolean SHALL NOT use the pipe symbol; and its ContactPoint row says servers may use special handling such as ignoring punctuation or performing partial searches.

Recommendation:
Keep this audit commit as-is. No further core-spec work is needed for FHIR-14237 unless FHIR-I separately decides to add more illustrative examples beyond the applied normative and explanatory guidance.
