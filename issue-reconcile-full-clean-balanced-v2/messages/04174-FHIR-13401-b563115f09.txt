FHIR-13401: Audit complex datatype diagram link casing

Issue request:
FHIR-13401 was a Published/Persuasive STU3 technical correction for FHIR-core datatypes. It reported that diagram links for Count, Money, SimpleQuantity, and similar complex datatype profiles pointed to lower-case anchors while the actual anchors were upper-case, and it was auto-approved.

Initial application:
The Jira comment identifies svn revision 12450. The corresponding git-svn commit 82431f7b7135396ed246c8f731c393a974be4d4a, "#13401 and #13746 - fix case on data type diagram links", changed the then-current SVG generator to use the datatype name casing directly instead of lower-casing diagram href fragments.

Additional context:
FHIR-13746 is the same change family and was applied by the same svn revision. The current datatypes page remains in build scope through source/datatypes.html and active [diagrams] entries in source/fhir.ini. The relevant diagram inputs list Quantity-derived and money-related datatypes with their uppercase names, and source/datatypes.html defines matching uppercase anchors. Current checked-in SVG hrefs for Quantity-related datatype references use uppercase datatypes.html#Quantity-style fragments, and build.fhir.org/datatypes.html does not show the old lower-case Quantity-specialization fragments. No directly relevant Zulip or Confluence evidence was found that changes the Jira/source/git conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The historical generator fix and current source/build evidence show the wrong-case complex datatype diagram link problem is already resolved in the current specification.

Recommendation:
Keep this empty audit commit as-is. No follow-up source work is needed for FHIR-13401 unless a future build regenerates datatype diagrams with lower-case fragments again.
