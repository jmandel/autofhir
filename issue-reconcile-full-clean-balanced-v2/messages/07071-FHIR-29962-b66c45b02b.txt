FHIR-29962 was Published as Persuasive with Modification for R5. It asked for a way to link patient-correction and formal-disagreement Tasks into one workflow conversation, and the final resolution defined a workflow follow-on extension with initial contexts Task, DeviceRequest, ServiceRequest, Procedure and Encounter.

Initial application:
The merged application was commit bef98ae93c, "FHIR-29961, FHIR-29962 - defined followOnOf extension". It added a followOnOf row to the active core workflow extension spreadsheet with the requested contexts, 0..* cardinality, Reference value, definition, rationale, examples, and a FHIR-29962 tracker note.

Additional context:
FHIR-29961 is the same change family and explains the chosen canonical name as workflow-followOnOf. FHIR Workflow minutes recorded the FHIR-29962 persuasive-with-modification vote. Core commit dd468d4f17 later removed these extension definitions from the R5 source, and the FHIR Extension Pack states that globally defined extensions moved out of the core specification starting with R5. The current Extension Pack source carries http://hl7.org/fhir/StructureDefinition/workflow-followOnOf with the same core definition, rationale, Reference value, and Task/DeviceRequest/ServiceRequest/Procedure/Encounter contexts.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The current core checkout no longer owns the extension definition; it only retains the OID registration, while the authoritative maintained artifact is in the FHIR Extension Pack and matches the merged Jira decision.

Recommendation:
Keep this audit commit as-is. Any future correction to the workflow-followOnOf artifact should be made in HL7/fhir-extensions rather than reintroducing the extension definition into core.
