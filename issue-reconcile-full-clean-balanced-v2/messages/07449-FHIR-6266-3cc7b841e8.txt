FHIR-6266: Audit retired DataElement wording

Issue request:
FHIR-6266 was a Published/Persuasive with Modification DSTU1 OO clarification request for the DataElement "Data Elements vs. Codes" section. The reporter asked for the confusing paragraph to be recrafted to distinguish data elements, codes, variables/observations/questions, and detailed metadata; Jira's resolution was to reword the current paragraph to better clarify.

Initial application:
No commit message explicitly mentions FHIR-6266, but the 2015-07-28 DataElement revamp commit cacb4626 rewrote the exact disputed paragraph in source/dataelement/dataelement-notes.xml, replacing the "Data elements describe... while codes describe..." and "One of their purpose..." wording with clearer text about identifiers, names, definitions, data types, value sets, and the shared/simple-code-system boundary. A 2015-09-18 QA commit then fixed nearby spelling and terminology in that rewritten section.

Additional context:
The DataElement resource is no longer an active current-build artifact. FHIR-13094 was Published/Persuasive with Modification to remove DataElement and replace it with StructureDefinition logical models. Current source/fhir.ini comments out DataElement in the resource, work group, and TLA registrations, and the historical source/dataelement/dataelement-notes.xml file was deleted by the 2021 source rework. Current StructureDefinition/ElementDefinition narrative now carries the metadata-layer role for data element definitions rather than a DataElement resource page with a "Data Elements vs. Codes" section.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The original paragraph was already rewritten historically, and the current build no longer contains the DataElement resource section that FHIR-6266 targeted; editing unrelated current generic "data element" prose or the remaining SDC DataElement value sets would not implement this retired-resource clarification.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-6266 unless the work group reintroduces a DataElement-specific page or asks for a new StructureDefinition/logical-model explanation; any such future work should be tracked as a new current-scope issue rather than reopening this DSTU1 clarification.
