FHIR-43667: Confirm que-1a status correction

Issue request:
FHIR-43667 was an Applied/Persuasive technical correction for FHIR-core Questionnaire. It reported that invariant que-1a incorrectly tested %resource.status='complete', a status that does not exist on Questionnaire and belongs to QuestionnaireResponse, and asked that the invariant use the Questionnaire status active instead.

Initial application:
The que-1a invariant came from FHIR-32525, which split the older que-1 rule into que-1a, que-1b, and que-1c and introduced the original complete status test in source/questionnaire/structuredefinition-Questionnaire.xml. FHIR-43667 was later applied by commit 5fa59a80deca6414b4dbd79a5a21941c537e1a13, corresponding to the Jira comment "Git 41c537e1a13", which changed both the que-1a human text and FHIRPath expression from complete to active.

Additional context:
Questionnaire is an active build resource in source/fhir.ini, and the current authoritative StructureDefinition source now contains %resource.status='active' for que-1a. The remaining exact %resource.status='complete' occurrences are in tools/history/release4b and tools/history/release5 profile bundles that preserve published release definitions for version-diff/history use, not in the current Questionnaire source to be corrected. Corrected Jira, Zulip, and Confluence searches found no later or conflicting community decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped Questionnaire source already reflects the Jira-approved correction, and changing the historical release bundles would retroactively alter archived R4B/R5 comparison inputs rather than fix the current specification.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed unless the work group separately decides that historical release comparison bundles should be regenerated or annotated, which is outside this issue reconciliation.
