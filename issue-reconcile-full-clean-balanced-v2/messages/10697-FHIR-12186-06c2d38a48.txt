FHIR-12186: Audit Questionnaire definition support

Issue request:
FHIR-12186 was a Published/Persuasive-with-Modification DSTU2 Questionnaire and QuestionnaireResponse change request. The adopted resolution removed the separate data-element-reference extension, added Questionnaire.item.definition as a uri reference to an ElementDefinition, changed Questionnaire.item.code so codes correspond to rather than define items, added DataElement/LOINC explanatory guidance, and added QuestionnaireResponse.item.definition.

Initial application:
The Jira comments record pre-application in SVN revisions 10207 and 11239, including QuestionnaireResponse.item.definition and the later clarification that code should remain separate from definition with "correspond" wording. No current Git commit explicitly mentions FHIR-12186, but the active source preserves the requested surfaces: Questionnaire.item.definition, Questionnaire.item.code's "corresponds" definition, QuestionnaireResponse.item.definition, and the Questionnaire narrative guidance.

Additional context:
Later Questionnaire issues evolved the same area without reversing FHIR-12186. FHIR-13900 clarified type consistency for Questionnaire.item.definition, FHIR-23765 allowed ObservationDefinition references, FHIR-40217 replaced obsolete DataElement references with ElementDefinition where appropriate, FHIR-48941 allowed multiple definitions, and FHIR-50141 updated Q/QR wording. Questionnaire and QuestionnaireResponse are active resources in source/fhir.ini. Zulip/Confluence searches found no contrary discussion for FHIR-12186; the relevant FHIR-40217 Zulip thread supports the later ElementDefinition terminology cleanup.

AutoFHIR reconciliation:
No source change was made. The current active source already carries the seed issue's implementer-visible semantics as refined by later published or applied Questionnaire decisions, and adding duplicate prose or reverting later terminology/cardinality updates would be incorrect.

Recommendation:
Keep this audit commit as-is. Future work should handle any separate FHIR-13900, FHIR-23765, FHIR-40217, FHIR-48941, or FHIR-50141 reconciliation under their own issue keys rather than changing FHIR-12186's already-applied baseline.
