FHIR-25737: Correct remaining relative canonical example URLs

Issue request:
FHIR-25737 was a Published/Persuasive CQI change request for R5 asking that PlanDefinition, Library, ActivityDefinition, and Measure examples stop using relative URLs where canonical references require full URI values.

Initial application:
The issue was applied by Bryn Rhodes in commit 54830d2febad78c584b8fde82d53885061dea26f and merged through HL7/fhir#2879. That commit corrected several clinical reasoning Library references in narrative/source snippets and CMS146 data-requirements examples, but a current-source search still found active included JSON examples with relative canonical values.

Additional context:
Measure and PlanDefinition are active current-build resources in source/fhir.ini, and the edited JSON files feed current operation examples through source/measure/$submit-data-request.txt, source/measure/$collect-data-response.txt, and source/plandefinition/$data-requirements-response.txt. MeasureReport.measure is typed as canonical(Measure), and RelatedArtifact.resource in the PlanDefinition data-requirements Library JSON is a canonical URL field. Zulip and Confluence searches found no directly relevant discussion changing the Jira/source conclusion.

AutoFHIR reconciliation:
This commit changes the remaining active relative canonical values to full URIs: both MeasureReport.measure examples now use http://example.org/fhir/Measure/measure-mrp, matching the surrounding collect-data request examples, and the Zika affected areas relatedArtifact.resource now uses http://hl7.org/fhir/ValueSet/zika-affected-areas, matching the ValueSet source URL.

Recommendation:
Keep this source fix. It is a bounded completion of the published Jira request for active example inputs; any future broader cleanup of generated narrative text should be handled separately from the canonical-valued source data corrected here.
