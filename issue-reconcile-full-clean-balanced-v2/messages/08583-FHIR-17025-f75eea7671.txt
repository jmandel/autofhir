FHIR-17025: Audit Binary boundaries guidance

Issue request:
FHIR-17025 was a Published/Persuasive FHIR-core Binary change request asking the Binary Boundaries and Relationships section to explain how Binary relates to DocumentReference, Media, and FHIR Documents, including that DocumentReference/Media content is searchable while Binary is not.

Initial application:
The issue was applied in svn revision 14349, represented in git by 6d889d86b413e655a0d9e033525a07a9ab9eee2d, which added the requested Binary boundaries prose for DocumentReference, Media, non-FHIR Binary targets, Binary search limitations, and FHIR Documents in Bundle form.

Additional context:
Later source history changed the correct current interpretation. Commit 5c62f91cd81f150be72ad506c876e3cc20bd631d removed Media references from the Binary page as part of the GF#19250 Media-to-DocumentReference work, and the current R6 history page records Media as removed with DocumentReference or Observation as replacements. FHIR-38950 then copied the remaining useful Media boundaries guidance into DocumentReference, whose active source now describes media files, audio/video/image observations, DICOM/WADO relationships, FHIR document format, and Binary targets. Binary and DocumentReference are active build resources in source/fhir.ini; Media is not in the active [resources] list.

AutoFHIR reconciliation:
No source change was made. The current Binary page still says DocumentReference can carry or point to Binary/non-FHIR URI content, that Binary does not support search, and that FHIR Documents can be sent natively as Bundles or sometimes as Binary. The historical Media wording should not be restored to Binary because current source treats Media as removed/out of the active resource list and preserves the Media-related guidance in DocumentReference.

Recommendation:
Keep this audit commit as-is. Reopening source text for FHIR-17025 would be redundant or would reintroduce obsolete Media guidance; any future work should be driven by a new current-version issue about Binary/DocumentReference wording rather than by the STU3 Media-era request.
