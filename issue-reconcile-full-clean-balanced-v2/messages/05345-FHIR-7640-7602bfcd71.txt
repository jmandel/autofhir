FHIR-7640: Audit MedicationRequest status alignment

Issue request:
FHIR-7640 was a Published/Persuasive with Modification DSTU1 Pharmacy issue asking to align MedicationPrescription.status with other request resources so medication prescriptions could express proposed or planned medication requests, including requests proposed by CDS. The final resolution was to review all statuses and update them as required, with an agreed status spreadsheet added in August 2015.

Initial application:
The issue was explicitly applied in git 50cda04a97f78cbba13ffec2774fceb4e777297e, whose message is "#7640". That patch updated the then-current MedicationOrder spreadsheet status code list and definitions after MedicationPrescription had been renamed to MedicationOrder, but it did not add proposed or planned as status codes. The current source records the later rename from MedicationPrescription/MedicationOrder to MedicationRequest.

Additional context:
FHIR-3720 was the broader request-family issue about representing proposed and planned activities, and FHIR-9266 later asked whether that had been missed for MedicationOrder. Pharmacy resolved FHIR-9266 as Not Persuasive/No Change, saying MedicationOrder was part of the Request workflow pattern and should not include proposed or planned statuses. Current Request pattern source instead separates lifecycle status from Request.intent: Request.status is lifecycle-oriented, while Request.intent carries proposal, plan, and order semantics. Current MedicationRequest follows that split: MedicationRequest.status is bound to medicationrequest-status and MedicationRequest.intent is bound to medicationrequest-intent, whose code system includes proposal, plan, order, original-order, reflex-order, filler-order, instance-order, and option. Related MedicationRequest intent issues FHIR-13704 and FHIR-20605 are already represented on the combined branch.

AutoFHIR reconciliation:
No source files were changed. The active current source already satisfies the FHIR-7640 concern when interpreted with later workflow and Pharmacy decisions: proposed/planned medication requests are represented by MedicationRequest.intent, not by expanding MedicationRequest.status. Adding proposed or planned status codes now would contradict the current Request pattern and the explicit FHIR-9266 Pharmacy no-change decision.

Recommendation:
Keep this empty audit commit as-is. Do not add proposed or planned to MedicationRequest.status under FHIR-7640; future changes to MedicationRequest intent or common request code-system alignment should be handled under the later intent-specific issues that already track that family.
