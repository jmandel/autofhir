FHIR-12710: Audit StructureDefinition name warning

Issue request:
FHIR-12710 was Published/Persuasive with Modification for DSTU2. It requested validator enforcement of the computer-friendly StructureDefinition.name format by adding a warning regex using [A-Z]([A-Za-z0-9_]){0,254} for the metadata resource name field.

Initial application:
The Jira comment records an SVN application, and git-svn history shows a30472b3a6 (GF#12710 - add warning on metadataresource.name) adding the warning invariant in the MetadataResource spreadsheet and parser support. Later source refactors moved the rule from the old MetadataResource spreadsheet form into current StructureDefinition/CanonicalResource XML source.

Additional context:
Current fhir.ini actively builds StructureDefinition and the CanonicalResource/MetadataResource infrastructure interfaces. Current source carries warning invariant cnl-0 and StructureDefinition.name is conditioned on cnl-0. The apparent difference from the original {0,254} regex is intentional: FHIR-34147, also Published/Persuasive with Modification, explicitly changed all such expressions to {1,254}; FHIR Infrastructure minutes on 2021-12-20 record the approval rationale. FHIR-36127 later guarded optional CanonicalResource.name with name.exists(). Both related issues are already represented on the combined branch, so this commit does not duplicate them.

AutoFHIR reconciliation:
No source files were changed. The current source already gives validators a warning constraint for StructureDefinition.name and related canonical-name fields, and the current {1,254} expression reflects a later published correction rather than a missed FHIR-12710 application detail.

Recommendation:
Keep this audit commit as-is. Do not revert the regex to {0,254}; that would contradict FHIR-34147. No follow-up is needed in core unless a future work group decision changes the canonical name format.
