FHIR-12444: Audit required binding wording

Issue request:
FHIR-12444 was a Published, Persuasive with Modification FHIR-core terminology issue asking the Binding Strengths table to avoid the ambiguous plural phrase "codes in this element" for required bindings. The approved resolution changed the required summary to "the concept in this element SHALL be from the specified value set", made the other binding strength summaries consistent, and added a note that precise conformance criteria vary by datatype in the following sections.

Initial application:
The issue was applied in git-svn revision 11142, now commit 6b65dcb852b1857ee0741ffe138026c24d58b47f, which updated source/terminologies/bindings.xml for required and extensible binding descriptions and added the datatype-specific conformance note to source/terminologies.html. A later FHIR-12951 cleanup removed the duplicate non-linked table but kept the note.

Additional context:
The current build source has since been refactored. source/fhir.ini maps resourceType to the terminologies page, and source/terminologies.html now contains an explicit Binding Strengths table with the required summary exactly using "the concept in this element" wording, an extensible summary with matching concept wording, and a note that required/extensible conformance criteria vary by datatype. Later terminology decisions such as FHIR-27144 refined the detailed required binding section and CodeSystem definition around value set expansion without reintroducing the original ambiguous table wording.

AutoFHIR reconciliation:
No source change was made. The current build source already conveys the approved FHIR-12444 clarification in the Binding Strengths table and points readers to the detailed datatype-specific rules, including the CodeableConcept rule that one Coding value SHALL be from the specified value set.

Recommendation:
Keep this empty audit commit as-is. Further edits for FHIR-12444 would be redundant and risk drifting from later terminology refinements; any future alignment between the summary table and later required-binding expansion wording should be handled under the later terminology issues, not this DSTU2 clarification.
