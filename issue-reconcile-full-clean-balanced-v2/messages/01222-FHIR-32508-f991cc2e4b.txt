FHIR-32508: Audit Procedure.location clarification

Issue request:
FHIR-32508 was Published/Persuasive for R5 by Patient Care. It asked to remove the Procedure.location requirements wording "Ties a procedure to where the records are likely kept" because Procedure.location is meant to identify where the procedure actually happened, not where related records are kept.

Initial application:
The issue was applied by git commit 85f9053b69a48a8556aad22b881efe9997508eef, which removed the Procedure.location requirements value from source/procedure/structuredefinition-Procedure.xml. That commit also addressed FHIR-32506 on Procedure.performer, but the Procedure.location hunk directly matches this issue.

Additional context:
Procedure is an active current-build resource in source/fhir.ini. Current source on the combined branch has Procedure.location short text "Where the procedure happened" and definition "The location where the procedure actually happened..." with no remaining requirements value tying it to record storage. Patient Care meeting evidence is reflected in the Jira comment and Confluence minutes reference; no Zulip discussion was found that conflicts with the Jira/source conclusion.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change because the current source already implements the approved clarification and the obsolete requirements text is absent from the authoritative Procedure source and combined branch.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-32508 unless a future work-group decision changes the intended semantics of Procedure.location.
