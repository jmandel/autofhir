FHIR-32859: Describe MedicationRequest status as request lifecycle

Issue request:
MedicationRequest.status codes should not refer to prescriptions because MedicationRequest covers plans, proposals, and orders. Jira FHIR-32859 is Published with resolution Persuasive with Modification; the approved change was to use "request" instead of "prescription" and to fix an "observation" reference.

Initial application:
The issue appears to have been partially applied by git commit 7acfd680713d0152367c6841b366974c594b4ec0, which changed the MedicationRequest status CodeSystem definitions from prescription/observation wording to request wording. Current source shows those code definitions already use request-centered text, but the status element binding, mapping-exception mirror, search parameter description, and checked-in diagram tooltip still carried order/prescription wording.

Additional context:
MedicationRequest is an active resource in source/fhir.ini, so the StructureDefinition, search parameter bundle, mapping exception file, and resource diagram under source/medicationrequest are in current build scope. Confluence Pharmacy agenda pages reference FHIR-32859 only as an item to follow in Jira, and the Zulip searches found no directly relevant discussion that changes the Jira/source conclusion. Later 2025 status-code maintenance changed status metadata and entered-in-error wording but did not correct these remaining status descriptions.

AutoFHIR reconciliation:
Updated the MedicationRequest.status definition and binding description to describe the lifecycle of the request, updated the status search parameter description to "Status of the request", updated the Request mapping exception mirror, and kept the checked-in MedicationRequest SVG tooltip consistent with the authoritative StructureDefinition change.

Recommendation:
Keep this commit as-is. The remaining uses of prescription/order in MedicationRequest source describe other medication-order concepts and are outside the status-code wording requested by FHIR-32859; a broader wording sweep should be handled by a separate Pharmacy WG decision if desired.
