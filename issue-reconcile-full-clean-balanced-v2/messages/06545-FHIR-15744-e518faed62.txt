FHIR-15744: Audit ValueSet canonical URL wording

Issue request:
FHIR-15744 was a Published/Persuasive STU3 Vocabulary change request for FHIR-core ValueSet. It asked to make references to "canonical URI" and "canonical URL" consistent, with the original request expecting "canonical URI" to be the primary term and to align with similar CodeSystem wording.

Initial application:
The Jira comments say the request was pre-applied in svn 13351. Git history preserves that as d90f55e1cbc897c77c5188342e1d43353f38f2c3, which changed the active ValueSet documentation from "canonical URL" to "canonical URI" phrasing. The CodeSystem companion issue FHIR-14691 was applied at the same time in 080e47c1a06da8867d5f876ed2bb2d528dc64632, also making CodeSystem terminology use "canonical URI".

Additional context:
The later Published issue FHIR-18673 explicitly revisited confusing canonical terminology and was applied by 6f7c3716ef8e176e5ea811ceb12844b81a3904ec. That commit changed the ValueSet and CodeSystem narrative away from the FHIR-15744/FHIR-14691 "canonical URI" wording and established the current "canonical URL" / "canonical reference" terminology. The current source/fhir.ini has ValueSet active in the build, and the active ValueSet and CodeSystem source no longer contain "canonical URI" wording.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current ValueSet source is consistent with the later canonical-terminology decision: ValueSet.url is described as the canonical URL, canonical references use the canonical datatype, and neither source/valueset nor source/codesystem contains the older "canonical URI" phrasing from the original application.

Recommendation:
Keep this audit commit as-is. Reintroducing "canonical URI" for FHIR-15744 would undo the later FHIR-18673 clarification and make ValueSet inconsistent with the current broader FHIR canonical URL convention. Any future change should be handled as a new cross-cutting canonical terminology decision, not as remaining work for FHIR-15744.
