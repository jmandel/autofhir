FHIR-18284: Audit Bundle bdl-7 history exception

Issue request:
FHIR-18284 was a Published/Persuasive FHIR-I change request raised against STU3 and applied for STU3. It reported that Bundle invariant bdl-7 failed history Bundles containing multiple delete entries because deleted entries do not contain entry.resource and therefore have no resource.meta.versionId. The proposed and accepted direction was to correct bdl-7 so it reflected the Bundle uniqueness text allowing history duplicate fullUrls.

Initial application:
The issue was initially applied by git commit dc4a4436ac41450dcf83c005b99929aa1a2db1f8, which updated the then-authoritative Bundle spreadsheet bdl-7 human text to add "except in history bundles" and changed the FHIRPath to start with `(type = 'history') or ...`. The current source has since moved the authoritative invariant to source/bundle/structuredefinition-Bundle.xml.

Additional context:
Bundle is an active current-build resource in source/fhir.ini, and the current Bundle notes say a given version of a resource SHALL appear only once while multiple versions of the same resource may appear, especially in history Bundles. Later Published issue FHIR-31986 clarified that the history exception was really about entries with no resource body, such as history deletes, and also applies to batch HEAD cases; it directed bdl-7 to filter to entries where resource is present and to compare fullUrl plus meta.versionId with a delimiter. Later Published issue FHIR-39476 corrected the absent meta.versionId case by adding an empty-string fallback. The current bdl-7 source incorporates both later refinements.

AutoFHIR reconciliation:
This empty audit commit makes no source change. Current source/bundle/structuredefinition-Bundle.xml already excludes entries without resource from bdl-7, so history delete entries no longer cause the failure reported by FHIR-18284. It also intentionally does not exempt all history Bundles, because the later FHIR-31986 resolution and current Bundle narrative preserve the rule that the same resource version should not appear twice.

Recommendation:
Keep this audit commit as-is. Do not restore the broad `(type = 'history') or ...` exemption for current builds; that would regress the later, more precise FHIR-31986/FHIR-39476 bdl-7 behavior. Any future relaxation of Bundle uniqueness for resource-bearing history entries should go through a new work-group decision.
