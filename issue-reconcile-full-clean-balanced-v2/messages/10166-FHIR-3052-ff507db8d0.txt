FHIR-3052: Audit cid reference wording

Issue request:
FHIR-3052 was a Published/Persuasive FHIR-core references-page change request from the initial draft/DSTU1 era. It said the page's use of "internal references" for cid: URIs in transactions was misleading because transaction references are references between Bundle entries, and asked for clearer documentation including whether cid: URIs can be used in documents or messages.

Initial application:
The issue was applied in svn revision 3079, now git commit 20c997a5a51ec1a84a5faa13d9401f3f3eef43e8. That commit changed source/references.html from "internal references" to "references within bundles" and added that cid: URIs can be used in documents or messages too.

Additional context:
Later reference-page refactoring in 2319e45e4115705f873661fe217ae2971eebc13f removed the old cid-specific paragraph while reorganizing Reference.type and canonical-reference material. The current references page no longer makes the misleading "internal references"/cid statement. Current active Bundle source carries the general rule: Bundle.entry.fullUrl can be an arbitrary URI and is not limited to urn:uuid, urn:oid, http, or https, and the Bundle reference narrative says entry resource reference.reference values can use any URI scheme. The Bundle resource and References page are in the current build through source/fhir.ini and source/hierarchy.xml.

AutoFHIR reconciliation:
No source change was made. The current source has no stale references-page cid wording to correct, and the current Bundle material already conveys the broader rule needed for cid-like temporary URI schemes within Bundles without duplicating cid-specific prose on the references page.

Recommendation:
Keep this audit commit as-is. If the work group wants to reopen the broader question of how non-URN URI schemes such as cid: should be illustrated in the Bundle resolution algorithm, that should be handled as a new Bundle/reference-resolution issue rather than as additional FHIR-3052 cleanup.
