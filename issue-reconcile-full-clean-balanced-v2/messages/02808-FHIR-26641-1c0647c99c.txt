FHIR-26641: Audit Location closure availability support

Issue request:
FHIR-26641 was a Published Patient Administration change request, resolved Persuasive with Modification for R5. The submitter asked for status change date/period support on Location; the approved resolution was narrower: copy the notAvailable structure from HealthcareService and PractitionerRole into Location to support discrete closures, with availabilityExceptions as a textual alternative for closure descriptions.

Initial application:
The application trail is present. Commit 447e89f4a40f92d16f33490766f29b9bce017236 explicitly cited FHIR-26641 and replaced Location.hoursOfOperation's inline opening-hours backbone with the shared Availability datatype, while adding the Availability.notAvailableTime.description and Availability.notAvailableTime.during structure. Commit 896a7fadf5d0db4d8aed896a6edc1cf569f20932 also cited FHIR-26641 but only corrected the newly added Location.virtualService path. A later FHIR-17622 commit added Location narrative guidance for hoursOfOperation.notAvailableTime.

Additional context:
FHIR-25381 is the same application family because it created the shared Availability datatype used by Location, HealthcareService, and PractitionerRole. The current build has Location active in source/fhir.ini, and fhir.ini records the R5 mapping from Location.availabilityExceptions to Location.hoursOfOperation.notAvailableTime.description after the datatype refactor. Later availability-related reconciliations on the combined branch refine adjacent Availability wording but do not remove or weaken Location closure support.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current source already lets Location.hoursOfOperation use Availability, whose notAvailableTime backbone has both description and during Period, and Location notes explicitly tell implementers to block public holidays or planned maintenance with hoursOfOperation.notAvailableTime and preferably include actual start/end dates.

Recommendation:
Keep this no-change audit. Further source work is not needed for the approved FHIR-26641 resolution unless PA opens a new decision to add a distinct status-history/status-effective element beyond the notAvailableTime closure mechanism that was approved for R5.
