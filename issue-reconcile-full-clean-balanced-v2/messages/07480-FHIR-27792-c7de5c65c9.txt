FHIR-27792: Audit R4 core package dependency fix

Issue request:
FHIR-27792 was a Published/Persuasive FHIR-I technical correction for R4. It reported that the hl7.fhir.core 4.0.1 group package at http://hl7.org/fhir/R4/package.tgz and Simplifier depended on hl7.fhir.r3.* packages even though the dependencies should have been hl7.fhir.r4.* packages; the reporter suggested publishing a corrected package version such as 4.0.2 and unlisting the bad one because packages are normally immutable.

Initial application:
No current FHIR-core source commit explicitly mentions FHIR-27792, and the current source checkout does not contain the historical R4 package tarball or mutable package-registry metadata. The issue appears to have been applied operationally: the current canonical http://hl7.org/fhir/R4/package.tgz package and packages2.fhir.org hl7.fhir.core 4.0.1 tarball now depend on hl7.fhir.r4.core, hl7.fhir.r4.examples, hl7.fhir.r4.expansions, and hl7.fhir.r4.elements. The old Simplifier tarball still shows the original hl7.fhir.r3.* dependency error.

Additional context:
Zulip records Ward Weistra raising the same package-only-fix problem on 2020-06-09 and Grahame Grieve immediately confirming the dependencies should be R4. FHIR-I WGM minutes from 2022-09 record FHIR-27792 with "Grahame believes this is done," matching the Jira comment. Current source/packages.html is build-scoped via source/hierarchy.xml and uses hl7.fhir.r4.core in package examples; current source grep found no hl7.fhir.r3.core package dependency text to correct. No hl7.fhir.core or hl7.fhir.r4.core 4.0.2 package is currently listed in the checked registries, so the durable applied state is a corrected 4.0.1 at the active HL7/package2 endpoints rather than a source-editable 4.0.2 entry.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The current official R4 package distribution no longer has the STU3 dependency error, and editing current FHIR source would not alter either the already-correct canonical package.tgz or the legacy Simplifier/package-registry mirror that still contains the old bad tarball.

Recommendation:
Keep this no-change audit for the FHIR source reconciliation. If HL7 still wants the legacy Simplifier or packages.fhir.org copy remediated, that should be handled as package-registry operations or human publication review, not by changing current core source files.
