Issue request:
FHIR-12065 was a Published/Persuasive DSTU2 Vocabulary change request for ValueSet/filter-operator is-a. It asked to clarify that is-a includes the head/provided concept and all descendants, replacing the misleading "child codes" parenthetical.

Initial application:
The Jira comment records svn revision 10421. In the git mirror, commit 4b26fc414250bb85aa86d46443e26e9d3f33abd1 references #12069/#12065 and updated source/valueset/valueset-notes.xml to say the relationship includes the concept itself. That historical revision applied the seed alongside unrelated FHIR-12069 CodeSystem concept-status work.

Additional context:
Later Published/Persuasive FHIR-16321 revisited the same ValueSet filter-operator parentheticals and changed is-a to the current clearer wording, "include descendant codes and self." Later source refactoring moved the built filter-operator content from spreadsheet-era sources into source/valueset/codesystem-filter-operator.xml. ValueSet remains active in source/fhir.ini, and ValueSet.compose.include.filter.op plus CodeSystem.filter.operator both bind to http://hl7.org/fhir/ValueSet/filter-operator, so the inspected filter-operator CodeSystem/ValueSet source is current build scope.

AutoFHIR reconciliation:
This audit commit makes no source change. Current source/valueset/codesystem-filter-operator.xml and the parallel source/codesystem/codesystem-notes.xml both define is-a as including the provided concept itself and descendant codes. The wording differs from the original Jira suggestion only because a later applied issue refined the parenthetical; the current wording preserves the seed's intended head-code-plus-descendants semantics.

Recommendation:
Keep this audit commit as-is. No FHIR-core source edit is needed for FHIR-12065; changing the current wording back to the original suggested phrase would be redundant and would undo the later FHIR-16321 clarification.
