FHIR-9880: Audit Observation event history provenance

Issue request:
FHIR-9880 was Published with a Persuasive with Modification resolution for DSTU2 Observation. It asked how to identify the person or machine responsible for status changes, concluded that Provenance should be used for actors involved in updates, and requested an event.eventHistory-style extension so OO event resources could reference past event history leading to status changes without replacing workflow management.

Initial application:
An explicit GF#9880 source commit exists, but its focused Observation patch changed Observation.effective[x] to allow Timing and disabled the older eventTiming extension rather than adding the final Provenance event-history mechanism. The event-history part of the resolution appears to have been applied later when the workflow/event profile sources were generated: the historical event extension spreadsheet included an eventHistory row for Observation, DiagnosticReport, Task, SupplyDelivery, and DeviceUseStatement.

Additional context:
The current build scope still includes Observation and the workflow/event pattern material in core, but extension definitions have since moved out of the core checkout. Current core Event pattern source defines Event.relevantHistory with element name eventHistory, references ProvenanceRelevantHistory, and includes narrative guidance for using Provenance to summarize relevant lifecycle events. The FHIR Extension Pack now defines the active event-eventHistory extension, including Observation and the other OO event resources as contexts. Later decisions reinforce this interpretation: FHIR-20760 added Event/Request relevant-history guidance, FHIR-48829 retained ProvenanceRelevantHistory in core for workflow use, and FHIR-43456 explicitly treated Observation.relevantHistory as covered by the event-eventHistory extension.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core source and Extension Pack together already provide the requested Provenance-based event history mechanism; adding a core Observation element or restoring old core extension rows would conflict with later source ownership and workflow-pattern decisions.

Recommendation:
Keep this no-change audit commit. If future work changes event-eventHistory, make it in the FHIR Extension Pack or through a new workflow-pattern decision; no FHIR core source edit is needed for FHIR-9880.
