FHIR-46522: Audit integer64 FHIRPath Long mapping

Issue request:
FHIR-46522 is an Applied/Persuasive FHIR-core technical correction asking that integer64 stop being represented as http://hl7.org/fhirpath/System.Integer, because FHIRPath Integer is 32-bit, and instead reference the FHIRPath 64-bit Long type once available for R6.

Initial application:
The integer64-to-FHIRPath mapping was first addressed for R5 by FHIR-26389 in commit a1a727070c2cd8bfed2507ea7ae0ad84f3e88a73, which added FHIR.integer64 -> System.Long to source/fhirpath.html. The seed issue was later applied through PR #3797; commit 0b26d1b1862f0a3028062a690fa09da278674bb2 added http://hl7.org/fhirpath/System.Long to source/terminologies/codesystem-fhirpath-types.xml.

Additional context:
FHIR-26542 records the FHIRPath-side decision to add a 64-bit System.Long type. FHIR-I minutes from 2024-08-12 recorded FHIR-46522 as a technical correction dependent on the FHIRPath R6 update. Zulip discussion in July and October 2025 confirms that FHIRPath Long became available, FHIR-46522 was waiting on it, and the generated integer64.value type was fixed in Kindling while the FHIR core CodeSystem update was committed in PR #3797.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped source/fhirpath.html page maps FHIR.integer64 to System.Long, and the current FHIRPath types CodeSystem includes System.Long for value set expansion. The worker and combined branches already contain those source changes, and no checked-in current JSON/XML profile source in the FHIR checkout still defines integer64.value as System.Integer.

Recommendation:
Keep this no-change audit commit. If a future generated integer64.profile.json again shows System.Integer, investigate the Kindling generator or build output rather than adding another core source hunk; the FHIR core source surfaces checked here already express the approved R6 mapping.
