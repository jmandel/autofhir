FHIR-17344: Audit Questionnaire repeats guidance

Issue request:
FHIR-17344 was a Published, Persuasive with Modification STU3 Questionnaire change request asking that Questionnaire.item.repeats be clarified after implementer confusion about whether repeats=true is commonly used for "any of these choices" / checkbox-style questions. The accepted resolution was to explain both rendering scenarios and what is typical.

Initial application:
The issue appears to have been applied in the 2018 git-svn history near the Jira comment's SVN reference: commit fccd01d1da946ae8d270f20c68e2b6407b3b6dec, git-svn r14686, updated source/questionnaire/questionnaire-spreadsheet.xml to explain that a repeated question may be rendered by repeating the question text or by allowing entry/selection of multiple answers, and that either rendering produces a single QuestionnaireResponse question item with multiple answers.

Additional context:
Questionnaire is an active current resource in source/fhir.ini. The spreadsheet source was later refactored into source/questionnaire/structuredefinition-Questionnaire.xml. Later Published/Applied Questionnaire repeat issues FHIR-33335 and FHIR-55973 refined the same element by making the question-vs-group QuestionnaireResponse representation explicit and by requiring repeated question answers to be distinct. The current active source now says repeats=true allows multiple distinct answers for a question or multiple repetitions for a group, that a question is represented by one item with multiple answers, and that rendering software may either repeat the question text or simply allow multiple answer entry/selection. The originating Zulip thread confirms that the question use case was "check all that apply" and that most of the time it is rendered as multiple answers rather than repeated question text. No Confluence records were found that changed this conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Questionnaire.item.repeats definition and comment already preserve the accepted semantics and cover the two rendering scenarios; adding a new "most often" sentence would be redundant guidance rather than a necessary correction to current implementer understanding.

Recommendation:
Keep this audit commit as-is. Revisit only if the work group wants a non-normative rendered example for choice/open-choice items; the current conformance source does not need a FHIR-17344 fix.
