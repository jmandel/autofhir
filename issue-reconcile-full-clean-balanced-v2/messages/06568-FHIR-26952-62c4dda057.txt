FHIR-26952: Audit SupplyRequest performerOrder outside core

Issue request:
FHIR-26952 was Applied with a Persuasive with Modification resolution for R6. It asked to make performerOrder usable for SupplyRequest by adding SupplyRequest.requestedPerformer and linking the standard http://hl7.org/fhir/StructureDefinition/request-performerOrder extension.

Initial application:
Core PR #3808 was merged as commit eaa86743db and added SupplyRequest.requestedPerformer plus an ElementDefinition extension pointing at request-performerOrder in source/supplyrequest/structuredefinition-SupplyRequest.xml. Extension Pack PR #218 added SupplyRequest.requestedPerformer as an allowed context, but that context was later commented out in the Extension Pack by commit 2b046fd3bd.

Additional context:
FHIR-43453 is the related SupplyRequest workflow-pattern alignment issue that Jira said should be resolved first; it was applied separately in commit 284febeeb5. After both issues were applied, core commit 3b38b80cf2 removed SupplyRequest and other OO additional resources from the active core fhir.ini resource list and changed core pages to point to the OO Incubator IG. The current OO Incubator SupplyRequest source keeps requestedPerformer but has the request-performerOrder annotation commented out with a TODO noting that the carryover extension usage was breaking the IG. Current Extension Pack master likewise has the SupplyRequest context commented out.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The active core build no longer includes SupplyRequest, so editing source/supplyrequest would not fix the current built artifact. The remaining performerOrder linkage, if it should be restored, belongs in the OO Incubator and/or FHIR Extension Pack sources rather than this core checkout.

Recommendation:
Keep this audit commit as-is for core. Follow up in HL7/oo-incubator and HL7/fhir-extensions to decide how to support request-performerOrder for SupplyRequest.requestedPerformer without breaking the IG build; no further core-source edit is warranted unless SupplyRequest returns to the active core build.
