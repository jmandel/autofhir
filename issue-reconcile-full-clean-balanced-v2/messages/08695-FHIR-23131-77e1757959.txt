FHIR-23131: Audit migrated FMM warning validation

Issue request:
FHIR-23131 was a Published/Persuasive FHIR-core technical correction. It reported that the old in-repo Java ResourceValidator rejected resources with warnings unless their FMM level was 0, but the build error said the resource could not have an FMM level >1, which made an FMM=1 Subscription failure misleading.

Initial application:
No FHIR source commit explicitly mentions FHIR-23131. Historical FHIR source shows the reported ResourceValidator message in tools/java/org.hl7.fhir.tools.core before the Java tooling was removed from this checkout. FHIR commit 9f549566d1346cad7db6d2afca6080d7cebdfbbe then switched the build to the external Gradle kindling dependency and deleted the in-repo ResourceValidator.java file.

Additional context:
The current FHIR build uses org.hl7.fhir:kindling:${property("kindlingVersion")} with kindlingVersion=1.25.5-SNAPSHOT, so the active publisher/validator source for this check is outside the FHIR checkout. In HL7/kindling, commit b501b047d5cc472e5be99ce938d202c5ff1972cd changed the primary FMM warning message from ">1" to "> 0", matching the actual FMM0 condition. Later kindling commit 02382b53ed0f3d170ccb3120ef0aabc6db0213e5 commented out the FMM warning requirement checks entirely. Zulip and Confluence searches found no relevant or conflicting community discussion for FHIR-23131.

AutoFHIR reconciliation:
This audit intentionally makes no source change in the FHIR checkout. The reported in-repo source file is no longer present, the current build delegates to kindling, and the external active source has already corrected and subsequently disabled the confusing FMM warning check.

Recommendation:
Keep this audit commit as-is. No core FHIR source follow-up is needed for FHIR-23131; if the FMM warning policy is reintroduced, make and test that change in HL7/kindling rather than in this FHIR source checkout.
