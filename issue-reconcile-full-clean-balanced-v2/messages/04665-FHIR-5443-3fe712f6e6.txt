FHIR-5443: Audit removed PendedRequest

Issue request:
FHIR-5443 was a Published/Persuasive with Modification FM change request from the January 2015 ballot for FHIR-core-PendedRequest. The requested disposition said PendedRequest should not remain a Financial resource with financial-specific language; if kept, it should be treated as an infrastructure polling mechanism and coordinated with querying, publish/subscribe, REST, messaging, and services. The Jira comments later recorded that the resource no longer existed, making the requested change moot.

Initial application:
No source commit found explicitly names FHIR-5443. The relevant 2015 source history shows the same application path described by the Jira comments: ProcessRequest was added to replace PendedRequest and related financial request/response resources, PendedRequest source files were deleted, and references from Financial, resource lists, compartments, hierarchy, and payment reconciliation were removed or redirected.

Additional context:
Current build scope confirms PendedRequest is not an active resource. In source/fhir.ini it appears only under [removed-resources], while the old ProcessRequest/ProcessResponse entries are commented out and also listed as removed resources. The release history page records PendedRequest/Readjudicate/Reversal/StatusRequest/StatusResponse as removed in favor of ProcessRequest/Response and then records ProcessRequest/Response as removed in favor of Task. The only remaining PendedRequest text in source is removed-resource/history text or an out-of-build ProcessRequest spreadsheet example/definition.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current specification no longer publishes PendedRequest as a Financial resource, and editing the remaining removed-resource/history or inactive ProcessRequest source would not improve the current built specification.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-5443 unless a future work group explicitly reopens polling/deferred-response modeling; any such work should start from current Task/subscription/query mechanisms rather than resurrecting PendedRequest.
