FHIR-26308: Audit DeviceUsage pre-applied changes externally owned

Issue request:
FHIR-26308 is an Applied/Persuasive OO change request for the R5 DeviceUseStatement/DeviceUsage resource. It asked the work group to validate implicit pre-applied updates made while resolving FHIR-14142, FHIR-24680, FHIR-20913, and FHIR-24936, including usageStatus, usageReason, dateAsserted, category, CodeableReference device/reason/body-site handling, and the absence of statusReason. The final Jira resolution was to accept the pre-applied changes.

Initial application:
No git commit message directly names FHIR-26308, but the February 2020 DeviceUseStatement spreadsheet history contains commits whose patch context says "Preapplied FHIR-26308" and shows the accepted element updates being introduced. The current checked-in DeviceUsage StructureDefinition still carries those accepted shapes and descriptions, although that directory is no longer an active core build input.

Additional context:
Later decisions changed the artifact around the accepted baseline: FHIR-31478 renamed DeviceUseStatement to DeviceUsage, FHIR-32829 added the adherence backbone related to usageStatus/usageReason, and FHIR-53203 moved OO body-site content toward bodyStructure CodeableReference. Most importantly for this reconciliation, commit 3b38b80cf2 removed DeviceUsage and other OO resources from active core fhir.ini resource/build lists and changed the core device module to link DeviceUsage to the OO Incubator IG. The current source/fhir.ini has no active DeviceUsage resource entry, and a package check of the OO Incubator continuous build shows DeviceUsage with the accepted category/dateAsserted/usageStatus/usageReason/device/reason/bodyStructure shape.

AutoFHIR reconciliation:
This is an empty external-repo audit commit. No core source files were changed because DeviceUsage is outside the current FHIR core build scope; editing the retained source/deviceusage files would not fix the current core specification.

Recommendation:
Keep this audit commit as-is for the core reconciliation. If future DeviceUsage corrections are needed, handle them in the OO Incubator source/publication path rather than by editing the inactive core source/deviceusage directory. Do not treat the stale checked-in SVG or inactive legacy files as current core build obligations unless DeviceUsage is reactivated in source/fhir.ini.
