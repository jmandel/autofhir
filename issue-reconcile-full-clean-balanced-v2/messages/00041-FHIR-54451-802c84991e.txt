FHIR-54451: Audit MedicationStatement reason clarification

Issue request:
FHIR-54451 was an Applied Pharmacy change request asking how implementers should choose between MedicationStatement.reason and MedicationStatement.relatedClinicalInformation, and asking whether relatedClinicalInformation should be rolled into reason or expanded to include DocumentReference. The final Not Persuasive with Modification resolution retained both elements and requested definition clarifications only: .reason should describe what leads to the medication being taken or not taken, and .relatedClinicalInformation should state that the actual indication normally belongs in .reason.

Initial application:
The issue was applied before this reconciliation by git commit 84c55f6b66eedb0c7341526f2cbf4a914ec4ed7a, which changed source/medicationstatement/structuredefinition-MedicationStatement.xml to the approved .reason and .relatedClinicalInformation wording. Commit cd0ae4e75773fa9c19e05ad754a6bf7a7d46eedd later moved the associated changelog entry into source/medicationstatement/_changelog.txt.

Additional context:
MedicationStatement is active in source/fhir.ini, so source/medicationstatement/structuredefinition-MedicationStatement.xml is in current build scope. Jira neighborhood searches found no other final FHIR-core issue specifically about relatedClinicalInformation, and the later reporter comment about target lists does not override the Applied resolution, which chose clarification rather than adding DocumentReference. Zulip searches found no directly relevant discussion. Confluence Pharmacy minutes reference FHIR-54451 on the January 2026 agenda but did not reveal conflicting implementation guidance. A stale tooltip remains in source/medicationstatement/medicationstatement.svg, but this is a generated-looking diagram artifact; the authoritative StructureDefinition now conveys the approved rule.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative MedicationStatement definitions already implement the approved clarification, and changing only the SVG tooltip would violate the run guidance against source-changing commits whose only edit is a generated-looking diagram/SVG artifact.

Recommendation:
