FHIR-13375: Audit Observation integer value choice

Issue request:
FHIR-13375 was a Published/Persuasive OO change request for STU3. It asked to allow the integer datatype in Observation.value[x] because representing integer-valued observations as Quantity/Count created avoidable datatype and expression-evaluation overhead. The recorded resolution was to add a choice of valueInteger to Observation.

Initial application:
The current git history has no commit whose message literally says FHIR-13375, but the historical GForge application commit 8a0e3f8d3b7a2a75418c2bdc8dc67ed31bb917b9 says "GF#13703 fix error- add component.valueBoolean  GF#13375 add valueInteger" and changes the old Observation spreadsheet source to add integer to Observation.value[x]. The same commit also added valueInteger to the Observation notes list and added integer to Observation.component.value[x], alongside the separate FHIR-13703 component boolean fix. The 2021 source rework preserved the integer choice in the modern StructureDefinition source.

Additional context:
Observation is an active current-build resource in source/fhir.ini. The current authoritative source/observation/structuredefinition-Observation.xml lists integer as an allowed type for both Observation.value[x] and Observation.component.value[x], and the Observation notes page still lists valueInteger under Value[x] and Datatypes. The 2017 Zulip thread for tracker #13375 records the implementer debate about Quantity versus integer and ends with OO having voted in favor. FHIR-13703 was part of the same historical source commit but was already represented on the combined branch, so this commit does not re-decide it.

AutoFHIR reconciliation:
Made no source change. The current active Observation source already satisfies FHIR-13375 by allowing <code value="integer"/> in Observation.value[x], with matching narrative guidance listing valueInteger.

Recommendation:
Keep this no-change audit commit as-is. No follow-up is needed for FHIR-13375 unless a future build removes integer from Observation.value[x] or changes the Observation value choice policy.
