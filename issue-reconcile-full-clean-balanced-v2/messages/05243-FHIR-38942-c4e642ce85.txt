FHIR-38942: Audit Bundle collection resource invariant

Issue request:
FHIR-38942 was a Published/Persuasive FHIR-I R5 ballot issue asking for a Bundle constraint that enforces the existing rule that each entry in a Bundle of type collection has a resource. The accepted resolution was to move all "SHALL contain a resource" Bundle entry rules into invariants and remove redundant SHALL prose while keeping other explanatory language.

Initial application:
The issue was applied in git commit 7fd7b9ce04e0675f40e902ba468f696a851dd51a, which added Bundle bdl-3a through bdl-3d in source/bundle/structuredefinition-Bundle.xml and removed redundant SHALL wording from the Bundle notes, including the collection paragraph. No prior AutoFHIR issue-reconcile commit for FHIR-38942 was found on the combined branch before this audit.

Additional context:
Bundle is active build source via source/fhir.ini, and source/bundle/structuredefinition-Bundle.xml is the authoritative resource definition. Current bdl-3a requires all entries for document, message, searchset, and collection Bundles to contain resources and have no request or response. The current collection narrative says each entry contains a resource without the redundant SHALL wording targeted by the resolution. FHIR-I 2022-10-17 minutes record the 12-0-0 Persuasive vote. No Zulip records or conflicting Confluence records were found. Later Bundle/history work, including the existing FHIR-7933 reconcile commit, leaves bdl-3a intact.

AutoFHIR reconciliation:
Made no source change. The current source already contains the requested invariant for collection Bundles and the collection prose no longer carries the redundant SHALL wording targeted by the resolution.

Recommendation:
Keep this empty audit commit. Future work, if any, should be tracked under separate Bundle/history or PATCH issues rather than reopening the collection requirement addressed by FHIR-38942.
