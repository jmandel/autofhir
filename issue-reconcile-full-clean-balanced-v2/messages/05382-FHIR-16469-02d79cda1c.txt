FHIR-16469: Audit CodeSystem content-mode clarification

Issue request:
FHIR-16469 was a Published/Persuasive with Modification STU3 vocabulary issue asking FHIR-core CodeSystem content mode definitions to distinguish the example and fragment codes more clearly. The approved clarification said example content has no useful subset intent and is not intended to be workable, while fragment content is a curated subset released for a purpose with the intent, bounds, and consequences of fragmentation clearly documented.

Initial application:
The issue was applied in SVN revision 14680, represented in git by 54cd02036599308b033f2838d80f5b7d842daf33, which changed the old CodeSystem spreadsheet definitions for example and fragment. That initial application introduced the requested distinction, including the later-corrected governance spelling in the fragment sentence.

Additional context:
The CodeSystem source has since been refactored from the spreadsheet to active XML resources. Later final decisions changed the same wording family: FHIR-39163 replaced the old example definition to remove the undefined "workable" phrase, FHIR-51110 added the warning not to use example when fragment is the better representation, and FHIR-33947 shortened the fragment concept definition while retaining the intent/bounds/consequences rule in the Code System Fragments narrative. FHIR-27147 rejected adding a separate subset content mode, while FHIR-53375 and FHIR-48959 remain later unresolved or not-yet-applied context and do not justify changing this seed.

AutoFHIR reconciliation:
This empty audit commit makes no source change. Current build-scope source already conveys the seed distinction: example is an illustrative subset with no specific purpose or documented intent and should not be used when fragment fits; fragment is a curated subset released for a specific purpose; and the fragment narrative requires the intent, bounds, and consequences of fragmentation to be clearly defined.

Recommendation:
Keep this audit commit as-is. No source follow-up is needed for FHIR-16469 unless a later final vocabulary decision changes the still-open example/fragment policy questions.
