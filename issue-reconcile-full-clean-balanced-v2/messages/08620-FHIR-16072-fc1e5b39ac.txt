FHIR-16072: Audit CapabilityStatement operation status

Issue request:
FHIR-16072 was a Published/Persuasive STU3 change request for FHIR-core Conformance asking that CapabilityStatement operations not be treated as normative because $subset, $implements, and $conforms did not have wide use. The accepted resolution was to mark these operations as trial-use.

Initial application:
The Jira comment points to svn revision 14280. In the Git mirror, commit 93f89b218b0ad4f87958985ee3bb48cccbbb3446 added a Standards-Status column to the CapabilityStatement spreadsheet and set $subset, $implements, $conforms, and the then-adjacent $versions row to trial-use. That is the original application of the issue.

Additional context:
Current core source no longer defines $subset, $implements, or $conforms under source/capabilitystatement. The active CapabilityStatement resource is still in build scope through source/fhir.ini, and source/capabilitystatement/list-CapabilityStatement-operations.xml now lists only OperationDefinition/CapabilityStatement-versions. The R6 normative cleanup commit 270e0ceb7b029dad4ca0fc5ccf5296ff370888cd removed the old $subset/$implements/$conforms OperationDefinition XML and examples from core, while deliberately changing $versions to normative. FHIR-I 2025 WGM minutes record the same split: move $subset to the feature IG, same with Conforms and implements, and keep $versions normative. The external CapabilityStatement/Application Feature IG currently shows $subset, $implements, and $conforms as Trial-use.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current core specification no longer contains the three operations that FHIR-16072 was concerned about, and the external definitions linked from current core narrative are trial-use. Downgrading the remaining core $versions operation would conflict with the later R6 normative cleanup and meeting record rather than apply FHIR-16072.

Recommendation:
Keep this no-change audit as-is. Any future changes to $subset, $implements, or $conforms should be handled in the CapabilityStatement/Application Feature IG rather than in core, while $versions should remain governed by the later R6 normative decision unless FHIR-I reopens it.
