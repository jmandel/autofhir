FHIR-28119: Audit ValueSet system-title extension reconciliation

Issue request:
FHIR-28119 was a Published/Persuasive Vocabulary issue for R5. It originally asked to update the valueset-systemName extension description to align the Value Set Definition Profile field DrawnFromCodeSystem.DescriptiveName with CodeSystem.title; the final resolution instead required a new valueset-systemTitle extension with description "The human-readable name for the code system" and deprecation of the existing valueset-systemName extension.

Initial application:
The issue was applied in core by commit 9fca6ca36fefa544491b1efc7fdb1530333ed78b, whose message lists FHIR-28119 among the R5 VSD Profile changes. That commit removed and re-added valueset-systemName in the ValueSet core IG, added StructureDefinition/valueset-systemTitle, and kept valueset-systemName as a referenced extension. A later broad core cleanup, dd468d4f1799dd79819315b211588ef1cf4586e0, removed the ValueSet extension StructureDefinitions from the R5 core source.

Additional context:
FHIR-37923 subsequently removed the VSD Aligned Value Set Profile because the shareable/computable/publishable/executable ValueSet profiles had superseded it. The current core ValueSet IG contains no extension definitions, while source/fhir.ini still lists ValueSet and Device as active resources and source/device/valueset-device-safety.xml remains an active example that uses valueset-systemName. Current extension definitions are in the FHIR Extension Pack: valueset-systemName is retired/deprecated with guidance to use the generic display extension, and valueset-systemTitle is absent because later Applied decisions FHIR-40710 and FHIR-40711 deprecated valueset-systemName and removed valueset-systemTitle.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Recreating valueset-systemTitle or changing valueset-systemName in core would reverse later applied decisions and edit artifacts that no longer live in the core build. The current core source is consistent with the later issue family: it does not define the retired/removed extensions, and the externally maintained extension definition carries the deprecation guidance.

Recommendation:
Keep this audit commit as-is. If future work reviews the remaining core example that uses valueset-systemName, handle it under FHIR-40710 or a new Terminology Infrastructure decision rather than reopening FHIR-28119, because FHIR-28119's R5 change was applied and later superseded.
