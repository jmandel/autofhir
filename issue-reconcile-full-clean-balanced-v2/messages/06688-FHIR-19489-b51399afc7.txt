FHIR-19489: Audit Task Draft start state

Issue request:
FHIR-19489 was an Applied/Persuasive OO change request for R6. It reported that the Task state machine text said "Tasks start in a Created state" even though Task.status is required-bound to TaskStatus, which has no Created code. The approved resolution was to replace "Created" with "Draft".

Initial application:
The issue had already been applied before this reconciliation. The Jira snapshot records that it was added to the build, and current local source history shows ff032a3110 changing source/task/task-notes.xml from Created to Draft in both the starting-state sentence and the non-terminal state list, followed by 8bcebf4320 whitespace cleanup. The Task resource is active in source/fhir.ini, so source/task/task-notes.xml feeds the current build.

Additional context:
The current Task.status definition remains required-bound to http://hl7.org/fhir/ValueSet/task-status. The TaskStatus code system includes draft and requested but no created code. OO Confluence minutes in April/May 2024 list FHIR-19489 with Task-specific tickets to make the Status and State Machine text consistent; no Zulip discussion or conflicting community evidence for FHIR-19489 was found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/task/task-notes.xml already says "Tasks start in a Draft state" and lists "Draft, Ready, In Progress" as non-terminal states, and a source-wide check found no remaining "Created state" wording for Task.

Recommendation:
Keep this no-change audit commit as-is. Any broader work on the Task state progression or related Task scope guidance should be handled under its own Jira issue rather than reopening this narrow terminology correction.
