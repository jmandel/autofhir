FHIR-6229: Audit extension definition readability

Issue request:
FHIR-6229 was a Published/Persuasive DSTU1 FHIR-core change request for FHIR-core-profiles. It reported that generated extension definition pages were hard to read because structural Extension.extension, url, and value[x] details obscured the extension's actual content; the requested improvement was a simplified StructureDefinition view that hid that clutter, and the comments also called out confusion around value[x] cardinality 0..0.

Initial application:
The issue was explicitly applied in git-svn commit aad6eb145955408c7ef55a8cd8f99ebf232c1e49, "#6229 - improve extension rendering", matching Jira's svn revision 5965. That commit changed source/template-extension.html from one Structure tab to separate Summary and Full Structure tabs, passed false/true flags through the <%extension-table%> renderer, and updated ProfileUtilities/PageProcessor so the simplified extension table could omit leaf-only structural rows while retaining the full view. The reporter then confirmed the JSON and XML were easier to read and filed the distinct FHIR-8485 follow-up for a missing XML comment terminator.

Additional context:
Current source keeps this historical model: tools/templates/template-extension.html still has separate Summary and Full Structure tabs plus XML, JSON, and All views, and source/fhir.ini still has active extension/profile spreadsheet inputs and an extensiondefinition work group entry. The active Defining Extensions page is listed in source/hierarchy.xml and now explains the specific value[x] cardinality pattern, including use of 0..0 for nested extensions. Many current HL7 extension pages are rendered from the separate FHIR Extension Pack, whose current rendered extension pages provide a Text Summary plus separate differential/snapshot and pseudo-format views, so the old single cluttered extension table is not the current publication pattern. Related extension-rendering/layout issues such as FHIR-5901, FHIR-6832, FHIR-8470, FHIR-8194, and FHIR-7759 are already represented on the combined branch or concern separate current-build ownership questions. Zulip and Confluence searches found no FHIR-6229-specific or conflicting later community decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source and publication pattern already preserve the approved readability fix, and adding more local prose or template churn would be optional presentation work rather than a necessary correction to the current FHIR specification.

Recommendation:
Keep this no-change audit commit as-is. If a future reviewer finds a concrete current extension page with unreadable rendering, handle it as a new publisher/template or Extension Pack issue with a reproducible page, not as a retroactive core source edit for FHIR-6229.
