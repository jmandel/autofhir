FHIR-7371: Audit narrative-only List guidance

Issue request:
FHIR-7371 was Published with resolution Not Persuasive with Modification. It asked to clarify that narrative-only content should use List only when humans would still regard the content as a list, and not for non-list narrative such as Chief Complaint or Hospital Course.

Initial application:
No Jira-tagged source commit for FHIR-7371 was found. The challenged List wording was already present from the earlier #5289 collection-type clarification, and Jira comments say the issue became redundant after other Composition changes while a wiki page about document profiling was created.

Additional context:
FHIR-7372 is the paired Scope and Usage comment and explicitly defers to this issue. Current active source now states that narrative-only document sections are represented with Composition.section.text and no Composition.section.entry, while Composition notes and the Documents guide define document attestation/presentation through Composition and section narratives rather than List.text. List remains a valid flat collection resource, including when a genuine list has no structured entries.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current build already reflects the final Composition-based resolution, and adding another List warning would duplicate or overstate current guidance because narrative-only List instances remain valid for genuine collections.

Recommendation:
Keep this audit as-is. Future work should only be considered if a new work-group decision changes the boundary between narrative-only Composition sections, narrative-only domain resources, and narrative-only List collections.
