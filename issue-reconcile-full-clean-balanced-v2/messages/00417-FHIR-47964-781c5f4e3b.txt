FHIR-47964: Confirm ImagingSelection derivedFrom cardinality

Issue request:
FHIR-47964 is an Applied/Persuasive FHIR-core ImagingSelection change request from the II work group. It asks, based on FHIR-45034, to update ImagingSelection.derivedFrom so the definition remains "The imaging study from which the imaging selection is made," the short display remains "The imaging study from which the imaging selection is derived," and the cardinality changes from 0..* to 0..1.

Initial application:
No source commit explicitly mentioning FHIR-47964 was found for ImagingSelection. The Jira comment says the change was applied as part of FHIR-45034 in PR 3221, and commit 3f26655a0d9c9b69dc90dba10dc5a89ed7f8c2fa changed source/imagingselection/structuredefinition-ImagingSelection.xml so ImagingSelection.derivedFrom moved from max="*" to max="1".

Additional context:
ImagingSelection is in current build scope through active source/fhir.ini entries for the resource, work group, and approval status. FHIR-45034 is the same change family and records the broader studyUid/derivedFrom clarification. FHIR-48101 later revised related ImagingSelection requirements and invariants without reversing the derivedFrom 0..1 cardinality. Confluence evidence from the 2024 O&O WGM also records the rationale that a single ImagingSelection can reference only one ImagingStudy and that imagingSelection.derivedFrom should be 0..1.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build source already has ImagingSelection.derivedFrom with min="0", max="1", the requested short and definition, and the expected ImagingStudy and DocumentReference target profiles.
