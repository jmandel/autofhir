FHIR-17012: Remove CI spec zip download link

Issue request:
FHIR-17012 was a Published/Persuasive FHIR-core index issue from the STU3 ballot. It reported that the downloaded specification package's index page did not match the online index, and the accepted resolution was to stop producing the downloadable build output automatically, build it manually for publication, and have no download from build.fhir.org.

Initial application:
The issue was applied in SVN revision 14430, imported as git commit e426fc3d2ef25df3cbfee90247aea5fee984f8fd, which removed the Publisher.produceZip path and changed source/downloads.html so fhir-spec.zip was text marked as not downloadable from build.fhir.org. The producer removal is still present, but a later untagged broken-link cleanup commit reintroduced an active downloads.html link to fhir-spec.zip without restoring build generation.

Additional context:
The current CI page at build.fhir.org/downloads.html exposes the fhir-spec.zip link while build.fhir.org/fhir-spec.zip returns 404. Published release sites can still host a manually prepared fhir-spec.zip, as R5 does, so this reconciliation is limited to the CI/build source downloads page and does not change release packaging or license wording. No direct Zulip or Confluence record was found that changed the Jira/source conclusion.

AutoFHIR reconciliation:
Restored the no-link wording in source/downloads.html and kept the note that the whole-specification ZIP is not downloadable from build.fhir.org. This source page is part of the current documentation surface and is linked from source/documentation.html, so the hunk removes a currently rendered broken CI link while preserving the manual-publication model approved for FHIR-17012.

Recommendation:
Keep this source change. Future formal publications can continue to add or host a manually prepared fhir-spec.zip as a publication step, but the current build source should not advertise an automatically generated CI ZIP unless generation is deliberately restored.
