FHIR-7472: Audit profiling terminology binding cleanup

Issue request:
FHIR-7472 was a Published/Persuasive vocab change request against the DSTU1 Profiling FHIR page section "Mixing Custom and Standard Terminologies". It asked that the old table using undefined "Binding Type" and profile properties such as conformance/extensible be redone or deleted because the specification had moved to defined Binding Strength terminology.

Initial application:
The issue was applied in git-svn commit 8a6bcabb3f3dc245fd0bba10b90dcde5e5abecde, whose message cites #7472 and svn revision 5708. That commit changed source/profiling.html by replacing the old Binding Type/Profile Properties table with a Binding Strength table using required, extensible, preferred, and example terminology and by linking the binding terminology section.

Additional context:
FHIR-6180 is the same change family and was later resolved as already done by another task. FHIR-7801 subsequently added the neighboring table that explains allowed binding-strength changes in derived profiles. The current source/profiling.html page remains active narrative source for profiling.html and is linked from current documentation/module pages. The current source/terminologies.html page defines terminology bindings and binding strengths, including the Binding Strengths section linked near the profiling binding definitions. Zulip and Confluence searches for FHIR-7472 and the key section/terminology terms found no conflicting community record.

AutoFHIR reconciliation:
This audit commit makes no source change. The current profiling source no longer contains the obsolete Binding Type/Profile Properties wording challenged by FHIR-7472, and the table now uses current Binding Strength terms with nearby terminology links, so another edit would be redundant rather than a necessary current-spec correction.

Recommendation:
Keep this audit commit as-is. Future work on newer binding-strength values or profile override rules should be handled under the Jira issues that introduced those later concepts, not as a reapplication of this DSTU1 cleanup.
