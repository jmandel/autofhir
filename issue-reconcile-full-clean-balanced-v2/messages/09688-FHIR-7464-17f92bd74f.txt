FHIR-7464: Audit Patient compartment URL casing

Issue request:
FHIR-7464 was a Published FHIR-core change request from the 2015May/DSTU1 ballot asking whether compartment search examples should use lowercase `/patient` or uppercase `/Patient`. The accepted resolution was Persuasive with Modification: use uppercase `/Patient` in all cases, remove stale lowercase examples, and remove the old compartment URI presentation that added no value.

Initial application:
The Jira comment records svn revision 5671. In git history this is commit ac324ca8a1a86de1d9990a1288aff1720fc0ab6a, `#7464 - compartment documentation improvements`, which changed the search example from `GET [base]/patient/[id]/[ResourceType]` to `GET [base]/Patient/[id]/[ResourceType]`, capitalized nearby `/patient` search examples, moved `extras.html` to `compartments.html`, and removed the compartment URI column from the compartment list.

Additional context:
CompartmentDefinition is an active current resource in `source/fhir.ini`, so `source/compartmentdefinition/compartmentdefinition-notes.xml` and `source/compartments.xml` are in current build scope. Current source uses uppercase `/Patient` in the compartment-qualified URL examples and no current source search found `GET [base]/patient` or `[base]/patient` endpoint examples. The current rendered Patient compartment page still shows a `Formal URI`, but that is the required `CompartmentDefinition.url` canonical metadata for the modern artifact, not the old lowercase endpoint path ambiguity that FHIR-7464 corrected.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already reflects the accepted URL-casing rule, and removing modern canonical CompartmentDefinition URL metadata would be broader than the Jira request and would conflict with the current CompartmentDefinition model.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for FHIR-7464 unless a future work group decision specifically changes how CompartmentDefinition canonical URLs are displayed.
