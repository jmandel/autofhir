FHIR-26902: Remove MessageEvent value set references

Issue request:
FHIR-26902 is Published/Persuasive with Modification. It reported that the MessageEvent code system and value set were empty but normative, and the accepted resolution was to delete the resource value set and code system, make the MessageHeader/MessageDefinition binding example/descriptive, and remove references to the code system and value set.

Initial application:
No explicit FHIR-26902-tagged source commit was found. The later 40e792c208 "try #2" change partially pursued the event-code cleanup but reintroduced source/messageheader/valueset-message-events.xml and changed MessageHeader.event[x] back to http://hl7.org/fhir/ValueSet/message-events. A subsequent FHIR-43807 edit improved the MessageHeader.event[x] definition to say the element is intentionally unbound, but the active MessageHeader and MessageDefinition bindings, terminology spreadsheet reference, OID entry, and MessageHeader notes still exposed the core MessageEvent value set.

Additional context:
FHIR-32398 is the seed issue and was resolved by reference to this issue after an incorrect duplicate-link removal. Duplicate FHIR-34080 records the same work-group intent for both MessageHeader and MessageDefinition: replace the confusing empty value set/code system with descriptive bindings. source/fhir.ini actively includes both messageheader and messagedefinition resources, so their StructureDefinition and resource-page source files are current-build inputs; example.org message-event systems in examples are local example systems and were intentionally left unchanged.

AutoFHIR reconciliation:
Removed the checked-in MessageEvent value set source, removed the canonical ValueSet/message-events references from MessageHeader.event[x] and MessageDefinition.event[x], changed the binding descriptions to state that FHIR does not define message event codes and that V2 event codes are only examples, updated MessageDefinition.event[x] and MessageHeader notes to match, removed the current-core OID mapping for the deleted value set, and blanked the terminology spreadsheet reference that had pointed at #message-events.

Recommendation:
Keep this source fix. Do not reintroduce a core MessageEvent value set or code system unless InM later defines real standardized message event codes; implementation guides and local implementations should define their own event codes or cite external examples where useful.
