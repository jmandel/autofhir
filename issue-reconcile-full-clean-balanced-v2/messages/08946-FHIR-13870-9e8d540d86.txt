FHIR-13870: Audit contained-resource narrative allowance

Issue request:
FHIR-13870 was a Published/Persuasive with Modification FHIR-core FHIR-I change request for STU3. It said DomainResource invariant dom-1 prevented narrative-only contained resources and requested dropping that invariant while adding guidance that relevant information about contained resources must appear in the containing resource's narrative because contained-resource narratives are ignored when rendering the containing resource.

Initial application:
The issue was applied in SVN/Git history by a18a11e219deb516933a73c8edf8f8a460f45051 (GF#13870 - allow contained resource narrative), which removed the References page bullet saying contained resources SHALL NOT contain any narrative and added the current rule that contained resources can contain narrative, but their narrative is ignored when rendering the containing resource and relevant information SHALL appear in the containing resource narrative.

Additional context:
DomainResource is an active abstract infrastructure resource in source/fhir.ini, and current DomainResource constraints include dom-2, dom-3, dom-4, dom-5, and dom-6 with no dom-1 narrative prohibition. The root References page still contains the requested contained-resource rendering rule. Later same-family issues FHIR-17802 and FHIR-18483 are already represented on the combined branch and removed or audited stale textual leftovers from the old no-contained-narrative rule, so this seed should not duplicate those source changes.
