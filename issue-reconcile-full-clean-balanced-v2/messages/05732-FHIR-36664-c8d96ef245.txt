FHIR-36664: Map NutritionOrder supporting information

Issue request:
FHIR-36664 was Published as Persuasive with Modification for R5 by OO. It asked for NutritionOrder to implement additional Request pattern elements, with the final scope adding basedOn, priority, supportingInfo, performer, and an enteralFormula delivery-device performer element; it left replaces, groupIdentifier, statusReason, doNotPerform, insurance, reason, occurrence, and requested food delivery for later consideration or extensions.

Initial application:
Git commit 5beeee0cf095be40008c2e3de9b20629668b1290 applied the core R5 source changes by adding NutritionOrder.basedOn, NutritionOrder.priority, NutritionOrder.supportingInformation, NutritionOrder.performer, and NutritionOrder.enteralFormula.deliveryDevice. Later source refactors preserved these elements, and FHIR-43447's applied commit 420cc15cd2ae94a67e86a8378118c1e00cfdfdfc added a missing workflow mapping for NutritionOrder.performer while making other workflow-alignment changes. The current source still had the supportingInformation element but did not map that root element to Request.supportingInfo.

Additional context:
source/fhir.ini actively includes nutritionorder=NutritionOrder, so source/nutritionorder/structuredefinition-NutritionOrder.xml and its mapping exception file are current build inputs. FHIR-37965 separately resolved the groupIdentifier item that FHIR-36664 had deferred, and that issue is already represented on the combined branch. FHIR-43447 later re-reviewed NutritionOrder against the Request pattern, kept the deferred no-use-case elements out of the resource, and is also already represented on the combined branch. Confluence WGM minutes from 2022-05-09/13 match the Jira scope by proposing at least performer/device, priority, and supportingInfo.

AutoFHIR reconciliation:
This commit completes the remaining FHIR-36664 source gap by adding the workflow mapping from NutritionOrder.supportingInformation to Request.supportingInfo, adding the matching Request-pattern mapping exception, and suppressing the expected name-difference workflow warning for the intentionally named NutritionOrder.supportingInformation element. It does not rename the element or add deferred elements because later decisions either handled them separately or confirmed no current use case.

Recommendation:
Keep this fixed commit. The authoritative NutritionOrder source now has the requested supporting-information element connected to the Request pattern, while future work for deferred elements should remain with the later targeted issues such as FHIR-37965 or any new work-group decision.
