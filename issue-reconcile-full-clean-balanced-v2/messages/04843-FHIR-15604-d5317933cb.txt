FHIR-15604: Audit ConceptMap dependsOn text support

Issue request:
FHIR-15604 was a Published/Persuasive STU3 Vocabulary change request for ConceptMap. It asked to rename ConceptMap.group.element.target.dependsOn.code to ConceptMap.group.element.target.dependsOn.value and define that value as the identity, code, path, element, item, ValueSet, or text that the map depends on, so uncoded textual mapping dependencies such as LIVD vendor descriptions could be represented.

Initial application:
The issue was pre-applied as svn 13289, now git commit 6d19edc3d4af224136214ed97d4137d56841f757, which changed ConceptMap dependsOn/product example and spreadsheet source from code to value. The current source no longer has an active ConceptMap.group.element.target.dependsOn.code element; the remaining fhir.ini occurrence is an R3 rename map from the old path to the applied value path.

Additional context:
ConceptMap is an active resource in source/fhir.ini. Later R5 work refactored the applied value element to ConceptMap.group.element.target.dependsOn.value[x] and added richer typing, including string and valueSet support. FHIR-32541, FHIR-40504, and FHIR-33032 were later ConceptMap dependsOn/property/type decisions already represented on the combined branch; none reverse the FHIR-15604 text-value capability.

AutoFHIR reconciliation:
No source change was made. The active ConceptMap StructureDefinition already has dependsOn.value[x] with string among its allowed types, and the $translate dependsOn.value output parameter also allows string. This preserves the uncoded textual dependency capability requested by FHIR-15604 without adding redundant prose or editing generated diagram artifacts.

Recommendation:
Keep this no-change audit commit. Future ConceptMap edits should preserve string/text support on dependsOn/product values unless the Vocabulary/TI work group explicitly decides to narrow that model.
