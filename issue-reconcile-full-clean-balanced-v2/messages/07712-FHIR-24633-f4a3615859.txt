FHIR-24633: Audit logical model type fix

Issue request:
FHIR-24633 was a Published/Persuasive FHIR-core change request reporting that R4 internal logical model StructureDefinitions such as Event and Request were missing the mandatory StructureDefinition.type element.

Initial application:
The Jira comment points to GH#128a73e5f5, and git history shows commit 128a73e5f544becd04f9fc295caa535a1b5571fe, "GF#24633 - fix broken logical model SDs", adding generator assignments for logical-model StructureDefinition.type. The relevant current source is generator-fed: source/fhir.ini lists event and request as active logical models, and their spreadsheets define root rows typed as Logical.

Additional context:
The original Zulip discussion records Richard Kavanagh identifying missing type in R4 event.json and request.json, after which Grahame Grieve put it on the technical-correction list. Current build output at build.fhir.org/event.json and build.fhir.org/request.json has kind=logical and type=Event/Request, and the current R4 published artifacts also now expose those type values. The old Java ProfileGenerator path that carried the direct 2019 fix is no longer present in the current checkout, so there is no remaining in-repo generator hunk to reapply.

AutoFHIR reconciliation:
This commit intentionally makes no source change because the active logical-model inputs are in build scope and the generated current and corrected R4 artifacts already contain the mandatory StructureDefinition.type values requested by the issue.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed in core unless a future build regression removes StructureDefinition.type from generated logical model StructureDefinitions.
