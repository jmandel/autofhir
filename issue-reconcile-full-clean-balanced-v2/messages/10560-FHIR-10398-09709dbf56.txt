FHIR-10398: Audit Observation not-performed handling

Issue request:
FHIR-10398 was a Published/Not Persuasive with Modification OO change request from DSTU2 asking for Observation extensions to support structured negation in Observation.code and Observation.value. The final resolution rejected the extensions, removed the earlier extension work, and added "not performed" to the Observation value/DataAbsentReason pathway.

Initial application:
The first implementation added observation-notPerformed and observation-valueNotObserved extensions. The later application commit cc69fb64602bcb037eeb72c394b43becade6faa9 removed those extensions and the procedure-not-performed value set from the Observation extension spreadsheet, with the commit message stating that not-performed was added to the Observation value absent reason value set.

Additional context:
The current build no longer has Observation notPerformed/valueNotObserved extensions, while the current THO data-absent-reason code system and R6 expansion include not-performed. The linked 2016 Zulip discussion shows the rationale: represent a blood glucose test that was not done using Observation.dataAbsentReason and add a sensible "test not performed" concept. FHIR-5629 established the CodeableConcept/extensible dataAbsentReason shape that makes this representation possible, and later FHIR-7150/FHIR-41322 guidance is already represented on the combined branch.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because the rejected extensions are absent from current Observation source and the not-performed concept is already present in the current DataAbsentReason terminology used by Observation.

Recommendation:
Keep this audit commit as-is. If more detailed laboratory rejection or specimen-condition reasons are desired, they should be handled by separate OO/terminology work rather than reopening the extension approach rejected by FHIR-10398.
