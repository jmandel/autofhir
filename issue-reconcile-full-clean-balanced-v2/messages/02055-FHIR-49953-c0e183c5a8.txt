FHIR-49953: Audit vital signs code placement

Issue request:
FHIR-49953 was an Applied/Persuasive OO issue for R6 arguing that the Vital Signs profiles needed to move the profile-specific identifying codes back to Observation.code instead of Observation.category. The Jira resolution says the request was handled by FHIR-45617 and had been pre-applied.

Initial application:
No source commit explicitly named FHIR-49953. The linked Applied FHIR-45617 Jira records commit 66a80b5fef2c43d4a46709f2a03b6d933063cb08 as the application point; that commit moved the Vital Signs "interoperability standard" LOINC code requirement back from Observation.category to Observation.code and removed the observation-vitalsign-category value set. A later combined-branch reconciliation commit for FHIR-50705, 77306523b255399153f826a0253a64b14382d3eb, fixed stale source-backed summaries and examples that still implied the rejected category model.

Additional context:
FHIR-45617 supplies the final supporting decision: OO did not believe changing from code to category was justified, but wanted guidance that the standard profile code can be accompanied by a more detailed coding when available. FHIR-50705 is the same change family and is already represented on the combined branch. FHIR-49961 is related background on generic-vs-specific code inference but remains unresolved and was not decided here. Confluence references and the Zulip thread found during this reconciliation show this was discussed as the same vital-signs category/code decision and did not reveal a conflicting final decision.

AutoFHIR reconciliation:
This is an empty no-change audit commit. Current source already matches the FHIR-49953 request: source/fhir.ini lists Observation as an active resource; the Vital Signs implementation guide includes the affected profiles; the base Vital Signs profile fixes only the broad observation-category#vital-signs classifier in Observation.category; the base and specific Vital Signs profiles bind or pattern the identifying LOINC codes on Observation.code; examples place LOINC vital-sign codes in Observation.code; no LOINC-coded Observation.category blocks or observation-vitalsign-category value set remain under source/observation.

Recommendation:
Keep this audit commit as-is. Do not move the specific vital-sign LOINC identifiers back into Observation.category. Any future work on generic-code inference should remain under FHIR-49961 or another dedicated safety/guidance tracker rather than reopening this applied category/code decision.
