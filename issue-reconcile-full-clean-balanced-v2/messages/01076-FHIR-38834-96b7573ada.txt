FHIR-38834: Clarify CodeSystem designation wording

Issue request:
FHIR-38834 was Applied/Persuasive for FHIR-core CodeSystem. It asked that the CodeSystem.concept.designation comment stop describing the display as an implied designation.use of "primary code" and instead use "primary designation" to avoid implying that designations can carry alternative concept codes.

Initial application:
The formal CodeSystem.concept.designation StructureDefinition comment was updated in git commit 39f96b21ce8d65b5b086b3ee61a455e47a359a98 to use "primary designation". That commit did not mention FHIR-38834 in its subject, but it made the Jira-requested change in source/codesystem/structuredefinition-CodeSystem.xml.

Additional context:
CodeSystem is an active resource in source/fhir.ini, so source/codesystem/codesystem-notes.xml feeds the current CodeSystem narrative. The same terminology wording family also appears in older FHIR-18575/FHIR-18637 and in the later open FHIR-51614 discussion, but FHIR-51614 asks for broader translation guidance and is not decided here.

AutoFHIR reconciliation:
This commit changes the active CodeSystem narrative from "primary code/designation" to "primary designation" so the built CodeSystem page no longer preserves the confusing "code" wording that FHIR-38834 was accepted to remove.

Recommendation:
Keep this source fix. It completes the FHIR-38834 clarification for the current CodeSystem page while leaving broader, unresolved translation-designation guidance such as FHIR-51614 for work-group review.
