FHIR-13595: Audit primitive type ontology hierarchy

Issue request:
FHIR-13595 was a Published/Persuasive FHIR-core datatypes issue from STU3 asking that the actual primitive types in fhir.ttl, such as string, uri, and date, have a primitive supertype instead of standing outside the ontology hierarchy.

Initial application:
The issue appears to have been applied by historical commit 99d996178dbd5412f38eaf881928cbec99441533, whose subject explicitly names issues 13594 and 13595 and whose RDF generator change added primitive type generation with each primitive class created under the Primitive superclass. Jira later recorded the FHIR-I vote and a "already done" application comment before publication.

Additional context:
The current build no longer exposes the old FhirTurtleGenerator source in this checkout, and the RDF representation has been refactored since STU3. Current build-scope datatype source defines PrimitiveType as the active parent type for datatypes with a simple value, and the current fhir.ttl output uses fhir:PrimitiveType as the primitive supertype. Sampled current ontology output from build.fhir.org shows fhir:Boolean, fhir:String, fhir:Uri, fhir:Date, fhir:DateTime, and fhir:Integer each have rdfs:subClassOf fhir:PrimitiveType. The RDF narrative also warns that OWL/Turtle class and property names may be refactored, so the current PrimitiveType spelling is compatible with the original Primitive-supertype request.

AutoFHIR reconciliation:
No source change was made. The current generated ontology already supplies a primitive supertype for the primitive classes, and the active datatype source supports that hierarchy.

Recommendation:
Keep this audit commit as-is. No FHIR source follow-up is needed for FHIR-13595 unless a future RDF generator refactor removes the fhir:PrimitiveType superclass relationship from generated primitive classes.
