FHIR-22749: Audit Location near-distance wording

Issue request:
FHIR-22749 was a Published/Persuasive Patient Administration change request for the Location near search parameter. It asked to remove the trailing sentence "Requires the near-distance parameter to be provided also" because near-distance no longer exists as a separate R4+ parameter after Location near became a special parameter carrying distance in the same value.

Initial application:
The issue was applied in commit eef7df40667d772031a1f7bd313612d0d91e4398, which removed the stale near-distance requirement sentence from source/location/bundle-Location-search-params.xml. Current git history does not show another FHIR-22749 application beyond that commit.

Additional context:
FHIR-14216/GF#14216 is the earlier same-change-family decision that merged near-distance into the Location near parameter, and the 2018 implementers Zulip thread records the editor's note that near-distance would disappear because it was merged into the single parameter. Later same-description updates for FHIR-27157 and FHIR-33976 clarified unit handling and sorting/distance behavior without reintroducing the stale near-distance requirement. source/fhir.ini lists location=Location, so the Location source folder and its search-parameter bundle are in current build scope.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current Location near SearchParameter description in source/location/bundle-Location-search-params.xml describes [latitude]|[longitude]|[distance]|[units], has type special, and no longer contains the Jira-reported near-distance sentence. The only current source mention of near-distance is explanatory narrative in source/location/location-notes.xml saying it was deprecated; remaining exact stale wording hits are under tools/history release archives rather than current build source.

Recommendation:
Keep this no-change audit as-is. No further core FHIR source edit is needed for FHIR-22749 unless a future issue reopens Location near semantics more broadly.
