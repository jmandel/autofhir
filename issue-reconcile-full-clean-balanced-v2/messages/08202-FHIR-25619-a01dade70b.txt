FHIR-25619: Audit primitive ShEx datatype fix

Issue request:
FHIR-25619 was Published/Persuasive for R5 and reported that generated ShEx for FHIR primitive types was recursively using primitive shapes for primitive values, for example integer using fhir:value @<integer>, when the value should be constrained by the relevant XML Schema datatype.

Initial application:
No HL7/fhir source commit explicitly tagged FHIR-25619 was found, and this checkout does not track the Java ShEx generator or generated primitive ShEx source files. The historical generated R4/R4B ShEx surfaces show the problem: integer was represented with fhir:value pointing at a FHIRPath/integer primitive shape. R5 and current generated ShEx now use the RDF primitive literal property fhir:v with concrete XSD datatypes, e.g. integer as xsd:int with the 32-bit FHIR integer range.

Additional context:
FHIR-I minutes for 2020-11-02 record FHIR-25619 as a technical correction, auto-approved. The current build path runs the Kindling publisher from build.gradle.kts, and source/rdf.html documents that primitive values are RDF literals carried by fhir:v. Related already-published reconciliation commits FHIR-25620, FHIR-25621, and FHIR-25622 cover neighboring ShEx link, packaging, and integer64 RDF/ShEx concerns; none require re-opening the primitive datatype fix here. The current generated output uses capitalized R6 shape names such as <Integer>, but the semantic fix remains the same.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The current R5/current generated ShEx surfaces already satisfy the issue intent by avoiding recursive primitive fhir:value shapes for primitive values and using XSD datatype constraints on fhir:v instead. Changing current integer ShEx to bare xsd:integer would be weaker than the current xsd:int plus min/max range semantics for FHIR integer.

Recommendation:
Keep this audit as-is. If future generated ShEx regresses to recursive primitive value shapes, fix the external Kindling/org.hl7.fhir.core ShEx generator used by the build rather than adding redundant prose or editing generated artifacts in this checkout.
