FHIR-18237: Confirm ActivityDefinition path rules

Issue request:
FHIR-18237 was Published/Persuasive for the CDS work group and asked that ActivityDefinition.dynamicValue.path clarify path resolution rules by using the same rule family as DataRequirement path elements, without importing DataRequirement's result-type restrictions.

Initial application:
The issue was applied in historical commit 66795a305d9328c8429b94d078be48a68321c218, which updated the then-authoritative ActivityDefinition spreadsheet to require a FHIRPath resolvable on the target type, limited to identifiers, constant indexers, and a restricted subset of functions. Later source migration preserved that wording in structuredefinition-ActivityDefinition.xml, and commit 60e98c41f6c5fab597bbdb8d7ec41898ca4ec777 corrected the spelling of "resolvable".

Additional context:
ActivityDefinition is active in source/fhir.ini. The current ActivityDefinition.dynamicValue.path definition now states the requested path-resolution requirements and links to the Simple FHIRPath profile; the DataRequirement path definitions use the same pattern plus their own result-type restrictions. A broader pre-existing Simple FHIRPath page location-list gap affects multiple elements that reference fhirpath.html#simple, so a seed-specific edit to that list would be incomplete and is not needed to preserve this Jira's applied rule. Zulip and Confluence searches found no directly relevant conflicting community evidence.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source files were edited because the current build-scope ActivityDefinition source already conveys the requested path-resolution rule.

Recommendation:
Keep this audit commit as-is for FHIR-18237. If the work group wants the Simple FHIRPath page's location list synchronized with every current fhirpath.html#simple reference, handle that as a separate broader cleanup rather than reopening this applied ActivityDefinition issue.
