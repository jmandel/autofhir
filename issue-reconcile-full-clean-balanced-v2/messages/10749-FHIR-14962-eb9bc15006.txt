FHIR-14962: Audit Questionnaire nested constraints

Issue request:
FHIR-14962 was a Published/Persuasive FHIR-core issue for STU3 Questionnaire and QuestionnaireResponse. It reported that constraints on Questionnaire.item and QuestionnaireResponse.item appeared to apply only to first-level items even though they should apply to nested groups and questions too, and the accepted resolution was to correct the tooling using repeat() / descendant item paths.

Initial application:
The issue was applied in the historical source by git-svn commit 3b483e96923e67c5be3bd98447b285b06a66f24f, "GF#14962 - fix generated schematrons," which changed the old SchematronGenerator to emit a descendant path when an element recurses to itself. That matches the Jira comment citing SVN revision 14842 as the generated-schematron fix. The remaining Jira comments characterize the issue as tooling/rendering/validation behavior, not a requested change to the Questionnaire business rules.

Additional context:
Questionnaire and QuestionnaireResponse are active current-build resources in source/fhir.ini. The old tools/java SchematronGenerator path edited for FHIR-14962 is absent from the current checkout after later build refactoring, and the current resource definitions are StructureDefinition XML sources rather than the old spreadsheets/generator inputs. Current Questionnaire.item and QuestionnaireResponse.item are recursive through contentReference entries, so constraints declared on those item ElementDefinitions apply to nested items. Current cross-tree Questionnaire constraints already use recursive FHIRPath where needed, including Questionnaire que-2 using repeat(item).linkId.isDistinct() and the later enableWhen existence check using %resource.repeat(item).linkId. Current Questionnaire and QuestionnaireResponse source contains no live XPath or checked-in schematron path such as f:Questionnaire/f:item that would need the historical // fix.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The historical schematron generator defect was applied before publication, and the current source representation either encodes recursive item constraints directly through contentReference or uses repeat(item) FHIRPath for whole-questionnaire traversal. There is no current build-scope source hunk that would improve implementer understanding or conformance behavior for FHIR-14962.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed unless the current build reintroduces checked-in schematron/XPath generation or a concrete current rendering/validator defect shows nested Questionnaire.item or QuestionnaireResponse.item constraints being skipped.
