FHIR-11492: Audit workflow module revamp

Issue request:
FHIR-11492 was Published/Persuasive with Modification for the DSTU2 workflow page. It asked to revamp the workflow module by distinguishing managed and unmanaged workflow patterns, adding patterns and examples, documenting exception handling for unmanaged workflows, and clarifying that a Request resource describes the intended activity but is not by itself an actionable demand without an actionable tag or Task-based workflow.

Initial application:
The issue was applied in source history by GForge-tagged commits. Later workflow commits refined the same area, including cancellation and exception-handling notes.

Additional context:
The current workflow pages are active build inputs via source/hierarchy.xml and the module index. The current source uses the terms "Ad-Hoc Workflow Patterns" and "Workflow Management Patterns" rather than the Jira resolution's exact "unmanaged" and "managed" labels, but the distinction is the same: no-Task/ad-hoc approaches are separated from Task-managed approaches. The current Request pattern text and Request logical-model notes also clarify that Request resources authorize or describe intended activity while fulfillment state and active execution are handled through Event and/or Task resources. Community searches found no Zulip or Confluence discussion that changes the Jira/source conclusion.
