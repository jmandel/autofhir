FHIR-34399: Audit core extension root cardinalities

Issue request:
FHIR-34399 was Published with a Persuasive with Modification resolution for R5. It asked that core extensions not define a root minimum cardinality above zero; the accepted modification was to warn, rather than error, if an extension definition root has min != 0.

Initial application:
The issue was applied in upstream commit 72c352b6b3296389275a7f4c71b5e57666bd8e29, which changed the known non-zero core extension roots for cqm-ValidityPeriod, messageheader-response-request, and the general language extension from 1..1 to 0..1. A later source refactor, dd468d4f1799dd79819315b211588ef1cf4586e0, removed many R5 extension definitions from the core source tree as part of the Extension Pack move.

Additional context:
The linked Zulip thread confirms the problem was first noticed because the common messageheader-response-request extension had root cardinality 1..1, making it impossible for profiles to include the extension optionally. Current source/fhir.ini still lists active core extension spreadsheet/profile inputs, and the affected extension definitions now present in the FHIR Extension Pack also carry root min=0. No Confluence references for FHIR-34399 were found.

AutoFHIR reconciliation:
This audit made no source change. A scan of current core Extension StructureDefinitions found no Extension root with min other than 0, a scan of active core extension spreadsheet/profile inputs found no non-zero root cardinality literals, and a read-only scan of the Extension Pack found no Extension root with min other than 0. The remaining warning-policy wording in the Jira resolution is build tooling behavior, and no current FHIR source correction is needed to make the specification content correct.

Recommendation:
Keep this no-change audit commit. If the work group wants to verify or strengthen generic warning enforcement, that should be handled in the publisher/build-tooling or Extension Pack QA workflow rather than by changing current core specification source.
