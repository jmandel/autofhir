FHIR-34467: Audit removed SearchParameter spatial modes

Issue request:
FHIR-34467 was Published/Persuasive for R5 SearchParameter. It asked to drop the nearby and distance usage modes because their generic semantics were unclear and appeared to require special search behavior that could not be automated.

Initial application:
PR 1964 and commit 1a0b67ee41 applied the issue by removing nearby and distance from source/searchparameter/codesystem-search-xpath-usage.xml. Commit b6ff86dc86 then updated SearchParameter.xpathUsage short text from normal | phonetic | nearby | distance | other to normal | phonetic | other.

Additional context:
SearchParameter is active and approved in source/fhir.ini. Later source refactors renamed SearchParameter.xpathUsage to SearchParameter.processingMode and renamed the terminology from search-xpath-usage to search-processingmode, preserving the already-trimmed code set. FHIR-35974 is the same change family; it was already represented on the combined branch and confirms keeping other while removing the unsupported spatial modes.

AutoFHIR reconciliation:
This commit intentionally makes no source changes. The current source/searchparameter/codesystem-search-processingmode.xml contains only normal, phonetic, and other; source/searchparameter/structuredefinition-SearchParameter.xml advertises processingMode as normal | phonetic | other with a required binding to ValueSet/search-processingmode; and a targeted source search found no remaining nearby/distance processing-mode concepts.

Recommendation:
Keep this audit commit as-is. The current core source already reflects the final FHIR-34467 decision, and no follow-up core edit is needed unless a future work-group decision changes the retained other processing mode.
