FHIR-13800: Audit claim type value set rename

Issue request:
FHIR-13800 was Published/Persuasive for STU3 FM terminology valuesets. It asked to remove "Example" from the Claim Type value set name because Claim and ExplanationOfBenefit had extensible bindings; its resolution says the work was done through tracker FHIR-13751.

Initial application:
The rename was applied before this reconciliation by git commit 49ee52b963abadc71e75fff3c1f5e31e86d25d30, "Tracker #13751 related", which changed the value set name from "Example Claim Type Codes" to "Claim Type Codes", changed the description away from a sample/example set, and changed the included system from the old ex-claimtype URL to claim-type. Later terminology metadata refactors converted the current source to name ClaimTypeCodes, title Claim Type Codes, and the THO claim-type code system URL without reintroducing the old example name.

Additional context:
FHIR-13751 is the directly related Published/Persuasive follow-up to FHIR-13614 and records the broader decision to use the Claim Type codes as extensible in Claim, ClaimResponse, and ExplanationOfBenefit, with the non-example value set description and claim-type URL. The current fhir.ini keeps Claim, ClaimResponse, and ExplanationOfBenefit active, and their type bindings are extensible to http://hl7.org/fhir/ValueSet/claim-type. A source-wide search found no remaining "Example Claim Type" wording; the only legacy ex-claimtype URL hits are not the value-set name itself and are in an XML-commented Communication placeholder and a disabled ProcessRequest file.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because the current build-relevant source already satisfies the requested rename: source/claim/valueset-claim-type.xml has name ClaimTypeCodes, title Claim Type Codes, and description "This value set includes Claim Type codes." while the relevant FM resource bindings are extensible and point to the claim-type value set.

Recommendation:
Keep this audit commit as-is. Any future cleanup of commented example fragments or disabled ProcessRequest leftovers should be considered under a targeted maintenance issue, not as a remaining FHIR-13800 requirement.
