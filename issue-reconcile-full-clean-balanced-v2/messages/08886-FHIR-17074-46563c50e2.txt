FHIR-17074: Audit Bundle entry request history wording

Issue request:
FHIR-17074 was a Published/Persuasive FHIR-core Feed change request for STU3 asking that the Bundle.entry.request definition no longer describe only transaction processing. The approved correction was to add that, for history, entry.request shows how the entry was processed to create the version contained in the entry.

Initial application:
The Jira application comment records svn revision 14399. No current Git commit is keyed with FHIR-17074, but the current Git history shows the history sentence already present when Bundle was carried into the XML StructureDefinition source during the 2021 source rework/R4B commits, and current blame shows later formatting/invariant work preserved the same definition.

Additional context:
Bundle is an active resource in source/fhir.ini, so source/bundle/structuredefinition-Bundle.xml is build-scope source. The current Bundle.entry.request short explicitly names transaction/batch/history, and the definition includes the requested history sentence. Nearby final Jira issues FHIR-13644 and FHIR-34388 concern Bundle.entry.request.method/PATCH history details, not this parent definition, and do not require changing the FHIR-17074 wording. Zulip and Confluence searches found no direct FHIR-17074 reference or conflicting work-group record.

AutoFHIR reconciliation:
This audit makes no source change because the authoritative current source already conveys the requested history semantics for Bundle.entry.request.

Recommendation:
Keep this no-change audit commit as-is. Future work on method-specific history behavior should be handled through the separate method/PATCH issues rather than by changing the already-correct parent definition.
