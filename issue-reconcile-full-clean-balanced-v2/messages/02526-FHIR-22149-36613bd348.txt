FHIR-22149: Audit Procedure performer actor targets

Issue request:
Published/Persuasive Patient Care issue FHIR-22149 asked that Procedure.performer.actor add support for CareTeam and HealthcareService because those are more specific performer representations than Organization.

Initial application:
The issue was applied by GF#22149 commit 810548665c, merged by PR #581 as 1c5e1bd4e5, which changed the then-authoritative Procedure spreadsheet target type from Reference(Practitioner|PractitionerRole|Organization|Patient|RelatedPerson|Device) to include CareTeam and HealthcareService and updated the actor wording. The later source refactor preserved that application in source/procedure/structuredefinition-Procedure.xml with a GF#22149 committee note.

Additional context:
Procedure is active in the current build through source/fhir.ini. Current source/procedure/structuredefinition-Procedure.xml lists both CareTeam and HealthcareService target profiles for Procedure.performer.actor. The 2019-05-30 Patient Care minutes and Jira comment record that Patient Care agreed to both types; the Event pattern still lacks HealthcareService, but source/procedure/procedure-event-mapping-exceptions.xml explicitly records Procedure.performer.actor as having HealthcareService as an extra type, so that pattern divergence is represented rather than a missing Procedure fix. Focused Jira, Zulip, and Confluence searches found no later decision reversing the Procedure target profiles.

AutoFHIR reconciliation:
This commit intentionally makes no source change because the current build-scoped Procedure StructureDefinition already implements FHIR-22149 exactly: Procedure.performer.actor allows CareTeam and HealthcareService.

Recommendation:
Keep this no-change audit commit. No core source follow-up is needed for FHIR-22149; any broader Event pattern policy question should be handled under its own tracker rather than by changing the already-correct Procedure definition.
