FHIR-13838: Audit performer-function value set alignment

Issue request:
FHIR-13838 is a Published/Persuasive Orders and Observations change request raised against STU3 Observation. It said the event-performerRole extension description described participation functions such as responsible party, author, or verifier, while the example value set was oriented toward performer roles, and the accepted resolution was to keep the description and update the value set to align with it.

Initial application:
The Jira discussion records that the editor pre-applied changes after community review. Git history has an explicit GF#13838 implementation commit, 29d523c8173d2ffd355d5606e88092c6917df0f5, which added the active core ValueSet http://hl7.org/fhir/ValueSet/performer-function and registered it in source/fhir.ini. The later profiles-directory commit ce006e8d156e66af655182e3a4e0cfcd4e666e59 introduced the event performerFunction extension source row with the same author/verifier/responsible-party definition and an extensible binding to that performer-function value set.

Additional context:
The linked Zulip thread confirms the intended distinction: function is what the performer did, while role is what hat or license they held; Michelle Miller confirmed the need was author/verifier style participation for Observation.performer. Current FHIR core no longer carries the event-performerRole extension as an active source artifact; current core keeps the performer-function value set in active build scope, while the current extension definition lives in the FHIR Extension Pack as event-performerFunction and binds to the core performer-function value set. FHIR-12638 is related background on Event performer-role binding strength and is already represented on the combined branch.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current active core value set includes participation-function concepts such as AUT, VRF, and RESP, matching the retained description, and the current Extension Pack event-performerFunction definition binds to that value set rather than the old role/title-oriented performer-role value set.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-13838; any future changes to the extension definition itself should be made in the FHIR Extension Pack, but the inspected current extension-pack source already matches the Jira decision.
