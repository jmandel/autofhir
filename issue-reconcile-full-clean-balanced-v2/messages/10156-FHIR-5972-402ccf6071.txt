FHIR-5972: Audit flag character encoding fix

Issue request:
FHIR-5972 was a Published/Persuasive FHIR-core change request from DSTU1 reporting mojibake/strange characters in the Flag column of generated structure views on a Windows local build.

Initial application:
The Jira comments identify the cause as a local Java code-page/encoding problem and say it was fixed in SVN revision 5447. The corresponding git-svn commit is e9a5c6012a8360d509be847ff3c7a77e6da955f7, "#3063 - code generation schemas fixes #5972 - character set issues", with git-svn-id build@5447; it changed several old Java generator/publisher writers from platform-default encoding to UTF-8. Those old Java publisher files are no longer present in the current FHIR source tree.

Additional context:
The current build is Gradle-based and invokes org.hl7.fhir:kindling rather than the old checked-in publisher sources; git history shows the switch to the Gradle build with Kindling dependency removed the old Publisher.java in 2021. The active build configuration sets -Dfile.encoding=UTF8, the shared generated-page header declares text/html; charset=utf-8, and source/formats.html still contains the intended flag glyphs such as Sigma in UTF-8. A later same-symptom FHIR-ips Jira, FHIR-16150, records that the issue was no longer present in its current build and is outside this FHIR-core reconciliation scope. No Zulip or Confluence evidence was found that changes the Jira/source/history conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The historical source fix was already applied, and the current build no longer carries the vulnerable checked-in Java publisher code; the current active source and templates already preserve and declare UTF-8 for pages that display the flag glyphs.

Recommendation:
Keep this audit commit as-is. Revisit only if a future local build produces mojibake in generated structure-table flags despite the current Gradle/Kindling UTF-8 configuration, in which case the fix would belong in the active Kindling publisher/tooling rather than the removed DSTU1-era Java files.
