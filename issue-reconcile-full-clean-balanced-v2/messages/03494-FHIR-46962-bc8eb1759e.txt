FHIR-46962: Audit corrected Device status narrative

Issue request:
FHIR-46962 is an Applied/Persuasive OO technical correction for R6 Device. It reported that the Device status narrative used the wrong element names: operationalStatus and associationStatus no longer existed in Device, availabilityStatus was missing, and Devices.status had a typo.

Initial application:
The issue was applied by git commit 82f2fd681e3cbeb85ca5302593dc1a45784edae6, which changed source/device/device-notes.xml from "Devices.status is about the record, while operationalStatus and associationStatus are about other aspects of the device" to "Device.status is about the record, while .availabilityStatus is about the device itself." Later source-only formatting commits changed the heading level and wrapped the element names in code tags without reverting the FHIR-46962 meaning.

Additional context:
The stale sentence originated in the broader Published FHIR-32557 Device status work, which clarified that Device.status is record status and added Device.availabilityStatus for the device itself. In the current build scope, source/fhir.ini actively lists device=Device, and the active Device notes source now names Device.status and .availabilityStatus only. Targeted Zulip and Confluence searches found no direct FHIR-46962 discussion or conflicting community decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already fixes the typo, removes the obsolete operationalStatus and associationStatus references from the Device status narrative, and includes availabilityStatus in the active Device notes source on the combined branch.

Recommendation:
Keep this empty audit commit as-is. No further core FHIR source work is needed for FHIR-46962 unless a future OO decision changes the Device status model again.
