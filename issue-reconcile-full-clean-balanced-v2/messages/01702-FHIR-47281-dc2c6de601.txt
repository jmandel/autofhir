FHIR-47281: Audit subscription server actor clarification

Issue request:
FHIR-47281 was an Applied FHIR-core R6 subscriptions issue with resolution Not Persuasive with Modification. The reporter said the Subscriptions Framework definition of Server as a "FHIR application" was vague and suggested "FHIR server" unless out-of-band notification-only services were supported; the accepted resolution instead clarified that subscription functionality need not be part of the same application or service that exposes a FHIR REST API.

Initial application:
The issue was already applied in source by commit 48703074e9d25cda8fb6304808769fe4a10a3b1a, "FHIR-47281 - subscription server actor clarification," which changed source/subscriptions.html to add the approved example phrase and a note about architectures that separate subscription notification services from a FHIR Server. The Jira comment points to HL7/fhir#3967, which was merged after collecting R6 ticket commits.

Additional context:
source/subscriptions.html is in current build scope through source/hierarchy.xml, which lists subscriptions.html under the Exchange module. FHIR-I minutes for 2025-03-31 record the R6 Subscriptions block vote including FHIR-47281 and the 17-0-0 motion to approve. A Zulip search found only the block-vote announcement for this issue family and no separate conflicting rationale.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Subscriptions Framework text already says Server may be a FHIR Server or a monitoring system converting internal events into FHIR notifications, and the adjacent note already says subscription implementations are not required to expose a FHIR REST API themselves.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-47281 unless the work group later changes the architectural scope of out-of-band subscription notification services.
