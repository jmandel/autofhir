FHIR-19632: Audit HL7 IG quality enforcement scope

Issue request:
FHIR-19632 was Published/Persuasive for R5 and asked that the IG Publisher be invokable in a mode that enforces HL7 implementation guide requirements, including warnings for publisher and publisher.contact being present. The decisive Jira comment says the old task predated current arrangements and that HL7 rules are enforced now.

Initial application:
No HL7/fhir source commit mentioning FHIR-19632 was found. The related predecessor FHIR-19012 records the underlying policy decision: HL7 IGs should use ImplementationGuide.publisher for "HL7 International - <workgroup name>" and ImplementationGuide.contact for the work group homepage, and those expectations were added to the HL7 IG guide quality criteria with FHIR-19632 filed to have IG Publisher enforce them.

Additional context:
Current Confluence policy/guidance now states that all FHIR implementation guides SHALL declare publisher and contact in the ImplementationGuide instance and that HL7-published IGs shall use the HL7 work group publisher/contact form. The FHIR IG Quality Criteria page explains that QA errors and warnings are found in qa.html and that the IG Publisher applies significant validation. ImplementationGuide is active in this build, but the base resource remains generally reusable: publisher and contact are optional metadata elements, with publisher guidance saying the item SHOULD be populated unless context supplies it. The current core checkout does not contain IG Publisher implementation code, and the active publisher source is the external HL7/fhir-ig-publisher repository.

AutoFHIR reconciliation:
This empty audit commit makes no FHIR core source change and records an external-repo decision. Changing the base ImplementationGuide cardinalities or adding HL7-specific conformance rules to the core StructureDefinition would overstate a publication/tooling policy that applies to HL7 IG publication workflows, not to every ImplementationGuide instance in FHIR. Any remaining enforcement behavior belongs in IG Publisher tooling or publication guidance outside this checkout.

Recommendation:
Keep this audit commit as-is for the core reconciliation. If a concrete HL7 IG quality rule is still missing or regressions are found, track that work in HL7/fhir-ig-publisher or the FHIR Confluence publication requirements rather than changing the core ImplementationGuide definition.
