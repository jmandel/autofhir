FHIR-13521: Audit DataAbsentReason declined code

Issue request:
FHIR-13521 is a Published/Persuasive FHIR-core STU3 OO change request asking to add a declined response reason to the Data Absent Reason value set. The final resolution renamed asked to asked-unknown, added asked-declined with definition "The source was asked but declined to answer.", renamed temp to temp-unknown, and placed asked-unknown, asked-declined, temp-unknown, and not-asked under unknown.

Initial application:
The issue was pre-applied in historical commit e7d78b64cb2a41fcce79fa37fdad6ce089167b12, which changed source/terminologies/bindings.xml to add asked-declined and the requested code renames/hierarchy, and deleted the older data-absent-reason CSV. Follow-up commit d06b52856c89401a981241a811faa7b455037c08 adjusted the Data Absent Reason display/name metadata as part of GF#13521/GF#15567 cleanup.

Additional context:
Current core no longer maintains the DataAbsentReason CodeSystem inline; the build-scoped source/terminologies/valueset-data-absent-reason.xml defines the FHIR ValueSet as all codes from http://terminology.hl7.org/CodeSystem/data-absent-reason, and source/terminologies/bindings.xml still references valueset-data-absent-reason for the active DataAbsentReason binding. THO 7.1.0 CodeSystem-data-absent-reason.json has 15 recursive concepts and includes asked-unknown, temp-unknown, not-asked, and asked-declined as children of unknown with the requested definitions. FHIR-15567 is the closely related DAR cleanup and is already represented on the combined branch; FHIR-39238 later reused the existing asked-declined code for a Gender Harmony value set rather than changing DataAbsentReason itself.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core source delegates the value set to the external THO code system, and the current THO code system already contains the requested asked-declined code and related hierarchy. Re-adding local core CodeSystem content or duplicating concepts in the ValueSet source would conflict with the current terminology ownership model.

Recommendation:
Keep this audit commit as-is. No FHIR-core source change is needed for FHIR-13521; if future validation finds a missing code, the follow-up should be against THO, not by redefining DataAbsentReason in core.
