FHIR-31569: Align ChargeItemDefinition applicability ModelInfo

Issue request:
FHIR-31569 was a Published/Persuasive Patient Administration change request for R5 asking to rationalize ChargeItemDefinition.applicability by replacing the old description/language/expression backbone detail with the Expression data type.

Initial application:
Jira records that this change was incorporated into FHIR-31521. Commit 082ba11f51 applied the combined ChargeItemDefinition change to the R5 StructureDefinition and examples, replacing applicability.description/language/expression with applicability.condition of type Expression in source/chargeitemdefinition/structuredefinition-ChargeItemDefinition.xml.

Additional context:
FHIR-31521 kept applicability as a backbone so it could also carry effectivePeriod and relatedArtifact. ChargeItemDefinition was later removed from active core resource build inputs by commit 71567db3ee and moved to the HL7 Administrative Incubator IG, whose current source and CI JSON already carry applicability.condition as Expression. The active core Library/FHIR-ModelInfo example remained stale and still exposed ChargeItemDefinition.Applicability.description, language, and expression as strings.

AutoFHIR reconciliation:
Updated the build-scope ModelInfo content source for Library/FHIR-ModelInfo, replacing the stale ChargeItemDefinition.Applicability string children with condition as FHIR.Expression. This keeps the current core Library example aligned with the applied R5 decision and the external Administrative Incubator source without reintroducing the removed core resource.

Recommendation:
Keep this commit. Future structural maintenance of ChargeItemDefinition itself should happen in HL7/admin-incubator; current core only needed the active ModelInfo example corrected where it still surfaced the old applicability shape.
