FHIR-18280: Audit jurisdiction ValueSet expansion

Issue request:
FHIR-18280 was a Published/Persuasive FHIR-I issue raised against STU3 and applied for STU3. It reported that the Jurisdiction ValueSet no longer expanded and the rendered page failed with "Unable to provide support for code system urn:iso:std:iso:3166:-2"; the recorded resolution was to add support before normative publication and the Jira comment says it was fixed.

Initial application:
No source commit explicitly mentioning FHIR-18280 was found. The issue was filed after the historical jurisdiction ValueSet source had added ISO 3166 Part 2 subdivision codes, so it appears to have been applied through terminology-server/publication tooling rather than a Jira-tagged source hunk. Historical source retained urn:iso:std:iso:3166:-2 in source/terminologies/valueset-jurisdiction.xml until that deprecated core artifact was removed in later source cleanup.

Additional context:
Same-family issues FHIR-14695 and FHIR-20375 reported jurisdiction expansion failures and are already represented on the combined branch by no-change audit commits. FHIR-31537 later resolved no-change because the current build expanded the Jurisdiction ValueSet successfully. UP-521 then created http://terminology.hl7.org/ValueSet/jurisdiction in THO with the same CLD after the core R5 value set was deprecated. Current core source no longer contains source/terminologies/valueset-jurisdiction.xml; active source bindings point to the THO Jurisdiction ValueSet, and R5/THO rendered pages show expansion content without the reported error.

AutoFHIR reconciliation:
Made no source changes. The current FHIR core source is already correct for FHIR-18280: the old broken core expansion page is not current build-scoped source, authoritative core bindings use the THO Jurisdiction ValueSet, and checked publication surfaces expand rather than returning the ISO 3166-2 support error.

Recommendation:
Keep this empty audit commit. No FHIR core source follow-up is recommended for FHIR-18280. If a future Jurisdiction ValueSet expansion problem recurs, handle it in THO/UTG or terminology publication tooling rather than by reintroducing the deprecated core value set.
