FHIR-7539: Audit obsolete PATCH future note

Issue request:
FHIR-7539 was a Published/Persuasive FHIR-core HTTP change request from the DSTU1 ballot cycle. It asked to add a note that PATCH was likely to be defined in a future version and that implementer experimentation and input would be welcome.

Initial application:
The issue was applied in git commit aa30e32cba4407e39c1acf0d22b2f2126982a93f, whose subject was "#7539 - add note about PATCH". That commit added a DSTU note to source/http.html under update saying HTTP PATCH functionality was likely to be defined and feedback was welcome. A later 2015 formatting commit corrected the typo from "liekely" to "likely" but retained the same note.

Additional context:
The current source no longer needs a future-looking DSTU note. The later Published/Persuasive FHIR-10655 decision documented PATCH as tested in connectathons, and git commit b1842341d2ae96d6f06a92d3a4ca3cd363c75f15 removed the FHIR-7539 note while adding the PATCH interaction to source/http.html. Current source/http.html is the active RESTful API source page and now lists patch and conditional patch among the RESTful interactions, defines the HTTP PATCH request, accepted patch body formats, conditional patch behavior, narrative safety guidance, and batch/transaction patch guidance. Current CapabilityStatement source also has patchFormat and conditionalPatch support. A related PATCH summary-row audit, FHIR-16046, is already represented on the combined branch, so this commit does not duplicate it.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Reintroducing a note that PATCH is likely to be defined would be stale and misleading because the current specification already defines PATCH in the authoritative HTTP page and related conformance artifacts.

Recommendation:
Keep this audit commit as-is. Do not re-add the DSTU future-PATCH note; any remaining detailed PATCH cleanup should be handled by the specific later PATCH tracker, not by FHIR-7539.
