FHIR-13715: Correct EventDefinition module link

Issue request:
FHIR-13715 was a Published/Persuasive FHIR-core change request, raised for STU3, to create an EventDefinition resource so event definitions could be reused by subscriptions, plan definitions, and similar artifacts. The Jira resolution says the change was accepted and pre-applied, with SVN revisions 12177, 12253, 12254, and 12259 recorded by the reporter.

Initial application:
The resource was already present in source history before the Jira issue was marked Published. Git history shows f08b464764 adding the draft EventDefinition resource, examples, introduction, fhir.ini registration, and TriggerDefinition source updates on 2017-06-29, followed by July 2017 EventDefinition clarification commits. Current source still has EventDefinition as an active resource and uses TriggerDefinition for EventDefinition.trigger.

Additional context:
Adjacent STU3 TriggerDefinition issues FHIR-13716 and FHIR-13717 cover the event-prefix rename and data-changed trigger support, and both already have separate reconciliation commits on the combined branch. Later R6 decisions briefly deprecated EventDefinition in favor of SubscriptionTopic (FHIR-41372) and then undeprecated it (FHIR-53316), with FHIR-53414 adding examples and refining trigger guidance. Those later decisions mean the correct current state is an active EventDefinition resource with a clear relationship to TriggerDefinition and SubscriptionTopic, not removal or replacement.

AutoFHIR reconciliation:
This commit keeps the existing EventDefinition resource and TriggerDefinition model intact, and corrects the active Clinical Reasoning module index so its EventDefinition row links to eventdefinition.html instead of evidence.html. The edited source page is part of the current build through publish.ini and source module navigation, and the hunk is necessary because the visible index label named EventDefinition but sent readers to the Evidence resource.

Recommendation:
Keep this commit as-is. The original resource creation and TriggerDefinition expansion remain correctly represented in current source, and this reconciliation only fixes a stale module link that undermined EventDefinition discoverability. No follow-up core source work is recommended for FHIR-13715.
