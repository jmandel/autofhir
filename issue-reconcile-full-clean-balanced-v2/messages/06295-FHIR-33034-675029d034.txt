FHIR-33034: Audit Device install date element

Issue request:
FHIR-33034 is a Published/Persuasive R5 Orders and Observations change request asking Device to support software installation date. The accepted resolution was to add Device.version.installDate, cardinality 0..1, type dateTime, defined as the date the version was installed on the device; the Jira description specifically called out software such as EHR/LIS systems and v2-to-FHIR SFT-6.

Initial application:
The change was applied in the FHIR source before this reconciliation. Commit 02cef27091958585a7c26a4fdbdc72194f56637f added Device.version.installDate to source/device/structuredefinition-Device.xml, commit ba098c8fb964b281ca63245b27704270e1690a94 refined the short text, and merge commit 393ccc2f172ce4819a4a4ccd5e964909f7a83e38 brought PR #1572 into the source.

Additional context:
The current Device resource is active in source/fhir.ini. A later Applied rename, FHIR-40488, changed the Device version backbone from Device.version to Device.deviceVersion in commit d0ee6976b376257bf44fc840b43b79b6f1c9487d; the current fhir.ini R5-to-R6 mapping explicitly maps Device.version.installDate to Device.deviceVersion.installDate. FHIR-40488 is already represented on the combined branch by commit 7b93d9f60ad22f8d23ba5e6b1a89ed1a84fb792b, so this audit does not decide that issue again. Confluence minutes show FHIR-33034 in the OO/HCP block-vote trail and later v2-to-FHIR SFT mapping follow-up; targeted Zulip searches found no conflicting discussion.

AutoFHIR reconciliation:
Made no source change. The authoritative current Device StructureDefinition already contains Device.deviceVersion.installDate with 0..1 cardinality, dateTime type, and the definition "The date the version was installed on the device." The current source therefore preserves the accepted FHIR-33034 requirement under the later Device.deviceVersion name, and adding duplicate or old-path prose would be misleading.

Recommendation:
Keep this empty audit commit as-is. No follow-up core source work is needed for FHIR-33034 unless a future issue requests additional examples or clarifies separate go-live-versus-install semantics beyond the accepted installed-on-device definition.
