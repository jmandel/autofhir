FHIR-20390: Clarify conditional update Resource.id wording

Issue request:
FHIR-20390 was a Published/Persuasive FHIR-I issue for the RESTful API conditional update section. It asked what "id provided" means in the conditional update decision table, noted ambiguity between the submitted resource's Resource.id and an _id search parameter, and approved changing the bullets to make clear that the id is Resource.id while removing the sentence saying a supplied id is ignored.

Initial application:
No git commit explicitly mentioning FHIR-20390 was found. The same conditional update decision table was introduced earlier by GF#17906 in d69dfafe26d9ad9151c011ef743568a3ab2158fc, the conflicting "server SHALL ignore it" sentence was removed later by FHIR-26688 in f03ddacb16c1befe035bc015be04709ef3cf5560, and FHIR-36859 in e76c0dd6aa055fe1ad4d07c56cee8784707220b0 later split the no-match/id-provided case. The Jira comment saying changes were applied with FHIR-31965 appears to refer to the same 2022 HTTP-page application batch, but the FHIR-31965 commit itself changed conditional create response metadata rather than this Resource.id wording.

Additional context:
The current build-scope source is the core HTTP narrative page source/http.html, listed as http.html in publish.ini and linked by the Jira's FHIR-core-http page. Related issues already represented on the combined branch cover the later no-match/id-existing split (FHIR-36859) and the deletion of the ignore-id sentence (FHIR-26688). The 2019 Zulip continuation of the GF#17906 thread records the exact FHIR-20390 concern: participants were unsure whether "id provided" meant Resource.id or the _id search parameter, and the thread converged on Resource.id plus removal of the ignore-id sentence.

AutoFHIR reconciliation:
This commit updates only source/http.html. It changes the conditional update branch labels from bare "id provided" / "resource id provided" to Resource.id, and clarifies the FHIR-36859 no-match branches as "no resource already exists with that id" versus "a resource already exists with that id". It makes no behavioral change beyond the approved clarification and preserves the existing 409 Conflict, Update as Create, and one-match mismatch outcomes.

Recommendation:
Keep this source fix. It completes the FHIR-20390 Resource.id clarification in the active HTTP page while leaving the already-reconciled FHIR-26688 and FHIR-36859 decisions intact. No additional core source follow-up is needed for this issue unless the work group separately addresses the later 2025 discussion about the one-match response text.
