FHIR-30926: Audit Claim-family tax amount application

Issue request:
FHIR-30926 was a Published/Persuasive with Modification Financial Management issue for R5 asking to add tax amount/type support in Claim, ClaimResponse, and ExplanationOfBenefit. The final resolution narrowed the data shape to `.tax 0..1 Money`, said the tax amount is in addition to the stated cost, and asked that .net handling account for whether tax is included when profiled.

Initial application:
No git commit message found in the current repository history explicitly names FHIR-30926. Commit 75e9d09e28, authored by the same editor who later commented that FHIR-30926 has the same resolution as FHIR-29689, added the Money tax elements to Claim.item/detail/subDetail, ClaimResponse.addItem/detail/subDetail, and ExplanationOfBenefit item/detail/subDetail plus addItem/detail/subDetail. Later FHIR-37594 history clarified the .net elements in these same resources.

Additional context:
FHIR-29689 is the same-change-family issue and records the approved Money-only tax resolution in more detail, including extension/profile handling for jurisdiction-specific tax breakdowns. FHIR-37594 is a later Published/Persuasive clarification that sets the current base .net formula to `unit price * quantity * factor`; the combined branch already contains an AutoFHIR FHIR-37594 source fix for the remaining .net requirements text. The seed's DRG mention does not justify a new diagnosisRelatedGroup tax element because the same-resolution issue and current source application place tax on charge line/addItem structures, while diagnosisRelatedGroup remains a CodeableConcept.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The authoritative current-build StructureDefinition sources already carry the requested `.tax 0..1 Money` elements, the final resolution no longer requires tax type children, and later net wording makes the base tax-exclusive formula explicit without adding redundant profile guidance.

Recommendation:
Keep this commit as-is. If Financial Management wants a future base-level tax type/backbone or diagnosisRelatedGroup-specific tax representation, that should be handled as a new substantive tracker because it would exceed the applied FHIR-30926/FHIR-29689 resolution family.
