FHIR-7540: Audit _elements partial-return support

Issue request:
FHIR-7540 was Published as Persuasive with Modification for DSTU1. It asked for a profile-driven way to request which parts of a resource a server should return, and the final resolution adopted the simpler IHE-style `_elements` parameter: a token/comma-delimited list of base element names, with subsetted resources tagged accordingly.

Initial application:
The local HL7/fhir history contains commit ca544e1cfb16d5154cc1cfa746620817c015c096, `#7540 - _elements parameter`, matching the Jira comment that SVN revision 6176 applied the issue. That commit added the `_elements` section to `source/search.html`, including the example `_elements=identifier,active,link`, base element-name selection, server discretion, mandatory-element return guidance, and SUBSETTED tagging.

Additional context:
FHIR-6234 is the same change family: it requested a `_fields` selector and was resolved by making the `_element`/`_elements` change agreed in FHIR-7540, with the same SVN revision 6176 application note. The current active source is broader than the original 2015 text because later applied decisions refined `_elements`: FHIR-23729 clarified dotted paths and resource-relative interpretation, and FHIR-27054/other later issues refined included-resource behavior and server discretion. `source/hierarchy.xml` lists `http.html` and `search.html` under the RESTful API pages, so these narrative sources are in current build scope. Focused Zulip and Confluence searches found no direct FHIR-7540 record or conflicting community decision.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current `source/search.html` defines `_elements` as a comma-separated list of element names or dotted element paths, includes the Patient example, preserves mandatory/modifier return and SUBSETTED tagging guidance, and lists `_elements` as a token search control parameter. The current `source/http.html` also lists `_elements` as a general REST parameter and applies the subsetted-resource implications to read interactions.

Recommendation:
Keep this no-change audit. FHIR-7540 is already applied in active source, and changing the text back toward the original root-only/base-element wording would undo later applied clarifications rather than improve the current specification.
