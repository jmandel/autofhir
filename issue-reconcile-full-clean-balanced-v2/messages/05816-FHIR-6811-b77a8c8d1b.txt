FHIR-6811: Audit Questionnaire coded answer type

Issue request:
FHIR-6811 was a Published/Persuasive FHIR-core Questionnaire issue raised against DSTU1 Questionnaire.group.question.type asking whether type can represent a code, such as a value picked from a dropdown. The approved resolution said yes: the Choice type allowed coded data, and definitions would be added to all type codes to make this clear.

Initial application:
The Jira comments record application in legacy SVN #5941. In the current git-era source, Questionnaire is an active resource and the item-type value set is actively registered in source/fhir.ini. The migrated Questionnaire item type code system already contained defined question type codes, including the historical choice/open-choice coded-answer definitions, before later R5 cleanup.

Additional context:
FHIR-20396 was later Published/Persuasive with Modification for the same Questionnaire item type family. It intentionally removed choice/open-choice from Questionnaire.item.type, added the coding item type, and moved list/off-list answer behavior into answerConstraint tied to answerOption and answerValueSet. Commit ae142a024a99c23b140a4d007595a8e3f1f06d52 applied that change. Current source therefore should not restore the old choice code wording; it should be judged against the current coding/answerOption/answerValueSet design.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active Questionnaire source already says Questionnaire.item.type captures particular data types including Coding, binds the element to the active item-type-useable value set, defines coding as a question with a Coding generally drawn from possible answers, constrains answerOption/answerValueSet use for coding questions, and narrative guidance explains permitted values through answerOption or answerValueSet.

Recommendation:
Keep this no-change audit commit. A source edit would either duplicate existing guidance or incorrectly reintroduce obsolete choice/open-choice terminology that FHIR-20396 deliberately removed.
