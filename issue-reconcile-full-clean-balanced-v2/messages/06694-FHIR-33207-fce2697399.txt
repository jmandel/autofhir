FHIR-33207: Audit datatype UML definition links

Issue request:
FHIR-33207 was Published/Persuasive for R5 and reported that datatype UML element links, such as ElementDefinition.constraint.expression from the ElementDefinition UML tab, incorrectly targeted datatypes-definitions.html instead of the datatype-specific definitions page such as elementdefinition-definitions.html. The Jira noted that larger datatypes with dedicated pages, including Dosage, appeared to be affected.

Initial application:
No FHIR-core source commit with FHIR-33207 was found because the SVG generator had already moved out of this repository before the issue was filed. The application is in the external HL7 Kindling history: commit b501b047d5cc472e5be99ce938d202c5ff1972cd, "FHIR-33207 Datatype UML links go to wrong page", changed SvgGenerator.baseUrl from hard-coded datatype/resource cases to definitions.getSrcFile(root)+"-definitions.html#" and stopped stripping datatype-relative links. That is the tooling path used by this checkout through the org.hl7.fhir:kindling dependency.

Additional context:
Current source/fhir.ini keeps ElementDefinition and Dosage in the active type list and maps elementdefinition, dosage, dosagedetails, dosagesafety, and dosagecondition to their dedicated pages under [type-pages]. The active ElementDefinition and Dosage narrative pages invoke the datatype renderer through [%dt ...%] includes, and build.gradle.kts/gradle.properties configure the build to use Kindling 1.25.5-SNAPSHOT. The R5 published pages and the current CI build both show SVG xlink targets for ElementDefinition and Dosage UML elements going to the dedicated -definitions pages, with no datatypes-definitions.html targets for those examples. FHIR-17767 is a related earlier datatype-diagram link issue, but it concerned the Element class-title link rather than element-row links.

AutoFHIR reconciliation:
No source files were changed. The current authoritative source plus the external Kindling generator already satisfy the Jira request, and the generated publication surface for both the original ElementDefinition example and the Jira-mentioned Dosage family is correct.

Recommendation:
Keep this no-change audit commit. Revisit only if the core build stops using the fixed Kindling behavior, or if a future regression reintroduces datatypes-definitions.html targets for datatypes that have dedicated definition pages.
