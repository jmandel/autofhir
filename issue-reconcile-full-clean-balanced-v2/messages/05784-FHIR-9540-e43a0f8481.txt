FHIR-9540: Audit ConceptMap element rename

Issue request:
FHIR-9540 was a Published FHIR-core ConceptMap change request, resolved Persuasive with Modification, asking that ConceptMap source and target codeSystem elements be renamed to system and the newly added codeSystemVersion elements be renamed to version for consistency with ValueSet and CodeSystem.

Initial application:
The Jira resolution says the change had already been done. Git history shows commit 7089931fcdcdea92b62c147d3d4966315566c14f, svn revision 7871, renamed ConceptMap example and spreadsheet fields from codeSystem/codeSystemVersion to system/version. The tightly related FHIR-9726 snapshot identifies the same revision and records the subsequent ConceptMap.group reorganization from element-level names to group.source, group.sourceVersion, group.target, and group.targetVersion.

Additional context:
ConceptMap is active in the current build through source/fhir.ini. Current source/conceptmap/structuredefinition-ConceptMap.xml defines ConceptMap.group.source and ConceptMap.group.target as canonical(CodeSystem) elements and no longer contains ConceptMap codeSystem or codeSystemVersion elements. The later Published FHIR-25925 decision intentionally removed group.sourceVersion and group.targetVersion by making group.source and group.target canonical(CodeSystem), so the absence of separate version elements is a later approved design rather than a missed FHIR-9540 application. Zulip and Confluence searches found no directly relevant conflicting community record.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current authoritative ConceptMap source no longer contains the old codeSystem/codeSystemVersion element names, and the later canonical(CodeSystem) refactor explains the current source/target shape.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-9540 unless a future work group decision reopens ConceptMap system/version modeling.
