FHIR-18846: Audit CDS Hooks mapping guidance

Issue request:
FHIR-18846 was a Published/Persuasive STU3 CDS work group change request asking the Clinical Reasoning material to provide clearer mappings between CDS Hooks constructs and FHIR resources, including CDS Hooks request prefetch data to PlanDefinition/DataRequirement inputs and CDS Hooks response content to GuidanceResponse/RequestGroup.

Initial application:
The Jira comment records GH#:20fd62db2d, and git commit 20fd62db2d557dd133bd32041d93ba3f4edbd62b explicitly states "GF#18846: Clarify mapping to CDS Hooks request." That commit added CDS Hooks-to-FHIR mapping guidance to source/clinicalreasoning-cds-on-fhir.html, including hook/service/prefetch mappings to TriggerDefinition, PlanDefinition, and DataRequirement, plus response mappings to GuidanceResponse and RequestGroup. Later source history renamed RequestGroup to RequestOrchestration as part of FHIR-24619.

Additional context:
Current source/fhir.ini and source/hierarchy.xml keep the Clinical Reasoning module and clinicalreasoning-cds-on-fhir.html in build scope. Later Applied issue FHIR-53085 intentionally moved most CDS-on-FHIR page content, the relevant profiles, and the supporting concept maps out of FHIR core into the Using FHIR Clinical Reasoning with CDS Hooks implementation guide, and changed the core page to an informative overview with links to that IG. FHIR-48393 separately removed the CDS Hooks PlanDefinition/RequestOrchestration/GuidanceResponse profiles from the base specification. The current IG source carries the detailed mapping content, including the prefetch/DataRequirement and response/RequestOrchestration tables.

AutoFHIR reconciliation:
This audit commit makes no source change. Re-adding the detailed mapping tables to core would reverse the later FHIR-53085/FHIR-48393 direction and duplicate content now maintained in the dedicated CDS Hooks Clinical Reasoning IG. The current core source still directs implementers to that IG and keeps concise local guidance about using PlanDefinition/$apply and transforming RequestOrchestration to a CDS Hooks response.

Recommendation:
Keep this no-change audit as-is for FHIR-18846. Any future correction to the moved detailed mapping content or the draft IG publication/link target should be handled under FHIR-53085 or a new CDS work group issue, not as a reopening of this STU3 mapping request.
