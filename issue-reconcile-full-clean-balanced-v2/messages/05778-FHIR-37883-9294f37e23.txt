FHIR-37883: Audit _contained clarification

Issue request:
FHIR-37883 was a Published/Persuasive FHIR-I clarification for the core search page. It asked that the _contained parameter text stop saying clients could modify "this behavior" ambiguously, and make clear that _contained controls whether contained resources are included as search result matches, not whether chained conditions are evaluated inside contained resources.

Initial application:
The issue was applied in two explicit source commits on 2022-08-29: cb2679824f changed source/search.html to say clients modify the search behavior for contained resources and to describe _contained values as searching/returning contained resources; 451cc74d06 then expanded the MedicationRequest/Medication examples and added concrete _contained=true examples for returning contained resources or their containers.

Additional context:
The current build source still contains the applied clarification in source/search.html. The section first states the default result behavior and separately states that chained parameters should be evaluated inside contained resources, then the _contained bullets and examples show that _contained=true/_containedType=contained returns the contained Medication and _containedType=container returns the container MedicationRequest. FHIR-I minutes for 2022-08-29 record the same 12-0-0 Persuasive vote. Exact Zulip search found no FHIR-37883 discussion, and no conflicting community evidence was found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active core search page already resolves the ambiguity identified by the issue, and adding more prose would duplicate the existing examples without changing implementer understanding.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-37883 unless the work group later wants to reopen the broader semantics of contained-resource search.
