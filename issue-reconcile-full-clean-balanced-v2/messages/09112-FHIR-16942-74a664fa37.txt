FHIR-16942: Audit datatype URI regex placement

Issue request:
FHIR-16942 was a Published/Persuasive with Modification STU3 datatype issue asking why canonical showed a `\S*` regex while `uri` and `url` did not. The accepted resolution said the regex had ended up in the wrong space and should be sorted out.

Initial application:
The issue was applied by git-svn commit 4d29ade0e4c2d662f2ecbdae89fbfb341293e6aa, corresponding to SVN revision 13853 and titled `GF#16942 - clarify URL regex`. That commit moved the literal `Regex: \S*` row and URI explanatory text out of the canonical block and into the URI block on `source/datatypes.html`.

Additional context:
The current build-scope datatype sources no longer have the original misplaced literal row. `source/datatypes/primitives.xml` defines `\S*` for `uri`, `url`, and `canonical`, and `source/datatypes.html` renders all three via regex tokens. Later Published issue FHIR-37368 explicitly revisited primitive regex page/package alignment and is consistent with keeping these three primitive regexes synchronized. Zulip and Confluence searches found no work-group minutes or community discussion that reverses the Jira/source conclusion; the only directly keyed Zulip hits were tracker/commit bot notifications.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because the current authoritative primitive spreadsheet and datatype page source already convey the no-whitespace regex for `uri`, `url`, and `canonical`, and the later regex-alignment work supports that state.

Recommendation:
Keep this audit commit as-is. Future changes to canonical URL absolute-URI policy or broader primitive regex mechanics should be handled under their own Jira issues rather than by reopening this placement fix.
