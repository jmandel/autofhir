FHIR-34408: Audit symptom observation category external terminology

Issue request:
FHIR-34408 is Applied/Persuasive with Modification for R6. It asked to clarify Observation Category use for signs and symptoms by adding `symptom` to the Observation Category ValueSet with display "Symptom" and the definition "A symptom is a manifestation of a disease apparent to and communicated by the patient," and by updating the `exam` definition to include physical exam findings, direct clinician observations, simple instruments, simple maneuvers, and signs.

Initial application:
No FHIR core source-changing commit mentioning FHIR-34408 was found. The current core source delegates Observation Category code content to external terminology: `source/observation/valueset-observation-category.xml` includes all codes from `http://terminology.hl7.org/CodeSystem/observation-category`, and active `Observation.category` source binds with preferred strength to `http://hl7.org/fhir/ValueSet/observation-category`.

Additional context:
FHIR-37560 is the same Applied symptom category change family and its Jira comments cross-link FHIR-34408. Later Applied issues FHIR-50889 and FHIR-52872 request the same symptom category update and are already represented on the combined branch by external-repo audit commits, as is FHIR-37560. UP-738 is Proposal Implemented for the UTG/THO Observation Category CodeSystem; its rationale cites FHIR-34408, its change object is `input/sourceOfTruth/fhir/codeSystems/CodeSystem-observation-category.xml`, and current THO observation-category version 2.0.0 includes `symptom` plus an editorially refined `exam` definition. OO minutes and Zulip announcements confirm the work group routed these R6 Observation Category updates through the UTG ticket path.

AutoFHIR reconciliation:
This commit intentionally makes no source change in the FHIR core checkout. The requested code and definition updates belong to the external THO/UTG Observation Category CodeSystem, while core already imports that CodeSystem wholesale and uses the importing ValueSet for the active Observation.category binding. The current FHIR build expansion already shows `symptom` from THO.

Recommendation:
Keep this audit commit as-is for FHIR core. Do not duplicate the THO CodeSystem concepts in core source; any remaining follow-up should be handled through THO/UTG release or package-version coordination if the external terminology publication changes.
