FHIR-3713: Audit Procedure location element

Issue request:
FHIR-3713 was a Published Patient Care change request, resolved Persuasive with Modification for DSTU1. It asked Procedure to be able to document the location where a procedure occurred, with examples such as a newborn delivered at home or a tracheostomy at a restaurant.

Initial application:
The issue was explicitly applied in git commit 9c7bb8368a37c9fc77536157561b19965be76867, whose subject is "#3713 - add location to Procedure" and whose git-svn trailer identifies svn revision 4792, matching the Jira comment. That commit added Procedure.location as Reference(Location), with short text "Where the procedure happened" and a definition using the same newborn-at-home and tracheostomy-at-a-restaurant examples.

Additional context:
Procedure is an active current-build resource in source/fhir.ini, and the source has since been refactored from the old spreadsheet to source/procedure/structuredefinition-Procedure.xml. Current source still contains Procedure.location as 0..1 Reference(Location), marks it summary, maps it to FiveWs.where[x], v2 PR1-23, and RIM LOC participation, and defines the element as the location where the procedure actually happened. The related later Published issue FHIR-32508 removed the old requirements rationale tying location to where records are kept; that issue is already represented on the combined branch by commit f991cc2e4b50c3b5d71e07032fb9a69175acb340, so this seed audit does not duplicate it.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change because the current authoritative Procedure source already contains the requested location element and the current wording correctly reflects later clarification that Procedure.location is where the procedure happened, not where records are stored.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-3713; future changes to Procedure.location semantics should be handled under a new or existing later Patient Care decision rather than by reopening this DSTU1 addition.
