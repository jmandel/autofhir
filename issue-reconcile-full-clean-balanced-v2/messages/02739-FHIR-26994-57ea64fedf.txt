FHIR-26994: Audit RelatedPerson relationship directionality

Issue request:
FHIR-26994 was a Published/Persuasive FHIR-core RelatedPerson change request from PA asking to clarify the directionality of RelatedPerson.relationship. The approved resolution required the short description to identify the relationship of the related person to the patient, the definition to name the relationship between the related person and patient, and a comment saying directionality is from RelatedPerson to Patient with PRN/MTH examples.

Initial application:
The issue was directly applied by commit 3b17466cd4311c8b261c00e1796fe76c1f303784, which added the approved short, definition, and explicit directionality comment. Commit 47ecaaf91a5ec157f4b45c3e094e11a966b26ed1 immediately removed a trailing period from the short description because it caused a build error. These commits updated the active RelatedPerson StructureDefinition source.

Additional context:
FHIR-19411 is an earlier Published/Persuasive tracker asking the same directionality question and was first applied in commit 1188130b6c17ef475c055f86a5eb12a1a77f3525. The September 2021 PA minutes record the FHIR-26994 motion, vote, and exact resolution text. A January 2021 Zulip thread shows implementer confusion over the same directionality and ends by pointing to FHIR-26994. FHIR-15841 later split RelatedPerson.relationship into personal relationship semantics and RelatedPerson.role for functional roles, preserving the FHIR-26994 directionality comment. FHIR-29929 is related to that role/relationship split and already has a combined-branch reconciliation commit.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. source/fhir.ini lists relatedperson as an active resource, and current source/relatedperson/structuredefinition-RelatedPerson.xml already contains the requested directionality in the active element definition/comment.

Recommendation:
Keep this audit as-is. The current source should not be changed merely to match older wording exactly; the later personal/functional split gives useful context while retaining the approved RelatedPerson-to-Patient directionality.
