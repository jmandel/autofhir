FHIR-3438: Audit search not-equal support

Issue request:
FHIR-3438 was a Published/Persuasive FHIR-core search issue asking for not-equal search capability, with the 2014 resolution to add != for numerical and date parameters and token modifiers/examples such as Patient?gender:not=male, :below, :above, and :in.

Initial application:
The historical application is visible in git commit a93fdda85e381e382444be8a937ef654a0a8d016, a git-svn import of SVN revision 3240, which added not-equal prefix prose and token modifier descriptions to source/search.html for #3438. A later applied search issue, FHIR-7957, changed comparison prefixes away from URL-problematic operators such as != to the two-letter prefixes used by _filter, so the current syntax is ne rather than literal !=.

Additional context:
source/search.html is an active built page listed in publish.ini, and SearchParameter is an active resource in source/fhir.ini. Later issues refined the same area without reversing FHIR-3438: FHIR-10479 and FHIR-32074 clarified that Patient?gender:not=male includes patients with no gender code, FHIR-36646 clarified that prefix tests such as ne only test present values while :not can include missing token values, and FHIR-40629 added the current warning for or-joined :not values. FHIR-54853 is still Triaged and may further refine :not with comma-separated values, but it is not a final decision that changes the current reconciliation.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/search.html already defines the token :not modifier with Patient?gender:not=male and Composition?section:not=48765-2 examples, defines the ne prefix and number/date/quantity prefix behavior, and the current search comparator and modifier code systems include ne and not/not-in/above/below/in codes.

Recommendation:
Keep this empty audit commit as-is. Future work, if any, belongs under active follow-up issues such as FHIR-54853 rather than FHIR-3438, because the seed issue's requested not-equal functionality is present in the current build using the later standardized ne spelling.
