FHIR-15913: Audit MeasureReport reporter Group exclusion

Issue request:
FHIR-15913 was a Published/Persuasive STU3 Change Request for FHIR-core MeasureReport. It asked to remove Group from MeasureReport.reporter because a FHIR Group is a collection that can be acted on, not an actor that can report data or take collective responsibility.

Initial application:
The issue was applied in SVN 14046, preserved in git commit e169985949ad77cfed6c6e86ee8036a90f98136e, which removed Group from the MeasureReport.reporter Reference choices in the then-authoritative measurereport-spreadsheet.xml source. The source was later refactored into structuredefinition-MeasureReport.xml. Group was subsequently reintroduced by commit 23790863f5a700c65612543f4cd24f1d7fea2b30 while incorporating DEQM MeasureReport extensions as first-class R5 elements.

Additional context:
Later core issue FHIR-31686 recorded a No Change decision while R5 still allowed Group on reporter, but FHIR-38002 revisited the same conflict and was Applied/Persuasive for R6. FHIR-38002 explicitly connected back to FHIR-15913, concluded that Organization and PractitionerRole can cover the provider-group use cases, and commit c6487923f555ea1723187bdb34ed052de50ae9d6 removed the Group target again. MeasureReport is active in the current build through source/fhir.ini, and the current MeasureReport.reporter source allows only Practitioner, PractitionerRole, and Organization.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative StructureDefinition already implements the seed issue's semantic rule, and nearby operation definitions for measure reporter inputs also describe Practitioner, PractitionerRole, or Organization rather than Group.

Recommendation:
Keep this audit commit as-is. No further core source action is indicated for FHIR-15913; any implementation examples about accountable provider groups should continue to use Organization and PractitionerRole or be handled in the appropriate IG context.
