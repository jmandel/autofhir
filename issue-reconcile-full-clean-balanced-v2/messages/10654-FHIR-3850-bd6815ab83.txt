FHIR-3850: Audit coded binding warnings

Issue request:
FHIR-3850 was a Published/Persuasive DSTU1 FHIR-core change request noting that Provenance.reason was a CodeableConcept with no binding and that the build did not fail for that condition.

Initial application:
The Jira comment records that the build began generating warnings for this condition. Git history confirms that commit 465b04a3a62118caa464d86396fce67add7a69e4 added a ResourceValidator warning for CodeableConcept or Coding elements without a binding on 2015-03-16, and commit 6c026c5064671ebbd76e4679a2e250ea2074e89d later added the ProvenanceReason binding to Provenance.reason with the v3 PurposeOfUse value set.

Additional context:
The old Provenance.reason element is no longer present in the current resource. source/fhir.ini keeps the active Provenance resource in build scope and maps Provenance.reason to Provenance.authorization; the current StructureDefinition defines Provenance.authorization as CodeableConcept with an example ProvenanceReason binding to v3-PurposeOfUse, and Provenance.why carries the free-text reason as markdown. Later history deliberately reduced missing CodeableConcept/Coding binding diagnostics from warning to information because some unbound elements are acceptable, and the current suppressed-messages.txt still shows this diagnostic being emitted.

AutoFHIR reconciliation:
No source change was made. The current source already preserves the applied outcome for the original example and the current build tooling still surfaces unbound CodeableConcept/Coding elements as informational diagnostics.

Recommendation:
Keep this no-change audit commit. Do not reintroduce a hard build failure for unbound CodeableConcept/Coding elements under FHIR-3850; any future severity change should be a new tooling policy decision because later history explicitly allowed informational diagnostics for some cases.
