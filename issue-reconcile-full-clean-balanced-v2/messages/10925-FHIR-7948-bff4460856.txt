FHIR-7948: Align messaging event narrative with local definitions

Issue request:
FHIR-7948 is a Published FHIR-core messaging change request with a Persuasive with Modification resolution. It asked about defining message events through a value set rather than a separate message-definition mechanism; the accepted resolution dropped the built-in list of messaging event codes and the STU note saying additional events could be defined elsewhere, because message events are local or implementation-guide vocabulary bindings.

Initial application:
Git history shows the core application in two steps. daae86217175 removed the STU-note wording "Additional events may be defined elsewhere" from source/messaging.html and replaced it with MessageDefinition guidance. 2b81a477bd4d then removed the rendered Event List, the [%events%] table, and the statement that FHIR defined message event codes, replacing the section with "Defining Events" and text saying the specification does not define any events.

Additional context:
Later FHIR-26902 and duplicate FHIR-34080 addressed the same event-code family by deleting the empty MessageEvent value set/code system and making MessageHeader/MessageDefinition bindings descriptive. That later cleanup is already represented on the combined branch and confirms that core FHIR should not imply a built-in message-event vocabulary. source/fhir.ini actively includes MessageHeader, and source/documentation.html plus source/exchange-module.html link the edited messaging and push/pull narrative pages into current documentation scope.

AutoFHIR reconciliation:
Removed remaining current-source wording that contradicted the FHIR-7948 resolution: MessageHeader notes no longer point readers to a nonexistent event-code list, the messaging/REST comparison no longer says the messaging framework itself defines a notification event, and the push/pull page now says implementations can define message events instead of saying FHIR defines them.

Recommendation:
Keep this source fix. The rendered current spec should continue to say that FHIR defines the messaging framework and MessageDefinition mechanism, while implementations and implementation guides define the actual message events and codes.
