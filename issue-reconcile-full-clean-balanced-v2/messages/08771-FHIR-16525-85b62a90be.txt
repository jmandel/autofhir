FHIR-16525: Audit extension discoverability links

Issue request:
FHIR-16525 was Published/Not Persuasive with Modification for R5. The original request asked to list the standard extensions for each resource directly on each resource Contents page so readers could discover them, but the accepted modification rejected a full content-page extension list and instead called for removing a duplicate extension link while Eric Haas gathered feedback on lighter-weight mockups.

Initial application:
The issue was initially applied in git commit 8a424ffcc6b1cf70bba4af7e5221930a2f6ca51e, "GF#17635 - fix duplicate codes in expansions + improve invariant rendering + GF#16525 - add link to extensions/profiles", which added a resource-page Profiles & Extensions link through the source template and publisher macro rather than embedding extension tables. Jira comments match this history by noting SVN revision 14576 and then clarifying that the implementation had added a duplicate link in a paragraph that already linked extensions.

Additional context:
The follow-up thread named for GF#16525 presented option 2 as "add link to extension below content view" and option 3 as adding a table of extensions to the content page. Feedback warned that a full table could be long and would give extensions nearly equal prominence with core elements. FHIR-20637 later Published/Persuasive adopted option 2 and was already represented on the combined branch. Its application commit 118fa79d000735ef4e115260ea6de72ebac5d728 removed the old leading res-ext-link wording, retitled the post-content paragraph as Additional definitions, and left the concrete resource template's [%ext-link%] hook that renders the resource-specific extension link.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current build-scope source keeps active resources in source/fhir.ini and the concrete resource page template in tools/templates/template.html includes the [%ext-link%] placeholder in the Additional definitions line; current CI rendering for Patient and Observation shows both a resource-specific Extensions navigation link and a "see the extensions" link below resource content. Re-adding a full extension list or the older duplicate Profiles & Extensions prose would conflict with the accepted modification and the later FHIR-20637 option-2 decision.

Recommendation:
Keep this no-change audit commit. Revisit only if concrete resource pages stop rendering the resource-specific extension link, or if the work group makes a new decision to promote standard extensions beyond the lightweight link approach.
