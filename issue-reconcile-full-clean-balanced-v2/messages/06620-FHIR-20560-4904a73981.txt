FHIR-20560: Audit BDP UDI-DI addition

Issue request:
FHIR-20560 is a Published/Persuasive OO change request for FHIR-core BiologicallyDerivedProduct. It asked to add optional BiologicallyDerivedProduct.udiDeviceIdentifier and a distinct identification string, similar to R4 Device.udiDeviceIdentifier, to support UDI and distinct identification requirements for HCT/P products regulated as medical devices.

Initial application:
The issue was applied for R5 before this reconciliation. Commit 18bb2a4bba68248dbacd0dc15f88cd0df2cd5fe8 added BiologicallyDerivedProduct.udiDeviceIdentifier and BiologicallyDerivedProduct.distinctIdentifier to source/biologicallyderivedproduct/structuredefinition-BiologicallyDerivedProduct.xml, and Jira-linked commit cc323ba311bded7d1e17c6d356bc8fdf9b3d1b24 added the UDI mapping metadata in PR #1569.

Additional context:
Two later Published/Persuasive OO correction issues changed the approved R5 outcome. FHIR-35967 said udiDeviceIdentifier had been added or left by accident and should be removed from BDP, including mapping cleanup. FHIR-35968 said distinctIdentifier should be removed because it was meant to be replaced by biologicalSource rather than left as a parallel element. Both later issues are already represented on the combined branch with no-change audit commits. The active current build includes BiologicallyDerivedProduct in source/fhir.ini, and the current StructureDefinition has no BDP udiDeviceIdentifier or distinctIdentifier element.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding either element for FHIR-20560 would contradict the later final OO decisions in FHIR-35967 and FHIR-35968. The authoritative current source has identifier followed by later BDP identifiers such as therapyIdentifier and biologicalSourceEvent, with no BDP-specific udiDeviceIdentifier or distinctIdentifier residue.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for FHIR-20560 unless OO makes a new device/BDP identifier decision that explicitly reintroduces UDI-DI or distinct identification support.
