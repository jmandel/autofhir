FHIR-13504: Restore OperationOutcome entity description example

Issue request:
FHIR-13504 was Published/Not Persuasive with Modification for STU3. The issue asked for a way to record an OperationOutcome on AuditEvent; the accepted resolution did not add a new operationOutcome element, but instead directed the AuditEvent page to describe recording an OperationOutcome as an AuditEvent.entity, likely contained, with a reference and description plus a visible example.

Initial application:
The Jira-tagged commit f36c03dbf2 added the AuditEvent OperationOutcome guidance and the auditevent-example-error example, including a contained OperationOutcome referenced from AuditEvent.entity and an entity.description value. Later AuditEvent model migrations changed the old entity.reference guidance to the current entity.what form, but the example's description was first changed to entity.name and then to entity.what.display, leaving the current example without the entity.description that the remaining notes text still recommends.

Additional context:
AuditEvent is an active resource in source/fhir.ini, so the AuditEvent notes and examples are current build inputs. FHIR-32467 later removed AuditEvent.entity.type as redundant with entity.what, and an existing reconciliation commit has already removed the stale entity.type narrative guidance; this issue should therefore preserve the current entity.what guidance rather than revive entity.type. Direct Zulip and Confluence searches found no FHIR-13504-specific discussion that changes the Jira/source conclusion, while a later Zulip thread repeats the same pattern of putting an OperationOutcome in AuditEvent.entity for persistence with context.

AutoFHIR reconciliation:
This commit updates the active transaction-failure AuditEvent example so the entity that references the contained OperationOutcome also includes entity.description. No StructureDefinition or entity.type change was made because the current model already supports the requested representation through entity.what and entity.description, with entity.type intentionally removed by the later FHIR-32467 decision.

Recommendation:
Keep this commit. It restores the specific example field requested by FHIR-13504 while respecting later AuditEvent model changes; no further core-source work is recommended for this seed.
