FHIR-17918: Audit payee resource removal

Issue request:
FHIR-17918 is a Published/Persuasive FM change request from STU3 asking to remove Claim.payee.resource because the reference/identifier datatype now handles identifying the target payee. The Jira related artifacts list both Claim and ExplanationOfBenefit, so both current payee definitions were checked.

Initial application:
The issue appears to have been applied in historical commit afb5ec66f68641293bb7950b6e0eeb118fa1444a, whose message explicitly lists "17918: Remove payee.resource from Claim as identifier datatype now handles" and whose Claim spreadsheet diff removed Claim.payee.resource and its ClaimPayeeResourceType binding. A closely adjacent FM commit, 89bb47c31d84c7cc3fb753e5408806226f62d395, removed the parallel ExplanationOfBenefit.payee.resource row and PayeeResourceType binding while applying neighboring EOB trackers.

Additional context:
Claim and ExplanationOfBenefit are active resources in source/fhir.ini. The current source definitions for Claim.payee and ExplanationOfBenefit.payee contain payee.type and payee.party, with payee.party typed as Reference to the permitted payee resource types; no payee.resource element remains in either active StructureDefinition. Reference.type and Reference.identifier now carry the resource type and logical identifier information that made the separate payee.resource discriminator unnecessary. FHIR-12919 is useful background because it introduced the older payee.resource name to replace payee.resourceType, but FHIR-17918 is the later published decision that removed that separate element. The only remaining payee resource-type terminology source files are unbound legacy terminology artifacts and disabled ProcessRequest text, not active Claim/EOB element definitions; removing those broader historical artifacts would exceed the specific published issue without a separate terminology decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative current Claim and ExplanationOfBenefit StructureDefinition sources already reflect the published decision: payee.resource is absent and payee.party is the reference element implementers should use.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-17918 unless a future work group decision separately retires or removes the unbound legacy payee resource-type terminology artifacts.
