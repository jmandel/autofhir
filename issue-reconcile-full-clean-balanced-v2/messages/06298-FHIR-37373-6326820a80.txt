FHIR-37373: Audit reference modifier stacking clarification

Issue request:
FHIR-37373 was a Published/Persuasive with Modification FHIR-I R4 clarification request for the Search page. It asked whether a reference type modifier, the reference :identifier modifier, and the token :of-type modifier could be combined in one parameter such as Consent?consenter:Patient:identifier:of-type=...; the accepted resolution pointed to FHIR-20641 and stated that chained/stacked modifiers are not permitted.

Initial application:
The issue was applied by commit fd19eba3ff735b49eb917ed3b722ce8511f8011f, which added the active source/search.html statement that only a single modifier is allowed on a single search parameter. The same application cluster also includes FHIR-20641 commit 1e3b7571675379e59420a5ceaba188bd20bb1012, which added the approved guidance to define a new search parameter or operation when multiple layers of modification are needed.

Additional context:
The seed Zulip thread shows the reporter raised exactly the multi-modifier reference identifier question and was asked to file a change request. FHIR-I minutes from 2022-05-23 record that FHIR-37373 was handled by pointing to FHIR-20641 because modifier chaining is prohibited. Later source changes have refined nearby reference-search wording and the type modifier value-set/example, but they do not relax the single-modifier rule. FHIR-51598 is a later Resolved - change required clarification about chaining before versus after :identifier; it is separate default-run context and does not alter the modifier-stacking decision.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current active Search narrative already states that the type modifier value is a resource type such as subject:Patient, then immediately states that only one modifier is allowed on a single search parameter and directs implementers needing layered behavior to define a new search parameter or operation. That current source answers the seed request by prohibiting consenter:Patient:identifier:of-type-style stacking without adding redundant prose.

Recommendation:
Keep this no-change audit for FHIR-37373. Handle any future wording update for FHIR-51598 separately if and when that resolved-change-required item is applied, because it concerns chaining placement around :identifier rather than the already-published prohibition on stacked modifiers.
