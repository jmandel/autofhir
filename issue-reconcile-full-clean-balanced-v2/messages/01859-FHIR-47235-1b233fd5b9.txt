FHIR-47235: Audit canonical status support guidance

Issue request:
FHIR-47235 was Applied/Persuasive with Modification for R6. It asked to clarify that the active status on canonical resources is the artifact lifecycle status, not a server declaration that the artifact is supported or enabled for use, and to point server support declarations to CapabilityStatement feature declarations.

Initial application:
The issue appears to have been applied by git commit 0fe79c935e6b847a8f6a6aba969a7588a648e597, "FHIR-47235 Active canonical resources and status fields", which changed source/canonicalresource/structuredefinition-CanonicalResource.xml. The current build-scope CanonicalResource.status comment contains the requested warning and CapabilityStatement feature guidance.

Additional context:
source/fhir.ini lists canonicalresource as an active interface and maps MetadataResource.status to CanonicalResource.status. ActivityDefinition, PlanDefinition, Questionnaire, and SubscriptionTopic remain active resources, but the Jira resolution specifically chose the base CanonicalResource.status comment rather than duplicating the warning on each concrete status element. Confluence minutes record the FHIR-I 2024-09-09 persuasive-with-modification vote and WGM notes place FHIR-47235 in the Feature Capability IG discussion, matching the non-core CapabilityStatement feature follow-up. Jira, Zulip, and Confluence searches found no later conflicting decision for this source location.
