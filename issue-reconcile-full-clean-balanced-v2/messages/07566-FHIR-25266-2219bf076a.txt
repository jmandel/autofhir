FHIR-25266: Align StructureMap identifier syntax

Issue request:
FHIR-25266 was Published/Persuasive with Modification for R5. It reported that the FHIR Mapping Language allowed escaped/delimited identifiers even though StructureMap group, rule, and variable-name fields used the id datatype; the approved resolution kept id rules for those map-defined names, excluded target.context because logical model contexts can be URIs, and required the general syntax section to distinguish what can and cannot be delimited.

Initial application:
The Jira-tagged commit 9799fa13cb changed StructureMap.group.rule.target.context from id to string, added the general syntax text prohibiting backticks around map-defined id values, and updated the then-current grammar to use id-like tokens for several names. The current StructureMap source still has the intended id/string split, but a later grammar rewrite (db673c36e8) reintroduced drift by omitting delimited identifiers from rule-path components while allowing delimited identifiers for as-variables and group invocations.

Additional context:
FHIR-23033 is a resolved-no-change predecessor that explicitly points to the FHIR-25266 resolution, and FHIR-25286 separately removed double quotes as an allowed delimiter in favor of backticks. The Mapping Language page is in the current build hierarchy, StructureMap is an active resource in fhir.ini, and publish.ini includes both mapping-language.html and mapping.g4, so the corrected prose and grammar are current build inputs rather than stale generated output.

AutoFHIR reconciliation:
This commit clarifies the general syntax prose so source/target data model path elements may be backtick-delimited, target.context may still be a logical-model URI, and map-defined group, rule, and variable names remain governed by id rules. It also updates images/mapping.g4 so qualified rule-path components can use DELIMITEDIDENTIFIER, while as-variables and group invocations use ID instead of the broader identifier rule.

Recommendation:
Keep this commit as-is. It completes the published FHIR-25266 intent without changing the StructureMap element model; future changes to rule-name quoting or broader FML grammar behavior should be handled as separate mapping-language decisions.
