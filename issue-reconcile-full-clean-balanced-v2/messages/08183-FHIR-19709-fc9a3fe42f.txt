FHIR-19709: Audit ElementDefinition path/name invariant correction

Issue request:
Published/Persuasive FHIR-core technical correction asking to change the ElementDefinition narrative length rule from "Element paths" to "Element names" and to update eld-19 so its computable expression enforces the stated element-name character and length rules.

Initial application:
The Jira comment points to GH#de65b7ad. That merge included commit 7df17c3460e62122489fc1fcd9d13cf270c2c189 (GF#19709), which changed source/elementdefinition.html from "Element paths SHALL NOT exceed 64 characters in length" to "Element names SHALL NOT exceed 64 characters in length" and replaced the old eld-19 path.matches('[^\\s#\\/]+') expression with a character-set and per-component length regex.

Additional context:
Later same-family decisions refined the same invariant area without reopening the seed result: FHIR-19745 and FHIR-25627 confirmed that the 64-character limit belongs in eld-19; FHIR-19968 fixed the generated Schematron/XPath escaping and anchoring concerns for eld-19; FHIR-38795 intentionally changed the human eld-19 description to the current "Element path SHALL be expressed as a set of '.'-separated components..." wording. Those related issues already have audit commits on the combined branch, so this commit does not duplicate them.

AutoFHIR reconciliation:
No source change was made. source/fhir.ini keeps ElementDefinition and the datatype source in the current build scope; source/elementdefinition.html now states the rule for element names, not whole paths; and source/datatypes/elementdefinition.xml has eld-19 as an anchored path regex that limits each dot-separated component to 1-64 allowed characters. Direct community searches for FHIR-19709 and eld-19 found no conflicting Zulip or Confluence evidence.

Recommendation:
Keep this no-change audit as-is. The seed request is already satisfied in current core source, and any further eld-19/eld-20 refinements should be tracked through the later, already-audited issues rather than by changing FHIR-19709 again.
