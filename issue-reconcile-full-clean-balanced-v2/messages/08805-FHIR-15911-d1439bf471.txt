FHIR-15911: Audit ele-1 operator correction

Issue request:
FHIR-15911 was a Published/Persuasive FHIR-core ElementDefinition issue raised against STU3. It reported that the ele-1 FHIRPath expression used collection union (`|`) where boolean `or` was intended, and questioned the `children().count() > id.count()` term. The accepted resolution was to change only the `|` operator to `or`; Jira comments clarified that `id` is itself a child, so the count comparison was intentional.

Initial application:
The issue was applied in SVN revision 13990, preserved in git as commit c50ea493463a70377e635b86153c803b73948953 (`GF#15911 - fix ele-1`). That commit changed source/datatypes/element.xml from `hasValue() | (children().count() > id.count())` to `hasValue() or (children().count() > id.count())`.

Additional context:
source/fhir.ini lists `Element=abstract` in the active infrastructure configuration, so source/datatypes/element.xml is the active source for the base Element invariant. The current source keeps the corrected `or` operator and also includes the later FHIR-26565 empty Parameters exception, already represented on the combined branch by commit 6bf6d264f8b1d1ef33091c8e8752a9d7628a5ebc. Focused Zulip and Confluence searches found no FHIR-15911-specific community record or conflicting later decision.

AutoFHIR reconciliation:
Made no source change. The current build source already satisfies FHIR-15911 because ele-1 uses boolean `or`, the old pipe expression is absent from current source, and the additional Parameters clause is a separate later approved correction rather than a regression.

Recommendation:
Keep this empty audit commit as-is. No follow-up source work is needed for FHIR-15911; future changes to ele-1 should preserve both the corrected boolean operator and any separately approved later exceptions.
