FHIR-5584: Audit removed mailbox constructs

Issue request:
FHIR-5584 was Published as Persuasive with Modification for FHIR-core documents. It reported that the documents page defined a $mailbox operation while the REST page also defined a /Mailbox endpoint, and asked to remove one of the overlapping mailbox constructs. The final Jira resolution says both were removed.

Initial application:
No git commit was found that explicitly names FHIR-5584. The historical application appears in the same mailbox cleanup family: git-svn mirror commit 8b801ae887a7ed1c4e58cb57c30a8379b50cf157, titled "#7976, #6343 - rework operations and messages", removed the [baseurl]/$mailbox document-submission row from source/documents.html and replaced the main messaging mailbox section with $process-message. Older source/http.html history shows the overlapping /Mailbox message and document rows that motivated the issue.

Additional context:
FHIR-6343 was Published as Persuasive with Modification and directly requested removal of the DSTU1 /Mailbox endpoint in favor of the operations framework. It cites svn revision 5657, matching the 8b801ae887a7ed1c4e58cb57c30a8379b50cf157 source application. FHIR-7976 was applied in the same svn revision for asynchronous message responses using $process-message. The combined branch already contains Issue-Reconcile-Key: FHIR-6343 as commit 7c13c339718d8101a7a8891eae7c2dad54cdfa67, which removed surviving current-source mailbox wording from active REST, CapabilityStatement, use-case, and MessageHeader operation text.

AutoFHIR reconciliation:
This commit makes no source change because current source already has no active mailbox endpoint or $mailbox document operation. The documents page lists Bundle, Composition, Binary, and whole-system transaction handling for documents and points to operations for any additional document handling; the REST overview links message processing to $process-message rather than mailbox; and the CapabilityStatement implementation URL definition no longer describes mailbox interfaces. A current-source scan found no mailbox references outside non-current/generated artifacts such as spelling, old QUICK model content, generated SVGs, or a binary PDF.

Recommendation:
Keep this empty audit commit as the FHIR-5584 decision. No further core source work is needed for this issue unless the work group wants separate editorial cleanup of generated diagrams or historical/out-of-build model artifacts, which should not be hand-edited for this reconciliation.
