FHIR-11408: Audit financial root cardinalities

Issue request:
FHIR-11408 was a Published/Persuasive Financial Management change request raised against DSTU2. It asked to reduce financial resource attribute cardinalities to 0..* because parties providing supporting information might not know required values, and the recorded resolution was to reduce all cardinalities to 0..? on root elements.

Initial application:
The issue was applied in two same-day source commits: 37303c8e87f010b309f155116763f10165ef6d3f ("First part of Tracker #11408, 12358") and 7fc33d1f033151db47e1313bc21a0721969f873b ("Remainder of Tracker #11408, 12358"). Parsing the old financial spreadsheets before and after those commits shows the pre-application required direct children, including Claim.status/type/patient and PaymentNotice.status/paymentStatus, were reduced so the listed financial resources had no required direct children after the second commit.

Additional context:
The current build uses StructureDefinition XML for the active current resources and fhir.ini confirms the active financial resources are Claim, ClaimResponse, CoverageEligibilityRequest, CoverageEligibilityResponse, EnrollmentRequest, EnrollmentResponse, ExplanationOfBenefit, PaymentNotice, PaymentReconciliation, and VisionPrescription. Older EligibilityRequest/EligibilityResponse names are mapped to CoverageEligibilityRequest/CoverageEligibilityResponse, and ProcessRequest/ProcessResponse are not active current resources. Later Published/Persuasive financial-resource issues, including FHIR-19457, FHIR-19463, FHIR-19490, FHIR-19491, FHIR-19493, FHIR-19494, FHIR-19496, FHIR-17986, and FHIR-18029, deliberately reworked or reintroduced specific required elements.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Reapplying the DSTU2 blanket optionality rule to the current R6 source would undo later work-group decisions and current model requirements rather than fixing an unapplied FHIR-11408 change.

Recommendation:
Keep this audit commit as-is. Future cardinality changes should be handled through resource-specific current trackers; do not use FHIR-11408 as authority to make all current financial-resource root elements optional.
