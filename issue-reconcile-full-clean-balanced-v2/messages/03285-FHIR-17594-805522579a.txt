FHIR-17594: Audit Claim procedure type application

Issue request:
FHIR-17594 was a Published/Persuasive STU3 Financial Management request to add a type sub-element to Claim.procedure, modeled like Claim.diagnosis.type, with a minimum value set including procedure ranking concepts. The Jira comment explicitly extended the request to ExplanationOfBenefit.

Initial application:
The issue was applied in two historical source commits rather than a single isolated current XML edit. Commit afb5ec66f68641293bb7950b6e0eeb118fa1444a explicitly listed 17594 in a broad Claim batch and added Claim.procedure.type with a ProcedureType binding plus the example procedure-type terminology. Commit 09259975771dffe6419b6a1293fa8f3b9232ac6d then enabled the matching ExplanationOfBenefit.procedure.type row. Later source conversion commits preserved those rows in the current StructureDefinition XML, and the 2020 UTG migration removed the core CodeSystem source while leaving the core ValueSet bound to the THO code system.

Additional context:
Claim and ExplanationOfBenefit are active resources in source/fhir.ini, so their StructureDefinition XML files are build-scope source. The current combined branch already contains Claim.procedure.type and ExplanationOfBenefit.procedure.type as CodeableConcept elements bound to http://hl7.org/fhir/ValueSet/ex-procedure-type. Later issue FHIR-53057, already represented on the combined branch, explains the current preferred binding strength. FHIR-31039 asks to replace the example procedure-type codes, but it remains Triaged and unresolved, so it is not an approved terminology correction for this applied/published seed.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current build-scope source already satisfies the structural request for both Claim and ExplanationOfBenefit. It intentionally does not alter procedure-type terminology semantics, which are governed by unresolved FHIR-31039 rather than by FHIR-17594.

Recommendation:
Keep this audit commit as-is. No core source change is needed for FHIR-17594; any future change from primary/secondary example procedure type codes to different claim-submission concepts should proceed through FHIR-31039 or a terminology proposal.
