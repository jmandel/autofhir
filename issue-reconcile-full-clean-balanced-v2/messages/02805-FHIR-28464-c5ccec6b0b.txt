FHIR-28464: Audit ResearchStudy status unknown handling

Issue request:
FHIR-28464 was a Published/Persuasive with Modification R4 change request asking for an unknown value in the ResearchStudy status code system because ResearchStudy.status is required and source data may have an unknown or blank clinical-trial status. The final resolution accepted the concern as part of shifting ResearchStudy.status to mean only the publication status of the resource.

Initial application:
A Jira-referencing source commit, 9175459a6e, mentions #28464 but only added ResearchStudy.site and ResearchStudy.result target profiles, so it did not itself implement the status resolution. The status semantics were actually changed in commit d5448ea900 for the broader ClinicalTrials.gov ResearchStudy work: ResearchStudy.status changed from the required research-study-status value set and "current state of the study" definition to the required publication-status value set with short "draft | active | retired | unknown" and definition "The publication state of the resource (not of the study)."

Additional context:
ResearchStudy is active in the current build through source/fhir.ini, and current source still carries the FHIR-28464 resolution: ResearchStudy.status is required, bound to http://hl7.org/fhir/ValueSet/publication-status, and the PublicationStatus code system includes unknown. The older research-study-status terminology remains in current source, but it is now used for ResearchStudy.progressStatus.state, not for the required resource status. Later Jira FHIR-50644 confirms this interpretation by rejecting a request to broaden ResearchStudy.status for trial lifecycle states because ResearchStudy.status is publication status and study states belong in ResearchStudy.progressStatus.state.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Adding unknown to the research-study-status code system would now be the wrong fix for FHIR-28464 because that code system no longer constrains required ResearchStudy.status; the current source already satisfies the final resolution through PublicationStatus.

Recommendation:
Keep this no-change audit commit as-is. No follow-up source work is needed for FHIR-28464 unless BR&R reopens the separate question of whether progressStatus.state should include a distinct unknown/blank study-state code.
