Issue request:
FHIR-13078 was a Published / Persuasive Patient Care change request from DSTU2 asking to remove the modifier flag from FamilyMemberHistory.estimatedAge. The Jira resolution repeated that request, with comments recording the contested interpretation of whether a boolean that changes age interpretation should itself be a modifier.

Initial application:

No later source history reintroduced an active modifier flag for estimatedAge.

Additional context:
FamilyMemberHistory remains an active current-build resource in source/fhir.ini. A later Applied Patient Care issue, FHIR-54457, removed FamilyMemberHistory.estimatedAge entirely; its existing reconciliation commit 6202fac1e4fd705975023b7b58a46535f99ccf25 is already present on the combined branch, so this audit does not duplicate that separate issue. The old estimatedAge XML block and fhs-2 invariant are retained only inside XML comments with a committee note that records both GF#13078 and J#54457. The relevant Zulip thread confirms the original isModifier review discussion; Confluence searches found no conflicting decision.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current authoritative source has no active FamilyMemberHistory.estimatedAge element and no active estimatedAge modifier flag; the only active FamilyMemberHistory modifier is FamilyMemberHistory.status for entered-in-error semantics. Editing the commented historical block would not change the built specification and would be redundant after FHIR-54457.

Recommendation:
Keep this no-change audit as-is. FHIR-13078 is already satisfied by the historical modifier removal and the current post-FHIR-54457 source state; future work should avoid reopening FHIR-13078 unless the work group decides to restore an estimatedAge-like element.
