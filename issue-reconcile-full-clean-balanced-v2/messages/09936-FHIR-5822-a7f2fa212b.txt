FHIR-5822: Audit element-definition query support

Issue request:
FHIR-5822 was a Published/Persuasive FHIR-core change request asking for a way to query across resources, profiles, and extensions to find where a data element is used, including value set consistency concerns. The final Jira resolution says the capability was already done.

Initial application:
No git commit explicitly mentions FHIR-5822. Jira comments show the request was deferred as ontology/definition metadata work and then marked done in 2018. The relevant source trail is broader: ElementDefinition documentation had already established that FHIR data elements are published as XML/JSON collections, and later source organization carries StructureDefinition search parameters that allow lookup by constrained element path and value set.

Additional context:
The current build no longer has DataElement as an active resource, but StructureDefinition is active and defines data types, resources, extensions, and profiles using ElementDefinition entries. Current StructureDefinition metadata says these definitions are shared through repositories and searchable by structured metadata, and the active StructureDefinition search parameters include path, base-path, type, context, and valueset. Registry/package pages also point users to registry.fhir.org and package registries for public artifacts. Direct Zulip and Confluence searches found no community record that contradicts the Jira/source conclusion.
