Issue request:
FHIR-43453 is Applied/Persuasive with Modification for R6 SupplyRequest. It asked OO to align SupplyRequest with the workflow Request pattern by adding SupplyRequest.replaces with a corresponding search parameter and by mapping category, item/product, deliverFor/subject, reason, and deliverTo as appropriate.

Initial application:
The Jira comment says the issue was applied in commit 284febeeb5. That commit added SupplyRequest.replaces, the requested workflow mappings, and a replaces search parameter to the core SupplyRequest source while SupplyRequest still had active core resource configuration. The dormant local search-parameter source still shows a copied id of ServiceRequest-replaces, but its URL and expression are SupplyRequest-specific.

Additional context:
A later core commit, 3b38b80cf2, removed SupplyRequest and related OO resources from the active core fhir.ini resource configuration and changed core narrative to link SupplyRequest to the OO incubator continuous build. The current core build therefore no longer owns the SupplyRequest resource definition. The linked OO incubator artifact already contains the requested workflow mappings and the SearchParameter id SupplyRequest-replaces.

AutoFHIR reconciliation:
This is an empty external-repo audit commit. No core source was changed because editing source/supplyrequest would only modify dormant, out-of-build core source, while the current SupplyRequest artifact lives in the external HL7/oo-incubator IG and already reflects the requested content.

Recommendation:
Keep this audit commit as-is for core reconciliation. If SupplyRequest content needs future corrections, make them in the OO incubator source repository rather than in the inactive core source/supplyrequest folder.
