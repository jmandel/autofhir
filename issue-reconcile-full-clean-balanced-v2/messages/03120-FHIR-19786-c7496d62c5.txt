FHIR-19786: Audit CDS Hooks indicator terminology retirement

Issue request:
FHIR-19786 was an Applied/Persuasive CDS change request from STU3, applied for R6. It originally asked for the CDS Hooks indicator CodeSystem to use http://terminology.hl7.org/CodeSystem/cdshooks-indicator, with id cdshooks-indicator and name CDSHooksIndicator, rather than the older http://cds-hooks.hl7.org/CodeSystem/indicator canonical.

Initial application:
The issue was not applied by directly changing the old FHIR CodeSystem canonical. Bryn Rhodes noted during application that the content was defined by CDS Hooks, then later that moving it to terminology.hl7.org required a UTG proposal. UP-392 created the THO CodeSystem, and HL7/fhir PR #3369 merged commits 54399a59 and 51d8fb83 to retire/deprecate the old FHIR CodeSystem and ValueSet while adding a successor link to the THO CodeSystem.

Additional context:
The current core source keeps the legacy CDS Hooks indicator CodeSystem and ValueSet as retired/deprecated artifacts rather than rewriting the old canonical in place. The current THO CodeSystem exists at http://terminology.hl7.org/CodeSystem/cdshooks-indicator with id cdshooks-indicator, name CDSHooksIndicator, and active status. Current build output still renders the legacy core pages, but they are retired and point implementers to the THO successor; changing the legacy canonical now would conflate the retired FHIR artifact with the active THO artifact.

AutoFHIR reconciliation:
No source change was made. The current source and publication surface already preserve historical compatibility for the old CDS Hooks canonical while making the THO CodeSystem the successor/current terminology location, which is the safe interpretation of the Jira comments and applied PR.

Recommendation:
Keep this audit commit as-is. Do not change the legacy core CodeSystem URL to the THO URL; any future cleanup should be reviewed by CDS/terminology maintainers because it would decide whether retired legacy terminology pages should remain published for compatibility or be removed from the build entirely.
