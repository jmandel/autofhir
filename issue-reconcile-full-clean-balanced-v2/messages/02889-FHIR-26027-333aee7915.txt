Issue request:
FHIR-26027 was a Published PA change request, resolved Persuasive with Modification for R5, asking the Organization and Location resource Boundaries and Relationships sections to clarify the Event-pattern distinction: Location records where a service is performed, while Organization may represent who performed the service.

Initial application:

Current source still contains the applied guidance in both files.

Additional context:
Location and Organization are active resources in source/fhir.ini, so these introduction files are current build-scope source. The Event pattern source distinguishes Event.performer.actor, which can reference Organization, from Event.location, which references Location. Later same-area changes, including FHIR-39145's virtual-location wording and later Organization boundary clarifications, preserved the FHIR-26027 sentence. PA WGM minutes record the same disposition and vote as Jira, and a later implementers Zulip thread quotes and reinforces the Organization-vs-Location distinction without contradicting it.

AutoFHIR reconciliation:

Keep this no-change audit commit as-is. Further Location/Organization modeling refinements, such as virtual locations or complex facilities, should remain separate PA decisions because the FHIR-26027 performer-versus-place clarification is already present and consistent.
