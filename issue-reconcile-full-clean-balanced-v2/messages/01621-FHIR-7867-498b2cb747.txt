FHIR-7867: Audit Immunization status application

Issue request:
FHIR-7867 was a Published/Persuasive DSTU1 PHER change request asking to add a record status to Immunization to communicate active, in error, and cancelled. The recorded 2015-07-02 PHER resolution agreed to add status and work on vocabulary.

Initial application:
The change appears to have been applied by git commit b4d544060a, whose subject explicitly says "#7867 add I.status". That commit added Immunization.status as a required modifier code with a required status binding, summary flag, statusCode mapping, committee note #7867, and example status values. The current source still carries the #7867 committee note on Immunization.status.

Additional context:
Immunization is an active resource in source/fhir.ini, so source/immunization files are in current build scope. Later workflow/event alignment changed the concrete Immunization status vocabulary from the 2015 draft wording to the current point-in-time event model: completed, entered-in-error, and not-done. FHIR-54325 later refined statusReason around not-done and entered-in-error and is already represented on the combined branch. A 2022 Zulip workflow thread likewise describes Immunization statuses as limited to completed, entered-in-error, and not-done because an immunization is essentially a point-in-time event. No direct Zulip or Confluence evidence for FHIR-7867 was found that changes this conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active Immunization definition has a required modifier Immunization.status element bound to the Immunization Status Codes value set, the value set includes completed, entered-in-error, and not-done, a status search parameter exists, and examples carry status values. Reintroducing the original words active/cancelled as codes would conflict with later vocabulary and event-pattern decisions rather than complete FHIR-7867.

Recommendation:
Keep this audit commit as-is. The seed issue is already applied in current core source, and future changes to Immunization status vocabulary should be handled by a new PHER/workflow decision rather than by replaying the 2015 wording.
