FHIR-41241: Audit DiagnosticReport relatesTo application

Issue request:
FHIR-41241 was Applied with resolution Persuasive with Modification for R6. It asked for a core way to identify prior DiagnosticReport resources amended, appended, replaced, extended, or otherwise related by the current report; the accepted resolution was to add DiagnosticReport.relatesTo 0..* RelatedArtifact and deprecate the diagnosticReport-addendumOf, diagnosticReport-extends, and diagnosticReport-replaces extensions.

Initial application:
The core source already contains the required active build change. DiagnosticReport is listed as an active resource in source/fhir.ini, commit 89b6ffd75a added DiagnosticReport.relatesTo, and commit fae86d3c8e corrected its type to RelatedArtifact rather than a Reference to RelatedArtifact.

Additional context:
OO WGM minutes from May 2024 show the same amended/appended DiagnosticReport workflow discussion and the option to add a relatesTo element with code plus reference semantics. The three named extension definitions now live in the FHIR Extension Pack; FHIR-41241 extension-pack commits first marked them deprecated with a replacement reason, and later Published issue FHIR-52827 intentionally changed that to version-specific-use metadata plus descriptions saying they are replaced by DiagnosticReport.relatesTo from R6.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The current FHIR core source already provides DiagnosticReport.relatesTo as 0..* RelatedArtifact in an active resource, and the extension-pack publication/deprecation handling is outside this core checkout and has a later FHIR-extensions decision.

Recommendation:
Keep this audit commit as-is for FHIR core. Any further changes to extension-pack deprecation presentation should be handled in the FHIR Extension Pack under FHIR-52827 or successor extension-pack governance, not as a core source correction for FHIR-41241.
