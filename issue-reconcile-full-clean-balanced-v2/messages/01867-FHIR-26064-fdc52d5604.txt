FHIR-26064: Align CarePlan activity ModelInfo

Issue request:
FHIR-26064 was a Published FHIR-core Patient Care change request, resolved Persuasive with Modification for R5, asking to rename CarePlan.activity.outcome to CarePlan.activity.performedActivity as a CodeableReference, rename CarePlan.activity.reference to CarePlan.activity.plannedActivityReference, and rename CarePlan.activity.detail to CarePlan.activity.plannedActivityDetail with clarified definitions separating performed activity from Goal.outcome.

Initial application:
The Jira-linked implementation commit 4f406d0e4653ab33d32498195371ff7d6a298f8c applied the rename across CarePlan examples, the introduction, the then-authoritative careplan spreadsheet, and the new care-plan-activity-performed value set. Later source refactoring moved the active CarePlan definition into source/careplan/structuredefinition-CarePlan.xml, where the main resource source already exposes performedActivity and plannedActivityReference. However, the active FHIR ModelInfo Library example still exposed the pre-rename outcomeCodeableConcept, outcomeReference, reference, and detail metadata.

Additional context:
FHIR-39101 later removed CarePlan.activity.plannedActivityDetail in favor of plannedActivityReference, including contained request resources; that issue is already represented on the combined branch by commit 07f2600fc6e1fc3e56f25e9ab478c13e8627b1c1. Current CarePlan source and active examples/search parameters therefore intentionally have no active plannedActivityDetail, while FHIR-45000 and FHIR-48415 later refined performedActivity wording without reversing the FHIR-26064 names. Library is active in source/fhir.ini, source/library/list-Library-examples.xml lists Library/library-fhir-model-definition, source/library/library-examples-header.xml links the readable XML information model, and publish.ini copies source/library/library-fhir-model-definition-content.xml, so the stale ModelInfo files are current build-scoped source rather than unrelated generated output.

AutoFHIR reconciliation:
Updated source/library/library-fhir-model-definition-content.xml so CarePlan.Activity now exposes performedActivity as the repeating CodeableConcept-or-Reference shape used elsewhere in this ModelInfo for CodeableReference, keeps progress, exposes plannedActivityReference, and no longer advertises the removed detail path or orphan CarePlan.Detail class. Refreshed the embedded base64 data in source/library/library-fhir-model-definition.xml so the Library resource and readable ModelInfo content remain synchronized. No change was needed to the authoritative CarePlan StructureDefinition.

Recommendation:
Keep this commit as-is. It completes FHIR-26064 across the active FHIR ModelInfo surface while respecting the later already-reconciled FHIR-39101 removal of plannedActivityDetail; broader regeneration of the whole FHIR ModelInfo or other CodeableReference cleanup should be handled under separate Jira decisions.
