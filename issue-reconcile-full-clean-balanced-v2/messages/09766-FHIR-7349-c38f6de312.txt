FHIR-7349: Audit CCDA support wording

Issue request:
FHIR-7349 was a Published/Persuasive DSTU1 ballot-intro issue asking to replace the claim that FHIR supported all content from the Consolidated CDA implementation guide with narrower language saying it supported the Common Meaningful Use Data Set and other CCDA content. The resolution was to update the language, with a 7-0-1 vote on 2015-07-07.

Initial application:
The Jira comment cited svn revision 6432. Git history maps that to commit 3124bf6dcc1bef1bde8b71890f35afea858f3943, which changed source/ballot-intro.html from "supporting all content from the Consolidated CDA implementation guide" to narrower Common Meaningful Use Data Set wording. Follow-up commit 4ec460ff92c32513e639742b2a11d61731d76ef8 cleaned up the duplicated words left by the initial application.

Additional context:
The current build still includes source/ballot-intro.html through source/hierarchy.xml and links it from source/index.html, but the current R6 ballot-intro text is a release-specific roadmap and no longer contains either the obsolete "all content from the Consolidated CDA" claim or the historical Common Meaningful Use replacement. Commit f1da22a70ab9bd5e7c15067aeb3e7c81c12c665ad later removed that historical CCDA/MU note while updating the ballot-intro material for normative packaging. Jira, Zulip, and Confluence searches found no related or later community record requiring the old DSTU1 wording to be reintroduced.

AutoFHIR reconciliation:
This commit makes no source change. The requested correction was applied historically, the remaining historical note was later retired as the ballot-intro page evolved, and current source does not make the disputed overbroad CCDA coverage claim.

Recommendation:
Keep this no-change audit commit. Reintroducing DSTU1-era Common Meaningful Use/CCDA scope prose into the current R6 ballot roadmap would be stale and would not improve current implementer understanding.
