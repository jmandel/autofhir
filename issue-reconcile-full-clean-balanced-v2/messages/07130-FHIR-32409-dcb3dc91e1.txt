FHIR-32409: Audit Device reason bindings

Issue request:
FHIR-32409 was Published with resolution Persuasive with Modification for R5. It began as a broad Device binding question for specialization.systemType, version.type, operationalStatus.reason, associationStatus.reason, and safety, but the accepted resolution narrowed this issue to adding example terminology for operationalStatus.reason and associationStatus.reason.

Initial application:
No source-changing commit explicitly labeled FHIR-32409 was found. The association side was applied indirectly: OO minutes marked associationState.statusReason done, FHIR-40529 later instructed editors to reuse the FHIR-32409 table for DeviceAssociation.statusReason, git commits 902ba6f126 and 925b08c4bf created the DeviceAssociation status-reason CodeSystem/ValueSet and bound DeviceAssociation.statusReason to it. The operational side was applied through the later FHIR-36213 path: commit 50f4a45ebb2b added the Device operation statusReason ValueSet/CodeSystem with the final MDC-derived example list and bound the then-current Device.operation.statusReason element.

Additional context:
Later final Device modeling changed where these concepts live. FHIR-38904 removed active Device association and operation statusReason content and moved association tracking to DeviceAssociation. FHIR-48532 then kept DeviceAssociation.statusReason bound to the FHIR-32409-derived ValueSet while changing the binding strength to extensible and adding DeviceAssociation.associationStatus for state concepts. Current source/fhir.ini includes Device and DeviceAssociation as active resources. The original issue's other named elements are adjacent background rather than remaining FHIR-32409 work: Device.deviceVersion.type, Device.conformsTo.specification, and Device.safety all have bindings and are already represented by separate reconcile commits for FHIR-32564, FHIR-32563, and FHIR-32573.

AutoFHIR reconciliation:
This commit intentionally makes no source change. XML parsing of the active current source finds no active Device.operation.statusReason or Device.association.statusReason elements; DeviceAssociation.statusReason is active, bound to ValueSet/deviceassociation-status-reason, and its CodeSystem contains attached, disconnected, failed, placed, and replaced. The surviving Device operation status-reason terminology artifact contains the later FHIR-36213 MDC-derived example concepts, and the active Device model should not be reverted to the older FHIR-32409 text.

Recommendation:
Keep this no-change audit commit as-is. Future edits should not resurrect Device.operation or Device.association for FHIR-32409; any further status or reason terminology changes should be made under the current DeviceAssociation/Device operation issue family with new WG direction.
