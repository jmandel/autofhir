FHIR-14101: Audit versioned reference search guidance

Issue request:
FHIR-14101 was a Published FHIR-core search change request, resolved Persuasive with Modification, asking how reference searches behave when stored references or search inputs use version-specific references such as Patient/1/_history/2, including include/chaining behavior and warnings when a search cannot act on the referenced version.

Initial application:
The issue was applied in svn revision 13432, represented in git as edd46025f8b0f51a2654785c8c7806c30e186bb7, which added an implementation note to source/search.html with the three resolution bullets for chaining, OperationOutcome warnings, and _include behavior. Later search-page refactors moved that text into the current References and Versions section without removing the substance.

Additional context:
The latest combined-branch source/search.html has active reference search syntax for [parameter]=[type]/[id]/_history/[version], states that relative and absolute references resolving to the same value qualify as matches, and states that a non-versioned relative reference search SHOULD match stored versioned references to the same target resource. The same page's References and Versions section retains the FHIR-14101 chaining, warning, and include guidance, and the include section separately says servers SHOULD resolve _include and _revinclude for version-specific references by resolving the version named. Later related Jira decisions FHIR-36715, FHIR-36716, FHIR-43073, and FHIR-16361 are already represented on the combined branch and refine the same search-page area rather than requiring another FHIR-14101 source edit.
