FHIR-32816: Audit nhin PurposeOfUse ConceptMap form

Issue request:
FHIR-32816 was Published/Persuasive for R4B and reported that the generated valuesets.xml entry for http://hl7.org/fhir/ValueSet/nhin-purposeofuse contained an invalid contained ConceptMap: R4B output used the R5 relationship element and source-is-* relationship codes where the R4/R4B ConceptMap representation requires equivalence and wider/narrower-style equivalence values.

Initial application:
No FHIR core source commit explicitly tagged FHIR-32816 was found. The active current source for source/valueset/valueset-nhin-purposeofuse.xml is part of the ValueSet examples list and currently uses the R5/R6 ConceptMap.group.element.target.relationship form. The checked R4B history artifact tools/history/release4b/valuesets.xml now uses equivalence values for the nhin-purposeofuse contained ConceptMap, while the checked release5 artifact uses the current relationship form.

Additional context:
FHIR-I September 2021 minutes record FHIR-32816 as a technical correction to be fixed. The later same-change-family issue FHIR-35784 made the valuesets.xml relationship/equivalence problem explicit, pointed to the R4B download, and was applied through HL7/kindling#69; a separate AutoFHIR audit commit for FHIR-35784 is already present on the combined branch. A related Zulip thread about the same nhin-purposeofuse contained ConceptMap concluded the R4B build problem was tooling rather than source content. Current ConceptMap source no longer has a ConceptMap.group.element.target.equivalence element, so changing active current source to equivalence would regress the current build.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current FHIR source is correct for the current ConceptMap model, and the checked R4B valuesets.xml artifact no longer has the invalid relationship/source-is-* representation that the seed reported.

Recommendation:
Keep this audit commit as-is. Do not change source/valueset/valueset-nhin-purposeofuse.xml back to equivalence for the current build; if historical R4B download generation is questioned again, handle it in the generation tooling path already represented by FHIR-35784/HL7 kindling work.
