FHIR-33231: Correct Encounter virtual-service datatype reference

Issue request:
FHIR-33231 was Published as Persuasive. The original request asked how to indicate video versus audio participation in telehealth encounters; the final PA resolution tied the answer directly to FHIR-33341 and added Encounter.virtualService using the same virtual-service detail structure.

Initial application:
The request was applied by git commit 4d515864f46e10b648e02e76cd8773d8636c6d07, which added Encounter.virtualService with type VirtualServiceDetail and copied the FHIR-33341 virtual-meeting guidance. The copied participant-specific guidance still named the obsolete VirtualServiceContactDetail.

Additional context:
source/fhir.ini actively includes Encounter and VirtualServiceDetail, and current source has no VirtualServiceContactDetail definition in core or the Extension Pack. The seed FHIR-33341 Appointment fix is the supporting decision for this same source family, and both current comments needed the same current datatype name.

AutoFHIR reconciliation:
This commit updates only the Encounter.virtualService comment so the participant-level extension guidance refers to VirtualServiceDetail, matching the actual active datatype and the element type.

Recommendation:
Keep this source fix with the FHIR-33341 seed fix. It preserves the approved Encounter virtual-service model while removing a stale datatype name that could mislead implementers looking for the extension value type.
