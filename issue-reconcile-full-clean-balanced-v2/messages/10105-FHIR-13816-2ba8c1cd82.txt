FHIR-13816: Audit Questionnaire initial answer support

Issue request:
FHIR-13816 was Published with resolution Persuasive with Modification for STU3 Questionnaire. It asked that repeating Questionnaire items be able to represent multiple initially selected values by adding option.initialSelected boolean 0..1 with default false, and by constraining initial[x] to be absent when option[x] is present.

Initial application:
The change was applied in the historical SVN-mirrored commit be83985eed2b7ffcdb602ed6ae8de9f25ef1d4c6 / svn revision 12718, whose subject says "#13816 - add questionnaire.item.option.initialSelected". That commit added the option initialSelected element and the que-11 invariant in the then-current Questionnaire spreadsheet source.

Additional context:
Questionnaire is an active core resource in source/fhir.ini. The current StructureDefinition has evolved from STU3 option to current answerOption naming, but it preserves the requested semantics: answerOption.initialSelected is 0..1 boolean with missing values treated as not selected, Questionnaire.item.initial is 0..*, and que-11 prohibits using answerOption and initial together. Later related issues FHIR-22686, FHIR-27803, and FHIR-41174 clarified the wording and cardinality interaction without removing the original FHIR-13816 mechanism.

AutoFHIR reconciliation:
No source change was made. The current active source already implements the FHIR-13816 resolution and later related clarifications, so changing the specification now would risk duplicating or weakening the existing rule.
