FHIR-39347: Audit async 429 handling externalization

Issue request:
FHIR-39347 was a Published FHIR-core change request resolved Persuasive with Modification for R5. It asked whether repeated status polling that receives 429 Too Many Requests also scraps the original asynchronous request. The approved wording replaced the ambiguous "terminate the session" sentence with text saying a server may return 429 without a status answer, may include Retry-After before it will respond to another status check, or may abandon the asynchronous operation and force a retry.

Initial application:
The issue appears to have been applied by commit 25d162090f40d6b45a5685aeb883778d4fd5d7a8, which changed source/async-bulk.html to use the approved clarification. That commit did not change source/async-bundle.html, and the R5 published async-bundle page still shows the older "terminate the session" wording. The FHIR-I WGM minutes confirm the Persuasive with Modification vote for FHIR-39347.

Additional context:
FHIR-35936 had split the async material into source/async-bulk.html and source/async-bundle.html for R5. Later, commit 270e0ceb7b029dad4ca0fc5ccf5296ff370888cd deleted both detailed core pages for R6 and rewrote the current source/async.html page as an informative overview that links to API Incubator copies of the patterns. The current core checkout no longer contains the ambiguous 429 status-polling sentence. The current build's API Incubator async links are broken, but those are separate unresolved Triaged issues (FHIR-53816 and FHIR-53868), not final decisions to edit under this reconciliation.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Adding the FHIR-39347 wording back to source/async.html would duplicate detailed behavior that has been externalized from current core, while the old in-core async-bulk.html and async-bundle.html source files are no longer part of the build. Any remaining correction to the detailed status-polling rule now belongs in the external API Incubator source once that material is available and link ownership is resolved.

Recommendation:
Keep this audit commit as an external-repo decision for current FHIR core. Follow up in the API Incubator work, not by restoring detailed polling semantics to core, and ensure any republished bulk and interaction async pattern pages use the FHIR-39347 clarification consistently after the broken-link issues are resolved.
