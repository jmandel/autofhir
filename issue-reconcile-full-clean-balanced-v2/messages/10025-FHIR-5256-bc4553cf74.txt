FHIR-5256: Audit Condition certainty value set display

Issue request:
FHIR-5256 was a Published/Persuasive DSTU1 FHIR-core Condition ballot correction reporting that http://hl7.org/fhir/valueset-condition-certainty.html displayed a publication tooling error instead of an expanded ValueSet: "OperationOutcome cannot be cast to ValueSet." The requested change was to fix the displayed value set.

Initial application:
No commit explicitly mentions FHIR-5256. The Jira comments say "This is fixed now" on 2015-02-12. The closest source-history application is commit da32ced84f5bc2a617e32c0a6158d114e24fb18c, "$5447 - fix valueset expansion," which added source/vscache/http_hl7.org_fhir_vs_condition-certainty.xml containing a concrete expanded Condition/Diagnosis Certainty ValueSet rather than the OperationOutcome error.

Additional context:
FHIR-3976 later resolved the overlapping Condition.status/Condition.certainty model by renaming status to clinicalStatus and removing the concept of certainty. Its implementation commit 1f32e2833bae9fb8cc45636c39142020e353b5c6 marked Condition.certainty and ConditionCertainty as removed in the Condition spreadsheet. The old source/condition/valueset-condition-certainty.xml and vscache entry were subsequently deleted, and the current active Condition source binds Condition.verificationStatus to http://hl7.org/fhir/ValueSet/condition-ver-status instead. A 2019 Zulip implementer thread also treats the old condition-certainty URL as a previous-release artifact and points users to the current Condition verificationStatus/refuted guidance. Current build checks return 404 for the old valueset-condition-certainty page and 200 for condition-ver-status.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The reported DSTU1 display failure was historically fixed, and the affected standalone Condition certainty page is no longer part of the current build surface. Current active Condition source already uses the later verificationStatus terminology, so reintroducing or editing the old condition-certainty value set would be a regression rather than a current-spec fix.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-5256; future work on Condition certainty should be handled under the later substantive Condition modeling issues, not this historical publication-display defect.
