FHIR-12905: Audit ProcedureRequest.code cardinality

Issue request:
FHIR-12905 was Published with a Persuasive resolution for DSTU2 OO: ProcedureRequest.code should not remain mandatory because a request can be narrative-only; the resolution was to change ProcedureRequest.code to 0..1.

Initial application:
Historical commit 8f78b25c34a539d54ff592c1cfae64b716381bfd ("[#12905], [#12813]") applied the issue on 2017-05-15 by changing ProcedureRequest.code Card. from 1..1 to 0..1 in both procedurerequest-spreadsheet.sheet.txt and procedurerequest-spreadsheet.xml. That commit also applied unrelated FHIR-12813 requester commentary, which is already separately audited on the combined branch.

Additional context:
ProcedureRequest is no longer an active current-build resource: source/fhir.ini has active `servicerequest=ServiceRequest` and a commented migration note `ProcedureRequest=approved -> merged into ServiceRequest`. The active ServiceRequest structure definition has ServiceRequest.code min 0/max 1. Its prr-1 invariant only constrains orderDetail to appear with code and does not make code globally mandatory. Jira searches found no later FHIR-core ProcedureRequest.code issue beyond FHIR-12905, and Zulip/Confluence searches found no conflicting rationale.

AutoFHIR reconciliation:
No source change was made. The current build already represents the requested optional code cardinality on the in-scope successor resource, while the retired ProcedureRequest source from the DSTU2 spreadsheet is not part of the current build.

Recommendation:
Keep this audit commit as-is; no follow-up source work is needed in core for FHIR-12905 unless a future work group decision changes ServiceRequest narrative-only behavior.
