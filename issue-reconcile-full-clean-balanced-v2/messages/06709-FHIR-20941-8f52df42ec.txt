FHIR-20941: Audit SupplyRequest DeviceDefinition migration

Issue request:
Published OO change request FHIR-20941, resolved Persuasive and applied for R5, asked to add DeviceDefinition to the SupplyRequest item reference choice because requests often identify kinds of devices rather than specific device instances.

Initial application:
No source commit explicitly mentioning FHIR-20941 was found. The same SupplyRequest.item change was later refined in FHIR-26301 to use CodeableReference and was implemented by commit 0603ec82cd, which changed the pre-R5 SupplyRequest spreadsheet from CodeableConcept|Reference(Medication|Substance|Device) to CodeableReference(Medication|Substance|Device|DeviceDefinition). The R5 source-conversion commit 33b409a4b6 preserved DeviceDefinition in the XML StructureDefinition and is contained in the v5.0.0 tag.

Additional context:
FHIR-26301 is the same change family and already has reconciliation commit 85b1a0c968 on the combined branch, so this commit does not duplicate that decision. Neighboring FHIR-20942 initially proposed removing Substance from the same choice but was retracted, so it does not conflict with keeping the current target list. In 2025, commit 3b38b80cf2 removed supplyrequest=SupplyRequest from active core fhir.ini registration and repointed core links to the OO Incubator additional-resources IG; the retained core source and current OO Incubator artifact both still include DeviceDefinition on SupplyRequest.item.

AutoFHIR reconciliation:
This empty audit commit makes no core source change. The requested R5 capability was applied and published, and SupplyRequest is outside the current core build scope, so any future active SupplyRequest edits belong in the OO Incubator source rather than this core checkout.

Recommendation:
Keep this audit as-is. If SupplyRequest is migrated back into core, preserve DeviceDefinition as an allowed SupplyRequest.item target; otherwise make future SupplyRequest.item changes in HL7/oo-incubator.
