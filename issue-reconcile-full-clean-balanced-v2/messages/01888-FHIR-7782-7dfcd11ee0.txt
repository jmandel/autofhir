FHIR-7782: Audit ElementDefinition min/max defaults

Issue request:
FHIR-7782 was a Published FHIR-core/MnM change request resolved Persuasive with Modification. It asked what cardinality applies when ElementDefinition.min or ElementDefinition.max is omitted, and the accepted resolution was to say that resource/datatype structure definitions require min and max while constraint differentials default omitted min and max to the base definition; it also asked to align the ElementDefinition page with StructureDefinition usage and make the content reachable from the StructureDefinition page.

Initial application:
The Jira comment identifies SVN revision 5946. In the git mirror this is commit 49dcd3b5343a466e9e1aa3bac05b1a1a20bd29a6, which changed source/elementdefinition.html to add an interpretation table and explicit rules for min and max in StructureDefinition contexts. Later source refactors, including 2f577a81d2c0833f5bbe23b020262257b89339cc and 1736091b56105ca469a08c4d7a91976dfe2346e8, preserved the min/max rule while updating the surrounding page and baseDefinition terminology.

Additional context:
Current source/fhir.ini keeps ElementDefinition as the active type page and StructureDefinition as an active resource page. The current ElementDefinition page includes the context table and a dedicated "Rules about min and max" section saying that absent baseDefinition means min and max are always required, differential min/max are optional and default to the base definition, and snapshot min/max are always required. The current StructureDefinition source types snapshot.element and differential.element as ElementDefinition and enforces formal definitions/cardinalities for non-logical snapshots through sdf-3. Searches found no relevant Zulip or Confluence conflict; a broad Jira search surfaced FHIR-28441, but that issue concerns extension inheritance/snapshot behavior rather than this default cardinality rule.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source already conveys the rule requested by FHIR-7782 through the authoritative ElementDefinition page and the StructureDefinition element definitions that use ElementDefinition. Adding another local restatement to the StructureDefinition notes would be redundant and could create future maintenance drift without changing implementer understanding.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed for FHIR-7782 unless the work group wants a broader editorial reorganization of StructureDefinition guidance, which is outside this applied DSTU1 clarification.
