FHIR-15687: Audit ConceptMap ValueSet mapping support

Issue request:
FHIR-15687 was a Published/Persuasive FHIR-core ConceptMap change request from Vocab asking that ConceptMap mappings be able to use ValueSet references instead of only enumerated codes. The final resolution required adding group.element.valueSet, group.element.target.valueSet, and group.unmapped.valueSet as canonical(ValueSet) elements with cardinality 0..1.

Initial application:
The Jira comments record initial application by Michael Lawley in commit 44b6a9fc8f977d070ab90083f6d1004394e83ffc, a wording fix in 2d37bd61fc, and the corrected cmd-2 constraint in 520ebaf4d3. In the current source history, the R5 ConceptMap2 material was folded into ConceptMap by 8623473ddfcef0cb88b9abf5241abfe6e28ea542, with later cleanup preserving the same ValueSet elements and constraints.

Additional context:
ConceptMap is active in source/fhir.ini. FHIR-33061 was the explicitly related usage-note follow-up, and the current ConceptMap introduction contains its expansion semantics for group.element.valueSet, group.element.target.valueSet, and group.unmapped.valueSet. FHIR-40598 later clarified the definitions for the ValueSet references and the unmapped behavior without reversing FHIR-15687.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active ConceptMap StructureDefinition already contains the three requested canonical(ValueSet) elements with 0..1 cardinality and mutual-exclusion constraints against the sibling code elements, and the narrative already explains their expansion semantics.

Recommendation:
Keep this audit commit as-is. No follow-up core source work is needed for FHIR-15687 unless a future Vocab decision changes how ConceptMap should handle ValueSet expansion or $translate behavior.
