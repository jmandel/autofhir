FHIR-39510: Audit SupplyRequest boundary relationship move

Issue request:
FHIR-39510 was a Published/Persuasive R5 Orders and Observations change request asking to update the SupplyRequest Boundaries and Relationships text with an entry for DeviceDispense, MedicationDispense, and BiologicallyDerivedProductDispense. The approved text says SupplyRequest does not document the formal association of a device, medication, biologically derived product, or supply item to a patient; the dispense resources document that patient-use association.

Initial application:
The issue was applied before R5 publication. Jira records John Nolen's comment that the change was added to the build in commit a198b29aae2ef6981542b3c57f0f1be0a203a16c, and that commit inserted the requested paragraph into source/supplyrequest/supplyrequest-introduction.xml. The dormant local SupplyRequest introduction still contains the requested DeviceDispense, MedicationDispense, and BiologicallyDerivedProductDispense boundary paragraph.

Additional context:
The 2022-11-21 OO HCP minutes record the 8-0-0 motion for this SupplyRequest boundary update together with three neighboring SupplyRequest updates. Later, the current core branch stopped building SupplyRequest: source/fhir.ini has no active supplyrequest entry in the resource or work-group lists, core module/ballot pages link SupplyRequest and DeviceDispense to the OO Incubator IG, and commit 3b38b80cf23f9cbb306fab8fcedb293315478c32 removed the immature OO resources from active core lists while pointing to the incubator. A 2025 OO Zulip thread confirms that SupplyRequest and related supply/dispense resources were pulled out of core to progress together in the OO additional resources/incubator IG. The current HL7/oo-incubator SupplyRequest page-content source contains the requested boundary paragraph.

AutoFHIR reconciliation:
This empty audit commit makes no core source change. The current FHIR core build does not own the SupplyRequest resource page or StructureDefinition, so editing source/supplyrequest/supplyrequest-introduction.xml would not repair an active core artifact. The requested boundary relationship text was applied historically and is present in the external OO Incubator source that now owns active SupplyRequest content.

Recommendation:
Keep this audit commit as-is. Do not edit dormant core SupplyRequest source for this issue; if OO wants further polishing of the migrated SupplyRequest narrative, that work should be done in HL7/oo-incubator rather than in the current core build.
