FHIR-7160: Audit Observation grouping guidance

Issue request:
FHIR-7160 was a Published/Persuasive OO clarification from the 2015 May ballot asking for more explanation of Observation grouping/panels in the component and related descriptions, plus resource-note text and example references such as blood pressure and USLab.

Initial application:
The request was applied in the historical Observation source before this reconciliation. Commit 6909eeca50 added Observation notes that explained panels/batteries, DiagnosticReport grouping, Observation.related, Observation.component, and examples including Blood Pressure and USLab. Commit d4505c43ef then reorganized and expanded those Observation notes while explicitly listing 7160 in the subject. The same 2015 change family included FHIR-7517/FHIR-7639 work that reintroduced Observation.component and separated component-style observations from member-style related observations.

Additional context:
Observation is active in the current build through source/fhir.ini. The old Observation.related structure was later replaced by explicit Observation.hasMember and Observation.derivedFrom elements under FHIR-10118, and later R6 changes such as FHIR-50138 and FHIR-50635 refined the organizer/grouping wording. Current source now contains a dedicated Observation Grouping notes section, element comments that point readers to the grouping notes, examples for blood pressure, BMI, Apgar, lipid/vital panels, and diagnostics-module guidance using DiagnosticReport.result, Observation.component, Observation.hasMember, and Observation.derivedFrom. The original USLab IG reference is no longer an active core build artifact; source/igs.xml has the USLab IG commented out.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already satisfies the substance of FHIR-7160 using the current R6 element model and examples, and reintroducing legacy Observation.related or USLab-specific wording would be stale.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed for FHIR-7160 unless OO separately decides to restore a current USLab-style example; that would be a new example-scope decision rather than unfinished application of this DSTU1 clarification.
