FHIR-37449: Audit shareable terminology examples

Issue request:
FHIR-37449 is a Published/Persuasive FHIR-core technical correction raised against R4B and applied for R5. It reported that several ValueSet examples were still missing publisher when they claimed conformance to ShareableValueSet, and that many CodeSystem examples had publisher but were missing description required by ShareableCodeSystem.

Initial application:
The issue was applied historically by HL7/fhir commit f87870f3725a6987f2cddcd4d804c6bdf39c0755, which explicitly cites FHIR-37449 and updates canonical resource names, titles, and descriptions across many CodeSystem, ValueSet, and other canonical-resource source files. The issue also follows FHIR-34450, where the same reporter identified shareable terminology examples missing required metadata and then opened FHIR-37449 for the remaining gaps.

Additional context:
Later and related profile decisions change how the current source should be read. FHIR-29943 removed the requirement that ShareableValueSet.publisher be mandatory; FHIR-31395 rebuilt the R5 ValueSet profile family; and FHIR-37959 later resolved for R6 that the Shareable/Publishable/Computable/Executable terminology profiles should be removed from core and maintained in CRMI with unchanged URIs. Current source/fhir.ini has no active ShareableValueSet or ShareableCodeSystem profile entry, the CodeSystem and ValueSet core implementation guides have empty definition sections, and the active Shareable pattern narrative points applications to CRMI. A current source check shows the issue-listed CodeSystem files have publisher and description and do not assert ShareableCodeSystem; the issue-listed ValueSet files that still exist do not assert ShareableValueSet. The only current XML terminology resource still asserting a shareable terminology profile is medicinal-product-name-part-type, and it has both publisher and description.

AutoFHIR reconciliation:
This is an empty audit commit. No core source change is needed for FHIR-37449: the original missing-required-element problem is no longer present in the current build inputs, and adding publisher elements or reintroducing old core profile definitions would conflict with later applied profile-migration decisions.

Recommendation:
Keep this audit commit as-is. Do not add publisher to the current ValueSet examples or restore ShareableValueSet/ShareableCodeSystem in core for FHIR-37449. Any future corrections to the migrated shareable terminology profiles should be handled in the CRMI/profile-maintenance source, or under a new tracker if the work group wants to revisit the remaining profile assertion on medicinal-product-name-part-type.
