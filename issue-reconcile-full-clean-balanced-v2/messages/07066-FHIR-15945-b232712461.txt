FHIR-15945: Audit SupplyRequest BDP scope externally

Issue request:
FHIR-15945 was Published/Persuasive with Modification for R5. It asked OO to make the ordering and administration model for blood products clear, including whether BiologicallyDerivedProduct, SupplyRequest, SupplyDelivery, and a statement-like resource should represent product, order, delivery/receipt, administration, and lack-of-compliance reasons. The recorded resolution was to connect the balloter with the active OO project so those use cases were covered.

Initial application:
No source commit explicitly mentions FHIR-15945. The issue appears to have been applied through the broader healthcare-product and biologically-derived-product work: later SupplyRequest/DeviceRequest boundary changes clarified that SupplyRequest is inventory-oriented, FHIR-45453 added SupplyRequest.intent, and commit 71fdef0f0c added the Biologically Derived Product module that models clinical BDP requests with ServiceRequest, product tracking with BiologicallyDerivedProduct, consignment delivery with SupplyDelivery, dispense/allocation with BiologicallyDerivedProductDispense, and administration with Procedure.

Additional context:
The current active resource list in source/fhir.ini includes BiologicallyDerivedProduct but no longer includes SupplyRequest, SupplyDelivery, or BiologicallyDerivedProductDispense. Commit 3b38b80cf2 removed those OO resources from the FHIR-core build and repointed the BDP module links to the OO Incubator IG. Current source still keeps the core BiologicallyDerivedProduct module in scope, where it links to OO Incubator SupplyDelivery/BDPDispense and describes ServiceRequest as the clinical request for BDP use. A 2019 OO healthcare-product minutes page also records the same modeling distinction between requesting supply and finding/matching biologically derived products.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The remaining SupplyRequest and SupplyDelivery element questions belong to the external OO Incubator/current out-of-build source, while the in-scope FHIR-core BDP guidance already points implementers to the current model and does not need redundant or contradictory core edits.

Recommendation:
Keep this audit commit as-is for FHIR-core. If OO wants to revisit SupplyRequest notDoneReason, refill/frequency semantics, or SupplyDelivery non-administration reasons, track that follow-up in the OO Incubator rather than editing inactive FHIR-core resource directories.
