FHIR-46418: Audit vital signs profile rework

Issue request:
FHIR-46418 was an Applied/Persuasive OO change request to re-work the core Observation Vital Signs profiles for R6. The request asked to remove LOINC "magic value" wording, move the then-described interoperability category from Observation.code to category, create specific vital-sign LOINC value sets with preferred Observation.code bindings, rename the main page and base profile, move the base-profile link to a more prominent place, and update examples. The Jira resolution says the work was pre-applied and any new text changes would be tracked in other Jiras.

Initial application:
The seed was initially applied in git commit 71babbf5ac7b and a cluster of follow-up FHIR-46418 commits through e1802f1bca, which changed the vital signs implementation guide, examples, StructureDefinitions, and value set definitions. Those commits introduced the profile/value-set rework and resolved early tooling issues with value set expansion.

Additional context:
The source files are active build inputs: source/fhir.ini includes Observation, source/observation/list-Observation-packs.xml includes ImplementationGuide/Observation-vitalsigns, and that IG is marked core and references the vital-signs StructureDefinitions. After the seed application, the category-vs-code part of the design was explicitly revisited. FHIR-45617 was Applied/Not Persuasive with Modification, rejecting the breaking move from code to category while requiring guidance and preferred broader LOINC bindings, and FHIR-49953 was Applied/Persuasive with a resolution saying that the move back to code was handled by FHIR-45617. Commit 66a80b5fef2c moved the "interoperability standard" code from category back to Observation.code. FHIR-44798 later replaced remaining "magic code" resolution wording with "Interoperability Standard" Code. Zulip and OO minutes show the same debate and do not identify a later source requirement contrary to the current code-based profile design.

AutoFHIR reconciliation:
This commit intentionally makes no source changes. Current source already uses "interoperability standard" terminology rather than "magic value", keeps the standardized LOINC code in Observation.code according to the later final decisions, gives the base and specific profiles preferred Observation.code bindings to the relevant vital-sign value sets, titles the shared profile "Vital Signs Base Profile", titles the IG page "Observation Vital Signs Profiles", links the base profile prominently in the page introduction, and includes examples with the vital-signs category plus Observation.code codings.

Recommendation:
Keep this audit commit as-is. No FHIR core source change is needed for FHIR-46418 because applying the seed literally would now undo later Applied OO decisions; any future change to move vital-sign standard codes between Observation.code and Observation.category should be handled by a new work-group decision.
