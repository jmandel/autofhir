FHIR-8687: Audit schematron generation fixes

Issue request:
FHIR-8687 was a Published/Persuasive DSTU1 FHIR-core correction for generated Schematron output. It reported redundant rule contexts such as `//name`, incorrect `f:div` handling for `Narrative.div` where XHTML requires `h:div`, and incorrect choice-element paths for Quantity-flavor choices such as `Timing.repeats.bounds[x]`, which was expected to use the Quantity base name in the then-current generator.

Initial application:
The Jira comment says items #2 and #3 were applied in SVN revision 6985, and git-svn commit da4ec94bd876232cb7fbccd56bf542fe9cd81e28 is the matching `#8687 - fix schematron generation` implementation. That commit changed the old core SchematronGenerator to map constrained choice types through their base type and to use `h:div` for div paths. A follow-up same-day commit, 1a3b080e4f1fc3fe5f16b881eec9d82087b38ebb, is explicitly labeled `#8687 - fix schematron generation - fix consequences`. Lloyd later commented in Jira that the remaining redundant-context item appeared to have been done.

Additional context:
The current HL7/fhir checkout no longer contains the old Java SchematronGenerator/ProfileUtilities tooling source that was changed in 2015, but current source still publishes XML Schema/Schematron artifacts through active build-scoped inputs. `source/fhir.ini` keeps Narrative as active infrastructure source, `source/downloads.html` publishes validation schemas including Schematron, and `source/validation.html`/`source/xml.html` describe the generated Schematron files. Current source and generated output have moved on from DSTU1 naming details: current Timing XML uses `boundsDuration` intentionally, and no current generated Schematron rule path was found that recreates the old `boundsDuration`/`boundsQuantity` bug.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The historical generator fix was applied, the old editable generator is no longer in this checkout, and a current build.fhir.org validation-schema check found 128 generated `.sch` files with zero `//...` rule contexts, `h:div` used in global element assertions, and no `f:div` usages.

Recommendation:
Keep this no-change audit commit. If a current generated Schematron artifact regresses, investigate the current FHIR build/publisher tooling, but do not edit current core specification source for this already-applied DSTU1 generator issue.
