FHIR-13646: Audit quantity system search clarification

Issue request:
FHIR-13646 was a Published/Persuasive FHIR-I change request from STU3 asking the core search page to explicitly clarify Quantity search behavior: when a quantity search value includes a system, the search should use the coded Quantity.system/Quantity.code form rather than the human Quantity.unit display, while a systemless code search may match either Quantity.code or Quantity.unit.

Initial application:
The issue was applied in git commit fe49f5736558e8ba99509de97187a447a9c0fbb9 (svn revision 13374, "GF#13646 - clarifications about searching quantity"), which updated source/search.html to identify the system/code example as matching Quantity.code and added explanatory prose that system+code implies a precise code-system match where searching the human unit display is inappropriate.

Additional context:
The linked 2017 implementers Zulip thread confirms the original interpretation and tracker creation: Michael Calderero asked whether a supplied system means matching only Quantity.code while omitting system allows Quantity.code or Quantity.unit, and Eric Haas/Lloyd McKenzie agreed that this needed clarification. Later Published issue FHIR-19597 refined the systemless side of the same rule by adding explicit syntax bullets; it is already represented on the combined branch and should not be duplicated here. No Confluence reference or later community record found in this investigation contradicts the Jira/source conclusion.
