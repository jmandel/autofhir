FHIR-3521: Audit v3 codesystems link separators

Issue request:
FHIR-3521 was a Published/Persuasive technical correction against the FHIR-core downloads page for DSTU1. It reported that the nightly valuesets download's v3-codesystems.xml <link> references used nonstandard backslashes and asked that they be changed back to forward slashes.

Initial application:
The Jira comments cite svn revision 3024. In the git-svn history, commit ef3b686fb9da9620a906b12850978179ab3de6f9 on 2014-10-14 is that revision and is titled "task 3521: fix slashes in atom feeds". It changed the old Java Publisher generator so the v3 code-system and v3 value-set atom feed path links used a literal "/" instead of File.separator.

Additional context:
The current FHIR source no longer contains v3-codesystems.xml or the old tools/java Publisher.java generator that produced the affected atom feed. The current downloads page is still an active build page through publish.ini and source/hierarchy.xml, but it now offers definitions and NPM packages rather than the old v3-codesystems.xml download. Current source searches found no v3-codesystems references and no XML/HTML link href values containing backslashes. Jira searches found only FHIR-3521 for the v3-codesystems/backslash wording, and Zulip/Confluence searches found no conflicting community context.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The requested correction was applied in the historical generator, and the affected generated artifact/generator is not part of the current build surface, so there is no current source defect to fix.

Recommendation:
Keep this no-change audit commit. No follow-up is needed for the current core build unless a future publisher reintroduces a v3-codesystems atom feed, in which case its link paths should continue to be generated with URL forward slashes rather than platform file separators.
