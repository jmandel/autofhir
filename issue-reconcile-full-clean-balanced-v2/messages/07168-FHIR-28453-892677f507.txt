FHIR-28453: Audit OperationDefinition copyright element

Issue request:
FHIR-28453 was a Published/Persuasive FHIR-I change request asking that OperationDefinition have a copyright element like StructureDefinition and other CanonicalResource-derived artifacts, with the resolution to add it as defined in CanonicalResource.

Initial application:
The issue was explicitly applied by git commit b2e9e2a04fe35a343723dc221228a4c5f8679fa3, which added OperationDefinition.copyright to source/operationdefinition/structuredefinition-OperationDefinition.xml as a 0..1 markdown element mapped to Definition.copyright. No earlier application was found before that Jira-tagged commit.

Additional context:
FHIR-I minutes from 2021-01-04 record the rationale and vote: because the CanonicalResource pattern does not guarantee its elements show in child resources, copyright should be added to OperationDefinition to emphasize the element's presence. The current source keeps OperationDefinition in the active [resources] list in source/fhir.ini, declares it with the CanonicalResource template/baseDefinition, and still contains OperationDefinition.copyright. Later copyright-family work added copyrightLabel and refined the copyright wording, but did not remove or contradict the FHIR-28453 element.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active OperationDefinition source already satisfies the published decision: OperationDefinition.copyright is present with cardinality 0..1, type markdown, Definition.copyright mapping, and CanonicalResource-aligned copyright semantics.

Recommendation:
Keep this audit commit as-is. No current FHIR core source follow-up is needed for FHIR-28453 unless a future work-group decision changes the broader CanonicalResource copyright model.
