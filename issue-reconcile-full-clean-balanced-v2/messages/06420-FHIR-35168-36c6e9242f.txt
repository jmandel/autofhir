FHIR-35168: Clarify fhirVersion definitions

Issue request:
FHIR-35168 was Published with a Persuasive with Modification resolution for R5. It asked that the fhirVersion definitions in StructureDefinition and ImplementationGuide stop describing versions as [publication].[major].[minor] "without the revision number" and instead align with the updated major.minor.patch-label version semantics, with a link from the versioning page to the releases/versioning section and removal of obsolete current-build/DSTU notes.

Initial application:
The historical implementation commit 6f6a8881881a31a2ec13ae9d185200556d161b53 addressed the versioning narrative, HTTP version parameter, FHIRVersion code system, and bindings together with FHIR-26067. It did not touch source/structuredefinition/structuredefinition-StructureDefinition.xml or source/implementationguide/structuredefinition-ImplementationGuide.xml, and those build-scoped resource sources still contained the original [publication].[major].[minor] wording.

Additional context:
source/fhir.ini actively lists implementationguide=ImplementationGuide and structuredefinition=StructureDefinition, so both edited XML files feed the current build. The versions page now defines major.minor.patch-label and versioning.html already links to versions.html#versions. FHIR-35169 was later resolved Not Persuasive because FHIR-26067 already added major.minor version codes, so the replacement definitions describe FHIRVersion codes in a way that covers both major.minor release-line codes and full major.minor.patch versions with optional labels. The only remaining old wording found after this change is in generated-looking SVG diagram files, which are not authoritative source edits for this reconciliation.

AutoFHIR reconciliation:
Updated StructureDefinition.fhirVersion and ImplementationGuide.fhirVersion definitions to remove obsolete publication/major/minor and revision-number terminology, point to the FHIRVersion code system, give current examples for major.minor and major.minor.patch-label forms, and link to FHIR Releases and Versioning.

Recommendation:
Keep this source fix. It completes the unapplied part of the published FHIR-35168 decision in the authoritative resource definitions; generated diagrams should be regenerated by the normal build pipeline rather than hand-maintained as primary source.
