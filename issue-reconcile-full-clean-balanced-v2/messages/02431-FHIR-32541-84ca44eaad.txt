FHIR-32541: Audit ConceptMap dependsOn explanation

Issue request:
FHIR-32541 was Published/Persuasive for R5 and asked for ConceptMap dependsOn.property to be better explained: the dependency table heading should identify the value column, the usage note should say an application SHOULD provide the dependency value for $translate rather than MUST, $translate output should include dependsOn and product values, and the dependsOn.property definition should no longer rely on the confusing "information model" explanation.

Initial application:
The request was initially applied in git commit e3ad1adf05, which updated the ConceptMap2 dependency narrative and replaced the old dependsOn.property short and long definitions. Commit 8623473ddf later folded ConceptMap2 back into ConceptMap while preserving that application path in the active ConceptMap resource.

Additional context:
ConceptMap is active in source/fhir.ini. Later ConceptMap work changed the model from dependsOn.property to dependsOn.attribute backed by ConceptMap.additionalAttribute, so the current source should not exactly reintroduce the older property wording. FHIR-31515 supplied the explanatory dependsOn/product example expected by the FHIR-32541 comments, FHIR-33055 declined adding a separate model-dependency declaration, FHIR-37773 and FHIR-40636 refined the valueCode guidance, and FHIR-40504 aligned the active notes with the attribute/additionalAttribute model.

AutoFHIR reconciliation:
Made no source change. The active ConceptMap StructureDefinition now defines dependsOn.attribute as a reference to the additional attribute holding the value the map depends on, the ConceptMap notes explain target.dependsOn and target.product with a concrete example, state the SHOULD-level $translate input expectation, and state that all dependsOn and product values are included in $translate output. Reverting to the exact R5 resolution wording would conflict with later approved ConceptMap terminology.

Recommendation:
Keep this audit commit as-is. The current source satisfies the FHIR-32541 clarification after later ConceptMap model changes; any further editorial work should be handled under a new issue that accounts for the current additionalAttribute/attribute design.
