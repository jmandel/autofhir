FHIR-15739: Audit Task focus wording

Issue request:
FHIR-15739 was a Published/Persuasive STU3 Task clarification asking that Boundaries and Relationships stop saying operational detail is carried as the "subject" of the task and instead say it is carried in the referenced focus of the task.

Initial application:
The issue appears to have been applied in git-svn commit 2ebd7c6f7fc99b6938d5a223685af7907288d11c, which changed source/task/task-introduction.xml from "expected to be carried as the subject of the task" to "expected to be carried in the referenced `focus` of the task." Later Task introduction rewrites moved that language, but the current build-scoped Task introduction still says the detail is carried in the referenced focus of the task.

Additional context:
Task is an active resource in source/fhir.ini, so source/task/task-introduction.xml is in current build scope. FHIR-46344 later reintroduced and reaffirmed the same Boundaries and Relationships focus wording for R6, and FHIR-15561 added nearby guidance that entities being instantiated or modified should be pointed to by Task.focus. The current Task StructureDefinition defines Task.focus as the thing the task is acting on. Zulip and Confluence searches found no conflicting community record for FHIR-15739.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source no longer uses the misleading "subject" wording and conveys the approved focus-based clarification when read with the current Task.focus definition and nearby Task.focus guidance.

Recommendation:
Keep this no-change audit commit. No follow-up is needed for FHIR-15739; any future editorial polish to the literal phrase "referenced .focus" should be handled separately because it does not change the FHIR-15739 semantic outcome.
