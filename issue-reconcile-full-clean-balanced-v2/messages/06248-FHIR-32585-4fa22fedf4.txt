FHIR-32585: Audit DocumentReference related reconciliation

Issue request:
FHIR-32585 was a Published/Persuasive with Modification OO change request for R5 asking why DocumentReference had both related and relatesTo. The accepted plan was to remove DocumentReference.related, add DocumentReference to workflow-supportingInfo usage, and move the XDS mapping for related away from the old open-ended element.

Initial application:
The request was applied before this reconciliation. Commit 1211a3b963 removed DocumentReference.related from the active DocumentReference StructureDefinition and moved the example's former related Patient reference into the workflow-supportingInfo extension. The PR merge recorded in Jira, 333a55c82177, also removed the DocumentReference-related search parameter and added DocumentReference to the workflow-supportingInfo extension context list in the then-core workflow extension spreadsheet.

Additional context:
The current source intentionally no longer matches the R5-era removal literally. FHIR-41186 was later Applied to restore an arbitrary-resource context path for DocumentReference after implementers found the R5 removal too limiting; its application brought back related instead of widening context. FHIR-53824 and FHIR-53550 then retained related but changed it into a coded backbone with a Reference(Any) target, added notes that related is not for lifecycle relationships or for duplicating subject/context, and left relatesTo dedicated to document-reference lifecycle links. Those later issues are already represented on the combined branch, so this seed should not republish them. The workflow-supportingInfo extension is now maintained in the FHIR Extension Pack and still includes DocumentReference as an allowed context.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current build-scope core source has DocumentReference as an active OO resource, has relatesTo for lifecycle links, has related as the later approved coded non-lifecycle backbone, and indexes related.target. The Extension Pack's workflow-supportingInfo definition includes DocumentReference, and the core example still demonstrates that extension. Removing related again or moving the current XDS referenceIdList mapping back to workflow-supportingInfo would undo later final OO decisions.

Recommendation:
Keep this no-change audit commit. Any future desire to remove DocumentReference.related again, rename it, change the AssociatedReferenceType binding, or change how XDS referenceIdList maps should be handled by a new OO tracker because FHIR-32585 has been superseded by later applied DocumentReference decisions.
