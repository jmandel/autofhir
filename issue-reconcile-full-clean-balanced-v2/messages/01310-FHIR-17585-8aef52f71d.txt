FHIR-17585: Audit MeasureReport evaluatedResource clarification

Issue request:
FHIR-17585 was Published with a Persuasive with Modification resolution. It asked CQI to clarify that the $data-requirements operation defines the resources subsequently referenced in MeasureReport.evaluatedResource when measure data is submitted, with the original payer-specific language generalized to a receiver.

Initial application:
The issue was applied by 8d854b84c9770d784d04bb23ad834bfa5a3af032, "GF#17585: Clarified MeasureReport.evaluatedResources element", which added the requested data-requirements wording and matching submit-data guidance to source/measure/measure-spreadsheet.xml. The January 2021 source rework commits 33b409a4b6d544598262f2f074ebb4b6dc466157 and c69d71aa213de86d55e0261339c15e4bacd509e6 carried that spreadsheet content into the current OperationDefinition XML sources.

Additional context:
source/fhir.ini marks Measure and MeasureReport as active approved resources, so the current Measure operation definitions and MeasureReport StructureDefinition are in build scope. The current $data-requirements OperationDefinition says that the operation defines the resources subsequently referenced in MeasureReport.evaluatedResource when submitting measure data, and the current $submit-data OperationDefinition says the receiving system can use the submitted data for later quality-measure calculation and that data-of-interest can be determined from the measure definition or $data-requirements. A later Published issue, FHIR-34033, clarified the MeasureReport.evaluatedResource definition so individual reports reference subject-specific calculation resources and data-exchange reports reference data-of-interest submitted or collected for the measure; that later clarification is already represented on the combined branch and does not conflict with FHIR-17585.
