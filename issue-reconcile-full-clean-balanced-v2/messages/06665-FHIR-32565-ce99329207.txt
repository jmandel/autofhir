FHIR-32565: Audit Device element extension migration

Issue request:
FHIR-32565 is an Applied/Persuasive with Modification FHIR-core OO change request raised for R4. The final motion was to move Device.mode, Device.cycle, Device.duration, Device.gateway, and Device.endpoint into extensions, with any other candidate elements left for separate Jiras.

Initial application:
Core commit 9d3783acc0 for FHIR-48924 commented Device.mode, Device.cycle, and Device.duration out of source/device/structuredefinition-Device.xml. Core commit 2286646d6c for FHIR-48923 then commented Device.endpoint and Device.gateway out of the same active Device StructureDefinition source. Extension Pack work created the corresponding device-operation-mode, device-operation-cycle, device-operation-duration, device-gateway, and device-endpoint definitions, and the combined branch already includes the FHIR-48924 follow-up commit 3a2c936081 that corrected the active Device note to use the actual operation extension ids.

Additional context:
Device remains active in source/fhir.ini, so source/device/structuredefinition-Device.xml and source/device/device-introduction.xml are in current build scope. The old Device element definitions now appear only inside XML comments and are ignored by XML parsing/build processing, while the active Device ballot note says the five elements were removed and names the replacement extensions. The five replacement StructureDefinitions are maintained in the FHIR Extension Pack checkout, not as core StructureDefinitions. Confluence OO HCP minutes from 2024-09-30 record the same FHIR-32565 candidates and the 7-0-2 persuasive-with-modification motion; focused Zulip searches found no conflicting discussion.

AutoFHIR reconciliation:
Published an empty no-change audit commit. No core source edit is needed because the current core conformance surface no longer exposes Device.mode, Device.cycle, Device.duration, Device.gateway, or Device.endpoint, and the active Device note points implementers to the existing replacement extension ids.

Recommendation:
Keep this audit commit as-is. Future changes to the moved concepts should usually be made in the FHIR Extension Pack unless a later Jira asks for corresponding core Device narrative, mapping, or migration guidance changes.
