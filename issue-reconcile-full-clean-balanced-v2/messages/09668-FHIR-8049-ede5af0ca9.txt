FHIR-8049: Audit extension markdown support

Issue request:
FHIR-8049 was a Published/Persuasive FHIR-core request from the DSTU1 era to support rich XHTML-like narrative content in extensions. The final Jira record includes a reopened decision to create a markdown datatype, document graceful fallback, use it for extensions and ElementDefinition, and also preserves older wording about exposing xhtml for Extension.

Initial application:
The exact Jira-tagged source application is commit 05495454879b7561aecb912e59d065b6354b4681, which added the markdown datatype documentation and added markdown to the Extension value type list. A companion generated-code commit, a3551b9aeacb5ad61ce1d34b06ab7a62fa493d5c, added the Java MarkdownType. No FHIR-8049-tagged commit added xhtml as a normal Extension.value[x] type.

Additional context:
The current build-scope Extension definition is active through source/fhir.ini's infrastructure/type-page entries and source/datatypes/extension.xml defines Extension.value[x] with the wildcard type list. Current CI output expands that list to include markdown and not xhtml. Later Jira decisions refined the model: FHIR-34314 clarified xhtml as special narrative content rather than an ordinary defined datatype, and FHIR-9693 created paired rendering-xhtml/rendering-markdown extensions for string display markup. The Extension Pack now carries those rendering extensions; rendering-xhtml constrains a string value with narrative XHTML checks rather than making xhtml a base Extension.value[x] datatype.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source preserves the applied markdown support from FHIR-8049, and adding a base valueXhtml choice now would conflict with later datatype and rendering-extension decisions.

Recommendation:
Keep this audit commit as-is. Do not add xhtml to Extension.value[x] for this historical issue. If a work group wants broader XHTML-bearing extension values beyond the existing rendering-xhtml mechanism, that should be raised as a new current-scope issue, likely involving the Extension Pack.
