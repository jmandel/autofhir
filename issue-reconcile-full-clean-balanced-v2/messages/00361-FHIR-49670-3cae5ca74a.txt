FHIR-49670: Audit MeasureReport linking clarification

Issue request:
FHIR-49670 was Applied with a Persuasive with Modification resolution for R6. It asked to clarify how MeasureReport group, population, stratifier, and supplementalData content corresponds to the Measure being reported, including preservation of codings and descriptions where the MeasureReport model has corresponding elements.

Initial application:
The issue was applied by commit 70bdb0961beee8ce56803a076c9d26d9677ff391 and merged through HL7/fhir#3423. That commit updated the active MeasureReport StructureDefinition definitions for group, group.linkId, group.code, group.description, group.population, group.population.linkId, group.population.code, group.population.description, group.stratifier, group.stratifier.linkId, group.stratifier.code, group.stratifier.description, stratifier component linkage/code/description, and stratum population linkage/code. No prior Issue-Reconcile-Key audit commit existed on the combined branch.

Additional context:
Measure and MeasureReport are active resources in source/fhir.ini. The current MeasureReport supplementalData element remains a Reference(Resource), consistent with the related FHIR-33192 decision to remove the proposed breaking supplementalDataElement/code/description backbone and leave supplementalData as a reference. FHIR-37559 and current quality-reporting narrative explain that supplemental data is reported through MeasureReport.supplementalData references, with summary supplemental data represented as contained Observations whose Observation.code corresponds to Measure.supplementalData.code. Later FHIR-50488 adds additional supplementalData inputs to Measure $evaluate, but reports them using the same MeasureReport supplementalData model.

AutoFHIR reconciliation:
This audit commit makes no source change. The active source already has the required MeasureReport group/population/stratifier correspondence, code-coding, and description guidance, and the supplementalData behavior is covered by the existing reference-based MeasureReport element plus quality-reporting narrative rather than by a non-existent MeasureReport.supplementalData.code or .description element.

Recommendation:
Keep this no-change audit. Do not add a core MeasureReport supplementalData code/description/linkId structure under this issue; that would conflict with the FHIR-33192 reversal and would require a separate work-group decision if stronger supplementalData linkage is desired.
