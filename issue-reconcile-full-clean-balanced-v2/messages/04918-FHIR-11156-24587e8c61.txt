FHIR-11156: Audit Condition category resolution

Issue request:
FHIR-11156 was a Published Patient Care change request, resolved Persuasive with Modification, asking to add problem/issue concepts to Condition.category because the then-current complaint | symptom | finding | diagnosis set did not cover all conditions of concern. The approved September 2016 WGM resolution instead made Condition.category 0..* CodeableConcept with an example binding to a FHIR-defined value set containing Encounter Diagnosis and Problem List Item.

Initial application:
The current branch has no commit explicitly naming FHIR-11156, but the same WGM Condition.category resolution family was applied in git commit bffc717a99. That commit changed the Condition category code system from complaint/symptom/finding/diagnosis to problem-list-item and encounter-diagnosis, changed Condition.category from 0..1 to 0..*, changed the binding from preferred to example, and updated examples to use the two approved codes.

Additional context:
Condition is active in the current build, and the current StructureDefinition still has Condition.category as 0..* CodeableConcept with an example binding to ValueSet/condition-category. The current ValueSet includes the terminology.hl7.org condition-category code system rather than enumerating local codes. Later approved work changed the current interpretation: FHIR-48358 and UP-635 added diagnostic-report-impression as a peer to the existing two category codes, kept the example binding, and removed the old con-2 warning; FHIR-54454 then deliberately replaced the short display's code list with broader wording because listing values is misleading for an example binding.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already carries the substance of FHIR-11156's final resolution when read with the related 2016 Condition.category decisions and the later approved R6 terminology update. Adding literal problem or issue codes, or restoring a two-code short display, would conflict with the actual approved resolution and later Jira decisions.

Recommendation:
Keep this no-change audit commit as-is. No core source follow-up is recommended for FHIR-11156; future work on the condition-category code system should follow the UTG/terminology process rather than reopen this 2016 core issue.
