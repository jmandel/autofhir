FHIR-11247: Audit profile maturity model support

Issue request:
FHIR-11247 is Published/Persuasive and asked to add a maturity model for profiles. Its Jira resolution delegates the substantive decision to FHIR-11245, whose accepted resolution was to let spreadsheets/XML-authored artifacts declare FMM levels and to have tooling expose FMM levels on extensions and profiles that choose to declare them.

Initial application:
No current git commit explicitly names FHIR-11247, matching the Jira comment that points to SVN work recorded under FHIR-11245. The December 2016 imported history around the cited SVN revisions includes commits such as 8bffa4f35aba636d69f24fbf71e9d57b5686b6bf, which added profile/extension FMM/status rendering to profile templates and publisher/profile parsing code, and 361b374c6d228a8b6a69d4d1bbcb2d1931f30c3c, which continued the StructureDefinition extension/workgroup support.

Additional context:
Current source has moved the profile and extension templates to tools/templates, but those templates still include the FMM/status table hooks for profile and extension pages. The active profile inputs are listed in source/fhir.ini, while the canonical structuredefinition-fmm extension definition now lives in the FHIR Extension Pack and permits StructureDefinition/DomainResource use. Current versions.html documents the FHIR Maturity Model and points to the FMG Confluence page as the maintained source of truth. No relevant Zulip or Confluence references were found that would narrow or reverse this historical application.

AutoFHIR reconciliation:
This audit commit makes no source change. The current build already preserves the mechanism requested by FHIR-11247 through profile page status/FMM rendering hooks and the canonical FMM extension; assigning new FMM values to specific profiles would be a separate, artifact-specific decision not requested by this Jira.

Recommendation:
Keep this no-change audit. Future work should only edit source if a specific active profile is approved for a changed FMM value or if the external Extension Pack definition needs a scoped update; neither condition is established by FHIR-11247.
