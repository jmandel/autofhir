FHIR-20671: Audit Timing text guidance

Issue request:
FHIR-20671 was a Published FHIR-core datatypes change request, resolved Not Persuasive with Modification, asking whether Timing needed a subelement such as description or displayName for text like "TID, for 14 days". The approved resolution was to rely on existing Timing.code.text guidance and make that guidance, example, and following paragraph more prominent by moving them before the examples table.

Initial application:
The R5 MnM source commit 5cbc14c7d0f361941099bf72066b75c3f74f6d4f explicitly listed FHIR-20671 and moved the Timing.code.text paragraph and JSON example above the common Timing examples table in source/datatypes.html. Current blame keeps the moved guidance at that location, with only later unrelated wording cleanup around it.

Additional context:
FHIR-13941 had already established the same approach for a Timing.text request: use Timing.code.text and document examples rather than adding a new datatype element. FHIR-53411 later removed an inaccurate sentence from the same Timing paragraph but preserved the Timing.code.text solution. MnM minutes for the May 2019 WGM record FHIR-20671 as Not Persuasive with Modification, and searches found no Zulip or Confluence evidence contradicting the Jira/source conclusion.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The active datatypes source already explains that free-text timing instructions map to Timing.code.text, shows the example before the Timing examples table, and the Timing spreadsheet defines Timing.code as CodeableConcept with text in code.text available.

Recommendation:
Keep this no-change audit as-is. Do not add a Timing.description or displayName element for FHIR-20671; future edits should only revisit Timing wording if a later work-group decision changes the Timing.code.text approach.
