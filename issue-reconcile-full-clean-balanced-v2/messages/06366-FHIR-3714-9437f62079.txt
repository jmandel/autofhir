FHIR-3714: Audit Procedure self-performer support

Issue request:
FHIR-3714 was a Published FHIR-core Procedure change request, resolved Persuasive with Modification, asking whether Procedure can represent procedures performed by the patient, such as peritoneal dialysis or wound care, and concluding that Procedure.performer should allow Patient and RelatedPerson performers.

Initial application:
The request was applied in the historical source as SVN revision 4379, migrated to git commit 5eed76a7662fea3230578b81d9edff1be6205a61, which changed the Procedure spreadsheet performer type from Reference(Practitioner) to Reference(Practitioner|Patient|RelatedPerson).

Additional context:
Procedure is active in the current build through source/fhir.ini. The authoritative current Procedure StructureDefinition has Procedure.performer.actor as Reference(Practitioner, PractitionerRole, Organization, Patient, RelatedPerson, Device, CareTeam, HealthcareService), keeps Procedure.encounter optional, and has a separate optional Procedure.location for where the procedure happened. Later Procedure performer work in FHIR-32507 constrained onBehalfOf for Practitioner/PractitionerRole but preserved Patient and RelatedPerson as performer actors. Searches found no Zulip or Confluence evidence that conflicts with the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change because the current source already satisfies the issue: patients and caregivers can be documented as Procedure performers, and Procedure is not required to be tied to an encounter.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-3714 unless a future Patient Care decision changes Procedure.performer.actor target profiles.
