FHIR-8726: Audit ValueSet filter modifier supersession

Issue request:
FHIR-8726 was Published with a Persuasive with Modification resolution asking that ValueSet.compose.include.filter be changed to a modifier because changing or including filters changes the meaning of a ValueSet.compose include.

Initial application:
The request was applied by git commit 5715c087c0 (svn r11118), which flagged ValueSet.compose.include.filter as a modifier in source/valueset/valueset-spreadsheet.xml and moved that status from filter.op to the filter backbone.

Additional context:
Later vocabulary decisions reversed this portion of the model. FHIR-13070 was Published/Persuasive and explicitly agreed that ValueSet.compose.include.filter should not be a modifier; git commit 00093bc6b3 (svn r13318) removed the modifier flag. FHIR-15586 was later Published/Persuasive with Modification and again included removal of the ValueSet filter modifier while separately asking for a ConceptMap modifier reason. The current ValueSet StructureDefinition is in active build scope via source/fhir.ini and has no isModifier on ValueSet.compose.include.filter.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding the modifier flag requested by FHIR-8726 would contradict the later FHIR-13070 and FHIR-15586 decisions and the current built source.

Recommendation:
Keep this audit as-is. Do not reapply FHIR-8726 in isolation; use FHIR-13070 and FHIR-15586 as the later controlling decisions for ValueSet.compose.include.filter.
