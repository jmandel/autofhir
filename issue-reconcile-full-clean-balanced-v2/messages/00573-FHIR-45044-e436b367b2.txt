FHIR-45044: Correct ImagingSelection seriesUid requirement reference

Issue request:
FHIR-45044 was an Applied/Persuasive FHIR-core ImagingSelection change request raised for R6. It asked to add textual constraints saying that seriesUid must identify a series within studyUid, instance.uid must identify an SOP Instance within seriesUid, and the related series/instance numbers must correspond to their UID elements.

Initial application:
The issue was applied in git commit a9b193fe26ebac455ff45f606bd759a9df076e32, which added requirements text for ImagingSelection.seriesUid, ImagingSelection.seriesNumber, ImagingSelection.instance.uid, and ImagingSelection.instance.number. Later ImagingSelection edits preserved the requested relationship text, but the instance.uid requirement still referred to the FHIR element as `seriesUID` instead of the actual element name `seriesUid`.

Additional context:
ImagingSelection is an active current-build resource in source/fhir.ini, so source/imagingselection/structuredefinition-ImagingSelection.xml is the authoritative source. Later commits for FHIR-48101 and FHIR-48106 reorganized related ImagingSelection constraints and corrected the same casing pattern for seriesNumber, while FHIR-51645 adjusted the instance.uid definition without changing this requirement. Zulip and Confluence searches found no directly relevant FHIR-45044 discussion or minutes changing the Jira/source conclusion.

AutoFHIR reconciliation:
This commit changes only the ImagingSelection.instance.uid requirements text from `seriesUID` to `seriesUid`, aligning the textual constraint with the actual FHIR element name. The other requested requirements text is already present and left unchanged.
