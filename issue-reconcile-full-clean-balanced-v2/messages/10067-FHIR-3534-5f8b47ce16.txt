FHIR-3534: Audit schema localization support

Issue request:
FHIR-3534 was a Published/Persuasive with Modification change request for formal i18n/l10n support in FHIR schemas and schematrons. The accepted resolution was to declare xml:lang on each xs:documentation repetition, and the Jira application comment records that the change was applied to schema while multi-language invariant/schematron translations were not added.

Initial application:
The historical git-svn commit 6afec1f8ed93fe2aa5394eb48033461dd77dca6a, "#3534 - schema support for xml:lang", matches Jira's svn revision 5562 application note. It changed the then-current Java XSD generators to emit xml:lang="en" on generated xs:documentation entries and to emit additional localized documentation/designation repetitions when language data was available.

Additional context:
The current core checkout still builds and publishes XML schema and Schematron artifacts through the active resource/infrastructure inputs and schema download pages, but the old Java generator source modified in 2015 no longer lives in this checkout. Current build output from fhir-all-xsd.zip has xml:lang on every FHIR-generated xs:documentation entry checked. The support schemas xml.xsd and fhir-xhtml.xsd contain documentation inherited under schema-level xml:lang="en" and were not the target of the historical FHIR generator fix. No Zulip or Confluence record was found that broadens the applied issue beyond the schema change recorded in Jira.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current generated FHIR XML schemas already preserve the approved localization mechanism for FHIR-generated documentation, and adding redundant source edits or new Schematron localization machinery would go beyond the applied Published decision.

Recommendation:
Keep this no-change audit commit. Open a new work-group issue only if FHIR-I wants to revisit Schematron/invariant message localization or require per-documentation xml:lang on copied support schemas despite their inherited schema-level language.
