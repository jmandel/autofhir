FHIR-14645: Audit CodeSystem supplement rules

Issue request:
FHIR-14645 was a Published/Persuasive vocab change request from the STU3 cycle asking to document the Connectathon resolution for CodeSystem supplements: a supplement identifies the supplemented CodeSystem, its own CodeSystem.url is not usable as Coding.system, its url must be controlled by the supplement publisher, and it cannot define new CodeSystem.concept.code values outside the supplemented code system.

Initial application:
The issue was applied by commit cc2be16424d331f7048ebe12272002e9a06734d1, matching the Jira comment for SVN revision 13083, which added the Code System Fragments and Code System Supplements narrative to source/codesystem/codesystem-notes.xml. Later cleanup removed the duplicate Coding.system bullet while preserving the four substantive supplement rules.

Additional context:
CodeSystem is an active resource in source/fhir.ini, so source/codesystem/codesystem-notes.xml and source/codesystem/structuredefinition-CodeSystem.xml are current build inputs. FHIR-33319 later converted one FHIR-14645 narrative rule into the formal csd-4 invariant that content = 'supplement' implies CodeSystem.supplements exists. FHIR-14356 and FHIR-16832 changed the same supplement section's standards-status and expansion-warning context without reversing the FHIR-14645 rules. Zulip discussion since then confirms the authority rule and ongoing operational questions, but does not create a conflicting final decision.

AutoFHIR reconciliation:
No source change was made. The current active source already says that content = supplement describes a code system supplement, requires CodeSystem.supplements, prohibits using a supplement url as Coding.system, requires publisher control of the supplement url, and prohibits supplements from defining new concept codes. Adding a new reciprocal invariant for CodeSystem.supplements.exists() would be a new conformance rule beyond the applied issue and later approved invariant.

Recommendation:
Keep this audit commit as-is. If the work group wants to formalize a reciprocal supplements/content invariant or polish the existing parenthetical wording, that should be handled as a separate terminology tracker because the current source already implements the applied FHIR-14645 semantics.
