FHIR-34407: Audit ClinicalDocument profile removal

Issue request:
FHIR-34407 was an Applied FHIR-core / Structured Documents change request with resolution Not Persuasive with Modification. The issue initially asked to re-align the ClinicalDocument profile with CDA after Composition changes, but the final SDWG decision was to remove the ClinicalDocument profile entirely because its only meaningful contribution, the composition-clinicaldocument-versionNumber extension, had been replaced by the base Composition.version element; the resolution also called for deleting that extension.

Initial application:
The issue was applied in core history rather than by this reconciliation. Commit 938bdf21940e09a728baa17dc0060c413a0054c7, titled "J#34407 Remove the ClinicalDocument Composition profile entirely", deleted source/composition/implementationguide-composition-clinicaldocument.xml and source/composition/structuredefinition-profile-clinicaldocument.xml. Earlier surrounding commits dd468d4f1799dd79819315b211588ef1cf4586e0 and 3a5b06b66d70b43948f87f2cd0d141e83f17268c removed the core Composition extension source and the profile's versionNumber slice/reference.

Additional context:
Current source/fhir.ini has no active ClinicalDocument profile entry, the removed ClinicalDocument profile files are absent, and the base Composition source contains Composition.version mapped to CDA versionNumber. SDWG minutes from September 2022 record the 6-0-0 motion to delete both the profile and the composition-clinicaldocument-versionNumber extension. February 2024 SDWG minutes later confirm FHIR-34407 was applied and removed from the current build. The companion FHIR-38201 trail explains why the extension still exists in the separate FHIR Extension Pack: it is constrained to pre-R5 use because Composition.version exists in R5+.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core build no longer contains the ClinicalDocument profile or a core source definition for composition-clinicaldocument-versionNumber, and adding or removing remaining CDA mapping prose or OID registry entries would not implement the Jira decision.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed for FHIR-34407; any future ClinicalDocument profile should be handled as a new SDWG project, and any additional extension-pack policy change should be handled in the FHIR Extension Pack repository.
