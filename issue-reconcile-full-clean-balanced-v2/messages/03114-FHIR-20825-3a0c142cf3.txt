FHIR-20825: Audit PlanDefinition actor/function model

Issue request:
FHIR-20825 was Published/Persuasive with Modification for R5. The request started as adding PlanDefinition.action.participant.function, and the accepted resolution broadened that to introduce PlanDefinition.actor for actors involved in a plan, with labels/descriptions/options, and to revise PlanDefinition.action.participant so actions can identify the participating actor and the actor's function such as author, reviewer, or witness.

Initial application:
The issue was explicitly applied by c68fb1d080 (J#20825: Added actor and participant.function to PlanDefinition). That commit added PlanDefinition.actor, actor title/description/options, PlanDefinition.action.participant.actorId, PlanDefinition.action.participant.function, and the action participant function code system/value set. It also made action.participant.type optional so a participant can be represented through a referenced actor rather than only an inline type.

Additional context:
Workflow and CDS meeting records show the issue came from PlanDefinition workflow-conformance modeling, with the actor concept discussed as swimlane-like workflow actors and then approved by CDS on 2020-09-22. Later participant-model work changed the exact shape from the Jira resolution prose: f83e1f04c1 converted participant typing toward choice-based definitional/reference options, subsequent R5/R6 commits added CapabilityStatement, DeviceDefinition, Endpoint, ActorDefinition, and other participant targets, and c3a6fdf8e8 renamed the function terminology to the current example value set. These later changes preserve the core FHIR-20825 semantics while explaining why current action.participant.actorId and actor.option.type are optional alongside type/typeCanonical/typeReference alternatives.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. PlanDefinition is active in source/fhir.ini, and current source/plandefinition/structuredefinition-PlanDefinition.xml already contains PlanDefinition.actor with title, description, option, type/typeCanonical/typeReference, and role; PlanDefinition.action.participant already contains actorId and function; and the function binding resolves to the current action-participant-function-example ValueSet/CodeSystem source. Adding a new source hunk would either duplicate existing definitions or incorrectly undo later participant-model decisions.

Recommendation:
Keep this no-change audit commit. Revisit only under a separate work-group decision if PlanDefinition.action.participant.actorId should become mandatory, if the FHIR-42717 ActorDefinition-specific shape needs further reconciliation, or if future participant-model policy changes the choice-based actor/participant design.
