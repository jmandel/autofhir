FHIR-17354: Request Pharmacy review of v2 dosage and timing mappings

Issue request:
FHIR-17354 was a Published/Persuasive Pharmacy change request asking to add HL7 v2 mappings for the Dosage and Timing FHIR data types, with the approved resolution "Agree will add mappings for V2 for dosage and timing."

Initial application:
The Jira application comment points to merge commit 7a787c5ab6, which merged PR HL7/fhir#183 for GF 19517, GF 19485, and GF 17354. The first-parent diff from that merge added v2 mapping cells to source/datatypes/dosage.xml for Dosage sequence/text/additionalInstruction/patientInstruction/asNeeded/site/route/method/doseAndRate/dose/rate/maxDosePerPeriod-era rows, but it did not change source/datatypes/timing.xml.

Additional context:
Current build-scope source still has active datatype/dosage page configuration in source/fhir.ini, source/dosage-mappings.html renders <%dtmappings Dosage%>, and source/datatypes-mappings.html renders <%dtmappings Timing%>. Current Dosage source preserves many v2 mapping values from the 2018 application, but Dosage.timing has an empty v2 Mapping cell while a neighboring unpublished/unknown mapping column contains "TQ1-X / ORC Quantity/timing". Current Timing source has a v2 Mapping column but only maps the root Timing row to "N/A"; detailed Timing rows such as repeat/count/frequency/period/when/code have no v2 mapping entries. The reporter's post-application Jira comment and related Zulip discussion show that v2 TQ/TQ1/RX* medication timing mapping remained non-obvious and included possible corrections, but no later final Pharmacy decision was found that safely specifies the missing Timing mapping table or the disputed Dosage corrections.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Adding or moving v2 mappings for Timing/TQ/TQ1 or changing disputed Dosage mappings would be a normative mapping decision rather than a mechanical reconciliation, and the available evidence does not provide enough approved detail to edit the current build safely.

Recommendation:
Keep this audit commit as a human-review marker. Pharmacy or a mapping specialist should decide whether current FHIR should add detailed Timing v2/TQ/TQ1 mappings, move or clarify the existing Dosage.timing "TQ1-X / ORC Quantity/timing" value into a published mapping column, and address the reporter's post-application concerns about RXE/RXO/TQ field choices before any source-changing commit is made.
