FHIR-55268: Clarify NutritionProduct status guidance

Issue request:
FHIR-55268 was Applied with resolution Persuasive with Modification. It asked for an escape valve because NutritionProduct.status was mandatory, used a required binding, and the value set had no unknown or other code. The accepted resolution was to change NutritionProduct.status cardinality to 0..1, consistent with similar status elements.

Initial application:
The Jira-applied commit 3b2d08c1b61cc0418e57e120f851ed6ab991c8d3 changed NutritionProduct.status from min=1 to min=0 in source/nutritionproduct/structuredefinition-NutritionProduct.xml. The current branch already contains that implementation and the active build configuration lists nutritionproduct=NutritionProduct.

Additional context:
The status code system still contains only active, inactive, and entered-in-error, so adding unknown or other was not the applied resolution. However, the status element retained stale boilerplate saying that Unknown is used when the authoring system is not sure what the current status is. That text became misleading after the accepted escape valve was optional cardinality, because no unknown code exists in the required value set. OO minutes for 2026-02-25 reference FHIR-55268 but do not add conflicting instructions; targeted Zulip and Confluence searches found no contrary discussion. A later same-day NutritionProduct source reorder under FHIR-53526 touched the same file, but the current merged source still preserves the FHIR-55268 min=0 cardinality.

AutoFHIR reconciliation:
This commit keeps NutritionProduct.status optional and keeps the required binding to the existing Nutrition Product Status value set. It narrows the element comment to say that, when the optional element is populated, one of the defined statuses must apply, removing the impossible guidance to use an unknown status code.

Recommendation:
Keep this commit as a source fix. If the work group later wants an explicit unknown or other code instead of optional status, that should be handled by a new terminology/cardinality decision because it would differ from the applied FHIR-55268 resolution.
