FHIR-12255: Audit MedicationStatement reason invariant removal

Issue request:
FHIR-12255 was a Published/Persuasive Pharmacy change request for DSTU2 MedicationStatement. It asked to remove mst-2 and mst-3 because MedicationStatement.reasonForUse recorded the intended reason for the medication and should remain valid even when the medication was not actually taken.

Initial application:
The issue was applied in git commit 0e9aa872c529a491a7acec3f5a008250c5a0c184, "GForge #12255, and QA item for MedicationStatement", which removed the two spreadsheet invariant rows that allowed reasonForUseCodeableConcept and reasonForUseReference only when notTaken was No. No Jira-tagged source change remains missing for the old invariant text.

Additional context:
MedicationStatement is active in the current build through source/fhir.ini. Current source no longer has reasonForUse or wasNotTaken; later source history renamed reasonForUseCodeableConcept/reasonForUseReference to reasonCode/reasonReference and then the current build merges those into MedicationStatement.reason. The current reason definition explicitly covers why the medication is being/was taken or not taken, while adherence.reason separately covers non-use/adherence reasons. Jira FHIR-11091 was a nearby naming-consistency issue but does not require restoring the removed FHIR-12255 restriction.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current authoritative MedicationStatement StructureDefinition has no mst-2/mst-3 constraint or equivalent reason-vs-notTaken/wasNotTaken gate, and a current source grep found no stale copy of the removed invariant text.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed in core for FHIR-12255 unless a future Pharmacy decision intentionally changes the semantics of MedicationStatement.reason or MedicationStatement.adherence.reason.
