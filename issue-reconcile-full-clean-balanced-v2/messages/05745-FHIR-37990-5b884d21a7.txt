FHIR-37990: Audit token id pipe restriction

Issue request:
FHIR-37990 was a Published FHIR-core search-page change request, resolved Persuasive for R5, asking that the token search parameter type documentation extend the existing no-pipe restriction for ContactPoint, uri, and boolean targets to targets of datatype id because _id is a token parameter over logical ids.

Initial application:
The issue was applied by commit 7f8767e5b763626bfd9bbb9ed4952fcec9acb325, which updated source/search.html to add ids to the introductory token discussion and to the token notes forbidding pipe syntax where no system portion applies.

Additional context:
The current active search page source still contains the applied id wording. Earlier FHIR-14237 established the same no-pipe rule for ContactPoint, uri, and boolean, while FHIR-13320 is related background for _id token semantics and case sensitivity. The FHIR-I 2022-08-29 minutes record the Persuasive 15-0-0 vote for FHIR-37990, and no direct Zulip or Confluence conflict was found.

AutoFHIR reconciliation:
No source change was made. The current source/search.html token section already says ids are among token targets where the URI/system portion is not used, and its conformance note says token parameters on id, ContactPoint, uri, or boolean SHALL NOT use the pipe symbol and only the [parameter]=[code] form is allowed.

Recommendation:
Keep this audit commit as-is. No further core-spec work is needed for FHIR-37990 unless a future FHIR-I decision changes token syntax for id-valued search parameters.
