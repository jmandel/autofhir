FHIR-26643: Audit confidential extension location

Issue request:
FHIR-26643 was Published/Persuasive with Modification for R5. It asked to add a standard extension on Address and ContactPoint to express the access policy associated with the element, using 0..* URI or CodeableConcept values with an example v3 ConfidentialityCode binding rather than a boolean confidential flag.

Initial application:
A 2021 core commit mentioned FHIR-26643 while changing datatype extension spreadsheet sources, but current core Address and ContactPoint extension spreadsheets do not contain a confidential/access-policy extension. The concrete implementation was later made in the FHIR Extension Pack by HL7/fhir-extensions commit 370be10 and merge 743095c, which added StructureDefinition-confidential with Address and ContactPoint contexts, URI and CodeableConcept value choices, and the v3-Confidentiality example binding.

Additional context:
Current core fhir.ini still builds datatype extension spreadsheet sources, but the confidential extension definition is maintained outside this checkout in /home/jmandel/work/fhir-extensions. The current Extension Pack source marks that extension retired/deprecated and points implementers to Inline-sec-label. Later FHIR-44331 explains that FHIR-I chose deprecation in favor of the DS4P Inline-sec-label extension because it is generic, applies anywhere, and has implementation guidance. The related Zulip thread records Marc Duteau saying the FHIR-26643 fix would go into the extensions IG rather than base FHIR.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The requested artifact belongs to the FHIR Extension Pack rather than the current FHIR core build, and the Extension Pack already contains the FHIR-26643 extension plus later deprecation guidance.

Recommendation:
Keep this audit commit as-is and do not add a duplicate core extension. Any future work on this artifact should be handled in the FHIR Extension Pack or the DS4P Inline-sec-label guidance, considering FHIR-44331 before reviving or changing the deprecated confidential extension.
