FHIR-5549: Audit ValueSet expansion case-sensitivity guidance

Issue request:
FHIR-5549 was a Published/Persuasive with Modification DSTU1 ValueSet request asking that caseSensitive either be represented consistently on compose/expansion or removed from define. The accepted resolution was to leave the model as-is and modify documentation so any expansion is treated as case sensitive until the code system is consulted.

Initial application:
The issue was directly applied in the SVN-imported git history by 4ccdb66276a122d32d4eefaf7ca2d5c0caf7f030, "#5549 - note about case sensitivity on expansions", from SVN revision 5883. Follow-up history only corrected wording and later reorganized nearby ValueSet prose; the case-sensitivity rule remains in the current ValueSet notes.

Additional context:
ValueSet is an active build-scoped resource in source/fhir.ini, and source/valueset/valueset-notes.xml is the resource narrative source. A later applied issue, FHIR-40719, clarified the external valueset-caseSensitive extension in the FHIR Extension Pack so the assertion must be based on the underlying CodeSystem and must not be used when the generator does not know the code system's case-sensitivity rules. That later extension-specific clarification aligns with the current core guidance rather than requiring a core source change.

AutoFHIR reconciliation:
This audit commit intentionally makes no source changes. The current core source already says that expansion codes should be treated as case sensitive, that implementers should use the correct case, and that implementers can consult the underlying code systems to determine whether the defining code system is case sensitive.

Recommendation:
Keep this no-change audit as-is. No core FHIR edit is needed for FHIR-5549; any future changes to machine-readable expansion case-sensitivity metadata should be handled through the valueset-caseSensitive extension or terminology-server behavior, not by reintroducing a ValueSet compose/expansion element.
