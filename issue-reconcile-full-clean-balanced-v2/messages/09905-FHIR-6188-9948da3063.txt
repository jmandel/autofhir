Issue request:
FHIR-6188 was a Published/Persuasive with Modification FHIR-core profiling clarification from DSTU1. It asked to make the difference between the two profile uses clearer, replace vague "system profile" terminology by headings that refer directly to the relevant paths, update the DSTU note, update the two element definitions to point to the discussion, and add examples.

Initial application:
The issue was applied by git-svn commit 9cf5e61f124da005d8e70d53b12c577e1bd7e5f6, matching Jira's svn revision 5532 comment. That commit changed source/profiling.html to add the profile-use anchor, path-based headings for Conformance.rest.resource.profile and Conformance.profile, removed the "System Profiles" heading and DSTU note wording, and updated the Conformance spreadsheet definitions/comments to point to the profile-use discussion.

Additional context:
The old Conformance resource was later renamed/reworked into CapabilityStatement, and the corresponding current paths are CapabilityStatement.rest.resource.profile and CapabilityStatement.rest.resource.supportedProfile. Later Published issue FHIR-25462 refined the same area for R5, and the combined branch already contains a separate FHIR-25462 reconciliation commit updating the current profiling guidance to direct use-case-specific profile communication to supportedProfile after deprecation of the declared-profile extension.
