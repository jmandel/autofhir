FHIR-46649: Audit sensitive-link wording

Issue request:
FHIR-46649 is an Applied/Persuasive FHIR-I change request for the FHIR-core Search page. It asked to clarify the trial-use conformance sentence "Servers SHOULD NOT include content that is considered sensitive in the URLs." so that the sensitive-content warning applies to paging links such as next/prev and explicitly excludes the self link.

Initial application:
The issue was applied before this reconciliation by commit 20dd71b98d7fbbc1b76799d43ffbfb7b7ddf7ed5, "FHIR-46649 - clarify sensitive content expectations in bundle links", which changed source/search.html to say "Servers SHOULD NOT include content that is considered sensitive in URLs, excluding the self link." The combined branch already contains that implementation commit.

The relevant source is source/search.html, the current FHIR-core Search narrative page containing the #paginglinks section. Zulip discussion in #implementers > Bundle Search Links shows the reporter clarifying on 2024-08-16 that the sensitive-content sentence was meant for next/prev links, not the self link.
