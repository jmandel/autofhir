FHIR-29699: Audit searchset self-link invariant

Issue request:
FHIR-29699 was a Published/Persuasive FHIR-I change request asking for a Bundle invariant so that Bundle.type = searchset requires a Bundle.link with relation = self and a URL, matching the search conformance rule that servers return the parameters actually used in the search self link.

Initial application:
The issue was applied before this reconciliation by commit 908ab6c031a3144c98da8d4351a8757be7ac9e0f, which added Bundle constraint bdl-18 to source/bundle/structuredefinition-Bundle.xml. A same-evening follow-up commit, 1f683a11386b08ebfdb12390f7e8696466fd1e0b, refreshed invariant references, and the v5.0.0 tag contains bdl-18.

Additional context:
source/fhir.ini actively lists bundle=Bundle, so source/bundle/structuredefinition-Bundle.xml is in current build scope. Current search.html still defines the self-link conformance rule, and current Bundle source has bdl-18 plus condition references on Bundle.type, Bundle.link, Bundle.link.relation, and Bundle.link.url. Zulip and Confluence evidence support the same scoped searchset invariant and did not reveal a later reversal.

AutoFHIR reconciliation:
No source change was made. The current specification already contains the requested invariant with expression `type = 'searchset' implies link.where(relation = 'self' and url.exists()).exists()` and the related element condition references.

Recommendation:
Keep this empty audit commit as-is. No further core FHIR source work is needed for FHIR-29699 unless a future work-group decision changes the searchset self-link conformance rule.
