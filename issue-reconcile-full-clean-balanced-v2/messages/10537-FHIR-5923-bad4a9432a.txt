FHIR-5923: Audit BodySite duplicate mapping typo

Issue request:
FHIR-5923 was Published/Persuasive for a non-substantive DSTU1 correction. It reported that the generated BodySite profile repeated the OpenEHR mapping for BodySite.specificLocation.side as "Side Side Side" and repeated the short text for BodySite.relativeLocation.landmark as "Identified landmark" three times.

Initial application:
The issue was applied in historical commit 9f140c6f55, which changed source/bodysite/bodysite-spreadsheet.xml from multiline repeated values to single "Side" and "Identified landmark" values. Jira comments from the reporter and editor also state that the hidden multiline spreadsheet values were the root cause and were already fixed.

Additional context:
BodySite is no longer an active current-build resource: source/fhir.ini lists bodystructure=BodyStructure in [resources] and records that BodySite became BodyStructure. The active BodyStructure source contains laterality and body-landmark elements without the duplicated strings, and a current source search found no remaining "Side Side Side", repeated "Identified landmark", BodySite.specificLocation.side, or BodySite.relativeLocation.landmark definitions. Zulip and Confluence searches found no direct FHIR-5923 conflict; a broad Confluence BodySite/landmark hit concerns later BodyStructure modeling, not the DSTU1 spreadsheet typo.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The original typo was fixed in the historical BodySite spreadsheet, and the affected BodySite profile is outside the current build scope; the active successor resource does not carry forward the duplicate mapping or short text.

Recommendation:
Keep this audit commit as-is. No current FHIR core source change is needed for FHIR-5923; any future review of old DSTU1 generated profile output should trace back to the historical spreadsheet correction.
