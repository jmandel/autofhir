FHIR-13973: Audit Composition.section profiling support

Issue request:
FHIR-13973 was Published/Persuasive with Modification. It asked for reusable profiling of Composition.section, originally suggesting a new CompositionSection datatype, and resolved that the functionality could instead be achieved by applying constraints from one StructureDefinition to a specific element in another profile, with an example needed.

Initial application:
Commit a74f2b313b576 explicitly applied GF#13973 by adding profile-element support, example section-library and example-composition StructureDefinitions, and validation test changes. Later source refactoring removed the executable example-composition profile under FHIR-48828, but did not remove the section-library example or the profiling.html narrative.

Additional context:
FHIR-13386 was closed because FHIR-13973 made a new datatype unnecessary, while FHIR-25477 later requested a concrete profiling.html example for the same mechanism. The current representation documents the profile-element extension rather than relying on the older Jira wording about a literal fragment in type.profile; that is the implemented and current source pattern.

AutoFHIR reconciliation:
This empty audit commit makes no source change. Current source documents the supported mechanism, ElementDefinition.type.profile points readers to the profile-element extension for profiling a backbone element, the profile-element extension exists in the FHIR Extension Pack, and Composition.section does not need to become a datatype.

Recommendation:
Keep this no-change audit. Treat FHIR-13973 as already applied in current core and extension-pack source; any future change to how profile-element is represented should be a new conformance/tooling decision, not a reopening of the datatype request.
