FHIR-31051: Audit CapabilityStatement searchParam clarification

Issue request:
FHIR-31051 was a Published/Persuasive FHIR-I clarification asking that CapabilityStatement.rest.searchParam be described as only for searches executed against the base/system-level endpoint, not as a shortcut for resource-level search parameters that happen to apply to every resource type.

Initial application:
The issue was applied by git commit 9e03d2afba72d8e2f1e4f7d8788b3c9c166bf5af, which changed source/capabilitystatement/structuredefinition-CapabilityStatement.xml so CapabilityStatement.rest.searchParam says it is only for searches executed against the system-level endpoint. CapabilityStatement is an active current-build resource through source/fhir.ini.

Additional context:
The linked Zulip thread records the ambiguity and Grahame Grieve's clarification that rest.searchParam is for searches without a type specified, not merely for parameters common to all resource types. FHIR-I minutes later record the persuasive/block-vote disposition. A later related issue, FHIR-46110, concerns whether comments should mention non-true search/control parameters; it is Resolved - change required rather than Applied/Published and is not decided by this audit.

AutoFHIR reconciliation:
No source change was made. The current build-scoped source already contains the required system-level-endpoint clarification, and the remaining "searching all resources" wording is consistent with the system-level search endpoint once read with that explicit sentence.

Recommendation:
Keep this empty audit commit as-is for FHIR-31051. Do not duplicate the guidance elsewhere unless a later applied/published decision changes the CapabilityStatement search parameter model; track FHIR-46110 separately if that unresolved application work needs reconciliation.
