FHIR-7542: Audit extension registry URL application

Issue request:
FHIR-7542 was Published/Persuasive for the DSTU1 Defining Extensions page and asked to define the registry URLs by replacing the old registry table with a single reference to http://fhir.org/registry.

Initial application:
The issue was applied in svn revision 6066, mirrored as git commit 656686ab6e0b3aad00ee5012c86844bd1915455a, whose subject is "#7542 - FHIR registry URL". That commit removed the table containing TBD/interim registry search and submit URLs from source/defining-extensions.html and inserted a single HL7 FHIR registry link. Later pre-publication commits changed the exact link target from http://fhir.org/registry to http://hl7.org/fhir/registry and removed an external-link image, leaving the table removal intact.

Additional context:
The current Defining Extensions page is active build source through publish.ini and source/hierarchy.xml. It no longer contains the old registry URL table. Later FHIR-16989 clarified the nearby distinction between publishing an extension and advertising it in a registry, adding a direct registry.fhir.org link to the same paragraph family. Later FHIR-19342 records that http://hl7.org/fhir/registry was the advertised old registry address and that https://registry.fhir.org/ is the actual registry address, to be handled by redirect. A Zulip thread that prompted FHIR-19342 confirms that later understanding. The original http://fhir.org/registry target now returns 404, so reverting to the literal 2015 resolution URL would make the current page worse.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The source-changing part of FHIR-7542, removal of the old table and replacement with a registry reference, is already present in current build-scoped source, and later registry URL decisions explain why the current source should not be changed back to the exact 2015 URL.

Recommendation:
Keep this audit commit as-is. If the work group wants to modernize all remaining HTTP registry links to https://registry.fhir.org/, that should be handled as a separate link-maintenance issue across the affected pages rather than as a FHIR-7542 reconciliation.
