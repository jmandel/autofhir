FHIR-42947: Audit SupplyDelivery and Transport boundary wording

Issue request:
FHIR-42947 was an Applied/Persuasive OO change request for R5, applied for R6, asking that SupplyDelivery and Transport be better differentiated. The approved disposition changed SupplyDelivery Scope and Usage to describe dispatch and/or receipt events and added Boundary and Relationships text explaining that Transport documents movement between dispatch and receipt, including time of movement, transporter, and average temperature during transport.

Initial application:
The issue was applied before this reconciliation by Jira-tagged commit d853f5ef36, which updated source/supplydelivery/supplydelivery-introduction.xml with the requested dispatch/receipt wording and the Transport boundary paragraph. The current legacy core SupplyDelivery narrative still contains that text.

Additional context:
FHIR-45506 was explicitly linked from FHIR-42947 as related SupplyDelivery dispatch/reception work and is already represented on the combined branch by an external-repo audit commit. Later source ownership changed: commit 3b38b80cf2 removed SupplyDelivery, SupplyRequest, Transport, and related OO resources from active core resource metadata and updated current core narrative links to the OO Incubator IG. The active HL7/oo-incubator SupplyDelivery source preserves the FHIR-42947 wording, including the boundary paragraph linking to Transport.

AutoFHIR reconciliation:
This is an empty external-repo/out-of-current-core-build audit commit. No core source was changed because editing the remaining source/supplydelivery or source/transport files would only adjust inactive legacy resource source, while the current core publication surface points implementers to the OO Incubator artifacts and the active SupplyDelivery source there already has the approved clarification.

Recommendation:
Keep this audit commit as-is for FHIR core. No follow-up source change is needed for FHIR-42947 unless OO later changes the active OO Incubator SupplyDelivery or Transport guidance; any such future work should be reconciled in HL7/oo-incubator, not in inactive core resource files.
