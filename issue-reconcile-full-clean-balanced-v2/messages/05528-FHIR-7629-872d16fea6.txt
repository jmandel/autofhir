FHIR-7629: Audit Condition bodySite rename

Issue request:
FHIR-7629 was Published/Persuasive for the DSTU1 Patient Care Condition resource. It asked to rename the overloaded Condition.location element to bodySite or affectedSite, and the final resolution was to rename it to bodySite for consistency with Observation.

Initial application:
The rename appears to have been applied by commit 35ae82d571ad6a2c9a518bd356fadaf63acf2837, whose subject explicitly includes #7629 and which changed Condition examples and the then-authoritative Condition spreadsheet from location/siteCodeableConcept to bodySite CodeableConcept. The old spreadsheet source was later replaced by generated source files in commit 33b409a4b6d544598262f2f074ebb4b6dc466157, carrying the bodySite element into source/condition/structuredefinition-Condition.xml and the Condition body-site search parameter bundle.

Additional context:
The Condition resource is active in source/fhir.ini, so source/condition is in current build scope. The current StructureDefinition defines Condition.bodySite as the anatomical location where the condition manifests itself, examples use bodySite tags, and the Condition body-site search parameter expression is Condition.bodySite. Same-implementation issues FHIR-7589 and FHIR-8474 concern the related body-site representation and laterality discussion, but they are separate tracker decisions and are not being decided by this seed audit.

AutoFHIR reconciliation:
No source change was made. The current build-scope source already uses Condition.bodySite and a targeted grep found no remaining Condition.location, location element, siteCodeableConcept, or affectedSite usage under source/condition that would contradict the rename request.

Recommendation:
Keep this no-change audit commit as-is for FHIR-7629. Any further review of laterality/body structure behavior should be handled through the separate related trackers rather than reopening this completed rename.
