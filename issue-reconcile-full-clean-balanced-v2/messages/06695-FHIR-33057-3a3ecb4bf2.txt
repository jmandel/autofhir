FHIR-33057: Audit que-14 answerExpression handling

Issue request:
FHIR-33057 was Published with a Persuasive with Modification resolution for R5. It asked that Questionnaire invariant que-14 stop precluding answerConstraint when allowed answers come from an equivalent extension such as answerExpression, by changing the invariant to a warning and rewording it to explain the extension case. The resolution also noted an SDC Questionnaire profile override, which is outside this FHIR-core checkout.

Initial application:
Core commit 95a609eee7 changed source/questionnaire/structuredefinition-Questionnaire.xml so que-14 moved from error to warning and added wording that extensions may serve the same purpose. R5 generated history also contains the warning form, and later core refactors removed XPath and normalized answerValueSet casing without restoring an error or otherwise reversing the issue.

Additional context:
source/fhir.ini actively includes Questionnaire as a current resource, so source/questionnaire/structuredefinition-Questionnaire.xml is in build scope. The current source still has que-14 as a warning with expression answerConstraint.exists() implies answerOption.exists() or answerValueSet.exists(), and the human text explains that extensions may serve the same purpose. The FHIR-I/SDC Confluence minutes record the issue as persuasive with modification. Community searches found later answerExpression/answerConstraint discussion, including FHIR-41652 for an SDC R4 IG issue, but no core-source decision that conflicts with the current R5/R6 core warning.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core source already implements the material FHIR-33057 decision: answerConstraint with answerExpression is no longer a hard error in core, and the warning text preserves the intended guidance without duplicating SDC-specific extension logic in core.

Recommendation:
Keep this audit commit as-is. No FHIR-core follow-up is needed for FHIR-33057; any remaining SDC-profile-specific behavior should be handled in the FHIR-sdc repository or issue family rather than by changing core Questionnaire.
