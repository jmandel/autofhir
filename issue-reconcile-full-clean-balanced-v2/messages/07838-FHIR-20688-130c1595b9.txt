FHIR-20688: Audit Meta.source source scope

Issue request:
FHIR-20688 was a Published/Persuasive FHIR-I clarification request raised against STU3 and applied for R5. It asked whether Resource.meta.source identifies only a source system, a full source resource URI, or something broader, and the approved resolution was to clarify the Meta.source table, the Resource metadata discussion, and the Meta.source definitions so the source may be a fully qualified resource reference, a more abstract identifier, or a service endpoint, while keeping Provenance context without treating Provenance.entity.what[x] as the sole mapping.

Initial application:
The issue was directly applied by git commit 9edd51287b10ae90910262893cc060ad9df66f0b, which changed source/datatypes/meta.xml and source/resource/resource-notes.xml. That application removed the old definitive Provenance.entity.what[x] correspondence from the Resource metadata summary and changed the detailed Meta.source comment so its Provenance mapping is possible rather than exclusive and may be more general or abstract.

Additional context:
Related Published issue FHIR-20906 clarified that Meta.source can correspond to Provenance.agent.who as well as Provenance.entity.what, and the current combined branch already includes a source-changing FHIR-20906 reconciliation commit. Later Applied issue FHIR-49878 clarified the definition from "source system" to "data source" and added non-FHIR/server and structure-fragment examples; the current combined branch already includes an audit for that issue. FHIR-15659 also updated obsolete Provenance choice-element names from what[x]/who[x] to current what/who. source/fhir.ini lists Meta as an active datatype and Resource as active infrastructure/normative content, so source/datatypes/meta.xml and source/resource/resource-notes.xml are current-build source.

AutoFHIR reconciliation:
This commit intentionally makes no source change. On the latest combined branch, the authoritative Meta.source definition identifies a data source, allows another server/document/message/database and portions of a structure, and says the source may correspond to Provenance.entity.what or Provenance.agent.who while still being more general or abstract. The Resource metadata table and consistency text no longer constrain Meta.source to a single system or resource; the remaining Provenance.entity.what mention is in the common-derivation discussion where entity.role=derivation is the specific comparison being described.

Recommendation:
Keep this audit commit as-is. The seed's requested clarification is already present in active source after its initial application and tightly related later reconciliations; further hand edits would either duplicate existing guidance or touch generated-looking diagram/tool-tip fragments rather than change implementer understanding.
