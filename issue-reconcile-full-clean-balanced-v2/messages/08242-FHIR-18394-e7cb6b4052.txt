FHIR-18394: Audit extension registry scope

Issue request:
FHIR-18394 was a Published/Persuasive STU3 FHIR-core clarification asking that the old extensibility registry page define the registry scope by changing "Extension Registry" to "FHIR Core-defined Extension Registry" and clarifying that the listed extensions were defined in the FHIR specification.

Initial application:
The issue appears to have been applied before this reconciliation in git commit db9355a66d, which changed source/extensibility-registry.html to use "FHIR Core-defined Extension Registry" for the page title/header and clarified that all extensions in the list were defined in the specification with the http://hl7.org/fhir/StructureDefinition/ base URI. The Jira comment on 2018-11-08 says "already done."

Additional context:
The old core source/extensibility-registry.html page was later deleted by commit 4118eb9ddb, which removed extension registry and extension-map pages from publish.ini with the commit summary "remove content now moved to extensions IG." Current core publish.ini keeps extensibility.html, extensibility-definitions.html, and extensibility-examples.html active but leaves extensibility-registry.html commented out. The read-only FHIR Extension Pack checkout now contains the registry page and its text already scopes the list as extensions "defined in this specification" with the same base URI. Later FHIR-extensions issues such as FHIR-43634 and FHIR-47833 show that the Extension Pack registry is intentionally tightly integrated with core, but they are separate extension-pack concerns and not additional core decisions for this run.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The source location named by the Jira is no longer a current core build page, and the historically requested scope clarification was applied before the page moved to the Extension Pack. Editing core source now would either touch an unrelated extensibility page or an out-of-build/deleted registry page and would not improve implementer understanding.

Recommendation:
Keep this no-change audit commit. No FHIR-core follow-up is needed for FHIR-18394; any future problem with the current Extension Pack registry wording or navigation should be handled in the FHIR-extensions repository/workflow rather than by reviving the deleted core page.
