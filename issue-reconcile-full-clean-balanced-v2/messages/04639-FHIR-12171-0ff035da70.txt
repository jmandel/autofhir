FHIR-12171: Audit CarePlan doNotPerform wording

Issue request:
FHIR-12171 was a Published/Persuasive Patient Care change request for DSTU2 asking that the CarePlan.activity.detail.prohibited description be reworded because "Do NOT do" and the true-only definition made false ambiguous. The accepted resolution was to state that true means the activity must not be engaged in, while false means it should be engaged in.

Initial application:
The historical source application is commit bd9f60dbff, which changed the CarePlan spreadsheet definition from only describing true to also saying false indicates the activity should be engaged in. FHIR-11349 had just made the same element optional with a false default, and later workflow-alignment history renamed the element from prohibited to doNotPerform.

Additional context:
Current CarePlan is active in source/fhir.ini and the current StructureDefinition uses CarePlan.activity.plannedActivityDetail.doNotPerform rather than the old prohibited name. Its short is no longer "Do NOT do", its definition says false or missing means the activity should be engaged in, and its meaningWhenMissing repeats the missing-value interpretation. source/fhir.ini retains historical rename mappings from the old CarePlan.activity.detail.prohibited path. A leftover source/careplan/PFM.xml still uses the old prohibited element, but it is not referenced by the active CarePlan example or pack lists and is not the current build-scope conformance source.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change because the current build-scope CarePlan definition already conveys the clarified false/missing meaning and no active generated/input artifact still presents the misleading "Do NOT do" description as the current element definition.

Recommendation:
Keep this no-change audit as-is. Do not add redundant wording elsewhere; the authoritative element definition already carries the resolved semantics, and any cleanup of unlisted historical example files should be handled separately if those files are brought into scope.
