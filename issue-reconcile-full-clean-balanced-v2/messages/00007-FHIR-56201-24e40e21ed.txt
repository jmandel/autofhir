FHIR-56201: Align lastVersionPresent CRMI reference

Issue request:
FHIR-56201 was an Applied FHIR-core CodeSystem change request from Vocabulary. The Jira initially asked for an invalidInVersion concept property, but the final Persuasive with Modification resolution required adding lastVersionPresent as a string concept property, with text explaining that it appears in value set expansions for explicitly referenced concepts no longer present in the code system version used for expansion.

Initial application:
The issue was first pre-applied by e46b57c91b, which added invalidInVersion to the active concept-properties CodeSystem source, CodeSystem narrative table, and CodeSystem change note. The updated disposition was then applied by 95e797e1e0, which renamed that concept to lastVersionPresent and updated the definition and change notes. The relevant CodeSystem resource is in current build scope through source/fhir.ini: codesystem is an active resource and concept-properties is an active [codesystems] entry.

Additional context:
The linked Applied CRMI issue FHIR-55634 was reopened after FHIR-56201 and its final disposition renamed the CRMI ValueSet/$expand input parameter to includeNoLongerPresent. Vocabulary minutes from 2026-04-06 record the same discussion: invalidInVersion was unclear, lastVersionPresent was selected, and FHIR-55634 was reopened to update the operation parameter name. The CRMI implementation commit 428a46bf49a1a59f6c207352f27335570e866d4a confirms the external operation parameter is includeNoLongerPresent and that it uses the core lastVersionPresent concept property.

AutoFHIR reconciliation:
This commit keeps the already-applied lastVersionPresent concept property and updates the stale cross-reference in both the authoritative CodeSystem XML and the rendered CodeSystem narrative table from includeLastVersionPresent to includeNoLongerPresent. No other CodeSystem semantics changed.

Recommendation:
Keep this commit as-is. The current core source now matches the final Vocabulary/CRMI naming trail, while CRMI-specific operation-definition content remains outside this FHIR-core checkout and should continue to be maintained in the CRMI IG.
