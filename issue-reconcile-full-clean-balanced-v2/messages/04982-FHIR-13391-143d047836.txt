FHIR-13391: Audit Location GeoJSON boundary support

Issue request:
FHIR-13391 was Published/Persuasive for STU3 by Patient Administration. It asked for Location to identify a geographic area rather than only a point, with the accepted resolution to create the standard extension location-boundary-geojson as a 0..1 Attachment carrying GeoJSON inline in Attachment.data or externally in Attachment.url with contentType application/geo+json.

Initial application:
The issue was first pre-applied in git as GF#13391, adding a Location extension spreadsheet row for boundary-geojson. A same-day follow-up changed that extension from string to Attachment and documented GeoJSON data/url handling. Later Location-source refactoring removed the old spreadsheet representation, and FHIR-19725 added the current Location notes, example, search parameter, and Location.position comment that make the boundary extension discoverable from the active Location resource pages.

Additional context:
The Location resource is active in source/fhir.ini, so source/location remains in the current build. The standard extension definition itself has intentionally moved out of core into the FHIR Extension Pack, where StructureDefinition-location-boundary-geojson is active with context Location, value Attachment, and the application/geo+json guidance. Later PA issue FHIR-47304 resolved No Change on adding a core GeoJSON element because the extension and Washington DC metro example already cover the use case; FHIR-28346 separately clarified that GeoJSON volumes are out of scope. FHIR-10234 is an earlier duplicate/background request for the same boundary-shape capability.

AutoFHIR reconciliation:
No source change was made. Current core Location source already references the standard extension from Location.position, explains boundary/contains searching in the Location notes, includes the location-contains SearchParameter, and carries a Washington, DC metro area example using valueAttachment with contentType application/geo+json. The authoritative extension definition is present in the Extension Pack, so re-adding a core extension file or adding a core Location element would conflict with the current source organization and later PA no-change guidance.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed for FHIR-13391 unless the work group later changes the Extension Pack artifact or decides to supersede the extension with a first-class core element.
