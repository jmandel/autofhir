FHIR-36751: Audit DocumentReference attester cardinality

Issue request:
FHIR-36751 was Published/Persuasive for FHIR-core DocumentReference. It asked to change R4 DocumentReference.authenticator from 0..1 to 0..* because C-CDA note mappings can have multiple people legally responsible for content; the approved resolution said no source change was needed because the R5 attester element already has 0..* cardinality.

Initial application:
No Jira-tagged source commit for FHIR-36751 was found. The relevant R5 source already contained DocumentReference.attester as a 0..* BackboneElement before this issue was resolved, and the OO minutes for the vote recorded FHIR-36751 as already fixed with the work on .attester. The current R4/R5 conversion notes map DocumentReference.authenticator to DocumentReference.attester.

Additional context:
FHIR-25087 is the earlier same-change-family request to allow multiple DocumentReference authenticators by aligning with Composition.attester and bringing in the attester backbone element. FHIR-34160 later clarified the attester definition to use authenticated language, and current attester.party includes Patient, RelatedPerson, Practitioner, PractitionerRole, Organization, and Group. Later IG/backport discussions found during the search do not require a FHIR-core source change for the current build.

AutoFHIR reconciliation:
This empty audit commit makes no source change. DocumentReference is active in source/fhir.ini, current source/documentreference/structuredefinition-DocumentReference.xml defines DocumentReference.attester with min 0 and max *, and there is no active DocumentReference.authenticator element to widen.

Recommendation:
Keep this no-change audit. No FHIR-core follow-up is needed for FHIR-36751; implementation guides that need the R5 attester shape in R4 should use the appropriate cross-version/backport mechanism rather than reintroducing authenticator in current core.
