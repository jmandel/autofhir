FHIR-12062: Audit MedicationRequest subject requirement

Issue request:
FHIR-12062 was Published with a Persuasive with Modification resolution for the Pharmacy work group. It asked to make patient mandatory in MedicationOrder, and the approved resolution was to change the element to 1:1 with guidance for an anonymized patient when the actual patient is not supplied.

Initial application:
The issue was explicitly applied by git commit 4b93d6353b51eb1a8d46a63f1baec446f9a23115, whose subject says "GFTracker #12062 - made patient mandatory in MedicationRequest". That commit changed source/medicationrequest/medicationrequest-spreadsheet.xml so MedicationRequest.patient moved from 0..1 to 1..1 and replaced the old mapping/comment text with anonymized-patient guidance. The resource had already been renamed from MedicationOrder to MedicationRequest by FHIR-10456, and the old-to-new mapping in source/fhir.ini still maps MedicationOrder.patient to MedicationOrder.subject/MedicationRequest.subject.

Additional context:
MedicationRequest is an active resource in the current build via source/fhir.ini. The current authoritative StructureDefinition source carries the applied rule forward as MedicationRequest.subject with min 1, max 1, Patient and Group targets, and the anonymized-subject comment. Later FHIR-39142 clarified the subject short/definition and FHIR-41408 broadened medication-related references for Group use cases, but neither later decision made MedicationRequest.subject optional or contradicted the FHIR-12062 requirement. Zulip and Confluence searches found only the original tracker bot notification and no conflicting community decision.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already preserves the required 1..1 subject cardinality and the approved anonymized-subject guidance in a build-scoped MedicationRequest StructureDefinition.

Recommendation:
Keep this no-change audit commit as-is. No core follow-up is needed for FHIR-12062 unless a future Pharmacy decision revisits whether MedicationRequest.subject should remain mandatory.
