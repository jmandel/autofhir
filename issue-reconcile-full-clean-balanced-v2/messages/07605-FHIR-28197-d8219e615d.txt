FHIR-28197: Audit Device brand-name resolution

Issue request:
FHIR-28197 is a Published FHIR-core Device change request, resolved Persuasive with Modification for R5. It asked whether Device needed a brand-name element, how to represent GUDID-style properties such as safety/radioactivity, and noted the misspelled DeviceDefinitionPropetyCode name. The accepted disposition was to avoid a new brand-name element, rely on Device/DeviceDefinition name-type clarification from FHIR-20639 for brand names, use Device.safety for the safety aspect, and fix the typo/terminology issue.

Initial application:
No source commit explicitly mentioning FHIR-28197 was found. The name-type portion was applied through the FHIR-20639 history: cae641cfad replaced udi-label-name/manufacturer-name/model-name/other with registered-name, user-friendly-name, and patient-reported-name, and c4a95b2b91 updated the Device and DeviceDefinition name-type element summaries. The property/typing cleanup relevant to the typo and allowed property value types was applied through the FHIR-26424 Device property consolidation history.

Additional context:
The May 2021 #devices Zulip thread for Device.deviceName.type explicitly discussed FHIR-28197 and concluded that the GUDID brand name is the formal registered/labeler/manufacturer-assigned name. The 2021-09-27 OO HCP minutes list FHIR-28197 under both Device.name and Device.safety and proposed the registered-name wording. Later related work refined the same area: FHIR-32812 removed the old open-ended name-type values; FHIR-27765 introduced a commercialBrand extension for a different brand-family concept; and FHIR-47605, already represented on the combined branch, added commercial-brand-family to the current core Device Name Type CodeSystem for post-R5 use.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Device and DeviceDefinition are active build resources in source/fhir.ini. Current Device/DeviceDefinition source has name elements bound to Device Name Type, whose registered-name definition explicitly covers brand names assigned by a labeler/manufacturer, and also includes the later commercial-brand-family concept. Current Device.safety and DeviceDefinition.safety are both bound to the device-safety value set, which includes MRI safety codes, and the old misspelled DeviceDefinitionPropetyCode/DeviceDefinitionPropertyCode text and old name-type codes are absent from active Device/DeviceDefinition source.

Recommendation:
Keep this no-change audit commit. The current core source already conveys the accepted resolution after the later name-type and property decisions; adding a separate Device brand-name element or restating the same guidance would contradict or duplicate the now-current model.
