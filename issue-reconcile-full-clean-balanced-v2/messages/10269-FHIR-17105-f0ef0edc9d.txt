FHIR-17105: Audit resource identity clarification

Issue request:
FHIR-17105 was a Published/Persuasive FHIR-core BaseResource change request for STU3. It asked the specification to define the then-used term "literal identity" and explain resource identity generally, not only as an HTTP server base plus resource type plus logical id.

Initial application:
The issue was applied in svn 14500, represented in git as 7ee661f6b4022414f36a63274872d7ef207a8716, which explicitly cites GF#17105. That commit reorganized source/resource/resource-notes.xml into Resource Identity and Logical ID sections, changed the problematic "unique identifier" and "literal identity" wording to "location", and added guidance for resources outside RESTful server contexts.

Additional context:
The current source keeps that correction. source/resource/resource-notes.xml now describes the logical id, the location URI, HTTP resolvability limits, and non-REST contexts without using "literal identity" in the resource.html#id section. A repository-wide search finds "literal identity" only in source/managing.html, where the preceding paragraph defines resource identity as a URI/URL, and in source/valueset/valueset-introduction.xml, where the phrase is parenthetically defined. FHIR-15615 and FHIR-14191 were applied in the same svn 14500 commit but concern broader identifier/canonical URL guidance and are not decided here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active source already satisfies FHIR-17105, and adding another local definition or restating the same guidance would be redundant and could create future drift.

Recommendation:
Keep this no-change audit commit. If the work group wants to retire every remaining use of "literal identity" across the specification, handle that as a separate terminology-cleanup issue rather than as part of FHIR-17105.
