FHIR-26946: Audit exposed-link privacy guidance

Issue request:
FHIR-26946 was a Published FHIR-core Security change request resolved Persuasive with Modification for R5. It asked the Security and Privacy considerations to cover privacy leakage when a returned resource contains links to, contained data from, or narrative about resources the recipient cannot access. The final resolution narrowed the applied source change to adding an H4 "Risks to Privacy by Exposing links" on the secpriv-module page explaining that links expose resource ids, ids can be correlated across resources, and that correlation may be desirable or may present an unacceptable privacy risk.

Initial application:
No commit subject explicitly mentions FHIR-26946, but git pickaxe shows commit 19da5709ad ("set of security tickets", 2022-12-14) added the secpriv-module table-of-contents entry and the "Risks to Privacy by Exposing Links" H4 section. That section contains the requested explanation about inaccessible linked resources exposing identifiers and enabling correlation.

Additional context:
The active build references source/secpriv-module.html from source/hierarchy.xml, source/modules-list.html, and source/modules-fragment.html. The older source/security.html Security and Privacy Considerations section still has generic redaction/access-control text, but the Jira resolution specifically named the secpriv-module page. Earlier FHIR-17676 raised the same reference-link concern and was closed No Change before FHIR-26946 reopened the topic with more specific requested text. Security WG minutes and the Zulip block-vote thread show the issue moving through Security WG review without a discovered later contrary decision.
