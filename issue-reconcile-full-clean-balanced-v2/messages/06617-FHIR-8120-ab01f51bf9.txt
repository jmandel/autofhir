FHIR-8120: Audit Encounter location status codes

Issue request:
FHIR-8120 was Published with resolution Persuasive for the PA work group. It questioned the original Encounter.location.status code present and the ambiguity caused when multiple Encounter.location entries could all be present. The approved resolution changed the Encounter location status values to Planned, Active, Reserved, and Completed.

Initial application:
Commit bf320e3425c2ad24825390bfd7c87d565b89b39b, titled "Tracker# 8120, Encounter location status," changed the historical Encounter spreadsheet from planned | present | reserved to planned | active | reserved | completed, renamed present to active, added completed, and added guidance that a location may become completed after the patient is no longer active there.

Additional context:
FHIR-3846 created the same Encounter.location.status element that FHIR-8120 refined. The current build uses source/encounter because encounter=Encounter is active in source/fhir.ini. FHIR-12321 later cleaned carriage-return artifacts in the encounter-location-status definitions and is already represented on the combined branch. Later community/minutes hits discuss temporary locations and V2 PL-5 mapping but do not record a core FHIR reversal of the FHIR-8120 code set.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/encounter/codesystem-encounter-location-status.xml defines exactly planned, active, reserved, and completed, and source/encounter/structuredefinition-Encounter.xml binds Encounter.location.status required to that value set.

Recommendation:
Keep this audit commit as-is. No current core source edit is needed for FHIR-8120; any future change to add different temporary-location semantics should be handled as a new PA decision.
