FHIR-3624: Audit superseded JSON comments support

Issue request:
FHIR-3624 was a Published/Persuasive DSTU1 ITS change request asking the JSON representation to support comments by documenting a special comments property, proposed as _comments, with primitive comments in the underscored primitive companion object.

Initial application:
The issue was applied in the old SVN/Git history around October 2014. Git commit b120d06e7b5e898e498bdef1a4fd58a48bbf30fa added JSON-format text for a special fhir_comments array property and noted that primitive comments could live in the underscored primitive companion object. That application differed in property name from the Jira proposal but implemented the same comment-carrying concept.

Additional context:
The same normative JSON format page is still part of the documentation surface through source/documentation.html and the active documentation page group in source/fhir.ini. A later Published/Persuasive ITS issue, FHIR-10656, explicitly decided to remove JSON comments because the special property caused operational difficulties and no implementer objections were received by the stated deadline. Git commit 75b64c909db45b251281f7d6129bfbe42a3336cd removed the fhir_comments text, the primitive-comment parenthetical, and the canonicalization instruction to omit fhir_comments. The current source/json.html now states that comments SHALL NOT be in JSON instances. Remaining fhir_comments occurrences are limited to invariant test fixture JSON files, not the normative JSON format page.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding a JSON comments property for FHIR-3624 would contradict the later final FHIR-10656 decision and the current normative JSON text.

Recommendation:
Keep this audit commit as-is. If JSON comments are reconsidered, that should happen as a new ITS work-group decision that revisits or supersedes FHIR-10656 rather than by reapplying FHIR-3624.
