FHIR-8682: Audit generated extension XPath correction

Issue request:
FHIR-8682 was a Published/Persuasive FHIR-core SearchParameter issue from DSTU1 asking to correct generated SearchParameter.xpath values for extension search parameters, with the us-core Patient race search parameter as the reported example.

Initial application:
The issue was applied in git-svn revision 6956, represented by commit 820b028efc594595fb9cc78b6b6bfea4fedd9fb9, which changed the old XPathQueryGenerator so extension path segments were not split on dots inside the URL and extension predicates were emitted as @url='...'. The checked-in DSTU2 history artifact for us-core-Patient-race contains the corrected XPath predicate form.

Additional context:
SearchParameter is active in source/fhir.ini, but the current SearchParameter structure no longer has the SearchParameter.xpath element; source/fhir.ini records SearchParameter.xpath as removed due to lack of use and maintenance and maps xpathUsage to processingMode. Later SearchParameter extension guidance and examples now use FHIRPath expressions such as Patient.extension('...').value, and directly related extension SearchParameter issues FHIR-27095, FHIR-27134, and FHIR-8848 are already represented on the combined reconciliation branch.

AutoFHIR reconciliation:
This commit makes no source change because the 2015 defect was already applied in the historical generator/output, and the current build no longer exposes XPath as the authoritative way to define SearchParameter extraction. The active extension SearchParameter example and notes already show the current FHIRPath form.

Recommendation:
Keep this audit commit as-is. Do not reintroduce or edit XPath for this issue; any future cleanup of build-only path metadata or individual SearchParameter expressions should be handled under the specific current issue that owns that artifact.
