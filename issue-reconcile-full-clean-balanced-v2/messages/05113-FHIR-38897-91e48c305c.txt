FHIR-38897: Audit SupplyRequest DeviceRequest separation

Issue request:
FHIR-38897 was a Published/Persuasive with Modification R5 Orders and Observations issue asking to keep SupplyRequest and DeviceRequest separate. The decision says DeviceRequest is patient-specific clinical device use, while SupplyRequest is logistics/movement of supplies, including devices, not for associating clinical use; it also asked to clarify SupplyRequest.deliverTo, SupplyRequest/SupplyDelivery boundaries, and DeviceRequest accordingly.

Initial application:
The issue was applied before R5 publication through PR #2630. The merge commit 47fccfe6c1 listed FHIR-38897, and commit ac8c3aa2b3 added the SupplyRequest narrative saying it is logistics-only, that Patient in deliverTo is only a delivery destination and not clinical use, and that SupplyRequest expresses the need to deliver an item while SupplyDelivery tracks the actual delivery. The same commit added RelatedPerson to SupplyRequest.deliverTo. DeviceRequest already described request for device use by a patient, and current DeviceRequest narrative still states the patient-specific clinical/device-allocation boundary.

Additional context:
FHIR-39066 later made the same SupplyRequest/DeviceRequest separation decision actionable by removing the remaining SupplyRequest combination question from active core workflow text; it is already represented on the combined branch by commit 48300cc4c7. FHIR-39509, FHIR-39510, and FHIR-39511 are neighboring SupplyRequest updates already represented on the combined branch. Later core history intentionally moved SupplyRequest, SupplyDelivery, DeviceDispense, and related immature OO resources out of active core into the HL7 OO Incubator IG; source/fhir.ini has no active SupplyRequest or SupplyDelivery entry, and active core pages now link those resources externally. The current OO Incubator SupplyRequest and SupplyDelivery source carries the logistics/inventory, delivery-context, and movement-boundary text.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current core source is already correct when the issue family is considered: active DeviceRequest remains patient-specific, the active workflow combination note has already been narrowed by FHIR-39066, and the active SupplyRequest/SupplyDelivery content is now owned by HL7/oo-incubator and contains the FHIR-38897 boundary language. Editing dormant source/supplyrequest or duplicating the already-published FHIR-39066 source change would not improve the current core build.

Recommendation:
Keep this audit commit as-is. Future authoritative SupplyRequest or SupplyDelivery wording changes should be made in HL7/oo-incubator; core follow-up is only needed if active core pages again imply that SupplyRequest should merge with DeviceRequest or that SupplyRequest records patient-specific clinical use.
