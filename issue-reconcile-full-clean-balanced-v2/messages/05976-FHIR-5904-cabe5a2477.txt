FHIR-5904: Audit Condition imprecise age choices

Issue request:
FHIR-5904 is a Published/Persuasive Patient Care change request for FHIR-core Condition. It asked to add Period, Range, and string as additional choices for Condition.onset[x] and Condition.abatement[x], so Condition could represent imprecise onset and abatement in the same style as FamilyMemberHistory. Jira comments clarified that the existing abatement boolean choice was not to be omitted by this issue.

Initial application:
The issue was applied in svn revision 4816, represented in git by e1e29f4ad6c14edf8a8ea1000cb53f1b7fc5b2c8. That commit changed the then-authoritative Condition spreadsheet so Condition.onset[x] went from dateTime | Age to dateTime | Age | Period | Range | string, and Condition.abatement[x] went from date | Age | boolean to date | Age | boolean | Period | Range | string. It also adjusted onset search-parameter rows related to the new choices.

Additional context:
Condition is in current build scope through the active condition=Condition entry in source/fhir.ini. The current authoritative Condition StructureDefinition source already has dateTime, Age, Period, Range, and string for both onset[x] and abatement[x]. The Condition search-parameter bundle also exposes age/range, date/Period, and string search parameters for those choices. The historical abatementBoolean choice is absent because later Published issue FHIR-13201 removed abatementBoolean and its search parameter, as implemented by bac396f21d6dc845c746e29a9fb7c79e27ee6ff5 and confirmed by related no-change issue FHIR-13525.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The requested imprecise Period, Range, and string choices are already present in the active Condition source and related search parameters. Re-adding abatementBoolean would contradict the later published FHIR-13201 decision rather than complete FHIR-5904.

Recommendation:
Keep this no-change audit as-is. No FHIR-core follow-up is needed for FHIR-5904 unless Patient Care separately decides to revisit the later abatementBoolean removal.
