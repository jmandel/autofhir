FHIR-39096: Audit Bundle.identifier message identity

Issue request:
FHIR-39096 was Published/Persuasive with Modification for R5 messaging. It asked to stop using Bundle.id and MessageHeader.id as the logical message identifier and instead use exactly one Bundle.identifier, update reliable messaging retry/cache rules, add MessageHeader usage guidance, and clarify the REST relationship.

Initial application:
The issue was applied in source by git 87b1af3c09, following a small preparatory whitespace commit 5e04fe1f02, with direct edits to source/messaging.html and source/messageheader/messageheader-notes.xml. The earlier FHIR-29690 commit bce22083f1 had already updated MessageHeader.response.identifier's short/definition to refer to the original Bundle.identifier. Later commits b667d192f3 and 749bbcaef2 refined the REST paragraph and added an implementer note without changing the Bundle.identifier decision.

Additional context:
The messaging page is a current source page linked from active source navigation, and source/fhir.ini actively lists MessageHeader as a built resource. Confluence minutes for 2023-02-23 record FHIR-39096 as Persuasive with Modification and FHIR-24645 as Not Persuasive because it was dealt with by FHIR-39096. The Zulip "Proposal for message identifier issues" thread records the same choice: InM agreed only Bundle.identifier is needed.

AutoFHIR reconciliation:
No source change was made. Current source/messaging.html states Bundle.identifier exclusively identifies the message, uses it in retry/cache rules, quotes it through MessageHeader.response.identifier, warns that Bundle.id and MessageHeader.id are REST resource ids, and explains that RESTful message representation is the complete Bundle. Current source/messageheader/messageheader-notes.xml contains the required note that MessageHeader has no persistent identifier for the triggering event.

Recommendation:
Keep this audit commit as-is. FHIR-40518 and FHIR-40519 were implemented in the same historical commit but are already represented on the combined branch, so do not duplicate them; use this FHIR-39096 audit as evidence that no further core source change is needed for the message identity decision.
