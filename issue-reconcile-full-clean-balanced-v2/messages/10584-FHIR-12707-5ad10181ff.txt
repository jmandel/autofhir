FHIR-12707: Audit FHIRPath invariant engine fix

Issue request:
FHIR-12707 was a Published/Persuasive FHIR-I issue raised against DSTU2. It asked to investigate a FHIRPath engine problem that made a compliant CareTeam example fail when validating the CareTeam.participant invariant intended by FHIR-12647: onBehalfOf could be populated only when member resolved to Practitioner.

Initial application:
The engine problem was fixed before this reconciliation. The linked Zulip thread records Grahame debugging the CareTeam invariant and replying "fixed" on 2017-02-09. Git commit f05a2daa11a9 then fixed resolve support while validating resources, including contained Reference resolution in the DSTU3 FHIRPath engine. The next-day source commit 9beeccb22219 enabled the CareTeam.participant invariant in the CareTeam spreadsheet for FHIR-12647, showing that the seed issue unblocked the originally intended invariant application.

Additional context:
CareTeam is active in source/fhir.ini, and the current build input is source/careteam/structuredefinition-CareTeam.xml. The current StructureDefinition still preserves the historical ctm-1 invariant text only as a commented-out block, while ctm-2 remains the active participant constraint. That current shape is intentional: later final Patient Care issue FHIR-42928 broadened CareTeam.participant.onBehalfOf targets and explicitly removed the Practitioner-only invariant, and later applied issues added additional onBehalfOf/member targets. A prior combined-branch audit commit for FHIR-12647 already documents this same CareTeam onBehalfOf family and lists FHIR-12707 as the supporting FHIRPath fix.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Reinstating the old ctm-1 invariant would reverse FHIR-42928 and conflict with current CareTeam semantics; changing FHIRPath engine source is also outside the current specification source state because the 2017 engine fix was already applied historically.

Recommendation:
Keep this no-change audit commit for FHIR-12707. No core source follow-up is needed for this seed; future CareTeam onBehalfOf work should proceed under the later CareTeam semantic issues rather than by restoring the superseded invariant from this engine-investigation issue.
