FHIR-13632: Audit no-parameter operation invocation

Issue request:
FHIR-13632 was a Published FHIR-core/fhir-i STU3 clarification asking how to invoke a non-idempotent operation with no parameters. The Persuasive with Modification resolution said to use an empty POST, include a zero-length body indication for systems that require a body, and omit the Content-Type header.

Initial application:
The issue was applied by git-svn commit 21d133dda3cd71a3d2fd35f1e85627c1148c71b9, svn revision 12807, which added the Operations with no parameters section to source/operations.html. That section remains in the current source and shows a POST request with an empty body and Content-Length: 0, with no Content-Type header.

Additional context:
The current operations page is an active top-level source page referenced by source/hierarchy.xml and linked from source/http.html. A contemporaneous Zulip implementers thread records the FHIR Infrastructure check that an empty request body with no Content-Type header and Content-Length: 0 was acceptable. No Confluence reference or later Jira hit was found that changes this interpretation.

AutoFHIR reconciliation:
No source change was made. The current source already conveys that operations with no parameters use GET when no state change is caused, and use POST with an empty body and Content-Length: 0 when state changes require POST; the example omits Content-Type consistently with the Jira resolution and Zulip confirmation.

Recommendation:
Keep this audit commit as-is. Future editorial cleanup could separately improve nearby grammar, but FHIR-13632 itself is already applied and does not require another normative or source change.
