FHIR-7954: Audit historical _language removal

Issue request:
FHIR-7954 was a Published/Persuasive FHIR-I change request from the 2015May ballot asking to remove the generic _language query parameter from the Resource-level search parameters because the value of a default language query was low and its matching semantics were under-specified.

Initial application:
The issue was applied in svn revision 5430, now git commit 340bce1f8e7a7c8cb085a7ad210afa802a852d77, which removed the _language link and explanatory prose from source/search.html.

Additional context:
The current source intentionally contains _language again because later Published/Persuasive with Modification issue FHIR-32020 approved adding a standard _language search parameter against Resource.language for R5. The later Zulip discussion and FHIR-I WGM minutes record multilingual questionnaire/document use cases and an 8-0-0 decision to add _language. Current source/search.html and source/resource/bundle-Resource-search-params.xml now define that later parameter in active build-scope search documentation and Resource search-parameter source.

AutoFHIR reconciliation:
This empty audit commit makes no source change. Removing _language now would incorrectly revert the later FHIR-32020 decision rather than finish FHIR-7954.

Recommendation:
Keep this audit commit as-is. Treat FHIR-7954 as historically applied and later superseded by FHIR-32020; any new concerns about Resource.language search semantics should be handled as a new tracker or as follow-up on the later language-search decision, not by reapplying FHIR-7954.
