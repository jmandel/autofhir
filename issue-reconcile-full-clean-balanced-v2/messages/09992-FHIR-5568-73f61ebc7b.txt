FHIR-5568: Audit OID extension retirement

Issue request:
FHIR-5568 was Published/Persuasive for the DSTU1 ValueSet OID extension. The reporter noted that the old ExtensionDefinition/valueset-oid URL was being used where the OID identified a code system, and the approved request was to change the URI link and description so the extension did not imply value-set-only semantics.

Initial application:
The historical application was commit 089bbf555b41fedf41b9e30b499689ee62d390c4, titled "#5568 - clarify definition of OID extension". It updated source/valueset/valueset-extensions-spreadsheet.xml so the OID extension description referred to the object identified by the URI and gave code system, value set, and identifier-system examples. It did not rename the extension URL in that commit, but the affected spreadsheet is no longer present in the current source tree.

Additional context:
A later source change, commit 127b78439c60e54c876f20860ee41f26d8b3450c, explicitly removed the OID extension from the ValueSet and CodeSystem extension spreadsheets with the rationale "remove OID extension (just use identifier)". Current source/fhir.ini keeps ValueSet and CodeSystem in the active resource list, and the current StructureDefinition sources give both resources canonical URL elements that may be urn:oid plus repeatable identifier elements for additional formal/business identifiers. Searches of the current core source and the FHIR Extension Pack found no remaining valueset-oid or generic oid extension definition needing a URI or description correction. A later Zulip thread about CodeSystem/ValueSet identifiers also points users to ValueSet.identifier and distinguishes value set and code system OIDs, which is consistent with the post-removal model rather than reviving the old extension.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build no longer contains the misleading ValueSet OID extension that FHIR-5568 targeted, and the active ValueSet/CodeSystem definitions already provide the current mechanism for OIDs through url and identifier.

Recommendation:
Keep this no-change audit as-is. No FHIR core source follow-up is needed for FHIR-5568 unless the work group decides to reintroduce an OID extension, which would be a new design decision rather than completion of this DSTU1 correction.
