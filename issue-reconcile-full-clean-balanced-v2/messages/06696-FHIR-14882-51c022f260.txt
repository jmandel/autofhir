FHIR-14882: Audit ValueSet expansion status clarification

Issue request:
FHIR-14882 was a Published/Persuasive with Modification vocab issue against FHIR-core ValueSet from the STU3 ballot. It asked to clarify what ValueSet.status means when a ValueSet instance is carrying only an expansion, because status is required but expansion-only responses do not have separate value set definition metadata. The recorded resolution was to create an invariant requiring status = active when only status and expansion are populated.

Initial application:
The Jira comments say the issue was applied as svn 13467. Git history shows that application as 6df7f5cfc26ca11762fb1d16dbebe9a2dbe8ad88, titled "GF#1488 - Add ValueSet invariant for status must = 'active' if expansion is present and compose is absent." That commit added the old ValueSet invariant with expression status='active' or compose.exists() or expansion.empty() to source/valueset/valueset-spreadsheet.xml.

Additional context:
Later STU3 ballot issues FHIR-18564 and FHIR-18685 revisited the same invariant and status semantics. FHIR-18564 objected that an expansion might exist for a non-active value set, and FHIR-18685 resolved to remove vsd-11, keep the ValueSet.status name, clarify that ValueSet.status applies to the value set definition/compose and associated metadata, and state that expansions are stateless. Git commit fbcbcb6ac4f574b7f9859cc6bf36e54befb5d312 applied that later decision. Current source/fhir.ini keeps ValueSet in the active build, and current ValueSet source and notes contain the later clarification while no current source match remains for the old active-only expansion invariant.

AutoFHIR reconciliation:
This commit intentionally makes no source changes. Re-adding the FHIR-14882 active-only invariant would conflict with the later Vocabulary WG decisions, and the current ValueSet.status, ValueSet.expansion, VSD notes, and $expand guidance already explain that status comes from the definition/metadata rather than the expansion itself.

Recommendation:
Keep this audit commit as-is. No current core source follow-up is needed for FHIR-14882 unless Vocabulary reopens expansion lifecycle/status modeling; any future work should start from the later FHIR-18564/FHIR-18685 decisions rather than the superseded active-only invariant.
