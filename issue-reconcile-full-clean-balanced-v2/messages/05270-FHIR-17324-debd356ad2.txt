FHIR-17324: Audit ValueSet expand filter property support

Issue request:
FHIR-17324 was an Applied Vocabulary change request, resolved Persuasive with Modification for R6, asking for ValueSet $expand filtering to support targeted property search. The accepted resolution changed the $expand filter documentation from searching definition and display(s) to searching definition, designations, and display(s), and added a repeatable filterProperty input parameter for string-representable properties used when matching filter text.

Initial application:
The issue was applied by commit 4cd9f00b61b02c28e614ef3268a899e8610b9242, "FHIR-33944, FHIR-41229, FHIR-41230, FHIR-45986, FHIR-17324, FHIR-41639: ValueSet operation parameters". That commit updated source/valueset/operationdefinition-ValueSet-expand.xml to include the revised filter bullet and the new 0..* filterProperty input parameter.

Additional context:
ValueSet is an active resource in source/fhir.ini and source/valueset/list-ValueSet-operations.xml references OperationDefinition/ValueSet-expand, so this OperationDefinition is in current build scope. The linked Zulip discussion and TI minutes support the final narrowing to property search plus designation-aware filter wording rather than a separate filterDesignation parameter. I also inspected nearby expansion-parameter narrative; it already states that used $expand input parameters should be recorded, and its macro omits several current $expand inputs, so any broader refresh of that curated list should be reviewed separately rather than treated as a FHIR-17324 source defect.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current active OperationDefinition already contains the required "searching on definition, designations and display(s)" wording and the repeatable filterProperty input parameter with documentation limiting it to properties with string representations.

Recommendation:
Keep this audit commit as-is for FHIR-17324. If the work group wants the ValueSet expansion-parameter narrative macro to enumerate additional newer $expand inputs, handle that as a separate terminology documentation cleanup because it is broader than this issue and affects multiple parameters.
