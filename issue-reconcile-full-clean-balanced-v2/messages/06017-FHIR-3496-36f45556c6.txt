FHIR-3496: Audit Organization alias support

Issue request:
FHIR-3496 was a Published/Persuasive with Modification PA change request for Initial Draft/DSTU1 noting that Organization.name allowed only one value and asking for support for multiple organization names used as aliases, translations, or variants. The recorded resolution was that the standard extension "alias" had been added.

Initial application:
The issue appears to have been applied by git commit bf00335915ed7f0e22ec5fa03e2a306f3418fa4f, whose subject explicitly says "Tracker: 3496 Organization alias Standard Extension and example" and which added organization-alias extension material plus an Organization example use. That historical standard-extension surface is no longer active current core source.

Additional context:
Later same-family PA decisions moved the capability into the core resource. FHIR-9625 was Published/Persuasive and, via commit 562804d8f5daf71a614a11cbfd3d4df6be40fdda, added Organization.alias as a 0..* string and included it in Organization's name search. FHIR-13345 was Published/Persuasive and removed the now-redundant standard alias extensions; it is already represented on the combined branch by commit 1c8eb12b4d7792aec840f7c4149d8654e6343969. FHIR-14834 later confirmed that organization abbreviations are handled by Organization.alias and that the name search parameter includes both Organization.name and Organization.alias. A 2016 Zulip committers thread also records PA's intent to remove Organization.alias and Location.alias standard extensions because they were now core properties.

AutoFHIR reconciliation:
This empty audit commit makes no source change. Organization is active in source/fhir.ini, current source/organization/structuredefinition-Organization.xml has Organization.name at 0..1 and Organization.alias at 0..* with alternate/historic-name guidance, and source/organization/bundle-Organization-search-params.xml searches Organization.name | Organization.alias. That current model satisfies the original multiple-name use case more directly than the historical extension.

Recommendation:
Keep this no-change audit. The current core specification already supports multiple organization aliases and name search over aliases, and the historical standard extension has been intentionally superseded by the core Organization.alias element. No follow-up core edit is needed for FHIR-3496.
