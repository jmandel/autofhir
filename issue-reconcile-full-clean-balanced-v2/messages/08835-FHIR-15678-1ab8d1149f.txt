FHIR-15678: Audit ElementDefinition path invariants

Issue request:
FHIR-15678 was a Published/Persuasive FHIR-core Change Request for STU3. It asked FHIR-I to clearly define special rules for logical-model element names and add computable invariants: error-level checks for forbidden characters such as '/', whitespace, '.', and '#', plus warning-level checks that element names remain simple alphanumerics starting with a letter to reduce code-generation problems.

Initial application:
The Jira comments record SVN revision 13886. Git-svn commit 1df3fff3b3d7a4d6ee306dae2e6fd6245d959abf, "GF#15678 - element name constraint", is the matching implementation: it added error and warning rows to source/datatypes/elementdefinition.xml for ElementDefinition.path/name constraints. The current source has since been refined, but the original invariant family remains present.

Additional context:
source/fhir.ini lists ElementDefinition as an active datatype and maps the ElementDefinition type page to source/elementdefinition.html, so source/datatypes/elementdefinition.xml and source/elementdefinition.html are current build-scoped sources. Later Published FHIR-I issues intentionally refined the same invariant family: FHIR-17728 allowed [x] in paths, FHIR-19745 and FHIR-26306 fixed 64-character anchoring and Schematron/FHIRPath details, and FHIR-38795/FHIR-38796 clarified the eld-19/eld-20 human descriptions, including logical-model warning context. Those later decisions explain why the current regexes are broader and better worded than the original 2018 text.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The active ElementDefinition spreadsheet contains error-level eld-19, which restricts each '.'-separated path component to 64 characters and excludes whitespace and punctuation including '/', '.', and '#'; it also contains warning-level eld-20, which enforces simple ASCII alphanumeric UpperCamelCase/lowerCamelCase path conventions for code-generation safety. The narrative ElementDefinition.path section states the same path/name rules. A regex smoke check confirmed representative valid paths pass and forbidden whitespace, '/', '#', over-length, underscore, hyphen, and non-ASCII examples fail at the appropriate level.

Recommendation:
Keep this no-change audit commit as-is. No further core FHIR source work is needed for FHIR-15678 unless a future FHIR-I decision changes the broader ElementDefinition.path naming policy.
