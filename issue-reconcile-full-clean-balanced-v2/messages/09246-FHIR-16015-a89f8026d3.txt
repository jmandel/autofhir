FHIR-16015: Audit cross-version extension guidance

Issue request:
FHIR-16015 was a Published/Persuasive FHIR-core STU3 change request asking HL7 to document standard backport extension URLs and generate the related extension information so IGs could reference elements from newer FHIR versions in older-version implementations, including STU3-to-DSTU2 and R4-to-R3/R2 use cases.

Initial application:
The issue traces back to GForge tracker GF#13323 and was applied in source history by commits 641002468f296d9085044e7704733e224a609f82 and 29cb644ee885b2c6959f2ab41d4b767391158b21 on 2018-07-27. Those commits added the "Extensions for converting between versions" section to source/versions.html and linked the diff/transform pages to versions.html#extensions. The originating Zulip thread records Grahame pointing implementers to build.fhir.org/versions.html#extensions immediately after that source change.

Additional context:
Current source/versions.html is an active build page via source/hierarchy.xml and now documents the cross-version URL pattern plus the hl7.fhir.uv.xver-* package matrix. Later applied work, including FHIR-44614 and FHIR-42924, refined the same section, while FHIR-46348 and FHIR-I minutes moved the generated cross-version artifacts/maps out of the Extension Pack into the separate HL7 fhir-cross-version IG/repository. Community discussion in 2025-2026 confirms that package publication and content completeness are now handled in that external cross-version stream, not by editing FHIR core source.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current FHIR core source already provides the standard cross-version extension documentation and current package pointers needed for the core side of FHIR-16015. Adding duplicate prose to source/extensibility.html would not change implementer understanding and would create another maintenance point for guidance that is already centralized on the active version-management page.

Recommendation:
Keep this audit commit as-is for FHIR core. Follow-up work, if any, should be tracked against the fhir-cross-version IG/package publication process or a newer applied Jira issue that specifically changes the core package table or links.
