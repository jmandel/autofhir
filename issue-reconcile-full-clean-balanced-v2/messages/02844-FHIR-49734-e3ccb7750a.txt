FHIR-49734: Audit ElementDefinition.requirements short

Issue request:
FHIR-49734 is Applied/Persuasive with Modification for R6 and asks to fix the ElementDefinition.requirements short display, which said "Why this resource has been created." The voted resolution proposed changing it to "Why this element is defined as it is," and the Jira application comment records that it had already been changed to something else better.

Initial application:
The directly relevant source change was commit 28e721e (FHIR-41846), which changed ElementDefinition.requirements from "Why this resource has been created" to "Requirements satisfied by this element/structure and its constraints." That current wording is the "something else better" noted in the FHIR-49734 Jira application comment. A later commit, 7da8914 titled FHIR-49734, changed Requirements.statement instead of ElementDefinition.requirements; that history was the reason this issue was checked from the FHIR-44500 investigation, but it is not a needed ElementDefinition source change.

Additional context:
source/fhir.ini maps elementdefinition to the elementdefinition datatype page and marks ElementDefinition normative, so source/datatypes/elementdefinition.xml is the current core source to check. The FHIR-I WGM minutes for May 2025 record the FHIR-49734 vote and rationale that both "resource" and "created" were problematic in the old short. The current source no longer uses either problematic term and gives an ElementDefinition-specific requirements description already approved through FHIR-41846.

AutoFHIR reconciliation:
This is an empty audit commit. No source edit is made for FHIR-49734 because the active ElementDefinition.requirements short already corrects the problematic old wording, and changing it again to the literal FHIR-49734 proposal would override the newer, more specific FHIR-41846 wording that Jira explicitly treated as better at application time.

Recommendation:
Keep this audit commit as-is. If the work group later wants the literal FHIR-49734 wording instead of the current FHIR-41846 wording, that should be a new explicit change because the current Applied record says the existing replacement was acceptable.
