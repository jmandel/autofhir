FHIR-26364: Audit BMI valueQuantity cardinality

Issue request:
FHIR-26364 was Applied/Persuasive with Modification for R6 by OO. It asked to change the BMI profile ValueQuantity minimum from 1 to 0, with the final resolution to change ValueQuantity cardinality to 0..1 so a BMI Observation without a measured value can use Observation.dataAbsentReason.

Initial application:
The issue was applied in commit 189879e54bfba9553226a45163c97a39c76ce26f, which changed source/observation/structuredefinition-profile-bmi.xml from min=1 to min=0 on the then-current Observation.valueQuantity element. Later vital-signs cleanup commit 983b8c8cd0 removed explicit valueQuantity min/max details while preserving optionality, FHIR-36401 commits added and aligned the value-or-dataAbsentReason invariant, and FHIR-39181 commit 48a20a606f converted the old Observation.valueQuantity differential element to the current Observation.value[x]:valueQuantity typed-choice slice.

Additional context:
source/fhir.ini lists Observation as an active resource, and source/observation/implementationguide-Observation-vitalsigns.xml includes StructureDefinition/bmi, so the BMI profile XML is current build source. The linked Argonaut Zulip thread shows the original problem: required BMI valueQuantity conflicted with using inline dataAbsentReason when BMI is absent. OO WGM minutes on 2024-09-25 confirm the approved motion to make valueQuantity 0..1. Current base Observation.value[x] is 0..1, and the BMI profile's value[x]:valueQuantity slice does not reintroduce min=1; both the slice and Observation.dataAbsentReason reference the vsp-4 invariant requiring either a value or dataAbsentReason.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already carries the approved semantics after the later refactors: BMI valueQuantity is optional, dataAbsentReason is supported, and the profile still requires one of value[x] or dataAbsentReason for single vital-sign BMI observations.

Recommendation:
Keep this audit commit as-is. No further core source edit is indicated; future edits should retain the current Observation.value[x]:valueQuantity typed-choice representation rather than restoring the obsolete Observation.valueQuantity differential element.
