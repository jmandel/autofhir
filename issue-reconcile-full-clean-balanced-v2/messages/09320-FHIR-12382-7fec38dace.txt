FHIR-12382: Audit extension value/children validation

Issue request:
FHIR-12382 was a Published/Persuasive FHIR-core Encounter issue raised against DSTU2. It reported that the encounter-relatedCondition extension definition showed both a root valueReference and child extensions, which should not be allowed, and asked for automated validation to detect that pattern.

Initial application:
The Jira comments cite svn revision 11399. In git history, the directly matching application is 035362eee26ecc29f555fa60b2e02191aedcb77e, "#12382 - validate extensions", which added ExtensionDefinitionValidator and invoked it from SpreadsheetParser when extension definitions are generated. That validator failed extension definitions that had both a root value and sub-extensions, and otherwise set Extension.extension max to 0 for simple extensions.

Additional context:
The historical DSTU2 encounter-relatedCondition definition still exists only under tools/history/release2, where it demonstrates the original problem by combining child extension slices with a root Extension.valueReference. The current build source does not define encounter-relatedCondition in source/ or in the FHIR Extension Pack checkout, and source/fhir.ini has no release2/tools-history references. The old source/release2 conformance artifacts were removed from the active core build by 5c0494aacfd0b8bd52bc72c587aa89d0a64246f8. Current authoritative source states the general rule both in Extension's invariant and in extensibility narrative, and a current source scan found no active core or extension-pack extension StructureDefinitions with both a non-zero root value and non-zero child extension slices.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The applied issue is already reflected in the current specification rule, the current active extension definitions satisfy the rule, and the only encountered old violation is a historical DSTU2 snapshot outside the current build source.

Recommendation:
Keep this audit commit as-is. No current core source change is needed for FHIR-12382; do not edit the historical tools/history snapshot unless a separate human-reviewed task decides those archived artifacts are in current maintenance scope.
