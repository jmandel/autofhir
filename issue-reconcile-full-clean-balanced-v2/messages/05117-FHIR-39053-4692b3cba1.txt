FHIR-39053: Audit Device conformsTo/property distinction

Issue request:
FHIR-39053 was Published as Persuasive for OO. It reported ambiguity over when to use Device.specialization versus Device.property because specialization.systemType and property.type could appear to carry the same measurement-standard concepts, and its final disposition was to link the answer to FHIR-39322.

Initial application:
No FHIR-39053-tagged source commit was found. The effective application came through the linked Device issue family: FHIR-39322 commits 9e56351cad, 9a661e74e3, and 19e52b5fc8 clarified Device.property as static/fixed and separated dynamic settings into DeviceMetric/Observation, while FHIR-39084 commit 2ca4db69e8 renamed Device.specialization to Device.conformsTo and systemType to specification.

Additional context:
Device, DeviceDefinition, and DeviceMetric are active resources in source/fhir.ini. The current source has no active Device.specialization element; it defines Device.conformsTo for standards/specifications/formal guidance, Device.conformsTo.specification for the specific standard or scheme, and Device.property for inherent, essentially fixed characteristics. The Device property code system now contains fixed-characteristic examples such as material, size, storage, and color, while the specification value set is for standards a device can adhere to. FHIR-39322 itself remains Resolved - change required rather than Applied/Published, so this audit does not decide that broader issue separately.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current active source already resolves the seed ambiguity: the old specialization element that conflicted with property is gone, conformsTo carries the conformance-standard use case, and property is limited to fixed characteristics with dynamic settings directed to DeviceMetric and Observation.

Recommendation:
Keep this audit commit as-is. Do not add redundant Device prose for FHIR-39053; any remaining broader DeviceMetric/Observation guidance from FHIR-39322 should be handled under that issue when it enters the appropriate reconciliation scope.
