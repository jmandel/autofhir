FHIR-15998: Audit ValueSet all-versions syntax

Issue request:
FHIR-15998 was Published with a Persuasive with Modification resolution for STU3. It asked for syntax on ValueSet.compose.include.version to include all versions of a CodeSystem, with '*' accepted as the special identifier for all versions and expansion/version support left to server discretion pending future implementation experience.

Initial application:
The issue was applied in git-svn commit 3ed2652e3d56764f8a8b1f5024155e6b6840a9e1, matching Jira's svn revision 14124 comment. That commit added the all-versions '*' guidance to source/valueset/valueset-notes.xml and to the then-authoritative ValueSet spreadsheet definition for ValueSet.compose.include.version. Later QA and source-format refactors preserved the same semantics in the current XML StructureDefinition and narrative notes.

Additional context:
ValueSet remains an active core resource in source/fhir.ini, so source/valueset/structuredefinition-ValueSet.xml and source/valueset/valueset-notes.xml are in current build scope. The Zulip thread linked from Jira confirms the intended distinction: omitting a version lets the server choose a single version, while '*' explicitly asks for all versions known/supported by the server. No Confluence reference or later community evidence was found that changes the published Jira decision.

AutoFHIR reconciliation:
No source change was made. The current source already defines ValueSet.compose.include.version as "the special version '*' for all versions" and explains that '*' means all versions with server discretion for expansions and supported versions. The narrative composition rules also state that '<code>*</code>' includes codes from all versions of the code system and preserve the implementation-experience warning.

Recommendation:
Keep this audit commit as-is. The current core specification already implements the published FHIR-15998 resolution in the active ValueSet source, and adding more wording would be redundant rather than corrective.
