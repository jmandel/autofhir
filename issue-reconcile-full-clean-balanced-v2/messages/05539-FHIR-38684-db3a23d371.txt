FHIR-38684: Audit Element.id fhir-type correction

Issue request:
FHIR-38684 was a Published/Persuasive FHIR-I technical correction for R4B/R5 reporting that build.fhir.org still showed Element.id with the structuredefinition-fhir-type extension valueUrl "id" after the related FHIR-36036 correction, and requested that the valueUrl be changed to "string".

Initial application:
No FHIR source commit in this checkout directly references FHIR-38684. The issue followed FHIR-36036, which Jira recorded as a tooling issue with an HL7/kindling pull request, and the active FHIR source already declares Element.@id as type string. The historical failure was therefore in generated metadata rather than in the current Element datatype spreadsheet source.

Additional context:
FHIR-25274 documents the intended System.String plus structuredefinition-fhir-type pattern, while FHIR-25262 and the later FHIR-44817 audit keep Resource.id distinct: Resource.id remains constrained as fhir-type id and should not be changed as part of this Element.id issue. A later same-family issue, FHIR-41183, reported the same id-vs-string defect for ElementDefinition.id in R5; it is already represented on the combined branch by a no-change audit commit and records that current R6/build output is corrected. FHIR-I minutes from 2022-12-12 list FHIR-38684 as a technical correction that was auto-approved.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative source has Element.@id as type string in the active Element datatype definition, Element and ElementDefinition are in build scope through fhir.ini, and the current build.fhir.org Element profile now emits Element.id with structuredefinition-fhir-type valueUrl "string".

Recommendation:
Keep this no-change audit as the FHIR-38684 reconciliation. Do not edit Resource.id or other resource logical id metadata under this issue; any remaining R4B/R5 publication-surface concern is historical or generator/republication work outside a current FHIR source edit.
