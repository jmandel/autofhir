FHIR-41582: Correct RelativeTime code value set metadata

Issue request:
FHIR-41582 was Applied/Persuasive with Modification for R6. It requested creation of a TimeFromEvent datatype, resolved as the new RelativeTime datatype with contextReference, contextDefinition, contextPath, contextCode, offset[x], and text plus invariants limiting contextReference/contextDefinition and requiring a context when contextPath is present. The resolution specifically called for RelativeTime.contextCode to have an example binding to Evidence Variable Event.

Initial application:
Commit 86dc727207 created the RelativeTime datatype and made it active in source/fhir.ini for the current build. The current source has RelativeTime in the active [types] list, defines the requested elements and invariants in source/datatypes/relativetime.xml, and binds RelativeTime.contextCode to RelativeTimeCodes using source/datatypes/valueset-relativetime-codes.xml. A later untagged RelativeTime/Dosage commit, e225678eb9, added that value set but copied the canonical URL and work-group metadata from price-component-type.

Additional context:
The current contextDefinition target list includes EventDefinition because later Applied issue FHIR-53409 explicitly added it, so that difference from the original FHIR-41582 resolution is intentional. FHIR-50530 later clarified RelativeTime wording and does not change the contextCode binding. FHIR-41513 was resolved no-change because the datatype and follow-on use trackers covered its scope. FHIR-50586 remains Resolved - change required rather than Applied/Published and concerns rendered datatype constraints boxes, so it is not a source-edit decision for this seed.

AutoFHIR reconciliation:
This commit fixes the active RelativeTime contextCode value set metadata by changing source/datatypes/valueset-relativetime-codes.xml from the copied price-component canonical URL to http://hl7.org/fhir/ValueSet/relativetime-codes and from the copied Patient Administration work-group code to the FHIR Infrastructure work-group code. This is in build scope because RelativeTime is an active datatype in source/fhir.ini and source/datatypes/relativetime.xml references valueset-relativetime-codes for the RelativeTimeCodes binding.

Recommendation:
Keep this commit. The RelativeTime structure and later EventDefinition refinement are otherwise applied; this small fix removes the remaining canonical metadata mismatch that would misidentify the example value set used by RelativeTime.contextCode.
