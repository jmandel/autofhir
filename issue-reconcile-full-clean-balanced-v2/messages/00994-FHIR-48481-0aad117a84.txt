FHIR-48481: Clarify derivation wording

Issue request:
FHIR-48481 is Applied/Persuasive with Modification for R6. It asked FHIR-I to clarify what changes are permitted when deriving OperationDefinitions and SearchParameters, to make SearchParameter.derivedFrom less hand-wavy, to correct the SearchParameter.derivedFrom wording from "defined" to "derived", and to tighten OperationDefinition.base/SearchParameter derivation guidance while keeping the new rules at SHOULD level because the resources are normative.

Initial application:
The main application was commit 4b0ec846152125c2a4906230501aa515d46b2bdf, merged through HL7/fhir#3967, which added the OperationDefinition derivation rules, the SearchParameter "Deriving Search Parameters" usage-note section, ballot feedback notes, and version-specific canonical-reference comments. Follow-up commit 7d7aaa259cf026f8eb99548349474f9b7fc693a5 refined the experimental-rule wording after PR review, and 02f79b0a3ba639280ab7d0d92e364f0a2b676bea made the ballot notes linkable. The implementation left a few issue-scoped source defects: the original OperationDefinition prose still said "change add types", the OperationDefinition derivation rule pointed to a non-existent target element, the added OperationDefinition optional-parameter bullet said "base observation", and SearchParameter.derivedFrom still said "definition from which it is defined".

Additional context:
FHIR-I WGM minutes for 2025-01 record the final 20-0-1 Persuasive with Modification decision, including SHOULD-level rules, targetProfile reduction, parameter add/remove guidance, and SearchParameter derivation guidance. Later FHIR-52921 added a complementary Operation Parameter and Profile Alignment section without reversing the FHIR-48481 derivation rules. FHIR-49704 addressed a separate SearchParameter derivation workflow problem through an extension-pack audit already present on the combined branch. OperationDefinition and SearchParameter are active current-build resources in source/fhir.ini, and no relevant Zulip discussion was found for FHIR-48481.

AutoFHIR reconciliation:
This commit completes the current-core source application by correcting only the remaining issue-scoped wording defects in active source files. It fixes the OperationDefinition narrative to say derived operations cannot "change or add types", changes the derivation rule's original element reference from non-existent OperationDefinition target to OperationDefinition resource, changes "base observation" to "base OperationDefinition", and updates SearchParameter.derivedFrom to refer to the definition from which the search parameter is derived. No generated SVG or rendered artifacts were edited.

Recommendation:
Keep this commit as-is. It preserves the already-approved SHOULD-level derivation guidance and later refinements while removing wording defects that undermine the clarity requested by FHIR-48481. Separate issues such as FHIR-52921 and FHIR-51717 should remain separate reconciliation work if needed.
