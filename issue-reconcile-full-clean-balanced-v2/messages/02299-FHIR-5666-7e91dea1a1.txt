FHIR-5666: Audit identifier cardinality reconciliation

Issue request:
FHIR-5666 was a Published FHIR-core/MnM change request with resolution Persuasive with Modification. It asked for identifier cardinality and type consistency across several resources; the final disposition specifically changed Observation.identifier and DiagnosticReport.identifier to 0..* Identifier, noted a Substance preapplication, and recorded MnM's tooling/design preference rather than applying every originally suggested resource change.

Initial application:
The issue was applied before this reconciliation. Commit 301f09fdfe changed Observation.identifier from 0..1 to 0..* and added the #5666 committee note in the old Observation spreadsheet. Commit 6a069aa5ab preapplied #5666 to Substance.identifier and Substance.instance.identifier in response to a build warning. Later source refactors, including the 2021 StructureDefinition conversion, carried the Observation #5666 note and the repeating Identifier cardinality forward into the current XML source.

Additional context:
The current build scope lists Observation, DiagnosticReport, Composition, Group, Location, MedicationDispense, MessageHeader, Substance, SupplyRequest, SupplyDelivery, and AuditEvent as active resources, while DeviceObservationReport, Query, Supply, and SecurityEvent are in removed-resources. Current active listed resources with top-level identifier elements use Identifier with max=*, including Observation and DiagnosticReport. MessageHeader has no top-level identifier and only MessageHeader.response.identifier 1..1 Identifier, which is consistent with the Jira discussion that multiple MessageHeader identifiers were not common and with the modified resolution's narrower application. AuditEvent has no identifier, matching the Jira comment that the change request was removed from AuditEvent/SecurityEvent because no application was found. Current resource guidance already discusses consistent business identifiers, and the current suppression list confirms the build still warns when resources lack identifiers.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative current source already reflects the final applied issue scope: Observation.identifier and DiagnosticReport.identifier are 0..* Identifier, related active resources are not using non-Identifier top-level identifier types, and out-of-scope historical resources are removed from the current build.

Recommendation:
Keep this audit commit as-is. If the work group wants stronger public design guidance that identifier upper cardinality should generally be *, that should be handled as a new editorial/design issue because FHIR-5666's conformance-impacting changes are already represented in the current build.
