FHIR-43484: Audit ExampleScenario usage scope

Issue request:
FHIR-43484 was an Applied/Persuasive with Modification FHIR-I R6 clarification asking whether ExampleScenario should be treated as a FHIR resource for data exchange. The accepted resolution changed the Scope and Usage opening from saying the resource was expected to be used in implementation guides or specifications to saying that ExampleScenario provides examples for data exchange workflows, is similar to ImplementationGuide, Requirements, ActorDefinition, and related definitional resources, and is typically exchanged in implementation guide packages rather than between clinical systems.

Initial application:
The issue was explicitly applied by git commit 6d21a4c1c014f8b726b9f21861b2ce666dfc6282, which Jira cites as "Git master 6d21a4c1c0." That commit changed source/examplescenario/examplescenario-introduction.xml by replacing the old first sentence with the approved scope wording and splitting the following usage sentence into a separate paragraph.

Additional context:
source/fhir.ini actively registers examplescenario=ExampleScenario and lists ExampleScenario as fhir-owned, normative, and approved, so source/examplescenario/examplescenario-introduction.xml is build-scoped narrative for the current resource. FHIR-I minutes for 2024-01-08 record FHIR-43484 as P w/ mod. A later FMG resource-maturity thread lists ExampleScenario among resources recommended to stay in the main specification, and searches found no direct Zulip discussion or later Jira issue that conflicts with the applied usage wording. The extra rationale in the Jira resolution about computable representations explains why such artifacts can use resource form; it does not require a separate source hunk beyond the applied scope clarification.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current introduction already says that ExampleScenario examples describe data exchange workflows and that the resource is typically exchanged as part of implementation guide packages for implementer understanding, not as clinical-system information exchange.

Recommendation:
Keep this no-change audit commit as-is. No follow-up source work is needed for FHIR-43484 unless FHIR-I later decides to add broader rationale about computable definitional artifacts across ExampleScenario or related resources.
