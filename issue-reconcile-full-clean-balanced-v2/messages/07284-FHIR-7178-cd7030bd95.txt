FHIR-7178: Audit NutritionOrder order-scope note

Issue request:
FHIR-7178 was Published/Persuasive with Modification for DSTU1 NutritionOrder.oralDiet.nutrient.amount. The comment asked to distinguish fields that are part of a provider order from fields used by internal dietary systems; the final decision said the base resource stays broad, profiles constrain specific use cases, and the example/resource narrative should explain pre-coordination of diet items into picklists.

Initial application:
The issue appears to have been applied by git commit 5609ec13c8 (#6103, #7178 add notes to NO), which added the NutritionOrder notes section and specifically added the example note that examples show core elements, real implementations may be constrained by profiles, and renal diets may use pre-coordinated components such as protein, potassium, and phosphorus. Later editorial commits kept that note while updating surrounding wording and links.

Additional context:
NutritionOrder is an active current-build resource in source/fhir.ini and belongs to the OO work group. Current NutritionOrder scope text already says the resource can be used by physicians, dietitians/nutritionists, and speech therapists, that optional elements support both simple provider orders and more detailed information augmented by specialists, and gives a physician 2 g sodium diet example. FHIR-7172 is supporting context for the same provider-versus-dietary scope question, while FHIR-6103 shared the same historical notes commit for the enteral feeding note.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current source still contains the FHIR-7178 application note, and the nearby scope/usage text now conveys the intended separation by use case without labeling base elements as provider-only or internal-only. Adding new element-level labels would go beyond the final resolution that profiles should constrain those distinctions.

Recommendation:
Keep this no-change audit as-is. Future work should only add more specific provider/internal dietary guidance if OO opens a new tracker or profile-specific requirement; the base resource should remain broad per the published FHIR-7178 decision.
