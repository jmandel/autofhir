FHIR-27920: Audit canonical version scheme guidance

Issue request:
FHIR-27920 was Published with a Persuasive with Modification resolution for FHIR-core Questionnaire. It asked the specification to identify common versioning schemes such as SemVer and timestamps for conformance/canonical resources, warn that servers may not be able to determine the most recent version when no standard or known mechanism is used, and initially proposed adding SemVer guidance to FHIR-I-owned canonical resources.

Initial application:
The issue was explicitly applied by commit 5aca6cffba09000504c4fc24204d3f6605648b80 on 2022-09-05. That commit changed the active References page source, source/references.html, to mention SemVer and dateTime-style version practices, to state that canonical resources are not required to use SemVer but HL7 recommends and uses it, and to add guidance that unknown version algorithms make determining the current version problematic. The Jira application comment says the language was intentionally placed on the References page because that is where version resolution is discussed, with wording adjusted for the new versionAlgorithm[x] mechanism.

Additional context:
FHIR-26370 introduced CanonicalResource.versionAlgorithm[x] as the computable mechanism for comparing canonical versions. Current source keeps that element on CanonicalResource and on Questionnaire, and later FHIR-52895 expanded source/references.html with detailed canonical version matching rules for SemVer, date, URL, and fallback schemes. FHIR-39268 later challenged whether versionAlgorithm[x] belonged on each resource, but FHIR-I kept it there as the least-bad mechanism for cases where context cannot identify a versioning scheme. The 2020 Zulip thread that led to FHIR-27920 and the 2020 FHIR-I minutes both align with the current centralized guidance: servers cannot reliably infer latest business versions unless a consistent scheme or comparison algorithm is known.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope References page already conveys the required guidance, and active Questionnaire/CanonicalResource definitions already expose versionAlgorithm[x]. Adding a separate Questionnaire.version SHOULD-use-SemVer sentence now would be redundant at best and could conflict with the later versionAlgorithm model that explicitly permits SemVer, date, URL, and fallback schemes.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for FHIR-27920 unless FHIR-I opens a new tracker to strengthen the current centralized recommendation or to change the versionAlgorithm[x] model.
