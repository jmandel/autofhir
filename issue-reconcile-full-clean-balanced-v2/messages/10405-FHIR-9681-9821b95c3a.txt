FHIR-9681: Audit batch processing clarification

Issue request:
FHIR-9681 was Published/Persuasive for DSTU2 and asked to clarify ambiguous Batch Processing Rules in the RESTful API. The approved wording kept a SHALL that there are no interdependencies between batch entries that cause server changes, changed the success/failure and validation statements to SHOULD, and added that references to resources being created within the batch are non-conformant.

Initial application:
The Jira comment cites svn revision 8922, represented by git commit 0f3e257ee48e646527b7803437da37d829bb8c75. That commit changed source/http.html from the original FHIR-6122 batch rule to the clarified wording, including the SHOULD validation language and the created-resource reference warning.

Additional context:
FHIR-6122 introduced non-atomic batch support and the first no-interdependencies rule. The linked Zulip discussion in #implementers > transactions shows the ambiguity that prompted FHIR-9681: implementers asked whether cross-entry references and server validation were testable, and Grahame Grieve noted deliberate looseness before the change request was filed.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current combined-branch REST source contains the clarified FHIR-9681 rule, including the narrowed interdependency scope, SHOULD validation language, and non-conformant references to resources created in the same batch.

Recommendation:
Keep this commit as-is. The current source matches the final clarification; any move back to mandatory server validation/rejection would need a new work-group decision because it would reverse FHIR-9681.
