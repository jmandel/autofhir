FHIR-32575: Audit DiagnosticReport subject focus handling

Issue request:
FHIR-32575 was Published with a Persuasive with Modification resolution for R5. It asked that Procedure not remain a DiagnosticReport.subject and resolved to remove Procedure from DiagnosticReport.subject while adding a focus extension, 0..* Reference(Any), for focal components such as a Procedure or manufacturing process evaluated by a quality report.

Initial application:
The R5 application is visible in HL7/fhir PR #2598. Commit 9622124f4e removed Procedure from DiagnosticReport.subject, and merge 8b80ac4b98 brought in that removal plus a DiagnosticReport focus extension for FHIR-32575. The current core source preserves the subject change: DiagnosticReport.subject references Patient, Group, Device, Location, Organization, Practitioner, Medication, Substance, and BiologicallyDerivedProduct, but not Procedure.

Additional context:
OO minutes show the January 2023 discussion first reopened an in-person not-persuasive motion to confirm the BR&R manufacturing-process use case, then the January 26 main call accepted the block vote 10-0-2. Later R6 work changed the current core shape: FHIR-49614 added DiagnosticReport.procedure for performed procedures reported on by the DiagnosticReport, FHIR-50866 kept and clarified that element, and FHIR-45132 expanded DiagnosticReport.supportingInfo.reference. The original diagnosticReport-focus extension is no longer authored in core; it exists in the FHIR Extension Pack with the canonical URL http://hl7.org/fhir/StructureDefinition/diagnosticReport-focus and the resolved fixedUri/value reference definition.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active DiagnosticReport resource is in build scope, the current core source already excludes Procedure from DiagnosticReport.subject, and the remaining focus-extension artifact is maintained outside this core checkout in the FHIR Extension Pack. Adding redundant core prose or recreating the extension in core would conflict with the current artifact split and later DiagnosticReport elements.

Recommendation:
Keep this audit commit as-is. Future changes to the focus extension should be made in the FHIR Extension Pack; future changes to core should be handled through the later DiagnosticReport.procedure and supportingInfo decisions rather than reversing the FHIR-32575 subject cleanup.
