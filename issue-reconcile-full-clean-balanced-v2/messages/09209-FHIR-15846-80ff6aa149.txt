FHIR-15846: Audit implant status modifier removal

Issue request:
FHIR-15846 was a Published/Persuasive OO change request for STU3 asking whether the Device implant-status extension should be a modifier extension. The approved resolution was to leave the isModifier tag off, because implant status does not nullify the Device resource in the way an entered-in-error status would.

Initial application:
The request was pre-applied in git commit b437a5fdc0b21d669e05f8854231006deac215f7, which removed the populated Is Modifier column from the implant-status row in source/device/device-extensions-spreadsheet.xml. Before that commit the row contained Y in the Is Modifier column; after the commit the corresponding cells were blank. That spreadsheet was later removed during the current build source rework.

Additional context:
Current core no longer has an active device-implant-status extension source, and the FHIR Extension Pack checkout also has no device-implant-status definition. Device remains an active resource and DeviceAssociation is now an active resource for subject/device association state; its associationStatus element carries implanted/explanted style state as a normal CodeableConcept without an isModifier flag. The only current checkout occurrence of the old extension is tools/history/release3/extension-definitions.xml, a historical STU3 bundle copy outside source/fhir.ini current build scope; editing that generated-looking historical copy would not be a current-spec correction.

AutoFHIR reconciliation:
This audit commit makes no source change. The current build-source state already satisfies the Jira decision: the old active extension source with the modifier flag is gone, no replacement active extension reintroduces it, and the current DeviceAssociation representation does not mark implant association state as modifier.

Recommendation:
Keep this audit commit as-is. Do not edit tools/history/release3 for this issue unless a separate human decision says the historical release bundle should be regenerated or corrected outside the current-spec source reconciliation scope.
