FHIR-20211: Audit Last-Modified format note

Issue request:
FHIR-20211 was a Published/Persuasive FHIR-core HTTP change request raised against STU3 and applied for R5. It observed that the HTTP page said the Last-Modified header should come from Resource.meta.lastUpdated even though meta.lastUpdated is a FHIR instant and the HTTP Last-Modified header uses a different RFC 7232 HTTP-date format. The approved resolution was to add a note that the header format is different.

Initial application:
The issue was applied in source/http.html by commit 0a1dbe19f6, which added a note under Resource Metadata and Versioning stating that Last-Modified should come from .meta.lastUpdated but has a different format, with MDN and RFC 7232 references. Commit 7b129e2288 immediately corrected XHTML syntax around that note. Later HTTP-page edits left this FHIR-20211 note intact.

Additional context:
The HTTP page is in current build scope as the RESTful API page listed in source/hierarchy.xml under Exchange. Later lastUpdated work, including FHIR-45047 and implementer discussion about Last-Modified being GMT/UTC, clarifies that meta.lastUpdated and HTTP Last-Modified can denote the same instant even though their string formats differ. That later context supports, rather than conflicts with, the existing FHIR-20211 note. No Confluence reference to FHIR-20211 was found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already contains the requested warning at source/http.html:215, and adding another wording change would be redundant rather than a necessary correction to implementer understanding.

Recommendation:
Keep this no-change audit commit as the FHIR-20211 reconciliation. If future work wants to modernize the RFC link from RFC 7232 to the current HTTP Semantics RFCs or expand the Meta.lastUpdated discussion, handle that under a new HTTP editorial issue or the existing lastUpdated issue family rather than reopening this applied tracker.
