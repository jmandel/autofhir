FHIR-7687: Audit history authorization guidance

Issue request:
FHIR-7687 was a Published FHIR-core Security change request, resolved Not Persuasive with Modification, asking for delete/history-specific authorization caveats based on Provenance and Consent. The accepted disposition rejected embedding a specific delete policy in the REST specification, but directed that the security guidance note that operations are subject to RBAC, ABAC, consent, and related authorization controls.

Initial application:
The issue was applied by git-svn commit ae3042ca1e07b476a53c38836836edbf5255a3a2, matching Jira's svn revision 6464 comment. That commit added RESTful API guidance to source/http.html stating that most operations require user authentication, operations that do are subject to RBAC and/or ABAC, and some operations may depend on appropriate consent.

Additional context:
The current build still includes source/http.html and source/security.html as publish.ini pages. The HTTP page retains the authorization note and links to the Security page, while the Security page has broader Authorization/Access Control guidance explaining RBAC, ABAC, consent-driven policies, CRUD/operation authorization checks, AuditEvent recording, and Provenance/Consent linkage. A later FHIR-40957 terminology cleanup changed "operations" to "interaction" in the HTTP note, but did not remove the RBAC/ABAC/consent meaning needed for this issue.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because the current specification already implements the accepted general authorization guidance, and adding a delete/history-specific policy rule would contradict the Jira disposition that policy should not be embedded in the specification.

Recommendation:
Keep this audit commit as-is. If editors revisit the HTTP note, they may separately tidy the singular/plural wording introduced by the later interaction terminology cleanup, but FHIR-7687 itself does not require a source change.
