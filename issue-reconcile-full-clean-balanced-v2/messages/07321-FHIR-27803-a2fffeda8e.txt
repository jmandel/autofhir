FHIR-27803: Audit initialSelected comment removal

Issue request:
FHIR-27803 was a Published FHIR-core Questionnaire change request, resolved Persuasive with Modification for R5. The reporter found the comment on Questionnaire.item.answerOption.initialSelected confusing because it said to use initialSelected when answerValueSet is present even though answerOption and answerValueSet are mutually exclusive. The approved resolution was to remove that comment and rely on the invariant that bars initial[x] when answerOption is present.

Initial application:
The issue was applied by 97fc73a3795794215b6c33d365787cfc3d4bc6df, which removed the misleading comment from source/questionnaire/structuredefinition-Questionnaire.xml. The current source still has no comment on Questionnaire.item.answerOption.initialSelected, while the active Questionnaire resource entry in source/fhir.ini confirms the StructureDefinition remains in current build scope.

Additional context:
The linked Zulip thread shows the confusion came directly from the answerValueSet wording, and the SDC minutes for 2020-06-11 record the 9-0-0 decision to remove the comment. FHIR-22686, decided in the same meeting, kept que-11 and updated its English text to say that when answerOption is present, initial[x] cannot be present and answerOption.initialSelected should be used instead. FHIR-13816 is historical background for why initialSelected exists, but it does not require any further change for this issue.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The obsolete answerValueSet comment has already been removed from the authoritative Questionnaire StructureDefinition, the current que-11 invariant provides the replacement guidance the resolution relied on, and a source search found no remaining copy of the removed wording.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for FHIR-27803 unless a future work group decision revisits the broader initialSelected versus initial[x] design.
