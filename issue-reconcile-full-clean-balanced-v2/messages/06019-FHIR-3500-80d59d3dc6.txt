FHIR-3500: Audit HumanName practitioner name support

Issue request:
FHIR-3500 was a Published/Persuasive PA issue asking that practitioner names support the components needed for real-world health-worker directory names. The final resolution was to add HumanName documentation and examples explaining how common name components map, with PA separately approving repeat Practitioner.name rather than repeat HumanName.text.

Initial application:
The HumanName documentation part appears to have been applied by git-svn commit 77004cea3f6efea47c635074f2b8ff2d5680c1ad, "{#3500}: clarifications around use of name", which added a common-parts table and international examples. The Practitioner.name repeatability portion was handled through FHIR-9067 and applied by 64afb1d0b601aca0cd926438c18e5ca11ddbf6ab, which changed Practitioner.name from 0..1 to 0..* and added display-name selection guidance.

Additional context:
Current fhir.ini keeps HumanName in the active datatype list and Practitioner in the active resource list. Current HumanName source now includes the common-parts table, guidance about alternate HumanName instances, culture-dependent ordering, text-versus-parts robustness, and family-name decomposition guidance. Current Practitioner.name is 0..* with the expected guidance for choosing the name used in ResourceReference.display. Later FHIR-12351 reworked HumanName family-name decomposition and is already represented on the combined branch, which explains why current HumanName.family is no longer modeled as repeating even though older FHIR-3500 examples showed repeated family elements.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative source already satisfies the applied FHIR-3500 request when read with the linked FHIR-9067 application and later HumanName rework; adding more prose would duplicate existing guidance and risk drifting from the current HumanName model.

Recommendation:
Keep this no-change audit commit as-is. No follow-up is needed in core unless a future work group decision asks for new HumanName examples or Practitioner-specific name guidance beyond the existing datatype and Practitioner.name text.
