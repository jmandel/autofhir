FHIR-27910: Audit care-gap DetectedIssue category

Issue request:
FHIR-27910 was a Published/Persuasive CDS change request for R5 asking to add a care-gap code to the Detected Issue Category value set because Gaps in Care Reporting was using DetectedIssue with a fixed care-gap code.

Initial application:
No source commit explicitly mentions FHIR-27910. The request was initially satisfied through the same change family: UTG proposal UP-175 added v3 ActCode CAREGAP under _ClinicalActionDetectedIssueCode, and FHIR-39309 implemented FHIR-31677 by adding _ClinicalActionDetectedIssueCode to the FHIR DetectedIssueCategory value set before R5 publication. The R5 historical value set therefore included CAREGAP through that parent.

Additional context:
FHIR-39458 later made an Applied/Persuasive R6 decision that DetectedIssue.code should not be bound to the Detected Issue Category value set. Its implementation created a separate DetectedIssue Code value set for detailed issue codes and restricted DetectedIssue Category to only category-level codes. Current source follows that later decision: source/fhir.ini lists detectedissue as an active resource; DetectedIssue.category binds to the restricted category value set, and DetectedIssue.code binds to the new value set that includes _ClinicalActionDetectedIssueCode, where CAREGAP belongs.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Re-adding CAREGAP to DetectedIssue.category would undo the later FHIR-39458 category/code split; the current build still permits the care-gap concept in the appropriate detailed DetectedIssue.code binding.

Recommendation:
Keep this no-change audit. Use DetectedIssue.code for v3 ActCode CAREGAP in the current model. If CDS wants CAREGAP to be a category-level value again, that should be raised as a new work-group decision revisiting the FHIR-39458 split rather than as a reconciliation fix for FHIR-27910.
