FHIR-17458: Audit eligibility purpose support

Issue request:
FHIR-17458 was a Published/Persuasive with Modification FM change request for STU3. It asked to add a 1..* code to EligibilityRequest and EligibilityResponse to convey the purpose/requested actions, and the final resolution named the element `purpose` with auth-requirements, benefits, discovery, and validation codes.

Initial application:
The issue was applied in historical commit 10ac2496c7, which explicitly listed tracker 17458 and added purpose/use values to the old EligibilityRequest and EligibilityResponse source/examples as part of the STU3-era eligibility cleanup. Later source refactors, especially 33b409a4b6 and c69d71aa21, carried the content into the current CoverageEligibilityRequest and CoverageEligibilityResponse source files, StructureDefinitions, code systems, and value sets. No prior FHIR-17458 reconcile commit was present on the combined branch.

Additional context:
The current build uses CoverageEligibilityRequest and CoverageEligibilityResponse as the active resources; source/fhir.ini maps those current names back to the old EligibilityRequest and EligibilityResponse names. The same historical eligibility cleanup commit also touched FHIR-17459, FHIR-17460, and FHIR-17473, but those are separate decisions and already have their own reconcile commits on the combined branch. FHIR-17473 is relevant only as supporting context because its final resolution says the type-of-request code is already handled by `.purpose`. Jira, Zulip, and Confluence searches found no later decision that changes FHIR-17458's purpose-element requirement.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current source already has CoverageEligibilityRequest.purpose and CoverageEligibilityResponse.purpose as 1..* `code` elements with required bindings, the current code systems and value sets include the four requested purpose codes, and the active examples populate purpose values.

Recommendation:
Keep this no-change audit commit as-is. The current core source already implements FHIR-17458 through the renamed CoverageEligibilityRequest/CoverageEligibilityResponse resources, so further core changes would be redundant for this issue.
