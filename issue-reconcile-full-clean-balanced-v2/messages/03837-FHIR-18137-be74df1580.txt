FHIR-18137: Audit VerificationResult communication method rename

Issue request:
FHIR-18137 was a Published/Persuasive with Modification Patient Administration change request for VerificationResult. It required renaming VerificationResult.primarySource.validationProcess to communicationMethod with short text "Method for exchanging information with the primary source", renaming VerificationResult.attestation.method to communicationMethod with corresponding attester wording, and adding a generic communication-method example binding/value set.

Initial application:
The request was applied in core by git commit ffe009e9cf00c81dc11cf81d1045b641b0d9a7bb, whose subject explicitly includes GF#18137. That commit changed source/verificationresult/verificationresult-spreadsheet.xml from VerificationResult.primarySource.validationProcess and VerificationResult.attestation.method to VerificationResult.primarySource.communicationMethod and VerificationResult.attestation.communicationMethod, and added the communication-method terminology source.

Additional context:
VerificationResult is no longer an active resource in this FHIR core checkout: source/fhir.ini has no active VerificationResult resource entry, source/verificationresult is absent, and commit 71567db3ee039ac6977be5f96a7e013896569a36 removed the core source while leaving history/ballot text pointing to the HL7 Admin Incubator copy. The current checked history/model artifacts and the current Admin Incubator StructureDefinition use primarySource.communicationMethod and attestation.communicationMethod; the remaining VerificationResult.validationProcess element is the separate resource-level element that the Jira intentionally distinguished from primarySource.communicationMethod.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current core build has no active VerificationResult source to edit, and the current surviving/external representations already preserve the FHIR-18137 rename and binding target.

Recommendation:
Keep this audit commit as-is. Any future changes to the live VerificationResult resource should be made in HL7/admin-incubator, not in core, unless the resource is reintroduced to the core build.
