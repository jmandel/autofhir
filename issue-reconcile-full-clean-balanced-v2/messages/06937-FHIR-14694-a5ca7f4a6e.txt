FHIR-14694: Audit ValueSet include.valueSet union wording

Issue request:
FHIR-14694 was Published/Persuasive with Modification for STU3. The ballot comment asked to clarify ValueSet.compose.include.valueSet cardinality and whether multiple referenced value sets were intersected or joined; the final resolution retained singular element wording but changed the definition to say multiple valueSet references included the union of all referenced value-set contents.

Initial application:
The issue was pre-applied in SVN r13351, represented in git as d90f55e1cb, which updated source/valueset/valueset-spreadsheet.xml with the seed's short text and union definition. Later source refactors moved the active ValueSet definition into source/valueset/structuredefinition-ValueSet.xml.

Additional context:
FHIR-25179 was a later Published/Persuasive R5 Vocabulary decision for the same element and explicitly changed this sentence from union to intersection, with matching expansion-algorithm guidance for how to create unions through separate include entries. FHIR-30574 later raised the same apparent inconsistency and was closed Resolved - No Change / Not Persuasive as duplicate/background. The combined branch already contains bbb15e86e66f453d528c4dde1a08846ded2f63f0 auditing FHIR-25179, so this reconciliation does not republish that related issue.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active ValueSet resource is in build scope through source/fhir.ini, the current structure definition says multiple valueSet references within one include use the intersection of referenced contents, and the Value Set Expansion narrative also describes intersecting the referenced value-set result sets. Restoring the seed's older union sentence would undo the later final FHIR-25179 decision.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-14694 because its applied union wording was superseded by a later published decision; revisit only if Vocabulary creates a new final Jira decision changing include.valueSet semantics again.
