FHIR-18241: Audit CDS Hooks response mapping

Issue request:
FHIR-18241 was a Published/Persuasive STU3 CDS work group change request asking the Clinical Reasoning CDS-on-FHIR guidance to clarify that a CDS Hooks Response maps 1:1 to a RequestGroup, that each Card maps to a root action, each Suggestion maps to a nested action, suggestion resources map to the nested action resources, and selection behavior is specified.

Initial application:
The Jira comment records GH#:20fd62db2d, and git commit 20fd62db2d557dd133bd32041d93ba3f4edbd62b explicitly states "GF#18241: Clarify mapping to CDS Hooks response". That commit added the requested response mapping tables to source/clinicalreasoning-cds-on-fhir.html, including Response/Card/Suggestion/Action object mappings, nested RequestGroup.action paths, and card/suggestion selectionBehavior guidance.

Additional context:
The current core build still includes source/clinicalreasoning-cds-on-fhir.html through source/hierarchy.xml, but later FHIR evolution renamed RequestGroup to RequestOrchestration and later Applied/Persuasive CDS decisions FHIR-53085 and FHIR-48393 intentionally moved the detailed CDS-on-FHIR page content, CDS Hooks profiles, and mapping concept maps out of FHIR core into the Using FHIR Clinical Reasoning with CDS Hooks IG. Current core source is now an informative overview that describes transforming PlanDefinition/$apply output into a CDS Hooks response and links detailed guidance to that IG. The IG source contains the response mapping table with the RequestOrchestration equivalents of the original RequestGroup mappings.

AutoFHIR reconciliation:
This audit commit makes no source change. Re-adding the detailed response mapping table to FHIR core would undo the later migration and duplicate content now maintained in the dedicated CDS Hooks Clinical Reasoning IG. The current core source correctly keeps a concise local overview and points implementers to the artifact that owns the detailed response mapping.

Recommendation:
Keep this no-change audit as-is for FHIR-18241. Future corrections to the CDS Hooks response mapping, the RequestOrchestration profile, or IG anchors should be handled in the CDS Hooks Clinical Reasoning IG or under a new CDS work group issue, not by restoring the old STU3 table to FHIR core.
