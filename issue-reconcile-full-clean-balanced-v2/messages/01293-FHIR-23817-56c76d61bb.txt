FHIR-23817: Audit timezone extension rename

Issue request:
FHIR-23817 was a Published/Persuasive FHIR-core datatype issue for R5. It requested renaming the R4 tz-code extension to timezone, changing its name/title, and improving the description so implementers distinguish a named IANA time zone from a numeric time offset.

Initial application:
Core commit 5cbc14c7d0f361941099bf72066b75c3f74f6d4f listed FHIR-23817 in the R5 MnM batch and changed the extension row in source/profiles/general-extensions-spreadsheet.xml from tz-code to timezone. Later core commits normalized extension name/title fields to TimezoneCode/Timezone Code, added related context, and then removed extension definitions from the active R5 core source when they moved out of this checkout.

Additional context:
The current core build no longer owns the timezone StructureDefinition source: source/fhir.ini has no active timezone extension-definition entry, and current core source only references http://hl7.org/fhir/StructureDefinition/timezone from datatype narrative, examples, and the OID registry. The FHIR Extension Pack is the active source for input/definitions/datatypes/StructureDefinition-timezone.xml and includes input/definitions/* in its IG resource path. It also carries a retired/deprecated StructureDefinition-tz-code.json that points users to StructureDefinition/timezone. Later issues FHIR-38006 and FHIR-43351 clarified time-zone-code versus time-offset language and the timezone extension description, so the current TimezoneCode/Timezone Code wording is not treated as a semantic defect.

AutoFHIR reconciliation:
Published an empty external-repo audit commit. No FHIR-core source was changed because the remaining authoritative extension definition source lives in the FHIR Extension Pack, and that source already represents the approved rename by defining StructureDefinition/timezone and retiring/deprecating StructureDefinition/tz-code.

Recommendation:
Keep this audit commit as-is for the FHIR-core reconciliation. Future changes to the timezone or tz-code StructureDefinition metadata should be made in the FHIR Extension Pack; only reopen the name/title wording there if the work group wants a new decision overriding the later TimezoneCode/Timezone Code and FHIR-43351 description.
