FHIR-17232: Audit canonical source guidance

Issue request:
FHIR-17232 was Published/Persuasive with Modification for FHIR-core many metadata resources. It asked for a mutable resource.authoritativeurl element to identify the source-of-truth location for a resource when MetadataResource.url is no longer a reliable location; the accepted resolution instead used Resource.meta.source, adding guidance to MetadataResource.url, Meta.source, and terminology/registry narrative.

Initial application:
The request was applied before this reconciliation by commit 8d91ecdf35396eebd61bcd65853d1384a559d470, "GF#17232 - notes about meta.source and canonical url", which added the requested canonical URL and Meta.source notes to the then-current MetadataResource spreadsheet and Meta datatype spreadsheet. The current source has since refactored MetadataResource.url through CanonicalResource.url, but source/fhir.ini actively maps MetadataResource.url to CanonicalResource.url.

Additional context:
Current source/canonicalresource/structuredefinition-CanonicalResource.xml says the canonical URL should be a literal address for an authoritative instance and that, when the resource can no longer be found at the stated URL but the URL cannot change, implementations can use meta.source to indicate where the current master source is found. Current source/datatypes/meta.xml says Meta.source can indicate where the current master source of a canonical resource is found when it is no longer hosted at the canonical URL. Later FHIR-17570 concluded that this general Meta.source guidance was not reliable enough for the ValueSet-specific authoritative-source use case and added a valueset-authoritativeSource extension, now maintained in the FHIR Extension Pack; that later decision narrows rather than invalidates the general FHIR-17232 guidance. Later FHIR-49878 clarified the Meta.source definition from "source system" to "data source" and explicitly allowed portions of a structure, while preserving the current-master-source canonical URL note.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current source already carries the FHIR-17232 canonical URL and Meta.source guidance in the refactored CanonicalResource/Meta locations, and adding new terminology ValueSet prose that directs users to Resource.meta.source would conflict with the later ValueSet-specific FHIR-17570 resolution.

Recommendation:
Keep this no-change audit as-is. Future edits should avoid adding a new core authoritativeurl element or reasserting Meta.source as the sole ValueSet authoritative-source mechanism; ValueSet/artifact authoritative-source maintenance belongs with the Extension Pack extensions while the core CanonicalResource.url and Meta.source guidance remains appropriate.
