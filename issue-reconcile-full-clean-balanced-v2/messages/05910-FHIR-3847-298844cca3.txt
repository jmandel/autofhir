FHIR-3847: Audit RelatedPerson modifier status

Issue request:
FHIR-3847 is a Published / Persuasive with Modification DSTU1 PA issue asking that incorrectly marked isModifier fields be removed from RelatedPerson. The recorded resolution says there are no isModifier fields on RelatedPerson and that all were removed.

Initial application:
No current git commit in this checkout mentions FHIR-3847, which appears to have been applied in the legacy DSTU1 source history before the current StructureDefinition XML source. The current build source no longer has the original group of incorrectly marked RelatedPerson fields; it has exactly one RelatedPerson isModifier flag, on RelatedPerson.active.

Additional context:
The remaining RelatedPerson.active modifier is a later status-element change, not the old set of fields addressed by FHIR-3847. FHIR-10364 later added an active flag and search parameter to RelatedPerson, Schedule, and HealthcareService so those resources could be marked inactive/not in current use, consistent with Patient, Practitioner, and Person. Published STU3, R4, and R5 RelatedPerson definitions and the current active build source all treat RelatedPerson.active as a modifier because it can indicate that a record should not be treated as valid. FHIR-54873 separately confirms the same current .active pattern for another resource.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Removing the current RelatedPerson.active isModifier flag would conflict with the later active/status semantics and with the current published FHIR pattern.

Recommendation:
Keep this no-change audit. If PA wants to revisit whether .active should distinguish inactive from entered-in-error or whether active should remain a modifier, that should be handled as a new cross-resource active/status tracker rather than by reapplying the older DSTU1 cleanup.
