FHIR-7653: Audit Encounter.class binding disposition

Issue request:
FHIR-7653 is a Published/Not Persuasive with Modification PA change request from the 2015 May core ballot. It asked whether Encounter.class should allow multiple values because outpatient/inpatient and emergency use cases are not mutually exclusive; the final disposition kept class as the encounter setting rather than urgency, pointed to Encounter.priority for priority, expected separate/related Encounters or class transitions for emergency-to-inpatient workflows, confirmed virtual visits were covered, and required the emergency class description to be changed from urgent-care wording to an emergency department/location concept.

Initial application:
The issue was explicitly applied in commit 171fbc6b79cecfd1f0db542a6c3c827cb043c9dd, "Tracker# 7653, encounter class valueset descriptions update." That commit changed the old Encounter spreadsheet value set definition for emergency from "An encounter where the patient needs urgent care" to "An encounter in the Emergency Care Department." The old spreadsheet source is no longer the current authoritative source for Encounter.class in this build.

Additional context:
Encounter is active in source/fhir.ini, and the current source/encounter/structuredefinition-Encounter.xml defines Encounter.class as 0..* CodeableConcept with a preferred binding to http://terminology.hl7.org/ValueSet/encounter-class. Later Published PA decisions FHIR-32342 and FHIR-32341 intentionally changed Encounter.class from the older singular coded shape to CodeableConcept, 0..*, and a preferred binding to a smaller THO value set; those issues are already represented on the combined branch. FHIR-39147 later fixed the THO value set URL casing. The current THO v3 ActCode EMER definition is location/setting based and explicitly describes transfer/admission after emergency care, while VR covers virtual encounters, so the current terminology surface preserves the material FHIR-7653 clarification even though wording has evolved.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The 2015 required description update was applied historically, current core source binds to the terminology-owned encounter-class value set, and later PA decisions deliberately changed the cardinality and binding strength in a way that now accommodates multiple classifications. Reintroducing old wording into core narrative would be redundant and could drift from the terminology source of truth.

Recommendation:
Keep this no-change audit commit. No FHIR core edit is needed for FHIR-7653; if PA wants the THO EMER definition to use the exact phrase "Emergency Care Department," that should be handled as a terminology/UTG follow-up rather than a core source reconciliation.
