FHIR-19531: Audit publisher support for contained container references

Issue request:
FHIR-19531 was a Published/Persuasive FHIR-core technical correction in the FHIR-Tools-Core grouping. It reported that a local publish/build using InstanceValidator rejected a contained AdverseEvent reference of `#` back to the containing Immunization, even though contained resources had been allowed to reference their container.

Initial application:
No current source-history commit explicitly mentions FHIR-19531. The FHIR-I 2020-01-27 minutes recorded Lloyd's assessment that the tooling handled this correctly and assigned the issue back to the reporter for retesting; the 2020-03-02 minutes recorded Grahame's statement that the issue and several other tooling-related issues were fixed, after which Lloyd auto-approved it. The underlying specification rule was already present from the FHIR-13187 source change that added the contained-resource-to-container `#` guidance and example.

Additional context:
Later final issues in the same contained-resource rule family confirm the current interpretation and have already been reconciled on the combined branch. FHIR-33008 clarified the references narrative so contained resources may be included when they reference the container. FHIR-31732 updated Reference ref-1 to allow a bare `#` when evaluated inside a contained resource, and FHIR-37793 preserved that branch while adding a display-only guard. FHIR-13187 was also reconciled on the combined branch with a narrow dom-3 expression fix. Although the FHIR-19531 resolution note says a contained resource still needs an id, the later final Reference and contained-resource decisions and the current source preserve the `#` container-reference case without requiring a contained id.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active source/references.html guidance already states that a contained resource may reference the container and shows `reference value="#"`; source/datatypes/reference.xml already includes the FHIR-31732 ref-1 branch allowing `reference='#' and %rootResource!=%resource`; and source/domainresource/structuredefinition-DomainResource.xml already has dom-3 aligned with the same rule after the existing FHIR-13187 reconcile fix.

Recommendation:
Keep this no-change audit commit as-is. No FHIR-core source follow-up is needed for FHIR-19531; if a publisher or validator implementation again rejects contained resources that reference their container with `#`, that should be handled in the relevant tooling implementation rather than by changing the current core specification source.
