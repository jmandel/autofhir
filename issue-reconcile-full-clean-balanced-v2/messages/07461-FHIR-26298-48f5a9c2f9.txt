FHIR-26298: Audit list-for extension outside core

Issue request:
FHIR-26298 is a Published/Persuasive with Modification FHIR-core FHIR-I change request raised against R4 List. It asked for a List field indicating whom a list is for, with at least Practitioner, PractitionerRole, Organization, and CareTeam targets; the final resolution chose a standard extension, plus an associated search parameter, rather than a new core List element.

Initial application:
The issue was partially applied before this reconciliation. Commit 027acecb014e70ac1007bd1a76706c6d60a05b21 added source/list/structuredefinition-extension-list-for.xml, registered it in the List implementation guide, and updated the current-allergies List example to use http://hl7.org/fhir/StructureDefinition/list-for. I found no historical core commit that added the associated List extension search parameter. Commit dd468d4f1799dd79819315b211588ef1cf4586e0 then removed List extension definitions from core during the R5 move of extensions to the hl7.fhir.uv.extensions package, while the core example and OID assignment for list-for remain.

Additional context:
Current source/fhir.ini lists List as an active, approved resource, but source/history.html says all extensions moved to the hl7.fhir.uv.extensions package and are still published as part of the specification from there. The FHIR Extension Pack currently contains StructureDefinition-list-for with List context and the expected reference target profiles, and FHIR-43342 later improved its description. The Extension Pack input and current build search-parameter registry do not contain a list-for SearchParameter; the current core List search page explicitly directs readers to the Extension Pack registry for search parameters on List-related extensions. FHIR-27083 and the 2022 Zulip reopening discussion address the patient-list concern raised after application: Group should be preferred when Group is suitable, but that guidance does not negate the list-for extension for List use cases such as allergy or problem lists.

AutoFHIR reconciliation:
This commit intentionally makes no source change in the core FHIR checkout. Re-adding the extension definition or defining its extension search parameter in core would be in the wrong source repository after the extension-pack move. The only apparent unfinished portion of the original resolution is the associated extension SearchParameter, and that work belongs in HL7/fhir-extensions if the work group still wants it.

Recommendation:
Keep this external-repo audit commit as-is for the core reconciliation. Follow up in the FHIR Extension Pack with a List list-for extension SearchParameter, or explicitly record that no standard search parameter is desired, before considering FHIR-26298 fully complete across repositories.
