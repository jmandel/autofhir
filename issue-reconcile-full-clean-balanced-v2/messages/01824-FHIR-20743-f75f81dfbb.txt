FHIR-20743: Audit official-address extension location

Issue request:
FHIR-20743 is a Published/Persuasive with Modification FHIR-core MnM change request raised against STU3 and applied for R5. It asked to support marking an Address as official. The final resolution was to define a standard extension on Address, cardinality 0..*, whose value is either a boolean asserting whether the address is official or a CodeableConcept bound to country/jurisdiction codes asserting the address is official for that jurisdiction.

Initial application:
The request was applied in core by commit 2add270d47 ("more mnm changes"), which listed fhir-20743 and added an officialAddress row to source/datatypes/address-extensions-spreadsheet.xml for DataType Address with cardinality 0..1, valueBoolean|valueCodeableConcept, and an ISO Country Codes binding. Later core commit ce7674d793 applied FHIR-25938 by changing that row into a complex-extension-style officialAddress with required valueBoolean and optional/repeatable valueCodeableConcept child rows.

Additional context:
The old core address extension spreadsheet is no longer a current build-scoped source for this extension: source/fhir.ini has no active address-extensions profile entry, current core git grep finds no officialAddress/address-official definition, and commit dd468d4f17 removed the officialAddress rows during the "remove extensions from R5 source" migration. Current extension ownership is in HL7/fhir-extensions, where input/definitions/datatypes/StructureDefinition-address-official.xml defines http://hl7.org/fhir/StructureDefinition/address-official with context Address, valueBoolean, and valueCodeableConcept. Related FHIR-extensions issues FHIR-43838/FHIR-43840 and merged PR 99 document adding the missing extension to that repository. The later FHIR-25938 refinement is already represented on the combined branch by an external-repo audit commit, so this commit does not duplicate that decision.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. Re-adding the extension to the FHIR core checkout would duplicate source now owned by the FHIR Extension Pack, and there is no current build-scoped core definition to repair for the original FHIR-20743 request.

Recommendation:
Keep this external-repo audit in core. Do not reintroduce address-official into the core source tree. If follow-up work is done, do it in HL7/fhir-extensions and use the existing FHIR-25938 audit as the guide for the later boolean-plus-jurisdiction semantic refinement.
