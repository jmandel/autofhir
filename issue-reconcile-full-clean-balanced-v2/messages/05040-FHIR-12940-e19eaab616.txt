FHIR-12940: Confirm PractitionerRole role value set

Issue request:
FHIR-12940 was a Published PA change request with resolution Not Persuasive with Modification. It asked whether PractitionerRole should leverage the existing security-role-type value set, possibly as an extensible binding. PA decided that security-role-type was mostly about event and patient security contexts rather than practitioner functional roles, and resolved to update the example Practitioner Role value set with SNOMED CT descendants of 223366009 (Healthcare professional).

Initial application:
Commit 78b39f30cdbfa85f6d37f5ec56c46ff002f7bbd3, whose subject listed tracker 12940, changed source/practitioner/valueset-practitioner-role.xml on 2017-12-10 to add the SNOMED CT copyright and a compose include using concept is-a 223366009. The current file later moved/refactored; commit 2d08ba87dfb77e949b1d8d94c9dc630fbda96ef1 recreated source/practitionerrole/valueset-practitioner-role.xml and preserved the same SNOMED filter.

Additional context:
source/fhir.ini lists practitionerrole as an active resource, and the current PractitionerRole.code binding remains an example binding to http://hl7.org/fhir/ValueSet/practitioner-role. The current security-role-type example value set is still used by AuditEvent, Provenance, and Contract, but not PractitionerRole. Jira, Zulip, and Confluence searches found no later substantive community or work-group evidence that changes the PA resolution for this artifact.
