FHIR-16877: Audit BackboneElement detail link

Issue request:
FHIR-16877 is a Published/Persuasive FHIR-core STU3 correction asking that the BackboneElement "Detailed descriptions" tab and content structure links point to BackboneElement detail definitions rather than Element detail definitions. The report noted that this wrong-page behavior also left modifierExtension without a BackboneElement definition.

Initial application:
The issue was applied by historical commit 22d5233b31f33ae541736868584dea6fc8790a50, whose GF#16877 change switched the old source/backboneelement-definitions.html page from <%dictionary Element%> to <%dictionary BackboneElement%> and changed the header from elheader to belheader. The Jira comment records "svn revision 14308", matching that commit's git-svn revision.

Additional context:
The old standalone source/backboneelement-definitions.html input no longer exists in the current source tree after later type-framework refactors. BackboneElement remains in current build scope: source/fhir.ini lists it as an active abstract infrastructure type, maps the backboneelement type page into the shared type framework, and marks BackboneElement normative. Current source/types.html links BackboneElement detailed descriptions to types-definitions.html#BackboneElement, and source/types-definitions.html renders <%dictionary BackboneElement%>. The BackboneElement dictionary source includes BackboneElement.modifierExtension.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current built-source path now routes BackboneElement details through the shared types definitions page and uses the BackboneElement dictionary, so the wrong Element detail link reported by FHIR-16877 is no longer present.

Recommendation:
Keep this audit commit as-is. No follow-up is needed unless a future generated build reintroduces links from BackboneElement structure details to Element definitions or omits the BackboneElement.modifierExtension anchor.
