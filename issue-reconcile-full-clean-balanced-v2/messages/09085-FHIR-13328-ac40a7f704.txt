FHIR-13328: Audit regex extension consolidation

Issue request:
FHIR-13328 was a Published/Persuasive STU3 FHIR-I change request asking to combine the two regular-expression extensions, http://hl7.org/fhir/StructureDefinition/structuredefinition-regex and http://hl7.org/fhir/StructureDefinition/regex. The accepted resolution was to deprecate structuredefinition-regex because its name and ElementDefinition.type placement were inappropriate, while retaining regex with the same name.

Initial application:
The issue was applied by git-svn commit 6977725bc70491aa5c85db4c7ed54d32f04d42db, corresponding to SVN revision 12722 from the Jira comment. That commit changed the R4 tooling extension constant from StructureDefinition/structuredefinition-regex to StructureDefinition/regex and removed the regex row from source/structuredefinition/structuredefinition-extensions-spreadsheet.xml, leaving the historical release snapshots as historical artifacts.

Additional context:
The current core build no longer defines either regex extension in active source and source/fhir.ini does not list the old structuredefinition extension spreadsheet as an active profile input. The FHIR Extension Pack now retains only StructureDefinition/regex as a retired/deprecated compatibility artifact, with a standards-status reason pointing implementers to ElementDefinition.constraint for regex validation with a human-readable message. Later Published issue FHIR-37359 went further and removed active core use of the regex extension; its reconciliation commit 5790b437946b033512a535f1aff5160c69d53c7c is already on the combined branch.

AutoFHIR reconciliation:
Made no source changes. The duplicate structuredefinition-regex extension is absent from current core, the retained regex artifact is outside the core checkout and already retired/deprecated, and the later FHIR-37359 decision means reintroducing active core regex extension content would be incorrect.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed for FHIR-13328; any future compatibility wording for StructureDefinition/regex belongs with the FHIR Extension Pack or with the later FHIR-37359 guidance, not with a new core source edit.
