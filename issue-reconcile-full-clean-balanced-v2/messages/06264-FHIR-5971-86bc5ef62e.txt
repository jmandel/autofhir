FHIR-5971: Audit Encounter class and diet binding

Issue request:
FHIR-5971 was a Published PA change request from DSTU1 asking that Encounter.class not be mandatory and that the Encounter diet value set be an example set rather than a mandatory FHIR-defined set. The final resolution was Persuasive with Modification: change class cardinality to 0..1 and change the diet value set type to example rather than required.

Initial application:
The issue was initially applied in git commit 34bd650fb0b0f4c6d94f1dbdcfd3d7be1bc98325, which changed the historical Encounter spreadsheet so Encounter.class moved from 1..1 to 0..1 and the PatientDiet binding row was marked as an example value set.

Additional context:
Encounter is an active current-build resource in source/fhir.ini. The current authoritative source is source/encounter/structuredefinition-Encounter.xml, not the checked-in SVG diagram. Later Published issue FHIR-32341 deliberately revised Encounter.class further to 0..* CodeableConcept with Preferred binding, and later Resolved - No Change issue FHIR-39014 rejected a request to make Encounter.class required again because legacy and jurisdictional data may lack class. FHIR-14157 reorganized Encounter and moved dietPreference to a top-level Encounter element, but the current dietPreference binding remains Example.

AutoFHIR reconciliation:
No source change was made. Current Encounter.class has min 0 and max *, satisfying the non-mandatory requirement after later PA decisions, and Encounter.dietPreference is bound to http://hl7.org/fhir/ValueSet/encounter-diet with strength example.

Recommendation:
Keep this audit commit as-is. Further changes to Encounter.class cardinality or binding should be handled through the later Encounter.class issue family, not by reverting FHIR-5971; no follow-up is needed for the diet binding in core.
