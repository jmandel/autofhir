FHIR-18151: Audit ValueSet display guidance

Issue request:
FHIR-18151 was a Published STU3 FHIR-core ValueSet change request from Vocabulary, resolved Not Persuasive with Modification. It asked to clarify ValueSet.compose.include.concept.display notes because a value-set-specific display can change perceived concept meaning if it is treated as the code system's display; the accepted disposition was to wordsmith the surrounding text rather than require the expansion display itself to be the code-system preferred display.

Initial application:
The Jira application comment cites git 66ae1e40f1bc02283363c872db14035fc795f8f7. That commit updated source/datatypes.html so Coding.display must be one of the display strings defined by the code system, and updated the ValueSet notes so value-set-provided displays are UI/expansion labels that must not be copied into Coding.display. The same source meaning has survived later refactors into the current active ValueSet StructureDefinition XML and narrative.

Additional context:
ValueSet is an active current-build resource in source/fhir.ini. Sept 2018 Vocabulary/FHIR-I minutes show the work group discussed FHIR-18151, then moved Rob McClure to wordsmith display/designation guidance for value set expansions and recorded the same 22-0-3 vote as Jira. Related AutoFHIR audits for FHIR-18572 and FHIR-18575 are already on the combined branch for adjacent ValueSet display/designation placement and wording. Later Published issue FHIR-37603 clarified the Coding.display rule further by naming CodeSystem.concept.display and CodeSystem.concept.designation.value as code-system display sources and excluding value-set-defined displays from Coding.display.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current ValueSet narrative explains that compose.include.concept.display can provide an alternative UI display, shows the expansion display using that value-set-specific label, and states that the Coding produced after selection must use the underlying code system display while the value-set label belongs in CodeableConcept.text. The datatype page independently states that Coding.display SHALL come from the code system and that value-set-defined displays/designations are not allowed in Coding.display. The element comment points readers back to the ValueSet narrative for correct use.

Recommendation:
Keep this audit commit as-is. No further core source work is needed for FHIR-18151 unless a future work-group decision changes the expansion-display policy; do not duplicate the already-landed FHIR-18572/FHIR-18575 audits or reopen the later FHIR-37603 Coding.display clarification here.
