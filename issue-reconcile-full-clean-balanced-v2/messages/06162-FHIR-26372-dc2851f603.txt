FHIR-26372: Audit Device.property.type value set

Issue request:
FHIR-26372 was a Published/Persuasive with Modification OO change request for R5. It said Device.property.type had no value set for its codes and that the type description should refer to Device rather than DeviceDefinition. The accepted resolution was to include the attached code systems for both DeviceDefinition.property.type and Device.property.type as example bindings.

Initial application:
No commit message explicitly naming FHIR-26372 was found. The Device side was effectively applied through related commit 0d858aae58, which applied FHIR-32567 by adding an example binding from Device.property.type to http://hl7.org/fhir/ValueSet/device-property-type. Later 0d21525adf and related fixes corrected the ValueSet URL, and FHIR-49750 commits replaced the old device-type content with a dedicated device-property CodeSystem/ValueSet.

Additional context:
FHIR-26373 is the DeviceDefinition companion with the same resolution. FHIR-32286 is the later Device follow-up and explicitly says FHIR-32567 resolves it. FHIR-49750 is a later Applied R6 correction to the shared ValueSet content and is already represented on the combined branch by audit commit 64d1bd56251dc80814c73c7b9e868c8fd530713a. Device and DeviceDefinition are active current-build resources in source/fhir.ini.

AutoFHIR reconciliation:
No source change was made. Current Device.property.type has an example binding to ValueSet/device-property-type, DeviceDefinition.property.type has the same binding, and the shared ValueSet now composes a dedicated DevicePropertyType CodeSystem with example property codes rather than device-type codes.

Recommendation:
Keep this audit commit as-is. The original missing-binding concern is resolved in current source; any future experimental flag or terminology-packaging work should follow the later issues already noted in the existing FHIR-49750 audit, not reopen this R5 tracker.
