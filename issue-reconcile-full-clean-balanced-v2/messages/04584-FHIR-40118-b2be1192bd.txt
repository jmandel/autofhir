FHIR-40118: Audit Resource operation binding correction

Issue request:
FHIR-40118 was a Published/Persuasive R5 technical correction reporting that 5.0.0-snapshot3 Profiles-resources.xml contained Resource-level OperationDefinitions whose OperationDefinition.resource value was "Resource", while the then-used ResourceType binding did not include the abstract Resource code.

Initial application:
The issue was applied by git commit a3f1bf01af25d350a34b9089ddbf94138f217429, which changed OperationDefinition.resource from ValueSet/resource-types to ValueSet/all-resource-types and clarified the resource type value set descriptions. That application made the existing Resource-level operation instances valid instead of changing each operation instance.

Additional context:
The active current source still includes Resource as an abstract resource in source/fhir.ini and the active Resource operations list now references Resource-validate, Resource-convert, and Resource-graphql. The current OperationDefinition.resource element explicitly says abstract resources such as Resource and DomainResource can be used and binds to version-independent-all-resource-types, with all-resource-types as the R5-specific additional binding. Later FHIR-40492 changed the element to the inter-version all-resource-types binding family while preserving the R5 all-resource-types additional binding. FHIR-51651 is a later R6 Resolved - change required proposal to change several elements to URI for logical models, but it is not Applied/Published and does not reopen this R5 snapshot correction.

AutoFHIR reconciliation:
No source change was made. The current source already represents the intended correction: Resource-valued OperationDefinition.resource entries are allowed by the binding and explanatory comment, so removing or rewriting the Resource operation entries would be incorrect.

Recommendation:
Keep this no-change audit commit. If FHIR-51651 is later applied, handle that broader URI/logical-model change as its own R6 issue rather than as a follow-up to this R5 snapshot correction.
