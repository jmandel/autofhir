FHIR-29678: Audit PlanDefinition apply transient result

Issue request:
FHIR-29678 was Published/Persuasive for R5 and asked to clarify that PlanDefinition/$apply returns a proposed result that is transient, not persisted, with the note added both to the operation comment and to the PlanDefinition realization/apply documentation.

Initial application:
The issue was applied by commit 9bb40cfbb993 (merged by 38e52ec5a0ba via PR #1819), which added the requested transient/proposed-result note to source/plandefinition/operationdefinition-PlanDefinition-apply.xml and source/plandefinition/plandefinition-notes.xml. The current operation definition and PlanDefinition narrative are in build scope because PlanDefinition is an active resource in source/fhir.ini and PlanDefinition/$apply is listed in source/plandefinition/list-PlanDefinition-operations.xml.

Additional context:
Later PlanDefinition/$apply decisions changed the result shape from the older CarePlan/contained-resource wording to Bundle-based output. FHIR-33169 changed the operation to return Bundle 0..* results, and FHIR-46313 relaxed the Bundle content description to allow any applicable request-resource combination. An already-published FHIR-33169 reconciliation commit updated the remaining narrative wording so the transient note now refers to entries in result Bundle(s), preserving FHIR-29678's no-persistence/proposed-activities rule without reverting later semantics.

AutoFHIR reconciliation:
Made no source changes. The latest combined branch already states in both the OperationDefinition comment/footer and PlanDefinition narrative that the result is transient, created resources are not persisted on the server, resources are returned as entries in the result Bundle(s), and the caller decides whether and how to carry out or persist the proposed activities.

Recommendation:
Keep this empty audit commit as-is. No follow-up source change is needed for FHIR-29678 unless the work group separately wants editorial cleanup of unrelated wording in the PlanDefinition/$apply prose.
