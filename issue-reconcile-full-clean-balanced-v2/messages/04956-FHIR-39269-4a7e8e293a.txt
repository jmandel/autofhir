FHIR-39269: Audit Specimen retention in Group

Issue request:
FHIR-39269 was a Published R5 ballot issue asking to remove Specimen from the Group member types after the FHIR-24848 participant-scope tightening, or otherwise justify retaining Specimen. The final resolution was Not Persuasive with Modification: update Group scope and usage to state that Specimen is not typically a participant but is still allowed as a Group member to avoid a breaking change to normative Observation.

Initial application:
The relevant Group participant-scope work was applied in 272e3fb71e for FHIR-24848, which kept Specimen in the Group type/member set. FHIR-39269 itself was applied in 6705cadb21 by adding an explicit Scope and Usage note to source/group/group-introduction.xml explaining why Specimen remains in Group.

Additional context:
FHIR-35972 added Specimen to Group.member.entity for the same multiple-specimen Observation use case, and FHIR-34002 added Group as an Observation.specimen target with a constraint that such Groups contain specimens. OO minutes on 2023-01-23 record the specimen work group rationale: multiple specimens, pooled samples, OBX-33 mapping, and the inability to change normative Observation.specimen cardinality. FHIR-I minutes on 2023-02-20 record the 13-0-0 Not Persuasive with Modification vote for FHIR-39269. Current source/fhir.ini keeps Group in the active resource list, and the current Group source retains both the Specimen type code and Specimen member target.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build-scoped Group source already reflects the approved resolution: Specimen is retained in the formal Group type/member definitions and the Scope and Usage narrative includes the FHIR-39269 explanation.

Recommendation:
Keep this no-change audit as-is. Revisit only if the work group later wants to reconsider the Observation multiple-specimen modeling or the oyster example; FHIR-39269 itself has already been applied correctly.
