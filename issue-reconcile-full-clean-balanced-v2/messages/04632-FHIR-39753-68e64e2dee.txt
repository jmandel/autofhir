FHIR-39753: Audit recursive profiling wording

Issue request:
FHIR-39753 was a Published/Persuasive FHIR-core change request for the profiling page. It asked the specification to clarify that constraints on recursive backbone elements, such as Questionnaire.item, normally apply to recursive occurrences too, and that root-only behavior can be expressed with invariants.

Initial application:
The issue was applied by git commit 98c42a7603d86d713ccbbb96ccd8e0ef2d78feec, which added the Recursive Elements section to source/profiling.html. The current source still contains that section, and source/hierarchy.xml lists profiling.html under the Conformance page tree, so the checked text is in current build scope.

Additional context:
FHIR-39754 is a duplicate of this same request and is not an independent reconciliation target. Later community discussion exposed real problems with treating recursive/profiled content references as recursive by default, especially for Composition, Parameters, and similar structures. FHIR-I subsequently resolved FHIR-57266 as a core R6 change required to revise this section, paired with FHIR-57265 in the FHIR Extension Pack to define contentReferenceProfile. Those later issues are Resolved - change required, not Applied or Published in this run's seed scope, and the extension is not present in the checked Extension Pack source.

AutoFHIR reconciliation:

Rewriting the section under FHIR-39753 would either implement FHIR-57266 without its own audit trail or link to an extension that is not yet present.

Recommendation:
