FHIR-14225: Audit RelatedPerson relationship cardinality

Issue request:
FHIR-14225 is a Published/Persuasive Patient Administration change request raised for STU3. It requested changing RelatedPerson.relationship cardinality from 0..1 to 0..* so a related person could carry use cases such as mother and guardian.

Initial application:
The request was applied by git commit 2e012e76a18a08930e5396bbee8addc60c952edb ("Tracker #14225") on 2017-12-10, which changed the RelatedPerson spreadsheet card from 0..1 to 0..*. The source was later regenerated/refactored into the current StructureDefinition XML, but the applied multiplicity was preserved.

Additional context:
source/fhir.ini actively includes relatedperson=RelatedPerson under the current resources and assigns it to PA, so source/relatedperson/structuredefinition-RelatedPerson.xml is in build scope. Current source has RelatedPerson.relationship min 0 and max *, and later PA work for FHIR-15841 split personal relationships from functional roles by keeping RelatedPerson.relationship 0..* and adding RelatedPerson.role 0..*. That later change narrows the meaning of the relationship element to personal relationships but does not reverse the FHIR-14225 cardinality decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current source already contains the requested 0..* cardinality for RelatedPerson.relationship, and the later role split provides the current place for functional concepts such as guardian without requiring a cardinality correction.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-14225 unless the work group wants to revisit the later personal-vs-functional relationship model separately.
