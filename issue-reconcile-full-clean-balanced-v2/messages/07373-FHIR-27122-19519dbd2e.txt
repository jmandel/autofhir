FHIR-27122: Audit ValueSet expansion system column

Issue request:
FHIR-27122 was Published with a Persuasive with Modification resolution. The reporter asked to re-add the DSTU2-style "System URL" row to ValueSet documentation pages because R4/current pages no longer made the code system URL obvious. The approved resolution intentionally did not restore a single summary System URL because a ValueSet can draw from multiple systems; instead, ValueSet expansions should show the system as a column next to Code whenever the value set is used for Coding or CodeableConcept, rather than only for multi-system expansions.

Initial application:
No FHIR source commit mentioning FHIR-27122 was found in this checkout. The current build path uses the active ValueSet source under source/condition and the ValueSet page template's <%vsexpansion%> placeholder, while expansion table rendering is generated by the build tooling rather than by a per-ValueSet static System URL row in the template.

Additional context:
FHIR-I minutes from 2021-02-22 record the same modification: System URL was removed because value sets do not always come from a single code system, and a System column would be added to the expansion table for Coding/CodeableConcept uses. The current R5 publication and current build page for the seed's related Condition Clinical Status value set both show a System column beside Code even though the source ValueSet includes only one code system; the R4 page did not show that column for the same single-system expansion. No directly relevant Zulip discussion was found that changes this Jira/Confluence/source conclusion.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed in the core FHIR checkout because the current built specification already implements the approved resolution: the single-system Condition Clinical Status expansion exposes http://terminology.hl7.org/CodeSystem/condition-clinical in a System column rather than relying on a summary System URL row.

Recommendation:
Keep this audit commit as-is. Do not re-add a single System URL summary row to ValueSet pages; that would conflict with the approved rationale for multi-system value sets. If a future problem is found, it should be handled in the expansion renderer/build tooling, not by adding per-ValueSet static prose in core source.
