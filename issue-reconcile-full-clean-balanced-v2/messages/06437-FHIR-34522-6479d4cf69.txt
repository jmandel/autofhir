FHIR-34522: Audit extension search parameter visibility

Issue request:
FHIR-34522 was Published/Persuasive for R5. It asked how IG authors should find and cite SearchParameter canonicals for core extensions such as patient-mothersMaidenName, and the approved resolution was to update tooling so any standard SearchParameter defined for an extension is linked prominently from the page that describes the extension.

Initial application:
No git commit explicitly tagged FHIR-34522 was found in the core source history. The issue was discussed in FHIR-I minutes as "Move to tooling"; later non-FHIR-34522 source history moved extension SearchParameters out of core and into the FHIR Extension Pack, and current publisher output now exposes the mothersMaidenName SearchParameter from the patient-mothersMaidenName extension page.

Additional context:
The current core checkout no longer owns the standard extension definitions or their extension-specific SearchParameter files. The FHIR Extension Pack contains StructureDefinition-patient-mothersMaidenName.xml and SearchParameter-profile-patient-extensions-Patient-mothersMaidenName.xml, defines a search-params.html page for extension SearchParameters, and uses extension-resource-template.xml plus extension-resource-factory.json to generate per-resource extension pages with an "Extension Search Parameters" section. Related FHIR-38080 is already represented on the combined branch and confirms that extension SearchParameters should remain in the Extension Pack with a core registry link rather than being duplicated back into core.

AutoFHIR reconciliation:
This audit commit intentionally makes no core source change. The current core registry points to the Extension Pack search registry, and the current Extension Pack/publisher surface prominently links "Search Parameters using this Extension: MothersMaidenName" from the individual patient-mothersMaidenName extension page.

Recommendation:
Keep this no-change audit commit as-is. No FHIR-core source edit is needed for FHIR-34522; future defects in the per-extension usage block or extension SearchParameter registry should be handled in the FHIR Extension Pack or IG Publisher/tooling, not by reintroducing extension SearchParameters into core.
