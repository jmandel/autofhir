FHIR-7801: Audit binding-strength override rules

Issue request:
FHIR-7801 is a Published/Persuasive with Modification FHIR-core profiling issue from DSTU1 asking the specification to list the complete rules for what binding-strength overrides are allowed or disallowed in derived profiles. The issue specifically requested a base-vs-derived table showing that derived profiles can keep or strengthen a terminology binding strength, but cannot loosen a required binding to extensible, preferred, or example; it also noted that profiles may reduce the allowed codes in a required value set.

Initial application:
The Jira application comment says "svn revision 6466." Git history contains that SVN import as commit 07b69f0ae9de3f1948987978bca35b07dfdde37f, "#7801 - binding strength table," which added the "Changing Binding Strength in Profiles" section and the required/extensible/preferred/example base-vs-derived table to source/profiling.html. Later editorial changes moved the anchor/name and adjusted spelling/wording, but the matrix and rule remain in the current profiling source.

Additional context:
The current source/profiling.html page is active top-level core narrative and is linked from the conformance module. Related combined-branch audit commits already cover adjacent issues: FHIR-7802 for the historical tooling warning, and FHIR-6180/FHIR-7472 for the terminology-label cleanup in the neighboring profiling table. Later terminology guidance and community evidence continue to support the same rule that a derived profile must use the same or a narrower binding strength; FHIR-51975 is a later Resolved - change required clarification about CodeableConcept wording on the terminology page, but it is outside this default Applied/Published source-edit scope and does not reverse the FHIR-7801 profiling matrix.
