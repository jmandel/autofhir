FHIR-11820: Audit CodeSystem infer rework

Issue request:
FHIR-11820 was Published/Persuasive for DSTU2 and asked to rework the CodeSystem $infers/$infer material from a connectathon breakout: expose code decomposition through $lookup, replace the old infer operation with an inverse composition-style operation, and start documenting canonical external code-system definitions for systems such as SNOMED CT, LOINC, and RxNorm.

Initial application:
The issue was explicitly applied in svn revision 10029, now git commit 679dc9462a, which replaced the $infer examples with $compose examples, updated the CodeSystem operation spreadsheet so $lookup was titled and described as concept lookup and decomposition, and added early SNOMED CT and LOINC CodeSystem definition material. No separate current RxNorm CodeSystem source file was found in core.

Additional context:
Later vocabulary decisions changed the initially-applied operation. FHIR-15956 lowered the maturity and renamed $compose to $find-matches, FHIR-17563 cleaned up remaining $compose references on the renamed page, and commit 40306e5cd9 removed $find-matches from active core CodeSystem operations for the R6 normative ballot. A 2026 Terminology Zulip thread confirms $find-matches and $closure were removed from core because they were not mature enough for R6 normative status and were expected to move to a Terminology Module Incubator IG. Current core also treats SNOMED CT, RxNorm, and LOINC as external code systems whose authoritative usage information is reached via THO, rather than reintroducing the old core SNOMED CT/RxNorm canonical resource work.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current active source already has no $infer or $compose operation, keeps the decomposition semantics in CodeSystem $lookup, and lists only the active CodeSystem operations $lookup, $validate-code, and $subsumes. The remaining $find-matches example text files are not referenced by the active operation list or any current operation definition, so editing them would not be a current-spec semantic fix for FHIR-11820.

Recommendation:
Keep this no-change audit commit. Re-adding $compose or $find-matches to core would reverse later Vocabulary/Terminology Infrastructure decisions; any future revival should be handled by a new work-group decision or in the Terminology Module Incubator IG, not by reopening this DSTU2 reconciliation.
