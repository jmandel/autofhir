FHIR-16452: Audit metadata OPTIONS removal

Issue request:
FHIR-16452 was a Published/Persuasive FHIR-core-http change request raised for STU3. It asked whether R4 should be the future release that removed the deprecated use of HTTP OPTIONS to retrieve capabilities, and its resolution was to remove OPTIONS as described for meta.

Initial application:
No source commit was found that explicitly names FHIR-16452, and the Jira comments say the change was already done under another task. Git history shows the relevant current-source application: commit 6c524e959315a07f484862bbcd627c2ce90a3057 removed the actual OPTIONS [base] capabilities text and its STU3 deprecation paragraph from source/http.html; FHIR-17322 then recorded the explicit R4 removal decision and its cited svn revision 13874 corresponds to commit 996a1f3590fd9b32e1883f47b977b26a3e98234b, which finished cleanup of a residual hData OPTIONS note.

Additional context:
FHIR-9841 is the earlier published decision that deprecated OPTIONS for retrieving the conformance/capability statement. FHIR-17831 is a later published decision that deliberately added a generic note that behavior for HTTP capabilities such as OPTIONS follows the underlying HTTP protocol when FHIR does not specify it, so the surviving OPTIONS mention on the HTTP page is not stale capability-statement retrieval guidance. The R4 branch and the current source both describe the capabilities interaction as GET [base]/metadata only.

AutoFHIR reconciliation:
This audit commit makes no source change. The current source/http.html capabilities section and interaction summary list GET /metadata for capabilities, source/capabilitystatement/codesystem-capability-statement-kind.xml says the instance kind is returned by /metadata, and a targeted source search found no current obsolete instruction to use OPTIONS [base] or OPTIONS to retrieve a CapabilityStatement.

Recommendation:
Keep this no-change audit commit as-is. Do not remove the generic HTTP OPTIONS note from FHIR-17831 or historical release-note mentions; they serve different purposes and do not reintroduce the removed capabilities retrieval mechanism.
