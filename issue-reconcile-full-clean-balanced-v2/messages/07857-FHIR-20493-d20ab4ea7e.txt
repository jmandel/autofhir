FHIR-20493: Audit terminology value set version handling

Issue request:
FHIR-20493 was a Published/Persuasive FHIR-core change request for the validator to stop appending the FHIR release version, such as |4.0.0, to terminology.hl7.org / terminology.fhir.org ValueSet bindings like the then-current Composition.confidentiality binding to v3-ConfidentialityClassification. A later Jira comment noted the intermediate behavior had changed to duplicating the THO version instead.

Initial application:
The Jira comment recorded Git Kindling b400b4b. In local git history, the explicit issue-tagged application is commit 1e00672e608e5357f8d8db1349db0c091031acae, GF#20493: Fix incorrect version appended by validator to terminology.fhir.org value sets. That commit changed the old tools/java ProfileGenerator so required bindings used the referenced ValueSet's own version when present instead of blindly appending the FHIR version. The old Java tools tree is not present in the current FHIR checkout and that historical commit is not an ancestor of the current worker branch.

Additional context:
Composition remains an active build resource in source/fhir.ini, but the current Composition source no longer has Composition.confidentiality and now documents CDA confidentiality through Bundle.meta.security. Current Composition terminology.hl7.org ValueSet bindings are unversioned in source, and source-wide checks found no terminology.hl7.org ValueSet binding with duplicate pipe versions or a FHIR release version suffix. The linked Zulip topic confirms the issue was a validator/tooling correction rather than a request to add versions to core conformance source. Confluence searches found no additional FHIR-20493 decision record.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR source change. The current core source checkout has no incorrect version-appended terminology.hl7.org ValueSet references to correct, and the only historical code-level fix was in validator/generator tooling that is no longer part of this checkout.

Recommendation:
Keep this audit commit as-is for FHIR core. If the value-set version behavior regresses, handle it in the current external validator/IG Publisher tooling rather than by editing core resource definitions.
