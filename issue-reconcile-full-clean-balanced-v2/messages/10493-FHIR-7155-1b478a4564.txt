FHIR-7155: Clarify Observation identifier instance scope

Issue request:
FHIR-7155 was a Published/Persuasive with Modification OO clarification for the DSTU1 Observation.identifier definition. It asked to add "instance" after "observation" and to address the scope of identifier uniqueness through a discussion link rather than leaving the element as a type-level or globally unique identifier ambiguity.

Initial application:
The historical application commit 89739dcf15 (#7152,7155,7157) changed the old Observation spreadsheet definition from "A unique identifier for the simple observation" to "A unique identifier for the simple observation instance." It did not add separate scope/comment text. A later final harmonization issue, FHIR-12679, was applied in 2c8fb553cf and changed Observation.identifier to the event-pattern-style short and definition, leaving the current source as "A unique identifier assigned to this observation." without a comment.

Additional context:
Observation is active in source/fhir.ini and the current authoritative source is source/observation/structuredefinition-Observation.xml. The Event pattern now carries the relevant scope guidance: this is a business identifier, not the resource id, with a resource-identifier discussion link and best-practice language about appearing on a single resource instance while allowing business exceptions. Zulip discussions show both the old "simple observation instance" wording and the current "assigned to this observation" wording prompted implementer questions; the authoritative answer was that Observation.identifier identifies the observation instance, not the observation code/type. No Confluence evidence or related community record was found that conflicts with the Jira/source conclusion.

AutoFHIR reconciliation:
This commit restores the instance-level clarification in the active Observation.identifier definition, adds the Event.identifier business-identifier comment that supplies the requested discussion link and uniqueness-scope guidance, and updates observation-event-mapping-exceptions.xml so the pattern metadata matches the changed resource source.

Recommendation:
Keep this source fix as a narrow non-substantive clarification for the active Observation resource. Future OO review can separately decide whether Observation.identifier should fully adopt the Event.identifier definition and requirements, but that broader pattern-alignment question is outside FHIR-7155.
