FHIR-24564: Use UTC offset wording for datatypes

Issue request:
FHIR-24564 was Published/Persuasive for FHIR-core datatypes and asked to replace primitive datatype references to "time zone" with "UTC offset" because the +zz:zz portion of instant/date/dateTime/time lexical forms is an offset from UTC, not a named time zone.

Initial application:
The R5 MnM batch commit 5cbc14c7d0f361941099bf72066b75c3f74f6d4f explicitly listed FHIR-24564 and changed source/datatypes/primitives.xml so instant/date/dateTime spreadsheet definitions use UTC-offset language. That commit did not update the top-level datatype narrative rows, and later edits left source/datatypes.html and source/datatypes-examples.html with "timezone offset" or "including timezone" wording.

Additional context:
The linked Zulip thread records Nick Radov raising that dateTime carries an offset rather than a time zone and Grahame Grieve directing him to file the cleanup task. Current source/datatypes/primitives.xml already uses UTC offset, and the remaining true time-zone-code guidance in source/datatypes.html is intentionally preserved because it describes the timezone extension for named time zones.

AutoFHIR reconciliation:
Updated the active datatype source page for date, dateTime, instant, and time to say UTC offset where the primitive lexical value is constrained, and updated the XML and JSON instant examples to describe +01:00 as a UTC offset rather than a timezone. No conformance semantics changed; this completes the published clarification across the current datatype page and examples.

Recommendation:
Keep this source fix as-is. It aligns the narrative datatype table and examples with the already-correct primitive spreadsheet and the published FHIR-24564 clarification while preserving separate wording about actual time zone codes.
