FHIR-16773: Audit ConceptMap unmapped source-code guidance

Issue request:
FHIR-16773 was a Published / Persuasive with Modification Vocabulary issue for ConceptMap, raised against STU3. It said the ConceptMap unmapped-mode wording around "provided" was unclear because it referred to a $translate operation and did not explain what was provided or where; the approved resolution was to say to use the source code being translated and to add discussion/example material about unmapped handling.

Initial application:
The Jira comment records SVN revision 14770, represented in this git history by f82e3c73beeeeed5c68cbcae84004e5952ae3f01. That commit added a ConceptMap introduction paragraph linking to the ConceptMap $translate operation and changed the Handling Unmapped Codes table entry for the then-current "provided" mode to link $translate. The unmapped discussion section itself had just been added by d75acd989aa64eb9de7ae6a439abe0b3377ecfdd for related issue FHIR-14687.

Additional context:
ConceptMap is active in source/fhir.ini, so the source/conceptmap resource, notes, terminology, and operation definition are current build inputs. Later Published ConceptMap decisions refined the same area: FHIR-22100 clarified the unmapped-mode descriptions, and FHIR-32546 replaced the confusing "provided" code with "use-source-code". Both are already represented on the combined branch. The current source now defines ConceptMap/$translate as a ConceptMap operation, includes request/response examples for $translate, defines unmapped mode "use-source-code" as using the source code supplied in sourceCode/sourceCoding/sourceCodeableConcept, and the ConceptMap notes table states the same rule with a link to $translate. A bounded Confluence search found no direct FHIR-16773 minutes, and Zulip evidence shows the old "provided" ambiguity rather than a conflicting current requirement.

AutoFHIR reconciliation:
This commit intentionally makes no source changes. The latest combined source already carries the materially correct FHIR-16773 guidance after the original application and later FHIR-22100/FHIR-32546 refinements, and adding another local example or restating the same rule would be redundant rather than a necessary current-spec correction.

Recommendation:
Keep this no-change audit commit as-is. No further core FHIR source work is needed for FHIR-16773 unless Vocabulary later decides that ConceptMap should include a dedicated unmapped/use-source-code example beyond the existing notes, CodeSystem definition, and $translate examples.
