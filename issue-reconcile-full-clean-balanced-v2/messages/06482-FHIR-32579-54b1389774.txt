FHIR-32579: Align DocumentReference event ModelInfo

Issue request:
FHIR-32579 was a Published/Persuasive OO change request for R5. It asked for DocumentReference.event to be able to point to a Procedure, Observation, or other described resource, like Composition. The Jira comments clarified that this should not add RelatedArtifact or mirror the Composition event backbone; the approved change was to make DocumentReference.event 0..* CodeableReference, keep the existing event value set, and allow Reference(Any).

Initial application:
No git commit message in the local history directly mentions FHIR-32579, but git 56832a9e59e07d5449776a61dbb3d0ec3cd0f3d2 changed source/documentreference/structuredefinition-DocumentReference.xml from CodeableConcept to CodeableReference and split the search parameter into event-code and event-reference. OO minutes on 2022-03-17 record a FHIR pull request including FHIR-32579 with the summary item "Make event CodeableReference." Current DocumentReference StructureDefinition, search parameters, and examples already use CodeableReference concept/reference. The active FHIR-ModelInfo Library, however, still lacked DocumentReference.event and exposed only the old nested DocumentReference.Context.event as a list of CodeableConcept.

Additional context:
FHIR-32538 is the same R5 change family for Composition, changing Composition.event.detail to CodeableReference and updating the parallel Composition event search parameters. Later DocumentReference work, including FHIR-37549, refined mappings for the already-current DocumentReference.event but did not change the CodeableReference decision. source/fhir.ini keeps both DocumentReference and Library in the active build, and source/library/list-Library-examples.xml includes Library/FHIR-ModelInfo, so the ModelInfo Library is a current build surface. Exact Zulip searches for FHIR-32579 found no directly relevant discussion that changes the Jira/source conclusion; Confluence minutes support both the January 2022 vote and the March 2022 application review.

AutoFHIR reconciliation:
This commit updates the active FHIR-ModelInfo source to match the approved DocumentReference.event shape. It adds DocumentReference.event as a list of FHIR.CodeableReference in source/library/library-fhir-model-definition-content.xml, removes the stale nested DocumentReference.Context.event CodeableConcept entry, and regenerates the embedded base64 attachment in source/library/library-fhir-model-definition.xml. It intentionally leaves other older DocumentReference ModelInfo fields alone because this issue is specifically about event.

Recommendation:
Keep this source fix as-is. It completes the remaining current-build surface for FHIR-32579 without reopening the broader DocumentReference ModelInfo cleanup; any future work to align unrelated stale DocumentReference ModelInfo fields should be handled by separate tracker decisions.
