FHIR-26543: Remove stale ProductShelfLife identifier ModelInfo

Issue request:
FHIR-26543 was Published/Persuasive for BR&R and asked to improve the ProductShelfLife datatype for R5: remove the legacy identifier, make type optional, make period[x] Quantity|string and later optional, and correct the ownership/maturity metadata because ProductShelfLife belonged to BR&R rather than Pharmacy.

Initial application:
Git commit 06292b1b26ffdcd194174e1ca60da619e39ae790 applied the structural datatype changes in source/datatypes/productshelflife.xml by removing ProductShelfLife.identifier, changing ProductShelfLife.type to 0..1, and changing ProductShelfLife.period to optional period[x] Quantity|string. Later FHIR-31802 commits changed the period choice to Duration|string, and an existing AutoFHIR commit on the combined branch already aligned the ProductShelfLife.period ModelInfo surface for that related issue. Before this reconciliation, the active datatype spreadsheet and generated pages were correct, but source/library/library-fhir-model-definition-content.xml and the embedded Library payload still exposed ProductShelfLife.identifier.

Additional context:
ProductShelfLife is active in source/fhir.ini and its page now shows BR&R ownership. The current Normative standards status came from the later R6-wide normative-status change, so this reconciliation does not revert that later decision to the original issue's 2020 maturity suggestion. Library ModelInfo is also current build-scoped source: publish.ini publishes source/library/library-fhir-model-definition-content.xml and source/library/library-fhir-model-definition.xml embeds the same content for CQL tooling. FHIR-28255 later confirmed the R5/R6 period target as Duration|string while keeping the period name, and FHIR-35961 only explains an R4B compatibility branch revert that does not supersede current HEAD.

AutoFHIR reconciliation:
Removed the stale ProductShelfLife identifier entry from source/library/library-fhir-model-definition-content.xml and refreshed source/library/library-fhir-model-definition.xml so the embedded Library data matches the XML ModelInfo content. No change was needed to source/datatypes/productshelflife.xml, source/productshelflife.html, PackagedProductDefinition, or DeviceDefinition because their current source already reflects the applied issue and later related decisions.

Recommendation:
Keep this commit as-is. It completes the applied FHIR-26543 identifier removal across the current build's active FHIR ModelInfo surface while preserving later ProductShelfLife period and standards-status decisions.
