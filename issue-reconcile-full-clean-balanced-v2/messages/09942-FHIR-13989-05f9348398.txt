FHIR-13989: Audit conditional update Resource.id handling

Issue request:
FHIR-13989 was a Published FHIR-I STU3 change request, resolved Persuasive, asking whether a submitted resource may carry Resource.id during conditional update. The approved clarification allowed an id in the instance and said the server should ignore it by referring to the create/id-handling guidance.

Initial application:
The issue was explicitly applied by 91be5c2880262ecd2d4ad09ca259612955bcf24d, "GF#13989 - note about resource id on conditional update", matching Jira comment svn revision 14199. That commit added a paragraph to source/http.html saying the resource MAY contain an id, does not need to, and if an id is provided the server SHALL ignore it, though the applied link pointed to the update interaction.

Additional context:
The current build-scope HTTP page is source/http.html, included by publish.ini as http.html. Later finalized same-section decisions changed how the original ignore-id wording should be interpreted: FHIR-17906 replaced the simple no-match/one-match conditional update bullets with separate no Resource.id, Resource.id, matching-id, and mismatching-id outcomes; FHIR-20390 clarified those bullets are about Resource.id and also called for removing the ignore sentence; FHIR-26688 specifically resolved that the conditional update statement saying a supplied id is ignored was wrong and should be removed; and FHIR-36859 further split the no-match Resource.id case based on whether that id already exists. FHIR-13989 is therefore preserved only as the allowance that Resource.id may be present or absent, not as a current requirement to ignore a supplied id in all conditional update outcomes.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/http.html already says conditional update can be submitted with or without Resource.id, and its outcome list now gives the later approved handling for each Resource.id case instead of the superseded blanket ignore rule. Reintroducing the original ignore-id text would conflict with later published decisions.

Recommendation:
Keep this no-change audit commit as-is. No core source follow-up is needed for FHIR-13989; future edits to conditional update Resource.id behavior should be made only under a newer finalized tracker that changes the later FHIR-17906/FHIR-20390/FHIR-26688/FHIR-36859 family of decisions.
