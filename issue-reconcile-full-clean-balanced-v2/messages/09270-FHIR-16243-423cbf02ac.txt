FHIR-16243: Clarify itemWeight answer option scoring

Issue request:
FHIR-16243 was a Published/Persuasive with Modification FHIR-core STU3 change request for Questionnaire scoring. It asked for the scoring/ordinalValue extension to cover all answer value types, not just coded answers, and the approved resolution was to change the ordinalValue context from valueCoding to value so any valueTypes could be used.

Initial application:
The issue was applied by svn revision 14123, represented in git as 449e48ec1c9021a078d61afe87b901dabd5f2ec4 with subject "GF#16243 - extend use of ordinalValue extension". That commit changed source/profiles/iso-21090-spreadsheet.xml so the ordinal-value extension context moved from specific coded locations, including Questionnaire.item.answerOption.valueCoding, to Any, and changed the short wording from a value associated with a code to a value associated with a concept. The current core checkout no longer contains that old extension spreadsheet row, but the Questionnaire notes retained older coded-answer wording.

Additional context:
Later published decisions changed the extension family without reversing the seed. FHIR-17350 and FHIR-17824 consolidated the older questionnaire/code-system/value-set/ISO ordinal extensions into a general ordinalValue extension, FHIR-24672 renamed ordinalValue to itemWeight, and the active itemWeight StructureDefinition moved to the FHIR Extension Pack. Current Extension Pack source allows itemWeight on Questionnaire.item.answerOption and FHIR-49854 later clarified that, for questionnaires, itemWeight goes on answerOption rather than answerOption.valueCoding. Questionnaire is an active core resource in source/fhir.ini, so its narrative notes are current build-scoped source.

AutoFHIR reconciliation:
This commit updates the active Questionnaire math note in source/questionnaire/questionnaire-notes.xml so it no longer describes itemWeight as only for coded answers or as weighting only a code. The note now says itemWeight can be used on Questionnaire.item.answerOption for inline answer choices, including when the option value is not a code. No core extension-definition source was edited because the authoritative itemWeight and retired ordinalValue definitions are now maintained in the FHIR Extension Pack and already carry the broader answerOption context.

Recommendation:
Keep this commit as-is. It fixes the remaining build-scoped core narrative ambiguity from FHIR-16243 while preserving the later itemWeight naming and Extension Pack ownership. Future changes to itemWeight contexts should be made in the FHIR Extension Pack and coordinated with FHIR-I/SDC decisions such as FHIR-49854.
