FHIR-17810: Audit AllergyIntolerance abatement extension

Issue request:
FHIR-17810 was a Published FHIR-core/Patient Care change request, resolved Persuasive with Modification for R5, asking to add an AllergyIntolerance abatement[x] extension analogous to Condition.abatement. The approved extension was 0..1 with value[x] choices dateTime, Age, Period, Range, and string, definition text explaining the date or estimated date the allergy or intolerance resolved, and comments tying missing abatement back to clinicalStatus.

Initial application:
The issue was applied in core by 89170aaa03115a9f408c1cf12fac8d86c2694e48, whose subject says GF#17810 added the abatement extension for AllergyIntolerance. The patch added the abatement extension row to source/allergyintolerance/allergyintolerance-extensions-spreadsheet.xml with the requested context, cardinality, type choices, definition, and comment. Later source history shows dd468d4f1799dd79819315b211588ef1cf4586e0 removed AllergyIntolerance extension definitions from the R5 core source as part of moving extension content out of this checkout.

Additional context:
The active AllergyIntolerance resource remains in the core build, but the abatement extension artifact now lives in the FHIR Extension Pack at input/definitions/AllergyIntolerance/StructureDefinition-allergyintolerance-abatement.xml. That definition has URL http://hl7.org/fhir/StructureDefinition/allergyintolerance-abatement, context AllergyIntolerance, max 1, and value[x] choices dateTime, Age, Period, Range, and string. Related later decisions support this split: FHIR-47505 deprecated the older allergyintolerance-resolutionAge extension in favor of allergyintolerance-abatement, FHIR-52938 clarified the abatement comment for Period and Range, and FHIR-47615 declined to elevate abatement into the base AllergyIntolerance resource due to insufficient implementation evidence. A 2024 Zulip implementers thread likewise directs users needing an AllergyIntolerance end date to clinicalStatus=resolved plus the allergyintolerance-abatement extension rather than a core element.

AutoFHIR reconciliation:
This commit intentionally makes no source change in the FHIR-core checkout. The current core source should not re-add an extension definition that has moved to the Extension Pack, and the current external definition already represents the approved FHIR-17810 behavior plus later clarifications.

Recommendation:
Keep this audit commit as-is. Future changes to the abatement extension should be made in HL7/fhir-extensions; adding a native AllergyIntolerance.abatement[x] element to core would require a new Patient Care work-group decision because FHIR-47615 explicitly rejected that elevation for R6.
