FHIR-33026: Audit Endpoint client wording

Issue request:
FHIR-33026 was Published/Persuasive for R5 by Patient Administration. It asked whether Endpoint can describe client-like or messaging-peer connectivity, and resolved to loosen Endpoint wording that sounded server-only: add an s/Mime email address example to the resource definition, change CapabilityStatement comparison wording from server to system, and add DICOM connectivity advertising to Expected Implementations.

Initial application:
The issue was applied in the FHIR source before this reconciliation. Commit 184888d97efd9ce622be8ca882d18f6dda4e855a updated the Endpoint StructureDefinition description/definition, changed the CapabilityStatement narrative from server to system, and added the DICOM Expected Implementations item. Commit fee6332451d2b268caced83039a73fce08507198 fixed the possessive typo introduced in that narrative. The current combined branch also contains these Jira-tagged commits and their merge.

Additional context:
Endpoint is an active core resource in source/fhir.ini, so source/endpoint/structuredefinition-Endpoint.xml and source/endpoint/endpoint-introduction.xml are build-scope inputs. Current source keeps the s/Mime email address example, the system-based CapabilityStatement comparison, and the DICOM expected implementation. Patient Administration January 2022 minutes corroborate the WG intent to loosen server-only perception for email/MIME and other endpoint types. No Zulip search hit was found that would change or conflict with this conclusion.
