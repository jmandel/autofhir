FHIR-21622: Audit eld-11 non-FHIR datatype allowance

Issue request:
FHIR-21622 was a Published/Persuasive with Modification FHIR-core ElementDefinition change request. It reported that eld-11 required bindings to be on an enumerated set of FHIR coded/string/uri/Quantity types, which incorrectly rejected CDA and HL7 v3 coded logical-model datatypes such as CD, CE, CV, CO, and CS. The approved resolution was to modify eld-11 so the invariant does not apply when ElementDefinition.type.code is an absolute URI.

Initial application:
The issue was applied before this reconciliation. Jira comments point to git ffbe557c66f601c8b9b5f687e5f1e5506c5c817e, and that commit changed source/datatypes/elementdefinition.xml so eld-11's human text says it applies "if using FHIR-defined types" and both the FHIRPath and XPath expressions allow type codes containing a colon before checking the enumerated FHIR type list.

Additional context:
source/fhir.ini lists ElementDefinition as an active datatype, maps it to the elementdefinition page, marks it normative, and assigns the eld abbreviation, so source/datatypes/elementdefinition.xml is build-scoped source for eld-11. The current invariant also preserves the later/parallel Duration allowance audited for FHIR-30085. FHIR-24692, the structural follow-up referenced in the FHIR-21622 resolution, is already represented on the combined branch and concerns the broader type-characteristics mechanism rather than a missing eld-11 source edit.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current eld-11 row already exempts absolute/non-FHIR type codes with type.code.contains(':') and contains(f:type/f:code/@value, ':'), which satisfies the FHIR-21622 request for CDA and v3 logical-model datatype URIs.

Recommendation:
Keep this no-change audit commit as-is. No follow-up is needed in current FHIR-core for FHIR-21622 unless a future work group decision replaces eld-11's enumerated rule with the broader type-characteristics mechanism or changes how absolute type-code URIs are recognized.
