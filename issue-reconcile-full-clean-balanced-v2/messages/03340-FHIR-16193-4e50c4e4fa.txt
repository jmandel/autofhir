FHIR-16193: Audit Condition status datatype

Issue request:
FHIR-16193 was a Published/Persuasive Patient Care change request from the STU3 ballot asking to change Condition.clinicalStatus and Condition.verificationStatus from code to CodeableConcept so implementers can include translations, text, and more specific codings such as SNOMED CT alongside the required FHIR value set code.

Initial application:
The issue appears to have been applied in the historical GForge-era commit 8fa342565e4257941f388ece874b02f4f9c9f43f, whose subject is "GF#16193 Condition.clinicalStatus and Condition.verificationStatus data type changed to CodeableConcept". That commit converted the Condition spreadsheet entries to CodeableConcept, added GF#16193 committee notes, updated FHIRPath/XPath invariants for CodeableConcept coding access, and rewrote Condition examples from scalar code-valued statuses to CodeableConcept codings. Later source refactors carried the same GF#16193 markers into the current structuredefinition-Condition.xml.

Additional context:
Condition is an active core resource in source/fhir.ini, so source/condition/structuredefinition-Condition.xml and the source/condition examples are in current build scope. Later related decisions did not reverse the datatype change: FHIR-19633 added explanatory comments because GF#16193 made the statuses CodeableConcept; FHIR-16190 was Not Persuasive on loosening the required verificationStatus binding because CodeableConcept already permits the required FHIR code plus additional codings; and FHIR-54914 later clarified the verificationStatus comment while keeping the CodeableConcept type.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Condition StructureDefinition already declares both Condition.clinicalStatus and Condition.verificationStatus with type CodeableConcept, the clinicalStatus comment explains the GF#16193 rationale, the verificationStatus comment includes the later required-binding clarification, and current Condition examples no longer use the obsolete scalar <clinicalStatus value="..."/> or <verificationStatus value="..."/> form.

Recommendation:
Keep this audit commit as-is. No current-spec edit is needed for FHIR-16193; future work should treat datatype questions for neighboring AllergyIntolerance or later terminology/value-set requests as separate trackers rather than re-opening this Condition datatype decision.
