FHIR-13549: Audit Goal date search expressions

Issue request:
FHIR-13549 was a Published/Persuasive FHIR-core Goal change request raised for STU3. It said the Goal start-date and target-date SearchParameter FHIRPath expressions used the wrong primitive type case, and asked for lowercase date in expressions equivalent to Goal.start.as(date) and Goal.target.due.as(date).

Initial application:
The Jira snapshot records Grahame Grieve's application note as "svn revision 12701". No explicit FHIR-13549, GF#13549, or svn revision 12701 source commit was found in the current git history. The current active Goal search-parameter source already has lowercase date: the new-build source import 33b409a4b6 carried the R4-era expressions as Goal.start as date and Goal.target.due as date, and aac5d575d8 later migrated them from as date syntax to the current ofType(date) form.

Additional context:
Goal is an active current-build resource in source/fhir.ini, so source/goal/bundle-Goal-search-params.xml is the authoritative current source for these resource search parameters. The checked-in tools/history/release3/search-parameters.xml archive still contains the older STU3 uppercase Date expressions, while R4/R4B history and current source use lowercase date. Those tools/history release bundles are archived historical artifacts, not the current Goal source to edit for this reconciliation. Related combined-branch audits for FHIR-12400, FHIR-7885, and FHIR-5328 cover the existence and model context for Goal start and target dates, but not this separate expression-case audit. Zulip and Confluence searches found no conflicting work-group evidence beyond a Zulip tracker-item bot notification.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current spec source already satisfies the Jira decision because Goal-start-date is type date with expression Goal.start.ofType(date), and Goal-target-date is type date with expression Goal.target.due.ofType(date). The lowercase FHIRPath primitive type name is preserved in both expressions.

Recommendation:
Keep this no-change audit commit as-is. Do not edit archived release history bundles as a current-spec fix; revisit only if maintainers separately decide historical release artifacts should be retroactively corrected.
