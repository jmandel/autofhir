FHIR-7874: Audit Patient v2 care provider mapping

Issue request:
FHIR-7874 was a Published/Persuasive Patient Administration correction from the DSTU1 ballot. It reported that Patient.careProvider lacked an HL7 v2 mapping and requested mapping that element to PD1-4, "Primary Care Provider"; the accepted resolution was to add this mapping.

Initial application:
The request was applied in git commit 2ca6343b43, "Tracker #7874 Additional v2 mapping", which added PD1-4 to the Patient.careProvider v2 mapping column in source/patient/patient-spreadsheet.xml. Later source migrations carried the mapping into source/patient/structuredefinition-Patient.xml.

Additional context:
FHIR-7963 later renamed Patient.careProvider to Patient.generalPractitioner while retaining careProvider as an alias, and the current combined branch already contains a separate FHIR-7963 audit commit, so this reconciliation does not duplicate that issue. Current source/fhir.ini lists Patient as an active resource. The current Patient.generalPractitioner element is the build-scoped successor to Patient.careProvider, retains alias careProvider, and includes the v2 mapping PD1-4. Zulip evidence for the FHIR-7963 rename confirms the rename/cardinality context and does not change the v2 mapping conclusion. Jira/Zulip/Confluence searches found no later direct issue or community record requiring a different current mapping.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The authoritative current Patient StructureDefinition already contains the requested HL7 v2 PD1-4 mapping on the renamed-but-aliased Patient.generalPractitioner element.

Recommendation:
Keep this no-change audit as-is. No FHIR core follow-up is needed for FHIR-7874 unless Patient Administration decides in a future tracker to change the HL7 v2 mapping itself.
