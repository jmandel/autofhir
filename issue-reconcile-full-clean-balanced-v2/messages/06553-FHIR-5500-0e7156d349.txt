FHIR-5500: Audit Range comparator wording

Issue request:
FHIR-5500 was a Published/Persuasive with Modification DSTU1 MnM ballot comment asking what the Range datatype note meant by a "range flag" on low or high, because neither Range nor Quantity had such a property. The final resolution said the obsolete Quantity element had become comparator, and the Jira comments recorded the source application.

Initial application:
The issue was directly applied in git commit 1dbbca6b115568107edc4dbfae0f0d483d9a44b5, "#5500 - remove reference to superceded element name", which changed the Range invariant text from "No Range flag on Quantity" to "No Comparator flag on Quantity" and corrected the OCL path to low.comparator. Earlier HTML/source history also shows the local narrative phrase using comparator rather than the obsolete range flag.

Additional context:
Range is an active normative datatype in source/fhir.ini, and the current source defines Range.low and Range.high as SimpleQuantity. SimpleQuantity is a Quantity profile whose rule says the comparator is not used, so the current generated/narrative Range statement that comparators cannot be present is still consistent. Later FHIR-51566 intentionally allowed comparators only for Observation.referenceRange.low/high by changing those elements from SimpleQuantity to Quantity with explicit comparator constraints; it did not change the base Range datatype.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The obsolete "range flag" wording has already been removed from the active Range source, and the current SimpleQuantity-based datatype model still expresses the intended prohibition on comparators for Range.low and Range.high.

Recommendation:
Keep this no-change audit commit. Do not alter the base Range datatype for FHIR-5500; any future comparator work should be handled by a separate work-group decision like the existing Observation.referenceRange-specific FHIR-51566 change.
