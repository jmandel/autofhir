FHIR-20182: Audit CLIA identifier registry entry

Issue request:
FHIR-20182 was a Published/Persuasive FHIR-core change request asking to create or report the URI for CLIA Lab identifiers. The approved resolution said to add urn:oid:2.16.840.1.113883.4.7 to the identifier list until a future terminology registry existed.

Initial application:
The issue was applied by bac96ea2f3, which added a CLIA Lab identifier NamingSystem entry to source/namingsystem/namingsystem-registry.xml with OID 2.16.840.1.113883.4.7 and URI urn:oid:2.16.840.1.113883.4.7. That file is no longer present in the current source after later R5 cleanup of duplicated terminology and identity-system bundles.

Additional context:
FHIR-35932 intentionally migrated the core identifier registry table to HL7 Terminology, and the current source/identifier-registry.html page remains in build scope through publish.ini while directing implementers to the actively curated THO identifier registry. FHIR-37889 and FHIR-40117 later removed the duplicate NamingSystem registry bundle from core because the authoritative content belongs in THO. The current HL7 Terminology CLIA NamingSystem page contains the requested OID and urn:oid URI, and FHIR-36926/TA minutes confirm the CLIA THO page was created and approved.

AutoFHIR reconciliation:
This audit commit makes no source change. Re-adding CLIA to core would contradict the later published migration of identifier-system content to THO; the current core source correctly points to THO, where the CLIA identifier is already present.

Recommendation:
Keep this commit as a no-change audit. No core follow-up is needed unless a future THO governance issue changes the CLIA NamingSystem itself.
