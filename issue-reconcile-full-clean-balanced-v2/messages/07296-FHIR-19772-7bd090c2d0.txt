FHIR-19772: Audit normal range definition

Issue request:
FHIR-19772 was an OO Applied/Persuasive clarification asking FHIR-core Observation to loosen the ReferenceRange meaning code `normal` definition from the strict statement "Within two standard deviations from the mean and accounting for 95.45% of the relevant control population" to wording that describes values expected for a normal member of the relevant control population and treats the two-standard-deviation rule as typical rather than definitional.

Initial application:
The requested wording was pre-applied in commit f103fbd30441a7596bc298842427ef0fdf1be564, which changed `source/observation/codesystem-referencerange-meaning.xml` from the strict definition to the resolved wording, including the Jira resolution's inserted word "normal". The older strict definition had been introduced by GF#16139 in commit 1e59a65e1b6dc1798196f55d782d17e3400b1355. No existing commit with `Issue-Reconcile-Key: FHIR-19772` was found on the combined branch before this audit.

Additional context:
FHIR core no longer maintains `source/observation/codesystem-referencerange-meaning.xml`: commit 5c0494aacfd0b8bd52bc72c587aa89d0a64246f8 removed it during the UTG/THO content move. The current active core source keeps `Observation.referenceRange.type` and `ObservationDefinition.qualifiedValue.context` bound to `ValueSet/referencerange-meaning`, and that ValueSet composes the external `http://terminology.hl7.org/CodeSystem/referencerange-meaning`. Current THO JSON plus the build and published FHIR ValueSet pages show the accepted `normal` definition, so the current core build already exposes the intended text. The adjacent `FHIR-19773` request to add a non-critical code was resolved no-change and was not decided here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative code definition is no longer a core source file, and the current core ValueSet source and rendered expansion already reflect the accepted FHIR-19772 wording through THO.

Recommendation:
Keep this audit commit as-is. If OO wants different wording beyond the applied "normal member" resolution or wants to alter the external code system, handle that as a new Jira/THO terminology proposal rather than editing FHIR core source.
