FHIR-17266: Audit ValueSet display example

Issue request:
FHIR-17266 was a Published STU3 FHIR-core ValueSet change request from Vocabulary, resolved Persuasive. It asked to add an example showing how ValueSet.compose.include.concept.display is used, based on the terminology Zulip discussion about whether a value-set-specific display such as "Step Count" belongs in CodeableConcept.text rather than Coding.display.

Initial application:
The Jira application comment cites GH#7a32b4a312. Commit 7a32b4a31253f8389987096e0a5c1931efffaea7 added an example block to source/valueset/valueset-notes.xml showing a ValueSet with LOINC 55423-8 and value-set display "Step Count", the matching expansion display, and the resulting Observation.code where Coding.display uses the LOINC display while CodeableConcept.text carries "Step Count".

Additional context:
ValueSet is an active current-build resource in source/fhir.ini. The linked Zulip thread records the original implementer confusion and confirms the requested example: ValueSet.compose.include.concept.display is the UI/expansion label, but Coding.display must come from the underlying code system and the value-set label is represented in CodeableConcept.text. Related Published issue FHIR-18151 clarified the same ValueSet display guidance and is already represented on the combined branch. Later Published issue FHIR-37603 further clarified datatypes.html by explicitly excluding value-set-defined displays/designations from Coding.display.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current source still contains the FHIR-17266 example in the active ValueSet narrative, with the Step Count value set, expansion, Observation.code, and designation variants. The surrounding ValueSet notes and datatype guidance still convey the same rule, so adding or rewriting source would be redundant.

Recommendation:
Keep this audit commit as-is. No further core source work is needed for FHIR-17266 unless a future Vocabulary/FHIR-I decision changes the policy for value-set-specific displays in expansions or CodeableConcept.text.
