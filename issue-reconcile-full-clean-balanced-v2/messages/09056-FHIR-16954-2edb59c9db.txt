FHIR-16954: Audit Count constraint wording

Issue request:
FHIR-16954 is a Published/Persuasive STU3 FHIR-I change request asking to fix the Count cnt-3 invariant because the old human text said Count had to be "an expression of length," which is inappropriate for a count.

Initial application:
The Jira comment records svn 14287. Git history maps that application to 495348bc65a433ebf3c01152732f2b401170331b, "GF#16954 - fix Count constraint," which removed the length phrase from source/datatypes/count.xml. The current source/fhir.ini [types] section lists Count as an active datatype, and source/datatypes/count.xml now has cnt-3 without the length wording.

Additional context:
The current build Count profile also reports cnt-3 with the corrected Count wording. A legacy Quantity-restrictions copy in source/datatypes/distance.xml still contains an old Count row with the length phrase, but the active Count datatype source and current built Count profile do not use that copy; it also lacks later Count invariant updates, confirming it is not the authoritative Count constraint source. Jira phrase searches found only FHIR-16954, and Zulip/Confluence searches found no conflicting community or work-group context.

AutoFHIR reconciliation:
Made no source change. The current Count definition and conformance surface already implement the issue. Editing the stale Distance restrictions copy would not correct the current Count specification and would risk treating a legacy non-authoritative sheet as the Count source.

Recommendation:
Keep this audit commit as-is for FHIR-16954. If future build tooling starts consuming the Distance Restrictions sheet for Count, reconcile that sheet separately after confirming its build role; no current FHIR-core source fix is needed for this issue.
