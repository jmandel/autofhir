FHIR-12706: Audit Procedure progress status code cleanup

Issue request:
FHIR-12706 was Published/Persuasive for Patient Care and asked to clean up the Procedure progress status code system by replacing placeholder codes and missing definitions with the six named codes, displays, and definitions for operating room, prepared, anesthesia induced, open incision, closed incision, and recovery room states.

Initial application:
The request was applied in core by git commit 25942dbc1758266ff46e77163000a86d322d7d2c on 2017-01-26, which changed source/procedure/codesystem-procedure-progress-status-codes.xml from placeholder codes a-f to the requested named codes and definitions. A later source cleanup retained the corrected terminology until Procedure extension artifacts were removed from core R5 source.

Additional context:
Procedure is still an active resource in source/fhir.ini, but the procedure-progressStatus extension, Procedure Progress Status CodeSystem, and Procedure Progress Status ValueSet are no longer current FHIR core source artifacts. Core retains only OID mappings for their canonical URLs in source/oids.ini. The current FHIR Extension Pack checkout contains the active Procedure progressStatus extension source and the Procedure Progress Status CodeSystem/ValueSet, and the CodeSystem already has the six codes, displays, and definitions requested by FHIR-12706. Community searches found no conflicting work-group discussion; Zulip hits were tracker/commit notifications and a later FMG extension-move thread, while Confluence hits were event pages showing the same corrected code table.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The current FHIR core checkout no longer owns the affected CodeSystem/ValueSet source, and the external extension-pack source already reflects the published Jira resolution.

Recommendation:
Keep this empty audit commit as-is for FHIR core. If future corrections are needed for procedure-progressStatus or its example terminology, make them in the FHIR Extension Pack rather than reintroducing Procedure extension terminology into core.
