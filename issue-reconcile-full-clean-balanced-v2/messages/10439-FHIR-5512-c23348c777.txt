FHIR-5512: Audit REST URL identity clarification

Issue request:
FHIR-5512 was Published/Persuasive for FHIR-core HTTP and asked the specification to clarify whether http versus https and explicit port numbers are significant when determining resource identity. The adopted ITS wording said http and https are not separate objects, while the URL portion after the protocol, including specified ports, is significant and explicit ports should only be used when meaningful to the server.

Initial application:
The issue was applied in svn revision 5051, represented in git by d0f47223ad0f368f159e7f2ccbd205234b2fc31f, which added the RESTful API Identity paragraph to source/http.html. The original application included the http/https rule, port identity rule, and examples. A later Published/Persuasive issue, FHIR-8683, clarified the same paragraph in cd02a83cb81e816388e258b698d29f8f9b4c49ee so it says http and https SHALL NOT be used to refer to different underlying objects rather than saying they are simply exchangeable.

Additional context:
The current source/http.html page is in the active page hierarchy as the RESTful API page. Its Identity section says URL query strings are ignored, the document portion is case-sensitive, http and https cannot identify different underlying objects, and specified ports must be identical or the objects are different. Related audits for FHIR-8683 and FHIR-19668 already exist on the combined branch, so this reconciliation does not publish duplicate related issue commits. Zulip and Confluence searches found no directly relevant contradictory community record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current RESTful API source already carries the resource-identity clarification requested by FHIR-5512, including the http/https equivalence rule and the port-significance rule, and later wording changes preserve rather than reverse the original decision.

Recommendation:
Keep this no-change audit commit as-is. No follow-up source edit is recommended for FHIR-5512 unless the work group chooses to revisit the underlying http/https identity policy separately.
