FHIR-41400: Align EpisodeOfCare summary with group subject

Issue request:
FHIR-41400 was Applied/Persuasive for R6 by Patient Administration. It asked for EpisodeOfCare to support family-oriented care by renaming the patient element to subject, allowing Reference(Patient | Group), and updating search parameters including a new subject search parameter, consistent with Encounter.

Initial application:
The issue was initially applied in 58df91709e, which renamed EpisodeOfCare.patient to EpisodeOfCare.subject, added Group as a target, and added/retargeted the subject and patient search parameters. The follow-up ad64f69d78 made QA wording updates in search parameters and narrative. Those commits left several current source summaries and the checked-in diagram using patient-only wording or the old EpisodeOfCare.patient anchor.

Additional context:
PA WGM minutes for September 2023 record that Encounter already supported groups and that PA would add the same support for EpisodeOfCare. Current fhir.ini actively includes EpisodeOfCare, and the patient-to-subject aliases in fhir.ini are intentional migration/diff mappings rather than live patient elements. The authoritative current XML and search parameter source already expose EpisodeOfCare.subject as Reference(Patient | Group), so the remaining problem was stale summary and display text that could mislead readers back to patient-only care.

AutoFHIR reconciliation:
This commit updates the active EpisodeOfCare StructureDefinition resource summary/root definition and careManager description to avoid patient-only language, keeps the Event mapping exception text synchronized, updates the checked-in EpisodeOfCare diagram to point at EpisodeOfCare.subject and show Patient|Group, and updates the resource guide's EpisodeOfCare summary to say patient or group. It does not remove the patient search parameter or fhir.ini aliases because they are the deliberate patient-only compatibility surface over EpisodeOfCare.subject.

Recommendation:
Keep this commit as-is. It completes the applied patient-to-subject/group change in the current core source while preserving the compatibility patient search parameter and historical alias mappings.
