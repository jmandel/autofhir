FHIR-8065: Audit Medication form value set

Issue request:
FHIR-8065 was a Published/Persuasive FHIR-core Pharmacy correction for DSTU1. It reported that Medication.product.form pointed to value-set contents for route of administration and asked to fix the link/binding so medication.product.form used SNOMED CT concepts where concept is-a 421967003.

Initial application:
The Jira comment says this was fixed in svn 6615. The corresponding git-svn commit c74b8e3ebbf92ccc157a591a1571158559a655cd changed source/medication/valueset-medication-form-codes.xml from the route-of-administration concept 284009009 to 421967003, matching the Jira resolution.

Additional context:
Medication is active in the current build through source/fhir.ini, but the DSTU1 Medication.product.form element has since become Medication.doseForm. Later Published/Persuasive Pharmacy issue FHIR-19296 changed the drug form binding from 421967003 to SNOMED CT 736542009, Pharmaceutical Dose Form, and is already represented on the combined branch by audit commit 3f8121c74ce427b4f97c621f41f9355c4a81a84d. No current source or community evidence indicates that FHIR-8065 should override that later decision.

AutoFHIR reconciliation:
No source change was made. Current Medication.doseForm binds to http://hl7.org/fhir/ValueSet/medication-form-codes, and that active value set includes SNOMED CT codes where concept is-a 736542009. Reverting it to 421967003 would contradict the later applied FHIR-19296 decision; the original route-of-administration binding error is not present.

Recommendation:
Keep this audit commit as-is. FHIR-8065 is reconciled as already applied historically and superseded by later medication-form terminology maintenance; future form-binding questions should be reviewed under the FHIR-19296 family rather than reopening the DSTU1 route-of-administration correction.
