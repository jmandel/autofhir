FHIR-14212: Audit Dosage doseAndRate application

Issue request:
FHIR-14212 was a Published, Persuasive with Modification Pharmacy issue asking to let Dosage carry multiple dose representations. The accepted resolution pulled DoseQuantity and RateQuantity under a repeating DoseAndRate backbone element and added a coded type whose binding was to be determined.

Initial application:
The change appears to have been applied in SVN/git history by e60c66de12, whose message names GF 14212 and build@13207 and whose patch added Dosage.doseAndRate with 0..* cardinality, type, dose[x], and rate[x] rows in source/datatypes/dosage.xml.

Additional context:
The current build still treats Dosage as an active, normative datatype on the dosage page. Later related records clarify rather than reverse the issue: FHIR-40217 corrected the Dosage.doseAndRate.type binding to http://terminology.hl7.org/ValueSet/dose-rate-type; FHIR-35896 clarified that doseAndRate wording depends on the containing resource; FHIR-15905 declined adding an invariant/comment about conflicting multiple dose/rate entries as an implementation consideration. A 2021 Zulip thread linked FHIR-14212 as the original multiplicity discussion and confirmed the type binding remains an example binding because no internationally complete required value set exists.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active source/fhir.ini entries include Dosage on the dosage page, assign it to Pharmacy, and mark it normative. The authoritative source/datatypes/dosage.xml already has Dosage.doseAndRate at 0..*, with Dosage.doseAndRate.type, dose[x], and rate[x], plus the later DoseAndRateType value set binding. There is no current source omission that would change implementer understanding of FHIR-14212.

Recommendation:
Keep this audit commit as-is. Do not make a redundant source edit for FHIR-14212; any future work should be handled under newer dosage regime issues if Pharmacy wants to further clarify multiple dose/rate semantics or examples.
