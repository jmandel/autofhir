FHIR-12517: Audit retired target body site context

Issue request:
FHIR-12517 was Published with resolution Persuasive with Modification. It asked to add DiagnosticRequest to the context of the procedure/procedurerequest targetBodySite extension, with final resolution text saying to add DiagnosticRequest to procedurerequest-targetbodysite.

Initial application:
The issue appears to have been pre-applied in git commit 2cd605d912cb03536541fa1b4db1093df394b58b, whose subject cites [#12517]. That commit changed source/procedurerequest/procedurerequest-extensions-spreadsheet.xml so the targetBodySite extension context changed from ProcedureRequest to ProcedureRequest;DiagnosticRequest, and it also carried the closely related FHIR-12505 DiagnosticRequest bodySite work.

Additional context:
Later source history merged DiagnosticRequest into ProcedureRequest in commit e9a85998b0, and current build history records ProcedureRequest -> ServiceRequest and BodySite -> BodyStructure. In the current core source, source/fhir.ini actively builds BodyStructure, Procedure, and ServiceRequest, while there is no live core definition for the old procedurerequest-targetBodySite/procedure-targetBodySite extension. Current ServiceRequest has ServiceRequest.bodyStructure as the native target-site representation, and the FHIR Extension Pack replacement extension procedure-targetBodyStructure is scoped to Procedure plus ServiceRequest for FHIR 4.0 and later.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The DSTU2-era DiagnosticRequest extension-context request was historically applied, and the current specification no longer has a DiagnosticRequest or ProcedureRequest extension context in core that should be edited. The current ServiceRequest/BodyStructure model and Extension Pack replacement already cover the surviving semantics.

Recommendation:
Keep this no-change audit commit. No core follow-up is needed for FHIR-12517; if a future issue finds a defect in the replacement procedure-targetBodyStructure extension, that work belongs in the FHIR Extension Pack rather than this core checkout.
