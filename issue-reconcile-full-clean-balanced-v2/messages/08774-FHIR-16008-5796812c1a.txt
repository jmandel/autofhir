FHIR-16008: Audit ElementDefinition mustSupport typo fix

Issue request:
FHIR-16008 was a Published/Persuasive STU3 technical correction for FHIR-core ElementDefinition. It reported that the ElementDefinition.mustSupport short description was missing the word "be" and read "If the element must supported" instead of "If the element must be supported"; Jira records the resolution as auto-approved.

Initial application:
The correction appears to have been applied before this reconciliation by git commit 414943838fa916af23d94682039f6b827bdf3915, "GF#16296 - fix typo", which changed source/datatypes/elementdefinition.xml from "If the element must supported" to "If the element must be supported". Jira comments from Grahame Grieve on FHIR-16008 also state that it was already fixed.

Additional context:
ElementDefinition remains an active current-build datatype and normative artifact in source/fhir.ini. Later wording updates added the parenthetical "(discouraged - see obligations)" to the same short description, but preserved the grammatical correction requested by FHIR-16008. Searches for the exact typo in current source, Zulip, and Confluence found no conflicting later decision or unapplied parallel location.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already contains "If the element must be supported (discouraged - see obligations)" for ElementDefinition.mustSupport, and the obsolete typo text is absent from current source.

Recommendation:
Keep this no-change audit commit as-is. No further FHIR-core source work is needed for FHIR-16008 unless a future work group decision reopens mustSupport wording more broadly.
