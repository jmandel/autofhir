FHIR-11236: Audit retired Sequence coordinate interval wording

Issue request:
FHIR-11236 was a Published/Persuasive Clinical Genomics change request for the DSTU2 FHIR-core Sequence resource. It asked to make Sequence.coordinateSystem absolutely clear about inclusive versus exclusive starts and ends: 0-based coordinates use an inclusive start and exclusive end, while 1-based coordinates use an inclusive start and inclusive end.

Initial application:
The issue was historically applied by commit d830ddede2fa70d5f6ccca85e723caa4a2c7a7bf, "#11235 #11236 #11239 #11240 Change description related with Sequence.coordinateSystem to be more accurate." That commit changed the Sequence spreadsheet source so Sequence.coordinateSystem had the requested short description and definition, and it updated the paired start/end elements using the same coordinate-system semantics. Historical release3 and release4 generated/profile artifacts preserve the applied wording on Sequence.coordinateSystem and MolecularSequence.coordinateSystem.

Additional context:
The original Sequence source is no longer part of the current core build: source/fhir.ini lists Sequence under removed resources, source/sequence is absent, molecularsequence is commented out, and source/molecularsequence has been deleted. Later R6 decisions, including FHIR-51227 and FHIR-50365, replaced legacy MolecularSequence with MolecularDefinition and then moved MolecularDefinition to the CG incubator/additional-resource track. Current MolecularDefinition source uses a different coordinateInterval/CodeableConcept model, while diagnostics/genomics narrative points implementers to the incubator MolecularDefinition resource rather than retaining the old core Sequence element.

AutoFHIR reconciliation:
This commit intentionally makes no source change. FHIR-11236 was applied to the then-current Sequence source, and the current core build no longer exposes the affected Sequence.coordinateSystem or MolecularSequence.coordinateSystem target. Porting the old integer coordinateSystem prose into MolecularDefinition would be a new MolecularDefinition/incubator modeling decision, not a reconciliation of this published DSTU2 Sequence clarification.

Recommendation:
Keep this audit commit as-is. No current FHIR-core source follow-up is needed for FHIR-11236; if implementers find MolecularDefinition coordinateInterval semantics ambiguous, handle that as a new MolecularDefinition-specific Clinical Genomics/incubator issue rather than resurrecting retired Sequence wording in core.
