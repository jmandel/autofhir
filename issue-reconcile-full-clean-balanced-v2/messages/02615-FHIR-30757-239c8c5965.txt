FHIR-30757: Make therapy relationship binding extensible

Issue request:
FHIR-30757 was a Published/Persuasive R5 BRR change request asking to bind ClinicalUseDefinition otherTherapy.relationshipType to a proposed extensible Therapy Relationship Type ValueSet covering contraindicated-with, indicated-with, sequencing, and replacement relationship codes.

Initial application:
The issue was applied in 2a6f7f57903587fca420433c42bcbb65ddd00a42 by adding CodeSystem/therapy-relationship-type, ValueSet/therapy-relationship-type, and a binding on the ClinicalUseDefinition otherTherapy relationshipType element. Current source preserves the CodeSystem and ValueSet, and the later ClinicalUseDefinition contentReference structure defines the shared relationshipType binding once under indication.otherTherapy for both indication and contraindication use. However, the binding strength remained preferred rather than the extensible strength requested and accepted for FHIR-30757.

Additional context:
ClinicalUseDefinition is an active current-build resource in source/fhir.ini and ClinicalUseIssue is retired/commented out. FHIR-30175 and FHIR-30758 are adjacent otherTherapy issues already represented on the combined branch and do not alter this binding-strength decision. FHIR-37450 later corrected the duplicate therapy relationship code by deciding the prep concept should use indicated-only-after, so this reconciliation leaves the current CodeSystem code assignments unchanged.

AutoFHIR reconciliation:
Changed only source/clinicalusedefinition/structuredefinition-ClinicalUseDefinition.xml so ClinicalUseDefinition.indication.otherTherapy.relationshipType binds to ValueSet/therapy-relationship-type with extensible strength. The existing CodeSystem and ValueSet already carry the accepted terminology, and no generated diagram or unrelated binding was changed.

Recommendation:
Keep this source fix as-is. It completes the accepted FHIR-30757 binding semantics in the active ClinicalUseDefinition source while preserving later same-family corrections and avoiding redundant terminology edits.
