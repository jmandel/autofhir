FHIR-37618: Audit ServiceRequest location search parameter

Issue request:
FHIR-37618 was Applied/Persuasive for FHIR-core ServiceRequest after the reporter found that R4 ServiceRequest.locationReference was not available as a search parameter and therefore could not be used with _include by default. The approved resolution was to add a reference search parameter for the preferred location specified in the ServiceRequest.

Initial application:
The issue was applied by commit 1b03c897bf868ef3a05a177d97870eb448c8a285, which added ServiceRequest location search parameters to source/servicerequest/bundle-ServiceRequest-search-params.xml. In the current R6 source, the historical R4 locationReference element is represented by ServiceRequest.location.reference under the ServiceRequest.location CodeableReference element, and the current active search parameter bundle contains ServiceRequest-location-reference with code location-reference, type reference, expression ServiceRequest.location.reference, and the approved description.

Additional context:
source/fhir.ini lists servicerequest=ServiceRequest and ServiceRequest=prr, so the ServiceRequest source folder and search parameter bundle are in the current build scope. The linked Zulip thread confirms the original problem: _include is driven by search parameters, there was no ServiceRequest location search parameter, and this was considered an oversight. Patient Care minutes show the issue was triaged to OO. Later same-file search-parameter cleanup commits did not remove or reinterpret the ServiceRequest.location.reference search parameter; the only observed later change to these location entries changed their standards status to normative.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already satisfies the applied decision for the current build: a reference search parameter exists for ServiceRequest.location.reference, preserving the requested ability to search/include by preferred location in the current ServiceRequest model. The current location-reference name is consistent with the current split representation of CodeableReference search parameters and avoids reintroducing the obsolete R4 element name.

Recommendation:
Keep this no-change audit commit as-is. No follow-up core FHIR source work is needed for FHIR-37618 unless a future work group decision changes the CodeableReference search-parameter naming convention or requests a compatibility alias for the old R4 locationReference search code.
