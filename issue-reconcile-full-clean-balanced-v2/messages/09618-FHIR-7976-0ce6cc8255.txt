FHIR-7976: Audit async process-message response URL

Issue request:
FHIR-7976 was Published as Persuasive with Modification for the FHIR-core messaging page. It asked to add an option for a message receiver to send responses to a mailbox endpoint chosen by the source, with the accepted modification defining asynchronous $process-message use: async=true, an optional response-url defaulting to MessageHeader.source.endpoint/$process-message, immediate acceptance/error acknowledgement, and later response messages submitted to the chosen endpoint with async=true.

Initial application:
The issue appears to have been applied by svn revision 5657, mirrored as git commit 8b801ae887a7ed1c4e58cb57c30a8379b50cf157, whose subject explicitly names #7976 and #6343. That commit replaced the old mailbox messaging text with $process-message rules and added the async=true, default source endpoint, and response-url behavior. Later source restructuring moved the durable operation details into source/messageheader/operationdefinition-MessageHeader-process-message.xml.

Additional context:
MessageHeader is an active current-build resource in source/fhir.ini, its operations list references OperationDefinition/MessageHeader-process-message, and source/messaging.html links readers from the $process-message section to that operation definition. FHIR-6343 is the same implementation family because it converted the old mailbox endpoint into $process-message. Later response-message reconciliation commits for the same operation and messaging area refine HTTP/message-response wording but preserve the FHIR-7976 async response URL mechanism.
