FHIR-5405: Audit no change for transaction bundle redesign

Issue request:
FHIR-5405 was a Published FHIR-core Feed ballot comment from DSTU1 asking to redesign transaction Bundle entries: separate the operation name from the status element, make it Coding-extensible, represent delete/read/vread and other operations more uniformly, and add a flag controlling whether processing halts on errors or warnings. The final Jira resolution was Considered - No action required, approved on the FHIR core teleconference on 12-Feb-2015.

Initial application:
No Jira-tagged source commit for FHIR-5405 was found. That is consistent with the final no-action resolution. The current source has evolved through other Bundle/HTTP issues rather than through a FHIR-5405 redesign: batch/transaction entries use Bundle.entry.request.method and Bundle.entry.request.url for the HTTP-equivalent action, while response.status/outcome and transaction atomicity define failure behavior.

Additional context:
Bundle is active in source/fhir.ini, and the Bundle core implementation guide includes transaction and batch profiles. Later related work, especially FHIR-34060, clarified transaction processing in terms of FHIR interactions while retaining HTTP verb references, including read, vread, search, and history as GET/HEAD interactions. Searches for FHIR-5405 in Zulip and Confluence, plus transaction/vread Bundle.entry.request terms, found no conflicting community decision requiring the 2015 rejected redesign.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source is aligned with the no-action decision: transaction/batch entries already carry an explicit request.method with a required HTTPVerb binding and a request.url, read/vread are supported as GET/HEAD interactions, and transaction failure semantics plus OperationOutcome handling avoid the requested warning/error halt flag.

Recommendation:
Keep this audit commit as-is. Reopening the broader redesign would require a new work-group decision because FHIR-5405 itself was Published with no action required and later source changes addressed transaction clarity without adopting Coding-extensible operation names or halt-on-warning flags.
