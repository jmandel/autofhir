FHIR-18838: Audit ServiceRequest instructional material support

Issue request:
FHIR-18838 was a Published FHIR-core ServiceRequest change request resolved Persuasive with Modification for R5. It asked to add support for instructional material by replacing the single string patientInstruction with a repeating patient-instruction structure that could carry either markdown or a reference to DocumentReference.

Initial application:
The change was applied before this reconciliation in the PR #2600 history. Commit 54d590c4141f492cba55736b75f98cd05adef687 first changed ServiceRequest.patientInstruction to a repeating markdown-or-DocumentReference choice named patientInstructions[x]; commit 9a3ecaeb96723757430685c56710131351afae20 then made it a repeating BackboneElement with a single instructions[x] child; commit a056425bd1cda209e84ec099f2999919746ab055 immediately normalized the names to ServiceRequest.patientInstruction and ServiceRequest.patientInstruction.instruction[x]. The Jira application comment points to the PR branch merge/application commit 82a5e11548ca38466674c55e3f4dcfd39f533d46.

Additional context:
ServiceRequest is an active current-build resource in source/fhir.ini. The current authoritative StructureDefinition source has ServiceRequest.patientInstruction as 0..* BackboneElement and ServiceRequest.patientInstruction.instruction[x] as 0..1 markdown or Reference(DocumentReference); the example uses the same shape. Later issue FHIR-54623 directly challenged the BackboneElement/single-child model and was Resolved - No Change, with the resolution stating that the choice element must be a child in order to allow multiple patient instructions.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already preserves the implementer-significant outcome of FHIR-18838: multiple patient/consumer instructions can be represented, and each instruction can be markdown or a DocumentReference. Renaming the element back to the plural Jira wording or flattening it into a direct choice would be a new breaking model change and would conflict with the later no-change decision.

Recommendation:
Keep this audit commit as-is. If OO wants to revisit the singular element name, child optionality, or BackboneElement shape, that should be handled as a new work-group decision because the current R6 source and the later FHIR-54623 disposition support leaving the model unchanged.
