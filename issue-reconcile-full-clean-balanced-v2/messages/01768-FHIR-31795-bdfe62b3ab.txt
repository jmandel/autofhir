FHIR-31795: Audit packaged product identifier distinction

Issue request:
FHIR-31795 was a Published/Persuasive BR&R clarification request for R5 asking what distinguishes PackagedProductDefinition.identifier from PackagedProductDefinition.package.identifier and what a Data Carrier Identifier is. The resolution says the top-level identifier is for the whole package, the package-level identifier is for parts of the package, and a Data Carrier Identifier is a GS1 bar code; the approved action was to improve the documentation.

Initial application:
The change appears to have been applied before this reconciliation. Commit 8f276af0294e5a576ebd983b58659aa54899dff2 changed the generic PackagedProductDefinition.identifier and PackagedProductDefinition.package.identifier wording to the whole-package and packaging-part descriptions for FHIR#31795/FHIR#31796. Commit c58270261982846561c4e2c2a7612e2b1f660b55 then synced the same wording from R4B for FHIR#31795. Later wording work in 09e9fd4d7caabbd76b12d2c73f26a9adf5c3ab22 and 41d2b22c8d91836f8c43576c245312a37a8c9bfe kept the same distinction while adding the content/package contrast, manufacturer assignment note, and a typo fix.

Additional context:
The current build actively includes PackagedProductDefinition in source/fhir.ini, with normative maturity and approved standards status. FHIR-29692 later renamed PackagedProductDefinition.package to PackagedProductDefinition.packaging because the child backbone describes packaging details rather than the package as a whole; the current target element is therefore PackagedProductDefinition.packaging.identifier. Related FHIR-31796 is already represented on the combined branch, and FHIR-29783 later recorded that the PackagedProductDefinition identifier wording had already been updated and no further tracker change was needed. Zulip and Confluence searches found no conflicting community record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active StructureDefinition already says PackagedProductDefinition.identifier is a unique identifier for the package as a whole and not the package contents, while PackagedProductDefinition.packaging.identifier is specific to a particular part of the packaging and may include a Data Carrier Identifier, identified as a GS1 barcode. Small grammar imperfections such as "as whole" do not change the implementer-facing meaning and do not justify a source edit under this reconciliation threshold.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is recommended for FHIR-31795 unless BR&R wants an editorial-only grammar cleanup outside issue reconciliation.
