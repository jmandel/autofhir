FHIR-31836: Audit SubstanceDefinition binding review

Issue request:
FHIR-31836 was Published/Persuasive for R5 and asked whether several SubstanceSpecification coded elements, including name.type, name.domain, and relationship.type, should have extensible or required bindings. The final resolution says the bindings were reviewed, value sets were created, a few value sets were made required, and the remaining binding strength should stay at example until more implementation experience exists.

Initial application:
No source commit found in this checkout explicitly names FHIR-31836. The change appears to have been pre-applied through the broader BRR/MedDef terminology work: commits c4105f29435c and related January 2022 commits created the substance code systems and value sets, and commit 9ee11711505a added the SubstanceDefinition bindings. Later QA and metadata commits refined those terminology resources without changing the issue's substantive example-binding outcome.

Additional context:
SubstanceSpecification is represented in the current build as the active SubstanceDefinition resource. source/fhir.ini lists substancedefinition as an active resource under BRR. BRR minutes on 2022-02-10 record FHIR-31836 as Persuasive with value sets created, while earlier 2021 minutes grouped it with the broader MedDef/vocabulary binding work. Later FHIR-39596, already represented on the combined branch, intentionally removed the structure-technique binding from the newer characterization.technique element, so not every current SubstanceDefinition CodeableConcept should be treated as a missed FHIR-31836 binding.

AutoFHIR reconciliation:
This audit commit makes no source change. The current SubstanceDefinition source already binds name.type to ValueSet/substance-name-type, name.domain to ValueSet/substance-name-domain, and relationship.type to ValueSet/substance-relationship-type with example strength, and the corresponding value set files exist in the active source/substancedefinition folder. Required/common bindings such as name.language and sourceMaterial.countryOfOrigin are also present where the issue family called for them.

Recommendation:
Keep this no-change audit. Future work should only change SubstanceDefinition binding strengths or add new substance terminology after a new BRR/vocabulary decision, because the FHIR-31836 resolution explicitly chose example bindings for most substance-specific value sets pending more implementation experience.
