FHIR-7568: Audit Provenance agent activity linkage

Issue request:
FHIR-7568 was a Published/Persuasive with Modification DSTU1 Security tracker asking how Provenance agents and entities are linked when multiple agents and multiple entities participate in the activity that resulted in the target resource. The issue was explicitly resolved by FHIR-9840.

Initial application:
No commit was found that mentions FHIR-7568 directly. The linked resolution was applied through git commit 7755ff73d634727ea105334aa4aa76f05df7cbd1, which included GF#9840 and changed Provenance.entity.agent from 0..1 to 0..* while adding the explanatory use-case comment about an agent providing access to an externally managed entity used in the Provenance activity.

Additional context:
Provenance is an active current-build resource in source/fhir.ini. The current authoritative StructureDefinition preserves the FHIR-9840 cardinality and comment on Provenance.entity.agent, and the Provenance introduction says a Provenance resource corresponds to a single activity, with multiple activities represented by independent Provenance records. A related FHIR-7570 audit is already on the combined branch for the companion entity-agent clarification. Later Published tracker FHIR-33228 intentionally changed the same definition from "generated the entity" to "used the entity", confirming that the current wording should describe source entities used by the Provenance activity rather than target generation.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already answers the FHIR-7568 question through the active Provenance.entity.agent definition/comment and cardinality, interpreted with the related FHIR-9840 and FHIR-33228 decisions.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-7568 unless the Security work group later decides to remodel Provenance.entity.agent or the single-activity Provenance guidance.
