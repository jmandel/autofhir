The filed Jira description narrowed the concrete wording to narrative and attachments, and the historical application used the Attachment datatype plus resource-set/id consistency guidance rather than a separate FHIR document-Bundle sentence.

AutoFHIR reconciliation:
No source change was made. The current build-scope source at source/secpriv-module.html already contains the De-Identification, pseudonymization, anonymization section, explicitly links Narrative and Attachment as particularly difficult challenges, discusses ids and external identifiers, explains consistent changes across a de-identified resource set, and frames the process by use case, data scope, and release risk. The page is linked from the current module list and module fragment, so this is active specification source. Adding another local mention of documents would be redundant and less precise than the existing Attachment/resource-set guidance.

Keep this empty audit commit as-is. The current Security and Privacy module satisfies FHIR-14312; any future desire for detailed FHIR document-Bundle-specific de-identification guidance should be raised as a new work-group decision rather than inferred from this already-applied STU3 issue.
