FHIR-29663: Audit UCUM common [kp_C] correction

Issue request:
FHIR-29663 was a Published/Persuasive FHIR-core vocabulary change request for R5 asking to replace the UCUM common ValueSet code `{kp_C}` with `[kp_C]` because the published R4 value set contained an invalid expression for the intended homeopathic potency unit. The resolution also noted that the example value set was out of date and should be considered separately for a new version.

Initial application:
The issue appears to have been applied before this reconciliation by commit 0c94343a04a2ae99f2e071fb983bf663cce7af5c, whose subject was `fhir-36010 + fhir-29663`. That commit changed `source/valueset/valueset-ucum-common.xml` from `{kp_C}` to `[kp_C]`; current R5 history also contains `[kp_C]`, while older R4/R4B history retains `{kp_C}`.

Additional context:
The current active ValueSet source still has `[kp_C]`, and `source/ucum-essence.xml` contains the matching UCUM unit code. The ValueSet is part of the current core build surface because ValueSet is an active resource in `source/fhir.ini` and `source/valueset/list-ValueSet-examples.xml` references `ValueSet/ucum-common`. Vocabulary WG Confluence minutes for 2021-06-10 confirm the group found the issue persuasive and needed to change the code, while separate search found no conflicting Zulip or Confluence discussion. FHIR-36010 was applied in the same historical commit but concerns adding `1`/`{1}` to UCUM value sets, so it is related history rather than a decision made here.

AutoFHIR reconciliation:
No source change was made. The current source already implements the approved correction by using `[kp_C]` in `source/valueset/valueset-ucum-common.xml`.

Recommendation:
Keep this audit commit as-is. No further FHIR core source work is needed for FHIR-29663; any broader refresh of the UCUM common example value set should be handled under a separate vocabulary decision.
