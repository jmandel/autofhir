FHIR-37811: Audit _filter parameter scope

Issue request:
Published/Persuasive with Modification FHIR-I issue FHIR-37811 asked to clarify the _filter documentation because the old phrase "same set of standard parameters" could be read as excluding server-created SearchParameter definitions. The approved resolution was to change that wording to say _filter uses the search parameters available in that resource context on the server.

Initial application:
The issue was applied by commit 29624ec5f80763efe18849b995c45334eccf6f59, which replaced the old standard-parameters sentence in source/search_filter.html with wording that filter requests access the same search parameters available to the search operation in the resource context on the server. The current source still has that wording, and source/hierarchy.xml includes search_filter.html under the RESTful API search pages, so the checked source is in the current build path.

Additional context:
The Jira related community.fhir.org thread records Grahame Grieve answering that custom search parameters can be used, matching the approved clarification. FHIR-I minutes on 2022-08-29 record the Persuasive with Modification vote for FHIR-37811. Later same-page commits adjusted examples, grammar, and unrelated superseded content without reversing the introductory clarification.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current _filter introduction already conveys the approved server-context rule, no copy of the old standard-only phrase remains in current source, and adding another restatement would not change implementer understanding.

Recommendation:
Keep this audit commit as-is. Revisit only if a future work-group decision wants a broader rewrite of the _filter grammar or search-parameter availability rules; FHIR-37811 itself is already correctly reflected in the current core source.
