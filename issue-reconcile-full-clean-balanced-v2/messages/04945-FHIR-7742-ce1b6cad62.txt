FHIR-7742: Audit administration method value set correction

Issue request:
FHIR-7742 was a Published/Persuasive Pharmacy change request for DSTU1 MedicationAdministration. It said the administration method value set could confuse readers because many values were not appropriate for medications, and the accepted resolution was to fix the link to the correct value set and add SNOMED CT 422096002 Dosing instruction fragment as an exemplar value set.

Initial application:
The historical application is commit adf4e89f89fd, whose subject explicitly includes GF#7742 and GF#5990 and says it added the administration method exemplar value set binding. That commit changed MedicationAdministrationMethod from unbound to an example value-set binding to http://hl7.org/fhir/ValueSet/administration-method-codes and rewrote the then medication order administration-method value set around SNOMED CT 422096002.

Additional context:
FHIR-5990 is the same value-set correction family for neighboring medication resources. A later Published/Persuasive with Modification Pharmacy decision, FHIR-19913, changed the active Dosage.method value set basis from 422096002 to SNOMED CT 736665006 Dose form administration method; historical commit 1dcdc4c567 applied that to source/datatypes/valueset-administration-method-codes.xml. The combined branch already contains FHIR-19913 commit 8f91c3f2e034, which fixed the remaining example wording and documented that the old source/medicationrequest copy containing 422096002 is not the active current binding source. Current source/fhir.ini lists MedicationAdministration and Dosage as active build inputs, MedicationAdministration.dosage.method remains example-bound to the administration-method canonical, and the active datatypes value set now filters on 736665006.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The seed request was applied historically, and the current active source is correct after the later FHIR-19913 decision. Reverting the active value set to 422096002 would contradict that later published decision, while editing the unreferenced MedicationRequest duplicate would not change current built content for this issue.

Recommendation:
Keep this empty audit commit as-is. No FHIR-7742 follow-up is needed in core; any future cleanup of duplicate, unreferenced value-set source files should be handled as a separate terminology/source hygiene task.
