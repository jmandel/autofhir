FHIR-11279: Audit ConceptMap related-to relationship

Issue request:
FHIR-11279 was a Published/Persuasive FHIR-core ConceptMap issue from the Vocabulary work group. It asked to address required ConceptMap equivalence assertions by adding a root "related to" code with guidance encouraging more specific codes when possible.

Initial application:
The issue was applied before this reconciliation. Jira FHIR-11279 records svn revision 9925, and git commit b11f1f4131d2c977cef30cb82e26399fad2ecedc added `relatedto` to ConceptMapEquivalence and made the more specific equivalence codes children of that new parent.

Additional context:
FHIR-10437 was the earlier Mayo request with the same substance and was resolved as already done under another task. Later R5 decisions FHIR-22632 and FHIR-25923 retired ConceptMapEquivalence, introduced ConceptMapRelationship, and clarified the directional relationship code names. Those later issues are already represented on the combined branch and preserve the root concept as `related-to`.

AutoFHIR reconciliation:
No source change was made. The current active ConceptMap source has ConceptMap.group.element.target.relationship and ConceptMap.group.unmapped.relationship required-bound to ValueSet/concept-map-relationship, and the authoritative ConceptMapRelationship code system includes `related-to` as the parent of `equivalent`, `source-is-narrower-than-target`, and `source-is-broader-than-target` with guidance to use a more specific code where possible.

Recommendation:
Keep this no-change audit commit. Reintroducing the obsolete ConceptMapEquivalence value set would conflict with later published ConceptMap relationship decisions; any future semantic change should be handled as a new ConceptMapRelationship issue.
