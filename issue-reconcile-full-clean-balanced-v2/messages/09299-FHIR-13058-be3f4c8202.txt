Issue request:
FHIR-13058 was a Published/Persuasive FHIR-core correction for DSTU2. It reported that the Binding table for Questionnaire.subjectType rendered two binding links, one for the value set URL and one for the ResourceType name, and requested that only the named binding link be shown.

Initial application:
The Jira issue was auto-approved and Grahame Grieve commented on 2017-03-24 that it was already fixed. No current git commit mentioning FHIR-13058 was found in the FHIR source history, so the original application appears to have been a pre-existing renderer/tooling fix or an unkeyed historical source/build change rather than a current source defect.

Additional context:
Questionnaire is an active current-build resource in source/fhir.ini. The current Questionnaire.subjectType StructureDefinition source carries a single required binding with bindingName ResourceType and valueSet http://hl7.org/fhir/ValueSet/resource-types. Current public CI output renders the binding table row as a single row for Questionnaire.subjectType / ResourceType / Required / Concrete FHIR Resource Types. A 2023 Zulip thread about Questionnaire.subjectType confirmed that ResourceType is the intended bound code enumeration for schema/rendering purposes and did not identify the duplicate-link rendering problem as current.
