FHIR-23079: Correct Address codedString example codes

Issue request:
FHIR-23079 was Published / Not Persuasive with Modification for the request to change Address.state, Address.country, and Address.district from string to CodeableConcept. The accepted modification was to keep the Address elements as strings, rename the iso21090-SC-coding extension to a more human-readable name, reference that extension in the Address datatype description, and add Address examples that use it.

Initial application:
Core commit b8aac7778d29 applied FHIR-23079 by adding Address datatype description text for ISO21090-codedString and an Address example using the extension. Later commit e9e4e5f34c8d added JSON datatype examples, including a JSON version of this codedString Address example. The extension definitions were subsequently removed from core source when extensions moved out to the Extension Pack, where iso21090-codedString is active and iso21090-SC-coding is retired/deprecated in favor of it.

Additional context:
The current build-scope datatype examples page still contains the FHIR-23079 example. The example used the right extension URL, but the state and country codings were semantically inconsistent: the state value IN was paired with country-level coding and the JSON country coding used IN for United States. The current terminology systems page lists ISO 3166 URNs including urn:iso:std:iso:3166:-2, which is the appropriate ISO subdivision code system for the Indiana state code US-IN.

AutoFHIR reconciliation:
This commit keeps the original FHIR-23079 design decision: Address.state, Address.country, and Address.district remain strings, and coded representations use iso21090-codedString. It corrects only the Address codedString example so state uses urn:iso:std:iso:3166:-2#US-IN and country uses urn:iso:std:iso:3166#US consistently in XML and JSON.

Recommendation:
Keep this source fix. It is a bounded correction to the example created for FHIR-23079 and avoids changing the datatype model or the extension-pack source. FHIR-19608 and FHIR-51664 were useful background, but neither needs a separate core reconciliation commit from this seed.
