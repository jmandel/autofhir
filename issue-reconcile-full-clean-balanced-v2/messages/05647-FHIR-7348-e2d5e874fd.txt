FHIR-7348: Audit Appointment participant actor rule

Issue request:
FHIR-7348 was Published with resolution Not Persuasive with Modification. The issue asked to make Appointment.participant.actor 1..1 because a participant without an actor seemed meaningless, but the accepted resolution kept actor optional and required an invariant that each participant has either type and/or actor, with documentation explaining why actor can be absent.

Initial application:
No current-history commit explicitly mentions FHIR-7348, but the 2015 Appointment reconciliation commit 44a2cf49 added supporting narrative that participant type can stand in for an unknown actor and added the Appointment.participant invariant text. Later source maintenance converted the expression to FHIRPath in af77b9dac9, changed MUST to SHALL in 329acfd730, and carried the rule into the current StructureDefinition source during the 2021 build-source rework.

Additional context:
Appointment is an active current-build resource in source/fhir.ini, and source/appointment/structuredefinition-Appointment.xml is the active definition. The current source keeps Appointment.participant.actor at 0..1, applies app-1 to both participant.type and participant.actor, and defines app-1 as type.exists() or actor.exists(). The current introduction and participant.type comment both describe the unknown-actor scheduling use case. Later related Appointment actor/value-set issues found during neighborhood checks, including FHIR-28588 and FHIR-34141, address CareTeam targeting and value-set wording and do not reverse the FHIR-7348 rule.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already implements the accepted invariant and explanatory documentation, so changing actor to 1..1 would contradict the final Jira disposition.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-7348 unless PA later decides to remove or alter the app-1 invariant.
