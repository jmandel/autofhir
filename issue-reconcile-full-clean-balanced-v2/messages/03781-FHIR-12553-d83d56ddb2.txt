FHIR-12553: Remove stale QUICK Claim prosthesis metadata

Issue request:
FHIR-12553 was Published/Persuasive for DSTU2 and asked to remove Claim.prosthesis and ExplanationOfBenefit Prosthesis because prosthetic details are better handled as resource information.

Initial application:
The historical application appears in commit 6b87ac547b0c0739c9e9feb5305c4d7c6ec999ed, which disabled Claim.item.prosthesis and ExplanationOfBenefit.item.prosthesis rows in the Claim and ExplanationOfBenefit spreadsheets and added a prosthesis information-category code for the replacement information pattern. The current Claim and ExplanationOfBenefit StructureDefinitions already expose supportingInfo and no longer define the removed prosthesis item backbone.

Additional context:
Later resource refactoring renamed information to supportingInfo, and the active Library resource examples include the QUICK model definition content. The current FHIR ModelInfo is aligned with supportingInfo, but the QUICK example ModelInfo still retained QUICK.Claim.Prosthesis and QUICK.Claim.Item.prosthesis. Jira and community searches found no later decision reversing FHIR-12553; the only Zulip hit was the original tracker bot announcement and no Confluence references were found.

AutoFHIR reconciliation:
Removed the stale QUICK.Claim.Prosthesis ClassInfo and QUICK.Claim.Item.prosthesis element from source/library/library-quick-model-definition-content.xml. The authoritative Claim and ExplanationOfBenefit resources and the FHIR ModelInfo were left unchanged because they already reflect the issue, and the remaining prosthesis code in Claim.supportingInfo is the intended replacement representation.

Recommendation:
Keep this commit as a narrow cleanup of the active Library example ModelInfo. No further core source work is needed for FHIR-12553 unless maintainers decide the legacy QUICK example should be regenerated from an external source rather than manually maintained.
