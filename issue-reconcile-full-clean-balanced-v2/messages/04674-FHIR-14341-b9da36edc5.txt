FHIR-14341: Audit AdministrativeGender intersex wording

Issue request:
FHIR-14341 was a Published/Persuasive PA change request against the FHIR-core terminologies/value sets area. It requested replacing the outdated term "hermaphrodite" with "intersex" in the v3 AdministrativeGender `UN` (Undifferentiated) definition; the resolution stated that this modernized terminology without changing the meaning and noted that the v3 terminology change might require harmonization.

Initial application:
No git commit explicitly mentioning FHIR-14341 was found. PA January 2019 WGM minutes record acceptance of the requested AdministrativeGender `UN` wording update. The historical v3 terminology source update in git commit f04f624af84359656111d4bfbef5e06703525fef replaced `source/v3/source.xml` with a 2019 vocabulary source where `UN` uses "intersex" and the Dutch "intersekse-conditie" text, with a Gender Harmony stopgap note. Later commit 5c0494aacfd0b8bd52bc72c587aa89d0a64246f8 removed UTG content from the core build, and commit 02557a9364dab7c1c03bc9597ec62955ee76e635 carried the same updated v3 source into `tools/tx/v3/source.xml`.

Additional context:
Current core source composes the AdministrativeGender value set from `http://terminology.hl7.org/CodeSystem/v3-AdministrativeGender`; the current HL7 Terminology JSON definition for code `UN` says "such as intersex" and does not use the Jira-requested obsolete wording. The remaining `hermaphrodite` hits are in release-history snapshots, DICOM imported terminology, spelling dictionaries, or the old separate Dutch `tools/tx/v3/source_nl.xml` helper file. That helper is not referenced by `source/fhir.ini`, while `tools/tx/v3/source.xml` and THO already carry the approved text. Related FHIR-16340 separately rejected adding an Intersex code and kept AdministrativeGender `other`; it is already represented on the combined branch.

AutoFHIR reconciliation:
No source change was made. The current active/current authoritative surfaces already have the modernized `UN` definition, and core no longer owns the v3 CodeSystem definition as current build source. Editing stale release history, imported DICOM source, spelling dictionaries, or auxiliary legacy translation input would not correct the current FHIR specification.

Recommendation:
Keep this no-change audit commit. No current FHIR core follow-up is needed for FHIR-14341; if legacy terminology tooling is ever refreshed, `tools/tx/v3/source_nl.xml` can be considered as a housekeeping update outside this current-spec reconciliation.
