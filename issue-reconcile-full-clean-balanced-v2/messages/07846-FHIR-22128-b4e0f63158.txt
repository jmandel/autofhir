FHIR-22128: Clarify maxLength primitive type scope

Issue request:
FHIR-22128 was Published/Persuasive with Modification for FHIR-core ElementDefinition. It asked that ElementDefinition.maxLength and the minLength extension be constrained to simple data types, not complex types such as Coding, with the limitation reflected in descriptions and handled by validation tooling.

Initial application:
The closest source application was commit fce5daa6e5be65acdae0d73ed5aa36503e75b532 for FHIR-20925, the earlier maxLength-only issue referenced from the FHIR-22128 comments. That commit changed ElementDefinition.maxLength to a string-oriented short description and a SHOULD-level primitive-type note. No core commit explicitly mentioning FHIR-22128 was found. The minLength extension was later removed from core source by dd468d4f1799dd79819315b211588ef1cf4586e0 and now lives in the FHIR Extension Pack.

Additional context:
FHIR-I minutes on 2022-08-22 record the FHIR-22128 reopen and Persuasive with Modification vote. The associated Zulip thread shows that an invariant was considered difficult and Grahame proposed putting the enforcement in validator logic instead. Later FHIR-49226 broadened maxLength support to dates/dateTimes/times and changed the same ElementDefinition sentence, but left the short description string-specific and introduced weak/typoed wording. source/fhir.ini lists ElementDefinition as an active normative datatype, so source/datatypes/elementdefinition.xml is in current build scope.

AutoFHIR reconciliation:
Updated source/datatypes/elementdefinition.xml so ElementDefinition.maxLength no longer has a string-only short description and now states that maxLength SHALL only be used on primitive data types where character length has meaning, not complex types such as Coding. The edit also fixes the broken Type Characteristics link text introduced by the later maxLength wording change. No core minLength source was edited because that extension is no longer built from this checkout.

Recommendation:
Keep this commit as the FHIR-core reconciliation for FHIR-22128. If the work group wants the Extension Pack minLength definition to use the same explicit SHALL wording, handle that as follow-up work in /home/jmandel/work/fhir-extensions rather than in this core branch.
