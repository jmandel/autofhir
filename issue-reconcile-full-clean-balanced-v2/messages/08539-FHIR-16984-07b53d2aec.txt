FHIR-16984: Audit ContactPoint rank clarification

Issue request:
FHIR-16984 was a Published/Persuasive FHIR-core datatype change request for STU3 asking to clarify ContactPoint.rank. The key request was to replace wording that could imply ordering of repetitions, "Contacts are ranked with lower values coming before higher values", with wording that says ContactPoints with lower rank values are more preferred than those with higher rank values.

Initial application:
The Jira comment records svn revision 14299. In the git mirror, e8f0a1acb64f4c98a41dc4ebd4899d9665efc1c0 is that git-svn revision and changed source/datatypes/contactpoint.xml from the old "Contacts are ranked..." wording to the requested "ContactPoints with lower rank values are more preferred..." wording.

Additional context:
source/fhir.ini lists ContactPoint as an active datatype and marks it normative, so source/datatypes/contactpoint.xml is current build-scope source. The current ContactPoint.rank row still contains the FHIR-16984 clarification and also says rank does not necessarily follow instance order. Later Published issue FHIR-38824 added examples for equal, missing, and non-sequential ranks; those additions complement rather than reverse FHIR-16984.

AutoFHIR reconciliation:
No source change was made. The active current source already carries the required lower-rank-is-more-preferred clarification, and later comments address the repetition-order ambiguity that motivated the original issue.
