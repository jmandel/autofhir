FHIR-44487: Audit ExampleScenario ordering semantics

Issue request:
FHIR-44487 was an Applied FHIR-I change request for ExampleScenario asking whether process and step needed explicit ordering elements. The persuasive-with-modification resolution directed that ElementDefinition.orderMeaning be declared on ExampleScenario.actor, process, step, and alternative, with step also explaining execution order, and that no separate ordering element was needed because FHIR instance order is retained.

Initial application:
The issue was applied in git master commit 3e0dcd29555e3653d929981a79676ffe68ceca50, which added orderMeaning values to the active ExampleScenario StructureDefinition. Current source still contains those values on ExampleScenario.actor, ExampleScenario.process, ExampleScenario.process.step, ExampleScenario.process.step.alternative, and the nested step/content-reference locations needed to carry the same ordering semantics through sub-processes and alternatives.

Additional context:
ExampleScenario is in the current build scope through active source/fhir.ini entries. FHIR-I minutes from 2024-02-12 record FHIR-44487 as persuasive with modification, matching the Jira vote record. Searches for additional ExampleScenario ordering/orderMeaning Jira, Zulip, and Confluence evidence found no conflicting later decision; the current step text says the order indicates when events occur, which preserves the intended process/step execution-order meaning.

AutoFHIR reconciliation:
