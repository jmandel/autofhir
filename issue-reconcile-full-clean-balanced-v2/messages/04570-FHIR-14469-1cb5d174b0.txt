FHIR-14469: Audit Appointment procedure request coverage

Issue request:
FHIR-14469 was a Published PA change request for STU3, resolved Not Persuasive with Modification. It asked to update the Appointment indication so a procedure-to-be-performed could be represented by ProcedureRequest, and also noted the typo "Reason the appointment is to takes place".

Initial application:
No direct git commit mentioning FHIR-14469 was found. The relevant application happened through the Appointment request-reference work: FHIR-13195 renamed Appointment.incomingReferral to Appointment.basedOn, and the historical request-resource commits merged ReferralRequest with ProcedureRequest and then renamed ProcedureRequest to ServiceRequest before current source generation.

Additional context:
Appointment is an active resource in source/fhir.ini. Current Appointment.basedOn is a request reference whose definition explicitly includes an incoming referral or procedure request and whose target profiles include ServiceRequest, the current successor that covers the old ProcedureRequest/ReferralRequest scope. Current Appointment.reason also has clean wording and no remaining "to takes place" typo. The existing combined-branch FHIR-25278 audit records a later basedOn expansion that preserved ServiceRequest and the reason-vs-basedOn separation.

AutoFHIR reconciliation:
No source change was made. Adding a legacy ProcedureRequest target or moving this request relationship back into Appointment.reason/indication would be wrong for current FHIR source; the current build already conveys the approved resolution through Appointment.basedOn.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-14469 unless PA later decides to change Appointment.reason semantics independently of the already-applied basedOn request relationship.
