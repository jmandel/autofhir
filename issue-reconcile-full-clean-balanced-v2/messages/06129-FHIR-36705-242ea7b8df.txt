FHIR-36705: Audit Expression.language max binding

Issue request:
FHIR-36705 was a Published/Persuasive FHIR-core technical correction for R5 asking that the Expression.language maxBinding stop using the obsolete http://www.rfc-editor.org/bcp/bcp13.txt reference and instead use the R5 media-type value set.

Initial application:
The issue was applied by git commit 8d74e147a505af1f37628052a63002b7a88d8d02 and merged by 3707e60601831442b157f84df88a8e91db0f7bc6. That source change replaced the old bcp13.txt maxBinding in source/datatypes/expression.xml with http://hl7.org/fhir/ValueSet/mimetypes for the ExpressionLanguage binding.

Additional context:
Expression is active in the current build through source/fhir.ini's datatype registration and metadatatypes page mapping. The current source/datatypes/expression.xml binding points Expression.language at valueset-expression-language with a maximum binding of http://hl7.org/fhir/ValueSet/mimetypes, and source/terminologies/valueset-mimetypes.xml defines that active value set as all BCP-13 media type codes. The Jira description named AllMediaTypes, but later FHIR-36752 deleted the redundant valueset-all-media-types artifact and confirmed that ValueSet/mimetypes is the normative replacement; that issue already has an audit commit on the combined branch. Published R5 and current build Expression profiles both expose the maximum binding as http://hl7.org/fhir/ValueSet/mimetypes, and valueset-all-media-types is not published in R5/current build.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped source and published conformance surface already satisfy FHIR-36705 after the later FHIR-36752 cleanup clarified that the requested media-type value set is now ValueSet/mimetypes rather than a separate all-media-types artifact.

Recommendation:
Keep this no-change audit commit. No further core FHIR source work is needed for FHIR-36705 unless a future Vocab/FHIR-I decision reintroduces or renames the all-media-types value set.
