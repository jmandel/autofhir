FHIR-16920: Audit Bundle endpoint behavior note

Issue request:
FHIR-16920 was Published with a Persuasive with Modification resolution for the STU3 Bundle/Feed artifact. It asked for brief Bundle-page guidance about special considerations when writing to the /Bundle endpoint rather than the RESTful base address, with server implementer input about any additional endpoint complexities.

Initial application:
The issue was applied in git-svn revision 14407, now commit 194adcb3902ba5dc3c5e2d8192e61069b2225924, which added the Bundle page section "Serving Bundles using the RESTful API". That section states that /Bundle behaves like the normal Bundle resource endpoint: a batch, transaction, or message POSTed there is stored as a Bundle resource and is not processed as a batch, transaction, or message.

Additional context:
Bundle is an active resource in source/fhir.ini, and source/bundle/bundle-notes.xml is current Bundle narrative source. The RESTful HTTP page separately defines batch/transaction processing as POST [base], which is the complementary behavior needed to understand the distinction. Later Zulip and Confluence searches found discussion consistent with the same rule and no final later Jira decision requiring a different core change.

AutoFHIR reconciliation:
No source change was made. The current active Bundle source already provides the requested /Bundle endpoint warning and links to the usual RESTful interactions, while the HTTP page covers POST [base] processing. Additional wording would be redundant rather than corrective.

Recommendation:
Keep this audit commit as-is. Revisit only if the work group wants to clarify broader transaction semantics for operations or non-base endpoints in a new issue; FHIR-16920 itself is already represented in current build source.
