FHIR-7356: Audit resource identity wording

Issue request:
FHIR-7356 was Published with resolution Persuasive with Modification for DSTU1 section 1.10.3.2. It asked to avoid the ambiguous "may not" wording in Resource Identity text and clarify that a copied resource always has a different full/location identity on another server while its local/logical id might or might not be retained.

Initial application:
The issue was applied in git commit 3d7d55ef1615c3ef845da02f3397566936f2d7e4, which corresponds to the Jira comment's svn revision 6430 and changed source/resource/resource-notes.xml from "may not retain the same identity" to text saying the copied resource might not be able to retain the same logical identity.

Additional context:
The current built Resource narrative is sourced from the active Resource infrastructure entry in source/fhir.ini. Later Resource Identity work, including FHIR-9089 and commit 7ee661f6b4022414f36a63274872d7ef207a8716, refactored the section to distinguish location/full URL identity from logical id more explicitly. The current source no longer contains the ambiguous seed wording and now says a copy "might or might not keep the same logical id" while linking to Managing Resource Identity.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already conveys the issue's required distinction without the ambiguous "may not retain the same identity" phrase, and adding another clarification would duplicate existing Resource Identity guidance.

Recommendation:
Keep this no-change audit commit as-is. No FHIR-core follow-up is needed for FHIR-7356 unless the work group wants a broader editorial rewrite of Resource Identity, which would be outside this issue's narrow applied correction.
