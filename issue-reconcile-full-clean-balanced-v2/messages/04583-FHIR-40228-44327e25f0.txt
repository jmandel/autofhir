FHIR-40228: Audit ConformanceExpectation SHALL-NOT application

Issue request:
FHIR-40228 was an Applied/Persuasive with Modification FHIR-core FHIR-I issue reporting that ConformanceExpectation, and therefore the conformance-expectation ValueSet, was missing the SHALL-NOT code used by the conformance language. The approved resolution added SHALL-NOT to the broader code system, let the current value set inherit it, and kept CapabilityStatement prohibition semantics out of the non-modifier expectation extension by using a separate prohibited modifier extension and THO/Extension Pack handling.

Initial application:
The active FHIR-core source was updated by f094b0ede945 for FHIR-40228, adding SHALL-NOT to source/capabilitystatement/codesystem-conformance-expectation.xml. The active source/capabilitystatement/valueset-conformance-expectation.xml composes all codes from http://hl7.org/fhir/conformance-expectation, so it inherits SHALL-NOT. A later AutoFHIR commit for FHIR-29593 on the combined branch corrected the malformed SHALL-NOT definition text while preserving the code/display.

Additional context:
CapabilityStatement is an active current-build resource in source/fhir.ini, and conformance-expectation is an active ValueSet entry. The extension-specific part of the FHIR-40228 resolution is not owned by the current FHIR-core source: capabilitystatement-expectation and capabilitystatement-prohibited are maintained in the FHIR Extension Pack. There, capabilitystatement-expectation points implementers to capabilitystatement-prohibited for SHALL NOT/prohibited semantics, and capabilitystatement-prohibited is a modifier extension. FHIR-44609 later published that cross-reference clarification, while the FHIR-40228 Jira comment notes that the extension uses the THO code system/value set and changes there are tied to THO.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current FHIR-core CodeSystem has SHALL-NOT with the corrected prohibition definition, the current FHIR-core ValueSet includes it through its all-codes compose, and the CapabilityStatement-specific prohibition handling is already represented in the Extension Pack rather than by a new core source artifact.

Recommendation:
Keep this audit commit as-is. No additional FHIR-core edit is needed for FHIR-40228; any future change to the THO conformance-expectation value set or the Extension Pack binding should be handled in those repositories and coordinated with FHIR-44609-style extension guidance.
