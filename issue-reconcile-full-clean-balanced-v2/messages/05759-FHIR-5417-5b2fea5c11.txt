FHIR-5417: Audit Organization contact gender removal

Issue request:
FHIR-5417 was a Published/Persuasive Patient Administration change request for the DSTU1 Organization resource. The ballot comment challenged the arbitrary-looking Organization.contact.gender element, and the final resolution was to remove the gender property from the organization contact.

Initial application:
No explicit Jira-tagged implementation commit for FHIR-5417 was found on the current branch history. Historical Organization spreadsheet source from 2014/2015 did contain Organization.contact.gender, while the 2021 source rework commit 33b409a4b6 introduced the current structuredefinition-Organization.xml without that element; the active current Organization resource continues to omit it.

Additional context:
Organization is an active resource in source/fhir.ini. The current Organization.contact element is typed as ExtendedContactDetail rather than a local backbone with child elements, and the active ExtendedContactDetail datatype contains purpose, name, telecom, address, organization, and period entries with no gender element. Confluence exact Jira reference search found no FHIR-5417 minutes, and broad Zulip/Confluence searches did not reveal a conflicting later decision to reintroduce gender on Organization contact.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change because the current build-scope source already satisfies the issue: Organization.contact has no Organization.contact.gender child and its contact detail datatype has no gender field.

Recommendation:
Keep this no-change audit. Revisit only if a future Patient Administration decision intentionally adds a gender/sex-related contact-detail field to ExtendedContactDetail or a replacement Organization contact structure.
