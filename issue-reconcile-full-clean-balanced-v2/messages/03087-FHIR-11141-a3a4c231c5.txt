FHIR-11141: Audit Provenance agent delegation

Issue request:
FHIR-11141 was Published/Persuasive with Modification for the Security WG. It asked Provenance.agent to support the organization or organizational part that a user acted on behalf of by adding a Signature.onBehalfOf-like structure, and also contemplated replacing the older Provenance.agent.actor/userId shape with a Signature.who-like agent identity structure.

Initial application:
The historical GF#11141 application is visible in commit d6bec27176add2738ac0b05bd3dddcc177ab67ff. That commit changed the old Provenance spreadsheet and examples by adding Provenance.agent.who[x] and Provenance.agent.onBehalfOf[x], while marking Provenance.agent.actor, Provenance.agent.userId, and the old relatedAgent structure as deleted.

Additional context:
Provenance is active in the current build through source/fhir.ini. The current StructureDefinition no longer uses the old actor/userId model: Provenance.agent.who is the required actor Reference, and Provenance.agent.onBehalfOf is the optional delegating-authority Reference. Later Provenance cleanup, including the already-published FHIR-14370 audit/fix on the combined branch, removed stale userId-era wording rather than restoring the old elements. Direct Zulip and Confluence searches for FHIR-11141 found no conflicting community record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already preserves the issue's substantive model by pairing the acting agent with a same-agent onBehalfOf relationship, and the current signatures guidance explicitly aligns Signature.who/onBehalfOf with Provenance.agent.who/onBehalfOf.

Recommendation:
Keep this audit commit as-is. No FHIR source follow-up is needed for FHIR-11141 unless the Security WG wants a new, separate change to the current Provenance delegation semantics or target profile list.
