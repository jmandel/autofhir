FHIR-5960: Audit ContactPoint token search support

Issue request:
FHIR-5960 was a Published/Persuasive FHIR-core search issue asking that the token search type apply to ContactPoint attributes, specifically on Patient and Practitioner, with Jira comments adding Person and RelatedPerson.

Initial application:
The issue appears to have been applied by git commit f0d0e629d2c20055b8eed059c070d96ac0e1f90d, titled "Tracker #5960 Telecon Search parameter type token", which changed the telecom search parameter rows in the Patient, Practitioner, Person, and RelatedPerson spreadsheets from string to token. The current generated search-parameter bundles preserve that application as token parameters on telecom, phone, and email ContactPoint paths.

Additional context:
The current search source is in build scope as the core search page, and Patient, Practitioner, Person, and RelatedPerson are active resources in source/fhir.ini. Later issue FHIR-14237 refined the same ContactPoint token-search guidance by requiring no pipe syntax for ContactPoint, uri, and boolean tokens and by allowing server-specific ContactPoint matching behavior; current source/search.html includes that later guidance, so it does not reverse or undermine FHIR-5960.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current source/search.html lists ContactPoint as a token-search FHIR type, explains that ContactPoint token searches use only the code/value form without a system pipe, and includes ContactPoint.value in the token datatype table. Current build-generated search-parameter bundles for Patient, Practitioner, Person, and RelatedPerson define the relevant telecom/email/phone ContactPoint searches as type token.

Recommendation:
Keep this no-change audit commit as-is. A source edit would either duplicate existing normative search guidance or risk diverging from the later FHIR-14237 clarification; no follow-up is needed for FHIR-5960 in the core repository.
