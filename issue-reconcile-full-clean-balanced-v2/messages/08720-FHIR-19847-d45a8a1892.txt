FHIR-19847: Audit Device last maintenance time extension location

Issue request:
FHIR-19847 was a Published OO change request from STU3 asking to support CDA `asMaintainedEntity.effectiveTime` in FHIR by adding a Device HL7 extension for maintenance time. The final Persuasive with Modification resolution approved no core Device element and instead approved extensions for `maintenanceResponsibility` with person and organization subparts plus `lastMaintenanceTime`.

Initial application:
No Jira-tagged FHIR core source commit for FHIR-19847 was found, which is consistent with the Jira comment that there should be no core resource change. The applied source change appears in the FHIR Extension Pack: commit 0737edd33c8c1665e7cb5e2eae08e54896850e24 added `device-lastmaintenancetime` and `device-maintenanceresponsibility` for FHIR-19846, FHIR-19847, and FHIR-19848. Core retains only OID registry entries for those extension URLs.

Additional context:
Global extensions moved out of the core specification after R5 and are maintained in the FHIR Extension Pack. Later OO minutes from 2025-07-07 say the maintenance-responsibility extension should become obsolete because of DeviceAssociation, but explicitly say to keep `device-lastmaintenancetime`. Related core issue FHIR-51494 added the `maintainer` DeviceAssociation relationship code for current R6+ maintenance-responsibility modeling; it does not replace the last-maintenance-time extension.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR core source change. The requested `lastMaintenanceTime` extension source belongs to `/home/jmandel/work/fhir-extensions`, where `StructureDefinition-device-lastmaintenancetime.xml` currently defines a Device-scoped extension with a `dateTime` value. The active core build-scope files already contain Device and DeviceAssociation, and core only keeps the extension OID registration.

Recommendation:
Keep this external-repo audit commit. Do not add `device-lastmaintenancetime` back into core. Any future changes to the extension definition should be handled in the FHIR Extension Pack; R6+ core maintenance-responsibility work should continue through DeviceAssociation while preserving the separate last-maintenance-time extension unless OO decides otherwise.
