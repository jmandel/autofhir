FHIR-15676: Audit Bundle document invariants

Issue request:
FHIR-15676 was a Published/Persuasive FHIR-core change request for STU3 documents. It asked that the document date requirement and the rule that a document Bundle starts with a Composition be enforced with Bundle invariants.

Initial application:
The issue was applied in git-svn commit f0690edbf6e6d7f4b833f9c9c46ffad54696a1be, matching Jira's svn revision 14408 comment. That commit added bdl-10 for a document date and bdl-11 for a document's first resource being Composition to the Bundle spreadsheet source.

Additional context:
The current build no longer uses the old spreadsheet as the authoritative source for Bundle. Bundle is active in source/fhir.ini and source/bundle/structuredefinition-Bundle.xml now contains bdl-10 and bdl-11. The document date invariant intentionally checks Bundle.timestamp, not meta.lastUpdated, because later Published issue FHIR-22709 corrected the original bdl-10 FHIRPath from meta.lastUpdated to timestamp. The documents page also names Bundle.timestamp as the mandatory document date, so the narrative and conformance source are aligned.

AutoFHIR reconciliation:
This audit commit makes no source change. The current active Bundle StructureDefinition already enforces the two requested rules: type = 'document' implies timestamp.hasValue(), and type = 'document' implies entry.first().resource.is(Composition).

Recommendation:
Keep this audit commit as-is. FHIR-15676 is already represented correctly in the current source; further edits would either duplicate existing constraints or revert the later FHIR-22709 correction from Bundle.timestamp back to meta.lastUpdated.
