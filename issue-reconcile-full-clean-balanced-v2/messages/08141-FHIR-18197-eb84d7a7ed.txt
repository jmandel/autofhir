FHIR-18197: Audit affectsState idempotent clarification

Issue request:
FHIR-18197 was a Published/Persuasive FHIR-core OperationDefinition clarification for STU3. It asked to remove or explain the misleading RFC idempotent reference in OperationDefinition.affectsState, fix the awkward "affects state = false" definition wording, and close the malformed link/parenthesis. The approved resolution changed the definition to state directly that affectsState means whether the operation affects state and that audit-trail side effects do not count.

Initial application:
The Jira snapshot records Grahame Grieve's application note "GH#1e03edb85b". Commit 1e03edb85b changed the then-authoritative OperationDefinition spreadsheet definition from the idempotent/RFC wording to the approved direct affects-state wording, and also removed the idempotent link from source/operations.html. The spreadsheet source was later migrated into source/operationdefinition/structuredefinition-OperationDefinition.xml, preserving that applied wording.

Additional context:
Earlier related issues FHIR-13018 and FHIR-14960 explain why the element was renamed from idempotent to affectsState and how GET support is governed by affectsState plus parameter shape. Current source/fhir.ini actively includes OperationDefinition in the build. Current OperationDefinition and operations narrative source no longer describes affectsState by reference to HTTP idempotence, and later edits have refined the GET criteria without reversing the FHIR-18197 clarification. Zulip and Confluence searches found no directly relevant community record that conflicts with the Jira/source/history evidence.

AutoFHIR reconciliation:
This audit commit makes no source change because the current build-scope source already satisfies the approved clarification: OperationDefinition.affectsState has the direct definition, and the operations narrative uses affectsState directly for GET eligibility. The retained double space inside "affecting  state" mirrors the approved/applied wording and is not a semantic defect requiring an issue-reconcile source commit.

Recommendation:
Keep this no-change audit commit as-is. If a future editorial cleanup wants to normalize the double space or modernize the sentence style, handle that as ordinary editorial work rather than as necessary FHIR-18197 reconciliation.
