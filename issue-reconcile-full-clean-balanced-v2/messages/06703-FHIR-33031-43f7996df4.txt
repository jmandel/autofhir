FHIR-33031: Audit workflow reason extension migration

Issue request:
FHIR-33031 was a Published/Persuasive FHIR-core request to replace the separate workflow-reasonCode and workflow-reasonReference extensions with a single workflow-reason extension whose value is CodeableReference, matching the Request and Event pattern reason element. The resolution also called for a separate Task resource follow-up because Task still used separate reasonCode and reasonReference elements.

Initial application:
The Jira application comment cites Git 562b7ac102aa9ec7564da50d40df280a69ea735b. That commit changed source/profiles/workflow-extensions-spreadsheet.xml by deleting the workflow-reasonReference row, renaming workflow-reasonCode to workflow-reason, and changing the extension type to CodeableReference(Condition|DiagnosticReport|DocumentReference|Observation). Later core commit dd468d4f1799dd79819315b211588ef1cf4586e0 removed those workflow extension definition rows from the R5 core source as part of the extension migration.

Additional context:
The current FHIR core checkout still has source/fhir.ini actively referencing the workflow extension spreadsheet, but the spreadsheet no longer contains workflow-reason, workflow-reasonCode, or workflow-reasonReference rows. The authoritative current definitions are in the FHIR Extension Pack checkout: workflow-reason is active and uses CodeableReference, while workflow-reasonCode and workflow-reasonReference are retired/deprecated with standards-status reasons saying they were replaced by workflow-reason. FHIR-37905 is the separate Task follow-up and current core Task.reason is CodeableReference(Resource/Any). FHIR-41240 later expanded the Extension Pack workflow-reason context to Flag. FHIR-38083 was a related rendering concern for CodeableReference extension bindings, but it was retracted/no-change and does not alter this reconciliation.
