FHIR-18829: Audit Appointment and Encounter reason alignment

Issue request:
FHIR-18829 was a Published/Persuasive with Modification Patient Administration change request, raised against STU3 and applied for STU3. It asked to make Appointment and Encounter reason naming/modeling consistent by using reasonCode plus reasonReference targets for coded and referenced reasons, renaming Encounter.diagnosis.role to use, and changing the Encounter.diagnosis.condition description away from saying it was the reason the encounter takes place.

Initial application:
The Appointment side appears in adjacent Appointment history rather than in the explicit FHIR-18829 commit: commit 87ce43db92 renamed Appointment.indication usage to reasonReference, updated examples to reasonCode/reasonReference, and left reasonReference targeting Condition, Procedure, Observation, and ImmunizationRecommendation. The Encounter side was applied by commit 4d97d1578c, whose subject explicitly includes GF#18829; it changed Encounter examples from reason to reasonCode and renamed diagnosis.role to diagnosis.use in the Encounter spreadsheet/examples. The R5 CodeableReference refactor commit 7daa0d220d later merged repeating reasonCode/reasonReference pairs into reason CodeableReference elements while preserving separate reason-code and reason-reference search surfaces.

Additional context:
FHIR-16148 later redesigned Encounter.reason and Encounter.diagnosis for R5, so current Encounter.reason is a backbone element with Encounter.reason.value as the CodeableReference and Encounter.diagnosis.condition is a condition-only CodeableReference with Encounter.diagnosis.use. FHIR-19285 moved billing-related diagnosis/procedure rank concerns to Account and is already represented on the combined branch. FHIR-32130 and FHIR-48869 later added DiagnosticReport support to Encounter and Appointment reason references, and FHIR-48869 explicitly left Encounter.reason.value references as-is; both have existing combined-branch audits. ImmunizationRecommendation was removed from the current core build in commit e073fb45ec, which also removed it from Appointment.reason and Encounter.reason.value, so its absence is no longer a missing FHIR-18829 application. A stale generated-looking Appointment SVG still shows the older ImmunizationRecommendation-only target list, but the authoritative StructureDefinition source is correct and this reconciliation does not edit diagram-only artifacts.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Appointment and Encounter are active build resources in source/fhir.ini. The current Appointment.reason and Encounter.reason.value StructureDefinitions use CodeableReference for coded-or-referenced reasons and include the current valid targets. Encounter.diagnosis.condition no longer describes the encounter reason, Encounter.diagnosis.use exists, and active examples/search parameters use the current reason concept/reference paths rather than retired reasonCode/reasonReference or diagnosis.role/rank elements.

Recommendation:
Keep this no-change audit commit as-is. No core source fix is needed for FHIR-18829; any future regeneration of stale UML/SVG diagrams should be handled as a generated-artifact maintenance task rather than as a semantic source correction for this issue.
