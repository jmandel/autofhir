FHIR-15809: Audit Procedure reason search parameters

Issue request:
FHIR-15809 was Published/Persuasive for FHIR-core Procedure after an STU3 Patient Care vote. It asked to make Procedure searchable by the associated condition, symptom, or diagnosis by adding search parameters for reasonCode and reasonReference.

Initial application:
The issue was applied in git-svn commit 722ed5c93f4bc9828e96f0f5b476bedc3486fb92, whose message explicitly says GF#15809 added Procedure search parameters for reasonCode and reasonReference. That commit added reason-code and reason-reference rows to the old Procedure spreadsheet using Procedure.reasonCode and Procedure.reasonReference. Later source refactors, including the bundled search-parameter source introduced in 2021, carried the search parameters forward.

Additional context:
The current Procedure resource is active in source/fhir.ini. Since R5/R6, the former Procedure.reasonCode and Procedure.reasonReference elements are represented as CodeableReference parts under Procedure.reason, and source/fhir.ini records the migration to reason.concept and reason.reference. The current source therefore exposes reason-code as a token search over Procedure.reason.concept and reason-reference as a reference search over Procedure.reason.reference. Related Procedure reason guidance issues FHIR-13974 and FHIR-16346 explain when to use coded versus referenced reasons; FHIR-16346 already has its own audit commit on the combined branch and does not require another decision here.

AutoFHIR reconciliation:
No source change was made. The active current-source search parameter bundle already contains the two requested Procedure reason search parameters, updated to the current CodeableReference representation.

Recommendation:
Keep this empty audit commit as-is. No FHIR-core follow-up is needed for FHIR-15809 unless a work group separately decides to add historical aliases or change current Procedure.reason search behavior.
