Issue request:
FHIR-28342 was a Published, Persuasive FHIR-I change request asking to extend the FHIR NPM package.json metadata with a jurisdiction property, using ISO code systems, and noting that IG package jurisdiction should align with the ImplementationGuide resource jurisdiction.

Initial application:
No FHIR-core source commit explicitly mentions FHIR-28342. The Jira comment says it was applied to the Confluence NPM Package Specification in June 2021. The current core source application appears in c9186a64e1, which added source/packages.html with a package.json jurisdiction row and an example value of urn:iso:std:iso:3166#US; later source history retained that property and updated its ValueSet link.

Additional context:
source/packages.html is in the current build navigation and is linked from ImplementationGuide notes, so it is the active core source for FHIR package metadata guidance. The current Confluence NPM Package Specification page points readers to the core packages page and still records the broader historical manifest-to-ImplementationGuide mapping. The later Applied/Persuasive with Modification FHIR-31583 decision, already reconciled on the combined branch, concluded that package/IG jurisdiction warning and matching behavior belongs in IG Publisher discretion/documentation rather than as a firm core specification rule.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The active core package page already defines package.json jurisdiction with {system}#{code} syntax from the Jurisdiction ValueSet and includes an ISO 3166 example. Adding the stricter IG Publisher jurisdiction-matching heuristic to core would go beyond the seed's preserved core application and conflict with the later FHIR-31583 scope decision.

Recommendation:
Keep this no-change audit. The current core source satisfies the package.json jurisdiction metadata addition; any remaining tool-specific expectations about deriving or validating package jurisdiction against ImplementationGuide.jurisdiction should stay with IG Publisher or package registry documentation.
