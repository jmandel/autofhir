FHIR-13124: Audit Questionnaire summary flag correction

Issue request:
FHIR-13124 was a Published/Persuasive DSTU2 FHIR-core change request for Questionnaire where Questionnaire.item was not part of the summary but Questionnaire.item.enableWhen, and nearby item children, were marked summary. The accepted resolution was to remove isSummary from enableWhen and improve tooling so descendants are not summary when their ancestors are not; modifier summary checks only apply when ancestors are also summary.

Initial application:
Jira records svn revision 11889. In git-svn commit 1ec4a66a17506fa38537e6e2d18b67406ed97362, that revision added a temporary Search _summary STU note warning that some elements were marked summary while their parents were not and that the definitions would be resolved for Release 4. The source flag correction appears in same-family commit 0ad99fb844c59d64bf782e85eec2e491813f84c5, which removed Summary=Y from Questionnaire.item.code, Questionnaire.item.text, and Questionnaire.item.enableWhen and added summary consistency validation for required elements under summary parents.

Additional context:
The current build-scope authority, source/fhir.ini, lists Questionnaire as an active resource. Current source/questionnaire/structuredefinition-Questionnaire.xml leaves Questionnaire.item outside summary and has no isSummary on any Questionnaire.item descendants, including enableWhen. The companion FHIR-13125 audit commit already on the combined branch checked the related required-child-under-summary-parent rule and cited FHIR-13124 as same-change-family background. A 2018 summary clarification commit removed the temporary open-issues STU note, leaving no stale current-spec warning for this issue family.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative Questionnaire StructureDefinition already reflects the accepted FHIR-13124 result, and a current active-resource XML scan found zero elements marked summary when their immediate non-root parent is not summary.

Recommendation:
Keep this audit commit as-is. No core FHIR source follow-up is needed for FHIR-13124 unless future publisher/tooling changes reintroduce a summary-descendant consistency gap; do not duplicate the already-published FHIR-13125 audit.
