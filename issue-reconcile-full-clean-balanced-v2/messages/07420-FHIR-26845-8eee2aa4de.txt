FHIR-26845: Audit conditional create Location headers

Issue request:
FHIR-26845 was Published/Persuasive for R5 and asked the FHIR-core HTTP conditional create section to state that, for either the "No matches" or "One Match" outcome, the server SHALL populate the response Location header. The Jira comment records that this had already been applied with FHIR-31965.

Initial application:
No Jira-tagged source commit for FHIR-26845 was found. The overlapping FHIR-31965 request was applied by f9b3cf00eec480a65fa6963c978a330ce2d57946, which updated source/http.html so the conditional-create "One Match" outcome returns 200 OK with headers and body populated as if a create had occurred. The current source/http.html also already states that the "No matches" outcome SHALL return a Location header when a resource is created.

Additional context:
source/hierarchy.xml includes source/http.html as the active RESTful API page, and FHIR-31965 is the same conditional-create response-metadata family explicitly cited by the FHIR-26845 Jira comment. The combined branch already contains fb1b37f11fcf4e918578390e1d2c3b10282fffc3 for FHIR-31965, which fixed the related transaction response example, so this audit must not duplicate that related issue's source-changing reconciliation. FHIR-I Confluence minutes confirm the FHIR-26845 and FHIR-31965 votes, and the implementers Zulip discussion for FHIR-31965 supports returning Location and related metadata on a one-match conditional create.

AutoFHIR reconciliation:
Made no source change. The current active HTTP narrative satisfies FHIR-26845: "No matches" requires a Location header for the created resource, and "One Match" requires create-like headers/body, which incorporates the Location requirement from the create interaction.

Recommendation:
Keep this empty audit commit as the FHIR-26845 reconciliation. No additional core source change is recommended unless the work group later wants a redundant explicit "Location" sentence in the one-match bullet; that would be editorial rather than necessary for the current published decision.
