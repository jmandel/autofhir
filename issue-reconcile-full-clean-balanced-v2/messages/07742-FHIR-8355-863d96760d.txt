FHIR-8355: Audit ordinal value decimal application

Issue request:
FHIR-8355 is a Published/Persuasive FHIR-core ValueSet issue raised for DSTU1. It asked that the ordinal value extension use a decimal rather than an integer because some survey instruments, including PROMIS and F-Score instruments, use fractional scores.

Initial application:
The Jira comment records svn revision 5888, and the migrated git commit e8c52f3a3682cb3dcbbc5b287c3949f7a201533f is the matching application: it changed the old source/valueset/valueset-extensions-spreadsheet.xml ordinalValue row from integer to decimal. That old spreadsheet is no longer present in the current core source.

Additional context:
Current core build configuration has active ValueSet and CodeSystem resources and active extension profile spreadsheets, but not the old ValueSet extension spreadsheet. The ordinalValue definition has moved to the FHIR Extension Pack as a retired/deprecated extension whose Extension.value[x] type is decimal, and the active replacement itemWeight extension is also decimal. Later core issues in the same change family renamed ordinalValue to itemWeight (FHIR-24672) and added the core concept property itemWeight with decimal datatype while removing itemWeight extension contexts from terminology resources (FHIR-33540, already represented on the combined branch).

AutoFHIR reconciliation:
This is an empty audit commit. No current core source change is needed because the original integer-to-decimal change was applied historically, the moved Extension Pack definitions are decimal, and the current core replacement concept property is decimal.

Recommendation:
Keep this no-change audit for FHIR-8355. Do not reintroduce the old core ValueSet extension source; any separate cleanup of remaining ordinalValue naming references should be considered under the later rename/change-family issues rather than this type-change issue.
