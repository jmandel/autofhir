FHIR-46238: Align MeasureReport score model metadata

Issue request:
FHIR-46238 was an Applied/Persuasive CQI R6 change request asking to allow boolean values on MeasureReport measureScore elements because attestation-style measures need boolean scores. The accepted resolution was to allow boolean as a possible type in the MeasureReport measureScore elements.

Initial application:
The Jira comment identifies commit da71fb39ce81cab9f55b3210115d4e41ab6bf077 and PR HL7/fhir#3314. That commit added boolean to both authoritative MeasureReport StructureDefinition elements, MeasureReport.group.measureScore[x] and MeasureReport.group.stratifier.stratum.measureScore[x], but it did not update the active FHIR model-definition Library metadata that still exposed both model properties as FHIR.Quantity only.

Additional context:
source/fhir.ini keeps both MeasureReport and Library active in the current build. The Library examples page links library-fhir-model-definition-content.xml as the FHIR model information file used by the CQL-to-ELM translator, and recent reconciliation commits in this run have treated this model-definition content and its embedded Library attachment as active source metadata that must stay aligned with resource changes. Jira and community searches found no later core decision reversing the boolean score change; the only broad Zulip hit was a DEQM invariant discussion that assumes boolean attestation MeasureReport examples are legitimate and belongs to a separate IG/FHIRPath issue path.

AutoFHIR reconciliation:
This commit updates source/library/library-fhir-model-definition-content.xml so both MeasureReport.Stratum.measureScore and MeasureReport.Group.measureScore use a ChoiceTypeSpecifier matching the current StructureDefinition types: Quantity, dateTime, CodeableConcept, Period, Range, Duration, boolean, and Ratio. It also refreshes the embedded base64 attachment in source/library/library-fhir-model-definition.xml so the Library resource and the linked raw modelinfo content remain byte-for-byte consistent.

Recommendation:
Keep this commit as-is. The authoritative MeasureReport StructureDefinition was already correct, and this narrow follow-up fixes the remaining active model metadata surface needed for CQL consumers without changing unrelated examples or MeasureReport semantics.
