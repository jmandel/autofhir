FHIR-15567: Align Observation DAR example code

Issue request:
FHIR-15567 was Published with a Persuasive with Modification resolution for STU3. It requested data-absent-reason code, definition, hierarchy, mapping, and value set updates: readable FHIR codes, corrected floating-point error definitions and hierarchy, removal of inaccurate mappings for error/not-performed concepts, removal of the redundant observation-valueabsentreason value set, and bindings to the core data-absent-reason value set, with NaN/PINF/NINF retained parenthetically in displays.

Initial application:
The issue was pre-applied before this reconciliation. Git history shows GF#15567 commits 2ebdf2bb94, dee72c96d2, and d06b52856c updating the data-absent-reason code list, deleting source/observation/valueset-observation-valueabsentreason.xml, replacing Observation bindings with data-absent-reason, and adding the parenthetical display abbreviations. Current source already has source/terminologies/valueset-data-absent-reason.xml including the THO CodeSystem and Observation.dataAbsentReason/component.dataAbsentReason bound to http://hl7.org/fhir/ValueSet/data-absent-reason. However, active Observation narrative still had a JSON example using the obsolete code "NaN" and display "Not a Number".

Additional context:
The current THO CodeSystem data-absent-reason defines not-a-number under error with display "Not a Number (NaN)", alongside negative-infinity and positive-infinity under error with NINF/PINF parenthetical displays. A 2018 Zulip community-consultation announcement for GF#15567, GF#13521, and GF#10556 confirmed the intended breaking change from NAN to not-a-number; the nearby FHIR-13066 reference in Jira was a mistaken issue-number mention and is unrelated Location.mode work.

AutoFHIR reconciliation:
This commit updates source/observation/observation-notes.xml, an Observation resource page source in the active source/fhir.ini Observation resource folder, so the narrative guidance and JSON example use code "not-a-number" and display "Not a Number (NaN)". No terminology source or binding edits were needed because the authoritative ValueSet binding and external THO CodeSystem are already correct.

Recommendation:
Keep this source fix. It removes a current rendered-page contradiction with the published data-absent-reason code system without broadening the issue scope; normal publication generation should carry the corrected example into generated pages.
