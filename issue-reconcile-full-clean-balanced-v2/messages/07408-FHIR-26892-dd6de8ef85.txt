FHIR-26892: Audit ElementDefinition binding target invariant

Issue request:
FHIR-26892 was Published with resolution Persuasive. It asked that ElementDefinition.binding not be allowed to carry only a strength with no binding target, because binding.valueSet and binding.description were optional and a binding with neither target was meaningless. The Jira discussion clarified that differential-only binding changes were a concern, while the final FHIR-I resolution approved proposing the substantive normative ElementDefinition rule at Error strength unless ballot feedback required best-practice treatment.

Initial application:
The current source history shows two relevant applications. The StructureDefinition source already carried snapshot-scoped sdf-10, requiring StructureDefinition.snapshot.element binding to have either valueSet or description, in the 2021 source rework/R4B history. Commit 8c5984683a, titled FHIR-26892, then added the Error invariant to source/datatypes/elementdefinition.xml as ElementDefinition.binding invariant 23 with expression description.exists() or valueSet.exists(); that commit is contained in v5.0.0.

Additional context:
The original Zulip thread and Jira comment noted that a differential can validly change only binding.strength and inherit the valueSet/description into the generated snapshot. Current source preserves the StructureDefinition snapshot-specific sdf-10 and does not add sdf-10 to StructureDefinition.differential.element. Later FHIR-48325 did not remove the FHIR-26892 target rule; it added descriptive binding strength and an invariant that descriptive bindings omit valueSet, with an already-published reconciliation commit on the combined branch. FHIR-26883 was the motivating RiskAssessment example, but it is a separate CDS issue and not decided here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. source/fhir.ini marks ElementDefinition as normative and StructureDefinition as an active resource, and the current authoritative source already enforces the FHIR-26892 rule through ElementDefinition.binding invariant 23 plus snapshot-scoped StructureDefinition sdf-10. Removing or narrowing the normative ElementDefinition invariant to handle differential-only binding-strength deltas would change published R5/R6 conformance behavior and needs an explicit later work-group decision, not an issue-reconcile edit for this published issue.

Recommendation:
Keep this audit commit as-is. If implementer or tooling feedback shows that eld-23 should not apply to differentials, raise a new focused FHIR-I issue to decide whether to move the rule exclusively to StructureDefinition.snapshot.element or otherwise express a context-sensitive exception.
