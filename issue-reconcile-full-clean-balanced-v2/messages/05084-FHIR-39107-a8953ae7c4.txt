FHIR-39107: Audit search mode declaration extension location

Issue request:
FHIR-39107 was Published with a Not Persuasive with Modification resolution. The ballot request asked to mandate both GET and POST search support and remove the practical 405 fallback; the approved resolution instead called for a 0..1 code extension on CapabilityStatement.rest and CapabilityStatement.rest.resource to declare GET, POST, or BOTH search-mode support until CapabilityStatement2 handles the topic.

Initial application:
No FHIR-core commit explicitly tagged FHIR-39107 was found. The source implementation trail is in the FHIR Extension Pack: commit 4beef02fa74740a3d4daf3c22b7d46bd0781df65 added capabilitystatement-search-mode StructureDefinition and terminology artifacts, and later extension-pack cleanup commits adjusted OIDs, value set binding, status metadata, and the FHIR-44374 punctuation correction.

Additional context:
The current core checkout does not contain an active StructureDefinition source for capabilitystatement-search-mode; it only has OID registrations for that canonical. Current core HTTP/search prose still defines search over both GET and POST and allows HTTP 405 for either method but not both. FHIR-I minutes confirm the work group chose an extension rather than mandating both methods. The available Extension Pack definition covers the current declared-search-mode concept, though any exact alignment questions about the Jira's requested rest-level context or comment text belong in the Extension Pack, not this core checkout.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The requested artifact is maintained outside the FHIR-core source tree in HL7/fhir-extensions, and no current core source hunk is needed to make the core build internally consistent.

Recommendation:
Keep this external-repo audit commit for the core reconciliation. If the work group wants the extension to exactly mirror FHIR-39107's original wording for CapabilityStatement.rest scope, the absent-value comment, or uppercase BOTH, handle that as Extension Pack follow-up rather than a core-source edit.
