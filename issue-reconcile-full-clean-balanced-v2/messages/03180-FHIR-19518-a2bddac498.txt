Issue request:
FHIR-19518 was Published/Persuasive with Modification for STU3 CDS workflow alignment. It requested changing the CDS resources' `context` element to `encounter`, restricting it to `Reference(Encounter)`, and not adding the proposed `reported[x]` element because the work group disagreed that GuidanceResponse should support it.

Initial application:
The Jira comments cite `8c6fae38c1` for GuidanceResponse and `9eac103eb6` for RequestGroup and RiskAssessment. Those commits renamed or retained the active encounter elements and restricted the relevant CDS resources to Encounter references; current source still carries `GuidanceResponse.encounter`, `RiskAssessment.encounter`, and the RequestGroup successor `RequestOrchestration.encounter` as `0..1 Reference(Encounter)`.

Additional context:
The current build scope includes GuidanceResponse, RiskAssessment, and RequestOrchestration in `source/fhir.ini`. RequestGroup was later renamed to RequestOrchestration by FHIR-24619, so the current source location is the successor resource. RiskAssessment's local encounter wording is also supported by the earlier FHIR-7868 decision to describe it as the encounter where the assessment was performed. Negative Zulip and Confluence searches found no community record that conflicts with the Jira/source/git conclusion.

The remaining wording differences are either local resource wording or later resource-renaming context, not a semantic failure to apply FHIR-19518.

Recommendation:
