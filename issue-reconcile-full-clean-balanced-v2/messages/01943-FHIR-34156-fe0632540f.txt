FHIR-34156: Audit Patient.link.other definition

Issue request:
FHIR-34156 was a Published/Persuasive PA change request for R5 Patient. It reported that Patient.link.other had a short description including a RelatedPerson target, while the definition still said only "The other patient resource that the link refers to." The approved resolution was to update the definition to "Link to a Patient or RelatedPerson resource that concerns the same actual individual."

Initial application:
The change was already applied in source by git commit 00eacab651795cde741170aa227fe10d72b761d6, which replaced the Patient.link.other definition in source/patient/structuredefinition-Patient.xml with the approved Patient-or-RelatedPerson wording. Patient is an active resource in source/fhir.ini, so this StructureDefinition source is in the current build scope.

Additional context:
The wording sits in a Patient.link family that was built up by earlier Published issues FHIR-23009 and FHIR-32874, which made Patient.link inclusive of RelatedPerson, and by later issue FHIR-34329, which replaced "person" with "individual" and is already represented on the combined reconciliation branch. The PA 2022-04-13 minutes record the FHIR-34156 persuasive vote. A later Zulip discussion led to FHIR-41559 clarifying RelatedPerson rather than reversing the Patient.link wording.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/patient/structuredefinition-Patient.xml has Patient.link.other.definition exactly as approved, keeps the short description inclusive of RelatedPerson, and declares both Patient and RelatedPerson as target profiles.

Recommendation:
Keep this audit commit as-is. No further core source work is needed for FHIR-34156 unless a future PA decision changes the Patient.link/RelatedPerson model.
