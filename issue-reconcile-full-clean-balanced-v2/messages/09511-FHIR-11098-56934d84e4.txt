FHIR-11098: Audit Task.restriction clarification

Issue request:
FHIR-11098 was a Published FHIR-core Task change request, resolved Persuasive with Modification for DSTU2. It asked to clarify the confusing Task.fulfillment element and the final resolution was to rename Task.fulfillment to Task.restriction and define it as restrictions on fulfillment of the request referenced by the Task.

Initial application:
The issue appears to have been applied by git commit 839bf586d6c1cf9a322e122852f0cc49bcfed263, whose workflow batch message explicitly includes {#11098}. That commit changed the Task spreadsheet source from Task.fulfillment, Task.fulfillment.repetitions, Task.fulfillment.period, and Task.fulfillment.recipients to Task.restriction, Task.restriction.repetitions, Task.restriction.period, and Task.restriction.recipient, and replaced the parent definition with text explaining that the element identifies limitations on what parts of the referenced request should be actioned.

Additional context:
Task is an active current-build resource in source/fhir.ini. The source was later refactored from spreadsheet input to source/task/structuredefinition-Task.xml. Later published Task decisions, especially FHIR-31900 and FHIR-34136, refined the same area by adding an invariant/usage note for Task.restriction and distinguishing Task.requestedPeriod from Task.restriction.period. Those later changes reinforce, rather than contradict, the FHIR-11098 rename and clarification.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/task/structuredefinition-Task.xml no longer contains Task.fulfillment, defines Task.restriction with the FHIR-11098 requested request-fulfillment wording, includes a usage comment saying the element is only for fulfillment of a request resource, and carries the later invariant limiting restriction to fulfill Tasks with a focus Reference.

Recommendation:
Keep this no-change audit commit as-is. No follow-up source work is needed for FHIR-11098 in the current FHIR core build; any future Task.restriction changes should be evaluated under newer Task issues rather than this DSTU2 rename clarification.
