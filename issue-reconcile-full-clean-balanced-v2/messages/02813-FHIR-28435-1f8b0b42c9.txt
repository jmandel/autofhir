FHIR-28435: Audit packaged product recursion target

Issue request:
FHIR-28435 was a Published FHIR-core BR&R change request, resolved Persuasive for R5, asking to add PackagedProductDefinition to the PackagedProductDefinition.package.containedItem.item list so identified packages can recursively contain a full packaged-product resource while retaining the lighter-weight approach.

Initial application:
The issue was explicitly applied before this reconciliation in git 0ee3e67a82, whose message includes "add package as package item FHIR#28435". That commit changed the then-spreadsheet source for PackagedProductDefinition.package.containedItem.item from Reference(ManufacturedItemDefinition|DeviceDefinition|BiologicallyDerivedProduct|NutritionProduct) to CodeableReference(ManufacturedItemDefinition|DeviceDefinition|PackagedProductDefinition|BiologicallyDerivedProduct|NutritionProduct) and added the matching package search parameter. Later source regeneration carried the target into the current StructureDefinition XML.

Additional context:
FHIR-29692 later renamed the backbone from package to packaging, so the current element path is PackagedProductDefinition.packaging.containedItem.item. FHIR-28584 was applied in the same commit family and is already represented on the combined branch as a no-change audit that cites FHIR-28435. FHIR-31805 is also already represented on the combined branch and preserved the package-of-packages guidance for when the recursive PackagedProductDefinition route should be used.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current source defines PackagedProductDefinition.packaging.containedItem.item as CodeableReference with a PackagedProductDefinition targetProfile, its definition explains that another whole packaged product can be included for wholesale/distribution package-of-packages cases, and the PackagedProductDefinition-package search parameter points to the item.reference expression. CodeableReference also preserves the requested lightweight option through its concept arm.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-28435 unless BR&R opens a later issue to change the package-of-packages modeling; the current source already implements the published request and later path-name/guidance decisions.
