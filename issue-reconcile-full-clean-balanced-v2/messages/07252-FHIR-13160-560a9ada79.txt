FHIR-13160: Audit ServiceRequest diagnostic wording

Issue request:
FHIR-13160 was Published with resolution Persuasive for STU3. It asked OO to remove DiagnosticRequest-specific wording from ProcedureRequest element descriptions, specifically changing performer wording from diagnostic testing to requested procedure and reason wording from diagnostic investigation to procedure.

Initial application:
The Jira-tagged STU3 application appears in git commit 7c87cdc144040f83684cc75ff4c090163d148f62, which changed the ProcedureRequest spreadsheet definitions for occurrence, performerType, performer, reasonCode, and reasonReference from diagnostic testing/investigation wording to requested procedure/procedure wording. That was an appropriate application for the then-current ProcedureRequest source.

Additional context:
ProcedureRequest was later renamed and broadened to ServiceRequest by FHIR-13867, which is already represented on the combined branch. Current source/fhir.ini lists ServiceRequest as an active OO resource and keeps ProcedureRequest only as a historical merged/renamed note. Later ServiceRequest source refactors and R6 scope work, including already-represented FHIR-50610, intentionally describe diagnostics as one supported ServiceRequest use case rather than as the sole scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active ServiceRequest definitions no longer contain the stale FHIR-13160 element wording: performerType says the performer is for the requested service, and reason says it is the reason or indication for requesting the service with service-oriented comments. Remaining uses of diagnostic investigation in ServiceRequest are contextual examples or broad-scope statements, not the obsolete DiagnosticRequest-only descriptions identified by the issue.

Recommendation:
Keep this audit commit as-is. No current FHIR source fix is needed for FHIR-13160; future wording changes should be handled under a ServiceRequest-specific issue rather than re-opening this STU3 ProcedureRequest correction.
