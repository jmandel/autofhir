FHIR-17272: Audit MeasureReport data-exchange report type

Issue request:
FHIR-17272 was a Published/Persuasive CQI change request for STU3 asking to add a data-collection MeasureReport type, explain that MeasureReport can communicate only data of interest for a measure, support incremental retrieval of data of interest, and discuss this usage in the MeasureReport scope.

Initial application:
The issue was originally applied in SVN 14063, imported as git commit 1ce7bae0e8d4457eb17aa85c120f207893e9c1fb, whose message explicitly says GF#17272 added the data-collection type to MeasureReport. That same application also handled paired Measure/MeasureReport quality-reporting work, including GF#17274 for $collect-data.

Additional context:
Later final CQI decisions intentionally changed the current surface. FHIR-20509 renamed the report type from data-collection to data-exchange for R5, and that issue is already represented on the combined branch. FHIR-17274, the paired collect-data operation issue, is also already represented on the combined branch. Later FHIR-49824/FHIR-49821 context added or confirmed the current Scope and Usage language describing data-exchange reports as communicating data of interest with no scoring or other calculated information expected.

AutoFHIR reconciliation:
This commit makes no source change. MeasureReport and Measure are active resources in source/fhir.ini. Current MeasureReport source defines the data-exchange type code for data of interest, constrains data-exchange reports not to include group/score information, documents the data-exchange use case in Scope and Usage, and defines evaluatedResource/dataUpdateType text for data-of-interest exchange. Current Measure $collect-data source documents lastReceivedOn incremental data collection and Bundle responses whose first entries are data-exchange MeasureReports followed by data-of-interest resources. Differences from the literal 2018 data-collection wording are explained by later approved decisions.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-17272 unless CQI opens a new issue to revisit the later data-exchange terminology or the current DEQM-aligned collect-data operation behavior.
