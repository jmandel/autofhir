FHIR-16934: Audit conformance defaultValue removal

Issue request:
FHIR-16934 was a Published FHIR-core/fhir-i STU3 change request for the conformance rules page. It noted that the Other Metadata list still paired defaultValue with meaningWhenMissing and asked to remove defaultValue as no longer supported; the final resolution first said to clarify that defaultValue is supported but never used by FHIR, and the later Jira comment directed removal of the defaultValue reference from the FHIR element conformance text.

Initial application:
The issue was applied by git-svn commit c5c82e6e906a4fc520ad9c2b651c038dca80a3b5, "GF#16934 - remove defaultValue reference", with git-svn-id build@14211. That commit changed source/conformance-rules.html from "defaultValue / meaningWhenMissing" to "meaningWhenMissing", matching the Jira comment.

Additional context:
The current source/conformance-rules.html is a built conformance narrative page linked from source/conformance-module.html. Its Other Metadata section lists isSummary, meaningWhenMissing, and maxLength, with no defaultValue reference. The current StructureDefinition source still models defaultValue as an ElementDefinition feature while constraining HL7 FHIR specification models to have no default values and allowing defaultValue only on specializations, preserving the distinction in the Jira resolution.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current conformance rules page already reflects the applied issue by omitting defaultValue from the FHIR element metadata list, while nearby StructureDefinition rules carry the remaining "supported but not used by FHIR models" semantics.

Recommendation:
Keep this no-change audit commit as-is. No follow-up source edit is needed unless a future work group decision changes the current ElementDefinition defaultValue policy.
