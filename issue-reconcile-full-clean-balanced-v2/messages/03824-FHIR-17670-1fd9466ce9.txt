FHIR-17670: Audit administrative gender v2 mapping

Issue request:
FHIR-17670 was a Published/Persuasive with Modification PA change request for the STU3 Patient-related AdministrativeGender value set. It reported that FHIR AdministrativeGender code other should map to both v2 table 0001 A (Ambiguous) and O (Other), but the STU3 rendering only showed A.

Initial application:
The Jira comment records svn revision 14803. In git history this is commit 879b2dcd6165efa6d784f86d0e3b3523a461abc3, a tooling/rendering change touching ConceptMap narrative generation and related publisher code rather than the administrative-gender binding row. The binding spreadsheet already carried both v2 targets as >0001.A and >0001.O, and the issue was about the tooling/rendering surfacing both targets.

Additional context:
The closely related FHIR-16189 thread and Jira comments discuss duplicate administrative-gender ConceptMap rendering and the same missing second v2 target. Current source/fhir.ini keeps Patient active, and source/terminologies/bindings.xml is the build input for the AdministrativeGender binding/mapping data. Later rendering/comment cleanups have not removed either v2 target.

AutoFHIR reconciliation:
No source change was made. The current combined-branch source row for AdministrativeGender other maps to both >0001.A and >0001.O, with explanatory ConceptMap relationship comments, and the current build renders both v2 links in the AdministrativeGender value set table.

Recommendation:
Keep this audit commit as-is. FHIR-17670 is already satisfied in current core source and rendered output; further edits would be redundant and risk changing a correct terminology mapping.
