FHIR-32499: Audit allDay availability invariant

Issue request:
FHIR-32499 was a Published/Persuasive with Modification PA change request raised against R4 PractitionerRole asking why start and end times were allowed when allDay is true. The approved resolution required a new invariant preventing hour values when allDay is true on PractitionerRole, HealthcareService, and Location.

Initial application:
The issue was applied in the R5 source history by 62dbb8e5cd0536b23d6b4deb89c3f9a13f01bb37, which added the allDay/start/end invariant to the newly shared Availability.availableTime datatype, and then corrected by 3335c22c1ce8340b6211fcb1b6bd3d618313a02c so the FHIRPath expression handles absent allDay correctly. Because PractitionerRole, HealthcareService, and Location had already been migrated to the Availability datatype, the datatype-level invariant covered all three requested resource contexts.

Additional context:
The current source/fhir.ini lists Availability as an active metadatatype and lists Location, PractitionerRole, and HealthcareService as active resources. The same file maps the older R4 availability fields for HealthcareService, Location, and PractitionerRole into the current Availability-based elements. The active StructureDefinition source for all three resources uses type code Availability for the relevant availability/hours element. Later Availability work, including FHIR-41311 and the already-published FHIR-32500 reconciliation commit, did not remove or conflict with the allDay invariant.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active source already contains the required invariant on Availability.availableTime: allDay must be absent or, when true, availableStartTime and availableEndTime must be absent. Since the affected resources all use the same active Availability datatype, adding duplicate resource-specific constraints would be redundant and would risk drift.

Recommendation:
Keep this audit commit as-is. No follow-up source change is needed for FHIR-32499 unless the work group later decides that the invariant should move from the shared datatype to resource-specific profiles, which current source and history do not support.
