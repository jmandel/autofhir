FHIR-33540: Audit itemWeight expansion property application

Issue request:
FHIR-33540 was Published with a Persuasive with Modification Vocabulary resolution for R5. The original request asked for ordinalValue/itemWeight weights from coded concepts to be visible in value set expansions. The accepted resolution changed the mechanism: remove CodeSystem.concept, ValueSet.compose.include.concept, and ValueSet.expansion.contains contexts from the itemWeight extension; state that CodeSystem and ValueSet use the defined concept property http://hl7.org/fhir/concept-properties#itemWeight; add itemWeight to the FHIR Defined Concept Properties CodeSystem with decimal type; and update the defined-properties table.

Initial application:
Core commit 3d7a100629ff78f7ad6b25489616e332ce2d6a5e added itemWeight to source/codesystem/codesystem-concept-properties.xml. A same-day adjacent core commit f43f55953f3d55407718d24c676f2471597f9deb added the itemWeight row to source/codesystem/codesystem-notes.xml. Extension Pack commit 784a10b5c83c80ad7f387b244b4eee65558ec624 removed the CodeSystem and ValueSet contexts from StructureDefinition-itemWeight and added the CodeSystem/ValueSet property guidance.

Additional context:
source/fhir.ini actively includes the CodeSystem and ValueSet resources and the concept-properties CodeSystem, so the checked source surfaces are in current build scope. Later FHIR-48428 concept-property work added explicit dataType metadata, leaving itemWeight with dataType decimal. ValueSet.$expand already has a property input parameter that can request named or URI properties, and ValueSet.expansion.contains.property carries property values in expansions. A 2026 Zulip discussion about ValueSet.compose weights confirmed the current interpretation that value-set weights are handled as a property; it raised a compose.include.concept question, but no discovered Jira or WG decision reverses FHIR-33540 or supports restoring extension contexts.

AutoFHIR reconciliation:
Made no source change. The current core source already contains concept-properties#itemWeight with decimal type, the defined-properties table includes itemWeight, ValueSet expansion supports returned properties, and the Extension Pack itemWeight definition no longer allows the removed CodeSystem/ValueSet extension contexts while pointing users to the itemWeight property.

Recommendation:
Keep this audit commit as-is. Do not restore ordinalValue/itemWeight extension contexts in core; any future desire to attach weights directly to ValueSet.compose.include.concept should be handled as a new Vocabulary/FHIR-I decision rather than as incomplete application of FHIR-33540.
