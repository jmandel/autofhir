FHIR-19000: Audit Sequence window cardinality

Issue request:
FHIR-19000 was a Published/Persuasive Clinical Genomics change request for the STU3 Sequence artifact. It asked that when referenceSeq is present, referenceSeq.windowStart and referenceSeq.windowEnd should be relaxed from 1..1 to 0..1 because lab reports can identify a reference sequence without always knowing the reference window.

Initial application:
The Jira comment cites GH#7f860bf. Local history shows implementation commit 9c23a7fb0f8197559bfa229b4beab313a017d729, merged by 7f860bf8648888c27d85c440df358f8b2b47a40f, changed source/molecularsequence/molecularsequence-spreadsheet.xml so MolecularSequence.referenceSeq.windowStart and MolecularSequence.referenceSeq.windowEnd changed from 1..1 to 0..1. Current historical release artifacts confirm the later R4 and R4B MolecularSequence definitions have both elements at 0..1; the STU3/R3 Sequence history still shows 1..1 because it preserves the prior published release surface rather than current source to edit.

Additional context:
MolecularSequence is no longer an active current-build resource in source/fhir.ini; the current active genomics resource is MolecularDefinition. Later Published work, especially FHIR-37486 and PR #2030, reframed MolecularSequence's reference sequence model toward starting-sequence/IM-aligned concepts, and the current source has since been renamed to source/moleculardefinition. Current source has no active referenceSeq, windowStart, or windowEnd elements. The coordinate interval start/end elements that now represent sequence locations or extracted/relative sequence intervals in MolecularDefinition are already optional. A 2022 genomics Zulip thread confirms the old window concept remained important but was being reconsidered as interval/location or extracted-sequence modeling, not as a requirement to restore the old mandatory fields. No Confluence references were found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The requested cardinality relaxation was applied to the then-current MolecularSequence source, the current build no longer contains the old referenceSeq.windowStart/windowEnd elements, and the active MolecularDefinition replacement does not reintroduce mandatory start/end coordinates.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for FHIR-19000 unless the Clinical Genomics work group opens a new issue about the current MolecularDefinition location/interval semantics.
