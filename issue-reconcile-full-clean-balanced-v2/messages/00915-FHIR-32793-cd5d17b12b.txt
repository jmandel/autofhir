FHIR-32793: Audit ImagingStudy procedure binding

Issue request:
FHIR-32793 was a Published/Persuasive Imaging Integration change request for R4B, applied for R5, asking that the RadLex binding on ImagingStudy.procedure.valueCodeableConcept be weakened from extensible to preferred because requiring RadLex whenever expressible forced systems to translate local procedure codes.

Initial application:
The issue was applied in git commit 52a5df179457fea03c4c8e598133c470f4e1de38, which changed the ImagingStudy procedure binding strength from extensible to preferred while also converting the old procedure backbone to a CodeableReference shape. The September 2021 Imaging Integration WGM record also notes the resolved change required action as changing the binding from extensible to preferred.

Additional context:
ImagingStudy is in the active build through source/fhir.ini. Later ImagingStudy decisions changed the model around this element: FHIR-50894 removed the CodeableReference ImagingStudy.procedure element and represented performed procedure through a Reference(Procedure), and FHIR-53025 then restored the element name ImagingStudy.procedure for that Reference(Procedure) relationship. The current source has ImagingStudy.procedure as Reference(Procedure) with no terminology binding, and the procedure search parameter is a reference search over that element.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The original too-strong RadLex binding is not present in the current built ImagingStudy source, so adding or changing a preferred binding would be stale and would contradict the later Reference(Procedure) modeling.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-32793 unless the Imaging Integration work group reintroduces a coded ImagingStudy procedure element in a future change; if that happens, this history supports using preferred rather than extensible for any RadLex/LOINC-RSNA playbook binding.
