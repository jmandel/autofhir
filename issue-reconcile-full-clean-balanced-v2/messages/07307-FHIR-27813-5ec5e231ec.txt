FHIR-27813: Audit Bundle fullUrl requirement wording

Issue request:
FHIR-27813 was a Published FHIR-core/FHIR-I change request, resolved Persuasive for R5. It asked to clarify the confusing Bundle.entry.fullUrl language by replacing the ambiguous "fullUrl can be empty on a POST" wording with request.method-specific language and by adding an opening sentence to Bundle.entry.fullUrl stating that, except for transactions and batches, each Bundle entry must have a fullUrl.

Initial application:
The issue was applied in b2642eedbe38bc90d8b2aeca1a3d7d3ddd18e40a, which changed source/bundle/bundle-notes.xml from "transaction on a POST" to "transaction when entry.request.method = POST" and added the requested opening sentence to source/bundle/structuredefinition-Bundle.xml. No prior Issue-Reconcile-Key: FHIR-27813 commit was present on the combined branch before this audit.

Additional context:
Bundle is an active resource in source/fhir.ini, so source/bundle/bundle-notes.xml and source/bundle/structuredefinition-Bundle.xml are current build inputs. The nearby fullUrl language has since been refined by related applied/published issues, especially FHIR-29803, FHIR-31354, FHIR-28364, and FHIR-43106; those later changes are already represented on the combined branch and now express the batch/transaction request-or-response exception more precisely than the original request.method=POST phrasing. Zulip and Confluence evidence show the original confusion, the 2022 reopening to provide actual replacement text, and a short September 2022 thread agreeing the then-current definition adequately addressed the issue.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative Bundle definition already says, "Except for transactions and batches, each entry in a Bundle must have a fullUrl," and its exception text has been superseded by the later FHIR-43106 wording rather than the older ambiguous POST sentence. The Bundle narrative likewise points readers to the formal Bundle.entry.fullUrl exceptions instead of restating stale POST-only rules.

Recommendation:
Keep this audit commit as-is. No FHIR-27813 source change is recommended because the seed clarification is present and later fullUrl decisions have already reconciled the adjacent exception wording.
