FHIR-17356: Align Turtle media type terminology

Issue request:
FHIR-17356 was a Published/Persuasive with Modification FHIR-core HTTP issue requesting the Turtle format media type change from text/turtle to application/fhir+turtle so the media type identifies FHIR content and can carry the fhirVersion parameter. The accepted resolution was to use application/fhir+turtle.

Initial application:
The issue was applied in svn revision 13999, mirrored as git commit 6162473437bd1f1f065688569768a5c626c68532, which changed source/http.html and source/rdf.html to make application/fhir+turtle the formal RDF/Turtle media type while continuing to accept text/turtle as a _format alias. Later CapabilityStatement format terminology introduced by FHIR-20617 reintroduced text/turtle in the ttl code definition and application/fhir+ttl in the starter value set.

Additional context:
The current HTTP and RDF narrative already state that FHIR RDF uses application/fhir+turtle, and the _format text/turtle alias remains a compatibility synonym rather than the formal media type. FHIR-48679 later moved CapabilityStatement.format's main required binding to supplemented-mimetypes and added simple-format-codes with the correct application/fhir+turtle definition, but the active fhir-format-type CodeSystem and capability-format-type starter ValueSet still carried the stale Turtle media type values.

AutoFHIR reconciliation:
Updated the active fhir-format-type ttl definition to say application/fhir+turtle and changed capability-format-type's explicit Turtle MIME code from application/fhir+ttl to application/fhir+turtle. These files are in build scope because fhir-format-type is an active [codesystems] entry in source/fhir.ini, and capability-format-type is referenced as the starter binding for CapabilityStatement.format.

Recommendation:
Keep this source fix. It aligns the remaining active CapabilityStatement terminology with the published FHIR-17356 decision and the existing HTTP/RDF narrative without removing the intentional text/turtle _format compatibility alias.
