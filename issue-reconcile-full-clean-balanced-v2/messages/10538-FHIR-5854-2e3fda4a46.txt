FHIR-5854: Audit DiagnosticOrder status codes

Issue request:
FHIR-5854 was a Published/Persuasive OO change request from DSTU1 asking to add Draft and Cancelled concepts to the DiagnosticOrder.status value set, with Draft meaning the request is preliminary before being sent and Cancelled meaning the request has been withdrawn. The resolution records the 2015-03-12 OO block vote to add both concepts and notes the change was preapplied.

Initial application:
The old DiagnosticOrder source was changed in git-svn commit cd3cbf8d9dd13675993f7872d512d8c72541c4c5, whose subject explicitly includes #5854 DiagnosticOrder. That commit added draft and cancelled to the DiagnosticOrder status short labels and to the diagnostic-order-status worksheet, including the requested definitions.

Additional context:
DiagnosticOrder is not an active current resource. FHIR-10295 later renamed request resources from Order to Request, and current source/fhir.ini lists DiagnosticOrder under removed resources with the note that it was subsumed into ServiceRequest. ServiceRequest is active in the current build and ServiceRequest.status is required-bound to ValueSet/request-status. The shared RequestStatus code system includes draft and the current termination/withdrawal concept is expressed as revoked rather than the old DiagnosticOrder literal cancelled code. Targeted Zulip and Confluence searches found no directly relevant community evidence that conflicts with the Jira, git, and source-history conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-editing removed DiagnosticOrder spreadsheet/source would not affect the current build, and changing the current normative RequestStatus vocabulary from revoked back to cancelled would be a broader later terminology decision not required by FHIR-5854.

Recommendation:
Keep this audit commit as-is. If OO wants a literal cancelled code or wording in the current shared RequestStatus value set, that should be raised and reviewed as a new current-build request-pattern terminology change rather than as residual application work for the retired DiagnosticOrder issue.
