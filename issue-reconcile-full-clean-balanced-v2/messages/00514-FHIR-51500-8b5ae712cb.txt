FHIR-51500: Audit Device type search expression

Issue request:
FHIR-51500 was an Applied/Persuasive OO change request for R6 asking to review the Device type search parameter and remove the expensive Device.definition.resolve().classification.type clause from the Device-type expression.

Initial application:
The issue was applied before this reconciliation in commit d304eb5317bd3162289cd96cac52484f37014390, which changed source/device/bundle-Device-search-params.xml so the SearchParameter with id/code Device-type uses only Device.type. No Jira-tagged reconciliation commit already existed on the combined branch.

Additional context:
FHIR-40397 had earlier added the Device.definition resolve path to both the type search parameter and the separate code search parameter. FHIR-51500 narrowed only Device-type, and the current source still preserves the separate Device-definition-code/code parameter as FHIR-40397 context rather than as part of this seed. Device is an active resource in source/fhir.ini, so source/device/bundle-Device-search-params.xml is in current build scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change because the active Device-type search parameter already has expression Device.type, matching the applied Jira decision. Adding redundant narrative or changing the separate code parameter would exceed the FHIR-51500 decision.

Recommendation:
Keep this audit commit as-is. If the work group later wants to remove Device.definition.resolve() from the separate Device code search parameter, handle that as a distinct FHIR-40397-family decision rather than through FHIR-51500.
