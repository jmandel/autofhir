FHIR-37622: Audit SearchParameter comparator constraint

Issue request:
FHIR-37622 was Published/Persuasive for R5 and asked FHIR-core SearchParameter to prohibit SearchParameter.comparator unless SearchParameter.type is number, date, quantity, or special, because comparators on string/token parameters create ambiguous query strings.

Initial application:
The issue was applied by HL7/fhir PR #2138. Commit a3559a4a0773e71e3310a7671c084e72bedcf1e9 added invariant spd-3 to source/searchparameter/structuredefinition-SearchParameter.xml, and merge commit 49ad1d9e6f8418767d40a0e63db6bc18786e2730 brought that change into the main history.

Additional context:
SearchParameter is an active core resource in source/fhir.ini, and the current source still contains spd-3 with SearchParameter.comparator conditioned on that invariant. FHIR-I minutes record the 2022-07-18 vote to limit comparators to number, date, quantity, and special. The originating Zulip thread confirms the ambiguity for token/string searches and led to a separate Da Vinci Drug Formulary IG cleanup, FHIR-37623, which is outside this core checkout.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change because the current build-scope SearchParameter StructureDefinition already enforces the requested rule: comparator.empty() or type in ('number' | 'date' | 'quantity' | 'special'), and the comparator element declares condition spd-3.

Recommendation:
Keep this no-change audit commit. No core source follow-up is needed for FHIR-37622 unless a future work group decision changes which SearchParameter.type codes may carry comparators.
