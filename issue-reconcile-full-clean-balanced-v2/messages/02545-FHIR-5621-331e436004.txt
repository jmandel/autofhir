FHIR-5621: Audit Composition confidentiality replacement

Issue request:
FHIR-5621 was a Published Structured Documents change request for DSTU1. It asked why Composition.confidentiality was Coding rather than CodeableConcept; the accepted SDWG disposition went the opposite direction, voting on 2015-03-17 to make the element a primitive code and provide a clinical document extension for alternate confidentiality coding systems.

Initial application:
The issue was initially applied in SVN revision 4660, imported as git commit 90a18571ed32b65db8e46fe83cb470e5347810ac. That commit explicitly mentioned "#5621 - narrow confidentiality to a code", changed the Composition spreadsheet row from Coding to code, and updated examples to use a primitive confidentiality value.

Additional context:
Later final decisions superseded the DSTU1 element shape. FHIR-17301 was Published for R5 with a resolution to remove Composition.confidentiality and record a Clinical Document's confidentiality on the document Bundle's meta.security. Current core source matches that state: Composition is an active resource, source/fhir.ini records Composition.confidentiality as removed, the StructureDefinition and search parameter bundle no longer define Composition.confidentiality, the Composition CDA note maps ClinicalDocument.confidentialityCode to Bundle.meta.security, and document Bundle examples carry v3 Confidentiality in Bundle.meta.security. FHIR-37719 then removed the otherConfidentiality extension because that content also belongs in Composition.meta.security or Bundle.meta.security; the Extension Pack now retains the old extension only as retired/deprecated with the reason "Use Bundle.meta.security instead." A Zulip implementers thread from 2019 reached the same direction and pointed back to FHIR-17301.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current specification is correct for FHIR-5621 when the later R5 removal and extension decisions are considered; reintroducing or changing Composition.confidentiality, or reviving the alternate-code extension in core, would contradict those later final decisions.

Recommendation:
Keep this no-change audit commit as-is. No current core FHIR source follow-up is recommended for FHIR-5621; any future reconsideration should be raised against the later Bundle.meta.security/extension-policy decisions rather than the original DSTU1 Coding-to-code change.
