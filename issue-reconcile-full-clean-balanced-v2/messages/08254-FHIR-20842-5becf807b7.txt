FHIR-20842: Align dependent parameter ModelInfo

Issue request:
FHIR-20842 was Published/Persuasive for FHIR-core StructureMap and asked that dependent rule variables stop being a string-only StructureMap.group.rule.dependent.variable. The final resolution changed the element to StructureMap.group.rule.dependent.parameter and reused the backbone element defined by StructureMap.group.rule.target.parameter.

Initial application:
Git commit 375c99bc97f04b8f1e12662b3f552a9193015dd6 applied the issue to source/structuremap/structuredefinition-StructureMap.xml by renaming dependent.variable to dependent.parameter and replacing the string type with a contentReference to StructureMap.group.rule.target.parameter. No matching FHIR-20842 application was found for the active FHIR ModelInfo library, which still exposed StructureMap.Dependent.variable as a list of FHIR.string.

Additional context:
StructureMap is active in source/fhir.ini, and the Library examples are also active current-build content. source/library/library-fhir-model-definition.xml and list-Library-examples.xml publish Library/FHIR-ModelInfo, whose XML attachment is source/library/library-fhir-model-definition-content.xml. That ModelInfo surface should describe the same current StructureMap model as the authoritative StructureMap XML. FHIR-20844 is tightly related because it concerns the target.parameter backbone now reused by dependent.parameter, but it is already represented on the combined branch by commit 014f84d9853469f06a846d9e027ad8bce4d2ebfd and is not duplicated here.

AutoFHIR reconciliation:
This commit updates source/library/library-fhir-model-definition-content.xml so StructureMap.Dependent has parameter: List<FHIR.StructureMap.Parameter> instead of variable: List<FHIR.string>. No StructureMap XML or mapping-language narrative edit was needed because the authoritative resource definition already contains dependent.parameter with the required contentReference.

Recommendation:
Keep this source fix. It completes the FHIR-20842 application across the active ModelInfo publication surface while preserving the already-correct StructureMap resource definition. If the separate FHIR-20844 audit is revisited later, assess StructureMap.Parameter's own value[x] choices under that issue rather than duplicating it here.
