FHIR-25556: Audit AdverseEvent outcome binding

Issue request:
FHIR-25556 was a Published Patient Care change request, resolved Persuasive with Modification for R5, asking that AdverseEvent.outcome stop using the overly strict preferred binding to the NCI UMLS value set and instead use an example binding to SNOMED CT adverse incident outcome categories under SCTID 405533003.

Initial application:
The issue was applied by c31023666df8a405c7dd87ba90542d2eb32b7154, which changed the AdverseEvent outcome binding strength from preferred to example in the then-authoritative adverseevent spreadsheet and replaced the NCI compose in valueset-adverse-event-outcome.xml with a SNOMED CT hierarchy filter rooted at 405533003. That followed FHIR-23022, which had introduced the preferred NCI value set that FHIR-25556 later relaxed.

Additional context:
AdverseEvent is active in source/fhir.ini and assigned to Patient Care; later source refactoring moved the resource definition into source/adverseevent/structuredefinition-AdverseEvent.xml while preserving the issue's applied semantics. Patient Care minutes from 2020-01-02 record the same action item to change outcome to an example SNOMED binding for international implementers. Zulip searches for issue-specific or NCI/SNOMED AdverseEvent outcome discussion found no conflicting community evidence.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source has AdverseEvent.outcome bound with strength="example" to http://hl7.org/fhir/ValueSet/adverse-event-outcome, and that value set composes SNOMED CT descendants of 405533003, so the current specification already implements the Jira decision.

Recommendation:
Keep this audit commit as-is. No follow-up source edit is needed for FHIR-25556 unless Patient Care later decides that the example value set should enumerate a different SNOMED expression or include the 405533003 grouping concept itself.
