FHIR-13764: Audit code regex backtracking fix

Issue request:
FHIR-13764 was a Published/Persuasive MnM STU3 change request asking to correct the primitive code regex because `[^\s]+([\s]?[^\s]+)*` caused catastrophic backtracking when a value ended in whitespace. The issue proposed removing the nested optional whitespace and noted that the prose about no leading/trailing whitespace and only single spaces supported `[^\s]+( [^\s]+)*` as the best target.

Initial application:
The Jira comment records svn revision 12454. In git history this is commit 0f9097af2a78da0ef2d92afbbef029ffde9a8a99, `#13764 - fix code regex`, which changed `source/datatypes.html` and `source/datatypes/primitives.xml` from `[^\s]+([\s]?[^\s]+)*` to `[^\s]+(\s[^\s]+)*`. That removed the catastrophic optional-whitespace structure and applied the seed's immediate correction.

Additional context:
Later Published/Persuasive code-regex issues refined the final source. FHIR-25413 changed the authoritative primitive spreadsheet to `[^\s]+( [^\s]+)*` so the pattern permits only literal spaces between non-whitespace tokens, and FHIR-37406 corrected the datatype-page display. Both related issues are already represented on the combined branch. Current `source/datatypes/primitives.xml` contains `[^\s]+( [^\s]+)*`, current `source/datatypes.html` uses `[%regex code%]`, and `source/fhir.ini` routes datatypes through the active datatype page. FHIR-46202 is a later `Resolved - change required` issue asking for a schema-style `^[^\s]+(\s[^\s]+)*$`; it is not Applied/Published, appears to conflict with the Published FHIR-25413/FHIR-37406 literal-space decision, and is not decided in this default applied/published run.
