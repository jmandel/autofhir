FHIR-14321: Align Event pattern status names

Issue request:
FHIR-14321 was Published/Persuasive for STU3 and asked the Workflow/Event and Request patterns to use clearer status names: Event suspended to on-hold, Event aborted to stopped, Request suspended to on-hold, and Request cancelled to revoked. It also approved the current Request revoked definition with known full completion, the Event not-done definition distinguishing preparation from main activity, and the Event stopped definition for termination after some main activity occurred.

Initial application:
The change appears to have been substantially applied by the 2018 workflow-pattern update in git 14b69a1c6dd33918b20d53ffd6cfbab523f840ba, then carried into the 2021 split CodeSystem XML sources. The current EventStatus and RequestStatus CodeSystems already use the approved code names and definitions, and the current Request pattern spreadsheet already uses on-hold/revoked metadata. The remaining gap was that the active Event pattern spreadsheet still advertised the old suspended/aborted names in Event.status metadata and old suspended/cancelled examples in Event.statusReason; active Event mapping exception files had copied those stale Event pattern values.

Additional context:
source/fhir.ini lists event and request as active logical patterns. The current RequestStatus wording also reflects later same-family decisions, including FHIR-15782's Request on-hold definition fix already represented on the combined branch and FHIR-48861's later ended parent status. The stale Event mapping exception values were updated only for folders that are active resources in source/fhir.ini; inactive resource folders and separate Product/FiveWs pattern text were left for separate review because FHIR-14321's related artifacts are Event and Request.

AutoFHIR reconciliation:
This commit updates the active Event pattern source to list on-hold and stopped in Event.status, to describe Event.statusReason in terms of not-done/on-hold/stopped, and to use on-hold in the Event eventHistory note. It also updates active Event mapping exception _pattern snapshots so resource-to-Event mapping documentation no longer carries the obsolete suspended/aborted/cancelled Event pattern wording.

Recommendation:
Keep this source fix as-is. It completes the approved FHIR-14321 Event/Request reconciliation without reopening separate Product/FiveWs pattern status terminology or later RequestStatus hierarchy work; those should remain separate trackers if the work group wants them changed.
