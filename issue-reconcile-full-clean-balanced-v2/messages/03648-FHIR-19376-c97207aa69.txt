FHIR-19376: Audit Appointment PractitionerRole actor support

Issue request:
FHIR-19376 was a Published/Persuasive PA change request for STU3 asking Appointment to support PractitionerRole as well as Practitioner when a virtual appointment needs a practitioner's organizational affiliation or role. The recorded resolution was to update the reference options to include PractitionerRole for the appointment actor; in the current source that element is Appointment.participant.actor.

Initial application:
The issue appears to have been applied by commit 87ce43db922810cf7461a4b098916209234ae0be on 2018-10-28. That commit message explicitly listed "GF#19376 Appointment supporting PractitionerRole" and changed source/appointment/appointment-spreadsheet.xml so Appointment.participant.actor accepted Reference(Patient|Practitioner|PractitionerRole|RelatedPerson|Device|HealthcareService|Location) instead of omitting PractitionerRole. Later source refactoring moved the authoritative input from the spreadsheet to structuredefinition-Appointment.xml.

Additional context:
source/fhir.ini keeps Appointment and PractitionerRole in the active [resources] list and assigns Appointment to PA. Current Appointment.participant.actor includes PractitionerRole among its Reference target profiles. AppointmentResponse.actor and Schedule.actor also include PractitionerRole, which is consistent with the originating community question about appointment participants and schedules. Jira, Zulip, and Confluence searches found no later FHIR-core decision that removes or narrows PractitionerRole support for Appointment.participant.actor.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope Appointment source already carries the requested PractitionerRole target profile, and the adjacent scheduling artifacts are consistent. Adding redundant narrative or changing the Practitioner-specific search parameter would not be required by FHIR-19376 and could create unrelated maintenance drift.

Recommendation:
Keep this no-change audit commit as-is. No FHIR-core follow-up is needed for FHIR-19376 unless PA later reopens the broader actor target-profile policy.
