FHIR-14099: Audit Patient MRN request guidance

Issue request:
FHIR-14099 was a Published FHIR-core Patient issue, resolved Persuasive for STU3, asking for consistent guidance on how a client can request creation of a new identifier such as an MRN. The accepted resolution said to add guidance to the Patient ids and Patient resource ids section explaining that an automated MRN identifier can be requested by including a Patient.identifier with an appropriate assigner, MRN type and/or system, and no value, allowing internal business rules to populate the actual identifier.

Initial application:
The issue appears to have been applied by commit dfe2cd1c803a8430f4175cbc3b2c105db227ded6, titled "GF#14099: Guidance on how to request a new identifier", which added the accepted paragraph to source/patient/patient-notes.xml. Later Patient notes work, including FHIR-48396 commit 54897cd3ffc4c700392ddae3204b41627e63b561, rewrote adjacent Patient linking text and external operation links but preserved the MRN request paragraph.

Additional context:
source/fhir.ini lists patient=Patient as an active resource and patient=pa as its work group, so source/patient/patient-notes.xml is build-scoped Patient narrative source. The linked Zulip thread shows the original tradeoff between a custom operation, data-absent-reason, Identifier.assigner without Identifier.value, and a rejected Identifier.use code; that context matches the current paragraph's local-business-rule framing rather than a new mandatory operation or global invariant. The PA Confluence identifier page references FHIR-14099 alongside broader identifier issues and gives later guidance about using identifier type, system, assigner, and value, but it does not reverse the Patient-specific MRN request guidance.

AutoFHIR reconciliation:
No source change was made. The current Patient notes already include the requested section heading and the accepted guidance: a Patient.identifier may carry an appropriate assigner, MRN type and/or system with no value, so internal business rules can replace or populate it with one or more identifiers. Adding another statement elsewhere would be redundant and could create maintenance drift.

Recommendation:
Keep this no-change audit commit. Future changes about broader identifier profiling or registry guidance should proceed under later identifier issues such as FHIR-48692 or successors once they are Applied/Published; FHIR-14099 does not need a current core source edit unless the Patient notes lose this paragraph or later PA guidance explicitly changes the MRN request approach.
