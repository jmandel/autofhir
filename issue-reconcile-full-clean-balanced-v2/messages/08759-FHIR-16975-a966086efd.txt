FHIR-16975: Audit Identifier definition clarification

Issue request:
FHIR-16975 was a Published/Persuasive STU3 FHIR-core-datatypes change request asking whether Identifier's definition should avoid the phrase "technical identifier" and clarify that Identifier is typically a business identifier rather than a resource id.

Initial application:
The issue appears to have been applied by git-svn commit c31e254aa7 (svn 14290), which changed source/datatypes/identifier.xml from "A technical identifier - identifies some entity uniquely and unambiguously" to "An identifier - identifies some entity uniquely and unambiguously. Typically this is used for business identifiers".

Additional context:
Identifier is an active datatype in source/fhir.ini and is marked normative. Current datatypes narrative also describes Identifier as a string associated with a single object or entity within a system and explains system/value uniqueness, so the current source avoids the confusing "technical identifier" wording and gives implementers the intended business-identifier context. Later R5 datatype narrative work adjusted adjacent Identifier prose without reversing this Jira decision. Quoted Zulip, Confluence, and Jira-neighborhood searches found no later discussion or related final issue that changes the conclusion.

This commit intentionally makes no source change because the build-scope Identifier XML and narrative already reflect the requested clarification.

Keep this audit commit as-is. No follow-up source edit is needed for FHIR-16975 unless the work group separately chooses to modernize Identifier wording beyond the already-applied clarification.
