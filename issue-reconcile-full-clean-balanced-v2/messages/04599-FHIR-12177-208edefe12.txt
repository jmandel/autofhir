FHIR-12177: Audit AllergyIntolerance criticality guidance

Issue request:
FHIR-12177 was Published with a Not Persuasive with Modification disposition for DSTU2 AllergyIntolerance. It asked whether AllergyIntolerance.criticality should be removed or have its value set aligned with SNOMED severity concepts; the approved resolution was to add a usage note explaining condition-level severity versus reaction-level severity and to make no value set change because the criticality concepts are FHIR/V3 criticality concepts rather than SNOMED severity concepts.

Initial application:
The issue appears to have been applied in git commit f3f2ad2c4b57ba4d2dfbbd990363885b40b49101, whose subject explicitly says "GF#12177 add AllergyIntolerance.criticality comment" and whose patch added the approved comment to the AllergyIntolerance spreadsheet source. The current generated StructureDefinition source retains a GF#12177 committee note and the requested criticality/severity usage note on AllergyIntolerance.criticality.

Additional context:
AllergyIntolerance is an active current-build resource in source/fhir.ini. Earlier FHIR-8146 requested narrative usage notes distinguishing criticality from reaction severity, and the current notes page still does that. Later FHIR-31770 resolved no-change for HL7 v2/SNOMED mapping guidance and confirmed that implementers must decide whether local severity maps to reaction severity, condition criticality, or neither. FHIR-53608 questioned the categorical wording but was Resolved - No Change/Retracted, and FHIR-54013 remains Triaged, so neither supplies a final applied decision that supersedes FHIR-12177 for this reconciliation.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active AllergyIntolerance source already contains the approved FHIR-12177 usage note, and the AllergyIntoleranceCriticality CodeSystem/ValueSet remain a FHIR criticality value set rather than a SNOMED severity binding, consistent with the issue resolution and later no-change mapping guidance.

Recommendation:
Keep this no-change audit commit as-is for FHIR-12177. Future edits to qualify, remove, or make criticality an extension should be handled only if Patient Care advances a separate final issue such as FHIR-54013 or another applied/published superseding decision.
