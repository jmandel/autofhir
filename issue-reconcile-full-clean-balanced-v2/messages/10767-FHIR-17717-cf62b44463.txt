FHIR-17717: Audit vital signs effective precision constraint

Issue request:
FHIR-17717 was a Published/Persuasive OO STU3 change request for the Vital Signs profile. It asked that the vs-1 invariant apply only when Observation.effective[x] is dateTime and has an actual value, that the XPath be corrected, and that Period/nullFlavor-style primitive-extension cases not be incorrectly rejected.

Initial application:
The Jira comment identifies commit 98752dd6c14e0ad544430fd0d7457f25282173d0 as the initial pre-application. That commit updated the old observation-vitalsigns spreadsheet so the human text said the rule applies when effective[x] is dateTime and has a value, and replaced the broken XPath with f:effectiveDateTime[matches(@value, '^\d{4}-\d{2}-\d{2}')]. The old spreadsheet source was later replaced by structuredefinition-profile-vitalsigns.xml.

Additional context:
Observation is an active resource in source/fhir.ini, so source/observation/structuredefinition-profile-vitalsigns.xml is current build-scope source. The current profile uses vsp-1 with human text "if Observation.effective[x] (as dateTime) has a value then that value shall be precise at least to the day" and expression "(effective as dateTime).toString().length() >= 8". Later source history removed XPath usage, disambiguated the vital signs constraint keys, fixed the root-context expression, removed Period from Observation.effective[x] via FHIR-21297, and clarified "at least" via FHIR-26964. Later related Jira issues FHIR-29654 and FHIR-34463 re-raised the invariant concern, including the primitive hasValue discussion, but OO ultimately resolved them Not Persuasive/No Change after concluding the current vsp-1 rule works with dateTime as the only allowed datatype.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Changing the expression now would not be a bounded application of FHIR-17717; it would reopen a later OO no-change decision in FHIR-29654/FHIR-34463. The active source already carries the approved human rule, the old XPath surface no longer exists, and the remaining apparent expression concern has been superseded by later work-group disposition.

Recommendation:
Keep this audit commit as-is. If implementers still need primitive-extension-only effectiveDateTime values to pass vsp-1, that should be taken back to OO as a new or reopened tracker because the current source reflects later explicit no-change decisions rather than an unapplied FHIR-17717 omission.
