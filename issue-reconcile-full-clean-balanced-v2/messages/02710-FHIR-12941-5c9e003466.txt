FHIR-12941: Audit ISO security role vocabulary application

Issue request:
FHIR-12941 was Published/Persuasive for DSTU2. It asked that the Security Role vocabulary/value set include role vocabulary defined in ISO 21298, while noting uncertainty about whether FHIR could legally pull in the whole or partial ISO vocabulary. The final Jira resolution says Gary provided the needed details, and a later comment says the work had already been done after discussion.

Initial application:
No Jira-tagged FHIR-12941 source commit was found. The relevant source history instead shows a SecurityRoleType value set added just before the Jira was filed, followed by later Security WG maintenance. The current explicit ISO-21298-derived structural-role sample vocabulary was introduced by the FHIR-32520 application and subsequent terminology cleanup commits, not by a commit that names FHIR-12941.

Additional context:
Later Security WG decisions narrowed the modern role model rather than importing the full ISO vocabulary. FHIR-32520 says SecurityRoleType should be an example binding with radically different structural-role sample codes derived from ISO-21298. FHIR-28184, FHIR-53882, and FHIR-55889 further clarify agent.type versus agent.role without requiring a broader ISO import. The active current source has SecurityRoleType in the terminology bindings table, an active security-structural-roles-example CodeSystem in source/fhir.ini, and AuditEvent/Provenance bindings that use the ISO-derived security-role-type-example value set.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current specification already satisfies the durable intent of FHIR-12941 for the current build: it provides an ISO-21298-derived example Security Role value set and applies it to the active security role binding surfaces, while avoiding an unsupported wholesale ISO vocabulary import.

Recommendation:
Keep this audit commit as-is. Any future request to include more complete ISO 21298 content should be handled as a new Security/Terminology work-group and licensing decision, because the later applied source intentionally uses sample derived structural-role codes as an example binding.
