FHIR-55069: Audit PlanDefinition example action terminology

Issue request:
FHIR-55069 is an Applied/Persuasive CDS change request for PlanDefinition. It asked that the action-code, action-reason-code, and action-participant-function ValueSets and CodeSystems be treated as THO-candidate example terminology by marking the involved ValueSets and CodeSystems experimental and adding Example to each name, title, id, and url.

Initial application:
The request was applied by git commit c3a6fdf8e877337135834b15a02de1e4615aece9, which explicitly named FHIR-55069 and FHIR-55072. That commit renamed the six shared action terminology XML files under source/plandefinition to *-example, changed their ids, canonical urls, names, titles, experimental flags, internal ValueSet/CodeSystem references, source/oids.ini entries, and updated PlanDefinition bindings to the new example ValueSet canonicals.

Additional context:
PlanDefinition is active in source/fhir.ini and owns the shared terminology files used by PlanDefinition, RequestOrchestration, and ActivityDefinition. FHIR-55072 is the same-change-family RequestOrchestration issue and is audited separately in this run. Adjacent Jira issues FHIR-55070 and FHIR-55071 are Resolved - No Change escape-valve requests for other PlanDefinition elements and do not require source changes here. The only remaining non-example references found for these bindings are in checked-in resource SVG diagrams, which are generated-looking artifacts and are not the authoritative source for this reconciliation. Zulip and Confluence searches did not find conflicting community evidence.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative XML source already has PlanDefinition.action.code, PlanDefinition.action.reason, and PlanDefinition.action.participant.function bound to the *-example ValueSet URLs, and the corresponding ValueSet and CodeSystem definitions are experimental with Example in their id, url, name, and title.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for FHIR-55069 unless a future diagram regeneration workflow chooses to refresh the checked-in SVGs from the authoritative StructureDefinition source.
