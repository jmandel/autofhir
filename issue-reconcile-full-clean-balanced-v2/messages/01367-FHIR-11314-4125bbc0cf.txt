FHIR-11314: Audit retired Sequence clarification

Issue request:
FHIR-11314 was a Published Clinical Genomics change request for the DSTU2 Sequence resource. The request asked for clarification around Sequence.variant.observedAllele, Sequence.observedSeq, read coverage, and Sequence.repository; the final resolution was Not Persuasive with Modification/Persuasive clarification text stating that observedAllele is scoped to variant.start through variant.end, observedSeq is scoped to referenceSeq.windowStart through referenceSeq.windowEnd, and repository points to an external repository containing the observedSeq report.

Initial application:
The historical application was commit d5ba8fdc2448787bf21f9411357e3a0780a7f039, "#11314 Revise definition on Sequence.observedAllele and Sequence.observedSeq", which edited source/sequence/sequence-spreadsheet.xml to add the variant range wording and observedSeq/referenceSeq window wording. I found no current source path for the original Sequence resource in the active build.

Additional context:
The affected Sequence resource was later renamed to MolecularSequence by GF#19453, and Sequence is now listed under removed resources in source/fhir.ini. The MolecularSequence workgroup/security entries are commented out, and FHIR-51227 is an Applied R6 decision that superseded legacy MolecularSequence with MolecularDefinition. The current MolecularDefinition source uses a different representation model with code, literal, resolvable, extracted, concatenated, repeated, and relative representations, so the old observedSeq/observedAllele/repository clarification is not directly portable.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The issue's requested clarification was applied to the historical Sequence spreadsheet, and the current build no longer exposes the affected Sequence elements that would need the wording. Reintroducing the old Sequence prose into MolecularDefinition would be misleading because MolecularDefinition has a different model and any profile-level guidance belongs to the current MolecularDefinition/Molecular Data Types work.

Recommendation:
Keep this audit commit as-is. Do not resurrect the retired Sequence text in the current core source; if implementers find an ambiguity in MolecularDefinition sequence, allele, or variation profiles, handle it as a new MolecularDefinition-specific Clinical Genomics issue.
