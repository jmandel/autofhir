FHIR-6196: Audit retired DiagnosticOrder boundary guidance

Issue request:
FHIR-6196 was a Published/Persuasive Patient Care change request for DSTU1 DiagnosticOrder, asking for a Boundaries and Relationships section distinguishing DiagnosticOrder from ReferralRequest and ProcedureRequest and explaining overlap among request resources.

Initial application:
The issue appears to have been applied by git commit 88898109f2bf5eac2691ee76b90169af3a430031, which rewrote source/diagnosticorder/diagnosticorder-introduction.xml with the requested guidance. Commit 16997a29cae89d6a31d09dabd782afdb0077b2e7 then carried that guidance forward when DiagnosticOrder was renamed to DiagnosticRequest.

Additional context:
The current build no longer includes DiagnosticOrder, DiagnosticRequest, ProcedureRequest, or ReferralRequest as active resources. source/fhir.ini records DiagnosticOrder as subsumed into ServiceRequest, ProcedureRequest as merged into ServiceRequest, and ReferralRequest as becoming ServiceRequest. Current ServiceRequest source covers diagnostic tests, procedures, specialist consultation/referral-style use, resulting Procedure/DiagnosticReport/Observation/ImagingStudy outputs, request workflow, and boundaries against Task and CommunicationRequest. The old issue-specific distinction among separate request resources is therefore obsolete rather than missing.

AutoFHIR reconciliation:
This empty audit commit makes no source change. Reintroducing the DSTU1 DiagnosticOrder/ProcedureRequest/ReferralRequest comparison into current ServiceRequest would revive retired resource distinctions and duplicate broader current workflow/request guidance without changing implementer understanding.

Recommendation:
Keep this no-change audit as-is. Future work should only add new ServiceRequest boundary prose if Patient Care or Orders and Observations makes a new current-version decision; FHIR-6196 itself is fully represented by historical application plus later resource consolidation.
