FHIR-22269: Audit Binary compartment clarification

Issue request:
FHIR-22269 was Published/Persuasive with Modification for R5. It originally asked to add Binary to compartments because Binary resources concerning a patient should not be described as never in the Patient compartment, but the final resolution changed the remedy.

Initial application:
The issue was applied by commit c2ddea7415c6952f2988e332315c5e1becdf9bd0, "22269 - clarify compartments", which updated the CompartmentDefinition narrative, the compartment page template, and related compartment source. That commit removed the old framing and added text that non-listed resources may still be relevant for access-control uses such as Binary.

Additional context:
FHIR-26879 raised the same Binary Patient-compartment exclusion concern in 2020, and its Jira comment later says "see 22269". Confluence minutes show FHIR-I reopening FHIR-22269 on 2022-08-08 for more discussion, then approving the Persuasive with Modification resolution on 2022-08-15. FHIR-51725 later clarified that listed resources with .param elements are part of a compartment while listed resources without .param elements are outside it, and that local convention can still return non-compartment resources in compartment-based retrieval operations.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active CompartmentDefinition narrative and active compartment page template already implement the FHIR-22269 resolution; Binary is not falsely described as never relevant to patient access control, but the source also preserves the later distinction that resources without computable params are outside formal compartment membership.

Recommendation:
Keep this audit commit as-is. Further changes to make Binary formally part of Patient or every other compartment via Binary.securityContext would require a new work-group decision because the applied FHIR-22269/FHIR-51725 path deliberately chose narrative access-control guidance rather than a computable compartment parameter.
