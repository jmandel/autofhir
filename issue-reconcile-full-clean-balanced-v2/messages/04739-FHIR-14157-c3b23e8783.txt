FHIR-14157: Audit Encounter reorganization remainder

Issue request:
FHIR-14157 was Published/Persuasive with Modification for R5. It asked to reorganize time-varying Encounter tracking by creating EncounterHistory, removing Encounter.statusHistory and Encounter.classHistory from Encounter, moving specialArrangement and specialCourtesy out of hospitalization to top-level Encounter elements, updating the special-arrangement search parameter, clarifying specialCourtesy versus security labels, and removing dietPreference from Encounter in favor of an extension after Patient Care discussion.

Initial application:
The main source work was applied before R5 publication. Commit 2c0f3a8733 removed Encounter.statusHistory and Encounter.classHistory, moved the hospitality fields including dietPreference/specialArrangement/specialCourtesy to top-level Encounter, and updated Encounter source shape. Commit 53538c40d6 added the first EncounterHistory resource draft, commit 935d04e828 completed EncounterHistory narrative and location structure while also citing FHIR-38856, and commit 90f631ea1f clarified Encounter.specialCourtesy versus VIP/security-label use. The implementation deliberately did not remove Encounter.dietPreference; the applying editor stated on Zulip that the conversion to an extension would be deferred out of scope pending PA/PC follow-up.

Additional context:
Current source/fhir.ini has Encounter as an active resource and maps R4/R5 class/status histories to EncounterHistory, while source/encounter/structuredefinition-Encounter.xml no longer contains Encounter.statusHistory or Encounter.classHistory. Encounter.specialArrangement and Encounter.specialCourtesy are top-level elements and the special-arrangement search parameter points to Encounter.specialArrangement. Encounter.dietPreference remains a top-level element and the example still uses it. Patient Care minutes and FHIR-10028 show preference modeling was not settled, and searches did not find a later final dietPreference-extension ticket. Separately, current core no longer carries EncounterHistory as an active resource because later R6 cleanup moved it out of the current build and current Encounter narrative links to the PA admin-incubator EncounterHistory page; FHIR-38856 already has a no-change audit commit on the combined branch for the R5 inclusion question.

AutoFHIR reconciliation:
This is an empty human-review audit commit. No source change is safe here: the mechanical EncounterHistory/status/class/specialArrangement/specialCourtesy parts are already represented in the current source lineage, re-adding EncounterHistory to current core would contradict later R6 build-scope changes, and removing Encounter.dietPreference now would be a breaking change whose own PA/PC follow-up was explicitly deferred and not found as a final applied decision.

Recommendation:
Keep this audit commit as-is and have PA/PC decide whether Encounter.dietPreference should still be converted to a standard extension or left as a core Encounter element. If the work group still wants the extension path, file or locate a dedicated final tracker and apply that targeted change there rather than reopening the already-applied EncounterHistory restructuring in FHIR-14157.
