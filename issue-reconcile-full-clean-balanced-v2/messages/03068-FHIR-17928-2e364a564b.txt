FHIR-17928: Audit ClaimResponse requestor rename

Issue request:
FHIR-17928 is a Published FHIR-core ClaimResponse change request, resolved Persuasive, asking to change ClaimResponse.requestProvider to ClaimResponse.provider for STU3.

Initial application:
The request was applied before this reconciliation by the broad financial-management commit afb5ec66f6, whose message explicitly lists FHIR-17928. That commit changed ClaimResponse examples and the then-authoritative spreadsheet from requestProvider to requestor, not provider. The follow-up R3/R4 mapping commit d2a25ba3c3 records ClaimResponse.requestProvider=ClaimResponse.requestor.

Additional context:
Current source/fhir.ini lists ClaimResponse as an active resource and retains the old-to-current rename map from ClaimResponse.requestProvider to ClaimResponse.requestor. Current ClaimResponse source, examples, and search parameters use ClaimResponse.requestor; there is no top-level ClaimResponse.provider. Closely related published financial-management issues FHIR-17962 and FHIR-17996 explicitly resolved parallel requestProvider rename requests as requestor, and the already-published FHIR-37879 reconciliation describes ClaimResponse.requestor as the current R6 billing-provider element. A 2026 Da Vinci Zulip discussion likewise states that there is no ClaimResponse.provider and that ClaimResponse.requestor carries the requesting provider.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current specification already removes requestProvider and uses the resolved requestor element consistently; changing the resource to ClaimResponse.provider would contradict the explicit same-family resolutions and current ClaimResponse model.

Recommendation:
Keep this empty audit commit as-is. No core source follow-up is recommended for FHIR-17928 unless the Financial Management work group opens a new issue to rename the current ClaimResponse.requestor element.
