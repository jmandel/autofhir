FHIR-17245: Add inherited MetadataResource context searches

Issue request:
FHIR-17245 was a Published/Persuasive FHIR-I STU3 issue reporting that useContext search parameters added to MetadataResource by earlier trackers were not inherited consistently by resources using MetadataResource as their template. The accepted resolution was to ensure the search parameters were inherited too.

Initial application:
The underlying useContext search-parameter family was added for FHIR-13565 and FHIR-13566 in imported SVN/Git commit bc0e408c80a3d8ff7d558e023496ecffd4d76e7b. No source commit with an explicit FHIR-17245 key was found; the Jira comment says the parameters were being applied consistently by October 2018. Later source rework into per-resource bundle-*-search-params.xml files left most active MetadataResource descendants with the inherited context parameters, but active ObservationDefinition and SpecimenDefinition still lacked the original context, context-quantity, context-type, context-type-quantity, and context-type-value search parameters despite both being MetadataResource specializations with useContext.

Additional context:
source/fhir.ini lists ObservationDefinition and SpecimenDefinition as active resources, abbreviations, and approved resources in the current build, so their search-parameter bundles are in build scope. MedicationKnowledge and ConditionDefinition also have MetadataResource source files, but they are not listed in the active [resources] section and were not edited. FHIR-37570's later context-reference parameter is already represented on the combined branch and FHIR-53850 is a broader Resolved - change required propagation issue, so this reconciliation intentionally fixes only the original FHIR-17245 useContext search-parameter family.

AutoFHIR reconciliation:
This commit adds the five original MetadataResource useContext search parameters to source/observationdefinition/bundle-ObservationDefinition-search-params.xml and source/specimendefinition/bundle-SpecimenDefinition-search-params.xml, matching the established structure, expressions, status extension, and ordering used by the other active MetadataResource-derived resource bundles.

Recommendation:
Keep this source fix. Handle any broader CanonicalResource context-reference propagation work under the already-related FHIR-53850 scope if that issue later enters applied/published source-edit scope.
