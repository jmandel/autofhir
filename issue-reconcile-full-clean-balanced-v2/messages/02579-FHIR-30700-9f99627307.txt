FHIR-30700: Audit ValueSet $expand parameter descriptions

Issue request:
FHIR-30700 was Published/Persuasive with Modification for R5. It asked to rename the ValueSet $expand input parameters excludeNested and excludeNotForUI and improve their descriptions; the accepted resolution kept the existing normative parameter names and replaced the descriptions with clearer rules for nesting and UI/navigation-only concepts.

Initial application:
No prior commit explicitly tagged FHIR-30700 was found. The substantive source application appears in git commit 1c4a35dbe293f96f5b95682b627ef541a838ea92, which updated source/valueset/operationdefinition-ValueSet-expand.xml with the approved excludeNested and excludeNotForUI description semantics while carrying a different Jira key in the subject. Later source history cleaned the markdown links, leaving the current operation definition semantically aligned with FHIR-30700.

Additional context:
The active build includes ValueSet as a resource in source/fhir.ini, and source/valueset/operationdefinition-ValueSet-expand.xml is the authoritative operation definition for ValueSet/$expand. Vocab minutes and the related Zulip thread show the WG chose to improve the existing parameter descriptions rather than rename them or add a new mode parameter. Related FHIR-30702 and FHIR-30703 removed the under-specified valueset expand-group and expand-rules extensions and are already represented on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already says excludeNested=true requires a flat expansion, excludeNested=false allows but does not require nesting, and excludeNotForUI controls whether notSelectable/no-code/abstract navigation concepts may be included, including the FHIR Specification generation notes. The remaining differences from Jira prose are harmless formatting/link/punctuation details and do not change implementer understanding.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-30700 unless a future WG decision reopens the larger question of renaming these normative parameters or adding a replacement UI/mode parameter.
