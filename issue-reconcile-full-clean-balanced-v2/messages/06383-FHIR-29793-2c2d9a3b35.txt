FHIR-29793: Audit BodyStructure landmark enhancement

Issue request:
FHIR-29793 was Published with a Persuasive with Modification resolution for R5. It asked OO to enhance BodyStructure by incorporating the Wound Care IG body-location/landmark elements, except that UnderlyingAnatomicalStructure would remain an extension, and to QA the example code sets used by the IG and BodyStructure to remove overlap.

Initial application:
The issue was applied before this reconciliation. Commit 43c4e40bdb added the BodyStructure landmark backbone and related value sets, ecaae5997 corrected a short description, and da17698bdf fixed the body-site value set after the OO Specimen follow-up by using both the explicit wound-care body-site concepts and the broader SNOMED CT anatomical/acquired body structure filter.

Additional context:
OO Specimen minutes on 2022-12-19 confirm the intended model: build the included/excluded structure once, add bodyLandmark as a backbone, keep UnderlyingAnatomicalStructure as an extension, and clean up laterality/qualifier value sets. OO Specimen minutes on 2023-02-20 confirm the body-site value-set follow-up that restored the broader SNOMED CT filter alongside wound-care concepts. Later Published issues FHIR-39795 and FHIR-39796 refined the newly added distanceFromLandmark elements by changing device to CodeableReference(Device) and broadening the distance wording to any linear unit; both are already represented on the combined branch.

AutoFHIR reconciliation:
No source change was made. BodyStructure is active in the build, and the current authoritative source already contains includedStructure, bodyLandmarkOrientation and its landmarkDescription, clockFacePosition, distanceFromLandmark, and surfaceOrientation children, plus excludedStructure as a contentReference to includedStructure. The current body-site value set contains both the explicit wound-care anatomical concept list and the SNOMED CT is-a 442083009 filter requested by the later QA discussion.

Recommendation:
Keep this empty audit commit as-is. The seed issue needs no further core source change; later refinements to the same newly added elements are covered by their own Jira/reconcile records and should not be republished here.
