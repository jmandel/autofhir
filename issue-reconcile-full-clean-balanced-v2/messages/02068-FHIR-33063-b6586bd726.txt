FHIR-33063: Audit UCUM annotation guidance

Issue request:
FHIR-33063 was a Published/Persuasive Vocab change request, raised in R4 and applied for R5, asking the core UCUM page to discourage curly-brace content in UCUM code expressions because braces add descriptive text but do not contribute to code meaning.

Initial application:
The issue was applied before this reconciliation by git commit 19d78411d5a1784e71184f70e91244a6b520a575, which added the requested two-sentence curly-brace warning to source/ucum.html along with other terminology page fixes. There is no separate current source/ucum.html to edit now.

Additional context:
FHIR-35933 later moved the "Using external code system with FHIR" pages out of core and into HL7 Terminology, deleting source/ucum.html and changing source/terminologies-systems.html to link to the THO UCUM page. Current core therefore no longer owns the UCUM page. FHIR-42788 later added the actionable FHIR guidance as a best-practice invariant on Quantity: UCUM annotations such as {Z-Score} can be misleading, and Quantity.unit should carry the human-readable unit text. The origin Zulip thread and FHIR-27540 no-change decision support this as guidance rather than a prohibition.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Reintroducing a core UCUM page or duplicating the Quantity guidance on the code-system index would conflict with the later page migration and create maintenance drift; the current core source already carries the implementer-facing guidance on the Quantity datatype where the relevant code/unit elements are defined.

Recommendation:
Keep this no-change audit as-is for FHIR core. If Terminology Infrastructure wants the THO "Using UCUM with HL7 Standards" page to mirror the Quantity best-practice guidance, that follow-up belongs in THO/UTG rather than this core checkout.
