FHIR-11151: Audit AllergyIntolerance status split

Issue request:
FHIR-11151 was Published/Persuasive for FHIR-core AllergyIntolerance. It asked to replace the mixed AllergyIntolerance.status with separate clinicalStatus and verificationStatus elements, both summary and modifier elements, with clinicalStatus covering active/inactive/resolved, verificationStatus covering confirmed/unconfirmed/refuted/entered-in-error, and invariants connecting clinicalStatus to entered-in-error verification status.

Initial application:
The split was applied by ed170ff075, which explicitly cited #10642, #11151, and #11920 and replaced status usages in AllergyIntolerance source examples, notes, and the spreadsheet with clinicalStatus and verificationStatus. The current build-scope resource is active in source/fhir.ini and no longer defines AllergyIntolerance.status; it defines AllergyIntolerance.clinicalStatus and AllergyIntolerance.verificationStatus as summary modifier elements with required bindings and current search parameters.

Additional context:
The same 2016 block vote included FHIR-10642 and FHIR-11920. Later published Patient Care decisions deliberately changed details from the original resolution: FHIR-13997 made verificationStatus 0..1 instead of adding an unknown code, FHIR-17743 changed both status elements to CodeableConcept, FHIR-20189 added presumed to verificationStatus, and FHIR-25514 plus FHIR-28458 removed the original clinicalStatus invariants in favor of guidance for negated and refuted AllergyIntolerance records. Zulip discussion confirms both the original status-default concern and later invariant problems; no Confluence reference was found for FHIR-11151.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source already conveys the status split required by FHIR-11151, and the differences from the original 2016 wording are explained by later published decisions that should not be reverted.

Recommendation:
Keep this audit commit as-is. No core source follow-up is recommended for FHIR-11151; any future change to verificationStatus cardinality or clinicalStatus constraints would need a new Patient Care decision because later published issues intentionally relaxed those parts.
