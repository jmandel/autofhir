FHIR-14076: Audit named-query search-parameter scope

Issue request:
FHIR-14076 was Published with a Persuasive with Modification resolution for STU3. It asked whether standard FHIR search parameters such as _count or resource search parameters could be mixed into OperationDefinition invocations. The accepted resolution was to document that standard search parameters are in scope for OperationDefinition.kind = query, while servers do not need to support them unless explicitly documented; for OperationDefinition.kind = operation, parameters must be explicitly defined.

Initial application:
The issue was applied by git-svn commit 0ce8de7c02663f8bdd2b7865985be9ec6550abb7, svn revision 14271, which split the OperationDefinition narrative into separate Executing Operations and Executing Named Queries sections and added the original statement that standard search parameters are automatically in scope for named queries but need not be supported unless documented.

Additional context:
The current source has since been refined by later Published named-query decisions. FHIR-31491 clarified the inherited standard/resource search-parameter scope, server-support, CapabilityStatement, and documentation expectations; its reconciliation commit ac2ee46c80a89b04cdaadb2f8de51eea25c24ca8 is already on the combined branch. FHIR-39318 clarified named-query execution semantics and stale OperationDefinition comments; its reconciliation commit f86d508e0db21179850573fc570b98303db8a557 is also already on the combined branch. source/fhir.ini actively lists operationdefinition=OperationDefinition, so source/operationdefinition/operationdefinition-notes.xml feeds the current build, and publish.ini lists search.html, so the parallel Search guidance is also in build scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source preserves FHIR-14076's operation/query distinction: kind=operation points to the Operations Framework rather than inherited search parameters, while named-query guidance says standard and resource-context search parameters are potentially available, not necessarily supported, and should be documented or constrained when relevant. That current wording incorporates the later refinements and is more precise than the original STU3 sentence.

Recommendation:
Keep this audit commit as-is. No further core FHIR source change is recommended for FHIR-14076 unless the work group reopens named-query parameter-scope policy; related issues FHIR-31491 and FHIR-39318 are already represented and should not receive duplicate commits here.
