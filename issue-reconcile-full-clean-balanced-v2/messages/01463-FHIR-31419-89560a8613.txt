FHIR-31419: Audit Procedure.statusReason value set

Issue request:
FHIR-31419 was a Published/Persuasive Patient Care change request for R5 asking that Procedure.statusReason's example "Procedure Not Performed Reason (SNOMED-CT)" value set include SNOMED CT qualifier value 410536001 Contraindicated rather than relying only on highly precoordinated procedure/situation codes.

Initial application:
The issue was applied by commit 4490a6918cfe685fc75111dc2151b312fd5fe386, "Added a contraindicated  code to the Procedure.statusReason value set", which added 410536001 to source/procedure/valueset-procedure-not-performed-reason.xml and to tools/tx/snomed/snomed.xml. Current source retains that addition.

Additional context:
source/fhir.ini actively lists procedure=Procedure, so source/procedure artifacts feed the current build. Procedure.statusReason still has an example binding to http://hl7.org/fhir/ValueSet/procedure-not-performed-reason. Later related Jira FHIR-47822 challenged the adequacy of the same value set for R6, but Patient Care resolved it no-change because the binding is example strength and can be constrained by profiles/IGs. Older FHIR-14869 similarly left the statusReason binding unchanged because the element comment limits typical use to exception statuses and the binding is example strength.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current authoritative value set source already includes 410536001 Contraindicated (qualifier value), and Procedure.statusReason already points to that value set with example binding strength.

Recommendation:
Keep this no-change audit commit as-is. No FHIR core follow-up is needed for FHIR-31419; future narrower terminology guidance should be handled through a new Patient Care decision or profile-specific constraints rather than by reopening this applied R5 clarification.
