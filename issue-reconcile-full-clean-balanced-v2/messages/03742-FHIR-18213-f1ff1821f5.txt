FHIR-18213: Audit Coverage and InsurancePlan boundaries

Issue request:
FHIR-18213 was a Published/Not Persuasive with Modification PA change request from the STU3 cycle. It argued that Coverage and InsurancePlan duplicated each other and the accepted modification was to clarify the Boundaries and Relationships content, distinguishing InsurancePlan as insurer-offered plan information from Coverage as beneficiary-specific coverage information.

Initial application:
No git commit explicitly mentioning FHIR-18213 or 18213 was found. The overlapping Published/Persuasive Coverage issue FHIR-17950 was applied by git commit 288d1e5047c9743642f053c3b5099e6bfd882d60, which added the Coverage Boundaries and Relationships table distinguishing Coverage from Contract and InsurancePlan. The combined branch already contains a later FHIR-17950 reconciliation commit, 86bf9ad30b1c3ce3159cb6f54f29c9a91ffd4199, that updates the Coverage InsurancePlan row for the current InsurancePlan/InsuranceProduct split.

Additional context:
source/fhir.ini keeps Coverage, InsurancePlan, and InsuranceProduct as active core resources. FHIR-24827 later split the old ProductPlan/InsurancePlan model into InsuranceProduct plus InsurancePlan and specified that Coverage.insurancePlan refers to InsurancePlan. FHIR-47649 and FHIR-47650 then updated the InsurancePlan and InsuranceProduct Boundaries and Relationships pages to say Coverage links an InsurancePlan to a beneficiary and optionally a subscriber. Current source matches that later model.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current Coverage page says Coverage is specific insurance card/self-pay information for a specific individual and that InsurancePlan defines the reusable plan offering, with benefits in the referenced InsuranceProduct. The current InsurancePlan page also says Coverage establishes the link between an InsurancePlan and a beneficiary/subscriber. Additional prose would only restate already-aligned build-scope guidance.

Recommendation:
Keep this no-change audit. The seed's requested distinction is already present in the current specification after the FHIR-17950, FHIR-24827, FHIR-47649, and FHIR-47650 source history. Reconcile the later R6 InsurancePlan/InsuranceProduct trackers separately if desired; they were used here only as bounded context for interpreting the seed.
