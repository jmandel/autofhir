FHIR-16886: Normalize Binary native return guidance

Issue request:
FHIR-16886 was a Published/Persuasive with Modification FHIR-core Binary issue from the STU3 ballot. It asked to restructure the Binary contentType handling notes so retrieval, create/update, _summary, generic MIME handling, and header mappings were clearer, and specifically called out the inconsistent lower-case "should" in the Binary return guidance.

Initial application:
The issue was applied by svn revision 14354, represented in git as 4c0d34042c3e8742eda89fdb336da09c622aa009, together with FHIR-13507. That commit rewrote source/binary/binary-notes.xml into the current list-based REST guidance and moved the _summary and create/update points into the relevant bullets, but it retained lower-case "should" in the non-FHIR Accept-header return rule that FHIR-16886 had explicitly asked to check.

Additional context:
Binary is an active current-build resource in source/fhir.ini and part of the infrastructure normative package. Later Binary edits, including FHIR-18338 grammar cleanup, FHIR-17833 X-Security-Context clarification, FHIR-37381 duplicate-bullet removal, and the recent FHIR-17026/FHIR-17027 reconciliations, preserved the same conformance-style non-FHIR return rule. Confluence minutes for 2018-07-09 list FHIR-16886 in a persuasive-with-modification block vote, and community searches found no directly relevant Zulip discussion or conflicting later decision.

AutoFHIR reconciliation:
This commit updates the active Binary REST narrative so the non-FHIR Accept-header return rule uses uppercase SHOULD and rewrites the immediately following PDF example to avoid a second lower-case conformance-looking "should". No other Binary behavior is changed; the existing retrieval, create/update, _summary, and header mapping structure from the original application is retained.

Recommendation:
Keep this source fix as-is. It completes the narrow part of FHIR-16886 that remained visibly unapplied in current build-scope source while leaving the historically applied Binary contentType restructuring intact.
