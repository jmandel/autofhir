FHIR-11133: Audit Condition no-known-problems coding

Issue request:
FHIR-11133 was a Published FHIR-core Patient Care change request with resolution Persuasive with Modification. It provided STU feedback supporting CodeableConcept/Condition.code for reporting no known conditions rather than relying on a List.emptyReason-only problem list representation. The final resolution pointed to GF#8749 and required adding SNOMED CT 160245001 "No current problems or disability (situation)" to the condition.code value set definition.

Initial application:
The seed issue itself does not appear to have a separate FHIR-11133-tagged source commit. Its Jira resolution and comments identify GF#8749 as the applied change. Historical commit afcde8c93515a0c8879ccce26779347a15c7bd36 implemented GF#8749 by adding SNOMED CT code 160245001 to source/condition/valueset-condition-code.xml and adding Condition.code/no-known-problems guidance to source/condition/condition-notes.xml.

Additional context:
FHIR-8749 is the original same-change-family Patient Care issue, and FHIR-11100 is a parallel 2016 ballot comment supporting the same CodeableConcept approach; both point back to the same GF#8749 application. Current source/fhir.ini lists Condition as an active resource owned by Patient Care, and Condition.code has an example binding to http://hl7.org/fhir/ValueSet/condition-code. The current notes still describe List.emptyReason for full-list or not-asked statements, but the accepted resolution was Persuasive with Modification and added the Condition.code code/guidance rather than removing every List.emptyReason mention. Later source maintenance preserved the STU note wording, and a 2025 Patient Care minute still references the current Condition page and value set as support for negation/no-known-condition discussion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active source already includes SNOMED CT 160245001 in the Condition code value set and the Condition notes already state that Condition.code can capture "no known problems" or negated conditions, with a preference for the code when all condition/problem data should be queryable as Condition instances.

Recommendation:
Keep this audit commit as-is for FHIR-11133. If Patient Care wants to retire or rewrite the remaining STU feedback note, that should be a separate editorial/work-group decision because the current seed's published modified resolution is already represented in active source.
