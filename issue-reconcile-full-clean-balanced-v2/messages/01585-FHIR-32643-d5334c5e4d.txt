FHIR-32643: Audit artifact repository guidance

Issue request:
FHIR-32643 was an Applied/Persuasive CDS change request asking FHIR core to consider knowledge artifact repository capability statements, originally by generalizing the QM IG measure repository service into ShareableArtifactRepository, PublishableArtifactRepository, and AuthoringArtifactRepository capabilities. Later Jira comments narrowed the applied core action to adding discussion of these capabilities and referencing the CRMI IG for the formal capability statements.

Initial application:
The issue was applied in Git commit 0b4226bcd1f7ab7f5b2b8c5f0b6cfd32a59a97a5, included in merged PR HL7/fhir#3369, which added CRMI Artifact Repository Service and Artifact Terminology Service links to source/clinicalreasoning-knowledge-artifact-distribution.html. No separate core source commit added the three formal CRMI capability statements to FHIR core, consistent with the later Jira comments that the formal definitions live in CRMI.

Additional context:
The current Clinical Reasoning module links to the Sharing Knowledge Artifacts topic and keeps a basic Knowledge Repository service/capability statement in core while saying that more detailed treatment is available in CRMI and the Quality Measure IG. The current CRMI Artifact Repository Service page contains the formal ShareableArtifactRepository, PublishableArtifactRepository, and AuthoringArtifactRepository capability statements. Later Applied issue FHIR-53084 updated the same artifact distribution topic to informative guidance and reworded recommendations, but it preserved the CRMI capability links added for FHIR-32643.

AutoFHIR reconciliation:
No source change was made. The current build-scoped Clinical Reasoning source already provides the core discussion and CRMI references requested by the applied Jira comments, and duplicating the CRMI formal capability statements in FHIR core would contradict the chosen split between core overview guidance and CRMI-owned formal conformance content.

Recommendation:
Keep this audit commit as-is. If a future work group decision wants the Shareable/Publishable/Authoring repository capability statements copied or re-owned by FHIR core, that should be handled as a new substantive change coordinated with CRMI; FHIR-32643 itself is already correctly represented.
