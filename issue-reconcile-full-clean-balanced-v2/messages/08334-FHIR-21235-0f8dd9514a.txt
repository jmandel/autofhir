FHIR-21235: Audit Device status separation

Issue request:
FHIR-21235 was a Published OO change request, resolved Persuasive with Modification for R5, asking to separate active/inactive device state from implanted/explanted association state. The final resolution moved beyond the original proposed Device.patient rename and inactive-status note removal, instead directing Device.operationalStatus and Device.associationStatus backbones with value and reason subelements.

Initial application:
No standalone Jira-keyed FHIR-21235 commit was found. Commit a7f2575daa, "Device updates", explicitly listed FHIR-21235 as preapplied through the FHIR-26309 summary and added the R5-era Device.operationalStatus and Device.associationStatus value/reason rows to the old Device spreadsheet. The FHIR-26375 follow-up issue later confirmed in Jira comments that Device already had record status, operationalStatus, and associationStatus.

Additional context:
Later final Device decisions superseded the exact R5-era element placement without reversing the status-separation intent. FHIR-32557 clarified that Device.status is about the Device record and added Device.availabilityStatus for the device itself. FHIR-36195 revised the old operationalStatus model. FHIR-46962 then explicitly corrected R6 narrative because operationalStatus and associationStatus no longer exist on Device. Current R6 source keeps Device and DeviceAssociation active in source/fhir.ini; Device.status is record status, Device.availabilityStatus is device availability, and DeviceAssociation.associationStatus now carries association/operational states. FHIR-48532 created that DeviceAssociation.associationStatus split, and FHIR-48713 added an abandoned code for implanted devices that remain in the patient and are no longer in use.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The current active source no longer says Device.status inactive means an implanted device was removed, and it already represents implanted/explanted/attached/on/off/standby/defective/abandoned separately from Device record status. Reintroducing Device.operationalStatus or Device.associationStatus on Device would conflict with later Applied/Published R6 decisions.

Recommendation:
Keep this audit commit as-is. No core source follow-up is recommended for FHIR-21235 unless OO opens a new issue to revise the current Device.status, Device.availabilityStatus, and DeviceAssociation.associationStatus model.
