FHIR-23785: Audit trusted expansion text ownership

Issue request:
FHIR-23785 was a Published FHIR-core/Vocabulary change request, resolved Persuasive with Modification for R5, asking to revise the valueset-trusted-expansion extension text. The final resolution said that when the designated valueset-authoritativeSource cannot provide a valid expansion, valueset-trusted-expansion indicates the base URL of a FHIR server that is an alternate trusted source where expansion may be obtained, either through ValueSet $expand or through the ValueSet endpoint returning a persisted expansion, and that the extension should only be used when the authoritative source lacks a FHIR service capable of generating or returning a valid FHIR value set expansion.

Initial application:
No core commit message was found that explicitly names FHIR-23785. Core commit 9fca6ca36fefa544491b1efc7fdb1530333ed78b applied the FHIR-23785 comment text to source/valueset/structuredefinition-extension-valueset-trusted-expansion.xml along with the companion FHIR-27848 url datatype change, but that commit was reverted; commit 054eabf3116825c0f65107fedff6668447bf43a1 re-applied the same source change. Later core commit ade907ca5b1bc08efb093bc524c5b00bdc7fa5ac, explicitly listing FHIR-27028, replaced the broader FHIR-23785 wording with the approved endpoint-focused clarification. Core commit dd468d4f1799dd79819315b211588ef1cf4586e0 then removed valueset-trusted-expansion and the other extension StructureDefinitions from the FHIR-core source tree.

Additional context:
The current core build still includes ValueSet as an active resource, but source/fhir.ini has no active valueset-trusted-expansion StructureDefinition source and current core source searches find only the OID registration in source/oids.ini. The current owning artifact is in HL7/fhir-extensions at input/definitions/ValueSet/StructureDefinition-valueset-trusted-expansion.xml. That external source carries the later FHIR-27028 endpoint comment and the FHIR-40707 definition/description clarification, and Extension.value[x] remains url as audited separately for FHIR-27848. The combined branch already contains external-repo audit commits for FHIR-27848 and FHIR-27028, so this seed is limited to the original text issue.

AutoFHIR reconciliation:
This commit intentionally makes no source change in the FHIR-core checkout. Re-adding or editing the StructureDefinition in core would reverse the current extension ownership split, and the current external artifact should be interpreted through the later FHIR-27028 and FHIR-40707 decisions rather than by restoring the exact older FHIR-23785 wording.

Recommendation:
Keep this external-repo audit as-is for core. No FHIR-core follow-up is needed for FHIR-23785; any future wording or status cleanup for valueset-trusted-expansion should be handled in HL7/fhir-extensions, especially if the work group wants to revisit persisted-expansion retrieval language or the later external retirement/status state.
