FHIR-7367: Audit Medication compartment clarification

Issue request:
FHIR-7367 was Published/Persuasive with Modification for the 2015 DSTU1 ballot. It asked to clarify that Medication is non-patient-specific even though "patient medication list" is a common phrase, and the final resolution said to clearly show each resource's compartment membership and discuss the consequences on the compartments page.

Initial application:
The Jira application comment points to svn revision 6453. In git this is commit 3be288e561fbfb7b91f0568b3db68023e53784b0, "@7367 - note about resources not in compartments", which added a paragraph to the old compartments page explaining that Medication, Substance, and Location are not in any compartment and that MedicationAdministration links the Medication to the patient. When CompartmentDefinition became the current compartment page source, commit 373b612eb89afded7ed828b553d4b058822f1659 carried that paragraph into source/compartmentdefinition/compartmentdefinition-notes.xml.

Additional context:
The current source/compartments.xml matrix lists Medication with no compartment parameters while MedicationAdministration, MedicationDispense, MedicationRequest, and MedicationStatement have patient/subject-related parameters. Later FHIR-51725 clarified the current compartment semantics: listed resources with .param entries are in the compartment, listed resources without .param entries are outside it, but servers may still make outside resources available through _include or local convention. That later issue is already represented on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current build-scope source already contains the requested Medication explanation on the CompartmentDefinition notes page, the authoritative compartment matrix already distinguishes Medication from patient-linked medication event/request resources, and the later FHIR-51725 text prevents the requested clarification from being misread as saying Medication is formally inside the Patient compartment.

Recommendation:
Keep this empty audit commit as-is. No core source follow-up is needed for FHIR-7367 unless a future work group decision changes the broader compartment semantics.
