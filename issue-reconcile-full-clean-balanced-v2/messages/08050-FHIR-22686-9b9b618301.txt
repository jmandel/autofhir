FHIR-22686: Audit que-11 invariant wording

Issue request:
FHIR-22686 was a Published FHIR-core Questionnaire change request, resolved Not Persuasive with Modification for R5. The original request asked to remove invariant que-11 because it prevented using item.initial when a question also had answerOption. The final decision kept the invariant and instead required its English description to explain that if answerOption is present, initial[x] must be missing and answerOption.initialSelected should be used instead.

Initial application:
The issue was applied by 8e4b30c6569a4e16ab1523a76f7b6365e0d4feff, which changed the que-11 human text in source/questionnaire/structuredefinition-Questionnaire.xml to say that initial[x] cannot be present when answerOption is present and to use answerOption.initialSelected instead. The current source later rewrites the element name as initial rather than initial[x], but it preserves the same rule through the que-11 human text and expression.

Additional context:
source/fhir.ini lists Questionnaire as an active resource, so source/questionnaire/structuredefinition-Questionnaire.xml is in current build scope. The SDC 2020-06-11 minutes confirm the 9-0-0 decision to reopen FHIR-22686 and keep the answerOption.initialSelected mechanism. Zulip discussions from 2020 and 2022 show implementation confusion and a possible revisit idea, but no applied or published reversal was found. FHIR-27803 removed a misleading initialSelected comment and FHIR-41174 added a repeat-count invariant; both are related Questionnaire/initialSelected decisions already represented on the combined branch and neither changes que-11.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative Questionnaire StructureDefinition still has que-11, still prohibits answerOption and initial together with expression answerOption.empty() or initial.empty(), and still directs implementers to answerOption.initialSelected. The wording difference between initial and initial[x] is not a semantic defect because the current element being tested by the expression is Questionnaire.item.initial.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for FHIR-22686 unless a future work group decision explicitly revisits whether answerOption.initialSelected or initial should be the required defaulting mechanism.
