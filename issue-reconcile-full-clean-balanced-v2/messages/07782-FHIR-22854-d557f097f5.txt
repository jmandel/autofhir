FHIR-22854: Audit ExampleScenario response cardinality

Issue request:
FHIR-22854 was Published with a Persuasive with Modification resolution. It requested widening ExampleScenario.process.step.operation.response to 0..* and adding a usage note for cases such as v2 accept and application acknowledgements. The resolution explicitly left ExampleScenario.process.step.operation.request at 0..1.

Initial application:
The issue was applied by git commit 05356b0c69dd058fa1eddb990a5a393ab8442a87, which changed source/examplescenario/structuredefinition-ExampleScenario.xml to add the multiple-response comment and set operation.response max="*".

Additional context:
ExampleScenario is active in the current build via source/fhir.ini. A later Published issue, FHIR-37895, revisited the same element and explicitly concluded that response should be limited to synchronous responses, with later asynchronous responses represented by subsequent steps. Git commit 022f97b17fd7c471d51097c7e1fd60bf24d421ed applied that later decision by changing the definition to synchronous response, commenting out the FHIR-22854 note, and returning max to "1"; c1dda1d5fd1c53b64abb0f0eb8d68392621895cd later removed the dead commented note during cleanup. The current combined branch has response 0..1 and no multiple-response note, matching the later decision.

AutoFHIR reconciliation:
No source change was made. Restoring FHIR-22854's 0..* cardinality would undo FHIR-37895, so this empty audit commit records that the original FHIR-22854 change is superseded in the current specification.

Recommendation:
Keep this commit as-is. Do not re-widen ExampleScenario.process.step.operation.response unless the work group reverses or narrows FHIR-37895.
