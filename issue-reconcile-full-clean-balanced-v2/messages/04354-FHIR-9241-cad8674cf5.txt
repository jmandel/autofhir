FHIR-9241: Audit Contract search parameter names

Issue request:
FHIR-9241 was a Published/Persuasive DSTU2 technical correction for FHIR-core-Contract. It reported that some Contract elements had been renamed but the search parameters connected to those elements had not been renamed.

Initial application:
No commit message uses the exact Jira key, but SVN-derived commit cd16d2ab019e19045b5a0bd96722731f4211ef1c explicitly cites CP 9241 and updates the Contract spreadsheet search rows: the search parameter for Contract.subject became topic/Contract.topic, the search parameter for Contract.party.entity became agent/Contract.agent.actor, and authority, domain, and issued rows were added alongside the existing identifier and signer rows.

Additional context:
Contract remains in the current build through source/fhir.ini. The current Contract model is no longer the DSTU2 model: Contract.subject is again a current element, Contract.signer.party is current, Contract.authority/domain/issued/instantiatesUri/url/status/identifier are current, and there is no stale Contract.party or Contract.agent search parameter in the active search parameter bundle. No relevant Zulip or Confluence evidence was found that changes the Jira/source/history conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active source/contract/bundle-Contract-search-params.xml search parameters all use current element paths and expressions that resolve in source/contract/structuredefinition-Contract.xml, so applying the old DSTU2 rename again would make the current specification less correct.

Recommendation:
Keep this empty audit commit as-is. If the work group later wants a search parameter over current Contract.topic[x], that should be raised and evaluated as a new feature or correction rather than treated as incomplete application of FHIR-9241.
