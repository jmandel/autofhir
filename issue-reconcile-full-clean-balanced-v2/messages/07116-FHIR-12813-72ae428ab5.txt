FHIR-12813: Audit requester delegation guidance

Issue request:
FHIR-12813 was a Published FHIR-core change request for DSTU2 DiagnosticRequest and MedicationPrescription asking for RequestOnBehalfOf, RequestedBy, or requestSubmittedBy support so systems could distinguish the authorized clinician from staff entering the request. The final Not Persuasive with Modification disposition rejected a new core element or extension because Provenance manages intermediaries, allowed local extensions, and asked for requester comments clarifying that delegation is generally handled through Provenance.

Initial application:
The explicit implementation commit 8f78b25c34a539d54ff592c1cfae64b716381bfd, titled "[#12905], [#12813]", added the approved delegation/Provenance sentence to ProcedureRequest.requester. That historical ProcedureRequest/DiagnosticRequest lineage is now represented in the current build by ServiceRequest, whose requester comment still contains the delegation/Provenance guidance. No FHIR-12813-tagged commit was found for MedicationRequest, but MedicationRequest had already been changed through Pharmacy workflow issue FHIR-10456 to model requester choices and a recorder for the person entering an order on behalf of another.

Additional context:
source/fhir.ini lists request, medicationrequest, and servicerequest as active current-build artifacts. Current ServiceRequest.requester says the requester is the authorizer, not the dispatcher, and that delegation is generally managed through Provenance. Current MedicationRequest.requester identifies the entity responsible for activation, and MedicationRequest.recorder specifically captures the person who entered the order on behalf of another individual for verbal or telephone orders. The Request pattern itself contains a generic requester row but the FHIR-12813 resolution only called for creating a future tracker to consider pattern-wide guidance; no final linked tracker or community record was found requiring a broader current-core edit.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current build preserves the applied OO guidance for the DiagnosticRequest/ProcedureRequest successor and has a medication-specific mechanism for the MedicationPrescription use case, so adding a duplicate requester comment or a broad request-pattern rule would be redundant and could conflict with MedicationRequest.recorder semantics.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-12813 unless a work group separately decides to add generic Request-pattern delegation guidance; that would be a new broader decision rather than a missed application of this issue.
