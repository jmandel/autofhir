FHIR-16138: Audit specimen code extension ownership

Issue request:
FHIR-16138 was a Published FHIR-core Observation change request with a Persuasive with Modification resolution. It asked to support a code-only way to identify the specimen for an Observation, and the approved resolution was to add a specimenCode extension when neither a Specimen resource nor a precoordinated Observation.code specimen type was wanted.

Initial application:
The issue was pre-applied in core by commit 99532b4c0a, which added an Observation specimen-code/specimenCode extension row with CodeableConcept value and v2-0487 example binding. Later core history generated a standalone StructureDefinition-observation-specimenCode.xml, and commit dd468d4f17 removed that and the other extension definitions from the R5 core source as part of moving extensions out of the core checkout.

Additional context:
The current core build still owns Observation and Specimen, but not the observation-specimenCode extension definition. Observation.specimen remains a Reference to Specimen or Group, while Specimen.type is a CodeableConcept bound to the specimen type value set. The extension definition is now in the FHIR Extension Pack checkout, where FHIR-44334 retired/deprecated it because a referenced Specimen resource can represent just the code; FHIR-52988 later clarified the same replacement guidance by pointing to Specimen.type.

AutoFHIR reconciliation:
This is an empty external-repo audit commit. No core source was changed because the only artifact created for FHIR-16138 is no longer owned by the current FHIR core build, and the current Extension Pack source already records the later OO decision to retire/deprecate that extension and use Specimen.type instead.

Recommendation:
Keep this audit commit as-is. There is no follow-up core source change for FHIR-16138; any future changes to observation-specimenCode belong in the FHIR Extension Pack and should account for the later FHIR-44334/FHIR-52988 decisions.
