Issue request:
FHIR-36240 was Published/Persuasive for FHIR-core Consent. It requested adding a new root element Consent.period with cardinality 0..1, short text "Effective period for this Consent", and definition "Effective period for this Consent Resource and all provisions unless specified in that provision".

Initial application:
No git commit message explicitly mentioned FHIR-36240, but commit d4aba66bf49bed3c8b5ccfc888c4d313c91913f3 added the requested Consent.period element to source/consent/structuredefinition-Consent.xml with the requested cardinality, Period type, short text, and definition.

Additional context:
Consent is active in the current build through source/fhir.ini. The parent omnibus issue FHIR-31910 explains that the period request was split out because the work group wanted an overall consent period on the root rather than forcing that meaning into a provision. Later Consent work on the combined branch updated the provision-period comment to point to Consent.period for consent-wide effective time. Later search-parameter work kept the Consent period search parameter scoped to provision periods, so broadening that search parameter is not part of this seed decision.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current StructureDefinition already contains root Consent.period 0..1 as a Period with the approved short and definition, and the neighboring Consent.provision.period comment now directs consent-wide effective time to Consent.period.

Recommendation:
Keep this no-change audit commit as-is. No core source follow-up is needed for FHIR-36240; if the work group wants search-by-root-Consent.period behavior, that should be handled as a separate search-parameter decision rather than inferred from this element-addition issue.
