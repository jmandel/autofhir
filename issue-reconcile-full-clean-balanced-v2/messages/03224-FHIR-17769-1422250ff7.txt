FHIR-17769: Audit MedicationRequest substitution type choice

Issue request:
FHIR-17769 was a Published/Persuasive Pharmacy WG change request raised against STU3 MedicationPrescription/MedicationRequest substitution. The reporter noted that using substitution.reason to say "All substitution allowed", "Stay in drug class", "Same Active Ingredient", or "No Substitution" seemed useful but did not fit the reason definition. The approved resolution was to add a CodeableConcept choice to substitution.allowed[x] with an ActSubstanceAdminSubstitutionCode binding so the type of permitted substitution is carried by allowed[x], not by reason.

Initial application:
The Jira comment identifies merge commit 65133c5c9a9c6b94e85467b69529239812f98374 as the application. The underlying commit e1b82bc5a61a35b623c05f0ac408111209e5c0bb, whose subject includes GF 17769, changed the then-authoritative medicationrequest-spreadsheet.xml from MedicationRequest.substitution.allowed:boolean to MedicationRequest.substitution.allowed[x]: boolean | CodeableConcept, added the MedicationRequestSubstitution binding name, and added an example binding to http://terminology.hl7.org/ValueSet/v3-ActSubstanceAdminSubstitutionCode.

Additional context:
MedicationRequest is an active current-build resource in source/fhir.ini. The current StructureDefinition source has MedicationRequest.substitution.allowed[x] with boolean and CodeableConcept types and a binding to the ActSubstanceAdminSubstitutionCode value set, while MedicationRequest.substitution.reason remains a separate CodeableConcept for why substitution should or should not be made. A later Published/Persuasive Pharmacy issue, FHIR-32491, intentionally tightened the same allowed[x] binding from example to preferred; that later issue is already represented on the combined branch by commit 0170cfff6efbb2183c105c84b33a4920b5eea042. The linked Zulip thread for FHIR-17769 supports adding a substitution type code element, and no Confluence reference or later direct conflict for FHIR-17769 was found.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already implements the FHIR-17769 design by making substitution.allowed[x] the place for substitution type codes, and the apparent stronger preferred binding is explained by the later FHIR-32491 decision rather than by incomplete application of FHIR-17769.

Recommendation:
Keep this no-change audit commit as-is. No core source follow-up is needed for FHIR-17769 unless Pharmacy opens a new issue to revisit the substitution type value set or the later preferred binding.
