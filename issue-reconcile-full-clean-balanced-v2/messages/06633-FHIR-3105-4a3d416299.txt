FHIR-3105: Audit Questionnaire publisher metadata

Issue request:
FHIR-3105 was a Published/Persuasive with Modification Patient Care change request asking Questionnaire to provide a way to capture the person or organization that designed the questionnaire, instead of overloading an author element that was also used for filled-out answers. The final DSTU1 decision was to use publisher and contact information, remove a distinct designer concept, add Questionnaire copyright, and keep answer authorship on QuestionnaireResponse/QuestionnaireAnswers.

Initial application:
The Jira-tagged SVN import commit 227cf05278be5788737854e9fa76bcbb663c32b3 ([3105] - Added telecom, SVN r4105) applied the issue to the old Questionnaire spreadsheet by broadening publisher from an organization to an organization/individual and adding Questionnaire.telecom/contact information for the publisher. Subsequent source refactors moved the active definition into structuredefinition-Questionnaire.xml and split QuestionnaireAnswers into QuestionnaireResponse.

Additional context:
Questionnaire and QuestionnaireResponse are active current-build resources in source/fhir.ini. The current Questionnaire source has publisher/contact metadata, copyright/copyrightLabel metadata, and no active Questionnaire.author, Questionnaire.designer, Questionnaire.authority, or Questionnaire.telecom element. QuestionnaireResponse.author remains the element for the individual or device that received and recorded answers. Jira neighborhood and community searches found no later final decision that reintroduces a Questionnaire designer element or reverses the publisher/contact approach.

AutoFHIR reconciliation:
This audit commit makes no source change because the current source already preserves the applied issue outcome in the current model: Questionnaire records steward/publisher and contact/copyright metadata, while QuestionnaireResponse separately records answer authorship. Adding a new designer or author element now would conflict with the historical resolution that explicitly removed designer as a core element.

Recommendation:
Keep this no-change audit commit as-is. Future requests for questionnaire designer/author metadata should be handled as a new work-group decision or, if outside the core 80% rule, by an extension rather than by changing FHIR-3105 retroactively.
