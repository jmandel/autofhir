FHIR-25179: Audit ValueSet include.valueSet intersection wording

Issue request:
FHIR-25179 was Published/Persuasive for R5 and asked Vocabulary to change ValueSet.compose.include.valueSet from union semantics to intersection semantics when multiple valueSet references appear within a single compose.include, plus update the Value Set Expansion guidance so the union mechanism remains separate include entries.

Initial application:
The source history shows the R5 ValueSet work first applied the requested wording in 9fca6ca36f, that merge was reverted in 5161923416, and the same source changes were reapplied in 054eabf311. The current build-scope ValueSet resource source keeps the intersection definition and the expansion algorithm uses a collection of imported value-set result sets whose intersection is added to the expansion.

Additional context:
FHIR-30574 later raised the same apparent inconsistency and was closed Resolved - No Change / Not Persuasive as a duplicate/background issue. A 2022 terminology Zulip thread questioned the compatibility impact, but the discussion recorded that FHIR-25179 remained the intended rule for future value sets and tooling was adjusted for forward processing with legacy handling. Confluence minutes in 2022 show the work group revisited the question, but no discovered minutes or Jira record reversed the Published FHIR-25179 decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active ValueSet resource is in build scope through source/fhir.ini, source/valueset/structuredefinition-ValueSet.xml already says multiple valueSet references in one include use the intersection of referenced contents, and source/valueset/valueset-notes.xml already describes producing value-set result sets and adding their intersection to the expansion. An exact source search found no remaining stale union definition phrase.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-25179 unless Vocabulary reopens the broader normative/tooling compatibility question in a new final Jira decision.
