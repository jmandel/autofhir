FHIR-37405: Audit ImagingSelection category binding

Issue request:
FHIR-37405 is Published with resolution Persuasive. It asked to update ImagingSelection.category so its terminology binding used the same binding as ImagingSelection.code and to remove the DICOM tag mapping from ImagingSelection.category.

Initial application:
The Jira comment links merge commit c138fb1b9ed930251866ab1da3be7d524b3fb1d4. The source-changing implementation in that merge, e89adf0784a54c08ffd911a3263cf2c60ef430cb, changed ImagingSelection.category from the ImagingSelectionCategory example binding with a DICOM Concept Name Code Sequence mapping to the ImagingSelectionCode binding, the same DICOM CID 7010 value set then used by ImagingSelection.code, and removed the category DICOM mapping.

Additional context:
ImagingSelection is active in the current build through source/fhir.ini. Later Applied R6 issues refined the same code/category area: FHIR-48095 and FHIR-48097 made ImagingSelection.category Preferred while retaining the DICOM Key Object Selection Document Title value set, and FHIR-47966 later narrowed its final resolution to moving ImagingSelection.code, not category, to the THO Image Reference Type value set. Those later issue decisions are already represented on the combined branch and explain why category no longer literally matches the current code value set.

AutoFHIR reconciliation:
No source change was made. The authoritative current StructureDefinition still reflects the FHIR-37405 application by using the ImagingSelectionCode binding name on ImagingSelection.category and by omitting the category DICOM mapping; the later difference between category's DICOM CID 7010 value set and code's THO image-reference-type value set is intentional under subsequent Applied decisions rather than a missed FHIR-37405 edit.

Recommendation:
Keep this audit commit as-is. Do not change ImagingSelection.category to the current ImagingSelection.code THO value set for FHIR-37405 unless II reopens the later FHIR-48095/FHIR-48097/FHIR-47966 decisions and explicitly chooses to align the two elements again.
