FHIR-13569: Audit AuditEvent period support

Issue request:
FHIR-13569 was a Published/Persuasive STU3 Security WG change request asking for a top-level AuditEvent period element like Provenance. The approved resolution was to add the period line from Provenance to AuditEvent.

Initial application:
The request was applied in git commit 84f8086d21facb3551bfb28481156250510ae48b, whose message includes GF#13569 among Security WG updates. That commit added AuditEvent.period as a 0..1 Period with Provenance-style wording in the then-authoritative AuditEvent spreadsheet source.

Additional context:
AuditEvent is active in the current build via source/fhir.ini. Later Published/Persuasive issue FHIR-32444 intentionally changed AuditEvent.period to the Provenance-style AuditEvent.occurred[x] choice of Period or dateTime for R5, with a Security WG block vote recorded 8-0-1. The current source preserves backward mapping from AuditEvent.period to AuditEvent.occurred[x], and the active AuditEvent definition and search parameter both use AuditEvent.occurred[x] with Period support.

AutoFHIR reconciliation:
This audit commit makes no source change. The current specification already satisfies the semantic request for an AuditEvent period through AuditEvent.occurred[x]; reintroducing AuditEvent.period would conflict with the later FHIR-32444 rename and choice-type decision.

Recommendation:
Keep this no-change audit. No follow-up is needed for FHIR-13569 unless the work group wants to revisit the later FHIR-32444 naming/type decision.
