FHIR-39488: Audit search prefix existence wording

Issue request:
FHIR-39488 was Published/Persuasive for R5 by FHIR-I. It asked whether the Search page prefix table's "resource value exists" condition also applied to the eq prefix and requested removing repeated wording from each prefix row if the condition applied to all prefixes.

Initial application:
The issue was applied in untrailed history by commit dcfcc35738, which added "exists" to the eq row. Minutes from the January 2023 FHIR-I WGM record the persuasive vote. Immediately afterward, same-page cleanup in commit c8ca272252 removed the repeated "resource value exists" phrase from every row and added the shared note that prefixes always test against values present in elements, matching the issue's request to state the rule once.

Additional context:
Later Search page prefix work, including FHIR-40319's R6 clarification and the combined-branch FHIR-40319 reconciliation, expanded the prefix table with boundary interpretations and examples but retained the shared existence note. source/search.html is the current core Search page source, and source/fhir.ini's active search-rules section explicitly points maintainers to update search.html when search-rule entries change.

AutoFHIR reconciliation:
No source change was made. The current Search page already says that prefixes always test against values present in elements and that prefix-based tests against missing elements fail, while the eq row remains aligned with the other prefix descriptions without repeating the existence phrase.

Recommendation:
Keep this empty audit commit as-is. No follow-up is needed for FHIR-39488 unless a future work group decision changes the general prefix/missing-value semantics.
