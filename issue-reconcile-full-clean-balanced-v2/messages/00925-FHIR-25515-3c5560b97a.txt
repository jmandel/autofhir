FHIR-25515: Confirm Expression.name variable-name rule

Issue request:
FHIR-25515 was Published as Not Persuasive with Modification. It asked to expand the normative id datatype pattern to include underscore for Expression variable names; the accepted resolution instead kept id unchanged and directed Expression.name to become code with an invariant matching '[A-Za-z][A-Za-z0-9_]{0,63}', allowing underscore while requiring an initial letter and excluding hyphen and dot.

Initial application:
Git history shows f71b77cc4c applied the Jira-specific change in source/datatypes/expression.xml by changing Expression.name from id to code and adding the variable-name invariant. A later local fix, 6f4b000da0, preserved the same regex while guarding the invariant with name.hasValue() so the optional element remains valid when absent.

Additional context:
source/fhir.ini actively lists Expression as a datatype, maps expression to metadatatypes, and marks Expression normative, so source/datatypes/expression.xml is in the current core build scope. The cited Zulip thread records the original underscore request for variable names, and MnM WGM minutes record the Not Persuasive with Modification vote. Later FHIR-51752 references this change and confirms the code datatype remains intentional, but that issue is only Resolved - change required and asks for a future explanatory note, so it is context rather than a source-edit mandate in this applied/published reconciliation run.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current source already has Expression.name typed as code and the invariant name.hasValue() implies name.matches('[A-Za-z][A-Za-z0-9\\_]{0,63}'), which implements the FHIR-25515 resolution without changing the normative id datatype.

Recommendation:
Keep this audit as-is. Do not change the id datatype regex for FHIR-25515. If FHIR-51752 later enters an applied/published reconciliation scope, handle its explanatory note separately without undoing the Expression.name code-and-regex decision.
