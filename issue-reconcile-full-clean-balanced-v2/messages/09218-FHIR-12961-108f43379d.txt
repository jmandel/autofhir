FHIR-12961: Audit validation misuse warning

Issue request:
FHIR-12961 was a Published/Persuasive FHIR-core validation-page change request asking the validation page to warn against improper runtime use of validation, including performance and data-quality harms, security needs, runtime validation choices, and secondary-use impacts.

Initial application:
The issue was applied in SVN revision 13269, preserved in git as 26c933c82f1c19283a7d2e1642aa3a2abe112085, whose subject explicitly includes GF#12961 and which added the "Correct Use of Validation" section to source/validation.html plus a security-page narrative-validation clarification.

Additional context:
Current source/validation.html remains in the active documentation navigation and still warns that production validation can be computationally demanding, can lose critical healthcare data, and can fail historical data, while also saying security-related validation and control-point validation may be important, recommending Postel's law, and advising careful runtime choices. Current source/security.html also includes an Input Validation security checklist item and a narrative-security subsection telling implementers to validate narrative and manage external references. The older validator-jar details, including the brief runtime-options note added with GF#12961, were intentionally removed from the spec page by later Published issue FHIR-31735, which moved tool-specific validator documentation to Confluence; this does not leave a current-spec gap.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current built source already conveys the WG-approved warning and related security guidance, and adding more prose would be redundant rather than corrective.

Recommendation:
Keep this no-change audit commit as-is. Future work, if desired, should happen in current validator/tooling documentation rather than by duplicating already-present validation misuse guidance in the core spec.
