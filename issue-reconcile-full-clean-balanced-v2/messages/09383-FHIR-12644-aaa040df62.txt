FHIR-12644: Audit translation extension enhancement

Issue request:
FHIR-12644 was a Published/Persuasive FHIR-core DSTU2 change request for the translation extension. It asked to bind the lang slice to the FHIR language value set, allow the content slice to carry string or markdown, explicitly allow the extension on markdown elements, and state that the translation content type must match the translated element type.

Initial application:
The Jira comment records svn revision 11190. In the converted git history, commit 9e81a801abf6308133485c9f025ba09c5d8c9ef3 (#12644 - allow translations to be markdown) is git-svn build@11190 and changed the then-current general extensions spreadsheet from string to string | markdown for translation content and added the type-match comment. Related FHIR-10650 was applied nearby in commit 3c3c39d1e9 by adding publication/tooling support for translatable elements.

Additional context:
The translation StructureDefinition no longer lives in this FHIR-core source tree: commit dd468d4f17 removed extensions from the R5 core source, and the current authoritative definition is in the FHIR Extension Pack. Current core source still references the external translation extension from the Languages page and marks string and markdown as translation-capable in fhir.ini. Later FHIR-49722 is an Extension Pack clarification about code context and type matching; it does not reverse the FHIR-12644 string/markdown and markdown-context decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Extension Pack translation definition has contexts for string and markdown, has the lang value bound to all-languages with languages as a starter set, allows content.value[x] as string or markdown, and carries type-match guidance in the extension definition/comment. The current core source points readers to that external definition and marks the relevant primitive types as supporting translations, so adding duplicate core prose or resurrecting the moved core extension source would not improve the current build.

Recommendation:
Keep this audit commit as-is for FHIR-12644. Any follow-up about the later FHIR-49722 warning-invariant request should be handled in the FHIR Extension Pack rather than as a FHIR-core source edit for this issue.
