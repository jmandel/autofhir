FHIR-10975: Audit removed ST language extension

Issue request:
FHIR-10975 was a Published/Persuasive FHIR-core correction for DSTU2 SDC #38. It asked that the DataElement language extension text for http://hl7.org/fhir/StructureDefinition/iso21090-ST-language say it identifies the language of a particular string, not a particular value of any other data type, because the extension context was string.

Initial application:
No current git commit with an explicit FHIR-10975 tag was found. Jira records Grahame Grieve's 2016-11-29 note that the extension had been removed, and later SDC history shows broad restructuring of the SDC guide rather than a current active core extension definition for this URL.

Additional context:
Current core build scope does not include DataElement as an active resource in source/fhir.ini, and the active source tree contains no current iso21090-ST-language definition or stale SDC wording. The only remaining core match is the DSTU2 history bundle under tools/history/release2/extension-definitions.xml, where the extension is already constrained to context string and its definition says "The language in which the string is expressed." The FHIR Extension Pack checkout also has no matching current extension definition.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Editing the historical release2 snapshot is unnecessary because it already has the corrected string-specific semantics, and editing active core source is impossible because the obsolete DataElement/SDC extension text is no longer in current build scope.

Recommendation:
Keep this audit commit as-is. No follow-up core source work is needed unless a future publication process intentionally revives the retired SDC/DataElement extension material; in that case, the revived source should continue to limit iso21090-ST-language to string.
