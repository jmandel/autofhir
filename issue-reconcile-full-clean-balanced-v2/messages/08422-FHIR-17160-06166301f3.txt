FHIR-17160: Audit ExampleScenario numbering documentation

Issue request:
FHIR-17160 was a Published/Persuasive with Modification FHIR-I change request for STU3. It reported that ExampleScenario.process.step.operation.number was a string and suggested an integer, unsignedInt, or positiveInt data type; the accepted resolution was to leave it as string for substeps but document its use more carefully.

Initial application:
Jira records SVN #14774. In git, fa09d5c5a364d1aa82d9a4cf91e0d3dead5616bb changed the ExampleScenario spreadsheet definition for operation.number from "The sequential number of the interaction" to "The sequential number of the interaction, e.g. 1.2.5", preserving the string type while clarifying non-integer/substep-style labels.

Additional context:
ExampleScenario is active in the current build configuration, and source/fhir.ini marks ExampleScenario normative. Later Published issue FHIR-37895 moved operation.number to ExampleScenario.process.step.number because the number applies to any step, not just operation steps; fhir.ini now maps the old operation.number as removed and the new step.number as active. The current StructureDefinition defines ExampleScenario.process.step.number as string, says "The sequence number of the step, e.g. 1.2.5.", and explicitly comments that numbers do not have to be numeric. Later FHIR-44497 refined "sequential" to "sequence" and is already represented on the combined branch, so it is related context rather than a new decision here.

AutoFHIR reconciliation:
This audit commit makes no source change. The current source already implements the accepted FHIR-17160 outcome: the number remains a string, the superseding step-level element is the current build-scope location, and the definition/comment now document dotted and non-numeric labels more carefully than the original application.

Recommendation:
Keep this no-change audit commit as-is. Do not change the current element to an integer-like type or recreate operation.number; any future wording adjustments to ExampleScenario step labels should be handled under their own tracker, as FHIR-44497 was.
