FHIR-41410: Audit ServiceRequest family Group support

Issue request:
FHIR-41410 was an Applied/Persuasive with Modification OO change request for R6. It asked to add Group as a permitted ServiceRequest requester and performer reference type so a family or household can request or perform care, and to add comments limiting that use to family/household Groups rather than practitioner groups.

Initial application:
The issue was applied by HL7/fhir merge commit e85984d3ce957e0948964ae2a73f1974275d20d7 for PR #3283, which added Reference(Group) to ServiceRequest.requester and ServiceRequest.performer, updated both comments, and added the corresponding ServiceRequest request-pattern mapping exceptions.

Additional context:
ServiceRequest is an active build resource in source/fhir.ini. The broader OO family/household discussion and Zulip thread support the same limited use: Group can act only in selected family/household cases, and groups of practitioners should continue to use more specific resources. Later ServiceRequest edits have not removed the Group target profiles or the limiting comments.

AutoFHIR reconciliation:
This audit made no source change. The current authoritative ServiceRequest XML already includes Group in both requested target profile lists, has comments limiting Group to family/household use and excluding practitioner groups, and has matching mapping exceptions for the Request pattern divergence.

Recommendation:
Keep this empty audit commit as-is. No core follow-up is needed for FHIR-41410 unless the work group later reopens the broader family/household Group policy; separate family/household issues for other resources should remain separate decisions.
