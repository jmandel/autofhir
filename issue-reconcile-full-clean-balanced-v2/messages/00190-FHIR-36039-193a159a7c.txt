FHIR-36039: Remove stale RelatedArtifact subset reference

Issue request:
FHIR-36039 was Published/Persuasive with Modification for R5 and asked for multiple RelatedArtifactType value set changes: updated definitions, new relationship codes including documents, specification-of, created-with, and cite-as, deprecation consideration for citation, a FHIR-resource subset value set with an invariant, and documentation that RelatedArtifact is for definitional resources.

Initial application:
Commit bb9b33616984aecc330c7a9ac8d252854387aae4 applied the R5 tracker by expanding the RelatedArtifactType source list, adding the fhir-related-artifact-type subset value set source file, and adding a RelatedArtifact.type comment requiring resource-to-resource uses to draw from that subset. The current R6 source had later reduced RelatedArtifact.type to documentation, justification, citation, predecessor, successor, derived-from, depends-on, composed-of, and part-of, but the old comment still pointed to the now-unbuilt fhir-related-artifact-type ValueSet.

Additional context:
FHIR-50010 later simplified RelatedArtifact for R6 and added resource/profile usage guidance instead of the broad R5 expanded type list. FHIR-49758, FHIR-49759, FHIR-52968, and UP-644 moved broader relationship-code use into resource-specific relatesTo backbones bound to the THO artifact-relationship-type value set. FHIR-38026 records a later no-change decision not to deprecate the old citation code. The current build serves RelatedArtifact.type with the reduced nine-code binding and returns 404 for valueset-fhir-related-artifact-type, so the stale comment created a broken and contradictory conformance instruction.

AutoFHIR reconciliation:
Updated source/datatypes/relatedartifact.xml to remove the stale fhir-related-artifact-type ValueSet mandate while preserving the SHALL NOT guidance against bidirectional FHIR resource links and pointing readers to the RelatedArtifact usage guidance for relationship and target constraints.

Recommendation:
Keep this commit. It preserves the current R6 RelatedArtifact simplification and fixes a broken leftover from the FHIR-36039 application without reintroducing the superseded R5 subset/invariant design. If work groups want a new machine-checkable subset rule for RelatedArtifact after FHIR-50010, that should be a new methodology decision because the current datatype guidance now relies on resource/profile-specific constraints.
