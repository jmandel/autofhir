FHIR-22634: Audit Claim procedure search disposition

Issue request:
FHIR-22634 was a Published Financial Management change request asking for Claim search support by procedure code, with a Persuasive with Modification resolution stating that changes similar to the request had already been applied in R4.

Initial application:
No commit in current git history explicitly mentions FHIR-22634. The relevant prior application is the R4 Claim work that added Claim.procedure.udi and the corresponding procedure-udi search parameter, including Jira FHIR-19484 and the consolidated R4 commit afb5ec66f6 that added Claim.procedure.udi plus the Claim Search worksheet rows for procedure-udi, item-udi, detail-udi, and subdetail-udi. Later source refactors preserved those rows in source/claim/bundle-Claim-search-params.xml.

Additional context:
Claim is an active resource in source/fhir.ini, so source/claim/bundle-Claim-search-params.xml is in current build scope. Current Claim.procedure.procedure[x] still represents the clinical procedure code or Procedure reference, while the active search parameter bundle has procedure-udi but no direct procedure-code token search. Jira FHIR-22634's final disposition did not direct a new R5 procedure-code search parameter; it explicitly accepted the similar R4 change, and no Zulip or Confluence evidence was found that contradicts that disposition.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Adding a new Claim procedure-code token search parameter now would go beyond the published Jira resolution and would create a new normative search surface without a final work-group decision for that exact addition.

Recommendation:
Keep this audit commit as-is. If Financial Management wants direct Claim search by Claim.procedure.procedure[x] or Claim item product/service codes, open or resolve a new tracker with explicit search parameter names, expressions, and whether matching should include CodeableConcept-only values, referenced Procedure.code values, or both.
