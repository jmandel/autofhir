FHIR-37448: Audit current Questionnaire example downloads

Issue request:
FHIR-37448 was Published/Persuasive for R5 after reporting that JSON examples downloads contained generated Questionnaire examples whose choice-type linkId values were duplicated, violating Questionnaire invariant que-2. The reported examples included activitydefinition-questionnaire.json with repeated ActivityDefinition.timing[x]._null linkIds and supplydelivery-questionnaire.json with repeated SupplyDelivery.occurrence[x]._null linkIds.

Initial application:
No Jira-tagged FHIR source commit for FHIR-37448 was found. The R5 published examples-json.zip still contains generated per-resource Questionnaire JSON files and many of those files continue to violate que-2, including the reported ActivityDefinition and SupplyDelivery examples, so the original R5 publication artifact was not corrected in-place.

Additional context:
The generated per-resource Questionnaire artifacts were produced by the external Kindling publisher dependency rather than by checked-in FHIR source files. Current FHIR source still builds the Downloads page and active Questionnaire/ActivityDefinition resources, but current build.fhir.org examples-json.zip no longer contains generated per-resource *-questionnaire.json files. Kindling commit cc11a2d18bc89191caf59af41f73823d04b6fdf2 removed questionnaire generation functionality, and the FHIR source later moved to a Kindling version that includes that removal.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current built specification no longer publishes the invalid generated Questionnaire JSON files, and the remaining local Questionnaire XML examples do not duplicate linkId values except for the intentional invariant failure test fixture.

Recommendation:
Keep this no-change audit for the current FHIR core branch. If HL7 wants to repair historical R5 downloadable artifacts or reintroduce generated profile Questionnaires, that would need separate publication maintenance or Kindling/publisher work with explicit que-2 validation.
