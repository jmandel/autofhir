FHIR-5219: Audit Narrative root cardinality display

Issue request:
FHIR-5219 was a Published/Persuasive DSTU1 ballot comment against the Narrative page. The commenter asked whether narrative should be mandatory because the Narrative structure table showed a 1..1 cardinality at the root; the accepted resolution rejected making all resource narrative mandatory and required removing the misleading root cardinality display.

Initial application:
The issue was applied by the historical SVN-imported commit f5d0affc0fe3b6bd05def7efdbb6ceb5bfce725a, whose message is "#5219 - remove cardinality from root element in tree view". That commit changed the old table generator so non-resource rows with child elements render cardinality only when the path is not the root. The exact generator code no longer exists in the current checkout, but the current Narrative datatype source reflects the same outcome: the root Narrative row has an empty Card. cell while Narrative.status and Narrative.div remain 1..1.

Additional context:
Narrative is still an active infrastructure datatype and type page in source/fhir.ini, and source/narrative.html includes the active [%dt Narrative 1%] table include. The current narrative guidance still says resources that permit narrative MAY include it and SHOULD generally include it for robust human fallback; DomainResource.text remains 0..1 with a best-practice warning rather than a SHALL-level requirement. Corrected searches found no relevant Zulip or Confluence discussion that reverses or narrows the Jira resolution.

AutoFHIR reconciliation:
No source change was made. The current build inputs already avoid the misleading root cardinality and preserve the work group decision not to make narrative mandatory for every resource.

Recommendation:
Keep this no-change audit commit as-is. No follow-up is needed unless a future work group decision separately changes the optional narrative policy or the publisher table-rendering contract.
