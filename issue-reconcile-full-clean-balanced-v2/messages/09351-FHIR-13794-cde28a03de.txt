FHIR-13794: Audit extension examples correction

Issue request:
FHIR-13794 was a Published/Persuasive STU3 correction request for the Extensibility Examples page. It asked to update the examples discussed on Zulip because the extension definitions were missing fixedUri entries for Extension.url, the context/contextType examples were confusing, and the StructureDefinition kind was wrong.

Initial application:
The issue was applied by git-svn commit e8dd2ff9ba714af8e42fdabb3e42fffd923a97a8, matching the Jira comment for svn revision 13367. That commit changed source/extensibility-examples.html by replacing kind="datatype" with kind="complex-type" in the two simple extension definition examples and by adding fixedUri entries for Extension.url to both examples. The context/contextType shape had already been reorganized shortly beforehand by GF#15570, and subsequent source evolution converted the examples to the current context.type/context.expression form.

Additional context:
The cited Zulip thread #implementers > extensions Patient Name Parts records Lloyd McKenzie confirming that the Patient Name Parts example should include a fixed value for Extension.url, that context must remain computable rather than descriptive free text, and that the earlier participation-agreement example was wrong too. The current source/hierarchy.xml includes extensibility-examples.html under the Extensibility page, so the checked source is in build scope. No Confluence references or conflicting community records were found for FHIR-13794 or the fixedUri/contextType search terms.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source/extensibility-examples.html already contains fixedUri entries for the participation-agreement and iso21090-EN-qualifier examples in both XML and JSON, uses kind="complex-type" for extension StructureDefinitions, and uses the current computable context object with type="element" and expression paths. The obsolete contextType and kind="datatype" forms are absent from this page.

Recommendation:
Keep this audit commit as-is. No follow-up source edit is needed for core FHIR unless a future work-group decision changes extension definition examples more broadly.
