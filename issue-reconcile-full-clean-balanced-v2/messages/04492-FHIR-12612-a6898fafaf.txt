FHIR-12612: Audit CarePlan search parameter names

Issue request:
FHIR-12612 was a Published/Persuasive DSTU2 QA issue for Patient Care asking to rename CarePlan search parameter codes activitycode, activitydate, activityreference, and relatedcode to follow the search parameter style guide.

Initial application:
The issue was applied in git commit df58ee3f55a1d3406b2d01e380bf7e0001546445, whose subject explicitly includes "#12612 Rename CarePlan search parameters according to style guide" and whose CarePlan spreadsheet diff changed activitycode to activity-code, activitydate to activity-date, activityreference to activity-reference, and relatedcode to related-code. Later source rework moved CarePlan search parameter definitions from the spreadsheet into source/careplan/bundle-CarePlan-search-params.xml.

Additional context:
CarePlan is still an active resource in source/fhir.ini. In the current source, the obsolete compact names from the Jira request are absent. The current CarePlan search parameter bundle uses the hyphenated style for surviving or historical/commented activity parameters, including activity-reference and activity-scheduled-date; later CarePlan model/search refactors removed the old related-code family from the current active search parameters rather than leaving a stale compact name. No relevant human Zulip or Confluence discussion was found beyond bot/noisy references.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build source already avoids the non-style-guide names identified by FHIR-12612, and reintroducing DSTU2-era activitydate or relatedcode-style parameters would be incorrect for the current CarePlan model.

Recommendation:
Keep this no-change audit commit as-is. No follow-up source work is needed for FHIR-12612 unless a future work group decision reintroduces the removed CarePlan search parameter family under current model semantics.
