FHIR-20391: Audit sdf-20 XPath correction

Issue request:
FHIR-20391 was a Published/Persuasive FHIR-I technical correction for FHIR-core StructureDefinition. It reported that invariant sdf-20's XPath checked the first differential element with `not(f:element[1]/f:slicing)` even though the matching FHIRPath expression checks the root element with `element.where(path.contains('.').not()).slicing.empty()`.

Initial application:
The issue was explicitly applied in commit 011a0f83e202c9b0315015d1bc60cfca0fbcfa13, which changed the StructureDefinition sdf-20 XPath from `not(f:element[1]/f:slicing)` to `not(exists(f:element[not(contains(f:path/@value,'.'))]/f:slicing))`. The current source no longer carries either XPath expression.

Additional context:
FHIR-13768 was the predecessor issue that fixed the FHIRPath expression for the same root-versus-first-element problem. Later ElementDefinition XPath-removal work removed constraint XPath usage from active StructureDefinition resource definitions; source/fhir.ini also records `ElementDefinition.constraint.xpath=XPath removed due to lack of use and maintenance`. A related FHIR-37871 reconciliation already handled remaining ModelInfo sidecar exposure of ElementDefinition.constraint.xpath and is not duplicated here.

AutoFHIR reconciliation:
Made no source change. StructureDefinition is an active resource in source/fhir.ini, and the active source/structuredefinition/structuredefinition-StructureDefinition.xml sdf-20 constraint retains the correct FHIRPath expression but has no XPath field to fix. The obsolete bad XPath only remains in historical release snapshots under tools/history, which are not current source corrections for this R5-applied issue.

Recommendation:
Keep this audit commit as-is. The current build source is correct for FHIR-20391; do not reintroduce XPath just to mirror the historical correction. Any future work on historical release archives or tooling packages should be handled separately from this current-spec reconciliation.
