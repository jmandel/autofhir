FHIR-37596: Audit external CapabilityStatement expectation binding

Issue request:
FHIR-37596 was a Published/Persuasive FHIR-core R5 technical correction. The Jira reported that the R5 capabilitystatement-expectation extension was bound to http://hl7.org/fhir/ValueSet/conformance-expectation and requested the reusable THO value set http://terminology.hl7.org/ValueSet/conformance-expectation instead.

Initial application:
No current FHIR-core commit in this checkout explicitly mentions FHIR-37596. The Jira comment cites Git c31b31e, which is an HL7/fhir-extensions commit that changed input/definitions/multiple/StructureDefinition-capabilitystatement-expectation.xml from the hl7.org/fhir conformance-expectation ValueSet to the THO ValueSet. Core commit dd468d4f removed R5 extension definitions from the FHIR-core source shortly before that application, and core link-fix history now points narrative references at [%extensions-location%]StructureDefinition-capabilitystatement-expectation.html.

Additional context:
FHIR-I WGM minutes for September 2022 record the intended direction for FHIR-37596: the CodeSystem and ValueSet would be removed from R5 and live only in THO. The current FHIR-core build no longer contains an active StructureDefinition source for capabilitystatement-expectation; current core pages only link to the external extension location. The Extension Pack source now binds capabilitystatement-expectation to THO and, after later FHIR-44609 clarification, directs SHALL NOT/prohibition semantics to the separate capabilitystatement-prohibited modifier extension. The remaining FHIR-core conformance-expectation ValueSet is still active for Requirements.statement.conformance and related R6 conformance-language work; FHIR-40228 is already represented on the combined branch, so this reconciliation does not reopen that separate core terminology trail.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR-core source change. The artifact requested by FHIR-37596 is outside the current FHIR-core checkout and is already correct in the FHIR Extension Pack source. The current core references resolve through the extension-location mechanism rather than a local extension definition, and changing the active Requirements/conformance terminology would be a separate decision governed by later issues.

Recommendation:
Keep this audit commit as-is. No FHIR-core source edit is needed for FHIR-37596; any future changes to the capabilitystatement-expectation extension binding or its THO value set should be handled in the Extension Pack or THO, with FHIR-core only updating external links if those locations change.
