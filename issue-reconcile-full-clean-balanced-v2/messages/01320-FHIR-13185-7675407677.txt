FHIR-13185: Audit superseded immunization dose datatype change

Issue request:
FHIR-13185 was Published with a Persuasive with Modification resolution for STU3. It reported that Immunization.vaccinationProtocol.seriesDoses, ImmunizationRecommendation.recommendation.doseNumber, and ImmunizationRecommendation.recommendation.protocol.doseSequence were too narrowly modeled as positiveInt, because values such as recurring boosters may be non-numeric. The approved direction was to allow both integer and string representations while expressing a preference for integers when known; the issue comments also noted that related dose search parameters should be removed if there was no use case.

Initial application:
The source history includes b294e9e7f9239a04662837e18dfffefbe41d5ecb, "#13185 - add a string option for doseNumber and seriesDose in both ImmunizationRecommendation and ImmunizationEvaluation", which applied the original integer/string compromise to the older spreadsheet/example source. Later R4 cross-version history shows the immunization dose fields as positiveInt|string choices, so the original datatype compromise existed in the FHIR lineage. Search-parameter cleanup was subsequently formalized by FHIR-19340 and applied in 760cdc540d095f4d73ccc47fc91be0098ec53076, removing unnecessary ImmunizationRecommendation dose search parameters.

Additional context:
Later final PHER decisions intentionally superseded the original integer/string compromise. FHIR-25277 changed doseNumber and seriesDoses in the immunization resources to string-only for R5, and the combined branch already contains Issue-Reconcile-Key: FHIR-25277 at 7f80bd9be381213fd16dfc24e785a84648ae56c0 auditing that superseded state. FHIR-44982 then changed the current Immunization doseNumber and seriesDoses elements from string to CodeableConcept for R6 so implementers can use coded concepts or free text; the combined branch already contains Issue-Reconcile-Key: FHIR-44982 at d71140d621d3265e4cb4df589b68e53706ef5a0a completing the current in-scope source reconciliation. Current source/fhir.ini keeps Immunization as an active core resource but no longer lists ImmunizationEvaluation or ImmunizationRecommendation as active core resources; source/resourceguide.html links those resources to the Immunization Incubator IG instead. The remaining search.html ImmunizationRecommendation dose-number example is generic number-search prose pointing at that external IG, not an active base-core search parameter definition.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Reintroducing positiveInt|string or the older integer-preference comments would contradict the later Published/Applied decisions. Current active Immunization source uses CodeableConcept for protocolApplied.doseNumber and protocolApplied.seriesDoses with comments allowing coded concepts or free text, examples use CodeableConcept text, and targeted source searches found no active core doseNumber/seriesDoses/doseSequence search parameter definitions to remove.

Recommendation:
Keep this audit commit as-is. The current FHIR core source is correct for FHIR-13185 after considering later final decisions; do not recreate deleted ImmunizationEvaluation or ImmunizationRecommendation core source or revert the current CodeableConcept outcome. If the external Immunization Incubator resource or the generic search-page example needs future cleanup, handle that under the owning IG or a separate search documentation issue.
