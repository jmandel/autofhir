FHIR-30373: Audit removed notification URL default

Issue request:
FHIR-30373 was a Published/Persuasive R5 FHIR-core Subscription clarification. It asked that Subscription.notificationUrlLocation document the server behavior when the element is not set, proposing that empty notifications mean none and other notifications default to full-url.

Initial application:
No source commit mentioning FHIR-30373 was found. Historical Subscription source before the later FHIR-36081 cleanup contained Subscription.notificationUrlLocation and the subscription-url-location code system, but the element definition still only said where to place URLs if present and did not carry the proposed default guidance. The companion backport issue FHIR-30374 recorded suggested-text work in the external subscriptions backport IG, not this core checkout, and was later superseded there as well.

Additional context:
Subscription is an active current-build resource in source/fhir.ini. Later final work-group issue FHIR-36081 removed Subscription.notificationUrlLocation and the subscription-url-location terminology for R5 because SubscriptionStatus.notificationEvent provided a fixed place for event resource references. Git commit c1d340d7c8 applied that removal in core source, and combined-branch audits for FHIR-36081 and FHIR-30404 already cover the related cleanup/example request. Current source has no notificationUrlLocation or subscription-url-location references; Subscription.endpoint, Subscription.content, and subscription notification-content guidance now define the current model.

AutoFHIR reconciliation:
This empty audit commit makes no source change. Adding default guidance for Subscription.notificationUrlLocation would be incorrect in the current build because the element and its value set were intentionally removed by a later Published R5 decision.

Recommendation:
Keep this no-change audit. Do not reintroduce notificationUrlLocation default text in core; any future clarification should target the current Subscription.content and SubscriptionStatus.notificationEvent mechanisms.
