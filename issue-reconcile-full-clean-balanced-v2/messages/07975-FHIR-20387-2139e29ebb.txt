FHIR-20387: Audit examples-json field completeness

Issue request:
FHIR-20387 was Published/Persuasive with Modification for FHIR-I, raised against the R4 4.0.0 examples-json.zip download. It reported missing SearchParameter.base on CodeSystem/ValueSet extension search parameter JSON files, missing StructureDefinition.type on definition/event/fivews/request JSON files, and missing Questionnaire.item.linkId on generated resource-definition questionnaire JSON files; the resolution was to fix per the linked Zulip discussion, applied for R5.

Initial application:
No core repository commit was found that explicitly mentions FHIR-20387. The application appears to have happened through later generator/source maintenance and release refactoring: current R4 publication artifacts now show StructureDefinition.type on the four logical model JSON files, R5 examples-json.zip has the logical-model type values and no missing linkId values in the generated questionnaire files, and R5/current no longer include the old CodeSystem/ValueSet extension search parameter JSON files in the core examples archive.

Additional context:
The linked Zulip thread confirms the original report and the mixed resolution context: Lloyd McKenzie said examples should follow the standard, while Grahame Grieve questioned the base/type reports but agreed the missing linkId was an error. Current core source keeps downloads.html, the logical model spreadsheets, and Questionnaire in build scope. The CodeSystem/ValueSet extension search parameters named by the issue were later removed from core and moved to the FHIR Extension Pack, where the current definitions include base and type. Related no-change audits for current examples archive validity and Questionnaire linkId examples are already on the combined branch, so this commit does not duplicate those issues.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current generated/publication surfaces checked for this issue do not have a current core defect to correct: definition.json, event.json, fivews.json, and request.json carry StructureDefinition.type; current source Questionnaire examples contain linkId on every item and the current examples-json.zip no longer publishes the old resource-definition *-questionnaire.json files; and the moved extension search parameter definitions are correct in the Extension Pack rather than editable in this core checkout.

Recommendation:
Keep this no-change audit for the current core branch. Revisit only if a future current examples-json.zip reintroduces one of these concrete missing-field defects; any retrospective R4-patch repair would need to target the historical publication/release process rather than this current source branch.
