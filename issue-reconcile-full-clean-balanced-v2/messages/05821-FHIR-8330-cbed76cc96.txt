FHIR-8330: Audit reverse $translate support

Issue request:
FHIR-8330 was Published/Persuasive for DSTU1 and asked ConceptMap $translate to support reverse translation, for example returning all source codes that map to a supplied SNOMED CT target code. The final Jira resolution says this had already been done because the reverse parameter covered the use case.

Initial application:
No Jira-tagged FHIR-8330 source commit was found. Git history shows the reverse parameter was present in ConceptMap $translate source by b33187f27b (2016), with documentation saying that reverse=true returns all codes that might be mapped to the supplied code and reverses the source/target interpretation. Later R5 ConceptMap work kept and clarified that reverse-parameter model, including FHIR-28577's target-side wording.

Additional context:
FHIR-32129 was a later Published/Persuasive with Modification decision for R5 that removed the reverse parameter, renamed the original code/coding/codeableConcept inputs to source*, added targetCode/targetCoding/targetCodeableConcept, and described reverse lookup directly through target* inputs. That later decision has already been represented on the combined branch by aab515ed02. FHIR-28577 and FHIR-22666 are closely related reverse/source/target wording issues and are already represented on the combined branch by 56ead5c361 and fd1bde3ce9. FHIR-56187 is a later Triaged, unresolved question about reverse response output details, so it is background only and not a final source-edit decision for this seed.

AutoFHIR reconciliation:
This commit intentionally makes no source change. ConceptMap is active in source/fhir.ini, its operation list includes OperationDefinition/ConceptMap-translate, and the active OperationDefinition has no reverse parameter because the current source*/target* model now covers the FHIR-8330 reverse lookup use case. Reintroducing a reverse flag or obsolete reverse documentation would conflict with the later published FHIR-32129 decision.

Recommendation:
Keep this audit commit as-is. The current build-scope source already satisfies the seed after later ConceptMap $translate decisions are considered; any future clarification about reverse response output shape should proceed through unresolved FHIR-56187 or a successor issue, not through FHIR-8330.
