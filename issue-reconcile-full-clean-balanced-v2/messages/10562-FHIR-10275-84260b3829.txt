FHIR-10275: Audit Observation valueBoolean allowance

Issue request:
FHIR-10275 was a Published/Persuasive OO change request asking to add valueBoolean to Observation because some Observation results are genuinely boolean and implementers wanted to send true/false directly instead of always mapping to coded yes/no concepts. The final resolution was to add Boolean to Observation.value[x].

Initial application:
The source history explicitly includes commits aeebcb9ecb9b445566cb8800f8dbd8e3b7b423cf ("[#10275]") and b4942e8229294f9cb982009175771b76b00ebe3d ("[#10275] part 2"). Those commits revised the Observation guidance and added valueBoolean to the old notes. Later source refactoring, including the StructureDefinition source rewrite, carried boolean forward into the authoritative Observation.value[x] and Observation.component.value[x] type lists.

Additional context:
FHIR-10275 superseded the older FHIR-3505/FHIR-6344/FHIR-7547 premise that Observation should not define valueBoolean, but it did not remove the guidance that CodeableConcept with v2/0136 remains preferable for many boolean-like observations that may need exceptional values such as unknown. Current Observation is active in source/fhir.ini, and the current source therefore correctly combines valueBoolean support with coded yes/no guidance in the Notes section.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/observation/structuredefinition-Observation.xml already permits boolean for Observation.value[x] and Observation.component.value[x], and current source/observation/observation-notes.xml already lists valueBoolean while retaining the coded-value guidance. There is no missing current-spec edit for FHIR-10275.

Recommendation:
Keep this no-change audit commit as-is. No core source edit is needed for FHIR-10275 unless OO makes a newer decision to remove, constrain, or further explain Observation valueBoolean use.
