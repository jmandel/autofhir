FHIR-19250: Audit DocumentReference boundary clarification

Issue request:
FHIR-19250 was a Published, Persuasive with Modification OO change request asking the DocumentReference Boundaries and Relationships section to clarify its overlap with DiagnosticReport. The final resolution added text explaining that DiagnosticReport is appropriate for discrete Observation-backed reports, DocumentReference often indexes non-FHIR or narrative/report content, a scanned CBC report may fit either representation, and implementation guides should clarify the choice for specific use cases.

Initial application:
The issue was applied in commit f2fe753f95, which updated both source/documentreference/documentreference-introduction.xml and source/diagnosticreport/diagnosticreport-introduction.xml. The current active DocumentReference source still contains the requested overlap guidance, and the paired DiagnosticReport source contains the reciprocal boundary paragraph.

Additional context:
DiagnosticReport and DocumentReference are active current-build resources in source/fhir.ini. The companion DiagnosticReport issue FHIR-19249 later refined the shared wording in commit a9822236fa by adding that a single in-system entity may be represented as both resources, and later source history corrected the DiagnosticReport element name from representedForm to the actual presentedForm. FHIR-19249 is already represented on the combined branch by audit commit 4c0fdb4db03740f9bdba644f0f304567c2025afa, so this commit does not duplicate that issue. Confluence minutes and the linked Zulip thread support the same implementer-confusion rationale and did not reveal a conflicting later decision for FHIR-19250.

AutoFHIR reconciliation:
This commit makes no source change because the latest combined-branch source already conveys the approved DocumentReference boundary clarification, including the later FHIR-19249 refinement that keeps the two resource pages consistent. Adding additional search warnings or duplicating IG-specific guidance would go beyond the final applied wording.

Recommendation:
Keep this no-change audit as-is. Future edits should require a new OO decision if the work group wants stronger retrieval guidance or a different boundary rule between DocumentReference and DiagnosticReport.
