FHIR-38732: Audit Specimen grouping guidance

Issue request:
FHIR-38732 was a Published / Persuasive R5 Orders and Observations issue asking for Specimen notes that describe how to group Specimen resources using Specimen.parent, including parent specimens with multiple child specimens. The approved resolution was to add a Specimen Grouping note explaining grouping through Observation.specimen and through groups of specimens independent of observations, plus a statement that one parent specimen may have multiple child specimens.

Initial application:
The Jira application comment points to the FHIR-38732 pull-request work. Git history shows the source-changing application in 5d7ac0f8750a, which replaced the placeholder Specimen notes content with the Specimen Grouping section in source/specimen/specimen-notes.xml, and the pull request was merged as 4056cd2eccd6.

Additional context:
Specimen is an active build-scoped resource in source/fhir.ini. The current Observation source supports the first grouping path because Observation.specimen can reference Specimen or Group and constrains Group members to specimens. The current Group source still allows Specimen as a Group.member.entity target; the related FHIR-39269 audit already on the combined branch confirms that retaining Specimen in Group is the approved later decision. FHIR-38733 is the same Specimen.parent family and later added the complementary parent/recursive search note.
