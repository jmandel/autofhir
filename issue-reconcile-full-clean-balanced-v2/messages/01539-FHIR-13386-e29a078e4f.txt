Issue request:
FHIR-13386 was Published/Not Persuasive with Modification. It originally asked to change Composition.section into a datatype so reusable section profiles would be easier, but the final disposition said that was no longer relevant because GF#13973/FHIR-13973 provided another mechanism and that the remaining need was an example and/or documentation for Composition.section.

Initial application:

The seed itself was later applied by d30af6ea06bd9, which added the current profiling.html section documenting how to profile portions of a resource, using Composition.section as the example.

Additional context:
FHIR-25477 later asked for the same concrete section-profile example on profiling.html and was voted persuasive. FHIR-17114 is a duplicate of GF#13973. FHIR-33062 corrected the old executable example-composition reference to the example-section-library profile before FHIR-48828 later removed the example-composition core profile; the inline profiling guidance and active example-section-library source remain.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The active source already explains that profile-element lets validators apply a profile starting at a nominated element, shows a Composition.section section-library pattern and application snippet, and retains an active example-section-library StructureDefinition example. Changing Composition.section into a datatype would conflict with the final resolution and is unnecessary.

Recommendation:
Keep this no-change audit. Future work should avoid restoring the rejected datatype approach; if editors want richer examples, handle that as a new documentation issue rather than as unfinished FHIR-13386 work.
