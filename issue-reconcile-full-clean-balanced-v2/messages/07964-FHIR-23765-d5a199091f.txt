FHIR-23765: Audit ObservationDefinition definition support

Issue request:
FHIR-23765 is Published/Persuasive for FHIR-core Questionnaire. It asked for Questionnaire.item.definition to be able to reference an ObservationDefinition and for population/extraction guidance to permit an ObservationDefinition definition as an alternative to item.code when selecting Observations to populate from or extract to.

Initial application:
The core change was applied before this reconciliation. Git commit 6eb67586f8 added ObservationDefinition to the Questionnaire.item.definition comment, and git commit 256b419e69 added ObservationDefinition to the formal element definition. The Jira comment explicitly records Core Git: Questionnaire-fixes 6eb67586f8 and notes that SDC changes were still needed outside the core application.

Additional context:
Questionnaire and ObservationDefinition are active current-build resources in source/fhir.ini. Current source/questionnaire/structuredefinition-Questionnaire.xml says Questionnaire.item.definition may refer to an ElementDefinition or ObservationDefinition and explains the canonical URI form. The original Zulip thread supports the request. SDC minutes later show the remaining concern was whether ObservationDefinition itself should expose ElementDefinition/Profile-based constraints; the related follow-up issues FHIR-31747 and FHIR-31748 were resolved no-change/retracted, so they do not require a further core Questionnaire source change.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative current core Questionnaire definition already supports ObservationDefinition, and the remaining SDC-specific population/extraction guidance belongs to the SDC IG rather than this FHIR-core checkout.

Recommendation:
Keep this audit commit as-is for core. If current SDC IG guidance still limits observation pre-population or extraction matching to Questionnaire.item.code, handle that as follow-up SDC IG work; do not add redundant core Questionnaire prose unless a future work-group decision asks for core-specific ObservationDefinition mapping guidance.
