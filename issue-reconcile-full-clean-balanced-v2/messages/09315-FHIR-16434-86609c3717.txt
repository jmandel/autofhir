FHIR-16434: Audit HTTP timezone text relocation

Issue request:
FHIR-16434 was a Published/Persuasive STU3 FHIR-core HTTP issue asking to move the default-timezone sentence out of the unrelated "Support for Versions" section and into http.html#return, reworded as: "If the server has a default timezone, it SHOULD return the default timezone in the HTTP Response headers using the "Date" header."

Initial application:
The issue was initially applied in SVN revision 14192, mirrored as git commit 69bc784817a08f775619849c0e5374d09748b179, which removed the paragraph from the versioning section and added the reworded paragraph under source/http.html#return. Current source no longer has the old paragraph in "Support for Versions".

Additional context:
The current build includes source/http.html as the RESTful API page through source/hierarchy.xml. Later applied issue FHIR-42971 determined that the moved sentence was technically wrong because the HTTP Date header is UTC/GMT and cannot convey a server default timezone. Commit b811010c8b85b48fa2419b47a250e5ffba3e3f51 removed the sentence from source/http.html, and current CapabilityStatement narrative now points implementers to the timezone extension on CapabilityStatement.meta. FHIR-42971 is already represented on the combined branch by dbcb00cce4cc9087dd3a64ca872c8b0e1fb40e57.

AutoFHIR reconciliation:
This audit intentionally makes no source change. Reintroducing the FHIR-16434 resolution text into http.html#return would undo the later FHIR-42971 correction. The seed issue's durable current-state requirement is satisfied because the default-timezone Date-header sentence is no longer misplaced in "Support for Versions", and the current spec uses later guidance for timezone discovery.

Recommendation:
Keep this no-change audit commit. Do not restore the HTTP Date-header timezone sentence; any future timezone-discovery work should proceed from the CapabilityStatement timezone extension guidance and the already-audited FHIR-42971 decision.
