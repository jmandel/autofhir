FHIR-5535: Audit resource profile common elements

Issue request:
FHIR-5535 was a Published/Persuasive DSTU1 change request asking that resource profile JSON definitions include the common elements and attributes shared by all resources, not just resource-specific elements.

Initial application:
The Jira comments record that this was a DSTU1 profile-generation concern and that, after profile work in 2015, it was considered sorted. No source-changing commit explicitly tagged FHIR-5535 was found on the current combined branch. Later source rework moved the current build to active StructureDefinition sources with explicit baseDefinition chains rather than duplicating inherited elements into each differential.

Additional context:
The current build-scope configuration registers Resource and DomainResource as abstract infrastructure resources and registers concrete resources such as Patient in the active resource list. Resource defines id, meta, implicitRules, and language; DomainResource defines text, contained, extension, and modifierExtension; concrete resource StructureDefinitions, represented by Patient, derive from DomainResource. A current build Patient snapshot also contains all of those inherited elements, so the JSON profile surface requested by the issue is present even though the per-resource source differentials do not duplicate inherited elements. Jira, Zulip, and Confluence searches found no later conflicting decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source model and generated profile snapshots already satisfy the applied DSTU1 request through inheritance and snapshot expansion, and adding duplicated common elements to each resource differential would be inconsistent with the current StructureDefinition source pattern.

Recommendation:
Keep this audit commit as-is. Revisit only if a current generated StructureDefinition snapshot omits inherited Resource or DomainResource elements; otherwise no FHIR core follow-up is needed.
