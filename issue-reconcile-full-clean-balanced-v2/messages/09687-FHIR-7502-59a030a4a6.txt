FHIR-7502: Align List order notes

Issue request:
FHIR-7502 was Published/Persuasive for DSTU1 FHIR-core List. It asked whether List item order is preserved, how that order can be reconstructed without an item sequence number, and whether List.orderedBy only describes the ordering criterion. The accepted resolution was to add notes clarifying this.

Initial application:
The issue was applied in git commit 884699db409ff12d65bfbbdd2976a9abb381046b, imported from svn revision 5596, which added the List Order narrative to source/list/list-notes.xml. The List resource remains active in source/fhir.ini, and the current source still carries the ordering guidance added for the issue.

Additional context:
Later FHIR-24878, also Published/Persuasive and already represented on the combined branch, added List.entry.orderMeaning with the rule that order has no meaning unless specifically asserted by List.orderedBy. FHIR-I minutes and the linked Zulip thread confirm that this later decision was about how implementations recognize when List.entry order has a defined meaning. That later decision narrows the older narrative sentence saying the meaning of the order may be known implicitly.

AutoFHIR reconciliation:
This commit keeps the FHIR-7502 clarification that List entries have a literal order, but updates the narrative to align with the current List.entry.orderMeaning: List.orderedBy gives the item order a defined meaning, and if it is absent the specification does not assign one, even though the entries are still represented in literal order.

Recommendation:
Keep this source change. It preserves the seed issue's ordering clarification while removing a real inconsistency with the later published List.entry.orderMeaning decision. Do not publish a separate FHIR-24878 commit from this worker because the combined branch already contains Issue-Reconcile-Key: FHIR-24878.
