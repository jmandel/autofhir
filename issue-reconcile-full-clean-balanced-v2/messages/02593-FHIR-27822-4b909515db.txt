FHIR-27822: Audit PlanDefinition participant type expansion

Issue request:
FHIR-27822 was Published/Persuasive for R5. It reported that required PlanDefinition.action.participant.type lacked non-clinical participant choices such as List and Organization, and the accepted resolution was to expand participant typing to resources that implement the Participant pattern.

Initial application:
No commit explicitly mentioning FHIR-27822 was found. The same R5-era source path was nevertheless changed shortly after the Jira decision: c68fb1d080 (J#20825) introduced the PlanDefinition actor model and changed PlanDefinition.action.participant.type from required to optional, and f83e1f04c1 (J#24618) expanded the action-participant-type code system to the current Participant-pattern resource code set including Organization and Group. Later participant commits added canonical/reference choices without restoring the original required-code limitation.

Additional context:
The seed Jira comments clarify that List was not suitable because List does not implement the Participant pattern, and that Group was the likely way to express collections. Current fhir.ini keeps PlanDefinition and the Participant/ParticipantContactable/ParticipantLiving logical patterns in the build. The current PlanDefinition.action.participant model has optional type, typeCanonical, and typeReference choices; typeReference includes Organization plus later-approved non-clinical participant targets such as Medication, Specimen, Substance, and BiologicallyDerivedProduct, while action-participant-type contains exactly the current source resources whose root interface mapping is Participant, ParticipantContactable, or ParticipantLiving.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The authoritative current source already implements the WG decision in a broader and safer way than simply adding List to the required code list: the code list covers the Participant-pattern resources, List remains excluded, and the current reference/canonical choices handle expanded participant use cases.

Recommendation:
Keep this no-change audit commit. Reopen only if a future WG decision changes whether List itself should become a Participant-pattern resource; otherwise adding List or duplicative explanatory prose to PlanDefinition would contradict the recorded Jira discussion or create maintenance drift.
