FHIR-11148: Audit PlanDefinition workflow ownership

Issue request:
FHIR-11148 was a Published/Persuasive with Modification DSTU2 request to move PlanDefinition from the Clinical Decision Support work group to the workflow work group because PlanDefinition also models workflows, protocols, order sets, and other non-CDS processes.

Initial application:
No commit explicitly mentions FHIR-11148. The issue comment says PlanDefinition was recategorized as Workflow by Lloyd's changes. The directly corresponding applied issue FHIR-10683 was implemented in SVN 11382 / git bd1507dafa96568bf37503ff029bbabe8c3d8be2, which updated CDS resource workflow mappings and added PlanDefinition prose identifying it as a FHIR Workflow definition resource.

Additional context:
The FHIR-11148 resolution did not approve transfer of resource ownership to a separate Workflow work group; it states that Workflow is a task force, not a specific working group that could own the resource, and that CDS would coordinate with that task force. The current build keeps PlanDefinition active, owned by CDS in fhir.ini and the StructureDefinition wg extension, while the PlanDefinition and Workflow pages present PlanDefinition from the Workflow definition perspective. FHIR-11232 made the same request for both PlanDefinition and ActivityDefinition and received the same resolution and application comments.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source matches the final decision: CDS remains the responsible work group, and the workflow perspective is already represented in the PlanDefinition introduction and Workflow module/page.

Recommendation:
Keep this audit commit as-is. Revisit only if HL7 creates a formal Workflow work group that can own resources or a later final Jira decision transfers PlanDefinition ownership away from CDS.
