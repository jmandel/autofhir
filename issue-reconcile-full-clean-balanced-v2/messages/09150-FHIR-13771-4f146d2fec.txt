FHIR-13771: Audit eld-16 regex underscore escape

Issue request:
FHIR-13771 was a Published/Persuasive FHIR-core ElementDefinition issue for STU3. It reported that eld-16 called matches() with a sliceName regex that escaped underscore as \_, which is not a valid escape in many regex engines, and requested removing the unnecessary underscore escape.

Initial application:
The Jira comment records svn revision 12831. Git history preserves that application as commit 1709591740fd1ffd8c82b3a874bfe4ba3bca021b, whose message is "#13771 - fix eld-16" and whose patch changed source/datatypes/elementdefinition.xml to replace the escaped underscore with a literal underscore in the eld-16 FHIRPath and XPath regex cells.

Additional context:
ElementDefinition is an active datatype in source/fhir.ini, and source/datatypes/elementdefinition.xml is the authoritative current spreadsheet source for eld-16. Later same-invariant decisions changed the allowed character set and regex shape: FHIR-15133 repaired a malformed eld-16 regex, and FHIR-14389 added the accepted @default allowance. Both are already represented on the combined branch, and their later changes preserve FHIR-13771's literal underscore.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active eld-16 row uses sliceName.matches('^[a-zA-Z0-9\\/\\-_\\[\\]\\@]+$') and the matching XPath regex with a literal underscore, and a source search found no remaining sliceName.matches expression with an escaped underscore.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-13771 unless a future work-group decision revisits the broader sliceName character policy.
