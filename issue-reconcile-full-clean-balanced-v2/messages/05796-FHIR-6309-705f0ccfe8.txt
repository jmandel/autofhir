FHIR-6309: Audit medication code/reference choice

Issue request:
FHIR-6309 was a Published/Persuasive with Modification Pharmacy change request from DSTU1 asking that MedicationStatement, and by resolution MedicationPrescription, MedicationAdministration, and MedicationDispense, allow the medication to be represented either by a code or by a Medication resource reference instead of always requiring a separate Medication resource.

Initial application:
No current source commit was found with an explicit FHIR-6309 reference. The Jira comments say the change had already been made by August 2015, and related same-family issues record the same approved application. Later source history preserved the model: FHIR-10389 added guidance about when a code is enough versus when a Medication resource reference is required, and FHIR-25929 converted Pharmacy CodeableConcept-plus-Reference choices to the current CodeableReference datatype.

Additional context:
The active build scope includes MedicationAdministration, MedicationDispense, MedicationRequest, and MedicationStatement in source/fhir.ini; MedicationPrescription is documented there as having become MedicationRequest. The current StructureDefinition source uses CodeableReference with targetProfile Medication for each affected medication element, with medication-code bindings and comments explaining code versus Medication resource use. FHIR-14851 later rejected allowing both branches at the same time, which is consistent with the current single CodeableReference element. FHIR-5633, the older same-family tracker referenced from FHIR-6309, is already represented on the combined branch by a no-change audit commit and is not duplicated here.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build-scope source already implements the approved code-or-Medication-reference semantics using the current CodeableReference representation, and adding duplicate wording would not change implementer understanding.

Recommendation:
Keep this no-change audit as-is. Future work should only revisit this area if Pharmacy changes the Medication CodeableReference target, the single-choice cardinality, or the code-versus-reference guidance; FHIR-6309 itself is already satisfied in the current source.
