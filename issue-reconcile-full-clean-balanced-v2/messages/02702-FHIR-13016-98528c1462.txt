FHIR-13016: Audit Provenance agent role split

Issue request:
FHIR-13016 was Published/Persuasive with Modification for DSTU2 Provenance. The original request said Provenance.agent.role should not repeat for multiple participation functions; the Jira discussion and resolution transformed that into separating the agent's participation from authorization/security roles, with a coded 0..1 participation element and companion AuditEvent alignment.

Initial application:
No explicit source commit mentioning FHIR-13016 was found in the current git history. The post-migration source already carried the modeled split as Provenance.agent.type and AuditEvent.agent.type for the participation/function of the agent, while retaining Provenance.agent.role and AuditEvent.agent.role for repeatable role/authorization concepts. Later commits, especially f577d68ceb for FHIR-32453/FHIR-32520 and subsequent participation value set work, refined the same source locations.

Additional context:
FHIR-13011, resolved in the same DSTU2 family, records that the model had changed so Provenance.agent.type indicates how the agent participated, while Provenance.agent.role is intended for security roles such as RBAC or ABAC roles. Later Published/Applied issues FHIR-28184, FHIR-32453, FHIR-32519, FHIR-32520, and FHIR-53882 further clarified the distinction between agent.type and agent.role and their terminology bindings. source/fhir.ini actively includes both Provenance and AuditEvent, so the inspected StructureDefinition XML files are in current build scope.

AutoFHIR reconciliation:
Made no source change. The current active source already satisfies the durable FHIR-13016 requirement by representing participation as Provenance.agent.type 0..1, bound to participation-role-type, and by keeping Provenance.agent.role as 0..* for structural/security role concepts under later published decisions. Changing Provenance.agent.role to 1..1 or 0..1 now would reintroduce the participation/security conflation that later decisions explicitly resolved.

Recommendation:
Keep this audit commit as-is. Do not change Provenance.agent.role cardinality for FHIR-13016; any desire to apply the newer FHIR-53882-style wording to Provenance should be handled as a separate Security WG clarification because FHIR-53882 itself was AuditEvent-scoped.
