FHIR-13081: Audit MedicationStatement unknown status history

Issue request:
FHIR-13081 was a Published/Persuasive Pharmacy change request raised for DSTU2. It asked to add unknown to the MedicationStatement.status value set so a MedicationStatement derived from a MedicationRequest with unknown status could also report status unknown.

Initial application:
The Jira comment identifies historical commit 4b21106775caa782aa07057cdc51cb67b83f467f as the original application. That commit added an unknown row to the then-active MedicationStatement status spreadsheet, updated the MedicationStatement.status short display to include unknown, and updated notes explaining the unknown/taken scenario.

Additional context:
Later Pharmacy decisions deliberately changed the same status family. FHIR-19468/FHIR-19470 moved taking/not-taking semantics into an adherence element. FHIR-28593 made MedicationUsage.status a record-status element rather than a clinical medication-use status. FHIR-32060 then explicitly removed unknown from that status value set, renamed completed to recorded, and added draft because unknown did not make sense for record status. FHIR-39271, after the MedicationUsage name was reverted to MedicationStatement, confirmed that MedicationStatement.status reflects the recording status of the statement and MedicationStatement.adherence carries taking/not-taking semantics. Those later related issues are already represented on the combined branch and should not be duplicated here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. In the current build, source/fhir.ini actively includes MedicationStatement, MedicationStatement.status is recorded | entered-in-error | draft with text limiting it to recording status, and the status CodeSystem contains only recorded, entered-in-error, and draft. The current adherence CodeSystem includes unknown for whether the medication is being taken. Re-adding unknown to the required MedicationStatement.status value set would contradict the later published status/adherence redesign.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for FHIR-13081 unless Pharmacy reopens the current MedicationStatement status/adherence model; any future reconsideration should start from FHIR-32060, FHIR-32858, and FHIR-39271 rather than the superseded DSTU2 status-code model.
