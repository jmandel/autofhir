FHIR-5851: Audit ElementDefinition binding string text

Issue request:
FHIR-5851 was a Published/Persuasive DSTU1 FHIR-core change request for FHIR-I. The formal ElementDefinition binding rule had been generalized to allow string, so the human description saying "Binding can only be present for coded elements" needed to add string; the Jira resolution says to add string to the description in SVN revision 4611.

Initial application:
The issue appears to have been applied by git-svn commit 6dc4494b702f8adfa8accd9c0632ea8e6f440547, which imported SVN build revision 4611 and changed source/datatypes/elementdefinition.xml from "Binding can only be present for coded elements" to "Binding can only be present for coded elements, and string" while leaving the formal expression with string included.

Additional context:
ElementDefinition remains an active, normative type in source/fhir.ini, while DataElement resource entries are commented out in the current build. Later same-invariant work intentionally refined the current text beyond the original request: c932c0fb84da434a50f6dd78ecd29316c4466d82 added uri, FHIR-30085 added Duration, and FHIR-21622 scoped ELD-11 to FHIR-defined types. Current source/datatypes/elementdefinition.xml therefore says "Binding can only be present for coded elements, string, and uri if using FHIR-defined types" and the expression still includes string.

AutoFHIR reconciliation:
This commit makes no source change. The current authoritative source already satisfies FHIR-5851, and changing it back to the narrower DSTU1 wording would discard later published refinements.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed for FHIR-5851 unless a future work group decision reopens the broader ELD-11 bindable-type policy.
