FHIR-12689: Audit retired ReferralRequest element order

Issue request:
FHIR-12689 was a Published/Persuasive DSTU2 Patient Care QA issue reporting that ReferralRequest elements were out of order. It requested the order identifier, status, category, type, priority, serviceRequested, patient, context, authored, fulfillmentTime, requester, recipient, reason instead of leaving serviceRequested last and fulfillmentTime before authored.

Initial application:
The issue was explicitly applied in git commit e73353ab39a4227a35c7ec0fe8d20c75161c7064 on 2017-01-24, whose subject names #12689. That patch reworked the then-active source/referralrequest spreadsheet and moved ReferralRequest.serviceRequested from the last element position up before ReferralRequest.patient, while concurrent #10293 workflow-alignment edits renamed authored to authoredOn and changed surrounding request-workflow rows.

Additional context:
FHIR-13196 was later Published/Persuasive with Modification and merged ReferralRequest and ProcedureRequest into ServiceRequest because the resources lacked a clear boundary. In the current build, source/fhir.ini actively registers servicerequest=ServiceRequest, records that ReferralRequest became ServiceRequest, and contains only historical rename mappings for ReferralRequest. The current source tree has no active source/referralrequest StructureDefinition; the active ServiceRequest definition has a different post-merge element sequence.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The FHIR-12689 defect was applied to the historical ReferralRequest spreadsheet, and the affected resource is no longer an active current-build artifact. Editing retired ReferralRequest material would be out of build scope, and the current ServiceRequest source does not carry the reported DSTU2 ReferralRequest ordering problem.

Recommendation:
Keep this audit commit as-is. No current FHIR core source change is recommended unless a human is maintaining a historical DSTU2 branch or identifies a distinct ServiceRequest ordering defect under a new tracker.
