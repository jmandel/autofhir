FHIR-7618: Audit Condition abatement Range guidance

Issue request:
FHIR-7618 was a Published Patient Care change request with resolution Persuasive with Modification. It asked for clarification of when/how Range should be used for Condition.range / Condition.abatement, with the accepted resolution to explain that Range communicates the subject's age at the time of abatement.

Initial application:
The issue appears to have been applied in git commit b8fddd3c06, whose message explicitly references #7618 and added a Condition.abatementRange usage note to source/condition/condition-notes.xml. The note was later editorially refined, but it still carries the requested substance.

Additional context:
Condition is an active resource in source/fhir.ini, so source/condition/condition-notes.xml and source/condition/structuredefinition-Condition.xml are current build inputs. Later issue FHIR-50437 separately revisited Condition.onsetRange and Condition.abatementRange and added matching abatement comment text to the StructureDefinition source, while FHIR-12064 rejected removing distinct abatement choice types. No direct Zulip or Confluence references to FHIR-7618 were found.

AutoFHIR reconciliation:
No source change was made. Current source already says that Condition.abatementRange communicates an imprecise age of the subject at abatement, and the element comment now also distinguishes Period as imprecise abatement timing from Range as an imprecise age range.

Recommendation:
Keep this audit commit as-is. Reopening the source would be redundant and could create drift between the narrative notes and StructureDefinition comments; future work should only revisit this if Patient Care changes the broader Condition onset/abatement choice-type model.
