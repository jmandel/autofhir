FHIR-33163: Audit Specimen collection device

Issue request:
FHIR-33163 is a Published/Persuasive FHIR-core Specimen change request from OO, raised and applied for R5. It asked to add Specimen.collection.device with cardinality 0..1, datatype CodeableReference to Device, and a definition for the device used to obtain the specimen, such as a catheter or catheter part used for a blood draw.

Initial application:
The Jira comment cites PR branch commit fda799bf5efe44482ed5108a486e897dd7b138c6 as the applied change. The actual source addition appears in git commit 7f5c512945e99213aa6431b2eb9c11d86aa04630 and was merged to the mainline by PR #1382 as 73d52b1656e0f8b4d01b3c955257614edd0b265f, adding Specimen.collection.device to source/specimen/structuredefinition-Specimen.xml with min 0, max 1, CodeableReference(Device), and the collection-device binding description.

Additional context:
The OO 2021-08-09 minutes record the use case and vote to add specimen.collection.device for identifying the device or device part used in specimen collection, following a Patient Care Zulip thread about drains, catheters, ports, and the gap in Specimen documentation. Later Specimen work changed the current modeling without removing the seed change: FHIR-42081 corrected the copied definition from technique wording to device wording, FHIR-49751 broadened Specimen device elements for Device/DeviceDefinition modeling and removed the old binding, FHIR-39389 contributed the current DeviceDefinition/canonical modeling, and FHIR-53467 source history restored Reference(Device) as a choice on collection.device[x]. Specimen remains an active build-scope resource in source/fhir.ini.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active StructureDefinition already has Specimen.collection.device[x] with min 0, max 1, a device-focused short and definition, CodeableConcept, Reference(Device), and canonical(DeviceDefinition) choices. That current shape preserves the seed's implementer-facing requirement after later R6 modeling changes, and no current authoritative source location was found that omits the element.

Recommendation:
Keep this no-change audit commit as-is. Do not revert the current device[x] representation to the original R5 CodeableReference wording; any remaining binding or DeviceDefinition modeling concerns belong to their later Jira issues rather than FHIR-33163.
