FHIR-19446: Audit improvement notation terminology

Issue request:
FHIR-19446 was Published/Persuasive with Modification for CQI. It asked to change Measure and MeasureReport improvementNotation from code to CodeableConcept with a required binding to the existing value set, then after harmonization to update the value set to HL7 terminology under v3 ObservationValue _MeasurementImprovementNotation.

Initial application:
The Jira comment cites GH#780fae5356. That commit changed the historical Measure and MeasureReport spreadsheet sources from code to CodeableConcept and updated the MeasureImprovementNotation wording/value-set description. Current XML sources are post-refactor descendants of those spreadsheets.

Additional context:
Measure and MeasureReport are active current build resources in source/fhir.ini. The current authoritative XML has group-level improvementNotation as CodeableConcept and binds to http://terminology.hl7.org/ValueSet/measure-improvement-notation. The v3 ObservationValue source also contains _MeasurementImprovementNotation with IncrIsImp and DecrIsImp descendants, but later CQI/core decisions moved the FHIR measure-improvement-notation code system to THO and then deliberately relaxed the Measure and MeasureReport improvementNotation bindings to extensible. Checked-in SVG diagrams still contain some stale generated-looking binding/anchor text, but the authoritative XML is correct and SVG-only changes are out of scope for this reconciliation.

AutoFHIR reconciliation:
No source change was made. Replacing the current THO measure-improvement-notation value set with a v3 ObservationValue-based binding, or restoring required binding strength, would conflict with later applied decisions FHIR-39623 and FHIR-53101. The current source is correct when the full issue family is considered.

Recommendation:
Keep this audit commit as-is. Any future desire to replace the THO measure-improvement-notation value set with v3 ObservationValue descendants should be handled as a new CQI/terminology decision, likely in THO/UTG rather than as a core source cleanup.
