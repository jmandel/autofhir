FHIR-8399: Audit observation methods LOINC cleanup

Issue request:
FHIR-8399 was a Published/Persuasive with Modification DSTU1 change request for Observation noting that ValueSet/observation-methods still included a LOINC filter "Type = METHOD_TYP" that did not conform to LOINC guidance or the actual LOINC database. The recorded resolution was to describe how the Type pseudo-property should work.

Initial application:
The issue appears to have been applied in git commit f16ff276ebde2a99c3ef4bd03b9e020f89144335, corresponding to the Jira comment "svn revision 6634". Rather than adding explanatory text for the old Type pseudo-property, the commit cleaned up the value set by removing the LOINC include entirely, leaving SNOMED CT and then-current v3 content.

Additional context:
FHIR-8399 directly follows the same Observation Methods LOINC-filter trail as FHIR-5600. The current source has continued to evolve and now defines ValueSet/observation-methods with SNOMED CT filters only. Observation is active in source/fhir.ini and Observation.method binds to this value set, so the absence of the invalid LOINC filter is visible in the current core build source.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The current source no longer has the LOINC include or the invalid Type = METHOD_TYP filter that FHIR-8399 raised.

Recommendation:
Keep this audit commit as-is. If LOINC method part codes are reintroduced in the future, that should be handled as a new terminology design decision with explicit LOINC filter semantics rather than by restoring the old pseudo-property filter.
