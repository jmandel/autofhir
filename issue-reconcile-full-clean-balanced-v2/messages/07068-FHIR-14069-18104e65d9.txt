FHIR-14069: Audit ShareableValueSet immutable cleanup

Issue request:
FHIR-14069 is a Published/Persuasive Vocab change request for STU3. It asked to remove ValueSet.immutable from the ShareableValueSet profile because the element did not change anything relative to base ValueSet and made the differential table confusing.

Initial application:
The issue appears to have been applied before this reconciliation by git commit d661e10df91629292e27e58e9b4d039facfbab90, the git-svn import of svn revision 13447 named "GF#14069 - fix value set profile". That commit removed the ValueSet.immutable row from source/valueset/valueset-shareable-spreadsheet.xml. The later XML StructureDefinition form of source/valueset/structuredefinition-profile-shareablevalueset.xml, immediately before its FHIR-37959 migration removal, also had no ValueSet.immutable differential element.

Additional context:
FHIR-37959 later migrated the Shareable, Publishable, Computable, and Executable terminology-resource profiles out of core and into CRMI while preserving their canonical URLs; that issue is already represented on the combined branch. The current core build no longer has an active ShareableValueSet profile definition or ValueSet-core IG reference. Current source/fhir.ini has no active [profiles] entry for shareablevalueset, source/valueset/implementationguide-ValueSet-core.xml has an empty definition, and a current source search finds only incidental ShareableValueSet comments and the OID mapping. The current build.fhir.org core page for shareablevalueset.html returns 404, while the CRMI continuous-build package contains ShareableValueSet profile definitions whose differentials do not include ValueSet.immutable. The historical static STU3 page still contains generated immutable entries, but this reconciliation updates the current source/build, not past published artifacts.

AutoFHIR reconciliation:
This is an empty audit commit. No current core source change is needed: the requested differential cleanup was already applied in the old core profile source, and the current core build no longer owns or builds the ShareableValueSet profile. The external CRMI profile surface checked during reconciliation also already omits ValueSet.immutable from the ShareableValueSet differential.

Recommendation:
Keep this audit commit as-is. Do not reintroduce or edit a core ShareableValueSet profile for FHIR-14069; any future profile-specific corrections should be handled in CRMI, and any concern about immutable in the frozen STU3 publication would require a separate historical-publication process outside this current core source branch.
