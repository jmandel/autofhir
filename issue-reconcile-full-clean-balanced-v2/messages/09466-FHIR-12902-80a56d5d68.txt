FHIR-12902: Audit CapabilityStatement canonical reference

Issue request:
FHIR-12902 was a Published/Persuasive with Modification FHIR-core Conformance issue raised against DSTU2. It asked why CapabilityStatement.instantiates was a uri instead of Reference and recorded a broader final decision to make canonical/url primitive types explicit, use canonical references for conformance and knowledge artifacts that are identified by canonical URL, allow canonical targetProfile/aggregation handling, update contained-reference and _include guidance, and change CapabilityStatement.instantiates plus related conformance-resource references to canonical rather than a generic uri or Reference.

Initial application:
The issue was applied in git-svn revision 13214, represented in this repository by git commit 2319e45e4115705f873661fe217ae2971eebc13f ("GF#13543 - add Reference.type and #12902 - sort out canonical references"). That commit changed the historical CapabilityStatement spreadsheet row for CapabilityStatement.instantiates from uri to canonical(CapabilityStatement), introduced the url and canonical primitive types, and updated canonical-reference narrative. The later source rework in c69d71aa213de86d55e0261339c15e4bacd509e6 carried CapabilityStatement.instantiates forward as canonical(CapabilityStatement) in the current StructureDefinition XML source.

Additional context:
CapabilityStatement is an active current-build resource in source/fhir.ini. The current CapabilityStatement source defines instantiates, implementationGuide, rest.resource.searchParam.definition, rest.resource.operation.definition, rest.compartment, rest.resource.profile, rest.resource.supportedProfile, messaging.supportedMessage.definition, and document.profile with canonical targets. The primitive datatype source and references narrative define url/canonical, versioned canonical references, and the limits of using Reference.reference for canonical URLs. Later community and Jira context, including FHIR-39173, considered related instantiatesCanonical/instantiatesUri patterns but resolved that separate datatype question as No Change and did not reverse the CapabilityStatement canonical-reference decision.
