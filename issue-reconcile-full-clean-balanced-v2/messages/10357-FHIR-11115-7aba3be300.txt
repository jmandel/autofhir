FHIR-11115: Audit Observation reference range split

Issue request:
FHIR-11115 was a Published/Persuasive OO change request against DSTU2 Observation. It asked not to unbound Observation.referenceRange.meaning for both reference-range type and population, and instead to replace it with Observation.referenceRange.type 0..1 and Observation.referenceRange.appliesTo 0..*.

Initial application:
The request was applied in historical commit bd736a46cc4788abc6cc24be56c2694efac20e51, which replaced Observation.referenceRange.meaning with type and appliesTo in the Observation spreadsheet and updated examples from meaning to type. Follow-up commit 7eec4cc9c2b6c5502c00ce207326d5f1736b239b added the missing referencerange-appliesto value set. The later build-core refactor 33b409a4b6d544598262f2f074ebb4b6dc466157 migrated this applied content into source/observation/structuredefinition-Observation.xml.

Additional context:
FHIR-8941 was the earlier Published issue asking to make referenceRange.meaning 0..*, but FHIR-11115 superseded that approach; the current source's committee notes still show both issue numbers on the split elements. Observation is active in source/fhir.ini, so source/observation/structuredefinition-Observation.xml and the source/observation value sets are in current build scope. FHIR-16187 later changed Observation.referenceRange.type's binding strength from extensible to preferred and is already represented on the combined branch, explaining why the current type binding no longer matches FHIR-11115's original extensible baseline.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Observation source has Observation.referenceRange.type 0..1 and Observation.referenceRange.appliesTo 0..*, binds appliesTo to ValueSet/referencerange-appliesto with example strength, and no longer contains Observation.referenceRange.meaning in the Observation source or examples.

Recommendation:
Keep this empty audit commit as-is. No FHIR core source follow-up is needed for FHIR-11115 unless OO later decides to revisit the current type/appliesTo model or re-open the later FHIR-16187 preferred binding decision.
