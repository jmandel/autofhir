FHIR-20843: Audit StructureMap typeMode values

Issue request:
FHIR-20843 was a Published/Persuasive FHIR-core StructureMap change request asking to remove the `none` code from StructureMapGroupTypeMode, with the concrete concern that StructureMap.group.typeMode should be optional instead of requiring a coded sentinel value.

Initial application:
The issue was applied by e7ab035ff3872b1c0980a883b9602256f2d67bdb and merged by a572c61cf7ff2cb1b47b4ebfd9e7f40f3b3adf24 in PR #977. That change removed `typeMode value="none"` from StructureMap examples, changed StructureMap.group.typeMode from 1..1 to 0..1 in the StructureMap spreadsheet source, and removed the `none` code row from the group type mode binding source used at that time.

Additional context:
StructureMap is an active build resource in source/fhir.ini. The current authoritative StructureMap XML has StructureMap.group.typeMode as 0..1, its short display is only `types | type-and-types`, and the current CodeSystem/ValueSet source defines only `types` and `type-and-types`. The R5 published history likewise shows only those two map-group-type-mode codes. Zulip records show the issue in the FHIR-I block vote and PR coordination thread; Confluence and broader community searches found no conflicting later decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change because the current build source already implements the requested removal of `none` and optionality for StructureMap.group.typeMode.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed for FHIR-20843 unless a future mapping-language decision changes the allowed StructureMap.group.typeMode codes.
