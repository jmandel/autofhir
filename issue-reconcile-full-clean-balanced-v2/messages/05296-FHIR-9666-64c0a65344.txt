FHIR-9666: Audit removal of superseded medication statuses

Issue request:
FHIR-9666 was Published/Persuasive with Modification for DSTU2 Pharmacy medication resources. It asked to remove superseded as a medication status and represent the relationship between orders separately; the final resolution says superseded/superceded was removed as a status and priorPrescription should describe a link to an earlier related order or prescription.

Initial application:
The change was applied historically. Commit 29f5a29869ef removed superseded from the medication prescription/order status value set during the MedicationPrescription to MedicationOrder rename. Commit ea52ada470f6 explicitly references #9666 and updated MedicationOrder.priorPrescription wording. The earlier FHIR-8015 commit 4bde19269737 had already introduced priorPrescription as the relationship element.

Additional context:
The current source has evolved from MedicationOrder to MedicationRequest. The active resources in source/fhir.ini include MedicationAdministration, MedicationDispense, MedicationRequest, and MedicationStatement. Their current status CodeSystems do not contain superseded or superceded, and MedicationRequest.priorPrescription remains a 0..1 Reference(MedicationRequest). Later published FHIR-39142 replaced older priorPrescription wording with the current clearer statement that it references an order/prescription being replaced by this MedicationRequest. The existing FHIR-8015 combined-branch audit covers the priorPrescription addition, so this audit is limited to the FHIR-9666 status-removal follow-up.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current build-scope medication sources already satisfy FHIR-9666: no active medication status CodeSystem exposes superseded/superceded, and the order replacement relationship is represented through MedicationRequest.priorPrescription.

Recommendation:
Keep this audit commit as-is. No current core source correction is needed for FHIR-9666; later questions about broadening or clarifying medication request relationships should be handled under newer Pharmacy trackers rather than by reopening the old superseded-status model.
