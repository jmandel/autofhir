FHIR-3977: Audit ValueSet inv-7 correction

Issue request:
FHIR-3977 was a Published/Persuasive DSTU1 technical correction for FHIR-core ValueSet. It reported that the old Inv-7 XPath failed when ValueSet.identifier was absent and requested the expression be changed to not(f:define/f:system/@value = f:identifier/@value).

Initial application:
The Jira comment says this was fixed in SVN revision 4055. Git history maps that to 87833681e38f85c6bd683317732c672ffd9dc7dc, which changed source/valueset/valueset-spreadsheet.xml from not(exists(f:define)) or (f:define/f:system/@value != f:identifier/@value) to not(f:define/f:system/@value = f:identifier/@value).

Additional context:
The corrected invariant belonged to the retired DSTU1/R2 spreadsheet source model where ValueSet.define represented an inline code system definition. Current build scope uses source/fhir.ini's active valueset=ValueSet resource entry and source/valueset/structuredefinition-ValueSet.xml. That current StructureDefinition has no ValueSet.define element, no vsd-7 constraint, and no f:define/f:system XPath; the active constraints are the modern ValueSet compose and expansion constraints.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The issue's requested correction was historically applied, and the modern specification has since removed the old element and invariant rather than carrying forward an incorrect expression.

Recommendation:
Keep this audit commit as-is. No follow-up source work is recommended for FHIR-3977 unless a future work group decision reintroduces a comparable ValueSet inline-code-system invariant in the current model.
