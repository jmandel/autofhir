FHIR-8889: Require dateTime offset in regex

Issue request:
FHIR-8889 was a Published/Persuasive FHIR-core technical correction for the datatypes page. It reported that the dateTime regular expression allowed a time component without a timezone/UTC offset even though the datatype rule says an offset SHALL be populated when hours and minutes are specified.

Initial application:
The Jira comment records SVN revision 7195, and git-svn commit 02da8332d164281d0bbbd3ac45617afb7334c1da (#8889 - correct dateTime regex in narrative) updated the old datatype narrative regex to require the offset when time was present. Later datatype regex work for R5, especially FHIR-34355 and subsequent corrections, changed the active primitive regex shape and left the full-time offset optional again.

Additional context:
Current source/datatypes.html still states that a UTC offset SHALL be populated when hours and minutes are specified and renders the dateTime regex from the primitive datatype source. Later Published issue FHIR-38735 and Applied issue FHIR-52878 constrained offsets so they are allowed only with a time component, and the already-published FHIR-38735 reconciliation updated the primitive comment accordingly. Resolved-change-required FHIR-46453 explicitly identifies the remaining behavior as a regression of FHIR-8889. The FHIR-52878 Zulip thread notes that regexes need not enforce every possible rule, but it did not reverse the specific FHIR-8889/FHIR-46453 requirement that the displayed dateTime validation regex reject a full time without an offset.

AutoFHIR reconciliation:
Updated source/datatypes/primitives.xml so the dateTime regex keeps the later partial-date behavior while requiring a Z or signed UTC offset whenever the T time branch is used. This also rejects a bare + or - offset marker. No generated artifacts were edited.

Recommendation:
Keep this source fix. FHIR-46453 should not receive a separate commit in this default Applied/Published run, but this change should satisfy its source correction if that issue is later audited; a separate follow-up can add regression tests if the work group wants a dedicated regex test harness.
