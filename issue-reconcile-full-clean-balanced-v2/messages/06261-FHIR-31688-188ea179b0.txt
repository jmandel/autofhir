FHIR-31688: Align DeviceRequest ModelInfo replaces

Issue request:
FHIR-31688 is a Published/Persuasive with Modification OO change request for R5. It reported that DeviceRequest.replaces pointed to Any and should point to DeviceRequest; the accepted resolution was to rename DeviceRequest.priorRequest to DeviceRequest.replaces while keeping the Reference(DeviceRequest) target and cardinality unchanged.

Initial application:
The target-reference portion was first applied in commit ecc60e218f43b9f07e9f9d29eab3c2e3470c5e22, which changed DeviceRequest.priorRequest from Reference(Resource) to Reference(DeviceRequest). The rename portion was applied by commit 40683b9663fdea9e6b83e4abf6a4bc5a92f6df6f and merged to master as 683489d03ea825b9038550fc92db462d716a6fce in PR #1974, changing the StructureDefinition element and DeviceRequest prior-request search parameter path/expression from DeviceRequest.priorRequest to DeviceRequest.replaces. The Jira comment points to b61ff7c, but that hash is a PR-branch merge sync; the semantic DeviceRequest change is the 40683b/683489 history.

Additional context:
DeviceRequest is active in source/fhir.ini, and the current DeviceRequest StructureDefinition already defines DeviceRequest.replaces as Reference(DeviceRequest). The DeviceRequest prior-request search parameter still uses the code/id prior-request, but its path and expression point to DeviceRequest.replaces; later FHIR-53213 explicitly lists DeviceRequest-prior-request (prior-request) as an active normative search parameter, and broader FHIR-34866 search-parameter naming work is outside this seed. The active Library examples and publish.ini expose source/library/library-fhir-model-definition-content.xml as the FHIR ModelInfo sidecar used by CQL tooling, and source/library/library-fhir-model-definition.xml embeds a matching ModelInfo payload. That ModelInfo surface still exposed DeviceRequest.priorRequest before this reconciliation.

AutoFHIR reconciliation:
Updated the active FHIR ModelInfo sidecar and its embedded Library payload so DeviceRequest now exposes replaces rather than the stale priorRequest element. No DeviceRequest StructureDefinition or search parameter code change was made because the authoritative resource source already has Reference(DeviceRequest), the search parameter expression already targets DeviceRequest.replaces, and the retained prior-request search code is governed by later search-parameter decisions.

Recommendation:
Keep this commit. It completes the applied FHIR-31688 rename across the active ModelInfo publication surface without reopening broader search-parameter alias/code policy or changing the already-correct DeviceRequest resource definition.
