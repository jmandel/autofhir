FHIR-17460: Audit eligibility detail cleanup

Issue request:
FHIR-17460 was a Published/Persuasive FM change request for STU3 EligibilityRequest and EligibilityResponse. It asked to rename the authorization backbone to detail, remove BenefitSubCategory, move benefitCategory under detail.category, use the example BenefitCategory value set for detailed service categories, and add detail.provider for the servicing practitioner.

Initial application:
The issue appears to have been applied in historical commit 10ac2496c7fa29fe458c13a1ef3f7edb89485acc, whose message lists tracker 17460. That commit changed the old EligibilityRequest and EligibilityResponse spreadsheet sources to mark the authorization backbones and BenefitSubCategory rows as removed, add EligibilityRequest.detail and EligibilityResponse.insurance.detail with category/provider/preauthorization detail fields, and bind the retained category fields to BenefitCategory/ex-benefitcategory.

Additional context:
The current build no longer uses the old EligibilityRequest and EligibilityResponse resources directly. source/fhir.ini lists CoverageEligibilityRequest and CoverageEligibilityResponse as active approved resources, records EligibilityRequest/Response as removed, and maps CoverageEligibilityRequest=EligibilityRequest and CoverageEligibilityResponse=EligibilityResponse for name-change history. A later Published decision, FHIR-17473, changed the neutralized detail backbone name to item for the current CoverageEligibility resources; a separate combined-branch reconciliation for FHIR-17473 is already present. FHIR-17484 made the same BenefitSubCategory consolidation for Claim, ClaimResponse, and ExplanationOfBenefit, but those artifacts are outside this seed's bounded EligibilityRequest/Response scope.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. On the latest combined branch, the active CoverageEligibilityRequest source already has CoverageEligibilityRequest.item.category bound as BenefitCategory to ex-benefitcategory and CoverageEligibilityRequest.item.provider for the servicing practitioner. The active CoverageEligibilityResponse source already has CoverageEligibilityResponse.insurance.item.category bound as BenefitCategory to ex-benefitcategory, provider, and item-level preauthorization fields, and grep finds no active BenefitSubCategory, benefitSubCategory, or obsolete CoverageEligibilityRequest/Response authorization backbone in the current build resource directories. The remaining old EligibilityRequest/Response spreadsheet rows are retired build-scope history rather than current-spec source needing edits.

Recommendation:
Keep this audit commit as-is. No current FHIR-core source edit is needed for FHIR-17460; future cleanup should avoid modifying the retired EligibilityRequest/Response spreadsheet artifacts unless the build machinery explicitly reactivates them.
