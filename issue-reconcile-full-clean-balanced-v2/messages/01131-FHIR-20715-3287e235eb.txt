FHIR-20715: Audit MeasureReport data source guidance

Issue request:
FHIR-20715 was Applied/Persuasive with Modification for R6 by CQI. It originally requested a way to capture data sources used for MeasureReport results, but the final disposition narrowed the core change to adding $submit-data and $collect-data operation guidance for use of the X-Provenance header, citing the DEQM provenance/data-capture resolutions; a 2025 Jira comment explicitly said not to make the earlier requested device-extension change.

Initial application:
The core source was updated by HL7/fhir commit a80ba4b9a48ee09eb77fa52cbb0fe0841ec24e54, merged through PR #3379, which added X-Provenance guidance to source/measure/operationdefinition-Measure-submit-data.xml and source/measure/operationdefinition-Measure-collect-data.xml. Follow-up commits on the PR corrected the link form and restored submit-data wording. Later CQI operation-alignment commits for FHIR-34112, FHIR-50487, FHIR-51066, and FHIR-55967 changed surrounding operation content but preserved the seed's X-Provenance guidance.

Additional context:
Measure and MeasureReport are active current-build resources in source/fhir.ini, and source/measure/list-Measure-operations.xml references both OperationDefinition/Measure-submit-data and OperationDefinition/Measure-collect-data. Current source/measure operation definitions both state that X-Provenance header data with provenance for submitted/collected data SHOULD be supported and should be consistent with the reporter element in the DEQM Data Exchange MeasureReport Profile. The referenced Provenance header section exists in source/provenance/provenance-notes.xml. Related DEQM issues FHIR-25624 and FHIR-25721 support the provenance-vs-extension context but belong to DEQM/QM rather than requiring another core source edit here.
