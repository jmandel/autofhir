FHIR-20484: Audit Encounter diagnosis use resolution

Issue request:
FHIR-20484 is an Applied/Persuasive with Modification Patient Administration issue raised against STU3 and applied for R5. It asked to relax Encounter.diagnosis.use to 0..* because diagnosis use classifications can overlap, clarify the diagnosis-role codes, add quality-measure/billing-related codes, and rename billing to billing diagnosis. The final resolution did not relax the cardinality at that time: because Encounter.diagnosis.rank still belonged to the repeating diagnosis backbone, PA concluded that separate Encounter.diagnosis repetitions kept the rank/use relationship clearer; the resolution instead kept the preferred binding extensible for local needs and required completing diagnosis-role code definitions.

Initial application:
No core source commit was found that directly names FHIR-20484, which is consistent with the final decision not requiring a cardinality source change in the then-current Encounter model. PA minutes record the 2020-02-06 Persuasive with Modification vote. The terminology-definition portion was later handled outside the core checkout by UP-529, which lists FHIR-20484 as adding definitions for diagnosis-role and was published in THO 5.5.0.

Additional context:
Later Encounter decisions changed the model that FHIR-20484 had evaluated. FHIR-16148 redesigned Encounter.reason and Encounter.diagnosis, removed Encounter.diagnosis.rank from the active Encounter source, moved billing-diagnosis ranking guidance to Account, and introduced the current Encounter Diagnosis Use value set. FHIR-38784 then made Encounter.reason.use and Encounter.diagnosis.use repeat; that issue is already represented on the combined branch. FHIR-38807 is also already represented and corrected remaining Encounter reason/diagnosis wording while preserving the later repeating cardinalities. Zulip discussion of FHIR-38784 explicitly compared it with FHIR-20484 and confirmed the later tracker was the path used to relax the upper bound.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Encounter is an active approved resource in source/fhir.ini, and the authoritative current StructureDefinition already has Encounter.diagnosis max="*" and Encounter.diagnosis.use max="*" with a preferred binding to http://hl7.org/fhir/ValueSet/encounter-diagnosis-use. The current source is therefore correct after considering the original FHIR-20484 resolution, the external THO terminology follow-up, and later Encounter decisions.

Recommendation:
Keep this no-change audit commit. Do not revert Encounter.diagnosis.use to 0..1 based on the original FHIR-20484 rank rationale, because FHIR-16148 removed that rank context and FHIR-38784 deliberately changed the cardinality. Do not add the old diagnosis-role definitions in core; any remaining diagnosis-role terminology work belongs to THO/UTG rather than this FHIR source checkout.
