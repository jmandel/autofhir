FHIR-47393: Audit Task.note lifecycle wording

Issue request:
FHIR-47393 was an Applied, Persuasive with Modification FHIR-core Task change request from OO for R6. The reporter observed that Task.note's definition, "Free-text information captured about the task as it progresses," could imply notes only belong while the task is in progress and asked for the definition to be rephrased. The accepted resolution was to change Task.note to "Free-text information about the task during its lifecycle."

Initial application:
The issue was applied in commit ef79e2a519cfb356a05f218572862ac01b9207d1 and merged by HL7/fhir#3208 as 5a1cb94cab08f5f2129a9d07395eb830bb388841. That source change replaced only the Task.note long definition in source/task/structuredefinition-Task.xml with the lifecycle wording approved by the Jira resolution.

Additional context:
Task is an active resource in source/fhir.ini, so source/task/structuredefinition-Task.xml is in current build scope. The current source keeps the short display as "Comments made about the task" and has the approved long definition, while Task mapping exception sources and the checked-in SVG also reflect the lifecycle wording. OO minutes for 2024-10-22 record the motion to find the issue Persuasive with Modification, specifically rewording the long definition to remove "as it progresses." Jira and Zulip searches did not reveal a later conflicting core Task.note decision.

AutoFHIR reconciliation:
This audit commit makes no source change because the current active Task source already contains the approved lifecycle definition and the obsolete "as it progresses" wording is absent from source/task. Adding further prose or changing the short display would exceed the Jira resolution, which targeted the long definition.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed in FHIR core for FHIR-47393 unless OO later chooses to revisit the Task.note short display separately.
