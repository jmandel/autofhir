FHIR-12501: Audit Provenance CodeableConcept types

Issue request:
FHIR-12501 was a Published/Persuasive Security WG change request asking that Provenance.reason and Provenance.activity be CodeableConcept rather than Coding, because multiple coding systems and translations are relevant for Provenance activity and purpose/reason concepts.

Initial application:
The issue appears to have been applied by git commit 84f8086d21facb3551bfb28481156250510ae48b, whose message lists Provenance GF#12501 and whose provenance spreadsheet patch changed both Provenance.reason and Provenance.activity from Coding to CodeableConcept.

Additional context:
FHIR-9105 is the earlier Published issue that had changed Provenance.activity and Provenance.reason from CodeableConcept to Coding, creating the regression FHIR-12501 reversed. In the current build, Provenance is an active resource in source/fhir.ini, Provenance.reason is mapped as a prior name for Provenance.authorization, and later Applied issue FHIR-54833 confirms the renamed authorization element should remain CodeableConcept while free-text rationale is carried by Provenance.why.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active Provenance StructureDefinition has Provenance.authorization with type CodeableConcept and Provenance.activity with type CodeableConcept, and the current Provenance source checked for this reconciliation has no residual Coding type on those relevant elements.

Recommendation:
Keep this no-change audit commit as-is. No core source follow-up is needed for FHIR-12501 unless a future ballot decision changes the Provenance.authorization/why split or the Provenance.activity type.
