FHIR-14013: Audit CodeSystem alternate-code handling

Issue request:
FHIR-14013 was a Published/Persuasive STU3 vocabulary request to let CodeSystem represent several codes for one concept. Its final resolution chose an "alternate" extension rather than changing CodeSystem.concept.code into a repeating element.

Initial application:
The issue was applied in SVN revision 12746, represented in git as bda4a109ec8e5d17fcd0a356ca2befa7282815a0, which added CodeSystem alternate-code extension content and the associated alternate-code-kind value set in the then-current spreadsheet sources. Later source restructuring removed the core extension definitions from R5 source; the codesystem-alternate extension now exists in the FHIR Extension Pack, and the core checkout retains only historical OID references for that canonical.

Additional context:
Later vocabulary decisions substantially refined the representation. FHIR-39542 rejected a direct synonym-property rename while noting that a new alternate-code solution would be proposed. FHIR-44627 then formally adopted the R6 property-based approach: multiple CodeSystem.concept entries are related using the defined alternateCode concept property, codeKind can classify the code form, and a CodeSystem invariant requires reciprocal alternateCode relationships. The current build has CodeSystem active in source/fhir.ini, has concept-properties active as a generated CodeSystem, and the CodeSystem narrative explains the alternateCode approach.

AutoFHIR reconciliation:
This audit commit makes no source change. The current core specification already gives implementers a current mechanism for multiple codes per real-world concept through alternateCode/codeKind concept properties and a reciprocal constraint, while the older codesystem-alternate extension is maintained outside core in the Extension Pack. Reintroducing or editing the old core extension source would be out of build scope and would conflict with later R6 decisions.

Recommendation:
Keep this audit as-is. No core source edit is needed for FHIR-14013; any future change should be driven by later alternate-code tickets such as FHIR-44627 or by an explicit Extension Pack issue if the moved extension definition needs maintenance.
