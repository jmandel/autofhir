FHIR-30274: Align DeviceDefinition property ModelInfo

Issue request:
FHIR-30274 was Published as Not Persuasive with Modification for OO. It asked to replace DeviceDefinition.physicalCharacteristics, which used the removed ProdCharacteristic datatype, with a repeating backbone property carrying a 1..1 CodeableConcept type and a value[x]. The final resolution treated the main structural change as already addressed by the DeviceDefinition.property consolidation and clarified that valueInteger/valueQuantity and valueCodeableConcept/valueString should remain separate choices.

Initial application:
No Jira-keyed FHIR-30274 source commit was found. The same change family was applied through FHIR-26424 and FHIR-32290: commits 188021453f and 01a6bc6ffa removed DeviceDefinition.physicalCharacteristics from the authoritative DeviceDefinition StructureDefinition, commit 23d0f3c36f adjusted Device and DeviceDefinition property.value[x] to 1..1, and commit 7333cb0ead commented ProdCharacteristic out of source/fhir.ini. The active StructureDefinition now has DeviceDefinition.property as a BackboneElement with type and value[x] choices and no physicalCharacteristics element.

Additional context:
The FHIR-30274 resolution text names FHIR-32464, but that Jira is an unrelated AuditEvent issue; the FHIR-30274 comments, FHIR-26424 resolution, FHIR-32290 follow-up, and OO minutes identify FHIR-26424/FHIR-32290 as the relevant DeviceDefinition.property consolidation trail. OO minutes on 2021-09-13 recorded that FHIR-30274 had been merged into DeviceDefinition.property while the value[x] datatype discussion remained, and the 2022-06-20 minutes recorded that this issue was no longer needed and done. The Library/FHIR-ModelInfo example is build-visible via the Library examples list and publish.ini, so its stale DeviceDefinition model surface is in scope.

AutoFHIR reconciliation:
Updated source/library/library-fhir-model-definition-content.xml so DeviceDefinition.Property exposes a single value choice with Quantity, CodeableConcept, string, boolean, integer, Range, and Attachment, matching the current DeviceDefinition.property.value[x] source. Removed the stale DeviceDefinition.physicalCharacteristics ModelInfo element and refreshed source/library/library-fhir-model-definition.xml so the embedded Library.data payload matches the edited ModelInfo content. No primary DeviceDefinition StructureDefinition edit was needed because it was already correct.

Recommendation:
Keep this source fix. It completes FHIR-30274 on the remaining build-visible ModelInfo surface while preserving the fhir.ini R4/R6 migration mapping from old DeviceDefinition.physicalCharacteristics to DeviceDefinition.property. Do not treat this commit as a full reconciliation of the broader FHIR-26424/FHIR-32290 Device/DeviceDefinition consolidation; those issues have wider scope and should be audited separately if needed.
