FHIR-16675: Audit Identifier.system example

Issue request:
FHIR-16675 was a Published/Persuasive FHIR-I STU3 correction reporting that the generated Identifier.system valueUri example in profiles-type.xml/profiles-types.xml contained prose with whitespace (`http://www.acme.com/identifiers/patient or urn:ietf:rfc:3986 if the Identifier.value itself is a full uri`) instead of a valid URI. The issue was auto-approved as a non-substantive correction.

Initial application:
No commit explicitly mentioning FHIR-16675 was found. The same invalid Identifier.system example was fixed through the same-change-family Published issue FHIR-17431 in svn revision 14075, represented in git as 2f577a81d2c0833f5bbe23b020262257b89339cc (`GF#17431 - fix invalid example for Identifier + validate generated conformance resources, and fix many discovered issues, and more work on R3/R4 mappings`). That commit changed `source/datatypes/identifier.xml` by replacing the invalid combined value with `http://www.acme.com/identifiers/patient`, matching the FHIR-16675 comment that the problem was fixed for R4.

Additional context:
`source/fhir.ini` actively lists Identifier under `[types]`, so `source/datatypes/identifier.xml` remains the current build-scope source for this datatype. The current source has Identifier.system typed as `uri` with the valid example `http://www.acme.com/identifiers/patient`, and it separately preserves the Identifier.value guidance that `urn:ietf:rfc:3986` is used when no system has been assigned for a globally unique URI value. FHIR-17431 has already been represented on the combined branch by audit commit df6b1487d7f70e88661147428b1cf3373f63183c. Later FHIR-22711 asked for a STU3 technical correction for the same bad generated example, but it was resolved Not Persuasive/No Change because the work group determined there would be no STU3 technical correction release.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The invalid combined value is absent from current authoritative source, the active Identifier source already carries a valid URI example, and the remaining STU3-only generated artifact concern was explicitly closed as no-change.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed unless a future work group decision reopens STU3 patch publication or asks for additional Identifier.system example repetitions in the current build.
