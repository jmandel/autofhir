FHIR-31400: Audit eld-1 snapshot-only application

Issue request:
FHIR-31400 was Published/Persuasive with Modification for R5. It asked that eld-1 stop applying to differentials and apply only to snapshots, and noted that the normative compatibility text for value constraints needed to allow this kind of relaxation.

Initial application:
The issue was applied by HL7/fhir PR #1700, merged as 05c1368fca9b665e75c1fb2f62a37a9c4e90690b, which added the former eld-1 slicing discriminator rule to StructureDefinition.snapshot.element as an sdf constraint and updated source/versions.html. The implementation discussion records removal from the ElementDefinition spreadsheet and the final move to snapshot.element after build feedback.

Additional context:
FHIR-I WGM minutes recorded the approved motion to move eld-1 from ElementDefinition to StructureDefinition.snapshot and to consider relaxing value-constraint compatibility rules. FHIR-37692 later renamed the new StructureDefinition constraint from sdf-24 to sdf-28 to avoid duplicate constraint keys. FHIR-36755 later replaced the literal FHIR-31400 compatibility wording with the current rule that invariants and similar constraints are not changed in a way that could invalidate previous instances, while warning/best-practice invariants and certain error invariants may be added.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope StructureDefinition source contains sdf-28 on StructureDefinition.snapshot.element with the same discriminator-or-description rule, the ElementDefinition spreadsheet no longer contains the eld-1 discriminator rule, and the current versions.html text already covers non-invalidating constraint relaxations when read with the later FHIR-36755 decision.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-31400 unless the work group wants a separate, broader review of ElementDefinition.condition display flags or compatibility policy wording, which would belong to other Jira decisions rather than this seed.
