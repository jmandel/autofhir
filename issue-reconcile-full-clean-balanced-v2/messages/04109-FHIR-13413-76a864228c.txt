FHIR-13413: Audit RequestGroup label rename

Issue request:
FHIR-13413 was a Published/Persuasive with Modification CDS work group request for STU3 RequestGroup changes in support of CDS Hooks. It asked to rename the existing RequestGroup action label element to prefix and to add a label field matching CDS Hooks terminology; the approved resolution was to rename label to prefix but keep the existing title element for consistency with other FHIR resources.

Initial application:
The issue was applied in SVN 12255, represented in git as 571fea972c605378a443f9fa8c2bace66e61a178, which changed RequestGroup.action.label to RequestGroup.action.prefix in the RequestGroup spreadsheet source and example. No later evidence showed the FHIR-13413 application was reverted.

Additional context:
FHIR-24619 later renamed RequestGroup to RequestOrchestration for R5, so the current build-scope source to inspect is source/requestorchestration, not the removed source/requestgroup directory. source/fhir.ini has an active requestorchestration resource entry and a migration alias from RequestGroup to RequestOrchestration. The current StructureDefinition contains RequestOrchestration.action.prefix followed by RequestOrchestration.action.title, current examples use prefix, and targeted source searches found no RequestOrchestration.action.label or RequestGroup.action.label source in the active resource. Zulip and Confluence searches found no direct FHIR-13413 conflict; a CDS Hooks notification thread from May 2017 is consistent with the Jira alignment context.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already preserves the approved label-to-prefix rename and the decision to retain title rather than introduce a separate RequestGroup/RequestOrchestration action label field.

Recommendation:
Keep this audit commit as-is. Any future desire to add a CDS Hooks-style label element would be a new compatibility-affecting design change, not an unapplied remainder of FHIR-13413.
