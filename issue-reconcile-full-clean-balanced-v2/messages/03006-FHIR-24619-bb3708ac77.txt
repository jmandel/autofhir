FHIR-24619: Audit RequestGroup rename

Issue request:
FHIR-24619 was Published/Persuasive with Modification for R5. It asked to rename RequestGroup, with the final work group decision choosing RequestOrchestration, and to clarify the Request pattern and resource documentation while recording implementer concerns from the Zulip naming discussion.

Initial application:
The issue was applied by PR #2236 in commit 46bea37a00, which changed the active resource registration from requestgroup=RequestGroup to requestorchestration=RequestOrchestration, updated the StructureDefinition, examples, search-parameter bundles, operation/profile lists, CDS and Request-pattern narrative, and related references. Commit ecfdbab9c6 then cleaned up now-obsolete commented RequestGroup fhir.ini entries. There is no current source/requestgroup resource folder.

Additional context:
The linked Zulip thread shows the concern behind the documentation request: implementers worried that RequestOrchestration sounded too heavy for simple grouping, and the discussion clarified that groupIdentifier covers independently managed grouped requests while RequestOrchestration covers interdependent options with shared status. That thread also led to FHIR-24905, which was resolved no-change because the Request pattern already points multi-item prescription use cases to groupIdentifier. Later final issues FHIR-38869 and FHIR-40635 added durable Request pattern and RequestOrchestration notes for groupIdentifier differences, documenting choices, and completion. The remaining RequestGroup occurrences in current source are historical/compatibility records: removed-resource or old-type entries, the R5 mapping RequestGroup=@RequestOrchestration, and release-history text.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped source already uses RequestOrchestration as the active CDS resource and contains the clarified Request pattern and RequestOrchestration guidance. Re-adding a 2019 "seeking feedback" ballot-era note would now be stale because later accepted issues converted that feedback into enduring guidance.

Recommendation:
Keep this audit commit as-is. No core FHIR source follow-up is needed for FHIR-24619; any renewed concern about the name itself should be raised as a new work-group decision rather than by restoring RequestGroup wording or a temporary feedback request.
