FHIR-12655: Audit retired DocumentManifest attachment removal

Issue request:
FHIR-12655 was a Published/Persuasive DSTU2 change request for DocumentManifest asking to remove DocumentManifest.content.pAttachment because DocumentManifest is a manifest, not a container for the referenced objects. The final resolution records FM confirmation that DocumentManifest was no longer used for attachment workflows and did not need the attachment element.

Initial application:
The issue was applied in git commit 94e532a611046fcdc40df2d7d28457eeb7dad3a6, whose San Diego WGM block-vote message explicitly names GF#12655. That commit removed pAttachment/p[x] usage from examples and changed the historical DocumentManifest spreadsheet from a content backbone with DocumentManifest.content.p[x] typed Attachment|Reference(Any) to DocumentManifest.content 1..* Reference(Any).

Additional context:
FHIR-5877 previously added Attachment as a DocumentManifest content alternative, while FHIR-13534 was applied in the same 2017 block-vote commit to broaden DocumentManifest language around manifests of any FHIR resource type. Both related issues already have audit commits on the combined branch. Current source no longer has an active DocumentManifest resource: source/fhir.ini comments the old documentmanifest resource/workgroup/TLA entries, lists DocumentManifest under removed resources, marks the old approval as dropped, and maps the old type to List; source/history.html says DocumentManifest was removed with use List; git commit ea941737076615e7e2772299c80c63e1490f2e93 deleted source/documentmanifest. The remaining DocumentManifest.content.p[x] hits are historical release snapshots under tools/history, not authoritative current-build source.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The requested pAttachment removal was applied to the historical DocumentManifest source, and the current build has retired DocumentManifest rather than carrying any current DocumentManifest.content model forward. Editing historical release snapshots would rewrite old-release evidence, and adding guidance to List or DocumentReference would be a new current-release design decision rather than a safe reconciliation of FHIR-12655.

Recommendation:
Keep this audit commit as-is for FHIR-12655. If current implementations need manifest-like inline attachment guidance, raise or use a current tracker against List, DocumentReference, or another active resource instead of reviving retired DocumentManifest content.
