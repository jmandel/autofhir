FHIR-12181: Audit ElementDefinition sliceName rename

Issue request:
FHIR-12181 was a Published/Persuasive FHIR-core StructureDefinition change request from DSTU2 asking to clarify that ElementDefinition.name applied only to slice roots by renaming it to sliceName. The issue also noted a desired constraint limiting presence to sliced paths, but the Jira application comment described that expression as hard to make reliable for differential, snapshot, and nested slicing.

Initial application:
The issue was applied in svn revision 10016, now git commit c997080bc43c87c6a1c22e4ac6b06a2cb0cdcf40, which renamed ElementDefinition.name to ElementDefinition.sliceName, updated its definition/short text, and added the first sliceName token invariant. Later history added the compatibility map ElementDefinition.name=ElementDefinition.sliceName in source/fhir.ini rather than reintroducing the old element.

Additional context:
ElementDefinition is still an active normative datatype in source/fhir.ini, and the authoritative spreadsheet source now defines ElementDefinition.sliceName with slice-specific wording. The ElementDefinition narrative also states sliceName is prohibited except where required for constrained-resource slices, so the current spec conveys the intended use without adding a brittle cross-snapshot invariant. Jira and Zulip searches found no later conflicting decision; related sliceName/example issues discovered during the check are already represented on the combined branch.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because the old ElementDefinition.name element is absent from the current ElementDefinition source except for the explicit backwards-compatibility rename map, while current source and narrative already use and constrain sliceName.

Recommendation:
Keep this audit as-is. Further core changes for FHIR-12181 would be redundant unless FHIR-I decides to introduce a new enforceable invariant for sliceName presence in a separate tracker.
