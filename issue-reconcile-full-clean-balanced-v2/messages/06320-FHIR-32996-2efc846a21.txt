FHIR-32996: Audit cancelled Observation status guidance

Issue request:
FHIR-32996 was an Applied FHIR-core Observation change request, resolved Persuasive with Modification, asking that Observation.status "cancelled" indicate that when an Observation records a cancelled/aborted or incomplete test, a reason should be supplied, particularly through Observation.dataAbsentReason.

Initial application:
The change was applied before this reconciliation. Commit 0ad9c3cabd7821f1d02b513946d291cb14a28c2b updated source/observation/codesystem-observation-status.xml so the cancelled code definition now says a data absent reason should be present to explain why there is no Observation value; PR #3269 later merged that work and the Jira comment cites the applied build commit.

Additional context:
Observation is an active current-build resource in source/fhir.ini, and the current Observation guidance page also tells implementers to use status "cancelled" with details, preferably coded in dataAbsentReason or valueCodeableConcept. Later related Jira FHIR-46682 requested a separate Observation.statusReason but was withdrawn/resolved Not Persuasive, so it does not supersede the existing dataAbsentReason guidance.

AutoFHIR reconciliation:
No source change was made. The active source already conveys the approved rule in the Observation status CodeSystem and supporting Observation narrative guidance, and adding duplicative prose or a stronger conformance rule would go beyond the Applied FHIR-32996 resolution.

Recommendation:
Keep this audit commit as-is. No follow-up is needed in FHIR core unless the work group later approves a different mechanism for cancellation reasons.
