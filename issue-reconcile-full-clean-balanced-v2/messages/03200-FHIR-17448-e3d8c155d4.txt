FHIR-17448: Audit HealthcareService communication targets

Issue request:
FHIR-17448 is a Published, Persuasive with Modification FHIR-core Communication change request. It asked to add HealthcareService as an allowed reference target for Communication.recipient, add HealthcareService to Communication.sender and CommunicationRequest.recipient, and update the Communication sender/recipient notes so the prose matched the reference targets.

Initial application:
The issue was applied in git-svn commit 210b298936180b3e43c7158581a5cf4e56d770b7, which explicitly names GF#17448 and added HealthcareService to the old Communication and CommunicationRequest spreadsheet targets and to both notes pages. The current source has since been refactored from spreadsheets to StructureDefinition XML, and the HealthcareService target profiles remain present in the active resource source.

Additional context:
Communication and CommunicationRequest are active resources in source/fhir.ini. CommunicationRequest.sender has since been renamed/reworked as CommunicationRequest.informationProvider in current source, but the HealthcareService target that FHIR-17448 expected for the sender role is still present there. Later Jira FHIR-49290 provides background that HealthcareService can be used as an actor/participant, but it concerns a broader HealthcareService/Event-pattern clarification and is not decided by this audit.

AutoFHIR reconciliation:
No source change was made. Current Communication.recipient, Communication.sender, CommunicationRequest.recipient, and CommunicationRequest.informationProvider all include HealthcareService targetProfile entries, and the notes pages already list HealthcareService in the sender/provider and recipient target lists.

Recommendation:
Keep this no-change audit commit as-is for FHIR-17448. No follow-up is needed for this issue in FHIR core unless a separate work group decision changes the broader HealthcareService participant policy.
