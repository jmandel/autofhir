FHIR-18395: Audit extension registry base URI wording

Issue request:
FHIR-18395 was a Published/Persuasive STU3 FHIR-core clarification from N-Infra #83. It asked to change the extension registry sentence from "All extensions are defined under http://hl7.org/fhir/StructureDefinition/" to wording that says the entries in this list have a base URI of http://hl7.org/fhir/StructureDefinition/.

Initial application:
The Jira comment points to GH#db9355a66d. Commit db9355a66d9e549d3043a73c6aef8c9f6e40b46b changed source/extensibility-registry.html in November 2018, replacing the overbroad sentence with wording that the extensions in the list are defined in the specification and have the requested base URI. That commit bundled several neighboring extension-registry trackers, so the FHIR-18395 wording change was applied as part of a multi-issue registry cleanup.

Additional context:
The old core source/extensibility-registry.html page was later removed by commit 4118eb9ddb6eabe52c56c903b3932f27c2c42e38 when registry content moved to the FHIR Extension Pack. In the current core checkout, publish.ini actively publishes extensibility.html and related pages but has extensibility-registry.html commented out under special pages, while source/defining-extensions.html links to the extension registry through the extensions-location substitution. The Extension Pack's active extension-registry page now contains the corrected base-URI wording. Exact source searches found no remaining old "All extensions are defined under" sentence in either current core or the Extension Pack, and Zulip/Confluence searches found no conflicting discussion specific to FHIR-18395.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current core no longer owns the old registry page, and the current authoritative Extension Pack registry already says that extensions in the list are defined in the specification and have a base URI of http://hl7.org/fhir/StructureDefinition/.

Recommendation:
Keep this audit commit as-is. No FHIR-core follow-up is needed for FHIR-18395 unless the Extension Pack registry wording is later changed or ownership of the registry page moves back into core.
