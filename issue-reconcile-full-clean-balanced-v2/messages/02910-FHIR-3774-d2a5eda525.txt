FHIR-3774: Audit optional Composition confidentiality

Issue request:
FHIR-3774 was a Published/Persuasive with Modification Structured Documents change request against DSTU1 Composition. It asked to make Composition.confidentiality optional because confidentiality is not relevant for all Composition use cases, while allowing clinical-document profiles to require it where appropriate.

Initial application:
The Jira comments record svn revision 4661. In the git mirror, that revision is c252f36517f7c77524bde4f19390d450b001f167, whose before/after source comparison changes the old source/composition/composition-spreadsheet.xml row for Composition.confidentiality from 1..1 to 0..1. The same svn revision also handled the nearby FHIR-3775 clinical-document profile/subject work, explaining why the commit subject does not name FHIR-3774.

Additional context:
Composition is still an active current-build resource, but later Structured Documents issue FHIR-17301 removed Composition.confidentiality entirely for R5 because it duplicated security-tag functionality. That later decision is already represented on the combined branch by 3f1e99663a2dd3eaaa0ad9b8349b76af6602842f. Current Composition source has no active Composition.confidentiality element or search parameter, the CDA note maps ClinicalDocument.confidentialityCode to Bundle.meta.security, and the $document operation tells servers to determine a document Bundle.meta.security high-water mark. The old source/profiles/cda.profile.xml still contains a required Composition.confidentiality slice, but source/fhir.ini comments that profile out, so it is not a current build input.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The seed requirement that base Composition not require confidentiality is satisfied: the current active resource no longer has the element at all, and the later approved replacement guidance uses Bundle.meta.security rather than reintroducing a required Composition.confidentiality field.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for FHIR-3774; future clinical-document confidentiality constraints should follow the later Bundle.meta.security direction or be handled by specific active profiles, not by restoring the removed base Composition element.
