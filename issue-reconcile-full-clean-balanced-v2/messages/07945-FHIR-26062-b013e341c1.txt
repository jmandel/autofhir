FHIR-26062: Add search modifier type properties

Issue request:
FHIR-26062 was Published with a Persuasive with Modification resolution for R5. It asked FHIR-I to update the search-modifier-code CodeSystem so the of-type modifier code matches the normative search specification spelling, and to add properties to the modifier concepts indicating the search parameter type each modifier corresponds to.

Initial application:
The code spelling portion was already applied in source/searchparameter/codesystem-search-modifier-code.xml: the current concept code is of-type, not ofType. Git history shows commit 7c3f73fb1f51cbbb40b332c19799a40dbab2bfaf changed that code while applying later search modifier consistency work. The requested computable concept properties were not present before this reconciliation.

Additional context:
The current build scope includes the search modifier value set through source/fhir.ini, and the adjacent search-modifier-code CodeSystem is the source for the code system referenced by that value set. Later search-page work, especially FHIR-36684 and FHIR-37846, refined the current modifier-to-search-parameter-type table; this reconciliation follows the current search.html table rather than the older 2020 wording. The iterate modifier is intentionally left without a search-param-type property because the current search page says it is not allowed for any search parameter type by default and only applies to _include/_revinclude result parameters.

AutoFHIR reconciliation:
Added a CodeSystem property definition named search-param-type, bound by the codesystem-property-valueset extension to ValueSet/search-param-type, and populated each generally typed search modifier concept with repeated valueCode properties matching the current search modifier table. No narrative text or generated diagram artifacts were changed.

Recommendation:
Keep this commit as-is. It completes the missing computable metadata from FHIR-26062 while preserving the already-applied of-type spelling and following later normative search-page decisions for the current type mapping.
