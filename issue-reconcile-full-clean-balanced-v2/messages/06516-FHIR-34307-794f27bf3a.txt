FHIR-34307: Audit logical-model sdf-3 exception

Issue request:
FHIR-34307 was a Published FHIR-core StructureDefinition issue with Persuasive with Modification resolution. It asked to relax sdf-3 because forcing formal definitions on every element does not make sense for some logical models, and it also requested the versions page to clarify that normative invariant changes are prohibited only when they break forward compatibility.

Initial application:
The issue was applied by cb57c390ab490af5018e01f60f27c5f395e282ca, which changed sdf-3 on StructureDefinition.snapshot so the formal-definition/cardinality rule is skipped when %resource.kind = 'logical', and changed source/versions.html to frame invariant changes around forward compatibility. No prior Issue-Reconcile-Key commit for FHIR-34307 exists on the combined branch.

Additional context:
source/fhir.ini actively includes StructureDefinition as a resource, so source/structuredefinition/structuredefinition-StructureDefinition.xml is in current build scope. A later FHIR-36755 commit superseded the exact versions-page wording with a more specific compatible formulation that bars changes that could invalidate previous instances while allowing warning/best-practice and certain error invariants; FHIR-36755 is already represented on the combined branch. The August 2022 FHIR-I minutes and Zulip thread show the application review focused on whether normative invariants were checked and on unreliable xpath constraints; FHIR-37871 later addressed the xpath concern and is also already represented on the combined branch.
