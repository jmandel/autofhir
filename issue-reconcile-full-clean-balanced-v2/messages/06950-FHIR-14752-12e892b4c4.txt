FHIR-14752: Clarify SpecimenDefinition temperature qualifier binding

Issue request:
FHIR-14752 was Published/Persuasive with Modification for the STU3 SpecimenDefinition ballot comment that the handling-condition value set contained temperature concepts but was described as a general set of handling instructions. The accepted resolution renamed conditionSet to temperatureQualifier, renamed tempRange to temperatureRange, and directed non-temperature handling conditions to the instruction element.

Initial application:
No Jira-keyed source commit was found. The change appears to have been partially applied through the 2018 SpecimenDefinition tracker-items commit that renamed the old spreadsheet element paths from conditionSet/tempRange to temperatureQualifier/temperatureRange, and the current XML source preserves those element names and definitions. The active binding and ValueSet descriptions, however, still retained the old "Set of handling instructions" wording.

Additional context:
SpecimenDefinition is an active resource in source/fhir.ini, and source/specimendefinition/structuredefinition-SpecimenDefinition.xml plus source/specimendefinition/valueset-handling-condition.xml feed the current build. OO Confluence minutes record FHIR-14752 as approved and applied. No Zulip discussion or conflicting Jira issue was found for this exact change. The included THO CodeSystem still has similar legacy metadata, but this reconciliation is limited to the current FHIR core checkout.

AutoFHIR reconciliation:
Updated the SpecimenDefinition.typeTested.handling.temperatureQualifier binding description and the core ValueSet/handling-condition description to say they are qualifiers for the temperature interval of specimen handling before testing, matching the renamed element and accepted resolution without changing the canonical URL, binding name, code system, or example binding strength.

Recommendation:
Keep this source fix. If terminology owners want the external THO CodeSystem metadata aligned as well, handle that separately through the terminology/UTG process; the core build no longer describes the value set or binding as generic handling instructions.
