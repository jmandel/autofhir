FHIR-6149: Audit transaction entry wording

Issue request:
FHIR-6149 was a Published/Persuasive DSTU1 technical correction against the Bundle transaction narrative. It reported that the sentence "Each entry element MAY contain a transaction element, and MAY contain either a resource element" was incomplete after "either" and needed the transaction entry wording corrected.

Initial application:
The issue was directly applied in git commit 12427be0018a72ecad38f4aa697d9660278a2ca7, matching Jira's svn revision 5354 comment. That commit changed the Bundle transaction paragraph to say each transaction entry SHALL contain either a transaction element or a resource element, or both, and retained the resource body requirement for PUT and POST entries.

Additional context:
Bundle is an active current-build resource in source/fhir.ini. Later same-family issues changed the old DSTU1 wording substantially: FHIR-8874 and FHIR-8881 replaced the obsolete "transaction element" terminology with Bundle.entry.request, FHIR-14550 made request details mandatory for transaction and batch entries, FHIR-14551 clarified parallel HTTP transaction prose, and FHIR-38942 preserved the current rule in Bundle invariant bdl-3c. The old either/or sentence is now gone from the active Bundle narrative, and related audit commits for FHIR-8874, FHIR-8881, FHIR-14550, FHIR-14551, FHIR-17083, and FHIR-38942 are already present on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped Bundle narrative says transaction and batch entries contain a request element with HTTP operation details and contain a resource when the method is PUT, PATCH, or POST; the authoritative bdl-3c invariant enforces request.method and the corresponding resource condition. Reintroducing or polishing the obsolete either/or sentence would be less correct than preserving the later approved request-based rule.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed for FHIR-6149; any future grammar cleanup in the Bundle transaction paragraph should be handled as a separate editorial issue rather than as required reconciliation for this tracker.
