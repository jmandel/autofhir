FHIR-39358: Audit search parameter table links

Issue request:
FHIR-39358 was a Published/Persuasive FHIR-core R5 change request asking that names in ResourceType Search Parameters tables be hyperlinked so the search parameter definitions are discoverable, with the final resolution allowing links from resource search sections to the per-resource search-definition page or registry.

Initial application:
No commit in this repository's history explicitly mentions FHIR-39358. The closest prior source-side application found was b7e37c11 (FHIR-38728), which updated active resource/search templates to point users from each resource page to the full resource search-parameter list and from resource search pages to related search-parameter material. The row-level table links themselves are generated by the FHIR publishing tooling rather than maintained as static source rows in this checkout.

Additional context:
FHIR-I minutes for the January 2023 WGM record FHIR-39358 as Persuasive and assigned to tooling, which matches the current source structure: active resources are declared in source/fhir.ini, tools/templates/template.html contains the Search Parameters section and delegates the table to <%search%>, and tools/templates/template-search.html delegates the full list to <%searchParamTable%>. The current CI build shows the generated first-column names on resource Search Parameters tables linking to per-resource search-definition anchors, with registry links for common parameters.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current built specification already satisfies the accepted discoverability requirement, and changing core source templates would either duplicate publisher-owned table-generation behavior or risk perturbing unrelated rendering.

Recommendation:
Keep this no-change audit commit. If future builds lose the row-level links, handle that as a publisher/tooling regression rather than a FHIR core source content correction.
