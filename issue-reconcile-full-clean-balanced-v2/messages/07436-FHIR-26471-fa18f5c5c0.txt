FHIR-26471: Audit _profile search parameter type

Issue request:
FHIR-26471 was a Published/Persuasive technical correction against FHIR-core BaseResource. It asked for the Search page's _profile text to say that _profile is a uri search parameter because, at the time, the summary table and Resource search parameter page showed uri rather than reference.

Initial application:
The issue was initially applied by commit 83caaa1641, which changed the original source/search.html prose from "_profile is a reference search parameter" to "_profile is a uri search parameter." No other source files were changed by that issue-tagged commit.

Additional context:
FHIR-30514 was later Published/Persuasive with the explicit resolution "Will mark the type as reference everywhere." Its application commit 6d75b061ed changed Resource-_profile from uri to reference, and FHIR-33203 was retracted after confirming that FHIR-30514 had been applied. Current source/search.html and source/resource/bundle-Resource-search-params.xml now consistently define _profile as reference, and a 2026 implementers Zulip discussion confirms that reference remains the intended R4-and-later interpretation for version-aware canonical profile URLs.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Changing _profile back to uri for FHIR-26471 would reintroduce the inconsistency that the later FHIR-30514 decision resolved and would contradict the current active source.

Recommendation:
Keep this empty audit commit as-is. Any future desire to change _profile away from reference should be handled as a new work-group decision, not by reapplying the superseded FHIR-26471 wording.
