FHIR-17782: Audit id extension note

Issue request:
FHIR-17782 is a Published/Persuasive with Modification FHIR-I change request for STU3 BaseResource. It asked the specification to document that id fields cannot have extensions or their own id fields, after a Zulip JSON Schema discussion showed that the rule was not clearly stated in the StructureDefinition surfaces. The accepted resolution was to add a text note and leave infrastructure enforcement for a later R5 tracker.

Initial application:
The Jira comment points to GH#d61a7279cf, and git history confirms commit d61a7279cf added "The <code>id</code> element does not have extensions itself" to source/element.html. Commit cbdf7d1e55 later rebuilt the abstract type framework and moved the active Element text into source/types.html while preserving the same note.

Additional context:
source/fhir.ini maps element=types in [type-pages], so source/types.html is the active current-build source for the Element page. Current source/types.html retains the internal id scope section and the no-extensions note. Zulip confirms the original gap and Confluence searches found no conflicting work-group record.
