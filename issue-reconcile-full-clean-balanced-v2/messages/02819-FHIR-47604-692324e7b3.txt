FHIR-47604: Remove stale DeviceAssociation operation usage

Issue request:
FHIR-47604 was Applied/Persuasive with Modification for R6. The Orders and Observations decision was to remove the DeviceAssociation operator/operation backbone, add DeviceAssociation.focus with the same reference targets as subject, add the focus search parameter and compartment participation, and carry operation-status concepts through DeviceAssociation.associationStatus instead of a separate operation backbone.

Initial application:
The issue was applied by HL7/fhir#3872 and HL7/fhir#3897. PR #3872 removed the operator search parameter, added focus, updated compartments, and began converting examples; PR #3897 removed the remaining DeviceAssociation.operation backbone from the StructureDefinition and deleted the operation-status CodeSystem/ValueSet. After those commits, active DeviceAssociation examples still contained <operation> blocks and one subject comment still described the deleted operation/operator backbone.

Additional context:
DeviceAssociation is active in source/fhir.ini, and the edited files are current resource source inputs under source/deviceassociation. source/fhir.ini's r5-r6 change list correctly records DeviceAssociation.operation.* removals and DeviceAssociation.focus addition, so it was not changed. Confluence OO/HCP minutes for 2025-10-20 record the 8-0-0 persuasive-with-modification vote for FHIR-47604. The later FHIR-53680 ticket notes that the .subject comment is confusing because it still talks about operation, but it remains Waiting for Input and was treated only as background. Zulip searches found no directly relevant conflicting discussion.

AutoFHIR reconciliation:
This commit removes the obsolete DeviceAssociation.operation blocks from active examples, represents operator examples with DeviceAssociation.relationship=operator plus base period and associationStatus=on, and replaces the stale DeviceAssociation.subject comment with current guidance that subject identifies the operator while focus identifies the entity for which the device is being used. No generated-looking SVG diagram was manually edited; the authoritative StructureDefinition and examples now carry the reconciled semantics.

Recommendation:
Keep this source fix. It completes the applied FHIR-47604 behavior in the current build inputs; future work on FHIR-53680 can still review broader DeviceAssociation attribute wording, and any diagram refresh should be handled by the normal generation process rather than hand-editing the stale SVG.
