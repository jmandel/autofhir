FHIR-42911: Audit all-resource search parameter wording

Issue request:
FHIR-42911 was an Applied/Persuasive FHIR-I technical correction against FHIR-core SearchParameter/search.html. It reported that section 3.2.1.8.1 "Parameters for all resources" listed _text and _filter in the all-resource parameter list and then repeated that _text and _filter also applied to all resources, making the "In addition" sentence confusing.

Initial application:
The issue was applied before this reconciliation by source/search.html commit 597f358387d1417e0bd8efbdb03907668d276742, also present as duplicate branch commit 027fc41f8b440a62babb2fae9fdd928102e03ba0 before merge. That commit replaced the explicit repeated _text/_filter sentence with a note that search result parameters also apply to all resources.

Additional context:
FHIR-I minutes for 2023-11-06 record FHIR-42911 in a search/HTTP/subscriptions block vote that passed 12-0-0, and the preceding Zulip block-vote announcement listed the issue without later objection in that thread. The current source/search.html page is the source page for build.fhir.org/search.html, the Jira related URL, and its current all-resource paragraph no longer duplicates _text or _filter.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/search.html already says "The following parameters apply to all resources: [%allparams%]" followed only by a note that search result parameters also apply, which preserves the intended guidance without repeating _text and _filter as additional all-resource search parameters.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-42911 unless a future search-page edit reintroduces an explicit duplicated _text/_filter all-resource sentence.
