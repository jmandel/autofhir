FHIR-22505: Audit profile name casing compliance

Issue request:
FHIR-22505 was Published with a Persuasive with Modification resolution for FHIR-core Feed profiles raised from STU3 and applied for R5. The request observed that profiles in Bundle-profiles-others.json mixed run-on ids with spaced names and asked for consistency; the final decision was to leave id values alone but make StructureDefinition.name values comply with sdf-0, i.e. name.matches('[A-Z]([A-Za-z0-9_]){0,254}').

Initial application:
No commit explicitly mentioning FHIR-22505 was found. Historical release bundles show the affected examples still had spaced names in R4/R4B, while R5 profiles-others.xml has sdf-0-safe names such as ShareableActivityDefinition and ProvenanceRelevantHistory. Git history points to broader canonical naming cleanup, especially f87870f3725a6987f2cddcd4d804c6bdf39c0755 (FHIR-37449), which changed source profile names including Shareable ActivityDefinition to ShareableActivityDefinition and Provenance Relevant History to ProvenanceRelevantHistory.

Additional context:
The current build no longer has a checked-in Bundle-profiles-others.json source artifact. Active resource folders remain governed through source/fhir.ini, and current profile StructureDefinition source is held in active resource folders such as Bundle, Parameters, Observation, Composition, FamilyMemberHistory, and Provenance. Later source refactors removed or migrated some older shareable/publishable metadata profiles, so obsolete release-history bundles are not current build inputs. A full current-source scan found one noncompliant StructureDefinition.name, source/structuredefinition/invariant-tests/cnl-0.f1.fail.xml, but that file is intentionally named as a failing cnl-0 invariant test rather than an active profile requiring correction.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current structuredefinition-profile-*.xml files all have names matching the sdf-0 regex, and representative current names retain stable ids while using PascalCase names such as DocumentBundle, DefinedParameters, and ProvenanceRelevantHistory.

Recommendation:
Keep this no-change audit commit. No current FHIR core source edit is needed for FHIR-22505; future cleanup should not rewrite historical release bundles or the intentional invariant failure test as part of this issue.
