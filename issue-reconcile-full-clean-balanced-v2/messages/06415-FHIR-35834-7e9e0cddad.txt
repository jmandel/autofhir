FHIR-35834: Audit current-canonical operation

Issue request:
FHIR-35834 was a Published/Persuasive with Modification FHIR-I change request for R5 asking for an operation that accepts an unversioned canonical URL and returns the most current version of the matching canonical resource, with optional status filtering and version-comparison semantics from FHIR-26370.

Initial application:
The issue was explicitly applied by commit dff8b8d97d1dd45db806680c44cd318b68c21333, which added the CanonicalResource $current-canonical OperationDefinition, request/response examples, and operations list entry. Follow-up commit 3642d16be2895c4bb49a67465ad40f4226bf8efe, also marked FHIR-35834, corrected the request examples to use CodeSystem, changed the url parameter type from url to uri, and clarified that version comparison uses the specified versionAlgorithm rather than lastUpdated.

Additional context:
FHIR-26370 introduced CanonicalResource.versionAlgorithm[x], the comparison mechanism that FHIR-35834 depends on. Current source/fhir.ini declares CanonicalResource as an active infrastructure interface, and the CanonicalResource source folder contains the active OperationDefinition and list entry. A later FHIR-48980 no-change decision discussed a resource-independent canonical lookup, but it did not require changing $current-canonical and instead confirmed existing cross-resource canonical-url/canonical-version search behavior.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source already defines $current-canonical at system and type level for CanonicalResource, with required uri url input, repeating code status input, optional CanonicalResource result output, no-result behavior, ambiguous-version failure behavior, examples, and a list entry that exposes the operation for the active CanonicalResource interface.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-35834 unless a new tracker reopens broader behavior such as accepting versioned canonical values or adding resource-type filtering to the operation.
