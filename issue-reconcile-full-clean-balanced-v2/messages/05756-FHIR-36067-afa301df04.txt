FHIR-36067: Audit Observation component absent-value invariant

Issue request:
FHIR-36067 is an Applied/Persuasive with Modification OO change request for FHIR-core Observation. It reported that a blood pressure Observation validating against the bp profile passed when both systolic and diastolic components had component.valueQuantity and component.dataAbsentReason, and the accepted resolution was to add an invariant to Observation.component.value[x] analogous to the existing Observation.value[x] rule.

Initial application:
The issue was applied in source history by commit e832cabab82fa5c30949380ede5d2eef80f5194c, which added the obs-10 constraint to source/observation/structuredefinition-Observation.xml. The Jira comment later pointed at PR #3351 commit 7522e5c98a262dd2a46575a4fe324e849e7c661d as the build application record.

Additional context:
Observation is an active current-build resource in source/fhir.ini, and the bp profile is part of the Observation vital signs implementation guide. FHIR-50145, a later Applied/Persuasive technical correction in the same constraint family, clarified obs-6/obs-10 text, added missing obs-10 condition tags, and added obs-10 invariant tests in commit 58e1e1353018b34133ee9ad8cb4d5b6768eb04ac. FHIR-50145 is already represented on the combined branch by audit commit 4d2b1aaf089f44790e86ed7eafd9d5e39f0f52d8, so this reconciliation does not publish a duplicate commit for it. Community searches found one early OO minutes page asking for broader discussion of FHIR-36067 and no conflicting Zulip evidence.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current Observation source already has obs-10 as an error invariant with expression component.empty() or component.where(dataAbsentReason.exists()).all(value.empty()), and the relevant Observation.component, Observation.component.value[x], and Observation.component.dataAbsentReason elements carry obs-10 condition tags. The current invariant tests include the blood-pressure-style failing XML example with both component.valueQuantity and component.dataAbsentReason, so the originally reported validator gap is represented in active source and tests.

Recommendation:
Keep this audit commit as-is. No further core FHIR source change is needed for FHIR-36067 unless a future OO decision changes the Observation component value/dataAbsentReason exclusivity rule.
