Issue request:
FHIR-17247 was a Published/Persuasive CQI change request raised against STU3 Measure asking for improvementNotation to be machine-readable, either as a code bound to known increase/decrease values or as a CodeableConcept extensibly bound to the current known values. The final resolution requested improvementNotation 0..1 code { increase, decrease } and adding the element to MeasureReport.

Initial application:
SVN 14046, represented in git as e169985949ad77cfed6c6e86ee8036a90f98136e, explicitly included GF#17247 and changed Measure/MeasureReport source spreadsheets and examples so improvementNotation used code values such as increase. No current source edit is needed solely to repeat that STU3 application.

Additional context:
Measure and MeasureReport are active current-build resources in source/fhir.ini. Later CQI decisions changed the current conformance shape: FHIR-28936 added group-level Measure calculation metadata including Measure.group.improvementNotation as CodeableConcept, FHIR-31413 clarified why MeasureReport repeats the Measure improvementNotation, FHIR-49670 clarified Measure-to-MeasureReport group correspondence, FHIR-49922 moved calculation-characterizing elements to group level, and FHIR-50664 removed the deprecated root Measure and MeasureReport improvementNotation elements. Current source therefore correctly carries Measure.group.improvementNotation and MeasureReport.group.improvementNotation as CodeableConcept with extensible bindings to the measure-improvement-notation value set, and MeasureReport says the value is populated from the corresponding Measure group. Zulip and Confluence searches found no contrary community evidence.
