FHIR-7530: Audit removed ElementDefinition binding name

Issue request:
FHIR-7530 was a Published/Persuasive 2015 May FHIR-core ballot issue for FHIR-I. It asked to remove ElementDefinition.binding.name because binding-name links confused readers, and to have tooling use the target ValueSet name or a NamingSystem-backed external source label instead.

Initial application:
The Jira snapshot records a vote of 11-0-0 on 2015-06-10 and an application comment of "svn revision 7530." No Git commit in this checkout explicitly mentions FHIR-7530, but the current history shows the requested source change was applied during the DSTU2 ballot cleanup: commit fbaf29fb043878886a33392fb9a1017135ef9fed removed the ElementDefinition.binding.name row from source/datatypes/elementdefinition.xml, and commit 58727a74e2a7cac67026906f355607b64bd0bf90 added the release-history note listing "remove binding.name" for ElementDefinition.

Additional context:
ElementDefinition is an active datatype in source/fhir.ini, so source/datatypes/elementdefinition.xml is the authoritative current build input. Current source searches find no ElementDefinition.binding.name child in the core datatype; the only core source occurrence of "binding.name" is the version-history note that it was removed. Later related work kept an optional elementdefinition-bindingName extension for rendering/table convenience rather than reintroducing a formal ElementDefinition.binding.name element. FHIR-51990, which clarified that extension's wording and scope, is already represented on the combined branch by commit 2d439b612e4e7750890cc38f922f1ad3c562254a and must not be duplicated here.

AutoFHIR reconciliation:
This commit makes no source change. The current FHIR-core source already satisfies FHIR-7530: the formal ElementDefinition binding backbone contains strength, description, valueSet, and additional binding children, but no name element.

Recommendation:
Keep this no-change audit commit. No further FHIR-core work is needed for FHIR-7530; any future cleanup of the separate bindingName extension should remain with the already-audited extension-pack issue family, not this removed core element.
