FHIR-38745: Audit compartment GET search examples

Issue request:
FHIR-38745 was Published with resolution Persuasive with Modification. It asked to add a GET-based compartment search example to the search HTTP GET table and to retain or clarify the note that the old compartment-search URL was indistinguishable from a read operation; the final resolution instead said the indistinguishable statement was not true, should be dropped, and compartment search examples should be added.

Initial application:
The issue was applied by git commit 72539afe56e743824da8f6b8d6e71f33c908dc71, which changed source/search.html by replacing the old "Compartment Search" row that said the search was unavailable because it was indistinguishable from a READ operation with two GET compartment-search examples: one using [compartment-id]/* for all compartment resource types and one using [compartment-id]/[resource-type] for a specific type.

Additional context:
FHIR-I minutes on 2022-10-24 record the Persuasive with Modification vote for FHIR-38745. A later source refactor, FHIR-39137 in commit e441170220c19e992f803667b245e63dcdd508cf, moved the detailed HTTP POST/GET search protocol material from source/search.html into source/http.html. The active source hierarchy still includes http.html as the RESTful API page and search.html as its Search child page, so the current location of the detailed GET table is in build scope. Searches of Zulip and nearby Jira/Confluence records found no conflicting later decision for this issue.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current source/http.html contains the two GET compartment search examples, including the [compartment-id]/* disambiguating form, and the old "not available because indistinguishable from a READ operation" statement is absent. Current source/search.html also explains that '*' is valid as [type] in a GET-based compartment search to disambiguate a read from a compartment search.

Recommendation:
Keep this no-change audit commit as-is. The Published issue has already been applied and preserved through the later HTTP/Search page refactor; no further core source work is needed for FHIR-38745.
