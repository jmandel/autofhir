FHIR-36646: Audit search missing-element clarification

Issue request:
FHIR-36646 was Published/Persuasive with Modification for the FHIR-core search page. It asked the search page to clarify that a SearchParameter whose path has no element value does not match ordinary value/prefix searches, and to clarify that ne means the element has a value that is not equal to the specified value.

Initial application:
The issue was applied by git commit 13b8634a1423459eecdad6f69bc4f45b735cba44, which changed source/search.html for FHIR-36646 by making prefix descriptions value-present tests and adding an explicit paragraph that a prefix-based test against a missing element fails, with missing-value searches requiring the missing or token not modifier.

Additional context:
FHIR-I minutes on 2022-04-04 record the approved clarification as "ne does not apply to missing value" with an 11-0-0 vote. The July 2022 Zulip implementation discussion resolved the apparent tension with the existing token :not modifier: :not intentionally includes resources with no matching token value, so it is not the same as ne, while ne/prefix tests still fail when the searched value is absent. Later source edits, including FHIR-40029 and FHIR-40319 wording work, reorganized the prefix table but retained the current explicit missing-element rule.

AutoFHIR reconciliation:
This audit commit makes no source change. The current build source at source/search.html already states that prefixes always test against values present in elements, that a prefix-based test against a non-existent element fails, and that searching for missing values requires the missing modifier or the token-specific not modifier. The missing and not modifier sections also define their behavior consistently with that rule.

Recommendation:
Keep this audit commit as-is. No additional core source change is needed for FHIR-36646 unless the work group later decides to change the long-standing token :not behavior or add a separate single-query OR mechanism for missing date values.
