FHIR-33268: Audit optional SubscriptionStatus topic

Issue request:
FHIR-33268 was a Published/Persuasive FHIR-I change request for R5. It asked to make SubscriptionStatus.topic optional (0..1) because a canonical SubscriptionTopic URL can disclose PHI, and to add guidance that the topic SHOULD NOT be included for empty payloads, MAY be included for id-only payloads, and SHOULD be included for full-resource payloads.

Initial application:
The Jira comment cites commit cc31b9e89b0c81721faede7b4375631fc8377d73, which changed SubscriptionStatus.topic from min 1 to min 0, added the payload-level comment to the StructureDefinition, and added Content and PHI guidance to the SubscriptionStatus notes. In the current source blame, those lines are carried through commit 17740f61cda26cd5836bee2905becfd196ab1e5c, the R4B/R5 subscription change import that now owns the current topic comment and min value.

Additional context:
source/fhir.ini actively includes subscriptionstatus and subscriptiontopic as resources in the current build. FHIR-I minutes for 2021-09-13 record the FHIR-33268 persuasive 6-0-0 vote and note that Subscription.id remains available to identify the related subscription. Earlier FHIR-27141 explains why SubscriptionStatus.topic is canonical. Later FHIR-39037 considered removing SubscriptionStatus.topic but resolved no-change because optionality already reflects the PHI concern while preserving routing use cases. Later FHIR-39038 added enforceable SubscriptionStatus constraints only where rules are locally checkable; it did not supersede the topic payload guidance. Zulip and broader Jira searches found no conflicting decision for FHIR-33268.

AutoFHIR reconciliation:
This audit commit makes no source change. The active SubscriptionStatus source already has SubscriptionStatus.topic as 0..1 with the requested empty/id-only/full-resource guidance, and the SubscriptionStatus notes include the PHI rationale and link the per-notification tables to that guidance.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-33268 unless the work group later decides to replace the cross-resource payload guidance with a different computable mechanism.
