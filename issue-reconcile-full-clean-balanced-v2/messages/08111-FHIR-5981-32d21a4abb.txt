FHIR-5981: Audit ValueSet context parameters

Issue request:
FHIR-5981 was Published/Persuasive for a compatible substantive DSTU1 Vocabulary change to ValueSet terminology operations. It asked to let clients identify a value set indirectly by supplying a binding/application context, such as a StructureDefinition URL plus a fragment naming or pathing into the structure definition, instead of always supplying the value set identity or resource directly.

Initial application:
The Jira comment records svn revision 5719. The converted git commit ca6ed70bdea0f16cd6171d9cf200fbb46787a087 carries git-svn-id build@5719 and message "#5981 - add $expand.context". Its ValueSet spreadsheet patch updated the expansion operation description to allow identifier, context, or valueset and added both expand.context and validate-code.context URI parameters with the requested StructureDefinition#path guidance. Later source refactors moved the operation definitions out of the spreadsheet into source/valueset/operationdefinition-ValueSet-expand.xml and source/valueset/operationdefinition-ValueSet-validate-code.xml.

Additional context:
source/fhir.ini lists valueset=ValueSet under [resources] and valueset=vocab under work groups, and source/valueset/list-ValueSet-operations.xml references the two active ValueSet operations. The current $expand and $validate-code OperationDefinition sources both say one of url, context, or valueSet must be provided when not called at instance level, and both define a context input parameter using the Structure Definition URL plus fragment form requested by FHIR-5981. Later Published issue FHIR-13326 depends on this behavior by allowing validate-code with a code and context; unresolved Triaged issue FHIR-56399 discusses possible future URI/canonical cleanup for terminology operation parameters but is not a final decision and does not remove the context parameter. Zulip discussion in #terminology confirms the context parameter semantics and implementation experience without conflicting with the source.

AutoFHIR reconciliation:
No source change was made. The current build-scope ValueSet operation sources already implement the requested context parameter for both expansion and validation, preserve the requested URI shape, and present context as an alternative to url/valueSet in the operation descriptions.

Recommendation:
Keep this audit commit as-is. No FHIR-core follow-up is needed for FHIR-5981 unless the work group later resolves FHIR-56399 or a similar issue to change the datatype/version model of terminology operation context parameters.
