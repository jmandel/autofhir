FHIR-11238: Audit retired Sequence strand clarification

Issue request:
FHIR-11238 was a Published/Persuasive Clinical Genomics change request against the DSTU2 FHIR-core Sequence resource. It asked that the vague Sequence.referenceSeq.strand wording "Strand of DNA" be expanded with acceptable values: "1" for the plus strand (5' to 3')/Watson/Sense/positive and "-1" for the minus strand (3' to 5')/Crick/Antisense/negative.

Initial application:
The issue was applied in the old Sequence source before this reconciliation. Commit 6072b705b6 changed source/sequence/sequence-spreadsheet.xml so Sequence.referenceSeq.strand had the requested directionality text and numeric value definitions. Commit a26b8894d0 also added a Sequence notes section explaining +1/-1 and mapping those values to Watson/Crick, Sense/Antisense, and positive/negative.

Additional context:
Later Clinical Genomics work changed the same model. FHIR-14273, also Published/Persuasive, split Sequence.referenceSeq.strand semantics into strand = watson|crick and orientation = sense|antisense, applied by commit ed2a92ec79. FHIR-19453 then renamed Sequence to MolecularSequence in commit 78abae0217. Current source no longer has source/sequence or source/molecularsequence directories; source/fhir.ini lists Sequence under removed resources and comments MolecularSequence out of current build metadata. The remaining MolecularDefinition strand text is a separate current/draft CodeableConcept element and not the old Sequence.referenceSeq.strand integer element.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Reapplying FHIR-11238's old numeric +1/-1 clarification to current source would be outside the current build scope and would conflict with later Clinical Genomics decisions that superseded the original single integer strand element.

Recommendation:
Keep this audit commit as-is for FHIR-11238. If Clinical Genomics wants tighter current MolecularDefinition strand value guidance, that should be handled as a separate current-resource issue rather than as a backport of the retired Sequence.referenceSeq.strand wording.
