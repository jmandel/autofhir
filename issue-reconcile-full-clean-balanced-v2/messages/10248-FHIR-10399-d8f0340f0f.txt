FHIR-10399: Audit DELETE 200 response allowance

Issue request:
FHIR-10399 was a Published/Persuasive FHIR-I change request for the FHIR-core HTTP page. It reported that the delete interaction appeared to allow 200 OK only when a resource was already deleted, while successful deletion or a nonexistent resource appeared to allow only 204 No Content. The accepted outcome was that 200 OK should be allowed for successful deletion too.

Initial application:
No git commit explicitly mentions FHIR-10399. The Jira comment says it was already fixed under a different task. The matching applied task is FHIR-12216/#12216, whose Published/Persuasive resolution aligned the same DELETE statements so 200 OK is used when the response contains a payload and 204 No Content is used when there is no response payload. Git-svn commit 3d7763fc7d0a1a1921562cf73de46c53197d669e, corresponding to svn @10126 cited by FHIR-12216, changed source/http.html accordingly.

Additional context:
The current HTTP page source is in build scope through publish.ini [pages], where http.html is listed as the HTTP page. The current source still says both the general successful-deletion/nonexistent-resource paragraph and the already-deleted-resource paragraph return either 200 OK with a payload or 204 No Content with no response payload. The combined branch already contains an AutoFHIR no-change audit commit for FHIR-12216, so this commit does not duplicate that related issue.

AutoFHIR reconciliation:
This commit intentionally makes no source change because the current build-scope source already satisfies FHIR-10399: 200 OK is allowed for successful deletion when a response payload is returned, and the already-deleted wording is aligned with that rule.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed for FHIR-10399 unless FHIR-I separately decides to revisit DELETE success response codes more broadly.
