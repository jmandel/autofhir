FHIR-33158: Audit search combining clarification

Issue request:
FHIR-33158 was a Published/Persuasive FHIR-core search-page clarification, applied for R5, asking that AND and OR search-parameter combination behavior not be grouped under a "Composite Search Parameters" heading. The request specifically called for renaming the #combining section and removing the misplaced introductory composite/$ sentences because AND and OR parameters are not composite parameters.

Initial application:
The issue was initially applied by Jira-tagged commit 7553224a3289edc37b55479254c15c9db228d047, which moved the #combining anchor to the multiple-values section and rewrote the composite discussion. No prior Issue-Reconcile-Key: FHIR-33158 commit was present on robo-spec-combined-issue-reconcile-full-clean-balanced-v2.

Additional context:
On the current combined branch, source/search.html keeps #combining immediately before "Searching Multiple Values (joining with AND or OR)" and explains AND/OR set logic there, while #composite remains a separate "Composite Search Parameters" section describing true $-joined composite tuples. Later search-page work has preserved that separation, and the community searches found supporting discussion but no conflicting later decision.

AutoFHIR reconciliation:
This audit commit makes no source change. The current build source already removes the misleading placement that FHIR-33158 identified; changing the heading text exactly to "Combining Search Parameters" would be an editorial relabeling rather than a necessary correction to implementer understanding.

Recommendation:
Keep this no-change audit as-is. Revisit only if the work group wants a purely editorial retitling of the multiple-values heading; the applied source already satisfies the substantive clarification.
