FHIR-16435: Audit lockedDate short text

Issue request:
FHIR-16435 was a Published/Not Persuasive with Modification Vocab change request for ValueSet.compose.lockedDate. The ballot comment questioned the short description "fixed date for version-less references (transitive)" and proposed "fixed date for version specific reference"; the final resolution clarified that the references are versionless, but lockedDate determines their versions, so the short text should say "fixed date for references with no specified version".

Initial application:
The issue was explicitly applied by git commit 6eedfb3a12102c0b7aec099a38392ad64d5fcd6d, "GF#16435 - fix definition", which changed source/valueset/valueset-spreadsheet.xml from "Fixed date for version-less references (transitive)" to "Fixed date for references with no specified version (transitive)". Later source migrations carried that short text into source/valueset/structuredefinition-ValueSet.xml.

Additional context:
ValueSet is active in source/fhir.ini, and the current authoritative StructureDefinition source contains the approved short text. FHIR-10490 is an earlier same-element clarification that established the distinction between specified and unspecified versions; FHIR-18702 is a later same-element definition clarification that is already represented on the combined branch by commit cdb63e861bda8989558ad0e1af5d1da31a1874f4; FHIR-55478 is a later deprecation proposal, but Jira still shows it as Triaged/indeterminate rather than Applied or Published. Confluence minutes list FHIR-16435 in the Vocab final vote block as Not Persuasive with Modification, and no direct Zulip discussion was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:

Recommendation:
