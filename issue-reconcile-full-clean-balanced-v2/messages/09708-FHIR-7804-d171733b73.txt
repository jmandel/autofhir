FHIR-7804: Audit extensibility examples

Issue request:
FHIR-7804 was a Published/Persuasive FHIR-core extensibility change request from the DSTU1 ballot asking for better documentation and examples for extensions, both simple primitive extensions and more complex nested structures. The reported problem was that the 2015May extensibility example used a non-real trial-status extension and did not give an inspectable, valid example of nested extension URLs; the accepted resolution was to add more examples.

Initial application:
The issue was applied by git commit 1a0d7e31b50d92270bc4563b315a23feeca892cd, the git-svn import of SVN revision 6521, which replaced the old acme trial-status example in source/extensibility.html with a patient-clinicalTrial example using relative nested URLs and noted the extension definition. Later source refactoring moved the tutorial material to source/extensibility-examples.html. Same-family commits then expanded and repaired the examples: 1848eb0a601336790008a0ee237e768cd2bb7849 added the complex Patient Clinical Trial example for FHIR-8543, 256eb4f2512d7b9e1bbcfefc549d15569882233b added additional simple and complex extension surfaces for FHIR-9648, and recent reconciliation commits corrected current snippet details.

Additional context:
The active current-build source is source/extensibility-examples.html, which is listed in publish.ini. On the combined branch it contains a simple Patient participation-agreement extension, an iso21090-EN-qualifier example on a primitive HumanName part, and the Complex Extension: Patient Clinical Trial tutorial with definition, instance-use, and Patient profile snippets. Later FHIR-12441 removed the official HL7 patient-clinicalTrial extension, so the current tutorial intentionally uses an example.org canonical and states that real clinical-trial participation is usually represented with ResearchStudy or the workflow-researchstudy extension. Direct Zulip and Confluence searches for FHIR-7804 found no conflicting community record; broader complex-extension Zulip threads showed continued implementer questions but no final decision requiring an additional FHIR-7804 edit.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current combined-branch source already satisfies FHIR-7804's accepted request by providing inspectable simple, primitive, and complex extension examples in an active page; reintroducing the removed official clinical-trial extension or adding redundant local prose would risk conflicting with later decisions and maintenance drift.

Recommendation:
Keep this audit commit as-is. If the work group wants deeper nested-extension examples or ElementDefinition.id attributes in tutorial snippets, that should be handled as a separate current Jira decision rather than as unfinished FHIR-7804 work.
