FHIR-32757: Correct duplicate create guidance

Issue request:
FHIR-32757 was a Published/Persuasive with Modification FHIR-core issue for R5. It asked for normative guidance on create/update variability, including ETag handling when stored content differs from submitted content, removal of the visible SUBSETTED Security Label suggestion, duplicate-create handling, 422 Location guidance for uniqueness conflicts, transaction 2xx/3xx wording, and de-containment guidance.

Initial application:
The Jira-tagged commit aa8e2ccd33ac9e6fa6d92d5b0d097d2328b48321 applied much of the issue to source/http.html and source/updates.html. Current source already retained the ETag replacement, visible removal of the SUBSETTED Security Label sentence, de-containment text, transaction 2xx/3xx wording, and one 422 uniqueness-conflict Location sentence. However, the duplicate POST 303 paragraph was placed in the update section, while the create section still retained the older FHIR-22770 note allowing a 201 response for a pre-existing resource.

Additional context:
FHIR-22770 was a Published/Persuasive R5 change that intentionally added the 201-for-existing-record note, but FHIR-32757 was the later final work-group decision for the same duplicate-create behavior and says returning 201 without creating a new record is non-conformant. FHIR-42769 later allowed non-committal 202 Accepted create responses without Location/ETag, so this reconciliation preserves that later exception. FHIR-53926 is a later Triaged, unresolved ballot comment noting that the 303 create response was not listed; it is useful background but is not separately decided here.

AutoFHIR reconciliation:
This commit updates the active HTTP narrative source source/http.html. It moves the duplicate POST guidance into the create section, replaces the stale 201-for-existing-record note with the FHIR-32757 303 See Other guidance and explicit 201-only-when-created rule, clarifies the 201 paragraph so it applies when a new resource is created, adds 303 to the create status-code list and summary row, and adds the approved 422 uniqueness-conflict Location sentence to the create status list. No source/updates.html edit was needed because its current built narrative already carries the ETag and de-containment portions of the issue.

Recommendation:
Keep this source fix. It completes the FHIR-32757 duplicate-create application without changing the later FHIR-42769 202 guidance; FHIR-53926 can be reviewed separately by the work group, but its observed 303-listing gap is addressed by this reconciliation rather than by a separate unresolved-issue decision.
