FHIR-47845: Audit DetectedIssue value set split

Issue request:
FHIR-47845 was Applied/Persuasive for R6 after the reporter noted that DetectedIssue.category and DetectedIssue.code should not both use the Detected Issue Category value set. The accepted resolution was to bind DetectedIssue.category to a value set containing only detected-issue categories while DetectedIssue.code uses the full detected-issue code value set, the same resolution family as FHIR-39458.

Initial application:
No source commit explicitly mentions FHIR-47845. The Jira comment says it was applied in FHIR-39458, and git commit 34181b9f2184a72b527d9f5b26c234c0c07669ed created valueset-detectedissue-code.xml, restricted valueset-detectedissue-category.xml to category concepts, and changed DetectedIssue.code from ValueSet/detectedissue-category to ValueSet/detectedissue-code.

Additional context:
DetectedIssue is an active resource in source/fhir.ini, so source/detectedissue/structuredefinition-DetectedIssue.xml and the source/detectedissue value sets are in current build scope. FHIR-44531 is another Applied tracker with the same concern and resolution. The 2025-03-05 CDS agenda records approval of the pre-applied FHIR-47845 resolution. A checked-in source/detectedissue/detectedissue.svg still shows the old DetectedIssue.code binding, but it is a generated-looking diagram artifact and the authoritative XML/value-set sources now carry the correct binding semantics.

AutoFHIR reconciliation:
This commit intentionally makes no source change.
