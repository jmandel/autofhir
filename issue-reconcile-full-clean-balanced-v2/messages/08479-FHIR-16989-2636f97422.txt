FHIR-16989: Audit extension publication clarification

Issue request:
FHIR-16989 was Published/Persuasive for FHIR-core defining extensions section 2.5.1.5. It asked to clarify that making an extension definition available or published is not the same as advertising it in the HL7 or another extension registry; a public-facing or otherwise available publication context can be sufficient.

Initial application:
The issue was applied by SVN revision 14441, represented in git as cd3a8219245e (GF#16989 - clarify extension publishing). That commit changed source/defining-extensions.html to say that publishing on a public-facing web site is preferable when resources travel, and that using the FHIR registry or another publicly accessible extension registry both publishes the extension and makes it easy to find.

Additional context:
The current defining-extensions page is in the active build navigation through source/hierarchy.xml. The current text preserves the clarified distinction: registration is encouraged but not required; the definition SHALL be published; an intranet can work for local-only use; a public-facing web site can publish a broader extension; and registries add discoverability and reuse. A bounded Jira search found FHIR-13133 as background for the requirement that extension definitions be available, but no later source-edit decision reversing FHIR-16989. A 2023 Zulip implementers thread about where to publish extensions likewise distinguishes hosting IG/extension pages at a canonical URL from package or registry registration.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active source already conveys the FHIR-16989 clarification, and another prose edit would be redundant rather than a necessary current-spec correction.

Recommendation:
Keep this no-change audit commit as-is. No FHIR-core follow-up is needed for FHIR-16989 unless the work group wants a broader future rewrite of extension registry and package publication guidance.
