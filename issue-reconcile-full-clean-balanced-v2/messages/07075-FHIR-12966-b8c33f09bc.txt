FHIR-12966: Audit ServiceRequest instructions and quantity

Issue request:
FHIR-12966 was a Published, Persuasive with Modification Orders and Observations change request raised against DSTU2 ProcedureRequest and possibly DiagnosticRequest. It asked for a dosageInstruction or quantity location for orders such as blood products. The final decision deferred the specific blood-products model to a separate project and, for request instructions, directed ServiceRequest to add inline supporting/order-detail and patient-instruction/provider-instruction capability covering both FHIR-12966 and FHIR-14002.

Initial application:
The change was pre-applied in SVN-era git history. Commit 5971b343bd, "Preapply [#12966], [#14002]", added ServiceRequest.orderDetail as a coded order-detail element, added ServiceRequest.patientInstruction, updated ServiceRequest.supportingInfo guidance, and tagged orderDetail committee notes with [#14002][#12966]. ProcedureRequest and DiagnosticRequest are no longer active current-build resources; ProcedureRequest is marked as merged into ServiceRequest and DiagnosticOrder/DiagnosticRequest functionality is subsumed by ServiceRequest/DiagnosticReport-era artifacts.

Additional context:
Later approved work explains why the current source is not a literal copy of the 2017 resolution text. ServiceRequest is active in source/fhir.ini, and current ServiceRequest now has orderDetail as a structured BackboneElement with parameter values including Quantity, Ratio, Range, CodeableConcept, string, boolean, and Period; ServiceRequest.quantity[x] separately carries a requested service amount; supportingInfo is CodeableReference(Resource) for existing supporting information; and patientInstruction is a repeatable backbone with markdown or DocumentReference instruction content. FHIR-31589 clarified the supportingInfo/orderDetail boundary, FHIR-32265 reshaped orderDetail into the current structured parameter/value model, and FHIR-37355 changed supportingInfo to CodeableReference. FHIR-14002 is the same change family and is already represented on the combined branch by commit a91aeb7677, so this commit does not duplicate it.

AutoFHIR reconciliation:
This audit commit makes no source change. The current build-scoped ServiceRequest source already gives implementers places for the requested instructions and quantities without adding a medication-style dosageInstruction to ProcedureRequest, and the source comments correctly distinguish existing supporting information from delivery/order details.

Recommendation:
Keep this audit commit as-is. No follow-up core source change is needed for FHIR-12966; any future blood-products-specific modeling belongs to the separate blood product/administration issue family rather than this old ProcedureRequest tracker.
