FHIR-13290: Audit Immunization organization performer support

Issue request:
FHIR-13290 was a Published/Persuasive with Modification FHIR-core Immunization change request asking to represent the organization responsible for administering an immunization when an individual practitioner is unknown. The approved motion was to expand practitioner.actor to include Organization, rename practitioner to performer, and add onBehalfOf, with the later Jira application comment noting that R4 included the Organization/performer rename but intentionally did not add onBehalfOf because the Event pattern changed.

Initial application:
No commit message explicitly naming FHIR-13290 was found. The application is visible in git history in f451f3fc4b093f23541fadb82141a50def0e1cc5, which added #13290 committee notes to Immunization.performer, Immunization.performer.function, and Immunization.performer.actor and set actor to Reference(Practitioner | Organization). The 2021 source rework preserved those #13290 committee notes in the current StructureDefinition source.

Additional context:
The Immunization resource is active in source/fhir.ini. Current source has Immunization.performer rather than Immunization.practitioner, maps the historical practitioner name to performer in fhir.ini, and defines Immunization.performer.actor as a Reference that includes Organization. The current source also includes Patient and RelatedPerson because the later Published issue FHIR-32773 broadened the same actor element for self- or parent-administered immunizations. No current Immunization onBehalfOf element exists, consistent with the Jira application comment that the Event pattern no longer used it.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative Immunization StructureDefinition and performer search parameter already implement the organization-performer behavior requested by FHIR-13290, and adding onBehalfOf now would contradict the recorded R4 application rationale.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-13290 in the core source unless the work group opens a new issue to revisit the broader performer/onBehalfOf pattern or to make editorial improvements to existing comments.
