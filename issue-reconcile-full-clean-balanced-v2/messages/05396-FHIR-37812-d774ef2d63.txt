FHIR-37812: Audit DeviceAssociation clinical-patient search

Issue request:
FHIR-37812 was Applied with a Persuasive with Modification resolution for R6. It asked why Device/DeviceAssociation did not use the common http://hl7.org/fhir/SearchParameter/clinical-patient search parameter and resolved that DeviceAssociation.subject should participate in clinical-patient with expression DeviceAssociation.subject.where(resolve() is Patient), with the unused generated DeviceAssociation-patient search parameter removed.

Initial application:
Commit f8251515a3 added DeviceAssociation to source/searchparameter/common-search-parameters.xml under clinical-patient. That initial Jira-tagged application did not itself touch the DeviceAssociation search-parameter bundle, but the current source also has a DeviceAssociation patient row that supplies the resource-specific expression used by the build.

Additional context:
DeviceAssociation is active in source/fhir.ini, and its search-parameter bundle is an active resource source. A later Applied issue, FHIR-46973, noticed that the patient parameter had disappeared or was incorrect and resolved to add the DeviceAssociation patient search row while keeping it linked to the common clinical-patient parameter. The current CI build and search-parameters.json show the generated canonical URL as http://hl7.org/fhir/SearchParameter/clinical-patient, include DeviceAssociation in the common base list, include DeviceAssociation.subject.where(resolve() is Patient) in the clinical-patient expression, and do not expose a separate DeviceAssociation-patient canonical search parameter.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Removing the local DeviceAssociation-patient source entry would not improve the generated specification; it would remove the source row that currently feeds the DeviceAssociation expression/target into the common generated clinical-patient search parameter.

Recommendation:
Keep this audit commit as-is. The seed request is satisfied in the generated current specification; any future cleanup of the resource-local source id/url convention should be handled as a publisher/source-model refactor rather than as a FHIR-37812 correction.
