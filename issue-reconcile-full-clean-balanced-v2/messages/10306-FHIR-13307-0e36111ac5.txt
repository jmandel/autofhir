FHIR-13307: Audit search modifier OR wording

Issue request:
FHIR-13307 was a Published/Persuasive FHIR-I change request for STU3 asking the Search page to clarify whether comma-separated OR values are allowed when a search parameter uses a modifier, with :missing called out as an exception and :in as an example that should allow multiple values.

Initial application:
The issue was applied in git-svn commit 8200d5f1f3ca93e5ebb38d464a3691320d312572, which corresponds to Jira's svn revision 12862 comment and added text to source/search.html saying every search parameter may use comma-separated values, including modifiers such as ?code:text=this,that. No prior Issue-Reconcile-Key commit exists on the combined branch.

Additional context:
The Search page has since been reorganized by FHIR-33158 and clarified by FHIR-40629. The current active source/search.html has a dedicated "Searching Multiple Values (joining with AND or OR)" section that defines comma-separated OR values, examples prefixes in OR values, and explicitly says a modifier applies to each OR value. The Modifiers section repeats that modifiers are allowed with multiple terms and links back to the multiple-values section. Zulip discussion shows the original :in modifier question led to GF#13307, and later :not discussion led to FHIR-40629 rather than reversing the FHIR-13307 rule.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change because the current source already conveys the requested rule in the active Search page and later clarifications make the modifier semantics more explicit than the original STU3 text.

Recommendation:
Keep this no-change audit as-is. Future work on special-case behavior for :not with comma-separated values should proceed through the later FHIR-40629 follow-up path, not by reopening FHIR-13307's general rule that modifiers can be used with OR values.
