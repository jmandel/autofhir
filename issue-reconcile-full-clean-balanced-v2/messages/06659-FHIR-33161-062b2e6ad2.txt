FHIR-33161: Audit primitive type definition downloads

Issue request:
FHIR-33161 was Published/Persuasive for an R4B downloads issue. It reported that profiles-types.json primitive StructureDefinitions pointed at http://hl7.org/fhir/StructureDefinition/PrimitiveType even though PrimitiveType was not accessible in R4B, and that structuredefinition-fhir-type extension instances in profiles JSON used valueUri instead of the long-standing valueUrl. The accepted resolution said the valueUrl/valueUri point was handled by other trackers and that R4B references to the R5-only PrimitiveType construct would be reverted.

Initial application:
No commit explicitly tagged FHIR-33161 was found. The applied state is visible in the current checked-in R4B history artifacts and the published R4B download surface: tools/history/release4b/profiles-types.xml and https://hl7.org/fhir/R4B/profiles-types.json use Element as the baseDefinition for primitive types such as base64Binary and boolean, while the structuredefinition-fhir-type extension instances use valueUrl. FHIR-32105 and FHIR-31733 are the final Jira decisions that cover the valueUrl/valueUri portion named by this issue.

Additional context:
PrimitiveType is now a real current-build abstract type, not an inaccessible dangling URL. It is active in source/fhir.ini, has current narrative in source/types.html, and is defined from source/datatypes/primitivetype.xml as a DataType-specializing abstract type. The R5 published profiles-types.json correspondingly uses PrimitiveType as the primitive baseDefinition and includes a PrimitiveType StructureDefinition based on DataType. That later/current R5+ shape is consistent with the source model and should not be reverted as part of this R4B correction.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The R4B correction requested by FHIR-33161 is already reflected in the current R4B history/published artifacts, and changing the current R5/R6 source away from PrimitiveType would regress the active abstract type model.

Recommendation:
Keep this no-change audit as-is. Any further investigation of the valueUrl/valueUri portion should stay with FHIR-32105/FHIR-31733 or release-history tooling, not with a new current-spec edit for FHIR-33161.
