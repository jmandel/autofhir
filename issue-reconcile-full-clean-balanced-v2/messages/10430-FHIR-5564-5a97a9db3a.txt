FHIR-5564: Audit optional Accept header summary

Issue request:
FHIR-5564 was a Published/Persuasive FHIR-I change request for the FHIR-core HTTP page. It asked that the REST summary table stop saying the Accept header was not applicable for PUT, POST, and DELETE interactions, because those interactions can return OperationOutcome responses that need normal HTTP content negotiation.

Initial application:
The issue appears to have been applied before final Jira resolution. Jira comments from March 2015 say "already applied", and git commit 8ae7ef29bea3aded54acb531d872a1532a89a5ca, dated 2015-02-17, refreshed source/http.html by removing the per-interaction Accept column whose update, create, and delete rows had said N/A, and adding a summary note that all requests may include an optional Accept header, even DELETE.

Additional context:
The current build-scope source page is source/http.html, the core RESTful API narrative page. Later table refactors preserved the issue's semantics: the request summary no longer has an Accept column with N/A for PUT/POST/DELETE, the notes define N/A/R/O only for the remaining columns, and the response table still documents optional response bodies including OperationOutcome for delete interactions. Targeted Zulip and Confluence searches found no relevant community record that changes the Jira/source conclusion.

AutoFHIR reconciliation:
No source change was made. The current source already conveys that Accept is an optional request header for every interaction and therefore covers PUT, POST, and DELETE without reintroducing a redundant table column.

Recommendation:
Keep this empty audit commit as-is. No follow-up source work is needed for FHIR-5564 unless the work group later decides to reformat the HTTP summary tables for unrelated reasons.
