FHIR-40397: Audit product code search alignment

Issue request:
FHIR-40397 was an Applied/Persuasive OO change request for R6 to align product code search parameters: rename BiologicallyDerivedProduct product-code to code, make Device's product-code search available as code, have Device code/type search account for Device.type and DeviceDefinition.classification.type, and remove the duplicate CodeableReference concept on Device.definition.

Initial application:
The issue was partially pre-applied in commit 31564391acbf120de82ad6b2720eb87e3270659a, which changed BiologicallyDerivedProduct product-code to code and changed the Device token search parameter code from definition to code. Later FHIR-40397a commits c76ef436f261283b0cc61135e79524a58f6fe506, 115748e7f52b3a98f20d0a3460219cb81e4415e7, and 98dfcfe61357133aa44d5e46a3296d4680c96f16 changed Device.definition back away from CodeableReference, added Device.type/DeviceDefinition.classification.type search behavior, and added Device narrative/element guidance. The Jira comment's 934d958cebb69995500fac61b7f24e33d896b217 link is a feature-branch merge and was not the substantive Device/BDP delta in this checkout.

Additional context:
Device, DeviceDefinition, and BiologicallyDerivedProduct are active current-build resources in source/fhir.ini. Later FHIR-51500 intentionally removed the Device.definition.resolve().classification.type clause from the Device-type search parameter for performance and has already been represented on the combined branch by 8b5ae712cb72f13692aab81eebd6d3718407e21e. Later DeviceDefinition canonical-resource work in FHIR-39389/FHIR-42900 changed Device.definition from Reference(DeviceDefinition) to canonical(DeviceDefinition), so the current Device code expression uses Device.definition.resolve().classification.type rather than the older reference path. FHIR-40305 was also resolved no-change because Device.definition is no longer a Codeable element.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source has BiologicallyDerivedProduct-code with code code and expression BiologicallyDerivedProduct.productCode; Device-code renders in the current build with expression Device.type | Device.definition.resolve().classification.type; Device-type is now correctly limited to Device.type by the later FHIR-51500 decision; and Device/DeviceDefinition retain matching device-type bindings and narrative guidance.

Recommendation:
Keep this audit commit as-is. Do not re-add the Device.definition-derived clause to Device-type unless the work group reverses FHIR-51500. If future tooling wants the source id/url metadata for the Device code search parameter normalized, handle that as build-source cleanup only, because the current rendered search parameter is already Device-code.
