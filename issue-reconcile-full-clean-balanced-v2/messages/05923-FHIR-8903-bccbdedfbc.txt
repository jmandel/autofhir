FHIR-8903: Audit ICD-9 diagnosis URI typo

Issue request:
FHIR-8903 is a Published/Persuasive vocab change request for DSTU1/DSTU2 asking to correct a typo in the ICD-9-CM diagnosis system URI from http://hl7.org/fhir/sid/icd-9-cm/diagosis to the intended diagnosis spelling.

Initial application:
The issue was applied by historical svn/git commit 9eff2268e43126ba48c4aaced9d6fb3087969e2c (#8903 - correct icd9 url), matching Jira's comment that the fix was svn revision 7183. That commit changed source/terminologies-systems.html from diagosis to diagnosis and populated the ICD-9-CM diagnosis/procedure code system OIDs in the same old table row.

Additional context:
FHIR-8904 is the immediately related Published issue for the same typo and is already represented on the combined branch; its Jira comment says the typo was already fixed and rejects a suggested value set OID as not being a code system OID. Later ICD terminology maintenance changed the current source shape: commit 3e1ab0a91d removed the old diagnosis/procedure-specific ICD-9-CM row in favor of an ICD guidance page, and FHIR-41305/commit 11181dd489 corrected the current ICD URI column to show the ICD-9-CM and ICD-10 root URIs. The active current Code Systems page is in the terminology module/hierarchy and no longer contains either the misspelled URI or the old diagnosis-specific URI.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source searches find no occurrence of diagosis, source/terminologies-systems.html now lists http://hl7.org/fhir/sid/icd-9-cm for ICD-9-CM, and restoring the removed diagnosis-specific row would conflict with later applied terminology decisions rather than completing FHIR-8903.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed for FHIR-8903 unless the terminology work group separately decides to reintroduce diagnosis/procedure-specific ICD-9-CM identifiers or move more ICD identifier detail from THO back into the core terminology page.
