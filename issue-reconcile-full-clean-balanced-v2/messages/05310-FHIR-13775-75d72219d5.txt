FHIR-13775: Audit DataAbsentReason not-applicable code

Issue request:
FHIR-13775 was Published/Persuasive with Modification for STU3 by Vocabulary. It requested adding "not applicable" for cases where a value is not expected, and the final resolution was to add `not-applicable` to the Data Absent Reason code system and value set while deferring broader product-family unification to UTG.

Initial application:
The issue was applied in the old core terminology spreadsheet lineage. Jira records svn revision 13066; git commit df58b619135a2e170435e0af16e61b82b2280152 added a Not Applicable Data Absent Reason row under the temporary code `n/a`, and git commit 2ebdf2bb94ec0b0fc462c670e05fb06b043551a6 completed the GF#15567 update by changing that code to `not-applicable` and updating the Data Absent Reason hierarchy and value set.

Additional context:
Core no longer carries the Data Absent Reason CodeSystem as an inline spreadsheet code list. Commit d382fc3af52ab7607c6c8fead1f47cdf09be3562 changed the active terminology binding from `#data-absent-reason` to `valueset-data-absent-reason` and introduced `source/terminologies/valueset-data-absent-reason.xml`, whose compose includes all codes from `http://terminology.hl7.org/CodeSystem/data-absent-reason`. The current THO CodeSystem version used by the build contains `not-applicable`, and the current CI ValueSet expansion displays it. FHIR-46130 is a later Resolved - change required clarification about the example text in the same code's definition; it does not reopen whether the `not-applicable` code belongs in the value set and is outside this default Applied/Published reconciliation scope.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current core source is already correct for FHIR-13775 because the active DataAbsentReason binding points to the current ValueSet, the ValueSet includes the THO Data Absent Reason CodeSystem, and that CodeSystem includes `not-applicable`.

Recommendation:
Keep this audit commit as-is. Do not re-add a local core CodeSystem row; the remaining ownership/wording cleanup discussed in FHIR-46130 should proceed through the appropriate later FHIR/UTG workflow rather than as part of this STU3 Published issue.
