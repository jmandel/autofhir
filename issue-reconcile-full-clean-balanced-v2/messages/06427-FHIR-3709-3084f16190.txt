FHIR-3709: Audit Procedure subject naming

Issue request:
FHIR-3709 was Published/Persuasive for DSTU1 Procedure. It asked to rename Procedure.subject to Procedure.patient under the then-current naming guideline because Procedure.subject was only allowed to reference Patient.

Initial application:
The request was initially applied by git commit 34a07126efd7f1aba8087adf8facefcd680e5dcb, which changed the Procedure spreadsheet and examples from Procedure.subject to Procedure.patient and tagged the row with [#3709]. A later DSTU1 Procedure alignment issue, FHIR-7633, explicitly recorded that Procedure.patient was renamed back to Procedure.subject and Group was added for consistency; commit 27f73740e4afc943ade51df795872e6e5c3865ee includes that Procedure/ProcedureRequest alignment work.

Additional context:
Current Procedure is in build scope through the active source/fhir.ini resources entry. The current Procedure StructureDefinition has Procedure.subject, keeps patient as an alias, and allows Patient, Group, Device, Practitioner, Organization, and Location. The current Procedure introduction also says procedures can be performed on non-patient subjects. FHIR-26859 was Published/Persuasive with Modification for R5 and intentionally broadened Procedure.subject beyond Patient/Group for inspections, licensing, devices, organizations, locations, and practitioners; git commit b91c941c0d72e2291ac6ec3729c92af941f7216b applied that scope expansion. The patient search parameter remains as a patient-only search over Procedure.subject, so patient-specific search behavior is preserved without renaming the element.

AutoFHIR reconciliation:
No source change was made. Renaming the current element to Procedure.patient would now contradict later published Patient Care decisions and the current non-patient Procedure scope. The existing source already preserves the useful part of FHIR-3709 by keeping patient as an alias and a patient search parameter while using subject for a multi-target element.

Recommendation:
Keep this empty audit commit as-is. Do not reapply the DSTU1 rename unless a future work group decision narrows Procedure.subject back to Patient-only; current source is correct for the later Procedure scope decisions.
