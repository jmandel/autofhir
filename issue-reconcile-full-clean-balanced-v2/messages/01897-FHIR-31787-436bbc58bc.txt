FHIR-31787: Audit packaged product property naming

Issue request:
FHIR-31787 was a Published BR&R change request for R5 asking what distinguished PackagedProductDefinition.characteristic from package.property. Its Persuasive with Modification resolution said to standardise on "property" as the attribute and use the same for both.

Initial application:
No git commit explicitly tagged FHIR-31787 was found. The surrounding history shows the package-level physical characteristic backbone had already been renamed from package.characteristic to package.property by FHIR-26673, while FHIR-26824 added PackagedProductDefinition.characteristic for overall pack-type features.

Additional context:
Later Published issue FHIR-39043 explicitly kept the PackagedProductDefinition.characteristic element name and changed it from a single CodeableConcept to a contentReference to PackagedProductDefinition.packaging.property, making the characteristic use the same type/value property backbone. PackagedProductDefinition is active in source/fhir.ini, so this source is in current build scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already uses PackagedProductDefinition.packaging.property for packaging-item properties and has PackagedProductDefinition.characteristic reuse that same property backbone through a contentReference. Renaming the top-level element to property now would contradict the later final FHIR-39043 decision and would be a breaking model change requiring a fresh work-group decision.

Recommendation:
Keep this audit commit as-is. If BR&R still wants to rename or remove PackagedProductDefinition.characteristic, raise a new tracker that explicitly supersedes FHIR-39043; do not make that change as a reconciliation of FHIR-31787 alone.
