FHIR-37822: Audit search Prefer header placement

Issue request:
FHIR-37822 was Published with a Persuasive with Modification resolution for R5. It asked to move the official definition of the search Prefer handling=strict and handling=lenient headers to the HTTP page while keeping the search-page explanation of how the headers are used and linking from search to the official definition.

Initial application:
The issue appears to have been applied by git commit 7415a1eb0824ba59d977db335205d71eed004312, which added the HTTP Headers section to source/http.html and changed source/search.html so the search error-handling text links to the HTTP Headers section. That same historical commit also applied separate POST-search work for FHIR-35859.

Additional context:
source/hierarchy.xml lists source/http.html as the RESTful API page and source/search.html as its Search child page, so both narrative sources are in the current build scope. FHIR-I minutes for 2022-08-01 record the FHIR-37822 Persuasive with Modification motion at 14-0-0. A Zulip implementation thread on 2022-09-01 confirms the issue was about search-related HTTP header definitions and that other header cleanups should be separate or pre-applied.

AutoFHIR reconciliation:
This commit makes no source change. The current source already has source/http.html#Http-Headers with a Prefer row pointing to RFC 7240 processing preference and to search.html#errors, and source/search.html still describes handling=strict and handling=lenient while linking to http.html#Http-Headers.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for FHIR-37822; broader HTTP header table cleanup should remain separate from this tracker if future review finds a problem.
