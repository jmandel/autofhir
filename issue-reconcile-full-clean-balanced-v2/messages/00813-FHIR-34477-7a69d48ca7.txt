FHIR-34477: Audit CarePlan SupplyRequest support

Issue request:
FHIR-34477 was a Published/Persuasive R4 change request applied for R5. It asked Patient Care to add SupplyRequest as a supported CarePlan.activity.plannedActivityReference target because a comparable CDA activity could refer to supply-related content. The final Jira resolution was to add Reference(SupplyRequest).

Initial application:
The issue was applied by 7a6201070b574b69afe13a68407f9dcdee16be95, the commit linked from Jira. That commit added J#34477 to the CarePlan.activity.plannedActivityReference committee notes and added http://hl7.org/fhir/StructureDefinition/SupplyRequest as a targetProfile in source/careplan/structuredefinition-CarePlan.xml.

Additional context:
The current build scope changed after R5. SupplyRequest now remains as source residue but is not an active resource in source/fhir.ini, while CarePlan is active. Commit 3b38b80cf23f9cbb306fab8fcedb293315478c32 removed the active SupplyRequest/SupplyDelivery and other OO resource entries from fhir.ini, removed the SupplyRequest targetProfile from CarePlan.activity.plannedActivityReference, and updated current narrative pages to point SupplyRequest readers to the HL7 OO incubator. The original Zulip filing thread also noted after Jira creation that SupplyRequest is not patient-specific, but the formal Jira disposition still explains the R5 application.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding SupplyRequest to the active core CarePlan target list would reference a resource that is no longer active in the current core build and would partially reverse the later OO-incubator migration.

Recommendation:
Keep this audit commit as-is for core FHIR. If Patient Care and Orders & Observations want CarePlan to reference the OO-incubator SupplyRequest definition across package boundaries, that should be handled as a new cross-package design/change request rather than as a replay of this R5-era core issue.
