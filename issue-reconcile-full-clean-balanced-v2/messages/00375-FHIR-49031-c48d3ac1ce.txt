FHIR-49031: Audit Permission limit outside core

Issue request:
FHIR-49031 was an Applied/Persuasive Security WG change request for the R6 Permission resource. It asked to change Permission.rule.limit from a repeating CodeableConcept into a BackboneElement, move the coded limit to Permission.rule.limit.control with a preferred binding to http://terminology.hl7.org/ValueSet/v3-SecurityControlObservationValue, and add repeating tag and element children.

Initial application:
The request was applied in core by commit 3962d10cc10fbc4335159bc57a9f96a24e633d7b and merged through HL7/fhir#3296. That commit changed source/permission/structuredefinition-Permission.xml so Permission.rule.limit became a BackboneElement with control, tag, and element children using the requested bindings and types.

Additional context:
After the application, commit 0e2a8a7f839d5e1a43787523daccf07d958362f3 removed the Permission resource from the core build, including the active source/fhir.ini entries and the source/permission directory. The current Security module links Permission to the Data Access Policies IG instead of a core resource page, and the current Data Access Policies CI package contains Permission.rule.limit as a BackboneElement with the requested control, tag, and element children.

AutoFHIR reconciliation:
This audit commit intentionally makes no core source change because the current core checkout no longer owns or builds the Permission resource. Reintroducing or editing source/permission would be out of current build scope and would conflict with the later resource removal.

Recommendation:
Keep this external-repo audit as-is for the core reconciliation. No core follow-up is indicated for FHIR-49031; any future Permission changes should be made in the Data Access Policies IG if that external source-of-truth changes.
