FHIR-16078: Audit HTTP verb RFC references

Issue request:
FHIR-16078 was a Published/Persuasive STU3 non-substantive FHIR-core clarification for the HTTP verb CodeSystem page. It asked to add preferred HTTP specification links because the then-current concept definitions only said "HTTP GET", "HTTP HEAD", and so on; the final resolution said to add the current RFC URL anchors for each term as part of the definitions.

Initial application:
The issue was applied in svn revision 14169, represented in git as f4da5602278eaa3576addcf3402cd8cf00b96a98 with subject "GF#16078 - fix definitions for http verbs". That commit added a markdown HTTP RFC link to the HTTPVerb description and changed the per-code definitions from bare labels such as "HTTP GET" to sentence-style definitions such as "HTTP GET Command". Jira's application comment explains why the RFC links were not embedded in each concept definition: the definition field is not markdown. Commit 86a07e2f5a18780ff44c6ef3daf33f0e6a85f066 later updated the description link from RFC 2616 to RFC 7231, and subsequent source refactors carried the terminology into the current standalone CodeSystem and ValueSet XML files.

Additional context:
Bundle is active in source/fhir.ini, and Bundle.entry.request.method is required-bound to ValueSet/http-verb. Current source/bundle/codesystem-http-verb.xml and source/bundle/valueset-http-verb.xml both include the HTTP RFC 7231 link in their descriptions; the Bundle binding description carries the same link. The tightly related FHIR-17092 issue about better HTTP verb definitions is already represented on the combined branch by commit 63bca72aa76ed1d2eb41bf001508df765ef3410d, so this reconciliation does not duplicate that related decision. Focused Zulip and Confluence searches found no directly relevant FHIR-16078 discussion or conflict; Confluence minutes only surfaced the related FHIR-17092 block-vote context.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because the current build-scope source already provides the requested HTTP specification reference in the terminology descriptions and binding description, while per-definition markdown links remain unsupported by the CodeSystem concept definition field. Adding redundant prose or trying to encode links in the non-markdown definitions would not improve the current specification and could create maintenance drift.

Recommendation:
Keep this audit commit as-is. If the work group wants per-code external links in the future, that should be handled as a new terminology design decision rather than inferred from FHIR-16078's already-applied STU3 clarification.
