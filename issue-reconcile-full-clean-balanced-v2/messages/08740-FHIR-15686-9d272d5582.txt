FHIR-15686: Audit Request intent immutability guidance

Issue request:
FHIR-15686 was Published/Persuasive for FHIR-I and asked the Request pattern to make clear that intent is immutable: a proposal should not turn into an order on the same instance, and a separate Request with a different intent should be created using Request.basedOn. The issue summary also preserves the later-important nuance that intent may change granularity.

Initial application:
No prior source commit was found that names FHIR-15686 directly. The apparent historical application is commit 14b69a1c6d, which updated the active Request pattern spreadsheet by adding "(immutable)" to Request.intent and adding the comment that a proposal should not become a plan or order on the same instance; instead a new basedOn instance should carry the new intent. That same source text also records the granularity exception for order/filler-order refinements.

Additional context:
source/fhir.ini lists request under [logical], so source/request/request-spreadsheet.xml remains in current build scope. Later Request-pattern issue FHIR-20607 clarified related narrative by avoiding the word immutable for other request fields and by saying replacements should have the same intent while an order can be basedOn a proposal. Per-resource follow-up issues such as FHIR-20606 and FHIR-20605 govern resource-local wording, and existing combined-branch reconciliation commits have already handled those related local cases where needed.

AutoFHIR reconciliation:
No source change was made. The current active Request.intent source already contains the immutable-intent rule, the new-instance-via-basedOn instruction, and the allowed granularity-change exception. Adding parallel wording under this seed would duplicate later per-resource tracker work rather than correct a current specification defect.

Recommendation:
Keep this audit commit as-is. Future changes to individual resource intent comments should be reconciled under their resource-specific Jira issues, while FHIR-15686 should remain closed as already applied to the Request pattern.
