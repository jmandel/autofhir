FHIR-19517: Audit Pharmacy workflow changes

Issue request:
FHIR-19517 was a Published/Persuasive with Modification Pharmacy change request for STU3. The approved request renamed MedicationRequest.context to MedicationRequest.encounter as a 0..1 Reference(Encounter), kept support for identifying reported MedicationRequest records, and updated informationSource so the source of a report could include PractitionerRole.

Initial application:
Jira records the original application as commit 7a787c5ab6b278c2af6d3644c38931486b7330f4, with implementation commit 417949e3bc69f9124d0e589d52b1b9acc47ca460. That implementation changed the active MedicationRequest spreadsheet from context to encounter, changed the search parameter from context to encounter, and changed reported to a reported[x] choice while removing informationSource.

Additional context:
The reported/informationSource portion was immediately refined by later published Pharmacy decisions. FHIR-19640 restored MedicationRequest.informationSource and made reported a standalone boolean again. FHIR-35847 later changed MedicationRequest.informationSource to 0..* to support multiple information sources. FHIR-41408 added Group to MedicationRequest informationSource and related pharmacy source references. FHIR-47855 clarified the informationSource definition, and current source also reflects the later FHIR-49863 rename from reported to isRecordOfRequest; FHIR-49863 remains Resolved - change required and is cited only as current-source context, not decided here. Current source/fhir.ini lists MedicationRequest as an active Pharmacy resource and maps the old MedicationRequest.reported[x] name to MedicationRequest.isRecordOfRequest.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active MedicationRequest StructureDefinition already has encounter as 0..1 Reference(Encounter) with the approved encounter semantics and an encounter search parameter. The current informationSource and isRecordOfRequest shape is correct after later applied/published decisions, so reverting it to the literal 2018 wording or to the first FHIR-19517 implementation would undo subsequent WG decisions.

Recommendation:
Keep this no-change audit commit. Do not reopen FHIR-19517 unless a separate review decides to revisit the later isRecordOfRequest/modifier work; that separate question belongs to the later MedicationRequest issues, not to this published STU3 reconciliation.
