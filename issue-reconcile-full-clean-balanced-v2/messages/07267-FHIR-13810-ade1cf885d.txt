FHIR-13810: Audit ValueSet expansion version guidance

Issue request:
FHIR-13810 was Published/Persuasive with Modification for STU3 by Vocabulary. It asked that ValueSet expansions identify both system and version for expanded codes, but the accepted resolution narrowed that to conditional expansion-parameter guidance because versions are not always required or meaningful in every server context.

Initial application:
The issue was applied in SVN revision 13082 / git commit 458301bbf4dc45e5f1602d4f159dae0051829145 by adding ValueSet expansion parameter prose to source/valueset/valueset-notes.xml. That text said expansion parameters record what controlled the expansion process, that servers decide which parameters to include, and that when a code system on the server has a specified version the version is provided as an expansion parameter.

Additional context:
ValueSet is an active current-build resource and its $expand operation is listed from source/valueset/list-ValueSet-operations.xml. Related FHIR-3535 introduced ValueSet.expansion.contains.version as an optional per-code element; FHIR-14688 later clarified that per-code version is still not a blanket SHALL; FHIR-13820 handled the separate $expand valueSetVersion action item and is already audited on the combined branch. Later applied FHIR-41589 deliberately replaced the older GF#13810 sentence with SHOULD-level categories for ValueSet.expansion.parameter and FHIR-41639 added used-system/used-supplement/used-valueset response parameters.

AutoFHIR reconciliation:
No source change was made. The latest combined source already says ValueSet.expansion.parameter SHOULD include canonical or URI references, including version, for all CodeSystems, CodeSystem Supplements, and ValueSets used in the expansion; persisted expansions SHALL include the full parameter set; response-only used-system records system|version when available; and ValueSet.expansion.contains.version remains optional with SHOULD-level semantics when code meaning is not guaranteed to be stable. Reintroducing the older blanket SHALL wording would conflict with the issue's own modification and with later applied FHIR-41589 guidance.

Recommendation:
Keep this empty audit commit. The current source satisfies FHIR-13810 when interpreted with later Vocabulary decisions, and no additional core source edit is needed.
