FHIR-20394: Audit Questionnaire unit constraint

Issue request:
FHIR-20394 is Published/Persuasive for FHIR-core Questionnaire and was applied for R5. It asked that the questionnaire-unitOption and questionnaire-unitValueSet extension descriptions directly answer whether off-list units can be entered by saying that, if either extension is present, the units for a Quantity element are constrained to only the units listed by the extensions: a required binding, not an extensible binding.

Initial application:
The issue was explicitly applied in core by f7b451ebc6, merged as 596ab9615a. That source change updated the unitOption and unitValueSet rows in source/questionnaire/questionnaire-extensions-spreadsheet.xml from the older "any unit is valid" wording to the required/not-extensible constraint requested by the Jira resolution.

Additional context:
The current core build still actively includes Questionnaire, but it no longer owns the two unit extension StructureDefinitions. Current core source searches find only OID registry entries and the Questionnaire item-type definition that points readers to the extension URLs. Core commit dd468d4f17 later removed extension definitions from the R5 source, and the current FHIR Extension Pack IG includes input/definitions/* as source resources. The active Extension Pack definitions for questionnaire-unitOption and questionnaire-unitValueSet contain the exact required/not-extensible wording, plus later FHIR-37363 answer-validation guidance. Existing combined-branch audit commits already represent the neighboring FHIR-28132, FHIR-34391, and FHIR-37363 unit-guidance decisions; FHIR-30581 is related SDC IG background for an explicit off-list-unit extension and does not reverse this default rule.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative current extension definitions are outside this core checkout and already satisfy FHIR-20394, while adding the same rule to the remaining core Questionnaire item-type wording would be redundant and could create maintenance drift.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed for FHIR-20394; future changes to questionnaire-unitOption or questionnaire-unitValueSet descriptions should be made in the FHIR Extension Pack or in the SDC IG when changing off-list-unit behavior.
