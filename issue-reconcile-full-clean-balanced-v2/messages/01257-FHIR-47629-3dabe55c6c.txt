FHIR-47629: Audit cardinality compatibility wording

Issue request:
FHIR-47629 was Applied with a Not Persuasive with Modification resolution for the FHIR-core versioning/compatibility page. The issue asked to reconcile the statement that normative upper cardinality may change from 1 to * with the fact that older JSON parsers can fail when a singleton property becomes an array. The approved resolution added a caution to the cardinality rule and a dragon warning to the JSON repeating-elements section.

Initial application:
The issue was applied before this reconciliation by git commit 0a5592638b4ebfaa8352e8ec5f9b2ae0044e7a71, "Changes from FHIR-47629.", which edited source/versions.html and source/json.html. That commit added the cardinality anchor and JSON compatibility warning in the current build source, and the combined branch already contains that source application, though it did not yet have an Issue-Reconcile-Key audit commit for FHIR-47629.

Additional context:
FHIR-I WGM minutes for 2024-09 record the 16-0-8 vote and the decision to warn that changing upper cardinality from 1 to * may break JSON, encourage new sibling elements, and raise a new ticket for FHIRPath. The later applied FHIR-48379 decision did that follow-up by changing the same cardinality paragraph from "JSON issue" to "JSON and FHIRPath issues" and adding FHIRPath-specific warning language. FHIR-48379 already has its own reconciliation commit on the combined branch, so this audit treats the extra FHIRPath wording as approved later context rather than a deviation from FHIR-47629.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source/versions.html cardinality row says upper cardinality may change from 1 to * only when extra repetitions can be safely ignored, warns that this may change JSON paths and break FHIRPath expressions, and says normative cardinality changes will be minimized, for example by defining new sibling elements. The current source/json.html repeating-elements section contains a dragon warning that elements may change repeatability between versions, even once normative, and that processors should be prepared to manage such changes.

Recommendation:
Keep this empty audit commit as-is. The current source reflects the applied FHIR-47629 resolution as subsequently refined by FHIR-48379, and adding or reverting wording would either duplicate the existing warning or undo later approved work.
