FHIR-7590: Remove stale Device GMDN binding metadata

Issue request:
FHIR-7590 was a Published/Persuasive with Modification OO change request from the 2015May core ballot. It asked to require GMDN for Device.type/DeviceKind; the accepted resolution rejected a required binding but changed the DeviceKind binding to GMDN with preferred strength and added notes describing GMDN as the example device-type code source.

Initial application:
The request appears to have been preapplied in git commit 0aa0bd9898801029935c8ac861ffb12380ba7d2e, titled "preapplied  #7590  GMDN as preferred binding for DeviceKind". That commit changed the historical DeviceKind binding from an RTM example to a preferred GMDN binding and updated the Device notes to describe GMDN as the example source.

Additional context:
Later final Device decisions changed the current interpretation. FHIR-9635 was Published/Persuasive for DSTU2 and explicitly changed Device.type from the GMDN preferred binding to a SNOMED CT example binding while keeping GMDN as a note. FHIR-12897 later corrected the GMDN note link and is already represented on the combined branch. FHIR-53019 was Applied/Persuasive with Modification for R6 and removed GMDN concepts from the Device Type value set after the expansion failed; FHIR-51642 then recorded a no-change decision because GMDN had been removed. Current source/fhir.ini keeps Device in the active core build, so source/device/structuredefinition-Device.xml is in scope.

AutoFHIR reconciliation:
This commit removes the obsolete GMDN copyright extension from the current Device.type binding. The current binding is an example DeviceType binding to ValueSet/device-type, whose source no longer includes GMDN, so retaining GMDN binding copyright metadata was a stale remnant of the old FHIR-7590 application. The commit intentionally leaves the Device notes GMDN link in place because FHIR-9635 preserved GMDN as an alternate device-type coding source.

Recommendation:
Keep this source change. Do not restore the old preferred GMDN Device.type binding in current core; later Published/Applied decisions superseded that part of FHIR-7590. If GMDN content is ever reintroduced into the Device Type value set, it should be handled through a new terminology/work-group decision and include the appropriate terminology metadata then.
