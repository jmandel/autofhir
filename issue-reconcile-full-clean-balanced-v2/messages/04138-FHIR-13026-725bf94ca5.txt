FHIR-13026: Audit controlled clinical status codes

Issue request:
FHIR-13026 was a Published Patient Care change request for DSTU2 Condition.clinicalStatus. Its Persuasive with Modification resolution asked to add well-controlled and poorly-controlled codes under active, with definitions tied to evidence-based outcome targets, and to add a Condition.clinicalStatus comment noting that those statuses could alternatively be conveyed by a pre-coordinated Condition.code.

Initial application:
The issue was applied in git commit 8da21fd1e42462d6253f4ce91b89c267bb415801, which added well-controlled and poorly-controlled concepts to the Condition clinical status code system, updated the Condition.clinicalStatus short name, and added the requested pre-coordinated Condition.code comment. The Jira's own later comments already show follow-up concern about whether the codes should remain.

Additional context:
FHIR-14874 is the tightly related later Published Patient Care decision that superseded this addition for STU3: its final resolution voted to remove well-controlled and poorly-controlled from the existing Condition clinical status value set. Git commit f4005f37a69d8556e2141831d1593747b2319994 removed those concepts, and cccb69d8142e7ec5234dde242ca3da5d556591f5 later removed the residual comment about conveying them with Condition.code. Current source/fhir.ini lists Condition as an active resource; source/condition/structuredefinition-Condition.xml binds Condition.clinicalStatus to ValueSet/condition-clinical; source/condition/valueset-condition-clinical.xml composes that value set from the THO condition-clinical code system; and local THO packages list active, recurrence, relapse, inactive, remission, resolved, and unknown, but not well-controlled or poorly-controlled. FHIR-54841 is a later Waiting for Input issue about broader clinicalStatus value-set adequacy, so it is background rather than a final change to apply here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding the FHIR-13026 codes or pre-coordination comment would conflict with the later applied and already audited FHIR-14874 reversal; the current built Condition source and terminology dependency are correct for the current specification.

Recommendation:
Keep this no-change audit commit as-is. Do not re-add well-controlled or poorly-controlled for FHIR-13026 unless a future finalized Patient Care decision explicitly reverses FHIR-14874; handle broader clinicalStatus redesign under a finalized later tracker such as FHIR-54841.
