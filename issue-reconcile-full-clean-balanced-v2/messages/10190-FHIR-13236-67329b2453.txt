FHIR-13236: Audit Observation obs-7 invariant correction

Issue request:
FHIR-13236 was a Published OO change request for STU3 with a Persuasive with Modification resolution. It reported that the XPath/Schematron implementation of Observation invariant obs-7 produced false negatives when Observation.value[x] was present and no component shared the Observation.code coding; the final comments replaced the double-negative XPath with a rule that fails only when a value is present and a component code matches the Observation code.

Initial application:
No current git commit explicitly mentioning FHIR-13236 was found. The same obs-7 source area was updated in the historical Observation spreadsheet in 2017 by commit 311839957674a44444b3876d8e7a24662b624742 for GF#14073, changing the FHIRPath expression from the older code!=component.code form to a coding-level component-code comparison and carrying an XPath expression equivalent to "not(value exists and matching component code exists)". The source was later migrated to structuredefinition-Observation.xml, and commit 88a1f3d6bd60f7618ae140179b008ac5686e8a08 removed checked-in XPath constraints from ElementDefinition altogether.

Additional context:
Observation is an active current-build resource in source/fhir.ini. The current Observation StructureDefinition contains obs-7 as FHIRPath only: value.empty() or component.code.where(coding.intersect(%resource.code.coding).exists()).empty(). That expression allows an Observation with a value and no matching component code, and disallows only the case the invariant describes: Observation.value[x] together with a component whose code coding intersects Observation.code.coding. Later related issues clarified the human wording (FHIR-38955) and flagged the affected elements with condition references (FHIR-20521). The directly relevant Zulip thread confirms the STU3 Schematron problem was an R3/STU3 artifact; no Confluence reference or direct FHIR-13236 community record was found that changes the current-source conclusion.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current build no longer uses the obsolete XPath assertion that FHIR-13236 challenged, and the active FHIRPath expression already implements the intended truth table.

Recommendation:
Keep this audit commit as-is. Do not reintroduce XPath or make a current core source edit for FHIR-13236; any concern about the historical STU3 published Schematron belongs to a versioned technical-correction process rather than the current FHIR source build.
