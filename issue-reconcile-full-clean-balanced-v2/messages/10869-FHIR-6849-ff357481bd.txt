FHIR-6849: Audit enabled specification search

Issue request:
FHIR-6849 was a Published/Persuasive FHIR-I change request from the 2015 May SDC ballot asking to provide search capability across the FHIR DSTU and FHIR Continuous build sites so implementers and ballot reviewers could find specification content more easily. The issue was applied for DSTU1, carried a 4-0-0 vote, and Grahame Grieve later commented that the work was already done.

Initial application:
No source commit explicitly tagged FHIR-6849 was found. The issue itself records the historical application as already done in October 2015. A 2017 Zulip thread records Grahame announcing that specification search was working again at hl7.org/fhir/search.cfm, and later source history introduced source/search-build.html with an active DuckDuckGo CI search iframe and build registration.

Additional context:
This issue is the same search-capability ballot family as Published/Persuasive FHIR-8151 and FHIR-7712 plus Duplicate FHIR-7748. The combined branch already contains a source-changing FHIR-8151 reconciliation that points the current home page and shared footer to the publisher search-location variable, matching the navbar and the active search-build.html page. The combined branch also contains a no-change FHIR-11438 audit for a later ballot request to enable the same search page. Later live search.cfm reports FHIR-50549 and FHIR-54549 remain unresolved, so they are background operational concerns rather than final applied scope for this DSTU1 issue.

AutoFHIR reconciliation:
This audit commit makes no source change. Current build-scope source already includes the CI search page in publish.ini and the page hierarchy, and user-facing search links on the combined branch route through search-location because of the existing FHIR-8151 reconciliation. Editing tools/html/search.cfm here would duplicate the already-applied link fix or preempt unresolved later live-site work.

Recommendation:
Keep this no-change audit for FHIR-6849. Treat further live search.cfm/searchform behavior as follow-up under a resolved later issue rather than reopening this historical SDC ballot comment.
