FHIR-24687: Audit message example canonical link

Issue request:
FHIR-24687 was a Published/Persuasive technical correction for the FHIR-core messaging page. The reporter identified that the message request example page linked its "canonical form" target at https://www.hl7.org/fhir/message-request-link.canonical.xml, but that target returned 404; later comments indicated this affected generated canonical-form links for resource examples generally.

Initial application:
No Jira-tagged source commit for FHIR-24687 was found in this checkout. The example XML/JSON templates already contained the canonical-form link token before the issue was filed, and git history shows the relevant templates were moved from source/ to tools/templates/ in 2020 and later updated for narrative/example headers without changing the canonical target. The actual issue appears to have been a build/publication tooling or deployment problem: the source link remained correct, while the generated canonical files were missing from the served site.

Additional context:
The MessageHeader resource and example list are active in source/fhir.ini, and source/messageheader/list-MessageHeader-examples.xml includes the message-request-link example that is linked from source/messaging.html. Confluence InM minutes from 2022-01-18 record FHIR-24687 as still broken at that time, but no Zulip or additional Confluence discussion was found that changes the Jira/source conclusion. Current build.fhir.org and hl7.org/fhir both serve message-request-link.xml.html with a canonical-form link to message-request-link.canonical.xml, and that canonical XML URL now returns HTTP 200; build.fhir.org/patient-example.canonical.xml also returns HTTP 200, matching the later comment that the issue was general to resource examples.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source templates still generate canonical-form links, the relevant messaging example remains in the active build, and the public generated canonical targets now exist. Changing source would not improve implementer-facing behavior and could risk removing a now-working link.

Recommendation:
Keep this audit commit as-is. If this resurfaces, investigate the publisher/deployment artifact generation path rather than changing the messaging example source or the canonical-form links in the templates.
