FHIR-36415: Audit workflow barrier extensions

Issue request:
FHIR-36415 is a Published/Persuasive with Modification Patient Care issue for R5. It asked for support for barriers and supportive/protective factors on request-type resources and Goal; the approved resolution was to add workflow-barrier and workflow-protectiveFactor as 0..* CodeableReference extensions, with example value-set bindings, Reference(Any), and contexts of Goal, CommunicationRequest, and CarePlan.activity.

Initial application:
FHIR core commit e547441b507bf3733608ce11ecb92a5a62f50a3d added the J#36415 workflow extension spreadsheet rows plus valueset-barrier and valueset-protective-factor source files, and the work was merged through the 2022 workflow-extension PR. Current core no longer contains those definitions because commit dd468d4f1799dd79819315b211588ef1cf4586e0 removed extension artifacts from R5 core source; core retains only OID registrations for the barrier/protectiveFactor canonical URLs and related SearchParameters.

Additional context:
The authoritative current definitions are now in the FHIR Extension Pack checkout. Its StructureDefinition-workflow-barrier and StructureDefinition-workflow-protectiveFactor files define the requested Goal, CommunicationRequest, and CarePlan.activity contexts, CodeableReference(Any) values, example bindings, and matching ValueSet references; the companion ValueSet files contain the SNOMED codes from the FHIR-36415 resolution. FHIR-36691, the same-change-family request for SearchParameters on these extensions, is already represented on the combined branch as an external-repo audit. FHIR-40301 later repeated the SearchParameter request under the FHIR-extensions specification, while FHIR-44354 is only Triaged/unresolved and does not alter the current contexts.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The seed issue has already been implemented in the repository that now owns standard extension definitions, so re-adding workflow-barrier or workflow-protectiveFactor source to core would duplicate out-of-build artifacts rather than correct the current specification.

Recommendation:
Keep this external-repo audit commit as-is for FHIR core. No core follow-up is indicated; future changes to these extension definitions, names, contexts, bindings, or search parameters should be made in HL7/fhir-extensions after the responsible work group resolves the relevant FHIR-extensions issue.
