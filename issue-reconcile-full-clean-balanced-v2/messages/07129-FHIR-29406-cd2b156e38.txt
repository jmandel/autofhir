FHIR-29406: Audit Resource instance extensions in Extension Pack

Issue request:
FHIR-29406 was a Published/Persuasive with Modification FHIR-core request to add name and description extensions for resource instances, intended to populate ImplementationGuide.definition.resource.name and .description, with appearance constraints preventing use where the resource already has proper title/description slots.

Initial application:
The issue was applied in core by 02d97e2292, which added resource-instance-name and resource-instance-description StructureDefinitions plus Resource-core IG references. The description extension initially had a copy/paste fixedUri error. The core extension source was later removed by dd468d4f17 as part of moving extension definitions out of the R5 core source.

Additional context:
FHIR-I minutes from 2020-11-02 and 2020-11-09 confirm the original approval and reopened/modified vote. The originating Zulip thread records the tooling use case and early expectation of instance-name/instance-description URLs, but a 2023 follow-up thread and FHIR-42968 clarify that the official Extension Pack names are resource-instance-name and resource-instance-description under the usual resource-prefixed naming convention. FHIR-40817 separately corrected the resource-instance-description fixedUri in the Extension Pack.

AutoFHIR reconciliation:
No core source was changed. The current FHIR core checkout has no active source definition for these extensions beyond OID registry entries, while the read-only FHIR Extension Pack checkout contains active resource-instance-name and resource-instance-description definitions with the requested purpose and appearance constraints. Because the authoritative current source for this issue is outside the core repository, this commit records an external-repo audit decision rather than reintroducing core extension definitions.

Recommendation:
Keep this audit commit as-is for the FHIR core reconciliation. Any future source changes for these extensions should be made in the FHIR Extension Pack or IG Publisher/SUSHI tooling, not by adding duplicate definitions back to core.
