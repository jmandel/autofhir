FHIR-13171: Audit invariant XPath propagation

Issue request:
FHIR-13171 was a Published/Persuasive FHIR-core issue asking that technical corrections made to schematron XPath invariants before R3 publication be propagated into the StructureDefinition/source definitions.

Initial application:
The issue key is not named in source history, but Lloyd McKenzie's 2018-02-16 commit 8e56ed7ded34f4d7f721ffdb97987b73fa9be5df, "Fixed a number of schematron errors," changed the relevant invariant XPath cells in CapabilityStatement, TriggerDefinition, DomainResource, Questionnaire, and TerminologyCapabilities source spreadsheets. The corrected examples include CapabilityStatement cpb-15 using XPath equality instead of `==`, TriggerDefinition's timing XPath closing bracket, DomainResource dom-3's `f:reference` namespace prefix, Questionnaire que-11's missing parenthesis, and TerminologyCapabilities tcp-1's `not(exists(...))` syntax.

Additional context:
Those artifacts are in current build scope through active source/fhir.ini entries. The 2021-01-14 source refactor commit 33b409a4b6d544598262f2f074ebb4b6dc466157 replaced the resource spreadsheets for CapabilityStatement, DomainResource, Questionnaire, and TerminologyCapabilities with StructureDefinition XML sources. Those current XML sources carry FHIRPath constraint expressions and no live `<xpath>` constraint elements. TriggerDefinition remains spreadsheet-backed and its current XPath for the historically fixed timing/data invariant is the corrected `not(exists(f:data)) or not(exists(*[starts-with(local-name(.), 'timing')]))` expression. Current ElementDefinition source also notes XPath constraints are generally not useful and may be removed, consistent with the current absence of XPath constraints from the refactored XML sources.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The historical correction was propagated into the old source, and the current source either retains the corrected XPath where XPath is still present or has intentionally moved to FHIRPath-only StructureDefinition source for the affected resources.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for FHIR-13171 unless the build starts requiring regenerated XPath constraints for the refactored StructureDefinition XML sources.
