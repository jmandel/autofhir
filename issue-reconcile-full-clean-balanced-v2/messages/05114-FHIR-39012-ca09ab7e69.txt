FHIR-39012: Audit TestScript response code scope

Issue request:
FHIR-39012 was a Published/Persuasive FHIR-core TestScript change request asking for AssertionResponseTypes to support HTTP 401 Unauthorized, with the approved January 2023 note that the CodeSystem should be updated with valid RFC 9110 HTTP status codes and that other response-code checks remain available through TestScript.setup.action.assert.responseCode.

Initial application:
The issue was applied by git commit 51ad89525e, which updated source/testscript/codesystem-assert-response-code-types.xml to include unauthorized/401 and the broader HTTP status-code set, updated TestScript.setup.action.assert.response wording, and adjusted an example from the old bad code to badRequest.

Additional context:
The current FHIR core build no longer owns the TestScript resource or its assertion response CodeSystem. Commit f9a44787c removed TestPlan, TestReport, TestScript, and their terminology from source/fhir.ini and source/testscript while adding an additional-ig-list entry for the external FHIR Testing IG. The HL7/fhir-testing-ig source and continuous build still contain the AssertionResponseTypes CodeSystem with unauthorized mapped to response code 401.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR core source change. Reintroducing source/testscript or editing generated-looking leftovers in core would be out of build scope; the active artifact for future maintenance is the external FHIR Testing IG, where the requested 401 code is already present.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed for FHIR-39012; any future AssertionResponseTypes changes should be made in HL7/fhir-testing-ig rather than in the FHIR core checkout.
