FHIR-12452: Clarify Observation stats units and codes

Issue request:
FHIR-12452 is a Published/Persuasive OO change request for Observation.$stats. It asked to use `statistic` consistently instead of `params`, prevent statistics over observations the user is not authorized to see, add skew/kurtosis/regression statistic codes, and clarify how unit variations should be handled.

Initial application:
The issue was initially applied by git commit a4bc03f16720aa6553cbff8e798d1585f5a63ed5, which updated the legacy Observation spreadsheet for FHIR-12452 and FHIR-9964. That commit added skew, kurtosis, and regression, renamed the input from `params` to `statistic`, and added the authorization footer. The later source refactor in 33b409a4b6d544598262f2f074ebb4b6dc466157 split the generated material into the current OperationDefinition and observation-statistics CodeSystem, but the $stats request/response examples and the statistic parameter summary still used stale `min`/`max` codes while the required CodeSystem uses `minimum`/`maximum`; the unit-variation clarification was still absent.

Additional context:
Observation is an active resource in source/fhir.ini and source/observation/list-Observation-operations.xml includes OperationDefinition/Observation-stats, so these files are in current build scope. FHIR-10041 is the same change family because it created the $stats operation and statistic code system. Jira, Zulip, and Confluence searches found no later applied decision that changes the FHIR-12452 unit-handling or authorization conclusions; OO 2025 WGM minutes mention a possible future move of $stats to an API Incubator IG, but there is no applied source change for that migration in the current core build.

AutoFHIR reconciliation:
This commit adds the missing common-UCUM-unit guidance to the OperationDefinition footer/comment, aligns the statistic parameter documentation with the required `average|maximum|minimum|count` codes, and updates the request and response examples to use `maximum` and `minimum` instead of stale `max` and `min`.

Recommendation:
Keep this source fix as-is for the current core build. If OO later applies a separate decision to move Observation.$stats out of core, handle that as a separate issue because the current source still publishes this operation.
