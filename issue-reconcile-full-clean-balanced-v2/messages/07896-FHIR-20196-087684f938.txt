FHIR-20196: Audit CapabilityStatement expectation contexts

Issue request:
FHIR-20196 was Published/Persuasive with Modification for R5 and asked to expand http://hl7.org/fhir/StructureDefinition/capabilitystatement-expectation beyond its narrow original context list. The approved resolution was to expand the extension context explicitly according to Eric Haas's listed CapabilityStatement elements rather than making it valid on every element.

Initial application:
Core commit 5b129917061c5f19861dfc5326f95b4be59d507c applied FHIR-20196 together with FHIR-27829 by editing source/capabilitystatement/structuredefinition-extension-capabilitystatement-expectation.xml. That commit added the requested explicit CapabilityStatement contexts including instantiates, format, patchFormat, implementationGuide, rest.security, rest.resource, rest.resource.profile, rest.resource.supportedProfile, rest/resource interactions, conditional flags, search parameters, operations, and REST interaction details.

Additional context:
The current FHIR core checkout no longer owns the capabilitystatement-expectation StructureDefinition. Core commit dd468d4f1799dd79819315b211588ef1cf4586e0 removed the R5 extension definition source from source/capabilitystatement when extensions moved out of core, and current source/fhir.ini has no active [profiles] entry for this extension. The authoritative source is now the FHIR Extension Pack. Its initial import preserved the FHIR-20196 context set, but later Published FHIR-extensions issue FHIR-46192 intentionally corrected that list by removing instantiates, rest.interaction.code, rest.interaction.documentation, and rest.resource.profile, and by adding acceptLanguage and messaging contexts. Existing combined-branch audit commits already cover related FHIR-27829 and FHIR-28103.

AutoFHIR reconciliation:

Keep this empty audit commit as an external-repo decision for core. No FHIR core follow-up is needed; future changes to capabilitystatement-expectation contexts should be made in HL7/fhir-extensions and evaluated against the later FHIR-46192 correction.
