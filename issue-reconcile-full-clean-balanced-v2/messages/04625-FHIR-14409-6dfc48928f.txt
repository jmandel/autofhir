FHIR-14409: Audit ChargeItem product external ownership

Issue request:
FHIR-14409 was a Published/Persuasive with Modification PA change request raised against STU3 and applied for R5. It asked to add ChargeItem.product for cases where a charge depends on a specific delivered product instance, originally as Reference(Device|Substance|Medication), with the final resolution adopting the pre-applied content but changing it to CodeableReference.

Initial application:
The issue was pre-applied in legacy commit 370535c6c2924200b9b30c3a539f6456d334471c, whose git-svn id is build@13749. The final resolution was then applied by commit 659ea74c5598ec1a0c30d45951bf26eb03718886, which changed source/chargeitem/structuredefinition-ChargeItem.xml from ChargeItem.product[x] 0..1 Reference(Device|Medication|Substance)|CodeableConcept to ChargeItem.product 0..* CodeableReference(Device|Medication|Substance). The v5.0.0 tag contains that same product element.

Additional context:
ChargeItem is no longer an active FHIR core resource in the current checkout. source/fhir.ini's active [resources] list omits ChargeItem, source/chargeitem is absent, and source/ballot-intro.html plus source/modules-fragment.html link ChargeItem to the HL7 Admin Incubator IG. Later core commit 71567db3ee039ac6977be5f96a7e013896569a36 removed source/chargeitem and the ChargeItem fhir.ini entries. The current Admin Incubator package contains StructureDefinition/ChargeItem, and its ChargeItem.product element is still 0..* CodeableReference(Device|Medication|Substance).

AutoFHIR reconciliation:
This commit intentionally makes no source change in HL7/fhir and records an external-repo decision. Re-adding or editing source/chargeitem in core would alter out-of-build source, while the requested product modeling was already applied for R5 and is preserved in the current external ChargeItem artifact.

Recommendation:
Keep this external-repo audit as-is for FHIR core. Do not restore ChargeItem to source/fhir.ini or source/chargeitem for FHIR-14409; any future changes to ChargeItem.product should be made in HL7/admin-incubator or whichever repository owns the additional resource at that time.
