FHIR-11232: Audit workflow presentation for PlanDefinition and ActivityDefinition

Issue request:
FHIR-11232 was Published with a Persuasive with Modification resolution for the DSTU2 ballot. It asked to move PlanDefinition and ActivityDefinition under the Workflow Working Group to provide a wider focus beyond clinical decision support. The final resolution declined a formal ownership move because Workflow was a task force rather than a working group, but said CDS would participate in that task force and documentation should present the resources from both CDS and workflow perspectives.

Initial application:
No current git commit was found with an explicit FHIR-11232/Jira tracker tag. The Jira comments record that ActivityDefinition and PlanDefinition were recategorized as Workflow by Lloyd's changes. In source history, Lloyd's 2017 workflow-module edits, especially 6a96b06674, expanded the Workflow module to discuss PlanDefinition and ActivityDefinition as workflow definition resources and to describe their evolution across clinical order sets, medication protocols, workflow protocols, clinical pathways, and administrative protocols.

Additional context:
Current source/fhir.ini actively builds both resources. The current workgroup metadata still assigns ActivityDefinition and PlanDefinition to CDS, and fhir.ini has no Workflow working group code; that matches the resolution's point that Workflow was not a distinct owning work group. Current Workflow module and modules diagram include PlanDefinition, and the Workflow module directly names both PlanDefinition and ActivityDefinition as definitions for clinical-process/workflow use. Current Clinical Reasoning pages also retain both resources, preserving the CDS perspective instead of creating a misleading ownership transfer.
