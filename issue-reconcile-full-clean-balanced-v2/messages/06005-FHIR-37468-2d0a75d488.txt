FHIR-37468: Audit Questionnaire SimpleQuantity answers

Issue request:
FHIR-37468 is Published/Persuasive with Modification. It asked for Questionnaire quantity questions to support forms that need a numeric quantity and unit without allowing comparators; the accepted modification was not to add a separate Questionnaire.item.type code, but to make the existing quantity item type always mean SimpleQuantity and to change QuestionnaireResponse quantity answers to SimpleQuantity.

Initial application:
The Jira comment cites git Questionnaire-fixes 28dd25d341. That commit updated source/questionnaire/codesystem-item-type.xml from a comparator-capable Quantity description to a SimpleQuantity answer description and changed source/questionnaireresponse/structuredefinition-QuestionnaireResponse.xml so QuestionnaireResponse.item.answer.value[x] uses SimpleQuantity instead of Quantity.

Additional context:
Questionnaire and QuestionnaireResponse are active resources in source/fhir.ini, so their resource folders feed the current build. A later same-change-family issue, FHIR-41195, completed the remaining Questionnaire-side SimpleQuantity cleanup by changing enableWhen.answer[x] and initial.value[x] to SimpleQuantity and changing the item-type wording away from the impossible valueSimpleQuantity element name; that related issue is already represented on the combined branch and is not re-decided here. The Zulip comparator thread and SDC minutes align with the modified resolution: Questionnaire quantity answers should omit comparator support by using SimpleQuantity semantics.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/questionnaire/codesystem-item-type.xml defines the quantity item type as a Quantity constrained to SimpleQuantity, source/questionnaireresponse/structuredefinition-QuestionnaireResponse.xml uses SimpleQuantity for QuestionnaireResponse.item.answer.value[x], and related Questionnaire answer locations are already SimpleQuantity.

Recommendation:
Keep this audit commit as-is. The seed issue is already correctly applied in active source, and adding a separate SimpleQuantity Questionnaire.item.type code or reintroducing valueSimpleQuantity wording would contradict the accepted modification and later cleanup.
