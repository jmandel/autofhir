FHIR-10647: Clarify ContactPoint URL narrative

Issue request:
FHIR-10647 is a Published/Persuasive FHIR-core datatypes change request. It asked to restore ContactPoint.system code "url" after FHIR-6089 removed it, define "url" for non-phone/fax/pager/email contacts expressed as URLs, redefine "other" for contacts not expressible as URLs, and change the display for "other" to "Other".

Initial application:
The 2016-12-04 implementation commit 2ea2f88f92ad35028521ebd3e595f50daa73990e restored "url" in source/datatypes/contactpoint.xml and added the revised "url" and "other" code definitions. However, the source/datatypes.html ContactPoint narrative still carried the earlier FHIR-6089 wording that told readers to use system "other" for URL-style contact points, which conflicted with the restored code.

Additional context:
FHIR-6089 is the earlier Published/Persuasive change that renamed ContactPoint.system.url to "other" and added URL/human-interpretation guidance. FHIR-12684 later added "sms" without changing the URL/other split. Later no-change decisions such as FHIR-32004, FHIR-36033, and FHIR-39154 retained the required ContactPoint.system code set and relied on "url", "other", and extensions for new contact technologies. ContactPoint is active in source/fhir.ini as a normative datatype published from the datatypes page.

AutoFHIR reconciliation:
This commit updates source/datatypes.html so the narrative now matches the authoritative ContactPoint.system code list: URL-expressible contact points use system "url" with a URL value, while contacts not expressible as URLs use system "other" and may need human interpretation or extensions. It also removes the stale http{s}: typo in the same sentence.

Recommendation:
Keep this source change as-is. It completes the missed narrative portion of FHIR-10647 while preserving the current required code list and avoiding any change to ContactPoint.system bindings.
