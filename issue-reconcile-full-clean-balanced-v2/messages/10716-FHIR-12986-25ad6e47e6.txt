FHIR-12986: Audit open-type metadata and Dosage allowance

Issue request:
FHIR-12986 was a Published/Persuasive FHIR-I change request for DSTU2. It asked that the open type element list for "*" allow the newly introduced metadata datatypes and the medication-specific Dosage datatype so extensions and operation Parameters could use them.

Initial application:
The request was applied in svn revision 12844, now git commit 0abcdc9272, which added Dosage and the STU3 metadata datatypes to the then hand-maintained open type list in source/datatypes.html. A later source refactor in dcd3ffda90 replaced duplicated hand-maintained lists in source/datatypes.html and source/extensibility.html with [%wildcard-type-list%] and [%extension-type-list%] placeholders, leaving the allowed type set driven by the build's datatype configuration rather than the old inline list.

Additional context:
The current build configuration in source/fhir.ini includes the issue-relevant metadata datatypes ContactDetail, DataRequirement, ParameterDefinition, RelatedArtifact, TriggerDefinition, UsageContext, and Dosage in the active [types] list, with current successor metadata types also present and Contributor intentionally absent after later model changes. The active Parameters source also lists those metadata datatypes and Dosage in Parameters.parameter.value[x]. The current CI-rendered datatypes and extensibility pages show these types in the open/wildcard and extension value lists, and no Zulip or Confluence evidence was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative source and rendered build already satisfy the published request for open type elements, Extension.value[x], and operation Parameters.

Recommendation:
Keep this no-change audit commit as-is. No core source follow-up is needed for FHIR-12986 unless a future publisher regression drops the fhir.ini-driven metadata or Dosage entries from the generated wildcard/extension lists.
