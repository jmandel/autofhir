FHIR-26955: Audit Task performerOrder extension context

Issue request:
FHIR-26955 was a Published/Persuasive FHIR-I change request for R5 asking that the standard request-performerOrder extension be applicable to Task, or that an equivalent core mechanism be justified. The accepted resolution was to add the extension as an allowed extension on Task.requestedPerformer.

Initial application:
The issue was applied in git commit 5b5f62f55a, which updated the request-pattern extension spreadsheet so performerOrder applied to ServiceRequest.performer and Task.requestedPerformer, and adjusted the Task.requestedPerformer short description. The same change family includes FHIR-26960, which renamed Task.performerType to Task.requestedPerformer and changed it to CodeableReference before this extension context could target the final R5 element name.

Additional context:
Task is an active resource in source/fhir.ini, and current source/task/structuredefinition-Task.xml still defines Task.requestedPerformer as a 0..* CodeableReference. Core later removed extension definitions from the R5 source in dd468d4f17, so request-performerOrder is no longer maintained as a core source spreadsheet row. The current FHIR Extension Pack source defines http://hl7.org/fhir/StructureDefinition/request-performerOrder with an element context expression of Task.requestedPerformer starting in FHIR 5.0, preserving the accepted FHIR-26955 behavior outside the core checkout.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding request-performerOrder to core would conflict with the later extension-pack move, and the authoritative Extension Pack definition already contains the Task.requestedPerformer context requested by the issue.

Recommendation:
Keep this no-change audit commit as-is. No core follow-up is needed for Task; future maintenance should preserve the Task.requestedPerformer context in the Extension Pack rather than restoring removed core extension-source rows.
