FHIR-6344: Audit Observation boolean value guidance

Issue request:
FHIR-6344 was a Published/Persuasive OO change request from the DSTU1 Observation ballot asking that, if Observation.valueBoolean was not added, the Observation page explain why and link to an appropriate value set for representing boolean-like values with Observation.valueCodeableConcept. The accepted resolution agreed to add notes explaining why coded values were preferred for most boolean-like observations and to link to HL7 v2 Table 0136.

Initial application:
The issue was explicitly applied in git-svn commit 41029c884d580ad7aa45a0df42dbdbefd2d6acaf, titled "#6344 update notes to explain boolean values", which refined the Observation Notes text to say that Boolean is rarely appropriate because observations often need exceptional values such as unknown and to point to HL7 v2 Table 0136 yes/no concepts. Commit 861e258d1a204905f5c0a41386f0d95cb5495ce9 had just added the v2 Table 0136 true/false-style note as part of the same old Observation.value guidance family.

Additional context:
Observation is active in source/fhir.ini, so source/observation/observation-notes.xml and source/observation/structuredefinition-Observation.xml are current build-scope sources. Current notes still explain that Boolean values are rarely truly Boolean, recommend CodeableConcept with terminology.hl7.org/ValueSet/v2-0136 for yes/no-style concepts, and list valueBoolean among value[x] choices. Later Published/Persuasive issue FHIR-10275 added boolean to Observation.value[x], so the current spec is more permissive than the original FHIR-6344 premise while preserving the coded-value guidance. Related combined-branch audits for FHIR-7547 and FHIR-8605 already cover the adjacent true/false and datatype-page notes.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Observation source already satisfies the FHIR-6344 request, and adding more prose would duplicate existing notes rather than correct a missing or misleading rule.

Recommendation:
Keep this no-change audit commit as-is. No core source edit is needed for FHIR-6344 unless OO makes a newer decision to change the balance between direct valueBoolean use and coded yes/no Observation values.
