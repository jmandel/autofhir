FHIR-25237: Audit SNOMED laterality property cleanup

Issue request:
FHIR-25237 was a Published/Persuasive FHIR-core technical correction raised against the R4 definitions.xml.zip valuesets.xml bundle. It reported that CodeSystem/snomedct listed two properties with code Laterality: the valid laterality URI http://snomed.info/id/272741003 and the unrelated URI http://snomed.info/id/363699004, which should identify Direct Device.

Initial application:
No commit explicitly tagged FHIR-25237 was found. The pre-R5 active source file source/codesystem/codesystem-snomedct.xml contained the duplicate Laterality property, and the R4 history bundle still reflects that published R4 state. R5 vocabulary cleanup commit 9500b398d1d850a06cd180c82ce330e4809a2b49 removed the active core SNOMED CT CodeSystem source and removed CodeSystem/snomedct from the CodeSystem examples list; follow-up commit 9049817626509bd4faf0ac6b8187b08149e1f0a3 removed the narrative link to codesystem-snomedct.html.

Additional context:
A 2022 terminology Zulip thread independently confirmed that CodeSystem property codes are intended to be unique and that http://snomed.info/id/363699004 should be Direct Device, matching the Jira reporter's diagnosis. Current source has no non-history occurrence of 363699004, build.fhir.org and the published R5 site both return 404 for codesystem-snomedct, and tools/history/release5/valuesets.xml no longer contains CodeSystem/snomedct. The R4 history file remains unchanged as a historical published artifact, while the later R4B history import labels 363699004 as Direct Device.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build no longer publishes the erroneous core SNOMED CT CodeSystem resource, and editing the R4 historical generated valuesets.xml would rewrite a past release artifact rather than correct the current specification.

Recommendation:
Keep this audit commit as-is. No FHIR-core source change is needed for the current build; only a separate, explicit historical-release errata process should consider modifying the R4 generated history artifact.
