FHIR-17463: Audit narrative normative wording

Issue request:
FHIR-17463 was a Published/Persuasive with Modification FHIR-I change request for the core Narrative page. It asked to distinguish normative requirements from informative guidance by changing selected narrative prose to RFC-style SHALL/MAY/SHOULD wording, while the approved resolution explicitly said to make all proposed changes except the final proposed sentence changing "The narrative is an XHTML fragment" to "The narrative SHALL BE an XHTML fragment."

Initial application:
The issue was applied in git commit d2f5be10b33b56c87d6a9ea51a46d2c48ac7efa1, "GF#17463 - fix normative language," which carries the Jira comment's svn revision 14245. That patch changed the requested narrative page wording to "It SHALL be safe," "MAY define," "MAY contain," "SHOULD include," split the informative example before the systems paragraph, changed the List/Composition rule sentence to non-normative "can," changed the consideration sentence to "would," and changed the text-only resource sentence to "A resource MAY" with "can be necessary."

Additional context:
FHIR-17463 was a follow-up to FHIR-16480, which was Resolved - No Change / Not Persuasive because a SHALL does not need to be testable technical criteria. The current source/fhir.ini lists Narrative as an active type page and normative datatype, so source/narrative.html is in current build scope. No directly relevant Zulip or Confluence hits were found for FHIR-17463/FHIR-16480 plus the narrative normative/informative terms.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source/narrative.html already preserves the accepted application: the normative wording is present, the paragraph break separating the informative example from the normative systems rule is present, and the rejected final sentence remains "The narrative is an XHTML fragment" rather than "SHALL BE."

Recommendation:
Keep this audit commit as-is. Further source edits would either duplicate already-applied wording or apply the one proposed change that the work group explicitly excluded.
