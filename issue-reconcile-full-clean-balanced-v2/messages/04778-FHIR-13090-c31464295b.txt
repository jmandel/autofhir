FHIR-13090: Audit UsageContext species value binding

Issue request:
FHIR-13090 was a Published/Persuasive MnM change request for the DSTU2 datatypes page. It asked that the UsageContext context type code `species` have a value set, with the resolution to define an example binding to the same value set used for SDC.

Initial application:
No source commit explicitly names FHIR-13090. The relevant source was already in place before the issue was resolved: FHIR-12904 added the `species` usage-context-type code and SNOMED species include, and the later #13059/FHIR-13059 commit added the `UsageContextValue` example binding to `http://hl7.org/fhir/ValueSet/use-context`.

Additional context:
Current source keeps UsageContext in the active datatype list and marks it normative. `UsageContext.code` is bound to the usage-context-type value set, `UsageContext.value[x]` is bound by example to `ValueSet/use-context`, and that value set still includes SNOMED CT descendants of `387961004 | Kingdom Animalia (organism)`. The newer `UsageContext-additional-bindings.xml` fragment gives conditional helper bindings for several usage-context-type codes, but the seed issue's requested example binding is already satisfied by the datatype's active `UsageContextValue` binding and the composed value set; adding redundant species-only prose or another conditional binding is not necessary for current implementer understanding.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source already carries the species context type and the example value set containing the species code hierarchy requested by the Jira resolution.

Recommendation:
Keep this audit commit as-is. Revisit only if MnM or CDS decides that `species` needs a separate conditional additional binding in addition to the existing `UsageContext.value[x]` example binding.
