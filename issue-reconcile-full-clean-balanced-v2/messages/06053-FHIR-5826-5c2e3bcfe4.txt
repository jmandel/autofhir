FHIR-5826: Audit FamilyMemberHistory status for unknown history

Issue request:
FHIR-5826 was a Published Patient Care change request, resolved Persuasive with Modification, asking for a described way to record that family history for a relation was not collected or unavailable and considering a status element. The accepted resolution was to add a FamilyHistory status with entered-in-error, complete/partial, and health-unknown concepts.

Initial application:
The original source application is commit 1f59a1646f, which explicitly mentions #5826 and added FamilyMemberHistory.status, the FamilyHistoryStatus code list, and required status values while also applying FHIR-7483 condition-alignment work. That initial code list used the implemented code completed for the resolution's complete concept and included health-unknown for unavailable family-member history.

Additional context:
FamilyMemberHistory is active in source/fhir.ini, so source/familymemberhistory is in the current build. Later FHIR-13077 removed notDone and renamed notDoneReason to dataAbsentReason, clarifying that when family member history is attempted but unavailable or unknown, status is health-unknown. Later FHIR-8781/FHIR-8782 added notes for patient-level List.emptyReason and condition negation, and FHIR-55325 reaffirmed in R6 that FamilyMemberHistory.status already includes health-unknown while adding local note text. FHIR-32901 remains Triaged and is not a final decision.

AutoFHIR reconciliation:
This audit commit makes no source change because the current active source already implements the required status mechanism, keeps the required history-status binding, includes entered-in-error, partial, completed, and health-unknown in the code system, and documents health-unknown plus dataAbsentReason for unavailable history of an individual family member.

Recommendation:
Keep this no-change audit as-is. Further changes to broader List-vs-FamilyMemberHistory guidance should wait for a final decision on newer open trackers such as FHIR-32901 rather than reopening FHIR-5826.
