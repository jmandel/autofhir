FHIR-13323: Audit versioned backport extension URLs

Issue request:
FHIR-13323 was a Published/Persuasive with Modification FHIR-core STU3 change request asking HL7 to adopt a standard URL convention for extensions used to backport newer-version elements into older-version resources, originally prompted by STU3 elements such as MedicationStatement.category being represented in DSTU2 resources.

Initial application:
The Jira records Grahame's application as svn revisions 14138-9. In the git-svn history, commits 641002468f296d9085044e7704733e224a609f82 and 29cb644ee885b2c6959f2ab41d4b767391158b21 are both labelled GF#13323 and added the source/versions.html "Extensions for converting between versions" section plus links from diff/transform pages. That application introduced the standard extension URL pattern and examples for R4, STU3, and DSTU2 elements.

Additional context:
The originating Zulip thread shows the original proposed URL, Grahame's refinement to StructureDefinition/extension-[path], the later move to major.minor version components, and Grahame pointing implementers to build.fhir.org/versions.html#extensions after applying the change. The later Published follow-up FHIR-16015 requested documentation and generated package information for the same family and is already represented on the combined branch by commit a89f8026d38666b594784393f1018e403e841c08. Current source/versions.html, an active build page via source/hierarchy.xml, now centralizes the rule as http://hl7.org/fhir/[defining_version]/StructureDefinition/extension-[Path], lists formal milestone version values, gives representative extension URLs, and links to the cross-version definition package matrix. Later source history, including FHIR-42923, refined the wording rather than reversing the convention.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current FHIR core source already contains the versioned backport/cross-version extension URL convention requested by FHIR-13323, and duplicating it on the extensibility page would add a maintenance risk without changing implementer understanding.

Recommendation:
Keep this audit commit as-is for FHIR core. Future work should only change core if a newer applied Jira changes the centralized versions.html guidance; package-generation or content completeness questions belong to the cross-version package/IG stream rather than this seed.
