FHIR-25470: Audit PlanDefinition timing choices

Issue request:
FHIR-25470 was a Published/Persuasive CDS change request for R5 asking to remove dateTime and Period from PlanDefinition.action.timing[x] because static dateTime and Period values are not appropriate in a definitional resource. The approved resolution also required clarifying documentation that the timing element provides timing for when an action should be performed, interpreted during apply so resulting request actions receive concrete timing from the evaluated definition.

Initial application:
No explicit FHIR-25470-tagged source commit was found. The approved change appears to have been applied by git commit 1b8c8728485bc9bfa8dcc454047dba518eca81e5, whose subject references the neighboring FHIR-25471 ActivityDefinition issue and which removed dateTime and Period from both ActivityDefinition.timing[x] and PlanDefinition.action.timing[x] while adding the requested apply-operation timing comments.

Additional context:
PlanDefinition is an active approved current-build resource in source/fhir.ini. The parallel FHIR-25471 issue has already been represented on the combined branch by a no-change audit commit, so it is not republished here. Later timing-family work did not reverse FHIR-25470: FHIR-43696 added RelativeTime as an approved timing choice for R6, and the already-published FHIR-29799 reconciliation updated the PlanDefinition and ActivityDefinition timing comments to explain RelativeTime while preserving the removal of dateTime and Period. The old RequestGroup wording in the Jira resolution now appears as RequestOrchestration in the current source, matching the current resource name.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Recommendation:
Keep this no-change audit commit. No current FHIR core source correction is needed for FHIR-25470; future timing-choice changes should be handled through later timing-family trackers rather than reintroducing static dateTime or Period choices.
