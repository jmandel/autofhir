FHIR-27052: Audit Resource.id operation id guidance

Issue request:
FHIR-27052 was a Published/Persuasive FHIR-I clarification asking that the Resource.id comment no longer say that create is the only time a resource lacks an id, because operation Parameters and other non-RESTful/transient uses can also omit a logical id.

Initial application:
The issue was applied by git commit bfc3c04c9a00f50497c966d8db85b0861dd4d296, which changed the active Resource StructureDefinition comment from the old create-only statement to REST-scoped wording in source/resource/structuredefinition-Resource.xml. There was no prior Issue-Reconcile-Key: FHIR-27052 commit on the combined branch.

Additional context:
The referenced Zulip thread records the rationale: Grahame Grieve said the old sentence was only correct for the RESTful API and that operations are one of the contexts where resources can lack ids. FHIR-I minutes for 2020-05-11 record the 14-0-0 persuasive vote. Current source/resource/resource-notes.xml now also lists operation input/output resources and resources exchanged outside REST as logical-id exceptions. Related identity wording issues FHIR-33978 and FHIR-33979 were already separately audited on the combined branch and are not re-decided here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active Resource.id definition and Resource Logical ID narrative already preserve the work-group decision and give implementers the non-REST and operation exceptions needed for this issue.

Recommendation:
Keep this audit commit as-is. No source fix is needed for FHIR-27052; any future cleanup of small editorial details in the existing wording should be handled separately from this applied clarification.
