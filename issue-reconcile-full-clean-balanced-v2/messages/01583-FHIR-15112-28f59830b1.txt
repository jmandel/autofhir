FHIR-15112: Audit Consent subject optionality

Issue request:
FHIR-15112 was a Published/Persuasive STU3 CBCC change request asking to relax Consent.patient from 1..1 to 0..1 so Consent could be used for provider-directory restrictions without a required patient. Its resolution also proposed making Consent.scope extensible with invariants for existing patient-oriented scopes.

Initial application:
The issue was applied historically in commit 2c05932185 (GF#15112 GF#15102), which changed the Consent spreadsheet so Consent.patient moved from 1..1 to 0..1 while remaining Reference(Patient). The same commit also co-applied the unrelated FHIR-15102 identifier cardinality change.

Additional context:
Current Consent source is no longer spreadsheet-driven for this resource. Consent is active in source/fhir.ini, and fhir.ini maps old Consent.patient to Consent.subject and old Consent.scope to Consent.category. Later Published Consent decisions changed the relevant model: FHIR-26644 renamed Consent.patient to Consent.subject and added Practitioner, FHIR-27032 added ResearchSubject, and FHIR-31903 eliminated Consent.scope and moved flexible categorization to Consent.category with profiling/IG guardrails rather than core invariants. The current source also carries a VHDir-style provider restriction example with no subject, confirming the no-patient use case remains representable.

AutoFHIR reconciliation:
This commit makes no source change. The current active Consent definition already has Consent.subject (the successor of Consent.patient) with min 0 and max 1, so the seed issue's required optionality is present. Restoring the old scope invariant plan would conflict with the later Published FHIR-31903 decision that removed Consent.scope from core.

Recommendation:
Keep this no-change audit. Future work, if any, should be driven by new WG decisions about broadening Consent.subject target types or provider-directory profiling, not by FHIR-15112, whose applied requirement is already reflected in current core source.
