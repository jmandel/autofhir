FHIR-27812: Audit _elements modifier guidance

Issue request:
FHIR-27812 was Published as Persuasive for R5. It asked the search page to align _elements advice for clients and servers by advising both to pay attention to mandatory elements and modifier elements, because the server-side guidance only mentioned mandatory elements.

Initial application:
The request was applied by historical commit 22b2855454d1fdcabe258f22b89290ad4a6e4c35, titled "FHIR-27812", which changed source/search.html so servers SHOULD return mandatory and modifier elements whether requested or not. There was no existing Issue-Reconcile-Key audit commit for FHIR-27812 on the combined branch before this reconciliation.

Additional context:
FHIR-31655 later clarified the neighboring client-side _elements wording and explicitly referenced FHIR-27812, preserving the same mandatory/modifier safety model. FHIR-43354 later removed the confusing word "always" from the server SHOULD sentence and added the RESTful API note, but it retained the mandatory and modifier element guidance required by FHIR-27812. The FHIR-I 2020-06-22 minutes also record the decision as "Will list modifiers for server too" with an 8-0-0 vote.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the active FHIR-core search page source already says that clients can generally expect returned elements to include explicitly requested elements, mandatory elements, or modifier elements with values, and that servers SHOULD return mandatory and modifier elements whether requested or not.

Recommendation:
Keep this audit commit as-is. No follow-up core source change is needed for FHIR-27812 unless a future work-group decision changes the conformance strength or the safety guidance for modifier elements returned under _elements.
