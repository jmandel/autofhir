FHIR-32571: Audit DeviceAssociation status cardinality

Issue request:
FHIR-32571 was Published with a Persuasive with Modification resolution for the R4 Device resource. It asked why associationStatus was not mandatory when a reason could be present, and OO resolved to make Device.associationStatus.value 1..1 while leaving the optional backbone/reason structure otherwise optional.

Initial application:
The issue was initially applied by git commit 57eb8685b7, which changed source/device/structuredefinition-Device.xml so Device.associationStatus.value moved from 0..1 to 1..1. The old Device.associationStatus backbone was later removed from Device as the model evolved, and DeviceAssociation became the active current resource for this area.

Additional context:
OO WGM minutes for 2021-05-24 list FHIR-32571 with the decision to make status values mandatory and leave reason optional. In the current build, source/fhir.ini actively includes deviceassociation=DeviceAssociation, and source/deviceassociation/structuredefinition-DeviceAssociation.xml has DeviceAssociation.status as 1..1 with DeviceAssociation.statusReason optional. A later Applied issue, FHIR-48532, intentionally split record/lifecycle status from association state by keeping DeviceAssociation.status required and adding DeviceAssociation.associationStatus as 0..1 CodeableConcept.

AutoFHIR reconciliation:
This audit commit makes no source change. The current required DeviceAssociation.status preserves the FHIR-32571 rule that a reason is not present without a status, while changing DeviceAssociation.associationStatus to mandatory would conflict with the later explicit FHIR-48532 decision that introduced it as optional.

Recommendation:
Keep this audit commit as-is. Do not make DeviceAssociation.associationStatus mandatory for FHIR-32571 without new OO review, because the current source already has a mandatory status for statusReason and later WG action deliberately made the separate associationStatus element optional.
