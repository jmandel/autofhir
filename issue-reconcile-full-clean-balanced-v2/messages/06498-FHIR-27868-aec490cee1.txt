FHIR-27868: Audit DeviceRequest performer wording

Issue request:
FHIR-27868 was Published with a Persuasive with Modification resolution for R5. It asked to replace the copied DiagnosticRequest wording on DeviceRequest.performer and, after OO discussion, to update DeviceRequest.performer, DeviceRequest.performerType, and DeviceRequest.requester so requester identifies who submitted or initiated the request while performer/performerType identify the individual, entity, or category providing the requested device.

Initial application:
No prior AutoFHIR audit commit for FHIR-27868 was present on the combined branch. Source history shows commit 0763661ef79399537866358e94efadccc2577c4a ("27868 25799") changed source/devicerequest/structuredefinition-DeviceRequest.xml on 2021-04-04, replacing the requester short/definition, performerType definition, and performer definition with the requested language. Commit 086649a2357c29f8c83dca7604dc592d32c84355 later added the DeviceRequest request-pattern mapping exception file with the same current requester and performer wording.

Additional context:
DeviceRequest is active in source/fhir.ini. The current source no longer has DeviceRequest.performerType as a separate element; later R6 cleanup removed the commented performerType element after performer became the CodeableReference surface, and source/fhir.ini records DeviceRequest.performerType as mapped to performer.concept. Current source/devicerequest/structuredefinition-DeviceRequest.xml already defines DeviceRequest.requester as "Who/what submitted the device request" with the requested initiated/responsibility definition, and DeviceRequest.performer as the desired individual or entity to provide the device. OO HCP minutes from 2020-07-27 record the same proposed updates; no directly relevant Zulip conflict was found. FHIR-25799 appeared in the same historical commit subject and minutes but concerns DeviceUseStatement, so it is background only.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current build source already carries the required DeviceRequest requester and performer wording, and the performerType part of the historical resolution is represented by the later merged performer CodeableReference model/migration note rather than by a current separate element.

Recommendation:
Keep this no-change audit as-is. No core FHIR source follow-up is needed for FHIR-27868 unless OO decides in a future tracker to reintroduce a separate performerType element or revise the current CodeableReference modeling.
