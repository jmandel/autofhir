FHIR-13644: Audit Bundle PATCH method binding

Issue request:
FHIR-13644 was Published/Persuasive with Modification for STU3. It asked FHIR-I to add PATCH to the required Bundle.entry.request.method HTTPVerb binding and to document how PATCH payloads are represented inside Bundle entries.

Initial application:
The issue was explicitly applied in git commit 0791ecad7f986bc7cc47c91bc5edafcc4facd452, the svn revision 12834 commit referenced in Jira, which added PATCH to the Bundle spreadsheet's HTTPVerb code list. Later source refactoring moved the authoritative Bundle definition and HTTP verb terminology into source/bundle/structuredefinition-Bundle.xml and source/bundle/codesystem-http-verb.xml.

Additional context:
Bundle is active in the current build through source/fhir.ini. Current source/bundle/codesystem-http-verb.xml includes PATCH, and Bundle.entry.request.method's short code list includes PATCH with a required binding to ValueSet/http-verb. Current Bundle constraints allow PATCH for transaction and batch request entries. Later Published issue FHIR-19620 says PATCH-created history entries are represented as PUT and added bdl-14 prohibiting PATCH when Bundle.type is history. Later Published issue FHIR-33945 accepted a Binary resource mechanism for JSON Patch in batch/transaction Bundles after considering Parameters, so the old FHIR-13644 Parameters-string documentation request should not be reintroduced as current guidance. The remaining PATCH-history tension between FHIR-19620 and FHIR-34388 is already represented on the combined branch as a human-review issue, not something to resolve under this seed.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The core FHIR-13644 request is already present in active source: PATCH is an allowed HTTPVerb for Bundle.entry.request.method and transaction/batch PATCH entries have current guidance. No edit is needed for the obsolete Parameters-string wording because later accepted source uses FHIRPath Patch Parameters normally and JSON Patch Binary for batch/transaction Bundles.

Recommendation:
Keep this no-change audit commit as-is. Do not add the older JSON/XML Patch-as-Parameters-string wording back to Bundle; follow FHIR-33945's Binary guidance and leave the separate PATCH-history conflict to the existing FHIR-19620/FHIR-34388 human-review trail.
