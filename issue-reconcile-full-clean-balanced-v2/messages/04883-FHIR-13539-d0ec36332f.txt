FHIR-13539: Audit Encounter location detail

Issue request:
FHIR-13539 was a Published/Persuasive PA change request from STU3 asking Encounter.location to state which level of the location hierarchy is being recorded. Its resolution added Encounter.location.physicalType 0..1 CodeableConcept with an example binding to the location physical type value set so implementations could record bed, room, ward, or similar levels directly for messaging and query.

Initial application:
No git commit explicitly mentioning FHIR-13539 was found in the current repository history, which appears to post-date the STU3 application. The imported Encounter source already contained Encounter.location.physicalType with the requested 0..1 CodeableConcept shape, the requested definition about bed/ward/room levels, and an example binding to http://hl7.org/fhir/ValueSet/location-physical-type.

Additional context:
Encounter is active in source/fhir.ini, so source/encounter/structuredefinition-Encounter.xml is in the current build. FHIR-36815 later renamed Location.physicalType to Location.form, renamed the value set to location-form, added virtual location support, and explicitly made Encounter.location.physicalType consistent by renaming it to Encounter.location.form. The current fhir.ini R4/R5 mapping aliases Encounter.location.physicalType to Encounter.location.form. FHIR-57398 is a later Resolved - change required clarification for Location.form/Encounter.location.form, but it is not Applied or Published and is outside this default source-edit seed scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Encounter.location.form element is the renamed continuation of the FHIR-13539 physicalType element: it is 0..1 CodeableConcept, retains the same definition about specifying bed/ward/room/etc. levels for messaging or query, and binds with example strength to the current location-form value set. Reintroducing physicalType or adding duplicate prose would conflict with the later Published FHIR-36815 rename without improving implementer understanding.

Recommendation:
Keep this audit commit as-is for FHIR-13539. If the later FHIR-57398 clarification enters an applied/published reconciliation scope, handle that separately because it changes current display/description wording for Location.form and Encounter.location.form rather than the original STU3 location-detail requirement.
