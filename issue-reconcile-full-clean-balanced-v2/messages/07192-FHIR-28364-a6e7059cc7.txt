FHIR-28364: Audit Bundle fullUrl invariant

Issue request:
FHIR-28364 was Published with a Persuasive with Modification resolution for R5. It asked to add a Bundle constraint for the existing Bundle uniqueness statement that, except for transactions and batches, each Bundle.entry must have fullUrl; the resolution clarified that transaction-response and batch-response were also exceptions and that POST creates were to be exempted.

Initial application:
The issue was applied in 23ee64c28d, which added the bdl-15 invariant to source/bundle/structuredefinition-Bundle.xml. The Bundle resource is active in source/fhir.ini, so source/bundle/structuredefinition-Bundle.xml and source/bundle/bundle-notes.xml are current build inputs. The original Zulip thread requested exactly this constraint, and the FHIR-I 2020-11-30 minutes record the vote and discussion about transaction/batch responses and POST.

Additional context:
Later fullUrl work changed how the older POST exception should be understood. FHIR-43106 was Applied for R6 and is already represented on the combined branch by 74c0b5c778; that reconciliation aligned bdl-15 and the Bundle notes with the current Bundle.entry.fullUrl definition, scoping omission of fullUrl to batch or transaction request/response entries that match the create, operation, search, or history exceptions. Current source still has bdl-15 attached to Bundle, Bundle.type, Bundle.entry, and Bundle.entry.fullUrl, and it requires fullUrl for Bundles that are not batch or transaction request/response Bundles.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The seed request has already been applied by bdl-15, and the current source is correct after the later FHIR-43106 refinement. Reintroducing the old POST-specific FHIR-28364 expression would conflict with the later applied fullUrl rule.

Recommendation:
Keep this audit commit as-is. Do not restore the original POST-only exception wording; use the current FHIR-43106-aligned Bundle.entry.fullUrl prose and bdl-15 invariant. If the work group wants machine enforcement of every granular batch/transaction entry exception, that should be handled as a separate FHIRPath design decision.
