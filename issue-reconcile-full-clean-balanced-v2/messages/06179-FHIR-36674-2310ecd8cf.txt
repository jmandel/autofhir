FHIR-36674: Align new patient search parameters

Issue request:
FHIR-36674 was Published/Persuasive for R5 and asked the search parameter registry to stop showing many separately named *-patient search parameters when they were the same cross-resource patient search concept, folding them into clinical-patient except for unrelated text such as wrong-patient.

Initial application:
The original application appears to be git commit 02267166956241cca648a944409aa70d9adce398, which expanded source/searchparameter/common-search-parameters.xml for clinical-date, clinical-code, clinical-encounter, clinical-identifier, and clinical-patient shortly after the FHIR-I vote. That commit did not cite FHIR-36674, but it matches the Jira comment that Grahame had merged the common search parameter registry entries. Later FHIR-37812 followed the same pattern by adding DeviceAssociation to clinical-patient rather than removing the resource-specific source SearchParameter file.

Additional context:
The registry generator keeps resource-specific SearchParameter definitions in their resource bundles, but suppresses aligned patient rows in the all-search-parameters registry when the resource base is listed under clinical-patient. Current fhir.ini still builds DeviceAlert and EnrollmentResponse and classifies both in the patient compartment. Their patient SearchParameters were added or changed after the original FHIR-36674 application, so the current build exposed DeviceAlert-patient and EnrollmentResponse-patient as the only real remaining *-patient registry rows outside clinical-patient.

AutoFHIR reconciliation:
This commit adds DeviceAlert and EnrollmentResponse as bases of source/searchparameter/common-search-parameters.xml clinical-patient. It intentionally leaves the resource-specific SearchParameter definitions in place, matching the existing build pattern used by FHIR-37812 and the current source generator.

Recommendation:
Keep this source fix. It is a narrow continuation of the already-applied registry alignment and should remove the two current patient-registry outliers without changing the individual resource search parameter definitions.
