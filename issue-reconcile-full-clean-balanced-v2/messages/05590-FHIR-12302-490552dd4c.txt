FHIR-12302: Audit SNOMED Description ID extension migration

Issue request:
FHIR-12302 was Published/Persuasive for DSTU2 in the Vocabulary work group. It asked for a standard extension for SNOMED Description IDs because several SNOMED CT jurisdictions needed to exchange description identifiers, with the final resolution to add the extension, reference it on the SNOMED CT page, and consider the paired FHIR-12217 request.

Initial application:
The request was applied in historical SVN/git commit e7180dea8444e0bc39f443e7306444ee80bb12c7, whose subject names both #12302 and #12217. That commit added an sctdescid row to source/datatypes/coding-extensions-spreadsheet.xml and referenced extension-coding-sctdescid.html from the then-current source/snomedct.html page.

Additional context:
The current FHIR-core checkout no longer owns the live coding-sctdescid StructureDefinition. Core commit dd468d4f1799dd79819315b211588ef1cf4586e0 removed the old extension spreadsheet row from R5 source, and source search now finds coding-sctdescid only in source/oids.ini while source/fhir.ini still points to the active coding extensions spreadsheet that no longer contains this row. Core commit 81e5862f203fdb8a03e9c943a7cf455aba8973f4 deleted the old SNOMED CT guidance page and left only the generated/local SNOMED CT usage report under the current terminology hierarchy. The authoritative current extension source is in HL7/fhir-extensions at input/definitions/datatypes/StructureDefinition-coding-sctdescid.xml, with the original Coding context plus later display/designation contexts. Later related issues FHIR-33058 and FHIR-40724 are already represented on the combined branch as external-repo audits for the same extension-pack migration, and FHIR-32065 rejected a generic non-SNOMED version of the extension.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR-core source change. The seed's requested extension exists in the Extension Pack, and the original core SNOMED CT page reference was applied historically but the page is no longer part of current core source. Re-adding the extension row or adding new core SNOMED guidance would either edit the wrong repository or create unapproved duplicate guidance.

Recommendation:
Keep this empty external-repo audit commit as-is. No FHIR-core follow-up is needed for FHIR-12302 unless the Extension Pack loses the coding-sctdescid definition; any future explanatory SNOMED CT guidance should be handled in the appropriate Extension Pack or terminology guidance source with work-group-approved wording.
