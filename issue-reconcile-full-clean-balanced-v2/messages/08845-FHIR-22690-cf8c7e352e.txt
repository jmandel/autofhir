FHIR-22690: Audit reference membership search

Issue request:
FHIR-22690 was Published/Persuasive with Modification for R5. It asked to define a Reference-search :in modifier so searches such as GET /Encounter?patient:in=Group/123 could match references whose targets are members of a specified Group or List, with enumerated Group membership preferred when a Group had both members and characteristics and characteristic-only Groups left to server support.

Initial application:
No commit message explicitly cites FHIR-22690. The request was implicitly applied in commit 652ee3df4866d4910bf9d0573677f5a5183cea45, which added in-modifier Reference semantics, List.entry.item and Group.member.entity language, and the Encounter?patient:in=Group/123 example to source/search.html. Later FHIR-37846 application in commits 3e70503739324804fad2ddfc1a424e1e6b4e6692, e6032af6c9cbf233e1a804e87310b81fb8937fe5, and ddecc63591d23dab5767aa2888c985a7c75964b6 removed the draft Reference :in modifier design and replaced it with the standard Resource-level _in search parameter.

Additional context:
The originating Zulip thread and 2019 FHIR-I minutes confirm the original motivation was clearer Group/List membership search for referenced resources. FHIR-23724, filed from the same discussion, clarified Group membership basis and is already represented on the combined branch. FHIR-37846 later superseded the syntax by replacing Reference :in with _in while retaining _list; it is also already represented on the combined branch by commit 410f08e1be763424d9b1528ff54d9c1c6efbf10a, which completed the current Resource-_in targets and _list note.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current source/search.html defines _in as a reference search parameter for active membership in CareTeam, Group, or List, includes the Encounter?patient._in=Group example that preserves the seed use case under the later approved syntax, and removes Reference-specific :in modifier prose. Current source/resource/bundle-Resource-search-params.xml defines Resource-_in as a reference SearchParameter over Resource.id with CareTeam, Group, and List targets, while source/searchparameter/codesystem-search-modifier-code.xml now limits the in modifier to token ValueSet membership.

Recommendation:
Keep this audit commit as-is. Do not reintroduce Reference :in; the seed request is satisfied by the later approved _in design and the current source already conveys the correct implementer behavior.
