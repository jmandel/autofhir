FHIR-31943: Audit POST search method support

Issue request:
FHIR-31943 was a Published/Not Persuasive with Modification FHIR-core issue asking to remove or relax the HTTP search requirement that servers supporting search also support POST-based search. The final FHIR-I decision kept core support for both GET and POST search, clarified that a server unable to process a specific search with the client-supplied method uses 405 Method Not Allowed, disallowed returning 405 for both methods, and requested method-choice, security, examples, and paging-link guidance.

Initial application:
No historical source-changing commit explicitly mentioning FHIR-31943 was found. The current wording appears to have been applied through same-family R5 search work: a8509373541feb0c553e8c86dfe2bdf0136efee7 introduced the GET/POST plus 405 conformance language on the Search page; 7415a1eb0824ba59d977db335205d71eed004312 added POST search examples; f47290bddbd45abf5ead98478c1796e50bb8ea83 added the 405 search error row and method-choice pointer; and e441170220c19e992f803667b245e63dcdd508cf moved HTTP-specific transport guidance from source/search.html to source/http.html.

Additional context:
The #implementers Search via POST Zulip thread linked from Jira shows why the old wording was confusing: implementers disagreed about whether GET and POST were required, how IGs could constrain them, whether POST is more secure, and how self/paging links should work after POST searches. FHIR-I minutes on 2021-10-18 record the Not Persuasive with Modification vote, and 2021-10-25 minutes record follow-up discussion retaining the sensitive-link SHOULD NOT and suggesting state/encoding strategies. Later related reconciliation commits already on the combined branch cover companion details: FHIR-31944 for POST URL/body parameter equivalence, FHIR-38994 for HTTP search method guidance, FHIR-39137 for the Search/HTTP page refactor, FHIR-35859 for POST examples, FHIR-36126 for conformance scoping, and FHIR-46649 for the self-link exception in sensitive URL guidance.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active REST (HTTP) page already states that HTTP search supports GET and POST and may return 405 for either method but not both; it provides POST and GET examples, discusses method-choice considerations, says neither GET nor POST is inherently more secure, and advises testing both methods. The active Search page already requires self and paging links to be expressed as GET requests and says paging URLs should not include sensitive content except for the self link. The HTTP paging section also describes GET follow-up paging and state-tracking parameters. Adding more prose would be redundant or would reopen choices already handled by related issues.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-31943 unless FHIR-I later changes the normative GET/POST search support model or asks for additional implementation-note examples beyond the existing state-tracking and sensitive-link guidance.
