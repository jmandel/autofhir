FHIR-34115: Remove stale Task title code guidance

Issue request:
FHIR-34115 is an Applied/Persuasive OO change request for R6 asking to remove the Task.code comment that said titles such as "My Tasks" or "Outstanding Tasks for Patient X" should go into Task.code, because those examples describe a list of tasks rather than the action code for an individual Task.

Initial application:
The Jira application linked commit 987f7bf6657edb8a306b805b21220647f399ac89, which removed that exact ElementDefinition.comment from source/task/structuredefinition-Task.xml. The current Task.code element definition no longer contains the rejected comment, so the explicit Jira-tagged application was partially successful.

Additional context:
Task is an active current-build resource in source/fhir.ini and is owned by OO. The active Task notes page still contained an older "Task Titles" section with the same examples and the same direction that a task title should go into Task.code, so the built Task page still conveyed the guidance the Jira decision rejected. OO minutes for 2024-04-16 record the Persuasive vote to make the requested change, and no conflicting Zulip or Confluence search result was found.

AutoFHIR reconciliation:
This commit removes the stale "Task Titles" section from source/task/task-notes.xml. It leaves the current Task.code definition and historical release archives untouched, because the StructureDefinition comment was already removed by the Jira-tagged commit and the remaining source change needed for the current build is the active narrative note.

Recommendation:
Keep this source fix as-is. It removes the remaining misleading current-spec guidance without adding replacement prose; any broader Task title modeling guidance should be a separate OO decision.
