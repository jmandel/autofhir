FHIR-13511: Audit address search parameter district coverage

Issue request:
FHIR-13511 was a Published/Persuasive STU3 correction for Patient, Person, Practitioner, and RelatedPerson. It observed that the shared address search parameter description and FHIRPath named Address line, city, state, country, postalCode, and text, but omitted Address.district even though district is also a string field; the accepted resolution was to include district in the definition.

Initial application:
The issue was applied by two historical commits: 5e16b9345c0 updated Patient, and 37ecf3c5e9e updated Person, Practitioner, and RelatedPerson. Those commits added Address.district to both the pre-R5 expression-style source and the generated SearchParameter descriptions for the affected active resource spreadsheets.

Additional context:
Patient, Person, Practitioner, and RelatedPerson are active resources in source/fhir.ini, so their spreadsheet SearchParameter blocks are current build inputs. Later technical correction FHIR-45300 replaced the explicit field-list FHIRPath expressions with whole-Address expressions for all four resources while keeping the district-inclusive description text. Later Patient-only FHIR-54876 deliberately replaced Patient's enumerated description with the broader approved text "An address in any kind of address/part of the patient". No Zulip or Confluence search found a conflicting community record for FHIR-13511.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current Person, Practitioner, and RelatedPerson address SearchParameter descriptions explicitly include district, and all four resources now use whole-address expressions that include Address.district by construction; Patient's different description is the result of a later Applied/Persuasive issue, not a missed FHIR-13511 application.

Recommendation:
Keep this audit commit as-is. Do not re-add an enumerated Patient description for FHIR-13511; that would conflict with FHIR-54876. Future cleanup, if desired, should be considered as a separate consistency issue for the remaining Person/Practitioner/RelatedPerson descriptions rather than as a FHIR-13511 fix.
