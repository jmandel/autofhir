FHIR-30379: Audit $status parameter clarification

Issue request:
FHIR-30379 is a Published/Persuasive R5 FHIR-I change request asking core Subscription $status documentation to match the R4 Backport clarification: distinguish resource-level and instance-level behavior for the id parameter, clarify multiple ids for GET/POST representations, and make clear that returning all caller-visible Subscriptions when ids are absent applies only to Subscription/$status, not Subscription/[id]/$status.

Initial application:
The current source has already been applied. Commit 17740f61cd imported the R4B/backport-style $status wording into source/subscription/operationdefinition-Subscription-status.xml, including id, status, and return-parameter clarifications. Commit f1da78150b explicitly tagged FHIR-30379 and refined the core wording for the id parameter, Subscription status code filter, and zero-or-more return semantics. No existing combined-branch Issue-Reconcile-Key commit for FHIR-30379 was found before this audit.

Additional context:
The Subscription and SubscriptionStatus resources are active build inputs in source/fhir.ini, and source/subscription/list-Subscription-operations.xml includes OperationDefinition/Subscription-status. FHIR-30378 is the R4 Backport counterpart named by the FHIR-30379 resolution, and the current published Backport page uses the same parameter semantics. R5 and current CI rendered core pages also show the clarified resource-vs-instance text. Later applied changes FHIR-47291 and FHIR-47292 adjusted the operation description and return guidance but did not reverse or weaken the id parameter clarification.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped OperationDefinition already states that the id parameter is ignored at the instance level, applies at the resource/type level, returns all available Subscriptions only when no resource-level ids are supplied, and joins multiple values as OR; that satisfies the applied FHIR-30379 clarification without duplicating representation-specific GET/POST prose.

Recommendation:
Keep this audit commit as-is. No follow-up core source change is needed for FHIR-30379 unless a future work-group decision wants the operation page to add explicit HTTP encoding examples beyond the existing operation parameter semantics.
