FHIR-44798: Audit vital signs scope update

Issue request:
FHIR-44798 is an Applied, Persuasive with Modification R6 OO change request for the Observation Vital Signs profiles. It asked the profile scope to state that Vital Signs profiles apply only to point-in-time observations, that calculated observations based on two or more point-in-time vital sign observations cannot derive from the Vital Signs profiles or reuse their point-in-time Observation.code interoperability-standard codes, and that those calculated vital-sign-related observations may still use Observation.category = "vital-signs". It also asked the VSCat category slice definition to cover both point-in-time and calculated vital-sign-related observations.

Initial application:
The source change appears to have been applied before this reconciliation. Commit f3c3f92af73f3bce459357d42046a42995902084, merged by PR #3786, added the two profile-content bullets and the VSCat definition while still using the older "magic code" phrase. Jira comments then clarified that "magic code" should be replaced with "Interoperability Standard" code; commits 6dc7cf647a89671924a0962486a93cc828c77e70 and 1382e8eeeab6201a66bf9871dcfe031286dd6862, merged by PR #3817, applied that wording correction.

Additional context:
The edited files are in current build scope: source/fhir.ini lists Observation as an active resource, and implementationguide-Observation-vitalsigns.xml includes observation-vitalsigns-profile-introduction.xml and StructureDefinition/vitalsigns plus the derived vital-sign profiles. The derived vital-sign profiles inherit from StructureDefinition/vitalsigns, so the single VSCat slice definition on the base profile is the authoritative source for the related component profiles. OO Confluence minutes record the 2025-10-09 block vote and the 2025-10-10 decision that replacing "magic codes" with "Interoperability Standard" codes did not change the disposition. No direct Zulip discussion for FHIR-44798 was found, and the current source has no remaining "magic code" wording in the Observation source.

No further core source edit is needed.
