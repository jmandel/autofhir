FHIR-6095 was Published/Persuasive for the DSTU1 core styleSensitive extension. It reported that saying systems must respect "style extensions" was ambiguous because the applicable style extensions were not enumerated, and the approved resolution was to update the description to explicitly reference the two style extensions that applied at the time.

Initial application:
The issue was applied historically in SVN revision 8901, imported as git commit 54bcc3f9ff4388f12f01ef009eb8790d7c01d7e2 with subject "#6095 - make extension implicit reference clear". Additional context:
Later rendering-extension work changed the applicable list and ownership. FHIR-17912 revised the same styleSensitive guidance to refer to style, markdown, and xhtml rendering extensions; FHIR-21225 later corrected those names to be real links; and FHIR-18097 addressed a typo in the same family of text. The R5 source cleanup in dd468d4f1799dd79819315b211588ef1cf4586e0 removed extension definitions from the core source, while source/history.html records that extensions moved to the hl7.fhir.uv.extensions package. Current core source retains only the rendering-styleSensitive OID and has no active styleSensitive row in the rendering-extensions spreadsheet. The current FHIR Extension Pack definition explicitly enumerates style, markdown, and xhtml in the description/comment.

AutoFHIR reconciliation:

Editing core source/oids.ini, historical/generated release material, or the active core rendering-extensions spreadsheet would not improve the current specification.

Recommendation:
Keep this no-change audit commit.
