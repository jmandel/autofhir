FHIR-18162: Audit MedicationKnowledge status semantics

Issue request:
FHIR-18162 was a Published/Not Persuasive with Modification Pharmacy change request raised and applied for STU3. It asked for MedicationKnowledge.status to be clarified because a compounded medication might contain active components even when the compounded medication itself is inactive. The final resolution said the status refers to the validity of the medication information, not the medication's medicinal properties, and retained the isModifier flag.

Initial application:
The issue was applied before this reconciliation. Git commit 3354519ea28bbb65a6e62edf130a5e6960559cca, merged as 9e4994a6be79c46b2bec5a8bbe5ba117684bbbee from MedicationKnowledge-GF18162, changed the MedicationKnowledge spreadsheet status wording from a bare active-use statement to include that status is about validity of the medication information and not medicinal properties. Later source refactors carried the element into source/medicationknowledge/structuredefinition-MedicationKnowledge.xml.

Additional context:
MedicationKnowledge is an active current-build resource in source/fhir.ini. Later same-family issue FHIR-28598 repeated the drug-database/inventory status cleanup and is already represented on the combined branch by a no-change audit commit. Later Pharmacy issue FHIR-32801 made MedicationKnowledge a MetadataResource and is already represented on the combined branch by a source fix that changed the authoritative MedicationKnowledge.status element to publication-status lifecycle semantics. The old MedicationKnowledge status terminology and generated-looking SVG still preserve pre-metadata wording, but the active StructureDefinition binding is publication-status and those surfaces are not a reason to reapply the old local inventory wording.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative status definition says it is the lifecycle status of the MedicationKnowledge content, not the medicinal properties of the medication, and it remains a modifier because retired MedicationKnowledge requires due consideration. Restoring the original drug-database/inventory wording would conflict with the later MetadataResource decision already reconciled on the combined branch.

Recommendation:
Keep this audit commit as-is. Do not restore the STU3/R4 inventory-status wording to MedicationKnowledge.status unless Pharmacy reopens the later MetadataResource decision. If generated diagrams or obsolete MedicationKnowledge status terminology are still emitted, handle that as a separate generation or terminology-retirement cleanup rather than as FHIR-18162.
