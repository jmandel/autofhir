FHIR-12769: Audit Observation event extensions

Issue request:
FHIR-12769 was a Published/Persuasive DSTU2 Orders and Observations change request to add Observation extensions based on Event workflow-pattern alignment as a follow-up to FHIR-10299. The Jira resolution confirmed Event pattern alignment and extension additions, while noting that partOf overlapped with Observation related/relationship modeling depending on value-set use.

Initial application:
The issue was applied historically. Commit 05be7755d3d221e2c0fa3cb2805bfe7afb4a4856 explicitly mentioned #12769 and added Event extension rows for Observation and DiagnosticReport, including instantiates/definition, partOf, performer role/function, on-behalf-of, reasonCode, and reasonReference rows. Later workflow cleanup commits changed those rows: b9bed92ed75e renamed definition to instantiates and removed performer/on-behalf-of rows during workflow mapping cleanup, GF#13838 follow-up restored the performer function concept under its current name, and later commits continued to adjust Event extension contexts.

Additional context:
Current core build scope has changed since DSTU2. source/fhir.ini still registers the event-pattern extension spreadsheet, but the current source/profiles/event-extensions-spreadsheet.xml Extensions worksheet is only a header after dd468d4f1799 removed extension definitions from R5 core source. The active Observation resource now carries core Event mappings for instantiates[x], basedOn, partOf, and note, and FHIR-14095 already audited the later elevation of event-partOf into core Observation.partOf. The remaining current extension definitions relevant to the old Observation rows live in the FHIR Extension Pack, including event-performerFunction on Observation.performer, workflow-reason on Observation, event-location on Observation, and the later event-statusReason/event-eventHistory Observation contexts. FHIR-10299 and FHIR-43456 are already represented by combined-branch audit commits and provide the broader and later Observation workflow context.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding the old Event extension rows to FHIR core would be wrong because core no longer owns those extension definitions, and current Observation/Extension Pack source already represents the applicable current semantics or later superseding decisions.

Recommendation:
Keep this no-change audit commit. Future changes to Observation workflow extensions should be made through current resource-specific tickets or the FHIR Extension Pack, not by restoring the old DSTU2 core event-extension spreadsheet rows.
