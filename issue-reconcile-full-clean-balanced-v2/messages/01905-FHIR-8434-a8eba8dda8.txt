FHIR-8434: Audit document content reference wording

Issue request:
FHIR-8434 was Published/Persuasive for the FHIR-core documents page. It objected that the document guidance could be read to require every resource referenced by Composition, including author, attester, custodian, and reference-valued extensions, to be included in a document Bundle. The final resolution was to trim the wording so the document rule listed the specific header reference elements rather than saying all Composition references, because extensions were not intended to be covered.

Initial application:
No Jira-tagged commit for FHIR-8434 was found. The Jira comment says the change was already done for another task. The same source area had already been changed by f5bac309 (#8026/FHIR-8026) to replace the unqualified "Any resource referenced directly in the Composition" wording with an explicit generated list of Composition reference elements. Current source/documents.html keeps that model with "Resources referenced by the Composition as listed below SHALL" followed by <%res-ref-list Composition%>.

Additional context:
The current rendered build expands the generated list to concrete base Composition elements such as Composition.subject, Composition.author, Composition.attester.party, Composition.custodian, Composition.section.focus, and Composition.section.entry; it does not make reference-valued extensions part of the SHALL. Later document-link wording, including FHIR-43295, clarified graph/reference mechanics but did not restore the overbroad extension interpretation. Zulip and Confluence searches found no conflicting community record for this issue or the relevant document-content terms.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped source already implements the accepted clarification by using a generated explicit Composition reference list, and the surrounding text only says indirectly referenced resources SHOULD also be included.

Recommendation:
Keep this audit commit as-is. If the work group wants to revisit whether header references such as author, attester, or custodian should be SHOULD rather than SHALL, that would be a new substantive policy decision beyond FHIR-8434's published resolution.
