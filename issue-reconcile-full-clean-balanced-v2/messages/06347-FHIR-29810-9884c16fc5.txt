FHIR-29810: Audit BodyStructure relative-location SNOMED codes

Issue request:
FHIR-29810 was Published/Persuasive for FHIR-core BodySite/BodyStructure, raised in R4 and applied for R5. It reported obsolete SNOMED CT concepts 419161000 Unilateral left and 419465000 Unilateral right in http://hl7.org/fhir/ValueSet/bodystructure-relative-location and asked to replace them, probably with 7771000 Left and 24028007 Right.

Initial application:
Jira comments identify pre-application commit 29e94a49e4772ffe4ef30d988217564ea948c7b7 and reapplication commit 35ef574d61ba4ab133fe86c61d4d88f964be3514. The first changed source/bodystructure/valueset-bodystructure-relative-location.xml from 419161000/419465000 to 7771000/24028007 with Left/Right displays; after an intervening FHIR-32889 commit briefly reintroduced the inactive concepts, 35ef574d61 corrected the same value set to 7771000 Left (qualifier value) and 24028007 Right (qualifier value).

Additional context:
BodyStructure is active in source/fhir.ini. Related FHIR-32889 and FHIR-23866 reconciliation commits are already present on the combined branch and cover the same inactive left/right SNOMED CT code family. Later Applied/Persuasive issue FHIR-45256 split laterality from general BodyStructure qualifier content for R6: BodyStructure.includedStructure.laterality is now bound to bodystructure-laterality, that value set contains 7771000 and 24028007, and bodystructure-relative-location no longer contains left/right laterality concepts at all. Direct FHIR-29810 Zulip and Confluence searches found no conflicting community evidence; a 2019 terminology Zulip thread had already noted the inactive codes and the distinction between laterality and relative location.
