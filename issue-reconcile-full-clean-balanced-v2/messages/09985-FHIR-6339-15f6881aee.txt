FHIR-6339: Audit pattern slicing guidance

Issue request:
FHIR-6339 was a Published/Persuasive with Modification FHIR-core change request from DSTU1 asking whether slicing discriminators were compatible with ElementDefinition pattern[x] constraints. The approved resolution was temporary: note, for the DSTU period, that pattern[x] was not recommended for discrimination until the issues were investigated.

Initial application:
The issue was applied by historical git-svn commit 63a62f03c95b6d77d7d13eb0b5794d6c5c4a2103, svn revision 5863, which updated source/profiling.html to say that only fixed values or required value set bindings should be used for slicing and that ElementDefinition.pattern[x] was not recommended as a slicing basis while the issue was investigated. That temporary caution was later removed by the FHIR-12618/FHIR-12641 discriminator rework in 3253654af7787e9b738b15f4618a2b9d02d56f7f.

Additional context:
Later final FHIR-I decisions answered the deferred DSTU question in the opposite direction from the temporary caution. FHIR-13672 explicitly allowed pattern[x] in ElementDefinition for discriminators, and FHIR-25206 merged the value and pattern discriminator behaviors by deprecating the pattern discriminator type while documenting that value discrimination can use fixed values, pattern values, or required value set bindings. The linked Zulip threads and FHIR-I minutes for FHIR-25206 show the work group considered the pattern/fixed/value set distinction and chose that merged rule. The current build-scoped profiling and ElementDefinition sources reflect this: value discrimination lists fixed, pattern, and required binding; pattern is retained as equivalent/backwards-compatible and deprecated; and pattern examples are linked from the profiling page.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Reinstating the DSTU-era warning from FHIR-6339 would contradict the later Published decisions and the current conformance model. The current source already resolves the original compatibility question by allowing pattern[x] where it provides non-overlapping discriminator values.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed for FHIR-6339; any future change to pattern-based discrimination should be handled as a new FHIR-I decision rather than by restoring the superseded DSTU caution.
