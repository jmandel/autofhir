FHIR-13901: Use searchParam in medication filter examples

Issue request:
FHIR-13901 was a Published/Persuasive with Modification FHIR-core STU3 issue for DataRequirement. It asked to clarify that codeFilter.path and dateFilter.path do not silently traverse references, requiring constrained FHIRPath paths that are resolvable on the DataRequirement type, adding codeFilter/dateFilter searchParam 0..1, and requiring each filter to provide either path or searchParam with searchParam naming a defined SearchParameter for the DataRequirement type.

Initial application:
The issue was explicitly applied by SVN/git commit 74161b7e2037bc36b915e2d57d02743cc607ad3f, "GF#13593 - clarify datarequirements.mustSupport and GF#13901 - clarify DataRequirements filters". That commit added the constrained FHIRPath wording, codeFilter.searchParam/dateFilter.searchParam, and path/searchParam invariants to source/datatypes/datarequirement.xml. The active current source still contains those structural and definitional changes, but the CMS146 $data-requirements examples that predated the issue continued to use codeFilter.path="medication.code" for MedicationRequest and MedicationStatement.

Additional context:
source/fhir.ini keeps DataRequirement active and normative and keeps Library and Measure as active resources, so the edited Library/Measure examples feed the current build. In the current resource definitions, MedicationRequest.medication and MedicationStatement.medication are CodeableReference elements; the defined token SearchParameters named code on both resources point at medication.concept. Using codeFilter.searchParam="code" therefore expresses the medication code filter through the mechanism approved by FHIR-13901 without relying on implicit reference traversal. FHIR-13718, FHIR-13593, and FHIR-32373 are related DataRequirement filter/history issues already represented on the combined branch and are not re-decided here. Targeted Jira/Zulip/Confluence searches found no later conflicting final decision.

AutoFHIR reconciliation:
Updated the active CMS146 data-requirements examples in source/library/cms146_data_requirements.json, source/measure/cms146_data_requirements.json, and the corresponding Library example body/narrative in source/library/library-cms146-example.xml so the MedicationRequest and MedicationStatement medication code filters use searchParam="code" instead of the stale implicit traversal path medication.code.

Recommendation:
Keep this source-changing commit. It completes the remaining visible example correction for FHIR-13901 while preserving the already-applied DataRequirement datatype definitions; any future change to broaden or narrow the compatible type lists for DataRequirement filters should be handled as a separate work-group decision.
