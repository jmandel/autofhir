FHIR-11239: Audit retired Sequence window-start clarification

Issue request:
FHIR-11239 was a Published/Persuasive Clinical Genomics change request for the DSTU2 FHIR-core Sequence resource. It asked to clarify the Sequence.referenceSeq.windowStart wording so the start position was not tied to only one coordinate convention: if the coordinate system is either 0-based or 1-based, the start position is inclusive. The final resolution accepted the proposed wording for the Sequence.referenceSeq.windowStart target.

Initial application:
The historical application was commit d830ddede2fa70d5f6ccca85e723caa4a2c7a7bf, "#11235 #11236 #11239 #11240 Change description related with Sequence.coordinateSystem to be more accurate." It changed source/sequence/sequence-spreadsheet.sheet.txt and source/sequence/sequence-spreadsheet.xml so Sequence.referenceSeq.windowStart says "Start position of the window on the reference sequence" and defines both 0-based and 1-based starts as inclusive. The same commit applied the paired FHIR-11240 end-coordinate clarification and related coordinate-system wording.

Additional context:
The original Sequence source path is no longer present in the current build. Sequence is listed as a removed resource in source/fhir.ini, molecularsequence is commented out, and moleculardefinition is the active Clinical Genomics resource. Later R6 decisions replaced MolecularSequence with MolecularDefinition; current MolecularDefinition uses a different coordinateInterval model with CodeableConcept coordinate-system examples such as 1-based character counting and 0-based interval counting, not the old Sequence.referenceSeq.windowStart element. Historical release3 artifacts preserve the applied Sequence wording, while current source has no active Sequence.referenceSeq.windowStart target to edit.

AutoFHIR reconciliation:
This commit intentionally makes no source change. FHIR-11239 was applied to the then-current Sequence source, and the current build no longer exposes the affected Sequence element. Copying the old referenceSeq.windowStart prose into MolecularDefinition would be a model-porting change, not a reconciliation of the published DSTU2 Sequence clarification.

Recommendation:
Keep this audit commit as-is. No current FHIR-core source follow-up is needed for FHIR-11239; if implementers find ambiguity in MolecularDefinition coordinateInterval start/end semantics, handle it as a new MolecularDefinition-specific Clinical Genomics issue rather than resurrecting retired Sequence wording.
