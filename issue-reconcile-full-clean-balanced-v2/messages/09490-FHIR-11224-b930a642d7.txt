FHIR-11224: Audit inherited fields in tree views

Issue request:
FHIR-11224 was Published with a Persuasive with Modification resolution for the DSTU2 ValueSet page. The reporter expected ValueSet.id to appear in the resource representations; the accepted resolution was not to make a ValueSet-specific change, but to reduce general confusion by showing inherited Resource/DomainResource fields at the top of tree views, similar to XML and JSON views.

Initial application:
The Jira comments record an SVN application note, but the cited revision number maps in local git history to unrelated Task changes. The directly relevant 2017-02-26 git-svn commit is 704ad94007bf29524c4d248945ecebae4bb8f957, which added XML/JSON templates and made inherited elements explicit by adding the "Elements defined in Ancestors" table text to the structure table generator.

Additional context:
ValueSet is an active current resource in source/fhir.ini and its authoritative StructureDefinition source is a differential specialization, so inherited fields are expected to be supplied by the base definitions and renderer rather than duplicated as ValueSet-specific elements. The current CI-rendered ValueSet Structure tab lists inherited ancestor elements including id, meta, implicitRules, language, text, contained, extension, and modifierExtension. No Zulip or Confluence evidence was found that changes or reverses this application.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current specification already conveys the requested clarification in the ValueSet tree view, and adding ValueSet.id to the ValueSet differential would be semantically wrong because id remains inherited from Resource.

Recommendation:
Keep this audit commit as-is. No FHIR source follow-up is needed for FHIR-11224 unless the rendering machinery later stops displaying inherited ancestor elements in resource tree views.
