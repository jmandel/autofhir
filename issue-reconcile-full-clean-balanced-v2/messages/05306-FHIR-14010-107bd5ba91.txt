FHIR-14010: Audit SNOMED ECL implicit value set query

Issue request:
FHIR-14010 was Published/Persuasive for STU3. It asked to add a fifth SNOMED CT implicit value set query value for Expression Constraint Language queries, corrected in comments to the form ?fhir_vs=ecl/{expression}, where the expression is URI encoded. The final resolution agreed to add the syntax documented by SNOMED International.

Initial application:
The issue was pre-applied in SVN r12747, now git commit 5557727253b532ee80752365259b8a112524f386. That commit changed source/snomedct.html from four to five SNOMED CT implicit value set query forms and added an ECL template using the constraint filter, but the initial form used ?fhir_vs=ecl:[ecl]. The tightly related FHIR-14006/FHIR-14359 correction in git commit 9fe99d788004f20048165682a9ff7d64bc23c01d updated the historical source to ?fhir_vs=ecl/[ecl] and fixed the ECL template URL, name, and description.

Additional context:
FHIR-14006 is the same change family and records the full proposed ECL implicit ValueSet URI/template. FHIR-14359 corrected the separator to match existing implicit URI formats and is already represented on the combined branch by commit ad4f9523d27a3c8343fda97ff57ee40e38418095. FHIR-35933 later removed the old source/snomedct.html external terminology detail page from the current FHIR core build and changed source/terminologies-systems.html to link to THO's Using SNOMED CT with HL7 Standards page; source/hierarchy.xml now includes only the local SNOMED CT Usage Report under Code Systems. The current THO SNOMED CT page linked from core, https://terminology.hl7.org/en/SNOMEDCT.html, documents the five implicit value set query forms including ?fhir_vs=ecl/[ecl] and the matching ECL template. Direct Zulip and Confluence searches for FHIR-14010 found no conflicting community record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The historical core source applied the requested ECL query form, the later syntax correction is already accounted for, and the current FHIR core source no longer owns the detailed SNOMED CT implicit value set page; it correctly delegates external terminology guidance to THO, where the requested ECL syntax is present.

Recommendation:
Keep this no-change audit commit as-is. No FHIR core source follow-up is needed for FHIR-14010. Future maintenance of the SNOMED CT implicit value set wording should be handled in the THO/UTG source that produces terminology.hl7.org/SNOMEDCT.html, not by restoring the removed core page.
