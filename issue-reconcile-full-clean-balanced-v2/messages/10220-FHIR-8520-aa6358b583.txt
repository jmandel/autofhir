FHIR-8520: Audit duplicate profile id checks

Issue request:
FHIR-8520 was a Published/Persuasive FHIR-core change request from DSTU1 asking the build to fail when two profiles use the same id, instead of silently letting one profile overwrite another.

Initial application:
The Jira comment records svn revision 6157. In the git-svn history, commit 389772eae769faca08a64c0a2e1f5bc3067d95b1 applied that revision as "#8520 - check uniqueness on value set, code system and profile urls", adding duplicate pack/profile/resource-url checks to the then in-repository Java build tooling.

Additional context:
The old in-repository Java publisher code that received the 2015 fix was removed by 9f549566d1346cad7db6d2afca6080d7cebdfbbe when the FHIR build switched to the external kindling Gradle dependency. The current build.gradle.kts and gradle.properties use org.hl7.fhir:kindling:1.25.5-SNAPSHOT, and the active profile package entries remain build-scoped through source/fhir.ini. The current kindling SourceParser and OldSpreadsheetParser still raise errors for duplicate pack ids and duplicate profile names, and javap against the cached kindling jar confirmed those duplicate-check constants are present in the dependency used by this checkout.

AutoFHIR reconciliation:
No source change was made. The current build path already implements the requested fail-fast duplicate profile/pack id behavior, and the source location that originally changed for FHIR-8520 is no longer maintained in this repository.

Recommendation:
Keep this no-change audit commit as-is. If duplicate profile id behavior regresses, the follow-up should target the kindling publisher dependency or its version pin, not retired in-repository Java tooling.
