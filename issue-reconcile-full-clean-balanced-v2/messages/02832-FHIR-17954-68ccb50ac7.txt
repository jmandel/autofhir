FHIR-17954: Align CoverageEligibilityRequest priority binding

Issue request:
FHIR-17954 was a Published/Persuasive with Modification Financial Management change request for the STU3 CERq/EligibilityRequest artifact asking to change the .priority binding strength to extensible; its resolution also said to change the priority-code binding to extensible where it appears on other financial resources.

Initial application:
The large GF#17954 batch commit f369c813fb touched the then-current coverage eligibility request spreadsheet, but the ProcessPriority binding row still had conformance "example". The later source rework 33b409a4b6 made source/coverageeligibilityrequest/structuredefinition-CoverageEligibilityRequest.xml the active current source and preserved the example binding strength.

Additional context:
EligibilityRequest is no longer an active current-build resource; source/fhir.ini maps it to active CoverageEligibilityRequest. Parallel active ProcessPriority bindings on Claim.priority and ExplanationOfBenefit.priority were changed by FHIR-49886 from example to extensible, then superseded by FHIR-53057 and commit 149e073856, which changed them to preferred under the R6 FM decision that base FM bindings should not go beyond preferred.

AutoFHIR reconciliation:
Updated the active CoverageEligibilityRequest StructureDefinition so CoverageEligibilityRequest.priority now uses a preferred ProcessPriority binding. This strengthens the stale example binding as requested by FHIR-17954 while honoring the later R6 FM preference cap rather than reintroducing an extensible base binding. Retired EligibilityRequest spreadsheet content and generated-looking SVG artifacts were intentionally left unchanged.

Recommendation:
Keep this source fix as-is. It completes the remaining current-build gap for FHIR-17954 and aligns CoverageEligibilityRequest.priority with the later Claim and ExplanationOfBenefit priority binding policy; no follow-up is needed unless FM later chooses to revisit CoverageEligibilityRequest specifically.
