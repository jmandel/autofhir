FHIR-13935: Audit MedicationRequest intent options

Issue request:
FHIR-13935 was a Published/Persuasive STU3 Pharmacy issue asking for MedicationRequest and CommunicationRequest intent options to be as comprehensive as other request resources, with the submitter specifically needing order, original-order, and instance-order for medication order workflows.

Initial application:
The issue was explicitly applied in git 73c779d3aeb5, whose commit message says "TR# 13935 (updated MedicationRequest.intent valueset)" and whose MedicationRequest spreadsheet patch added original-order to the MedicationRequest.intent short/value-set content while retaining order and instance-order. That application was scoped to the Pharmacy/MedicationPrescription artifact, which is now MedicationRequest.

Additional context:
source/fhir.ini lists medicationrequest as an active resource and records that MedicationPrescription became MedicationRequest. Current MedicationRequest.intent remains a 1..1 required code bound to http://hl7.org/fhir/ValueSet/medicationrequest-intent, whose complete CodeSystem includes proposal, plan, order, original-order, reflex-order, filler-order, instance-order, and option. Later FHIR-13999, already published on the combined branch, corrected the MedicationRequest-specific hierarchy so instance-order is a direct child of order. The CommunicationRequest part of the original submitter's wording was split to FHIR-13936 and resolved No Change at the time; later Published FHIR-27153 added CommunicationRequest.intent with required request-intent binding and is already audited on the combined branch. The NutritionOrder follow-up was split to FHIR-14414 and is present in current source.

AutoFHIR reconciliation:
No source files were changed. The current active MedicationRequest source already supports the requested medication order intents, including the specific original-order and instance-order use cases, and separate final trackers account for the CommunicationRequest and NutritionOrder surfaces.

Recommendation:
Keep this empty audit commit as-is. Do not change MedicationRequest to the generic request-intent ValueSet solely for this issue; the current MedicationRequest-specific normative CodeSystem preserves Pharmacy-approved wording while covering the requested workflow codes.
