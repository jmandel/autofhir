FHIR-27941: Audit SupplyRequest scope relocation

Issue request:
FHIR-27941 was Published/Persuasive with Modification for R5. It asked OO to clarify that DeviceRequest is the clinical request for a device used by or for a patient, while SupplyRequest is an inventory/logistics request, with Medication allowed as a SupplyRequest item for floor-stock style replenishment.

Initial application:
No Jira-tagged FHIR-27941 source commit was found. The related FHIR-24936 commit adjusted DeviceRequest and SupplyRequest descriptions and boundaries, including a non-patient-specific SupplyRequest description and a DeviceRequest patient-specific description. Later commits added the current SupplyRequest logistics wording, removed the R5 ballot question about combining SupplyRequest and DeviceRequest, and added SupplyRequest.deliverFor under FHIR-39511.

Additional context:
SupplyRequest is no longer an active resource in the current core build: source/fhir.ini no longer contains an active supplyrequest=SupplyRequest entry after the 2025 commit that removed OO resources and pointed to the OO Incubator. The active core DeviceRequest source still states that DeviceRequest is for use/allocation of a device by a patient. The current OO Incubator SupplyRequest JSON is now the live external surface for SupplyRequest; it still carries the migrated SupplyRequest definitions, so any further cleanup of SupplyRequest wording belongs in HL7/oo-incubator rather than this core checkout.

AutoFHIR reconciliation:
Published an empty external-repo audit commit. No core source was changed because editing source/supplyrequest would modify an out-of-build copy, and the active core DeviceRequest wording already preserves the patient-focused side of the FHIR-27941 boundary.

Recommendation:
Keep this audit commit as-is for core. If OO wants to reconcile the remaining SupplyRequest wording with the later FHIR-39511 deliverFor semantics, do that in the OO Incubator source; do not patch the inactive core SupplyRequest files.
