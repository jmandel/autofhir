FHIR-20003: Audit Patient name search wording

Issue request:
FHIR-20003 was a Published FHIR-core Patient change request with Persuasive with Modification resolution. It asked that the Patient:name search parameter description use "given" instead of "give" and remove the duplicate "suffix" term from the HumanName field list.

Initial application:
No git commit explicitly mentioning FHIR-20003 was found for the Patient search-parameter source. The Patient search-parameter bundle was initially imported with the old wording, and commit e6a9a72025eeda3b1b5e3ee29af2c350f5809762, nominally for FHIR-25446, changed Patient-name to "family, given, prefix, suffix, and/or text" while also fixing the Patient deceased search-parameter typo.

Additional context:
Patient is an active current-build resource in source/fhir.ini, so source/patient/bundle-Patient-search-params.xml is in build scope. PA minutes from 2022-03-02 record FHIR-20003 as already voted and needing only update/closure because the change had been applied. Later FHIR-39454, another core Patient-name typo report, was resolved No Change because the fix was already applied in R5. A bounded source search found the same typo in parallel non-Patient HumanName search parameter descriptions and an HTML source comment, but those artifacts are outside this Patient-specific Jira decision and were not changed under FHIR-20003.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Patient-name SearchParameter description already says "family, given, prefix, suffix, and/or text", preserving the approved correction with one suffix occurrence.

Recommendation:
Keep this audit commit as-is for FHIR-20003. If PA wants the same editorial cleanup applied to Person, Practitioner, or RelatedPerson core search parameters, handle that as a separate tightly scoped tracker rather than broadening this Patient-specific reconciliation.
