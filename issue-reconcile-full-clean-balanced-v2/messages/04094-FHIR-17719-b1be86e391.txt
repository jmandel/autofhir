FHIR-17719: Audit invalid UCUM code correction

Issue request:
FHIR-17719 was a Published/Persuasive Vocab STU3 correction asking to fix the invalid UCUM unit reported as mmol/kg[H20]. The approved resolution was to use mmol/kg{H2O} instead, because H2O is an annotation for kilograms of water rather than a square-bracket UCUM unit atom following kg.

Initial application:
The issue was applied in git commit 00cae9abb1 (GF#17719 - fix ucum code), which changed source/valueset/valueset-ucum-common.xml from mmol/kg{H20} to mmol/kg{H2O} and retained a comment noting that the original mmol/kg[H20] form was invalid. No prior Issue-Reconcile-Key: FHIR-17719 commit was present on the combined branch.

Additional context:
The current source no longer contains mmol/kg[H20], mmol/kg{H20}, or mmol/kg{H2O}. The all-UCUM ValueSet source at source/datatypes/valueset-ucum-units.xml includes the UCUM code system rather than enumerating local concepts, and the active ucum-common example ValueSet is in build scope through the active ValueSet resource and source/valueset/list-ValueSet-examples.xml. Later Published issue FHIR-36012 deliberately removed all curly-brace comments from ucum-units and ucum-common and deduplicated resulting codes, so re-adding mmol/kg{H2O} would contradict later approved cleanup. The remaining H2O square-bracket units in ucum-common are length-derived water-column units such as cm[H2O], which are outside the FHIR-17719 problem.

AutoFHIR reconciliation:
This commit makes no source change. The original invalid code was historically corrected, and later source normalization validly removed the curly-brace annotation form from the current common UCUM value set.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-17719; any future desire to represent kilogram-of-water-specific units in ucum-common should be handled as a new Vocab/MnM terminology decision because FHIR-36012 changed the current policy for annotated UCUM codes.
