FHIR-13921: Audit $everything update-mode documentation

Issue request:
FHIR-13921 was a Published FHIR-core change request with resolution Persuasive with Modification. It asked that $everything explicitly document the periodic-update use case where a client asks for information changed since the last query using record timestamp semantics, and that the result be consistent with bulk data guidance.

Initial application:
The historical application appears in git commit fe1ee3d74919f92c159a423dd4014bac7bc9ebcd / SVN r14118, whose subject is "GF#13921 - Add note to $everything about periodic queries". That commit added the _since parameter and explanatory periodic-query text to the then-current Patient, Encounter, and Group $everything spreadsheet sources. Current core source still carries the resulting guidance on Group/$everything, including start/end care-date parameters, _since as record-time change selection, and _type for resource-type restriction.

Additional context:
The current build no longer contains Patient/Encounter/EpisodeOfCare $everything OperationDefinition source files: their resource operation lists do not reference them, current narrative points to the PA admin-incubator operation pages, and commit b487fdda4b removed those operation definitions from core. Later PA trackers FHIR-43373, FHIR-44604, and FHIR-44816 updated related Patient/Encounter/EpisodeOfCare $everything wording for provenance, paging, ordering, and synchronization, but they do not reverse the FHIR-13921 _since/update-mode semantics. No directly relevant Zulip or Confluence evidence was found.
