FHIR-36796: Audit R4B R3/R4 maps limitation

Issue request:
FHIR-36796 was a Published FHIR-core R4B change request for the FHIR-core-r3maps page. It asked to update the R3/R4 maps page for R4B changes; the final Not Persuasive with Modification resolution said not to update the maps themselves, because R4B either did not change existing resources or changed low-use resources radically, and instead to document limitations of interversion mapping.

Initial application:
The R4B branch contains commit 670aa69262, "Add R4/R4B documentation", which added an R4B note to source/r3maps.html explaining that the transforms are between R3 and R4, not R4 and R4B, and that no R4-to-R4B conversions are offered. The published R4B r3maps page includes that note, so the requested R4B publication change was applied there.

Additional context:
The current build no longer publishes r3maps.html; build.fhir.org/r3maps.html returns 404, while source/hierarchy.xml and source/documentation.html expose r4maps.html as the active current version-transforms page. The active r4maps page already says the current maps are not authoritative, cover resources that were in R4 or R4B, and point to the conversion registry. A related Zulip thread only shows pre-resolution community interest in fixing R3/R4 maps during R4B, and no direct conflicting Zulip evidence was found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Restoring the old R4B note to the dormant current-source r3maps.html would not affect the current built specification, and the authoritative R4B publication already carries the limitation text requested by the issue.

Recommendation:
Keep this no-change audit as-is. If the current build ever reintroduces an R3/R4 maps page, copy or re-evaluate the R4B limitation from the published R4B page at that time; no current core-source change is needed for FHIR-36796.
