FHIR-7925: Audit OperationOutcome return preference clarification

Issue request:
FHIR-7925 was Published with a Persuasive with Modification resolution for the FHIR-core HTTP page. It asked for clarification of ambiguous wording that said successful create/update responses could include an OperationOutcome with hints and warnings but no errors, including how resources and OperationOutcome resources could both be returned.

Initial application:
The Jira resolution points to SVN revision 5346. In the git mirror, commit b9c12da264d64a19244377f6c12b69b27ce5ac8b implements that revision, removing the old update/create OperationOutcome wording, adding return-preference guidance, clarifying that failures should return an OperationOutcome body, and moving the rejecting-updates guidance next to update behavior.

Additional context:
FHIR-7984 is the same 2015May HTTP wording family and specifically asked whether the removed update wording prohibited OperationOutcome.issue.severity = error; its Jira comment says the language had been removed. FHIR-12815 later handled a similar but separate search-success ambiguity. FHIR-27840 later clarified OperationOutcome issue severity/code relationships and is already represented on the combined branch.

AutoFHIR reconciliation:
No source change was made. The current active HTTP source says Prefer: return=OperationOutcome applies only to successful interactions, while failed interactions should return an OperationOutcome body; the rejecting-updates section also describes error responses and OperationOutcome detail. This preserves the SVN 5346 clarification without duplicating prose.

Recommendation:
Keep this empty audit commit as-is. Further changes would be redundant unless the work group wants to reopen the broader return-preference model or the separate search-response wording.
