FHIR-33065: Audit StructureDefinition.type logical model URL wording

Issue request:
FHIR-33065 was a Published FHIR-core StructureDefinition change request, resolved Persuasive with Modification for R5, asking to clarify that StructureDefinition.type for logical models SHALL be a fully specified URL and that the type name should start with the final path segment of that URL where required.

Initial application:
The issue was applied before this reconciliation by git commit 6ad3e66b264b665f9b5b20e93f319ecf7ced6e64 ("Apply FHIR-33065"), later merged by 1d769fe82f752181812e20765024fa913f1e8e35. That commit changed the StructureDefinition.type comment from "where the type is a URL" and "tail of the type URL" to the resolved SHALL/fully specified URL/final path segment wording.

Additional context:
The active build includes StructureDefinition as a resource in source/fhir.ini, and the current source/structuredefinition/structuredefinition-StructureDefinition.xml still carries the resolved wording. The initiating Zulip thread records the ambiguity and Grahame Grieve's answer that absolute URLs are required for non-HL7 logical models, and the FHIR-I 2021-08-30 minutes record the 16-0-1 Persuasive with Modification vote to use "fully specified URL" and explain the URL tail. FHIR-13331 is historical background: it introduced the earlier logical-model URL wording that FHIR-33065 clarified.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active StructureDefinition.type definition/comment already conveys the FHIR-33065 requirement, including "where the type SHALL be a fully specified URL" and the final path segment example.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed for FHIR-33065 unless a future work-group decision changes the logical-model StructureDefinition.type rule.
