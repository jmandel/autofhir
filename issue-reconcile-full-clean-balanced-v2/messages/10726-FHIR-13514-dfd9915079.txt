FHIR-13514: Audit StructureDefinition id constraints

Issue request:
FHIR-13514 was a Published, Persuasive with Modification STU3 change request for the StructureDefinition schematron. It reported that sdf-16 and sdf-17 said element ids must be unique while their XPath only checked that elements had ids, and the final resolution required fixing the XPath and adding a FHIRPath requirement that ids exist.

Initial application:
The issue was applied by git-svn commit e198be1ad40c0e3534d58cf314bea2d112d61573, svn revision 12865, on 2017-12-18. That commit changed the StructureDefinition spreadsheet source so sdf-16 and sdf-17 used snapshot/differential-specific XPath with distinct-values(), and changed the FHIRPath expressions to require ids before checking isDistinct().

Additional context:
StructureDefinition is active in the current build through source/fhir.ini with StructureDefinition=sdf. The current authoritative XML no longer uses the old spreadsheet source or checked-in schematron XPath: sdf-16 is snapshot.element.all(id.exists()) and snapshot.element.id.trace('ids').isDistinct(), sdf-17 is the matching differential expression, and sdf-14 separately requires ids on both snapshot and differential elements. Commit 88a1f3d6bd60f7618ae140179b008ac5686e8a08 intentionally removed XPath constraints from StructureDefinition in 2022, including the corrected sdf-16/sdf-17 XPath from FHIR-13514. A 2023 Zulip FHIRPath thread also describes the current sdf-16/sdf-17 rules as enforcing both id existence and uniqueness.

AutoFHIR reconciliation:
No source change was made. The current active source preserves the semantic fix requested by FHIR-13514 in FHIRPath form, while reintroducing or editing schematron/XPath source would be out of date for the current build.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed unless the work group decides to reintroduce checked-in schematron/XPath artifacts.
