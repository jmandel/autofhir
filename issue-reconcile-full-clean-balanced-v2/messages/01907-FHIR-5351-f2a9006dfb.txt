FHIR-5351: Audit Immunization refusal reason rename

Issue request:
FHIR-5351 is a Published/Persuasive DSTU1 ballot comment for FHIR-core Immunization and ImmunizationRecommendation asking to replace the Immunization refusal-specific element name refusalReason with the more general reasonNotGiven. Its Jira resolution says this request is a duplication of FHIR-3762.

Initial application:
The duplicate target FHIR-3762 was Published/Persuasive with Modification and approved renaming refusedIndicator to wasNotGiven and refusalReason to reasonNotGiven, while leaving the value set name unchanged and adding related invariants by reference to FHIR-3758. The source application was commit 64fbbf28ef27948a7944954073c8df878bac2bc9, whose subject explicitly included both #3762 and #5351 and changed the Immunization spreadsheet and refused example from refusalReason/refusedIndicator to reasonNotGiven/wasNotGiven.

Additional context:
Later R4 Immunization workflow alignment superseded the DSTU1 not-given element names. Commit 4c5a8902abffdfb5b6e9f07b4bca119d875dc64a replaced the refused example's completed + notGiven representation with status not-done, and commit f451f3fc4b093f23541fadb82141a50def0e1cc5 added Immunization.statusReason for the not-done reason. FHIR-9073 records the same final context: R4 removed notGiven/notTaken and added not-done, leaving no old two-element relationship to clarify. FHIR-54325 later refined the current statusReason wording and invariant for not-done or entered-in-error. The current combined-branch source actively includes Immunization in source/fhir.ini, has no active Immunization.refusalReason, Immunization.reasonNotGiven, Immunization.refusedIndicator, wasNotGiven, notGiven, or notTaken element definitions, and represents non-administration reasons with Immunization.statusReason. No current build-scoped ImmunizationRecommendation source remains for this DSTU1 artifact reference.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because FHIR-5351's requested generalization was applied through its duplicate target and the current specification has since moved to the correct status/statusReason model without retaining the misleading refusalReason element.

Recommendation:
Keep this audit commit as-is. Future Immunization non-administration wording should be handled under the current statusReason/status model, not by restoring the retired DSTU1 reasonNotGiven element name.
