FHIR-24887: Audit ConceptMap binding extension ownership

Issue request:
FHIR-24887 was Published/Persuasive for R5 and asked for a reusable extension, similar to 11179-permitted-value-conceptmap, that lets an ElementDefinition binding point to one or more ConceptMaps relevant to local terminology mappings.

Initial application:
The issue was applied in core by commit 0433e4161c3995fbc6c8709715d560d54fb59ad2, which added a conceptmap extension row to source/datatypes/elementdefinition-extensions-spreadsheet.xml with StructureDefinition snapshot/differential binding valueSet contexts, 0..* cardinality, canonical(ConceptMap) value type, and matching description text. A later core refactor/removal commit, dd468d4f1799dd79819315b211588ef1cf4586e0, removed this and other extension definitions from the R5 core source.

Additional context:
Current core source no longer contains the elementdefinition-conceptmap definition, aside from the retained OID registration in source/oids.ini. The FHIR Extension Pack source now contains the active authoritative StructureDefinition at input/definitions/multiple/StructureDefinition-elementdefinition-conceptmap.xml, and the Extension Pack IG states that globally defined extensions were moved out of the core specification starting with R5 so they can be updated independently.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The requested extension exists in the Extension Pack with the requested 0..* cardinality, binding valueSet contexts, and canonical ConceptMap value type, so re-adding it to core would duplicate content that is now owned outside this checkout.

Recommendation:
Keep this audit commit as-is. Future changes to this extension should be made in the FHIR Extension Pack, not in core FHIR, unless the work group changes extension ownership policy.
