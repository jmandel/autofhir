FHIR-12974: Audit patient birthPlace extension rename

Issue request:
FHIR-12974 was a Published/Persuasive PA change request from DSTU2 asking that the Patient birthPlace extension URL be changed from http://hl7.org/fhir/StructureDefinition/birthPlace to the patient-prefixed form used by other Patient standard extensions.

Initial application:
The requested change was applied in git commit e2e7e918b0d131eb5f933729c2eca6935a2392af, whose subject is "GF#12974 move patient-birthPlace extension" and whose patch moved the extension into the Patient extension spreadsheet with a note that it had been moved from a general non-patient-prefixed extension. Later R4/R4B generated/history artifacts and the R4B-era source carried http://hl7.org/fhir/StructureDefinition/patient-birthPlace.

Additional context:
Current core no longer owns the extension definition: commit dd468d4f1799dd79819315b211588ef1cf4586e0 removed R5 extension definitions from core, and the FHIR Extension Pack now contains input/definitions/Patient/StructureDefinition-patient-birthPlace.xml with id, canonical URL, and fixedUri all using patient-birthPlace. Current core references outside release/history material also use patient-birthPlace, and no active core source reference to the old StructureDefinition/birthPlace canonical was found. Later Jira FHIR-45141 is an AU Core out-of-scope naming issue that points similar feedback to the Extension Pack; it does not create a current FHIR-core source change for this seed.

AutoFHIR reconciliation:
This is an empty audit commit. No FHIR-core source was changed because the seed rename is already reflected in the current build inputs and examples that remain in core, while the authoritative extension definition is now correct in the Extension Pack.

Recommendation:
Keep this audit commit as-is. Future changes to the extension definition, display name, title, or context should be handled in the FHIR Extension Pack unless a specific core reference becomes stale.
