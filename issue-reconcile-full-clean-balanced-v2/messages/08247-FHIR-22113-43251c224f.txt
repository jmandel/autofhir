FHIR-22113: Audit Device display-name replacement

Issue request:
FHIR-22113 was Published with a Persuasive with Modification resolution for R5. It requested a simple Device display name, resolved as Device.displayName string [0..1] with the definition that it is the default display name for references and may reflect a Device.deviceName value or another simple name.

Initial application:
The Jira-tagged Device updates commit a7f2575 added Device.displayName to the then-authoritative Device spreadsheet as a 0..1 string and listed FHIR-22113 among the applied issues. Later source migration carried that content into the generated StructureDefinition source.

Additional context:
Later final Device name decisions intentionally superseded the separate element. FHIR-39162 was Published with a motion to remove Device.displayName and update the Device name backbone with Device.name.value, Device.name.type, and Device.name.display as the default/preferred display flag. FHIR-46397 was Applied with a Persuasive R6 resolution to remove Device.displayName because it was redundant with Device.name, especially Device.name.display; a combined-branch FHIR-46397 reconciliation commit has already removed remaining stale Device.displayName source comments. FHIR-55372/FHIR-54320 then removed modifier treatment from Device.name.display without changing its preferred-name role.

AutoFHIR reconciliation:
This audit commit makes no source change. Device is active in source/fhir.ini, and the current authoritative Device StructureDefinition has Device.name, Device.name.value, Device.name.type, Device.name.display, and the dev-1 uniqueness constraint for the display flag, while no active Device.displayName element remains. Re-adding Device.displayName would contradict the later Published/Applied decisions.

Recommendation:
Keep this no-change audit as-is. Treat FHIR-22113 as historically applied and now intentionally represented by Device.name/display rather than by a standalone Device.displayName element; any future change to the display-name model should be a new OO work-group decision.
