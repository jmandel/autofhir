FHIR-5279: Audit DiagnosticOrder request wording

Issue request:
FHIR-5279 was a Published/Persuasive January 2015 OO ballot comment against the FHIR core clinical table of contents. It asked that the Diagnostic Order entry change from "A request for a diagnostic investigation service to be performed" to "A record of a request for a diagnostic investigation service to be performed" to avoid contradicting the DiagnosticOrder scope text.

Initial application:
The change appears to have been pre-applied in the historical DiagnosticOrder spreadsheet by git commit d6259fa8e3, which changed the root DiagnosticOrder long definition to "A record of a request for a diagnostic investigation service to be performed" and tagged the row with [#5279].

Additional context:
DiagnosticOrder is no longer an active current-build resource. source/fhir.ini lists ServiceRequest as active, lists DiagnosticOrder and DiagnosticRequest under removed resources, and records that DiagnosticOrder was subsumed into ServiceRequest. Later Published issues FHIR-10295 and FHIR-11119 renamed DiagnosticOrder to DiagnosticRequest and then merged DiagnosticRequest with ProcedureRequest, and the current ServiceRequest definition retains the "record of a request" semantics with committee notes including [#5279][#11119]. The current active source search found no remaining active DiagnosticOrder page carrying the old wording.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The historical wording change was applied, and the current active successor resource already carries the needed "record of a request" definition while the original DiagnosticOrder page is out of the current build.

Recommendation:
Keep this no-change audit as-is. No core FHIR source follow-up is needed for FHIR-5279 unless a future work group decision changes ServiceRequest's request-resource wording more broadly.
