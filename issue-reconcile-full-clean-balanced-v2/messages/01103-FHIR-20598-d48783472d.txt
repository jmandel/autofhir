FHIR-20598: Audit string and markdown guidance

Issue request:
FHIR-20598 was Published/Persuasive with Modification for an STU3 question about when free-form fields should use string versus markdown, citing HealthcareService.comment as string while HealthcareService.eligibility.comment was markdown. The approved resolution said guidance had been added to the HL7 resource-design wiki, noted that "appropriate" use is subjective and support varies by element, and invited specific trackers where a work group chose the wrong datatype.

Initial application:
No source commit explicitly mentioning FHIR-20598 was found. The current build source includes markdown datatype guidance in source/datatypes.html, including that markdown is a string, systems are not required to support markdown rendering, string-to-markdown conversion has compatibility caveats, and plain string data in markdown fields must be escaped for safe display. The HealthcareService example from the Jira is no longer inconsistent in current source: both HealthcareService.comment and HealthcareService.eligibility.comment are markdown, with HealthcareService.comment changed by the later field-specific FHIR-39575 commit.

Additional context:
The MnM 2019-09-03 minutes record the FHIR-20598 Persuasive with Modification vote. A fetch of the historical HL7 wiki section found the intended design guidance: use string for simple text where formatting is unnecessary, inappropriate, or rarely supported, and markdown for multiple paragraphs or formatting such as bullets. Later published issues FHIR-38714 and FHIR-40555 refined the official markdown datatype and string-to-markdown safety guidance now present in datatypes.html. Later discussion around FHIR-40560 confirms that string-to-markdown changes still need element-specific judgment rather than a blanket conversion rule.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already covers the markdown datatype and conversion caveats, the original HealthcareService example has been corrected through the separate field-specific tracker path that FHIR-20598 recommended, and adding a new blanket "free-form text should be markdown" rule would overstate a subjective resource-design decision.

Recommendation:
Keep this audit commit as-is. Future concerns about individual fields should continue to be handled as field-specific Jira issues, as FHIR-20598 directed, rather than by changing all comments or descriptions to markdown globally.
