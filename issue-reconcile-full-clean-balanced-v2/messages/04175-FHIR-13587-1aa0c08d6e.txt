FHIR-13587: Audit Using Expressions examples

Issue request:
FHIR-13587 was a Published/Persuasive STU3 CDS change request about the Clinical Reasoning Using Expressions examples for ActivityDefinition and PlanDefinition dynamicValue expressions. It asked that examples specify the expression language instead of leaving interpreters to infer it from referenced libraries, and that the multiple-library example put the library qualifier in the expression reference rather than in the FHIR element path.

Initial application:
The issue was applied by git-svn commit fe9a278da48fa5f1e5fac3ca1bc517fafd96b8e2, corresponding to SVN 13322 cited in Jira. That commit added CQL language declarations to the examples and changed the qualified example from path value="mmi-suiciderisk-orderset-logic.reasonCode" with an unqualified expression to path value="reasonCode" with a qualified expression value="&quot;mmi-suiciderisk-orderset-logic&quot;.RiskAssessmentScore".

Additional context:
The old cqif page is now source/clinicalreasoning-topics-using-expressions.html and is in the current build through the Clinical Reasoning hierarchy and module page. Later changes refined the same example family without reversing FHIR-13587: FHIR-16708 added quote-escaping guidance and a JSON example, and FHIR-35981 corrected the CQL media types to text/cql-identifier and text/cql-expression. FHIR-49976 and FHIR-53080 added later Using Expressions guidance on inline CQL and page consolidation. FHIR-49246 corrected the encoded content of the suicide-risk library example, but that is a distinct library-content issue rather than the expression path/language problem raised here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/clinicalreasoning-topics-using-expressions.html already specifies language for the relevant CQL examples, shows the named and qualified RiskAssessmentScore examples as nested Expression values, keeps the dynamicValue path as reasonCode, and contains no remaining stale mmi-suiciderisk-orderset-logic.reasonCode path.

Recommendation:
Keep this audit commit as-is. The current specification already carries the approved clarification, and additional prose would be redundant with the existing Expression Language and Expression sections plus later CQL media-type guidance.
