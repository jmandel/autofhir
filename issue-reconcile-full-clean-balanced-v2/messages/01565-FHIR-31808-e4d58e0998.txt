FHIR-31808: Audit Ingredient link direction

Issue request:
FHIR-31808 was Published with a Persuasive with Modification resolution for R5. The request objected that Ingredient was being modeled as independently shareable, and the accepted resolution was to add references from Ingredient to the products that use it and remove the direct Ingredient references from the product resources that previously pointed to it.

Initial application:
The change was applied before this reconciliation by the FHIR#31808 commits fbfbf287b1 and 4b8f3f0577. Those commits added Ingredient.for and changed MedicinalProductDefinition.ingredient, AdministrableProductDefinition.ingredient, and ManufacturedItemDefinition.ingredient from references to Ingredient into coded ingredient elements with text explaining that detailed Ingredient resources refer inward through Ingredient.for.

Additional context:
Ingredient is active in the current build through source/fhir.ini. Current source retains Ingredient as a resource, which is consistent with the modified resolution rather than the issue title alone. A later Published issue, FHIR-39515, renamed ManufacturedItemDefinition.component.constituent.locationForIngredient to hasIngredient and its comment explains that this is another reference to an existing ingredient mentioned elsewhere, not the main ingredient reference direction.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative source already has Ingredient.for referencing MedicinalProductDefinition, AdministrableProductDefinition, and ManufacturedItemDefinition, while the three product-definition ingredient elements no longer target StructureDefinition/Ingredient.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-31808 unless the work group later reopens the broader modeling question of whether Ingredient should remain a resource at all.
