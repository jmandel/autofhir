FHIR-34423: Audit optional eligibility response request

Issue request:
FHIR-34423 was Applied/Persuasive with Modification for R6 and requested that CoverageEligibilityResponse.request change from mandatory 1..1 to optional 0..1 because some eligibility responses are produced without a CoverageEligibilityRequest.

Initial application:
The source change was applied by git commit 917db6986abcc1205c7ca1a1cb8c0af67b723b7c, which changed CoverageEligibilityResponse.request min from 1 to 0 in source/coverageeligibilityresponse/structuredefinition-CoverageEligibilityResponse.xml.

Additional context:
The earlier Published/Persuasive FHIR-19493 request had made CoverageEligibilityResponse.request 1..1 along with several other eligibility response fields. FHIR-34423 is the later, narrower work-group decision for the same element and therefore supersedes that earlier request cardinality. A 2021 financial Zulip thread records the motivating interoperability problem: implementers had eligibility responses from other workflows and no real request resource to reference.

AutoFHIR reconciliation:
This commit intentionally makes no source change. CoverageEligibilityResponse is active in source/fhir.ini and the current source has CoverageEligibilityResponse.request at 0..1, exactly matching FHIR-34423.

Recommendation:
Keep this no-change audit commit. Any implementation guide that requires a request can still profile the base resource, but the core R6 source should keep request optional unless a later FM decision changes it again.
