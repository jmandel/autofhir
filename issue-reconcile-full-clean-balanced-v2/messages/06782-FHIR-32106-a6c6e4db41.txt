FHIR-32106: Replace stale binding definition extension URL

Issue request:
FHIR-32106 was Published/Persuasive with Modification for FHIR-core XML after R4B. It reported that http://hl7.org/fhir/build/StructureDefinition/definition appeared as an unknown extension in profiles-resources.xml and requested removal of that extension reference, with the accepted resolution to remove the reference and prevent this tooling problem from recurring.

Initial application:
The issue appears to have been applied before reconciliation: FHIR-I minutes record the vote to remove the extension, Rick Geimer later commented that the change looked applied, and commit 49ccba43692b0b120e4e25729570c065984c33b2 converted old build/StructureDefinition/definition binding metadata to the current tools/StructureDefinition/binding-definition URL across active source. That commit converted two DeviceAssociation bindings but missed DeviceAssociation.statusReason, which had been added two days earlier by commit 925b08c4bf11c8da9804ff50af017766db10980e.

Additional context:
DeviceAssociation is an active resource in source/fhir.ini, so source/deviceassociation/structuredefinition-DeviceAssociation.xml feeds the current build. The R5 historical profiles-resources.xml has no old build/StructureDefinition/definition references and does contain tools/StructureDefinition/binding-definition entries, confirming the intended replacement pattern. FHIR-32779 is the same R5 complaint resolved as no longer an issue and is context only, not a separate source-edit decision in this run. A Zulip R4B process thread said FHIR-32106-style R4B fixes should be made in both R4B and master.

AutoFHIR reconciliation:
This commit changes the remaining active core source occurrence on DeviceAssociation.statusReason from http://hl7.org/fhir/build/StructureDefinition/definition to http://hl7.org/fhir/tools/StructureDefinition/binding-definition, matching the prior bulk conversion and leaving no old URL matches in active source.

Recommendation:
Keep this source fix. It completes the prior application for current core source without changing binding semantics; future extension-pack cleanup, if any, should be handled in the extension-pack repository rather than in this core commit.
