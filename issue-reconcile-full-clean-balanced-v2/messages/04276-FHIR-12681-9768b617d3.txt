FHIR-12681: Audit Communication element ordering

Issue request:
FHIR-12681 was a Published/Persuasive DSTU2 Patient Care QA issue reporting that Communication elements were out of order. The Jira warning expected Communication.recipient to appear before topic/context/sent/received/sender/reason rather than after sender.

Initial application:
The issue was applied in git commit 047a0c6ab1c00e633177a675d7146fc48793bf00, which moved Communication.recipient earlier in the then-authoritative Communication spreadsheet and reordered the affected Communication examples. That spreadsheet source was later retired when Communication moved to StructureDefinition XML source.

Additional context:
Communication is active in source/fhir.ini. The current authoritative source is source/communication/structuredefinition-Communication.xml, where Communication.recipient follows sent/received and precedes sender/reason. That is explained by later Published workflow-alignment issue FHIR-14446: its resolution says Communication.recipient should map to who.actor/Event.performer.actor rather than who.focus, and implementation commit 0b3156fcf0c2c6f49163a515ab17173a52cc8deb explicitly says that mapping change triggered re-sequencing of elements. The 2021 source rework introduced the current XML with the later ordering and current examples align with that ordering. Direct Zulip and Confluence searches for FHIR-12681 found no conflicting discussion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The DSTU2 QA warning was applied, and the current R6 ordering reflects a later applied workflow decision rather than an un-applied FHIR-12681 defect.

Recommendation:
Keep this audit commit as-is. Do not restore the DSTU2 recipient-before-topic order unless Patient Care opens a new issue that supersedes the later workflow-alignment sequencing.
