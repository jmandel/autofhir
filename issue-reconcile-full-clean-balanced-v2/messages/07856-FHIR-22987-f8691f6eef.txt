FHIR-22987: Audit Reference minimum invariant

Issue request:
FHIR-22987 was a Published/Persuasive FHIR-core datatypes issue asking that the Reference narrative SHALL about having at least one of reference, identifier, or display not remain an ad-hoc validator warning. The approved resolution was to make it a standard invariant so failures are errors and so the rule appears with the Reference constraints.

Initial application:
The issue was explicitly applied by git commit ae562314cc, which added a Reference invariant row named "Minimum requirements" with error severity. Subsequent nearby R5 commits in the same source area normalized the wording and completed the XPath/extension-inclusive expression, leaving the current source with a standard invariant rather than only narrative prose or a validator-only warning.

Additional context:
source/fhir.ini actively lists Reference as a FHIR datatype, marks it normative, and assigns it the ref code, so source/datatypes/reference.xml is current build input. The current generated R5 history surface includes ref-2 for the same rule. Zulip discussion in 2020 and 2022 confirms the warning/narrative mismatch that motivated the Jira resolution and does not reveal a later conflicting decision; Confluence refs search found no direct FHIR-22987 minutes.

AutoFHIR reconciliation:
No source change was made. The current authoritative Reference spreadsheet already has an error-severity Reference invariant whose English, FHIRPath, and XPath require reference, identifier, display, or extension to exist.

Recommendation:
Keep this no-change audit commit as-is. Any remaining validator behavior belongs outside this core source reconciliation unless a current validator repository issue shows the old warning still exists independently of the R5 Reference invariant.
