FHIR-39290: Confirm Reference.type comment removal

Issue request:
FHIR-39290 was a Published/Persuasive R5 FHIR-I correction asking to delete the Reference.type comment sentence "if both the type and a reference is provided, the reference SHALL resolve to a resource of the same type as that specified." The resolution accepted that the existing definition already says Reference.type and a FHIR Reference.reference SHALL be consistent, while the removed comment incorrectly implied that a reference must resolve whenever type is present.

Initial application:
The issue was already applied in source by git commit f33b8b9e0b27fe06995acde5a15329725904b3eb, "FHIR-39290 Remove extraneous comment from Reference.type," which changed source/datatypes/reference.xml and removed exactly the disputed sentence. The combined branch contains that source commit, and no prior Issue-Reconcile-Key: FHIR-39290 audit commit was present before this reconciliation.

Additional context:
Reference is an active datatype in source/fhir.ini and is rendered on source/references.html through the Reference datatype include, so source/datatypes/reference.xml is the authoritative build-scoped source for this text. Zulip discussion in #implementers identified the same overstatement and led to FHIR-39290; FHIR-I January 2023 minutes record the Persuasive vote. Jira phrase searches found no separate related tracker beyond FHIR-39290.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/datatypes/reference.xml retains the normative consistency sentence in the definition and the Reference.type comment now stops after explaining that type may be determined by inspection or resolution, without the erroneous SHALL-resolve sentence.

Recommendation:
Keep this no-change audit commit as-is. The current core source already reflects the Published Jira decision, and no follow-up is needed unless a future tracker requests a broader editorial rewrite of Reference.type.
