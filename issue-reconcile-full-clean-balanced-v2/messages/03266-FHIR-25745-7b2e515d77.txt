FHIR-25745: Audit CodeSystem property repetition guidance

Issue request:
FHIR-25745 was Published with a Persuasive with Modification resolution for R5. The request was to clarify that CodeSystem concept properties can repeat when a single concept has multiple CodeSystem.concept.property entries with the same property code and different values; the Vocab work group chose to add a comment to CodeSystem.property rather than add a new repeatability flag.

Initial application:
The issue was applied before this reconciliation by commit 0e7bc53aeea7725b86d61e87a663b341dafe4580, merged by PR #1980, which added the requested CodeSystem.property comment to source/codesystem/structuredefinition-CodeSystem.xml. A pickaxe search for the exact comment finds that commit as the source-history application point.

Additional context:
source/fhir.ini actively lists codesystem=CodeSystem in [resources], so source/codesystem/structuredefinition-CodeSystem.xml is build-scope source for the current resource definition. The 2022-04-25 Vocab minutes confirm the submitter clarification and the work-group decision to resolve change required without adding the proposed flag. Zulip search for the issue key and key terms found no directly relevant discussion that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current CodeSystem.property element already contains the requested comment explaining that repeated CodeSystem.concept.property entries may share a CodeSystem.property code when their values differ, so adding more prose or a repeatability flag would go beyond the published resolution.

Recommendation:
Keep this audit commit as-is. Future work should only revisit the design if a new Vocab decision asks for machine-readable property repeatability metadata; FHIR-25745 itself is already represented correctly in current build-scope source.
