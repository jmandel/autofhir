FHIR-31249: Audit SearchParameter spd-1 expression condition

Issue request:
FHIR-31249 was a Published/Persuasive FHIR-I R5 technical correction for SearchParameter. It observed that SearchParameter.expression listed invariant spd-1 even though spd-1 was then an xpath/xpathUsage rule, and requested removing that unrelated condition mention from the expression element.

Initial application:
The issue was applied by commit 4a2e1d85ae54ff4d7f68ec5af9591eca21029e80, included in merged PR HL7/fhir#1960. That commit deleted `<condition value="spd-1"/>` from SearchParameter.expression while spd-1 still referred to xpath/xpathUsage, which matched the Jira request.

Additional context:
FHIR-32530 later reached Published/Persuasive with Modification for the same SearchParameter artifact. Its accepted resolution was to drop SearchParameter.xpath, rename xpathUsage to processingMode, update descriptions to refer to expression rather than xpath, and revise spd-1 to depend on expression/processingMode. The current source reflects that later accepted rule: SearchParameter is active in source/fhir.ini, spd-1 now says `expression.empty() or processingMode.exists()`, and the condition is listed on both SearchParameter.expression and SearchParameter.processingMode. The combined branch already contains a separate FHIR-32530 reconciliation commit, so this audit does not decide that related issue again.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Removing spd-1 from SearchParameter.expression now would be incorrect because the current invariant is no longer the xpath-only rule that FHIR-31249 corrected; it is the later FHIR-32530 expression/processingMode requirement.

Recommendation:
Keep this empty audit commit. No core source follow-up is needed for FHIR-31249 unless a future work group decision changes the SearchParameter.processingMode requirement itself.
