FHIR-7307: Audit RelatedPerson birthDate inclusion

Issue request:
FHIR-7307 was a Published/Persuasive Patient Administration DSTU1 change request asking to add a birthDate to RelatedPerson, analogous to Person, because the age of an individual involved in care may matter. Its resolution says the birthdate, as a date, will be added to RelatedPerson, and a follow-up Jira comment asks that it also be included as a search parameter.

Initial application:
The issue appears to have been applied by git commit a96f358a486ac632eadda2a5de834bc1a64e29f2, "Tracker# 7307 RelatedPerson to include birthDate", which added RelatedPerson.birthDate as a 0..1 date element to the then-authoritative RelatedPerson spreadsheet. The later 2021 source rework commit 33b409a4b6d544598262f2f074ebb4b6dc466157 migrated RelatedPerson into current XML source files and retained the element and generated/search-parameter source.

Additional context:
RelatedPerson is active in source/fhir.ini as a current resource with PA approval status. The current Person source also uses date for Person.birthDate, so the current RelatedPerson date type matches the final FHIR-7307 resolution rather than the issue summary's loose "dateTime" wording. Jira and community searches found no later final FHIR-core decision or direct Zulip/Confluence discussion reversing the birthDate or birthdate search parameter; FHIR-17504 is a later no-change RelatedPerson demographics/background issue and does not alter this element.

AutoFHIR reconciliation:
No source files were changed. The current build-scope RelatedPerson StructureDefinition already contains RelatedPerson.birthDate as 0..1 date, and the current RelatedPerson search-parameter bundle already contains the birthdate date search parameter over RelatedPerson.birthDate.

Recommendation:
Keep this empty audit commit as-is. No core FHIR follow-up is needed for FHIR-7307 unless a future Patient Administration decision intentionally revisits RelatedPerson demographic duplication more broadly.
