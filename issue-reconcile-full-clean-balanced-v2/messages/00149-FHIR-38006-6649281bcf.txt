FHIR-38006: Audit timezone offset datatype wording

Issue request:
FHIR-38006 was Published/Persuasive for R5 and asked the date, dateTime, instant, and time datatype descriptions to distinguish timezone offsets from actual time zone identifiers. The approved resolution required adding "offset" to the existing offset rules and adding a note on dateTime and instant that actual time zone codes may be sent with http://hl7.org/fhir/StructureDefinition/timezone.

Initial application:
The issue was applied by commit 96a8f6cf4179999f7df02e3648b33562c5b5bdf0, which changed source/datatypes.html for date, dateTime, instant, and time and added the timezone extension note for dateTime and instant. Later editorial changes normalized wording to "timezone offset" and adjusted one extension-link macro, but preserved the approved semantics.

Additional context:
MnM minutes from 2022-09-14 record the work group decision to update the specification 3-0-0. Current source/fhir.ini routes primitive datatypes to datatypes.html, so the inspected page is in build scope. The canonical timezone extension is now evidenced in the FHIR Extension Pack, while core source continues to reference the canonical URL from the datatype prose and oids.ini. Quoted Zulip searches found no FHIR-38006-specific discussion or conflicting community evidence.

AutoFHIR reconciliation:
This audit made no source change. The current combined-branch source already says there is no timezone offset for date, a timezone offset is required for dateTime when hours and minutes are present, instant includes a timezone offset, and time cannot include a timezone offset. dateTime and instant also point to the timezone extension for actual time zone codes.

Recommendation:
Keep this no-change audit commit as-is. No core follow-up is needed for FHIR-38006 unless a future work group decision changes how the timezone extension should be linked or represented.
