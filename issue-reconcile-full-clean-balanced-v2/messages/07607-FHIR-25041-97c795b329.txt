FHIR-25041: Clarify search support declarations

Issue request:
FHIR-25041 was Published/Persuasive for FHIR-core Conformance and asked for clearer guidance on how CapabilityStatement declares search qualifiers, how search parameters differ from search behavior modifiers such as _sort, and how servers/clients should express search capabilities.

Initial application:
The issue was applied for R5 by commit 8f6ce81, which added the CapabilityStatement "Supporting Search" notes and linked to them from search.html. Follow-up source history repaired the link markup and later wrapped the server declaration as a conformance statement, but the search page still said servers declare search features they "require" rather than the search features they support.

Additional context:
The linked Zulip thread shows the original confusion: underscore controls, _include/_revinclude, modifiers, and server-specific SearchParameter resources were being conflated. FHIR-I minutes recorded approval to add CapabilityStatement search capability notes. Later Jira issues FHIR-43332, FHIR-46110, and FHIR-51160 concern broader or later search-capability mechanisms/comments and are not decided by this Applied/Published seed reconciliation.

AutoFHIR reconciliation:
Updated source/search.html, an active top-level Search page referenced by source/hierarchy.xml, so the normative reference to CapabilityStatement search declarations says servers declare search features they support and clients declare search features they use. This aligns the Search page with the active CapabilityStatement notes, which already state that CapabilityStatement indicates search functionality a server supports or a client uses.

Recommendation:
Keep this source fix. Treat FHIR-43332, FHIR-46110, and FHIR-51160 as separate follow-up/application work for their own issue scopes rather than expanding this seed beyond the one-word semantic mismatch in the FHIR-25041 application.
