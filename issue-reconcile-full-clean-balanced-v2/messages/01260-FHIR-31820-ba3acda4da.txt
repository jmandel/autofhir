FHIR-31820: Audit strength and referenceStrength clarification

Issue request:
FHIR-31820 was a Published/Persuasive FHIR-core BR&R change request for MedicinalProductIngredient asking whether an ingredient can have both strength and referenceStrength. The resolution said to improve documentation, call out that a simple translation mechanism is insufficient because the reference substance must also be specified, and provide examples.

Initial application:
No current-source commit explicitly tagged FHIR#31820 was found. The applied source history instead shows the companion FHIR#31819 commits 72c7bcfe69c0b11deaefc688b833b242cf18474c and 9ac982b98acc0b1b67fdc1dd53c4b087e29419f7 adding the definition text quoted in the FHIR-31820 comments, and the active Ingredient example includes both a primary strength and a referenceStrength.

Additional context:
MedicinalProductIngredient is now redirected to the active Ingredient resource. FHIR-35931 later made Ingredient.substance.strength.referenceStrength.substance 1..1, so the model now structurally requires the reference substance whenever referenceStrength is used. No direct Zulip discussion of FHIR-31820 was found, and Confluence only surfaced BR&R agenda/minutes references that list the issue with other R4B ballot work.

AutoFHIR reconciliation:
No source change was made. The active StructureDefinition already states that both strength and referenceStrength are needed when active substance and active moiety differ, the referenceStrength backbone requires a substance, and the active example demonstrates a strength with a referenceStrength and explanatory comments.

Recommendation:
Keep this no-change audit commit. The current source answers the issue's implementer question without adding redundant examples or translation-mechanism prose; future editorial examples can be handled by BR&R if they want named real-world products rather than the current generic example.
