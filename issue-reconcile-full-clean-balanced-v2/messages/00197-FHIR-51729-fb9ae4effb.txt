FHIR-51729: Remove stale CompartmentDefinition example documentation

Issue request:
FHIR-51729 was Applied/Persuasive with Modification for R6. It asked to remove unused CompartmentDefinition elements because HL7 defines the complete set of core compartment definitions; the approved disposition removed CompartmentDefinition.resource.documentation and populated start/end parameter mappings instead of removing those elements.

Initial application:
The upstream source commit d116faa04d484120c90b33bc0d06cfe038915d42 removed CompartmentDefinition.resource.documentation from source/compartmentdefinition/structuredefinition-CompartmentDefinition.xml and added date/startdate/enddate columns to source/compartments.xml for generated compartment definitions. The active example source still contained two resource.documentation elements, so the application was incomplete for an in-scope example.

Additional context:
CompartmentDefinition is active in source/fhir.ini, and source/compartmentdefinition/list-CompartmentDefinition-examples.xml lists CompartmentDefinition/example as an example artifact. FHIR-I minutes from 2025-11-03 confirm the committee decision to remove .documentation and populate startParam/endParam. The adjacent FHIR-51725 decision clarified that resources without .param are outside a compartment and removed narrative reliance on documentation; FHIR-51607 discusses a separate tooling extension for post-R6 additional resources and does not keep documentation in the core CompartmentDefinition resource.

AutoFHIR reconciliation:
Removed the two stale <documentation> elements from source/compartmentdefinition/compartmentdefinition-example.xml so the example no longer uses an element removed from the current CompartmentDefinition structure.

Recommendation:
Keep this commit as-is. The authoritative structure and generated compartment spreadsheet already reflect the Jira disposition; this commit only completes the same change for the active example.
