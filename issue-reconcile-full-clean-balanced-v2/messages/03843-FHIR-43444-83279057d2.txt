FHIR-43444: Audit DeviceRequest workflow alignment

Issue request:
FHIR-43444 was Applied with a Persuasive with Modification resolution for OO to analyze DeviceRequest against the workflow Request pattern. The approved work was to rename DeviceRequest.code to DeviceRequest.product, add workflow mappings from DeviceRequest.doNotPerform to Request.doNotPerform and DeviceRequest.product to Request.product, remove the obsolete DeviceRequest instantiates elements in favor of workflow-instantiates extensions, and leave other Request pattern elements such as category, statusReason, reported[x], performerType, and deliverTo out where there was no use case.

Initial application:
The Jira comment records application in commit 24b68f1e49. That commit updated the active DeviceRequest StructureDefinition, examples, and search-parameter bundle by removing DeviceRequest.instantiatesCanonical and DeviceRequest.instantiatesUri, renaming the requested device element from code to product, and updating product/device search parameter expressions. Later commit ce624b1f85 added a ballot note that documents the R6 DeviceRequest changes but did not reverse the workflow mapping application.

Additional context:
DeviceRequest is active in source/fhir.ini under draft resources and resources, so source/devicerequest is in current build scope. Current source/devicerequest/structuredefinition-DeviceRequest.xml has DeviceRequest.doNotPerform mapped to Request.doNotPerform and DeviceRequest.product[x] mapped to Request.product. Current source/devicerequest/devicerequest-request-mapping-exceptions.xml records those mappings as the deliberate Request-pattern divergences and leaves Request.code/category/statusReason/reported/performerType/deliverTo unmapped. The R5-to-R6 migration entries in source/fhir.ini map the old DeviceRequest.code and instantiates elements for version transition purposes. A generated-looking source/devicerequest/devicerequest.svg still contains old anchors, but the authoritative XML and search parameter sources are correct and this reconciliation does not make SVG-only edits.
