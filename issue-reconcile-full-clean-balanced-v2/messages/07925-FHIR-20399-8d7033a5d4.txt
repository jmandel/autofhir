FHIR-20399: Audit dateTime schema regex correction

Issue request:
FHIR-20399 was a Published/Persuasive FHIR-core change request from STU3 asking to correct the v3/STU3 fhir-base.xsd dateTime regex so it matched the datatype-page regex and required a UTC offset whenever a full time is supplied. The resolution said to fix the STU3 schemas to match the regex from the spec per the Zulip discussion.

Initial application:
The issue was explicitly applied by git commit 20f1fafd1524580a9c4872dc63ce10a468f44b41, "FHIR-20399 Correction to v3 schema dateTime regex", which changed source/datatypes/primitives.xml, the primitive datatype source from which the schema regex is generated. The current branch has that commit in history, and the current dateTime primitive row still keeps the offset group inside the time portion rather than making it optional after a time.

Additional context:
The linked Zulip thread confirms the original mismatch was specific to the STU3 schema and that R4 already had the required-offset behavior. Later dateTime regex work, especially FHIR-38735, refined the R5 ballot regex so date-only values remain valid while offsets are allowed only when a full time is specified; the current source reflects that later accepted state. FHIR-14094 reported the same STU3 validation-schema mismatch earlier and is already represented on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source/datatypes/primitives.xml dateTime regex accepts partial dates, rejects a full dateTime without an offset, and accepts full dateTimes with Z or numeric offsets. The current checkout does not contain an authoritative checked-in fhir-base.xsd to edit; the checked-in fhir-all.xsd is a generated template, and the active primitive regex source is already correct for this issue family.

Recommendation:
Keep this audit commit as-is. No current core source fix is needed for FHIR-20399; any further concern about historical STU3 downloadable archives would be release-archive maintenance rather than a change to the current FHIR source.
