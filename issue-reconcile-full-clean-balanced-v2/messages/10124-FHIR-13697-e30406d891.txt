FHIR-13697: Audit LastN input restrictions

Issue request:
FHIR-13697 was a Published/Persuasive OO change request for the Observation `$lastn` operation. The issue asked to clarify the linked Zulip discussion and add the substantive restriction that a `$lastn` request requires a subject and either code(s) or category(s); the Jira resolution says the change was preapplied and that the quoted typo correction was not part of the tracker.

Initial application:
Commit 62dd40971ee01b8cd8b4903594098accbe5ea7e7 preapplied #13697 on 2017-07-27 by updating the then-authoritative Observation spreadsheet operation text. It added a "The request for a lastn query SHALL include" section with bullets for a subject via `patient` or `subject` and for `category` and/or a code-bearing search parameter.

Additional context:
The current source no longer uses the spreadsheet source from 2017, but `source/fhir.ini` lists Observation as an active resource and `source/observation/list-Observation-operations.xml` references `OperationDefinition/Observation-lastn`. Later `$lastn` changes, including FHIR-41448 ordering/footer clarifications, edited the same operation text without removing or reversing the FHIR-13697 request restrictions.

AutoFHIR reconciliation:
Made no source change. The current active OperationDefinition description already says a lastn query SHALL include a subject using `patient` or `subject` and a `category` parameter and/or a search parameter whose FHIRPath expression contains a code element, which preserves the applied issue requirement.

Recommendation:
Keep this empty audit commit as-is. No additional core source edit is needed for FHIR-13697 unless OO makes a new decision to formalize the search-derived inputs as explicit OperationDefinition parameters instead of narrative requirements.
