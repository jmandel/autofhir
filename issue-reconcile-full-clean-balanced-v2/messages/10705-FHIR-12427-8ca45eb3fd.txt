FHIR-12427: Audit Java generator pct handling

Issue request:
FHIR-12427 was a Published/Persuasive DSTU2 FHIR-core change request asking the Java code generator to replace '%' with 'pct' when deriving Java enum/constant identifiers from binding code values, after observation-statistics codes such as '%20' and '%80' produced illegal Java identifiers.

Initial application:
The issue was applied in historical commit fd70583337b3caf1e62b58e43978f5535c33a724, whose message cites #12427 and svn build@10496. That commit added handling in JavaBaseGenerator.makeConst so a literal '%' became 'pct' and remaining percent characters were replaced with 'pct', matching the Jira resolution.

Additional context:
The relevant Java generator source is no longer present in the current FHIR specification checkout. Later history removed the old reference implementation/generator tree, and the current Gradle build runs the publisher from the external org.hl7.fhir:kindling dependency. The current observation-statistics code system in core also no longer has the leading percent codes that originally exposed the Java identifier problem; it uses 20-percent and 80-percent instead, and Observation remains an active resource with the stats operation listed.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The historical source change was applied, and the current core checkout has no JavaBaseGenerator/makeConst source to edit; any remaining generator behavior would need to be checked in the external kindling/tooling repository rather than patched in HL7/fhir.

Recommendation:
Keep this audit commit as-is for core reconciliation. If implementers still see illegal Java enum identifiers from percent-containing codes in current generated artifacts, open a focused follow-up against the current generator owner, likely HL7/kindling, using the old fd705833 fix as implementation history.
