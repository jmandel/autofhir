FHIR-16941: Confirm GuidanceResponse persistence guidance

Issue request:
FHIR-16941 was a Published/Persuasive CDS change request for STU3. It reported that GuidanceResponse was problematic as a stand-alone persisted resource unless the specification either clarified that it behaved only like Parameters or added documentation and elements so downstream systems could interpret a persisted response.

Initial application:
The issue was applied historically by GF#16941 commits 2dec2bb140 and a430482562. Commit 2dec2bb140, corresponding to SVN build 14866 cited in Jira, clarified the persistence use case and added a ballot note. Commit a430482562, also cited in Jira, removed the temporary STU ballot note after implementer feedback confirmed persisted GuidanceResponse use cases. No missing FHIR-16941-specific source application was found in the current resource.

Additional context:
GuidanceResponse is active in the current build, owned by CDS, and remains an approved resource. Current source describes GuidanceResponse as supporting recorded decision-support interaction results, lists keeping a record of past service requests as a use case, explains search support for historical records, and includes identifiers, required module[x], status, subject/context, reason, outputParameters, result, and dataRequirement elements needed to carry or point to the response context. DetectedIssue also still explicitly cites GuidanceResponse as supporting evidence, matching the Jira comment about downstream reference use. Later independent GuidanceResponse changes, including FHIR-30798, FHIR-35849, and FHIR-37891, refined module coding, reason context, and result references without reversing the persistence decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source already conveys that GuidanceResponse can be recorded/persisted and provides the structural elements that distinguish it from a raw Parameters wrapper. Adding another local restatement would be redundant and could create maintenance drift.

Recommendation:
Keep this no-change audit commit as-is. Reopen with CDS work-group review only if the group wants a new, stronger normative rule for standalone interpretability beyond the existing persistence guidance and element model.
