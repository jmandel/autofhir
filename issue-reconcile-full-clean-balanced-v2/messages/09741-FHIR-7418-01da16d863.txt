FHIR-7418: Audit Device.location definition

Issue request:
FHIR-7418 was a Published/Persuasive OO change request for the Device resource. It reported a DSTU1 contradiction between Scope and Usage text saying an implanted device would have a patient and no location, and the Device.location definition saying the resource could be found in a literal, logical, or coded location. The approved resolution was to change the Device.location description to "The place where the device can be found."

Initial application:
The issue appears to have been applied in commit 165f27cb02e9a41309bffb199dbf6aa7f36c54f2, whose subject says "#7418 changee def of device.location". Before that commit, source/device/device-spreadsheet.xml described Device.location as a resource found in a literal, logical, or coded location; that commit changed the definition to "The place where the device can be found." and added the #7418 committee note. The 2021 source-format rewrite commit 33b409a4b6d544598262f2f074ebb4b6dc466157 carried the #7418 note and corrected definition into source/device/structuredefinition-Device.xml.

Additional context:
The current Device resource is in build scope through the active device=Device entry in source/fhir.ini. The current authoritative source has Device.location short value "Where the device is found" and definition "The place where the device can be found." The current Device Scope and Usage text says Device tracks individual device instances and their location and no longer contains the reported rule that implanted devices have no location. Related FHIR-17376 later corrected the Device.location short text from "resource" to "device" and already has an Issue-Reconcile-Key commit on the combined branch, so this reconciliation does not duplicate it. FHIR-8221 was a retracted no-change request to make Device.location 0..*, and does not alter the seed decision. Zulip and Confluence searches found no directly relevant community evidence that changes the Jira/source conclusion.
