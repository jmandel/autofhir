FHIR-23937: Audit mapping-language dateOp resolution

Issue request:
FHIR-23937 is Published/Persuasive with Modification for the FHIR-core Mapping Language page. The issue originally asked to document the undocumented dateOp target transform parameters, but the final resolution narrowed the R5 change to correcting the evaluate shorthand context wording and explicitly deferred defining dateOp parameters to a new R6 tracker.

Initial application:
The seed was applied in git commit 8d9c57d215, which changed source/mapping-language.html from saying the shorthand FHIRPath expression has no context and must start with a defined variable to saying it has no explicit context and any context is implicit through references to existing variables such as $this. That current source wording still appears in the active Mapping Language page.

Additional context:
The linked follow-up tracker FHIR-40645 is already represented on the combined branch by commit b1a41b0b04, which fixed the separate date/time transform definition work by adding concrete toDateTime, toInstant, toDate, toTime and Unix-offset transform codes and removing the stale dateOp placeholder from the active CodeSystem. Zulip and FHIR-I minutes confirm that the seed discussion led first to the R5 context-wording correction and then to the later R6 date/time transform decision.

AutoFHIR reconciliation:
This commit makes no source change. The current source already contains the exact semantic correction approved for FHIR-23937, and adding dateOp parameters under the seed would duplicate or conflict with the already-published FHIR-40645 reconciliation.

Recommendation:
Keep this audit commit as-is. Future date/time transform changes should be handled under FHIR-40645 or a new FHIR-I tracker, not by reopening FHIR-23937's R5 context-wording disposition.
