FHIR-43191: Audit date search interval clarification

Issue request:
FHIR-43191 was Applied with resolution Persuasive for R6. It reported that the Search page wording "When the date parameter is not fully specified, matches against it are based on the behavior of intervals" implied that only partially specified date searches are range-based. The approved change was to replace that clause with "Matches against dates are based on the behavior of intervals, where" so all date search values are described as interval-based according to precision.

Initial application:
The issue was applied before this reconciliation by git commit 500f17b8f9a36411cc0a09ccec868b375ce2deab, "FHIR-43191 - clarification around partial date interval," which changed source/search.html to the approved wording and added a day-precision interval example. Jira later linked this application to HL7/fhir pull request 3967, which was merged on 2025-11-09.

Additional context:
The current source/search.html is the FHIR-core Search page named by the Jira related page and related URL, and source/fhir.ini keeps search behavior metadata tied to search.html. Current source/search.html no longer contains the misleading "not fully specified" qualifier. FHIR-I minutes from 2024-04-22 record the 8-0-0 motion to approve FHIR-43191 as Persuasive. The nearby FHIR-43208 date-search example cleanup was separately reconciled on the combined branch and is consistent with this interval wording.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative source already conveys the approved rule that date searches match using intervals determined by date precision.

Recommendation:
Keep this no-change audit commit as-is. No follow-up source work is needed for FHIR-43191 unless the work group later revisits date search interval semantics more broadly.
