FHIR-25127: Audit displayCategory invariant correction

Issue request:
FHIR-25127 is a Published/Persuasive FHIR-core Questionnaire change request for R5. It reported that the questionnaire-displayCategory extension had contextInvariant type!='display' even though the extension is intended for display items, and requested correcting the invariant to type='display'.

Initial application:
The issue was applied on the then-current core source by f0b7244ac8, which changed source/questionnaire/structuredefinition-extension-questionnaire-displayCategory.xml from type!='display' to type='display'. Jira's comment for FHIR-25127 records that implementation commit, and the linked Zulip thread shows the reporter and Lloyd McKenzie agreed the old invariant was an error.

Additional context:
Core later removed questionnaire extension definitions from the active R5 source in dd468d4f17, so structuredefinition-extension-questionnaire-displayCategory.xml is no longer a current FHIR-core build input. The current FHIR Extension Pack definition for questionnaire-displayCategory is the active extension source; it has Questionnaire.item and ElementDefinition contexts and no stale type!='display' invariant. That no-invariant state is not an unapplied regression: later Published FHIR-extensions issue FHIR-43033 and commit 59d4c2c restored ElementDefinition context and removed displayCategory's type='display' contextInvariant because a single Questionnaire.item-oriented invariant could not safely cover both contexts.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The inverted invariant was already corrected in core before the extension definition moved out of this checkout, current core has no active source file containing the stale invariant, and the current external source reflects a later final context review.

Recommendation:
Keep this no-change audit as-is for FHIR-core. Do not reintroduce the old core extension definition or add a core patch; any future displayCategory context change belongs in the FHIR Extension Pack and should account for FHIR-43033's ElementDefinition-context decision.
