FHIR-12750: Audit ReferralRequest binding application

Issue request:
FHIR-12750 was a Published/Persuasive DSTU2 Patient Care change request for ReferralRequest. It asked for ReferralRequest.type to have an example binding to SNOMED CT concept 3457005 and for the old .type comment to be removed, and for ReferralRequest.reason to have an example binding to SNOMED clinical findings.

Initial application:
The issue was applied in git commit 6e701e5ef7be2338059f27c6f3a397c01fd10d85, whose subject explicitly included '#12750 ReferralRequest.type and .reason value set bindings'. That commit changed the then-active ReferralRequest spreadsheet, added an example ReferralType binding referencing valueset-referral-type, removed the .type comment, bound ReferralReason to http://hl7.org/fhir/ValueSet/clinical-findings, and added source/referralrequest/valueset-referral-type.xml with SNOMED CT filter concept is-a 3457005.

Additional context:
ReferralRequest is no longer an active current-build resource. Current source/fhir.ini lists servicerequest=ServiceRequest as an active resource and records that ReferralRequest became ServiceRequest. The active ServiceRequest source has example bindings on the successor concepts: ServiceRequest.code is bound to http://hl7.org/fhir/ValueSet/procedure-code, and ServiceRequest.reason is bound to http://hl7.org/fhir/ValueSet/procedure-reason, whose compose includes SNOMED clinical findings and procedure concepts. The broader ServiceRequest model now covers referrals as well as procedure and diagnostic requests, so restoring the retired ReferralRequest-only value set would be inappropriate in the current build.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The DSTU2 request was historically applied to ReferralRequest, and the current active ServiceRequest successor already has example bindings that reflect the broadened post-ReferralRequest model.

Recommendation:
Keep this audit commit as-is. No current core source edit is needed for FHIR-12750 unless Patient Care makes a new decision to reintroduce a referral-specific binding or profile for the current ServiceRequest model.
