FHIR-18665: Audit ValueSet exclude processing

Issue request:
FHIR-18665 was a Published vocab Change Request for the STU3 ValueSet page. It requested a sentence saying any compose.exclude process SHALL occur after all compose.include processing. The final Persuasive with Modification resolution intentionally reworded this as an outcome requirement: any compose.exclude SHALL be processed such that excluded codes are not found in the expansion.

Initial application:
The Jira comment identifies git 4907f9bcb0b710cb2837a93a20c4b23210a37249. That commit added the resolved sentence to source/valueset/valueset-notes.xml in the ValueSet composition rules, alongside other terminology ballot documentation updates.

Additional context:
ValueSet is an active resource in source/fhir.ini, so source/valueset/valueset-notes.xml is current build input. The current source still contains the exact outcome rule in Composition Rules and the expansion algorithm still says compose.exclude follows compose.include but removes codes instead of adding them. Community searches found no FHIR-18665-specific Zulip or Confluence discussion that changes the Jira/source conclusion; one later Vocab minutes page cites the sentence as an existing requirement in a separate supplement-rule discussion, not as a reversal.
