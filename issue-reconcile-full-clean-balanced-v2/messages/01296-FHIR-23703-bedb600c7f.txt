FHIR-23703: Audit jurisdiction security-label value set

Issue request:
FHIR-23703 was a Published FHIR-core Security work group change request, resolved Persuasive with Modification for R5, reporting that the security-labels "Jurisdiction Specific Security Labels" section pointed to a USPrivacyLaw value set whose values were deprecated. The approved resolution was to remove the FHIR-specific USPrivacyLaw value set/reference and use the v3 ActUSPrivacyLaw value set instead.

Initial application:
Git commit d97f7c47d6 applied the Security WG changes for J#25287, J#23714, and J#23703 by commenting out the jurisdiction-specific section and changing the US Privacy Law row from the old local v3/ActUSPrivacyLaw/vs.html link to terminology.hl7.org/ValueSet/v3-ActUSPrivacyLaw. Later current-branch source history in 28032417e6 removed the commented-out jurisdiction block entirely while restructuring the security-labels HCS table, leaving no rendered old USPrivacyLaw row.

Additional context:
The current security-labels page is in build scope through source/hierarchy.xml under the Security and Privacy module. The current source/security-labels.html HCS guidance no longer contains the old Jurisdiction Specific Security Labels subsection or the v3/ActUSPrivacyLaw/vs.html link. The current source/terminologies/valueset-security-labels.xml composes http://terminology.hl7.org/ValueSet/v3-ActUSPrivacyLaw. FHIR-25171 later raised the same ActUSPrivacyLaw deprecation/UTG concern and was resolved No Change because the submitter had addressed terminology changes through UTG. Security WG Confluence minutes record FHIR-23703 as recommended persuasive on 2020-01-13 and as applied to the FHIR core build on 2020-04-13. Zulip searches found no direct FHIR-23703 discussion; later ActUSPrivacyLaw discussion noted that the current FHIR security-label value sets do not point at the deprecated codes.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current authoritative source has already removed the misleading jurisdiction-specific narrative and uses the THO v3 ActUSPrivacyLaw value set where ActUSPrivacyLaw remains part of the aggregate FHIR security-label value set. Re-adding local narrative or changing the aggregate value-set composition would be broader than the Jira resolution and could reintroduce duplication with terminology/UTG ownership.

Recommendation:
Keep this no-change audit commit as-is. Future changes to the ActUSPrivacyLaw code system or value-set membership should proceed through UTG/THO rather than a FHIR-core security-labels source edit unless a new Security/Vocabulary work-group decision explicitly changes current FHIR guidance.
