FHIR-5882: Audit master-file terminology guidance

Issue request:
FHIR-5882 was a Published/Persuasive with Modification Vocabulary change request for FHIR-core ValueSet, raised and applied for DSTU1. It asked for ValueSet notes to explain that systems often treat drug tables, lab test tables, location tables, and similar master files as code tables, while FHIR separates the terminology/code-system aspect from detailed resource content. The Jira resolution endorsed the edited text at the bottom of the ValueSet notes section.

Initial application:
The Jira comments record pre-application in SVN#4442. The git-svn mirror contains commit 85c263ee7b96373b8193179b65917bbb08705be4, "Pre-applied [5882] - added language on masterfiles", which added a "Code systems with detailed metadata" section to source/valueset/valueset-notes.xml. After CodeSystem became separate from ValueSet, commit 1120eb61d0d267aae58f1da321cd5c9286dbff1d removed inline-code-system ValueSet language and moved the same detailed-metadata discussion into source/codesystem/codesystem-notes.xml.

Additional context:
ValueSet and CodeSystem are active current resources in source/fhir.ini, so source/valueset and source/codesystem are the relevant build inputs. Later Published issues refined and then superseded the old detailed-metadata prose: FHIR-12305 fixed misleading ValueSet references in the CodeSystem copy, FHIR-16335 marked the section informative and less specific, FHIR-39265 resolved to remove the old detailed-metadata/Implicit Code Systems material after finding it confusing, and Applied issue FHIR-40432 restored a rewritten Implicit Code Systems section without the medication/location/detail-resource master-file prose. FHIR-12305, FHIR-16335, and FHIR-40432 already have Issue-Reconcile-Key commits on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The original FHIR-5882 request was applied historically, then the exact guidance was moved to CodeSystem and later removed/replaced by final Vocabulary decisions. Current source/codesystem has the restored implicit-code-systems section and current source/valueset describes ValueSet as selecting codes from CodeSystems; neither currently contains the old master-file/detail-resource guidance. Reintroducing it under this DSTU1 ValueSet issue would conflict with the later CodeSystem decisions and with the modern split between CodeSystem and ValueSet.

Recommendation:
Keep this audit commit as-is. If TI wants fresh general guidance on modeling master data versus terminology properties, it should be raised as a new current-scope issue rather than restoring the old FHIR-5882 text.
