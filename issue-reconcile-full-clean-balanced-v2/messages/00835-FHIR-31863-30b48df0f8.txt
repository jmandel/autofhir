FHIR-31863: Correct packageFor boundary guidance

Issue request:
FHIR-31863 was a Published FHIR-core BR&R change request resolved as Not Persuasive with Modification for R5. It argued that MedicinalProduct, MedicinalProductPharmaceutical, MedicinalProductPackaged, and MedicinalProductManufactured should be collapsed into one resource because the resource boundaries were not justified. The final resolution rejected the collapse, stating that the issue had been discussed multiple times, documentation and justification had been improved, and the resource boundaries were appropriate.

Initial application:
No source commit explicitly tagged FHIR-31863 was found. The current source already carries the relevant R5 application through the renamed medication-definition resources, the module overview, and resource Scope and Usage text. Earlier Jira-tagged work for FHIR-31544 made the module-page guidance prominent, and FHIR-31805 added or refined contained-resource and packaging guidance that explains how simple users can use a smaller subset while complex/product-regulatory use cases keep independent resources.

Additional context:
The active current-build resources are MedicinalProductDefinition, PackagedProductDefinition, ManufacturedItemDefinition, and AdministrableProductDefinition. FHIR-28581 is the same change family and was also Published/Not Persuasive with Modification after asking to reduce the number of product-definition resource types; its comments and resolution support retaining distinct resources with better explanations. BR&R minutes from 2022-03-03 list FHIR-31863 and FHIR-28581 as the remaining in-person negatives, later resolved by the same work group vote path. Current PackagedProductDefinition source and examples use packageFor, while the boundary guidance still contained three stale productFor references from earlier documentation work.

AutoFHIR reconciliation:
This commit keeps the work group decision not to collapse the resources, and fixes the stale narrative element-path references that made part of the boundary guidance misleading. It changes MedicinalProductDefinition and PackagedProductDefinition Scope and Usage text from PackagedProductDefinition.productFor/productFor to the active PackagedProductDefinition.packageFor/packageFor element.

Recommendation:
Keep this commit as-is. The current resource split and justification text are consistent with the published decision, and the only current-spec correction needed for FHIR-31863 was to make the explanatory relationship name match the actual PackagedProductDefinition element. FHIR-28581 should not be treated as independently resolved by this commit, but the same evidence will support a separate audit if that issue is reconciled later.
