FHIR-11206: Audit AllergyIntolerance status hierarchy

Issue request:
FHIR-11206 was a Published/Persuasive with Modification Patient Care change request for DSTU2 AllergyIntolerance. It asked to remove entered-in-error from under inactive in the AllergyIntolerance.status code hierarchy, place it at the same level as active and inactive, and align AllergyIntolerance with Condition; the resolution also noted that the mixed clinical/workflow status question would be handled by FHIR-11151.

Initial application:
The issue was applied in git commit e7c9c0d32a1b91ac406c98fd0a2441fec2c625fb, whose message explicitly cites #11206 and whose AllergyIntolerance spreadsheet diff removes `Parent = #2` from the entered-in-error row. The same commit also applied related FHIR-11207 narrative wording. Later commit ed170ff0754268f2a677a011f9d432d1328415f0 applied FHIR-11151 by replacing the old combined AllergyIntolerance.status with separate clinicalStatus and verificationStatus elements.

Additional context:
source/fhir.ini actively lists allergyintolerance=AllergyIntolerance, so the checked AllergyIntolerance StructureDefinition and supporting terminology references are in current build scope. The current StructureDefinition has AllergyIntolerance.clinicalStatus bound to the clinical value set with active/inactive/resolved and AllergyIntolerance.verificationStatus bound to the verification value set with unconfirmed/presumed/confirmed/refuted/entered-in-error. Current local terminology package artifacts mirror that split: inactive has only resolved as a child in allergyintolerance-clinical, while entered-in-error is a separate top-level allergyintolerance-verification code. Condition now uses the same clinicalStatus/verificationStatus pattern with entered-in-error on verificationStatus, preserving the requested alignment. A related FHIR-11207 audit is already present on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The original hierarchy problem is gone from current core source, the current source no longer exposes a combined AllergyIntolerance.status where entered-in-error could be a child of inactive, and the current clinical/verification split conveys the issue's requested semantics without redundant edits.

Recommendation:
Keep this audit commit as-is. No current FHIR core source work is needed for FHIR-11206; future changes to the external terminology package should be handled through the normal terminology/UTG process if Patient Care reopens the status hierarchy.
