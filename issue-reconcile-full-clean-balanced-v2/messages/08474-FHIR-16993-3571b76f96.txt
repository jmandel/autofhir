FHIR-16993: Audit Media.frames meaningIfMissing removal

Issue request:
FHIR-16993 was a Published/Persuasive FHIR-core Media change request from the STU3 ballot asking to remove the Media.frames meaningIfMissing because assuming one frame made it impossible to express an unknown frame count. The accepted resolution was to remove the meaning and add a note to the comment.

Initial application:
The issue was applied in git-svn mirrored commit 7e062875383499b6039d916107ae30c5ae8d9c0b, which removed the Media.frames cell saying systems could assume one frame when absent and added the comment that an absent frame count may be unknown. Current source/media/media-spreadsheet.xml still contains that note and no Media.frames meaningIfMissing text.

Additional context:
source/fhir.ini keeps Media in the active current build, so source/media/media-spreadsheet.xml remains the authoritative source for this check. The later GF#19250 Media-to-DocumentReference work copied the same frame-count note into Attachment.frames rather than reintroducing the removed assumption. Jira search found no later Attachment.frames issue changing this conclusion. FHIR-I minutes for 2018-07-09 list FHIR-16993 in the persuasive block vote, and community searches found only bot notifications plus those minutes, with no conflicting discussion.

AutoFHIR reconciliation:
No source files were changed. The current build-scoped Media source already reflects the approved resolution: Media.frames has no meaningIfMissing/default assumption and its comment explicitly warns that absence may mean the frame count is unknown.

Recommendation:
Keep this audit commit as-is. No follow-up is needed in FHIR core unless a future issue intentionally revisits frame-count semantics for Media or Attachment.
