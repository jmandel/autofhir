FHIR-5935: Audit Break the Glass policy note

Issue request:
FHIR-5935 was a Published/Persuasive with Modification DSTU1 Security WG issue about the Security Labels Break the Glass discussion. The request argued that the simple tag/header description could be read as a complete interoperable break-glass method and omitted practical policy concerns such as notifying users, recording a reason, and after-the-fact review. The approved resolution was to add a note that the break-the-glass tag must be used as part of an agreed policy and protocol, and that FHIR does not define that policy or protocol.

Initial application:
The issue was applied in commit 1ca8cc96b8a6323b76b0d91ec3eeed92067ab06a, whose message includes #5935 and whose patch added the requested warning to source/security-labels.html: "The break the glass tag needs to be used as part of an agreed policy and protocol. FHIR does not attempt to define this policy or protocol, it must be agreed on a implementation by implementation basis."

Additional context:
Later FHIR-14192 work reworked the Break the Glass material and preserved the same normative point as broader implementation guidance: the current text says the section indicates methods to represent break-the-glass as a purpose of use, but "does not define any policy or protocol around such requests," and lists implementation responsibilities including when/how to initiate, authorization and consent checking, audit representation, and how clinicians know break-the-glass is available. FHIR-53885 then moved the Break the Glass section from Security Labels to the Security page because the examples were not security-labeling guidance; a later FHIR-53885 reconciliation fixed stale links to the moved anchor.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope Security page already conveys the approved FHIR-5935 warning and surrounding implementation concerns, while the Security Labels page correctly records that the standalone Break the Glass section moved away from label-specific guidance. Re-adding the old sentence to Security Labels would duplicate moved content and risk drifting from the later Security WG organization.

Recommendation:
Keep this no-change audit commit as-is. No further core source work is needed for FHIR-5935 unless the Security WG decides to redesign the current Break the Glass examples or policy guidance in a new issue.
