FHIR-5197: Audit PractitionerRole grouping

Issue request:
FHIR-5197 was a Published/Persuasive with Modification DSTU1 Practitioner ballot issue asking to group role, period, and location under a PractitionerRole component, with managingOrganization, role, specialty, period, location, and HealthcareService role-specific properties.

Initial application:
The issue was applied in the source history by commit 8ed9982708ac31ba37ad6670f9be8ba628634329, whose message explicitly lists tracker 5197 and describes the Practitioner Role section change. That commit introduced Practitioner.practitionerRole and nested the role-related fields under it in the Practitioner spreadsheet and examples.

Additional context:
Later source history changed the representation without reversing the issue's substance: commit ffe864085b20ebb8750d1cb35a7cab404608f944 added a draft standalone PractitionerRole resource to be extracted from Practitioner, and commit 485ed5cfca20db7b56d9dfb56fbe19c15e3c7641 performed Practitioner Role cleanup after approval in San Antonio. In the current build, source/fhir.ini actively includes both Practitioner and PractitionerRole, Practitioner has no legacy role/practitionerRole element, and PractitionerRole carries the role-specific period, practitioner, organization, code, specialty, location, and healthcareService elements.

AutoFHIR reconciliation:
This commit makes no source change because the current specification already preserves the approved modeling outcome. The modern standalone PractitionerRole resource is the current representation of the original role grouping, and adding an embedded Practitioner component or reverting cardinalities from later decisions would be wrong for the current build.

Recommendation:
Keep this no-change audit commit. Future work should treat any desired changes to current PractitionerRole cardinalities or narrative as separate PA work items rather than as unfinished application of FHIR-5197.
