FHIR-19767: Audit migrated LOINC STATUS property

Issue request:
FHIR-19767 was a Published/Persuasive Vocabulary WG change request for STU3 to change the LOINC STATUS property type from code to string and to fix the "LOINC tables fields" wording. The Jira resolution approved the change as pre-applied.

Initial application:
The issue was pre-applied in git commit 9a9bf70d87, which updated the then-current source/loinc.html page so the LOINC Properties table said STATUS was string and changed "LOINC tables fields" to "LOINC table fields". That commit did not update source/codesystem/loinc.xml, which already contained a separate STATUS property row and currently still says boolean.

Additional context:
The old source/loinc.html page was later removed by FHIR-35933 during the external terminology page migration, and the current build-scoped source/terminologies-systems.html page links LOINC usage guidance to THO. The active current THO LOINC page documents the same LOINC Properties table with STATUS as string. source/codesystem/loinc.xml is still tracked, but it is not listed in source/fhir.ini [codesystems], no current source reference to codesystem/loinc.xml was found, and publish.ini lists terminologies-systems.html rather than the removed loinc.html page.

AutoFHIR reconciliation:
No source change was made. Editing the stale, unreferenced source/codesystem/loinc.xml file would not correct the current FHIR build, while the build-scoped FHIR source points implementers to the authoritative THO page that already preserves the FHIR-19767 STATUS=string decision.

Recommendation:
Keep this empty audit commit as-is. No FHIR-core follow-up is needed for FHIR-19767; if future work wants to delete or refresh the unreferenced source/codesystem/loinc.xml artifact, that should be handled as a separate cleanup or build-scope decision rather than as this applied STU3 issue.
