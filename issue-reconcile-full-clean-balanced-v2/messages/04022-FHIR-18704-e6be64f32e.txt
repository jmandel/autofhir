FHIR-18704: Audit ValueSet ActiveOnly inactive mapping

Issue request:
FHIR-18704 was a Published/Persuasive vocab change request for STU3 asking the ValueSet compose.inactive documentation to note that the Value Set Definition ActiveOnly flag uses the opposite polarity: VSD.ActiveOnly=TRUE is equivalent to ValueSet.compose.inactive=FALSE.

Initial application:
The Jira records Grahame's application comment pointing to git 4907f9bcb0b710cb2837a93a20c4b23210a37249. That terminology ballot documentation commit mentions GF#18704 and added the ActiveOnly/compose.inactive equivalence to the ValueSet spreadsheet source. Later source restructures preserved the relationship in current build-scoped ValueSet source.

Additional context:
ValueSet is an active resource in source/fhir.ini, so source/valueset/structuredefinition-ValueSet.xml and the resource notes are current build inputs. The current ValueSet.compose.inactive element comment states that ActiveOnly is the reverse of compose.inactive, and the ValueSet Alignment with VSD notes include an "Include Active Concepts Only" subsection with the same equivalence. Direct community searches for FHIR-18704 found no Zulip or Confluence records that change the Jira/source conclusion; broader term hits did not identify conflicting guidance.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current specification already documents the requested relationship in the ValueSet element definition comments and in the VSD alignment notes, and adding another restatement would be redundant.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-18704 unless the Vocab work group later changes the VSD/FHIR mapping itself.
