FHIR-7488: Audit retired DataElement population clarification

Issue request:
FHIR-7488 was a Published/Persuasive with Modification FHIR-core DSTU1 ballot issue for the DataElement resource. It asked whether DataElement links implied that Questionnaire servers must understand and validate any declared DataElement, and the accepted resolution was to clarify that servers populate what they recognize by data elements while unknown data elements are not an error.

Initial application:
The issue was applied in git commit 29ccb4aa1d2847ac036097f077b0927ea3081ecb, whose message cites #7488 and svn revision 6458. That commit changed source/dataelement/dataelement-notes.xml to add the requested clarification to the old DataElement notes section.

Additional context:
DataElement is no longer a current core resource. Later Published issue FHIR-13094 resolved to remove DataElement and replace it with StructureDefinition logical models, and the current build configuration keeps DataElement commented out in the resource, work-group, TLA, and compatibility rename entries. The source/dataelement directory is absent. The active Questionnaire source now carries the analogous current guidance through Questionnaire.item.definition, which refers to ElementDefinition or ObservationDefinition and documents derivation/pre-population behavior without relying on the retired DataElement resource.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The FHIR-7488 wording was historically applied to the DataElement page, but that page is no longer in the current build; adding the old DataElement server-population wording to unrelated active pages would restate a retired-resource clarification and risk drifting from the current Questionnaire/StructureDefinition model.

Recommendation:
Keep this no-change audit commit as-is. No current FHIR-core source edit is needed for FHIR-7488 unless a maintained historical branch for the retired DataElement page is explicitly being updated; future current-build guidance should stay aligned with Questionnaire.item.definition and StructureDefinition logical-model guidance.
