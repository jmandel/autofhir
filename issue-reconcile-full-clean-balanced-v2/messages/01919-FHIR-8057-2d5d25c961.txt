FHIR-8057: Audit document class retention

Issue request:
FHIR-8057 was a Published, Not Persuasive with Modification DSTU1 FHIR-core change request for Composition and DocumentReference. It asked to remove Composition.class and DocumentReference.class from core as MHD/XDS-only metadata; the final decision rejected removal, found class/category not redundant with type, and asked for better class/type documentation plus an example value set based on the LOINC Document Kind hierarchy.

Initial application:
The Jira application comment cites svn revision 5993, represented in git by 995666d69f5f472f2f493a231edee9c2be1c967e. That commit kept the class element in core, changed the Composition.class binding name from DocumentC80Class to DocumentClass, and added source/composition/valueset-doc-classcodes.xml with LOINC Document Kind LP codes. The documentation part had already been handled by the closely related FHIR-5561 application commit a4f7d63ab329bf6443e65c4ec50d5d88c53c029e, which clarified Composition.class and DocumentReference.class/type wording.

Additional context:
Later final issues changed the surface without reversing the FHIR-8057 decision. FHIR-11907 found the old LOINC Part-code list unsuitable as exchangeable codes and aligned the Composition and DocumentReference class value sets. FHIR-17171 and FHIR-17555 renamed DocumentReference.class and Composition.class to category and increased cardinality to 0..*. FHIR-32577 then renamed document-classcodes to referenced-item-category because DocumentReference can reference more than documents. Composition and DocumentReference remain active resources in source/fhir.ini, and fhir.ini maps the old class element names to the current category elements.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current authoritative source defines Composition.category and DocumentReference.category, not the removed old class names, and both current category elements bind to http://hl7.org/fhir/ValueSet/referenced-item-category. That active value set includes media-category plus LOINC codes filtered by DOC scale type, preserving the current evolved document-category example binding. Editing the unreferenced legacy Composition valueset-doc-categorycodes.xml file or reintroducing XDS/MHD-specific class prose would not improve current build behavior.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-8057; separate audits or work-group review, not this seed, should handle any future cleanup of the old unreferenced valueset-doc-categorycodes.xml file or broader category terminology questions.
