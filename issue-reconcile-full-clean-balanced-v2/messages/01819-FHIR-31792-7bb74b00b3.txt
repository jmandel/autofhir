FHIR-31792: Remove stale packaged authorization ModelInfo

Issue request:
FHIR-31792 was a Published/Persuasive with Modification BRR change request for R5. It said the marketing authorization should point to the packaged product rather than PackagedProductDefinition carrying a back-reference to the authorization, and the resolution agreed to change the reference direction while noting related bidirectional-link issues FHIR-31782, FHIR-31859, and FHIR-31862.

Initial application:
The issue was explicitly applied before this reconciliation. Commits 05841da3edffbd41949d8547c323362859a1e998 and a404d9f6bc55cfff0a33603371eb935e919031c7 removed PackagedProductDefinition.marketingAuthorization and the RegulatedAuthorization target from the PackagedProductDefinition StructureDefinition. Commits dc008bd65482b3817a2a818883be30aa83d77986 and f16b0ee38e70c7e874b1330dc0c8624becc7f8d8 made RegulatedAuthorization.subject 0..*. Current authoritative resource definitions therefore already have RegulatedAuthorization.subject as the product-facing reference and lack the packaged-product authorization back-link.

Additional context:
source/fhir.ini keeps PackagedProductDefinition, RegulatedAuthorization, and Library in the current build. source/library/list-Library-examples.xml lists Library/library-fhir-model-definition as the active FHIR ModelInfo Library. That active computable surface still exposed the old MedicinalProductPackaged.marketingAuthorization element, even though the current PackagedProductDefinition source and RegulatedAuthorization source had already been corrected. BRR minutes on 2021-07-13 record agreement to change the direction of the reference, and 2021-08-03 minutes record FHIR-31792 as persuasive with the related issues identified. Zulip searches found no conflicting discussion.

AutoFHIR reconciliation:
Removed the stale marketingAuthorization element from source/library/library-fhir-model-definition-content.xml and refreshed the embedded base64 attachment in source/library/library-fhir-model-definition.xml so the active FHIR ModelInfo Library no longer advertises the removed packaged-product authorization back-link.

Recommendation:
Keep this source fix. It completes the FHIR-31792 application in the current build without expanding into the broader legacy MedicinalProductPackaged versus PackagedProductDefinition ModelInfo naming cleanup or separately deciding the related bidirectional-link issues.
