FHIR-8826: Audit historical entered-in-error guidance

Issue request:
FHIR-8826 was Published with a Persuasive with Modification resolution for DSTU2. It asked for a standardized way to flag historical resource versions as "entered in error" and resolved to document that Provenance should be used for a past version, that multiple Provenance instances may exist for a version, and that clients tracing history should retrieve Provenance for the resource or its versions. The resolution also distinguished whole-record entered-in-error status from documenting a historical version as erroneous.

Initial application:
The issue appears to have been applied by git-svn commit ea40a685d3c475a4d356d4aec37cdfd7dfbf2e61, "#8826 - notes about past history", corresponding to SVN build@8038 and the Jira comment. That commit added the HTTP history-page notes saying past versions cannot be updated/deleted, Provenance should point to a past version when it needs to be documented as entered-in-error, and applications tracing history should retrieve related Provenance resources.

Additional context:
The current build retains the history-page guidance in source/http.html. The Provenance resource introduction now explicitly says Provenance can target any resource or version, including past versions, and that multiple Provenance records may exist for a resource or version. The current lifecycle page describes entered-in-error as a whole-resource state. Later R6 Provenance work, including FHIR-53917 and FHIR-53783, further refined correction/removal guidance and added a relevant-history profile and activity value set containing a NULLIFY/Mark Entered-in-error code, but those later Applied issues are separate Security WG changes and were not decided here.
