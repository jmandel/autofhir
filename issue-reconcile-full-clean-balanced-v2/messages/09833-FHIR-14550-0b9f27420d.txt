FHIR-14550: Audit mandatory Bundle request rule

Issue request:
FHIR-14550 was a Published/Persuasive STU3 FHIR-I change request for FHIR-core. It asked to remove the optionality of Bundle.entry.request for transaction and batch Bundle entries so servers no longer infer create/update intent, and to enforce the rule with an invariant; it also noted that then-current transaction/batch fullUrl wording needed separate clarification.

Initial application:
The issue appears to have been applied by git-svn commit c613b68f9b76a6d4f114766f447107ba47643a62, matching the Jira comment for svn revision 13906. That commit changed the historical Bundle spreadsheet invariant from request merely being allowed for batch/transaction/history to request being mandatory for those Bundle types, and changed the Bundle transaction/batch narrative to remove the no-request inference path. The spreadsheet source was later replaced/refactored into source/bundle/structuredefinition-Bundle.xml.

Additional context:
Bundle is an active resource in source/fhir.ini and source/hierarchy.xml includes both the Bundle resource page and source/http.html RESTful API page in the current build. Later commit 7fd7b9ce04e0675f40e902ba468f696a851dd51a split the old request/response invariant into current bdl-3a through bdl-3d constraints while preserving the transaction/batch request requirement as bdl-3c. FHIR-14551, already represented on the combined branch, audited the related RESTful API paragraph that now says each batch/transaction entry SHALL carry Bundle.entry.request details. FHIR-17170, also already represented, audited the fullUrl clarification that FHIR-14550 called out as separate related work. A direct Zulip/Confluence search found no FHIR-14550-specific contrary community record; a later implementers thread confirms the community interpretation that missing transaction request blocks are invalid.

AutoFHIR reconciliation:
This audit commit makes no source change. The current Bundle StructureDefinition has bdl-3c requiring every transaction or batch entry to have request.method, which enforces the presence of Bundle.entry.request and the explicit HTTP method; the RESTful API page also says each batch/transaction entry SHALL carry request details and requires resource bodies for PUT/POST. Current transaction and batch Bundle profiles require Bundle.entry.request within each method slice.

Recommendation:
Keep this no-change audit commit as-is for FHIR-14550. No further core source edit is needed; related FHIR-14551 and FHIR-17170 audit records should remain separate because they cover the adjacent REST paragraph and fullUrl wording rather than the seed invariant itself.
