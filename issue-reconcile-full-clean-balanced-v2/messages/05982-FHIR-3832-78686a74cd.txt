FHIR-3832: Audit Appointment patient search parameter

Issue request:
FHIR-3832 was a Published/Persuasive PA change request asking for an Appointment patient/subject search parameter so implementers could retrieve appointments for a patient and support patient compartment-style queries.

Initial application:
No Jira-tagged FHIR-3832 source commit was found in current git history. The active current source already contains an Appointment-patient SearchParameter, and the old source rewrite history shows the Appointment-patient definition carried into the current XML search-parameter bundle. Later Appointment work added Appointment.subject and expanded Appointment-patient to include patient-valued subject references as well as patient participant actors.

Additional context:
Appointment is an active resource in source/fhir.ini, and source/appointment/bundle-Appointment-search-params.xml is the active search-parameter bundle for that resource. FHIR-14803 later rejected replacing Appointment.participant with a direct patient element and explicitly relied on the specific patient search parameter. The current Patient compartment spreadsheet row for Appointment uses actor for Patient and subject | actor for Group; a 2023 Zulip follow-up and FHIR-56547 show newer compartment questions around AppointmentResponse/patient-vs-subject remain unresolved and should not be folded into this DSTU1 audit. FHIR-36674 is a broad R5 registry alignment issue, not a bounded Appointment-only decision for this seed.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Appointment search bundle already defines code="patient" as a reference SearchParameter targeting Patient with expression Appointment.participant.actor.where(resolve() is Patient) | Appointment.subject.where(resolve() is Patient), and also defines the requested subject search parameter. Adding redundant prose or changing unresolved compartment policy would go beyond FHIR-3832.

Recommendation:
Keep this audit commit as-is for FHIR-3832. Do not change Appointment for this seed unless a future final PA/FHIR-I decision resolves the newer compartment questions around patient-vs-subject membership or AppointmentResponse.
