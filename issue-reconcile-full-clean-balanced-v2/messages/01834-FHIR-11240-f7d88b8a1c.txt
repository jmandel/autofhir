FHIR-11240: Audit retired Sequence window-end clarification

Issue request:
FHIR-11240 was a Published/Persuasive Clinical Genomics change request for the DSTU2 FHIR-core Sequence resource. It asked to clarify the Sequence coordinate-system end-position wording so implementers would not read every end coordinate as exclusive: for 0-based coordinates the end is exclusive, while for 1-based coordinates the end is inclusive. The final resolution specifically accepted changing both the short description and long definition, with the preview target at Sequence.referenceSeq.windowEnd.

Initial application:
The historical application was commit d830ddede2fa70d5f6ccca85e723caa4a2c7a7bf, "#11235 #11236 #11239 #11240 Change description related with Sequence.coordinateSystem to be more accurate." It changed source/sequence/sequence-spreadsheet.sheet.txt and source/sequence/sequence-spreadsheet.xml so Sequence.referenceSeq.windowEnd says "End position of the window on the reference sequence" and defines 0-based ends as exclusive and 1-based ends as inclusive. The same commit applied parallel coordinate-system start/end clarifications for the same issue family.

Additional context:
The original Sequence source path is no longer present in the current build. Sequence is listed as a removed resource in source/fhir.ini, molecularsequence is commented out, and moleculardefinition is the active Clinical Genomics resource. Later MolecularSequence work was superseded by the MolecularDefinition replacement work; the current MolecularDefinition source has a different coordinateInterval model with CodeableConcept coordinate-system examples such as 1-based character counting and 0-based interval counting, not the old Sequence.referenceSeq.windowEnd element. Historical release3 artifacts still preserve the applied Sequence wording, while current source has no active Sequence.referenceSeq.windowEnd target to edit.

AutoFHIR reconciliation:
This commit intentionally makes no source change. FHIR-11240 was applied to the then-current Sequence source, and the current build no longer exposes the affected Sequence element. Copying the old referenceSeq.windowEnd prose into MolecularDefinition would be a model-porting change, not a reconciliation of the published DSTU2 Sequence clarification.

Recommendation:
Keep this audit commit as-is. No current FHIR-core source follow-up is needed for FHIR-11240; if implementers find ambiguity in MolecularDefinition coordinateInterval semantics, handle it as a new MolecularDefinition-specific Clinical Genomics issue rather than resurrecting retired Sequence wording.
