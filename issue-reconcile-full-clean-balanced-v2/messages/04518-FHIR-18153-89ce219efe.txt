FHIR-18153: Audit CodeSystem fragment partition wording

Issue request:
FHIR-18153 was a Published Vocabulary change request for STU3 asking whether CodeSystemContentMode needed a separate partition content mode. The final Not Persuasive with Modification resolution said to clarify the definition of fragment in the codesystem-content-mode value set to indicate that it may also be known as a code system partition, and to add SNOMED CT guidance explaining how this works.

Initial application:
The issue was initially applied by git commit 66ae1e40f1bc02283363c872db14035fc795f8f7, which changed the historical CodeSystem spreadsheet so the fragment definition ended with "Fragments are also known as partitions" and added SNOMED CT text describing overlapping fragments. In the 2021 source rework, that partition sentence was carried into source/codesystem/codesystem-codesystem-content-mode.xml.

Additional context:
Later Vocabulary/Terminology review revisited this exact interpretation. The 2024 Terminology Fundamentals minutes state that FHIR-18153 led to defining fragments as partitions but the group disagreed, and the R6 Terminology Content Review records that the FHIR-18153 wording generated an error because Code System fragments are not synonymous with partitions. Jira FHIR-33947 was Applied for R6 and explicitly replaced the whole fragment definition with the current shorter definition, removing the partition synonym. Jira FHIR-35933 separately removed the old "Using SNOMED CT with FHIR" page from core because external-code-system guidance moved to HL7 Terminology; core now keeps only a SNOMED CT usage summary and links to THO for authoritative SNOMED guidance.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope CodeSystem content-mode source matches the later FHIR-33947 decision, and restoring the FHIR-18153 partition synonym would reintroduce wording that later Vocabulary/Terminology review identified as erroneous. The remaining CodeSystem and ValueSet narrative still discusses fragments and SNOMED CT without making the CodeSystemContentMode fragment definition synonymous with partitions.

Recommendation:
Keep this audit commit as-is. Do not re-add "partition" as a synonym in the CodeSystemContentMode fragment definition for this seed; any further ValueSet fragment behavior changes should follow the later fragment tickets such as FHIR-48959 once they are applied/published.
