FHIR-15724: Audit ExpansionProfile fixedVersion system type

Issue request:
FHIR-15724 was a Published/Persuasive vocabulary change request for STU3 asking that ExpansionProfile.fixedVersion.system be changed back from canonical(CodeSystem) to uri because it follows the same kind of code-system identifier as Coding.system.

Initial application:
The Jira comments say the change was pre-applied in svn revision 13313. Git history confirms commit 51ade094c17ae71888887de9e49a5f40effdbf38 made exactly that source change in source/expansionprofile/expansionprofile-spreadsheet.xml, replacing canonical(CodeSystem) with uri for ExpansionProfile.fixedVersion.system. The preserved release-3 profile artifact in tools/history/release3/profiles-resources.xml now shows ExpansionProfile.fixedVersion.system with type uri.

Additional context:
ExpansionProfile is no longer an active resource in the current build. source/fhir.ini keeps only a commented historical note, "; ExpansionProfile=approved -> dropped", and current source searches find no active ExpansionProfile.fixedVersion source. The later GF#16337/FHIR-16337 and GF#16490 trail removed ExpansionProfile and moved relevant expansion controls into ValueSet $expand parameters; those successor parameters are separate current-build material and do not require changing the removed STU3 element.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The requested STU3 correction is already reflected in the preserved historical artifact, and the affected ExpansionProfile source is outside the active current build because the resource was removed.

Recommendation:
Keep this audit commit as-is. Revisit only if the project decides to regenerate historical STU3 artifacts from a different source or to reintroduce ExpansionProfile; otherwise no current FHIR source edit is needed for FHIR-15724.
