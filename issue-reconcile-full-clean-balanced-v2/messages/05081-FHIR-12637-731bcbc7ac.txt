FHIR-12637: Audit Timing event usage wording

Issue request:
FHIR-12637 was a Published/Persuasive MnM change request for DSTU2 asking to remove the Timing datatype sentence that said Timing schedules are not used for recording when things did happen, but only when they are expected or requested to occur.

Initial application:
The issue was explicitly applied in historical git-svn commit ed9e3b435c3f18ca0557747fbeb01b18b05619b1, whose message references #12637 and svn revision 11269. That commit removed the prohibitive sentence from source/datatypes.html and updated source/datatypes/timing.xml to allow planned, expected, requested, and past regular-activity timing schedules.

Additional context:
Timing remains an active datatype in source/fhir.ini and is marked normative. The current source/datatypes.html Timing introduction no longer contains the prohibited-use sentence and now says Timing may represent a summary of a past or ongoing event. The later Published/Persuasive FHIR-13231 decision, already audited on the combined branch, refined the same Timing event-use family with broader future/current/past wording rather than reversing FHIR-12637. Zulip discussion around GF#12637 confirms the original concern that simply deleting the sentence required broader Timing definition updates; no Confluence search found conflicting evidence.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change because the current active Timing source already satisfies FHIR-12637 when read with the later FHIR-13231 refinement. Reintroducing or further editing this text would be redundant editorial churn rather than a necessary current-spec correction.

Recommendation:
Keep this no-change audit as-is. No core FHIR follow-up is needed for FHIR-12637 unless a future work-group decision reopens Timing semantics for event resources.
