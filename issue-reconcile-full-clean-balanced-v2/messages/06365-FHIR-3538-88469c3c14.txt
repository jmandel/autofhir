FHIR-3538: Audit CarePlan activity tense application

Issue request:
FHIR-3538 was Published with a Persuasive with Modification resolution for DSTU1. The request noted inconsistent tense in CarePlan.activity.simple element descriptions and asked whether the resource conveyed past as well as future activity; Patient Care resolved that all activity properties except "action resulting" should be expressed in future tense.

Initial application:
The historical application is the 2015 git-svn commit db4ace37c6615c9732f958d34d6286fe739fc657, which explicitly lists {#3538} among PC-approved CarePlan change requests. That commit removed the old CarePlan.activity.simple shape from the CarePlan spreadsheet, kept actionResulting as the resulting-action exception, and made the inline activity/detail wording future-oriented, such as "Action to occur as part of plan" and "Identifies a planned action to occur as part of the plan."

Additional context:
CarePlan is still an active resource in source/fhir.ini. Later Patient Care decisions changed the relevant activity model: FHIR-26064 renamed activity.outcome/reference/detail into performedActivity, plannedActivityReference, and plannedActivityDetail to clarify performed versus planned activity, and FHIR-39101 then removed the active plannedActivityDetail inline backbone in favor of plannedActivityReference. Current CarePlan source has no active CarePlan.activity.simple, activity.detail, or plannedActivityDetail element once XML comments are excluded; the active activity children are performedActivity, progress, and plannedActivityReference.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build no longer exposes the DSTU1 simple activity element that FHIR-3538 targeted, and the current performed/planned split is a later approved model rather than an uncorrected tense inconsistency.

Recommendation:
Keep this audit commit as-is. If Patient Care wants different current guidance about CarePlan.activity mixing performed and planned activities, that would be a new model/wording decision, not a pending application of FHIR-3538.
