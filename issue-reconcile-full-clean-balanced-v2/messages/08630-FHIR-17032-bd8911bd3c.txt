FHIR-17032: Audit mapping log support

Issue request:
FHIR-17032 was a Published/Persuasive with Modification FHIR-I change request from STU3. It asked for the mapping language to explicitly declare when source content is unknown or lost in conversion, using Binary.securityContext in historical version maps as the motivating example. The approved resolution was to add a log "xxx" as part of the source statement and make the make/target part optional when a log part is present.

Initial application:
Jira records application as svn revision 14038. In git history this is commit d9c2be4be8, `GF#17032 - add logging to mapping language`, which added the mapping-language Log Statement section. The current branch contains that commit. Later mapping-language edits retained the feature while normalizing embedded FHIRPath expression syntax.

Additional context:
The current build still includes StructureMap as an active resource in source/fhir.ini and includes mapping-language.html in source/hierarchy.xml under Implementation Support. The current source also has StructureMap.group.rule.source.logMessage and StructureMap.group.rule.target with min=0. The original Binary version-map page was a historical STU3/R2/R3 application concern and is not present as current build source; the durable current-spec requirement is the mapping-language/StructureMap capability. FHIR-17710, already represented on the combined branch, audited the related request for log examples. FHIR-20841 later required parentheses around embedded FHIRPath expressions, and FHIR-39486 later kept `log` as the mapping-language keyword while documenting equivalence to FHIRPath trace().

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current mapping-language.html documents `log` as part of each source statement, gives literal and FHIRPath examples, explains where it runs in relation to where/check, and states that rules can have no target transform. The active StructureMap abstract syntax and mapping.g4 grammar likewise support source log messages and optional target transforms.

Recommendation:
Keep this audit commit as-is. If someone wants historical Binary conversion maps to emit specific securityContext messages, that should be handled as a separate conversion-registry or historical transform task, not as unfinished application of FHIR-17032 in the current core source.
