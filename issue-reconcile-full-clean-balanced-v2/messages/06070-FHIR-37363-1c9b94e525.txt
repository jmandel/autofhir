FHIR-37363: Audit Questionnaire unit extension guidance

Issue request:
FHIR-37363 is Published/Persuasive with Modification for FHIR-core Questionnaire. It asked that questionnaire-unitOption and questionnaire-unitValueSet clarify that, when an answer is provided, the QuestionnaireResponse valueQuantity must use one of the allowed units: Quantity.code/system match the allowed Coding code/system when those are present, display-only Codings fall back to Quantity.unit, display/unit mismatches may warn, and unitValueSet validation may use $validateCode.

Initial application:
The issue was applied in core by 2753aeaa53, which added the requested guidance to source/questionnaire/structuredefinition-extension-questionnaire-unitOption.xml and source/questionnaire/structuredefinition-extension-questionnaire-unitValueSet.xml. Those core files were later removed by dd468d4f17 as part of removing extension definitions from the R5 source, and the Extension Pack initial import 4087c90 carried forward the same comments.

Additional context:
The current core checkout actively builds Questionnaire, but it no longer owns the two extension StructureDefinitions; searches find only the OID registry entries and a Questionnaire item-type definition that references their URLs. The active Extension Pack source includes input/definitions/* and currently contains questionnaire-unitOption and questionnaire-unitValueSet with the FHIR-37363 code/system/unit guidance intact. The linked Zulip thread provided the validation/display context, and the FHIR SDC 2022-07-07 minutes record the persuasive-with-modification decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change in core. The authoritative current extension definitions are outside the core checkout and already contain the required language, while the remaining core references are not misleading and do not duplicate extension-level validation rules.

Recommendation:
Keep this audit commit as-is. If future edits to the unitOption/unitValueSet guidance are needed, make them in the FHIR Extension Pack; no core follow-up is needed for FHIR-37363.
