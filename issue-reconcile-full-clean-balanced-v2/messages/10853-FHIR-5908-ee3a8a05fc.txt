FHIR-5908: Audit extension context placement

Issue request:
FHIR-5908 was a Published/Persuasive FHIR-core change request asking that the context where an extension can be used be made more obvious, preferably near the top of each extension definition under the extension URL.

Initial application:
The Jira comments identify svn revision 4539. The imported git commit 465b04a3a62118caa464d86396fce67add7a69e4 is that revision and added the <%context-info%> placeholder to source/template-extension.html, backed by describeExtensionContext rendering support in the old publisher code.

Additional context:
The current source has moved the extension template to tools/templates/template-extension.html, and the template now places the official URL in the top metadata block and renders <%context-info%> before the Definition section. Active [profiles] entries in source/fhir.ini still feed FHIR-core extension definitions through this template family. The StructureDefinition resource definition also explicitly describes StructureDefinition.context as the extension-use context and points to the Defining Extensions guidance. No Zulip or Confluence evidence was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:
No source change was made. The current template already makes extension context prominent near the top of extension pages, before the descriptive definition, so moving or duplicating the context would be editorial churn rather than a necessary current-spec correction.

Recommendation:
Keep this audit commit as-is. Revisit only if a future rendered core extension page loses the Context of Use section or places it below the extension definition/content in a way that obscures where the extension can be used.
