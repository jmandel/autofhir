FHIR-10580: Audit test-data guidance

Issue request:
FHIR-10580 was a Published/Persuasive with Modification Security WG change request asking how completely fabricated test data should be identified and whether security tags were legitimate for that use. The approved resolution asked for an informative "Using FHIR to publish test data" section on the Security and Privacy module page, covering isolated test-data systems, integrated systems with HTEST security labeling, integrated systems with test-patient indicators, and the risk of accidentally using co-mingled test data.

Initial application:
The issue appears to have been applied by git commit df8241d8ed19f08b12c18f34bf71c7bdbf611ef9, whose subject explicitly included GF#10580 and which added the requested test-data section to source/secpriv-module.html. Later QA commits adjusted wording and normative keyword casing, but preserved the substance of the approved guidance.

Additional context:
The current source/hierarchy.xml includes secpriv-module.html as the active Security and Privacy module page, and source/secpriv-module.html includes both a table-of-contents link to Security Considerations on Test Data and the requested section. The linked 2016 Zulip discussion shows the alternatives that the section now summarizes: isolated environments, ordinary tags or security labels, test-patient identifiers, and the operational risk of co-mingling test records with production data. A Confluence search found no conflicting work-group minutes or later decision for FHIR-10580.

AutoFHIR reconciliation:
This audit commit intentionally makes no source changes. The current build-scope Security and Privacy module already conveys the requested guidance, including that test data MAY be fabricated/synthetic, MAY need identification, can be isolated or co-mingled, can use PurposeOfUse HTEST or test-patient indicators, and carries accidental-use risk when co-mingled with real patient data.
