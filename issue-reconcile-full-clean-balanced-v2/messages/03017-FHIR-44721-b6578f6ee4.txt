FHIR-44721: Audit vital signs component UCUM binding

Issue request:
FHIR-44721 is an Applied/Persuasive with Modification OO change request, raised against R5 and applied for R6, asking to remove the overly narrow required binding on Observation.component.valueQuantity in the Vital Signs profile. The approved resolution was to change the binding for Observation.component.valueQuantity to the all-UCUM value set http://unitsofmeasure.org/vs.

Initial application:
No source commit found during this reconciliation explicitly names FHIR-44721. Jira comments state that the FHIR-47136 application, specifically git fb9f069 on 2025-03-16, had already changed Observation.component.valueQuantity to http://unitsofmeasure.org/vs and therefore satisfied the approved FHIR-44721 resolution.

Additional context:
FHIR-44721 is directly linked to FHIR-47136. The source hunk is in the active Observation Vital Signs IG and the current base vitalsigns StructureDefinition declares Observation.component.value[x]:valueQuantity with a preferred UCUM binding to http://unitsofmeasure.org/vs. The linked Zulip thread records the implementer problem: oxygen saturation components such as flow rate use UCUM units outside the old small vital-signs set, and participants agreed the limited required binding was too constraining. OO minutes on 2024-02-23 record the motion to bind to http://unitsofmeasure.org/vs instead of the constrained required list.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope base vital signs source already uses http://unitsofmeasure.org/vs for Observation.component.value[x]:valueQuantity, matching the approved FHIR-44721 resolution, and no later source or community evidence found during this bounded check requires a different core edit.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-44721 unless OO later decides to replace the all-UCUM binding with a new scoped vital-sign component unit mechanism.
