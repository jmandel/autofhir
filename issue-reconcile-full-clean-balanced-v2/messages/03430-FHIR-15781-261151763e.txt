FHIR-15781: Audit AllergyIntolerance recorded date wording

Issue request:
FHIR-15781 was Published with a Persuasive with Modification resolution for STU3 AllergyIntolerance.assertedDate. It asked Patient Care to clarify that the ambiguous asserted date was the date the allergy record was first recorded/created in the system, not onset, provider learning date, or later resource update time.

Initial application:
The issue was applied in git commit 722ed5c93f, which explicitly listed GF#15781 with GF#17285 and changed AllergyIntolerance from assertedDate in the core resource to recordedDate in core, with assertedDate moved to an extension. The current source no longer has AllergyIntolerance.assertedDate in the AllergyIntolerance resource and still records GF#15781/GF#17285 in the recordedDate committee notes.

Additional context:
FHIR-17285 superseded FHIR-15781 and made the broader Patient Care decision to separate assertion semantics from recording semantics for both AllergyIntolerance and Condition. Later Published issues, especially FHIR-34396 following FHIR-27808, refined the current AllergyIntolerance.recordedDate short text and comments, including preserving a sending system's recordedDate when known and contrasting recordedDate with recorder/asserter roles.

AutoFHIR reconciliation:
This audit commit makes no source change. The active current source already has AllergyIntolerance.recordedDate in the build-scoped AllergyIntolerance resource, with wording that conveys the intended created/first-recorded semantics and later clarifications. Editing it back toward the original FHIR-15781 prose would conflict with the superseding/current issue family.

Recommendation:
Keep this no-change audit as-is for FHIR-15781. If further work is desired, evaluate the broader recordedDate/asserter issue family separately rather than changing this seed in isolation.
