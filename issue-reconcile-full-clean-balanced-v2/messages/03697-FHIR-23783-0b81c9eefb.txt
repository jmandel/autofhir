FHIR-23783: Audit filter operator VSD additions

Issue request:
FHIR-23783 was a Published/Persuasive with Modification Vocabulary WG R5 change request for FHIR-core ValueSet. It asked to fill VSD mapping gaps in the required FilterOperator binding by adding operators for DirectRelationsOnly with IncludeHeadCode=false and TransitiveClosureLeaves with IncludeHeadCode=false, while supporting the corresponding IncludeHeadCode=true cases by adding a separate ValueSet.compose include for the head code itself rather than creating two more operators.

Initial application:
The R5 application happened across several vocabulary commits. Commit 054eabf3116825c0f65107fedff6668447bf43a1 added child-of to source/valueset/codesystem-filter-operator.xml after an earlier reverted attempt, commit b0172dd266bc5061422826c714e77a6d3c559296 explicitly listed FHIR-23783 and added descendant-leaf, and commit 732b40c16876bd7f23e75b50253824d920485f4e corrected that newly added code to the published spelling descendent-leaf while adding the matching narrative row. The current ValueSet includes the complete http://hl7.org/fhir/filter-operator code system, so these CodeSystem concepts are included in the bound value set.

Additional context:
ValueSet is an active resource in source/fhir.ini, and the current source/valueset/structuredefinition-ValueSet.xml and source/codesystem/structuredefinition-CodeSystem.xml required-binding summaries include child-of and descendent-leaf. The checked-in R5 history contains both codes, while R4/R4B history does not, matching the issue's R5 application target. Related FHIR-36644 later reused the same child-of and descendent-leaf operators in the CodeSystem common concept-filter guidance and is already represented on the combined branch. Later FHIR-39264 and FHIR-49057 confirm that the descendent spelling family is a normative/backward-compatible code-spelling issue, not a reason to rename current codes.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current build-scoped filter-operator CodeSystem already defines child-of and descendent-leaf with the requested DirectRelationsOnly-without-head and TransitiveClosureLeaves-without-head semantics, and the filter-operator ValueSet includes those codes via the complete code system. Adding child-and-self or leaf-and-self now would contradict the published modification that chose separate includes for the head-code cases.

Recommendation:
Keep this no-change audit commit. The current core source satisfies FHIR-23783; future changes to add explicit self-including operators or rename descendent/descendant spellings should be handled as new Vocabulary WG terminology decisions, not as this reconciliation.
