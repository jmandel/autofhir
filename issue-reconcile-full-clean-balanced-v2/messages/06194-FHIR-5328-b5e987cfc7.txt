FHIR-5328: Audit Goal timing elements

Issue request:
FHIR-5328 is a Published/Persuasive Patient Care ballot comment for FHIR-core Goal asking that Goal include timing for when the goal was met and when it is expected to be met. The recorded resolution was to add a status date and a target date to achieve the goal.

Initial application:
No current combined-branch audit commit existed for FHIR-5328. The apparent original source application was the 2015-03-28 PC-approved Goal rewrite in db4ace37, which added Goal.targetDate with "Reach goal on or before" / "Indicates when the goal is intended to be reached" and added Goal.statusDate with "When goal status took effect".

Additional context:
Goal is active in the current build via source/fhir.ini. The historical targetDate concept is now represented by Goal.target.due[x], while statusDate was later narrowed/renamed by FHIR-53981 to Goal.achievementStatusDate so it explicitly dates the current achievement status. FHIR-9084 later requested dateTime precision for the Goal dates but was withdrawn/resolved no-change, so the remaining date-based timing model is intentional.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already contains Goal.achievementStatusDate for when an achievement status such as achieved took effect, Goal.target.due[x] for the expected goal due date/duration, an active target-date search parameter, and examples using both achievementStatusDate and dueDate.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-5328 unless Patient Care later reopens the separate question of adding lifecycle-status timing distinct from achievement-status timing.
