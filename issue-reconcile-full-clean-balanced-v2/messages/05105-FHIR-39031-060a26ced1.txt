FHIR-39031: Audit SubscriptionTopic notificationShape guidance

Issue request:
FHIR-39031 was a Published/Persuasive with Modification R5 ballot issue asking whether SubscriptionTopic.notificationShape.include and revInclude describe server-supported options, and whether clients should be able to request those include/revInclude choices on Subscription. The accepted resolution said related resources are included at the server's discretion, are not client-requested, and that the existing client-expectation sentence from the include/revInclude element definitions should also be surfaced in the main SubscriptionTopic documentation: "Clients SHOULD be prepared to receive these additional resources, but SHALL function properly without them."

Initial application:
The client-expectation sentence was already present in the SubscriptionTopic include/revInclude element definitions from earlier SubscriptionTopic work. The explicit FHIR-39031 application was git commit 18d9f5a194038b2b3154e1dcc24ae9abacdb61c8 on 2023-02-15, which added the same sentence to source/subscriptiontopic/subscriptiontopic-notes.xml and made the local included-resources guidance normative with SHOULD.

Additional context:
SubscriptionTopic is active in source/fhir.ini, so source/subscriptiontopic/structuredefinition-SubscriptionTopic.xml and source/subscriptiontopic/subscriptiontopic-notes.xml are in the current build scope. Current source still has the requested client-expectation text in both the element definitions and the main Notification Shape narrative, and it keeps include/revInclude as SubscriptionTopic shape directives rather than Subscription request fields. Subscription itself exposes filterBy for allowed filters, with no include/revInclude request surface. FHIR-I WGM minutes from January 2023 confirm the issue disposition: the element definitions already clarified expected behavior and the action was to bring that text into the main documentation. No relevant Zulip or conflicting Confluence evidence was found.

AutoFHIR reconciliation:
This is an empty no-change audit commit. The current core source already reflects the accepted clarification and does not need another Subscription element or duplicate explanatory prose.

Recommendation:
Keep this audit commit as-is. No follow-up core change is needed for FHIR-39031 unless the work group later decides to add explicit client-requestable notification shaping, which would be a new substantive design decision.
