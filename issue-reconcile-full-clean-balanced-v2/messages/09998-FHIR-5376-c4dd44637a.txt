FHIR-5376: Audit use context metadata

Issue request:
FHIR-5376 was a Published/Persuasive DSTU1 ballot reconciliation item for ExtensionDefinition/conformance metadata. The approved resolution requested adding useContext [0..*] to StructureDefinition, ValueSet, ConceptMap, and DataElement, with context values covering realms/locales and similar use contexts.

Initial application:
The original application is visible in git commit 8ec1d99d697586c6b520cf455b7a41b5c931cf06, imported from SVN as "#5376 - add useContext to StructureDefinition, ValueSet, ConceptMap, DataElement (and make DataElement conform to decision)". That commit added useContext rows to the StructureDefinition, ValueSet, ConceptMap, and DataElement spreadsheets and added the original use-context value set.

Additional context:
The current build no longer includes DataElement as an active resource; source/fhir.ini comments out dataelement while keeping StructureDefinition, ValueSet, and ConceptMap active. Current source has StructureDefinition.useContext, ValueSet.useContext, and ConceptMap.useContext as 0..* UsageContext elements. The old CodeableConcept shape has been superseded by the UsageContext datatype, with an extensible additional binding for UsageContext.code=jurisdiction to the THO Jurisdiction value set and separate jurisdiction elements on these resources. Quoted Zulip and Confluence searches found no directly relevant community record that conflicts with this source/history conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current resources already carry the intended context-of-use metadata, and the only requested artifact not present, DataElement, is outside the current build scope.

Recommendation:
Keep this no-change audit commit. No core source follow-up is needed for FHIR-5376 unless a future work-group decision reintroduces DataElement or changes the modern UsageContext/jurisdiction model.
