FHIR-17742: Audit MIME :below first-segment search support

Issue request:
FHIR-17742 was a Published/Persuasive FHIR-core search issue raised against STU3 and applied for R5. It asked for MIME/content-type search behavior to cover top-level media types and all subtypes, originally described as [type]/* and */*. The accepted resolution specified adding this to the :below operation by searching on just the media-type segment, for example /DocumentReference?contenttype:below=image selecting image/gif, image/jpeg, and similar values irrespective of MIME parameters.

Initial application:
The MIME :below search guidance was first introduced by git-svn commit 466c4233f3dce83b7ebe6c63305f9161dada150f for GF#16970. FHIR-17742 itself was explicitly applied by bb804361418ab15066908540b1e4639e5f068288 on 2022-08-25, which added the current first-segment :below example to source/search.html and used contenttype:below=image rather than image/*, matching the final Jira resolution text.

Additional context:
source/hierarchy.xml lists search.html as the active RESTful API Search page, and the current source/search.html MIME section still documents DocumentReference.contenttype searches, parameter handling with contenttype:below=text/xml, and first-segment matching with contenttype:below=image. A later AutoFHIR audit for FHIR-16970 on the combined branch reached the same conclusion for the underlying MIME search section. Corrected Zulip and Confluence searches for FHIR-17742 and exact MIME search anchors found no directly relevant or conflicting community records, and Jira full-text searches did not surface a later final FHIR-core reversal.

AutoFHIR reconciliation:
Published an empty no-change audit commit. No source edit is needed because the active search source already implements the accepted FHIR-17742 semantics: :below may be applied to the first MIME type segment, and contenttype:below=image matches image/* content types regardless of MIME parameters. The literal wildcard syntax from the Jira summary was not carried forward because the voted resolution expressed the behavior using the bare media-type segment.

Recommendation:
Keep this audit commit as-is. If the work group later wants literal wildcard inputs such as image/* or */* to have normative search syntax in addition to the resolved contenttype:below=image form, that should be handled as a new search-semantics decision rather than as a missing application of FHIR-17742.
