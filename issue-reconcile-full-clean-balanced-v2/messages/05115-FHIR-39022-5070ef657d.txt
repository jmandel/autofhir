Issue request:
FHIR-39022 was an Applied FHIR-core change request for EvidenceReport that ultimately resolved as Persuasive with Modification. The final decision recorded that EvidenceReport had been removed from the specification, so no EvidenceReport source change was needed, and redirected the substantive request to add publication-date and broaden List Order Codes wording to the THO-owned list-order terminology.

Initial application:
No prior FHIR-core commit tagged with FHIR-39022 was found. EvidenceReport had already been disconnected and de-listed from the active core build in an untagged 2025 source commit, and the list-order code system/value set change was later implemented through UTG proposal UP-739 in THO.

Additional context:
The current core source has no active EvidenceReport resource files or fhir.ini registration. Core still contains a legacy http://hl7.org/fhir/ValueSet/list-order source under the active List resource that composes the THO CodeSystem/list-order, while later Composition work in FHIR-53167 moved Composition.section.orderedBy to the THO ValueSet/list-order canonical. Published THO currently includes the publication-date code and the broadened non-List-specific descriptions.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR-core source change. The requested terminology content is owned and now applied in THO, and changing the remaining core List-specific legacy ValueSet canonical would be a separate core/terminology decision rather than the FHIR-39022 application.

Recommendation:
Keep this empty external-repo audit commit as-is. No FHIR-core follow-up is needed for FHIR-39022; any future cleanup of the legacy core ValueSet/list-order canonical or List.orderedBy binding should be handled by a separate tracker with explicit work-group approval.
