FHIR-5574: Audit corrected FHIR code-system URIs

Issue request:
FHIR-5574 is a Published/Persuasive FHIR-core technical correction for DSTU1 ValueSet terminology. It reported code system URIs using http://www.hl7.org/fhir/... for contract, payment, and process-outcome value sets and requested removal of the "www." prefix so the systems align with FHIR canonical URI practice.

Initial application:
The issue was applied in the source history by the Jira-tagged SVN import commits #5574/SVN 3977 and #5574/SVN 4213. Commit 3a02354c0bb7183b06faec216afe712c7b841560 changed the affected contract, payment reconciliation, status/process outcome, and related example system URIs from http://www.hl7.org/fhir/... to http://hl7.org/fhir/.... Commit 6a9b86cc7bd1f7fe02ff9487e10d67106e19e854 followed with the remaining non-system base URL occurrences noted in the Jira comments.

Additional context:
Current source has since moved several affected example code systems to terminology.hl7.org CodeSystem URLs, while the remaining legacy process-outcome source is under ProcessResponse, a removed/commented resource in source/fhir.ini. The current combined branch still contains a few http://www.hl7.org/fhir/... web links to external IG pages, but a focused scan found no current system, url, or valueSet declarations with the obsolete www-prefixed FHIR canonical base. No Zulip or Confluence records for FHIR-5574 were found that would change the Jira/source conclusion.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The live build-scoped Contract and PaymentReconciliation value set sources no longer use the incorrect www-prefixed code system URIs, and the remaining historical/removed ProcessResponse value set source is also no-www for the reported processoutcomecodes system.

Recommendation:
Keep this audit commit as-is. FHIR-5574 is already reflected in current source; any future cleanup of ordinary web links that still use www.hl7.org/fhir should be handled under a separate link-canonicalization issue, not as a correction to these code system URIs.
