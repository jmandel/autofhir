FHIR-26688: Audit conditional update id handling

Issue request:
FHIR-26688 was a Published/Persuasive FHIR-I correction for the RESTful API conditional update section. It identified a contradiction between the conditional update bullets, which treat a mismatching submitted Resource.id as an error, and a final sentence saying that if an id is provided the server SHALL ignore it. The approved resolution was to remove that sentence.

Initial application:
The issue appears to have been applied by f03ddacb16c1befe035bc015be04709ef3cf5560, "Fix FHIR-26688", which deleted the two-line sentence from source/http.html. That commit was merged via HL7/fhir#1124 in fc265b034702d6da73fc86af5c727b59c5bcb74a with the PR body listing FHIR-26688.

Additional context:
The current build-scope RESTful API page source, source/http.html, still omits the removed conditional-update sentence and retains explicit behavior for submitted ids: no-match/id cases are separated and one-match/mismatching-id returns 400 Bad Request. A later same-section clarification, FHIR-36859, refined the no-match/id behavior and is already represented on the combined branch, so this commit does not duplicate that related issue. The remaining "server SHALL ignore it" occurrence is in the create interaction, not conditional update.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative current source already implements the FHIR-26688 resolution, and adding or removing other conditional-update wording would conflate this issue with later decisions already handled separately.

Recommendation:
Keep this no-change audit commit as-is. No core source follow-up is needed for FHIR-26688 unless a future work-group decision reopens conditional update Resource.id behavior.
