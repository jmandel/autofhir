FHIR-38000: Audit DocumentReference version support

Issue request:
FHIR-38000 was Published/Persuasive with Modification for R5. It asked for DocumentReference to support a document version because Composition had gained Composition.version and the prior composition-clinicaldocument-versionNumber extension did not apply to DocumentReference. The final OO decision was to adopt a version element for DocumentReference modeled on Composition.version, with DocumentReference-appropriate wording.

Initial application:
The change was applied before this reconciliation. Commit 5493ce6532e563d2c9cba54155c56a4edfa11ebc, with subject "close FHIR-3800", added DocumentReference.version to source/documentreference/structuredefinition-DocumentReference.xml and added a DocumentReference-version search parameter. Commit e41db687b398699cf93fb3dff28b80d554c9c311 then corrected the search parameter URL, and commit 0567b321121d035aeefc71f3508017e34d7efdbb added the reciprocal Composition.version mapping to DocumentReference.version.

Additional context:
DocumentReference and Composition are active resources in source/fhir.ini and both are approved in the standards-status section. SD decisions FHIR-34407 and FHIR-38201 removed the old Composition ClinicalDocument version extension/profile because Composition.version is now a base element. The Extension Pack retains composition-clinicaldocument-versionNumber only as a version-specific extension ending at FHIR 4.3, which supports not adding a new core extension for R5/R6. OO minutes for 2022-10-18 record the 3-0-0 vote to add a DocumentReference element mirroring Composition.version, and a 2025 implementers Zulip thread confirms the Jira intent was alignment with Composition.version.

AutoFHIR reconciliation:
This commit intentionally makes no source changes. The active DocumentReference structure definition already has DocumentReference.version as 0..1 string, isSummary=true, mapped to Composition.version and FiveWs.version, and the active DocumentReference search parameter bundle exposes version with expression DocumentReference.version. The current source therefore satisfies the published request without redundant prose or an extension-pack edit.

Recommendation:
Keep this no-change audit commit. No FHIR core follow-up is needed for FHIR-38000 unless a work group later wants to revise the semantics of DocumentReference.version itself; that would be a new issue rather than an incomplete application of FHIR-38000.
