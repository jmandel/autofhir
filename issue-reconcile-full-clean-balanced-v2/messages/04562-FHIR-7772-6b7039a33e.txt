FHIR-7772: Audit Coverage subscriber reference types

Issue request:
FHIR-7772 was a Published FHIR-core Coverage change request asking that Coverage.subscriber support a non-patient person because a subscriber can be a parent, guardian, spouse, or other party who is not the provider's Patient. FM resolved it as Persuasive with Modification: Person itself could not be used because it is an indexing resource, but RelatedPerson should be added to the allowed subscriber reference types.

Initial application:
The issue appears to have been applied in git commit 43806174288e821cb06173a72cde96317186412b, whose message explicitly lists tracker 7772 among a group of Coverage trackers. That commit added Coverage.subscriber in the spreadsheet source with type Reference(Patient|RelatedPerson), alongside subscriberId and related Coverage restructuring. Later source refactors moved the authoritative definition into source/coverage/structuredefinition-Coverage.xml while preserving the Patient and RelatedPerson target profiles.

Additional context:
Coverage is an active current-build resource through source/fhir.ini, so source/coverage/structuredefinition-Coverage.xml is in scope. Current source defines Coverage.subscriber as Reference with targetProfile Patient and RelatedPerson, and does not include Person. Later related decisions do not reverse this: FHIR-14382 records that a subscriber may be Patient or RelatedPerson and can be referenced as a standalone resource or contained with the Coverage, and FHIR-40365 expressly rejected removing RelatedPerson because some jurisdictions find it appropriate.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active Coverage source already carries the exact semantic outcome approved for FHIR-7772: not Person, but RelatedPerson in addition to Patient for Coverage.subscriber.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-7772 unless FM later approves a new issue changing the subscriber target profiles.
