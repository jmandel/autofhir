FHIR-5409 was a Published/Persuasive DSTU1 Patient Care ballot issue for Condition asking to rename the child path Condition.occurredFollowing.codeableConcept to Condition.occurredFollowing.code because codeableConcept was a poor attribute name and likely a typographic error.

Initial application:
The issue was applied in historical git-svn commit 32a14bb92d9bcbea7d25cbc1774a4e32576244ea, matching Jira's svn revision 4581 note. That commit changed source/condition/condition-spreadsheet.xml and the DAF Condition profile spreadsheet from Condition.occurredFollowing.codeableConcept to Condition.occurredFollowing.code, including the old following-code search parameter expression.

Additional context:
Later Published issues FHIR-7620 and FHIR-7621 moved Condition.dueTo and Condition.occurredFollowing out of the core Condition resource into extensions, and FHIR-10102 later changed those extensions from separate code/detail children to a choice of CodeableConcept or Reference. The current core build still actively includes Condition, but the active Condition StructureDefinition no longer contains Condition.occurredFollowing or the obsolete codeableConcept child path. The current condition-occurredFollowing definition lives in the FHIR Extension Pack and uses Extension.value[x] with CodeableConcept and Reference types, so there is no remaining core source fix for this old element-name typo.

AutoFHIR reconciliation:
This is an empty audit commit. No source change was made because the Jira-requested rename was applied historically and the current authoritative artifacts no longer contain the obsolete Condition.occurredFollowing.codeableConcept path.

Recommendation:
Keep this audit commit as-is. Do not reintroduce Condition.occurredFollowing children in core; future changes to the moved condition-occurredFollowing extension, if any, should be handled in the FHIR Extension Pack.
