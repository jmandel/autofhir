FHIR-22778: Audit Measure Report Type value set rendering

Issue request:
FHIR-22778 was a Published/Persuasive FHIR-core technical correction for the CQI Measure Report Type CodeSystem page. It reported that the R4 rendered page for codesystem-measure-report-type listed the same ValueSet bullet twice after the "This Code system is used in the following value sets" heading; the resolution was "Will fix" and it was applied for R5.

Initial application:
No git commit explicitly mentioning FHIR-22778 was found. The Jira reporter later confirmed the defect was fixed in the R5 ballot page, and the R5 ballot/published rendering shows a single MeasureReportType ValueSet bullet. Git history shows the R5 source refactor in 33b409a4b6 split the Measure Report Type CodeSystem and ValueSet into source/measurereport/codesystem-measure-report-type.xml and source/measurereport/valueset-measure-report-type.xml with a single all-codes ValueSet relationship.

Additional context:
The current build includes the MeasureReport resource from source/fhir.ini, and the current source-owned terminology is not duplicated: the CodeSystem names one all-codes ValueSet, the all-codes ValueSet includes the code system once, and the later FHIR-33004 MeasureReportEvaluationType ValueSet legitimately includes the same code system for evaluate-measure reporting types. Current build.fhir.org output still repeats value-set bullets, but the repeated entries correspond to distinct legitimate source references and bindings; deleting those source references would damage the specification instead of fixing the rendering. The duplicate-list aggregation text is not source-owned in this checkout, so any remaining rendered-page de-duplication belongs in the publisher/site generation path.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR source change and records an external-repo audit decision. The current authoritative XML source has valid, non-duplicative CodeSystem/ValueSet content; the remaining visible duplicate bullets on the live CI page need publisher-side de-duplication by ValueSet canonical rather than content-source edits.

Recommendation:
Keep this audit commit as-is for the FHIR source reconciliation. If the current CI page must be cleaned up, fix or file a follow-up against the publisher/site generator to de-duplicate the "used in FHIR core-defined or referenced value sets" list by ValueSet URL while preserving the legitimate MeasureReport.type and evaluate-measure bindings.
