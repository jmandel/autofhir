FHIR-45479: Audit Identifier namespace guidance

Issue request:
FHIR-45479 was an Applied/Persuasive with Modification FHIR-I clarification for R6 asking the Identifier datatype narrative to make clear that globally unique values, including UUID-shaped values, may be used under custom/community Identifier.system namespaces, and that urn:ietf:rfc:3986 is required when a globally unique URI value has no assigned system.

Initial application:
The issue was applied before this reconciliation. Commit 761673c67182cc4ebd521dfafee8f62f39d577c0 first replaced the older "naturally globally unique" paragraph in source/datatypes.html, and commit 369aa0c0cdf6832e4b9370858d9a4c507fa4984c cleaned that application into local links and separate paragraphs.

Additional context:
The linked Zulip thread confirms the ambiguity: participants agreed that custom identifier systems can be used for globally unique identifier values, while urn:ietf:rfc:3986 applies when no assigned system exists and the value is expressed as a URI. FHIR-19602 and FHIR-26438 are older background for the same ambiguity. FHIR-41478 was later marked superseded/merged with FHIR-45479 and refined the same wording; FHIR-42959 adjusted the adjacent OID/UUID registry guidance. The Identifier narrative is in current build scope through source/fhir.ini's active datatypes page wiring.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current combined-branch source already contains the approved replacement guidance in source/datatypes.html and the old "naturally globally unique" wording is absent, so a new edit would only duplicate or editorially polish an already-applied decision.

Recommendation:
Keep this audit commit as-is. Reopen only if FHIR-I chooses to further revise the broader Identifier.system/URI guidance; no current-spec follow-up is needed for FHIR-45479.
