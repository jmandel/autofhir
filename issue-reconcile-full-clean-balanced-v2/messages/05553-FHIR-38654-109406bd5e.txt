FHIR-38654: Audit Questionnaire linkId guidance

Issue request:
FHIR-38654 was a Published/Persuasive FHIR-core technical correction asking whether Questionnaire.item.linkId should prohibit spaces because IG Publisher-generated narrative had used linkId values directly as XHTML element IDs. The final resolution was that linkIds can have whitespace and slashes by design, and tooling must not rely on linkIds being valid XHTML element IDs or directly embed them as such.

Initial application:
The Jira application comment points to git commit d3cf3998e5a1db5f7faaa013f182d47543decdfc, "FHIR-38654 - Added guidance on linkId." Although that commit's patch is noisy because of line-ending churn, the intended source change is present in the Questionnaire.item.linkId comment in source/questionnaire/structuredefinition-Questionnaire.xml.

Additional context:
source/fhir.ini lists questionnaire as an active current-build resource. FHIR-I WGM 2022 minutes referencing FHIR-38654 record the same conclusion: Element.id was a red herring, the intent was to allow whitespace and slashes in linkId, and tooling should handle them. The triggering FHIR-38642 IG issue remains Triaged and is not an independent core decision. Later Applied issue FHIR-46191 tightened leading/trailing and intervening whitespace behavior with code-like regex constraints while preserving linkId as string and preserving slash use; that later issue is already represented on the combined branch.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The current build-scope Questionnaire source already says linkIds can have whitespaces and slashes by design and that tooling should not treat linkIds as XHTML element IDs. The later regex constraint disallows leading/trailing whitespace and non-single-space intervening whitespace, but still allows internal single spaces and slashes, so it narrows only whitespace shape and does not reverse FHIR-38654's core guidance.

Recommendation:
Keep this audit commit as-is. No additional core FHIR source change is needed for FHIR-38654; any remaining XHTML-id handling belongs in tooling, not in Questionnaire.item.linkId's datatype or narrative guidance.
