FHIR-23032: Audit datatype usage links

Issue request:
FHIR-23032 was a Published/Persuasive FHIR-core technical correction reporting broken internal links on the datatypes page, especially Attachment usage links to RelatedArtifact and ProdCharacteristic and Coding usage links to Meta, DataRequirement, and UsageContext.

Initial application:
The Jira comment records R4 commit a00b4aa155 and R5 commit ed006b5. Both commits changed the then-current Java publisher so generated datatype usage links used definitions.getSrcFile(...)+".html#..." instead of assuming all datatype targets lived on the current datatypes page; that directly addressed cross-page links such as RelatedArtifact, Meta, DataRequirement, and UsageContext.

Additional context:
The current core source keeps datatypes.html in build scope and still uses [%dtusage ...%] placeholders. The active [type-pages] mappings in source/fhir.ini send Meta to resource.html, DataRequirement/RelatedArtifact/UsageContext to metadatatypes.html, and in-page datatypes such as Signature to datatypes.html; ProdCharacteristic is commented out and is not a current built datatype page target. The Java publisher files changed in 2019 are no longer present in this checkout, so there is no current core generator source hunk to reapply.

AutoFHIR reconciliation:
This audit makes no source change because the current generated CI page already emits working cross-page usage links for the reported cases: Attachment links RelatedArtifact to metadatatypes.html#RelatedArtifact, Coding links Meta to resource.html#Meta, DataRequirement and UsageContext to metadatatypes.html anchors, and Signature to datatypes.html#Signature. The checked target anchors resolve on the current rendered pages.

Recommendation:
Keep this no-change audit as-is. No further core FHIR source edit is needed for FHIR-23032 unless the external publisher later regresses dtusage link generation.
