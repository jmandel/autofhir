FHIR-3970: Audit extension definition inheritance

Issue request:
FHIR-3970 was a Published/Persuasive FHIR-core change request from DSTU1 asking that extension definitions not inherit descriptive content such as aliases or comments from the base Extension definition when the extension definition does not declare them. The example was Observation.extension(USLabSpecimenRejectReason), whose generated page also appeared to omit the extension's value set binding.

Initial application:
The issue was applied in historical svn revision 4542, now git commit 3683b5294b18890b25b2311a3b0b947061ac145d, with the commit summary "3970 - don't inherit descriptive text from Extension". That implementation changed ProfileUtilities so Extension, .extension, and .modifierExtension derivations clear inherited definition, short, comments, requirements, synonyms, and mappings before overlaying the derived extension content.

Additional context:
The cited US Lab artifact is not active core source in the current build: source/igs.xml keeps the old uslab IG entry commented out, and current core source does not contain USLabSpecimenRejectReason or specimen-reject-reason. The successor Specimen Reject Reason extension is in the FHIR Extension Pack, where its differential supplies its own definition and the Extension.value[x] binding without aliases or comments. A current build.fhir.org Extension Pack JSON check likewise shows no alias/comment on the generated Extension root and includes the value[x] binding. FHIR-3971 was found in the same Jira search because it used the same example, but it concerns hyperlink presentation and is a separate audit path.

AutoFHIR reconciliation:
No source files were changed. The current core repository has no active stale source location for the DSTU1 US Lab example, and the external extension-pack source and current built artifact do not show the inherited alias/comment or missing-binding symptom described by FHIR-3970.

Recommendation:
Keep this audit commit as-is for the core reconciliation. If someone wants to improve the current Specimen Reject Reason extension wording, that should be reviewed separately in the FHIR Extension Pack because it is outside this core-source issue and is not evidence of inherited base Extension aliases or comments.
