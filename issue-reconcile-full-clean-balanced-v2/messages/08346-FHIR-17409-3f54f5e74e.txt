FHIR-17409: Fix GraphQL error example JSON

Issue request:
FHIR-17409 was Published/Persuasive for FHIR-core GraphQL and asked that GraphQL queries support native GraphQL errors instead of overriding GraphQL error handling with OperationOutcome responses. The accepted resolution was to return a proper GraphQL error instead of an OperationOutcome.

Initial application:
The issue was applied in svn revision 14545, represented in git as bb4b8d2e8a ("GF#17409 - fix graphQL error"). That commit changed source/graphql.html from requiring OperationOutcome responses and forbidding an errors property to requiring a GraphQL error response, adding an errors array example, and allowing OperationOutcome detail inside GraphQL extensions.

Additional context:
The linked Zulip discussion agreed that FHIR GraphQL endpoints should return a valid GraphQL error response and SHOULD carry an OperationOutcome under the error extensions. The current source/graphql.html page is in build scope through source/hierarchy.xml and source/documentation.html. Related Jira and Confluence searches found no later decision reversing this error-handling rule; FHIR-55105 is only an unrelated same-page spelling correction and is not decided here.

AutoFHIR reconciliation:
This commit removes the stray trailing comma after the OperationOutcome resource object in the GraphQL error example. The surrounding normative text already implements FHIR-17409 by using native GraphQL errors, so the only source change needed is to make the example valid JSON.

Recommendation:
Keep this source fix. It preserves the published FHIR-17409 semantics while correcting the example syntax implementers may copy; no further core GraphQL error-handling change was found.
