FHIR-6913: Audit Composition append handling

Issue request:
FHIR-6913 was Published/Persuasive with Modification for DSTU1 and asked Structured Documents to stop treating Composition.status code appended as a specialized amendment status. The approved resolution was to strike the appended status code, update amended so it covers edited or added content after final release, and document that pathology-style workflows requiring original narrative preservation would be handled through an extension.

Initial application:
The issue was applied in SVN-backed git commits dfaf9ed8e8 (#6913 - remove Composition Status 'appeneded') and ade86cb39b (#6913 - document appended behavior). Those commits removed appended from the then-current Composition spreadsheet status list and added the Composition.status comment now preserved in source XML saying that workflows requiring original final narrative not to be altered are handled by extension rather than by a dedicated Composition status.

Additional context:
Current Composition source is active in source/fhir.ini and no longer uses the old composition spreadsheet. The current source still carries the FHIR-6913 extension guidance, but later final WG decisions deliberately changed the surrounding model: FHIR-37403 was Published/Persuasive for R5 and aligned Composition Status with DiagnosticReport Status, which includes corrected/appended beneath amended; the combined branch already has an AutoFHIR FHIR-37403 reconciliation commit preserving that later decision. FHIR-49759 was Applied/Persuasive with Modification for R6 and reshaped Composition.relatesTo with an ArtifactRelationshipType binding that explicitly includes appends/appended-with. No FHIR-6913-specific Zulip or Confluence record was found that would override these later Jira/source decisions.

AutoFHIR reconciliation:
Made no source change. Removing appended again would undo later final WG decisions rather than complete FHIR-6913. The current source preserves the original 2015 point that a business rule requiring immutable original final narrative is extension-governed, while later approved status and relationship models now provide append-related concepts where the work group chose to support them.

Recommendation:
Keep this audit commit as-is. Do not remove Composition Status appended or Composition.relatesTo appends/appended-with as part of FHIR-6913; any renewed disagreement about append semantics should be handled as a new SDWG decision that explicitly revisits the later FHIR-37403 and FHIR-49759 outcomes.
