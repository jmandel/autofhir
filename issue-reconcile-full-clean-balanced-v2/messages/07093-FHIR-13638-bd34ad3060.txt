FHIR-13638: Audit Task reason reference support

Issue request:
FHIR-13638 is a Published/Persuasive OO change request raised and applied for STU3. It asked that Task.reason become a choice that includes Reference() because tasks may be justified by an Observation, Condition, past or planned procedure, or similar resource rather than only by a code.

Initial application:
The issue appears to have been applied in git commit bc96ecb066, whose message names GF#13638. That STU3-era source changed the then-current Task spreadsheet from a single Task.reason CodeableConcept into Task.reasonCode plus Task.reasonReference of type Reference(Any), which applied the requested code-or-reference semantics even though the source shape used split elements rather than a reason[x] element.

Additional context:
Task is an active resource in source/fhir.ini. Later same-family Task decisions changed the representation: FHIR-25255 replaced reasonCode and reasonReference with 0..* Task.reason CodeableReference, and FHIR-37905 completed that current representation by adding the Resource target profile that renders as CodeableReference(Any). FHIR-37905 is already represented on the combined branch, so this seed audit does not duplicate that related issue.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current source/task/structuredefinition-Task.xml defines Task.reason as 0..* CodeableReference with targetProfile http://hl7.org/fhir/StructureDefinition/Resource, and source/fhir.ini records the migration from Task.reasonCode and Task.reasonReference into reason.concept and reason.reference. No active Task.reasonCode or Task.reasonReference elements remain.

Recommendation:
Keep this commit as-is. The current CodeableReference(Any) representation satisfies the reference-capable reason requirement after later datatype refactoring; do not reintroduce separate reason[x] or reasonReference elements for this STU3 tracker.
