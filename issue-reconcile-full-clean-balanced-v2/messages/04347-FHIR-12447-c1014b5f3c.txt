FHIR-12447: Audit MedicationRequest intent search parameter

Issue request:
FHIR-12447 was a Published/Persuasive Pharmacy change request raised against DSTU2 MedicationPrescription/MedicationRequest asking that MedicationRequest.intent be available in the search criteria so systems could distinguish prescriptions from downstream MAR/instance entries. The Jira resolution says it was approved as part of TR#12388, and the recorded motion was to add instance-order to the MedicationRequest intent value set and make intent a search parameter.

Initial application:
The Jira comments record revision @10662. In git history this corresponds to SVN-import commit 7975773ab18e3799e0e0d5223493e46cb2ea3b3a, whose subject explicitly includes "TR#12447 - added MedicationRequest.intent as a search parameter" and whose patch added an intent token search row with path MedicationRequest.intent to the then-authoritative MedicationRequest spreadsheet source.

Additional context:
MedicationRequest is active in source/fhir.ini, so source/medicationrequest participates in the current build. The 2021 source rework commit 33b409a4b6d544598262f2f074ebb4b6dc466157 removed the old spreadsheet and created source/medicationrequest/bundle-MedicationRequest-search-params.xml with the MedicationRequest-intent SearchParameter preserved. The current source also has MedicationRequest.intent as a required code element bound to the MedicationRequest intent value set, including instance-order. Related issues FHIR-12388 and FHIR-10456 explain the broader workflow/value-set context; FHIR-12446 is a duplicate/background rename issue and is not separately decided here.

AutoFHIR reconciliation:
No source change is needed. The current active MedicationRequest search-parameter bundle already defines code="intent", type="token", expression="MedicationRequest.intent", and the active resource entry in source/fhir.ini confirms the resource folder is in build scope.

Recommendation:
Keep this empty audit commit as-is. The requested search criterion is already present in current source, and adding duplicate narrative or another search-parameter definition would create maintenance drift rather than improve conformance clarity.
