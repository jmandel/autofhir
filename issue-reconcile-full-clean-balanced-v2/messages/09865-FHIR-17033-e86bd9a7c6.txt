FHIR-17033: Audit Bundle independent-existence wording

Issue request:
FHIR-17033 was a Published/Persuasive STU3 clarification for FHIR-core-Feed asking that the Bundle Boundaries and Relationships sentence change from resources that "have an independent existence" to resources that "may have an independent existence," because resources in documents or messages might not be independently REST-addressable.

Initial application:
The issue was applied in svn revision 14393, represented in Git as 42bf1cc54758d0827fefec7124969a2b3be546e4, which changed source/bundle/bundle-introduction.xml from "have an independent existence" to "can have an independent existence" and also changed the example clause from "can also" to "might also." Current blame still attributes the relevant sentence to that Jira-tagged commit.

Additional context:
Bundle is an active current-build resource in source/fhir.ini, so source/bundle/bundle-introduction.xml is in build scope. Later source history has not reversed the FHIR-17033 meaning, and community searches found no direct Zulip or Confluence record conflicting with the Jira/source conclusion; a 2023 Zulip discussion quoted the current "can have ... might also" wording as the applicable Bundle text.

AutoFHIR reconciliation:
This is an empty audit commit. The current source already conveys the required optionality: Bundle entries can, but need not, have independent existence, and the REST API example is framed as something they might also support. Changing "can" to "may" would be a non-substantive wording preference rather than a necessary current-spec correction.

Recommendation:
Keep this no-change audit as-is. Revisit only if the work group wants a broader policy statement about context conduction or independent access for documents/messages, which would be outside the narrow FHIR-17033 wording fix.
