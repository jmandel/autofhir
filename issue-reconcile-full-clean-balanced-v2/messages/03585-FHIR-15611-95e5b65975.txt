FHIR-15611: Audit Money invariant correction

Issue request:
FHIR-15611 was a Published/Persuasive STU3 technical correction for FHIR-core datatypes. It asked to correct the Money mny-1 invariant to `(code.exists() or value.empty()) and (system.empty() or system = 'urn:iso:std:iso:4217')`; the Jira was auto-approved and recorded as applied for STU3.

Initial application:
The requested correction appears to have been applied in SVN revision 13439, represented in git by 19d34d51c846e16ada19d52db5f08a79802ce96e, which changed source/datatypes/money.xml from `(code or value.empty()) ...` to the requested `code.exists()` expression. The later FHIR-16297 application reworked Money and moved the Quantity-style currency rule to MoneyQuantity.

Additional context:
Current source/fhir.ini keeps Money and MoneyQuantity in active datatype build scope. Current source/datatypes/money.xml defines Money as a DataType with Money.value and Money.currency, so the old code/system invariant no longer applies to Money itself. Current source/datatypes/quantity.xml retains the corrected Quantity-style invariant for MoneyQuantity. FHIR-16297 was Published/Persuasive with Modification and explicitly approved this split by introducing a specific Money type and renaming the old Money profile to MoneyQuantity. Zulip and Confluence searches found no contrary community record.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source is already correct for FHIR-15611: the historical mny-1 correction is preserved where the Quantity-style profile still exists, and re-adding it to current Money would be wrong because current Money has no code or system elements.

Recommendation:
Keep this no-change audit as-is. Future changes to MoneyQuantity should preserve the corrected `code.exists()` invariant, but no current core source follow-up is needed for FHIR-15611.
