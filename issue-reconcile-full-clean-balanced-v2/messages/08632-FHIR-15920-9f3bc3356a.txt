FHIR-15920: Audit QuestionnaireResponse absent-answer guidance

Issue request:
FHIR-15920 was a Published FHIR-core change request for STU3 asking to add a data absent reason element under QuestionnaireResponse.item.answer for missing, especially non-code, answers. The final disposition was Not Persuasive with Modification: do not add a universal QuestionnaireResponse dataAbsentReason element; instead add guidance explaining how to handle a missing response in Questionnaire.

Initial application:
The issue was applied by the historical 2018 Questionnaire tracker commit 37ee370c54, which added Questionnaire notes guidance stating that when a reason for a missing response must be captured, the Questionnaire should define an explicit child item for the relevant question, for example a "Reason not specified" child enabled when the parent answer does not exist. The application commit did not mention FHIR-15920 in its subject, but the added sentence matches the Jira resolution and comment text.

Additional context:
Questionnaire and QuestionnaireResponse are active resources in source/fhir.ini, so their resource folders are in the current build scope. The current QuestionnaireResponse answer backbone still has answer.value[x] as the required value within each answer and has no dataAbsentReason child. A 2021 Questionnaire Zulip thread discussed nullFlavor/data-absent-reason for unanswered questionnaire items; Lloyd McKenzie reiterated that extensions/core fields should not be introduced there and that dataAbsentReason can be a reasonable code system for a separate questionnaire answer. Confluence has no FHIR-15920 references, and Jira searches found no later core issue that reverses this disposition.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Questionnaire notes already provide the missing-response guidance required by the final Jira decision, and adding a dataAbsentReason element or duplicate local prose on QuestionnaireResponse would be broader than the approved change and risk contradicting the existing guidance.

Recommendation:
Keep this no-change audit commit. Future work should only revisit this if FHIR-I approves a new core QuestionnaireResponse absent-answer element or more prescriptive Questionnaire authoring rules; FHIR-15920 itself is already represented correctly in the current build source.
