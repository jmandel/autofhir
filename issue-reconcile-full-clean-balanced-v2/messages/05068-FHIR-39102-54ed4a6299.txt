FHIR-39102: Audit large-resource operation definitions outside core

Issue request:
FHIR-39102 was a Published FHIR-core change request for List and Group asking that $add, $remove, and $filter have formal OperationDefinitions with clearer details. The final Not Persuasive with Modification resolution said the definitions already existed, but the Operations for Large Resources page should hyperlink to the respective operation definitions.

Initial application:
The issue was applied in core by da39345a88, which added links from source/operations-for-large-resources.html to resource-operation-add.html, resource-operation-remove.html, and resource-operation-filter.html. The R5 history bundle still contains the corresponding Resource add, filter, and remove OperationDefinitions.

Additional context:
Later R6 work changed the current core page from a draft operation definition page into an informative handoff to the API Incubator. Commit 270e0ceb7b removed the local operation details and formal-definition links from core, and the current source only points readers to the API Incubator. The active OperationDefinition XMLs for Resource-large-resource-add, Resource-large-resource-remove, and Resource-large-resource-filter are now present in the external HL7/api-incubator-ig repository, not this core checkout. Live build probes for the referenced API Incubator page and the external operation-definition pages returned 404, so the remaining publication/link repair is in that external IG or requires a stable external URL before the core pointer can be safely changed.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. Re-adding the R5-era local links would contradict the current R6 handoff, while guessing new core links to unpublished external pages would create more stale/broken links. The actionable work for this issue family is now outside the FHIR core checkout.

Recommendation:
Keep this external-repo audit commit. Follow up in HL7/api-incubator-ig to publish the Operations for Large Resources page and its three OperationDefinitions, then update the core handoff URL only after the API Incubator has a stable published location.
