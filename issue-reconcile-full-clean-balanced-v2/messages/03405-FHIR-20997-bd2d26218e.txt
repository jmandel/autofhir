FHIR-20997: Audit Account relationship model

Issue request:
FHIR-20997 was Published/Persuasive for R5 and asked Account to expose non-parent account relationships as a relatedAccounts/relatedAccount backbone with relationship 0..1 CodeableConcept using an example Account Relationship value set and account 1..1 Reference(Account). The resolution also said this tracker would overwrite the proposed FHIR-20994 Account.partOf cardinality update.

Initial application:
The issue was applied before R5 by ebc4150af999256bac52f7e2db925c9804a829d9, which replaced Account.partOf with Account.relatedAccount, added Account.relatedAccount.relationship and Account.relatedAccount.account, and created the Account Relationship CodeSystem/ValueSet with parent and guarantor codes. The v5.0.0 source tag still contains that R5 Account.relatedAccount structure, so the Published issue was carried into the R5 publication. FHIR-20994 is already represented on the combined branch by 834241d7b8e1ea91e6f0de9c4913f3fecce1fdbc.

Additional context:
A later Applied/Persuasive with Modification R6 issue, FHIR-44682, found Account.relatedAccount problematic and approved replacing it with Account.parent plus Account.guarantor.account, along with a relaxed guarantor party rule and explanatory comments. Commit 8b7413dafcb1d98ad5db1460c978d1c6295e2a91 made that source change, and current source/fhir.ini records the R5-to-R6 mapping from Account.relatedAccount to parent or guarantor depending on relationship type. The current Account resource is active in source/fhir.ini, and the current StructureDefinition exposes Account.parent and Account.guarantor.account rather than Account.relatedAccount. FHIR-31366, already represented on the combined branch, added the current Account.parent search parameter.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Reintroducing Account.relatedAccount would undo the later FHIR-44682 R6 decision, and removing or rewriting the retained account-relationship terminology would be a separate compatibility/terminology decision not requested by FHIR-20997.

Recommendation:
Keep this audit as-is. If PA/FM wants the now-unbound Account Relationship CodeSystem/ValueSet retired or otherwise marked, handle that as a separate FHIR-44682/terminology follow-up rather than as FHIR-20997 reconciliation.
