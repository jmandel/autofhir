FHIR-12605: Audit CodeSystem compose exact parameter

Issue request:
FHIR-12605 was Published/Persuasive with Modification for Vocabulary. It asked to rename the CodeSystem $compose input parameter from 'mode' to 'exact' as a boolean and update the operation documentation to describe exact matching behavior.

Initial application:
Jira records svn revision 11130. Git commit 5038447f45b71f7bcfe5184df46798ed4bc7601d corresponds to that revision; the source spreadsheet at that commit already used compose.exact as a boolean input parameter and the commit added operation-level documentation explaining that the two modes are differentiated by the 'exact' parameter.

Additional context:
The old $compose operation was later renamed to $find-matches under FHIR-15956/FHIR-17563, and FHIR-16358 further clarified the 'exact' parameter text. Those related issues already have reconciliation commits on the combined branch. The current R6 CodeSystem resource remains in build scope through source/fhir.ini, but its active operation list includes only $lookup, $validate-code, and $subsumes. The $find-matches OperationDefinition and its list/narrative references were removed by 40306e5cd9 in preparation for the R6 normative ballot. A leftover $find-matches request example still names exact, not mode, and is not referenced by the active CodeSystem operation list.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No current build-scope CodeSystem operation exposes the obsolete $compose/$find-matches parameter, and the only residual example already uses exact, so changing current source would either be redundant or touch out-of-build residue.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed for FHIR-12605; if maintainers later clean unused example files, they can handle the orphaned $find-matches examples separately from this historical rename.
