FHIR-47469: Audit async-bulk filesize migration

Issue request:
FHIR-47469 was Applied/Persuasive for R6 by FHIR-I to add an optional output file item field, `filesize`, to the asynchronous bulk data complete-status manifest. The field is the file size in bytes as a JSON number and supplements the already-optional `count` field.

Initial application:
The issue was applied in HL7/fhir pull request #3215. Commit 7ab6c58528ff709d8a090d7a6b77e563e7a94385 added the `filesize` bullet to `source/async-bulk.html`, and merge commit 90846c660edeba796d95abdfa67ecda59a62622e brought that change into the core repository.

Additional context:
The current core build no longer contains `source/async-bulk.html`; commit 270e0ceb7b029dad4ca0fc5ccf5296ff370888cd removed the detailed async bulk and async bundle pages and changed `source/async.html` to point readers to the API Incubator while the details are finalized through implementation testing. The corresponding external HL7/api-incubator-ig source file `input/pagecontent/async-bulk.html` still contains the FHIR-47469 `filesize` bullet, so the substantive applied wording was preserved outside this core checkout. The API Incubator publication/link state appears to need separate follow-up, but that is broader than the `filesize` field decision and belongs with the external IG/link maintenance.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. Restoring the old core async-bulk page or duplicating the `filesize` field in `source/async.html` would contradict the current build-scope decision to keep the detailed pattern in the API Incubator.

Recommendation:
Keep this audit commit as-is for FHIR core. If implementers need the incubator content published or the core pointer corrected, handle that as a separate API Incubator/linking task; do not change core solely for FHIR-47469 while the external source already carries the requested field.
