FHIR-43073: Audit search reference clarification

Issue request:
FHIR-43073 was an Applied/Persuasive with Modification FHIR-I clarification for the core Search page. It asked for references on the search page, especially Canonical Identifiers and Chaining, to distinguish the reference search type, the FHIR datatype Reference, and ordinary references to other resources, and to add a base mapping table after Escaping Search Parameters showing allowed search type to FHIR type mappings.

Initial application:
The issue was applied in source/search.html by Jira-tagged commits 3290d342984541dd13caa741d010469a12b5acfe, ccd40c3336b87260cb1d4574fa403ab8fcac603f, and fc6e2e2be243c11142e8adf72288d3eefcb7051e, then merged in HL7/fhir#2998. Those commits clarified ambiguous "reference" wording across modifiers, includes, the reference search type, and chaining-related prose, and added the Search Types and FHIR Types mapping section immediately after Escaping Search Parameters.

Additional context:
The linked Zulip thread shows the source of confusion: implementers were reading canonical search parameters as normal references for chaining, while the discussion distinguished the reference search type from the Reference datatype and from generic resource references. FHIR-I minutes on 2023-11-13 record the 13-0-0 Persuasive with Modification vote. A later Applied issue, FHIR-45252, refined the non-Reference/canonical traversal wording and is already represented on the combined branch, so the current source should be read with that later clarification included.
