FHIR-52017: Audit NutritionProduct boundary links

Issue request:
FHIR-52017 was Applied as Persuasive with Modification for R6 by OO. It asked to add NutritionOrder to the NutritionProduct Boundaries and Relationships section and to modify the NutritionIntake entry so it is described as the resource used for recording oral intake, supplements, enteral nutrition, and infant formula.

Initial application:
The request was applied upstream in commit f08af008345a71485a7eee5f3ce559a3c12559dd, which changed source/nutritionproduct/nutritionproduct-introduction.xml by adding a NutritionOrder boundary entry and changing the NutritionIntake entry to start with "Used for recording". That application commit did not include an issue-reconcile trailer, so this audit commit records the reconciliation decision.

Additional context:
NutritionProduct is an active resource in source/fhir.ini, so its introduction page is in current build scope. OO Nutrition minutes on 2025-08-27 recorded that FHIR-52017 text would be drafted using existing resource and module content for consistency, and the 2025-09-24 minutes record the 7-0-0 Persuasive with Modification vote. Searches found no Zulip discussion or conflicting Jira issue that changes the source conclusion. The application commit also included other nutrition work, especially FHIR-50383, but those broader module changes are not needed to decide this seed issue.

AutoFHIR reconciliation:
No source change was made. The current NutritionProduct Boundaries and Relationships list already includes NutritionOrder for requesting oral diets, oral nutrition supplements, enteral feedings, nutrition products, and infant formula, and the NutritionIntake line already says it is used for recording the relevant intake. The remaining wording differences from the Jira resolution are editorial rather than a different implementer-facing rule.

Recommendation:
Keep this audit commit as-is. If OO later wants smoother phrasing for the NutritionIntake sentence, that can be handled as general editorial cleanup, but FHIR-52017 itself is already applied in the current build-scope source.
