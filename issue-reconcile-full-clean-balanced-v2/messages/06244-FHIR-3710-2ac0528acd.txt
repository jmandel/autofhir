FHIR-3710: Audit retired ReferralRequest patient rename

Issue request:
FHIR-3710 was Published with resolution Persuasive. It asked to rename ReferralRequest.subject to ReferralRequest.patient because the DSTU1 ReferralRequest element could only reference a Patient, following the naming guideline to use patient when Patient is the only reasonable subject.

Initial application:
The change was applied in historical commit 7b81ef098a, which changed the ReferralRequest example from <subject> to <patient>, renamed ReferralRequest.subject to ReferralRequest.patient in the spreadsheet, and changed the ReferralRequest patient search parameter path to ReferralRequest.patient.

Additional context:
Later Patient Care workflow standardization in FHIR-10293 changed ReferralRequest.patient back to ReferralRequest.subject, made it required, and aligned it with the Request.subject workflow pattern. Current source/fhir.ini records that legacy migration as ReferralRequest.patient=ReferralRequest.subject. ReferralRequest is no longer an active current-build resource: source/fhir.ini lists ServiceRequest as active, lists ReferralRequest under removed resources, and records that ReferralRequest became ServiceRequest; source/history.html also records ReferralRequest and ProcedureRequest becoming ServiceRequest. Current ServiceRequest.subject is intentionally broader than Patient, with Patient, Group, Location, and Device targets, and the patient-specific access point is represented as the ServiceRequest-patient search parameter. FHIR-6023 is already represented on the combined branch and audits the current ServiceRequest.subject scope.

AutoFHIR reconciliation:
This empty audit commit makes no source change. Renaming the active ServiceRequest.subject element to patient would conflict with later workflow and ServiceRequest scope decisions, while the retired ReferralRequest source folder is absent from the current build.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-3710 unless a future work group decision changes the current ServiceRequest.subject model or reintroduces a Patient-only referral resource.
