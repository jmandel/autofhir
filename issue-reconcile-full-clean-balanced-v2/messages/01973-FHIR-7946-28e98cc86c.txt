FHIR-7946: Audit document immutability clarification

Issue request:
FHIR-7946 was a Published/Persuasive SD clarification for the FHIR Documents page from DSTU1. It asked to replace broad wording that the document content, attested resources, and order could not change with wording that only directly referenced content within the document could not change, because indirectly referenced resources outside the document may change on a server after document creation.

Initial application:
The Jira comment says the change was applied in SVN revision 6213. Git history maps that to 59689d945f216b7336d6f560f5008ef406b3907e, which changed source/documents.html from "the content (the set of attested resources, and their order)" to "the directly referenced content within the document" plus presentation. That was the original application of this issue.

Additional context:
The active source file is source/documents.html, referenced from source/navigation.xml and linked by the exchange/documentation pages. Later Published document-page decisions intentionally rewrote this same section. FHIR-36636 replaced the strict "Once assembled" immutability paragraph with text that a document Bundle contains specific frozen versions of resources, that changes may risk attestation, that implementers should define update-vs-new-document policies, and that derived documents need different Bundle.identifier values. FHIR-38930 then removed the residual "document immutability" terminology sentence. The referenced Zulip thread and FHIR-I WGM minutes confirm the later WG discussion and vote.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Documents page no longer contains the old overbroad "attested resources and their order" wording that FHIR-7946 corrected, and it also should not restore the 2015 "directly referenced content" sentence because later R5 Published decisions deliberately softened and restructured the immutability guidance.

Recommendation:
Keep this audit commit as-is. If stricter rules about directly referenced or indirectly referenced document content are desired again, that should be raised as a new work-group decision rather than reapplying FHIR-7946 over the later FHIR-36636/FHIR-38930 resolutions.
