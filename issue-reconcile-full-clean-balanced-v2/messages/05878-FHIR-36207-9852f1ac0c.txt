FHIR-36207: Audit Device operation mode value set

Issue request:
FHIR-36207 was Published/Persuasive with Modification for R5. It requested adding a Device operation-mode value set, with the final resolution phrased as Device.operationState.mode and codes normal, demo, service, maintenance, and test.

Initial application:
The issue was applied in R5 source history by commit 04efb9949f4a60599a63a9d1caf3f79c7b909f56, which added source/device/codesystem-device-operation-mode.xml and source/device/valueset-device-operation-mode.xml with the requested code set. Later Device operation-state work renamed the files and binding while Device.operationalState existed, and FHIR-37545 then renamed the family back to Device.operation/device-operation-mode while keeping the same code set. Commit 689b68cc93e0bd00d4ee47e1c640c87f14556c92 later removed old unneeded operational-state terminology files in that rename family.

Additional context:
Later final Device decisions changed the active model. FHIR-37545 renamed Device.operationalState to Device.operation. FHIR-32565 then approved moving Device.mode, Device.cycle, Device.duration, Device.gateway, and Device.endpoint out of core Device into extensions for R6, and FHIR-47323 created the FHIR Extension Pack device-operation-mode extension bound to http://hl7.org/fhir/ValueSet/device-operation-mode. The combined branch already contains related audits/fixes for FHIR-36208, FHIR-36213, FHIR-37545, FHIR-47891, FHIR-48924, and FHIR-47038, and no prior FHIR-36207 reconciliation commit was present.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Device remains active in source/fhir.ini, but parsing the current Device and DeviceAssociation StructureDefinition XML finds no active Device.operation, Device.operationalState, Device.mode, Device.cycle, Device.duration, or DeviceAssociation.operation elements. The surviving core CodeSystem and ValueSet for device-operation-mode already carry the requested normal/demo/service/maintenance/test concepts and are the terminology binding used by the current Extension Pack device-operation-mode extension. Reintroducing a core Device.operationState.mode or Device.mode element would contradict later applied Device modeling decisions, and retiring legacy unbound operational-state artifacts would be a separate terminology-governance decision.

Recommendation:
Keep this audit commit as-is. Do not reintroduce Device.operationState.mode or Device.mode in core for FHIR-36207. If the work group wants to move or retire the operation-mode terminology, handle that separately with terminology governance and Extension Pack coordination because the active extension still binds to the core ValueSet/device-operation-mode.
