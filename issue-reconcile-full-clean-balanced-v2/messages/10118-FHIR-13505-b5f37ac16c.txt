FHIR-13505: Audit REST create return body guidance

Issue request:
FHIR-13505 was a Published/Persuasive FHIR-I STU3 change request asking the RESTful create interaction to make clear that successful create responses can use the return body options described in the create/update/patch/transaction return-content section, including OperationOutcome hints or warnings requested with Prefer: return=OperationOutcome. The description also questioned how the same Prefer rule interacts with batch/transaction responses.

Initial application:
The Jira comment says the change was applied in SVN revision 12838. Git history maps that to commit 31f6f40b29, which added a note in source/http.html for both update and create that the response body is described in the Managing Return Content section.

Additional context:
The current RESTful API source is in build scope through source/documentation.html and still contains the relevant Managing Return Content section. That section describes Prefer: return=minimal, Prefer: return=representation, and Prefer: return=OperationOutcome for create/update/patch/transaction, with successful OperationOutcome responses only when explicitly requested. The current create section links back to that section after the success headers. The current Batch/Transaction Response text separately states that the response is a Bundle and that included entry resources are governed by the Prefer header, so the batch concern is not a conflicting rule. FHIR-6120 is earlier background on the same success-warning concern and was Resolved - No Change because the Prefer header handles it. Targeted Zulip and Confluence searches found no FHIR-13505-specific discussion or work-group record that changes this conclusion.
