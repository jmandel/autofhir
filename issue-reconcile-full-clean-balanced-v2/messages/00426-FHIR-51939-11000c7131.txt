FHIR-51939: Audit BDP collection source split

Issue request:
FHIR-51939 was an Applied/Persuasive OO change request for R6 asking to replace BiologicallyDerivedProduct.collection.source with separate collection.sourcePatient and collection.sourceOrganization elements, update the HCT examples to use sourcePatient, replace the old source search parameter with patient, and add BiologicallyDerivedProduct to the patient compartment via collection.sourcePatient.

Initial application:
The issue appears to have been applied by HL7/fhir#3717 in commit 7e1bd58e5366e7d630afee29458031a4b32818eb. That commit split the StructureDefinition element, updated the allogeneic and autologous HCT examples, changed BiologicallyDerivedProduct-collection-source to BiologicallyDerivedProduct-collection-sourcePatient with code patient, added BiologicallyDerivedProduct to the common clinical patient search parameter, and added the patient compartment row entry.

Additional context:
BiologicallyDerivedProduct is active in source/fhir.ini and the relevant files are current build source, not stale generated output. The current source no longer contains the old collection.source element or source search parameter. A later Applied/Persuasive issue, FHIR-56179, intentionally added a search parameter for collection.sourceOrganization in HL7/fhir#4046 and commit 27bd95ec53c3ba23fcbd3acd1ad2b1443b206be2; its Jira comments explicitly accepted the build's use of search code organization rather than the initially suggested source-organization. That later decision explains the current organization search parameter and prevents treating it as a FHIR-51939 application error.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The seed request is already represented in the current authoritative source, and the only apparent mismatch from the original FHIR-51939 text is superseded by the later FHIR-56179 decision to add the sourceOrganization search parameter.

Recommendation:
Keep this audit commit as-is. Do not remove BiologicallyDerivedProduct.collection.sourceOrganization or its organization search parameter while reconciling FHIR-51939; any future concern about that search parameter should be handled under FHIR-56179 or a new OO decision.
