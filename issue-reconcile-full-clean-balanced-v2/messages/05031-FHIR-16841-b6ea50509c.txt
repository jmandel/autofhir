FHIR-16841: Audit fragment expansion parameter guidance

Issue request:
FHIR-16841 was a Published/Persuasive with Modification vocab Change Request raised against STU3 CodeSystem/ValueSet behavior. It asked for a way for a ValueSet expansion result to indicate that the expansion operation was completed against a CodeSystem fragment; the accepted resolution was to note this as one of the things that should be in expansion parameters, and how.

Initial application:
The Jira comment records SVN revision 14017. Git history shows the application in b178b1be54533cde22ea827d6cb8ef2ab5ddef11 and a5f0637555b6b6f47439a73fce551b681355fe62, which added and corrected the new ValueSet Expansion Parameters section and introduced the [canonical]#CodeSystem.content parameter. Later same-day commit 252fc52edfdbfbf0899b646437b94f6421358c8e strengthened that row to require applications generating expansions to use the parameter when CodeSystem.content is fragment, and commit ade907ca5b1bc08efb093bc524c5b00bdc7fa5ac removed a stray unfinished phrase from that sentence.

Additional context:
The current source/fhir.ini has active valueset=ValueSet and codesystem=CodeSystem resource entries, so source/valueset/valueset-notes.xml and source/codesystem/codesystem-notes.xml are current build inputs. Current CodeSystem narrative defines CodeSystem.content=fragment, and current ValueSet narrative requires expansion generators to include [canonical]#CodeSystem.content with the fragment content value when a fragment CodeSystem was used. Later FHIR-41589/FHIR-41639 work aligned broader expansion parameter documentation and added used-system/used-supplement/used-valueset response parameters without removing the fragment content parameter. FHIR-48959 is a later Resolved - change required proposal to add a used-fragment output parameter when completeness cannot be guaranteed, but it is not Applied/Published and remains outside this default reconciliation scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active ValueSet expansion parameter guidance already provides the required way to signal that an expansion used a CodeSystem fragment, and adding another core source edit for FHIR-16841 would either duplicate existing guidance or prematurely apply the later FHIR-48959 proposal.

Recommendation:
Keep this audit commit as-is for FHIR-16841. Handle FHIR-48959 separately when it reaches the applied/published workflow state, because it refines fragment-completeness signaling beyond the 2018 seed request.
