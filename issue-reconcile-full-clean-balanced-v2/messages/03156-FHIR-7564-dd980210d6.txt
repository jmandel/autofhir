FHIR-7564: Confirm AuditEvent vocabulary cleanup

Issue request:
FHIR-7564 was Published/Persuasive with Modification for the Security WG's 2015May AuditEvent value-set concern. It asked to relax AuditEvent.source.type, AuditEvent.object.type, AuditEvent.object.role, and AuditEvent.object.lifecycle to coded data with Preferred bindings, to allow additional value sets, to explain that AuditEvent profiles/IGs are the right way to specify event-specific recording rules, and to update Scope and Usage with ASTM and ISO foundations.

Initial application:
The issue was explicitly applied by git commit 8e1a48066d70501f76de61f4511ec19b48da2df2, "Updates for items 6233, 6269, 7431, 7564, 7566, 8123, and 8589." That commit added the AuditEvent Scope and Usage standards list and changed the then-current object type, role, and lifecycle rows from code to Coding. Later source conversions carried the same family forward as AuditEvent.source.type, AuditEvent.entity.type, AuditEvent.entity.role, and AuditEvent.entity.lifecycle.

Additional context:
AuditEvent is an active current-build resource in source/fhir.ini. The current source no longer matches the 2015 request literally because later published R5/R6 decisions intentionally changed the model: FHIR-32460 changed relevant AuditEvent codings, including source.type and entity.role/lifecycle, from Coding to CodeableConcept; FHIR-32463 made source.type Preferred with DICOM translation guidance; FHIR-32467/FHIR-32466 removed entity.type as redundant with entity.what; FHIR-32468 changed entity.role to an example binding; and FHIR-32470 removed entity.lifecycle from the core resource and moved that capability to the auditevent-Lifecycle extension, now maintained in the FHIR Extension Pack. Current narrative still says DICOM/IHE/ISO codes are examples that SHOULD be used when suitable, other codes can be defined, and Implementation Guides may make AuditEvent requirements clearer for workflow/security context.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because the current specification already preserves the durable intent of FHIR-7564 where it still applies and later published decisions supersede the literal DSTU1 element/binding details. Reintroducing removed elements, narrowing CodeableConcept back to Coding, or strengthening entity.role/lifecycle bindings would conflict with those later decisions.

Recommendation:
Keep this audit commit as-is. No core FHIR source follow-up is recommended for FHIR-7564; any future lifecycle-specific work should be evaluated in the FHIR Extension Pack where auditevent-Lifecycle now lives.
