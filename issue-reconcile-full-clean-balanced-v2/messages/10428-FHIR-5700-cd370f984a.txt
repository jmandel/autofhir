FHIR-5700: Audit constrained system-wide search

Issue request:
FHIR-5700 was a Published/Persuasive DSTU1 FHIR-core HTTP issue asking to remove search across all resource types because it was hard to implement, could mix same-named parameters with different meanings, and lacked a clear use case. The recorded final resolution did not remove the interaction; it constrained cross-resource search to base/common parameters, asked for a reference to that guidance and _text, and added Encounter, RelatedPerson, Practitioner, and Device compartments.

Initial application:
The directly relevant application is git-svn commit 5229cf7f3915899b829cd4d5e3780a4bfd916b17, svn revision 4386, whose subject explicitly mentions FHIR-5700. It moved root-level `GET [base]?[parameters]` out of the primary search form into variant searches, stated that all-resource searches may use only parameters defined for all resources, added _text and other common search controls to the all-resources search section, and added the requested compartment definitions. Earlier #5700 commits adjusted resource search criteria, but 5229cf7f is the commit that applied the HTTP/search/compartment decision recorded in Jira.

Additional context:
Later published issues refined the same root-search family without reversing FHIR-5700. FHIR-10459 corrected the all-resource GET URL to `GET [base]?parameter(s)`, FHIR-13836 clarified the _type/common-parameters rule for root searches, FHIR-12148 added cross-resource _type search support, and FHIR-36347 moved detailed base-search parameter guidance to `search.html#type`. Those later decisions make removing the root search interaction now unsafe; the correct current interpretation is that system-wide search remains available only under the later/common-parameter constraints.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current combined-branch source already matches the final FHIR-5700 resolution as refined by later decisions: the HTTP page still lists whole-system search and shows `GET [base]?[parameters]`, the Search page says no-_type all-resource searches may use only parameters common to all resource types and lists _text in the common-parameter table, and `source/compartments.xml` contains Encounter, RelatedPerson, Practitioner, and Device compartments.

Recommendation:
Keep this audit commit as-is. Removing system-wide search would contradict the applied FHIR-5700 resolution and later published search issues; any future removal should be handled as a new work-group decision rather than as reconciliation of this tracker.
