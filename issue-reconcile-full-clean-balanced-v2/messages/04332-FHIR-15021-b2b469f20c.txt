FHIR-15021: Audit Encounter admission origin references

Issue request:
FHIR-15021 was Published/Persuasive for STU3 by PA. It requested that Encounter.hospitalization.origin, and the same destination element noted in comments/resolution, allow references to both Organization and Location because the originating or destination facility may be known only as an organization name or identifier.

Initial application:
The issue was applied before this reconciliation. Commit b60b1f71994c66dccd2ef3964fd52a956acaa535 changed the then-authoritative Encounter spreadsheet so Encounter.hospitalization.origin used Reference(Location|Organization) and updated its wording to location/organization. Commit d81b5a8c41222f15a1fb9151aba3d8a8212d5dc7 followed with the FHIR-15021 correction for Encounter.hospitalization.destination.

Additional context:
FHIR-32390 later renamed Encounter.hospitalization to Encounter.admission for R5. The current fhir.ini keeps legacy maps from Encounter.hospitalization.origin and .destination to Encounter.admission.origin and .destination, and Encounter is an active approved resource in the current build. A PA Zulip thread records the rationale and 5-0-0 persuasive resolution; no Confluence reference for FHIR-15021 was found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative Encounter StructureDefinition already has Encounter.admission.origin and Encounter.admission.destination as Reference elements with both Location and Organization targetProfiles, preserving the FHIR-15021 semantics under the later admission rename.

Recommendation:
Keep this no-change audit commit as-is. No core source follow-up is needed unless PA later changes the Encounter.admission origin/destination target resource set.
