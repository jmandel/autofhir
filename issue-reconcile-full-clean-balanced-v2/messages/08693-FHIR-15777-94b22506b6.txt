FHIR-15777: Audit FHIRPath terminology service API

Issue request:
FHIR-15777 was a Published FHIR-core change request, resolved Persuasive, raised and applied for STU3, asking to define a standard terminology service API so terminology operations can be referenced from FHIRPath constraints. The approved resolution was to add this to the context for FHIRPath.

Initial application:
The Jira comments cite svn revision 13922. Git commit 843247233eca86f26c8251f8a1c59d94c13d692f is the git-svn import of build@13922 and added a Terminology Service API section to source/fhirpath.html, including %terminologies operations for expand, lookup, validateVS, validateCS, subsumes, and translate. The current source retains this section.

Additional context:
The current source/fhirpath.html page is the active FHIRPath page linked from the specification documentation. Later edits kept the API while reorganizing the page for the separate FHIRPath release 2 specification and adding related FHIR-specific APIs. FHIR-46082 later refined the same terminology section by adding %terminologies and %terminologies.at(url) so expressions can identify the default or a specific terminology server. Community searches found no Zulip or Confluence evidence that changes the Jira and source-history conclusion.

AutoFHIR reconciliation:
