FHIR-34098: Audit PlanDefinition trigger semantics

Issue request:
FHIR-34098 was a Published/Persuasive CDS change request for FHIR-core PlanDefinition. It asked to clarify that when multiple trigger definitions are present on a PlanDefinition action, ANY triggering event invokes the action rather than requiring all triggers.

Initial application:
The Jira comment links HL7/fhir PR #1802. That PR was merged by e793bfc7ab512424f052bc68d699a77a5e2be01a and included commit 6b2c72268228cec5c9af4b844ad17244b469e0a2, which added the clarification sentence to source/plandefinition/structuredefinition-PlanDefinition.xml.

Additional context:
source/fhir.ini actively includes plandefinition=PlanDefinition, so source/plandefinition/structuredefinition-PlanDefinition.xml is in the current core build. Later source cleanups reformatted or regenerated the PlanDefinition StructureDefinition but preserved the OR-semantics sentence. Zulip discussion before the Jira confirms the intended semantics were OR, and a later Zulip clarification says the post-R4 CI build wording reflects the same intent. Confluence has no direct FHIR-34098 references.
