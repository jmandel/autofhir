FHIR-13201: Audit Condition abatement invariant

Issue request:
FHIR-13201 was Published/Persuasive with Modification for STU3. It asked to correct the Condition con-4 XPath because the prior rule could reject a resolved clinicalStatus with no abatement value; the approved resolution removed abatementBoolean, required inactive/resolved/remission only when abatement is populated, and left clinicalStatus unconstrained by this invariant when abatement is absent.

Initial application:
The issue was applied in bac396f21d6dc845c746e29a9fb7c79e27ee6ff5, which updated the Condition spreadsheet invariant, removed the abatementBoolean datatype and abatement-boolean search parameter, and changed the f204 renal example to inactive. The spreadsheet content was later migrated into source/condition/structuredefinition-Condition.xml during the core source refactor.

Additional context:
Later Condition decisions refined the same area without reopening the FHIR-13201 rule. FHIR-22973 proposed allowing abated conditions with no clinicalStatus, but FHIR-29409 subsequently made Condition.clinicalStatus 1..1 and rendered that exception unnecessary. The 2022 ElementDefinition cleanup removed XPath rows from current StructureDefinition source. FHIR-39630 later reused key con-4 for an unrelated bodyStructure/bodySite invariant, so the current abatement invariant is key con-3.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Condition is active in source/fhir.ini; the current Condition StructureDefinition has no XPath entry, no abatementBoolean datatype, no abatement-boolean search parameter in the authoritative resource definition, and its abatement rule is `abatement.exists() implies (...)`, which matches the approved direction by constraining only populated abatement cases to inactive/resolved/remission clinical status codes.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-13201; any future change to the abatement/clinicalStatus policy should be handled as a new Patient Care decision because later applied issues have already superseded the STU3 XPath-specific concern.
