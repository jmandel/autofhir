FHIR-5608: Audit imaging retrieval element naming

Issue request:
FHIR-5608 was a Published/Persuasive FHIR-core Imaging Integration change request for DSTU1. It asked that the WADO-RS retrieval link use a consistent element name because ImagingStudy used url while ImagingObjectSelection used retrieveUrl, and it also asked the work group to consider ordering common elements consistently. The final Jira resolution was narrower: rename RetrieveUrl to url.

Initial application:
The application commit a51afaf7a9b18b211c1b998e3903993967cc3984 explicitly cites [#5608] and renamed ImagingObjectSelection retrieveUrl elements in the example and spreadsheet to url. A residual explanatory cell still mentioned retrieveUrl in that old spreadsheet at the time, but the element paths and example tags were changed to url.

Additional context:
The affected ImagingObjectSelection artifact did not remain an active current-build resource. Later source history renamed ImagingObjectSelection/ImagingExchange to ImagingManifest, removed ImagingManifest from active resources, and introduced the current ImagingSelection resource. Current source/fhir.ini lists only imagingselection and imagingstudy as active resources in this family and lists imagingmanifest and ImagingObjectSelection under removed-resources. Current active ImagingSelection uses Endpoint references and Endpoint.address for DICOM WADO access rather than a retrieveUrl/url element, and current active ImagingStudy has no ImagingStudy.url or ImagingStudy.series.url element. The only current retrieveUrl occurrence found in source is a historical release-note entry describing the old rename.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build no longer contains an active ImagingObjectSelection retrieveUrl element, the successor/current imaging retrieval guidance is represented through ImagingSelection.endpoint, and editing removed-resource source or historical release notes would not improve the current specification.

Recommendation:
Keep this no-change audit as-is. No core source follow-up is needed for FHIR-5608 unless a future human review chooses to curate removed-resource archival files outside the current build.
