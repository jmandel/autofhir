FHIR-31485: Audit Slot serviceType Schedule wording

Issue request:
FHIR-31485 was a Published/Persuasive Patient Administration change request for FHIR-core Slot. It asked that Slot.serviceType stop using the undefined phrase "availability resource" and the final resolution said the definition should instead say that it overrides the value provided on the Schedule resource.

Initial application:
The issue was applied before this reconciliation by git commit 938a96e1cdd538baa9f7d6a4e5d7126edc42aafc, which changed source/slot/structuredefinition-Slot.xml from "availability resource" to "Schedule resource" in Slot.serviceType and also updated the nearby iCal mapping from Availability to Schedule. No prior Issue-Reconcile-Key audit commit for FHIR-31485 existed on the combined branch.

Additional context:
Slot is active in the current build: source/fhir.ini lists Slot in the active [resources] section and marks Slot approved. A later same-element change, FHIR-22687, changed serviceType to CodeableReference but did not reintroduce the undefined wording. PA May 2021 minutes record the same persuasive 7-0-0 disposition, and a 2017 Zulip question shows the original ambiguity existed without adding a conflicting resolution.

AutoFHIR reconciliation:
This commit intentionally makes no source changes. The authoritative current Slot StructureDefinition already says "Schedule resource" in both the short and definition for Slot.serviceType, and a source-wide search found no remaining "availability resource" phrase.

Recommendation:
Keep this audit commit as-is. No source follow-up is needed for FHIR-31485 unless a future ballot deliberately revisits the scheduling model wording.
