FHIR-46494: Audit notification authorization hinting

Issue request:
FHIR-46494 was Applied/Persuasive for FHIR-core R6 Subscriptions and SubscriptionStatus. It requested that R6 add documentation and examples for authorization information in subscription notifications, based on the authorization-hint work approved for the Subscriptions Backport IG in FHIR-43081 and incorporating the FHIR-44102 clarification.

Initial application:
The combined branch did not yet have an Issue-Reconcile-Key commit for FHIR-46494. The source change itself was already present from commit 0857a9913b, merged through HL7/fhir#3967, which added SubscriptionStatus.notificationEvent.authorizationHint, an id-only notification example using authorizationHint, and an Authorization Hinting in Notifications subsection. Later build-fix commit e47a0d9002 refined the authorizationType and value labels/definitions.

Additional context:
FHIR-43081 approved the backport authorization-hint concept as a Coding plus optional string value for SubscriptionStatus.notificationEvent, while FHIR-44102 clarified that the type describes how the sibling value is to be used. FHIR-I minutes show the backport-to-R6 family was queued for review on 2024-07-29 and FHIR-46494 was approved 11-0-0 on 2024-08-05. Current source/fhir.ini actively includes SubscriptionStatus, so the checked StructureDefinition and examples are build-scope source.

AutoFHIR reconciliation:
No source change was made. The current R6 source already contains the requested authorizationHint structure on SubscriptionStatus.notificationEvent, an example notification with authorizationType/value, and security-oriented subscription guidance covering short-lived/single-use tokens and secure handling. The current wording sufficiently carries the FHIR-44102 clarification by making authorizationType classify the hint and value be defined by authorizationType.

Recommendation:
Keep this empty audit commit as-is. Future work should be handled through a new tracker only if the work group wants a stronger terminology binding or different standard code system; FHIR-46494's applied documentation/example request is already represented in active core source.
