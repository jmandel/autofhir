FHIR-11549: Audit intent-resource examples

Issue request:
FHIR-11549 is a Published/Persuasive CDS change request, raised against DSTU2 ActivityDefinition, asking for full examples of intent resources created from definitional resources using both StructureMap and dynamicValues approaches; the description also says the same applies to PlanDefinition. The approved resolution was that full examples would be provided.

Initial application:
The Jira comments record SVN 11431. Local git history maps that to 6b3d41e5942929df6a82eeda4debd668bbdfc3ec, which explicitly mentions #11549 and added ActivityDefinition and PlanDefinition $apply request/response examples plus the operation example hooks. No prior combined-branch commit for Issue-Reconcile-Key: FHIR-11549 was present before this reconciliation.

Additional context:
ActivityDefinition and PlanDefinition are active current-build resources in source/fhir.ini. Since the original DSTU2 issue, the current source has evolved from "intent resources" terminology to request-resource application semantics: ActivityDefinition notes describe $apply realization through kind, StructureMap, and dynamicValue; PlanDefinition notes describe applying contained ActivityDefinitions and overriding dynamicValue behavior; ActivityDefinition and PlanDefinition examples still include ServiceRequest and MedicationRequest realization examples with dynamicValue content and operation response snippets. The closely related StructureMap/default-map request FHIR-11652 is already represented on the combined branch as a no-change audit, which records that later FHIR-29210/PR #2834 supplied the broad ActivityDefinition mapping snippets and companion .fhirmap files.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source already preserves the examples and mechanisms needed to satisfy the applied FHIR-11549 request when read with later mapping/example work. Adding a new exhaustive example set for every current request resource type, or rewriting all clinical reasoning examples for modern style, would be a new editorial/design decision rather than a necessary correction to this Published DSTU2 tracker.

Recommendation:
Keep this no-change audit. If CDS wants a fully refreshed R6 example suite with validated end-to-end $apply outputs for every request resource kind, handle that as a new tracker or under an existing open example-quality tracker rather than reopening FHIR-11549.
