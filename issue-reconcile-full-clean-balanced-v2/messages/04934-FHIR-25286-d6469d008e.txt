FHIR-25286: Audit FML delimited identifier harmonization

Issue request:
FHIR-25286 was a Published/Persuasive FHIR-core change request asking to harmonize FHIR Mapping Language delimited identifiers with FHIRPath by removing the double-quote option and leaving only backtick-delimited identifiers.

Initial application:
The issue was initially applied in git commit 54fc90739e2cf48503811483f3cf7ffa8c5a5ce6, which updated source/mapping-language.html to say escaping is done with backticks and changed examples from double quotes to backticks. The grammar itself still needed a later correction, which was applied by FHIR-39282 in commit 4988dd04f338d63595d004d52ccfb55c8dc9aa60.

Additional context:
FHIR-39282 is the later same-change-family technical correction that completed the grammar side of the FHIR-25286 request. The current source keeps mapping-language.html in the built hierarchy and publishes mapping.g4; the current grammar's DELIMITEDIDENTIFIER rule is backtick-only, while DOUBLE_QUOTED_STRING remains available only for other FML string constructs such as URLs, metadata values, and rule names. The Zulip discussion linked from FHIR-25286 supports the rationale for avoiding double-quoted identifiers.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because the current mapping language narrative, examples, and grammar all consistently implement the backtick-only delimited identifier rule requested by FHIR-25286.

Recommendation:
Keep this audit commit as-is. No follow-up is needed in core unless a future grammar refactor accidentally makes double-quoted strings valid identifiers again.
