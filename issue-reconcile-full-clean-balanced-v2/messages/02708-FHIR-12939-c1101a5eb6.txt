FHIR-12939: Audit security role vocabulary guidance

Issue request:
FHIR-12939 was a Published Security WG change request, resolved Persuasive with Modification for DSTU2, asking that the Security Role vocabulary and PurposeOfUse vocabulary be discussed more prominently on the Security and Privacy module/security page. The accepted wording asked for guidance that users have functional and/or structural roles declared when relevant, that roles use standard codes, that purpose of use be asserted for requested resource actions using standard codes, and that OAuth authorization services may manage and convey role and purpose-of-use information in JWT security tokens.

Initial application:
The request was applied by commit 84f8086d21facb3551bfb28481156250510ae48b, whose subject explicitly listed GF#12939 under Security and Privacy Module updates. That commit added the requested User Identity and Access Context guidance to source/secpriv-module.html, including links to the then-current Security Role Vocabulary and Purpose of Use Vocabulary.

Additional context:
The current build still contains the same guidance on source/secpriv-module.html, an active Security and Privacy Module page linked from the security module index. Later Security WG terminology work changed the role value set from the old broad security-role-type value set into the current example security-role-type-example value set; FHIR-32520 explains that the security role value set should be example structural role guidance, and the current module text now links to Example Security Role Vocabulary. The separate source/security.html Authorization/Access Control section already lists user role and purpose of use among access-control decision inputs and links back to related security guidance, so duplicating the module wording there would be redundant rather than a required correction.

AutoFHIR reconciliation:
This audit commit makes no source change because the accepted Jira guidance is already present in current build-scope source and later terminology changes explain the updated value-set link and wording.

Recommendation:
Keep this no-change audit commit as-is. Future work should only revisit the wording if the Security WG decides that the Security Principles page should duplicate the module-level User Identity and Access Context guidance; FHIR-12939 itself is already satisfied by the active module source.
