FHIR-23738: Audit Subscription topic-based redesign

Issue request:
FHIR-23738 is a Published/Persuasive FHIR-I change request for R5 that served as the placeholder for the Argonaut-led Subscription redesign, including aligning Subscription with a publish-subscribe pattern using SubscriptionTopic and client filters.

Initial application:
The broad redesign was applied before this reconciliation. Early GF#23738 commits revised Subscription notes in 2019, and merge commit 87b7ee84c2 (PR #848 from HL7/argonaut-subscription) merged the Argonaut Subscription branch on 2020-04-27 with the explicit message "Subscription R5 work: https://jira.hl7.org/browse/FHIR-23738". That merge introduced or updated Subscription, SubscriptionTopic, SubscriptionStatus, subscription-notification Bundle content, and related narrative/examples. Later R5 cleanup and ballot commits converted the source to the current build format and refined details.

Additional context:
FHIR-I minutes for 2020-04-27 reference FHIR-23738 and record approval to merge the Subscription changes, specifically naming subscription.topic, Subscription.filterBy, removal/flattening of Subscription.channel, SubscriptionTopic, the subscription-notification Bundle type, and SubscriptionStatus. The same discussion is mirrored in Zulip. Later Published R5 issues, including FHIR-39026 and FHIR-39028, refined the SubscriptionTopic filter model and timing text, so current comparator/modifier and trigger wording should be read as later approved refinements rather than a missed literal copy of the 2020 branch notes.

AutoFHIR reconciliation:
No source change was made. The current build-scope source already contains the R5 topic-based model: source/fhir.ini actively includes Subscription, SubscriptionTopic, and SubscriptionStatus; Subscription.topic is a required canonical reference to SubscriptionTopic; Subscription.filterBy defines client filters; SubscriptionTopic.trigger.canFilterBy defines allowed filters; SubscriptionStatus and subscription-notification Bundle rules are present. The seed issue is therefore adequately represented in the current source.

Recommendation:
Keep this no-change audit commit as-is. Do not use FHIR-23738 as a reason to re-expand the 2020 branch text into current source; any remaining concerns should be handled through the narrower related Jira issues or newer R6 trackers.
