Issue request:
FHIR-48389 was an Applied FHIR-core DiagnosticReport change request from OO, resolved Persuasive with Modification for R6. It asked for machine-readable encoding of the radiology assertion that no comparison exams were available; the final resolution added DiagnosticReport.comparison (0..1 Reference(List)), defined its short and long descriptions, noted List.entry.item profiling for ImagingStudy, DiagnosticReport, or Observation, and clarified that DiagnosticReport.supportingInfo should not duplicate resources referenced elsewhere such as comparison.

Initial application:
The source change appears to have been applied in commit e6a85fac75c45701596e307987e910220386a599, "Assert no comparison exams were available", linked from Jira as PR #3705. That commit added the DiagnosticReport.supportingInfo comment and the new DiagnosticReport.comparison differential element in source/diagnosticreport/structuredefinition-DiagnosticReport.xml.

Additional context:
source/fhir.ini actively includes diagnosticreport in the current build, so source/diagnosticreport/structuredefinition-DiagnosticReport.xml is build-scoped. OO Confluence minutes from 2025-09-25 and 2025-09-30 show the work group reconsidered the original attempt to constrain List.entry.item inside the referenced List, then retained a Persuasive with Modification outcome with explanatory comment text rather than an impossible inline target constraint. The related FHIR-48391 patient-history issue separately changed DiagnosticReport.supportingInfo and added DocumentReference; it does not supersede or contradict this comparison element.

List.emptyReason remains the correct mechanism for representing an empty comparison list with nil-known/no-comparison semantics.

Keep this empty audit commit as-is. No further core source work is needed for FHIR-48389 unless OO later decides to add a formal DiagnosticReport.comparison profile or invariant on the referenced List, which was explicitly not part of the applied source representation.
