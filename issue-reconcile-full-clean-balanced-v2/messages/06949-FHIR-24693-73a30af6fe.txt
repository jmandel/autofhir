FHIR-24693: Audit native Observation valueAttachment

Issue request:
FHIR-24693 was an Applied/Persuasive OO change request raised against STU3 and applied for R6. It asked to include Observation.valueAttachment in the R5/R6 build as an STU item and to clearly document when to use Observation.valueAttachment versus Observation.derivedFrom and DiagnosticReport.presentedForm in the Observation introduction and element definitions.

Initial application:
The Jira comments identify commit 0acff97ca003816dc9ddb57f84c591cffbd84666 as the partial 2019 application. That commit added Attachment to the Observation value[x] and component.value[x] type lists in the old spreadsheet source and added guidance explaining that Attachment represents the actual binary observation result, while derivedFrom references a DocumentReference when the observation value is derived from the binary content. The later core source rework commit 33b409a4b6d544598262f2f074ebb4b6dc466157 converted that applied spreadsheet content into the current StructureDefinition source with Attachment still present.

Additional context:
Observation is an active current-build resource in source/fhir.ini. Current source/observation/structuredefinition-Observation.xml includes Attachment for Observation.value[x] and Observation.component.value[x], and the value[x] element comment includes the Attachment-versus-derivedFrom guidance and points to the Observation notes. Current source/observation/observation-notes.xml lists valueAttachment and explains Attachment, derivedFrom, DiagnosticReport.media, and DiagnosticReport.presentedForm usage. The Jira follow-up noted that making only one choice type Trial Use was not supported; the linked Zulip conformance discussion confirms that limitation. The tightly related FHIR-24695 R4-extension issue is already represented on the combined branch by audit commit 8829d816a947f849a0b678c91fd2cad02f2e9cef, so this commit does not duplicate that decision.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The active Observation source already contains the requested native Attachment choice and the requested usage guidance, and later wording cleanup in the same guidance has already been handled by FHIR-55270.

Recommendation:
Keep this audit commit as-is for core. Any future concern about choice-level standards status or cross-version extension packaging should be handled as a separate infrastructure or extension-packaging decision, not by adding duplicate Observation prose.
