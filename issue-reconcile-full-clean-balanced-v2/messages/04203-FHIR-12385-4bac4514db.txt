FHIR-12385: Audit MedicationStatement workflow harmonization

Issue request:
FHIR-12385 was Published with a Persuasive with Modification resolution for Pharmacy's DSTU2 MedicationStatement workflow harmonization. The approved notes said to keep identifier, code, and status unchanged; rename patient to subject and allow Group; rename/add reason code/reference support including Observation; add basedOn and context; and later add partOf plus wording for effective[x] and dosage.

Initial application:
The request was applied across the historical spreadsheet source rather than as one exact Jira-keyed source commit. Commit ea9a368e150219ed88a5b2d9811443fcdee98cec explicitly cited TR#12385 and renamed MedicationStatement.patient to subject, allowed Reference(Patient | Group), renamed reasonForUseCode to reasonForUseCodeableConcept, and expanded reasonForUseReference to Condition | Observation. Commit 9445bd2bbd2e405f15219ddd6b7abafec40353a7 then added MedicationStatement.basedOn and MedicationStatement.context as workflow elements. Commit 7003eba639b96a6cb1198300f293effe3f4bda1d added MedicationStatement.partOf and the requested effective[x] and dosage guidance.

Additional context:
MedicationStatement is active in source/fhir.ini, and the current authoritative source is source/medicationstatement/structuredefinition-MedicationStatement.xml. Current source preserves the workflow mapping, subject Group support, encounter/context mapping, occurrence/effective mapping, reason as CodeableReference including Observation, dosage guidance, and partOf. The current build no longer has MedicationStatement.basedOn: source/fhir.ini records basedOn as removed and context renamed to encounter. That absence is not a FHIR-12385 reconciliation fix because FHIR-32071 later recorded a no-change decision that basedOn had been removed from MedicationUsage, while FHIR-55888 is a separate 2026 Resolved - change required request to add basedOn back but has not reached Applied or Published status in this run scope.

AutoFHIR reconciliation:
This empty audit commit makes no source change. Re-adding basedOn under FHIR-12385 would bypass the separate FHIR-55888 add-back decision, and the other FHIR-12385 workflow harmonization semantics are already represented in current active source or by later accepted names such as encounter and reason.

Recommendation:
Keep this audit commit as-is for FHIR-12385. If the run scope later includes Resolved - change required issues, apply the MedicationStatement.basedOn restoration and explanatory comments under FHIR-55888 in its own commit; do not reopen FHIR-12385 for that later change.
