FHIR-31422: Audit Bundle fullUrl URI scheme clarification

Issue request:
FHIR-31422 was Published/Persuasive with Modification for R5. It asked FHIR-I to clarify that Bundle.entry.fullUrl examples such as urn:uuid, urn:oid, http, and https are examples rather than an exclusive scheme list, and that in-Bundle Reference.reference matching can use any URI scheme in addition to relative references.

Initial application:
The issue appears to have been applied by Rick Geimer's e084181ce7 commit, which explicitly updated source/bundle/structuredefinition-Bundle.xml and source/bundle/bundle-notes.xml for FHIR-29271 and FHIR-31422. That commit added the "e.g." short-definition wording, the arbitrary-URI fullUrl definition text, and Bundle reference-resolution prose for Reference.reference URI schemes. The commit is already an ancestor of the current worker source.

Additional context:
FHIR-29271 is the tightly related Published issue that rewrote Bundle reference resolution, and FHIR-31422 supplied the URI-scheme clarification layered onto that section. FHIR-I minutes from 2021-04-05 record the ambiguity, exact matching semantics, and the 15-1-3 Persuasive with Modification decision. A follow-up Zulip exchange confirms the intended scope covered Bundle.entry.fullUrl and reference.reference. Later Bundle edits adjusted surrounding wording but preserved the URI-scheme clarification.

AutoFHIR reconciliation:
No source change was made. The current build-scoped Bundle source already has Bundle.entry.fullUrl short text framed as examples, the definition says fullUrl can be an arbitrary URI and is not limited to urn:uuid, urn:oid, http, or https, and bundle-notes says reference.reference in entry resources can use any URI scheme.

Recommendation:
Keep this empty audit commit as-is. No follow-up source work is needed for FHIR-31422 unless a future work group decision reopens the broader Reference datatype wording outside Bundle entry resolution.
