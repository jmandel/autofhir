FHIR-13551: Audit CapabilityStatement kind constraint replacement

Issue request:
FHIR-13551 was a Published/Persuasive with Modification FHIR-core Conformance change request for STU3. It reported that cpb-15 incorrectly said kind instance CapabilityStatements do not have implementation elements and that the textual representation and repeated expressions around CapabilityStatement.kind did not match the intended rules. The accepted resolution replaced cpb-14/cpb-15 with three rules: kind instance requires implementation and may have software; kind capability prohibits implementation and requires software; kind requirements prohibits both implementation and software. It also requested scope-section text that names the three kinds and their implementation/software constraints and a clearer CapabilityStatement.kind definition.

Initial application:
The issue was explicitly applied by git-svn commit ae4fe43507fa005829ffdb6b3116b52a87e84050, '#13551 - fix capability statmnet invariants', recorded as SVN revision 13876 in the Jira comment. That commit added the current Scope and Usage table and anchors for Instance, Capability, and Requirements, and replaced the old spreadsheet constraints with the three-rule model.

Additional context:
FHIR-13550 was an earlier Published issue from the same reporter that partially corrected cpb-15 to allow implementation only for kind instance; FHIR-13551 superseded it with the more complete three-rule resolution. Later FHIR-19955 and FHIR-36685 dealt with stale XPath/Schematron details for the same constraints and are already represented on the combined branch as no-change audits because current mainline removed XPath constraint fields. Later FHIR-55150 is Resolved - change required but not Applied/Published and would clarify use of requirements as a fallback; it does not reverse the FHIR-13551 implementation/software constraints and is outside this default reconciliation scope.

This audit commit intentionally makes no source change. CapabilityStatement is an active build resource, the current StructureDefinition has cpb-16/cpb-15/cpb-14 with the accepted FHIRPath semantics and condition references on kind/software/implementation, and the current introduction contains the requested three-kind table and corresponding scope subsections.

Recommendation:
