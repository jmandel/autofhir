FHIR-12749: Audit ContactPoint phone-part extensions

Issue request:
FHIR-12749 was a FHIR-core Published/Persuasive change request for DSTU2 asking to add ContactPoint phone-number part extensions for country code, area/zone/city code, local number, and private-network extension. The accepted resolution said each component should be optional, should describe use for systems that need parsed phone-number parts, and should state that ContactPoint.value SHOULD still be populated when the extension is present.

Initial application:
The issue was applied in core by git-svn commit 01e275584309380677051d6b139af44070ab3d73, matching Jira's svn revision 12469 comment. That commit added source/datatypes/contactpoint-extensions-spreadsheet.xml and the active source/fhir.ini profile entry, with rows for country, area, local, and extension on ContactPoint using string values, 0..1 cardinality, the requested descriptions, and the ContactPoint.value SHOULD comment.

Additional context:
FHIR-core later removed the ContactPoint extension rows from R5 source in commit dd468d4f1799dd79819315b211588ef1cf4586e0 as part of moving standard extensions out of core. The current FHIR Extension Pack repository now owns the authoritative definitions as input/definitions/datatypes/StructureDefinition-contactpoint-country.xml, StructureDefinition-contactpoint-area.xml, StructureDefinition-contactpoint-local.xml, and StructureDefinition-contactpoint-extension.xml. Related Extension Pack issue FHIR-41562 subsequently changed these definitions' context from ContactPoint to ContactPoint.value, explaining the intentional difference from the original core spreadsheet rows.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR-core source change. The current core checkout no longer contains active definitions for these extension artifacts beyond historical release bundles and OID registry references, while the Extension Pack source contains the four requested active definitions with the accepted descriptions and ContactPoint.value population guidance.

Recommendation:
Keep this audit commit as-is for FHIR-core. No core follow-up is needed for FHIR-12749; future source edits, if any, belong in the FHIR Extension Pack rather than this core checkout.
