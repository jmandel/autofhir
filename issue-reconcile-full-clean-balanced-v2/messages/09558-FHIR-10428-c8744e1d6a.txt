FHIR-10428: Audit StructureMap profile references

Issue request:
FHIR-10428 was Published as Persuasive with Modification for DSTU2 after asking that StructureMap be able to identify constrained inputs and outputs such as profiles and Questionnaires. The recorded resolution was that the mapping language already supports this.

Initial application:
No Jira-tagged source commit for FHIR-10428 was found. The original draft StructureMap source already had StructureMap.structure.url as a URI for the canonical URL that identifies a structure, and later source refactors carried that declaration forward as a canonical reference to StructureDefinition.

Additional context:
StructureMap is active in source/fhir.ini. In the current source, StructureMap.structure.url and the FHIR Mapping Language uses statements point at StructureDefinition canonicals, which covers profiles because profiles are StructureDefinitions. Questionnaire-specific applicability is still expressible by normal StructureMap source conditions/checks over the input instance, so adding Questionnaire as a first-class StructureMap.structure target would be a new semantic expansion beyond the recorded resolution. Later Jira/Zulip/Confluence searches did not find a final decision changing that interpretation.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The current core source matches the published Jira decision closely enough: profile references are represented by StructureDefinition canonicals and non-structural Questionnaire constraints can be enforced in the mapping rules rather than by changing the StructureMap.structure target type.

Recommendation:
Keep this audit commit as-is. If the work group now wants StructureMap.structure.url or FHIR Mapping Language uses statements to directly accept Questionnaire canonicals as searchable metadata, that should be revisited as a new source-changing decision because it would alter the current canonical target model.
