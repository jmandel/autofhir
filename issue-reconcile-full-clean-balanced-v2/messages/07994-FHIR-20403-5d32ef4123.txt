FHIR-20403: Audit StructureDefinition derivation invariant

Issue request:
FHIR-20403 was a Published FHIR Infrastructure change request, resolved Persuasive with Modification for R5, asking that StructureDefinition.derivation be mandatory or otherwise validated because missing derivation makes a StructureDefinition with a baseDefinition ambiguous. The approved resolution was to add an invariant: if baseDefinition.exists() implies derivation.exists().

Initial application:
No commit explicitly mentioning FHIR-20403 was found. The requested rule appears to have been applied implicitly in eefb19aee666980d9efede00670c6ce795820c8b, which added sdf-27 to StructureDefinition with expression baseDefinition.exists() implies derivation.exists(); later reformatting retained the invariant.

Additional context:
source/fhir.ini lists structuredefinition=StructureDefinition in the active [resources] section, so source/structuredefinition/structuredefinition-StructureDefinition.xml is in current build scope. The current StructureDefinition.derivation element remains min=0 but carries condition sdf-27, which preserves the exception for structures without a baseDefinition while enforcing derivation whenever baseDefinition exists. Quoted Zulip and Confluence searches found no community evidence changing the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change because the current source already contains the approved sdf-27 invariant and links it from both StructureDefinition.baseDefinition and StructureDefinition.derivation. Changing the element cardinality to 1..1 would be broader than the accepted modified resolution and would not respect the base-less root definitions discussed on the issue.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed unless the work group later chooses a stricter rule for base-less root StructureDefinitions.
