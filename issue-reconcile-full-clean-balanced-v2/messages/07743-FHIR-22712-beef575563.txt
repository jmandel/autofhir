FHIR-22712: Audit STU3 eld-10 backport

Issue request:
FHIR-22712 was Published with resolution Persuasive. It asked to apply the prior eld-10 correction to STU3/R3 because the old ElementDefinition.binding invariant, "provide either a reference or a description (or both)", caused false validation errors for differential bindings; the accepted resolution was that R3 should read as R4 did after GF#13782.

Initial application:
The parent FHIR-13782 issue was applied by svn/git commit f57d0e635b in December 2017, removing the old eld-10 invariant from the ElementDefinition datatype source for R4. FHIR-22712 itself was later recorded as applied to the FHIR STU3 v3.0.2 specification published on 2019-10-14, and current published STU3 and R4 ElementDefinition profile artifacts no longer contain the old eld-10 text.

Additional context:
The current build-scope source has ElementDefinition as an active normative datatype in source/fhir.ini and no longer contains the old eld-10 invariant text. A later, separate R5 issue, FHIR-26892, added ElementDefinition.binding invariant 23 requiring either description or valueSet; that later invariant and the related FHIR-48325 descriptive binding work are already represented on the combined branch and are not duplicated here. The checked-in tools/history/release3 generated profile files still contain old eld-10 text, but they are historical generated artifacts, not the authoritative current source or a current-build STU3 backport input.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The requested STU3 backport is already reflected in the published STU3 profile surface, and changing current R6 ElementDefinition binding rules would duplicate or contradict later FHIR-26892/FHIR-48325 reconciliation rather than complete FHIR-22712.

Recommendation:
Keep this audit commit as-is. Do not edit historical generated release3 files for this issue; if the work group wants to revisit the later eld-23 differential behavior, use a new focused FHIR-I tracker rather than reopening this already-published STU3 backport.
