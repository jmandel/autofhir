FHIR-17624: Audit reference policy definitions

Issue request:
FHIR-17624 was a Published/Persuasive FHIR-core Conformance issue asking that the ReferenceHandlingPolicy code system definitions clarify which code corresponds to literal references, which corresponds to logical references, and what it means for a server to resolve logical references to literal references.

Initial application:
The issue was applied in git-svn commit 5f2716093f (svn r14525), which changed source/capabilitystatement/capabilitystatement-spreadsheet.xml to add the requested inline explanations: literal references use Reference.reference, logical references use Reference.identifier, and resolving converts Reference.identifier to Reference.reference. Later source refactoring, including 33b409a4b6, split the CapabilityStatement spreadsheet into standalone terminology files; the current CodeSystem still carries the clarified definitions.

Additional context:
CapabilityStatement is an active resource in source/fhir.ini, and CapabilityStatement.rest.resource.referencePolicy is still bound to http://hl7.org/fhir/ValueSet/reference-handling-policy in the current StructureDefinition source. The Reference datatype narrative also explains resolving logical identifier references and points readers to CapabilityStatement.rest.resource.referencePolicy. Jira/Zulip/Confluence searches found no conflicting FHIR-core decision; FHIR-37901 is a later FHIR-us-core issue that quotes the current resolves wording for an IG-specific conformance expectation.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped CodeSystem already says literal means using Reference.reference, logical means using Reference.identifier, and resolves means converting Reference.identifier to Reference.reference; adding duplicate prose would not change implementer understanding.

Recommendation:
Keep this audit commit as-is. No FHIR-core follow-up is needed unless a future work group decision changes the reference-handling policy semantics.
