FHIR-17557: Audit ConceptMap standards status

Issue request:
FHIR-17557 was a Published/Persuasive Vocab change request raised against STU3/R4 stating that ConceptMap should not go normative in R4 and should remain STU/Trial Use. The resolution was to change ConceptMap to Trial Use status as requested, with the Jira noting the change was pre-applied.

Initial application:
The directly related GForge/Jira family was applied through GF#16363. Git commit cd9f15d22c removed ConceptMap from source/fhir.ini's [normative-package] section, and FHIR-16363 records that svn revision 14127 as the implementation. R4 publication metadata now reports ConceptMap as trial-use with FMM 3, matching the 2018 request.

Additional context:
The current build is no longer the R4 normative-candidate context from FHIR-17557. Later Terminology Infrastructure work moved ConceptMap onto the R6 normative path: Confluence minutes in 2023 say ConceptMap was on track for normative in R6, and git commit 148c3eb080 later changed the ConceptMap StructureDefinition and $translate operation standards status from trial-use to normative with normative version 6.0.0. Current source keeps ConceptMap in build scope via source/fhir.ini and carries the normative status in the active ConceptMap StructureDefinition.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Reverting ConceptMap to Trial Use would reapply the old R4 decision over a later R6 normative-ballot source change. The seed issue is therefore reconciled as already applied for its original scope and superseded by later current-build decisions.

Recommendation:
Keep this audit commit as-is. If the R6 normative classification itself is questioned, open or reconcile a separate R6-era tracker rather than using FHIR-17557 to undo the later ConceptMap normative work.
