FHIR-24666: Audit medication basedOn additions

Issue request:
FHIR-24666 was a Published Pharmacy change request with resolution Persuasive with Modification. The request asked to link MedicationStatement, MedicationDispense, and MedicationAdministration to CarePlan like MedicationRequest.basedOn; the final resolution narrowed the applied change to adding basedOn to MedicationDispense and MedicationAdministration as 0..* Reference(CarePlan).

Initial application:
Jira records that the issue was committed on 2019-09-20 in HL7/fhir commit 2933d19faad5a9c3da59470ac68ba7222b4495d7. That commit added MedicationAdministration.basedOn and MedicationDispense.basedOn rows to the then-authoritative spreadsheets with cardinality 0..* and Reference(CarePlan), and adjusted MedicationUsage/MedicationStatement lineage text around derivedFrom rather than adding a MedicationStatement basedOn row. The January 2021 R5 source rework commit 33b409a4b6d544598262f2f074ebb4b6dc466157 carried those basedOn elements into the current StructureDefinition XML source.

Additional context:
MedicationAdministration, MedicationDispense, and MedicationStatement are active resources in source/fhir.ini. The current MedicationAdministration and MedicationDispense StructureDefinitions both contain basedOn as 0..* Reference(CarePlan). MedicationStatement currently has no basedOn element and instead has derivedFrom guidance for links to MedicationRequest, MedicationDispense, MedicationAdministration, and other supporting information; that is consistent with the FHIR-24666 modified resolution, which did not require adding MedicationStatement.basedOn. Later related work matters but does not change this seed decision: FHIR-27019/commit 3186dbfc7568af9b5f4420775f2e489c69310ec5 corrected the MedicationAdministration.basedOn wording, while FHIR-55888 is a later Resolved - change required R6 issue to restore MedicationStatement.basedOn and should be applied or audited separately in a scope that includes that status.

AutoFHIR reconciliation:
Made no source change. The current source already contains the two CarePlan basedOn elements required by the published FHIR-24666 resolution, and adding MedicationStatement.basedOn under this seed would over-apply the issue and duplicate the separate later FHIR-55888 decision path.

Recommendation:
Keep this audit commit as-is for FHIR-24666. Handle MedicationStatement.basedOn only through FHIR-55888 or another explicit Pharmacy work item/run that includes Resolved - change required issues, because that later non-compatible R6 correction has its own approved scope and wording.
