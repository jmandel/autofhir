FHIR-2881: Audit NullFlavor reconciliation

Issue request:
FHIR-2881 was Published with a Persuasive with Modification resolution for DSTU1. It asked that v3-specific terminology such as nullFlavor not appear in the core specification except when discussing v3, CDA, RIM, or RMIM mappings, and specifically asked for nullFlavor/null flavor wording to be made non-v3-specific where it appeared in resource descriptions.

Initial application:
The issue was applied in git-svn revision 3030, now commit ac1ed867441c5d426787214ad07a167716e3e61b, with the subject "task 2881: remove narrative references to nullFlavor". That commit changed an Observation profile comment from "data null flavor" to "data absent reason" and removed "nullflavor" from Person.deceased[x] spreadsheet rationale. The original application therefore addressed the resource-description narrative instances found at the time.

Additional context:
Current source still contains NullFlavor/null flavor strings, but they are not the stale resource-description wording FHIR-2881 targeted. They fall into current mapping or interoperability contexts, such as RIM mapping values in Observation and v3 comparison narrative; current ISO 21090/nullFlavor extension guidance that links to the Extension Pack; C-CDA/v3 example material; terminology value-set inclusions; and later applied decisions such as FHIR-31385 and FHIR-47558 that deliberately discuss missing primitive values or exceptional Quantity values. The Extension Pack still defines StructureDefinition/iso21090-nullFlavor as an active FHIR-I extension and explicitly cautions that it is tied to v3.

AutoFHIR reconciliation:
This is an empty no-change audit commit. A targeted current-source search found no active element short/definition/comment/requirements/description fields that still use NullFlavor/null flavor as ordinary resource-description prose, and the remaining occurrences are either within the exception categories, moved/current extension references, examples/tests, or later work-group-approved guidance.

Recommendation:
Keep this audit commit as-is. If the work group wants to further discourage the iso21090-nullFlavor extension or prefer Data Absent Reason more strongly in current guidance, that should be handled as a new policy issue, likely coordinated with the Extension Pack, rather than as a belated FHIR-2881 source correction.
