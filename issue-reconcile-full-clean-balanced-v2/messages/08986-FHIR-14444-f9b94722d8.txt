FHIR-14444: Audit CapabilityStatement normative status

Issue request:
FHIR-14444 was a Published/Persuasive STU3 FHIR-I change request questioning whether all of CapabilityStatement was ready to be normative. The accepted resolution made selected CapabilityStatement.rest.resource details trial-use, added mixed normative/trial-use implementation guidance, and documented a parameter to indicate the kind of response returned by /metadata.

Initial application:
The issue was applied in migrated svn revision 14469, now git commit 81544e1ec1a3d0e678fc0266a0f1510d1d9a44a1. That commit added the /metadata mode parameter to source/http.html, added a Mixed Normative Content note to the CapabilityStatement introduction, and marked the listed rest.resource elements trial-use in the then-authoritative spreadsheet source. The 2021 source migration carried those element-level standards-status markers into structuredefinition-CapabilityStatement.xml.

Additional context:
CapabilityStatement is active in the current build via source/fhir.ini and is now a normative resource with first normative version 4.0.0. The /metadata mode parameter remains in the active RESTful API page, including full, normative, and terminology modes. Later R6 normative-ballot cleanup intentionally removed CapabilityStatement mixed trial-use notes and broad element-level trial-use markers: 5c20769cc74459a8c1057d2747418dc4340f4244 removed the markers from the target elements, and 7466cfc63cd0b162497a42c80a67480eed86c75a removed the Mixed Normative Content note. This matches later governance context: FMG minutes say trial-use elements in normative R6 resources need a policy and FMG approval, and FHIR-54783 deferred a future mechanism for STU elements in normative artifacts rather than requiring an R6 core change.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding the FHIR-14444 trial-use markers or mixed-content note would undo later R6 normative-ballot source history and conflict with the current policy path for STU elements inside normative resources. The part of FHIR-14444 that still matters operationally, the /metadata mode parameter, remains present in current build-scoped source.

Recommendation:
Keep this audit commit as-is. Do not reintroduce the broad FHIR-14444 mixed trial-use labels in current core unless FMG/FHIR-I makes a new explicit R6+ decision for STU elements inside normative resources; future work should follow FHIR-54783 or successor policy work.
