FHIR-17462: Audit marital status CodeSystem removal

Issue request:
FHIR-17462 was a Published/Persuasive Patient Administration change request to remove the FHIR-defined Marital Status CodeSystem and its generated page because the missing concept that had justified a one-code FHIR CodeSystem was handled in the v3 marital status terminology.

Initial application:
No current git commit was found that names FHIR-17462 directly. The same source change appears to have been applied by git commit 6fc4d3572997f7944371158e8a12dd5f511e1dfc, which deleted source/terminologies/codesystem-marital-status.xml with the message "Tracker 16319 remove codesystem-marital-status as it is not used." FHIR-17462's Jira comments also record that Drew Torres removed codesystem-marital-status and that the v3 code system included the needed unmarried concept.

Additional context:
FHIR-16319 is the tightly related Published issue that explicitly requested removing the confusing one-code CodeSystem, and FHIR-16229 is a duplicate describing the same problem. The current build-scope inputs keep Patient and Person active in source/fhir.ini, bind their maritalStatus elements to http://hl7.org/fhir/ValueSet/marital-status, and define that ValueSet from the THO v3 MaritalStatus CodeSystem plus NullFlavor UNK. Zulip PA discussion around FHIR-17462 confirms the intended split: remove the FHIR CodeSystem page, while the ValueSet page continues to use v3 terminology. PA minutes in 2019 record later v3 marital status harmonization, not a need to restore a FHIR-owned CodeSystem.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current authoritative source has no source/terminologies/codesystem-marital-status.xml file, no active source/fhir.ini CodeSystem entry for marital-status, and no current source reference to the old http://hl7.org/fhir/marital-status CodeSystem URL. The remaining source/terminologies/valueset-marital-status.xml is still needed for active Patient and Person bindings and already composes from external v3 terminology.

Recommendation:
Keep this no-change audit commit as-is. No core FHIR source follow-up is needed for FHIR-17462 unless a future terminology decision changes the maintained THO/v3 marital status content or the Patient/Person maritalStatus binding itself.
