FHIR-5170: Audit StructureDefinition profile split

Issue request:
FHIR-5170 was a Published/Persuasive with Modification DSTU1 ballot comment asking the specification to distinguish top-level/core profile definitions from profiles derived from another profile or resource. The ballot text objected that core resource profile differentials duplicated snapshots and suggested that the old profile section clarify no-base top-level definitions versus base-derived profiles. The recorded resolution was pre-applied: clarified as part of the rework of Structure Definition, with a 2015-03-09 MnM/FHIR block vote.

Initial application:
No git commit explicitly mentions FHIR-5170. The Jira comments say the clarification was applied through the StructureDefinition rework, and the relevant history matches that: StructureDefinition was added as a candidate in February 2015, Profile and ExtensionDefinition were merged into StructureDefinition on 2015-03-01, and remaining Profile terminology in StructureDefinition element definitions was cleaned up on 2015-03-09. Those changes replaced the old Profile model that the ballot comment targeted.

Additional context:
StructureDefinition is an active current-build resource in source/fhir.ini. The current resource definition has baseDefinition and derivation elements, differentiates specialization from constraint, and separately defines differential and snapshot. The current narrative also gives examples for base resource definitions, constrained data types, defined extensions, constrained extensions, logical models, and resource definitions, then points constrained structures to the Profiling rules. The Profiling page separately explains sparse differentials and snapshots.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source already conveys the distinction requested by FHIR-5170: base StructureDefinitions and specializations are distinct from constraint profiles, baseDefinition carries the derivation relationship, and a differential is explicitly relative to its base while a snapshot is the fully calculated operational form.

Recommendation:
Keep this audit commit as-is. Further editing would restate existing guidance and risk drift across StructureDefinition and Profiling pages. FHIR-3873 contains the same ballot text in a comment but resolves a separate element-type tooling question, so it was treated as related background rather than decided here.
