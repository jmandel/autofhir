FHIR-20605: Clarify MedicationRequest intent granularity

Issue request:
FHIR-20605 was Published/Persuasive for the Pharmacy work group and asked for MedicationRequest.intent to highlight that intent is immutable: a proposal instance should not be changed into a plan or order; instead a new instance basedOn the prior instance should be created. Its approved wording also included the Request.intent granularity exception for order/filler-order refinements.

Initial application:
Jira records a6310682 as the CI-build application commit, via the 8c0d5b260d Pharmacy changes merge. That change set touched MedicationRequest source but did not add the requested MedicationRequest.intent comment. The current immutable sentence and "(immutable)" short text were later added by FHIR-50000 in cb9d506ccc, leaving the older approved granularity exception absent from the local element comment.

Additional context:
FHIR-15686 established the Request pattern immutability rule, and current source/request/request-spreadsheet.xml still carries the same granularity exception. FHIR-20603 spawned per-resource trackers including FHIR-20605. Later Pharmacy decisions FHIR-50000 and FHIR-48887 confirm that MedicationRequest.intent should be immutable and that broader workflow/request-pattern guidance remains relevant; they do not reject the approved order/filler-order granularity exception.

AutoFHIR reconciliation:
Updated the active MedicationRequest StructureDefinition source to include the approved granularity exception in the MedicationRequest.intent comment. This is a source-changing fix because source/fhir.ini lists medicationrequest as an active resource, and a local immutable-only comment can otherwise be read as prohibiting the order/filler-order refinement that the Request pattern allows.

Recommendation:
Keep this commit as-is. It completes the FHIR-20605 resource-local wording while preserving FHIR-50000's later immutable short text and aligning MedicationRequest with the current Request pattern.
