FHIR-27785: Audit Evidence Statistic application

Issue request:
FHIR-27785 was a Published/Persuasive R5 CDS change request to rename Evidence certainty code system/binding names away from Statistic-prefixed names, add very-serious-concern and replace critical-concern with extremely-serious-concern for certainty subcomponent ratings, add Statistic.modelCharacteristic with statistic model code/method terminology and value choices, and replace Statistic.attributeEstimate.estimateQualifier with a nested attributeEstimate structure plus clearer attributeEstimate descriptions.

Initial application:
The issue was initially applied in the old spreadsheet-based source. Commit 270d44c2227e0ae056a3140c5b384899f73c557f added most of the Statistic datatype changes, including modelCharacteristic rows, statistic-model-code/statistic-model-method sheets, and nested attributeEstimate rows, while noting the nested datatype build issue was not fully resolved. Commit 7004774c8a98895e9b7c5fbae10eecd754856219 then applied the Evidence certainty renames and rating code changes in source/evidence/evidence-spreadsheet.xml, including EvidenceCertaintyRating, CertaintySubcomponentType/Rating, very-serious-concern, and extremely-serious-concern.

Additional context:
The current build no longer has a standalone Statistic datatype: FHIR-31866 removed Statistic as a datatype and moved its elements into the active Evidence resource. Later final decisions intentionally changed details from the literal 2020 request: FHIR-29639 made statistic model code required and removed the Boolean/method split from the value choice; FHIR-41379 later re-expanded current Evidence.statistic.modelCharacteristic.value[x] to Quantity, Range, and CodeableConcept; FHIR-28920 streamlined Evidence.certainty into a recursive certainty backbone; and FHIR-39632 moved duplicate Evidence terminology definitions out of base FHIR to THO. Current THO terminology contains the requested certainty-rating replacement codes and statistic model code family. The only current StatisticCertaintyRating text found in core source is in generated SVG diagrams, while the authoritative XML StructureDefinitions use EvidenceCertaintyRating.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active Evidence source already has the requested nested attributeEstimate structure, modelCharacteristic backbone, current modelCharacteristic value shape after later WG decisions, and EvidenceCertaintyType/EvidenceCertaintyRating bindings to terminology.hl7.org value sets. Editing the stale SVG labels alone would violate the generated-diagram guardrail and would not change authoritative conformance source.

Recommendation:
Keep this audit commit as-is. The current core source is correct after FHIR-27785 plus later Evidence and terminology decisions; any future concern about stale checked-in SVG diagram labels should be handled by regenerating diagrams or by a separate build-artifact policy decision, not by changing the authoritative Evidence XML for this issue.
