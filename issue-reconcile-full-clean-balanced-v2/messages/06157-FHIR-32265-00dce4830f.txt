FHIR-32265: Audit ServiceRequest order detail parameters

Issue request:
FHIR-32265 was an Applied/Persuasive with Modification R5 O&O request to support structured storage of procedure or device parameters in ServiceRequest. The accepted shape made ServiceRequest.orderDetail a 0..* BackboneElement with an optional parameterFocus and 1..* parameter entries, each with required code and value[x]. The later WG motion also requested an implementer note warning that the modeling remains subject to feedback because requiring a focus for every detail or repeating focus per code/value pair both have drawbacks.

Initial application:
The change was applied in source history by FHIR-32265 commits. f3d976857e converted ServiceRequest.orderDetail from CodeableConcept to a backbone with parameterFocus and parameter/code/value children; 6c47335c14 corrected the value[x] choice type serialization; a4b2e7aafc corrected orderDetail.parameter to 1..*; and a3d9d73c01 added the requested implementer note after the Jira comments observed it had missed the R5 publication.

Additional context:
FHIR-31584 is the same change family and supplied the earlier Published request for code/value order details. The 2023-02-16 O&O minutes record the motion for the implementer note, and the 2023-03-06 HCP minutes record that the application needed correction. Later R6 work, especially FHIR-54847, refined parameterFocus[x] definitions and binding behavior, but that issue is only Resolved - change required in this run scope and does not require changing the seed audit result.

AutoFHIR reconciliation:
No source change was made. The active fhir.ini resource list includes servicerequest=ServiceRequest, and the current ServiceRequest source has orderDetail as a BackboneElement, parameterFocus[x] as 0..1, parameter as 1..*, and parameter.code and parameter.value[x] as 1..1. The ServiceRequest introduction also contains the requested Note to Implementers with the exact modeling-feedback warning.
