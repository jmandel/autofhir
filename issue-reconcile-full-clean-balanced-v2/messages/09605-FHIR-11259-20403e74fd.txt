FHIR-11259: Clarify versioned meta wording

Issue request:
FHIR-11259 was Published/Persuasive with Modification for the DSTU2 overview wording that said meta.versionId changes whenever resource contents change. The accepted resolution clarified that this is true only when a server supports versioning, and asked the overview developer page and HTTP page to be consistent with the three CapabilityStatement.rest.resource.versioning levels.

Initial application:
The issue was initially applied by git commit 02305b03c50a337f8643c05fbcd26b0cd8235c78, imported from svn revision 10333, which added a Managing Versions section to source/overview-dev.html and the three versioning levels to source/http.html. That application left the original overview implementer note saying meta.versionId changes on every resource-content change, and later QA wrapping preserved the HTTP bullets as meta.version rather than the actual meta.versionId element.

Additional context:
Current source/http.html already says servers that do not support versioning must not return Resource.meta.versionId, and CapabilityStatement.rest.resource.versioning defines non-no-version values as requiring correct tracking and population of the versionId meta-property. FHIR-34193 later clarified only the versioned-update wording and is already represented on the combined branch, so this commit does not decide it. source/fhir.ini keeps Resource in the active infrastructure/resource build, so source/resource/resource-notes.xml is in scope; source/http.html and source/overview-dev.html are active top-level narrative sources.

AutoFHIR reconciliation:
This commit updates source/http.html and source/overview-dev.html to name meta.versionId rather than the nonexistent meta.version field in the three-level versioning explanation. It also caveats the overview and Resource metadata descriptions so meta.versionId changes are described as applying when the element is present/versioning is supported, preserving the intended rule while avoiding the old implication that all servers must return a version id.

Recommendation:
Keep this source-changing commit. It completes the FHIR-11259 clarification in the current build without changing the later FHIR-34193 versioned-update decision or adding broader versioning policy changes.
