FHIR-12391: Audit Medication.code userSelected guidance

Issue request:
FHIR-12391 was a Published Pharmacy change request for DSTU2 asking whether Medication.code needed a separate definitive/source Coding distinct from descriptive translations. The final Not Persuasive with Modification resolution did not add an element; it required the Medication.code comment to explicitly say that the selected code uses coding.userSelected=true and to point to the Coding datatype guidance.

Initial application:

That wording was later carried into the generated/current source/medication/structuredefinition-Medication.xml source after the build-source refactor.

Additional context:
Medication is active in the current build through source/fhir.ini, and the current Medication.code comment already contains the resolved coding.userSelected guidance. The copied Coding datatype narrative still defines userSelected as the preferred choice for translations. Later same-element work for FHIR-45876 changed Medication.code short/definition text to clarify medication names in code.text, but it left this userSelected comment intact and is already represented separately on the combined branch. Searches found no direct Zulip or Confluence discussion for FHIR-12391 and no conflicting later Pharmacy decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active Medication.code ElementDefinition already tells implementers to use coding.userSelected=true for the code selected by the user and preserves the translation/granularity guidance, so adding a separate machine-generated definitive Coding element would contradict the published resolution rather than complete it.

Recommendation:
Keep this no-change audit commit as-is. No FHIR core source follow-up is needed for FHIR-12391 unless Pharmacy reopens the broader question of representing non-user-selected source/definitive medication codes.
