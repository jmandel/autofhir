FHIR-27029: Audit Expression.language cardinality

Issue request:
FHIR-27029 was a Published/Persuasive FHIR-core R4 change request, applied for R5, asking that Expression.language have minimum cardinality 0 so authoring-time Measure expressions can be text-only before executable logic or references are available. The approved resolution also required explanatory requirements text saying the optional cardinality allows text-only authoring, but executable content must specify the expression element.

Initial application:
The issue appears to have been applied by PR HL7/fhir#2358, merged on 2022-09-04. Commit 272e3fb71ecb0d87630a48101b00015f0f18b038 explicitly cites J#27029 and changes source/datatypes/expression.xml by relaxing Expression.language from 1..1 to 0..1 and adding the requested requirements sentence.

Additional context:
Expression remains in current build scope through source/fhir.ini as an active metadata datatype, metadatatypes page entry, normative type, and abbreviation. The current combined branch also already contains FHIR-31082, a later Expression-language decision that preserves the FHIR-27029 authoring use case while requiring language when executable expression or reference content is present. FHIR-I minutes from 2020-11-02 record the FHIR-27029 persuasive vote, and the FHIR-27029-specific Zulip/Confluence searches found no conflicting community evidence.
