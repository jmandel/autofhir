FHIR-53367: Audit DeviceMetric modifier reasons

Issue request:
FHIR-53367 was Applied with resolution Persuasive with Modification for R6. The issue asked that DeviceMetric modifier elements explain why they are modifiers; the accepted decision was to add a reason for DeviceMetric.status and to stop treating DeviceMetric.operationalStatus as a modifier.

Initial application:
The Jira comments point to HL7/fhir#3945 and merge commit 73cffd7d54e65524a6327ec3211e4a7de7c47112. The implementation commit 533f3383c9746718a840e9c0cc84c987d0cf30be added the DeviceMetric.status isModifierReason and changed DeviceMetric.operationalStatus isModifier from true to false in source/devicemetric/structuredefinition-DeviceMetric.xml.

Additional context:
source/fhir.ini lists devicemetric as an active DeviceMetric resource owned by the Devices work group, so the inspected StructureDefinition source is in current build scope. Devices WG minutes for 2025-11-05 record the same 7-0-0 decision to add a status modifier reason copied from Observation.status and remove the operationalStatus modifier flag. The same PR also addressed FHIR-53309 mapping updates, but that mapping issue is a separate change family member and is not decided by this audit.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current DeviceMetric source already has DeviceMetric.status marked as a modifier with an isModifierReason explaining the entered-in-error and inactive statuses, and DeviceMetric.operationalStatus is explicitly not a modifier.

Recommendation:
Keep this no-change audit commit as-is. No further FHIR core source work is needed for FHIR-53367 unless the work group later changes DeviceMetric status semantics.
