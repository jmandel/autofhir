FHIR-33432: Audit ElementDefinition path choice-name clarification

Issue request:
FHIR-33432 was a Published FHIR-core change request, resolved Persuasive with Modification for R5, asking that the ElementDefinition.path character rules clarify how polymorphic choice elements can use [x] even though brackets are otherwise excluded from element names.

Initial application:
The issue was applied by b1329db957738e422efb1a88e83984e1f00528d7, which inserted a paragraph under source/elementdefinition.html#path explaining that polymorphic element paths end in [x] and that [x] is not part of the official element name. A later FHIR-25431 editorial pass changed "data type" to "datatype" without altering the rule.

Additional context:
The Zulip origin thread and the January 2022 FHIR-I minutes both confirm the intended clarification: brackets cannot be part of an element name, but [x] can appear in polymorphic paths such as value[x] and ElementDefinition.path. The current source/fhir.ini lists ElementDefinition as an active datatype and normative content, so source/elementdefinition.html is in current build scope. Later same-page issues FHIR-39180 and FHIR-39182 corrected examples for type-choice ids/elements and do not conflict with the FHIR-33432 paragraph.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already conveys the approved rule at source/elementdefinition.html:95-96: polymorphic paths SHALL end with [x], and [x] is not part of the official element name.

Recommendation:
