FHIR-7279: Audit delete ETag guidance

Issue request:
FHIR-7279 was Published with a Persuasive with Modification resolution for the FHIR-core HTTP page. It asked how version contention is handled when one client deletes a resource and another later tries to update the same previously current version, and the accepted resolution was to add notes to the read and delete interactions about returning an ETag for a deleted resource.

Initial application:
The issue was applied by git commit e7a0b55a1e6aae358c6571e85a8a9b7f61fc8b21, whose subject references #7279 and whose patch added read and delete notes saying servers MAY include an ETag for deleted resources so clients can perform version contention management when bringing a deleted resource back to life. Later refactors preserved that guidance in source/http.html.

Additional context:
The current source/http.html page is the active RESTful API (HTTP) page linked from source/documentation.html. Its read interaction says a GET for a deleted resource can return 410 and MAY include an ETag on the error response, while its delete interaction says deleted resources can be brought back to life and servers MAY include an ETag on the delete response. Later Published HTTP-page issues support the current optional wording: FHIR-23996 softened deleted-resource 410 behavior for security/policy reasons, and FHIR-25038 clarified that ETag response headers are generally SHOULD/optional rather than mandatory. A 2023 Zulip implementers thread about finding the version id of a deleted resource confirmed response.etag as the way to carry the version in history/transaction contexts and did not contradict the current wording.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current source already contains the read/delete ETag notes requested by FHIR-7279, and strengthening them would conflict with later optionality and access-denied guidance.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-7279 unless the work group later decides to make deleted-resource ETags mandatory or to add a machine-testable conformance rule.
