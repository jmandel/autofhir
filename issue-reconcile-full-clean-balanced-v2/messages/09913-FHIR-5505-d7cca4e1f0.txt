FHIR-5505: Audit Device UDI repository wording

Issue request:
FHIR-5505 was a Published/Persuasive with Modification OO change request from the January 2015 DSTU1 ballot. It asked the Device UDI notes to stop presenting UDI as only an FDA/GUDID concept, to explain DI/PI components and jurisdictional repositories, and to require Device details to be consistent with the UDI string or the local repository rather than only GUDID.

Initial application:
Commit 85cad2a017a228c70b358dab887c56b5bfccb18e pre-applied Device ballot comments FHIR-5849, FHIR-5503, FHIR-5505, FHIR-5506, and part of FHIR-5504 before the 2015-03-26 OO block vote. For FHIR-5505 it changed the Device notes from GUDID-only wording to jurisdictional repository/local repository wording and separated the US GUDID explanation as an example.

Additional context:
Device is active in the current build through source/fhir.ini. The current Device notes have since evolved from the old DSTU1 Device.udi string to the current Device.udiCarrier model, but the relevant UDI section still says the DI may be stored in a jurisdictional repository, uses US GUDID only as an example, describes DI/PI/other elements, and ends with the approved local-repository consistency rule. FHIR-5454 was explicitly merged with FHIR-5505 and supports the same global-vs-US clarification. A later reconciliation for FHIR-5849 already removed a remaining misleading instance-or-type UDI sentence without changing the FHIR-5505 repository rule.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active Device source already preserves the FHIR-5505 clarification, and a repository-wide source search did not find the old "registered in the GUDID" consistency rule needing another current-source fix.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-5505 unless a separate worker or human elects to audit merged ballot comment FHIR-5454 independently.
