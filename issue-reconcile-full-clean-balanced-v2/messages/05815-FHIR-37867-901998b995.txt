FHIR-37867: Audit CodeableReference search guidance

Issue request:
FHIR-37867 was a Published/Persuasive with Modification FHIR-I issue asking the search summary tables and related search handling to account for CodeableReference after R4B introduced the datatype and ClinicalUseDefinition search parameters used it. The final resolution was not to index a CodeableReference as a whole, but to ensure search paths resolve to either CodeableReference.concept or CodeableReference.reference and to flag paths ending at CodeableReference.

Initial application:
The issue was applied by commit 211e70eb7d9e1f2114659e1724230b660e5f5ce8, which added a CodeableReference row to source/search.html in the cross-map between search parameter types and datatypes. The row uses the existing xcmchk not-used-in-search pattern and states that searches either refer to .concept or .reference.

Additional context:
CodeableReference remains an active datatype and ClinicalUseDefinition remains an active resource in source/fhir.ini. Current ClinicalUseDefinition search parameters use .concept for token searches and .reference for reference searches, and a repository-wide search of checked-in search-parameter bundles found no SearchParameter path or expression ending at CodeableReference. Zulip discussion before the Jira resolution likewise says a CodeableReference is searched with separate concept and/or reference parameters rather than one parameter for the whole datatype. No FHIR-37867-specific Zulip or Confluence evidence was found that conflicts with the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current search summary table already contains the CodeableReference note required by the final resolution, and the current search-parameter sources follow that rule.

Recommendation:
Keep this audit commit as-is. No core FHIR source follow-up is needed for FHIR-37867 unless future search-parameter generation introduces a path ending at CodeableReference, in which case the search table xcmchk guidance should fail the build or be investigated with the publisher/Kindling tooling.
