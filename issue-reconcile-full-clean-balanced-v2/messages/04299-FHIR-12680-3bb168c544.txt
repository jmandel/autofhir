Issue request:
FHIR-12680 was a Published/Persuasive Patient Care QA issue for DSTU2 FamilyMemberHistory. It reported that the resource elements were out of order: identifier, patient, date, status appeared where the correct order was identifier, status, patient, date.

Initial application:
The issue appears to have been applied by git commit 047a0c6ab1c00e633177a675d7146fc48793bf00 on 2017-01-24. That commit explicitly names #12680, moved FamilyMemberHistory.status ahead of patient and date in the then-current spreadsheet source, and adjusted FamilyMemberHistory examples so status appeared before patient/date. The old spreadsheet helper was removed in 2018, and the spreadsheet XML source was replaced by the current StructureDefinition XML source in the 2021 build-source rework.

Additional context:
FamilyMemberHistory is still an active current-build resource in source/fhir.ini, but the authoritative current source is source/familymemberhistory/structuredefinition-FamilyMemberHistory.xml. Later model changes added and reordered other elements such as dataAbsentReason, recorder, asserter, and participant, so the exact DSTU2 list is no longer the complete current top-level order. The current StructureDefinition preserves the issue's relevant relative order: identifier, status, patient, date. The same historical commit also handled FHIR-12681 and FHIR-12682 for different resources; both already have separate audit commits on the combined branch and are not decided again here.
