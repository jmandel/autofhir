FHIR-36164: Audit ImagingSelection bodySite application

Issue request:
FHIR-36164 was a Published/Persuasive R5 Imaging Integration change request asking that ImagingSelection.bodySite become a CodeableReference able to reference BodyStructure while still allowing a coded body-site value.

Initial application:
The issue was applied by git commit 1891df8e49 ("imaging CR FHIR-36165, FHIR-36164, FHIR-36120"), which changed source/imagingselection/structuredefinition-ImagingSelection.xml from Coding to CodeableReference with targetProfile BodyStructure and adjusted the existing body-site token search parameter to use ImagingSelection.bodySite.concept. The Jira comment also recorded that the token search parameter was intentionally kept.

Additional context:
ImagingSelection is an active current-build resource in source/fhir.ini. Later final bodySite-family decisions explain the current source differences from the original Jira comment XML: FHIR-40276 added a body-structure reference search parameter; FHIR-45274 changed bodySite cardinality to 0..*, added AnatomicRegionSequence, and expanded the DICOM mapping; FHIR-36787 rejected removing bodySite; and FHIR-50859 later considered BodyStructure-only but ultimately kept CodeableReference with BodyStructure guidance and is already represented on the combined branch.

AutoFHIR reconciliation:
No source change was made. The current authoritative source already defines ImagingSelection.bodySite as 0..* CodeableReference targeting BodyStructure, retains the example BodySite binding for coded values, exposes separate body-site token and body-structure reference search parameters, and includes Body Site and Laterality guidance for coded and referenced BodyStructure representations.

Recommendation:
Keep this audit commit as-is. The current specification satisfies FHIR-36164 after later accepted refinements, so changing the source back toward the original single-cardinality Jira snippet or removing the coded/search surfaces would undo subsequent work-group decisions.
