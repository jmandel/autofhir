FHIR-19595: Audit version-specific code bindings

Issue request:
FHIR-19595 was a Published/Persuasive FHIR-I change request for STU3/R4 generation asking that bindings for elements of type code be version-specific in the final generated packages, with the canonical ValueSet reference including the FHIR version. The resolution approved that code bindings should be marked as version-specific/static bindings and left the broader dynamic-binding cleanup to the editor.

Initial application:
The Jira comment points to Git commit 7dad348872e99ca452ec098076d3d7bef3117d03, "GF#19595 - make bindings version specific for required code." That commit changed the then-current ProfileGenerator binding generation to append "|" plus the FHIR version to required binding ValueSet references and is an ancestor of the current worker and combined branches.

Additional context:
Current raw source StructureDefinition inputs still commonly hold unversioned ValueSet canonicals, but FHIR-19595 targeted final generation rather than those raw inputs. The current terminology guidance explains that required bindings on code are static/versioned, and published/current generated StructureDefinition JSON for representative code elements includes versioned ValueSet references such as administrative-gender|4.0.1, |5.0.0, and |6.0.0-ballot4. A 2018 FMG Zulip R4-preparation thread also lists "required/code bindings to be version specific" as part of the R4 completion work. The later FHIR-38967 terminology examples work is already represented on the combined branch and only provides background documentation context.

AutoFHIR reconciliation:
Made no source change. The historical generator change was applied, current generated outputs demonstrate the requested version-specific canonicals for code bindings, and editing unversioned raw source StructureDefinition inputs would not be the correct fix for this final-generation issue.

Recommendation:
Keep this audit commit as-is. If a future package build loses the version suffix on required code binding ValueSet canonicals, fix the generation/publisher path rather than bulk-editing raw source inputs.
