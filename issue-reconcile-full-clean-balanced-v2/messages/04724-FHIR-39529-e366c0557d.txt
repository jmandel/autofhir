FHIR-39529: Audit primitive integer min values

Issue request:
FHIR-39529 was a Published/Persuasive FHIR-core datatypes change request for R5 asking that the unsignedInt and positiveInt StructureDefinitions override the inherited integer.value minimum, with unsignedInt.value constrained to a minimum of 0 and positiveInt.value constrained to a minimum of 1. The issue also noted a tooling concern that some snapshot generators inherited integer.value's -2147483648 minimum unless the derived primitive profiles carried their own minValue.

Initial application:
No explicit FHIR-39529-tagged commit was found in this checkout. The current R5 definitions available in this repository, and the published R5/current build conformance JSON, already include the requested differential constraints as typed ElementDefinition.minValue[x] values: minValueUnsignedInt=0 for unsignedInt.value and minValuePositiveInt=1 for positiveInt.value.

Additional context:
The active primitive datatype source defines unsignedInt and positiveInt as integer-derived primitive types and their regular expressions already exclude the invalid ranges. The generated snapshots still do not repeat the minValue[x] entries, which is consistent with the Jira note about Java snapshot behavior; the important source/published differential now carries the constraining minValue[x] entries so downstream snapshot generation should not inherit integer.value's -2147483648 minimum.
