FHIR-7452: Audit duplicate extension registry guidance

Issue request:
FHIR-7452 was a Published/Not Persuasive with Modification DSTU1 FHIR-core issue for the Extensibility area. It asked how to avoid duplicate extensions because the 2015May core registered-extension list was not easily searchable and appeared to contain obvious duplicate location extensions. The accepted resolution was that an extension registry had been added; the resolution also noted that the apparent location duplicate was not clearly an actual duplicate and might have been revised by other tasks.

Initial application:
No explicit FHIR-7452-tagged source commit was found. The Jira comment records that the issue was already applied by the extension registry. Nearby history shows the registry response: source/defining-extensions.html was introduced in 2015 with guidance to reuse shared registries and a publishing/registry section, the source/extensibility-registry.html page existed and was actively maintained, and FHIR-7542's registry URL follow-up was applied in svn revision 6066. FHIR-7542 is already represented on the combined branch, so this commit does not duplicate that decision.

Additional context:
The current core build still contains the relevant guidance: source/defining-extensions.html is listed in publish.ini, tells authors to attempt reuse of extensions from shared registries before defining new ones, links to the FHIR extension registry through [%extensions-location%]extension-registry.html, and points to the HL7/FHIR registry for discoverability and reuse. The old core source/extensibility-registry.html page is intentionally no longer active; commit 4118eb9ddb6e moved extension registry content to the FHIR Extension Pack. The Extension Pack checkout now has extension-registry.html as an active ImplementationGuide page and includes the generated extension-list table. Later community evidence discusses overlapping or duplicate extensions in the Extension Pack, but it does not reverse the FHIR-7452 conclusion or identify a current core-source defect.

This empty audit commit intentionally makes no source change.
