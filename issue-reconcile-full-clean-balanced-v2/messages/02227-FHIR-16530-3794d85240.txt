FHIR-16530: Audit authenticator protection guidance

Issue request:
FHIR-16530 was a Published/Persuasive with Modification FHIR-core security change request asking the Authentication section of the security guidance to require protection of authenticator mechanisms and risk-based selection of credential/authenticator strength.

Initial application:
The request appears to have been applied in git commit 95ee245e72e4bd1ac09824738ae7b5f7519239ef, which explicitly listed GF#16530 and added the authenticator-protection sentence to source/security.html. Later security narrative edits corrected the original "are shall" grammar and normalized the conformance verb to "SHALL".

Additional context:
source/security.html is an active core security narrative page referenced from source/hierarchy.xml under the Security and Privacy module. Later issue FHIR-53719 changed the adjacent scalable-security/FAST guidance from SHOULD to MAY and removed the tiered OAuth sentence, but preserved the authenticator-protection requirement. Jira searches found no later issue asking to remove or weaken the FHIR-16530 sentence, and Zulip/Confluence searches found no conflicting community record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Authentication section already says: "All systems SHALL protect authenticator mechanisms, and select the type of credential/strength of authenticator based on use-case and risk management."

Recommendation:
Keep this audit commit as-is. No follow-up source change is needed for FHIR-16530 unless the Security Work Group later decides to revisit the normative strength or wording of this authentication guidance.
