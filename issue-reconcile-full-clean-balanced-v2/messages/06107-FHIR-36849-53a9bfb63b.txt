FHIR-36849: Audit releaseDate extension ownership

Issue request:
FHIR-36849 is Published/Persuasive with Modification for R5. It asked for an optional on-hold period concept for requests or events and was resolved as a standard `releaseDate` extension indicating when a request or event with status `on-hold` or `suspended` should return to active, with guidance that the transition timing is system dependent and that the element should be cleared when the status returns to active.

Initial application:
The issue was applied in core history by eec3aa6e91730558ef84e4bbf4dc3d0e6d8f7735, which added a `releaseDate` row to `source/profiles/workflow-extensions-spreadsheet.xml`. Later core history in dd468d4f1799dd79819315b211588ef1cf4586e0 removed extension rows from the R5 core source as part of the extension migration; the current core workflow spreadsheet no longer contains `releaseDate`, while core retains the OID assignment in `source/oids.ini`.

Additional context:
The current authoritative definition is in the FHIR Extension Pack at `/home/jmandel/work/fhir-extensions/input/definitions/multiple/StructureDefinition-workflow-releaseDate.xml`. That file defines `http://hl7.org/fhir/StructureDefinition/workflow-releaseDate`, a `dateTime` extension, with request/event contexts and the Jira definition/comment through the system-dependent transition guidance. It does not include the final Jira sentence that the element should be cleared when the status returns to active. Confluence WGM minutes confirm the FHIR-I decision to create a standard extension for the holding period, and no directly relevant Zulip or additional Confluence FTS hits were found that change the interpretation.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. Reintroducing the extension row into core would duplicate the post-R5 Extension Pack ownership and conflict with the historical removal of extension definitions from core source. The remaining possible semantic gap, if judged necessary to fix, is in the Extension Pack definition rather than this FHIR core checkout.

Recommendation:
Keep this audit commit as the core reconciliation record. If Extension Pack work is in scope, add the missing clear-on-active guidance to `input/definitions/multiple/StructureDefinition-workflow-releaseDate.xml`; otherwise no core follow-up is needed.
