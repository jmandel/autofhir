FHIR-14396: Audit PlanDefinition apply wording

Issue request:
FHIR-14396 was a Published/Persuasive STU3 CDS change request saying that the verb "render" was not easy to understand in the Clinical Reasoning knowledge artifact representation page's PlanDefinition $apply discussion. The approved wording was to describe $apply as applying a PlanDefinition to a specific context and producing a CarePlan from data available in that context.

Initial application:
The issue was applied in SVN 13332 / git commit d73633fa577ac98c9cf467f762361756cb8b9b1a, which changed the Clinical Reasoning narrative from "render a plan definition" to "apply a plan definition" and updated the ActivityDefinition and PlanDefinition $apply spreadsheet rows. No separate current-source omission was found for the seed wording.

Additional context:
The current build-scope resources include ActivityDefinition, PlanDefinition, and RequestOrchestration in source/fhir.ini. The current Clinical Reasoning page still says the $apply operation is used to apply a plan definition. The current PlanDefinition operation description also uses "applies" rather than "render", but later PlanDefinition $apply output decisions superseded the STU3 CarePlan-only result wording: FHIR-25056 added RequestGroup as an output option, FHIR-33169 changed the operation to return Bundles, FHIR-46313 relaxed the result to Bundles of request resources including CarePlan, RequestOrchestration, and individual requests, and FHIR-51557 clarified the multi-cardinality return parameter.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Reintroducing the exact STU3 resolution sentence would undo later applied PlanDefinition $apply semantics, while the original clarity request is already satisfied in current build-scope source.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-14396 unless the CDS work group separately wants to revisit the broader current PlanDefinition $apply result wording under a new tracker.
