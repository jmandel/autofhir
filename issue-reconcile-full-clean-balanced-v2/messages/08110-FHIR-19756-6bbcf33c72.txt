FHIR-19756: Audit root cardinality clarification

Issue request:
FHIR-19756 was Published as Persuasive for R5. It asked FHIR-I to clarify that root cardinality is not meaningless: the ElementDefinition interpretation table should drop the old first-repetition min/max "(irrelevant)" note and add a note explaining that cardinality on a type constrains references to that type, especially Extension profiles.

Initial application:
The issue was explicitly applied by git commit 2fb5b028a63c2d5932dbaf549cd777bc0ffb05ed, which changed source/elementdefinition.html to replace "optional (irrelevant)" with "optional§" in the min/max row for type-definition root elements and added the requested § note below the table. Current source still contains those semantics.

Additional context:
source/fhir.ini lists elementdefinition=elementdefinition, so source/elementdefinition.html is active build input. Later ElementDefinition page commits adjusted nearby wording and punctuation but preserved the § root-cardinality rule. The linked Zulip thread records the same rationale: Extension definitions, and potentially other type profiles, can constrain how their type is referenced. Jira has no normalized related links for this issue, Confluence has no direct FHIR-19756 references, and broader community searches found no conflicting later decision.
