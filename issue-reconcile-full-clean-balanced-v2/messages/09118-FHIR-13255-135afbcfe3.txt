FHIR-13255: Audit profile download links

Issue request:
FHIR-13255 was a Published/Persuasive STU3 FHIR-core request to add downloadable alternate-definition links to profile pages, using the vital signs panel profile as the example and asking for Master Definition XML/JSON and validation-format links.

Initial application:
The issue was applied in svn revision 12608, represented in git by 58ac284e01124f95b84e785a17f699499df849ad, which changed the profile page template from a generic "Other representations of profile" sentence to "Alternate definitions: Master Definition (XML, JSON), ...". Later repository refactoring moved that template from source/template-profile.html to tools/templates/template-profile.html without removing the FHIR-13255 link text.

Additional context:
The current build scope still includes Observation as an active resource in source/fhir.ini, and the Observation vital signs implementation guide source includes StructureDefinition/vitalspanel. Current tools/templates/template-profile.html still emits the requested alternate-definition links for generated profile pages, and the current CI build vitalspanel page renders links to vitalspanel.profile.xml.html, vitalspanel.profile.json.html, and vitalspanel.sch. Bounded Jira/community searches found no later Jira or Confluence decision reversing this application; Zulip search found only a tracker bot mention and later user guidance that the alternate-definition links are how to find structure definition downloads.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because the authoritative profile template and the generated current profile page already satisfy the applied issue.

Recommendation:
Keep this audit commit as-is. Revisit only if the work group wants a new, broader profile-page download policy beyond the links implemented for FHIR-13255; that would be a new requirement, not a missing application of this Published issue.
