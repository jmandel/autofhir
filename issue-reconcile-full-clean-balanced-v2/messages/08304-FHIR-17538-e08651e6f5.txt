FHIR-17538: Audit DeviceRequest requester compartment

Issue request:
FHIR-17538 was a Published/Persuasive STU3 technical correction against FHIR-core CompartmentDefinition. It reported that Patient CompartmentDefinition listed DeviceRequest.requester even though the then-current DeviceRequest-requester search parameter could not target Patient, making the Patient compartment link invalid.

Initial application:
The issue was applied in git commit 00abb9a0d4 (GF#17538 - fix compartment definitions), matching the Jira comment for svn revision 14559. That commit removed requester from the DeviceRequest row's Patient compartment entry in source/compartments.xml while leaving subject and performer.

Additional context:
DeviceRequest and CompartmentDefinition are active resources in source/fhir.ini, so source/devicerequest/structuredefinition-DeviceRequest.xml and source/compartments.xml are current build-scoped inputs. A later Applied/Persuasive-with-Modification issue, FHIR-26378, intentionally added Patient and RelatedPerson as allowed DeviceRequest.requester target profiles and updated the Patient and RelatedPerson compartment entries. That later issue is already represented on the combined branch by commit eff719a3643 and should not receive a duplicate commit here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Patient compartment entry for DeviceRequest includes requester, but DeviceRequest.requester now explicitly allows Patient as a target profile, so the incompatibility that FHIR-17538 fixed in STU3 no longer exists in the current specification.

Recommendation:
Keep this audit commit as-is. Do not remove requester from the current Patient compartment for DeviceRequest unless a future work-group decision reverses FHIR-26378's Patient requester target.
