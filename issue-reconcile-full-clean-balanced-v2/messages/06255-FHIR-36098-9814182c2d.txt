FHIR-36098: Audit messaging search URL mechanism

Issue request:
FHIR-36098 was Published/Persuasive with Modification for R5. It asked to replace the Search via Messaging mapping of search input parameters into typed Parameters because that approach lost REST search behavior such as decimals, prefixes, modifiers, URI version syntax, and joins. The approved replacement uses a Parameters instance with parameter name "url" and a valueString containing the REST search string to the right of the base URL, with MessageHeader events search-type or search-system.

Initial application:
Commit f3dfec64462aa8ec3a0d95db4cf9eff7ace9394e applied FHIR-36098 to source/messaging.html by adding the approved URL-string Parameters guidance and commenting out the older typed-parameter mapping table and example. Commit 4baa8f22bae6d8f787c024219b5842a6cc658bb5 later made only XML fragment quoting fixes in the same area. No later source commit was found that reverses the FHIR-36098 semantics.

Additional context:
source/messaging.html is in current build scope through source/navigation.xml, where Messaging is an Implementation section page. The current visible page says to use parameter name "url" with a valueString such as Patient?name=joe, identifies search-type/search-system events, and notes that limitations for messaging-only search are not currently defined. The old resourceType mapping remains only inside an HTML comment. Related FHIR-36116 was resolved Resolved - No Change/Not Persuasive because FHIR-36098 made the old resourceType text no longer relevant. The Zulip thread linked from FHIR-36098 confirms both issues came from the same review of Search in Messaging; the Confluence reference only records assignment before the later Jira vote.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current implementer-visible messaging guidance already preserves the approved FHIR-36098 behavior, and removing the hidden commented historical block would be editorial cleanup rather than a required current-spec correction.

Recommendation:
Keep this no-change audit commit as-is. Future editors may remove the commented-out old search example during ordinary page cleanup, but no FHIR-36098 source correction is needed now.
