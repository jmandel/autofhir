FHIR-19644: Audit AuditEvent generic scope wording

Issue request:
FHIR-19644 was a Published/Persuasive with Modification Security WG change request asking that AuditEvent no longer read as specific to security audit logs. The accepted resolution was to define it as "A record of an event relevant for purposes such as operations, privacy, security, maintenance, and performance analysis."

Initial application:
The issue appears to have been applied by John Moehrke's 2019-04-11 commit d417c5d674a4a6b7e4af8d9ef15b7d55d3b4d3e8, which replaced the security-audit-log-only introduction sentence in source/auditevent/auditevent-introduction.xml with the accepted broader wording. The 2021 build-source rework commit 33b409a4b6d544598262f2f074ebb4b6dc466157 then carried that same wording into source/auditevent/structuredefinition-AuditEvent.xml.

Additional context:
AuditEvent is active in source/fhir.ini, and the current built source has the broader wording in both the resource StructureDefinition description/definition and the Scope and Usage introduction. The Jira-linked Zulip thread confirms that implementers found the old wording too security-specific and that John Moehrke created GF#19644 to soften historic language that no longer represented current intent. No Confluence references or conflicting community records were found for FHIR-19644.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because the current authoritative AuditEvent source already conveys the accepted generic audit-event scope and no longer contains the quoted restrictive wording in active source.

Recommendation:
Keep this audit commit as-is. Future AuditEvent scope changes should be handled by new tracker items, but FHIR-19644 itself is already correctly represented in the current FHIR core source.
