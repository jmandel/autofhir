FHIR-51480: Audit vital signs value-set bindings

Issue request:
FHIR-51480 was an Applied/Persuasive OO change request for R6 asking that validation of vital signs profile categories rely on defined value sets rather than a validator-specific GitHub file. The recorded resolution says, "The value set is on the core profile."

Initial application:
No commit explicitly named FHIR-51480. The relevant prior application was already present before the Jira vote: git commit 0a17c0f40f added a preferred Observation.category binding to a then-new observation-vitalsign-category value set and added the observation-vitalsign-measurement value set/bindings used by the Vital Signs Base profile.

Additional context:
Later and related OO decisions changed how this family should be interpreted. FHIR-45617 and FHIR-50689 rejected moving vital-signs identification from Observation.code to Observation.category, and git commit 66a80b5fef removed the special observation-vitalsign-category value set and the category binding while keeping the Vital Signs Base profile's Observation.code binding to observation-vitalsign-measurement. FHIR-50452 and the 2025-10-10 OO minutes further confirm that the interoperability standard code no longer belongs in category. The base Observation.category element still has the general observation-category value set binding, and the Vital Signs Base profile fixes the required vital-signs category slice.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. On the latest combined branch, source/observation/structuredefinition-profile-vitalsigns.xml fixes Observation.category:VSCat to http://terminology.hl7.org/CodeSystem/observation-category#vital-signs and binds Observation.code to http://hl7.org/fhir/ValueSet/observation-vitalsign-measurement. The vital signs profile introduction also directs validator-style conformance triggering to the value sets bound on Observation.code. Reintroducing the deleted special category value set would contradict the later applied category-vs-code decisions.

Recommendation:
Keep this no-change audit as-is. Future work on validator trigger lists should use the value sets currently bound to Observation.code and Observation.component.code, not restore observation-vitalsign-category in core. Separate later metadata/text-summary cleanup such as FHIR-54960 should be handled under its own tracker.
