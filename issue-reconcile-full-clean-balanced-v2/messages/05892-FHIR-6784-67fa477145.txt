FHIR-6784: Audit Questionnaire answer ValueSet reuse

Issue request:
FHIR-6784 was a Published/Persuasive with Modification DSTU1 Patient Care change request asking whether Questionnaire answer lists, modeled as ValueSets, can exist independently of a single question. The accepted resolution said ValueSets can be reused by multiple Questionnaire questions and other artifacts, while ValueSets intrinsically tied to one Questionnaire can be sent as contained resources, and requested Questionnaire documentation explaining both behaviors.

Initial application:
The Jira comments record SVN #5941. The matching git-svn commit 26e8b597d5034f4372a848e5660a88268f4b664c added the Questionnaire notes section on permitted values for questions, including the statements that answer sets can be shared across questions and that a question-specific ValueSet can be included as a contained resource. The commit subject appears to have omitted or mistyped this tracker number, but its git-svn id and patch content match the Jira application note and requested resolution.

Additional context:
Questionnaire is still an active current-build resource in source/fhir.ini. The current Questionnaire notes preserve the FHIR-6784 guidance and have evolved to include both item.answerValueSet and item.answerOption, consistent with later Questionnaire work such as FHIR-8481. The current StructureDefinition defines Questionnaire.item.answerValueSet as a canonical reference to ValueSet and separately defines answerOption for inline answers. Targeted Zulip and Confluence searches found no FHIR-6784-specific or conflicting community record.

AutoFHIR reconciliation:
This audit makes no source change. The active source already tells implementers that answerValueSet refers to a ValueSet resource, that answer sets can be shared across questions, and that a Questionnaire-specific ValueSet can be contained and referenced by the relevant questions, with version-specific references available when the Questionnaire author needs control over value set changes.

Recommendation:
Keep this no-change audit commit as-is. No core FHIR source follow-up is needed for FHIR-6784; FHIR-8481 remains only background here because it concerns the separate later addition of inline answer choices rather than the independence and reuse of ValueSet answer lists.
