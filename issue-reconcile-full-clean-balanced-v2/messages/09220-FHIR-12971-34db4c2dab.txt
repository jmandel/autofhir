FHIR-12971: Audit Request reasonReference targets

Issue request:
FHIR-12971 was a Published/Persuasive FHIR-I DSTU2 request-pattern issue asking that ProcedureRequest.reasonReference support DiagnosticReport because MedicationRequest followed the ProcedureRequest/Request reasonReference pattern. The final resolution was to add DiagnosticReport and DocumentReference to the reasonReference choices.

Initial application:
The Jira comment records SVN#12374. The corresponding git-svn commit 5064224bd079b7f4ef4023d3ead9111b57bd8bff updated source/request/request-spreadsheet.xml so Request.reasonReference changed from Reference(Condition|Observation) to Reference(Condition|Observation|DiagnosticReport|DocumentReference). The current Request pattern keeps that result, now both as Request.reason CodeableReference(Condition|Observation|DiagnosticReport|DocumentReference) and as the hidden legacy !Request.reasonReference row.

Additional context:
ProcedureRequest is no longer an active current-build resource; source/fhir.ini records that it was merged into ServiceRequest, while ServiceRequest is active. Current ServiceRequest.reason includes DiagnosticReport and DocumentReference target profiles, and the already-published FHIR-13630 reconciliation restored the companion findings guidance for DiagnosticReport and DocumentReference on the active ServiceRequest successor. MedicationRequest is governed by later Pharmacy issue FHIR-40785, already audited on the combined branch, which specifically added DiagnosticReport to MedicationRequest.reason in sync with the medication-event resources and did not establish a DocumentReference expansion for MedicationRequest.

AutoFHIR reconciliation:
This commit intentionally makes no source changes. The current build-scope Request pattern and active ServiceRequest successor already include DiagnosticReport and DocumentReference, and the remaining MedicationRequest target-list difference is covered by later resource-specific Pharmacy scope rather than by this FHIR-I request-pattern issue.

Recommendation:
Keep this audit commit as-is. Further changes to MedicationRequest.reason, especially adding DocumentReference, should be handled only through a new or existing Pharmacy decision rather than inferred from this retired ProcedureRequest/request-pattern tracker.
