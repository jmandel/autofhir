FHIR-23062: Correct R4/R5 transform page title

Issue request:
FHIR-23062 is a Published/Persuasive technical correction against FHIR-core. It reported that selecting the R4 Conversions tab on resource model pages produced breadcrumb text ending in "R2/R3 Conversions" and requested the conversion breadcrumb use the R3/R4 wording instead.

Initial application:
The Jira comment points to GH#11e3a4e14e, and commit 11e3a4e14ee4eab1e5ce8a7bf55d6afcbd74b922 changed the old in-tree Publisher.java resource version-map title from "res-R2/R3 Conversions" to "res-R3/R4 Conversions". That publisher source was later removed when the build moved to the Gradle/kindling publisher dependency, so the original literal no longer exists in current in-tree Java source.

Additional context:
The current build is now publishing R4/R5 conversion material. The resource version-map template already says "Resource <%title%> - R4/R5 Conversions", and source/r4maps.html is active in publish.ini and source/hierarchy.xml as the Release 4/5 transform page. While checking that current path, AutoFHIR found the active r4maps page still had a copied settitle of "Differences from DSTU Release 3", even though the page heading, links, hierarchy title, and content are all R4/R5. The legacy source/r3maps.html still contains older R2/R3 wording, but it is not listed in the current publish.ini or hierarchy.xml build paths, so it was left unchanged.

AutoFHIR reconciliation:
This commit changes only the active source/r4maps.html page title to "Transforms between Release 4 and Release 5". The resource-specific conversion template needed no change because its current R4/R5 title is already consistent with the current build.

Recommendation:
Keep this source fix as-is. It preserves the historical FHIR-23062 breadcrumb correction through the current R4/R5 conversion page without editing inactive legacy R3/R4 files; any cleanup of source/r3maps.html should be handled separately only if that page is restored to the build.
