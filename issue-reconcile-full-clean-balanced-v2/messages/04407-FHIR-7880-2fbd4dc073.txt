FHIR-7880: Audit Coverage subscriber relationship

Issue request:
FHIR-7880 was a Published/Persuasive Financial Management change request from the 2015 May ballot asking to add Coverage.relationshipToSubscriber (Coding) 0..1 to Coverage using a v3 relationship value set, because Claim.coverage.relationship described an attribute that applies outside the claim context.

Initial application:
No current git commit explicitly mentions FHIR-7880. Source history shows the requested move was applied in the legacy spreadsheet era: commit 9874f360497fb610204cb1aea808e8d78419c5ed removed the active Claim.coverage.relationship row and added Coverage.relationship, and later migration commits carried Coverage into the current StructureDefinition XML source.

Additional context:
The current build uses source/fhir.ini's active coverage=Coverage resource entry. Later Published issue FHIR-17944 changed the same Coverage.relationship terminology from the original v3-style request to a specific subscriber relationship value set, renamed the concept to beneficiary relationship to the subscriber, and made the binding extensible. That later decision explains why the current source uses Coverage.relationship as a CodeableConcept bound to ValueSet/subscriber-relationship rather than the exact original relationshipToSubscriber/Coding wording. FHIR-41765 is a separate Resolved - change required copyright issue for the subscriber relationship terminology and was not treated as applied/published source-edit scope for this seed.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current Coverage defines Coverage.relationship 0..1 as the beneficiary relationship to the subscriber with an extensible binding to http://hl7.org/fhir/ValueSet/subscriber-relationship, and current Claim.insurance.coverage points to Coverage without retaining the old Claim.coverage.relationship element. The current source therefore preserves the requested rule after later accepted terminology refinements.

Keep this empty audit commit as-is. No FHIR core source follow-up is needed for FHIR-7880; handle FHIR-41765 separately if this run's scope later includes resolved-but-not-applied terminology copyright cleanups.
