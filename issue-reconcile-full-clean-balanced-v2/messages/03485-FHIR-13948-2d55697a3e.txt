FHIR-13948: Audit queued claim outcome

Issue request:
FHIR-13948 was Published/Persuasive with Modification for STU3. It asked to add an acknowledgement-style code to ExplanationOfBenefit.outcome because the existing partial code implied some adjudication had already occurred; the final resolution chose the code `queued` for a claim/preauthorization/predetermination received but not yet processed.

Initial application:
The issue was applied in SVN-era commits cff1ea3a29 and fca077283d, first adding a received concept to the remittance outcome code system and then changing the outcome code list, ClaimResponse source, and ExplanationOfBenefit source from `received` to `queued`.

Additional context:
The current build lists ExplanationOfBenefit and ClaimResponse as active resources in source/fhir.ini. The old remittance-outcome source file was later refactored into the current claim-outcome source by 33b409a4b6, preserving the `queued` concept. Current ExplanationOfBenefit.outcome binds to ValueSet/claim-outcome and its short/comment explicitly include `queued`; the claim-outcome CodeSystem defines `queued` with the received-but-not-processed meaning. A later Zulip thread about an R4B RemittanceOutcome regression described a rogue legacy remittance definition and recorded that it was fixed in source, supporting the current claim-outcome source as the authoritative location.

AutoFHIR reconciliation:
This audit commit intentionally makes no source changes because the current active ExplanationOfBenefit source and required outcome value set already contain the resolved `queued` semantics. Editing the remaining legacy remittance-outcome strings would not improve the current EOB binding and could re-open retired terminology plumbing rather than correcting the active build artifact.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-13948 unless a future terminology cleanup deliberately removes legacy RemittanceOutcome names from non-authoritative model/binding artifacts as a separate maintenance task.
