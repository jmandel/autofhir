FHIR-16335: Audit CodeSystem metadata guidance

Issue request:
FHIR-16335 was a Published/Persuasive with Modification STU3 Vocabulary change request for FHIR-core CodeSystem. It said the "detailed metadata" section was confusing because it separated concept detail from terminology content with RxNorm and LOINC examples, and the approved resolution was to mark the section informative, make it less specific, and use examples such as Medication resource instances for RxNorm code details and ObservationDefinition instances for LOINC code details.

Initial application:
The issue was applied in svn r14659 / git commit 1997a01d8577f30f5d3623567efbad30292eed53, which wrapped the detailed-metadata section in informative content and revised the examples to Medication resource instances, ObservationDefinition instances, and Location. A later 2018 terminology documentation update, 4907f9bcb0b710cb2837a93a20c4b23210a37249, moved the same area under a draft/informative Implicit Code Systems section while retaining the detail-resource guidance.

Additional context:
The CodeSystem resource remains active in the current build through source/fhir.ini. Later Published issue FHIR-39265 targeted the same codesystem.html#detailed-metadata/Implicit Code Systems area and resolved to remove it after concluding that the detail-resource text was confusing and not clearly about implicit code systems; commit 5b5b4bd9e5cd01b766e91cc133cbd49ed7b2dcae commented it out. FHIR-40432 later restored a rewritten Implicit Code Systems section through commit b43da92ce17ba143a684e32b04edfd5b18d82ecd, but the old RxNorm/LOINC "detail resource" prose was not restored. Zulip search found only bot notifications for FHIR-16335; Confluence minutes showed later Vocab discussion of the detailed-metadata/implicit-code-system topic without contradicting the Jira/source trail.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The latest combined-branch CodeSystem source contains the rewritten <a name="implicit-code-systems"> section and no detailed-metadata anchor or old separate "detail" resource guidance, so the current specification no longer has the confusing text FHIR-16335 asked to soften. Reintroducing FHIR-16335's examples would conflict with later applied/published decisions.

Recommendation:
Keep this audit commit as-is. No FHIR-core follow-up is needed for FHIR-16335; future work on implicit code systems should proceed through later issues such as FHIR-40432 or its linked successors.
