FHIR-22745: Resolve AdverseEvent causality TODO

Issue request:
FHIR-22745 was a Published/Persuasive Patient Care QA issue asking to remove two AdverseEvent TODOs: one questioning whether AdverseEvent.suspectEntity.causality was a backbone element, and one questioning the difference between causality.assessmentMethod and the result. The accepted resolution said to remove both TODOs because causality is now a BackboneElement supporting multiple methods and the old assessment/result concern no longer applied.

Initial application:
The issue was initially applied by e07c2ff1ac898dde0686f31a089dd8fb9bbfb14e, which removed the two element-level TODO notes from source/adverseevent/adverseevent-spreadsheet.xml while also applying the related FHIR-22746 AdverseEvent.event rename. The current source no longer has those element comments, and causality is defined as a BackboneElement, but the later XML source conversion left the AdverseEventCausalityMethod binding description as TODO.

Additional context:
AdverseEvent is active build input in source/fhir.ini, with an active [resources] entry, Patient Care ownership, normative status, and FMG approval. The related FHIR-22746 change is already represented on the combined reconciliation branch, so this commit is limited to FHIR-22745. Searches of local Jira, Zulip, and Confluence indexes found no later or conflicting community decision for the AdverseEvent causality TODOs.

AutoFHIR reconciliation:
This commit replaces the lone remaining AdverseEvent TODO binding description in source/adverseevent/structuredefinition-AdverseEvent.xml with the matching description from source/adverseevent/valueset-adverse-event-causality-method.xml. This removes a visible placeholder from the authoritative StructureDefinition source without changing cardinality, types, bindings, examples, or generated diagram artifacts.

Recommendation:
Keep this source fix as-is. It completes the FHIR-22745 QA cleanup in current build scope, while leaving the separately audited FHIR-22746 rename and generated diagram output untouched.
