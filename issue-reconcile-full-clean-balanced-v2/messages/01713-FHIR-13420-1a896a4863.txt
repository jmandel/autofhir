FHIR-13420: Register no-emergency Consent example

Issue request:
FHIR-13420 was Published / Persuasive for the Consent resource. It asked for an example showing a privacy consent that forbids both normal treatment sharing and emergency break-glass use, and the final resolution said this could be managed with Consent provisions rather than structural or codelist changes, with a comment noting that other codes such as BTG and disaster-related purposes might be needed.

Initial application:
No local source commit explicitly mentioning FHIR-13420 was found. Git history shows b6c8eb172f added source/consent/consent-example-No-Emergency.xml in January 2019, and later Consent model work including FHIR-39597 updated the example to the current Consent.decision/provision pattern. However, the active Consent examples list was created later without this example, and the example source did not include the requested BTG/disaster-code comment.

Additional context:
Consent is an active current-build resource in source/fhir.ini. FHIR-39597 moved Consent.provision.type to Consent.decision and made provision levels alternate from the base decision, so the current example's permit base with a first-level TREAT/ETREAT provision is the current-model equivalent of denying those matching purposes. The current model's missing Consent.provision.action means all actions, so it still covers disclosure without reintroducing obsolete STU3-era structure. FHIR-13419 was related only as an Organization/HIE example request and was resolved no-change; it does not require a Consent source edit.

AutoFHIR reconciliation:
Registered consent-example-No-Emergency in source/consent/list-Consent-examples.xml so the example is exposed with the other active Consent examples. Added the requested XML comment to source/consent/consent-example-No-Emergency.xml noting that BTG and disaster-related purpose codes may be needed in some policies. No structural, binding, or codelist changes were made.

Recommendation:
Keep this source-changing commit as-is. Further work would only be needed if CBCC wants a normative rule for specific break-glass/disaster codes or wants to narrow the example to a specific Consent.provision.action code, which is broader than this applied example request.
