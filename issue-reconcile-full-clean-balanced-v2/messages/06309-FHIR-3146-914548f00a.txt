FHIR-3146: Audit repeated Questionnaire answers

Issue request:
FHIR-3146 was a Published/Persuasive DSTU1 Patient Care change request asking QuestionnaireAnswers to support multiple answers to a question, because answer[x] itself could not repeat. The final Jira comments record PC approval on 2014-05-29 and note that repeating and required controls were also added.

Initial application:
No current git commit message explicitly names FHIR-3146. The early Questionnaire/QuestionnaireAnswers history shows the May 2014 split and outstanding-change application in commit 54ddc30bbb4f, the remaining agreed Questionnaire updates in commit 0d77af906c3c, and the January 2015 draft history entry in commit 91c9acbdfbaa explicitly listing QuestionnaireAnswers "allow multiple answers" for tracker 3146.

Additional context:
The current build has active Questionnaire and QuestionnaireResponse resources. Later repeat-answer issues FHIR-12170, FHIR-33335, and FHIR-55973 clarified that question repeats are represented as one QuestionnaireResponse item with multiple answer entries, added the qrs-2 repeated-answer constraint, and then required distinct answer values; none of those later decisions removes support for multiple answers.

AutoFHIR reconciliation:
No source change was made. Current source already implements the requested capability: Questionnaire.item.repeats defines when a question can have multiple distinct answers, QuestionnaireResponse.item.answer has max="*", and QuestionnaireResponse.item comments and constraints explain that repeated answers are combined in the answer array for a single item.

Recommendation:
Keep this no-change audit commit as-is. Further edits for FHIR-3146 would be redundant and could conflict with later clarifications that already govern the current Questionnaire/QuestionnaireResponse model.
