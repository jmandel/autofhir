FHIR-25500: Audit code-list short-name plus display

Issue request:
FHIR-25500 was a Published/Persuasive FHIR-I change request for R5 asking for consistent publisher display of code-list short names. The accepted resolution required the publisher to include "+" whenever the codes shown in an element short name are not the complete list, without mandating a fixed number of displayed codes.

Initial application:
No FHIR-25500-tagged source commit was found in this checkout. The issue was explicitly treated as a tooling fix in FHIR-I minutes, and the legacy IG publisher had already been removed from this repository to Maven before the issue was filed. Current generated StructureDefinition source introduced by the 2021 source rework already contains "+" on truncated code-list short names, and a later FHIR-I Zulip thread records Grahame's understanding that the "+" policy had long been coded as a publisher rule.

Additional context:
The current FHIR core build-facing source contains active resources whose coded-element short names use "+" when the visible list is truncated, including Task.status and Questionnaire.item.type. The current build.fhir.org rendering also shows the same "+" for Task.status. Jira, Zulip, and Confluence searches found no related final decision reversing or narrowing the policy.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core source and rendered build already demonstrate the requested "+" convention, and the implementation point for any future violation is the publisher tooling rather than manual edits to generated StructureDefinition short strings in this checkout.

Recommendation:
Keep this no-change audit as-is. If a future page shows a truncated code-list short name without "+", fix the publisher rule or its generation inputs in the appropriate tooling repository instead of hand-editing generated core artifacts.
