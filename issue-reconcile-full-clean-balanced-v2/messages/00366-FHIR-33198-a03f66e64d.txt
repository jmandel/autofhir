FHIR-33198: Audit NamingSystem R4B ballot maturity

Issue request:
FHIR-33198 was Published with a Not Persuasive with Modification resolution. It reported that the R4B ballot introduction said resources had increased to maturity level 3+ even though NamingSystem only reached FMM level 2. The approved resolution said the final R4B release had the correct actual FMM, but the no-longer-referenced R4B ballot intro page should be removed so the stale statement could not confuse readers.

Initial application:
The NamingSystem metadata correction itself was applied through the related NamingSystem issues, not through a FHIR-33198-tagged source commit. Git commit c0e7329f4d updated the R4B source for FHIR-29945 and FHIR-29113, changing NamingSystem FMM from 1 to 2 and ownership from FHIR-I to Vocab. Git commit 387eb6b80a applied the same NamingSystem FMM/owner update for R5. No current-branch source commit explicitly tagged FHIR-33198 was found.

Additional context:
The current build source is not the old R4B ballot page. source/ballot-intro.html is an active R6 ballot roadmap, and searches of the current source found no remaining R4B wording that says NamingSystem or the listed resources moved to level 3+. The historical origin/R4B source branch still contains the stale R4B ballot-intro phrase, but that branch is outside the current combined-branch build, and https://hl7.org/fhir/R4B/ballot-intro.html now returns 404. The published R4B NamingSystem profile reports FMM 2 and wg vocab. Later FMG minutes on 2023-03-22 approved moving NamingSystem to FMM 4 for R5 publication readiness, and git commit 1ade81c36b updated source/fhir.ini accordingly; that later decision supersedes treating FMM 2 as the current-build target.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Removing source/ballot-intro.html or its hierarchy/index links would remove the current R6 ballot page, not the obsolete R4B page. Reverting source/fhir.ini NamingSystem FMM from 4 to 2 would also contradict the later FMG-approved FMM update. The current build therefore needs only this audit record for FHIR-33198.

Recommendation:
Keep this no-change audit as-is for the current branch. No current FHIR source follow-up is needed for FHIR-33198. If someone wants the historical origin/R4B source branch to match the already-correct published R4B surface, that should be handled separately from this current-build reconciliation.
