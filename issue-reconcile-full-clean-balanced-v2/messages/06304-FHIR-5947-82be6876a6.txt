FHIR-5947: Audit code system hierarchy semantics

Issue request:
FHIR-5947 was a Published/Persuasive with Modification FHIR-core ValueSet change request from DSTU1. It asked to clarify that child concepts in an inline code system are not necessarily subsumed by their parents, to change the child concept label from only "is-a / contains" toward "is-a / contains / etc", and to replace the old note saying contained concepts are subsumed with language that the specification does not fix the parent/child relationship and that partitive or categorization relationships are also possible.

Initial application:
The issue was directly applied in svn revision 5884, now git commit 4d58ba423fb6e247c224c0ad6967c2fdf863059e, which replaced the ValueSet note asserting an is-a/subsumption relationship with text saying the relationship is not fixed and may be partitive or categorization-based. Later source refactoring for #10309 in 1120eb61d0d267aae58f1da321cd5c9286dbff1d moved inline code system material out of ValueSet, and FHIR-10542 in 0660290432e8973697937511a6c321643c0c5ea6 corrected the successor CodeSystem.concept.concept definition to point to CodeSystem.hierarchyMeaning.

Additional context:
The current build scope includes both ValueSet and CodeSystem as active resources in source/fhir.ini. In the current source, CodeSystem.hierarchyMeaning is the required-bound element for hierarchy semantics, CodeSystem.concept.concept says child relationships are variable and refers readers to hierarchyMeaning, and the CodeSystem hierarchy/subsumption narrative defines subsumption relative to the declared hierarchy meaning. Later Published issues FHIR-25983 and FHIR-39262 further refined the same model by adding hierarchyMeaning warning invariants and clarifying nested concepts versus property-based polyhierarchies. Current ValueSet expansion hierarchy text separately says expansion nesting has no logical-inference implication, which is compatible with the seed's concern and not a stale copy of the old inline-code-system rule. Zulip and Confluence searches for FHIR-5947 and the seed terms found no conflicting community context.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The original DSTU1 wording was applied, and the current R6-era source expresses the same semantic rule through CodeSystem.hierarchyMeaning rather than the obsolete ValueSet.define inline code system structure. Reintroducing the old resolution wording into ValueSet would duplicate or stale the modern CodeSystem model.

Recommendation:
Keep this commit as-is. No follow-up is needed for FHIR-5947 in the core source unless the work group opens a separate issue to revise the broader ValueSet expansion wording or CodeSystem hierarchy model.
