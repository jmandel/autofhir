FHIR-13157: Audit MedicationRequest dosage rate examples

Issue request:
FHIR-13157 was a Published FHIR-core Pharmacy change request for the DSTU2 MedicationPrescription/MedicationRequest examples. It asked why a simple infusion rate such as 100 ml/hr was represented with rateRatio rather than rateSimpleQuantity, and it also asked for clearer guidance about the relationship between free-text dosage instructions and structured dosage data. The accepted resolution was Persuasive with Modification: create examples for all three rate[x] forms (rateRatio, rateRange, and rateQuantity) and add overview wording about free-text dosage instructions.

Initial application:
The Jira comments record an August 17, 2017 dosing-clarification application and an August 21, 2017 example/rate guidance update. Git history confirms commit 17795bbfaf5fb47e4c1961e386c5fea10e7b4926 added MedicationRequest dosage-instruction notes for FHIR-13157, and commit 485e4881046bcb3b7f45ac130fc7641bbd2bf969 changed medicationrequest0319 from rateRatio to rateQuantity, labeled MedicationRequest examples by rate type, and added Dosage.doseAndRate.rate[x] guidance saying 100 ml/hour may be represented using either rateRatio or rateQuantity.

Additional context:
MedicationRequest is an active current-build resource in source/fhir.ini. The current MedicationRequest example index still includes active examples for rateRange, rateRatio, and rateQuantity, including the FHIR-13157 rateQuantity example and later FHIR-14111 weight-based rateQuantity examples. Later Pharmacy issues FHIR-13222 and FHIR-39319 refined the Dosage.text guidance; the current source now routes MedicationRequest dosageInstruction through DosageDetails.renderedInstruction and Dosage.text, preserving the substantive rule that human-readable instructions remain available and should align with structured dosage content without restoring the exact older wording.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already implements the modified resolution through active MedicationRequest examples and current Dosage/DosageDetails wording, and changing the rateRatio example to rateQuantity would undo the approved choice to show all three rate[x] representations.

Recommendation:
Keep this audit commit as-is. Future work should handle any independent example-data cleanup through separate tracker issues, not under FHIR-13157, because this issue's approved rate-type coverage and dosage-text clarification are already present in the current build source.
