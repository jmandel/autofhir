FHIR-13656: Audit standard extension visibility

Issue request:
FHIR-13656 was a Published/Persuasive STU3 FHIR-core change request asking that standard extensions be made more visible because readers often missed resource-specific standard extensions; the request suggested a table on the content page or a prominent link from the resource structure content to the standard extensions for that profile/resource.

Initial application:
The issue appears to have been applied by SVN revision 12640, represented in git as 65beab7892f222ac4460dcfd25ab40c007777c0b, which added a resource content-page link from the alternate/additional definitions paragraph to each resource's profiles/extensions page. Later template history preserved that behavior by replacing the literal link with the generated [%ext-link%] placeholder and moving the template from source/template.html to tools/templates/template.html.

Additional context:
FHIR-16525 revisited the same visibility concern and rejected an inline table of all standard extensions as too prominent/noisy, preferring links near the resource content instead. The follow-up FHIR-20637 decision accepted the Zulip option to add a link to extensions below the content view. The current rendered build also has top resource-page tabs for Profiles and Extensions, uses the FHIR Extension Pack URLs for resource extension lists, shows "See the Extensions" links after the resource structure views, and retains the additional-definitions extension link generated from the current template.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope resource template still carries the extension-link placeholder in the additional definitions area, and current rendered Patient and Observation pages demonstrate the resource-level extension links that satisfy the seed request without adding a redundant table or prose.

Recommendation:
Keep this audit commit as-is. No core FHIR source change is recommended for FHIR-13656; future extension visibility changes should be considered through the later FHIR-16525/FHIR-20637 design family rather than by re-adding a resource-page extension table.
