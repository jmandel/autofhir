FHIR-5342: Audit AuditEvent participant reference targets

Issue request:
FHIR-5342 is a Published FHIR-core AuditEvent ballot issue from DSTU1 resolved Persuasive with Modification. It asked to broaden SecurityEvent.participant.reference from Practitioner|Patient|Device to include RelatedPerson, with the accepted application also adding Organization while explicitly not adding Group at that time because Group rules then did not support collective actors.

Initial application:
The issue appears to have been applied in git commit 8e3bf13ba6, "Updated AuditEvent for [5775] [5342] [5337] [5336]", which changed the then-authoritative AuditEvent spreadsheet reference type from Reference(Practitioner|Patient|Device) to Reference(Practitioner|Organization|Device|Patient|RelatedPerson). The later SecurityEvent to AuditEvent rename and generated-source migrations moved that same concept into the current StructureDefinition source.

Additional context:
AuditEvent is an active build resource in source/fhir.ini, and source/fhir.ini maps the old AuditEvent.participant name to the current AuditEvent.agent element. Later final AuditEvent decisions changed the element name from agent.reference to agent.who and broadened the allowed actor types: FHIR-17412 renamed agent.reference to agent.who, FHIR-32454 aligned agent.who with Event performer actor types, and FHIR-49672 added further agent kinds after FHIR-49304 workflow actor guidance. Those later changes explain the extra current target profiles and do not reverse the FHIR-5342 requirement that RelatedPerson and Organization be allowed.

AutoFHIR reconciliation:
No source change was made. The current active source for AuditEvent.agent.who already includes Practitioner, Organization, Patient, Device, and RelatedPerson, plus later-added actor types including PractitionerRole, CareTeam, DeviceDefinition, Group, and HealthcareService. Adding or removing target profiles for this old ballot item would either duplicate current behavior or undo later applied decisions.

Recommendation:
Keep this no-change audit commit as-is. No FHIR core follow-up is needed for FHIR-5342 unless the Security work group separately reopens the broader question of which resources may act as AuditEvent agents.
