FHIR-28099: Audit SMART OAuth extension registry

Issue request:
FHIR-28099 was a Published/Persuasive FHIR-core change request for R5 asking that the core FHIR extension page for the SMART OAuth URIs extension be fixed to match the SMART App Launch definition, and noting that HL7 should later discuss whether IG-defined extensions should be hosted in the base spec.

Initial application:
No Jira-tagged FHIR-28099 core commit was found. The core source originally added the SMART App Launch extension spreadsheet in fc9f4585b4, including oauth-uris rows, but dd468d4f17 later removed those extension rows from the active core profile source as part of removing extensions from the R5 source. The current core checkout keeps only the permanent OID assignment for the SMART oauth-uris canonical URL.

Additional context:
The 2020 Zulip thread that prompted the Jira confirmed that the SMART IG definition was authoritative and that the duplicated core definition was out of sync because it lacked revoke and introspect. FHIR-I minutes approved FHIR-28099 as Persuasive. The current authoritative extension definition is now in the FHIR Extension Pack, where FHIR-48552 added introspect and revoke and deprecated the extension in favor of .well-known/smart-configuration.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current FHIR-core source no longer publishes a competing oauth-uris StructureDefinition from source/profiles/smart-app-launch-spreadsheet.xml, and editing source/oids.ini would be wrong because it is only the permanent OID registry. The remaining maintained definition belongs to the FHIR Extension Pack, which already contains the expected SMART sub-extensions.

Recommendation:
Keep this audit commit as-is for core. Future changes to the SMART oauth-uris extension should be made in the FHIR Extension Pack or SMART IG, not by reintroducing a duplicate core definition.
