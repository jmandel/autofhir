FHIR-8668 was a Published/Persuasive FHIR-core DiagnosticReport correction from DSTU1. It asked to replace outdated retraction guidance that used Special Values/withdrawn result values with guidance to retract the DiagnosticReport and associated Observations by setting their statuses to "entered-in-error", updating conclusion/comment and narrative text, and optionally recording a reason in the narrative.

Initial application:

That commit changed source/diagnosticreport/diagnosticreport-notes.xml from the old Special Values/withdrawn guidance to the entered-in-error wording. A later editorial commit, 72be4e488cad4031ab41edce39f3ffb1fa0bf83c, adjusted punctuation and surrounding DiagnosticReport status prose without changing the FHIR-8668 rule.

Additional context:
DiagnosticReport is an active resource in source/fhir.ini, so source/diagnosticreport/diagnosticreport-notes.xml is in the current build scope. The current DiagnosticReport notes still contain the entered-in-error retraction sentence, DiagnosticReport.status is bound to the status value set that includes entered-in-error, and Observation.status also includes entered-in-error. A later R6 issue, FHIR-56192, requests a new statusReason element for Observation and DiagnosticReport, but it is only Resolved - change required/Ready_to_Apply and no current DiagnosticReport.statusReason source element exists, so it is context rather than a completed change that should rewrite FHIR-8668 now.
