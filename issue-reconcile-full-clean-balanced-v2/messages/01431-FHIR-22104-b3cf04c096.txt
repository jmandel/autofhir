FHIR-22104: Audit Provenance ISO activity vocabulary

Issue request:
FHIR-22104 was Published with resolution Persuasive. It asked for the Provenance.activity value set to include the ISO 21089 vocabulary, pointing to the AuditEvent type value set as the model for assembling the vocabulary.

Initial application:
The request was applied before this reconciliation through the Security WG PR #708 path. Git commit b569c4406b1d2a7944cc4b25869f7075524fe4f3 added an include for http://terminology.hl7.org/CodeSystem/iso-21089-lifecycle to the then-current source/provenance/valueset-provenance-activity-type.xml, and merge commit e5f777ad514d570245abf181a3637f154a2529a9 brought PR #708 into the specification.

Additional context:
Later same-artifact decisions changed how that vocabulary should be represented now. FHIR-23712 first expanded provenance-activity-type broadly, but later Published issue FHIR-32517 found that broad/extensible value set incoherent and changed Provenance.activity to an example binding with a small representative ISO 21089 lifecycle sample. Later Applied issues FHIR-55798 and FHIR-55797 refined the same value set description and added destroy while preserving the example ISO sample model. source/fhir.ini actively lists provenance as a current resource, source/provenance/structuredefinition-Provenance.xml binds Provenance.activity to http://hl7.org/fhir/ValueSet/provenance-activity-type, and source/terminologies/valueset-provenance-activity-type.xml now contains representative ISO 21089 lifecycle codes.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source satisfies FHIR-22104 after considering the original application and later final Security WG decisions: Provenance.activity still uses the provenance activity value set, and that value set is an example set composed from ISO 21089 lifecycle codes. Re-expanding or otherwise changing the value set for FHIR-22104 would risk undoing the later FHIR-32517/55797/55798 shape.

Recommendation:
Keep this audit commit as-is. No core FHIR source follow-up is recommended for FHIR-22104 unless the Security WG creates a new issue to replace the current example ISO lifecycle sample with a different Provenance.activity vocabulary policy.
