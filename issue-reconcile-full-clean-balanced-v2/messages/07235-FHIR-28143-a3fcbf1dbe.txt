FHIR-28143: Audit extension URL wording

Issue request:
FHIR-28143 was a Published/Persuasive FHIR-core technical correction for the extensibility Extension Element notes. It asked to clarify that Extension.url SHALL be a reference to the canonical URL of the StructureDefinition defining the extension, not an element of the canonical datatype itself.

Initial application:
The issue was explicitly applied by git commit 34f08837d9, which changed source/extensibility.html from "SHALL be the canonical URL of a StructureDefinition that defines the extension" to "SHALL be a reference to the canonical URL of a StructureDefinition that defines the extension". Current source/fhir.ini maps the active extension page to source/extensibility.html, and current source/extensibility.html still contains the requested wording.

Additional context:
The linked Zulip discussion confirms the rationale: Extension.url is typed as uri and intentionally cannot carry a canonical "|version" suffix, while still referring to the canonical URL in StructureDefinition.url. A Jira neighborhood search found the earlier FHIR-8966 issue that introduced StructureDefinition/canonical-URL language, but that issue is historical background rather than additional current reconciliation work. Confluence searches found no FHIR-28143 reference or conflicting work-group decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active source already conveys the requested distinction, and an exact source search found no remaining occurrence of the old "SHALL be the canonical URL of a StructureDefinition" requirement.

Recommendation:
Keep this no-change audit commit as-is. No FHIR core source follow-up is needed unless the work group later revisits whether Extension.url should support version-qualified canonical references.
