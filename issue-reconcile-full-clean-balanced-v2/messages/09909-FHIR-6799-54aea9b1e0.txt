FHIR-6799: Audit schema warning coverage

Issue request:
FHIR-6799 was Published/Persuasive with Modification for the DSTU1 schema/schematron downloads page. It asked for warnings, preferably in the schema download area, that schemas and schematrons do not enforce every FHIR conformance rule and that implementers must still understand the specification and applicable profiles; the resolution was to add warnings and references to generated schematrons for profiles.

Initial application:
The issue was applied in SVN revision 6393, represented in this git history by commit 56b5aa5b881daf312d25d7905f78cfc809d5cd25, which added a downloads-page warning that schemas and schematrons do not contain all rules for valid resources and that implementers must know the specification and applicable profiles. Later downloads-page reorganization moved the warning into the FHIR Definitions row and broadened it to all derived download forms while preserving the same implementer guidance.

Additional context:
The current Downloads page remains an active source page linked from the documentation and implementation-support navigation. It says the definitions package is the master source and that the other forms below, including validation schemas and code-generation schemas, are incomplete subsets that do not contain all validity rules. The current XML and Validation pages also warn that schema plus Schematron validity is not sufficient for a conformant instance, describe profile-generated schematron limits, and identify human inspection of the relevant implementation guides and base specification as the final arbiter. No Zulip or Confluence evidence found a conflicting later decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already conveys the requested warning and profile/schematron limitations in the relevant built guidance pages, so adding another readme-style warning or duplicating prose next to the schema download link would not change implementer understanding and could create maintenance drift.

Recommendation:
Keep this no-change audit commit as-is. Revisit only if the build later removes the existing downloads/XML/validation warnings or if the actual downloadable schema archive gains a maintained README mechanism that needs separate source wiring.
