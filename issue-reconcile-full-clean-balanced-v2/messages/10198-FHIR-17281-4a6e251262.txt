FHIR-17281: Audit IG canonical redirect ownership

Issue request:
FHIR-17281 was a Published/Persuasive FHIR-core STU3 change request asking that canonical URLs for Implementation Guide resources, using Argonaut as the example, redirect to the current rendered IG pages instead of returning 404s. The issue specifically cited http://fhir.org/guides/argonaut/ValueSet/usrealm-birthsex and element-fragment URLs such as StructureDefinition/argo-patient#Patient:argoprofile.birthDate.

Initial application:
No current FHIR-core git commit explicitly mentioning FHIR-17281 was found. The Jira record was auto-approved and later comments from Grahame characterize it as an old tooling issue, directing any continuing problem to HL7/fhir-ig-publisher. Source and history searches did not find a current build-scope FHIR-core source location where an Argonaut canonical-to-rendered-page redirect is defined.

Additional context:
Argonaut guide publication is not active current core build content: source/igs.xml keeps the Argonaut IG declaration commented out, and related combined-branch audits already cover historical Argonaut publication and adjacent IG Publisher URL behavior. The in-repository IG Publisher was removed in 2019 because it moved to Maven. A 2016 Zulip discussion confirms that canonical URL redirects for IG resources were IG Publisher/web tooling behavior, and a live check of the exact Jira ValueSet canonical URL still returns 404 while the rendered Argonaut page returns 200.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR-core source change. The remaining problem, if still to be fixed for historical Argonaut URLs, belongs to IG Publisher or fhir.org/IG web redirect infrastructure rather than to the current FHIR specification checkout.

Recommendation:
Keep this external-repo audit as-is for FHIR-core. If the Argonaut canonical URLs must still resolve, file or update external IG Publisher/web infrastructure work with the exact failing canonical URLs and expected rendered targets; do not edit current core source unless a current build-scope redirect source is identified.
