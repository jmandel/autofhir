FHIR-12205: Audit search sort discretion

Issue request:
FHIR-12205 was a Published/Not Persuasive with Modification FHIR-I clarification asking how _sort should behave for complex values such as Range/Period and for missing/null values, using Observation.effective[x] date sorting as the motivating example. The approved resolution was not to prescribe a detailed cross-server ordering rule, but to make the existing "reasonable order" and implementation-dependent sort-order guidance apply to all datatypes rather than only strings.

Initial application:
The issue was applied by git-svn commit a76403735f4636f667e40a703e5cc865f0fd8f94, "#12205 - note about sort order", corresponding to Jira's noted svn revision 10272. That commit edited build-scoped source/search.html to split the consistency-of-sorting paragraph out of the string-specific bullet so it applied generally across sorting.

Additional context:
The original Zulip thread "Observation date sorting" records the same Observation.effective[x], Period boundary, and missing-effective questions that became this tracker. Later Published issues refined the same search sorting section without reversing FHIR-12205: FHIR-19692 added explicit server discretion for repeated and complex elements, and FHIR-39398 added date/Period-specific server-defined wording plus the Period.start implementation note. Both of those related issues already have audit commits on the combined branch, so this seed should not republish them.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source/search.html _sort notes already state that servers have discretion for repeated and complex elements, that the specification does not specify exact rules for consistency of sorting across servers, and that date sorting over non-singleton source data such as Period is server-defined. Adding a separate null-ordering rule would go beyond the approved FHIR-12205 resolution, which deliberately left exact sort order implementation-dependent.

Recommendation:
Keep this no-change audit commit. No follow-up source work is needed for FHIR-12205 unless the work group later decides to prescribe exact null placement, Period boundary handling, or Range ordering for specific search parameters.
