FHIR-41691: Audit DiagnosticReport self-testing guidance

Issue request:
FHIR-41691 is an Applied/Not Persuasive with Modification OO change request about HIV self-testing and DiagnosticReport. The reporter asked whether DiagnosticReport.performer or DiagnosticReport.resultsInterpreter could identify the patient for a self-test result; OO decided this use case did not warrant adding Patient to those elements at that time and directed that patient-generated information such as self-test results should be captured as Observation guidance in the DiagnosticReport boundaries text.

Initial application:
The issue was applied before this reconciliation. Jira records PR #3188 commit 55736d2, and git history shows ca2dd9b changed source/diagnosticreport/diagnosticreport-introduction.xml to add the requested boundaries sentence: "The Observation resource should be used to record patient-generated information (e.g., self-test results)." DiagnosticReport is an active build resource in source/fhir.ini, so that narrative source is in scope.

Additional context:
Later source history changed the exact FHIR-41691 sentence. FHIR-54543, currently Resolved - change required rather than Applied/Published, identified that the FHIR-41691 wording could imply Observations are only for patient-generated data; source commit d7e54b5 replaced it with the current broader sentence that Observation represents individual, atomic measurements or assertions regardless of whether they are generated by a clinical service, device, or patient. FHIR-49190 is a later Applied OO decision that superseded the earlier no-target-addition aspect by allowing Patient and RelatedPerson on DiagnosticReport.performer and DiagnosticReport.resultsInterpreter for self-performed and at-home testing, with explanatory narrative; that issue is already represented on the combined branch by d4df5a4. The linked Zulip thread and OO minutes support the original conclusion that rapid self-test values belong at the Observation/result level, while later discussion recognized more complex at-home testing scenarios.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current DiagnosticReport boundaries paragraph still preserves the FHIR-41691 implementer guidance for atomic patient-generated self-test results through Observation, but avoids the misleading narrow wording that later source history corrected. The current Patient/RelatedPerson target profiles and explanatory paragraph are left intact because they reflect the later FHIR-49190 Applied decision rather than an unapplied gap in FHIR-41691.

Recommendation:
Keep this no-change audit commit. Do not restore the exact FHIR-41691 sentence or remove Patient/RelatedPerson from DiagnosticReport performer/resultsInterpreter; doing so would conflict with later issue history. Future review should focus only on FHIR-54543 if OO wants to finish applying/publishing that clarification workflow state.
