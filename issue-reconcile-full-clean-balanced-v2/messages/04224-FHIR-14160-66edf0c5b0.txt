FHIR-14160: Audit ResearchStudy purpose type value set

Issue request:
FHIR-14160 was Published/Persuasive for STU3 by BR&R and asked for a new value set to accompany the newly added ResearchStudy.primaryPurposeType element. Jira records that the change was made and published in the December 2017 FHIR ballot.

Initial application:
No source commit was found that literally names FHIR-14160, but the November 2017 ResearchStudy application trail shows the same work: git commit 271b5865933a3afcb3e636c823af2daf78efb9d9 added ResearchStudy.primaryPurposeType to the ResearchStudy spreadsheet and corrected the ResearchStudyPrimaryPurposeType value set worksheet with the primary purpose codes. A later December 2017 commit for FHIR-14287 removed the two non-vetted codes from that same value set, matching the published STU3 ballot cleanup.

Additional context:
ResearchStudy is an active current-build resource in source/fhir.ini. The current source no longer has the STU3-era local primary-purpose ValueSet or the exact primaryPurposeType element: FHIR-50710 moved the binding to the THO value set, removed the retired local core terminology files, and has already been reconciled on the combined branch; FHIR-53692 then changed the element in the current source to ResearchStudy.purposeType 0..* with an example binding while preserving the primary-purpose THO value set URL. FHIR-37876 is earlier binding-strength background for the same element family. The checked-in ResearchStudy SVG still contains stale primaryPurposeType text, but the authoritative StructureDefinition source is correct and this reconciliation does not make SVG-only generated-artifact edits.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped source already provides the ResearchStudy purpose type element with a binding to http://terminology.hl7.org/ValueSet/research-study-prim-purp-type, and re-adding an old core value set file or reverting the purposeType rename would conflict with later ResearchStudy decisions.

Recommendation:
Keep this audit commit as-is for FHIR-14160. No follow-up is needed for the historical STU3 value-set request; any separate review of the R6 FHIR-53692 status or generated ResearchStudy SVG refresh should be tracked under those later changes, not this issue.
