FHIR-47468: Audit async-bulk file-size parameters migration

Issue request:
FHIR-47468 was Applied/Persuasive for R6 by FHIR-I to add optional async-bulk kick-off query parameters, `_minimumFileSize` and `_maximumFileSize`, so clients can request generated NDJSON files within preferred size bounds. The resolution requires positive integer values, `_maximumFileSize` greater than `_minimumFileSize` when both are present, server conformance expectations for lower/upper bounds, and implementation notes for defaults, necessary deviations, and documented fixed bounds.

Initial application:
The issue was applied in HL7/fhir pull request #3214. Commit a613c0bff23537722fa4f68f65f56dfa6ddc337d added the two parameter bullets and implementation notes to `source/async-bulk.html`, and merge commit a3e413fdf1661c8f6a0bcfdb644f2ccb91c7bf93 brought that branch into the core repository.

Additional context:
The current core build no longer contains `source/async-bulk.html`; commit 270e0ceb7b029dad4ca0fc5ccf5296ff370888cd removed the detailed async bulk and async bundle pages and changed `source/async.html` to point readers to the API Incubator while the details are finalized through implementation testing. The corresponding external HL7/api-incubator-ig source file `input/pagecontent/async-bulk.html` still contains the `_minimumFileSize` and `_maximumFileSize` bullets and implementation notes. Sibling issue FHIR-47469 followed the same migration path for the async-bulk output `filesize` field and has already been audited separately on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. Restoring the old core async-bulk page or duplicating the file-size parameters in `source/async.html` would contradict the current build-scope decision to keep the detailed pattern in the API Incubator.

Recommendation:
Keep this audit commit as-is for FHIR core. If implementers need the incubator content published, linked differently, or further refined, handle that as API Incubator work; do not change core solely for FHIR-47468 while the external source already carries the requested parameters.
