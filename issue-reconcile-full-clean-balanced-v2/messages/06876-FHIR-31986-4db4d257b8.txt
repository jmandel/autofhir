FHIR-31986: Fix Bundle bdl-7 uniqueness invariant

Issue request:
FHIR-31986 was a Published/Not Persuasive with Modification FHIR-I change request raised against R4 and applied for R5. The reporter asked how search include results could legitimately contain the same resource more than once when Bundle fullUrl uniqueness appeared to forbid it. The final resolution kept the rule that a given resource version appears only once, but directed bdl-7 to be clearer: entries with the same fullUrl where a resource is present must have different meta.versionId values.

Initial application:
Git history contains commit d1672bb7c204f7fd6aa18a944692982e02fba3e7, whose subject mentions FHIR-31986, but that commit did not change bdl-7. The current Bundle notes already say that a given version of a resource SHALL only appear once and multiple versions can appear, but the authoritative bdl-7 constraint still used the older whole-history-bundle exception and concatenated fullUrl directly with versionId.

Additional context:
Bundle is an active current-build resource in source/fhir.ini, so source/bundle/structuredefinition-Bundle.xml is in scope. Earlier FHIR-18284 added the broad history exception because deleted history entries lack resource bodies; FHIR-31986 later narrowed that rationale to entries where resource is absent, including history deletes and batch HEAD cases. Later FHIR-39476 corrected missing meta.versionId handling by adding the iif(..., '') fallback, and that issue is already represented on the combined branch, so this reconciliation preserves that later behavior while applying the still-missing FHIR-31986 scope and delimiter fix.

AutoFHIR reconciliation:
This commit updates bdl-7 in source/bundle/structuredefinition-Bundle.xml. The human text now describes entries with the same fullUrl where resource is present, and the FHIRPath now filters to entries with both fullUrl and resource, separates fullUrl from meta.versionId with '|', and keeps the later empty-versionId fallback.

Recommendation:
Keep this commit as-is. It completes the published FHIR-31986 bdl-7 resolution without reopening the already-audited FHIR-39476 correction; future changes to broader Bundle uniqueness semantics should be handled through a new work-group decision.
