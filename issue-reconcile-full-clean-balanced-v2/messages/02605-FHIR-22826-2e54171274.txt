FHIR-22826: Audit medication statement category label

Issue request:
FHIR-22826 was a Published/Persuasive Pharmacy change request, raised in STU3 and applied for R5, reporting that the medication-statement-category ValueSet page incorrectly used "Medication Status Codes" as its name and title. The approved resolution was to fix the current build and, once technical corrections were confirmed possible, carry the R4 correction as well.

Initial application:
The same current-build defect was already addressed in the Pharmacy terminology change trail. FHIR-20306 was an earlier Published issue for the same MedicationStatement.category value-set label problem and its cited PR #490/merge 16680e7ffc includes commit 92cc863203, which changed the old source/medicationstatement/valueset-medication-statement-category.xml metadata away from "Medication Status Codes". FHIR-22826 then recorded the R4 technical-correction application, with Jira comment GH#7880dfaedd; that commit changed the old value-set name to "Medication usage category codes".

Additional context:
MedicationStatement remains active in source/fhir.ini, but the current source no longer contains source/medicationstatement/valueset-medication-statement-category.xml or active references to http://hl7.org/fhir/ValueSet/medication-statement-category. The active MedicationStatement.category binding now points to the shared http://hl7.org/fhir/ValueSet/medicationrequest-category value set, consistent with later Published FHIR-32825 rationalizing duplicate MedicationUsage/MedicationStatement and MedicationRequest category vocabulary. The combined branch already includes FHIR-31632 reconciliation commit d84cc64933, which removed the obsolete unbound MedicationStatement category value-set source after aligning current examples with the core medicationrequest-category terminology. The remaining source/oids.ini row for the old URL is an OID registry remnant, not the authoritative value-set definition that produced the erroneous name/title.

AutoFHIR reconciliation:
This commit intentionally makes no source change. There is no current built medication-statement-category ValueSet summary left to correct, and the current active category binding uses the shared MedicationRequest category ValueSet whose name/title/description are not "Medication Status Codes".

Recommendation:
Keep this no-change audit commit. Do not recreate or edit the obsolete MedicationStatement category ValueSet in core for FHIR-22826; future medication category terminology movement should follow the later Pharmacy/Terminology issue trail rather than this historical label correction.
