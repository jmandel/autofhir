FHIR-14002: Audit ServiceRequest codified order details

Issue request:
FHIR-14002 was a Published, Persuasive with Modification Orders and Observations change request raised against STU3 ProcedureRequest.supportingInfo. It asked for support for codified order-entry details such as isolation precautions, transportation mode, anesthesia type, NPO exceptions, catheter type, and ventilator mode, because using supportingInfo as only Reference(Any) did not cover these coded details. The final resolution did not simply turn supportingInfo into arbitrary coded instructions; it directed ServiceRequest to carry supportingInfo as a reference and add inline patient/provider instruction/order-detail elements, covering both FHIR-14002 and FHIR-12966.

Initial application:
The change appears to have been pre-applied in SVN-era git history. Commit 5971b343bd added ServiceRequest.orderDetail as CodeableConcept, kept ServiceRequest.supportingInfo as Reference(Any), added ServiceRequest.patientInstruction, and tagged the orderDetail committee notes with [#14002][#12966]. Follow-up commits a0c6e08b5e and 23cf0426e1 added orderDetail and patientInstruction usage to examples. ProcedureRequest is now retired/merged into ServiceRequest, and ServiceRequest is the active resource in source/fhir.ini.

Additional context:
FHIR-14000, the parallel Request-pattern issue, was resolved Not Persuasive because supportingInfo is existing clinical context rather than instructions for how services should be delivered. Later OO decisions preserved and refined that interpretation: FHIR-31589 clarified that ServiceRequest.supportingInfo is for existing supporting information and points delivery instructions/questions to orderDetail; FHIR-32265 reshaped orderDetail into the current parameter/value BackboneElement; FHIR-37355 later changed ServiceRequest.supportingInfo itself to CodeableReference(Resource). Zulip discussion linked from FHIR-12966 shows implementers wanted extra ServiceRequest details beyond supportingInfo, and a later thread describes FHIR-14002 as the origin of orderDetail.

AutoFHIR reconciliation:
This audit commit makes no source change. The current build-scoped ServiceRequest StructureDefinition already conveys the reconciled rule: orderDetail carries additional coded/structured delivery details, patientInstruction carries patient-facing instructions, supportingInfo is active and can now be CodeableReference(Resource), and the current comments steer implementers away from using supportingInfo for instructions.

Recommendation:
Keep this audit commit as-is. No follow-up core source work is needed for FHIR-14002; any broader reconsideration of the Request logical pattern or newer orderDetail shape belongs to the later issue family rather than this STU3 ProcedureRequest tracker.
