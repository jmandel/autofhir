FHIR-46256: Record ClaimResponse adjudication date as R6 change

Issue request:
FHIR-46256 was Applied with resolution Persuasive with Modification for R6. It asked to add .decisionDate 0..1 dateTime to the adjudication elements on ClaimResponse and ExplanationOfBenefit because a single ClaimResponse.created timestamp and the absence of an EOB timestamp were insufficient for tracking when adjudication decisions were made.

Initial application:
The issue was applied by 385d56bffbad3d7572b4cc12d57203a1e389514d, which added decisionDate to ClaimResponse.item.adjudication and ExplanationOfBenefit.item.adjudication. The other ClaimResponse and ExplanationOfBenefit adjudication sites are contentReferences to those item adjudication backbones, so the element is available throughout the repeated adjudication structures. Commit a2d4dd1a93d76c4077c5d9ab14b73deb9d5bbb2d later refined the short and definition text. The later R5-to-R6 change metadata recorded the EOB addition but omitted the parallel ClaimResponse addition.

Additional context:
ClaimResponse and ExplanationOfBenefit are active resources in source/fhir.ini. The linked FHIR-43309 issue concerns multi-patient EOB/claim response support and is a separate change family that does not alter the adjudication date decision. Jira, Zulip, and Confluence searches did not reveal a later reversal or conflicting work-group instruction for FHIR-46256.

AutoFHIR reconciliation:
This commit adds ClaimResponse.item.adjudication.decisionDate=+ to the [r5-r6-changes] section in source/fhir.ini so generated R5-to-R6 change notes can recognize the ClaimResponse decisionDate addition consistently with ExplanationOfBenefit. No StructureDefinition edit was needed because the authoritative ClaimResponse and ExplanationOfBenefit XML already contains the dateTime element and the other adjudication paths reuse it by contentReference.

Recommendation:
Keep this commit as-is. No further core source change or work-group review appears necessary for FHIR-46256; generated diagram artifacts should be refreshed by the normal build rather than edited manually.
