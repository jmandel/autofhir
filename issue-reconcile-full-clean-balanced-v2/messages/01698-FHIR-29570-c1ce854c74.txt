FHIR-29570: Audit Medication batch container lot extension

Issue request:
FHIR-29570 was a Published Pharmacy change request, resolved Persuasive with Modification for R5, asking to add a string Container Lot Number to Medication.Batch. The requested value identifies the container's manufacturing lot and is distinct from the drug product batch/lot number. The approved resolution was to create a core extension rather than add a base Medication element.

Initial application:
No source commit was found whose message explicitly names FHIR-29570. Git history shows the request was nevertheless applied in the Medication manufacturing-batch extension family: commit 5faa63a834 added manufacturingBatch.container.lotNumber and its definition to source/medication/medication-extensions-spreadsheet.xml, commit 33b409a4b6 generated source/medication/structuredefinition-extension-medication-manufacturingBatch.xml with container.lotNumber as a string sub-extension, and commit dd468d4f17 later removed that core extension source when R5 extensions were moved out of this repository. The Extension Pack imported the same extension in commit 4087c90 and retained the differential after snapshot cleanup in 51879de.

Additional context:
Medication remains an active core resource, but the current core source maps the historical Medication.batch path to Medication.instance and no longer owns the medication-manufacturingBatch StructureDefinition except for its OID registry entry. The same extension now lives in the FHIR Extension Pack, whose input/definitions/multiple/StructureDefinition-medication-manufacturingBatch.xml applies to Medication.batch and defines Extension.extension:container.extension:lotNumber with the exact requested manufacturing-lot definition and a string value. Pharmacy minutes for 2020-11-09 record the PQ/CMC manufacturing discussion and the 9-0-0 carried block vote, including FHIR-29570, to add a core extension. A 2022 Zulip thread discussed using this standard extension in a PQ/CMC profile and exposed an old generated max=0 issue in the nested container extension; the current Extension Pack differential no longer carries that conflicting generated snapshot content. No later conflicting community decision was found.

AutoFHIR reconciliation:
This commit intentionally makes no source change in HL7/fhir. The current core checkout does not own the extension definition, and the external Extension Pack source already carries the requested container lot number slice on the Medication manufacturing-batch extension.

Recommendation:
Keep this audit commit as an external-repo decision. No core FHIR source change is recommended; any future content correction to medication-manufacturingBatch should be made in HL7/fhir-extensions rather than reintroducing the extension source into core.
