FHIR-17634: Audit Practitioner deceased support

Issue request:
FHIR-17634 is a Published/Persuasive PA change request asking to add a Practitioner deceased indicator modeled like Patient.deceased[x], with 0..1 boolean/dateTime choices for verifying whether a prescription was validly issued. Its 2019 resolution said the deceased property would be added as a standard extension usable in earlier FHIR versions using the Patient pattern.

Initial application:
The issue was explicitly applied before this reconciliation by commit 353b3b965d8b2975d5ceaf02cee00c154daf1e38, which cites FHIR-17634 and FHIR-26590 and added Practitioner.deceased[x] plus Practitioner death-date and deceased search parameters to the build-scope Practitioner source. The application landed as a core Practitioner element rather than a separate standard extension.

Additional context:
FHIR-26590 later/pairwise requested the core Practitioner.deceased[x] element and search parameter directly, was Published/Persuasive for R5, and is already represented on the combined branch by 8fb6be07d335d4ca063d3cfdc7bbcaf502737d54. FHIR-37897 subsequently added the modifier flag and reason now present in the current source and is already represented by da24b911e6d9e7df6e38823d6a9b7e2f5924c941. FHIR-37902 resolved no-change on adding an unknown/code data type, supporting the current boolean/dateTime shape. Practitioner is active in source/fhir.ini, while no current Practitioner-deceased standard extension was found in the core extension/profile sources or the Extension Pack checkout.

AutoFHIR reconciliation:
No source change was made. The current active Practitioner StructureDefinition already contains Practitioner.deceased[x] as 0..1 boolean/dateTime, with isModifier=true and a historical-use modifier reason, and the Practitioner search parameter bundle contains the deceased and death-date search parameters. Given the later core-element decision in FHIR-26590, replacing or duplicating the current element with a standard extension would make the current build less consistent rather than more correct.

Recommendation:
Keep this empty audit commit as-is for FHIR-17634. No FHIR core follow-up is needed; if the work group still wants a separately maintained earlier-version standard extension, that should be handled as an Extension Pack/work-group follow-up rather than as a correction to the current core Practitioner resource.
