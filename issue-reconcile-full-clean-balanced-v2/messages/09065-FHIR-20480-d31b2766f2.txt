FHIR-20480: Audit external validator year warning

Issue request:
FHIR-20480 was a Published FHIR-core change request, resolved Persuasive with Modification, asking to remove the Java InstanceValidator yearIsValid() rejection of years outside 1800..2100 because the FHIR date/dateTime/instant regexes do not impose that range. The approved resolution kept the validation but changed the result from an error to a warning.

Initial application:
The Jira comments report that Grahame Grieve committed the change to the then-separate org.hl7.fhir.core validator repository. The linked commit 0477bf174e44583ea4c227ad9d37756789ccba9c changes InstanceValidator dateTime, date, and instant checks from rule(...) errors to warning(...) diagnostics with reasonable-year wording. The current HL7/fhir source checkout has no Java source files and no yearIsValid/current-year diagnostic text to update.

Additional context:
The Zulip thread and FHIR-I minutes from 2019-03-04 match the Jira decision: unusually old or future dates can be suspicious but are not necessarily invalid, so they should warn rather than fail validation. The current org.hl7.fhir.core validator source still reports the reasonable-year check through warning(...), while the current FHIR spec source contains the date primitive definitions but not the Java validator implementation.

AutoFHIR reconciliation:
This commit intentionally makes no source change in HL7/fhir. The issue was already applied in the external validator implementation repository, and the current FHIR spec checkout does not own the InstanceValidator code or any conflicting normative year-range prose.

Recommendation:
Keep this audit commit as-is. Future changes to the reasonable-year diagnostic should be made in org.hl7.fhir.core/validator code; a new FHIR-core tracker would be needed only if the work group wants normative date guidance added to the specification itself.
