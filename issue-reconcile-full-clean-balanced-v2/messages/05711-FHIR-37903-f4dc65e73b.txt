FHIR-37903: Audit modifier extension clarification

Issue request:
FHIR-37903 was a Published/Persuasive FHIR-core clarification asking that modifier-extension guidance be easier to find: add a worked modifier-extension definition example, state that root isModifier=true makes an extension a modifierExtension while root isModifier=false uses extension, note the internal-extension exception, update defining-extensions ElementDefinition guidance, update ElementDefinition.isModifier text, and identify modifier extensions in the registry.

Initial application:
The issue was applied before this reconciliation by d461d9831352eb489c8c77466208c8c7399c21e1, which added the modifier-extension definition example to source/extensibility-examples.html, added the extension/modifierExtension if-and-only-if rule and internal-extension exception to source/extensibility.html, added IsModifier guidance and must-support discouragement to source/defining-extensions.html, and updated source/datatypes/elementdefinition.xml so generated ElementDefinition.isModifier details say that root isModifier identifies modifier extensions. The same historical commit also contained an unrelated OperationDefinition expression cleanup, but the current seed-relevant source remains present.

Additional context:
FHIR-36738 was an earlier Published clarification in the same change family that asked how to define a modifier extension; its requested sentence is present on the extensibility page and is consistent with FHIR-37903. FHIR-40769 later added a conformance-rules cross-reference to the ElementDefinition.isModifier comments. After FHIR-37903, commit 4118eb9ddb6eabe52c56c903b3932f27c2c42e38 removed source/extensibility-registry.html and related core extension pages because the content moved to the FHIR Extension Pack; publish.ini now keeps extensibility-registry.html commented out. The current build.fhir.org core extensibility-registry URL returns 404, while the Extension Pack registry page is live and marks modifier extensions with an “M” in the Card. column and a legend explaining that “M” means the extension is a modifier extension.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active core source already conveys the requested modifier-extension rules in the relevant build-scoped pages and ElementDefinition source, and the registry portion no longer has an active core source file to edit. The current external registry presentation satisfies the implementer-facing need to identify modifier extensions even though it is not a literal separate column.

Recommendation:
Keep this no-change audit as-is for core. If the work group still wants a literal separate registry column rather than the current Card. “M” marker, that should be handled as a new FHIR Extension Pack publishing/generator request, not as a core-source correction for FHIR-37903.
