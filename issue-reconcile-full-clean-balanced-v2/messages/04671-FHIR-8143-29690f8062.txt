FHIR-8143: Audit repeat count original-fill clarification

Issue request:
FHIR-8143 was a Published/Persuasive FHIR-core Pharmacy issue raised against DSTU1 MedicationPrescription.dispense.numberOfRepeatsAllowed. It asked whether the repeat count includes the original order dispense, and the accepted resolution was to define the element as additional repeats/refills only, explicitly not including the original order dispense, with the 30 tablets plus "3 repeats" equals 4 total dispenses example.

Initial application:
The issue was applied by git-svn commit d6a8c1cff53246b94cce2d0ba943b68db8e20b0a, which changed the then-current MedicationOrder spreadsheet definition from a total-fill-style usage note to the accepted "additional times" wording. MedicationPrescription had already been renamed to MedicationOrder by #7224/#5896, and MedicationOrder was later renamed to active MedicationRequest by commit 7387b2894c026dce7c36229cd84b90e883d6e5cb.

Additional context:
MedicationRequest is the current active build-scope resource in source/fhir.ini. The active source/medicationrequest/structuredefinition-MedicationRequest.xml definition for MedicationRequest.dispenseRequest.numberOfRepeatsAllowed still says the number is in addition to the original dispense, does not include the original order dispense, and gives the 30 tablets plus 3 repeats equals 4 total dispenses example. FHIR-10096 later corrected the display comment for the same element; FHIR-13182 later changed the datatype to unsignedInt and added zero-refill guidance and is already represented on the combined branch; FHIR-14565 later left the element name unchanged.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because the authoritative current source already preserves the FHIR-8143 rule and no stale current-source wording was found that says numberOfRepeatsAllowed includes the initial standard fill.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is recommended for FHIR-8143; any future Pharmacy discussion should treat the current element as counting additional authorized repeats/refills, not the original dispense.
