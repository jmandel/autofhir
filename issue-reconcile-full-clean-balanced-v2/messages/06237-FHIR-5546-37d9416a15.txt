FHIR-5546: Audit Condition timing clarification

Issue request:
FHIR-5546 was a Published/Persuasive with Modification DSTU1 Patient Care change request asking whether Condition represented a point-in-time event or a longer-lived problem-list concern, and proposing a separate Concern resource if needed. The final recorded motions called for analysis of the Condition-vs-concern distinction and clarification that Condition could be used as a point-in-time observation of a condition event.

Initial application:
No source commit was found that explicitly names FHIR-5546. The Jira comments record that Condition scope/introduction changes were applied based on GF#10090, and git history shows df58ee3f55 applying "#10090 Condition Introduction updates" to the active Condition introduction. That commit changed the Scope and Usage text to say Condition records a condition, problem, diagnosis, event, issue, or clinical concept that has risen to a level of concern, including a point-in-time diagnosis, a practitioner Problem List item, or a concern outside the Problem List.

Additional context:
FHIR-10090 is a Published/Persuasive same-artifact decision to broaden the Condition introduction beyond clinician-only and disease-only wording, including patient concern statements and cases without stakeholder consensus. FHIR-10614 was closed as duplicate with FHIR-10090 identified as the issue that would review/expand the Condition introduction. Later Published Condition clarifications such as FHIR-26904 and FHIR-38954 preserved the same model: Condition can represent problem/concern-list items, while also clarifying Observation boundaries and that a Condition is an instance, not a categorical patient state. Direct Zulip and Confluence issue-key searches found no conflicting community record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active Condition source already contains the needed timing/scope clarification: it explicitly includes point-in-time diagnoses, Problem List items, and concerns, and the later boundary text explains when symptoms should remain Observations. Changing the source to make Condition only a point-in-time event would contradict the applied FHIR-10090 text and later published Condition decisions.

Recommendation:
Keep this audit commit as-is. No current core source follow-up is recommended for FHIR-5546 unless Patient Care reopens the broader Condition/Concern modeling question in a new tracker.
