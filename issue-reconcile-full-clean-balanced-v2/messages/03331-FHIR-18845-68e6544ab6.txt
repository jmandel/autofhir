FHIR-18845: Audit ComputablePlanDefinition profile disposition

Issue request:
FHIR-18845 was Published/Persuasive for STU3 and asked core FHIR to define a ComputablePlanDefinition profile on PlanDefinition, requiring PlanDefinition.library to be 1..1 so a CQL engine has a principal library to load and limiting expressions to names defined in that specified library.

Initial application:
The issue was applied by commit 35c37212b7 ("GF#18845: Added ComputablePlanDefinition and CQLLibrary profiles"), which added the PlanDefinition computable spreadsheet source and related CQL Library profile source. Historical generated/release artifacts carried StructureDefinition/computableplandefinition, and the pre-FHIR-48393 source constrained PlanDefinition.library to 1..1 with the requested single-library semantics.

Additional context:
The current R6 source no longer contains StructureDefinition/computableplandefinition, PlanDefinition profile introduction files, or PlanDefinition profile pack entries. That absence is intentional: FHIR-48393 was Applied/Persuasive to remove these base-spec CDS profiles, explicitly listing ComputablePlanDefinition as already moved to CRMI. CDS/CQI meeting evidence records a 17-0-0 motion to move ComputablePlanDefinition and related profiles out of base, and current Clinical Reasoning/Shareable pattern guidance directs applications to CRMI for Shareable, Publishable, Computable, and Executable profiles. The CRMI repository contains a crmi-computableplandefinition source file with the same 1..1 library constraint under its unused resources area, so any remaining activation or publication work belongs in CRMI rather than core FHIR.

AutoFHIR reconciliation:
No source change was made. Recreating ComputablePlanDefinition in core would reverse the later applied FHIR-48393 removal decision and conflict with the current build scope, where PlanDefinition remains active but its old core profile pack is intentionally empty. The remaining OID entry is historical identifier metadata and does not make the removed profile part of the current build.

Recommendation:
Keep this audit commit as-is. Do not restore the old core ComputablePlanDefinition profile; if the profile needs to be active or corrected going forward, handle that in the CRMI implementation guide or through a new CDS/FMG decision that explicitly brings the matured profiles back into core.
