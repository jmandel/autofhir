FHIR-22689: Clarify PaymentReconciliation requestor

Issue request:
FHIR-22689 is Applied/Persuasive for R5. It asked FM to clarify the confusing Claim.provider description so implementers would understand the field as the billing provider/accountable party rather than necessarily the rendering or servicing provider. The resolution directed the same provider/requestor comment update across Claim, ClaimResponse, ExplanationOfBenefit, CoverageEligibilityRequest, CoverageEligibilityResponse, and PaymentReconciliation.

Initial application:
The historical FHIR-22689 application commit 7af5ba658c1a44e83e5feb8bba39498da34bba3a updated Claim.provider, ClaimResponse.requestor, CoverageEligibilityRequest.provider, and ExplanationOfBenefit.provider, but it did not touch PaymentReconciliation.requestor. CoverageEligibilityResponse.requestor was later completed by FHIR-40940 and the combined-branch FHIR-40940 reconciliation commit. PaymentReconciliation.requestor still carried the old rendering/servicing-provider definition.

Additional context:
PaymentReconciliation is an active current resource in source/fhir.ini. Older requestor naming issues, including FHIR-17996, show that PaymentReconciliation.requestor replaced requestProvider for the provider/payee-side party, and the current PaymentReconciliation requestor search parameter describes "the provider who submitted the claim." Later FHIR-20171 and FHIR-37906 removed the cardinality lead-in from the FHIR-22689 comment family, so this reconciliation uses the current trimmed accountable-data-content and Billing Provider wording. FHIR-26601 later expanded PaymentReconciliation to patient-payment use cases, but it did not redefine requestor and does not support leaving requestor described as the practitioner responsible for services rendered.

AutoFHIR reconciliation:
This commit updates the build-scope PaymentReconciliation StructureDefinition so requestor is the party/provider responsible for the request and carries the FHIR-22689 Billing Provider/accountable-data-content comment. It also updates the checked-in PaymentReconciliation SVG tooltip for the same element so the diagram does not continue to show the stale services-rendered definition.

Recommendation:
Keep this source fix. It completes the one remaining current-source omission from FHIR-22689 while preserving later FHIR-20171/FHIR-37906 wording cleanup and avoiding duplicate decisions for FHIR-40940, FHIR-20171, or FHIR-37906.
