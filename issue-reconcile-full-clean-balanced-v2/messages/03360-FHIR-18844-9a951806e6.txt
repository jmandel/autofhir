FHIR-18844: Audit CDS Hooks Clinical Reasoning guidance

Issue request:
FHIR-18844 was Published/Persuasive with Modification for STU3 and asked for implementation-guide-style documentation for using logical reasoning resources with CDS Hooks and CQL-based reasoning engines. The accepted resolution was to expand Clinical Reasoning documentation for PlanDefinitions computable using CQL libraries to support CDS Hooks service evaluation, referring to the CDSHooksPlanDefinition and ComputablePlanDefinition profiles while making clear that ComputablePlanDefinition is an orthogonal concern rather than a prerequisite.

Initial application:
The issue was originally applied in core by Jira-tagged commits 1c7aa38e3e and 60a763e7ca. Those changes expanded source/clinicalreasoning-cds-on-fhir.html with CDS Hooks service/PlanDefinition mapping guidance and links to the then-core CDS Hooks service and Computable PlanDefinition profiles.

Additional context:
The current R6 source is shaped by later applied CDS decisions. FHIR-53085 moved most CDS-on-FHIR page content, CDS Hooks PlanDefinition/RequestOrchestration profiles, and supporting concept maps to the Using FHIR Clinical Reasoning with CDS Hooks IG, leaving the active core CDS-on-FHIR page informative and linking to that IG. FHIR-48393 and the related FHIR-18845 audit establish that ComputablePlanDefinition and other computable/shareable/publishable profiles have moved out of base FHIR, with applications directed to CRMI for those patterns. The active Clinical Reasoning module still links to the CDS-on-FHIR page and lists the CDS Hooks Clinical Reasoning IG, while current source contains no active core CDSHooksServicePlanDefinition or ComputablePlanDefinition profile source apart from historical OID metadata.

AutoFHIR reconciliation:
No source change was made. Restoring the old local profile references or duplicating detailed CDS Hooks/CQL mapping prose in core would conflict with later applied decisions that moved that material to maintained IGs. The current core source already gives implementers the correct high-level PlanDefinition/$apply and CDS Hooks relationship and points to the IG that now owns the detailed conformance and mapping guidance.

Recommendation:
Keep this audit commit as-is. Do not recreate the old CDS Hooks or ComputablePlanDefinition profile guidance in core; future corrections should update the Using FHIR Clinical Reasoning with CDS Hooks IG or CRMI unless a new CDS/FM group decision explicitly brings that content back into the base specification.
