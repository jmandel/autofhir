FHIR-6233: Audit AuditEvent network address rename

Issue request:
FHIR-6233 was a Published Security WG change request for DSTU1. It reported confusion in AuditEvent because participant.network.identifier was a string, not an Identifier, and asked to rename AuditEvent.participant.network.identifier to address; the issue also noted that any search for this value should be string, not token. The accepted resolution was: AuditEvent.participant.network.identifier --> address.

Initial application:
The issue appears to have been applied in git commit 8e1a48066d70501f76de61f4511ec19b48da2df2, whose message lists item 6233 and whose AuditEvent spreadsheet/examples patch renamed AuditEvent.participant.network.identifier to AuditEvent.participant.network.address. Later AuditEvent refactoring moved participant to agent, and a subsequent security block vote commit replaced the network backbone (including address/type children) with AuditEvent.agent.network[x].

Additional context:
AuditEvent is active in source/fhir.ini, so source/auditevent/structuredefinition-AuditEvent.xml and source/auditevent/bundle-AuditEvent-search-params.xml are current build inputs. Current source has AuditEvent.agent.network[x] as Reference(Endpoint), uri, or string, with fhir.ini conversion notes mapping the old AuditEvent.agent.network.address/type children to network[x]. The current AuditEvent search parameter bundle contains no network/address search parameter, so there is no lingering token search for the old string value. Zulip and Confluence searches for FHIR-6233 plus AuditEvent did not find conflicting community evidence.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current specification no longer exposes an element named participant.network.identifier or agent.network.identifier, and it does not define the problematic token search parameter. The remaining checked-in DICOM ATNA test XML uses DICOM NetworkAccessPointID attributes, not FHIR element names, and does not reintroduce the issue.

Recommendation:
Keep this empty audit commit as-is. No follow-up core source work is needed for FHIR-6233 unless a future work group decision wants to add a new, explicitly specified AuditEvent network search parameter.
