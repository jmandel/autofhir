FHIR-14179: Audit GuidanceResponse deprecation reversal

Issue request:
FHIR-14179 was a Published/Persuasive STU3 CDS change request asking that GuidanceResponse not be deprecated because implementers needed it for persistent decision-support request/response records, additional DataRequirement prompts, RequestGroup/request orchestration results, CDS Hooks-related response recording, and profile/extension-based implementation guidance. The approved resolution was to reverse deprecation and continue evolving GuidanceResponse with input from CDS Hooks and Clinical Quality Improvement communities.

Initial application:
The issue appears to have been applied in git-svn commit 43553fde72d177e29e7f8406bb14a3eaf6c4af77, which matches the Jira comment "SVN 13324" and added GuidanceResponse scope/use-case documentation plus a purpose statement. That commit did not remove a current source deprecation flag because no GuidanceResponse deprecation marker is present in the current source history inspected here; instead it documented ongoing use cases and retained the resource.

Additional context:
GuidanceResponse remains in the current build: source/fhir.ini actively lists it as a resource owned by CDS, patient security category, FMM 4, and approved status. The current StructureDefinition marks it normative/FMM 4, describes it as the formal response to a guidance request, and says its purpose includes recording decision-support interactions, public-health reportability determinations, and additional data requirements. Later source history refined but did not reverse the decision: FHIR-16941 clarified persistence usage and then removed a temporary ballot note, FHIR-15925 added an additional-data GuidanceResponse example, FHIR-30798 matured the resource and mappings, and FHIR-53085 redirected detailed CDS Hooks discussion to the external Clinical Reasoning with CDS Hooks IG while preserving the GuidanceResponse use-case reference.
