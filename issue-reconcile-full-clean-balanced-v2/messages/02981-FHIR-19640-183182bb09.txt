FHIR-19640: Audit MedicationRequest informationSource

Issue request:
FHIR-19640 was a Published Pharmacy change request, resolved Persuasive with Modification for R5, asking to add MedicationRequest.informationSource back as a standalone element for the source of information when different from the requester. The request also replaced the prior reported[x] reference choice with a standalone reporting boolean and said the missing/default reporting value should be false.

Initial application:
The issue appears to have been initially applied in commit cdb9b154325715da80c5913ec7939955b7d52105, merged by ec284380a4c273eeee93dc77e0ead3366dddec01. That commit changed the then-authoritative MedicationRequest spreadsheet from reported[x] boolean|Reference to a boolean reported element and added MedicationRequest.informationSource as 0..1 Reference(Patient, Practitioner, PractitionerRole, RelatedPerson, Organization) with the requested reporter/source wording.

Additional context:
MedicationRequest is an active resource in source/fhir.ini, and the current authoritative source is source/medicationrequest/structuredefinition-MedicationRequest.xml. Current source defines MedicationRequest.informationSource with the original target profiles, plus Group from later Applied issue FHIR-41408, and with cardinality 0..* from later Published issue FHIR-35847. Later Applied issue FHIR-47855 clarified that informationSource is the reporter of the MedicationRequest rather than the original requester. The current reporting boolean is MedicationRequest.isRecordOfRequest after the later FHIR-49863 rename, and the missing-value/default-false semantics are already encoded by the existing FHIR-34195 reconciliation commit on the combined branch.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current build input already contains the informationSource element requested by FHIR-19640, the obsolete reportedReference/reported[x] reference choice is absent, and later decisions explain why the current cardinality, target list, wording, and reporting element name no longer exactly match the 2019 request text.

Recommendation:
Keep this no-change audit commit. Do not narrow MedicationRequest.informationSource back to 0..1 or remove Group as part of FHIR-19640; those differences reflect later Jira decisions. Any remaining questions about isRecordOfRequest modifier behavior belong with FHIR-49863 or a future Pharmacy WG decision, not this seed.
