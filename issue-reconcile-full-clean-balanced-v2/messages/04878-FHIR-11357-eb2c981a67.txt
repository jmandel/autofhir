FHIR-11357: Audit CarePlan activity code binding

Issue request:
FHIR-11357 was Published with a Persuasive with Modification resolution for DSTU2 CarePlan. It asked that CarePlan.activity.detail.code stop wrapping the SNOMED procedure hierarchy in http://hl7.org/fhir/ValueSet/care-plan-activity and instead bind to the shared Procedure.code value set at http://hl7.org/fhir/ValueSet/procedure-code; the Procedure.code value set itself was to remain unchanged absent a confirmed SNOMED IP problem.

Initial application:
The request was applied by the April 2017 #11357 source commit, which changed the CarePlanActivityType binding in the CarePlan authoring spreadsheet from valueset-care-plan-activity to http://hl7.org/fhir/ValueSet/procedure-code. Subsequent source refactors regenerated the current StructureDefinition, where the active CarePlan element now carries that procedure-code binding.

Additional context:
CarePlan is an active resource in source/fhir.ini. A later J#26064 CarePlan refactor renamed CarePlan.activity.detail to CarePlan.activity.plannedActivityDetail, so the current element to inspect is CarePlan.activity.plannedActivityDetail.code. The old care-plan-activity value set source still exists as a standalone terminology artifact, but searches of the authoritative CarePlan StructureDefinition show that the planned activity code binding no longer points to that wrapper. No direct Zulip or Confluence evidence was found that conflicts with the Jira/source/git conclusion.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because the current active CarePlan source already implements the requested shared Procedure code binding.

Recommendation:
Keep this audit commit as-is. Do not remove or rewrite the standalone care-plan-activity value set as part of FHIR-11357; any future lifecycle cleanup for that terminology artifact should be handled as a separate Patient Care or terminology decision.
