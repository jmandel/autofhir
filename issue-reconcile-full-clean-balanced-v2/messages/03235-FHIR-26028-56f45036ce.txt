FHIR-26028: Restore preferred maximum binding wording

Issue request:
FHIR-26028 was a Published Vocab change request, resolved Persuasive with Modification, asking the core terminology page to clarify that rendered binding language such as "but limited to" represents a maximum value set declared with the maxValueSet extension.

Initial application:
The issue was initially applied in git commit 633035c38a, which moved Binding Strengths under Controlling the use of Coded Values and added a Max Value Set subsection describing maxValueSet for extensible or preferred bindings. FHIR-22794 later refined that text in ab0ada5222. Subsequent ElementDefinition/additional-binding refactors moved the explanation into the additional binding purpose table.

Additional context:
The 2020 Vocab WGM minutes and originating Zulip discussion both show that the confusing example was a preferred binding limited by a maximum value set. Later FHIR-46350, FHIR-43156, and FHIR-46445 deprecated the maximum additional-binding purpose and the maxValueSet extension in favor of required/additionalBinding semantics, but the current Additional Binding Purpose CodeSystem still defines maximum as a required binding for use when the base binding strength is extensible or preferred. A 2025 terminology-page consolidation left the table saying only extensible, which lost the preferred-binding half of the original clarification.

AutoFHIR reconciliation:
Updated source/terminologies.html, a published terminology page listed in publish.ini, so the maximum additional-binding table row again covers main bindings with strength extensible or preferred while preserving the current R5+ note that maximum replaces the deprecated maxValueSet extension and is equivalent to required.

Recommendation:
Keep this source fix. It restores consistency between the terminology narrative, the Additional Binding Purpose CodeSystem, and the original FHIR-26028/FHIR-22794 wording without reviving the removed standalone maxValueSet section or changing the later deprecation policy.
