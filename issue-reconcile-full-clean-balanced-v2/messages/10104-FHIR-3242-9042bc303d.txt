FHIR-3242: Audit historical message event code system fix

Issue request:
FHIR-3242 is Published/Persuasive. It asked to correct the old messaging Event List text for the message.code element so the listed event code system/value set reference used http://hl7.org/fhir/message-events instead of the incorrect message-type URL.

Initial application:
The issue was applied in git-svn commit 1c347e99ed491e716c37bbe11acee18e0b24b534, matching Jira's svn revision 3056 comment. That commit changed source/messaging.html from http://hl7.org/fhir/message-type to a link to http://hl7.org/fhir/message-events in the then-current message.code Event List prose.

Additional context:
The current build no longer has that DSTU1 Event List model: messaging.html now describes MessageHeader.event[x] and says this specification does not define events, while the active MessageHeader source is in source/fhir.ini and its event binding is an example binding with descriptive text and no ValueSet/message-events reference. Later Published issue FHIR-26902, already represented on the combined branch, decided to delete the empty MessageEvent code system/value set and remove its references; duplicate FHIR-34080 records the same intent. FHIR-43807 and FHIR-57214 discuss possible future v2 event-code binding work, but they are not final Applied/Published scope for this seed decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Restoring http://hl7.org/fhir/message-events for FHIR-3242 would reintroduce a retired current-core value set and conflict with FHIR-26902; the historical correction was applied in 2014 and the current source is correct for this issue family.

Recommendation:
Keep this audit commit as-is for FHIR-3242. Any future change to bind MessageHeader.event[x] or MessageDefinition.event[x] to v2 event codes should be handled under FHIR-43807/FHIR-57214 or another current InM decision, not by reopening this DSTU1 Event List correction.
