FHIR-32488: Audit MedicationRequest performer role value set

Issue request:
FHIR-32488 was Published/Persuasive for R5 and asked Pharmacy to replace the unrealistic, broad performer-role value set used by MedicationPrescription/MedicationRequest with a small exemplar list of roles that might realistically be requested for drug administration, such as Registered Nurse, Oncology Nurse, Pain Control Nurse, Physician, and Pharmacist.

Initial application:
The issue was applied before this reconciliation. Commit 3eb5717 changed MedicationRequest.performerType from an example binding to the broad http://hl7.org/fhir/ValueSet/performer-role to an extensible binding to http://hl7.org/fhir/ValueSet/medication-intended-performer-role, and commit bd922b20 added the dedicated Medication Intended Performer Role value set and code system containing the five exemplar role codes named in the Jira resolution. Later terminology/OID cleanup commits changed metadata but retained the binding and exemplar content.

Additional context:
MedicationRequest is an active build resource in source/fhir.ini. The current StructureDefinition still binds MedicationRequest.performerType to medication-intended-performer-role, and the current code system expands only registerednurse, oncologynurse, paincontrolnurse, physician, and pharmacist. Pharmacy WGM minutes from May 2021 confirm the motion to accept FHIR-32488 and create a subset with a few nurse types, physician, and pharmacist. No Zulip discussion or final later Jira decision was found that reverses the value set content; FHIR-55335 is a later Triaged/Unresolved THO-migration consideration, not an applied content change.

AutoFHIR reconciliation:
This commit intentionally makes no source change because the current authoritative source already implements the requested performer-role subset for MedicationRequest.performerType.

Recommendation:
Keep this audit commit as-is for FHIR-32488. Handle any future THO migration or reuse cleanup under FHIR-55335 or another final terminology-management decision rather than changing this already-correct R5 application.
