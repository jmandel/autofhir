FHIR-34120: Audit $translate dependency parameter

Issue request:
FHIR-34120 was Published/Persuasive for R5. It asked to change the ConceptMap $translate input parameter from dependency.concept with type CodeableConcept to dependency.value with allowed Element value types matching the then-current FHIR-28284 ConceptMap dependsOn.value[x] model.

Initial application:
The issue was initially applied in commit 76d47fab4b990e9c6b97d9f26b97ee57126df137 on the old source/conceptmap2 OperationDefinition and examples, then merged by fbcc847ae2d73cbc1f4065b84d70555927ad3b6c. Later ConceptMap2-to-ConceptMap refactoring and OperationDefinition allowedType syntax updates carried the input parameter forward into the current source.

Additional context:
ConceptMap is in the active build scope through source/fhir.ini. The current source/conceptmap/operationdefinition-ConceptMap-translate.xml already defines the input as dependency.value with type Element. Its allowed types are code, Coding, string, boolean, and Quantity, which intentionally differs from the original FHIR-34120 list because later Published issue FHIR-40504 revised the ConceptMap additionalAttribute/dependsOn/product model; the current ConceptMap.group.element.target.dependsOn.value[x] source uses the same type set. Confluence Vocab minutes from 2021-11-08 record the original FHIR-28284/FHIR-30515/FHIR-34120 application as completed. No Zulip evidence was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This empty audit commit makes no source change. Restoring the original integer/dateTime/decimal/uri/id list on the input parameter would now conflict with the later current ConceptMap model, and the seed request is already satisfied by the current input parameter name and shape.

Recommendation:
Keep this audit commit as-is for FHIR-34120. Any remaining concern about $translate output dependsOn/product allowed types should be reviewed under the output-specific or later ConceptMap issues rather than by changing the FHIR-34120 input parameter.
