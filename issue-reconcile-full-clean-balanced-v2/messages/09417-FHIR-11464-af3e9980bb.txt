FHIR-11464: Audit DataElement maturity correction

Issue request:
FHIR-11464 was a Published/Persuasive FHIR-core conformance-module ballot correction for DSTU2. It said the conformance roadmap should not characterize DataElement as mature because DataElement had not been well tested and SDC had not rigorously exercised it.

Initial application:
The Jira comments cite svn revision 10271. In git history, ba8eb01c7c39e3343c75d60fbb0ecffce7630d10 is the matching git-svn commit: it removed DataElement from the mature conformance-resource list in source/conformance-module.html and added DataElement to the still-under-development list with the note that the exact role of data element definitions was still being studied.

Additional context:
Later Published issue FHIR-13094 resolved to collapse DataElement into StructureDefinition logical models. Historical commit d0802c9b75a4705416fe7f8c601c46dfa2ed8892 removed DataElement references from the conformance module, and the current combined branch already contains c1a07840fdc89786d1b71cdd5f635e9032155d72 for FHIR-13094, which completes active DataElement cleanup. In the latest combined source, source/conformance-module.html no longer lists or discusses DataElement in the roadmap, and source/fhir.ini keeps DataElement commented out rather than active in the resource/work-group/TLA build lists. A 2020 implementers Zulip thread also points to FHIR-13094 as the DataElement removal and explains the current interpretation in terms of logical models or element references.

AutoFHIR reconciliation:
No source change was made. The original maturity correction is already applied, the current conformance roadmap no longer contains the challenged maturity claim, and DataElement is no longer an active current-build resource. Reintroducing a local DataElement maturity note would be stale after the later DataElement-to-StructureDefinition decision.

Recommendation:
Keep this no-change audit commit as-is. No FHIR-core follow-up is needed for FHIR-11464; any future guidance about data elements should remain aligned with StructureDefinition logical-model guidance rather than the retired DataElement resource.
