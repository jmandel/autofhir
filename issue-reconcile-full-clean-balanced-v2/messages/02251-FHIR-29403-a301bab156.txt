FHIR-29403: Audit Library profile replacement

Issue request:
FHIR-29403 was a Published CDS change request for R5, resolved Persuasive with Modification, asking core to replace the older CQL Library profile approach with SDC/CPG-style Library profiles: add knowledgeCapability and knowledgeRepresentationLevel to ShareableLibrary, add Computable/Publishable/Executable Library profiles, allow FHIRPath and x-fhir-query content slices on ComputableLibrary, require equivalent meaning across CQL/FHIRPath/xFHIRQuery content, and keep individual FHIRPath/xFHIRQuery expression references out of scope.

Initial application:
No current git commit explicitly tagged FHIR-29403 was found. Nearby R5 history shows the Library profile work was applied through related Jira-numbered commits: bd5308f495 added shareable/publishable/CQL/ELM/Logic/ModelInfo/ModuleDefinition/FHIRPath Library profile source plus knowledge capability/representation terminology, and d0df1250f1 corrected the FHIRPath Library content cardinality to 0..*. That profile source later existed in source/library as active Library packs before being removed.

Additional context:
FHIR-48393 was later Applied for R6 with a CDS vote to remove resource profiles from the base specification, explicitly listing CQLLibrary, ELMLibrary, LogicLibrary, ModelInfoLibrary, FHIRPathLibrary, ModuleDefinitionLibrary, PublishableLibrary, and ShareableLibrary as already moved to Using CQL with FHIR or CRMI. Commit 571498e2b2 removed the Library profile source and emptied source/library/list-Library-packs.xml. The active R6 source now keeps Shareable and Publishable only as logical patterns in source/fhir.ini and points applications to the CRMI profiles.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Reintroducing or editing the Library profiles in core would conflict with the later FHIR-48393 decision and the current active source already tells implementers to use CRMI for the Shareable, Publishable, Computable, and Executable profiles.

Recommendation:
Keep this no-change audit as-is for core. If future work is needed, it belongs in CRMI or Using CQL with FHIR rather than in the base FHIR checkout, unless a new work-group decision reverses FHIR-48393.
