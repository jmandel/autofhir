FHIR-8244: Audit Timing.code abbreviation additions

Issue request:
FHIR-8244 was a Published/Persuasive with Modification DSTU1 MnM change request for the Data Types Timing.code value set. The final recorded resolution was to add qh, q4h, q6h, and qod, after comments noted common medication timing abbreviations such as qd, qh, q4h, q6h, qid, and qod while also noting that the value set is extensible.

Initial application:
The Jira application comment cites svn revision 6123. In the git mirror, commit 6e45ed2fb4d013f7f2498db5672be81c5b632ecc, "#8244 - new codes in Timing.code + generate data elements," applied the issue to source/datatypes/timing.xml by adding QD, QOD, Q4H, and Q6H rows to the TimingAbbreviation sheet and by updating the Timing.code short display. The historical hunk did not add a literal qh/QH row, but the current value set now contains Q1H for every hour through the later FHIR-13520 timing-abbreviation decision.

Additional context:
source/fhir.ini actively lists Timing as a datatype, so source/datatypes/timing.xml and the related datatype narrative are current build inputs. Later datatype terminology migration work represented by FHIR-9239 moved the seed-era TimingAbbreviation rows to http://terminology.hl7.org/CodeSystem/v3-GTSAbbreviation. FHIR-13520, already represented on the combined branch, added Q1H and other common timing abbreviations and explicitly noted that QD and QOD were already supported. FHIR-20609, also already represented, later added C/Continuous to the same value set. Community searches found no Zulip or Confluence evidence that changes the Jira/source conclusion.
