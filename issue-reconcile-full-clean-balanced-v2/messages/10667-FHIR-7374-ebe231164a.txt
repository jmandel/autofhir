FHIR-7374: Audit contained extension wording

Issue request:
FHIR-7374 was a Published/Persuasive FHIR-core change request for the Extensibility page, raised against DSTU1, asking to clarify wording that said the contained extension was defined separately. The approved correction was to make clear that the separately defined item was the additional nested extension field, not the whole containing extension.

Initial application:
The Jira comment says the change was applied as SVN revision 7374. In the git-svn history, commit 5a87e1cdb34dfa6ce424f5e9eec06c04936f50f4, "#7374 - clarify extension wording", replaced "In the second case, the contained extension is defined separately" with wording naming the nested "registrar" extension as the separately defined extension.

Additional context:
The current build includes source/extensibility.html through source/fhir.ini's type-page mapping for Extension. Later extensibility-page work replaced the old clinical-trial/registrar example with the current citizenship/passport-number example, but preserved the same distinction: complex extension content has local relative parts, while an additional nested extension can have its own canonical URL and definition. Searches of Zulip and Confluence found no community record contradicting the Jira/source history.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already says extensions can contain extensions either because the definition has complex content or because the extension is extended with an additional extension defined separately, and the nearby example identifies passport-number as the separately defined extension rather than treating the full citizenship extension as separately defined.

Recommendation:
Keep this audit commit as-is. No follow-up source edit is recommended for FHIR-7374 unless the work group wants a broader rewrite of the extensibility examples independent of this resolved clarification.
