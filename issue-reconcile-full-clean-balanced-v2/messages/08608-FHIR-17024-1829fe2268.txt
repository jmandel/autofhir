FHIR-17024: Clarify Binary encoding in FHIR formats

Issue request:
FHIR-17024 was a Published/Persuasive FHIR-core Binary correction raised against STU3. It asked to replace scope wording that said Binary resources could be represented "in XML or JSON" with wording covering XML, JSON, or other FHIR formats and clarifying that the content is represented as base64-encoded content.

Initial application:
The issue was initially applied by git-svn commit 2941d0f9788c72cfa11ca22a381c2157e87eef9f / svn 14347, which changed the Binary scope text from "XML or JSON" to "XML, JSON, of other formats" and fixed an unrelated punctuation typo. Later commit 7bf7397f4a965784698e0d343f8a96789cdf4942 corrected "of" to "or", leaving the all-formats part applied but still omitting the requested base64 clarification.

Additional context:
Binary remains an active current-build resource through source/fhir.ini, and source/binary/binary-introduction.xml feeds the built Binary narrative. The authoritative StructureDefinition already defines Binary.data as base64Binary with the definition "The actual content, base64 encoded," so the remaining gap was the scope prose not explicitly tying FHIR-format representations of Binary to that base64-encoded data element. Targeted Zulip and Confluence searches found no direct discussion or later decision that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit updates the active Binary scope prose to say that Binary resources can be represented in XML, JSON, or other formats as base64-encoded data, preserving the existing native REST-interface distinction and Bundle example while completing the applied Jira wording.

Recommendation:
Keep this source fix. It is a narrow correction to the current Binary narrative, aligns the scope text with Binary.data, and completes the originally published issue without introducing broader Binary behavior changes.
