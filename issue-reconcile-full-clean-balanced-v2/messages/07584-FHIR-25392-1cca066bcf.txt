FHIR-25392: Audit constraint.human markdown decision

Issue request:
FHIR-25392 is Published/Not Persuasive with Modification. The Jira asked to change ElementDefinition.constraint.human from string to markdown so rich text could be used in human-readable constraint messages, and to update the IG Publisher to render that field as markdown. The final decision rejected a core datatype change because constraint violation messages should remain plain strings in many contexts, and recommended using the existing rendering-markdown extension for a marked-up alternative.

Initial application:
No Jira-tagged FHIR-25392 source-changing commit was found in the core checkout. That is consistent with the resolution: the active ElementDefinition source still defines ElementDefinition.constraint.human as string, while the rendering-markdown extension exists as the optional rich-text mechanism and is now maintained in the FHIR Extension Pack.

Additional context:
FHIR-28141 later created an apparent conflict by referring to ElementDefinition.constraint.human in its resolution, but its Jira title/description asked about ElementDefinition.constraint.requirements. The Jira-tagged implementation commit a74d790b4480099fb9d8b68ad2df3bef4844d99b changed ElementDefinition.constraint.requirements, ElementDefinition.binding.description, and ElementDefinition.mapping.comment to markdown, not ElementDefinition.constraint.human. FHIR-I minutes on 2022-08-29 and the matching Zulip discussion concluded that FHIR-28141 had a resolution typo and that both FHIR-25392 and FHIR-28141 were already applied correctly. The combined branch already contains the no-change audit commit for FHIR-28141.

AutoFHIR reconciliation:
No source change was made. The active, normative ElementDefinition source in source/datatypes/elementdefinition.xml already keeps ElementDefinition.constraint.human as string, which matches the FHIR-25392 decision and the later FHIR-28141 clarification. The optional rendering-markdown extension applies to string elements and has a markdown value, so marked-up alternatives do not require changing the core datatype.

Recommendation:
Keep this audit commit as-is. Do not change ElementDefinition.constraint.human to markdown unless FHIR-I reopens and reverses the plain-string error-message decision; use the rendering-markdown extension for richer display, and track any remaining IG Publisher behavior in the IG Publisher repository rather than in core FHIR source.
