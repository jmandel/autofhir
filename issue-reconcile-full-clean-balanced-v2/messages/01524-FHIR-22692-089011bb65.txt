FHIR-22692: Audit language extension contexts

Issue request:
FHIR-22692 was a Published/Persuasive MnM change request raised against STU3 and applied for R5. It asked that the language extension at http://hl7.org/fhir/StructureDefinition/language be applicable in more places, with the final resolution to allow the extension on the string and markdown datatypes.

Initial application:
The issue was applied in core by ec83d5b5057f1402bdeb77453f5d214806de6b8c, a bundled MnM R5 non-substantive commit that changed the language extension row in source/profiles/general-extensions-spreadsheet.xml from HumanName;Address;Annotation to HumanName;Address;Annotation;string;markdown.

Additional context:
Core extension definitions were later split out of the FHIR core source. Commit dd468d4f1799dd79819315b211588ef1cf4586e0 removed the language extension row from the core general-extensions spreadsheet, while the FHIR Extension Pack first imported and still maintains input/definitions/datatypes/StructureDefinition-language.xml with contexts for HumanName, Address, Annotation, string, and markdown. Current core source only references the extension through the extension-pack location from source/languages.html and has no active language extension definition in source/fhir.ini profiles.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The current authoritative extension-pack source already carries the approved string and markdown contexts, and restoring or duplicating the extension definition in core would conflict with the current build ownership split.

Recommendation:
Keep this no-change audit as-is. If future language extension applicability changes are required, make them in the FHIR Extension Pack rather than in the core FHIR checkout; no follow-up is needed for FHIR-22692.
