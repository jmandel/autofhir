FHIR-7963: Audit Patient generalPractitioner rename

Issue request:
FHIR-7963 was a Published/Persuasive with Modification Patient Administration change request from the DSTU1 ballot asking that Patient.careProvider account for provider roles. The accepted disposition was not to add a type backbone to Patient, but to rename careProvider to generalPractitioner, keep the cardinality multiple, describe it as the gatekeeper/primary provider for the patient's care, point other role-based care providers toward CareTeam, and create preferred dentist/pharmacy-style extensions outside the core element.

Initial application:
The change was applied in git commit fb14d2fad1, which renamed Patient.careProvider to Patient.generalPractitioner in the Patient source, retained careProvider as an alias, updated the search parameter name, and updated nearby Patient guidance. That implementation commit also bundled unrelated Patient/RelatedPerson work for FHIR-9366 and FHIR-3408, so those trackers are not independently decided here.

Additional context:
Current source/fhir.ini lists Patient as an active resource, so source/patient/structuredefinition-Patient.xml is in the current build. The current Patient.generalPractitioner element is 0..*, has the short "Patient's nominated primary care provider", retains careProvider as an alias, explains that CareTeam should carry broader care team roles and history, and includes later FHIR-14224/FHIR-14442 changes adding PractitionerRole and multiplicity guidance. FHIR-14734 later rejected consolidation with CareTeam and explicitly confirmed that generalPractitioner is distinct from role-specific CareTeam members. The only current extension-pack evidence found for the extension part is patient-preferredPharmacy in the FHIR Extension Pack; no core source edit is appropriate merely to restate that external extension evidence or to create a new dentist extension without fresh work-group review.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The active current Patient source already preserves the approved semantic outcome for core: the old careProvider name is no longer the element name, the element is primary/general-practitioner focused rather than a general typed care-team member, role/history use cases are directed to CareTeam, and later source history addresses the PractitionerRole role-disambiguation concern.

Recommendation:
Keep this no-change audit as-is for FHIR core. If Patient Administration still wants a preferred dentist or pharmacist extension beyond the existing patient-preferredPharmacy extension, that should be raised and reviewed as FHIR Extension Pack work rather than patched into the core Patient element during this reconciliation.
