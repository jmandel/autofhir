FHIR-5758: Audit immunization program fields

Issue request:
FHIR-5758 was a Published / Persuasive with Modification DSTU1 ballot comment asking whether Immunization should support registry data for multiple birth indicator, birth order, mother's maiden name, vaccine program, and reason for non-compliance with a vaccine program. The final resolution recorded that items 1-3 belonged in Patient and that PHER would work out whether items 4-5 belonged in core or extensions.

Initial application:
The issue appears to have been applied in git commit 4c5a8902abffdfb5b6e9f07b4bca119d875dc64a, which added Immunization program eligibility and funding source content and examples for gForge item #5758. Public Health minutes from 2017-11-30 approved adding education and eligibility/funding source elements, and the 2018-01 WGM notes later recorded that the R4 changes handled items 4 and 5 from the original comment.

Additional context:
The current build includes Immunization and Patient as active resources in source/fhir.ini. Current Immunization source still carries committee notes for #5758 on programEligibility and fundingSource, while later FHIR-32397 refined programEligibility into a backbone with a required program and programStatus so eligibility is no longer under-specified. Patient.multipleBirth[x] covers both multiple-birth indication and birth order, and the standard patient-mothersMaidenName extension now lives in the FHIR Extension Pack rather than as a core StructureDefinition.

AutoFHIR reconciliation:
No source change was made. The current source already represents the accepted R4/R5+ outcome: Immunization records program eligibility and actual funding source, Patient covers multiple-birth identity data, and the mother's maiden name extension is defined outside the core checkout.

Recommendation:
Keep this audit commit as-is. Reopening FHIR-5758 is not recommended unless the Public Health work group wants a new substantive requirement for an explicit non-compliance reason element beyond the existing eligibility/status plus funding-source model.
