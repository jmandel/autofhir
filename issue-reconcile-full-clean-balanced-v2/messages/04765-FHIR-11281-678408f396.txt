FHIR-11281: Audit Condition status and body site guidance

Issue request:
FHIR-11281 was a Published/Persuasive with Modification DSTU2 Patient Care request for Condition. It asked to make Condition.verificationStatus optional with an unknown default, add explanatory verificationStatus comment text for cases such as abdominal pain in the ED, and add Condition.bodySite guidance that bodySite is used only when not implicit in Condition.code and that richer body-site attributes should use the then-current body-site-instance extension.

Initial application:
The issue was applied in git commit f6747b5dae067e2b72852f858c8004070b307fcd, which changed the old Condition spreadsheet source by setting Condition.verificationStatus from 1..1 to 0..1, adding the ED example comment and unknown default, adding GF#11281 committee notes, and adding the requested bodySite comment with the extension reference. The current source has since been converted to structuredefinition-Condition.xml, but the Condition resource remains active in source/fhir.ini and the current verificationStatus element still carries GF#11281 in committee notes with min 0 and max 1.

Additional context:
Later applied Condition decisions explain why the current text no longer literally matches every 2016 sentence. FHIR-16193 changed clinicalStatus and verificationStatus from code to CodeableConcept. FHIR-54914 explicitly replaced the verificationStatus comments and removed the abdominal-pain example because it was unclear next to the required CodeableConcept binding. FHIR-39630 added Condition.bodyStructure Reference(BodyStructure), added a mutual-exclusion invariant with bodySite, and explicitly removed Condition.bodySite comments that referenced the old standard extension. FHIR-31027 is earlier BodyStructure/bodySite context but was superseded by the later bodyStructure element work for this seed's extension guidance.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Restoring the old ED example or old body-site extension pointer would conflict with later applied Jira decisions, while the durable semantic effects of FHIR-11281 that still apply to the current build are already present: Condition.verificationStatus is optional, and Condition.bodySite is limited to cases not implicit in Condition.code.

Recommendation:
Keep this audit commit as-is. Do not reintroduce the obsolete verificationStatus example or old extension reference in core Condition; any future work should be driven by the later Condition status/bodyStructure issues rather than by the original DSTU2 wording.
