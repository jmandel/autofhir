FHIR-23068: Audit Patient deceased search XPath removal

Issue request:
FHIR-23068 was a Published PA change request, resolved Persuasive with Modification for R5, asking whether the Patient deceased SearchParameter XPath was correct and resolving that the XPath should become exists(f:Patient/f:deceasedBoolean[@value = 'true'] | f:Patient/f:deceasedDateTime/@value).

Initial application:
No FHIR-23068-tagged source commit was found. The Jira comments record the later application decision: the XPath-specific change was not applied because XPath search parameter definitions were being removed under FHIR-32530. Git history instead shows the old Patient-deceased XPath comment being removed as part of the broader XPath cleanup.

Additional context:
FHIR-32530 is a Published FHIR-I change request for R5 that dropped SearchParameter.xpath, renamed xpathUsage to processingMode, and updated search-parameter rules to depend on expression rather than xpath. Current source/fhir.ini keeps Patient in the active build, and the current Patient deceased search parameter has the intended FHIRPath expression plus processingMode with no XPath field to correct.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Reintroducing or correcting a SearchParameter.xpath value would contradict the later R5 removal of XPath support and would not affect the current build artifact.

Recommendation:
Keep this no-change audit as-is. No core FHIR source follow-up is needed for FHIR-23068 unless the work group reopens XPath support or identifies a current non-XPath deceased search-parameter defect.
