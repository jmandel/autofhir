FHIR-11431: Audit Task cancellation clarification

Issue request:
Published/Persuasive with Modification FHIR-core workflow issue FHIR-11431 reported confusion between a Task cancellation request and Task status, noting that `cancelled` was missing from the required Task status value set. The accepted resolution was to add `cancelled`, explain that cancellation is generally terminal, and clarify that a placer cancelling a task signals they no longer care about the task outcome even if the originally requested action is later completed.

Initial application:
The related code-system work was applied in the DSTU2 workflow issue family: commit 839bf586d6c1cf9a322e122852f0cc49bcfed263 added the Task cancelled-state note and a `cancelled` status, and commit 135effcdc18c5860253e8fc6df7197732441fe74 adjusted the definition under #10416. The Jira comment for FHIR-11431 cites SVN @11029, which corresponds to commit ff03a14ae8e8334436a8c416f7f2da8a87fb0f29; that commit explicitly tagged #11431 and changed the workflow ad-hoc cancellation scenario to say the placer is no longer concerned about the task outcome.

Additional context:
FHIR-10416 is the same change family and supplies the final code-system request to add `cancelled`. Later FHIR-14781 moved the Task state-machine explanation into the Task page and clarified that a task in any non-terminal state may be cancelled. Current build-scope checks show Task is active in `source/fhir.ini`, and `workflow-ad-hoc.html` is included in `publish.ini` and `source/hierarchy.xml`. No directly relevant Zulip or Confluence record was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source contains the `cancelled` Task status, includes it in the TaskStatus ValueSet, retains the dedicated Cancelled-state explanation, and the active workflow ad-hoc page now says the placer sets status to `cancelled` to signal they are no longer concerned while the filler ceases work if able.

Recommendation:
Keep this no-change audit commit. Do not change the current TaskStatus definition back to the seed issue's older "withdrawn prior to commencement" phrase without new WG review, because the same issue family and later Task state-machine guidance support broader cancellation semantics.
