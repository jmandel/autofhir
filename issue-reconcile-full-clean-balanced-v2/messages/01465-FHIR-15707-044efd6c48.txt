FHIR-15707: Audit Consent source search parameters

Issue request:
FHIR-15707 was a Published/Persuasive STU3 CBCC request to make Consent.source searching consistent: references should be searched with a reference parameter limited to Consent, DocumentReference, Contract, and QuestionnaireResponse; identifiers should use a token parameter; attachment search remained out of scope.

Initial application:
The STU3 spreadsheet already had separate source-reference and source-identifier rows by the Jira-tagged commit 7c8a912aeb. The actual source-row split appears in nearby history at 96e8cdaec5, which replaced the generic source reference row with source-reference plus source-identifier. That matched the issue's requested separation for STU3.

Additional context:
FHIR-19339 later resolved that source-identifier should be removed because identifiers are represented through Consent.sourceReference; commit eaffed2f39 removed Identifier from Consent.source[x] and deleted the source-identifier search row. The current build has Consent active in source/fhir.ini, has sourceAttachment and sourceReference as separate elements, and defines only Consent-source-reference with expression Consent.sourceReference. The 2017 Zulip thread that raised the issue agrees the old reference parameter should not cover attachment or identifier; no Confluence record was found that changes that conclusion.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current source no longer has the inconsistent generic Consent.source reference search or a separate sourceIdentifier choice. The remaining source-reference parameter targets only Consent.sourceReference, and attachment remains unsearchable as requested.

Recommendation:
Keep this no-change audit. Do not re-add a source-identifier parameter unless a future work-group decision reintroduces a separate identifier-valued source element or changes reference-identifier search expectations.
