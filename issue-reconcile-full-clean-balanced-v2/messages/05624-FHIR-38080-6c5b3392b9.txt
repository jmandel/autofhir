FHIR-38080: Audit extension search registry link

Issue request:
FHIR-38080 was a Published FHIR-core change request resolved Persuasive with Modification for R5. It reported that the mothersMaidenName extension search parameter did not display in the core search parameter registry, and the approved resolution said search parameters on extensions were moving out of core while the top of searchparameter-registry.html should point readers to the extension IG search-parameter listing.

Initial application:
The issue was explicitly applied by git commit 284d294d5c6744964e6b8ae96838ef1929e31872, which changed source/searchparameter-registry.html to add an extension search registry link. That commit is already an ancestor of both this worker branch and robo-spec-combined-issue-reconcile-full-clean-balanced-v2.

Additional context:
The current core registry page is in build scope through source/hierarchy.xml and publish.ini, and it still says that additional search parameters associated with extensions can be found in [%extensions-location%]search-params.html. The FHIR Extension Pack checkout contains the patient-extensions-Patient-mothersMaidenName SearchParameter and its search-params.html source page for core extension search parameters. Related visibility issue FHIR-34522 and the Zulip/Confluence evidence support this split between core registry and extension-pack registry rather than adding extension search parameters back into the core registry.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change because the current source already satisfies the FHIR-38080 resolution and a new core-source edit would only duplicate the existing link.

Recommendation:
Keep this no-change audit commit as-is. No core follow-up is needed for FHIR-38080; any future defects in the extension search-parameter listing itself should be handled in the FHIR Extension Pack repository.
