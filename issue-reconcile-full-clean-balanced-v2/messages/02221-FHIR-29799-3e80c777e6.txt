FHIR-29799: Explain RelativeTime timing choice

Issue request:
FHIR-29799 was a Published/Persuasive CDS change request asking that PlanDefinition.activity timing choices be explained, especially that Range means ages and that Duration is an offset. Its resolution agreed to clarify timing usages in both PlanDefinition and ActivityDefinition for R5.

Initial application:
No explicit FHIR-29799-tagged source commit was found. The same timing-choice clarification appears to have been initially applied by commit 1b8c872848 for FHIR-25471, which removed dateTime and Period from the definitional timing choices and added comments to ActivityDefinition.timing[x] and PlanDefinition.action.timing[x] explaining Age, Duration, Range, and Timing; the Jira comment on FHIR-29799 later recorded "Already applied".

Additional context:
ActivityDefinition and PlanDefinition are active current-build resources in source/fhir.ini. A later Applied issue, FHIR-43696, added RelativeTime to both timing[x] choice lists for R6 in commit da29739dd3, but that implementation did not extend the explanatory comments. RelativeTime itself is an active datatype whose definition describes a time or time period relative to an event, with a Duration or Range offset. No Zulip or Confluence search found a conflicting community decision.

AutoFHIR reconciliation:
This commit updates the authoritative StructureDefinition source for ActivityDefinition.timing[x] and PlanDefinition.action.timing[x] so the timing-choice comment also explains RelativeTime as expected timing expressed as an offset or offset range from an event described by the RelativeTime. This is a source-changing reconciliation because the current choice list had outgrown the prior clarification and otherwise no longer explained all timing choices.

Recommendation:
Keep this commit. It preserves the existing R5 clarification, incorporates the later R6 RelativeTime addition without changing cardinality or allowed types, and avoids duplicating guidance outside the two build-scoped definitions that FHIR-29799 targeted.
