FHIR-9260: Correct HealthcareService availability references

Issue request:
FHIR-9260 was an Applied/Not Persuasive with Modification PA change request, raised against DSTU2 and applied for R5, asking to restructure HealthcareService availability around a single availability structure with locations, available times, exceptions, and removed standalone exception text. The final resolution did not adopt every proposed nesting change; it says the R5 availability structure was made consistent across the specification by using a datatype, supporting the submitter's use cases.

Initial application:
No source commit explicitly tagged FHIR-9260 was found. The relevant application appears to have happened through the PA availability-family work, especially commit 447e89f4a40f92d16f33490766f29b9bce017236 for FHIR-25381/FHIR-26641, which introduced source/datatypes/availability.xml and replaced HealthcareService.availableTime, HealthcareService.notAvailable, and HealthcareService.availabilityExceptions with HealthcareService.availability of type Availability. The active fhir.ini R4/R5 change annotations also recorded that HealthcareService availability was changed to a datatype.

Additional context:
FHIR-25381's Published/Persuasive resolution explicitly created the Availability datatype and said PractitionerRole, Location, and HealthcareService would replace their prior availability structures with an availability property. FHIR-26641 supplied related closure/not-available semantics for Location. Later changes refined the shared datatype and current shape: FHIR-36017 changed HealthcareService.availability to a single Availability instance, and FHIR-41311 added Availability.availableTime.period; FHIR-41311 is already represented on the combined branch. A 2023 Zulip discussion with Brian Postlethwaite confirms the primary purpose of the R5 change was consistency across directory resources. Current fhir.ini entries keep both HealthcareService and Availability in build scope.

AutoFHIR reconciliation:
This commit keeps the approved datatype-based structure intact and fixes stale HealthcareService references that still pointed readers at the deleted notAvailable spelling. It updates the authoritative HealthcareService.active definition, the matching Participant mapping exception, the checked-in HealthcareService SVG title that mirrors that definition, and the fhir.ini R4/R5 change annotation for HealthcareService.availabilityExceptions so it points to HealthcareService.availability.notAvailableTime.description.

Recommendation:
Keep this source fix. It does not reopen the rejected parts of the original proposal, but it removes the remaining misleading references to the pre-R5 HealthcareService.notAvailable/availabilityExceptions structure from current build inputs and their companion diagram artifact.
