FHIR-38903: Audit regulatoryIdentifier rename

Issue request:
FHIR-38903 is an Applied/Persuasive with Modification OO change request for R6 asking whether the repeated deviceIdentifier naming under DeviceDefinition.regulatoryIdentifier would confuse implementers. The final resolution renamed regulatoryIdentifier.deviceIdentifier to regulatoryIdentifier.identifier, renamed regulatoryIdentifier.deviceIdentifierSystem to regulatoryIdentifier.identifierSystem, updated the identifier and identifierSystem definitions, and revised regulatoryIdentifier.jurisdiction short/definition text.

Initial application:
The change was applied before this reconciliation by PR #3842. Commit 11436a5fa623b1beb38a21b8562435125efc4117 changed the build-scoped source/devicedefinition/structuredefinition-DeviceDefinition.xml paths from regulatoryIdentifier.deviceIdentifier/deviceIdentifierSystem to regulatoryIdentifier.identifier/identifierSystem and applied the requested definition and jurisdiction wording. The merge commit is f8a725b7b0967fe6dd9f4f3cbc0d73a205ef9086.

Additional context:
source/fhir.ini actively lists devicedefinition as a current resource, so the StructureDefinition XML file feeds the current core build. The R5 history file contains regulatoryIdentifier.deviceIdentifier but no regulatoryIdentifier.deviceIdentifierSystem, which explains why source/fhir.ini maps the R5 deviceIdentifier element to the R6 identifier element while marking identifierSystem as a new R5-to-R6 element. OO minutes first deferred the issue in 2023 and later recorded the 2025 block vote that approved FHIR-38903 as Persuasive with Modification. Zulip searches found only an unrelated tracker-planning mention and no conflicting discussion.
