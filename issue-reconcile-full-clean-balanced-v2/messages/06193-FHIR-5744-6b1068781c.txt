FHIR-5744: Audit attachment extension generalization

Issue request:
FHIR-5744 was a Published/Persuasive FHIR-core Questionnaire issue asking that two attachment-related common Questionnaire extensions be moved to the generic element extensions profile because they can apply to profiled elements, extension definitions, and data elements beyond Questionnaire.

Initial application:
The Jira comments identify SVN #4165 as pre-applied. Git commit e4f5c0d73d001a82fba48ff47d65a7154166c19c is that git-svn application and removed mimeType and maxSize from the old Questionnaire extension spreadsheet while refactoring the shared Questionnaire extension design. Later source reorganization added the element-extensions profile under source/profiles with mimeType and maxSize defined for Questionnaire.item and ElementDefinition, so the requested move was present in the core source lineage before the R5 extension ownership cleanup.

Additional context:
Questionnaire and the element-extensions profile are active current-build source entries in source/fhir.ini. Current core no longer owns the extension StructureDefinitions directly after the R5 removal of extension definitions from the core checkout; the FHIR Extension Pack now defines mimeType and maxSize in input/definitions/multiple with contexts for both Questionnaire.item and ElementDefinition, and comments limiting their meaning to elements whose type is Attachment. The current core element-extensions introduction still classifies mimeType and maxSize as attachment-related element extensions, while Questionnaire notes recognize that extensions with both ElementDefinition and Questionnaire.item contexts propagate.

AutoFHIR reconciliation:
This audit intentionally makes no source change. The current source and Extension Pack ownership already satisfy the issue: the attachment extensions are generic element-related extensions rather than Questionnaire-only extensions, and no current core source location is misleading enough to require a corrective edit.

Recommendation:
Keep this no-change audit commit. No FHIR core source fix is needed for FHIR-5744. Future normative changes to mimeType or maxSize should be made in the FHIR Extension Pack definitions, with only core narrative updates if the core build still references those extension categories incorrectly.
