FHIR-19305: Audit CodeableConcept multiple-coding heading

Issue request:
FHIR-19305 was a Published/Persuasive STU3 FHIR-I change request for the CodeableConcept datatype page. It asked to replace the "Code Translations" heading with better multiple-coding wording and trim related language around translations.

Initial application:
The apparent application was git commit 5bce7af6aa58f2ab8bd1da6743756d42fd155707, referenced from the Jira comment as GH#5bce7af6aa, which changed the CodeableConcept heading in source/datatypes.html from "Code Translations" to "Additional Codes". The seed FHIR-19431 then made the parallel Observation-page rename to "Multiple Codings" and "additional codings".

Additional context:
source/fhir.ini maps ordinary datatypes to datatypes.html, so source/datatypes.html is current build-scope content. Later Applied issue FHIR-50188 replaced the old Additional Codes text with the current "Multiple Codings" section and stronger semantics. That later approved text explicitly says each coding is sometimes called a translation and includes an example sentence using the term, so the remaining terminology is deliberate context rather than a stale section title.

AutoFHIR reconciliation:
This is an empty no-change audit commit. The current CodeableConcept page already has the requested modern section heading, and later approved guidance controls the current balance between "multiple codings" terminology and limited legacy alias wording.

Recommendation:
Keep this audit commit as-is. No source follow-up is recommended for FHIR-19305; any further removal of the word "translation" from CodeableConcept should be proposed as a new terminology/editorial issue because FHIR-50188 intentionally retained it in limited places.
