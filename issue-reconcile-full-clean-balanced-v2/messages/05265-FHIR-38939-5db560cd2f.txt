FHIR-38939: Correct Bundle signature deprecation reason

Issue request:
FHIR-38939 was a Published FHIR-core change request, resolved Persuasive with Modification for R5. It asked for a structured and visible way to identify deprecated content: correct the standards-status Deprecated definition, add a Withdrawn standards-status code, define a markdown deprecation reason extension for standards-status.valueCode, and apply standards-status plus reason metadata to deprecated Bundle content so the build could render the status and flyover reason.

Initial application:
The main R5 application appears in c1dda1d5fd ("Cleaning up extensions and status codes"), which added the corrected standards-status code system entries, the markdown-valued structuredefinition-standards-status-reason extension, and a deprecated standards-status reason on Bundle.entry.search.mode code outcome. The generic standards-status code system and extension definitions were later moved out of the core source into the FHIR Extension Pack by dd468d4f17, where their current source still has the corrected Deprecated definition, the Withdrawn code, and a markdown status-reason value.

Additional context:
The current core build still owns Bundle: source/fhir.ini has an active bundle=Bundle resource entry and Bundle work-group/status metadata. Later commit 9fe4e8ba2e deprecated Bundle.signature, but placed the standards-status reason as a child extension with valueString beside valueCode. That shape differs from the existing core examples, where the reason is an extension on standards-status.valueCode with valueMarkdown, and from the current Extension Pack definition that constrains the reason extension value to markdown. Confluence minutes for the FHIR-I 2022-10-24 call confirm the FHIR-38939 decision and no Zulip search found conflicting discussion.

AutoFHIR reconciliation:
This commit updates source/bundle/structuredefinition-Bundle.xml so Bundle.signature carries the standards-status reason inside standards-status.valueCode and uses valueMarkdown, matching the extension definition and the other current source usages. No source change was made for the standards-status code system or extension definitions because those have intentionally moved to the FHIR Extension Pack and are already correct there.

Recommendation:
Keep this commit as-is. It fixes a malformed current core Bundle deprecation marker that would otherwise undermine the mechanism approved by FHIR-38939, while leaving the already-correct Extension Pack terminology and extension definitions untouched.
