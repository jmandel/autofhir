FHIR-11116: Audit CarePlan activity outcome clarification

Issue request:
FHIR-11116 was a Published/Persuasive Patient Care change request from DSTU2 asking for CarePlan.activity.outcome to be better defined and harmonized with Goal.outcome. The final resolution clarified that the activity outcome is assessed independently from related goal outcomes, expanded CarePlan.activity.outcome to 0..*, introduced outcome.result[x], and gave the body-weight/diet example that separates activity evidence from goal measurement.

Initial application:
The issue appears to have been applied in historical source by git commit a2b1e7d44e, whose message explicitly includes #11116 and whose patch changed CarePlan.activity.actionResulting into CarePlan.activity.outcome/result[x], added the requested activity-vs-goal explanation, and updated Goal.outcome wording with a GF#11116 committee note. Later companion commits handled the old outcome bindings and flattening, but those are separate Jira decisions.

Additional context:
The current build no longer has a literal CarePlan.activity.outcome element. FHIR-26064 renamed the element to CarePlan.activity.performedActivity, using CodeableReference and preserving the semantic distinction between activities performed and goal outcomes. The active CarePlan source has the performedActivity definition/comment from that later decision, and source/fhir.ini maps the retired outcomeCodeableConcept/outcomeReference names to performedActivity for version conversion. Goal.outcome was later removed under FHIR-37262, so the seed's Goal.outcome clarification remains only in commented historical source and is not an active current-build element. FHIR-48415 later removed the obsolete note about duplicating an activity status because there is no CarePlan.activity.status.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because the current active CarePlan element already conveys the seed's implementer-facing rule after the later rename, and reintroducing the old outcome wording or active Goal.outcome text would conflict with later final Jira decisions.

Recommendation:
Keep this audit commit as-is for FHIR-11116. Future work should not restore CarePlan.activity.outcome or Goal.outcome for this seed; any review of the performedActivity name, bindings, or progress/status text should happen under the later CarePlan trackers rather than reopening this historical clarification.
