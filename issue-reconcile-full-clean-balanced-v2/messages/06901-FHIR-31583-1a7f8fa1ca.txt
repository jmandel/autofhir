Initial application:
No FHIR-core source commit explicitly mentions FHIR-31583, and bounded source-history searches found no core edit adding the reported publisher warning or inheritance rule. Later package documentation was added in core by c9186a64e1 and documents the optional package.json jurisdiction property without making the publisher's matching heuristic a core conformance rule.

Additional context:
The Jira resolution says the rule lives in publisher-discretion space and should be handled with HL7 IG Publisher/Confluence documentation, not as a firm core specification rule. The linked Zulip thread shows the question was about publisher behavior and package namespace policy, and the FHIR-I minutes record approval of that Persuasive with Modification disposition. Current build-scoped core source has source/packages.html in the page hierarchy and ImplementationGuide active in fhir.ini; those sources document package jurisdiction and ImplementationGuide.jurisdiction generally but do not assert the disputed inherited-jurisdiction validation rule.
