FHIR-26965: Audit Appointment replaces property

Issue request:
FHIR-26965 was Published with a Persuasive with Modification resolution. The original request asked whether the request-replaces standard extension should apply to Appointment; the adopted resolution instead called for a native Appointment.replaces 0..* Reference(Appointment) property describing appointments replaced by this Appointment, with cancellation details available through cancellationReason on the referenced Appointment.

Initial application:
The issue was applied before this reconciliation. Jira-tagged commit 58aa3c2fb9 added Appointment.replaces to source/appointment/structuredefinition-Appointment.xml on 2021-05-25, and Jira-tagged commit 91957e4ef6 moved the element into the request workflow order on 2021-05-26 after PA's May 2021 agenda requested reconfirming where the element should appear.

Additional context:
Appointment is active in the current build through source/fhir.ini. FHIR-26526 spawned the request-extension follow-up issues and specifically listed Appointment replaces as FHIR-26965 for PA consideration. Current source maps Appointment.replaces to Request.replaces, and the mapping exception records intentional Appointment-specific differences from the generic Request pattern. The Extension Pack request-replaces extension does not list Appointment as a context, which is consistent with Appointment having a native element rather than using the extension.

AutoFHIR reconciliation:
Made no source change. The current Appointment StructureDefinition already defines Appointment.replaces as 0..* Reference(Appointment), includes the cancellationReason guidance requested by the resolution, and maps the element to Request.replaces.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed for FHIR-26965 unless PA later chooses to revisit element ordering, summary behavior, or whether the Extension Pack request-replaces context should also mention Appointment despite the native element.
