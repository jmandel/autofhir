FHIR-13152: Use col-12 on static tooling pages

Issue request:
FHIR-13152 was Published/Persuasive for a non-substantive FHIR-I technical correction. The Jira reported a random mix of Bootstrap col-12 and col-9 content wrappers across FHIR-core pages and requested that everything use col-12 if possible.

Initial application:
The Jira comment says the change was applied in svn revision 12604. In git history, commit a6edf67ad6cf62cfcbc581dea7a330cb8e5c9181 carries that git-svn revision and changed 101 source/*.html pages from col-9 to col-12; commit 66f032b79d04b7e11e7b6c94408f6f6178f933d7 then made the same home page correction. Current source/ no longer contains col-9, but the publish-scope tools/html static pages for search and registry still used col-9 wrappers.

Additional context:
publish.ini maps the [html] source directory to tools/html, so tools/html/search.cfm and tools/html/registry/index.html are current publish inputs. A remaining col-9 in tools/ig/pages/_includes/header.html is not referenced by publish.ini, source/fhir.ini, or the current publish scripts checked for this reconciliation, so this commit does not edit that legacy IG sample/template. Jira full-text search found no other col-9/col-12 tracker, and Zulip/Confluence searches found no conflicting community discussion.

AutoFHIR reconciliation:
Changed the two in-scope tools/html content wrappers from col-9 to col-12 so the copied static search and registry pages follow the same full-width layout already applied to source pages and current templates.

Recommendation:
Keep this source fix as-is. No further core source work is indicated for FHIR-13152 unless a future build process intentionally brings the legacy tools/ig sample pages into current publication scope.
