FHIR-23719: Audit Consent ADR scope reconciliation

Issue request:
FHIR-23719 was Published/Persuasive for R5. It asked to remove Advance Directives from the scope of the Consent resource, remove references through Consent.scope and the introductory text, and add a note that HL7 was working on Advance Directives.

Initial application:
The issue appears to have been applied by git commit 2da480ca699986fa93ba5f234dc5b055146d8144, which explicitly listed GF#23719 and changed the Consent introduction plus the then-current Consent spreadsheet source. Later Consent source refactoring removed the Consent.scope element entirely; the current source has no Consent.scope element and the current introduction lists only privacy, treatment, and research as the three anticipated Consent uses.

Additional context:
Later final terminology decisions changed how the old scope codelist should be interpreted. FHIR-34215 was Published/Persuasive for R5 to add adr back into the ConsentScope codelist, and UP-255 was implemented in THO to restore adr because R4 implementations still used the code and THO had become inconsistent with the R4 code system. The related Zulip discussion records that CBCC had removed Advance Directives from the R5 codelist, but was merging scope and category for R5 and had users asking for the code to return. Current THO therefore intentionally includes adr in CodeSystem/consentscope, and current Consent.category remains only an example binding that includes broader category codes, including advance-directive-related examples.

AutoFHIR reconciliation:
This commit makes no source change. The current core Consent scope text already omits Advance Directives and Consent.scope no longer exists, while the remaining adr code and advance-directive category examples are explained by later final FHIR/UTG decisions rather than an unapplied part of FHIR-23719. Adding the 2019 note now would be stale and potentially misleading because later PACIO/ADI and terminology work exists and the current page already says other use cases may be handled through category codes.

Recommendation:
Keep this audit commit as-is for FHIR-23719. Do not remove adr from the current THO-backed consent scope/category surfaces as part of this old issue; any new change to how Advance Directives, treatment directives, Consent, ServiceRequest, or PACIO/ADI should align should proceed through a new work-group decision such as the still-open FHIR-50903 discussion.
