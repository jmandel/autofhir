FHIR-22116: Audit revenue code attribution removal

Issue request:
FHIR-22116 is Published/Persuasive for Financial Management. It asked core to add National Uniform Billing Committee attribution to the example Revenue Center CodeSystem used by Claim and ExplanationOfBenefit, and the Jira resolution comment states that the codes in question were removed from the example codeset to resolve the issue.

Initial application:
No Jira-keyed commit was found for FHIR-22116. The matching early source history is 2a7b55d5f4, which added NUBC attribution to source/claim/codesystem-ex-revenue-center.xml on the issue creation date. The later same-family implementation f7b4d814e2 removed the potentially infringing revenue-center concepts and replaced them with generic example concepts; 5c0494aacf then removed the former core CodeSystem source during UTG/THO migration.

Additional context:
FHIR-23003 is the applied companion issue for removing infringing or potentially infringing ex-revenue-center examples, and it is already represented on the combined branch by 46dde41f4b493844f884877b51ccc992dffe85e5. Current source/fhir.ini keeps Claim, ClaimResponse, and ExplanationOfBenefit in the build, while source/claim/valueset-ex-revenue-center.xml only composes the external terminology.hl7.org CodeSystem. The current core checkout no longer contains source/claim/codesystem-ex-revenue-center.xml, and the current THO CodeSystem carries only the generic concepts 0010 Vision Clinic, 0011 Dental Clinic, and 1001 Emergency under THO licensing.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Adding NUBC attribution back into core would contradict the issue's own resolution comment and the later FHIR-23003 disposition, because the NUBC-derived examples were removed and the authoritative CodeSystem concepts are no longer maintained in this core source checkout.

Recommendation:
Keep this audit commit as-is for FHIR core. No core source follow-up is needed for FHIR-22116; any future concern about the external ex-revenue-center CodeSystem should be handled through THO/UTG, not by adding stale NUBC attribution to the core ValueSet wrapper.
