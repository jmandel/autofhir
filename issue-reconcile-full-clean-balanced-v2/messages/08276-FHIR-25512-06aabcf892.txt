FHIR-25512: Audit variable extension constraint ownership

Issue request:
FHIR-25512 was Published as Persuasive for R5. It reported that the variable extension did not require variable expressions to have names, and the accepted resolution was to add a constraint on the extension's Expression value so Expression.name is required.

Initial application:
The issue was explicitly applied in core history. Commit f03a153a3fd50b4257966231573fea131b6c0fb4 added a MustHaveName constraint to source/profiles/general-extensions-spreadsheet.xml for the variable extension, using value.name.exists() and an XPath check against valueExpression.name. Commit 02d5f0bffcaefadbf7619c9314915307cc4a0444 then corrected the invariant key from ext-1 to var-1 after the original key collided.

Additional context:
Current core still has source/profiles/general-extensions-spreadsheet.xml in build scope through source/fhir.ini, but that spreadsheet no longer contains the variable extension or the FHIR-25512 constraint; commit dd468d4f1799dd79819315b211588ef1cf4586e0 removed the extension rows from the R5 source as part of moving extensions out of core. The current source of truth is the FHIR Extension Pack, whose IG identifies package hl7.fhir.uv.extensions and whose input/definitions/multiple/StructureDefinition-variable.xml defines http://hl7.org/fhir/StructureDefinition/variable with differential constraint var-1, severity error, human text "Variable expressions must have a name", and expression value.name.exists(). The linked Zulip thread and FHIR SDC minutes match the Jira request and vote. FHIR-25515 came from the same thread but concerned Expression.name's datatype/regex and is already represented on the combined branch.

AutoFHIR reconciliation:
This empty audit commit makes no core source change. The requested conformance rule is already present in the Extension Pack artifact that now owns the variable extension, while the current core checkout has no active variable-extension definition to edit.

Recommendation:
Keep this audit as-is for core. Do not reintroduce the variable extension into core for FHIR-25512. If future work changes the variable extension, apply and audit that work in the FHIR Extension Pack repository.
