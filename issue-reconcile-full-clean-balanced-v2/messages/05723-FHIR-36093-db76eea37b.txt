FHIR-36093: Audit Vital Signs category slicing

Issue request:
FHIR-36093 is an Applied FHIR-core Observation issue from OO, resolved Not Persuasive with Modification for R6. It reported that the R4 VitalSigns.category slicing by value:coding.code and value:coding.system prevented derived Vital Signs profiles from allowing alternate codings in an added category slice. The approved resolution text said to change category:VSCat.coding cardinality to 1:1, but later Jira comments clarified that the submitter's original concern was already addressed by changing the slicing to pattern:$this and that applying the literal 1:1 cardinality change would be incorrect.

Initial application:
No git commit explicitly mentioning FHIR-36093 was found. The substantive source application appears to have happened through later Vital Signs profile rework, especially git 71babbf5ac for FHIR-46418, which replaced Observation.category slicing by value:coding.code/value:coding.system and fixed VSCat.coding child constraints with open pattern:$this slicing and a VSCat patternCodeableConcept. The current combined branch already has a separate FHIR-46418 audit commit, so this commit does not duplicate that related issue.

Additional context:
The current source is in build scope: Observation is active in source/fhir.ini, source/igs.xml marks the Vital Signs IG as core, and source/observation/implementationguide-Observation-vitalsigns.xml includes StructureDefinition/vitalsigns. A 2022 Zulip thread confirmed the original fixed-repeated-coding problem and linked FHIR-36093. Later Jira comments on FHIR-36093 say the current pattern:$this slicing and unconstrained category:VSCat.coding cardinality allow alternate translation codings and require no further source change. FHIR-44798 later added current narrative stating that additional category codes may be included with the vital-signs category code, and that related issue is also already represented on the combined branch.

AutoFHIR reconciliation:
This is an empty audit commit. The current formal Vital Signs Base Profile has Observation.category sliced as unordered/open by pattern:$this, defines Observation.category:VSCat with a patternCodeableConcept for the vital-signs coding, and has no Observation.category:VSCat.coding child element that would force all codings in that CodeableConcept to the same system/code. The nearby Vital Signs introduction also explicitly allows one or more additional category codes. No source change is needed for FHIR-36093.
