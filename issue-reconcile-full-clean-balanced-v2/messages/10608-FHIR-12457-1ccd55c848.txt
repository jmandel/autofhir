FHIR-12457: Audit localization alias already present

Issue request:
FHIR-12457 was a Published/Persuasive FHIR-core change request from DSTU2 asking that the standard translation extension page include the words "localize" or "localization" so implementers searching for localization could find it. The accepted resolution was to add the word as an alias.

Initial application:
The issue was applied in SVN revision 11177, preserved in git as commit 448416f7fc (#12457 - add "Localization"), which added "Localization" as the alias and changed the translation extension short text in the then-core general extensions spreadsheet to "Language Translation (Localization)".

Additional context:
The translation extension is no longer maintained as a core source row; commit dd468d4f17 removed the extension rows from the R5 core source when extensions moved out of core. The current FHIR Extension Pack source for StructureDefinition/translation still carries "Language Translation (Localization)", and the current core Multi-Language Support page is active in hierarchy.xml, titled "Multi-Language support in FHIR (Localization/Internationalization)", and links to the translation extension. Direct Zulip and Confluence searches for FHIR-12457 found no conflicting implementation history.

AutoFHIR reconciliation:
No source files were changed. The current core build already exposes localization language on the multi-language page, while the authoritative translation extension definition now lives in the Extension Pack and retains the localization wording requested by the issue.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed unless the Extension Pack later drops the localization wording or core stops linking the translation extension from the multi-language/localization page.
