FHIR-9978: Audit MedicationRequest summary flags

Issue request:
FHIR-9978 was Published/Persuasive for DSTU2 and requested that MedicationOrder summary flags be reduced from all attributes to status, medication, patient, dateWritten, and prescriber, clearing the summary flag on all other MedicationOrder attributes.

Initial application:
The issue was applied in historical commit 178b92d8e2a7bbe79da9412e8d74a28285d7aa0c, whose subject explicitly lists gForge 9978 and whose patch added the summary-column marker to MedicationOrder.status, MedicationOrder.medication[x], MedicationOrder.patient, MedicationOrder.dateWritten, and MedicationOrder.prescriber in the then-authoritative spreadsheet. No later Jira-tagged commit for FHIR-9978 was found.

Additional context:
MedicationOrder is no longer a current active resource; source/fhir.ini lists MedicationRequest as the active resource and records the MedicationPrescription-to-MedicationRequest transition plus legacy MedicationOrder mappings including dateWritten to authoredOn and patient to subject. The current source has moved from spreadsheet XML to StructureDefinition XML. Later R5-era source migration, FHIR-32487 element ordering, and FHIR-24100 workflow reconciliation retained the five requested descendant summary elements while also carrying current workflow/request summary fields such as basedOn, groupIdentifier, intent, priority, doNotPerform, isRecordOfRequest, and performerType. Peer current request resources show the same broader pattern of workflow summary elements. Zulip and Confluence searches found no human discussion or conflicting work-group evidence that would require reverting the current MedicationRequest summary set to the narrower DSTU2 MedicationOrder list.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped MedicationRequest source already preserves the FHIR-9978 descendants status, medication, subject, authoredOn, and requester/prescriber-equivalent, while the additional current summary flags reflect later resource and workflow evolution rather than an unapplied DSTU2 defect.

Recommendation:
Keep this audit commit as-is. Do not remove the additional current MedicationRequest summary markers as part of FHIR-9978; any future change to the R6 MedicationRequest summary set should be a new Pharmacy work group decision that considers current workflow-pattern consistency.
