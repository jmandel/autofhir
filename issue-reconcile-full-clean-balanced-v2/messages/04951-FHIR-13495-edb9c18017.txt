FHIR-13495: Audit Location.address comment

Issue request:
FHIR-13495 was a Published/Persuasive with Modification STU3 FHIR-core Location change request. It reported that Location.address incorrectly said the element stayed 0..1 because Address had no use property; the approved resolution removed that incorrect comment, added guidance that additional addresses should be represented by another Location or by the Organization, and did not change cardinality.

Initial application:
The issue was applied in git commit aea6363ec7, which replaced the old source/location/location-spreadsheet.xml Location.address comment with the approved additional-address guidance. Later source rework commits carried the applied wording into source/location/structuredefinition-Location.xml, where the active current source now says additional addresses should be recorded using another Location instance or via the Organization.

Additional context:
source/fhir.ini lists location=Location under active resources, so source/location/structuredefinition-Location.xml is in current build scope. The linked Patient Administration Zulip thread records agreement to remove the inaccurate comment, leave cardinality alone, and add that another address should be another Location instance. Jira, Zulip, and Confluence searches found no later conflicting decision for this Location.address comment.

AutoFHIR reconciliation:
Made no source change. The current active source already contains the intended replacement comment, and the obsolete statement about Address lacking a use property is absent.

Recommendation:
Keep this audit commit as-is. The current specification already reflects the final FHIR-13495 decision; no core follow-up is indicated.
