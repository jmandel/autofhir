FHIR-14441: Audit patient-pattern alignment

Issue request:
FHIR-14441 was Published/Not Persuasive with Modification for R5 by PA. It asked whether FHIR should define a formal pattern for Patient-like resources. PA declined to create a formal pattern unless future resources made one useful, but approved concrete alignment changes: move Person.active after Person.identifier, make Person.identifier and Person.address summary elements, change Person.photo to 0..*, and move Practitioner.telecom, Practitioner.gender, Practitioner.birthDate, and Practitioner.address into the same relative order as Patient.

Initial application:
The approved work appears to have been applied through a small chain of source commits. Commit 1410ca6ac9b4 (#FHIR-20590) changed Person.photo from 0..1 to 0..*. Commit 1bf9c6c3a619 (#FHIR-20771) added Person.active after identifier and added other Patient-like Person demographics. The direct FHIR-14441 implementation commit 7aa395b0f558 then added Person.identifier and Person.address to summary and realigned Practitioner/Person ordering and status metadata; it was merged by PR #2167.

Additional context:
source/fhir.ini actively builds Patient, Person, Practitioner, and RelatedPerson, so the StructureDefinition source files checked here are current build inputs. Current Patient, Person, and Practitioner definitions retain the common Patient-like order for identifier, active, name, telecom, gender, birthDate, deceased, address, and photo where applicable; Person.identifier and Person.address are summary, and Person.photo is 0..*. RelatedPerson includes resource-specific patient/relationship/role elements ahead of name, which does not conflict with the FHIR-14441 resolution. Confluence PA January 2019 minutes echo the tracker discussion and note that the issue did not change Patient itself. Zulip and Confluence issue-key searches found no conflicting community rationale.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current authoritative source already reflects the approved alignment and because adding a formal pattern would contradict the PA resolution for this issue.

Recommendation:
Keep this no-change audit. Future work should revisit a formal pattern only if PA introduces additional resources that make the pattern valuable; there is no current core source correction needed for FHIR-14441.
