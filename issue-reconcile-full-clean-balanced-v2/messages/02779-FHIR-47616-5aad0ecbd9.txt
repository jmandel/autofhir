FHIR-47616: Audit BodyStructure morphology value set

Issue request:
FHIR-47616 was an Applied/Persuasive OO change request for R6 asking that BodyStructure.morphology's example value set be cleaned up because the ballot value set included disease/pathology examples rather than morphology. The approved resolution was to update the example value set to the SNOMED CT hierarchy 118956008 |Body structure, altered from its original anatomical structure (morphologic abnormality)| so it only includes SNOMED morphologic abnormalities.

Initial application:
The issue was applied before this reconciliation by commit 8d706af07d07c6c92b41965482fd5735bffeb3c4, later merged via HL7/fhir PR #3552 as cd8e130841. That commit changed source/bodystructure/valueset-bodystructure-code.xml from the broader anatomical/acquired body-site hierarchy to a SNOMED CT concept is-a filter on 118956008. Later commits on the same file only adjusted value set metadata such as shareability/status, not the hierarchy selected for FHIR-47616.

Additional context:
BodyStructure is an active current-build resource in source/fhir.ini, and BodyStructure.includedStructure.morphology still has an example binding to http://hl7.org/fhir/ValueSet/bodystructure-code. The current combined branch already has the 118956008 description and compose filter. OO minutes from 2025-03-13 record the block vote for FHIR-47616 as Triaged/Persuasive with a 12-0-0 motion, and no Zulip or Confluence search found a conflicting community decision. Jira search found similarly named EU IG morphology tickets, but they concern non-core IG artifacts and are not part of this FHIR-core reconciliation.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change because the current source already implements the approved FHIR-47616 resolution in the build-scoped BodyStructure value set and binding.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed for FHIR-47616 unless the OO work group later chooses a different morphology value set policy; the separate EU IG morphology issues should be handled in their own repositories/workflows if needed.
