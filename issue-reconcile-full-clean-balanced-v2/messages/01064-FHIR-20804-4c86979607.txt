FHIR-20804: Audit MeasureReport.date clarification

Issue request:
FHIR-20804 was a Published/Persuasive FHIR-core MeasureReport clarification for R5. It asked to resolve ambiguity in MeasureReport.date by changing the description from report generation timing to the date the measure was calculated.

Initial application:
The issue was initially applied by commit e62ab8df772ec147612cd8c36a9b1ebd4071ae56, which changed source/measurereport/structuredefinition-MeasureReport.xml so MeasureReport.date said "When the measure was calculated" and "The date this measure was calculated." Jira also records PR HL7/fhir#2879 as the application.

Additional context:
The Jira comments explicitly say the change was revisited in FHIR-40797. That later DEQM issue identified the same ambiguity and led to FHIR-41018 for FHIR core. FHIR-41018 is Applied/Persuasive with Modification for R6 and intentionally changes MeasureReport.date back to report generation while adding MeasureReport.group.calculatedDate for measure calculation timing. source/fhir.ini lists MeasureReport as an active resource and lists MeasureReport.group.calculatedDate as a current element, so the inspected XML source is in build scope.

AutoFHIR reconciliation:
This commit makes no source change. The current source is already correct after the later CQI decision: MeasureReport.date is "When the measure report was generated" and MeasureReport.group.calculatedDate carries the calculation date.

Recommendation:
Keep this audit commit and do not re-apply FHIR-20804's R5 wording to the current build. The original request was applied for R5, but it has been superseded in current core by FHIR-41018's more precise split between report generation and calculated date.
