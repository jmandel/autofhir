FHIR-26555: Audit SNOMED effectiveTime property migration

Issue request:
FHIR-26555 was a Published/Persuasive R5 Vocabulary WG change request asking the SNOMED CT usage page's standard property documentation for CodeSystem $lookup to add the effectiveTime property, defined as the RF2 Concepts snapshot effectiveTime, with FHIR property data type dateTime.

Initial application:
The issue was directly applied before this reconciliation by commit 0bcb947d84, which updated source/snomedct.html and added the effectiveTime row with data type dateTime and the RF2 Concepts snapshot wording. The same commit also reordered/added neighboring SNOMED CT property rows as part of a broader Using X with FHIR text update.

Additional context:
FHIR-35933 and UP-289 later moved the old FHIR-core Using external code-system pages, including source/snomedct.html, to HL7 Terminology (THO). The current FHIR-core source no longer has source/snomedct.html in source or publish scope; instead, source/terminologies-systems.html states that external terminology guidance is authoritative in THO and links SNOMED CT to terminology.hl7.org/SNOMEDCT.html, while retaining only the FHIR-specific snomedct-usage.html summary. Published THO versions checked for the migrated SNOMED CT page retain the effectiveTime/dateTime row.

AutoFHIR reconciliation:
No source change was made. Restoring the old SNOMED CT property table in FHIR core would conflict with the later approved migration to THO, and the build-scoped FHIR source already points implementers to THO for authoritative SNOMED CT usage guidance.

Recommendation:
Keep this empty audit commit as-is for FHIR core. If the current THO publication needs correction or a newer THO page unexpectedly omits the migrated property table, handle that as THO/UTG work rather than a FHIR-core source edit.
