FHIR-18606: Audit CodeSystem.date date semantics

Issue request:
FHIR-18606 was Published with a Persuasive with Modification resolution for STU3 Vocab CodeSystem.date. It asked to replace "The date (and optionally time) when the code system was published." with "The date (and optionally time) when the code system resource was created or revised." so CodeSystem dates would not be treated as publish dates.

Initial application:
The Jira comment cites git 4907f9bcb0b710cb2837a93a20c4b23210a37249, whose terminology ballot spreadsheet patch added the resolved CodeSystem.date wording. Later source conversion/history no longer preserved that exact date text on CodeSystem.date, and related status-definition cleanup was handled separately by FHIR-24865/FHIR-22842.

Additional context:
FHIR-37858 later made the current broader CanonicalResource.date decision: separate last-significant-change date from publication date, and add comment guidance that the date may be present before publication and is not the resource last-modified date. Git 378fe392dd102168828a322355a66656eff4d1bb changed CodeSystem.date from the stale "published" wording to "last significantly changed," and git 49b86f8a6978650d8f8a6d36d27dee0433e455bc retained that wording while adding local-change guidance. The current CodeSystem resource is active in source/fhir.ini.

AutoFHIR reconciliation:
No source change was made. The active CodeSystem.date definition now avoids using date as a publication date, explicitly ties it to significant change/version/status/content changes, and the comment clarifies draft and provenance/last-modified semantics. Replacing it with the older "created or revised" sentence would regress the later FHIR-37858 clarification.

Recommendation:
Keep this empty audit commit as-is. No follow-up core source work is needed for FHIR-18606 unless a future work group decision reopens the broader CanonicalResource.date model.
