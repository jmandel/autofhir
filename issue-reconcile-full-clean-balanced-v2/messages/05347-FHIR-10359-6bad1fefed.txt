FHIR-10359: Audit maternal/paternal relationship codes

Issue request:
FHIR-10359 was Published with resolution Not Persuasive with Modification. It asked to add maternal_family, paternal_family, first_cousin, second_cousin, and blood_relative codes to the RelatedPerson relationship type value set for a family-history/pregnancy use case. The accepted resolution did not add those codes; it said the binding had been changed to be extensible so implementations could extend the value set locally.

Initial application:
No explicit git commit mentioning FHIR-10359 was found. The current RelatedPerson StructureDefinition was later imported into the XML source with RelatedPerson.relationship using a preferred binding, and the requested codes were not added to the RelatedPerson relationship type value set.

Additional context:
RelatedPerson is an active resource in source/fhir.ini, so its StructureDefinition and value set files are in current build scope. Later FHIR-15841 deliberately split personal relationships from functional roles: RelatedPerson.relationship now uses the THO v3 PersonalRelationshipRoleType value set with preferred strength, while RelatedPerson.role uses the relatedperson-relationshiptype value set with preferred strength. FHIR-31670 later expanded relatedperson-relationshiptype for functional role concepts and is already represented on the combined branch. The FamilyMemberHistory source also has only an example binding for relationship and notes that a family-history List can include Observations such as maternal family history assertions.

AutoFHIR reconciliation:
This is an empty no-change audit commit. The current preferred bindings are at least as permissive for local/use-case-specific codes as the extensible binding cited by the Jira resolution, and later source history intentionally moved personal family relationships away from relatedperson-relationshiptype. Adding the requested codes now would contradict the original no-add resolution and the later relationship/role split.

Recommendation:
Keep this audit commit as-is. If a future work group wants universal maternal_family, paternal_family, cousin, or blood_relative concepts, it should be raised as a new PA/terminology request against the current personal-relationship terminology rather than reopening FHIR-10359.
