FHIR-19731: Audit CodeSystem hierarchy wording

Issue request:
FHIR-19731 was a Published/Persuasive STU3 vocabulary technical correction for FHIR-core CodeSystem. It asked to change the hierarchy guidance from saying relationships between resources should be defined using CodeSystem properties to saying relationships between concepts should be defined using properties.

Initial application:
The issue was applied by commit 291e76beae37741b5e4482bded1636e832a07e49, "GF#19731 - fix typo", which changed source/codesystem/codesystem-notes.xml from "relationships between resources" to "relationships between concepts". The same historical commit also corrected an unrelated ValueSet typo, but the CodeSystem hunk is the issue-relevant application.

Additional context:
CodeSystem is an active resource in source/fhir.ini, and the current source/codesystem/codesystem-notes.xml hierarchy section still says that when hierarchy is represented using properties, nested concepts should not be used for hierarchy structure and relationships between concepts should be defined using properties. Jira searches only surfaced FHIR-19731 for this exact wording, and corrected Zulip and Confluence searches found no later or conflicting community discussion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped CodeSystem source already uses the requested "relationships between concepts" wording, and no stale "relationships between resources should be defined" wording remains in the CodeSystem/ValueSet/source checks relevant to the issue.

Recommendation:
Keep this audit commit as-is. No follow-up source work is recommended for FHIR-19731 unless a future vocabulary decision changes the CodeSystem hierarchy/property guidance itself.
