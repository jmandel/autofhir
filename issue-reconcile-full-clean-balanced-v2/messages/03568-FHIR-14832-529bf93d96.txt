FHIR-14832: Audit MedicationStatement statusReason history

Issue request:
FHIR-14832 was a Published Pharmacy change request with resolution Persuasive. It asked to replace MedicationStatement.statusReason's misleading STU3 short description "True if asserting medication was not given" with "Reason for current status", change the definition to "Captures the reason for the current state of the MedicationStatement.", and add a comment distinguishing status reason from reasonCode.

Initial application:
The Jira comment records application on Feb. 16, 2018 in SVN/git-svn build commit e4206a3abafba1275c89a32c29f2715a17e0e0e7. That commit changed source/medicationstatement/medicationstatement-spreadsheet.xml from the misleading short/definition to the requested short, definition, and comment. Later generated StructureDefinition history also carried that wording on MedicationStatement.statusReason.

Additional context:
MedicationStatement is active current-build source in source/fhir.ini, but the current MedicationStatement StructureDefinition no longer has a MedicationStatement.statusReason element. The later Published FHIR-31950 decision moved the statusReason concept to adherence.reason and made adherence a backbone; that issue is already represented on the combined branch by commit 72d020b5bc49ded7e3664bb1da2b4275e43b3a79. FHIR-38682 later renamed MedicationUsage back to MedicationStatement while retaining the status/adherence model, and the combined branch also has FHIR-32858 commit d23bc1561f2919b1feeaad8baae92334beb40992 clarifying current MedicationStatement.adherence.reason wording.

AutoFHIR reconciliation:
This audit commit makes no source change. The original FHIR-14832 wording was applied to the old statusReason element, and the current build source is already correct because that obsolete element is absent; the current MedicationStatement.reason and MedicationStatement.adherence.reason text now distinguish the reason for the medication statement from reasons tied to medication use, non-use, or adherence. The only remaining MedicationStatement.statusReason mention found in current source is a source/fhir.ini change-map entry, not an active resource element.

Recommendation:
Keep this no-change audit commit. Reintroducing or editing MedicationStatement.statusReason would conflict with the later published adherence model; future work should handle any adherence.reason wording through the already-audited FHIR-31950/FHIR-32858 family rather than through this retired STU3 element.
