FHIR-5752: Audit RiskAssessment scope clarification

Issue request:
FHIR-5752 was a Published/Persuasive DSTU1 ballot comment for FHIR-core-RiskAssessment asking that the RiskAssessment definition make clear that the resource covers both structured risk assessments, such as results from validated evaluation instruments, and subjective clinician or patient impressions of risk.

Initial application:
The issue was applied in SVN revision 5121, represented in git as 9c2e250404bf0f52ab4a9c3e13034efa3ac3c84a ({#5752} Clarified use of RiskAssessment). That commit added the current Scope and Usage paragraph explaining formal scoring/decision-support tools and practitioner subjective assessment to source/riskassessment/riskassessment-introduction.xml.

Additional context:
RiskAssessment remains an active current-build resource through source/fhir.ini. The current introduction still contains the exact formal-tool and subjective-assessment clarification, and the Background and Context section independently says risk assessments can be manual, algorithmic, combined, or decision-support generated. Jira term searches found only FHIR-5752 for the original validated-evaluation wording, and Zulip/Confluence searches found no conflicting or superseding community evidence.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current source already conveys the Jira-requested meaning in the resource narrative, so adding parallel wording to the StructureDefinition description would be redundant and could create future maintenance drift without changing implementer understanding.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-5752 unless the work group separately decides that the conformance artifact's root definition, rather than the resource page narrative, must duplicate the same clarification.
