FHIR-10524: Audit RelatedPerson role-code binding request

Issue request:
FHIR-10524 was a Published/Persuasive with Modification PA change request from the DSTU2 cycle asking RelatedPerson.relationship to include v3 RoleCode concepts under _AffiliationRoleType to support guardian and power-of-attorney use cases. The accepted resolution matched FHIR-12141: do not further enlarge the expanded RelatedPerson relationship value set; instead relax the binding from extensible, and from required in DSTU2, to preferred so local value sets can be used.

Initial application:
No git commit explicitly mentioning FHIR-10524 was found in the current repository history. The current active source nevertheless reflects the accepted effect: RelatedPerson.relationship is preferred, RelatedPerson.role is a preferred functional-role element, and the functional-role value set now includes the power-of-attorney RoleCode variants that motivated part of the request.

Additional context:
FHIR-12141, audited in the previous commit, has the same vote and resolution text for an Attorney code across RelatedPerson, Patient.contact, and CareTeam. FHIR-15841 later separated personal relationships from functional roles for Patient.contact and RelatedPerson, and FHIR-31670 later populated relatedperson-relationshiptype with WIT, NOT, POWATT, DPOWATT, HPOWATT, SPOWATT, and related contact/role concepts. FHIR-15841 and FHIR-31670 are already represented on the combined branch, so this audit does not duplicate those decisions.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source has the non-restrictive binding strength approved by FHIR-10524, and later accepted changes provide a clearer functional-role place for power-of-attorney concepts without requiring RelatedPerson.relationship to include the full requested affiliation hierarchy.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-10524 unless PA approves a new, narrower terminology expansion beyond the already-preferred bindings and existing functional-role codes.
