FHIR-5951: Audit Timing repeat bounds duration support

Issue request:
FHIR-5951 was a Published/Persuasive FHIR-core datatypes change request from DSTU1 asking that Timing support an overall duration without requiring specific dates. The recorded resolution was to change Timing.repeat.bounds to a choice element and update the definition so bounds could express duration-like limits rather than only a Period.

Initial application:
The issue was applied in SVN revision 5605, now git commit fca58ccc39dd07aaf03838155eb8654a5f713d9c, which changed source/datatypes/timing.xml from Timing.repeat.bounds with type Period to Timing.repeat.bounds[x] with type Duration | Period and revised the short/definition text to mention duration length. A tightly related follow-up, FHIR-6252, was applied in git commit 2fbb4392eeaedcf258c8e4f38bbe77af755cb2d6 and added Range plus corrected the bounds definition text.

Additional context:
The current build scope includes Timing as an active datatype in source/fhir.ini and marks Timing normative. The authoritative Timing spreadsheet currently defines Timing.repeat.bounds[x] as Duration | Range | Period with a definition covering a duration, a range of possible length, or Period start/end limits. FHIR-8344 was later Published/Persuasive with Modification as "Done under another task" because Timing.repeat.bounds[x] already had duration support, and FHIR-31559 chose an extension approach for combining start dates with duration/range rather than changing the base bounds choice. Zulip and Confluence searches did not reveal a conflicting community decision for FHIR-5951.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current active source preserves the FHIR-5951 semantic change and the later same-element refinement from FHIR-6252, so narrowing or rewording the element would be incorrect and redundant prose is unnecessary.

Recommendation:
Keep this no-change audit as-is. Future work on Timing duration/range plus explicit start-date modeling should follow the later extension-path decisions rather than reopen FHIR-5951 in the base Timing.repeat.bounds[x] element.
