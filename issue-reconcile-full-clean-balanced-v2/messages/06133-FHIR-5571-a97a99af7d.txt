FHIR-5571: Audit Questionnaire text type case sensitivity

Issue request:
FHIR-5571 was a Published/Persuasive PC work group change request for DSTU1. It identified the questionnaire-question-text-type and questionnaire-text-type code systems as incorrectly case insensitive and resolved that the codes are case sensitive.

Initial application:
The issue was explicitly applied by git commit 8668fd7cf601088670fe9b57d485549099f0bdd8 (#5571: mark as case sensitive), which changed both source/questionnaire/valueset-questionnaire-question-text-type.xml and source/questionnaire/valueset-questionnaire-text-type.xml from caseSensitive=false to caseSensitive=true. A later 2015 questionnaire/SDC refactor, commit e4f5c0d73d001a82fba48ff47d65a7154166c19c, removed those obsolete source files and replaced their extension usages.

Additional context:
Questionnaire and QuestionnaireResponse remain active resources in source/fhir.ini. The current core source and FHIR Extension Pack contain no questionnaire-question-text-type or questionnaire-text-type canonical URLs. Current Questionnaire/QuestionnaireResponse code systems in source/questionnaire and source/questionnaireresponse do not carry the erroneous caseSensitive=false setting; the active code systems relevant to the resource family either explicitly say caseSensitive=true or, for the unrelated question-max-occurs helper with only the '*' code, do not assert false. Zulip and Confluence searches found no later community decision that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because the requested case-sensitivity correction was applied in 2015 and the affected old code systems are no longer part of the current build.

Recommendation:
Keep this audit commit as-is. No follow-up is needed in core FHIR for FHIR-5571 unless a future terminology-wide policy decides to require explicit caseSensitive=true on unrelated helper code systems that currently omit the element.
