FHIR-16977: Audit datatype definitions diagram links

Issue request:
FHIR-16977 was a Published/Persuasive STU3 correction for the FHIR-core datatypes page. It reported that diagrams in the datatypes page table of contents linked to datatypes.html instead of the corresponding content on datatypes-definitions.html, and the recorded resolution was to fix the links.

Initial application:
The issue was applied in SVN r14306, represented in git as bfae89f160d2798001c532d9b7287299aa6ea82b, whose subject explicitly included GF#16977. That commit changed the then-checked-in SvgGenerator/PageProcessor so datatype-family pages generated datatype diagram links relative to the active datatype page instead of always using datatypes.html anchors.

Additional context:
The old publisher generator source touched by r14306 is no longer present in this checkout, so the current source evidence is the active datatype page inputs and the rendered CI build output produced from the current publisher. source/datatypes-definitions.html still includes the Datatypes Index diagram macros, and source/fhir.ini keeps datatypes as the default datatype page with active diagram definitions. The current CI build renders the definitions-page index with datatype diagram links pointing to datatypes-definitions.html anchors and no datatypes.html datatype links in that index.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current generated specification already satisfies FHIR-16977, and editing diagram source or narrative would be redundant and risk diverging from the publisher behavior that now selects the correct datatype-family page target.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed unless a future publisher/build regression again renders datatypes-definitions.html index diagram links to datatypes.html anchors.
