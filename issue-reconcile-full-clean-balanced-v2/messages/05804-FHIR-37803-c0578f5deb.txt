FHIR-37803: Audit large-Group operations outside core

Issue request:
FHIR-37803 was a Published FHIR-core Change Request for Group, resolved Persuasive with Modification for R5. It asked for better support for very large Groups, including paging or limiting Group.member retrieval, membership testing for enumerated and characteristic-defined Groups, expansion-like listing of characteristic-defined members, and a memberOf-style search. The accepted resolution was to define the set of operations Josh proposed in core as FMM 0/draft with an STU note that the content was provisional and retention depended on interest and adoption.

Initial application:
The issue was initially applied in core by 64dc56710e, which added source/operations-for-large-resources.html, linked it from Group and List notes, and introduced Resource large-resource add, remove, and filter OperationDefinitions. Follow-up commit 8f1052a2a0 added those operations to source/resource/list-Resource-operations.xml. Later R5 ballot follow-up commits da39345a88 and 9510c3ae69 refined the same page for FHIR-39102 and FHIR-38923. R5 release history still contains the large-resource operation definitions, confirming the original core publication surface existed for R5.

Additional context:
The current R6 core source still includes Group and the Operations for Large Resources page in build scope, but the page is now informative and only points readers to the API Incubator. Commit 270e0ceb7b, titled "normative changes for R6", removed the detailed local operation narrative and deleted the Resource-large-resource add, remove, and filter OperationDefinition XMLs from core. FHIR-I minutes in September 2025 considered the page too draft for normative progression and preferred moving it to an IG, and later Zulip discussion says the operations are moving to, and should be handled in, the incubator space. The external HL7/api-incubator-ig repository now contains the detailed operations page and three OperationDefinition sources. Related reconcile commits for FHIR-38923 and FHIR-39102 already audited the same R6 move as external-repo on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no core source change and records an external-repo decision. Re-adding the R5 draft operations to core would undo the later R6 handoff to API Incubator, while changing the core link now would be speculative because the probed build.fhir.org API Incubator operation pages currently return 404 even though the GitHub source exists. The current core source is correct as a handoff; the remaining publication or URL repair belongs with the external API Incubator IG before core can safely point at a stable rendered target.

Recommendation:
Keep this audit commit. Follow up in HL7/api-incubator-ig or its publication process to publish the Operations for Large Resources page and the add/remove/filter OperationDefinitions at stable URLs. Once that external publication is available, consider a small core edit only if the handoff URL needs to be updated.
