FHIR-21280: Audit Specimen container location

Issue request:
FHIR-21280 was a Published/Persuasive Orders and Observations change request raised against STU3 and applied for R5. It asked to add Specimen.container.location as a Reference(Location) so biobanks, oncology scenarios, and similar use cases could record where a specimen container currently resides, such as a freezer, room, or building.

Initial application:
The request was initially applied in source/specimen/structuredefinition-Specimen.xml by ceb670a418e300180a910f0b7242a033e61c7fe4, and Jira specifically cites follow-up commit 296d94523ee40ea9843fcc4e605e54fcd587c0d3 adjusting the element short description. That direct element was later removed from the active Specimen StructureDefinition by the FHIR-40559 implementation when the work group settled on representing container location through the referenced container Device.

Additional context:
Specimen, Device, and Location are active current-build resources in source/fhir.ini. Later final work in the same Specimen container family changed the model: FHIR-22823 kept Specimen.container but added a required container Device reference and points container/holder nesting through Device.parent, while FHIR-40559 explicitly removed Specimen.container.location because Specimen.container.device.location has the location information. FHIR-51580 later removed the trial-use container-location search parameter because it required resolve() and the group decided not to keep that parameter. Current source/specimen/structuredefinition-Specimen.xml has Specimen.container.device[x] and no Specimen.container.location, current source/specimen/specimen-introduction.xml points readers to Device.parent and Device.location, and source/device/structuredefinition-Device.xml defines Device.location as Reference(Location).

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding Specimen.container.location would conflict with the later applied/published Device-based container model and would duplicate the current Device.location path that the Specimen narrative already documents.

Recommendation:
Keep this no-change audit for FHIR-21280. Do not restore a direct Specimen.container.location element unless OO opens and resolves a new tracker that reverses the FHIR-22823/FHIR-40559 Device-based approach.
