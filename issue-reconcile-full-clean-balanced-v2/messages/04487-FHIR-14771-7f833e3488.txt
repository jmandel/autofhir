FHIR-14771: Audit PractitionerRole availability guidance

Issue request:
FHIR-14771 was a Published/Persuasive PA change request against FHIR-core-PractitionerRole. It asked how to associate repeated location, healthcareService, and availability values and was resolved to add guidance explaining that if availability differs by location, a separate PractitionerRole instance should be created.

Initial application:
The issue was applied by legacy commit a0a7a69e0dae891e23be5069769cb1d50f7a8ae5 ("GF#14771 clarified guidance"), which added both the brief PractitionerRole Scope and Usage sentence and a longer multiple-locations note. No commit using the later FHIR-14771 key was found, but the legacy GF#14771 commit matches the Jira key and requested text.

Additional context:
PractitionerRole is active in source/fhir.ini, and the current PractitionerRole source still carries the guidance. source/practitionerrole/practitionerrole-introduction.xml says separate PractitionerRole instances should be created when availability, telecom, or other details differ across healthcareservices or locations. source/practitionerrole/practitionerrole-notes.xml further explains that when multiple locations or specialties are represented in one instance, all details apply to all locations and different values require a new/split instance. Later refactoring changed PractitionerRole.availability to an Availability datatype with max 1, but the source still addresses the same implementer question about differing availability by location or service. The linked Zulip thread confirms the original discussion, and Confluence search found no conflicting work-group record.

This is an empty no-change audit commit. The current source already conveys the requested rule in build-scoped PractitionerRole narrative, so adding another copy to Boundaries and Relationships would be redundant and could create maintenance drift.

Recommendation:
Keep this audit commit as-is. No source follow-up is needed for FHIR-14771 unless the PA work group specifically wants an editorial relocation of the already-present guidance.
