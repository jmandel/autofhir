FHIR-13556: Audit workflow definition URI handling

Issue request:
FHIR-13556 was Published with resolution Persuasive with Modification for STU3. It asked for Definition.definition, Request.definition, and Event.definition to be able to identify externally maintained protocols, guidelines, order sets, PDFs, web pages, or other definitions by URI as well as by formal FHIR Definition references. The recorded application clarified the model to 0..* instantiatesUri plus 0..* instantiatesCanonical(Definition) for Request and Event, and 0..* derivedFromUri plus 0..* derivedFromCanonical(Definition) for Definition.

Initial application:
No Jira-keyed source commit was found for FHIR-13556. Git history shows the request was applied implicitly in f91b7989da9eb2f61dd16b9c28cb44c4f1c772aa, which replaced the old single Definition.derivedFrom, Request.instantiates, and Event.instantiates URI rows with separate canonical(Definition) and uri rows in the active workflow logical-pattern spreadsheets.

Additional context:
The active current build still lists definition, event, and request under source/fhir.ini [logical]. Current Definition source keeps Definition.derivedFromCanonical and Definition.derivedFromUri. Later Published workflow decisions, especially FHIR-29261 with FHIR-32897 and FHIR-29665, deliberately dropped the Request/Event instantiatesCanonical and instantiatesUri logical elements and replaced the overloaded instantiation concept with more precise workflow extensions. Those extensions now live in the FHIR Extension Pack and include canonical, Reference, and uri choices for the relevant Request/Event relationships.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding Request/Event instantiatesUri or instantiatesCanonical to core would contradict the later R5 workflow decision. The remaining current core source and extension-pack evidence already preserve the URI capability required by FHIR-13556 through Definition.derivedFromUri and the newer workflow extension model.

Recommendation:
Keep this no-change audit commit as-is. Do not reintroduce the old Request/Event instantiates elements for FHIR-13556. If future work wants to revisit the current workflow extension shapes or their extension-pack build status, handle that as a separate workflow-extension issue rather than as a correction to this STU3 tracker.
