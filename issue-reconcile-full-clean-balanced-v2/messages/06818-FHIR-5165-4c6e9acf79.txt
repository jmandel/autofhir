FHIR-5165: Audit Quantity comparator split

Issue request:
FHIR-5165 is Published/Persuasive with Modification. The 2015 ballot comment objected that Quantity.comparator changes Quantity semantics into a bounded value and asked for a comparator-capable measured quantity plus a no-comparator quantity constraint, with Observation.value[x], Observation.component.value[x], and QuestionnaireAnswers.group.question.answer.value[x] using the comparator-capable form.

Initial application:
The issue was applied by git commit 6073d8ce5f2495a586e8cac31b86479933fb0623, titled "#5165 - reorganize Quantity data type". That implementation did not keep the proposed MeasuredQuantity name; instead it preserved Quantity as the comparator-capable datatype and introduced SimpleQuantity as the constrained no-comparator profile/alias of Quantity in source/fhir.ini and the Quantity datatype source.

Additional context:
The current source/fhir.ini actively includes Quantity, SimpleQuantity, and MoneyQuantity in the datatype build, with Quantity and SimpleQuantity both marked normative. Current source/datatypes/quantity.xml defines Quantity as a measured amount whose comparator significantly modifies interpretation, and defines SimpleQuantity with comparator.empty() plus comparator.max=0. Observation.value[x] and Observation.component.value[x] remain Quantity, preserving the comparator-capable observation use case from FHIR-5165. QuestionnaireResponse.item.answer.value[x] is now SimpleQuantity because later final issues FHIR-37468 and FHIR-41195 intentionally constrained questionnaire quantities to the no-comparator form; that later decision supersedes the questionnaire-specific part of the 2015 disposition for the current build.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current source already carries the semantic split required by FHIR-5165, and the only apparent naming difference from the original resolution is the long-standing, subsequently relied-on implementation choice to call the no-comparator form SimpleQuantity rather than renaming the comparator-capable form to MeasuredQuantity.

Recommendation:
Keep this audit commit as-is. Do not rename datatypes or change questionnaire quantities under FHIR-5165; any future changes to comparator support should be handled by targeted follow-up issues because later published/applied issues already depend on the current Quantity/SimpleQuantity representation.
