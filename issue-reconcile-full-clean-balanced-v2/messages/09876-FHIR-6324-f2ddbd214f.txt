FHIR-6324: Audit canonical JSON links

Issue request:
FHIR-6324 was a Published/Persuasive DSTU1 FHIR-core change request asking that generated JSON view pages, such as valueset-marital-status.json.html, stop linking their "canonical form" anchor to a missing target.

Initial application:
No commit with an explicit FHIR-6324 marker was found. Jira comments record "fixed now" on 2015-07-20, and the adjacent 2015-07-19 source commit f51982040455436f5bace90a3fc1613871e6c4d4 changed the generated example templates while fixing many broken links, including removing a page-level setting from the JSON and XML example templates that could affect generated links. Later repository refactors moved the same template family into tools/templates, where the JSON page template still emits separate Raw JSON and canonical form links.

Additional context:
The current build still includes ValueSet pages and the MaritalStatus binding that produced the example URL cited in the Jira issue. The current CI build and current published specification page both render valueset-marital-status.json.html with a canonical form link to valueset-marital-status.canonical.json, and that target returns HTTP 200. Jira/Zulip/Confluence searches found no later decision requiring a different link target; FHIR-41522 appeared only as a separate no-change discussion about JSON canonicalization algorithms, not generated canonical-form page links.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active template/source state and current rendered pages already satisfy the old request, so editing the template would be redundant and risk changing correct generated output.

Recommendation:
Keep this no-change audit commit as-is. No follow-up is needed for FHIR-6324 unless a future build regresses the generated canonical form links or removes the .canonical.json outputs.
