FHIR-19645: Audit retained _query named-query behavior

Issue request:
FHIR-19645 was a Published/Not Persuasive with Modification FHIR-I clarification for R5. It asked to deprecate _query as subsumed by custom operations, but the final decision kept _query and required clarifying that query operations are only base/type level, return search Bundles, support search mechanisms such as paging, _sort, _include, and _revinclude that custom operations generally do not, and require kind=query input parameters to declare searchType.

Initial application:
The earlier deprecation resolution was reopened in 2022. Source commit 0d3162cfbb9fbd27bc071508bdde6ed46a182f92 applied the retained-_query direction together with FHIR-28110, adding OperationDefinition constraints for query instance=false and input searchType, and revising search.html's named-query guidance. Later related commits and reconciliations refined examples and parallel OperationDefinition notes without removing _query.

Additional context:
FHIR-I minutes from 2022-08-08 record the work group discussing FHIR-19645 together with FHIR-28110 and FHIR-34406 and deciding Not Persuasive with Modification by 13-0-1. The current source has active build-scope Search narrative through publish.ini and source/hierarchy.xml, and OperationDefinition is active in source/fhir.ini. Related FHIR-28110 is audited by this worker; FHIR-34406, FHIR-31491, FHIR-39316, and FHIR-39318 are already represented on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Search page retains _query, limits named-query OperationDefinitions to base/type search contexts, explains that named queries are searches with standard and resource-scoped search parameters potentially available, and documents non-$code invocation. The OperationDefinition structure definition includes query constraints for instance=false, input searchType, and a single result Bundle output parameter, and the notes page describes named queries as search interactions.

Recommendation:
Keep this audit commit as-is. The current specification reflects the work group decision not to deprecate _query while documenting the constraints and search-behavior advantages that justified retaining it.
