FHIR-8449: Audit OperationOutcome issue code model

Issue request:
FHIR-8449 was a Published/Persuasive with Modification FHIR-core OperationOutcome change request from DSTU1. It questioned whether OperationOutcome.issue.code should remain a CodeableConcept with a required binding or become a primitive code, while preserving an extension point for more specific local issue codes.

Initial application:
The issue was applied by git-svn commit 8f9d370156502bee2cc1371a3c97f28a1588ed2a, svn revision 6027, which reworked OperationOutcome.issue coding. That commit changed issue.code from CodeableConcept to primitive code, updated examples to use code values, and made issue.details the CodeableConcept place for more specific issue information.

Additional context:
FHIR-8449 intentionally revised the earlier FHIR-5622 implementation. FHIR-5622 had made the old issue type/code a CodeableConcept; FHIR-8449 resolved the tension between a required IssueType binding and local codes by keeping issue.code interoperably required and moving local CodeableConcept detail to issue.details. The active current source/fhir.ini includes operationoutcome as a built resource.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current source/operationoutcome/structuredefinition-OperationOutcome.xml defines issue.code as primitive code with required IssueType, issue.details as CodeableConcept with example IssueDetails binding, and issue.diagnostics as string. Current OperationOutcome examples use primitive issue.code and optional details content, matching the approved FHIR-8449 shape.

Recommendation:
Keep this audit commit as-is. Future changes to OperationOutcome issue coding should be handled as new work-group decisions rather than by reapplying the pre-FHIR-8449 CodeableConcept issue.code model.
