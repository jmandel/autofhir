FHIR-17279: Clarify ImagingStudy modality binding text

Issue request:
FHIR-17279 was Published/Persuasive with Modification for R5 by Imaging Integration. It asked whether ImagingStudy.modality and ImagingStudy.series.modality should remain acquisition-only CID 29/extensible bindings; the final resolution selected DICOM CID 33 Modality, kept an extensible binding, removed acquisition-only terminology if unused, and updated the ImagingStudy modality definitions to include both acquisition and non-acquisition modalities.

Initial application:
The issue was initially applied in e64cab69af, a combined ImagingStudy update commit that changed the old ImagingStudy spreadsheet from DICOM CID 29 to CID 33 and changed the ImagingStudy.modality and ImagingStudy.series.modality descriptions away from acquisition-only wording. Later source refactoring moved the authoritative resource definition into source/imagingstudy/structuredefinition-ImagingStudy.xml.

Additional context:
ImagingStudy is an active current-build resource in source/fhir.ini and belongs to the Imaging Integration work group. Current source already used the DICOM CID 33 value set with extensible strength, and later FHIR-50775/FHIR-53181 wording updates preserved the acquisition/non-acquisition distinction. Community searches found no Confluence or Zulip record for FHIR-17279 itself; related Zulip terminology discussion after the 2019 application confirms that the DICOM CID 33 external value set was intentionally used rather than a copied core value set.

AutoFHIR reconciliation:
This commit fixes the remaining stale conformance text in the two ImagingStudy CID 33 bindings. Both binding.description values now describe DICOM Modality values including acquisition and non-acquisition modalities, instead of saying only "Type of acquired data in the instance." No binding strength, value set URL, cardinality, or element definition changed.

Recommendation:
Keep this source change. A future publisher build should regenerate any rendered artifacts from the corrected StructureDefinition; broader cleanup of identical CID 33 binding descriptions on other resources should be tracked separately if the work group wants that sweep.
