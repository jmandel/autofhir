FHIR-13808: Audit scheduling search parameter alignment

Issue request:
FHIR-13808 was Published with a Persuasive with Modification resolution for STU3 scheduling search-parameter alignment. It requested Schedule service-category/specialty plus type renamed to service-type; Slot service-category/specialty/appointment-type plus slot-type renamed to service-type; Appointment service-category/specialty plus reason-reference, reason-code, and supporting-information based on FHIR-18829; and HealthcareService specialty/coverage-area plus type/category/programname search-parameter renames.

Initial application:
The explicit historical application is git 28a69ce87d75315e2ba423a04c9e1f9e717b9a75, whose subject is "GF#13808 Update search parameters across Slot, Schedule, Appointment, Encounter and HealthcareService" and which updated the then-authoritative Schedule and Slot spreadsheets. Later source restructuring in git 33b409a4b6d544598262f2f074ebb4b6dc466157 introduced the current checked-in search-parameter bundles for Appointment, HealthcareService, Schedule, and Slot.

Additional context:
The affected resources are active in source/fhir.ini. Current source bundles contain the requested Schedule and Slot search parameters, Appointment contains service-category, specialty, reason-code, reason-reference, and the active Appointment.supportingInformation parameter under the current code supporting-info, and HealthcareService contains specialty, coverage-area, service-category, service-type, and the current program token parameter. FHIR-18829 is the referenced Appointment/Encounter reason-modeling decision, while FHIR-19357 explains the later HealthcareService programName-to-program CodeableConcept model that makes a literal program-name search parameter inappropriate now.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source already carries the seed issue's conformance effect, and changing supporting-info to supporting-information or program to program-name would conflict with later/current resource modeling rather than complete FHIR-13808.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-core unless a separate work-group decision explicitly reopens the current search parameter codes for Appointment.supportingInformation or HealthcareService.program.
