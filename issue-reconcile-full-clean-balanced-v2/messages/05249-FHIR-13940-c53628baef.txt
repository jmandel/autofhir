FHIR-13940: Audit ValueSet code search support

Issue request:
FHIR-13940 was a Published/Persuasive Vocabulary change request from STU3 asking FHIR-core to let clients search ValueSet by code, e.g. ValueSet?code=http://loinc.org|1234-5, so implementers could find reusable value sets. The accepted resolution required adding the ValueSet code search capability and a TerminologyCapabilities declaration for whether the server searches definitions, expansions, or both.

Initial application:
The issue was applied in svn/git import commit 6826aa32162838368e2e38376119ff0b90e35b95 (#13940, svn r12750), which added the ValueSet search notes, the TerminologyCapabilities.codeSearch element/example, and the original ValueSet code search parameter to the then-current spreadsheet source. Commit e0f69bc5cb8aa9ec01633efea90d88bacb2f8ef3 immediately corrected the search expression to select expansion codes. The later 2021 source rework carried the same capability into the current XML bundle and resource StructureDefinition sources.

Additional context:
Current source/fhir.ini actively includes ValueSet and TerminologyCapabilities resources, so the checked source files feed the current build. Later FHIR-17792 replaced the confusing original CodeSearchSupport values with in-compose, in-expansion, and in-compose-or-expansion, and that related issue is already represented on the combined branch. Later FHIR-49784 changed ValueSet-code to use repeat(contains), preserving the seed behavior for nested expansions. Community searches found no conflicting FHIR-13940-specific record; the relevant Zulip thread confirms the intended distinction between compose and expansion support.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current ValueSet-code SearchParameter searches ValueSet.expansion.repeat(contains).code and ValueSet.compose.include.concept.code, the ValueSet notes explain the cost/context of the search and point to TerminologyCapabilities, and TerminologyCapabilities.codeSearch has the required binding to CodeSearchSupport.

Recommendation:
Keep this no-change audit commit as-is. No FHIR-core follow-up is needed for FHIR-13940; any future work should be driven by a new decision about broader ValueSet reverse-lookup behavior or terminology-server implementation guidance rather than by this already-applied STU3 tracker.
