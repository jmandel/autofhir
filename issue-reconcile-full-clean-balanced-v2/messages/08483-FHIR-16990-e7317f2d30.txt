Issue request:
FHIR-16990 was a Published/Persuasive FHIR-core Element page change request asking that the XML/JSON representation examples stop using an element named 'code' of type Coding, because that confused element names with the primitive code datatype.

Initial application:
The Jira comment records svn 14305. In the git mirror, commit 3f47c0507c60e581b62ea07dfa0fe31add7539b4 (GF#16990 - clarify language) is the corresponding application: it changed the Coding examples from code to use and changed the primitive examples to a code-valued status element/property.

Additional context:
The historical source/element.html page was moved into source/types.html by the abstract type framework rebuild in cbdf7d1e55, preserving the corrected example names. FHIR-18414 later decided to remove the whole XML/JSON Representation of Elements section as redundant with the syntax pages, and commit 7c6b930880820a97fb1515a3ec096dfc24130a7e removed it from source/types.html. The current build still has Element active as an abstract infrastructure type in source/fhir.ini, but the current source/types.html Element section no longer contains the confusing code/Coding example.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The originally requested wording problem was applied in 2018 and the current build source no longer contains the affected example section at all.
