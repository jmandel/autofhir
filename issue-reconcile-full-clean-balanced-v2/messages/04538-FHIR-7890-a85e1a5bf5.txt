FHIR-7890: Audit Claim original prescription clarification

Issue request:
FHIR-7890 was a Published/Persuasive FM clarification request from the 2015May ballot asking the specification to elaborate the difference between Claim.prescription and Claim.originalPrescription. The Jira resolution specifically asked to add an example explaining that when a fulfiller supersedes the original prescription with an alternate having the same therapeutic intent, the fulfiller's prescription is Claim.prescription and the earlier prescriber's order is Claim.originalPrescription.

Initial application:
The requested clarification appears to have been applied before this reconciliation in git commit 22d93a5dadf63d5f0ad563ac0560e61f03013e88, which added the example text to the then-authoritative Claim spreadsheet source. The later source conversion carried the content into source/claim/structuredefinition-Claim.xml, with spelling corrected and the example split into the element comment.

Additional context:
Claim is active in source/fhir.ini, so source/claim/structuredefinition-Claim.xml is in current build scope. Later related changes FHIR-17921 and FHIR-41258 adjusted the allowed target resource choices for Claim.prescription and Claim.originalPrescription, and both already have Issue-Reconcile-Key audit commits on the combined branch. Those changes do not alter the FHIR-7890 clarification. A 2024 Zulip implementers thread asks about the same elements and is consistent with the current source distinction; Confluence and direct issue-key Zulip searches found no conflicting evidence.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Claim.originalPrescription definition and comment already explain that originalPrescription is the prior prescription superseded by the fulfiller's prescription, including the physician/pharmacy alternate-medication example requested by FHIR-7890.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-7890 unless the FM work group later wants a broader redesign of Claim prescription cardinality or line-level prescription modeling, which would be a separate issue from this published clarification.
