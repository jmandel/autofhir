FHIR-5581: Audit openAtEnd discouraged wording

Issue request:
FHIR-5581 was a Published/Persuasive DSTU1 FHIR-core datatypes request to add language discouraging openAtEnd because it creates interoperability issues by enforcing ordering.

Initial application:
The request was applied in the imported SVN history by git commit 8349666a9e471630178f9caa97d3452153062d54, which corresponds to Jira's svn 4491 comment and changed source/datatypes/elementdefinition.xml to add the warning to the openAtEnd code definition.

Additional context:
ElementDefinition is active in the current build as a normative datatype. The SlicingRules binding in source/datatypes/elementdefinition.xml points to #resource-slicing-rules, whose openAtEnd row still says that it requires ordered slices, makes sharing uses hard, and should only be done where absolutely required. Later FHIR-34142 added a warning invariant that also catches openAtEnd when orderMeaning is absent, reinforcing rather than reversing the FHIR-5581 guidance.

AutoFHIR reconciliation:
No source change was made. The current authoritative datatype spreadsheet already carries the requested discouraging language in the openAtEnd definition, and adding more local prose would be redundant.

Recommendation:
Keep this audit commit as-is. No follow-up is needed in FHIR core unless a future work group decision changes the slicing model or removes openAtEnd.
