FHIR-5236: Audit extensibility example clarification

Issue request:
FHIR-5236 was a Published/Persuasive DSTU1 ballot comment on FHIR-core-extensibility asking why the clinical trial opt-in complex-extension example lacked an element like the earlier HumanName "Chief Red Cloud" example, whether complex extension fields can have text for each field, and whether the HumanName example was actually about extensions.

Initial application:
The issue was applied by svn revision 4601, imported as Git commit 7631a420ec7328b59b0e8ef3ebda059bcd7e6e9b, which added explanatory text saying the "Chief Red Cloud" text belonged to the extended HumanName and clarified complex extension content as a nested tree of values with locally relative parts. No additional source application is needed for the original request.

Additional context:
The current build uses source/extensibility.html for the Extension type page via source/fhir.ini. Later extensibility-example work changed the clinical-trial example under FHIR-7804, replaced it with patient-citizenship examples under FHIR-14296 after the clinical-trial extension was removed, and added RDF examples in 2023 without removing the original clarification. The current page states that simple extensions have a value and complex extensions have nested extensions, explains that the HumanName text is the name being extended, and presents complex extension fields as nested extension/value pairs rather than separate text elements.
