FHIR-3002: Audit retired Observation reliability request

Issue request:
FHIR-3002 was a Published OO change request for the DSTU1 Observation resource. It began as a request to add microbiology-oriented presumptive and confirmed concepts to the ObservationReliability value set, but the final Persuasive with Modification resolution instead changed Observation.reliability cardinality from 1..1 to 0..1, replaced the reliability note, and clarified the unknown code definition as an observation reliability value.

Initial application:
No current git commit explicitly mentions FHIR-3002. Historical source search shows the old Observation.reliability / ObservationReliability machinery existed in early Observation source, but a later published Observation issue, FHIR-7154, removed the reliability element from Observation in commit 54f14f427c. A subsequent #8479 Observation binding cleanup removed the residual ObservationReliability binding row from the Observation spreadsheet source.

Additional context:
The current build actively includes Observation through source/fhir.ini, and the current authoritative Observation StructureDefinition has Observation.status, Observation.dataAbsentReason, and Observation.interpretation but no Observation.reliability element. Source search found only a retained bindings.ini identifier and an old QUICK model-definition Library example mentioning ObservationReliability; neither is the active Observation resource or the retired observation-reliability value set. FHIR-7154 is already represented on the combined branch, so this commit does not duplicate that related audit.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Reintroducing Observation.reliability, adding presumptive/confirmed concepts, or editing the stale QUICK example would contradict the later published removal of the Observation reliability element and would not improve the current Observation specification.

Recommendation:
Keep this no-change audit. Future work should not revive ObservationReliability in core unless OO makes a new current-version decision; any quality/signal-quality requirement should be handled through a fresh tracker and current Observation modeling, not through this retired DSTU1 element.
