FHIR-15838: Audit detailed descriptions cardinality label

Issue request:
FHIR-15838 was a Published/Persuasive STU3 change request asking whether the Resource Detailed Descriptions tab label "Control" should instead be "Cardinality" and link to conformance-rules.html#cardinality rather than #conformance. The accepted resolution was to rename Control to "Cardinality" and change the link.

Initial application:
The issue was applied by git commit 7803ddf08984e8598431cbd793a6301e5bd195c4, which changed the old DictHTMLGenerator renderer from tableRow("Control", "conformance-rules.html#conformance", ...) to tableRow("Cardinality", "conformance-rules.html#cardinality", ...) in both detailed-description generation paths.

Additional context:
Current core source no longer carries tools/java/org.hl7.fhir.tools.core/src/org/hl7/fhir/definitions/generators/specification/DictHTMLGenerator.java. The active Gradle build depends on org.hl7.fhir:kindling 1.25.5-SNAPSHOT and runs org.hl7.fhir.tools.publisher.Publisher; the template for Resource Detailed Descriptions injects <%dictionary%>, so the label/link are produced by kindling. The current HL7/kindling renderer and build.fhir.org Device detailed-description page both show the resolved "Cardinality" label linked to conformance-rules.html#cardinality. No Zulip or Confluence evidence was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The accepted renderer behavior is already present in the current rendering toolchain and current build output, and adding redundant local prose or editing stale generated output would not improve the specification.

Recommendation:
Keep this audit commit as-is. No follow-up is needed in the core FHIR checkout unless a future kindling update regresses the generated Detailed Descriptions label or link.
