FHIR-39248: Audit SFCU specified definition

Issue request:
FHIR-39248 is an Applied FHIR-core Patient Administration change request with a Persuasive with Modification resolution. It asked how the Sex for Clinical Use value "specified" relates to intersex, and the approved resolution says intersex patients may be classified as specified when the intersex condition is relevant for the care being provided. The approved terminology change was to add that the terms "Other" or "Complex" may be considered synonyms of "Specified" to the definition of the specified concept.

Initial application:
No FHIR-core git commit was found that explicitly mentions FHIR-39248. The relevant Sex for Clinical Use terminology existed in core during R5 development, was renamed as part of the FHIR-39219 Sex Parameter for Clinical Use work, and was later removed from core by f3c0d3659c when Gender Harmony terminology moved out of the core repository. The FHIR Extension Pack then removed the SPCU CodeSystem and ValueSet in 7e35b16 because those terminology resources had moved to THO.

Additional context:
The Jira comment says the issue was resolved via UP-461, but local Jira and Confluence searches did not find UP-461. UP-452 contains the same requested definition text, references FHIR-39248 as Pro Forma Information, is Proposal Implemented, and THO 5.3.0 release notes list UP-452. The current THO CodeSystem http://terminology.hl7.org/CodeSystem/sex-parameter-for-clinical-use version 2.0.0 includes the requested "Other"/"Complex" sentence on the specified concept and a history row for up-452. Current core source has no local SFCU/SPCU CodeSystem or ValueSet definition; its remaining Patient example points at the THO CodeSystem and the Patient narrative points to the Extension Pack extension.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no core source change. The authoritative terminology source for the requested definition is outside this FHIR-core checkout, and the external THO artifact already carries the approved definition.

Recommendation:
Keep this external-repo audit commit as-is. Future changes to the specified concept definition should go through UTG/THO rather than editing the FHIR-core source; core should only be revisited if a core-owned narrative starts contradicting the THO definition.
