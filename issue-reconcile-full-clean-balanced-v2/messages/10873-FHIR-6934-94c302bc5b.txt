FHIR-6934: Audit URI search escaping guidance

Issue request:
FHIR-6934 was a Published FHIR-I change request resolved as Persuasive with Modification for DSTU1. It asked how URI search values should be escaped when a search parameter uses comma-delimited OR semantics and one URI value itself contains a comma or other URL-escaped characters. The accepted resolution directed the spec to explain that percent encoding gets characters to the FHIR server, while FHIR backslash escaping distinguishes search delimiters after query parsing, and to add a NamingSystem note discouraging system identifier URIs that contain backslash, question mark, or comma.

Initial application:
The Jira comments record SVN revision 6534. The migrated git-svn commit c1eef260f554e28cdcf75064a00d41627b05e095, titled "#6934 - add note about escaping" and carrying git-svn build@6534, applied the issue by adding ValueSet URL escaping examples to source/search.html and adding the requested NamingSystem identifier warning to source/namingsystem/namingsystem-spreadsheet.xml. Later source-format refactors moved the NamingSystem content into the current StructureDefinition XML, where the warning is still present.

Additional context:
The same search.html escaping section was later reworded by e45b3e06685838ef5be827524cd4915ae0f9d214 for GF#17464 and then corrected by the FHIR-42834 reconciliation commit 9fd56a094161229b765cdcb8a626f4e744793545, which is already on the combined branch. Those later changes refined examples but did not reverse FHIR-6934's two-layer escaping rule. FHIR-6933 is the same report resolved Not Persuasive with a comment to see FHIR-6934, so it is background rather than a separate source-edit decision here. Zulip and Confluence searches found no directly relevant or conflicting community record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/search.html is the active FHIR-core search page and its escaping section explains that backslash escaping is distinct from RFC 3986 percent encoding, shows same-meaning percent-encoded URL forms, and separately shows that a backslash-escaped comma inside a ValueSet url yields two literal URI search values rather than three comma-delimited values. Current source/namingsystem/structuredefinition-NamingSystem.xml, for the active NamingSystem resource listed in source/fhir.ini, still carries the requested warning against hard-to-escape FHIR system identifier URI characters.

Recommendation:
Keep this empty audit commit as-is. FHIR-6934 is already correctly represented in the current build-scope source; further edits for this historical issue would be redundant and risk diverging from later FHIR-42834/FHIR-48702 cleanup work.
