FHIR-3292: Audit Alert.note cardinality supersession

Issue request:
FHIR-3292 was a Published/Persuasive Patient Care change request raised against the initial Alert resource and applied for DSTU1. It proposed changing Alert.note from 1..1 to 0..1, adding a 0..1 Alert.code CodeableConcept, adding a constraint that at least note or code exist, and providing guidance on code versus original text.

Initial application:
No standalone current source change remains that exactly implements separate optional note and code elements. The historical source trail shows that #3523 first changed Alert.note itself to CodeableConcept while retaining 1..1, and commit db4ace37c6615c9732f958d34d6286fe739fc657 later cited {#3292} among PC-approved Alert/Flag change requests while renaming Alert.note to Flag.code and carrying forward a 1..1 CodeableConcept.

Additional context:
FHIR-3523 and FHIR-3877 are same-family Published decisions after the original FHIR-3292 request. They converged on a single required CodeableConcept rather than separate note and code elements, preserving required alert text through CodeableConcept.text while allowing coded values through CodeableConcept.coding. FHIR-3877 is already represented on the combined branch by d46dfb8b0234981dc2d8865005397ad7d134be60. The current build scope is Flag, not removed Alert, and later FHIR-8560/FHIR-11202 refinements confirm the current Flag.code binding and coded/textual wording. Community searches found no relevant conflicting discussion; a Confluence refs search for FHIR-3292 only surfaced an unrelated Security WG page where the string appeared as a prefix of other Jira keys.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Changing the current source to the literal early FHIR-3292 shape would undo later final decisions by reintroducing separate note/code elements and weakening the required Flag.code model.

Recommendation:
Keep this audit commit as-is. Treat FHIR-3292 as superseded by the later Alert.note CodeableConcept decisions; do not add a parallel Flag.note or make Flag.code optional without a new applied/published tracker.
