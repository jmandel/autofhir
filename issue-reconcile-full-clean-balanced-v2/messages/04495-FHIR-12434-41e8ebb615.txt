FHIR-12434: Audit answerInstant removal

Issue request:
FHIR-12434 was a Published/Persuasive Patient Care change request for DSTU2 asking to remove answerInstant from Questionnaire(Response). The decision was based on instant being intended for precisely observed/system times rather than human-entered questionnaire answers.

Initial application:
The application appears in git commit bd819cfbf9a33c335e7030ff69591f11f7a57882, which explicitly mentions #12434 and removes instant from the then-authoritative Questionnaire and QuestionnaireResponse spreadsheet sources: Questionnaire.item.enableWhen.answer[x], Questionnaire.item.initial[x], QuestionnaireResponse.item.answer.value[x], and the Questionnaire item-type code list.

Additional context:
The referenced Zulip thread records Michelle Miller confirming the exact scope of the approved tracker: remove Questionnaire.item.enableWhen.answerInstant, Questionnaire.item.initialInstant, the instant item-type code, and QuestionnaireResponse.item.answer.valueInstant; Lloyd McKenzie confirmed that scope. Current build-scope checks show Questionnaire and QuestionnaireResponse are active resources in source/fhir.ini, and the current StructureDefinition/CodeSystem source still provides date/dateTime/time without an instant choice for those questionnaire answer surfaces. No related Jira issue or Confluence record was found that changes this conclusion.

AutoFHIR reconciliation:
This audit made no source change. The requested removal is already present in the current core source, including the active QuestionnaireResponse answer value choices, the Questionnaire enableWhen/initial/answer option choices, and the Questionnaire item-type code system.

Recommendation:
Keep this no-change audit commit as-is. No core follow-up is recommended unless the work group opens a new issue to reintroduce or further constrain instant-valued questionnaire answers.
