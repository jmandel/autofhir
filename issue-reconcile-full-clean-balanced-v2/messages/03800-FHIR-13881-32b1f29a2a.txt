Issue request:
FHIR-13881 was a Published/Persuasive with Modification Pharmacy change request for STU3 MedicationDispense. It asked to clean up MedicationDispense status definitions around dispense phases and pickup, and its final resolution required applying the follow-up definitions and renaming the former Not-Done status to Cancelled.

Initial application:
The Jira snapshot records application on 2018-02-16 in git-svn commit e4206a3abafba1275c89a32c29f2715a17e0e0e7. That commit changed the then-authoritative MedicationDispense spreadsheet so MedicationDispense.status was required, the short status list used cancelled instead of not-done, and the status code definitions for in-progress, cancelled, on-hold, and completed matched the follow-up comments. Later source refactors moved this terminology into the current source/medicationdispense CodeSystem and related conformance files.

Additional context:
MedicationDispense is active in source/fhir.ini, so the current source/medicationdispense CodeSystem, ValueSet, StructureDefinition, examples, and source/status-codes.xml status table are current build inputs. The current CodeSystem retains the FHIR-13881 semantics for preparation, in-progress, cancelled, on-hold, completed, and entered-in-error. A later Applied Pharmacy issue, FHIR-40692, intentionally changed the old stopped status to unfulfilled and refined related status terminology for R6; that issue is already represented on the combined branch by commit 79ecb41f09ac5a4869795f7fca29481c6613e938, so this seed should not re-decide or reverse it. Confluence references for FHIR-13881 were absent, and direct Zulip searches found no conflicting discussion.
