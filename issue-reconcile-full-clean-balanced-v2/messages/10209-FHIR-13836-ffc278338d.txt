FHIR-13836: Audit base _type search rule

Issue request:
FHIR-13836 was a Published/Persuasive FHIR-core search change request for STU3. It asked the search page to clarify root-level searches by adding that, when the _type parameter is present, all other search parameters SHALL be common to all provided resource types, and when _type is absent, all parameters SHALL be common to all resource types.

Initial application:
The issue was applied in SVN revision 13878, now git commit 5d3347c67a57eeedfa55827c86442aa70a333a64, which changed source/search.html to add the requested _type clarification to the "All resource types" search context. Later search-page refactors moved and reformatted the text, but preserved the normative rule in the current Search Contexts section.

Additional context:
The original Zulip thread linked from the Jira records the implementation concern: root searches with _type should allow parameters shared by the requested types, while searches without _type remain limited to parameters common to all resources. Earlier related core issues FHIR-5700 and FHIR-10459 explain the pre-existing root-level search context and URL form, but do not supersede FHIR-13836. No Confluence reference or later conflicting community evidence was found for FHIR-13836.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source/search.html text already says that if _type is included, all other search parameters SHALL be common to all provided types, and if _type is not included, all parameters SHALL be common to all resource types. The current _type section also gives an example where _type=Observation,Condition&patient=Patient/123 is valid only because patient is valid on both resources.

Recommendation:
Keep this empty audit commit as-is. The current FHIR source satisfies the published issue, and adding more prose would duplicate existing normative guidance without changing implementer understanding.
