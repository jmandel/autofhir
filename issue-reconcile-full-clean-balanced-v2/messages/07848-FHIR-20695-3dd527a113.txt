FHIR-20695: Audit workflow pattern variance tooling

Issue request:
FHIR-20695 was Published/Persuasive with Modification for R5. It asked for the Event, Request, Definition, and FiveWs pattern variance tables to expose enough detail for review: optionally link to downloadable spreadsheets, add a legend, and formalize documentation of suppressed workflow-warning overrides so intentional missing or divergent pattern mappings can carry explanations while unexplained variances can still be flagged.

Initial application:
No current git commit explicitly names FHIR-20695. The application appears to have been split across nearby pattern/tooling work: Grahame added pattern support and pattern analysis pages in May 2019, FHIR-20621 later added the shared logical-pattern mapping legend to tools/templates/template-logical.html, and the March 2023 mapping-exceptions work added structured per-resource files plus schema support for unmapped/divergent pattern elements and reason attributes.

Additional context:
The current build scope lists definition, event, request, and fivews as active logical models in source/fhir.ini. The shared logical template renders a Mappings section with a legend for cell counts, colors, and E/N/T/C flags, while the logical-analysis template renders the Detailed Cross Analysis pages. Current source has mappingExceptions schema support and 230 mapping-exception files, replacing the older raw suppressed-warning list as the maintainable place to document intentional variances. External current-build checks show the analysis pages render cross-analysis tables; the optional spreadsheet URLs are not published, which is consistent with the Jira resolution saying a spreadsheet link might not be necessary.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The mandatory parts of the accepted resolution are already represented by active logical-pattern templates, analysis pages, the shared legend, and structured mapping-exception rationale files. Adding broad prose or a broken spreadsheet link from this seed would be redundant or unsafe, and remaining per-resource rationale cleanup belongs in resource-specific workflow trackers.

Recommendation:
Keep this audit commit as-is. Revisit only if FHIR-I explicitly wants publisher-level changes to publish logical-pattern spreadsheet artifacts or a separate legend on the Detailed Analysis pages; otherwise continue using resource-specific mapping-exception files and trackers for missing rationales.
