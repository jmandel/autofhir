FHIR-10529: Audit SpecimenDefinition resource availability

Issue request:
FHIR-10529 was Published with a Persuasive O&O resolution. It asked FHIR core to introduce SpecimenDefinition as a new resource, derived from Specimen-style specimen requirements without instance-only fields such as status and subject, so eDOS/laboratory catalog orderables could describe specimen collection requirements and be used from ActivityDefinition.

Initial application:
No git commit explicitly names FHIR-10529. The apparent source application is git commit 8cb3819831ae04dbab4d6ce22eb9f73b736e4090, which added the SpecimenDefinition resource source and fhir.ini registrations as part of the 2017 Catalog/SOA work. The dependent ActivityDefinition side was applied separately for FHIR-10528 at SVN 12592 by commit c890d2deb85cbdbc98047ae7f8e9b57cd09186c0.

Additional context:
SpecimenDefinition and ActivityDefinition are both active current-build resources in source/fhir.ini, and SpecimenDefinition is a concrete resource StructureDefinition. ActivityDefinition currently has specimenRequirement as a repeating canonical targetting SpecimenDefinition. That canonical datatype is intentional because later Published issue FHIR-32751 changed the ActivityDefinition requirement references from Reference to canonical. Later FHIR-20553 withdrew a proposed backbone-element reshaping of specimenRequirement. Later FHIR-54837 is related to SpecimenDefinition relationship narrative and the stale Catalog-resource bullet, but its workflow status is Triaged, so it is not a final source-edit decision for this default Applied/Published reconciliation.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build-facing source already contains the requested SpecimenDefinition resource and the ActivityDefinition use point needed by the seed. Editing SpecimenDefinition relationship prose now would either be redundant for FHIR-10529 or would preempt the separate, not-yet-final FHIR-54837 narrative cleanup.

Recommendation:
Keep this empty audit commit as-is. No core FHIR follow-up is needed for FHIR-10529 itself; handle the Catalog-resource relationship bullet and added relationship bullets only through FHIR-54837 or a later final work-group decision.
