FHIR-14104: Audit PACP FormatCode terminology handoff

Issue request:
FHIR-14104 was a Published/Persuasive with Modification STU3 DocumentReference and terminology-valuesets issue requesting two PACP 1.0 format codes, urn:hl7-org:sdwg:pacp-structuredBody:1.0 and urn:hl7-org:sdwg:pacp-nonXMLBody:1.0, be added to the FHIR Format Code Value Set. The final resolution broadened the implementation path: create an HL7-managed code system through harmonization, add the new HL7 codes there, verify the code/version modeling, and update the IHE/FHIR format-code value set composition to include the new HL7-managed content.

Initial application:
The direct source-history application started in git commit cc53370316b463e09e710d62a51582332a5832e4, which was explicitly labeled FHIR-14104 and updated source/documentreference/valueset-formatcodes.xml to compose IHE, HL7 document format, and DICOM format-code sources. Jira comments record that this local composition failed in the core build. The final merged PR #1710 application, ad1b6c072ad346fd59fbccea8e0409d27acf9abf, includes commit 6f1b3314e9956e3c1eb469c13860238345e02d20, which removed the obsolete core-local valueset-formatcodes.xml and changed the active DocumentReference binding to the THO-managed http://terminology.hl7.org/ValueSet/v3-HL7FormatCodes value set.

Additional context:
Current R5/R6 core source no longer has DocumentReference.content.format as the element name; FHIR-32583 changed it to DocumentReference.content.profile.value[x], with source/fhir.ini preserving the migration map from DocumentReference.content.format to content.profile. DocumentReference remains active in source/fhir.ini, and the current authoritative resource source binds DocumentReference.content.profile.value[x] to http://terminology.hl7.org/ValueSet/v3-HL7FormatCodes. The cached hl7.terminology.r5#5.3.0 package shows that ValueSet v3-HL7FormatCodes composes the IHE format code system and http://terminology.hl7.org/CodeSystem/v3-HL7DocumentFormatCodes, and that the HL7 Document Format Codes code system contains both requested PACP 1.0 concepts. Zulip and Confluence evidence show the intermediate uncertainty around how to publish the HL7 and IHE code systems, followed by UP-241 creating the THO value set and confirming that the value set was fully defined and expanding.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The requested PACP 1.0 codes are now in THO, the current core build binds DocumentReference to the THO value set that includes them, and restoring a core-local source/documentreference/valueset-formatcodes.xml would reverse the later terminology handoff and duplicate externally managed terminology.

Recommendation:
Keep this no-change audit commit as-is. Future additions or corrections to PACP or other document FormatCode concepts should go through THO/UTG or the IHE FormatCode package, unless a separate FHIR-core Jira explicitly asks to change the DocumentReference binding itself.
