FHIR-43028: Audit Coverage.order clarification

Issue request:
FHIR-43028 was an Applied FHIR-core Financial Management change request asking to clarify how Coverage.order should be used relative to Account.coverage.priority. The final Not Persuasive with Modification resolution directed the spec to add that Coverage.order conveys use-case-independent COB ordering, while use-case-dependent coverage sets belong in Account.coverage.priority.

Initial application:
No prior AutoFHIR reconcile commit exists on the combined branch for FHIR-43028. The Jira-tagged implementation commit 69ee02c04f6590507f2ac9fc4b0d0461e1416ab0, merged by ce69f716691ef214a4ce5f0c0283484962cb4466, updated source/coverage/structuredefinition-Coverage.xml to add the requested clarification and correct the existing "applicatble" typo.

Additional context:
Coverage and Account are active build resources in source/fhir.ini. The current Coverage.order definition contains the resolution sentence and Account.coverage.priority still defines the account-context priority. Earlier FHIR-27106 expanded the Coverage.order example, and FHIR-27107 recorded that Coverage.order and Account.coverage.priority are similar but context-dependent. Zulip and PA/FM meeting minutes show the confusion that led to FHIR-43028, but no discovered later final decision reverses the applied wording.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source already conveys the approved distinction between use-case-independent Coverage.order COB ordering and use-case-dependent Account.coverage.priority ordering.

Recommendation:
Keep this audit commit as-is. Future work should occur only if FM/PA makes a new substantive decision about whether Coverage.order should be aligned with, constrained by, or replaced by Account.coverage.priority.
