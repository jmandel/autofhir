FHIR-2889: Audit resource XML metadata availability

Issue request:
FHIR-2889 was a Published/Persuasive change request asking that metadata such as profile identifiers/tags be expressible and accessible in ordinary XML resource instances and resource-level schemas, without needing a FHIR server, an extension, or the old full fhir.atom wrapper schema.

Initial application:
Jira records the issue as done as part of FHIR-3728. FHIR-3728 was the Published/Persuasive Atom replacement issue, approved in November 2014, and its implementation commits removed Atom wrappers and added resource-level metadata infrastructure. Historical source at commit 80fbeea246 already contained Resource.meta metadata rows as part of that change family.

Additional context:
The current build has Resource as an active resource infrastructure entry and Meta as an active type in source/fhir.ini. Current Resource defines Resource.meta as a Meta element, current Meta defines Meta.profile as canonical(StructureDefinition), current resource narrative explains profile assertions in Resource Metadata, and the XML representation page explicitly includes id, meta, implicitRules, and language as base Resource children before resource-specific elements. No Zulip or Confluence search result was found that conflicts with this source/Jira conclusion.

AutoFHIR reconciliation:
This audit intentionally makes no source change. The current source already satisfies FHIR-2889 by making profile metadata a normal resource XML element, not Atom-only metadata, and adding duplicative wording would not change implementer understanding.

Recommendation:
Keep this no-change audit. Do not reopen FHIR-2889 unless a separate concrete defect is found in generated schemas or examples; any broad Atom-replacement review belongs under FHIR-3728 or a new focused tracker, not this already-satisfied profile-metadata request.
