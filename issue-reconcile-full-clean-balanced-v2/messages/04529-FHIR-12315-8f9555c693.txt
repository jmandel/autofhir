FHIR-12315: Audit stopped QuestionnaireResponse status

Issue request:
Published/Persuasive FHIR-core QuestionnaireAnswers issue FHIR-12315 asked for a QuestionnaireResponse status for responses that are not complete and are not expected to be revisited. The accepted PC resolution was to add the code `stopped` with a definition covering a partially filled-out response where completion status/reason should not become a separate status.

Initial application:
The issue was applied in git-svn commit f3f2ad2c4b57ba4d2dfbbd990363885b40b49101 on 2017-01-06, which added `stopped` to the old QuestionnaireResponse spreadsheet source and added committee note GF#12315 to QuestionnaireResponse.status. The 2021 source rework preserved the status in the current CodeSystem and StructureDefinition source.

Additional context:
QuestionnaireResponse is an active build resource in source/fhir.ini. Current source/questionnaireresponse/structuredefinition-QuestionnaireResponse.xml includes `stopped` in the QuestionnaireResponse.status short name and binds the element to ValueSet/questionnaire-answers-status; source/questionnaireresponse/codesystem-questionnaire-answers-status.xml defines code `stopped`. Later Published issue FHIR-20767 intentionally clarified `stopped` as the terminal incomplete/abandoned state and declined separate `incomplete`/`expired` codes. Zulip and Confluence searches found no conflicting work-group record; a later implementers Zulip thread aligned with the same interpretation that `stopped` means choosing not to finish and does not encode why.

AutoFHIR reconciliation:
No source change was made. The current active source already contains the requested status code and the later clarification makes the current wording more precise than the original issue text without changing the accepted intent.

Recommendation:
Keep this empty audit commit as-is. No follow-up is needed in FHIR core unless a future work group decision adds a distinct status reason extension or additional final statuses.
