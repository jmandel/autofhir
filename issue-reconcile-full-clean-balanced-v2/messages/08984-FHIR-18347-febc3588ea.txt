FHIR-18347: Replace stale modifier-extension examples

Issue request:
FHIR-18347 was Published/Persuasive for STU3 and requested replacing the anti-prescription modifier-extension example because core MedicationRequest now supports do-not-administer requests. The Jira specifically asked to use a Patient.contact do-not-contact example, update the XML/JSON instance example plus the sample warning graphic and surrounding text, and preferably replace the narrative example with a Condition family-history modifier example.

Initial application:
The explicit application commit 32abd5cc959eb6f7daac0704952cd9c681ac0101 changed only the introductory modifier-extension bullet in source/extensibility.html from anti-prescription to Patient.contact. The lower XML/JSON example, narrative example, warning image, and RDF example still carried the anti-prescription pattern in the current source.

Additional context:
MedicationRequest now has MedicationRequest.doNotPerform for requests not to take or administer medication, so retaining anti-prescription as an extension example is misleading. source/hierarchy.xml includes extensibility.html and rdf.html in the current build, and source/extensibility.html directly references the warning image and RDF example. No Zulip or Confluence search result found a conflicting work-group or community decision. FHIR-7376 is already represented on the combined branch as a separate typo audit touching the same historical anti-prescription area, so it was not decided again here.

AutoFHIR reconciliation:
Updated source/extensibility.html so the primary XML/JSON modifier-extension example uses Patient.contact with a do-not-contact modifier extension, replaced the narrative example with a Condition family-history modifier example, updated images/modifier-extension-warning.png to match the Patient.contact warning, and updated source/rdf.html so the linked RDF modifier-extension example no longer uses anti-prescription.

Recommendation:
Keep this source fix as-is. It completes the missed current-build surfaces from the published Jira request while preserving the examples as illustrative extension URLs; further work is only needed if the work group wants to replace the illustrative URLs with registered extension definitions.
