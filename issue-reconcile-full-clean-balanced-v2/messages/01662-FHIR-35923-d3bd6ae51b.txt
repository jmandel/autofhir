FHIR-35923: Audit no-fixed-address extension move

Issue request:
FHIR-35923 was Published/Persuasive for FHIR-core Patient. It requested a boolean Address extension for no fixed address handling, modeled on the Australian extension, and asked to add that extension to the Patient extension listing.

Initial application:
The request was approved by PA on 2022-04-13 and was applied in core commit 0bcf5a628352f8e84a7dc1d3fac6fa9bca0cbe1b. That commit added source/patient/structuredefinition-extension-no-fixed-address.xml and listed StructureDefinition/no-fixed-address in source/patient/implementationguide-Patient-core.xml, alongside the earlier FHIR-25401 no-fixed-address request.

Additional context:
The no-fixed-address concept was already approved in FHIR-25401 as an Address datatype extension. Core commit dd468d4f1799dd79819315b211588ef1cf4586e0 later removed extension definitions and extension-listing resources from R5 core source. The current Extension Pack introduction states that globally defined extensions moved out of core starting with R5, and the current Extension Pack source contains an active Address-scoped no-fixed-address StructureDefinition. FHIR-53014 later removed "Patient" from the extension name and title, confirming that the extension is not restricted to Patient.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR core source change. The current FHIR core checkout is correct not to carry the extension definition or Patient extension-listing entry because the current source of truth is the FHIR Extension Pack.

Recommendation:
Keep this external-repo audit commit. Do not reintroduce the extension definition into core; if future changes are needed, update HL7/fhir-extensions and keep core limited to shared registries such as the existing OID assignment.
