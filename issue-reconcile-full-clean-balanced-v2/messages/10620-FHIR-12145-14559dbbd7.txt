FHIR-12145: Audit Bundle fullUrl constraint removal

Issue request:
FHIR-12145 was a Published/Persuasive with Modification FHIR-I change request for DSTU2. It reported that Bundle.entry.fullUrl allowed an empty fullUrl for POST while bdl-6 required fullUrl whenever a resource was present and prohibited it otherwise. The approved resolution was to remove bdl-6 from Bundle.entry and add documentation explaining why a fullUrl can still be useful when a transaction create entry does not require one.

Initial application:
The explicit application commit 0883095aa9ce39c88032162d3292123a6b22a1bb removed the bdl-6 row from the then-authoritative Bundle spreadsheet source and added Bundle notes for transaction and batch POST entries without identity, including the reason to keep a fullUrl when entries need to reference each other. The current source no longer contains bdl-6 or the old "fullUrl present when resource present" rule.

Additional context:
Bundle is an active current-build resource in source/fhir.ini. Current Bundle source has Bundle.entry.fullUrl cardinality 0..1, no bdl-6 condition, bdl-7/bdl-8 uniqueness and version-reference rules, and a later bdl-15 rule requiring fullUrl for non-batch/non-transaction Bundles. Later fullUrl decisions already represented on the combined branch, especially FHIR-31354 and FHIR-43106, refined the batch/transaction exception language and aligned the narrative and invariant without reintroducing the obsolete bdl-6 contradiction.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current authoritative Bundle StructureDefinition and Bundle notes already implement the FHIR-12145 outcome: bdl-6 is gone, transaction/batch exceptions remain, and the notes and ElementDefinition explain that fullUrl can still be used to support references between transaction entries.

Recommendation:
Keep this empty audit commit as-is. No further core FHIR source change is needed for FHIR-12145; any future change to the later bdl-15 exception scope should be handled under the already separate fullUrl issue family, not by reopening this DSTU2 conflict.
