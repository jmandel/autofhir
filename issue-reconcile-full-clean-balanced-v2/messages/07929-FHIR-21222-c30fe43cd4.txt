Issue request:
FHIR-21222 was a Published/Persuasive with Modification FHIR-I change request raised against STU3 and applied for R5. It reported that the StructureDefinition ext-context search parameter FHIRPath expression resolved to the StructureDefinition.context backbone element rather than the expression value, and its accepted resolution proposed redesigning ext-context as a composite search parameter over SD.context with separate component parameters for the coded context type and context expression.

Initial application:

The active source file source/structuredefinition/bundle-StructureDefinition-search-params.xml was introduced in the 2021 new-build-core source rework with the older token-over-StructureDefinition.context shape, then commit 84a650b04be0fcabffb180bb88c24ef8211da93f changed ext-context to type composite and added ext-context-type and ext-context-expression search parameters. Although that commit subject mentions FHIR-27532 rather than FHIR-21222, the patch exactly implements this issue's accepted composite design.

Additional context:
StructureDefinition is an active current-build resource in source/fhir.ini, and the StructureDefinition model still defines context as a BackboneElement with required type and expression children. The related Published/Persuasive FHIR-24917 technical correction noted the old BackboneElement problem and suggested StructureDefinition.context.type for the R4 token parameter; that issue has already been represented on the combined branch by commit 039fac863c212d6c42dae484421c2196cbda532d. Current R5 published evidence and current source moved beyond the R4 token-only correction to the FHIR-21222 composite design, where searches by type use ext-context-type and searches by expression use ext-context-expression.
