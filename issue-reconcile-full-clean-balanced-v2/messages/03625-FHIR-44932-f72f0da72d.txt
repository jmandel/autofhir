FHIR-44932: Audit Specimen processing duration choice

Issue request:
FHIR-44932 was an Applied/Persuasive OO change request for R6 asking to add timeDuration as a choice for Specimen.processing.time[x], so the duration capability from the specimen-processingTime extension would be retained after that extension was deprecated.

Initial application:
No core git commit explicitly mentioning FHIR-44932 was found. The same source requirement had already been applied by commit 2e47a771ff78f16314747f5451f30a1f80317784 for FHIR-40950, which added Duration to source/specimen/structuredefinition-Specimen.xml under Specimen.processing.time[x]. The FHIR-44932 Jira comment later records the issue as applied.

Additional context:
FHIR-40950 is the same-change-family core tracker that originally asked to add duration to Specimen.processing.time and remove the specimen-processingTime extension. FHIR-44361 is the Extension Pack tracker that tied deprecating/replacing specimen-processingTime to creating FHIR-44932. OO meeting minutes on 2024-03-08 and 2024-03-22 record the extension-pack decision, the additional FHIR-44932 Jira, and the later March 2024 block-vote handling. Zulip discussion in #Orders and Observation WG also points implementers from the processingTime extension question to FHIR-40950.

AutoFHIR reconciliation:
This audit commit makes no source change. Specimen is an active resource in source/fhir.ini, and the active StructureDefinition source already lists dateTime, Period, and Duration for Specimen.processing.time[x], which generates the requested timeDuration choice.

Recommendation:
Keep this audit commit as-is. No FHIR-core follow-up is needed for FHIR-44932; any future maintenance of the deprecated specimen-processingTime extension belongs in the FHIR Extension Pack rather than this core checkout.
