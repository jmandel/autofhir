FHIR-7990: Audit _id search bundle clarification

Issue request:
FHIR-7990 was a Published/Persuasive FHIR-core search change request from the DSTU1 cycle. It asked to clarify that the bundle-vs-resource distinction applied specifically to search with the _id parameter: "the search with parameter _id returns a bundle with the requested resource, rather than the resource itself." The recorded resolution was "change as suggested."

Initial application:
The issue was applied in git-svn commit 0f05c40d4974ffef702077b745646502c536f52a, matching the Jira comment for svn revision 6471. That commit changed source/search.html from the broad "except that it returns a bundle" wording to wording explicitly naming search with parameter _id, and also noted additional search functionality such as _include.

Additional context:
The current source/search.html page is the active Search (RESTful API) source page. Later search-page reorganizations moved this topic into a dedicated "Searching Identifiers" / "Logical Identifiers" section and a separate _id parameter section. Current text says logical-id searches are performed with _id, search operations always return bundles, an existing logical id returns a bundle containing the resource instead of the resource itself, valid searches for missing/non-returnable ids still return bundles, and additional search features such as related-resource inclusion remain available. Targeted Jira, Zulip, and Confluence searches found no FHIR-7990-specific later reversal; a 2022 implementers Zulip exchange matches the same read-vs-_id-search distinction.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source preserves and expands the accepted clarification, so restoring the exact 2015 wording would be redundant and less complete.

Recommendation:
Keep this no-change audit commit as-is. No core follow-up is needed for FHIR-7990 unless a future work group decision changes the semantics of _id search responses.
