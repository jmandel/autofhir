FHIR-29410: Audit identifier modifier distinction

Issue request:
FHIR-29410 was a Published FHIR-I change request for the FHIR-core Search page. It asked either to remove the :identifier modifier or to make reference:identifier equivalent to chained reference.identifier searches. The final Not Persuasive with Modification resolution rejected equivalence because servers may support either capability independently, but approved adding clarifying language that the behaviors are different and clients may need to account for both.

Initial application:
The issue appears to have been applied by git commit 90c02ba9a4d70c6b0281011bfcf3b5f2066fe515, which explicitly mentions both FHIR-29410 and FHIR-37424 and expands source/search.html from a TODO into detailed identifier-search guidance and examples. No prior Issue-Reconcile-Key commit for FHIR-29410 was found on the combined branch before this audit.

Additional context:
FHIR-37424 is the same change family: it raised the same .identifier versus :identifier gotcha after Zulip implementer discussion, and FHIR-I minutes resolved it by pointing to the FHIR-29410 resolution. Later FHIR-45252 refined adjacent wording by changing some chaining/modifier language from "not supported" to "not defined" with server discretion, but that later R6 clarification does not make :identifier equivalent to chained identifier searches.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source/search.html already says the identifier modifier tests Reference.identifier rather than Reference.reference, notes that chaining behavior with the identifier modifier is not defined, and contains a dedicated Identifiers and References section contrasting patient.identifier chained searches with patient:identifier modifier searches. The current text therefore implements the approved FHIR-29410 clarification without obscuring the capability distinction.

Recommendation:
Keep this empty audit commit as-is. No further FHIR-29410 source work is needed unless FHIR-I later chooses a different policy that intentionally makes chained identifier and :identifier searches equivalent.
