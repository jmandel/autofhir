FHIR-5994: Audit MedicationAdministration medication wording

Issue request:
FHIR-5994 was a Published/Persuasive Pharmacy change request from DSTU1 saying MedicationAdministration.medication was misleading because its definition said a simple medication code was possible even though a medication code was not then allowed.

Initial application:
No git commit explicitly mentions FHIR-5994, but the 2015 pharmacy ballot-resolution commit d406f9a2c0 changed the same element from MedicationAdministration.medication Reference(Medication) 0..1 to MedicationAdministration.medication[x] CodeableConcept|Reference(Medication) 1..1, updated examples to medicationReference, and added the explanatory comment for code-only use. That matches Jira's note that the request was done as part of other tracker items.

Additional context:
Current source/fhir.ini lists MedicationAdministration as an active resource. The current StructureDefinition uses CodeableReference(Medication), with search parameters and notes exposing both MedicationAdministration.medication.concept and MedicationAdministration.medication.reference. FHIR-25929 later Published/Persuasive work changed Pharmacy code-or-reference choices to CodeableReference for R5, preserving the ability to represent medication by code or by Medication reference.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The original contradiction no longer exists in the current build: the definition's reference-or-code wording is consistent with CodeableReference(Medication) and with current search parameter/source notes.

Recommendation:
Keep this no-change audit. Revisit only if Pharmacy later decides MedicationAdministration.medication should stop allowing coded products; FHIR-5994 itself does not justify changing the current CodeableReference wording.
