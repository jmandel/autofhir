FHIR-28116: Audit ValueSet include title extension

Issue request:
FHIR-28116 was a Published/Persuasive Vocabulary change request for R5 from the Value Set Definition Profile project. It asked FHIR Core to add a string extension named valueset-compose-include-valueSetTitle on ValueSet.compose.include.valueSet with description "Human readable name for the included Value Set"; Jira comments clarified that the extension was required for the VSD profile and was to be added to FHIR Core.

Initial application:
Commit 9fca6ca36fefa544491b1efc7fdb1530333ed78b explicitly listed FHIR-28116 among the R5 VSD Profile changes and added the ValueSet include title extension source. Follow-up VSD extension work corrected the canonical/id details, and by the pre-removal source the extension had the hl7.org/fhir canonical URL, ValueSet.compose.include.valueSet context, string value type, OID, and the requested top-level description. Later cleanup commit dd468d4f1799dd79819315b211588ef1cf4586e0 removed the ValueSet extension StructureDefinitions from core source as part of the R5 extension source move.

Additional context:
The current maintained extension source is in the FHIR Extension Pack, not the core checkout. That Extension Pack definition still has the requested canonical URL, context, string value type, OID, and top-level description, and later FHIR-40715 deprecated/retired the extension in favor of the generic display extension. FHIR-40715 has already been represented on the combined branch by commit 7ead6a391a05345eb3dbc6d907ac29727399ebbc, which also updated active core ValueSet notes to recommend display on ValueSet.compose.include.valueSet and state that the earlier valueSetTitle extension is deprecated. FHIR-31936 separately considered whether publisher rendering should replace the extension and was retracted with a decision to keep the extension at that time; FHIR-36678 corrected the same extension family's generated fullUrl/canonical problem before the extension move.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding the original extension definition to core would reverse the extension-source move and the later FHIR-40715 deprecation guidance. The active core ValueSet narrative is in build scope and already points implementers to the current display extension, while the deprecated original extension is maintained externally in the Extension Pack.

Recommendation:
Keep this audit commit as-is for core. If the Extension Pack is reviewed separately, the deprecated valueSetTitle extension's residual differential short/definition wording can be checked for consistency with its correct top-level description, but no additional core source work is needed for FHIR-28116.
