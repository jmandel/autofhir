FHIR-31867: Audit EvidenceReport replacement by Composition

Issue request:
FHIR-31867 was an Applied/Persuasive CDS change request raised against FHIR-core EvidenceReport. It asked core to stop recreating document organization in EvidenceReport, create an EvidenceReport profile on Composition using FHIR document capabilities, and deprecate the EvidenceReport resource.

Initial application:
The issue was applied in stages. Earlier R5/R6 work added Composition support for evidence-report use cases through related Structured Documents issues. Git commit 060d12b60c76 explicitly marked EvidenceReport deprecated/retired for J#31867, and PR #3317 was merged as bd561abc6ca0 with the summary "J#31867 deleted EvidenceReport resource", removing the source/evidencereport folder and active fhir.ini/resource-list references.

Additional context:
Current source/fhir.ini has active Composition, Evidence, and EvidenceVariable entries but no EvidenceReport entry. The Clinical Reasoning Evidence and Statistics page says the prior EvidenceReport resource has been replaced with an EvidenceReport profile of Composition in the Evidence-Based Medicine on FHIR IG, and the EBM IG package contains StructureDefinition/evidence-report with baseDefinition Composition. Related Composition trackers FHIR-34158, FHIR-34159, and FHIR-32795 cover supporting status/attester/relatesTo/additional-element work and are either represented separately on the combined branch or superseded by later R6 relationship-design changes.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core build no longer publishes EvidenceReport as a resource, preserves active Composition support, points implementers to the EBM Composition profile, and records the removal in history. Adding a redundant core profile or resurrecting EvidenceReport source would conflict with the current source organization.

Recommendation:
Keep this audit commit as-is. Future corrections to the EvidenceReport Composition profile should be made in the EBM IG/package source, while future core Composition shape changes should be handled under their own Composition trackers rather than under FHIR-31867.
