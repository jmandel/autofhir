FHIR-27141: Audit SubscriptionStatus canonical topic

Issue request:
FHIR-27141 was a Published/Persuasive with Modification FHIR-I change request for R5. It asked to stop making SubscriptionStatus.topic a link to a server-local SubscriptionTopic reference, make it a canonical SubscriptionTopic URL instead, make SubscriptionTopic.url 1..1, and document conventions for local or one-off topics.

Initial application:
The Jira comment says the issue was applied in commit 17740f61cda26cd5836bee2905becfd196ab1e5c, the R4B subscription change import. In the current source history, SubscriptionStatus.topic was already introduced as canonical(SubscriptionTopic) and SubscriptionTopic.url as 1..1 in the initial SubscriptionStatus/SubscriptionTopic source additions (33b409a4b6d544598262f2f074ebb4b6dc466157 and d372875a89c93d078b7a1d937273a53d331e0c9f); 17740f61 carried those semantics forward while later applying payload/PHI optionality guidance.

Additional context:
source/fhir.ini actively includes subscriptionstatus and subscriptiontopic in the current build. The 2020-05-18 FHIR-I minutes corroborate the accepted scope: make SubscriptionStatus.topic canonical and make SubscriptionTopic.url 1..1. Related FHIR-27142 separately clarified SubscriptionTopic.url text for local, derived, and direct implementation scenarios and is already represented on the combined branch. Later FHIR-33268 made the canonical topic optional because the URL can disclose PHI, and later FHIR-39037 considered removing SubscriptionStatus.topic but resolved no-change because optionality preserves routing use cases without requiring disclosure.

AutoFHIR reconciliation:
This audit commit makes no source change. The active SubscriptionStatus definition has topic as 0..1 canonical(SubscriptionTopic), not Reference(SubscriptionTopic), and all Subscription/SubscriptionStatus examples encode topic as a URI value rather than a Reference child. The active SubscriptionTopic definition has url 1..1 and its comment contains the local/derived/direct implementation URL conventions. The remaining word "Reference" in the topic short/definition is generic canonical-reference wording and does not create a misleading local Reference type when read with the generated canonical type and examples.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-27141; future work should preserve the canonical URL type and required SubscriptionTopic.url while respecting the later optional/PHI guidance from FHIR-33268.
