FHIR-13558: Audit Timing dayOfMonth extension location

Issue request:
FHIR-13558 was a Published FHIR-core STU3 change request with a Persuasive with Modification resolution. It asked to consider adding dayOfMonth, 0..*, integer, range 1 to 31 to Timing.repeat, and the accepted resolution was to define this as a standard extension.

Initial application:
The Jira comment says the change was applied in svn revision 12465. In git history this corresponds to 12ab1356c5, which added the dayOfMonth extension row to source/datatypes/timing-extensions-spreadsheet.xml in core rather than adding a native Timing.repeat.dayOfMonth element.

Additional context:
Core extension definitions were later moved out of the R5 source, including removal of timing-dayOfMonth from source/datatypes/timing-extensions-spreadsheet.xml in dd468d4f17. The current authoritative StructureDefinition exists in the FHIR Extension Pack at input/definitions/datatypes/StructureDefinition-timing-dayOfMonth.xml with canonical URL http://hl7.org/fhir/StructureDefinition/timing-dayOfMonth and context Timing.repeat. Current core source still demonstrates use of the extension in dosage examples and does not define Timing.repeat.dayOfMonth as a core element. Jira search found no other Timing.repeat dayOfMonth issue beyond FHIR-13558; broader dayOfMonth hits concern separate Appointment recurrence and Dosage work and are not decided here. Community searches found only the tracker bot notification and no Confluence record changing the conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The issue was applied as a standard extension, and the extension's source of truth now belongs to the FHIR Extension Pack rather than the current core FHIR checkout. Re-adding timing-dayOfMonth to core extension source would conflict with the R5 extension-source migration.

Recommendation:
Keep this empty external-repo audit commit as-is for core reconciliation. If humans want to adjust the extension definition details, such as its range prose or constraints, do that in the FHIR Extension Pack rather than in the core FHIR repository.
