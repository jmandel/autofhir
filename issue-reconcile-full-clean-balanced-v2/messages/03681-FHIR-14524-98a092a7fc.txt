FHIR-14524: Audit MedicationRequest example coverage

Issue request:
FHIR-14524 was a Published/Persuasive STU3 Pharmacy issue asking to update MedicationRequest examples so the examples included all attributes. The Jira resolution agreed to change, and the Jira comment records that the example updates were applied to the build in git-svn commit 6a66821c691aae27795820aa49a7da81cabedf82.

Initial application:
The referenced application commit is present in current history. It explicitly named TR#14524 and updated source/medicationrequest/medicationrequest0301.xml and source/medicationrequest/medicationrequest0316.xml by adding values for the STU3 QA gaps: MedicationRequest.statusReason, MedicationRequest.performerType, MedicationRequest.insurance, MedicationRequest.dispenseRequest.performer, and MedicationRequest.instantiates. The sibling umbrella Jira FHIR-14431 identifies the same MedicationRequest gaps and the intended-performertype search-parameter coverage warning.

Additional context:
MedicationRequest remains an active build resource in source/fhir.ini, and the active examples list still registers medicationrequest0301. Current source retains statusReason, performerType, insurance, and the renamed dispenseRequest.dispenser coverage in medicationrequest0301. The historical instantiates example was first renamed to instantiatesUri by GF 17829 and later removed when FHIR-24100/FHIR-32864 removed instantiatesCanonical/instantiatesUri from the current MedicationRequest model. A current coverage parse shows later optional R5/R6 elements such as statusChanged, device, courseOfTherapyType, and effectiveTiming are not represented in examples, but those are later model changes and not part of the bounded STU3 QA cleanup represented by FHIR-14524.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build source already carries the still-valid MedicationRequest example coverage that FHIR-14524 added, and reinterpreting this old applied issue as a broad mandate to populate every newer optional MedicationRequest element would over-read the historical decision.

Recommendation:
Keep this no-change audit as-is for FHIR-14524. If Pharmacy wants the current R6 MedicationRequest examples to demonstrate every post-STU3 optional element, open or use a current tracker scoped to those later elements rather than reopening this applied STU3 cleanup.
