FHIR-5723: Audit Encounter modifier flags

Issue request:
FHIR-5723 is a Published/Persuasive Patient Administration DSTU1 change request asking to clean up Encounter modifier properties: Encounter.class should not be a modifier, and Encounter.location.status "probably should be."

Initial application:
No Jira-keyed source commit for FHIR-5723 was found. The legacy Encounter spreadsheet before application had Encounter.class marked as a modifier and Encounter.location.status unmarked. Commit 27302910 removed the Encounter.class modifier flag during Encounter ballot reconciliation, and the published DSTU-era spreadsheet kept Encounter.class non-modifier while leaving Encounter.location.status non-modifier. The later StructureDefinition source rework preserved the same modifier state.

Additional context:
Encounter is an active resource in the current build. Current Encounter.status is a modifier because entered-in-error makes the resource invalid, while Encounter.location.status is a nested presence/status field for a location entry whose parent is defined as the list of locations where the patient has been. Its values planned, active, reserved, and completed qualify that location participation and period; they do not mark the Encounter resource or the location entry as invalid. The later FHIR-13465/status-code discussion considered a broad status-as-modifier rule, including Encounter.location.status, but ended as Resolved - No Change/tooling-warning context rather than a blanket source rule.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already reflects the durable part of FHIR-5723 by keeping Encounter.class non-modifier, and adding isModifier to Encounter.location.status now would over-apply the tentative "probably" note against later modifier semantics and current Encounter modeling.

Recommendation:
Keep this no-change audit. If PA wants Encounter.location.status to become a modifier in a future release, open a focused new tracker that supplies the modifier reason and decides the summary/missing-value implications for this optional nested element.
