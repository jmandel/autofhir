FHIR-17662: Audit OO encounter element application

Issue request:
FHIR-17662 was a Published/Persuasive STU3 OO change request asking that all applicable OO event and request resources change their .context element back to .encounter, cardinality 0..1 Reference(Encounter), and that the event/workflow episode-of-care extension be usable at the resource level.

Initial application:
The Jira comment names commit 7ea8dbba47af731f137a84550120bf1963408ca3, which applied the context-to-encounter change to DiagnosticReport, Media, NutritionOrder, ServiceRequest, their examples, and compartments. Earlier GF#17662 commits efd2a28750 and e6887f2aa8 applied the same change to DeviceRequest, and 886a9c0976 handled Task as a parallel OO resource.

Additional context:
FHIR-17661 is the linked Observation-specific precedent and confirms the intended split between Encounter and EpisodeOfCare. Current fhir.ini shows DeviceRequest, DiagnosticReport, NutritionOrder, and ServiceRequest as active core resources, while Media is retired and DeviceUseStatement is only a rename entry to DeviceUsage. Current core module pages link DeviceUsage to the OO incubator IG rather than an active core resource; the remaining local DeviceUsage.context definition is therefore not a current-core build-scope miss. The former eventEpisodeOfCare extension now lives in the FHIR Extension Pack as workflow-episodeOfCare and includes contexts/search bases for the relevant resource family.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the active current core resources still in scope for FHIR-17662 already expose .encounter as 0..1 Reference(Encounter), and their search parameters use code encounter. The only old-style local element found, DeviceUsage.context, is outside active core build scope and should not be changed in this core reconciliation.

Recommendation:
Keep this no-change audit. If DeviceUsage is later repatriated from the OO incubator into core, the work group should make a separate current-version decision about whether its context element should be renamed or modeled differently.
