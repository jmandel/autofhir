FHIR-30240: Audit unauthorized search OperationOutcome wording

Issue request:
Published/Persuasive FHIR-I clarification request for the HTTP search section. The reporter read the old sentence "the return value return value SHALL be a status code 4xx or 5xx with an OperationOutcome" as requiring OperationOutcome for authorization-related search failures such as HTTP 401/403, while the status-code guidance said OperationOutcome is not always required. The accepted resolution was to make OperationOutcome optional for this case.

Initial application:
The issue was applied in git commit b05c3d81668ddaef25eac26202e9ade43f3a9b69, changing the search-failure sentence from mandatory OperationOutcome wording to "possibly accompanied by an OperationOutcome." Jira comments link that work to PR 1729 and the R5 merge PR 1731.

Additional context:
The initiating Zulip thread records the same security-framework concern: authorization or load-balancer layers may not be FHIR-aware and may return bare 401/403 responses, and several participants said clients must be prepared for errors without OperationOutcome. FHIR-I minutes on 2021-02-22 record the work-group decision to make OperationOutcome optional for this case. Later Published issue FHIR-27051 refined the same sentence to the current SHOULD-level rule for failures at a FHIR-aware processing level, preserving the seed's non-mandatory intent while giving stronger guidance when the FHIR server can provide useful details.

AutoFHIR reconciliation:
No source change was made. The active source/http.html page now states generally that OperationOutcome may be returned for any HTTP 4xx/5xx but is not required, and the search-failure paragraph requires only a 4xx/5xx status code while saying FHIR-aware failures SHOULD be accompanied by an OperationOutcome. That current wording fully addresses the 401/403 concern without reverting the later FHIR-27051 clarification.

Recommendation:
Keep this empty audit commit. The seed's requested behavior is already present in the current HTTP source, and changing the wording back to merely "possibly accompanied" would discard the later accepted SHOULD guidance for FHIR-aware failures.
