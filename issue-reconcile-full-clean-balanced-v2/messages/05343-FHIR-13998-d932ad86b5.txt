FHIR-13998: Audit DSM-5 terminology URI stewardship

Issue request:
FHIR-13998 was a Published/Persuasive Vocabulary change request raised for STU3 asking HL7 to assign an OID and FHIR system URI for DSM-5. The approved resolution created the FHIR canonical URL http://hl7.org/fhir/sid/dsm5 and noted OID 2.16.840.1.113883.6.344.

Initial application:
The issue was applied in source history by c4bc403b9b, svn revision 13081, which added a DSM-5 row with http://hl7.org/fhir/sid/dsm5 and OID 2.16.840.1.113883.6.344 to source/terminologies-systems.html.

Additional context:
Later terminology governance changed how external code systems are represented. HTA-8 and the 2021-12-16 HTA minutes concluded that DSM-V/DSM-5 is not a standalone code system with native concepts, while also noting that the already-published R4 URI could not simply be removed from that release. FHIR-37853 was then Published/Persuasive for R5 and deliberately made THO the authoritative source for external terminology and identifier information, removing core External Code Systems rows that lacked a Using-X-with-FHIR page, including the DSM-5 row.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core source already says FHIR-defined code system URIs are authoritative in core, that external terminology content in the Defined Externally tab is non-authoritative, and that HL7 Terminology is the authoritative place for external terminology URI and OID information. Re-adding a DSM-5 row to core would contradict the later FHIR-37853 policy and the HTA-8 conclusion that DSM-5 is not itself a standalone code system.

Recommendation:
Keep this no-change audit commit. Do not re-add DSM-5 as a core External Code Systems row. If implementer guidance for DSM-5 is still needed, handle it through HTA/THO rather than this FHIR core source checkout, and make sure any guidance reflects the HTA-8 finding that DSM-5 uses ICD code systems rather than native DSM-5 codes.
