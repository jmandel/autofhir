FHIR-11818: Audit EOB MedicationDispense support

Issue request:
FHIR-11818 was a Published FHIR-core ExplanationOfBenefit change request, resolved Persuasive with Modification, asking that MedicationDispense be included in ExplanationOfBenefit in addition to MedicationOrder because an EOB can reflect what was issued to the patient. The applied resolution was that MedicationDispense can be provided in x.information.value[x].

Initial application:
No current git history commit found by this reconciliation explicitly mentions FHIR-11818. However, the relevant DSTU2/R3 x.information element is mapped in current source to ExplanationOfBenefit.supportingInfo, and historical R4B source already allowed ExplanationOfBenefit.supportingInfo.value[x] to be a Reference to Resource. The current source has since broadened the element to a wildcard value[x] and retained definition/comment text describing resources and references as valid supporting data.

Additional context:
ExplanationOfBenefit is active in source/fhir.ini, and source/fhir.ini maps ExplanationOfBenefit.information to ExplanationOfBenefit.supportingInfo. Later closely related pharmacy/EOB issues do not supersede this seed: FHIR-17772 was Resolved - No Change and pointed to FHIR-17735, FHIR-17735 resolved the dispensed-drug placement question for Claim via productOrService/drug code, and FHIR-22775 was Resolved - No Change with the clarification that EOB prescription uses RX information rather than dispensed information. Exact Zulip and Confluence searches found no work-group/community record contradicting the Jira/source conclusion; the only exact Zulip title hit was the original tracker bot notification.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative EOB StructureDefinition already lets supportingInfo.value[x] carry arbitrary value content, including resource references, and the current rename map shows this is the successor to the x.information.value[x] location named by FHIR-11818. Adding MedicationDispense to EOB.prescription or originalPrescription would conflict with later no-change decisions and is not required by the seed resolution.

Recommendation:
Keep this no-change audit commit as-is. Future work should not add MedicationDispense as an EOB prescription target for this issue; if a work group wants item-level links to a dispense event, that should be handled under newer open EOB/Claim modeling work rather than reopening this DSTU2 supportingInfo resolution.
