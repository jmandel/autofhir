FHIR-11091: Audit medication not-given harmonization

Issue request:
FHIR-11091 was a Published/Persuasive with Modification DSTU2 Pharmacy issue asking to harmonize MedicationAdministration, MedicationStatement, and Immunization not-given/reason naming. The final resolution changed MedicationAdministration.wasNotGiven to notGiven, cleaned MedicationAdministration search parameter names, added MedicationAdministration reason-given and reason-not-given search parameters, left MedicationStatement naming as-is, and recorded PHER agreement to align Immunization and remove its Explanation component.

Initial application:
The issue was explicitly applied in git commit aa43a356750a1cbf3c70e7b8ab69ca464c3b77c3, which changed the MedicationAdministration spreadsheet from wasNotGiven to notGiven, renamed the wasnotgiven search parameter to not-given, and added reason-given and reason-not-given search parameters. Immunization was aligned shortly afterward by commit 85a7ed8e2886500b437fe45efe3057fe02f01aa2, and later Immunization event-pattern work in commit 4c5a8902abffdfb5b6e9f07b4bca119d875dc64a removed the old notGiven/explanation pattern from the active Immunization source.

Additional context:
The current build-scope resources are active in source/fhir.ini. Current MedicationAdministration no longer has wasNotGiven/notGiven elements; it represents not-done state through status and statusReason while retaining the requested reason-given/reason-not-given search parameters against the current reason and statusReason elements. Current Immunization similarly uses status and statusReason, and the active refused Immunization example uses status=not-done with statusReason rather than explanation/reasonNotGiven. Current MedicationStatement uses the later adherence model for taking/not-taking; FHIR-39271 confirms that later Pharmacy decision, so the old DSTU2 MedicationStatement naming question should not be re-applied to the current model.

AutoFHIR reconciliation:
This commit intentionally makes no source change. A targeted search found old wasNotGiven/explanation text only in a stale unreferenced copy at source/medicationadministration/immunization-example-refused.xml and in historical/compatibility material, while the active resource definitions, active Immunization refused example, and MedicationAdministration search parameters already reflect the final issue intent as adapted by later model changes.

Recommendation:
Keep this no-change audit. Do not reintroduce DSTU2 notGiven names into current resources; any cleanup of unrelated stale examples or MedicationStatement/adherence examples should be handled under the later issue family rather than FHIR-11091.
