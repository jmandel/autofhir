FHIR-11652: Audit default ActivityDefinition StructureMaps

Issue request:
FHIR-11652 is a Published/Persuasive CDS change request, raised against DSTU2 and applied for R5, asking whether FHIR should define standard transforms/StructureMaps for the basic ActivityDefinition activity categories. The approved resolution was that default structure maps would be provided.

Initial application:
No local source commit explicitly mentions FHIR-11652. The Jira comment cites HL7/fhir#2834, and local history shows that PR merged d5c8096f562da742bfcbd81943d91bcf488b8854, which added the ActivityDefinition Structure Mapping section, plus f0d5d69c3a16f31cbdf667090336ba87f5f77550, which added the 15 companion activitydefinition-map-*.fhirmap files. Those commits are explicitly tied to the later same-change-family issue FHIR-29210.

Additional context:
FHIR-29210 is a Published/Persuasive CDS issue requesting example ActivityDefinition transforms using FHIR mapping language, with 15 attached Parameters-to-target .fhirmap examples, and it is already represented on the combined branch. The current build-scope ActivityDefinition page includes FHIR Mapping Language snippets for mapping ActivityDefinition instances to each kind of Request resource that can be created, while ActivityDefinition.transform remains a canonical reference to StructureMap. Source/fhir.ini actively includes ActivityDefinition, PlanDefinition, and StructureMap resources in the current build.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope ActivityDefinition source already provides the mapping examples that implement the approved default-map intent as it was ultimately applied through PR #2834/FHIR-29210, and the companion .fhirmap files remain in source as supporting examples. Creating additional canonical HL7 StructureMap resources or changing the examples from informative snippets into normative defaults would be a new work-group decision rather than a necessary correction for FHIR-11652.

Recommendation:
Keep this no-change audit. If CDS wants normative, canonical default StructureMap resources for each current R6 request resource type, open a new tracker or use an existing unresolved tracker rather than treating that broader design choice as unfinished FHIR-11652 work.
