FHIR-28458: Audit refuted status guidance

Issue request:
FHIR-28458 was a Published/Persuasive with Modification Patient Care change request for R5 asking AllergyIntolerance and Condition to add guidance that clinicalStatus can be empty when verificationStatus is refuted. The accepted resolution removed the Condition con-5 and AllergyIntolerance ait-1 invariants, clarified both verificationStatus definitions as applying to the resource itself rather than an attribute, and added refuted-record guidance to the Condition and AllergyIntolerance notes.

Initial application:
The issue was applied in git commit 54c9fc124088d2698ee846b31d29652a659158c1, which updated the then-authoritative Condition and AllergyIntolerance spreadsheets and notes. That commit removed the entered-in-error clinicalStatus exclusion invariants, made AllergyIntolerance clinicalStatus/verificationStatus no longer tied to those invariant conditions, added J#28458 committee notes, and added the refuted-record legal-retention guidance. The current XML source is descended from that application after the 2021 source rework.

Additional context:
Condition and AllergyIntolerance are active resources in source/fhir.ini, so their StructureDefinition and notes files are current build inputs. The current AllergyIntolerance source remains compatible with FHIR-28458 because clinicalStatus is 0..1 and the refuted guidance is present. The current Condition source also retains the FHIR-28458 definition and refuted guidance, but a later Published Patient Care decision, FHIR-29409, made Condition.clinicalStatus 1..1 because it is a modifier element and added an unknown code path for cases where the clinical status is not known. That later decision is already represented on the combined branch and intentionally governs the current Condition cardinality. FHIR-54914 later clarified only the Condition.verificationStatus comment and did not change the FHIR-28458 definition or refuted guidance.

AutoFHIR reconciliation:
No source change was made. The current source already contains the FHIR-28458 wording that remains applicable, the obsolete con-5 and ait-1 invariants are absent, and the apparent Condition clinicalStatus cardinality difference is explained by the later FHIR-29409 decision rather than by a missed FHIR-28458 application.

Recommendation:
Keep this audit commit as-is. Do not reintroduce an exception allowing absent Condition.clinicalStatus for refuted conditions unless Patient Care explicitly revisits FHIR-29409; AllergyIntolerance and the shared refuted-record guidance need no follow-up for FHIR-28458.
