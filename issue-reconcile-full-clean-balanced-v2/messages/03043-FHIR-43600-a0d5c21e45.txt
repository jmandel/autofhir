Issue request:
FHIR-43600 is Applied/Persuasive for FHIR-core Provenance. It asked for an example Bundle showing Provenance.target references that request version-specific resolution with the resolve-as-version-specific extension, a reference from http.html, mention from the Provenance page under #using, and an example associated with the extension definition.

Initial application:
The underlying extension was defined by FHIR-34343 and transaction wording was clarified by FHIR-34344. Commit d5f982f643 added the HTTP transaction guidance for resolve-as-version-specific. Commit 50431f3b5f then applied FHIR-43600 by adding a Provenance entry to source/bundle/bundle-transaction.xml with resolve-as-version-specific on Provenance.target references, linking that Transaction Example from source/http.html#vs-refs, and linking the same example from the Provenance #using notes. The current core checkout no longer contains the resolve-as-version-specific StructureDefinition source; the definition lives in the FHIR Extension Pack.

Additional context:
The January 2024 Zulip thread that prompted the Jira records the concrete use case: a transaction Bundle includes resources plus Provenance, but the client cannot know the server-assigned versions for Provenance.target. FHIR-I minutes on 2024-05-13 record the persuasive 11-0-0 vote. Later FHIR-51135 is complementary: it added and linked a separate searchset Bundle example for Provenance targets that are already version-specific; the combined branch already contains an audit/fix commit for FHIR-51135, so this reconciliation does not duplicate it.
