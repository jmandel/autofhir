FHIR-29409: Audit Condition clinicalStatus reconciliation

Issue request:
FHIR-29409 was Published/Persuasive with Modification for R5. It asked to remove the dependency of the Condition.clinicalStatus invariant on the condition-category problem-list-item code after the Condition.category binding had made IPS Condition profiles/examples non-conformant. The final resolution required Condition.clinicalStatus 1..1, added an unknown clinical status code through terminology governance, removed the old category-dependent con-3 invariant, loosened Condition.category binding strength, and added explanatory clinicalStatus guidance.

Initial application:
The issue was applied in core by commit 91c6eeca7e20574ca2f9d941bc0a19fe76539a45, which set Condition.clinicalStatus to 1..1, added the requested explanatory comment, replaced the old problem-list-item-gated clinicalStatus-presence con-3 with a problem-list/unknown warning, and changed Condition.category from extensible to preferred. The Jira comments explicitly note that the unknown code could not be added in that core commit because it needed the UTG process; that work was later tracked as UP-280.

Additional context:
Condition is an active current-build resource through source/fhir.ini. Current source/condition/structuredefinition-Condition.xml has Condition.clinicalStatus at 1..1, includes unknown in the short/comment, and no longer contains the old clinicalStatus.exists/category problem-list-item con-3 logic. The current con-3 is an abatement rule, not the removed category-dependent rule. UP-280 is implemented in THO and the current condition-clinical code system includes the requested unknown code. Later Patient Care decisions explain the remaining differences from the 2020 resolution: FHIR-39011 rejected moving Condition.category back to extensible, and FHIR-48358 later changed Condition.category from preferred to example and removed the post-29409 problem-list/unknown warning.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative current source already removes the category-dependent clinicalStatus requirement, carries the required clinicalStatus cardinality and comment, obtains unknown through the terminology source of truth, and reflects later applied Condition.category decisions.

Recommendation:
Keep this empty audit commit as-is. No core follow-up is needed for FHIR-29409; any future change to Condition.clinicalStatus cardinality or Condition.category policy should be handled under its own later Jira decision rather than by reverting this applied R5 reconciliation history.
