FHIR-20675: Audit constraint source canonical URLs

Issue request:
FHIR-20675 is a Published/Persuasive FHIR-core StructureDefinition issue raised against STU3 and applied for R5. It reported that ElementDefinition.constraint.source has type canonical(StructureDefinition), but generated constraints were being populated with an element FHIRPath or resource name instead of the canonical URL of the source StructureDefinition.

Initial application:
No source commit explicitly mentioning FHIR-20675 was found. The broader canonical-reference work in FHIR-12902 had already changed ElementDefinition.constraint.source from uri to canonical(StructureDefinition) in source/datatypes/elementdefinition.xml, and later tooling/source regeneration now emits canonical URL values for inherited constraint sources.

Additional context:
The current ElementDefinition datatype is active build input in source/fhir.ini and remains normative. A later same-family Jira, FHIR-26682, reported short type names such as DomainResource in generated snapshots but was retracted after the reporter confirmed the problem had been fixed in the then-current R4/R5 output. Zulip discussion in late 2019 matches the seed issue: Grahame clarified that source should be blank for locally defined constraints and otherwise populated with the canonical URL of the source.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The active datatype source defines ElementDefinition.constraint.source as canonical(StructureDefinition), and a current-source scan found no ElementDefinition constraint source values in checked-in StructureDefinition XML that are FHIRPath/resource-name strings instead of canonical URLs.

Recommendation:
Keep this no-change audit commit. No FHIR-core source fix is needed unless a future generated artifact or tool output again produces non-canonical ElementDefinition.constraint.source values.
