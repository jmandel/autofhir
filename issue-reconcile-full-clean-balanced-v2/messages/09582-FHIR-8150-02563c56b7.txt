FHIR-8150: Audit List emptyReason withholding clarification

Issue request:
FHIR-8150 was a Published FHIR-core/List change request from the 2015 May DAF ballot, resolved Not Persuasive with Modification. It questioned whether the List.emptyReason code "information withheld" could communicate partial withholding on a non-empty list, and the approved disposition was to clarify that the empty reason applies when all list content has been withheld while acknowledging that partial population has no known general solution other than notes or entry-level flags.

Initial application:
The issue was applied by git-svn commit 41329eb70f2b855bd911c8fdcf95b521332faefd, svn revision 6085, titled "#8150 - clarify use of List.emptyReason". That commit changed the List spreadsheet comment to say the code is for use when the entire list has been suppressed, not when individual items are omitted, and changed the withheld code definition to say the content of the list was not provided. The 2021 source rework carried the List.emptyReason comment forward into source/list/structuredefinition-List.xml.

Additional context:
List is an active current-build resource in source/fhir.ini. The current List StructureDefinition has constraint lst-1 requiring emptyReason only when entry is empty, and the List.emptyReason comment still says the code is for the entire list being suppressed rather than individual omitted items. The List narrative also warns receivers not to assume a list is complete because entries may have been withheld, and the current THO CodeSystem definition for list-empty-reason#withheld preserves the "content of the list was not provided" wording. Jira/Zulip/Confluence searches found no final later decision requiring a different core source change.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active core source and current terminology surface already express the approved FHIR-8150 clarification and avoid implying that List.emptyReason reports partial withholding on non-empty lists.

Recommendation:
Keep this audit commit as-is. If a future work group wants a standard way to mark partial withholding within populated lists, that should be handled as a new substantive design issue rather than by changing the existing List.emptyReason semantics.
