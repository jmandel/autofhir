FHIR-13702: Audit Encounter waiting subject status

Issue request:
FHIR-13702 was Published/Persuasive with Modification for R5. It asked to add a "waiting" code to Encounter.status so outpatient and similar encounters could track time spent waiting. The accepted resolution did not add waiting to the required Encounter.status value set; it split overall encounter state from patient-specific state by adding Encounter.subjectStatus, reorganizing status/subjectStatus codes, updating Status Management guidance, and noting that statusHistory was out of scope for this issue.

Initial application:
The Jira application comment says the change was partially applied with GF#13072. Git history confirms that b8e66a8579ca2e5e44a6fbd18ba4362b631a38f8 added Encounter.subjectStatus, reorganized Encounter.status and subjectStatus terminology, and updated Encounter examples. Later FHIR-13702-tagged commits 84c280b9715941ba29c953bf6c3cd14779d381ce and dc223befbe35bc659d657b3124bc6a70d697583d updated the Status Management section and subjectStatus definition to explain waiting-like patient states and local workflow-specific subjectStatus codes.

Additional context:
Encounter is active in source/fhir.ini, so source/encounter/structuredefinition-Encounter.xml, source/encounter/codesystem-encounter-status.xml, source/encounter/valueset-encounter-status.xml, source/encounter/valueset-encounter-subject-status.xml, and source/encounter/encounter-introduction.xml are current build-scope source. Later Published issue FHIR-32343 relaxed Encounter.subjectStatus from extensible to example and added definitions/new subject-status semantics, so the current example binding is an intentional later refinement rather than an incomplete FHIR-13702 application. FHIR-14157 separately replaced statusHistory/classHistory with EncounterHistory, matching FHIR-13702's note that statusHistory would be revisited elsewhere. Community searches found no direct FHIR-13702 Zulip or Confluence decision that conflicts with the Jira/source/git trail; a later ED waiting-room Zulip question shows implementation modeling interest but no approved reversal.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current build-scope source already keeps Encounter.status as the required overall encounter state without a waiting code, defines Encounter.subjectStatus as the patient-specific status that can represent waiting-like states, and states in the Status Management narrative that the example subjectStatus binding permits local "waiting" statuses for workflow-specific use.

Recommendation:
Keep this no-change audit. Do not add waiting to the required Encounter.status code system for FHIR-13702; any future standardized waiting code or additional ED workflow guidance should be handled by a new PA decision because the current source matches the published modified resolution and later Encounter refinements.
