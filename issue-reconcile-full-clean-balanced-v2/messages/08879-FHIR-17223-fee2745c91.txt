FHIR-17223: Audit compartment search URL correction

Issue request:
FHIR-17223 was a Published/Persuasive technical correction for the FHIR-core HTTP page. It asked to correct the GET compartment search URL from `[base]/[Compartment]/[id]/{*?...}` to `[base]/[Compartment]/[id]/*{?...}` and to explain that the literal `*` in the URL means all resource types in the named compartment.

Initial application:
The Jira comments record SVN revision 14180, and the imported git history contains e69671f97d1f8c1f6564601b041bd6ebe1ff228f (`GF#17223 - typo`) from 2018-07-29. That commit changed `source/http.html` to use `GET [base]/[Compartment]/[id]/*{?[parameters]{&_format=[mime-type]}}` and added prose saying the `*` appears literally to mean all types.

Additional context:
The referenced Zulip thread confirms the original interpretation: Grahame Grieve called the `{*` placement a typo, gave the corrected `/*{?...}` form, and clarified that `*` means resources of all types. Current `source/http.html` still has the corrected GET form and literal-star explanation, while `source/search.html` has matching current search-context prose using `GET [base]/[compartment]/[id]/*?parameter(s)`. Later compartment-search clarification work in FHIR-51608 added cross-links and behavior text in the same area without reversing the FHIR-17223 correction.
