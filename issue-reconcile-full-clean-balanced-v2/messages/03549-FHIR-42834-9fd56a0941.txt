FHIR-42834: Restore escaped-comma example clarification

Issue request:
FHIR-42834 was an Applied FHIR-I change request resolved as Persuasive. The reporter noted that the escaping section claimed a URL containing a backslash-escaped comma had the same meaning as examples where the comma remained a multi-value delimiter, even though the escaped comma becomes part of the search value.

Initial application:
The issue appears to have been applied by source commit badb98fe3e2df7a0e5c8bb10364697439ac3655b and its later equivalent 7a31ece31b504b076d7257877184ae3a8047d7a1, both titled "FHIR-42834 : Clarify escaping examples." Those commits changed source/search.html so the same-meaning examples no longer used a backslash-escaped comma and added a separate escaped-delimiter example with explanatory text.

Additional context:
The later FHIR-48702 implementation commit d83729a5d4743f1218b4e53aad9e70c5363880da reorganized the same search page to explain readable unencoded examples and URL encoding. During that refactor, source/search.html again put the backslash-escaped comma form in the list of URL strings with the same meaning. The related FHIR-48702 reconciliation is already represented on the combined branch and does not need a duplicate decision.

AutoFHIR reconciliation:
This commit makes the narrow source correction in the current build-scope source page source/search.html: the same-meaning percent-encoding list now uses a mixed percent-encoded comma example instead of the backslash-escaped comma example. The separate paragraph below remains the place that demonstrates a backslash-escaped delimiter and explains that it yields two ValueSet url literals.

Recommendation:
Keep this source fix. It restores the approved FHIR-42834 clarification while preserving the later FHIR-48702 readable-example structure and avoiding a duplicate FHIR-48702 audit.
