FHIR-3505: Audit Observation boolean value decision

Issue request:
FHIR-3505 was a Published/Persuasive with Modification OO change request asking whether Observation.value[x] should permit a boolean value. The final 2014 OO resolution voted not to add a Boolean choice at that time and instead to add a note directing boolean-like Observation values to Observation.valueCodeableConcept with HL7 v2 Table 0136 yes/no concepts, which could be displayed as true/false or other mutually exclusive terms.

Initial application:
The old source history explicitly applied the modified resolution in commit e7e897aecfb7be8264ee48025b0f0a0908c81320, titled "[#3505]update comments in obs.value". That commit added the v2 0136 yes/no guidance to the Observation.value[x] spreadsheet comment and added #3505 to the committee notes. The current StructureDefinition still carries #3505 in the committee notes for Observation.value[x] and Observation.component.value[x].

Additional context:
Observation is active in source/fhir.ini, and the current source/observation StructureDefinition and notes are build-scope evidence. Later Published/Persuasive OO issue FHIR-10275 revisited the same premise and explicitly resolved to add Boolean to Observation.value[x]. Related Published issues FHIR-6344, FHIR-7547, and FHIR-8605 already have combined-branch audit commits covering the explanatory yes/no guidance; those audits identify FHIR-3505 as the same old Observation boolean-value family. Current source now both permits valueBoolean and retains notes recommending valueCodeableConcept with terminology.hl7.org/ValueSet/v2-0136 when Observation results are not truly binary.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The original no-Boolean part of FHIR-3505 has been superseded by FHIR-10275, while the modified-resolution note remains present in current Observation notes. Removing valueBoolean would contradict later final OO guidance, and adding more text would duplicate existing Notes guidance.

Recommendation:
Keep this no-change audit commit as-is. No core source edit is needed for FHIR-3505; future changes to the balance between direct valueBoolean and coded yes/no Observation values should be made only under a newer OO decision.
