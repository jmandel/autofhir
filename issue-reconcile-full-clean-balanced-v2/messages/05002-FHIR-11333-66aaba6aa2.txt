FHIR-11333: Audit CarePlan context clarification

Issue request:
FHIR-11333 was a Published/Persuasive Patient Care change request against DSTU2 CarePlan.context asking that the definition stop saying the care plan was "defined" in a context and instead clarify the original context in which the CarePlan was created.

Initial application:
The issue appears to have been applied in commit f39dde8e171836d3345715f788c746e0a1624492, which changed the CarePlan.context definition from "Identifies the context in which this particular CarePlan is defined" to "Identifies the original context in which this particular CarePlan was created" in the then-authoritative CarePlan spreadsheet source.

Additional context:
CarePlan is active in source/fhir.ini. Later workflow alignment renamed the old CarePlan.context element to CarePlan.encounter and narrowed the target to Encounter, while preserving the creation-context meaning as "The Encounter during which this CarePlan was created or to which the creation of this record is tightly associated." FHIR-11171 subsequently relied on this clarification when deciding that CarePlan.context could still support longitudinal care plans and separately clarified CarePlan.period. No Zulip or Confluence evidence was found that conflicts with the Jira/source history.

AutoFHIR reconciliation:
This is an empty audit commit. The current active source already conveys the requested distinction: it describes the encounter associated with CarePlan record creation, not a boundary that confines all care plan activity to that encounter, and the comment explicitly says resulting activities may occur in other encounters.

Recommendation:
Keep this no-change audit commit as-is. No core source edit is needed for FHIR-11333 unless a future Patient Care decision intentionally changes the CarePlan.encounter semantics.
