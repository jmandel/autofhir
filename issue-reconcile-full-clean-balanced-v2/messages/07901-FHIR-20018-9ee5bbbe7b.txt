FHIR-20018: Audit IG parameter extensible binding

Issue request:
FHIR-20018 was a Published/Persuasive with Modification FHIR-I change request for R5 asking to loosen the fixed required ImplementationGuide.definition.parameter binding. The accepted resolution changed ImplementationGuide.definition.parameter.code from string to Coding and added an extensible binding so tool-specific code systems can define additional IG build parameters.

Initial application:
The issue was applied in core by commit 493ea99d47628ab5c056aed42faff4b36ecdb638, "FHIR-20018 - Made ImplementationGuide.definition.parameter Coding instead of string," which changed the active ImplementationGuide StructureDefinition from string to Coding and added the extensible guide-parameter-code binding. Follow-up history updated examples and guide-parameter-code terminology metadata, leaving the current resource source and examples internally consistent.

Additional context:
ImplementationGuide is active in source/fhir.ini, so source/implementationguide/structuredefinition-ImplementationGuide.xml is current build input. Earlier FHIR-17189 raised the same extensible-binding idea but was verbally withdrawn for lack of justification. Later FHIR-25569 explicitly relied on the FHIR-20018 Coding/extensible model when deciding not to rename existing hyphenated guide-parameter-code values, and it is already represented on the combined branch. Later FHIR-35778 and FHIR-55166 confirm that supplemental IG Publisher parameter definitions live in the tooling IG/external package space rather than requiring core to close or enumerate the value set.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current core source has ImplementationGuide.definition.parameter.code as Coding with an extensible binding to http://hl7.org/fhir/ValueSet/guide-parameter-code, and the checked ImplementationGuide example encodes parameter.code as a Coding with the guide-parameter-code system.

Recommendation:
Keep this no-change audit commit as-is. Future IG Publisher/tool-specific parameters should continue to be represented through Coding systems and external tooling IG definitions; do not re-tighten the core binding or add redundant core prose unless a later work-group decision changes that ownership model.
