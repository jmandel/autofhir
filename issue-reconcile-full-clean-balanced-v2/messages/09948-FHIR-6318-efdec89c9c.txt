FHIR-6318: Audit Bundle search mode precedence

Issue request:
FHIR-6318 was a Published FHIR-core change request with a Persuasive with Modification resolution. It asked what to do when a Bundle search result entry is both a match and an _include result even though Bundle.entry.search.mode is single-valued; the approved resolution was to specify that match takes precedence.

Initial application:
The issue appears to have been applied by imported SVN commit 98d6090a13fe3b4b406dd8c856c74602d7b0d8dc (#6318 - note about search.mode, svn revision 6385), which added the precedence comment to source/bundle/bundle-spreadsheet.xml. Later source rework commits 33b409a4b6d544598262f2f074ebb4b6dc466157 and c69d71aa213de86d55e0261339c15e4bacd509e6 carried the same comment into source/bundle/structuredefinition-Bundle.xml.

Additional context:
Bundle is an active current-build resource in source/fhir.ini, and current source/search.html also states the same rule in the search narrative. Jira searches found FHIR-6318 as the only final issue for the match-precedence phrase; FHIR-8335 was a same-element Resolved - No Change definition concern, and FHIR-50491 is an unresolved R6 issue about outcome-mode references rather than match/include precedence. Zulip discussions cite the current line as guidance, and Confluence searches found no conflicting work-group record.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already says there is only one mode and that, when a resource is both a match and an include, match takes precedence, in both the Bundle element comment and the search page narrative.

Recommendation:
Keep this no-change audit commit as-is. No core follow-up is needed for FHIR-6318 unless a later resolved issue intentionally changes Bundle.entry.search.mode semantics.
