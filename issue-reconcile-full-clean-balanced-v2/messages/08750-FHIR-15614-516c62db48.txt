FHIR-15614: Audit IG spreadsheet name parsing

Issue request:
FHIR-15614 was a Published/Persuasive FHIR-core change request from STU3. It asked spreadsheet authoring to capture both a descriptive name and a computable name for profiles and extensions, and to expose both during publication.

Initial application:
The Jira comment cites svn 14848, but the git-svn history shows the substantive adjacent application as 434b134490aac49a8d7ed62856b41317e6ef6a77, build@14849, titled "GF#15614 - fix name/title parsing in IG spreadsheets". That commit updated the historical IG spreadsheet parser to read Profile.name and Profile.title columns for profile and extension StructureDefinitions. The exact build@14848 commit was only a build-file fix, and dce1c6d144781e8e53b187d6e598cf8917467949 had begun the same name/title parsing work earlier that day.

Additional context:
The implementation file that carried this issue, tools/java/org.hl7.fhir.igtools/src/org/hl7/fhir/igtools/spreadsheets/IgSpreadsheetParser.java, is not present in the current core checkout. It was removed when the IG publisher moved out of this repository, notably by 56ceb0df08dd72381a4f98f1ea4ac5ea6d139a8b ("Remove IG publisher (it's gone to Maven)") and later Java cleanup. The current build depends on the external Kindling publisher artifact, while current active core extension source already has separate Name and Title columns and the extension page template exposes the computable name.

AutoFHIR reconciliation:

Recommendation:
