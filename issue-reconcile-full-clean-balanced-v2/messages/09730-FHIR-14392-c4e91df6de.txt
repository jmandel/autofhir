FHIR-14392: Audit Observation component guidance

Issue request:
FHIR-14392 was a Published/Persuasive OO change request for STU3 Observation. It asked the specification to clarify that Observation.component can represent either separate individual parts of an observation or qualifying information for Observation.code, and that the complete set of Observation code/value and component code/value pairs must be considered to understand the observation.

Initial application:
The issue appears to have been applied by git commit 0b2b3d039c ("GF#14392"), which added the component guidance to source/observation/observation-notes.xml and added code/comment text to the then-current Observation spreadsheet. The current source has been migrated from that spreadsheet into source/observation/structuredefinition-Observation.xml while retaining the relevant comments.

Additional context:
Observation is active in source/fhir.ini, so source/observation is in current build scope. The current notes explicitly say component observations may be separate individual parts or qualifying information to Observation.code, and that all code-value and component.code-component.value pairs need to be taken into account. The current StructureDefinition comments for Observation.code and Observation.component.code carry the same interpretation rule, and Observation.component links readers to the notes. A later OO issue, FHIR-51724, was Resolved - No Change after quoting this same text as sufficient to distinguish Observation.component and Observation.hasMember. Zulip searches found discussion and direct references to the qualifier use, but no final community decision that reverses the Jira/source outcome; Confluence searches found no references.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current active Observation source already conveys the FHIR-14392 guidance through the Observation notes and element comments, and adding another restatement to Observation.component would be redundant rather than a necessary correction.

Recommendation:
Keep this no-change audit as-is for FHIR-14392. If OO wants stronger future rules defining observation qualifiers or prohibiting hasMember for qualifiers, that should be handled as a new work-group decision rather than as a FHIR-14392 reconciliation change.
