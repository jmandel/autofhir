FHIR-12252: Audit DeviceRequest rename

Issue request:
FHIR-12252 was a Published/Persuasive OO change request for the FHIR-core DeviceUseRequest artifact. It asked to rename DeviceUseRequest to DeviceRequest and clarify that the resource concerns allocation of a device to a patient, may include instructions for use, and leaves the logistics of getting the device to the patient to other resources.

Initial application:
No source-history commit was found that explicitly names FHIR-12252. The apparent application is the January 9, 2017 DeviceUseRequest-to-DeviceRequest source work in commits 7bf0f7e00f13fcfaec67c9e17d8c89e75f3cf08a and 2d7f54c1d65906343cdc69a239a51781713be51f, whose subjects cite [#12552]. The first commit renamed the active resource folder and fhir.ini entries from DeviceUseRequest to DeviceRequest and replaced the Boundaries and Relationships text with the requested allocation/instructions/logistics clarification; the second updated a related diagram/translation surface.

Additional context:
The current build-scoped source continues to use DeviceRequest as the active resource: source/fhir.ini lists devicerequest=DeviceRequest in [resources], and source/devicerequest/structuredefinition-DeviceRequest.xml defines id, name, URL, and type as DeviceRequest. Remaining DeviceUseRequest strings are legacy compatibility records in the deleted-resource list, resource-name tracker, and old resource type code system. Later Zulip and OO Confluence evidence treats DeviceRequest as having replaced DeviceUseRequest and found no final decision reversing this rename. FHIR-57360 was found as a current Triaged issue, but it concerns the later DeviceRequest.code-to-product element rename rather than the DeviceUseRequest resource rename and is not final.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The latest combined-branch source already reflects both halves of FHIR-12252: the active resource is DeviceRequest, and the current DeviceRequest introduction says the resource deals with allocation of a device to a patient, may contain instructions for use, and addresses delivery/implantation/fulfillment logistics in other resources.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-12252 unless OO later resolves a separate naming or DeviceRequest workflow issue that intentionally changes the current resource scope.
