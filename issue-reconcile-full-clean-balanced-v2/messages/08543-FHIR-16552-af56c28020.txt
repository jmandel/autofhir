FHIR-16552: Audit ImplementationGuide apply parameter

Issue request:
FHIR-16552 was a Published/Persuasive with Modification STU3 FHIR-I change request for ImplementationGuide.definition.parameter. The original request asked for apply-status, apply-publisher, and apply-contact boolean parameters, but the accepted resolution changed that to a single repeatable "apply" parameter whose value names the metadata field to propagate: version, date, status, publisher, contact, copyright, experimental, jurisdiction, or useContext. The resolution also dropped the specialized apply-version design and included an IG Publisher tooling follow-up for generated resource URLs.

Initial application:
The issue was applied in the old spreadsheet-era source by 08263bfe9f, which replaced the old apply-business-version/apply-jurisdiction code list with the single "apply" parameter and the metadata-field definition that includes status, publisher, and contact. The Jira-commented follow-up 6c82a7d4e4 changed the then-present IG Publisher ConfigFileConverter from specialized apply constants to GuideParameterCode.APPLY with values such as "version" and "jurisdiction".

Additional context:
Current source no longer uses the old ImplementationGuide spreadsheet or includes the IG Publisher tooling path that 6c82a7d4e4 modified. Later source refactors preserved the issue's semantics: FHIR-20018 made ImplementationGuide.definition.parameter.code a Coding with an extensible binding to ValueSet/guide-parameter-code, and the active code system still defines the single "apply" code with the full metadata-field list. source/fhir.ini actively lists implementationguide=ImplementationGuide, so the inspected resource folder is in the current build.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current active ImplementationGuide source already represents the accepted modified resolution: parameter.code is bound to guide-parameter-code, the guide-parameter-code CodeSystem defines "apply", and the definition says the value can be version, date, status, publisher, contact, copyright, experimental, jurisdiction, or useContext.

Recommendation:
Keep this audit commit as-is. No current FHIR source correction is needed for FHIR-16552; any future publisher-tool behavior about generated resource URLs belongs in the current IG Publisher/tooling repository rather than this core-spec checkout.
