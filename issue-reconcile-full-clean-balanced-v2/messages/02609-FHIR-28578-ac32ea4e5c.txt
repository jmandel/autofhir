FHIR-28578: Correct Appointment invariant source metadata

Issue request:
FHIR-28578 was Published/Persuasive for R5 and asked PA to add an Appointment invariant ensuring Appointment.end is not before Appointment.start when the dates are provided.

Initial application:
The issue was applied by git commit 42ae2bc6afe1ad0f2afcd922884f14aa6c5e74ce, which added app-5 to source/appointment/structuredefinition-Appointment.xml. That commit added the correct human text and FHIRPath expression, and the current source still attaches app-5 to Appointment.start and Appointment.end. The same initial hunk also copied a constraint source URI of Questionnaire, leaving the Appointment constraint with incorrect metadata.

Additional context:
Appointment is an active current-build resource in source/fhir.ini, and PA WGM minutes recorded the FHIR-28578 persuasive vote. The originating Zulip thread supports the same model-level rule and did not identify a later conflicting decision. Later Appointment history reformatted or cleaned the invariant but did not correct the copied Questionnaire source URI.

AutoFHIR reconciliation:
This commit changes only the app-5 constraint source from http://hl7.org/fhir/StructureDefinition/Questionnaire to http://hl7.org/fhir/StructureDefinition/Appointment. The invariant itself is already present, so no redundant rule or prose was added.

Recommendation:
Keep this commit as-is. The current specification already enforces the requested start/end ordering rule; this correction makes the active Appointment StructureDefinition metadata match the resource that declares the invariant.
