FHIR-8171: Audit differential inherited context rendering

Issue request:
FHIR-8171 was a Published / Persuasive with Modification DSTU1 FHIR-core issue on the profiles page. It asked generated profile Differential Table views to show inherited base cardinality, type, and definition information greyed out when omitted from the differential, so readers could understand the delta without switching between differential and snapshot views.

Initial application:
Jira records svn revision 6682 as the application. The migrated source history contains commit b1640e6611a7d2b99e6c31bd31ad7205dcb5dbb5, git-svn build@6682, with the message "#8171 - improve rendering of differentials". That commit changed the old ProfileUtilities differential rendering code to fall back to base ElementDefinition type/cardinality/definition content and mark it with DERIVATION_EQUALS-style metadata for greyed inherited display.

Additional context:
FHIR-5909 raised the complementary concern that unchanged primitive value elements should not appear as if they were constrained. Current build-scope profiling source resolves the same presentation tension by stating that differentials contain only differences, snapshots are verbose and complete, and Differential Tables may show non-differential context partially transparent. The old Java renderer files changed in 2015 are not current build-scope source in this checkout.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already documents the accepted differential/snapshot presentation model from FHIR-8171, and the current CI build renders the profiling page with the same "additional information not in the differential is also shown partially transparent" text.

Recommendation:
Keep this audit commit as-is. Follow up only if the active publisher stops rendering inherited differential context transparently, or if FHIR-I decides to replace the current sparse differential plus transparent context model.
