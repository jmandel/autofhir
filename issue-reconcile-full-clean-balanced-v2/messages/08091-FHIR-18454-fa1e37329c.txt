FHIR-18454: Audit JSON complex id example

Issue request:
FHIR-18454 was a Published/Persuasive FHIR-core JSON clarification raised against STU3. It asked for the JSON complex datatype section to show an id on a complex type, because the prose said complex datatypes can have ids but the example only showed the id on the primitive family element.

Initial application:
The issue was applied by git commit 2877c9faab985bf0d59bf5a3bfea6129bdcd8fe8, whose subject was "GF#18454 - fix json example". That commit added id="f2" to the XML Patient.name element, added the matching JSON "id" property under "name", and expanded the explanatory note to distinguish the primitive family id from the complex name id.

Additional context:
The current source/json.html page still contains the same substantive example in the JSON representation of Complex Datatypes and XHTML section: Patient.name has id="f2", the JSON name object has "id" : "f2", and the note explicitly explains that the family id is represented in _family while the id on name is represented as a normal property. Although the Jira resolution text said to remove the family id, the implementation comment explained that it was retained because the nearby note still needed to illustrate primitive id handling; with the added name id, the original ambiguity is resolved. No Confluence reference to this issue and no relevant Zulip discussion were found.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build source already demonstrates a complex datatype id and preserves useful adjacent primitive-id contrast without misleading implementers.

Recommendation:
Keep this no-change audit commit as-is. No follow-up is needed unless the work group wants to simplify the example by removing the primitive family id, which would be an editorial preference rather than a required correction for FHIR-18454.
