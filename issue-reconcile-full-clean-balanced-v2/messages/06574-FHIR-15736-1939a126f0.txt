FHIR-15736: Audit ValueSet display designation guidance

Issue request:
FHIR-15736 was Published/Not Persuasive with Modification for FHIR-core ValueSet. It asked to let ValueSet.compose.include.concept.display carry designation language, use, and value details, either by turning display into a backbone element or by adding a designation.isPrimary flag. The accepted resolution rejected those structural changes and said the relationship between display, designations, and Resource.language should be documented instead.

Initial application:
The recorded application is git commit 670fde290b18eb77285b22912615dc941c139afa, which added a Display and Designations section to source/valueset/valueset-notes.xml explaining that display is equivalent to a special designation and that its language is the Resource Language. No current evidence shows a missing structural change because the Jira resolution explicitly chose documentation rather than a new display substructure or isPrimary element.

Additional context:
FHIR-18575 later corrected the same ValueSet designation wording from primary code to primary designation and is already represented on the combined branch by c67067b7a2f4cca5a7925b711cd79a57e38066b5. Current source/valueset/valueset-notes.xml uses that later wording, and source/valueset/structuredefinition-ValueSet.xml points display readers to the narrative while repeating the same display/designation relationship in the designation comment. ValueSet is active in source/fhir.ini, so these files are current build inputs.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current built ValueSet guidance already satisfies FHIR-15736: the display remains a simple string, designations remain the extensible representation for alternate languages and purposes, and the narrative plus StructureDefinition comments identify display as the primary designation in the resource language.

Recommendation:
Keep this audit commit as-is. Do not add display subelements or designation.isPrimary for FHIR-15736; those alternatives were rejected, and duplicating the existing guidance elsewhere would add maintenance risk without changing implementer understanding.
