FHIR-15779: Audit string search punctuation handling

Issue request:
FHIR-15779 was a Published/Persuasive FHIR-core search change request from STU3 asking that string search matching allow servers discretion to ignore punctuation and non-significant whitespace, such as matching OLeary against O'Leary. Its resolution said to add to the current description that ignoring punctuation and non-significant whitespace is appropriate too.

Initial application:
The issue was applied in git-svn commit 281cb96e04d1a226a770e42beede9de64269b647, which records svn revision 14265 and added the string-search sentence "Punctuation and non-significant whitespace (e.g. repeated space characters, tab vs space) should also be ignored" to source/search.html. The current active search page still contains that rule, now in a conformance span and with editorial punctuation only.

Additional context:
source/search.html is an active specification page listed in source/hierarchy.xml. Later edits, including FHIR-44047, touched the sentence editorially without changing the substance. The originating Zulip thread confirms the same O'Leary use case and the intended server-discretion framing, and bounded Jira/Zulip/Confluence searches found no later conflicting decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already tells implementers that punctuation and non-significant whitespace SHOULD also be ignored for string searches, preserving the published application of FHIR-15779 while leaving room for justified exceptions under SHOULD semantics.

Recommendation:
Keep this no-change audit commit as-is. If the work group later wants weaker MAY-level language instead of the historically applied SHOULD wording, that would be a new policy decision rather than a reconciliation fix for FHIR-15779.
