FHIR-7933: Align history entry requirements

Issue request:
FHIR-7933 was a Published/Persuasive with Modification DSTU1 issue asking to remove the then-current requirement that each history entry contain entry.transaction, because servers may create resource versions through channels other than FHIR REST interactions.

Initial application:
The issue was initially applied by SVN revision 5343, represented in git as 8c21b3c592, which changed source/http.html to allow a history entry to contain either the resource state or a transaction entry for a DELETE. Later source history renamed transaction to request, but the old optional-request wording remained in the HTTP history paragraph and had become an incomplete sentence that no longer matched current Bundle rules.

Additional context:
Later published decisions refined the current rule. FHIR-8818 renamed the Bundle transaction element to request. FHIR-17075 clarified that history Bundles need request/response details, and FHIR-38942 moved Bundle type entry requirements into invariants; current Bundle bdl-3b requires history entries to have request and response elements, and bdl-14 preserves FHIR-19620's rule that PATCH interactions are represented as PUT rather than PATCH in history. The 2020 implementers Zulip thread on non-REST history entries clarifies that systems should still expose equivalent create/update/delete request details for changes made outside the RESTful interface.

AutoFHIR reconciliation:
Updated the active source/http.html history interaction paragraph so it no longer says a history entry may contain only a resource instead of request details. The paragraph now states the current request and response requirement, explains that request details can describe an equivalent non-REST change, and keeps the current PUT/POST resource requirement with no PATCH expansion.

Recommendation:
Keep this source change. It reconciles the stale 2015 FHIR-7933 application with later published current-spec requirements. A separate PATCH wording conflict from FHIR-34388 versus FHIR-19620 remains outside this seed and should be reviewed under that issue family if assigned.
