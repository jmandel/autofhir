FHIR-32403: Remove stale MessageHeader author example

Issue request:
FHIR-32403 was an Applied/Persuasive with Modification FHIR-core MessageHeader change request raised against R4. It asked how MessageHeader.author and MessageHeader.responsible differ, and the final resolution was to move sender under source as the last element while removing author and responsible.

Initial application:
Git commit 21db7ce85648ecbcc2a88295b74e4a4015053b22 applied the main conformance-source change for FHIR-32403 and related MessageHeader issues by removing the top-level MessageHeader.author and MessageHeader.responsible differential elements and replacing top-level sender with MessageHeader.source.sender. That commit did not update the active MessageHeader example, leaving source/messageheader/messageheader-example.xml with a top-level author element that no longer exists in the current StructureDefinition.

Additional context:
FHIR-41269 asked the same sender/author/responsible removal question for R6 and is already represented on the combined branch by an audit commit, so this reconciliation does not duplicate that issue. INM minutes for 2023-09-13 record the 10-0-4 motion to move sender under source and remove author/responsible for FHIR-32403, FHIR-41269, and related issues. FHIR-41271 supplied the supporting Messaging-module clarification that MessageHeader is necessary for interpreting a bundle but should not be persistent context once message resources are processed elsewhere. FHIR-45997 later cleaned MessageHeader notes that still referred to deleted enterer/author/responsible elements.

AutoFHIR reconciliation:
Removed the stale top-level author element from source/messageheader/messageheader-example.xml. The file is in current build scope because MessageHeader is active in source/fhir.ini and list-MessageHeader-examples.xml names messageheader-example as the listed active MessageHeader example. The hunk is necessary because the current StructureDefinition no longer defines MessageHeader.author, so the active example was showing a removed element.

Recommendation:
Keep this source fix as-is for FHIR-32403. Do not add new MessageHeader.author guidance; event authorship or persistent responsibility should be represented on the payload, Provenance, Task, or other appropriate resources rather than on the transient MessageHeader.
