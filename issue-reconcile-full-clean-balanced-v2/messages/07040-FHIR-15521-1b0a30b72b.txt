FHIR-15521: Audit DiagnosticReport supportingInfo

Issue request:
FHIR-15521 was Published/Persuasive with Modification for STU3. It asked for DiagnosticReport to reference other information considered in creating or interpreting a report; the final resolution was to make the standard extension event-supportingInfo, cardinality 0..*, type Reference(Any), with DiagnosticReport context.

Initial application:
No commit is tagged with the modern FHIR-15521 key, but the historical GF#15521 application is present. Commit 2ebd7c6f added supportingInfo to source/profiles/event-extensions-spreadsheet.xml as a Resource extension with DiagnosticReport and Observation contexts, cardinality 0..*, Reference(Any), and patient-record supporting-information wording. Commit 36d02fb3 documented the new event-supportingInfo extension in ballot notes.

Additional context:
The linked Zulip thread records OO's 2018 motion to make this a standard extension and the rationale that report responses need to identify patient-record information used in creating the report, distinct from RelatedArtifact's knowledge-resource/citation role. Later, FHIR-36858 made DiagnosticReport.supportingInfo a core R5 backbone element with a role code and reference. FHIR-53024 then clarified that the workflow-supportingInfo extension should only list DiagnosticReport for R4B and earlier; the Extension Pack currently carries that version-specific context limit.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope DiagnosticReport source already contains DiagnosticReport.supportingInfo as a 0..* core element, with type and reference children and a live example, while the older extension definition belongs to the Extension Pack and is version-limited for DiagnosticReport pre-R5. Reintroducing or editing a core extension in this checkout would conflict with the later model.

Recommendation:
Keep this no-change audit commit as-is. Future work, if any, belongs with later DiagnosticReport.supportingInfo terminology or Extension Pack maintenance issues rather than FHIR-15521.
