FHIR-8490: Audit Timing documentation cleanup

Issue request:
FHIR-8490 was Published/Persuasive for the DSTU1 core datatypes page. It asked to remove or correct contradictory Timing.repeat wording that said both "Event occurs frequency times per duration" and "Event occurs frequency times per period", and to improve the before-meals Timing example so duration and period did not both appear as 10 minutes.

Initial application:
The same frequency wording was already corrected by the related Published issue FHIR-8102 in svn revision 6035, which changed the Timing definitions from "per duration" to "per period". FHIR-8490 itself was then applied in svn revision 6611 by commit ff4f5844ef2a0b69f40884f3b6e04db8e3b69745, changing the table row from "For 10 minutes before meals" with matching 10 minute values to "For 5 minutes, 10 minutes before meals".

Additional context:
The current build includes Timing as an active datatype on the datatypes page. A later Published Timing issue, FHIR-8697, introduced the offset column for before/after event timing and moved the before-meals example away from using period as an offset. Current source now shows frequency and period definitions using "per period" and the example uses duration=5 min, when=AC, offset=10, and no period value. No relevant Zulip or Confluence evidence was found that changes this interpretation.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already satisfies FHIR-8490's requested correction, and changing the surrounding narrative would be redundant rather than necessary for implementer understanding.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-8490 unless a future work group decision chooses to further reword the general Timing narrative for style or terminology consistency.
