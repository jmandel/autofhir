FHIR-46910: Audit MedicationAdministration statusReason wording

Issue request:
FHIR-46910 was Applied/Persuasive for R6 by Pharmacy. It asked that MedicationAdministration.statusReason no longer read as only a not-performed reason because the element can also explain status changes such as on-hold or entered-in-error. The approved Jira resolution was to update the element definition to "A code indicating why the status of the administration changed," and a later Pharmacy clarification requested both the definition and short description be updated.

Initial application:
The issue was applied before this reconciliation by the Jira-tagged FHIR-46910 commits in PR HL7/fhir#3896. Commit 9528799f1c changed the MedicationAdministration.statusReason definition from the not-performed wording to the approved status-change wording, and the later FHIR-46910 commits edda560a84, 2613343df1, and 34e8fe0e00 refined the short display to the current "Reason status of the administration changed."

Additional context:
MedicationAdministration is active in source/fhir.ini, so source/medicationadministration/structuredefinition-MedicationAdministration.xml is in build scope. The current element short and definition match the Jira resolution and the September 2025 clarification. Older adjacent artifacts still contain historical not-given/search-parameter/binding labels, but FHIR-46910's final application was explicitly limited to the element definition and short description; changing canonical search parameters or example terminology would need a separate Pharmacy decision.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change because the active StructureDefinition already carries the approved FHIR-46910 wording for both MedicationAdministration.statusReason short and definition.

Recommendation:
Keep this audit commit as-is. If Pharmacy wants the legacy reason-not-given search parameter, binding label, or example value set broadened to match the newer statusReason framing, handle that as a separate Jira decision because it is beyond the Applied FHIR-46910 scope and may affect canonical or terminology surfaces.
