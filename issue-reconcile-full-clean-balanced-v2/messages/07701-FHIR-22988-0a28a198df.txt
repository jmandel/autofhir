FHIR-22988: Audit value-set registry Id column removal

Issue request:
FHIR-22988 was a Published FHIR-I change request, resolved Persuasive with Modification for R5, asking why the first tab of the FHIR value-set registry had an Id column whose values did not match the ValueSet.id values in XML/JSON/Turtle. The approved resolution said the column was only the tail of the artifact OID, was unclear and rarely useful, and should be removed.

Initial application:
No core-source commit mentioning FHIR-22988 was found. The current source page source/terminologies-valuesets.html is active narrative for the value-set registry and delegates the table to the <%valuesetslist%> generator include. Published-page comparison shows the requested application did occur by R5: the R4 value-set registry table had columns Name, Definition, Source, and Id, while the R5 and current build outputs have only Name, Definition, and Source.

Additional context:
FHIR-I January 2020 WGM minutes record Grahame's explanation that the Id column showed the end of the OID for the value set and was not useful, with a Persuasive with Modification motion to remove it. Current source/fhir.ini still has an active [valuesets] section feeding the registry, and the current generated build page continues to omit the Id column. A nearby search hit, FHIR-40545, concerns ConceptMap table headings rather than this value-set registry and was not decided here.

AutoFHIR reconciliation:
This audit commit makes no source change. The authoritative current build surface for terminologies-valuesets.html already reflects the approved removal, and the remaining core source page contains only the active narrative shell plus generator placeholder rather than a stale Id-column definition to edit.

Recommendation:
Keep this audit commit as-is. No core FHIR source change is needed for FHIR-22988 unless a future build-regression reintroduces an Id column into the generated value-set registry table.
