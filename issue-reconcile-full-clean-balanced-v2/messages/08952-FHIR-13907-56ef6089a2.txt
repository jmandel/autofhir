Issue request:
FHIR-13907 was Published/Persuasive for STU3 by FHIR-I. It asked to put statusReason on the Request and Event workflow patterns so the status reason could explain suspended, cancelled, not-done, aborted, and similar statuses without requiring Provenance, and so statusReason would subsume the earlier notDoneReason concept.

Initial application:

The same revision also applied the closely related FHIR-13457 Event.notDone collapse; FHIR-13457's Jira comment explicitly notes that notDoneReasonCode was subsumed by GF#13907 into statusReason.

Additional context:
Current source/fhir.ini includes both event and request in [logical], so source/event/event-spreadsheet.xml and source/request/request-spreadsheet.xml are current build inputs. The current Event pattern has status code not-done plus Event.statusReason, and the current Request pattern has Request.statusReason with guidance to replace status reasons when state changes.
