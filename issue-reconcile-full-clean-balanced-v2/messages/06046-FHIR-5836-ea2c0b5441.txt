FHIR-5836: Audit retired ReferralRequest status names

Issue request:
FHIR-5836 was a Published/Persuasive Patient Care DSTU1 change request for ReferralRequest.status. It asked to rename the status code sent to requested and the status code refused to rejected for consistency with equivalent request resources; the approved resolution was to make both name changes.

Initial application:
The refused-to-rejected portion appears to have been applied before the Jira-tagged commit: git commit 34f497b60d2cc6fda5b0cd29d5416bf2f50b8b17 changed the ReferralRequest status code row from refused to rejected and updated the status-codes matrix, and commit 3b756d3151caf9335f852a0bf9a01d2500e4e3b6 changed the ReferralRequest.status short value list from refused to rejected. Git commit b40ce8e28558ce4b7a692f4fa9b0ea24b8bd5c38, titled "{#5836} {#3827} Update ReferralRequest statuses", then changed the ReferralRequest example status and value-set row from sent to requested.

Additional context:
FHIR-3827 is the same ReferralRequest.status change family and was applied in the same Jira-tagged commit by adding accepted. The current build no longer includes ReferralRequest as an active resource: source/fhir.ini lists ServiceRequest as active, lists ReferralRequest under removed resources, and records "ReferralRequest became ServiceRequest"; source/history.html also records ReferralRequest and ProcedureRequest becoming ServiceRequest. Current ServiceRequest.status is bound to the general RequestStatus value set, not the old DSTU1 ReferralRequest-specific sent/requested/refused/rejected/accepted lifecycle.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The requested DSTU1 ReferralRequest status names were applied historically, and changing current ServiceRequest.status to reintroduce the old ReferralRequest-specific codes would be an incorrect current-version change rather than a reconciliation of FHIR-5836.

Recommendation:
Keep this no-change audit as-is. Any future ServiceRequest status changes should come from a current Patient Care/Orders and Observations decision for the active ServiceRequest/RequestStatus model, not from the retired ReferralRequest DSTU1 tracker.
