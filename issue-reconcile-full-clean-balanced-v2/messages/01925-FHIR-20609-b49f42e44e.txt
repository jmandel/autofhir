Initial application:
The issue appears to have been applied in commit c4807a5165ee632872ef9f6289fee8e9e1abbb5f, whose message lists FHIR-20609 among MnM R5 changes and initially added source/datatypes/codesystem-timingabbreviation-codes.xml with code C. Follow-up commit 6314862f6c410bf17b0136e5e54e1d20b7c2d5c3 moved the new code directly into the timing-abbreviation worksheet in source/datatypes/timing.xml, which is the current source representation.

Additional context:
source/fhir.ini actively lists Timing in the [types] section, so source/datatypes/timing.xml is in current build scope. Related same-value-set issue FHIR-13520 concerned other timing abbreviations and is already represented on the combined branch; it does not change the FHIR-20609 result.
