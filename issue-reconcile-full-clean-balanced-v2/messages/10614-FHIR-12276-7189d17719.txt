FHIR-12276: Audit extension code binding validator

Issue request:
FHIR-12276 was a Published/Persuasive FHIR-core change request from DSTU2 asking that the build tool reject extension definitions whose value type is code when the binding strength is not required. The Jira example was QICore-AdverseEvent.severity with an example binding, and the application comment says the future build would generate an error in SVN revision 11444.

Initial application:
The issue was applied by git commit 48770dbe1f6b54bb320aca9a3bf5644ddfd1b4e0, whose subject is '#12276 - error for extensions that have type = code and not a required binding' and whose git-svn-id records build@11444. That commit added ExtensionDefinitionValidator.checkCodesHaveRequiredBinding to throw when an Extension.value element has type code without a required binding, and it made extension spreadsheet parsing invoke the validator after snapshot generation.

Additional context:
The old tools/java build sources that contained the original validator were removed from this repository by commit 9f549566d1346cad7db6d2afca6080d7cebdfbbe when the repository switched to Gradle and the external Kindling dependency. Current source/build configuration uses org.hl7.fhir:kindling version 1.25.5-SNAPSHOT, and that dependency's source jar still contains ExtensionDefinitionValidator.checkCodesHaveRequiredBinding plus the parser call that validates generated extension StructureDefinitions. The active [profiles] extension spreadsheet entries in source/fhir.ini were checked, and a scan of the current active core extension spreadsheet/XML sources found no code-valued extension rows with non-required bindings. Direct Zulip and Confluence searches for FHIR-12276 and the QICore-AdverseEvent example found no conflicting community record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The requested build-tool behavior was implemented historically, migrated out of the core checkout into the Kindling build dependency, and remains present in the current dependency used by this repository. Editing current FHIR source would either duplicate external tooling logic or change unrelated extension content.

Recommendation:
Keep this audit commit as-is. If a future failure shows that a particular current extension pack or IG build is not receiving this validation, follow up in the relevant external publisher/Kindling or extension-pack repository rather than changing HL7/fhir source for FHIR-12276.
