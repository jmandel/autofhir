FHIR-19590: Audit Device Type value set rename

Issue request:
FHIR-19590 is Published/Persuasive for FHIR core Device. It asked to rename the former FHIR Device Type / device-kind value set to Device Type so it could be referenced by other specifications, and the recorded resolution says Device and DeviceDefinition should reference http://hl7.org/fhir/valueset-device-type.html, with DeviceDefinition being the source needing change.

Initial application:
The issue was applied before this reconciliation. Commit a8227bb51b renamed source/device/valueset-device-kind.xml to source/device/valueset-device-type.xml and changed the Device binding name to DeviceType; commit 90089e6daa fixed the value set name/title to DeviceType / Device Type; commit 902dde180b changed DeviceDefinition to bind to http://hl7.org/fhir/ValueSet/device-type; and commit 3a62519d7f removed remaining active source references to the old device-kind URL in related resources.

Additional context:
source/fhir.ini lists both device and devicedefinition as active current resources. The current source has no active source/device-kind or valueset-device-kind references outside historical release snapshots. The July 2019 OO Confluence minutes include FHIR-19590 in the Device block-vote material, and a later Zulip thread about Device type versus kind raises terminology clarity concerns but does not reverse the canonical rename. FHIR-19588 was co-applied in a8227bb51b but is a separate DeviceDefinition.safety value-set issue and is already represented on the combined branch. FHIR-16125 is an earlier no-change DeviceKind expansion question and does not alter this rename decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active value set source is source/device/valueset-device-type.xml with url http://hl7.org/fhir/ValueSet/device-type and title Device Type, and the active Device.type and DeviceDefinition.classification.type definitions bind to that same value set. A remaining DeviceKind bindingName label on DeviceDefinition.classification.type is not the canonical value set URL/title targeted by FHIR-19590 and does not change the Jira-requested conformance target.

Recommendation:
Keep this no-change audit. The current build source satisfies the published FHIR-19590 decision; any future cleanup of historical/internal binding labels should be handled as a separate work-group decision rather than as a required FHIR-19590 reconciliation fix.
