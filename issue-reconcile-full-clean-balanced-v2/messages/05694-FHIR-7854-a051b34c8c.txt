FHIR-7854: Restore Encounter.type v2 mapping to PV1-18

Issue request:
FHIR-7854 is a Published/Persuasive FHIR-core Encounter change request from the Patient Administration work group. It asked to change the HL7 v2 mapping for Encounter.type from PV1-4 Admission Type to PV1-18 Patient Type because PV1-4 describes admission circumstances and Encounter.priority already maps to PV2-25.

Initial application:
The Jira resolution says the mapping was updated as specified. Git commit 2afe9fbe29 applied the tracker by changing the old Encounter spreadsheet mapping from PV1-4-admission type to PV1-18 Patient Type.

Additional context:
Encounter is an active resource in source/fhir.ini, so source/encounter/structuredefinition-Encounter.xml is in the current build scope. Later commit 5f27be6a8d changed the same mapping from PV1-18 Patient Type to PV1-4 / PV1-18 during a broad final-QA pass over v2 mappings, but no later core Jira or community evidence was found that reversed FHIR-7854. FHIR-5699 is a related Encounter v2 mapping issue, but its requested changes did not include Encounter.type.

AutoFHIR reconciliation:
Updated source/encounter/structuredefinition-Encounter.xml so the current Encounter.type HL7 v2 mapping is PV1-18 only, preserving the current field-number-only style used by nearby v2 mappings while removing the rejected PV1-4 reference.

Recommendation:
Keep this source fix as-is. If a future work group decision wants to allow PV1-4 as an additional Encounter.type source, it should be recorded in a new core tracker because it would intentionally reverse the specific FHIR-7854 mapping decision.
