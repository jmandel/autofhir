FHIR-26455: Audit Evidence simplification changes

Issue request:
FHIR-26455 was Published/Persuasive for R5. It asked to simplify Evidence by folding referentGroup into variableDefinition, adding population and subpopulation variable roles, allowing variableDefinition observed/intended references to Group or EvidenceVariable, removing referentGroup, renaming actualDefinition/intendedDefinition to observed/intended, making variableDefinition 1..*, making variableRole 1..1, and updating Evidence examples.

Initial application:
The change was applied in commit 6c133340e7 (merged by 1f19fe12d5) as "Evidence resource change J#26455". That implementation replaced referentGroup usage in Evidence examples with variableDefinition, renamed actualDefinition/intendedDefinition to observed/intended, and updated the then-authoritative Evidence spreadsheet source.

Additional context:
Evidence is in current build scope through source/fhir.ini. The current StructureDefinition has no referentGroup, actualDefinition, or intendedDefinition, and Evidence.variableDefinition.observed and .intended both reference Group and EvidenceVariable. The current variableRole element is 1..1 with a required binding. The two apparent differences from the 2020 request are intentional later changes: FHIR-43056 changed variableRole to the R6 code set population | exposure | outcome | covariate and added roleSubtype for sub-classifications, and FHIR-48987 explicitly changed Evidence.variableDefinition cardinality from 1..* back to 0..*. The CDS 2020-03-11 agenda records approval of FHIR-26455, and no conflicting Zulip or Confluence evidence was found.

AutoFHIR reconciliation:
This commit makes no source change. The current source already carries the FHIR-26455 structural simplification where it remains current, while the missing subpopulation role and 1..* cardinality are superseded by later applied R6 decisions.

Recommendation:
Keep this audit commit as-is. Re-adding subpopulation as an Evidence.variableDefinition.variableRole code or changing variableDefinition back to 1..* would conflict with later applied Jira decisions; any further changes to role subtype terminology should be handled under the later R6/UTG work, not FHIR-26455.
