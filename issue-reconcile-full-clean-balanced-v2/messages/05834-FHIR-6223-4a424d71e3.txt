FHIR-6223: Audit MedicationStatement request and dispense links

Issue request:
FHIR-6223 was a Published/Persuasive with Modification Pharmacy change request from DSTU1 asking why MedicationStatement did not have a reference to MedicationDispense or Prescription to link the statement to an order, possibly as an alternative to inline dosing elements. The accepted resolution was to add MedicationStatement commentary that dosage information in a medication statement is independent of dispense or prescription information and is not conducted from those resources in FHIR, and the issue was recorded as addressed as part of FHIR-7167.

Initial application:
No git commit explicitly mentioning FHIR-6223 was found in the MedicationStatement source history. The referenced FHIR-7167 application is explicit: commit 7d50996061 (#7167, svn 6686) added MedicationStatement scope/usage text saying the resource is not part of the prescribe -> dispense -> administer sequence, and commit e7200c208f immediately adjusted that text for the build. The current source has since been refactored from older inputs into active MedicationStatement XML source while retaining and extending the same distinction.

Additional context:
MedicationPrescription was later renamed to MedicationRequest, and current MedicationStatement source is active and approved in source/fhir.ini. The current introduction distinguishes MedicationStatement from MedicationRequest, MedicationDispense, and MedicationAdministration, states that MedicationStatement is a broader assertion independent of specific order, dispense, or dosing events, and directs links to the request, dispense, or administration used to derive the statement into MedicationStatement.derivedFrom. The active StructureDefinition defines derivedFrom as a Reference(Resource) for underlying MedicationRequest or other supporting information and comments that likely references include MedicationRequest and MedicationDispense. Later FHIR-13695 resolved a similar request for prescription and dispense dates as no-change because those details can be reached through derivedFrom, and the associated Zulip thread reached the same implementation pattern. FHIR-41500, already represented on the combined branch, further clarified that informationSource is the who or what source of the statement while derivedFrom is for source resources.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already gives implementers both parts of the FHIR-6223 outcome: a MedicationStatement does not conduct dosage/order details from prescriptions or dispenses, and when an actual MedicationRequest, MedicationDispense, or MedicationAdministration was used to derive the statement, the relationship belongs in MedicationStatement.derivedFrom rather than replacing local MedicationStatement dosage information.

Recommendation:
Keep this audit commit as-is. Do not add another redundant comment for FHIR-6223; future changes should come from a later Pharmacy decision if the work group wants different derivedFrom targets, different MedicationStatement dosage semantics, or new core elements for request/dispense details.
