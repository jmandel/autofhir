FHIR-11271: Audit current-list clarification request

Issue request:
FHIR-11271 was a Published FHIR-core lifecycle issue from DSTU2 asking for more explanation of "current resource lists", including how a resource becomes available to a current list and whether active status or period is enough. The final disposition was Not Persuasive: current lists were intended to capture a clinical curation activity, and membership cannot generally be inferred from the resource content alone.

Initial application:
No git commit explicitly mentioning FHIR-11271 was found. The current-list mechanism itself was added earlier by the FHIR-7551 implementation commit, and the current source still preserves the core curation point in the List resource notes: direct resource queries expose an uncurated view, while lists are curated and may reflect an author's notion of current/relevant. The current lifecycle page has since had its detailed current-list section removed rather than expanded.

Additional context:
Later evidence continues to treat "current" as server/business-rule curation rather than a deterministic status calculation. FHIR-47135 was resolved No Change with the same rationale that current does not mean status=active, and a 2024 implementers Zulip thread records that the logic for determining current is not interoperable and is up to the server. FHIR-47134 sought more status guidance but remains Resolved - change required, so it is context only for this default Applied/Published reconciliation. A 2025 source commit removed the lifecycle current-list details for R6 due to lack of implementation experience and possible API Incubator follow-up.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Adding the requested extra lifecycle explanation would contradict the seed issue's Not Persuasive disposition, and the current source already avoids promising that resource status or period alone can determine current-list membership. Any broader cleanup after the R6 removal of the lifecycle details, such as references from search or resource-guide pages to the now-removed definitions, should be handled by a separate current-list issue or work-group review rather than by this rejected DSTU2 clarification request.

Recommendation:
Keep this audit commit as-is for FHIR-11271. If FHIR-I wants to reintroduce, relocate, or fully remove current-list mechanics after the R6 lifecycle-page change, revisit that through an active issue such as the FHIR-47134/FHIR-39342 family or API Incubator follow-up, not by reopening this Not Persuasive seed.
