FHIR-19256: Audit Library content summary

Issue request:
FHIR-19256 was Published/Persuasive for the FHIR-core Library resource. It asked that Library.content be marked as a summary element so clients can list libraries with content metadata without retrieving full embedded content, while relying on Attachment.data remaining outside summaries.

Initial application:
The Jira comment points to GH#6898f7fb27, and commit 6898f7fb27963bc638709c80faac396b1272d773 changed the historical source/library/library-spreadsheet.xml row for Library.content by setting the Summary column to Y. Later source refactoring moved the authoritative Library definition into source/library/structuredefinition-Library.xml and preserved the summary flag.

Additional context:
source/fhir.ini actively includes library=Library, so source/library/structuredefinition-Library.xml is in current build scope. The current Library.content differential is type Attachment and has isSummary=true, and the ElementDefinition summary documentation still lists Attachment.data as an exception that is not marked as summary. Jira, Zulip, and Confluence searches found no later or conflicting decision for FHIR-19256.

AutoFHIR reconciliation:
This commit intentionally makes no source change because the current build-scoped source already satisfies the published Jira decision and preserves the intended exclusion of the actual attachment data.

Recommendation:
Keep this audit commit as-is. No follow-up is needed unless a future CDS or infrastructure decision changes Library.content summary behavior or Attachment summary rules.
