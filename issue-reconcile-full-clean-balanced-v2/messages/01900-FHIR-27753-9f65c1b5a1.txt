FHIR-27753: Audit MedicationRequest entered-in-error definition

Issue request:
FHIR-27753 was a Published/Persuasive Pharmacy technical correction for R5. It reported that the MedicationRequest status code entered-in-error only had usage notes and no actual definition, and asked to add a definition before the notes; the accepted resolution supplied wording beginning "The prescription was recorded against the wrong patient or for some reason should not have been recorded".

Initial application:
The issue was applied by git commit 76ef92c3597ed1e3e2e1e7e398e6e772f385df64, which changed source/medicationrequest/codesystem-medicationrequest-status.xml from notes-only text to the accepted definition-plus-notes wording. MedicationRequest is active in the current build through source/fhir.ini resource and work-group entries, so the CodeSystem source remains the authoritative place to check this code.

Additional context:
A later Applied/Persuasive Pharmacy issue, FHIR-54903, explicitly revisited the same MedicationRequest entered-in-error definition and resolved to replace the FHIR-27753 wording with "The request was entered in error and is not valid." Pharmacy minutes record the FHIR-54903 vote, and git commit 358c5eb203b35c6326e060566926db8aeda12352 applied that later wording. The original Zulip thread for FHIR-27753 confirms the problem was the absence of a clear definition before usage notes, not a requirement to preserve the original examples indefinitely.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already gives entered-in-error a direct definition, and the current wording reflects a later final Pharmacy decision that superseded the longer FHIR-27753 text.

Recommendation:
Keep this no-change audit commit as-is. Do not reintroduce the FHIR-27753 examples or longer wording unless Pharmacy reopens or reverses FHIR-54903.
