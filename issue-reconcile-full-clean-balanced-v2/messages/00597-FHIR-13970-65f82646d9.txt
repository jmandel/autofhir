FHIR-13970: Audit MessageDefinition GraphDefinition move

Issue request:
FHIR-13970 was a Published/Persuasive STU3 InM change request asking MessageDefinition to reference GraphDefinition to define the full content of the message. The Jira resolution says the reference was added, with a 2018-07-26 InM vote recorded as 3-0-0.

Initial application:
The request was initially applied in commit 92e2142167c74cdff8b2bea73813c2eea0f15c0f, which changed the MessageDefinition spreadsheet to add MessageDefinition.graph as canonical(GraphDefinition) with cardinality 0..*. The element survived the 2021 source rework into structuredefinition-MessageDefinition.xml, and later FHIR-23723/FHIR-39095 decisions refined it to 0..1 and updated the wording for message Bundles.

Additional context:
Current R6 source no longer has GraphDefinition as an active core resource: source/fhir.ini has MessageDefinition active and normative but no active GraphDefinition entries, and source/conformance-module.html says GraphDefinition is now in the API Incubator because it is still subject to change. Commit 270e0ceb7b029dad4ca0fc5ccf5296ff370888cd made that R6 normative/build-scope change by removing GraphDefinition from fhir.ini and deleting MessageDefinition.graph. FHIR-I/FMG additional-resources discussions confirm GraphDefinition and $graph moved to the API Incubator lane while keeping hl7.org/fhir canonicals and using package dependencies/allowed-target mechanisms for moved content.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no core source change. Restoring MessageDefinition.graph in core would reintroduce a hard dependency on a GraphDefinition resource that is no longer part of the current core build and would cut across the later R6 Additional Resources/API Incubator decision.

Recommendation:
Keep this audit commit as-is for core reconciliation. If InM/FHIR-I wants R6 MessageDefinition to computably point at API Incubator GraphDefinition again, handle that as follow-up work in the API Incubator/additional-resources mechanism or through a new explicit work-group decision, not by reviving the retired core element under this STU3 issue.
