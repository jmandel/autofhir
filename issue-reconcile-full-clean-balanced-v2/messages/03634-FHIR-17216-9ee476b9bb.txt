FHIR-17216: Audit medicinal product effective date range

Issue request:
FHIR-17216 was a Published/Persuasive BR&R change request, raised against STU3 MedicinalProduct and applied for R5, asking that the MedicinalProduct effectiveDate dateTime be represented as a range because licenses and similar applicability periods can require renewal. The Jira resolution says the request was accepted and that the change had already happened by the time it was discussed.

Initial application:
No git commit explicitly mentioning FHIR-17216 was found. Git history shows the older draft MedicinalProduct manufacturingBusinessOperation.effectiveDate existed as dateTime in the pre-R5 source, while the active current-branch MedicinalProductDefinition source introduced by 33b409a4b6 already represented operation.effectiveDate as Period with range wording.

Additional context:
The current build uses MedicinalProductDefinition rather than the old MedicinalProduct name, with fhir.ini carrying MedicinalProduct as a redirect to MedicinalProductDefinition. The active resource entry is in source/fhir.ini, and the R5 published StructureDefinition also has MedicinalProductDefinition.operation.effectiveDate typed as Period. Jira search found no other same-artifact issue beyond FHIR-17216, and community searches found no substantive Zulip or Confluence discussion changing the Jira/source conclusion.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The authoritative current source already satisfies the issue by using Period for MedicinalProductDefinition.operation.effectiveDate and describing it as a date range of applicability.

Recommendation:
Keep this no-change audit as-is. No follow-up is needed in FHIR core unless a future BR&R decision changes the MedicinalProductDefinition operation effective date semantics.
