FHIR-26876: Audit Organization contact data type

Issue request:
FHIR-26876 was Applied with resolution Persuasive with Modification. It asked whether Organization.contact should use Location rather than Address so implementations could represent location-specific business identifiers, status, aliases, and similar details. The final resolution states that Organization.contact was updated in R5 to use the new ExtendedContactDetail data type and that no additional changes are necessary.

Initial application:
No source commit explicitly tagged FHIR-26876 was found. The requested contact model was instead applied through the R5 ExtendedContactDetail issue family: FHIR-29035 created ExtendedContactDetail, FHIR-29034 changed Organization.contact from a backbone element to ExtendedContactDetail, and FHIR-27005 confirmed that this data type satisfied missing Organization contact period needs. The seed comments record the submitter reviewing the R5 model and reporting no issues with the proposed model for most use cases.

Additional context:
FHIR-25375 handled the parallel Location.contact use case with the same ExtendedContactDetail type. PA minutes on 2023-03-29 explicitly resolved FHIR-26876 as already updated in R5 with prior changes. The current build includes Organization as an active resource and ExtendedContactDetail as an active normative data type, and the current Organization.contact element is typed as ExtendedContactDetail.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Changing Organization.contact to Location would conflict with the final Jira resolution and with the current model that separates contact details from Location resources while allowing purpose, name, telecom, address, responsible organization, and period through ExtendedContactDetail.

Recommendation:
Keep this empty audit commit as-is. No core source follow-up is needed for FHIR-26876 unless PA opens a new tracker to model additional location-scoped or role-specific contact semantics beyond ExtendedContactDetail.
