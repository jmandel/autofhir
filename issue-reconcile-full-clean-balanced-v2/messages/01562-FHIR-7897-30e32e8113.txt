FHIR-7897: Audit Immunization patient search parameter

Issue request:
FHIR-7897 was a Published PHER change request, resolved Not Persuasive with Modification, asking whether Immunization should be searchable by subject and whether the same question applied to AllergyIntolerance. The decisive Jira comment and resolution accepted the FHIR group pattern: remove the subject search parameter where a resource has a patient element; resources with a patient element should have a patient search parameter, while resources with a broader subject that could be a patient may have both subject and patient search parameters.

Initial application:
The historical source application is explicit: git commit b4d544060a included "#7897 remove subject search param" and removed the subject row from source/immunization/immunization-spreadsheet.xml while leaving the patient search row against Immunization.patient. Later source refactoring moved search parameter definitions from spreadsheets into bundle-*-search-params.xml files without reintroducing the Immunization subject parameter.

Additional context:
FHIR-3705 had already renamed Immunization.subject to Immunization.patient under the same patient-vs-subject naming rule, which explains why Immunization should expose patient rather than subject. source/fhir.ini actively includes both allergyintolerance and immunization resources, so their current bundle search parameter files are in build scope. The current AllergyIntolerance and Immunization search parameter bundles each define a patient search parameter against the .patient element, and neither resource folder contains a subject search parameter. Zulip and Confluence searches for FHIR-7897 and for Immunization.subject/Immunization.patient found no contrary community guidance.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current active source already matches the FHIR-7897 decision: Immunization is searchable by patient, not subject, and AllergyIntolerance follows the same patient-only pattern.

Recommendation:
Keep this no-change audit commit as-is. No follow-up source work is recommended for FHIR-7897 unless a future work group decision changes the patient-vs-subject search parameter policy.
