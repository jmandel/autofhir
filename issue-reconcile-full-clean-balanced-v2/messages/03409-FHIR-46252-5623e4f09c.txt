FHIR-46252: Audit DeviceDefinition owner removal

Issue request:
FHIR-46252 is an Applied/Not Persuasive with Modification R6 OO change request. It reported that DeviceDefinition.owner was defined as the organization responsible for provision and maintenance even though a concrete device could be owned or maintained by a Patient, Practitioner, or RelatedPerson. The approved resolution was to remove DeviceDefinition.owner, restate DeviceDefinition.contact, and rely on DeviceDefinition becoming a CanonicalResource with publisher 0..1 and contact 0..* publisher-contact semantics.

Initial application:
The issue has a direct application trail. Git commit 2b74d88a57 added publisher/contact and removed the DeviceDefinition.owner element. Commit 16ad92fc76 removed the remaining duplicate ContactPoint contact element while preapplying FHIR-49107. Commit 29848d66ff adjusted the publisher/contact short text for FHIR-46252. The related search parameter work was preapplied in b50e9309dc and finished in 62decc7761 for FHIR-49105.

Additional context:
DeviceDefinition is active in source/fhir.ini and the current combined branch defines DeviceDefinition as a CanonicalResource. Current source/devicedefinition/structuredefinition-DeviceDefinition.xml has no DeviceDefinition.owner element, has DeviceDefinition.publisher, and has DeviceDefinition.contact as 0..* ContactDetail with publisher-contact wording. Current source/devicedefinition/bundle-DeviceDefinition-search-params.xml defines the publisher string search parameter over DeviceDefinition.contact.name | DeviceDefinition.publisher. FHIR-49105 and FHIR-49107 are tightly related but are already represented on the combined branch by separate no-change audit commits, so this commit does not duplicate them. FHIR-39389 and FHIR-42900 remain broader CanonicalResource context rather than additional issue decisions in this default applied/published run.

AutoFHIR reconciliation:
No source change was made. The current authoritative source already implements the FHIR-46252 resolution: owner is removed, publisher/contact are present with CanonicalResource semantics, and the dependent publisher search parameter is in place.

Recommendation:
Keep this no-change audit commit as-is. Do not reintroduce DeviceDefinition.owner; handle any broader remaining CanonicalResource alignment under FHIR-39389/FHIR-42900 or their own reconciliation decisions.
