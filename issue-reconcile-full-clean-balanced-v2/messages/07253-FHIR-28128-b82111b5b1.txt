FHIR-28128: Use capabilities interaction wording

Issue request:
FHIR-28128 was a Published FHIR-core Conformance change request, resolved Persuasive with Modification for R5. It asked to fix the CapabilityStatement typo "CapabilityStatemnt" and to replace confusing "on demand" wording in the CapabilityStatement Notes section with references to the RESTful capabilities interaction, while leaving "publish" wording intact because it refers to traditional publication by clients.

Initial application:
The prior application commit 6727905ebbfaa8aee1c52e2c5f5d723798707964 fixed the typo and changed "The CapabilityStatement returned on demand" to "The CapabilityStatement returned in the capabilities interaction" in source/capabilitystatement/capabilitystatement-notes.xml. That left an adjacent RESTful server bullet in the same active notes source saying servers provide "this resource on demand", so the full issue resolution was only partially reflected.

Additional context:
source/fhir.ini actively lists capabilitystatement=CapabilityStatement, so source/capabilitystatement/capabilitystatement-notes.xml is in current build scope for the CapabilityStatement resource page. The FHIR-I WGM 202105 minutes record the same decision: "We cannot change \"publish\" language but will update \"on demand\"." Later commits touched this notes file for unrelated edits and did not reverse the FHIR-28128 wording decision. Jira and community searches found no related issue that supersedes this request.

AutoFHIR reconciliation:
This commit changes the remaining stale RESTful server bullet from "this resource on demand" to "this resource using the capabilities interaction", preserving the existing http.html#capabilities link target and leaving the client "publish" guidance unchanged.

Recommendation:
Keep this source-changing reconciliation as-is. It completes the Published FHIR-28128 wording decision in the active CapabilityStatement notes source without broadening the edit beyond the approved non-substantive clarification.
