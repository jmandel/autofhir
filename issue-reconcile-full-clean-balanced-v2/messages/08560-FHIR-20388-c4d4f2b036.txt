FHIR-20388: Audit Device parent search parameter

Issue request:
FHIR-20388 was Published/Persuasive for R5 by OO and asked that Device.parent be added as a reference search parameter so clients can reconstruct complex device trees by searching for devices that reference a parent Device.

Initial application:
The change was already applied before this reconciliation. Commit a7f2575daae7bbacd9a22ea439c7ec35a4784f96, merged by f2409b3c69e13268c406a168498173bcd4677190 as PR #802, explicitly listed FHIR-20388 in the Device updates and added the parent search row to source/device/device-spreadsheet.xml. The later source rework commit 33b409a4b6d544598262f2f074ebb4b6dc466157 carried that search parameter into the current split source file source/device/bundle-Device-search-params.xml.

Additional context:
Device is an active current-build resource in source/fhir.ini. Later Device.parent issues such as FHIR-31563 and FHIR-34310 clarified that Device.parent remains the hierarchical/encompassing Device relationship while other associations belong in Device.link; those decisions do not remove or narrow the need for the Device.parent search parameter. Community searches found no conflicting Zulip discussion, and OO Confluence minutes align with the Jira block-vote history.

AutoFHIR reconciliation:
No source change was made. The current active source already contains SearchParameter/Device-parent with code parent, type reference, expression Device.parent, and the Device.parent element remains a Reference(Device).

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-20388 unless a future work-group decision changes Device.parent search metadata more broadly.
