FHIR-12349: Audit FHIRPath Patch support

Issue request:
FHIR-12349 is Published/Persuasive with Modification for DSTU2. It asked for a special Patch resource to support PATCH in transactions, batches, and history entries; the accepted modification was not to create a new resource, but to use a Parameters resource as the HTTP PATCH body with the standard FHIR content type.

Initial application:
The issue was explicitly applied in git commit 9f852260fef9f4cdd37913228c5a24cf9c1c72b2, the migrated SVN revision 11207 noted in Jira. That commit added source/fhirpatch.html, linked it from source/hierarchy.xml, added FHIRPath Patch Parameters as an allowed HTTP PATCH body in source/http.html, and replaced the old note that batch/transaction PATCH was unsupported with a statement that batch/transaction PATCH may use the FHIRPath Patch format.

Additional context:
The current source keeps the FHIRPath Patch page in the built hierarchy and the Parameters resource is active in source/fhir.ini. Later related issues refined adjacent behavior: FHIR-13644 added PATCH to Bundle.entry.request.method for Bundle use; FHIR-19620 clarified that a PATCH interaction creates history but is represented as PUT in history Bundles and added a PATCH-for-history prohibition; FHIR-34388 records a conflicting history wording decision already audited for human review; FHIR-46086 added FHIRPath Patch operation terminology/profile support and is already represented on the combined branch. FHIR-37744 asks for additional transaction examples but remains Resolved - change required and is outside this default applied/published reconciliation scope.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. Current source already satisfies the seed's accepted Parameters-based PATCH mechanism and its transaction/batch support, while the seed's original history-entry phrasing has been narrowed by later final history-specific decisions. Changing history semantics or adding transaction examples would belong to those later issues, not to FHIR-12349.

Recommendation:
Keep this no-change audit as-is for FHIR-12349. Handle any future transaction example work under FHIR-37744 and any remaining PATCH history conflict through the existing FHIR-19620/FHIR-34388 human-review path.
