FHIR-38680: Audit MetadataResource review provenance

Issue request:
FHIR-38680 was Published with a Persuasive with Modification resolution for R5 MetadataResource. The accepted scope was to clarify that lastReviewDate is the publisher's review date, retain reviewer and endorser but define them as publisher-asserted rather than local review or endorsement fields, and treat the requested standard extensions as already available.

Initial application:
The issue was applied by git commit 794ffc14b84f569c88d209a3366675e91b528f01, which updated MetadataResource.lastReviewDate to say it was last reviewed by the publisher and changed reviewer and endorser definitions to say they are asserted by the publisher. That commit also propagated equivalent wording to the concrete metadata-resource structure definitions and related source inputs that existed at the time.

Additional context:
MetadataResource is an active interface resource in source/fhir.ini, so source/metadataresource/structuredefinition-MetadataResource.xml is in current build scope. Later FHIR-39270 work added CanonicalResource localization guidance saying canonical/metadata resource elements are original author/publisher assertions and that local usage requirements should be captured in separate resources such as List or ArtifactAssessment; MetadataResource date/reviewer/endorser comments now link to that guidance. No later conflicting Jira, Zulip, Confluence, or source-history evidence was found.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already conveys the FHIR-38680 rule: lastReviewDate is publisher-scoped, reviewer and endorser are publisher-asserted, and local review/endorsement belongs outside the canonical/metadata resource instance.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed for FHIR-38680 unless the work group wants a broader editorial pass on extension-pack artifact metadata definitions, which is outside this core reconciliation.
