FHIR-14231: Audit Timing.period lower-bound wording

Issue request:
FHIR-14231 was a Published FHIR-core MedicationStatement change request resolved Persuasive with Modification. It asked the specification to clarify that, when periodMax is specified, period is the lower bound/minimum interval between each time a drug is given or taken; the final Jira comments record adding that sentence to Period and equivalent elements and explicitly not adding it to the safety page.

Initial application:
No current git commit explicitly names FHIR-14231. The requested wording appears to have been applied through the same Timing range clarification family: commit 3c90bd518312a0c35842ca968584ee9d017dba8c, for FHIR-16986/svn r14076, added the exact periodMax lower-bound sentence to source/datatypes/timing.xml and made parallel count/duration/frequency range clarifications before FHIR-14231 was called done in Jira.

Additional context:
FHIR-13384 is the original related request and was resolved No Change after Lloyd McKenzie explained that period is periodMin when periodMax is present and suggested a separate clarification request. FHIR-16986 is the broader Published Timing range issue whose applied source change supplies the requested clarification. source/fhir.ini keeps Timing, Dosage, DosageDetails, and MedicationStatement in the current build scope, and MedicationStatement.dosage now points through DosageDetails/Dosage rather than carrying independent Timing.period prose. Zulip and Confluence searches found no conflicting discussion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative Timing source already says, for Timing.repeat.period, "If periodMax is present, this element indicates the lower bound of the allowed range of the period length," which is the semantic clarification FHIR-14231 requested. The Jira follow-up comment also says the safety-page addition was not accepted, so adding new safety checklist text now would be a redundant or contrary change.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed unless a work group wants a new, broader safety-checklist policy separate from FHIR-14231.
