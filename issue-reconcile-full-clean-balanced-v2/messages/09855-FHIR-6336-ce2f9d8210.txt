FHIR-6336: Audit async operations section removal

Issue request:
FHIR-6336 was a Published/Persuasive FHIR-core change request raised against the DSTU1 operations page. It said the old "Executing an Operation Asynchronously" section was complex and under-documented, and argued that asynchronous behavior should not be forced into a single confusing message-based pattern.

Initial application:
No current git commit explicitly names FHIR-6336, but the Jira comments link the issue family to the 2015 asynchronous messaging rewrite. FHIR-7944, marked as a duplicate of FHIR-6336, records svn revision 5657; git-svn commit 8b801ae887a7ed1c4e58cb57c30a8379b50cf157 is build@5657 and removed the detailed message-transfer-agent instructions from source/operations.html while moving operation-via-message guidance to source/messaging.html. The current operations page keeps only a short pointer to the standard RESTful asynchronous pattern.

Additional context:
FHIR-7944's final resolution was not to add callback URL semantics, but to move section 2.2.0.6 to messaging, refer to it from the asynchronous section, and rewrite the note. FHIR-7976 and FHIR-6343 were part of the same build@5657 messaging/$process-message rewrite, while FHIR-7969 was a related no-change messaging comment. Later final async decisions, including FHIR-35936, FHIR-41202, and FHIR-47271, updated async.html, added synchronicity conformance, and clarified async-pattern selection; those later decisions explain why the current operations page points to async.html instead of restoring the old DSTU messaging text or the rejected callback proposal.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source no longer contains the old under-documented operations-page asynchronous execution mechanism that FHIR-6336 objected to. source/operations.html now contains only a short link to async.html; source/async.html defines the current RESTful asynchronous patterns for operations and interactions; and source/messaging.html retains operation invocation by messages in the messaging context where the 2015 resolution placed it.

Recommendation:
Keep this audit commit as-is. Removing the remaining operations-page pointer would make the current spec less clear because later applied issues deliberately use async.html as the canonical asynchronous operation guidance; any future change should come through a new FHIR-I decision about the current async.html and messaging.html pages.
