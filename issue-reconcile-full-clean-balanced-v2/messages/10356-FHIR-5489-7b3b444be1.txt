FHIR-5489: Audit Bundle entry examples

Issue request:
FHIR-5489 is a Published FHIR-I FHIR-core Feed change request from the Jan 2015 ballot. It asked for examples showing how the child attributes of Bundle entry are used, with Grahame's resolution note saying the examples existed but there should be a single detailed example. The final disposition was Persuasive and approved as edited/currently published by the FHIR core teleconference on 2015-02-12.

Initial application:
The issue appears to have been applied in the continuous build before Jira publication rather than by a commit explicitly tagged FHIR-5489. Commit 368c9c3074eeb60fb30efdb8d319e75345501ebc rewrote the Bundle example as a commented searchset and added Bundle notes that link examples by Bundle type. Commit f5a4865af08cdd1cd46e513340a9c7338b8b4d17 then added transaction and transaction-response Bundle examples and linked them from the Bundle notes. Those changes match the Jira comments and predate the 2015-02-12 approval as edited/currently published.

Additional context:
Bundle is an active resource in source/fhir.ini, so source/bundle is in current build scope. The current Bundle notes describe how entry content varies by document, message, searchset, history, transaction/batch, transaction/batch-response, collection, and subscription-notification bundle types, with links to current examples. The current Bundle examples list includes search, transaction, transaction-response, batch request/response, complex transaction request/response, and reference-resolution examples. The StructureDefinition defines the current entry children and explicitly says Bundle.entry.link has no FHIR-defined use beyond implementation-specific context, so the absence of a separate normative entry.link example is not a current semantic defect. Community searches found no Zulip or Confluence record that changes the Jira/source conclusion.

AutoFHIR reconciliation:
Made no source change. The current active source already contains the requested explanatory examples and type-specific guidance, while adding another example solely to re-satisfy this old DSTU1 ballot comment would be redundant and could create maintenance drift.

Recommendation:
Keep this audit commit as-is. No follow-up source edit is recommended for FHIR-5489 unless the work group opens a new, specific request for a missing current Bundle example such as a concrete history-bundle example or implementation-specific entry.link usage.
