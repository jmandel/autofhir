FHIR-14402: Audit aggregationMode guidance

Issue request:
FHIR-14402 was a Published FHIR-core / fhir-i change request for STU3 asking when ElementDefinition.type.aggregation applies to a Reference that has no populated Reference.reference value. The Persuasive resolution required a usage notes section saying that when aggregationMode is present, the reference SHALL be aggregated as defined and Reference.reference/Reference.reference.value SHALL be present, with the same populated-reference requirement for type.versioning.

Initial application:
The issue was applied by commit 2ae97c25bc1b176eb183225e2835f2e44b74973a, "GF#14402 - clarification about aggregation", matching the Jira comment's svn revision 14067. That commit added the ElementDefinition aggregation rules section and linked ElementDefinition.type.aggregation and ElementDefinition.type.versioning comments to it.

Additional context:
source/fhir.ini actively maps datatypes and elementdefinition pages into the current build, so source/elementdefinition.html and source/datatypes/elementdefinition.xml are authoritative current inputs. The current Account source is active but does not carry a separate aggregationMode rule needing an Account-specific edit. Later related aggregation issues FHIR-26386 and FHIR-39644 are already represented on the combined branch and refine adjacent logical-reference and bundled-definition behavior without removing the FHIR-14402 populated-reference rule.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active ElementDefinition page still says that if aggregationMode is present, Reference.reference must be present and have a value and the target must be aggregated as defined; the ElementDefinition.type.aggregation and ElementDefinition.type.versioning comments still link to that section.

Recommendation:
Keep this no-change audit commit as-is. No further core source work is needed for FHIR-14402 unless FHIR-I decides to reopen the broader relationship between aggregationMode, logical references, and identifier-only references.
