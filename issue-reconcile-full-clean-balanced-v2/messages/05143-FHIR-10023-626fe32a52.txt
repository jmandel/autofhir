FHIR-10023: Audit Goal progress application

Issue request:
FHIR-10023 was a Published/Persuasive with Modification Patient Care change request for the Goal resource. It asked to represent goal progress by adding on-target, ahead-of-target, and behind-target to the then-current Goal status value set, and to add Goal.statusReason as a 0..* CodeableConcept with an example set including not-attainable and barrier reasons.

Initial application:
The issue was explicitly applied by eda8809625 ([#10023] Updated goal status codes, and goal.statusReason cardinality and value set for goal.statusReason), which added the requested progress codes to the old Goal status spreadsheet source and added the requested status-reason codes. No current source edit is needed merely to recreate that old DSTU2 shape because the Goal model was later reworked by final Jira decisions.

Additional context:
Goal is an active current-build resource in source/fhir.ini. Later published/applied decisions changed how the same semantics are represented: FHIR-17756 split the old Goal.status into Goal.lifecycleStatus and Goal.achievementStatus, moving progress/achievement semantics out of lifecycle status; FHIR-10615 removed the original FHIR-specific status-reason value set by changing statusReason to string; FHIR-44978 then restored statusReason as 0..* CodeableConcept with a SNOMED example value set; and FHIR-53981 renamed statusReason to lifecycleStatusReason. The current authoritative StructureDefinition has Goal.achievementStatus bound to GoalAchievementStatus and Goal.lifecycleStatusReason as 0..* CodeableConcept with an example GoalStatusReason binding.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source is correct for FHIR-10023 after the later Goal status-family decisions: progress is represented by achievementStatus rather than the lifecycle status code list, and lifecycle status reasons are represented by lifecycleStatusReason with the current example value set.

Recommendation:
Keep this audit commit as-is. Re-adding the exact DSTU2 on-target/ahead-of-target/behind-target codes to Goal.lifecycleStatus would reverse FHIR-17756's split; changing the current status-reason value set back to the FHIR-10023 example codes would conflict with FHIR-10615 and FHIR-44978.
