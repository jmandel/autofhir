FHIR-8009: Audit MedicationStatement not-taken relevance

Issue request:
FHIR-8009 was a Published Pharmacy change request with resolution Persuasive with Modification. It asked whether the old MedicationStatement wasNotGiven and reasonNotGiven fields were relevant for a medication statement, and the final resolution said the previous ballot comment was persuasive to rename them to wasNotTaken and reasonNotTaken.

Initial application:
No git commit explicitly names FHIR-8009, but the same evidence trail as the prior ballot comment applies. Commit d406f9a2c0 changed the then-current MedicationStatement spreadsheet and examples from wasNotGiven/reasonNotGiven to wasNotTaken/reasonNotTaken after the 2015 Pharmacy ballot-resolution votes. Later commits and Jira decisions revised the old notTaken/taken model before replacing it with adherence.

Additional context:
FHIR-5701 is the prior Published ballot item that directly requested the wasNotGiven/reasonNotGiven rename and is audited in this same reconciliation. FHIR-11091 later reviewed harmonization with MedicationAdministration and Immunization and left MedicationStatement naming as-is. FHIR-8010 and FHIR-12470 addressed status plus notTaken/taken interpretation. Later Published Pharmacy decisions FHIR-19468, FHIR-19470, FHIR-38682, FHIR-31573, and FHIR-39271 explain the current model: status records the statement state, while MedicationStatement.adherence carries taking/not-taking and reason semantics.

AutoFHIR reconciliation:
This commit makes no source change. The current build already avoids the misleading MedicationStatement notGiven terminology; MedicationStatement is active, but current source has no active wasNotGiven or reasonNotGiven fields and instead defines MedicationStatement.adherence, adherence.code with not-taking, and adherence.reason for current use/non-use/adherence rationale.

Recommendation:
Keep this no-change audit commit. FHIR-8009 was applied historically through the DSTU1 rename, and later Pharmacy decisions intentionally moved the semantics into adherence. Reintroducing old wasNotTaken/reasonNotTaken fields or adding redundant prose would conflict with the current model.
