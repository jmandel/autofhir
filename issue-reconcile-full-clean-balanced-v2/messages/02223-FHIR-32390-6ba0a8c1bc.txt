FHIR-32390: Align Encounter ModelInfo admission rename

Issue request:
FHIR-32390 was a Published/Persuasive PA change request applied for R5. It asked to rename Encounter.hospitalization to Encounter.admission because the component describes formal admission/stay information across care settings, not only hospitalizations.

Initial application:
The primary application was commit 8112b8b2fd, merged by b99e0af032, which renamed Encounter.hospitalization in the Encounter StructureDefinition, Encounter examples, introduction text, and Encounter search parameter source. That application did not update the build-scoped FHIR ModelInfo content, which still exposed Encounter.Hospitalization and the Encounter.hospitalization element in the FHIR model definition Library.

Additional context:
Encounter and Library are active current resources in source/fhir.ini, and publish.ini copies source/library/library-fhir-model-definition-content.xml into the published build with a link from the Library examples page. The remaining Encounter.hospitalization entries in source/fhir.ini are intentional R4/R5-to-current rename compatibility metadata. FHIR-34443 is a duplicate of the same rename request, FHIR-14157 separately reorganized some former hospitalization children, and FHIR-39148 later clarified the definition of Encounter.admission and is already represented on the combined branch.

AutoFHIR reconciliation:
Updated source/library/library-fhir-model-definition-content.xml so the FHIR ModelInfo ClassInfo is Encounter.Admission and Encounter exposes an admission element of type FHIR.Encounter.Admission. No fhir.ini compatibility mappings were removed, and older QUICK/CQM/R4 example artifacts were not rewritten as part of this PA rename.

Recommendation:
Keep this source fix. It completes the seed rename on the active FHIR ModelInfo surface; any remaining modelinfo alignment for the broader FHIR-14157 Encounter reorganization should be handled by a separate reconciliation.
