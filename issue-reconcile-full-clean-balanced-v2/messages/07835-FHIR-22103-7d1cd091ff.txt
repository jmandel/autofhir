FHIR-22103: Audit version-independent Provenance target search

Issue request:
FHIR-22103 was a Published FHIR-I change request, resolved Persuasive with Modification for R5, asking for clarity when Provenance.target holds version-specific references but clients need to find Provenance records for a non-version-specific target resource. The approved resolution was to update search.html#versions so a Reference search value without /_history/[version] matches the specified URL independent of version, and to make the _include documentation also refer to _revinclude.

Initial application:
Commit 723edd92686c3667d435b854fefabb1618dc20d6 applied FHIR-22103 directly to source/search.html by adding the References and Versions rule that a reference-type search parameter without a version matches resources containing both versioned and un-versioned references, and by changing the versioned include guidance to name both _include and _revinclude. The current source retains those changes.

Additional context:
Provenance remains an active core resource in source/fhir.ini, and source/provenance/structuredefinition-Provenance.xml still describes Provenance.target as usually version specific, which is the scenario the issue was meant to support. Later Published issues FHIR-36715 and FHIR-36716 refined the adjacent reference-search syntax and explicitly confirmed that an unversioned reference search such as Provenance?target=Patient/example should match versioned target references. Later FHIR-45428 was resolved No Change and said that clients wanting all Provenances for a resource irrespective of target version should use a separate non-versioned search against Provenance.target, which aligns with the FHIR-22103 rule rather than replacing it.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The active Search page already states in source/search.html#versions that an unversioned reference-type search parameter matches versioned and un-versioned references, and the same section's include guidance already names both _include and _revinclude. The current reference search section also has examples showing a non-versioned search value matching a versioned reference to the same target resource.

Recommendation:
Keep this no-change audit commit. The current core source satisfies the published Jira decision and later related decisions reinforce the same behavior; no follow-up source edit is needed for FHIR-22103.
