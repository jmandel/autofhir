FHIR-5629: Audit Observation dataAbsentReason handling

Issue request:
FHIR-5629 was a Published/Persuasive OO change request from DSTU1 asking to add "observation not done" and "specimen unsatisfactory" to the DataAbsentReason value set. The final OO resolution changed the Observation dataAbsentReason element to CodeableConcept 0..1 with a non-exhaustive binding starting from v3 NullFlavor/DataAbsentReason concepts, rather than requiring both ideas to be fixed base FHIR codes.

Initial application:
The issue was initially applied by e09054f5d3e16546d792c10ff2188720b6aaee15, which added an Observation Value Absent Reason value set for [#5629]. Current Observation source still carries committee notes for [#5629] on Observation.dataAbsentReason and Observation.component.dataAbsentReason, and the later GF#15567 refactor replaced the redundant Observation-specific value set with the general DataAbsentReason value set.

Additional context:
Later FHIR-10398 added the generic not-performed code to DataAbsentReason, and the current terminology package and R6 expansion contain that code. For specimen-unsatisfactory cases, current Observation guidance and examples allow a coded dataAbsentReason or valueCodeableConcept, and OO minutes in 2018 explicitly treated specimen rejection details as too lab-specific for the base table while noting the table is extensible. FHIR-7150 and FHIR-41322 are already represented on the combined branch and provide later cancelled/not-performed Observation guidance.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed: the active Observation source has the CodeableConcept 0..1 extensible binding requested by the final resolution, the current DataAbsentReason expansion includes not-performed, and specimen-unsatisfactory can be represented through the existing extensible coding guidance and example without adding a base FHIR code.

Recommendation:
Keep this audit commit as-is. Future work to add more lab-specific specimen rejection reasons should be handled as a separate OO/terminology decision, not as a delayed source fix for FHIR-5629.
