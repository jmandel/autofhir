FHIR-37959: Audit profile migration to CRMI

Issue request:
FHIR-37959 is an Applied/Persuasive Vocab issue for R6 asking that the Shareable, Publishable, Computable, and Executable terminology-resource profiles be removed from the core FHIR specification and maintained going forward in the Canonical Resource Management Infrastructure IG, while leaving their canonical profile URIs unchanged.

Initial application:
The issue was applied before this reconciliation by git commit 3958dd1e7c2fd73ad1e94c66f8d0884df55695d5, which removed the ValueSet profile StructureDefinitions and removed the CodeSystem, ConceptMap, and ValueSet implementation-guide references and profile introduction files. Git commit 8c199a9c87a4339854475fec053caa6519a6ba07 then removed the remaining CodeSystem, ConceptMap, and NamingSystem profile StructureDefinitions plus their build-scope metadata/profile references.

Additional context:
May 2025 joint TI/CDS/CQI minutes record the decision to reopen FHIR-37959 and keep these profiles in CRMI rather than THO. The linked UP-634 THO proposal was later withdrawn, FHIR-48827 was retracted as a duplicate of FHIR-37959, and FHIR-47807's request to keep the ValueSet profiles in core was retracted. Later CRMI issues FHIR-52711 and FHIR-52719 updated the external CRMI profile URLs and explanatory text to reflect FHIR-37959.

AutoFHIR reconciliation:
This is an empty audit commit. Current core source/fhir.ini has no active profile entries for the migrated terminology profiles, current resource implementation guides have no StructureDefinition references to those profiles, and the old profile StructureDefinition files are absent. Existing build-scope pattern/module text points implementers to CRMI, so editing remaining unreferenced profile-introduction stubs would not change the current built specification.

Recommendation:
Keep this audit commit as-is. No core source change is recommended for FHIR-37959; future corrections to the migrated profile definitions or CRMI-specific explanatory text should be handled in the CRMI source that now owns the profiles.
