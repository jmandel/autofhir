FHIR-42720: Audit TestPlan requirement outside core

Issue request:
FHIR-42720 was Applied/Persuasive with Modification for FHIR-I. It asked for TestPlan test cases to be able to point to a single Requirements.statement.key; the accepted resolution was to add a repeated TestPlan.testCase.requirement backbone with a canonical Requirements reference and an id key identifying the statement.

Initial application:
FHIR-I discussed the canonical-vs-reference shape on 2024-04-01 and approved the canonical Requirements approach on 2024-04-15 by Richard Ettema / Yunwei Wang 10-0-0. Core commit c73f9fd93553d43f5069797c458fc0ebe6c98d6c, merged by PR HL7/fhir#3070 as af86b789611b3bddb6ca80c2ad12ca85988a61cb, added TestPlan.testCase.requirement.reference as canonical(Requirements) and TestPlan.testCase.requirement.key as id in source/testplan/structuredefinition-TestPlan.xml.

Additional context:
Later TestPlan work superseded the old testCase-centric shape. FHIR-50901 was Applied/Persuasive for R6 and concluded that the existing TestPlan was not sufficient, leading commit 80ac210e33dd10b2582e5bbcea1000bf4d4fabb4 to rework TestPlan around the Tooling IG TestCases-style suite/test structure. Commit f9a44787c45071394532c7c2ee94d76f30f47387 then removed TestPlan, TestReport, and TestScript source from active core and added a FHIR Testing IG pointer. Current source/fhir.ini has no active TestPlan resource entry, source/testplan is absent, and source/ballot-intro.html links TestPlan to the external FHIR Testing IG. The current external Testing IG TestPlan StructureDefinition has TestPlan.scope.reference canonical targets that include Requirements, but it no longer contains TestPlan.testCase or the per-test requirement.reference/key backbone added by FHIR-42720.

AutoFHIR reconciliation:
No core source change was made. The accepted change was applied while TestPlan lived in core, and the current core checkout no longer has a build-scope TestPlan StructureDefinition source to edit. Reintroducing the removed TestPlan.testCase.requirement elements in core would conflict with the later TestPlan redesign and the move of TestPlan maintenance to the external FHIR Testing IG.

Recommendation:
Keep this empty external-repo audit commit for core. If FHIR-I still wants per-test traceability to individual Requirements.statement.key values in the redesigned TestPlan model, handle that as follow-up work in HL7/fhir-testing-ig rather than in the core FHIR checkout.
