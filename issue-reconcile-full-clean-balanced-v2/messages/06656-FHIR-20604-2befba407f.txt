FHIR-20604: Audit request intent immutability guidance

Issue request:
FHIR-20604 was an Applied/Persuasive OO change request for R5 asking that intent be highlighted as immutable for request workflow implementers, with the Jira resolution specifically asking to update the DeviceRequest.intent comment and the issue metadata also naming ServiceRequest, SupplyRequest, and Task.

Initial application:
The change was applied in core source by two FHIR-20604 commits on 2024-05-03. Commit 2e1351283869 added an immutable comment to DeviceRequest.intent, and commit 15f50a71de07 added equivalent immutable wording to ServiceRequest.intent and SupplyRequest.intent. Task.intent already had immutable guidance in current source. SupplyRequest source still contains the applied wording, but SupplyRequest is no longer an active core resource in source/fhir.ini and the workflow page now links to the OO incubator SupplyRequest.

Additional context:
FHIR-20603 is the parent request-pattern issue that asked for individual trackers on request resources and for harmonized Request.intent guidance. The current Request pattern says intent is expected to be immutable, with a granularity exception. Later Applied issue FHIR-47465 intentionally changed ServiceRequest.intent to that Request-pattern wording, including the granularity exception and the instruction to create a new ServiceRequest basedOn the prior instance when a proposal becomes a plan or order. FHIR-25500, mentioned in a FHIR-20604 comment, concerned publisher display of truncated code lists with '+', not the immutability rule.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current active core source already warns implementers that DeviceRequest.intent, ServiceRequest.intent, and Task.intent are immutable or expected to be immutable, and the only current divergence for ServiceRequest is an intentional later OO decision. SupplyRequest is outside the active core build, and its retained source also already contains the immutable wording.

Recommendation:
Keep this no-change audit as-is. Do not replace the current ServiceRequest wording with the older strict sentence, because FHIR-47465 deliberately softened it to allow intent granularity changes. If future work wants all request resources to share the full Request.intent prose, handle that as a separate request-pattern harmonization issue rather than as FHIR-20604 cleanup.
