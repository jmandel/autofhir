FHIR-5802: Audit validate-code display case handling

Issue request:
FHIR-5802 was a Published/Persuasive Vocabulary change request from DSTU1 asking whether display text case should be handled case-sensitively or case-insensitively during validation. The accepted resolution was to clarify that display case handling is code-system dependent and to clarify known described code systems where that was known.

Initial application:
No current git commit explicitly mentions FHIR-5802. Jira records the application as SVN revision 5692, and the applied wording is visible in the checked release-history artifacts beginning with release2: the CodeSystem and ValueSet $validate-code display parameter documentation says, "Whether displays are case sensitive is code system dependent." The current git-era OperationDefinition XML was imported later by the build/source rework commits without changing that substance.

Additional context:
ValueSet, CodeSystem, and OperationDefinition are active resources in source/fhir.ini, and the ValueSet and CodeSystem operation lists reference their validate-code OperationDefinitions, so the inspected XML files are current-build source. Later final issues in the same operation family already govern adjacent behavior: FHIR-17218 preserved the open language-display caveat, FHIR-40770 aligned displayLanguage validation semantics, and FHIR-41229 added lenient-display-validation for invalid display severity. Zulip discussions in 2018, 2024, and 2026 show implementers still debate whether display matching should default to exact or lenient and clarify that CodeSystem.caseSensitive is about codes, not displays, but no later final Jira decision found in this investigation supersedes FHIR-5802's code-system-dependent rule.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current ValueSet and CodeSystem $validate-code sources already contain the accepted FHIR-5802 clarification, and changing the rule now based only on unresolved community discussion would exceed this Published issue and risk conflicting with later display-validation decisions that already have their own combined-branch commits.

Recommendation:
Keep this no-change audit. If Vocabulary wants a stronger default rule, a CodeSystem/Designation mechanism for display case sensitivity, or explicit text that CodeSystem.caseSensitive does not control displays, that should be handled through a new work-group decision rather than by reinterpreting FHIR-5802.
