FHIR-18363: Confirm CapabilityStatement declaration removal

Issue request:
FHIR-18363 was a Published/Persuasive FHIR-I technical correction from the STU3 ballot asking to drop the extensibility-page requirement that systems not accepting unknown extensions declare that fact in CapabilityStatement resources. The accepted rationale was that FHIR-14647/GF#14647 had removed CapabilityStatement.acceptUnknown, leaving no formal way to satisfy the requirement.

Initial application:
FHIR-14647 was applied in f0ec862a5f986e3a82bb9ef1a4fa32619c65d6e1 by removing/disabling CapabilityStatement.acceptUnknown in the CapabilityStatement spreadsheet. FHIR-18363 itself was then applied in cd5231d416ef0145942d6a04f15d50d66640be98, which removed the exact bullet "Systems that do not accept unknown extensions SHALL declare so in their CapabilityStatement resource instances" from source/extensibility.html.

Additional context:
source/fhir.ini keeps the extension type page mapped to source/extensibility.html, so that file remains the build-scope source for the affected narrative. The current extension exchange rules no longer contain the CapabilityStatement declaration requirement, and the current CapabilityStatement source has no active CapabilityStatement.acceptUnknown element. FHIR-I minutes for 2018-10-08 record the same decision and vote. A later Zulip implementers thread confirms that acceptUnknown had been removed in R4 and that a single boolean was considered a poor fit for real implementations.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because the requested requirement has already been removed from the active extensibility source, and adding or removing broader legacy acceptUnknown remnants would be outside the FHIR-18363 correction.

Recommendation:
Keep this audit commit as-is for FHIR-18363. If the work group wants cleanup of non-rendered legacy comments, narrative XSLT branches, or retired unknown-content terminology artifacts, handle that under a separate issue because the FHIR-18363 declaration requirement is already absent.
