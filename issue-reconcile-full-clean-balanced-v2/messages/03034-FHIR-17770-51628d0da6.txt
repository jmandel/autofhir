FHIR-17770: Remove lingering Person reference from Contract asset context

Issue request:
FHIR-17770 was Published/Persuasive for STU3 and asked FM to remove Person from Contract reference targets because Person is only for linking shared demographics across Patient, Practitioner, and RelatedPerson records and must not be used as a Contract author, publisher, party, subject, or other actor/relationship target.

Initial application:
Commit d7062ffc63 ("GF #17770") applied the issue to the old Contract spreadsheet by removing Person from explicit Contract reference lists such as author, publisher, party, action subject/requester, performer, and signer. The current XML StructureDefinition already had no explicit targetProfile for http://hl7.org/fhir/StructureDefinition/Person, but the old asset-context definition still described a referenced owner as an "owning Person or Organization."

Additional context:
Contract remains active in the current build through source/fhir.ini. The Person narrative currently says Person instances are never directly referenced as actors and SHALL NOT be referenced by other clinical or administrative resources, while a 2018 committers Zulip thread also called out Contract.author, Contract.contentDefinition.publisher, Contract.term.offer.party.reference, Contract.term.action.subject.reference, Contract.term.action.requester, and Contract.signer.party as part of the broader late-R4 Person-reference cleanup. Later source history added RelatedPerson to Contract.author, reinforcing that role-specific resources may be used where an individual actor is needed, but Person itself is not the actor resource.

AutoFHIR reconciliation:
Removed the remaining Contract asset-context prose that could be read as allowing a direct Person resource reference and replaced it with role-neutral owner wording. Updated the matching checked-in Contract SVG tooltip so the visible diagram artifact does not keep the stale Person cue; the authoritative source change is the StructureDefinition XML.

Recommendation:
Keep this commit as a narrow current-build cleanup for FHIR-17770. No further Contract source change is needed unless a work group chooses to replace broad Reference(Resource) uses with narrower target profiles; the current Person page already supplies the cross-resource prohibition that prevents using Person as a clinical or administrative relationship target.
