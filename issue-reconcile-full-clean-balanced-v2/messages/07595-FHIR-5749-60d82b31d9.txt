FHIR-5749: Audit ElementDefinition formal mappings

Issue request:
FHIR-5749 was a Published FHIR-core DataElement change request from DSTU1, resolved Persuasive with Modification, asking for support to capture formal mapping paths for data elements, including a mapping language such as XPath, SQL, or SPARQL and formal mapping syntax for both DataElement and ElementDefinition. The accepted resolution says this is now handled by ElementDefinition.mapping.

Initial application:
No git commit explicitly mentioning FHIR-5749 was found. The relevant application history is the 2015 commit 91a79d84e2828108b9f063bf085fc57ad6b7cc86, "Changed DataElement to use ElementDefinition", which moved the data-element modeling work onto ElementDefinition and introduced ElementDefinition mapping support. Current source/datatypes/elementdefinition.xml now defines ElementDefinition.mapping with identity, language, map, and comment children.

Additional context:
Current build scope no longer includes DataElement as an active resource: source/fhir.ini has the generic elementdefinition page active and the DataElement resource commented out, while retaining an active ElementDefinition 11179 profile. FHIR-12323 later confirmed that StructureDefinition.mapping and ElementDefinition.mapping are intentionally different: StructureDefinition declares the target mapping specification and ElementDefinition carries the actual mapping expression, with comment added for formal mapping needs. Zulip and Confluence searches for FHIR-5749 and ElementDefinition.mapping/DataElement did not find conflicting community evidence.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current built source already satisfies the Jira resolution through ElementDefinition.mapping.language for the computable language, ElementDefinition.mapping.map for the formal path/expression, and ElementDefinition.mapping.comment for mapping-use notes. Editing removed/out-of-build DataElement source or adding redundant extensions would not improve the current specification.

Recommendation:
Keep this no-change audit commit as-is. Future mapping work should be handled as new ElementDefinition.mapping, StructureDefinition.mapping, or StructureMap requirements rather than reopening DataElement-specific extensions for a resource that is no longer active in the core build.
