FHIR-23705: Audit third-party Consent wording

Issue request:
FHIR-23705 was a Published/Persuasive CBCC change request for FHIR-core Consent. It asked for Consent introduction language allowing legal consent on another's behalf, including third-party and/or court-ordered consent. The final resolution inserted language that a Consent can record a healthcare consumer's choices or choices made on their behalf by a third party, and made parallel changes to the Consent Directive definition.

Initial application:
No git commit with FHIR-23705 or 23705 in the commit message was found for the Consent source. Git history shows bbe7cd28ea, committed by the issue reporter on 2019-08-15, added the third-party/on-behalf wording to the Consent narrative definitions and source spreadsheet. Later Consent refactoring, including 24a94d5102 and the 2022 source rework in c1dda1d5fd, preserved that wording while moving it between Consent narrative/source-definition surfaces.

Additional context:
Consent is active in source/fhir.ini. The current combined branch has the third-party/on-behalf wording in the active Consent StructureDefinition description and root definition, includes a personal representative in the Consent scope introduction, retains third-party grantor language in the privacy consent model, and keeps the Consent/Consent Directive definitions that explicitly mention choices or agreements made on the consumer's behalf. Focused Zulip and Confluence searches found no FHIR-23705 discussion, minutes, or later conflicting decision; a 2018 Zulip hit showed the personal-representative introduction wording already existed before this tracker.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current active Consent source already conveys the approved rule that Consent may represent choices made on a healthcare consumer's behalf by a third party. Adding separate court-order-specific prose would go beyond the Jira's accepted resolution and duplicate the existing representative/grantor language without fixing a current semantic gap.

Recommendation:
Keep this no-change audit. If a work group wants explicit court-order terminology beyond the current third-party, personal-representative, and substitute-decision-maker language, that should be handled as a new substantive tracker rather than as FHIR-23705 reconciliation.
