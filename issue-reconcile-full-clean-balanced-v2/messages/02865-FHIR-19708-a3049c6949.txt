FHIR-19708: Audit medication category cardinalities

Issue request:
FHIR-19708 was a Published/Persuasive Pharmacy change request asking to relax category cardinality from 0..1 to 0..* for medication resources. The voted resolution was to change MedicationAdministration.category, MedicationDispense.category, and MedicationStatement.category to 0..* so they match MedicationRequest.category.

Initial application:
The Jira snapshot records application on 18Feb2019 in HL7/fhir commit aa42e5dcc1e780bf1fa001dc784d2801f6d3b1d4. That merge contains commit 9d4a0fe09370e2b75ede4debcff124f36c3d3d7e, which changed the then-authoritative medication spreadsheets for MedicationAdministration.category, MedicationDispense.category, and MedicationStatement.category from 0..1 to 0..*; MedicationRequest.category was already 0..*.

Additional context:
The resource source was later reworked for the new build core in 33b409a4b6d544598262f2f074ebb4b6dc466157, replacing the old medication spreadsheets with active structuredefinition source files. The current fhir.ini keeps MedicationAdministration, MedicationDispense, MedicationRequest, and MedicationStatement active and approved. Current source also shows AdverseEvent.category at 0..*, but the FHIR-19708 resolution did not require an AdverseEvent edit.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current structure definitions have max="*" for MedicationAdministration.category, MedicationDispense.category, MedicationStatement.category, MedicationRequest.category, and the related AdverseEvent.category, so the requested cardinality relaxation is already present in the current build-scope source.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-19708 unless a future Pharmacy decision changes medication category cardinality policy.
