FHIR-12295: Audit ElementDefinition.base snapshot requirement

Issue request:
FHIR-12295 was Published/Persuasive for FHIR-core ElementDefinition after a 2018-02-26 FHIR-I vote. It asked to make ElementDefinition.base mandatory for tooling consistency, especially to expose original cardinality for XML/JSON conversion, and to remove the sentence saying the base information is only provided when an element definition is not the original definition.

Initial application:
The explicit application commit is 895710265113b796cb75d13c9abf5cfe4aabf207, "GF#12295 - make elementdefinition.base mandatory + GF#13363 - data type related chagnes". That commit removed the old limiting sentence from source/datatypes/elementdefinition.xml and added the statement that base information must always be populated in snapshot element definitions, while leaving the ElementDefinition.base datatype cardinality at 0..1.

Additional context:
ElementDefinition is an active normative infrastructure datatype and StructureDefinition is an active conformance resource in source/fhir.ini. Current source keeps ElementDefinition.base at 0..1 because ElementDefinition is also used in StructureDefinition.differential.element, where base is not required. The active StructureDefinition source instead carries the contextual rule: StructureDefinition.snapshot has sdf-8b, "All snapshot elements must have a base definition", with expression element.all(base.exists()), and StructureDefinition.snapshot.element lists sdf-8b as a condition. FHIR-9641 and FHIR-15929 are the same rule family: FHIR-9641 clarified base population for inherited snapshot elements, and FHIR-15929 split/enforced the snapshot base-definition invariant; FHIR-15929 is already represented on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already reflects the approved behavior: the old sentence is gone, the comment says snapshots must always populate base, and the StructureDefinition snapshot invariant enforces base.exists() for all snapshot elements. Changing ElementDefinition.base itself from 0..1 to 1..1 would be broader than the applied decision and would incorrectly make base mandatory in differential element definitions too.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed unless FHIR-I makes a new decision to require base in all ElementDefinition uses, including differentials; that would be a separate substantive change rather than completion of FHIR-12295.
