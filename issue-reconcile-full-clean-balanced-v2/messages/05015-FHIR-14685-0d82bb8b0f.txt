FHIR-14685: Audit ConceptMap value-set context wording

Issue request:
FHIR-14685 was a Published/Not Persuasive with Modification Vocabulary issue for STU3 ConceptMap. It questioned why ConceptMap mappings are described as value-set-specific and proposed saying that mappings are defined only in the context of source and destination code systems. The final resolution kept the value-set/context model, added a business-usage explanation, and clarified that the business use case is normally defined by the source and target value sets.

Initial application:
The issue was pre-applied in SVN revision 13358, now git commit fed48b46b1cb32a986d70fd4c69d9b569a0aab61, which changed the ConceptMap introduction from the older source/destination value-set wording to source/target value-set context wording and added the SNOMED CT to ICD-10 data-analysis-versus-billing example. Jira then recorded that the second sentence-level replacement still needed application; git commit 6d764b49297ea32917d13c2b9cc7bdb413a6d413, GF#14685 - edit sentence, applied the final business-usage wording now present in the current source.

Additional context:
ConceptMap is an active resource in source/fhir.ini, so source/conceptmap is in current build scope. Later ConceptMap redesigns renamed source and target to sourceScope and targetScope and moved the source from spreadsheet-generated STU3-era definitions to the current StructureDefinition XML, but the current source still says the sourceScope value set contains the mapped concepts and provides context, and the targetScope value set provides important context about mapping choices. Confluence block-vote material records FHIR-14685 as Not Persuasive with Modification and partially pre-applied for the 2018-04-19 Vocabulary vote. Direct Zulip and Confluence searches found no community discussion that contradicts the Jira/source trail.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current ConceptMap introduction already contains the approved final wording and example, including business usage, source/target value-set context, and all-codes value sets for maps valid across all appropriate use contexts. The current active StructureDefinition definitions also preserve the context role of sourceScope and targetScope value sets, so adding new prose would be redundant and could create maintenance drift.

Recommendation:
Keep this no-change audit commit as-is. No current FHIR core follow-up is needed for FHIR-14685; future changes to whether ConceptMap context should be value-set, business-usage, or code-system based should be handled by a new terminology work-group decision.
