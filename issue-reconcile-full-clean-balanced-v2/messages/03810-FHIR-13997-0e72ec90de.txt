FHIR-13997: Audit AllergyIntolerance verification status unknown handling

Issue request:
FHIR-13997 was a Published STU3 Patient Care issue, resolved Persuasive with Modification, asking that AllergyIntolerance.verificationStatus either include an unknown value or provide default guidance because the STU3 element was mandatory and some systems did not track whether an allergy was confirmed, unconfirmed, or refuted. The accepted resolution was to make AllergyIntolerance.verificationStatus optional (0..1) rather than add unknown.

Initial application:
The issue appears to have been applied in git commit 52ac1cc0e7, whose commit message explicitly includes #13997 and whose patch changed the then-authoritative AllergyIntolerance spreadsheet cardinality for AllergyIntolerance.verificationStatus from 1..1 to 0..1. Later source refactors regenerated/migrated that spreadsheet content into the current StructureDefinition XML and terminology sources.

Additional context:
AllergyIntolerance is active in source/fhir.ini, so source/allergyintolerance/structuredefinition-AllergyIntolerance.xml is in current build scope. The current source keeps AllergyIntolerance.verificationStatus at min 0/max 1, binds it to the required AllergyIntolerance verification value set, and its current short/search-parameter code lists do not include unknown. The 2017 Zulip thread linked from the Jira explains the original interoperability problem and records that GF#13997 would relax the cardinality; it also discussed data-absent-reason as an interim STU3 workaround. A later R6 core issue, FHIR-47613, asked again to add unknown and Patient Care resolved it Not Persuasive/Resolved - No Change after a failed motion to add unknown, distinguishing optional absence from explicit unknown.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source already reflects the FHIR-13997 resolution, and later Patient Care evidence argues against adding unknown now.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-13997 unless Patient Care opens and approves a new change request with concrete use cases that reverse the 2025 no-change decision.
