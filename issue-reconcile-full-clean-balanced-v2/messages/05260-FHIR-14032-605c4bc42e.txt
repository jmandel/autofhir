FHIR-14032: Audit ICD-10 variant URL handling

Issue request:
FHIR-14032 was a Published/Persuasive STU3 Vocabulary change request reporting that the ICD-10 variant URLs listed on the old ICD page, especially http://hl7.org/fhir/sid/icd-10-de and http://hl7.org/fhir/sid/icd-10-cm, did not resolve. The resolution was to fix the missing/incorrect declaration so the listed system URIs resolved correctly.

Initial application:
The issue was applied in git commit 998dc1674be6, the svn revision 12765 cited in the Jira comment. That commit changed source/namingsystem/namingsystem-terminologies.xml from the old US variant id/URI tx-icd-10-us and http://hl7.org/fhir/sid/icd-10-us to tx-icd-10-cm and http://hl7.org/fhir/sid/icd-10-cm. No current publish.ini SID alias was part of that historical application.

Additional context:
Later Vocabulary/TSMG work moved externally defined code system usage pages and metadata out of FHIR core and into HL7 Terminology: FHIR-35933 removed the core Using External Code System pages, UP-289 implemented the THO side, and FHIR-37889 removed the remaining source/namingsystem/namingsystem-terminologies.xml bundle from the current build. The active current core Code Systems page is in source/hierarchy.xml, points implementers to THO for authoritative external terminology identifiers, and now lists only the generic ICD-9/ICD-10 row rather than the old de/nl/cm variant table. The THO package now carries current external NamingSystem records such as ICD-10-CM and the Dutch ICD-10 translation.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core source no longer contains the obsolete broken ICD-10 variant list or the NamingSystem bundle that FHIR-14032 originally corrected, and reintroducing the old variant rows in FHIR core would duplicate or conflict with the THO-governed external terminology records.

Recommendation:
Keep this empty audit commit as-is. If maintainers still want direct HTTP redirect behavior for old http://hl7.org/fhir/sid/icd-10-* URLs, handle that through THO/web infrastructure or terminology governance rather than by restoring retired FHIR-core NamingSystem content.
