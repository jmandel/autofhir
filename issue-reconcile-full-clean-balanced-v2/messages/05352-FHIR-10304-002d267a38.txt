FHIR-10304: Audit OrganizationAffiliation implementation

Issue request:
FHIR-10304 was a Published/Persuasive with Modification PA change request asking to add Organization.affiliation for Organization relationships, similar to PractitionerRole, with relationship type, period, and an organization/manager reference. The final resolution did not require a nested Organization element; it said the new OrganizationAssociation resource had been approved and was more extensive than the original request, with Argonaut directed to review that resource for usage.

Initial application:
The application appears in git commit 0b2790895e9de4db72ee18820200e9be7fee6c66, whose subject explicitly cites GF#10304 with GF#14413 and GF#14879. That commit replaced the draft OrganizationRole resource with OrganizationAffiliation in source/fhir.ini, added the OrganizationAffiliation source directory, examples, terminology, introduction, and spreadsheet inputs, and moved organizationrole to the removed-resource list.

Additional context:
The current build uses OrganizationAffiliation rather than the Jira resolution's older OrganizationAssociation wording. Current fhir.ini lists organizationaffiliation as an active PA resource with normative status and lists organizationrole only under removed resources. The active Organization and OrganizationAffiliation narrative and StructureDefinition now describe a separate resource for non-hierarchical relationships between distinct organizations, including period, organization, participatingOrganization, code, location/service, contact, and endpoint details. The Jira-linked Zulip thread supports the same use case and records discussion of using a separate resource rather than expanding Organization.partOf. Related same-commit issues FHIR-14413 and FHIR-14879 are already represented on the combined branch, and later FHIR-25406 preserved the current OrganizationAffiliation framing while refining its organization/participatingOrganization definitions.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Adding Organization.affiliation now would contradict the applied PA resolution and duplicate the active OrganizationAffiliation resource; the current source already satisfies the seed issue through the approved separate resource.

Recommendation:
Keep this audit commit as-is. No FHIR-core follow-up is needed for FHIR-10304 unless PA opens a new issue to replace OrganizationAffiliation with a nested Organization element or to rename the resource again.
