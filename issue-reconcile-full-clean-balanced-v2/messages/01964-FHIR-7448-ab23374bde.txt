FHIR-7448: Audit lifecycle table generation

Issue request:
FHIR-7448 was a Published FHIR-core/MnM DSTU1 change request with a Persuasive with Modification resolution. It objected that many rows on the lifecycle/status table said "Unknown - not stated by committee" and asked to improve table generation, add a hint to the generation process, and make the issue part of QA criteria.

Initial application:
The issue was applied by svn revision 5535, preserved as git commit da3856859e16179bd5c47577e86dd68e2dda2bcf, which added ResourceValidator logic to infer common entered-in-error mechanisms from status, retired, or active=false and emit a hint when no entered-in-error status was known. The same commit also improved generated table rows by linking resource names. The Jira comments also cite svn revision 5935, preserved as git commit 5afc2790463eed7e4191e9ce13d5369b29b89537, which added the lifecycle page note that resources omitted from the generated table have no explicit entered-in-error documentation.

Additional context:
The current source/lifecycle.html page is still an active FHIR source page and now describes resource status lifecycle categories with generated status-code lists and an entered-in-error summary placeholder. Later Published issue FHIR-32152 broadened lifecycle visibility by adding Appointment.status to the current lifecycle examples. The current CI-rendered lifecycle page expands the source placeholders into explicit code lists and a resource/status table, while the obsolete "Unknown - not stated by committee" text is absent from current source and rendered output.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The requested automated generation and QA/hint treatment were applied historically, the current build source keeps the generated lifecycle summary mechanism, and adding redundant prose would not correct a current implementer-facing defect.

Recommendation:
Keep this audit commit as-is. Future lifecycle work should be handled as resource-specific tracker items when a work group wants to change a particular status value set or entered-in-error mechanism; FHIR-7448 itself does not require a current core source edit.
