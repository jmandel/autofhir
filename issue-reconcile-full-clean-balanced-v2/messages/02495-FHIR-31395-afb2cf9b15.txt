Initial application:
The issue was applied before this reconciliation. Jira comments point to HL7/fhir pull request 2068, and git commit 93fadfaa2a89cdc46a2a2633431ebbc34f06fe74 explicitly records "J#31395" while updating source/valueset/implementationguide-ValueSet-core.xml, modifying ShareableValueSet, and adding the Publishable, Computable, and Executable ValueSet StructureDefinitions.

Additional context:
Later decisions changed the current build scope. FHIR-38833 first added R5 profile-introduction notes saying the shareable/publishable/computable/executable profiles would migrate to CRMI. FHIR-37959 then made the R6 Applied/Persuasive decision to remove the terminology-resource profile family from core and maintain it in CRMI with unchanged profile URIs. Commit 3958dd1e7c2fd73ad1e94c66f8d0884df55695d5 removed the ValueSet profile StructureDefinitions and ValueSet implementation-guide references. FHIR-47807, which asked to keep the existing R6 ValueSet profiles in core, was retracted/Resolved - No Change.

AutoFHIR reconciliation:
This is an empty audit commit. No core source change is needed: ValueSet itself remains an active resource in source/fhir.ini, but current source has no active ValueSet-profile StructureDefinition files or implementation-guide references for shareablevalueset, publishablevalueset, computablevalueset, or executablevalueset. Recommendation:
Keep this audit commit as-is. Do not re-add the ValueSet profiles to current FHIR core for FHIR-31395; future fixes to these profile definitions or CRMI-specific explanatory text should be made in the CRMI source that now owns them.
