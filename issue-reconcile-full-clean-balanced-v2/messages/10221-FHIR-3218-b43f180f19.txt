FHIR-3218: Audit datatype tab structure

Issue request:
FHIR-3218 was a Published/Persuasive FHIR-core change request for DSTU1 asking that datatypes use the same multi-tab style as resource pages, with separate tabs for the main datatype page, examples, definitions, mappings, profiles, and similar pages instead of scattered links.

Initial application:
The Jira comments say Grahame applied the change in SVN revisions 3016 and 3017. Those map to git commits 0652011d547371a2206472b5de0d245996ed232a and cef4f70fb1262eb6c9fc645cab346eb23f1e4231, both titled "Task 3218: standardise tab use in core documentation"; they changed core documentation pages and the publisher tab/header machinery rather than leaving an unapplied source request.

Additional context:
Current source still carries datatype-specific page tabs: source/hierarchy.xml nests Datatypes with Examples, Detailed Descriptions, Mappings, Profiles, and MetaData Types child pages; publish.ini actively includes the datatype tab pages; and each datatype tab source invokes the dtheader macro for its selected tab. A later source reorganization, 22b5c2457301de9acd614a6d899679b609536031, kept and expanded the datatype tab family for IG packaging, including datatypes-profiles.html and metadata-type counterparts. The current CI build renders those entries as a nav-tabs list on datatypes.html and datatypes-examples.html. Zulip and Confluence searches found no later discussion or work-group record contradicting the Jira/source outcome.

AutoFHIR reconciliation:
This commit intentionally makes no source changes. The current build-scoped FHIR source already implements the requested multi-tab datatype presentation, including examples, detailed descriptions, mappings, profiles, and extension-related links, so adding or changing source now would be redundant.

Recommendation:
Keep this no-change audit commit as-is. No follow-up is needed for FHIR-3218 unless the work group opens a new issue to redesign the current datatype page navigation.
