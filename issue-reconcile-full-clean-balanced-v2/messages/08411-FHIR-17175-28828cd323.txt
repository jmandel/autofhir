FHIR-17175: Audit security-service status

Issue request:
FHIR-17175 was a Published/Persuasive STU3 FHIR-I request to mark the CapabilityStatement `security-service` search parameter as trial-use because `CapabilityStatement.rest.security` was then a trial-use backbone. The Jira resolution agreed, while noting that tooling did not yet have a robust way to mark search parameters as trial-use.

Initial application:
There is no FHIR-17175-tagged Git commit in the post-SVN history, but the Jira comment records SVN revision 14528. The imported Git source for CapabilityStatement subsequently carried the requested state: `CapabilityStatement.rest.security` had a trial-use standards-status extension, and `CapabilityStatement-security-service` in the active CapabilityStatement search-parameter bundle also had `structuredefinition-standards-status` set to `trial-use`.

Additional context:
The source files are in current build scope because `source/fhir.ini` lists `capabilitystatement=CapabilityStatement` as an active resource. Later Published issue FHIR-25744 clarified search-parameter status semantics, saying a SearchParameter definition can be normative while a non-normative resource or target remains non-normative; its implementation commit changed `CapabilityStatement-security-service` from trial-use to normative. Current source also no longer marks `CapabilityStatement.rest.security` itself as trial-use, and recent community discussion describes CapabilityStatement as normative since R4 while treating `rest.security.service` as an existing discovery element rather than a trial-use exception.

AutoFHIR reconciliation:
This empty audit commit makes no source change. Re-marking `CapabilityStatement-security-service` as trial-use would undo the later search-parameter status policy and would conflict with the current CapabilityStatement source, where the underlying `rest.security` backbone is not marked trial-use.

Recommendation:
Keep this audit commit as-is. No follow-up core source change is recommended for FHIR-17175 unless FHIR-I reopens the current standards status of `CapabilityStatement.rest.security` or the search-parameter status policy.
