FHIR-3856: Audit operation extension guidance

Issue request:
FHIR-3856 was a Published/Persuasive with Modification DSTU1 FHIR-I change request asking the operations documentation to explain how an implementation can extend an existing operation for local use, including avoiding future collision with HL7-defined parameter names.

Initial application:
The issue was applied in the historical SVN-era source: git commit 918490af7f19e4d0c1bdacbc7a74df5e7850c531 records svn r4064 and added the reservation that FHIR will not define operation parameter names beginning with "x-". The operations page already contained, and later QA preserved, the guidance that implementations may define new named parameters and publish an extended OperationDefinition using OperationDefinition.base to point to the underlying definition.

Additional context:
The current operations page is part of the built specification through source/hierarchy.xml, and OperationDefinition is an active resource in source/fhir.ini. Later applied/published work in the same area, including FHIR-30509 and FHIR-38034, strengthened the OperationDefinition page by making clear that derived OperationDefinitions can introduce new parameters and by linking the operations page to that derived-definition guidance. FHIR-28222 separately addressed operation code naming and collision guidance. Those related issues already have issue-reconcile commits on the combined branch and should not be duplicated here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already tells implementers to extend operations by defining additional named parameters, publishing an extended OperationDefinition, and using OperationDefinition.base, with the current OperationDefinition page providing the detailed derivation rules and collision-handling context. Adding more local prose for FHIR-3856 would duplicate later, more complete guidance and would not materially change implementer understanding.

Recommendation:
Keep this audit commit as-is. Revisit only if the work group wants a fresh normative decision about reserving additional local parameter prefixes beyond the existing "x-" note; that would be a new issue rather than an unapplied part of FHIR-3856.
