FHIR-3408: Audit Patient contact relationship binding

Issue request:
FHIR-3408 is Published/Persuasive and asked PA to replace the self-defined Patient.contact.relationship value set with the HL7 v2 table 0131 value set and to represent mother-child relationships from the context of RelatedPerson.

Initial application:
The application is historical. Git commit fb14d2fad17858e1b603cb0032db8a62b3563517 changed the old Patient spreadsheet binding reference from valueset-patient-contact-relationship to http://hl7.org/fhir/ValueSet/v2-0131 and added Patient narrative guidance for mother/newborn relationships using Patient/RelatedPerson; no current commit subject used the Jira key format, but the SVN-era subject names tracker 3408.

Additional context:
Patient is an active resource in source/fhir.ini, so source/patient/structuredefinition-Patient.xml and the Patient narrative are in current build scope. FHIR-17472 later replaced the direct table-131 binding with the FHIR patient-contactrelationship value set that excludes the v2 "other" code. FHIR-15841 is Applied for R6 and intentionally supersedes the old model: Patient.contact.relationship is now a preferred binding to v3-PersonalRelationshipRoleType for personal relationships, a new Patient.contact.role carries functional roles with relatedperson-relationshiptype, and patient-contactrelationship is deprecated/retired. Current Patient notes still direct mother/newborn administrative relationships to Patient/RelatedPerson.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Rebinding Patient.contact.relationship back to v2 table 0131 would undo FHIR-15841 and make the current R6 model less accurate. The authoritative XML and narrative source already preserve the parts of FHIR-3408 still applicable after later decisions.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed for FHIR-3408 unless the work group reopens the R6 personal-versus-functional split or chooses to regenerate stale diagram artifacts separately from this issue.
