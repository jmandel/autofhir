FHIR-18003: Audit PaymentReconciliation short descriptions

Issue request:
FHIR-18003 is Published/Persuasive with Modification for STU3. It asked FM to update short descriptions for PaymentReconciliation.organization, request, requestProvider, detail.request, detail.response, detail.submitted, detail.payee, and detail.date; the recorded resolution says additional changes were presented and approved.

Initial application:
The issue was included in the 2018 batched PaymentReconciliation application commit f369c813fb40cd39c0db46336b2b3186f496fb47, which updated the then-authoritative paymentreconciliation-spreadsheet.xml. That commit also applied neighboring PaymentReconciliation rename and element issues, so the applied short text did not literally match every proposed phrase: for example organization became paymentIssuer with "Party generating payment", request became "Reference to requesting resource", requestProvider became requestor, and detail fields were later carried forward from the spreadsheet into StructureDefinition source.

Additional context:
PaymentReconciliation is active in source/fhir.ini. Current fhir.ini redirects map the old STU3 element names to current paths: organization to paymentIssuer, requestProvider to requestor, and detail.* to allocation.*. Later FHIR-26601 renamed detail to allocation and replaced detail.request with allocation.target for expanded patient-payment scope; later FHIR-22689 clarified requestor as the party/provider responsible for the request with Billing Provider/accountability wording. These final later decisions supersede a literal restoration of the old short-description proposals.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope StructureDefinition already gives implementers the same or more current semantics for the affected concepts: paymentIssuer is the party generating payment, request is the original requesting resource, requestor is the party responsible for the request, allocation.target is the subject payable, allocation.response is the payment-commitment response, allocation.submitter/payee identify the submitting and receiving parties, and allocation.date/payment date definitions identify the relevant financial-instrument or commitment date.

Recommendation:
Keep this audit commit as-is. Do not reword current R6 PaymentReconciliation back to the STU3 phrases from FHIR-18003; any further description changes should be raised as a new FM issue against the current paymentIssuer/requestor/allocation model.
