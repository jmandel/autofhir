FHIR-48421: Audit Basic search-parameter naming guidance

Issue request:
FHIR-48421 was an Applied/Persuasive FHIR-I change request for R6 asking Basic to define a pattern for custom search parameters so names used by profiled Basic concepts are clearly distinct and less likely to collide.

Initial application:
The issue was applied before this reconciliation by commit 31ec17fc71, which added a "Search Parameters against Basic" subsection to source/basic/basic-notes.xml as part of the merged HL7/fhir#3967 R6 ticket bundle. The current combined branch already contains that commit and text.

Additional context:
FHIR-I minutes from 2024-11-18 record the approval to add Basic notes guidance that search parameters should have a prefix representing the resource concept to help avoid name collisions. The current source uses lower-hyphenated example codes rather than the exact camel-case examples in the Jira resolution, but it preserves the approved semantics and adds a non-normative note that non-prefixed codes remain possible.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Basic is an active resource in source/fhir.ini, and source/basic/basic-notes.xml already gives the required guidance: custom SearchParameters can be defined against Basic profiles, collision risk is higher, best practice is to prefix codes with the conceptual resource name, and examples show prefixed Basic search parameter codes.

Recommendation:
Keep this audit commit as-is. No further core FHIR source work is recommended for FHIR-48421 unless the work group later wants a different naming style for the examples.
