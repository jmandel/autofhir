FHIR-13843: Audit Patient genderIdentity extension

Issue request:
FHIR-13843 was a Published/Persuasive STU3 Patient issue from PA. It requested adding genderIdentity to Patient, resolved as a standard Patient extension with CodeableConcept 0..1, definition "The gender the patient identifies with. The Patient's gender identity is used as guidance (e.g. for staff) about how to interact with the patient", and only an example binding.

Initial application:
The change was initially applied in commit 077d81592c, explicitly titled "GF#13843: add gender-identity extension". That commit added Patient gender identity terminology and updated the Patient extension spreadsheet for the then-current build. No current combined-branch commit already carries Issue-Reconcile-Key: FHIR-13843.

Additional context:
Later Patient Administration and Gender Harmony work intentionally changed the shape of the feature. FHIR-29673 generalized the Patient-specific genderIdentity extension into individual-genderIdentity for Patient and other person resources, adding period/comment slices. FHIR-39202 removed the old "openly known" note from the Patient Gender and Sex text. FHIR-38639 removed the old FHIR gender-identity example code system after the value set moved to THO/SNOMED content. FHIR-46412 later records that genderIdentity search support belongs in the Extensions IG. The old patient-genderIdentity definition is now a deprecated/retired Extension Pack artifact, while the active individual-genderIdentity extension is maintained in the FHIR Extension Pack.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Patient is an active build-scoped resource, and current core source already has a Patient Gender and Sex section that defines Gender Identity, links to the standard individual-genderIdentity extension, and also points to pronouns. The Patient sex-and-gender example uses individual-genderIdentity and is registered in the Patient examples list. Restoring the older patient-genderIdentity source or FHIR-local gender-identity code system in core would conflict with the later Extension Pack, Gender Harmony, and THO migration decisions.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for FHIR-13843 unless PA/Gender Harmony makes a new decision to change the canonical extension model or move the Extension Pack content back into core.
