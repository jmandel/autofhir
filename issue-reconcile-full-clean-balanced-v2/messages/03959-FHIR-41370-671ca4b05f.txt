FHIR-41370: Audit ISO 8601 datatype wording

Issue request:
FHIR-41370 is an Applied/Persuasive FHIR-core change request asking the datatype page to state that date, dateTime, and time follow ISO 8601 because the regexes did not otherwise identify the calendar/format basis.

Initial application:
The Jira comment linked HL7/fhir#2950. That PR added ISO8601 subset wording to source/datatypes.html in commit 68e29442 and then made the references hyperlinks in commit c756d616 after review; the PR was merged as 3bb70ca on 2023-09-19. Later source edits changed nearby UTC-offset wording and instant precision language, but preserved the ISO8601 subset references.

Additional context:
source/fhir.ini routes primitive datatype pages through the active datatypes page, and source/datatypes.html is the Related Pages target from Jira. The nearby primitive spreadsheet source still carries shorter schema/regex descriptions for generated type definitions, but those descriptions do not contradict the active datatype-table rule. Confluence minutes from 2023-06-26 record FHIR-41370 as Persuasive with a 16-0-0 vote, and searches found no later community record reversing the ISO8601 wording.

AutoFHIR reconciliation:
This audit intentionally makes no source change. The current datatype table already says date, dateTime, instant, and time formats are subsets of linked ISO8601 text, which satisfies the issue without duplicating the same clarification into generated-description inputs.

Recommendation:
Keep this no-change audit commit. Revisit only if the work group wants the ISO8601 reference duplicated in generated primitive StructureDefinition descriptions or package artifacts; the current build-facing datatype page already conveys the approved rule.
