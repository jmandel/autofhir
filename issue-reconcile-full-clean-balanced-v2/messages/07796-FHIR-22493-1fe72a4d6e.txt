FHIR-22493: Audit Element.id type profile propagation

Issue request:
FHIR-22493 was a Published/Persuasive FHIR-I change request raised against STU3/R4 type profiles and applied for R5. It reported that StructureDefinitions derived from Element, such as primitive datatype profiles, did not repeat the base Element.id primitive/system type metadata in their snapshots and instead exposed a regular FHIR type such as string. The accepted resolution was that the extension/type metadata from the base Element profile should be repeated in derived snapshots.

Initial application:
No current FHIR source commit directly referencing FHIR-22493 was found. The checked-in R4 history bundle still illustrates the original defect: tools/history/release4/profiles-types.xml has Element.id represented with the special json/xml/rdf type extensions, while string.id has a plain code value of string. Later generation changed the representation to FHIRPath System.String plus structuredefinition-fhir-type, and the same Element.id propagation family was handled by follow-up tooling issues/audits such as FHIR-36036, FHIR-38684, and FHIR-41183.

Additional context:
The current build-scope source defines Element.@id as type string in source/datatypes/element.xml, and source/fhir.ini keeps Element, BackboneElement, and ElementDefinition active in the datatype/infrastructure build. BackboneElement derives from Element without declaring a separate @id row, and current ElementDefinition notes document the FHIRPath System.String plus structuredefinition-fhir-type pattern. Current build output now emits Element.id, string.id, Address.id, BackboneElement.id, and ElementDefinition.id with code http://hl7.org/fhirpath/System.String and structuredefinition-fhir-type valueUrl string. Related final decisions keep Resource.id separate: FHIR-25262/FHIR-25274 establish Resource.id as System.String constrained by fhir-type id, and FHIR-45989 later confirms Element.id is fhir-type string while Resource.id remains fhir-type id.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative source and generated build output already satisfy FHIR-22493's requirement for Element-derived type profiles, and editing checked-in historical release cache files would not be a current-spec source fix.

Recommendation:
Keep this no-change audit as the FHIR-22493 reconciliation. Do not broaden it into Resource.id changes or historical R4/R5 cache rewrites; any future publication-surface correction for old releases should be handled through the publication/generator process and related issues already audited on the combined branch.
