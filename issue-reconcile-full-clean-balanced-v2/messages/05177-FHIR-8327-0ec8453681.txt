FHIR-8327: Confirm Procedure.status modifier

Issue request:
FHIR-8327 is a Published/Persuasive FHIR-core Procedure change request from the DSTU1 QICore ballot. It asked for base Procedure.status to be listed as an isModifier element because status values such as aborted and entered-in-error can negate the procedure event.

Initial application:
The Jira comments record that Mark Kramer planned to mark Procedure.status as modifying on 2015-07-27 and that Lloyd McKenzie replied on 2015-08-27 that it was already applied. Source history supports that: commit 140947a909 introduced Procedure.status with the old spreadsheet Is Modifier column set to Y, and the explicit issue-tagged commit d51bbbe626 (#8261, #8327, #8408) preserved Procedure.status with Is Modifier = Y before the later source-format migration.

Additional context:
Procedure is an active resource in source/fhir.ini, so source/procedure/structuredefinition-Procedure.xml is in the current build scope. Later status-code wording has changed from the DSTU1 "aborted" phrasing to current event-status codes such as not-done, stopped, completed, entered-in-error, and unknown, but the current element still carries isModifier=true and an isModifierReason. Jira, Zulip, and Confluence searches did not find a later decision reversing or narrowing the modifier requirement.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active Procedure StructureDefinition already marks Procedure.status as a modifier, and adding another edit would not change implementer understanding of the current specification.

Recommendation:
Keep this no-change audit commit as-is. No follow-up is needed for FHIR-8327 unless a work group separately wants to revisit the generic modifier reason wording for Procedure.status.
