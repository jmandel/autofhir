FHIR-13195: Audit Appointment basedOn rename

Issue request:
FHIR-13195 was a Published PA change request, resolved Persuasive with Modification for STU3. It asked to add a reference from Appointment to a prior order/procedure request, either as a new ProcedureRequest reference or by generalizing Appointment.incomingReferral.

Initial application:
The change was applied in source history by commit 62c1d1a5a69cd36ef1eb086ba089c27d865d8a02, "GF#13195 (applied with mod): rename Appointment.incomingReferral to Appointment.basedOn". Follow-up commit b60b1f71994c66dccd2ef3964fd52a956acaa535 updated examples and definitions for the Encounter/Appointment incomingReferral-to-basedOn rename.

Additional context:
The issue comments and linked PA Zulip discussion explain why the original ProcedureRequest wording became basedOn(ServiceRequest): ReferralRequest and ProcedureRequest had already merged into ServiceRequest. Appointment is active in the current build, and current Appointment.basedOn retains the incomingReferral alias, includes the procedure-request example, and targets ServiceRequest plus later-added request resources. FHIR-25278 later expanded this same element and is already represented on the combined branch.

AutoFHIR reconciliation:
No source change was made. The current active Appointment StructureDefinition already implements the approved rename/generalization, and reintroducing ProcedureRequest or incomingReferral as current element names would be stale.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-13195; future changes to request-like Appointment targets should continue to be handled on Appointment.basedOn.
