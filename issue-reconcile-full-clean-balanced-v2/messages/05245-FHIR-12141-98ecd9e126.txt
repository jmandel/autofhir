FHIR-12141: Audit attorney role value-set request

Issue request:
FHIR-12141 was a Published/Persuasive with Modification PA change request from the DSTU2 cycle asking for an Attorney code usable in RelatedPerson.relationship, Patient.contact.relationship, and CareTeam.participant.role. The accepted resolution did not add another code to the large RelatedPerson relationship value set; it directed that the binding be relaxed from extensible, and from required in DSTU2, to preferred so local and jurisdictional value sets can be used.

Initial application:
No git commit explicitly mentioning FHIR-12141 was found in the current repository history. In the current active build source, however, the requested conformance effect is present: Patient.contact.relationship and RelatedPerson.relationship are preferred bindings, Patient.contact.role and RelatedPerson.role are preferred functional-role bindings, and CareTeam.participant.role is only an example binding.

Additional context:
The linked #implementers Zulip RelatedPerson thread records the reporter's attorney and power-of-attorney use case, including advice that local RoleCode/SNOMED codes were already possible and that PA should clarify the model. FHIR-10524 has the same vote and resolution text for adding RoleCode affiliation values such as power of attorney; it is audited separately in the next commit. FHIR-15841 later split personal relationship from functional role for Patient.contact and RelatedPerson, and FHIR-31670 later added POWATT, DPOWATT, HPOWATT, and SPOWATT to relatedperson-relationshiptype; both related issues already have reconciliation commits on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already implements the accepted non-restrictive approach, and adding a core Attorney code now would go beyond the final FHIR-12141 decision. The active resources are in source/fhir.ini, and their binding strengths allow implementers to use local attorney-related codings where needed.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-12141 unless PA reopens the terminology question and explicitly approves a new standard Attorney code.
