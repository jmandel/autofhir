FHIR-13806: Audit Consent notOrg example

Issue request:
FHIR-13806 was Published/Persuasive for the FHIR-core Consent resource. It reported that consent-example-notOrg is an opt-in consent that excludes a named organization and therefore the provision needed type=deny in the STU3 Consent model.

Initial application:
The request was applied in commit ce4c96b9c3, which explicitly said it corrected CR #13806 and added the deny provision to source/consent/consent-example-notOrg.xml. Later Consent example/model refactors retained the same scenario while adapting the representation to newer Consent structures.

Additional context:
Consent is an active current-build resource in source/fhir.ini, and source/consent/list-Consent-examples.xml includes consent-example-notOrg. Later Published Consent decisions changed the model: FHIR-32817 split policy context from computable policy structure, and FHIR-39597 moved provision.type to Consent.decision while making provisions and subprovisions inferred reverse decisions of the previous level. The current source therefore should not reintroduce the removed STU3 provision.type element.

AutoFHIR reconciliation:
No source change was made. The current example sets Consent.decision to permit, then has a provision scoped to Organization/f001 with access/correct actions and a no-read/no-write comment; under the current Consent definition and FHIR-39597 resolution, that provision is the denial exception to the opt-in permit base decision. Organization/f001 is the Burgers University Medical Center named in the narrative.

Recommendation:
Keep this no-change audit commit. Revisit only if CBCC later changes the current Consent provision inference semantics or wants an additional explicit narrative note, not as part of FHIR-13806.
