FHIR-6121: Audit HTTP _format header clarification

Issue request:
FHIR-6121 was Published/Persuasive with Modification for the FHIR-core HTTP page. The original request asked to clarify Content-Type, _format, Accept, and Accept-Charset; the final resolution specifically required that _format only override Accept and not Content-Type.

Initial application:
The issue was applied in Subversion revision 5961, imported as git commit 49a0a0f517e8 ("#6121 - clarify the use of _format header"). That commit changed source/http.html to say _format overrides the accept header and added a note that _format does not override the content-type header.

Additional context:
The current build includes source/http.html via source/hierarchy.xml. Later HTTP-page decisions refined adjacent MIME negotiation wording: FHIR-8978 added the undefined response MIME-type case when neither Accept nor _format is supplied, FHIR-9029 reorganized generic Accept/_format behavior while preserving the Content-Type limitation, and FHIR-16343 removed stale Accept-Charset/default-charset text in favor of the current UTF-8 guidance.

AutoFHIR reconciliation:
No source change was made. Current source/http.html states that _format specifies alternative response formats and overrides the accept header value, and its implementation notes state that _format does not override the Content-Type header for the body type of a POST request. The remaining encoding guidance says UTF-8 SHALL be used, so reintroducing Accept-Charset language would conflict with later published clarification.

Recommendation:
Keep this no-change audit commit. Future changes to charset negotiation or generic MIME response handling should be handled through the later issue family rather than reopening FHIR-6121.
