FHIR-29315: Audit Subscription maxCount application

Issue request:
FHIR-29315 was a Published/Persuasive with Modification FHIR-I change request for the FHIR-core Subscription resource. It asked for a predictable upper bound on large subscription notification bundles by adding Subscription.maxCount 0..1 positiveInteger, with _count-like semantics that servers do not include more than the requested count while allowing fewer, and with the limit applying to triggering notification resources rather than additional supporting bundle entries.

Initial application:
The issue was applied in git commit dbeb5e6a7aa3cba0705a1c337c0eaf6174d32eb2, "FHIR#29315", which added maxCount to the Subscription spreadsheet source and to a Subscription example. The later source rework commit 33b409a4b6d544598262f2f074ebb4b6dc466157 carried that element into source/subscription/structuredefinition-Subscription.xml as Subscription.maxCount 0..1 positiveInt.

Additional context:
source/fhir.ini actively lists subscription=Subscription, so the inspected Subscription resource source is in current build scope. The origin Zulip discussion confirms the problem was large batches of subscription notifications, that notification bundles were not paginated, and that batching remains a server decision while clients needed a way to state an upper bound. FHIR-I minutes record the 12-0-0 Persuasive with Modification vote. Later FHIR-39467 changed the original "triggering resources" wording to "events", and later FHIR-50622 added Batching Results narrative text that describes maxCount with the same event/count semantics.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current source/subscription/structuredefinition-Subscription.xml defines Subscription.maxCount as 0..1 positiveInt with the event-count definition and dependent-resource exception, and current source/subscription/subscription-notes.xml explains that servers SHALL NOT include more than the specified number of events while dependent resources may add additional bundle entries.

Recommendation:
Keep this no-change audit commit as-is. The current core source already satisfies FHIR-29315 after later accepted terminology clarifications; do not reintroduce the older "triggering resources" wording. FHIR-50622 remains a separate later applied narrative issue if independent audit tracking is needed.
