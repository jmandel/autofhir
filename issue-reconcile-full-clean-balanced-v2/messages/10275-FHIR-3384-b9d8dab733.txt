FHIR-3384: Audit messaging authoring transition

Issue request:
FHIR-3384 was a Published FHIR-core StructureDefinition change request with a Persuasive with Modification resolution. It reported that the resource authoring spreadsheet could describe multiple request and response resources for messaging events but could not capture the profiles and other metadata required by Conformance.messaging.event. The final decision was to change tooling so populated spreadsheet messaging content raised an error and directed work groups to use MessageDefinition instead.

Initial application:
The Jira comments record that parsing of messaging events was disabled in SVN#13045. In git history, 6e29947a8ab67049eb42873d59a9df6ffc92eb42 ("Disable parsing of messaging events") is that svn revision and comments out readEvents(loadSheet("Events")) in tools/java/org.hl7.fhir.tools.core/src/org/hl7/fhir/definitions/parsers/SpreadsheetParser.java. Earlier history also shows the migration path: 759ccddbac853e6544b1ae26ba96cce426cb405f added CapabilityStatement.messaging.supportedMessage as a MessageDefinition-based alternative, and 343a847a76165dbd02b4d14edafadb853278b122 removed old messaging todos as addressed by MessageDefinition.

Additional context:
The current repository no longer has the old tools/java SpreadsheetParser path, so there is no current core parser to update for the historical Events sheet behavior. The active current-build source in source/fhir.ini includes CapabilityStatement, MessageHeader, and MessageDefinition. Current CapabilityStatement.messaging exposes supportedMessage only, and source/capabilitystatement/capabilitystatement-notes.xml directs messaging capability declarations through supportedMessage/MessageDefinition. Current MessageDefinition carries the event, focus profile, and allowed response structure that replaces the historical spreadsheet event columns. FHIR-10121 later removed remaining stale CapabilityStatement.messaging.event references and is already represented on the combined branch.

AutoFHIR reconciliation:
This commit makes no source change. The current core source and active build inputs already reflect the FHIR-3384 outcome: old spreadsheet-authored messaging event metadata is not an active current-spec mechanism, and implementers are directed to the MessageDefinition-based model.

Recommendation:
Keep this no-change audit commit as-is. No current FHIR core source edit is needed for FHIR-3384; if legacy spreadsheet parser tooling is revived in another repository, it should preserve the FHIR-3384 behavior of rejecting populated messaging Events-sheet content and directing authors to MessageDefinition.
