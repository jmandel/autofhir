FHIR-13550: Audit earlier CapabilityStatement implementation rule

Issue request:
FHIR-13550 was a Published/Persuasive with Modification FHIR-core Conformance change request for STU3. It reported that CapabilityStatement cpb-15 said kind instance statements do not have implementation elements, while the intended rule was that implementation elements are allowed only for kind instance; it also requested linking the invariant to CapabilityStatement.kind and CapabilityStatement.implementation and clarifying ElementDefinition.condition to mention value as well as cardinality.

Initial application:
The issue was applied in git-svn commit d4fc4a47fe5e5d3d539bf12c42f50f0d8f8f1a9f, which changed the old CapabilityStatement spreadsheet invariant text and expression to the implementation-only-for-instance rule and linked it from both kind and implementation in the spreadsheet source. The ElementDefinition.condition wording now states that an invariant may make additional statements about cardinality or value.

Additional context:
FHIR-13551, created moments after FHIR-13550 and later Published, replaced the two-rule model with the current three-rule split: kind instance requires implementation, kind capability prohibits implementation and requires software, and kind requirements prohibits both implementation and software. Later FHIR-19955 and FHIR-36685 concerned XPath/Schematron artifacts for the same constraints and are already represented on the combined branch; later FHIR-55150 is Resolved - change required but not Applied/Published and concerns a future clarification of the requirements fallback, not this implementation-presence rule.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The active current CapabilityStatement source enforces the FHIR-13550 intent through the FHIR-13551 three-constraint model, repeats the relevant conditions on CapabilityStatement.kind and CapabilityStatement.implementation, and the ElementDefinition.condition definition includes the requested cardinality-or-value wording.

Recommendation:
Keep this no-change audit as-is. Do not reintroduce the old single cpb-15 wording; the current three-rule model is clearer and is the later accepted resolution for the same issue family. Treat FHIR-55150 separately if the run scope later includes Resolved - change required issues.
