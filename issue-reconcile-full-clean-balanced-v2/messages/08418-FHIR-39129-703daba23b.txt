FHIR-39129: Align DocumentReference bodyStructure artifacts

Issue request:
FHIR-39129 was a Published/Persuasive with Modification R5 SD issue asking DocumentReference to carry Media attributes that were not directly mapped, specifically encounter, bodysite, and modality. The accepted resolution said encounter had already been added, bodySite 0..* and modality 0..* should be added, search parameters should be added for modality and bodySite, and an encounter search parameter should exist.

Initial application:
The issue was initially applied through HL7/fhir PR #2501, merged as accd7ce497462e69c5b61c8ec6ded4af7c93b4f8. Its implementation commit e41db687b398699cf93fb3dff28b80d554c9c311 added `DocumentReference.bodySite`, `DocumentReference.modality`, the coded body-site and modality search parameters, and the DICOM example body-site content. Encounter search support was already present in the common `clinical-encounter` search parameter for DocumentReference, consistent with the Jira resolution's first point.

Additional context:
DocumentReference is active in `source/fhir.ini`, and `source/documentreference/list-DocumentReference-examples.xml` lists the DICOM example, so the edited example and resource diagram are in current build scope. Later Applied issue FHIR-53203 renamed OO bodySite elements/search parameters to bodyStructure/body-structure; current source has `DocumentReference.bodyStructure`, `body-structure`, `body-structure-reference`, and `modality` definitions/search parameters, with `fhir.ini` R5-to-R6 path mappings from `DocumentReference.bodySite` to `DocumentReference.bodyStructure` and from `DocumentReference.context.encounter` to `DocumentReference.context`. Related Published issue FHIR-38966 added the reference-side body-site search parameter and is already represented on the combined branch. OO minutes for 2022-12-13 record FHIR-39129 as persuasive by vote. No Zulip or Confluence search result was found that conflicts with the Jira/source conclusion.

AutoFHIR reconciliation:
This commit fixes the remaining stale source artifacts from the original bodySite application by changing the DICOM DocumentReference example to use `bodyStructure` and by aligning the checked-in DocumentReference SVG link/label with `DocumentReference.bodyStructure`. It intentionally leaves the authoritative element and search parameter definitions unchanged because current source already carries the requested Media attributes under the later R6 bodyStructure naming and already includes encounter/context search support.

Recommendation:
Keep this commit as-is. No further FHIR core source change is needed for FHIR-39129 unless the build system regenerates the SVG from another source, in which case the same `bodyStructure` label/link should be preserved there as generated output.
