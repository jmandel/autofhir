FHIR-14233: Audit UsageContext context code clarification

Issue request:
FHIR-14233 was a Published/Persuasive CDS change request for STU3 asking to clarify UsageContext usage-context-type code descriptions. The issue said several descriptions made example value sets sound required, objected to US-realm NUCC venue guidance where universal-realm guidance was available, and requested ServiceDeliveryLocationRoleType for venue.

Initial application:
The issue was applied by Bryn Rhodes in SVN 12614 / git commit 279a2c1589b5263a5fadfc49624892370b8dd5b2. That commit relaxed the usage-context-type descriptions from mandatory-sounding wording such as "should be" and "can be any" to example-oriented wording, and replaced the venue suggestion with ServiceDeliveryLocationRoleType.

Additional context:
UsageContext remains an active metadatatypes datatype in source/fhir.ini, and source/metadatatypes.html includes the UsageContext terminology section. Later terminology maintenance moved usage-context-type to THO and the already-published FHIR-39632 reconcile commit updated the UsageContext additional-binding usage codings to http://terminology.hl7.org/CodeSystem/usage-context-type. The current additional bindings still use ServiceDeliveryLocationRoleType for venue as a starter binding, which is compatible with the FHIR-14233 venue guidance and later THO ownership.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/datatypes/usagecontext.xml already contains the relaxed example wording for gender, age, user, task, and venue, and the venue description points at http://terminology.hl7.org/ValueSet/v3-ServiceDeliveryLocationRoleType. Searches found no surviving current UsageContext code-description text using the specific mandatory-sounding phrases that FHIR-14233 removed.

Recommendation:
Keep this audit commit as-is. The current source already reflects the published STU3 decision, and adding further prose would be redundant with the existing code descriptions and later additional-binding machinery.
