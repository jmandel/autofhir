FHIR-7547: Audit Observation true/false value guidance

Issue request:
FHIR-7547 was a Published/Persuasive OO change request from the DSTU1 ballot asking that Observation make the availability of true and false value codes explicitly obvious. The accepted resolution directed the Notes section to say that boolean values should use valueCodeableConcept with the HL7 v2 0136 yes/no value set, whose yes/no concepts can be mapped to display names such as true/false.

Initial application:
No current git commit explicitly names FHIR-7547, but the source history shows the relevant Observation Notes text was applied in the same old tracker family. Commit 861e258d1a20 added the requested note that boolean values use valueCodeableConcept with HL7 v2 Table 0136 and can map yes/no to true/false. Commit 41029c884d58 then refined the note to say that the Boolean datatype is rarely used because observations often need exceptional values such as unknown. Later editorial commits carried the same guidance forward.

Additional context:
The active fhir.ini resources list includes Observation, so source/observation/observation-notes.xml and source/observation/structuredefinition-Observation.xml are in current build scope. The current Observation.value[x] StructureDefinition links readers to the Notes section and includes the later valueBoolean choice added by FHIR-10275. FHIR-3505 records the earlier same-family decision to add the v2 0136 true/false note instead of adding valueBoolean at that time; FHIR-10275 later superseded only the prohibition by adding valueBoolean, not by removing the coded-value guidance. No Zulip or Confluence hit for FHIR-7547 itself, and the relevant community thread led to FHIR-10275 rather than a reversal of the Notes guidance.

AutoFHIR reconciliation:
This audit commit makes no source change because current Observation Notes already say that Boolean values are rarely truly Boolean, recommend CodeableConcept with terminology.hl7.org/ValueSet/v2-0136 for yes/no concepts, and explicitly state those concepts can map to the display name true/false. This preserves the later valueBoolean allowance while retaining the FHIR-7547 guidance.

Recommendation:
Keep this audit commit as-is. No core source edit is needed for FHIR-7547; any future change to the balance between valueBoolean and coded yes/no values should be handled under a newer OO decision rather than by reopening this published DSTU1 note.
