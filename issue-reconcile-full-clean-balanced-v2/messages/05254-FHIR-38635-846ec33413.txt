Issue request:
FHIR-38635 is a Published FHIR-core OO change request, raised against R4 and applied for R5, asking to move the $docref operation from US Core/IPA into the base FHIR specification with DocumentReference. The final resolution was Persuasive with Modification: create a clone of US Core $docref in the base standard with DocumentReference, consider a name change, and inform CGP and Patient Care.

Initial application:
The source history contains an explicit implementation commit, 57f52fb89496fefc88fea3fbb7e5177771114b90, "FHIR-38635: add $docref to base spec." It added source/documentreference/operationdefinition-DocumentReference-docref.xml, request and response example snippets, and a DocumentReference operations-list entry. Later source commits normalized the operation name/metadata and clarified behavior without removing the base operation.

Additional context:
FHIR-34736 is the antecedent IPA issue that raised the collision/divergence concern and records FHIR-I's view that OO should own a core DocumentReference operation. OO WGM minutes for 2022-09-19/23 discuss FHIR-38635, note that OO owns DocumentReference, and frame the question as the DocRef operation moving into the base spec. Later same-artifact decisions such as FHIR-38667 and FHIR-42917 are already represented on the combined branch and should not be duplicated here. FHIR-53038 is a later unresolved R6 alignment request, so it is context rather than a final source-edit decision for this run.
