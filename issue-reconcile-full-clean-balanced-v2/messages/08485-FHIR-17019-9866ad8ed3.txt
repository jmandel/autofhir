FHIR-17019: Audit invariant rendering differentiation

Issue request:
FHIR-17019 was a Published/Persuasive FHIR-core, FHIR-I clarification raised against the May 2018 BackboneElement detailed definitions page. It asked that definitions pages distinguish invariants inherited from elsewhere, or otherwise affecting an element, from invariants defined on that specific element.

Initial application:
The Jira comment records svn 14600 as the application. In git, commit 1a55c86456d5afa508298905b88b933bdd11e813, "GF#17019 - invariant rendering improvements," implemented that change by updating the old checked-in DictHTMLGenerator and TableGenerator rendering to group constraints under headings such as "Defined on this element," "Inherited by this element," and "Affect this element." The generator code was later removed from the FHIR checkout during the Gradle/Kindling build refactor, so current rendering behavior is supplied by the Kindling dependency rather than editable source in this repository.

Additional context:
BackboneElement remains in current build scope: source/fhir.ini lists it as active infrastructure, maps backboneelement to the types page, marks it normative, and assigns the bbe code. The current build.gradle.kts invokes org.hl7.fhir.tools.publisher.Publisher from the configured Kindling dependency. Current CI output still differentiates constraint origins: types-definitions.html and elementdefinition-definitions.html show "Defined on this element" separately from "Affect this element," and profile output such as vitalsigns-definitions.html shows "Inherited by this element." Jira neighborhood searching found no later FHIR-core issue that reverses this rendering decision, and Zulip/Confluence searching found only a commit-bot notification plus no conflicting discussion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The requested rendering distinction is already present in the current generated specification, and there is no authoritative core source hunk to adjust for the historical rendering request.

Recommendation:
Keep this no-change audit commit. If a future reviewer wants a different label or rendering rule, that follow-up belongs in the Kindling/publisher rendering code, not in the BackboneElement datatype source.
