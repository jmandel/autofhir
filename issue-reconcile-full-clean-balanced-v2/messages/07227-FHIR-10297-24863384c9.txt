FHIR-10297: Audit request status alignment

Issue request:
FHIR-10297 was a Published/Persuasive OO change request for DSTU2 NutritionRequest and Supply. It asked to align status elements in request resources with request lifecycle states, including entered-in-error and later cancelled/withdrawn handling, while keeping fulfillment-progress states in Task rather than in the request resource status.

Initial application:
No explicit source commit mentioning FHIR-10297 was found. The change appears to have been applied indirectly through the request-pattern cleanup history: git f7edc9ba53 added entered-in-error to the then-current SupplyRequest/SupplyDelivery status sources, git 8b2144d9f1 changed SupplyRequest statuses to draft, active, suspended, cancelled, completed, entered-in-error, and unknown as part of aligning SupplyRequest with the request pattern, and git 4d4a837d01 for FHIR-14414 later moved NutritionOrder/NutritionRequest status to the shared request-status binding and added request intent.

Additional context:
Current core build scope differs from the DSTU2 artifact names. source/fhir.ini lists nutritionorder=NutritionOrder as an active resource, while NutritionRequest and Supply appear only in the removed-resources list, and SupplyRequest/SupplyDelivery no longer have active fhir.ini resource entries. Current NutritionOrder.status is required-bound to http://hl7.org/fhir/ValueSet/request-status, whose code system contains draft, active, on-hold, entered-in-error, unknown, ended, completed, and revoked. Request pattern notes explicitly keep fulfillment-progress states on Event/Task rather than changing the request status. FHIR-14414, FHIR-3720, FHIR-43447, and FHIR-43453 are already represented on the combined branch and confirm the later NutritionOrder/request-pattern and external SupplyRequest state.

Editing dormant source/supplyrequest or source/supplydelivery would not change the current core build.
