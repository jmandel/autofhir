FHIR-47905: Audit Device category relocation

Issue request:
FHIR-47905 was an Applied FHIR-core DeviceDefinition change request with a Persuasive with Modification resolution. The ballot comment said DeviceDefinition's scope section had a device subdivision list that was not clearly related to DeviceDefinition and duplicated a long Device list. The approved resolution was to keep the combined detailed device category list in DeviceDefinition and make the Device resource text refer readers to DeviceDefinition for the device kinds/categories considered devices.

Initial application:
The source application appears in commit 3cf635fa2b606d038462a683a53338e39b3f30e3, a March 31, 2025 multi-issue Device text update that explicitly listed FHIR-47905. That commit removed the detailed category subsections from source/device/device-introduction.xml, added a Device-to-DeviceDefinition reference for category descriptions, and placed the detailed category descriptions in source/devicedefinition/devicedefinition-introduction.xml.

Additional context:
FHIR-47904 is the same Scope and Usage change family and was resolved to rework the DeviceDefinition opening in light of FHIR-47905; the current source includes the later FHIR-47904 wording refinement from PR #3667. Commit 0d559917d48c69ce6b362625246e95407e103b2d later fixed the Device page typo in the DeviceDefinition category-reference sentence. Confluence OO/DEV minutes confirm the joint work-group discussion and vote to move device categories into DeviceDefinition. Device and DeviceDefinition are active resources in source/fhir.ini, so these introduction files feed current build output.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/device/device-introduction.xml has only a compact category summary and links to DeviceDefinition for detailed category descriptions, while current source/devicedefinition/devicedefinition-introduction.xml contains the detailed category list and definitions. That satisfies the approved relocation without adding redundant prose or reopening the related FHIR-47904 wording work.

Recommendation:
Keep this audit commit as-is. Future changes should only be made if the work group decides that Device should omit even the compact category examples; FHIR-47905 itself is already applied in the current build source.
