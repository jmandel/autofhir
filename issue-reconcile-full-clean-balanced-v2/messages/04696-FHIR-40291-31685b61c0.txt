FHIR-40291: Confirm device specification value set cleanup

Issue request:
FHIR-40291 was an Applied OO change request raised against R5 for Device and DeviceDefinition. It originally asked to expand the example value set for Device.conformsTo.specification and DeviceDefinition.conformsTo.specification with additional kinds of specifications; the final Not Persuasive with Modification resolution instead declined new example types and required removing display names from the compose concepts of the Device Specification Type value set.

Initial application:
The source application is commit 8d113e206a5226b6f569645c86dfd63f9d67e4b5, linked from Jira as PR #3714, which removed all 17 <display> elements from source/device/valueset-device-specification-type.xml. No other Jira-tagged source change was needed for the active Device and DeviceDefinition bindings.

Additional context:
source/fhir.ini actively includes both Device and DeviceDefinition resources, and their StructureDefinition sources bind Device.conformsTo.specification and DeviceDefinition.conformsTo.specification to http://hl7.org/fhir/ValueSet/device-specification-type. The value set source is therefore in current build scope through the active Device resource area. The 2025-10-06 OO HCP minutes record the same Not Persuasive with Modification disposition and 5-0-0 vote; no Zulip discussion changing this conclusion was found.

AutoFHIR reconciliation:
This commit intentionally makes no source changes. The current value set compose includes the same ISO 11073:10101 codes but no display values, satisfying the final applied resolution without adding unapproved example types.

Recommendation:
Keep this audit commit as-is. Future requests to add Bluetooth, IHE, FHIR, regulatory, or other specification examples should come through a new Jira with specific proposed codes, as the FHIR-40291 resolution requested.
