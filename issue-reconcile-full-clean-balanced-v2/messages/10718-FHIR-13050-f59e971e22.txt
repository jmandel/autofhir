FHIR-13050: Audit HEAD support in Bundle requests

Issue request:
FHIR-13050 was a Published/Persuasive FHIR-I change request asking to allow HEAD wherever GET is allowed, add HEAD to Bundle.entry.request.method, and require unsupported HEAD requests to fail according to HTTP (for example 405 or 501).

Initial application:
The issue was applied in December 2017 by SVN-sourced commits #13050/r12847 and #13050/r12849. Those commits added the RESTful HEAD narrative to source/http.html and added HEAD to the Bundle request-method spreadsheet source. Later source rework migrated that spreadsheet content into the current Bundle StructureDefinition and HTTPVerb CodeSystem.

Additional context:
Bundle remains an active resource in source/fhir.ini, so source/bundle/structuredefinition-Bundle.xml and source/bundle/codesystem-http-verb.xml are current build inputs. A later Applied issue, FHIR-40497, only clarified the nearby vread HEAD note and did not reverse or narrow the broader FHIR-13050 rule. Community searches found only the tracker bot notification and no substantive Zulip or Confluence discussion changing the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already lists HEAD in Bundle.entry.request.method, includes HEAD in the required HTTPVerb code system, and states in the HTTP page that HEAD is allowed wherever GET is used and that unsupported HEAD requests must follow HTTP error behavior.

Recommendation:
Keep this no-change audit commit as-is. No follow-up source work is needed for FHIR-13050 unless a future work-group issue changes the global HEAD policy.
