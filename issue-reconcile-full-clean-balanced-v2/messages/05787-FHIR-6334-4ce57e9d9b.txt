FHIR-6334: Audit Condition abatement dateTime

Issue request:
FHIR-6334 was a Published/Persuasive Patient Care change request from DSTU1 asking why Condition.onset[x] allowed dateTime while Condition.abatement[x] only allowed date, and resolving to change abatement[x] to use dateTime instead of date.

Initial application:
The change appears to have been applied by git commit 136c952ea9e750c07d05f53e3c98dfecaad7b55b, which changed the then-authoritative Condition spreadsheet type from date to dateTime and updated the renal example from abatementDate to abatementDateTime.

Additional context:
The current source/fhir.ini actively includes Condition as a built resource. Current source/condition/structuredefinition-Condition.xml defines both Condition.onset[x] and Condition.abatement[x] with dateTime among their choice types, and the date search parameter explicitly covers Condition.abatement.ofType(dateTime). Later history removed abatementBoolean under FHIR-13201, leaving the current type list dateTime, Age, Period, Range, and string; that later cleanup does not reverse the FHIR-6334 dateTime decision. Duplicate Jira reports FHIR-7879, FHIR-7619, and FHIR-7296 all ask for the same date/dateTime consistency and do not require separate source changes.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change because the current build-scope Condition definition already implements the requested dateTime abatement type and no contradictory source or community evidence was found.

Recommendation:
Keep this no-change audit commit as-is. No core FHIR source follow-up is needed for FHIR-6334 unless a future Patient Care decision changes Condition.abatement[x] datatypes again.
