FHIR-14217: Audit Meta.source addition

Issue request:
FHIR-14217 was a Published/Persuasive FHIR-core BaseResource change request from STU3 asking to add source : url to Resource.meta as new normative content, with the resolution note to apply it fully including the Resource.meta table of contents.

Initial application:
The change was applied before this reconciliation. Git commit 7acde0ac43e83f7b9b7076269eac28735def62f8 added Meta.source to source/datatypes/meta.xml on 2017-11-23 as a 0..1 uri element, and commit 56226183c1cd1b8a31928471771de6c317ae4410 updated the Meta.source documentation immediately after the 2017-12-18 vote. Current source/fhir.ini routes the Meta datatype to the Resource page, and the current Resource/Meta source includes Meta.source in the element row, narrative table, _source search parameter bundle, and search parameter prose.

Additional context:
The issue summary's "url" wording does not justify changing the current datatype: the initial implementation used uri, and later final decisions around the same element preserved that model while clarifying scope. FHIR-20688 and FHIR-20906 clarified that Meta.source can be a broad source identifier corresponding to Provenance.entity.what or Provenance.agent.who; FHIR-20908 rejected changing cardinality to 0..*; FHIR-17232 reused Meta.source for current authoritative service guidance; and FHIR-49878 updated the definition from "source system" to "data source." Existing combined-branch audit commits already represent FHIR-20688, FHIR-20906, FHIR-17232, and FHIR-49878, so this commit does not duplicate them.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current active source already contains the requested Resource.meta.source element and related built surfaces, and further wording or datatype edits would go beyond FHIR-14217 and the later applied decisions.

Recommendation:
Keep this empty no-change audit commit as-is. Revisit only if a new work-group decision specifically asks to change Meta.source's datatype or relationship to Provenance beyond the current uri-based, single-source guidance.
