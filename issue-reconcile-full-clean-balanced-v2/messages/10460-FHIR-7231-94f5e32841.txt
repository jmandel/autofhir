FHIR-7231: Audit f202 temperature coding

Issue request:
FHIR-7231 was a Published/Persuasive with Modification OO change request for the DSTU1 Observation f202 temperature example. It objected that the example showed SNOMED CT oral-temperature and LOINC body-temperature codings together in Observation.code without explaining the choice or aligning the concepts, and the final resolution was to edit examples so Observation.code was not SNOMED-only: add LOINC as a translation or make the code local.

Initial application:
The issue appears to have been applied by git commit 474be19befc8b8882da2b23a826dd0e2106a1538, whose subject explicitly lists 7231. That commit changed source/observation/observation-example-f202-temperature.xml by replacing the challenged SNOMED CT 415945006 oral-temperature Observation.code coding with a local acme.lab BT coding, keeping the LOINC 8310-5 body-temperature coding, and changing the body site to Oral cavity. Later edits added explanatory international-coding text and a SNOMED CT secondary coding, and later Vital Signs work restored the required LOINC 8310-5 coding to Observation.code after a temporary category-based experiment.

Additional context:
FHIR-7211 is the same 2015May f202 temperature concern and was explicitly referenced from FHIR-7231 as core #271. FHIR-7211's resolution says to fix the example while noting that FHIR core is an international standard and is not limited to LOINC, so the accepted decision does not ban all SNOMED CT codings. Current source/fhir.ini lists Observation as an active resource, so the f202 example is in current build scope. Current f202 has LOINC 8310-5, local BT, and the more specific LOINC 8331-1 oral-temperature coding in Observation.code, while the old SNOMED CT 415945006 coding is absent and oral details are also represented through bodySite/method. Direct Zulip and Confluence searches for FHIR-7231 found no conflicting community record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative current source already removes the original mismatched SNOMED oral-temperature Observation.code coding and includes the LOINC codings needed to avoid the SNOMED-only/misaligned example problem; removing all remaining SNOMED CT from the example would go beyond the accepted international-scope resolution.

Recommendation:
Keep this no-change audit commit. Future cleanup, if desired, should be handled under a new tracker focused on whether the remaining secondary SNOMED CT Temperature taking coding is pedagogically useful, not under FHIR-7231.
