FHIR-9961: Audit V2 value set ownership

Issue request:
FHIR-9961 was a Published/Persuasive DSTU2 change request asking for version-dependent and version-independent HL7 V2 value set URLs and identifiers, with explicit documentation of what V2 version or set of versions each value set covered.

Initial application:
No current git commit explicitly mentioning FHIR-9961 was found. The original 2016 Zulip thread records Grahame's application intent: generate version-specific V2 value sets while using the same value set URL with different versions. Current core history then superseded that local page surface when commit 5c0494aacfd0b8bd52bc72c587aa89d0a64246f8 removed the HL7 v2 value-set tab and v2VSIndex placeholder from source/terminologies-valuesets.html as part of moving UTG terminology content out of the core build.

Additional context:
The Jira itself says the issue became a UTG matter by 2018. Vocabulary minutes in 2019 record the plan that FHIR would remove vocabulary details from ballot pages and link to UTG, with V2 code systems and value sets versioned independently of the ballot. Later Vocab minutes in 2021 say Version 2.x vocabulary was replaced in THO and direct users to terminology.hl7.org for V2 value sets. The already-published FHIR-26836 audit and FHIR-25896 source change cover the same core Value Sets page migration and clarify that HL7 Terminology value sets outside core are not listed on the page.

AutoFHIR reconciliation:
This commit intentionally makes no source change in HL7/fhir. Current active source/terminologies-valuesets.html lists only core FHIR value sets and points to HL7 Terminology for additional value sets; source/fhir.ini has no active V2 value-set entries; and current THO publishes V2 value sets such as http://terminology.hl7.org/ValueSet/v2-0203 with version and OID metadata outside this checkout. Any remaining update to V2 version-dependent/independent value-set identifiers belongs in THO/UTG, not in current core FHIR source.

Recommendation:
Keep this external-repo audit commit as-is for core FHIR. If humans want to reassess whether THO still satisfies the original version-specific V2 value-set policy, open or review a THO/UTG proposal; do not reintroduce the old core V2 value-set tab or edit inactive tools/tx/v2 templates as a core-spec reconciliation.
