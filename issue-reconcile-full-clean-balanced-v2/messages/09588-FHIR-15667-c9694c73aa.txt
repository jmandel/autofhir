FHIR-15667: Audit current itemControl handling

Issue request:
FHIR-15667 was a Published/Persuasive with Modification STU3 Questionnaire change request asking for richer itemControl support: a complex choiceColumn extension for choice/openChoice columns, a width extension for table columns, additional table-oriented itemControl codes, and examples.

Initial application:
The issue was applied in historical core commit b8c5990ac5, whose message names 15667 and whose Questionnaire changes added choiceColumn/width extension rows and itemControl table codes including table, htable, gtable, and atable. No current combined-branch audit commit for FHIR-15667 existed before this reconciliation.

Additional context:
Later Published issue FHIR-19527 moved questionnaire-choiceColumn and questionnaire-width out of FHIR core to the SDC IG. Current SDC source defines sdc-questionnaire-choiceColumn and sdc-questionnaire-width, documents their rendering use, and includes examples. The current FHIR Extension Pack carries the active questionnaire-itemControl extension and questionnaire-item-control code system, including Vertical Answer Table (table), Horizontal Answer Table (htable), and Group Table (gtable). Later Published issue FHIR-20944 removed atable as redundant, and FHIR-32664 clarified the table/htable definitions to say the child questions should share answer options/value set/expression.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core checkout correctly does not re-add the complex choiceColumn/width extensions because FHIR-19527 moved them to SDC, and it correctly does not restore atable because FHIR-20944 removed it. The remaining itemControl codes and guidance are present in the current extension-pack/SDC sources rather than in an active core Questionnaire source file.

Recommendation:
Keep this audit commit as-is. If future work wants to change rendering behavior or examples, it should be filed against the SDC IG or Extension Pack artifact that now owns the relevant source, not as a back-port of FHIR-15667 into core.
