FHIR-6326: Audit break-glass OperationOutcome guidance

Issue request:
FHIR-6326 was a Published/Persuasive with Modification DSTU1 FHIR-I change request asking how an OperationOutcome should communicate security-imposed search limitations, specifically where a break-the-glass hint would appear and what Bundle.entry.search.mode would apply. The accepted resolution was to add a break-the-glass OperationOutcome example and reference it from the security guidance.

Initial application:
The issue was applied in git commit 0b6797bec0ffc5f0bd1afdba375f0d2fc93694a7, imported from SVN revision 6513, which added source/operationoutcome/operationoutcome-example-break-the-glass.xml, listed the example for OperationOutcome publication, and linked it from the then-current security chained-search paragraph. Current source still carries the example, and the OperationOutcome resource is active in source/fhir.ini.

Additional context:
Later maintenance updated the same example from ETREAT to the more specific BTG purpose-of-use code requested by FHIR-27917, and FHIR-27917 is already represented on the combined branch. FHIR-53885 later moved the Break-the-Glass material from security-labels to the Security page and is also already represented on the combined branch. The current HTTP/search guidance says OperationOutcome entries in searchset Bundles use Bundle.entry.search.mode=outcome, matching the example's markdown note.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source already answers the issue: the break-the-glass OperationOutcome example explains that it can be returned in a search-result Bundle with search.mode=outcome; the OperationOutcome example list publishes it; the Security page links to it from the Break the Glass section; and the general HTTP search text defines the outcome search mode for OperationOutcome entries.

Recommendation:
Keep this no-change audit commit. Further source edits would duplicate existing guidance rather than change implementer understanding. FHIR-27917 and FHIR-53885 should remain separate prior reconciliations because they update/refactor later break-glass details rather than alter the FHIR-6326 application.
