FHIR-28441: Audit inheritance-control extension location

Issue request:
FHIR-28441 was a Published FHIR-core change request, resolved Persuasive with Modification, asking for a StructureDefinition extension to let extension authors declare how an extension should be inherited by snapshot generators. The approved resolution called for a 0..1 code extension on StructureDefinition with inheritance behavior codes.

Initial application:
The issue was applied in core by commit 4944ac0e15, which added structuredefinition-inheritance-control plus its inheritance-control-code CodeSystem and ValueSet under source/structuredefinition and registered them in the StructureDefinition core implementation guide. A later core refactor, dd468d4f17, removed extension definitions from the R5 core source tree as part of moving extensions out of core; current core source now retains only the OID registry entries for these canonical URLs.

Additional context:
FHIR-27535 was treated as the duplicate/problem statement resolved by FHIR-28441, and FHIR-I minutes record the 2020-09-14 persuasive-with-modification vote for FHIR-28441 as the survivor. The current external artifacts are not owned by this core checkout: the FHIR Extension Pack contains structuredefinition-inheritance-control and its legacy code system/value set, while the current FHIR Tools IG carries the active http://hl7.org/fhir/tools/StructureDefinition/snapshot-behavior extension, required binding, and ignore/add/defer/overwrite codes. Later Zulip discussion and FHIR-56447 show that applying snapshot-behavior to specific extension definitions is ongoing external-repo work, not a safe core-source edit.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR core source change. The requested inheritance-control mechanism was historically applied and the current maintained artifacts live outside the FHIR core source checkout, so editing core would either duplicate an external artifact or change out-of-build source.

Recommendation:
Keep this audit commit as-is for the core reconciliation. If the work group wants additional snapshot-behavior annotations on individual extensions, handle that in the FHIR Tools IG and/or FHIR Extension Pack, following FHIR-56447 and related extension-pack issues rather than changing core.
