FHIR-37849: Align concept property datatypes

Issue request:
FHIR-37849 was Published with a Persuasive resolution for R5 to reconcile the CodeSystem Concept Properties table with the http://hl7.org/fhir/concept-properties code system. The accepted disposition retained the table, added table codes to the code system and vice versa, deprecated the old deprecated property code in the code system, and kept deprecated out of section 4.8.12.

Initial application:
Git commit bad31b070fe6703f221a0c60357e2d0cde9c5938 applied FHIR-37849 by adding status, effectiveDate, deprecationDate, and retirementDate to the Concept Properties CodeSystem and adding the corresponding table rows. Later source work added explicit dataType property values and new concept-property rows, but the current table still carried stale datatypes and two wrong copy-button URIs.

Additional context:
source/fhir.ini actively includes concept-properties under [codesystems], and CodeSystem is an active resource, so both source/codesystem/codesystem-concept-properties.xml and source/codesystem/codesystem-notes.xml are in current build scope. FHIR-48428 made concept-property datatypes explicit using ValueSet/concept-property-type; FHIR-44627 deprecated synonym and added a deprecationDate value; FHIR-50433 later added replacedByCode and replacedByCoding. FHIR-42956 is later Resolved - change required clarification work about status versus inactive, but it is not applied/published source-edit scope for this default run.

AutoFHIR reconciliation:
Aligned the CodeSystem Concept Properties table with the formal concept-property datatypes by changing effectiveDate, deprecationDate, and retirementDate from date to dateTime, fixing the deprecationDate and retirementDate clipboard URIs, and changing the grouped replacedBy[X] row from string to code or Coding. Also corrected the synonym concept's deprecationDate property value from valueCode to valueDateTime so the instance uses the declared dateTime property type.

Recommendation:
Keep this source commit as-is. It is a narrow consistency fix for the same normative table/code-system relationship FHIR-37849 addressed; separate future work can still apply FHIR-42956 if the work group wants broader prose about status, inactive, and date-related properties.
