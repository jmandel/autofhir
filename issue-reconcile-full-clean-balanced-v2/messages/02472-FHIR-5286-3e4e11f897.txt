FHIR-5286: Audit ImagingStudy alias cleanup

Issue request:
FHIR-5286 was a Published / Persuasive with Modification DSTU1 Imaging WG ballot issue for ImagingStudy.clinicalInformation. It asked that the misleading alias "Admitting Diagnoses Description" not imply only admitting diagnoses; the accepted resolution added AdditionalPatientHistory and used camel-case DICOM-style alias text. Issue comments also flagged "Manifest" and "XDS-I summary" as aliases of ImagingObjectSelection rather than ImagingStudy, while the broader meaning of aliases was split to FHIR-5542.

Initial application:
The explicit 2015 application commit a51afaf7a9b18b211c1b998e3903993967cc3984 tagged [#5286] and changed source/imagingstudy/imagingstudy-spreadsheet.xml so ImagingStudy.clinicalInformation used "AdmittingDiagnosesDescription; AdditionalPatientHistory". A later 2015 ImagingStudy cleanup commit 2a416c3e036ffe6effcec41c32d86923d7b7fad7 removed the ImagingStudy root alias row that still contained "Manifest,XDS-I summary, Key Images". A 2016 Imaging update af0194455209a0b1f8e57e5ab25f8db53645da0b removed the old clinicalInformation element from ImagingStudy entirely.

Additional context:
The current build scope has active [resources] imagingstudy=ImagingStudy, and the current active source/imagingstudy/structuredefinition-ImagingStudy.xml has no ImagingStudy.clinicalInformation element and no root-level aliases. Its remaining aliases are DICOM-style camel-case terms such as StudyInstanceUID, StudyDescription, and AccessionNumber. Exact stale terms only remain in retired/historical artifacts such as old ImagingManifest/history files, not in the active ImagingStudy definition. FHIR-5542 separately records and applies the broader alias-label explanation, and negative Zulip/Confluence searches found no contrary community record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active ImagingStudy source no longer contains the misleading clinicalInformation alias or the root aliases that prompted the issue, and editing retired history/removed-resource artifacts would not improve the current specification.

Recommendation:
Keep this no-change audit commit as-is. No FHIR core follow-up is needed for FHIR-5286 unless the work group wants a separate editorial review of alias rendering outside the current ImagingStudy source.
