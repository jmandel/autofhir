FHIR-14271: Audit request parameters already applied

Issue request:
FHIR-14271 was a Published/Persuasive OO change request for STU3. It asked to add a repeating parameters element to DeviceRequest and SupplyRequest, add ballot-comment guidance around whether VisionPrescription was still needed, and add a DeviceRequest example based on VisionPrescription lens data.

Initial application:
The issue was applied in the historical SVN/Git stream. Commit 17a86882a2 added DeviceRequest.parameter and SupplyRequest.parameter backbone elements with code/value children and #14271 committee notes. Commit 430cbb5ff2 corrected a misapplied SupplyRequest cardinality in the same application area, and commit 22dab73da5 added coded lens details to the DeviceRequest examples.

Additional context:
FHIR-11217 is the predecessor discussion that kept VisionPrescription separate while motivating this parameter-based modeling path. Later R6 work such as FHIR-51718 refined VisionPrescription request-pattern alignment but did not reverse DeviceRequest.parameter. In the current core build, source/fhir.ini actively includes DeviceRequest, while SupplyRequest and SupplyDelivery were removed from the active resource list by 3b38b80cf2 and current core pages point SupplyRequest references at the OO Incubator IG.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active DeviceRequest StructureDefinition already contains DeviceRequest.parameter, DeviceRequest.parameter.code, and DeviceRequest.parameter.value[x]; the current DeviceRequest example list includes right-lens and left-lens examples that exercise parameter; and the DeviceRequest introduction still explains the VisionPrescription overlap. The remaining SupplyRequest source file also contains the requested parameter elements, but SupplyRequest is no longer part of the active core build.

Recommendation:
Keep this audit commit as-is. No FHIR core source fix is needed for FHIR-14271. If implementers need to verify or change the current SupplyRequest representation, that should be handled in the OO Incubator IG rather than by editing inactive core SupplyRequest source.
