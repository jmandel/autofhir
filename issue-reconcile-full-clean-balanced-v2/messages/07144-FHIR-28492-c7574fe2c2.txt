FHIR-28492: Audit Coding display/code warning invariant

Issue request:
FHIR-28492 was a Published FHIR-core datatypes clarification, resolved Persuasive with Modification for R5, asking the specification to clarify whether Coding.code is required when Coding.display is populated. The accepted resolution was to add a warning invariant to Coding saying a Coding SHOULD NOT have a display unless a code is also present, that Coding.display alone is unsafe for computation, and that CodeableConcept.text should be considered.

Initial application:
The issue appears to have been applied by commit 1afdc56774dad83e4bc0207bbfe0e78c599e3742, which added the warning invariant text and the logically equivalent FHIRPath expression code.exists().not() implies display.exists().not() to source/datatypes/coding.xml. The parent of that commit did not contain the invariant phrase, and the current source still contains it.

Additional context:
source/fhir.ini lists Coding as an active datatype and routes datatypes through datatypes.html, whose Coding section renders datatype constraints with [%dt.constraints Coding%]. Later related datatype decisions FHIR-37603 and FHIR-38981 refined adjacent display-string and CodeableConcept.text narrative but did not remove or contradict the FHIR-28492 warning invariant. The linked Zulip discussion supports warning-level guidance rather than making Coding.code mandatory, and the Confluence minutes show the item was routed for FHIR-I handling before later publication.
