FHIR-15674: Audit Questionnaire calculated values

Issue request:
FHIR-15674 was a Published/Persuasive with Modification FHIR-core Questionnaire change request raised for STU3. It asked for a way to specify a question value by formula, such as BMI computed from other answers. The final resolution was to use the same approach as the scored-answer work in FHIR-15669 and to ensure the documentation made clear that the solution covered both scores and calculated question values.

Initial application:
The Jira comments cite SVN #14772. In git, that application is b8c5990ac5ad735ba1e8e836fd8a4c6fd3534a3e, whose subject names both 15669 and 15674. It added a Questionnaire math section describing tabulated scores plus dynamic element values using expressions, and the then-current Questionnaire extension spreadsheet included a calculatedExpression extension of type Expression for values updated as QuestionnaireResponse answers are filled in.

Additional context:
Later source history split the detailed expression extensions out of current core. Commit 9b1695bfd4838b17f97463de138bd962fa78a7c9 removed the calculatedExpression row from the core Questionnaire extension spreadsheet, and commit 6a2623d0c014b977d37bd7c0cf28e86b4201647e explicitly moved related Questionnaire expression-extension material to SDC. The current FHIR core checkout no longer contains calculatedExpression in core or in the Extension Pack, but the published SDC IG has an active sdc-questionnaire-calculatedExpression StructureDefinition with value[x] constrained to Expression. Questionnaire remains active in source/fhir.ini, and the current Questionnaire notes point advanced dynamic questionnaires, including calculated scores, to SDC while the math section links dynamic values using expressions.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core source is correct at the core-build level: it does not re-own the SDC calculatedExpression extension, and it already gives implementers the necessary direction through the SDC and expression guidance. Re-adding or duplicating the detailed calculatedExpression definition in core would conflict with the later SDC ownership split.

Recommendation:
Keep this no-change audit commit. Future changes to calculated question behavior should be made in the SDC implementation guide unless FHIR-I explicitly decides to move the extension back into core. Core should continue to reference SDC and expression guidance rather than duplicating SDC-specific rules.
