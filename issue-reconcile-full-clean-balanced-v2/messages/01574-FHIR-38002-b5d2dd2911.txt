FHIR-38002: Audit MeasureReport reporter Group removal

Issue request:
FHIR-38002 was an Applied/Persuasive R6 Change Request for FHIR-core MeasureReport. It asked to remove Group from the MeasureReport.reporter allowed targets because the DEQM ReporterGroup extension had been incorporated as a first-class reporter target in conflict with earlier guidance that Groups cannot act or take responsibility; the final resolution also concluded that no additionalReporter extension was needed in core.

Initial application:
The issue was applied by commit c6487923f555ea1723187bdb34ed052de50ae9d6, which removed the Group targetProfile from MeasureReport.reporter in source/measurereport/structuredefinition-MeasureReport.xml. The current source still has that correction: reporter targets only Practitioner, PractitionerRole, and Organization.

Additional context:
FHIR-15913 had already established the same no-Group rule in STU3, but commit 23790863f5a700c65612543f4cd24f1d7fea2b30 reintroduced Group while incorporating DEQM MeasureReport extensions as R5 first-class elements. FHIR-31686 recorded a temporary No Change rationale while Group was present in R5, but FHIR-38002 later revisited the provider-group use cases and resolved that Organization and PractitionerRole can cover them, with any illustrative example belonging in DEQM rather than core. MeasureReport is active in the current build through source/fhir.ini.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative StructureDefinition already reflects FHIR-38002, and no current core source surface was found that still presents Group as a valid MeasureReport.reporter target.

Recommendation:
Keep this audit commit as-is. No further core source action is indicated for FHIR-38002; follow-up examples for accountable provider-group reporting, if still needed, belong in the DEQM IG issue trail rather than in FHIR core.
