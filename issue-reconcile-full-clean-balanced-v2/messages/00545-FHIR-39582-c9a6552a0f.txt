FHIR-39582: Audit rendered dosage markdown application

Issue request:
FHIR-39582 was Published with a Persuasive resolution for R5 Pharmacy content. It asked whether MedicationRequest.dose.renderedDosageInstruction could contain more than one paragraph and therefore should use the markdown datatype; the accepted resolution was to update the element to markdown.

Initial application:
The issue was applied before this reconciliation by git commit 2b88d1c62bc99724e079a33de0d9f92d4b0e4f86, which explicitly mentions FHIR-39582 and changed MedicationRequest.renderedDosageInstruction from string to markdown. That commit also bundled unrelated FHIR-39142 MedicationRequest wording edits.

Additional context:
Current source no longer has a standalone MedicationRequest.renderedDosageInstruction element. R6 dosage redesign work moved medication-resource rendered dosage text into the active DosageDetails datatype as renderedInstruction, and the current MedicationRequest.dosageInstruction element is typed as DosageDetails. DosageDetails is an active normative datatype in source/fhir.ini, and its spreadsheet source defines DosageDetails.renderedInstruction as markdown. A later already-published FHIR-54014 reconciliation on the combined branch made related renderedInstruction narrative wording consistent with the 1..1 DosageDetails requirement; it did not reverse the markdown datatype.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative source already preserves the FHIR-39582 intent: MedicationRequest dosage instructions use DosageDetails, and the renderedInstruction text field that replaced renderedDosageInstruction is markdown.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-39582 unless a separate R5-to-R6 migration-map issue asks to adjust the historical renderedDosageInstruction mapping entry.
