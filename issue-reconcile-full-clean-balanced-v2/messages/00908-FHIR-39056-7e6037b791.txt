FHIR-39056: Audit required code binding wording

Issue request:
FHIR-39056 was Published/Persuasive with Modification for R5. It reported that terminologies.html said required binding strength SHALL be used for elements with type code, while some code-typed elements and IG uses were not required-bound. The final resolution kept the SHALL expectation but added the context-free maximum additional binding exception, required FHIR-I approval for other exception patterns, and noted a separate IG Publisher tooling issue.

Initial application:
Commit d917880aaa first changed source/terminologies.html and added an ElementDefinition invariant for the code-binding rule. Jira was then reopened because that was not what could actually be applied; the FHIR-I Zulip thread records that the invariant caused hundreds of validation errors and was too hard for corner cases. Commit f685fbdd61 applied the durable prose-only form with the FHIR-I exception rule.

Additional context:
source/fhir.ini actively maps resourceType to the terminologies page, so source/terminologies.html is in current build scope. The current source retains the maximum-additional-binding exception and the FHIR-I approval rule. Later Applied R6 work for FHIR-46626 intentionally added that a context-free maximum additional binding is strongly discouraged as of R6, which refines but does not contradict FHIR-39056.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current wording no longer has the misleading absolute rule from the ballot comment: it allows the specified context-free maximum additional binding exception and requires FHIR-I approval for other patterns. Restoring the exact phrase "In most cases" would be redundant and could obscure the later R6 qualifier.

Recommendation:
Keep this no-change audit commit as-is. Future changes should be made only for a new FHIR-I/Vocab decision that documents additional exception patterns or changes the R6 maximum-additional-binding guidance.
