FHIR-5866: Audit split Resource meta operations

Issue request:
FHIR-5866 was a Published/Persuasive DSTU1 FHIR-core change request asking to split the error-prone $meta-change operation into separate add and delete operations. The resolution was "split them as requested (already applied)", approved in the 2015-03-19 MnM/FHIR block vote.

Initial application:
The split appears to have been applied before final Jira publication by git commit 04d21fe50138366eeb15ad127e26199e27449b6e, which changed source/resource/resource-spreadsheet.xml from meta-change to meta-add, removed the mode parameter, and added a separate meta-delete operation. No commit explicitly mentioning FHIR-5866 was found.

Additional context:
Resource is active current-build infrastructure content in source/fhir.ini, and the current Resource operation list contains validate, convert, and graphql only. Current core source has no active $meta-change operation and no active core OperationDefinition for Resource.$meta-add or Resource.$meta-delete because the R6 operation cleanup removed those core definitions; ballot-intro.html now lists Resource.$meta, Resource.$meta-add, and Resource.$meta-delete as artifacts moved to the API Incubator. Checked-in release history bundles for DSTU2 through R5 contain Resource-meta-add and Resource-meta-delete and no meta-change. Related no-change Jira FHIR-5867 explicitly said its mode-code concern might be unnecessary if FHIR-5866 split the operation.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core source does not expose the old combined $meta-change operation, the split operation names are preserved in historical release artifacts and in the current moved-artifact note, and restoring current core OperationDefinitions would conflict with the later R6 move out of core.

Recommendation:
Keep this audit commit as-is for FHIR-5866. Separate current-R6 work, if any, should be handled by the API Incubator or by the unresolved/current meta-operation link issues rather than by reintroducing $meta operation definitions into core for this historical split issue.
