FHIR-12748: Audit Provenance entity identifier support

Issue request:
FHIR-12748 was a Published/Persuasive Security change request raised and applied for DSTU2 asking to add Identifier to Provenance.entity so source material that is not a FHIR Resource can be identified.

Initial application:
The request was applied historically in commit 8058a0886c12cc7a61a61db3edae51be5e5698ef, which explicitly cites GF#12748 and changed the old Provenance.entity.reference model into Provenance.entity.what[x] with uri|Reference(Any)|Identifier choices, updated examples to use whatIdentifier, and added an entity-id token search path.

Additional context:
Later final issues changed how the same requirement is represented. FHIR-13694 clarified that Reference.identifier supports logical references for business concepts that can potentially be expressed as FHIR resources even when no actual FHIR instance exists. FHIR-13570 aligned Provenance with that Reference.identifier guidance, and FHIR-15659 then removed redundant Provenance Identifier|Reference choices after logical references made them unnecessary. FHIR-49893 later corrected the current Provenance.entity.what comment to say what.identifier. The combined branch already contains AutoFHIR audit commits for FHIR-13570 and FHIR-15659, so those related issues are not being republished here.

AutoFHIR reconciliation:
Made no source change. Provenance is active in the current build, source/provenance/structuredefinition-Provenance.xml defines Provenance.entity.what as a Reference(Any), and its comment says that what.identifier SHOULD be used for entities that are not a Resource type. The Reference datatype source defines Reference.identifier as Identifier and includes the logical-reference guidance that covers non-instantiated source material. Reintroducing a separate Provenance.entity Identifier choice would reverse later applied decisions rather than complete FHIR-12748.

Recommendation:
Keep this empty audit commit. The current specification satisfies the DSTU2 request through Reference.identifier; any future change should be a new targeted Provenance or Reference issue, not a reapplication of the retired choice-element model.
