FHIR-3123: Audit CarePlan participant role binding

Issue request:
FHIR-3123 is Published/Persuasive for FHIR-core CarePlan. It asked for a value set for CarePlan.participant.role because the role element was unconstrained, and the accepted resolution said Rob would produce a value set.

Initial application:
The Jira comment cites SVN #6813. Git commit 45a51719e6c526a6bf7df614e1b9f7d5f8c3b4bf is the imported SVN 6813 commit and changed the CarePlanParticipantRole binding from unbound to an example value-set binding while adding source/careplan/valueset-participant-role.xml.

Additional context:
FHIR-9765 later replaced CarePlan.participant with CarePlan.careTeam referencing CareTeam. The active successor element, CareTeam.participant.role, retains an example binding to http://hl7.org/fhir/ValueSet/participant-role. FHIR-6212 is the same binding-change family and explicitly referred to FHIR-3123 in its resolution.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source no longer has an active CarePlan.participant.role element, but the role binding survives on the current CareTeam participant-role element used by CarePlan.careTeam.

Recommendation:
Keep this no-change audit. Do not re-add participant-role binding text to CarePlan itself unless the Patient Care work group reverses the CarePlan.careTeam modeling decision.
