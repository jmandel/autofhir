FHIR-15946: Audit DeviceRequest intent type

Issue request:
FHIR-15946 was a Published/Persuasive OO change request asking to change DeviceRequest.intent from CodeableConcept to code because request intent uses a fixed request-intent vocabulary and parallel request resources already used code.

Initial application:
No commit explicitly mentioning FHIR-15946 or GF#15946 was found in the current local git history. The current build-source layout introduced DeviceRequest.intent already typed as code in c69d71a and the later source rework 33b409a preserved that datatype with the request-intent binding.

Additional context:
DeviceUseRequest became DeviceRequest, and DeviceRequest is an active current-build resource in source/fhir.ini. The OO block-vote minutes and matching Zulip block-vote notice list FHIR-15946 as Persuasive. Same-family FHIR-15954 for ServiceRequest.intent and same-element FHIR-19563 for the DeviceRequest.intent binding URL are already represented on the combined branch, and neither changes the DeviceRequest datatype conclusion.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The active DeviceRequest StructureDefinition already defines DeviceRequest.intent as a primitive code with required binding to http://hl7.org/fhir/ValueSet/request-intent, which satisfies the Jira request.

Recommendation:
Keep this no-change audit as-is. No follow-up is needed for FHIR-15946 unless future work changes DeviceRequest.intent away from code or weakens/removes its request-intent binding.
