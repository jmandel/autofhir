FHIR-22702: Audit search operation ordering

Issue request:
FHIR-22702 was a Published/Persuasive FHIR-I clarification request for R5 asking the Search page to make search parameter order of operations explicit: URL parameter order does not drive processing, except that repeated _sort order matters; filters are applied first, then sorting, then paging, and then _include/_revinclude resources are returned for each page.

Initial application:
The requested clarification was applied in PR https://github.com/HL7/fhir/pull/1282 by commit 142ad7624ca77d81a9463a6ddbd278f521a109da, which inserted the order-of-operations paragraph in source/search.html. The same PR also carried neighboring search clarifications such as FHIR-19523 and FHIR-31401, but FHIR-22702's requested ordering text was independently present in that patch.

Additional context:
The current active search source, source/search.html, still says that URL order does not drive operations except sort, then states filters, sorting, paging, and included resources in that sequence. The SearchParameter registry page is only the parameter list and points readers back to search.html for search behavior, so duplicating the rule there is unnecessary. Later search/count clarifications, including the current _count text that applies _count only to entry.search.mode = match and excludes included resources and OperationOutcome entries, are consistent with FHIR-22702 rather than superseding it. The origin Zulip thread matches the Jira description, and no Confluence references or conflicting minutes were found.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source files were changed because the current source already conveys the final FHIR-22702 rule in the authoritative search narrative and the related registry page does not need independent wording.

Recommendation:
Keep this audit commit as-is. Future search-result pagination work can clarify _count/include edge cases if needed, but FHIR-22702 itself is already correctly represented in the current specification.
