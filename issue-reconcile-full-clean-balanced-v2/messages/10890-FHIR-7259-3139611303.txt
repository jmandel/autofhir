FHIR-7259: Audit modifier-extension OperationOutcome example

Issue request:
FHIR-7259 was a Published/Persuasive FHIR-core extensibility issue from the DSTU1 ballot asking that the modifier-extension guidance that told systems to refuse to process data specify the error code and any OperationOutcome recommendations. The recorded resolution was to add an example, and the Jira follow-up comment says this was already done.

Initial application:
No git commit explicitly mentioning FHIR-7259 was found. The same modifier-extension section was updated one day before the FHIR-7259 "already done" comment by git commit b58cc25916bd7787982d82331cb5654a4b7bc305 / svn revision 6392, whose message references #6850 and adds an example that a server could return HTTP 422 with an OperationOutcome when a client PUTs or POSTs an unknown modifier extension.

Additional context:
FHIR-6850 is the same change family and directly requested clarification of the HTTP response for create/update when a modifier extension is detected; its Jira comments cite svn revision 6392. Later FHIR-18353 refined the old "refuse to process" wording so the current page distinguishes processing resource data from simply storing or moving resources, but it retained rejection as one valid handling path. source/fhir.ini maps the Extension type page to extensibility, so source/extensibility.html is in the current build scope.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current source/extensibility.html still includes the relevant example: implementations may reject unknown modifier extensions, and a server could return HTTP 422 with an OperationOutcome when a client PUTs or POSTs one. Adding a specific OperationOutcome.issue code now would go beyond the Jira resolution and the historical applied change.

Recommendation:
Keep this no-change audit. If the work group wants a specific OperationOutcome.issue.code for this scenario, that should be handled as a new decision rather than inferred from this DSTU1 issue.
