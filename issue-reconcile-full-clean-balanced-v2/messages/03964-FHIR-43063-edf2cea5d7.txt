FHIR-43063: Audit Device UDI identifier system

Issue request:
FHIR-43063 was Applied with a Persuasive with Modification resolution for the OO Device artifact. It asked to clarify that the UDI issuer and the naming system for the device identifier are not the same, and the approved change was to add Device.udiCarrier.deviceIdentifierSystem 0..1 uri with short text "The namespace for the device identifier value" and a long definition identifying the namespace for the device identifier value.

Initial application:
The issue was applied in git commit 3798821db4, which added Device.udiCarrier.deviceIdentifierSystem to source/device/structuredefinition-Device.xml as a 0..1 uri with the approved short text and initial long definition. The element is also listed in source/fhir.ini in the active R5-to-R6 changes section, confirming the Device source is in current build scope.

Additional context:
The originating Zulip thread and OO minutes show the problem was the distinction between issuing organizations such as GS1 and identifier namespaces such as GTIN. Later Applied issue FHIR-47419 refined the same Device UDI wording and added parallel DeviceDefinition deviceIdentifierSystem elements; it changed the long definition to "Establishes the namespace for the issuing agency's system (e.g, GS1's GTIN, ICCBBA's ISBT-128) used to create the device identifier." FHIR-47419 is already represented on the combined branch, so this reconciliation does not duplicate that decision.
