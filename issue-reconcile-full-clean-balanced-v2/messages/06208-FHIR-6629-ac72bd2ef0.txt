FHIR-6629: Audit common coding system URI handling

Issue request:
FHIR-6629 is a Published/Persuasive Vocabulary change request for the DSTU1 Code Systems page. It asked FHIR core to define system URIs for several common external coding systems: WHO ICF, national ICD-10 variants for the US/Germany/Netherlands, and Dutch ICPC-1, with associated OID information where known.

Initial application:
Historical git-svn commit e2e7b1ea09020c8286800fc4fc62451eb5df21e7 applied FHIR-6629 together with FHIR-7521 in svn revision 6372. It added explicit rows in source/terminologies-systems.html for ICD-10 variants, ICPC-1/ICPC-1-NL/ICPC-2, and ICF-NL, plus a note that multiple listed systems identify distinct code systems. Later ICD-specific commits moved the ICD details to a dedicated ICD page and corrected individual variant details.

Additional context:
FHIR-37853 later made HL7 Terminology (THO) the source of truth for external terminology identifiers, changed the core Code Systems preamble to say only FHIR-defined code system URIs are authoritative in core, and deleted external rows lacking a "Using X with FHIR" page, including the old ICPC and ICF rows from FHIR-6629. Current source/terminologies-systems.html is active in the build and points readers to THO's External Code Systems page for authoritative external URI/OID information. Subsequent ICF work in FHIR-37402, HTA-89, and UP-335 also split the international ICF identifier from the older Dutch translation identifier, confirming that re-adding the original ICF-NL row and OID text to core would be stale.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The current core specification already reflects the later approved policy: core lists only a small subset of external systems with FHIR-specific usage pages and delegates other external code system URI/OID records to THO. Re-adding FHIR-6629's old explicit external rows to core would conflict with FHIR-37853 and risk reintroducing stale variant details.

Recommendation:
Keep this audit commit as-is. If implementers still need missing or revised individual external terminology records, such as an old national ICD-10 variant URI or ICPC-1-NL identifier, that follow-up belongs in THO/UTG or TSMG review rather than in FHIR core source.
