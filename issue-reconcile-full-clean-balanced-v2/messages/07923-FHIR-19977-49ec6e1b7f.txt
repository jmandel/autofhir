FHIR-19977: Audit OperationOutcome external failure code

Issue request:
FHIR-19977 is Published/Persuasive for R5. It asked FHIR core to add an OperationOutcome code for unresolved external references, specifically a code such as MSG_EXTERNAL_FAIL alongside the existing MSG_LOCAL_FAIL.

Initial application:
The issue was first applied in upstream commit 69f783bf72ce8ed0be2268fefae6307148dbe756, which added an OperationOutcome terminology binding row and a new MSG_REMOTE_FAIL entry in implementations/translations.xml. A later upstream repair commit, 54c96b26b2a89805739101a5f23a6da64c576b8f, generated duplicate core source/terminologies OperationOutcome CodeSystem and ValueSet files from that state. Those core artifacts used MSG_REMOTE_FAIL and did not carry the requested MSG_EXTERNAL_FAIL spelling, so the historical core application was not the final source of truth for the requested code.

Additional context:
UTG proposal UP-299 implemented the FHIR-19977 request in http://terminology.hl7.org/CodeSystem/operation-outcome with the requested MSG_EXTERNAL_FAIL code. In the #committers Zulip thread FHIR-19977, Alexander Zautke reported that the R5 fix had been applied to UTG, and Grahame Grieve said THO should be used and the duplicate core CodeSystem deleted for R6. FHIR-41668 then formalized that later change and was applied by upstream commit 6f6c22d0efabe54f0f7abac122cf9fdb62f8d055, which removed the core OperationOutcome binding row and deleted the duplicate source/terminologies operation-outcome CodeSystem and ValueSet. The current core source keeps OperationOutcome.issue.code bound to the separate IssueType value set, and the remaining core source reference to the THO operation-outcome CodeSystem is an AuditEvent example ValueSet include. The downloadable implementations/translations.xml file still contains the historical MSG_REMOTE_FAIL message key, but it no longer defines the OperationOutcome CodeSystem and should not be treated as the current core terminology source of truth.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current FHIR core no longer owns or publishes the duplicate operation-outcome CodeSystem/ValueSet, and the active THO CodeSystem contains MSG_EXTERNAL_FAIL with the external-reference display requested by FHIR-19977.

Recommendation:
Keep this audit commit as-is. No current FHIR-core source edit is needed for FHIR-19977. Any future cleanup of downloadable tooling translation messages should be handled separately with the tooling/terminology owners, not as a core OperationOutcome CodeSystem fix.
