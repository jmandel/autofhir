FHIR-32549: Audit ConceptMap dependency valueSet support

Issue request:
FHIR-32549 was Published/Persuasive with Modification for R5 and asked whether a ConceptMap target dependency can depend on membership in a value set rather than only on a fixed value. The approved resolution added ConceptMap.group.element.target.dependsOn.valueSet as canonical(ValueSet) 0..1, relaxed dependsOn.value[x] to 0..1, and required exactly one of value[x] or valueSet; because product reuses the same backbone, the resolution also affects product.

Initial application:
The Jira comments identify applied commits 14f645013c, e2bf9a5e7c, and fda3bd7c99. Those commits made the requested changes in the then-current ConceptMap2 source, corrected the valueSet descriptions, and tightened cmd-6 from at-least-one to exactly-one.

Additional context:
ConceptMap2 was later folded back into the active ConceptMap resource, and later ConceptMap cleanup commits carried the valueSet support and wording into source/conceptmap/structuredefinition-ConceptMap.xml. ConceptMap is an active resource in source/fhir.ini. Current source also includes invariant tests for the two cmd-6 failure cases, and FHIR-33032 has already been reconciled on the combined branch for the related id type addition.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active ConceptMap source already has dependsOn.value[x] at 0..1, dependsOn.valueSet as canonical(ValueSet) 0..1, cmd-6 enforcing exactly one of value[x] or valueSet, and product inheriting that same structure through contentReference.

Recommendation:
Keep this audit commit as-is. No additional core source edit is needed for FHIR-32549; any broader explanatory examples or simple/complex profiles mentioned during the discussion belong to separate ConceptMap documentation/profile tickets rather than this applied structural change.
