FHIR-49675: Correct ImagingStudy accession example

Issue request:
FHIR-49675 was Applied/Persuasive with Modification for R6. It asked ImagingStudy to stop treating the accession number as an ImagingStudy.identifier and instead describe accession numbers on ImagingStudy.basedOn by using Reference.identifier with identifier.type ACSN; the final resolution also updated the based-on and identifier search-parameter descriptions.

Initial application:
Commit 1386be9f55 applied the issue to ImagingStudy source by removing accession-number language from ImagingStudy.identifier, adding accession-number requirements and aliasing to ImagingStudy.basedOn, moving search-parameter descriptions, and changing the narrative accession-number example. That application restored the intended basedOn location, but the narrative example reintroduced an extra "reference" object level that had previously been corrected by FHIR-41484.

Additional context:
FHIR-48644 is the earlier applied decision that placed accession number on ImagingStudy.identifier, and FHIR-49675 reversed that location after identifier-scope discussion in FHIR-48692. FHIR-56033 later removed another remaining ImagingStudy.identifier accession-number comment, so the current resource definition is consistent with keeping accession numbers off ImagingStudy.identifier. FHIR-41484 is tightly related because it specifically corrected the same invalid extra "reference" wrapper in the basedOn accession-number example.

AutoFHIR reconciliation:
This commit updates the active ImagingStudy narrative source so the accession-number example is a valid Reference object in ImagingStudy.basedOn with identifier.type ACSN and no non-existent reference wrapper. The authoritative resource definition and search parameters already reflect the FHIR-49675 basedOn model, so no other source changes were needed.

Recommendation:
Keep this source fix. It is a narrow correction to the FHIR-49675 application that aligns the example with Reference.identifier and preserves the later ImagingStudy.identifier cleanup; no follow-up core-source work is recommended for this issue.
