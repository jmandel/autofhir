FHIR-22994: Audit AdverseEvent seriousness values

Issue request:
FHIR-22994 was Published/Persuasive with Modification for the Patient Care AdverseEvent resource. It asked to reduce the AdverseEvent.seriousness example value set to only serious and non-serious because the former FDA outcome-style child codes confused seriousness with AdverseEvent.outcome.

Initial application:
The issue appears to have been applied in 2019 by 05acdd8, linked from the Jira issue, which removed the former serious-results-in-death, serious-is-life-threatening, serious-results-in-hospitalization, serious-results-in-disability, serious-is-birth-defect, and serious-requires-prevent-impairment codes from the then-authoritative AdverseEvent spreadsheet and gave serious/non-serious the requested definitions. Later source refactoring moved the current value set into source/adverseevent/valueset-adverse-event-seriousness.xml.

Additional context:
AdverseEvent is active in the current build according to source/fhir.ini. The current AdverseEvent.seriousness element has an example binding to the Adverse Event Seriousness value set, and that value set includes the THO adverse-event-seriousness code system. The current THO CodeSystem contains exactly non-serious and serious with the FHIR-22994 definitions, and current core source has no remaining old FDA outcome-style seriousness codes. Later Patient Care decisions reinforce this interpretation: FHIR-23023 rejected adding overdose/cancer outcome-style codes because FHIR-22994 intentionally kept seriousness focused on serious/non-serious, and FHIR-48544 kept the binding strength as example so IGs can profile or tighten it. Patient Care minutes in 2021 and 2022 similarly distinguish seriousness from outcome and note that results-in-death was intentionally removed by FHIR-22994.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped core source plus the current THO code system already implement the requested two-code value set, preserve the example binding, and keep outcome-specific semantics on AdverseEvent.outcome rather than AdverseEvent.seriousness.

Recommendation:
Keep this no-change audit commit as-is. Core FHIR already reflects the published FHIR-22994 decision; follow-up requests for more specific clinical-research criteria should remain in IG profiles, extensions, or separate terminology work rather than reintroducing outcome-like codes into the core example value set.
