FHIR-12231: Audit Coverage ordering support

Issue request:
FHIR-12231 was a Published/Persuasive with Modification FM change request asking Coverage to support primary, secondary, and tertiary priority with an integer field. The final resolution added a Coverage order element for relative priority and clarified that primary/secondary/etc. for a claim is represented by the actual order of Coverages in the Claim.

Initial application:
Current source contains Coverage.order as a 0..1 positiveInt on the active Coverage resource, with requirements for managing coordination of benefits. Git history did not expose a Jira-keyed FHIR-12231 implementation commit in the current repository, but the element was present when the Coverage StructureDefinition was reworked into the current XML source lineage in 2021.

Additional context:
Later FM issues FHIR-27106, FHIR-27107, and FHIR-43028 revisited how Coverage.order relates to account- or use-case-specific coverage ordering. FHIR-43028 is already represented on the combined branch and the current source now states that Coverage.order conveys COB ordering independent of use-case, while use-case-dependent ordering belongs in Account.coverage.priority. Claim.insurance.sequence still provides the ordered claim-level list referenced by the original FHIR-12231 resolution.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active Coverage source already has the requested order element, the Claim source has the claim-level ordering surface, and later applied clarifications preserve the original distinction without requiring additional edits for FHIR-12231.

Recommendation:
Keep this audit commit as-is. Any further changes to Coverage.order versus Account.coverage.priority should be handled through the later clarification issues, which are already represented separately on the combined branch.
