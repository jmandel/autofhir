FHIR-8741: Audit date search documentation correction

Issue request:
FHIR-8741 was a Published/Persuasive technical correction against the FHIR-core search page. It reported an incorrect date parameter format, proposing ISO-style timezone syntax, and questioned the sample [parameter]=ge2013-03-14 description that mentioned a period "from 21-Jan 2013 onwards".

Initial application:
The issue was applied in svn revision 7197, represented in Git as 9ddb75f06e78299173119e7355e1513dea759b23. That commit changed the old yyyy-mm-ddThh:nn:ss(TZ) pattern to yyyy-mm-ddThh:mm:ss[Z|(+|-)hh:mm] and clarified the example wording while intentionally leaving the yyyy-mm-dd date pattern and the "from 21-Jan 2013 onwards" example in place.

Additional context:
Current source/search.html remains the active search documentation source linked from the documentation index. Its prefix table defines ge as overlap between the resource value and the range from the parameter value to +infinity, and the date examples still explain that an open-ended period starting 21-Jan 2013 may include times after 14-Mar 2013. FHIR-12414 later expanded the same date-prefix examples and preserved this interpretation. A 2024 Zulip implementers thread asked whether the example was a typo; Lloyd McKenzie confirmed that an event starting 21-Jan 2013 with no end is ongoing and should match ge2013-03-14, while a point-in-time birthDate of 2013-01-21 would not.

AutoFHIR reconciliation:
This audit commit makes no source change. The date/time typo reported by FHIR-8741 has been corrected, and the remaining 21-Jan example is semantically correct for an open-ended period under the current ge definition rather than a current-spec typo.

Recommendation:
Keep this no-change audit commit. Do not replace the 21-Jan open-ended period example with 14-Mar; that would remove the distinction the example is meant to illustrate. If future readers continue to find the example confusing, a separate editorial issue could add an explicit contrast with point-in-time date values, but FHIR-8741 itself is already correctly applied.
