FHIR-34450: Audit ValueSet experimental metadata

Issue request:
FHIR-34450 is a Published/Persuasive FHIR-core technical correction raised against R4B and applied for R5. It reported many ValueSet examples in the R4B examples download asserting http://hl7.org/fhir/StructureDefinition/shareablevalueset while missing the profile-required ValueSet.experimental element, and resolved that tooling should set experimental to true for examples and false for non-examples unless already declared.

Initial application:
The issue was applied in tooling rather than by a core source commit. Jira records that the fix was pre-applied in R4B and R5, then notes additional fixes in HL7/kindling#69. That merged Kindling change explicitly cites FHIR-34450 and added canonical-resource processing that sets experimental from example status, warns when an existing value disagrees, and calls the fix for ValueSet examples before serialization.

Additional context:
FHIR-37449 was opened by the same reporter as a follow-up for remaining shareable metadata gaps and is already represented on the combined branch. Later ValueSet/shareable-profile decisions also affect the current source: FHIR-29943 and FHIR-31395 revised the R5 ValueSet profile family, FHIR-38672 and FHIR-39143 kept experimental required where ShareableValueSet was imposed, and FHIR-37959 later moved the Shareable/Publishable/Computable/Executable profile family out of core for CRMI maintenance. In the current core build inputs, source/fhir.ini has no active ShareableValueSet profile entry, ValueSet-core has no profile definitions, and no XML ValueSet asserts the shareablevalueset profile. A current source scan found 21 ValueSet XML files without explicit experimental, but none asserts ShareableValueSet; current build.fhir.org output for spot-checked missing-source cases includes experimental=false, consistent with the FHIR-34450 tooling rule.

AutoFHIR reconciliation:
This is an empty audit commit. No core source change is needed for FHIR-34450 because the original reported class of invalid examples is no longer present in current core source, the generated-output behavior matches the accepted tooling rule, and manually adding experimental to current ValueSet source files that do not assert ShareableValueSet would be redundant and would not address a current conformance defect.

Recommendation:
Keep this audit commit as-is. Do not add experimental elements to current core ValueSet sources solely for FHIR-34450. If a future build again emits a ValueSet that asserts ShareableValueSet without experimental, fix the canonical-resource tooling or the CRMI-maintained profile/application source rather than reintroducing obsolete core profile assumptions.
