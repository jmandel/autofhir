FHIR-16172: Audit Observation supportingInfo application

Issue request:
FHIR-16172 was Published/Persuasive with Modification for Observation.derivedFrom/hasMember. The accepted resolution rejected a new catch-all Observation element and instead asked for a 0..* Reference(Any) supportingInfo extension for other patient-record resources used in creating an Observation, with guidance not to use it when more specific inline relationships such as hasMember or derivedFrom, or extensions such as relatedArtifact, fit better.

Initial application:
No commit explicitly tagged FHIR-16172 was found. The apparent application is the workflow extension work in git commit 633021569c, which added source/profiles/workflow-extensions-spreadsheet.xml with workflow-supportingInfo in Observation context as Reference(Any), using the patient-record definition and the "do not use when a more specific inline element or extension is available" guidance.

Additional context:
Observation remains an active resource in source/fhir.ini. Current Observation source retains the narrower hasMember and derivedFrom relationships and grouping guidance. Core no longer owns the source definition for workflow-supportingInfo because R5 moved standard extensions to the hl7.fhir.uv.extensions package; the Extension Pack source now contains the authoritative workflow-supportingInfo definition with Observation context and the requested Reference(Resource/Any) value. OO community discussion and minutes found during reconciliation treat workflow-supportingInfo as the generic Observation supporting-information relationship and distinguish it from component, hasMember, and derivedFrom. No direct Zulip or Confluence reference to FHIR-16172 was found that changes the Jira/source conclusion.
