FHIR-6246: Flag DiagnosticReport image-selection linkage

Issue request:
FHIR-6246 was a Published/Persuasive with Modification DSTU1 Imaging Integration request to add ImagingObjectSelection as a DiagnosticReport.imagingStudy choice. The decisive comments narrowed the request: DiagnosticReport.imagingStudy should remain the critical link to full DICOM study details, while ImagingObjectSelection could be an alternative for key-image selection, with O&O left to choose the specific mechanism.

Initial application:
The issue was initially applied by ae4866b512efb6620d418a4870b8d2c14ba9984a, which preapplied #6246 by changing the old DiagnosticReport spreadsheet's imagingStudy type from Reference(ImagingStudy) to Reference(ImagingStudy|imagingObjectSelection) and adding the overlap note. The related FHIR-7682 implementation commit 165f27cb02e9a41309bffb199dbf6aa7f36c54f2 added the corresponding DiagnosticReport notes text. Commit 7da3e85d1128fc712018adcaa1883b9d9203cb3d later renamed ImagingObjectSelection to ImagingManifest in the same DiagnosticReport references and comments.

Additional context:
Later source history changed the artifact family enough that a current edit is not a direct application of FHIR-6246. FHIR-14080 removed ImagingManifest from active FHIR-core resources, and current fhir.ini lists both imagingmanifest and ImagingObjectSelection only under removed/dropped resources. FHIR-17183 introduced ImagingSelection as a separate active R5 resource, but did not decide DiagnosticReport references. Current DiagnosticReport.study is Reference(ImagingStudy) only, current DiagnosticReport.media.link is Reference(DocumentReference) only, and current diagnostics module guidance discusses ImagingSelection through Observation imaging profiles. The unresolved FHIR-57389 issue now asks exactly whether baseline DiagnosticReport should directly relate to ImagingSelection, listing media, supportingInfo, and results as possible mechanisms. FHIR-54164 also recently kept DiagnosticReport.study ImagingStudy-only while removing the older study comment.

AutoFHIR reconciliation:
This commit intentionally makes no source change and records a human-review decision. Reintroducing ImagingObjectSelection or ImagingManifest would conflict with current removed-resource decisions, while adding ImagingSelection to DiagnosticReport now would pre-empt the unresolved FHIR-57389 work-group question about whether and where such a relationship belongs.

Recommendation:
Keep this audit commit as human-review. The work group should resolve FHIR-57389 or a successor issue to decide whether DiagnosticReport should directly reference ImagingSelection and, if so, whether the correct mechanism is media, supportingInfo, results, or something else; the eventual implementation should be tracked under that current issue rather than inferred from FHIR-6246 alone.
