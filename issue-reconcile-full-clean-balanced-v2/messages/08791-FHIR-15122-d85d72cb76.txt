FHIR-15122: Audit Resource implicitRules clarity

Issue request:
FHIR-15122 was a Published FHIR-I STU3 change request, resolved Not Persuasive with Modification, asking that Resource.implicitRules be clarified because it looked like metadata only for an associated implementation guide. The accepted resolution was that implicitRules may indicate an implementation guide, but may also indicate a business-context/custom agreement, so the description should be clearer.

Initial application:
The Jira application comment cites SVN revision 13363. In the git-svn history this maps to cf3941f15c410a484846cab676357718699775ff, which changed the then-authoritative source/resource/resource-spreadsheet.xml Resource.implicitRules definition to add that implicitRules is often a reference to an implementation guide defining special rules, and moved the modifier rationale into a separate comment that also explains the IG use case. The later R4B source rework preserved that definition/comment in source/resource/structuredefinition-Resource.xml.

Additional context:
Resource is an active build artifact through source/fhir.ini's [resource-infrastructure] entry. Current source/resource/structuredefinition-Resource.xml says implicitRules is a reference to rules followed when constructing the resource that must be understood when processing it, and says it is often an implementation guide. Current narrative in source/resource/resource-notes.xml and source/overview-dev.html describes it as a custom agreement, with an implementation guide as an example, which preserves the Jira distinction between IGs and broader agreements. FHIR-43016 later added guidance for additional implicitRules policies through the additionalImplicitRules extension without reversing the FHIR-15122 clarification.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The active Resource definition and narrative already convey that implicitRules is not limited to an associated implementation guide and that it represents rules/custom agreements that must be understood for safe processing.

Recommendation:
Keep this no-change audit. No current FHIR-core source correction is needed for FHIR-15122; future editorial cleanup, if any, should avoid narrowing implicitRules back to implementation-guide-only semantics.
