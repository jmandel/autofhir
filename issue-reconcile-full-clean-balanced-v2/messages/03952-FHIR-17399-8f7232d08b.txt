FHIR-17399: Audit Person linking clarification

Issue request:
FHIR-17399 was a Published/Persuasive Patient Administration clarification asking the Person linking narrative to stop saying that the Person link element could not link to RelatedPerson entries, because Person.link can reference RelatedPerson.

Initial application:
The contradictory paragraph was introduced in the older Person notes history and was explicitly replaced by commit baca2ec26671f781bf91a59f6a6279e3a9bfcbe7, "#FHIR-17399 Clarify statement about person linking", merged by 6a22234ecafea0d1b5c5656c4c6a61989f9cceac. A later ballot/STU-note macro cleanup preserved the corrected meaning.

Additional context:
Person is an active current-build resource in source/fhir.ini. The current Person notes now say that prior Patient.link limitations left Person to link RelatedPerson records, that Patient.link has supported RelatedPerson since STU3, and that using Person for this linkage can still be done. The current Person.link.target type includes RelatedPerson, and Patient.link.other also includes RelatedPerson with a comment that this removes the need to use Person in some cases. The originating Zulip thread and PA minutes align with this interpretation and do not identify a later reversal.
