FHIR-18228: Audit ShareableLibrary core disposition

Issue request:
FHIR-18228 was Published/Persuasive for STU3 and asked core FHIR to define a ShareableLibrary profile, analogous to ShareableValueSet, requiring publishing metadata elements url, version, name, title, experimental, description, date, and publisher.

Initial application:
The issue was applied by commit 421cbd47bd ("GF#18228: Added ShareableLibrary profile"), which added source/library/library-shareable-spreadsheet.xml and registered the Shareable Library profile in source/library/library-spreadsheet.xml. Historical R4/R4B/R5 artifacts include StructureDefinition/shareablelibrary, and later converted source retained source/library/structuredefinition-profile-shareablelibrary.xml until the R6 profile-removal work.

Additional context:
The current R6 source no longer contains an active ShareableLibrary profile definition or Library profile pack entry. That absence is intentional: FHIR-48393 was Applied/Persuasive to remove resource profiles from the base specification, explicitly listing ShareableLibrary and related Library profiles as already moved to CRMI or Using CQL With FHIR. Current Clinical Reasoning and Shareable pattern guidance directs applications to CRMI for Shareable, Publishable, Computable, and Executable profiles, and the published CRMI IG contains an active CRMI Shareable Library profile for Library.

AutoFHIR reconciliation:
No source change was made. Recreating StructureDefinition/shareablelibrary in core would reverse the later applied FHIR-48393 decision and conflict with the current build scope, where Library remains active but source/library/list-Library-packs.xml is intentionally empty. The remaining core OID row is historical identifier metadata and does not make the removed profile part of the current build.

Recommendation:
Keep this audit commit as-is. Do not restore the old core ShareableLibrary profile; future maintenance of ShareableLibrary constraints should occur in CRMI unless a new work-group decision explicitly brings the profile family back into core.
