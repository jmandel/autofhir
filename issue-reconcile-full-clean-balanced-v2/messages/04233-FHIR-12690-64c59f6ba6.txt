FHIR-12690: Audit CarePlan activity definition target

Issue request:
FHIR-12690 was a Published/Persuasive Patient Care technical correction asking that CarePlan.activity.detail.definition allow an ActivityDefinition reference as well as PlanDefinition. The request was based on implementer discussion that an inline CarePlan activity definition could appropriately point to either a smaller plan or an ActivityDefinition.

Initial application:
The issue was explicitly applied by git commit 080534600a039a1721ecf27cd415885eeb011f80 on 2017-01-25, whose CarePlan hunk changed CarePlan.activity.detail.definition from Reference(PlanDefinition|Questionnaire) to Reference(PlanDefinition|ActivityDefinition|Questionnaire). No prior missing application remains for the original DSTU/STU CarePlan source.

Additional context:
FHIR-26064 later renamed CarePlan.activity.detail to CarePlan.activity.plannedActivityDetail as part of CarePlan activity workflow alignment, and FHIR-39101 later removed CarePlan.activity.plannedActivityDetail and its children. The latest combined branch already contains reconciliation commits for both FHIR-26064 and FHIR-39101. In the current combined source, CarePlan is active in source/fhir.ini, but the only active CarePlan.activity children are activity, performedActivity, progress, and plannedActivityReference; plannedActivityDetail.instantiatesCanonical appears only inside the commented-out retired block and therefore is not current build behavior.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the original requested target was applied historically and the relevant inline-detail element is no longer active in the current build after later final Patient Care decisions. Re-editing the commented retired plannedActivityDetail block or reintroducing an inline detail target would not be an appropriate current-spec fix for FHIR-12690.

Recommendation:
Keep this audit commit as-is. No FHIR-12690 follow-up is needed unless Patient Care reverses the later removal of CarePlan.activity.plannedActivityDetail or reintroduces an equivalent inline definition element; if that happens, ActivityDefinition should remain an allowed definition target.
