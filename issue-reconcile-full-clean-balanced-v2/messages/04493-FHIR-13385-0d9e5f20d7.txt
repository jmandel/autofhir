FHIR-13385: Audit Timing.repeat.when event timing codes

Issue request:
FHIR-13385 was a Published/Persuasive with Modification STU3 MnM change request asking for Timing.repeat.when to be usable for more approximate day periods. The final resolution did not change the code-typed binding to extensible; it requested the current short/definition, a NOON code, early/late morning/afternoon/evening codes, and definitions saying these periods are vague and determined by institutional convention or patient interpretation.

Initial application:
The change was applied in git commit 7b39e2dc1b7999233017d71b8bc8ab9950775620 (#13385 - enhancements to Timing.repeat.when; svn r12712). That commit updated source/datatypes/timing.xml by changing the Timing.repeat.when short/definition and adding the requested event-timing codes/definitions. The current active datatype source still contains those rows.

Additional context:
source/fhir.ini maps normal datatypes to the current datatypes pages, and Timing is maintained in source/datatypes/timing.xml. Later related no-change decisions FHIR-17283 and FHIR-34124 considered loosening the same required binding and reaffirmed that code-typed Timing.repeat.when cannot safely be made extensible/preferred; missing true timing codes should be proposed individually, and extensions can be used in the meantime. Zulip and Confluence records align with that interpretation.

AutoFHIR reconciliation:
Made no source changes. Current source already carries the FHIR-13385 resolution, including "Code for time period of occurrence", the approximate-time definition, NOON, MORN.early/MORN.late, AFT.early/AFT.late, EVE.early/EVE.late, and vague institutional/patient interpretation wording for the affected codes.

Recommendation:
Keep this empty audit commit as-is. Do not loosen the binding in core for this issue; future requests should identify specific missing true timing codes or use extensions as FHIR-34124 recommends.
