FHIR-15808: Audit canonical terminology extension references

Issue request:
FHIR-15808 was a Published STU3 Vocab change request resolved Persuasive with Modification. It asked that extension value types such as Reference(CodeSystem) and Reference(ValueSet), where the target is an infrastructure or knowledge resource with a canonical url, be represented as canonical(...) rather than Reference(...).

Initial application:
The issue was applied by svn revision 15373, imported as git commit caade7d22f6ac69282b179c5f488a1fa2a799d53 ("GF#15808 - fix canonical in extensions"). That commit changed the historical ValueSet extension spreadsheet rows for valueset-map, valueset-system, and valueset-supplement from Reference(ConceptMap)/Reference(CodeSystem) to canonical(ConceptMap)/canonical(CodeSystem), along with parallel extension spreadsheet cleanups.

Additional context:
The old core ValueSet extension spreadsheet is no longer active in the current core build, and source/fhir.ini now lists active core extension/profile spreadsheets without a ValueSet-specific extension spreadsheet. The valueset-supplement extension now lives in the FHIR Extension Pack, where its current StructureDefinition value[x] type is canonical with targetProfile CodeSystem and later FHIR-40761 context additions are also present. Current core structured XML still has two Reference(ValueSet) resource elements on EvidenceVariable, but those are resource elements rather than extension definitions and are outside the Jira resolution scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current core extension spreadsheets do not contain Reference(CodeSystem), Reference(ValueSet), or Reference(ConceptMap), and the moved valueset-supplement definition is already canonical(CodeSystem) in the Extension Pack.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-15808; future changes to valueset-supplement context or behavior should be handled in the FHIR Extension Pack, where the related FHIR-40761 work is already reflected in current source.
