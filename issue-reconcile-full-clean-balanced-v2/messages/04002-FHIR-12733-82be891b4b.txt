FHIR-12733 was a Published FHIR-core Pharmacy change request with resolution Persuasive with Modification. It requested an Encounter search parameter after San Antonio Connectathon discussion, and the final resolution was to add a context search parameter to MedicationStatement and MedicationDispense.

Initial application:
The Jira comments point to git-svn commit 491a59353e4244177fb0b6cd8a2de31e46f7f448 / SVN r11158. That bundled several pharmacy tracker updates and specifically added reference search rows named context for MedicationDispense.context and MedicationStatement.context, satisfying the DSTU2-era element names.

Additional context:
MedicationStatement and MedicationDispense are active resources in source/fhir.ini. The current source has since renamed those context elements to encounter, with source/fhir.ini mapping MedicationDispense.context to MedicationDispense.encounter and MedicationStatement.context to MedicationStatement.encounter. The current StructureDefinition sources define both encounter elements as Encounter references, and the current search parameter bundles define MedicationDispense-encounter and MedicationStatement-encounter reference SearchParameters over those paths.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The requested search behavior is already present in the current build under the current element/search code name, so reintroducing a context-named search parameter would be redundant and inconsistent with the current resource model.

Recommendation:
Keep this no-change audit commit as-is. If a work group wants historical context aliases for compatibility, that should be raised and evaluated as a separate current-version search parameter policy issue rather than as a missing application of FHIR-12733.
