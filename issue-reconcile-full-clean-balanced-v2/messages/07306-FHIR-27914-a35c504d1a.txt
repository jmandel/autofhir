FHIR-27914: Audit minValue/maxValue extension types

Issue request:
FHIR-27914 was a Published FHIR-core change request resolved Persuasive with Modification for R5. It asked to resolve inconsistent value types between the minValue and maxValue Questionnaire.item extensions: add Quantity to both because Questionnaire.item supports Quantity, keep instant/positiveInt/unsignedInt/integer64 out of the extensions, and remove instant from maxValue.

Initial application:
The request was applied by HL7/fhir commit 115e85b1ea (merged by PR #1328), which updated source/profiles/element-extensions-spreadsheet.xml so minValue and maxValue both used date|dateTime|time|decimal|integer|Quantity, adding Quantity to minValue and replacing maxValue's instant with Quantity. That same PR also carried unrelated FHIR-32524 Questionnaire wording.

Additional context:
FHIR-14016 had already removed instant from minValue because Questionnaire.item does not allow instant. The FHIR-I 2020-11-16 minutes record the FHIR-27914 vote and the same scope: Questionnaire.item supports Quantity but not instant, add Quantity to both extensions, and remove instant from maxValue. Current core no longer carries these extension definitions in the active element-extensions spreadsheet after dd468d4f17 moved R5 extension definitions out of core; the definitions now live in the FHIR Extension Pack.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative Extension Pack files input/definitions/Questionnaire/StructureDefinition-minValue.xml and StructureDefinition-maxValue.xml both constrain Extension.value[x] to date, dateTime, time, decimal, integer, and Quantity, with no instant, positiveInt, unsignedInt, or integer64. The active core element-extensions spreadsheet contains no minValue/maxValue rows to correct.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed for FHIR-27914; do not reintroduce duplicate core definitions, and no Extension Pack follow-up is needed for the value type list unless a later work-group decision changes Questionnaire.item's supported answer types.
