FHIR-32533: Align Composition title prose with optional cardinality

Issue request:
FHIR-32533 was Applied with a Persuasive with Modification resolution for core Composition. The issue requested that Composition.type, Composition.date, Composition.author, and Composition.title not be mandatory for every Composition use case; the final resolution loosened author and title to optional while retaining type and date as required.

Initial application:
Commit 160c286be6540041b2468bd7b618fc7c4e907297 applied the cardinality part of the decision by changing Composition.author from 1..* to 0..* and Composition.title from 1..1 to 0..1 in source/composition/structuredefinition-Composition.xml. That commit did not update the existing Composition.title comment or the Composition notes page, both of which still described title as mandatory.

Additional context:
source/fhir.ini has an active composition=Composition resource entry, so files under source/composition are in the current build scope. Later unresolved ballot comments FHIR-54115 and FHIR-54510 independently observed that the Composition.title comment still conflicts with the now-optional cardinality, but they are Triaged/Submitted and are cited only as background, not decided here. Earlier FHIR-7073 explains why the mandatory-title text was originally introduced for document-profile feedback, which FHIR-32533 now supersedes for the base resource.

AutoFHIR reconciliation:
This commit keeps Composition.type and Composition.date mandatory, preserves the already-applied optional cardinalities for author and title, updates the Composition.title comment to say profiles can require title while base Composition leaves it optional, and removes the obsolete Composition notes bullet that said title was mandatory during trial use.

Recommendation:
Keep this commit as-is. It completes the applied FHIR-32533 source change without deciding the later unresolved ballot comments; those can be closed by the work group if this reconciliation satisfies them.
