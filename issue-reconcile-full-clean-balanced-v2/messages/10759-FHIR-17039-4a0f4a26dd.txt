FHIR-17039: Audit Bundle fullUrl URI wording

Issue request:
FHIR-17039 was a Published/Persuasive STU3 FHIR-core Feed correction asking to fix the comma in the Bundle.entry.fullUrl short text and avoid implying support for bare UUID/OID values; its proposed wording was "server address or UUID-based URI" and its Jira comment records svn 14392 as the application.

Initial application:
The issue was applied in git commit 7a29b021806db7f982d4826c8f6ddd8b421600fb, which changed the Bundle spreadsheet short description from "URI for resource (Absolute URL server address or UUID/OID)" to "URI for resource (Absolute URL server address or URI for UUID/OID)". That implementation did not remove OID, but it did clarify that UUID/OID forms are URIs rather than bare identifiers. The later build-source migration carried the wording into source/bundle/structuredefinition-Bundle.xml.

Additional context:
FHIR-16909 had just aligned the same element on URI language. Later R5 work is decisive for the current build: FHIR-31422 was Published/Persuasive with Modification and explicitly resolved that Bundle.entry.fullUrl can be an arbitrary URI, not limited to urn:uuid, urn:oid, http, and https, while adding "e.g." to the short description so UUID/OID are examples rather than restrictions. The current Bundle resource is active in source/fhir.ini, and the current source contains both the example short text and the arbitrary-URI definition. Confluence minutes show the 2021 debate over whether fullUrl was limited to HTTP/URN and record the FHIR-31422 vote; a related WGM note said a future ticket might remove OID from the short description, but no such final Jira decision was found and FHIR-31422 later resolved the ambiguity by retaining OID as one example.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is made because removing OID from the current Bundle.entry.fullUrl short text would conflict with the later published arbitrary-URI clarification, and the current wording no longer implies bare UUID/OID values.

Recommendation:
Keep this audit commit as-is. If the work group wants the short description to stop naming OID even as a non-exclusive example, that should be handled by a new current-scope Jira because the existing later decision supports the current source.
