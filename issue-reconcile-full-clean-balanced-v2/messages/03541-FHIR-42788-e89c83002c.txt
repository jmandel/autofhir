FHIR-42788: Audit Quantity UCUM annotation invariant

Issue request:
FHIR-42788 was an Applied/Persuasive FHIR-I change request, raised in R5 and applied for R6, asking FHIR core to document the IG Publisher warning that UCUM codes with human-readable annotations such as {Z-Score} can be misleading and should instead use Quantity.unit for human-readable text. The requester also asked for invariant tests.

Initial application:
The issue was applied before this reconciliation by git commit 744e8befa99ad87fd2853b7612a0eb6b082b8bb5, which added a Quantity invariant row with best-practice severity to source/datatypes/quantity.xml and added source/observation/invariant-tests/qty-4.f1.fail.xml with an annotated UCUM code example.

Additional context:
FHIR-I minutes from 2024-03-18 record the motion to accept the request to explicitly put the IG Publisher warning into the specification. The origin Zulip discussion confirms the warning came from earlier committee discussion and clarifies the intended guidance: UCUM annotations are legal but can be mistaken as meaningful, while FHIR already has Quantity.unit for human-readable unit text. FHIR-33063 is a same-family Vocab issue about UCUM curly-brace guidance that is already represented on the combined branch; it does not require a duplicate decision here.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. source/fhir.ini lists Quantity as an active normative datatype, and current source/datatypes/quantity.xml already contains qty-4 with best-practice severity, the requested FHIRPath expression on Quantity.code, and the requested explanatory warning. The current build output also renders the guideline and the best-practice explanation. Adding more prose would be redundant and could create maintenance drift.

Recommendation:
Keep this no-change audit as-is. The current core source already implements the accepted FHIR-I request in the authoritative Quantity datatype spreadsheet and includes a negative invariant test fixture; future changes should occur only if FHIR-I revisits the UCUM annotation policy or wants a broader test-suite convention change.
