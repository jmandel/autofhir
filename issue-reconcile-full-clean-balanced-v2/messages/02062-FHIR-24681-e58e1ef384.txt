FHIR-24681: Audit AdverseEvent occurrence rename

Issue request:
FHIR-24681 was Published with a Persuasive with Modification resolution for R5. It requested renaming AdverseEvent.date to occurrence and supporting a choice of dateTime, Period, and Timing to align AdverseEvent with the workflow Event.occurrence[x] pattern.

Initial application:
The Jira comments identify PR #694 commits af7e02d and f430558. Commit af7e02d renamed AdverseEvent.date to AdverseEvent.occurrence[x], changed the type from dateTime to dateTime | Period | Timing, and tagged the element with GF#24681 in the then-current AdverseEvent spreadsheet. Commit f430558 followed with the search parameter description update. There was no evidence that the original Jira application was skipped.

Additional context:
Later Applied issue FHIR-37718 reinterpreted the generic top-level AdverseEvent.occurrence[x] as ambiguous and resolved to remove it in favor of more specific cause/effect timing elements, without Timing. Commit 456b302 implemented that change and preserved the GF#24681 note on the replacement elements. Later Applied issue FHIR-47827 moved cause[x] into AdverseEvent.suspectEntity.occurrence[x], leaving AdverseEvent.effect[x] as the top-level timing element for the effect of the adverse event. The active build scope includes AdverseEvent in source/fhir.ini, and the R4/R5-to-R6 change maps explicitly connect AdverseEvent.date and AdverseEvent.occurrence[x] to current AdverseEvent.effect[x].

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source no longer has AdverseEvent.date, carries the GF#24681/J#37718 note on AdverseEvent.effect[x], defines effect[x] as dateTime | Period, and has date search parameters for effect and suspectEntity.occurrence. Reintroducing a top-level occurrence[x] element or Timing type would contradict the later Applied Patient Care decisions.

Recommendation:
Keep this no-change audit as-is. Further source work should happen only if Patient Care reopens the later AdverseEvent timing decisions; FHIR-24681 itself is already represented in the current source through the approved date/occurrence/effect migration path.
