FHIR-26357: Audit MedicationKnowledge package type binding

Issue request:
FHIR-26357 was a Published/Persuasive Pharmacy change request for R5 asking to fix the MedicationKnowledge package type terminology QA issue. The request specifically preferred changing the MedicationKnowledge package-type binding/value set to SNOMED CT Unit of Presentation, SCTID 732935002, as an exemplar rather than maintaining a local package-type code system with undefined codes.

Initial application:
The issue was applied by commit 519614a7a9adc064d66931e3a5e48a81478c2d1c, which changed source/medicationknowledge/valueset-medicationknowledge-package-type.xml from the local terminology.hl7.org CodeSystem include to a SNOMED CT compose include using filter concept is-a 732935002, and removed the CodeSystem valueSet back-reference that blocked that change. A contemporaneous Zulip committers thread confirms the build error and the need to yank the local CodeSystem's valueSet reference.

Additional context:
MedicationKnowledge remains an active resource in source/fhir.ini, and the current value set source still carries the SNOMED CT Unit of Presentation name, title, description, copyright, and is-a 732935002 filter. Later MedicationKnowledge model changes, including the FHIR-26536 packaging refactor/audit already represented on the combined branch, removed MedicationKnowledge.packaging.type from the current resource and replaced the detailed package definition with MedicationKnowledge.packaging.packagedProduct referencing PackagedProductDefinition. Current source searches find no remaining local CodeSystem medicationknowledge-package-type definition and no current MedicationKnowledge.packaging.type binding to fix.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already embodies the Jira resolution where the value set exists, and the former binding location no longer exists in the current MedicationKnowledge model. Editing source now would either duplicate the already-applied SNOMED CT change or broaden this reconciliation into unrelated current package terminology.

Recommendation:
Keep this no-change audit as-is. No FHIR core follow-up is needed for FHIR-26357 unless Pharmacy separately decides to retire the now-unbound historical MedicationKnowledge package-type value set or move that terminology maintenance to another workstream.
