FHIR-38807: Correct Encounter reason and diagnosis text

Issue request:
FHIR-38807 is a Published/Persuasive R5 ballot reconciliation issue for Patient Administration. It asked that outstanding Encounter trackers, including Encounter.reason and Encounter.diagnosis updates that missed the September 2022 R5 ballot publication, be applied for R5.

Initial application:
The issue appears to have been initially applied by PR #2650, merged as 3ac1ab47dd, whose merge message explicitly lists FHIR-38807. The implementation commit 084c723e14 applied the Encounter.reason and Encounter.diagnosis restructuring from FHIR-16148 and the EpisodeOfCare alignment from FHIR-35863, including new Encounter reason/diagnosis search parameter paths and new reason/diagnosis use terminology. However, the current Encounter source still retained semantically stale prose: Encounter.reason described medical reasons expected during an "episode of care", Encounter.diagnosis still said "diagnosis relevant to this encounter", and Encounter.diagnosis.condition still described a coded diagnosis/reference rather than the medical condition addressed during the encounter.

Additional context:
FHIR-16148 is the tightly related final decision that defines the Encounter.reason and Encounter.diagnosis wording, and Confluence page 51223352 records it as the master tracker for this design family. Later FHIR-38784 intentionally changed Encounter.reason.use and Encounter.diagnosis.use to repeat, so this reconciliation preserves those cardinalities. Later FHIR-48869 synced EpisodeOfCare.reason with Encounter.reason for R6 and is already represented on the combined branch; it does not require changing Encounter reference targets here. Encounter and EpisodeOfCare are active build resources in source/fhir.ini.

AutoFHIR reconciliation:
This commit updates the authoritative Encounter StructureDefinition prose so Encounter.reason is about the encounter, Encounter.diagnosis is the list of medical conditions addressed during the encounter, and Encounter.diagnosis.condition follows the approved CodeableReference wording. It also updates the matching Event mapping exception text and Encounter SVG tooltips so the checked-in diagram source does not contradict the authoritative XML. It intentionally does not change EpisodeOfCare or Encounter reason target profiles, because those are governed by later applied decisions and the current active source already reflects them.

Recommendation:
Keep this commit as a source fix for FHIR-38807. If FHIR-16148 is audited separately later, use this commit as supporting evidence that the remaining Encounter wording gap from that change family has been closed; do not re-add retired or absent Encounter.reason reference targets without a separate current work-group decision.
