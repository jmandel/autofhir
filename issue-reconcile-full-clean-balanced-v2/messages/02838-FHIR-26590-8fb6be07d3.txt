FHIR-26590: Audit Practitioner deceased support

Issue request:
FHIR-26590 is a Published/Persuasive PA change request asking to add Practitioner.deceased[x] to indicate whether a practitioner is deceased, using the Patient-style boolean/dateTime pattern, marking the element as modifier-significant, and adding a search parameter.

Initial application:
The request was applied before this reconciliation by commit 353b3b965d8b2975d5ceaf02cee00c154daf1e38, which explicitly cites FHIR-17634 and FHIR-26590 and added Practitioner.deceased[x] plus Practitioner death-date and deceased search parameters. Later source maintenance normalized the search expression form, and FHIR-37897 added the isModifier flag and reason that FHIR-26590's description expected.

Additional context:
Practitioner is an active current-build resource in source/fhir.ini and is owned by PA. The 2021 PA WGM minutes record the FHIR-26590 motion as persuasive with an 8-0-0 vote and state that it means adding deceased to Practitioner. FHIR-37897 is already represented on the combined branch by da24b911e6d9e7df6e38823d6a9b7e2f5924c941, so this commit does not duplicate that audit. FHIR-37902 later resolved no-change on adding an unknown/code data type, supporting the current boolean/dateTime shape.

AutoFHIR reconciliation:
No source change was made. The current active Practitioner source already has Practitioner.deceased[x] as 0..1 boolean/dateTime with isModifier=true and a modifier reason, and bundle-Practitioner-search-params.xml includes both death-date and deceased search parameters matching the Patient pattern.

Recommendation:
Keep this empty audit commit as-is. No core follow-up is needed for FHIR-26590; any further review of alternate deceased-state data types should remain tied to the separate no-change decision in FHIR-37902 rather than reopening this applied element addition.
