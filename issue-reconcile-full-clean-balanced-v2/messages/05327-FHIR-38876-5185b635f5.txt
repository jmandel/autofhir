FHIR-38876: Audit inter-version compatibility warning

Issue request:
FHIR-38876 was a Published/Persuasive with Modification FHIR-core change request for the Rules for Inter-version change section of the Version Management Policy. It asked for the section to be revised after the September 2022 Breaking Change BoF and for the page to clarify the kind of interoperability FHIR targets; the final applied resolution was to add Lloyd McKenzie's proposed second "dragon" warning about implementation failures caused by allowed non-breaking changes.

Initial application:
The issue was explicitly applied on master by 653d9c4f9ed7886d566c50c27b0fe127d6955ec3, matching the Jira comment that cites Git master 653d9c4f9e. That commit edited the build-scoped source/versions.html page to add the second dragon paragraph immediately after the non-breaking/substantive/breaking change definitions.

Additional context:
The September 2022 #methodology Zulip thread shows the discussion behind the issue: participants debated application compatibility, data-instance validity, new codes/elements, and whether receivers can safely handle future content. FHIR-I minutes for 2023-02-20 record FHIR-38876 as Persuasive with Modification 13-0-0. The Jira comments then split the remaining data-vs-implementation framing into FHIR-40494, which is already represented on the combined branch by audit commit 5951864e50e750259645d34e669c4a7904276900. Later same-page decisions such as FHIR-41452 reorganized adjacent wording but preserved the FHIR-38876 implementation-failure warning.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source/versions.html still contains the approved second dragon warning, including examples of schema validation failure, status-code fall-through, and the instruction that system designers consider how allowed changes affect safe function with newer FHIR versions. Adding more prose for the data-vs-implementation topic would duplicate or conflict with the already-audited FHIR-40494 follow-up rather than fixing an unapplied part of FHIR-38876.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for FHIR-38876 unless a future work-group decision reopens the broader inter-version compatibility policy.
