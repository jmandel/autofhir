FHIR-6815: Audit obsolete Questionnaire root group constraint

Issue request:
FHIR-6815 was a Published/Persuasive Patient Care change request for DSTU1 Questionnaire asking whether a non-required root group conflicted with the root group's cardinality. The accepted resolution was to add a constraint that the root group must have required=true.

Initial application:
The Jira comments cite SVN #5941. Git commit 26e8b597d5034f4372a848e5660a88268f4b664c is the matching imported SVN commit and added invariant 3 to the Questionnaire spreadsheet with context Questionnaire, human text "If root group must be required", and expression group.required = true. The DSTU2 historical generated artifacts in tools/history/release2 include the resulting que-3 constraint on Questionnaire.

Additional context:
Questionnaire no longer has the DSTU1/DSTU2 root group structure. FHIR-8986 was a later Published/Persuasive Questionnaire change that merged question and group into recursive Questionnaire.item, and git commit 52dbc1c47868e26651369ea4109008738f17ce5e removed the old root-group prose and repurposed que-3 while mapping Questionnaire.group to Questionnaire.item for migration. The current active Questionnaire source is in build scope through source/fhir.ini and defines Questionnaire.item as 0..* with the current Questionnaire.item.required semantics.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The requested root-group required=true constraint was applied to the historical model, but the current build has no root group or group.required element to constrain, and reintroducing an equivalent top-level required constraint would contradict the later accepted FHIR-8986 model.

Recommendation:
Keep this no-change audit commit. No current FHIR core source edit is needed for FHIR-6815 unless Patient Care reopens a new question about minimum top-level Questionnaire.item content under the post-FHIR-8986 model.
