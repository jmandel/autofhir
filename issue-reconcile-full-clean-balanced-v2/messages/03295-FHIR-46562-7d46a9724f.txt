FHIR-46562: Audit DeviceDefinition type search split

Issue request:
FHIR-46562 was an Applied/Persuasive OO change request for R6. It reported that the DeviceDefinition `type` search parameter searched `DeviceDefinition.conformsTo.category` instead of `DeviceDefinition.classification.type`, and requested two token search parameters: one for conformance category and one for classification type.

Initial application:
The issue was applied before this reconciliation in commit d1a19f14c66e1beca2ddfa4883f2925af653e96c, linked from Jira comment/PR 3578. That commit changed the `type` search parameter path/expression to `DeviceDefinition.classification.type` and added a separate conformance-category search parameter for `DeviceDefinition.conformsTo.category`.

Additional context:
`source/fhir.ini` actively includes DeviceDefinition, so `source/devicedefinition/bundle-DeviceDefinition-search-params.xml` is in the current build scope. A later Applied technical correction, FHIR-51716, renamed the newly added conformance-category search parameter id/url/code to avoid conflict with `type`; current source and the combined branch include that follow-up. OO minutes on 2025-08-05 noted additional DeviceDefinition search-parameter technical corrections, and no Zulip discussion for FHIR-46562 was found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already has `DeviceDefinition-type` with code `type` and expression `DeviceDefinition.classification.type`, plus a separate `DeviceDefinition-conformsTo-category` search parameter with code `conforms-to-category` and expression `DeviceDefinition.conformsTo.category`.

Recommendation:
Keep this audit commit as-is. The current core source satisfies FHIR-46562 after accounting for the later FHIR-51716 naming correction; no additional FHIR core edit is needed.
