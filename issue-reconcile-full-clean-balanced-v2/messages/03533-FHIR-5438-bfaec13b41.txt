FHIR-5438: Audit Provenance signature type

Issue request:
FHIR-5438 was a Published/Persuasive DSTU1 Security issue for FHIR-core-Provenance asking to change Provenance.integritySignature from string to base64Binary; the Jira resolution accepted the change to base64.

Initial application:
The change was applied in 2015 before the current generated StructureDefinition source: git history shows 5c0d5519e3 explicitly updated Provenance.signature to hold base64Binary for #5438, and c455598a28 then replaced the old Provenance.integritySignature row with Provenance.signature, cardinality 0..*, type Signature, in the Provenance spreadsheet while also updating Signature-related content for [5438].

Additional context:
Current build scope includes Provenance as an active resource and Signature as an active normative datatype in source/fhir.ini. The current Provenance StructureDefinition has Provenance.signature typed as Signature, and the active Signature datatype defines Signature.data as base64Binary. Later related decisions renamed Signature.blob to Signature.data and broadened allowed signature formats without reverting the base64Binary payload requirement.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change because the current source already satisfies the requested correction through the Signature datatype. No current source reference to Provenance.integritySignature remains in the active Provenance source checked for this issue.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-5438 unless a future Security work group decision asks to change the broader Signature datatype semantics.
