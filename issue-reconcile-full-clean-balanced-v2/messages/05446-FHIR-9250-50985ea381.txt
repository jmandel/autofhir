FHIR-9250: Audit PractitionerRole repeat guidance

Issue request:
FHIR-9250 was a Published/Persuasive PA change request against FHIR-core-Practitioner from the DSTU2 cycle. It asked the PractitionerRole documentation to clarify that repeating role, specialty, location, healthcareService, telecom, availability, and similar details in one PractitionerRole all apply together; if a practitioner has different specialties or details at different locations, separate PractitionerRole instances should be used.

Initial application:
No current git commit explicitly mentioning FHIR-9250 was found. The current build-scoped PractitionerRole narrative nevertheless contains the requested guidance. The main visible source-history application came through the later same-change-family issue FHIR-14771 in commit a0a7a69e0dae891e23be5069769cb1d50f7a8ae5, which added both the concise Scope and Usage sentence and a detailed multiple-location note. Commit 7571a34d8b034e2cc5f9d1b546787dbe129aaa5d later preserved that multiple-location note inside the current Notes list.

Additional context:
PractitionerRole is active in source/fhir.ini. The current Scope and Usage text says repeated role, specialty, Location telecom, and HealthcareService properties can be represented in different acceptable shapes, but that a separate PractitionerRole instance should be created when availability, telecom, or other details differ across healthcareservices or locations. The current Notes section states that when representing multiple locations and/or multiple specialties in one instance, all details apply to all locations and different values require a new/split instance. FHIR-14771, which asked the same implementer question for location, healthcareService, and availability, is already represented on the combined branch by commit 7f833e348815f6a6a38a27e12684443d5555ca97, so it was not duplicated here. FHIR-56377 is a later Submitted/unresolved editorial rewrite proposal for this same Notes paragraph and is not a final decision.
