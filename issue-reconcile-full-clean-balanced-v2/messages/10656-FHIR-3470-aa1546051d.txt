FHIR-3470: Audit code system OID exposure

Issue request:
FHIR-3470 was a Published/Persuasive FHIR-core change request for DSTU1 asking that OIDs be exposed where some value sets, and possibly FHIR-defined code systems, were not showing them in the specification; the cited page was encounter-discharge-disposition.

Initial application:
No git commit explicitly mentions FHIR-3470. The Jira comments say the issue was fixed as part of another task, and the closely related FHIR-3620 discussion records the 2014 implementation approach: publish OID metadata for most value sets and code systems rather than putting every OID directly into the resource at that time. Later source history imported the encounter-discharge-disposition ValueSet with an explicit OID identifier and added source/oids.ini as the permanent OID assignment record.

Additional context:
Encounter is an active current-build resource, and the current encounter-discharge-disposition ValueSet source contains urn:oid:2.16.840.1.113883.4.642.3.259. source/oids.ini records the same ValueSet OID under the ValueSet root and separately maintains CodeSystem OID assignments. The expansion now uses the external THO CodeSystem URL, and the current THO CodeSystem artifact exposes its own OID identifier. Searches found no direct Zulip or Confluence evidence that changes this Jira/source conclusion.

AutoFHIR reconciliation:
This audit commit makes no source change because the current core build already exposes the cited ValueSet OID, the current published CI page renders it, and the associated CodeSystem OID is maintained in the external THO artifact rather than as a missing core source entry.

Recommendation:
Keep this no-change audit. Any remaining concern about the THO CodeSystem or HL7 OID registry should be handled in the terminology/THO source of truth, not by adding redundant or conflicting core FHIR source.
