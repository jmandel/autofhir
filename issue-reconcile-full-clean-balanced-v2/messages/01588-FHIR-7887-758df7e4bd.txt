FHIR-7887: Audit Immunization occurrence date flexibility

Issue request:
FHIR-7887 was a Published/Persuasive PHER core issue from the 2015May ballot asking to make Immunization.date optional (0..1) because patient-reported immunizations may lack a specific date, including cases where an adult cannot recall the year of a childhood immunization.

Initial application:
The issue was explicitly applied in git commit b4d544060ae9468bc9fe06353a0af056866f9d28, which changed Immunization.date from 1..1 to 0..1 and added the Jira rationale as committee-comment text. Later source refactoring moved the element to Immunization.occurrence[x].

Additional context:
Current Immunization is in build scope through the active source/fhir.ini resources entry. The current StructureDefinition carries committee note #7887 on Immunization.occurrence[x], keeps the patient-reported-date rationale in the comment, and permits dateTime or string. Although the current cardinality is 1..1, later Jira context shows this was intentional: FHIR-16223 considered unknown IPS immunization dates resolved by adopting R4, FHIR-18293 declined an interval for imprecise dates and documented string use when exact dates are unknown, and FHIR-46477 updated the same occurrence comment while preserving that rule.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already preserves the substantive FHIR-7887 implementer guidance for unknown or imprecise patient-reported immunization dates through Immunization.occurrence[x] dateTime|string and explicit comment text. Changing occurrence[x] back to 0..1 would conflict with later applied/published design rather than complete the 2015 issue.

Recommendation:
Keep this audit commit as-is. No core source follow-up is recommended for FHIR-7887 unless PHER reopens the broader question of whether every Immunization must carry at least a narrative/string occurrence value.
