FHIR-32480: Audit confirmed definition resolution

Issue request:
FHIR-32480 was an Applied/Persuasive with Modification Patient Care change request for the Condition verification status confirmed code. It asked to replace the tautological definition "There is sufficient diagnostic and/or clinical evidence to treat this as a confirmed condition" with "There is sufficient evidence to assert the presence of the subject's condition".

Initial application:
No Jira-tagged core source commit for FHIR-32480 was found. The core-owned CodeSystem duplicate for condition-ver-status had already been deleted by the December 2022 "Remove THO duplicates" commit, so the current core source no longer contains the authoritative confirmed code definition. The subsequent implementation path was the UTG/THO proposal UP-387, referenced from the Jira comments.

Additional context:
FHIR-32479 is the companion unconfirmed-code issue. UP-387 is Proposal Implemented and records the Patient Care-approved definitions for both unconfirmed and confirmed. Current THO terminology artifacts now carry the requested confirmed definition, while current core source keeps Condition.verificationStatus bound to the Condition Verification Status ValueSet, whose compose includes the external THO CodeSystem. The commented OID entry in source/oids.ini is further evidence that the CodeSystem itself is not active core source.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Editing core would either recreate an external THO CodeSystem duplicate or touch generated/stale package artifacts; the authoritative current terminology already has the FHIR-32480 definition.

Recommendation:
Keep this no-change audit. If a future build surface shows the old confirmed definition, resolve it by updating the THO dependency/build input or generated package publication process, not by reintroducing a core CodeSystem source file.
