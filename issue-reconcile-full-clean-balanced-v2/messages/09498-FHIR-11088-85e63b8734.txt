FHIR-11088: Audit composite search parameter application

Issue request:
FHIR-11088 was a Published/Persuasive with Modification FHIR-core Observation change request raised against DSTU2. It asked for composite search parameters such as Observation code-value-[x] to be computable without ambiguous Cartesian pairing, by splitting the Observation composites where needed and by changing SearchParameter.component so component.expression specifies how each component value is extracted from the composite's main expression.

Initial application:
The Jira comments record Grahame Grieve applying the issue in svn revision 10444. A contemporaneous Zulip implementers thread for GF#11088 shows the adopted model: keep component definitions for metadata, add a main SearchParameter.expression that yields the indexable item, and add component sub-expressions such as code and value.as(Quantity). The current git history does not contain an explicit FHIR-11088 commit; the present source came through later source rework commits that preserve the applied model.

Additional context:
Observation and SearchParameter are active resources in source/fhir.ini. Current SearchParameter.component.expression is mandatory and says it overrides the referenced definition's expression. Current Observation search parameters include separate top-level code-value-concept/date/quantity/string composites, component-code-value-concept/quantity composites, and combo composites whose main expression is Observation | Observation.component with relative component expressions. Later FHIR-25297 and its Zulip thread rely on the same component.expression semantics for another resource, confirming the model rather than superseding it. Confluence searches found no conflicting WG minutes.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because the current build-scope source already conveys the computable composite search parameter semantics requested by FHIR-11088 and avoids the ambiguous top-level/component value pairing that motivated the issue.

Recommendation:
Keep this no-change audit commit. Future work on individual composite search parameters should be handled as resource-specific corrections, as in FHIR-25297, rather than reopening FHIR-11088's already-applied SearchParameter model.
