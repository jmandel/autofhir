FHIR-7503: Audit List nested-list guidance

Issue request:
FHIR-7503 was a Published/Persuasive FHIR-core List change request from the DSTU1 ballot asking whether nested lists were covered. The accepted resolution was to add a note about how to do lists of lists, with the Jira comment specifying introduction text that Lists are allowed to contain other Lists so there can be a nested collection of Lists.

Initial application:
The issue was applied in git commit e1936257b0cdeea11828989b9b5fa1f324d101a9 on 2015-06-26 with subject "#7503 - add note about nested lists" and git-svn revision 5597, matching the Jira application comment. That commit added the nested-list note to source/list/list-introduction.xml. Later QA commits, including 08a43ec5a1a68e8b02543dd0d193bd44e5e03f1c, preserved the same meaning while changing the sentence to the current wording.

Additional context:
List is an active current-build resource through source/fhir.ini. The current List introduction says, "Lists are allowed to contain other Lists, to create a nested collection of Lists," and List.entry.item remains a Reference(Resource), which permits a List entry to reference another List resource. Jira searches found FHIR-7503 as the only directly matching issue for nested/list-of-lists wording. Zulip and Confluence searches found no FHIR-7503-specific conflict; one 2026 OO lab grouping minutes page quoted the current nested-list sentence while discussing other lab grouping issues, but it did not record a FHIR-I reversal of FHIR-7503.

AutoFHIR reconciliation:

Keep this no-change audit as-is for FHIR-7503. Any future concern about whether the List resource is appropriate for laboratory observation grouping should be handled under the separate OO lab grouping issues or a new FHIR-I tracker, not by changing this already-applied DSTU1 nested-list request.
