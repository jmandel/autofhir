FHIR-12322: Audit Coverage classification structure

Issue request:
FHIR-12322 was Published/Persuasive for DSTU2 Coverage and requested replacing the repeating Coverage.level Coding classifier with an explicit group of classifier details such as group/groupDisplay and plan/planDisplay, so implementers could carry insurer card classifiers without inventing code systems for display-only values.

Initial application:
The request was initially applied in git commit 22950798fedd80df280840e9c56951c9a4d0e28f, which marked Coverage.level inactive and introduced Coverage.group with typed child elements in the Coverage spreadsheet and examples. That commit also included the separate FHIR-12230 planholder change, but the level-to-group changes are directly traceable to FHIR-12322.

Additional context:
Coverage remains an active current-build resource in source/fhir.ini. A later Published/Persuasive FM decision, FHIR-15564, explicitly accepted a new Coverage Class structure and removed the intermediate Grouping and Sequence structure. Commit 8f5e8739dc6dfa0edfae82f9d09b26f6f0e7b02a applied that decision by replacing Coverage.grouping examples with repeating Coverage.class entries. Current source defines Coverage.class as a repeating BackboneElement with type, value, and name, backed by the coverage-class value set; the examples use class entries for group, plan, subplan, class, subclass, sequence, and pharmacy card identifiers.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The obsolete Coverage.level and Coverage.group/grouping shapes are absent from current Coverage XML source, while the current Coverage.class structure preserves the FHIR-12322 purpose in the later, explicitly approved representation.

Recommendation:
Keep this audit commit as-is. Reintroducing the old group-specific element names would conflict with FHIR-15564; any future changes to Coverage.class cardinality or terminology should be handled under a new FM tracker rather than this DSTU2 issue.
