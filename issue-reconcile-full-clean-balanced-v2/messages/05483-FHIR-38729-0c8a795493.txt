Issue request:
FHIR-38729 was Published/Persuasive with Modification and asked for an ImplementationGuide `refersTo` relationship for links to profiles or pages in another IG without asserting a conformance dependency. The final disposition narrowed that request to a tooling extension and explicitly said no changes were needed to the IG resource.

Initial application:
No FHIR core commit or current source reference mentioning FHIR-38729, `refersTo`, or HL7/fhir-ig-publisher#646 was found. The active ImplementationGuide resource still contains `dependsOn.reason`, added earlier by FHIR-36313, but no no-dependency relationship element; current narrative points IG authors to the Guidance IG for tooling extensions.

Additional context:
FHIR-I minutes on 2022-10-24 discussed the non-dependency reference use case, on 2023-02-27 recorded that the likely solution was a tooling extension, and on 2023-03-13 voted 11-0-1 for the tooling-extension approach. The seed Zulip discussion shows the practical problem was IG Publisher broken-link/QA handling for narrative links to other IGs. Jira then linked HL7/fhir-ig-publisher#646, which remains an approved external tooling issue rather than a core resource-definition change.

AutoFHIR reconciliation:
This commit intentionally makes no source change in the FHIR core checkout. Adding `ImplementationGuide.refersTo` or equivalent core resource content would contradict the final FHIR-I decision; any remaining implementation belongs in IG Publisher and/or the tooling-extension source that IG Publisher consumes.

Recommendation:
Keep this audit as an external-repo decision for FHIR core. Follow up in HL7/fhir-ig-publisher#646 and the relevant tooling-extension source if the extension still needs implementation; do not add a core ImplementationGuide element unless FHIR-I reopens and changes the decision.
