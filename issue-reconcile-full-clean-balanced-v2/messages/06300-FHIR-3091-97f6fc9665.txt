FHIR-3091: Audit FamilyMemberHistory patient-record extension

Issue request:
FHIR-3091 was a Published FHIR-core Patient Care change request with a Persuasive with Modification decision to add an extension allowing FamilyHistory.relation to point to the Patient resource for the relative's medical record. The Jira comments record that the extension should be repeatable because multiple patient records may exist.

Initial application:
The Jira comment says svn revision 4805 added the extension as 0..*. The current git mirror's build@4805 commit does not show the extension payload, but later checked-in release history and pre-R5 core source contain StructureDefinition/familymemberhistory-patient-record with max="*" and valueReference constrained to Patient.

Additional context:
FamilyHistory is now FamilyMemberHistory in the current build. FamilyMemberHistory remains an active core resource, but the patient-record extension definition is no longer a core source artifact: commit dd468d4 removed resource-specific extension definitions, including source/familymemberhistory/structuredefinition-extension-familymemberhistory-patient-record.xml, from the R5 source. The FHIR Extension Pack checkout contains the current authoritative StructureDefinition-familymemberhistory-patient-record.xml with context FamilyMemberHistory and value[x] Reference(Patient).

AutoFHIR reconciliation:
This audit intentionally made no core source change. Re-adding the extension to the core checkout or adding redundant local prose to FamilyMemberHistory.relationship would conflict with the current extension-pack ownership model; the semantically required extension already exists outside this repository.

Recommendation:
Keep this external-repo audit commit as-is for core. If future cleanup is desired, it should be handled in the FHIR Extension Pack rather than by restoring the extension definition to core.
