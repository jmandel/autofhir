FHIR-11438: Audit enabled specification search

Issue request:
FHIR-11438 was a Published/Persuasive FHIR-I change request from the 2016 September core ballot asking that search actually be enabled for the FHIR specification search page at the 2016sep search.cfm URL. The Jira has an 8-0-0 vote, was applied for DSTU2, and Grahame Grieve later commented that the work had been done.

Initial application:
No source commit explicitly tagged FHIR-11438 was found. Git history shows tools/html/search.cfm was introduced in 2016 as a static "Still under development" page before this Jira was filed, while a 2017 Zulip thread records Grahame announcing that specification search was working again at the hl7.org/fhir/search.cfm URL. The current source history later added an active CI search page, source/search-build.html, with a DuckDuckGo search iframe and included it in publish.ini and the page hierarchy.

Additional context:
This issue is tightly connected to earlier Published/Persuasive search-capability ballot issues FHIR-8151, FHIR-7712, and FHIR-6849 plus duplicate FHIR-7748. The combined branch already contains FHIR-8151, which changed the current home page and shared footer to use the publisher search-location variable instead of hard-coding search.cfm, matching the navbar's existing behavior. Later Jira issues FHIR-50549 and FHIR-54549 report that live search.cfm links are broken in R6-era publications, but both are unresolved and therefore are background operational/publishing concerns rather than final decisions to apply here.

AutoFHIR reconciliation:
This audit commit makes no source change. The current source already contains an active build-scope search page and the current build inputs route user-facing search links through the configured search-location target because of the already-published FHIR-8151 reconciliation. Editing tools/html/search.cfm in this issue would duplicate or preempt unresolved later work about the live server-side search.cfm endpoint.

Recommendation:
Keep this no-change audit. If the work group resolves FHIR-50549 or FHIR-54549, handle the live search.cfm/searchform behavior under those issue keys rather than reopening this DSTU2 ballot comment.
