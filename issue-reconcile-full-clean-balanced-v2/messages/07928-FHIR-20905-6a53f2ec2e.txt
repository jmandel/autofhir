FHIR-20905: Audit choice-target mapping guidance

Issue request:
FHIR-20905 was Published/Persuasive for R5 and asked how a mapping rule should behave when a target element that is auto-created by a transform has a choice of possible target types. The accepted resolution was to document that the engine raises an error when the instance type cannot be determined, and that maps should use an explicit create() in those cases.

Initial application:
The issue was applied by git commit 379e1fd5fa6933531e474aa54c53a900c53897bb, which added the requested Mapping Language paragraph and create() example to source/mapping-language.html. Current blame still attributes the relevant lines to that Jira-tagged commit.

Additional context:
The Mapping Language page is in the current build navigation at source/hierarchy.xml and is linked from the StructureMap introduction. Current source also has adjacent target-transform text stating that autocreation is an error when an element has more than one possible type, so the issue resolution is represented both locally and in the more specific Type Wrangling paragraph. Zulip searches found only a FHIR-I block-vote notice and a later mapping-framework status list; Confluence searches found no FHIR-20905 references or conflicting minutes.

AutoFHIR reconciliation:
No source change was made. The current built source already documents the required error behavior for choice-type autocreation and shows that an explicit create("x") should be used to choose the target type.

Recommendation:
Keep this audit commit as-is. No further core FHIR source work is needed for FHIR-20905 unless a future work-group decision changes the Mapping Language semantics for autocreation into choice elements.
