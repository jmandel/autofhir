FHIR-5950: Audit Timing coded representation

Issue request:
FHIR-5950 was a Published FHIR-core datatypes change request, resolved Persuasive, asking that Timing support a text or coded representation for institution-specific timing mnemonics alongside the computational timing form. The accepted resolution was to add a new element with datatype CodeableConcept.

Initial application:
The Jira comments cite the historical application, and the git-svn history contains a direct implementation commit, a4cda65a856e75aae09758faef7d4c91cf3d5ec7, with subject "#5950 - add Timing.code". That commit added Timing.code as a 0..1 CodeableConcept in source/datatypes/timing.xml with a TimingAbbreviation binding and explanatory definition text. The current source still defines Timing.code as 0..1 CodeableConcept.

Additional context:
source/fhir.ini lists Timing as an active datatype and marks Timing normative, so source/datatypes/timing.xml and the Timing narrative are in current build scope. Later Timing work did not reverse the FHIR-5950 model: FHIR-13941, already represented on the combined branch, treated free-text timing as Timing.code.text rather than adding another element, and current source/datatypes.html documents that mapping. Searches for FHIR-5950 and Timing.code in Zulip and Confluence found no conflicting community record.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build-scope source already satisfies FHIR-5950: Timing has a top-level optional CodeableConcept element, Coding and text can be exchanged through that element, and the surrounding definition/narrative explain institution-specific timing codes and text.

Recommendation:
Keep this no-change audit as-is. No core FHIR source follow-up is needed for FHIR-5950 unless a future work-group decision changes the established Timing.code/Timing.code.text approach.
