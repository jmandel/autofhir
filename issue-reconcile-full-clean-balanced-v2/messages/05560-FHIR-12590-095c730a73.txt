FHIR-12590: Audit ConceptMap default mappings

Issue request:
FHIR-12590 was a Published/Persuasive with Modification Vocabulary issue for DSTU2. It asked ConceptMap to support default mappings for codes not otherwise listed, and the approved resolution was to add a group-level unmapped element, sibling to element, with three options: map to a fixed code, use the unmapped/source code, or nominate another map.

Initial application:
The Jira comments cite svn revision 11144. The matching git-svn commit 7ad0c6364e2c36a9bc3d92cb70f7aa22231970c3 is titled "#12590 & #12617 - add default mappings and display to ConceptMap" and added ConceptMap.group.unmapped, the conceptmap-unmapped-mode code list, constraints for fixed and other-map modes, and an example fixed unmapped mapping. Later source refactors moved the old spreadsheet-defined content into the current source/conceptmap/structuredefinition-ConceptMap.xml without losing the unmapped backbone.

Additional context:
ConceptMap is an active current-build resource in source/fhir.ini. Later Published ConceptMap issues refined the original unmapped design rather than reversing it: FHIR-14686 clarified fallback descriptions, FHIR-22100 clarified unmapped mode definitions, FHIR-22129 added the default relationship element, FHIR-32543 constrained fixed-mode code/display use, FHIR-32545 renamed url to otherMap, FHIR-32546 renamed provided to use-source-code, and FHIR-34279 allowed fixed mode to use either code or valueSet. Those related issues are already represented on the combined branch where applicable, and the non-final FHIR-55356 escape-valve discussion is only background.

AutoFHIR reconciliation:
No source change was made. The latest combined ConceptMap source is already correct for FHIR-12590: source/conceptmap/structuredefinition-ConceptMap.xml defines ConceptMap.group.unmapped as a group child with mode values use-source-code, fixed, and other-map; fixed mode supports code or valueSet; other-map uses otherMap; relationship captures the default relationship for fixed or use-source-code; source/conceptmap/codesystem-conceptmap-unmapped-mode.xml and source/conceptmap/conceptmap-notes.xml describe the current modes; and source/conceptmap/conceptmap-example.xml includes an unmapped fixed-code example.

Recommendation:
Keep this no-change audit commit. Future changes should be handled through specific later trackers, such as the triaged FHIR-55356 escape-valve question, rather than changing FHIR-12590's already-applied default mapping mechanism.
