FHIR-29114: Clarify Procedure.supportingInfo as an element

Issue request:
FHIR-29114 was a Published/Persuasive Patient Care R5 change request to add supportingInfo to the base Procedure resource as 0..* Reference(Any), described as extra information relevant to the procedure, and to stop treating this as a Procedure extension.

Initial application:
The issue appears to have been applied in October 2020 by d1143ee, which added Procedure.supportingInfo to the then-authoritative Procedure spreadsheet, and 658b09f, which added supportingInfo to the Procedure example. The January 2021 source rework in 33b409a carried the element into source/procedure/structuredefinition-Procedure.xml with the J#29114 committee note, but also preserved the stale definition sentence saying "This extension should not be used...".

Additional context:
Procedure is an active build resource in source/fhir.ini. The Jira comments clarify that the workflow-supportingInfo extension Patient Care had seen did not apply to Procedure, so the intended current artifact is the base Procedure.supportingInfo element. Confluence minutes for the 2020-10-08 Patient Care call reference FHIR-29114, and no direct Zulip discussion was found that changes the Jira/source conclusion. Later Procedure parameter issues FHIR-33391 and FHIR-46303 ask for richer structured procedure details and do not supersede this base supportingInfo wording fix.

AutoFHIR reconciliation:
This commit changes the active Procedure.supportingInfo definition from "This extension" to "This element" and makes the same one-word correction in the checked-in Procedure SVG tooltip that mirrors the definition. It preserves the approved cardinality, reference target, short description, definition meaning, example, and related structure.

Recommendation:
Keep this source fix as-is. It removes a misleading extension reference from the base element created for FHIR-29114 without broadening Procedure or pre-judging later structured-parameter proposals.
