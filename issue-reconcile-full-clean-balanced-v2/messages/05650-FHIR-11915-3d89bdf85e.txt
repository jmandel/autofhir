FHIR-11915: Audit language ValueSet OID correction

Issue request:
FHIR-11915 was a Published FHIR-core vocab change request from the DSTU2/2016Sep ballot, resolved Persuasive with Modification, asking to correct the generated OID shown for the Common Languages ValueSet. The ballot page exposed 2.16.840.1.113883.4.642.2.languages for OID-based terminology systems, while the issue noted that BCP47/RFC5646 language tags should not be represented by that generated textual OID and referenced the older 2.16.840.1.113883.6.121 language-code OID.

Initial application:
Jira records this as a publishing issue, with a comment that the specification was correct and the ballot output was wrong, followed by an SVN revision note. No Git commit message mentions FHIR-11915 directly, but git pickaxe shows commit 06af2eaa68a07b473d22ea80f85e8404a762307b, "rebuild value set OID system", removing the bad urn:oid:2.16.840.1.113883.4.642.2.languages identifier from source/terminologies/valueset-languages.xml. Published release checks show the bad 2016Sep identifier was replaced by numeric FHIR ValueSet OIDs in later releases.

Additional context:
Current source/terminologies/valueset-languages.xml defines http://hl7.org/fhir/ValueSet/languages with urn:oid:2.16.840.1.113883.4.642.3.20 as the primary identifier and urn:oid:2.16.840.1.113883.4.642.3.891 as an old identifier; source/oids.ini maps the current ValueSet URL to 2.16.840.1.113883.4.642.3.20. The related all-languages ValueSet uses 2.16.840.1.113883.4.642.3.21. build.fhir.org matches those identifiers. A later Jira search surfaced FHIR-26606 about the v3 HumanLanguage/ISO reference, but that issue was retracted and concerns a different v3/THO terminology artifact rather than this generated FHIR ValueSet OID.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative source and current generated build no longer contain the reported 2.16.840.1.113883.4.642.2.languages identifier, and changing the present numeric OID mapping would contradict later OID normalization rather than complete FHIR-11915.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-11915 unless a future TSMG or Vocabulary decision explicitly changes FHIR ValueSet OID allocation; any such decision should be handled as a new issue rather than reopening this 2016 publishing correction.
