FHIR-9070: Audit Immunization status value set

Issue request:
FHIR-9070 was a Published FHIR-core Immunization change request, resolved Persuasive with Modification, asking that Immunization.status stop using the full MedicationAdministration status value set because codes such as on-hold, in-progress, and stopped were not relevant to an immunization event. The approved resolution trimmed the allowed values to completed and entered-in-error, with refused/deferred concepts handled through the then-current reasonNotGiven path.

Initial application:
The issue was applied in historical source by commit 1212b3f471b75003758b78b258e740eed23a98dd, whose message explicitly says it addressed tracker items 9070 and 11122. That commit changed the Immunization spreadsheet status short list from in-progress/on-hold/completed/entered-in-error/stopped to completed/entered-in-error, pointed the binding at a new Immunization-specific status value set, and added source/immunization/valueset-immunization-status.xml containing only completed and entered-in-error from the then-current pharmacy status code system. The Jira comment also records the change as committed on 2016-11-04.

Additional context:
Later R4 work changed the modeling rather than reverting FHIR-9070. Commit 4c5a8902abffdfb5b6e9f07b4bca119d875dc64a synchronized Immunization with the Event workflow pattern, removed the separate notGiven representation, moved refused/not-administered events into Immunization.status as not-done, and changed the status value set to a narrow event-status subset. PHWG 2018 WGM minutes and FHIR-14377 record the Event-pattern statusReason/not-done rationale. More recent PHWG decisions, including FHIR-54325 and FHIR-55330, reaffirm that current Immunization.status has exactly completed, entered-in-error, and not-done and that statusReason is limited to not-done or entered-in-error. The combined branch already contains a separate FHIR-14377 audit commit, so this commit does not duplicate that decision.

AutoFHIR reconciliation:
No source change was made. source/fhir.ini keeps Immunization in the active build, and the current authoritative source already has a required binding to http://hl7.org/fhir/ValueSet/immunization-status. That value set includes only completed, entered-in-error, and the later-approved not-done code from event-status; it does not include the irrelevant MedicationAdministration codes called out by FHIR-9070.

Recommendation:
Keep this audit commit as-is. Do not remove not-done in an attempt to match the 2016 wording literally; it is the result of later PHER/Event-pattern decisions, while the original FHIR-9070 concern remains satisfied because the broad MedicationAdministration statuses are not allowed.
