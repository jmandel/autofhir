FHIR-36095: Audit search batching GET guidance

Issue request:
FHIR-36095 was Published with a Persuasive with Modification resolution for R5. It asked the spec to clarify whether POST-based search is allowed in batch/transaction Bundles or, if not, how search should be represented there; the accepted resolution says searches in Bundles should be accepted as GET, there is no standard POST-search encoding in a Bundle, and servers should not apply GET-only limits in that context.

Initial application:
The current source already contains the accepted guidance in source/search.html under "Batching Search Requests". Git history shows commit b464a229a5f3fc4f8d1cde220ed7fbcbad74fc2c replaced a TODO that explicitly referenced FHIR-36095 with the substantive GET-in-Bundle guidance; later editorial/conformance cleanups retained the same rule.

Additional context:
FHIR-I minutes on 2022-02-28 record the work-group discussion that POST-based search should be disallowed or not standardized inside batch/transaction Bundles because Bundle bodies can only carry a Resource, while search POST parameters are form-encoded. Related search decisions, including FHIR-31912, FHIR-35859, and FHIR-39107, refine general GET/POST search support but do not change the Bundle-specific conclusion.

AutoFHIR reconciliation:
No source change was made. The Search page is part of the RESTful API documentation and already states that Bundle search requests use HTTP verbs and URLs, systems SHOULD accept GET searches in a Bundle even if they do not typically accept GET-based searches, POST-based searches have no standard Bundle representation, and servers SHOULD NOT impose GET-specific limits in this context.

Recommendation:
Keep this audit commit as-is. Do not duplicate the guidance on http.html unless the work group wants additional cross-linking, because the current Search page text conveys the normative behavior without creating parallel wording that could drift.
