FHIR-42984: Audit instant regex precision clarification

Issue request:
FHIR-42984 was Applied/Persuasive for the FHIR-core datatypes page. It reported that the instant prose and example format appeared to limit fractional seconds to milliseconds while the regular expression allowed more precision; the approved clarification was to keep sub-millisecond precision allowed and state that precision beyond milliseconds is optional.

Initial application:
No prior AutoFHIR reconcile commit with Issue-Reconcile-Key: FHIR-42984 was present on the combined branch. The source change itself was already applied by commit cf56ea1c5b5bf3b860bfef8ee6c6f84a13b2ded6, which added "Sub-millisecond precision is optionally allowed" to the instant row in source/datatypes.html.

Additional context:
FHIR-I minutes for 2024-12-09 record the discussion that values beyond milliseconds may be sent but servers are not required by a general rule to accept or preserve them, followed by a 7-0-0 Persuasive vote to add the optional-precision note. The current active datatype source page is listed in publish.ini, and the primitive spreadsheet regex for instant allows one to nine fractional-second digits, matching the regex shape quoted in the Jira resolution. Later FHIR-24564 only changed "timezone offset" to "UTC offset" in the same row and preserved the FHIR-42984 precision note.

AutoFHIR reconciliation:
This audit commit intentionally made no source change. The current build-source text already contains the approved sub-millisecond clarification, and the source regex remains consistent with the applied resolution, so adding or rewriting prose would be redundant.

Recommendation:
Keep this audit commit as-is. No additional core source work is needed for FHIR-42984 unless the work group separately reopens the broader question of whether instant should allow more than the currently specified fractional-second digit range.
