FHIR-17085: Audit Bundle duplicate-version guidance

Issue request:
FHIR-17085 was a Published/Persuasive with Modification FHIR-I change request raised against STU3. It asked why document and message Bundles barred duplicates when multiple versions of the same resource can be valid. The accepted resolution removed the no-duplicates table, allowed multiple versions of a resource while keeping each version unique, warned that unversioned references can be ambiguous, documented transaction/batch discretion and Provenance-driven use cases, and updated Bundle reference resolution to account for version-specific references.

Initial application:
The Jira comment records svn revision 13895, which corresponds to git commit 7633fe38902205aa7792b94ed25e0666cf8e5a91. That commit removed the per-Bundle-type duplicate prohibition table from source/bundle/bundle-notes.xml and added the current guidance that a given resource version appears once, multiple versions may appear, unversioned references can be ambiguous, Provenance may require multiple versions, and batch/transaction behavior is server discretion.

Additional context:
Bundle is an active current-build resource in source/fhir.ini. Later Bundle issues refined the same area without reversing FHIR-17085: FHIR-29803 tightened conformance wording in the uniqueness section, FHIR-29271 and FHIR-31422 rewrote the reference-resolution algorithm to explicitly handle version-specific absolute references and arbitrary URI schemes, and the already-published FHIR-31986 reconciliation fixed bdl-7 so the authoritative invariant compares fullUrl plus meta.versionId for entries where a resource is present.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current source/bundle/bundle-notes.xml already conveys the FHIR-17085 rule and risk language, current source/bundle/structuredefinition-Bundle.xml contains the matching bdl-7 invariant, and the current reference-resolution algorithm explains how version-specific references resolve against Bundle entries.

Recommendation:
Keep this audit commit as-is. The current specification already reflects the published FHIR-17085 decision, and additional edits would be redundant; any future change to Bundle duplicate/version semantics should be handled by a new work-group decision.
