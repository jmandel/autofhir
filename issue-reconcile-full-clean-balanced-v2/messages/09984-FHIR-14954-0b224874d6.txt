FHIR-14954: Audit above/below search modifiers

Issue request:
FHIR-14954 is a Published/Persuasive FHIR-core search issue asking that GF#8776 be applied after the older :above/:below search-modifier request had a positive vote but appeared to have been closed as no change. The decisive Jira comment says the change was applied except for adding SearchParameter.supportsAboveBelow, because SearchParameter.modifier already explicitly lists supported above/below modifiers; FHIR-I accepted that on the 2018-08-10 call.

Initial application:
No current git commit was found that names FHIR-14954 directly. The underlying GF#8776 work was applied earlier in git-svn commit 26c933c82f1c19283a7d2e1642aa3a2abe112085, which added the search.html hierarchy examples, :above/:below reference-search prose, and references.html circular-reference linkage for SVN revision 13269. The current source retains the applied behavior through later search-page refactors and clarifications.

Additional context:
FHIR-8776 itself is Published/Persuasive and asked to support :above and :below for partOf/parent-style hierarchy traversal, with support advertised on the SearchParameter rather than inferred by element name. A contemporary Zulip thread narrowed the practical scope to parent/child relationships such as partOf and parent/base and discussed using a flag; the final applied Jira comment for FHIR-14954 confirms that the existing SearchParameter.modifier list is the accepted representation instead of a separate supportsAboveBelow element.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/search.html lists :above and :below as modifiers for reference, token, and uri search parameters, documents hierarchical reference semantics and examples for Procedure.location:below and MedicationAdministration.encounter:above, and says servers advertise support by listing the modifiers in SearchParameter.modifier. Current SearchParameter source defines SearchParameter.modifier and the search-modifier-code code system contains both above and below. Adding the rejected/redundant supportsAboveBelow element would contradict the accepted application note.

Recommendation:
Keep this no-change audit commit as-is. The current build source already reflects the accepted GF#8776/FHIR-14954 outcome, and no follow-up core source edit is recommended unless the work group later decides to replace SearchParameter.modifier with a more specific support flag.
