FHIR-15688: Audit MedicationRequest category value set

Issue request:
FHIR-15688 was Published/Persuasive with Modification for STU3 Pharmacy. It asked that MedicationRequest.category value set definitions stop referring only to "orders" because MedicationRequest covers more than intent=order, questioned whether a patient-specified category should be added, and was resolved by keeping category focused on care setting, adding a separate treatment/course attribute, and changing "orders" to "requests".

Initial application:
The issue was applied by git commit b87c1a290d1ad3d6e352f8bf4127fc61c949e67d, which updated the MedicationRequest spreadsheet category prose and changed the category code definitions from "orders" to "requests". The related treatment/course split was applied by ce698b9ee5288dac0d1f13735b92bb16a46c008d for GF/FHIR-17255, which added MedicationRequest.courseOfTherapyType.

Additional context:
MedicationRequest is active and approved in source/fhir.ini. The current source has since been refactored from spreadsheets into StructureDefinition, CodeSystem, and ValueSet XML. Later category work matters: FHIR-25555 removed discharge from the exemplar medication category sets, and FHIR-51726 moved the MedicationRequest category CodeSystem/ValueSet back into FHIR core with the current medicationrequest-category canonical. FHIR-17255 is already represented on the combined branch, so it is cited here only as supporting context for the split.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active MedicationRequest category CodeSystem now contains only inpatient, outpatient, and community, and all three definitions say "requests" rather than "orders". The current MedicationRequest.category element describes administration/consumption location or other request categorization without treatment-type examples, while MedicationRequest.courseOfTherapyType separately represents the overall medication administration pattern.

Recommendation:
Keep this audit commit as-is. The current core source already satisfies FHIR-15688 after the original application and later category cleanup, and adding patient-specified or discharge back into MedicationRequest.category would conflict with the resolved split and later exemplar value set decisions.
