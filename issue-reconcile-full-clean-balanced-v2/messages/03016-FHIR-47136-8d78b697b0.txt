FHIR-47136: Audit vital signs component Must Support placement

Issue request:
FHIR-47136 is an Applied/Persuasive with Modification OO change request, raised against R4 and applied for R6, asking to remove Must Support from Observation.component for non-Blood Pressure vital signs profiles. The approved resolution was to remove the Observation.component Must Support flag from the Vital Signs Base Profile and add it to the Blood Pressure-specific vital signs profile.

Initial application:
The issue was applied before this reconciliation. Jira comments identify March 2025 application commits, and source history shows 983b8c8cd0 removed base/non-Blood Pressure component Must Support while adding Blood Pressure-specific component profiling, followed by fb9f069dba, 32a93609e2, 51f56178b6, 93350bb259, and e4978f7381 refinements to component constraints and value[x] slicing.

Additional context:
The Observation Vital Signs IG is in current build scope and lists StructureDefinition/vitalsigns, StructureDefinition/bp, and the individual vital sign profiles. The current base vitalsigns differential still mentions Observation.component as an allowed structure, but it does not mark component or component children Must Support; the Blood Pressure profile marks component, systolic/diastolic slices, component.code, component.valueQuantity, and component.dataAbsentReason Must Support. The already-published FHIR-49736 reconciliation fixed the remaining stale base-profile summary text for the same component Must Support family, and the already-published FHIR-48427 reconciliation handled the related base value/result Must Support narrative. FHIR-44721 is linked because the same March 2025 work also changed the base component.valueQuantity binding.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current build-scope source already reflects the FHIR-47136 decision: component Must Support is absent from the Vital Signs Base and non-Blood Pressure vital signs profiles, present in the Blood Pressure profile, and no stale component-specific base summary text remains after the FHIR-49736 follow-up.

Recommendation:
Keep this audit commit as-is. No further core source work is needed for FHIR-47136 unless a future OO decision changes the current profile model; FHIR-44721 should be tracked as the separate binding decision from the same source application family.
