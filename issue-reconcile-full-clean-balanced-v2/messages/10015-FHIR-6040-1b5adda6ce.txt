FHIR-6040: Audit StructureDefinition root overlap handling

Issue request:
FHIR-6040 was a Published/Persuasive with Modification DSTU1 change request about apparent overlap between StructureDefinition metadata and the first root ElementDefinition in snapshot.element. The resolution distinguished StructureDefinition.description from ElementDefinition.definition, treated the then-current name/label overlap as redundant, and directed that ElementDefinition.label, ElementDefinition.code, and ElementDefinition.requirements not be used on a root ElementDefinition by adding an invariant.

Initial application:
The Jira comments record application in SVN revision 5726. The current Git history does not contain an explicit FHIR-6040 commit, but historical release artifacts and current source history show the original broad sdf-9 invariant was carried forward through later source reworks, with label/code/requirements prohibited on root snapshot and differential elements before the later R6 change.

Additional context:
FHIR-48326 is the later Applied/Persuasive R6 decision for the same sdf-9 invariant. It explicitly cites FHIR-6040 and concludes that the code and label portions of the old rationale are flawed because current StructureDefinition no longer has true overlapping root fields for those ElementDefinition values. It retains the requirements prohibition because ElementDefinition.requirements still overlaps StructureDefinition.purpose. The current active StructureDefinition source in source/fhir.ini build scope now matches that later decision: sdf-9 mentions only root requirements, while label/code are no longer prohibited. FHIR-48326 is already represented on the combined branch by commit b77eec34403a5bca4ac9f69b7ea8ca3e11286785, so this commit does not duplicate it.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Reinstating the original FHIR-6040 label/code prohibition would contradict the later applied FHIR-48326 decision, and adding further prose would be redundant because the active source already carries the remaining requirements-only invariant and nearby StructureDefinition root-element guidance.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-6040 unless a future work-group decision revisits whether root ElementDefinition.requirements should continue to be prohibited in favor of StructureDefinition.purpose.
