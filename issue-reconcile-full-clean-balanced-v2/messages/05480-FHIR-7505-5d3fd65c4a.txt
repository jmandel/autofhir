FHIR-7505: Audit FamilyMemberHistory search parameters

Issue request:
FHIR-7505 was Published with a Persuasive with Modification resolution for the DSTU1 FamilyMemberHistory resource. The accepted change requested additional FamilyMemberHistory search parameters for identifier, gender, relationship, and condition.

Initial application:
The issue was applied in git commit 50fdb0bd4ee1aa9505cfe058280227de532cbe5b, whose message says "#7505 - updated the search" and whose FamilyMemberHistory spreadsheet patch populated the requested identifier, relationship, and gender search parameter rows and documented condition-code search. The current source no longer uses the old spreadsheet format, but the generated source bundle keeps the same search-parameter family.

Additional context:
FamilyMemberHistory is active in source/fhir.ini, so source/familymemberhistory/bundle-FamilyMemberHistory-search-params.xml is in current build scope as the resource search-parameter bundle. Later FHIR-17780 renamed FamilyMemberHistory.gender to FamilyMemberHistory.sex; git commit 984e2972b7e7f986862d87deb199a8920570215c and the contemporaneous Zulip thread updated the search parameter from gender to sex accordingly.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current bundle defines token search parameters for identifier, relationship, sex, and the condition-code search parameter as code with expression FamilyMemberHistory.condition.code, which preserves the applied FHIR-7505 intent after the later gender-to-sex rename.

Recommendation:
Keep this audit commit as-is. Do not add a separate gender or condition search parameter unless the work group makes a new decision, because current source already exposes the requested semantics using the current element names and established search parameter code.
