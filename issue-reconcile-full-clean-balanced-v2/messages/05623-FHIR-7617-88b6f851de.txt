FHIR-7617: Audit Condition working status removal

Issue request:
FHIR-7617 was Published with resolution Persuasive with Modification for the DSTU1 Condition resource. It asked whether systems really distinguish Working from Confirmed in Condition.clinicalStatus and requested guidance for systems without an explicit distinction. The approved resolution was to drop "working", use "provisional" instead, and use an extension if an implementation really needs to differentiate.

Initial application:
The historical application is commit 0a6643ad13 ("Split Condition.status {#7581} {#7617} {#7864}"). That commit split the old Condition.status/clinicalStatus content into separate clinicalStatus and verificationStatus concepts, changed examples that had clinicalStatus="working" to active clinical status plus differential verification status, and added the post-split condition-clinical value set. No later source-changing reconciliation is needed for the seed request.

Additional context:
Related status-split trackers FHIR-7581 and FHIR-7864 explain that lifecycle state and verification/confirmation state were separated; FHIR-7851 records the corresponding v2 mapping distinction. Current source has evolved since the 2015 wording: Condition.clinicalStatus is bound to lifecycle codes such as active, recurrence, relapse, inactive, remission, resolved, and unknown, while Condition.verificationStatus is bound to verification codes including provisional and confirmed. The remaining source file valueset-condition-status-present.xml still contains an old "working" concept, but source search finds no active references to that value set except its OID reservation, source/fhir.ini does not list it in current standalone value sets, and build.fhir.org returns 404 for valueset-condition-status-present.html/json.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The current built Condition definition already satisfies FHIR-7617 by omitting "working" from Condition.clinicalStatus and preserving provisional/confirmed under verificationStatus. Editing or deleting the unused condition-status-present residue would not improve current implementer-facing specification behavior and could be a broader cleanup outside this issue.

Recommendation:
Keep this audit commit as-is. If a future cleanup campaign removes obsolete unreferenced terminology source files, valueset-condition-status-present.xml can be reviewed then, but FHIR-7617 itself is already correctly reflected in the current Condition specification.
