FHIR-14564: Audit RelatedPerson communication backbone

Issue request:
FHIR-14564 was a Published PA change request for STU3, resolved Persuasive with Modification. It asked to add language support to RelatedPerson because a RelatedPerson may not be a patient but may still need language documented, captured, or communicated. The approved resolution was to replicate Patient.communication on RelatedPerson, including language and preferred.

Initial application:
The issue appears to have been applied by git commit 9f4ee1f6517d1d69efa4688d649536ff38f3c08f, whose subject was "GF#14564 Add language to RelatedPerson" and whose spreadsheet source added RelatedPerson.communication, RelatedPerson.communication.language, and RelatedPerson.communication.preferred. The old spreadsheet source was later refactored into the current XML resource definition; source/fhir.ini actively lists relatedperson=RelatedPerson, so source/relatedperson/structuredefinition-RelatedPerson.xml is in current build scope.

Additional context:
FHIR-18821 is a duplicate request for the same RelatedPerson communication element, and the PA 2018 Baltimore WGM minutes record the same 11-0-0 Drew/Cooper vote and duplicate relationship. Later FHIR-32003 corrected the initial patient-oriented wording for RelatedPerson.communication and RelatedPerson.communication.preferred; it has already been represented on the combined branch by d0a958af87b085463dfa42b19ca8c965ab55dbcf. Current checked-in RelatedPerson SVG tooltips still contain stale wording, but the SVG is generated-looking diagram material and the authoritative XML source now carries the correct semantics.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build-scoped RelatedPerson StructureDefinition already contains RelatedPerson.communication with 0..* cardinality, a required 1..1 CodeableConcept language child, and a 0..1 boolean preferred child, with wording adapted to the related person.

Recommendation:
Keep this audit commit as-is. No FHIR core source edit is needed for FHIR-14564; if the stale RelatedPerson SVG tooltips are considered important, they should be regenerated or handled under the already-audited FHIR-32003 wording issue rather than as a source-only FHIR-14564 fix.
