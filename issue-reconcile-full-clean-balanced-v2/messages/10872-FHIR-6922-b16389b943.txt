FHIR-6922: Audit Group identifier cardinality

Issue request:
FHIR-6922 is a Published/Persuasive FHIR-core Group change request from the 2015 May ballot asking that Group.identifier allow multiple values, changing the maximum cardinality from 0..1 to 0..* because groups can be defined across multiple systems with multiple identifiers.

Initial application:
The Jira resolution says to make the element 0..* and the comments identify svn revision 5960. Git history contains commit 8f6a995f0557e88eaf35743f1d6a3f24258a8d62, "#6922 - make Group.identifier 0..*", which changed the old source/group/group-spreadsheet.xml row for Group.identifier from 0..1 in the parent to 0..* in the commit.

Additional context:
The current build scope includes Group as an active resource in source/fhir.ini. A related broader DSTU1 identifier-consistency issue, FHIR-5666, supports case-by-case review of identifier repeatability but spans many resources and does not create a separate bounded reconciliation decision here. Jira/Zulip/Confluence searches found no later directly relevant reversal of the Group.identifier max.
