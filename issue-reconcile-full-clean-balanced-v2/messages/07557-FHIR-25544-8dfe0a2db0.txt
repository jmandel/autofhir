FHIR-25544: Audit StructureDefinition cardinality constraint

Issue request:
FHIR-25544 was a Published/Persuasive with Modification R5 FHIR-core issue asking to make it explicit that, when defining a new resource, ElementDefinition.min is limited to 0 or 1 and max is limited to 1 or *. The accepted resolution was to add a StructureDefinition constraint rather than a general ElementDefinition constraint because profiles can use other cardinalities.

Initial application:
The issue was applied in git commit b2634dc630dcba91a636a4bffa3c297ca71fa845, `FHIR-25544 Limit ElementDefnition.min to 0 or 1`, which added StructureDefinition invariant sdf-29 to source/structuredefinition/structuredefinition-StructureDefinition.xml. That initial expression had a derivation/specialization typo, but later Jira FHIR-39166 and commit 79bc579f239eac5af9a155b766c9b0f75bdbcd56 corrected it to `(derivation = 'specialization')`.

Additional context:
source/fhir.ini actively lists StructureDefinition as a current resource and ElementDefinition as a current type page. Current StructureDefinition source contains sdf-29 as a warning on the root StructureDefinition element, references it from kind, derivation, and differential.element, and scopes it to resource and complex-type specializations. FHIR-I minutes for 2020-01-20 show FHIR-9283 was rejected with a follow-up ticket to limit minOccurs to 0..1, and minutes for 2020-01-27 record FHIR-25544 as Persuasive with Modification for a StructureDefinition constraint. A 2022 Zulip thread about sdf-29 led to FHIR-39166's expression correction, not to a change in the underlying cardinality rule.

AutoFHIR reconciliation:
No source change was made. The current active source already contains the corrected sdf-29 cardinality constraint requested by FHIR-25544, and a targeted scan found no current resource or complex-type specialization differential elements with min outside 0/1 or max outside 1/*.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-25544 unless a future work-group decision changes the sdf-29 rule or its warning severity.
