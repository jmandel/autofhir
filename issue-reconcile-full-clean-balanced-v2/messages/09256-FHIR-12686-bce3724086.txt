FHIR-12686: Audit sdf-7 XPath correction

Issue request:
FHIR-12686 is Published/Persuasive for FHIR-core StructureDefinition schemas/schematrons. It asked to correct the sdf-7 schematron XPath so the logical-model exception used f:kind/@value = 'logical' rather than f:derivation/@value = 'logical'; the Jira resolution was to correct the schematron path.

Initial application:
The issue was applied by git commit 1553de3d6d748b5151eb605c290e71ad10b0ce1f, the git-svn mirror of svn revision 11394 noted in Jira. That commit changed StructureDefinition's source spreadsheet XPath from f:derivation/@value = 'logical' to f:kind/@value = 'logical' in both the sheet text and spreadsheet XML. Earlier commit 4457108370 had introduced the intermediate, still-wrong derivation-based logical check, which explains the Jira report.

Additional context:
The generated historical STU3 StructureDefinition profile now contains the corrected sdf-7 XPath with f:kind/@value = 'logical'. The old spreadsheet source was later removed, and FHIR-17185/GF#17185 deliberately dropped sdf-7 while updating adjacent StructureDefinition invariants for non-HL7-originated structure definitions. Current source/fhir.ini lists StructureDefinition as an active resource, but the current StructureDefinition source no longer contains sdf-7 or the obsolete schematron XPath target. A Zulip implementers thread from 2016 records the same bug report and Grahame Grieve's confirmation that the XPath was wrong; Confluence searches found no conflicting decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The requested XPath correction is already present in the relevant historical generated artifact, and the current active source has moved past that invariant, so editing current core source would either be redundant or would reintroduce a retired constraint.

Recommendation:
Keep this audit commit as-is. No current core source fix is needed for FHIR-12686; only revisit if a future build reintroduces sdf-7 or a schematron XPath for the same StructureDefinition URL rule.
