FHIR-14951: Audit chained search warning

Issue request:
FHIR-14951 was a Published/Persuasive FHIR-core search change request for STU3. It asked to add a warning to Chained Parameters explaining that chained parameters are applied independently to the target resource; for example, Patient?general-practitioner.name=Joe&general-practitioner.address-state=MN can match a Patient whose matching name and matching address belong to different practitioners.

Initial application:
The issue was applied in git-svn commit 066d5651b05bedffe21a1fc177387289d1a81e5e, corresponding to the Jira comment "svn revision 13412". That commit added the chained-search warning, the general-practitioner example, and pointers to Composite search parameters and _filter in source/search.html.

Additional context:
The current Search narrative page is in build scope through source/hierarchy.xml, where search.html is listed under RESTful API. Later same-section issues refined but did not reverse the FHIR-14951 rule: FHIR-34023 reworded the example for R5 and is already represented on the combined branch, and FHIR-52942 later expanded the same paragraph to spell out the independent set-building and Patient-level AND join.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/search.html already contains the requested warning and now states that each chained parameter is evaluated individually, that a Patient seeing Dr. Joe in California and Dr. Jane in Minnesota matches, that implementations find separate Patient sets and join them with AND at the Patient level, and that Composite search parameters or _filter can be used when grouped joins are required.

Recommendation:
Keep this audit commit as-is. The current source satisfies FHIR-14951 after the original application and later same-family clarifications, so no further core source work is recommended for this issue.
