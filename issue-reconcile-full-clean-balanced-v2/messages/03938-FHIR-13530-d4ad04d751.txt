FHIR-13530: Audit Condition unconfirmed verification status

Issue request:
FHIR-13530 was Published/Persuasive for STU3 Patient Care work. It requested adding an unconfirmed Condition.verificationStatus code that subsumes provisional and differential, with the definition "There is not sufficient diagnostic and/or clinical evidence to treat this as a confirmed condition."

Initial application:
The request was applied in git commit 1afa3503ac4fcef5a2d591f73dc5a1a143a1da25, which added unconfirmed to the Condition condition-ver-status spreadsheet, made provisional and differential children of that new code, and updated the Condition.verificationStatus short display. Later terminology refactoring moved the authoritative CodeSystem content out of core source and left the active core ValueSet as an include of the THO condition-ver-status CodeSystem.

Additional context:
The active Condition resource is in source/fhir.ini, source/condition/structuredefinition-Condition.xml still binds Condition.verificationStatus required to http://hl7.org/fhir/ValueSet/condition-ver-status and lists unconfirmed, provisional, and differential in the element short, and source/condition/valueset-condition-ver-status.xml includes http://terminology.hl7.org/CodeSystem/condition-ver-status. THO CodeSystem version 2.0.1 contains unconfirmed as a parent of provisional and differential. Later applied issues FHIR-32479 and FHIR-32480 intentionally changed the unconfirmed and confirmed definitions to remove tautological wording, so the current THO definition need not match FHIR-13530's original sentence exactly.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build obtains the requested code and subsumption hierarchy from THO through the active Condition verification status ValueSet, and duplicating the CodeSystem content in core would be wrong after the THO migration.

Recommendation:
Keep this no-change audit commit. No core source follow-up is needed for FHIR-13530; future work about definition wording should stay with the already-audited later terminology issues or THO/UTG if a new final decision is made.
