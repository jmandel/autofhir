FHIR-41225: Audit ExampleScenario actor definition reference

Issue request:
FHIR-41225 was an Applied FHIR-I change request resolved Persuasive with Modification. It asked to let ExampleScenario actors refer to ActorDefinition by adding ExampleScenario.actor.definition 0..1 canonical(ActorDefinition), making ExampleScenario.actor.type 0..1, and requiring exactly one of actor.type or actor.definition.

Initial application:
The issue was first applied in commit b7141f572474eaca235597fe385c4f5dc3e31a64, which added ExampleScenario.actor.definition, relaxed ExampleScenario.actor.type, and introduced the exs-24 type/definition XOR invariant. PR #3299 merged that work with related ActorDefinition and ExampleScenario changes. PR #3307 then carried a follow-up "part of FHIR-41225" correction that changed actor.definition from Reference to canonical, matching the Jira comment that the reference should be a canonical URL.

Additional context:
Both examplescenario and actordefinition are active core resources in source/fhir.ini and ExampleScenario is assigned to FHIR-I, so source/examplescenario/structuredefinition-ExampleScenario.xml is in current build scope. The related FHIR-42807 audit already confirmed that the later comment on actor.definition is correct and that no further source change is needed for the same ActorDefinition link family. The FHIR Workflow minutes from 2023-06-12 record the FHIR-41225 persuasive-with-modification decision, and targeted Zulip searches found no conflicting discussion.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The invariant tests include failure cases for both type+definition and neither type nor definition.
