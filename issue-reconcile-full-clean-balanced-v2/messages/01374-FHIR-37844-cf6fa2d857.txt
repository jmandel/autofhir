FHIR-37844: Audit NamingSystem profile migration

Issue request:
FHIR-37844 was a Published/Persuasive Vocabulary change request for R5 asking to define Shareable and Publishable NamingSystem profiles based on the shared Shareable and Publishable patterns.

Initial application:
The request was applied before this reconciliation. PR #2068 was merged as 0d4401be, with implementation commit 93fadfaa adding source/namingsystem/structuredefinition-profile-shareablenamingsystem.xml and source/namingsystem/structuredefinition-profile-publishablenamingsystem.xml and registering them in source/namingsystem/implementationguide-NamingSystem-core.xml. The checked-in R5 history bundle still contains StructureDefinition/shareablenamingsystem and StructureDefinition/publishablenamingsystem entries, confirming the R5 publication surface.

Additional context:
A later Applied/Persuasive issue, FHIR-37959, changed the current R6 direction: remove Shareable/Publishable/Computable/Executable profiles from core FHIR and maintain them going forward in the Canonical Resource Management IG. Confluence minutes for the May 2025 joint Vocabulary/CDS/CQI session record the 16-0-0 decision that these profiles should remain in CRMI because core is moving away from including quickly evolving profiles. Commit 8c199a9c removed the NamingSystem profile StructureDefinition files and emptied their NamingSystem core IG registrations. Current source/namingsystem/implementationguide-NamingSystem-core.xml has an empty definition section; current source has no shareablenamingsystem or publishablenamingsystem StructureDefinition source files and no active profile-id references outside historical R5 and OID records.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding the NamingSystem profiles to core would reverse the later FHIR-37959 R6 decision rather than completing FHIR-37844. The remaining profile introduction note files are not backed by profile StructureDefinitions or active IG resource entries, so they do not justify a seed-source change for this R5 application issue.

Recommendation:
Keep this audit as-is for FHIR-37844. Do not reintroduce the core NamingSystem profile source unless the work group revisits FHIR-37959 or the CRMI ownership decision. Any remaining cleanup of inert profile-note source files or core-to-CRMI references should be handled under the already represented FHIR-37959 migration work, not this R5 application issue.
