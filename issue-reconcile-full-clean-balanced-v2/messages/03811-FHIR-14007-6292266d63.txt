FHIR-14007: Audit Condition and Allergy harmonization

Issue request:
FHIR-14007 was a Published/Persuasive Patient Care STU3 change request to change Condition.asserter's w5 mapping to who.source, add Condition.recorder 0..1 Reference(Practitioner | Patient | RelatedPerson) mapped to who.author with recorder-focused text, update AllergyIntolerance.recorder to allow RelatedPerson, and add the AllergyIntolerance.assertedDate comment clarifying that it records when the allergy record was created in the EHR plus a v2 IAM-13 mapping.

Initial application:
The issue appears to have been applied by git commit 52ac1cc0e7288f26eca9df7e2fb559dcbcbc1efd on 2017-11-13. That commit explicitly mentions #14007 and its patch adds Condition.recorder, changes Condition.asserter's w5 mapping from who.author to who.source, adds RelatedPerson to AllergyIntolerance.recorder, adds the AllergyIntolerance.assertedDate comment, changes its v2 mapping to IAM-13, and tags the affected source with GF#14007 committee notes.

Additional context:
The current build-scope source is no longer the original STU3 spreadsheets. AllergyIntolerance and Condition are active resources in source/fhir.ini, and fhir.ini maps the R3 assertedDate name to the current recordedDate name. Current source/condition/structuredefinition-Condition.xml has active Condition.recorder and Condition.asserter elements with FiveWs.author and FiveWs.source mappings respectively. Current source/allergyintolerance/structuredefinition-AllergyIntolerance.xml has AllergyIntolerance.recordedDate with the intended creation-date semantics and IAM-13 mapping, and AllergyIntolerance.recorder includes RelatedPerson. Later Patient Care decisions changed the same area: FHIR-34395 temporarily replaced recorder/asserter with participant, FHIR-39602 restored Condition.recorder and Condition.asserter, FHIR-39513/FHIR-44517 restored AllergyIntolerance.recorder and AllergyIntolerance.asserter, FHIR-41403 added Group to Condition recorder/asserter, and FHIR-48804 clarified recorder definitions. Related reconciliation commits for the overlapping later issues are already present on the combined branch, so this audit does not duplicate them.
