FHIR-18673: Audit canonical URL clarification

Issue request:
FHIR-18673 was Published/Persuasive with Modification for STU3. It asked to clarify confusing canonical URI wording, keep the canonical datatype because it carries canonical-reference expectations beyond plain uri syntax, explain that a canonical reference resolves to a canonical resource instance using url plus optional version, keep resource .url elements as uri rather than renaming them, and avoid using "canonical" as an unqualified noun.

Initial application:
The Jira comment records git 6f7c3716ef, and commit 6f7c3716ef8e176e5ea811ceb12844b81a3904ec is titled "GF#18673 - clarify language around canonical URLs". That commit updated the canonical datatype row, references.html canonical URL section, ValueSet/CodeSystem narrative, and other conformance-resource wording from ambiguous canonical URI language toward canonical URL and canonical reference terminology.

Additional context:
Current build-scope source keeps ValueSet active through source/fhir.ini and now has broader canonical-resource guidance. Later related audits already on the combined branch checked adjacent ValueSet and CodeSystem wording, canonical target-list guidance, canonical display guidance, canonical version/hash parsing, and canonical version uniqueness without finding a reversal of FHIR-18673. FHIR-15744 and FHIR-14691 explain older "canonical URI" wording, but their current audit commits treat FHIR-18673 as the later terminology decision that should not be undone.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current canonical datatype definition links to canonical resources with url properties, explains the vertical-bar version suffix and fragment handling, and states that canonical is not the datatype of the target canonical URL itself. The current references page says canonical references use the canonical datatype to refer to the url element, documents the {{CanonicalResource.url}}|{{CanonicalResource.version}} form, and limits canonical(Any) targets to canonical resources. The current ValueSet source describes ValueSet.url as the canonical URL while retaining uri syntax and target-of-canonical-reference wording, so the seed clarification is already represented.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-18673 unless a future work-group decision reopens the cross-cutting canonical URL/canonical reference terminology policy.
