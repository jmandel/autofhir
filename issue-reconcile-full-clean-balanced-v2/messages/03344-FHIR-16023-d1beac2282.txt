FHIR-16023: Audit OID regex alignment

Issue request:
FHIR-16023 was Published/Persuasive with Modification for the STU3 datatype page because datatypes.html showed OID regex [0-2](\.[1-9]\d*)+ while profiles-types.xml used a looser oid.value regex. The approved resolution was to use [0-2](\.(0|[1-9][0-9]*))+.

Initial application:
The issue was applied by git-svn commit 8f4b0e6555542518ecbc96bafa30e32eaa3b364d, labelled "GF#16023 - fix oid regex" and SVN revision 14079. That commit changed source/datatypes.html and source/datatypes/primitives.xml to the approved OID pattern.

Additional context:
Current source/datatypes.html now renders the primitive regex through [%regex oid%], and source/datatypes/primitives.xml is the current authoritative primitive datatype source containing urn:oid:[0-2](\.(0|[1-9][0-9]*))+. Current release history snapshots for R4/R4B/R5 also contain the corrected generated profiles-types regex. The old regex remains only in tools/history/release2 and release3 snapshots, which represent historical publications rather than current source to edit.

AutoFHIR reconciliation:
No source change was made. The current build inputs already implement the approved resolution, and editing historical release snapshots would not be a current-spec correction.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for the current FHIR source unless a separate work-group decision asks to revise historical release snapshots or change the OID datatype regex again.
