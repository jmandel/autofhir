FHIR-39132: Audit CodeableReference ambiguity resolution

Issue request:
FHIR-39132 was a Published FHIR-core R5 change request resolved Persuasive. It asked to clarify an ambiguous CodeableReference narrative sentence by changing "If they are specified on both" to "If they are specified on both the CodeableConcept and the .reference or .concept" so readers would not think "both" meant only the child .reference and .concept elements.

Initial application:
The issue was explicitly applied in git commit af5f22e7cfac05593b3bd86d61c2a3cc21a53734 on 2023-02-14, which changed source/references.html to the proposed wording. The current reconciliation branch contains that implementation, but later same-paragraph work changed the active text so the proposed sentence is no longer rendered.

Additional context:
source/fhir.ini actively lists CodeableReference as a datatype and maps codeablereference to the references page, so source/references.html is current build-scoped source for this narrative. FHIR-39176 changed the same paragraph from SHOULD NOT to SHALL NOT to match StructureDefinition constraints sdf-24 and sdf-25. FHIR-38957 later clarified that targetProfile and binding constraints declared on CodeableReference apply to CodeableReference.reference and CodeableReference.concept respectively, while preserving the SHALL NOT rule. The FHIR-I 2022-11-14 minutes confirm the FHIR-39132 vote, and no conflicting Zulip or Confluence evidence was found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active CodeableReference paragraph no longer contains the ambiguous "If they are specified on both" sentence; it states directly that targetProfile and binding constraints declared on CodeableReference apply to CodeableReference.reference and CodeableReference.concept respectively and SHALL NOT be specified directly on .reference or .concept. The old proposed sentence remains only inside an HTML comment and does not change rendered specification guidance.

Recommendation:
Keep this empty audit commit as-is. No FHIR-core source follow-up is needed for FHIR-39132 unless a future work group decision changes CodeableReference profiling policy.
