FHIR-20841: Audit StructureMap source defaults

Issue request:
FHIR-20841 was a Published/Persuasive with Modification FHIR-I change request for the FHIR Mapping Language and StructureMap. It asked to stop representing StructureMap.group.rule.source.defaultValue[x] as a polymorphic value and instead represent embedded FHIRPath consistently as a single string-valued StructureMap.group.rule.source.defaultValue; the resolution also required embedded FHIRPath expressions in the mapping language, including default values, where, check, and log, to be surrounded by parentheses.

Initial application:
The issue was applied before this reconciliation. Commit 53e50e29332ff33bf433b294bb5d3bc1717f76ba, "FHIR#20841 - StructureMap.group.rule.source.defaultValue should be of type string", updated the mapping-language prose, images/mapping.g4, and the then-current StructureMap spreadsheet source. After the source tooling changed, commit 7ce61e3bb680a17f7e4777211028c126e553b17a, "Reapplied changes for FHIR#20841 after tooling change", changed the current StructureMap XML source from defaultValue[x] with many datatype choices to defaultValue with a single string type.

Additional context:
StructureMap is an active resource in source/fhir.ini, and mapping-language.html is linked from source/hierarchy.xml, so the inspected XML, mapping-language page, and linked grammar are current build inputs. The latest combined branch has StructureMap.group.rule.source.defaultValue as a single string, mapping-language examples and grammar notes use default ([value]), where ([FHIRPath]), check ([FHIRPath]), and log ([expression]), and images/mapping.g4 uses parenthesized FHIRPath productions for default, where, check, and log. A later R6 issue, FHIR-57220, asked to broaden defaultValue again for mappable FHIRPath datatypes, but it was Resolved - No Change/Retracted, so it does not reverse FHIR-20841. FHIR-20844 was applied in the same StructureMap change family for target parameter value choices and is already represented separately on the combined branch.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change because the current authoritative core source already satisfies FHIR-20841: source.defaultValue is no longer a choice element, its only type is string, and the current mapping-language documentation and grammar require parentheses around embedded FHIRPath expressions.

Recommendation:
Keep this audit commit as-is. No follow-up core source work is needed for FHIR-20841 unless a future work-group decision reopens the legacy grammar compatibility question or changes the defaultValue representation again.
