Issue request:
FHIR-5966 was a Published/Persuasive DSTU1 Structured Documents change request asking that Composition.section.content be moved before the nested Composition.section.section element.

Initial application:
The issue was applied in git commit c5e4c8a2aa3483544ef4138d2295510606589c46, whose subject says "Composition section content should come before a nested section 5966". The parent source had Composition.section.section before Composition.section.content in source/composition/composition-spreadsheet.xml; the commit reordered the primary spreadsheet rows so Composition.section.content came first.

Additional context:
Current FHIR source no longer uses the DSTU1 element name Composition.section.content in the active Composition resource; the equivalent data reference is Composition.section.entry. source/fhir.ini actively includes composition=Composition, and source/composition/structuredefinition-Composition.xml places Composition.section.entry before Composition.section.section. Later source refactoring commits that introduced the current StructureDefinition XML preserved that ordering. The legacy CDA profile still has Composition.section.content before Composition.section.section, but its fhir.ini profile entry is commented out, so it is not a current build target for this reconciliation.

AutoFHIR reconciliation:
No source change was made. The current active Composition StructureDefinition already conveys the requested order: section entry/content appears before nested section.

Recommendation:
Keep this no-change audit commit. No follow-up is needed in core unless a future build reactivates the legacy CDA profile or changes the Composition section ordering source.
