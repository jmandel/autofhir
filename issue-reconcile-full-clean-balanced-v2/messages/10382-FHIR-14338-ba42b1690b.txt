FHIR-14338: Audit empty search parameter handling

Issue request:
FHIR-14338 was a Published/Persuasive STU3 FHIR-core change request asking the search specification to state how servers handle query parameters with no value, such as `...?subject=&code=foo`. The accepted resolution was that empty parameters are not an error and are ignored by the server.

Initial application:
The issue was applied in svn revision 12842, imported as git commit 58df405880b593872420484b91c84090c77590a3, which added the empty-parameter note to source/search.html. A same-day cleanup capitalized the note, and the 2022 search-page rewrite retained it with Lloyd McKenzie's suggested wording, "not an error".

Additional context:
The current active search page still contains the rule in the Handling Errors section, and publish.ini includes search.html in the published page list. The originating Zulip thread records the same rationale: empty-valued HTML form parameters should be ignored, while `:missing=true` is the search mechanism for absent data. A later implementer thread quoted the current note as the answer, and Jira/Zulip/Confluence searches found no later conflicting decision.

AutoFHIR reconciliation:
No source change was made. The current source already conveys the accepted rule that empty search parameters are ignored rather than rejected.

Recommendation:
Keep this audit commit as-is. No follow-up is needed unless a future work-group decision intentionally changes empty search parameter semantics.
