FHIR-19911: Audit MedicationStatement status binding names

Issue request:
FHIR-19911 was a Published/Persuasive with Modification Pharmacy change request raised in STU3 for R5 asking to fix the value set binding name for MedicationStatement.status. The resolution broadened the check to bindings that had been changed away from value sets defined in the build spreadsheets and specifically called out fixing the status bindings for MedicationAdministration and MedicationDispense to clear a QA error.

Initial application:
The Jira comment records application by merge commit aa42e5dcc1 on 2019-02-18. The merged child commit 9d4a0fe093 changed the historical spreadsheet/value-set sources, including renaming the MedicationStatement status value set from Medication Status Codes to MedicationStatement Status Codes and adjusting the Pharmacy status-code spreadsheet. Those spreadsheet files are no longer current source inputs, but their applied result is represented in the current StructureDefinition and ValueSet XML.

Additional context:
source/fhir.ini actively lists MedicationAdministration, MedicationDispense, and MedicationStatement as current resources. Later Pharmacy decisions changed the MedicationStatement status semantics and resource naming: FHIR-38682 renamed MedicationUsage back to MedicationStatement, and FHIR-39271 clarified that MedicationStatement.status is the recording status while adherence carries taking/not-taking semantics. The combined branch already contains the FHIR-39271 reconciliation commit d5e940beb2. FHIR-55338 is a later unresolved request about an escape-valve code for MedicationStatement.status, so it is not a final change to the FHIR-19911 binding-name decision.

AutoFHIR reconciliation:
This audit makes no source change. The current active MedicationStatement status element has bindingName MedicationStatementStatus and valueSet http://hl7.org/fhir/ValueSet/medication-statement-status, and the active value set is named MedicationStatementStatusCodes with title/description MedicationStatement Status Codes. The current MedicationAdministration.status and MedicationDispense.status elements also bind to their distinct required status value sets, so the applied binding-name fix remains present.

Recommendation:
Keep this no-change audit. No further core source work is needed for FHIR-19911; future changes to the allowed MedicationStatement.status codes should wait for a final decision on later issues such as FHIR-55338 rather than being mixed into this historical binding-name fix.
