FHIR-40448: Correct PaymentNotice reporter description

Issue request:
FHIR-40448 was Published/Persuasive for R5 by FM and requested three PaymentNotice corrections: fix the identifier short description typo from "noctice" to "notice", change PaymentNotice.payment from 1..1 to 0..1, and rename PaymentNotice.provider to PaymentNotice.reporter with the description "Entity reporting payment".

Initial application:
The Jira-tagged commit 2be1440043170cc0df19d0f270235e5d232d262d applied most of the issue by fixing the identifier typo, changing PaymentNotice.payment min cardinality to 0, renaming the StructureDefinition element and example XML from provider to reporter, and adding the R4-to-current rename map in fhir.ini. However, that commit left the reporter element short description as the old "Responsible practitioner" wording and used only a fuller reporter definition sentence, so the generated element summary remained stale.

Additional context:
PaymentNotice is an active current-build resource in source/fhir.ini, and source/fhir.ini records the historical PaymentNotice.provider to PaymentNotice.reporter rename. The current source and published/build profile surfaces already show the corrected identifier spelling and 0..1 payment cardinality, but they still expose "Responsible practitioner" as PaymentNotice.reporter.short. The PaymentNotice event mapping exception source mirrors the same reporter short string, so it needed to stay consistent with the authoritative StructureDefinition source. Later PaymentNotice commits touched other elements and did not reverse this reporter decision. Quoted Zulip and Confluence searches found no community record changing the Jira/source conclusion.

AutoFHIR reconciliation:
This commit updates the authoritative PaymentNotice.reporter short description to "Entity reporting payment" and updates the matching PaymentNotice event mapping exception resource value. It intentionally leaves the reporter definition sentence unchanged because it already states the reporting role in a complete ElementDefinition definition form, and it leaves the identifier typo, payment cardinality, element rename, example rename, and fhir.ini rename mapping unchanged because those parts were already correctly applied.

Recommendation:
Keep this source fix. No further core FHIR source action is needed for FHIR-40448 beyond normal generated artifact refresh by the build; related Jira keys sharing the historical implementation commit should be evaluated separately if they are selected as their own reconciliation seeds.
