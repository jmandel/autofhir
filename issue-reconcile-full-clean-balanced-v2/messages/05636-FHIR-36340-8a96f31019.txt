FHIR-36340: Use TQ1-9 in ServiceRequest V2 mapping

Issue request:
FHIR-36340 was a Published/Persuasive OO change request for R5 asking that the ServiceRequest V2 mapping table use hyphen notation between v2 segment and field numbers, and that the performerType typo RF!-3 be corrected to RF1-3. The listed separator examples included ORC fields and TQ1.9, which should be TQ1-9.

Initial application:
The issue was applied in commit 920033196d497180b7d8579ebae5a1f733561ab2 and merged via HL7/fhir#2186. That commit corrected the listed ORC separator strings in source/servicerequest/structuredefinition-ServiceRequest.xml, and current source already has RF1-3, but the active ServiceRequest priority V2 mapping still used `TQ1.9, RF1-2`.

Additional context:
FHIR-36340 was found while checking the same Zulip and OO block-vote trail as FHIR-36341. The linked Zulip thread explicitly says the ServiceRequest priority mapping should be TQ1-9 and confirms hyphen-for-field notation. ServiceRequest is an active resource in source/fhir.ini; other resources with similar inherited request-family mapping text are outside this issue's ServiceRequest scope.

AutoFHIR reconciliation:
Changed the active ServiceRequest priority V2 map from `TQ1.9, RF1-2` to `TQ1-9, RF1-2`. No broader request-family or historical release files were changed.
