FHIR-27547: Audit overlapping value set guidance scope

Issue request:
FHIR-27547 was Published/Persuasive with Modification. It asked whether a value set may include nearly overlapping codes from different systems, using the proposed HL7 v3 PurposeOfUse plus ISO 14265 PurposeOfUse value set as the motivating case. MnM guidance was to document why such overlap is included and the consequences for downstream translation and UI lookup, with the approved action to add guidance to the Confluence Guide to Designing Resources.

Initial application:
No source commit or current source comment was found that explicitly mentions FHIR-27547. Current core source does not define a combined HL7-v3-plus-ISO PurposeOfUse value set: the active bindings inspected still point to the HL7 Terminology v3 PurposeOfUse value set, while the separate NHIN example value set is listed only as an example and notes that it is derived from but not compatible with the HL7 v3 code system.

Additional context:
The linked security issue FHIR-24676 was later Published with a narrower resolution: instead of creating a combined overlapping value set, security PurposeOfUse bindings were loosened to example where appropriate so ISO codes can be used without forcing overlap in the base value set. Current AuditEvent and Provenance authorization elements reflect that pattern and explicitly say their security context is not restricted to the purposeOfUse value set. The MnM minutes confirm the FHIR-27547 vote, and no directly relevant Zulip or Confluence guidance page search result was found beyond those minutes.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The approved FHIR-27547 action targets external MnM/Confluence design guidance, not a current built FHIR core source file, and the current core source no longer contains the overlapping PurposeOfUse value set design that prompted the request. Adding duplicate guidance to security or terminology pages would be broader than the approved source scope and could drift from the external design guidance.

Recommendation:
Keep this external-repo audit as-is for the FHIR core source checkout. If MnM still wants durable guidance about overlapping code systems in value sets, create or update the Guide to Designing Resources/other design-governance material outside this current build; do not introduce a combined PurposeOfUse value set in core as part of this issue.
