FHIR-39034: Audit Subscription parameter application

Issue request:
FHIR-39034 was a Published/Persuasive R5 FHIR-core Subscription change request asking to replace the string collection Subscription.header with a repeatable Subscription.parameter backbone element containing required string children name and value, with repeated parameter names allowed and channel-specific handling.

Initial application:
The change appears to have been applied by git commit c7ec1674c87447bafbfc174e4c9f1902670c49c4, "FHIR-39034 - Change header into key-value pairs", which replaced Subscription.header in the Subscription StructureDefinition, updated the admission example from a header string to parameter.name/parameter.value, and changed the REST hook narrative to refer to Subscription.parameter.

Additional context:
Subscription is an active resource in source/fhir.ini, so source/subscription/structuredefinition-Subscription.xml and the listed Subscription examples are in current build scope. Later Subscription edits preserved the parameter element, and FHIR-I WGM minutes recorded agreement that implementations would benefit from changing to key-value pairs. A later Zulip subscriptions thread from the issue assignee described the header-to-parameter change as intended to enable more complicated authorization flows. Jira searches found no later conflicting final issue for this exact header/parameter replacement.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current active StructureDefinition defines Subscription.parameter 0..* as a BackboneElement with required string name and value children, the comment preserves the repeated-name/channel-specific restriction point, the REST hook narrative maps parameters to HTTP headers, and the active admission example uses Authorization/Bearer as parameter.name/value. Current source searches found no remaining build-scope Subscription.header reference; an old unreferenced proposal text file and Endpoint.header are outside this issue's current build-scope fix.

Recommendation:
Keep this no-change audit commit as-is. No FHIR-core source follow-up is needed for FHIR-39034 unless a future work-group decision changes Subscription notification parameter semantics.
