FHIR-13553: Audit eld-11 Extension removal

Issue request:
FHIR-13553 was a Published/Persuasive FHIR-core ElementDefinition change request from STU3. It noted that ElementDefinition.binding described value-set binding for coded elements and string/uri, while invariant eld-11 also allowed type Extension, and the final resolution was to remove "Extension" from eld-11.

Initial application:
The Jira comments record svn revision 13330 and "already done". In the git-svn history, commit 7508d2f2cbc6e6e4b77037539465e714c045a3d0 corresponds to build@13330 and removed `(code = 'Extension')` and `Extension` from the FHIRPath and XPath forms of eld-11 in source/datatypes/elementdefinition.xml.

Additional context:
ElementDefinition is an active datatype in source/fhir.ini, and elementdefinition is mapped to the ElementDefinition page, so source/datatypes/elementdefinition.xml is in current build scope. Later FHIR-30085 added Duration to the same invariant; that later change is already represented on the combined branch and does not reintroduce the Extension allowance that FHIR-13553 removed. Exact-key Zulip and Confluence searches found no community evidence that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current combined source still omits Extension from eld-11 and permits only code, Coding, CodeableConcept, Quantity, string, uri, Duration, empty type lists, or external type codes; the ElementDefinition.binding definition also does not mention Extension.

Recommendation:
Keep this audit commit as-is for FHIR-13553. No current FHIR-core source correction is needed for the Extension binding question; any future editorial alignment around Duration belongs to the later FHIR-30085/future-issue trail, not this STU3 Extension removal.
