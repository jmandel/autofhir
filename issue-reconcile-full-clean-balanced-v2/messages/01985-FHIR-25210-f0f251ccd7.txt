FHIR-25210: Audit CarePlan activity search parameters

Issue request:
FHIR-25210 was a Published FHIR-core CarePlan change request, resolved Persuasive with Modification for R5. It asked to replace the CarePlan activity-date date search parameter whose expression selected scheduled[x] including string, rename it to activity-scheduled-date with only Timing and Period choices, and add an activity-scheduled-string search parameter for the string choice.

Initial application:
The issue was applied in git commit 6947f33720ee371e1b2ab3c29b350831ebaeb547, which changed the then-current source/careplan/careplan-spreadsheet.xml search tab from activity-date to activity-scheduled-date and added activity-scheduled-string with the requested type-filtering expressions. A May 2020 implementers Zulip thread identified the same concern and confirmed the current build had been fixed by that commit.

Additional context:
CarePlan is an active build resource in source/fhir.ini. The current source no longer has the old spreadsheet file; CarePlan search parameters live in source/careplan/bundle-CarePlan-search-params.xml. Later FHIR-39101 removed CarePlan.activity.plannedActivityDetail for R5, and commit 0222d171b0466cb633dce3342278e3da94cfd815 commented out the plannedActivityDetail-derived search parameters, including the two scheduled parameters created for FHIR-25210. Parsing the current XML finds only activity-reference as an active CarePlan activity search parameter and zero active plannedActivityDetail elements, so the original string-to-date mapping is not present in current built source.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because the requested correction was applied historically, and the later removal of plannedActivityDetail means there is no active CarePlan activity-date or activity-scheduled-date search parameter that can still map a string choice to a date search parameter.

Recommendation:
Keep this audit commit as-is for FHIR-25210. Do not reintroduce the scheduled search parameters while plannedActivityDetail remains out of the current CarePlan model; any cleanup of old commented plannedActivityDetail source or examples belongs with the separate FHIR-39101 change family, not this issue.
