FHIR-20328: Audit Provenance agent role distinction

Issue request:
FHIR-20328 was Published/Not Persuasive with Modification for R5. It asked whether Provenance.agent.type and Provenance.agent.role overlapped too much, rejected constraining the flexible core model, and directed clearer definitions/comments using structural and functional role concepts while acknowledging that some vocabulary overlap can remain.

Initial application:
The issue was initially applied through security branch commit d417c5d674 and merge 3845b72a87, which changed source/provenance/provenance-spreadsheet.xml from the older generic wording. That application made agent.type the primary act of participation and added an overlap/ISO 21298 note, while agent.role became functional or structural roles with PRIMAUTH/REVIEWER/VERF examples; it did not leave the STU3 wording unchanged.

Additional context:
Later final Security WG issues FHIR-28184 and FHIR-32453 revisited the same ambiguity and more precisely settled Provenance.agent.type as the functional role/how the agent participated and Provenance.agent.role as structural/security roles. FHIR-32519 and FHIR-32520 then cleaned the companion bindings and value sets; their reconciliation commits are already on the combined branch. A 2020 Zulip discussion also records the intended split as functional workflow codes in agent.type and structural role/competency codes in agent.role. Later FHIR-53882 is AuditEvent-only and does not reopen Provenance.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Provenance is active in source/fhir.ini, and the current source/provenance/structuredefinition-Provenance.xml already reflects the later, more precise issue-family outcome: agent.type is a functional role with a preferred participation-role-type binding, while agent.role is structural/security role text with an example structural-role binding.

Recommendation:
Keep this audit commit as-is. Do not restore the literal 2019 wording from FHIR-20328 because it has been superseded and refined by later final Security WG decisions; only revisit if a future Provenance-specific issue intentionally loosens the ISO 21298 functional/structural distinction.
