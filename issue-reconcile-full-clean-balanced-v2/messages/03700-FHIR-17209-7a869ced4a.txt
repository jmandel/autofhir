FHIR-17209: Align special measures ModelInfo

Issue request:
FHIR-17209 was Published/Persuasive for R5 and asked that MedicinalProduct.specialMeasures stop being a string and use CodeableConcept because the use case needs a coded term with value and OID.

Initial application:
The request was applied in git commit e14c2059ec7797ff05d19cc2960372c6958002ef, which changed the then-authoritative MedicinalProductDefinition spreadsheet row from string to CodeableConcept and restored the plural specialMeasures name. The current MedicinalProductDefinition StructureDefinition already has specialMeasures as 0..* CodeableConcept, so the main resource definition did not need another edit.

Additional context:
The current build lists medicinalproductdefinition as an active resource and redirects the retired MedicinalProduct name to MedicinalProductDefinition. The active FHIR ModelInfo Library attachment under source/library still included the retired MedicinalProduct.specialMeasures element as a list of FHIR.string, and nearby AutoFHIR ModelInfo commits show this attachment is being reconciled as current source evidence rather than ignored generated output. Zulip and Confluence searches found no substantive discussion that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit updates source/library/library-fhir-model-definition-content.xml and the embedded base64 data in source/library/library-fhir-model-definition.xml so the ModelInfo entry for specialMeasures is a list of FHIR.CodeableConcept. No change was made to MedicinalProductDefinition itself because it already matches the published issue request.

Recommendation:
Keep this commit as-is. It preserves the already-correct resource definition while removing the remaining active ModelInfo inconsistency that could mislead CQL/modelinfo consumers about the datatype of specialMeasures.
