FHIR-6181: Audit code datatype regex correction

Issue request:
FHIR-6181 was a Published/Persuasive FHIR-I DSTU1 technical correction saying the code datatype regex `[^\s]+([\s]+[^\s]+)*` was wrong because it allowed multiple whitespace characters in the middle of a code even though the prose allows no whitespace other than single spaces. The requested correction was to tighten the middle separator to a single whitespace occurrence.

Initial application:
The Jira comment records svn revision 5627. In git history this is commit e98f119211c45993a393fafe1f38b00a0d079b02, `#6181 - fix code regex`, which changed `source/datatypes/primitives.xml` from `[^\s]+([\s]+[^\s]+)*` to `[^\s]+([\s][^\s]+)*` for the code primitive regex.

Additional context:
Later Published code-regex issues refined the same rule. FHIR-9031 repeated the multiple-whitespace concern and was applied at svn revision 7984 with an optional-whitespace pattern. FHIR-13764 then removed that catastrophic optional-whitespace structure, and FHIR-25413/FHIR-37406 moved the current source to the stricter literal-space regex `[^\s]+( [^\s]+)*`. Those later FHIR-13764, FHIR-25413, and FHIR-37406 decisions are already represented on the combined branch. Current `source/datatypes/primitives.xml` is the authoritative primitive source, and `source/datatypes.html` uses `[%regex code%]` under active datatype page routing in `source/fhir.ini`.

AutoFHIR reconciliation:
This empty audit commit records that no current core source change is needed for FHIR-6181. The old multiple-whitespace regex no longer appears in active datatype source, and the current regex accepts single spaces while rejecting double spaces, tabs, newlines, leading whitespace, trailing whitespace, and empty values.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-6181 in core FHIR; any future reconsideration of code whitespace should be handled as a new work-group decision rather than reverting this applied correction.
