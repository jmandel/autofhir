FHIR-3504: Audit extension value xor sub-extension rule

Issue request:
FHIR-3504 was Published/Persuasive for FHIR-core extensibility. It asked whether an Extension may carry both value[x] and child extensions, and the accepted resolution was to clarify that an extension has either a value or child extensions, but not both.

Initial application:
The requested narrative appears to have been applied before this reconciliation by 1902100d7d on 2015-03-15, which inserted "but not both" in source/extensibility.html. A later 2016-07-17 source commit, ae218b8ca5, added the corresponding Extension invariant "Must have either extensions or value[x], not both" with FHIRPath and XPath checks. Later source refactors and editorial updates preserved the same rule.

Additional context:
source/fhir.ini lists Extension as an active infrastructure type and maps the Extension type page to extensibility, so source/extensibility.html and source/datatypes/extension.xml are current build inputs. Later Zulip discussions distinguished an Extension's own child extensions from extensions on the value[x] element, confirming that the root Extension rule remains while values may carry their own extensions. No Confluence reference or later Jira/community search result was found that reverses the FHIR-3504 rule.
