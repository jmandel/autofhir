FHIR-16354: Audit CodeSystem subsumes extension status

Issue request:
FHIR-16354 was a Published/Persuasive with Modification STU3 Vocabulary issue for FHIR-core CodeSystem. It asked why the codesystem-subsumes extension was a modifier extension, requested removal of confusing "also" wording, and was resolved to make the extension non-modifier, define it as referring to a different descendant concept, note polyhierarchy issues in the is-a definition, and avoid inconsistency with CodeSystem property-based subsumption relationships.

Initial application:
The issue was applied in git commit 473c56983d9d307e467f1e5ef12a716163a5ef6f, which changed source/codesystem/codesystem-extensions-spreadsheet.xml so codesystem-subsumes was no longer a modifier and replaced the modifier rationale with polyhierarchy/subsumption wording. The same commit updated source/codesystem/codesystem-spreadsheet.xml is-a wording to mention additional subsumption relationships, though the text still referred to the old extension.

Additional context:
The historical extension spreadsheet was removed during later build/source refactoring, and current source no longer contains a codesystem-subsumes extension definition in core or in the FHIR Extension Pack input definitions. Later Published issues FHIR-19307 and FHIR-31671 refined the same area: FHIR-19307 removed the normative assertion that additional parents must use the trial-use subsumes extension and replaced it with property-based hierarchy guidance, while FHIR-31671 removed the stale is-a sentence because the extension no longer exists. FHIR-18645, FHIR-19307, and FHIR-31671 are already represented on the combined branch, so this commit does not duplicate those decisions.
