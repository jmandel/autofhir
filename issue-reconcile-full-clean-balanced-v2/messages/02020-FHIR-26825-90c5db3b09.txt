FHIR-26825: Audit MedicationKnowledge cost date range

Issue request:
FHIR-26825 was Published with resolution Persuasive with Modification for R5. It asked to add a date range to MedicationKnowledge.cost so old prices, price types, bands, and current price applicability could be represented; the resolution text identified the needed capability as a cost date range and named MedicationKnowledge.cost.period.

Initial application:
The issue appears to have been applied by commit 603de50396, which included FHIR-26825 among several Pharmacy changes and added MedicationKnowledge.cost.effectiveDate as a 0..* Period with date-range short and definition text in the then-authoritative MedicationKnowledge spreadsheet. The current StructureDefinition source was later produced by source rework commit 33b409a4b6 and preserves the same effectiveDate Period element.

Additional context:
MedicationKnowledge is active in the current build scope in source/fhir.ini. The current source has MedicationKnowledge.cost.effectiveDate with type Period, max *, and definitions saying it is the date range for which the medication cost is effective. The name differs from the resolution's suggested MedicationKnowledge.cost.period path, but it carries the requested semantics and has been the published application path; changing it now to period would be a breaking rename without discovered Jira, Zulip, or Confluence evidence requiring that change. A Jira neighborhood search found FHIR-31365 in the same resource/cost area, but that issue concerns packaging cost/identifier cardinalities and does not alter this decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already provides the requested repeatable cost date range through MedicationKnowledge.cost.effectiveDate.

Recommendation:
Keep this audit commit as-is. Revisit only if the Pharmacy work group opens an explicit issue to rename the published effectiveDate element or otherwise change MedicationKnowledge cost semantics.
