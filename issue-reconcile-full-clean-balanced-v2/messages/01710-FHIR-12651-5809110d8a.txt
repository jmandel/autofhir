FHIR-12651: Audit Composition.subject minimum cardinality

Issue request:
FHIR-12651 was a Published/Persuasive FHIR-core Structured Documents request to make Composition.subject minOccurs=0. The issue argued that base Composition should not require a subject for every possible document because FHIR documents are not always patient-centric and may be about things that do not have a sensible resource instance.

Initial application:
The issue appears to have been applied before this reconciliation. Commit 520fd2a49849fbe29582967aec4b9dbce948d9f0 changed the then-current Composition spreadsheet source from Composition.subject 1..1 to 0..1. Later source refactoring preserved the minimum of 0 in source/composition/structuredefinition-Composition.xml.

Additional context:
Composition is an active current-build resource in source/fhir.ini. Later Published issue FHIR-37801 broadened only the maximum cardinality from 1 to * for multiple regulatory document subjects; the combined reconciliation branch already contains an audit commit for FHIR-37801. Duplicate issue FHIR-13760 raised the same non-patient-centric Composition.subject concern. No human Zulip or Confluence discussion directly conflicting with the FHIR-12651 source state was found.

AutoFHIR reconciliation:
No source change was made. The active Composition StructureDefinition already defines Composition.subject with min 0, and the later max * change is consistent with, not a reversal of, the FHIR-12651 relaxation.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed for FHIR-12651 unless SDWG later decides to revisit Composition.subject cardinality or clinical-document profiling separately.
