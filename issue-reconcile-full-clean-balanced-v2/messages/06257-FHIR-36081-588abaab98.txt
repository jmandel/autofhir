FHIR-36081: Remove stale subscription event count

Issue request:
FHIR-36081 was Published with resolution Persuasive with Modification for R5. It requested simplifying notification URL location by removing Subscription.notificationUrlLocation, tightening SubscriptionStatus.notificationEvent.focus guidance for empty/id-only/full-resource notifications, and, per the Jira comment, removing the now-unneeded SubscriptionStatus.eventsInNotification element.

Initial application:
The main application was git commit c1d340d7c8 ("FHIR-36081 - simplify notification url placement"), which deleted Subscription.notificationUrlLocation, deleted the subscription URL location terminology, removed SubscriptionStatus.eventsInNotification from the resource definition and notes, added SubscriptionStatus notificationEvent guidance, and added the initial event-notification invariant. Later source still retained one commented-out eventsInNotification line in the $status response example.

Additional context:
Subscription and SubscriptionStatus are active current-build resources in source/fhir.ini. The $status OperationDefinition includes $status-response.txt, which in turn includes source/subscription/subscription-status-response.xml, so the stale commented element was in build scope. Current authoritative Subscription and SubscriptionStatus StructureDefinitions and notes otherwise reflect the issue. A raw SVG diagram still contains a historical eventsInNotification string, but no non-SVG source reference to that diagram was found and diagram/SVG-only artifacts are not the authoritative source for this reconciliation.

AutoFHIR reconciliation:
Removed the commented-out <eventsInNotification value="0"/> line from source/subscription/subscription-status-response.xml so the included $status response example no longer names a deleted SubscriptionStatus element. No other source change was needed.

Recommendation:
Keep this commit. It completes the already-applied FHIR-36081 source cleanup by removing the last build-included non-SVG reference to the deleted element; no work-group review is needed for this narrow correction.
