FHIR-12054: Audit document Bundle identity and version semantics

Issue request:
FHIR-12054 was Published with a Persuasive with Modification resolution for DSTU2. It asked for explicit FHIR document Bundle identifier, document date, and document version semantics that do not depend on mutable REST metadata such as Bundle.id, Bundle.meta.lastUpdated, or Bundle.meta.versionId. The resolution recorded that Bundle.identifier was now on the latest Bundle and that a Composition versionId extension would be explored in C-CDA on FHIR for possible core use.

Initial application:
No git commit explicitly names FHIR-12054. The identifier portion was implicitly applied through the closely related FHIR-12162 work in 88db4c7805d907c61bc750d3694adeaadb784063, which changed the document narrative to use Bundle.identifier. Current Bundle source defines Bundle.identifier and Bundle.timestamp with document-specific semantics, and current document narrative names Bundle.identifier and Bundle.timestamp as the mandatory document identifier and date.

Additional context:
FHIR-12162 is the same-change-family issue that added Bundle.identifier. FHIR-13356 later addressed ClinicalDocument versionNumber as a standard Composition extension, and later R5 work added Composition.version with a CDA .versionNumber mapping. FHIR-34407/FHIR-38201 then concluded the old ClinicalDocument versionNumber extension was no longer needed for R5/R6 because Composition.version exists. The extension-pack checkout still carries composition-clinicaldocument-versionNumber for pre-R5 use, while current core Composition has the base version element.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because current core source already conveys the identifier and date rules, and current Composition.version plus the pre-R5 extension-pack artifact cover the versionNumber thread without requiring a new Bundle element in core.

Recommendation:
Keep this audit commit as-is. Future work should not add redundant core Bundle version prose for this old DSTU2 issue unless a new work group decision changes the post-R5 Composition.version approach or asks for a distinct document Bundle version element.
