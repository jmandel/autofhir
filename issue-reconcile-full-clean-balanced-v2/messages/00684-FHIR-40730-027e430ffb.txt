FHIR-40730: Audit external CodeSystem authoritativeSource deprecation

Issue request:
FHIR-40730 was an Applied FHIR-core Vocabulary change request asking whether codes in http://hl7.org/fhir/StructureDefinition/codesystem-authoritativeSource needed clarification and whether they were actual codes rather than references to other concepts. The final Persuasive with Modification decision was to deprecate the extension because it was poorly defined and CodeSystem information is available in THO.

Initial application:
No source-changing FHIR-core commit directly tagged FHIR-40730 remains in the current core checkout. The extension was originally added to core in the R5 vocabulary batch that introduced codesystem-authoritativeSource, then core commit dd468d4f17 removed the extension definitions from R5 source as part of the move of extensions out of core. The applied FHIR-40730 work is in the FHIR Extension Pack: commit 2d8d674 added deprecated standards-status to codesystem-authoritativeSource, and later commit 3daa870 refined that deprecation to point to the replacement artifact-authoritativeSource extension.

Additional context:
Current core source/fhir.ini has active generic extension spreadsheet entries but no active profile entry for codesystem-authoritativeSource, and searching core source finds only the historical OID registration plus unrelated uses of the phrase authoritative source. The current Extension Pack definition is retired/deprecated, says to use artifact-authoritativeSource instead, and notes that external code system information can be found in THO or HTA pages. Later published Extension Pack issues FHIR-56275 and FHIR-56401 created the artifact-authoritativeSource replacement and explicitly updated the CodeSystem deprecation message.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR-core source change. The artifact FHIR-40730 concerns is now owned by the FHIR Extension Pack, where the requested deprecation and later replacement guidance are already present; editing core would either miss the authoritative source or only disturb registry/OID data that should continue to preserve the canonical URL.

Recommendation:
Keep this audit commit as-is for the core reconciliation. If future work is needed, make it in the FHIR Extension Pack, but no immediate follow-up is recommended because the extension-pack source already carries the deprecation and replacement guidance.
