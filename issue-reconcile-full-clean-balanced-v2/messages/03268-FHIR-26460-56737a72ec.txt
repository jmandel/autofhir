FHIR-26460: Audit Coding-to-CodeableConcept migration

Issue request:
FHIR-26460 was a Published/Persuasive BRR change request for R5 asking that Coding elements in medication definition resources be changed to CodeableConcept unless there was a good reason not to. The named resources were MedicinalProductDefinition, SubstanceDefinition, PackagedProductDefinition, AdministrableDefinition/AdministrableProductDefinition, and ManufacturedItemDefinition.

Initial application:
The issue was explicitly applied in March 2020 across five FHIR-26460 commits. Those commits changed source spreadsheets for SubstanceDefinition.structure.sourceCoding, PackagedProductDefinition.package.characteristic, multiple MedicinalProductDefinition coded elements, AdministrableProductDefinition.characteristic.value[x], and ManufacturedItemDefinition.characteristic.value[x]. The current source has since been reworked into StructureDefinition XML, and the active target resource definitions now have no remaining bare Coding types except MedicinalProductDefinition.code.

Additional context:
The remaining MedicinalProductDefinition.code Coding was not missed by FHIR-26460; it was added later by the Published/Persuasive with Modification FHIR-31794 decision, whose resolution explicitly requested a 0..* coding attribute alongside identifier. Commit e640618988 added that element as Coding 0..* and later FHIR-31794 commits clarified the identifier/code distinction. The combined branch already contains the FHIR-31794 audit commit b22faf4d10cc76f807013099a1a1c60b5634926e, so this reconciliation should not duplicate that issue. A 2026 terminology Zulip discussion also records Lloyd McKenzie's rationale that MedicinalProductDefinition.code is a list of equivalent codes for the product rather than a CodeableConcept needing separate original text.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Changing MedicinalProductDefinition.code to CodeableConcept under FHIR-26460 would conflict with the later, more specific FHIR-31794 resolution, while all other build-scoped medication definition resources checked for this seed already satisfy the Coding-to-CodeableConcept migration.

Recommendation:
Keep this audit commit as-is. The current FHIR source is correct for FHIR-26460 when the later FHIR-31794 decision is considered; future questions about MedicinalProductDefinition.code should be handled under a specific code-vs-CodeableConcept tracker rather than by reopening the broad 2020 migration.
