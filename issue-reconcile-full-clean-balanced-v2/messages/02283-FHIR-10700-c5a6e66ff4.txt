FHIR-10700: Audit Consent privacy scope

Issue request:
FHIR-10700 was a Published DSTU2 Consent change request noting that privacy Consent use cases should not be limited to "sharing" and should also recognize collection, use, and disclosure. The final resolution was Considered for Future Use, with WG vote 14-0-1, saying additional use cases would be considered after STU3.

Initial application:
No Jira-keyed FHIR-10700 commit or current source reference was found. The issue was not applied as a direct source change, but later Consent source history broadened the current text: commit 24a94d5102 changed the privacy directive introduction from an agreement to collect/access/use/disclose into an agreement, restriction, or prohibition to collect/access/use/disclose, and R4B source reconstruction retained a StructureDefinition comment describing privacy consent as authorization to collect, use, or disclose information.

Additional context:
Consent is active in the current build through source/fhir.ini. The current authoritative Consent narrative says the resource covers privacy consent directives to collect, access, use, or disclose/share information, while also saying only the privacy use case is fully modeled and other scopes may evolve. The current StructureDefinition describes Consent as permitting or denying one or more actions, has a provision.action element bound to Consent Action codes with meaningWhenMissing="all actions", and separately records the later tested-scope caution that the only understood/tested action is read. No Zulip or Confluence search result was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already satisfies the part of FHIR-10700 that asked for Consent text to recognize privacy consent beyond sharing, and the Jira disposition did not require adding more detailed current-build modeling for collection/use/disclosure.

Recommendation:
Keep this no-change audit. Future work on broader computable Consent actions should be handled through new or already-open Consent action/modeling issues, not by re-opening this DSTU2 future-use request.
