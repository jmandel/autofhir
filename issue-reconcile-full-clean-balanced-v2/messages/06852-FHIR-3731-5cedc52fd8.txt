FHIR-3731: Audit Patient birthDate date separation

Issue request:
FHIR-3731 was Published with a Persuasive with Modification resolution for the DSTU1 request to separate Patient birth date from birth time. The issue asked to avoid dateTime/timezone handling on the core date-of-birth element and resolved that the date of birth field should change from dateTime to date only.

Initial application:
The Jira-tagged historical commit 782b46a25e changed the legacy Patient spreadsheet source for Patient.birthDate from dateTime to date. Later source refactors moved the authoritative Patient definition into source/patient/structuredefinition-Patient.xml, where the date-only type is preserved.

Additional context:
Patient is active in the current build via source/fhir.ini. Current Patient.birthDate is type date, its short and definition say "date of birth," and its comment points time-of-birth use cases to the standard patient-birthTime extension. Later same-family Jira decisions, especially FHIR-5544 and FHIR-7301, retained the date-only core element and used a standard extension for birth time; FHIR-7301 already has a separate combined-branch audit commit. The patient-birthTime StructureDefinition has since moved from core into the FHIR Extension Pack, where it remains active with Patient.birthDate context and a dateTime value.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current core source already implements the published FHIR-3731 decision, and recreating the moved extension definition in core would be incorrect.

Recommendation:
Keep this no-change audit as-is. No FHIR core follow-up is needed for FHIR-3731 unless a future PA/MnM decision changes the birth-time extension in the Extension Pack.
