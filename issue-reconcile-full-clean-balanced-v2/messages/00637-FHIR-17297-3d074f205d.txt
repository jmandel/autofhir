FHIR-17297: Audit retired DocumentManifest type clarification

Issue request:
FHIR-17297 was a Published/Persuasive SD issue for STU3 DocumentManifest. It asked to clarify DocumentManifest.type as the code for the clinical activity that resulted in placing associated content into the DocumentManifest, remove the Document Type Value Set binding, and use an example ActCode binding because XDS SubmissionSet.contentTypeCode is not a document-type value.

Initial application:
The issue was applied by historical commit 6fbb7de857bcd3b0a9de6efb2f384ccb08b05b92, whose subject was "DocumentManifest GF#17297" and whose git-svn revision matches the Jira comment. That commit changed DocumentManifest.type from the DocumentC80Type binding to v3Act and replaced the old definition with the requested clinical-activity wording.

Additional context:
FHIR-13969 was the same request submitted against the wrong ballot and was closed after being cloned into FHIR-17297. The current core build no longer has an active DocumentManifest resource: source/fhir.ini comments it as dropped, maps DocumentManifest to List, and keeps List as the active resource. The DocumentManifest source was removed by ea941737076615e7e2772299c80c63e1490f2e93, and later FHIR-39006 moved XDS mappings and an XDS example onto List. The related List category extension requested in FHIR-19822 now lives in the FHIR Extension Pack, not in this core checkout.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current specification has no DocumentManifest.type element to correct, and the historical STU3/R4-era request was already applied before DocumentManifest was retired. Changing the broad current List.code definition or binding to reproduce DocumentManifest.type wording would over-apply an old DocumentManifest-specific decision to a different, general-purpose resource.

Recommendation:
Keep this audit commit as-is for FHIR-17297. Any remaining current-spec cleanup around retired DocumentManifest references, List XDS mappings, or the external list-category extension should be handled under their own Jira keys rather than under this historical DocumentManifest.type issue.
