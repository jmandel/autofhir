FHIR-8769: Audit retired enableWhen extension naming

Issue request:
FHIR-8769 was a Published/Persuasive FHIR-core change request for FHIR-core-profiles. It said the old `extension-questionnaire-enablewhen.xml` output incorrectly used `name="Only allow data when:"`; it should use `name="enableWhen"` with `display="Only allow data when:"`.

Initial application:
This was applied in git commit 664f0ce06bae8e4bef6b238cb2573ac979cfe394 (`8769 - adjust default name for extensions`), which changed the spreadsheet parser so short labels would not override an existing extension name and records the corresponding SVN build revision. Jira also records Grahame's application comment for the SVN revision.

Additional context:
The same retired `questionnaire-enableWhen` extension appears in historical release content, but current source no longer defines it as an active extension. Current Questionnaire source has native `Questionnaire.item.enableWhen`, and exact current-source searches find the old extension URL only in a DSTU2-to-DSTU3 converter. FHIR-6834 was a same-family rendering correction for the old extension's XML representation.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The historic parser fix was already applied, and there is no active current core or extension-pack `questionnaire-enableWhen` definition whose generated name/display needs correction.

Recommendation:
Keep this no-change audit commit as-is. No current-source follow-up is needed unless a future human specifically chooses to regenerate or annotate historical release artifacts, which is outside current build-scope reconciliation.
