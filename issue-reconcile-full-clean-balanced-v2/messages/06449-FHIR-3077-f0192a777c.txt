FHIR-3077: Audit CarePlan planned activity references

Issue request:
FHIR-3077 was Published with a Persuasive with Modification resolution for DSTU1. It asked that CarePlan.activity.detail describe planned activities/orders, not event resources, so Encounter and Procedure should be removed from that planned-activity reference set and order/request resources such as referral/procedure request, diagnostic order, medication prescription, nutrition order, and supply should be used instead.

Initial application:
No git commit in the current repository history directly mentions FHIR-3077, which is consistent with the issue being applied for the early DSTU1 era. Current source no longer has an active CarePlan.activity.detail element: source/fhir.ini maps the old name to CarePlan.activity.plannedActivityReference, and the active CarePlan resource source constrains plannedActivityReference to request/planning resources rather than Encounter or Procedure.

Additional context:
Later CarePlan decisions refined the same modeling boundary. FHIR-26064 split performed events from planned/requested activities, explicitly allowing Procedure and Encounter only as event references in CarePlan.activity.performedActivity while renaming activity.reference/detail to plannedActivityReference/plannedActivityDetail. FHIR-39101 then removed the inline plannedActivityDetail path and expanded plannedActivityReference to additional request resources. FHIR-34477 temporarily added SupplyRequest to plannedActivityReference, but a later core-source commit removed OO resources, including SupplyRequest, from the current core build.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped CarePlan definition already implements the FHIR-3077 distinction: plannedActivityReference lists request/planning targets and omits Encounter and Procedure, while performedActivity is the element whose narrative permits event resources such as Procedure and Encounter. The remaining old plannedActivityDetail definitions and related example/search-parameter fragments are commented out and not active source semantics.

Recommendation:
Keep this no-change audit commit. Do not re-add Encounter or Procedure to plannedActivityReference. If SupplyRequest support is reconsidered, handle that through the later SupplyRequest/core-incubator issue family rather than FHIR-3077.
