FHIR-5912: Audit MedicationRequest stopped-reason handling

Issue request:
FHIR-5912 was a Published FHIR-core Pharmacy change request, resolved Persuasive for DSTU1, asking to add a MedicationPrescription.reasonEnded CodeableConcept to explain completed, entered-in-error, stopped, superseded, and possibly on-hold statuses. The resolution also records that Pharmacy later wanted the change rolled back if possible and reconsidered with FHIR-8276 and FHIR-8378.

Initial application:
SVN-imported Git commit 3c8466459a1a9319f0d359b0418c84b87592fc16 explicitly applied #5912 by adding MedicationPrescription.reasonEnded to the then-authoritative MedicationPrescription spreadsheet. A later Pharmacy commit, adf4e89f89fd36602f6b6e7520c1025949477424, explicitly removed MedicationOrder.dateEnded and MedicationOrder.reasonEnded under the related event-history decision family and added MedicationOrder.eventHistory. The current source no longer contains reasonEnded or dateEnded.

Additional context:
MedicationPrescription became MedicationRequest and MedicationRequest is an active current-build resource. Current authoritative source contains MedicationRequest.statusReason as a 0..1 CodeableConcept mapped to Request.statusReason, MedicationRequest.statusChanged for the current status-change date, MedicationRequest.eventHistory as Reference(Provenance) for relevant lifecycle transitions, the MedicationRequest status-reason example value set, and an example with status=completed and statusReason. FHIR-14020 later added the workflow statusReason alignment and is already represented on the combined branch, so this audit does not duplicate that issue.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding reasonEnded would contradict the later Pharmacy rollback/event-history path, while current MedicationRequest.statusReason and eventHistory already preserve the implementer-facing capability to say why a medication request has a stopped, completed, on-hold, cancelled, or other current/non-current status.

Recommendation:
Keep this empty audit commit as-is. No FHIR-5912-specific core source edit is needed; future changes to MedicationRequest.statusReason cardinality, wording, bindings, or event-history semantics should be handled under the later Jira issue that approves that specific change.
