FHIR-7980: Audit Resource identifier language

Issue request:
FHIR-7980 was Published with a Persuasive, non-substantive clarification for DSTU1. It asked to fix unclear BaseResource language where the phrase "literal" appeared only in the "Business Identifier" section, making it ambiguous whether the specification was referring to Resource.id/logical identity or Resource.identifier/business identifiers.

Initial application:
The issue was applied in svn revision 6469, preserved in git commit 1e51376ec558bf14cc3c0926410609002322315b with subject "#7980 - improve language about identifiers". That commit rewrote source/resource/resource-notes.xml to distinguish logical id, literal identity/location, and business identifiers instead of treating the identity/id wording as interchangeable.

Additional context:
The current Resource page source has evolved since the original DSTU1 wording. It now introduces Resource Identity as two routes: a Location URL based on the Logical ID, and inherent identifiers such as Business Identifier or Canonical URL. The active Resource infrastructure entry in source/fhir.ini confirms this is build-scope source. The closely related FHIR-7982 request for a business-identifier search example was applied one svn revision later and is already represented on the combined branch, so this reconciliation does not duplicate it.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/resource/resource-notes.xml already uses a dedicated "Logical ID" section for the id element and a separate "Business Identifiers" section for identifier-based identity, which resolves the ambiguity reported by FHIR-7980. Adding more explanatory prose would be redundant and risk drifting from later identity guidance.

Recommendation:
Keep this empty audit commit as-is. No follow-up source work is needed for FHIR-7980 unless the work group wants a broader editorial rewrite of Resource identity terminology beyond the published 2015 clarification.
