FHIR-46005: Audit Patient.deceased description as already applied

Issue request:
FHIR-46005 was an Applied/Persuasive PA change request for R6 asking that Patient.deceased no longer be described only as a boolean. The approved resolution updated the definition to "Indicates the date when the individual died, or, if the date is not known or cannot be estimated, a flag indicating the patient is known to be deceased." and the short display to "Indicates if/when the individual is deceased".

Initial application:
The change was already applied by git commit 5c7031e3d470da172746e2b54a3657c27e306996, which replaced the old Patient.deceased short display and definition in source/patient/structuredefinition-Patient.xml with the approved Jira text. The combined branch contains that application commit.

Additional context:
source/fhir.ini has patient=Patient in the active [resources] list, so source/patient/structuredefinition-Patient.xml is build-scoped source. A later same-element Jira, FHIR-53438, explicitly relied on the current short display and found the existing semantics clear enough for a no-change future-date request. A repository search still finds the old Patient wording in source/patient/patient.svg, but that is a generated-looking SVG tooltip; the authoritative Patient StructureDefinition source is correct. The same old wording also appears on Person.deceased, which is a boolean-only element and is outside this Patient-specific Jira.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active Patient StructureDefinition already matches the approved FHIR-46005 resolution, and editing only the checked-in SVG would violate the generated-artifact guardrail without changing the authoritative source semantics.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-46005; if reviewers separately require checked-in resource SVGs to be refreshed, that should be handled through the normal generation process rather than as this issue's source fix.
