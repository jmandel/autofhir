FHIR-13300: Audit NamingSystem Medicare id fix

Issue request:
FHIR-13300 was Published/Persuasive for STU3 and reported that source/namingsystem/namingsystem-registry.xml had two Bundle entries whose NamingSystem resources both used id us-ssn; the Medicare entry was expected to use us-medicare.

Initial application:
The issue appears to have been applied by svn revision 12609, now git commit ae17b6dedb88d7f0bcecd9bdcebce023a07f49f5, which changed the old us-medicare NamingSystem entry id from us-ssn to us-medicare. The Jira comment records that same revision.

Additional context:
FHIR-16002 later reported the same duplicate-id problem and was also marked Published/Persuasive with an "already fixed" comment. Later FHIR-37889 removed the old NamingSystem registry and terminologies bundles from current core examples because that content is authoritatively maintained in HL7 Terminology; the current build lists only individual NamingSystem examples and the terminology module links to identifier-registry.html for known identifier-system guidance.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The exact historical duplicate was corrected in the old registry source, and the current core source no longer includes namingsystem-registry.xml or the removed registry bundle, so there is no remaining current-build defect to fix for FHIR-13300.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for the old duplicate id; if a future problem is found in HL7 Terminology's current external registry, it should be handled in that external terminology governance/source path rather than by restoring or editing the removed core bundle.
