FHIR-49105: Audit DeviceDefinition publisher search parameter

Issue request:
FHIR-49105 is an Applied/Persuasive R6 OO change request to replace the DeviceDefinition organization search parameter with a publisher string search parameter over DeviceDefinition.publisher and DeviceDefinition.contact.name.

Initial application:
The change was preapplied in b50e9309dc by changing the old owner/reference search parameter to a string expression over DeviceDefinition.contact.name and DeviceDefinition.publisher. Commit 62decc7761 finished the Jira application by renaming the id, url, code, and description to DeviceDefinition-publisher/publisher.

Additional context:
FHIR-49105 is tightly coupled to FHIR-49107 because the search parameter relies on DeviceDefinition.contact being ContactDetail and therefore having .name. It also follows FHIR-46252, which removed owner and adopted CanonicalResource publisher/contact semantics. Later Jira comments and 2025-02-03 OO minutes note that reopening was no longer needed because the publisher search parameter resolved the ambiguity.

AutoFHIR reconciliation:
No source change was made. DeviceDefinition is active in source/fhir.ini, and source/devicedefinition/bundle-DeviceDefinition-search-params.xml already defines an active string SearchParameter with id DeviceDefinition-publisher, code publisher, and expression DeviceDefinition.contact.name | DeviceDefinition.publisher.

Recommendation:
Keep this no-change audit commit as-is. The current source already implements the requested publisher search parameter, and no separate organization/reference search parameter fix is required.
