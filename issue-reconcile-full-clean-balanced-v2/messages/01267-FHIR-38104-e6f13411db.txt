FHIR-38104: Audit ValueSet filter value clarification

Issue request:
FHIR-38104 was an Applied/Persuasive Vocab change request asking that ValueSet.compose.include.filter.value be clarified as a string whose expected lexical form depends on the filter operation and CodeSystem-defined filter/property, and that decimal be added to the CodeSystem properties table.

Initial application:
Commit 09caaf636406cf39544c443f4b55bbf33e78cfdf applied the issue as part of a bundled terminology update by replacing the old ValueSet.compose.include.filter.value definition with the requested three-case text and adding decimal to the CodeSystem property type details. Later source history refined the same area: FHIR-44866 moved the element definition to a link to valueset.html#filter-values and added a detailed syntax section, and FHIR-51117 refined in/not-in value handling.

Additional context:
The current source/fhir.ini has CodeSystem and ValueSet as active normative/conformance resources, so source/codesystem and source/valueset are in current build scope. FHIR-44866 and FHIR-51117 are Applied issues that extend the original clarification to cover property data types, Coding syntax, ordered search prefixes, and in/not-in code-list or ValueSet URI forms. FHIR-48831 is a Triaged unresolved follow-up that questioned the original FHIR-38104 wording, but its comments record that the submitter considered the concern resolved by later work, likely FHIR-51117. No Zulip discussion was found for the seed query; Confluence tracker minutes record the 2023-11-27 change-required resolution path.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current ValueSet element definition still states that filter.value is represented as a string and links to the build-scoped filter-values section. That section covers regex, exists, in/not-in, concept, CodeSystem.filter, and CodeSystem.property cases; its property-type table covers string, integer, boolean, dateTime, decimal, code, and Coding, with search prefixes for ordered types. The current CodeSystem properties table includes decimal, and the CodeSystem filter/search-prefix text includes decimal alongside integer and dateTime. Restoring the literal three-bullet FHIR-38104 wording would lose later approved clarification.

Recommendation:
Keep this no-change audit as-is. Do not add redundant local prose for FHIR-38104 unless a future final Vocab decision reopens the unresolved FHIR-48831/related-ticket thread and requires a new source change.
