FHIR-17771: Audit ICD-10 variant OID correction

Issue request:
FHIR-17771 was a Published/Persuasive technical correction for STU3 Vocabulary content reporting that paragraph 4.2.11.2 had the ICD-10-NL and ICD-10-DE OIDs reversed. The requested correction was to identify ICD-10-NL as 2.16.840.1.113883.6.3.2 and ICD-10-DE as 1.2.276.0.76.5.409.

Initial application:
The specific Jira key is not present in git history, matching the Jira comment that the problem was already fixed. Historical source shows the original ICD page introduced the correct NL and DE values in 2017, then GF#13123-era commits removed the German system URL/OID from the core page after German community feedback while retaining the correct Netherlands OID. The current source no longer has source/icd.html at all.

Additional context:
The current build references source/sid-icd-10.html and source/terminologies-systems.html from publish.ini. source/sid-icd-10.html describes only the international ICD-10 system URL, and source/terminologies-systems.html delegates ICD-9/10 details to the HL7 Terminology Using ICD page instead of listing the old national variant OID table. Later commit FHIR-35933 deleted the old ICD variants page, and FHIR-41305 made a later ICD URI-column correction that is already represented on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The reversed ICD-10-NL/DE OID statement is absent from current build-scoped core source, and the only current in-repository references to the two OIDs found outside the old page label 1.2.276.0.76.5.409 as ICD-10-DE and 2.16.840.1.113883.6.3.2 as ICD-10-NL.

Recommendation:
Keep this audit commit as-is. No core source edit is needed for FHIR-17771; any future detailed ICD national-variant maintenance should be handled in the terminology source of truth rather than by reviving the retired core ICD variants page.
