FHIR-12201: Audit Timing dayOfWeek support

Issue request:
FHIR-12201 was Published/Persuasive for DSTU2 and asked for a way to express medication schedules on specified weekdays such as Monday, Wednesday, and Friday. The approved resolution added Timing.repeat.dayOfWeek as 0..* code with a required DayOfWeek binding, definition that the action happens only on specified days when present, and a comment that absence of days means every day as otherwise specified.

Initial application:
The issue was applied in svn revision 10350, represented in git as 91bf3e7b836dc9486da4c4d4b7829d9df7167900, a grouped Timing commit for FHIR-10478, FHIR-12201, and FHIR-12352. That commit added Timing.repeat.dayOfWeek to source/datatypes/timing.xml with 0..* cardinality, code type, DayOfWeek binding, weekday code summary, the approved definition, and the missing-day comment.

Additional context:
Timing is an active core datatype in source/fhir.ini, so source/datatypes/timing.xml is in current build scope. Current source still contains the requested dayOfWeek element and required binding; the DayOfWeek binding resolves to the days-of-week ValueSet/CodeSystem with mon through sun codes, and the Timing narrative table includes a Mon/Wed/Fri example. Later FHIR-12460 intentionally relaxed the original Timing constraints so dayOfWeek can coexist with frequency and period, and FHIR-25289/FHIR-23710 are already represented on the combined branch for related stale Timing comment cleanup. Direct FHIR-12201 Zulip and Confluence searches found no conflicting community record.
