FHIR-15679: Audit search parameter FHIRPath expressions

Issue request:
FHIR-15679 was Published/Persuasive for STU3 and asked that generated search-parameters.json expressions stop using obsolete .is()/.as() FHIRPath functions, with Condition abatement-age given as an example. The resolution accepted correcting those statements and explicitly left the separate operator-precedence concern for a different tracker.

Initial application:
The issue was applied in git commit 066aa2229dc6b81e2f31ea04fac2adfa083c6e42, matching the Jira comment for svn revision 14466. That commit changed the generated search-parameter FHIRPath builder in SourceParser.java from .as(Type) calls to parenthesized as operators.

Additional context:
The current build no longer has the old SourceParser path from the 2018 commit, and current checked-in bundle-*-search-params.xml files are the authoritative search-parameter source inputs. SearchParameter is an active resource in source/fhir.ini. Current FHIRPath documentation also describes .as(type) as a legacy simple-FHIRPath alias, so the safe reconciliation target is the specific search-parameter expressions from this issue, not a broad removal of every .as/.is mention in unrelated FHIRPath documentation or constraints.

AutoFHIR reconciliation:
This commit makes no source change. A current-source scan of all 147 source/**/bundle-*-search-params.xml files found zero .as() or .is() calls, and the Jira example now appears as Condition.abatement.ofType(Age) | Condition.abatement.ofType(Range), which avoids the obsolete function syntax.

Recommendation:
Keep this audit commit as-is. No current core source edit is needed for FHIR-15679; future work, if any, should be handled under a separate tracker if the FHIRPath legacy-alias documentation or operator-precedence behavior is intentionally revisited.
