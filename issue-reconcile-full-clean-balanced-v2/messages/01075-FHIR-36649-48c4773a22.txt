FHIR-36649: Audit ImagingSelection coordinate cardinality

Issue request:
FHIR-36649 was Published/Persuasive with Modification for R5 and asked the Imaging Integration work group to change ImagingSelection coordinate cardinality from 1..* to 2..* because even a point requires both x and y coordinate values. The accepted resolution pointed to the grouped IMIN Confluence page for FHIR-36648, FHIR-36649, and the related ImagingSelection coordinate work.

Initial application:
The grouped ImagingSelection update was applied through commit 5c5a620527e102650cad53df57ff594d1706fe2a and merge commit 471fbc468b8fd5427fcebad076569e16590ac707. That implementation split 2D coordinate content under instance.imageRegion2D, retained 3D coordinate content at imageRegion3D, and added the textual requirements that 2D coordinate counts are multiples of two and 3D coordinate counts are multiples of three, but it did not change the coordinate min values in the source to 2 or 3.

Additional context:
ImagingSelection is active in source/fhir.ini, so source/imagingselection/structuredefinition-ImagingSelection.xml is current build scope. Later applied ImagingSelection work in PR HL7/fhir#3729 for FHIR-51645 briefly changed instance.imageRegion2D.coordinate to min 2 and imageRegion3D.coordinate to min 3, then commit 6be488465a4c7d957c5cb8a0f9b0a8d00aa3b816 changed both mins back to 1 before the PR merged. The current source still has required invariants isl-7 and isl-8, so a single 2D coordinate or one/two 3D coordinates remains invalid even though the element cardinality display remains 1..*.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The seed issue's substantive rule that coordinates cannot consist of a lone x value is already enforced by the current build-scoped StructureDefinition through the multiple-of-two and multiple-of-three invariants, and changing the mins now would override later applied source history without a clear later WG decision to reverse that representation.

Recommendation:
Keep this no-change audit for FHIR-36649. If the work group wants the rendered cardinality row itself to show 2..* for 2D and 3..* for 3D, revisit that as a follow-up tied to FHIR-51645/PR 3729 because it would reverse the later merged commit that restored min 1 while preserving the invariant constraints.
