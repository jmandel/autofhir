FHIR-16451: Audit ValueSet expansion size wording

Issue request:
FHIR-16451 was a Published/Persuasive Vocabulary change request for the STU3 ValueSet $expand operation text. It asked that the sentence "If the expansion is too large ..., the server will return an error" be changed so that the server may return an OperationOutcome with code too-costly.

Initial application:
The Jira comments identify svn 14717 as the application. In this git history, commit 7443cef017d9583c7d6555c208dd084f89c267a3 (GF#16451) applied that exact change in source/valueset/valueset-spreadsheet.xml, replacing "will return" with "MAY return". Later source refactoring moved the ValueSet $expand operation text into source/valueset/operationdefinition-ValueSet-expand.xml while preserving the requested MAY wording.

Additional context:
The Vocabulary WG minutes and Zulip block-vote thread list GF#16451 as Persuasive. ValueSet is an active current-build resource in source/fhir.ini, and the authoritative current OperationDefinition source contains the requested MAY wording in both the generated footer text and operation comment. A repository-wide check found the old "will return" wording only under tools/history/release3 historical artifacts, not in current source.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope ValueSet $expand source already reflects the published Jira decision, and editing historical release snapshots would be incorrect.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-16451 unless a future Vocabulary decision changes the $expand too-costly behavior.
