FHIR-35835: Audit ExtendedContactDetail extension contexts

Issue request:
FHIR-35835 was a Published FHIR-core/Patient Administration change request, resolved Persuasive with Modification for R5. It asked that extensions affected by the new ExtendedContactDetail datatype support that datatype: contactpoint-area, contactpoint-comment, contactpoint-country, contactpoint-extension, contactpoint-local, iso21090-TEL-address, and iso21090-preferred.

Initial application:
The issue was applied in core source before this reconciliation. Commit b759378e9a updated source/profiles/iso-21090-spreadsheet.xml so iso21090-preferred changed from Address;ContactPoint to Address;ContactPoint;ExtendedContactDetail, and updated source/datatypes/contactpoint-extensions-spreadsheet.xml so contactpoint-comment changed from ContactPoint to ContactPoint;ExtendedContactDetail. The Jira application comment explicitly notes that the phone-related extensions already applied through the ContactPoint nested inside ExtendedContactDetail, so only preferred and comment needed direct ExtendedContactDetail contexts.

Additional context:
PA WGM minutes for January 2022 record that FHIR-35835 was created and voted persuasive to allow iso21090-preferred on ExtendedContactDetails, satisfying the related preferred-method-of-contact request FHIR-31615. Commit dd468d4f17 later removed the extension rows from the R5 core source. Current core retains only the relevant extension OIDs and an active but row-empty contactpoint extension spreadsheet, while the authoritative extension definitions now live in the FHIR Extension Pack. The current Extension Pack definitions list Address, ContactPoint, and version-gated ExtendedContactDetail contexts for iso21090-preferred, and ContactPoint plus version-gated ExtendedContactDetail contexts for contactpoint-comment. The other listed phone-related extensions still target ContactPoint or ContactPoint.value, which applies to ExtendedContactDetail.telecom because that element is ContactPoint. Later deprecation work for iso21090-preferred changes usage guidance but does not remove the ExtendedContactDetail context.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative extension source already preserves the FHIR-35835 decision, and editing core would either duplicate Extension Pack artifacts or reintroduce extension rows that were intentionally removed from current core source.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed for FHIR-35835; any future changes to these extension definitions should be made in the FHIR Extension Pack, not by editing the retired core spreadsheet rows.
