FHIR-10299: Audit OO event resource alignment

Issue request:
FHIR-10299 was a Published/Persuasive DSTU2 OO change request to ensure event-resource data elements aligned with the event resource template for the then-listed Supply, Alert, Observation, DeviceUseStatement, and DiagnosticReport artifacts. The approved resolution was to align the data elements as described in the attached spreadsheets, and a later Jira comment recorded that remaining workflow-pattern tasks were consolidated into GF#19631.

Initial application:
The issue was applied historically rather than left pending. Commits 5a6e321c64, aa45786302, a61742ca1c, and 1639b8d104 explicitly mention #10299/GF#10299 and changed SupplyDelivery, DeviceUseStatement, DiagnosticReport, Observation, status codes, and event-pattern extension source. A Zulip #committers close-out thread likewise records Eric Haas saying GF#10299 was marked applied and remaining workflow tasks were consolidated into GF#19631.

Additional context:
Current build scope differs from the DSTU2 tracker list. source/fhir.ini actively registers Observation, DiagnosticReport, and Flag, records Alert and Supply as removed resources, and has no active DeviceUsage, DeviceUseStatement, SupplyDelivery, or SupplyRequest resource entries. The workflow page now links DeviceUsage, SupplyRequest, and SupplyDelivery to the OO Incubator rather than active core pages. Later resource-specific decisions have already audited or applied the current workflow family: FHIR-43456 for Observation, FHIR-43443 and FHIR-50597 for DiagnosticReport, FHIR-43452 for SupplyDelivery, FHIR-51713 for DeviceUsage, and FHIR-19631 for the remaining OO workflow umbrella. The Event pattern source also says strict adherence is not mandatory and omissions or domain-specific deviations can be appropriate when reviewed.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current active Observation and DiagnosticReport StructureDefinitions map to Event and contain the checked Event mappings; Flag is not listed as an Event resource; and the old Supply, Alert, and DeviceUseStatement/SupplyDelivery surfaces are removed, renamed, or externalized from active core build scope. Re-opening the broad DSTU2 umbrella would duplicate later resource-specific Jira decisions rather than improve the current specification.

Recommendation:
Keep this no-change audit commit. Future event-pattern work should continue through current resource-specific tickets and, for DeviceUsage/SupplyRequest/SupplyDelivery, the owning OO Incubator or extension-pack source rather than broad edits under this old core tracker.
