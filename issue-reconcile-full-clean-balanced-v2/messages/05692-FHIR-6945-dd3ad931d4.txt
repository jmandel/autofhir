FHIR-6945: Audit CarePlan activity reasons

Issue request:
FHIR-6945 is a Published/Persuasive Patient Care DSTU1 change request for FHIR-core CarePlan. It asked to change CarePlan.Activity.detail.reasonReference from 0..1 to 0..* because a single activity can have multiple reason references, such as obesity and diabetes both justifying diet modification.

Initial application:
The Jira comment cites SVN #6766. The corresponding git-svn commit d6c4981fa8fe7d58cc3e1cc393aa8cc0b6a83c54 updated source/careplan/careplan-spreadsheet.xml and includes CarePlan.activity.detail.reasonReference with cardinality 0..*. The later R4B XML import in c69d71aa213de86d55e0261339c15e4bacd509e6 preserved the active CarePlan.activity.detail.reasonReference element with max="*".

Additional context:
CarePlan is still an active resource in source/fhir.ini, but the current StructureDefinition no longer has an active CarePlan.activity.detail.reasonReference element. The old activity.detail path is mapped to CarePlan.activity.plannedActivityReference, and the legacy plannedActivityDetail subtree in source/careplan/structuredefinition-CarePlan.xml is commented out. Later Patient Care decisions, especially FHIR-26064 and FHIR-39101, renamed/refactored the activity model and then removed CarePlan.activity.plannedActivityDetail from the active resource. FHIR-28546 is a later no-change decision confirming that the inline detail reasonReference is no longer applicable in R5 and that reasons for referenced activities belong on the referenced request resources.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The original cardinality change was applied, no active current source still has a stale 0..1 CarePlan activity reasonReference, and the current absence of that active element is explained by later published Patient Care refactoring decisions rather than by a missed FHIR-6945 application.

Recommendation:
Keep this audit commit as-is. No core FHIR follow-up is needed for FHIR-6945; future concerns about reasons on activities represented through CarePlan.activity.plannedActivityReference should be handled on the referenced request resource or through a new Patient Care decision.
