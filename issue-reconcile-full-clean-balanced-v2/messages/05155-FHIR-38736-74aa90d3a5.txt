FHIR-38736: Allow definition table cells to wrap

Issue request:
FHIR-38736 was a Published/Persuasive OO change request for R5 reporting that word wrap was missing on the Task detailed definitions page at https://www.hl7.org/fhir/task-definitions.html. The issue was non-substantive and accepted as proposed.

Initial application:
No prior source commit or current-tree reference mentioning FHIR-38736 was found. The active Task definitions page is generated from the standard definitions template, and the current source stylesheet for dictionary tables lacked a wrap rule for long generated strings.

Additional context:
Task is active in source/fhir.ini, and tools/templates/template-definitions.html emits the dictionary table used by task-definitions.html. The published R5 page and the current CI page both load fhir.css and show table class="dict" for the detailed descriptions, with long generated FHIRPath and element/type strings that can force table overflow without explicit wrapping. Corrected Zulip and Confluence searches found no directly relevant discussion or conflicting work-group guidance.

AutoFHIR reconciliation:
Added overflow-wrap/word-wrap to tools/templates/fhir.css for table.dict td so generated detailed-definition cells can break long content instead of expanding beyond the page width. This is the shared build-scope stylesheet for resource detailed-description pages, so it fixes Task and the same generated table pattern without changing conformance content.

Recommendation:
Keep this source fix. It is non-substantive presentation behavior matching the Published Jira request and should be included wherever the FHIR specification templates are used to render dictionary definition tables.
