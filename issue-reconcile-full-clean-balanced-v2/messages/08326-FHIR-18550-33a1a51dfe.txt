FHIR-18550: Audit search logging warning

Issue request:
FHIR-18550 was Published/Persuasive for STU3 and asked the HTTP search section to repeat security guidance warning that required GET/POST search support can expose sensitive search parameters and PHI in request URLs and client/server HTTP logs. The approved resolution was "Repeat as requested."

Initial application:
The issue appears to have been applied by Grahame Grieve's commit 06e4aba5d2d49c420d28c6cc77b35484baa9830b, "GF#18550 - note about securing logs," which added a note to source/http.html that PHI can appear in search parameters and HTTP logs, logs should be treated as sensitive as the resources, and the security page has further commentary.

Additional context:
Later search-method work changed the surrounding conformance wording. FHIR-31943 was Published/Not Persuasive with Modification for R5 and clarified that servers supporting HTTP search support both GET and POST modes but can return 405 for either method, not both; it also explicitly warned that neither GET nor POST is inherently more secure and implementers must verify logging protection for PHI. Commit e441170220c19e992f803667b245e63dcdd508cf for FHIR-39137 moved the search protocol content into source/http.html while preserving and broadening the FHIR-18550 warning. Negative Zulip and Confluence searches found no conflicting community evidence.
