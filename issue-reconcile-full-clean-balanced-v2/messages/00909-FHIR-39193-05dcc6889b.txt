FHIR-39193: Audit removed RSG international equivalent slice

Issue request:
FHIR-39193 was a Published FHIR-core change request resolved Persuasive with Modification for R5. It asked to remove the internationalEquivalent element from the recordedSexOrGender extension because the CodeableConcept value can carry translations, and its resolution also directed deletion of the ICAO value set and code system that were only used by that extension property.

Initial application:
The issue appears to have been applied before this reconciliation by core commit 2955956df2e4fcd1b456c4f0249f07ee6b6f2de7, which deleted the ICAO CodeSystem and ValueSet source files under source/patient, and by Extension Pack commit bd62a3b5e6392bf1d7f21422ca4f9feb9b893196, which removed the internationalEquivalent slice from input/definitions/multiple/StructureDefinition-individual-recordedSexOrGender.xml. Both commits were issue-tagged as FHIR-38892, FHIR-39193.

Additional context:
The current FHIR core checkout no longer contains the recordedSexOrGender StructureDefinition source; the active extension definition is in the FHIR Extension Pack checkout. Core still has Patient examples and the canonical OID assignment that reference individual-recordedSexOrGender, but searches found no remaining internationalEquivalent, misspelled internationalEquivilent/internationalEquivelent, or ICAO sex-or-gender terminology source in core or the Extension Pack. The 2023-02-14 RSG minutes record FHIR-39193 as persuasive with modification and ready for main, deleting the element and code system, and 2024 PA minutes later cite FHIR-39193 as the reason ICAO references were removed.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The requested element and dependent ICAO terminology are already absent from current in-scope core source, and the read-only Extension Pack source also shows the migrated extension definition without the removed slice.

Recommendation:
Keep this no-change audit commit as-is for FHIR core. No follow-up core edit is needed for FHIR-39193; if a separate Extension Pack reconciliation process audits the migrated extension, it should observe that bd62a3b already applied the slice removal there as well.
