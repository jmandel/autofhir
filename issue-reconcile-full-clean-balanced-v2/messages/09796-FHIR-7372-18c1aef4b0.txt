FHIR-7372: Audit List narrative-only wording

Issue request:
FHIR-7372 was Published with resolution Not Persuasive with Modification. It objected to List scope wording that said List content might be narrative only, such as a text record of family history, because some narrative document sections should not be called Lists. The final disposition explicitly said to see FHIR-7371.

Initial application:
No Jira-tagged source commit for FHIR-7372 or FHIR-7371 was found. The challenged List introduction wording came from the earlier #5289 collection-type clarification commit d72b1d787a, and the FHIR-7371 comments say the disposition became redundant after Composition was reworked and a wiki page was created.

Additional context:
FHIR-7371 carries the substantive paired request: narrative-only content should not use List unless the content is actually a collection/list. Current active source now separates the cases: List remains a flat collection whose entries are optional, while narrative-only document sections are represented by Composition.section.text with no Composition.section.entry, and document presentation/attestation is based on Composition and section narratives rather than List.text.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current source no longer forces non-list narrative document sections through List, and the remaining List introduction sentence is still valid for genuine List instances whose curated collection is represented only in narrative.

Recommendation:
Keep this audit as-is. Revisit only if the work group wants a new, broader policy that forbids narrative-only List instances entirely or wants to add non-normative examples distinguishing List from other narrative-bearing resources.
