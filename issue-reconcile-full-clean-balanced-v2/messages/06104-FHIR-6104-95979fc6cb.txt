FHIR-6104: Audit CodeSystem casing tooling

Issue request:
FHIR-6104 is a Published vocab change request resolved Persuasive with Modification. It asked tooling to enforce consistent capitalization for FHIR-defined code systems; the approved rule was lowercase codes with dashes as separators and title-case display names, with exceptions allowed when confirmed with Vocab or MnM.

Initial application:
The issue was applied in the legacy in-repo publisher tooling by git commit 430e840f067da7df7b7634ee9710d1c275f529ff, corresponding to SVN revision 5847 mentioned in Jira. That commit added ValueSetValidator checks for title-case displays and lowercase-dash codes for non-known/non-external code systems, while also touching source terminology content.

Additional context:
The current FHIR source no longer carries the legacy tools/java publisher code. Commit 9f549566d1346cad7db6d2afca6080d7cebdfbbe moved the publisher implementation to the external org.hl7.fhir:kindling dependency, and the active build.gradle.kts now runs org.hl7.fhir.tools.publisher.Publisher from Kindling. Current checked-in build inputs still show this rule being enforced: suppressed-messages.txt contains the exact current warnings "Display Names must be TitleCase" and "Defined codes must be lowercase-dash" for the active W3C Provenance CodeSystem, which source/fhir.ini includes in the build. The underlying CodeSystem intentionally uses W3C PROV code/display forms, making it an approved exception rather than a missing normalization.

AutoFHIR reconciliation:
No source change was made. The historical application exists, the current build tooling continues to surface the casing checks, and the only current discovered exception is explicitly suppressed as an intentional external vocabulary form.

Recommendation:
Keep this audit commit as-is. If future work changes the enforcement algorithm itself, make that change in the Kindling publisher/tooling repository rather than in core spec source; core source changes should only be needed for specific unsuppressed terminology content violations.
