FHIR-5437: Audit Subscription endpoint rename

Issue request:
FHIR-5437 was a Published FHIR-I DSTU1 change request, resolved Persuasive, asking that the Subscription channel URL element be renamed from URL to endpoint because non-HTTP channel targets such as email addresses are not ordinary URLs. The ballot comment also suggested cardinality 1..1, but the recorded resolution and application text were limited to renaming Subscription.url/Subscription.channel.url to Subscription.endpoint.

Initial application:
The issue was explicitly applied by git-svn commit 5b1b287a952af278548982b89b750a645cd7808c, whose message references #5437 and SVN revision 4495. That commit renamed Subscription.channel.url to Subscription.channel.endpoint in the then-authoritative spreadsheet source and updated examples/payload notes; the element remained 0..1 in that application, matching the narrower recorded resolution rather than the broader ballot-comment wording.

Additional context:
The current R6 source no longer has the old Subscription.channel backbone, but Subscription is active in source/fhir.ini and the authoritative StructureDefinition defines Subscription.endpoint as a 0..1 url. Later Subscription redesigns made the endpoint channel-specific: current narrative says websocket is the predefined channel type that does not require the client to have an endpoint, while rest-hook/email/message sections describe when Subscription.endpoint is supplied. FHIR-47344 was later Applied for R6 and commit ac3fd3079e5d96596e6a54930833012879584176 clarified Subscription.endpoint as a channel-specific URL, including that websocket URLs are supplied by the server. Related FHIR-10190 was already audited on the combined branch and also supports not converting this endpoint field to a different model.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build already uses Subscription.endpoint rather than Subscription.channel.url, and changing endpoint cardinality to 1..1 now would contradict the current channel-specific Subscription model and later applied endpoint clarification.

Recommendation:
Keep this no-change audit as-is. Do not reopen FHIR-5437 to force endpoint cardinality to 1..1; any future cardinality or Endpoint-resource relationship change should be handled through a newer, explicit Subscription issue because the current model intentionally permits channel-dependent endpoint use.
