FHIR-40494: Audit inter-version compatibility clarification

Issue request:
FHIR-40494 was a Published/Persuasive with Modification FHIR-core clarification for the Version Management Policy. It asked to finish the FHIR-38876 inter-version-change follow-up by making the compatibility framing about conformant resource instances/data representation, making clear that the rules do not apply to non-normative content including STU content within normative artifacts, and scoping the listed changes to normative portions of the specification.

Initial application:
The issue was applied on master by 96bbb3012090ba09fd4c9f4cb2659881c77cdb9c, matching the Jira comment that cites Git master 96bbb30120. That commit edited source/versions.html to add the non-normative/STU caveat, move the normative compatibility paragraph, change breaking and non-substantive descriptions from conformant applications to conformant resource instances, and phrase the change-kind list as applying to normative portions.

Additional context:
FHIR-38876 is the immediate predecessor that added the surrounding warning that non-breaking spec changes can still break applications. Later, FHIR-41452 was an Applied/Persuasive R6 clarification implemented by PR #2944. Its source commits intentionally moved the change-kind definitions back to a general list, kept the non-normative/STU caveat with the normative paragraph, and added the rare-normative-breaking-change governance paragraph. FHIR-51051 later changed only the datatype row in the same normative rules table.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source/versions.html still preserves the FHIR-40494 semantic fixes: breaking and non-substantive change definitions are about resource instances, non-normative/STU content is explicitly out of scope for the normative compatibility rules, and the forward/backward compatibility rules table says it applies once core or HL7 international IG artifacts become normative. Reintroducing the exact older "normative portions" placement would conflict with the later FHIR-41452 structure without improving implementer understanding.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for FHIR-40494 unless a future work-group decision reopens the broader inter-version compatibility policy.
