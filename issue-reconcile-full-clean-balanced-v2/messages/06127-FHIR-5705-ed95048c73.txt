Issue request:
FHIR-5705 was a Published Patient Care DSTU1 change request asking to add a Procedure.status element because Procedure lacked the status field common to comparable resources. The final Persuasive with Modification resolution added Procedure.status with values in-progress, completed, and entered-in-error.

Initial application:
Git commit 140947a909f933c7c04cfbfa38eb1ece8be5e0b5, "#5705 define Procedure.status", added Procedure.status to the then-authoritative source/procedure/procedure-spreadsheet.xml as a required modifier code with a ProcedureStatus binding and the requested in-progress, completed, and entered-in-error examples. The companion FHIR-5707 commit 0136d72a7b0c4246350f85195b5ffcd2cc19e3d3 immediately added aborted to that local Procedure status set, and later Procedure status work added non-performance and workflow-pattern refinements.

Additional context:
Procedure remains an active current-build resource in source/fhir.ini. The current authoritative XML source keeps Procedure.status as 1..1, modifier, mapped to Event.status, and required-bound to ValueSet/event-status. Later applied decisions intentionally moved Procedure from the DSTU1 local code list to the Event workflow status family, including not-done/on-hold/stopped/unknown terminology and restored not-done guidance from subsequent Procedure status trackers.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current source already satisfies the core request to have Procedure.status, and changing it back to the literal DSTU1 code list would undo later workflow and terminology decisions.

Recommendation:
Keep this no-change audit commit. Future Procedure status changes should be made against the current Event Status workflow model rather than the obsolete DSTU1 local status list.
