FHIR-25471: Audit ActivityDefinition timing choices

Issue request:
FHIR-25471 was a Published/Persuasive CDS change request for R5 asking to remove dateTime and Period from the ActivityDefinition timing choice because static dateTime and Period values are not appropriate in a definitional resource. The approved resolution also required clarifying documentation that the timing is interpreted during apply so resulting request actions receive concrete timing from the evaluated definition.

Initial application:
The issue was applied before this reconciliation by git commit 1b8c8728485bc9bfa8dcc454047dba518eca81e5, which explicitly referenced J#25471 and removed dateTime and Period from ActivityDefinition.timing[x]. The same commit also made the parallel PlanDefinition.action.timing[x] cleanup and added the explanatory apply-operation comments called for by the Jira resolution.

Additional context:
ActivityDefinition and PlanDefinition are active current-build resources in source/fhir.ini. Later timing-family work did not reverse FHIR-25471: FHIR-43696 added RelativeTime as an additional approved timing choice for R6, and the already-published FHIR-29799 reconciliation updated the comments to explain RelativeTime while preserving the FHIR-25471 removal of dateTime and Period. Community searches for FHIR-25471 and the timing/dateTime/Period terms found no conflicting Zulip or Confluence decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative current StructureDefinition source for ActivityDefinition.timing[x] allows Timing, Age, Range, Duration, and RelativeTime, but not dateTime or Period, and its comment explains interpretation during apply. The parallel PlanDefinition.action.timing[x] source is likewise consistent with the original application and later approved RelativeTime addition.

Recommendation:
Keep this no-change audit commit. No current FHIR core source correction is needed for FHIR-25471; future timing-choice changes should be handled through later trackers such as FHIR-43696 rather than reintroducing static dateTime or Period choices.
