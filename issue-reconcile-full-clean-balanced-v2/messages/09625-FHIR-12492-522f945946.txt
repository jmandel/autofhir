FHIR-12492: Audit corrected vital signs invariant

Issue request:
FHIR-12492 was a Published/Persuasive FHIR-core change request for the DSTU2 vital signs profile. It reported that the vital signs invariant shared with US Core used the wrong logic and could reject component-based examples, such as blood pressure, by requiring a root value[x] or dataAbsentReason when there was a component but no related element.

Initial application:
No current git commit explicitly names FHIR-12492. The Jira comment says the expression error was fixed in GitHub, and the closest source-history evidence is 1b733457b2, "fix observation vitals invariant [#12596]", which reworked the legacy vital signs spreadsheet invariant into implication form using component.empty() and related.empty(). Later history kept that semantics while adapting the profile to the current model: 5bdc655967 replaced Observation.related with Observation.hasMember, and f9057f0d24 made the FHIRPath expression explicitly call exists() on dataAbsentReason and value.

Additional context:
The current build source is the active Observation resource folder listed in source/fhir.ini, and source/observation/implementationguide-Observation-vitalsigns.xml includes StructureDefinition/vitalsigns in the core vital signs IG. The current source/observation/structuredefinition-profile-vitalsigns.xml constraint vsp-2 says `(component.empty() and hasMember.empty()) implies (dataAbsentReason.exists() or value.exists())`, which is the corrected semantics for the reported problem. Searches of Zulip and Confluence found no directly relevant discussion or minutes that conflict with the Jira/source-history conclusion.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because the current core vital signs profile already permits observations with components or hasMember references without requiring a root value[x] or dataAbsentReason.

Recommendation:
Keep this audit commit as-is. No follow-up is needed in the core FHIR checkout unless a separate US Core reconciliation finds a current IG-specific copy of the old invariant.
