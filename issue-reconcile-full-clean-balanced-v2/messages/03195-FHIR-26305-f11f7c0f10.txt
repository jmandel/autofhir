FHIR-26305: Audit SNOMED descendant filter migration

Issue request:
FHIR-26305 was a Published/Persuasive Vocabulary WG R5 change request. It asked the SNOMED CT-on-FHIR filters documentation to support the FHIR ValueSet filter operator descendent-of for SNOMED CT ECL "<" descendantOf semantics, because is-a includes the head concept and the generic constraint filter is more powerful than needed.

Initial application:
The issue was approved on the 2020-11-12 Vocab WG call, whose minutes say the ticket was only about SNOMED CT filter documentation and that the existing FHIR descendent-of operation should be added as an allowed SNOMED page filter. The R5 source application was commit b0172dd266bc5061422826c714e77a6d3c559296, which listed FHIR-26305 in the commit message and added a second subsumption table to source/snomedct.html documenting the SNOMED CT ECL "<" / descendantOf case. The common FHIR filter-operator CodeSystem already defined the normative descendent-of code with the backwards-compatible spelling note.

Additional context:
FHIR-35933 later removed the old local source/snomedct.html external terminology guidance page from the FHIR-core build and moved the "Using SNOMED CT with HL7 Standards" content to HL7 Terminology (THO). The current build-scoped source/terminologies-systems.html row for http://snomed.info/sct links to https://terminology.hl7.org/SNOMEDCT.html and keeps only source/snomedct-usage.html as a FHIR-specific usage summary. The current THO English page contains the SNOMED CT Filters section and the ECL "<" table, so the remaining page content is outside this FHIR-core checkout. Later FHIR-39264/FHIR-49057 evidence confirms that the FHIR operator code spelling remains descendent-of for compatibility.

AutoFHIR reconciliation:
This empty audit commit makes no FHIR-core source change. Recreating the old local SNOMED CT filters page or duplicating its filter table in terminologies-systems.html would conflict with the later THO migration. The current FHIR-core source already defines the descendent-of filter operator and points implementers to the external THO page for SNOMED CT usage guidance.

Recommendation:
Keep this audit commit as-is for FHIR core. If the migrated THO SNOMED CT page should align its operation label exactly with the normative FHIR descendent-of spelling, handle that as THO/UTG follow-up rather than in this FHIR source checkout.
