FHIR-3225: Audit ValueSet VSD alignment

Issue request:
FHIR-3225 was Published/Persuasive for DSTU1 and asked Vocab to change the FHIR-core ValueSet resource so its basic metadata aligned with the HL7 Value Set Definition Process, citing the 5-May-2014 Vocab committee minutes and the approval vote recorded in Jira.

Initial application:
The issue appears to have been applied immediately after the cited Vocab discussion by git commit 2e2d1d98 on 2014-05-06, whose subject says it updated ValueSet as agreed with Vocabulary committee by adding optional metadata elements, extensions for the remaining VSD project metadata, and a formal minimum metadata profile. The historical source at that time was spreadsheet-based, while current source has since been migrated to XML and refactored through later terminology work.

Additional context:
ValueSet is an active resource in source/fhir.ini. Current ValueSet source includes the metadata concepts introduced by the issue and its successors, including identifier, version, name/title, status, experimental, date, publisher/contact, description, immutable, purpose, copyright, lockedDate, inactive, and later MetadataResource-derived elements. Current narrative explicitly says ValueSet is aligned with the VSD project, maps compose to the VSD Content Logical Definition, and contains a dedicated ValueSet Alignment with VSD section. Later FHIR-36015 added the current VSD guidance text, and later FHIR-35985 made ValueSet a MetadataResource; both are already represented on the combined reconciliation branch. Older VSD-specific extension artifacts now live in the FHIR Extension Pack, where replaced metadata extensions such as valueset-author, valueset-steward, valueset-effectiveDate, and valueset-expirationDate are retired/deprecated while other VSD support extensions remain active.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope core source already reflects the requested VSD alignment after the original 2014 application and later approved refactors, and editing core now would either duplicate existing guidance or revisit later decisions outside the seed issue.

Recommendation:
Keep this no-change audit commit as-is. Future VSD metadata changes should be raised against the current ValueSet/MetadataResource model or the FHIR Extension Pack artifacts with a new tracker, not as a retroactive core edit for FHIR-3225.
