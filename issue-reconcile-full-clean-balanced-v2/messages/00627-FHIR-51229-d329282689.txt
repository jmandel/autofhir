FHIR-51229: Audit DeviceAssociation status binding split

Issue request:
FHIR-51229 was Applied as Persuasive with Modification for R6 after the reporter found that DeviceAssociation.status was required but its required binding still mixed association lifecycle values with resource-record status values, leaving no clear way to represent an ended or disconnected association. The resolution explicitly deferred to FHIR-48532, which was to pre-apply the separation of record status from association status values.

Initial application:
No commit mentioning FHIR-51229 was found in the DeviceAssociation source history. The applying evidence is the Jira-referenced FHIR-48532 implementation commit 2b906e8ba0, which changed DeviceAssociation.status to code, narrowed its required value set to active | inactive | entered-in-error | unknown, changed statusReason to extensible, added DeviceAssociation.associationStatus with a preferred value set, and updated DeviceAssociation examples. FHIR-48713 then added the related abandoned associationStatus code in f09755d231.

Additional context:
DeviceAssociation is active in source/fhir.ini, and the current build source contains the FHIR-48532/FHIR-48713 split in source/deviceassociation/structuredefinition-DeviceAssociation.xml and the corresponding status, statusReason, and associationStatus CodeSystem/ValueSet sources. OO minutes for 2025-10-24 record FHIR-51229 as pre-applied and same as FHIR-48532, while also noting possible future questions about the interplay between status, statusReason, and associationStatus. Later Jira FHIR-54463 is only Triaged and asks for broader quality review of those elements, so it is not a final source-edit decision for this reconciliation.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already addresses the FHIR-51229 request by keeping DeviceAssociation.status as the required resource-record status, making statusReason extensible, and moving physical/operational association states to the optional preferred associationStatus element and its value set.

Recommendation:
Keep this audit as-is for FHIR-51229. Handle any broader terminology or narrative clarification under a final follow-up decision such as FHIR-54463, and handle unrelated residual operation-backbone cleanup under the issues that removed DeviceAssociation.operation rather than reopening FHIR-51229.
