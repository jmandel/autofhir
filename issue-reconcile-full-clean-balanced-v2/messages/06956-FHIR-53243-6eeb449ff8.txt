FHIR-53243: Audit Device status unknown restoration

Issue request:
FHIR-53243 is an Applied/Persuasive R6 change request asking to add `unknown` to `http://hl7.org/fhir/device-status` and therefore to `http://hl7.org/fhir/ValueSet/device-status`, using the R4 definition `The status of the device has not been determined.` The resolution also asked to put the code in the status mapping spreadsheet.

Initial application:
Commit b76fa6ef19abe4717b0de45c4cfe1419894424f9, merged by PR #3849, implemented FHIR-53243 by re-adding the `unknown` concept to `source/device/codesystem-device-status.xml` and updating `source/status-codes.xml`. The Device status ValueSet composes the entire Device status CodeSystem, so no separate enumerated ValueSet hunk was needed.

Additional context:
FHIR-53243 is a direct later reversal of FHIR-32555, the R5 issue that removed `unknown` from Device.status. Current source has since restored the Device.status short text to a record-status description, but the CodeSystem, ValueSet include, and status mapping still carry the later `unknown` code. FHIR-51586 was implemented in the same source commit/PR but concerns BiologicallyDerivedProduct and is not part of this Device status decision.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current build-scope Device sources already satisfy FHIR-53243. The active Device resource source includes `unknown` in the CodeSystem, includes the full CodeSystem in the ValueSet, and includes `unknown` in the status mapping row.

Recommendation:
Keep this audit as-is. Future edits should not remove `unknown` from Device.status unless a new OO decision explicitly reverses FHIR-53243.
