FHIR-18230: Audit ShareablePlanDefinition external migration

Issue request:
FHIR-18230 was Published/Persuasive for STU3 and asked FHIR core PlanDefinition to define a ShareablePlanDefinition profile analogous to ShareableValueSet. The approved profile required the publication metadata elements url, version, name, title, experimental, description, date, and publisher.

Initial application:
The issue was applied by 7fab0975b9f824870fcc1ca9f28322401123675a, which added source/plandefinition/plandefinition-shareable-spreadsheet.xml and updated source/plandefinition/plandefinition-spreadsheet.xml. Later source history carried ShareablePlanDefinition into R4/R5 history, including tools/history/release5/profiles-others.xml. There is no evidence that the original application was missed.

Additional context:
Later Applied/Persuasive issue FHIR-48393 removed ShareablePlanDefinition and related shareable/publishable profiles from the base specification for R6 because they had already moved to CRMI. Commit 571498e2b2959573e07980c9117923b42624e3a1 removed source/plandefinition/structuredefinition-profile-shareableplandefinition.xml along with the active PlanDefinition profile pack and introduction files. The current build still includes PlanDefinition and the Shareable logical pattern, but no active core ShareablePlanDefinition profile source or fhir.ini/profile reference remains; only the historical OID entry remains. The active Shareable pattern introduction directs applications using Shareable and Publishable patterns to CRMI, and the published CRMI IG exposes CRMI Shareable PlanDefinition outside core. CDS agenda evidence for FHIR-48393 records the TSC determination that resource profiles should not remain in the base FHIR specification.

AutoFHIR reconciliation:
This empty audit commit records an external-repo decision. It intentionally does not restore the retired core ShareablePlanDefinition profile or duplicate the CRMI profile in current core source.

Recommendation:
Keep this audit commit as-is for core. If future work needs to adjust the ShareablePlanDefinition profile itself, reconcile it in CRMI/source package maintenance rather than reintroducing the removed base-spec profile.
