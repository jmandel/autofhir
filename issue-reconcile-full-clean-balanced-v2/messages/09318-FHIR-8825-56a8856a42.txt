FHIR-8825: Audit reference versioning profile support

Issue request:
FHIR-8825 is a Published/Persuasive FHIR-core StructureDefinition change request, raised for DSTU1 and applied for DSTU2, asking profiles to be able to indicate whether references can or must be version-specific or version-independent. The accepted resolution was to add ElementDefinition.typeRef/versioning with a value set for version specific, version independent, and don't care.

Initial application:
The Jira comment records svn revision 8004. The matching git-svn commit 9e1eefd1d8be3b86f5fccfe3fbd7f6c46a4b1cc1, dated 2016-03-23 and titled "#8825 - add ElementDefinition.type.versioning", added the ElementDefinition.type.versioning row, the ReferenceVersionRules type, and the reference-version-rules code list to source/datatypes/elementdefinition.xml.

Additional context:
FHIR-13101 is a same-change-family follow-up that added spreadsheet parser support for populating this element from type declarations. The current ElementDefinition source still defines type.versioning as ReferenceVersionRules with the allowed values either, independent, and specific, and the active ElementDefinition page includes an invariant mentioning type.versioning. Current source also demonstrates real profile usage in the active Provenance relevant-history profile, where Provenance.target carries versioning="specific". No Zulip or Confluence evidence was found that narrows, reverses, or questions the Jira/source conclusion.
