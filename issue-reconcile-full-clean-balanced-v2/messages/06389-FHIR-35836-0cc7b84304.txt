FHIR-35836: Audit missing XPath handling

Issue request:
FHIR-35836 was a Published/Persuasive FHIR-I technical correction for the R5 publisher failure when an extension constraint omitted ElementDefinition.constraint.xpath. The Jira description pointed at the derivation-reference extension workaround line and the resolution asked to change code so lack of XPath would not fail, possibly by auto-filling true().

Initial application:
The derivation-reference extension was added in commit cc46687ac0f400c85f5d78e433031c7fe02562d2 without an XPath on its der-1 constraint. Commit 31fb500068bed0ae846ac325f18748c83c4693b1 then added a temporary dummy XPath line to avoid the publisher bug. The Jira-tagged commit 192e11e7aa7a8cefca87deec3a621ea4efa709e9 later removed a dummy XPath from DiagnosticReport and corrected a CoverageEligibilityResponse XPath expression as part of the same cleanup trail.

Additional context:
Later R5 work removed the optional trial-use ElementDefinition.constraint.xpath surface itself. FHIR-37871 records the Published/Persuasive decision to remove constraint.xpath and update tooling so Schematron no longer exposes constraints; current source/fhir.ini records ElementDefinition.constraint.xpath as removed. Commit 88a1f3d6bd60f7618ae140179b008ac5686e8a08 removed the derivation-reference dummy XPath line, and commit dd468d4f1799dd79819315b211588ef1cf4586e0 removed the derivation-reference extension from core R5 source. The extension now lives in the FHIR Extension Pack and its current definition keeps the der-1 FHIRPath expression without an XPath element.

AutoFHIR reconciliation:
Made no source change. The current core checkout has no source/resource/structuredefinition-extension-derivation-reference.xml, the active StructureDefinition source has no ElementDefinition.constraint.xpath element, the historical DiagnosticReport and CoverageEligibilityResponse constraints no longer carry XPath constraint metadata, and the extension-pack derivation-reference definition already demonstrates that a constraint without XPath is accepted by the current source ecosystem.

Recommendation:
Keep this empty audit commit. No current core source correction is needed for FHIR-35836; future work should not reintroduce dummy XPath values. Any remaining publisher-code behavior belongs in the publisher/tooling repositories rather than as a core spec source edit.
