FHIR-7311: Audit birthDate date-only consistency

Issue request:
FHIR-7311 was a Published PA change request from the 2015 May ballot that proposed changing Practitioner.birthDate from date to dateTime for consistency with then-current Person.birthDate. The final Persuasive with Modification resolution instead changed Person.birthDate to date so the person-type resources remain date-only.

Initial application:
The issue appears to have been applied by git commit 0522d003c90c49a5774028204610056c3360d1c6, whose message says "Tracker# 7311 Person BirthDate is a date only type" and whose patch changed Person.birthDate in source/person/person-spreadsheet.xml from dateTime to date while also replacing the requirements text with date-only rationale.

Additional context:
Person and Practitioner are active current-build resources in source/fhir.ini, and the current StructureDefinition sources have Person.birthDate and Practitioner.birthDate typed as date. Patient.birthDate and RelatedPerson.birthDate are also date, so the resource family is consistent. FHIR-7307 was the companion 2015 RelatedPerson birthDate change, FHIR-14441 later aligned the Patient/Practitioner/RelatedPerson/Person pattern without changing the date type, and FHIR-35090 later clarified birthDate comments without changing the type. No relevant Zulip or Confluence evidence was found that changes this conclusion.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current build already implements the final FHIR-7311 decision. Changing Practitioner.birthDate to dateTime would contradict the accepted resolution.

Recommendation:
Keep this audit commit as-is. No follow-up core source work is needed for FHIR-7311 unless a future PA decision explicitly reopens the date-only policy for these resources.
