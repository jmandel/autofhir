FHIR-41356: Audit system-level validate support

Issue request:
FHIR-41356 is an Applied/Persuasive FHIR-I R6 change request asking that Resource.$validate support system-level invocation at [base]/$validate, because the existing type-level operation already takes the resource as an input parameter and base invocation helps clients validate resources, existing types, and logical-model/profile test instances without first selecting a REST resource type endpoint.

Initial application:
No source commit explicitly mentioning FHIR-41356 was found. The requested change appears to have been applied implicitly in commit 85f4e0aaf0, whose subject names FHIR-44864 but changes source/resource/operationdefinition-Resource-validate.xml from system=false to system=true and adds source/resource/operation-Resource-validate-notes.xml with a system/type invocation table. Commit 66cc0c8aac then refined the table wording.

Additional context:
FHIR-I minutes for 2023-11-06 record the FHIR-41356 discussion and 9-0-0 persuasive vote, including the rationale that system invocation avoids clients needing to derive the resource type URL and can better support logical-model testing. FHIR-41357 is the same validate-operation decision family and its already-published AutoFHIR audit explains why the current table was reconciled with FHIR-41356. A later Zulip validator thread observed that R5 had system=false and pointed implementers to FHIR-41356 for R6 support. The inspected files are build-scope source because source/fhir.ini lists Resource as an active infrastructure resource and source/resource/list-Resource-operations.xml references OperationDefinition/Resource-validate.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current operation definition already has system=true while retaining type and instance support, and the notes table explicitly covers invocation at System/Type level with / or /[ResourceType]. Those source entries satisfy the approved request to add system-level $validate support.

Recommendation:
Keep this audit commit as-is. Further source edits for FHIR-41356 would duplicate already-applied semantics rather than correct a current specification problem; any future work on batch Bundle validation behavior should be handled under a separate issue because FHIR-41356 only approved the invocation level.
