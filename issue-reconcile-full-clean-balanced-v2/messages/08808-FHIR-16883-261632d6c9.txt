Issue request:
FHIR-16883 was a Published/Persuasive FHIR-core Binary change request asking whether special considerations were needed for PATCH operations on Binary. The final resolution was that the semantics of a PATCH operation on a Binary resource are not currently specified.

Initial application:
The issue was applied in git-svn commit cdd45cd9b71fe62b96233d7b00425b2678c431f4, which references GF#16883 and svn revision 14341, matching the Jira implementation comment. That commit added the Binary resource Patch section and the exact sentence from the Jira resolution to source/binary/binary-notes.xml.

Additional context:
Binary is an active current-build resource through source/fhir.ini, so source/binary/binary-notes.xml remains build-scope resource narrative. The RESTful API PATCH section also points readers to the Binary-specific note. Later PATCH issues found during the same search, including FHIR-34278 and FHIR-33945, clarify PATCH optionality and the use of Binary as a transaction payload for JSON Patch, but neither reverses the Binary-target rule from FHIR-16883.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current specification already contains the approved Binary PATCH clarification and the general HTTP PATCH page links to it, so adding or rewriting text would be redundant and could create maintenance drift.

Recommendation:
Keep this no-change audit commit as-is. Future work should only revisit this area if FHIR-I decides to define explicit PATCH semantics for Binary resources or to change the Binary-as-payload transaction pattern separately.
