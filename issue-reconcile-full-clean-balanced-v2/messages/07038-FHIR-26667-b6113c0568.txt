FHIR-26667: Audit fragment-only contained-reference clarification

Issue request:
FHIR-26667 was Published/Persuasive for FHIR-core references. It reported that the contained-resources guidance said "References to contained resources are never resolved outside the container resource" even though canonical URLs such as Questionnaire/example|1.0#vs1 can refer to a contained resource inside another resource, and the approved resolution was to clarify the statement by adding "Fragment-only URL References".

Initial application:
The issue was applied by commit ffd8f8488e9bab23f82c97fd634f64a7ef9a4cf7, titled "FHIR-26667", and then merged through HL7/fhir pull request #1284 in merge commit 5cdf26b454d37dc39e9dab4e93486f2b58ebb7e0. That commit changed the relevant source/references.html bullet to begin "Fragment-only URL References to contained resources...".

Additional context:
FHIR-31582 was applied in the same PR and added the neighboring sentence explaining that references to contained resources in a different Parameters or Bundle entry, or elsewhere, must include the containing resource. Earlier FHIR-20340 is useful background on cross-resource contained references but was Resolved - No Change; it does not supersede the later fragment-only clarification. The linked Questionnaire Zulip discussion and FHIR-I minutes confirm the intended scope: the prohibition is about fragment-only references, not canonical URLs that include the containing resource.

AutoFHIR reconciliation:
Made no source change. The current source/references.html active references page already begins the relevant contained-resource bullet with "Fragment-only URL References" and preserves the accompanying resolution-stop elements.

Recommendation:
Keep this empty audit commit as-is. No current core source change is needed for FHIR-26667; avoid broadening the audit to companion FHIR-26666 without a separate source check.
