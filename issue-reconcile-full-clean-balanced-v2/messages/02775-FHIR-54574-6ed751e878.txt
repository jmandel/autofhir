Issue request:
FHIR-54574 was Applied/Persuasive for R6 Provenance. It reported that the Provenance when search parameter only searched occurredDateTime and should also match occurredPeriod by using Provenance.occurred.ofType(dateTime) | Provenance.occurred.ofType(Period).

Initial application:
The source change was applied in commit 33028e962140dc12fd01b8d317de213eb15e72c6, which updated source/provenance/bundle-Provenance-search-params.xml to include both dateTime and Period in the when expression. That commit accidentally wrote the path extension as Provenance.occurred[x]], and follow-up commit ebb2280526728d18eac0d625f99a023e38fa60d9 corrected it to Provenance.occurred[x].

Additional context:
FHIR-13012 is the earlier change-family issue that introduced the Provenance.occurred[x] dateTime|Period choice. Provenance is active in the current build, and the current StructureDefinition still exposes both choice types. No direct Zulip or Confluence evidence was found that changes the Jira/source conclusion for this narrow search-parameter correction.
