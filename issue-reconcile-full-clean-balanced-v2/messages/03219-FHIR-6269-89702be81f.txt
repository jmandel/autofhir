FHIR-6269: Audit AuditEvent user identifier application

Issue request:
FHIR-6269 was a Published/Persuasive with Modification Security change request for the DSTU1 AuditEvent resource. It asked for an AuditEvent participant userId type code to explain how to interpret values such as a Patient ID in CX form, and the final resolution was to change userId from string to Identifier.

Initial application:
The historical application is visible in git commit 8e1a48066d70501f76de61f4511ec19b48da2df2, whose message explicitly lists item 6269 and whose AuditEvent spreadsheet patch changes AuditEvent.participant.userId from string to Identifier while updating examples to represent userId as an Identifier element. No additional source-changing work is needed to complete that original application.

Additional context:
AuditEvent is an active resource in source/fhir.ini. Later, Published/Persuasive FHIR-17412 intentionally removed the now-redundant AuditEvent.agent.userId element and moved its semantics into AuditEvent.agent.who, using Reference because Reference supports logical identifiers. The applying commit 6c0a0563b3ac6a188b713f2f1a04ff26229100cf renamed agent.reference to agent.who, marked agent.userId removed, and added guidance that a User ID goes into who.identifier. The current source retains that guidance and current AuditEvent examples carry user identifiers in who.identifier.

AutoFHIR reconciliation:
This commit makes no source change. The current build-scoped AuditEvent source no longer has the old participant.userId element, but it preserves the Jira-approved Identifier semantics through AuditEvent.agent.who.identifier after the later FHIR-17412 refactor.

Recommendation:
Keep this no-change audit commit as-is. No follow-up core source work is needed for FHIR-6269 unless the Security work group separately reopens the later design choice that folds user identifiers into Reference.identifier.
