FHIR-28160: Audit disabled enableWhen dependency behavior

Issue request:
FHIR-28160 was a Published/Persuasive R4 change request for FHIR-core Questionnaire asking the core spec to state what happens when enableWhen.question points at an item that is itself disabled. The approved resolution was to clarify that enableWhen or enableWhenExpression logic must treat a disabled dependency as having no value, even if an initial or retained value exists.

Initial application:
The issue was applied by e1b4063a56, which changed source/questionnaire/structuredefinition-Questionnaire.xml to add the disabled-dependency rule to Questionnaire.item.enableWhen. The Jira comment records that same commit hash.

Additional context:
Questionnaire is an active resource in source/fhir.ini, so the StructureDefinition source is in the current build. The current comment at Questionnaire.item.enableWhen still says that if enableWhen logic depends on a disabled item, evaluation proceeds as though that item is not valued, including when a default or retained value exists. Later same-comment work for FHIR-36233 appended precision guidance but preserved this rule. The cited Zulip thread and FHIR SDC minutes both support the same interpretation, and no conflicting later decision was found in the bounded Jira/Zulip/Confluence/source checks.
