FHIR-34326: Audit ShareableCodeSystem content requirements

Issue request:
FHIR-34326 was a Published/Persuasive with Modification Vocab change request for R5 asking HL7-authored CodeSystems and the ShareableCodeSystem profile to require appropriate CodeSystem metadata. The approved resolution kept CodeSystem.content as already mandatory, made CodeSystem.caseSensitive mandatory and mustSupport in ShareableCodeSystem, made CodeSystem.hierarchyMeaning mustSupport, and added an invariant requiring hierarchyMeaning when CodeSystem.concept.concept exists.

Initial application:
The issue was applied before this reconciliation. PR #2068 was merged as 0d4401be, with implementation commit 93fadfaa updating source/codesystem/structuredefinition-profile-shareablecodesystem.xml. That change made CodeSystem.caseSensitive 1..1 and mustSupport, made hierarchyMeaning mustSupport with condition scs-1, and added the scs-1 nested-concept hierarchyMeaning invariant. The checked-in R5 history bundle still contains StructureDefinition/shareablecodesystem version 5.0.0 with those constraints.

Additional context:
FHIR-31753 was handled in the same May 2022 Vocab session and PR #2068, removing the old ShareableCodeSystem concept cardinality requirement while adding a separate content/concept invariant. Later FHIR-37959 changed the current R6 direction: remove the Shareable, Publishable, Computable, and Executable terminology-resource profiles from core FHIR and maintain them in CRMI. Current source/codesystem/implementationguide-CodeSystem-core.xml has an empty definition section, the current source tree has no source/codesystem/structuredefinition-profile-shareablecodesystem.xml, and source/shareable/shareable-spreadsheet-introduction.xml directs implementers to CRMI profiles. Published/current CRMI profile artifacts carry the same caseSensitive, hierarchyMeaning, scs-1, content, and concept constraints.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding ShareableCodeSystem to core would reverse the later FHIR-37959 R6 decision rather than completing FHIR-34326, and the external CRMI profile already preserves the FHIR-34326 constraint set.

Recommendation:
Keep this audit as-is for core. Do not restore the core ShareableCodeSystem source unless the work group revisits FHIR-37959 or the CRMI ownership decision. Future corrections to the ShareableCodeSystem profile should be handled in CRMI, not by reintroducing the retired core profile.
