FHIR-36029: Refresh Specimen container example comments

Issue request:
FHIR-36029 was a Published/Persuasive OO R5 change request to move Specimen.container.capacity and Specimen.container.additive[x] from the Specimen.container backbone to Device.property and to update examples.

Initial application:
Jira records that the change was added to the build by a3ecc28015a80f4b69145f0bb125eb99ec00b381 in PR #1891. That commit removed Specimen.container.capacity and Specimen.container.additive[x] from the Specimen StructureDefinition, changed Specimen examples to reference container Device examples, and added specimen-container Device examples. Current source still has the structural removal and the Device property examples.

Additional context:
Specimen, Device, and DeviceDefinition are active current-build resources in source/fhir.ini, and list-Specimen-examples.xml lists the three edited examples. FHIR-22823 had already removed Specimen.container.type in favor of container device modeling, so the same repeated example comments also contained a stale container.type reference. FHIR-49741 later added Device.additive/DeviceDefinition.additive for specimen container additives and is already represented on the combined branch; this later final decision affects how current examples should describe additive details without restoring Specimen.container.additive or changing the already-audited FHIR-49741 work.

AutoFHIR reconciliation:
This commit updates the repeated comments in source/specimen/specimen-example.xml, source/specimen/specimen-example-isolate.xml, and source/specimen/specimen-example-urine.xml so they no longer point readers to removed Specimen.container.additive or Specimen.container.type paths. The comments now point to Specimen.container.device[x] and current Device details such as Device.additive and Device.type. No StructureDefinition or Device example change was needed for the seed because the original structural move is already present and later additive modeling belongs to FHIR-49741.

Recommendation:
Keep this commit as the bounded FHIR-36029 cleanup for current core source. Do not use this issue to reopen the FHIR-49741 Device.additive design; if that later additive model changes again, update these examples under that later issue family.
