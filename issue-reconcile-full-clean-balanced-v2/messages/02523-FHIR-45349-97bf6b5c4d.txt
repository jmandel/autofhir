FHIR-45349: Audit SearchParameter code separators

Issue request:
FHIR-45349 was an Applied/Persuasive FHIR-I R6 change request to prohibit '.', '$', and '|' in SearchParameter.code because those characters are used as search-processing separators; the Jira description also suggested prohibiting whitespace to avoid confusion.

Initial application:
The issue was applied before this reconciliation by commit d5f07239ce65aaf9b19fe17ede1e66aa10ba960f, whose subject was "FHIR-45349 - added search parameter constraints on code and aliascode regarding invalid characters". That commit added SearchParameter-level spd-4 and spd-5 error constraints, attached them to SearchParameter.code and SearchParameter.aliasCode, and updated the SearchParameter.code comment to explain that '.', '$', '|', and whitespace are prohibited. The Jira comment points to HL7/fhir#3967, which merged on 2025-11-09 and includes that commit.

Additional context:
SearchParameter is active in the current build through source/fhir.ini. The April 2024 Zulip discussion that led to the ticket asked whether a period in SearchParameter.code should be non-conformant because it interferes with chaining; Lloyd McKenzie suggested adding an explicit invariant and then filed FHIR-45349. FHIR-I minutes for 2024-05-13 record the Persuasive 9-0-0 vote. Related search-parameter naming work, including FHIR-3855 and FHIR-37590, concerns broader lowercase/hyphen or custom-prefix guidance and does not require broadening this separator-specific reconciliation.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already contains machine-readable constraints prohibiting '.', '$', '|', and whitespace in SearchParameter.code and aliasCode, and those constraints are present on the combined branch. A scan of parsed source XML found no SearchParameter.code or aliasCode values violating those prohibited-character constraints.

Recommendation:
Keep this no-change audit commit as-is. No additional core FHIR source edit is needed for FHIR-45349; future changes to search-parameter naming conventions or prefix recommendations should be handled through their own focused tickets rather than expanding this separator-specific issue.
