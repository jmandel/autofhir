FHIR-3699: Audit retained Flag.subject name

Issue request:
FHIR-3699 was a Published FHIR-core Flag change request with a Persuasive resolution. It asked to rename Alert.subject to Alert.patient because, at the time, the only reasonable target was Patient; the Patient Care motion approved the change on 2014-11-13.

Initial application:
The issue was applied in git-svn commit b2d9ba199f61 (#3699, SVN revision 4797), which changed Alert examples, the Alert spreadsheet element, and Alert search parameter paths from subject to patient. The current repository no longer has the DSTU1 Alert source in build scope, but the historical commit matches the Jira application comments.

Additional context:
Later Published issue FHIR-6171 deliberately reversed the patient-only premise for the renamed Flag resource: it kept the element mandatory, renamed patient back to subject, added Location, Group, Organization, and Practitioner targets, retained patient search, and added subject search. The combined branch already has a separate FHIR-6171 audit commit. Later Flag subject decisions further broadened the same element, including FHIR-10083 for PlanDefinition/Medication/Procedure, FHIR-20380 for PractitionerRole, and FHIR-37950 for RelatedPerson.

AutoFHIR reconciliation:
This empty audit commit makes no source change. Flag is an active core resource in source/fhir.ini, and current source/flag/structuredefinition-Flag.xml correctly uses Flag.subject with multiple non-Patient targets. Current source/flag/bundle-Flag-search-params.xml preserves a Patient-only patient search parameter while also defining subject search. Renaming the current element to patient would contradict the later published Flag decisions.

Recommendation:
Keep this no-change audit commit. No core source follow-up is needed for FHIR-3699; any future changes to the broader Flag.subject target set should be handled under the later subject-expansion issues rather than this superseded DSTU1 rename.
