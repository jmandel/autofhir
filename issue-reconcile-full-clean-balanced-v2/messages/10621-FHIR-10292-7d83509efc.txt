FHIR-10292: Audit code binding tooling enforcement

Issue request:
FHIR-10292 was Published/Persuasive for FHIR-core and asked that the build fail when an element of type code has a binding strength other than required. The Jira was copied from FHIR-10272, whose motivating example was Condition.clinicalStatus being a code with a preferred binding.

Initial application:
The issue was applied in historical HL7/fhir commit 25a14c34669e6e4e477a6970231743ce1ebd9432, matching the Jira comment's SVN revision 9170. That commit changed the then-vendored ResourceValidator so simple code bindings had to be required, with a max-binding exception and grandfathered exemptions, and required code elements to provide a binding.

Additional context:
FHIR-10272 fixed the specific Condition.clinicalStatus example, and the current active Condition resource now has clinicalStatus as CodeableConcept with a required ConditionClinicalStatus binding. FHIR-28285 later reaffirmed and refined the same tooling rule for example bindings and the max-binding/extensible exception; it is already represented on the combined branch by 06449f181d7b733debe269c563625ba4ca0e0e4c. Current HL7/fhir no longer carries the publisher validation source directly: build.gradle.kts depends on org.hl7.fhir:kindling and runs org.hl7.fhir.tools.publisher.Publisher using the kindlingVersion from gradle.properties. Current Kindling ResourceValidator retains the required-binding rule for simple code bindings.

AutoFHIR reconciliation:
This is an empty external-repo audit commit. No HL7/fhir source file was changed because the requested enforcement is a build-tooling behavior now maintained in HL7/kindling, and scans of current core StructureDefinition and spreadsheet source found no code element bindings with a non-required strength.

Recommendation:
Keep this audit commit as-is for core source reconciliation. If the rule regresses, update or version the external Kindling/Publisher tooling rather than adding redundant narrative or editing generated artifacts in HL7/fhir.
