FHIR-8048: Audit retired CommunicationRequest message event

Issue request:
FHIR-8048 is Published/Persuasive. It asked to add `communication-request` as a MessageEvents code so a message whose root payload is a CommunicationRequest could say "please tell so-and-so X"; the resolution said the Message event value set was generated from tooling and to add the communication-request event to the CommunicationRequest resource.

Initial application:
The requested DSTU-era event row was applied by 9f82d098055987a7913dff68e7a1dcd0ae199932, which edited `source/communicationrequest/communicationrequest-spreadsheet.xml` so `communication-request` had notification text and a CommunicationRequest focus. That spreadsheet source was later removed in the 2021 new-build-core migration, and current CommunicationRequest source is the active StructureDefinition-based resource input.

Additional context:
The current build actively includes CommunicationRequest, MessageHeader, and MessageDefinition. Later Published/Persuasive-with-Modification issue FHIR-26902 governs the current MessageEvent policy: the empty core MessageEvent code system/value set was to be deleted, bindings made example/descriptive, and FHIR no longer defines message event codes. The combined branch already contains the FHIR-26902 source-fix commit, so this audit should not reintroduce `communication-request` as a core event code.

AutoFHIR reconciliation:
No source change was made. Current source has no active `http://hl7.org/fhir/ValueSet/message-events`, `http://hl7.org/fhir/message-events`, or `communication-request` MessageEvent definition to amend, and MessageHeader/MessageDefinition now say implementations and IGs define the event codes they need.

Recommendation:
Keep this audit commit as-is. Do not restore the old core `communication-request` event unless InM/PC later decide to re-standardize core FHIR message event codes; CommunicationRequest-based messages can use implementation-defined event codes under the current binding model.
