FHIR-19628: Audit operations list generator scope

Issue request:
FHIR-19628 was Published/Persuasive for the FHIR-core operations list page. It requested adding the resource name and operation code as left-hand columns because the list was sorted by those values but displayed only descriptive operation names and invocation URLs.

Initial application:
No core-source commit or combined-branch audit for FHIR-19628 was found. The active operations list source still contains only the <%operationslist%> include, and the current CI-rendered page still shows the generated two-column table.

Additional context:
The operations list page is in build scope through source/hierarchy.xml and publish.ini, but the table rows are generated by the external Kindling dependency declared in gradle.properties. Kindling's PageProcessor.genOperationList/genOperationDetails currently emits only two table cells per operation: linked title and invocation URL. The OperationDefinition source files already carry the resource and code values, so the missing display columns require a Kindling generator change rather than an authoritative FHIR source edit in this checkout.

AutoFHIR reconciliation:
This commit intentionally makes no source change in the FHIR checkout and records the issue as external-repo. A source-only edit here would either leave the generated table unchanged or replace a generated maintained list with duplicated hand-maintained content.

Recommendation:
Keep this audit commit as-is for the core reconciliation record. Follow up in HL7/kindling by changing PageProcessor.genOperationList/genOperationDetails to render separate Resource and Code columns, then rebuild the FHIR publication output.
