FHIR-2885: Audit tag delete endpoint cleanup

Issue request:
FHIR-2885 was a Published FHIR-core HTTP change request with resolution Persuasive with Modification. It objected that tag deletion was specified as DELETE with a request body and asked to change deletion into a POST operation on an operation-specific _delete endpoint.

Initial application:
The available Git history starts after the original DSTU1 application, but the first available source/http.html already uses POST [base]/[type]/[id]/_tags/_delete and POST [base]/[type]/[id]/_history/[vid]/_tags/_delete rather than DELETE-with-body tag operations. Later history replaced the TagList/_tags text with direct Meta operations and then fixed the delete URLs to POST .../_meta/_delete.

Additional context:
Current source/http.html no longer contains the legacy _tags or _meta/_delete interaction section at all. The active RESTful API page lists DELETE interactions with N/A request body and explicitly says the delete request body SHALL be empty. The only current core source references to Resource.$meta, Resource.$meta-add, and Resource.$meta-delete are ballot-intro links saying those artifacts moved out of the specification. Related FHIR-3938 asked for additional system/type-level tag delete operations and was Resolved - No Change, confirming that broader tag-delete expansion is not a current core requirement.

AutoFHIR reconciliation:
No source change was made. The current core source has no tag deletion operation that uses DELETE with a body, and its DELETE interaction guidance already prohibits request bodies.

Recommendation:
Keep this audit commit as-is. Do not reintroduce local tag-delete prose in core; if meta operations are revisited, handle that in the current operation-owning artifact rather than as a FHIR-core HTTP correction for FHIR-2885.
