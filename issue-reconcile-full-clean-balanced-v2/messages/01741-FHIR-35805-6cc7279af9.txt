FHIR-35805: Audit HealthcareService location guidance

Issue request:
FHIR-35805 was an Applied/Persuasive PA change request asking for clearer guidance on when to represent a service as one HealthcareService with multiple Location references versus multiple HealthcareService resources, and how to choose between HealthcareService and Location contact/availability/endpoint details.

Initial application:
The requested guidance was applied before this reconciliation. Commit c7f71ebf75ce9066bfd5389f6e73affa16f9fee4 added the "Single or Multiple Locations" section to source/healthcareservice/healthcareservice-notes.xml, and merge commit 0cf428e3e2873b4d65e42acfdd11e7e6f083edd9 included that Jira-tagged change in PR #2927. Git history shows no later commits changing the HealthcareService notes file.

Additional context:
source/fhir.ini lists both Location and HealthcareService as active resources, so the HealthcareService notes file is in the current build scope. The current notes section covers the approved considerations: availability hours, contact details, endpoint details, location characteristics, coverage areas, downstream split/merge management, using one HealthcareService when details are shared, and omitting HealthcareService contact/availability/endpoint details when the Location details are the same. PA minutes from January 2022 record the WG discussion and intended notes guidance, and May 2023 PA minutes record the Persuasive 3-0-0 tracker disposition. Jira neighborhood search found only FHIR-35805 for the same HealthcareService/Location availability/contact/multiple-location question, and a direct Zulip issue-key search found no conflicting community thread.
