FHIR-7134: Align QUICK DiagnosticOrder reason metadata

Issue request:
FHIR-7134 was Published with a Persuasive with Modification disposition for DSTU1. It asked to rename DiagnosticOrder.clinicalNotes to DiagnosticOrder.reason 0..* CodeableConcept, remove the no-longer-needed diagnosticorder-reason extension, and add DiagnosticOrder.note 0..* Annotation for other order notes.

Initial application:
The issue was explicitly pre-applied in commit a7b323be06, titled "pre-applied #7134,#7135,#7684", which changed the then-authoritative DiagnosticOrder spreadsheet and examples from clinicalNotes to reason, added coded/text examples, and added DiagnosticOrder.note. Later history renamed DiagnosticOrder to DiagnosticRequest and then merged it into the current ServiceRequest successor.

Additional context:
source/fhir.ini lists ServiceRequest as active and comments that DiagnosticOrder was subsumed into ServiceRequest. Current ServiceRequest.reason and ServiceRequest.note already carry the seed semantics, including reason/indication wording, repeatable coded-or-referenced reason support, free-text reason guidance, and 0..* Annotation notes. The old diagnosticorder-reason extension remains only in tools/history release artifacts. A stale DiagnosticOrder.clinicalNotes path remains in source/profiles/cda.profile.xml, but the CDA profile entry is commented out in fhir.ini and is not current build scope. The active Library example surface publishes and links source/library/library-quick-model-definition-content.xml, where QUICK.DiagnosticOrder still exposed clinicalNotes.

AutoFHIR reconciliation:
This commit updates the active QUICK model-info XML so QUICK.DiagnosticOrder uses reason as a repeatable System.Concept and adds note as a repeatable System.String, matching the FHIR-7134 clinicalNotes split in the simplified QUICK model representation. It intentionally leaves retired DiagnosticOrder/DiagnosticRequest source, historical release artifacts, and the out-of-build CDA profile untouched.

Recommendation:
Keep this source fix. The authoritative current resource is already correct, and this commit removes the remaining build-scope stale model-info surface without reopening broader retired DiagnosticOrder or QUICK regeneration questions.
