FHIR-26551: Audit reversed ValueSet multiplicity extensions

Issue request:
FHIR-26551 was a Published/Persuasive Vocab change request raised against R4 and applied for R5. It asked to create two standard core ValueSet extensions supporting VSD ContentSystemElement.RelationshipBasedContent.MinimumMultiplicity and MaximumMultiplicity, with the Jira resolution saying to create the standard extensions as part of the core specification.

Initial application:
The request was initially applied in the R5 ValueSet/VSDP work. Commit 054eabf311 added the minimumMultiplicity and maximumMultiplicity extension StructureDefinitions and ValueSet-core ImplementationGuide entries, and commit c7fbae90f8 renamed the source references to valueset-compose-include-minimumMultiplicity and valueset-compose-include-maximumMultiplicity while wiring the VSD-aligned profile family.

Additional context:
The later Published/Persuasive Vocab issue FHIR-34259 explicitly reversed this part of the VSDP work after Rob McClure's research and the 2021-11-04 CPG/CQI Value Set Profiles discussion concluded the two extensions were not necessary and could not be implemented in a FHIR environment. FHIR-34259 was applied by commit 6cd93edefb, which deleted the two extension StructureDefinition XML files and removed their ValueSet-core IG references, and by commit 61b4f0d4a3, which removed the corresponding VSD-aligned profile slices. The combined branch already contains an audit commit for FHIR-34259, so this seed audit should not duplicate that related issue.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/fhir.ini keeps ValueSet in the active resource build, but current core source has no files, IG entries, profile slices, or canonical URLs for valueset-compose-include-minimumMultiplicity or valueset-compose-include-maximumMultiplicity. The FHIR Extension Pack also has no migrated copy of these extensions, and the checked release5 history artifacts do not contain the removed extension names. Reintroducing the original FHIR-26551 extensions would conflict with the later final FHIR-34259 decision.

Recommendation:
Keep this audit commit as-is and do not re-add the two ValueSet multiplicity extensions to FHIR core. Further work is only needed if the Vocab work group reopens or supersedes FHIR-34259 with a new design for relationship multiplicity constraints.
