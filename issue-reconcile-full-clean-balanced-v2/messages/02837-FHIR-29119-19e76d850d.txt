FHIR-29119: Audit concept subsumption outcome definitions

Issue request:
FHIR-29119 was a Published/Persuasive Vocabulary change request for R5. It reported that concept-subsumption-outcome code not-subsumed was incorrectly defined as A and B being disjoint, which was too strong because not-subsumed should cover the exhaustive case where neither code subsumes the other. The approved resolution also updated all four CodeSystem concept definitions and added CodeSystem-level text pointing readers to the FHIR CodeSystem definition of subsumption.

Initial application:
The issue was applied by Jess Bota in cb515c0480, which updated source/codesystem/codesystem-concept-subsumption-outcome.xml to add the CodeSystem description/title and replace the four concept definitions, including not-subsumed as "Neither A subsumes B nor B subsumes A". Follow-up commit c8876b14ca replaced the attempted markdown relative link with the wording "under Resource Types - CodeSystem", matching the later Jira comment and Vocabulary minutes that the applied text was accepted.

Additional context:
The current source still contains the FHIR-29119 definitions, and the terminology service narrative describes not-subsumed as concepts not related by any subsumption relationship. The concept-subsumption-outcome CodeSystem, the ValueSet that includes it, and the CodeSystem/$subsumes operation binding are current build-scope files because source/fhir.ini has active CodeSystem, ValueSet, and OperationDefinition entries. A later AutoFHIR audit for FHIR-34183 is already on the combined branch and confirms the same ValueSet/CodeSystem family exists in current source; it is a separate missing-artifact issue and does not require another decision here. Zulip searches found only implementation-specific $subsumes troubleshooting threads, not a conflicting specification decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current CodeSystem definition for not-subsumed is no longer the disjoint wording rejected by FHIR-29119, the other three concept definitions match the approved resolution, and the accepted CodeSystem description text remains present.

Recommendation:
Keep this no-change audit commit as-is. No core source follow-up is needed for FHIR-29119; any future refinement of the CodeSystem description into a rendered link would be an editorial improvement rather than required reconciliation of this Published issue.
