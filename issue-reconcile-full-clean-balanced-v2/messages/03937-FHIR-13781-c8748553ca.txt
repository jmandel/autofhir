FHIR-13781: Audit MedicationRequest category reconciliation

Issue request:
FHIR-13781 was a Published/Persuasive with Modification Pharmacy change request for the STU3 MedicationPrescription/MedicationRequest artifact. Despite the reasonCode/reasonReference title, the accepted request was to make MedicationRequest.category 0..*, change its binding from preferred to exemplar/example while retaining inpatient, outpatient, and community, and add usage notes allowing categories such as treatment types with profile-specific bindings/invariants.

Initial application:
The historical application is explicit in git commit cf35ab7ebc, whose message names GF #13781. That commit changed the old MedicationRequest spreadsheet category cardinality from 0..1 to 0..*, changed the category binding conformance from preferred to example, and added definition/comment text mentioning chemotherapy/endocrine treatment types and profile-specific value set binding.

Additional context:
The source and model subsequently changed. MedicationPrescription became MedicationRequest, and current source/fhir.ini lists MedicationRequest as an active resource. More importantly, later Published issue FHIR-15688 found MedicationRequest.category overloaded, resolved to put category back to the inpatient/outpatient/etc. care-setting use, and to separate treatment-type handling; commit b87c1a290d removed the chemotherapy/endocrine and invariant-profiling language from the category definition/comment. Related Published issue FHIR-17255 added MedicationRequest.courseOfTherapyType as a separate medication therapy-pattern element. Later terminology work restored the MedicationRequest category example CodeSystem/ValueSet to core, but did not reverse FHIR-15688's narrowing of the category prose.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The active MedicationRequest source already has category cardinality 0..*, an example binding to the in-core MedicationRequest category ValueSet, and the inpatient/outpatient/community category codes. Reintroducing the original FHIR-13781 treatment-type examples or profiling/invariant note would be a stale edit because FHIR-15688 later removed that language and split the concern from category.

Recommendation:
Keep this no-change audit as-is. The current build reflects the seed's durable structural changes after later Pharmacy decisions, and any renewed desire to represent chemotherapy/endocrine treatment classification should be handled under a fresh final tracker rather than by restoring superseded FHIR-13781 wording.
