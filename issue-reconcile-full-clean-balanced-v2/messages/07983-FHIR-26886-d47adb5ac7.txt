FHIR-26886: Audit chaining modifier guidance

Issue request:
FHIR-26886 was a Published/Not Persuasive with Modification FHIR-I R4 issue asking for clarification on modifiers in reverse-chaining queries, especially a query such as Patient?_has:Condition:patient:code:not=X,Y,Z. The accepted resolution said the Search page did not address modifiers on forward or reverse chaining and should add notes to the Chaining and Reverse Chaining sections explaining that these queries are not intended to support modifiers, with _filter as an alternative.

Initial application:
The issue was applied by git commit 1750a1f28827a057685c0b8150320636ebc5e7e9, "FHIR-26886 - Chaining and modifiers", which added notes to source/search.html under both #chaining and #has. The forward-chaining note was later reorganized by the FHIR-45252 reconciliation, but the substance of the FHIR-26886 warning and links to Named Queries and Advanced filtering were preserved.

Additional context:
source/search.html is in the current build scope through publish.ini. Earlier FHIR-12068 removed a blanket _has prohibition on modifiers/chaining, so the current language appropriately clarifies that modifiers are not intended for chaining while not prohibiting servers from experimenting. FHIR-13324 separately records that URL-based chained/reverse-chained search cannot express grouped joins well and points complex cases to _filter or composites. The FHIR-I minutes for 2020-05-11 record the FHIR-26886 Not Persuasive with Modification motion, and the Zulip thread that prompted the issue confirms the original ambiguity: participants observed that the spec did not say either way.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Search page already contains the requested forward-chaining note at source/search.html:4506-4508 and the requested reverse-chaining note at source/search.html:4573-4576, each pointing to advanced alternatives including _filter.

Recommendation:
Keep this audit commit as-is. No source edit is needed for FHIR-26886 unless FHIR-I later decides to define portable modifier semantics for chained or reverse-chained search instead of leaving them outside the intended URL-search surface.
