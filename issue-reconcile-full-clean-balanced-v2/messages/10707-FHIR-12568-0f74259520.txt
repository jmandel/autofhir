FHIR-12568: Audit Subscription multiple header support

Issue request:
FHIR-12568 was Published/Persuasive for FHIR-core Subscription after a 7-0-0 fhir-i vote. It asked to increase Subscription.channel.header from 0..1 to 0..* so REST-hook subscriptions could carry multiple outgoing notification headers, and to document the header format clearly.

Initial application:
The Jira comments point to an SVN application, and git history contains commit 003e481c663cde6269595c85593bbc62b7ddf05a with the explicit #12568 message. That commit changed the Subscription spreadsheet source for Subscription.channel.header from 0..1 to 0..* and expanded the comment to mention multiple REST-hook headers. No separate current source omission was found for the original cardinality change.

Additional context:
Subscription is still an active, approved resource in the current build, but the current resource no longer has Subscription.channel.header. Later Published issue FHIR-39034 replaced the repeated string header element with repeated Subscription.parameter backbone entries containing name and value, with repeated values/names allowed. The current Subscription definition keeps Subscription.parameter at 0..* and explicitly cites support for multiple REST-hook headers; the current REST-hook prose says each Subscription.parameter is sent as an HTTP request header formatted as {parameter.name}: {parameter.value}. Zulip and Confluence searches found no conflicting community evidence for FHIR-12568 or the old Subscription.channel.header wording.

Recommendation:
