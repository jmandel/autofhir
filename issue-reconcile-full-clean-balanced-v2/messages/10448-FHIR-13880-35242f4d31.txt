FHIR-13880: Audit reserved-word code generation warning

Issue request:
FHIR-13880 was a Published FHIR-core STU3 change request asking for automated enforcement of a banned list of reserved words for Java, C#, SQL, Javascript, and Delphi in extension names. The final Not Persuasive with Modification resolution rejected a language-specific banned list because reserved words are numerous and context-dependent, and instead required a note that StructureDefinition.name and sliceName values used in code may collide with target-language reserved words and must be adjusted by code generation processes.

Initial application:
The issue was applied in git commit d26f97fdfc929858462f012cccd8520c21fb9488, which matches the Jira comment "svn 14560" via git-svn-id build@14560. That commit added the reserved-word collision warning to source/structuredefinition/structuredefinition-introduction.xml and source/downloads.html. Later editorial and download-page changes preserved and lightly polished the warning text.

Additional context:
The current build includes StructureDefinition as an active resource in source/fhir.ini and includes downloads.html in source/hierarchy.xml under Implementation Support. The current warning explicitly covers names relevant for code generation, including structure names, element and slice names, codes, and target-language reserved words. Jira searches for the same reserved-word/code-generation topic found only FHIR-13880, and issue-key Zulip and Confluence searches found no directly relevant or conflicting community record.

AutoFHIR reconciliation:
