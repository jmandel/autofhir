FHIR-8002: Audit validate mode value set binding

Issue request:
FHIR-8002 was a Published/Persuasive DSTU1 FHIR-core BaseResource change request asking to add the Resource $validate mode parameter as a value set instead of leaving it as an unconstrained string.

Initial application:
Jira records SVN revision 5534, and the converted git commit 4f363ad0bd1afafaa97da59cb1cee0d469fcf2ef has the matching git-svn-id for build@5534. That commit changed the Resource operation spreadsheet so validate.mode became type code with the ResourceValidationMode binding and added the resource-validation-mode value set worksheet.

Additional context:
The current source has since been refactored from spreadsheets into OperationDefinition, CodeSystem, and ValueSet XML. Later $validate work, including FHIR-41357, clarified mode semantics and the resource/profile parameters but did not remove or weaken the required mode binding. FHIR-8446 separately corrected the mode=create definition typo in the same validation mode family.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change because source/resource/operationdefinition-Resource-validate.xml already defines the in parameter mode as code with a required binding to http://hl7.org/fhir/ValueSet/resource-validation-mode, and source/resource/valueset-resource-validation-mode.xml composes the complete code system source/resource/codesystem-resource-validation-mode.xml.

Recommendation:
Keep this no-change audit. The current source preserves the requested value set binding in build-scope Resource $validate artifacts; future work on $validate should proceed under later tracker items rather than reopening FHIR-8002.
