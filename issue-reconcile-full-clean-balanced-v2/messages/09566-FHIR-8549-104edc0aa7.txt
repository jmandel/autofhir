FHIR-8549: Audit superseded nested modifier restriction

Issue request:
FHIR-8549 was a Published/Persuasive FHIR-core extensibility issue raised against DSTU1. It asked that tooling reject extension definitions whose nested child elements were flagged isModifier=Y while the specification did not yet allow modifier extensions inside complex extensions.

Initial application:
The issue was applied in git commit 467588e0b14b4d1a761ab22b4424968836f1e49f, whose subject says "#8549 - do not allow nested extensions to have modifier flag + add support for extension invariants" and whose svn revision matches the Jira comment. That historical commit added a SpreadsheetParser exception for nested extension definitions marked as modifiers in tooling that is no longer present in the current checkout.

Additional context:
FHIR-8549 was explicitly temporary: its description said to reject such child elements "until such time" as FHIR decided extensions could contain modifiers. FHIR-8548, resolved later as Published/Not Persuasive with Modification, made exactly that decision and added source/extensibility.html language allowing complex extension elements to be Is-Modifier=true while representing them with extension, not modifierExtension. Later FHIR-11036, FHIR-18352, and FHIR-37903 refined the same guidance and are already represented on the combined branch. source/fhir.ini maps extension=extensibility, so source/extensibility.html is the active current build surface for this rule.

AutoFHIR reconciliation:
This empty commit intentionally makes no source change. Reintroducing the FHIR-8549 rejection into current source or tooling would contradict the later approved FHIR-8548 rule, and the current active source already states that complex extension parts may be Is-Modifier=true while externally defined modifierExtension content cannot be conveyed inside an extension.

Recommendation:
Keep this no-change audit commit. FHIR-8549 was correctly applied historically as a temporary guardrail, but it has been superseded by later final extensibility decisions; no current FHIR-core edit should restore the obsolete rejection.
