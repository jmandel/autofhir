FHIR-12174: Audit medication reason Observation support

Issue request:
FHIR-12174 was a Published/Persuasive Pharmacy change request from DSTU2 asking to support observations such as BP, pulse, or INR as related reasons for MedicationOrder and MedicationAdministration so they can inform administration, dose setting, or withholding. The recorded resolution agreed to add a reason reference to Observation to MedicationOrder after workflow harmonization discussion.

Initial application:
The issue appears to have been applied by commit 1d00edee4413c641918bdf96071c2407902bc4c3 on 2016-10-18, whose message includes "#12174 - added observation as a reason." The patch changed the former MedicationOrder.reasonReference from Reference(Condition) to Reference(Condition | Observation) and added MedicationAdministration.reasonReference as Reference(Condition | Observation).

Additional context:
MedicationOrder/MedicationPrescription is now represented by MedicationRequest in the active build, and source/fhir.ini lists both MedicationAdministration and MedicationRequest as active resources. Later Pharmacy changes, especially the FHIR-25929 CodeableReference migration and follow-up cleanup, changed the representation from separate reasonCode/reasonReference choices to a CodeableReference reason element. Current MedicationRequest.reason and MedicationAdministration.reason still include Observation as a targetProfile, alongside later permitted reason targets.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative current StructureDefinitions already preserve the FHIR-12174 requirement: MedicationRequest.reason is a CodeableReference targeting Observation, and MedicationAdministration.reason is a CodeableReference targeting Observation. Adding redundant prose or reintroducing old reasonReference naming would make the current R6 source less accurate.

Recommendation:
Keep this empty audit commit as-is. No FHIR core source follow-up is needed for FHIR-12174 unless the Pharmacy work group later decides to change the broader reason CodeableReference model or the set of permitted reason target resources.
