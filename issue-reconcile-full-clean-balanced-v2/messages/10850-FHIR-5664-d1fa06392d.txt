FHIR-5664: Audit Identifier.use modifier cardinality

Issue request:
FHIR-5664 was Published/Not Persuasive with Modification for DSTU1 datatypes. The reporter read the Identifier.use modifier marker as implying that the element was required and asked that Identifier.use either stop being indicated as required or change cardinality from 0..1 to 1..1. The work group clarified that the marker meant modifier, not mandatory, and the Jira comments record the applied publication change as using "?!" instead of the old marker.

Initial application:
No Git commit explicitly mentioning FHIR-5664 was found; the Jira application was an SVN-era publication note, "change to \"?!' instead. svn revision 4551." Current tracked datatype pages now render Identifier.use with a "?!" modifier marker and keep the cardinality 0..1, which matches the accepted explanation that use is optional even though it changes interpretation when present.

Additional context:
Later published Identifier.use decisions did not reverse the optional cardinality. FHIR-28472 clarified the modifier rationale, and FHIR-26676 added the same permanent-unless-temporary assumption at the Identifier level. Current active datatypes pages are referenced by source/fhir.ini, while generated StructureDefinition files under source/datatypes/ are ignored build outputs and were not edited.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active datatype source already distinguishes modifier status from required cardinality by showing "?!" and 0..1 for Identifier.use, and changing the cardinality to 1..1 would contradict the published resolution and later context that the use may be unknown or absent.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-5664 unless the datatype rendering system changes and reintroduces ambiguity between modifier markers and mandatory cardinality.
