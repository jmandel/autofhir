FHIR-11003: Audit Questionnaire initial default text

Issue request:
FHIR-11003 was a Published FHIR-core Questionnaire change request with a Not Persuasive with Modification resolution. The request proposed renaming Questionnaire.item.initial to Questionnaire.item.prePopInfo because the element name and short description were confusing; the approved modification retained the element name, changed the short description to describe a default value when first rendered, and added a note that users may override the value unless read-only and that unchanged initial values persist into the initial QuestionnaireResponse.

Initial application:
The issue was pre-applied in the DSTU2-era spreadsheet sources. Commit 76675fcc91 changed Questionnaire.item.initial's short name from "Initial presumed answer for question" to "Default value when item is first rendered". Commit 014f454e13, explicitly mentioning #11003, added the approved override/persistence comment and the GF#11003 committee note.

Additional context:
Questionnaire remains an active build resource in source/fhir.ini, and the current authoritative StructureDefinition source has the GF#11003 note on Questionnaire.item.initial. After later source refactoring, the current short description is "Initial value(s) when item is first rendered" rather than the exact 2016 wording, but the adjacent definition says the values are pre-populated for rendering and the comment preserves the approved user-override and persistence semantics, including the word "default". Jira searches found no linked issue changing this decision, and Zulip/Confluence searches found no conflicting community guidance.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current active source preserves the approved meaning: initial values are default/pre-populated values shown when rendering the Questionnaire, may be changed unless read-only, and persist into the initially created QuestionnaireResponse if unchanged. Changing only the short description back to the exact 2016 phrase would be editorial churn rather than a necessary semantic correction.

Recommendation:
Keep this no-change audit as-is. Revisit only if the Patient Care work group wants an editorial preference for the exact historical short-description wording; no current conformance or implementer-understanding fix is needed for FHIR-11003.
