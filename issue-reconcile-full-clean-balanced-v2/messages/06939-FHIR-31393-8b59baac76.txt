FHIR-31393: Audit ordinalValue expansion context

Issue request:
FHIR-31393 was Published with a Persuasive FHIR-I decision for R5. It asked to add ValueSet.expansion.contains as a context for the ordinalValue extension so ordinal values could be visible when looking at a ValueSet expansion.

Initial application:
Core commit 8df9b37980c9dd473e0ebf48bef9cce830725162 applied the issue by adding ValueSet.expansion.contains to the ordinalValue row in source/profiles/general-extensions-spreadsheet.xml. Core commit 02d5f0bffcaefadbf7619c9314915307cc4a0444 then renamed ordinalValue to itemWeight for FHIR-24672 while preserving that ValueSet.expansion.contains context. The general extension spreadsheet is still listed in source/fhir.ini, but the ordinalValue/itemWeight row no longer exists there because core commit dd468d4f1799dd79819315b211588ef1cf4586e0 removed extensions from the R5 core source.

Additional context:
FHIR-33540 later made a Published/Persuasive with Modification decision for the same ValueSet expansion weighting problem: remove CodeSystem.concept, ValueSet.compose.include.concept, and ValueSet.expansion.contains contexts from the itemWeight extension and represent CodeSystem/ValueSet weights with the defined concept property http://hl7.org/fhir/concept-properties#itemWeight instead. The current core source has active CodeSystem and ValueSet build entries, includes the concept-properties CodeSystem, defines itemWeight with decimal type, and lets ValueSet.$expand request and return expansion concept properties. The Extension Pack itemWeight definition is scoped away from CodeSystem/ValueSet and points users to the itemWeight property; the retained ordinalValue definition is retired. The combined branch already contains a FHIR-33540 audit commit for this later decision.

AutoFHIR reconciliation:
Made no source change. Restoring ValueSet.expansion.contains as an extension context would contradict the later FHIR-33540 decision and duplicate the current property-based expansion mechanism. The current core build surfaces already support the implementer outcome FHIR-31393 sought: ordinal/item weights can appear in ValueSet expansions as concept properties.

Recommendation:
Keep this audit commit as-is. Do not re-add ordinalValue or itemWeight extension contexts in core. If R4/R4B compatibility guidance or the retired Extension Pack ordinalValue definition needs different handling, that should be a separate work-group decision in the appropriate repository rather than a core-source fix for FHIR-31393.
