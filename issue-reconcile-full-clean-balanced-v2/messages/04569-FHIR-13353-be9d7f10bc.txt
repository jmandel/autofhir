FHIR-13353: Confirm Quantity unit binding guidance

Issue request:
FHIR-13353 was a Published FHIR-core datatypes issue, resolved Persuasive with Modification, asking for clearer guidance on how profiles and logical models can constrain units on Quantity. The accepted resolution was to update the Quantity datatype to reference the terminologies page that describes how to bind Quantity units to value sets.

Initial application:
The Jira application comment cites svn revision 14154. In this git history that is commit 07b20b4fc864ed477db0166f80391ea75878aada, which added the current Quantity text saying that the context of use may require a code from a particular system or a value set, and linking to Using Terminologies for binding Quantity to a value set to constrain unit codes.

Additional context:
The current build-scope configuration marks Quantity as a normative datatype with can-bind and has-units characteristics. Current source/datatypes.html still contains the FHIR-13353 link, and source/terminologies.html now explicitly summarizes Quantity binding as applying to Quantity.code and Quantity.system. The original Zulip thread confirms the concern was whether to use allowedUnits, direct Quantity.code/system binding, or a value set on Quantity. Later questionnaire-specific unitOption/unitValueSet issues clarify those extensions but do not supersede the general Quantity datatype guidance. The old elementdefinition-allowedUnits extension now lives in the FHIR Extension Pack, not active core source.
