FHIR-17362: Audit $everything care-date mapping

Issue request:
FHIR-17362 was Published/Persuasive for R5. It asked whether the Patient $everything start and end date parameters should follow normal date-search prefix/range behavior and how servers should know which resource dates count as care dates; the accepted resolution added CompartmentDefinition resource-level properties naming the search parameter(s) to use for $everything.start and $everything.end, required compartment definitions to populate those mappings, and called for cross-references between compartment search guidance and the $everything operations.

Initial application:
The explicit upstream application was git commit 8aebbfeb81b5da4d214d946e51388645baa4edcb, which added CompartmentDefinition.resource.startParam and CompartmentDefinition.resource.endParam. Later source history completed the practical mapping input: d116faa04d484120c90b33bc0d06cfe038915d42 (tracked in this run by FHIR-51729) added date/startdate/enddate columns to source/compartments.xml, and FHIR-25037 later corrected the Encounter end-date mapping to date-end. No prior Issue-Reconcile-Key commit for FHIR-17362 existed on the combined branch.

Additional context:
The 2019 FHIR Infrastructure Zulip thread and PA WGM minutes match the Jira disposition: $everything is broader than a compartment wildcard search, and care-date ambiguity should be handled by CompartmentDefinition mappings. Current source/fhir.ini keeps Patient and CompartmentDefinition active in the core build. Patient and Encounter $everything OperationDefinition sources were moved out of core to the Admin Incubator work in b487fdda4bb4a5382a93dbb5a811efd02425b9bc; core now links to those external operation pages from the HTTP compartment-search section and from the startParam/endParam definitions.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core source already defines startParam/endParam, provides the date/startdate/enddate spreadsheet inputs used to generate compartment definitions, and preserves the relevant compartment-search-to-$everything cross-reference. Adding more local prose would duplicate existing generated/source semantics, and editing the external Admin Incubator operation definitions is outside this core checkout.

Recommendation:
Keep this no-change audit commit. Future work, if needed, should be targeted at individual resource care-date choices or the external Admin Incubator operation definitions rather than re-opening the core CompartmentDefinition mechanism; FHIR-25037 is the pattern for a resource-specific mapping correction.
