FHIR-32543: Audit ConceptMap unmapped fixed-mode invariant

Issue request:
FHIR-32543 was a Published/Persuasive Vocabulary change request for R5. It asked what ConceptMap.group.unmapped.code means when group.unmapped.mode is not 'fixed' and was resolved by adding constraints so unmapped.code and unmapped.display may only be valued when unmapped.mode = fixed.

Initial application:
The issue was initially applied in git commit 6fcced7147, which added cmd-8 to source/conceptmap2/structuredefinition-ConceptMap2.xml with the rule "If the mode is not 'fixed', code, display and valueSet are not allowed". A later ConceptMap2-to-ConceptMap refactor preserved the same invariant in the current ConceptMap source.

Additional context:
source/fhir.ini lists conceptmap=ConceptMap as an active resource and assigns ConceptMap to the vocabulary work group, so source/conceptmap/structuredefinition-ConceptMap.xml is in current build scope. Current source has cmd-8 on ConceptMap.group.unmapped and condition references on mode, code, display, and valueSet. Vocabulary WG minutes for 2021-06-23 also record FHIR-32543 as adding invariants for the ConceptMap unmapped element. No issue-specific Zulip discussion or conflicting Confluence full-text hit was found.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already implements the approved rule by prohibiting code, display, and valueSet unless mode is fixed, which covers the requested code/display restriction and the analogous fixed valueSet case preserved by the applied commit.

Recommendation:
Keep this no-change audit commit as-is. No follow-up is needed for FHIR-32543 unless the work group later changes the semantics of ConceptMap.group.unmapped fixed-mode behavior.
