FHIR-38833: Audit CRMI pattern profile guidance

Issue request:
FHIR-38833 is a Published/Persuasive with Modification FHIR-I R5 issue asking to move the Shareable/Publishable patterns and associated Shareable/Publishable profiles from FHIR core to the CRMI IG. The accepted R5 resolution narrowed that request: core could not move the artifacts before publication, so the intended application was to add introductions to the affected profiles saying they would move to CRMI and encouraging implementers to look there for updates, corrections, and clarifications.

Initial application:
Jira records Git master 348dbf91cb. That commit added CRMI warning introductions for 20 Shareable, Publishable, Computable, and Executable profile pages; commit 885919d75b re-applied those notes as standalone profile-introduction files, and commit 80eecb02fa changed the hard-coded build.fhir.org link to the current [%ig crmi%] macro. Those intro files were later removed or became out-of-build stubs as the underlying profile definitions were migrated out of core.

Additional context:
The current R6 source reflects later, more specific decisions. FHIR-48393 removed the CDS/CQI profile definitions that had already moved to CRMI or related IGs, and FHIR-37959 removed the terminology-resource Shareable/Publishable/Computable/Executable profiles from core for R6 while maintaining them in CRMI. That related FHIR-37959 decision is already represented on the combined branch by commit d03c22085815adc28a5145788c36ffd231f07da2. Later CRMI issues FHIR-52711 and FHIR-52719 addressed the external CRMI URL/text details for the migrated terminology profiles. Current core source/fhir.ini still builds the Shareable and Publishable logical patterns, but not the migrated profile StructureDefinitions; current build-scope pattern and module narrative already tells implementers that CRMI contains the relevant content patterns, profiles, and guidance.

AutoFHIR reconciliation:
This is an empty audit commit. No core source change is needed for FHIR-38833 because the original R5 note was applied, the profile definitions have since been removed from current core build scope by later applied issues, and the remaining build-scope Shareable/Publishable pattern pages and Clinical Reasoning module text already point applications to CRMI. The remaining profile-introduction stub files for NamingSystem and ValueSet are not active profile definitions or active fhir.ini profile entries, so editing them would not correct the current built specification.

Recommendation:
Keep this audit commit as-is. Future changes to the migrated profile definitions, CRMI-specific canonical URL handling, or CRMI explanatory text should be made in the CRMI IG; core only needs reconsideration if a later FHIR-core decision changes whether the Shareable/Publishable logical patterns themselves should remain in the base specification.
