FHIR-2952: Audit Condition onset dateTime support

Issue request:
FHIR-2952 was Published/Persuasive with Modification and requested allowing a time component for Condition.onset[x]. The PC resolution voted to change the type from date to dateTime while still allowing date-only precision.

Initial application:
The historical application appears in git commit a7d4372eee6bc082995cfca0a3028c8f3afc48c9, which changed the then-authoritative Condition spreadsheet row for Condition.onset[x] from "date | Age" to "dateTime | Age", updated the short/definition text, and added committee note [#2952]. The current StructureDefinition was recreated during the 2021 source rework with dateTime still present and later preserved through R6 wording clarifications.

Additional context:
Condition is active in source/fhir.ini. The current active StructureDefinition has committee notes [#2952], J#42978 and allows dateTime, Age, Period, Range, and string for Condition.onset[x]. The Condition-onset-date search parameter also covers Condition.onset.ofType(dateTime) and Period. Later FHIR-42978 clarified onset wording for clinical events and situations without narrowing the dateTime type. FHIR-6334 separately changed abatement[x] to dateTime for consistency and does not alter the FHIR-2952 onset decision.

AutoFHIR reconciliation:
Made no source change. The current active Condition source already satisfies FHIR-2952, and an additional source edit would be redundant rather than corrective.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-2952 unless future Patient Care work independently revisits Condition.onset semantics.
