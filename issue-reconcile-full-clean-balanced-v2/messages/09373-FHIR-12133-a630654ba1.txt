FHIR-12133: Audit ConceptMap related-to relationship

Issue request:
FHIR-12133 was a Published/Persuasive with Modification DSTU2 FHIR-I issue saying that the required ConceptMap equivalence value set made unasserted map equivalence hard for Mayo Clinic and asking for a parent concept "related to" for equal/equivalent/narrower/wider/inexact mappings. Its resolution says the work was already done on a different task.

Initial application:
No commit explicitly mentions FHIR-12133. The same request was applied under FHIR-11279 in git-svn revision 9925, commit b11f1f4131, which added the relatedto code and made the existing ConceptMapEquivalence mapping codes children of it. The directly overlapping FHIR-10437 tracker was also resolved as already done under another task.

Additional context:
ConceptMap was redesigned for R5: FHIR-22632 renamed target.equivalence to target.relationship and retired the old ConceptMapEquivalence value set, while FHIR-25923 finalized the directional relationship code names. The current source keeps the requested general relationship as ConceptMapRelationship code related-to, makes equivalent/source-is-narrower-than-target/source-is-broader-than-target children of it, and keeps required bindings to the current concept-map-relationship value set. The overlapping FHIR-10437, FHIR-11279, FHIR-22632, and FHIR-25923 issues already have reconciliation commits on the combined branch.

AutoFHIR reconciliation:
No source change was made. The current build-scope ConceptMap resource and terminology source already preserve the requested general "related-to" parent in the successor ConceptMapRelationship value set, so adding or resurrecting the retired DSTU2 ConceptMapEquivalence artifact would be wrong for the current specification.

Recommendation:
Keep this audit commit as-is. Future ConceptMap relationship changes should be handled through the current ConceptMapRelationship code system and binding source, not by editing retired ConceptMapEquivalence artifacts.
