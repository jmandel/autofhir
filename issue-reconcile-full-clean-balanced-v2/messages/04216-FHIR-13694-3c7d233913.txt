FHIR-13694: Clarify logical Reference.identifier scope

Issue request:
FHIR-13694 was a Published/Persuasive FHIR-core datatypes issue asking for a definitive rule about whether Reference.identifier can carry any business identifier or only identifiers for concepts that can be represented as FHIR resources. The approved resolution said Reference.identifier points to a structure that can potentially be expressed as a FHIR resource, need not identify an actual FHIR instance, and must still respect any Reference type limits.

Initial application:
The Jira comment records svn revision 12470, represented in git by ae45563ea5abedd261338cf4ff404a07a722d4ed, which added the resolution language to source/datatypes/reference.xml and source/references.html. That application left the older definition wording saying the target would be expected to be exposed as a FHIR instance, so the current source still mixed the old wording with the clarified rule.

Additional context:
source/fhir.ini lists Reference as an active normative datatype, and source/hierarchy.xml includes references.html as the built References between Resources page. FHIR-13571 was rejected as no-change because FHIR-13694 resolved how to distinguish Reference.identifier from separate Identifier elements. FHIR-50120 later added canonical URL guidance without changing the FHIR-13694 scope rule. FHIR-50074 is still Triaged and quotes the same current wording as confusing, so it is useful evidence of ambiguity but not an independent final decision to reconcile here.

AutoFHIR reconciliation:
Updated the active Reference datatype definition and References page to use the approved FHIR-13694 phrase "can potentially be expressed as a FHIR resource" instead of the stale "expected to be exposed as a FHIR instance" wording. The edit also fixed adjacent grammar and the Reference(Any) parenthesis so the source consistently says that an actual FHIR instance need not exist while the referenced business concept must still be capable of FHIR-resource expression and satisfy allowed type constraints.

Recommendation:
Keep this source fix. It is a narrow clarification of an already-published decision and should not be treated as resolving the still-Triaged FHIR-50074 beyond providing context for that future review.
