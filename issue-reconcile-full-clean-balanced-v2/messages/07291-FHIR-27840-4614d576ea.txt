FHIR-27840: Audit OperationOutcome severity guidance

Issue request:
FHIR-27840 was Published/Persuasive with Modification for R5 after asking whether OperationOutcome.issue.severity information and OperationOutcome.issue.code informational could be used when an OperationOutcome reports successful checks or outcomes without actual problems. The accepted resolution did not add a success message then; it required a usage note on OperationOutcome.issue.code explaining that code values should generally align with severity, while preserving flexibility because there are no strict rules tying each issue code to one severity.

Initial application:
Commit 4f468df051 added the approved comment to source/operationoutcome/structuredefinition-OperationOutcome.xml on OperationOutcome.issue.code. The current source still contains that same comment, and OperationOutcome is an active current-build resource in source/fhir.ini.

Additional context:
FHIR-32445 is related AuditEvent terminology context: it noted that AuditEvent outcome should import OperationOutcome issue-severity codes and that issue-severity would be sufficient if a success code were added. FHIR-39622 later made that substantive change by adding success to issue-severity and intentionally not excluding it from OperationOutcome; that later issue is already represented on the combined branch. The later success code does not make FHIR-27840 incomplete, because the FHIR-27840 resolution's required OperationOutcome.issue.code guidance remains present and the later success-code decision supersedes the earlier no-success direction.

AutoFHIR reconciliation:
This audit commit makes no source change. The current build-scope OperationOutcome source already includes the exact approved guidance for FHIR-27840, and changing the current success-code state would incorrectly revisit later published terminology decisions rather than reconcile this issue.

Recommendation:
Keep this audit as-is. No follow-up source edit is needed for FHIR-27840; any future change to OperationOutcome success semantics should be handled as a new substantive tracker or through the already-audited FHIR-39622 family.
