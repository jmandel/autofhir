FHIR-13717: Audit data-changed trigger type

Issue request:
FHIR-13717 was a Published/Persuasive CDS issue for STU3 datatypes. It requested a data-changed TriggerDefinition type for any data change, with data-changed as the parent of the existing added/updated/removed data event codes.

Initial application:
Jira records the application as SVN 12254 and 12258. Git-svn commit 068f0b3582 (SVN r12254) added data-changed to the TriggerDefinition.type allowed codes and EventDefinition examples. Git-svn commit d9b5a43d92 (SVN r12258) then moved data-changed ahead of the specific data events and made data-added, data-modified, and data-removed children of data-changed. The resolution wording says data-updated, which maps to the existing data-modified code whose display is Data Updated.

Additional context:
TriggerDefinition is an active metadata type in source/fhir.ini, and EventDefinition remains an active resource using TriggerDefinition triggers. A later same-area Published issue, FHIR-14281, concerns required elements for trigger types and is already represented on the combined branch; it does not change the data-changed hierarchy. Later FHIR-53414 EventDefinition example and condition-guidance work also keeps data-changed as the broad data event. Zulip and Confluence searches found no conflicting work-group or community record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current TriggerDefinition source already lists data-changed in TriggerDefinition.type, defines it as any add/modify/remove change, and records data-added, data-modified, and data-removed as children of data-changed. Current EventDefinition examples also use data-changed for all data changes.

Recommendation:
Keep this audit commit as-is. No follow-up source change is needed for FHIR-13717 unless a future work-group decision renames data-modified or changes the TriggerDefinition data-event hierarchy.
