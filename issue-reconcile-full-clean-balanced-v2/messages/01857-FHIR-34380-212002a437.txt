FHIR-34380: Audit practitioner service modes application

Issue request:
FHIR-34380 was a Published/Persuasive with Modification PA request to add a PractitionerRole attribute for the modes by which a practitioner can provide services, add a matching search parameter, add example service-mode terminology, bind PractitionerRole.characteristic to that terminology, and update HealthcareService.characteristic example terminology in the same area.

Initial application:
The issue was applied by git commit 674ac4c30338106ba2fc79fb3203bcb7e535ad03, which added PractitionerRole.characteristic, the PractitionerRole characteristic search parameter, the service-mode CodeSystem and ValueSet, and the HealthcareService.characteristic binding to the service-mode ValueSet.

Additional context:
Current source still contains those changes in active build-scope resource folders listed in source/fhir.ini for PractitionerRole and HealthcareService. Later Applied issue FHIR-39306 records that an example value set for HealthcareService.characteristics had already been added, and later Applied issue FHIR-53269 intentionally updates the service-mode CodeSystem/ValueSet metadata by setting experimental=false. FHIR-55297 is a later Resolved - change required proposal to move the HealthcareService service-mode binding to THO, but it is not Applied/Published in this default reconciliation scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. PractitionerRole.characteristic, its search parameter, and service-mode terminology are present, and later PA decisions treat the HealthcareService.characteristic service-mode binding as the existing example value set rather than requiring a new current-core correction.

Recommendation:
Keep this audit commit as-is for FHIR-34380. Future terminology movement for service-mode should proceed through the later THO-migration work such as FHIR-55297 rather than through this R5 PractitionerRole reconciliation.
