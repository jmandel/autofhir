FHIR-33066: Audit Identifier check digit handling

Issue request:
FHIR-33066 was Published with a Persuasive with Modification resolution for R5. The request asked for Identifier support for v2 CX check digit, check digit scheme, and assigning facility concepts. The accepted disposition rejected a standard assigning-facility extension, added standard check digit/check digit scheme extension support, and required Identifier and extension documentation to say that the rules of the identifier type determine whether the check digit is part of Identifier.value or sent separately.

Initial application:
Core commit 699fdc9b06a18e9faa6fbfaae588f237c483bfff, titled "fhir-33066", added the Identifier datatype comment that the rules of identifier.type determine whether a check digit is part of the ID value or sent separately through the checkDigit extension. The current core source also carries OID assignments for identifier-checkDigit and namingsystem-checkDigit. The extension definitions themselves are not current core-owned source; they are present in the FHIR Extension Pack checkout.

Additional context:
source/fhir.ini lists Identifier as an active datatype and normative artifact, so source/datatypes/identifier.xml is in current build scope. The Extension Pack contains identifier-checkDigit scoped to Identifier and namingsystem-checkDigit scoped to NamingSystem, each with the rule about the ID type determining whether the check digit is included in the ID value or transmitted separately. No directly relevant Zulip discussion or conflicting Confluence decision was found; Confluence references are recurring v2-to-FHIR tracker/minutes references rather than a different MnM disposition.
