FHIR-7566: Audit AuditEvent security label rename

Issue request:
FHIR-7566 was a Published/Persuasive with Modification DSTU1 Security change request asking to replace AuditEvent.object.sensitivity with the correct confidentiality/security-label terminology. The final resolution was to rename sensitivity to security-tags and use the same explanation as Resource meta security tags, allowing the element to carry any security tag.

Initial application:
The issue appears to have been applied in git commit 8e1a48066d70501f76de61f4511ec19b48da2df2, a multi-issue Security update whose AuditEvent spreadsheet source changed AuditEvent.object.sensitivity to AuditEvent.object.securityLabel, switched the binding from AuditEventObjectSensitivity to SecurityLabels, and described the element as security labels applied to the object. No current source still defines AuditEvent.object.sensitivity.

Additional context:
AuditEvent is active in the current build through source/fhir.ini. Later AuditEvent refactoring renamed the old object backbone to entity, and source/fhir.ini maps AuditEvent.object to AuditEvent.entity for version conversion. Current source therefore carries the successor element as AuditEvent.entity.securityLabel. Later Published issue FHIR-32471 changed AuditEvent and other non-normative securityLabel bindings to example security-label value sets, so the current example binding should not be reverted merely to match the older DSTU1 wording literally. FHIR-7709 is a duplicate of the same 2015 request. Zulip and Confluence searches found no directly relevant conflicting community record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current build-scope source already uses AuditEvent.entity.securityLabel, binds it to a security label example value set, retains DICOM/RIM mappings including confidentialityCode/ParticipantObjectSensitivity, and has no stale AuditEvent.object.sensitivity or AuditEvent.object.confidentiality element to correct.

Recommendation:
Keep this no-change audit commit. Any future work on AuditEvent.entity.securityLabel wording or binding should be handled under the later security-label binding decisions such as FHIR-32471, not by reopening this DSTU1 rename request.
