FHIR-15617: Audit ValueSet validate-code version parameters

Issue request:
FHIR-15617 was Published/Persuasive for STU3 by Vocabulary. It asked ValueSet $validate-code to add an input parameter for the value set business version and to rename the existing input parameter named version, which represented the code system version from source data, so it would not be confused with the value set version. The final resolution was to add valueSetVersion and rename version to systemVersion.

Initial application:
Jira comments record that the issue was pre-applied in SVN revision 13311. Git history maps that to commit 71e9614479, whose subject names GF#15617 and whose patch added validate-code.valueSetVersion and renamed validate-code.version to validate-code.systemVersion in the then-authoritative ValueSet spreadsheet source.

Additional context:
The current build no longer uses the old spreadsheet file for this operation; ValueSet is an active resource in source/fhir.ini and source/valueset/list-ValueSet-operations.xml references OperationDefinition/ValueSet-validate-code. Later applied issue FHIR-52907 intentionally added the system-version, check-system-version, and force-system-version canonical parameter family to ValueSet $validate-code and explicitly distinguished that family from systemVersion, so those additional current parameters do not reverse or confuse the FHIR-15617 rename.

AutoFHIR reconciliation:
No source change was made. The current authoritative operation definition already defines valueSetVersion as an input parameter and systemVersion as the renamed input parameter; a namespace-aware XML parameter check confirmed there is no remaining input parameter named version on ValueSet $validate-code, only the separate output parameter named version for the validated code system version.

Recommendation:
Keep this empty audit commit. The current source satisfies the published FHIR-15617 request, and changing terminology prose or examples would be redundant rather than corrective.
