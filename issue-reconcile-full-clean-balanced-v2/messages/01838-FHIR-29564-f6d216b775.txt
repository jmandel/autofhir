FHIR-29564: Audit manufacturing date extension location

Issue request:
FHIR-29564 was a Published Pharmacy change request, resolved Persuasive with Modification for R5, asking to add a Manufacturing Date attribute to Medication.Batch. The Jira description specified the date associated with manufacturing a batch, and the final resolution said to create a core extension for the attribute.

Initial application:
No source commit was found whose message explicitly names FHIR-29564. Git history shows the request was nevertheless applied in the Medication manufacturing-batch extension family: commit 52f3ef3d50 added the manufacturingBatch extension family to source/medication/medication-extensions-spreadsheet.xml, commit 5faa63a834 added the manufacturingDate description that points to manufacturingDateClassification for the process step/rationale, commit 33b409a4b6 generated source/medication/structuredefinition-extension-medication-manufacturingBatch.xml with manufacturingDate as a 0..1 dateTime slice, and commit dd468d4f17 later removed that core extension source when R5 extensions were moved out of this repository. The Extension Pack imported and retained the same extension family.

Additional context:
Medication remains an active core resource, but the current core source maps the historical Medication.batch path to Medication.instance and no longer owns the medication-manufacturingBatch StructureDefinition except for its OID registry entry. The same extension now lives in the FHIR Extension Pack, whose input/definitions/multiple/StructureDefinition-medication-manufacturingBatch.xml applies to Medication.batch and defines Extension.extension:manufacturingDate with a dateTime value. Pharmacy minutes for 2020-11-09 record the PQ/CMC manufacturing discussion and the 9-0-0 carried block vote, including FHIR-29564, to add a core extension. A broader Zulip search found implementation discussion of profiling medication-manufacturingBatch, with no later conflicting decision found.

AutoFHIR reconciliation:
This commit intentionally makes no HL7/fhir source change. The requested conformance content exists in the current external source of truth, HL7/fhir-extensions, and reintroducing the extension source into core would conflict with the post-R5 extension repository split.

Recommendation:
Keep this audit commit as an external-repo decision. No core FHIR source change is recommended; any future content correction to medication-manufacturingBatch should be made in HL7/fhir-extensions rather than reintroducing the extension source into core.
