FHIR-37545: Audit Device operation rename

Issue request:
FHIR-37545 was Published/Persuasive for R5. It requested additional updates to the Device.operationalState work, including renaming the backbone to Device.operation, updating short descriptions for operation/status/statusReason/operator/mode/cycle/duration, changing duration to the Duration datatype, and renaming the related value set/code system names from operational-state/status wording to operation wording while keeping the same code sets.

Initial application:
The issue was applied in the R5 source history. Commit cd0f210b03fb (FHIR-37545) adjusted Device operational-state descriptions and renamed Device operation terminology resources. Commit 2dd17b8ba4d5 continued the work by renaming Device.operationalState paths to Device.operation paths, changing bindings to device-operationstatus/device-operation-mode, and carrying the requested short-description updates. Commit 689b68cc93e0 then removed old Device operational-state/mode/status terminology files that were not needed after the rename.

Additional context:
Related R5 issue FHIR-36195 created the original operationalState/operation backbone, and FHIR-36208/FHIR-36213 created the status and statusReason terminology that FHIR-37545 referenced. Later Published issue FHIR-38904 removed the Device.operation status/statusReason/operator backbone content and kept mode/cycle/duration at Device level for R5. Later Applied issue FHIR-32565 moved Device.mode, Device.cycle, and Device.duration out of core Device into extensions; FHIR-47323/FHIR-48924 and the Extension Pack use the operation-specific extension and terminology names, including device-operation-mode. Later Applied issue FHIR-47604 removed the DeviceAssociation operation backbone as well and carried operational-state concepts through DeviceAssociation.associationStatus.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Device is active in source/fhir.ini, but the parsed current Device StructureDefinition has no active Device.operation, Device.operationalState, Device.mode, Device.cycle, or Device.duration elements, and DeviceAssociation has no active operation backbone. The surviving active operation-mode and operation-status-reason terminology files already use the operation-specific names requested by FHIR-37545. Reintroducing or renaming operation/status elements now would contradict later applied Device and DeviceAssociation decisions. Legacy device-operationalstatus/device-operational-state-mode source and OID entries remain, but they are not bound by active Device or DeviceAssociation definitions; retiring those canonical artifacts would be a separate terminology cleanup decision, not a safe FHIR-37545 source fix.

Recommendation:
Keep this audit commit as-is. Do not reintroduce Device.operation for FHIR-37545. If the work group wants to retire legacy unbound device-operationalstatus or device-operational-state-mode artifacts, handle that as a separate terminology review so it can consider compatibility and canonical-retirement policy explicitly.
