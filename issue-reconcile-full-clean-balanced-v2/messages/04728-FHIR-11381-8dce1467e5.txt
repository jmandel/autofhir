FHIR-11381: Audit CommunicationRequest topic evolution

Issue request:
FHIR-11381 was Published/Persuasive with Modification for DSTU2 after the 2016 September ballot. It asked Patient Care to expand CommunicationRequest.encounter so the request could identify the resource that was the topic of the communication. The accepted resolution was to add CommunicationRequest.topic as 0..* Reference(Any) and change CommunicationRequest.encounter to CommunicationRequest.context as Reference(Encounter | EpisodeOfCare).

Initial application:
The issue was applied by c124072d7bc14dd9eea48ac1aaf530bcd31171a6 on 2016-11-04. That commit updated the then-authoritative CommunicationRequest spreadsheet to replace CommunicationRequest.encounter with CommunicationRequest.topic 0..* Reference(Any) plus CommunicationRequest.context 0..1 Reference(Encounter | EpisodeOfCare), both marked GF#11381.

Additional context:
Later published Patient Care decisions intentionally changed both names. FHIR-13705 removed CommunicationRequest.topic and replaced the resource-that-the-communication-is-about concept with CommunicationRequest.about 0..* Reference(Any); the current StructureDefinition preserves that as CommunicationRequest.about with committee notes GF#11381, 13705 and targetProfile Resource. FHIR-19511 then changed Patient Care context elements back to encounter 0..1 Reference(Encounter), with EpisodeOfCare support handled by the workflow extension now maintained outside core; the combined branch already contains no-change/source-fix audit commits for FHIR-13705 and FHIR-19511. Current source/fhir.ini lists CommunicationRequest as an active resource, so source/communicationrequest/structuredefinition-CommunicationRequest.xml and its search parameter bundle are in current build scope.

AutoFHIR reconciliation:
This audit makes no source change. Current active core source already reflects the surviving FHIR-11381 semantics as modified by later published decisions: CommunicationRequest.about is the current Reference(Any) topic-like association, CommunicationRequest.encounter is the intentionally restored Encounter reference, and there is no active CommunicationRequest.topic element to reintroduce.

Recommendation:
Keep this no-change audit. Reverting the current model to topic/context for this old tracker would contradict FHIR-13705 and FHIR-19511; any future desire to rename about or broaden encounter again should be raised as a new Patient Care issue rather than as a FHIR-11381 reconciliation.
