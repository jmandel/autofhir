FHIR-39622: Audit issue-severity success code

Issue request:
FHIR-39622 was Published/Persuasive with Modification for R5 after asking for a success code in the issue-severity CodeSystem so AuditEvent.outcome would not need to use the legacy DICOM AuditMessage code 0. The written resolution said to add success and exclude it from the OperationOutcome value set, but the Jira application comment records that the code was not excluded because OperationOutcome also needed the code.

Initial application:
Commit 8f211ebdac added the success concept to source/operationoutcome/codesystem-issue-severity.xml and added success to the OperationOutcome.issue.severity short display. Commit 37ac63c5f9 then updated source/auditevent/valueset-audit-event-outcome.xml so AuditEvent outcome imports http://hl7.org/fhir/issue-severity instead of carrying the old DICOM 0 include.

Additional context:
OperationOutcome and AuditEvent are active current-build resources in source/fhir.ini. The current source still has the success code, OperationOutcome.issue.severity still binds to the issue-severity value set and lists success, and AuditEvent.outcome binds to a value set that includes issue-severity. FHIR-32445 is a same terminology-family decision requiring AuditEvent outcome to use OperationOutcome issue-severity codes and noting that issue-severity would be sufficient once success was added; that related issue is already represented on the combined branch. FHIR-27840 is earlier background on successful OperationOutcome responses, but FHIR-39622 and its implementation are the later accepted source state. Focused Zulip and Confluence searches found the FHIR-I vote minutes and no conflicting community decision.

AutoFHIR reconciliation:
This audit commit makes no source change. Excluding success from OperationOutcome now would reverse the applied Jira comment and the 2023 source commit rather than fixing a current-spec defect.

Recommendation:
Keep this audit as-is. If a work group wants OperationOutcome to disallow success in the future, that should be handled as a new substantive tracker because the current published source already reflects FHIR-39622 plus the AuditEvent outcome family.
