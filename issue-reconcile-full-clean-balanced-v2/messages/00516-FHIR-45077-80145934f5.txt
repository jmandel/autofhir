Issue request:
FHIR-45077 was an Applied/Persuasive Security work group issue asking for Permission activity actors to support role-only matching, by replicating the Consent.provision.actor backbone with role and reference semantics.

Initial application:
No commit found in history mentions the Jira key directly. The request appears to have been applied while Permission was active in core by commit 888dcbab3ac68f2ed5098d0f16e2962a5fbb8e1b, "Permission needs and activity role code", which changed source/permission/structuredefinition-Permission.xml so Permission.rule.activity.actor became a backbone with Permission.rule.activity.actor.role and Permission.rule.activity.actor.reference mapped to Consent.provision.actor.role and Consent.provision.actor.reference.

Additional context:
After that application, commit 0e2a8a7f839d5e1a43787523daccf07d958362f3 removed Permission from the current core build by deleting source/permission and removing active source/fhir.ini Permission entries. The current Security module no longer links a core permission.html page; it links Permission to the HL7 Data Access Policies IG. The current external Permission StructureDefinition in that IG still includes Permission.rule.activity.actor.role with an extensible participation-role-type binding.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. Reintroducing source/permission or restoring source/fhir.ini Permission entries would conflict with the later move of Permission out of the current core build, and the requested role element is preserved in the external Permission source of truth.

Recommendation:
Keep this external-repo audit as-is. No core follow-up is indicated for FHIR-45077 unless a future final work group decision moves Permission back into core; ongoing Permission activity actor changes should be made in HL7/data-access-policies.
