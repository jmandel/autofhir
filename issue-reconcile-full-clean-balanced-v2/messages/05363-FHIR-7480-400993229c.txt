FHIR-7480: Audit Medication value set naming correction

Issue request:
FHIR-7480 is a Published/Persuasive Pharmacy correction from the DSTU1 May 2015 ballot. It reported that Medication-related value sets appeared to be the same value set referenced with different names, with the linked MedicationFormalRepresentation value-set content actually showing route-of-administration codes rather than the intended medication terminology.

Initial application:
The historical application commit 534313123abc479f1c95a22956d9992582f9743c explicitly lists 7480 in its subject and changed source/medication/valueset-medication-package-form-codes.xml from the SNOMED CT route-of-administration root 284009009 to the package-form root 408102007. The companion Medication.code correction was applied the next day by 6ce87fde09500c2d61c86a07ac98f49037e7d747 for FHIR-8064, changing source/medication/valueset-medication-codes.xml from 284009009 to 410942007.

Additional context:
FHIR-7480 overlaps the already-audited Medication.code and package/container ballot family: FHIR-7743, FHIR-8022, FHIR-8061, FHIR-8063, FHIR-8064, FHIR-8066, and FHIR-12347. Medication is active in the current build. Current Medication.code binds to http://hl7.org/fhir/ValueSet/medication-codes, and that ValueSet now composes SNOMED CT is-a 763158003 medicinal product codes because later Published issue FHIR-19294 superseded the 2015 410942007 root. Current Medication no longer has Medication.package.container; package quantity information is represented by Medication.packageSize, while detailed package/container terminology lives in the current packaging model. Zulip and Confluence searches found no conflicting community evidence.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The original route-code problem was applied historically, current Medication.code no longer points at route-of-administration codes, and reapplying the exact 2015 wording would either duplicate already-audited companion issues or reverse later final Pharmacy terminology decisions.

Recommendation:
Keep this no-change audit as-is. Do not change the current Medication value set back to 410942007 or resurrect Medication.package.container for FHIR-7480; any future medication terminology or stale value-set cleanup should be handled as a separate Pharmacy/terminology decision.
