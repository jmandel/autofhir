FHIR-26535: Audit categorizing search parameters

Issue request:
FHIR-26535 was Published/Persuasive for R5 after BR&R approval, asking to add categorizing search parameters for MedicinalProductDefinition.type, MedicinalProductDefinition.domain, SubstanceDefinition.domain, SubstanceDefinition.category, and SubstanceDefinition.name.

Initial application:
The issue was applied in March 2020 by Jira-tagged commits: d25d442b40 added MedicinalProductDefinition type/domain search-parameter spreadsheet rows, and 3885120c62 added SubstanceDefinition domain/category/name search-parameter spreadsheet rows while also applying two nearby SubstanceDefinition issues.

Additional context:
The current build no longer uses the old SubstanceDefinition.category element because later Published issue FHIR-31823 explicitly accepted dropping category and combining it with the existing 0..* SubstanceDefinition.classification element. Current source therefore exposes a SubstanceDefinition classification search parameter instead of category. MedicinalProductDefinition and SubstanceDefinition are active resources in source/fhir.ini, and their checked-in search-parameter bundles contain the requested current search surfaces.

AutoFHIR reconciliation:
No source change was made. The active current source already includes MedicinalProductDefinition domain and type search parameters, SubstanceDefinition domain and name search parameters, and the later-approved SubstanceDefinition classification search parameter that supersedes the original category search parameter.

Recommendation:
Keep this audit commit as-is. Reintroducing a SubstanceDefinition.category search parameter would conflict with FHIR-31823; future work should only revisit this if BR&R makes a new decision to restore category as a distinct current element or search code.
