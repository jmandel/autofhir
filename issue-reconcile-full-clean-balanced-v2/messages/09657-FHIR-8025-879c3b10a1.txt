FHIR-8025: Audit document IG example removal

Issue request:
FHIR-8025 was a Published/Not Persuasive with Modification FHIR-I issue against the FHIR Documents page. It objected to the DSTU wording that listed "FHIR Implementation guides" as an example of non-clinical FHIR documents, saying FHIR IGs are not composition resources. The final disposition said Composition can be one possible way to express an implementation guide using sections and profiling, but suggested any Composition-page example should be discussed with Structured Documents first because mandatory Composition elements might not fit an IG.

Initial application:
The issue appears to have been applied by 30c5d5f934984dbf392d563c3e48693061af5f1f, "Updates for FHIR-33942, 17060, 8025, and 35830". That commit edited source/documents.html and removed "FHIR Implementation guides" from the non-clinical FHIR document examples. It did not add a Composition-page IG example, and no later source history or community record found in this reconciliation shows a Structured Documents approval for such an example.

Additional context:
The current source/documents.html page is in build scope through publish.ini and source/hierarchy.xml, and Composition remains an active resource in source/fhir.ini. The current Documents introduction still omits Implementation Guides from the non-clinical examples and describes FHIR documents as authored and assembled in FHIR, while ImplementationGuide is separately defined elsewhere in the conformance material. The later Published FHIR-35830 decision, already represented on the combined branch, independently asked to remove Implementation Guide as a document example from the same paragraph, confirming that the current source should not reintroduce that example.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The contested wording is already gone from the active Documents source, current Composition narrative does not assert that FHIR IGs are Composition resources, and adding a new IG-as-Composition example now would be speculative without the Structured Documents agreement that the FHIR-8025 disposition made conditional.

Recommendation:
Keep this audit commit as-is. No current core source edit is needed for FHIR-8025; if Structured Documents or FHIR-I wants an explicit Composition example for an implementation guide, that should be handled as a new work-group decision with a concrete example and constraints.
