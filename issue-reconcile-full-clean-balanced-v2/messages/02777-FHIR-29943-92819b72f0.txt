FHIR-29943: Audit ShareableValueSet publisher requirement

Issue request:
FHIR-29943 is a Published/Persuasive Vocab change request for R5. It asked that the ShareableValueSet profile stop requiring publisher, because VSD-P use cases may supply author and steward instead, and raised whether description should also stop being required because VSD-P scope guidance might replace it.

Initial application:
No HL7/fhir commit explicitly mentions FHIR-29943. The requested publisher cardinality change appears to have been applied during R5 ValueSet profile work: commits 9fca6ca36f and 054eabf311 removed the explicit 1..1 min/max constraints from ValueSet.publisher and ValueSet.description in source/valueset/structuredefinition-profile-shareablevalueset.xml, and commit b0172dd266 removed the publisher steward alias. Later commit 93fadfaa2a for FHIR-31395 rebuilt the profile family: ShareableValueSet.publisher remained non-required and mustSupport, while ShareableValueSet.description was explicitly 1..1 and mustSupport.

Additional context:
The VSD-P Confluence resource-element list records the same publisher concern and points to FHIR-29943/FHIR-29944. Later Published Vocab decisions FHIR-34171 and FHIR-35989 resolved the scope concern by treating scope as further clarification of ValueSet.description and updating description guidance, rather than replacing description with an optional scope extension. FHIR-31395 then updated ShareableValueSet as part of the four ValueSet profile family. FHIR-37959 later made the Applied R6 decision to remove the Shareable/Publishable/Computable/Executable profiles from core and maintain them in CRMI with unchanged canonical URIs; commit 3958dd1e7c deleted source/valueset/structuredefinition-profile-shareablevalueset.xml and removed the ValueSet core IG references.

AutoFHIR reconciliation:
This is an empty audit commit. Current core source no longer contains or builds the ShareableValueSet StructureDefinition, source/fhir.ini has no active ShareableValueSet profile entry, and the active shareable pattern has publisher as 0..1 with SHOULD-level guidance rather than a required cardinality. Changing the current core source would either reintroduce a profile that later decisions removed or disturb the broader shareable pattern outside the approved FHIR-29943 scope.

Recommendation:
Keep this audit commit as-is for core. Do not re-add or edit ShareableValueSet in the FHIR core checkout for FHIR-29943; any future profile-definition change should be made in the CRMI source that now owns the migrated profiles, or through a new tracker that explicitly reverses FHIR-37959.
