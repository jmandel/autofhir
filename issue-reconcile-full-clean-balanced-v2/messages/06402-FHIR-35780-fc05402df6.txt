FHIR-35780: Audit version-specific StructureDefinition guidance

Issue request:
FHIR-35780 is a Published/Not Persuasive with Modification FHIR-I change request against the FHIR-core compatibility/versioning page. The reporter asked to replace the version-specific StructureDefinition profile example, such as `http://hl7.org/fhir/3.0/StructureDefinition/Patient`, with a normal canonical URL plus version, because `canonical` references normally point to the StructureDefinition.url. The accepted resolution explicitly chose not to remove the version-specific canonicals and instead to make version-specific packages available so software can resolve them.

Initial application:
The issue was applied by git commit e93b4f3ecd8b2bfbfaf8996b19d5926cde408578, which added explanatory text to source/versioning.html after the version-specific profile table. That text says the `http://hl7.org/fhir/{ver}/StructureDefinition/{type}` pattern is not the normal URL for the relevant StructureDefinitions and points implementers to the version-specific core package. The version-specific profile mechanism itself predates this issue and traces to FHIR-16165.

Additional context:
The 2022-01 implementers Zulip thread shows the reporter raising the canonical-versus-version-specific-URL concern before opening FHIR-35779 and FHIR-35780. FHIR-I minutes for 2022-04-18 record the final FHIR-35780 decision: it was too late to change Transformer behavior, version-specific URLs are used by version-specific publishing packages, and the motion was Not Persuasive with Modification 8-0-0. Later FHIR-41622 corrected the package-id example on the same source line from `hl7.fhir.r{x}.core{x}` / `hl7.fhir.r4.core4` to `hl7.fhir.r{x}.core` / `hl7.fhir.r4.core`; that related issue already has a separate combined-branch audit commit. The versioning page is current build-scope source via publish.ini and source/hierarchy.xml.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current source/versioning.html already preserves the version-specific profile example, warns that the version-specific URL pattern is not the normal StructureDefinition URL, and points to the corrected version-specific core package id. Replacing the example with `http://hl7.org/fhir/StructureDefinition/Patient|4.0.1` would conflict with the recorded FHIR-I resolution rather than complete it.

Recommendation:
Keep this no-change audit as-is. Revisit only if FHIR-I opens a new tracker to supersede the version-specific URL guidance or to clarify package resolver behavior beyond the FHIR-35780 resolution.
