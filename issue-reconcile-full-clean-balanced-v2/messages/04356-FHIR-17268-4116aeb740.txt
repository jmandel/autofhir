FHIR-17268: Audit CodeableConcept userSelected guidance

Issue request:
FHIR-17268 was a Published/Persuasive with Modification STU3 change request for the CodeableConcept datatype narrative. It reported conflicting guidance between the repeatable coding structure and text that said only one coding may be userSelected, and the accepted resolution was to say that in all but a few cases only one coding is user-selected, but multiple true codings mean the user explicitly chose multiple codes.

Initial application:
The Jira comment records svn 14755. Git-svn commit 20081d755a98d5cd0925f03ccaa19d7dd1fbd5d8, "GF#17268 - note about user selected", changed source/datatypes.html from "One of the codings" to "One or more of the codings" and added the accepted explanatory note about rare multiple user-selected codings.

Additional context:
source/fhir.ini keeps CodeableConcept and the datatypes page in current build scope through the active [types] CodeableConcept entry and [type-pages] *=datatypes mapping. Related Published issue FHIR-17681 later clarified the same note to say coding.userSelected = true, and FHIR-38981 later appended guidance about retaining the chosen text in CodeableConcept.text. Those later decisions are consistent with the FHIR-17268 semantics. Zulip and Confluence searches found no FHIR-17268-specific discussion or conflicting community evidence.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active CodeableConcept narrative already says one or more codings may be flagged as user selected, adds that only one is typical, and explains that multiple user-selected codings mean the user explicitly chose multiple codes.

Recommendation:
Keep this no-change audit commit as-is. No core FHIR follow-up is needed for FHIR-17268 unless a future Vocabulary or methodology decision reopens CodeableConcept userSelected semantics.
