FHIR-7301: Audit Patient birthDate birthTime guidance

Issue request:
FHIR-7301 was Published with a Not Persuasive with Modification resolution for the DSTU1 Patient ballot request to change Patient.birthDate from date to dateTime. The accepted direction kept birthDate as date to avoid timezone-related identity problems and asked for notes pointing implementers to the standard birth-time extension.

Initial application:
The Jira-tagged historical commit c68d460586 added FHIR-7301 birth-time guidance to the then-authoritative Patient spreadsheet comment, alongside a Patient introduction update. Earlier supporting work added the standard birthTime extension, and later source refactors moved the current Patient definition into source/patient/structuredefinition-Patient.xml.

Additional context:
Patient is an active resource in source/fhir.ini, and the current Patient.birthDate element remains type date with a comment that explicitly directs time-of-birth use cases to the standard patient-birthTime extension. The patient-birthTime StructureDefinition has moved out of core into the FHIR Extension Pack, where it is active, has dateTime value type, and is scoped to Patient.birthDate plus Person, RelatedPerson, and Practitioner birthDate. Duplicate and related Jira issues FHIR-7605, FHIR-8507, FHIR-7478, and the earlier FHIR-3731 all support the same design rather than requiring a current core edit.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current core source already conveys the required rule for Patient.birthDate, and the extension definition is maintained in the Extension Pack rather than as a core StructureDefinition source file.

Recommendation:
Keep this no-change audit as-is. No FHIR core follow-up is needed for FHIR-7301 unless PA later decides to change the birth-time extension itself in the Extension Pack.
