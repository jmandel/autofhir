FHIR-35853: Audit ElementDefinition type binding

Issue request:
FHIR-35853 was Published/Persuasive for R5 and asked FHIR-I to define FHIRPathTypes terminology, create a grouper value set covering FHIRPath types plus FHIR-defined types, and bind ElementDefinition.type.code extensibly to that broader value set because core StructureDefinitions use codes such as http://hl7.org/fhirpath/System.String.

Initial application:
The Jira comments identify R4B commit ba0e0d91eb and core commits 680ce0a481 and a920f92752 as the original application. In core, 680ce0a481 added the ElementDefinition.type.code binding machinery and a920f92752 added the FHIRPath code system and value-set artifacts. A later type-system cleanup in e7b4eba11e renamed/refined the grouper to ElementDefinitionTypes and changed it to include ValueSet/fhir-types.

Additional context:
The originating Zulip thread records the same rationale: FHIRPath primitive codes were being used in core ElementDefinition.type.code values, and Bryn Rhodes suggested defining FHIRPathTypes plus a grouper binding. FHIR-I minutes for 2022-01-31 record the persuasive motion for FHIR-35853 at 18-0-0. The current fhir.ini keeps ElementDefinition active, current source/datatypes/elementdefinition.xml binds ElementDefinition.type.code to ElementDefinitionTypes, source/terminologies/bindings.xml declares that binding extensible and maps it to valueset-elementdefinition-types, and the current value set includes both CodeSystem/fhirpath-types and ValueSet/fhir-types.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already implements the requested FHIRPathTypes code system/value set and the broader extensible ElementDefinition.type.code binding. A coverage check found the current source uses System.Boolean, System.Date, System.DateTime, System.Decimal, System.Integer, System.Long, System.String, and System.Time under http://hl7.org/fhirpath/System.*, and all eight are present in source/terminologies/codesystem-fhirpath-types.xml.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed for FHIR-35853 unless a future issue changes the set of FHIRPath System.* codes used in core StructureDefinitions or changes the type-system terminology model again.
