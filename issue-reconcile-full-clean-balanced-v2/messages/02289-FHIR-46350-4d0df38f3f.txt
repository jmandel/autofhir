FHIR-46350: Align required binding warning text

Issue request:
FHIR-46350 was Applied as Not Persuasive with Modification for R6. It asked FHIR-I to make common/preferred plus required/maximum binding patterns consistent by deprecating the `maximum` additional binding purpose as equivalent to `required`, adding a best-practice ElementDefinition warning with the text "Required bindings SHOULD appear as the primary binding" when a context-free required additional binding is used while the primary binding is not required, and documenting how multiple required bindings can apply to CodeableConcept or CodeableReference.

Initial application:
The relevant source was initially changed in git commit 8e42147627f, whose message included `+ FHIR-46350`. That commit deprecated the `maximum` additional binding purpose in the Additional Binding Purpose code system, added the ElementDefinition best-practice predicate, and added terminology-page prose for multiple required bindings. The current source therefore already had the substantive rule, but the best-practice diagnostic did not use the approved Jira text and its explanatory note said "but the max value set", which was both a typo and inconsistent with deprecating `maximum` in favor of `required`.

Additional context:
`source/fhir.ini` maps ElementDefinition to the active datatype pages, so `source/datatypes/elementdefinition.xml` is build-scoped source for this warning. The terminology page and Additional Binding Purpose code system already carry the other FHIR-46350 changes. FHIR-41000 was retracted as handled by FHIR-46350, while later issues FHIR-54589 and FHIR-55475 discuss broader terminology wording but are not Applied/Published source-edit decisions in this run's default scope.

AutoFHIR reconciliation:
This commit changes the ElementDefinition best-practice warning message to the exact approved text, "Required bindings SHOULD appear as the primary binding", and updates the directly associated author guidance to say the required value set belongs in the primary binding while other value sets can remain additional bindings. It intentionally does not broaden the terminology-page text because the FHIR-46350-required terminology note and `maximum` deprecation are already present and later unresolved or not-yet-applied issues own broader terminology revisions.

Recommendation:
Keep this commit as a narrow completion of the applied FHIR-46350 work. Revisit the terminology page only when FHIR-54589/FHIR-55475 or related Vocab/FHIR-I decisions are in scope for application.
