FHIR-19359: Audit extension modifier safety clarification

Issue request:
FHIR-19359 was a Published/Persuasive FHIR-core change request for the extensibility page. It asked FHIR-I to clarify the fifth Notes bullet that said unsafe-to-ignore extensions SHALL be represented as modifier extensions, because the linked clinical-safety Zulip discussion showed that generic safety impact was being confused with changing the meaning of existing elements. The accepted resolution was to append a sentence defining "Not safe" as causing information in other elements within the resource to be interpreted inconsistently with their base definitions and to point readers to the modifier-extension examples.

Initial application:
The issue was explicitly applied by git commit 67ee800fd2ddfec4ee1fbcc42d293789a7429077, which changed source/extensibility.html to add the requested "Not safe" sentence to the Notes bullet. Later editorial work corrected the original typo/link form, and current source/fhir.ini actively includes the extensibility page with extension=extensibility.

Additional context:
The motivating Zulip thread distinguishes generic patient-safety importance from modifier-extension semantics: Lloyd McKenzie explained that a modifier extension is about changing the meaning of other elements, not simply whether a decision-support system might want to know the added fact. FHIR-I minutes show the tracker was deferred to R5 on 2018-10-22 and then accepted on 2019-04-22 with a 7-0-0 motion to add wording clarifying "not safe". Later modifier-extension work, including FHIR-37903 and surrounding source edits, added guidance but did not reverse or conflict with this seed clarification.

AutoFHIR reconciliation:
This audit commit makes no source change. The active current source at source/extensibility.html retains the approved clarification: "'Not safe' means that the extension causes information in other elements within the resource to be interpreted in a way that is not consistent with their base definition," with an HTML link to the examples below. Nearby modifier-extension prose and conformance rules explain the processing implications, so adding more text would be redundant rather than corrective.

Recommendation:
Keep this no-change audit commit as-is. No FHIR-core follow-up is needed for FHIR-19359 unless FHIR-I later reopens the broader modifier-extension policy; FHIR-37903 was only background here and should remain a separate issue decision if it is ever reconciled.
