FHIR-19485: Audit Dosage doseAndRate type cardinality

Issue request:
FHIR-19485 was Published/Persuasive for the Pharmacy work group after identifying that mandatory Dosage.doseAndRate.type plus an example CodeableConcept binding was not semantically justified. The resolution was to change DoseAndRate.type cardinality to 0..1 with a default/meaning-if-missing value of "ordered"; the issue comments clarified this should be represented as meaning if missing, not an actual default.

Initial application:
The Jira comment links merge commit 7a787c5ab6b278c2af6d3644c38931486b7330f4, whose GF 19485 source commit 5262ee548c7b86f38e88093b6be05706be6b3d49 changed source/datatypes/dosage.xml for Dosage.doseAndRate.type from 1..1 to 0..1 and added "If the type is not populated, assume to be \"ordered\"." Later formatting and terminology commits preserved that rule.

Additional context:
source/fhir.ini lists Dosage as an active datatype under the dosage page machinery, Pharmacy work group ownership, normative status, and abbreviation mapping, so source/datatypes/dosage.xml is in current build scope. Later related Jira context did not reverse the seed: FHIR-34129 explicitly declined making the dose-rate-type binding required, and FHIR-40217 concerned the binding target rather than this cardinality/meaning-if-missing rule.
