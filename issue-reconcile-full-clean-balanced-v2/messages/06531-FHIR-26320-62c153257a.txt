FHIR-26320: Audit Specimen bodySite BodyStructure link

Issue request:
FHIR-26320 was a Published/Persuasive OO change request for R5. It asked for a way for a Specimen taken from a specific tumor, lesion, fetus, or similar entity to link to that specific BodyStructure, and the final resolution was to make Specimen.collection.bodySite a CodeableReference.

Initial application:
The issue was applied before this reconciliation. The Jira comments say it was added to the build with 24781f0, and that commit changed source/specimen/structuredefinition-Specimen.xml from CodeableConcept to CodeableReference with targetProfile BodyStructure while updating the primary specimen example to use CodeableReference.concept. A follow-up commit, 4a86eeac, adjusted the Specimen-bodysite search parameter from a token search on Specimen.collection.bodySite to a reference search on Specimen.collection.bodySite.reference.

Additional context:
Specimen is an active core resource in source/fhir.ini, so source/specimen/structuredefinition-Specimen.xml and source/specimen/bundle-Specimen-search-params.xml are current build inputs. The current source already has Specimen.collection.bodySite typed as CodeableReference targeting http://hl7.org/fhir/StructureDefinition/BodyStructure, with a comment explaining BodyStructure reference use cases, and the bodysite search parameter is reference-based. FHIR-33072 is the same Specimen bodySite CodeableReference change family and is already represented on the combined branch by 64aee052fe07ccad23fa13d1755e1bc61efec2cb. FHIR-53203 is later Applied OO body-structure alignment work and does not require a different result for this seed. FHIR-54843 is a later Resolved - change required issue that would rename Specimen.collection.bodySite to bodyStructure and change cardinality, but it is not Applied or Published and is outside this default applied/published reconciliation scope.

AutoFHIR reconciliation:
No source change was made. The current authoritative Specimen source already satisfies FHIR-26320 by allowing a coded body site or a reference to a BodyStructure instance through CodeableReference(BodyStructure), and applying the later FHIR-54843 rename/cardinality proposal here would overreach the seed issue.

Recommendation:
Keep this no-change audit commit as-is for FHIR-26320. Any future Specimen.collection.bodySite rename, search-parameter rename, binding-name change, comment update, or cardinality change should be handled under FHIR-54843 or an applied successor once that work is in scope.
