FHIR-5493: Audit ClinicalDocument.id mapping history

Issue request:
FHIR-5493 was a Published/Persuasive DSTU1 Structured Documents clarification for Composition. It asked to keep the CDA comparison that Composition.identifier corresponds to ClinicalDocument.setId and add a note that ClinicalDocument.id goes in the document Bundle identity, with Grahame's clarification that the relationship should be described as equivalent in function rather than literally identical.

Initial application:
The issue was applied in svn revision 4622, represented in this git history by commit 9728390581527fbfe248afbde3a47bac77d46b2f. That commit changed source/composition/composition-introduction.xml to add that Bundle.id was equivalent in function to ClinicalDocument.id, with a parenthetical warning that interconversion is a transform rather than identity.

Additional context:
Composition is active in source/fhir.ini, so source/composition/composition-introduction.xml feeds the current build. Later Structured Documents work superseded the original Bundle.id target: FHIR-30766 and SDWG May 2021 minutes changed the mapping to Bundle.identifier, and that later decision is already represented on the combined branch by FHIR-30766 commit be198de99cc9e7b5182659c7a8e205f827ec51b9. The current source still says Composition.identifier matches ClinicalDocument.setId and now says Bundle.identifier is equivalent to ClinicalDocument.id, consistent with the current documents page's Bundle.identifier/Composition.identifier distinction.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because the FHIR-5493 clarification was historically applied, and the current source is correct after the later FHIR-30766 correction from Bundle.id to Bundle.identifier. Reintroducing Bundle.id would conflict with the later approved mapping and current document identity guidance.

Recommendation:
Keep this audit commit as-is. No FHIR-core follow-up is needed for FHIR-5493; any future CDA-to-FHIR identifier changes should be handled under later Structured Documents mapping issues rather than by reverting this historical clarification.
