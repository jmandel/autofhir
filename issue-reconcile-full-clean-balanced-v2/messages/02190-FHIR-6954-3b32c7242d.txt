FHIR-6954: Audit DocumentManifest author clarification

Issue request:
FHIR-6954 was a Published/Persuasive with Modification DSTU1 Structured Documents issue asking whether DocumentManifest.author identified the authors of documents in the set or the author of the DocumentManifest. The accepted resolution was to clarify that the element identifies who authored the manifest.

Initial application:
The issue was applied in historical source by git-svn commit effcc548e4472b26ada0e12101f498c3ca0d3d89, whose message references #6954 and SVN revision 6193. That commit changed source/documentmanifest/documentmanifest-spreadsheet.xml so DocumentManifest.author said "Who and/or what authored the manifest" and identified who was responsible for creating the manifest and adding documents to it. Current checked-in historical release artifacts for R2/R3 say "manifest" and R4/R4B say "DocumentManifest," so the old ambiguity is not present in those retained history files.

Additional context:
DocumentManifest is not an active current-build resource: source/fhir.ini comments out documentmanifest in the active resource work-group list, records the resource as dropped, and maps DocumentManifest to List. The current history page also lists DocumentManifest as removed after R4B with List as the replacement. The current List source uses List.source as the author-like field and defines it as the entity responsible for deciding list contents, not as the author of referenced documents. Jira searches found no other DocumentManifest.author issue besides FHIR-6954, and Zulip/Confluence searches found no conflicting community evidence.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The historical issue was already applied, the retained historical artifacts reflect the clarified manifest semantics, and there is no active DocumentManifest.author source in the current build to edit.

Recommendation:
Keep this empty audit commit as-is for FHIR-6954. No core source follow-up is needed for this issue unless a separate tracker asks to clean up unrelated removed-resource references or examples.
