FHIR-22679: Audit URI search escaping guidance

Issue request:
FHIR-22679 was a Published FHIR-I change request resolved as Persuasive with Modification. It asked the search page to remove the confusing claim that uri search matching was "escape" sensitive and to correct the ValueSet URL escaping example so percent-encoding was treated as transparent transport encoding rather than a distinct comparison dimension.

Initial application:
The issue appears to have been applied in source commit 82418ca8e77ceefa65a24270427f91e0a7d64f6e, "Verification of changes from PR 1799 (Yunwei): FHIR-35812 FHIR-32018 FHIR-22679." That commit edited source/search.html to change the uri type sentence from "case, accent, and escape" sensitive to "case and accent sensitive" and to correct the percent-encoded ValueSet example. No prior Issue-Reconcile-Key commit for FHIR-22679 was present on the combined branch.

Additional context:
FHIR-I minutes from 2019-10-28 record the same rationale: HTTP processors often unescape URLs, making escape-sensitive comparisons impractical or impossible. Current source/search.html has since been reorganized by later search-page work, but it still preserves the FHIR-22679 semantics: URL encoding is described as transparent, the same-meaning examples use percent-encoding variants, and uri matching no longer mentions escape sensitivity. The later same-section FHIR-42834 escaped-comma correction is already represented on the combined branch and does not require a duplicate decision here.
