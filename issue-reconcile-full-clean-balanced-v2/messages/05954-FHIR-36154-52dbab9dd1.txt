FHIR-36154: Audit Device specialization replacement

Issue request:
FHIR-36154 was Published/Persuasive with Modification for R5 by Orders & Observations. It asked to re-introduce Device.specialization, separate from Device.property, with systemType 1..1 CodeableConcept, version 0..1 string, and category 0..1 code using communication, performance, and measurement examples.

Initial application:
The issue was applied in 2022. Git history shows 3e31d8d adding Device.specialization to source/device/structuredefinition-Device.xml, and the Jira comments point to f7c69bc and 74b7215 adjusting specialization.category through the PR #1827/#1883 application path. Related interim published issues then refined the temporary specialization/property wording before the later rename.

Additional context:
Later Published issues FHIR-39084 and FHIR-39242 explicitly changed .specialization to .conformsTo because standards conformance, compliance certification, and regulatory/legal compliance are broader than IEEE 11073 specialization. Current source/fhir.ini has Device as an active resource, and current source/device/structuredefinition-Device.xml contains Device.conformsTo with category, specification, and version subelements instead of Device.specialization. Confluence minutes confirm both the original FHIR-36154 vote and the later FHIR-39084/FHIR-39242 review path; Zulip searches found no conflicting FHIR-36154 discussion.

AutoFHIR reconciliation:
No source change was made. Re-introducing Device.specialization would reverse the later published rename and create a duplicate or conflicting model. The current build represents the FHIR-36154 capability through Device.conformsTo.

Recommendation:
Keep this audit commit as-is. Any future examples or vocabulary expansion should be handled through the later Device.conformsTo/value-set issue family, not by restoring Device.specialization.
