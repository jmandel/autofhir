FHIR-14155: Audit ResearchStudy status value set

Issue request:
FHIR-14155 was Published/Persuasive for STU3 and asked to change the ResearchStudyStatus value set to the vetted SME list for ResearchStudy. The Jira resolution says the change was made and published in the December 2017 FHIR ballot.

Initial application:
The initial application is visible in three explicit GF#14155 commits. Commit 31ac7a2 changed the ResearchStudy spreadsheet short value list and example from the old draft/in-progress/suspended/stopped/completed/entered-in-error status set to the vetted study-status codes. Commits 0979e21 and 30b741 updated source/status-codes.xml so ResearchStudy.status mapped to the vetted status codes and corrected administratively-completed spelling.

Additional context:
Later ResearchStudy modeling changed the meaning of ResearchStudy.status to the resource publication status and moved study conduct/progress status to ResearchStudy.progressStatus.state. Later final decisions added ClinicalTrials.gov codes to ResearchStudyStatus (FHIR-32314), corrected the completed definition and binding strength (FHIR-33096), moved the Research Study Status terminology toward THO (UP-758), and changed ResearchStudy.progressStatus.state to Preferred binding to the THO value set (FHIR-53697). FHIR-50644 explicitly confirms that ResearchStudy.status is not study status in the current model. The current checked-in SVG still shows an older generated-looking Example-strength label, but the authoritative StructureDefinition and release-note source now carry the Preferred THO binding.

AutoFHIR reconciliation:
No source change was made. ResearchStudy is active in source/fhir.ini, the current ResearchStudy CodeSystem/ValueSet source contains the vetted study-status code family plus later approved additions, and the active ResearchStudy StructureDefinition binds ResearchStudy.progressStatus.state to http://terminology.hl7.org/ValueSet/research-study-status with Preferred strength while ResearchStudy.status correctly uses publication-status.

Recommendation:
Keep this empty audit commit. Reopening FHIR-14155 would be inappropriate because the STU3 vetted-list change was applied and later final decisions intentionally refined where and how the terminology is used. Any future cleanup of generated diagrams or remaining core/THO terminology duplication should be handled under the later THO/binding issues, not this STU3 value-set issue.
