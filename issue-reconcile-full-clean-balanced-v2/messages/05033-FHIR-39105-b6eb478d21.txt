FHIR-39105: Audit List.subject cardinality

Issue request:
FHIR-39105 was a Published R5 FHIR-core/List change request resolved Persuasive with Modification. It asked to align List.subject cardinality with Composition for lists of document bundles and the approved resolution was to change List.subject from 0..1 to 0..* and add a usage note warning about access-control and compartment challenges for Lists with multiple subjects.

Initial application:
The change appears to have been applied by commit a74c2edee9528723ae58535e3502101f87643347, which changed List.subject short/definition wording to allow subject(s), changed max from 1 to *, and added the requested multiple-subject security/access-control comment.

Additional context:
FHIR-39104 is the directly related earlier List.subject issue that relaxed the target type to Reference(Any), enabling the ePI/MedicinalProductDefinition use case referenced in FHIR-39105 comments. FHIR Infrastructure WGM 202301 minutes record that a list-for extension alternative was discussed but would not necessarily work, and that the WG accepted changing List.subject cardinality to 0..* with a 17-0-12 motion. Direct Zulip searches for FHIR-39105 found no additional discussion that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current combined source has List active in source/fhir.ini and source/list/structuredefinition-List.xml already defines List.subject with max="*" and the requested usage note about multiple subjects affecting access control, security considerations, and patient compartments.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed for FHIR-39105; the current authoritative source matches the Jira resolution and meeting decision.
