FHIR-22685: Audit Questionnaire code search parameters

Issue request:
FHIR-22685 was a Published/Persuasive FHIR-I change request for Questionnaire. The request observed that the historical Questionnaire `code` search parameter searched only Questionnaire.item.code and should also allow searching Questionnaire.code. The final resolution was to drop the ambiguous `code` search parameter and add `questionnaire-code` for Questionnaire.code, `item-code` for Questionnaire.item.code, and `combo-code` for both.

Initial application:
The issue appears to have been applied by commit 50e453775ef3cf19e1ee233ba60ff2f5963d61c0, which the Jira comment records and which split source/questionnaire/bundle-Questionnaire-search-params.xml from the old Questionnaire-code/code definition into the three named search parameters. Later search-parameter refactors changed surrounding metadata and FHIRPath style, but preserved the split search parameters.

Additional context:
Questionnaire is active in source/fhir.ini, so source/questionnaire/bundle-Questionnaire-search-params.xml is in current build scope. The current source contains `questionnaire-code`, `item-code`, and `combo-code` with expressions covering Questionnaire.code, Questionnaire.repeat(item).code, and their union, and no legacy Questionnaire `code` SearchParameter remains in that authoritative bundle. A Zulip Questionnaire thread shortly after the vote references J#22685 and describes the same planned replacement; direct Confluence searches found no conflicting FHIR-22685 record.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change because the current build source already implements the Jira resolution.

Recommendation:
Keep this no-change audit as-is. No follow-up is needed in core FHIR unless a later work-group decision changes the search-parameter naming or semantics.
