FHIR-38649: Audit version-specific URL extension scope

Issue request:
FHIR-38649 was a Published FHIR-core change request, resolved Persuasive with Modification, asking that the resolve-as-version-specific extension no longer be limited to Reference and be usable on uri and url while leaving narrative, markdown, href, and img scenarios alone unless a practical use case required a more complex solution.

Initial application:
The FHIR core checkout no longer carries the StructureDefinition source for this extension; core commit dd468d4f17 removed extension definitions from the R5 source before the issue was applied. The implementation landed in the FHIR Extension Pack as commit 6c6f51f32afbe1a4f1071d615c89f88b6620b3da, which added uri and url contexts to StructureDefinition-resolve-as-version-specific.xml.

Additional context:
The current Extension Pack source still lists Reference, uri, and url as context expressions for the extension, with a later QA commit adding the version-specific-use metadata for the url context. The current core HTTP page links to the extension through the external extensions location and does not contain an in-build core StructureDefinition that would override those contexts. FHIR-I minutes and the originating Zulip thread match the Jira resolution: uri/url were the bounded fix, while narrative/markdown URLs were intentionally not solved.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The authoritative extension definition is outside this FHIR core checkout and already reflects the requested scope; editing core prose would only duplicate the extension context and risk drifting from the external source of truth.

Recommendation:
Keep this audit commit as-is. If future reviewers want clearer transaction-page wording, handle that as a separate editorial tracker coordinated with the Extension Pack, not as a missing application of FHIR-38649.
