FHIR-6190: Audit duplicate Clinical Document profiles removal

Issue request:
FHIR-6190 was a Published FHIR-core / Structured Documents change request from DSTU1, resolved Persuasive with Modification. It reported two Clinical Document profile pages, cda-clinicaldocument.html and composition-clindoc-clinicaldocument.html, and asked to clarify or rename them. The accepted resolution was to remove the first CDA profile set and bring it back in DSTU R2.

Initial application:
No current git commit explicitly mentions FHIR-6190, and the Jira comments say the CDA profiles were already removed. Source history shows the legacy CDA profile was introduced in 04a8cb53d1407614ab9991f0d3fc3858349ae4a6 and the separate Composition ClinicalDocument profile was later introduced by c252f365176314ea286fc98033c0cc8e128b7b7c for FHIR-3775. In the current source, the legacy CDA profile remains only as source/profiles/cda.profile.xml with its source/fhir.ini profile hook commented out, so it is not a current build input.

Additional context:
Later SDWG decisions changed the profile landscape. FHIR-13528 resolved the profile naming question by keeping ClinicalDocument as the name rather than CDA on FHIR, and the combined reconciliation branch already contains a FHIR-13528 source fix. FHIR-34407 then removed the Composition ClinicalDocument profile entirely because its meaningful versionNumber contribution had been replaced by Composition.version, and the combined branch already contains a FHIR-34407 audit commit. The current active Composition source now points to CDA-aware guidance and CDA comparison text rather than a retired ClinicalDocument profile page.
