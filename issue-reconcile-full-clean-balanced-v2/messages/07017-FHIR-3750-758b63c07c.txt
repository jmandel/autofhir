FHIR-3750: Align id primitive definition

Issue request:
FHIR-3750 was Published/Persuasive and asked to change the allowable values for resource logical ids: permit upper- and lower-case ASCII letters, use a 64-character limit, treat ids as case-sensitive, require lowercase UUIDs, and apply the regex [A-Za-z0-9\-\.]{1,64}.

Initial application:
The later id narrative was applied in git history, especially 79e6d1ae12 updating source/datatypes.html to 64 characters, upper/lower-case ASCII, case-sensitive ids, lowercase UUIDs, and ISO 18232 context. A later spreadsheet edit in 06e4d2acc9 raised source/datatypes/primitives.xml to 64 characters but left the primitive definition saying ids are case-insensitive, so generated primitive/profile surfaces could still conflict with the accepted FHIR-3750 rule.

Additional context:
FHIR-3088 originally introduced a lower-case, 36-character, case-insensitive id definition, but FHIR-3750 superseded those constraints. FHIR-3768 added the ISO 18232 distinction, FHIR-5140/FHIR-5141 confirmed the 64-character resource/datatype alignment, and FHIR-13320 later made _id searching explicitly case-sensitive. Current source/datatypes.html and source/search.html already follow the later case-sensitive interpretation.

AutoFHIR reconciliation:
Updated the active primitive datatype spreadsheet row for id in source/datatypes/primitives.xml so it now states upper- or lower-case ASCII letters, the existing 64-character limit, case-sensitive ids, and lowercase UUIDs. The existing regex [A-Za-z0-9\-\.]{1,64} was already correct and was left unchanged.

Recommendation:
Keep this source fix. It aligns the generated primitive/profile definition with the current narrative and later published decisions without reapplying the superseded FHIR-3088 lowercase/case-insensitive rule. FHIR-53669's pending punctuation cleanup on the narrative page remains outside this reconciliation because it is Triaged rather than Applied/Published.
