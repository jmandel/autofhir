FHIR-36046: Fix Appointment recurrence element metadata

Issue request:
FHIR-36046 was Published/Persuasive for R5 and asked Patient Administration to define how recurring appointments should be represented. The accepted resolution was to apply the Confluence Recurring Appointments proposed updates to Appointment and AppointmentResponse, including a recurrence template on the originating Appointment, occurrence links back to that Appointment, series linkage via previousAppointment, response handling for all versus individual occurrences, and timezone guidance.

Initial application:
The issue was applied through HL7/fhir PR #2009, merged as f0f613f7a8b1ecb5c292c2e18d803cd705f37ed2 after implementation commits 50fc60f0bfe81f07d90ad1abc3eb9e142ca92349 and e04c65906d113a401a30cfaef385fa8f644a8949. Those commits added Appointment recurrence narrative, previousAppointment, originatingAppointment, recurrenceId, occurrenceChanged, recurrenceTemplate and its supporting value sets, plus AppointmentResponse recurring, occurrenceDate, and recurrenceId.

Additional context:
Appointment and AppointmentResponse are active current-build resources in source/fhir.ini. The current source already contains the approved recurrence model and later FHIR-47677 search parameters were handled separately on the combined branch. Later R6 issues FHIR-54400 and FHIR-55285 are Resolved - change required but not Applied/Published in this run scope; they identify future guidance/datatype work and do not supersede the seed application.

AutoFHIR reconciliation:
This commit keeps the applied model and fixes three narrow source defects left in the Appointment StructureDefinition: the recurrenceTemplate element id now matches its path without a trailing space, the recurrenceType binding description no longer says it is an IANA timezone binding, and the monthly dayOfWeek comment now points to the actual nthWeekOfMonth element path.

Recommendation:
Keep this source fix. It corrects conformance-source metadata and a broken local reference without changing the approved recurrence design; leave FHIR-54400 and FHIR-55285 for their own application when they move into the Applied/Published workflow scope.
