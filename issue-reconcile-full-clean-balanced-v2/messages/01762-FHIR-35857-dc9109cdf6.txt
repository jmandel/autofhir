FHIR-35857: Audit external CodeSystem authoritativeSource addition

Issue request:
FHIR-35857 was a Published FHIR-core Vocabulary change request to add a CodeSystem authoritativeSource extension because some terminology canonical URLs, such as CDCREC, do not resolve to the current human-readable terminology source of truth. The final Persuasive resolution requested an authoritativeSource extension with uri value and also noted that the publisher should use that URL for browsing when populated.

Initial application:
No current FHIR-core source file defines codesystem-authoritativeSource. Historically, core commit 9500b398d1 added source/codesystem/structuredefinition-extension-codesystem-authoritativeSource.xml with context CodeSystem, uri value type, and the requested source-of-truth definition, and commit 86f05f16e6 attempted to add it to the CodeSystem implementation guide extension list. The original implementation used max 1 rather than the Jira resolution's max 0..*, but it matched the singular source-of-truth rationale recorded in Jira and minutes.

Additional context:
Core commit dd468d4f17 later removed CodeSystem and ValueSet extension definitions from the R5 core source as part of moving extensions out of core. Current source/fhir.ini has active extension/profile spreadsheet entries but no active codesystem-authoritativeSource profile entry, current source/codesystem/implementationguide-CodeSystem-core.xml no longer lists CodeSystem-specific extension resources, and core source search finds only the OID registry entry for the canonical URL. The Extension Pack now owns the StructureDefinition: input/definitions/CodeSystem/StructureDefinition-codesystem-authoritativeSource.xml defines the CodeSystem extension with the same canonical URL and uri value type, but it is retired/deprecated. Later final decisions FHIR-40730, FHIR-56275, and FHIR-56401 deprecated the CodeSystem-specific extension and point users to the more general artifact-authoritativeSource extension, also 0..1 uri.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR-core source change. The seed's requested artifact was applied historically and is now maintained outside the core checkout; the only remaining core trace is the OID registration, which should remain. Reintroducing or changing a deprecated, externally owned extension in core would conflict with the current repository split and later replacement guidance.

Recommendation:
Keep this audit commit as-is for core reconciliation. No immediate follow-up is recommended in core. If future work revisits authoritative-source semantics or publisher linking behavior, it should start from the FHIR Extension Pack artifact-authoritativeSource/codesystem-authoritativeSource definitions and the publisher/tooling repository that consumes them, not by restoring the retired extension definition to FHIR core.
