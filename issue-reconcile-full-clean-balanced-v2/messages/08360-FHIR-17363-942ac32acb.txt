FHIR-17363: Audit terminology business version display

Issue request:
FHIR-17363 was Published/Persuasive for STU3. It asked that terminology pages display the business version for CodeSystem resources, the business version for the ValueSet definition being shown, and clarify which code system version was used to generate a displayed expansion.

Initial application:
The issue was applied in git-svn revision 13944, commit 6259891d42d22190d1908d9ba8f5058b0c6582dd, which added Version rows/tokens to code system and value set templates and corresponding renderer/PageProcessor support. The current source has since been refactored from the older source/template-* locations into tools/templates and tools/tx templates, but the business-version display behavior was retained.

Additional context:
source/hierarchy.xml still places the Code Systems and Value Sets registry pages in the active Terminology section and declares generated pages for code systems and value sets. Current core templates display <%csver%> on CodeSystem pages and <%vsver%> on ValueSet pages, and ValueSet pages still include the generated expansion block. Current build.fhir.org examples render _Version_: 6.0.0-ballot4 for both AdministrativeGender CodeSystem and ValueSet pages, and the ValueSet expansion states it was generated based on codesystem AdministrativeGender v6.0.0-ballot4. Related FHIR-13820 addressed $expand input parameters and intentionally did not add a code-system-version input parameter, so it does not require an additional source change for this display-focused issue.

AutoFHIR reconciliation:
No source change was made. The current source and rendered CI output already satisfy the requested business-version display and expansion-source-version clarification for the relevant current terminology pages.

Recommendation:
Keep this no-change audit commit. Revisit only if a future renderer/template refactor drops the Version rows or stops rendering expansion provenance with the code system version.
