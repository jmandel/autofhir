FHIR-6214: Audit CarePlan activity product choice

Issue request:
FHIR-6214 was a Published FHIR-core CarePlan change request from DSTU1, resolved Persuasive with Modification. It asked that CarePlan.activity.detail.product support diet and nutritional supplements by changing detail.product from Reference(Medication | Substance) to CodeableConcept | Reference(Medication | Substance).

Initial application:
The Jira comment records SVN #6766. Git commit d6c4981fa8fe7d58cc3e1cc393aa8cc0b6a83c54 is the corresponding git-svn build@6766 commit, and its CarePlan spreadsheet patch changes CarePlan.activity.detail.product to CarePlan.activity.detail.product[x] with type CodeableConcept | Reference(Medication|Substance).

Additional context:
CarePlan is an active resource in source/fhir.ini. Current source has the successor element CarePlan.activity.plannedActivityDetail.product[x], with CodeableConcept plus Reference targets Medication and Substance. Later Published issue FHIR-26064 renamed CarePlan.activity.detail to CarePlan.activity.plannedActivityDetail for R5, so the current path is the renamed descendant of the DSTU1 detail.product element. Current plannedActivityReference also includes NutritionOrder, but that is later adjacent functionality and does not change the FHIR-6214 datatype check.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The active CarePlan StructureDefinition already preserves the requested CodeableConcept choice and the Medication/Substance references on the current plannedActivityDetail.product[x] element.

Recommendation:
Keep this no-change audit commit as-is. No core source follow-up is needed for FHIR-6214 unless the work group separately wants to revisit the example medication-codes binding or broader nutrition modeling, which would be outside this published datatype request.
