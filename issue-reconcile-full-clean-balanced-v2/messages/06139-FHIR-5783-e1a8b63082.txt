FHIR-5783: Audit version-specific value set references

Issue request:
FHIR-5783 was a Published FHIR-core vocab change request, resolved Persuasive with Modification, asking that logical references to value sets be able to identify a specific ValueSet.version in binding/reference locations and terminology operations. The recorded resolution was to append a version to the value set URL and, when no version is supplied and multiple matches exist, use the latest known value set.

Initial application:
The issue was applied in the historical SVN import as git commit 06210c87a1 / svn r4668, which added the Value Set References section to source/terminologies.html with version-specific logical reference guidance and the latest-version fallback. No current source edit was needed to repeat that application.

Additional context:
Later published issues changed the representation rather than reversing the FHIR-5783 rule: FHIR-10576 replaced the original ?version syntax with canonical url|version syntax for conformance-resource references, FHIR-16055 changed ElementDefinition.binding.valueSet from valueSet[x] to canonical(ValueSet), and FHIR-18673 clarified that canonical references resolve by URL plus optional version suffix. Current source reflects those later decisions and the relevant files are in build scope through source/fhir.ini resource/type entries.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/terminologies.html still contains the FHIR-5783 rule, updated to say that a value set version is appended to the canonical URL with a vertical bar, shows the corresponding terminology-server search with the version parameter, and says that a versionless reference should use the latest version when multiple value sets match. Current ElementDefinition, ValueSet, OperationDefinition, Questionnaire, and ConceptMap source locations use canonical(ValueSet) or otherwise state that value set references may be version-specific.

Recommendation:
Keep this no-change audit commit. The seed issue is satisfied in current build-scope source after later canonical-reference decisions; follow-up, if any, should be handled under separate terminology-page cleanup issues rather than re-opening FHIR-5783.
