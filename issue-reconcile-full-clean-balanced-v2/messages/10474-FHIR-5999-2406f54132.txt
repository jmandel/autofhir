FHIR-5999: Audit choice type-slicing support

Issue request:
FHIR-5999 was a Published FHIR-core profiles change request, resolved Persuasive with Modification, asking for a spreadsheet/tooling way to place separate bindings on different datatypes of a choice element such as a CodeableConcept branch and a Reference branch of an [x] element. The recorded resolution says type slicing for non-repeating choice elements is now supported by the tools, so the original problem is no longer an issue.

Initial application:
No current git commit explicitly mentions FHIR-5999. The matching historical application appears to be legacy commit 320e08d887, which clarified that slicing can be used on elements that do not repeat but have a choice of datatypes and updated ElementDefinition.slicing to allow slicing for resources with a choice of types. That application is still present in the current source through ElementDefinition, profiling, and terminology guidance.

Additional context:
FHIR-28619 later rejected broad slicing of arbitrary non-repeating elements and confirmed the intended boundary: non-repeating slicing is presently supported only by type for polymorphic elements. Current terminology text says that a binding on a choice element applies to all meaningful bindable datatypes, and that a binding for only one choice type should be handled by slicing the element by type and applying the binding to that slice. A 2026 ServiceRequest discussion and FHIR-54847 show a separate resource-definition/spreadsheet limitation for core resource definitions, not a contradiction of the profile support requested by FHIR-5999.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active build already carries the needed semantics: ElementDefinition permits slicing for choice types, the profiling page documents type discriminators for polymorphic elements and gives Observation.value[x] as a type-slicing example with vocabulary bindings, and active Observation profile sources demonstrate a choice-type slice with a binding on Observation.value[x]:valueQuantity.

Recommendation:
Keep this audit commit as-is. Do not add redundant prose for FHIR-5999; follow-up work, if any, belongs to later issue-specific resource-definition or rendering/tooling tickets such as FHIR-54847 or the IG Publisher issue referenced by FHIR-44344.
