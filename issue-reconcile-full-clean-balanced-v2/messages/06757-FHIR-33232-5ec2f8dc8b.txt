FHIR-33232: Audit FHIRPatch choice-element names

Issue request:
FHIR-33232 was a Published/Persuasive with Modification FHIR-core clarification for the FHIRPath Patch page. The reporter asked whether a FHIRPath Patch part for a choice element such as Specimen.processing.time[x] should use the unsuffixed FHIRPath name "time" or the concrete element name "timeDateTime"; FHIR-I resolved that the first approach is correct and that the spec and test cases should show it.

Initial application:
The issue was applied by git commit ccc2f1bc607deb41208efc01f710a42d5f44c68e, which added the Choice Elements section to source/fhirpatch.html and changed the test-case reference to the fhir-test-cases repository. The FHIRPath Patch page is in current build scope through source/hierarchy.xml and is linked from the HTTP PATCH guidance in source/http.html.

Additional context:
The linked Zulip thread records the same conclusion: use name="time" rather than name="timeDateTime", consistent with FHIRPath polymorphism. FHIR-I minutes for 2021-11-01 record the 17-0-1 Persuasive with Modification vote and Grahame Grieve's statement that the spec would clarify that using "time" is correct. A Jira neighborhood search found no later FHIRPatch choice-value issue that reverses this rule. FHIR-33256 is a separate same-page extension-example issue and is already represented on the combined branch, but it does not change the FHIR-33232 choice-element rule.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current combined-branch source/fhirpatch.html already has a Choice Elements section explaining that the FHIRPath name in the parameter name omits the data type suffix, and its example uses "name": "time" with a valueDateTime. The checked page has no choice-example part named "timeDateTime", and the example JSON parses.

Recommendation:
Keep this audit commit as-is. No core FHIR source follow-up is needed for FHIR-33232; any additional test-case maintenance would belong in the external fhir-test-cases repository rather than this source checkout.
