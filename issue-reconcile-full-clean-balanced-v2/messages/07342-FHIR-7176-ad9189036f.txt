FHIR-7176: Audit NutritionOrder exclusion guidance

Issue request:
FHIR-7176 was Published with a Persuasive with Modification resolution for the DSTU1 NutritionRequest/NutritionOrder artifact. The issue asked how to handle confusion between food intolerance, preference, and excludeFoodModifier, and the final decision kept the clinical distinction while requiring text that allergy or intolerance information should not need to be repeated in excludeFoodModifier.

Initial application:
Commit 2308bb93df0b674c1cb64370db6a2540ba2d47b6 applied the Jira-tagged change to the then-authoritative NutritionOrder spreadsheet source by adding the requested non-duplication sentence to NutritionOrder.excludeFoodModifier. Later source conversion preserved that guidance in source/nutritionorder/structuredefinition-NutritionOrder.xml.

Additional context:
source/fhir.ini lists nutritionorder=NutritionOrder and assigns it to the OO work group, so source/nutritionorder/structuredefinition-NutritionOrder.xml is in current build scope. FHIR-46700 later refined the same excludeFoodModifier descriptions for R6 and current combined-branch history includes commit 1132d5ac97f871f8d4f4f3fe740b9317e3083483, which completed the short description without reversing the FHIR-7176 guidance. The adjacent FHIR-7175 issue is the same May 2015 preference/intolerance family and points back to FHIR-7176, but this audit only decides the seed issue.

AutoFHIR reconciliation:
No source change was made. The current NutritionOrder.excludeFoodModifier definition already says it should not be necessary to repeat allergy or intolerance information captured in AllergyIntolerance, and the current short text says the element complements but does not duplicate AllergyIntolerance.

Recommendation:
Keep this no-change audit commit. The current active source satisfies the published resolution and later related work has made the wording clearer, so another source edit would be redundant and risk creating parallel guidance drift.
