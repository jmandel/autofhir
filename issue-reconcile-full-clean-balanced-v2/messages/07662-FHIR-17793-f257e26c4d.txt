FHIR-17793: Audit Observation deviceCode extension ownership

Issue request:
FHIR-17793 was Published with a Persuasive with Modification resolution for STU3. It rejected changing Observation.device into a choice of reference or code because Observation.device identifies a device instance, and instead requested a core extension like observation-specimenCode that can carry a CodeableConcept device type when the device kind is not already implicit in Observation.code, using the same example binding as Device.type.

Initial application:
The Jira comment cites dfe20c1, but that commit only corrected an Observation.focusCode link in source/observation/observation-spreadsheet.xml and did not add observation-deviceCode. Historical core source nevertheless did contain source/observation/structuredefinition-extension-observation-deviceCode.xml and listed StructureDefinition/observation-deviceCode in the Observation core implementation guide, with CodeableConcept value[x] and an example binding to http://hl7.org/fhir/ValueSet/device-type. Later core source refactoring removed Observation extension definitions from this checkout.

Additional context:
The current FHIR core build has Observation active in source/fhir.ini and keeps Observation.device as a Reference to Device or DeviceMetric, which is consistent with the Jira decision not to make Observation.device a device-code choice. The extension definition now lives in the FHIR Extension Pack, where StructureDefinition-observation-deviceCode is active, Trial Use, scoped to Observation, and still binds value[x] CodeableConcept to the Device type value set. Later FHIR-extensions issues FHIR-44332, FHIR-43391, and FHIR-46838 reconsidered whether the extension should be removed or deprecated; the final applied state un-deprecated it and restored active/trial-use status with a note about alternate Observation.device/Device.type representation.

AutoFHIR reconciliation:
This is an empty external-repo audit commit. No FHIR core source change is needed because the current core artifact remains semantically correct and the authoritative extension source is outside this checkout in the FHIR Extension Pack.

Recommendation:
Keep this audit commit as-is for FHIR core. Do not re-add observation-deviceCode to core source; any future changes to the extension's status, description, or binding should be made in the FHIR Extension Pack and reconciled against FHIR-44332, FHIR-43391, and FHIR-46838.
