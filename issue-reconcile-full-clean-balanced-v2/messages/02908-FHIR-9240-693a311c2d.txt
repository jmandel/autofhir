FHIR-9240: Audit Signature Type external codes

Issue request:
FHIR-9240 was a Published/Persuasive Security change request for DSTU2. It asked that the Signature Type value set stop using FHIR-defined codes for a Coding element and instead draw from a non-FHIR code system, with the resolution clarifying that the vocabulary should be ASTM.

Initial application:
The Jira comment says the fix was applied in SVN revision 7952. The matching git-svn commit 2cc1452ce1d1f421f880a81f501c3b1ad2765064 changed source/datatypes/valueset-signature-type.xml from the FHIR value-set URL to urn:iso-astm:E1762-95:2013, directly applying the requested external ASTM system.

Additional context:
The current build still has Signature as an active normative datatype and actively registers the ASTM and ETSI signature type code systems in source/fhir.ini. FHIR-20807 later added ETSI signature commitment types to the same value set for R5, but it preserved the ASTM include and continued the same non-FHIR-code-system approach. Current source makes the ASTM provenance explicit through the ASTM CodeSystem URL, publisher, copyright, and value-set compose include.

AutoFHIR reconciliation:
This audit commit makes no source change. The current source already satisfies FHIR-9240: Signature.type remains bound to valueset-signature-type, and that value set composes codes from urn:iso-astm:E1762-95:2013 rather than a FHIR code system.

Recommendation:
Keep this audit as-is. No core source follow-up is needed for FHIR-9240 unless the Security work group later changes the Signature Type terminology policy; any such later change should be handled under its own tracker.
