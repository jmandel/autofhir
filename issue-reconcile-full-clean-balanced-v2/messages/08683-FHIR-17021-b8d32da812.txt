FHIR-17021: Audit Binary definition reconciliation

Issue request:
FHIR-17021 was Published with a Persuasive with Modification resolution for the STU3 Binary resource. It requested changing the Binary resource definition from "A binary resource can contain any content, whether text, image, pdf, zip archive, etc." to "A resource that represents the data of a single raw artifact as digital content accessible in its native format. A Binary resource can contain any content, whether text, image, pdf, zip archive, etc."

Initial application:
The issue was applied in git-svn revision 14340, represented in this repository by commit 5a98eb6b3cb2717ab0b1a36cafd65a5dc5e2a7a9, which changed the Binary spreadsheet definition cell to the resolved wording. The current post-refactor source carries that same resolved definition in source/binary/structuredefinition-Binary.xml for both the StructureDefinition description and the root Binary element definition.

Additional context:
Binary is an active current-build resource in source/fhir.ini. The Scope and Usage introduction still includes the old "can contain any content" sentence as supporting explanatory prose, but it is not the canonical resource definition and it is not inconsistent with the resolved definition already present in the StructureDefinition source. Bounded Jira, Zulip, and Confluence checks found no later conflicting decision; FHIR-I minutes for 2018-07-09 list FHIR-17021 as Persuasive with Modification.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. Repeating the full formal definition in the Scope and Usage paragraph would be redundant and outside the applied issue's actual definition-cell change; the authoritative current source already conveys the requested definition.
