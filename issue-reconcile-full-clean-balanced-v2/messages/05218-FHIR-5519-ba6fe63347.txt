FHIR-5519: Audit Immunization and MedicationAdministration alignment

Issue request:
FHIR-5519 is a Published/Persuasive FHIR-core change request from DSTU1 asking to implement changes required to align the Immunization and MedicationAdministration resources. The Jira resolution says the work was done in the September 2014 and January 2015 WGMs.

Initial application:
No historical commit that explicitly mentions FHIR-5519 was found, which is consistent with this very early tracker era. The implementation trail appears to be commit 5350fdb47507aa316ec0da7985d650a4889455f6, "Harmonize Immunization and MedicationAdministration", made on 2015-01-20 immediately after the Jira was created and matching the January 2015 WGM resolution note. That commit changed the then-authoritative spreadsheet source for MedicationAdministration, including making practitioner and prescription optional and adding reasonGiven support, as part of aligning MedicationAdministration with Immunization-era semantics.

Additional context:
Both Immunization and MedicationAdministration are active current-build resources in source/fhir.ini. The current source has since been refactored and further harmonized through later final issues, especially FHIR-11091, which is already represented on the combined branch and audited the later medication/immunization not-given and reason-name harmonization. Current StructureDefinition source maps both resources to the workflow Event pattern and uses statusReason, reason, occurrence[x], performer, and compatibility rename aliases rather than the old DSTU1/DSTU2 wasNotGiven/reasonGiven surface. A stale Immunization example copy remains under source/medicationadministration, but current source search found no build-scope reference to that file; the active Immunization example list points to the corrected source/immunization/immunization-example-refused.xml.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The seed issue's requested alignment was applied historically, current build-scoped resource definitions already reflect the aligned/current model after later published decisions, and editing the unreferenced stale copy would not be a current-spec fix.
