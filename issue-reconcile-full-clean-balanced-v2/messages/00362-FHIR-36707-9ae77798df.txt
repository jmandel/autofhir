FHIR-36707: Audit external Consent category definitions

Issue request:
FHIR-36707 is an Applied/Persuasive FHIR-core Consent change request from CBCC asking that Consent Category Code definitions remove embedded references, notes, and comments, with small wording updates for advance directive and health care directive definitions. The Jira resolution says the FHIR issue was pending on UTG ticket UP-413.

Initial application:
No Jira-tagged FHIR core commit for FHIR-36707 or UP-413 was found. The relevant Consent category definitions were no longer maintained in core before this issue was filed: commit 5c0494aacfd0b8bd52bc72c587aa89d0a64246f8 removed source/consent/codesystem-consent-category.xml as part of removing UTG content from the core build. The current active Consent ValueSet source only composes the external THO CodeSystem at http://terminology.hl7.org/CodeSystem/consentcategorycodes.

Additional context:
UP-413 is Proposal Implemented and identifies the changed objects as http://hl7.org/fhir/CodeSystem/consent-category and http://terminology.hl7.org/CodeSystem/consentcategorycodes. Terminology Infrastructure minutes recorded review of UP-413, and the THO 5.4.0 release notes list UP-413 as published. A current THO fetch shows the requested references were removed from the concept definitions, but the health care directive definition still contains the typo "thoe" that was called out in a 2024 UP-413 comment for later technical correction.

AutoFHIR reconciliation:
This is an empty external-repo audit commit. No FHIR core source was changed because the requested code definitions are maintained in THO/UTG, not in the current FHIR core checkout. Editing the core ValueSet would not correct the authoritative CodeSystem definitions and would risk duplicating external terminology content.

Recommendation:
Keep this audit commit as-is for FHIR core. If the remaining "thoe" typo is still present in the live THO CodeSystem, pursue that as a THO/UTG technical correction rather than a FHIR core source change.
