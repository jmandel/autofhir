FHIR-5186: Audit Person link target rename

Issue request:
FHIR-5186 was a Published/Persuasive DSTU1 Patient Administration change request for Person and RelatedPerson. The ballot comment objected that Person should not use the element name "other" because Other was itself a FHIR resource name, and the approved resolution was to change the property to "Target" while noting that Patient link "Other" might be considered separately for consistency.

Initial application:
The issue appears to have been applied in git commit dc2afae9f6e31b220e90a9d948c46e3743363e68, a grouped Person ballot reconciliation commit whose message explicitly included tracker 5186. That commit changed the Person spreadsheet from Person.link.other to Person.link.target, added Person example links using target, and added Person search parameters based on Person.link.target. Later source refactors migrated the spreadsheet-defined content into the current StructureDefinition and search-parameter bundle.

Additional context:
Person, Patient, and RelatedPerson are active current-build resources in source/fhir.ini. Current source/person/structuredefinition-Person.xml defines Person.link.target as the reference element, with Patient, Practitioner, RelatedPerson, and Person target profiles; current Person examples and Person search parameters also use target, and focused source searches found no remaining Person.link.other or Person <other> element. Patient.link.other still exists, but the seed issue's final approved action was the Person rename; the Patient note was only to consider a separate consistency change, and current Patient wording describes the other Patient or RelatedPerson rather than the retired Other resource name. Focused Zulip and Confluence searches found no relevant conflicting discussion or minutes for FHIR-5186.

AutoFHIR reconciliation:
This audit commit makes no source change. The current authoritative Person source already implements the approved rename from other to target across the element definition, examples, and search parameters, and the separate Patient.link.other element should not be renamed based only on FHIR-5186's non-final consistency note.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-5186; any future Patient.link.other rename would be a separate, breaking Patient Administration work-group decision rather than an unapplied part of this Person issue.
