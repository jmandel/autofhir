FHIR-19511: Audit Patient Care workflow changes

Issue request:
Published / Persuasive with Modification Patient Care issue requesting two workflow alignments for Patient Care resources: rename context to encounter as 0..1 Reference(Encounter) and add workflow EpisodeOfCare extension support for AdverseEvent, CarePlan, CareTeam, ClinicalImpression, Communication, CommunicationRequest, Condition, and Procedure; then rename/redefine Procedure.asserter to Procedure.reported[x], add CarePlan.activity.detail.reported[x], and exempt the remaining resources from the reported[x] pattern.

Initial application:
The encounter/EpisodeOfCare portion was pre-applied by 9e6a11d5a0bd, which changed the affected Patient Care resource spreadsheets and the workflow extension spreadsheet. The reported[x] portion was applied by 218ec67c42, which added CarePlan.activity.detail.reported[x] and changed Procedure.asserter to Procedure.reported[x].

Additional context:
Current fhir.ini keeps CarePlan, CareTeam, Condition, Communication, CommunicationRequest, Procedure, and AdverseEvent active resources; ClinicalImpression source remains present but is not listed as an active resource in current fhir.ini. Later published issues deliberately changed parts of the original application: FHIR-23029 removed CareTeam.encounter and CareTeam's workflow-episodeOfCare extension context, FHIR-25397 refined AdverseEvent.encounter wording, FHIR-26064 renamed CarePlan.activity.detail to plannedActivityDetail, FHIR-39101 removed CarePlan.activity.plannedActivityDetail and its children, and FHIR-26292 broadened the workflow-episodeOfCare extension now maintained in the Extension Pack. Community and Confluence searches found the 2018 workflow/pre-application discussion and PC minutes but no conflicting direction.

AutoFHIR reconciliation:
This audit makes no source change. The current active source already carries the surviving FHIR-19511 semantics: the active Patient Care resources that still have encounter use 0..1 Reference(Encounter), Procedure has reported[x] with the requested boolean/reference shape and no Procedure.asserter, Condition remains exempt with asserter, CareTeam has no encounter/context after FHIR-23029, and CarePlan has no active activity.detail/plannedActivityDetail reported[x] after FHIR-39101. The workflow-episodeOfCare extension is no longer a core source file; the Extension Pack definition includes AdverseEvent, CarePlan, ClinicalImpression, Communication, CommunicationRequest, Condition, and Procedure contexts and intentionally omits CareTeam.

Recommendation:
Keep this no-change audit. Reintroducing CareTeam.encounter, CareTeam workflow-episodeOfCare support, or CarePlan activity detail reporting would contradict later published Patient Care decisions. Any future work should be filed as a new Patient Care tracker, and Extension Pack changes should be handled in the Extension Pack repository rather than this core checkout.
