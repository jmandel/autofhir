FHIR-8605: Audit boolean datatype guidance

Issue request:
FHIR-8605 was a Published/Persuasive DSTU1 FHIR-core datatype issue asking that the Data Types page explain that boolean-like Observation values could be represented with valueCodeableConcept using the HL7 v2 Yes/No table, because Observation did not then have valueBoolean.

Initial application:
The Jira comments identify svn revision 6604. The corresponding git-svn commit fb66d5178323d942348b8b591562a2d8da7a0b91 added the datatype-page note linking HL7 v2 Table 0136 and Observation value[x], and added the Observation anchor needed by that link.

Additional context:
The active build includes the datatypes page through the type-page mapping and Observation through source/fhir.ini. Current source still has the datatype note at source/datatypes.html:420. Current Observation source also now lists valueBoolean for Observation.value[x] and the notes page still discusses boolean-like values using valueBoolean or valueCodeableConcept with v2 Yes/No codes. Related later work, especially FHIR-10275, changed the old assumption by adding boolean to Observation.value[x], so removing or expanding the old explanatory note would not improve current implementer guidance.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source already contains the requested datatype-page explanation and the later Observation model is more permissive than the original DSTU1 context.

Recommendation:
Keep this no-change audit commit as-is. Do not add redundant prose to the Data Types page unless a future work-group decision reopens the Observation boolean/coded-value guidance.
