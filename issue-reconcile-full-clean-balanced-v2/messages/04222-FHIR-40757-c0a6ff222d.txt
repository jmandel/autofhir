FHIR-40757: Audit mixed-version mandatory field guidance

Issue request:
FHIR-40757 was Applied as Persuasive with Modification for R6. It asked how an R4 instance can satisfy mandatory SampledData.period when using an R5 backport extension such as SampledData.offsets that makes period obsolete. The accepted resolution says data-absent-reason "not-applicable" can satisfy the minimum cardinality and asks for general guidance in versions.html under "Managing Change during the development process".

Initial application:
The first visible application, git 7e5f4f3cf5, inserted the requested paragraph into source/versions.html but left the Jira placeholder form [data-absent-reason]. The current source comes from git aec3a16f60, which applied the same guidance with a real link to the data-absent-reason extension and scoped the wording to trial-use versions. That commit is already in the current source and on the combined branch.

Additional context:
The Zulip thread linked from the Jira records the original SampledData.offsets/R4 period question and the idea that data-absent-reason could be used. FHIR-I minutes from 2023-06-12 record the work group decision that data-absent-reason/not-applicable can indicate SampledData.period is not used and satisfies the R4 mandatory requirement, with general mixed-version guidance to be added to the spec.

AutoFHIR reconciliation:
This commit intentionally makes no source change. source/versions.html is the active Version Management Policy page and already contains the accepted paragraph in the "Managing Change during the development process" section, including the linked data-absent-reason extension, value "not-applicable", and the SHOULD-level warning to check for a value rather than only element presence.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed in FHIR core for FHIR-40757 unless the work group later decides to revise the broader mixed-version conversion guidance.
