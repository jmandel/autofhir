FHIR-13751: Audit claim type terminology application

Issue request:
FHIR-13751 was a Published/Persuasive STU3 Financial Management change request asking whether ExplanationOfBenefit.type's Claim Type terminology should stop saying "Example" and stop using the example-looking ex-claimtype URI after the binding had changed from required to extensible. The accepted resolution says Claim, ClaimResponse, and ExplanationOfBenefit should use Claim Type codes with extensible bindings, a non-example claim-type code system URL, and the description "Claim Type Codes".

Initial application:
The application is visible in git history. Commit 49ee52b963abadc71e75fff3c1f5e31e86d25d30 changed source/claim/valueset-claim-type.xml from "Example Claim Type Codes", sample/example copyright text, and http://hl7.org/fhir/ex-claimtype to "Claim Type Codes", HL7 copyright, and http://hl7.org/fhir/claim-type. Commit cff1ea3a296fa00d51eaed13763ffd518bbc7378 then changed the ExplanationOfBenefit examples from ex-claimtype to claim-type while applying Tracker #13751. Later commit b63ba456ef969b5e173fc94623f34884301e68cc moved the CodeSystem reference to the terminology.hl7.org URL now used by current FHIR terminology.

Additional context:
source/fhir.ini keeps Claim, ClaimResponse, and ExplanationOfBenefit in the active resource list, so their current StructureDefinition and ValueSet sources are authoritative. Current source/claim/valueset-claim-type.xml is titled "Claim Type Codes", has description "This value set includes Claim Type codes.", and composes from http://terminology.hl7.org/CodeSystem/claim-type. Current Claim.type, ClaimResponse.type, and ExplanationOfBenefit.type each have extensible bindings to http://hl7.org/fhir/ValueSet/claim-type. The only current source hits for ex-claimtype are inside an XML comment in an active Communication example and in ProcessRequest $submit-response text; ProcessRequest is commented out in fhir.ini, so neither hit changes the current built Claim/ClaimResponse/ExplanationOfBenefit conformance surface. FHIR-13614 is the predecessor mismatch report and is background for this follow-up.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope Claim Type terminology and the three affected resource bindings already convey the accepted FHIR-13751 decision, and editing only commented or out-of-build remnants would not be a current-spec correction.

Recommendation:
Keep this no-change audit commit as-is. No core FHIR follow-up is needed for FHIR-13751 unless a human wants a separate editorial cleanup of non-rendered comments or retired ProcessRequest material.
