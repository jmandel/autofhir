FHIR-37845: Audit ConceptMap profile migration

Issue request:
FHIR-37845 was a Published/Persuasive Vocab change request for R5 asking to define Shareable and Publishable ConceptMap profiles based on the shared Shareable and Publishable patterns.

Initial application:
The request was applied before this reconciliation. PR #2068 was merged as 0d4401be, with implementation commit 93fadfaa adding source/conceptmap/structuredefinition-profile-shareableconceptmap.xml and source/conceptmap/structuredefinition-profile-publishableconceptmap.xml and registering both in source/conceptmap/implementationguide-ConceptMap-core.xml. The checked-in R5 history bundle still contains StructureDefinition/shareableconceptmap and StructureDefinition/publishableconceptmap entries, confirming the R5 publication surface.

Additional context:
A later Applied/Persuasive issue, FHIR-37959, changed the current R6 direction: remove Shareable/Publishable/Computable/Executable profiles from core FHIR and maintain them in the Canonical Resource Management IG. Confluence minutes for the May 2025 joint Vocab/CDS/CQI session record the 16-0-0 decision that these profiles should remain in CRMI because they evolve more quickly and need the CRMI context. Commit 3958dd1e removed the ConceptMap profile registrations and their migration-note introduction pages from core. Current source/conceptmap/implementationguide-ConceptMap-core.xml has an empty definition section and current source has no shareableconceptmap or publishableconceptmap StructureDefinition source files; only OID history remains.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding the ConceptMap profiles to core would reverse the later FHIR-37959 R6 decision rather than completing FHIR-37845.

Recommendation:
Keep this audit as-is for FHIR-37845. Do not reintroduce the core ConceptMap profile source unless the work group revisits FHIR-37959 or the CRMI ownership decision. Any remaining concern about profile hosting or core-to-CRMI references should be handled under FHIR-37959 or the CRMI/THO publication work, not this R5 application issue.
