FHIR-5785: Audit filter-operator is-a semantics

Issue request:
FHIR-5785 was a Published/Persuasive with Modification DSTU1 Vocabulary change request for ValueSet.compose.include.filter.op. It originally proposed renaming the is-a operator to a descendant-style name, but the accepted resolution kept is-a and changed its definition to state that it includes all concept ids with a transitive is-a relationship to the supplied concept, including the supplied concept itself.

Initial application:
The Jira comments record svn revision 4663. In the git mirror, revision 4663 maps to commit 2f3aa5a7808ad7c4cc958c0c3903cfe347bef687, whose subject and visible ValueSet diff concern FHIR-5795 rather than the filter-operator text. The first visible git diff found for the FHIR-5785 wording is commit 29e0f369d9ecc6206cbf5fa26140addc947202a2, which changed the then-authoritative source/valueset/valueset-spreadsheet.xml is-a definition from the circular relationship wording to the transitive is-a wording including the concept itself.

Additional context:
Later Published/Persuasive FHIR-12065 clarified the same is-a definition parenthetical, and later Published/Persuasive FHIR-16321 refined the filter-operator parentheticals to the current descendant/self wording. Both related issues are already represented on the combined branch, so this commit does not duplicate them. Later source refactoring moved the built filter-operator content from spreadsheet-era sources into source/valueset/codesystem-filter-operator.xml, and ValueSet remains active in source/fhir.ini with ValueSet.compose.include.filter.op bound to http://hl7.org/fhir/ValueSet/filter-operator.

AutoFHIR reconciliation:

The related source/codesystem/codesystem-notes.xml uses the same semantics. This matches the accepted FHIR-5785 resolution after later approved wording refinements.

Recommendation:
Keep this audit commit as-is. No FHIR-core source edit is needed for FHIR-5785; renaming is-a would contradict the accepted resolution and later compatibility decisions, while changing the current descendant/self wording back to the older exact phrase would undo later approved clarifications.
