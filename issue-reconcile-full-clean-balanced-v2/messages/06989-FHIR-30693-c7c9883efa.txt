FHIR-30693: Audit ImplementationGuide generation invariant

Issue request:
FHIR-30693 is a Published/Persuasive FHIR-core ImplementationGuide change request for R5. It asked to add an invariant that when ImplementationGuide.definition.page.generation is generated, ImplementationGuide.definition.page.source[x] is not allowed.

Initial application:
The Jira snapshot records Lloyd McKenzie's application note "Git master 1fbaee7964". Commit 1fbaee7964c114b5586a1cf28405bbb77642ba8e applied FHIR-30693 together with FHIR-24649 by adding ImplementationGuide.definition.page.source[x], changing page name handling, and adding the ig-3 invariant controlling source[x]. The first expression used the wrong element name, and commit 4590480e3217b3b115c3d9bcc1068a120dfa3f87 later corrected it from generated='generated' to generation='generated'.

Additional context:
FHIR-24649 is the same change family because it introduced source[x], the element constrained by FHIR-30693. FHIR Infrastructure minutes show FHIR-30693 accepted as Persuasive and later included in the TSC-delayed block vote. A Zulip issue-key search found no direct FHIR-30693 discussion; a later IG creation thread quotes the current ig-3 rule in use and does not reveal a conflicting decision.

AutoFHIR reconciliation:
No source change was made. source/fhir.ini actively includes implementationguide=ImplementationGuide, and source/implementationguide/structuredefinition-ImplementationGuide.xml currently defines ig-3 on ImplementationGuide.definition.page with expression generation='generated' implies source.empty(); both source[x] and generation carry condition ig-3.

Recommendation:
Keep this no-change audit commit as-is. The current build source already implements the requested invariant, and no follow-up core source work is indicated for FHIR-30693.
