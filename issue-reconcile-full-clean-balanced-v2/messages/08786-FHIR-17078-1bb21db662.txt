FHIR-17078: Audit Bundle fullUrl wording cleanup

Issue request:
FHIR-17078 was a Published/Persuasive FHIR-I change request raised against STU3. It asked to change the Bundle bdl-7 human wording from "FullUrl must be unique in a bundle, or else entries with the same fullUrl must have different meta.versionId" to "Either fullUrl must be unique in a bundle or else entries with the same fullUrl must have different meta.versionId" to make the either/or relationship explicit and remove the unnecessary comma.

Initial application:
No explicit FHIR-17078 source commit was found. The Jira comment says the request had become redundant because the language had been removed, but git history shows the older bdl-7 sentence persisted through later source forms and was then refined by later Bundle issues. The current combined branch has since applied the later FHIR-31986 reconciliation that replaces the old sentence entirely.

Additional context:
Bundle is an active current-build resource in source/fhir.ini, and source/bundle/structuredefinition-Bundle.xml is the current authoritative Bundle StructureDefinition source. Later same-family decisions supersede the literal 2018 wording edit: FHIR-18284 handled history delete entries, FHIR-39476 handled missing meta.versionId behavior, and FHIR-31986 rewrote bdl-7 to describe entries with the same fullUrl where resource is present and to compare fullUrl plus meta.versionId. The current Bundle uniqueness narrative also states the rule directly: a given version of a resource appears once, while multiple versions of one resource may appear.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The current bdl-7 human text no longer contains the ambiguous comma-separated wording that FHIR-17078 targeted, and restoring the exact 2018 either/or phrasing would conflict with the later, more precise bdl-7 text already published on the combined branch.

Recommendation:
Keep this audit commit as-is. The current source is correct for FHIR-17078 when the later Bundle invariant decisions are considered; future changes to Bundle fullUrl/version uniqueness should be handled through a new work-group decision rather than by reapplying the obsolete 2018 sentence.
