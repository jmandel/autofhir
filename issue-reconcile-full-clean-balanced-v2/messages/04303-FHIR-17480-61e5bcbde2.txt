FHIR-17480: Clarify external code-system binding versions

Issue request:
FHIR-17480 was a Published/Persuasive with Modification FHIR-core Vocabulary change request to clarify required binding strength, code datatype bindings, and whether value set and code system versions can be left unspecified. The accepted January 2022 resolution replaced the required-binding text and explicitly distinguished code-system version requirements from value-set version requirements.

Initial application:
Commit 9500b398d1d850a06cd180c82ce330e4809a2b49 applied most of the voted R5 text to source/terminologies.html, including required binding strength for code elements, the requirement to version multiple-code-system or HL7-defined code-system inputs, and the requirement to version external value-set bindings. That application left the prior generic external-standard bullet in place where the voted resolution called for the explicit single-external-code-system rule.

Additional context:
source/terminologies.html is the active Using Codes in Resources terminology page and is linked from the terminology module and datatype guidance. Later published changes for FHIR-27144, FHIR-38962, and FHIR-39056 adjusted nearby required-binding wording, expansion wording, and the code-vs-Coding scope, but did not supersede the single-external-code-system version rule. The January 2022 Vocabulary WGM minutes confirm the FHIR-17480 motion and vote.

AutoFHIR reconciliation:
This commit replaces the residual old external-standard bullet with the voted clarification: when an element is bound to a single external code system such as MIME types, BCP47 language codes, or UCUM, the value set definition need not specify the code system version. The existing external value-set version requirement and later required-binding clarifications are preserved.

Recommendation:
Keep this commit as-is. It completes the narrow FHIR-17480 application without reopening later required-binding decisions or making broader terminology policy changes.
