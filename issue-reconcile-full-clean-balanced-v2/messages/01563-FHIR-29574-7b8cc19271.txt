FHIR-29574: Audit manufacturing-batch closure type location

Issue request:
FHIR-29574 was Published/Persuasive with Modification for R5. It asked to add a CodeableConcept closure-type attribute to Medication.batch for the kind of closures used for the container in which drug substances and finished dosage forms are stored. The accepted resolution was to create a core extension for this attribute.

Initial application:
The request was initially applied in core source by commit 52f3ef3d50, which added the medication manufacturing-batch extension spreadsheet rows for Medication.batch, including manufacturingBatch.container.closureType as a CodeableConcept. The generated StructureDefinition was present before commit dd468d4f17 and included the closureType slice with the Jira-requested definition. Commit dd468d4f17 then intentionally removed extension definitions from the R5 core source, including source/medication/structuredefinition-extension-medication-manufacturingBatch.xml and its Medication-core IG reference.

Additional context:
Current core source does not build this extension definition: searches find medication-manufacturingBatch only in source/oids.ini, while source/fhir.ini actively builds Medication as a resource and the current Medication structure uses Medication.instance after later FHIR-47622 work. The FHIR Extension Pack checkout now contains input/definitions/multiple/StructureDefinition-medication-manufacturingBatch.xml with the canonical URL, Pharmacy ownership, Medication.batch context, and the requested closureType CodeableConcept slice. The Extension Pack continuous build publishes the same extension and lists closureType in the summary. Pharmacy 2020-11-09 minutes confirm the block vote for FHIR-29574 and the plan to add a core extension rather than a core Medication element.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. Re-adding the extension definition to HL7/fhir would reverse the later source split that moved extension definitions to HL7/fhir-extensions. The current core checkout only needs to retain the canonical OID, and the substantive extension source is external to this repository.

Recommendation:
Keep this audit commit as an external-repo decision for core reconciliation. If further changes are needed for the manufacturing-batch extension, including any future context adjustment from Medication.batch to Medication.instance for R6-era Medication, handle them in HL7/fhir-extensions or with work-group review rather than in the core FHIR source checkout.
