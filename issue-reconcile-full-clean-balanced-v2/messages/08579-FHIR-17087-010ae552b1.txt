FHIR-17087: Clarify Bundle reference example

Issue request:
FHIR-17087 was a Published/Persuasive STU3 FHIR-I clarification for FHIR-core-Feed. It said the Bundle reference-resolution algorithm was unclear because the then-current wording referred to appending an id to a bundle base URL even though Bundles no longer had base URLs, and it asked to rewrite the algorithm plus develop an example bundle covering the variations.

Initial application:
No git commit explicitly mentioning FHIR-17087 was found. The Jira application comment cites svn revision 14417, which maps to git commit 8d324d06d652c7422b056ed4845d4959d5c83e43. That commit rewrote source/bundle/bundle-notes.xml to replace the old urn/baseUrl wording with the approved relative-to-absolute and absolute-reference flow, added the identifier and conditional-reference note from the resolution, and retained the example Bundle as source/bundle/bundle-references.xml.

Additional context:
Bundle is an active current-build resource in source/fhir.ini, and the current Bundle notes contain a later, clearer algorithm for URNs, absolute URLs, RESTful-base relative references, transaction conditional references, canonical references, and failure when no rule applies. Later same-family decisions matter: FHIR-18235 and FHIR-29271 have already been audited on the combined branch, and FHIR-29271's Jira, Confluence minutes, and Zulip review show that Reference.identifier resolution was intentionally removed from the Bundle algorithm. The current algorithm reflects that later decision, but the registered bundle-references example still said an identifier-based reference "resolves to first patient," which could mislead implementers into treating Reference.identifier matching as a Bundle resolution rule.

AutoFHIR reconciliation:
This commit leaves the approved algorithm text unchanged and fixes the stale example surface. It changes the registered example description to say the example covers reference forms and resolution paths, and it changes the identifier-based Reference comment to say the logical reference uses the first patient's business identifier but resolution is application-specific and not part of the Bundle reference-resolution algorithm.

Recommendation:
Keep this source fix. It preserves the FHIR-17087 example while aligning it with later final FHIR-I decisions; no separate FHIR-29271 reconciliation commit is published here because Issue-Reconcile-Key: FHIR-29271 is already present on the combined branch.
