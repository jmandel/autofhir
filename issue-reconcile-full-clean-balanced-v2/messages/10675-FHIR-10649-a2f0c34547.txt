FHIR-10649: Audit ElementDefinition name definition

Issue request:
FHIR-10649 was a Published/Persuasive FHIR-core ElementDefinition change request from DSTU2 asking to fix the short definition of ElementDefinition.name, which incorrectly said "Name for this particular element definition (reference target)". The Jira resolution was persuasive, and the application comment says the issue was already fixed.

Initial application:
No source commit explicitly names FHIR-10649, but the relevant correction appears in git commit c997080bc43c87c6a1c22e4ac6b06a2cb0cdcf40, imported from svn revision 10016 on 2016-10-18. That same commit renamed ElementDefinition.name to ElementDefinition.sliceName and changed the bad short definition to "Name for this particular element (in a set of slices)".

Additional context:
The same revision is the explicit application for FHIR-12181, the related Published/Persuasive issue that requested renaming ElementDefinition.name to sliceName to clarify that the element applies to slices. FHIR-12181 is already represented on the combined branch, so this commit does not duplicate it. In the current build, ElementDefinition is an active normative type, the authoritative spreadsheet defines ElementDefinition.sliceName with slice-specific wording, and source/fhir.ini retains ElementDefinition.name only as a backwards-compatibility map to ElementDefinition.sliceName.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because the incorrect ElementDefinition.name short definition is absent from the current source, the live element is now ElementDefinition.sliceName with the corrected slice-oriented definition, and the old name appears only in compatibility mapping.

Recommendation:
Keep this audit as-is. Further core changes for FHIR-10649 would be redundant unless a separate work-group decision reintroduces ElementDefinition.name or changes sliceName semantics.
