FHIR-36696: Audit BDP description text

Issue request:
FHIR-36696 was a Published OO change request with resolution Persuasive with Modification. It asked to replace BiologicallyDerivedProduct.collection.source content description text from "Who is product from" to "The patient or entity providing the product" and to replace the BiologicallyDerivedProduct.productCode detailed description with the approved codified-value wording for medical products of human origin.

Initial application:
The issue was applied before this reconciliation by commit d48dddc5a71994a6ea4f5fb5e6fe0cf84426d0bd in HL7/fhir#1858, later merged as 43912e2929. That commit changed the old productCode definition to the approved codified-value text and changed the old collection.source short display to "The patient or entity providing the product." The current combined reconciliation branch did not already contain an Issue-Reconcile-Key commit for FHIR-36696.

Additional context:
BiologicallyDerivedProduct is an active current-build resource in source/fhir.ini. The current productCode definition still matches the FHIR-36696 resolution. The old combined collection.source element no longer exists because later OO decisions refined and then split it: FHIR-37953 changed the source wording to distinguish a patient undergoing collection from an organization facilitating collection, and FHIR-51939 replaced collection.source with collection.sourcePatient and collection.sourceOrganization. Both later issues are already represented on the combined reconciliation branch, and their current split-element wording supersedes the older combined display text without losing the FHIR-36696 meaning that the product source is the patient or entity providing the product.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative source already contains the approved productCode definition, and the current sourcePatient/sourceOrganization elements carry forward the collection-source meaning through later, more specific work-group decisions. Reverting those split elements to the literal FHIR-36696 wording would overrun later applied issues rather than complete the seed.

Recommendation:
Keep this audit commit as-is. Any future desire to harmonize the split-element wording should be handled as a follow-up to FHIR-51939 or a new OO decision, not as a late FHIR-36696 fix.
