FHIR-13457: Audit Event not-done status application

Issue request:
FHIR-13457 was Published/Persuasive with Modification for STU3. It requested removing Event.notDone, adding a status code of "not-done" with a definition distinct from aborted/stopped activity, updating the state machine and invariants to use the status code, and moving/renaming the not-done reason element. The Jira comment records that the reason element was subsumed by GF#13907/FHIR-13907 into statusReason.

Initial application:
The Jira comment points to SVN#12374, imported as git commit 5064224bd079b7f4ef4023d3ead9111b57bd8bff. That commit removed Event.notDone and Event.notDoneReason from the Event spreadsheet, added Event.statusReason, and changed Event invariants from the removed boolean to status='not-done'. Follow-up commit c51d0794c04ae7d497f677da5309768774286d10 corrected the EventStatus value set/source row so not-done appeared as a status code.

Additional context:
The current build still includes the Event logical pattern and event-pattern extensions through source/fhir.ini. Current Event source defines Event.status with not-done, Event.statusReason for exception statuses including not-done, and a status-based invariant for reason when status is not-done. The current terminology uses on-hold/stopped rather than the older suspended/aborted names while preserving the requested distinction: not-done is before main activity, stopped is after some main activity. FHIR-13907 and FHIR-7754 are already represented on the combined branch, so this commit does not duplicate those related audits.

AutoFHIR reconciliation:
Made no source change. The active Event source no longer exposes Event.notDone/Event.notDoneReason and already carries the requested status/statusReason model, not-done status code, and status-based invariant.

Recommendation:
Keep this empty audit commit as-is. No follow-up source work is needed for FHIR-13457 unless a work group later chooses to revise Event pattern status semantics more broadly.
