FHIR-17062: Audit Bundle fullUrl id matching wording

Issue request:
FHIR-17062 was a Published/Persuasive STU3 FHIR-I change request for FHIR-core-Feed. It asked to improve the Bundle.entry.fullUrl comment because merely saying a RESTful-looking fullUrl must end with Resource.id was insufficient; the approved wording needed to distinguish URNs or other absolute URLs from RESTful server URLs and require the RESTful URL id portion to match the resource id.

Initial application:
The Jira records Grahame Grieve's "svn 13498" application comment. The original SVN change is not directly present in this Git history, but the first Git-traceable Bundle StructureDefinition source migration already contained the revised note that fullUrl may be a URN or an absolute URL that does not end with Resource.id, while preserving the older id-only RESTful URL sentence.

Additional context:
Bundle is an active resource in source/fhir.ini and its StructureDefinition is current build input. The closely related FHIR-15139 clarified that fullUrl is an endpoint URL, not a canonical URL, and that urn:uuid fullUrls do not need to match Resource.id. Later Applied/Persuasive FHIR-43101 refined the same Bundle.entry.fullUrl comment so a RESTful-looking fullUrl must match both the resource type and id; that later issue is already represented on the combined branch by its own FHIR-43101 reconciliation commit.

AutoFHIR reconciliation:
No source change was made. The current authoritative source/bundle/structuredefinition-Bundle.xml comment already says that fullUrl may be a URN or non-id-ending absolute URL, and that if it looks like a RESTful server URL, the URL portion corresponding to the resource type and id SHALL match the resource type and id of the resource. That fully covers FHIR-17062 after the later FHIR-43101 refinement.

Recommendation:
Keep this empty audit commit. Further edits for FHIR-17062 would either duplicate current normative source text or risk conflicting with the later type/id clarification; unrelated spelling or casing cleanups should remain with their own trackers.
