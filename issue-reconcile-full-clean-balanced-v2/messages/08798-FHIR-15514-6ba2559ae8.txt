FHIR-15514: Audit completion mode extension ownership

Issue request:
FHIR-15514 was a Published/Persuasive with Modification STU3 change request asking QuestionnaireResponse to support recording how the questionnaire was completed. The accepted resolution was to define a standard CodeableConcept extension with a binding to a value set of Electronic, Verbal, and Written v3 ParticipationMode concepts, and to include that extension optionally in the SDC IG.

Initial application:
The Jira comments identify SVN #14772 as the core application and later note SDC profile application at Git 18c1f08. In this repository, git-svn commit b8c5990ac5ad735ba1e8e836fd8a4c6fd3534a3e for build@14772 explicitly listed issue 15514 and added the QuestionnaireResponse completionMode extension row plus ValueSet-questionnaireresponse-mode with ELECTRONIC, VERBAL, and WRITTEN concepts. The generated R4/R4B history and the later R5 XML source rework carried that extension forward.

Additional context:
The current core build still includes QuestionnaireResponse as an active resource, but it no longer has active source for the completionMode extension or value set. Commit dd468d4f1799dd79819315b211588ef1cf4586e0 removed the QuestionnaireResponse extension/value set source as part of moving extensions out of R5 core source, while the FHIR Extension Pack now includes input/definitions/* and contains StructureDefinition-questionnaireresponse-completionMode plus ValueSet-questionnaireresponse-mode. Historical core and current Extension Pack definitions use a required binding even though the Jira resolution text said preferred; no related Jira, Zulip, or Confluence evidence found a later decision specifically about changing that binding strength. Zulip evidence does show SDC profile use of completionMode/signature slices in 2022, supporting that the SDC portion was external to core rather than a missing current core artifact.

AutoFHIR reconciliation:
This commit intentionally makes no core source change and records an external-repo decision. Re-adding the extension to core would be wrong because the authoritative current definition is in hl7.fhir.uv.extensions, not in this FHIR core checkout/build; the core checkout only retains OID registry entries for the extension and value set. If the binding strength needs to be reconciled to the Jira wording, that should be reviewed and changed in the Extension Pack and/or SDC sources, not in core.

Recommendation:
Keep this audit commit as-is for core. Do not re-add the extension to the core source. Open follow-up work in the Extension Pack or SDC IG only if the work group wants the current required binding changed to preferred or wants to revisit SDC profile usage.
