FHIR-6834: Audit retired enableWhen XML rendering

Issue request:
FHIR-6834 was a Published/Persuasive FHIR-core Technical Correction for the FHIR-core-profiles page. The 2015May SDC request said the XML representation for the last `value*` element in the `Only allow data when:` extension should have the entire element crossed out, not only its description; Jira's resolution says this was already fixed.

Initial application:
No git commit using the exact `FHIR-6834` key was found. The historical DSTU2 extension bundle shows the old `questionnaire-enableWhen` extension and its prohibited base `Extension.value[x]` element (`max=0`), which matches the non-substantive rendering issue Jira describes. Later SDC source history moved the same conditional-display concept out of that extension and into native Questionnaire `enableWhen` elements.

Additional context:
The current build-scope authority lists Questionnaire as an active resource. Current source has `Questionnaire.item.enableWhen` as a native BackboneElement with the short label `Only allow data when`; the retired `questionnaire-enableWhen` extension URL appears only in a DSTU2-to-DSTU3 conversion stylesheet and not as an active core or extension-pack definition. Related FHIR-8769 addressed the same retired extension's generated naming behavior.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current specification no longer builds the old `extension-questionnaire-enablewhen.xml` profile page whose XML table rendering was criticized, and the active Questionnaire source already represents the conditional-display feature without a crossed-out extension value element.

Recommendation:
Keep this no-change audit commit as-is. No current core source follow-up is needed; historical release artifacts can remain historical and should not be edited as current-spec fixes.
