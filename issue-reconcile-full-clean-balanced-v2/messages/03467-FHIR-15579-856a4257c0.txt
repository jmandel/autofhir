FHIR-15579: Audit CarePlan activity modifier status

Issue request:
FHIR-15579 was Resolved - No Change/Not Persuasive for STU3. It asked why CarePlan.activity.status was a modifier and proposed removing the modifier flag because the activity status value set did not have an entered-in-error code.

Initial application:
No independent source change was required for FHIR-15579. Its resolution says FHIR-15583 approved adding entered-in-error to the CarePlan.activity.detail.status value set, which made the status element a modifier. Git commit 722ed5c93f4bc9828e96f0f5b476bedc3486fb92 records the GF#15583 implementation, including the entered-in-error addition and modifier-reason updates.

Additional context:
The current CarePlan source is active in source/fhir.ini. The historical CarePlan.activity.detail.status element has since been refactored to CarePlan.activity.plannedActivityDetail.status, and it remains an isModifier element with an isModifierReason tied to entered-in-error. The CarePlan activity status CodeSystem includes entered-in-error and the ValueSet includes that CodeSystem.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source matches the FHIR-15579 no-change rationale: entered-in-error is available in CarePlan activity status, so retaining the modifier flag and reason is correct.

Recommendation:
Keep this audit commit as-is. No source follow-up is needed unless Patient Care later reopens the activity-status modifier decision.
