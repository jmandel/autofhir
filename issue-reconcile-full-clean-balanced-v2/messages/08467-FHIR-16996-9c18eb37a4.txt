FHIR-16996: Audit ElementDefinition LOINC mapping clarification

Issue request:
FHIR-16996 was Published/Persuasive with Modification for FHIR-core ElementDefinition after STU3. It objected that ElementDefinition.requirements was mapped to LOINC R/O/C even though the element records traceability/rationale, and asked why ElementDefinition LOINC mappings appeared inline rather than on the mappings page. The approved resolution was to make the mapping clearer and add a section or reference about the relationship between LOINC, ElementDefinition, and ObservationDefinition.

Initial application:
The Jira comment says the change was applied in svn revision 14327. In git history this is commit 1147638b97b47c53569b2b2f2905ad24568f89e5, which removed the misleading R/O/C LOINC mapping from ElementDefinition.requirements in source/datatypes/elementdefinition.xml and added introductory mapping-page guidance for ElementDefinition, including the LOINC relationship to observation definitions.

Additional context:
ElementDefinition is an active datatype and type page in source/fhir.ini, so source/datatypes/elementdefinition.xml and source/elementdefinition-mappings.html are current build inputs. Later same-family issue FHIR-20502 refined the LOINC terminology from code to field name and is already represented on the combined branch by commit ad43174a61952b63ba1e18541b6dab01829d7d22. Current source now labels the spreadsheet column and mapping-space metadata as LOINC Field Name, explains that the values are LOINC table field names rather than term codes, and leaves ElementDefinition.requirements without a LOINC field-name mapping. FHIR-I minutes for 2018-07-09 record FHIR-16996 in the approved block vote, and no conflicting Zulip or Confluence evidence was found.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already carries the approved FHIR-16996 semantics: the incorrect requirements-to-R/O/C mapping is gone, and the ElementDefinition mappings page explains the relationship among ElementDefinition, LOINC field names, and ObservationDefinition without duplicating guidance elsewhere.

Recommendation:
Keep this commit as-is. No further core source work is needed for FHIR-16996 unless the work group later wants a broader redesign of ElementDefinition mapping presentation; FHIR-20502 already handled the later field-name terminology correction.
