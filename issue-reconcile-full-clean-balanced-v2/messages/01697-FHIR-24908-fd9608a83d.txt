FHIR-24908: Audit DICOM terminology import

Issue request:
FHIR-24908 was a Published/Persuasive R5 technical correction asking FHIR core to stop duplicating DICOM-managed code systems and value sets in AuditEvent and ImagingStudy, and instead use the DICOM-published terminology available to the terminology server.

Initial application:
The issue was pre-applied in commit 26f1439636ec3a00a96ffe742b9f5cba1ac1a8ba, merged by af4f14dcdcd7dd3e7d3da15864963ab2a00e8010 as PR #951. That change replaced local AuditEvent and ImagingStudy DICOM value-set content with DICOM URI imports and deleted the hand-maintained local value-set files named in the Jira comment.

Additional context:
The original Zulip thread records that tx.fhir.org could load DICOM value sets directly from DICOM, that the DICOM value-set URLs were unfortunately HTML-shaped but usable, and that John Moehrke successfully pre-applied the core update. Security minutes tracked the issue as waiting on DICOM and then moving toward using DICOM terminology rather than self-crafted code systems. Current source/fhir.ini keeps AuditEvent and ImagingStudy in active build scope; the current successor XML binds AuditEvent values through value sets that import DICOM CIDs 400, 401, 403, 404, and 402, and ImagingStudy modality uses DICOM CID 33 directly. Later ImagingStudy decisions, including FHIR-17279 and the FHIR-47481 no-change ballot resolution, support preserving the current core-level DICOM binding choices rather than making stricter baseline bindings here. The only remaining reference to a removed old local value set is in source/genomicstudy/imagingstudy.svg, a generated-looking orphan outside fhir.ini resource scope, while the active ImagingStudy source has no such stale reference.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active FHIR core sources already implement the published FHIR-24908 decision, and editing the orphan SVG-only leftover would not be an authoritative current-spec fix.

Recommendation:
Keep this audit commit as-is. Do not reintroduce local DICOM vocabulary copies in core; any future stricter DICOM conformance should follow II/THO or IG-specific work rather than this Security R5 correction.
