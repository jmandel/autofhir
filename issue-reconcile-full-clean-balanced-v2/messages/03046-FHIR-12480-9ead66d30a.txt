FHIR-12480: Audit Provenance entity URL support

Issue request:
FHIR-12480 was a Published Security work group change request raised against DSTU2 and resolved Persuasive with Modification. It asked to change Provenance.entity.reference into entity.what[x] so the entity could be identified by either a URI or Reference(Any), because Provenance sometimes needs to point at non-FHIR source material.

Initial application:
The issue was initially applied in git commit 8058a0886c12cc7a61a61db3edae51be5e5698ef, whose subject explicitly cites GF#12480. That commit replaced Provenance.entity.reference with Provenance.entity.what[x], added uri|Reference(Any)|Identifier choices in the old spreadsheet source, and updated the entity search paths. The same commit also cited closely related Provenance entity issues GF#12503 and GF#12748.

Additional context:
Later final decisions intentionally changed the representation. FHIR-13694 clarified Reference.identifier logical-reference semantics, FHIR-13570 removed the separate Provenance.entity.whatUri as redundant with Identifier guidance, and FHIR-15659 simplified Provenance.entity.what[x] to a single Reference after logical references made the separate identifier/reference choices redundant. FHIR-49893 later corrected the current Provenance.entity.what comment to say what.identifier. The combined branch already has no-change audits for tightly related Provenance entity logical-reference issues, including FHIR-12503 and FHIR-15659, so this commit does not duplicate those decisions.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Provenance is active in source/fhir.ini, and current source/provenance/structuredefinition-Provenance.xml defines Provenance.entity.what as Reference(Resource) with a comment directing non-resource entities to what.identifier. The Reference datatype source and narrative define Reference.identifier as the logical-reference mechanism and explicitly cover cases where no actual FHIR instance exists for a Reference(Any) target. Reintroducing a direct uri choice would reverse later applied decisions rather than complete FHIR-12480.

Recommendation:
Keep this audit commit as-is. The current specification satisfies the DSTU2 URL/non-FHIR-source need through Reference.identifier; any future desire for a distinct Provenance.entity URI choice should be raised as a new Security/MnM issue because it would change later published Reference/Provenance modeling decisions.
