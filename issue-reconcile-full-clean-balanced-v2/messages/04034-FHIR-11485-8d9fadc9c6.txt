FHIR-11485: Audit financial GET/create clarification

Issue request:
FHIR-11485 was a Published FHIR-core financial-module change request with a Not Persuasive with Modification resolution. It objected that the DSTU2 financial module wording, "GET may be used in place of a CREATE of the request resource," was unclear because GET cannot create a resource. The accepted clarification says SEARCH (GET) may be used when no content model is needed to obtain the appropriate status element, but a content model must be CREATED when one is required to support the request for information.

Initial application:
The issue was applied by git commit 0169d534b2c20774f47743ce2b55d056826f27d2, "Tracker #11485," which replaced the ambiguous Read/Search-vs-Create sentence in source/financial-module.html with the resolved SEARCH (GET) / CREATE (POST) content-model wording. A subsequent QA commit, fe148b2af9615e85a33c70d0633fe7f6a57d4b9b, corrected spelling in that applied sentence without changing the intended meaning.

Additional context:
The current financial-module.html page remains in the build navigation and publication list through source/hierarchy.xml and publish.ini, and it is linked from the modules list and active financial resources. Searches for related Jira/community evidence found FHIR-11485 as the only exact Jira hit for the content-model/status-element wording; exact Zulip and Confluence searches found no conflicting discussion or later reversal. A broader Zulip thread on Financial Management claim modeling provides background about financial content models and exchange patterns but does not change the Jira/source conclusion.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already states the resolved rule: SEARCH (GET) may be used when no content model is required for the status element, while CREATE (POST) is needed when a content model is required for the information request.

Recommendation:
Keep this commit as-is. No follow-up source work is needed for FHIR-11485 unless the Financial Management work group later wants to modernize the surrounding financial-module prose for reasons independent of this applied tracker.
