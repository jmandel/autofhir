FHIR-11534: Audit ActivityDefinition Task distinction

Issue request:
FHIR-11534 was a Published/Persuasive CDS change request asking the specification to clarify why ActivityDefinition differs from Task. The accepted resolution said ActivityDefinition describes what should be done in the abstract, while Task represents the actionable portions of a concrete activity as it moves through workflow.

Initial application:
The issue appears to have been applied by git/SVN commit c03a8aca8404dc242356064fbc17b482dfc33d81, whose message includes "#11534: Clarified relationship to Task" and SVN 10927. That commit added a Boundaries and Relationships paragraph to source/activitydefinition/activitydefinition-introduction.xml distinguishing ActivityDefinition as an abstract task description from Task as a tracked workflow instance. Later commit bd1507dafa96568bf37503ff029bbabe8c3d8be2 updated workflow links and resource names but preserved the same distinction.

Additional context:
source/fhir.ini actively includes both task=Task and activitydefinition=ActivityDefinition, and maps ActivityDefinition to the active adf resource code, so the checked ActivityDefinition narrative is in current build scope. Current source/activitydefinition/activitydefinition-introduction.xml still contains the requested distinction, and current source/task/structuredefinition-Task.xml describes Task in terms of workflow execution progress. FHIR-12415 is a related no-change Task/ActivityDefinition tracker that was handled by allowing ActivityDefinition.kind to support any resource type; it does not change the FHIR-11534 distinction. Zulip and Confluence searches found no direct FHIR-11534 discussion or conflicting later work-group record.
