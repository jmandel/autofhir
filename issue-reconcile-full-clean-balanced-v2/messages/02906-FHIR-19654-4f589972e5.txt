FHIR-19654: Audit MedicationStatement taken explanation

Issue request:
FHIR-19654 was a Published Pharmacy change request, resolved Persuasive for R5, asking the specification to explain why the STU3 MedicationStatement.taken element had been removed and replaced by a status value of not-taken.

Initial application:
The issue was applied in the historical MedicationStatement spreadsheet by cdb9b154325715da80c5913ec7939955b7d52105 and merged by ec284380a4c273eeee93dc77e0ead3366dddec01. That application added a MedicationStatement.status note saying the taken attribute was removed to align with Workflow and was replaced with not-Taken status.

Additional context:
The linked Zulip thread confirms the original 2018 explanation: workflow alignment replaced taken with a not-taken status. Later Published Pharmacy decisions superseded that current model. FHIR-19468 removed not-taken from MedicationUsage.status and directed that an adherence attribute convey taken/not-taken; FHIR-19470 added and renamed that attribute to adherence; and FHIR-39271 confirmed that MedicationStatement.status now reflects the recording status of the statement while MedicationStatement.adherence carries taking/not-taking information. The active current build uses source/medicationstatement, and existing combined-branch reconciliation for FHIR-39271 has already cleaned stale status wording.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding the old FHIR-19654 explanation that taken was replaced by status not-taken would now be stale and misleading because the current source correctly points implementers to MedicationStatement.adherence, including its not-taking code, rather than to MedicationStatement.status.

Recommendation:
Keep this audit commit as-is. Do not restore the historical status-not-taken explanation in the current specification; any future migration note should be work-group reviewed and phrased around the current adherence model, not the superseded R4 status model.
