FHIR-5877: Audit retired DocumentManifest content attachment

Issue request:
FHIR-5877 was a Published/Persuasive with Modification DSTU1 change request asking DocumentManifest.content to become content[x] 1..* with either Attachment or a resource pointer to DocumentReference or Media, explicitly dropping Binary because Binary lacked enough technical context on its own.

Initial application:
The issue was applied in git commit 289d5edc33dcd7b4955566c5876f6613a7112eb2, whose message explicitly says "Updates to DocumentManifest [5877] - to add Attachment as a type of content". That commit changed the historical DocumentManifest spreadsheet from content 1..* Reference(DocumentReference|Binary|Media) to a content backbone plus DocumentManifest.content.p[x] 1..1 Attachment|Reference(DocumentReference|Media).

Additional context:
Later Published issue FHIR-12655 directly reversed the Attachment part of this model after FM confirmed it was no longer using DocumentManifest for attachment workflows. The applying commit 94e532a611046fcdc40df2d7d28457eeb7dad3a6 removed DocumentManifest.content.p[x] and made DocumentManifest.content a Reference(Any), while FHIR-13534 broadened the manifest narrative to avoid restricting it to DocumentReference only. Later Published issue FHIR-33021 recorded the retirement path because IHE MHD had moved from DocumentManifest to List, and the linked Zulip thread confirms IHE now used List where it had used DocumentManifest. Current source/fhir.ini no longer has an active documentmanifest resource, comments the old workgroup/TLA/status entries, marks DocumentManifest as dropped, and maps the old type to List; source/history.html records DocumentManifest as removed with "use List".

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding Attachment to DocumentManifest would contradict FHIR-12655, and there is no current-build DocumentManifest source to edit after the R5 removal. Carrying this DSTU1 Attachment alternative into List or DocumentReference would be a new substantive model decision, not a safe reconciliation of FHIR-5877.

Recommendation:
Keep this audit commit as-is for FHIR-5877. If a current workflow needs inline attachments in a manifest-like collection, open or use a current-release tracker against List, DocumentReference, or another active artifact rather than reopening this already-applied, later-reversed, and finally retired DocumentManifest tracker.
