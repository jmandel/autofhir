FHIR-7457: Audit ConceptMap translate outputs

Issue request:
FHIR-7457 was a Published/Persuasive with Modification vocabulary issue for the DSTU1 ConceptMap $translate operation. It asked to allow multiple Coding results instead of a single out parameter outcome 0..1 Coding; the accepted resolution was to allow multiple codings for translate, but with no primary marking per FHIR-7454 and no userSelected flag unless a client truly knew the user selected that Coding.

Initial application:
The Jira comment says the issue was applied in svn revision 5518. The imported git commit b1e826a4b83ef9617115bf221f0df040c5e39951 is titled "#7457 - multiple return values from $translate" and also applies FHIR-7454. In the old ConceptMap spreadsheet it replaced the single translate.outcome shape with repeated translate.match entries, each carrying a translate.match.concept Coding, and added wording that the returned Coding would never have userSelected = true.

Additional context:
ConceptMap is an active resource in source/fhir.ini, and the current build source for the operation is source/conceptmap/operationdefinition-ConceptMap-translate.xml after later source refactors. That current OperationDefinition returns a 0..* match parameter, states that there may be multiple matches, and has a Coding concept part whose documentation preserves the FHIR-7454-related rule that translate-generated codings are not userSelected. FHIR-7454 is relevant background but was not separately decided here because it is a datatypes-wide Coding issue beyond the ConceptMap $translate source checked for this seed.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already implements the issue's semantic requirement through repeated match results rather than the obsolete top-level outcome parameter, and it continues to avoid primary/userSelected marking on translated codings.

Recommendation:
Keep this no-change audit for FHIR-7457 as-is. No ConceptMap source follow-up is needed for this seed; a separate FHIR-7454 audit, if desired, should inspect the Coding datatype and CodeableConcept guidance independently.
