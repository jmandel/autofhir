FHIR-34147: Audit machine-friendly name regex length

Issue request:
FHIR-34147 was a Published/Persuasive with Modification FHIR-core change request, raised for R5 CodeSystem, asking that the machine-friendly name regular expression require at least one character after the initial uppercase letter by using `[A-Z]([A-Za-z0-9_]){1,254}` instead of `[A-Z]([A-Za-z0-9_]){0,254}`. The resolution said to change all such regular expressions to a minimum of 1 because other mechanisms already enforced the requirement and the change made the documentation consistent.

Initial application:
Git history shows the issue was explicitly applied by commit 70ad673b9e1f81ff3c228e62b42f005a1538d9ad, which changed the cnl-0 name regular expressions in `source/canonicalresource/structuredefinition-CanonicalResource.xml`, `source/codesystem/structuredefinition-CodeSystem.xml`, and `source/questionnaire/structuredefinition-Questionnaire.xml` from `{0,254}` to `{1,254}`.

Additional context:
The current CodeSystem source is in build scope through `source/fhir.ini` resource and approval entries, and the current active CodeSystem constraint uses `name.exists() implies name.matches('^[A-Z]([A-Za-z0-9_]){1,254}$')`. Searches across current `source/` found no remaining `{0,254}` regex occurrences, while the remaining `{0,254}` hits are in historical R4 release archive files under `tools/history/release4`, not current build source. Related audit commits for FHIR-36127 and FHIR-36184 confirm the surrounding `name.exists() implies` guard is intentional later context and should be preserved.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current build-scope source already implements the approved minimum-length regex for CodeSystem and the broader canonical-name regex family, so editing current source would be redundant and risks disturbing later guard/anchoring cleanup.

Recommendation:
