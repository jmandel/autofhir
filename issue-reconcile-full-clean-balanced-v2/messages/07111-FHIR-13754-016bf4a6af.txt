FHIR-13754: Audit ServiceRequest description removal

Issue request:
FHIR-13754 was a Published/Persuasive with Modification STU3 Orders and Observations issue for ProcedureRequest asking to clarify the boundary of .description because the cited myringotomy example used it as a reason or clinical summary overlapping reasonCodeableConcept.text and supportingInformation. The approved resolution was to remove the .description element and move the example text into .note.

Initial application:
The issue was explicitly applied in commit 3d115c2bcdd810afbf7553f0857fa36de88ccc2c, "GF#13754 remove description element". That commit marked !ServiceRequest.description in the then-authoritative ServiceRequest spreadsheet source and changed servicerequest-example-myringotomy.xml from a description element to a note with author, time, and the same clinical-summary text. The file path was already ServiceRequest because ProcedureRequest had been merged/renamed into ServiceRequest shortly before this issue was applied.

Additional context:
The current build actively includes ServiceRequest in source/fhir.ini and no longer has an active ProcedureRequest resource surface. Current source/servicerequest/structuredefinition-ServiceRequest.xml has ServiceRequest.reason, ServiceRequest.supportingInfo, and ServiceRequest.note, but no ServiceRequest.description element. The cited myringotomy example still carries the clinical-summary text in note. A related FHIR-13630 reconciliation has already restored the ServiceRequest.reason guidance for free-text reasons and report/document findings on the combined branch, so this issue does not need additional reason/supportingInfo prose to preserve the approved boundary.

AutoFHIR reconciliation:
