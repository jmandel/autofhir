FHIR-12316: Audit RequestIntent definitions

Issue request:
FHIR-12316 was a Published/Persuasive FHIR-core workflow change request from DSTU2 asking for better definitions for the RequestStage values because the old definitions mostly repeated the code names.

Initial application:
The application is represented by git commit 839bf586d6c1cf9a322e122852f0cc49bcfed263, "FHIR Workflow changes", which explicitly lists {#12316}. That workflow commit reworked the Request pattern spreadsheet and changed the active request-intent code definitions from terse names to explanatory definitions for proposal, plan, order, original-order, reflex-order, filler-order, and instance-order.

Additional context:
Current source uses RequestIntent, not RequestStage, for active request-pattern bindings. source/fhir.ini keeps the request logical pattern in build scope, active resource StructureDefinitions bind intent elements to ValueSet/request-intent, and the request-intent spreadsheet/codesystem carry the expanded definitions. The old source/terminologies request-stage files still exist but are not active fhir.ini codesystem/valueset entries, are not referenced by current structure definitions, and the current build URL for valueset-request-stage returns 404 while valueset-request-intent resolves. Later community evidence found no FHIR-12316-specific reversal; a 2026 Zulip thread only noted a Request Intent listing question, not a definition problem.

AutoFHIR reconciliation:
No source change was made. Editing the obsolete request-stage files would not correct the current built specification, and the active RequestIntent definitions already satisfy the issue's requested clarification.

Recommendation:
Keep this audit commit as-is. If a future work item wants to clean up orphaned request-stage source files or code-system listing behavior, handle that separately; FHIR-12316 itself is already reconciled in the active RequestIntent source.
