FHIR-7431: Record AuditEvent source identifier reconciliation

Issue request:
FHIR-7431 was Published/Persuasive with Modification for the Security work group after asking that AuditEvent.source.identifier be changed from string to the Identifier datatype and that the old note distinguishing business and resource identifiers be fixed.

Initial application:
The issue was applied in the historical AuditEvent spreadsheet/examples by commit 8e1a48066d, which changed the AuditEvent source identifier type from string to Identifier and updated example source.identifier entries to Identifier syntax. No FHIR-7431-specific reconciliation commit was already present on the combined branch.

Additional context:
Later Published issue FHIR-17413 deliberately replaced AuditEvent.source.identifier with AuditEvent.source.observer as a Reference. Current AuditEvent is an active build resource, and its source.observer element is a required Reference to the reporting actor. The Reference datatype still has Reference.identifier as an Identifier logical reference, and current examples and Zulip guidance show AuditEvent.source.observer.identifier is the intended way to carry the business/source identifier when there is no literal resource reference. Later Published issues FHIR-32461 and FHIR-32465 broadened and clarified the source observer actor model without restoring a direct source.identifier element.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source no longer matches the old element name because a later final Jira decision superseded it, but it still supports the original business identifier use case through Reference.identifier on AuditEvent.source.observer.

Recommendation:
Keep this no-change audit as-is. Reintroducing AuditEvent.source.identifier would conflict with the later FHIR-17413 model; any future changes should be handled as a new AuditEvent.source.observer modeling issue rather than as a FHIR-7431 fixup.
