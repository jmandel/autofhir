FHIR-7170: Audit MedicationStatement RxNorm request

Issue request:
FHIR-7170 was a Published/Persuasive with Modification Pharmacy issue for DSTU1 MedicationStatement.medication. It asked to say that in the US the code would usually be RxNorm because of Meaningful Use regulation; the accepted resolution rejected US-specific "usually RxNorm" wording for a universal standard, said possible medication-code examples would be provided, and specifically required correcting the exemplar medication.code value set to SNOMED CT is-a 410942007.

Initial application:
The Jira comment says the issue was already fixed in SVN 6684. That maps to git commit 6ce87fde09500c2d61c86a07ac98f49037e7d747, whose git-svn-id is build@6684 and whose subject is "#8064 - fixed Medication.code exemplar valueset"; the patch changed source/medication/valueset-medication-codes.xml from the route-of-administration root 284009009 to 410942007. This is the exact medication-code correction named in the FHIR-7170 resolution, even though the commit was labeled with the companion FHIR-8064/8022 Medication issue.

Additional context:
MedicationStatement is active in the current build. Its current medication element is CodeableReference(Medication) with an example binding to http://hl7.org/fhir/ValueSet/medication-statement-medication-codes, and that ValueSet includes http://hl7.org/fhir/ValueSet/medication-codes plus a no-known-medications code. Later Published Pharmacy issue FHIR-19294 changed the underlying Medication SNOMED exemplar binding from the 2015 410942007 family to only SNOMED CT is-a 763158003, and the combined branch already contains that reconciliation. Current core also lists RxNorm in the terminology systems table and delegates RxNorm usage guidance to HL7 Terminology, while direct Zulip and Confluence searches found no conflicting FHIR-7170 discussion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Reapplying the 2015 410942007 root would reverse a later final Pharmacy decision, and adding US-specific RxNorm regulation wording would contradict the accepted FHIR-7170 resolution. The current source remains consistent with the issue family: MedicationStatement has an example medication-code binding, core recognizes RxNorm as an external terminology, and the current SNOMED exemplar reflects later published guidance.

Recommendation:
Keep this no-change audit as-is. Do not change the current Medication value set back to 410942007 or add US Meaningful Use/RxNorm preference text for FHIR-7170; any future RxNorm-specific MedicationStatement preference should be handled in jurisdictional implementation guides or terminology guidance, not as a core universal rule.
