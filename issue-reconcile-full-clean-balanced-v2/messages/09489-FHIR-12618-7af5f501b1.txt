FHIR-12618: Audit explicit slicing discriminator type

Issue request:
FHIR-12618 was Published/Persuasive with Modification for DSTU2. It asked to make slicing discriminator semantics explicit by replacing the old single discriminator string convention with a complex discriminator containing a required type code and a restricted FHIRPath path, and by linking/explaining the allowed path syntax.

Initial application:
The issue appears to have been applied in SVN revision 11179, imported as git commit 3253654af7787e9b738b15f4618a2b9d02d56f7f with subject "#12618 + #12641- rework discriminator and add selector extension". That commit removed the old @type/@profile discriminator-string guidance, added ElementDefinition.slicing.discriminator.type and .path, added the discriminator-type code list, and rewrote the profiling discriminator section around type/path pairs.

Additional context:
Current build-scope source still carries the intended model: source/fhir.ini actively maps elementdefinition as a datatype; source/datatypes/elementdefinition.xml defines ElementDefinition.slicing.discriminator.type as 1..1 code with a DiscriminatorType binding and .path as 1..1 string; source/profiling.html describes each discriminator as a type plus FHIRPath expression; and source/fhirpath.html#simple defines the restricted FHIRPath subset and lists ElementDefinition.slicing.discriminator.path as a user. Later related issues FHIR-13711, FHIR-19612, FHIR-23035, and FHIR-27532 refined the simple-FHIRPath and resolve() documentation and are already represented on the combined branch, so they do not require a duplicate decision here.
