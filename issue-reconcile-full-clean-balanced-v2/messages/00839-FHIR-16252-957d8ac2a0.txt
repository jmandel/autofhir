FHIR-16252: Audit Sequence deprecation-note resolution

Issue request:
FHIR-16252 was Published as Persuasive with Modification for STU3. The commenter objected to deprecating or converting the Sequence resource into a definition-only resource because Sequence still needed to represent observed patient sequence data, raw sequencing outputs, and analytic accuracy; the accepted resolution was to replace the strong definitional-only STU note with a softer note saying Clinical Genomics had identified overlap with genomics-reporting Observation profiles and expected future ballot changes.

Initial application:
The issue was applied before this reconciliation. Commit 6828d02018d3cfd565a293c7f9c1284c37ce2d6d, merged as 9ef639a3fb9bc7f5c5206fb7ac249d825ea0ae81 and linked from the Jira comment, replaced the old source/sequence/sequence-introduction.xml STU note about making Sequence definition-only with the accepted overlap/future-changes note. That same application commit also covered FHIR-16501, which had the same final resolution text.

Additional context:
The old Sequence resource no longer exists as a current build-scope resource. FHIR-19453 later renamed Sequence to MolecularSequence, and later CG work replaced the legacy MolecularSequence model with MolecularDefinition through FHIR-51227. Current source has no source/sequence or source/molecularsequence directory; source/fhir.ini lists Sequence only under removed resources and leaves MolecularSequence as commented or legacy metadata, while the diagnostics module says MolecularSequence has been replaced by MolecularDefinition and MolecularDefinition notes describe Sequence as a profile/concept rather than resurrecting the old resource-level deprecation note.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The requested STU3 note change was applied historically, and the current specification should not reintroduce wording for the removed Sequence resource or add redundant deprecation/anti-deprecation prose to the successor MolecularDefinition material.

Recommendation:
Keep this commit as-is. Do not restore the old Sequence note or add new core wording for FHIR-16252 unless Clinical Genomics makes a future decision to re-open the current MolecularDefinition/MolecularSequence replacement strategy.
