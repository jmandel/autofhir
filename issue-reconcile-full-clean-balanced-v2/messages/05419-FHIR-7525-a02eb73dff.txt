FHIR-7525: Audit MedicationStatement status definitions

Issue request:
FHIR-7525 was a Published Pharmacy change request with a Persuasive resolution. It challenged the DSTU1 MedicationStatement.status definitions for completed and entered-in-error, questioned whether in-progress and completed were a binary choice, and asked that v3-flavored wording such as nullified be improved. The approved resolution was to review and update all statuses using the Pharmacy status spreadsheet.

Initial application:
No source commit tagged FHIR-7525 was found. The Jira comment says it was fixed as part of tracker FHIR-6310 in svn 6552; git-svn commit d3c2a3a055 is that svn 6552 application and updated MedicationStatement.status codes from the Pharmacy spreadsheet. The immediately following FHIR-8107/svn 6553 commit, 31e9678a6e, corrected the MedicationStatement.status description and minor status-spreadsheet mistakes from the same work.

Additional context:
MedicationStatement is an active current resource in source/fhir.ini, and the authoritative current source under source/medicationstatement no longer has the DSTU1 in-progress/completed/nullified model. Later Pharmacy decisions substantially changed the status model: FHIR-19468/FHIR-19470 moved taking/not-taking semantics into adherence, FHIR-32060 changed status to recorded, entered-in-error, and draft, and FHIR-39271 kept that model while renaming MedicationUsage back to MedicationStatement. The combined branch already contains a separate FHIR-39271 reconciliation commit that fixed remaining rename-era status wording.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current StructureDefinition says MedicationStatement.status is the status of recording the medication statement, points usage/adherence semantics to MedicationStatement.adherence, and binds to a CodeSystem whose current code definitions for recorded, entered-in-error, and draft are clear. Re-introducing or further editing the old completed/in-progress/nullified wording would conflict with later published Pharmacy decisions rather than complete FHIR-7525.

Recommendation:
Keep this no-change audit. No FHIR core source follow-up is needed for FHIR-7525 unless Pharmacy reopens the MedicationStatement status/adherence model in a new tracker.
