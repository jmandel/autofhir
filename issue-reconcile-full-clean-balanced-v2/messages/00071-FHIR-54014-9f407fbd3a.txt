FHIR-54014: Align dosage narrative with renderedInstruction requirement

Issue request:
FHIR-54014 was Applied with a Persuasive with Modification resolution for R6 Pharmacy dosage redesign. It asked to require DosageDetails.renderedInstruction so users always have a simple human-readable representation of the dosing; the accepted resolution made the element 1..1, removed complex-dosing-only definition text, added that renderedInstructions must always be present to communicate the full dosage intent, and revised the comment to say the renderedInstructions content SHALL contain the structured dosage information and may contain additional information.

Initial application:
The issue had already been partially applied in source: git commit efe537aa9a928e9adbd54659c83cd02482cb34e9 changed the active DosageDetails spreadsheet source so DosageDetails.renderedInstruction is 1..1 with the accepted definition and comment, and git commit b641e8e249fac89aeac83d6e3f5e0e275ccb1058 added renderedInstruction to selected medication examples. The datatype is in current build scope because source/fhir.ini actively lists DosageDetails as a datatype and as normative. However, the dosage narrative page still retained optional wording, saying renderedInstruction may be present and that applications SHOULD consider populating it.

Additional context:
The January 2026 Pharmacy WG minutes record the same decision path: the group discussed requiring human-readable instructions, selected SHALL rather than SHOULD, and proposed making .renderedInstruction mandatory and clarifying that it must include all aspects of the instruction. Later dosage work such as FHIR-54651 changed the same narrative while removing DosageDetails.simple, but did not reverse the FHIR-54014 requirement. Related rendered-instruction issues FHIR-54032 and FHIR-54793 remain Triaged and were treated only as background.

AutoFHIR reconciliation:
This commit updates source/dosage.html, an active dosage narrative page for the current build, so it no longer contradicts the required cardinality. The opening sentence now says DosageDetails must contain renderedInstruction, and the final paragraph now explains that renderedInstruction remains important for humans and is required to be present and communicate the full dosage intent. No datatype spreadsheet change was needed because the authoritative DosageDetails source already matches the Jira resolution.

Recommendation:
Keep this source fix. It is a narrow correction to remove a real conformance contradiction between the renderedInstruction 1..1 datatype definition and the narrative guidance. Broader R6 dosage example modernization should remain under the existing dosage/example issues rather than being bundled into this reconciliation.
