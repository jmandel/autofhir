FHIR-8958: Audit Claim serviced period support

Issue request:
FHIR-8958 was a Published FHIR-core Claim change request, resolved Persuasive with Modification, asking that Claim.serviceDate support services spanning a period and suggesting a more general service-performed name. The recorded resolution says this was addressed in STU3 as serviced[x] DateTime|Period; the durable request for this reconciliation is that the Claim service date element allow a Period.

Initial application:
No Jira-keyed source commit for FHIR-8958 was found. The relevant pre-GitHub history shows commit 649fcd4cbf changed Claim.item.serviceDate from a single date to Claim.item.service[x] with date|Period and added Claim.billablePeriod. Commit 6850355e89 then renamed the item element to Claim.item.serviced[x] and updated examples to servicedDate. Later source conversion commits preserved the same date|Period type in source/claim/structuredefinition-Claim.xml.

Additional context:
Claim is an active current-build resource in source/fhir.ini. Current source/claim/structuredefinition-Claim.xml defines Claim.item.serviced[x] as 0..1 date or Period with the service/product delivery definition. Published STU3, R4, R5, and the current build all expose Claim.item.serviced[x] as date|Period, so the Jira resolution's DateTime wording does not match the actual STU3-and-later publication surface. Related FHIR-7314 also requested dateTime|Period, and FHIR-7315 requested a claim-level service period; those were used as context only because changing the current date choice to dateTime would be a separate substantive decision, and Claim.billablePeriod is already present. No Zulip or Confluence evidence was found that changes the source/history conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative Claim definition already permits the period use case through Claim.item.servicedPeriod while retaining the published date|Period choice that has existed since STU3. The old unreferenced gg-testing-connectathon-9.xml sample still contains DSTU-era serviceDate elements, but it is not listed in the active Claim example or pack lists and is not a current-spec fix target for this issue.

Recommendation:
Keep this no-change audit commit as-is for FHIR-8958. If the Financial Management work group wants to revisit the separate date-versus-dateTime question from FHIR-7314, handle it as a new/source-changing decision rather than as part of this already-published period-support audit.
