FHIR-8774: Audit Appointment example bindings

Issue request:
FHIR-8774 was Published/Persuasive for DSTU2 and asked that Appointment examples stop using participant type/code "attending" outside the required binding and use preferred-bound appointment type codes instead of the old General Discussion type code where sensible.

Initial application:
The participant type issue had already been corrected by commit 976513d094, which replaced the local "attending" code with v3 ParticipationType ATND. The explicit GF8774 application commit aea6363ec7 then changed the Appointment examples from local specialty and appointment-type codes to SNOMED CT specialty 394814009 and v2-0276 appointment type codes WALKIN/FOLLOWUP. A later terminology URL update, d1f387ce5e, moved the v3 ParticipationType system URL to terminology.hl7.org.

Additional context:
Appointment is active in source/fhir.ini and its three examples are listed in list-Appointment-examples.xml. The current R6 model no longer has the old Appointment.type element; Appointment.appointmentType remains preferred-bound to v2-0276 and the examples use v2-0276 codes, while Appointment.serviceType is only example-bound. The remaining General Discussion coding is an unsystemed serviceType example, not a required/preferred binding violation. Participant.required is now boolean and participant.type uses ATND from v3 ParticipationType.

AutoFHIR reconciliation:
No source change was made. The current authoritative Appointment examples already reflect the applied issue for current build scope: preferred-bound appointmentType examples use v2-0276 codes, invalid participant type "attending" is gone, and the remaining General Discussion serviceType text is not governed by a required or preferred binding.

Recommendation:
Keep this no-change audit commit. Do not add redundant edits for the unsystemed serviceType example unless PA makes a new decision to constrain or replace the example-bound serviceType coding.
