FHIR-27793: Audit HTTP resource type wording

Issue request:
FHIR-27793 was Published/Persuasive for R5 and asked the HTTP specification to clarify that create and update request bodies at typed endpoints must be resources of the named type, not arbitrary FHIR resources. The accepted resolution said to update both the create and update sentences as proposed.

Initial application:
The issue was applied by historical commit 81268cc6bf9885efe1c6e6993f10e197a7937c31, "Fix FHIR-27793", associated with PR 1729 and merged into R5 PR 1731. That commit changed source/http.html in exactly the two requested places, adding "of the named type" to the update and create request-body rules.

Additional context:
The originating Zulip thread confirms the intended REST rule: a POST to a resource-type endpoint must carry the same resource type, with operations as the exception.
