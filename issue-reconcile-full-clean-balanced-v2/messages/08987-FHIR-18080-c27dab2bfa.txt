FHIR-18080: Audit Device search parameter expressions

Issue request:
FHIR-18080 was a Published/Persuasive with Modification OO change request for STU3 Device search parameters. It asked to add the missing expressions for Device-model, Device-udi-carrier, and Device-udi-di, with the final comments narrowing Device-model to Device.modelNumber and Device-udi-di to Device.udiCarrier.deviceIdentifier while deferring the HRF/AIDC handling to FHIR-19288.

Initial application:
The Jira comment points to commit 9d8ee7f71d35a16a7dd17e9249f90f3b0f8beda8. That commit updated the then-authoritative Device spreadsheet search parameter rows so Device-model used Device.modelNumber, Device-udi-carrier used Device.udiCarrier.carrierHRF, and Device-udi-di used Device.udiCarrier.deviceIdentifier. The current build has since moved those definitions into source/device/bundle-Device-search-params.xml.

Additional context:
Device is active in source/fhir.ini, so source/device/bundle-Device-search-params.xml is current build input for the Device resource. FHIR-19288, also Published/Persuasive with Modification, explicitly limited the UDI carrier search criterion to HRF until AIDC search semantics could be demonstrated. Current SearchParameter no longer defines XPath fields, so there is no current XPath source location to add for this STU3-era request.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source already has Device-model with expression Device.modelNumber, Device-udi-di with expression Device.udiCarrier.deviceIdentifier, and the remaining UDI carrier search parameter scoped to HRF with expression Device.udiCarrier.carrierHRF, matching the current Device element names and the FHIR-19288 narrowing.

Recommendation:
Keep this no-change audit commit. No core source follow-up is needed for FHIR-18080 unless a future issue reintroduces XPath metadata or defines AIDC search semantics.
