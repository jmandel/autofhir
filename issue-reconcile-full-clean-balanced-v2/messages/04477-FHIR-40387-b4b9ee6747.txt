FHIR-40387: Audit markdown datatype guidance

Issue request:
FHIR-40387 was a Published/Persuasive R5 clarification from FHIR-I asking for base datatype guidance that systems placing plain string data in markdown fields escape markdown formatting characters so downstream markdown rendering does not strip clinically meaningful text.

Initial application:
The issue was applied by commits 14d0d18cf8 and 67661b5631 on 2023-02-16. The first commit added the requested warning bullet and an implementation note to source/datatypes.html; the second corrected the implementation-note text and closing marker. The primitive datatype table comment in source/datatypes/primitives.xml was not changed, which is consistent with the resolution because it targeted the narrative "About the markdown datatype" list rather than the primitive table comment.

Additional context:
source/fhir.ini places datatypes in the active datatypes build area, and the current source/datatypes.html contains the approved warning plus the escaping implementation note. The FHIR-39574 GenomicStudy markdown discussion is the same concern family and led to the core tracker, but FHIR-39574 already has its own reconciliation commit on the combined branch. FHIR-I minutes on 2023-02-15 record the Persuasive 3-0-0 vote for FHIR-40387. Community searches found background discussion but no later final decision requiring a different core edit.

AutoFHIR reconciliation:
No source change was made. The current core source already carries the approved warning in the requested narrative location, and duplicating that guidance into the primitive definition/comment would go beyond the Jira resolution and create an avoidable maintenance divergence risk.

Recommendation:
Keep this audit commit as-is. Revisit only if FHIR-I separately decides that the primitive markdown datatype definition/comment should also carry renderer-safety warning text or changes the escaping guidance.
