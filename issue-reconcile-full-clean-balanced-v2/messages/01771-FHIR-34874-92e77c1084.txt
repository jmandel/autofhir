FHIR-34874: Audit external patient-proficiency context

Issue request:
FHIR-34874 was Published/Persuasive with Modification for R5. It asked to broaden the patient-proficiency extension from Patient, Person, and RelatedPerson so proficiency could also be represented for practitioner communication; the final resolution specifically required adding practitioner.communication and explicitly declined healthcareservice.communication and practitionerrole.communication because those advertise service or role language capability rather than a person's proficiency level.

Initial application:
No current HL7/fhir core source file defines StructureDefinition/patient-proficiency. The applicable source moved out of the core checkout, and the FHIR Extension Pack commit 8cb6561b118b30ad5e942862da75b2475305f850, titled "FHIR-34874 Patient proficiency extension permitted on Practitioner", added a Practitioner.communication context to input/definitions/multiple/StructureDefinition-patient-proficiency.xml.

Additional context:
The core source still actively builds Practitioner, PractitionerRole, and HealthcareService, but the patient-proficiency extension definition is no longer in those core resource folders. The current Extension Pack definition has contexts for Patient.communication, RelatedPerson.communication, Practitioner.communication, and Person.communication, with no HealthcareService.communication or PractitionerRole.communication context. A later Applied issue, FHIR-47305, confirms that patient-proficiency remains the intended mechanism for Practitioner.communication and added a core Practitioner.communication comment that points implementers to that extension.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The requested extension-context change belongs to the FHIR Extension Pack rather than this HL7/fhir checkout, and that external source already reflects the final Jira resolution while preserving the exclusions for HealthcareService and PractitionerRole.

Recommendation:
Keep this empty audit commit as-is for the core reconciliation record. No HL7/fhir source follow-up is needed for FHIR-34874; future changes to the extension context should be made and reviewed in the FHIR Extension Pack source.
