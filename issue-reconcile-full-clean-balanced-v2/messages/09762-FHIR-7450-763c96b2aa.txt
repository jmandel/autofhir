FHIR-7450: Audit unknown extension declaration history

Issue request:
FHIR-7450 was a Published/Persuasive with Modification FHIR-I change request from the DSTU1 ballot. It asked how systems that do not accept unknown extensions should declare that fact, and the resolution first proposed a new Conformance.rejectUnknown element before the Jira comments clarified that the request was merged into the existing Conformance.acceptUnknown mechanism.

Initial application:
The Jira comment records svn revision 6101. In git history, 578f4a5f5c145453fc3cb71847eb44b247d6d96a corresponds to build@6101 and applied FHIR-7450 by changing Conformance.acceptUnknown from a boolean to a code bound to UnknownContentCode, with values for accepting neither unknown elements nor extensions, only extensions, only elements, or both. That mechanism was later carried through the Conformance to CapabilityStatement rename.

Additional context:
FHIR-8170 was the same missing-declaration concern and was closed as a duplicate of FHIR-7450. Later, FHIR-14647 intentionally removed CapabilityStatement.acceptUnknown because the element and vocabulary were awkward and unused, and f0ec862a5f986e3a82bb9ef1a4fa32619c65d6e1 applied that removal. FHIR-18363 then removed the corresponding extensibility-page SHALL because there was no longer a formal way to satisfy it, and cd5231d416ef0145942d6a04f15d50d66640be98 removed the exact bullet from source/extensibility.html. Current source/fhir.ini keeps CapabilityStatement and the extension type page in build scope, but the current CapabilityStatement StructureDefinition has no acceptUnknown element and the active extensibility exchange rules no longer require a CapabilityStatement declaration. The combined branch already has separate audit commits for FHIR-14647 and FHIR-18363.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because FHIR-7450 was applied historically through Conformance.acceptUnknown, and later final FHIR-I decisions intentionally removed that mechanism and the declaration requirement from the current specification.

Recommendation:
Keep this audit commit as-is. Do not resurrect rejectUnknown or acceptUnknown for FHIR-7450; any future replacement for declaring unknown-extension handling should be a new work-group decision because the current source correctly reflects the later removal decisions.
