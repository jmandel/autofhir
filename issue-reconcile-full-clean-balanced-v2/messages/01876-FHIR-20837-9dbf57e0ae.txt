FHIR-20837: Audit AuditEvent DICOM EventDateTime mapping

Issue request:
FHIR-20837 was a Security work group Change Request with Published/Persuasive status for R5. It asked that the AuditEvent DICOM AuditMessage EventDateTime mapping move from AuditEvent.period to AuditEvent.recorded.

Initial application:
The issue is not named in source-history commit subjects, but the Jira comment links HL7/fhir pull request #708. That PR merged as e5f777ad51 and includes commit 8f93636e05, which removed EventDateTime from the AuditEvent.period DICOM mapping cell and added it to AuditEvent.recorded in the then-authoritative auditevent spreadsheet. The later 33b409a4b6 source conversion generated source/auditevent/structuredefinition-AuditEvent.xml with AuditEvent.recorded mapped to EventDateTime.

Additional context:
AuditEvent is an active resource in source/fhir.ini. FHIR-32444 later renamed AuditEvent.period to AuditEvent.occurred[x] and changed it to Period|dateTime, but did not add a DICOM EventDateTime mapping to occurred[x]. Current source has the only AuditEvent StructureDefinition EventDateTime mapping on AuditEvent.recorded. Confluence and Zulip searches found no directly relevant conflicting discussion.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because the current build source already reflects the requested DICOM mapping and the later period-to-occurred[x] rename is consistent with that result.

Recommendation:
Keep this audit commit as-is. No follow-up source work is recommended for FHIR-20837 unless a future Security work group decision changes the AuditEvent-to-DICOM mapping model.
