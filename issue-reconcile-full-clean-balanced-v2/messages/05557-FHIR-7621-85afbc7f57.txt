FHIR-7621: Audit Condition relationship detail rename

Issue request:
FHIR-7621 was Published with resolution Persuasive with Modification. It asked whether Condition.dueTo.target, Condition.occurredFollowing.target, and Condition.evidence.detail should use a consistent child name, and the accepted resolution was to change target to detail for Condition.dueTo and Condition.occurredFollowing while recognizing that those concepts were moving to extensions under FHIR-7620.

Initial application:
The historical application is commit d9e60bf0bbf8924afe37bac0b3187b05d498573c, "#7620, #7621 - dueTo and following are moved to standard extensions". The parent Condition spreadsheet contained Condition.dueTo.target and Condition.occurredFollowing.target; after the commit, the extension spreadsheet contained dueTo.detail and occurredFollowing.detail, and the old in-resource example elements were removed.

Additional context:
Condition is active in the current build through source/fhir.ini. The current Condition resource no longer has Condition.dueTo or Condition.occurredFollowing elements, and Condition.evidence has since been represented as CodeableReference with a current R4-R6 diff note mapping Condition.evidence.detail to Condition.evidence.reference. The current condition-dueTo and condition-occurredFollowing definitions live in the FHIR Extension Pack as simple value[x] extensions, so neither a stale target child nor a detail child remains in the maintained source.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The original inconsistency was applied historically, and the current core checkout and extension-pack source do not contain an unrenamed target element requiring correction.

Recommendation:
Keep this no-change audit as-is. Any future redesign of the moved extensions would belong in the Extension Pack and should be handled as a new work-group decision, not as remaining FHIR-7621 core source work.
