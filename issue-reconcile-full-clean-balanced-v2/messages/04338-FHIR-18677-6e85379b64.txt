FHIR-18677: Audit ValueSet metadata-only form

Issue request:
FHIR-18677 was Published/Persuasive for STU3 and asked to clarify that a ValueSet resource can have neither .compose nor .expansion, so metadata-only ValueSet retrieval/use is valid alongside definition-only, expansion-only, and combined forms.

Initial application:
The Jira comment points to git 4907f9bcb0b710cb2837a93a20c4b23210a37249. That commit included GF#18677 and changed source/valueset/valueset-introduction.xml from allowing either .compose, .expansion, or both to explicitly allowing "both of them, or neither of them (if only the metadata is being represented)." The same source area had already been shaped by FHIR-17475 / commit 37b0ae652bb936957e6a8ccbecdcc8a17e97d6e4, which removed the old VSD-5 invariant and added the combinations-of-.compose-and-.expansion section.

Additional context:
ValueSet is an active resource in source/fhir.ini, and the current StructureDefinition source gives both ValueSet.compose and ValueSet.expansion minimum cardinality 0. Current ValueSet narrative also lists the neither-compose-nor-expansion case as a valid format, primarily for summary search. Searches for FHIR-18677 in Zulip and Confluence found no conflicting community record. The related FHIR-17475 Jira/Zulip history supports the same metadata-only interpretation but is not decided in this commit.

AutoFHIR reconciliation:
No source change was made. The current build-scope ValueSet source already preserves the FHIR-18677 clarification in both the introductory narrative and the detailed combinations section, and the conformance source no longer contains the old invariant that would forbid metadata-only ValueSet instances.

Recommendation:
Keep this no-change audit commit as-is. No follow-up core change is recommended for FHIR-18677 unless a future work group decision wants to revisit ValueSet summary or metadata-only semantics.
