FHIR-17169: Audit Request reporting intent decision

Issue request:
FHIR-17169 was Published/Persuasive with Modification for STU3. It originally asked to add `reported` to the Request.intent value set for requests that do not authorize action, but the final decision rejected adding that intent code, changed the Request.authoredOn short description, added Request.reported[x] and Event.reported[x] as 0..1 boolean|Reference(Patient|RelatedPerson|Practitioner|PractitionerRole|Organization), and called for safety/signature guidance about important tag information.

Initial application:
The Jira comment cites GitHub merge `6b8ca9c6`. The implementation commit in that merge, `633021569c4ee210837d89828831cac8764c69bd`, changed `Request.authoredOn` to "When request was created/transitioned to active" and added the Request/Event `reported[x]` pattern rows with the approved definition. It did not add a `reported` code to Request.intent.

Additional context:
Current `source/fhir.ini` keeps `request` and `event` as active logical pattern build inputs. Current source still has the authoredOn short, the Request/Event `reported[x]` rows, and no Request.intent `reported` code. Later Pharmacy issues that specialize the seed discussion for MedicationRequest, including FHIR-19313 and FHIR-19517, are already represented by their own combined-branch audit commits; the later FHIR-49863 MedicationRequest rename is only Resolved - change required and is context rather than a separate decision in this default run. FHIR-I and Pharmacy WGM minutes confirm the approved direction: `reported` should be orthogonal to Request.intent and Pharmacy should handle MedicationRequest-specific reporting separately.
