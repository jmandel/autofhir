FHIR-12245: Audit ElementDefinition type URI support

Issue request:
FHIR-12245 was Published/Persuasive for DSTU2 and asked to rework ElementDefinition.type.code so logical models could name other logical-model types. The accepted change was to make ElementDefinition.type.code a uri, define it as a reference to a canonical StructureDefinition, treat relative references as relative to http://hl7.org/fhir/StructureDefinition, and constrain non-logical StructureDefinitions to relative/FHIR-defined type references.

Initial application:
The issue was applied by git-svn commit f632a5f6862e53cac15952040d46197658a517be (SVN r10013), which changed ElementDefinition.type.code from code to uri, added the relative StructureDefinition URL wording, and added sdf-19 for custom types only in logical models. Current source still carries the substantive ElementDefinition.type.code URI/reference wording.

Additional context:
Later FHIR-17185 deliberately revised sdf-19 so it applies to FHIR-originated/core StructureDefinitions rather than all externally authored StructureDefinitions, explaining why the current invariant no longer literally says kind = logical. Later ElementDefinition.type.code work such as FHIR-22670 and FHIR-35769 is already represented on the combined branch and does not require a duplicate decision here.

AutoFHIR reconciliation:
This commit makes no source change. The active ElementDefinition source already defines type.code as uri and documents relative StructureDefinition references plus the logical-model absolute-URL exception. The active StructureDefinition source still binds the rule into sdf-19 for FHIR specification models, consistent with the later FHIR-17185 narrowing.

Recommendation:
Keep this audit commit as-is. Reintroducing the original broader invariant would conflict with FHIR-17185; any future change to the scope of absolute type-code URLs should be handled as a new FHIR-I decision rather than as a FHIR-12245 fixup.
