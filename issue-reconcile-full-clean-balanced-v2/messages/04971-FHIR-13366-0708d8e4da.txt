FHIR-13366: Audit Endpoint ContactPoint guidance

Issue request:
FHIR-13366 was a Published/Persuasive STU3 Patient Administration request to clarify the Endpoint boundaries discussion so implementers know when to use Reference(Endpoint) rather than directly embedding a ContactPoint. The accepted resolution said Endpoint is for system-to-system communication where the address value only makes sense with the endpoint's protocols, purpose, and other connection details, while ContactPoint is directly usable contact information for communicating with an entity.

Initial application:
The request was applied before this reconciliation. Git commit aea6363ec7a9d007043d6b8358d2f29b348056a1 added the ContactPoint subsection to source/endpoint/endpoint-introduction.xml under Boundaries and Relationships, including the XDS URL and US Direct examples and the ContactPoint distinction. Commit b95b88afff619d81714abcd1f0c954e7cdf0a0a5 later corrected the typo in "address value" and preserved the same guidance.

Additional context:
Endpoint is an active current-build resource in source/fhir.ini. Later Endpoint work, including FHIR-33026, relaxed adjacent CapabilityStatement wording from server-focused to system-focused text and left the ContactPoint boundary guidance intact. Community searches for FHIR-13366 and for the distinctive Endpoint/ContactPoint/system-to-system wording found no conflicting Zulip or Confluence decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change.
