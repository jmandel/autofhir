FHIR-28608: Audit ObservationDefinition subject application

Issue request:
FHIR-28608 was Published/Persuasive for R5 by OO. It requested replacing ObservationDefinition.subject[x] 0..1 CodeableConcept|Reference(Group) with ObservationDefinition.subject 0..* CodeableConcept because ObservationDefinition defines kinds of observations on kinds of subjects, not actual Group subjects.

Initial application:
The request was applied in stages before this reconciliation. Git history shows the ObservationDefinition update commit 1872b9243b53a169bebb90fb52e09a217ea4b071 / 56b91f72c1e36104fa43f12c189891648867d5bd removed the subject[x] CodeableConcept|Reference(Group) choice and introduced ObservationDefinition.subject as CodeableConcept, initially 0..1. A later commit f4f1df7c14521468c7e7048ef896c6b4705f6ca4 changed the cardinality to 0..*, completing the Jira request.

Additional context:
ObservationDefinition is an active current-build resource in source/fhir.ini. The linked Zulip thread records the original concern that a Group reference did not make sense as a subject type and asks why the element was not 0..* code instead. OO minutes on 2020-12-17 record the same current/requested text and a 13-0-4 motion to accept the catalog block vote. The current source also has narrative saying Observation.subject should conform to one of the codeable concepts listed in ObservationDefinition.subject.

AutoFHIR reconciliation:
No source change was made. The current combined branch defines ObservationDefinition.subject as a non-choice element with min 0, max *, and type CodeableConcept, and a stale-reference check found no remaining subject[x] or Reference(Group) text in the authoritative ObservationDefinition StructureDefinition source.

Recommendation:
Keep this audit commit as-is. No follow-up core source work is needed for FHIR-28608 unless a future OO decision intentionally reopens ObservationDefinition.subject semantics.
