FHIR-20840: Audit repeated dependent invocation syntax

Issue request:
FHIR-20840 was Published/Persuasive for the FHIR mapping language and StructureMap. It observed that StructureMap.group.rule.dependent is 0..* but the language description and ANTLR grammar did not clearly document repeated dependent group invocations, and it requested comma-separated invocations after `then`.

Initial application:
FHIR-20840 was applied together with FHIR-20848 by commits 562bf9f82d7 and a81d5848a6, merged by PR #984 as b3a5ebd9c3. The application changed source/mapping-language.html so multiple groups may be separated by commas and changed images/mapping.g4 to allow repeated invocations. A later grammar refactor in db673c36e8 preserved the same repeatable groupInvocation form in the current dependentExpression rule.

Additional context:
StructureMap remains an active current resource, and the mapping-language page plus linked grammar are in the current build surface. FHIR-20848 is the same resolution family for allowing nested local rules after the invocation list. The only unresolved-looking part of the old shared resolution is the parenthetical execution-order wording; later FHIR-25220/FHIR-23010 evidence explains why new deterministic-order prose should not be added now.

AutoFHIR reconciliation:
This empty audit commit makes no source change. Current source already documents and parses repeated comma-separated dependent group invocations, and the active StructureMap model still has StructureMap.group.rule.dependent at 0..*.

Recommendation:
Keep this audit commit as-is. Revisit only if FHIR-I makes a new, explicit ordering decision for `then` group invocations; the repeated-invocation syntax itself is already correctly represented.
