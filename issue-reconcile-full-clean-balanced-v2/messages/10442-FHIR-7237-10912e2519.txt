FHIR-7237: Audit Observation f002 example corrections

Issue request:
FHIR-7237 was a Published/Persuasive OO change request from the 2015May ballot for FHIR-core Observation. It reported errors in the generated narrative for the base-excess Observation example: the numeric result used the abnormal/non-numeric interpretation code, included an injection-related detail, and showed lower-case display units beside UCUM codes in reference ranges. The final resolution pointed to 2015May core #270 and clarified that Quantity.unit can preserve a local display such as mmol/l while Quantity.code carries the standard UCUM form mmol/L.

Initial application:
The correction was applied before reconciliation. Commit 474be19befc8b8882da2b23a826dd0e2106a1538 explicitly listed 7237 and 7210 in its message, changed the f002 interpretation from A / "Abnormal (applies to non-numeric results)" to H / "Above high normal", and removed the injection/body-site details from source/observation/observation-example-f002-excess.xml. Later maintenance commits updated the display to "High" and moved the interpretation system to the current v3 ObservationInterpretation URL without reintroducing the reported problem.

Additional context:
The active [resources] section of source/fhir.ini includes observation=Observation, and source/observation/list-Observation-examples.xml plus source/observation/observation-examples-header.xml still publish observation-example-f002-excess as the Base Excess example. The linked FHIR-7210 issue contains the fuller duplicate report for the same example and resolution family. Current source intentionally retains Quantity.unit="mmol/l" with Quantity.code="mmol/L" for the value and reference range, matching the resolution's local-display-versus-UCUM-code distinction.

AutoFHIR reconciliation:
No source change was made. The current build source already uses interpretation H / High for a numeric result, has no injection/body-site content in the example, and represents the local display unit and standard UCUM code separately for the value and reference range.

Recommendation:
Keep this no-change audit commit as-is. Do not normalize the display unit to mmol/L for this issue unless the work group makes a new decision, because the published 2015 resolution explicitly preserves the two Quantity representations.
