FHIR-43446: Remove invalid Task Event doNotPerform mapping

Issue request:
FHIR-43446 was Applied with a Persuasive with Modification resolution for R6. The OO decision asked to align Task with the workflow Request and Event patterns by adding missing mappings for Task.statusReason, Task.focus, Task.input.value[x], Task.authoredOn, and Task.location, and by remapping Task.doNotPerform from the old Task.code relationship to Request.doNotPerform.

Initial application:
The issue was applied through PR #3719. Commit 816e404de8 added most of the requested Task workflow mappings, commit 496f78917f restored Task.status to Request.status plus Event.status and changed Task.doNotPerform away from Request.code/Event.code, and commit 0036c8e0c1 updated the Task Request/Event mapping exception files. That application left Task.doNotPerform mapped to both Request.doNotPerform and Event.doNotPerform even though the Event workflow pattern has no Event.doNotPerform element.

Additional context:
The current Task source is in build scope through active source/fhir.ini Task entries. OO WGM minutes for 2025-09-15/19 record the motion to approve the Task mappings as captured in the Jira comment, including the Event.recorded/AuthoredOn discussion, and no Zulip discussion was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit removes only the invalid Event.doNotPerform target from the Task.doNotPerform workflow mapping, leaving the approved Request.doNotPerform mapping and the other FHIR-43446 Task mappings intact.

Recommendation:
Keep this commit. It is a bounded correction to the applied FHIR-43446 mapping work: Task.doNotPerform now maps to the approved Request pattern element without claiming an Event pattern element that does not exist.
