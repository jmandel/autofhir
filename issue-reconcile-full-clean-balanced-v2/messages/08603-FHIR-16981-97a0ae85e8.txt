FHIR-16981: Audit Address physical-use clarification

Issue request:
FHIR-16981 was a Published/Persuasive STU3 change request for FHIR-core datatypes. It reported that the Address comment, "address is for postal addresses, not physical locations," appeared to contradict Address.type, which distinguishes physical visitable addresses from mailing addresses, and the approved resolution was to add a clarifying sentence.

Initial application:
The issue was applied in SVN revision 14323, represented in git by 12b8d31a18 "GF#16981 - clarifying sentence." That commit added Address.type comment text explaining that many applications track whether an address can be visited as well as used for delivery. A later same-family issue, FHIR-17722, changed the root Address note in 89b894c3a3 and was already reconciled on the combined branch by cad4329c7d.

Additional context:
source/fhir.ini lists Address in the active [types] section, so source/datatypes/address.xml is active datatype build source. The current Address definition/comment now says Address uses postal conventions for administrative purposes rather than absolute geographic coordinates, while postal addresses are often used as proxies for physical locations. Address.type still distinguishes physical, postal, and both. FHIR-17722 and FHIR-42765 are already represented on the combined branch and do not require a duplicate decision here. Zulip and Confluence searches found no conflicting community record.

AutoFHIR reconciliation:
No source change was made. The current source preserves the seed issue's intended clarification without the old contradiction: Address may describe visitable physical addresses through postal-address conventions, but it is not a coordinate/location-definition datatype.

Recommendation:
Keep this empty audit commit as-is. No further core source work is indicated for FHIR-16981 unless a future work group decision wants a broader Address/Location modeling change.
