FHIR-12471: Audit CapabilityStatement profile guidance

Issue request:
FHIR-12471 was a Published/Persuasive DSTU2 FHIR-core Conformance change request asking to improve wording that confused CapabilityStatement.profile with CapabilityStatement.rest.resource.profile. The request said the per-resource profile is a single common/system-wide denominator, while multiple use-case-specific profiles belonged in CapabilityStatement.profile, and it objected to a comment implying those profiles typically crossed resource types.

Initial application:
No current git commit with FHIR-12471 in the message was found. The Jira discussion records Grahame Grieve saying the clarification was already done, and the profiling page already contained a dedicated "Two uses of Profiles" section. Later applied work moved the old top-level CapabilityStatement.profile concept into CapabilityStatement.rest.resource.supportedProfile and refined the definitions, so the old CS.profile versus CS.resource.profile wording is no longer the current element shape.

Additional context:
FHIR-12829 formally moved CapabilityStatement.profile under CapabilityStatement.rest.resource as supportedProfile. FHIR-25462 later clarified the three CapabilityStatement profile-related use cases and updated the active definitions and profiling narrative. A later Zulip discussion led to unresolved FHIR-53641, which says the distinction could still be clearer, but that issue is Triaged/Unresolved and is not a final work-group decision to change the current source in this reconciliation.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Active build scope includes CapabilityStatement, and the authoritative source now distinguishes a single `.rest.resource.profile` system-wide profile from multiple `.rest.resource.supportedProfile` use-case-specific profiles, with both elements pointing to the profiling guidance. The obsolete sentence about typical supported profiles crossing resource types is not present in the current authoritative CapabilityStatement definitions.

Recommendation:
Keep this audit commit as-is for FHIR-12471. Any further clarification about strictness, requirements CapabilityStatements, or client/server interpretation should wait for FHIR-53641 or another final FHIR-I decision rather than being folded into this old Published tracker.
