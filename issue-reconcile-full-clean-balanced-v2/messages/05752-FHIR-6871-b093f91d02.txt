FHIR-6871: Audit investigation value set name

Issue request:
FHIR-6871 was a Published/Persuasive Patient Care technical correction for the DSTU1 ClinicalImpression artifact. It reported that ClinicalImpression.investigations.code was bound to investigation-sets while the binding appeared under the confusing "Condition/Diagnosis Certainty" name, and the accepted resolution was to change the value set binding name to "Investigation Type".

Initial application:
The issue was applied by git commit 28d24714bac4fb8fce6349a00eb3d18bf6e04637, whose message explicitly references #6871 and changes source/clinicalimpression/valueset-investigation-sets.xml from the condition-certainty URL/name/description to investigation-sets and "Investigation Type". Later metadata/OID cleanup commits normalized the XML to name="InvestigationType" and title="Investigation Type" without reversing the Jira decision.

Additional context:
FHIR-7718 is a Duplicate with the same ClinicalImpression.investigations.code report. FHIR-46596 later renamed ClinicalImpression to ClinicalAssessment and copied the investigation-sets value set with title="Investigation Type". The later fad1b9cf84 "remove additional resources" commit removed ClinicalAssessment from active source/fhir.ini build lists, and current core narrative links ClinicalAssessment to the PC incubator IG rather than building it as a core resource. FHIR-50411 later considered adding a type/code structure back to ClinicalAssessment.supportingInfo and was resolved No Change, so there is no later core decision requiring the historical investigations.code binding to be revived. Searches of Zulip and Confluence found only the implementation commit notification and no conflicting work-group/community evidence.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The requested value set naming correction is already present in the preserved ClinicalImpression source and in the later ClinicalAssessment source, while the current core build no longer has an active ClinicalImpression or ClinicalAssessment resource entry in source/fhir.ini. Remaining "Condition/Diagnosis Certainty" strings are the separate Condition certainty value sets, not the investigation-sets value set from this issue.

Recommendation:
Keep this audit commit as-is for FHIR core. No core follow-up is needed for FHIR-6871; if the external PC incubator ClinicalAssessment IG later needs reconciliation, verify that repository separately rather than editing the inactive core resource folder.
