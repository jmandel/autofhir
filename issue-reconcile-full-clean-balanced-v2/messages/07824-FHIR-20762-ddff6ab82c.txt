FHIR-20762: Audit SearchParameter URL discoverability

Issue request:
FHIR-20762 was Published/Persuasive with Modification for R5 and asked the SearchParameter registry to make the canonical URL for a resource/code search parameter easier to discover. The original suggestion was a type/code/url table with links to the SearchParameter resources; the accepted resolution said repeating the common URL base everywhere would be visually noisy, but the full URL could be exposed as a flyover.

Initial application:
No FHIR-20762-tagged implementation commit was found in the current repository history. The search parameter registry already had the canonical URL construction note before the Jira was filed, and current source keeps that note plus links to the XML and JSON SearchParameter bundle. The later Jira assignee comment says the remaining clinical-* URL concern had already been handled by using resource-specific SearchParameter URLs in source and that no source change was needed.

Additional context:
The registry is in current build scope: source/hierarchy.xml lists searchparameter-registry.html, and SearchParameter is an active resource/status entry in source/fhir.ini. Current source/searchparameter-registry.html tells readers that every canonical URL is http://hl7.org/fhir/SearchParameter/[id], with [id] taken from the table below. Source SearchParameter bundles use resource-specific ids/URLs such as Condition-patient for resource-specific parameters. FHIR-38728 is a later same-family discoverability issue, already represented on the combined branch, that links resource search pages back to the registry.

AutoFHIR reconciliation:
Made no source change and published this empty audit commit. Adding a redundant URL column or extra narrative restatement would work against the accepted resolution's concern about visual noise and would duplicate the existing canonical-URL construction rule. The current source already gives implementers a stable way to derive each full URL from the registry id, and the Jira's final application comment records no further change needed.

Recommendation:
Keep this audit commit as-is. If the work group still wants actual per-row hover text in generated registry output, track that as a new publisher/generation enhancement; it is not necessary to reconcile FHIR-20762 in the current source.
