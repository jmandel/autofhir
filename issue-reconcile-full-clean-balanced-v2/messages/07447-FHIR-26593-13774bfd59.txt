FHIR-26593: Audit contained-resource id constraint

Issue request:
FHIR-26593 is Published/Persuasive and requested a dom-3 update for DomainResource so that when a link points to a contained resource, the contained resource must have a non-empty id.

Initial application:
The issue was applied in git commit 60e802c6f260664a350604c66575dc13d299a1b6, which explicitly updated source/domainresource/structuredefinition-DomainResource.xml dom-3 to include id.exists() in the inbound-reference branch and adjusted the matching XPath. The Jira comment records that R4B application commit.

Additional context:
DomainResource is still in current build scope through source/fhir.ini [resource-infrastructure]. The current source has since been refactored by FHIR-43690 into the R6 expression using '#'+id.trace('id') against descendant references, while preserving the semantic requirement that an inbound contained-resource reference can only match a non-empty contained id. Confluence minutes show FHIR-I first noted that the FHIRPath already implied a #id requirement, then later accepted FHIR-26593 as a technical correction. FHIR-56263 reports a separate unresolved R6 dom-3 precedence concern about the branch for contained resources that refer back to the container; that open issue should not be resolved under this seed.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active DomainResource source already carries dom-3 on DomainResource.contained and the current inbound-reference test still requires a contained id before a '#id' reference can satisfy the invariant.

Recommendation:
Keep this audit commit as-is for FHIR-26593. Track any future source correction for the broader dom-3 R6 precedence report under FHIR-56263 or another work-group-approved issue, rather than reopening this already-applied id-constraint tracker.
