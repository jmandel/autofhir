FHIR-12226: Audit _type search example correction

Issue request:
FHIR-12226 was a Published/Persuasive FHIR-core technical correction for the search page. It asked to fix the _type example under the type-of-resource search section because `GET [base]/Observation?_type=Observation,Condition&other params...` incorrectly scoped a multi-type search under the Observation type endpoint; the accepted form was `[base]/?_type=Observation,Condition&other params...`.

Initial application:
The Jira comments record svn @10123. In the current git history this is commit 785a04a465032908316dcf4741f24a769c6c194b, whose message includes `#12226 Fix typo in search specification for _type parameter`; comparing that commit with its parent shows the example changed from `GET [base]/Observation?_type=Observation,Condition&other params...` to `GET [base]/?_type=Observation,Condition&other params...` in source/search.html.

Additional context:
The same typo family also appears in FHIR-11085, which was later marked already fixed, and FHIR-12148 separately formalized cross-resource searches on the base endpoint. The current source/search.html _type section uses `GET [base]/?_type=Observation,Condition&patient=Patient/123`, and source/http.html also shows cross-resource search as `GET [base]?_type=Condition,Observation...`. Exact community searches found only Jira/commit notification traces for FHIR-12226 and no Confluence decision that conflicts with the source/history conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build source no longer contains the resource-qualified typo from FHIR-12226, and the surrounding current prose still conveys that _type filters resource types in searches across multiple resource types while other search parameters must be valid for all selected types.

Recommendation:
Keep this empty audit commit as-is. No follow-up source work is needed in core for FHIR-12226; any broader review of cross-resource search behavior belongs to the separate FHIR-12148 issue family rather than this typo correction.
