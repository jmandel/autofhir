FHIR-17258: Audit historical operation removal

Issue request:
FHIR-17258 was a Published/Persuasive STU3 change request asking whether operations such as $validate could be invoked on a specific historical resource version endpoint like Patient/1/_history/4. The approved resolution removed support for operations on historical resource versions until a use case emerges.

Initial application:
The Jira comment cites svn revision 13893, which maps to git commit d53fc1417c5b0fecc727dc1733c548ac2c07548b. That commit changed source/operations.html from four endpoint types to three by commenting out the specific-version endpoint bullet, and added the ballot/history note that support for operations on historical resources was removed.

Additional context:
The current operations narrative still says operations can be invoked on three endpoint types and the only remaining _history operation bullet is inside the 2018 HTML comment. Current source searches found no active meta-add/meta-delete OperationDefinition in core and no operation invocation examples under _history version URLs. The remaining history/delete-history text in source/http.html concerns RESTful history interactions, not operations, so it is outside this issue's removal scope. Negative Zulip and Confluence searches found no later community evidence changing the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build source already implements the issue: operations are limited to base, type, and instance endpoints, and historical version operation support is not rendered as normative current text.

Recommendation:
Keep this audit commit as-is. Removing the commented legacy bullet would be optional source cleanup rather than a necessary specification correction, so it should not be part of this reconciliation.
