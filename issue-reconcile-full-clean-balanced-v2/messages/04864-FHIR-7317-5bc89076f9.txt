FHIR-7317: Clarify EOB item diagnosis order

Issue request:
FHIR-7317 was a Published/Persuasive with Modification FM change request for FHIR-core Claim. It asked how diagnosisLinkId ordering should work at line items, and the final modified resolution said Claim.item.diagnosisLinkId and EOB.item.diagnosisLinkId are lists that should be created in order of decreasing relevance, with the resource element definitions updated to reflect that rule.

Initial application:
No explicit FHIR-7317-tagged source commit was found. Current source had the old diagnosisLinkId elements represented as diagnosisSequence lists, and the companion FHIR-7318 reconciliation commit applies the same order rule to Claim.item.diagnosisSequence. Before this commit, the active ExplanationOfBenefit item diagnosisSequence element still lacked any orderMeaning, so the EOB half of the FHIR-7317 resolution was not visible in current conformance source.

Additional context:
FHIR-7318 is the same line-item diagnosisLinkId ordering issue family and supports applying the rule to the current Claim-family model. FHIR-7319 separately clarifies that diagnosis.sequence is a local reference identifier and not global primary/secondary diagnosis ranking; that remains compatible with FHIR-7317 because this change only defines the order of diagnosis references attached to one service or product. source/fhir.ini lists ExplanationOfBenefit as an active FM resource and maps historical ExplanationOfBenefit.item.diagnosisLinkId to the current ExplanationOfBenefit.item.diagnosisSequence element.

AutoFHIR reconciliation:
This commit adds orderMeaning to the active ExplanationOfBenefit StructureDefinition element ExplanationOfBenefit.item.diagnosisSequence, stating that diagnosis sequence references are listed in order of decreasing relevance to the service or product. No generated diagram-only artifacts were edited.

Recommendation:
Keep this source fix with the companion FHIR-7318 Claim fix. Together they implement the later narrowed same-family decision for the active Claim and ExplanationOfBenefit sources without introducing a obsolete diagnosis-link backbone.
