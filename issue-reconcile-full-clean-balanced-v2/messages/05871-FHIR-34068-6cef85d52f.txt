FHIR-34068: Audit DiagnosticReport media data linkage

Issue request:
FHIR-34068 was a Published FHIR-core DiagnosticReport change request resolved as Persuasive with Modification for R5. Clinical Genomics needed a generic way for DiagnosticReport to refer to DocumentReference resources for generated files such as VCFs; OO decided to expand DiagnosticReport.media from image-only wording to image-or-data wording, update media.comment accordingly, and adjust local media guidance.

Initial application:
The Jira comment records that the change was added to the build with commit e041968cbe8b6a3343953f751b2b5f6f0cc11567 from HL7/fhir#1507. That commit changed source/diagnosticreport/structuredefinition-DiagnosticReport.xml and source/diagnosticreport/diagnosticreport-introduction.xml to say "Key images or data", "image or data", and "Reference to the image or data source" while retaining DiagnosticReport.media.link as Reference(DocumentReference).

Additional context:
DiagnosticReport is an active current-build resource in source/fhir.ini. Earlier FHIR-19734 established that DiagnosticReport.media.link should allow DocumentReference and was closed as fixed in R5. Later FHIR-48391 added DocumentReference to DiagnosticReport.supportingInfo.reference for a separate R6 supporting-information use case, but it does not supersede the media wording requested by FHIR-34068. The Clinical Genomics Zulip discussion and OO minutes support the same conclusion: broaden R5 DiagnosticReport.media as the long-term core path for genomics files while avoiding R4 backport overreach.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current combined branch already has DiagnosticReport.media, media.comment, media.link, and the DiagnosticReport introduction text using image-or-data wording, media.link still targets DocumentReference, the R5 publication surface contains the same FHIR-34068 wording, and a targeted stale-text search found no remaining active DiagnosticReport XML or narrative source using the old image-only media labels.

Recommendation:
Keep this no-change audit as the reconciliation for FHIR-34068. No core source follow-up is needed for this issue; future work on DiagnosticReport.supportingInfo or genomics IG guidance should remain in their own Jira tracks.
