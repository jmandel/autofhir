FHIR-5926: Audit MedicationStatement invariant history

Issue request:
FHIR-5926 was a Published/Persuasive Pharmacy correction for DSTU1 MedicationStatement. It said two invariants were declared on child contexts where their XPath expressions were evaluated against MedicationStatement, and the reasonForUse[x] XPath needed wildcard local-name handling rather than exists(reasonForUse[x]).

Initial application:
The issue was applied in svn/git commit daa466d3dbfb73541c84cf9e72cb74ee69e107a8 (#5926, svn @6683), which changed the MedicationStatement spreadsheet invariants to use Context = MedicationStatement and changed the reasonForUse XPath to starts-with(local-name(.), 'reasonForUse'). A later expression cleanup commit kept those corrected contexts while normalizing FHIRPath expressions.

Additional context:
MedicationStatement remained an active current-build resource in source/fhir.ini, but the relevant DSTU1/STU2 elements and invariants were later revised by FHIR-12470/TR#12470 and then removed by FHIR-14023/GF#14023 as MedicationStatement aligned to the Workflow Event pattern. Current source/medicationstatement/structuredefinition-MedicationStatement.xml has no MedicationStatement constraints/invariants and no reasonNotTaken, wasNotTaken, or reasonForUse[x] elements; it now uses MedicationStatement.reason and MedicationStatement.adherence.reason instead. Jira/Zulip/Confluence searches found no later community record requiring the old invariant behavior to be restored.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The original defect was applied in historical spreadsheet source, and the current active StructureDefinition has moved past the affected elements and constraints, so adding or reintroducing an invariant would be incorrect.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-5926 unless a separate work-group decision asks to add new MedicationStatement constraints to the current reason/adherence model.
