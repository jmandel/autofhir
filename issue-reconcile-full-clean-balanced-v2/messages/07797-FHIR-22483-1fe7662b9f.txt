FHIR-22483: Use DICOM-published CID-29 value set

Issue request:
FHIR-22483 was a Published/Persuasive FHIR-I change request asking the core build to use DICOM-published FHIR CodeSystems and ValueSets, with DICOM CID-29 as the example, instead of relying on FHIR-maintained copies or stale fhir.ini handling.

Initial application:
The issue itself does not appear in a source commit message. The closest applied implementation is the DICOM terminology family work represented by FHIR-24908 and commit 26f1439636ec3a00a96ffe742b9f5cba1ac1a8ba, which switched ImagingStudy and AuditEvent-related terminology to DICOM-authored value sets and removed several local hand-written DICOM value set files. That application did not cover source/composition/valueset-doc-event-code.xml, which still imported the old FHIR-hosted http://hl7.org/fhir/ValueSet/dicom-cid29 value set in the current branch.

Additional context:
The linked Zulip topic records John Moehrke asking on 2019-05-20 whether fhir.ini should point to DICOM-published FHIR resources, Grahame Grieve asking him to file a task, and later discussion confirming that DICOM uses the chtml CID page URLs as the ValueSet canonicals. FHIR-I minutes on 2022-08-22 record FHIR-22483 as Persuasive 13-0-0. Current fhir.ini lists Composition as an active resource, so source/composition/valueset-doc-event-code.xml is in current build scope. The parallel source/media/valueset-media-modality.xml occurrence is in the dropped Media resource folder, with Media absent from the active [resources] list and present only as a commented dropped FMG entry, so it is not a current-spec hunk for this reconciliation. The remaining valueset-dicom-dcim fixup entry has no current source definition or local DICOM value set file to update.

AutoFHIR reconciliation:
This commit replaces the active Composition example value set's stale FHIR-owned dicom-cid29 import with DICOM's published CID-29 canonical URL, matching the DICOM package artifact for Acquisition Modality and the earlier unlanded broken-link fix pattern.

Recommendation:
Keep this source fix. If future work removes the dropped Media source folder or the historical valueset-dicom-dcim fixup, handle that as cleanup under a separate build-configuration or retired-resource task rather than broadening this active Composition terminology correction.
