FHIR-46425: Audit superseded ServiceRequest copy-to request

Issue request:
FHIR-46425 was an Applied/Persuasive R6 OO change request asking to add ServiceRequest.additionalRecipient and update ServiceRequest.requester guidance so requesters could name additional result recipients.

Initial application:
The request was initially applied in git commit 4a989ec22d019ba21c4b07cffa34088127162f46 and merged by PR #3263, adding ServiceRequest.additionalRecipient plus requester-comment text that pointed implementers to that new element.

Additional context:
FHIR-49694 later reached Applied/Persuasive with Modification and explicitly voted to revert the FHIR-46425 changes. The current build-scope source has ServiceRequest active in source/fhir.ini, has no ServiceRequest.additionalRecipient element, and now points additional result-recipient workflow to CommunicationRequest. Zulip and OO minutes show the original concern: a bare list of additional recipients was too underspecified for copy-results workflows that may need reason, conditions, communication mode, and downstream routing.

AutoFHIR reconciliation:
No source change was made. The current source is intentionally different from the original FHIR-46425 request because the later FHIR-49694 decision superseded it, so re-adding ServiceRequest.additionalRecipient would make the current specification wrong.

Recommendation:
Keep this audit commit as-is and do not re-add ServiceRequest.additionalRecipient unless a new work-group decision reverses FHIR-49694. The current copy-results guidance should continue through CommunicationRequest and any IG-specific workflow guidance.
