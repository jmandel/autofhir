FHIR-19304: Audit inherited-element rendering ownership

Issue request:
FHIR-19304 is Published/Persuasive for FHIR-core STU3 and asked the rendered structure tables to make inherited Resource/DomainResource elements more prominent by moving the "Elements defined in Ancestors" list out of the root row description column, changing it to "Inherited elements not included below", and doing the same for datatype pages that inherit Element elements.

Initial application:
Jira records Grahame's application note as GH#dbe102bb95, but that short hash is not present in the current HL7/fhir history or GitHub commit lookup. Current rendered build pages still emit the old "Elements defined in Ancestors" text in the Description & Constraints cell, so the requested rendering behavior is not represented in the current publication surface from core source alone.

Additional context:
FHIR-18335 was the related ballot comment resolved no-change because the behavior was out of ballot scope; FHIR-I minutes explicitly created FHIR-19304 as the separate follow-up tracker. The current FHIR build invokes org.hl7.fhir:kindling, and the active renderer implementation is in HL7/kindling TableGenerator.java, which still appends "Elements defined in Ancestors" to the root element description cell. A later Zulip publisher thread also identifies ancestor-element display as a publisher issue.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR source change and records an external-repo decision. Editing checked-in generated-looking snippets or one resource note in this checkout would not fix the all-resource/all-datatype renderer behavior requested by FHIR-19304; the durable fix belongs in the external Kindling publisher/renderer and then requires a core rebuild.

Recommendation:
Keep this audit commit as-is for the core reconciliation. Follow up in HL7/kindling, especially src/main/java/org/hl7/fhir/definitions/generators/specification/TableGenerator.java, to move the inherited-element list above the generated table/root row and change the label consistently for resource and datatype renderings before rebuilding FHIR core.
