FHIR-20602: Audit Procedure recorded timing change

Issue request:
FHIR-20602 was Published with a Persuasive with Modification resolution for STU3/R5 Patient Care feedback. It asked about adding recorded timing support for MedicationAdministration.notGiven and Procedure.notDone and whether Period is a default timing type. The final core resolution added Procedure.recorded as 0..1 dateTime with the requested short/definition and a workflow Event.recorded mapping, and stated that FHIR base does not default a data type for choice elements; profiles can constrain types when needed.

Initial application:
The change was applied in git by cff3828142, merged as 88c604c66b028201ee797438b5154f3366ee7ec0, in the old Procedure spreadsheet source. That commit added Procedure.recorded with dateTime type, the requested short text, an Event.recorded workflow mapping, and retained Procedure.occurrence[x] as an explicit choice type list rather than introducing a default type. The later source refactor 33b409a4b6 moved these definitions into source/procedure/structuredefinition-Procedure.xml.

Additional context:

MedicationAdministration already has occurrence[x] with explicit dateTime, Period, and Timing types plus its own recorded element. FHIR-24938 is already represented on the combined branch, so this commit does not duplicate that decision.
