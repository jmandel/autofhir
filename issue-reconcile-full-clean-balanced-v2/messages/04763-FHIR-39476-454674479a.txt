FHIR-39476: Audit bdl-7 invariant revision

Issue request:
FHIR-39476 was a Published/Persuasive FHIR-I change request for R5 asking to revise Bundle invariant bdl-7. The reported problem was that `entry.where(fullUrl.exists()).select(fullUrl&resource.meta.versionId).isDistinct()` treated absent `meta.versionId` values as empty collections and therefore effectively forced resources with duplicate fullUrls to carry version ids rather than only distinguishing entries when version ids are present.

Initial application:
The issue appears to have been applied before this reconciliation by git commit 4a5d9b44614a286ad703b525a850b8464f4978b1, `FHIR-39476 bdl-7 needs revision`, which changed `source/bundle/structuredefinition-Bundle.xml` from `fullUrl&resource.meta.versionId` to `fullUrl&iif(resource.meta.versionId.exists(), resource.meta.versionId, '')`. The current source still contains that expression, and the commit is contained in the v5.0.0 tag.

Additional context:
`source/fhir.ini` lists Bundle as an active resource and assigns it to the infrastructure work group, so `source/bundle/structuredefinition-Bundle.xml` is in current build scope. FHIR-I January 2023 WGM minutes record FHIR-39476 as Persuasive with a 13-0-3 motion, matching the Jira resolution. A November 2022 Zulip IG creation thread shows the validation problem that led to Grahame filing the Jira. Jira neighborhood search found older bdl-7 history issues, including FHIR-15649 and FHIR-18284, but no later final issue that changes this R5 correction.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Bundle invariant already implements the requested correction in the authoritative active source, and adding another source hunk would be redundant.

Recommendation:
Keep this audit commit as-is. No core FHIR source follow-up is needed for FHIR-39476 unless a future issue reopens bdl-7 semantics beyond the already-applied missing-versionId correction.
