FHIR-13409: Audit JSON charset parameter guidance

Issue request:
FHIR-13409 was Published/Persuasive with Modification for the FHIR-core HTTP page. It asked that JSON FHIR responses not be required to include `charset=utf-8` in the Content-Type header because UTF-8 is already implied for JSON, while retaining clear UTF-8 guidance for other formats.

Initial application:
The issue appears to have been applied in the HTTP narrative by commit 4b3c2b6858b70b4b2342c48ac651412b5ebf7e8e, matching the Jira comment's December 2017 SVN application window. That commit changed the old universal SHALL for an explicit charset parameter to SHOULD for XML/Turtle and MAY for JSON/ND-JSON in source/http.html.

Additional context:
The current source/http.html page is active build narrative through source/documentation.html. A later Published/Persuasive issue, FHIR-16343, found the old HTTP default-character-set rationale incorrect and commit eaa7a5f5e9ab41d2c4a9088649e5dc1f2f8e9f23 replaced the split XML/Turtle-vs-JSON charset-parameter paragraph with generic UTF-8 guidance and an optional MIME-parameter statement. FHIR-35811 later clarified that this generic wording is about FHIR instances and not a standalone application/fhir media type. The JSON format page separately states that JSON character encoding is always UTF-8.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current spec already allows `application/fhir+json` without an explicit charset parameter, preserves the rule that FHIR instances use UTF-8, and reflects later Published issues that removed the obsolete HTTP default-charset premise. Reintroducing the older split charset-parameter language would conflict with those later decisions rather than better applying FHIR-13409.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed unless the work group makes a new decision to distinguish charset-parameter requirements by serialization format again.
