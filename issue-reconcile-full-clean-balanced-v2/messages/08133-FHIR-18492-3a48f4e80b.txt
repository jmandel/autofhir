FHIR-18492: Audit Narrative definition update

Issue request:
FHIR-18492 is a Published/Persuasive FHIR-core narrative issue raised against STU3. It asked to replace the Narrative type definition "A human-readable formatted text, including images" with a human-readable summary definition conveying the essential clinical and business information for the resource, and to keep the image allowance in comments rather than in the primary definition.

Initial application:
The Jira comment points to GH#9cad63bc63. Commit 9cad63bc639139c7a04b8c84407de26df7654128 changed source/datatypes/narrative.xml by replacing both the Narrative short description and formal definition with the accepted summary/essential-clinical-and-business wording. The existing Narrative.div comment already described XHTML image allowance, so the implementation did not add a separate root Narrative comment.

Additional context:
Narrative remains active current-build source: source/fhir.ini lists Narrative as an infrastructure type, maps narrative/xhtml to narrative.html, marks Narrative normative, and assigns its txt abbreviation. Current narrative guidance already says that non-empty narrative SHALL reflect all content needed for a human to understand the essential clinical and business information. The generated CI definitions page and narrative.profile.json display the accepted Narrative definition and the Narrative.div image comment. Earlier FHIR-9826 established the essential clinical/business narrative scope, and FHIR-17463 later refined the normative wording on the narrative page; neither changes the FHIR-18492 conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source and generated CI output already reflect the accepted replacement definition, and the image allowance is present in the comments/guidance for Narrative.div rather than being retained in the root definition.

Recommendation:
Keep this no-change audit commit. No FHIR source edit is needed for FHIR-18492; future changes to narrative safety or image rules should be handled as separate narrative-page or XHTML-content decisions rather than by reverting the Narrative root definition.
