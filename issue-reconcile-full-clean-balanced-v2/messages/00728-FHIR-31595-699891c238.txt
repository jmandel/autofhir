FHIR-31595: Align PaymentNotice boundary wording

Issue request:
FHIR-31595 was Applied/Persuasive with Modification for R6 by FM. It asked why PaymentNotice.payment was mandatory when a PaymentReconciliation might not exist, and the accepted disposition clarified that PaymentNotice indicates that payment has been initiated, added explanatory resource-page text, and called for related financial content to be reviewed.

Initial application:
The Jira-tagged commit c3ac965d8195fc72c7421f3b12660e95ad0a1119 applied the PaymentNotice resource-page wording change and header explanation. Separately, the R5 FHIR-40448 implementation commit 2be1440043170cc0df19d0f270235e5d232d262d changed PaymentNotice.payment from 1..1 to 0..1, so the current StructureDefinition no longer makes the payment reference mandatory. The PaymentReconciliation boundary page still carried the old PaymentNotice description using "has, or is about to occur" and the old related-resource table wording.

Additional context:
PaymentNotice and PaymentReconciliation are both active resources in source/fhir.ini, so their narrative boundary pages are current-build source. R4 published PaymentNotice.payment as 1..1, while R5 and build.fhir.org show it as 0..1. An intermediate Jira comment proposed allowing Reference(PaymentNotice | PaymentReconciliation), but the current R5/R6 source trail resolved the mandatory-reference concern through optionality and did not add a PaymentNotice self-reference target. Later FHIR-53918 is a separate Resolved - change required clarification for PaymentNotice introductory prose and was not decided in this default Applied/Published reconciliation.

AutoFHIR reconciliation:
This commit updates the active PaymentReconciliation narrative so its PaymentNotice boundary paragraph and related-resource table use the same "payment has been initiated" wording as the already-applied PaymentNotice page. It intentionally makes no StructureDefinition change because PaymentNotice.payment is already optional in the current source, and adding a new target profile would be a separate semantic expansion not required to reconcile this seed.

Recommendation:
Keep this source fix. FHIR-31595 is now consistently reflected across the active PaymentNotice and PaymentReconciliation boundary narratives; separate later PaymentNotice editorial/search-parameter issues should be handled by their own applied-change workflow.
