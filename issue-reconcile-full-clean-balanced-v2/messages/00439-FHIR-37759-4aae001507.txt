FHIR-37759: Audit GenomicStudy data format binding

Issue request:
FHIR-37759 is a Published Clinical Genomics R5 change request resolved Persuasive with Modification. It asked for terminology support on GenomicStudy.analysis.input.type and GenomicStudy.analysis.output.type, with an example binding to a new data-format CodeSystem/ValueSet populated from genomic file-format examples such as IGV/Broad Institute formats.

Initial application:
The issue was first partially applied in commit 5f1e5c87e79e by adding inline examples to the input and output type definitions. The full terminology application followed on the genomicStudy_terminologyBinding branch and was merged by PR #2116 in ff7c5cbbec68, including the genomicstudy-dataformat CodeSystem, the genomicstudy-dataformat ValueSet, and example bindings on both GenomicStudy.analysis.input.type and GenomicStudy.analysis.output.type.

Additional context:
The current retained GenomicStudy source still has both example bindings to http://hl7.org/fhir/ValueSet/genomicstudy-dataformat, and the R5 published StructureDefinition exposes the same bindings. Current source/fhir.ini no longer includes GenomicStudy in the active resource build after the 2025 "remove additional resources" change, so editing the retained GenomicStudy source would not be a current-build correction. Confluence CG minutes and the genomics Zulip thread show the same terminology-binding discussion and block-vote path.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The requested R5 change is already present in the retained source and published R5 artifact, and the artifact is outside the current core build scope.

Recommendation:
Keep this audit commit as-is. Do not edit the inactive core GenomicStudy source for this issue unless GenomicStudy is reintroduced to the current build; if that happens, the existing data-format CodeSystem, ValueSet, and element bindings should be preserved.
