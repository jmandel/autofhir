FHIR-7907: Audit RESTful underscore guidance

Issue request:
FHIR-7907 was a Published/Persuasive DSTU1 FHIR-core change request asking for explicit documentation of why RESTful interactions and parameters use leading underscores, including examples such as _history, _search, _format, _count, and _since.

Initial application:
The Jira comment records SVN revision 5534. The corresponding git-svn commit 4f363ad0bd1afafaa97da59cb1cee0d469fcf2ef explicitly includes "#7907 - explain RESTful special characters" and added RESTful API prose explaining underscore-prefixed names on source/http.html. Later source history corrected typos and refined the first sentence without removing the approved explanation.

Additional context:
The current source/http.html page is the active RESTful API narrative source and now says the specification uses underscores to disambiguate names in three cases: system-wide history/search from resource-type interactions, search/history interactions from resource instances, and all-resource search parameters from type-specific search parameters. The current search.html page separately describes search result parameters such as _count, _include, _revinclude, _sort, _summary, and _total as specification-defined result modifiers rather than SearchParameter resources. Searches of Zulip and Confluence found no directly relevant discussion or conflicting later work-group record. Later FHIR-50847 only removed the potentially misleading phrase "reserved names from other names", preserving the FHIR-7907 convention.

Recommendation:
Keep this no-change audit commit as-is. No follow-up is needed for FHIR-7907 unless the work group wants a new, separate policy change to the RESTful naming convention.
