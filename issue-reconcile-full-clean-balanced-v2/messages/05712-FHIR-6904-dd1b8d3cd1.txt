FHIR-6904: Audit Questionnaire answer list guidance

Issue request:
FHIR-6904 was a Published, Not Persuasive with Modification DSTU1 Questionnaire issue asking why simple answer lists appeared to require extensions. The approved resolution said answer lists were handled by the core question.options element and that the specification should explain how to embed a ValueSet inside a Questionnaire where appropriate.

Initial application:
The issue appears to have been applied in SVN revision 5941, imported as git commit 26e8b597d5034f4372a848e5660a88268f4b664c. That commit explicitly listed #6904 and added the Questionnaire notes section on permitted values for questions, including use of contained ValueSet resources.

Additional context:
Questionnaire remains an active resource in the current build. Later Questionnaire work, including FHIR-15934/GF#15934, renamed the old options/option elements to the current answerValueSet and answerOption names. The current source therefore uses modern names while preserving the substance of the FHIR-6904 resolution: simple inline answers are core via answerOption, value-set-based answers are core via answerValueSet, and locally maintained value sets can be contained in the Questionnaire. Direct Zulip and Confluence searches found no conflicting community guidance.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current source already contains the requested explanation and the relevant core element definitions, so adding more text would be redundant and would not change implementer understanding.

Recommendation:
Keep this no-change audit commit as-is. No follow-up core FHIR source work is needed for FHIR-6904 unless a future work group decision changes Questionnaire answer-list modeling.
