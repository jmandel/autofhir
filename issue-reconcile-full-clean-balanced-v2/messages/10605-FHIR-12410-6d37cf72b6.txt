Issue request:
FHIR-12410 was a Published/Persuasive DSTU2 FHIR-core tooling change request reporting confusing IG Publisher behavior: no helpful error when the -ig argument was omitted, and NullPointer failures when the publisher was run from the same directory as the IG file.

Initial application:
The Jira comments say the issue was applied in SVN revision 10443. The migrated Git commit b7a5e37e50140d046c1b27c553611451d9e06f27 is exactly that revision and changed tools/java/org.hl7.fhir.igtools/src/org/hl7/fhir/igtools/publisher/Publisher.java to throw an explicit "No Implementation Guide Specified (-ig parameter)" exception when -ig is absent and to normalize the configured IG path.

Additional context:
The affected old in-tree IG Publisher source is no longer present in the current FHIR specification checkout. Commit 56ceb0df08dd72381a4f98f1ea4ac5ea6d139a8b removed tools/java/org.hl7.fhir.igtools with the summary "Remove IG publisher (it's gone to Maven)." Current Gradle configuration depends on org.hl7.fhir:kindling and runs org.hl7.fhir.tools.publisher.Publisher from that dependency, so executable publisher behavior is not maintained in the current core source tree. Jira search found only FHIR-12410 for the exact key/IG Publisher terms, and direct Zulip/Confluence searches found no community record that changes the Jira/git conclusion.

AutoFHIR reconciliation:

Recommendation:
