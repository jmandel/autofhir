FHIR-16448: Audit conditional-operation normativity

Issue request:
FHIR-16448 was a Published FHIR-I change request for the RESTful API HTTP page asking whether conditional delete was mature enough to be normative. The final Persuasive with Modification resolution broadened the decision to make conditional create, update, and delete non-normative at that time.

Initial application:
The Jira comment records SVN revision 14206. Git commit 051eb59d8749d2453417410ed7d2d55ec1f19a1a, "GF#16448 + GF#17256 - conditional operations status," applied the decision by wrapping conditional update, conditional patch, conditional delete, and conditional create content in draft-content and adding trial-use warning text.

Additional context:
FHIR-17256 was applied in the same 2018 commit for conditional patch behavior. Later, Applied FHIR-42728 explicitly decided for R6 to remove the Trial Use tags from conditional interaction content and CapabilityStatement REST resource elements because the interactions had existed since DSTU2, and to add conditional interaction codes to the RESTful interaction code system. FHIR-I 2023-11-06 minutes record the FHIR-42728 block-vote approval, and current source reflects that later decision.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The current build-scope HTTP page is normative as a page and no longer marks conditional create, update, patch, or delete as trial-use; the RESTful interaction code system is normative and contains create-conditional, update-conditional, patch-conditional, delete-conditional-single, and delete-conditional-multiple; and CapabilityStatement.rest.resource interaction and conditional support elements no longer carry trial-use status overrides for these interactions.

Recommendation:
Keep this audit as-is. Do not reintroduce the STU3-era non-normative markers for FHIR-16448 unless the work group opens a new issue reversing the later FHIR-42728 R6 decision.
