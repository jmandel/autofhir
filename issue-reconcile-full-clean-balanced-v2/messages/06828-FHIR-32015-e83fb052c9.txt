FHIR-32015: Fix operation Bundle.type example

Issue request:
FHIR-32015 was Published with a Persuasive with Modification resolution for R5. The issue asked to correct the operations framework text that said a Bundle response's Bundle.type was collection unless it had search semantics, because operations such as Composition $document can return a document Bundle.

Initial application:
The issue was initially applied by git commit 5d7c5faef3 ("FHIR-32015 Bundles returned from operation are not always collection"), which changed source/operations.html to say Bundle.type is typically collection but could be other types. That application left the search-semantics example with a typo, an unclosed paging link, and a broken/mis-spelled searchset code link.

Additional context:
source/operations.html is an active source page referenced by publish.ini and source/hierarchy.xml. Jira and FHIR-I minutes record the approved "will fix" decision, and the Zulip thread that led to the issue confirms the problem was the general operations wording incorrectly excluding $document's document Bundle response. Later $document-specific issues such as FHIR-19974 and FHIR-32016 are related background, but they concern the Composition OperationDefinition and are not separate decisions in this reconciliation.

AutoFHIR reconciliation:
This commit keeps the existing semantic clarification and fixes only the defective applied example in source/operations.html: "For example" is spelled correctly, the paging link is closed before the comma, and the example Bundle.type now links to and displays the actual Bundle type code searchset.

Recommendation:
Keep this source fix. It is a narrow correction to the already-approved FHIR-32015 wording, removes a broken link in a built operations page, and does not reopen the later $document-specific operation-definition decisions.
