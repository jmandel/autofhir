FHIR-7712: Audit specification search already enabled

Issue request:
FHIR-7712 was a Published/Persuasive FHIR-I change request from the 2015 May core ballot asking to provide search capability across the FHIR DSTU and FHIR Continuous build sites, specifically so implementers and ballot reviewers could find content such as v3 mappings with the attribute isNormal. The issue was voted 7-0-1, applied for DSTU1, and later received Grahame Grieve's comment that it was already done.

Initial application:
No source commit explicitly tagged FHIR-7712 was found. The historical application appears to have been operational/site-level: a 2017 Zulip thread records Grahame Grieve announcing that search on the specification was working again at hl7.org/fhir/search.cfm, and later source history added source/search-build.html as the active CI search page. A closely related Published/Persuasive issue, FHIR-8151, is already represented on the combined branch by a source-changing reconciliation that routes current home-page and shared-footer search links through the build's search-location target.

Additional context:
FHIR-7712 is part of a small repeated ballot-comment family: FHIR-8151 and FHIR-6849 made the same search-capability request from other ballot contexts, and FHIR-7748 was marked Duplicate with the same text. FHIR-11438 later asked that the 2016 September search page be enabled and is already represented on the combined branch by a no-change audit. Current source includes an active DuckDuckGo-backed CI search page in source/search-build.html, lists that page in source/hierarchy.xml and publish.ini, and uses [%search-location%] from the navbar, home page, and footer. The live CI search-build page renders the active search iframe, while the old search.cfm page is only a historical stub.

AutoFHIR reconciliation:
This audit commit makes no source change. Recommendation:
Keep this no-change audit. Treat FHIR-8151 as the source-changing reconciliation for this search-capability family, and handle any future live-site search endpoint problems under their own final Jira decisions rather than reopening this DSTU1 ballot request.
