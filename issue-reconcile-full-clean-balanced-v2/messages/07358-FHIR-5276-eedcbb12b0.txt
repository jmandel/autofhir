FHIR-5276: Replace stale Observation.name profiling examples

Issue request:
FHIR-5276 was a Published/Persuasive DSTU1 OO change request asking to rename Observation.name to Observation.code because the element carries coded observation identifiers such as LOINC or SNOMED CT codes, not a human-readable name.

Initial application:
The issue was initially applied in git commit d6259fa8e3beda8fd5e58ad54d85001f1efb9d42, whose message explicitly says "[#5276] - change Observation.name to Observation.code" and whose patch updated Observation examples, profiles, and source spreadsheets from name to code. Later source refactors left the active Observation StructureDefinition using Observation.code, with Observation listed as an active resource in source/fhir.ini and DeviceObservationReport listed only as removed.

Additional context:
A related Published technical correction, FHIR-9651, fixed one profiling.html sentence that still referred to a target resource "name" element; git commit b6a5fbd68ee31141b18a69a7a43fcbb2b85140b4 applied that exact correction. Current source still had nearby profiling/slicing examples that named the nonexistent Observation.name path and item.resolve().name discriminator while describing an Observation target. Zulip/Confluence searches found the FHIR-9651 missed-reference report and no conflicting work-group or community evidence.

AutoFHIR reconciliation:
Updated the active profiling narrative to use Observation.code.extension, Observation.code, and item.resolve().code in the affected slicing/discriminator examples. The authoritative Observation StructureDefinition already uses Observation.code, so no resource-definition change was needed.

Recommendation:
Keep this source fix. It removes the last discovered current-source references that would teach implementers to use Observation.name while preserving the intended profiling examples and the established Observation.code element name.
