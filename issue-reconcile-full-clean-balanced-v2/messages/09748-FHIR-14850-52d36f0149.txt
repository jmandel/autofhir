FHIR-14850: Audit batch HTTP response code guidance

Issue request:
FHIR-14850 was a Published/Persuasive with Modification STU3 FHIR-I change request for the RESTful API batch interaction. It asked for guidance on HTTP response codes for batch, and the accepted resolution was to clarify that the overall status is 200 OK when the batch was processed correctly, regardless of success of the operations within the batch, with per-operation status determined inside the returned Bundle.

Initial application:
The Jira comments record svn revision 13373. Git-svn commit e867cdb92d42d005171704c48e7d9f15667aff1a applied GF#14850 to source/http.html and added the batch-response-code paragraph. The original paragraph included the requested 200 OK and returned-Bundle guidance; a later adjacent sentence about entry failure semantics was subsequently corrected by FHIR-17776 and does not change the FHIR-14850 resolution.

Additional context:
source/http.html is in the current build as the active RESTful API page via source/hierarchy.xml. The current Batch Processing Rules still say the HTTP response code is 200 OK when the batch was processed correctly, regardless of individual interaction success, and direct readers to the returned Bundle for interaction-level status. FHIR-17776 is already represented on the combined branch and audits the adjacent per-entry non-2xx failure wording, so no duplicate related issue commit is needed. A 2021 Zulip implementers thread quotes and discusses this same rule without identifying a conflicting work-group decision; Confluence searches found no FHIR-14850 references.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active source already conveys the accepted FHIR-14850 rule, and changing it to add 201, 207, or 4xx guidance from the reporter's rejected proposal would conflict with the final resolution that a correctly processed batch receives an overall 200 OK while individual outcomes live in the response Bundle.

Recommendation:
Keep this audit commit as-is. No further core source work is needed for FHIR-14850 unless the work group later reopens the broader policy for whole-batch rejection versus entry-level failures.
