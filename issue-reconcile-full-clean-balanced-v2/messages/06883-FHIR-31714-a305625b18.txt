FHIR-31714: Audit clinical-patient target scope

Issue request:
FHIR-31714 is a Published/Persuasive FHIR-I technical correction, raised for R4B and applied for R5, reporting that the downloaded SearchParameter/clinical-patient resource had expanded SearchParameter.target to all resource types after FHIR-28219 when the target list should be limited to Patient.

Initial application:
The Jira comments state that the target types needed to be limited to Patient and that the problem affected all reference SearchParameters whose targets were constrained. Local git history shows the R4B/R5 application commits a96b79e23a892164f261dcf4c7868ec1ef8023e2 and b9ee4c1747a9d505eec4b76c41e26d95c5dd6a30, both titled "Ensure targets are declared on target-constrained SearchParameters - part of FHIR-31714", adding explicit target declarations across resource search-parameter bundles.

Additional context:
FHIR-28219 established the underlying rule that common patient searches should resolve only Patient, using Patient-filtered expressions where needed. FHIR-32876 later reported the same clinical-patient all-resource target expansion and was recorded in FHIR-I minutes as a duplicate of FHIR-31714; it already has a combined-branch no-change audit commit. The Zulip implementer thread confirmed the problem was in generated/downloaded targets and noted that R4B looked correct after the fix, while a later current-build regression was suspected in 2023.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. SearchParameter is active in source/fhir.ini. The current source/searchparameter/common-search-parameters.xml clinical-patient block lists the common bases without a Group or all-resource target assertion, current resource-level patient SearchParameters have no explicit non-Patient targets, and current build/R5/R4B search-parameters.json downloads all return SearchParameter/clinical-patient target ["Patient"].

Recommendation:
Keep this no-change audit. The current core source and generated publication surfaces already satisfy FHIR-31714; follow-up would only be needed if a future generator/build regression again expands clinical-patient.target beyond Patient.
