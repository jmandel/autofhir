FHIR-8032: Audit Provenance role bindings

Issue request:
FHIR-8032 was Published/Not Persuasive with Modification for the DSTU1 Provenance.entity.role concern that a required code looked inconsistent with related Provenance role/type elements. The resolution kept Provenance.entity.role constrained, changed Provenance.agent.role toward a more extensible/open binding, and requested a note explaining why entity-role was not extensible.

Initial application:
The Jira comments record application as SVN revision 6088. In the current migrated source, Provenance is an active resource, Provenance.entity.role remains a 1..1 code with a required binding to provenance-entity-role, and the committee note says no use cases have been identified for extensibility for this role. Provenance.agent.role is currently CodeableConcept with an example binding, so it is not constrained in the way that prompted the original inconsistency concern.

Additional context:
Later Security WG work changed the agent role/type model. FHIR-32520 was Published/Persuasive with Modification and explicitly says agent.role should not be extensible; it keeps agent.role as an example structural-role binding. A related Zulip thread also records the need to separate functional agent.type from structural agent.role. FHIR-55346 later addressed the remaining entity-role escape-valve concern by adding an other code to provenance-entity-role rather than changing Provenance.entity.role to Coding/CodeableConcept or loosening the required binding.

AutoFHIR reconciliation:
This is an empty no-change audit. No source edit is needed because the current active Provenance source preserves the FHIR-8032 entity-role note and code/required binding, while later final decisions explain why the old agent.role extensible wording should not be restored literally.

Recommendation:
Keep this audit commit as-is. Future work should not use FHIR-8032 to change Provenance.entity.role to Coding or to make Provenance.agent.role extensible; any further wording cleanup around the committee note after FHIR-55346 should be handled as a separate Security WG decision.
