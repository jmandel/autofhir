FHIR-14216: Audit Location near-distance merge

Issue request:
FHIR-14216 was a Published/Persuasive PA change request raised against STU3 Location. It said near-distance was not useful without a location and could not be safely matched during chained searching, and its resolution requested merging the search parameter pair so the distance stayed with the location in chained search use.

Initial application:
The explicit history uses the older GForge key rather than the Jira key: git commit 1d2f0c3e02b3ad1f21c8b3c4d8b88bce34fe9587, "GF#14216 location near parameter searching updates", replaced the STU3 example `near=latitude:longitude&near-distance=...` with `near=latitude|longitude|distance|unit`, updated the Location spreadsheet source, and added notes that the new format supports multiples and chaining while deprecating near-distance.

Additional context:
The committers Zulip thread for "Composite Search" records that this was first considered as a composite, but the implementer/editor discussion settled on a manually coded single search parameter because the distance is relative to the supplied point rather than a second resource element. A later implementers Zulip preview described the R4 format as a `special` type search parameter that works with multiples and chaining, with near-distance merged into the single parameter. FHIR-22749 later removed stale Location-near text saying near-distance was still required, and FHIR-27157/FHIR-33976 added unit and sorting clarifications without reviving a separate near-distance parameter.

AutoFHIR reconciliation:
This commit intentionally makes no source change. `source/fhir.ini` includes Location as an active resource, and the current active Location search parameter source defines only `Location-near` with syntax `[latitude]|[longitude]|[distance]|[units]`. The Location notes still explain that the STU3 syntax did not support multiples or chaining and that near-distance was deprecated by the new format. A current source search found no remaining near-distance requirement outside that historical deprecation note.

Recommendation:
Keep this audit commit as-is. Do not rewrite the current `near` parameter as a literal composite search parameter: the surviving source and later issue history show the intended current representation is the single `special` Location-near parameter with embedded distance and unit components.
