FHIR-41549: Restore QuestionnaireResponse answer URI search

Issue request:
FHIR-41549 is Applied/Persuasive with Modification. It asked to add standard QuestionnaireResponse search parameters for linkId, answer value types, and linkId+answer composites, with cautionary searching guidance, and to define a questionnaire-index-answer extension for servers to request answer indexing.

Initial application:
The core application commit 7083569cc2 added the answer search parameters and QuestionnaireResponse guidance. Follow-up core commits 92df410891 and 74cf42cc92 commented out answer-uri while later re-enabling item-uri, leaving item-uri's answer-uri component pointing at a SearchParameter that no longer appeared as an active resource. The Jira comment's 0caf207e2 locator corresponds to f1891774c4f25e44e740e50aa94bcf20caf207e2 in the FHIR Extension Pack, where questionnaire-index-answer was added outside the core checkout.

Additional context:
QuestionnaireResponse is an active resource in source/fhir.ini, so its search parameter bundle feeds the current build. Later issue FHIR-49784 updated these search parameter expressions to recurse through nested QuestionnaireResponse items. The current CI search page showed item-uri as active but displayed its answer-uri comparator as a bare canonical URL rather than a linked comparator, matching the commented-out source. The Extension Pack currently contains questionnaire-index-answer, but its context is outside this core repository and should be reviewed there if further extension-context correction is desired.

AutoFHIR reconciliation:
This commit restores the active QuestionnaireResponse-answer-uri SearchParameter in source/questionnaireresponse/bundle-QuestionnaireResponse-search-params.xml. That completes the requested URI answer search family and gives QuestionnaireResponse-item-uri an active answer-uri component definition.

Recommendation:
Keep this core-source fix. As follow-up outside this repository, review the FHIR Extension Pack questionnaire-index-answer context against the FHIR-41549 resolution because the extension now lives there rather than in core.
