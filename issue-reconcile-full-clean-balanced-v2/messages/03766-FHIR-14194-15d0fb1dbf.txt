FHIR-14194: Audit Range invariant removal

Issue request:
FHIR-14194 was a Published/Persuasive with Modification FHIR-core datatypes issue raised in STU3. It reported that the Range rng-2 invariant used `low.empty() or high.empty() or (low <= high)` even though Range.low and Range.high are SimpleQuantity values and Quantity comparison was not then defined in FHIRPath. The approved disposition was to remove rng-2 as an executable invariant for the time being, track Quantity comparison support separately, and re-add the constraint once that support existed.

Initial application:
The seed appears to have been applied by git-svn commit b700546ea6 (`#14194 - fix range invariant`) on source/datatypes/range.xml. That commit changed the Range.low and Range.high invariant references from `2` to `!2` and changed the Invariants sheet id from `2` to `!2`, disabling rng-2 while retaining the Range datatype prose about ordered low/high quantities and boundary meaning.

Additional context:
FHIR-14308 added the FHIRPath Quantity-comparison support that FHIR-14194 requested as a prerequisite. FHIR-14309 and FHIR-14326 then asked to re-enable the Range invariant, and git-svn commit 11f97b11d7 (`GF#14309 - reenable rng-2 invraiant`, svn revision 13459) changed the invariant id back from `!2` to `2`. Later, FHIR-25736 changed rng-2 to ignore missing low.value/high.value in patterns, and FHIR-34417 refined the expression with lowBoundary/highBoundary plus comparable(). The combined branch already contains audit commits for FHIR-14309 and FHIR-25736; FHIR-14326 is audited separately by the following commit.

AutoFHIR reconciliation:
No source change was made for FHIR-14194. Range is active in source/fhir.ini, and the authoritative current source/datatypes/range.xml contains rng-2 as invariant id 2 with the current Quantity-aware expression. Removing it now would undo later final decisions, while adding redundant usage prose is unnecessary because current source already conveys the low/high Range semantics and enforces them using the later approved FHIRPath support.

Recommendation:
Keep this audit commit as-is. FHIR-14194 was correctly applied as a temporary disabling of rng-2, and the current re-enabled invariant is correct because later final issues superseded the temporary state.
