FHIR-25279: Audit _elements choice-type naming

Issue request:
FHIR-25279 was Published as Persuasive with Modification for R5. It asked the FHIR-core search page to lock down how _elements names polymorphic choice elements, and the final resolution says clients SHALL use the base element name without [x] or a type-specific suffix, e.g. "value" rather than "value[x]" or "valueQuantity".

Initial application:
The request was directly applied before this reconciliation by historical commit e934020f41d1892646addc75e2627e8b3fc27f5e, titled "FHIR-25279 First Pass", which added the base-name SHALL sentence to source/search.html. Later conformance-language cleanup and adjacent _elements edits preserved that rule in the active search page source.

Additional context:
The original Zulip thread shows implementers reporting variable server behavior for Observation.value[x] selections and Josh Mandel adding J#25279 from that discussion. FHIR-I minutes from 2020-04-13 record agreement that polymorphic elements should be referenced by the base element name without [x], with the same examples and a 9-0-0 motion. FHIR-31655 later clarified neighboring _elements return-expectation wording but did not change the choice-type naming rule and is already represented on the combined branch.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the active FHIR-core search page already says each _elements name SHALL be the base element name without specifying [x] or one of the types, with "value" valid and "value[x]"/"valueQuantity" invalid.

Recommendation:
Keep this audit commit as-is. No follow-up core source change is needed for FHIR-25279 unless a future work-group decision changes the _elements naming convention for polymorphic elements.
