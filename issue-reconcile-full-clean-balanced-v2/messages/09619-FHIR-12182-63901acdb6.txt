FHIR-12182: Audit ElementDefinition id rules

Issue request:
FHIR-12182 was Published/Persuasive for DSTU2 and asked that profiles have complete, reliable ElementDefinition identifiers: every ElementDefinition should have an id constructed from the element path with slice/reslice names using pathpart:slicename/reslicename syntax, ids should remain in the inherited id field for URI fragment references, slice-name/name syntax and uniqueness guidance should be clarified, and StructureDefinition documentation should clarify differential/snapshot ordering.

Initial application:
Jira records svn revision 10018 as the application. In this Git history that is commit 35476b4eabc31ac9f28342386aefde59693d436f, whose subject is "#12182 - more controlled use of ElementDefinition.id". That commit added the ElementDefinition.id narrative algorithm and the StructureDefinition differential/snapshot ordering notes. A nearby follow-up, 82e1ca4af69d33f527a180c7bfa003e811feb4c0, also names Tasks 12180, 12182, and 12179 and tightened build/generator behavior around ElementDefinition.id and snapshots.

Additional context:
Current build scope still includes ElementDefinition as an active datatype and StructureDefinition as an active resource. The current ElementDefinition page says every ElementDefinition SHALL have a populated id, gives the pathpart:slicename/reslicename algorithm, and notes that unsliced profiles match path exactly. Current StructureDefinition source enforces id existence and id uniqueness for snapshot and differential elements through sdf-14, sdf-16, and sdf-17. The related FHIR-12181 rename from name to sliceName is reflected in the current ElementDefinition source, including the no-dot/no-space token guidance, uniqueness documentation, and sliceName regex. Later FHIR-13514 refined the StructureDefinition id constraints and is already represented separately on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative source already conveys the requested id location, required population, uniqueness, slice/reslice format, sliceName syntax/uniqueness, and differential/snapshot ordering behavior; adding duplicate prose or changing the inherited Element.id cardinality would be less accurate than the existing StructureDefinition-level constraints.

Recommendation:
Keep this audit commit as-is. Revisit only if a future publisher/build regression drops ElementDefinition ids, allows duplicate ids in StructureDefinition snapshots or differentials, or changes the sliceName/id algorithm without updating the ElementDefinition and StructureDefinition guidance together.
