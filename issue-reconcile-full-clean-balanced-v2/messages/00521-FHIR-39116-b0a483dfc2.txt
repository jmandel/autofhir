FHIR-39116: Audit applied AuditEvent network string guidance

Issue request:
FHIR-39116 was a Published FHIR-core AuditEvent change request with resolution Not Persuasive with Modification. It asked to bring back R4 AuditEvent.agent.network.type so an AuditEvent client network value could indicate that a stored networkString is an IP address. The accepted resolution did not restore network.type; it clarified the AuditEvent.agent.network[x] requirements to prefer Reference(Endpoint) or URI and to use string only when address or hostname is all that is known, with canonical hostname and literal numeric address encoding guidance.

Initial application:
The issue appears to have been applied by git commit a3adca8e6f9921c9bdca3288f8f39b1455794b96, "close FHIR-39116", which replaced the old AuditEvent.agent.network[x] requirements text in source/auditevent/structuredefinition-AuditEvent.xml with the Jira resolution wording. The current build includes AuditEvent as an active resource in source/fhir.ini, and the R4-to-current xver mappings still map AuditEvent.agent.network.address and AuditEvent.agent.network.type to network[x].

Additional context:
The originating Zulip thread records the reporter's R5 concern that network.type was gone and asks how to represent a client IP address; John Moehrke answered that Reference(Endpoint) or URI should be preferred and string used only when those do not fit. Security WG Confluence references include the 2022-10-31 minutes noting the plan to use string encoding of hostnames or numeric addresses in square brackets, matching the Jira resolution and final source text. No later final source decision was found that reverses this R5 resolution.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active AuditEvent source already contains the final requirement text, and AuditEvent.agent.network[x] already permits Reference(Endpoint), uri, and string. Reintroducing AuditEvent.agent.network.type would contradict the Published Not Persuasive with Modification disposition.

Recommendation:
Keep this no-change audit commit as-is. No core FHIR follow-up is needed unless the Security Work Group opens a new issue to reintroduce typed network address metadata or change the current string encoding guidance.
