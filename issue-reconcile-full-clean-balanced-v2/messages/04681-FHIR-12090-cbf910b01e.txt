FHIR-12090: Audit Goal target migration

Issue request:
FHIR-12090 was a Published/Persuasive with Modification Patient Care change request for FHIR-core Goal, raised from QI-Core #16 in DSTU2. It asked to resolve the clash between the old goal-target extension and Goal's target/date representation; the final resolution was to move goal-target into the Goal resource as a Target backbone element with measure, detail, and due child elements.

Initial application:
The January 2017 application commit bd819cfbf9a33c335e7030ff69591f11f7a57882 moved the old goal-target extension content into the Goal spreadsheet and updated the main Goal and CarePlan examples to use Goal.target instead of the extension. Current source migration preserved that application in source/goal/structuredefinition-Goal.xml, where Goal.target carries a GF#12090 committee note and defines the target backbone with measure, detail, and due.

Additional context:
Goal is active in source/fhir.ini, so source/goal/structuredefinition-Goal.xml is the current authoritative source. Later Patient Care decisions intentionally changed the original 2017 shape: FHIR-12585 added the measure-if-detail invariant, FHIR-12661 added the Goal.target.measure example binding, FHIR-17572 changed Goal.target to 0..* for multi-component goals and added the all-targets-must-be-met guidance, FHIR-17753 added string, boolean, integer, and Ratio to Goal.target.detail[x], and FHIR-46293 removed an orphaned detail binding. A source search found the old goal-target extension only in source/careplan/careplan-example-asthma.xml outside historical archives; exact reference searches found that stale asthma XML is not listed in the CarePlan examples list or otherwise referenced by current source, and it also contains broader obsolete resource syntax, so it is not a safe current-build source fix for this issue. The FHIR Extension Pack has no goal-target definition to reconcile.

AutoFHIR reconciliation:
Made no source change. The active Goal StructureDefinition already implements the FHIR-12090 migration as modified by later final decisions, and editing an unlisted stale CarePlan asthma file would not improve the current built specification.

Recommendation:
Keep this empty audit commit as-is. If the unlisted asthma example is ever reactivated, update it as a separate whole-example cleanup against the current CarePlan, Goal, MedicationRequest, and related schemas rather than treating that dormant file as an incomplete FHIR-12090 application.
