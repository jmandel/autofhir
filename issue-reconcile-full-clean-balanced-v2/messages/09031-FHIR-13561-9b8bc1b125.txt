FHIR-13561: Audit OperationDefinition parameter profiles

Issue request:
FHIR-13561 was Published/Persuasive for STU3 and asked OperationDefinition to avoid duplicating the full expressiveness of ElementDefinition for operation parameters by adding root-level inputProfile and outputProfile references to StructureDefinition profiles on Parameters. The resolution also required the profiles to be optional additional validation that must align with OperationDefinition.parameter cardinalities and removed OperationDefinition.parameter.profile as redundant.

Initial application:
The Jira comments record svn revision 12730. In git-svn history, commit a2de5baa9f30abf227aab9f92f27632121ff40f5 (build@12730) added OperationDefinition.inputProfile and OperationDefinition.outputProfile, added narrative explaining the profile/parameter relationship, removed OperationDefinition.parameter.profile, and replaced the per-parameter profile slot with OperationDefinition.parameter.targetProfile because the editor noted the capability still had to be retained under that name.

Additional context:
source/fhir.ini actively includes operationdefinition=OperationDefinition, so the OperationDefinition StructureDefinition and notes are current build-scoped source. The current StructureDefinition defines inputProfile and outputProfile as canonical references to StructureDefinition and says each is a single profile covering all parameters; it also has OperationDefinition.parameter.targetProfile, not parameter.profile, with text explaining the special OperationDefinition behavior that corresponds to ElementDefinition.type.profile for resource-valued parameters. The current notes section says profiles SHALL be profiles on Parameters, SHALL NOT disagree with OperationDefinition.parameter, and gives detailed alignment rules. FHIR-14433 later clarified the example/profile-on-Parameters text and is already represented on the combined branch; a 2024 Zulip question confirmed outputProfile is still intended to profile Parameters rather than the directly returned resource.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The requested structural elements, removal/renaming of OperationDefinition.parameter.profile, and required documentation about the relationship to Parameters profiles are already present in active current source, and later related clarifications do not contradict the original decision.

Recommendation:
Keep this no-change audit. No FHIR-core edit is needed for FHIR-13561; any future work should be handled under narrower later issues if the OperationDefinition/profile alignment rules need additional examples or validator behavior changes.
