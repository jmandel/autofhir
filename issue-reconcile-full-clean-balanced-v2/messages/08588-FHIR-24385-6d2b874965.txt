FHIR-24385: Audit canonical JSON template rendering

Issue request:
FHIR-24385 was Published/Persuasive for FHIR-core and asked that the Resource Content JSON pseudo-template stop rendering canonical values inside surrounding braces. The concrete example was CapabilityStatement.instantiates, where the final resolution was to remove the surrounding {}.

Initial application:
No core source commit in this checkout mentions FHIR-24385. The active CapabilityStatement source defines instantiates/imports as primitive canonical elements with CapabilityStatement target profiles, and the current rendered CI build and published R5 page both show those elements as JSON string arrays such as ["<canonical(CapabilityStatement)>"] rather than arrays of objects. The fix therefore appears to have been applied through the generated template rendering/tooling path before R5 publication, not as a later editable CapabilityStatement XML change.

Additional context:
CapabilityStatement is an active resource in source/fhir.ini, and the current build is driven by the external Kindling publisher dependency declared in build.gradle.kts and gradle.properties. The Resource Content JSON template is generated output, while the authoritative core source already carries canonical as a primitive type. Jira/Zulip/Confluence searches found no later conflicting community or work-group evidence.

AutoFHIR reconciliation:
This commit intentionally makes no source changes. The current source and rendered specification already satisfy the Jira resolution, and changing CapabilityStatement source would not address the template-rendering concern.

Recommendation:
