FHIR-28498: Audit duplicate subscription notification warning

Issue request:
FHIR-28498 was a Published/Persuasive FHIR-I R5 change request asking the Subscriptions documentation to explicitly say duplicate notifications are possible and that client applications need to handle them.

Initial application:
The Jira comment records git commit dbeb5e6a7aa3cba0705a1c337c0eaf6174d32eb2 as the application commit. Although that commit's subject names another subscription tracker and bundled several subscription updates, its source/subscriptions.html patch added the requested delivery-limitation warning: some notifications might not be delivered and some might be delivered multiple times, with a link to delivery-error detection guidance.

Additional context:
The cited Zulip thread established the rationale: subscriptions do not require guaranteed delivery and do not prevent duplicate delivery, so clients need detection/reconciliation behavior. FHIR-I minutes on 2020-11-09 recorded FHIR-28498 as Persuasive with a 13-0-0 motion. Later FHIR-43516 cleanup removed a duplicated overview copy, kept the warning in Scoping Responsibilities, and has already been represented on the combined branch with Issue-Reconcile-Key: FHIR-43516. A later FHIR-47280 source refactor reformatted the page while preserving the same normative content.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active source/subscriptions.html page still states that the framework does not involve guaranteed delivery unless otherwise specified, tells clients that some notifications might be delivered multiple times, and points to Detecting Delivery Errors for mitigation. The page is in current build scope through publish.ini and source/hierarchy.xml, with Subscription active in source/fhir.ini.

Recommendation:
Keep this audit commit as-is. The current core source already satisfies FHIR-28498; adding another duplicate-notification paragraph would reintroduce the redundancy that FHIR-43516 already cleaned up.
