FHIR-14443: Audit Observation subject focus resolution

Issue request:
FHIR-14443 was a Published/Persuasive with Modification FHIR-core Observation request arguing that Observation.subject was too narrow for observations about other observations, practitioners, organizations, and other entities. The accepted resolution was not to make Observation.subject unbounded; it was to promote the focal-subject extension to a DSTU core element with Reference(Any) and add boundary guidance about when Observation is appropriate.

Initial application:
The same STU3/R4 source work that applied FHIR-14863 also applied this issue family. Commit d06b52856c89401a981241a811faa7b455037c08 added focal-subject-related Observation source and boundary text, and commit 5c093b94a97c0320ee01c1ec9914fd824433ba4e explicitly mentions GF#14443 while renaming Observation.focalSubject to Observation.focus. Observation is active in the current build through source/fhir.ini.

Additional context:
The linked Zulip discussion records the modeling choice: preserve a clear subject/record target instead of changing Observation.subject to Reference(Any), add an inline focus element for the actual focus when different from the subject, and discourage use of Observation when a more specific resource exists. Later FHIR-15825 changed the focus cardinality from 0..1 to 0..*, and later subject/focus clarification work refined the surrounding guidance.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Observation source defines Observation.subject with explicit target profiles and a definition that points to `focus` or `code` when the actual focus differs from the subject. Observation.focus is present as a 0..* Reference(Resource) and the narrative explains subject, focus, and device usage plus Observation boundaries.

Recommendation:
Keep this audit commit as-is. Do not reinterpret FHIR-14443 as requiring Observation.subject Reference(Any); the accepted and applied design is the existing Observation.focus mechanism, with subsequent Jira decisions governing later cardinality and wording refinements.
