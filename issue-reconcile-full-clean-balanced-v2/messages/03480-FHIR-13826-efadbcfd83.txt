FHIR-13826: Audit hospitalization supportingInfo handling

Issue request:
FHIR-13826 was Published with a Persuasive with Modification resolution for STU3. The request began as allowing a boolean value for ExplanationOfBenefit.hospitalization, and the final resolution instead removed the standalone Claim and ExplanationOfBenefit hospitalization and EmploymentImpacted elements, represented them through the information/supportingInfo structure using claim information category codes, and added boolean as an allowed information value.

Initial application:
The Jira-tagged source application is git commit 4a2f618cfd6a35e6bf8445eab10ac7310da3de6c, "Tracker #13826", which changed the Claim and ExplanationOfBenefit spreadsheets and examples, removed the old standalone hospitalization/employmentImpacted example usage, and added hospitalized and employmentimpacted claim information category codes. Later source refactoring renamed information to supportingInfo and commit 5c0494aacfd0b8bd52bc72c587aa89d0a64246f8 moved the code system content out of core as part of UTG/THO terminology separation.

Additional context:
Claim and ExplanationOfBenefit are active resources in source/fhir.ini. Current core source has Claim.supportingInfo.category and ExplanationOfBenefit.supportingInfo.category bound to http://hl7.org/fhir/ValueSet/claim-informationcategory, examples use the THO system http://terminology.hl7.org/CodeSystem/claiminformationcategory with hospitalized and employmentimpacted, and no Claim/ExplanationOfBenefit hospitalization or employmentImpacted elements remain. Current THO/published terminology still defines hospitalized and employmentimpacted with definitions that explicitly allow a period if known or a Yes/No boolean otherwise. A later UP-691 proposal draft discusses broad claim information category harmonization, but it is unresolved and does not change this applied core issue.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because the current build-scope Claim and ExplanationOfBenefit sources already implement the final Jira disposition, and the terminology source of truth now lives in THO while core correctly references it.

Recommendation:
Keep this audit commit as-is. Do not add duplicate prose or restore standalone elements in core; any future changes to the claim information category code system should proceed through the active UTG/THO proposal process rather than this closed core tracker.
