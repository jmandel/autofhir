FHIR-18443: Audit signature canonicalization warning

Issue request:
FHIR-18443 was Published with resolution Persuasive with Modification for STU3. It asked how canonicalization excludes the element that contains the signature and resolved to add a warning to the XML digital signature section, and the equivalent JSON section, saying the canonicalization algorithms did not work for enveloped signatures and would be researched for a future release.

Initial application:
The issue was applied by git commit 440a4372a0e154b4fbe4622ae870cab1ee41c2f7, which added the warning text to source/xml.html and source/json.html. No separate FHIR-18443-tagged source commit was found after that initial application.

Additional context:
The current build-scope source no longer keeps canonicalization details on xml.html and json.html; both pages link to source/signatures.html, and source/hierarchy.xml includes signatures.html under the Security and Privacy page tree. The 2025 signatures rewrite dcf53a8af6d730f886918f45af2510e990a986eb deliberately removed the old warning while centralizing canonicalization rules. Later signature work added current embedded Bundle rules: entries that contain embedded signing Provenance resources are removed from the signed Bundle, Bundle.signature is deprecated, and the legacy worked example explicitly rebuilds the detached JWS payload with Bundle.signature removed. FHIR-50934 then refined recursive canonicalization variants, and FHIR-52810 refined embedded Bundle signature targets to use the #/ fragment identifier.

AutoFHIR reconciliation:
This is an empty no-change audit commit. Re-adding the STU3 warning would now be misleading because the current signatures page gives affirmative rules for embedded signatures rather than leaving enveloped signatures unsupported. The current XML and JSON pages correctly defer to that shared signature guidance.

Recommendation:
Keep this audit commit as-is. Future signature changes should continue in source/signatures.html and related current signature issues, not by restoring the obsolete STU3 warning on the XML and JSON format pages.
