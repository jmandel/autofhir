FHIR-17589: Confirm OperationOutcome location deprecation

Issue request:
FHIR-17589 was a Published/Persuasive with Modification STU3 FHIR Infrastructure change request titled "Drop OperationOutcome.issue.location". The final resolution did not remove the element immediately; it required marking OperationOutcome.issue.location as deprecated and reworking the documentation about the use of the element because issue.expression was the format-independent replacement.

Initial application:
The issue was applied by git-svn commit e8c22a3727455852300b359fe317824ad3ae2224, whose message names GF#17589 and svn revision 14528. That commit marked the OperationOutcome.issue.location spreadsheet row as deprecated, changed its short/definition/comment to point to issue.expression, and rewrote the OperationOutcome notes from "Using the Location Element" toward expression-based location reporting. Later source refactors converted the old spreadsheet source into the current StructureDefinition XML while preserving the deprecation.

Additional context:
The linked July 2018 Zulip thread shows the rationale: location used limited XPath while expression was intended to become the single syntax-independent location mechanism. OperationOutcome is an active current-build resource in source/fhir.ini. Later same-family work, including FHIR-18508 and the already-published FHIR-18505/FHIR-18508 AutoFHIR audit commits on the combined branch, clarified the OperationOutcome issue.expression narrative and did not reverse the FHIR-17589 decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/operationoutcome/structuredefinition-OperationOutcome.xml marks OperationOutcome.issue.location as deprecated with a standards-status reason saying it is replaced by issue.expression, and the current OperationOutcome notes section is titled "Using the Expression" and tells applications to use the expression element consistently for resource and HTTP request locations. Removing the element now would go beyond the Jira resolution and would be a new compatibility decision.

Recommendation:
Keep this empty audit commit as-is. No core source follow-up is needed for FHIR-17589 unless the work group makes a new decision to remove OperationOutcome.issue.location entirely in a future release.
