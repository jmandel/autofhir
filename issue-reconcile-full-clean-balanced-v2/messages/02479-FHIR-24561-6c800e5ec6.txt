FHIR-24561: Audit MedicationKnowledge ingredient strength

Issue request:
FHIR-24561 was a Published/Persuasive Pharmacy change request raised against STU3 and applied for R5. It asked to replicate Medication's strengthCodeableConcept capability on MedicationKnowledge so trace/sufficient ingredient strengths could be represented.

Initial application:
The issue was initially applied in commit 80c2f73ea490c414129d8406d6d00d4e94af04c0, which Jira also cites in its application comment. That commit added MedicationKnowledge ingredient-strength spreadsheet content and introduced the medication-ingredientstrength CodeSystem/ValueSet for qs and trace, along with other Pharmacy tracker work in the same batch.

Additional context:
Pharmacy Confluence minutes from 2019-11-25 record FHIR-24561 as voted and approved. Later source history moved the MedicationKnowledge ingredient element into the definitional backbone in commit 6422f2f98a0fcf03140c15fe93bfd6c765fc6377 while preserving the strength choice. Commit 129c9fa6f54e03f7a5ebc6de4172227fb2f830dd consolidated the ingredient strength CodeSystem/ValueSet under the Medication source folder, but the canonical URLs and MedicationKnowledge binding remain in current build scope.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current source/fhir.ini actively includes MedicationKnowledge, and source/medicationknowledge/structuredefinition-MedicationKnowledge.xml defines MedicationKnowledge.definitional.ingredient.strength[x] with Ratio, CodeableConcept, and Quantity choices, binding the CodeableConcept choice to http://hl7.org/fhir/ValueSet/medication-ingredientstrength. That satisfies the issue despite the current R5/R6 path and choice-element name differing from the original STU3 wording.

Recommendation:
Keep this no-change audit commit. No follow-up core source work is needed for FHIR-24561 unless Pharmacy later decides to change the strength value set or the MedicationKnowledge ingredient model more broadly.
