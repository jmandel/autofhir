FHIR-23788: Audit Questionnaire dynamic option extensions

Issue request:
FHIR-23788 was a Published/Persuasive FHIR-core Questionnaire change request asking for dynamic control over answer options, originally resolved as adding an expression-driven answerValueSet mechanism and a complex option-control extension so individual choices could be enabled or disabled based on other answers.

Initial application:
The Jira comments record that a new answerValueSet extension was not needed because the existing cqf-expression extension could be used, and that core commit 52616f04e0 added questionnaire-optionRestriction. That commit added source/questionnaire/structuredefinition-extension-questionnaire-optionRestriction.xml and registered it in source/questionnaire/implementationguide-Questionnaire-core.xml.

Additional context:
The Questionnaire resource remains active in source/fhir.ini, but the specific extension definitions are no longer maintained in this core checkout. Commit dd468d4f17 removed Questionnaire extension definitions from the R5 source, and the current Extension Pack checkout contains active definitions for questionnaire-optionRestriction and cqf-expression. Later Extension Pack issue FHIR-43033 refined questionnaire-optionRestriction contexts there, confirming that this artifact is now governed outside the core source tree. Core retains only supporting registry/legacy references such as OIDs and the Questionnaire IG shell.

AutoFHIR reconciliation:
This commit intentionally makes no source change in FHIR core. Re-adding or editing questionnaire-optionRestriction or cqf-expression in core would duplicate artifacts whose current source of truth is the FHIR Extension Pack, and the inspected Extension Pack definitions already carry the dynamic option restriction and expression semantics needed for the original issue.

Recommendation:
Keep this empty audit commit as-is for core reconciliation. If future changes are needed to questionnaire-optionRestriction or cqf-expression behavior, make them in the FHIR Extension Pack and coordinate with SDC guidance rather than restoring these extension definitions to core.
