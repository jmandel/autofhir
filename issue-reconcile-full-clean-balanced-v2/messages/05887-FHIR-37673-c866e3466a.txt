FHIR-37673: Complete preferred-id active/date handling

Issue request:
FHIR-37673 was Published as Persuasive with Modification for R5. It asked that $preferred-id not return results from retired NamingSystem resources, that clients be able to request the preferred identifier for a specific time using a date input rather than a period input, that ambiguous multiple-preferred matches may either be returned or reported as an error, and that preferred identifiers for the same identifier type SHOULD NOT overlap by period.

Initial application:
Commit b709f1aec3008d932753b1a0ac53f60235208aa0 added the date input, added multiple-preferred wording to the operation footer, and added the preferred-period overlap note to NamingSystem.uniqueId.type. Later reconciliation commits for FHIR-22105 and FHIR-37674 fixed the period-aware nsd-2 invariant and aligned the operation comment with the preferred-identifier selection wording. The current source still omitted the approved active-status filter, still described the operation as taking only two input parameters, and still constrained the result output to a single string even though the approved wording allows returning all applicable identifiers.

Additional context:
NamingSystem is active in source/fhir.ini and source/namingsystem/list-NamingSystem-operations.xml lists OperationDefinition/NamingSystem-preferred-id, so the edited OperationDefinition feeds the current build. FHIR-I minutes for 2022-07-18 confirm the work group accepted the retired-status bullet and chose a date parameter instead of a period parameter. Bounded Jira/Zulip/Confluence searches found the same NamingSystem operation family, including already-published FHIR-22105 and FHIR-37674 decisions, but no later decision reversing FHIR-37673.

AutoFHIR reconciliation:
Updated source/namingsystem/operationdefinition-NamingSystem-preferred-id.xml so the footer, description, and OperationDefinition.comment state that $preferred-id SHOULD only consider active NamingSystem instances. The description now lists the optional date input and no longer says the operation has only two inputs. The result output cardinality is now repeatable so the operation definition can represent the approved option to return all applicable identifiers instead of an error.

Recommendation:
Keep this source fix. It completes the parts of FHIR-37673 that remained inconsistent in the active operation source while preserving the related FHIR-22105 period-aware invariant and FHIR-37674 preferred-identifier selection behavior already represented on the combined branch.
