FHIR-13481: Audit closure version parameter type

Issue request:
FHIR-13481 was a Published/Persuasive STU3 Vocab change request for ConceptMap. It asked to change the $closure input parameter `version` from `id` to `string`, because the examples showed string values and that datatype better matched the version use case.

Initial application:
The Jira record says the change was applied in svn revision 13308. Git commit 4ce38f7d888beef54b46323abd585e6c0b481999 is the matching git-svn import for build@13308 and changed `source/conceptmap/conceptmap-spreadsheet.xml` so `closure.version` used `string` instead of `id`. The 2021 source rework then carried that into `source/conceptmap/operationdefinition-ConceptMap-closure.xml` with `<type value="string"/>` for the `version` parameter.

Additional context:
ConceptMap remains an active current-build resource, but $closure is no longer a current ConceptMap operation. Commit 40306e5cd9c1b1e3eb6f115de16a8da3aa13a351 removed the $closure OperationDefinition and examples during R6 normative-ballot terminology cleanup, and the current ConceptMap operation list and terminology service/module pages now expose only ConceptMap $translate. Zulip and Confluence records match the Jira request and block-vote history and do not reveal a conflicting current requirement.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The requested datatype correction was applied while $closure existed, and the current specification no longer has a $closure `version` parameter to correct.

Recommendation:
Keep this empty audit commit as-is. Do not reintroduce $closure for FHIR-13481; only revisit if Terminology Infrastructure separately decides to restore the operation in the current build.
