FHIR-16931: Audit modifier list grouping clarification

Issue request:
FHIR-16931 was a Published FHIR-core change request, resolved Persuasive with Modification, asking the FHIR-I work group to clarify why the conformance-rules list of modifier elements grouped some resources in one bullet while other status elements appeared individually. The recorded resolution was to fix the issue that led to some status codes being listed individually.

Initial application:
The issue was applied in git commit 82d58b83174a490cfdc312007ac0e1387e3ba3f6, corresponding to the Jira comment's svn revision 14215. That commit replaced the misleading introductory modifier-list wording in source/conformance-rules.html with the current grouping statement, removed the explicit status/experimental resource bullet, and removed the experimental modifier flag from the then-current MetadataResource spreadsheet source.

Additional context:
The current conformance page remains in build scope through source/hierarchy.xml and linked narrative pages. The current source still carries the Jira-applied wording: most status elements are modifiers because of entered-in-error, while other modifiers are emitted through the generated modifier-list placeholder. The old MetadataResource spreadsheet was deleted during the 2021 source rework, and the current active CanonicalResource definition keeps status as a modifier while experimental is summary-only and not marked isModifier. Jira, Zulip, and Confluence searches did not reveal a later conflicting decision for this narrow grouping issue.

AutoFHIR reconciliation:
This commit makes no source change because the current source already reflects the FHIR-16931 correction and later source refactors preserved the relevant semantics in active build inputs.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-16931 unless a future work-group decision changes the broader isModifier presentation or generated modifier-list behavior.
