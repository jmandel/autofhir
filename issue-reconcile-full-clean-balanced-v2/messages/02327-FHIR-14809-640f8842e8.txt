FHIR-14809: Audit AuditEvent.recorded clarification

Issue request:
FHIR-14809 was a Published Security WG change request for STU3 AuditEvent. It asked whether AuditEvent.period and AuditEvent.recorded were redundant; the accepted Persuasive with Modification resolution was to clarify recorded's short description as "the time when the event was recorded" while preserving period as the event activity timeframe.

Initial application:
The issue appears to have been applied in df8241d8ed, an explicit Security WG commit listing GF#14809. That commit changed the AuditEvent spreadsheet from "Time when the event occurred on source" / "The time when the event occurred on the source" to "Time when the event was recorded" / "The time when the event was recorded" for AuditEvent.recorded. Later source restructuring commits carried the same wording into source/auditevent/structuredefinition-AuditEvent.xml and the AuditEvent date search parameter description.

Additional context:
AuditEvent is active in source/fhir.ini. Current source no longer has AuditEvent.period as a live element because the later Published FHIR-32444 change renamed it to AuditEvent.occurred[x] and made it Period or dateTime; the current definition still distinguishes the activity time/period from the required AuditEvent.recorded instant. Community searches found no direct FHIR-14809 Zulip or Confluence record and no conflicting discussion.

AutoFHIR reconciliation:
No source change was made. The current authoritative AuditEvent source already gives AuditEvent.recorded the requested short/definition and separately defines AuditEvent.occurred[x] as the activity time or period, so adding more prose would be redundant.

Recommendation:
Keep this empty audit commit as-is. No core follow-up is needed for FHIR-14809 unless a future Security WG decision changes the distinction between activity occurrence time and recording time.
