FHIR-34042: Audit search include-mode clarification

Issue request:
FHIR-34042 was a Published/Persuasive FHIR-I change request asking the specification to be more explicit that a searchset Bundle may contain entries marked entry.search.mode=include for referenced resources even when the client did not request _include.

Initial application:
No prior commit on the combined branch was tagged with Issue-Reconcile-Key: FHIR-34042, and no FHIR-34042-tagged source commit was found in local history. The relevant clarification appears to have been applied by git commit 36e9fd596f19b74d5c8d764b14cf9faa96d943d7, which added the current Search Responses include-mode prose to source/search.html before the final FHIR-I vote and R5 publication.

Additional context:
The linked Zulip thread confirms the issue origin: participants agreed the behavior was not forbidden, raised brittle-client concerns, and Lloyd McKenzie asked for a change request to make the possibility explicit. FHIR-I minutes for 2022-03-07 record FHIR-34042 as Persuasive by a 9-0-0 motion. The current HTTP search interaction points implementers to the Search handling mechanism, where the clarified include-mode text now lives.

AutoFHIR reconciliation:
This is an empty audit commit. No source change was made because current source/search.html already states that entries marked include may be returned because a resource is referred to from a result or because the server believes it is useful or necessary for the client to process other results. That directly covers unrequested included resources and avoids duplicating the same guidance elsewhere.

Recommendation:
Keep this audit commit as-is. Future editorial work may choose to align shorter generated Bundle/value-set descriptions with the Search page, but FHIR-34042 itself is already satisfied by the current Search page wording and does not need a source correction.
