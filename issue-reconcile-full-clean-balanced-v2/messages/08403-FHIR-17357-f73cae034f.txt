FHIR-17357: Audit canonical fragment guidance

Issue request:
FHIR-17357 was Published/Persuasive for STU3. It asked FHIR-core datatypes to make clear that canonical references may include hashtag/fragment references, especially where a reference needs to identify an ElementDefinition inside a particular StructureDefinition version. The accepted resolution said that a canonical targeting ElementDefinition should use the StructureDefinition canonical URL followed by '#' and the ElementDefinition path/id, and that omitting the fragment refers to the StructureDefinition root element.

Initial application:
The issue was explicitly applied in source history. Jira records svn revision 13945, and git commit 8e46cfb7a23bb6b6839535087993eb18253bf523 is titled "GF#17357 - explain fragments on canonicals" and added fragment-reference wording to source/datatypes.html. Later commit 6f7c3716ef8e176e5ea811ceb12844b81a3904ec for FHIR-18673 refined the same canonical datatype wording without removing the fragment allowance.

Additional context:
Current source/fhir.ini keeps datatypes and Questionnaire in build scope. The current canonical datatype row says elements of type canonical may have #fragment references and that canonical URLs are absolute URIs or fragment identifiers. The current Questionnaire.item.definition source is typed as uri, not canonical, after later Questionnaire evolution including FHIR-23765 support for ObservationDefinition; nevertheless its definition/comment and narrative explicitly say that ElementDefinition references start with the target StructureDefinition canonical URL, use a fragment identifier for Element.id, and refer to the root element when the fragment is absent. No active source now declares a canonical targetProfile of ElementDefinition, so adding a new generic canonical(ElementDefinition) rule would be stale rather than a needed current-build fix.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source already preserves the implementer-facing rule requested by FHIR-17357: canonical values may include fragments, and the Questionnaire ElementDefinition use case explains StructureDefinition#Element.id and the no-fragment root case. Later represented canonical-related decisions on the combined branch support the current wording and do not require a FHIR-17357 edit.

Recommendation:
Keep this audit commit as-is. Do not add redundant datatype or Questionnaire prose for FHIR-17357 unless a future work-group decision reintroduces a computable canonical(ElementDefinition) target-profile rule or changes how ElementDefinition fragment identifiers are represented.
