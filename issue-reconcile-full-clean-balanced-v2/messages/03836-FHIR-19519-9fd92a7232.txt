FHIR-19519: Audit migrated LOINC inactive guidance

Issue request:
FHIR-19519 was a Published/Not Persuasive with Modification Vocabulary WG issue for STU3. The final resolution rejected adding a general statement that every non-DEPRECATED LOINC status is active; instead it required the old LOINC page to say that codes with Property STATUS = DEPRECATED are inactive for ValueSet.compose.inactive, remove the old STATUS-property inactive sentence, change the STATUS property type away from boolean, and update the LOINC table-fields lead-in.

Initial application:
Git commit b7d3ba7dfa applied the FHIR-19519 resolution to the then-current source/loinc.html page: the summary Inactive row was changed to "Codes with Property STATUS = DEPRECATED are considered inactive for use in ValueSet.compose.inactive", the LOINC Properties lead-in was updated, and the STATUS property row was changed from boolean with the old inactive sentence to code with only "Status of the term". That commit did not update source/codesystem/loinc.xml, which was already a separate tracked artifact and still contains the old boolean/type sentence.

Additional context:
FHIR-19767 later superseded the STATUS type portion of FHIR-19519 from code to string and has already been represented on the combined branch by commit 172dc282dccfd77a60b85d15f2698b8cdb0f541b. FHIR-35933 later removed source/loinc.html from FHIR core and moved the external terminology usage pages to THO links; the current build-scoped source/terminologies-systems.html page links LOINC guidance to terminology.hl7.org/LOINC.html. The current THO LOINC page preserves the FHIR-19519 inactive-row wording and the FHIR-19767 STATUS=string decision. source/codesystem/loinc.xml remains tracked, but source/fhir.ini has no active loinc entry and no current tracked source reference to codesystem/loinc.xml was found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Editing the stale, unreferenced source/codesystem/loinc.xml artifact would not correct the current FHIR build, while the build-scoped FHIR page already points implementers to the migrated THO page that carries the approved LOINC inactive guidance.

Recommendation:
Keep this empty audit commit as-is. No FHIR-core source follow-up is needed for FHIR-19519; any future deletion or refresh of source/codesystem/loinc.xml should be handled as a separate cleanup/build-scope decision, not as this applied STU3 issue.
