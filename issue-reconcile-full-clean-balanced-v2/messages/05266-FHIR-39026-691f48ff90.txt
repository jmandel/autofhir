FHIR-39026: Audit SubscriptionTopic filter operators

Issue request:
FHIR-39026 is a Published/Persuasive with Modification R5 FHIR-I change request asking whether `=` and `eq` in `SubscriptionTopic.canFilterBy.modifier` mean different things and whether relying on a default `=` comparison should instead make the element mandatory. The accepted decision was that the distinction came from FHIR search semantics (`=` default matching versus the `eq` prefix/comparator) and that SubscriptionTopic canFilterBy should be changed to match SearchParameter's separate modifier and comparator definitions.

Initial application:
The issue-tagged source commit 07ab8970da2eb29b515d039788e861347d0cdfb8 separated `SubscriptionTopic.canFilterBy.comparator` from `SubscriptionTopic.canFilterBy.modifier`, bound the comparator to `ValueSet/search-comparator`, replaced the old Subscription-specific search modifier value set with the SearchParameter modifier value set, and updated SubscriptionTopic examples and notes. No prior AutoFHIR reconcile commit for FHIR-39026 was present on the combined branch.

Additional context:
The active current source has since moved the R5 `SubscriptionTopic.canFilterBy` elements under `SubscriptionTopic.trigger.canFilterBy`; `source/fhir.ini` records the old R5 paths as aliases to the new trigger paths. Later FHIR-50614 intentionally broadened the modifier binding to `ValueSet/search-modifier-all-codes` so resource type codes can be used with `:type`, but it preserved the FHIR-39026 split between comparator and modifier. FHIR-I minutes confirm the 9-0-0 vote for this disposition, and direct Zulip searches found no conflicting discussion.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current authoritative SubscriptionTopic StructureDefinition already has `SubscriptionTopic.trigger.canFilterBy.comparator` bound to search comparator codes and `SubscriptionTopic.trigger.canFilterBy.modifier` bound to search modifier/resource type codes, matching the SearchParameter pattern and preserving the WG's intended distinction between `=` default matching and `eq` comparators.

Recommendation:
Keep this commit as a no-change audit. Do not make `canFilterBy.modifier` mandatory for this issue, and do not revert the later FHIR-50614 all-codes broadening; both would go beyond the FHIR-39026 disposition and current source context.
