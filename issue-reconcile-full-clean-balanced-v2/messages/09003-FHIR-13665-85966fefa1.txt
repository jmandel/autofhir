FHIR-13665: Audit mapping-language typo fix

Issue request:
FHIR-13665 was a Published/Persuasive FHIR-core fhir-i change request raised against STU3 and applied for STU3. It asked to correct the mapping-language sentence "Alternatively, a rule can nominating another group of rules..." to use "nominate" instead of "nominating".

Initial application:
The issue was applied by the Sept. 6, 2017 typo commit 150060340b, whose message explicitly lists GF #13665 and whose patch changed `source/mapping-language.html` from "a rule can nominating another group" to "a rule can nominate another group". The Jira comment also records application on Sept. 6, 2017.

Additional context:
`source/mapping-language.html` is still a current build page: it is listed under the Implementation Support page hierarchy and linked from `source/implsupport-module.html`. Later Published issues FHIR-20840 and FHIR-20848 changed the same dependent-rules paragraph to document multiple group invocations, so the current sentence now says a rule can "nominate other groups of rules" rather than the original singular wording. That later pluralization preserves the FHIR-13665 correction and explains the current wording difference.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current `source/mapping-language.html` uses the grammatical "nominate" wording, and source/history evidence shows the historical typo was already corrected and then safely refined by later published StructureMap work.

Recommendation:
Keep this audit commit as-is. No follow-up source change is needed for FHIR-13665 unless a future work group decision revisits the dependent-rules wording independently of this typo.
