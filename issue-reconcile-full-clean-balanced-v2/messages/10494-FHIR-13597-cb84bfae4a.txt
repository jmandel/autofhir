FHIR-13597: Audit publisher scan filename handling

Issue request:
FHIR-13597 was a Published/Persuasive STU3 FHIR-core tooling issue asking that the publisher's scanForPages and scanForImages logic not abort when a build output file has no filename suffix.

Initial application:
The issue was applied in git commit 48c2dd532de7226381382e377156fae0b2bda987, matching the Jira comment's svn revision 12624. That commit changed both scanForPages and scanForImages in tools/java/org.hl7.fhir.tools.core/src/org/hl7/fhir/tools/publisher/Publisher.java to return an empty extension when the filename does not contain a dot.

Additional context:
The affected Publisher.java source is no longer present in this FHIR checkout. Commit 9f549566d1346cad7db6d2afca6080d7cebdfbbe removed tools/java/org.hl7.fhir.tools.core and switched the build to a Gradle dependency on org.hl7.fhir:kindling. The current FHIR build.gradle.kts runs org.hl7.fhir.tools.publisher.Publisher from that dependency, and the current HL7/kindling Publisher.java still contains the dot-presence guard in both scanForPages and scanForImages. Zulip/Confluence searches found only bot notifications for this issue and no substantive conflicting community decision.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR source change. The Jira-requested guard was historically applied, the obsolete in-repo Java source was later externalized, and the current external publisher source used by this build preserves the corrected behavior.

Recommendation:
Keep this audit commit as-is. No FHIR source follow-up is needed unless a future Kindling update regresses the scanForPages or scanForImages filename-extension guard.
