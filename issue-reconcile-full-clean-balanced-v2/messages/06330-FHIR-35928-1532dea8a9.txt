FHIR-35928: Confirm $versions examples use valueCode

Issue request:
FHIR-35928 was a Published/Persuasive FHIR-I technical correction for R5. It reported that CapabilityStatement/$versions output parameters `version` and `default` are typed as `code`, while the response examples used `valueString`, and requested `valueCode` instead.

Initial application:
The issue was applied by commit bf0d34160e8fb4b70bd74ca3463cb6193b5ae6cb and merged through PR #1766 as bee3b4c8d26a1bfaf24c631445e52dfb87d9623b. That commit changed every XML and JSON response example value in source/capabilitystatement/$versions-response.txt from valueString to valueCode.

Additional context:
The active CapabilityStatement operation list references OperationDefinition/CapabilityStatement-versions, so the checked source is in current build scope. The operation definition still declares both relevant output parameters as `code`; the response example uses `valueCode` for `version` and `default`. The earlier same-family FHIR-26065 also identified valueString/valueCode problems and later added a required binding for `default`, but this seed is limited to the example datatype mismatch. Zulip discussion that led to FHIR-35928 confirms the intended fix was valueCode, and Confluence search found no FHIR-35928 minutes that would change that interpretation.

AutoFHIR reconciliation:
No source change was made. The current build-scoped example source already contains `valueCode` in the XML and JSON Parameters examples, matching the output parameter datatype and the Jira request.
