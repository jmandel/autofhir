FHIR-8656: Audit v2 yes/no terminology handling

Issue request:
FHIR-8656 is a Published/Persuasive FHIR-core change request from the DSTU1 cycle. It asked to restore HL7 v2 table 0136 or create a Y/N value set based on v2 table 0532, depending on Vocabulary guidance, because Observation guidance needed a coded yes/no alternative for result values that are not truly Boolean.

Initial application:
The Jira comment records svn revision 6892. In git, 3886233da6ae mirrors svn @6892 and updated source/v2/v2.ini plus source/v2/v2oids.txt: table 0136 was restored in the v2 OID/table list, and the [valuesets] mapping made table 0532 a value set over 0136 plus v3 NullFlavor. The related example yes/no/don't know ValueSet had already been added in e94679451e and later URL/ValueSet syntax migrations kept it in the ValueSet examples.

Additional context:
Current core no longer owns generated v2 table source: commit 5c0494aacf removed source/v2 and other UTG terminology content from the core build. Current authoritative terminology is externalized at terminology.hl7.org, where ValueSet/v2-0136 exists and is defined over CodeSystem/v2-0532, while CodeSystem/v2-0136 does not exist. The current core source still has the build-scoped yesnodontknow ValueSet example and Observation note: the ValueSet imports http://terminology.hl7.org/ValueSet/v2-0136, its expansion lists Y and N from http://terminology.hl7.org/CodeSystem/v2-0532, and Observation guidance points implementers to ValueSet/v2-0136. Later FHIR-37453, already audited on the combined branch, specifically reconciled the missing CodeSystem/v2-0136 problem and confirmed that v2-0136 is a ValueSet, not a CodeSystem. FHIR-27788 was reopened and rejected because the example value set remains used.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Restoring a core CodeSystem/v2-0136 definition would be wrong in the current build because v2 terminology ownership has moved out of core and the current core source already references the surviving THO ValueSet/v2-0136 and CodeSystem/v2-0532 artifacts needed for yes/no Observation guidance.

Recommendation:
Keep this audit commit as-is. No FHIR-core source edit is needed for FHIR-8656; if future maintenance finds an error in the underlying v2-0136 or v2-0532 terminology definitions, that follow-up belongs in the external terminology source/THO process, not by reintroducing retired core source/v2 content.
