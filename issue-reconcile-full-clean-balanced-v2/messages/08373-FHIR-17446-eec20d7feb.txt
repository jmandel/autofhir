FHIR-17446: Audit XHTML datatype placement

Issue request:
FHIR-17446 was a Published FHIR-core change request, resolved Persuasive for STU3 after a 6-0-0 FHIR-I vote, asking that the xhtml datatype be shown on datatypes.html because Narrative.div used it like other primitive datatypes and its StructureDefinition kind was primitive-type.

Initial application:
The Jira comment records svn revision 14291. In git history this is f80d9a7a03c02dc731793f576b9d4b25d6166528, titled "GF#17446 - add xhtml to data types page"; it added xhtml to the special-purpose datatype diagram and taught the then-current SVG generator how to draw xhtml. The current source no longer carries that Java generator, but the build-scope datatype pages still include source/datatypes/specialtypes.diagram and that diagram still lists xhtml.

Additional context:
Later Published issue FHIR-34314 explicitly observed that xhtml was listed as a Special Purpose datatype but lacked enough definition. Its accepted resolution did not move xhtml into the primitive table; instead it added an XHTML Content section on narrative.html, kept datatype references routed there, and corrected PrimitiveType link routing. The existing combined branch already contains a no-change reconciliation commit for FHIR-34314. A newer related issue, FHIR-57292, asks whether xhtml should derive from PrimitiveType or be included in the primitive list, but it is still Submitted and unresolved.

AutoFHIR reconciliation:
No source change was made. Current build-scope source already preserves the applied FHIR-17446 outcome by making xhtml discoverable from datatypes.html as a special-purpose datatype, including xhtml in source/datatypes/specialtypes.diagram, routing xhtml datatype references to narrative.html, and providing a table there with xhtml XML/JSON definition links and xhtml-specific constraints. Adding xhtml to the primitive table now would preempt the unresolved FHIR-57292 work-group question rather than merely reconciling this Published STU3 issue.

Recommendation:
Keep this empty audit commit as-is. If FHIR-I later resolves FHIR-57292 to reclassify xhtml as PrimitiveType or to change the datatype diagrams/listing, that future issue should drive the source edit; this reconciliation should not make that unresolved semantic change.
