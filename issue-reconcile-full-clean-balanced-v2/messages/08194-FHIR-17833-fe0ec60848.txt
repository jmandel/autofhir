FHIR-17833: Audit X-Security-Context reference clarification

Issue request:
FHIR-17833 was a Published/Persuasive FHIR-I change request for Binary, raised against STU3, asking that the Binary native HTTP X-Security-Context header specify which part of the Binary.securityContext Reference is sent. The approved resolution was to clarify that the header value is securityContext.reference, i.e. just the URI string.

Initial application:

The Jira comments point to the same short hash and then state that the issue was already done.

Additional context:
Binary is an active resource in source/fhir.ini, and source/binary/binary-notes.xml is the active narrative source for the Binary page. The current Binary.securityContext StructureDefinition still defines the element as a Reference to Resource, while the narrative header mapping now explicitly identifies the Reference.reference value for the native HTTP header. The related FHIR-16890 Binary security clarification predates FHIR-17833 and explains nearby security-context prose, but it does not change the header-value question.
