FHIR-25440: Audit default type extension registration

Issue request:
FHIR-25440 was Published/Persuasive for R5 and asked to add http://hl7.org/fhir/StructureDefinition/elementdefinition-defaulttype to the official core extension registry because CDA and other logical models need a defined default type when the instance or StructureDefinition does not otherwise identify one.

Initial application:
The issue was applied in core by e2e927509d, which added the defaulttype row to source/datatypes/elementdefinition-extensions-spreadsheet.xml. The context was corrected by f1f8b4f391 from ElementDefinition.type to ElementDefinition, and the extension's OID remains in source/oids.ini.

Additional context:
Standard extension definitions were later separated from the R5 core source into the FHIR Extension Pack. Core commit dd468d4f17 removed extension definitions from the R5 source, while the Extension Pack first-commit history includes StructureDefinition-elementdefinition-defaulttype.xml. The current Extension Pack README says these are the standard extensions referenced by core and logically part of the main FHIR expectation; its IG defines extension-registry.html, and the current published registry lists elementdefinition-defaulttype with context ElementDefinition. FHIR-41651 later updated this extension's description to say it is only for logical models and proposed a future move to the tooling IG, which is related Extension Pack/tooling work rather than a missing core-source change for FHIR-25440.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core checkout no longer owns the registry entry source, and the current Extension Pack source and published registry already define and list elementdefinition-defaulttype under the original canonical URL with canonical(StructureDefinition) value type and ElementDefinition context.

Recommendation:
Keep this audit commit as-is for FHIR-25440. Any remaining work to move or further explain the extension should be handled under FHIR-41651 in the FHIR Extension Pack or tooling IG, not by re-adding a duplicate core definition.
