Issue request:
FHIR-18428 was a Published/Persuasive FHIR-core technical correction from FHIR-I for STU3. It reported that clicking the ND-JSON link on the formats page showed the content under the JSON tab and requested that ND-JSON have its own tab; the Jira resolution was auto-approved.

Initial application:
The Jira comment points to Git commit fe9cc68c23d0d8a7be76fa28493e4f771c310cea, which changed source/nd-json.html from `<%fmtheader json%>` to `<%fmtheader ndjson%>` and added an ND-JSON tab to the then-current PageProcessor format header. Current source still has the separate NDJSON header mode on source/nd-json.html.

Additional context:
Current source/hierarchy.xml lists nd-json.html as a distinct page under Resource Definitions, and source/documentation.html links to it as a separate NDJSON Format page. Later NDJSON cleanup for FHIR-31425 is already represented on the combined branch and normalizes wording on the same page without reversing the separate-tab fix. The old in-repository PageProcessor path touched by the 2018 commit is no longer present in the current checkout, so there is no current Java source hunk to reapply.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the approved fix is already present in current build-scope source: the NDJSON page uses `fmtheader ndjson` rather than `fmtheader json`, and current navigation treats nd-json.html as its own format page.

Recommendation:
Keep this no-change audit commit. No further FHIR-core source work is indicated for FHIR-18428 unless a future publisher/template regression causes nd-json.html to render under the JSON tab again.
