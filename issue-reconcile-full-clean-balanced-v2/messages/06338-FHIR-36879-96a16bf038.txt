FHIR-36879: Audit search parameter definition clarification

Issue request:
FHIR-36879 was a Published FHIR-I change request, resolved Persuasive with Modification for R5, asking how to represent several parameters documented near search in CapabilityStatement/search parameter registries. The request listed search-result control parameters such as _sort, _count, _include, _revinclude, _summary, _total, _elements, _contained, and _containedType, general HTTP parameters such as _format and _pretty, and special parameters _query and _filter. The accepted resolution was that appropriate actual SearchParameter definitions had already been added and that search.html should explain why other parameters are not included as SearchParameter resources.

Initial application:
The issue appears to have been applied before this reconciliation. Commit 952e7fcef1 explicitly references FHIR-36879 and added the current search.html clarification that Search Result Parameters are not SearchParameter resources and do not appear in the search parameter registry. Earlier related work in 1fd6427cf7 added missing common Resource search parameter definitions after FHIR-26430, and later FHIR-39335 work in a5e2e453da restored R5 definitions that had been missed.

Additional context:
The linked Zulip thread shows the distinction that drove the resolution: common resource search parameters could receive formal definitions, but search-result parameters were not formally defined and CapabilityStatement declarations should not invent unresolved canonical definitions for them. The HTTP page separately defines _format and _pretty as general parameters for all RESTful interactions, not as SearchParameter resources. FHIR-I minutes mark FHIR-34332 as a duplicate of FHIR-36879 and record the Persuasive with Modification vote for FHIR-36879.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current active source/search.html already says search-result parameters do not have SearchParameter resources and do not appear in the search parameter registry; source/resource/bundle-Resource-search-params.xml contains current Resource SearchParameter entries for _query and _filter; and source/http.html defines _format and _pretty as general HTTP parameters.

Recommendation:
Keep this empty audit commit as-is. No current core source correction is needed for FHIR-36879; future work would be a new work-group decision if HL7 wants search-result control parameters to become formal SearchParameter resources, because that would change the current distinction between search filters and result/HTTP controls.
