FHIR-14142: Audit DeviceUsage alignment externally owned

Issue request:
FHIR-14142 was Published/Persuasive with Modification for R5. It asked to harmonize DeviceUseStatement with MedicationStatement by renaming source to informationSource with Organization as a target, renaming recordedOn to dateAsserted, adding category, renaming indication to reasonCode, adding reasonReference, adding context, and changing device to a code-or-reference choice to support class-level and negative/no-information device-use statements.

Initial application:
The requested R5 alignment was applied in the historical DeviceUseStatement source. Commit ce5720447c ("Updates on DeviceUseStatement") names FHIR-14142 and shows category, context, dateAsserted, informationSource, device code/reference, and reasonReference changes in the spreadsheet. Later R5 source converted the shape to DeviceUsage and CodeableReference, so the current element names are DeviceUsage.informationSource, DeviceUsage.dateAsserted, DeviceUsage.category, DeviceUsage.context, DeviceUsage.device, and DeviceUsage.reason rather than the older split reasonCode/reasonReference or device[x] representation.

Additional context:
FHIR-31478 later renamed DeviceUseStatement to DeviceUsage for R5, and an existing combined-branch audit commit for FHIR-31478 records that rename. FHIR-26308 later accepted the pre-applied DeviceUsage changes around this same family, and an existing combined-branch audit commit for FHIR-26308 records that the current DeviceUsage maintenance path moved out of core. Current source/fhir.ini has no active DeviceUsage resource entry; it retains only the historical cross-version alias DeviceUseStatement=@DeviceUsage. Commit 3b38b80cf2 removed DeviceUsage and related OO resources from active core build lists and changed the device module to link DeviceUsage to the OO Incubator IG.

AutoFHIR reconciliation:
This is an empty external-repo audit commit. No core source files were changed because DeviceUsage is no longer an active FHIR core build input. The retained inactive source/deviceusage StructureDefinition and the published R5/current OO Incubator DeviceUsage artifacts already carry the semantically accepted alignment, so editing inactive core files would not correct the current built core specification.

Recommendation:
Keep this audit commit as-is for FHIR core reconciliation. Future substantive DeviceUsage corrections should be handled in the OO Incubator source/publication path, not by editing inactive core source/deviceusage files. Do not reopen the old split reasonCode/reasonReference or device[x] wording unless the work group intentionally reverses the later CodeableReference representation.
