FHIR-19307: Audit CodeSystem hierarchy wording

Issue request:
FHIR-19307 was a Published/Persuasive STU3 vocabulary issue for FHIR-core CodeSystem. It asked to remove the normative CodeSystem hierarchy assertion that polyhierarchical code systems must use the trial-use subsumes extension, and to replace it with property-based guidance for additional parents plus the rule that CodeSystem operations must behave the same whether relationships are represented through properties or nested hierarchy.

Initial application:
The Jira comment cites git 80086b8f22b9b182c473fbb7b7a446d7aafbd37c, but that commit is unrelated to CodeSystem and changes Subscription notes only. A source pickaxe found c27b4eaede30c4537c55ae885110719ef3067ae0 as the actual CodeSystem application: it removed the subsumes-extension wording and added property/operation guidance in source/codesystem/codesystem-notes.xml.

Additional context:
CodeSystem is an active resource in source/fhir.ini, so source/codesystem/codesystem-notes.xml is in current build scope. The current source defines parent and child concept properties and its Concept Hierarchy section no longer mentions the subsumes extension. Later Published issue FHIR-39262 intentionally rephrased the same paragraph to say nested concepts are for single-tree hierarchies, properties allow polyhierarchies, and when hierarchy is represented with properties the relationships should be defined with properties rather than mixed nested hierarchy.

AutoFHIR reconciliation:
This is an empty no-change audit commit. The current source already satisfies FHIR-19307 after the later FHIR-39262 clarification: the incorrect subsumes-extension assertion is gone, parent/child properties are available for hierarchy relationships, and CodeSystem operations are still required to return the same result whether relationships are represented explicitly as properties or implicitly through nested concepts.

Recommendation:
Keep this audit commit as-is. Do not reintroduce the exact 2018 replacement sentence about additional parents because the 2023 FHIR-39262 wording is the later published work-group clarification for the same hierarchy section and preserves the intended property-based guidance without the single-parent ambiguity.
