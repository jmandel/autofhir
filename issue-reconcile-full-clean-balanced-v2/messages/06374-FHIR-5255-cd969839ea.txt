FHIR-5255: Audit Condition category wording

Issue request:
FHIR-5255 is a Published/Persuasive Patient Care DSTU1 ballot comment for Condition.category. It asked to replace the duplicated example wording "finding | Condition | diagnosis | concern | condition" with wording aligned to the then-current value set: "finding | complaint | diagnosis | symptom | etc." The Jira comments and PC block vote recorded that the change was accepted and already done.

Initial application:
No git commit explicitly mentioning FHIR-5255 was found. The initial imported Condition spreadsheet already contained the proposed complaint/symptom/finding/diagnosis element wording while the ConditionCategory binding definition still contained the older duplicated list. Commit b62a71399e6c7c3092a36b37b627835e687e36d1 later removed the example list from both the Condition.category element definition and the ConditionCategory binding definition, leaving the neutral definition "A category assigned to the condition." and updating the binding metadata.

Additional context:
Condition is an active resource in source/fhir.ini. The current authoritative StructureDefinition keeps Condition.category as CodeableConcept with an example binding to http://hl7.org/fhir/ValueSet/condition-category and no obsolete example list. The current value set composes the THO condition-category code system. Later Published Patient Care issues FHIR-10091, FHIR-10404, FHIR-10611, and FHIR-11156 replaced the old four-code complaint/symptom/finding/diagnosis framing with encounter-diagnosis and problem-list-item guidance; FHIR-8872 also records that symptom-specific category value set text became not applicable after the September 2016 WGM decision. More recent source commits further removed the old category short display and clarified it as "Classification of type of condition."

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build already avoids the DSTU1 mismatch that FHIR-5255 identified, and reintroducing a local example list would conflict with later Patient Care decisions and the current example binding/value set design.

Recommendation:
Keep this no-change audit. Future changes to Condition.category examples or codes should follow current Patient Care and terminology governance rather than resurrecting the DSTU1 ballot wording.
