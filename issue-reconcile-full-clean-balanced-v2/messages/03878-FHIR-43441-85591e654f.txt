FHIR-43441: Audit ServiceRequest workflow alignment

Issue request:
FHIR-43441 was an Applied OO change request for R6 asking ServiceRequest to align with the Workflow Request pattern. The final Persuasive with Modification resolution removed ServiceRequest.instantiatesCanonical and ServiceRequest.instantiatesUri, removed their instantiates-canonical and instantiates-uri search parameters, removed the corresponding Request.instantiates mappings, and added Workflow mappings from ServiceRequest.category to Request.category and ServiceRequest.orderDetail.parameterFocus[x] to Request.product. It also directed use of the Workflow instantiation extensions instead of keeping local elements.

Initial application:
The Jira application comment identifies commit 696cf9c646. That commit changed active ServiceRequest source by deleting the two instantiates elements from source/servicerequest/structuredefinition-ServiceRequest.xml, deleting the two search parameters from source/servicerequest/bundle-ServiceRequest-search-params.xml, and adding the two requested Workflow mappings to the ServiceRequest StructureDefinition. Current history shows no prior Issue-Reconcile-Key commit for FHIR-43441 on the combined branch.

Additional context:
ServiceRequest is active in source/fhir.ini and the checked StructureDefinition/search-parameter bundle are authoritative ServiceRequest build inputs. Later ServiceRequest commits, including FHIR-54847 work on parameterFocus[x], refined nearby content while preserving the Request.product mapping. The FHIR Extension Pack contains the replacement Workflow extension family and marks the old workflow-instantiatesCanonical/workflow-instantiatesUri extensions as retired/deprecated in favor of workflow-generatedFrom, workflow-compliesWith, or workflow-adheresTo. The only remaining ServiceRequest-local mentions of the removed elements are in source/servicerequest/servicerequest.svg, a generated-looking diagram artifact; the run rules specifically avoid source-changing commits whose only edit would be a checked-in SVG/diagram.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active ServiceRequest StructureDefinition no longer defines instantiatesCanonical or instantiatesUri, the active ServiceRequest search-parameter bundle no longer defines instantiates-canonical or instantiates-uri, and the requested Workflow mappings to Request.category and Request.product are present. The stale SVG is recorded as audit evidence rather than manually edited.

Recommendation:
Keep this audit commit as-is. If diagram artifacts are regenerated as part of normal publication tooling, the ServiceRequest SVG should be regenerated from the authoritative StructureDefinition, but no manual core source fix is warranted for FHIR-43441.
