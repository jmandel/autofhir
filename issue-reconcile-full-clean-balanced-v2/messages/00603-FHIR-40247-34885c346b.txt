FHIR-40247: Align Endpoint payload ModelInfo

Issue request:
FHIR-40247 was Published with a Persuasive resolution for R5. It asked to represent specific supported combinations of Endpoint.payloadType and Endpoint.payloadMimeType by moving them under a repeating Endpoint.payload backbone, with payload.type as an example-bound CodeableConcept and payload.mimeType as a required-bound code, and to update the payload-type search parameter to Endpoint.payload.type.

Initial application:
The issue was initially applied in core by a5ee70eef51c2aa87c5067b24e9a4eecc4938e26, which added Endpoint.payload, nested payload.type and payload.mimeType, and updated Endpoint examples. Follow-up commits 1ad1ec7113fec9071016db69aab8ea9d6b88ce6a and 41eaf64dbc9d4acf4963395dc799894418ed8150 corrected the payload-type search parameter to Endpoint.payload.type and fixed related wording.

Additional context:
Current source/fhir.ini keeps Endpoint and Library active, and publish.ini copies source/library/library-fhir-model-definition-content.xml into the build. The authoritative Endpoint StructureDefinition and search parameter bundle already use Endpoint.payload.type and Endpoint.payload.mimeType, while fhir.ini's Endpoint.payloadType and Endpoint.payloadMimeType entries are cross-version aliases to the new paths. The remaining stale build-scope surface was the FHIR ModelInfo Library, which still exposed Endpoint.payloadType and Endpoint.payloadMimeType. FHIR-39616 later added profile metadata under the same Endpoint.payload backbone and is reconciled by a separate follow-up commit.

AutoFHIR reconciliation:
This commit updates the active FHIR model-definition Library so Endpoint has a repeating payload element of type FHIR.Endpoint.Payload, with nested type and mimeType list metadata matching the FHIR-40247 backbone. It also regenerates the Library.data attachment so source/library/library-fhir-model-definition.xml remains synchronized with source/library/library-fhir-model-definition-content.xml.

Recommendation:
Keep this source fix as-is. It completes the FHIR-40247 application on the active core ModelInfo surface without changing the already-correct Endpoint StructureDefinition, examples, search parameter expression, or cross-version aliases.
