FHIR-32382: Audit Device scope boundary clarification

Issue request:
FHIR-32382 was a Published, Persuasive with Modification OO change request for R5. It asked the Device Scope and Usage text to be clearer that UDI is optional and jurisdiction/context dependent, especially for reusable or disposable non-implantable devices, and asked Boundaries and Relationships to clarify when device use, placement/removal, monitoring, and requests should use DeviceUsage, Observation, ServiceRequest/DeviceRequest, or Procedure. The final disposition was to accept the Device Scope-Boundary-Relationships document through FHIR-20574 and use that document to resolve FHIR-32382 and sibling Device scope/boundary issues.

Initial application:
The issue was applied before this reconciliation by git commit 3c23148747a7d0fead21ff9afaab2fc3bb65eae9 (apply #20574), whose message explicitly lists FHIR-32382. That commit rewrote the Device introduction with broader device scope wording, clarified UDI use as appropriate or necessary, and added a Device boundary list covering DeviceRequest, DeviceUsage, Observation, Procedure, and medication/device distinctions. Later source refactors retained the accepted substance while trimming long category detail and updating links.

Additional context:
Device remains active in the current core build through source/fhir.ini, and current source/device/device-introduction.xml already states that UDI is documented where appropriate or necessary and lists the relevant resources for device requests, patient-reported/second-hand use, observations, procedures, associations, and related workflow. DeviceUsage is no longer an active core resource in source/fhir.ini after the OO resource externalization, so the current Device narrative correctly points to the OO incubator DeviceUsage artifact rather than reactivating local core DeviceUsage source. The OO 2022-06-13 HCP minutes record the 10-0-0 motion to accept the Device Scope-Boundary-Relationships document and disposition FHIR-32382 through it. Direct Zulip searches found no conflicting community discussion.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current build-scoped Device source already conveys the accepted rule: Device can represent broad device instances with optional UDI information; DeviceRequest covers orders/requests; DeviceUsage covers patient-reported or second-hand use not otherwise covered by a procedure; Observation captures measurements generated by devices; Procedure captures device implantation, explantation, and other clinical actions; and DeviceAssociation covers associations/custodianship. Adding more prose here would duplicate existing guidance and risk drift, especially now that DeviceUsage is outside core.

Recommendation:
Keep this no-change audit commit. No core source follow-up is needed for FHIR-32382 unless OO opens a new issue to revise the Device module or the external OO incubator DeviceUsage guidance under the current R6 resource set.
