FHIR-25381: Correct Organization availability example hours

Issue request:
FHIR-25381 is a Published/Persuasive PA change request raised against R4 and applied for R5. It asked for a standard way to communicate Organization telephone/opening hours. The accepted resolution created the Availability datatype, made it available through a standard extension on ExtendedContactDetail, and replaced the prior resource-specific availability structures on PractitionerRole, Location, and HealthcareService with Availability.

Initial application:
The core source history shows substantial prior application. Commit a9d7aa77e8 migrated Organization.contact to ExtendedContactDetail through the related Organization contact work, commit 447e89f4a4 introduced the shared Availability datatype and moved HealthcareService, Location, and PractitionerRole availability structures to it, and commit d763653d2d added the extended-contact-availability standard extension plus an Organization example using valueAvailability. Later source history moved the active Organization example to source/organization/organization-hl7.xml, copied a negative invariant fixture from it, and moved the extension definition itself out of core into the FHIR Extension Pack.

Additional context:
Current source/fhir.ini actively includes Availability and ExtendedContactDetail as metadatatypes and Organization, Location, PractitionerRole, and HealthcareService as active resources. The active StructureDefinitions already use Availability where the Jira resolution required it, and the FHIR Extension Pack defines http://hl7.org/fhir/StructureDefinition/extended-contact-availability for ExtendedContactDetail, ContactDetail, and Address with value[x] typed as Availability. PA May 2022 minutes record the 7-0-0 persuasive vote and the action to take the datatype/extension question to FHIR-I/MnM; MnM minutes and the Zulip committers thread confirm Availability was approved as an extension value datatype. The remaining in-scope problem was the Organization example introduced by the extension application: it advertised Monday-Friday availability with a 09:00 start but a 07:00 end, which reads as closing before opening rather than ordinary daytime opening hours.

AutoFHIR reconciliation:
This commit fixes that seed-scope example error by changing availableEndTime from 07:00:00 to 17:00:00 in the active Organization/hl7 example and in the copied org-1 negative invariant fixture. It leaves the datatype, resource structures, extension URL, extension-pack definition, and related availability guidance unchanged because those already reflect the approved Jira decision and later source refactors.

Recommendation:
Keep this source fix. It completes the FHIR-25381 reconciliation in core by preserving the already-applied Availability and standard-extension design while correcting the only misleading current core example found during the audit. No additional core source change is needed unless PA or MnM later revisits the extension contexts or the Extension Pack owner chooses to clean up extension-pack-only wording.
