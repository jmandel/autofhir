FHIR-13759: Restore AuditEvent detail binary encoding guidance

Issue request:
FHIR-13759 was a Published Security WG change request for STU3, resolved Not Persuasive with Modification. It asked whether AuditEvent.entity.query and AuditEvent.entity.detail.value base64Binary content needed a fixed character encoding or a way to say how decoded bytes should be interpreted. The approved resolution was not to mandate a universal encoding, but to add comments explaining that the meaning and secondary encoding are event-specific and must be understood by the consuming application.

Initial application:
Git commit f36c03dbf21c applied Security update GF#13759 in the STU3-era AuditEvent spreadsheet source, adding the requested comment to both AuditEvent.entity.query and AuditEvent.entity.detail.value. The source was later converted to source/auditevent/structuredefinition-AuditEvent.xml, and the query-side comment remains in current source.

Additional context:
AuditEvent is active in source/fhir.ini. FHIR-32475 later broadened AuditEvent.entity.detail.value[x] from string/base64Binary to the current choice of computable datatypes plus base64Binary; its implementation commit bd6dd636238 removed the older FHIR-13759 comment from the detail value element while making the datatype change. FHIR-32475 did not reverse the encoding clarification, and current source still allows valueBase64Binary, so the missing detail-value guidance remained a current-spec gap.

AutoFHIR reconciliation:
Restored the FHIR-13759 clarification to the active AuditEvent StructureDefinition at AuditEvent.entity.detail.value[x], scoped specifically to valueBase64Binary and updated for current element names by using AuditEvent.entity.role and AuditEvent.entity.detail.type rather than the obsolete AuditEvent.entity.type wording. No generated diagram or out-of-build artifact was edited.

Recommendation:
Keep this commit as-is. It restores the applied Security WG clarification without undoing the later FHIR-32475 datatype expansion; no broader AuditEvent encoding policy change is indicated by the available Jira, source, git, Zulip, or Confluence evidence.
