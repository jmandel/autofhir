FHIR-13615: Audit DiagnosticReport identifier mapping

Issue request:
FHIR-13615 was a Published/Persuasive STU3 OO change request to update the DiagnosticReport.identifier HL7 v2 mapping so it explains how to handle unique and non-unique filler identifiers.

Initial application:
The issue was applied by git commit b434255fbc971400e662a6a7409206826628b33b ("GF#13615"), which changed the DiagnosticReport spreadsheet v2 mapping from OBR-51 to text distinguishing globally unique filler IDs from non-globally unique filler/placer identifiers combined with the universal service ID. Later source rework commit 33b409a4b6d544598262f2f074ebb4b6dc466157 migrated that same mapping into source/diagnosticreport/structuredefinition-DiagnosticReport.xml.

Additional context:
DiagnosticReport is an active resource in source/fhir.ini, and the current authoritative StructureDefinition source still contains the FHIR-13615 mapping on DiagnosticReport.identifier. The originating Zulip thread confirms the issue arose from ORU^R01 mapping discussion about combining a group/order identifier with the test code when a standalone filler identifier is not unique. A later R6 issue, FHIR-54545, has reached Resolved - change required / Ready_to_Apply and would replace this mapping because placer/filler order numbers belong on basedOn rather than DiagnosticReport.identifier, but that is a separate unapplied R6 decision outside this seed's applied/published reconciliation scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source already preserves the FHIR-13615 applied mapping, and applying the later FHIR-54545 replacement under this historical seed would conflate two separate work-group decisions.

Recommendation:
Keep this audit commit as-is for FHIR-13615. Handle FHIR-54545 separately when the R6 Ready_to_Apply work is in scope, including replacing the DiagnosticReport.identifier v2 mapping, updating basedOn mappings, and removing the DiagnosticReport identifier note as directed there.
