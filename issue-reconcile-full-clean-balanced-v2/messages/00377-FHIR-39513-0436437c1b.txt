FHIR-39513: Audit AllergyIntolerance participant function reversion

Issue request:
FHIR-39513 is Applied/Persuasive for R6. It objected that AllergyIntolerance.participant.function used a typed relationship anti-pattern and that core relationships should instead be represented explicitly for the common cases. Its final resolution says that, as per FHIR-44517, AllergyIntolerance.participant is removed in R6 with a reversion to AllergyIntolerance.recorder and AllergyIntolerance.asserter to align with R4.

Initial application:
The Jira comments cite the same HL7/fhir#3141 commits as FHIR-44517: ed99dff, a4fa606, and 1f388a4. Commit ed99dff directly changed the AllergyIntolerance StructureDefinition, examples, and search parameter source to restore recorder/asserter and retire active participant use. Those commits are already ancestors of the current combined branch.

Additional context:
FHIR-39513 is tightly coupled to the FHIR-44517 seed because it supplies the participant/function anti-pattern rationale for the same AllergyIntolerance reversion. The issue also mentions FHIR-34395 as the issue that introduced participant and FHIR-39602 as a related Condition question, but those are background for this AllergyIntolerance-only audit. Patient Care May 2024 minutes state that FHIR-39513 was solved because participant was removed.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active AllergyIntolerance resource source contains recorder and asserter, no active participant after stripping XML comments, and examples/search parameters are consistent with the reversion. A checked-in SVG still shows participant, but it is a generated-looking diagram artifact and was not edited without an authoritative source change.

Recommendation:
Keep this audit commit as-is. Treat any remaining participant diagram display as a diagram-refresh concern, not as a normative source defect for FHIR-39513.
