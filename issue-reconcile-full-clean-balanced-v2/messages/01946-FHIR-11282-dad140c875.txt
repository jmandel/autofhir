FHIR-11282: Audit ImagingStudy interpreter cardinality

Issue request:
FHIR-11282 was a Published/Persuasive II change request against DSTU2 ImagingStudy. It asked to update ImagingStudy.interpreter cardinality from 0..1 to 0..* because more than one interpreter can exist for an imaging study.

Initial application:
The issue was applied in commit b838ed23f345f4271d38d8146ca240d4a4ef1a89, "Updates to ImagingStudy for CP GF#10740, GF#11282, and GF#11285". That commit changed the then-authoritative ImagingStudy spreadsheet source so the ImagingStudy.interpreter row card changed from 0..1 to 0..* in both imagingstudy-spreadsheet.sheet.txt and imagingstudy-spreadsheet.xml.

Additional context:
ImagingStudy is active in the current build, but the old ImagingStudy.interpreter element is no longer part of the current authoritative ImagingStudy StructureDefinition or search-parameter bundle. Later Published/Persuasive issue FHIR-38922 explicitly removed ImagingStudy.interpreter and its search parameter because interpreter information is better represented by associated DiagnosticReport or Composition resources. Commit e4628bf37f62e48e5292b2d73de592a63b012e80 applied that removal. Current DiagnosticReport.resultsInterpreter remains 0..* for report conclusions and interpretations. A focused source search found only one stale ImagingStudy.interpreter reference in source/genomicstudy/imagingstudy.svg; source/fhir.ini has no active GenomicStudy resource entry, and the remaining hit is a generated-looking SVG/link rather than conformance source.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The DSTU2 cardinality change was applied while ImagingStudy.interpreter existed, and reintroducing or editing that removed element now would contradict the later FHIR-38922 final decision. The only residual SVG occurrence is outside the authoritative ImagingStudy source and does not justify a source-changing reconciliation commit for this cardinality issue.

Recommendation:
Keep this no-change audit as-is. Do not restore ImagingStudy.interpreter for FHIR-11282; if editors want to clean the stale source/genomicstudy/imagingstudy.svg cross-link, handle it as a separate diagram/build-scope cleanup rather than as this DSTU2 cardinality issue.
