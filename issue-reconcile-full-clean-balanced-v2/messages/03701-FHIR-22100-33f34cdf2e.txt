FHIR-22100: Clarify ConceptMap unmapped modes

Issue request:
FHIR-22100 was a Published/Persuasive Vocabulary issue for R5. It asked to clarify the conceptmap-unmapped-mode descriptions because the old 'provided' wording did not clearly say that ConceptMap.group.unmapped.mode=provided makes $translate return the source code when no explicit map is found, and it requested clearer descriptions for provided, fixed, and other-map.

Initial application:
The issue was initially applied by commit 9500b398d1d850a06cd180c82ce330e4809a2b49, which changed the unmapped-mode CodeSystem descriptions toward the Jira resolution text. Later ConceptMap R5 work replaced the confusing 'provided' code with 'use-source-code' and migrated ConceptMap2 back into the active ConceptMap source, but left the current ConceptMap notes page with the old 'provided' code and left the CodeSystem definitions less precise about the renamed current elements.

Additional context:
ConceptMap is an active resource in source/fhir.ini, and the inspected CodeSystem and notes source feed current ConceptMap terminology and narrative. Related Published issues FHIR-32546 and FHIR-32545, already represented on the combined branch, changed the current mode code to 'use-source-code' and renamed ConceptMap.group.unmapped.url to ConceptMap.group.unmapped.otherMap. The current source also supports fixed mappings through ConceptMap.group.unmapped.code or ConceptMap.group.unmapped.valueSet, so the old seed wording needed to be interpreted through these later R5 changes rather than copied literally.

AutoFHIR reconciliation:
This commit updates the active ConceptMap unmapped-mode CodeSystem definitions and the Handling Unmapped Codes narrative. It replaces stale 'provided' narrative wording with 'use-source-code', clarifies that the source code comes from the $translate source input, identifies fixed-mode sources as ConceptMap.group.unmapped.code or ConceptMap.group.unmapped.valueSet, and changes the other-map description to reference ConceptMap.group.unmapped.otherMap.

Recommendation:
Keep this source-changing commit. It is a narrow current-spec clarification for FHIR-22100 that preserves the later FHIR-32545/FHIR-32546 semantics already audited on the combined branch and avoids re-deciding those issues.
