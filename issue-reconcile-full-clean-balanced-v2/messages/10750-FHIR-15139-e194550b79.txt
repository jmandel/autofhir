FHIR-15139: Audit Bundle fullUrl canonical rule

Issue request:
FHIR-15139 was a Published/Persuasive with Modification STU3 FHIR-I issue for FHIR-core-Feed. It asked whether Bundle.entry.fullUrl may be a canonical URL and whether a urn:uuid fullUrl must match Resource.id; the approved answer was that fullUrl is an absolute endpoint URL, not the canonical URL, while urn:uuid fullUrls do not match the RESTful URL regex and therefore need not match Resource.id.

Initial application:
Jira records Grahame Grieve's svn revision 14417 application comment. That SVN revision is not directly represented in the current Git history, but the first Git-traceable Bundle StructureDefinition source migration already included the essential applied note: fullUrl is not the same as the canonical URL, but is an absolute URL for an endpoint serving the resource, and these can coincide on the canonical server.

Additional context:
Bundle is active in source/fhir.ini, so source/bundle/structuredefinition-Bundle.xml is current build input. Later fullUrl issue-family decisions already represented on the combined branch refined the same area: FHIR-17061 and FHIR-17062 audited the id-disagreement and RESTful URL matching wording, FHIR-31422 kept arbitrary URI schemes valid for fullUrl, and FHIR-43101/FHIR-43106 refined RESTful type/id matching and omission exceptions. A current source search did not find remaining StructureDefinition, ValueSet, CodeSystem, SearchParameter, OperationDefinition, or similar canonical conformance-resource URLs used as Bundle.fullUrl values.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active Bundle.entry.fullUrl comment already says fullUrl may be a URN or an absolute URL that does not end with Resource.id, RESTful-looking fullUrls must match the resource type and id, and fullUrl is not the same as the canonical URL. That satisfies the Jira decision while preserving later accepted fullUrl clarifications.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-15139 unless FHIR-I opens a separate issue for a specific current example whose fullUrl is demonstrably neither a RESTful endpoint URL nor another allowed URI identifier.
