FHIR-12366: Audit search-parameter outcome locations

Issue request:
FHIR-12366 was a Published/Persuasive FHIR-core OperationOutcome change request from the DSTU2 era. It asked for the definition and supporting detail for OperationOutcome.location to explain how to populate the location when search parameters are unrecognized; the recorded resolution was to add an example based on the notes in the definitions, and the Jira comments say this had already been done.

Initial application:
No source commit that explicitly mentions FHIR-12366 was found. The relevant source history instead predates the Jira item: GForge #7955 added the search failure OperationOutcome example, and GForge #8450, commit 696c4075bab4f75ee97c531e4c5bd9d8f7bd2df9, added OperationOutcome location notes for HTTP query parameters and changed the search failure example location from name:exact to http.name:exact. That matches the later Jira comment that the requested detail was already present.

Additional context:
OperationOutcome is an active resource in the current build. The current source still carries the requested search-parameter example and the OperationOutcome.issue.location definition says HTTP errors use the http-plus-parameter-name convention. Later FHIR-17589 deprecated OperationOutcome.issue.location in favor of OperationOutcome.issue.expression and reworked the notes to emphasize expression-based reporting, including HTTP header/query parameter examples. The later deprecation changes how new guidance should be written, but it does not make the old FHIR-12366 request incomplete.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current specification already preserves the needed implementer guidance through the active search failure example, the location definition, and the current expression notes; adding more local prose about deprecated issue.location would duplicate existing guidance and risk drifting from the post-FHIR-17589 expression-first direction.

Recommendation:
Keep this no-change audit. If the work group later wants to expand search-parameter error-location guidance, do it against OperationOutcome.issue.expression rather than adding more normative weight to the deprecated OperationOutcome.issue.location element.
