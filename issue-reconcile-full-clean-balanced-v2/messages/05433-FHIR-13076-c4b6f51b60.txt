FHIR-13076: Audit NUCC provider taxonomy sources

Issue request:
FHIR-13076 was a Published/Persuasive with Modification FHIR-core Vocab change request for MetadataResource asking that the NUCC Provider Taxonomy value set resolve correctly. The Jira description said provider-taxonomy was defined in terminologies but commented out in bindings.xml and that valueset-use-context also had the provider taxonomy reference commented out. The final Jira resolution recorded that the issue had already been resolved.

Initial application:
No git commit explicitly mentions FHIR-13076. The relevant initial application is in the same UsageContext value-set family: SVN 11663, imported as git commit 08d280b8e8593f627923e0cade06a02eea8d7d2b for FHIR-13059, added the provider-taxonomy value set and use-context references but left ProviderTaxonomy disabled and the use-context include commented because it did not resolve. The immediately following git commit 8b16115d880b33726d98fd973da248d688742494 removed the disabling prefix from the ProviderTaxonomy binding, changed valueset-use-context to include the NUCC code system directly, and fixed the provider-taxonomy system URI.

Additional context:
The FHIR-13076 Jira comment records Bryn Rhodes and Rob Hausam confirming in July 2018 that the ProviderTaxonomy reference in bindings.xml was adequate, the relevant value sets worked without failing the build, and empty expansions were expected because NUCC codes require a license. Current source keeps the same model: the active terminology binding names ProviderTaxonomy, the provider-taxonomy ValueSet composes over http://nucc.org/provider-taxonomy, valueset-use-context includes that code system, and UsageContext's user additional binding points at http://hl7.org/fhir/ValueSet/provider-taxonomy. The related FHIR-13059 UsageContext value-set audit is already represented on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already preserves the accepted FHIR-13076 outcome, and adding NUCC expansion content would contradict the Jira discussion that implementers must obtain licensed codes from NUCC.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-13076 unless the work group later chooses to change the external NUCC code system handling or licensing guidance.
