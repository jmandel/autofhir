FHIR-32812: Audit Device name type values

Issue request:
FHIR-32812 was a Published OO change request for R5 asking to remove the "other" code from DeviceNameType and, if no out-of-set name type could then be conveyed, to consider relaxing Device.deviceName.type to an extensible CodeableConcept or Coding. The final resolution was Persuasive with Modification: remove "other" in accordance with FHIR-20639, but do not make that value set extensible as part of this issue.

Initial application:
The issue was applied through the FHIR-20639 change family rather than by a separately named FHIR-32812 source commit. Commit cae641cfad replaced the DeviceNameType code system with registered-name, user-friendly-name, and patient-reported-name, removing udi-label-name, manufacturer-name, model-name, and other. Commit c4a95b2b91 updated the Device and DeviceDefinition name type short/definition text to the same three codes, and the linked merge dc516986c5 is cited from the Jira comments.

Additional context:
The Jira comment that mentions FHIR-20369 appears to be a typo; FHIR-20369 is an unrelated LIVD markdown rendering issue, while FHIR-20639 is the DeviceNameType replacement referenced by the resolution and minutes. OO minutes on 2021-10-11 and 2021-10-25 record the linked discussion: remove "other," determine extensibility, and then let FHIR-20639 take care of the seed. Later applied issue FHIR-43164 intentionally changed DeviceDefinition.deviceName.type and Device.name.type from required code to extensible CodeableConcept for R6, so the current extensible binding is a later work-group decision, not an unfinished part of FHIR-32812.

AutoFHIR reconciliation:
No source files were changed. The active DeviceNameType CodeSystem source no longer contains an "other" concept, active Device and DeviceDefinition name type definitions list only registered-name, user-friendly-name, and patient-reported-name, and fhir.ini lists Device and DeviceDefinition as active resources. The remaining extensible CodeableConcept binding is intentionally preserved because it is governed by later FHIR-43164.

Recommendation:
Keep this audit commit as-is. Do not re-add an "other" code, and do not use FHIR-32812 to revert the current extensible CodeableConcept binding; any concern with that binding belongs to the later FHIR-43164 decision family.
