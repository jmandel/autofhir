FHIR-8686: Audit search range-above date correction

Issue request:
FHIR-8686 was Published/Persuasive for FHIR-core Search. It reported that the Prefixes table's "range above the value" date example had copied the range-below wording and incorrectly said the range after 2015-08-12T05:23:45 included times "up to" that instant. The Jira discussion asked whether the correction should be after the literal instant or after the date/time value's implicit range; the editor response recorded this as a QA typo fix for "after", not "up to".

Initial application:
The issue was applied in git commit 925f1eec721501c5b46240b172e2400ae12369b0, imported from SVN revision 7004, which changed source/search.html from "includes any time up to 2015-08-12T05:23:45.000000000000000" to "includes any time after 2015-08-12T05:23:45.000000000000000". No existing Issue-Reconcile-Key: FHIR-8686 commit was present on the combined branch before this audit.

Additional context:
Later search-prefix work refined the same active Search page rather than preserving the original 2015 example verbatim. FHIR-26311 clarified implicit range behavior for prefix searches. FHIR-43208, already represented on the combined branch, split decimal and date/time examples and made less-precise date examples explicit. The current source now says the range after 2015-08-12T05:23:45 starts at 2015-08-12T05:23:46 and the range after 2015-08 starts at 2015-09-01, which matches the 2024 implementers discussion that range-above for dates is the time after the date value's implicit interval. FHIR-40319 is also already represented on the combined branch for nearby prefix-definition cleanup. FHIR-51077 remains Resolved - change required rather than Applied/Published and is not decided here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The original copy/paste defect is absent from source/search.html, and the current wording is better interpreted as a later, final clarification of date range-above semantics rather than a regression against FHIR-8686.

Recommendation:
Keep this audit commit as-is. Do not revert the current 2015-08-12T05:23:46 and 2015-09-01 examples to the older 2015 wording; any remaining search range table cleanup should be handled through the later tickets in their own scope, especially FHIR-51077 if and when it becomes an applied/published reconciliation target.
