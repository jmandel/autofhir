FHIR-51028: Audit Measure stratifier type example

Issue request:
FHIR-51028 was an Applied CQI change request for R6 asking Core to address the measure-stratifier example CodeSystem and ValueSet. The original proposal asked to remove the example labeling and experimental flags, but the final Persuasive with Modification resolution instead kept this as a clearly labeled Measure Stratifier Type example: rename measure-stratifier-example/Measure Stratifier Example to measure-stratifier-type-example/Measure Stratifier Type Example, change code age to age-range, change region to facility, and update affected definitions and references.

Initial application:
The issue was applied by HL7/fhir PR #4050. Commit 18df653fdc321d3e20a95d14638e59a6d41168d7 renamed the CodeSystem and ValueSet source files and URLs, updated the Measure and MeasureReport bindings, adjusted the OID registry entries, and changed the concepts to age-range, gender, and facility. Commit f43fbf565a77bf872216d73bce2ef961e739462c then added Measure and MeasureReport ballot notes describing FHIR-51028 as clarifying that examples are experimental content. No prior Issue-Reconcile-Key commit for FHIR-51028 existed on the combined branch.

Additional context:
Measure and MeasureReport are active resources in source/fhir.ini, so the terminology source and bindings in their folders are in current build scope. The June 2025 TSMG minutes that motivated the Jira issue record a policy against example code systems in THO, but also note that experimental flags describe example code system intent in IGs; FHIR-51028 comments likewise clarify that Core may keep a clearly labeled example while the intended production Measure Stratifier Type terminology matures elsewhere. Related QM/UTG work such as FHIR-49756 and UP-702 is outside this Core source reconciliation and does not require an additional Core change now.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current Core source already uses measure-stratifier-type-example for the CodeSystem, ValueSet, OIDs, Measure bindings, MeasureReport bindings, and Measure $evaluate parameter binding; the CodeSystem concepts match the final resolution's age-range and facility changes. The retained experimental=true values are consistent with the applied follow-up note and the final modified resolution, so changing them during this reconciliation would override the work-group's applied compromise.

Recommendation:
Keep this audit commit as-is. Revisit only if CQI/TSMG later finalizes production THO terminology for measure-stratifier-type and opens a final Core issue to replace or rebind the example terminology.
