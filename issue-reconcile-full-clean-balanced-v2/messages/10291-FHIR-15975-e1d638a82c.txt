FHIR-15975: Audit deletion safety checklist

Issue request:
FHIR-15975 was a Published/Persuasive FHIR-core STU3 change request asking the Implementer's Safety Checklist to include checks/testing that deletions of records are properly documented and handled. The resolution was to make the change.

Initial application:
The issue was applied in svn revision 14463, mirrored as git commit cf887ff87350f763cd0b2ad9cf93b5187dba645f ("GF#15975 - ad safety note about deleted records"), which added deletion-record checklist wording to source/safety.html. A later safety-page refactor in 68f6cca29ae4d06f089f338982a2b98269e1a48a kept the deletion material as a dedicated "Deletion Safety Checks" section, and FHIR-22500/commit 76ce9865e683576c6712b6d0c6860272de60ad13 added a formal CodeSystem that includes the same deletion checklist entries.

Additional context:
The current build scope includes source/safety.html through source/hierarchy.xml and other core page references, and includes source/codesystem/codesystem-safety-entries.xml through the active [codesystems] entry in source/fhir.ini. The Zulip thread cited by the Jira records the safety concern: systems need to handle deleted or no-longer-current clinical records explicitly rather than silently omitting them. No Confluence references or conflicting community evidence were found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current safety page already has a "Deletion Safety Checks" section requiring implementers to check whether each resource can be deleted or marked incorrect/no-longer-relevant, ensure deletions or equivalent status updates propagate to replicated copies, and document deleted resources with deleted/error cases in sandbox test data. The active CodeSystem mirrors these deletion checklist items for formal references.

Recommendation:
Keep this no-change audit commit as-is. No follow-up source work is needed for FHIR-15975 unless the work group later decides to change the deletion policy itself or require additional conformance language beyond the current informative safety checklist.
