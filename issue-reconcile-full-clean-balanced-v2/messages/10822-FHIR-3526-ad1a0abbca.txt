FHIR-3526: Audit slicing discriminator reference paths

Issue request:
FHIR-3526 was a Published/Persuasive with Modification FHIR-core StructureDefinition issue asking that slice discriminator syntax stop implicitly jumping through ResourceReference to the referenced resource, so profiles could discriminate on elements or extensions carried on the reference itself. The approved DSTU-era resolution was to make the reference traversal explicit while allowing extension-based discriminator paths on the reference element.

Initial application:
The Jira comments say the issue was already applied in October 2014. No commit explicitly names FHIR-3526, but the same historical window includes commit 365400a19a, which updated discriminator documentation and examples to distinguish reference-target paths such as item.reference.name from reference-entry extension paths such as item.extension.url.

Additional context:
The current specification has since replaced the old ResourceReference wording with Reference and expresses discriminator paths as a restricted FHIRPath subset. Later related work, including FHIR-23035 and FHIR-27532, refined the same discriminator-path documentation by clarifying resolve() and aligning the simple FHIRPath function list, rather than restoring implicit reference traversal.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current build-scope source already supports the requested distinction: ElementDefinition.slicing.discriminator.path points to the simple FHIRPath subset; profiling.html lists extension(url) for selecting an extension and resolve() for slicing across resource boundaries; the examples show item.extension('http://acme.org/extensions/test').value for an extension on the sliced item separately from item.resolve().code for a referenced target resource; and fhirpath.html lists .extension("url") and .resolve() as allowed simple FHIRPath functions.

Recommendation:
Keep this audit commit as-is. No FHIR-core source edit is needed for FHIR-3526 unless a future work group decision changes the restricted FHIRPath discriminator model; adding duplicate local prose would risk drifting from the authoritative ElementDefinition, Profiling, and FHIRPath sections.
