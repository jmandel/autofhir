FHIR-5796: Audit contained resource metadata rules

Issue request:
FHIR-5796 was a Published/Persuasive FHIR-core BaseResource change request raised against DSTU1. It asked to prohibit meta.versionId and meta.lastUpdated on contained resources because only the root resource is independently versioned or updated, and also noted that meta.deleted should be removed if it survived.

Initial application:
The issue was applied in svn revision 4609, mirrored in git as 612bb5891be2abc43dd06bacbdfcbf853aac0213 with the subject "task #5796 - remove meta.deleted and make rules about meta in contained resources". That commit removed Meta.deleted from the Meta datatype spreadsheet and added the DomainResource invariant for no meta.versionId or meta.lastUpdated in contained resources; later source refactors preserved the rule as dom-4.

Additional context:
DomainResource is active build input in source/fhir.ini and is part of the infrastructure normative package. Current source also repeats the contained-resource metadata prohibition in the references narrative. A later Zulip implementer thread cited the same references.html rule and no issue-key or Confluence search found conflicting work-group evidence.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because current DomainResource source has dom-4 with severity error and expression contained.meta.versionId.empty() and contained.meta.lastUpdated.empty(), the contained element carries that condition, the narrative says contained resources SHALL NOT contain meta.versionId or meta.lastUpdated, and the current Meta source no longer has Meta.deleted.

Recommendation:
Keep this audit commit as-is. Revisit only if a future work-group decision changes the broader contained-resource metadata policy; FHIR-5796 itself remains correctly applied in current build-scope source.
