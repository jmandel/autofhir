FHIR-13018: Audit affectsState rename

Issue request:
FHIR-13018 was a Published/Persuasive with Modification FHIR-core OperationDefinition issue raised against DSTU2. It reported that OperationDefinition.idempotent and the Operations page were using HTTP idempotence where HTTP safe-method semantics were intended, since idempotent operations such as DELETE can still affect server state. The approved resolution renamed OperationDefinition.idempotent to OperationDefinition.affectsState, updated the definition, and noted that STU3-to-STU4 conversion needs to negate existing values.

Initial application:
The Jira application comment records svn revision 12727. Git-svn commit 50ff76d9cb4d07379bbd6cd2aab33b8b330acf26, revision 12726, changed the then-authoritative OperationDefinition spreadsheet element from idempotent to affectsState and updated source/operations.html from idempotent wording to affectsState=false wording. Git-svn commit 000f9318213d7bbd6df221ec25f8cb296baca153, revision 12727, applied the same rename through the generated R4 Java model, parsers, and version converters.

Additional context:
Later Published/Applied decisions refined the same semantics rather than reversing them. FHIR-14960 added explicit POST-for-all-operations and GET-for-non-state-affecting URL-representable-parameter guidance, FHIR-18197 removed the remaining misleading HTTP idempotent reference from the affectsState definition, and FHIR-51046 later updated the Operations-page GET parameter criterion to datatypes with corresponding search types. Current source/fhir.ini actively lists OperationDefinition, source/hierarchy.xml includes operations.html, and the active FHIR ModelInfo Library exposes affectsState. The remaining OperationDefinition.idempotent entry in source/fhir.ini is an intentional old-to-new element map, not current element guidance.

AutoFHIR reconciliation:
This audit commit makes no source change because the current build-scope source already reflects the FHIR-13018 decision. OperationDefinition.affectsState is the current element, its definition directly describes state effects instead of HTTP idempotence, and the Operations page bases GET invocation on affectsState=false plus URL/search-type representability rather than on idempotence. Focused source and community searches found no current authoritative FHIR-core OperationDefinition surface that still needs the FHIR-13018 rename applied.

Recommendation:
Keep this no-change audit commit as-is. Do not reintroduce idempotent terminology for OperationDefinition; future changes should preserve affectsState as the current element name and apply later method-support decisions such as FHIR-51046 when editing Operations-page GET criteria.
