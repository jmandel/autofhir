FHIR-17664: Audit Questionnaire initial value invariant

Issue request:
FHIR-17664 was a Published/Persuasive FHIR-core Questionnaire change request from STU3. It requested enforcement that a Questionnaire item cannot have multiple initial values unless the item itself can repeat, with the final resolution to add an invariant.

Initial application:
The issue does not appear by key in current git history, but the requested invariant was added to the pre-R4 Questionnaire spreadsheet in commit b8c5990ac5ad735ba1e8e836fd8a4c6fd3534a3e on 2018-08-11 as que-13, with human text "Can only have multiple initial values for repeating items" and expression "repeats=true or initial.count() <= 1". Later source refactors carried the invariant into the current StructureDefinition source.

Additional context:
Questionnaire is active in source/fhir.ini, so source/questionnaire/structuredefinition-Questionnaire.xml is current build input. The current StructureDefinition still contains que-13 on Questionnaire.item, and both Questionnaire.item.repeats and Questionnaire.item.initial list que-13 as a condition. A later Applied issue, FHIR-41174, used que-13 as existing context when adding a parallel rule for answerOption.initialSelected, which supports treating the current que-13 rule as intentional and still relevant. Searches of Zulip and Confluence found no conflicting community decision for FHIR-17664.

AutoFHIR reconciliation:
Made no source change. The active current Questionnaire source already contains the invariant requested by FHIR-17664 and wires it to the relevant elements, so an additional edit would be redundant.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-17664 unless a future work-group decision changes the Questionnaire initial value/repeats rule.
