FHIR-13293: Audit CareTeam ctm-1 XPath reconciliation

Issue request:
FHIR-13293 was a Published/Persuasive with Modification STU3 change request for FHIR-core-CareTeam. It reported that the CareTeam.participant ctm-1 XPath used contains(f:member/f:reference/@value, '/Practitioner/') and therefore rejected legal relative Practitioner/... references; the accepted resolution was to update the XPath to allow relative Practitioner references and to prefer generated XPath from FHIRPath.

Initial application:
The issue was applied historically in commit bd3f8a7ba5aba2347a6542d772cdc96897766a9c, whose subject explicitly included #13293 Update CareTeam invariant and whose patch changed the CareTeam XPath to the starts-with(... 'Practitioner/') plus contains(... '/Practitioner/') form. Later source conversion carried the fixed XPath forward until commit 88a1f3d6bd60f7618ae140179b008ac5686e8a08 removed checked-in ElementDefinition XPath values, including the already-fixed ctm-1 XPath.

Additional context:
FHIR-21219 later reported the same STU3 schematron false-positive and recorded that the resource was already fixed. FHIR-42928 subsequently made a broader Patient Care decision to expand CareTeam.participant.onBehalfOf target profiles and remove ctm-1, so the current CareTeam source has ctm-1 only in an XML comment and no active XPath/string-reference test to correct.

AutoFHIR reconciliation:
This commit intentionally makes no source change. CareTeam is in the active build, but the current source no longer contains an active restrictive XPath and reintroducing or editing ctm-1 would conflict with the later applied FHIR-42928 removal.

Recommendation:
Keep this audit commit as-is. No current core source work is needed for FHIR-13293; any concern about old STU3 generated schematron output would be a historic publication/backport question rather than a current-build source fix.
