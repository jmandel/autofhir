FHIR-37060: Audit MolecularSequence formatted cardinality

Issue request:
FHIR-37060 was a Published/Persuasive Clinical Genomics technical correction for R5 MolecularSequence asking that MolecularSequence.formatted be limited to one Attachment so a single sequence representation is shared with a MolecularSequence resource. The final resolution was to update formatted cardinality to 0..1.

Initial application:
The issue was applied before this reconciliation by commit 087684e44393718e34bc9d91e0d254836098986a, "FHIR-37060 - fix cardinality of formatted attribute", which changed source/molecularsequence/structuredefinition-MolecularSequence.xml from max="*" to max="1". The Jira comment also points to HL7/fhir pull request 1921 for that implementation.

Additional context:
Later Clinical Genomics work renamed MolecularSequence.formatted to MolecularSequence.file under FHIR-40567, and the current build no longer includes the old MolecularSequence resource source: source/fhir.ini has ;molecularsequence=cg commented out and moleculardefinition=cg active, while source/molecularsequence has been deleted. The active successor source, source/moleculardefinition/structuredefinition-MolecularDefinition.xml, represents the file/URI concept as MolecularDefinition.representation.resolvable with max="1", so the single-representation intent remains preserved in current build scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The requested cardinality correction was already applied to the historical MolecularSequence source, and current build-scope source either no longer contains MolecularSequence.formatted or already carries equivalent single-cardinality behavior in MolecularDefinition.

Recommendation:
Keep this audit commit as-is. No current FHIR core source edit is recommended for FHIR-37060; future review should only revisit this if MolecularSequence is reintroduced or a later Clinical Genomics decision changes the single-resolvable-representation model.
