FHIR-13316: Audit FML quoted field-name support

Issue request:
FHIR-13316 was Published/Persuasive for STU3. It asked the FHIR Mapping Language to allow source and target field/property names in rule paths to be quoted when the field name includes characters that would otherwise be parsed as keywords or operators, such as observation-geneticsGene.

Initial application:
The Jira comment records svn revision 12859, and git commit dcf8318b0b85b7d09665b779cfb85d7fb33f5b99 applied that revision to source/mapping-language.html by extending the source element description so non-valid identifier characters could be quoted. That original application used double-quote wording in the older STU3-era prose.

Additional context:
Later mapping-language decisions refined the delimiter model. FHIR-25286 and FHIR-39282 harmonized FML delimited identifiers with FHIRPath by removing double quotes as identifier delimiters, and FHIR-25266 clarified that map-defined group, rule, and variable names remain id-constrained while source/target data model path elements may be delimited. Those related issues are already represented on the combined branch, and the current build inputs reflect their conclusions.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/mapping-language.html says source and target data model elements used in rule paths may be surrounded with backticks, and images/mapping.g4 allows DELIMITEDIDENTIFIER in qualified rule-path parts while defining DELIMITEDIDENTIFIER as a backtick-delimited token. Reintroducing double-quote identifier syntax would contradict the later FHIRPath-harmonization decisions.

Recommendation:
Keep this audit commit as-is. The current specification satisfies the FHIR-13316 intent using the current FHIRPath-aligned backtick delimiter; any future desire to restore double-quote delimited identifiers should be handled as a new FHIR-I decision.
