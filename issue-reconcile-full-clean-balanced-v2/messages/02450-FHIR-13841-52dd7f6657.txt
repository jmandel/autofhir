FHIR-13841: Keep AuditEvent Event mappings

Issue request:
FHIR-13841 was Published/Persuasive for STU3 AuditEvent. It asked the Security work group to align AuditEvent with the new Event pattern, with the recorded resolution "do mapping to Event" and a WG note that full structural conformance was not appropriate where Event required lifecycle status or subject semantics AuditEvent does not always have.

Initial application:
The explicit historical application was the 2018-03-01 GF#13841 commit 7b2b64512052c9a800a59b0ac3cd2cd013659b1b, which added a Workflow Mapping column to the AuditEvent spreadsheet and mapped AuditEvent to Event plus selected AuditEvent elements to Event paths. That application mapped AuditEvent.agent to Event.performer and related sub-elements rather than renaming the live element.

Additional context:
AuditEvent is an active current-build resource in source/fhir.ini. The current StructureDefinition preserves Event-pattern workflow mappings for the root and relevant elements, including type/category, subtype/code, occurred/occurrence, authorization/reason, basedOn, patient/subject, encounter, agent/performer, agent.type/performer.function, agent.who/performer.actor, and agent.location/location. Later work, especially FHIR-28100 and FHIR-38871, added more Event-pattern context and mapping-exception tooling. The current AuditEvent Event mapping-exceptions file records the intentional divergences called out by the seed, including optional patient/subject and no AuditEvent lifecycle status mapping.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative source already reflects the requested Event mapping while documenting the intentional non-alignment needed for AuditEvent semantics.

Recommendation:
Keep this no-change audit commit as-is. Future Event-pattern changes should be handled under their own Jira issues, not by reopening FHIR-13841.
