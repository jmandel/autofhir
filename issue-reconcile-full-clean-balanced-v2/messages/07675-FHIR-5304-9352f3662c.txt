FHIR-5304: Audit retired Order fulfillment guidance

Issue request:
FHIR-5304 was a Published, Persuasive with Modification DSTU1 OO ballot comment asking to replace unclear Order page text that said clients could determine non-performance by searching for order resources with no matching responses. The final resolution said to follow up after workflow discussion and records that the result was applied in the Workflow Module because Task replaces Order.

Initial application:
No Jira-keyed commit for FHIR-5304 was found. Git history shows the obsolete Order and OrderResponse sources, including the challenged wording, were removed by commit 16997a29cae89d6a31d09dabd782afdb0077b2e7 as part of removing Order/OrderResponse and moving workflow behavior to Task. The current build configuration has active Task, ServiceRequest, and NutritionOrder resources, while DiagnosticRequest, NutritionRequest, Order, and OrderResponse appear only in the removed-resource list.

Additional context:
Duplicate FHIR-7391 repeated the same ballot comment and was resolved as Duplicate. Current workflow source now explains that Request instances do not necessarily imply immediate fulfillment, that workflow state is tracked with Task, and that clients query Tasks whose focus is the request of interest to determine current workflow status. Current Task definitions state that when a Task seeks fulfillment of an order, the order to be fulfilled is communicated with Task.focus, not by searching obsolete Order resources for matching OrderResponse records.

AutoFHIR reconciliation:
This audit commit makes no source change. The current source no longer contains the misleading Order/OrderResponse wording, the retired resources are not active build resources, and the active Workflow/Task material already implements the intended clarification at the current specification level.

Recommendation:
Keep this no-change audit. Do not reintroduce Order/OrderResponse-specific guidance; future clarifications about order fulfillment status should be made in the active Workflow, Request, Task, or domain request/event resources if a current ambiguity is identified.
