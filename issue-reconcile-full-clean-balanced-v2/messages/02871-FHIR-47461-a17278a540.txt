FHIR-47461: Clarify ServiceRequest authorization role

Issue request:
FHIR-47461 was Applied with resolution Persuasive with Modification for R6. It asked OO to clarify that an active ServiceRequest represents authorization to perform the service, to split the ServiceRequest-vs-Task Boundaries and Relationships text into a separate paragraph, and to state that resulting Procedure, Observation, DiagnosticReport, ImagingStudy, or similar resources are basedOn the authorization represented by the ServiceRequest.

Initial application:
The Jira comment points to PR #3366 merge commit 2a8a2b8d10807b2f15a8562f3708adb0563370d3, and the underlying commit 04fcaf7ed88da59536e6626ebfc18da8658f027a changed only the ServiceRequest root ElementDefinition.definition. Before this reconciliation, source/servicerequest/structuredefinition-ServiceRequest.xml still had the older top-level StructureDefinition.description, and source/servicerequest/servicerequest-introduction.xml still had the pre-resolution single Boundaries and Relationships paragraph with no basedOn-authorization sentence.

Additional context:
ServiceRequest is an active OO resource in source/fhir.ini, so both the StructureDefinition source and the ServiceRequest introduction feed the current build. The Request pattern already contains later Applied guidance from FHIR-48862 that Request status remains under requester control and reflects recommendation/authorization rather than fulfillment, and earlier FHIR-45872 guidance explains why fulfillment state is handled through Task. Those related decisions support the local ServiceRequest clarification and avoid needing a broader Request-pattern edit in this commit.

AutoFHIR reconciliation:
This commit completes the Applied ServiceRequest source change. It aligns StructureDefinition.description with the already-applied root definition and updates the Boundaries and Relationships narrative to use the approved split paragraphs, including the basedOn authorization statement and the corrected Task request/event wording.

Recommendation:
Keep this source fix. It is limited to active ServiceRequest source, completes the missing pieces of the Applied Jira disposition, and is consistent with the existing Request pattern and Task guidance.
