FHIR-5690: Audit W5 informant mapping

Issue request:
FHIR-5690 was a Published/Persuasive with Modification DSTU1 change request about inconsistent handling of patient-entered and patient-reported data across Observation, QuestionnaireAnswers, MedicationStatement, and Immunization. The approved resolution was to add an informant/source concept to W5 under who.source and continue consistency tracking in future versions.

Initial application:
The issue was applied in SVN revision 6132, represented in git as 60a24188d814b7e957287a10635f71d61cfc9c78 (#5690 - add informants to w5). That commit updated source spreadsheets for Immunization, MedicationStatement, QuestionnaireAnswers, and ClinicalImpression, adding who.source mappings for relevant informant/reported-source elements.

Additional context:
The current build no longer uses the old DSTU1 spreadsheet surface directly. source/fhir.ini actively includes the FiveWs logical pattern and the relevant current resources, including Immunization, MedicationStatement, Observation, Questionnaire, and QuestionnaireResponse. The current FiveWs pattern contains FiveWs.source with W5 code who.source and definition text for who provided the information. Current Immunization.primarySource, Immunization.informationSource, MedicationStatement.informationSource, and QuestionnaireResponse.source mappings point to FiveWs.source. Observation.performer already allows Patient and RelatedPerson, and the current Observation FiveWs exception records FiveWs.source as unmapped rather than forcing performer into the informant/source role.
