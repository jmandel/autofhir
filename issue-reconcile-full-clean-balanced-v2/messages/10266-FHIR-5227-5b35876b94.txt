FHIR-5227: Audit transaction overview clarification

Issue request:
FHIR-5227 was a Published/Persuasive DSTU1 ballot comment asking the developer overview to make the Transaction interaction clearer. The old overview row showed only "Transaction = POST https://example.com/path/", and the commenter asked how the POST content was specified given that Create also uses POST for individual resources.

Initial application:
The issue was applied in git commit 03375e61e1734eb1dea95a3a2557ceba68d78e34, the git-svn mirror of svn revision 4510 cited by Jira. That commit changed source/overview-dev.html to add the parenthetical "POST a tranasction bundle to the system" to the Transaction row. A later typo fix corrected "tranasction" to "transaction", and a 2022 URL-consistency commit changed the example base from /path/ to /base/ while preserving the clarification.

Additional context:
source/hierarchy.xml includes overview-dev.html as the Developer Introduction, so the checked source is in the current build. The current overview lists Create as POST https://example.com/base/{resourceType} and Transaction as POST https://example.com/base/ with "POST a transaction bundle to the system". The RESTful API transaction section separately states that batch/transaction uses POST [base] and that the POST content is a Bundle whose Bundle.type is batch or transaction. Searches found no Zulip or Confluence record, and the Jira full-text search found no competing issue beyond FHIR-5227 for the exact transaction-overview wording.

AutoFHIR reconciliation:
No source change was made. The current source already preserves the applied clarification and now distinguishes both the endpoint and submitted content well enough that the original ambiguity is resolved.

Recommendation:
Keep this empty audit commit as-is. No follow-up source edit is recommended unless the work group wants a broader editorial rewrite of the developer overview, which is outside the resolved FHIR-5227 clarification.
