FHIR-26438: Audit Identifier UUID wording

Issue request:
FHIR-26438 was a Published/Persuasive MnM clarification for R5 asking to refine Identifier text about UUIDs. The approved resolution was to change "for which no system has been assigned" to "for which no other system has been assigned" so UUID values could still be used with an assigned Identifier.system other than urn:ietf:rfc:3986.

Initial application:
The issue was applied in commit 5cbc14c7d0f361941099bf72066b75c3f74f6d4f, which changed source/datatypes.html from "no system has been assigned" to "no other system has been assigned" in the Identifier narrative.

Additional context:
The Identifier section is in current build scope through source/fhir.ini's active Identifier datatype and normative status entries. Later applied Identifier issues FHIR-45479, FHIR-41478, and FHIR-42959 rewrote the same narrative to make the rule clearer: custom/community Identifier.system values may be established for globally unique values, and urn:ietf:rfc:3986 is required only when no assigned system exists and the value is expressed as a URI.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The obsolete phrase targeted by FHIR-26438 is no longer present, and the current source already conveys the intended distinction without reintroducing the older wording.

Recommendation:
Keep this audit commit as-is. Do not add redundant "no other system" prose unless a future work group decision reopens the broader Identifier namespace guidance.
