FHIR-18235: Audit Bundle reference resolution wording

Issue request:
FHIR-18235 was a Published/Persuasive STU3 FHIR-I issue for FHIR-core-Feed. It asked to replace the confusing nested if/else bullet list under "How to resolve a reference in a Bundle" with a clearer flow that handles absolute references, derives an absolute reference from a relative [type]/[id] reference when the containing entry has a RESTful fullUrl, then attempts bundle lookup, external dereference, or failure.

Initial application:
No commit explicitly mentioning FHIR-18235 or GF#18235 was found. The Jira comment cites GH#c9067ba302, but that commit is "GF#18552 - bundle clarifications" and only added the word "externally" plus an example comment; it left the confusing nested FHIR-18235 bullet flow in source/bundle/bundle-notes.xml. A later Zulip thread confirms the reporter and editor recognized that the cited commit did not contain the requested FHIR-18235 change.

Additional context:
Bundle is an active resource in source/fhir.ini, so source/bundle/bundle-notes.xml is current build-scope source. FHIR-29271 later reopened the same confusing Bundle reference-resolution section, explicitly noting frequent community questions and the earlier GF#18235 history. FHIR-31422 then refined the same area to clarify arbitrary URI schemes for fullUrl/reference matching. Commit e084181ce7efd960c27096be172fcc0d0e845a81 applied FHIR-29271 and FHIR-31422 by replacing the old nested list with the current explicit sections for URNs, absolute references, relative references against a RESTful base, conditional references, canonical references, and failure. Later wording commits, including FHIR-50423 terminology corrections from reference.value to reference.reference, preserved that structure.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope Bundle notes already satisfy the FHIR-18235 intent after later applied work: the old ambiguous if/else flow is gone, the relative-to-absolute step is explicit, absolute reference resolution is defined, and terminal failure cases now state that the reference has no defined meaning. Replacing the current text with the original five-step proposal would discard later approved detail and would not improve current implementer understanding.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-18235 unless the work group separately decides to revise Bundle reference-resolution semantics or clean up unrelated editorial wording.
