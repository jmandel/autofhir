FHIR-34304: Audit questionnaire extension contexts

Issue request:
FHIR-34304 was a Published/Persuasive FHIR-core change request, raised against R4 and applied for R5, asking that most Questionnaire extensions controlling appearance and behavior also be valid on ElementDefinition so reusable question-library definitions can carry those properties into generated Questionnaires.

Initial application:
The Jira comment identifies "Git Questionnaire-fixes 00afa6314b". Commit 00afa6314b4db439e283b1a6400ce44eb42198a8 applied the request in core by adding ElementDefinition context declarations to 20 source/questionnaire/structuredefinition-extension-questionnaire-*.xml definitions.

Additional context:
Those core extension-definition files are no longer present in the current FHIR core checkout; commit dd468d4f1799dd79819315b211588ef1cf4586e0 removed the extension definitions from R5 source, and the current definitions live in the FHIR Extension Pack. The later Published FHIR-extensions tracker FHIR-43033 reviewed the same Questionnaire extension contexts, restored ElementDefinition where appropriate after contextInvariant validation problems, and intentionally removed ElementDefinition from questionnaire-fhirType, questionnaire-maxOccurs, and questionnaire-minOccurs because corresponding ElementDefinition elements already exist.

AutoFHIR reconciliation:
This commit makes no source change. The active core Questionnaire source still describes propagation from ElementDefinition and is not contradicted by the current Extension Pack definitions, while the actionable extension context declarations are outside this core checkout and already reflect the later FHIR-43033 decision.

Recommendation:
Keep this no-change audit for FHIR core. Any future adjustment to the Questionnaire extension context declarations should be made in the FHIR Extension Pack and checked against FHIR-43033 and its follow-up history, not by reintroducing or editing removed core extension-definition files.
