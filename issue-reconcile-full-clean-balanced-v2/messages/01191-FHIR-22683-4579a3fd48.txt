FHIR-22683: Audit Consent example completeness

Issue request:
FHIR-22683 was Published/Persuasive for STU3 Consent. It asked that Consent examples be logically complete by having a root provision set the overall grant/deny context, purpose of use, timeframe, organization or agent, and similar facts, with sub-provisions used for exceptions.

Initial application:
No current git commit explicitly mentions FHIR-22683. In the 2019 application window, commit ea72f27bd1 reworked Consent examples to match the then-current model and commit bbe7cd28e updated Consent definitions and example linkages, including removal of the old signed Consent example from the examples spreadsheet and addition of the CDA sharing example. Those changes are consistent with applying the root-context/sub-provision pattern in the STU3-era model.

Additional context:
Later final Consent decisions changed how this issue should be interpreted in the current build. FHIR-32817 introduced a clearer default consent decision mechanism, FHIR-34322 documented the provision tree, and FHIR-39597 removed provision zero by moving the base permit/deny decision to Consent.decision while retaining Consent.provision for constraints and exceptions. Current source/fhir.ini keeps Consent in build scope, current narrative explains Consent.decision as the base policy and provisions as exceptions/contexts, and every Consent example listed in source/consent/list-Consent-examples.xml contains an explicit Consent.decision. A later FHIR-47212 ballot issue raises clarification questions about Consent.decision, but it remains Triaged and is not a final source-edit decision for this reconciliation.

AutoFHIR reconciliation:
This empty audit commit makes no source change. Reintroducing a root provision type would conflict with the later published FHIR-39597 model, and the active current examples already carry the equivalent base grant/deny context in Consent.decision with provision trees for constraints and exceptions.

Recommendation:
Keep this audit commit as-is for FHIR-22683. If the work group finalizes FHIR-47212 or another current-model clarification, handle any wording or example restructuring under that issue rather than reopening the obsolete STU3 root-provision-zero pattern.
