FHIR-3130: Audit profile condition generation

Issue request:
FHIR-3130 was a Published/Persuasive DSTU1 correction reporting that the Profile generator never populated Profile.structure.element.definition.condition even though it had the information available.

Initial application:
The Jira comments say "Already done as #3183". FHIR-3183 is the matching Published/Persuasive issue and records the application as "fixed. svn revision 2976".

Additional context:
The old DSTU1 Profile.structure surface is no longer a current source surface; the current build uses StructureDefinition and ElementDefinition. The current source has ElementDefinition.condition and generated StructureDefinition elements already carry condition references to invariant/constraint keys.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The issue's requested behavior is already present in current build-scope source, and adding text or changing generated-looking outputs would be redundant rather than corrective.

Recommendation:
Keep this audit commit as-is. No further core source action is recommended for FHIR-3130 unless a specific current StructureDefinition generator defect is reported separately.
