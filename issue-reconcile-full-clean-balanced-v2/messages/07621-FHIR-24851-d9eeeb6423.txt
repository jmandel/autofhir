FHIR-24851: Audit firstCreated extension location

Issue request:
FHIR-24851 was Published/Persuasive for FHIR-core MetadataResource. It asked to add a creation timestamp to Meta, or at least an official extension, and the final resolution was to add a 0..1 instant extension on Resource.meta named firstCreated to indicate the first time a resource ID was associated with content on a server.

Initial application:
The issue was applied in core by 1706b8fb8b, which added a firstCreated row to source/datatypes/meta-extensions-spreadsheet.xml for Meta with cardinality 0..1, type instant, and the resolved definition. The extension was part of the R5 source history. Core commit dd468d4f17 later removed extensions from the R5 source, and the current core checkout now retains only the canonical OID entry for firstCreated rather than the extension definition itself.

Additional context:
The authoritative current definition for http://hl7.org/fhir/StructureDefinition/firstCreated is in the FHIR Extension Pack checkout at input/definitions/datatypes/StructureDefinition-firstCreated.xml. That definition is active, trial-use/FMM 2, scoped to Meta, typed as instant, and carries the resolved description. Current published extension pages likewise show the official firstCreated extension with context Meta and type instant. FHIR-I minutes in 2023 discussed the Extension Pack page for firstCreated and FHIR-24851, with possible future clarification about firstCreated versus Meta.lastUpdated, but Jira searches found no later firstCreated clarification ticket and later Zulip implementer discussions point users to the existing extension rather than identifying a missing core change.
