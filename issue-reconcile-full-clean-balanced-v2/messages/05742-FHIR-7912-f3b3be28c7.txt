Issue request:
FHIR-7912 was Published/Persuasive for DSTU1 and asked for more examples showing when Timing elements are applicable, including when to use timing.event and repeat/count-style fields. The accepted resolution was to add more examples.

Initial application:
The issue was applied in svn revision 5944, represented in git by a89854200640fc200f1e4ce1772e61ea11fa5610. That commit updated source/datatypes.html with a broader Timing criteria table, adding the bounds[x] column and examples such as TID for 14 days and BID starting at a specific date/time. No prior Issue-Reconcile-Key commit existed on the combined branch for FHIR-7912.

Additional context:
source/fhir.ini lists Timing as an active datatype, maps general type pages to datatypes.html, and marks Timing normative, so source/datatypes.html is current build source. The current combined branch keeps the Timing common-use table and has expanded it further with durationUnit, frequency, period, periodMax, dayOfWeek, timeOfDay, when, offset, startOffset, bounds[x], and count columns plus rows for count, bounds, offsets, timing codes, and calendar/time-of-day patterns. Later same-area issues such as FHIR-10306 and FHIR-12637 changed the same Timing page for more specific count and event/past-event semantics, and FHIR-53412 is already represented on the combined branch for startOffset wording; none reverses or leaves a missing source change for FHIR-7912.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already satisfies the original request for more Timing examples, and adding more prose or duplicative rows under this old non-substantive issue would be optional polish rather than a necessary correction.

Recommendation:
