FHIR-17227: Audit Expression datatype application

Issue request:
FHIR-17227 was a Published/Persuasive STU3 MnM change request asking for a common metadata datatype for machine-readable expressions, including language as a code drawn from expression-language media types, and for existing definitional resources to adopt that common representation.

Initial application:
The request was explicitly applied by git-svn commit f9a0e672308594df4a403e585372a37d44132048, which cites GF#17227/SVN r13872 and added the Expression datatype source, metadata datatype page sections, fhir.ini build entries, and TriggerDefinition condition alignment. A closely related SVN r14073 commit later changed ActivityDefinition and PlanDefinition to use Expression, and other Measure/ChargeItemDefinition Expression adoption issues are already represented separately on the combined branch.

Additional context:
Expression remains active in the current build configuration as a metadata datatype, metadata type page, normative type, and abbreviation. The current datatype source defines Expression with description, name, language, expression, and reference elements; language is a code bound to the ExpressionLanguage value set; the value set includes text/cql, text/fhirpath, text/x-fhir-query, text/cql-identifier, and text/cql-expression from BCP 13 media types. Later published issues refined the datatype and its value set, including FHIR-27883, FHIR-27029, FHIR-31082, FHIR-36705, and FHIR-38872, so exact differences from the original proposal are intentional later source history rather than missed FHIR-17227 work. Current active PlanDefinition, ActivityDefinition, and Measure source elements use Expression where checked, while ChargeItemDefinition is no longer an active core resource and its Expression-related follow-up is already represented by FHIR-31569 on the combined branch.
