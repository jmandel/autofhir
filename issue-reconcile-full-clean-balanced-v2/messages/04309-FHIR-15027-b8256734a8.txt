FHIR-15027: Audit PractitionerRole availability wording

Issue request:
FHIR-15027 was a Published/Persuasive PA change request for STU3 asking that PractitionerRole.availableTime and PractitionerRole.notAvailable stop describing service-site or HealthcareService availability and instead describe when the practitioner is available or unavailable while performing the role at a location and/or healthcare service.

Initial application:
The change appears to have been applied by git commit 35f38f5e1a5a505af1480eeaf060a64de0df5cd5, "Tracker 15027 updated availableTime and notAvailable", which replaced the old Service Site and HealthcareService definitions in source/practitionerrole/practitionerrole-spreadsheet.xml with the practitioner-focused wording requested by the issue.

Additional context:
Later R5 work in FHIR-25381 replaced PractitionerRole.availableTime, PractitionerRole.notAvailable, and availabilityExceptions with the PractitionerRole.availability element using the shared Availability datatype. The active fhir.ini resource list includes PractitionerRole, and the deleted-element map redirects the old STU3 paths to PractitionerRole.availability and PractitionerRole.availability.notAvailableTime. FHIR-32500 subsequently added the rendering guidance now present in the PractitionerRole.availability comment. No direct Zulip or Confluence record was found that conflicts with the Jira/source/git conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative source/practitionerrole/structuredefinition-PractitionerRole.xml definition for PractitionerRole.availability says the practitioner is available or performing the role at the location and/or healthcare service, and the comment describes not-available periods as times when the practitioner is not available. Searches of the current PractitionerRole source found no remaining stale Service Site or HealthcareService availability phrasing.

Recommendation:
Keep this audit commit as-is. The current build already preserves the FHIR-15027 correction through the later availability datatype model, so a source edit would be redundant and could reopen wording settled by later availability issues.
