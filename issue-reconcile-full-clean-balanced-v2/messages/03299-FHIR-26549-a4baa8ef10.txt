FHIR-26549: Audit ValueSet identifier profile scope

Issue request:
FHIR-26549 was a Published/Persuasive Vocab change request for R5. It asked that the VSD Profile restrict ValueSet.identifier.system to OID, RUID, UUID, or URI so Value Set Definition identifiers are globally unique. Jira comments clarified that this applied to the VSD-compliant profile, not the base FHIR Core ValueSet definition.

Initial application:
The issue was first touched by the broad VSD Profile commit 9fca6ca36f, which explicitly listed FHIR-26549 but was reverted by 5161923416 and reapplied as 054eabf311 without the seed key in the message. The seed-specific identifier restriction appears to have been applied indirectly by 633035c38a under FHIR-30099, adding source/valueset/structuredefinition-profile-vsd-alignedvalueset.xml with a ValueSet.identifier comment and constraint saying Identifier.system is restricted to OID, RUID, UUID, or URI.

Additional context:
Later final decisions changed the current build scope. FHIR-30099 added only the VSD-P profile at first, FHIR-31395 then established the shareable/publishable/computable/executable ValueSet profile family, FHIR-37923 removed the old VSD Aligned ValueSet profile from core, and FHIR-37959 moved the remaining terminology-resource profile family out of current FHIR core for maintenance in CRMI with canonical URLs unchanged. Existing AutoFHIR audit commits for FHIR-30099, FHIR-31395, FHIR-37923, FHIR-37959, and FHIR-36015 are already on the combined branch and record those related decisions.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because the base ValueSet.identifier definition is still correct for FHIR Core, the profile-specific VSD constraint is not a current core build-scope artifact, source/valueset/implementationguide-ValueSet-core.xml has no profile resources, source/fhir.ini has no active ValueSet profile entry, and active shareable pattern text points implementers to CRMI for the migrated profiles.

Recommendation:
Keep this audit commit as-is. Do not add the VSD identifier.system restriction to the base ValueSet resource and do not restore the removed VSD-aligned profile in current FHIR core; any future correction to migrated profile definitions should be handled in the CRMI/profile-maintenance venue unless a new core tracker explicitly reverses FHIR-37923 and FHIR-37959.
