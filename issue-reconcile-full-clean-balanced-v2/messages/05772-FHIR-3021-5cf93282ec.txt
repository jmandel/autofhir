FHIR-3021: Audit draft medication request status

Issue request:
FHIR-3021 was Published with a Persuasive resolution for DSTU1. It asked for medication-prescription-status to include a "draft" code for prescription/order records that are not yet active, such as works in progress, orders requiring sign-off, narcotic counter-signature, or decision-support review before activation.

Initial application:
No commit explicitly tagged FHIR-3021 was found in the local git history. The early MedicationPrescription spreadsheet initially contained draft, commit 9cebb3da33e5 removed it with an explicit "will add it back later" note, and by commit abce09d8c1ed the MedicationPrescriptionStatus binding and code list again contained draft. Later rename commits preserved the status concept through MedicationPrescription to MedicationOrder and then MedicationRequest, including d75ee68d691c for the medication-order-status URL and 7387b2894c02 for the MedicationRequest rename and status value set update.

Additional context:
The current build scope is MedicationRequest, not the retired MedicationPrescription name: source/fhir.ini has an active medicationrequest resource entry and records that MedicationPrescription became MedicationRequest. The current MedicationRequest.status element has a required binding to ValueSet/medicationrequest-status, whose CodeSystem includes draft with a definition matching the Jira use case. Zulip and Confluence searches for FHIR-3021 and the status/draft terms found no conflicting community record.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The authoritative current source already exposes draft in the active MedicationRequest status CodeSystem and required status binding, so adding another code or duplicating prose would not change implementer understanding.

Recommendation:
Keep this no-change audit commit as-is. No core follow-up is needed unless a future Pharmacy work group decision changes MedicationRequest lifecycle status semantics.
