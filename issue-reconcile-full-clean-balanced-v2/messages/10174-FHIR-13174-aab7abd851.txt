FHIR-13174: Audit _count page-size clarification

Issue request:
FHIR-13174 was Published/Persuasive with Modification for STU3. It asked whether `_count` constrained a total result count or requested page size; the accepted resolution was to document `_count` as "the maximum number of search results on a page, excluding related resources included by _include or _revinclude or OperationOutcomes."

Initial application:
The issue was applied by git-svn commit 673c063e2915 (svn revision 14187), titled "GF#13174 - document _count more clearly." That commit changed source/http.html to use the accepted page-size wording and changed the history paging sentence from maintaining `_count` to respecting `_count` across pages.

Additional context:
The current active source still carries that clarification on the HTTP history interaction page. The search page has since been expanded to a dedicated "Limiting Page Size (_count)" section that states `_count` limits resources in a single page, requires servers not to exceed the requested page size, says reachable paging links should respect the original count or server max, excludes included resources and operation outcomes, and clarifies that `_count` does not affect Bundle.total. Later page-size discussions and edits refine the same interpretation rather than reversing it.
