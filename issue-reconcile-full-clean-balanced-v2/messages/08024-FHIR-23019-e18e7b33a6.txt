FHIR-23019: Audit boolean questionnaire guidance

Issue request:
FHIR-23019 was Published with a Persuasive with Modification resolution for FHIR-core Questionnaire. It asked for clarification that QuestionnaireResponse boolean answers should not record false unless false was actually selected, and that enableWhen logic referencing boolean questions must distinguish false from no answer when that distinction is possible.

Initial application:
The issue appears to have been applied by aaa68f89ca, whose subject is "FHIR-23019 - Added guidance on booleans" and whose Jira comment was the same commit hash. That commit added the Questionnaire "Handling Boolean Answers" section. Later wording-only commits, including 0cb570cabec and FHIR-36105 commit 687e88f506, refined the checkbox/control wording without reversing the FHIR-23019 rule.

Additional context:
Questionnaire is an active current-build resource in source/fhir.ini. The current source/questionnaire/questionnaire-notes.xml section says boolean questions have three states: unanswered, answered true, and answered false; says controls generally need to allow all three states unless a default is specified and the element is mandatory; warns that two-state checkbox-style controls cannot differentiate unanswered; and tells designers to account for non-answered boolean questions in enableWhen logic. A later Zulip questionnaire thread that explicitly found FHIR-23019 confirmed the same interpretation: if a control cannot distinguish non-answered, the system is effectively treating the checkbox as answered.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active Questionnaire narrative already covers both requested clarifications, and adding parallel text to QuestionnaireResponse or the enableWhen element definition would be redundant rather than a necessary current-spec correction.

Recommendation:
Keep this no-change audit commit as-is. No follow-up source edit is needed for FHIR-23019 unless the work group decides to change the current three-state boolean guidance or require a more prescriptive conformance rule.
