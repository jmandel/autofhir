FHIR-43224: Audit sdf-5 reprofiled extension allowance

Issue request:
FHIR-43224 was an Applied/Persuasive FHIR-I change request saying sdf-5 was too strict because it required context on reprofiled extensions. The accepted resolution was to change the invariant from requiring context for every Extension type to allowing profiles whose base is not the core Extension definition.

Initial application:
The issue was applied in commit 7d44c866fdb8481d1f6efe9ca2f33f969cd99466, which added a base check to sdf-5 in source/structuredefinition/structuredefinition-StructureDefinition.xml. Commit ec757b779e600c414583fa08c927deea20812f51 later corrected the element name from base to baseDefinition, matching the current StructureDefinition model.

Additional context:
source/fhir.ini actively includes structuredefinition=StructureDefinition, so source/structuredefinition/structuredefinition-StructureDefinition.xml is in current build scope. The linked Zulip thread shows the original reporter's reprofiling-extension problem and confirms the desired behavior: reprofiled extensions should inherit context rather than restating it. FHIR-I minutes from 2024-04-22 record the 8-0-0 motion to approve adding the base guard. Jira and community searches did not reveal a later conflicting issue for this invariant.

AutoFHIR reconciliation:
No source change was made. The active source now has sdf-5 as type != 'Extension' or baseDefinition != 'http://hl7.org/fhir/StructureDefinition/Extension' or derivation = 'specialization' or (context.exists()), which implements the accepted decision while preserving context requirements for newly defined extensions.

Recommendation:
Keep this audit commit as-is. The current source already satisfies FHIR-43224; future work should only revisit the human-readable invariant text if the work group wants an editorial clarification, not because the constraint logic remains too strict.
