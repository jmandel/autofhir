FHIR-20413: Audit IG Publisher JSON escaping

Issue request:
FHIR-20413 was a Published/Persuasive FHIR-core change request for the IG Publisher to escape embedded namespace quotes when rendering generated JSON examples, because unescaped quotes made the displayed JSON invalid. The Jira resolution was auto-approved and applied for R5.

Initial application:
The issue was applied in HL7/fhir by commit 89e7fddd8117f9b75c34a5057b193006c8b29793, which changed the IG Publisher JsonXhtmlRenderer string value rendering from XML-only escaping to JSON escaping followed by XML escaping. That directly addressed JSON strings containing XHTML namespace attributes such as xmlns="http://www.w3.org/1999/xhtml".

Additional context:
The relevant in-repo IG Publisher source was removed shortly afterward by commit 56ceb0df08dd72381a4f98f1ea4ac5ea6d139a8b with the message "Remove IG publisher (it's gone to Maven)", and the current FHIR checkout no longer contains tools/java. Current build configuration depends on external publisher tooling, while the current HL7/fhir-ig-publisher JsonXhtmlRenderer still uses Utilities.escapeXml(Utilities.escapeJson(value)). No Confluence reference was found that changes the Jira/Zulip/source conclusion.

AutoFHIR reconciliation:
This is an empty audit commit. No current FHIR specification source change is needed because the original fix was made before the tooling moved out of this checkout, and the current external publisher source retains the escaping behavior.

Recommendation:
Keep this audit commit as-is. If JSON example rendering regresses again, open follow-up work against the active publisher/tooling repository rather than editing the current FHIR specification source tree.
