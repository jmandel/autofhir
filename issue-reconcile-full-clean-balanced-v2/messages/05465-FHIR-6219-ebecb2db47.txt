FHIR-6219: Audit Medication form binding

Issue request:
FHIR-6219 was a Published/Persuasive DSTU1 Pharmacy correction for FHIR-core Medication. It reported that medication.product.form was bound to a dosage/route value set, and the accepted resolution was to fix the terminology binding so Medication.product.form used SNOMED CT descendants where concept is-a 421967003.

Initial application:
The Jira comments say the issue was fixed in svn 6615. The corresponding git-svn commit c74b8e3ebbf92ccc157a591a1571158559a655cd, titled "#6219, #7262, several other duplicates. Fixed Medication.form valueset expansion," changed source/medication/valueset-medication-form-codes.xml from SNOMED CT concept 284009009, a route-of-administration parent, to 421967003. That matches the FHIR-6219 resolution.

Additional context:
Medication is still an active current-build resource in source/fhir.ini, and the historical Medication.form/medication.product.form path maps to current Medication.doseForm. Current Medication.doseForm binds to http://hl7.org/fhir/ValueSet/medication-form-codes, and the current value set uses SNOMED CT concept is-a 736542009. This is not a regression: later Published/Persuasive Pharmacy issue FHIR-19296 approved changing the drug/form binding to 736542009, duplicate FHIR-22272 explains why 421967003 had become insufficient, and a 2019 Zulip terminology thread records that 421967003 was retired as ambiguous and that 736542009 was the intended replacement.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The current active Medication source is no longer bound to the route-of-administration parent corrected by FHIR-6219, and reverting the value set to 421967003 would undo the later FHIR-19296 Pharmacy decision.

Recommendation:
Keep this no-change audit as-is. Do not edit current Medication source for FHIR-6219; future medication dose-form terminology work should start from the later FHIR-19296/736542009 history and current terminology-tooling evidence.
