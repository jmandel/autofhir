FHIR-14875: Audit collection resource guidance

Issue request:
FHIR-14875 was a Published STU3 FHIR-core/MnM change request resolved Not Persuasive with Modification. It asked to combine collection-like resources such as Composition, Document/Bundle, List, DiagnosticReport, and Questionnaire; the resolution declined merging them because each serves a distinct purpose and said the distinctions belong in the resource Scope/Boundaries guidance, with more explanation expected around Composition.section, List.entry, and DiagnosticReport.

Initial application:
No source commit explicitly applying FHIR-14875 was found; the only git --grep hit for 14875 is an unrelated historical SVN revision number. The relevant collection-type distinction was already present before the issue in d72b1d787a, which added Boundaries and Relationships guidance for Bundle, Composition, Group, and List. The same MnM vote also resolved companion issue FHIR-14729 as Not Persuasive because the boundaries sections already documented the differences.

Additional context:
The MnM 2018-02-27 minutes record FHIR-14875 as Not Persuasive with Modification. Later published issues refined the same guidance family rather than combining resources: FHIR-27083 clarified when Group should be preferred over List, FHIR-27903 added that a List cannot be the subject of an intervention or direct action and updated the List description, and FHIR-19250 clarified DiagnosticReport overlap with DocumentReference. Current source/fhir.ini lists Bundle, Composition, DiagnosticReport, Group, List, Questionnaire, and QuestionnaireResponse as active resources, so the inspected introduction files are in current build scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current build-scope source already distinguishes the collection mechanisms: List describes five FHIR mechanisms for collections; Composition distinguishes List, Group, Bundle, and Questionnaire/QuestionnaireResponse and explains section entries; Bundle distinguishes technical transport/persistence bundling from meaningful groupings; DiagnosticReport distinguishes structured reports from Composition and DocumentReference; Questionnaire distinguishes itself from Lists, DiagnosticReports, Observations, and Compositions. Adding another general collection-comparison paragraph would be redundant and risks drifting from the more specific resource boundary text.

Recommendation:
Keep this no-change audit commit as-is. Revisit only if a future work group decision supplies concrete wording for a specific remaining overlap; broad consolidation of collection resources is not supported by the seed resolution or later published clarifications.
