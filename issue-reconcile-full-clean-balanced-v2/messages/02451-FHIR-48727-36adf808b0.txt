FHIR-48727: Audit NutritionIntake not-consumed modeling

Issue request:
FHIR-48727 was an Applied R6 OO change request asking whether NutritionIntake.nutritionItem could safely have multiple consumedItem instances when the model also had a notConsumed boolean and reason. The accepted disposition was Persuasive with Modification: pull the not-consumed flag and reason into a backbone element and add schedule and amount.

Initial application:
No git commit in the current source history explicitly names FHIR-48727. The same NutritionIntake model area was changed on 2025-02-25 in commit 05e646d74bb93a1c435d884747dc64da94898435, which removed the old notConsumed boolean/notConsumedReason shape and added NutritionIntake.nutritionItem.notConsumedItem with reason, schedule, and amount. Commit 9a769f27d3fdb6cee91898dd5d75c079b77a0563 then updated examples to the reorganized NutritionIntake model.

Additional context:
FHIR-45063 had already required separating consumed and not-consumed nutrition items, and FHIR-47247 considered whether the old notConsumed flag needed modifier treatment. The January 15, 2025 OO Nutrition minutes record FHIR-48727's decision to pull the not-consumed flag and reason into a backbone element adding schedule and amount. The current build includes NutritionIntake as an active OO resource.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current source/nutritionintake/structuredefinition-NutritionIntake.xml has NutritionIntake.nutritionItem.consumedItem as a 0..* backbone for actually consumed items, and a separate NutritionIntake.nutritionItem.notConsumedItem 0..* backbone with reason, schedule, and amount, satisfying the approved FHIR-48727 modeling change without constraining consumedItem to 0..1.

Recommendation:
Keep this no-change audit commit as-is. Further source changes are not needed for FHIR-48727 unless OO later decides to change consumedItem cardinality or add additional narrative guidance.
