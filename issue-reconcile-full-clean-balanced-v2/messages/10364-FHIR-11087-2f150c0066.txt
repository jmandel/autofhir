FHIR-11087: Audit Observation search split

Issue request:
FHIR-11087 was a Published/Persuasive OO change request from the DSTU2 ballot asking for Observation search parameters that can target only Observation.code or Observation.value[x], and separate parameters that can target only Observation.component.code or Observation.component.value[x], because the then-current combined search parameters made mixed code/value matches ambiguous.

Initial application:
The request was applied in historical commit 4d575fe47df8dfb6915328e0ab1dfb774f2f322c, whose message was [#11087]. That commit changed the old Observation spreadsheet source to make code and value parameters observation-only, add combo-* parameters for the prior combined behavior, and add component-* and component-code-value-* parameters. The current source has since been refactored into source/observation/bundle-Observation-search-params.xml, with Observation active in source/fhir.ini.

Additional context:
FHIR-9734 previously merged Observation.code with Observation.component.code, while FHIR-11087 and FHIR-11088 later captured the ambiguity caused by combined direct/component search paths and composite generation. The current build-scope bundle defines code, combo-code, component-code, observation-only value and code-value parameters, component value/code-value parameters for concept and quantity, and combo concept/quantity parameters. The original 2017 application also included component/combo string and date variants, but later FHIR-17789 specifically revisited missing Observation value search variants, including combo-* and component-* parameters for string and date, and ended as Resolved - No Change after OO determined the topic had been overcome by subsequent search-parameter work and should not be reopened here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding the omitted component/combo string and date variants would contradict the later no-change decision in FHIR-17789, while the currently accepted direct/component split for the retained Observation search-parameter family is already present in the active source.

Recommendation:
Keep this audit commit as-is for FHIR-11087. If OO wants to expand Observation value searches beyond the current accepted set, that should be raised as a new search-parameter issue rather than treated as an unapplied part of this DSTU2 tracker.
