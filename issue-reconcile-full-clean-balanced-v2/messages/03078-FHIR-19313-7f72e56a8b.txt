FHIR-19313: Audit MedicationRequest reporting elements

Issue request:
FHIR-19313 was a Published Pharmacy change request, resolved Persuasive for STU3, asking MedicationRequest to add one element indicating that a MedicationRequest was reported and another informationSource element, consistent with MedicationStatement. The request also asked for guidance on when to use MedicationRequest for reported orders versus MedicationStatement.

Initial application:
Jira records the application as merge commit 65133c5c9a9c6b94e85467b69529239812f98374. The implementation commit e1b82bc5a61a35b623c05f0ac408111209e5c0bb added MedicationRequest.reported as a 0..1 boolean, added MedicationRequest.informationSource as a 0..1 Reference(Patient | Practitioner | RelatedPerson | Organization), and updated MedicationRequest scope/boundary text to support non-authoritative reported medication orders.

Additional context:
MedicationRequest is active in source/fhir.ini, and the current authoritative source is source/medicationrequest/structuredefinition-MedicationRequest.xml. Later Pharmacy decisions changed the literal shape without changing the core FHIR-19313 intent: FHIR-19517 briefly changed reported/informationSource handling, FHIR-19640 restored informationSource and kept reporting as a standalone boolean, FHIR-35847 broadened informationSource to 0..*, FHIR-41408 added Group as a target, FHIR-47855 clarified that informationSource is the reporter rather than the original requester, FHIR-34195 encoded the missing-value semantics, and FHIR-49863 renamed the current reporting boolean to MedicationRequest.isRecordOfRequest. The combined branch already contains reconciliation commits for the relevant already-decided follow-up issues FHIR-19517, FHIR-19640, FHIR-34195, FHIR-47855, and FHIR-28575.

AutoFHIR reconciliation:
This empty audit commit makes no source change. Current build-scope source already has MedicationRequest.informationSource, MedicationRequest.isRecordOfRequest, optional requester/recorder support, narrative guidance distinguishing reported MedicationRequest orders from MedicationStatement, and a wired patient-reported prescription example. Reverting to the exact 2018 element name or cardinality would undo later Jira decisions.

Recommendation:
Keep this no-change audit commit. No current FHIR core source edit is needed for FHIR-19313; future work should address only later issues such as FHIR-49863 if they reach Applied/Published or if Pharmacy reopens the reporting/modifier semantics.
