FHIR-38800: Audit subscription resource bindings

Issue request:
FHIR-38800 was Published/Persuasive with Modification for R5. The Jira asked to stop binding Subscription.filterBy.resourceType and SubscriptionTopic.resourceTrigger.resource to all FHIR types and instead use resource-type values; the Jira resolution text says required binding to the new version-independent-resource-types value set, while the approving FHIR-I minutes recorded the accepted modification as an extensible binding to that new value set.

Initial application:
Git commits 6dbe9eae994 and a8293dbc39 first moved the Subscription and SubscriptionTopic resource selectors from fhir-types to resource-types/all-resource-types as an explicit half-step. Commit e4294d8526f3 then added fhir-old-types, version-independent-resource-types, and subscription-types, and switched Subscription.filterBy.resourceType to subscription-types while retaining extensible strength. Follow-up commits 9082a9058ae and 23bc6d67239 added the R5 all-resource-types additional UI binding on Subscription and moved the matching SubscriptionTopic resource selectors to the same subscription-types pattern.

Additional context:
The current build has renamed Subscription.filterBy.resourceType to Subscription.filterBy.resource and collapsed SubscriptionTopic.resourceTrigger.resource into SubscriptionTopic.trigger.resource, with fhir.ini aliases preserving the old R5 paths. Current source uses ValueSet/subscription-types, which includes ValueSet/version-independent-resource-types, plus an all-resource-types UI additional binding. Later Applied R6 subscription work, including FHIR-46492 and FHIR-47365, broadened SubscriptionTopic guidance for event triggers, logical models, and non-FHIR definitions, so changing these bindings now to required version-independent-resource-types would be a semantic narrowing rather than a safe reconciliation.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The active Subscription and SubscriptionTopic StructureDefinitions already use the FHIR-38800 value-set family and the same cross-version/current-version additional-binding pattern that subsequent FHIR-I decisions built on; the apparent mismatch with the Jira word "required" is resolved by the work-group minutes, implementation history, and later subscription decisions that preserve extensible non-current-version and non-FHIR uses.

Recommendation:
Keep this no-change audit commit. Revisit only if FHIR-I explicitly decides to narrow these current R6 subscription resource selector bindings; do not change them to required version-independent-resource-types as a mechanical reading of the older Jira resolution.
