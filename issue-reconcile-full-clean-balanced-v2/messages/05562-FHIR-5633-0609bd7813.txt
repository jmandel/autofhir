FHIR-5633: Audit medication CodeableReference choice

Issue request:
FHIR-5633 was a Published/Persuasive Pharmacy change request from DSTU1 asking that medication elements not force implementers to create a Medication resource when only a medication code is available. The approved resolution was to make the affected medication element a choice of CodeableConcept or Resource(Medication), with Grahame/Lloyd comments confirming CodeableConcept was the intended coded type.

Initial application:
No current git commit touching the medication source was found with an explicit FHIR-5633 reference. The historical source has nevertheless carried the requested coded-or-Medication-reference shape, and later commits show the same family being maintained: FHIR-10389 added guidance for choosing a code versus a Medication reference, and FHIR-25929 converted Pharmacy choices from CodeableConcept plus Reference to CodeableReference.

Additional context:
The active build scope includes MedicationAdministration, MedicationDispense, MedicationRequest, and MedicationStatement in source/fhir.ini; MedicationPrescription has become MedicationRequest. In the current StructureDefinition source, each affected medication element is a single CodeableReference with targetProfile Medication, a medication-code binding, and comments explaining when a code is enough versus when a Medication resource should be referenced. This preserves the substance of FHIR-5633 while using the current R5/R6 datatype representation, and it does not broaden the reference target to Substance.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already satisfies the issue by allowing a coded medication or a reference to Medication for the build-scope successor resources, and adding duplicate prose would not change implementer understanding.

Recommendation:
Keep this no-change audit as-is. Future work should only revisit this area if Pharmacy changes the CodeableReference target or the code-versus-reference guidance; FHIR-5633 itself is already represented in the current source.
