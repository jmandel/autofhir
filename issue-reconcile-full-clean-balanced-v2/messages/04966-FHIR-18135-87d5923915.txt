FHIR-18135: Audit ValueSet expression extension support

Issue request:
FHIR-18135 was a Published/Persuasive Vocab change request for STU3 asking ValueSet.compose to support a non-FHIR, non-code-system-specific expression syntax for defining value set content, using the R4 Expression datatype in a 0..1 ValueSet extension with VSD-derived language.

Initial application:
The Jira application comment points to git 4907f9bcb0b710cb2837a93a20c4b23210a37249. That terminology ballot reconciliation commit added an expression row to source/valueset/valueset-extensions-spreadsheet.xml with ValueSet context, 0..1 cardinality, Expression type, and definition/comment text for an alternative expression of value set content. Later core history moved extension definitions out of the core source while preserving the current ValueSet guidance.

Additional context:
ValueSet is an active current-build resource in source/fhir.ini, and current source/valueset/valueset-notes.xml points implementers to [%extensions-location%]StructureDefinition-valueset-expression.html when filter language cannot express the desired value set definition. The FHIR Extension Pack contains input/definitions/ValueSet/StructureDefinition-valueset-expression.xml with canonical http://hl7.org/fhir/StructureDefinition/valueset-expression, context ValueSet, value[x] type Expression, and the FHIR-40704 text cleanup. Vocab Confluence minutes also identify the CDC opioid CDS value set query use case as better supported by valueset-expression and list valueset-expression as the VSD CLDSyntaxReference representation. Later FHIR-27828 was Resolved - No Change for the Expression.language binding concern, so it does not require changing the extension approach.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core source already gives the necessary implementer guidance and the authoritative extension definition is now maintained in the Extension Pack, so editing core would either duplicate external source or add redundant prose.

Recommendation:
Keep this audit commit as-is for FHIR-18135. Future wording corrections to the extension definition should be handled in the FHIR Extension Pack under their own tracker history, not as a new core-source application of this STU3 seed.
