FHIR-3848: Audit Schedule resource rename

Issue request:
FHIR-3848 was a Published/Persuasive DSTU1 Patient Administration change request for FHIR-core-Schedule. It said the resource name "availability" was unclear for practitioner schedules and, now that the old Schedule datatype had been renamed, the Availability Resource should be renamed to Schedule; the recorded resolution is "The Availability Resource has been renamed to be Schedule."

Initial application:
The rename was applied in git commit 55cb2c06047c1ba74fc0eed54128434294f8c5fa, whose subject explicitly cites tracker 3848 and says it renamed the Availability resource to schedule. That commit changed the active resource entry in source/fhir.ini from availability=Availability to schedule=Schedule, moved source/availability inputs to source/schedule, and changed the root resource/example/search parameter wording from Availability to Schedule.

Additional context:
FHIR-3536 is the supporting prerequisite decision that renamed the old Schedule datatype to Timing so PA could rename the Availability resource to Schedule. Current source still has an Availability metadata datatype and a Schedule alias of Availability, but those are not a live resource named Availability. FHIR-31485 later cleaned up a residual Slot.serviceType phrase that referred to an "availability resource"; the current Slot definition already refers to the Schedule resource. Quoted Zulip and Confluence searches for FHIR-3848 found no direct conflicting community discussion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. In the current build scope, source/fhir.ini lists schedule=Schedule under [resources], source/schedule/structuredefinition-Schedule.xml has id/name/title/type Schedule with kind=resource, and current Schedule/Slot/Appointment narrative uses Schedule for the scheduling resource while using "availability" only as an ordinary concept.

Recommendation:
Keep this empty audit commit as-is. No core source follow-up is needed for FHIR-3848 unless a future work group decision wants to remove the historical Availability alias, which would be a separate compatibility decision.
