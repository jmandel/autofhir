FHIR-38106: Document notSelectable default in CodeSystem table

Issue request:
FHIR-38106 was an Applied/Persuasive Vocab change request asking that the meaning of a missing CodeSystem property be documented for http://hl7.org/fhir/concept-properties#notSelectable. The approved resolution was to state that the property type is boolean and the default value is false.

Initial application:
The issue was partially applied by git commit 39f96b21ce8d65b5b086b3ee61a455e47a359a98, which added "Property type is boolean, default value is false" to source/codesystem/codesystem-concept-properties.xml for the notSelectable concept. Later Concept Properties CodeSystem work preserved that formal definition and added a dataType=boolean property, but the active CodeSystem narrative table at codesystem.html#properties still described notSelectable without the default value.

Additional context:
source/fhir.ini has CodeSystem as an active resource and concept-properties as an active CodeSystem input, so both source/codesystem/codesystem-notes.xml and source/codesystem/codesystem-concept-properties.xml feed current build artifacts. The originating Zulip thread records the reporter being advised to file exactly this documentation request after discussion of absent notSelectable values, and the 2023-07-17 Vocab minutes record FHIR-38106 as resolved change required. Related FHIR-38104 and FHIR-38105 came from the same thread but concern separate filter-value and CodeSystem.property.type clarifications, so they are not decided here.

AutoFHIR reconciliation:
This commit updates the notSelectable row in source/codesystem/codesystem-notes.xml to include the same boolean/default-false sentence already present in the formal concept-properties CodeSystem definition. The hunk is necessary because the Jira related URL points readers to codesystem.html#properties, where the current narrative table otherwise omitted the approved default.

Recommendation:
Keep this source change. It closes the remaining current-build gap for FHIR-38106 without generalizing defaults to other properties or changing the separate related tracker decisions.
