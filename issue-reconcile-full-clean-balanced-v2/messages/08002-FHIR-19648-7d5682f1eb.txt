FHIR-19648: Audit JavaScript downloads link

Issue request:
FHIR-19648 was a Published/Persuasive STU3 FHIR-core change request for the downloads page. It reported that the downloads page referenced only fhir.js even though that JavaScript library was not well maintained and was not the only library people should consider, and it requested replacing that reference with a page where additional JavaScript references could be maintained over time.

Initial application:
The issue appears to have been applied in commit 1c2335f37881bf01454dff88123342d61a52a821, which replaced the source/downloads.html fhir.js row with a link to the HL7 wiki JavaScript implementations section. Commit 5755ae16f4100a5314f7a70404f951acc18a85f1 then changed that wiki URL to the corresponding HL7 Confluence page, matching the Jira resolution text.

Additional context:
Later FHIR-core changes kept the same policy direction rather than restoring fhir.js. FHIR-30088 and commit f575ef6b27e6bc5fc01db942c9cf8d00f50099f2 removed the per-language reference implementation rows, including the JavaScript row, and pointed the downloads page to Confluence for current implementation listings. FHIR-31735/commit 472abf78c495c2ae44924d499be7434ed50788d0 split tools out from the downloads page and added the current Confluence FHIR Tools Registry link. A later R6 cleanup removed the remaining standalone reference implementation section, leaving no fhir.js reference in current source.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The active source/downloads.html page is still part of the build and now points implementers to the HL7 Confluence FHIR Tools Registry for commonly used tools; searches of the current source found no downloads-page fhir.js reference to correct.

Recommendation:
Keep this audit commit as-is. Reintroducing a JavaScript-specific row would reverse later downloads-page simplification and is not needed to satisfy FHIR-19648; future implementation-library updates should be maintained on the Confluence tools/implementation registry rather than in core source.
