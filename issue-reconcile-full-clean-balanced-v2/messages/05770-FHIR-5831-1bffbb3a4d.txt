FHIR-5831: Audit EpisodeOfCare status rename

Issue request:
FHIR-5831 was a Published/Persuasive FHIR-core Patient Administration change request raised against DSTU1 EpisodeOfCare. It asked to rename EpisodeOfCare.currentStatus to EpisodeOfCare.status because statusHistory did not make the conventional status element name ambiguous, and the final resolution says currentStatus was updated to status as requested.

Initial application:
No explicit Jira-keyed source commit for FHIR-5831 was found by commit-message search. The change appears to have been applied implicitly in git commit f659c3fbc16870414aac80f798d75afcb5480bf8, whose EpisodeOfCare ballot-reconciliation patch changed the example element from <currentStatus> to <status> and changed the spreadsheet element path from EpisodeOfCare.currentStatus to EpisodeOfCare.status. The checked-in history page also records the DSTU2-era EpisodeOfCare rename from currentStatus to status.

Additional context:
EpisodeOfCare is in current core build scope through the active source/fhir.ini resource entry. The current StructureDefinition defines EpisodeOfCare.status and EpisodeOfCare.statusHistory as separate elements, the example instance uses <status>, and the EpisodeOfCare status search parameter points at EpisodeOfCare.status. A current-source grep found no EpisodeOfCare.currentStatus or currentStatus under source/episodeofcare; remaining currentStatus strings are historical release text or Action.currentStatus mappings on other resources. Related EpisodeOfCare status-code issues FHIR-5833 and FHIR-5834 are already represented on the combined branch by separate audit commits, so this commit does not duplicate them. Zulip and Confluence searches found no conflicting community evidence.

AutoFHIR reconciliation:
This commit intentionally makes no source changes. The active authoritative source already implements the requested rename and does not retain the old EpisodeOfCare.currentStatus path in current EpisodeOfCare artifacts.

Recommendation:
Keep this audit commit as-is. No follow-up source change is needed for FHIR-5831 unless a future work-group issue reopens EpisodeOfCare status naming.
