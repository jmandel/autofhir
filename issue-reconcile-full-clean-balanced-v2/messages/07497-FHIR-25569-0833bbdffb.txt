FHIR-25569: Audit ImplementationGuide cnl invariant

Issue request:
FHIR-25569 was a Published FHIR-core ImplementationGuide change request, resolved Persuasive with Modification for R5. It asked to put a cnl-style invariant on ImplementationGuide.definition.parameter.code and change existing implementation guide parameter codes to code-generation-friendly identifiers; the final resolution was to add the missing cnl invariant but not rename existing parameter codes because parameter.code is now Coding with an extensible binding.

Initial application:
No explicit source commit mentioning FHIR-25569 was found in the local FHIR history. The active ImplementationGuide StructureDefinition was introduced by the 2021 source rework with a cnl-0 constraint and a cnl-0 condition on ImplementationGuide.name; later canonical/metadata refactors preserved and normalized that invariant. The current guide parameter code system and value set still contain hyphenated codes, consistent with the final resolution not to make breaking code changes.

Additional context:
source/fhir.ini lists implementationguide=ImplementationGuide, so source/implementationguide/structuredefinition-ImplementationGuide.xml is in the current build scope. Current source defines ImplementationGuide.definition.parameter.code as Coding with an extensible binding to ValueSet/guide-parameter-code, so applying the name-oriented cnl-0 expression directly to parameter.code would be inappropriate and would contradict the rationale for not changing existing codes. FHIR-I WGM minutes from January 2020 record approval context for FHIR-25569 and note the impact on existing IGs/templates; no Zulip thread or later linked Jira issue was found that changes the published Jira/source conclusion.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current active source already reflects the durable part of the final resolution: ImplementationGuide has the cnl-0 name invariant and condition, while parameter.code remains Coding with an extensible guide-parameter binding and the existing guide-parameter codes are intentionally unchanged.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed unless the work group separately reopens the question of constraining ImplementationGuide.definition.parameter.code values or renaming the existing guide-parameter-code terminology, which would be a new breaking terminology decision.
