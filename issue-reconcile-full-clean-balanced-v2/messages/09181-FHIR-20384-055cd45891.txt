FHIR-20384: Audit logical-model Schematron handling

Issue request:
FHIR-20384 was a Published/Persuasive FHIR-core change request raised against STU3 and applied for R5. It asked that FHIR IG logical model pages stop creating links to Schematron files that are not generated, or otherwise have a flag/template distinction so logical models are not treated like regular model/profile pages for Schematron output.

Initial application:
No FHIR core commit explicitly mentions FHIR-20384, and the current core checkout does not contain an issue-specific source change for this tracker. The practical application appears in the IG base template repository: HL7/ig-template-base#134, merged on 2021-01-04, changed layouts/layout-profile.html so the Schematron link is skipped when modelType is 'Logical Model'.

Additional context:
The current FHIR core build has active logical models in source/fhir.ini, and the core logical model page template tools/templates/template-logical.html lists only XML and JSON master definitions, not Schematron. Zulip discussion around the same IG build error confirmed the intended base-template fix and recorded the merge; a later 2023 thread discusses a separate desire to generate Schematron for CDA-flavored logical models, but that is a distinct template/tooling feature request rather than a missing core-spec source edit.

AutoFHIR reconciliation:
This audit commit intentionally makes no FHIR core source change. The issue belongs to IG template/tooling outside this checkout, and the discovered external template change already implements the requested no-Schematron-link behavior for logical models. Editing core resource/profile templates would not address the IG base-template artifact named by the issue.

Recommendation:
Keep this external-repo audit commit as-is for FHIR core. If implementers still see logical-model Schematron links in current IG output, file or reconcile that against the active IG base template / publisher tooling rather than this core specification checkout; if CDA logical models need generated Schematron, handle that as a separate guide/tooling decision.
