FHIR-18827: Audit discontinued appointment status decision

Issue request:
FHIR-18827 was Published with a Not Persuasive with Modification resolution. It asked to add a `discontinued` code to `Appointment.status`, but the approved disposition kept post-start status tracking on Encounter and instead added an Encounter `discontinued` status with canonical status mapping changes.

Initial application:
The Jira-tagged implementation commit 6ac385ea8e added `discontinued` to the Encounter status code system and Encounter.status element text, and updated the status-code mapping matrix so Encounter `cancelled` maps to the failed canonical status while the new discontinued/abandoned state maps to the abandoned canonical status. No prior source change added `discontinued` to Appointment.status, which matches the non-persuasive portion of the decision.

Additional context:
The active build includes both Encounter and Appointment resources via `source/fhir.ini`. Current Appointment status still omits `discontinued` and its `fulfilled` definition says the encounter resource will track further status changes. Current Encounter status includes `discontinued`, and later FHIR-22726 added `discharged` plus corrected the discontinued definition typo without reversing the FHIR-18827 semantics. PA May 2019 minutes also record the work group conclusion that Appointment essentially ends when fulfilled/cancelled and subsequent status tracking belongs on Encounter.status.

AutoFHIR reconciliation:
This is an empty audit commit. The current source already implements the published issue outcome, so adding `discontinued` to Appointment.status would contradict the final resolution and no source change is needed.

Recommendation:
Keep this audit commit as-is. No follow-up is needed in the FHIR core checkout unless PA reopens the Appointment/Encounter boundary decision in a later tracker.
