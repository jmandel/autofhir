FHIR-9418: Audit datatype character-range guidance

Issue request:
FHIR-9418 was a Published/Persuasive with Modification DSTU2 request to add guidance on character ranges for string and markdown datatypes. The approved resolution asked for string and markdown to SHOULD exclude character points below 32 except horizontal tab, carriage return, and line feed, and to solicit implementer feedback on whether that SHOULD should become SHALL.

Initial application:
The issue was applied in git-svn revision 7996 as commit ed625d8f62, which added the string and markdown control-character notes plus a DSTU open-question todo. That initial text used the intended control-character guidance, though it also carried decimal/hex notation mistakes that were later corrected by FHIR-36679.

Additional context:
The active build-scoped datatype page is source/datatypes.html via source/fhir.ini [type-pages]. Current source states that strings SHOULD not contain Unicode character points below 32 except u0009, u000D, and u000A, recommends handling u000D/u000A/u000D u000A as new lines, defines markdown as a FHIR string, and explicitly says markdown is subject to the same string rules including valid characters. Later issues FHIR-16940, FHIR-36679, FHIR-38714, FHIR-48953, and a 2023 Zulip implementation thread refined or discussed the same area without contradicting the current SHOULD guidance or requiring the old DSTU open-question note to remain.

AutoFHIR reconciliation:
No source change was made. The current source already carries the requested guidance for string and markdown through the string datatype note and the markdown-as-string rule, with later corrections for the Unicode code points and newline handling.

Recommendation:
Keep this audit commit as-is. Reintroducing separate markdown wording or the old DSTU open question would be redundant and risks drifting from the current consolidated datatype guidance; any future move from SHOULD to SHALL would need a new work-group decision because the 2023 discussion noted normative and implementation constraints.
