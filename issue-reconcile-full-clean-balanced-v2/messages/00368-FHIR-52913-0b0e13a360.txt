FHIR-52913: Audit ServiceRequest perform-condition extension

Issue request:
FHIR-52913 was an Applied FHIR-core / ServiceRequest change request, resolved Persuasive with Modification, asking for a way to represent an "Other" option for treatment directives where ServiceRequest.doNotPerform is only boolean. The accepted resolution was to create a 0..1 modifier extension, perform-condition, on ServiceRequest root with value type Expression 1..1, usable when doNotPerform is false or absent, and with an invariant enforcing that condition.

Initial application:
No FHIR-core commit or current core source file was found applying FHIR-52913. The application happened in the FHIR Extension Pack: Jira comments point to HL7/fhir-extensions#243, and local extension-pack history shows commit 28f1751 creating input/definitions/ServiceRequest/StructureDefinition-servicerequest-performCondition.xml followed by merge commit a47afed, "FHIR-52913 Perform Condition Extension." The extension source defines the requested canonical URL, ServiceRequest context, contextInvariant, modifier flag, 0..1 cardinality, and required Expression value.

Additional context:
ServiceRequest is an active core resource in source/fhir.ini, and its current core StructureDefinition still correctly treats ServiceRequest.doNotPerform as the existing boolean. OO WGM minutes record the treatment-directive discussion and the idea of adding a doNotPerform-related extension. A later FHIR-extensions issue, FHIR-56311, is Triaged and unresolved; it asks for better usage guidance and cardinality rationale for this extension, so it is future extension-pack work rather than a final core-source correction.
