Issue request:
FHIR-5855 is a Published/Persuasive Patient Care change request from DSTU1 asking to add an optional Goal outcome so closed goals could record more detail than workflow status, with the approved motion to add outcome 0..* as a choice of CodeableConcept or Reference(Observation).

Initial application:
The original Jira key is not named in the March 2015 implementation commit, but commit db4ace37c6615c9732f958d34d6286fe739fc657 is the PC-approved change batch that cites the paired FHIR-5148 and added Goal.outcome 0..* with Goal.outcome.result[x] CodeableConcept | Reference(Observation). Later source history converted the pattern to Goal.outcome as CodeableReference(Observation) for R5-era source.

Additional context:
Goal is still an active current-build resource in source/fhir.ini, but current source intentionally has no active Goal.outcome element. FHIR-37262 was Applied as Not Persuasive with Modification to remove Goal.outcome and use resource-pertainsToGoal instead; that related issue is already represented on the combined branch by 08a7f575f86684c973ca907c77ebb564b781ad26. FHIR-53828 later added the current Goal narrative note pointing implementers to resource-pertainsToGoal, and FHIR-48360 resolved a direct Goal/Observation link request as No Change because the existing extension can be used. The extension definition now lives in the FHIR Extension Pack with Resource context and Reference(Goal) value.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding Goal.outcome for FHIR-5855 would reverse later final Patient Care decisions, while the current Goal notes already describe the replacement outcome/progress linkage through resource-pertainsToGoal.

Recommendation:
Keep this audit commit as-is. Do not restore Goal.outcome under FHIR-5855 unless Patient Care makes a new final decision superseding FHIR-37262/FHIR-48360; any Observation-side documentation should remain with its separate OO follow-up rather than this DSTU1 Goal outcome request.
