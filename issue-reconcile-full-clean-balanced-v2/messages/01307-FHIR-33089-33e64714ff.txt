FHIR-33089: Audit Evidence modelCharacteristic attribute reuse

Issue request:
FHIR-33089 was a Published/Persuasive R5 CDS change request asking to add Evidence.statistic.modelCharacteristic.attributeEstimate 0..* using the existing Evidence.statistic.attributeEstimate backbone element, with the short description "An attribute of the statistic used as a model characteristic".

Initial application:
The Jira comment points to commit e7d479cbe3978099d0b9c16201c07a2f3019dd0c, which added Evidence.statistic.modelCharacteristic.attributeEstimate as a contentReference to Evidence.statistic.attributeEstimate. Commit 7ac7d6258925baa8006bb8ba5ccddd7a62c9b1f4 then preserved the applied element while expanding Evidence.statistic directly after Evidence stopped using the Statistic datatype.

Additional context:
The current Evidence resource is active in source/fhir.ini and its StructureDefinition source now contains Evidence.statistic.modelCharacteristic.attribute 0..* with contentReference="#Evidence.statistic.attributeEstimate". That name difference is intentional: later Applied/Persuasive issue FHIR-43328 resolved for R6 to rename modelCharacteristic.attributeEstimate to modelCharacteristic.attribute because the reused structure is not always an estimate in this context. The current fhir.ini R5-to-R6 change map explicitly records Evidence.statistic.modelCharacteristic.attributeEstimate=@Evidence.statistic.modelCharacteristic.attribute.

AutoFHIR reconciliation:
This commit makes no source change. The current source already satisfies the substance of FHIR-33089 through the later-approved attribute element and preserves migration traceability for the original R5 attributeEstimate name.

Recommendation:
Keep this audit commit as-is. Reintroducing the old attributeEstimate element name would conflict with FHIR-43328; any further wording refinements to the current attribute element should be handled under a new Evidence/R6 issue, not as a FHIR-33089 fixup.
