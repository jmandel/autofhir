FHIR-10676: Audit Exchange module placement

Issue request:
FHIR-10676 was a Published/Persuasive with Modification FHIR-I issue raised in DSTU2 asking whether REST, Messaging, and Documents belonged better under Workflow than Foundation because they are architectural exchange approaches and listing them as common use cases was odd. The final resolution was to add quick links under Foundation for Messaging, Documents, and Services following REST API + Search, with a later Jira comment recording that this was already done as a new Exchange section.

Initial application:
No explicit FHIR-10676-tagged source commit was found in the current git history. The apparent application is the later untagged source reorganization in c397bd0b1f4c760dd227af300eaa8044b9e968a3, which created source/exchange-module.html, removed the old Foundation "Common Use Cases: Exchanging Data" text, removed REST API + Search from the Foundation module box, and added a dedicated Exchange box containing REST API + Search, Documents, Messaging, Services, and Databases.

Additional context:
The current source goes beyond the original quick-link wording by maintaining Exchange as a first-class module. source/modules.html includes the module diagram, source/modules-fragment.html lists Exchange beside the other Level 2 infrastructure modules with the requested links, source/foundation-module.html points to the Exchange module as the recognized methods of exchange, and source/workflow.html separately explains how REST, Messaging, Services, and Documents relate to workflow execution. Zulip and Confluence searches for FHIR-10676 and the issue wording found no conflicting work-group or community instruction.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped source already reflects the final applied resolution through the Exchange module and related links, while moving the exchange pages under Workflow now would contradict the later/current organization that distinguishes "How will information be exchanged?" from "When is information exchanged?".

Recommendation:
Keep this audit commit as-is. No follow-up source work is recommended for FHIR-10676 unless the work group separately decides to reorganize the module taxonomy again.
