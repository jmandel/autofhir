FHIR-16379: Audit CodeSystem and ValueSet definitions

Issue request:
FHIR-16379 was a Published/Persuasive STU3 Vocabulary issue asking that the CodeSystem and ValueSet definitions shown on the ValueSet and CodeSystem pages, including element definitions, be made consistent using the best of the glossary/page definitions while retaining the deliberate implementer-facing reference to enumerations.

Initial application:
The issue was applied in SVN revision 14665, now git commit 5416ae07ff434eba9704b8e386269467de646e52, which changed both source/codesystem/codesystem-introduction.xml and source/valueset/valueset-introduction.xml to contain the same paired CodeSystem and ValueSet definition bullets.

Additional context:
Later Published issue FHIR-39044 reconsidered that exact paired-bullet wording because the CodeSystem definition was self-referential, and its approved resolution removed those bullets from both pages for consistency. The same 2022 ballot neighborhood includes FHIR-39051, a Resolved - No Change issue saying the CodeSystem page's linked HL7 v3 Core Principles reference supplies the code system concept definition. Current source keeps the same introductory Core Principles sentence on both pages, keeps non-conflicting explanatory prose on the CodeSystem page, and carries full resource definitions in the current CodeSystem and ValueSet StructureDefinition descriptions/root definitions.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Restoring the identical 2018 bullets would reverse FHIR-39044, while editing the current short labels would add redundant wording without changing implementer understanding because the full authoritative root definitions are already present in the built resource definitions.

Recommendation:
Keep this no-change audit commit as-is. Future wording changes for the general code system/value set concept definitions should be handled as a new Vocabulary WG decision rather than as residual application of FHIR-16379.
