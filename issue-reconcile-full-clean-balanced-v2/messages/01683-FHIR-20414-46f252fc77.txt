FHIR-20414: Audit scalable security model references

Issue request:
FHIR-20414 was a Published Security WG change request, resolved Persuasive with Modification for R5, asking the FHIR-core security page to add a short reference to Unified Data Access Profiles (UDAP) as an OAuth 2.0-based scalable authorization/authentication model using JWTs and X.509 certificates.

Initial application:
The Jira comments point to HL7/fhir PR #708. Git history shows commit b569c4406b1d2a7944cc4b25869f7075524fe4f3 added the requested UDAP paragraph to source/security.html in the Approaches to Implementing Access Control section, and later security-page refactors preserved and moved that content into more specific UDAP/FAST guidance.

Additional context:
FHIR-53719 is a later Applied/Persuasive Security WG decision on the same security page and security-model family. It concluded that UDAP/FAST scalable security guidance should be relaxed from SHOULD to MAY and that Tiered OAuth should be removed from the base spec. Current source/security.html is in build scope through source/hierarchy.xml and now names FAST Security for Scalable Registration, Authentication, and Authorization in the authentication and access-control guidance, with a ballot note explicitly recording the UDAP-to-FAST naming update and MAY-strength guidance for FHIR-53719.

AutoFHIR reconciliation:
This commit makes no source change. The original FHIR-20414 request has already been applied, and reintroducing the old standalone UDAP wording would conflict with the later FHIR-53719 update that intentionally reframed the references as FAST Security and relaxed the recommendation strength.

Recommendation:
Keep this audit commit as-is. The current source correctly reflects the issue family; any future desire for additional FAST Security explanation should be handled as a new Security WG content decision rather than as a FHIR-20414 fixup.
