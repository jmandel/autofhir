FHIR-6089: Audit ContactPoint alternate systems

Issue request:
FHIR-6089 is a Published/Persuasive with Modification FHIR-core datatypes change request from DSTU1. It objected that ContactPoint.system required one of a small fixed set while real contact points could include pagers, TTY devices, EDI addresses, and other systems. The approved resolution was to document URL handling and why phone/fax/email were not modeled as URLs, rename the old "url" code to "other", say "other" values SHOULD be URLs when possible and require human interpretation otherwise, and create separate follow-up work for hearing-impaired requirements.

Initial application:
The issue was applied by the 2015-07-16 commit 1bb4eba1e593ff7b4827c82c0fde3a99b3691fc1, whose message says "#6089 - change ContactPoint.system.url to ContactPoint.system.other". That commit updated the ContactPoint datatype spreadsheet and datatypes narrative, added pager alongside the then-current phone/fax/email/other set, and added the URL/human-interpretation explanatory paragraph.

Additional context:
Later final ContactPoint.system decisions changed how the original FHIR-6089 resolution should be interpreted now. FHIR-10647 restored the distinct "url" code because removing it caused confusion, while retaining "other" for contacts not expressible as URLs. FHIR-12684 added "sms". Later no-change decisions including FHIR-32004, FHIR-36033, and FHIR-39154 retained the required ContactPoint.system binding and pointed additional contact technologies to the existing url/other codes, extensions, or future releases. A companion FHIR-10647 reconciliation commit in this branch aligned source/datatypes.html with the restored url/other split, so the current source now reflects both FHIR-6089 and the later published reversal.

AutoFHIR reconciliation:
This commit intentionally makes no additional source change for FHIR-6089. The active ContactPoint datatype source now allows alternate contact systems through the current required code set, distinguishes URL-expressible contacts from non-URL "other" contacts, and preserves the explanatory URL/human-interpretation guidance without reverting later final decisions.

Recommendation:
Keep this audit commit as-is. No FHIR-6089-specific source work remains in core; future requests for additional ContactPoint.system technologies should be evaluated as new work group decisions because ContactPoint is normative and the current binding remains required.
