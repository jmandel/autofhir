FHIR-13139: Audit contentReference profiling application

Issue request:
FHIR-13139 was a Published/Persuasive FHIR-core change request raised against DSTU2 and applied for STU3. It reported that a PlanDefinition profile could not constrain children below PlanDefinition.action.action because that element uses contentReference, and asked either for tooling to unwrap the contentReference in profile differentials/snapshots or for a reusable-profile mechanism for the referenced backbone element.

Initial application:
The issue was applied in git-svn commit bcfc15cded26440789c73645f859a8c5b4e0d084, whose message says "#13139 - fix profiling on content reference" and cites SVN revision 11862. That commit changed the DSTU3 Java ProfileUtilities snapshot-generation logic and added standard test IG/snapshot examples; it did not change current authoritative core source files. Those historical implementation/test paths are no longer present in the current checkout.

Additional context:
PlanDefinition remains an active current resource and PlanDefinition.action.action still uses contentReference, so the original artifact family is still relevant. Later Published FHIR-14958 clarified the normative contentReference rule in ElementDefinition: contentReferences can only be introduced in specializations, cannot be changed by constrained types, always reference the non-constrained definition, and bring across the referenced ElementDefinition rules. That issue is already represented on the combined branch. Later recursive-profiling guidance and follow-up concerns are also already represented by the existing FHIR-39753 human-review audit; the pending FHIR-57266 rewrite is only Resolved - change required and depends on paired extension-pack work.
