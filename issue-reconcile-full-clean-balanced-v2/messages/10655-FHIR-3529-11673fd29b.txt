FHIR-3529: Audit profile rendering publication fix

Issue request:
FHIR-3529 was a Published/Persuasive FHIR-core change request for DSTU1 reporting that profile displays were not showing profile-specific mustSupport, binding.conformance, or binding.isExtensible information.

Initial application:
The issue was applied in the migrated SVN history. Commit e193751a651b9cbff5b56cfc0cc95121b2a45a43, git-svn build@3117, updated ProfileUtilities so profiled elements display modifier, must-support, and summary markers and append binding conformance/isExtensible details. Commit ccb4093f15ca9635619216b6c9e0de499c91e230, build@3118, added the supporting marker images.

Additional context:
The current build no longer stores that old ProfileUtilities implementation in this repository; it depends on kindling 1.25.5-SNAPSHOT. The current kindling source renders mustSupport as an S marker linked to conformance-rules.html#mustSupport and renders binding strength in profile tables. Current source profiles use the modern ElementDefinition.binding.strength field instead of the obsolete binding.conformance and binding.isExtensible split, and active Observation/Vital Signs profile source still contains mustSupport flags and binding strengths. Current build.fhir.org output for those profiles contains Must Support and Terminology Binding rows and profile JSON includes the corresponding mustSupport and binding.strength data. No Zulip or Confluence evidence was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The historically requested profile-publication behavior is already present in the current build inputs, current kindling renderer, and current generated profile output.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-3529 unless a future publisher regression removes mustSupport or binding strength from profile renderings.
