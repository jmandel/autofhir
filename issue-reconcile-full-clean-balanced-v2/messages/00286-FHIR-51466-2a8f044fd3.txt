FHIR-51466: Audit canonical above/below clarification

Issue request:
FHIR-51466 was an Applied/Persuasive FHIR-I change request for R6 asking that the search page clarify how :above and :below behave for reference search parameters whose target is a canonical element, especially whether supplied versions are used as partial matches or only as inputs to a final ordered comparison. The approved resolution replaced the canonical-reference text so servers may use a specified or inferred version scheme, keep unknown-scheme criteria ignored or rejected, compare :above as greater-than and :below as less-than against that version scheme, exclude versions that match the supplied canonical search, and return matching versions in no particular order.

Initial application:
The issue was applied before this reconciliation by source commit 4dbcb67f72d1f701f1368db66f7a4b6250456583, included in merged PR HL7/fhir#3967. That commit changed the active source/search.html canonical-target subsections for both :above and :below, replacing the old "known version scheme" wording with "specified or inferred", and adding the exclusion and unordered-result semantics required by the Jira resolution.

Additional context:
The Jira resolution explicitly depends on the version-matching text added by FHIR-52895. Current source/references.html contains the FHIR-52895 canonical version matching rules for SemVer, date, URL, and fallback string schemes, and source/search.html already points canonical search readers to the References and Versions and Choosing the right Canonical Reference sections. FHIR-I WGM minutes and the linked Zulip thread show FHIR-52895 and FHIR-51466 were voted as the same version-matching discussion family; a direct Zulip search for FHIR-51466 found no conflicting implementation guidance.
