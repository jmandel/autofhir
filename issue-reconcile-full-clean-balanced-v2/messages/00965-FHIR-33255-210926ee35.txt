FHIR-33255: Audit intolerance definition clarification

Issue request:
FHIR-33255 was Published with a Persuasive with Modification resolution asking Patient Care to clarify the AllergyIntoleranceType CodeSystem definition of `intolerance` to say a propensity for adverse reactions to a substance that "is judged to be not" allergic or "allergy-like", with the existing non-immune, idiosyncratic, and patient-specific explanatory text.

Initial application:
The issue was applied by commit 9640a8b81743c06345b4dcdf7f5e72d89e23c444, which changed `source/allergyintolerance/codesystem-allergy-intolerance-type.xml` from "not judged to be allergic" to "judged to be not allergic". Later OID/formatting work in ab195a73a8e6090dbd0620b88025adfc5fbbd3c4 preserved that wording.

Additional context:
`source/fhir.ini` actively lists `allergyintolerance=AllergyIntolerance`, so the AllergyIntolerance source folder is in the current build. The Patient Care Zulip thread and Confluence minutes record the rationale that `intolerance` means non-allergy intolerance and that `AllergyIntolerance.type` should be omitted when the distinction is unknown. Later same-artifact issues did not supersede this definition: FHIR-35879 changed `AllergyIntolerance.type` to CodeableConcept with preferred binding, FHIR-38695 was its duplicate ballot issue, FHIR-35890 was resolved no-change because existing comments already covered type uncertainty, and FHIR-55316 later confirmed the value set remains intentionally narrow.

AutoFHIR reconciliation:
This audit commit makes no source change because the current active CodeSystem already contains the resolved FHIR-33255 wording at `source/allergyintolerance/codesystem-allergy-intolerance-type.xml:56-58`, and searches found no remaining active-source occurrence of the old "not judged to be allergic" wording.

Recommendation:
Keep this no-change audit commit as-is. No follow-up is needed for FHIR-33255 unless Patient Care reopens the broader AllergyIntolerance.type semantics in a future issue.
