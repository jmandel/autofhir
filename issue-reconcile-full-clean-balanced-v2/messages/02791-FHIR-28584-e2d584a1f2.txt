FHIR-28584: Audit medication CodeableReference model

Issue request:
FHIR-28584 was a Published BR&R FHIR-core change request, resolved Persuasive for R5, asking to use CodeableReference so medication-definition products could use either simple codes or fuller resources for MedicinalProductDefinition.ingredient, MedicinalProductDefinition.packagedMedicinalProduct, PackagedMedicinalProduct.package.containedItem.item, and ManufacturedItemDefinition.ingredient.

Initial application:
The issue was explicitly applied before this reconciliation. Git e9799080ee changed medication-definition examples and source inputs for FHIR#28584, and git 0ee3e67a82 continued the same FHIR#28584 CodeableReference work while also applying the adjacent FHIR#28435 and FHIR#28583 changes. The current StructureDefinition XML is in build scope through active fhir.ini entries for MedicinalProductDefinition, PackagedProductDefinition, ManufacturedItemDefinition, and Ingredient.

Additional context:
Later Published BR&R issues changed the same model. FHIR-31808 reversed ingredient link direction, leaving product resources with coded ingredient shortcuts while detailed Ingredient resources point back to the products that use them. FHIR-31859 removed MedicinalProductDefinition-to-PackagedProductDefinition references to avoid bidirectional links, and FHIR-31782/FHIR-31596 history explains why the simple package backbone was not retained. These later decisions are already represented on the combined branch, so this seed should not reintroduce the older CodeableReference targets.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source already preserves the parts of FHIR-28584 that remain valid after later decisions: PackagedProductDefinition.packaging.containedItem.item is a CodeableReference with ManufacturedItemDefinition, DeviceDefinition, PackagedProductDefinition, BiologicallyDerivedProduct, and NutritionProduct targets; MedicinalProductDefinition.ingredient and ManufacturedItemDefinition.ingredient are CodeableConcept coded shortcuts whose definitions point to incoming Ingredient references for detailed modeling; MedicinalProductDefinition.packagedMedicinalProduct is a coded package type, with the full package relationship now represented from PackagedProductDefinition.packageFor to MedicinalProductDefinition.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-28584 unless BR&R opens a new issue to revisit the later one-way Ingredient and PackagedProductDefinition relationship decisions.
