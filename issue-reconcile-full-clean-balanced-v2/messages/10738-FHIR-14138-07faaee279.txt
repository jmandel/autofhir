FHIR-14138: Audit superseded transaction version references

Issue request:
FHIR-14138 was a Published FHIR-I STU3 change request resolved Persuasive. It asked the HTTP transaction rules to clarify that, when a transaction creates or updates related resources and the client does not yet know the server-assigned versionId, a version-specific reference could use an arbitrary version because transaction reference rewriting would update the version-specific reference to the actual server-assigned version.

Initial application:
The issue was applied by HL7/fhir commit 39bbdfc466f00e43e561a63ae7a34104d306feed, "GF#14138 - note about version specific references", which added the sentence that clients could use arbitrarily chosen version references because they would be re-assigned. FHIR-14005 was resolved No Change because its closely related question was considered answered by FHIR-14138.

Additional context:
The linked 2017 Zulip thread shows the original assumption that temporary version ids would be replaced, but also the concern that rewriting historical version references could be unsafe. That concern was later resolved by Published issues FHIR-34344 and FHIR-34343: FHIR-34344 explicitly found the FHIR-14138 wording not careful enough, removed the broad "arbitrarily chosen version references" / "re-assigned anyway" text, and replaced it with guidance that existing version-specific references are expected to point to already-existing versions. FHIR-34343 approved the resolve-as-version-specific extension for transaction references to resources being created or updated in the same transaction. Later cleanup and example issues kept that newer mechanism intact.

AutoFHIR reconciliation:
No source change was made. The active source/http.html transaction section already reflects the later FHIR-34344/FHIR-34343 interpretation, the superseded FHIR-14138 wording is absent, the Extension Pack contains the resolve-as-version-specific definition, and the transaction Bundle example demonstrates the supported way to request server-assigned version-specific references.

Recommendation:
Keep this no-change audit commit. Do not restore the original arbitrary-version sentence; it was deliberately superseded because it over-described reference rewriting. Future changes to this behavior should be handled through the later resolve-as-version-specific issue family rather than through FHIR-14138.
