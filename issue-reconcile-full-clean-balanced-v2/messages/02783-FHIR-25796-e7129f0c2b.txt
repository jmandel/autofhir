FHIR-25796: Audit corrected RiskAssessment ras-2 constraint

Issue request:
FHIR-25796 was a Published, Persuasive CDS technical correction for RiskAssessment.prediction. The Jira reported that ras-2 used `probability is decimal implies (probability as decimal) <= 100`, which fails valid predictions with no probability value because the empty FHIRPath result is not a satisfied constraint, and requested an existence-guarded expression.

Initial application:
The Jira comment says the change was applied to master and R4B. Git history shows R4B commit e1bc1023d533d370b4110537f2328e514f589b6b (`J#25796: Fixed riskassessment constraint`) replacing the broken expression with `probability.exists($this is decimal) implies (probability as decimal) <= 100`. The current branch carries the same semantic correction through later master history: commit f3776db814632e6cab1020e2299919bb529201da changed the active RiskAssessment StructureDefinition to `probability.empty() or ((probability is decimal) implies ((probability as decimal) <= 100))`.

Additional context:
RiskAssessment is active in source/fhir.ini, so source/riskassessment/structuredefinition-RiskAssessment.xml is current build input. FHIR-27875 later changed the same probability element by adding Quantity support and ras-3; its implementation briefly rewrote ras-2 while preserving the missing-probability guard, and follow-up commit 46a47e604d2492e8e74a315907263b2fe2590667 restored the current decimal comparison. The combined branch already has a separate FHIR-27875 reconciliation commit, so this audit does not decide that later issue. Zulip discussion confirms both the general empty-collection FHIRPath problem and the specific RiskAssessment R4/R4B validator failure; Confluence searches found no conflicting minutes.

AutoFHIR reconciliation:
This commit makes no source change. The active current source already allows RiskAssessment.prediction without probability while still enforcing decimal probabilities to be <= 100, which satisfies the FHIR-25796 request. The remaining old broken ras-2 text found by search is in tools/history release snapshots for earlier published versions, not authoritative current-build source.

Recommendation:
Keep this empty audit commit as-is. No current core source follow-up is needed for FHIR-25796; any R4/R4B validator override behavior is outside this current-build reconciliation.
