FHIR-37416: Finish MessageHeader event cleanup in messaging examples

Issue request:
FHIR-37416 was a Published/Persuasive FHIR-core technical correction for the messaging page, raised against R5, asking that the section 3.4.6 examples for invoking operations via messages stop using DSTU2-era MessageHeader.data and MessageHeader.event forms and instead align with current MessageHeader.focus and MessageHeader.event[x].

Initial application:
The issue was initially applied by git commit 307c3216b45f4fc4ba59d6026605cad823d47daf, which changed the operation-message examples in source/messaging.html from MessageHeader.data to MessageHeader.focus and from <event> to <eventCoding>. That application did not update all surrounding prose in the active messaging page: the bundle rule still named MessageHeader.event, the operation bullets still said event.system and event.code, and the single-return bullet misspelled MessageHeader.focus.

Additional context:
source/messaging.html is an active core narrative page linked from source/documentation.html, and MessageHeader is an active resource in source/fhir.ini. The current MessageHeader definition uses MessageHeader.event[x] with a Coding choice represented in XML as eventCoding, and MessageHeader.focus for the actual message content. Community searches found no directly relevant Zulip or Confluence record that changed the Jira/source conclusion; later generic eventCoding discussions were about binding policy, not this example cleanup.

AutoFHIR reconciliation:
This commit updates the active messaging page to use MessageHeader.event[x] in the bundle rule, MessageHeader.eventCoding.system and MessageHeader.eventCoding.code in the operation invocation bullets, and the correctly spelled/code-formatted MessageHeader.focus in the single-return bullet. No generated artifacts or out-of-scope files were edited.

Recommendation:
Keep this commit as-is. It completes the already-applied FHIR-37416 cleanup in current core source without reopening broader messaging semantics or related binding-policy work.
