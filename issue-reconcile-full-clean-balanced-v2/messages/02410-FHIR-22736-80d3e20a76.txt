FHIR-22736: Audit AdverseEvent code style

Issue request:
FHIR-22736 was a Published/Persuasive Patient Care change request for R5 asking that the AdverseEvent causality assessment, causality method, outcome, and seriousness code systems use lowercase codes with dashes.

Initial application:
The Jira comments identify pre-applied commits 8f2524d and baf2691, plus follow-up 19edc88 after the reporter noted that one causality-assessment code, Certain, had been missed. Those commits changed the then-authoritative AdverseEvent spreadsheet and the AdverseEvent example so the affected local codes used lowercase/dash form.

Additional context:
AdverseEvent is active in the current build. Later AdverseEvent terminology refactors converted the current core source from the old spreadsheet to XML ValueSet and StructureDefinition files, removed duplicated THO CodeSystem files from core, and changed AdverseEvent.outcome to an example binding over a SNOMED CT value set rather than a local AdverseEvent outcome code system. The current core ValueSet files for seriousness and causality include THO CodeSystems, and the local THO package has only lowercase/dash codes for the remaining affected CodeSystems.

AutoFHIR reconciliation:
This is an empty audit commit. No source edit is needed because the current core source points to the correct ValueSets/CodeSystems, the current AdverseEvent example uses non-serious, the remaining THO AdverseEvent CodeSystem codes are lowercase/dash-form, and the outcome item no longer has a local core code system to normalize.

Recommendation:
Keep this no-change audit as-is. No core follow-up is indicated for FHIR-22736; any future edits to the remaining causality or seriousness code definitions belong in THO/terminology source rather than this core checkout.
