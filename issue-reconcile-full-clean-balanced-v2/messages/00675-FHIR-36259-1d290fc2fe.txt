FHIR-36259: Correct MedicationDispense example code system URL

Issue request:
FHIR-36259 was Published/Persuasive for R5 after Pharmacy agreed that the MedicationDispense category and status-reason CodeSystems defined by FHIR should use http://hl7.org/fhir/CodeSystem/... URLs, not the erroneous http://terminology.hl7.org/fhir/CodeSystem/... URLs seen in R4B candidate content.

Initial application:
Commit b9257918056a31ebdc080627432cc94db78637e0 applied FHIR-36259 by changing the MedicationDispense category and status-reason CodeSystem definitions and ValueSet compose.system entries to http://hl7.org/fhir. That application did not touch the built MedicationDispense example meddisp0303, whose category coding still carried the older http://terminology.hl7.org/fhir/CodeSystem/medicationdispense-category URL introduced by e82afc8031b6f3b395044435f63b29f33554dfbc.

Additional context:
MedicationDispense is an active resource in source/fhir.ini, and list-MedicationDispense-examples.xml includes medicationdispense0303, so the stale example is in current build scope. The linked Zulip discussion and Pharmacy minutes confirm the R5 URL target and that R4B users should keep the published R4B URL rather than treating this as errata. The broader FHIR-37440 URL review and the later Triaged FHIR-53306 future-THO note do not supersede the MedicationDispense-specific R5 correction; the FHIR-53306 notes are left untouched because they are about possible future terminology governance, not the current canonical URL in examples.

AutoFHIR reconciliation:
Changed source/medicationdispense/medicationdispense0303.xml so its MedicationDispense.category coding uses http://hl7.org/fhir/CodeSystem/medicationdispense-category, matching the current CodeSystem, ValueSet compose, OID registry, and binding target. No generated artifacts or unrelated ballot notes were edited.

Recommendation:
Keep this source fix. If Pharmacy/Vocab later finalizes moving medication category codes to THO, handle that as a separate issue because the current published FHIR-36259 decision still requires the FHIR-owned canonical in current core examples.
