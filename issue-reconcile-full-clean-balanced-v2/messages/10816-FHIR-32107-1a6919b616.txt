FHIR-32107: Audit R4B SearchParameter package restoration

Issue request:
FHIR-32107 was a Published/Persuasive FHIR-I technical correction for FHIR-core SearchParameter, raised against the 2021Mar R4B core package and applied for R5. It reported that the package exposed only about 25 SearchParameter definitions and that the definitions present were experimental, where roughly 1,400 SearchParameters were expected.

Initial application:
No source commit explicitly mentioning FHIR-32107 was found. FHIR-I minutes identify it as a tooling issue assigned to Grahame and later note that it would be addressed during the final R4B release. Rechecking the referenced 2021Mar package reproduces the reported defect: 25 SearchParameter files with 24 experimental=true. The published R4B core package now contains 1,439 SearchParameter files with 1,415 explicit experimental=false entries, showing that the package-generation defect was historically corrected outside a Jira-tagged source commit.

Additional context:
FHIR-32782 is the R5 copy of the same defect and its resolution points back to FHIR-32107. FHIR-26430 and FHIR-36879 are related but distinct definition/clarification issues: they explain why some search controls are intentionally not SearchParameter resources, while common Resource parameters such as _query and _filter now have definitions. FHIR-39010 later added a separate R5-and-later search-parameter package with uncombined resource-specific SearchParameters, so current package counts and package names are affected by later package-output decisions rather than a remaining FHIR-32107 defect.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. Current build source keeps SearchParameter as an active resource, current source contains 147 resource search-parameter bundle files with 2,077 SearchParameter entries and no experimental=true flag in those source bundles, and current published packages no longer show the 25-mostly-experimental SearchParameter failure.

Recommendation:
Keep this audit as-is. Do not edit current SearchParameter source for FHIR-32107; any future package-count or package-generation regression should be handled as a new tooling/package publication issue with concrete current package evidence.
