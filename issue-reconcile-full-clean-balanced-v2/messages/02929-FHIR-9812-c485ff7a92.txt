FHIR-9812: Audit AuditEvent purpose guidance

Issue request:
FHIR-9812 was a Published Security change request with a Persuasive with Modification resolution to add an AuditEvent note explaining PurposeOfEvent at the event level and PurposeOfUse at the agent level, including when reporting systems may omit either because the purpose is unknown and how different reporting perspectives may have different knowledge.

Initial application:
The requested note appears to have been applied by git commit 7755ff73d6, "Security WG updates to GF#9150, GF#9151, GF#9812, GF#9840, GF#9919, and GF#10046." That commit added a PurposeOfEvent and PurposeOfUse section to source/auditevent/auditevent-notes.xml in the active AuditEvent resource source.

Additional context:
Later AuditEvent work, especially FHIR-32515, changed the model from purposeOfEvent and agent.purposeOfUse to authorization and agent.authorization, lowered the PurposeOfUse binding to example, and kept PurposeOfEvent/PurposeOfUse as aliases. Current source/fhir.ini maps the old names to the current elements, and current StructureDefinition text and notes use the current authorization element names while preserving the distinction requested by FHIR-9812. Direct community searches found no FHIR-9812-specific conflicting discussion; a later Zulip thread and Security minutes support the broader authorization/PurposeOfUse context addressed by FHIR-32515.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current AuditEvent notes already explain the whole-event and per-agent purpose distinction, omission when unknown, and differing reporter perspectives, adapted to the current authorization and agent.authorization element names. Changing the note back to the original PurposeOfEvent/PurposeOfUse wording would be stale for the current build.

Recommendation:
Keep this no-change audit commit as-is. No current core source follow-up is needed for FHIR-9812; any future editorial cleanup should preserve the current authorization naming and alias relationship established by later Security decisions.
