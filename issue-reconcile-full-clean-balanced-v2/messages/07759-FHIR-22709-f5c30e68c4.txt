FHIR-22709: Audit Bundle document date invariant

Issue request:
FHIR-22709 was a Published/Persuasive FHIR-core change request from FHIR-I for the Bundle document-date invariant, then called bd-10. It reported that the invariant required a document Bundle date via Bundle.meta.lastUpdated, but the document date should be Bundle.timestamp, and the resolution specifically required the FHIRPath, XPath, and schematron surfaces to be corrected.

Initial application:
The issue was applied before this reconciliation by git commit 937db6abc7, which changed the Bundle bdl-10 FHIRPath expression from meta.lastUpdated.hasValue() to the Bundle timestamp and changed the XPath from f:meta/f:lastUpdated to f:timestamp. A same-day follow-up commit, 1f05d72e2a, updated the discharge summary document example to use Bundle.timestamp rather than Bundle.meta.lastUpdated.

Additional context:
Bundle is an active current-build resource in source/fhir.ini. Later source cleanup removed XPath constraints from ElementDefinition source generally, so there is no current XPath source field to correct; the authoritative current Bundle StructureDefinition keeps bdl-10 as type = 'document' implies (timestamp.hasValue()). The document-bundle profile also makes Bundle.timestamp mandatory for document Bundles. Confluence FHIR-I minutes from 2019-07-22 record the accepted intent as updating Bundle.timestamp and fixing FHIRPath and XPath, and the 2021 Zulip implementation thread ties the applied FHIR-22709 fix to the same timestamp/date work as FHIR-20210.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current authoritative source already enforces the issue's requested rule on Bundle.timestamp, no stale meta.lastUpdated.hasValue() or f:meta/f:lastUpdated invariant source remains under source/, and the later removal of XPath source means there is no separate current XPath or schematron source hunk to apply.

Recommendation:
Keep this commit as-is. No follow-up is needed for FHIR-22709 in the core spec unless a future build reintroduces checked-in XPath or schematron invariant source, in which case bdl-10 should still target Bundle.timestamp.
