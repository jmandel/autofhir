FHIR-16922: Audit IssueType transient clarification

Issue request:
FHIR-16922 was a Published FHIR-core CodeSystem change request, resolved Persuasive with Modification, asking why issue-type `incomplete` was a processing error rather than transient and whether `no-store` was a specialization of it. The accepted resolution moved `incomplete` to transient and clarified that `incomplete` is a partial-response condition while `no-store` means the persistent store is unavailable and the request cannot be processed.

Initial application:
The issue was applied in svn revision 13993, represented in git by 98f2e0e4c8 (GF#16922 - fix IssueType structure). That commit moved `incomplete` from the processing parent to the transient parent in `source/operationoutcome/operationoutcome-spreadsheet.xml`, updated the `no-store` definition to say the interaction or operation cannot be processed, and updated `incomplete` to describe partial returned results. The current source has since been refactored/generated into `source/operationoutcome/codesystem-issue-type.xml`.

Additional context:
`OperationOutcome` remains in the current build scope as an active resource/special resource with FHIR-I ownership and FMM 5 metadata in `source/fhir.ini`. Current `codesystem-issue-type.xml` declares `hierarchyMeaning="is-a"` and places `no-store` and `incomplete` as sibling child concepts under `transient`, with definitions distinguishing no response/cannot process from partial returned information. Jira searches found only FHIR-16922 for the incomplete/no-store IssueType clarification, and Zulip/Confluence searches found no conflicting community record.

AutoFHIR reconciliation:
No source change was made. The current authoritative CodeSystem already reflects the applied issue by moving `incomplete` under `transient` and not making `no-store` a specialization of it. Editing the current normative terminology would risk undoing the documented 2018 application rather than correcting the current build.

Recommendation:
Keep this no-change audit commit as-is. Revisit only if FHIR-I opens a new tracker to narrow or revise the current `incomplete` definition wording for operations.
