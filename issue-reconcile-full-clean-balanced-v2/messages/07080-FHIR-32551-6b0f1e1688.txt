FHIR-32551: Audit Device UDI identifier cardinality

Issue request:
FHIR-32551 was a Published/Persuasive FHIR-core Device change request raised against R4 and applied for R5. It asked why Device.udiCarrier.deviceIdentifier was optional despite short and long descriptions saying the component is mandatory, and the accepted resolution was to change Device.udiCarrier.deviceIdentifier to 1..1 because if a udiCarrier is present then the device identifier must be available.

Initial application:
The Jira comment says the issue was added to the build through the FHIR-32551 PR, and the source-changing commit 131f95eafe changed source/device/structuredefinition-Device.xml from <min value="0"/> to <min value="1"/> for Device.udiCarrier.deviceIdentifier. Current blame still attributes the min=1 line to that commit.

Additional context:
Device is active in the current build through source/fhir.ini. Later Device/UDI work such as FHIR-43063 and FHIR-47419 added Device.udiCarrier.deviceIdentifierSystem and clarified UDI wording, while preserving Device.udiCarrier.deviceIdentifier at 1..1. FHIR-20564 later rejected adding a cross-resource invariant between Device and DeviceDefinition, but did not change the per-udiCarrier requirement. Community checks found OO Confluence block-vote/minutes references for FHIR-32551 and no direct Zulip discussion or conflicting later community record.

AutoFHIR reconciliation:
No source change was made. The active Device StructureDefinition already has Device.udiCarrier.deviceIdentifier with min=1 and max=1, and the current build profile reports the same cardinality.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-32551 unless a future OO decision intentionally changes the UDI carrier model.
