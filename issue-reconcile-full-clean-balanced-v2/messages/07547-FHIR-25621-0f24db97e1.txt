FHIR-25621: Package generated ShEx artifacts

Issue request:
FHIR-25621 was Published/Persuasive for R5 and asked that fhir.schema.shex.zip include all generated ShEx artifacts, not only fhir.shex, so consumers can use granular schemas such as resource- or datatype-specific ShEx files.

Initial application:
No git history entry mentioning FHIR-25621 or 25621 was found. The earlier FHIR-20561/GF#20561 history fixed the existence/linkage of fhir.schema.shex.zip, but not the later requirement to include all ShEx artifacts. The current CI build still serves fhir.schema.shex.zip with only fhir.shex.

Additional context:
FHIR-I minutes for 2020-01-27 record FHIR-25621 as Persuasive by Grahame/Eric 9-0-0. The current build separately exposes granular ShEx content, including raw resource ShEx such as patient.shex and generated ShEx HTML pages such as integer.shex with an embedded ShEx pre block, so the missing piece is packaging those generated artifacts into the downloadable ZIP. The root Gradle build is in scope because README.md and publish.sh direct editors and CI to run ./gradlew publish, which executes build.gradle.kts tasks.

AutoFHIR reconciliation:
Updated build.gradle.kts so publish and publishFull refresh publish/fhir.schema.shex.zip after the publisher succeeds. The packager collects generated .shex and .shex.html artifacts from publish/, extracts raw ShEx from generated ShEx HTML pages when necessary, prefers raw .shex files over duplicate HTML renderings, and fails explicitly if no ShEx artifacts are available. A standalone packageShexSchemas task was also added for direct validation or recovery use.

Recommendation:
Keep this source fix. A full publisher run should now produce a multi-entry fhir.schema.shex.zip containing raw granular ShEx entries; if kindling later changes where ShEx artifacts are emitted, revisit the publishDir scan rather than reverting to a single fhir.shex ZIP.
