FHIR-6255: Audit relative date offset support

Issue request:
FHIR-6255 was Published/Persuasive for FHIR-core datatypes after being raised in DSTU1. It asked that Timing support offsets such as chemotherapy cycle days, and the accepted resolution was to add a complex extension to dateTime and date that captures an offset from an identified or coded event.

Initial application:
The request was applied by the historical git-svn commit 645a626442a75d4e2c27e7f8503676741e8b9150, matching Jira's svn revision 13462 comment. That commit added the relative-date extension to source/profiles/general-extensions-spreadsheet.xml with date/dateTime context, an event represented as Reference(Any) or CodeableConcept, and a required Duration offset.

Additional context:
Later trackers refined and reorganized the same relative-time family. FHIR-32899 reconciled relative-date with cqf-relativeDateTime, FHIR-34232 refined relative-date offset semantics, and FHIR-41582 created the core RelativeTime datatype for R6. Core extensions were then removed from the FHIR core source in dd468d4f1799dd79819315b211588ef1cf4586e0 and are now maintained in the FHIR Extension Pack. The current extension-pack relative-date definition remains active for date and dateTime and carries the event/offset structure, while the newer relative-time extension is still an extension-pack follow-up constrained by tooling and cross-version support.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core build has RelativeTime active in source/fhir.ini and defined in source/datatypes/relativetime.xml, and the date/dateTime extension requested by FHIR-6255 is present in the Extension Pack rather than the current core source checkout. Re-adding or duplicating that extension in core would be out of build scope and would conflict with the current extension-pack ownership model.

Recommendation:
Keep this audit commit as-is for FHIR-6255. No core source follow-up is needed for the seed issue; any remaining activation of the newer relative-time extension should be handled in the FHIR Extension Pack under its own trackers rather than as a core FHIR-6255 fix.
