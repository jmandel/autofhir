FHIR-17202: Audit MetadataResource URL guidance

Issue request:
FHIR-17202 was a Published/Persuasive FHIR-core STU3 change request from FHIR-I asking to improve MetadataResource.url guidance so the canonical URL points to an official/authoritative version of the artifact and does not get changed to a local URL when the artifact is stored on another server. The accepted resolution was to make the proposed wording change.

Initial application:
The original application is visible as git-svn commit f07cceebbe1520f616e08ca941d70f4e1774ce41, matching Jira's svn 14456 comment. That commit changed source/metadataresource/metadataresource-spreadsheet.xml to add the authoritative-instance language and the rule that the URL remains the same when stored on different servers. Later source rework moved this shared canonical URL guidance into CanonicalResource and related generated/build inputs.

Additional context:
Current build scope includes canonicalresource and metadataresource as active resource-infrastructure interfaces in source/fhir.ini. FHIR-25568 confirms MetadataResource snapshots should carry CanonicalResource fields, so the current CanonicalResource.url location is the right successor to the STU3 MetadataResource.url wording. FHIR-17232 adds complementary meta.source guidance for cases where the current authoritative source changes, and the current CanonicalResource.url comment already points implementers to meta.source. FHIR-21243 and FHIR-22699 corrected the duplicate "at which" typo introduced in the original text, and FHIR-40406 later aligned the Definition pattern wording with CanonicalResource while preserving the FHIR-17202 semantics. Targeted Zulip and Confluence searches found no conflicting work-group or community direction.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current source already says the canonical URL SHOULD be globally unique, SHOULD be a literal address at which an authoritative instance is or will be published, can be the target of a canonical reference, and SHALL remain the same when stored on different servers. The nearby comment also explains that meta.source can identify the current master source when the canonical URL no longer resolves to it. Additional edits would duplicate or churn already-correct build inputs.

Recommendation:
Keep this no-change audit commit as-is. FHIR-17202 is satisfied in the current build; any future desire for stronger constraints or new canonical/source-of-truth behavior should be handled by a new work-group decision rather than by reopening this applied STU3 wording issue.
