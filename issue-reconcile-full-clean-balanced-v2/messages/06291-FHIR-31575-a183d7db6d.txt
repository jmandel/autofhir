FHIR-31575: Remove DeviceDefinition onlineInformation ModelInfo

Issue request:
FHIR-31575 was Published as Persuasive for OO. It asked to address the inadequate 0..1 uri DeviceDefinition.onlineInformation element; the accepted persuasive-with-modification resolution was to remove onlineInformation rather than add another top-level RelatedArtifact because DeviceDefinition.guideline.relatedArtifact already existed from FHIR-29728.

Initial application:
Commits bc6378b7ac and 191756d0b7 commented out DeviceDefinition.onlineInformation in the DeviceDefinition StructureDefinition. Later cleanup commit c1dda1d5fd removed the commented-out block, so the current active DeviceDefinition source no longer defines DeviceDefinition.onlineInformation. source/fhir.ini keeps an R4/R6 migration note mapping the old DeviceDefinition.onlineInformation path to DeviceDefinition.guideline.relatedArtifact, which is appropriate historical conversion metadata rather than a current element definition.

Additional context:
FHIR-29728 is the directly related guideline issue; the immediately preceding AutoFHIR commit on this branch adds the missing guideline ModelInfo surface so the replacement path is present in the build-visible CQL model definition. OO Catalog and Main minutes confirm that FHIR-31575 was changed to just drop onlineInformation as redundant with guideline.relatedArtifact and then included in the March 25, 2021 block vote. No Zulip search results were found for the issue terms.

AutoFHIR reconciliation:
Removed the remaining build-visible DeviceDefinition.onlineInformation entry from source/library/library-fhir-model-definition-content.xml and refreshed source/library/library-fhir-model-definition.xml so the embedded Library.data payload matches the edited ModelInfo content. No primary StructureDefinition edit was needed because the active DeviceDefinition source was already correct.

Recommendation:
Keep this source fix. It completes the published FHIR-31575 resolution on the remaining active ModelInfo surface while preserving the fhir.ini migration mapping for older R4/R6 path conversion.
