FHIR-7581: Audit existing Condition status split

Issue request:
FHIR-7581 was a Published, Persuasive with Modification Patient Care change request for DSTU1 Condition. It asked to split the old overloaded Condition.clinicalStatus/status concept into verificationStatus (differential, provisional, working, confirmed, refuted, unknown, entered-in-error) and clinicalStatus (active, relapse, remission, resolved), and to add a usage note that Condition.stage and clinical status may have interdependencies.

Initial application:
The change was applied by git commit 0a6643ad139240e0f578cbe596e007d6c516df3e, "Split Condition.status {#7581} {#7617} {#7864}", which added Condition.verificationStatus, changed examples to carry both clinical and verification status where needed, and introduced the clinical status value set. The current active Condition source still has separate Condition.clinicalStatus and Condition.verificationStatus elements.

Additional context:
FHIR-7864 was resolved as per FHIR-7581 and is therefore duplicate background rather than an independent reconciliation target here. Later final Patient Care decisions intentionally refined this area: FHIR-16193 changed both status elements from code to CodeableConcept, FHIR-26464 clarified clinical status code definitions, and FHIR-29409 made clinicalStatus mandatory and added unknown for derived point-in-time conditions. Those later decisions explain why the current value lists and cardinalities are not a literal copy of the 2015 resolution text.

AutoFHIR reconciliation:
No source change was made. Condition is active in source/fhir.ini, and the current build source already preserves the core semantics of FHIR-7581: Condition.clinicalStatus and Condition.verificationStatus are separate elements with required bindings to their separate value sets, and source/condition/condition-notes.xml includes the requested Condition.stage/Condition.clinicalStatus interdependency note.

Recommendation:
Keep this no-change audit commit as-is. Do not revert the later CodeableConcept, mandatory clinicalStatus, unknown-code, or terminology-definition refinements while reconciling FHIR-7581; those changes came from later final Jira decisions.
