FHIR-2948: Audit MIME and Media Type terminology

Issue request:
FHIR-2948 was Published/Persuasive with Modification for the Initial Draft/DSTU1 datatypes page. The original request asked whether DocumentReference.mimeType, Attachment.contentType, and the corresponding value-set naming should move away from the deprecated term "MIME type" toward "Media Type" and IANA terminology.

Initial application:
The Jira comments show the disposition narrowed after the initial resolution text: ITS voted that continuing to use "Mime Type" was acceptable, DocumentReference was changed to use Attachment, and the remaining follow-up was the Media resource value-set naming. Git commit f586a7d12974994f9a470464a470c35e2bd32a6c explicitly applied #2948 by changing Media value-set names to DigitalMediaType/DigitalMediaSubtype, rather than renaming the normative Attachment.contentType element.

Additional context:
Attachment is active and normative in the current build through source/fhir.ini and still defines Attachment.contentType with a MimeType binding. DocumentReference is active and now carries technical format through content.attachment.contentType, not a separate mimeType element. The current Media.type value set is intentionally named MediaType/"Media Type" after the later Published/Persuasive FHIR-15605 decision and implementation commit e6e73a2910db3c87bf434b8e1d8185f4e82d8b8f, which supersedes the older DigitalMediaType naming created for FHIR-2948.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Renaming Attachment.contentType or broadly replacing "mime type" wording would contradict the later Jira comments and would be a large incompatible datatype change. Re-renaming the current Media.type value set to DigitalMediaType would contradict the later FHIR-15605 source change.

Recommendation:
Keep this audit commit as-is. If HL7 wants a future terminology modernization from "MimeType" to "MediaType", it should be handled as a new normative/backwards-compatibility decision rather than as unfinished FHIR-2948 application.
