FHIR-6140: Audit Quantity-derived schema extension inheritance

Issue request:
FHIR-6140 was a Published/Persuasive with Modification DSTU1 change request reporting that Quantity restriction datatypes such as Age and Count had XSD definitions with the inherited id attribute but without the inherited Element.extension child. The approved resolution was to fix the schema and defer a separate profile-schema discussion.

Initial application:
The issue was applied in git-svn commit bab51846f44373312018eb2de38ff460b7dd734d, which corresponds to SVN revision 6077 and was titled "#6140 - fix schema for restriction types". That historical commit added an explicit extension element while generating XSD restriction types in tools/java/org.hl7.fhir.tools.core/src/org/hl7/fhir/definitions/generators/xsd/XSDBaseGenerator.java. That Java generator path is no longer present in the current core source checkout.

Additional context:
Current build-scope datatype configuration still includes Quantity, Duration, SimpleQuantity=Quantity, MoneyQuantity=Quantity, Distance, Count, Money, and Age in source/fhir.ini. The active datatype spreadsheets define Age, Count, Distance, and Duration as Quantity-derived datatypes, while current generated build artifacts represent those datatypes with xs:extension base="Quantity". Element provides the extension child, DataType extends Element, and Quantity extends DataType, so the generated schema now inherits Element.extension without needing the old restriction-type special case. Current generated StructureDefinition snapshots for Age, Count, Distance, Duration, SimpleQuantity, and MoneyQuantity also include extension from Element.extension.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source and generated schema surface already satisfy the issue: Quantity-derived datatypes inherit Element.extension, and the old in-repository XSD generator fix has either been preserved in newer tooling or superseded by generating xs:extension-based derived datatypes.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-6140 unless a future publisher/schema regression reintroduces restriction-based Quantity derivatives without Element.extension.
