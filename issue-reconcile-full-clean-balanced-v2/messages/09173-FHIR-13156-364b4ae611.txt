FHIR-13156: Audit primitive JSON underscore example

Issue request:
FHIR-13156 was a Published/Persuasive FHIR-core Element-page issue raised against DSTU2 and applied for STU3. It reported that the Element JSON example for primitive extensions used the wrong primitive shadow property name, `name_` instead of `_name`, and the wrong id property, `_id` instead of `id`, and suggested relying on the correct JSON primitive representation guidance.

Initial application:
The issue was applied in the SVN-imported commit 8fac50cbd771ca6744c5c2d8fabc20c1cf8260fc, whose message says `#13156 - fix error about json format` and whose git-svn id is build@11890, matching the Jira comment. That commit changed the legacy `source/element.html` example from `_id` to `id`, changed `name_` to `_name`, and described the underscore as prepended rather than appended.

Additional context:
The legacy `source/element.html` file is no longer tracked in the current source. Current `source/fhir.ini` maps the Element type page to `source/types.html`, while the primitive JSON representation is maintained on `source/json.html`. The current JSON page says the primitive shadow property has `_` prepended to the element name and shows `_birthDate` with `id`, plus a Patient family example using `_family`. A prior Zulip implementers thread had identified the same prefix-versus-suffix discrepancy and confirmed the underscore starts the JSON property name; Confluence searches found no conflicting work-group record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source already conveys the correct JSON serialization rule, and the obsolete erroneous Element-page example is absent rather than needing another edit.

Recommendation:
Keep this audit commit as-is. No further FHIR core source work is needed for FHIR-13156 unless a future editorial decision wants to reintroduce local Element-page JSON examples, in which case they should refer back to `json.html#primitive` or match its `_element`/`id` pattern.
