FHIR-5670: Audit Condition unknown status

Issue request:
FHIR-5670 was a Published/Persuasive DSTU1 Patient Care issue asking to add an "unknown" code to the then-current Condition.status value set, with the same sort of cautionary commentary as the paired Observation.status request. The resolution was to add "unknown" as a status with Observation-style commentary.

Initial application:
The issue was explicitly applied in git commit decee3cf22e612e7e175c200ef84d83381bb5182, whose subject is "#5670 - add Condition.status = unknown" and whose git-svn metadata points to SVN revision 4840, matching the Jira comment. That commit changed the old Condition spreadsheet source to add the unknown code and a last-resort description.

Additional context:
The literal DSTU1 Condition.status surface is no longer the current build model. Later final Patient Care decisions renamed the old element to Condition.clinicalStatus, split clinical and verification status into separate elements, externalized the Condition clinical status code system to HL7 Terminology, and then added/confirmed unknown for the current Condition.clinicalStatus value set. Current source/fhir.ini lists Condition as an active resource, and source/condition/structuredefinition-Condition.xml now binds Condition.clinicalStatus to ValueSet/condition-clinical, shows unknown in the short display, and includes cautionary guidance that problem-list items should not use unknown while point-in-time derived conditions may.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source and terminology dependency already preserve the implementer-facing result of FHIR-5670: Condition can express unknown clinical status, and the current text cautions against using unknown when a meaningful problem-list status should be supplied. The old condition-status-present and condition-state files are not the authoritative current binding for Condition.clinicalStatus and should not be edited to resurrect DSTU1 Condition.status.

Recommendation:
Keep this audit commit as-is. Future changes to Condition clinical status values or unknown-use guidance should be handled under the later Condition.clinicalStatus/terminology issue family or through THO/UTG as appropriate, not by changing retired DSTU1 Condition.status artifacts in core.
