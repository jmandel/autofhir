FHIR-13618 was a Published/Persuasive STU3 FHIR-core Conformance change request asking that the word "Profile" be replaced with "Statement" in the CapabilityStatement "Describe an actual implementation" narrative, because the page is describing capability statements rather than StructureDefinition profiles.

Initial application:
The issue was initially applied by git commit 2050de9e088ea710ec76ae14b4bba6fd746d75a2, "GF#13618 - fix language", matching the Jira comment that cites svn revision 13064. That commit changed the quoted sentence from "This is the type of profile" to "This is the type of statement" in source/capabilitystatement/capabilitystatement-introduction.xml.

Additional context:
source/fhir.ini actively includes CapabilityStatement as a current resource, so the CapabilityStatement introduction source is in build scope. The exact Jira-requested sentence is already correct in current source, but the same introduction still used "profile" for the CapabilityStatement itself in two adjacent paragraphs: the generic-capability statement paragraph and the paragraph explaining how the three statement kinds can be used together. Jira, Zulip, and Confluence searches found no separate final decision or conflicting community context for those neighboring phrases.

AutoFHIR reconciliation:
This commit changes the remaining generic "profile" wording in the CapabilityStatement introduction to "statement"/"statements" where the text is describing CapabilityStatement instances, not FHIR profiles. It leaves legitimate references to resource profiles and profile search parameters unchanged.

Recommendation:
Keep this source fix. It completes the terminology correction intended by FHIR-13618 in the same build-scoped narrative section without changing conformance behavior; no further action is needed unless the work group wants a broader editorial review of unrelated CapabilityStatement prose.
