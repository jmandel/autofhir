FHIR-14211: Audit Extension value type list

Issue request:
FHIR-14211 was a Published FHIR-core / fhir-i STU3 change request with resolution Persuasive with Modification. The reporter noted that the Extension.value[x] type list included the Quantity-derived types Age, Count, Distance, Duration, and Money but did not include uuid; the final resolution was to add uuid as a supported datatype for extensions.

Initial application:
The Jira records svn revision 13277 as the application. In git history, commit 3870d6182e3815b4c2ed305fa5dab29461022f80 is the matching git-svn import commit with subject "GF#14211 - fix extensions types list". Immediately before that, commit dcd3ffda9020726ce3628f04603b19e4bf289c52 replaced the hand-maintained extensibility page list with the [%extension-type-list%] generated wildcard datatype list; the removed manual list already included valueUuid and the Quantity-derived datatypes.

Additional context:
The current build no longer keeps the Extension.value[x] type list as hand-authored prose. The active Extension spreadsheet leaves the element type as "*" and points readers to extensibility.html, while extensibility.html expands [%extension-type-list%] from the build's datatype configuration. source/fhir.ini actively lists the relevant datatypes, including Quantity plus Age, Count, Distance, Duration, Money, and uuid in the current type characteristics. A current build.fhir.org check confirms Extension.value[x] includes uuid and the Quantity-derived datatypes.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative source and current generated specification already satisfy the FHIR-14211 resolution, so editing the list would either duplicate generated content or risk drifting from the build's single source of truth.

Recommendation:
Keep this audit commit as-is. No core FHIR source follow-up is needed for FHIR-14211 unless a future build regression removes uuid from the generated Extension.value[x] wildcard list.
