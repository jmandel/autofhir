FHIR-17526: Audit Specimen collection duration

Issue request:
FHIR-17526 is a Published/Persuasive Orders and Observations change request from the STU3 cycle. It asked FHIR core to extend Specimen.collection so a specimen collection duration can be recorded when exact start and end times are unknown, with final resolution to add Specimen.collection.duration, definition "The span of time over which the collection of a specimen occurred.", cardinality 0..1, and datatype Duration.

Initial application:
The original source application is git-svn commit 1e39384034, titled "GF#17527, GF#17380, GF#17526", which added a Specimen.collection.duration row to source/specimen/specimen-spreadsheet.xml with 0..1 cardinality, Duration datatype, and the resolved definition. Later source rework commits, including 33b409a4b6 and c69d71aa21, carried the applied element into the current StructureDefinition XML source.

Additional context:
The Specimen resource is active in source/fhir.ini, with specimen=Specimen in [resources] and OO ownership/FMM metadata, so source/specimen/structuredefinition-Specimen.xml feeds the current core build. OO Confluence minutes for July 31, 2018 record the GF#17526 motion to accept the same element, cardinality, datatype, and definition by 4-0-0. Later implementer Zulip discussion treats duration as the intended representation for examples like multi-hour urine collection and did not identify a conflicting formal decision. FHIR-17514 and FHIR-17380 were encountered as adjacent Specimen.collection issues, but they concern different requested data and do not change this issue's duration decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already defines Specimen.collection.duration as a 0..1 Duration with the resolved definition, so adding another element or duplicative narrative would not change implementer understanding of the current specification.

Recommendation:
Keep this no-change audit commit as-is for FHIR-17526. Any future clarification about how Specimen.collection.duration should be used together with Specimen.collection.collected[x] should be handled as a separate work-group decision, not as further application of this already-applied issue.
