FHIR-5988: Audit QICore modifier propagation

Issue request:
FHIR-5988 is a Published/Persuasive FHIR-core change request raised and applied for DSTU1. It reported that the QICore AdverseEvent didNotOccur extension was defined with isModifier=true, but the generated QICore AdverseEvent profile HTML/XML did not show the profiled extension element as a modifier. The final Jira comments say the spreadsheet declaration was wrong, the tool was modified to catch this as an error, and the spreadsheets were fixed in svn revision 5969.

Initial application:
No migrated Git commit explicitly mentions FHIR-5988 or svn revision 5969. The checked-in Release 2 history bundle now shows the intended applied state: qicore-adverseevent-didNotOccur is a modifier extension, and the QICore AdverseEvent profile's Basic.modifierExtension didNotOccur element carries isModifier=true in both snapshot and differential.

Additional context:
The current core build no longer includes the QICore IG; source/igs.xml has the qicore IG commented out, source/fhir.ini has no active QICore profile entry, and searches outside tools/history find no current qicore-adverseevent-didNotOccur source to edit. The active ElementDefinition source already states that isModifier on an extension root indicates a modifier extension, and that only the original element or extension definition can set isModifier true. A later related audit, FHIR-14278, is already represented on the combined branch and confirms that analogous modern isModifier propagation symptoms belong to generation/publisher tooling rather than core source semantics when the base definitions are correct.
