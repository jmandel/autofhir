FHIR-22625: Audit NDJSON page typo correction

Issue request:
FHIR-22625 was a Published/Persuasive FHIR-core technical correction asking whether the NDJSON page opening paragraph's erroneous "ns-json (New line delimited JSON)" text should instead say nd-json/NDJSON. The Jira resolution was auto-approved and the issue was applied for R5.

Initial application:
The FHIR-22625 Jira comment says the issue was fixed in commit e2e378235d73d468f8277574cc86eca6c0. The resolvable merge commit is e2e378235d73d468f8277574cc86eca6c082f876, which merged the same-family FHIR-22656 branch; its underlying implementation commit 779657b7b93248a50d7b855d908c0d5177a95b62 changed source/nd-json.html from "ns-json" to "nd-json" in the opening paragraph.

Additional context:
FHIR-22656 is the duplicate/same-change-family Published/Persuasive issue for the same typo and is already represented on the combined branch by a no-change audit commit. Later FHIR-31425 source work normalized the page name to linked "NDJSON" terminology and is also already represented on the combined branch. The NDJSON page is active in the current build through source/hierarchy.xml and publish.ini, and a Zulip bulk data thread recognized FHIR-22625 and FHIR-22656 as the existing typo trackers before opening FHIR-26598 for the separate invalid sample issue.

AutoFHIR reconciliation:
No source change was made. Current source/nd-json.html says "NDJSON (New line delimited JSON)" in the opening paragraph and repository search found no remaining "ns-json" spelling in current non-publish source, so the approved correction remains present in the active current specification source.

Recommendation:
Keep this no-change audit commit as-is. No FHIR-core follow-up is indicated for FHIR-22625 unless a future work group decision changes the preferred NDJSON terminology beyond the already-applied FHIR-31425 cleanup.
