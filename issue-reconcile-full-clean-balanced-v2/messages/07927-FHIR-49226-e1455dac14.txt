FHIR-49226: Audit Questionnaire date maxLength support

Issue request:
FHIR-49226 was Applied/Persuasive with Modification for FHIR-core Questionnaire. It asked that Questionnaire.item.maxLength support date use cases already possible in ElementDefinition; the final resolution was to add date, dateTime, and time and remove boolean.

Initial application:
Commit 370a13b5c3cd9b8be8de15b4abcc4404c5861618 changed the ElementDefinition.maxLength definition toward primitive types that have length, and commit 24e5953c3f324c274613d15334ecacf76c52d27b changed Questionnaire que-10 to replace boolean with date, dateTime, and time. No prior Issue-Reconcile-Key for FHIR-49226 was found on the combined branch before this audit.

Additional context:
The SDC minutes for 2025-02-27 record FHIR-49226 as Persuasive. Zulip Questionnaire discussions show the practical date-precision use case and Lloyd McKenzie's statement that Questionnaire and ElementDefinition should be consistent. The later FHIR-22128 reconciliation already fixed the ElementDefinition wording typo/weakness while preserving date-capable primitive maxLength scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Questionnaire que-10 expression allows string, decimal, integer, text, date, dateTime, time, and url, and no longer allows boolean; the current ElementDefinition.maxLength definition also permits primitive values with meaningful character length. That matches FHIR-49226 for the current R6 build.

Recommendation:
Keep this audit commit as-is for FHIR-49226. No current FHIR-core source follow-up is needed; requests to backport the behavior to R4 or R5 would require a separate technical-correction decision outside this current-build reconciliation.
