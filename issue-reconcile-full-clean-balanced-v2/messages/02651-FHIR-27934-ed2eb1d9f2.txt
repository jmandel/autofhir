FHIR-27934: Audit Endpoint status environment split

Issue request:
FHIR-27934 is a Published PA change request with resolution Persuasive with Modification. It asked to remove the Endpoint.status `test` concept because testing is an environment rather than a status, and to add Endpoint.environmentType as 0..* CodeableConcept with an extensible endpoint environment value set covering development, test, staging, production, and training concepts.

Initial application:
The issue was applied by git commit 7e69b0db7b6e57654fa62c64426a42989727a78f, which removed `test` from source/endpoint/codesystem-endpoint-status.xml and source/status-codes.xml, added source/endpoint/codesystem-endpoint-environment.xml and source/endpoint/valueset-endpoint-environment.xml, added Endpoint.environmentType to source/endpoint/structuredefinition-Endpoint.xml, and updated the Endpoint example. The active current source still contains those changes.

Additional context:
source/fhir.ini has Endpoint as an active resource owned by PA, so the Endpoint source files and shared status-codes spreadsheet are in current build scope. The current environment code strings are abbreviated as `prod`, `staging`, `dev`, `test`, and `train`, with displays/definitions for the five concepts approved by the PA minutes and Jira resolution. Later Applied issue FHIR-47299 added `limited` as a status for endpoints with reduced availability, preserving the distinction between environmentType and status. Later FHIR-57362 and FHIR-55292 are Resolved - change required but not Applied/Published in this default run scope.
