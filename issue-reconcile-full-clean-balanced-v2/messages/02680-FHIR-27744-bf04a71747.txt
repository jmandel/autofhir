FHIR-27744: Audit Evidence terminology externalization

Issue request:
FHIR-27744 was Published/Persuasive for R5 and asked to update the Evidence-related synthesis-type and study-type terminology: add the code NotApplicable to synthesis-type, rename the synthesis-type name/title to SynthesisType, and rename the study-type name/title to StudyType. The Jira resolution agreed to update the code system and value set as described, with a note that the UTG process would be needed for the terminology update.

Initial application:
Commit 7909268d38fea563ac06a012b33b5c687cc190aa explicitly applied Jira FHIR tracker item J#27744 to source/evidence/evidence-spreadsheet.xml. It changed the Evidence bindings from StatisticSynthesisType and StatisticStudyType to SynthesisType and StudyType, updated the StudyType description, and added the NotApplicable concept to the synthesis-type code list. The current core source no longer has those spreadsheet terminology definitions; Evidence is active in source/fhir.ini and its authoritative StructureDefinition binds Evidence.synthesisType with bindingName SynthesisType to http://terminology.hl7.org/ValueSet/synthesis-type.

Additional context:
The relevant terminology artifacts have since moved out of the FHIR core source checkout and are now served from terminology.hl7.org/THO. Current core source contains no StatisticSynthesisType or StatisticStudyType strings, and a current Evidence example uses the NotApplicable code. However, the live THO ValueSet/CodeSystem resources for synthesis-type and study-type still report StatisticSynthesisType and StatisticStudyType as their name/title, while the synthesis-type CodeSystem does include NotApplicable. The CDS meeting agenda and Zulip terminology thread from June 2020 confirm the issue was approved and that the correct maintenance path for terminology rooted at terminology.hl7.org was being discussed as UTG/THO rather than ordinary core source edits.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The active core source is already free of the stale Statistic* binding names and still references the external synthesis-type value set, while the remaining name/title discrepancy is in the external THO/UTG terminology source of truth rather than in this FHIR core checkout.

Recommendation:
Keep this audit commit for the FHIR core reconciliation. Follow up in the THO/UTG repository/process to decide whether the current terminology.hl7.org CodeSystem and ValueSet resources for synthesis-type and study-type should have their name/title changed from StatisticSynthesisType and StatisticStudyType to SynthesisType and StudyType, preserving the already-present NotApplicable concept.
