FHIR-7834: Audit MedicationDispense dosage timing mapping

Issue request:
FHIR-7834 was a Published/Persuasive DSTU1 Pharmacy change request for the MedicationDispense HL7 V2 mapping. It asked to stop mapping the dosageInstruction scheduled/timing element to the RDS message type and instead use the TQ1 segment field collection plus ORC Quantity/timing: `TQ1-X / ORC Quantity/timing`.

Initial application:
The issue appears to have been applied in git commit 5bb461af1063efe577bac2b8b17b6992be7560bf, a 2015 multi-tracker Pharmacy V2 mapping update that explicitly listed tracker 7834. That commit removed the old `RDS:TQ1` map from the then-authoritative MedicationDispense spreadsheet source. A later Pharmacy commit, 6a4b0d916ec0983d3c0e8a2d28366e99dc12fc76 for FHIR-12840, refactored DosageInstruction into the reusable Dosage datatype and carried the requested `TQ1-X / ORC Quantity/timing` mapping on `Dosage.timing`.

Additional context:
MedicationDispense remains an active resource in `source/fhir.ini`, and the current MedicationDispense source now represents `dosageInstruction` as `DosageDetails`. The dosage page and datatype entries are also active in `source/fhir.ini`; the current `source/datatypes/dosage.xml` source is therefore the build-scoped mapping source for the timing component used by MedicationDispense dosage instructions. Searches found no remaining `RDS:TQ1` mapping in the active MedicationDispense or dosage datatype source, and no Zulip or Confluence evidence that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already removes the RDS message-type reference from MedicationDispense and preserves the requested TQ1/ORC mapping on the reusable dosage timing datatype used by MedicationDispense, so adding another local MedicationDispense mapping would be redundant and could conflict with the current datatype-centered model.

Recommendation:
Keep this no-change audit commit as-is. No follow-up source edit is needed for FHIR-7834 unless Pharmacy later decides that MedicationDispense should duplicate datatype-level V2 mappings locally.
