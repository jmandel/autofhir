FHIR-49912: Audit rank extension outside core

Issue request:
FHIR-49912 was an Applied, Not Persuasive with Modification FHIR Infrastructure change request that originally asked to link the deprecated Preferred extension to AD Use. The approved resolution rejected AD Use as the replacement and instead called for a new general Rank extension, 0..1 integer, with Address, Patient.contact, and Organization.contact contexts, plus deprecation guidance from iso21090-preferred, organization-preferredContact, and patient-contactPriority to rank.

Initial application:
No FHIR core source-changing commit was found for FHIR-49912, and the current core checkout has no active StructureDefinition source for iso21090-preferred, organization-preferredContact, patient-contactPriority, or rank beyond stable OID registry entries for the older extension URLs. The issue was applied in the FHIR Extension Pack by commit 5564e01710715a6c2aba23d0abd709c5a45da743, which added input/definitions/datatypes/StructureDefinition-rank.json and updated the deprecation notes for iso21090-preferred, organization-preferredContact, and patient-contactPriority.

Additional context:
FHIR-I minutes from 2025-12-01 record the decision to define a general rank extension because there were several deprecated extensions around this preference behavior. Related applied extension-family issues FHIR-44603 and FHIR-50768 are already represented on the combined branch as external-repo audit commits; they explain the prior patient-contactPriority and organization-preferredContact state that FHIR-49912 supersedes. Current extension-pack source contains the rank extension and links to it, but the new rank definition's value[x] is canonical(ValueSet) with value-set-related label/purpose text even though the Jira resolution says 0..1 integer.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR core source change. The affected authoritative StructureDefinitions live in /home/jmandel/work/fhir-extensions, not this core checkout, and a core edit would only touch unrelated OID registry data or narrative that does not define the current extension artifacts.

Recommendation:
Keep this core audit commit as-is. Follow-up should occur in the FHIR Extension Pack: review/fix StructureDefinition-rank so its value type and any purpose/label text match the FHIR-49912 approved 0..1 integer rank semantics, while retaining the deprecation guidance from the older preferred/contact-priority extensions to rank.
