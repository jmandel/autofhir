FHIR-40455: Audit DeviceAssociation examples

Issue request:
FHIR-40455 was Applied/Persuasive with Modification for R6 after being raised against R5. The request was to add DeviceAssociation examples, going down the proposed list as far as practical: implant assigned to a patient with open period and body site, wheelchair assigned to a patient with future end date, tablet assigned to a provider, surgical robot/patient/operator period, blood pressure monitor during an in-patient stay, and lab device calibration without a patient.

Initial application:
The issue was applied in July 2025 by commits 63aa9cc407, a8ca8f5230, 9840cc6ef0, 8c67215155, and fa2f8f096f. Those commits added active DeviceAssociation example XML files for implant-association, wheelchair-association, tablet-association, robot-association, bp-monitor-association, and lab-device-association, and registered them in list-DeviceAssociation-examples.xml. Jira comments in July and October 2025 confirm the examples were reviewed and listed in the build.

Additional context:
DeviceAssociation is active in source/fhir.ini, and the example files under source/deviceassociation are current build inputs. A later Applied DeviceAssociation change, FHIR-47604, removed the operation/operator backbone, added focus, and moved operator semantics to relationship=operator plus associationStatus/period. Its Jira discussion explicitly notes that examples with two operators are no longer viable under the new focus cardinality; the current StructureDefinition comment directs multiple simultaneous individuals to Group or CareTeam. The existing examples have already been adjusted to that later model.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already contains all six FHIR-40455 example categories in the active DeviceAssociation examples list, and the examples use the current post-FHIR-47604 DeviceAssociation representation. Reintroducing the original multiple-nurse operation shape would conflict with the later applied model rather than improve the current specification.

Recommendation:
Keep this no-change audit. No FHIR-core source fix is needed for FHIR-40455. If the work group wants a new example specifically demonstrating multiple simultaneous operators, that should be a separate current-model design decision, likely using Group or CareTeam rather than reviving the removed operation backbone.
