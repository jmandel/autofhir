FHIR-38998: Clarify version label precedence

Issue request:
FHIR-38998 was Published/Persuasive for R5 by FHIR-I and asked the FHIR-core compatibility/versioning page to state that FHIR version labels are not SemVer compliant. The requested clarification was specifically that SemVer precedence rules cannot be applied to FHIR labels; labels are only sortable against other labels with the same base.

Initial application:
The issue was initially applied in git commit 29b2f1596afb0a22642e6ac1727659395f94b985, which added the same-label-base sorting sentence to source/versions.html. A same-day follow-up commit d1399f74f158a7e810db07f8f79052c9b3ecd721 only escaped the example less-than sign. The current source kept the sortable-label wording but still did not explicitly tell readers that SemVer pre-release/precedence rules do not apply to FHIR labels.

Additional context:
The broader major.minor.patch-label table was established by related FHIR versioning work, especially FHIR-35168 and FHIR-35172, and source/hierarchy.xml includes versions.html as the Change Management and Versioning page, so source/versions.html is an active build input. FHIR-I minutes from 2022-10-24 confirm the persuasive 6-0-0 vote for FHIR-38998. Exact Zulip issue-key search found no conflicting implementation discussion.

AutoFHIR reconciliation:
This commit updates the label row in source/versions.html to say that FHIR labels are not SemVer pre-release labels and that SemVer precedence rules do not apply, while preserving the existing same-label-base sorting rule added by the original application.

Recommendation:
Keep this commit as-is. It completes the narrow clarification requested by FHIR-38998 on the active version management source page without changing the broader FHIR versioning policy or duplicating unrelated canonical-version guidance.
