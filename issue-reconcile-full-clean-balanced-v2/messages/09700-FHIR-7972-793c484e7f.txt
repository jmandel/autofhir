FHIR-7972: Audit legal authenticator provenance role

Issue request:
FHIR-7972 was a Published/Persuasive DSTU1 FHIR-core Provenance issue asking to add a legalAuthenticator code for XDS legalAuthenticator provenance mapping.

Initial application:
The issue was applied in commit 4f363ad0bd, which explicitly mentions #7972 and added a Legal Authenticator child concept to the then-current source/provenance/valueset-provenance-agent-role.xml value set.

Additional context:
Later R5 Security WG issues FHIR-32453, FHIR-32519, and FHIR-32520 reworked Provenance agent semantics. They clarified that agent.type is the functional role and agent.role is structural, then kept the functional role binding on participation-role-type with provenance-participant-type including Enterer, Performer, Author, Verifier, Legal Authenticator, Attester, Informant, Custodian, Assembler, and Composer. Current source reflects that model: Provenance.agent.type binds to participation-role-type, and the local/current terminology package includes the legal code under the provenance participant type code system. No Zulip or Confluence search found conflicting community evidence for FHIR-7972.

AutoFHIR reconciliation:
Made no source change. The current build already represents the requested Legal Authenticator function through Provenance.agent.type's participation-role-type binding and the included provenance participant type Legal Authenticator code; restoring or editing the retired agent-role value set would conflict with the later type/role split.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed unless a future work group decision changes the FHIR-32519 functional-role value set or moves the Legal Authenticator concept out of provenance-participant-type.
