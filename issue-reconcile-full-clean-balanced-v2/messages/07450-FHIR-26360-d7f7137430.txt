FHIR-26360: Audit extension meaning code application

Issue request:
FHIR-26360 was a Published FHIR-core change request resolved Persuasive with Modification for R5. It asked to support machine-readable coded meaning for extensions by defining a standard extension with contexts Extension and Extension.value and value type CodeableConcept, and by updating extensibility guidance so extension definitions SHOULD declare a clear coded meaning on the extension root element.code.

Initial application:
The issue was explicitly applied in core commit f6c7cdf7d6, which added the extensibility guidance and introduced source/structuredefinition/structuredefinition-extension-structuredefinition-extension-meaning.xml. The current core extensibility page still contains the guidance at source/extensibility.html:73-74. The original extension source was later removed from core in dd468d4f17 as part of the broader move of extension definitions out of the R5 core source.

Additional context:
The canonical extension is present in the FHIR Extension Pack at input/definitions/datatypes/StructureDefinition-structuredefinition-extension-meaning.xml with the requested Extension and Extension.value contexts, CodeableConcept value, and comment tying the instance code to StructureDefinition.snapshot.element[0].code. The current core source/fhir.ini maps Extension datatype narrative to the extensibility page, so the remaining core-owned documentation is in build scope. Zulip and FHIR-I minutes show the issue discussion evolved from whether meaning should be inline or definition-based to the accepted standard-extension/documentation approach, with no conflicting later core decision found.

AutoFHIR reconciliation:
This audit commit makes no source change. The current core source already carries the required authoring guidance, and the standard extension definition is correctly owned by the Extension Pack rather than this core checkout.

Recommendation:
Keep this audit commit as-is. No FHIR-core follow-up is needed unless the Extension Pack ownership model changes; any future edits to the structuredefinition-extension-meaning definition should be made in HL7/fhir-extensions.
