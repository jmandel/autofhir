Issue request:
FHIR-4037 was a Published Patient Care change request, resolved Persuasive with Modification, asking to add a coded CarePlan.activity.statusReason for cancelled, not-done, or on-hold activities, using CodeableConcept and an example binding.

Initial application:
The issue was not applied by a commit that names FHIR-4037. The March 2015 CarePlan revamp commit db4ace37c6615c9732f958d34d6286fe739fc657 added CarePlan.activity.detail.statusReason as 0..1 CodeableConcept with the CarePlanActivityStatusReason binding name. Later CarePlan binding work, especially FHIR-6212 and FHIR-22729, filled in the example binding/value-set trail for the same statusReason surface.

Additional context:
Later Patient Care decisions changed the model. FHIR-26064 renamed CarePlan.activity.detail to CarePlan.activity.plannedActivityDetail, and FHIR-39101 then removed CarePlan.activity.plannedActivityDetail and all children from the active CarePlan model in favor of CarePlan.activity.plannedActivityReference to request resources. On the combined branch, the old plannedActivityDetail/statusReason block remains only inside an XML comment; parsing the active StructureDefinition finds no active CarePlan statusReason path. FHIR-6212, FHIR-22729, FHIR-26064, and FHIR-39101 are already represented on the combined branch, so this seed should not duplicate those decisions.

AutoFHIR reconciliation:

The current source is correct when FHIR-4037 is interpreted through the later CarePlan refactors and removals.

Recommendation:
Keep this empty audit commit as-is. No core source follow-up is needed for FHIR-4037 unless Patient Care reopens the later removal decision or explicitly decides to add a status reason directly on the remaining CarePlan.activity backbone.
