FHIR-25921: Audit ConceptMap maturity history

Issue request:
FHIR-25921 is Published/Persuasive and requested changing the ConceptMap resource maturity level from 3 to 1 for R5, based on the Sydney WGM February 2020 Vocabulary vote that level 1 requirements were met but levels 2 and 3 were not.

Initial application:
The issue was explicitly applied in 2020 by git 3c623c55e48b47ecb54fb8f6d88bbb4e42d92e97, which changed source/fhir.ini [fmm] conceptmap from 3 to 1, followed by git e5c7d98d6d150ddefa6a767391bdf6f29b926b26 removing the redundant FMM cell from the then-current ConceptMap spreadsheet.

Additional context:
Later R5 publication FMM review changed the current resource-level outcome. Git 1ade81c36b0d486ec2eac30f04b2b316e96a989e raised source/fhir.ini [fmm] conceptmap from 1 to 3 on 2023-03-23. The linked March 2023 TI/FMG/Zulip discussion shows an FMM4 proposal, TI concern that level 1 better matched the written criteria, and a final R5 result where ConceptMap ended up at FMM level 3. The current R5 and build.fhir.org ConceptMap profile JSON expose structuredefinition-fmm value 3.

AutoFHIR reconciliation:
No source change was made. The current build-facing source/fhir.ini entry and current published/build surfaces already reflect the later FMM3 outcome, so changing the resource back to level 1 would incorrectly undo a later publication decision. The older inline StructureDefinition XML extension still reads 1, but source/fhir.ini is the active resource maturity authority for this build path and similar inline/source-fhir.ini mismatches exist outside this issue's scope.

Recommendation:
Keep this audit commit as-is. If the work group wants ConceptMap resource maturity reconsidered again, handle that as a new FMM/process decision rather than reopening FHIR-25921; if maintainers later clean up generated/source FMM duplication, align ConceptMap with the current source/fhir.ini value 3 as part of that broader cleanup.
