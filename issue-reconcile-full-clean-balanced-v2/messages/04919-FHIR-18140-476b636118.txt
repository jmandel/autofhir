FHIR-18140: Audit ValueSet rules-text support

Issue request:
FHIR-18140 was a Published/Persuasive with Modification Vocab change request raised against STU3 ValueSet. It asked FHIR core to support VSD non-computable Content Logical Definitions by adding a markdown extension, with the rule that when the non-computable extension is used the computable ValueSet.compose definition is not present.

Initial application:
The seed's Jira comment points to 66ae1e40f1bc02283363c872db14035fc795f8f7, which changed the then-current ValueSet extension spreadsheet by adding the rules-text markdown extension and by narrowing valueset-expression to computable expressions that should point to rules-text for non-computable descriptions. The closely related FHIR-18710/18135 implementation commit 4907f9bcb0b710cb2837a93a20c4b23210a37249 had first added the broader valueset-expression extension material.

Additional context:
Later Vocab/VSDP evidence confirms the same split: valueset-expression is computable, while valueset-rules-text is for non-computable human rules. FHIR-31489 clarified the valueset-expression wording to point non-computable definitions to rules-text, FHIR-36015 added broader VSD ValueSet guidance, and FHIR-37959 later removed the Shareable/Publishable/Computable/Executable profile StructureDefinitions from core for R6 so profile-specific one-of compose/expression/rules-text constraints are maintained outside this checkout. The combined branch already has no-change/external audit commits for FHIR-18710, FHIR-31489, FHIR-36015, and FHIR-37959, so those related decisions are not duplicated here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. ValueSet is active in the current core build, and source/valueset/valueset-notes.xml already tells implementers to use valueset-expression for alternative computable definitions and valueset-rules-text for rare value sets with no formal computable expression. The authoritative current valueset-rules-text StructureDefinition is in HL7/fhir-extensions and defines a ValueSet-context markdown extension; valueset-expression there also points to rules-text for non-computable definitions. Adding a new core base-resource invariant or re-adding removed profile constraints would go beyond the current core ownership and later FHIR-37959 profile-migration decision.

Recommendation:
Keep this audit commit as-is. No current FHIR core source change is needed for FHIR-18140; if a future work group wants stricter machine-enforceable no-compose behavior for rules-text, handle it in the Extension Pack or the external CRMI/THO profile-maintenance venue rather than by changing current core under this historical STU3 issue.
