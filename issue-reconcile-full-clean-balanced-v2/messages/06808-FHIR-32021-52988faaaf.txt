FHIR-32021: Audit MustSupport obligations mechanism

Issue request:
FHIR-32021 was Published/Persuasive with Modification for R5. It asked to make Must Support easier for implementation guides to explain by moving toward IG-specific, computable support flags. The final resolution reverted an earlier plan for simple code values on ElementDefinition.mustSupport and instead asked the must-support section to point to the Must Support replacement proposal and the fhir-tools-ig extension so the mechanism could be tried out and possibly migrate into core later.

Initial application:
No source commit found by grep explicitly mentions FHIR-32021. The first substantive source application found was 1e1665b935, which added source/obligations.html and updated source/elementdefinition.html to describe mustSupport together with an obligation mechanism. The current obligations page is in the build navigation and documentation index, so it is part of the current core documentation surface.

Additional context:
FHIR-I minutes from 2021-12-06 record the earlier experimental mustSupport-code approach, and FHIR-I minutes from 2022-08-15 record the reopening and final persuasive-with-modification vote with a link to the FHIR tooling extensions IG. The linked Zulip thread shows the proposal was intended to move beyond a single underspecified Must Support flag and to be implemented by validators, publishers, SUSHI, and testing tools. Later Published FHIR-40296 changed the model to an extension, and the combined branch already contains f3476bb09517bfc2be70454704575278968aef6a, which fixes stale core wording to refer directly to http://hl7.org/fhir/StructureDefinition/obligation. Later Applied FHIR-50579 and FHIR-50580 further clarified the obligations page without reversing the FHIR-32021 direction.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current source already tells IG authors that mustSupport itself does not define support semantics, that profiles SHALL make the required support clear, and that detailed expectations can be expressed with the obligation extension. It also links from ElementDefinition, Conformance, the documentation index, and hierarchy navigation to the Implementation Obligations page, and the extension definition now lives in the FHIR Extension Pack. Adding a historical Confluence or fhir-tools-ig pointer to the current core page would be stale because later applied work moved the durable mechanism to the obligation extension documentation.

Recommendation:
Keep this no-change audit. The current core specification has evolved past the interim Confluence/tooling-IG pointer while preserving the approved intent of FHIR-32021. Do not add redundant historical text unless a future work group decision asks for a migration-history note.
