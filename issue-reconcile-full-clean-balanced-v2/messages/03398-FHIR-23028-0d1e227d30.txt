FHIR-23028: Audit ResearchSubject discontinuation tracking

Issue request:
FHIR-23028 was a Published/Persuasive with Modification BR&R change request, raised against STU3 and applied for R5, asking for a way to know why a ResearchSubject discontinued from a study and, if applicable, connect that discontinuation to an AdverseEvent. The approved path was to add fuller status/progress supporting information for the subject lifecycle, with later Jira comments stating that FHIR-31657 addressed the outstanding process points.

Initial application:
ResearchSubject progress tracking appears to have been introduced by afae9447904fefafb8605fbe0786232a4fdd7c89, which added ResearchSubject.progress in the pre-StructureDefinition spreadsheet source after the 2019 vote. The later e25dc63817146f6e664114198b526b775941a3fa commit explicitly mentioned Jira #23028 as "adding progress" while preparing R5 ResearchSubject source. The R5 published profile exposed ResearchSubject.status as publication status and ResearchSubject.progress with subjectState, milestone, reason, startDate, and endDate.

Additional context:
FHIR-31657 says the FHIR-23028 implementation had gone beyond the original approval and should now be approved; BR&R minutes for 2021-03-30 record a 16-0-0 motion to add ResearchSubject.CurrentState. Later final R6 decisions FHIR-43561 and FHIR-44837 replaced the R5 progress backbone with ResearchSubject.subjectState and ResearchSubject.subjectMilestone, and source/fhir.ini maps R5 ResearchSubject.progress elements to those current structures. Those later approvals define reason as CodeableConcept, so adding a new direct Reference(AdverseEvent) now would exceed the applied issue family rather than complete it.

AutoFHIR reconciliation:
This commit intentionally makes no source change. ResearchSubject is active in the current build, current source already separates publication status from subject lifecycle state, and subjectState supplies the state code, start/end dates, and state-change reason needed to record discontinuation context. The current R6 model also preserves R5 progress migration mappings, so the absence of the old progress element name is an intentional later refactor rather than a missing FHIR-23028 application.

Recommendation:
Keep this no-change audit commit. If BR&R now wants a direct reference from ResearchSubject state transitions to a causal AdverseEvent, that should be handled as a new change request because the published R5 implementation and later R6 approvals use coded state-change reasons rather than a Reference choice.
