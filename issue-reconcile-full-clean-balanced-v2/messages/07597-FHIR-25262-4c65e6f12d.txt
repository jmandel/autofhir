FHIR-25262: Audit Resource.id fhir-type correction

Issue request:
FHIR-25262 was a Published/Persuasive FHIR-I technical correction raised against R4 and applied for R5. It reported that Resource.id-derived profile elements exposed the structuredefinition-fhir-type extension with value string, and requested that Resource.id be constrained with FHIR type id instead.

Initial application:
No current repository commit was found that explicitly names FHIR-25262. The Resource source history shows the correction being incorporated through source rework and cleanup: an early R4B source import had Resource.id with fhir-type id using valueUri, a later draft temporarily had valueUrl string, and commit 73080e5 changed the corrected value back to the proper valueUrl id representation. The closely related FHIR-25274 record also says the type error had already been corrected by another tracker.

Additional context:
source/fhir.ini keeps Resource in the active build and normative package, so source/resource/structuredefinition-Resource.xml is the authoritative core source for this reconciliation. Current ElementDefinition notes explain the System.String plus structuredefinition-fhir-type mechanism, and later FHIR-45989 confirms the intended distinction: Resource.id is System.String on the wire with FHIR id value constraints, while Element.id remains a System.String/string case. A newer submitted issue, FHIR-57383, reports that generated Patient.id snapshots in R6 ballot4/current builds regressed to string; that appears to be a Kindling/generated-snapshot problem and is not a final FHIR-core source decision for this seed.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core source already has Resource.id as http://hl7.org/fhirpath/System.String with structuredefinition-fhir-type valueUrl id, and there is no checked-in Patient profile source artifact to edit for the generated inherited-snapshot regression.

Recommendation:
Keep this audit commit as-is for FHIR-25262. Handle the generated Patient.id regression separately under FHIR-57383 or the relevant Kindling/tooling work once that submitted issue is resolved; do not change the current Resource.id source back away from valueUrl id.
