FHIR-5883: Audit Bundle entry contextual links

Issue request:
FHIR-5883 was a Published/Persuasive FHIR-core Feed change request raised for DSTU1 asking to support context-dependent links for individual resources and Bundle entries. The final working-group comments narrowed this to adding a Bundle.entry link element, documenting that its meaning is implementation specific in transactions, and noting its relationship to HTTP Link headers, while leaving a standard usage pattern to the separate FHIR-5884 discussion.

Initial application:
The issue was explicitly applied in git-svn history by commit dc91fb8899aa4b7af62f7b5c69b6f43f6e89be9d, "#5883 - add link to Bundle.entry" (git-svn build@4576). That commit added Bundle.entry.link to the then-authoritative bundle spreadsheet as a 0..* @Bundle.link child and added Bundle notes explaining HATEOAS/additional-context use, the HTTP header relationship for directly read resources, and implementation-specific transaction meaning. Later source refactoring regenerated the current StructureDefinition XML while retaining the same element and guidance.

Additional context:
Bundle is an active current-build resource in source/fhir.ini. Current source/bundle/structuredefinition-Bundle.xml defines Bundle.entry.link as a repeatable content reference to Bundle.link and carries guidance matching the accepted resolution. Current source/bundle/bundle-notes.xml also includes the same narrative note. The related FHIR-5884 usage-pattern issue was Resolved - No Change / Not Persuasive in 2019 because the community did not have enough interest to standardize valid-operation links, so FHIR-5883 should not be read as requiring new standard semantics for rel values or authorization workflows.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The current active Bundle source already contains the requested infrastructure and the accepted explanatory notes; adding more HTTP header or operation-link guidance would exceed the narrowed FHIR-5883 decision and conflict with the later no-change disposition of FHIR-5884.

Recommendation:
Keep this no-change audit commit as-is. Revisit only if the work group opens a new issue to standardize concrete contextual-link relations or valid-operation discovery; that would be new scope rather than unfinished FHIR-5883 application.
