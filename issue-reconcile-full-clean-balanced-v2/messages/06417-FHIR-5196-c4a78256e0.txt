FHIR-5196: Audit Encounter participant role clarification

Issue request:
FHIR-5196 was a Published PA ballot comment for DSTU1 Encounter asking how implementers distinguish an encounter-specific practitioner participation role, such as attending or consulting doctor, from the broader Practitioner role value set. The final Not Persuasive with Modification resolution directed that clarification notes be added to the Encounter participant type comment explaining that Encounter.participant.type is encounter-context participation/action type and Practitioner roles are functional roles from employment, education, licensing, and similar authority.

Initial application:
The issue was applied in historical commit 27302910ae49c6d1fd5544682e5f48f9e365b347, which explicitly listed tracker 5196 and added the requested participant type comment to the Encounter spreadsheet. Later source migration commits moved that text into source/encounter/structuredefinition-Encounter.xml, and subsequent cleanup preserved the same semantic distinction.

Additional context:
Encounter is active in source/fhir.ini, so source/encounter/structuredefinition-Encounter.xml is in the current build. Later FHIR-22696 work renamed Encounter.participant.individual to Encounter.participant.actor and adjusted the comment from "individual participates" to "individual actor participates" while leaving the FHIR-5196 distinction intact. Current PractitionerRole source still describes PractitionerRole.code as roles a practitioner is authorized to perform for an organization, which is consistent with the contrast. A Zulip implementer thread in 2020 also confirms the distinction: Encounter.participant.type is about how someone is involved in the encounter, while clinician kind/role belongs in PractitionerRole.code.

AutoFHIR reconciliation:
No source change was made. The active Encounter definition already contains the requested clarification at Encounter.participant.type: it includes non-practitioner participants, gives encounter-context examples such as Admitting Dr and Consulting Dr, and distinguishes those from practitioner roles derived from employment, education, licensing, and similar functional authority.

Recommendation:
Keep this audit commit as-is. No follow-up core FHIR source work is needed for FHIR-5196 unless the PA work group later chooses to revise the underlying Encounter participant or PractitionerRole modeling guidance.
