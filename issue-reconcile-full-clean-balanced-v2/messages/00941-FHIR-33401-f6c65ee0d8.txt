FHIR-33401: Audit Procedure nutrition intake boundary

Issue request:
FHIR-33401 was Published with resolution Not Persuasive with Modification. The requester asked how to store nutrients for a nutrition administration and proposed adding nutrition-facts elements to Procedure; the final resolution instead directed Procedure boundaries to say that Procedure should not capture an event when a more specific resource exists, including nutrition intake.

Initial application:
The issue was applied before this reconciliation by git commits 6f0e73e16a and 2922f045a9, merged by ece0ddd3b1 in PR #2737. The first commit changed Procedure boundaries from an exhaustive "i.e." list to an example "e.g." list and added a NutritionIntake link; the second fixed the spelling of "nutrition intake".

Additional context:
OO minutes from 2023-02-10 record that the ticket predates nutrition-specific resources and that NutritionIntake should be used when nutrition is the main focus of the procedure. The current build has active fhir.ini entries for both Procedure and NutritionIntake, and NutritionIntake itself now covers intake events plus nutrient, amount, and energy details.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Procedure source already says not to use Procedure when a more specific resource exists and includes linked nutrition intake; the active NutritionIntake source describes food, supplement, enteral, and infant formula intake and includes the nutrient/amount/energy structure needed for the request.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-33401 unless a future work group decision separately reopens the broader workflow-resource list or nutrition-boundary policy.
