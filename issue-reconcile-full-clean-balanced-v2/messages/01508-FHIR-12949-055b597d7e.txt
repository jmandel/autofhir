FHIR-12949: Audit DocumentReference summary settings

Issue request:
FHIR-12949 was Published/Persuasive with Modification for DSTU2. It asked for DocumentReference _summary to be a minimal UI-list subset rather than returning document content, with the final accepted set covering status, docStatus, type, class, subject, author, description, context.period, content.format, content.attachment.contentType, content.attachment.language, identifier, masterIdentifier, indexed, and securityLabel/confidentiality.

Initial application:
The issue appears to have been applied by git-svn commit 94e532a611046fcdc40df2d7d28457eeb7dad3a6, the San Diego WGM block-vote commit that explicitly lists GF#12949 for DocumentReference. That commit changed the then-authoritative source/documentreference/documentreference-spreadsheet.xml and its sheet text, leaving summary markers on the accepted metadata fields and removing summary from several non-list fields such as context.encounter, facilityType, practiceSetting, sourcePatientInfo, and context.related. Because the old source represented Attachment use by marking the attachment wrapper, the applied source kept DocumentReference.content and content.attachment as summary wrappers so that selected Attachment metadata could appear without returning Attachment.data.

Additional context:
The current build uses source/documentreference/structuredefinition-DocumentReference.xml through the active source/fhir.ini DocumentReference resource entry. Later resource evolution explains differences from the DSTU2 literal names: class is now category, indexed is now date, context.period is now period, content.format is now content.profile.value[x], and masterIdentifier has been folded into identifier. The current ElementDefinition summary rule says datatype properties are generally included in summary form but explicitly excludes Attachment.data; the Attachment datatype marks contentType and language as summary. Current DocumentReference also has additional R6-era summary metadata from later resource evolution, such as version, modality, bodyStructure, context, and relatesTo. A later R6 issue, FHIR-54538, asks to add practiceSetting to summary, but it is only Resolved - change required/Ready_to_Apply and was not in this default applied/published reconciliation scope.

AutoFHIR reconciliation:
This audit made no source changes. Current source already carries the FHIR-12949 outcome forward on the still-current equivalents of the accepted fields, and the content.attachment summary wrapper is necessary in the current source model to expose Attachment metadata while Attachment.data remains excluded from _summary. Removing the wrapper or reapplying the DSTU2 literal list would either lose the accepted contentType/language/profile metadata or overwrite later current-version resource decisions.

Recommendation:
Keep this no-change audit commit as-is. Do not make a FHIR-12949 edit to remove DocumentReference.content.attachment from the current differential; any desire to narrow Attachment summary metadata beyond the global Attachment.data exclusion or to add practiceSetting should be handled by a current-version work-group issue such as FHIR-54538 when it is applied.
