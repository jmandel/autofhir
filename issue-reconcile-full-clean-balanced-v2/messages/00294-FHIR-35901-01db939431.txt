FHIR-35901: Flag PCA lockout extension for review

Issue request:
FHIR-35901 was Published with a Persuasive with Modification resolution for R5. It asked how PCA pump lockout intervals should be represented, concluded that maxDosePerPeriod should support multiple limits, and proposed a new Dosage.minimumGapBetweenDose Duration element with short text "Time that must pass between doses", definition "The minimum amount of time that must pass between administering the specified dose amount", and synonym "lockout interval".

Initial application:
The Jira comments say the base change missed the R5 deadline and that an extension would be created instead. The implementation trail is Git commit 9bf87c1410aae87779e90336478f8777f618321c in the FHIR Extension Pack, which added input/definitions/datatypes/StructureDefinition-dosage-minimumGapBetweenDose.xml. Current core source retains an OID registry entry for that canonical URL and later Dosage/DosageSafety work gives dose limits a repeatable structure, but the minimum-gap extension definition itself is no longer a build-scope core source file.

Additional context:
Pharmacy May 2022 WGM minutes record the PCA modeling questions, including PCA dose, lockout, continuous rate, and max dose per period, and FHIR-I minutes on 2023-02-15 record the Persuasive with Mod vote. Later FHIR-51540 work reworked Dosage and dose limits for R6, but that issue is still Resolved - change required and is not a separate applied/published decision for this run. The current Extension Pack artifact is present, but its differential is a complex extension with meetGoal, whenTrigger, and precondition slices and Extension.value[x] max 0 rather than a straightforward valueDuration, so this worker cannot safely conclude whether the extension now correctly implements the Jira's simple Duration intent or whether a deliberate later design superseded it.

AutoFHIR reconciliation:
This is an empty human-review audit commit. No core source was changed because the only concrete implementation artifact for the lockout interval is maintained in the FHIR Extension Pack outside this checkout, and changing current core Dosage source to add a base element would conflict with the documented R5 extension workaround and later Dosage refactoring without a fresh work-group decision.

Recommendation:

Do not add a core Dosage.minimumGapBetweenDose element unless that review reopens the issue for current core.
