FHIR-46191: Audit linkId whitespace constraints

Issue request:
FHIR-46191 was an Applied/Persuasive with Modification FHIR-core change request asking to change Questionnaire.item.linkId from string to code, with the same whitespace behavior carried to QuestionnaireResponse, so linkIds would not allow leading/trailing whitespace or whitespace other than single internal spaces.

Initial application:
The Jira application comment says the datatype change was not used because changing to code would have required a binding that made no sense; instead, the regex behavior was copied as explicit constraints. Git commit 5000586d1b0d7c0c4c488541b3574fef0c9d3739, referenced in Jira as f0c9d3739, added the Questionnaire.item.linkId regex extension and the que-16/qrs-3 error constraints that enforce the approved whitespace rule on both Questionnaire and QuestionnaireResponse.

Additional context:
The relevant Questionnaire and QuestionnaireResponse StructureDefinition XML files are current build inputs because both resources are active in source/fhir.ini. The cited Zulip thread records the original concern about leading/trailing and intervening whitespace and the desire to use code-like whitespace rules without invalidating slash-containing linkIds. FHIR SDC minutes for 2024-06-20 record approval of FHIR-46191. The same historical commit also handled FHIR-48941, but that is a separate Questionnaire definition-cardinality request and is not decided here.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current source preserves linkId as string, consistent with the Jira application comment, and already constrains Questionnaire.item.linkId and QuestionnaireResponse.item.linkId with the regex [^\\s]+( [^\\s]+)* so leading/trailing whitespace and non-single-space intervening whitespace are rejected.

Recommendation:
Keep this audit commit as-is. No additional core source change is needed for FHIR-46191 unless a future work-group decision deliberately reopens the datatype choice or asks for additional explanatory wording beyond the existing constraints.
