FHIR-17640: Audit Schematron XPath corrections

Issue request:
FHIR-17640 was a Published/Persuasive STU3 FHIR-core correction reporting that generated fhir-invariants.sch contained invalid Schematron XPath, including XPath uses of xor, missing predicate closing brackets in Consent/ppc assertions, a malformed Questionnaire que-5 allowed-type list, and a missing close parenthesis in a ValueSet status/compose/expansion assertion. The issue also suggested adding Schematron validation to the build.

Initial application:
The Jira comment says Grahame fixed the XPath problems in SVN revision 14893. Git history maps that to 2eb5c5a53c24a5dab84a3754b9ea24c3fbe74560, which expanded the DataRequirement XPath xor checks into legal boolean expressions and fixed the missing Consent scope predicate brackets. A follow-up GF#17640 commit, a59f68bb9674a37edd4600c54776353e60dc81cc, fixed the missing ValueSet close parenthesis.

Additional context:
The old Consent and ValueSet spreadsheet files touched by the GF#17640 commits are no longer current checked-in source files; the current active resources use structuredefinition-Consent.xml and structuredefinition-ValueSet.xml. Later ElementDefinition cleanup removed XPath constraints from Questionnaire and ValueSet StructureDefinitions, so the current build source no longer exposes the specific invalid que-5 XPath or the old ValueSet XPath surface. DataRequirement remains a normative datatype and its XPath column still contains the corrected expanded boolean expression. FHIR-18113 and FHIR-31483 are related Schematron/XPath audits already represented on the combined branch, so they are cited only as background.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source contains no checked-in .sch files, no current-source instance of the malformed XPath strings reported by FHIR-17640, and the build-scope authoritative sources either carry the fixed XPath or no longer carry the obsolete XPath assertions.

Recommendation:
Keep this audit commit as-is. No FHIR-core source edit is needed for FHIR-17640 unless a future generated Schematron pipeline reintroduces one of the malformed XPath forms; if that happens, fix the authoritative constraint source or generator rather than generated fhir-invariants.sch output.
