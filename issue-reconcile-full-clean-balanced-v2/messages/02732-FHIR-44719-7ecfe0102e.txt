FHIR-44719: Audit FHIRPath empty extension example

Issue request:
FHIR-44719 was an Applied/Persuasive FHIR-I change request for R6 asking the FHIRPath primitive-type examples to clarify that empty() considers extensions. The approved resolution was to add the proposed example showing that a primitive with no value but with extensions can make !Patient.active.hasValue() and !Patient.active.empty() both true.

Initial application:
The issue was already applied by source commit 5465375c661b23de9bfabd4c18a30b9e51af4443, which added the Patient.active.hasValue()/empty() example to source/fhirpath.html. The current combined branch still contains that example in the FHIRPath page's primitive-type section.

Additional context:
The originating Zulip thread records Grahame Grieve's answer that Patient.active.empty() should be false when Patient._active carries extensions because such elements are not empty. FHIR-I minutes for 2025-01-06 record the 10-0-0 Persuasive vote for FHIR-44719. A later same-line edit in 4961dcb9df16e3e7316d64a1062c5f5c5c7701d4 changed the example operator from && to the FHIRPath keyword and, preserving the requested semantics while making the expression match FHIRPath syntax.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active authored source page source/fhirpath.html already says that primitives may contain extensions and includes the needed example: !Patient.active.hasValue() and !Patient.active.empty() can both be true if extensions are present but no primitive value is present.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-44719 unless a future FHIRPath decision changes the model for primitive elements with extensions.
