FHIR-11051: Audit retired CarePlan Questionnaire activity detail

Issue request:
FHIR-11051 was a Published Patient Care change request with resolution Not Persuasive with Modification. It asked to explain or remove Questionnaire as a target for CarePlan.activity.detail.definition; the approved resolution kept Questionnaire as a definition resource rather than QuestionnaireResponse as an event resource, and required the element requirements to say "Allows Questionnaires that the patient (or practitioner) should fill in to fulfill the care plan activity."

Initial application:
The issue was applied in commit c124072d7bc14dd9eea48ac1aaf530bcd31171a6, which changed the then-authoritative CarePlan spreadsheet for GF#11051 by adding exactly the required requirements text to CarePlan.activity.detail.definition. Later source conversion carried that text into structuredefinition-CarePlan.xml.

Additional context:
CarePlan is active in source/fhir.ini, so source/careplan/structuredefinition-CarePlan.xml is in current build scope. However, the current source no longer has active CarePlan.activity.detail.definition, CarePlan.activity.plannedActivityDetail, or CarePlan instantiates[x] elements. FHIR-39101/J#39101 removed CarePlan.activity.plannedActivityDetail in R5 by commenting out that block and broadening plannedActivityReference, and FHIR-40500/J#40500 later removed CarePlan.instantiatesCanonical/instantiatesUri from Patient Care resources. The old FHIR-11051 requirements wording remains only inside the commented-out plannedActivityDetail block, while active CarePlan activity source exposes plannedActivityReference and performedActivity instead.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because the original request was applied when the element existed, and the current built specification no longer has an active Questionnaire activity-definition target that requires this clarification.

Recommendation:
Keep this audit commit as-is. Do not edit the retired commented block or checked-in diagram output just to restate obsolete activity.detail.definition guidance. If a future change reintroduces an activity-level definition mechanism, evaluate it against current CarePlan workflow patterns and extensions rather than resurrecting the DSTU2 wording automatically.
