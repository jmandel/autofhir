FHIR-21000: Audit ContactPoint comment extension

Issue request:
FHIR-21000 was Published with resolution Persuasive with Modification. It requested a way to attach free-text comments to a patient's phone number or other ContactPoint such as email; the recorded resolution was to define a standard extension for comments on phone numbers, addresses, and names, with examples such as pronunciation or usage notes.

Initial application:
The issue appears to have been applied in core by git commit 732b40c16876bd7f23e75b50253824d920485f4e, which explicitly lists FHIR-21000 and added a 0..1 string ContactPoint comment extension row to source/datatypes/contactpoint-extensions-spreadsheet.xml. The same historical check did not find parallel address-comment or humanname-comment rows; the applied source change focused on ContactPoint. Commit dd468d4f17 later removed R5 extension definitions from core as part of moving extensions into the Extension Pack.

Additional context:
The current core history page states that all extensions moved to the hl7.fhir.uv.extensions package and are still published as part of the specification but released separately. Core still reserves the contactpoint-comment OID in source/oids.ini. The current Extension Pack source defines http://hl7.org/fhir/StructureDefinition/contactpoint-comment as an active ContactPointComment extension with ContactPoint and ExtendedContactDetail contexts and value[x] string. Later FHIR-41563, supported by FHIR-41560, clarified that ContactPoint-purpose carries the circumstances for using the contact while contactpoint-comment carries other notes such as days/times or who to ask for; that clarification is present in the current Extension Pack definition.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The current core checkout is correct to omit the extension definition because extension definitions now belong to the Extension Pack, and the current Extension Pack definition satisfies the ContactPoint support requested by FHIR-21000 after later clarification. Adding duplicate core narrative or a new core extension source would conflict with the current source ownership model.

Recommendation:
Keep this audit commit as-is for the core reconciliation. If the work group still wants new Address or HumanName comment examples or separate non-ContactPoint comment extensions, handle that as a new Extension Pack issue rather than editing core in this run.
