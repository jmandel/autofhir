FHIR-7056: Audit AllergyIntolerance missing status guidance

Issue request:
FHIR-7056 was a Published/Persuasive with Modification Patient Care change request against DSTU1 AllergyIntolerance.status. It asked whether the optional status should be mandatory and what an empty status meant; the resolution said an omitted status means the status is unknown, unavailable, or the system cannot differentiate status, and that comments would be added to that effect.

Initial application:
Historical commit a30496dcda9c86251cf286f1636c23e570a80113 explicitly lists #7056 in a broad AllergyIntolerance usage-notes update. That commit updated the AllergyIntolerance introduction, notes, and spreadsheet while leaving AllergyIntolerance.status 0..1 and documenting status handling in the row; no separate exact "unknown/unavailable" sentence survives from that DSTU1 row because the resource was later refactored.

Additional context:
AllergyIntolerance is an active current-build resource in source/fhir.ini. Later published Patient Care decisions changed the status model and are controlling for the current build: FHIR-10642 and FHIR-11151 replaced the single status with clinicalStatus and verificationStatus; FHIR-13997 made verificationStatus optional for unknown/default-guidance concerns; FHIR-18831 added a missing-data Special-Case link for clinicalStatus; and FHIR-25514/FHIR-28458 removed clinicalStatus invariants while retaining should-present guidance for non-entered-in-error, non-negated records. Existing combined-branch commits already audit the later FHIR-11151, FHIR-18831, FHIR-25514, and related status-family decisions, so this reconciliation does not duplicate them.

AutoFHIR reconciliation:
This is an empty no-change audit commit. The current authoritative source already keeps AllergyIntolerance.clinicalStatus optional, says it should be present in the clinically relevant cases, and points implementers to the standard missing-data Special-Case guidance when it is absent. Adding a new historical status-unknown sentence would be redundant with that guidance and could obscure later decisions that intentionally avoided a mandatory status/default code.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-7056; any future audit of FHIR-10642 should be handled as its own status-split/default-value reconciliation rather than by re-opening this DSTU1 clarification.
