FHIR-15089: Audit ServiceRequest performer cardinality

Issue request:
FHIR-15089 was a Published/Persuasive with Modification OO change request from STU3 asking whether ServiceRequest.performer should become 0..* for cases where several acceptable performers can fulfill a referral or order. The accepted resolution changed ServiceRequest.performer to 0..* and required comments explaining that multiple performers are alternatives, unordered unless a performer-order extension is used, and that CareTeam represents an AND/group of performers.

Initial application:
The original application is visible in git commit 0ec626c1ac946abcaab6309bcd4fc1bd4b03f475, titled "GF#15089 ServiceRequest.performer to 0..*". That commit changed the ServiceRequest spreadsheet cardinality from 0..1 to 0..* and replaced the old generic extension comment with the alternative-performer, performerOrder, and CareTeam guidance. The source was later migrated into source/servicerequest/structuredefinition-ServiceRequest.xml by the build-source rework, preserving the applied max="*" and comment semantics.

Additional context:
ServiceRequest is an active core resource in source/fhir.ini, so source/servicerequest/structuredefinition-ServiceRequest.xml is current build input. The current performer comment uses the current canonical http://hl7.org/fhir/StructureDefinition/request-performerOrder, whose StructureDefinition now lives in the FHIR Extension Pack and explicitly has ServiceRequest.performer context. Later FHIR-41410 added Group as a target and appended family/household-only Group guidance; that later change does not reverse FHIR-15089's alternative-performer and CareTeam distinction. A 2025 Da Vinci CRD Zulip thread quotes the current ServiceRequest.performer language as the operative interpretation for multiple performers. Confluence searches found no FHIR-15089 references or conflicting minutes.
