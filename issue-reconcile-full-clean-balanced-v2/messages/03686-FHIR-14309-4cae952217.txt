FHIR-14309: Audit Range invariant application

Issue request:
FHIR-14309 is a Published/Persuasive FHIR-core datatypes change request from MnM asking to re-add the Range rng-2 invariant after FHIRPath gained Quantity comparison support. The requested rule was that, when present, low SHALL have a lower value than high.

Initial application:
The issue appears to have been applied by git-svn commit 11f97b11d7 (svn revision 13459), matching the Jira comment. That commit re-enabled Range invariant id 2 by changing the Range spreadsheet invariant id from !2 back to 2 after FHIR-14194 had disabled the invalid earlier expression.

Additional context:
FHIR-14194 explains why rng-2 was temporarily disabled: Quantity comparison semantics were not defined enough for the old low <= high expression. FHIR-14308 added the related FHIRPath Quantity comparison support, and the linked Zulip thread confirms that this was the intended dependency. Later source history retained the invariant and commit 8a6a54029f updated the expression to use lowBoundary/highBoundary and a comparable guard, preserving the rule while matching newer FHIRPath semantics.

AutoFHIR reconciliation:
No source change was made. source/fhir.ini actively lists Range under [types], so source/datatypes/range.xml is in current build scope; that authoritative spreadsheet already contains invariant row 2 for context Range with the requested human text and a current Quantity-aware FHIRPath expression.

Recommendation:
Keep this audit commit as-is. The current source already satisfies FHIR-14309, and changing the expression back to the literal historical low <= high wording would regress the later Quantity-boundary clarification.
