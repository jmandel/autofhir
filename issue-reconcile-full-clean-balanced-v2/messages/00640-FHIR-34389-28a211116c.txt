FHIR-34389: Audit external Provenance enterer terminology

Issue request:
FHIR-34389 was an Applied FHIR-core Security change request with a Persuasive with Modification resolution. It asked that the Provenance agent type code "enterer" change from "A person entering the data into the originating system" to "An agent entering the data into the originating system, such as a scribe or transcriptionist." to distinguish enterer from author and avoid limiting the role to humans.

Initial application:
The current core checkout no longer contains the source CodeSystem concept definition for provenance-agent-type. Git history shows the old core file source/provenance/codesystem-provenance-agent-type.xml contained the stale "A person entering..." definition before commit 5c0494aacf removed UTG-maintained terminology content from the core build. Current Provenance source remains in build scope and binds Provenance.agent.type through source/terminologies/valueset-participation-role-type.xml, which includes the external THO value set http://terminology.hl7.org/ValueSet/provenance-agent-type.

Additional context:
UP-524, "Cleanup of Provenance Agent Types," explicitly grouped FHIR-34389 with related Provenance agent type cleanup, was approved by the Security WG on 2024-02-19, and was implemented as a THO/UTG change to input/sourceOfTruth/fhir/codeSystems/CodeSystem-provenance-participant-type.xml. Current THO JSON for CodeSystem/provenance-participant-type, including version 6.0.2-era output, now defines enterer as "An agent entering the data into the originating system, such as a scribe or transcriptionist."

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The needed terminology definition is owned by THO/UTG rather than this core source checkout, and the external source of truth already reflects the applied FHIR-34389 wording. Adding a duplicate local definition or redundant Provenance prose in core would not be the authoritative fix.

Recommendation:
Keep this external-repo audit commit as-is. No FHIR core follow-up is needed unless a future build is shown not to consume the corrected THO terminology package; any remaining source maintenance for this specific definition belongs in THO/UTG, not the core repository.
