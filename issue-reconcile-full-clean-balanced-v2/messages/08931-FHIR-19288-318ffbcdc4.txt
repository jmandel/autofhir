FHIR-19288: Audit Device UDI HRF search

Issue request:
FHIR-19288 was Published/Persuasive with Modification for STU3 Device. It requested that the Device UDI carrier search parameter stop presenting AIDC/base64Binary as a search criterion because the specification had not defined how base64Binary search should work; the accepted resolution was to leave only HRF as the search criterion while keeping future AIDC search open for later consideration.

Initial application:
The Jira comment cites HL7/fhir commit 79efcbfadbfcc39a48b3ecf041bdeea3df583007, which changed the legacy Device spreadsheet search parameter description from HRF-or-AIDC/base64 to HRF-only. Local git history also shows same-day GF#19288 follow-up commits c11df03b4c559af1d27b720be7812283027d7b97 and 67e557368146cea28273d8489557d0fc0c0054ee that moved the legacy spreadsheet expression to Device.udiCarrier.carrierHRF. The later source migration in 33b409a4b6d544598262f2f074ebb4b6dc466157 preserved an HRF-only search parameter.

Additional context:
Device is active in the current build through source/fhir.ini. The current authoritative search parameter source is source/device/bundle-Device-search-params.xml rather than the removed legacy device-spreadsheet.xml. FHIR-40503 later reviewed Device search parameters and explicitly renamed udi-carrier to udi-carrier-hrf because the parameter is HRF-only. FHIR-18080 is the adjacent STU3 Device search-parameter expression issue and explicitly deferred HRF/AIDC handling to FHIR-19288. FHIR-46078 later requested combined identifier/UDI search and was Resolved - No Change, so it does not reopen AIDC carrier search.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current search parameter is code udi-carrier-hrf, has description "UDI Barcode (RFID or other technology) string in *HRF* format.", and has expression Device.udiCarrier.carrierHRF. Current source searches found no Device search parameter expression over carrierAIDC and no remaining old HRF-or-AIDC/base64 search description in the active Device source.

Recommendation:
Keep this empty audit commit as-is. No core source edit is needed for FHIR-19288 unless a future work-group decision defines AIDC/base64Binary search semantics and adds a separate AIDC search parameter.
