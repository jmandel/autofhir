FHIR-5250: Audit Composition section code binding

Issue request:
FHIR-5250 was a Published/Persuasive DSTU1 ballot correction for FHIR-core Composition. It asked that the Composition.section.code binding definition stop saying it classified the whole composition/document and instead say it classifies a section of a document; the Jira application comment clarified that the binding definition, not the element definition, was the affected text.

Initial application:
The issue was applied in git commit 3fc5cd3e1b417b31c21234e89db22de9e4039330, which carries the SVN revision 4620 marker cited in Jira and changed the historical Composition spreadsheet binding text from "Classification of a composition / document" to "Classification of a section of a composition / document". Later source refactors moved the active Composition definition into source/composition/structuredefinition-Composition.xml.

Additional context:
The current build includes Composition as an active resource in source/fhir.ini, and the active Composition.section.code binding description now says "Classification of a section of a composition/document." A stale copy of the old wording remains in source/profiles/cda.profile.xml, but the corresponding cda profile entry is commented out in source/fhir.ini and is not a current-build source correction target. Jira search found only the seed issue for this exact wording, and Zulip/Confluence searches found no conflicting community context.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current specification already conveys the approved correction, and changing the disabled CDA profile would edit out-of-build source rather than a current spec artifact.

Recommendation:
Keep this no-change audit commit as-is for the current core build. If the CDA/clinicaldocument profile is ever reactivated, separately review and update its stale binding description before publication.
