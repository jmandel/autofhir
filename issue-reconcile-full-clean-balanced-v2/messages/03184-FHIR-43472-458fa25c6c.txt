FHIR-43472: Audit Codeable spelling note

Issue request:
FHIR-43472 was Applied/Not Persuasive with Modification for R6. It reported that CodeableConcept and CodeableReference use the long-standing FHIR spelling "Codeable" rather than dictionary "Codable" and suggested avoiding that spelling. The approved decision was not to rename these normative datatypes because doing so would affect all implementations, but to add an explanatory note that the FHIR spelling is long-standing and accepted by the community.

Initial application:
The current branch already contains Jira-tagged commit d18b13713fa, which added the explanatory note for both CodeableConcept and CodeableReference in source/help.html, the FHIR Glossary. That initial text inherited the Jira resolution typo "accpeted"; follow-up commit 1cae470f393 corrected the note to "accepted". A separate historical side-branch commit 08c5139c39 added the note only to CodeableConcept in source/datatypes.html and also carried the typo, but that partial application is not part of the current source line.

Additional context:
source/help.html is the built Glossary linked from source/documentation.html. source/fhir.ini maps CodeableConcept to the datatypes page by the default datatype page rule and maps CodeableReference to references.html, and those active pages contain no contrary guidance or attempted rename. The FHIR-I WGM minutes for 2024-01 record the same 19-0-0 Not Persuasive with Modification vote as Jira. Targeted Zulip search found no related discussion, and Jira neighborhood search found no other spelling issue in the same family.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current combined branch already carries the corrected explanatory note for both requested terms, and adding duplicate note text to the CodeableConcept and CodeableReference narrative sections would be redundant editorial duplication rather than a necessary current-spec correction.

Recommendation:
Keep this audit commit. The applied decision is represented in current source; only revisit if FHIR-I explicitly wants the same glossary note duplicated on the individual datatype narrative pages.
