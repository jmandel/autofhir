FHIR-19951: Audit ExampleScenario type rename

Issue request:
FHIR-19951 was a Published/Persuasive R5 change request to rename ExampleScenario.instance.resourceType because the element name conflicted with the JSON serialization pseudo-element resourceType. The recorded resolution was to rename resourceType to "type".

Initial application:
The issue was initially applied in b8667da649 and merged as 0dc020eab51b01c95a4a6a810f77f2bc0961a6c0, changing ExampleScenario.instance.resourceType to ExampleScenario.instance.type in the StructureDefinition and example XML. No prior Issue-Reconcile-Key commit for FHIR-19951 was present on the combined branch before this audit.

Additional context:
ExampleScenario is still an active current-build resource through source/fhir.ini. Later Published ExampleScenario issues changed the same element family: FHIR-37195 also listed instance.resourceType -> instance.type as part of a cleanup, FHIR-22855 broadened the element from FHIR-only resource types to general data structures with an extensible Coding binding, and FHIR-37895 explicitly changed instance.type to instance.structureType to align with structureVersion and structureProfile[x]. FHIR-I minutes record FHIR-37895 as Persuasive with Modification. The remaining source/fhir.ini occurrence of ExampleScenario.instance.resourceType is in the r4-r6-changes migration map to ExampleScenario.instance.structureType, not the current element definition.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active StructureDefinition and examples use ExampleScenario.instance.structureType, and a current-source search found no ExampleScenario resourceType element. That resolves the parser-conflict intent from FHIR-19951 while preserving later WG-approved ExampleScenario terminology.

Recommendation:
Keep this audit commit as-is. Do not rename structureType back to type for FHIR-19951; that would undo later FHIR-37895/FHIR-22855/37195 decisions. Revisit only if the work group reopens ExampleScenario naming more broadly.
