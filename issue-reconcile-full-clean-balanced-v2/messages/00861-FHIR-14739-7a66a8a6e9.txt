FHIR-14739: Audit dropped OccupationalData retirement status

Issue request:
FHIR-14739 was a Published/Persuasive STU3 OccupationalData ballot issue asking where OccupationalData.retirementStatus.value had gone and whether retirement should instead be represented by retirementDate and/or employmentStatus.

Initial application:
No commit explicitly names FHIR-14739. The 2018Jan published ballot page still exposed OccupationalData.retirementStatus.code, effective[x], and value. The development source had already been reshaped by git commit 43bb1f0626, which removed the retirementStatus backbone and its value set and introduced OccupationalData.retirementDate. PHWG minutes for the same retirement-status ballot comment record that the retirementStatus LOINC code was actually for retirement dates and that the code was no longer part of the resource because it had been replaced with a retirement date element.

Additional context:
Current source/fhir.ini comments OccupationalDataforHealth as "pending -> Dropped", so source/occupationaldata is not in the current core build. The current leftover OccupationalData spreadsheet contains OccupationalData.retirementDate and no OccupationalData.retirementStatus.value. A related later no-change issue, FHIR-14479, kept retirementDate independent of employer; it does not put OccupationalData back in current build scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Editing source/occupationaldata would alter a dropped, out-of-build artifact, and the retained source already reflects the historical resolution by using retirementDate instead of retirementStatus.value.

Recommendation:
Keep this audit commit as-is for core FHIR. If Occupational Data for Health is maintained in a separate IG or repository, review that external artifact only if it still publishes the obsolete retirementStatus.value model.
