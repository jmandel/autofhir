FHIR-7359: Audit validation tool clarification

Issue request:
FHIR-7359 was a Published/Persuasive with Modification DSTU1 FHIR-I change request against the conformance rules page. It challenged the statement that none of the listed tools could check complete conformance and asked whether testing tools should be able to check conformance to the FHIR specification and specific profiles; the recorded resolution was to add a clarification note.

Initial application:
The issue appears to have been applied in SVN revision 6456, represented in git as 4d589dd68bc9b557b73b073b069554ae4fbdeb92. That commit replaced the local list of schema/validator/reference-platform links and the blunt "none of these tools" sentence with a link to validation.html, saying the specification provides tools that assist with enforcing technical conformance to the base specification and profiles.

Additional context:
The current conformance-rules.html source is still an active top-level specification page linked from the conformance module and documentation index. Its current text links readers to validation.html for tooling detail. The current validation page explicitly lists profile validation as a validation aspect and then explains that all validation methods are incomplete, can only validate computable conformance, cannot check all narrative rules, and that human inspection remains the final arbiter. A later 2018 terminology-consistency commit removed the local phrase "and profiles on it", but the linked validation page still covers profiles, so the issue's intended clarification remains present without duplicating the validation guidance. Negative Zulip and Confluence searches found no community record that changes this conclusion. FHIR-7360 shared the historical implementation commit and is already represented on the combined branch.

AutoFHIR reconciliation:
This audit commit makes no source change. The current built source already avoids promising complete automated conformance checking and directs readers to the validation page where the limits and profile-validation capabilities are described.

Recommendation:
Keep this no-change audit as-is. Re-adding the old local caveat or duplicating validation.html would be redundant and could create maintenance drift; any future wording work should be handled as a fresh editorial issue if the work group wants the conformance page to summarize validation limits inline.
