FHIR-14833: Clarify MedicationStatement partial effective dates

Issue request:
FHIR-14833 was a Published Pharmacy change request for STU3, resolved Not Persuasive with Modification, asking to allow approximate dates for MedicationStatement.effective[x] when a patient cannot remember an exact medication date. The accepted resolution said dateTime already supports year-only, year/month, and exact-date precision, that fuzziness beyond those forms should be conveyed as text, and that this guidance should be added to MedicationStatement effectiveTime.

Initial application:
The Jira comments identify svn/git commit 73c779d3aeb5a6120955eb499d67727c2fdfdf47 as the original application. That commit added the requested wording to the old MedicationStatement spreadsheet comment: "The date/time attribute supports a variety of dates - year, year/month and exact date. If something more than this is required, this should be conveyed as text." The current build no longer uses that spreadsheet source; the active StructureDefinition retained the trailing text instruction but, after later effective[x] edits, described effectiveDateTime as documenting an "exact date/time" without explicitly preserving the partial-date guidance.

Additional context:
MedicationStatement is in the current build scope through source/fhir.ini, which lists medicationstatement=MedicationStatement and MedicationStatement=mst. The core primitive dateTime definition still permits partial dates such as year and year/month. A later already-published reconciliation for FHIR-37372 updated the same MedicationStatement.effective[x] comment to explain usage period plus last-administration-date recording with two MedicationStatement resources; this commit preserves that later guidance while restoring the FHIR-14833 partial-date clarification. Community searches found no Zulip or Confluence evidence that changes the Jira/source conclusion.

AutoFHIR reconciliation:
Updated the authoritative MedicationStatement StructureDefinition effective[x] comment to say effectiveDateTime can document the medication date/time including partial dates such as year or year/month, and to say fuzzier values than dateTime precision should be conveyed as text. Updated the MedicationStatement Event mapping exception copy of the same comment so mapping metadata remains consistent with the StructureDefinition.

Recommendation:
Keep this source-changing commit. It restores the published Pharmacy clarification in the active current source, removes a misleading "exact date/time" narrowing, and preserves the later FHIR-37372 guidance for usage period plus last administration date/time.
