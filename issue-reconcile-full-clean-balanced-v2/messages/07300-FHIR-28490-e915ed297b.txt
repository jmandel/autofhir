FHIR-28490: Audit Subscription resource-qualified filters

Issue request:
FHIR-28490 was Published/Persuasive for R5 and asked to clarify how Subscription filters and SubscriptionTopic criteria apply when a topic has multiple qualifying resource types. The concrete proposal was to add a 0..1 resource discriminator to Subscription.filterBy, change SubscriptionTopic resource triggers to repeat with a single resource each, and move canFilterBy under the resource-specific trigger.

Initial application:
The request appears to have been initially applied by 4f3fcec0394f15c2c0a93f377b15fd0b866b3c9f, whose body says "First pass of FHIR#28490" and which changed Subscription examples plus the Subscription and SubscriptionTopic spreadsheet sources. After later build refactors, the current authoritative XML sources carry the same model intent rather than the original spreadsheet representation.

Additional context:
The current names differ from the issue text because later applied decisions refined the same area: FHIR-30383 clarified that multiple filters are ANDed only when they apply to the resource being evaluated, FHIR-39033 retained the filter resource discriminator and added framework guidance, FHIR-41197 renamed Subscription.filterBy.resourceType to Subscription.filterBy.resource, and FHIR-46492 collapsed SubscriptionTopic.resourceTrigger/eventTrigger into the current repeating SubscriptionTopic.trigger while keeping canFilterBy under trigger. The linked 2020 Subscription connectathon Zulip discussion and FHIR-I minutes corroborate the original problem and vote, and no current-source stale resourceType references remain outside the intentional fhir.ini compatibility alias.

AutoFHIR reconciliation:
This audit makes no source change. The active current-build Subscription and SubscriptionTopic resources already express the approved behavior: Subscription.filterBy.resource is 0..1 and points to SubscriptionTopic.trigger.canFilterBy.resource; SubscriptionTopic.trigger repeats, has a single resource, and owns canFilterBy; the Subscriptions framework and resource pages explain multi-resource topics and resource-scoped filters.
