FHIR-3849: Audit Practitioner location search

Issue request:
FHIR-3849 was a Published/Persuasive Patient Administration change request from DSTU1 asking for a search parameter so implementations could produce a list of workers at a Location.

Initial application:
The issue was applied in commit 17d3e7f892683f3a42a65c384c3c4d7c253dd64f, which added a location reference search parameter on the then-current Practitioner spreadsheet. Later resource modeling moved the worker-at-location association out of Practitioner role backbone content and into the active PractitionerRole resource.

Additional context:
Practitioner and PractitionerRole are active current-build resources in source/fhir.ini. Current PractitionerRole defines PractitionerRole.location as Reference(Location), provides a normative location search parameter with expression PractitionerRole.location, and the Practitioner narrative directs role, organization, and location details to PractitionerRole. A direct Practitioner-location search parameter would point at no current Practitioner element and would duplicate the successor resource model.

AutoFHIR reconciliation:
No source change was made. The current specification already supports finding workers at a location through PractitionerRole?location=... and linking those results to Practitioner through PractitionerRole.practitioner.

Recommendation:
Keep this audit commit as-is. Do not add a direct Practitioner location search parameter unless a future PA decision explicitly reintroduces location as a Practitioner search surface or defines a cross-resource chained search requirement.
