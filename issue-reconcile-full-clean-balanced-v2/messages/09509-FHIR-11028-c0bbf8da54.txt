FHIR-11028: Audit ElementDefinition code clarification

Issue request:
FHIR-11028 was a Published/Persuasive FHIR-core StructureDefinition change request asking whether explicit semantic bindings for an element should be represented by ElementDefinition.code or ElementDefinition.mapping. The recorded resolution was to clarify that the "code" element is for indexing and searching rather than serving as the semantic definition.

Initial application:
The issue was applied in svn revision 11254, now git commit 63966220f6b9bb25011250f605a1d61aded103e5, which changed ElementDefinition.code from "Defining code" and "provides the meaning" to "Corresponding codes in terminologies", "has the same meaning", and "very useful for searching and indexing." The current source still contains that applied clarification and the accompanying notes distinguishing simple terminology/data-element correspondences from more complex ElementDefinition.mapping structures.

Additional context:
The linked Zulip thread shows the editors concluded that the semantics of an element come from the ElementDefinition itself, while code and mappings can express correspondences to external terminologies or models and are not themselves definitional. source/fhir.ini keeps ElementDefinition in the active build and marks it normative, so source/datatypes/elementdefinition.xml is the authoritative current source checked here. No later FHIR-core Jira or Confluence evidence found during this bounded search superseded the applied clarification.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build source already reflects the #11028 application: ElementDefinition.code no longer claims to provide the element's meaning, explicitly mentions searching and indexing, and points implementers to ElementDefinition.mapping for more complex structures.

Recommendation:
Keep this audit commit as-is. If FHIR-I wants a stronger modern statement that neither code nor mapping is definitional and the element definition itself is the semantic source, that should be a new work-group change request rather than a late rewrite under FHIR-11028.
