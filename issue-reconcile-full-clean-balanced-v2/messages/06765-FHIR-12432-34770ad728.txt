FHIR-12432: Audit CodeSystem lookup property documentation

Issue request:
FHIR-12432 was a Published/Persuasive with Modification Vocab change request for DSTU2 asking that the CodeSystem $lookup input parameter property stop describing unavailable or ambiguous return parameters. The accepted resolution clarified that name is the human-readable code system name, designation is returned explicitly, definition is returned, and other parameters are at server discretion.

Initial application:
The issue was initially applied in svn revision 11141, now git commit b2756e0e3b9e2e01d6f0a639b262e6e5368fd6f6, which replaced the stale list of system/version/display/definition/designation/parent/child/lang.X in the old CodeSystem spreadsheet source with clearer url/name/version/display/definition/designation/parent/child/lang.X wording. The 2021 build-source rework moved the operation into source/codesystem/operationdefinition-CodeSystem-lookup.xml, preserving the applied clarification in the active CodeSystem operation source.

Additional context:
Later Published Vocab issues refined the same area. FHIR-22496 added definition as an explicit optional $lookup output parameter, and FHIR-39160/FHIR-36643 aligned the terminology-service standard $lookup properties and CodeSystem defined concept properties so concept properties such as parent and child are described through the defined-properties path rather than as direct out parameters. Current source/fhir.ini includes CodeSystem as an active resource, and source/codesystem/list-CodeSystem-operations.xml references OperationDefinition/CodeSystem-lookup, so the inspected OperationDefinition is in build scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current CodeSystem $lookup property input documentation names the explicit response channels (name, version, display, designation, lang.X), links additional property codes to codesystem.html#defined-props and CodeSystem.property.code, and the operation now has a definition output parameter. The terminology-service page also describes standard $lookup property names consistently with the later Vocab decisions.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-12432 unless the Vocab work group later decides to reopen the post-R5 distinction between explicit $lookup output parameters and concept properties.
