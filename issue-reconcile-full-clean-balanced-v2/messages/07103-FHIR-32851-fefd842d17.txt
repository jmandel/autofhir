FHIR-32851: Audit search parameter combining section

Issue request:
FHIR-32851 was a Published/Persuasive FHIR-I clarification asking that the search page stop placing general multi-value joining rules under the composite search parameter section and instead break that information into a distinct section called "Combining Search Parameters" or otherwise make it a peer of the other search parameter mechanics.

Initial application:
No direct historical source commit for FHIR-32851 was found. The current application appears to have been consolidated into the related FHIR-33158 search-page work: commit 7553224a3289edc37b55479254c15c9db228d047 moved the #combining anchor out of the Composite Search Parameters section, added it beside the multi-value section, and clarified the AND/OR versus composite distinction in source/search.html.

Additional context:
FHIR-I minutes for 2022-01-24 record the approved FHIR-32851 motion, "Will break into sections called \"Combining Search Parameters\"", with a 14-0-0 vote. The related FHIR-33158 Jira explains the same source problem from the #combining anchor perspective, and the current search page table of contents now lists "Searching Multiple Values (joining with AND or OR)" as a peer of Modifiers, Prefixes, Escaping, and the parameter type sections. FHIR-32852 is the same search-page restructuring family but concerns the page table of contents rather than the combining prose itself.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current built source already has anchors #multivalue and #combining on a distinct "Searching Multiple Values (joining with AND or OR)" section, and that section explains AND joins, OR joins by comma-separated values, combined AND/OR requests, and the boundary with composite search parameters. Renaming the visible heading to the exact Jira phrase would not add semantic clarity because the anchor and prose already preserve the approved intent.

Recommendation:
Keep this no-change audit commit as-is. Future search-page edits should preserve #combining compatibility and keep general AND/OR joining guidance separate from the Composite Search Parameters subsection.
