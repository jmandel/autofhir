FHIR-23008: Audit superseded Condition and AllergyIntolerance invariants

Issue request:
FHIR-23008 was Published/Persuasive for a Patient Care technical correction. It reported that AllergyIntolerance ait-1/ait-2 and Condition con-3 still treated verificationStatus as a primitive code after verificationStatus became CodeableConcept, and asked that the invariants be rewritten to preserve their intent.

Initial application:
The issue was applied by commit a233ae44884fd822d0d3500d76d39b9c9ed93bc2 on the R4B line, which changed the AllergyIntolerance ait-1/ait-2 and Condition con-3 FHIRPath/XPath expressions to inspect CodeableConcept.coding system/code values instead of primitive code values. The Jira discussion also records that the seed duplicated GForge tracker items 22985 and 22986.

Additional context:
Later applied Patient Care decisions changed the relevant conformance surface. FHIR-25514 removed AllergyIntolerance ait-1 and replaced it with non-invariant guidance for negated allergy records. FHIR-28458 added refuted-status guidance and removed/refined invariants that made clinicalStatus inappropriate for refuted records. FHIR-29409 then made Condition.clinicalStatus 1..1, removed the old verificationStatus/category-dependent Condition con-3, and loosened Condition.category. The current active AllergyIntolerance and Condition source is in build scope via source/fhir.ini.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current AllergyIntolerance has no ait-1 or ait-2 constraints; clinicalStatus has the later guidance comment and verificationStatus remains a CodeableConcept. Current Condition has no verificationStatus-dependent con-3 and no expression that compares verificationStatus as a primitive code; clinicalStatus is 1..1, and the current constraints concern abatement, bodyStructure/bodySite, and stage. A targeted source search found none of the old broken invariant patterns.

Recommendation:
Keep this no-change audit as-is. The current specification no longer contains the broken invariants FHIR-23008 targeted, and the remaining wording reflects later published decisions; no core follow-up is needed for the seed issue.
