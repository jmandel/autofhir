FHIR-12947: Audit DICOM-derived value set consistency

Issue request:
FHIR-12947 was a Published/Persuasive FHIR-I change request asking that DICOM-derived value sets be defined consistently. It pointed to instance-availability, DICOM CID-29, AuditEvent type and subtype, DICOM CID-405 media type, and KOS title examples, and asked either to identify DICOM as the official definition or to clearly treat any FHIR-maintained derivatives as FHIR-specific.

Initial application:
No historical source commit explicitly tagged FHIR-12947 was found. The issue appears to have been applied through the DICOM terminology work that followed the editors' DICOM discussion: fcf583e852 removed the local ImagingStudy DICOM CID-29 value set and made the binding external, and 26f1439636 / PR #951 switched AuditEvent and ImagingStudy terminology to DICOM-authored value sets while deleting hand-written DICOM-derived copies such as valueset-dicm-405-mediatype.

Additional context:
Later FHIR-24908 and FHIR-22483 recorded the clearer policy that FHIR core should use DICOM-published FHIR CodeSystems and ValueSets. The combined branch already contains the FHIR-22483 fix for the remaining active Composition CID-29 import. Current source/fhir.ini keeps AuditEvent, Composition, DocumentReference, ImagingSelection, ImagingStudy, and terminology sources active, but Media is absent from active [resources] and ImagingManifest is listed under [removed-resources]. The only remaining http://hl7.org/fhir/ValueSet/dicom-cid29 source hit is in the inactive Media folder; KOS title files remain only under removed ImagingManifest and OID history; instance-availability and dicm-405-mediatype source files are absent.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current-build DICOM value set references now point to DICOM canonical CID pages, and the remaining local DICOM-derived artifacts named in the original issue are either intentionally mixed FHIR example value sets that import DICOM plus local additions or legacy/out-of-build source.

Recommendation:
Keep this no-change audit commit as-is. Do not resurrect local DICOM-derived value sets in core; any future terminology freshness work should follow the DICOM-published package/value-set policy tracked by FHIR-22483 and FHIR-24908, and any cleanup of inactive Media or removed ImagingManifest files should be handled as separate retired-source cleanup.
