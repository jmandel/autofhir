FHIR-6783: Audit NamingSystem registry history

Issue request:
FHIR-6783 is a Published/Persuasive DSTU1 FHIR-core issue asking that the named systems list on terminologies-systems.html be made available as a Bundle of NamingSystem resources so servers could load the systems and map OIDs to URIs. The resolution was "do this," and the Jira comments record that it was already done.

Initial application:
No commit explicitly names FHIR-6783. The matching historical application is git commit 6156a02e85, made before the Jira vote/comment, which removed the named systems ValueSet, introduced better registries, added source/identifier-registry.html, and added source/namingsystem/namingsystem-registry.xml as a Bundle containing NamingSystem entries with OID and URI uniqueIds.

Additional context:
Later Published/Persuasive issue FHIR-37889 superseded the ongoing presence of those bundles for R5 by finding that the Terminology and Identity System NamingSystem bundles duplicated content authoritatively held in HL7 Terminology and were likely to become misleading. Commit 76c99d3aae applied that by removing the terminology bundle and most identity-system content. Published FHIR-40117 then confirmed the remaining empty namingsystem-registry.xml should not exist, and commit ededc6fc84 deleted it and removed the example-list reference. Current core source routes external code-system authority to THO and no longer contains namingsystem-registry.xml or namingsystem-terminologies.xml.

AutoFHIR reconciliation:
This is an empty audit commit. Recreating the historical NamingSystem bundle in current core would reverse the later vocabulary decision and duplicate THO-governed content, so the current source is correct without a source change.

Recommendation:
Keep this no-change audit as-is. Any future need for machine-loadable NamingSystem content for external terminology or identity systems should be handled through THO/TSMG governance rather than restoring the removed core example bundles.
