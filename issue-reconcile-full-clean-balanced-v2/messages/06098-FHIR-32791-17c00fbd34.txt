FHIR-32791: Audit DocumentReference Composition example

Issue request:
FHIR-32791 was a Published R5 OO change request asking to loosen DocumentReference.content, or otherwise guide how to create a DocumentReference that only references a Composition, because DocumentReference.content is required. The final Not Persuasive with Modification resolution kept the content requirement and said FHIR-37444 established that Attachment.url can point at a Resource, so an example should be added instead.

Initial application:
The issue was applied by git commit ee4b4a76e229bdcb8acff98a0cbe97a07ff0d935, merged by PR #2087, which added DocumentReference examples for content.attachment.url pointing at a Composition and at a FHIR document Bundle and registered them in list-DocumentReference-examples.xml. Later QA/example-list commits preserved the Composition example.

Additional context:
DocumentReference is an active core resource in source/fhir.ini, so source/documentreference examples and definitions are in current build scope. The current StructureDefinition still has DocumentReference.content at 1..*, matching the not-persuasive part of the resolution, while documentreference-example-composition.xml demonstrates satisfying that required content slice with Attachment.url value Composition/example. FHIR-37444, FHIR-I/OO minutes, and Zulip discussion confirm that Attachment.url may be a relative reference/resource URL and no datatype change was required.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The requested example is already present in the active DocumentReference example list, and the authoritative Attachment.url/datatype text already supports the mechanism the work group chose instead of changing cardinality.

Recommendation:
Keep this no-change audit commit as-is. No further core source work is recommended for FHIR-32791 unless a future work group decision changes DocumentReference.content cardinality or narrows Attachment.url semantics.
