Issue request:
FHIR-13908 was a Published/Persuasive STU3 workflow issue for the active Definition, Event, and Request logical patterns. It asked to remove the split definitionReference/definitionUri approach, use a URI-oriented instantiates relationship for Event and Request, and use Definition.derivedFrom for the Definition pattern per the issue comment.

Initial application:

Additional context:
The current build still includes definition, event, and request as active logical models in source/fhir.ini. Later R5 workflow decisions changed the representation: FHIR-32897 was Published/Not Persuasive with Modification and commit 2ee637a94c1abc09d0ab102e1f1a655a7292322d dropped the Request/Event instantiates data elements in favor of canonical/display-extension handling, while FHIR-40406 aligned the Definition pattern with CanonicalResource and left Definition as derivedFromCanonical plus derivedFromUri. Current searches of source/definition, source/event, and source/request find no definitionReference or definitionUri elements. The remaining Event.instantiates and Request.instantiates hits are legacy Search worksheet rows, not the removed Data Elements rows, and do not reintroduce the old split definitionReference/definitionUri model.
