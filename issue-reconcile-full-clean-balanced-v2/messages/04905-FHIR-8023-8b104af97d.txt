FHIR-8023: Audit removal of Medication.kind

Issue request:
FHIR-8023 was a Published/Persuasive DSTU1 Pharmacy change request asking why Medication.kind was included when the distinction appeared available through Medication.code and/or Medication.package. The approved resolution agreed with the commenter and required removing Medication.kind.

Initial application:
The issue was applied in 2015 by commit c0a29b9d65d1d1443069140021a847b4c2b31113, whose subject says it removed Medication.kind from the resource definition and examples and updated the introduction text. The patch removed the MedicationKind binding, the Medication.kind data element, example <kind> entries, and obsolete explanatory prose. A later pickaxe search found no Medication.kind reintroduction after that application.

Additional context:
Medication is in the current build scope through the active source/fhir.ini [resources] entry. The current source/medication/structuredefinition-Medication.xml element list contains Medication, identifier, code, status, doseForm, packageSize, ingredient, instance, and definition paths, but no Medication.kind element. Current non-archive Medication examples also have no <kind> element. Later Medication product/package discussion in FHIR-12396 was resolved no-change because the requirements had moved into MedicationKnowledge, and FHIR-6225 was a retracted profiling question; neither reverses FHIR-8023. Zulip and Confluence searches found no direct FHIR-8023 discussion or conflicting work-group record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current Medication source already reflects the published FHIR-8023 decision by omitting Medication.kind and the old kind-specific introduction/example content.

Recommendation:
Keep this audit commit as-is. No core FHIR source follow-up is needed for FHIR-8023 unless the Pharmacy work group separately decides to reintroduce an explicit Medication kind/classification concept in a future issue.
