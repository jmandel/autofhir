FHIR-51498: Audit Device compartment updates

Issue request:
FHIR-51498 was an Applied/Persuasive FHIR-core OO change request to ensure Device-related resources were listed in appropriate compartments by updating source/compartments.xml. The final Jira comments and QA record narrowed the requested source changes to DeviceAssociation in RelatedPerson and Practitioner compartments, DeviceRequest in the Device compartment, and DeviceDispense in the Patient and Practitioner compartments.

Initial application:
The issue was initially applied in bd81961aef (PR #3604), which updated source/compartments.xml for DeviceAssociation, DeviceDispense, DeviceRequest, and DeviceUsage. A follow-up commit c40eb58839 fixed a spacing problem in the search-parameter text. No prior Issue-Reconcile-Key audit commit for FHIR-51498 was present on the combined branch.

Additional context:
Later applied DeviceAssociation work changed the relevant search parameters. FHIR-46973 added a DeviceAssociation patient search parameter and kept subject/operator compartment logic, then FHIR-47604 removed the operator backbone and operator search parameter, added DeviceAssociation.focus, and explicitly replaced operator-based compartment membership with subject/focus membership. FHIR-47931 was applied in the same PR as supporting DeviceAssociation boundaries text. Separately, commit 3b38b80cf2 removed DeviceDispense and DeviceUsage from the active core resource set and the core compartment spreadsheet, while source/device-module.html now links those resources to the OO incubator IG.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source/compartments.xml already has DeviceAssociation in the RelatedPerson and Practitioner compartments via subject | focus, has DeviceRequest in the Device compartment via subject | requester | performer | device, and no longer lists DeviceDispense or DeviceUsage because they are not active core resources in source/fhir.ini. Reintroducing operator or adding inactive-resource compartment rows would contradict later applied source decisions.

Recommendation:
Keep this no-change audit commit as-is for core FHIR. If DeviceDispense or DeviceUsage require compartment changes, handle them in the OO incubator/current external artifact or in a future core reintroduction decision; do not re-add them to core source/compartments.xml while they remain outside the active core resource list.
