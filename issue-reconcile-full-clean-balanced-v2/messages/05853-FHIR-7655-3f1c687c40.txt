FHIR-7655: Align QUICK Encounter request names

Issue request:
FHIR-7655 was a Published PA change request, resolved Persuasive with Modification for DSTU1. It asked to rename Encounter.incomingReferralRequest to Encounter.incomingReferral, change the description/short label from "Incoming Referral Request" to "The Referral that initiated this encounter", and rename Encounter.fulfills to Encounter.appointment.

Initial application:
The issue was explicitly applied in source history by dddc6a474980c75cca14a00e8f0371225f7eb748, "Tracker# 7655 Update encounter property names", which changed the then-authoritative Encounter spreadsheet from incomingReferralRequest to incomingReferral and from fulfills to appointment. The current active Encounter StructureDefinition no longer contains either obsolete element name.

Additional context:
Later PA decisions changed the current representation without reversing FHIR-7655: FHIR-13195 renamed Encounter/Appointment.incomingReferral to basedOn for consistency with generalized request handling, and FHIR-15108 made Encounter.appointment repeatable. Both later issues are already represented on the combined branch, so this commit does not decide them again. Encounter and Library are active resources in source/fhir.ini, and publish.ini copies the Library model-definition content XML files into the build; the Library examples page links the QUICK model information file as CQL-to-ELM model metadata.

AutoFHIR reconciliation:
Updated source/library/library-quick-model-definition-content.xml so QUICK.Encounter uses basedOn instead of incomingReferralRequest and appointment instead of fulfills, with appointment modeled as a list to match the current Encounter.appointment cardinality. No authoritative Encounter StructureDefinition change was needed because the current resource source already reflects FHIR-7655 plus the later basedOn/cardinality decisions.

Recommendation:
Keep this source fix. The edited Library model-info example is current build input and should not expose stale Encounter element names; future regeneration of the QUICK model should preserve the current Encounter.basedOn and repeating Encounter.appointment shape.
