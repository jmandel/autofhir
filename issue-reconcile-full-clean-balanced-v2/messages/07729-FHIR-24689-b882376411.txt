FHIR-24689 is a Published/Persuasive FHIR-core technical correction against ElementDefinition.mustSupport. It reported typos in the Meaning if Missing description for mustSupport, including the misspelled differential/from/Note/mustSupport wording and missing punctuation in the sentence describing inherited mustSupport values.

Initial application:

A separate AutoFHIR reconcile commit for FHIR-34382 already added the missing final period on the combined branch.

Additional context:
source/fhir.ini actively lists ElementDefinition as a current datatype/type page and normative artifact, so source/datatypes/elementdefinition.xml is in build scope. Current source no longer has the reported differentil/fro/Not/mustSuppot misspellings, but the same Meaning if Missing sentence still said "if mustSupport is not specific in either the differential or the snapshot", which is a remaining grammar typo in the active authoritative spreadsheet source. FHIR-24673 and FHIR-34382 are the same typo family; FHIR-34382 is already represented on the combined branch, while FHIR-24673 can be audited separately.

AutoFHIR reconciliation:
Changed the ElementDefinition.mustSupport Meaning if Missing text from "mustSupport is not specific" to "mustSupport is not specified" in source/datatypes/elementdefinition.xml. No other wording was changed.

Recommendation:
Keep this commit as-is. It finishes the remaining typo correction in the active ElementDefinition source without reopening adjacent mustSupport/obligations wording that later issues already adjusted.
