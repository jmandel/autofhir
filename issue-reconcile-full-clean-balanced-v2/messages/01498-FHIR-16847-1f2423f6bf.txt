FHIR-16847: Audit Measure.guidance clarification

Issue request:
FHIR-16847 is Published/Persuasive for the STU3 Measure resource. It asked CQI to clarify the Measure.guidance requirements text because "logic of the measure" was ambiguous and could be read as referring to logic contained in a Library resource.

Initial application:
The Jira comment records SVN 14860. The git-svn commit 3c2695705efcccfadfa96f5499d5e0d494cbb5da, titled "GF#16847: Clarified meaning of logic in the guidance element description," applied that request by changing the Measure.guidance requirements text in source/measure/measure-spreadsheet.xml from "the logic of the measure" to "the population criteria of the measure." That historical source input has since been refactored away, but the clarified wording survived in the current Measure source.

Additional context:
Measure is an active current-build resource in source/fhir.ini. The current authoritative source no longer defines a Measure.guidance element because later Applied/Persuasive issue FHIR-55437 removed the deprecated element; that related issue already has a separate Issue-Reconcile-Key audit on the combined branch. The remaining guidance-related current text is on Measure.usage and uses the clarified "population criteria of the measure" wording rather than the ambiguous Library/logic wording. Zulip and Confluence searches found no community evidence that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The original ambiguity was applied in SVN/git history, the current active source does not contain the old "logic of the measure" wording, and the specific deprecated element named by the STU3 issue has been removed from current conformance source by a later applied decision.

Recommendation:
Keep this audit commit as-is. No further core source work is needed for FHIR-16847; any review of the later Measure.guidance removal belongs to the already-published FHIR-55437 audit rather than this STU3 clarification.
