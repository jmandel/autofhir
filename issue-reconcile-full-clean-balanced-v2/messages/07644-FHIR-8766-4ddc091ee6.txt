FHIR-8766: Audit ValueSet validate-code url selector

Issue request:
FHIR-8766 was a Published/Persuasive with Modification vocab change request for DSTU1 ValueSet/$validate-code. It asked to validate a code against a value set using the value set's canonical URL rather than requiring a server-local ValueSet.id, and the approved resolution was to rename the identifier search/operation parameter to url.

Initial application:
The Jira comment records svn revision 10430. In git-svn history, commit 7ca9d3d32bf8b9309428d5bcfc20a8b3a6e9cb38 is that revision and changed the old ValueSet spreadsheet from validate-code.identifier to validate-code.url with canonical URL documentation. It also changed adjacent ValueSet expansion narrative from $expand$identifier=[compose.import] to $expand$url=[compose.include.valueSet].

Additional context:
FHIR-8877, decided by the previous AutoFHIR commit, is the earlier same-family issue that clarified the old identifier wording should point to ValueSet.url rather than ValueSet.identifier. FHIR-13946 and FHIR-14355 are later ValueSet $validate-code wording corrections already represented on the combined branch. The current build-scoped ValueSet $validate-code OperationDefinition defines the url input parameter and the code input parameter, so the issue's code-plus-ValueSet.url use case is represented by current source.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active ValueSet $validate-code operation already uses url for the value set selector, includes the code input parameter, and current ValueSet source no longer contains validate-code.identifier, expand.identifier, $expand$identifier, or the obsolete "identifier"/"valueset" selector wording.

Recommendation:
Keep this empty audit commit as-is. No follow-up is needed for FHIR-8766 unless a new work group decision changes ValueSet $validate-code behavior for unresolved or implicit value set URLs.
