FHIR-14094: Audit dateTime schema regex reconciliation

Issue request:
FHIR-14094 was a Published/Persuasive STU3 correction for FHIR-core datatypes. It reported that fhir-base.xsd allowed dateTime values with hours and minutes but no time zone, while the datatype page said a time zone SHALL be populated when hours and minutes are specified. The requested resolution was to correct the validation schema to use the same regex as the spec and verify that it only forces a time zone when hours and minutes are specified.

Initial application:
No commit in the current git history explicitly names FHIR-14094. The Jira comment says the change had already happened under a different task, and the surrounding Oct. 30, 2017 datatype work matches that: commit f2b3f28b2ff336fda895e176b2bdb2690ade688b for FHIR-13684/FHIR-13685 updated the primitive dateTime regex to require the offset in the time branch, and commit ffb483245175ff499a837bc605277a047ffa7b12 for FHIR-12959/FHIR-12960 added primitive regex publication and validation work.

Additional context:
The current build no longer has a checked-in fhir-base.xsd source file to edit directly; the active primitive datatype source is source/datatypes/primitives.xml, with source/datatypes.html rendering the dateTime regex through the [%regex dateTime%] placeholder and source/fhir.ini routing primitive types to datatypes. Later final decisions changed the intended regex family: FHIR-34355 allowed dateTime partial-date work to revisit the offset position, FHIR-38735 corrected date-only dateTime handling and confirmed that time zone is only permitted with full time, and FHIR-52878 approved the current R6 regex shape while the linked Zulip discussion records that regexes do not need to enforce every datatype rule. A prior AutoFHIR FHIR-38735 commit already fixed the stale primitive comment so it now says UTC offset is allowed only when a time is specified.

AutoFHIR reconciliation:
Made no source change. The current source already reflects the later approved dateTime regex family: it rejects offsets on date-only and partial-date values, allows full dateTime values with or without an offset, and leaves the normative SHALL about offset presence in the datatype narrative. Re-tightening the regex for FHIR-14094 would undo the later FHIR-52878-approved pattern rather than reconcile the current specification.

Recommendation:
Keep this audit commit as-is. If the work group wants the current schema regex to enforce the narrative SHALL for full dateTime offsets, that should be raised as a new current-version tracker or a reconsideration of the FHIR-52878/related dateTime decisions, not applied retroactively under the STU3 FHIR-14094 audit.
