FHIR-7589: Audit Condition body site model

Issue request:
FHIR-7589 was a Published/Persuasive with Modification DSTU1 Patient Care issue asking to simplify Condition.location.site[x], which was a choice between CodeableConcept and BodySite reference, because a simple body-site code with laterality support was preferred over making BodySite reference part of the base element.

Initial application:
The issue was applied by git commit 35ae82d571, which explicitly mentions #7589 and changed Condition.location/site[x] into Condition.bodySite as a CodeableConcept while updating Condition examples. No current source still contains the old Condition.location.site[x] or siteCodeableConcept model.

Additional context:
Related 2015 Condition issues FHIR-7629 and FHIR-8474 were applied in the same historical commit. Later FHIR-31027 kept the element named Condition.bodySite and clarified the BodyStructure extension guidance, and later Applied FHIR-39630 intentionally added Condition.bodyStructure 0..1 Reference(BodyStructure) with an invariant prohibiting simultaneous use with Condition.bodySite. The FHIR Extension Pack still carries the bodySite BodyStructure-reference extension for Condition.bodySite, so the extension mechanism remains available outside core.

AutoFHIR reconciliation:
No source change was made. The active current Condition source has Condition.bodySite as 0..* CodeableConcept, includes laterality in the BodySite binding description, removes the old standard-extension comment, and has the later Condition.bodyStructure element only because a newer final Jira decision added it explicitly. The active fhir.ini resource list includes Condition, so the checked source is in build scope.

Recommendation:
Keep this audit commit as-is. FHIR-7589 needs no current core source change; any future edits to BodyStructure/bodySite cardinality or guidance should be handled under newer tickets such as FHIR-39630, FHIR-50083, or FHIR-54843 rather than reopening this DSTU1 simplification.
