FHIR-32916: Audit AllergyIntolerance recorder Organization support

Issue request:
FHIR-32916 was a Published/Persuasive R5 Patient Care change request to allow AllergyIntolerance.recorder to reference Organization, covering cases where only the recording hospital or clinic is known.

Initial application:
The issue was initially applied in git commit a1529782122, which added the J#32916 committee note and the Organization targetProfile to source/allergyintolerance/structuredefinition-AllergyIntolerance.xml. A later R6 refactor commit, ed99dff4908 for FHIR-39513 and FHIR-44517, restored AllergyIntolerance.recorder after the temporary participant model and preserved Organization in the restored target profiles.

Additional context:
AllergyIntolerance is active in source/fhir.ini, so source/allergyintolerance/structuredefinition-AllergyIntolerance.xml is current build scope. The current recorder element still carries J#32916 and includes Organization alongside Practitioner, PractitionerRole, Patient, and RelatedPerson. Later applied clarification FHIR-48804 changed the recorder definition wording to say the recorder takes responsibility for accurately recording the content, but it did not remove Organization or otherwise reverse FHIR-32916. The original Zulip discussion and Patient Care minutes support the same use case and reveal no conflicting later community decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active StructureDefinition already permits Organization for AllergyIntolerance.recorder, and the apparently person-oriented definition wording is governed by the separate later FHIR-48804 clarification rather than by an incomplete application of FHIR-32916.

Recommendation:
Keep this audit commit as-is. No FHIR-32916 source fix is needed; any future concern about whether the recorder definition should say party or entity instead of individual should be handled as a separate Patient Care wording decision, not as this Organization target-profile reconciliation.
