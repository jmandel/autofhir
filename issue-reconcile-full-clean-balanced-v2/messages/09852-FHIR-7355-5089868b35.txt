FHIR-7355: Audit common properties clarification

Issue request:
FHIR-7355 was Published/Persuasive for DSTU1 section 1.10.2, asking to replace confusing wording that said all resources "have" optional or mandatory identity, metadata, language, and implicitRules properties with wording that made clear these elements may be absent.

Initial application:
The issue was applied in git commit a6f3e671994f186f7c9902f033e8166e385937de, matching the Jira comment's svn revision 6431. That commit changed source/resource/resource-introduction.xml from "All resources have the following optional or mandatory elements and properties" to "The following optional elements and properties are defined for all resources," and also softened the following DomainResource sentence from "contain" to "can contain."

Additional context:
The Resource infrastructure entry remains active in source/fhir.ini, so source/resource/resource-introduction.xml and source/resource/structuredefinition-Resource.xml are current build inputs. The current Resource StructureDefinition gives Resource.id, Resource.meta, Resource.implicitRules, and Resource.language cardinality 0..1, and no later Jira, Zulip, or Confluence evidence found in this bounded search changes the 2015 clarification.

AutoFHIR reconciliation:
No source change was made. The current source already removes the misleading "all resources have" phrasing and preserves the intended clarification that the common Resource elements are defined for all resource types but optional on instances unless constrained elsewhere.

Recommendation:
Keep this empty audit commit as-is. Further wording churn would be editorial and risks duplicating the same optionality rule already expressed by the corrected narrative and the authoritative Resource element cardinalities.
