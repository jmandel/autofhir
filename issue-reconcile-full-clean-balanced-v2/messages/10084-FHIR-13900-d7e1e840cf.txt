FHIR-13900: Audit Questionnaire definition guidance

Issue request:
FHIR-13900 was Published/Persuasive with Modification for STU3 and asked to resolve the apparent conflict between Questionnaire.item.definition saying values such as type could be inferred from an ElementDefinition and Questionnaire.item.type being mandatory. The accepted resolution was to clarify inference language so that type, required, and similar values can still be inferred or compared but required Questionnaire elements must be specified on the Questionnaire instance.

Initial application:
The issue was applied by a55b9bbe29675c4946a1b1f41615c45f8567e12e, which changed source/questionnaire/questionnaire-notes.xml to state that information on the Questionnaire overrides the definition and that some elements are always required to be populated so invariants can be enforced. No prior Issue-Reconcile-Key commit for FHIR-13900 was present on the combined branch.

Additional context:
Questionnaire is in the active resource list in source/fhir.ini. Later Questionnaire work, especially FHIR-28305, removed item.type from the derived-values list and added the current explicit statement that Questionnaire.item.type corresponds to ElementDefinition.type but is mandatory and cannot be populated from item.definition. FHIR-28305 is already represented on the combined branch, so this commit does not duplicate that issue. Current source also keeps Questionnaire.item.type at 1..1 and its comment says it must be present and should align with ElementDefinition.type when a definition is referenced. Community searches found no direct FHIR-13900 discussion beyond commit/tracker notifications; the later Zulip thread for FHIR-28305 confirms the same interpretation.

AutoFHIR reconciliation:
This is an empty no-change audit commit. The active Questionnaire source already conveys the FHIR-13900 resolution: item.definition may support derived or corresponding values, but mandatory Questionnaire elements, including item.type, remain present on the Questionnaire and should align with the referenced ElementDefinition. No source edit is needed.

Recommendation:
Keep this audit commit as-is. Future work should avoid re-adding item.type to the automatically derived-values list; any broader behavior around definition-driven Questionnaire processing should be handled through the already-applied FHIR-28305/SDC guidance rather than by changing FHIR-13900.
