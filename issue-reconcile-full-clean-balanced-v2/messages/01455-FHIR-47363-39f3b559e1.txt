FHIR-47363: Audit canonical version clarification

Issue request:
FHIR-47363 was an Applied/Persuasive FHIR-I change request for R6 asking whether CanonicalResource-style version values, raised from SubscriptionTopic.version wording, are tied to canonical URLs, identifiers, or both. The accepted resolution was to update CanonicalResource text to indicate that the element represents the canonical version for consistency.

Initial application:
The issue was applied before this reconciliation by git commit a0e14c3b8eec39d4c876488bf58b842423be1b0b, included in HL7/fhir pull request #3967, which changed source/canonicalresource/structuredefinition-CanonicalResource.xml from "Business version" language to "Canonical version" language and expanded the CanonicalResource.version and versionAlgorithm explanations. No earlier Jira-tagged application was found in the inspected history.

Additional context:
CanonicalResource is an active interface in source/fhir.ini, and SubscriptionTopic is an active resource that implements it. The current source defines CanonicalResource.version as the canonical version and explains [url]|[version] canonical references. Some concrete canonical resources, including SubscriptionTopic.version, still use local "Business version" short text, but the final Jira resolution and implementation PR targeted the CanonicalResource definition rather than a vocabulary-wide rewrite across every implementing resource. Confluence minutes record FHIR-47363 in the approved 2025-03-31 FHIR-I block vote, and Zulip searches found only the block-vote announcement and no conflicting substantive discussion.

AutoFHIR reconciliation:
This commit intentionally makes no source change because the current build-scoped CanonicalResource source already reflects the accepted resolution. Broadening this audit into edits across all concrete canonical resources would exceed the applied issue and could create inconsistent resource-specific wording without a separate work-group decision.

Recommendation:
Keep this audit commit as-is. If the work group wants every concrete canonical resource's local version short/definition text to replace "business version" with "canonical version", that should be handled as a separate, explicit terminology-consistency tracker rather than as a late expansion of FHIR-47363.
