FHIR-12386: Audit MedicationDispense workflow event harmonization

Issue request:
FHIR-12386 was a Published/Persuasive Pharmacy change request to harmonize MedicationDispense with the Workflow Event logical model. The Jira resolution says the spreadsheet evaluated all Event logical-model elements, that many would be implemented, and that not every Event element would be added to MedicationDispense.

Initial application:
The issue was applied in git commit 0c976c878b6cfd93e5d5fd478b86506f28c517bc, which is explicitly titled "TR #12386 - Harmonize MedicationDispense with Event logical model". That commit updated MedicationDispense examples from patient/dispenser to subject/performer, adjusted the MedicationDispense compartment entry from patient to subject and performer, and added the preparation status alignment.

Additional context:
MedicationDispense is active in the current build through source/fhir.ini, and the Event logical model is also active. The current MedicationDispense StructureDefinition declares the Workflow Pattern mapping and maps MedicationDispense to Event, including identifier, partOf, status, medication/code, subject, encounter, performer, performer.actor, authorizingPrescription/basedOn, whenHandedOver/occurrence, and note. Later Published Pharmacy work in FHIR-14021 re-aligned MedicationDispense to an updated Event pattern, and FHIR-34000 later renamed statusReason to notPerformedReason; those later decisions explain why current source is not a literal copy of the original 2017 spreadsheet and why some Event-pattern differences remain recorded as mapping exceptions.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source already represents the FHIR-12386 harmonization, and the remaining Event divergences are either explicitly within the Jira resolution's "not all elements" scope or were altered by later final Pharmacy decisions.

Recommendation:
Keep this audit commit as-is. Do not add redundant Event elements or restore older patient/dispenser/statusReason wording under FHIR-12386; any future mapping cleanup should be handled under a current Pharmacy/Workflow tracker that evaluates the current Event pattern, not this DSTU2-era applied issue.
