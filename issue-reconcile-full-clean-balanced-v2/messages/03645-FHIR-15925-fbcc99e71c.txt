FHIR-15925: Audit additional data guidance example

Issue request:
FHIR-15925 was a Published/Persuasive CDS issue from the STU3/QI-Core ballot context. It requested an example warning for cases where decision support could not make a reliable conclusion because required patient data was missing, with the resolution text suggesting a DetectedIssue profile/example for QI-Core.

Initial application:
The issue was applied in core by commit 993f6deef4787c65d3206ac5d8da460a0c634ad4, with follow-up commit 29562deafaf5f66a0cf9273c94719acf7bda7c40 correcting the example list entry. PR HL7/fhir#2834 merged those changes and identifies FHIR-15925 as adding a GuidanceResponse example that requests additional data.

Additional context:
GuidanceResponse and DetectedIssue are both active current-build resources. The current GuidanceResponse definition has data-required/data-requested statuses and a dataRequirement element for describing missing or desired data. The current DetectedIssue boundaries say insufficient data and other business-rule failures are not DetectedIssue clinical issues and should be conveyed with OperationOutcome; later FHIR-39407 also records that GuidanceResponse already handles completion/additional-data status rather than adding a DetectedIssue completionStatus element.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active core source already includes GuidanceResponse/additional-data-example in the GuidanceResponse examples list, and the DetectedIssue page is not missing a current-spec rule because present guidance routes insufficient-data cases away from DetectedIssue.

Recommendation:
Keep this audit commit as-is. Do not add a redundant DetectedIssue example to core unless the CDS work group later reverses the current boundary between DetectedIssue clinical issues and GuidanceResponse/OperationOutcome insufficient-data responses; any QI-Core profile work would belong outside this core checkout.
