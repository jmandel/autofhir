FHIR-12955: Audit canonical URL URI wording

Issue request:
FHIR-12955 was Published/Persuasive with Modification for DSTU2 and asked to clarify that SearchParameter.url and parallel canonical url elements identify artifacts with an absolute URI, not necessarily a resolvable network locator. The resolution directed all url element definitions to use absolute URI wording and move the version/resolution guidance into comments, including that a URL form is desired to resolve but cannot be relied on.

Initial application:
The change was applied in git-svn commit c95931bd5ead4f3f75c935595926ef8494ae05d8, whose subject is "#12955 - fix comments about URL". That commit updated the MetadataResource url template used at the time, removing the redundant "SHALL be a URI"/major-version definition wording and placing the version guidance into comments.

Additional context:
FHIR-13699 raised the same URL-vs-URI problem for CodeSystem.url and was resolved No Change with "see #12955" after the linked Zulip thread confirmed canonical URLs can be URNs and need not reflect the current server location. Later source refactors moved the wording from MetadataResource into the active CanonicalResource, Shareable, and resource-specific StructureDefinition sources; later history also added meta.source guidance and fixed wording defects such as FHIR-28183. The current build scope includes searchparameter in source/fhir.ini, and CanonicalResource/MetadataResource interfaces are active.

AutoFHIR reconciliation:
This audit made no source change. The active SearchParameter.url definition now says it is an absolute URI/canonical identifier, the url type is uri, and the comment explains that a resource may no longer be found at the stated url and that meta.source can identify the current master source. The active CanonicalResource.url interface and other checked canonical resources use the same URI/canonical wording, and a source search found no active canonical url definition still using the old "SHALL be a URL" rule.

Recommendation:
Keep this empty no-change audit commit as-is. The current source already preserves the implementer-facing distinction FHIR-12955 requested; adding the original 2017 sentence verbatim would duplicate and potentially conflict with the later canonical-resource wording.
