FHIR-10556: Audit DataAbsentReason infinity codes

Issue request:
FHIR-10556 was a Published/Persuasive with Modification OO change request from the DSTU2 cycle asking for additional DataAbsentReason options for device-reported special numeric values. The final applied request was to add PINF and NINF support to DataAbsentReason; the broader OTH/ascomp suggestions in the description were not the final applied core change.

Initial application:
The issue was applied before this reconciliation. Commit a113c29c06d93deff51d451695059344be601be5 added v3 NullFlavor NINF/PINF concepts to the Observation value-absent-reason value set, and commit df58b619135a2e170435e0af16e61b82b2280152 (svn revision 13066, cited by the Jira) added ninf/pinf entries to the FHIR data-absent-reason terminology content.

Additional context:
Later terminology review refined the pre-applied approach. FHIR-13547 recorded the Vocab concern about adding raw v3 NINF/PINF as DataAbsentReason codes. FHIR-15567 was then Published/Persuasive with Modification and changed the DataAbsentReason codes to FHIR-readable not-a-number, negative-infinity, and positive-infinity under error, while preserving NullFlavor NINF/PINF mappings and adding the NINF/PINF abbreviations to the displays. Core terminology CodeSystem content later moved to THO/UTG, leaving current core with the DataAbsentReason ValueSet wrapper and Observation bindings.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core source has an active DataAbsentReason ValueSet that includes all codes from http://terminology.hl7.org/CodeSystem/data-absent-reason, and Observation.dataAbsentReason plus Observation.component.dataAbsentReason bind to that ValueSet. The current THO DataAbsentReason CodeSystem includes negative-infinity and positive-infinity with displays "Negative Infinity (NINF)" and "Positive Infinity (PINF)". Reintroducing literal PINF/NINF codes or a core-owned CodeSystem would conflict with FHIR-15567 and the THO migration.

Recommendation:
Keep this audit commit as-is. If a future work group wants literal wire codes PINF/NINF rather than the current negative-infinity/positive-infinity codes with NINF/PINF display aliases, that should be handled as a new terminology/THO policy decision rather than as a missing core-source application of FHIR-10556.
