FHIR-15824: Audit workflow relatedArtifact ownership

Issue request:
FHIR-15824 was a Published/Persuasive OO change request asking for a standard relatedArtifact extension on Observation and DiagnosticReport. The final resolution was to create an extension using the RelatedArtifact datatype and to clarify that relatedArtifact is for knowledge resources supporting the instance, while supportingInfo is for patient-record resources used in creating or interpreting the instance.

Initial application:
The original core source application appears in git commit eb9d0942c0, titled "GF#15824 (new extension), GF#15599, GF#14450 pattern updates." That commit added a relatedArtifact row for DiagnosticReport and Observation to the event extension spreadsheet, with cardinality 0..* and type RelatedArtifact, and included the supportingInfo boundary language.

Additional context:
Core later refactored extension source and then removed extension definitions from the R5 core source in dd468d4f17. Current core source/fhir.ini still lists DiagnosticReport and Observation as active OO resources, but searching current core source finds workflow-relatedArtifact only in source/oids.ini. The authoritative StructureDefinition now lives in the FHIR Extension Pack, where workflow-relatedArtifact currently lists DiagnosticReport and Observation as contexts and carries the supportingInfo contrast. FHIR-39113 later expanded the same extension to Observation.component and is already represented on the combined branch.
