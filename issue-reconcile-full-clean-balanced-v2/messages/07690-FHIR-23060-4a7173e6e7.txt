FHIR-23060: Audit current-build comparison footer

Issue request:
FHIR-23060 is a Published/Persuasive FHIR-core technical correction from fhir-i, raised in STU3 and applied for R5. It asked for the Current Build bottom menu to offer "Compare to R4" rather than "Compare to R3" because R4 had become the current release.

Initial application:
The Jira snapshot includes an October 2019 comment saying the issue already looked fixed. Source history confirms the fix: commit 9baff334d6331ff8d69a1c3ae2fcab27e1572811 changed source/newfooter.html on 2019-08-08 from a services.w3.org link labeled "Compare to R3" against the STU3 tree to a link labeled "Compare to R4" against the R4 tree. The footer template later moved unchanged to tools/templates/newfooter.html in commit 24e6675dcd8f9f6dbd68745fbcfcafc9b32443b2.

Additional context:
The originating Zulip thread in #conformance records Peter Jordan proposing the R4 comparison link, Grahame Grieve agreeing, and Peter filing GForge/Jira 23060. FHIR-I minutes on 2019-11-04 list GF 23060 as a typo that was auto-approved. Later footer work retargeted comparison links for newer release cycles and now exposes Compare to R4, Compare to R5, and Compare to Last Ballot links through the active footer template. Related footer comparison audits for FHIR-34058 and FHIR-41288 are already represented on the combined branch and do not require another commit here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active footer template already includes a "Compare to R4" link, contains no "Compare to R3" link, and is included by the FHIR-core diff pages that remain in source/hierarchy.xml. The current source therefore preserves the issue's requested behavior in the current build.

Recommendation:
Keep this no-change audit commit as-is. No FHIR core source follow-up is recommended for FHIR-23060 unless a future release-cycle policy chooses different comparison targets for the footer.
