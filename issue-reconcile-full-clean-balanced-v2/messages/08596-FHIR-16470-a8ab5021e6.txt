FHIR-16470: Audit resource identity re-identification wording

Issue request:
FHIR-16470 was a Published/Persuasive FHIR-core clarification for the Managing Resource Identity page. It asked that the page stop using "Re-Identification" for assigning a new logical resource id, because that phrase has a distinct meaning in de-identification practice. The approved resolution was to replace "re-identification" in the managing-resource-identifiers section with wording such as "assign a new identifier" without introducing a new term.

Initial application:
The issue was applied in git commit 34e7bac54262a4da1fbbeb44bf09cc683757dd80, which matches the Jira comment's SVN revision 14233. That commit changed source/managing.html by renaming "Copying Resources and Re-identification" to "Copying Resources and Assigning new Ids" and replacing the targeted uses of re-identification with new-id/new-logical-id wording.

Additional context:
source/hierarchy.xml actively includes source/managing.html as the Managing Resource Identity page, so this is current build input. Current source/managing.html still carries the intended assigned-new-id wording in the targeted section. Remaining current uses of re-identification are outside this issue's target and are in de-identification/security/provenance contexts, where the Jira description explicitly recognized the term has its ordinary privacy meaning. Searches found no later Jira, Zulip, or Confluence evidence changing the original resolution.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build source already implements the requested terminology change in the relevant Managing Resource Identity section, and changing the remaining de-identification-context uses would be outside the approved request.

Recommendation:
Keep this no-change audit commit as-is. No FHIR-core follow-up is needed for FHIR-16470 unless the work group separately chooses to revisit unrelated privacy/de-identification wording.
