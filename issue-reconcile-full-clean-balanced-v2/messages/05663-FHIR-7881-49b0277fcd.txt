FHIR-7881: Audit Encounter account coverage linkage

Issue request:
FHIR-7881 was a Published/Persuasive Patient Administration FHIR-core Encounter change request raised against DSTU1. It asked to add Coverage, or at least financial class, to Encounter for registration and billing cases such as workers' compensation. The approved resolution was to add a multi-cardinality Encounter reference to Account, add an EpisodeOfCare reference to Account, and also include the Account-to-Coverage reference.

Initial application:
The historical Jira-tagged commit d79e721591063158c7da0b6ec54d09b1dd3fac91 ("Tracker 10247 7881") added Encounter.account 0..* Reference(Account) and EpisodeOfCare.account 0..* Reference(Account) to the spreadsheet-era source. The Account-to-Coverage leg was then applied in the tightly related FHIR-9234 commit 519a0de34da28045c1031f016cb4540e9ca0f3be ("Tracker# 9234"). Later source refactors preserved these links in the current StructureDefinition XML files.

Additional context:
Encounter, EpisodeOfCare, and Account are active resources in source/fhir.ini. FHIR-9234 is the same payment/coverage change family and explicitly says it is related to 7881. FHIR-12658 later refined the Account.coverage representation from a direct repeating Coverage reference to a repeating BackboneElement with Account.coverage.coverage Reference(Coverage) and Account.coverage.priority; the current combined branch already contains the FHIR-12658 reconciliation. Direct Zulip and Confluence searches found no community decision that conflicts with the Jira/source history.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already carries the approved model: Encounter.account is 0..* Reference(Account), EpisodeOfCare.account is 0..* Reference(Account), and Account.coverage contains a nested 1..1 Reference(Coverage) with account-specific priority guidance.

Recommendation:
Keep this audit commit as-is. The current FHIR core source satisfies FHIR-7881 through the Account-mediated billing/coverage model, and changing Encounter to reference Coverage or financial class directly would contradict the approved resolution and later Account coverage decisions.
