FHIR-18239: Audit PlanDefinition dynamicValue path rules

Issue request:
FHIR-18239 was a Published/Persuasive CDS issue for STU3 PlanDefinition. It requested clarification that PlanDefinition.action.dynamicValue.path follows the same path-resolution rules as DataRequirement path elements, without importing DataRequirement's result-type restriction.

Initial application:
The issue was applied by commit 7eb269c14f46ee1eaa02d52d6b7609a7bbbc4371, which updated the historical PlanDefinition spreadsheet source for PlanDefinition.action.dynamicValue.path. That application added the FHIRPath-resolvable target-type rule, identifiers/constant-indexers/function-subset restriction, and Simple FHIRPath reference. The later source rework to structuredefinition-PlanDefinition.xml preserved that applied wording.

Additional context:
PlanDefinition is active in the current build through source/fhir.ini. The sibling ActivityDefinition issue FHIR-18237 was applied the same day with matching wording for ActivityDefinition.dynamicValue.path. Later FHIR-19360 added the adjacent %action guidance for PlanDefinition dynamicValue paths and has already been audited on the combined branch. Current DataRequirement path definitions have evolved to point at the Simple FHIRPath profile and explicit type restrictions where relevant; PlanDefinition.action.dynamicValue.path already has the Simple FHIRPath/path-shape rule and correctly does not add a DataRequirement result-type restriction.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active PlanDefinition StructureDefinition already states that the path SHALL be a FHIRPath resolvable on the target type, consists only of identifiers, constant indexers, and a restricted function subset, and may use qualifiers and indexers with the Simple FHIRPath Profile for full details.

Recommendation:
Keep this no-change audit commit. No follow-up core source work is needed for FHIR-18239 unless the CDS work group opens a separate issue to revise the broader PlanDefinition/RequestOrchestration dynamicValue target semantics.
