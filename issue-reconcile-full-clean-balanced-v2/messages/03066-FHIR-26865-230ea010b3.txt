FHIR-26865: Audit ResearchStudy title handling

Issue request:
FHIR-26865 was a Published/Persuasive R5 BR&R change request asking for ResearchStudy.title to support multiple study titles by changing the single string title into a repeating structure with name/value and type so short, long, scientific, and other title use cases could be represented.

Initial application:
No source commit was found that explicitly mentions FHIR-26865. The Jira resolution states that the request was dealt with under FHIR-31604, and commit d5448ea900e832422a9dfa5dcaea0cd8cb30bb16 implemented FHIR-31604 by adding ResearchStudy.label 0..* with type and value under the active ResearchStudy structure while retaining a singular ResearchStudy.title.

Additional context:
ResearchStudy is active in source/fhir.ini, so source/researchstudy/structuredefinition-ResearchStudy.xml is current build-scope source. Later Jira decisions confirm that the current model is intentional: FHIR-31901 was retracted after the editor explained that ResearchStudy.label supports multiple names; FHIR-32312/FHIR-32975 refined the shared TitleType values used by ResearchStudy.label.type; FHIR-37730 later approved the current human-readable wording for ResearchStudy.title; and FHIR-51195 added ResearchStudy.label.language for translated titles. The 2020 BRR minutes show the original concern about multiple and bilingual titles, but no discovered Zulip or Confluence evidence conflicts with the later Jira/source trail.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already provides the required multi-title capability through ResearchStudy.label 0..* with a typed value and language support, while preserving ResearchStudy.title as the single human-readable display title approved by later R5 maintenance.

Recommendation:
Keep this audit commit as-is. Do not reshape ResearchStudy.title for FHIR-26865; any future desire to add title status/date metadata, require label.value, or change the value datatype should be raised as a new BR&R tracker because those details were not carried forward as the final applied resolution for this issue.
