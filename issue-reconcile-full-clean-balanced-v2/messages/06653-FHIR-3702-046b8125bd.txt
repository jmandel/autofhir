FHIR-3702: Audit Encounter subject supersession

Issue request:
FHIR-3702 was a Published/Persuasive DSTU1 Patient Administration request to rename Encounter.subject to Encounter.patient because Encounter.subject then only allowed Patient. Jira records the issue as pre-applied with the element updated to patient.

Initial application:
The historical implementation commit 1b5840ba77 explicitly listed tracker 3702 and changed Encounter examples from <subject> to <patient> while updating the Encounter spreadsheet. That shows the DSTU1 request was applied at the time rather than missed.

Additional context:
FHIR-12630 is the directly superseding Published/Persuasive Encounter issue. It decided that Encounter.patient should be renamed back to Encounter.subject, that the datatype should allow Reference(Patient|Group), and that the patient search parameter should remain while selecting only Patient references. Later Encounter work kept that model: FHIR-20479 clarified that the subject may be related to an encounter even when not present, FHIR-21770 narrowed the patient search parameter description to patients only, and FHIR-34100 kept Patient/Group as subject/participant-related concepts with constraints instead of reverting to a Patient-only element.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Encounter is active in source/fhir.ini, and the current authoritative source defines Encounter.subject with Patient and Group targets, keeps patient as an alias, and provides a patient search parameter over Encounter.subject.where(resolve() is Patient). Renaming the current element to Encounter.patient would undo the later, final PA decisions.

Recommendation:
Keep this audit commit as-is. No current core source fix is needed for FHIR-3702; future work should treat the DSTU1 rename as historically applied and superseded by FHIR-12630 and later Encounter subject clarifications.
