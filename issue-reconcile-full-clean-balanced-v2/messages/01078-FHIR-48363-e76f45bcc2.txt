FHIR-48363: Include resource in SearchParameter type search description

Issue request:
FHIR-48363 was Applied/Persuasive for FHIR-core search after the FHIR-I 2024-10-21 vote. It requested that the invalid Bundle composition and message search parameters stop using reference semantics for FHIRPath expressions that return embedded resources, by defining a resource search-parameter type, documenting its chaining-only semantics, and noting the R5-and-earlier reference-type history.

Initial application:
The issue was applied in commit 554d2c28aa585e14e3bbe39a4291c3bfedff0eb3, merged by PR #3442 as e38498cfac87086a1eb8b1f6d7ae2c17d96328a9. That changed Bundle-composition and Bundle-message to type resource, added the resource code to SearchParamType, updated the SearchParameter, CapabilityStatement, and OperationDefinition type summaries, and added search.html prose for resource parameters.

Additional context:
source/fhir.ini lists bundle, searchparameter, capabilitystatement, and operationdefinition as active resources, so the affected Bundle and SearchParameter source files feed the current build. Current search.html already explains that resource parameters are for chaining through actual embedded resources, that direct tests such as Bundle?composition=Composition/123 are undefined, and that earlier FHIR versions used reference where embedded-resource chaining was intended. FHIR-I minutes for 2024-10-21 confirm the decision to add a resource search-parameter type and document R4/R5 usage. While reviewing current source, the SearchParameter resource's own type search parameter still described only the old code list and omitted resource.

AutoFHIR reconciliation:
Updated source/searchparameter/bundle-SearchParameter-search-params.xml so the SearchParameter-type search-parameter description includes resource alongside the rest of the SearchParamType codes. No other stale old type-list descriptions remained, and the Bundle composition/message search parameters already use type resource.

Recommendation:
Keep this source fix. It completes the already-applied FHIR-48363 change on a build-scoped search-parameter source file without broadening the decision beyond the approved resource search type semantics.
