FHIR-6201: Audit referral creation date migration

Issue request:
FHIR-6201 was a Published/Persuasive with Modification DSTU1 Patient Care change request asking to add a referral creation date for tracking wait time. The accepted resolution added ReferralRequest.date with the definition "date of creation for draft requests and date of activation for active requests."

Initial application:
The issue was applied in historical commit a7344a39aa35eeb8f52cb6d13a8e63eabd6105b2, which added ReferralRequest.date and its date search parameter to the ReferralRequest spreadsheet. Later workflow harmonization moved the same concept to ReferralRequest.authoredOn with createdOn as an alias before ReferralRequest was merged into the current ServiceRequest resource.

Additional context:
ReferralRequest is no longer an active standalone resource in the current build; source/fhir.ini marks ServiceRequest as active and notes that ReferralRequest became ServiceRequest. Current history also maps ReferralRequest.date to ReferralRequest.authoredOn. Later Published Jira decisions in the same request-resource family, especially FHIR-10293, FHIR-11119, FHIR-13196, and FHIR-13867, aligned request resources, merged DiagnosticRequest/ProcedureRequest/ReferralRequest concepts, and renamed the surviving resource to ServiceRequest. Current source defines ServiceRequest.authoredOn and the corresponding ServiceRequest-authored date search parameter.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Reintroducing the original DSTU1 ReferralRequest.date wording into current ServiceRequest would conflict with the later applied request-pattern and merge decisions; the current active source already contains the migrated date element and search parameter.

Recommendation:
Keep this no-change audit commit as-is. No core source follow-up is recommended for FHIR-6201 unless a future work group decision separately changes the semantics of ServiceRequest.authoredOn for draft requests.
