FHIR-31938: Audit removed NCImeta code-system page

Issue request:
FHIR-31938 was a Published/Persuasive FHIR-core vocab change request for R5. It asked to remove the "Using the NCI Metathesaurus with FHIR" page because NCImeta is not a code system and should not be presented as a terminology for Coding.system use.

Initial application:
The issue was applied by commit 2c4f6306e8c47abf78ce9ba3e05bd032bfa17636, which deleted source/ncimeta.html, removed ncimeta.html from publish.ini, removed its hierarchy entry, removed the Metathesaurus filter link from source/valueset/valueset-notes.xml, and removed the local ncimeta page link from source/terminologies-systems.html. Commit 736ccce2005fd2c8c2d20dfe8df948e8c9d586d8 then applied FHIR-37853 and removed the remaining NCI Metathesaurus row from source/terminologies-systems.html as part of making THO authoritative for external terminology identifiers.

Additional context:
FHIR-17778 recorded the related earlier no-change decision that the Using Terminology pages were moving out of core and that the NCIM page would not be moved. Vocabulary minutes on 2022-08-08 record that FHIR-31938 had been resolved during the 2022-08-04 main WG call and had been applied. Current source has no source/ncimeta.html and no remaining build metadata or narrative references to ncimeta.html or NCI Metathesaurus. The only remaining current-source ncimeta URI is in source/medication/valueset-medication-productform.xml, a legacy DAF ValueSet file that is not listed in source/fhir.ini [valuesets], is not referenced by the Medication resource binding, and has no tracked generated publish artifact, so it is not a current built-spec correction for this page-removal issue.

AutoFHIR reconciliation:
This audit commit makes no source change. The current built specification already reflects the FHIR-31938 decision: the NCImeta usage page and code-system listing are gone from the active terminology pages and page metadata.

Recommendation:
Keep this audit commit as-is. If the legacy DAF medication product form ValueSet is ever brought back into build scope, handle its NCImeta system URI under a separate medication/terminology cleanup issue rather than reopening this completed page-removal decision.
