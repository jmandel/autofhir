FHIR-25378: Audit body length units

Issue request:
FHIR-25378 is an Applied/Persuasive FHIR-core Observation change request asking that the vital signs body length UCUM value set not be limited to [in_i], because cm should be available for non-US use. The final resolution says body length is now in Body Height and cm is available for use.

Initial application:
No source commit found in this checkout explicitly mentions FHIR-25378. The relevant source appears to have been pre-applied: git commit de0b55978c41886ebae72aac1a414de21ecec036 introduced source/observation/valueset-ucum-bodylength.xml with both cm and [in_i] in 2016, and later vital signs refactors added the Body Height code value set and binding that include body length in the Body Height profile. This matches the Jira comment that the issue had already been applied in an earlier, unidentified commit.

Additional context:
source/fhir.ini actively lists observation=Observation, so the source/observation artifacts are current build inputs. The current Body Height profile binds Observation.value[x]:valueQuantity to ValueSet/ucum-bodylength with required strength and summarizes the allowed UCUM codes as cm or [in_i]. The Body Height code value set describes body height including body length. OO minutes on 2025-03-07 recorded the issue as pre-applied, noted that cm is available in the value set, and approved that disposition 7-0-1. Related FHIR-34312 later confirmed that only cm and [in_i] were intended for this value set; FHIR-17636 is background for Body Height/body length guidance but was not separately decided here.
