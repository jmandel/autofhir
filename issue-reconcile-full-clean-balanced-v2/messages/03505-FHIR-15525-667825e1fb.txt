FHIR-15525: Audit resolved status clarification

Issue request:
FHIR-15525 was Published with resolution Persuasive with Modification. It asked whether AllergyIntolerance verificationStatus=unconfirmed with clinicalStatus=resolved should be disallowed or clarified, and the accepted Patient Care resolution said no invariant was needed because most allergies are unconfirmed. The requested text change was to update the resolved clinical-status code definition to add that re-exposure could be accidental, unplanned, or outside a clinical setting.

Initial application:
The issue was applied in git commit 722ed5c93f, which added the requested re-exposure sentence to the AllergyIntolerance clinicalStatus/resolved definition in source/allergyintolerance/allergyintolerance-spreadsheet.xml. Later, FHIR-17743 changed clinicalStatus and verificationStatus from primitive code to CodeableConcept and introduced explicit terminology files. FHIR-19634 then refined the AllergyIntolerance clinical-status definitions while preserving the FHIR-15525 re-exposure clarification.

Additional context:
AllergyIntolerance is still an active current-build resource in source/fhir.ini, and the current StructureDefinition binds AllergyIntolerance.clinicalStatus to ValueSet/allergyintolerance-clinical. The current core ValueSet includes the external CodeSystem at http://terminology.hl7.org/CodeSystem/allergyintolerance-clinical rather than carrying the code definitions locally, because commit 5c0494aacf removed UTG terminology content from the core build. The published THO CodeSystem currently defines resolved as clinically reassessed by testing or re-exposure and includes the FHIR-15525 sentence. Direct Zulip and Confluence searches for FHIR-15525 found no conflicting discussion; a later AllergyIntolerance refuted-status Zulip thread led to FHIR-28458, which is already represented on the combined branch and does not reverse this resolved-status clarification.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative current core source points to the external terminology system, and that external terminology already contains the approved clarification. Duplicating the code definition in core narrative would be redundant and could drift from THO.

Recommendation:
Keep this no-change audit commit. If future reviewers find a problem with the resolved code definition itself, it should be handled through HL7 Terminology/UTG or THO maintenance rather than by editing the current core FHIR source checkout.
