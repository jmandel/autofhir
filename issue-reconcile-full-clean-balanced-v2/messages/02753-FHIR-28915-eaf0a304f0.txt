FHIR-28915: Audit administrable route simplification

Issue request:
FHIR-28915 was a Published/Persuasive BR&R change request to simplify MedicinalProductDefinition use for applications that only need the licensed route. It requested a repeatable administrable-product backbone with a coded route and a reference to AdministrableProductDefinition, and its Jira comment clarified that only the route code or the full-resource reference should be used, not both.

Initial application:
The issue was initially applied by git commit 322e216d548de8d681323e54e3082f15f7d8f07b on 2020-10-07, which added MedicinalProductDefinition.administrableProduct to the then-authoritative medicinalproductdefinition spreadsheet and updated examples. That exact backbone was later removed from the active StructureDefinition source by a subsequent published BR&R decision.

Additional context:
FHIR-31859 was Published/Persuasive for R5 and resolved that bidirectional product links should be removed. Commit bb58238af40d7c5d02ee99d5e6fb65ce94c2a49d replaced the FHIR-28915 administrableProduct backbone/reference with direct MedicinalProductDefinition.route. The current active source keeps AdministrableProductDefinition.formOf pointing to MedicinalProductDefinition and includes apd-1, which prevents using AdministrableProductDefinition.routeOfAdministration when the formOf MedicinalProductDefinition already carries route. FHIR-28581 provides broader background: BR&R kept separate medication-definition resources but made common attributes such as routes directly available for smaller use cases.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current source/fhir.ini keeps MedicinalProductDefinition and AdministrableProductDefinition in the active build, and the active StructureDefinition source already preserves the implementer-facing simplification from FHIR-28915 through MedicinalProductDefinition.route while preserving the clarified not-both rule through AdministrableProductDefinition.apd-1. Reintroducing the original MPD-to-APD administrableProduct reference would conflict with the later FHIR-31859 no-bidirectional-links decision.

Recommendation:
Keep this no-change audit as-is. Do not reintroduce MedicinalProductDefinition.administrableProduct unless BR&R explicitly reverses the later FHIR-31859 direct-route/no-bidirectional-link design.
