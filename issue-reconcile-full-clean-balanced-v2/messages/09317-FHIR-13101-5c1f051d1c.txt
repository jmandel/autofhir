FHIR-13101: Audit spreadsheet type versioning support

Issue request:
FHIR-13101 is a Published/Persuasive FHIR-core change request, raised for DSTU2 and applied for DSTU2, asking to add the ability to capture ElementDefinition.type.versioning when declaring types in spreadsheets. The Jira description says this was needed for SDC QuestionnaireResponse.questionnaire and likely other places.

Initial application:
The Jira comment records svn revision 11835. The matching git-svn commit 490badf6923a12bdc3064e398ebe129378780c98, dated 2017-03-24 and titled "#13101 - support for ElementDefinition.type.versioning", changed the old IG spreadsheet parser by adding ReferenceVersionRules storage to TypeRef and by propagating parsed versioning into TypeRefComponent.versioning.

Additional context:
The original in-repository parser path tools/java/org.hl7.fhir.igtools/src/org/hl7/fhir/igtools/spreadsheets no longer exists in the current checkout; later history removed the IG publisher from this repository because it moved to Maven and then cleaned up remaining Java code. The current FHIR source still contains the underlying ElementDefinition.type.versioning model and ReferenceVersionRules values in the active ElementDefinition spreadsheet source, while QuestionnaireResponse is an active resource and its questionnaire element is now canonical(Questionnaire). Current canonical-reference guidance allows the url|version form, so the SDC QuestionnaireResponse use case no longer requires a missing Reference type.versioning declaration in the core source. No current core spreadsheet was found using the historical ~specific/~independent/~either parser syntax, and no Zulip or Confluence discussion was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:

Recommendation:
