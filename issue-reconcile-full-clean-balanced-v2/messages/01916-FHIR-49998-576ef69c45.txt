FHIR-49998: Audit SupplyRequest groupIdentifier externalized

Issue request:
FHIR-49998 was an Applied/Persuasive R6 change request for FHIR-core SupplyRequest. It asked to add SupplyRequest.groupIdentifier so SupplyRequest can be grouped like other Request-pattern resources; OO approved the proposal 5-0-1 on 2025-04-28.

Initial application:
The requested element is present in the legacy core SupplyRequest source. Git history shows commit 101fd3db791ec0148c1a135274883e16e97e158b added SupplyRequest.groupIdentifier as a 0..1 Identifier with the Request.groupIdentifier workflow mapping. A later SupplyRequest workflow-alignment issue, FHIR-43453, also records that SupplyRequest.groupIdentifier was already one of the current mappings and left it in place while adding other Request-pattern mappings.

Additional context:
Current core build scope changed after the Jira application. Commit 3b38b80cf23f9cbb306fab8fcedb293315478c32 removed SupplyRequest, SupplyDelivery, and related OO resources from active source/fhir.ini build/workgroup/FMM/TLA entries and pointed core pages to the OO incubator. Current source/workflow-module.html and source/resourceguide.html link SupplyRequest to https://build.fhir.org/ig/HL7/oo-incubator/StructureDefinition-SupplyRequest.html rather than to a core-built page. The current OO incubator JSON artifact also contains SupplyRequest.groupIdentifier as 0..1 Identifier. FHIR-50429 later kept Request.groupIdentifier as the pattern name and only removed alternate-name aliases from ServiceRequest.requisition, so it does not reverse the SupplyRequest element name.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The requested element is already present in the legacy core source copy, and authoritative current SupplyRequest page work is outside the active FHIR core build. Editing source/supplyrequest in core would not be a current-spec fix.

Recommendation:
Keep this empty external-repo audit commit as-is for core. If OO incubator issues are reconciled separately, retain or verify SupplyRequest.groupIdentifier there; the current continuous-build StructureDefinition already contains it.
