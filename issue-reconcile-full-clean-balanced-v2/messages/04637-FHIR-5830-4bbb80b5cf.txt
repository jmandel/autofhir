FHIR-5830: Audit VisionPrescription status

Issue request:
FHIR-5830 was a Published FHIR-core VisionPrescription change request, resolved Persuasive with Modification, asking to add a status to VisionPrescription comparable to MedicationPrescription status. The final resolution narrowed that request to the fact that status had already been added to all Financial Management resources for STU3.

Initial application:
No git commit on the current repository history explicitly mentions FHIR-5830. The matching historical application is commit ba29243912d2adb5ec994767eb45f6428c9f2bd7, which added VisionPrescription.status, made it 1..1, marked it as a modifier/summary element, added active example statuses, and introduced the initial VisionStatus code list. Commit 5de20f17514c0d3beb1c87841a9ee24d189cb8b2 then consolidated the resource-local VisionStatus binding to the shared Financial Management fm-status value set.

Additional context:
VisionPrescription is still in the current build scope through active source/fhir.ini resource entries, though ownership later moved to OO. The current authoritative StructureDefinition contains VisionPrescription.status as a required 1..1 modifier code bound required to http://hl7.org/fhir/ValueSet/fm-status, and the current resource page source links to the Financial Resource Status Lifecycle. Later FHIR-55281 was resolved No Change/Not Persuasive, confirming that VisionPrescription.status intentionally has no unknown/other escape valve because a prescription is not valid without a discrete state. FHIR-17980 separately added/confirmed status lifecycle documentation links for financial resources including VisionPrescription.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already contains the status element requested by FHIR-5830, uses the shared Financial Management status value set adopted after the initial implementation, carries status through examples/search-parameter surfaces, and has no later final decision requiring a different status model.

Recommendation:
Keep this no-change audit commit as-is. No FHIR-core follow-up is needed for FHIR-5830; any future change to the mandatory required status binding should be handled under a new work-group decision because FHIR-55281 explicitly rejected adding an escape-valve code.
