FHIR-15929: Audit split StructureDefinition snapshot invariant

Issue request:
FHIR-15929 was a Published/Persuasive FHIR-core StructureDefinition issue raised against STU3. It asked for compound invariant 8 on StructureDefinition.snapshot to be split because the base-definition half was not enforced in XPath, with a separate invariant for "All snapshot elements must have a base definition" and XPath for that second rule.

Initial application:
The issue was applied before this reconciliation in git commit 4799a5bd47. That commit explicitly mentioned #15929 and changed source/structuredefinition/structuredefinition-spreadsheet.xml by removing element.all(base.exists()) from sdf-8 and adding sdf-8b on StructureDefinition.snapshot with FHIRPath element.all(base.exists()) and XPath count(f:element) = count(f:element/f:base).

Additional context:
The current build includes StructureDefinition as an active resource in source/fhir.ini. The source was later migrated into source/structuredefinition/structuredefinition-StructureDefinition.xml, where sdf-8 and sdf-8b remain separate constraints and StructureDefinition.snapshot.element carries condition sdf-8b. A later global cleanup, commit 88a1f3d6bd, removed XPath usage from ElementDefinition constraints, so the absence of an XPath expression in the current StructureDefinition source is consistent with current spec source rather than a missed remnant of FHIR-15929. Jira, Zulip, and Confluence searches found no later conflicting decision for this issue.

AutoFHIR reconciliation:
This audit commit makes no source change. The current source already preserves the substantive result of FHIR-15929 by splitting the snapshot type rule from the base-definition rule and enforcing the latter with FHIRPath in sdf-8b. Re-adding XPath-only material would be inconsistent with the later source-wide removal of XPath constraint usage.

Recommendation:
Keep this audit commit as-is. No core FHIR source follow-up is needed unless the work group separately decides to reintroduce XPath constraint expressions.
