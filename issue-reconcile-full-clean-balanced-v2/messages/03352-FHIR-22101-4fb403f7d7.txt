FHIR-22101: Clarify Appointment priority iCalendar mapping

Issue request:
FHIR-22101 is a Published/Persuasive PA change request for Appointment.priority / Request.priority. It asked to change Appointment.priority from unsignedInt 0..1 to CodeableConcept 0..1 bound to ActPriority with example strength, and to update the comments so iCalendar priority is treated as a localization that requires a concept map to allocate the possible numeric value.

Initial application:
Git history shows b29145fb873cb62d180e958f040f791ec733d405 changed Appointment.priority from unsignedInt to CodeableConcept, added the ActPriority example binding, and commented out numeric priority examples. That initial application did not update the old element comment or Appointment notes, leaving pre-change guidance about a CodeableConcept extension and the numeric iCalendar scale in the element definition. Later generated/supporting artifacts copied the stale definition into the Appointment SVG title and Request mapping exception.

Additional context:
PA January 2021 WGM minutes record the same 11-0-0 disposition and explicitly state that the iCal priority would be a localization requiring a ConceptMap. The active source/fhir.ini resource entry includes appointment=Appointment, so source/appointment/structuredefinition-Appointment.xml is the active resource definition and source files in source/appointment feed the current Appointment page and mapping checks. Request.priority remains a code with the required request-priority value set, so Appointment.priority intentionally remains a divergent Request mapping with CodeableConcept and example ActPriority binding.

AutoFHIR reconciliation:
This commit keeps the already-applied CodeableConcept/ActPriority change, removes the stale numeric iCalendar parenthetical from the Appointment.priority definition and SVG tooltip, replaces the obsolete extension/implementer-feedback comment with the requested iCalendar localization and ConceptMap guidance, removes the obsolete Appointment notes sentence about using an extension for CodeableConcept values, and updates the Appointment Request mapping exception to match the revised definition.

Recommendation:
Keep this source fix. It completes the published PA disposition without changing Request.priority or the existing Appointment.priority binding. No additional related issue should be decided from this seed; FHIR-7964 is useful background for the older extension approach, but FHIR-22101 supersedes it for R5.
