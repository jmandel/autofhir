FHIR-17055: Audit Bundle searchset timestamp clarification

Issue request:
FHIR-17055 was a Published FHIR-core Feed change request from the STU3 ballot with a Persuasive with Modification resolution. It asked why paged query/searchset Bundles had wording saying different pages would have different timestamps, and the approved change was to clarify that pages may have different timestamps without implying that later pages represent changes made since the initial query.

Initial application:
The issue was applied in SVN revision 14402, now git commit 78badad8ce50a540df39b801796b1f611e725e24, which added the no-implication clarification to source/bundle/bundle-spreadsheet.xml. The spreadsheet source has since been refactored away, and the same semantics now appear in source/bundle/structuredefinition-Bundle.xml for Bundle.timestamp.

Additional context:
FHIR-16906 is the immediately related Bundle.timestamp tracker from the same ballot family. It first changed the searchset wording from "will have different timestamps" to "MAY have different timestamps but need not" and clarified that Bundle.timestamp is the time the Bundle was assembled. FHIR-17055 then added the distinct assurance that different page timestamps do not mean the result set includes post-query changes. Current source/fhir.ini lists Bundle as an active resource, so the current StructureDefinition source is in build scope. No relevant Zulip or Confluence evidence was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active Bundle.timestamp comment already says searchset timestamps are the time the search set was assembled, that different pages MAY have different timestamps but need not, and that having different timestamps does not imply subsequent pages will represent or include changes made since the initial query.

Recommendation:
Keep this audit commit as-is. The current build source preserves the approved FHIR-17055 clarification, and adding or rewording source text would be redundant rather than corrective.
