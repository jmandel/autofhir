FHIR-17200: Audit PlanDefinition profile support

Issue request:
FHIR-17200 was a Published/Persuasive CDS change request raised for STU3 asking to support workflow conformance profiles from PlanDefinition actions, with the concrete need to associate a StructureDefinition with a step. The recorded resolution was to add an optional profile element to ActivityDefinition and PlanDefinition to allow a profile to constrain resources that can satisfy an action requirement.

Initial application:
The issue was applied in the git-svn history by 3c199cb863/a9e864411d, whose message includes GF#17200 and whose patch added ActivityDefinition.profile as 0..1 canonical(StructureDefinition) with text saying it identifies the profile the target resource needs to conform to. The same commit touched PlanDefinition operation plumbing, but the relevant profile-row patch is in ActivityDefinition; no current or historical source evidence found a separate PlanDefinition.profile element.

Additional context:
The current build-scope resources include both ActivityDefinition and PlanDefinition in source/fhir.ini. Current ActivityDefinition still contains the optional canonical(StructureDefinition) profile element. Current PlanDefinition.action.definition[x] allows canonical(ActivityDefinition) among other definition resources, and the PlanDefinition narrative says atomic actions with an ActivityDefinition are realized by applying the ActivityDefinition and then applying PlanDefinition action overrides. The overlap table includes transform and dynamicValue overrides but not a separate profile override, so adding a PlanDefinition-level profile now would not be the action-level constraint requested and could create ambiguity.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already provides the requested conformance-profile support through ActivityDefinition.profile, reachable from PlanDefinition.action.definition[x] for action steps, and does not need a direct StructureDefinition target or a redundant PlanDefinition.profile element.

Recommendation:
Keep this no-change audit as-is. Revisit only if the CDS work group explicitly wants a new action-level profile override on PlanDefinition.action; that would be a new design change rather than completion of FHIR-17200.
