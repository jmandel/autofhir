FHIR-12917: Audit invariant expression rendering

Issue request:
FHIR-12917 was a Published/Persuasive FHIR-core Observation change request raised against the DSTU2 vital-signs page. It reported that profile invariant displays were showing XPath expressions instead of the FHIRPath expressions and was resolved as auto-approved/apparently already fixed.

Initial application:
No local git commit explicitly mentions FHIR-12917. The same-day Zulip thread records the reporter identifying the vital-signs invariant display problem and Grahame Grieve responding that the build was supposed to display FHIRPath, not XPath, and that he would fix it. Later source history also removed residual XPath usage from the vital-signs StructureDefinition.

Additional context:
FHIR-12916 was raised from the same Zulip thread for the adjacent vital-signs invariant-expression content problems. Observation is active in source/fhir.ini, and the Observation vital-signs ImplementationGuide references the vital-signs StructureDefinitions, so the checked XML is current build input. Current vital-sign profile constraints use ElementDefinition.expression FHIRPath values and no remaining XPath values in the vital-sign profile source.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped Observation vital-sign profile source already renders from FHIRPath expressions rather than XPath values for the relevant invariants, so changing source would be redundant.

Recommendation:
Keep this no-change audit commit as-is. Revisit only if a future rendered build again shows XPath instead of FHIRPath for profile invariants.
