FHIR-36755: Audit warning-constraint compatibility text

Issue request:
FHIR-36755 was a Published FHIR-core change request with resolution Persuasive with Modification. It asked that the forward/backward compatibility rules clarify that warning constraints and warning invariants do not affect compatibility, or otherwise qualify the invariant rule as applying to error constraints. The accepted replacement for the Value Constraints row allowed new warning or best practice invariants and limited new error invariants to newly introduced elements or codes.

Initial application:
The issue was applied before this reconciliation in git commit f0b227068f110edc2debe58489dffa7f55488083, which changed source/versions.html. That commit replaced the older Value Constraints text with language saying invariants, regular expressions, fixed values, and patterns will not be changed in a way that could invalidate previous instances; that new warning or best practice invariants may be added; and that error invariants may be added when tied to newly introduced elements or codes or existing narrative rules. The current source/versions.html still contains that clarification.

Additional context:
FHIR-I WGM minutes for May 2022 record the WG decision to update the text so warning constraints/invariants do not affect forward or backward compatibility, with a 20-0-1 vote. Source search found the applied warning/best-practice wording only on the current versions compatibility page, and Jira/community searches did not find a later conflicting decision for this issue. The authoritative current source is source/versions.html, not a generated artifact.
