FHIR-37512: Audit Parameters.part nesting guidance removal

Issue request:
FHIR-37512 was a Published/Persuasive FHIR-I correction for R5 asking to remove the Parameters.parameter.part comment "Only one level of nested parameters is allowed" because that restriction was not true and had not been followed.

Initial application:
The issue was applied by git commit 1f6276945733a91c610faab8dffce169540f0290, which removed the erroneous comment from source/parameters/structuredefinition-Parameters.xml. The current source still has Parameters as an active concrete resource in source/fhir.ini and the Parameters.parameter.part element now contains only the correct reusable part definition and contentReference, with no one-level nesting restriction.

Additional context:
FHIR-I minutes for 2022-06-13 record the Persuasive 12-0-0 vote for FHIR-37512. The originating Zulip thread shows implementers encountering legitimate nested Parameters, Lloyd McKenzie and Grahame Grieve agreeing the rule was unsupported, and the issue being filed from that discussion. The obsolete sentence remains only in tools/history release snapshots for older releases, which preserve historical published content rather than current build source.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current authoritative Parameters StructureDefinition already reflects the requested correction and editing historical release snapshots would be inappropriate.

Recommendation:
Keep this no-change audit as-is. No core follow-up is needed unless a future work group wants to add new positive guidance about deeply nested Parameters, which would be a separate specification decision.
