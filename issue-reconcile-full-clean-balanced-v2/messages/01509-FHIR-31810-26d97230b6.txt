FHIR-31810: Confirm Ingredient description removal

Issue request:
FHIR-31810 was Published/Persuasive for FHIR-core MedicinalProductIngredient/Ingredient. It requested dropping Ingredient.description because an Ingredient represents a single component, an unstructured list of excipients should not be represented by repeating Ingredient, and the substance already carries its own description. The accepted resolution was to drop the description attribute because there was no use case for it.

Initial application:
The requested change was applied before this reconciliation. Commits 7239948659 and 08d35148dd explicitly removed the Ingredient.description element from source/ingredient/structuredefinition-Ingredient.xml for FHIR#31810, matching the Jira comment that the change was applied in the R4B branch and main build.

Additional context:
The current build scope has Ingredient active in source/fhir.ini and maps the old MedicinalProductIngredient artifact name to Ingredient. Current source/ingredient/structuredefinition-Ingredient.xml has no Ingredient.description element. A later Published issue, FHIR-28349, partly revisited the note/comment use case: it initially reintroduced the element as Ingredient.description, but Jira comments and FHIR-I minutes approved the name Ingredient.comment, and the current source contains Ingredient.comment instead. That later change does not restore the description element that FHIR-31810 removed.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because the current authoritative Ingredient StructureDefinition already omits Ingredient.description while retaining the later, separately approved Ingredient.comment element for notes about the component.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-31810; future changes to the note/comment capability should be handled under the later Ingredient.comment decision family rather than by restoring Ingredient.description.
