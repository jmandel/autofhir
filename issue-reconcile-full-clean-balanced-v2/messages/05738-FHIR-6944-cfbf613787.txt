FHIR-6944: Audit CarePlan activity reason cardinality

Issue request:
FHIR-6944 was a Published Patient Care change request for DSTU1 CarePlan. It asked to make CarePlan.Activity.detail.reason repeatable; the final resolution was to split it into reasonCode 0..* and reasonCondition 0..* so an activity could carry multiple coded and condition-backed reasons.

Initial application:
The Jira comments record SVN #6766 as the original application. The local git history does not contain an explicit FHIR-6944 commit, but the earliest available imported CarePlan source in c69d71aa already had CarePlan.activity.detail.reasonCode and CarePlan.activity.detail.reasonReference with max="*", preserving the approved repeatable coded and resource-backed reason model under the later element naming.

Additional context:
CarePlan is active in source/fhir.ini. Later Patient Care decisions changed the activity model: FHIR-26064 renamed activity.detail to plannedActivityDetail, and FHIR-39101 removed plannedActivityDetail from the active CarePlan model in favor of plannedActivityReference. The current XML source still retains the old plannedActivityDetail block inside an XML comment, where its reason element is also max="*", but a namespace-aware parse of active ElementDefinitions shows only CarePlan.activity, performedActivity, progress, and plannedActivityReference under CarePlan.activity; there is no active activity detail/reason element to fix. FHIR-39101 already has an issue-reconcile commit on the combined branch, so no related duplicate decision is made here.

AutoFHIR reconciliation:
