FHIR-18406: Audit Resource cardinality reconciliation

Issue request:
FHIR-18406 was Published/Persuasive for STU3 and asked whether the displayed base cardinality for Resource and DomainResource should be 1..1 when uses such as Parameters.parameter.resource can constrain a Resource-typed element to 0..1. The approved resolution was to correct Resource and DomainResource cardinality to 0..*.

Initial application:
The Jira comment points to commit f8c346570d, which changed the old dictionary generator to display the root resource cardinality as 0..* instead of 1..1 and forced generated resource roots to min 0 and max unbounded during validation. No additional current source edit was needed in this reconciliation.

Additional context:
Resource and DomainResource are active current build resources in source/fhir.ini. Their current StructureDefinition XML differential roots both have min 0 and max *, while Parameters.parameter.resource remains a separate Resource-typed child element constrained to 0..1. Quoted Zulip and Confluence searches for FHIR-18406 and the Resource/DomainResource cardinality terms found no conflicting community record, and a Jira text search found only the seed issue.

Recommendation:
Keep this audit commit as-is. No follow-up source work is recommended unless a future build shows a generated display regressing from the authoritative 0..* root cardinalities.
