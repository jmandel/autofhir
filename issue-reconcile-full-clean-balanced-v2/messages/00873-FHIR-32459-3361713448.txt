FHIR-32459: Audit applied AuditEvent network choice

Issue request:
FHIR-32459 was a Published FHIR-core AuditEvent change request with resolution Not Persuasive with Modification. It asked whether AuditEvent.agent.network.type should draw on ContactPoint.system codes for cases such as voice phone, SMS, and fax. The accepted resolution instead replaced the old AuditEvent.agent.network backbone with AuditEvent.agent.network[x] 0..1, permitting Reference(Endpoint), uri, and string, with endpoint-oriented definition, requirements, and source/destination comment guidance.

Initial application:
The issue appears to have been applied by git commit 3d204189e23e03f0b4f11d03d491bc1d868e399b, "security block vote updates: FHIR-33020, FHIR-32466, FHIR-32450, and FHIR-32459". That commit removed the old AuditEvent.agent.network.address and AuditEvent.agent.network.type backbone children, including the required ValueSet/network-type binding, and added AuditEvent.agent.network[x] with Reference(Endpoint), uri, and string. The current build includes AuditEvent as an active resource in source/fhir.ini, and the R4-to-current mappings record AuditEvent.agent.network.address and AuditEvent.agent.network.type as mapping to network[x].

Additional context:
Security WG minutes for 2021-09-13 list FHIR-32459 in the block vote approved 8-0-1 with the same Not Persuasive with Modification disposition shown in Jira. A later Published issue, FHIR-39116, asked to bring AuditEvent.agent.network.type back for IP-address semantics, but its final resolution explicitly did not restore network.type; commit a3adca8e6f9921c9bdca3288f8f39b1455794b96 clarified the current network[x] requirements to prefer Reference(Endpoint) or URI and use string when only an address or hostname is known. FHIR-39116 is already represented on the combined branch by a separate no-change audit commit.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active AuditEvent source already has the resolved network[x] choice with Reference(Endpoint), uri, and string; it no longer binds an AuditEvent network type to ContactPoint.system or the old network-type value set. The only remaining network-type source references found are historical OID registry entries, not an active AuditEvent element binding.

Recommendation:
Keep this no-change audit commit as-is. No core FHIR follow-up is needed for FHIR-32459; any future desire to add typed network address metadata should be handled by a new Security WG issue because the later FHIR-39116 decision reaffirmed string guidance rather than restoring network.type.
