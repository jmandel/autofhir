FHIR-15811: Audit DeviceDefinition version wording

Issue request:
FHIR-15811 was Published/Persuasive for STU3. It reported that Device version information had been treated like device-kind metadata even though software, hardware, and firmware versions vary by instance; the accepted resolution noted that the then-current Device resource already had version under Device and asked for the DeviceDefinition.version definition to say it represented available versions of the device, e.g., software versions.

Initial application:
The Jira comment cites commits c1f2872 and 842cb7b, but those commits touch unrelated medicinal product and biologically derived product files. Source history for the exact requested wording shows the actual FHIR-15811 application in 703207df98c4873778cec46cf8d80dd2c3ad8433, followed by 7b53206c174560c2d395bae1b33af7aefe58457b to shorten the display text after a build issue. Those commits changed the old DeviceDefinition.version spreadsheet source from an instance-oriented definition to "Available versions" / "The available versions of the device, e.g., software versions."

Additional context:
Later device modelling changed the element family. FHIR-25400 converted DeviceDefinition.version from a string to a BackboneElement with version type/component/value, and FHIR-40488 then renamed the device/software version backbone in both Device and DeviceDefinition to deviceVersion. FHIR-42900 and the related FHIR-39389 canonical-resource work added a new canonical business DeviceDefinition.version near the top of the resource. Current source/fhir.ini actively includes both Device and DeviceDefinition, so the checked XML definitions are in build scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source keeps instance-specific versions on Device.deviceVersion, keeps device-definition available device/software versions on DeviceDefinition.deviceVersion, and uses DeviceDefinition.version only for the later canonical business version. Reapplying the old FHIR-15811 wording to DeviceDefinition.version would now be wrong because that element has a different, later-approved meaning.

Recommendation:
Keep this audit commit as-is for FHIR-15811. The seed request is already preserved in the current model through DeviceDefinition.deviceVersion, while the canonical DeviceDefinition.version wording should remain governed by FHIR-42900/FHIR-39389 and any follow-up canonical-resource tickets.
