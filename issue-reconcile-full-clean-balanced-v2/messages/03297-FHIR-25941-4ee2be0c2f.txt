FHIR-25941: Audit RegulatedAuthorization subject references

Issue request:
FHIR-25941 was Published/Persuasive for R5 and asked that RegulatedAuthorization.subject support references for regulated authorizations where the authorized subject is a facility or party independent of the product. The Jira comments narrowed the missing targets to practitioner (or practitionerRole), organization, and location.

Initial application:
The issue was explicitly applied in git commit c400edffd62c1c0aba45b6ea5a3821ef58e161e5, which changed the then-active RegulatedAuthorization spreadsheet subject type from Reference(MedicinalProductDefinition|PackagedProductDefinition|DeviceDefinition|ResearchStudy|ActivityDefinition|PlanDefinition|ObservationDefinition) to include Practitioner, Organization, and Location. The current build now uses source/regulatedauthorization/structuredefinition-RegulatedAuthorization.xml rather than the retired spreadsheet source, and git blame shows those target profiles were carried into the generated/refactored StructureDefinition source in commit 33b409a4b6d544598262f2f074ebb4b6dc466157.

Additional context:
RegulatedAuthorization is active in source/fhir.ini, so the current StructureDefinition is in build scope. BRR minutes from 2020-06-16 record the FHIR-25941 approval by 11-0-1, matching the Jira vote. Current source also reflects later same-element evolution, including FHIR-31792 changing RegulatedAuthorization.subject to 0..* and later additions of other product target types, but none of that later history removes the Practitioner, Organization, or Location targets requested by FHIR-25941. A targeted Jira/Zulip/Confluence search found no final or community evidence requiring PractitionerRole in addition to the Practitioner target chosen by the original application.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative RegulatedAuthorization StructureDefinition already includes targetProfile entries for Practitioner, Organization, and Location on RegulatedAuthorization.subject, and the checked search parameter remains a normal reference search over RegulatedAuthorization.subject.

Recommendation:
Keep this audit commit as-is. Revisit only if BRR opens a new tracker that explicitly requires PractitionerRole as an additional target; FHIR-25941 itself is already represented correctly in the current source.
