FHIR-17031: Audit Binary and Bundle extension listings

Issue request:
FHIR-17031 was Published/Persuasive for STU3 and asked that Binary and Bundle stop listing "Extensions for all resources or elements" because neither resource has root extension or modifierExtension elements. The requested correction was to avoid listing those extensions and state that the resources do not support extensions or modifier extensions.

Initial application:
The issue was applied in git-svn commit 277d844cf88efa4ddfb4d03eb3ab64c67fa4fb38, matching the Jira comment for svn revision 14351. That commit changed the old publisher so non-abstract resource Profiles & Extensions pages were only generated for resources whose root type was DomainResource, preventing Binary and Bundle from receiving the generic extension-list page.

Additional context:
Binary and Bundle remain active build resources and normative package members in source/fhir.ini. Their current StructureDefinition sources both derive from Resource rather than DomainResource and define no Binary.extension, Binary.modifierExtension, Bundle.extension, or Bundle.modifierExtension element. The current CI profile pages no longer show the stale "Extensions for all resources or elements" wording. Extension listings now live in the FHIR Extension Pack, where the Binary and Bundle extension pages explicitly state that resources of those types do not have extensions at the root element while allowing extensions on child elements where the model permits them. A related Zulip discussion states the same rule for Bundle and Binary; direct FHIR-17031 Zulip and Confluence searches found no conflicting community record.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The authoritative core source already prevents root extensions on Binary and Bundle, and the current extension-page surface contains the more precise root-element warning. Adding a blanket warning to core profile pages would duplicate Extension Pack guidance and could be less accurate for child elements that can carry extensions.

Recommendation:
Keep this no-change audit as-is. Revisit only if the work group wants a cross-build presentation policy change that duplicates the Extension Pack root-extension warning on core profile pages.
