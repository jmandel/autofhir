FHIR-18485: Audit narrative language guidance

Issue request:
FHIR-18485 was a Published FHIR-core/fhir-i clarification raised against the STU3 narrative page. The ballot comment observed that the spec said a lang attribute on the XHTML div SHOULD be used even though FHIR examples and metadata instances did not generally populate language/lang, and asked to add language to all published instances. The final Not Persuasive with Modification resolution instead narrowed the narrative rule to say the div lang attribute SHOULD be used if language is declared on the resource, and noted validator warning follow-up.

Initial application:
The Jira comment points to GH#df47b32c6c. That commit changed source/narrative.html from "SHOULD also be used" to "SHOULD also be used if language is declared on the resource" and made a typo cleanup in source/languages.html. The current blame still attributes the operative sentence in source/narrative.html to df47b32c6c, while a later link-clarification commit preserved the issue wording.

Additional context:
source/fhir.ini actively maps narrative and xhtml type pages to the narrative page, so source/narrative.html is in current build scope. The current narrative page already contains the approved conditional lang guidance. A later Zulip IG-creation discussion shows the validator/publisher side treating missing XHTML lang/xml:lang on resources with Resource.language as a warning/generation concern, consistent with the Jira note and not a conflicting source requirement. No direct Zulip hit for FHIR-18485 and no Confluence references to the issue were found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped narrative source already preserves the final Jira resolution, and adding language values to all examples or duplicating guidance elsewhere would contradict the work-group's narrowed disposition and create unnecessary maintenance drift.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for FHIR-18485 unless a future work-group decision changes the relationship between Resource.language and XHTML lang/xml:lang validation.
