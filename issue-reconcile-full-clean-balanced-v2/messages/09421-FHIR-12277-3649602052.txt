Issue request:
FHIR-12277 was a Published/Persuasive OO change request raised in DSTU2 and applied for DSTU2. It asked to change Device.type to 0..1 because a Device can still be useful when the type is unknown but manufacturer, model number, or other instance details are known.

Initial application:
No local source commit explicitly mentioning FHIR-12277 was found. Historical Device spreadsheet source immediately before the later FHIR-20578 application shows Device.type already at 0..1, which matches the published FHIR-12277 resolution and indicates the older request had been reflected in pre-current source.

Additional context:
Later Published/Persuasive with Modification issue FHIR-20578 explicitly superseded that cardinality by changing Device.type from 0..1 to 0..* for multiple distinct device type concepts, with the definition limited to types that apply to the specific device instance. Commit a7f2575daae7bbacd9a22ea439c7ec35a4784f96 lists FHIR-20578 in preapplied Device changes and changes the Device.type spreadsheet row from 0..1 to 0..* with that definition; the 2021 source refactor commit 33b409a4b6d544598262f2f074ebb4b6dc466157 preserved those semantics in the current StructureDefinition source. FHIR-32562 later added explanatory text for multiple Device.type repetitions. The combined branch already contains audit commits for FHIR-20578 and FHIR-32562, so those related issues are not republished here.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Reverting to 0..1 would contradict the later published OO decision.

Recommendation:
Keep this no-change audit commit. No core source follow-up is needed for FHIR-12277; any future change to Device.type cardinality should come from a new OO decision that explicitly revisits FHIR-20578 and the current multiple-type guidance.
