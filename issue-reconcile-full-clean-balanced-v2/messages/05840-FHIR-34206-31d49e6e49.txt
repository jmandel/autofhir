FHIR-34206: Audit add-on order specimen guidance

Issue request:
FHIR-34206 was an Applied/Persuasive OO change request for ServiceRequest add-on orders. The accepted resolution deprecated ServiceRequest.specimen, directed implementers to consider Specimen.request first, and called for a ServiceRequest specimenSuggestion extension that can identify a preferred specimen or the ServiceRequest that yielded it, with optional fallback action guidance.

Initial application:
The core application was split across later source history. Commit dda9465736 deprecated ServiceRequest.specimen and expanded its comment for FHIR-34206/FHIR-48286, and commit b0b8b0e63d corrected the specimenSuggestion extension name and added a temporary ballot note. In the Extension Pack, commit 647f0be added servicerequest-specimenSuggestion plus fallback terminology. Later follow-up commits refined the result rather than requiring a new core edit here.

Additional context:
Current core source has ServiceRequest active in source/fhir.ini, no longer defines ServiceRequest.specimen in the authoritative StructureDefinition, and uses servicerequest-notes.xml to direct implementers to Specimen.request for the usual association and to the Extension Pack specimenSuggestion extension for less-common known-specimen/add-on cases. FHIR-50611 added the linked note guidance, FHIR-55444 subsequently removed the deprecated element before R6 final ballot, and FHIR-52987/Extension Pack history added the missing reference short and definition that 2026 OO minutes had identified as incomplete. A checked-in servicerequest.svg still contains a generated-looking stale reference to ServiceRequest.specimen, but the authoritative XML and narrative source are correct and this reconciliation should not edit only that diagram artifact.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No core source edit is needed because the current build-scope source already carries the intended ServiceRequest guidance and the extension definition now lives in, and has been corrected in, the FHIR Extension Pack.

Recommendation:
Keep this audit as-is for FHIR-34206. Any future work on the extension definition should be handled in the Extension Pack, and any stale ServiceRequest diagram artifact should be regenerated or reviewed as generated output rather than patched as a standalone semantic source fix.
