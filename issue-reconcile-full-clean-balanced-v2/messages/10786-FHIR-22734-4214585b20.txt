FHIR-22734: Audit ClinicalImpression code removal

Issue request:
FHIR-22734 was a Published Patient Care change request asking to add a binding to ClinicalImpression.code. The final Not Persuasive with Modification resolution was instead to remove ClinicalImpression.code because the work group found no known use case and expected outcomes to be represented through ClinicalImpression.finding.

Initial application:
The Jira comment linked commit 0ff2673b37d4c0be72524476b0c0d0dd9a0d5973, which changed the spreadsheet-era ClinicalImpression source by marking the ClinicalImpression.code row as removed. Later source refactoring converted ClinicalImpression into source/clinicalimpression/structuredefinition-ClinicalImpression.xml without reintroducing the element.

Additional context:
ClinicalImpression is present in the current source tree as a FHIR 6.0.0 resource StructureDefinition owned by Patient Care. Its current differential lists identifier, status/statusReason, description, subject, encounter, effective/date, performer, previous, problem, changePattern, protocol, summary, finding, prognosis, supportingInfo, and note, but no ClinicalImpression.code. The remaining coded outcome path is ClinicalImpression.finding.item, a CodeableReference with an example binding to condition-code, matching the Jira rationale. The current ClinicalImpression search-parameter bundle has finding-code and finding-ref, but no resource-level code search parameter. Zulip and Confluence searches found no conflicting later rationale; Confluence only surfaced Patient Care meeting pages/backlog entries that align with the Jira context.

Recommendation:
Keep this audit commit as-is. Do not add a ClinicalImpression.code binding unless Patient Care makes a new explicit decision to restore that element; current coding needs should continue through ClinicalImpression.finding.item.
