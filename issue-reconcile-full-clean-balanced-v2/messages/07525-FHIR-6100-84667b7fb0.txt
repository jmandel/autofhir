FHIR-6100: Audit enteral formula rate datatype

Issue request:
FHIR-6100 is a Published FHIR-core NutritionRequest/NutritionOrder change request resolved Persuasive with Modification. It asked to change enteralFormula.rate because continuous feeding rates such as mL/hr are rates, not arbitrary ratios; the adopted resolution created a repeating enteralFormula.administration backbone with quantity, rate, and schedule, and allowed rate to be Ratio or Quantity.

Initial application:
The issue was pre-applied in historical NutritionOrder spreadsheet/example commits, especially 6497963440, which first separated rate and rateAdjustment, and 9a331d0ab4, which created NutritionOrder.enteralFormula.administration and changed administration.rate[x] to Quantity|Ratio while deleting the separate rateAdjustment element. The current generated StructureDefinition source carries committee notes for #6100 and #6111 on those elements.

Additional context:
FHIR-6111 is the paired change-family issue and explicitly says to use FHIR-6100 for disposition. The resource was later renamed to NutritionRequest and then back to NutritionOrder, but source/fhir.ini currently lists nutritionorder=NutritionOrder as an active resource, so source/nutritionorder/structuredefinition-NutritionOrder.xml is the current build source to evaluate.

AutoFHIR reconciliation:
No source change was made. The active source already has the requested administration backbone, keeps quantity as a per-administration volume, defines rate[x] as Quantity or Ratio, explains when Ratio versus Quantity is used, and has no current rateAdjustment element.

Recommendation:
Keep this audit commit as-is. The current specification matches the final disposition, and adding duplicate wording would not change implementer understanding.
