FHIR-26324: Clarify FHIRPath Patch move indexes

Issue request:
FHIR-26324 was a Published/Persuasive FHIR-core technical correction requesting clearer expected behavior for the FHIRPath Patch move operation. The reporter found that Reorder List #4 in the FHIRPath Patch test cases expected moving source index 0 to destination index 3 in a four-item list to put the moved item before the last item, while the accepted interpretation was that it moves the first item to the end.

Initial application:
No FHIR-26324-tagged commit was found in the current core source history. The external fhir-test-cases repository now has the Reorder List #4 expected output corrected to value 2, value 3, value 4, value 1, but the core fhirpatch.html page still only said that move moves an element within a single list and did not define whether indexes are zero-based or whether destination is evaluated before or after source removal.

Additional context:
The original Zulip thread records Brian Postlethwaite asking exactly whether the destination position is before or after removal and whether it is 0 based; Grahame Grieve then agreed with Lee Surprenant's assumption and said the test cases were wrong and would be updated in FHIR/fhir-test-cases. Later FHIRPath Patch page commits clarified other parts of the page but did not address the move-index semantics. The fhirpatch.html page is in the published page list and hierarchy, and the FHIRPath Patch Parameters profile is included by the Parameters implementation guide, so both edited source files feed the current build.

AutoFHIR reconciliation:
This commit clarifies the move row in source/fhirpatch.html: both indexes are 0 based, the source element is removed first, and the element is then inserted at the destination index in the resulting list, with the four-element move-to-end example from the issue. It also aligns the source and destination slice summaries in the FHIRPath Patch Parameters profile so generated profile text does not remain ambiguous.

Recommendation:
Keep this commit as-is. It is a narrow source correction that implements the published Jira decision in current core build inputs while leaving the already-correct external fhir-test-cases repository unchanged.
