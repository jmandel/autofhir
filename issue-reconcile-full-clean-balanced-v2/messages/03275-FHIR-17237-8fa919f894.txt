FHIR-17237: Audit AdverseEvent preventive action fields

Issue request:
FHIR-17237 was a Published/Persuasive with Modification Patient Care change request for R5. It asked for AdverseEvent to capture actions or circumstances that prevented harm, and the final disposition chose separate contributingFactor, preventiveAction, mitigatingAction, and supportingInfo elements instead of adding booleans under supportingInfo.

Initial application:
The Jira-cited commit 4c4287bd97 added AdverseEvent.contributingFactor, AdverseEvent.preventiveAction, AdverseEvent.mitigatingAction, and supportingInfo/item[x] source rows in the old AdverseEvent spreadsheet, with example value set bindings for the new roles. That commit implemented the approved R5 model and was merged by HL7/fhir#719.

Additional context:
AdverseEvent is an active current-build resource in source/fhir.ini. The source was later reworked into source/adverseevent/structuredefinition-AdverseEvent.xml, and later Jira FHIR-46599 was Applied/Persuasive with Modification for R6 to remove the single-child BackboneElement pattern by changing the same four elements to repeating CodeableReference elements. Commit 017e9edbd0 applied that later decision while preserving the preventive, mitigating, contributing, and supporting-information semantics and value set bindings.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current source already contains the requested harm-prevention surface as AdverseEvent.preventiveAction 0..* CodeableReference, with the paired contributingFactor, mitigatingAction, and supportingInfo fields in the later approved CodeableReference form.

Recommendation:
Keep this no-change audit as-is. Do not reintroduce the old BackboneElement/item[x] structure for FHIR-17237; future AdverseEvent role changes should be evaluated against the current FHIR-46599 CodeableReference design.
