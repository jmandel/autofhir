FHIR-8570: Audit remittance outcome pending request

Issue request:
FHIR-8570 was a Published/Persuasive with Modification Financial Management request raised against DSTU1 terminology to add a Pended/Interim-style code to RemittanceOutcome for an insurer that has received a claim request and is still handling it but cannot return a complete response yet. The final resolution did not require a new `pending` code; it recorded that the outcome already included `partial`, which could indicate a pended claim but not whether additional information was required.

Initial application:
No source commit explicitly names FHIR-8570. The apparent application path is the 2016 RemittanceOutcome source history: cce85fffda moved RemittanceOutcome into a code set used by ClaimResponse and ExplanationOfBenefit and introduced `complete | error | partial`, and a446d8be15 then cleaned up the remittance-outcome value set/code system generation while preserving the `partial` concept. That matches the Jira resolution's modified disposition rather than the reporter's original request for a separate pending code.

Additional context:
The current build lists ClaimResponse, ExplanationOfBenefit, and PaymentReconciliation as active resources in source/fhir.ini. The old RemittanceOutcome terminology has since been refactored into active claim-outcome and payment-outcome source files; ClaimResponse.outcome still carries the RemittanceOutcome binding name but now binds to ValueSet/claim-outcome. Current claim-outcome includes `partial`, and later already-published/audited work in FHIR-13948 added `queued` for received-but-not-yet-processed claims while FHIR-22660 separated processing outcome from adjudication decision and added a `pending` adjudication decision concept. Those later decisions explain why adding a `pending` processing-outcome code now would be less accurate than the current split.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current active source already preserves the FHIR-8570 resolution through `partial`, and the related later source now handles the more precise pending/queued cases in their proper locations. Adding `pending` to claim-outcome, payment-outcome, or the legacy remittance-outcome worksheet would conflict with the current processing-vs-adjudication model and duplicate already-audited related issue work.

Recommendation:
Keep this audit commit as-is. No follow-up core edit is recommended for FHIR-8570; any future cleanup of stale RemittanceOutcome names or legacy terminology worksheets should be handled as terminology maintenance, not as this issue's pending-code request.
