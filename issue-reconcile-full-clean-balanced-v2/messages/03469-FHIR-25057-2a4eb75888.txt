FHIR-25057: Correct cross-reference type binding text

Issue request:
FHIR-25057 was a Published/Persuasive BRR change request for R5 asking to fix MedicinalProductDefinition.crossReference by making it a BackboneElement so it could carry the referenced product and a separate MedicinalProductDefinition.crossReference.type relationship code.

Initial application:
The issue appears to have been applied by d017cd22c28c50b2e285e0a2b5dc87edcc6dbb71, whose message says it made MedicinalProductDefinition Product Cross-Reference a backbone element and added a type, despite using the apparent typo GF#25067 rather than FHIR-25057. That spreadsheet commit changed the old 0..* Identifier crossReference into a parent row with crossReference.product[x] 1..1 Identifier|Reference(MedicinalProductDefinition) and crossReference.type 0..1 Coding. The later XML source migration retained the BackboneElement shape.

Additional context:
FHIR-26570 later simplified crossReference.product[x] to CodeableReference(MedicinalProductDefinition), and that later issue is already represented on the combined branch by f9d6a727e79e31c052fb4a01fb19d9080e258358. Current source/fhir.ini includes medicinalproductdefinition as an active resource, and the current StructureDefinition already has crossReference as BackboneElement, product as CodeableReference targeting MedicinalProductDefinition, and type as CodeableConcept. However, the binding description for crossReference.type still described "Extra measures" instead of product cross-reference relationships, contradicting the ProductCrossReferenceType value set and code system descriptions.

AutoFHIR reconciliation:
This commit corrects the MedicinalProductDefinition.crossReference.type binding description to "Relationship to another Medicinal Product." so the binding text matches the active ProductCrossReferenceType terminology and the requested relationship-type element. No other crossReference structure change was needed.

Recommendation:
Keep this source fix as-is. The core model now reflects FHIR-25057 plus the later FHIR-26570 CodeableReference decision; further product-reference cardinality or datatype changes should be handled by a new BRR decision, not inferred from this issue.
