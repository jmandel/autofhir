FHIR-17045: Audit operation Bundle.type guidance

Issue request:
FHIR-17045 was a Published/Persuasive with Modification STU3 issue asking what Bundle.type an operation response should use when it returns a Bundle of resources generated by the operation. The approved resolution said the type is collection unless the Bundle has search semantics such as pages, next links, or totals, and asked for this to be clarified in the documentation.

Initial application:
The issue was applied by svn 14365, represented in git as 014935aa16 ("GF#17045 - note about bundles on operations"), which added guidance to source/operations.html saying an operation response Bundle is collection unless it has search semantics. No other build-scoped source location appears to have been missed for this issue.

Additional context:
source/operations.html is a built operations page referenced by publish.ini and source/hierarchy.xml. A later Published issue, FHIR-32015, intentionally broadened the same paragraph because operations such as Composition $document can return a document Bundle; that later issue is already represented on the combined branch with Issue-Reconcile-Key: FHIR-32015. The current operations text preserves the FHIR-17045 guidance by saying Bundle responses are typically collection, other Bundle.type values are possible, and search semantics with matching counts and page links should use searchset.
