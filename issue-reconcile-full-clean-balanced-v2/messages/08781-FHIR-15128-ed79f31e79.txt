FHIR-15128: Align Request requester search path

Issue request:
FHIR-15128 was Published with resolution Not Persuasive with Modification. It asked to restore Request.requester.onBehalfOf and Event.performer.onBehalfOf after workflow patterns replaced the Practitioner-plus-Organization onBehalfOf pattern with PractitionerRole. The final decision did not restore onBehalfOf for RelatedPerson/other actors under the 80% rule, accepted PractitionerRole as the intended representation, and directed removal of the stale Request constraint that referenced onBehalfOf.

Initial application:
No source commit was found that explicitly names FHIR-15128. History shows the old Request.requester.agent/onBehalfOf backbone and its onBehalfOf constraint were introduced before the issue, then the workflow-pattern reconciliation changed Request.requester and Event.performer to direct references that include PractitionerRole. A later 2018 pattern update removed the stale Request.requester onBehalfOf invariant, matching the Jira resolution, but the Request pattern search-parameter row still pointed at the removed Request.requester.agent subpath.

Additional context:
source/fhir.ini lists request and event as active logical models, so source/request/request-spreadsheet.xml and source/event/event-spreadsheet.xml are current build inputs. Current Request.requester is a direct Reference including PractitionerRole, Organization, Patient, RelatedPerson, and Device, and current Event.performer.actor is a direct Reference including PractitionerRole and RelatedPerson. A January 2018 Zulip workflow discussion also records that the updated workflow patterns called for eliminating onBehalfOf in favor of PractitionerRole, and no direct Confluence or Zulip conflict for FHIR-15128 was found.

AutoFHIR reconciliation:
Updated the Request pattern requester search-parameter mapping from the removed Request.requester.agent path to the current Request.requester element. No Event source change was needed because Event.performer.onBehalfOf is absent and Event.performer.actor already uses the current direct-reference pattern.

Recommendation:
Keep this source fix. Do not restore workflow-pattern onBehalfOf without a new work-group decision and evidence that the Organization-on-behalf-of use case is common enough for core; use PractitionerRole under the current pattern in the meantime.
