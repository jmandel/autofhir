FHIR-7898: Audit Observation category query support

Issue request:
FHIR-7898 was a Published OO change request from the DSTU1 era asking for clearer support for querying subsets of Observations such as vitals, labs, imaging, and social history. The approved resolution was persuasive with modification: add Observation.category as a searchable CodeableConcept, originally 0..1.

Initial application:
The request was applied in 2015 by dba136eacbbb, which added Observation.category and the category token search parameter to the Observation spreadsheet; 4e55d97ce3b0 refined the category definition/comment and examples; and 158840613957 added the Observation Category value set. No current source gap remains from that original application.

Additional context:
Observation is an active resource in source/fhir.ini, so source/observation/structuredefinition-Observation.xml and source/observation/bundle-Observation-search-params.xml are current build inputs. Current source has Observation.category as 0..* CodeableConcept with a preferred binding to http://hl7.org/fhir/ValueSet/observation-category, and the category search parameter targets Observation.category. The difference from FHIR-7898's original 0..1 request is intentional: FHIR-9543 approved changing Observation.category to 0..*, and 37b3f60da89f applied that cardinality and multiple-axis guidance. The difference from the original example-binding discussion is also intentional: FHIR-9857 approved changing the category binding to preferred, and 5d6bd01a92ad pre-applied it. FHIR-10006 further records the no-change explanation that categories are broad buckets for search even when clients do not understand Observation.code, with multiple orthogonal groupings allowed.

AutoFHIR reconciliation:
This commit makes no source change because the current build already preserves the necessary implementer-facing behavior: Observation.category exists, is searchable, uses the maintained observation-category value set, and reflects later approved cardinality and binding decisions.

Recommendation:
Keep this audit commit as-is. Reverting category to 0..1 or to the older example-binding approach would contradict later published OO decisions; any future changes to Observation.category should be handled through a new tracker or an explicit reconciliation of the later category issues.
