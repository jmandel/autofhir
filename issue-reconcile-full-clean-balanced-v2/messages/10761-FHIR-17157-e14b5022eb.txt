FHIR-17157: Audit XML string whitespace guidance

Issue request:
FHIR-17157 was a Published/Persuasive with Modification FHIR-core issue raised against STU3 after the Java RI Validator warned that values should not start or finish with whitespace even though the old string regex appeared to allow whitespace-only, leading-whitespace, and trailing-whitespace strings. The accepted decision was that the validator would raise a warning for leading or trailing whitespace when the instance was loaded from XML, while the separate regex correction would be handled by the related datatype tracker.

Initial application:
No git commit explicitly names FHIR-17157 or GF#17157 in this checkout. The underlying XML/source rule predated the issue in commit a8566ea065d07d44c6a49ebb58bdd6e478b1a8a0, which added XML attribute trimming guidance. The related datatype regex and string/markdown clarification work was applied separately through GF#16940 in commit a5c90c3db3cc87902faf8b096c1fdc5f179853fc, and the later GF#17639 commit f8e58880f9ee09717f279992dbbaebce6a1601d7 added the current whitespace-only string warning and validator-alignment note.

Additional context:
The active datatype page is routed by source/fhir.ini's type-page defaults and the current source/datatypes.html, source/xml.html, source/resource-formats.html, and source/datatypes/primitives.xml files are the authoritative core source for the primitive string and format-specific whitespace behavior. Current source says leading and trailing whitespace is allowed for string but SHOULD be removed in XML, explains that whitespace-only strings may trim to invalid emptiness, requires primitive types other than string to avoid leading/trailing whitespace, and states that JSON preserves string whitespace. The related FHIR-16940 and FHIR-17639 decisions are already represented on the combined branch and do not require duplicate commits here. The relevant 2018 Zulip thread records the same interpretation: the validator warning was enforcing XML format rules, not banning meaningful string whitespace in every syntax.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Adding a new statement about the Java validator warning would duplicate implementation behavior rather than improve the normative core source, and the current build-scope source already captures the accepted distinction between XML trimming/warnings and JSON string preservation.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for FHIR-17157 unless a future work-group decision changes primitive string whitespace policy or asks for validator-specific documentation outside the core datatype and format pages.
