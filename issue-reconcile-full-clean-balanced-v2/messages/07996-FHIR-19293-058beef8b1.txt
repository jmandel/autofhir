FHIR-19293: Audit Java profile canonical fix

Issue request:
FHIR-19293 was a Published/Persuasive STU3 FHIR-core documentation/tools change request. It reported that generated Java model resources under implementations/java used @ResourceDef profile URLs such as http://hl7.org/fhir/Profile/Observation and asked that they use the canonical StructureDefinition form, http://hl7.org/fhir/StructureDefinition/[Resource].

Initial application:
The Jira comment says the issue was fixed through https://github.com/HL7/fhir/pull/59. That PR was merged on 2018-10-06 with commit 9c2ebfad4a04a9971be8a4bbd3da5a142867f394, changing JavaResourceGenerator.java to generate StructureDefinition profile URLs instead of Profile URLs. The PR base still had the bad generated @ResourceDef annotations in implementations/java, which confirms that the PR addressed the reported source of the generated problem.

Additional context:

The current FHIR source checkout no longer contains implementations/java Java model resources or JavaResourceGenerator.java; later cleanup, including 5ffadd84f0955f35a3d73a16accd671c0d564d56, removed the remaining implementations/java files. Current source searches find no http://hl7.org/fhir/Profile/[Resource] canonical URLs or Java files under the current implementation/source/tool paths.
