FHIR-13373: Audit sourceValueSet removal

Issue request:
FHIR-13373 was a Published/Persuasive STU3 CDS issue asking FHIR-core to clarify two Coding extensions, http://hl7.org/fhir/StructureDefinition/cqif-sourceValueSet and valueset-reference. The approved resolution said sourceValueSet was a duplicate of valuesetReference, so sourceValueSet should be removed and the spec should refer to valuesetReference instead.

Initial application:
The duplicate sourceValueSet extension had been introduced by FHIR-11699 in SVN #10673, represented in git as 08e1533d19e05abddc53a954858448473f67b800. FHIR-13373 was applied at SVN #12605, represented in git as 3f65cb426c2c30b729b1df0abf225ee62c9e3115, which removed the sourceValueSet row from the clinical reasoning module extension list.

Additional context:
Current active core source no longer contains cqif-sourceValueSet or sourceValueSet under source/. The only remaining exact sourceValueSet hits are in tools/history/release3/extension-definitions.xml, a historical release archive rather than current build source. Current active core terminology prose still points readers to the ValueSet Reference Extension, and the Extension Pack checkout contains the active StructureDefinition-valueset-reference definition for Coding.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current FHIR core checkout already reflects the approved decision: the duplicate CQIF sourceValueSet extension is absent from current source, and the surviving valueset-reference extension is the referenced mechanism. Editing the historical release3 archive or duplicating extension-pack content in core would be incorrect.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed for FHIR-13373; do not restore sourceValueSet. Any future changes to the surviving valueset-reference extension should be handled in the FHIR Extension Pack / terminology ownership path rather than by reintroducing a core duplicate.
