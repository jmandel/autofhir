FHIR-14563: Audit Binary securityContext explanation

Issue request:
FHIR-14563 was a Published/Persuasive with Modification FHIR-I change request for Binary, raised against STU3, asking for the Binary.securityContext explanation to clarify what the element means, when it is appropriate or redundant, and how it relates to resources such as DocumentReference/Media and to security labels. The approved resolution was to replace the element definition/comment with text describing another resource as a proxy for Binary access-control sensitivity and explaining circumstances where automatic rules from referencing resources are or are not sufficient.

Initial application:
The issue was applied by 22764b92f28e8e450712ccdd2561b6f8827223da, "GF#14563 - fix definition of Binary.securityContext", which changed source/binary/binary-spreadsheet.xml with the approved short definition, proxy-resource definition, and comment. Jira's implementation comment records svn 14337, matching that git-svn commit. The source was later converted from the spreadsheet to source/binary/structuredefinition-Binary.xml during the current build-source refactor, and the substantive FHIR-14563 text was carried forward.

Additional context:
Binary is an active resource in source/fhir.ini, so source/binary/structuredefinition-Binary.xml and source/binary/binary-notes.xml are current build inputs. The current definition says the referenced resource can stand in as a proxy for security sensitivity because Binary has few elements for determining sensitivity or individual relationships, and the comment explains when a server may or may not rely on an already-referencing resource. The current narrative also says securityContext/X-Security-Context tells the server to treat the Binary as if it were another resource. The approved 2018 wording mentioned Media, but 5c62f91cd81f150be72ad506c876e3cc20bd631d later merged Media into DocumentReference and deliberately removed Media from this same example. Neighboring Binary security issues FHIR-16890 and FHIR-17833 are already represented on the combined branch and do not require changing this element definition.

AutoFHIR reconciliation:
No source change was made. The current source already conveys the approved FHIR-14563 semantics: Binary.securityContext is a Reference to another resource used as an access-control proxy, can point to related or unrelated resources, and is not required when server-side knowledge from existing references is sufficient. Re-adding the obsolete Media example or duplicating this guidance in narrative prose would not improve implementer understanding and could conflict with later source evolution.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed unless FHIR-I decides to reopen the broader design question of whether Binary.securityContext should be renamed, replaced by security labels, or moved to an extension.
