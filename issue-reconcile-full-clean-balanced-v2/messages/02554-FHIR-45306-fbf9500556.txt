FHIR-45306: Audit Observation patient chaining examples

Issue request:
FHIR-45306 was Applied with resolution Persuasive with Modification for R6. It asked for search and _filter examples that describe observations for a patient to use an explicitly patient-specific chained search instead of the broader Observation.subject chain.

Initial application:
The issue appears to have been applied by upstream commit 1d29a98d3d2f8e140eb23843984a6f2177fbe645 from PR 3967, which changed the cited examples in source/search.html and source/search_filter.html from subject.name/subject.id to the Observation.patient chain. That commit did not include an AutoFHIR issue-reconcile trailer.

Additional context:
The Jira resolution notes that the original examples were not technically wrong but that examples whose prose says patient should be patient-specific. The current source uses patient.name, and the Observation-patient SearchParameter is defined as Observation.subject.where(resolve() is Patient) with target Patient, so this is a patient-specific chain even though it is not spelled subject:Patient.name. FHIR-I minutes for 2024-05-13 record the Persuasive with Mod vote. No directly relevant Zulip or additional Confluence FTS hits were found that conflict with the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already satisfies the applied issue through the patient-specific Observation.patient chain in the affected search examples, and a duplicate source edit would either be redundant or risk replacing the clearer existing patient SearchParameter with a longer equivalent chain.

Recommendation:
Keep this audit commit as-is. No follow-up core source work is needed for FHIR-45306 unless the work group later decides the examples must prefer subject:Patient.name over the existing Observation.patient search parameter.
