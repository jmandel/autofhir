FHIR-8502: Align medication rate-change guidance

Issue request:
FHIR-8502 was a Published Pharmacy change request, resolved Persuasive with Modification, asking to resolve contradictory rate-change guidance. The final decision changed MedicationAdministration.dosage.rate[x] to say rate changes recorded during administration should be captured as distinct MedicationAdministration events with their times, changed the MedicationOrder dosage rate comment to new/updated orders, and removed the corresponding rate comment from MedicationDispense.

Initial application:
The issue was initially applied by git commit 0c6541df60, whose message explicitly says it changed MedicationOrder rate comments, MedicationAdministration rate comments, and removed the MedicationDispense rate comment for #8502. The current MedicationAdministration source still carries the intended distinct-MedicationAdministration wording. A later FHIR-12840 refactor in 6a4b0d916e moved MedicationOrder/MedicationRequest dosage details into the reusable Dosage datatype, so the old request-specific rate guidance now appears as generic Dosage.doseAndRate.rate[x] text.

Additional context:
The current build scope includes Dosage and the MedicationAdministration, MedicationDispense, and MedicationRequest resources through source/fhir.ini. Later R6 dosage work, including FHIR-51540 source changes and the Applied FHIR-54651 cleanup, changed MedicationRequest, MedicationDispense, and MedicationStatement dosageInstruction from repeated Dosage elements to a single DosageDetails element whose steps/components represent complex or changing dosage regimes. Current dosage narrative and the MedicationRequest/MedicationDispense introduction pages already describe that DosageDetails structure. The remaining old text in Dosage.doseAndRate.rate[x] still said each rate change should become a new MedicationRequest, and MedicationDispense.dosageInstruction still said multiple dosageInstruction instances were needed despite current cardinality 0..1. FHIR-52892 also copied that stale MedicationDispense comment onto doseAdministrationAid, an adherence-packaging element where dosageInstruction rate-change prose is not meaningful.

AutoFHIR reconciliation:
This commit keeps the current MedicationAdministration wording unchanged and updates active source so the rate-change guidance matches the current R6 dosage model. Dosage.doseAndRate.rate[x] now tells implementers to use the dosage structure available in the containing context, such as separate DosageDetails steps, or a new/updated MedicationRequest when the change represents a change to the request. MedicationDispense.dosageInstruction now points to DosageDetails instead of impossible repeated dosageInstruction instances, and the accidentally copied dosageInstruction rate-change comment was removed from MedicationDispense.doseAdministrationAid.

Recommendation:
Keep this source fix. It preserves the FHIR-8502 MedicationAdministration resolution while preventing the old MedicationOrder/MedicationDispense rate-change wording from misleading R6 implementers after the DosageDetails restructuring. If the broader FHIR-51540 DosageDetails model is later substantially reworked, re-check this wording with that change family, but no separate FHIR-51540 or FHIR-52892 audit is intended here.
