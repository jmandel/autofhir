FHIR-16833: Audit Measure criteria Expression use

Issue request:
FHIR-16833 was a Published/Persuasive STU3 CQI change request for FHIR-core Measure. It objected that Measure criteria appeared CQL-only and asked to use the dynamic-language pattern with a language indication; the accepted resolution was to update Measure criteria to the new Expression data type, specifically criteria 1..1 Expression instead of string.

Initial application:
The issue appears to have been applied in SVN 14046, represented in git by e169985949ad77cfed6c6e86ee8036a90f98136e. That commit message cites GF#16833 and GF#16783 and the visible patch updates Measure examples from old string/path criteria forms to Expression-shaped criteria with language and expression children. Later source refactoring carries the active Measure definition in source/measure/structuredefinition-Measure.xml.

Additional context:
Measure is in current build scope through source/fhir.ini's active resources entry. Current Measure population, stratifier, stratifier component, and supplementalData criteria are typed as Expression. FHIR-16783 is the same historical change family and is already represented on the combined branch by an empty no-change audit commit. Later FHIR-29815 considered multiple languages for criteria and resolved to use cqf-alternativeExpression on Expression rather than changing criteria cardinalities, which matches the current source comments.
