FHIR-10416: Audit Task cancelled status

Issue request:
Published/Persuasive FHIR-core Task issue FHIR-10416 requested adding a `cancelled` TaskStatus code because Task cancellation behavior was already implied by the Task cancel operation and request/order lifecycle. The accepted resolution was to add `cancelled` as a status with the meaning that the task was not completed as requested.

Initial application:
The status code was added in the DSTU2-era workflow changes, and commit 135effcdc18c5860253e8fc6df7197732441fe74 explicitly tagged #10416 while revising the `cancelled` definition from the earlier "withdrawn prior to commencement" wording to "the task was not completed (more or less) as requested." Current source is the post-refactor CodeSystem source, not the old spreadsheet, and it still includes `cancelled` in the active Task status code system.

Additional context:
FHIR-11431 is the tightly related workflow clarification explaining that when the placer cancels a task, the placer is no longer concerned about the task outcome and the filler should cease work if able. Later FHIR-14781 moved and expanded the Task state-machine text into the Task page without removing the `cancelled` status. The active build includes `task=Task`, and the TaskStatus ValueSet includes the whole Task status code system.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already contains the `cancelled` code in `source/task/codesystem-task-status.xml`, includes it through `source/task/valueset-task-status.xml`, and provides cancellation behavior guidance in `source/task/task-notes.xml` and the workflow ad-hoc page.

Recommendation:
Keep this no-change audit commit. Reintroducing the older "prior to commencement" wording would conflict with the accepted FHIR-10416 definition and current Task guidance that cancellation can occur from non-terminal states.
