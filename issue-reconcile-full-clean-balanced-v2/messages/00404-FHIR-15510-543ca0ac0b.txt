FHIR-15510: Audit DeviceComponent property binding spelling

Issue request:
FHIR-15510 was a Published/Persuasive FHIR-core DeviceComponent change request for STU3. It reported that the DeviceComponent property value set binding name was misspelled as DeiviceComponentPropertyCode and was auto-approved as a non-substantive correction.

Initial application:
The issue appears to have been applied by git-svn commit 3b799efe75 / svn revision 13440, which changed the DeviceComponent spreadsheet binding names from DeiviceComponentPropertyCode and DeiviceComponentPropertyValue to DeviceComponentPropertyCode and DeviceComponentPropertyValue. The retained source now uses the corrected spelling in the spreadsheet and generated terminology source.

DeviceComponent is no longer active in the current build: source/fhir.ini comments out the resource, work group, and TLA entries, and records DeviceComponent as dropped. The current history page also describes the device rework that removed DeviceComponent and added DeviceDefinition. Negative Zulip and Confluence searches found no later discussion that would alter the simple typo conclusion.

AutoFHIR reconciliation:

Recommendation:
Keep this no-change audit commit as-is. No core source follow-up is needed unless a future branch reactivates DeviceComponent or needs a separate legacy-publication correction.
