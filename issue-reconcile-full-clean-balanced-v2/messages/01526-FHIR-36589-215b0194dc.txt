FHIR-36589: Audit Endpoint connectionType change

Issue request:
FHIR-36589 was Published/Persuasive with Modification for R5. It requested changing Endpoint.connectionType from Coding to CodeableConcept so IHE could supply more detailed SOAP web-service profile codes, relaxing the binding to example, removing/moving the IHE connection type vocabulary out of the core example set, and adding Endpoint narrative that points implementers to the IHE mCSD profile/vocabulary.

Initial application:
The issue was applied before this reconciliation. Commit a77eb2160f0b5dffe00ecb67b41381d934446603 changed Endpoint.connectionType to CodeableConcept, preserved the 1..* cardinality from FHIR-34261, relaxed the binding from extensible to example, and converted active Endpoint examples to CodeableConcept-shaped connectionType values. Commit 53c02b1dccc5cfe91919ce7796c81efecd7f82d0 added the Endpoint notes text pointing to IHE mCSD.

Additional context:
Endpoint is active in source/fhir.ini, so source/endpoint feeds the current build. FHIR-34261 explains why the cardinality was already 1..* before FHIR-36589. FHIR-38799 subsequently made the mCSD URL clickable, and FHIR-38798 removed the stale IHE copyright statement from the core ValueSet after terminology handling moved outside the core source. Current THO still carries legacy IHE endpoint-connection-type concepts as deprecated terminology, while the current active FHIR Endpoint XCA example uses the IHE mCSD CodeSystem. The old IID Endpoint example remains in source, but its Endpoint example list entry is commented out and its remaining reference is from the removed ImagingManifest material, so it is not a current Endpoint build-scope defect for this tracker.

AutoFHIR reconciliation:
No source change was made. The current active Endpoint source already has Endpoint.connectionType as 1..* CodeableConcept with an example binding, the core ValueSet includes the THO endpoint connection type CodeSystem without the old IHE copyright/filter text, and the Endpoint notes include the mCSD link requested by the issue.

Recommendation:
Keep this audit commit as-is. Any future cleanup of deprecated IHE codes in THO or retired IID/ImagingManifest source should be handled by a terminology or retired-artifact tracker rather than reopening FHIR-36589 in core Endpoint.
