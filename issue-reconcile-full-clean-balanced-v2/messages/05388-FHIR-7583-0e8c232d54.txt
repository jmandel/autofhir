FHIR-7583: Audit MedicationStatement status model

Issue request:
FHIR-7583 was a Published Pharmacy change request with resolution Persuasive with Modification. It asked for MedicationStatement.status to distinguish medication-use states such as active versus discontinued, because the DSTU1 status appeared to reflect the record rather than the medication.

Initial application:
The Jira comment says the issue was fixed as part of tracker FHIR-6310 in svn 6552. Git commit d3c2a3a055 applied svn 6552 by replacing the old in-progress/completed/entered-in-error status set with active, on-hold, completed, entered-in-error, stopped, and draft. The immediately following commit 31e9678a6e refined that same spreadsheet change to active, completed, entered-in-error, and intended, with definitions explicitly describing the state of the medication used rather than the statement record.

Additional context:
Later Published Pharmacy decisions deliberately superseded the DSTU-era medication-use status model. FHIR-19468 and FHIR-19470 moved taking/not-taking semantics into an adherence element, FHIR-32060 redesigned the status codes to recorded, entered-in-error, and draft, and FHIR-39271 reaffirmed that MedicationStatement.status is now the recording status of the statement while MedicationStatement.adherence carries taking/not-taking information. The current source is in build scope because MedicationStatement is active in source/fhir.ini, and the later FHIR-39271, FHIR-19470, and FHIR-32060 reconciliations are already represented on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Reintroducing active/discontinued-style status codes would conflict with the later published status/adherence model. The current build-scope source already states that MedicationStatement.status concerns recording the medication statement and points users to MedicationStatement.adherence, whose example terminology includes taking, not-taking, stopped, and on-hold concepts for the medication-use semantics behind the original request.

Recommendation:
Keep this no-change audit commit. FHIR-7583 was historically applied for the DSTU1 model, but the current specification should stay aligned with the later Pharmacy decisions unless the work group reopens the broader MedicationStatement status/adherence design.
