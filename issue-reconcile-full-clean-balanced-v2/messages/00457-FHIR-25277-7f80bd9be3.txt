FHIR-25277: Audit superseded immunization dose datatypes

Issue request:
FHIR-25277 was Published with a Persuasive resolution for R5 to change doseNumber and seriesDoses in Immunization, ImmunizationEvaluation, and ImmunizationRecommendation from positiveInt/string choices to string-only elements, retaining the element names and clarifying that Immunization reflects provider intent while ImmunizationEvaluation and ImmunizationRecommendation reflect CDS evaluation output.

Initial application:
The source history shows commit c60c23462f1349890e3e14cc979075bad8e1ecc0, "JIRA#25277 - update the doseNumber and seriesDoses data types", applying the string-only change to the older spreadsheet and example sources. The later StructureDefinition source rework preserved the FHIR-25277 committee notes and string datatype in the relevant immunization definitions before subsequent changes.

Additional context:
FHIR-44982 is a later Applied/Persuasive with Modification PHER decision that intentionally changed the same doseNumber and seriesDoses elements from string to CodeableConcept and updated comments to allow coded concepts or free text. The combined branch already contains Issue-Reconcile-Key: FHIR-44982 at d71140d621d3265e4cb4df589b68e53706ef5a0a, which completed the current in-scope FHIR-44982 reconciliation. Current core build scope keeps Immunization as an active resource but no longer has active ImmunizationEvaluation or ImmunizationRecommendation core resource directories; those resources are referenced externally as additional/incubator resources.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Reverting the current CodeableConcept datatype back to string would contradict the later final FHIR-44982 decision and the already-published FHIR-44982 reconciliation on the combined branch. Current source records both the FHIR-25277 history and the later FHIR-44982 CodeableConcept outcome.

Recommendation:
Keep this audit commit as-is. FHIR-25277 is historically applied but superseded for the current build by FHIR-44982, so no additional core source change is appropriate unless PHER reopens the datatype question.
