Issue request:
FHIR-13469 was a Published/Persuasive STU3 technical correction for the JSON documentation page. It reported that examples referencing HumanName.family incorrectly showed family as a multi-value JSON array even though the STU3 HumanName.family definition was singular.

Initial application:
The Jira comment says the issue was applied in svn revision 12067. The Git import contains b33f3e2684f438b70d073419fb52ca052e15bd9b with git-svn-id build@12067 and subject "GF#13469 - fix json". That commit changed source/json.html by replacing the old example's "family" : [ "Van" ] and "_family" : [ {"id" : "a2"} ] with the current singular "family" : "Van" and "_family" : {"id" : "a2"}; current blame for those lines still points to that commit.

Additional context:
source/json.html is the current source for the JSON format page and is linked from the documentation/module navigation. The current HumanName source still defines HumanName.family as 0..1 string. A 2017 Zulip #implementers thread titled "HumanName JSON" matches the issue trail: Bruce Tietjen reported the JSON page array problem, Lloyd McKenzie requested a change request, Bruce filed GF#13469, and Grahame Grieve replied "fixed." Confluence reference/full-text searches found no conflicting work-group evidence.
