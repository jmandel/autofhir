FHIR-12959: Audit primitive regex documentation

Issue request:
FHIR-12959 was a Published/Persuasive DSTU2 FHIR-core datatypes issue asking for missing regular expressions to be available either in source or in the datatypes documentation for boolean, decimal, base64Binary, and instant. The Jira resolution said to do this, with a comment tying application to svn revision 12461.

Initial application:
The Jira-commented svn revision is present in git as ffb483245175ff499a837bc605277a047ffa7b12, "Work on primitive data type validation - task 12960 & 12959", with git-svn-id build@12461. That commit added literal regex rows to source/datatypes.html for boolean, decimal, base64Binary, instant, and other primitive types, and populated the RegEx column in source/datatypes/primitives.xml for the same primitive definitions.

Additional context:
The current build-scope datatypes page still has regex rows for boolean, decimal, base64Binary, and instant, now expressed as [%regex ...%] macros. The current primitive spreadsheet source has non-empty regex values for all four types. Later datatype issues refined these regexes without reversing the FHIR-12959 decision: FHIR-34099 moved the datatypes page from copied literal regex text to primitive-source macros and corrected base64Binary handling, FHIR-53492 corrected decimal regex syntax, and FHIR-22655 later tightened the decimal value-domain wording and regex to enforce an 18-digit mantissa limit.

AutoFHIR reconciliation:
Made no source change. The current active datatype source already satisfies the FHIR-12959 request: the documentation source includes regex rows for each named primitive and the primitive datatype source contains current regex definitions. Reintroducing the original literal DSTU2 regex prose would regress later approved corrections and duplicate generated macro content.

Recommendation:
Keep this no-change audit. Future primitive regex fixes should be handled under the specific later datatype tracker that changes a regex's semantics, not by reopening the already-applied FHIR-12959 documentation/source coverage request.
