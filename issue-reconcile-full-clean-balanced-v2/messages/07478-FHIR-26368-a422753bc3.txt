FHIR-26368: Audit Parameters messaging use

Issue request:
FHIR-26368 was Published with resolution Persuasive. It asked FHIR-I to remove the Parameters wording that said the resource had "no other use" outside operations, because that wording precluded Parameters from carrying named values in messaging, particularly through MessageHeader.focus.

Initial application:
The issue was initially applied by commit 6275ee6723bf77b15313933ea4c7b5fa927d12cd and merged by a410a74438d69a8f66d0dee3dd433dad31169128, changing the Parameters resource description from "It has no other use" to a softer operation-focused description. That broad application was later refined by the FHIR-26390 implementation commits and PR #1957, which updated the active Parameters source, MessageHeader.focus, Bundle.entry.resource, and other explicit allowance points.

Additional context:
The 2020 Zulip discussion and FHIR-I minutes show the original need was Parameters in messaging, while the follow-up FHIR-26390 discussion clarified that Parameters should not become allowed everywhere Resource or Reference(Any) appears. The current combined branch already contains a dedicated FHIR-26390 reconciliation commit, 4f2edddd4a388a76f071bb8b4f1f6f3ba7d1a743, aligning the remaining Parameters narrative and root definition with that limited-use policy. FHIR-57354 is a later Resolved - change required request to remove the Bundle.entry.resource guardrail, but it is not Applied/Published in this default run scope and does not change the FHIR-26368 audit decision.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current build-scope source already states that Parameters can be used for operations invoked directly from REST or within a messaging environment, no longer contains the old "no other use" prohibition, and explicitly allows MessageHeader.focus to reference Parameters. The current limitations around persistence, references, and Bundle.entry.resource are attributable to the later FHIR-26390 decision rather than a missed FHIR-26368 application.

Recommendation:
Keep this no-change audit for FHIR-26368. Do not reintroduce the broader "primarily used" wording from the original FHIR-26368 resolution, because later FHIR-26390 work intentionally replaced it with clearer limited-use guidance. Handle FHIR-57354 separately if and when this run includes Resolved - change required issues.
