FHIR-25922: Audit Device.definition type reconciliation

Issue request:
FHIR-25922 was a Published/Persuasive with Modification R4 issue for R5. Although the summary said DeviceDefinition.capability should become CodeableReference, the Jira comments and resolution narrowed the request to changing Device.definition from Reference(DeviceDefinition) to CodeableReference(DeviceDefinition) so a Device could point at a specific DeviceDefinition or carry code/text.

Initial application:
The issue was applied by git commit 7cb1548fac9c810f4943ecce7f02f7f549d87726, which changed source/device/structuredefinition-Device.xml so Device.definition used CodeableReference with targetProfile DeviceDefinition. No separate current DeviceDefinition.capability application remains to apply, because later DeviceDefinition capability/specialization cleanup removed those elements from the current source.

Additional context:
Later OO decisions superseded the R5 CodeableReference shape. FHIR-40397 was Applied for R6 and explicitly changed Device.definition back from CodeableReference(DeviceDefinition) to Reference(DeviceDefinition), moving the coding/search semantics to Device.type and DeviceDefinition.classification.type. FHIR-46560 was Resolved - No Change because R6 InfoBallot #3 had removed CodeableReference(DeviceDefinition) from Device and instructed use of Device.type instead. FHIR-39389 and related OO discussion then moved DeviceDefinition toward canonical resource modeling, and the current active Device source now uses canonical(DeviceDefinition); FHIR-53625's Applied R6 ballot note records that datatype change.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active Device and DeviceDefinition resources are in source/fhir.ini, the current Device.definition source is canonical(DeviceDefinition), and reintroducing CodeableReference would conflict with the later Applied/No-Change R6 issue family rather than preserving the current specification.

Recommendation:
Keep this audit commit as-is. Do not reapply the FHIR-25922 CodeableReference change unless the work group reopens the later DeviceDefinition canonical/modeling decisions; any remaining search-parameter cleanup for canonical(DeviceDefinition) belongs to the later R6 DeviceDefinition modeling family, not this R5 issue.
