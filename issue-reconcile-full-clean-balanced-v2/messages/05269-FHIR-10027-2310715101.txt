FHIR-10027: Audit CarePlan activity outcome handling

Issue request:
FHIR-10027 was a Published FHIR-core Patient Care change request, resolved Persuasive for DSTU2, asking to add an outcome under CarePlan.activity as a CodeableConcept so implementers could associate an intervention with what happened as a result.

Initial application:
The Jira-tagged implementation commit 0ce706f192a999ff2c605f513265344d6607f3d8 added CarePlan.activity.outcome as a 0..1 CodeableConcept with the CarePlanActivityOutcome binding in the then-authoritative CarePlan spreadsheet source. FHIR-10620 later added the example value set for that outcome binding. The current source no longer uses a literal outcome element because later CarePlan source refactors and FHIR-26064 intentionally renamed and broadened the element.

Additional context:
FHIR-26064 was a later Published/Persuasive with Modification Patient Care decision for R5 to rename CarePlan.activity.outcome to CarePlan.activity.performedActivity as a CodeableReference, clarify that it represents the activity performed rather than Goal.outcome, and rename adjacent planned-activity elements. The combined branch already contains the FHIR-26064 reconciliation commit fdc52d56040442ba2ec231a5f6d2c2275972b05b for the active ModelInfo surface, and it already contains the later FHIR-39101 reconciliation for the current no-plannedActivityDetail shape. FHIR-45000 and FHIR-48415 subsequently refined performedActivity wording/value-set examples and progress comments without reversing the rename. Current CarePlan is active in source/fhir.ini and the authoritative StructureDefinition exposes CarePlan.activity.performedActivity with a CodeableReference binding to care-plan-activity-performed, while fhir.ini maps the old outcomeCodeableConcept/outcomeReference names to performedActivity for version-transition purposes.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current specification already preserves the implementer capability requested by FHIR-10027 through CarePlan.activity.performedActivity, and reintroducing a separate CarePlan.activity.outcome CodeableConcept would conflict with later published Patient Care decisions that separated performed activity from Goal outcome.

Recommendation:
Keep this audit commit as-is. Future cleanup of the legacy care-plan-activity-outcome value set or historical name mappings, if desired, should be handled under a dedicated terminology/backward-compatibility or FHIR-26064/FHIR-10620 follow-up rather than under FHIR-10027.
