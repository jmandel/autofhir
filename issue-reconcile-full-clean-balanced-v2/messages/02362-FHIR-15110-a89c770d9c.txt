FHIR-15110: Audit de-identification isModifier guidance

Issue request:
FHIR-15110 was a Published/Persuasive with Modification Security WG change request for STU3 asking for de-identification guidance about the interpretation risks of redacting isModifier elements and elements with defaults. The approved resolution narrowed the requested change to adding a de-identification-section warning: "Care should be taken when modifying an isModifier elements, as the modification will change the meaning of the Resource."

Initial application:
The git history has an explicit GF#15110 commit, 7b2b64512052c9a800a59b0ac3cd2cd013659b1b, but that commit added query-parameter access-control guidance and did not add the approved isModifier sentence. The approved warning itself appears to have been applied implicitly by df8241d8ed19f08b12c18f34bf71c7bdbf611ef9, which added the de-identification section text now preserved in source/secpriv-module.html.

Additional context:
source/hierarchy.xml keeps source/secpriv-module.html in the active Security and Privacy module page tree. The current de-identification section still warns that modifying isModifier elements changes resource meaning, and later FHIR-52902 work added adjacent guidance that de-identified data may not satisfy normal profile constraints without removing or contradicting the isModifier warning. For the default-value part of the original description, the current ElementDefinition guidance says the FHIR specification does not define default values for resources or datatypes, and the final Jira resolution did not require adding separate default-value prose or cross-references.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope Security and Privacy module already contains the approved de-identification warning, and adding redundant links or default-value prose would go beyond the final modified resolution without changing implementer understanding.

Recommendation:
Keep this no-change audit commit as-is. Future editorial work could fix the grammar of "an isModifier elements", but FHIR-15110 is already semantically applied and does not require a source change.
