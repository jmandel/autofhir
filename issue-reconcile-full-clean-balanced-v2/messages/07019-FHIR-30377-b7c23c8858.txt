FHIR-30377: Audit task-code ValueSet version fix

Issue request:
FHIR-30377 was a Published/Persuasive technical correction for R5 asking that the source ValueSet http://hl7.org/fhir/ValueSet/task-code stop referencing http://hl7.org/fhir/CodeSystem/task-code with the old 3.6.0 version instead of the then-current R4 4.0.1 version. The resolution said to fix the hard-coded Task source value.

Initial application:
The issue was explicitly applied by commit 83f5f88f3cb45c226b55ef1f8a326804412ccc2a, which removed <version value="3.6.0"/> from source/task/valueset-task-code.xml under the include for CodeSystem/task-code. Earlier nearby version-maintenance commits changed the Task CodeSystem and ValueSet artifact versions, but this Jira-tagged commit removed the stale include version that caused the reported generated XML/JSON output problem.

Additional context:
The Task resource is active in source/fhir.ini, so source/task/valueset-task-code.xml and source/task/codesystem-task-code.xml are in current build scope. Current source has ValueSet/task-code at version 6.0.0, includes CodeSystem/task-code without an include-level version, and has CodeSystem/task-code at version 6.0.0. Hyphen-safe Zulip and Confluence searches found no directly relevant community or meeting evidence that changes the Jira/source/history conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative source already avoids the stale 3.6.0 CodeSystem include version and tracks the current artifact version, so adding or changing source would be redundant and could reintroduce unnecessary version pinning.

Recommendation:
Keep this no-change audit commit as-is. No follow-up is needed in core FHIR unless future publication tooling reintroduces a generated task-code ValueSet include version that diverges from the CodeSystem version.
