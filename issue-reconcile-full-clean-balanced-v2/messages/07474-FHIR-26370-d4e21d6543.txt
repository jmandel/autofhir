FHIR-26370: Audit canonical version comparison mechanism

Issue request:
FHIR-26370 was Published with a Persuasive with Modification resolution for FHIR-core ValueSet. It asked for a technical mechanism to determine the most recent canonical resource version, centered on a new STU CanonicalResource.versionAlgorithm[x] choice element of type Coding|string with an extensible VersionAlgorithm binding, comparison-expression comments, initial comparison codes, and a warning when a canonical version is present without a declared algorithm.

Initial application:
The issue was explicitly applied by git commit f5a3f369a4dc96aa0f75a2c75f90a258388a9a5a, which added CanonicalResource.versionAlgorithm[x] plus the version-algorithm CodeSystem and ValueSet. Later canonical-alignment commits propagated versionAlgorithm[x] to concrete canonical resources, including ValueSet, and related FHIR-35834 commits added the $current-canonical operation that uses versionAlgorithm to retrieve the most current canonical resource.

Additional context:
source/fhir.ini keeps CanonicalResource, ValueSet, CodeSystem, and OperationDefinition in current build scope. Later FHIR-I decisions and current source centralize the conformance guidance on canonical reference/version matching: source/references.html says canonical resources SHOULD declare versionAlgorithm[x] because determining the current version is problematic without it, while the $current-canonical operation allows servers to infer or reject ambiguous algorithms when the element is absent or inconsistent. FHIR-39268 later considered moving versionAlgorithm above the resource level but kept the per-resource element as the best available compromise. The current source does not contain a literal validator warning invariant for missing versionAlgorithm[x], but adding one now would broadly change validation/QA behavior across canonical resources and would be redundant with the current centralized SHOULD guidance absent a newer work-group decision to make that machine warning mandatory.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current build-scope source already contains the versionAlgorithm[x] element, the extensible VersionAlgorithm terminology, concrete ValueSet participation, the current-canonical retrieval operation, and narrative guidance for what servers may do when the algorithm is missing.

Recommendation:
Keep this no-change audit as-is. If FHIR-I still wants validators to emit a warning whenever a canonical resource has version but no versionAlgorithm[x], that should be handled as an explicit follow-up because it would affect many canonical resource instances; no current source correction is required for the published FHIR-26370 intent.
