FHIR-11211: Audit Condition-Observation boundary

Issue request:
FHIR-11211 is a Published/Persuasive with Modification DSTU2 Patient Care ballot issue asking to clarify the boundary between Observation and Condition because the old Condition.category codes for finding and symptom appeared to conflict with guidance that signs and symptoms are typically Observations. The Jira resolution points to the original GF/FHIR-8872 boundary clarification.

Initial application:
The source was already changed in the historical FHIR-8872 implementation commit f5f5c6ecae, which added the key Condition boundary paragraphs distinguishing symptoms captured as Observations from persistent symptoms managed as Conditions. The category-code concern was subsequently handled by bffc717a99, which replaced the old complaint/symptom/finding/diagnosis category codes with problem-list-item and encounter-diagnosis and changed the binding/cardinality as part of FHIR-10091/10404.

Additional context:
Condition is active in the current build through source/fhir.ini. Current Condition boundary text still contains the FHIR-8872 rule, later refined by FHIR-26904, and current Observation text cross-references the same boundary and says symptoms may be Observations or, in selected cases, Conditions. Later category decisions, including FHIR-48358 and FHIR-54454, made Condition.category an example binding and replaced the element short with broad text rather than a misleading code list.

AutoFHIR reconciliation:
No source files were changed. The current active Condition and Observation source already conveys the approved boundary, and the old category codes that triggered FHIR-11211 no longer appear in the current Condition source or locally cached HL7 Terminology condition-category CodeSystem packages.

Recommendation:
Keep this empty audit commit as-is. No core follow-up is needed for FHIR-11211; future work on Condition.category should follow newer category trackers rather than reintroducing symptom/finding guidance from this duplicate ballot comment.
