FHIR-32077: Audit DICOM metadata guidance

Issue request:
FHIR-32077 was Published with a Persuasive resolution for ImagingStudy. It asked to add commentary discouraging extensions for additional DICOM attributes and instead describe how imaging-aware consumers can access DICOMweb metadata-only content, including an example.

Initial application:
The request appears to have been applied by git commit 52a5df179457fea03c4c8e598133c470f4e1de38, "ImagingStudy updates November 2021: FHIR-33985, FHIR-32793, FHIR-32719, FHIR-32077". That commit added the "Additional DICOM attributes" section and a WADO-RS series metadata retrieval example to source/imagingstudy/imagingstudy-notes.xml.

Additional context:
The Confluence resolution page for FHIR-32077 contains the same guidance and example shape now present in the source. source/fhir.ini lists imagingstudy as an active resource, so source/imagingstudy/imagingstudy-notes.xml is in build scope. A later 2026 ImagingStudy notes edit linked the Endpoint reference but preserved the DICOMweb metadata guidance. The initiating Zulip thread supports the same rationale: the Imaging Integration work group favored metadata-only WADO retrieve over publishing arbitrary ImagingStudy extensions for additional DICOM attributes.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active ImagingStudy notes already tell consumers that WADO-RS metadata-only retrieval is the flexible solution for additional DICOM attributes, explain why that avoids publishers having to know each future consumer's needed attributes, and include a concrete WADO-RS /metadata request example.

Recommendation:
Keep this no-change audit commit as-is for FHIR-32077. Any broader cleanup of older DICOM extension examples in other resources should be handled under a separate issue and work-group decision, not under this ImagingStudy clarification.
