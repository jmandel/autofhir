FHIR-11103: Audit normalized RiskAssessment risk support

Issue request:
FHIR-11103 was a Published, Persuasive CDS change request for FHIR-core RiskAssessment. The DSTU2 ballot note asked whether relative risk was in the 80%, the commenter asked that a normalized risk be supported, and the accepted resolution said normalized risk score would be supported and the documentation updated to remove the balloting question.

Initial application:
The issue was applied in SVN 11387, imported as git commit de39c36babe215c48986f3c8edfacdb94459ac9b with the subject "#11102, #11103: Updating risk assessment todos and documentation." That commit removed the RiskAssessment STU open-issues block, removed the relative-risk "Is this in the 80%?" spreadsheet todo, and kept the relativeRisk element rather than adding a new current-source element. Later source refactoring moved the authoritative resource definition from the old spreadsheet files into source/riskassessment/structuredefinition-RiskAssessment.xml.

Additional context:
RiskAssessment is active in source/fhir.ini, so the current RiskAssessment XML and narrative files are current-build source. The current StructureDefinition supports numeric and normalized/relative representations through RiskAssessment.prediction.probability[x] as decimal, Quantity, or Range, qualitativeRisk, and RiskAssessment.prediction.relativeRisk as a decimal ratio to the general population. The current riskassessment-notes.xml no longer contains the old STU open-issue note. The related FHIR-11102 method question was handled in the same historical commit, and older FHIR-7769 was a no-change relative-risk tracker; neither creates a remaining FHIR-11103 source obligation. Later FHIR-27875 refined probability Quantity/Range handling without reversing this issue.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build-scoped source already conveys normalized/relative risk support and the obsolete balloting question is absent, so adding more prose would be redundant rather than corrective.

Recommendation:
Keep this no-change audit commit as-is. No follow-up source work is needed for FHIR-11103 unless CDS reopens the broader modeling question in a new tracker.
