FHIR-7535: Audit driver license naming system migration

Issue request:
FHIR-7535 was a Published/Persuasive Vocabulary change request from the 2015May core ballot asking to change the driver's license entries on the terminology systems page to NamingSystem-based handling. Jira records the accepted resolution as "do this (was supposed to have been done already)" with svn revision 5712.

Initial application:
The issue was applied in git commit 6156a02e859af9a1022dd9e52ae7ea8d0e0ffa0a, the git-svn import of svn revision 5712. That commit deleted source/valueset/valueset-systems.xml, added source/identifier-registry.html and source/namingsystem/namingsystem-registry.xml, changed datatypes.html to link identifier systems to the identifier registry instead of terminologies-systems.html, and reduced terminologies-systems.html to code-system-oriented content.

Additional context:
Later terminology source changes moved the detailed NamingSystem registry content out of core and toward HL7 Terminology. FHIR-37889 removed the terminology and identity NamingSystem bundles from core because they duplicated content maintained in HL7 Terminology, and the combined branch already contains FHIR-37889 and FHIR-40117 audit/fix commits for the remaining empty NamingSystem bundle artifacts. The current identifier registry page now directs shared identifier systems, including license-number-style identifiers, to HL7 Terminology and TSMG policy rather than maintaining the old core driver-license list.

AutoFHIR reconciliation:
Made no source change. The current build no longer has the old valueset-systems.xml driver-license value set or driver-license entries on terminologies-systems.html, identifier guidance links to identifier-registry.html and NamingSystem/THO policy, and the later removal of core NamingSystem registry bundles is already represented by separate issue-reconcile commits.

Recommendation:
Keep this no-change audit commit. Reintroducing driver-license NamingSystem entries into core would conflict with later Vocabulary direction that identifier-system registry content is maintained outside core; any future driver-license registry correction should be handled in HL7 Terminology/TSMG-managed content rather than this FHIR source checkout.
