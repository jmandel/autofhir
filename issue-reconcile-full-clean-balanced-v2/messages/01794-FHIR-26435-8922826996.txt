FHIR-26435: Audit AdverseEvent resulting effect definition

Issue request:
FHIR-26435 was a Published/Persuasive Patient Care change request for R5. It asked to update AdverseEvent.resultingCondition because the R4 definition only described reactions from exposure to substances, while resulting conditions can arise from any adverse event, such as a broken leg after a fall.

Initial application:
The issue was initially applied by commit 12d222c23df9fcab9742ec7e7bf1981d84539119, which changed the AdverseEvent source spreadsheet definition from an exposure-only reaction to a condition resulting from the adverse event and added the fall/broken-leg example with J#26435 committee notes. The spreadsheet source was later reworked into structuredefinition-AdverseEvent.xml, carrying that wording forward.

Additional context:
The current build-scoped AdverseEvent source uses the renamed element AdverseEvent.resultingEffect. FHIR-34316 renamed resultingCondition to resultingEffect and added Observation as a target, and FHIR-48833 later changed resultingEffect to CodeableReference; both later changes retained the FHIR-26435 definition. source/fhir.ini keeps AdverseEvent active and maps the old R4 name AdverseEvent.resultingCondition to AdverseEvent.resultingEffect for R4-R6 change tracking.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current definition already says the effect is the condition that occurred as a result of the adverse event, gives both substance-exposure and broken-leg-after-fall examples, and is attached to the current renamed element.

Recommendation:
Keep this no-change audit as-is. No FHIR core source follow-up is needed for FHIR-26435 unless a future Patient Care decision changes the intended scope of AdverseEvent.resultingEffect.
