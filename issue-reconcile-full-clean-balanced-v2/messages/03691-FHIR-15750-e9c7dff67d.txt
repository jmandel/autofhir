FHIR-15750: Audit CDS Hooks indicator mapping

Issue request:
FHIR-15750 was Published/Persuasive for STU3 by the CDS work group. It asked core FHIR to represent CDS Hooks indicator values and provide a bidirectional mapping between CDS Hooks Response.indicator and FHIR Request priority.

Initial application:
The issue was applied in the historical SVN/Git migration by GF#15750 commits eddc29460b and 8445a21031. Those commits added source/terminologies/codesystem-cdshooks-indicator.xml, source/terminologies/valueset-cdshooks-indicator.xml, source/conceptmap/conceptmap-cdshooks-indicator.xml, a ConceptMap spreadsheet entry, and a CDS-on-FHIR page link from Response.indicator to conceptmap-cdshooks-indicator.html.

Additional context:
Later Applied issue FHIR-19786 retired the core CDS Hooks indicator terminology in favor of THO. Later Applied issue FHIR-53085 intentionally moved most CDS-on-FHIR page content, the CDS Hooks mapping profiles, and the ConceptMaps supporting CDS Hooks-to-FHIR mappings to the Using FHIR Clinical Reasoning with CDS Hooks IG. Related Applied issues FHIR-52870 and FHIR-48308 were applied in that IG by the same external commit, making the indicator-to-request-priority ConceptMap owned by CDS and specifying CodeSystem URIs.

AutoFHIR reconciliation:
No core source change is made. The current core source keeps the Clinical Decision Support page in the build, summarizes CDS Hooks use, and points readers to the Using FHIR Clinical Reasoning with CDS Hooks IG. The old core ConceptMap source is intentionally absent after FHIR-53085, while the external IG contains the indicator-to-request-priority ConceptMap with the original info/routine, warning/urgent, and critical/stat mappings.

Recommendation:
Keep this no-change audit commit. Do not restore the old core ConceptMap or CDS-on-FHIR mapping table unless the CDS work group reverses FHIR-53085; any future corrections to the mapping itself should be made in the CDS Hooks Clinical Reasoning IG or THO as appropriate.
