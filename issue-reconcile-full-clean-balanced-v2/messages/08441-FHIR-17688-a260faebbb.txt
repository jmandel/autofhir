FHIR-17688: Audit narrative conformance language

Issue request:
FHIR-17688 was a Published, Persuasive with Modification FHIR-I change request raised against the STU3 narrative page. It noted mixed SHALL, SHOULD, and MAY language around narrative presence and content, and the final resolution said the modifier-extension wording was already partly addressed while the fallback narrative sentence should read: "Resource instances that permit narrative SHOULD always contain narrative to support human-consumption as a fallback".

Initial application:
The issue was applied in two relevant historical steps. Commit 98d8515d02da7984b3881dd53b042cf870d34e34 qualified the conformance-rules is-modifier statement after a FHIR-I Zulip discussion of GF#17688. Commit f283fcb089a0b386ec4c026fa45ef060998defb4 then changed source/narrative.html to the exact requested "Resource instances that permit narrative" wording cited by the Jira resolution. The modifier-extension text cited as already partly addressed traces to FHIR-16423 commit fe5743607404d3b80d049da7a8fde4dc85be2d5d.

Additional context:
The current build-scoped source still contains the requested wording in source/narrative.html, and source/fhir.ini actively maps Narrative and the narrative type page. A later Published issue, FHIR-18356, intentionally narrowed the narrative page modifier-extension prose to modifier extensions on elements described by the narrative, while the Narrative.status code definition in source/datatypes/narrative.xml still carries the broad SHALL language. This later change explains the current wording difference and does not reopen FHIR-17688.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current conformance-rules, narrative page, and Narrative datatype source already preserve the applied FHIR-17688 requirements after accounting for the related modifier-extension decisions.

Recommendation:
Keep this no-change audit commit as-is. No core FHIR follow-up is needed for FHIR-17688; changing the current narrative text would either duplicate existing guidance or risk undoing the later FHIR-18356 scope clarification.
