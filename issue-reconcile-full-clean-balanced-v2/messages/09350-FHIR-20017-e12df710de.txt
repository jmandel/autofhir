FHIR-20017: Audit min/max ValueSet binding extensions

Issue request:
FHIR-20017 was a Published/Persuasive FHIR-core change request raised against STU3 and applied for R5. It asked to indicate extensible binding types for the elementdefinition-minValueSet and elementdefinition-maxValueSet extension pages.

Initial application:
No current source commit explicitly mentions FHIR-20017. The Jira comment from 2022 says this looked like a resolved tooling issue, and the current Extension Pack definitions already carry the requested applicability: minValueSet says it is for binding strength 'required' or 'extensible', and maxValueSet says it is used over a less restrictive binding and usually where the base binding is 'extensible'.

Additional context:
The current FHIR core checkout does not have active source definitions for these extension pages, and source/fhir.ini has no active minValueSet or maxValueSet entry. Later R5/R6 work added ElementDefinition.additionalBinding and current core terminology text describes minimum and maximum additional binding purposes as replacing the old extensions. FHIR-43156 and FHIR-46445 then deprecated the Extension Pack definitions in favor of additionalBinding, and FHIR-50652 updated current core terminology prose to stop recommending minValueSet as the active mechanism.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core source is not missing active extension-page wording, the externally maintained extension definitions already state the requested binding applicability, and the current core guidance correctly points implementers to additional bindings instead of reviving deprecated extension prose.

Recommendation:
Keep this no-change audit commit as-is. Future maintenance, if any, should stay aligned with the Extension Pack definitions and additionalBinding guidance; no bounded core source fix is indicated for FHIR-20017.
