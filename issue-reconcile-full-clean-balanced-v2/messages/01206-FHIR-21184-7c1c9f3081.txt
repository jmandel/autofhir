FHIR-21184: Record CQFM proportion profile external ownership

Issue request:
FHIR-21184 was a Published/Persuasive FHIR-core Change Request from CQI asking to add a Denominator Exception slice to the CQFM Proportion Measure Profile. The Jira resolution agreed to add the slice, with vote Bryn Rhodes/Yan Heras 18-0-0 on 2019-06-28 and applied-for version R5.

Initial application:
No Jira-tagged implementation commit was found in the current HL7/fhir history. The Jira application comment lists 1c7262a998477f9ef6bd63d6030ccb27a6826ba9, and GitHub identifies that SHA as an HL7/cqf-measures commit by Bryn Rhodes on 2019-10-17 whose message includes GF#21184 and changes the CQFM measure profile spreadsheet. That places the recorded application in the CQF Measures implementation guide repository, not this FHIR core checkout.

Additional context:
The current FHIR core build includes the base Measure resource and quality-reporting narrative, but it does not include the CQFM Proportion Measure profile or its canonical URL. The active core Measure source already permits the denominator-exception population code, and the current quality-reporting page marks Denominator Exception optional for proportion measures and includes it in the proportion calculation. The current HL7/cqf-measures source owns StructureDefinition/proportion-measure-cqfm and contains both the denominatorException slice and the constraint allowing denominator-exception for proportion measures.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR core source change. Adding a CQFM profile slice to core would edit an artifact that is not owned by or built from this repository; the requested correction belongs to, and is already present in, HL7/cqf-measures.

Recommendation:
Keep this empty external-repo audit commit as-is for FHIR core reconciliation. If future review finds a remaining CQFM profile problem, handle it in HL7/cqf-measures rather than in the core FHIR build.
