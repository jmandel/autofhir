FHIR-7582: Audit AllergyIntolerance active status handling

Issue request:
FHIR-7582 was a Published/Persuasive with Modification Patient Care change request raised against DSTU1 AllergyIntolerance. It asked how to represent active or resolved allergies and requested a way to distinguish clinical activity from certainty, with the approved resolution to add `active` as a parent/ancestor for `confirmed` and `unconfirmed` and to define all AllergyIntolerance status codes; `resolved` was already an existing code.

Initial application:
No single clean seed-only commit exists in the current git history, but the 2015-08-20 application set is identifiable. Commit 895df7d512162acde0f7ccde8a9cdfb19d0290a9 added the `active` AllergyIntolerance.status code, made `unconfirmed` and `confirmed` children of it, and updated the status short label. The adjacent commit 4aafeeebac46b47f643f2d49a5a619d0cb000f72 explicitly cites `#7582 - added status "active"`; its AllergyIntolerance source hunk was example/criticality cleanup, which suggests the status-source change had just landed in the preceding generated/source spreadsheet update.

Additional context:
Later Published Patient Care issues refined and then superseded the old combined AllergyIntolerance.status hierarchy. FHIR-8599 added an `inactive` parent for resolved/refuted/entered-in-error; FHIR-10067 clarified the old status definitions and renamed `confirmed` to `active-confirmed`; FHIR-11206 moved entered-in-error out of the inactive hierarchy; and FHIR-11151 replaced the mixed status element with separate `clinicalStatus` and `verificationStatus` elements. The current resource is in build scope through `source/fhir.ini`, and the current build-scope StructureDefinition now has `AllergyIntolerance.clinicalStatus` for `active | inactive | resolved` and `AllergyIntolerance.verificationStatus` for certainty/error states including `unconfirmed`, `presumed`, `confirmed`, `refuted`, and `entered-in-error`. Current THO terminology definitions also define `active` and `resolved`, and keep certainty in the verification code system.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The original FHIR-7582 need is preserved in the current split representation: implementers can represent an active confirmed allergy as clinicalStatus=active plus verificationStatus=confirmed, an active unconfirmed allergy as clinicalStatus=active plus verificationStatus=unconfirmed, and a resolved allergy with clinicalStatus=resolved. Reintroducing an `active` ancestor under the obsolete combined status model would be wrong for the current specification.

Recommendation:
Keep this audit commit as-is. No current FHIR core source change is needed for FHIR-7582; any future change to the external allergy status code systems should go through the normal terminology/UTG process and account for the later FHIR-11151 split.
