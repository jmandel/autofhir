FHIR-27848: Audit trusted-expansion url type

Issue request:
FHIR-27848 was a Published FHIR-core/Vocabulary change request, resolved Persuasive with Modification for R5, asking that the valueset-trusted-expansion extension value type change from uri to url because the trusted expansion reference must be resolvable. The Jira resolution explicitly limited this issue to the datatype change and said the extension text would be handled in FHIR-23785.

Initial application:
No core commit was found with FHIR-27848 in its message. The R5 VSD Profile source change 9fca6ca36fefa544491b1efc7fdb1530333ed78b changed source/valueset/structuredefinition-extension-valueset-trusted-expansion.xml from code value="uri" to code value="url" while applying the related trusted-expansion text update; that attempt was reverted and then re-applied by 054eabf3116825c0f65107fedff6668447bf43a1. Before the R5 extension-source removal, the core definition still had value[x] type url. Later cleanup commit dd468d4f1799dd79819315b211588ef1cf4586e0 removed the ValueSet extension StructureDefinitions, including valueset-trusted-expansion, from the FHIR-core checkout.

Additional context:
ValueSet remains an active core resource, but source/fhir.ini has no active valueset-trusted-expansion extension definition and current core source only retains the extension OID in source/oids.ini. The maintained definition now lives in HL7/fhir-extensions at input/definitions/ValueSet/StructureDefinition-valueset-trusted-expansion.xml, where the canonical URL is still http://hl7.org/fhir/StructureDefinition/valueset-trusted-expansion and Extension.value[x] has type url. FHIR-23785 was voted on the same Vocab call for the text change; later FHIR-27028 narrowed the comment to a FHIR terminology server endpoint; and FHIR-40707, in the FHIR-extensions project, updated the external definition/description wording through HL7/fhir-extensions#120.

AutoFHIR reconciliation:
This commit intentionally makes no source change in the FHIR-core checkout. Re-adding or editing the extension definition in core would reverse the current extension ownership split, and the seed's requested datatype is already correct in the Extension Pack source that now owns the artifact.

Recommendation:
Keep this audit commit as-is for core. Future datatype or wording changes for valueset-trusted-expansion should be made in HL7/fhir-extensions; FHIR-23785 and FHIR-27028 can be audited separately if a text-focused reconciliation is needed, but no FHIR-core source edit is needed for FHIR-27848.
