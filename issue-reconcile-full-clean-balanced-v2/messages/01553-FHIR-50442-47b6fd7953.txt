FHIR-50442: Audit DeviceRequest diagram pointers

Issue request:
FHIR-50442 was an Applied, Persuasive OO change request for R6 asking that the Device module diagram adjust DeviceRequest pointers: DeviceRequest.subject should primarily point to Patient rather than only Device, and DeviceRequest.requester should start by pointing to Practitioner or PractitionerRole. Jira records a 10-0-0 OO vote and says the change was applied through FHIR-50445.

Initial application:
No source commit naming FHIR-50442 was found. The application trail points to FHIR-50445, and HL7/fhir PR #3836 / commit ff73a37610 added images/DeviceModule.svg, registered it in publish.ini, and changed source/device-module.html to replace the old PNG with the current SVG and clarify that the diagram shows representative relationships rather than every valid reference.

Additional context:
The Device module page is active build source through source/hierarchy.xml and publish.ini, and publish.ini includes DeviceModule.svg as a built image. The current authoritative DeviceRequest definition allows DeviceRequest.subject to reference Patient, Group, Location, or Device, and DeviceRequest.requester to reference Practitioner, PractitionerRole, Device, Organization, CareTeam, Group, Patient, or RelatedPerson. The rendered current SVG shows DeviceRequest relationships toward Patient/person actors as well as Device, while the module prose tells readers to review the resource definitions for all valid relationships.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build-scoped source already contains the applied representative-diagram wording and points to the replacement SVG; the remaining issue scope is diagram presentation, and the checked-in generated-looking SVG already includes the requested DeviceRequest relationship surface. Editing only the SVG would not be an appropriate AutoFHIR source correction.

Recommendation:
Keep this no-change audit commit. No FHIR-50442 follow-up is needed unless OO later decides to regenerate the Device module diagram from its source-of-truth for a presentation-only update.
