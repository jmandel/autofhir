FHIR-30891: Audit originalText narrative linking

Issue request:
FHIR-30891 was a Published FHIR-core change request, resolved Persuasive with Modification for R5. It reported that the Narrative Linking examples used originalText with valueUrl while the originalText extension was then string-only, and asked for clearer separation between originalText and narrativeLink. The approved resolution was to allow originalText to support both string and url and clarify that originalText with url points to the original wording encoded by the referencing element, while narrativeLink only associates data and text without claiming derivation.

Initial application:
No core or Extension Pack commit with an explicit FHIR-30891 tag was found. The core Narrative Linking section predates the issue in git commit e9f8d78996d66a0511b02dd92e6e0b60a1615da8 and already used originalText with valueUrl; source/fhir.ini keeps narrative.html in current build scope as a type page. Current authoritative extension source is in the FHIR Extension Pack, where originalText already permits both string and url and the originalText/narrativeLink comments distinguish derivation from non-derivation.
