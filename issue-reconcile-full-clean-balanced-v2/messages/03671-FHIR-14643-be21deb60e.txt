FHIR-14643: Audit Condition recordedDate wording

Issue request:
FHIR-14643 was a Published / Persuasive with Modification Patient Care tracker for STU3 Condition. It asked whether Condition.assertedDate's long definition, "The date on which the existence of the Condition was first asserted or acknowledged," or the Condition page short text, "Date record was believed accurate," was correct, and resolved to clarify the short/definition/comments around the date the record was first recorded/created in the system.

Initial application:
The seed was not left as a literal assertedDate wording edit. Its Jira comment says GF#17285 superseded it for the recorded-versus-asserted clarification. Historical commit 722ed5c93f4bc9828e96f0f5b476bedc3486fb92 explicitly includes GF#14643, GF#15781, and GF#17285 and changed Condition by moving assertedDate out of the core resource and adding core Condition.recordedDate with "Date record was first recorded" and the system-created definition. Later source refactors moved the authoritative definition into source/condition/structuredefinition-Condition.xml.

Additional context:
FHIR-17285 is the governing same-family Published decision: move assertedDate to an extension and add recordedDate to core for AllergyIntolerance and Condition. Later Published Condition trackers FHIR-27808, FHIR-34392, and FHIR-34394 refined recordedDate without reversing that core decision: recordedDate remains the first/created record date, can be preserved from a sending system, and contrasts with recorder as the most recent author. The current source/fhir.ini actively includes the Condition resource, while the old assertedDate element is absent from the Condition resource source except for version-conversion mappings. The condition-assertedDate extension now lives in the FHIR Extension Pack, outside the core resource source.

AutoFHIR reconciliation:
This is an empty no-change audit commit. The current active Condition source already resolves the seed inconsistency: Condition.recordedDate has short "Date condition was first recorded," defines the value as when the Condition record was created in the system, and includes later WG-approved comments on preserving sender recordedDate values and contrasting recorder. No source hunk is necessary.

Recommendation:
Keep this audit as-is. Do not reintroduce assertedDate into core or edit the current recordedDate wording for FHIR-14643; any future changes should be driven by newer Condition recordedDate or Extension Pack assertedDate trackers, not this superseded STU3 clarification.
