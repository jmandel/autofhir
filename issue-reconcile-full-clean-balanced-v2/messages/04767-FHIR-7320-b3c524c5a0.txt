FHIR-7320: Audit Claim hospitalization period handling

Issue request:
FHIR-7320 was Published with a Persuasive with Modification resolution for DSTU1. It requested an admit/discharge date-time representation because service dates might not cover an entire hospitalization, and the accepted resolution said to add a 0..1 Claim header hospitalization Period following EpisodeOfCare and Encounter patterns.

Initial application:
No commit with an explicit FHIR-7320/Jira key was found in the local git history. The closest historical application is git commit 649fcd4cbf21557ae6db78e0afb908f3030dad7a, "Updates to claim", which added Claim.hospitalization 0..1 Period to the Claim spreadsheet with a "Period in hospital" label and also added Claim.billablePeriod.

Additional context:
Claim is active in source/fhir.ini. Later Published issue FHIR-13826 changed the same area: commit 4a2f618cfd6a35e6bf8445eab10ac7310da3de6c removed standalone Claim.hospitalization from examples and represented hospitalization through Claim.information with the hospitalized category and a timingPeriod. Subsequent R4 refactoring in afb5ec66f68641293bb7950b6e0eeb118fa1444a renamed Claim.information to Claim.supportingInfo. The combined branch already contains a separate FHIR-13826 audit commit, efadbcfd8350e31147a8869617165b8b1b57dd33, confirming this later representation.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because current Claim source has Claim.supportingInfo.category bound to claim-informationcategory, Claim.supportingInfo.timing[x] permits Period, and current examples encode hospitalization with the hospitalized category and timingPeriod. Restoring a standalone Claim.hospitalization element would conflict with the later published FHIR-13826 decision.

Recommendation:
Keep this audit commit as-is. Do not re-add the retired standalone Claim.hospitalization field; use Claim.supportingInfo with the hospitalized category and timingPeriod for hospitalization/admit-discharge periods. Any future expansion of admission/discharge category codes should proceed through the separate UTG/THO proposal process, not this closed DSTU1 core tracker.
