FHIR-26883: Add RiskAssessment reason example binding

Issue request:
FHIR-26883 was an Applied/Persuasive CDS change request for FHIR-core RiskAssessment. The original report noted that RiskAssessment.prediction.outcome had an example binding with no valueSet target, and the accepted resolution was to provide example bindings for RiskAssessment.code, RiskAssessment.method, RiskAssessment.reason, and RiskAssessment.prediction.outcome.

Initial application:
The Jira was later marked applied with GitHub PR HL7/fhir#3369. That PR's RiskAssessment implementation commit 62c04424203f3ad49adb430c60369e446af78c00, labeled in the PR as FHIR-38925, added concrete example ValueSets/CodeSystems and valueSet targets for method, code, and prediction.outcome. It did not add any binding to RiskAssessment.reason, leaving one accepted FHIR-26883 element unapplied.

Additional context:
RiskAssessment is active in source/fhir.ini, so source/riskassessment/structuredefinition-RiskAssessment.xml and its workflow mapping exceptions feed current build behavior. Later FHIR-55077 renamed the RiskAssessment method/outcome terminology artifacts to Example canonicals, but it did not address reason. The workflow Event pattern still records Event.reason as an unbound reason binding concept, while comparable clinical reason CodeableReference elements use existing example ValueSets such as condition-code; that existing value set is a narrow source fix and avoids creating unsupported RiskAssessment-specific terminology.

AutoFHIR reconciliation:
Added an example binding on RiskAssessment.reason with bindingName RiskAssessmentReason and valueSet http://hl7.org/fhir/ValueSet/condition-code. Removed the stale RiskAssessment Event mapping exception that said the resource lacked a binding for Event.reason. No generated diagram/SVG files were edited.

Recommendation:
Keep this source fix. It completes the accepted FHIR-26883 resolution without changing cardinality, target profiles, or binding strength, and it aligns the RiskAssessment workflow mapping exceptions with the authoritative StructureDefinition.
