FHIR-22681: Audit profile element ids

Issue request:
FHIR-22681 was Published/Persuasive for R5 and reported that generated profiles-others output for profiles such as respiratory rate rendered typed choice element ids as Observation.valueQuantity with path Observation.valueQuantity, when the choice slice id should use Observation.value[x]:valueQuantity according to ElementDefinition.id rules.

Initial application:
The Jira comment says this was part of regenerating snapshots, but no current source commit explicitly mentions FHIR-22681. Current source history shows the respiratory-rate profile and sibling vital-sign profiles were later corrected by the FHIR-39181 reconciliation commit, which replaced obsolete Observation.valueQuantity profile element ids with typed choice slice ids.

Additional context:
source/fhir.ini lists Observation as an active current resource, and source/observation/implementationguide-Observation-vitalsigns.xml includes StructureDefinition/resprate, so the respiratory-rate profile remains in current build scope. The current ElementDefinition documentation says type-choice ids reflect the type slice, for example Patient.deceased[x]:deceasedBoolean. FHIR-39181 later generalized the same problem by stating that choice type renaming is no longer supported and that profiles should use ids such as Observation.value[x]:valueQuantity; the combined branch already contains a source-changing FHIR-39181 commit for the active vital-sign profiles. No directly relevant Zulip or Confluence record for FHIR-22681 was found.

AutoFHIR reconciliation:
Made no source change. The active respiratory-rate profile now has element id Observation.value[x]:valueQuantity, path Observation.value[x], sliceName valueQuantity, and type Quantity, and a search of current Observation profile XML found no remaining obsolete Observation.valueQuantity element ids or paths of the kind reported by FHIR-22681.

Recommendation:
Keep this audit commit as-is. The current source is correct for the seed issue because the later FHIR-39181 fix already applied the typed-choice id representation to resprate and the related active vital-sign profiles; no additional core source edit is needed for FHIR-22681.
