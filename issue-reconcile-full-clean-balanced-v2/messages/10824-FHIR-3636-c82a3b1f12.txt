FHIR-3636: Add missing patient search parameters

Issue request:
FHIR-3636 was Published/Persuasive for DSTU1. It asked that every resource in the Patient compartment have a patient search parameter so callers can use a consistent parameter name even when the underlying patient link element has a resource-specific name.

Initial application:
The Jira comments record editor approval on the 2014-10-29 MnM call and application in SVN revision 3288, with all then-current cases considered obvious. No Git commit in the converted repository mentions FHIR-3636, but the current source already contains patient search parameters and the clinical-patient common registry entry for the rest of the active non-root Patient-compartment resources.

Additional context:
The current Patient compartment matrix still lists active Group membership through member and active Schedule membership through actor, and both reference elements can target Patient. Before this reconciliation, Group and Schedule were the only active non-root resources with a Patient-compartment entry but no patient search parameter. The Patient resource itself remains a compartment root handled by the compartment identity/{def} rule rather than by a self-referential patient search parameter. Later unresolved Jira issues FHIR-56547 and FHIR-57217 discuss broader or indirect Patient-compartment membership problems, but they are not final decisions and do not contradict adding direct Patient-targeted parameters for Group.member.entity and Schedule.actor.

AutoFHIR reconciliation:
This commit adds Group-patient and Schedule-patient reference SearchParameters filtered to Patient targets, and adds Group and Schedule to the clinical-patient common SearchParameter base list. The edited search-parameter bundles and common registry file are active current build inputs for the active Group, Schedule, and SearchParameter resources.

Recommendation:
Keep this source fix. It completes the directly checkable FHIR-3636 consistency gap for the current active Patient compartment while leaving broader indirect Group-to-Patient compartment questions to their pending Jira trackers.
