FHIR-13738: Audit ConceptMap cmd-3 url wording

Issue request:
FHIR-13738 was a Published/Persuasive STU3 Vocabulary change request for ConceptMap. It reported that invariant cmd-3 said "a code must be provided" even though the constraint required a url, and requested the human text be changed to reference url.

Initial application:
The issue was explicitly applied in git commit 677b2ad4b8 (svn revision 13449), which changed the old ConceptMap spreadsheet cmd-3 human text from "a code must be provided" to "a url must be provided" while leaving the url.exists() expression intact.

Additional context:
ConceptMap is an active build resource in source/fhir.ini. The old spreadsheet source was replaced by structuredefinition-ConceptMap.xml in the 2021 source refactor, and later ConceptMap2/ConceptMap cleanup renamed ConceptMap.group.unmapped.url to ConceptMap.group.unmapped.otherMap while preserving the intended URL/canonical-map requirement. The current source maps the legacy url element name to otherMap and cmd-3 now says "a url for the other map must be provided" with expression otherMap.exists(). Jira neighborhood, Zulip, and Confluence searches found no later or conflicting issue/discussion for this cmd-3 wording.

AutoFHIR reconciliation:
No source change was made. The current build-scope ConceptMap StructureDefinition already uses the corrected url wording and its current expression targets the renamed otherMap element.

Recommendation:
Keep this no-change audit commit as-is. No follow-up is needed in core unless a future work group decision changes the ConceptMap.group.unmapped.otherMap constraint itself.
