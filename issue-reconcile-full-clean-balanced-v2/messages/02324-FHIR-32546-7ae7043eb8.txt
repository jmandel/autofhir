FHIR-32546: Audit ConceptMap unmapped source-code mode

FHIR-32546 was a Published / Persuasive with Modification Vocabulary issue for ConceptMap. It asked to remove the confusing concept code 'provided' from the ConceptMap unmapped-mode code system/value set and replace it with 'use-source-code', with a definition explaining that the translated code is the code supplied in the $translate request input.

Initial application:
The Jira comments identify an initial application as 37901c7dc7 and a reworked application as d37b9d240a. The reachable source history contains d37b9d240a, which created the temporary ConceptMap2 unmapped-mode code system/value set using 'use-source-code', and 8623473ddf later migrated ConceptMap2 back into the active ConceptMap source. Later QA cleanup removed generated narrative but retained the concept code and definition.

Additional context:
The current build includes ConceptMap as an active resource in source/fhir.ini. The active ConceptMap unmapped-mode CodeSystem now contains code 'use-source-code' and no code value 'provided'; ConceptMap.group.unmapped.mode is bound to the current value set and lists 'use-source-code | fixed | other-map'. The current $translate operation names the relevant inputs sourceCode, sourceCoding, and sourceCodeableConcept, so the current definition's source-prefixed parameter names align with the present operation surface. Confluence VOC minutes record the 2021-06-23 decision to replace 'provided' with 'use-source-code', and a later Zulip implementer thread points R4 users to the R5 rename rather than identifying a conflicting current requirement.
