FHIR-20351: Audit DocumentReference EpisodeOfCare removal

Issue request:
FHIR-20351 was a Published/Persuasive R5 OO request to remove EpisodeOfCare as a possible target from DocumentReference.context.encounter after EpisodeOfCare had been removed from encounter elements elsewhere, while ensuring the standard episode-of-care extension remained usable on DocumentReference.

Initial application:
The issue appears to have been applied by commit 24ebc2aadefd4ba91d3d5380d091e15c61a202e2, which explicitly listed GF#20351 and changed the then-authoritative DocumentReference spreadsheet from Reference(Encounter|EpisodeOfCare) to Reference(Encounter) for context.encounter.

Additional context:
FHIR-15658 had earlier added EpisodeOfCare to DocumentReference.context.encounter, and FHIR-20351 reversed that state for the pre-R5 element. A later Published/Persuasive with Modification R5 decision, FHIR-29801, explicitly directed adding Appointment and EpisodeOfCare to .encounter and renaming .encounter to .context. The current active DocumentReference StructureDefinition implements that later decision as DocumentReference.context with Appointment, Encounter, and EpisodeOfCare target profiles. FHIR-54170 later clarified the element description because the current context target set includes Appointment and EpisodeOfCare. The workflow-episodeOfCare standard extension is now maintained in the Extension Pack and declares DocumentReference as an allowed context.

AutoFHIR reconciliation:
No source change was made. Removing EpisodeOfCare from the current DocumentReference.context element would undo the later FHIR-29801 work-group decision and conflict with the current clarified R6 wording. The seed's original removal was historically applied, but it has been superseded by the later context redesign.

Recommendation:
Keep this audit commit as-is. Do not remove EpisodeOfCare from DocumentReference.context for FHIR-20351 unless a newer OO decision explicitly reverses FHIR-29801/FHIR-54170. Treat any extension-pack maintenance for workflow-episodeOfCare as external to this core-source audit; the current extension-pack source already permits DocumentReference.
