FHIR-37932: Audit GenomicStudy multi-subject handoff

Issue request:
FHIR-37932 was Published with a Persuasive with Modification resolution for R5. It asked GenomicStudy to support tests involving multiple patients and specimens, including trio testing, by widening analysis-level subject/specimen modeling, removing GenomicStudy.analysis.input.subject and .role, guiding use of DocumentReference.subject/Group for multi-subject files, and adding trio/somatic use-case notes.

Initial application:
The issue was applied through HL7/fhir pull request #2217, merged as d501bdc8133bf7c95908750f07559c2d39d4079c. That merge widened GenomicStudy subject/focus reference targets, changed GenomicStudy.analysis.specimen from 0..1 to 0..*, removed the input subject/role children from the model, added a Group-based trio example, and added trio and somatic mutation use-case notes. The residual core GenomicStudy source still contains those applied R5 changes.

Additional context:
GenomicStudy is no longer an active core resource in the current build: source/fhir.ini has no active GenomicStudy resource/workgroup/status entries, and commit fad1b9cf84ef652e88947e1a13b026c62f95334e removed the additional GenomicStudy and MolecularDefinition resources from core build configuration. The current core Genomics page instead links GenomicStudy to the HL7 Clinical Genomics Resource Incubator IG. The CG incubator repository actively includes GenomicStudy as a special-url/additional resource for FHIR 6.0.0-ballot3 and preserves the relevant multi-subject guidance and specimen cardinality.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. Editing source/genomicstudy would not affect the current core build, and the current core build already delegates GenomicStudy ownership to the CG incubator IG where future resource edits belong.

Recommendation:
Keep this external-repo audit as-is for FHIR core. If Clinical Genomics wants additional GenomicStudy changes beyond the R5-applied FHIR-37932 behavior, make them in HL7/cg-incubator rather than reactivating or editing the inactive core resource directory.
