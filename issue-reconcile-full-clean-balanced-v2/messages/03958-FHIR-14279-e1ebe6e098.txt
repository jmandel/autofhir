FHIR-14279: Audit PlanDefinition realization result placement

Issue request:
FHIR-14279 was Published/Persuasive for STU3 and asked where the resource produced by a PlanDefinition.action ActivityDefinition or StructureMap realization is stored. The accepted resolution was to add clarifying language to the PlanDefinition realization documentation explaining how realization proceeds and where the expected ActivityDefinition result is placed.

Initial application:
The Jira-commented SVN application is present as git commit 2025a5b26f38c7fa5c473f779f6ac7c503fb21e9, which records GF#14279 / SVN 13325. It added Applying-a-PlanDefinition narrative saying the ActivityDefinition target resource is created, referenced from the generated RequestGroup action.resource, and either contained or persisted independently, and it added ActivityDefinition guidance that StructureMap transform output is then modified by dynamicValue elements.

Additional context:
PlanDefinition and ActivityDefinition are active current-build resources in source/fhir.ini. Later PlanDefinition $apply work, especially FHIR-33169 and the RequestGroup-to-RequestOrchestration rename, intentionally replaced the older CarePlan/RequestGroup placement model with a Bundle-per-subject model whose first entry is a RequestOrchestration and whose other entries include the resources created while applying actions. Related PlanDefinition/ActivityDefinition reconciliation commits for FHIR-14280, FHIR-14283, FHIR-19501, and FHIR-28193 are already represented on the combined branch, so they are context rather than additional decisions here.

AutoFHIR reconciliation:
Made no source change. Current PlanDefinition narrative already says to create a result Bundle, create a RequestOrchestration, create the target resource as described by ActivityDefinition, reference the resulting resource in RequestOrchestration.action.resource, add it as an entry in the result Bundle, and treat the operation result as transient rather than server-persisted. Current ActivityDefinition narrative still explains StructureMap transform and dynamicValue processing. Adding new wording would duplicate existing guidance or reintroduce superseded STU3 containment/persistence wording.

Recommendation:
Keep this audit commit as-is. The current source satisfies FHIR-14279 after later PlanDefinition $apply refinements; no follow-up source edit is needed for this issue.
