FHIR-7591: Audit local-code interoperability note

Issue request:
FHIR-7591 was a Published FHIR-core vocabulary change request from the DSTU1 cycle asking that profiling guidance not allow local, custom, or proprietary terminology codes in interoperable profiles. The final resolution was Not Persuasive with Modification: keep the ability to declare local code use, but add a sentence noting that local codes are not as interoperable as publicly defined/standard codes.

Initial application:
The request was applied in Subversion revision 5674, imported as git commit fa1a4b9f34, which added the local-code interoperability note to source/profiling.html. Later source history retained the note while fixing its SNOMED CT punctuation/wording and updating the surrounding profiling terminology from ValueSet-defined local codes to CodeSystem-carried local codes plus ValueSet mixtures.

Additional context:
The current source/profiling.html page is active in the build hierarchy under the Conformance module. The present Mixing Custom and Standard Terminologies section still permits local-code declarations for accurate profiling, but it also says local codes are less interoperable than standard published code systems and that standard code systems are preferable. Jira search found no tighter current FHIR-core issue superseding this DSTU1 decision, and Zulip/Confluence searches found no directly relevant conflicting community discussion.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already implements the approved modification and matches the issue's final disposition; prohibiting all local/proprietary codes would contradict the Not Persuasive with Modification decision and the editor comment that profiles should declare what systems actually do.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-7591 unless the Vocabulary work group opens a new issue to change the policy from warning against local codes to disallowing them.
