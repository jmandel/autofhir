FHIR-31563: Audit gateway device references

Issue request:
FHIR-31563 was a Published/Persuasive with Modification OO change request, raised against R4 and applied for R5. It asked how to model gateway and sensor device relationships: keep Device.parent and DeviceDefinition.parentDevice as 0..1 hierarchy fields while removing "attached to" from Device.parent, and add related-device structures so Device could point to associated/gateway/connected/replaced devices and DeviceDefinition could list supported/associated gateway or related device definitions.

Initial application:
The issue appears to have been applied before this reconciliation in Jira-tagged commits bc6378b7ac and 58b93a890b, which added Device.link, DeviceDefinition.link, and device/devicedefinition relation terminology. The Device.parent wording part was later finalized by FHIR-34310 commits 6d6388768b and a552df470b. FHIR-36828 commit 3932ce4be6 then intentionally simplified Device.link to Device.gateway for R5.

Additional context:
Device and DeviceDefinition are active in the current build. DeviceDefinition.link remains active and uses a relation value set plus relatedDevice[x] to express associated/supported gateway-type relationships. Device.parent now has hierarchy-only wording and no longer defines parent as "attached to". For Device instances, later R6 decisions changed the current target state: FHIR-32565 moved Device.gateway and related communication elements out of core, and FHIR-47326 created the device-gateway extension in the FHIR Extension Pack. Existing combined-branch audit commits already represent FHIR-34310, FHIR-34311, FHIR-36828, and FHIR-32565, so this seed should not duplicate those decisions.

AutoFHIR reconciliation:
This empty commit intentionally makes no source change. The current source is correct after the later approved decisions: DeviceDefinition still supports related gateway definitions, Device.parent has the intended hierarchy-only wording, and the current Device gateway-instance mechanism belongs to the Device Gateway extension rather than a reintroduced core Device.link or Device.gateway element.

Recommendation:
Keep this audit commit as-is. Do not reintroduce Device.link or active Device.gateway into current core for FHIR-31563; any future gateway representation changes should be handled as current R6 or Extension Pack work.
