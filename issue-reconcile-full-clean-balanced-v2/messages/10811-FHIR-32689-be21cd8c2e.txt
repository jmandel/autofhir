FHIR-32689: Audit TestScript conformance codes outside core

Issue request:
FHIR-32689 was Published/Persuasive with Modification for R5 by FHIR-I. It originally asked to add a TestScript.scope.conformance code value of recommended and to correct mismatched code/display values. The final approved disposition did not add recommended; it updated required to allow warnings, kept optional, and added strict for cases where warnings are treated as failures.

Initial application:
The issue was applied in core by commit 2dea2a39f38e90040b839591d0261cb44ee589e0, merged by PR #1681 as d2e9af0c937606a967d5f4df4539cdcd3f0a573c. That commit changed source/testscript/codesystem-testscript-scope-conformance-codes.xml to use required/Required, optional/Optional, and strict/Strict with the approved definitions, and changed source/testscript/structuredefinition-TestScript.xml so TestScript.scope.conformance listed required | optional | strict. The commit is contained in the v5.0.0 tag.

Additional context:
The same implementation commit also applied FHIR-35952, but that separate TestScript assertion-constraint issue is already represented on the combined branch and is not being republished here. Current core no longer owns TestScript source: commit f9a44787c45071394532c7c2ee94d76f30f47387 removed source/testscript and the active TestScript fhir.ini entries while adding the FHIR Testing IG as an external IG. Current source/fhir.ini and source/ballot-intro.html point TestScript to HL7/fhir-testing-ig, and git ls-files source/testscript returns no tracked core build inputs. The current Testing IG CodeSystem and TestScript StructureDefinition still carry the required/optional/strict value set semantics approved for this issue.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The approved R5 terminology change was historically applied while TestScript was in core, and the authoritative current TestScript artifacts are maintained outside this core checkout.

Recommendation:
Keep this external-repo audit commit as-is for core. If FHIR-I wants to change TestScript.scope.conformance codes again, make that follow-up in HL7/fhir-testing-ig rather than reintroducing removed TestScript source in core.
