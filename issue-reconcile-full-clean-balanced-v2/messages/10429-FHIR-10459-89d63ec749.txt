FHIR-10459: Audit all-resource search URL correction

Issue request:
FHIR-10459 was a Published/Persuasive with Modification DSTU2 FHIR-core issue asking to reconcile two all-resource search URL forms. The accepted technical correction was to change the all-resource GET example from `GET [base]/_search?parameter(s)` to `GET [base]?parameter(s)`.

Initial application:
The issue was applied by git-svn commit db60fdfac76abb1a0e57e548359eab6250dfc5c5, svn revision 10386. That commit changed the Search page's all-resource context from `GET [base]/_search?parameter(s)` to `GET [base]?parameter(s)` and changed the HTTP summary table's all-resource GET path from `/_search?` to `?`.

Additional context:
FHIR-5700 is the earlier root-search baseline: it retained all-resource search but limited it to all-resource parameters. Later FHIR-13836 and FHIR-36347 refined the same root-search parameter rules, and FHIR-12148 added explicit cross-resource _type support. None of those later decisions restore `GET [base]/_search` as the all-resource GET form; current POST-based root search remains `POST [base]/_search`, which is not the URL form FHIR-10459 asked to remove.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current combined-branch HTTP source shows all-resource GET search as `GET [base]?[parameters]` and the HTTP summary table uses path `?` for search-system GET. The current Search page's all-resource context shows `GET [base]?parameter(s)`. The stale `GET [base]/_search?parameter(s)` GET form from the issue request is not present in the active source checked for this reconciliation.

Recommendation:
Keep this audit commit as-is. The accepted URL correction is already applied, and changing the valid POST `POST [base]/_search` form would be outside the issue request and would contradict current HTTP search syntax.
