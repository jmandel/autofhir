FHIR-19342: Redirect old registry page

Issue request:
FHIR-19342 was Published/Persuasive for FHIR-core as a non-substantive STU3 technical correction. It asked to create a redirect from the advertised old registry address, http://hl7.org/fhir/registry, to the actual registry address, https://registry.fhir.org/; the resolution was auto-approved.

Initial application:
No historical source commit explicitly applying FHIR-19342 was found. Current build-scoped source still published tools/html/registry/index.html as a registry landing page instead of a redirect, and a live check of http://hl7.org/fhir/registry showed it only canonicalized to the trailing-slash page and returned that landing page. Nearby history explains how the old address became advertised: git commit 00ab23e09b changed Defining Extensions from http://fhir.org/registry to http://hl7.org/fhir/registry, while later work added support for registry.fhir.org in tooling without changing the old registry page into a redirect.

Additional context:
The Zulip thread that prompted the Jira records Lloyd McKenzie identifying https://registry.fhir.org/ as the actual registry and asking Grahame Grieve to set up a redirect at the published location; Grahame agreed and asked for a task, after which Lloyd cited GF#19342. Confluence refs for FHIR-19342 found no directly relevant minutes. A separate AutoFHIR audit commit for FHIR-7542 already cites FHIR-19342 as later registry URL context, but it does not decide this issue or implement the old-address redirect.

AutoFHIR reconciliation:
This commit replaces the active tools/html/registry/index.html page with a small HTML redirect page that immediately refreshes to https://registry.fhir.org/, declares that URL as canonical, and leaves a fallback link for clients that do not follow the refresh. The file is in current build scope because publish.ini copies tools/html into the published output, so this is the source location that controls the /fhir/registry/ page.

Recommendation:
Keep this commit as-is. If HL7 web operations wants a true HTTP 301/302 for http://hl7.org/fhir/registry, that can still be added in deployment configuration, but the checked-in static source now implements the approved redirect behavior for the built page.
