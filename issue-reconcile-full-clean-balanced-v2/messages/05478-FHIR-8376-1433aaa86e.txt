FHIR-8376: Audit superseded Encounter participant codes

Issue request:
FHIR-8376 was a Published/Persuasive PA change request for DSTU1 asking to add the v3 ParticipationType codes SPRF, PPRF, and PART to the Encounter participant type value set so additional surgical and non-medical encounter participant roles were represented. The Jira resolution says the value set was updated as suggested.

Initial application:
The issue was initially applied by git commit 9b8489c7ed2bfbe4e4d08754fc02c7d4a3c2f20d, which added SPRF, PPRF, and PART to source/encounter/valueset-encounter-participant-type.xml. Same-day follow-up commits 362d64d4dc460f7241cf2d894f3b6cf8c89ca0e3 and 7f62dc520f65a3b95bcb3abc6acd16786e9f4ebe normalized that application into an explicit v3 ParticipationType include, and later terminology refactors preserved the include until the R5-era FHIR-36014 removal.

Additional context:
Encounter is an active current-build resource in source/fhir.ini, and Encounter.participant.type binds extensibly to http://hl7.org/fhir/ValueSet/encounter-participant-type. The current authoritative value set source no longer explicitly includes SPRF, PPRF, or PART because the later Published/Persuasive PA issue FHIR-36014 resolved to remove those three explicitly included v3 ParticipationType codes while leaving the other inclusions. PA WGM minutes record the FHIR-36014 persuasive vote and state existing systems using the removed codes would not be broken because the binding remains extensible. FHIR-36014 already has a reconcile audit commit on the combined branch, so this commit does not duplicate that issue.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding SPRF, PPRF, and PART for FHIR-8376 would conflict with the later FHIR-36014 decision, while the current source is correct when the full issue family is considered.

Recommendation:
Keep this audit commit as-is. If PA wants to reintroduce any of these v3 ParticipationType codes or further clarify recommended Encounter participant coding, that should be handled by a new targeted tracker rather than by reviving FHIR-8376.
