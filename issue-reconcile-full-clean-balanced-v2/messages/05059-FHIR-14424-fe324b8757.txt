FHIR-14424: Audit maternity encounter wording

Issue request:
FHIR-14424 was a Published/Persuasive Patient change request from the PA work group for STU3. It asked to clarify the Mother and newborn relationships wording from relating the singular encounter of a mother and baby "for" a maternity encounter to relating the encounters of a mother and her baby "in" a maternity encounter.

Initial application:
The requested wording was applied before this reconciliation by git commit 217f57fb93edafbb02a801e34f456a076e53ac90, titled "GF#14424: Clarification on wording for linkage of maternity encounters". That commit changed source/patient/patient-notes.xml from "To relate the encounter of a mother and her baby for a maternity encounter" to "To relate the encounters of a mother and her baby in a maternity encounter". The combined branch did not already contain an Issue-Reconcile-Key audit commit for FHIR-14424.

Additional context:
Patient is an active resource in source/fhir.ini, so source/patient/patient-notes.xml is current build-scope narrative. The maternity section descends from FHIR-9366's broader guidance to link mother and newborn with Patient/RelatedPerson/Person structures for ongoing relationships and Encounter.partOf for birth encounters. A newer FHIR-57419 request proposes adding fetal-record wording in the same section, but it is only Resolved - change required and is outside this applied/published reconciliation scope. Community searches found no direct FHIR-14424 references or conflicting Confluence minutes; the Zulip Mother/Child record thread shows broader implementation discussion but no final decision that changes this wording audit.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current source already contains the exact clarified wording requested by FHIR-14424, and adding more prose would go beyond the Jira request rather than correcting a current-spec defect.

Recommendation:
Keep this empty no-change audit commit as-is for FHIR-14424. Handle FHIR-57419 separately in a run that includes Resolved - change required issues or after it reaches Applied/Published, because that later fetal-record clarification is a different decision.
