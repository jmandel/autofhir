FHIR-11375: Audit ClaimResponse package-code terminology

Issue request:
FHIR-11375 is a Published/Persuasive with Modification FM change request from the DSTU2 ballot asking for a consistent term for the DRG, bundle, or equivalent package code in ClaimResponse. Although the description suggested adding `packageCode` near line-item service elements, the final resolution narrowed the approved change to renaming diagnosis `drg` to `packageCode`.

Initial application:
The Jira-tagged implementation commit d06f8787e6 (`Tracker #11375, 11376, 11391, 11392`) changed the historical spreadsheet sources for Claim and ExplanationOfBenefit from `*.diagnosis.drg` to `*.diagnosis.packageCode` and updated the short/definition/requirements text to "Package billing code". The same commit did not change ClaimResponse, and historical grep around that commit did not find a ClaimResponse diagnosis `drg` or `packageCode` child in the ClaimResponse spreadsheet source.

Additional context:
ClaimResponse is an active current resource in `source/fhir.ini`. The closely related FHIR-11376 audit is already present on the combined branch and confirms that no current ClaimResponse diagnosis-child package-code element remains. A later Published/Persuasive FM decision, FHIR-29688, superseded the diagnosis-child placement by adding `diagnosisRelatedGroup` at the root of Claim, ClaimResponse, and ExplanationOfBenefit and requiring removal of `resource.diagnosis.packageCode`; commit acb64eec3c applied the ClaimResponse root element that is still present in the current source.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because the current build has the approved ClaimResponse package billing concept as `ClaimResponse.diagnosisRelatedGroup`, there is no stale ClaimResponse diagnosis `drg` or `packageCode` element to rename, and reintroducing a diagnosis-child `packageCode` would conflict with the later FHIR-29688 model.

Recommendation:
Keep this audit commit as-is. Do not add a ClaimResponse diagnosis-child `packageCode`; any new FM change to package billing or DRG modeling should be handled as a new post-FHIR-29688 tracker.
