FHIR-34143: Audit abstract/interface structure flags

Issue request:
FHIR-34143 was a Published/Persuasive R5 technical correction asking that Structure tabs use the abstract flag for abstract types such as Base and BackboneType, and the interface flag for interface types such as CanonicalResource.

Initial application:
The Jira application record points to Kindling commit acffe7f. That external renderer commit changed TableGenerator.java so interface rows emit «I» linked to uml.html#interface and abstract rows emit «A» linked to uml.html#abstract. No FHIR core source commit mentioning FHIR-34143 was found, which is consistent with the defect living in rendering logic rather than in the type-definition source.

Additional context:
The current FHIR core source already marks Base and BackboneType as abstract build-scope infrastructure types in source/fhir.ini and marks CanonicalResource and MetadataResource as interface resources. CanonicalResource and MetadataResource source definitions also carry the structuredefinition-interface extension. Current build.fhir.org rendering shows Base and BackboneType with «A» and CanonicalResource and MetadataResource with «I».

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative source data and current rendered output already reflect the Jira-requested correction, and editing generated or unrelated source would not improve the current specification.

Recommendation:
Keep this no-change audit commit as-is. If this regresses, investigate the Kindling TableGenerator rendering path rather than the fhir.ini type classifications first.
