FHIR-6243: Audit ImagingStudy procedure binding decision

Issue request:
FHIR-6243 was a Published/Persuasive Imaging Integration issue from DSTU1 asking that ImagingStudy.procedure have at least an example binding to LOINC radiology orderables and that the ambiguous "procedure" definition be clarified, including whether the element should instead be a choice/reference to Procedure.

Initial application:
The issue was applied in the old spreadsheet source after FHIR-5998 changed ImagingStudy.procedure from a coded element to Reference(Procedure). Commit d2e4d8176d (svn revision 5634) added the approved LOINC radiology orderables guidance as a comment on Procedure.code rather than as a binding on ImagingStudy.procedure, matching the Jira comment that this was "made as a comment, since this is now a reference to procedure."

Additional context:
FHIR-11285 later revisited the same LOINC radiology orderables comment and resolved to remove it because ImagingStudy can be used outside radiology and implementers should select the value set appropriate for their environment. Commit b838ed23f3 removed that comment. Later R6 issues, including FHIR-47666 and FHIR-53025, refined and reaffirmed the current model: ImagingStudy.procedure is a Reference(Procedure) for the performed procedure(s), with notes distinguishing requested procedures via ServiceRequest from performed procedures via Procedure.

AutoFHIR reconciliation:
No source change was made. The latest combined branch already has ImagingStudy in active build scope, ImagingStudy.procedure defined as a Reference to Procedure with the performed-procedure definition, narrative notes explaining requested versus performed procedures, and no LOINC radiology orderables comment. Reintroducing a binding/comment requested by FHIR-6243 would conflict with the later Published FHIR-11285 decision.

Recommendation:
Keep this audit commit as-is. The current source is correct for FHIR-6243 when read with FHIR-5998 and FHIR-11285; do not restore radiology-specific LOINC guidance on ImagingStudy.procedure unless the Imaging Integration work group makes a new, narrower decision.
