Issue request:
FHIR-15670 was Published/Persuasive for STU3 Questionnaire and requested clarification that when a parent or ancestor item is disabled by enableWhen, child items are also hidden/disabled even if their own enableWhen logic would otherwise enable them.

Initial application:

The source was later refactored into the current XML StructureDefinition, where the same rule remains.

Additional context:
Questionnaire is an active core resource in source/fhir.ini. Later enableWhen and Questionnaire edits preserved the rule and added adjacent guidance for disabled dependency items; no searched Zulip or Confluence record was found that contradicts the Jira/source outcome. A broad Jira search surfaced FHIR-35957 in the SDC IG required-parent space, but that is outside this core Questionnaire enableWhen descendant-disable decision.

AutoFHIR reconciliation:
No source change was made. The active source/questionnaire/structuredefinition-Questionnaire.xml definition for Questionnaire.item.enableWhen already states: "When an item is disabled, all of its descendants are disabled, regardless of what their own enableWhen logic might evaluate to."
