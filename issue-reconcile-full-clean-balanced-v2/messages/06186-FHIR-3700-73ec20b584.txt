FHIR-3700: Audit AllergyIntolerance patient rename

Issue request:
FHIR-3700 is a Published/Persuasive FHIR-core Patient Care change request from DSTU1. It asked to apply the naming guideline that resources should use "patient" when the only reasonable subject is a Patient resource, so AllergyIntolerance.subject should be renamed to AllergyIntolerance.patient.

Initial application:
No pre-AutoFHIR git commit tagged FHIR-3700 was found. The Jira comment says "already done", and the implementation appears to be the same git-svn change used for the later ballot comment: abfa3dc8a71b155e9d632bc592bffb6bf02a4b08, whose subject is "#5400 - rename AllergyIntolerance.subject to allergyintolerance.patient" and whose git-svn-id is build@4397. That commit updated the AllergyIntolerance spreadsheet, examples, profiles, compartments, and generated Java model surfaces.

Additional context:
FHIR-5400 is the same AllergyIntolerance rename family and records the 2015 PC WG ballot disposition to make the element "patient". AllergyIntolerance is still an active current resource in source/fhir.ini. FHIR-39070 later clarified the AllergyIntolerance.patient short display and has already been reconciled on the combined branch, leaving the current element and search-parameter wording aligned with the patient name.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current build-scope source defines AllergyIntolerance.patient, the patient search parameter is based on AllergyIntolerance.patient, and exact searches found no current AllergyIntolerance.subject element or search-parameter remnants in the active AllergyIntolerance sources.

Recommendation:
Keep this empty no-change audit commit. The requested rename is already present in current source, and further edits would only duplicate an already-correct current model.
