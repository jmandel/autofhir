FHIR-7030: Audit ValueSet validate-code translations

Issue request:
FHIR-7030 was a Published/Persuasive 2015 Vocabulary change request for FHIR-core ValueSet $validate-code. It asked whether translation codes in a CodeableConcept input, particularly for batch validation, are allowed and evaluated; the resolution was to make clear that they are allowed and evaluated.

Initial application:
The issue was applied in svn revision 5698, now git commit b67f0b8834b3800e3c2dd7c6e6f6bd08fdebda38, which updated the old ValueSet spreadsheet operation definitions. The key surviving wording says a CodeableConcept validates true if one of its Coding values is in the value set and that a server may validate that multiple codings are not in conflict.

Additional context:
FHIR-8416 later removed the dedicated batch operations in favor of the generic batch interaction, so the batch-specific row touched by FHIR-7030 is no longer current build surface. The current build uses the split OperationDefinition source under source/valueset, with ValueSet listed as an active resource in source/fhir.ini and list-ValueSet-operations.xml referencing OperationDefinition/ValueSet-validate-code. Recent FHIR-51050 work about a possible new $validate-code-batch operation remains Waiting for Input and does not supersede the current normative $validate-code semantics.

AutoFHIR reconciliation:
No source change was made. The active ValueSet $validate-code OperationDefinition already states that code, coding, or codeableConcept is the input choice and that a full CodeableConcept returns true if one of the coding values is in the value set, with optional conflict checking when more than one coding is present. That satisfies the 2015 clarification without reintroducing removed batch-operation text.

Recommendation:
Keep this audit commit as-is. Do not add redundant prose unless a future finalized tracker changes CodeableConcept validation semantics or creates a new batch operation; follow FHIR-51050 separately if it later reaches a final applied state.
