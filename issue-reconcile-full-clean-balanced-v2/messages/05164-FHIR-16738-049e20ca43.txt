FHIR-16738: Audit CodeSystem content wording

Issue request:
FHIR-16738 was a Published/Persuasive STU3 vocabulary issue asking to clarify the CodeSystem.content definition from "represented in this resource" to "represented in this resource instance" because "resource" could be read as either the code system itself or the instance representation.

Initial application:
The issue was applied in SVN revision 14724, represented in git by 4bd66af456a647a3fb1abd385bd7c3aa17244e69, which changed the historical source/codesystem/codesystem-spreadsheet.xml wording to use "resource instance". That spreadsheet source has since been refactored away, and the wording is now carried by the active XML resource definition.

Additional context:
CodeSystem is an active resource in source/fhir.ini, and the current source/codesystem/structuredefinition-CodeSystem.xml definition for CodeSystem.content says "represented in this resource instance." The later FHIR-16861 reconciliation already on the combined branch fixed adjacent "How much"/grammar wording without reversing the resource-instance clarification. Exact source search found the only remaining CodeSystem.content wording without "instance" in source/codesystem/codesystem.svg, a generated-looking diagram title rather than the authoritative XML definition.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current authoritative CodeSystem source already implements the published issue. The remaining SVG-only mismatch should be handled by diagram regeneration rather than a manual source-changing commit whose only edit is to a generated-looking artifact.

Recommendation:
Keep this no-change audit as-is. If the checked-in CodeSystem SVG is regenerated in a broader diagram maintenance pass, ensure it picks up the authoritative "resource instance" definition from source/codesystem/structuredefinition-CodeSystem.xml.
