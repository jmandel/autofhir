FHIR-13704: Audit MedicationRequest intent binding

Issue request:
FHIR-13704 was a Published/Persuasive with Modification STU3 Pharmacy issue asking for MedicationRequest.intent to align with the RequestIntent value set because the then-current MedicationRequestIntent value set did not include "option" for RequestGroup-based chemotherapy regimen use. The approved motion said to change to RequestIntent and include proposal, plan, order, instance-order, and option; Lloyd McKenzie also commented that it should be bound to the common code system while still excluding codes not relevant to MedicationRequest.

Initial application:
The issue was explicitly applied in git cf35ab7ebcf102964085812bf6e2166fe3eaa11c, whose message says "GF #13704 - change medicaitonRequest.intent value set." The actual patch retained the MedicationRequestIntent binding name and MedicationRequest-specific value set, added option to the value set content and MedicationRequest.intent short list, and preserved the workflow mapping to Request.intent. That application matches the Jira modification/comment trail: use the common request-intent concepts needed for MedicationRequest without necessarily allowing every generic request intent code.

Additional context:
source/fhir.ini lists medicationrequest as an active current resource and records that MedicationPrescription became MedicationRequest. Current MedicationRequest.intent remains a required modifier bound to http://hl7.org/fhir/ValueSet/medicationrequest-intent, and the active MedicationRequest intent code system includes proposal, plan, order, original-order, reflex-order, filler-order, instance-order, and option. Later Published Pharmacy issues in the same family, including FHIR-13935, FHIR-17680, and FHIR-34218, expanded/reviewed the MedicationRequest intent codes and retained the MedicationRequest-specific value set shape; related audit commits for FHIR-13935, FHIR-17680, FHIR-13999, and FHIR-20605 are already on the combined branch. Newer R6 issues FHIR-56335 and FHIR-55336 are Resolved - change required, not Applied/Published; they propose a future migration to the common Request code system while keeping a MedicationRequest-specific value set subset, so they are context rather than source-edit authority for this default run.

AutoFHIR reconciliation:
No source files were changed. The active current source already supports the substantive FHIR-13704 use case by allowing option and the requested request-intent concept family for MedicationRequest. Changing MedicationRequest.intent directly to the generic request-intent value set in this audit would be overbroad because the current RequestIntent code system includes additional codes such as directive, and the later unresolved R6 decisions call for a more targeted code-system migration rather than a generic value-set binding.

Recommendation:
Keep this empty audit commit as-is. Handle the future common-code-system migration and any "other" escape-valve work under FHIR-56335/FHIR-55336 when those R6 decisions are applied or otherwise brought into source-edit scope; do not use FHIR-13704 alone to broaden MedicationRequest.intent beyond the Pharmacy-retained current value set.
