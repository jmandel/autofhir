Issue request:
FHIR-6078 was a Published/Persuasive DSTU1 OO change request for FHIR-core-DataElement asking that DataElement LOINC mappings use database columns rather than labels shown in the HTML view.

Initial application:
No commit explicitly tagged FHIR-6078 or GF#6078 was found. Historical DataElement source shows the relevant spreadsheet changed just before the Jira was created from a "LOINC Mapping" column to "LOINC Code" while retaining values such as LOINC_NUM, and later DataElement cleanup commits left that heading in place until the resource left the active build.

Additional context:
DataElement is no longer part of the current core build: source/fhir.ini keeps dataelement and the DataElement TLA as commented entries, the source/dataelement tree is absent from HEAD, and git history shows DataElement was commented out of fhir.ini in 2017 and the remaining source/dataelement files were deleted during the 2021 R4B source rework. Later FHIR-20502 changed the current global LOINC mapping display column from "LOINC Code" to "LOINC Field Name" and documented ElementDefinition mappings to the LOINC master table, but that later ElementDefinition issue does not resurrect or require edits to the retired DataElement resource.

AutoFHIR reconciliation:

Recommendation:
Keep this no-change audit commit as-is for current core. Revisit only if DataElement is intentionally restored to the active build or if a separate reconciliation explicitly scopes FHIR-20502-style ElementDefinition LOINC mapping display details.
