FHIR-15522: Audit DiagnosticReport risk extension location

Issue request:
FHIR-15522 was Published with a Persuasive with Modification resolution. It asked for genetic DiagnosticReport results and Observation panels to be able to link to RiskAssessment by creating a standard extension with contexts DiagnosticReport and Observation, cardinality 0..*, value Reference(RiskAssessment), and a definition explaining its use as an alternate choice for Observation.hasMember or DiagnosticReport.result.

Initial application:
The issue was preapplied in core by git commit f0244fd79a96ab323933e7ea52f6d54058f01a6d, which added the diagnosticReport-risk extension to the DiagnosticReport extensions spreadsheet. OO minutes for 2018-03-20 record FHIR-15522 as preapplied and approved as applied 6-0-0, subject only to fixing the typo in the extension description. Later core source contained source/diagnosticreport/structuredefinition-extension-diagnosticReport-risk.xml with the requested DiagnosticReport and Observation contexts and Reference(RiskAssessment) value.

Additional context:
Core commit dd468d4f1799dd79819315b211588ef1cf4586e0 removed extension definitions from the R5 source; current HL7/fhir source retains only the diagnosticReport-risk OID in source/oids.ini. The authoritative current definition is in the HL7/fhir-extensions checkout at input/definitions/multiple/StructureDefinition-diagnosticReport-risk.xml. FHIR-53006 later clarified the same extension sentence in the Extension Pack and kept the existing name and URL.

AutoFHIR reconciliation:
This commit intentionally makes no HL7/fhir source change. The current Extension Pack source already has the requested context entries for DiagnosticReport and Observation, max *, and value[x] typed as Reference with targetProfile http://hl7.org/fhir/StructureDefinition/RiskAssessment. Because the maintained artifact is outside the core checkout and is already correct, this is an external-repo audit decision.

Recommendation:
Keep this audit commit as-is. Any future corrections to diagnosticReport-risk should be made in HL7/fhir-extensions, not by restoring an extension definition to the core source checkout.
