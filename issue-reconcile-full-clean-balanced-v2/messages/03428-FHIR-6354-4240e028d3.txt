FHIR-6354: Audit Provenance W3C agent mapping

Issue request:
FHIR-6354 was Published/Persuasive for DSTU1 Provenance. It asked how closely FHIR Provenance conformed to W3C PROV and resolved to add a Provenance.agent relationship structure, including role/actor/userId and a relatedAgent with relationship type and internal target.

Initial application:
The issue was applied in git commit 750c21719d386744ac73b55d35fb9d777ff664e9, matching Jira's svn revision 6591 comment, which added Provenance.agent.relatedAgent, a RelatedAgentType binding to v3 RoleLinkType, and example content.

Additional context:
Later Provenance source history and Jira decisions changed the representation. FHIR-9996 and related Security changes refactored the agent identity model to who/onBehalfOf, while FHIR-12502 explicitly removed relatedAgentType because onBehalfOf had been added as the specific relationship and other agent relationship types were outside the 80% need. FHIR-13015 further confirmed that Provenance.onBehalfOf uses the W3C actedOnBehalfOf delegation concept. FHIR-25934 and FHIR-28162 later clarified the delegation semantics and constraints rather than restoring relatedAgent.

AutoFHIR reconciliation:
No source change was made. The active Provenance resource still declares W3C PROV mappings, represents agents, and carries the surviving agent-to-agent delegation relationship as Provenance.agent.onBehalfOf. Restoring relatedAgent or relatedAgentType would contradict later final decisions.

Recommendation:
Keep this audit commit as-is. Do not reintroduce relatedAgent/relatedAgentType for FHIR-6354; any future changes to onBehalfOf target choices or mapping details should proceed under current Security WG issues such as the unresolved RelatedPerson question rather than this DSTU1 tracker.
