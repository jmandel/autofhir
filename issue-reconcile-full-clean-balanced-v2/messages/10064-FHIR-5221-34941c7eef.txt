FHIR-5221: Audit reference no-inheritance wording

Issue request:
FHIR-5221 was a Published/Persuasive FHIR-I DSTU1 clarification from Jan 2015 Ballot Comment #98 asking the Resource References page to say a Condition "references" a Procedure as its cause, rather than saying it "links to" the Procedure, so the example consistently made the Condition the subject of both clauses.

Initial application:
The change was applied in SVN revision 4513, represented in git as commit baca552c90cca270c782e94757dc477734614e63, which changed source/references.html from "it links to" to "references" in the non-transitive-reference example.

Additional context:
The current source/references.html page is still in build scope through the active source/fhir.ini type-page mapping for Reference to references. Later edits rewrote the example to use Procedure.subject and Procedure.reason, and FHIR-19931 corrected the rewritten example's mistaken second Procedure link to Condition. FHIR-33008 later adjusted nearby contained-resource guidance but did not restore the old ambiguous "links to" wording or change the reference no-inheritance rule.

AutoFHIR reconciliation:
This audit commit makes no source change. The current references page already avoids the wording ambiguity FHIR-5221 identified and preserves the intended rule that relationships are not transitive; adding the original 2015 sentence back would conflict with later accepted clarifications.

Recommendation:
Keep this no-change audit as-is. No follow-up is needed for FHIR-5221 unless FHIR-I wants to revisit the broader example wording independently of this resolved grammatical clarification.
