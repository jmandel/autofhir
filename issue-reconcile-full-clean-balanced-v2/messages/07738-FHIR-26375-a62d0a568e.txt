FHIR-26375: Audit Device status update

Issue request:
FHIR-26375 was a Published/Persuasive OO change request for R5 asking to complete a missed piece of the FHIR-21235 Device status resolution. It cited the September 2019 OO WGM minutes and asked to add the remaining Device status backbone, described in the issue as Device.etcStatus with value and reason subelements.

Initial application:
The related Device status work was applied before this reconciliation. Commit a7f2575daa recorded Device updates with FHIR-21235 preapplied, and the then-current Device spreadsheet contained Device.operationalStatus and Device.associationStatus backbone elements with value and reason subelements. FHIR-26375 itself has no separate Jira-keyed source commit, but its Jira comments later recognized that operational and association status already existed.

Additional context:
Later published/applied Device status decisions changed the current model. FHIR-36195 revised Device.operationalStatus to operationalState during R5 work, FHIR-32557/FHIR-34542 clarified that Device.status is the Device record status and added Device.availabilityStatus for the device itself, and FHIR-46962 explicitly corrected R6 narrative because operationalStatus and associationStatus no longer exist on Device and availabilityStatus is the current status element. In the current source, source/fhir.ini actively builds Device and DeviceAssociation; Device has Device.status and Device.availabilityStatus, while DeviceAssociation carries associationStatus.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. Reintroducing Device.etcStatus, Device.operationalStatus, or Device.associationStatus into current Device would conflict with later published/applied decisions and the active R6 source structure.

Recommendation:
Keep this commit as-is. No core source follow-up is needed for FHIR-26375 unless OO deliberately reopens the current Device status model in a new Jira; future work should start from Device.status, Device.availabilityStatus, and DeviceAssociation.associationStatus rather than the superseded R5-era Device operational/association status elements.
