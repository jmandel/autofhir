FHIR-15612: Audit Questionnaire constraint extension ownership

Issue request:
FHIR-15612 was a Published/Persuasive with Modification STU3 FHIR-core change request asking for a Questionnaire and Questionnaire.item complex extension that could express StructureDefinition-invariant-style FHIRPath validation rules. The accepted resolution called for a Questionnaire invariant extension with identifier, severity, expression, human-readable message, and location components.

Initial application:
The Jira comments identify SVN #14772 as the application. In this repository, git-svn commit b8c5990ac5ad735ba1e8e836fd8a4c6fd3534a3e for build@14772 explicitly listed issue 15612 and added the Questionnaire constraint extension rows to source/questionnaire/questionnaire-extensions-spreadsheet.xml, including contexts for Questionnaire and Questionnaire.item, severity, expression, human, and location components.

Additional context:
The current core build still includes Questionnaire as an active resource, but the core checkout no longer has active questionnaire-constraint extension source; only the OID registry entry remains. Commit dd468d4f1799dd79819315b211588ef1cf4586e0 removed the generated R5 core extension source as part of moving standard extensions out of core. The current FHIR Extension Pack contains StructureDefinition-questionnaire-constraint, marks it retired/deprecated, and points users to targetConstraint. Later Published FHIR-extensions issue FHIR-45313 created targetConstraint and explicitly directed deprecating questionnaire-constraint; current Extension Pack source and a 2026 Questionnaire Zulip thread both identify targetConstraint as the replacement.

AutoFHIR reconciliation:
This commit intentionally makes no core source change and records an external-repo decision. Re-adding questionnaire-constraint to core would be wrong because the current authoritative artifacts are in hl7.fhir.uv.extensions, not in this FHIR core checkout/build, and the current replacement is targetConstraint.

Recommendation:
Keep this audit commit as-is for core. Do not re-add the Questionnaire constraint extension to the core source. Any future changes to questionnaire-constraint, targetConstraint, or their guidance should be handled in the FHIR Extension Pack and any dependent IGs such as SDC.
