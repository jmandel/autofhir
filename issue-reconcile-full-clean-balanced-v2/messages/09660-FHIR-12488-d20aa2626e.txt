FHIR-12488: Audit maxValueSet spreadsheet support

Issue request:
FHIR-12488 was a Published/Persuasive FHIR-core Change Request raised for DSTU2 asking to add a way to indicate elementdefinition-maxValueSet in the profile spreadsheet. The Jira application comment says SVN revision 10628 added a `max-valueset` column to spreadsheet binding tabs and validator support.

Initial application:
The request was applied by git-svn commit 1d0c527ee56ac607a95eb9b65b742e45cea48235 (`#12488 - support for maxValueSet when authoring and validating`) on 2016-12-23. That commit changed the DSTU3 validator, the IG spreadsheet parser, and a test IG spreadsheet, matching the Jira comment. The combined reconciliation branch did not already contain an `Issue-Reconcile-Key: FHIR-12488` commit before this audit.

Additional context:
The old spreadsheet parser/tooling touched by the 2016 commit is no longer present in the current core checkout. Current source still has active ElementDefinition/profile material in build scope, but maximum binding semantics are represented by `ElementDefinition.binding.additional` and the additional-binding-purpose `maximum` code rather than by the historical `elementdefinition-maxValueSet` spreadsheet column. The current terminology page explicitly says the maximum additional binding replaces the `http://hl7.org/fhir/StructureDefinition/elementdefinition-maxValueSet` extension for FHIR Release 5+. The FHIR Extension Pack now carries the extension as retired/deprecated with guidance to use additionalBinding instead.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Reintroducing or documenting a historical `max-valueset` spreadsheet column in current core would be stale: the original request was implemented for the DSTU2/STU3 spreadsheet workflow, and current FHIR source has replaced the mechanism with first-class additional bindings plus deprecated extension-pack compatibility.

Recommendation:
Keep this audit commit as-is. No current FHIR-core source fix is needed for FHIR-12488. If a current IG Publisher or extension-pack warning needs behavior changes for old R4 maxValueSet usage, handle that as a separate tooling or FHIR-extensions issue rather than reopening the historical profile-spreadsheet column request.
