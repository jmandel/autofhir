FHIR-5269: Audit Practitioner role search coverage

Issue request:
FHIR-5269 is a Published/Persuasive DSTU1 Patient Administration ballot comment for Practitioner. It asked that Specialty and Role be allowed as search parameters because those concepts were expected to be commonly desired in Practitioner searches.

Initial application:
The issue appears to have been applied in historical commit 8ed9982708ac31ba37ad6670f9be8ba628634329, which bundled several Practitioner ballot reconciliation trackers including 5269. That commit added role and specialty token search rows to the then-current Practitioner spreadsheet, pointing at Practitioner.practitionerRole.role and Practitioner.practitionerRole.specialty after the same change family moved organization/role details under Practitioner.practitionerRole.

Additional context:
In the current build, source/fhir.ini actively includes both Practitioner and PractitionerRole. The old nested Practitioner.practitionerRole structure is no longer present on Practitioner; current role-specific details live on PractitionerRole. PractitionerRole.code and PractitionerRole.specialty are active elements, and the PractitionerRole search parameter bundle defines token search parameters role and specialty over those elements. The Practitioner search parameter bundle has no direct role or specialty entries, which is consistent with the current model because those properties are not defined on Practitioner. Later related decisions FHIR-25033 and FHIR-32497 further clarified that PractitionerRole.specialty is role-specific and is not a general Practitioner qualification.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The requested search capability is already represented in the current source at the current resource boundary: clients search PractitionerRole by role or specialty, optionally using the practitioner reference to connect results to Practitioner. Adding direct Practitioner role/specialty search parameters now would duplicate or distort the current resource model rather than complete the DSTU1 ballot request.

Recommendation:
Keep this audit commit as-is. If Patient Administration wants a new convenience search directly on Practitioner for related PractitionerRole role/specialty, that should be raised as a new current-model search-design issue rather than treated as unapplied FHIR-5269 work.
