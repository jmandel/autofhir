FHIR-17211: Audit MedicinalProduct name type

Issue request:
FHIR-17211 was a Published/Persuasive FHIR-core BR&R change request raised against the STU3 MedicinalProduct resource. It asked for a type element at the product name level because multiple MedicinalProduct.name repetitions could represent proprietary and non-proprietary names, but the existing type was only on namePart.

Initial application:
No Jira-tagged source commit for FHIR-17211 was found. The requested capability appears to have been applied as part of the broader R5 medication-definition resource work: MedicinalProduct was mapped to MedicinalProductDefinition, and MedicinalProductDefinition.name.type was present when the current MedicinalProductDefinition source was introduced.

Additional context:
The current build has MedicinalProductDefinition as an active resource, includes the R4/R5 name element renames in fhir.ini, and maps legacy MedicinalProduct to MedicinalProductDefinition. The active StructureDefinition has MedicinalProductDefinition.name.type as a 0..1 CodeableConcept bound to ValueSet/medicinal-product-name-type with examples including Proprietary and Non-Proprietary. No Zulip or Confluence evidence was found that narrows or reverses the Jira decision.

AutoFHIR reconciliation:

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-17211 unless BR&R later decides to change the MedicinalProductDefinition name model or binding.
