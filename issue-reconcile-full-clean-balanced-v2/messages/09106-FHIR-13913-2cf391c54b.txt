FHIR-13913: Audit CapabilityStatement document profile wording

Issue request:
FHIR-13913 was a Published/Persuasive FHIR-core Conformance change request from STU3 asking to fix the CapabilityStatement document section after the linked Zulip discussion established that CapabilityStatement.document.profile should describe a profile on the document Bundle, not on an individual document resource.

Initial application:
The issue was applied in SVN revision 13424, represented in git by a5c102a5b8de353a5b40cf8078c66e15968dcac9. That commit changed the old CapabilityStatement spreadsheet text from an individual-resource constraint to a profile on the document bundle, added the note that the profile is actually on the Bundle, and adjusted documents.html wording from document resources to document-related resources.

Additional context:
The current build no longer uses the old capabilitystatement-spreadsheet.xml source; the 2021 source rework created source/capabilitystatement/structuredefinition-CapabilityStatement.xml and preserved the FHIR-13913 wording. source/fhir.ini lists capabilitystatement as an active resource, so the current StructureDefinition source is in build scope. The linked Zulip thread confirms the intended correction, and no Confluence reference or later core Jira search result was found that changes that interpretation.

AutoFHIR reconciliation:
No source change was made. The current CapabilityStatement.document.profile short, definition, and comment already say that this is a profile on the document Bundle constraining the resources present and their contents, and documents.html already uses the corrected document-related resources wording.

Recommendation:
Keep this audit commit as-is. The published issue has already been correctly applied and preserved through source migration; further edits would be redundant unless a future work group decision changes how CapabilityStatement documents should be modeled.
