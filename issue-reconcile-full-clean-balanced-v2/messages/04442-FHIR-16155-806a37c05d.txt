FHIR-16155: Audit Patient organization search parameter

Issue request:
FHIR-16155 was a Published/Persuasive Patient Administration change request for STU3. It reported that Patient.managingOrganization described the custodian of the patient record while the Patient search parameter named organization described the organization where the person is a patient, and the approved resolution was to update the search parameter description to be consistent with the property.

Initial application:
The issue was applied in git commit 8fb31595e9, which changed the historical patient spreadsheet search parameter description from "The organization at which this person is a patient" to "The organization that is the custodian of the patient record." The later source refactor in 33b409a4b6 carried that wording into the current Patient search parameter bundle and Patient StructureDefinition sources.

Additional context:
The current build scope includes Patient as an active resource in source/fhir.ini. Current source/patient/bundle-Patient-search-params.xml defines SearchParameter/Patient-organization with path and expression Patient.managingOrganization and a custodian-of-record description. Current source/patient/structuredefinition-Patient.xml defines Patient.managingOrganization as the organization that is the custodian of the patient record. No relevant Zulip or Confluence evidence was found that would alter the published Jira decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative Patient source already implements the requested consistency between Patient.managingOrganization and the organization search parameter, and remaining generated-looking diagram text is consistent with the same element definition.

Recommendation:
Keep this no-change audit commit as-is. No follow-up source work is needed for FHIR-16155 unless a future Patient Administration decision changes the meaning of Patient.managingOrganization or its search parameter.
