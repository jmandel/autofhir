FHIR-16077: Audit CodeSystem registry link text

Issue request:
FHIR-16077 was a Published/Persuasive STU3 FHIR-core Feed correction asking that a CodeSystem page no longer say "the full registry of value sets" when linking to the terminology code-system registry. The accepted resolution was to keep the code-system registry link and change the link text to "code systems".

Initial application:
The issue was applied by git-svn commit 9c64d6e4804129d892642f5e78e3cd8eeb2b4a2a, matching Jira's svn revision 14361 comment. That commit changed source/template-cs.html from "the full registry of value sets" to "the full registry of code systems" while preserving the terminologies-systems.html target. The template was later moved into tools/templates/template-cs.html without losing the fix.

Additional context:
The current Bundle resource is active in source/fhir.ini, and source/bundle/codesystem-bundle-type.xml is the current CodeSystem source for the page named in the Jira related URL. The current CodeSystem HTML template at tools/templates/template-cs.html links to terminologies-systems.html with the text "the full registry of code systems", and build.fhir.org/codesystem-bundle-type.html renders the same wording. Searches of Zulip and Confluence found no conflicting community or minutes evidence. Repository search found the expected value-set wording in value-set templates and a legacy -book CodeSystem template, but no current allcontent/book output was found and the historical Jira application targeted the active CodeSystem template.

AutoFHIR reconciliation:
This commit intentionally makes no source change because the source path that feeds current CodeSystem pages already carries the approved wording and the rendered current Bundle Type CodeSystem page is correct.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for current CodeSystem pages; if legacy book/allcontent output is ever reinstated, review the old -book terminology templates as a separate build-scope cleanup.
