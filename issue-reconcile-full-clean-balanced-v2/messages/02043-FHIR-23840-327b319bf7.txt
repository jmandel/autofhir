FHIR-23840: Audit Communication coded content guidance

Issue request:
FHIR-23840 was a Published/Persuasive Patient Care change request asking that Communication and CommunicationRequest explain why payload.content[x] can be a CodeableConcept, including the machine-generated/finite-terminology use case, use of contentCodeableConcept.text for uncoded text, and the rule that the CodeableConcept is the communicated content rather than a categorization.

Initial application:
The Jira comment points to GitHub commit 43fcc3d. Git history confirms 43fcc3d1fec8c0bed029f0a85650fcb3913991d4 updated the then-authoritative Communication and CommunicationRequest spreadsheets with the requested explanatory comment. The 2021 source rework commit 33b409a4b6d544598262f2f074ebb4b6dc466157 carried that comment into the current StructureDefinition XML files, and the 2023 mapping-exception source added the same CommunicationRequest comment for pattern divergence tracking.

Additional context:
FHIR-20770 introduced CodeableConcept as a Communication/CommunicationRequest payload type and supplied the original non-categorization rule. FHIR-24661 later rejected adding a separate payload categorization element and quoted this same guidance as the intended R5 behavior. FHIR-38783 revisited CommunicationRequest string/code concerns in 2024 but preserved the CodeableConcept guidance while only tightening the CommunicationRequest payload definition wording. The active fhir.ini resource list includes both communication and communicationrequest, so these StructureDefinition sources are in current build scope.

AutoFHIR reconciliation:
No source change was made. Current Communication.payload.content[x] and CommunicationRequest.payload.content[x] both contain the requested comment, both still allow CodeableConcept as one of the content types, and the CommunicationRequest request-pattern mapping exception mirrors the comment where that generated comparison needs it.

Recommendation:
Keep this no-change audit commit. Further wording changes would re-open policy already settled by FHIR-20770, FHIR-23840, FHIR-24661, and FHIR-38783 rather than apply the published FHIR-23840 decision.
