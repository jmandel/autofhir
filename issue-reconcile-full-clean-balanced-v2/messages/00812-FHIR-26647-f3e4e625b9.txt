FHIR-26647: Clarify MeasureReport stratum value type wording

Issue request:
FHIR-26647 was Published/Persuasive for R5 by CQI. It asked that MeasureReport.group.stratifier.stratum.component value support non-coded values matching the then-current Group.characteristic.value[x] choices: CodeableConcept, boolean, Quantity, Range, and Reference.

Initial application:
The issue was initially applied in J#26647 commits b9046de76637cf19bb3f8db403bf5d2e360d8604 and 646b2bf3114a00fb012ed3c88adb75612255382b. Those commits converted both MeasureReport.group.stratifier.stratum.value and MeasureReport.group.stratifier.stratum.component.value to value[x], added the requested five datatypes, and restored RIM mappings. The component value source is now correctly typed, but the non-component stratum value definition still described the value as a CodeableConcept.

Additional context:
source/fhir.ini actively includes measurereport=MeasureReport, so source/measurereport/structuredefinition-MeasureReport.xml is in current build scope. Later Group issue FHIR-41583 added uri and Expression to Group.characteristic.value[x] for R6 conceptual cohort definitions, but it was a Group-only change and no discovered Jira, Zulip, or Confluence evidence says to expand MeasureReport strata beyond the five types approved in FHIR-26647.

AutoFHIR reconciliation:
This commit removes the obsolete CodeableConcept-only phrase from MeasureReport.group.stratifier.stratum.value[x]. The allowed datatype list remains CodeableConcept, boolean, Quantity, Range, and Reference, and MeasureReport.group.stratifier.stratum.component.value[x] already carries those same choices.

Recommendation:
Keep this source fix as-is. It resolves a stale definitional contradiction from the FHIR-26647 application without broadening MeasureReport beyond the approved datatype set; any future uri or Expression expansion for MeasureReport should be handled by a separate CQI decision.
