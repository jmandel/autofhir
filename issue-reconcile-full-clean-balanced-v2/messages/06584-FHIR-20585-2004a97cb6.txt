FHIR-20585: Audit superseded Questionnaire text markdown change

Issue request:
FHIR-20585 was a Published/Persuasive FHIR-core Questionnaire change request for R5 asking to make Questionnaire.item.text markdown so display labels could use simple formatting such as bold, italics, and lists.

Initial application:
The request was initially applied by commit 5399a4a442ddcd037451eaeceaf3b5a55ec7943b, which changed source/questionnaire/structuredefinition-Questionnaire.xml so Questionnaire.item.text moved from string to markdown. QuestionnaireResponse.item.text was not changed by that implementation.

Additional context:
FHIR-34082 is a later Published/Persuasive decision in the same artifact family. It reconsidered the processing burden and the mismatch with ElementDefinition.label, concluded that markdown should be supplied via the existing markdown extension only where needed, and was applied by commit 680c4dae1c8438f0d9726a9ec952a1410b09c7e9 changing Questionnaire.item.text back to string. The #questionnaire Markdown Zulip thread and SDC minutes show the work group discussion path from the FHIR-20585 implementation to the FHIR-34082 reversal.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current active Questionnaire source has Questionnaire.item.text as string, QuestionnaireResponse.item.text is also string, and fhir.ini shows both resources are active build resources. The current source is therefore correct after the later FHIR-34082 superseding decision, even though it no longer matches the original FHIR-20585 request literally.

Recommendation:
Keep this audit commit as-is. Do not reintroduce markdown as the core Questionnaire.item.text datatype for FHIR-20585; any future rich-text requirement should come through a new work-group decision or use/profile the markdown extension explicitly.
