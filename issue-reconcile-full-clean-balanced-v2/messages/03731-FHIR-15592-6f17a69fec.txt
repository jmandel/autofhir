FHIR-15592: Audit RequestGroup participant Person removal

Issue request:
FHIR-15592 was a Published/Persuasive CDS change request for STU3 asking why RequestGroup.action.participant referenced Person when Person's scope text says Person is not directly referenced by other clinical or administrative resources. The approved resolution was to remove the Person reference.

Initial application:
The issue was applied in SVN 13285, represented in git as 222fded13d4e46e979f9c58d9399ecd625974a30, which removed Person from source/requestgroup/requestgroup-spreadsheet.xml's RequestGroup.action.participant reference target list. No Issue-Reconcile-Key audit commit for FHIR-15592 was present on the combined branch before this reconciliation.

Additional context:
RequestGroup is no longer an active current-build resource name. source/fhir.ini actively builds requestorchestration=RequestOrchestration and records RequestGroup=@RequestOrchestration for R4-to-R6 migration. Later published RequestGroup/RequestOrchestration work, including FHIR-24618's definitional participant remodel, FHIR-24619's rename, and FHIR-39267's subject-type alignment, did not reintroduce Person as an action participant target. The current RequestOrchestration action participant typeReference and actor[x] Reference target lists include Patient, Practitioner, PractitionerRole, RelatedPerson, and other participant-pattern resources, but not Person.

AutoFHIR reconciliation:
This is an empty audit commit. The current build-scoped source already satisfies FHIR-15592, so no source hunk is necessary or appropriate.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed unless a future CDS decision intentionally changes Person's boundary rule or explicitly allows Person as a RequestOrchestration action participant.
