FHIR-17919: Audit ClaimResponse form attachment support

Issue request:
FHIR-17919 was Published with a Persuasive with Modification resolution for STU3/FM. It asked to add an element or extension so an insurer could include a PDF/HTML/etc. EOB with a ClaimResponse, and the approved resolution was to extend the existing form attribute so the response can send both the form code and an attachment at the same time rather than a choice.

Initial application:
The issue was explicitly included in the 2018-11-05 financial management bulk commit afb5ec66f68641293bb7950b6e0eeb118fa1444a. In that commit, the ClaimResponse spreadsheet changed the former ClaimResponse.form CodeableConcept row into ClaimResponse.formCode and added a separate Attachment-valued ClaimResponse.form row; ClaimResponse examples that carried a form identifier were updated to use formCode. Later source refactors preserved those semantics in the current StructureDefinition XML.

Additional context:
ClaimResponse remains an active current-build resource through source/fhir.ini. The active source defines ClaimResponse.formCode as a CodeableConcept for the printed form identifier and ClaimResponse.form as an Attachment for the actual form by reference or inclusion, explicitly including an EOB. A matching pattern exists on ExplanationOfBenefit, but the Jira artifact and approved request are satisfied by ClaimResponse. Jira/Zulip/Confluence searches found no later or conflicting decision requiring a current FHIR source change.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active ClaimResponse source already supports simultaneous code plus attachment through two independent 0..1 elements, which is exactly the non-choice outcome requested by FHIR-17919.

Recommendation:
Keep this no-change audit commit as-is. No follow-up is needed in core FHIR unless the Financial Management work group wants to add examples showing both elements together, which would be illustrative rather than required for the applied issue.
