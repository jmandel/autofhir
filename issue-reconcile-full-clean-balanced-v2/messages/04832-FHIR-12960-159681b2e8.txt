FHIR-12960: Audit primitive validator examples migration

Issue request:
FHIR-12960 was a Published/Persuasive DSTU2 FHIR-core datatypes request to add negative primitive datatype examples so code generators, language implementations, and validator authors would have invalid primitive instances to test against. The approved resolution was to expand build\tests\validation-examples with invalid datatype instances that appear in the test cases available from the downloads page.

Initial application:
The Jira comment says svn revision 12461 added primitive-good.xml and primitive-bad.xml and improved validator behavior. In the current git history, commit ffb483245175ff499a837bc605277a047ffa7b12 has the matching git-svn-id for build@12461 and adds tests/validation-examples/primitive-good.xml plus tests/validation-examples/primitive-bad.xml with invalid boolean, integer, decimal, base64Binary, instant, string, URI, date, dateTime, time, code, oid, id, unsignedInt, positiveInt, and markdown instances.

Additional context:
The authoritative test-case surface later moved out of this FHIR spec checkout. Commit 39393f8f1db76ed75643b2926278944c03cfae40 deleted tests/validation-examples, including primitive-bad.xml and primitive-good.xml, with the message "delete test resource moved to java core". Commit 3fd6994c06dfa6b80ab93eccd87f9c8642f6dd0d then changed source/downloads.html from a local test-cases.zip link to the external org.hl7.fhir.core location, and the current source/downloads.html points implementers to https://github.com/FHIR/fhir-test-cases/releases for test cases. The current FHIR/fhir-test-cases repository contains validator/primitive-bad.xml, validator/primitive-good.xml, and related primitive validator files, preserving the requested negative examples outside this checkout.

AutoFHIR reconciliation:
Made no source change in the core FHIR repository. Restoring tests/validation-examples here would duplicate a deliberately migrated test corpus and would not be a current-spec fix. The current downloads page already sends implementers to the repository that contains the primitive negative examples requested by FHIR-12960.

Recommendation:
Keep this audit commit as-is. Any future changes to the primitive validator example corpus should be made in FHIR/fhir-test-cases; only update this repository if the downloads page stops pointing to the active external test-case releases or if the work group decides to repatriate validator test cases into the core spec checkout.
