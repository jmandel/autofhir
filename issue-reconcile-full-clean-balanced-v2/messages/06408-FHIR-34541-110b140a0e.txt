FHIR-34541: Audit Group reference search parameter

Issue request:
FHIR-34541 was Published/Persuasive for R5 by FHIR-I. It asked to add a Group value-reference search parameter, citing the Argonaut Patient Lists SearchParameter whose code was value-reference, type was reference, and expression targeted Group.characteristic.value as Reference.

Initial application:
No source commit was found that explicitly mentions FHIR-34541. The same search capability was already represented by FHIR-28291, a Published/Persuasive FHIR-I issue to add Group characteristic-reference search support; commit 7b5847c83c5ea46b8982c2cb4e974103c8f69fcf added Group-characteristic-reference to the active Group search-parameter bundle on 2022-08-09. Eric Haas then commented on FHIR-34541 on 2022-08-19 that it was already applied. R4/R4B history artifacts do not list the Group characteristic-reference search include, while R5 history artifacts do.

Additional context:
The Argonaut example changed an implementation query name from characteristic-reference to value-reference, but the core issue family settled on the current FHIR core name characteristic-reference. Later source maintenance converted the parameter into the current composite form so the characteristic code and reference value are matched together, and the FHIR-40341 reconciliation fixed the current reference component expression. Group is active in source/fhir.ini, and source/group/bundle-Group-search-params.xml is the authoritative current Group search-parameter bundle.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. Current source already contains a Group-characteristic-reference composite search parameter with a characteristic component and a reference component over value.ofType(Reference), which satisfies the accepted Group characteristic reference search capability. Adding a second Group value-reference search parameter now would introduce a new alias/search contract not reflected in the R5/R6 core naming trail or the current Group search-parameter family.

Recommendation:
Keep this no-change audit. If the work group wants FHIR core to expose the exact Argonaut code value-reference as an additional alias, that should be handled as a new explicit search-parameter naming decision rather than inferred from FHIR-34541.
