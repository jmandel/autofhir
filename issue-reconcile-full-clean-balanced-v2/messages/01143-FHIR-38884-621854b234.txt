FHIR-38884: Audit Patient merge processing clarification

Issue request:
FHIR-38884 was Published/Persuasive for R5 by Patient Administration. The reporter asked which Patient resource was meant by the Patient $merge Data Processing-stage sentence and what "indeterminate" meant. The accepted resolution was to name the source, target, and result patients; include resources referencing any of them; explain that resources may be changed, deleted, or have references updated in no implied order; state that the work is not implied to be a single transaction; and advise consumers to wait until merge processing completes.

Initial application:
The issue was applied in commit 3974bfe269c3a14d6c5ea6fd4e81299bb5f4809e, which replaced the ambiguous sentence in source/patient/$merge-notes.md and the Patient-merge OperationDefinition footer with the approved clarification. That change was merged for R5 by PR #2627 in 32eb6ebe3a3a27de0ae486202a7421be2d870359, alongside adjacent Patient merge ballot clarifications. Later source cleanup carried the same text into source/patient/operation-Patient-merge-notes.xml.

Additional context:
Patient remains an active core resource in source/fhir.ini, but the current Patient operations list includes Patient-match and Patient-purge, not Patient-merge. Commit b487fdda4bb4a5382a93dbb5a811efd02425b9bc intentionally removed OperationDefinition/Patient-merge from core and changed the Patient narrative to link to the Admin IG Patient $merge page. The residual core notes source and the current rendered Admin IG page both contain the FHIR-38884 Data Processing clarification.
