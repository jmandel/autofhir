Issue request:
FHIR-37442 was Published as Persuasive for R5. It asked FHIR-I to describe, in the specification and/or linked Confluence pages, when and how FHIR packages are used because FHIR had begun relying extensively on packages and there had been CI-build package-version discrepancies. The resolution said Grahame would provide the description and that it would not be normative content.

Initial application:

The R5 history page records "Documented FHIR NPM Packages", and current build inputs list packages.html in the site hierarchy, documentation index, and publish list.

Additional context:
The current source/packages.html page describes FHIR NPM package purpose, structure, package.json metadata, examples, .index.json, package composition, caching, and registry use. Later package-page decisions changed how the original non-normative note should be interpreted: FHIR-46072 deliberately made the package page Normative in R6 because it contains mandatory package metadata text, and FHIR-50860 plus FHIR-48547 added later package guidance on the same active page. Those related issues are already represented on the combined branch and do not create a remaining FHIR-37442 source gap.
