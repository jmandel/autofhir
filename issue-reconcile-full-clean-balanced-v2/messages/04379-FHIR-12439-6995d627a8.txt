FHIR-12439: Audit MedicationRequest intended performer

Issue request:
FHIR-12439 was a Published/Persuasive with Modification Pharmacy change request for DSTU2 asking MedicationRequest to include an intended performer for medication treatment or administration, with separate representation for the desired actual performer and the desired role/type of performer.

Initial application:
The Jira comment points to git-svn commit 4b21106775caa782aa07057cdc51cb67b83f467f, which added MedicationRequest.performer to the MedicationRequest spreadsheet source as a 0..1 Reference to Practitioner, Organization, Patient, Device, or RelatedPerson. The current build no longer uses that spreadsheet representation directly, but the active StructureDefinition source retains and evolves the field.

Additional context:
MedicationRequest is an active current-build resource in source/fhir.ini. Current authoritative XML contains MedicationRequest.performerType as the role/type field and MedicationRequest.performer as the intended administration performer, now with later build-scope evolution to 0..* and current target profiles. The accompanying search-parameter follow-up FHIR-13449 is also published and present as intended-performer and intended-performertype search parameters. Later FHIR-37631 clarification is already represented on the combined branch and refines device-versus-performer wording without undoing the FHIR-12439 requirement.

AutoFHIR reconciliation:
No source change was made. The current active source already conveys the requested intended performer concept, the separate intended performer role/type, and related search support, so adding or rewriting source would be redundant and could conflict with later accepted refinements.

Recommendation:
Keep this empty audit commit as-is. Future changes to MedicationRequest.performer or performerType should be handled through newer Pharmacy issues, not by reopening FHIR-12439.
