FHIR-13978: Audit medication status definitions

Issue request:
FHIR-13978 was a Published/Persuasive with Modification Pharmacy issue for STU3. It asked to clarify MedicationRequest and MedicationStatement status values so entered-in-error acknowledged that implied medication actions may already have occurred and clinical decision support should account for that status, and so stopped would not be used when the original order or statement was entered in error.

Initial application:
Jira records the issue as applied on 2018-02-16 by git commit e4206a3abafba1275c89a32c29f2715a17e0e0e7, build@13084. That commit changed the then-active MedicationRequest and MedicationStatement spreadsheets, adding the requested entered-in-error usage wording and adding the stopped caveat for both resources. Later source refactors split the relevant status terminology into the current CodeSystem XML files.

Additional context:
MedicationRequest and MedicationStatement are active current-build resources in source/fhir.ini. Current MedicationRequest still has the stopped caveat in its status CodeSystem and keeps the clinical decision support guidance on the MedicationRequest.status element comment, not on entered-in-error. Later same-area Pharmacy decisions changed the target semantics: FHIR-54903 explicitly replaced the longer MedicationStatement and MedicationRequest entered-in-error definitions with the current concise invalid-resource definitions, while FHIR-32060 and FHIR-39271 redesigned MedicationStatement.status so it now reflects recording status only and MedicationStatement.adherence carries taking/not-taking states such as stopped. Confluence minutes support the later FHIR-54903 vote, and the FHIR-13978 community search found only bot/commit references rather than conflicting substantive discussion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source differs from the original 2018 wording because later final Pharmacy decisions superseded the longer entered-in-error text and moved MedicationStatement's medication-use states out of status. Reintroducing the FHIR-13978 wording now would conflict with those later decisions.

Recommendation:
Keep this no-change audit commit as-is. Do not restore the 2018 entered-in-error text unless Pharmacy reopens or reverses FHIR-54903; any future MedicationStatement status work should start from the later status/adherence model confirmed by FHIR-32060 and FHIR-39271.
