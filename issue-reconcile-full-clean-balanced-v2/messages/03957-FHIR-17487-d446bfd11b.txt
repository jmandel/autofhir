FHIR-17487: Audit Patient merge compartment note

Issue request:
FHIR-17487 is a Published/Persuasive PA change request raised against STU3 Patient. It asked that the Patient merge STU consideration mention how linking and merging affect Patient compartment membership; the final Jira resolution records that the closing-stage R4 text had been updated and contained the requested notes.

Initial application:
The seed itself is not named in source history, but the same evidence trail shows the work was applied through the related GF#16429 Patient merge note update. Commit 9f6368a72b changed source/patient/patient-notes.xml from an STU note to a generic note, kept the linking/merging/unlinking questions, and added the explicit question "How will the patient compartment interact with the merge?".

Additional context:
Later Patient merge/link work superseded the old generic note. FHIR-15837, which the seed was filed while reviewing, was subsequently Published/Persuasive for R5 and commit 7001897476 updated active source/compartments.xml to state that linked Patient records retain separate compartment searches, while merged patients should move associated resources to the target patient so the target compartment includes the relevant data and the source compartment contains only the linked Patient plus possible remnants such as AuditEvent. Current Patient narrative keeps merge/link guidance and points merge behavior to the Admin Incubator $merge operation rather than restating the old STU question. FHIR-19687 is the later merge/link search-behavior issue and is already represented on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Adding another Patient-page sentence would duplicate the active compartment definition and risk drift; the current built core source already preserves the requested implementer understanding through the compartment definition and the Patient merge/link narrative.

Recommendation:
Keep this audit commit as-is. If future work changes the externally hosted $merge operation, review the Admin Incubator operation source, but no current FHIR core source edit is needed for FHIR-17487.
