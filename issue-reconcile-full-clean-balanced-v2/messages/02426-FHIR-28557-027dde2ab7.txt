FHIR-28557: Audit target constraint extension availability

Issue request:
FHIR-28557 was Published/Persuasive for FHIR core CarePlan/CDS and asked for a way to specify invariants in a definition that apply to the resource instantiated from that definition, using a Measure/MeasureReport validation rule as the motivating example. The final resolution was that the requested capability is enabled by the extension created for FHIR-28572.

Initial application:
HL7/fhir commit 69dc0e04cd5351136bb1ed6e884fa71bddd7cf3e explicitly applied both J#28572 and J#28557 by adding cqf-targetInvariant rows to source/profiles/clinicalreasoning-extensions-spreadsheet.xml, including key, requirements, severity, and expression children evaluated with %target and %definition context. The combined branch already has an FHIR-28572 external-repo audit commit, and no prior combined-branch commit had an Issue-Reconcile-Key trailer for FHIR-28557.

Additional context:
FHIR-I minutes from September 2020 record the original discussion as a need for an extension to express validation criteria on definitional content and show the issue moving to CDS. FHIR core later removed extension definitions from the R5 source, leaving the current active clinicalreasoning-extensions spreadsheet with only its header row. The authoritative extension source is now in HL7/fhir-extensions: cqf-targetInvariant still exists there as a retired/deprecated artifact, while FHIR-45313 created targetConstraint as the active replacement with the same target-resource constraint concept. FHIR-53078 updated the current core Clinical Reasoning page to list targetConstraint through the configured extension location.

AutoFHIR reconciliation:
Published an empty external-repo audit commit and made no core source change. Reintroducing cqf-targetInvariant rows into core, or adding CarePlan-specific prose for this seed, would be wrong for the current build because the extension source is external and the current core narrative already points implementers to the active targetConstraint extension.

Recommendation:
Keep this audit commit as-is. Future corrections to the target constraint capability should be made in HL7/fhir-extensions unless a new core issue specifically changes how core narrative should reference the external extension; core should continue to link the active Extension Pack artifact rather than restoring old core extension definitions.
