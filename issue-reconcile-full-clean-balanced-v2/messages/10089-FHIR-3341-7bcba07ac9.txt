FHIR-3341: Audit search parameter processing metadata

Issue request:
FHIR-3341 was a Published/Not Persuasive FHIR-I change request from the initial draft asking for model metadata that distinguished search parameters with normal element-driven matching from parameters requiring resource-specific matching algorithms. The request named empty-path DSTU1 examples such as ImagingStudy size, Location near/nearDistance, Patient/RelatedPerson/Organization phonetic, and SecurityEvent patientId. The final resolution said the request had been handled by another tracker: search parameters had paths and xpathUsage identified the search operation type.

Initial application:
No git commit explicitly mentioning FHIR-3341 was found. The matching application trail is FHIR-3317, whose Published/Persuasive with Modification resolution added SearchParameter.xpathUsage and whose implementation commit 572c59da417c5781bef6e10f35c9ba05d2113b40 recorded svn r5930 as "#3317 - add xpathUsage to SearchParameter". Current source has the successor model: SearchParameter.expression extracts search values, SearchParameter.processingMode states whether processing is normal, phonetic, or other, and the relevant resource search parameter bundles carry expressions plus processing modes.

Additional context:
Later R5 decisions deliberately changed the representation without reversing the seed's substance. FHIR-32530 removed SearchParameter.xpath, renamed xpathUsage to processingMode, and updated the model to use expression rather than XPath; FHIR-35974 trimmed obsolete processing mode codes while retaining other for searches that require custom coding. FHIR-I Zulip and Confluence evidence for FHIR-32530/FHIR-35974 confirms the rename and trimming were intentional. The active fhir.ini resource list includes AuditEvent, ImagingStudy, Location, Organization, Patient, and SearchParameter, and fhir.ini maps old SearchParameter.xpathUsage to SearchParameter.processingMode for version conversion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source already conveys the model-driven distinction FHIR-3341 wanted through expression plus processingMode. The specific historical candidate gaps are not current missing-source defects: ImagingStudy size, Location nearDistance, and AuditEvent patientId are not current search parameter codes, while Location near is marked processingMode="other" and the phonetic parameters are marked processingMode="phonetic".

Recommendation:
Keep this no-change audit commit as-is. Future work should not reintroduce xpathUsage or extra path metadata for FHIR-3341; any remaining cleanup of legacy XPath surfaces belongs to the later FHIR-32530/FHIR-35974 issue family, not this Not Persuasive seed.
