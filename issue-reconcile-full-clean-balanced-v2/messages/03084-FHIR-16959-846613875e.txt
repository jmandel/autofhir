FHIR-16959: Audit CDA identifier search guidance

Issue request:
FHIR-16959 was a Published FHIR-core/MnM STU3 change request, resolved Not Persuasive with Modification. The request asked for a better way to search CDA document identifiers because a CDA II.root can map either to Identifier.value with system urn:ietf:rfc:3986 or to Identifier.system when an II.extension is present. The accepted disposition kept the Identifier mapping rule unchanged but said to document the single token search syntax identifier=|[root],[root] in the search specification and in the v3 II mapping guidance.

Initial application:
The issue appears to have been applied in SVN revision 14160, imported as git commit a5c90c3db3cc87902faf8b096c1fdc5f179853fc, whose subject explicitly includes GF#16959. That commit added the CDA II.root search sentence to source/datatypes-mappings.html and added the same identifier=|[root],[root] guidance to the Identifier row in source/search.html.

Additional context:
The current source still contains both requested pieces of guidance. source/datatypes-mappings.html explains the two HL7 v3 II-to-Identifier mapping cases and then gives the CDA II.root search syntax. source/search.html's token search summary table for Identifier also says a CDA II.root may appear in either Identifier.system or Identifier.value and gives the same syntax. FHIR-13223 is the earlier published issue that established the root-only versus root-plus-extension Identifier mapping background; it is supporting context rather than a separate decision in this reconciliation. Searches for FHIR-16959 and the key CDA identifier terms found no Zulip or Confluence record that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source already implements the Jira disposition in the two requested locations, and changing the Identifier rule itself would contradict the Not Persuasive with Modification resolution.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-16959 unless a future work group decision changes the CDA II.root search guidance or the underlying Identifier mapping rule.
