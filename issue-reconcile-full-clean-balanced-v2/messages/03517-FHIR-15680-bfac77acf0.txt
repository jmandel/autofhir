FHIR-15680: Audit Period DST invariant

Issue request:
FHIR-15680 was a Published/Persuasive STU3 technical correction for FHIR-core datatypes. It reported that the Period per-1 XPath compared raw start/end string values and therefore did not account for daylight savings/time-zone ordering, requesting xs:dateTime(f:start/@value) <= xs:dateTime(f:end/@value).

Initial application:
The issue was applied by git-svn commit 7b9942d50e2fc3424002e4358e33e568505b1657, "GF#15680 - fix invariant", corresponding to svn revision 13438. That commit changed source/datatypes/period.xml from a raw f:start/@value <= f:end/@value comparison to an xs:dateTime(...) comparison.

Additional context:
The current authoritative datatype spreadsheet source is in build scope for the datatypes page through source/fhir.ini type-page handling, and its Period invariant row now has the later FHIRPath expression from FHIR-34417 plus the XPath cast requested by FHIR-15680. FHIR-29268 later clarified the English text to "lower or equal" and FHIR-34417 later changed the FHIRPath expression to lowBoundary()/highBoundary(); neither later decision removes the DST-safe XPath cast. Older tools/history/release2 and release3 profile snapshots still show the pre-fix XPath, but they are historical release snapshots rather than current datatype source inputs.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source/datatypes/period.xml per-1 XPath already compares xs:dateTime(f:start/@value) to xs:dateTime(f:end/@value), and the surrounding current expression/text remain consistent with later published Period invariant decisions.

Recommendation:
Keep this audit commit as-is. Future work on FHIR-29268 or FHIR-34417 should be handled under those issue keys if desired; FHIR-15680 itself needs no current source edit.
