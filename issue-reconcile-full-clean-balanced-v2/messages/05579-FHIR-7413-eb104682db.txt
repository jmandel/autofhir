FHIR-7413: Audit Procedure boundary wording

Issue request:
FHIR-7413 was a Published, Persuasive with Modification Patient Care change request from the DSTU1 ballot. It reported a typo in the Procedure boundaries text and said the phrase "for which there are specific resources" was vague. The accepted resolution was to reword the sentence to say that Procedure should not be used to capture an event if a more specific resource already exists, with Immunization, MedicationAdministration, and Communication as examples.

Initial application:
The historical implementation is visible in git commit 512b2462e3, which changed source/procedure/procedure-introduction.xml from the typo-bearing text to the accepted Procedure boundary sentence and linked examples. The Procedure resource is active in source/fhir.ini, so the current Procedure introduction source is in build scope.

Additional context:
Later Procedure introduction edits preserved the FHIR-7413 meaning. FHIR-33401 subsequently updated the same sentence from "i.e." to "e.g." and added NutritionIntake as another more-specific resource example, which makes the current text less exhaustive than the original accepted wording while preserving the rule. Community searches found no FHIR-7413-specific Zulip or Confluence discussion that conflicts with the Jira/git/source conclusion; one Zulip implementer thread only quoted the Procedure boundary while discussing immunizations not given.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source/procedure/procedure-introduction.xml already states that Procedure should not be used when a more specific resource exists, links the accepted example resources, and includes the later NutritionIntake clarification. Further rewording would be discretionary editorial polish rather than a necessary correction to the current specification.

Recommendation:
Keep this empty audit commit as-is. No core source follow-up is needed for FHIR-7413 unless Patient Care wants a new broader policy discussion about Procedure boundaries beyond the already-published Jira decisions.
