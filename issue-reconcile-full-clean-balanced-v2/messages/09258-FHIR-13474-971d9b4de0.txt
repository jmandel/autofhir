FHIR-13474: Audit ElementDefinition targetProfile wording

Issue request:
FHIR-13474 was Published / Persuasive for STU3. It asked for ElementDefinition.type.profile and ElementDefinition.type.targetProfile to be differentiated better, specifically by adding targetProfile text saying it works for Reference() and identifies the profile that the referenced target instance must satisfy.

Initial application:
The Jira comment says the change was applied in SVN revision 12839. Git commit 8336fb373a8298ffa8390f245686db7fa430d9b2 is the corresponding git-svn import, titled "#13474 - note about reference and targetProfile", and it updated source/datatypes/elementdefinition.xml so targetProfile was explicitly "Used when the type is \"Reference\"" and applied to the target of the reference.

Additional context:
The cited 2017 Zulip discussion confirms the intended distinction: type.profile constrains the Reference datatype itself, while type.targetProfile constrains the referenced resource. Later FHIR-37791 edits added interface behavior to the same ElementDefinition descriptions, but preserved the FHIR-13474 distinction. ElementDefinition remains an active build datatype in source/fhir.ini, so source/datatypes/elementdefinition.xml is the authoritative current source to check.

AutoFHIR reconciliation:
This audit commit makes no source change. Current source/datatypes/elementdefinition.xml already distinguishes profile as applying to the datatype and targetProfile as used for Reference or canonical targets, applying to the target of the reference and requiring conformance to at least one listed profile.

Recommendation:
Keep this no-change audit. The current source satisfies FHIR-13474 after later wording refinements, and adding redundant wording elsewhere would risk maintenance drift without improving the conformance rule.
