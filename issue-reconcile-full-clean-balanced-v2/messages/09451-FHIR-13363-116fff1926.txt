FHIR-13363: Audit datatype BackboneType reconciliation

Issue request:
FHIR-13363 was a Published/Persuasive with Modification FHIR-I STU3 change request asking to distinguish true datatypes from reusable structures and give the latter distinct behavior. The accepted resolution was to extend the datatype page diagrams to cover all type categories, allow all types in extensions except Narrative and Meta as then decided, and allow modifier extensions on Dosage, Section, and Timing by using an explicit BackboneElement-style base plus related documentation.

Initial application:
The issue was applied through several 2018 commits. Git commit 895710265113b796cb75d13c9abf5cfe4aabf207 began the GF#13363 datatype-related changes, dcd3ffda9020726ce3628f04603b19e4bf289c52 centralized the wildcard/open type lists, c59c201a849833554f5f564eab2b32e2a217658d made Timing and Dosage carry modifier extensions, and 7508d2f2cbc6e6e4b77037539465e714c045a3d0 completed the #13363 datatype page work by adding metadata and special-purpose diagrams plus the modifier-extension datatype summary.

Additional context:
The current build has since refined the model from the older literal BackboneElement wording to BackboneType for datatypes that can carry modifier extensions, while retaining BackboneElement for resource backbone components such as Composition.section. Current source/fhir.ini keeps the affected datatype, infrastructure, diagram, and Composition sources active. Current source/datatypes.html shows the four datatype categories and lists the selected modifier-extension-capable datatypes; source/types.html and source/datatypes/backbonetype.xml define BackboneType as the base for datatypes that allow modifier extensions; source/datatypes/dosage.xml and source/datatypes/timing.xml derive Dosage and Timing from BackboneType; and source/composition/structuredefinition-Composition.xml derives Composition.section from BackboneElement. The original Meta exclusion was intentionally changed by later Published issue FHIR-20487, which added Meta to the Open Type Element list for Parameters, Extension, and other wildcard locations.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already preserves the FHIR-13363 substance through the modern BackboneType abstraction, the datatype category diagrams, the modifier-extension datatype list, and the current wildcard/open-type behavior after FHIR-20487.

Recommendation:
Keep this no-change audit commit as-is. No core source follow-up is needed for FHIR-13363 unless a future work group decision revisits the modern BackboneType abstraction or the later FHIR-20487 decision to allow Meta in wildcard/open-type positions.
