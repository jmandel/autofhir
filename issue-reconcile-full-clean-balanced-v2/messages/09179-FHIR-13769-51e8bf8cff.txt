FHIR-13769: Audit eld-16 bracket allowance

Issue request:
FHIR-13769 was a Published/Persuasive FHIR-core ElementDefinition change request for STU3. It asked that invariant eld-16's sliceName token regex accept "[" and "]" because choice-type element ids such as Extension.value[x]:valueString use those characters.

Initial application:
The historical application is visible in git commit 4175e6261eb3353553ccf460e609985eecfded34, imported from SVN revision 12786 and labelled "#13769 - correct sdf-20". That commit changed source/datatypes/elementdefinition.xml so eld-16 accepted bracket characters in both the FHIRPath and XPath regexes.

Additional context:
ElementDefinition is an active datatype in source/fhir.ini, so source/datatypes/elementdefinition.xml is in current build scope. Later eld-16 cleanup commits, including #13771/#15133 and GF#14389, normalized the regex and added another allowed token character, but retained the bracket allowance. Corrected Zulip and Confluence searches found no directly relevant discussion or conflicting later decision.

AutoFHIR reconciliation:

Recommendation:
Keep this no-change audit commit as-is. No FHIR core source follow-up is needed for FHIR-13769 unless a future work group decision changes eld-16 token policy more broadly.
