FHIR-20629: Audit HTTP summary header cleanup

Issue request:
FHIR-20629 was Published/Persuasive for R5. It reported that the RESTful API HTTP summary table listed ETag as a conditional request header for the read interaction even though ETag is a response header, and asked to remove ETag from that request section; the resolution clarified that request conditionals should use If-Match/If-None-Match style headers instead.

Initial application:
The issue was applied by git commit c4347b18db67b41f314989c97e930b022ca892b3, which removed ETag from the read interaction's request Conditional column in source/http.html while leaving If-Modified-Since and If-None-Match. Jira comments point to PR #1729 and say it was merged through R5 PR #1731.

Additional context:
source/http.html is current build-scope source for the RESTful API page because publish.ini maps http.html to the http page and source/documentation.html links it as RESTful API (HTTP). The current summary section now separates the two surfaces: the request table's read row lists only If-Modified-Since and If-None-Match, while the response table's read row lists ETag and Last-Modified under Versioning. A Zulip FHIR-I block-vote thread lists FHIR-20629 among the items scheduled for vote, and no Confluence reference or conflicting community discussion was found.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current source already satisfies the Jira resolution. Re-adding or moving text would be redundant and could blur the existing request/response split.

Recommendation:
Keep this audit commit as-is. No further core FHIR source work is needed for FHIR-20629 unless a future tracker asks for a broader redesign of the HTTP summary table.
