FHIR-22696: Align Appointment participant ModelInfo

Issue request:
FHIR-22696 was a Published/Persuasive with Modification PA change request for R5. It reported that Appointment.participant.required's required ParticipantRequired value set, especially information-only, contradicted the participant definition; the approved resolution added Appointment.subject, changed Appointment.participant.required from a code to a boolean, aligned Appointment/Encounter participant actor references, and expanded AppointmentResponse.actor.

Initial application:
The main source was applied by #FHIR-22696 commits 21e95de9dc, 99a321f377, d1af9f83a1, and 51c7448ff0. Those commits updated the Appointment StructureDefinition, introduction text, two-doctor example, AppointmentResponse actor target list, Encounter participant actor rename, Encounter examples, and search parameters. They did not update the active Library model-definition examples, which still exposed Appointment.participant.required as ParticipantRequired, omitted Appointment.subject, and retained Encounter.Participant.individual.

Additional context:
The 2020-06-10 PA minutes record the same decision and vote: create a subject property for patient/group, align Appointment and Encounter participations, and make required boolean. Appointment, AppointmentResponse, Encounter, and Library are active in source/fhir.ini; publish.ini copies both model-definition content XML files into the build, and the Library examples page links them as CQL-to-ELM model information. Later PA decisions such as FHIR-35841 and FHIR-32347 clarified descriptions and optionality around participant.actor but do not reverse the FHIR-22696 model changes. The remaining source/fhir.ini Encounter.participant.individual mapping is compatibility metadata for the old name, not a current model element.

AutoFHIR reconciliation:
Updated the active FHIR and QUICK Library model-definition content so Appointment includes subject, Appointment.Participant.required is boolean/System.Boolean with period before actor, Encounter.Participant uses actor instead of individual, and the now-unused ParticipantRequired model type/conversion entries are removed.

Recommendation:
Keep this source fix. The authoritative Appointment, AppointmentResponse, and Encounter StructureDefinitions already carry the approved semantics, so no primary resource or terminology source change is needed; if the Library model-info examples are regenerated, preserve these R5/R6 Appointment and Encounter shapes.
