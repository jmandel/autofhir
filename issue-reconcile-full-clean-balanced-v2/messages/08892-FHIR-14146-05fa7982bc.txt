FHIR-14146: Audit Media modality value set

Issue request:
FHIR-14146 was Published/Persuasive for STU3. It asked to review the old MediaSubtype value set because it mixed DICOM/FHIR media modality values with SNOMED procedure concepts; the accepted motion was to change Media sub-type to modality as applied and remove SNOMED procedures from the associated value set.

Initial application:
No commit explicitly tagged FHIR-14146 was found. The matching source change appears in git history as commit 33340aa98afbb0a0c87dad22c4e7311253b21d4d, whose subject says "[#14881] change media sub-type to modality and remove snowed from binding" and whose patch renamed the binding to MediaModality, changed the value set reference to valueset-media-modality, and added the Media Modality value set.

Additional context:
OO January 2018 minutes record the same tracker item, rationale, vote, and scope: mediaSubtype mixed acquisition modality with procedures/body sites, the accepted fix was to trim the modality value set by removing SNOMED CT codes and rename subtype to modality, while other possible elements and ImagingStudy boundary clarifications required further discussion. Later source refactors moved the Media modality code system URL to terminology.hl7.org and removed local UTG code system content, but did not reintroduce the old subtype or SNOMED procedure binding. source/fhir.ini still contains a commented legacy rename line, ;Media.subtype=Media.modality, which is migration metadata rather than an active element definition. FHIR-9731 was an older published report that the media subtype value set expansion was broken; it is background only and not decided here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active Media source already has Media.modality bound to MediaModality, source/media/valueset-media-modality.xml composes DICOM CID 29 plus the HL7 media-modality code system, and the current Media modality value set source contains no SNOMED system or Phlebography-style procedure concepts. source/fhir.ini actively includes the Media resource, so these source checks are in current build scope.

Keep this no-change audit as-is. Do not add a new Media code element or duplicate the old discussion in narrative without a newer work-group decision, because the accepted FHIR-14146 source outcome is already present and the minutes explicitly left other potential additions for later discussion.
