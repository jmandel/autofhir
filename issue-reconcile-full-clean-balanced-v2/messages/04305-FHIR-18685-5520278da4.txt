FHIR-18685: Audit ValueSet status alignment

Issue request:
FHIR-18685 was a Published FHIR-core ValueSet change request resolved as Persuasive with Modification for STU3. It asked to align ValueSet.status with VSD Activity Status by removing the old VSD 11 invariant, keeping the ValueSet.status name, clarifying that ValueSet.status applies to the value set definition/compose plus non-expansion metadata, and stating that value set expansions are stateless in the ValueSet.expansion comments.

Initial application:
The Jira snapshot records Grahame's implementation comment pointing to git fbcbcb6ac4f574b7f9859cc6bf36e54befb5d312. That commit was titled "GF#18685 - remove vsd-11 and update definitions" and changed source/valueset/valueset-spreadsheet.xml to add the status definition sentence and the expansion stateless comment. The old expansion/status invariant is no longer present in the current ValueSet source.

Additional context:
ValueSet is an active resource in source/fhir.ini, so source/valueset/structuredefinition-ValueSet.xml and source/valueset/valueset-notes.xml are in current build scope. The current source states that ValueSet.status applies to ValueSet.compose and associated metadata, and that expansions do not have a state. It also explains in the VSD notes that ActivityStatus aligns with ValueSet.status except for ValueSet.expansion. A current vsd-11 key remains, but FHIR-29821 later reused that invariant number for concept.designation.additionalUse requiring concept.designation.use; it is unrelated to the removed expansion/status invariant. FHIR-36015 later added VSD-aligned guidance text consistent with the seed decision. Confluence WGM minutes confirm the 2018 motion, and the relevant Zulip discussion found no reversal of the seed rule.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active source already implements the FHIR-18685 decision, and changing the later unrelated designation vsd-11 invariant would be incorrect.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-18685 unless the work group separately decides to revise the broader terminology guidance for persisted expansions or workflow status.
