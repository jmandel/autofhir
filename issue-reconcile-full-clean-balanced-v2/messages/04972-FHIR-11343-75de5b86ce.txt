FHIR-11343: Audit CarePlan definition supersession

Issue request:
FHIR-11343 is a Published/Persuasive Patient Care change request from the DSTU2 ballot asking to add a top-level CarePlan.definition element, parallel to the then-existing CarePlan.activity.detail.definition, so a care plan could identify the protocol, questionnaire, guideline, or other specification it should follow.

Initial application:
The issue was applied by c124072d7b, which added CarePlan.definition with the requested definition text and GF#11343 committee notes to the CarePlan spreadsheet. Subsequent workflow-alignment history moved that same top-level concept from CarePlan.definition to CarePlan.instantiates and later to CarePlan.instantiatesCanonical and CarePlan.instantiatesUri.

Additional context:
A later final Patient Care decision, FHIR-40500, superseded the top-level instantiates approach for CarePlan. FHIR-40500 is Applied/Persuasive with Modification and requested removal of instantiatesCanonical and instantiatesUri from CarePlan, Communication, FamilyMemberHistory, and Procedure because workflow patterns replaced ambiguous instantiates usage with more precise workflow extensions. Core commit 6089508bef removed the top-level CarePlan instantiates elements, and combined-branch commit bd6bc0311a already represents FHIR-40500 reconciliation. Current authoritative CarePlan source has no top-level CarePlan.definition or CarePlan.instantiates[x]; it keeps activity-level plannedActivityDetail.instantiatesCanonical/Uri for individual activities, describes CarePlan as a specific intent rather than a generic definition, and records the removed CarePlan.instantiatesCanonical/Uri entries only as R5-to-R6 migration/deletion metadata in fhir.ini. A checked-in careplan.svg still mentions the removed top-level elements, but that is a generated-looking diagram artifact and not a sufficient reason for a FHIR-11343 source edit.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Re-adding a top-level CarePlan.definition or instantiates[x] element would conflict with the later applied FHIR-40500 workflow-pattern decision and duplicate work already represented on the combined branch.

Recommendation:
Keep this audit commit as-is. If the stale CarePlan SVG is considered build-significant, handle it through the diagram generation/source pipeline or as part of the existing FHIR-40500 family rather than by reopening FHIR-11343 semantics.
