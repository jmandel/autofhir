FHIR-32751: Align ActivityDefinition ModelInfo requirements

Issue request:
FHIR-32751 was Published with a Persuasive with Modification resolution for the CDS work group. It requested that ActivityDefinition's reference to ObservationDefinition use canonical, and the approved resolution explicitly extended the same change to SpecimenDefinition by making specimenRequirement, observationRequirement, and observationResultRequirement canonical.

Initial application:
The issue was applied for R5 by PR #2237. Commit 027786fb6f8598c84ab06411f07cc49739ecaa6c changed those three elements in source/activitydefinition/structuredefinition-ActivityDefinition.xml from Reference to canonical, and merge commit 7e44ec168d3c0b2bbf85e343e0eadff65bfcea4a brought that source change into the main branch. The current StructureDefinition source and ActivityDefinition diagram already show canonical for the three elements.

Additional context:
ActivityDefinition is an active resource in source/fhir.ini, and the Library resource examples include the checked-in FHIR ModelInfo library through source/library/list-Library-examples.xml and source/library/library-examples-header.xml. That ModelInfo content still described the three ActivityDefinition properties as lists of FHIR.Reference, creating a source-level inconsistency with the already-applied StructureDefinition and diagram. Targeted Jira, Zulip, and Confluence searches found no later final decision reversing the canonical change.

AutoFHIR reconciliation:
Updated source/library/library-fhir-model-definition-content.xml so ActivityDefinition.specimenRequirement, ActivityDefinition.observationRequirement, and ActivityDefinition.observationResultRequirement are lists of FHIR.canonical instead of FHIR.Reference. No other ActivityDefinition source was changed because the authoritative StructureDefinition already carries the approved canonical datatypes.

Recommendation:
Keep this commit as the completion of FHIR-32751 in the current build: it aligns the remaining checked-in ModelInfo surface with the published R5 StructureDefinition change. If a future automated ModelInfo regeneration overwrites this file, ensure the generator uses the canonical datatypes from the ActivityDefinition StructureDefinition.
