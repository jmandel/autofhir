FHIR-26663: Audit Medication reference list

Issue request:
FHIR-26663 was a Published/Persuasive FHIR-core change request for R5 asking that the Medication page's "References to this Resource" list include MedicationRequest, because MedicationRequest.medication used the then-new ConceptReference pattern and was missing from the generated resources-using-Medication list.

Initial application:
No local git commit explicitly tagged FHIR-26663 was found, and the combined branch did not already contain an Issue-Reconcile-Key audit for it. The current active R5/R6 source introduced by the 2021 source rework defines MedicationRequest.medication as a CodeableReference with targetProfile Medication, and the current CI build renders MedicationRequest in the Medication resource references list, so the source and tooling-visible output now reflect the requested application.

Additional context:
MedicationRequest and Medication are both active resources in source/fhir.ini. FHIR-I minutes from 2020-03-30 record the same issue with "Will fix tooling" and an 11-0-0 vote. Jira searches for the issue key and MedicationRequest/Medication/ConceptReference found no separate related issue to decide, and Zulip/Confluence term searches found no conflicting community direction.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative MedicationRequest StructureDefinition already targets Medication from MedicationRequest.medication, and the current CI-built Medication page already lists MedicationRequest under References to this Resource.

Recommendation:
Keep this audit commit as-is. If this regression reappears, investigate the publisher/reference-list generation for CodeableReference targetProfile handling rather than changing the current MedicationRequest source.
