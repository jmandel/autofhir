FHIR-14690: Audit CodeSystem key-property wording

Issue request:
FHIR-14690 was Published/Persuasive with Modification for STU3 CodeSystem wording. It asked to improve the introductory bullet so the code system's case-sensitivity property is clearly about the codes it defines, with final resolution text naming version safety, compositional grammar, and whether the defined codes are case sensitive.

Initial application:
The issue was pre-applied in SVN revision 13341, imported as git commit 080e47c1a06da8867d5f876ed2bb2d528dc64632. That commit replaced the older bullet, "whether it's case sensitive, version safe, and whether it defines a compositional grammar", with the clarified sentence that says "whether the codes that it defines are case sensitive".

Additional context:
The same sentence was intentionally updated three days later by Published/Persuasive with Modification issue FHIR-14243, imported as git commit d8e6a4d5c137f9f46a525457f09d248a8e892a42, replacing the unclear phrase "version safe" with "exhibits concept permanence". CodeSystem is an active resource in source/fhir.ini, and the authoritative current source at source/codesystem/codesystem-introduction.xml keeps the FHIR-14690 case-sensitivity clarification while reflecting the later FHIR-14243 wording.

AutoFHIR reconciliation:
This audit commit makes no source change because the current build-scoped CodeSystem introduction already conveys the approved FHIR-14690 clarification, and changing "concept permanence" back to the older resolution phrase would undo a later published decision.

Recommendation:
