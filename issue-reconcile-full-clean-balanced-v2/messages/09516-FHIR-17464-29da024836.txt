FHIR-17464: Audit search escaping clarification

Issue request:
FHIR-17464 was a Published FHIR-I change request resolved as Persuasive. It asked the search specification to clarify the difference between HTTP/RFC 3986 percent encoding of URL parameters and FHIR's backslash escaping for search separator characters such as comma, dollar sign, and pipe.

Initial application:
The issue appears to have been applied by Git/SVN import commit e45b3e06685838ef5be827524cd4915ae0f9d214, titled "GF#17464 - clarifications about escaping" and carrying SVN revision 14562. That commit changed source/search.html's "Escaping Search Parameters" section to distinguish values like code=a,b from code=a\,b and to state that FHIR backslash escaping is at a different level than percent encoding applied to URL parameters.

Additional context:
The linked Zulip thread records the rationale: Justin Stauffer raised the RFC 3986 reserved-character concern, Grahame Grieve described FHIR as having a second level of escaping, and Ewout Kramer explained that percent encoding gets a search string across HTTP while FHIR backslash escaping distinguishes search syntax from literal parameter values. Later FHIR-48702 added the current "Notes on URL-Encoding" section and refreshed examples, and FHIR-42834 corrected a same-section escaped-comma example; both related issues are already represented on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/search.html already includes a build-scope search page with top-level URL-encoding guidance, an escaping section that says standard percent escaping still applies, examples showing percent-encoded and unencoded delimiter forms with the same meaning, and a separate escaped-delimiter example showing that a backslash-escaped comma is literal data rather than a multi-value separator.

Recommendation:
Keep this audit commit as-is. No further FHIR-core source work is needed for FHIR-17464 unless a future work group decision changes the search URL-processing model.
