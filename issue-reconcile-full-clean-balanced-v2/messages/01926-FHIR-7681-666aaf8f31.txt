FHIR-7681: Audit ImagingObjectSelection retrieval URLs

Issue request:
FHIR-7681 was a Published, Not Persuasive with Modification DSTU1 Imaging issue asking whether ImagingObjectSelection really needed four Retrieve URLs that all mapped to DICOM (0008,1190). The resolution kept URLs at each retrieval level and called for explanatory text about Accept headers and links to DICOM Part 18.

Initial application:
The change appears to have been applied in git commit 2a416c3e03, whose subject explicitly lists 7681 and changed the ImagingObjectSelection spreadsheet: retrieveUrl elements were renamed to url, retained at study/series/instance/frame levels, and continued to describe WADO-RS retrieval and the DICOM Retrieve URL mapping.

Additional context:
The original ImagingObjectSelection resource is no longer active in the current build; source/fhir.ini keeps it only in the dropped-resource list, and current history records ImagingManifest as removed. Later imaging work created the active ImagingSelection resource, and the current ImagingSelection endpoint notes explain DICOM WADO-RS and WADO-URI retrieval, use of request Accept headers or query parameters for native/rendered formats such as JPEG, URL construction from Endpoint.address, and DICOM Part 18 links. Related endpoint/removal/ImagingSelection tickets already have their own audit commits on the combined branch.
