FHIR-36191: Confirm NamingSystem MetadataResource application

Issue request:
FHIR-36191 was a Published/Persuasive Vocab change request asking that NamingSystem become a MetadataResource because it is a knowledge artifact with the same content-management lifecycle considerations as other knowledge artifacts.

Initial application:
The issue was already applied in source history. Commit a43b2ee changed source/namingsystem/structuredefinition-NamingSystem.xml from CanonicalResource to MetadataResource, and the later PR 2065 work in ee7329e added the MetadataResource lifecycle elements, examples, and search parameters for NamingSystem.

Additional context:
NamingSystem is an active current-build resource in source/fhir.ini and remains assigned to Vocab. Vocab minutes show the issue was resolved on 2022-04-11, later reviewed under MetadataResource element rendering, and recorded on 2022-08-04 as applied with the note that the ConceptMap/NamingSystem MetadataResource follow-up should now be done. A related Zulip thread raised the same concern that NamingSystem lacked MetadataResource-like fields, but no discovered later Jira, Zulip, or Confluence evidence contradicts the applied result.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current source/namingsystem/structuredefinition-NamingSystem.xml already uses the MetadataResource build template and baseDefinition and includes the MetadataResource lifecycle elements, while the active NamingSystem search-parameter bundle includes metadata-related parameters such as identifier, effective, derived-from, successor, and topic.

Recommendation:
Keep this no-change audit commit as-is for FHIR-36191. No core source follow-up is needed for NamingSystem; the same-change-family ConceptMap issue FHIR-36190 should be handled separately if assigned.
