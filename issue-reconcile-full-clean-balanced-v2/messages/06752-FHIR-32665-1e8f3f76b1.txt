FHIR-32665: Audit QuestionnaireResponse answer value cardinality

Issue request:
FHIR-32665 was a Published FHIR-core QuestionnaireAnswers change request asking whether a QuestionnaireResponse child question can have an answer under item.answer.item when the parent item.answer has no value. The final Persuasive resolution was to make QuestionnaireResponse.item.answer.value[x] 1..1 instead of 0..1; if there is no parent answer, omit item.answer, so no extra prose clarification is needed.

Initial application:
The Jira comment points to HL7/fhir#1337. Commit 35ff6ea60f17c3279bb14071bfb3a9b73a89aa34 changed source/questionnaireresponse/structuredefinition-QuestionnaireResponse.xml from <min value="0"/> to <min value="1"/> for QuestionnaireResponse.item.answer.value[x], and merge commit 0a821bba35de3393a12e90941568eaa9cd01471b brought PR #1337 into the main history with the message "Fix FHIR-32665/26292".

Additional context:
QuestionnaireResponse is active in source/fhir.ini, so the inspected StructureDefinition source is in current build scope. The current source still has QuestionnaireResponse.item.answer.value[x] at min 1 and max 1, and item.answer.item remains available only as child items within a particular answer. The originating Zulip discussion explains the rationale: child questions under a question are per-answer details and are meaningless without a parent answer; a later Zulip thread cites FHIR-32665 when confirming that having children with no answer is invalid. FHIR SDC minutes for 2021-07-22 record approval of FHIR-32665 as Persuasive. A separate existing combined-branch audit for FHIR-6906 treats FHIR-32665 as supporting context in the broader questionnaire answer-nesting family, but it does not duplicate this seed decision.

AutoFHIR reconciliation:
This commit makes no source change. The current active QuestionnaireResponse source already implements the Jira resolution by requiring item.answer.value[x] whenever an item.answer exists, which resolves the ambiguity about item.answer.item child answers without adding redundant prose.

Recommendation:
Keep this no-change audit. Future changes to allow child question answers without a parent answer should come through a new SDC/FHIR-I decision because they would reverse the explicit FHIR-32665 cardinality decision.
