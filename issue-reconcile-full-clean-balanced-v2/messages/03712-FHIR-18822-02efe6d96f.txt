FHIR-18822: Use identifier wording for Organization identifiers

Issue request:
FHIR-18822 was a Published/Persuasive FHIR-core Organization clarification. It asked to avoid using "id" for business identifiers by changing org-1 from "name or an id" to "name or an identifier" and by updating the Organization.identifier requirements text to use "identifier" terminology.

Initial application:
The Jira-tagged commit 24a0db08528f365794be109bd33089f696be0772 updated the org-1 invariant wording in the then-authoritative Organization spreadsheet. Later source refactors carried the invariant text into source/organization/structuredefinition-Organization.xml, but the Organization.identifier requirements line in current active source still said "variety of ids". A later mapping-exception source file copied the same stale requirements text.

Additional context:
source/fhir.ini lists Organization as an active resource owned by PA, so source/organization/structuredefinition-Organization.xml is in current build scope. The Participant mapping exception records the current Organization.identifier requirements text for mapping-pattern comparison and must stay aligned with the resource source. Jira neighborhood and community searches did not identify a later conflicting decision or a separate related FHIR-core issue to decide.

AutoFHIR reconciliation:
Updated Organization.identifier requirements in the active StructureDefinition source from "variety of ids" to "variety of identifiers" and made the matching update in organization-participant-mapping-exceptions.xml. No other Organization wording changes were needed because org-1 already says "name or an identifier".

Recommendation:
Keep this commit as-is. It completes the second half of FHIR-18822's published resolution while preserving the already-correct invariant wording and keeping mapping exception source synchronized with the active resource definition.
