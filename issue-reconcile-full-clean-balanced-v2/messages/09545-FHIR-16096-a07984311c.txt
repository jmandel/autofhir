FHIR-16096: Audit HTTP contention status codes

Issue request:
FHIR-16096 was a Published/Persuasive FHIR-core HTTP change request for the RESTful API resource contention section. It asked that failed client If-Match preconditions return 412 Precondition Failed, that a missing If-Match header required by the server return 400 rather than 412, and that 409 Conflict remain available for server-detected conflicts such as pessimistic locking.

Initial application:
The Jira comments cite svn revision 13891. In git history this is 8a1c698f33ad8bd8939ff3cdf3b6c221b81e1a4b, which changed source/http.html from 409-on-If-Match-failure and 412-on-missing-If-Match to 412, 400, and a 409 pessimistic-locking note. That initial application left rough labels ("412 Conflict" and "400 Client Error"), which were later corrected by f25a484e20387684e12152c5625b387c453dd71f and ee761ef4bd5a52057846f25556c859510db5375c.

Additional context:
The current combined branch source/http.html is the active RESTful API page linked from source/exchange-module.html. It now says a non-matching If-Match returns 412 Precondition Failed, a server requiring If-Match can return 400 Bad Request when the header is absent, and 409 Conflict can be returned when the server detects the update cannot be done, for example due to server-side pessimistic locking. Jira, Zulip, and Confluence searches found no later directly relevant reversal or conflicting decision.
