FHIR-28593: Audit MedicationStatement status record semantics

Issue request:
FHIR-28593 was a Published/Persuasive Pharmacy issue for the R5 MedicationUsage resource. It asked whether MedicationUsage.status was still needed and whether its value set should be narrowed; the approved resolution kept the status attribute, clarified that it is the status of the record rather than clinical medication-use status, and initially chose completed, entered-in-error, and unknown.

Initial application:
The issue was applied by f351511a957fc178e55907a68ff1016e2387aa80, whose commit message explicitly cites FHIR-28593. That commit changed the then-active source/medicationusage StructureDefinition, status CodeSystem, examples, and related files so MedicationUsage.status used completed, entered-in-error, and unknown with record-status-oriented wording instead of the older broader medication-use status codes.

Additional context:
Later Published Pharmacy decisions changed the same status family. FHIR-32060 removed unknown, renamed completed to recorded, added draft, and required a note that the status meanings differ from prior MedicationStatement releases. FHIR-32858 confirmed that the missing medication-use scenarios are represented by effective[x] and adherence rather than by restoring old status codes. FHIR-39271 later renamed MedicationUsage back to MedicationStatement while preserving the record-status model and stating that MedicationStatement.adherence carries taking/not-taking meaning. Those related issues are already represented on the combined branch, including FHIR-32060 as 6d07ea813b80a81dc3c3040e9e078ddd95df49ee, FHIR-32858 as d23bc1561f2919b1feeaad8baae92334beb40992, and FHIR-39271 as d5e940beb286ab92d70095420b10a3ad7a643d06.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active build uses source/medicationstatement and source/fhir.ini lists MedicationStatement as an active resource. MedicationStatement.status is defined as recorded | entered-in-error | draft, its definition says it represents the status of recording the medication statement, and its comment directs medication taking/adherence semantics to MedicationStatement.adherence. That is the correct current state after FHIR-28593 plus the later published decisions; reverting to completed/entered-in-error/unknown would contradict FHIR-32060 and FHIR-39271.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-28593 unless Pharmacy reopens the later MedicationStatement status/adherence model; any future reconsideration should start from FHIR-32060, FHIR-32858, and FHIR-39271 rather than the superseded initial FHIR-28593 value list alone.
