FHIR-28589: Audit _count paging clarification

Issue request:
FHIR-28589 was a Published/Persuasive with Modification FHIR-I clarification for R5 asking the Search `_count` paging text to explain what happens when a requested `_count` exceeds a server's maximum page size. The accepted wording replaced advice to repeat the original `_count` in page links with a requirement that reachable page links respect the original requested `_count` expectations or a server-overridden maximum page size.

Initial application:
The issue was applied in git commit 575c96fa17 ("FHIR-28589 - First Pass"), which changed `source/search.html` under the `_count` section from repeating the original `_count` parameter in returned page links to ensuring reachable links respect the requested `_count` expectations or a server maximum. Later commits a3766ac36c6 and 887bc2383fb only wrapped the text in conformance markup and adjusted punctuation; they did not reverse the FHIR-28589 semantics.

Additional context:
The original Zulip thread confirms the problem statement: a server may cap a requested `_count` at its own page size, and Lloyd McKenzie asked for a change request to clarify that behavior. FHIR-I minutes from 2021-01-04 record the vote and state the intended change as enforcing page size consistency with the original `_count`. A Jira neighborhood search for `_count` and server page size found only FHIR-28589 as the applicable final tracker. The current source retains a duplicated article in "respect the the original requested", but that typo was present in the Jira resolution and does not change the conformance meaning.

AutoFHIR reconciliation:
No source change was made. The current Search source already says that pages reachable through previous/next links SHOULD respect the original requested `_count` expectations or a server-overridden max page size, which is the substantive clarification requested by FHIR-28589.

Recommendation:
Keep this audit commit as-is. If editors want to remove the duplicated "the", handle it as a separate editorial cleanup; it is below the issue-reconcile threshold because implementers still receive the intended `_count` page-size rule.
