FHIR-28577: Audit $translate reverse semantics

Issue request:
FHIR-28577 was Published/Persuasive for R5 and asked Vocab to clarify ConceptMap/$translate reverse=true behavior. The approved resolution reworded the reverse parameter so the input code/coding is understood as a target-side concept, targetScope rather than sourceScope applies, and dependency parameters match ConceptMap.group.element.target.product rather than ConceptMap.group.element.target.dependsOn.

Initial application:
Commit 3a8665b9c2 applied the issue during the R5 ConceptMap work by replacing the reverse parameter documentation in source/conceptmap/operationdefinition-ConceptMap-translate.xml with the approved target-side and product-vs-dependsOn wording. The same change family also adjusted sourceScope/targetScope names and $translate match product/dependsOn output parts.

Additional context:
FHIR-32129 was later Published/Persuasive with Modification and superseded the reverse-parameter model by removing reverse entirely, renaming the source inputs to source*, adding target* inputs, and describing forward and reverse lookup directly by which side of a mapping the input identifies. That later decision has already been represented on the combined branch by aab515ed02, which completed the active operation description wording. ConceptMap is active in source/fhir.ini, and source/conceptmap/list-ConceptMap-operations.xml includes OperationDefinition/ConceptMap-translate, so the current operation definition is the build-scope source to check.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current ConceptMap/$translate OperationDefinition no longer has a reverse parameter, includes sourceCode/sourceCoding/sourceCodeableConcept and targetCode/targetCoding/targetCodeableConcept inputs, and describes source* and target* behavior directly. Reintroducing FHIR-28577's reverse=true wording would conflict with the later FHIR-32129 model.

Recommendation:
Keep this audit commit as-is. The seed issue was applied historically, then safely superseded by the later published removal of reverse; any future clarification about dependency matching for target* lookups should be raised as a new ConceptMap/$translate issue rather than restoring obsolete reverse-parameter text.
