FHIR-16484: Audit ValueSet expansion content guidance

Issue request:
FHIR-16484 was a Published/Persuasive vocab Change Request raised against STU3 ValueSet behavior. It asked for guidance when a code system referenced during a ValueSet $expand operation is an example, a fragment, or a supplement; the accepted resolution was to add guidance and a note about expansion parameters in the fragment-related guidance.

Initial application:
The Jira comment records SVN revision 14017. Git history shows the application in b178b1be54533cde22ea827d6cb8ef2ab5ddef11 and a5f0637555b6b6f47439a73fce551b681355fe62, which added the ValueSet Expansion Parameters section and introduced [canonical]#CodeSystem.content plus [canonical1]#supplement rows. Same-day follow-up 252fc52edfdbfbf0899b646437b94f6421358c8e made the fragment and supplement recording requirements stronger, and later ade907ca5b1bc08efb093bc524c5b00bdc7fa5ac applied FHIR-27880 by removing a dangling unfinished "or" from the fragment requirement.

Additional context:
The current source/fhir.ini has active valueset=ValueSet and codesystem=CodeSystem resource entries, so source/valueset/valueset-notes.xml and source/codesystem/codesystem-notes.xml are current build inputs. Current ValueSet guidance says returned expansion parameters SHOULD include canonical or URI references for all CodeSystems, CodeSystem Supplements, and ValueSets used in the expansion, defines [canonical]#CodeSystem.content for the code-system content value, requires that parameter when CodeSystem.content is fragment, and requires [canonical1]#supplement when a supplement was used. Later applied FHIR-41589/FHIR-41639 work aligned the broader returned-parameter accounting and added used-system, used-supplement, and used-valueset response parameters. FHIR-48959 is a later Resolved - change required proposal for additional fragment-completeness signaling, and FHIR-53375 leaves the meaning of CodeSystem.content=example under active discussion; neither is Applied/Published for this run scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active ValueSet expansion-parameter guidance already carries the 2018 guidance for fragments and supplements, while the later Published FHIR-27880 correction explicitly removed the unfinished "or" instead of mandating an example-specific content parameter. Re-adding "example" here would overrun the later correction and preempt unresolved CodeSystem.content=example work.

Recommendation:
Keep this audit commit as-is for FHIR-16484. Handle FHIR-48959 and FHIR-53375 separately if and when they reach an Applied/Published state, because they refine fragment completeness and example content semantics beyond this seed's applied 2018 reconciliation.
