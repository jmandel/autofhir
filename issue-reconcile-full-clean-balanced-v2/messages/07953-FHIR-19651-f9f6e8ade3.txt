FHIR-19651: Audit CompartmentDefinition boundaries clarification

Issue request:
FHIR-19651 was a Published/Persuasive FHIR-I change request from STU3, applied for R5, asking the Boundaries and Relationships sections for GraphDefinition and CompartmentDefinition to clarify their overlap. The approved text distinguished CompartmentDefinition's compartment/search-parameter model from GraphDefinition's more expressive resource grouping model.

Initial application:
The issue was initially applied by commit ab4179d05ced32f5ad816ef3c2f4bc51562038e1, which added the requested CompartmentDefinition paragraph and the matching GraphDefinition paragraph. Later GraphDefinition edits, including FHIR-25474 in commit 93e0bc90e3a80969bae01ab57e37a0cb9221ee68, preserved the distinction and corrected the grammar in that paragraph.

Additional context:
The current build scope still includes CompartmentDefinition in source/fhir.ini, and source/compartmentdefinition/compartmentdefinition-introduction.xml still contains the requested Boundaries and Relationships clarification. GraphDefinition is no longer an active core resource in this checkout: commit 270e0ceb7b029dad4ca0fc5ccf5296ff370888cd removed the graphdefinition resource entries from source/fhir.ini and deleted source/graphdefinition/*. Current core references point to the API incubator GraphDefinition rather than to a core GraphDefinition page.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current core source already carries the CompartmentDefinition half of the approved clarification, and the former core GraphDefinition source location that previously carried the other half is outside the current FHIR core build.

Recommendation:
Keep this no-change audit commit as-is for FHIR core. No core follow-up is needed unless the work group wants a separate review of the external/API-incubator GraphDefinition material.
