FHIR-37517: Audit external religion extension binding

Issue request:
FHIR-37517 is a Published/Persuasive Patient Administration change request for R5. It asked that the ReligiousAffiliation binding on the patient-religion extension be changed from extensible to preferred because implementers cannot reliably decide whether every local religion concept is equivalent to or a subtype of a code in the supplied value set.

Initial application:
The issue was applied in core by commit 15e4b18305634e1cfc062c651703b3cbb12993fc, which changed source/patient/structuredefinition-extension-patient-religion.xml from <strength value="extensible"/> to <strength value="preferred"/>. That commit is contained in the v5.0.0 tag.

Additional context:
Core later removed this extension source in commit dd468d4f1799dd79819315b211588ef1cf4586e0 as part of moving extensions out of the R5 source. The current core checkout has no active source/fhir.ini reference for patient-religion and only retains the canonical OID mapping in source/oids.ini. The current FHIR Extension Pack source at input/definitions/Patient/StructureDefinition-patient-religion.xml is the active home of the extension and already carries <strength value="preferred"/> for http://terminology.hl7.org/ValueSet/v3-ReligiousAffiliation.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The requested binding correction was already applied before R5 publication, and the current authoritative extension definition is maintained in the FHIR Extension Pack rather than this core build.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed for FHIR-37517; if future changes are needed for patient-religion, they should be made in the FHIR Extension Pack, where the binding is already preferred.
