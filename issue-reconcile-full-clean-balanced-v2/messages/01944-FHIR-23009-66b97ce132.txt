FHIR-23009: Audit Patient.link RelatedPerson wording

Issue request:
FHIR-23009 was a Published/Persuasive PA change request, applied for R5, asking the Patient.link narrative and element wording to acknowledge that Patient.link can point to RelatedPerson as already supported by the structure and examples. Its resolution changed the wording from linking only another patient to linking other Patient or RelatedPerson resources that concern the same actual person.

Initial application:
The change was already applied in source by git commit 0c1f77f6446d5ba97a2a8e3153f1b9ab78c49f56, which updated Patient.link short and definition in source/patient/structuredefinition-Patient.xml to include RelatedPerson. Later commits for FHIR-32874 and FHIR-34329 cleaned up the same wording. Patient is active in source/fhir.ini, so the checked StructureDefinition source is in build scope.

Additional context:
FHIR-32874 corrected the Patient.link short and definition text that FHIR-23009 initially introduced, and FHIR-34156 later aligned Patient.link.other.definition with the same Patient-or-RelatedPerson model. FHIR-41559 and the linked 2023 Zulip thread clarified RelatedPerson's own description after an implementer questioned the Patient.link/RelatedPerson relationship, supporting the current model rather than reversing it.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/patient/structuredefinition-Patient.xml keeps Patient.link and Patient.link.other inclusive of Patient and RelatedPerson, and Patient.link.other declares both target profiles.

Recommendation:
Keep this audit commit as-is. No further core source work is needed for FHIR-23009; related cleanups are already reflected in current source and in separate issue history.
