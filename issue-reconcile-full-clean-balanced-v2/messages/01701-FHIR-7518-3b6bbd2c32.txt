FHIR-7518: Audit Immunization protocol cardinality

Issue request:
FHIR-7518 was Published with a Not Persuasive with Modification resolution for DSTU1 Immunization.vaccinationProtocol. The ballot question challenged the 0..* protocol cardinality; the recorded examples supported repeatable protocol entries for multivalent vaccines and the applied modification changed doseTarget/targetDisease to repeat and use SNOMED-derived target disease codes.

Initial application:
The issue was explicitly applied in 2015 commits 4e6d62c693, e43671d5b7, and bde793d48a. Those commits kept Immunization.vaccinationProtocol repeatable, changed Immunization.vaccinationProtocol.doseTarget/targetDisease from 1..1 to 1..*, renamed doseTarget to targetDisease with FHIR-7519, and updated the vaccination protocol target disease value set toward SNOMED CT disease concepts.

Additional context:
The current resource source is in build scope through the active Immunization entry in source/fhir.ini. Later published Immunization decisions changed the model: FHIR-8406 removed the old vaccinationProtocol backbone for R4, FHIR-16520 reintroduced a protocolApplied backbone at 0..*, and FHIR-19487 later changed protocolApplied.targetDisease to no minimum cardinality. FHIR-15972 further refined the example target disease value set while leaving the example binding in place.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source has Immunization.protocolApplied 0..* and a SNOMED CT-based Immunization Target Disease value set, preserving the parts of FHIR-7518 that still apply. The current targetDisease 0..* cardinality is an intentional later Published change from FHIR-19487, so restoring FHIR-7518's earlier 1..* application would be wrong.

Recommendation:
Keep this no-change audit as-is. No core source follow-up is needed for FHIR-7518 unless the Public Health work group reopens the later protocolApplied/targetDisease decisions.
