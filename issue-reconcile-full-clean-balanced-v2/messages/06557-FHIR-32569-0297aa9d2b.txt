FHIR-32569: Audit Device operational status cardinality

Issue request:
FHIR-32569 was a Published/Persuasive OO change request for R5 asking why Device.operationalStatus.value was optional; the approved motion was to make operationStatus.value 1..1 because the operationalStatus backbone is optional but a reason without a status does not make sense.

Initial application:
The request was applied in commit a984eb224b, which changed source/device/structuredefinition-Device.xml so Device.operationalStatus.value had min=1 instead of min=0.

Additional context:
Later Published Device redesign issues changed the same artifact before the current build: FHIR-36195 replaced Device.operationalStatus with Device.operation/status-style content, FHIR-37545 renamed operationalState to operation, and FHIR-38904 then removed the Device operation/operationStatus backbone from active Device source. Device remains an active resource in source/fhir.ini, and DeviceAssociation is also active, but current Device source contains the old Device.operation.status/statusReason structure only inside an XML comment while DeviceAssociation notes that its operation backbone was collapsed into other elements.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build has no active Device.operationalStatus.value element whose cardinality could be wrong; the only remaining commented Device.operation.status text already shows min=1 and is not build-scope source behavior.

Recommendation:
Keep this audit commit as-is. Do not reintroduce Device.operationalStatus or Device.operation just to satisfy FHIR-32569; any future reconsideration should be handled as a new Device/DeviceAssociation design issue because later published decisions superseded the original R5 element shape.
