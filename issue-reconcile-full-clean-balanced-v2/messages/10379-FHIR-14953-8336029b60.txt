FHIR-14953: Audit sparse differential tooling scope

Issue request:
FHIR-14953 is a Published/Persuasive FHIR-core change request, raised in STU3 and applied for R5, asking that the IG Publisher work with sparse StructureDefinition differentials rather than requiring parent nodes or the root element in every differential. The Jira resolution was auto-approved, and the later Jira comment says this was an old tooling issue that should be raised in HL7/fhir-ig-publisher if still reproducible.

Initial application:
No FHIR core source commit explicitly mentions FHIR-14953. The underlying core specification rule had already been applied through FHIR-8971: commit b2cbcf3afa7ef4fd2dc92fb9da59eb8ed8894f1a added profiling prose that sparse differentials are allowed and the root element need not be present. A later concrete IG Publisher failure was tracked outside this repository in HL7/fhir-ig-publisher#111 and was closed after the reporter confirmed the issue appeared resolved.

Additional context:
Current source/profiling.html is in build scope through source/hierarchy.xml and states that a differential profile can be sparse, mention only changed elements, and omit the root element. The 2020 Zulip thread "Snapshot generation with sparse differentials" and GitHub issue #111 show the remaining problem was snapshot generation behavior in the IG Publisher tooling, not a missing core specification rule. Confluence searches found no distinct work-group minutes that change this conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR core source change. The current core source already says sparse differentials, including omitted roots, are valid; the requested behavior belongs to the external IG Publisher tooling repository and appears to have been resolved there.

Recommendation:
Keep this external-repo audit commit as-is. If sparse differential handling regresses, reproduce and fix it in HL7/fhir-ig-publisher rather than editing the core FHIR specification.
