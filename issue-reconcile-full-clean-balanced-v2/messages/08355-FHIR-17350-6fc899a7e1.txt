FHIR-17350: Audit ordinal value extension merge

Issue request:
FHIR-17350 was a Published/Persuasive with Modification FHIR-core STU3 change request. It asked to remove the separate questionnaire-ordinalValue, codesystem-ordinalValue, and valueset-ordinalValue extensions and replace them with a single ISO 21090 ordinal-value extension, updating that extension's allowed contexts.

Initial application:
The issue was applied by svn revision 14011, represented in git as e147f126d41be07ceef591c5bd38b58750b3dfbb with subject "GF#17350 - rationalise ordinal value extensions". That commit changed the ISO 21090, CodeSystem, ValueSet, Questionnaire notes, and scoring examples so the duplicate questionnaire/value-set/code-system ordinal extensions were replaced by a single ISO 21090 ordinal-value extension with expanded contexts.

Additional context:
The same change family continued immediately after STU3. FHIR-17824 deleted the ISO and Questionnaire-specific ordinal extensions and defined a general ordinalValue extension; that later issue is already represented on the combined branch by commit b6f584cb073411a17877f6a7f49b5f12a618b011. Later, FHIR-24672 renamed ordinalValue to itemWeight for R5, and FHIR-33540 moved CodeSystem and ValueSet weighting semantics to the defined concept property http://hl7.org/fhir/concept-properties#itemWeight. The active itemWeight extension and retired ordinalValue lineage now live in the FHIR Extension Pack, while current core source links to itemWeight and defines the concept property.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current core source has no active definitions or uses of questionnaire-ordinalValue, codesystem-ordinalValue, valueset-ordinalValue, or iso21090-CO-value. The current built model uses itemWeight guidance and the itemWeight concept property, and the extension-pack source preserves the deprecated ordinalValue lineage and active itemWeight definition. Reintroducing ISO 21090 wording or editing core extension definitions would contradict later published decisions and current repository ownership.

Recommendation:
Keep this audit commit as-is. No core-source follow-up is needed for FHIR-17350; future changes to the active itemWeight extension should be handled in the FHIR Extension Pack, and terminology weighting changes should account for the current CodeSystem concept property model.
