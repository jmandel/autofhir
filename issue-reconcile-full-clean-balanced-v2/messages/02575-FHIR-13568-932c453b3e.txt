FHIR-13568: Audit AuditEvent detail value string support

Issue request:
FHIR-13568 was a Published Security WG STU3 change request resolved Persuasive. It asked to change AuditEvent.entity.detail.value into a choice of string or base64Binary so schema-safe string values in AuditEvent entity detail key/value pairs would not need to be base64Binary encoded.

Initial application:
Git commit 84f8086d21fa applied Security WG update GF#13568 in the STU3-era AuditEvent spreadsheet source. The commit renamed AuditEvent.entity.detail.value to AuditEvent.entity.detail.value[x], changed its type from base64Binary to string|base64Binary, and updated the detail value wording. Later source conversion carried that applied choice into the current StructureDefinition source.

Additional context:
AuditEvent is active in source/fhir.ini. FHIR-32475 later broadened AuditEvent.entity.detail.value[x] beyond string/base64Binary to a set of computable datatypes while preserving both string and base64Binary. FHIR-13759 concerns the base64Binary encoding guidance for the same element and is already represented on the combined branch; it does not narrow or reverse FHIR-13568's string support. No relevant Zulip or Confluence evidence was found that conflicts with the Jira/source/history conclusion.

AutoFHIR reconciliation:
Made no source change. The current authoritative source already defines AuditEvent.entity.detail.value[x] and includes both string and base64Binary in its allowed types, so the FHIR-13568 requirement is satisfied in the current build while later datatype additions remain intact.

Recommendation:
Keep this empty audit commit as-is. No further FHIR-core change is needed for FHIR-13568; any separate review of the later FHIR-32475 datatype expansion should be handled under that issue, not by narrowing this element back to only string and base64Binary.
