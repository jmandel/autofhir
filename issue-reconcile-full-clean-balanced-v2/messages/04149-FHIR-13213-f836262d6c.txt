FHIR-13213: Audit PlanDefinition definition search

Issue request:
FHIR-13213 was a Published/Persuasive CDS work group change request for STU3 PlanDefinition. It asked for a `definition` search parameter so clients could retrieve a PlanDefinition together with referenced activities, with the requested path described as PlanDefinition.activity.definition.

Initial application:
The Jira comment says the issue was applied at SVN 12595. The mirrored git commit e3ffa748c7810e3168b59f09e11fa062bdb380b5 explicitly added the PlanDefinition `definition` reference search parameter, using the then-current PlanDefinition.action.definition path and the description "Activity or plan definitions used by plan definition."

Additional context:
PlanDefinition is active in the current build through source/fhir.ini. The current source has since moved from spreadsheets to source/plandefinition/bundle-PlanDefinition-search-params.xml, and the same `definition` search parameter is still present on PlanDefinition.action.definition[x]. Duplicate issue FHIR-13785 confirmed the same need for _include and reverse lookup on PlanDefinition.action.definition. Later FHIR-18186 expanded PlanDefinition.action.definition to canonical or uri; the current search expression covers both canonical and uri choices and does not reverse the FHIR-13213 decision. Zulip and Confluence searches found no conflicting community or work-group record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current PlanDefinition search-parameter source already contains `code="definition"`, type `reference`, and an expression over PlanDefinition.repeat(action).definition canonical and uri values.

Recommendation:
Keep this audit commit as-is. No follow-up core source work is needed for FHIR-13213 unless a future CDS decision changes how PlanDefinition action definitions should be searched or included.
