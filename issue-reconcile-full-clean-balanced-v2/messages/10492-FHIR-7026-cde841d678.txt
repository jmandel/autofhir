FHIR-7026: Audit server timezone discovery

Issue request:
FHIR-7026 was a Published, Persuasive with Modification FHIR-core search issue from the 2015 May ballot. It objected that clients could not know the server local timezone when date searches defaulted to that timezone and requested an implementation note about the server communicating its timezone.

Initial application:
The issue was applied by git-svn commit 4dba5ab8ce (#7026 - add note about server timezone), which added HTTP-page text saying that servers should return the default timezone for date searches in HTTP response headers using the Date header, while noting that servers are not required to have a default timezone.

Additional context:
Later timezone-search work in FHIR-17630 added client-timezone guidance for client context, and the current search page also tells clients to provide a timezone when a time part is present. Later FHIR-42971 determined that the HTTP Date-header approach violated HTTP semantics because HTTP Date is UTC/GMT, and resolved to remove the HTTP-page text and instead document server default timezone discovery via the timezone extension on CapabilityStatement.meta. FHIR-17630 and FHIR-42971 are already represented on the combined reconciliation branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The original Date-header implementation should not be restored, and the current build-scope source already preserves the seed issue's implementer-relevant outcome through CapabilityStatement timezone discovery, client-timezone HTTP guidance, and date-search guidance.

Recommendation:
Keep this audit commit as-is. If the work group wants a different server timezone discovery mechanism in the future, handle that as a new substantive change rather than reviving the invalid HTTP Date-header note from the original FHIR-7026 application.
