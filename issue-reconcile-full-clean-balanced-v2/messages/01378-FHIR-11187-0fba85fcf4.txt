FHIR-11187: Audit Immunization reporting source split

Issue request:
FHIR-11187 was a Published FHIR-core Immunization change request, resolved Not Persuasive with Modification. It requested replacing the DSTU2 Immunization.reported boolean with an informationSource-style element aligned with MedicationStatement, and the PHER decision retained a direct-administration indicator while adding a separate attribute for the source of non-directly administered immunization events.

Initial application:
No current git commit explicitly mentions FHIR-11187. The relevant historical application appears in the 2016 Immunization commit baf0c978b8, which replaced top-level Immunization.reported with Immunization.primarySource and added Immunization.reportOrigin plus an ImmunizationReportOrigin value set. A later 2019 Immunization refactor in 8386871f82 renamed/expanded reportOrigin to Immunization.informationSource[x] while preserving the secondary-report source concept.

Additional context:
The active current build includes Immunization in source/fhir.ini. Current source has Immunization.primarySource for whether the record originated with the administering individual/organization, and Immunization.informationSource bound to the immunization-origin value set for the source of reported data. Later Published core issue FHIR-37722 reaffirmed that informationSource captures the source of a reported immunization event while primarySource captures the source relationship to the event, and its applied commit 0f4d89973f clarified the primarySource definition now present in source.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped Immunization StructureDefinition no longer has the old top-level Immunization.reported element, retains the direct/primary-source boolean concept, and provides the separate informationSource element requested by the modified resolution.

Recommendation:
Keep this audit commit as-is. Further source edits would be redundant for FHIR-11187; any future reconsideration of whether primarySource remains useful should be handled under the later primarySource issue family rather than this DSTU2 reconciliation item.
