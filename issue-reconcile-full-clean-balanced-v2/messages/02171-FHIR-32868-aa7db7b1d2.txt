FHIR-32868: Audit terminology resource identifier metadata extension

Issue request:
FHIR-32868 was a Published/Persuasive R5 Vocabulary request to add a standard complex extension named terminology-resource-identifier-metadata for CodeSystem.identifier, ValueSet.identifier, and ConceptMap.identifier. The requested extension carries optional preferred, authoritative, and comment components so terminology resources can hold identifier metadata that otherwise appears in NamingSystem.uniqueId.

Initial application:
The issue was explicitly applied in core by git commit 2ee2898feed9035554ffea5c8efc3f45e6f2b176, which added source/codesystem/structuredefinition-extension-terminology-resource-identifier-metadata.xml and registered it from source/codesystem/implementationguide-CodeSystem-core.xml. That core extension source was later removed by dd468d4f1799dd79819315b211588ef1cf4586e0 as part of moving extension definitions out of the R5 core source.

Additional context:
The current core checkout no longer contains the extension StructureDefinition, but it still carries the canonical OID mapping in source/oids.ini. The current FHIR Extension Pack checkout contains input/definitions/multiple/StructureDefinition-terminology-resource-identifier-metadata.xml with the requested canonical URL, active status, CodeSystem/ValueSet/ConceptMap identifier contexts, and the preferred/authoritative/comment slices. Later FHIR-40728 reconsidered this same extension and was Resolved - No Change; the Jan 2024 TI WGM minutes say the group voted to keep the extension and rejected deprecation. FHIR-56093 is a newer FHIR-extensions deprecation request, but it remains Triaged/Unresolved and therefore does not authorize changing the current core reconciliation.

AutoFHIR reconciliation:
This audit commit makes no source change. Re-adding the extension to core would be wrong because current extension definitions are maintained in the FHIR Extension Pack, and the Extension Pack source already satisfies the FHIR-32868 request.

Recommendation:
Keep this no-change audit as-is for the core repository. Any future change to the extension, including the unresolved deprecation proposal in FHIR-56093, should be handled through the FHIR Extension Pack after a final work-group decision.
