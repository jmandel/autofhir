FHIR-7682: Audit DiagnosticReport key-image linkage

Issue request:
FHIR-7682 was a Published/Not Persuasive with Modification DSTU1 O&O request for DiagnosticReport to reference individual key images, asking to replace the ImagingStudy reference with ImagingObjectSelection. The final resolution pointed to FHIR-6246 and chose notes text instead of replacing ImagingStudy: ImagingStudy, ImagingObjectSelection/ImageObjectStudy, and the image element were overlapping alternatives, with use cases for all of them.

Initial application:
The seed appears to have been applied by commit 165f27cb02e9a41309bffb199dbf6aa7f36c54f2, which added the DiagnosticReport notes text about overlapping imaging references. The related FHIR-6246 implementation trail includes ae4866b512efb6620d418a4870b8d2c14ba9984a, which briefly added ImagingObjectSelection to the old DiagnosticReport.imagingStudy type, and 7da3e85d1128fc712018adcaa1883b9d9203cb3d, which later renamed that old target to ImagingManifest. Later source cleanup, including FHIR-33105, carried the note forward using the current media element name.

Additional context:
The old ImagingObjectSelection/ImagingManifest resources are no longer active build-scope resources, while DiagnosticReport, ImagingStudy, and ImagingSelection are active. Current DiagnosticReport.study remains Reference(ImagingStudy), DiagnosticReport.media.link remains Reference(DocumentReference), and the current notes still explain the overlap between ImagingStudy and media. ImagingSelection itself documents a diagnostic-report key-image use case via a relevant Observation or a Composition, but FHIR-57389 is an unresolved Waiting for Input issue asking whether baseline DiagnosticReport should directly relate to ImagingSelection and whether media, supportingInfo, or results would be the correct mechanism. The combined branch already contains 8a0804b8e1a43a3f97f2758560f7172e90cfc903 for FHIR-6246, so this commit does not decide that related issue again.

AutoFHIR reconciliation:
This commit intentionally makes no source change and records a human-review decision for the seed. The seed's non-replacement notes request is reflected by current DiagnosticReport ImagingStudy/media wording, but a current source edit that adds ImagingSelection directly to DiagnosticReport would require the unresolved work-group decision in FHIR-57389 rather than a mechanical replay of the retired ImagingObjectSelection request.

Recommendation:
Keep this audit commit as human-review. If the work group wants a direct DiagnosticReport-to-ImagingSelection relationship, resolve FHIR-57389 or a successor issue and implement the chosen mechanism there; do not infer media, supportingInfo, or results placement from the 2015 FHIR-7682 text alone.
