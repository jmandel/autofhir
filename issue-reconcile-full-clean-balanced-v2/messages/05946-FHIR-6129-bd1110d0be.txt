FHIR-6129: Audit Procedure code rename

Issue request:
FHIR-6129 was Published/Persuasive for DSTU1 Procedure. It clarified that the request was to rename the Procedure attribute rather than change the datatype, and the PC work group motion changed Procedure.name to Procedure.code with clarifying description, applying the same name change to ProcedureRequest.

Initial application:
The historical application was commit 77c0aa01f08d8517bcba177c89b296095491221d, whose message explicitly says "#6129 and #7123 - renaming type to code for procedure and procedure-request" and which updated Procedure, ProcedureRequest, examples, profiles, and the procedure-code value set. Current source no longer contains active Procedure.name, Procedure.type, ProcedureRequest.name, or ProcedureRequest.type elements.

Additional context:
FHIR-7123 is the same change family and first resolved the category-versus-type confusion as Procedure.name; FHIR-6129 then harmonized that intermediate name to Procedure.code. The current build has active Procedure and ServiceRequest entries in source/fhir.ini, while ProcedureRequest is recorded only as a retired resource merged into ServiceRequest. Current Procedure.code identifies the procedure and keeps "type" only as an alias; current ServiceRequest.code identifies the requested procedure/service. A previously published AutoFHIR commit for FHIR-7123 corrected the remaining active Procedure notes example from name=amputation to code=amputation. Zulip and Confluence searches found no relevant conflicting community record.

AutoFHIR reconciliation:
Made no source change. The active Procedure and ServiceRequest definitions already use code for the element requested by FHIR-6129, the retired ProcedureRequest artifact is outside the current build, and the related active notes drift was already fixed under FHIR-7123.

Recommendation:
Keep this empty audit commit as-is. No further core source work is needed for FHIR-6129 unless a future work group reopens the retired ProcedureRequest history or asks for broader editorial cleanup.
