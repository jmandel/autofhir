FHIR-20204: Audit PZN validator issue outside core spec

Issue request:
FHIR-20204 was a Published/Persuasive technical correction asking that the Java JAR validator stop reporting an invalid-code error for code systems such as http://fhir.de/CodeSystem/ifa/pzn whose CodeSystem resource intentionally has no explicit concept list.

Initial application:
No source commit in this HL7/fhir checkout explicitly references FHIR-20204, and current source contains no Java validator implementation to change. The Jira trail shows the issue was assigned for investigation and later published, with a final comment directing remaining validator problems to https://github.com/hapifhir/org.hl7.fhir.core.

Additional context:
The current core build includes CodeSystem as an active resource and already defines CodeSystem.content plus the not-present content mode, including the rule that none of the code system concepts are included in that resource. Zulip discussion confirms the original PZN report was a validator/terminology-server behavior problem, and a later HAPI/core-validator thread treats the remaining work as validator implementation/message handling rather than FHIR specification source.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The requested fix belongs to the Java validator implementation outside this FHIR specification checkout, not to the authoritative core spec files in this repository.

Recommendation:
Keep this audit commit as an external-repo decision. If PZN or other not-present code systems still produce incorrect validator errors, track and fix that in hapifhir/org.hl7.fhir.core or the relevant validator/plugin implementation, while preserving the current core CodeSystem.content semantics.
