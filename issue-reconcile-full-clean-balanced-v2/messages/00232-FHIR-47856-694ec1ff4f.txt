FHIR-47856: Clarify MedicationRequest reason for doNotPerform orders

Issue request:
FHIR-47856 was Applied as Persuasive with Modification for R6 Pharmacy work. It asked for a doNotPerformReason element because MedicationRequest.doNotPerform has clinical safety implications. The approved resolution rejected a new element and instead said MedicationRequest.reason should be clarified as the reason or indication for ordering the medication to be taken or not taken, while also updating MedicationRequest.doNotPerform and Scope and Usage text.

Initial application:
The March 2025 source commit f089233519978d8523787ad7f5ff2ae606f6621b applied the MedicationRequest.doNotPerform definition/short-display change and the Scope and Usage sentence in the active medicationrequest resource source. It did not make the specific MedicationRequest.reason definition clarification from the Jira resolution. The current branch also has the doNotPerform source text in place, but the reason definition was later rewritten by FHIR-51447 without retaining the explicit not-taken wording.

Additional context:
FHIR-51447 is a later Applied Pharmacy clarification for the same MedicationRequest.reason element. It distinguishes MedicationRequest.basedOn from MedicationRequest.reason and changed reason to describe requests issued because something occurred, such as a lab test or performed procedure. FHIR-51148 is another Applied later Pharmacy change that added AllergyIntolerance as a MedicationRequest.reason target specifically for doNotPerform allergy scenarios. These later decisions support keeping .reason as the place for doNotPerform rationale while preserving FHIR-51447's basedOn/reason distinction.

AutoFHIR reconciliation:
Updated the active source/medicationrequest/structuredefinition-MedicationRequest.xml definition source for MedicationRequest.reason. The short display and definition now state that the reason or indication can be for ordering the medication to be taken or not taken, while the definition keeps FHIR-51447's guidance that reason documents requests issued because of something that occurred. The edited file is in build scope because source/fhir.ini actively maps medicationrequest=MedicationRequest.

Recommendation:
Keep this source fix. It completes the missing FHIR-47856 reason clarification without adding a new element and without reversing the later FHIR-51447 clarification. Generated diagram artifacts can be refreshed by the normal build if desired.
