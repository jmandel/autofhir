FHIR-14214: Audit Measure care gaps support

Issue request:
FHIR-14214 was Published with a Persuasive with Modification resolution for STU3. It asked for support for running care-gap/measure-report evaluation for all applicable measures for a single patient, resolved as a type-level Measure $care-gaps operation taking patient, periodStart, periodEnd, and an optional topic selector, with a FHIR Document Bundle containing a Composition and MeasureReport entries.

Initial application:
The historical application was SVN 14063, preserved as git commit 1ce7bae0e8d4457eb17aa85c120f207893e9c1fb, whose message explicitly says "GF#14214: Added $care-gaps operation to Measure" and which added the original care-gaps request/response examples, Measure spreadsheet operation content, and MeasureReport cleanup.

Additional context:
The current build has Measure and MeasureReport active in source/fhir.ini, includes OperationDefinition/Measure-care-gaps in source/measure/list-Measure-operations.xml, and defines the operation in source/measure/operationdefinition-Measure-care-gaps.xml. Later CQI decisions deliberately evolved the operation: FHIR-50485 aligned the base R6 operation with DEQM STU5, and its Jira comment records that the topic parameter should be removed because selecting all measures for a topic should be a separate client step. FHIR-56069 then aligned examples with the current parameters.

AutoFHIR reconciliation:
This audit commit makes no source change. The current source already supports the core FHIR-14214 outcome: Measure/$care-gaps is a type-level operation that calculates gaps in care for one or more measures, accepts periodStart and periodEnd plus subject selection, returns zero or more document Bundles through an operations Parameters response, and the checked example Bundle contains a Composition referencing multiple MeasureReport entries for one Patient. Re-adding the original topic parameter would contradict the later applied R6 reconciliation.

Recommendation:
Keep this no-change audit as-is. Do not reintroduce topic in core unless CQI opens and applies a new tracker; clients that want topic-based measure selection should discover the measure set separately and pass one or more measureUrl values.
