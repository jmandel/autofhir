FHIR-5680: Audit W5 element order reconciliation

Issue request:
FHIR-5680 was a Published/Persuasive with Modification DSTU1 MnM request to make common resource element ordering consistent. The accepted resolution required completing W5 mappings, aligning resources to W5 order with W5-mapped elements first while allowing related elements to be intermixed, applying that immediately to FMM 3 resources, and making the W5 order consistent with conformance resources.

Initial application:
The historical source contains explicit #5680 commits: 102c1eb84e reordered ValueSet source/examples, and a60d10808 reordered Observation and related resource/example material while adding the w5.ini comment that its order is the correct order for resource designs and XML instances. A later 7524d34ddd W5 overhaul added workflow and conformance categories, matching the resolution's conformance-resource alignment. No prior AutoFHIR reconciliation commit for FHIR-5680 was present on the combined branch.

Additional context:
The current build-scope source still includes the FiveWs logical pattern in source/fhir.ini, publishes w5.html, and renders QA/W5 pages from source/qa.html and source/w5.html. source/w5.ini preserves the explicit ordering rule and maps each W5 key to the current FiveWs pattern. Later source refactors converted old spreadsheets to StructureDefinition XML and a 2025 W5 cleanup refreshed current FiveWs mappings without removing the ordering machinery. Jira searches found later specific resource-order issues in the same policy family, but deciding those would require separate resource-specific checks and is outside this seed audit.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current specification source already contains the authoritative W5/FiveWs ordering configuration and build-scope report hooks needed for the accepted FHIR-5680 resolution, and reordering arbitrary current resources as part of this audit would be speculative rather than a bounded correction.

Recommendation:
Keep this audit commit as-is. Treat future complaints about a specific resource's order as separate resource-level issues, because FHIR-5680 established the general W5 ordering policy and historical application path rather than a single remaining current-source defect.
