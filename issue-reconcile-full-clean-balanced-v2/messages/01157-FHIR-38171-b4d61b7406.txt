FHIR-38171: Audit CodeSystem filter comparison support

Issue request:
FHIR-38171 was a Published/Persuasive vocab change request for R5 asking how CodeSystem and ValueSet filters could support comparative matching for dateTime, integer, and decimal concept properties, including precision behavior. The accepted resolution followed Michael Lawley's proposal: do not add new filter operator codes to the normative ValueSet/operator model; instead use the existing "=" operator with FHIR search prefixes in the filter value for ordered property types.

Initial application:
The issue was applied by Grahame Grieve in git commit 6ba28a62fc02ab39d84279e575608931a602f0a7, which added the CodeSystem Filters table note and a "FHIR Search Semantics" section to source/codesystem/codesystem-notes.xml. Current source retains that guidance, including the lt2021-01-01 and eq2022 retiredDate examples. The filter-operator CodeSystem still intentionally contains the pre-existing operator codes and no gt/lt/ge/le operator codes.

Additional context:
The cited Zulip thread records the original concern, the prefix-on-value proposal, the pointer to the implementation commit after the issue was marked Applied, and a later concern that the ValueSet page should point back to CodeSystem filter details. That later concern became FHIR-40753 and was ultimately retracted/resolved no-change. Current source has since been refactored so ValueSet.compose.include.filter.value links to valueset.html#filter-values, and the ValueSet filter-values section says ordered CodeSystem property types may use search prefixes.

AutoFHIR reconciliation:
This commit makes no source change. source/fhir.ini lists CodeSystem and ValueSet as active resources, and the authoritative current source already carries the intended semantics in build-scope CodeSystem and ValueSet material. Adding new filter operators would contradict the accepted resolution, and duplicating more prose is unnecessary given the current ValueSet cross-reference and filter-values section.

Recommendation:
Keep this audit commit as-is. No specification follow-up is needed for FHIR-38171 unless the work group intentionally reopens the design to add real operator codes or change the prefix semantics.
