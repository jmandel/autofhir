Issue request:
FHIR-24917 was a Published/Persuasive FHIR-I technical correction for R5. It reported that R4 search parameters SubstanceSpecification-code and StructureDefinition-ext-context resolved to BackboneElement values and requested corrected expressions, with the Jira resolution saying to correct them to SubstanceDefinition.code.code and StructureDefinition.context.type.

Initial application:

The originating Zulip thread reached the same two candidate fixes and noted that SubstanceSpecification-code was already fixed in the latest build.

Additional context:
Current source has moved beyond the R4 technical-correction shape. SubstanceDefinition is the active resource and SubstanceDefinition-code uses SubstanceDefinition.code.code. StructureDefinition now has separate extension-context search parameters: ext-context-type uses StructureDefinition.context.type, while ext-context is a composite parameter over StructureDefinition.context with components for type and expression. R5 publication evidence matches this current composite/token split.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The current source preserves the FHIR-24917 correction for SubstanceDefinition-code and represents extension context using the later composite design plus explicit ext-context-type token parameter, so there is no remaining current-build BackboneElement token expression to fix.

Recommendation:
Keep this no-change audit. Do not force the current composite StructureDefinition-ext-context parameter back to the R4 token-only expression; use the current ext-context-type token parameter when searching by context type.
