FHIR-15903: Audit clinical-patient Patient scope

Issue request:
FHIR-15903 is a Published/Persuasive FHIR-I change request raised against STU3 and applied for STU3. It asked whether the shared clinical-patient/patient search parameter was incorrectly scoped to Patient plus Group on resources such as Procedure and Observation, while resource pages showed Patient-only expressions. The approved resolution was to make patient search parameters refer only to Patient across resources and to define subject search parameters for Patient-or-Group cases where needed.

Initial application:
The Jira application comment cites svn revision 14044, which is git commit a474a736634709cdfdfdd609f7979e9526607fbf. That commit added a resource-validation rule requiring a patient search parameter to target only Patient unless the underlying patient element is itself Patient-only. The current resource search parameter source also contains the later applied shape: Procedure-patient and Observation-patient use subject.where(resolve() is Patient) and declare target Patient, while Procedure-subject and Observation-subject remain the broader subject searches.

Additional context:
FHIR-13601 raised the same Patient-vs-Group target problem and is already represented on the combined branch by a no-change audit. Later final issues FHIR-28219, FHIR-31714, and FHIR-32876 refined the same change family: non-patient-named expressions should be Patient-filtered, and generated/downloaded clinical-patient.target should be Patient only. Those related issues are already represented on the combined branch, and the current build's search-parameters.json reports SearchParameter/clinical-patient target ["Patient"]. Direct Confluence searches for FHIR-15903 and FHIR-13601 found no additional references; relevant Zulip threads consistently say patient search parameters should point only to Patient and subject should cover Patient or Group.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Procedure, Observation, and SearchParameter are active current-build inputs in source/fhir.ini; the active Procedure and Observation patient search parameters are Patient-scoped; their subject search parameters remain available for broader subject searches; the common clinical-patient source block does not assert a Group target; and a full source scan found no patient-code SearchParameter block with an explicit non-Patient target.

Recommendation:
Keep this no-change audit. The current core source and generated publication surface satisfy the published FHIR-15903 decision, and the tightly related target-generation follow-ups are already audited on the combined branch. Future work is only needed if a build regression again expands clinical-patient.target beyond Patient or a newly added patient search parameter explicitly targets a non-Patient resource.
