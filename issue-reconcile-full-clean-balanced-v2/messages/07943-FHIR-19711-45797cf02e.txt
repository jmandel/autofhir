FHIR-19711: Audit document bundle reference wording

Issue request:
FHIR-19711 was a Published FHIR-core STU3 change request, resolved Persuasive, asking the Documents page to stop saying that any resource referenced directly in Composition SHALL be included in a document bundle. The reporter noted that this broad wording appeared to include Composition.relatesTo and conflicted with the explicit generated list; the approved replacement was "Resources referenced by the Composition as listed below SHALL be included in the bundle when the document is assembled." Lloyd's follow-up comment intentionally omitted the proposed extension sentence because the preceding context already made it clear enough.

Initial application:
The issue was applied by git commit 84b04d276f (GF#19711), which replaced the broad "Any resource referenced directly" sentence in source/documents.html with the approved listed-reference sentence. Current source/documents.html still carries that applied wording immediately before the Composition reference-list include.

Additional context:
source/hierarchy.xml includes documents.html in the active build hierarchy, so source/documents.html is the authoritative source page for this guidance. The current built page expands the Composition reference list to Composition.consent, basedOn, subject, encounter, author, participant.party, attester.party, custodian, section.author, section.focus, and section.entry, and does not list Composition.relatesTo. Later related work changed nearby document-bundle guidance without reversing FHIR-19711: FHIR-15723 strengthened secondary-resource inclusion from optional prose to SHOULD guidance, FHIR-27891 moved duplicated Composition-page bundle guidance to the Documents page, and FHIR-43295 clarified that graph-linkage requirements use Reference.reference, canonical, or URI. A direct Zulip and Confluence search found no FHIR-19711-specific conflicting community record; a related 2019 Zulip thread on mandatory document references is consistent with the current source.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active Documents source already contains the FHIR-19711 replacement sentence, and external verification of the current built page confirms that the generated list avoids the original relatesTo ambiguity.

Recommendation:
Keep this audit commit as-is. If the work group later wants Composition.relatesTo targets to be mandatory document-bundle contents, that should be handled as a new substantive decision because the current approved source and generated list deliberately do not say that.
