FHIR-2986: Audit modifier-extension guidance link

Issue request:
FHIR-2986 was a Published/Persuasive FHIR-core change request for the conformance rules Is-modifier section. It asked for clearer extension-specific guidance: the isModifier flag is set where an extension is defined, resources containing a modifier extension use the modifierExtension element name, and the conformance page should link explicitly to extensibility.html#modifierExtension.

Initial application:
The Jira comments say the issue was done in SVN revision 3008. Git history preserves that application as commit 86354dfb2a721cbd789d0a2f7a0b64fc0e1926c7, "Task 2986: Clarifications related to modifier extensions", with git-svn-id build@3008. That commit added the conformance-rules paragraph explaining extension isModifier flags, modifierExtension representation, and the link to the modifier-extension rules.

Additional context:
The current build source still contains the requested guidance in source/conformance-rules.html and the linked source/extensibility.html section now contains detailed modifier-extension rules and an XML/JSON example. Later FHIR-I work such as FHIR-16188 clarified the broader isModifier definition and modifier-extension impacts, but did not remove or supersede the FHIR-2986 extension guidance. Searches for FHIR-2986 in Zulip and Confluence found no later conflicting community decision.

AutoFHIR reconciliation:
No source change is needed. The active conformance source already states that extension definitions set isModifier, that modifier extensions are represented with modifierExtension rather than extension, and links to the modifier-extension handling rules.

Recommendation:
Keep this audit commit as-is. Revisit only if a future work-group decision changes the current modifier-extension model or moves the authoritative conformance/extensibility pages out of the core build.
