FHIR-26685: Audit medicinal product status resolution

Issue request:
FHIR-26685 was a Published/Persuasive with Modification BR&R R5 issue asking the work group to resolve ambiguity around product.status: which codes to use and whether status represented the medicinal product, the product record, marketing approval, marketing availability, or another lifecycle concept. The recorded resolution says significant status changes were made for R4B and implementer experience was now needed, so the issue could be closed.

Initial application:
No source commit in this checkout directly mentions FHIR-26685. The relevant status work appears in the same medication-definition status history instead: FHIR-26658 added packaged-product status/statusDate support in April 2020, and later R4B/R5 BR&R status decisions such as FHIR-31780 and FHIR-31790 moved medication-definition status fields toward the draft/active/retired/unknown PublicationStatus pattern. Current source retains the resolved model rather than a separate application commit for this umbrella discussion issue.

Additional context:
source/fhir.ini lists MedicinalProductDefinition, PackagedProductDefinition, RegulatedAuthorization, and the other medication-definition resources as active current-build resources. MedicinalProductDefinition.status now explicitly means "The status of this product record" and tracks the lifecycle of the content, while RegulatedAuthorization.status separately represents the authorised/marketing authorization status and maps to Marketing Authorization.Authorization Status. PackagedProductDefinition.status has the parallel record-lifecycle pattern. A later published issue, FHIR-31790, further tightened MedicinalProductDefinition and PackagedProductDefinition status to required code values bound to PublicationStatus; that related decision is already represented on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build already expresses the resolved separation: product and pack status are record/content lifecycle status values using the common PublicationStatus codes, while marketing authorization status is modeled separately on RegulatedAuthorization. Adding more local prose for FHIR-26685 would be redundant and could drift from the authoritative element definitions and later FHIR-31790 resolution.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for FHIR-26685 unless BR&R opens a new issue based on implementer experience that changes the lifecycle/marketing-status model.
