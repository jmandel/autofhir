FHIR-48379: Audit FHIRPath cardinality warning

Issue request:
FHIR-48379 was an Applied/Persuasive FHIR-I R6 clarification asking the spec to warn that changing an element maximum cardinality from 1 to * can also break FHIRPath expressions, not only JSON paths. The approved resolution requested two updates on the version-management page, a dragons warning on the FHIRPath page, and an editor check of current invariant/SearchParameter FHIRPath expressions.

Initial application:
The source already contains the requested application. Brian Postlethwaite's 2025-10-22 commits 8a7bd856e19a1d222c350a911db3c04ecedd73f7 and cfbe4bd6c9435ec8643117cf43176e83a8a9b378, linked from the Jira comment through HL7/fhir#3797, added the FHIRPath dragons warning to source/fhirpath.html and changed the source/versions.html cardinality guidance from JSON-only wording to JSON-and-FHIRPath wording.

Additional context:
FHIR-I WGM minutes page 281219681 records the same 26-0-0 persuasive vote and notes that cardinality changes may also break FHIRPath. FHIR-47629 is the same change family because it introduced the previous JSON-only cardinality warning that FHIR-48379 extended; FHIR-47643 was checked because the Jira description mentions it, but it concerns a different versions-page draft-resource reference rule and did not change this decision. No directly relevant Zulip thread or conflicting community evidence was found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build source pages already contain the two versions-page edits and the FHIRPath dragons warning with the intended semantics, and no specific current invariant or SearchParameter source defect was identified from the issue evidence.

Recommendation:
Keep this audit commit as-is. Any future broad audit of every invariant and SearchParameter FHIRPath for maximum-cardinality safety should be treated as a separate human/tooling review task, not as a missing source edit for this already-applied documentation issue.
