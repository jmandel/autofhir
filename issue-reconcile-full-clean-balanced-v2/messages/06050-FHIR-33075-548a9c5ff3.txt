FHIR-33075: Audit ServiceRequest.code datatype alignment

Issue request:
FHIR-33075 was a Published, Persuasive with Modification OO change request for R5. It raised concern that ServiceRequest.orderDetail was taking on part of the requested "what" and asked to align ServiceRequest.code with orderDetail. The final approved resolution was narrower than the original proposed ServiceRequest.service backbone: change ServiceRequest.code from CodeableConcept to CodeableReference(ActivityDefinition | PlanDefinition).

Initial application:
The Jira application comment points to PR #2084 commit 5cfdb8d5b528ac164f1220d31425716f0bcb8db9. The underlying source-changing history includes b452b8ce425c090acd054dbcd888e61d4fc6ea83, which changed source/servicerequest/structuredefinition-ServiceRequest.xml so ServiceRequest.code is a CodeableReference targeting ActivityDefinition and PlanDefinition and updated ServiceRequest examples to wrap code values in CodeableReference.concept.

Additional context:
ServiceRequest is active in source/fhir.ini, so the ServiceRequest XML and search-parameter bundle are in current build scope. FHIR-31584 supplied the earlier orderDetail backbone context, but FHIR-33075's OO discussion narrowed this issue to the code datatype. The 2022-08-08 OO HCP minutes state that OO on FHIR agreed to only change the datatype to CodeableReference allowing ActivityDefinition and PlanDefinition, with any 0..1 to 1..1 cardinality change to be handled in a separate Jira. Later FHIR-47249 clarified the PlanDefinition use case for the same ServiceRequest.code element and is already represented on the combined branch; it did not reverse the FHIR-33075 datatype decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative ServiceRequest source already has ServiceRequest.code as CodeableReference with target profiles ActivityDefinition and PlanDefinition, retains orderDetail as the FHIR-31584 backbone structure, and exposes the split code-concept/code-reference search parameters expected for the CodeableReference datatype.

Recommendation:
Keep this audit commit as-is. A source edit for FHIR-33075 would either duplicate already-applied source history or broaden the issue beyond the approved datatype-only disposition.
