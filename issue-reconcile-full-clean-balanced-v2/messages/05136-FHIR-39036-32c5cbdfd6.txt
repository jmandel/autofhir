FHIR-39036: Audit subscription error documentation

Issue request:
FHIR-39036 was a Published/Persuasive R5 correction for the Subscription artifact. It reported that the subscription error-handling prose still named the removed Subscription.error element and asked that those references instead point to SubscriptionStatus.error, with the client-add-errors sentence removed because clients do not write SubscriptionStatus.error.

Initial application:
The issue was applied before this reconciliation by commit fc98efc7de862cf3ac1b1b9d59a8e3f00d727094, which replaced the stale Subscription.error paragraph in source/subscriptions.html with wording that communicates errors via SubscriptionStatus.error, mentions notification and $status-operation exposure, and drops the client-add-errors warning. The current source no longer defines Subscription.error; SubscriptionStatus.error is present in source/subscriptionstatus/structuredefinition-SubscriptionStatus.xml.

Additional context:
The modeling background is FHIR-27129, which moved Subscription.error to SubscriptionStatus.error. source/fhir.ini actively includes subscription, subscriptionstatus, and subscriptiontopic resources in the build, while its only remaining Subscription.error text is in the [r4-r6-changes] migration metadata, not current normative subscription prose or resource definition. FHIR-I WGM minutes for January 2023 record the FHIR-39036 disposition as "will update documentation" with an 11-0-0 vote. No Zulip or Confluence search found a later conflicting decision for FHIR-39036.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The build-scoped current subscriptions narrative already references SubscriptionStatus.error and no longer tells servers that clients cannot add errors to a nonexistent Subscription.error element.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for core FHIR unless a future work group decision changes where subscription error details are carried.
