FHIR-18412: Audit Resource id definition wording

Issue request:
FHIR-18412 was Published/Persuasive for STU3. It asked to stop describing the id used for inter-element references as "xml:id (or equivalent in JSON)" because Resource.id is not XML-id-like in all contexts such as Bundle, and because JSON should not be called out separately. The approved resolution was to reword as suggested: "unique id for inter-element referencing".

Initial application:
The Jira comment records GH#9e2f772483. Commit 9e2f772483e7c3922552320b662383b1498a016c, titled "GF#18412", changed source/datatypes/element.xml from "xml:id (or equivalent in JSON)" to "Unique id for inter-element referencing" and made the matching generated source/element.html update. No later Jira-tagged commit for this issue was found.

Additional context:
The current build no longer has source/element.html checked in as source, but source/fhir.ini still actively lists Element under [infrastructure], so source/datatypes/element.xml remains the source-driving artifact for Element.id. Current source/datatypes/element.xml still contains the approved Element.id wording, while current source/resource/structuredefinition-Resource.xml separately defines Resource.id as the logical id used in the resource URL. Searches for FHIR-18412 in Zulip and Confluence found no directly relevant or conflicting community record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The approved wording is already present in the active Element source, the old rejected phrase is absent from the relevant source, and the separate Resource.id definition does not recreate the XML/JSON wording problem.

Recommendation:
Keep this no-change audit commit as-is. No FHIR core source follow-up is needed for FHIR-18412 unless a future work group decision reopens Element.id or Resource.id wording.
