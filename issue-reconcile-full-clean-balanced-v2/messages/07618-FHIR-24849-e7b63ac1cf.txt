FHIR-24849: Audit Group characteristic combination handling

Issue request:
FHIR-24849 was a Published FHIR-core Group change request with a Persuasive with Modification resolution. It asked for a new Group.characteristicCombination code element to distinguish intersection/AND from union/OR behavior for multiple Group.characteristic entries. The accepted modification did not add that element; it recorded that OR can be modeled by sub-groups and that a standard characteristicExpression extension would support more sophisticated FHIRPath or CQL criteria when Group.characteristic is omitted.

Initial application:
The explicit source application was commit ac71406c7854b22379672089a4c8883e19268714, which added a characteristicExpression general extension row for Group rather than adding Group.characteristicCombination. The extension was later removed from core with the broader R5 extension migration in dd468d4f1799dd79819315b211588ef1cf4586e0 and now exists in the FHIR Extension Pack. No source history shows that the requested element name characteristicCombination was meant to remain in current core Group.

Additional context:
Group is active in the current core build. Current Group source contains Group.combinationMethod and Group.combinationThreshold, with required binding to group-characteristic-combination and all-of/any-of semantics that directly cover the original AND/OR use case for structured characteristics. Later FHIR-41583 Group work added that current conceptual cohort-definition model. The original characteristicExpression mechanism is present in the Extension Pack as a Group-scoped extension and remains exclusive with Group.characteristic. Zulip and Confluence searches found no conflicting community evidence; Confluence FHIR-I minutes for 2020-03-23 confirm the original decision rationale and vote.

AutoFHIR reconciliation:
This audit commit intentionally makes no source changes. Adding the obsolete requested Group.characteristicCombination element, duplicating the Extension Pack extension in core, or adding redundant prose would conflict with the accepted modification and the later current Group model.

Recommendation:
Keep this no-change audit commit as-is for core FHIR. If future work is needed on characteristicExpression itself, perform it in the FHIR Extension Pack rather than reintroducing the extension definition into core.
