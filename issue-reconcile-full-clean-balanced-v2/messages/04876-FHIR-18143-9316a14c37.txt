FHIR-18143: Audit ValueSet exclude expansion rule

Issue request:
FHIR-18143 was a Published vocab Change Request for the STU3 ValueSet artifact. It said ValueSet.compose.exclude handling in expansion was unclear and asked that all include operations and referenced value set unions be completed before codes identified by exclude are removed. The final Persuasive with Modification resolution points to the identical Carmela tracker and says to use clarifying language that makes the required outcome clear without fixing an implementation order.

Initial application:
The FHIR-18143 Jira comment identifies git 66ae1e40f1bc02283363c872db14035fc795f8f7, which updated ValueSet composition/expansion documentation and other terminology ballot material. The directly identical tracker is FHIR-18665; its Jira-commented git 4907f9bcb0b710cb2837a93a20c4b23210a37249 added the resolved sentence that any compose.exclude SHALL be processed such that excluded codes are not found in the expansion. Later git 054eabf3116825c0f65107fedff6668447bf43a1 retained and sharpened the expansion algorithm so exclude follows the include process but removes codes from the expansion instead of adding them.

Additional context:
ValueSet is an active current resource in source/fhir.ini, so source/valueset/valueset-notes.xml is build-scope source. The current source still contains both the outcome rule in Composition Rules and the expansion algorithm guidance that removes codes for compose.exclude. FHIR-18665 is already represented on the combined branch by audit commit a88b4456a6fe123347600f597b6ec37fa281c613, so this commit does not duplicate it. Later FHIR-54122 is only Triaged/Unresolved and proposes removing the outcome rule; it is background only and is not a final decision for this reconciliation.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source change is needed because the current specification already conveys the approved FHIR-18143 outcome: excluded codes must not be present in the expansion. Adding a literal include-before-exclude process-order sentence would be less correct because the accepted resolution deliberately avoided prescribing implementation order when an implementation can produce the same result another way.

Recommendation:
Keep this audit commit as-is. No FHIR-18143 source follow-up is needed unless a future final Vocab decision, such as a resolved successor to FHIR-54122, changes ValueSet compose.exclude semantics.
