FHIR-5370: Audit documentation index section numbering

Issue request:
FHIR-5370 was a Published/Persuasive DSTU1 ballot correction asking to fix the Documentation Index path where clicking the BackboneElement link under the old "Infrastructure Types" section produced section headings prefixed with "??" such as "?.?.1 Content". The final resolution said the content was not registered in the hierarchy and the broken index should be fixed.

Initial application:
No source commit explicitly tagged FHIR-5370 was found. The Jira comments from Grahame Grieve say this had already been done for another task. Git history shows the old Documentation Index "Infrastructure Types" block and standalone backboneelement.html link existed in 2014 and was removed by a later documentation layout refactor, while current source registers the Documentation Index and Type Framework pages in source/hierarchy.xml.

Additional context:
The current Documentation Index no longer has an "Infrastructure Types" section or BackboneElement link. BackboneElement now lives as an anchor on types.html, and source/hierarchy.xml registers types.html under Foundation > Documentation Index > Type Framework. Current build output shows the BackboneElement heading on types.html has a concrete generated section number rather than the old unknown "??" prefix. Jira, Zulip, and Confluence searches found no later or conflicting decision for this narrow documentation-index issue.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source and current build already avoid the broken path and provide proper generated section numbering for BackboneElement, so adding or editing current documentation would be redundant and risk reintroducing stale navigation.

Recommendation:
Keep this audit commit as-is. No follow-up is needed in core unless a future build regresses section-number generation for types.html anchors.
