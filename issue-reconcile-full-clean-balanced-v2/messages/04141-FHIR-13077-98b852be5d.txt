FHIR-13077: Audit FamilyMemberHistory dataAbsentReason application

Issue request:
FHIR-13077 was Published with a Persuasive with Modification resolution for DSTU2 Patient Care FamilyMemberHistory. It requested removing FamilyMemberHistory.notDone because a truly not-done family member history should not have an FMH instance, using status=health-unknown when information is unavailable or unknown, and renaming FamilyMemberHistory.notDoneReason to dataAbsentReason while keeping the value set/binding and defining it as the reason the family member's history is not available.

Initial application:
The change was applied in the historical source by 25735dcc63a312d77a995ab0d2d8d0ab2ed7f835, which removed notDone from the example, disabled the notDone row in the old spreadsheet source, renamed notDoneReason to dataAbsentReason, renamed the absent-reason binding/value set source, and updated the definition. The follow-up 6fea2d703b63c8cce46240dbf2ff35efdb4e223f assigned OIDs for the renamed history-absent-reason value set and code system.

Additional context:
FamilyMemberHistory is an active current-build resource in source/fhir.ini. The current authoritative StructureDefinition source has FamilyMemberHistory.status including health-unknown and has FamilyMemberHistory.dataAbsentReason as a 0..1 CodeableConcept with the definition and example binding expected from the issue. No FamilyMemberHistory.notDone or FamilyMemberHistory.notDoneReason remains in the current resource source. Later FHIR-55325 confirms that health-unknown remains the intended status escape valve and the current notes also mention dataAbsentReason for why a family member's history is unavailable.
