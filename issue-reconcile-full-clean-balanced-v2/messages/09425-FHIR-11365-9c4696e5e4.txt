FHIR-11365: Audit SNOMED route display sourcing

Issue request:
FHIR-11365 was a Published/Persuasive FHIR-core clarification for DSTU2 medication route-code artifacts. It reported that the route-codes value set expansion displayed some SNOMED CT concepts with the "(qualifier value)" semantic tag and others without it, and asked why the build process chose inconsistent displays.

Initial application:
The Jira comments record svn revision 11563. In the migrated git history, commit b6754c234cfadd320aea6259f0e6732f8b49c5d4 is the matching build@11563 commit, titled "update snomed ct content in cache"; it refreshed source/snomed/snomed.xml and many vscache entries rather than changing the route ValueSet definition itself. That historical embedded SNOMED cache source is no longer present in the current build-source tree.

Additional context:
The current build-scope medication resources are active in source/fhir.ini, with MedicationPrescription now represented by MedicationRequest. Their route bindings resolve to the shared http://hl7.org/fhir/ValueSet/route-codes value set, whose current authoritative source is an intensional SNOMED CT include under source/datatypes/valueset-route-codes.xml. Later issue FHIR-42606 changed that source from is-a to descendent-of 284009009 so the generic route-of-administration concept is no longer included; this confirms the current route-code semantics are maintained in the datatypes ValueSet source. The current build page expands the value set from tx.fhir.org using SNOMED CT International 01-Feb-2025 and shows terminology-supplied display/designation data rather than checked-in FHIR display rows. No relevant Zulip or Confluence discussion for FHIR-11365 was found.

AutoFHIR reconciliation:
No source change was made. The current source has no hard-coded route-code display list to normalize, Coding.display is defined as a representation following the code system's rules, and the current route-code expansion is terminology-server-derived. Adding or editing FHIR source solely to force all SNOMED displays to include "(qualifier value)" would override current terminology behavior without a current work-group decision.

Recommendation:
Keep this empty audit commit as-is. No core FHIR source follow-up is needed for FHIR-11365 unless the responsible work group makes a new decision to constrain SNOMED display/designation selection in generated expansions.
