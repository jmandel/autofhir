FHIR-25230: Audit MedicationKnowledge patientCharacteristic model

Issue request:
FHIR-25230 was a Published/Persuasive Pharmacy change request for R5. It asked to fix MedicationKnowledge AdministrationGuideline.patientCharacteristic so it could represent a characteristic name/value pair rather than the unusable R4 shape.

Initial application:
The request was applied in git commit 48438a7205421769bebb35c255e22d24aaa57251, which changed the MedicationKnowledge spreadsheet from patientCharacteristic.characteristic[x] plus repeatable value to patientCharacteristic.type plus patientCharacteristic.value[x]. The source was later migrated into structuredefinition-MedicationKnowledge.xml, preserving the type/value split.

Additional context:
MedicationKnowledge is active in source/fhir.ini. Later R5 Pharmacy work renamed the original AdministrationGuideline path into MedicationKnowledge.indicationGuideline.dosingGuideline.patientCharacteristic, and FHIR-30089 explicitly kept patientCharacteristic.value[x] at 0..1 while broadening its value choices to Quantity and Range and adding repeated-characteristic interpretation guidance. FHIR-24831 explains the pediatric-use use case that prompted FHIR-25230, but does not require a different current shape.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active StructureDefinition already has patientCharacteristic as a repeating BackboneElement with required type 1..1 CodeableConcept and optional value[x] 0..1 CodeableConcept, Quantity, or Range. The obsolete MedicationKnowledge.administrationGuideline.patientCharacteristic.characteristic[x] path is absent from current source, and making value[x] mandatory would conflict with the later accepted FHIR-30089 cardinality.

Recommendation:
Keep this audit commit as-is. No core FHIR source follow-up is needed for FHIR-25230 unless Pharmacy makes a new decision to change the later patientCharacteristic cardinality or semantics.
