FHIR-18083: Audit preauthorization effective period elements

Issue request:
FHIR-18083 was a Published/Persuasive FM change request for STU3 asking to add an element for preauthorization responses to carry an effective, in-effect period at the root level in addition to per-item periods, with ClaimResponse and ExplanationOfBenefit identified as related artifacts.

Initial application:
The explicit historical application is commit afb5ec66f68641293bb7950b6e0eeb118fa1444a, whose message lists FHIR-18083 and whose spreadsheet change added ClaimResponse.preAuthPeriod. ExplanationOfBenefit already carries a root preauthorization period element in the current source as ExplanationOfBenefit.preAuthRefPeriod, which matches the in-effect period semantics even though the element name differs from ClaimResponse.preAuthPeriod.

Additional context:
ClaimResponse and ExplanationOfBenefit are active current-build resources in source/fhir.ini. Later Published issues FHIR-22662 and FHIR-40082 added item-level reviewOutcome.preAuthRef/preAuthPeriod structures for ClaimResponse and ExplanationOfBenefit, preserving the root-level period elements and clarifying the distinction between whole-authorization and item-level authorization periods. FHIR-32762 records that the FHIR-22662 item-level periods addressed later item-date needs. Zulip discussion in 2018 confirms ClaimResponse.preAuthPeriod was present in the then-current R4 build as the validity period for the preauthorization; a 2026 Da Vinci PAS thread confirms the top-level period applies to the entire claim/prior authorization while item-level periods apply only to the item.

AutoFHIR reconciliation:
No source files were changed. Current active source already has ClaimResponse.preAuthPeriod as a root Period element and ExplanationOfBenefit.preAuthRefPeriod as a root Period element, and later item-level additions are present via reviewOutcome.preAuthPeriod and content references for detail/addItem levels. Adding or renaming source for FHIR-18083 would duplicate or disturb already-applied semantics.

Recommendation:
Keep this empty audit commit as-is. No FHIR core follow-up is needed for FHIR-18083 unless the FM work group separately decides to harmonize the historical ExplanationOfBenefit.preAuthRefPeriod name/cardinality with ClaimResponse, which would be a distinct later decision rather than this seed issue.
