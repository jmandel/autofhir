FHIR-45617: Audit vital signs semantic guidance

Issue request:
FHIR-45617 was an Applied/Not Persuasive with Modification OO change request for R6. It argued that vital-sign-specific LOINC identifiers in Observation.code created semantic ambiguity when a more detailed measurement code was also needed, proposed moving those grouping identifiers into Observation.category, and was resolved by rejecting that breaking category move while adding guidance that the mandated standard code can and ought to be accompanied by a more detailed coding when available, plus preferred bindings to broader LOINC code sets.

Initial application:
The Jira records applied git 66a80b5fef2c43d4a46709f2a03b6d933063cb08. That commit moved the Vital Signs "interoperability standard" LOINC codes back from Observation.category to Observation.code, updated the vital signs introduction guidance, removed the temporary observation-vitalsign-category value set source, and updated examples/profile differentials in source/observation.

Additional context:
The affected source is in the current build scope: source/fhir.ini lists Observation as an active resource, source/observation/list-Observation-packs.xml includes ImplementationGuide/Observation-vitalsigns, and that implementation guide is marked core and references the vital-sign profiles. Related applied issues on the combined branch already audit or fix the same category-vs-code family, including FHIR-49953, FHIR-50689, and FHIR-50705. Community searches found Orders and Observations WG Zulip/Confluence discussion of the same category/code debate and no conflicting final decision that would require a new source edit.

AutoFHIR reconciliation:
This commit intentionally makes no source changes. Current source already implements the FHIR-45617 resolution: the vital signs introduction says the standard code may be accompanied by a more detailed code.coding, the base Vital Signs profile binds Observation.code to observation-vitalsign-measurement with preferred strength, each specific vital-sign profile patterns the standard LOINC code in Observation.code and has a preferred binding to its broader observation-vitalsign-* value set, and searches found no remaining source-backed observation-vitalsign-category or magic/category-code remnants needing correction.

Recommendation:
Keep this no-change audit commit as-is. Do not move the profile-specific vital-sign identifiers into Observation.category unless a future work-group decision reopens the breaking-change tradeoff; any additional cross-paradigm or IG-specific vital-sign information model work should be handled in those separate repositories or trackers.
