FHIR-7551: Audit current-list retrieval guidance

Issue request:
FHIR-7551 was a Published FHIR-core search issue from DSTU1, resolved Persuasive with Modification, asking the specification to document how a client can retrieve a patient's current medication, problem, allergy, and similar lists. The implementing comment directed the editor to document the _list parameter and proposed List ids plus functional-list literals such as $current-problems, $current-allergies, and $current-medications.

Initial application:
The Jira comments record svn revision 5536, and the corresponding git-svn commit fd0c054ffc746285deaa92e2219cf17ab9ed8ea2 changed source/lifecycle.html and source/search.html with the subject "#7551 - candidate solution for current X lists + fix search parameter xpath evaluation". The current source still contains the _list search parameter, current-list examples, and List-resource notes about querying List instances, raw resources, or Current resource lists, but the detailed lifecycle section that originally defined current lists has since been removed.

Additional context:
Later current-list decisions and history constrain how this old DSTU1 issue should be interpreted now. FHIR-11271, already represented on the combined branch, was Published/Not Persuasive and reaffirmed that current-list membership is clinical/business-rule curation rather than something generally derivable from resource status alone. FHIR-47135 reached a later No Change decision with the same rationale, while FHIR-47134 requested additional expected-status guidance but remains Resolved - change required and is outside this run's Applied/Published source-edit scope. A 2025 R6 source commit, 270e0ceb7b029dad4ca0fc5ccf5296ff370888cd, removed the detailed Current Resource Lists lifecycle text due to lack of implementation experience and pointed possible future work to the API Incubator. FHIR-39342 and related search-page reconciliations already handle the current _list/linking surface separately.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding the old FHIR-7551 lifecycle guidance would conflict with the later R6 removal, while removing or redesigning the remaining _list functional-list references would be a broader current-list policy cleanup that needs a separate applied issue or human/work-group review. The historical FHIR-7551 application is accounted for, and the current source state should not be changed under this seed alone.

Recommendation:
Keep this audit commit as-is for FHIR-7551. If FHIR-I wants to fully retire, relocate, or reintroduce current-list mechanics after the R6 lifecycle-page removal, handle that through a current issue or API Incubator follow-up rather than by reopening the original DSTU1 current-list application.
