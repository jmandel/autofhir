FHIR-20767: Audit QuestionnaireResponse stopped status

Issue request:
FHIR-20767 was a Published FHIR-core change request for QuestionnaireResponseStatus asking to add terminal "incomplete" and "expired" codes. The final Not Persuasive with Modification resolution instead required changing the existing "stopped" definition to make it terminal: "No subsequent changes can be made," and rejected a no-answer expired QuestionnaireResponse use case.

Initial application:
The issue appears to have been applied by git commit 62958938b9c71812294149adf3dbb678e8ac2b00, which changed source/questionnaireresponse/codesystem-questionnaire-answers-status.xml so the stopped code definition ends with "No subsequent changes can be made." The Jira snapshot also records that commit SHA in a 2021 comment.

Additional context:
QuestionnaireResponse is active in source/fhir.ini, so the questionnaireresponse source folder is in current build scope. The current QuestionnaireResponse.status element remains required-bound to ValueSet/questionnaire-answers-status, the ValueSet includes the complete questionnaire-answers-status CodeSystem, and the current CodeSystem has no separate incomplete or expired codes. That matches the published resolution. FHIR-12315 is background for the original stopped status, but it does not require a separate reconciliation decision here. Jira/Zulip/Confluence searches found no later or conflicting decision for adding expired/incomplete status codes.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change because the authoritative current CodeSystem already carries the terminal stopped definition required by FHIR-20767, and the current absence of separate incomplete/expired codes is consistent with the final resolution.

Recommendation:
Keep this no-change audit commit as-is. Revisit only if the work group opens a new issue to introduce distinct expired or incomplete statuses; FHIR-20767 itself is already correctly reflected in the active source.
