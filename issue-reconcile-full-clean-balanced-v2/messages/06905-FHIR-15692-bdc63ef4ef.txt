FHIR-15692: Audit ServiceRequest directedBy extension location

Issue request:
FHIR-15692 was a Published/Persuasive with Modification Orders and Observations change request for the STU3 ServiceRequest artifact. It asked for a 0..1 way to indicate whether an LTSS service was self-directed; the accepted resolution was not a new core element but to add ServiceRequest context to the existing http://hl7.org/fhir/StructureDefinition/procedure-directedBy extension and clarify that the directed actor is distinct from the requester.

Initial application:
The request was applied in historical core source by b1dc88787a, whose commit message explicitly includes GF#15692 and whose patch changed source/procedure/procedure-extensions-spreadsheet.xml so the directedBy extension context changed from Procedure to Procedure;ServiceRequest. The pre-removal core extension definition later carried both Procedure and ServiceRequest contexts plus the clarified requester-distinct description.

Additional context:
FHIR-15691 is the paired Procedure tracker that created the directedBy extension for the same LTSS self-directed-services requirement; it is already represented on the combined branch by 8016eb3812d7edc918852a6e72517bfec364fae8. FHIR-17543 is the later clarification tracker for the requester-distinct wording and is already represented on the combined branch by a19a0ac05f7e586e1b7bb3d734db41b66a450b37. Current core source still lists ServiceRequest as an active approved resource and retains the procedure-directedBy OID, but the authoritative extension definition was removed from core during the R5 extension-source reorganization and now lives in the FHIR Extension Pack. The Extension Pack source currently contains the ServiceRequest context, the Procedure context, the approved value types, and the clarified decision-making-authority definition.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR core source change. The requested ServiceRequest extension context was historically applied and is now maintained outside this core checkout; the current external source already carries the semantics requested by FHIR-15692, so reintroducing or editing a core extension definition would be the wrong build-scope fix.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed for FHIR-15692; any future changes to procedure-directedBy should be made in the FHIR Extension Pack, with Orders and Observations and Patient Care review if the ServiceRequest or Procedure extension scope changes.
