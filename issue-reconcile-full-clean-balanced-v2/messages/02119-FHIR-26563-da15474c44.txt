FHIR-26563: Audit removed MedicationKnowledge definition link

Issue request:
FHIR-26563 was a Published/Persuasive with Modification Pharmacy change request for R5. It asked to add a MedicationKnowledge link to MedicinalProductDefinition so knowledge-base and variable/local information could be connected to the richer medicinal product definition; the final resolution specified a new 0..1 attribute named associatedDefinition.

Initial application:
No prior git commit found in this checkout explicitly mentions FHIR-26563. The R5 source nevertheless gained the requested link before publication: commit 33b409a4b6d544598262f2f074ebb4b6dc466157 introduced MedicationKnowledge.associatedDefinition as 0..1 Reference(MedicinalProductDefinition), matching the Jira resolution. Later commit 6422f2f98a0fcf03140c15fe93bfd6c765fc6377 refactored MedicationKnowledge's definitional content into a backbone and replaced the root associatedDefinition element with MedicationKnowledge.definitional.definition, a 0..* Reference(MedicinalProductDefinition), while adding introductory text explaining that MedicationKnowledge is not a complete definition but can carry definitional information alongside formulary/catalogue content.

Additional context:
MedicationKnowledge is no longer an active current-build resource. Commit 5a4307d78b0209f61bbc68d582c1e190b3aaee5c removed MedicationKnowledge from source/fhir.ini's active resource and generated-resource metadata. The residual source/medicationknowledge files still contain the MedicinalProductDefinition reference, but source/fhir.ini's active [resources] list now omits MedicationKnowledge and the current build URLs for medicationknowledge.html and medicationknowledge.profile.json return 404. FHIR-50845 and Pharmacy WGM minutes record the later work-group direction to remove/deprecate MedicationKnowledge after finding homes for ongoing content.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The FHIR-26563 request was historically applied, then superseded by a later refactor and finally by removal of MedicationKnowledge from the current core build. Editing the inactive MedicationKnowledge StructureDefinition to restore the old associatedDefinition name or cardinality would not correct a current built artifact and would conflict with the later source history.

Recommendation:
Keep this audit commit as-is for the current core build. If MedicationKnowledge is restored to core or moved to a maintained external specification, review the inactive source/medicationknowledge/structuredefinition-MedicationKnowledge.xml and carry forward the existing ability to reference MedicinalProductDefinition, deciding at that time whether the modern element should remain definitional.definition 0..* or return to a narrower associatedDefinition 0..1 shape.
