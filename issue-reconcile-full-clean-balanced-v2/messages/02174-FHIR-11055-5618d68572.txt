FHIR-11055: Audit Consent purpose-of-use guidance

Issue request:
FHIR-11055 was Published/Not Persuasive with Modification for FHIR-core Consent. The original request asked to remove DSTU2 Consent.except.purpose because purpose-of-use codes could conflict with security labels, but the final resolution instead directed adding this comment to purpose and securityLabel: "When the purpose of use tag is on the data, access request purpose of use shall not conflict."

Initial application:
The issue was explicitly applied by historical commit 0f594b3938a50781639ecd7fa5930288595d9bfe, titled "Definition and comment changes for CR 11055 and CR 11056." That commit changed the old Consent spreadsheet source by replacing the Consent purpose comment with the approved purpose-of-use conflict sentence and appending the same sentence to the adjacent securityLabel comment. Later source refactors carried that guidance into the current StructureDefinition source as Consent.provision.purpose and Consent.provision.securityLabel.

Additional context:
Consent is an active current-build resource in source/fhir.ini, and source/consent/structuredefinition-Consent.xml is the current authoritative StructureDefinition input. The DSTU2 Consent.except element family is now represented by Consent.provision, including recursive nested provisions. Related FHIR-11056 was applied in the same historical commit and already has an audit commit on the combined branch. A later FHIR-36354 reconciliation refined the hierarchical-security-label portion of the Consent.provision.securityLabel comment while intentionally preserving the FHIR-11055 purpose-of-use sentence.

AutoFHIR reconciliation:
