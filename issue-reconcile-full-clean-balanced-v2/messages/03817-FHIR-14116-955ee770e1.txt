FHIR-14116: Audit ResearchStudy condition element

Issue request:
FHIR-14116 was a Published/Persuasive FHIR-core ResearchStudy change request from STU3. It asked to add study condition as a specifically named ResearchStudy semantic instead of including it inside the general focus element. Jira records that the change was made and published in the Dec 2017 FHIR ballot.

Initial application:
Commit 61b5fa5576, "Make updates to ResearchStudy based on BR&R subgroup agreements," added ResearchStudy.condition to the old spreadsheet source immediately before ResearchStudy.focus. That initial application used Reference(Condition), and later historical ResearchStudy work corrected the current source to CodeableConcept with a condition-code binding. No current source-changing reconciliation is needed for this issue.

Additional context:
FHIR-14289 is the same change family's follow-up wording/order issue: after condition became separate, focus should no longer describe conditions. Current ResearchStudy source has since been refactored from spreadsheets to StructureDefinition XML and focus has been changed by later issues to CodeableReference, but condition remains a distinct CodeableConcept element.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. In active current source, ResearchStudy.condition exists as a 0..* CodeableConcept immediately after ResearchStudy.focus, has the short description "Condition being studied," has its own condition-code example binding, and has its own search parameter.

Recommendation:
Keep this no-change audit. The current specification already contains the separate condition element requested by FHIR-14116, and related later changes preserve that model.
