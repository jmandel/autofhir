FHIR-10190: Audit Subscription endpoint relationship

Issue request:
FHIR-10190 was a Published FHIR-I DSTU2 change request, resolved Not Persuasive with Modification, asking to replace the Subscription channel backbone with a reference to the Endpoint resource and to review subscription channel type naming/codes. The approved resolution rejected replacement because Subscription only partially overlaps Endpoint and includes details that do not belong in Endpoint, while saying the relationship should be declared as a mapping.

Initial application:
No source commit explicitly mentioning FHIR-10190 was found. Historical Subscription source after the 2016 vote still modeled Subscription.channel.endpoint as a URL-like endpoint inside the channel backbone, so any original application was either implicit, untagged, or later overtaken by the Subscription redesign. The current build source has active Subscription and Endpoint resources and the current Subscription structure keeps channelType plus a channel-specific URL endpoint rather than a Reference(Endpoint).

Additional context:
The R5/R6 topic-based Subscription redesign removed the old Subscription.channel backbone and now describes an abstract notification endpoint role, not the Endpoint resource, in the Subscriptions Framework. Later applied issue FHIR-47344 explicitly clarified Subscription.endpoint as a channel-specific URL where notifications are sent and was implemented by commit ac3fd3079e5d96596e6a54930833012879584176. A newer R6 request, FHIR-56309, asks again to make Subscription.endpoint reference Endpoint, but it is still Submitted and unresolved, so it is not a final decision that can override the current URL model.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already preserves the final FHIR-10190 decision not to replace Subscription delivery fields with Endpoint, and the later applied R6 clarification confirms the current element is a URL. Adding a new Endpoint mapping or reference now would be speculative because the remaining replacement question is open in FHIR-56309.

Recommendation:
Keep this no-change audit as-is. If the work group resolves FHIR-56309 or another future issue to change Subscription.endpoint to Reference(Endpoint) or to add an explicit Endpoint mapping, implement that later decision separately; do not infer it from FHIR-10190 alone.
