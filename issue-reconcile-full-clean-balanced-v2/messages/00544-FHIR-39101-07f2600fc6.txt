FHIR-39101: Add missing CarePlan activity request target

Issue request:
FHIR-39101 was Published with a Persuasive with Modification resolution for R5 to remove CarePlan.activity.plannedActivityDetail and change CarePlan.activity.plannedActivityReference to support additional request resources: CommunicationRequest, CoverageEligibilityRequest, RequestOrchestration, and Transport.

Initial application:
The Jira-linked implementation commit 0222d171b0466cb633dce3342278e3da94cfd815 commented out the inline plannedActivityDetail definition, the mutual-exclusion invariant/condition, and plannedActivityDetail search parameters, and it converted examples to plannedActivityReference/contained request usage. It did not add CoverageEligibilityRequest or Transport to the plannedActivityReference targetProfile list. Current source already includes CommunicationRequest and RequestOrchestration.

Additional context:
CarePlan is an active resource in source/fhir.ini, and CoverageEligibilityRequest is also an active current-build resource. A later source refactor removed Transport from the active [resources] list as part of moving OO resources out of core, so adding Transport back to this core target list would now reference an out-of-build resource rather than honoring current build scope. FHIR-31407 is the duplicate/background request that explains the consistency rationale for removing the inline detail.

AutoFHIR reconciliation:
This commit adds CoverageEligibilityRequest to CarePlan.activity.plannedActivityReference and tags the element committee notes with J#39101. It intentionally leaves Transport out because it is no longer an active core resource in the current build. No SVG/diagram file was hand-edited; source/careplan/structuredefinition-CarePlan.xml is the authoritative resource definition for this change, and the existing SVG already contains other stale target-list entries from later resource removals.

Recommendation:
Keep this commit as-is for the current core build. If Transport is restored to core or represented by a current core replacement, Patient Care/O&O should decide a separate follow-up for the CarePlan target list and regenerate any checked-in CarePlan diagrams from the authoritative definition.
