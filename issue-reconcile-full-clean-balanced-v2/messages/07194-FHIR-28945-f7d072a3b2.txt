FHIR-28945: Audit FMM support documentation

Issue request:
FHIR-28945 was an Applied/Persuasive FHIR-core change request asking for supporting information around FMM declarations for core and IG artifacts. The request wanted FMM3+ maturity assertions to point to the quality criteria and wanted a standard extension/tooling path to carry supporting maturity documentation.

Initial application:
No Jira-keyed source commit was found for FHIR-28945 itself. The same implementation trail appears in Lloyd McKenzie's 2021 core commit 63410495, which added the structuredefinition-fmm-support extension and related conformance-derivedFrom extension to the StructureDefinition core IG, and in later source reorganization that moved core-owned extensions out of this checkout.

Additional context:
Current core source already defines the FMM criteria on versions.html, including the Conformance Resource Quality Guidelines link at FMM3 and implementation/support criteria for higher levels. Current FMM values are driven by source/fhir.ini. The extension definition requested by the issue now lives in the FHIR Extension Pack, and the 2025 Jira comment points to HL7/fhir-ig-publisher#1135, which was merged to fix publisher rendering/reading of FMM and standards-status support extensions.

AutoFHIR reconciliation:
This audit intentionally makes no source change in the core FHIR checkout. Reintroducing the extension definition into core would conflict with the current extension-pack ownership model, and adding duplicate maturity prose to core pages would not change implementer understanding because the current maturity page and extension-pack artifact already carry the relevant rule and computable mechanism.

Recommendation:
Keep this audit commit as-is. Future FMM-support changes should be made in the FHIR Extension Pack or IG Publisher when they affect the extension definition or rendering behavior; core changes are only needed if the current maturity model text or fhir.ini-driven FMM declarations become misleading.
