FHIR-7429: Audit external LOINC binding guidance

Issue request:
FHIR-7429 was a Published/Not Persuasive with Modification DSTU1 Vocabulary WG request asking FHIR to allow SNOMED CT as an alternative where LOINC is not used globally. The final resolution did not ask for SNOMED-first resource prose; it directed an update to committee wiki documentation saying that LOINC value sets should never be required or extensible in Resources.

Initial application:
No FHIR source commit or current source text was found that explicitly applies FHIR-7429. Exact source/history searches for the policy phrases and old ballot wording did not locate a current build artifact. That is consistent with the resolution targeting external wiki/committee guidance rather than a checked-in source page. The same ballot-family Composition issue, FHIR-7428, was applied separately to Composition.type and has already been audited on the combined branch.

Additional context:
The current terminology page is in build scope and defines binding strengths generically, without a LOINC-specific prohibition; it also points resource-design advice to FHIR Confluence pages. Current Composition.type is preferred-bound and retains the LOINC endorsement note from FHIR-7428, so SNOMED CT remains possible without undoing that related decision. Later active resource source changes introduced extensible bindings to specific LOINC answer-list value sets in GenomicStudy and MolecularDefinition. Changing those under this DSTU1 wiki-guidance issue would reverse later work-group source changes without a bounded Jira decision.

AutoFHIR reconciliation:
No source change was made. This empty external-repo audit records that the only explicit FHIR-7429 action belongs to committee/wiki documentation outside the current FHIR source checkout or current build, while a current core-source edit would be either redundant or unsafe.

Recommendation:
Keep this external-repo audit. If Vocabulary wants the 2015 committee policy to be current operational guidance, update the relevant Confluence/process documentation and/or file new scoped Jira issues with the owning work groups to review any current LOINC extensible bindings.
