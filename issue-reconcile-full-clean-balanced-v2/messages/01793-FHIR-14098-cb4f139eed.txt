FHIR-14098: Audit Measure public health support

Issue request:
FHIR-14098 was a Published/Persuasive STU3 CQI issue asking to extend Measure and MeasureReport to better support public health and health-system indicator reporting. The request identified four areas: less patient-centric narrative, codes to correlate measurements across measures/reports, coded stratifier definitions with constrained stratum values, and a secondary MeasureReport classification. The final resolution said the changes had been applied through other tracker items, except the proposed MeasureReport.code for item 4, which could be achieved with useContext or topic.

Initial application:
No current git commit was found that names FHIR-14098 directly. The seed's own Jira comment says the requested changes were applied as other tracker items. The clearest historical application is SVN/git commit 734c7befc75f, which applied GF#14057, GF#14060, and GF#14083 together: generalizing Measure/MeasureReport from patient to subject, replacing Measure and MeasureReport correlation identifiers with code elements, and changing MeasureReport stratifier values to CodeableConcept. Later FHIR-13863 added the public-health MeasureReport example, and FHIR-20723 added stratifier valueSet/unit support that now carries the requested constrained-stratum-values concept after later refinement.

Additional context:
Measure and MeasureReport are active current-build resources in source/fhir.ini. Current Measure source includes useContext, group.code, stratifier.code, stratifier.component.code, and stratifier.component.valueSet; current MeasureReport source includes group.code, group.stratifier.code, and group.stratifier.stratum.value[x] with CodeableConcept among the allowed types. Current Measure narrative describes health-related measures including public health indicators and population analytics measures. Later FHIR-53139 refined value-set support to component-level value-based stratifiers, so reintroducing a top-level Measure.group.stratifier.valueSet/codeConstraint would conflict with later CQI decisions. Later FHIR-55436 removed Measure.topic from the explicit Measure differential, but Measure.useContext remains and satisfies the seed resolution's useContext-or-topic classification path.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already conveys the accepted FHIR-14098 behavior through active Measure and MeasureReport definitions plus later Measure-family refinements, and adding a MeasureReport.code or redundant narrative would either reverse the seed resolution or duplicate guidance already present in the current build.

Recommendation:
Keep this audit commit as-is. Future changes for mADX/public-health quality reporting should be handled by their own CQI or IG-specific trackers, especially if they propose changing the current component-level stratifier value-set model or adding new MeasureReport classification elements.
