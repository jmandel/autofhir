FHIR-32586: Audit DocumentReference security label binding

Issue request:
FHIR-32586 was a Published/Persuasive with Modification OO change request for DocumentReference.securityLabel. The ballot comment said the Security Labels value set was not coherent or mappable enough for an extensible binding, and the accepted resolution was to make the current value set an example binding while OO worked with Security on a better example set.

Initial application:
The Jira application comment points to merge commit 8d1cf2b00809434f98fd4f14c874c7837a19389b. The issue-branch content commit 3a3e468b4b4a94054cfe4b1d919e893ab935a4d1 changed DocumentReference.securityLabel from extensible to example while still referencing the broad security-labels value set.

Additional context:
DocumentReference is active in source/fhir.ini, so source/documentreference/structuredefinition-DocumentReference.xml is in the current build scope. Security WG issue FHIR-32471 later required elements using the broad HCS security-labels value set to use a new example value set; commit cd1c06923912f70a88c90d186ff3283b40e0403b updated DocumentReference to an example security-label value set, and 2025 commits 7231f4c27ab62fe032fd52c0e233c6955da6f295 and 20519d082a70e510caf4b497b616ec3946b302a2 normalized the current singular security-label-example URL. OO Confluence minutes confirm the FHIR-32586 block vote, and the only Zulip context found was pre-issue discussion of the old extensible binding rather than a later conflicting decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active DocumentReference.securityLabel binding is strength="example" and points to http://hl7.org/fhir/ValueSet/security-label-example, whose source is an explicitly experimental example set. The surrounding comment says HCS use is recommended but not mandated and is an administrative-domain responsibility, so it no longer imposes the extensible/preferred conformance expectation that FHIR-32586 rejected.

Recommendation:
Keep this audit commit as-is. Future changes to the content of the example security-label value sets should be handled through Security WG terminology trackers such as FHIR-32471, not by reopening this OO DocumentReference binding-strength issue.
