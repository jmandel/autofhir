FHIR-16188: Fix modifier rules cross-reference

Issue request:
FHIR-16188 was Published with resolution Not Persuasive with Modification. The submitter argued that Is-Modifier was too broad, inconsistently testable, and should be removed or replaced. FHIR-I instead kept Is-Modifier and decided to add clearer Conformance page content from the modifier discussion/document to formally define boundaries and make the rule testable.

Initial application:
The issue was applied by git-svn commit 005b06c3a4 / svn r14216, "GF#16188 - update definition of isModifier", which added the current litmus-test wording to source/conformance-rules.html and also added a modifier-extension cross-reference in source/extensibility.html. The current Conformance page still contains the substantive FHIR-16188 rule: an element is a modifier only if it cannot be safely ignored because its value or meaning-if-missing can make the containing element or descendants no longer conform to their stated definitions.

Additional context:
source/hierarchy.xml includes both conformance-rules.html and extensibility.html in the current Foundation documentation, so both pages are in build scope. Later modifier-related history adjusted adjacent guidance, including FHIR-40769 pointing ElementDefinition.isModifier toward the Conformance rules, but did not replace the FHIR-16188 criterion. Zulip evidence from the July 2018 Observation discussion matches the applied wording and did not reveal a later reversal; direct Zulip and Confluence searches for FHIR-16188 found no conflicting community record beyond the implementation notification.

AutoFHIR reconciliation:
This commit keeps the already-applied FHIR-16188 prose and fixes the source defect left in the same application trail: source/extensibility.html linked to conformance-rules.html#modifier, but conformance-rules.html defines the relevant anchors as #isModifier and #ismodifier. The link now targets conformance-rules.html#isModifier, matching the current modifier-rules section and existing cross-reference convention.

Recommendation:
Keep this commit as-is. It is a bounded current-spec repair to the applied FHIR-16188 guidance; no broader wording change is recommended unless FHIR-I reopens the modifier policy itself.
