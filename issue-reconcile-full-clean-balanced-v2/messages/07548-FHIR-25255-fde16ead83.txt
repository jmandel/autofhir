FHIR-25255: Audit Task reason cardinality update

Issue request:
FHIR-25255 is a Published/Persuasive with Modification FHIR-core Task change request raised against R4 and applied for R5. It asked to change Task.reasonReference from 0..1 to 0..* so multiple Observations could justify a Task recommendation; the approved modification was to replace Task.reasonCode and Task.reasonReference with 0..* reason CodeableReference.

Initial application:
The Jira comment records git commit fbb011b3a9 as the application. That commit changed the authoritative Task StructureDefinition by replacing Task.reasonCode and Task.reasonReference with Task.reason, setting max to *, and using CodeableReference. It also migrated the active Task examples from reasonCode to reason, and later reconciliation for FHIR-29636 removed stale example reason guidance that had been carried forward by the same refactor.

Additional context:
Task is an active resource in source/fhir.ini. Current migration annotations record Task.reason as the merge of reasonCode and reasonReference, mapping the old paths to reason.concept and reason.reference. The current Task source defines Task.reason as 0..* CodeableReference with targetProfile Resource, which is the current source representation of CodeableReference(Any). The original genomics Zulip thread confirms the use case: multiple Observations may support a recommendation and a workaround grouper should not be required. FHIRI minutes record the 2020 block-vote approval. Related issue FHIR-37905, already represented on the combined branch, completed/audited the Any target-profile aspect for the same Task.reason change family.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build-scope source already satisfies FHIR-25255, and targeted checks found no active Task.reasonCode or Task.reasonReference element definitions remaining. The only remaining reasonCode/reasonReference strings in fhir.ini are migration annotations for the old paths, which are appropriate.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-25255 unless a future work-group review intentionally changes the Task.reason design beyond the already-applied CodeableReference(Any) model.
