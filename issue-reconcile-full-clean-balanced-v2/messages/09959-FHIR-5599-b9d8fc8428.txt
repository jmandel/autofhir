FHIR-5599: Audit filter-operator not-in spelling

Issue request:
FHIR-5599 was a Published/Persuasive DSTU1 change request for FHIR-core ValueSet asking to rename the inconsistent FilterOperator code "not in" to the hyphenated "not-in". The recorded resolution says to rename FilterOperators "not in" to "not-in" and cites the 2015-03-09 MnM/FHIR block vote.

Initial application:
No current git commit is tagged with FHIR-5599. Jira comments say the change was already done for another task, and git history shows e995abe5d075934abc6de37f9449f057bcfbb82e (#5573: remove spaces from internally defined codes) changed the ValueSet spreadsheet filter-operator entries from "not in" to "not-in" before the Jira was resolved.

Additional context:
The current build has ValueSet as an active resource in source/fhir.ini. Current source/valueset/structuredefinition-ValueSet.xml binds ValueSet.compose.include.filter.op to http://hl7.org/fhir/ValueSet/filter-operator and lists "not-in" in the short display. Current source/valueset/codesystem-filter-operator.xml defines the canonical concept code as <code value="not-in"/>, and source/valueset/valueset-notes.xml documents op values "in" and "not-in". Focused source searches found no remaining operator-code spelling of "not in". Community searches found no exact FHIR-5599 discussion that would change the Jira/source conclusion; apparent FHIR-5599 hits were later issue keys such as FHIR-55991 and FHIR-55992. FHIR-5573 is the same application family but is broader than this bounded seed audit and is not decided here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative ValueSet, CodeSystem, and ValueSet.compose.include.filter.op binding already reflect the requested hyphenated FilterOperator code.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-5599 unless a future terminology decision changes the FilterOperator code set.
