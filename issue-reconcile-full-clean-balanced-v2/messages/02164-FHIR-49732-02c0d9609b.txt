FHIR-49732: Audit dual narrative no-list class names

Issue request:
FHIR-49732 was an Applied/Persuasive FHIR-core narrative request to fix the discrepancy where the narrative styling page named the no-bullet CSS class unlist while the linked fhir-runtime.css stylesheet defined nolist. The accepted resolution was the backwards-compatible fix: define both classes in both places.

Initial application:
The discrepancy came from the original FHIR-7084 implementation: git commit 9cdb0a817b722407dfa561b2e0060ab0e4ec9873 documented unlist and added an unlist example but added the runtime selector as nolist. Git commit d58d5482293fa7c56b050faa3007413e9abe662d applied FHIR-49732 by adding .unlist to implementations/fhir-runtime.css and adding nolist plus an explanatory duplicate-name note to source/narrative.html.

Additional context:
The Zulip thread linked from FHIR-49732 records the implementer report that R4/R5/build had mismatched names and Grahame Grieve's response that the only possible fix was to define both. Current source/narrative.html and implementations/fhir-runtime.css now match that decision. source/fhir.ini keeps Narrative active, maps narrative/xhtml to the narrative page, marks Narrative normative, and assigns Narrative=txt, so the inspected files are current build inputs.

AutoFHIR reconciliation:
No source change was made. The current source already defines both nolist and unlist in the narrative page and the runtime stylesheet, exactly matching the accepted backwards-compatible fix.

Recommendation:
Keep this empty audit commit as-is. No FHIR-core source follow-up is needed for FHIR-49732 unless a future work-group decision changes the supported narrative CSS class names.
