FHIR-13406: Audit CapabilityStatement search parameter guidance

Issue request:
FHIR-13406 was Published/Persuasive for STU3 and asked to clarify that CapabilityStatement.rest.resource.searchParam declarations may include supported search-result/control parameters such as _include, _sort, _count, and _summary, in addition to resource-specific and global search parameters. The resolution said to document behavioral parameters like _count and _summary, note that some parameter behavior may be described elsewhere in the CapabilityStatement, and update the default CapabilityStatement to expose these parameters.

Initial application:
The issue was applied by svn-derived commit f8fabe0b8a8b9d30b5e5551551e7cab7f4af3d83 / svn revision 12800, which added comments to the CapabilityStatement spreadsheet for CapabilityStatement.rest.resource.searchParam and CapabilityStatement.rest.searchParam. The current refactored source preserves that guidance in source/capabilitystatement/structuredefinition-CapabilityStatement.xml, which is in build scope because CapabilityStatement is an active resource in source/fhir.ini.

Additional context:
The current generated capabilitystatement-base artifact is not checked in as editable source, but the current build exposes the control/result parameters once at CapabilityStatement.rest.searchParam, including _sort, _count, _include, _revinclude, _summary, _elements, and related parameters. It does not repeat those parameters under every resource-specific searchParam list, which is consistent with the current element comments saying many will be listed at CapabilityStatement.rest.searchParam. Later FHIR-46110 and its applied source commit added the current compromise for non-true SearchParameters: omit .definition and use type special. FHIR-51160 requests a further correction to the rest.searchParam comment but remains Resolved - change required and is outside this Published seed decision.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The active CapabilityStatement source already conveys the FHIR-13406 rule for resource-level declarations, the current generated base CapabilityStatement exposes the relevant control/result parameters at the REST level, and later follow-up wording work should be handled under its own Jira scope rather than folded into this seed.

Recommendation:
Keep this no-change audit commit. If the work group wants the later rest.searchParam wording from FHIR-51160 applied, reconcile that issue separately; do not change the already-correct FHIR-13406 resource.searchParam guidance as part of this seed.
