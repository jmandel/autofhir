FHIR-47349: Audit Subscription payload modified-version wording

Issue request:
FHIR-47349 was an Applied/Persuasive R6 FHIR-core Subscription clarification asking the Notification Content payload-type paragraph to say that, when a server accepts a Subscription with modifications instead of rejecting an unsupported payload type, it returns the accepted modified version to the client.

Initial application:
The issue was applied by commit e17fc3fa4e7fab712ed7991cc2aa93a65d420436, which changed source/subscription/subscription-notes.xml from "return the accepted version to the client" to "return the accepted and modified version to the client." The Jira comment also points to HL7/fhir pull request 3967 for this application.

Additional context:
source/fhir.ini actively lists subscription=Subscription, so source/subscription/subscription-notes.xml is in current build scope for the Subscription resource page. The FHIR-I 2025-03-31 block vote minutes include FHIR-47349 as Persuasive and record the 17-0-0 motion. Current source searches show the old target sentence is gone from the Subscription notes; the remaining "accepted version" hit is a different workflow sentence in source/subscriptions.html.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current active source already conveys the approved clarification. The wording "accepted and modified version" is semantically equivalent to the Jira-requested "accepted modified version" and more explicitly ties the returned resource to both acceptance and modification, so a source edit would be unnecessary churn.

Recommendation:
Keep this no-change audit commit. No core follow-up is needed unless the work group later wants a purely stylistic exact-wording change, which is outside this reconciliation threshold.
