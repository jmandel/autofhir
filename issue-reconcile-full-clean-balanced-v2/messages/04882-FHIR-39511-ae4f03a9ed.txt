FHIR-39511: Audit SupplyRequest deliverFor migration

Issue request:
FHIR-39511 was a Published/Persuasive R5 Orders and Observations change request to add a SupplyRequest subject/deliverFor element, 0..1 Reference(Patient), with the short definition "The patient for who the supply request is for" and long definition "The patient to whom the supply will be given or for whom they will be used."

Initial application:
The issue was applied in core history. Commit fa4707d5a7 added the requested Patient reference as SupplyRequest.subject, and follow-up commit 2e15fce0f1 renamed the element and patient search parameter expression to SupplyRequest.deliverFor with subject as the alias. The legacy core SupplyRequest source still contains SupplyRequest.deliverFor as 0..1 Reference(Patient), and the SupplyRequest-patient search parameter points to SupplyRequest.deliverFor.

Additional context:
SupplyRequest is no longer an active resource in the current core build. The active [resources] list in source/fhir.ini has no supplyrequest entry, and commit 3b38b80cf2 removed SupplyRequest/SupplyDelivery and related OO resources from the core build while redirecting current core narrative links to the OO Incubator IG. The current OO Incubator package at build.fhir.org/ig/HL7/oo-incubator contains SupplyRequest.deliverFor as 0..1 Reference(Patient) and keeps the patient search parameter expression on SupplyRequest.deliverFor. FHIR-52991 is a later Triaged, unresolved OO Incubator request to revisit/widen/rename SupplyRequest/SupplyDelivery subject and destination actors, so it is context only and not a final reversal of FHIR-39511.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. FHIR-39511 has already been applied to the SupplyRequest definition, and current core no longer owns SupplyRequest as an active built resource. Any remaining SupplyRequest changes belong in the OO Incubator repository/build, not in inactive legacy core SupplyRequest files.

Recommendation:
Keep this external-repo audit commit as-is. If the work group later resolves FHIR-52991 or another OO Incubator issue, make that follow-up in HL7/oo-incubator rather than editing out-of-build core SupplyRequest source for FHIR-39511.
