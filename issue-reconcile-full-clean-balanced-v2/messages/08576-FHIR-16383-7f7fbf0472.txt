FHIR-16383: Audit test-resource HTEST guidance

Issue request:
FHIR-16383 was Published/Persuasive with Modification for STU3 and asked for clearer instructions on how to indicate that a resource is test data. The accepted resolution called for references to v3 ActReason HTEST on testing/security-label/tag guidance and for generated example packages to mark non-conformance example resources.

Initial application:
The issue was applied in svn revision 13959, mirrored as git commit ebfe68feb5e7a9145fb75fb5e75d43f4a8e6f5dc, which added an HTEST row to security-labels.html, added a "Mark a Resource as a Test" section to the then-current testing.html page, and changed the then-in-repo publisher to add HTEST to generated examples. Earlier related FHIR-10580 had already added the broader "Using FHIR to publish test data" section to the Security and Privacy module.

Additional context:
The old core testing.html page and TestPlan/TestScript/TestReport resources were removed from core by f9a44787c45071394532c7c2ee94d76f30f47387 when testing resources moved to the FHIR Testing IG, with fhir.ini and resourcelist.html retaining a link to that IG. The current core build still contains active security-labels.html and secpriv-module.html guidance: security-labels.html lists HTEST as the Test Data label, and secpriv-module.html explains that intermingled test data can be marked with PurposeOfUse HTEST. Current build examples-json.zip and examples.zip also still carry HTEST for non-canonical/non-conformance example resources, so the generated example-package part of the historical application remains represented in the publication surface.

AutoFHIR reconciliation:
This is an empty audit commit. No source change was made because the current core source already tells implementers where to indicate test data, the core testing page has intentionally moved out of this checkout, and generated example packages still include HTEST tagging for the relevant example resources.

Recommendation:
Keep this audit commit as-is. If maintainers want the external FHIR Testing IG to repeat the HTEST guidance from core, handle that as a separate IG follow-up; it is not necessary to change the current core source for FHIR-16383.
