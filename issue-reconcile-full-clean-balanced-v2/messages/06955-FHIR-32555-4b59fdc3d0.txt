FHIR-32555 was Published/Persuasive for R5 and asked OO to remove the `unknown` code from the Device.status value set because Device.status is the status of the record, not the physical device, and the issue found no clear case where a system would not know its own record status.

Initial application:

Because `source/device/valueset-device-status.xml` includes the whole `http://hl7.org/fhir/device-status` code system, that implementation also removed `unknown` from the Device.status required binding expansion for R5.
