Issue request:
FHIR-47738 was Applied as Persuasive with Modification for FHIR-core Requirements. It asked for a forward link from one Requirements instance to external requirement statements so an IG requirement can import referenced requirements without duplicating or redefining them; the approved disposition added a repeating Requirements.imports backbone with a canonical pointer to another Requirements resource and optional statement keys.

Initial application:
The upstream source commit ccc7c77def, titled "FHIR-47738 Need for a forward link to another requirement statement", added Requirements.imports, its canonical-valued child, and its key child to source/requirements/structuredefinition-Requirements.xml. The adjacent FHIR-47737 application commit 88c7b5ba then normalized the canonical-valued child name from canonical to reference across the related Requirements link structures, including Requirements.imports.reference.

Additional context:
The 2024-10-28 FHIR-I minutes record the same approved Requirements.imports disposition and 10-0-0 vote. A later Zulip implementation note from Grahame Grieve says the related Requirements tasks used different names for the canonical-valued child and he made them all reference, which explains the current child name without changing the import semantics. The active Requirements resource remains in build scope through source/fhir.ini, and related reconciliations for FHIR-47736 and FHIR-47739 are already represented on the combined branch.
