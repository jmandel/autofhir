FHIR-13011: Audit Provenance security role terminology

Issue request:
FHIR-13011 was Published/Persuasive with Modification for DSTU2 Provenance. The issue said the old security-role-type value set was broken for Provenance because it mixed participation concepts such as author/witness with structural/security roles such as RBAC or ABAC roles; the final resolution said Provenance.agent.type indicates how the agent participated, while Provenance.agent.role records the security roles that authorized the participation if those roles are recorded.

Initial application:
No explicit source commit mentioning FHIR-13011 was found in current git history. The model split was introduced in the same DSTU2 Provenance family by 84f8086d21, which added Provenance.agent.type in the old spreadsheet source, kept Provenance.agent.role separate, and changed the old role binding toward example use. Later source conversion preserved the split in source/provenance/structuredefinition-Provenance.xml.

Additional context:
Later final Security WG issues refined the same distinction instead of reverting it. FHIR-20328, FHIR-28184, and FHIR-32453 clarified agent.type as the functional participation/how-the-agent-participated concept and agent.role as structural/security roles. FHIR-32519 cleaned the participation-role-type value set and, through the existing combined-branch fix, leaves Provenance.agent.type with a preferred binding. FHIR-32520 replaced the old broad role vocabulary with the current example structural-role value set for agent.role. FHIR-55889 later removed an extra security-role include from participation-role-type. Provenance, the role code system, and both value set binding rows are active current-build inputs.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already satisfies FHIR-13011 after later approved refinements: Provenance.agent.type is 0..1, describes how the agent participated, and binds to participation-role-type; Provenance.agent.role is 0..*, describes structural/security roles and authorization, and binds at example strength to security-role-type-example. Restoring the older literal v3 ParticipationType wording or broad security-role-type value set would undo later final cleanup.

Recommendation:
Keep this audit commit as-is. No further core FHIR source change is needed for FHIR-13011; future changes to Provenance role terminology should be handled through a new Security WG decision because the current source reflects the later issue family.
