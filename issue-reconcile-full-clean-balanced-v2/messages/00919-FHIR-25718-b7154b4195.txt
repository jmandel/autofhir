FHIR-25718: Audit MeasureReport correlation guidance

Issue request:
FHIR-25718 was a Published/Persuasive R5 CQI change request asking to restore guidance that identifiers coordinate MeasureReport results with the corresponding Measure population, stratifier, and supplementalData definitions. The issue explains that STU3 had explicit identifier elements, R4 removed them in favor of Element.id, and the identifier guidance was lost.

Initial application:
The Jira comments identify commit e9e025abe745570e34e38009ffafc2570c0bb4a9 and HL7/fhir#2879 as the application. That commit updated the active clinicalreasoning-quality-reporting.html narrative to say Measure and MeasureReport content is correlated by linking ids. By the time the issue was applied, related FHIR-38832 had introduced linkId as the current R5 mechanism, so the applied text correctly used linkId rather than newly recommending Element.id.

Additional context:
Measure and MeasureReport are active resources in source/fhir.ini. The current StructureDefinitions define Measure group, population, stratifier, stratifier component, and supplementalData linkIds, and define corresponding MeasureReport group, population, stratifier, stratifier component, and stratum-population linkIds with backwards-compatible comments noting prior Element.id use. Later Applied/Persuasive issues refine the same area: FHIR-38832 added linkId and is already represented on the combined branch; FHIR-49670 clarified MeasureReport correspondence and is already represented on the combined branch; FHIR-37559 established MeasureReport.supplementalData as Reference(Resource); and FHIR-50012 updated the quality-reporting narrative, including removing the stale statement that MeasureReport.supplementalData itself has linkId. A later Zulip implementer question notes possible desire for stronger supplementalData categorization, but no final Jira/source decision was found for adding such a model now.

AutoFHIR reconciliation:
This audit commit makes no source change. The current build-scope source already preserves the issue's implementer-facing guidance through the current linkId mechanism and backwards-compatible id comments. Re-adding supplementalData to the MeasureReport linkId paragraph would be inaccurate because MeasureReport.supplementalData is currently a reference; its reporting/correlation behavior is instead documented through the supplementalData reference and contained Observation guidance.

Recommendation:
Keep this no-change audit. If the work group wants MeasureReport.supplementalData to carry linkId/code/id categorization directly, handle that as a new substantive modeling decision rather than as a FHIR-25718 reconciliation fix.
