FHIR-12620: Audit Encounter triaged status

Issue request:
FHIR-12620 was a Published/Persuasive PA change request for DSTU2 asking to add `triaged` to the Encounter.status value set, define it as the patient having been assessed for treatment priority and waiting, and update the Encounter Status Management notes to include triaged between arrival and in-progress.

Initial application:
The issue was applied in historical commit d562f07e0ff1abf6b607baacde81c2a276e3214e, which added `triaged` to the old Encounter status source and changed the Status Management note from "arrived"/"in progress" to "arrived", "triaged", or "in progress". The current source is no longer the old spreadsheet form, and no prior FHIR-12620 issue-reconcile commit was present on the combined branch.

Additional context:
Later final Encounter decisions changed the meaning of this area. FHIR-13702, Published/Persuasive with Modification for R5, split patient-flow concepts out of Encounter.status into Encounter.subjectStatus and explicitly listed `triaged` there rather than in the required Encounter.status code list. FHIR-32343 then defined the subjectStatus `triaged` code and relaxed the subjectStatus binding to Example, and FHIR-47297 added Encounter.businessStatus with an emergency workflow example that includes `triaged`. Encounter is active in source/fhir.ini; current build-scope source keeps Encounter.status as the overall encounter state, keeps triage language under Encounter.subjectStatus/status-management guidance, and adds `triaged` in the emergency business-status example. A Zulip thread in 2025 confirms this R4-to-R5/R6 interpretation, and Confluence search found no FHIR-12620 conflict.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. Re-adding `triaged` to the current required Encounter.status value set would contradict the later Published/Applied Encounter status split; the current specification already preserves the triage concept in the patient/workflow status locations chosen by later decisions.

Recommendation:
Keep this no-change audit as-is. Current implementations should use Encounter.subjectStatus or Encounter.businessStatus for triage-specific patient/workflow state, not add `triaged` back to Encounter.status. Handle any remaining FHIR-54491 businessStatus/class refinements separately because that issue is still Resolved - change required rather than Applied/Published in this run scope.
