FHIR-30078: Audit Communication reason search parameters

Issue request:
FHIR-30078 was Applied/Persuasive for FHIR-core Communication after the Patient Care vote on 2023-07-27. It asked that Communication be searchable by reasonCode and reasonReference, with the resolution to add the requested reason* search parameters.

Initial application:
The issue was applied by ed2ad0f22f37e3634066932e9b8e642d8c146e0c, merged by c925d26d06, which added Communication reason-code and reason-reference search parameter entries to source/communication/bundle-Communication-search-params.xml. That implementation was paired with separate FHIR-40760 Communication introduction text in the same commit, but the search parameter additions were the FHIR-30078 portion.

Additional context:
Communication is active in the current build through source/fhir.ini. The current model has migrated the former reasonCode/reasonReference split into Communication.reason as a CodeableReference, and fhir.ini records the migration from Communication.reasonCode to reason.concept and Communication.reasonReference to reason.reference. The current Communication search-parameter bundle uses those current paths.

AutoFHIR reconciliation:
No source change was made. The current source already contains normative Communication reason-code and reason-reference search parameters with expressions Communication.reason.concept and Communication.reason.reference, which preserves the Jira-requested search capability after the CodeableReference migration.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-30078 unless a future work group decision changes the Communication.reason model or search parameter naming.
