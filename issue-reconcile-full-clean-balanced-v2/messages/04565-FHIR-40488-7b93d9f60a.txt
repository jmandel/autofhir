FHIR-40488: Rename remaining Device example version

Issue request:
FHIR-40488 is an Applied/Persuasive R6 Orders & Observations change request asking to rename the device-version backbone from Device.version and the pre-canonical DeviceDefinition.version to deviceVersion. The stated reason was to leave DeviceDefinition.version available for the CanonicalResource business-version pattern while keeping Device consistent.

Initial application:
Git commit d0ee6976b376257bf44fc840b43b79b6f1c9487d applied FHIR-40488 to the main Device and DeviceDefinition StructureDefinitions, their search-parameter bundles, and many Device examples. Current source now defines Device.deviceVersion and DeviceDefinition.deviceVersion, and DeviceDefinition.version is the later CanonicalResource business version rather than the old device-version backbone. One active Device example, source/device/device-example-bpmonitor.xml, still used the old Device.version element.

Additional context:
Device and DeviceDefinition are active build resources in source/fhir.ini, and source/device/list-Device-examples.xml includes device-example-bpmonitor, so this example feeds the current Device example set. FHIR-42900 and the #devices Zulip thread explain the broader DeviceDefinition canonical-resource work; that context confirms DeviceDefinition.version should not be renamed now because it is the canonical business version. A stale Device.version example also exists under source/genomicstudy, but GenomicStudy is not active in source/fhir.ini, so that out-of-build file was not changed for this current-spec reconciliation.

AutoFHIR reconciliation:
Renamed the active bpmonitor Device example wrapper from <version> to <deviceVersion>, preserving the existing type and value children. No DeviceDefinition source change was needed because the current DeviceDefinition source already has both canonical version and deviceVersion in their distinct roles.

Recommendation:
Keep this source fix. If GenomicStudy is reactivated in a future build, separately review its examples for the same Device.deviceVersion migration rather than treating that disabled directory as part of this R6 Device/DeviceDefinition reconciliation.
