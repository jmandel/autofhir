FHIR-15760: Audit Composition document bundle references

Issue request:
FHIR-15760 was a Published STU3 SD change request, resolved Persuasive with Modification, asking that the document-bundle inclusion rule for Composition references not imply that identifier-only logical references require creating placeholder resources. The approved clarification changed the Composition-page rule to "Resources associated with the following list of Composition references SHALL be included in the bundle" and made the following optional inclusion sentence an uppercase, qualified MAY.

Initial application:
The issue was applied in git commit 3a143a863a, which changed source/composition/composition-introduction.xml with the GF#15760 wording. That exact local Composition-page list is no longer current: FHIR-27891 later replaced it with a link to the authoritative FHIR Documents page, and the current source/composition/composition-introduction.xml points readers there for document-bundle guidance.

Additional context:
The active source/documents.html page is in the build hierarchy and now carries the relevant rule. FHIR-19711 changed the older broad "Any resource referenced directly" wording to the current listed-Composition-reference rule. FHIR-15723 later intentionally replaced the earlier permissive secondary-reference prose with the current SHOULD guidance and contained-resource clarification. FHIR-39502 and FHIR-43295 further clarified the document bundle graph and, importantly for logical references, FHIR-43295 says bundle linkage requirements are met through Reference.reference, canonical, or URI rather than business-identifier resolution. A related Zulip thread confirms there is no expectation to resolve references that do not have an actual URL reference.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current specification already preserves the seed issue's core distinction: document bundles are built from actual linked/associated resources, while later approved text handles secondary resources and RESTful graph linkage more precisely than the original STU3 clarification. Reverting source/documents.html to the older FHIR-15760 MAY wording or duplicating the old Composition-page list would conflict with later applied decisions.

Recommendation:
Keep this audit commit as-is. If future work reopens document-bundle logical-reference behavior, start from FHIR-43295 and the Documents page graph-linkage rules rather than from the superseded Composition-page wording.
