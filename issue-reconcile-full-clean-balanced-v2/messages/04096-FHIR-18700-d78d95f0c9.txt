FHIR-18700: Audit ValueSet extension text ownership

Issue request:
FHIR-18700 was a Published FHIR-core/Vocabulary change request, resolved Persuasive for STU3, asking to add explanatory text to valueset-authoritativeSource and valueset-trusted-expansion. The accepted resolution was to make the suggested changes: authoritativeSource should say the designated authoritative source is normally expected to generate a valid expansion and to use valueset-trusted-expansion if it cannot, while trusted-expansion should identify an alternate authoritative source when the authoritative source cannot provide a valid expansion.

Initial application:
Core commit 4907f9bcb0b710cb2837a93a20c4b23210a37249 explicitly listed GF#18700 and applied the requested comments to source/valueset/valueset-extensions-spreadsheet.xml. The later generated StructureDefinition sources in core carried that wording before the extension definitions were removed from the core source tree.

Additional context:
The current FHIR-core checkout no longer owns these extension StructureDefinitions: source/fhir.ini has no active valueset-authoritativeSource or valueset-trusted-expansion source, and current core searches find only their OID registrations in source/oids.ini. Core commit dd468d4f1799dd79819315b211588ef1cf4586e0 removed both StructureDefinition source files as part of the R5 extension-source move. The current owning source is the FHIR Extension Pack, where input/definitions/ValueSet/StructureDefinition-valueset-authoritativeSource.xml still contains the FHIR-18700 authoritative-source comment, and input/definitions/ValueSet/StructureDefinition-valueset-trusted-expansion.xml contains the same relationship to valueset-authoritativeSource plus later FHIR-27028 endpoint-focused wording. FHIR-23784 later closed the authoritativeSource request as already applied, and FHIR-23785, FHIR-27028, and FHIR-27848 are later or companion trusted-expansion decisions already represented on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR-core source change. Re-adding or editing the extension definitions in core would reverse the current Extension Pack ownership split, while the external owning artifacts already preserve the substance of the FHIR-18700 change as refined by later approved decisions.

Recommendation:
Keep this external-repo audit as-is for core. No FHIR-core follow-up is needed for FHIR-18700; any future wording, status, or datatype work for these extension definitions should be handled in HL7/fhir-extensions and considered together with the already-audited FHIR-23785, FHIR-27028, and FHIR-27848 history.
