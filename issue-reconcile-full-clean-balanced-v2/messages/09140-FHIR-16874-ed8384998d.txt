FHIR-16874: Audit decimal exponential form

Issue request:
FHIR-16874 was a Published/Persuasive FHIR-core datatypes change request from the 2018-May Core Norm ballot. It asked to replace the prior prohibition on decimal exponents with a rule allowing exponential form in all formats, with XML decimal represented as a union of xs:decimal and xs:double so values such as 1.00E3 can preserve significant digits.

Initial application:
The Jira comment says the issue was applied in svn revision 13843. In git history that is commit c8e08d05ceadfdcd439fa409adf52bf0efecffe4, which changed the datatypes decimal row from the old "decimals SHALL not use exponents" / "exponents are not allowed" wording to an xs:decimal/xs:double union and added decimal limitations text. The immediately following same-day companion commit 79c1c0b5cb433f8068e231bd3ab2378464654f41 updated XML implementation guidance and search-number examples for exponent-capable decimals.

Additional context:
The current combined source keeps the issue's intended behavior in active build pages and datatype sources: datatypes.html says decimal uses an xs:decimal/xs:double union for XML and a JSON number, primitives.xml has an exponent-capable decimal regex, xml.html documents the union schema and exponent-capable string pattern, rdf.html explains that values containing e/E are xsd:double, and history.html records GF#16874. The relevant Zulip thread confirms the implementation intent, including preserving presentation form, disallowing INF/NaN, changing the XML schema type to a decimal/double union, and applying the behavior to search. FHIR-5653 and FHIR-8175 are related decimal precision decisions but do not reverse FHIR-16874; FHIR-16369 is the companion search behavior issue rather than a needed seed-source correction.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already allows decimal exponential form in the relevant FHIR representations and no checked source still carries the old exponent prohibition.

Recommendation:
Keep this audit commit as-is. No follow-up core source work is needed for FHIR-16874 unless a future work group decision changes decimal exponent policy.
