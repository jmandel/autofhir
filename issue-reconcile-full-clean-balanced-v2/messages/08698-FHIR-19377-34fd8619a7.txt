FHIR-19377: Audit Questionnaire modifier extension status

Issue request:
FHIR-19377 was a Published/Persuasive FHIR-core Questionnaire issue from STU3 asking to review questionnaire-optionExclusive and questionnaire-usageMode because they were labeled modifier extensions even though they did not meet the then-current modifier definition. The accepted resolution was to make the two Questionnaire extensions not modifier.

Initial application:
The issue was applied by git commit a671d22cc52ba84fd280945f700df4d2e0976309, "GF#19377 Q extensions not modifiers". That commit removed the old spreadsheet modifier flag and rationale cells for optionExclusive and usageMode in source/questionnaire/questionnaire-extensions-spreadsheet.xml. The generated historical artifacts confirm the effect: release3 carried isModifier=true for both extensions, while release4 carries isModifier=false.

Additional context:
The active core build still includes Questionnaire, but current core no longer owns the individual Questionnaire extension StructureDefinitions. Commit dd468d4f1799dd79819315b211588ef1cf4586e0 removed the Questionnaire extension StructureDefinitions from R5 core source. Current core retains only the Questionnaire extension IG stub and OID assignments for these two canonicals; the maintained definitions now live in the FHIR Extension Pack. Those Extension Pack source files have no isModifier override, so they inherit the normal non-modifier Extension behavior. A prior combined-branch audit for FHIR-12173 already recorded the optionExclusive source move and noted FHIR-19377 as the later modifier-status change.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. Reintroducing or editing these StructureDefinitions in core would duplicate artifacts now maintained in the Extension Pack, and the maintained Extension Pack definitions already reflect the FHIR-19377 decision by not marking either extension as a modifier.

Recommendation:
Keep this external-repo audit commit as-is. No follow-up source change is needed in core or in the current Extension Pack for FHIR-19377; future maintenance of questionnaire-optionExclusive or questionnaire-usageMode should happen in the FHIR Extension Pack rather than by recreating core StructureDefinition source.
