FHIR-27791: Audit MedicationRequest status guidance placement

Issue request:
FHIR-27791 is Published/Persuasive for R5. It asked Pharmacy to remove the clinical decision support guidance from the entered-in-error code in the MedicationRequest.status value set and instead add that guidance to the MedicationRequest.status element comment.

Initial application:
Jira records CI commit 400a4e8622a88cc7e168c93ee7c5fe0e0c36a057. Its underlying commit 7e6805e893172aefeef818dc5a743e1d6bbeb71e changed the then-authoritative MedicationRequest spreadsheet so the status element comment included the clinical decision support sentence. The current source was later split/refactored, but the requested text is still present on MedicationRequest.status in source/medicationrequest/structuredefinition-MedicationRequest.xml.

Additional context:
MedicationRequest is active in source/fhir.ini, and the current ValueSet is a compose-only wrapper around the MedicationRequest status CodeSystem. The current entered-in-error code definition has no clinical decision support usage note; a later Pharmacy issue, FHIR-54903, further simplified it to "The request was entered in error and is not valid." FHIR-27753 and its linked Zulip thread explain the same 2020 problem as usage notes being embedded in the entered-in-error definition. FHIR-32859 later updated adjacent status wording from prescription/order to request and is already represented on the combined branch.

AutoFHIR reconciliation:
No source change was made. The combined branch already has the FHIR-27791 guidance at MedicationRequest.status, not on the entered-in-error code definition or the ValueSet page source, so an empty audit commit is the correct reconciliation.

Recommendation:
Keep this audit commit as-is. FHIR-27791 needs no further core source work; future edits to MedicationRequest entered-in-error definitions should be handled under the later dedicated status-definition issues rather than by re-opening this wording-placement change.
