FHIR-20554 was a Published/Persuasive FHIR-core OO change request to define a SpecimenDefinition $apply operation that instantiates a Specimen from a SpecimenDefinition, with a Specimen return parameter and example request/response context.

Initial application:
The issue was pre-applied by git commit 8cdd5414a8, which added the $apply request/response example files and operation rows to the then-current SpecimenDefinition spreadsheet. The later source rework commit 33b409a4b6 materialized that spreadsheet content as source/specimendefinition/operationdefinition-SpecimenDefinition-apply.xml and initially listed OperationDefinition/SpecimenDefinition-apply in list-SpecimenDefinition-operations.xml.

Additional context:
SpecimenDefinition remains an active core resource, but current R6 source no longer lists SpecimenDefinition.$apply on the core SpecimenDefinition operations list. OO minutes on 2025-09-25 record a motion to move Observation $stats and SpecimenDefinition $apply to the FHIR-I API Incubator IG, and current ballot-intro text lists SpecimenDefinition.$apply among artifacts moved out of the core specification. The API Incubator repository/link exists only as follow-up context at this point; public searches did not find a migrated OperationDefinition there yet.

AutoFHIR reconciliation:
This commit intentionally makes no source change in core. Re-adding SpecimenDefinition.$apply to the core operations list or editing its example text would conflict with the later OO move-to-incubator decision, and the remaining migration work belongs in the FHIR-I API Incubator rather than in this FHIR-core checkout.

Recommendation:
Keep this audit commit as an external-repo disposition for FHIR-20554. Do not restore the operation to core unless OO/FHIR-I reverses the 2025 move decision; instead, follow up in HL7/api-incubator-ig to migrate the OperationDefinition/examples and ensure the ballot-intro target URL resolves.
