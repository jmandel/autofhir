FHIR-8642: Audit Observation effective wording

Issue request:
FHIR-8642 was a Published/Persuasive OO change request from DSTU1 asking that Observation documentation stop referring to appliesDateTime or appliesPeriod after the Observation applies[x] element family had been renamed to effective.

Initial application:
There is no git commit explicitly tagged FHIR-8642. The rename itself was applied in git commit 4a0be4946472e6777340612d597280fb5fb968ad for FHIR-7636, changing Observation examples and spreadsheet references from applies/appliesDateTime to effective/effectiveDateTime. The later QA Observation commit ab0cdd500d54274bf95882abf5e84d0e8892cf6f changed the Observation notes section from appliesDateTime/appliesPeriod to effectiveDateTime/effectivePeriod, matching the FHIR-8642 Jira resolution that this was fixed as part of editor QA.

Additional context:
Observation is an active resource in source/fhir.ini, and the current authoritative Observation source defines Observation.effective[x] with dateTime, Period, Timing, and instant choices. Current source/observation and source/diagnosticreport have no appliesDateTime, appliesPeriod, or Observation.applies[x] hits. A repository-wide current-source search still finds appliesDateTime/appliesPeriod in source/library/library-quick-model-definition-content.xml, but that file is the Library resource's QUICK model information example, not the authoritative FHIR Observation resource documentation; the parallel FHIR model definition example represents Observation with the effective choice element.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope Observation documentation and structure definition already use effectiveDateTime/effectivePeriod/effective[x], and changing the QUICK model example would go beyond this Observation documentation issue and could alter an external model snapshot rather than the FHIR Observation definition.

Recommendation:
Keep this audit commit as-is for FHIR-8642. If the Library QUICK example is still considered current and not merely historical/example content, review it separately with the Clinical Reasoning/CQL owners rather than treating it as part of this Observation documentation cleanup.
