FHIR-6189: Audit profile differential rendering

Issue request:
FHIR-6189 was a Published FHIR-core change request asking that the profile differential view show only what is different and remove unchanged material. The final Persuasive with Modification resolution said this had largely been done, while preserving editor discretion over what a differential view should show.

Initial application:
No Jira-tagged FHIR-6189 implementation commit was found in the current repository history. The current source reflects the issue family through the profile presentation machinery and profiling documentation: profile pages render a separate Differential View from a differential-specific table token, and the profiling page defines differentials as sparse statements of differences while allowing contextual information not in the differential to be shown partially transparent.

Additional context:
The Jira comments tied the concern to CDA R2 profiles and FHIR-6190. Current build scope no longer includes the old CDA profile because source/fhir.ini comments out the cda profile entry, while profilelist.html remains an active hierarchy page. Later Zulip discussion about unchanged content in differential renderings confirms the current nuance: consumers often want only changes, but authoring and rendering sometimes need repeated or contextual content, and automatically distinguishing all unchanged content is not always safe.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current core source already conveys that differentials describe differences, the current profile template separates Differential View from Full Structure, and the remaining contextual-display behavior is explicitly permitted by the accepted modification rather than a defect needing removal.

Recommendation:
Keep this audit as-is. Do not add redundant profilelist prose or remove contextual differential rendering from core based on FHIR-6189 alone; any stricter rule that profile differentials or rendered differential tables must contain only semantically changed content would need a new tooling/work-group decision, especially for IG Publisher behavior outside this core source checkout.
