FHIR-43566: Audit Permission import outside core

Issue request:
FHIR-43566 was an Applied/Persuasive with Modification Security issue for R6 asking for Permission to reference an overarching Permission so chained policies can be modeled. The approved resolution was to add Permission.rule.import, add an invariant preventing a rule from mixing import with local rule content, add Composite Permissions explanatory notes, and add examples.

Initial application:
The application was made through HL7/fhir PR #3248, which explicitly lists FHIR-43566 and was merged on 2025-03-05. Local history shows commit c1a3df664d5c79f9882ba8d15e9734a6c5caa1e0 added Permission.rule.import, the rule constraint, composite Permission notes, and base/composite examples under source/permission while Permission was still an active core resource; later PR/build-cleanup commits added invariant tests and retained the same feature.

Additional context:
Permission is no longer an active resource in the current core build. Commit 0e2a8a7f839d5e1a43787523daccf07d958362f3 removed source/permission and the active source/fhir.ini Permission entries, and current core Security/history pages link Permission to the HL7 Data Access Policies IG. The current HL7/data-access-policies source contains Permission.rule.import, the prm-1 invariant, Composite Permissions notes, and base/composite examples. A prior combined-branch audit for FHIR-43583 records the same Permission move-out-of-core context but did not audit FHIR-43566.
