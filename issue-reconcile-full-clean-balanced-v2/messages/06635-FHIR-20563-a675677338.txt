FHIR-20563: Align request status wording

Issue request:
FHIR-20563 was Published/Persuasive for R5 and asked that ServiceRequest.status and parallel request resources stop referring to non-current RequestStatus codes such as cancelled and suspended, use revoked and on-hold instead, and correct the RequestStatus entered-in-error definition so it refers to revoked.

Initial application:
Most of the issue had already been applied before this reconciliation. Historical commit 2ed04c432f updated the active Request pattern status list for FHIR-26677, and Jira's FHIR-20563 application comment points to commit 75420937b4, which changed ServiceRequest.status and DeviceRequest.status comments from cancelled/suspended wording to revoked/on-hold wording. The current RequestStatus CodeSystem already defines entered-in-error using revoked rather than cancelled.

Additional context:
source/fhir.ini lists request as an active logical pattern and lists ServiceRequest, DeviceRequest, CarePlan, CommunicationRequest, and NutritionOrder as active resources. Later FHIR-48861 added the higher-level ended RequestStatus parent for completed/revoked, so code-list descriptions now need to include ended to stay aligned with the current RequestStatus value set. RequestGroup is now RequestOrchestration, whose current status definition and search parameter description do not carry the stale cancelled/suspended code list. FHIR-54624 later addressed ServiceRequest.statusReason wording, but it remains Resolved - change required rather than Published/Applied and was not decided here. Stale _pattern snapshots in request-mapping-exceptions files and CarePlan activity/status-reason text were left alone because they are not the authoritative Request.status surfaces for this issue and some refer to different status concepts or terminology mappings.

AutoFHIR reconciliation:
This commit updates the active Request pattern spreadsheet and narrative notes so Request.status/statusReason prose uses on-hold and revoked instead of suspended and cancelled. It also updates the status SearchParameter descriptions for ServiceRequest, DeviceRequest, CarePlan, and CommunicationRequest to match the current Request.status short list, including the later ended parent. NutritionOrder and RequestOrchestration search parameter descriptions were already generic rather than stale code lists, so no source change was needed there.

Recommendation:
Keep this source fix as the FHIR-20563 reconciliation. Future FHIR-48861 or search-parameter cleanup can decide whether every request-derived status SearchParameter should use exhaustive code-list descriptions, but this commit fixes the stale cancelled/suspended references and aligns the affected active request-status descriptions with the current RequestStatus codes.
