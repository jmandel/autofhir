FHIR-17508: Audit OperationDefinition parameter reference expectations

Issue request:
FHIR-17508 was Published/Persuasive and asked to add an OperationDefinition.parameter child allowing an operation definition to state that another resource parameter is expected to reference this resource parameter. The requested shape was a 0..* backbone element with source and element-id details.

Initial application:
The issue was applied in git commit 34238bffe3 (svn revision 14221), which added OperationDefinition.parameter.referencedFrom, referencedFrom.source, and referencedFrom.sourceElement to the legacy OperationDefinition spreadsheet. That implementation preserved the requested semantics while using the name referencedFrom instead of references.

Additional context:
OperationDefinition is an active resource in source/fhir.ini and current source/operationdefinition/structuredefinition-OperationDefinition.xml contains OperationDefinition.parameter.referencedFrom with the expected cardinalities, definitions, and comment. A later emergent discussion and commit d3597eda7d renamed sourceElement to sourceId to avoid implementation-generator collisions with xElement fields; this is a naming refinement, not a reversal. FHIR-17509 is the paired Parameters-resource clarification and current Parameters source also points implementers to OperationDefinition for inter-parameter reference resolution.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current source already expresses the substantive requirement from FHIR-17508, and the only notable wording/name difference is accounted for by the later sourceId rename.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-17508 unless the work group wants new examples or additional guidance beyond the original applied structural elements.
