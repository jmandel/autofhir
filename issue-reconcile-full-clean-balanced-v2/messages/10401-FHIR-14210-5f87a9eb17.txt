FHIR-14210: Audit JSON Schema ResourceList repair

Issue request:
FHIR-14210 was a Published/Persuasive FHIR-core STU3 change request, auto-approved after a Jira description pointing to the community.fhir.org "FHIR JSON schema not valid" report. The forum report said a contained Practitioner matched multiple ResourceList oneOf branches in generated JSON Schema because abstract/base schemas such as DomainResource and Resource were present and permissive, and suggested removing DomainResource, Parameters, and Resource from ResourceList.

Initial application:
No commit explicitly mentions FHIR-14210. Jira records Grahame Grieve's 2018-08-16 comment that the issue had already been done. The relevant implicit source history is the January 2018 JSON Schema generator repair trail: commit 4757010487355c7ad9910dc788395f5a1d37d167 added required resourceType constraints, additionalProperties false, inherited property handling, and concrete-resource-only ResourceList generation; commit 05bfe5879059bdbd9f7dee5594f67ec819c8c85e followed with SchemaGenerator, library, downloads, and per-resource schema-page updates.

Additional context:
The old in-repository Java SchemaGenerator was removed in 2021 when the build switched to the Gradle Kindling dependency, so there is no current checked-in generator hunk to repair in this core checkout. Current build-scoped source still links the generated fhir.schema.json.zip from downloads.html and validation.html. The current build.fhir.org fhir.schema.json.zip contains a single combined schema whose ResourceList has no Resource or DomainResource abstract entries or definitions, includes Parameters as a concrete resource only once, and constrains resourceType with const values. The later, closely related FHIR-17696 ResourceList issue is already represented on the combined branch with an empty audit commit reaching the same no-change conclusion for the STU3 ResourceList ambiguity.

AutoFHIR reconciliation:
This is an empty no-change audit commit. The current source already points to the generated JSON Schema artifact, the current generated artifact no longer exhibits the abstract Resource/DomainResource oneOf ambiguity reported by FHIR-14210, and editing generated schema output or redundant narrative in core would not be a correct current-source fix.

Recommendation:
Keep this commit as-is. If a future JSON Schema ResourceList defect is found, investigate the current Kindling/publisher generator and generated artifact pipeline; no FHIR core source edit is needed for FHIR-14210 now.
