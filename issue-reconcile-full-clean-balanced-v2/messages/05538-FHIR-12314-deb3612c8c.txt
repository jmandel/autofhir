FHIR-12314: Audit ConceptMap optional scopes

Issue request:
FHIR-12314 was a Published/Persuasive DSTU2 vocabulary issue requesting that ConceptMap.source and ConceptMap.target be relaxed from mandatory 1..1 cardinalities because $closure initialization returns an empty ConceptMap with no meaningful source or target value set.

Initial application:
The issue appears to have been applied as svn r10151, preserved in git commit dbe68561c0544, which changed the old ConceptMap spreadsheet entries for ConceptMap.source[x] and ConceptMap.target[x] from 1..1 to 0..1 and added text explaining that a map can lack specified source/target context. That spreadsheet has since been superseded by the current StructureDefinition source.

Additional context:
ConceptMap is active in the current build through source/fhir.ini. Later R5/R6 work renamed ConceptMap.source[x] and ConceptMap.target[x] to sourceScope[x] and targetScope[x], and the active source keeps both elements at 0..1 with comments saying that when neither scope is specified, the map has no specified context. The $closure operation that motivated the issue has since been removed from the active ConceptMap operation list, leaving only $translate. A later Published issue, FHIR-14710, reconsidered ConceptMap source/target mandatory cardinalities and explicitly preserved the FHIR-12314 optionality for $closure initiation; that issue is already represented on the combined branch.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current active ConceptMap StructureDefinition already carries forward the requested 0..1 cardinalities, and there is no active $closure operation source that still needs a matching initialization example or operation-definition update.

Recommendation:
Keep this no-change audit. Future changes should only revisit these cardinalities if the Terminology Infrastructure WG makes a new decision about when ConceptMap scopes or group systems must be present; FHIR-12314 itself is already reflected in the current source.
