FHIR-39112: Audit Observation valueReference history

Issue request:
FHIR-39112 was a Published/Persuasive R5 OO change request asking for Reference to be allowed as a value data type on Observation.value[x] and Observation.component.value[x], with genomics use cases for referencing a Medication from a component and a MolecularSequence as an observed value.

Initial application:
OO minutes accepted the issue on 2023-02-02 and noted it was related to another ticket already allowing the type on Observation.value. Jira says it was applied through PR 2610 commit c09d2d2, although that specific commit only adjusted an Observation component-value-canonical search parameter. The substantive source application was the same-change-family FHIR-40292 commit 398f753, which added Reference(MolecularSequence) and canonical to both Observation.value[x] and Observation.component.value[x], plus related valueReference/valueCanonical comments/search-parameter work. The later R5 urgent correction FHIR-40560, applied by 3223f3d, removed canonical and restored string while retaining the restricted Reference(MolecularSequence) choice for both elements.

Additional context:
The current build scope still includes Observation as an active resource in source/fhir.ini. Current source/observation/structuredefinition-Observation.xml lists Quantity, CodeableConcept, string, boolean, integer, Range, Ratio, SampledData, time, dateTime, Period, and Attachment for both Observation.value[x] and Observation.component.value[x]; it does not list Reference or canonical. Current source/observation/bundle-Observation-search-params.xml likewise has no value-reference, component-value-reference, value-canonical, or component-value-canonical search parameters. The removal is not an accidental omission: FHIR-53610 and commit c552723 removed Observation.valueReference/Observation.component.valueReference and their search parameters as orphaned after the MolecularSequence/MolecularDefinition work moved out of core. A 2025 genomics Zulip thread shows the community was still debating the right R6 modeling path and the impact of valueReference(MolecularDefinition), rather than reaffirming the broad Reference request from FHIR-39112.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding Reference for FHIR-39112 would conflict with the later R5 narrowing to Reference(MolecularSequence), the R5 removal of canonical, and the current R6 source removal of the remaining orphaned valueReference choices and search parameters.

Recommendation:
Keep this audit commit as-is for FHIR-39112. Do not use this R5 ballot issue to reintroduce Observation.valueReference or Observation.component.valueReference in the current build. If OO and Clinical Genomics want a new R6 mechanism such as Reference, CodeableReference, or an extension for MolecularDefinition/Medication-related use cases, that should be handled through a new or explicitly advanced current-cycle tracker; FHIR-53610's workflow status should also be brought into alignment with the already-applied source change.
