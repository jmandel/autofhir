FHIR-13125: Audit summary flag consistency

Issue request:
FHIR-13125 was a Published/Persuasive DSTU2 FHIR-core change request for CapabilityStatement (then Conformance), Consent, Encounter, and Observation elements whose parents were summary elements but whose required children were not marked isSummary. The accepted rule was that when minOccurs=1 and the element's parents are isSummary, the child must be isSummary, and the tooling should treat violations as errors.

Initial application:
The issue was applied in SVN/git-svn commit 0ad99fb844c59d64bf782e85eec2e491813f84c5, which explicitly references #13125, changed the listed resource spreadsheet inputs, made CapabilityStatement.rest.resource.interaction optional for summary responses, added summary flags to required summary descendants such as CapabilityStatement.messaging.event.mode/focus and CapabilityStatement.document.mode, added Encounter.diagnosis.condition to summary, and added a ResourceValidator error for required elements under summary parents. The same history also shows FHIR-13124 as the companion issue that removed inappropriate descendant summary flags from Questionnaire.item children.

Additional context:
The current build-scope authority, source/fhir.ini, lists CapabilityStatement, Consent, Encounter, Observation, and Questionnaire as active resources. In the current XML StructureDefinition source, several DSTU2/STU3 paths have been renamed or remodeled: CapabilityStatement.messaging.event became messaging.supportedMessage, Consent.actor/except.actor became provision.actor and is no longer summary, Observation.related.target became hasMember/derivedFrom, and Questionnaire.item.enableWhen remains outside summary because Questionnaire.item is not summary. A current-source consistency scan of all 132 active resource StructureDefinition XML files found no cases where a min>0 element is missing isSummary while its immediate parent isSummary.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already satisfies the FHIR-13125 rule for the seed artifacts and active resource set; adding or removing summary flags now would either duplicate existing semantics or disturb later modeled changes.

Recommendation:
Keep this audit commit as-is. No core FHIR source follow-up is needed for FHIR-13125 unless future build tooling drops the equivalent summary/min consistency validation; FHIR-13124 remains useful background for the companion descendant-summary rule but is not independently decided by this commit.
