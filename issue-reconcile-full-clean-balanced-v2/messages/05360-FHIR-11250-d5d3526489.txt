FHIR-11250: Audit Endpoint connection type definition

Issue request:
FHIR-11250 was Published/Persuasive for DSTU2 by Patient Administration. It asked to update Endpoint.connectionType's definition and value set so the element represented the protocol/profile/standard used with an endpoint connection, with examples such as DICOM WADO-RS, DICOM QIDO-RS, IHE-XDS, IHE-XDR, IHE-XCA, and Direct.

Initial application:
No local git commit explicitly names FHIR-11250. The apparent initial application is git commit 3e7c097adea104fa3f766d892afffaaf65f6f0db, "Updates to the Endpoint resource based on ballot feedback/connectathon results", which changed Endpoint.connectionType from the old SubscriptionChannelType/rest-hook style binding to endpoint-contype, changed the short label to "Protocol/Profile/Standard to be used with this endpoint connection", added the technical-details definition, and introduced an Endpoint connection-type code system/value set with IHE, DICOM, FHIR, HL7v2, and secure-email codes. Later FHIR-12364 added the more specific direct-project code and Direct example.

Additional context:
Endpoint is active in source/fhir.ini, and the current build source keeps Endpoint.connectionType as a required, repeatable CodeableConcept with an example binding to ValueSet/endpoint-connection-type. The current ValueSet delegates the code list to the THO endpoint-connection-type CodeSystem, which includes the high-level codes relevant to the seed, including DICOM, IHE, Direct, FHIR REST/messaging, HL7v2 MLLP, secure-email, and later cds-hooks-service. Later already-audited Endpoint decisions refine the same family: FHIR-12342 and FHIR-34261 made connectionType repeatable, FHIR-36589 changed it to CodeableConcept/example binding and added IHE mCSD context, FHIR-12364 added direct-project, and FHIR-36327 declined making connectionType optional.

AutoFHIR reconciliation:
This commit makes no source change. The active current source already conveys the FHIR-11250 concept through the Endpoint.connectionType short/definition, the Endpoint value set binding, and the THO-backed code list; later Endpoint decisions explain the current CodeableConcept/example-binding and IHE external-vocabulary shape.

Recommendation:
Keep this no-change audit commit as-is. Future changes to individual connection-type codes should usually be handled through THO/UTG or the owning external vocabulary such as IHE mCSD, while core Endpoint source should continue to bind to the example endpoint-connection-type ValueSet unless a later PA decision changes that model.
