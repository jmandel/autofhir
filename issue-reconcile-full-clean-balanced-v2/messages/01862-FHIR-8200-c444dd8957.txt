FHIR-8200: Audit modifier cardinality guidance

Issue request:
FHIR-8200 was a Published/Persuasive with Modification MnM issue raised against DSTU1 AllergyIntolerance. It asked whether AllergyIntolerance.status, then a 0..1 modifier element, should be required and what general FHIR policy should apply to modifier element cardinalities. The accepted resolution was that missing modifier values can make a resource unreliable, so modifier elements SHOULD have minimum cardinality 1 or equivalent certainty wherever possible, but FHIR would not impose that as a universal SHALL because legacy data is often incomplete; producers SHOULD still provide appropriate modifier values, and the narrative-summary sentence should stand separately.

Initial application:
The issue was applied in git commit 2938f7d8f8e22e92939f7f8e65fb047cc6391cd9, the import of svn revision 5934 cited in Jira. That commit changed source/conformance-rules.html by replacing the stricter old paragraph with the nuanced FHIR-8200 language, split the narrative-summary requirement into its own paragraph, and lowered the producer obligation from SHALL to SHOULD.

Additional context:
The latest combined branch still carries the FHIR-8200 guidance in the active Conformance Rules page, which is linked from source/documentation.html and other current pages. Later source history explains the differences from the original resolution text: default-value wording was removed when FHIR stopped allowing defaultValue[x] for FHIR resources, and FHIR-17688 plus the linked Zulip discussion qualified the narrative-summary requirement for generated vs. other narratives. The AllergyIntolerance-specific concern was also revisited by later Patient Care issues: FHIR-10642 and FHIR-11151 split the old status into clinicalStatus and verificationStatus, while FHIR-25514 and FHIR-28458 later removed overly strict clinicalStatus invariants and added guidance for negated/refuted allergy records. Those later decisions mean the current optional AllergyIntolerance modifier elements are not evidence that FHIR-8200 is missing a cardinality edit.

AutoFHIR reconciliation:
This empty commit intentionally makes no source change. The current core source already conveys FHIR-8200's policy: modifier elements should be required where possible, missing modifier values can make safe interpretation impossible, producers SHOULD provide modifier values, and narrative handling is separately governed by the later clarified narrative rule. Re-adding the removed default-value phrase or making AllergyIntolerance modifier elements universally mandatory would conflict with later applied decisions.

Recommendation:
Keep this no-change audit as-is for FHIR-8200. If future review wants to revisit AllergyIntolerance clinicalStatus or verificationStatus cardinalities, handle that under the later AllergyIntolerance-specific trackers rather than reopening the broad FHIR-8200 methodology decision.
