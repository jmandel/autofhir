FHIR-50073: Correct HealthcareService offeredIn schedulable wording

Issue request:
FHIR-50073 was Applied/Persuasive with Modification for HealthcareService. It asked to clarify that HealthcareService can describe a single located healthcare service or a category of services at an organization/location, distinguish generic categories such as Radiology from directly schedulable services such as CT Scan, remove or condense confusing examples, update the catalog use case, and create a standard HealthcareService schedulable extension.

Initial application:
Core commit f069f1b7000dabc2e6cf6f6e023f59b5c9613ef9 already updated source/healthcareservice/healthcareservice-introduction.xml with the requested scope, examples, and catalog wording. The related extension-pack commit 0289b1c2ff9b7de7aa41ae927fb0dbb23328f764 added StructureDefinition/healthcareservice-schedulable with HealthcareService context and boolean value. HealthcareService is an active current-build resource in source/fhir.ini.

Additional context:
The linked and Published FHIR-22687 change added HealthcareService.offeredIn to represent the relationship between a specific schedulable service and a generic service. That existing definition still named a nonexistent availableIn property even though the element is HealthcareService.offeredIn and the comment already uses offeredIn. PA minutes record the 6-0-0 motion for FHIR-50073, and Zulip searches found no directly relevant conflicting discussion.

AutoFHIR reconciliation:
Corrected the authoritative HealthcareService.offeredIn definition and the checked-in HealthcareService diagram tooltip from availableIn to offeredIn. No further core edit was needed for the already-applied introduction text or for the standard schedulable extension, which is maintained in the FHIR Extension Pack checkout.

Recommendation:
Keep this commit as-is. The remaining core source now consistently names offeredIn for the generic-versus-schedulable HealthcareService relationship, while the FHIR-50073 introduction wording and extension-pack schedulable extension already match the applied Jira decision.
