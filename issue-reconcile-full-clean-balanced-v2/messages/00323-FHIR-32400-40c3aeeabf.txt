FHIR-32400: Audit MessageHeader enterer removal

Issue request:
FHIR-32400 was a Published/Persuasive FHIR-core MessageHeader change request raised against R4 and applied for R5. It asked for clearer guidance for MessageHeader.enterer because data-entry responsibility for message payload resources should live on those resources or associated Provenance, not on a transient MessageHeader; the final resolution was to remove enterer and add guidance proposing removal of sender, responsible, and author in favor of Task where persistent context is needed.

Initial application:
The issue appears to have been applied by git commit 7345c2bfebc9aab9e2a16611cb94df91710a9e9a, which removed the MessageHeader.enterer differential element from source/messageheader/structuredefinition-MessageHeader.xml, removed enterer from the active source/messageheader/messageheader-example.xml example, and added Task-removal proposal comments to the neighboring sender, author, and responsible elements. That commit was labelled for FHIR-34096, but its MessageHeader.enterer and Task-comment changes match the FHIR-32400 Jira resolution.

Additional context:
Later MessageHeader decisions refined the same area: FHIR-41271 clarified that MessageHeader is needed to interpret a message bundle but should not provide persistent context after resources are processed elsewhere; FHIR-32403 and FHIR-41269 later moved sender under source and removed author/responsible; FHIR-45997 then removed notes referring to the deleted enterer/author/responsible elements. source/fhir.ini actively includes MessageHeader in the build and records legacy mappings that drop MessageHeader.enterer, author, and responsible while redirecting sender to MessageHeader.source.sender. A source search found one remaining enterer occurrence only in source/messageheader/message-header-example.xml, a legacy Bundle example that is not named by list-MessageHeader-examples.xml and is not referenced elsewhere in source.

AutoFHIR reconciliation:
No source change was made for FHIR-32400. The authoritative current MessageHeader StructureDefinition contains no MessageHeader.enterer element, the active MessageHeader example listed for the resource contains no enterer, and the remaining enterer text is outside the current build-scope evidence for MessageHeader examples.

Recommendation:
Keep this audit commit as-is for FHIR-32400. Do not reintroduce local MessageHeader.enterer guidance; persistent authorship, responsibility, and data-entry context should remain on the relevant payload/provenance/workflow resources. Any cleanup of unreferenced legacy example files should be handled separately from this issue reconciliation.
