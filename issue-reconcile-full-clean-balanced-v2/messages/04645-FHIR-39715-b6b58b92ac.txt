FHIR-39715: Restore contained-resource XPath wildcards

Issue request:
FHIR-39715 was Published/Persuasive for R5 and reported that the contained-resource reference guidance XPath on references.html#contained tested Resource/@id instead of Resource/id/@value. The Jira resolution required changing the example to use f:id/@value; the later Jira comment explains that adding a FHIRPath example was not useful because resolve() hides those mechanics.

Initial application:
The issue was initially applied by commit 38aa93e3461d8c449438335c18a74054987993e1, which changed source/references.html from an @id predicate to f:id/@value. That commit also accidentally removed the wildcard node tests after f: and f:contained/, leaving the current XPath fragment syntactically wrong as ancestor::f:[...] and f:contained/[...].

Additional context:
source/fhir.ini maps the Reference datatype page to references, so source/references.html is an active source page for the current build. The Reference datatype invariant already uses the corrected f:id/@value form for local contained references. The Zulip thread that led to the Jira confirms the reporter was focusing on contained-resource id resolution, and FHIR-I minutes record the Persuasive vote for FHIR-39715.

AutoFHIR reconciliation:
This commit restores the two wildcard steps in source/references.html while preserving the previously applied f:id/@value predicate and not adding redundant FHIRPath prose.

Recommendation:
Keep this commit as-is. It completes the intended FHIR-39715 correction in the current active references page without changing the surrounding contained-resource semantics.
