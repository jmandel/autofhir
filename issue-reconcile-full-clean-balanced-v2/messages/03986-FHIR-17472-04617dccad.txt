FHIR-17472: Audit Patient contact relationship value set

Issue request:
FHIR-17472 was Published/Persuasive for STU3 and asked for Patient.contact.relationship, then described in the tracker as Patient.contact.role, to stop using the full v2-0131 contact role value set with an extensible binding. The approved resolution was to define a FHIR value set that includes the v2-0131 codes except the "other" concept and bind it to the patient contact relationship property.

Initial application:
The issue was applied before this reconciliation by git commit e9ce6c1043c051523fcbbc529aae0a0cf5c5a3e8, which changed the Patient ContactRelationship binding from http://terminology.hl7.org/ValueSet/v2-0131 to valueset-patient-contactrelationship and added source/patient/valueset-patient-contactrelationship.xml. The current value set source still filters http://terminology.hl7.org/CodeSystem/v2-0131 with concept is-not-a O, so the original v2-minus-other application remains present.

Additional context:
Patient is an active resource in source/fhir.ini, so source/patient/structuredefinition-Patient.xml and adjacent patient value-set XML are in the current build scope. Later Applied/Persuasive-with-Modification issue FHIR-15841 deliberately split Patient.contact.relationship from a new Patient.contact.role, changed Patient.contact.relationship to a preferred binding on v3-PersonalRelationshipRoleType, and added Patient.contact.role with a preferred binding on relatedperson-relationshiptype. That later model no longer uses the FHIR-17472 extensible v2-minus-other binding as the current Patient contact binding target. The checked-in patient.svg still mentions PatientContactRelationship/Extensible, but that is a generated-looking diagram artifact and the authoritative StructureDefinition XML carries the current bindings.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Rebinding the current Patient.contact.role back to patient-contactrelationship, or excluding v2-0131 O from the current preferred role value set for this old issue, would undo or narrow the later FHIR-15841 decision rather than complete FHIR-17472.

Recommendation:
Keep this empty audit commit for FHIR-17472. If the work group wants the unused Patient Contact Relationship value set explicitly deprecated or generated Patient diagrams regenerated, handle that under FHIR-15841 or a follow-up tracker rather than changing the seed issue.
