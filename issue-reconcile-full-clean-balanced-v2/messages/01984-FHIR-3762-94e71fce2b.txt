FHIR-3762: Audit Immunization not-given rename

Issue request:
FHIR-3762 is a Published/Persuasive with Modification DSTU1 FHIR-core Immunization issue. It asked to replace refusal-specific Immunization names with broader not-given names because no-immunization-reason included non-refusal reasons, and it noted missing invariants that should prevent inconsistent not-given/reason/reaction combinations. The final resolution approved refusedIndicator -> wasNotGiven and refusalReason -> reasonNotGiven, left the value set name unchanged, requested description alignment with pharmacy wording, and referred the invariant work to FHIR-3758.

Initial application:
The source application was commit 64fbbf28ef27948a7944954073c8df878bac2bc9. Its subject explicitly includes #3762 and changes the Immunization refused example and spreadsheet from refusedIndicator/refusalReason to wasNotGiven/reasonNotGiven while also adding the FHIR-3758 invariants. source/history.html also records the release-note application of refusedIndicator -> wasNotGiven and refusalReason -> reasonNotGiven.

Additional context:
FHIR-5351 was a duplicate request for refusalReason -> reasonNotGiven and is already represented on the combined branch by Issue-Reconcile-Key FHIR-5351. Later Immunization history intentionally superseded the DSTU1 elements: commit 85a7ed8e28 renamed wasNotGiven to notGiven to align with pharmacy, commit 4c5a8902ab replaced the old completed + notGiven representation with status not-done and removed reasonNotGiven, and commit f451f3fc4b introduced Immunization.statusReason for the not-done reason. FHIR-9073 is already audited on the combined branch as the later issue documenting the R4 retirement of notGiven/notTaken in favor of not-done status. FHIR-54325 is already fixed on the combined branch and refines current statusReason wording and the imm-1 invariant for not-done or entered-in-error.

AutoFHIR reconciliation:
This is an empty no-change audit commit. The current active Immunization source no longer has refusedIndicator, refusalReason, wasNotGiven, reasonNotGiven, or notGiven element definitions. It represents non-administration using status = not-done and statusReason, with an invariant restricting statusReason to not-done or entered-in-error. Reintroducing the old DSTU1 element names or adding duplicate guidance would conflict with later source history and existing related reconciliations.

Recommendation:
Keep this audit commit as-is. Future Immunization non-administration changes should be handled under the current status/statusReason model or later statusReason issues, not by restoring the retired DSTU1 wasNotGiven/reasonNotGiven representation.
