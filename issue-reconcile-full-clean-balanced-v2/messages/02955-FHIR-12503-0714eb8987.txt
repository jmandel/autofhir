FHIR-12503: Audit Provenance entity logical references

Issue request:
FHIR-12503 was a Published Security work group change request, resolved Persuasive with Modification for DSTU2, asking Provenance.entity.reference to support non-FHIR content; the recorded resolution was to add an Identifier element to entity.

Initial application:
The issue appears to have been applied in git commit 8058a0886c12cc7a61a61db3edae51be5e5698ef, whose subject names GF#12503 and changes Provenance.entity.reference into Provenance.entity.what[x] with uri, Reference(Any), and Identifier choices, plus example updates using whatIdentifier.

Additional context:
Later final decisions changed the interpretation. FHIR-13694 clarified Reference.identifier logical references, FHIR-13570 tied Provenance.entity.what guidance to that clarification, and FHIR-15659 explicitly found Provenance whatIdentifier/whatReference redundant after logical references and was implemented by commit 6c0a0563b3ac6a188b713f2f1a04ff26229100cf. FHIR-49893 later corrected the current Provenance.entity.what comment to say what.identifier.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Provenance is active in source/fhir.ini, current source/provenance/structuredefinition-Provenance.xml defines Provenance.entity.what as Reference(Resource) and tells readers to use what.identifier for entities that are not a Resource type, while source/datatypes/reference.xml and source/references.html define Reference.identifier logical references as usable when no FHIR representation exists for a Reference(Any) target. The older direct Identifier choice requested by FHIR-12503 was therefore superseded intentionally rather than accidentally dropped.

Recommendation:
Keep this audit commit as-is. Re-adding a direct Provenance.entity identifier choice would conflict with the later Published simplification decisions; any future change should be raised as a new Security/MnM decision about Reference.identifier semantics, not as a FHIR-12503 fixup.
