FHIR-31062: Audit financial event dates backbone

Issue request:
FHIR-31062 was Published/Persuasive with Modification for R5. The original request proposed a reusable "Dates" backbone for Claim, ClaimResponse, CoverageEligibilityRequest, CoverageEligibilityResponse, and ExplanationOfBenefit, with type 1..1 CodeableConcept and when 1..1 date-or-Period, and suggested it could replace CoverageEligibility serviced[x] and Claim/EOB billablePeriod. The final resolution narrowed this to creating a 0..* dates-style backbone, left the final element name open, and stated it would not be used for line-item service dates or periods.

Initial application:
The issue was applied by commit 7b44f67dce, merged by PR #2735 as a04d004d1f, which added an event backbone to all five listed active financial resources and added the datestype terminology. The current source still contains those event elements and the terminology. The current source also retains Claim.billablePeriod, ExplanationOfBenefit.billablePeriod, and CoverageEligibilityRequest/Response.serviced[x]; because the issue was Published after the explicit FHIR-31062 implementation and the final resolution was a modification, this audit treats those retained specific elements as part of the applied outcome rather than as a missing reconciliation fix.

Additional context:
The five resources are active in source/fhir.ini. Later final work, including FHIR-53057, changed some financial bindings such as CoverageEligibilityResponse.event.type to preferred, so exact binding strength is governed by later applied decisions where applicable. FHIR-50910 proposes moving datestype to THO and changing the binding, but it remains Triaged/In Progress and is not a final source-edit decision for this default run. No relevant Zulip or Confluence record was found that contradicts the Jira/source/git conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source already conveys the accepted backbone under the final chosen name, event, with a 0..* BackboneElement, 1..1 CodeableConcept type, and 1..1 when[x] dateTime-or-Period in each requested resource. Removing the older specific date elements now would be a breaking structural change broader than the published FHIR-31062 application and unsupported by any discovered later final decision.

Recommendation:
Keep this empty audit commit as-is. If the Financial Management work group still wants billablePeriod or serviced[x] removed, that should be handled through a new explicit applied tracker because it would require coordinated structure, examples, model-definition, and migration updates beyond this published issue's demonstrated application.
