FHIR-22629: Audit Endpoint payload type optionality

Issue request:
FHIR-22629 is a Published/Persuasive FHIR-core Patient Administration change request for Endpoint, raised in STU3 and applied for R5. It asked that Endpoint.payloadType not be mandatory because FHIR REST and messaging endpoints can rely on dynamic capability mechanisms and may have no appropriate payload type value; the final resolution was to relax payload type cardinality from 1..* to 0..* while allowing jurisdictions or projects to profile it as mandatory.

Initial application:
No standalone source commit specifically for FHIR-22629 was found. The requested cardinality relaxation was applied as part of the broader Endpoint cardinality work: commit 445d4741d1559c197decca8343f60d1cad753d36 changed the then-current Endpoint.payloadType minimum from 1 to 0, and merge commit 29c32a3f611f298e0601cd090b441155fed47286 explicitly lists FHIR-22629 among the Endpoint cardinality trackers addressed by PR #1832.

Additional context:
Endpoint is active in source/fhir.ini, so source/endpoint feeds the current build. The historical Endpoint.payloadType element has since been refactored to Endpoint.payload.type, with source/fhir.ini mapping Endpoint.payloadType to Endpoint.payload.type for compatibility/renaming. Related Endpoint payload cardinality trackers, including FHIR-34261 and FHIR-25393, are already represented on the combined branch and support the same 0..* payload type outcome. Later Endpoint payload refactors and clarifications did not restore a mandatory payload type.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active authoritative source already defines Endpoint.payload.type with min 0 and max *, which satisfies FHIR-22629 after the current Endpoint.payload grouping/refactor.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-22629 unless a future Patient Administration decision intentionally changes the Endpoint payload advertising model or makes payload type mandatory again.
