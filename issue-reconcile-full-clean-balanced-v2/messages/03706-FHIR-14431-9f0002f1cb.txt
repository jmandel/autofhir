FHIR-14431: Audit Pharmacy example coverage

Issue request:
FHIR-14431 was a Published/Persuasive STU3 FHIR-core Pharmacy umbrella change request to fix examples in Pharmacy resources so QA could find values for all attributes. The concrete warning list named Medication.status and the Medication.status search parameter, MedicationAdministration.instantiates, MedicationDispense.location, MedicationDispense.performer.function, MedicationRequest.instantiates, MedicationRequest.insurance, MedicationRequest.performerType, MedicationRequest.statusReason, and the MedicationRequest.intended-performertype search parameter.

Initial application:
The Jira comment says the example updates were applied to the build in git-svn commit 6a66821c691aae27795820aa49a7da81cabedf82. That commit is present in current history and added Medication.status to medicationexample0301.xml, MedicationAdministration.instantiates to medicationadministration0305.xml, MedicationDispense.location to medicationdispense0301.xml, MedicationDispense.performer.function to medicationdispense0302.xml, and MedicationRequest performerType, statusReason, insurance, dispenseRequest.performer, and instantiates values to MedicationRequest examples. The same commit explicitly named companion trackers FHIR-14524 through FHIR-14528.

Additional context:
The current build still lists Medication, MedicationAdministration, MedicationDispense, MedicationRequest, and MedicationStatement as active resources in source/fhir.ini. The current source retains the applicable Medication.status, MedicationDispense.location, MedicationDispense.performer.function, MedicationRequest.statusReason, MedicationRequest.performerType, MedicationRequest.insurance, and renamed MedicationRequest.dispenseRequest.dispenser example coverage. MedicationAdministration.instantiates and MedicationRequest.instantiatesCanonical/instantiatesUri are no longer current model elements: source/fhir.ini records them as removed and the current StructureDefinitions no longer define corresponding elements. The same-family audit commits for FHIR-14524, FHIR-14525, FHIR-14526, FHIR-14527, and FHIR-14528 are already on the combined branch. Direct Zulip and Confluence searches found no conflicting community decision for the umbrella issue.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The build-scope example source already contains the still-current values from the 2018 application, and reintroducing removed instantiates elements or treating this STU3 QA cleanup as a mandate to populate every later optional R5/R6 Pharmacy element would over-read the issue.

Recommendation:
Keep this no-change audit commit as-is. If Pharmacy wants examples for later optional elements added after STU3, handle those with current, element-specific trackers rather than reopening this applied umbrella QA issue.
