FHIR-13787: Audit Bundle reference base wording

Issue request:
FHIR-13787 was a Published/Persuasive STU3 FHIR-I issue for FHIR-core-Feed. It reported that the Reference documentation incorrectly said a bundle relative URL was relative to Bundle.entry.fullUrl itself, and the approved resolution changed that text to say a reference in a bundle is relative to the base URL implied by Bundle.entry.fullUrl.

Initial application:
Jira records Grahame Grieve's application comment as svn revision 12792. Git history preserves that SVN import as commit b4ab76b58dbfe3f45bb5f3ca1b36ec6169973a43, with the message "#13787 = fix note about resolving references in a bundle" and the same source/references.html wording change requested by Jira.

Additional context:
The Reference page is active through source/fhir.ini's reference=references type-page mapping, and Bundle is an active resource in source/fhir.ini. The current Bundle reference-resolution notes explain how relative references are expanded from the root implied by Bundle.entry.fullUrl and when resolution expectations are undefined. Later fullUrl issue-family audits already on the combined branch, including FHIR-15139 and FHIR-16909, refined Bundle.entry.fullUrl URI/endpoint wording without reversing the FHIR-13787 base-URL clarification. A related Zulip thread discussed literal and relative reference ambiguity but did not identify a conflicting work-group decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source/references.html text exactly carries the Jira-approved correction: relative references are relative to the Service Base URL, or, when processing a resource from a bundle, to the base URL implied by Bundle.entry.fullUrl. The current combined branch has the same wording, so adding another prose edit would be redundant.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-13787 unless FHIR-I opens a later issue to change the broader reference-resolution model.
