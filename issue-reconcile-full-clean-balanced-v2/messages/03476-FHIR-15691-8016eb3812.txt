FHIR-15691: Audit Procedure directedBy extension location

Issue request:
FHIR-15691 was a Published/Persuasive Patient Care change request for the STU3 Procedure artifact. It asked for a 0..1 way to indicate whether an LTSS service was self-directed; the accepted resolution was to add a standard directedBy[x] extension with CodeableConcept or Reference(Patient | RelatedPerson | Practitioner | PractitionerRole), defined as the actor with decision-making authority and direct management responsibility for the service.

Initial application:
The request was applied in historical core source by 722ed5c93f, whose commit message explicitly includes GF#15691 and whose patch added the directedBy row to source/procedure/procedure-extensions-spreadsheet.xml. The generated pre-removal core extension definition later existed as source/procedure/structuredefinition-extension-procedure-directedBy.xml with Procedure context, the approved value[x] choices, and the LTSS comment.

Additional context:
FHIR-15692 is the paired ServiceRequest tracker for the same LTSS requirement and added ServiceRequest context to the same procedure-directedBy extension. FHIR-17543 later clarified that the extension target is distinct from the requester; that related issue is already represented on the combined branch by a19a0ac05f7e586e1b7bb3d734db41b66a450b37. Current core source still lists Procedure as an active approved resource and retains the procedure-directedBy OID, but the authoritative extension definition was removed from core during the R5 extension-source reorganization and now lives in the FHIR Extension Pack. The Extension Pack source currently contains the Procedure context, the ServiceRequest context, the approved value types, and the clarified decision-making-authority definition.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR core source change. The requested artifact was historically applied and is now maintained outside this core checkout; the current external source already carries the semantics requested by FHIR-15691, so reintroducing or editing a core extension definition would be the wrong build-scope fix.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed for FHIR-15691; any future changes to procedure-directedBy should be made in the FHIR Extension Pack, with Patient Care review if the extension scope or wording changes.
