FHIR-17990: Audit PaymentNotice descriptions

Issue request:
FHIR-17990 was Published/Persuasive for STU3 by FM and requested PaymentNotice long-description changes: change the old PaymentNotice.target description to "The party who is intended to receive the notice" and change the old PaymentNotice.provider description from practitioner-centered wording to provider-centered wording.

Initial application:
The Jira-tagged batch commit f369c813fb40cd39c0db46336b2b3186f496fb47 included GF#17990 and revised the PaymentNotice spreadsheet/example during the R3-to-R4 financial resource update. That application removed the old PaymentNotice.target element in favor of PaymentNotice.recipient, updated the example from target to recipient, and carried forward recipient wording as "The party who is notified of the payment status." The old provider element remained in R4/R4B with practitioner-centered short/definition wording, so the provider side of the original wording family was not fully reflected until later current-build work.

Additional context:
PaymentNotice is active in the current build. source/fhir.ini records the historical R3 rename PaymentNotice.target to PaymentNotice.recipient and the current R4-to-R6 rename PaymentNotice.provider to PaymentNotice.reporter. FHIR-40448 later made a final FM decision for R5 to rename PaymentNotice.provider to PaymentNotice.reporter and update its description; that decision has already been represented on the combined branch by the FHIR-40448 reconciliation commit, leaving the current source with reporter short "Entity reporting payment" and definition "The party who reports the payment notice." No Zulip or Confluence evidence was found that changes this source/history conclusion.

AutoFHIR reconciliation:
This audit commit makes no source change. The current authoritative source no longer has PaymentNotice.target and instead uses the mapped current PaymentNotice.recipient element with a recipient/notification definition that preserves the intended-notice-recipient meaning. The current authoritative source also no longer has PaymentNotice.provider and instead uses PaymentNotice.reporter with the later approved generic party/reporting wording, so changing it back toward the older provider wording would conflict with the later applied current-build decision.

Recommendation:
Keep this no-change audit commit. No further core FHIR source action is needed for FHIR-17990 unless FM wants a new current-version editorial issue to adjust PaymentNotice.recipient wording; FHIR-17990 itself should not be used to override the later reporter decision.
