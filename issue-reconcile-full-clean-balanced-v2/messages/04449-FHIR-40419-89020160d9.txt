FHIR-40419: Audit Identifier missing value guidance

Issue request:
FHIR-40419 was a Published FHIR-core/R5 datatypes change request resolved Persuasive with Modification. It asked for best-practice guidance or a warning-level FHIRPath expression when Identifier lacked system and value; the approved resolution narrowed this to a warning when Identifier.value is missing and a sentence explaining that the human-readable label for Identifier.value typically belongs in Identifier.type.text whether or not Identifier.system is known.

Initial application:
The issue was applied in git commit 342751f76e01b92363de3e8fedb4608ceef1797d, which changed source/datatypes.html and source/datatypes/identifier.xml. Current source still contains the Identifier.type.text guidance in the Identifier datatype narrative and the ident-1 warning invariant with expression value.exists().

Additional context:
The linked Zulip discussion shows why core could not require both system and value: Identifier is used in many contexts, including suppressed/redacted or server-generated values, and the agreed path was only a warning-level best-practice invariant. FHIR-I minutes for 2023-03-01 record the Persuasive with Modification vote 4-0-0. source/fhir.ini lists Identifier as an active datatype and normative, with datatypes as its default type page, so the checked files are in current build scope. Follow-up searches found no later core Jira decision or source history reversing the FHIR-40419 guidance.

This empty audit commit makes no source change because the current specification already contains the approved warning and narrative guidance.

Recommendation:
Keep this no-change audit commit as-is. No FHIR-core follow-up is needed for FHIR-40419 unless a future work group decision changes Identifier.value guidance.
