FHIR-18848: Audit FamilyMemberHistory birth sex binding

Issue request:
FHIR-18848 was a Published Patient Care change request raised against STU3 FamilyMemberHistory. It asked to replace the Birth Sex value set's administrative-gender male/female framing with a chromosomal-sex style XX/XY/other set. Patient Care's Persuasive with Modification resolution was narrower: keep administrative-gender and the male/female code displays for consistency with Patient.gender and FamilyMemberHistory.sex, but include other by removing the value set exclusion of administrative-gender#other.

Initial application:
The issue appears to have been applied in the STU3/R4-era FamilyMemberHistory spreadsheet work. Commit 04c4d675c5f4 included FHIR-18848 in the FamilyMemberHistory.sex binding change family, and commit 2bf5371d7642 changed the FamilyMemberHistory.sex short/description row to include other. Later FHIR-20393 commits corrected the binding URL so FamilyMemberHistory.sex points at the canonical administrative-gender value set rather than an unstable build URL.

Additional context:
The current source has FamilyMemberHistory active in source/fhir.ini and FamilyMemberHistory.sex is an extensible CodeableConcept binding to http://hl7.org/fhir/ValueSet/administrative-gender with the short list male | female | other | unknown. The old source/familymemberhistory/valueset-birth-sex.xml file still contains the original is-not-a other filter, but current source references to ValueSet/birth-sex are limited to that file and the OID registry, and the current build.fhir.org/hl7.org build surface has no valueset-birth-sex artifact. Related FHIR-19716 was resolved as a duplicate/no-change of this same decision not to switch away from administrative-gender, and later FHIR-43360 again left the element named sex while noting the extensible administrative-gender binding can carry other codes.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The active FamilyMemberHistory resource already conveys the approved result by allowing administrative-gender#other through the administrative-gender binding, and editing the unreferenced/out-of-build Birth Sex value set source would not be a current-spec fix.

Recommendation:
Keep this audit commit as-is. If maintainers want to remove or normalize orphaned historical source files such as valueset-birth-sex.xml, that should be handled as separate cleanup with build-system confirmation rather than as part of FHIR-18848.
