FHIR-44706: Audit operation error response clarification

Issue request:
FHIR-44706 was Applied/Persuasive with Modification for R6. It asked the Operations: Operation Response section to clarify that a 4xx/5xx failure OperationOutcome is returned bare rather than wrapped in Parameters, and that the single "return" resource shortcut also applies when the expected response is OperationOutcome.

Initial application:
The request was applied to the active top-level operations source page in source/operations.html. Commit a6fb921f2e8d04d7db39ca923afd70427b2bf77f first inserted the clarification, and commit 2e0758d21869d6ceed701a9ef5e317df20c349a9 reformatted it while preserving the requested meaning.

Additional context:
The originating Zulip thread records the implementer confusion and Lloyd McKenzie's clarification that a 4xx failure returns a bare OperationOutcome, while a 2xx success returns a response resource or Parameters and may include a warning OperationOutcome inside Parameters. FHIR-I minutes on 2024-04-08 approved the Persuasive with Modification disposition and pointed back to the same operations response section and Zulip thread. No later source history found a reversal of this clarification.

AutoFHIR reconciliation:
No source change was made. Current source/operations.html already states that an OperationOutcome indicating a failure returned by a 4xx or 5xx code is not wrapped in Parameters, and that the single-resource "return" shortcut is true when the expected response is OperationOutcome.

Recommendation:
Keep this audit commit as-is. The current source satisfies the applied Jira resolution, and adding or changing wording now would be redundant rather than a necessary specification correction.
