FHIR-32130: Audit Encounter DiagnosticReport reason support

Issue request:
FHIR-32130 was a Published/Persuasive with Modification Patient Administration change request raised against R4 and applied for R5. It asked whether Encounter.reasonReference could also reference DiagnosticReport so systems can use a DiagnosticReport that groups/interprets observations as the reason an Encounter takes place. The final resolution agreed, with modification due to FHIR-16148's Encounter.reason redesign, that Encounter.reason should allow a reference to DiagnosticReport.

Initial application:
The issue was applied by commit 4750ea8dbf, "FHIR-32130 Encounter.reason references DiagnosticReport", which added http://hl7.org/fhir/StructureDefinition/DiagnosticReport to the Encounter reason target profiles in source/encounter/structuredefinition-Encounter.xml. Later Encounter.reason restructuring moved the R4 reasonReference shape to the current Encounter.reason.value CodeableReference shape, but the DiagnosticReport target remains present in the active Encounter StructureDefinition.

Additional context:
FHIR-16148 is the same Encounter.reason change family and explains why the current source location is Encounter.reason.value rather than the R4 Encounter.reasonReference element named in the original request. Later Encounter reconciliation work changed reason prose and removed/adjusted other reason targets, but did not remove DiagnosticReport. FHIR-48869 later synchronized EpisodeOfCare.reason with Encounter.reason and explicitly said the Encounter.reason.value references remain as they are; it is already represented on the combined branch, so it is context rather than a second decision here. A Zulip implementers thread supplied the original use-case prompt and no conflicting community evidence was found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Encounter is an active build resource in source/fhir.ini, and the authoritative current source already lists DiagnosticReport as an Encounter.reason.value CodeableReference target profile, satisfying the FHIR-32130 resolution.

Recommendation:
Keep this no-change audit commit as-is. No follow-up is needed for core Encounter for FHIR-32130; future work on parallel resources such as EpisodeOfCare or Appointment should remain tied to their own Jira decisions, such as FHIR-48869.
