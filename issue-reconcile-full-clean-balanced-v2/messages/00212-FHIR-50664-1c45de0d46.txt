FHIR-50664: Audit Measure option 3 application

Issue request:
FHIR-50664 was an Applied/Persuasive CQI change request for FHIR-core Measure raised for R6. The requester preferred option 3 from the Measure ballot note: use one place for the calculation definition by removing the root-level Measure calculation elements and requiring the calculation metadata on Measure.group, with related MeasureReport root scoring/improvementNotation cleanup.

Initial application:
The issue was applied before this reconciliation by 1278aaf985ed, a78ec3bfb390, and f98976a67811, then merged by HL7/fhir#3811 as 30464797464c. Those commits removed the ballot option note from source/measure/measure-introduction.xml, removed deprecated root-level Measure calculation elements, removed root Measure.type, removed root MeasureReport.scoring and MeasureReport.improvementNotation, and added MeasureReport.group.type.

Additional context:
FHIR-50463 was a Resolved - No Change ballot comment that also recommended option 3 and explicitly redirected tracking to FHIR-50664. source/fhir.ini lists Measure and MeasureReport as active resources, so the inspected StructureDefinition sources are in current build scope. Later FHIR-55366 work changed MeasureReport modifier metadata, but it did not reverse the FHIR-50664 group-level placement decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/measure/structuredefinition-Measure.xml no longer contains the root-level Measure.basis, Measure.scoring, Measure.scoringUnit, Measure.scoringPrecision, Measure.compositeScoring, Measure.type, Measure.improvementNotation, or Measure.improvementNotationGuidance elements, while the corresponding Measure.group elements remain. Current source/measurereport/structuredefinition-MeasureReport.xml no longer contains root MeasureReport.scoring or MeasureReport.improvementNotation, and it contains MeasureReport.group.type, group.scoring, group.improvementNotation, and group.improvementNotationGuidance.

Recommendation:
Keep this audit commit as-is. The current build source already implements the applied CQI decision, and additional prose would only duplicate the source element placement and risk future drift.
