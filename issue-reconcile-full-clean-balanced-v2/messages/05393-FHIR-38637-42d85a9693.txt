FHIR-38637: Audit DeviceAssociation period resolution

Issue request:
FHIR-38637 was Published with resolution Persuasive for R5. It asked to add a period to Device.association, review whether Device.association.status values such as active/inactive were still needed once a period existed, consider PHI/history concerns for multiple patient associations, and rename humanSubject to patient. The final Jira resolution says the ticket was overcome by the creation of DeviceAssociation and covered by FHIR-38904.

Initial application:
No direct source commit mentioning FHIR-38637 was found in the relevant Device/DeviceAssociation history. The applied source trail is the related FHIR-38904 work: commit 97e59d026d9311992199080e53a49ec78cf6aae5 removed the active Device.association backbone and its humanSubject/bodyStructure content from Device by commenting it out during R5 application, and commit 7a135eb3489ef36b8935e36d80d88b1729a2e8e8 added DeviceAssociation operation/operator/period QA changes. Current history and source show that the period requirement was carried forward on DeviceAssociation rather than by resurrecting Device.association.

Additional context:
FHIR-38904 is already represented on the combined branch by commit 7991e0aed0bfba3d3de954850eab05a9c91e7a6b, so this reconciliation does not publish a duplicate FHIR-38904 audit. Current source/fhir.ini lists both Device and DeviceAssociation as active resources. Device.association and Device.association.humanSubject remain only in XML comments, while XML parsing finds no active Device association or humanSubject paths. DeviceAssociation now has active device, status, associationStatus, subject, focus, bodyStructure, and period elements; later R6 changes removed the older DeviceAssociation.operation backbone without reversing the top-level DeviceAssociation.period or the move away from Device patient association.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped source already implements the accepted direction: Device no longer exposes an active association/humanSubject backbone, DeviceAssociation carries the association period, and the existing DeviceAssociation status/value set remains part of the later DeviceAssociation model rather than an unresolved Device.association value set problem.

Recommendation:
Keep this audit commit as-is. Do not add period or patient back to Device.association, because that backbone is no longer active build content; use DeviceAssociation.period for the history interval. If work groups want to further refine DeviceAssociation.status semantics, that should be handled as a new DeviceAssociation issue rather than as a late application of FHIR-38637.
