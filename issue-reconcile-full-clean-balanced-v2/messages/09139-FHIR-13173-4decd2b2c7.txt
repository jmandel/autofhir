FHIR-13173: Audit ele-1 value allowance

Issue request:
FHIR-13173 was a Published/Persuasive FHIR-core Element issue raised against DSTU2 and applied for STU3. It reported that the ele-1 invariant did not account for whether the FHIRPath children() function includes a primitive value, and requested changing the expression from `children().count() > id.count()` to `hasValue() | (children().count() > id.count())` so the invariant explicitly passes when an element has a value.

Initial application:
The Jira comment records SVN revision 11893. In nearby imported git history, commit 1040ceaadd7415c013f59cebd966098ff9dbda77 (SVN revision 11898) changed `source/datatypes/element.sheet.txt` from `Expression = children().count() > id.count()` to `Expression = hasValue() | (children().count() > id.count())`. The old `.sheet.txt` file was later removed, and the current authoritative spreadsheet source is `source/datatypes/element.xml`.

Additional context:
A later Published/Persuasive issue, FHIR-15911, corrected the FHIRPath operator from collection union `|` to boolean `or` in commit c50ea493463a70377e635b86153c803b73948953 while preserving the `hasValue()` addition. FHIR-26565 later added the empty Parameters exception, and FHIR-43103 later clarified the human description to include "or both"; both later decisions are already represented on the combined branch and explain why the current text is broader than the original FHIR-13173 request. `source/fhir.ini` actively maps `element=types`, so `source/datatypes/element.xml` is in current build scope.

AutoFHIR reconciliation:
Made no source change. The current ele-1 invariant in `source/datatypes/element.xml` is `hasValue() or (children().count() > id.count()) or $this is Parameters`, so it retains the value-aware behavior requested by FHIR-13173, incorporates the later operator correction, and preserves the later approved Parameters exception.

Recommendation:
Keep this empty audit commit as-is. No FHIR-13173 source follow-up is needed; future ele-1 edits should preserve the explicit `hasValue()` branch unless a new work-group decision supersedes this issue family.
