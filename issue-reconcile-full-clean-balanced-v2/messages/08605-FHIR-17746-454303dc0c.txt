FHIR-17746: Audit Location header URL guidance

Issue request:
FHIR-17746 was Published/Persuasive with Modification for STU3. It asked the HTTP create interaction to clarify whether the response Location header may use either an absolute URL or a relative URL, including reverse-proxy and federated-server scenarios where relative paths are useful.

Initial application:
The issue was applied by git commit de09f7d5cdca1ecfbaecc553a82d19f233aff404, "GF#17746 - clarify location header", which changed source/http.html to add that the Location header MAY be an absolute or relative URL. Later commit c32a2adb0774d63553808f9e2b551292292e7fed, for FHIR-26358, carried the same wording into the update-as-create Location header text when it made Location mandatory for create outcomes there.

Additional context:
The current build includes source/http.html through the active publish.ini [pages] entry "http.html = http". Current source/http.html contains the absolute-or-relative sentence in both the update-create response text and the create response text. The originating Zulip discussion confirms that participants believed either form was allowed and requested only an explicit spec clarification. No Confluence reference for FHIR-17746 was found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already implements the final Jira decision in the active HTTP page and covers the create/update-create surfaces relevant to the issue.

Recommendation:
Keep this no-change audit commit as-is. No follow-up source work is needed for FHIR-17746 unless the work group later decides to specify a narrower relative-URL resolution rule beyond the published clarification.
