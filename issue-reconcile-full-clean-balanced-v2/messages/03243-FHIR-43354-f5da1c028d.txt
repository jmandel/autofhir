FHIR-43354: Audit _elements clarification

Issue request:
FHIR-43354 was Applied as Persuasive with Modification for R6. It asked whether the _elements wording "Servers SHOULD always return mandatory and modifier elements whether they are requested or not" made returning those elements mandatory; the approved change removed "always" and added a note that _elements can be used outside search with a pointer to the RESTful API parameter documentation.

Initial application:
The requested source change was already applied before this reconciliation. Commit 65662fd0e6253b3e15d7a8205b407b2193bbcb5e, titled "FHIR-43354 - clarifications for _elements", changed source/search.html by adding the RESTful API pointer and replacing "Servers SHOULD always return" with "Servers SHOULD return". Earlier commit 22b2855454d1fdcabe258f22b89290ad4a6e4c35 for FHIR-27812 introduced the mandatory/modifier server guidance that FHIR-43354 later clarified.

Additional context:
FHIR-I minutes from 2024-01-08 record the discussion and 16-0-0 vote: "SHOULD always" has the same conformance meaning as "SHOULD", and the group would remove "always" to avoid confusion. A 2022 Zulip implementers thread about _elements confirms the surrounding guidance was intentionally a SHOULD, not a SHALL, and does not conflict with the later clarification. The combined branch already contains the current source/search.html text and the relevant source file is the FHIR-core search page identified by the Jira related page.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current combined-branch source already contains both approved FHIR-43354 changes in source/search.html: the RESTful API note and the removal of "always" from the conformance sentence.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-43354 unless a future work group decision changes the semantics of _elements or the RESTful API parameter guidance.
