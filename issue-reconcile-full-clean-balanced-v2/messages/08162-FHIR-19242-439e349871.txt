FHIR-19242: Audit generated snapshot consistency

Issue request:
FHIR-19242 was a Published/Persuasive FHIR-I correction raised against STU3. It reported that generated StructureDefinition snapshots were not consistently carrying differential changes, including Extension.extension max="0" on extensions, primitive value descriptions, ConsentDirective cardinalities/mappings, ElementDefinition-de comments, and Vital Signs conditions.

Initial application:
No FHIR-19242-specific source commit was found. The Jira application record is Grahame Grieve's 2018-11-12 comment that the examples all looked okay in the then-current build. The same application-era history contains general snapshot processing fixes, including abdb33577d8acc0200bbfaf079afefb0876821ea, 8e8b8534006e48ac3c53719fd6611247f1cdcc16, and 2bf2d89913f48c0d2b632de18d34fe93b22a0553, plus FHIR-19237's separate ConsentDirective contentReference fix from the same differential/snapshot mismatch trail.

Additional context:
Current build scope has moved since STU3. The allowedUnits extension now lives in the FHIR Extension Pack rather than core and its current generated snapshot has Extension.extension max="0". The active Vital Signs profile is still published from source/igs.xml and current generated snapshots carry the current vsp-1/vsp-2 conditions. The retained ConsentDirective profile source is not an active [profiles] entry and the current build no longer publishes consentdirective.profile.json; ElementDefinition-de likewise is not an active current profile. Some primitive type build JSON still uses the inherited generic snapshot definition "The actual value" while the differential says "Primitive value for ...", but that is generated primitive-definition behavior with no current editable source phrase in this checkout and no later Jira/community evidence found that turns it into a new source correction under this seed.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative current source and extension-pack evidence do not show a necessary FHIR core source edit for FHIR-19242, and the remaining primitive wording nuance is not safe to change as an incidental source reconciliation without a separate tooling/work-group decision.

Recommendation:
Keep this no-change audit commit as-is. If the work group wants primitive .value snapshot definitions to exactly mirror generated differentials, or wants a general differential-versus-snapshot QA rule, handle that as a separate tooling/spec decision rather than changing current core source for this STU3 issue.
