FHIR-14301: Audit fixed-order slicing guidance

Issue request:
FHIR-14301 was Published/Not Persuasive with Modification for STU3. It reopened the earlier rank/position slicing request and asked for a supported way to slice by rank or position, but the accepted disposition was not to add a dedicated discriminator then: ordered slicing with fixed slice cardinalities can be validated without a discriminator, while the required slicing.description invariant stays in place. The resolution asked to explain this behavior and include an example.

Initial application:
The issue appears to have been applied by git commit aaf66b61d10e1d03180462585a9b73dbadbf49da, "GF#14301 - profiling example with no discriminator", which added the Fixed Order Slicing section to source/profiling-examples.html. That section shows closed, ordered slicing with no discriminator, a required slicing.description, fixed overall cardinality, named ordered slices, an instance example, and cautionary prose recommending a value-based discriminator where one is practical.

Additional context:
The Jira-linked Zulip thread confirms the discussion path from FHIR-9729: participants considered ordered slicing without a discriminator, noted that the description is required, and observed validator/tooling limitations. The current build also contains the later R5 FHIR-26944 position discriminator guidance in source/datatypes/elementdefinition.xml and source/profiling.html; that later issue is already represented on the combined branch by commit 977539de5d21f972ef18cfdde6fff9d23aba8b8c, which completed the $this path and single-discriminator constraints. This later work covers the dedicated-discriminator direction without requiring a new FHIR-14301 source edit.

AutoFHIR reconciliation:
This audit commit makes no source change. The current source already preserves the FHIR-14301 accepted no-discriminator example and warning, and the current profiling narrative/code list also includes the later explicit position discriminator rule from FHIR-26944. Editing the FHIR-14301 example to remove no-discriminator slicing would erase the historical resolution rather than correct the current specification.

Recommendation:
Keep this audit commit as-is. Future work on position slicing should proceed through FHIR-26944 or a new tracker if the work group wants to deprecate ordered/no-discriminator examples, add formal invariants for position, or further align examples with R5+ position discriminator usage.
