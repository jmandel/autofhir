FHIR-28479: Audit backport backbone extension guidance

Issue request:
FHIR-28479 was a Published/Persuasive FHIR-core compatibility issue asking for clarification on how to backport a future BackboneElement as a cross-version extension, using ValueSet.expansion.contains.property as the example and expecting the child extension names to match the backbone element's component names.

Initial application:
The issue was applied by commit 526d8c02b3, which added guidance to source/versions.html saying complex data types without earlier-version equivalents should use complex extensions whose child properties are named for the complex extension components. That commit also refreshed an unrelated patient example, but the relevant application was the versions.html compatibility-page wording.

Additional context:
Later Published issues FHIR-31721 and FHIR-36702 expanded the same cross-version extension guidance. In 2025, commit f45505e5b3 intentionally removed the detailed inline examples and rules from source/versions.html because the cross-version content moved to the individual cross-version definition guides. The current active core page still defines the cross-version URL pattern and points to those packages, and the published xver-r5.r4 0.1.0 package contains the formal R5 ValueSet.expansion.contains.property extension with child slices named code, value, and subProperty, including nested code/value slices for the subProperty backbone.

AutoFHIR reconciliation:
This is an empty audit commit. No core source change is needed because the current core specification is not missing the rule in its present architecture: source/versions.html remains the active compatibility page and delegates the detailed backbone-extension representation to the cross-version packages where the example artifact is now formally defined. Re-adding the old inline prose to core would duplicate guide-owned guidance and risk future drift.

Recommendation:
Keep this audit as a no-change reconciliation for FHIR-28479. If implementers need more tutorial examples beyond the generated definitions, that should be raised against the cross-version extension guide/FAQ rather than restored as duplicated prose in core versions.html.
