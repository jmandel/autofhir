FHIR-16369: Correct search number history link

Issue request:
FHIR-16369 was Published/Persuasive with Modification for STU3. It asked to make number search behavior less surprising by documenting precision effects more clearly, allowing exponential decimal forms if MnM permitted them, creating follow-up work for decimal equality, and clarifying that integer searches are exact under the published rules.

Initial application:
The issue was applied in svn revision 13844, represented in git as 79c1c0b5cb433f8068e231bd3ab2378464654f41, which updated source/search.html to describe exponent-form number searches, exact comparison prefixes, and exact integer matching. The current search.html retains that applied behavior, with later clarifications from the same search-number family.

Additional context:
FHIR-16874 supplied the required prerequisite by allowing exponential decimal forms. FHIR-17668 later made the significant-digit rule explicit, including that 100 and 1.00e2 both have three significant digits, and FHIR-17669 confirmed that sa/eb are not used with integer values but are used for decimals. The current source/search.html number and prefix sections reflect those decisions. The remaining defect was on the current build-scope history page: the R4 ballot history entry for GF#16369 linked to search.html#decimal, but the relevant search section has current and historical anchor search.html#number.

AutoFHIR reconciliation:
This commit changes only the FHIR-16369 entry in source/history.html from search.html#decimal to search.html#number so the release-history diff link points at the actual number-search section. No substantive search semantics were changed because the current search source already reflects the seed and later related decisions.

Recommendation:
Keep this commit as-is. The source behavior is already correct, and this bounded history-page fix removes a directly related broken anchor without broadening the issue scope.
