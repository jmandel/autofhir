FHIR-8754: Audit physical item alignment

Issue request:
FHIR-8754 was a Published/Persuasive with Modification FHIR-core OO change request for Medication, Device, Substance, and Immunization. It asked for a common way to represent a physical item's type and instance attributes; the accepted resolution narrowed this to aligning grouping, ordering, and definitions across related "thing" resources as much as possible, while explicitly not creating a new common structure.

Initial application:
The direct source history found two explicit #8754 application commits, both in the Device resource. Commit 22debf21aa reordered and grouped Device physical item elements and examples, and commit 966df8c99a continued Device updates while incorporating UDI-related identifier/type/production metadata. I did not find an explicit #8754 commit for Medication, Substance, or Immunization; their current models have subsequently evolved through later resource-specific decisions.

Additional context:
The current build includes Device, Immunization, Medication, and Substance as active approved resources. Current Device keeps identifiers, UDI carrier, record/availability status, manufacturer, manufacturing/expiration, lot, serial, type, and other device properties inline. Current Medication separates catalog/business identity from physical package instance details via Medication.instance and points to definitional medication/product resources. Current Immunization keeps vaccineCode plus an optional administeredProduct CodeableReference(Medication), with manufacturer, lot number, and expiration date adjacent; that later shape was specifically approved in FHIR-27018. Current Substance keeps identifier, status, category/code, description, expiry, and quantity inline. A later Zulip discussion about type-vs-physical-instance confirmed the broader modeling tension but did not reveal a conflicting final decision requiring a common PhysicalItem structure.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already matches the accepted FHIR-8754 disposition: no new shared structure, inline per-resource fields, and resource-specific ordering/definitions that are aligned where the semantics overlap but differ where the resources now model different type-vs-instance boundaries. Reordering or renaming current elements solely for cosmetic parallelism would be broader than the issue resolution and could disrupt later approved resource designs.

Recommendation:
Keep this audit commit as-is. Future work on a cross-resource physical-item pattern should proceed through a new work-group decision because current Medication, Device, Immunization, and Substance definitions reflect later resource-specific choices rather than an unapplied FHIR-8754 correction.
