Issue request:
FHIR-16759 is a Published/Persuasive FHIR-core ConceptMap ballot issue from the 2018-May Core Norm Conformance ballot. It asked for Purpose and Use Context to be more clearly distinguished and said examples would be helpful. The accepted resolution was to add examples in the example concept maps, cloned from the value set examples.

Initial application:
The issue was applied in svn revision 14770, represented in git as f82e3c73beeeeed5c68cbcae84004e5952ae3f01, whose subject explicitly includes GF#16759. That commit changed source/conceptmap/conceptmap-example.xml by correcting the useContext example text and adding jurisdiction next to the existing purpose example, alongside parallel ValueSet example changes.

Additional context:
ConceptMap is an active current-build resource in source/fhir.ini, and source/conceptmap/list-ConceptMap-examples.xml includes ConceptMap/101 as the general ConceptMap example. Current source/conceptmap/conceptmap-example.xml contains both a useContext example and a purpose example. Current source/conceptmap/structuredefinition-ConceptMap.xml separately defines useContext as the contexts the content is intended to support and purpose as why the concept map is needed/designed as it is. FHIR-16794 is the parallel ValueSet purpose/useContext ballot item applied by the same historical revision. Zulip and Confluence searches found no conflicting community record.

AutoFHIR reconciliation:
No source change was made. The current build-scope ConceptMap source already preserves the accepted example coverage and the element definitions already distinguish useContext from purpose.

Recommendation:
Keep this no-change audit commit as-is. Revisit only if the Vocabulary WG wants a new editorial example beyond the existing ConceptMap/101 coverage; the original applied request does not require one.
