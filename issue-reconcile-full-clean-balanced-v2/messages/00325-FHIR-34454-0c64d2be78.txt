FHIR-34454: Audit RatioRange invariant fix

Issue request:
FHIR-34454 was a Published/Persuasive MnM change request raised against R4B and applied for R5. It reported that RatioRange inv-1 incorrectly prohibited a RatioRange with highNumerator and denominator but no lowNumerator, and the final resolution agreed to rewrite both Ratio rat-1 and RatioRange inv-1 and to rename the RatioRange invariant ids inv-1/inv-2 to ratrng-1/ratrng-2 in R5.

Initial application:
The formula change was pre-applied for R4B and is present in the current source. Git commit 9c691ba64ee67ad143027cabf526318b5ae864f1 changed the Ratio and RatioRange datatype spreadsheet FHIRPath expressions from the xor forms to the clearer exists/empty forms requested by the issue. Git commit 9b24283fc116fa7861fbd9b2d49c0c6b57ee800d later corrected the RatioRange three-letter abbreviation entry to RatioRange=ratrng, which is the source mechanism used to produce ratrng-prefixed constraint ids.

Additional context:
Ratio and RatioRange are active datatype entries in source/fhir.ini, and RatioRange has the current TLA mapping RatioRange=ratrng. The R5 generated type snapshot in tools/history/release5/profiles-types.xml contains ratrng-1 and ratrng-2 constraints and shows ratrng-1 with the corrected FHIRPath expression. Although the RatioRange spreadsheet row still has an old XPath-column value copied from Ratio, ElementDefinition.constraint.xpath is disabled in the current datatype definition, so that value is not part of the current conformance surface.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The authoritative current source already applies the Jira decision: Ratio rat-1 and RatioRange ratrng-1 use the corrected formulas, the old RatioRange xor expression is absent from the current datatype source and R5 generated snapshot, and the generated R5 constraint keys use ratrng-1/ratrng-2.

Recommendation:
Keep this no-change audit commit as-is. No core source follow-up is needed for FHIR-34454 unless a future work group decision reintroduces XPath constraint generation or otherwise changes how datatype spreadsheet XPath columns are consumed.
