FHIR-27784: Audit AdverseEvent outcome cardinality

Issue request:
FHIR-27784 is a Published/Persuasive FHIR-core Patient Care change request for AdverseEvent. It asked to change AdverseEvent.outcome from 0..1 to 0..* because outcome value sets can include non-mutually-exclusive outcomes such as required hospitalization, long-term disability, and fetal abnormalities.

Initial application:
The issue was applied by HL7/fhir commit 12d222c23df9fcab9742ec7e7bf1981d84539119, which changed source/adverseevent/adverseevent-spreadsheet.xml for AdverseEvent.outcome from 0..1 to 0..* and added the J#27784 committee note. The later source rework commit 33b409a4b6d544598262f2f074ebb4b6dc466157 preserved that outcome max cardinality and note in source/adverseevent/structuredefinition-AdverseEvent.xml.

Additional context:
source/fhir.ini actively includes AdverseEvent, so source/adverseevent/structuredefinition-AdverseEvent.xml is in current build scope. The current source has AdverseEvent.outcome min 0 and max *, and source/adverseevent/adverseevent.svg also displays [0..*]. Jira and community searches found related AdverseEvent outcome discussion but no later conflicting decision to make the element single-valued again.

AutoFHIR reconciliation:
