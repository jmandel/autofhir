FHIR-17420: Audit Bundle response timestamp note

Issue request:
FHIR-17420 was a Published/Persuasive with Modification FHIR-core Feed change request raised against STU3 and applied for STU3. It said Meta.lastUpdated and Bundle.response.lastModified are semantically equivalent in a batch/transaction response and should generally have the same value; the approved resolution was to document that relationship without renaming either element.

Initial application:
The issue was explicitly applied in svn/git commit 45de2ec6cd, recorded as GF#17420 and svn 14374. That commit updated the then-authoritative Bundle spreadsheet comment for response.lastModified to name meta.lastUpdated and updated the Meta.lastUpdated comment to describe equivalence with HTTP Last-Modified. Later source refactors migrated the Bundle spreadsheet content into source/bundle/structuredefinition-Bundle.xml, where the response.lastModified comment remains.

Additional context:
Bundle is an active infrastructure resource in source/fhir.ini, so source/bundle/structuredefinition-Bundle.xml is current build scope. The current Bundle comment says response.lastModified has to match the same time in the meta header (meta.lastUpdated) when a resource is included, which covers the batch/transaction response case without requiring a rename. Later lastUpdated issues refine adjacent semantics rather than reversing this rule: FHIR-20211 documents HTTP Last-Modified's different wire format and is already reconciled on the combined branch; FHIR-45047 clarifies Meta.lastUpdated is server-managed and can be out of sync with visible resource changes unless otherwise specified; FHIR-54516 remains Resolved - change required and outside this default applied/published source-edit scope. No directly relevant human Zulip or Confluence evidence was found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative Bundle source already carries the FHIR-17420 clarification, and the later Meta.lastUpdated wording does not make the Bundle response note stale because the Bundle note governs consistency between the included response resource metadata and its entry response metadata.

Recommendation:
Keep this no-change audit commit as the FHIR-17420 reconciliation. Future work should not rename either element under this old tracker; if the work group wants to soften or constrain the existing Bundle comment in light of newer lastUpdated policy, that should be a new FHIR-I decision because the current source still reflects the applied FHIR-17420 resolution.
