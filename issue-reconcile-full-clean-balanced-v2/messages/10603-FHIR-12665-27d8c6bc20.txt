FHIR-12665: Audit regex validator support

Issue request:
FHIR-12665 was a Published/Persuasive DSTU2 FHIR-I change request asking the FHIR Validator to support extension-regex.html so profiles could declare value patterns without custom validation code. The Jira resolution text says Auto-deferred, but the applied-history signal is the Jira comment citing SVN revision 11986 and the related regex-consolidation task FHIR-13328.

Initial application:
The issue was applied by git-svn commit 3aa34558348514881e2df90a50796815e13cfc68, corresponding to SVN revision 11986. That commit changed the then-in-repository Java InstanceValidator to read the regex extension while checking primitive values. The related FHIR-13328 application later changed ToolingExtensions.EXT_REGEX from StructureDefinition/structuredefinition-regex to StructureDefinition/regex, aligning tooling with the retained extension URL.

Additional context:
The current core checkout no longer contains the old implementations/java validator source or any active source reference to extension-regex, structuredefinition-regex, or http://hl7.org/fhir/StructureDefinition/regex. FHIR-13328 has already been represented on the combined branch with an audit commit, and later Published issue FHIR-37359 removed active core use of the regex extension in favor of ElementDefinition.constraint or SDC equivalents. The FHIR Extension Pack retains StructureDefinition/regex only as a retired/deprecated compatibility artifact with the same constraint-based recommendation.

AutoFHIR reconciliation:
Made no source changes. The original validator implementation surface is outside this current FHIR core build, and reintroducing active core regex-extension content would conflict with the later FHIR-37359 retirement/removal decision. Any live validator compatibility work belongs in the current validator/tooling repository rather than this core source checkout.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed for FHIR-12665; if implementers need to change live validator behavior for historical R4 regex-extension instances, file that against the current validator/tooling codebase, and keep core aligned with the later constraint-based guidance.
