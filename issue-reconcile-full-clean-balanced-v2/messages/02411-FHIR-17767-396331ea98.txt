FHIR-17767: Audit Element datatype diagram links

Issue request:
FHIR-17767 was Published/Persuasive for STU3 and asked that the word "Element" in data type diagrams be made a hyperlink to the Element definition page.

Initial application:
The Jira comment points to GH#989ce5acbb. That commit is present in the FHIR history as 989ce5acbb78e72435e14a9c18d2c2b959559bf0, "GF#17767 - fix missing link", and changed the then in-repo SvgGenerator so the generated Element box text was wrapped in an SVG anchor to the source file for Element.

Additional context:
The current core checkout no longer owns that Java generator source directly: build.gradle.kts uses the external HL7 Kindling dependency. The current source still keeps Element in the active infrastructure list and maps element to the types page, and the active type framework page renders datatypes/abstracts.diagram, whose classes include Element. Current Kindling source renders linked class titles through makeLink(tn), and the live build verifies the resulting Element title link is types.html#Element. FHIR-33207 is a later same-link-family issue about detailed datatype UML element links going to the wrong page, but it is separate from this seed and is not needed to decide this audit.

AutoFHIR reconciliation:
No source files were changed. The current authoritative source and generator path already satisfy the issue, while editing the checked-in source/datatypes/primitives.svg alone would be a generated-artifact-only change and is not appropriate for this reconciliation.

Recommendation:
Keep this no-change audit commit. Revisit only if the Kindling diagram renderer regresses or if a human explicitly decides that checked-in SVG artifacts should be regenerated as a separate build-maintenance task.
