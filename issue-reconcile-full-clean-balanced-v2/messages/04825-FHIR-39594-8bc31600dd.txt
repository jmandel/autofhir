FHIR-39594: Audit Transport description ownership

Issue request:
FHIR-39594 is Applied/Persuasive for R6 and asks that Transport.description use the markdown datatype because the free-text description may be lengthy. The approved resolution says to update Transport.description from string to markdown while preserving the existing definition, short display, cardinality, and summary flag.

Initial application:
The requested datatype change was applied before this reconciliation by HL7/fhir PR #3660, which changed source/transport/structuredefinition-Transport.xml from <code value="string"/> to <code value="markdown"/> for Transport.description. The local implementation commit f98cc499514637b58624cfda9203ea84f527ba1c has the correct patch and subject but its body references unrelated FHIR-51840; the PR body, Jira comment, and changed file disambiguate the application as FHIR-39594.

Additional context:
FHIR-38714 established that converting an element from string to markdown is compatible and asked for review of string elements that may contain more than one paragraph. Later source history moved Transport and several other OO resources out of the active core build: commit 3b38b80cf23f9cbb306fab8fcedb293315478c32 removed Transport from the active draft/resource/normative fhir.ini sections and pointed core narrative pages at the OO Incubator artifact. The remaining core source/transport file is not an active core resource, and the current OO Incubator Transport StructureDefinition also has Transport.description typed as markdown.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The original core source application is present, the current active Transport definition outside core already matches the Jira resolution, and editing the inactive core Transport source would not affect the current core build.

Recommendation:
Keep this external-ownership audit as-is. No core follow-up is needed for FHIR-39594; if Transport returns to core or the OO Incubator definition is changed, maintain Transport.description as markdown there.
