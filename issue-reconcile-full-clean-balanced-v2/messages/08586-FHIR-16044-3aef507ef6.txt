FHIR-16044: Audit Questionnaire signature extensions

Issue request:
FHIR-16044 was a Published/Persuasive with Modification FHIR-core change request asking for a Signature datatype on Questionnaire for legally significant forms. The approved resolution did not add a core Questionnaire.signature element; it directed two standard extensions instead: questionnaire signature-required, with a preferred signature-type binding and a reference to the response extension, and QuestionnaireResponse signature 0..* Signature.

Initial application:
The change appears to have been applied by SVN #14772, represented in git as b8c5990ac5, which added signatureRequired and signature rows to the Questionnaire and QuestionnaireResponse extension spreadsheets. No prior Issue-Reconcile-Key commit for FHIR-16044 was present on the combined branch.

Additional context:
FHIR-16045 is the companion QuestionnaireResponse request and explicitly says it was addressed as part of FHIR-16044. Core later removed the extension definitions from the R5 source in dd468d4f17 as part of moving standard extensions out of the core checkout; the current FHIR Extension Pack contains the active questionnaire-signatureRequired and questionnaireresponse-signature definitions. Current core source still preserves the OID assignments and the Signature datatype page points to the QuestionnaireResponse signature extension. Later Zulip discussion still refers to these as the standard extensions and records no final decision to remove or replace them.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no core source change. Adding a Questionnaire.signature element now would contradict the published modified resolution, while the extension-pack source already carries the approved extension definitions.

Recommendation:
Keep this no-change audit. Future work should use a new tracker if the work group decides to replace the extension approach with Provenance-only guidance or new signature semantics.
