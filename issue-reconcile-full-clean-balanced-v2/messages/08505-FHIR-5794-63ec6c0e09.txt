FHIR-5794: Audit retired @all URI definition

Issue request:
FHIR-5794 was a Published FHIR-core ValueSet change request, resolved Persuasive and applied for DSTU1. It asked the specification to define a single magic URI for "all known value sets" so terminology servers would not use server-specific identifiers for cross-value-set $expand filtering and $validate-code use cases.

Initial application:
The Jira comment cites SVN revision 5690, and git history maps that to commit c4bfe496c8, which added the "Operations across all value sets" section to source/terminology-service.html and defined http://hl7.org/fhir/ValueSet/@all as the server-specific value set meaning all value sets known to the server. FHIR-8447 later clarified in commit ae41753104 that the URL had no fixed meaning and that version granularity was at server discretion.

Additional context:
FHIR-19442 is a later Published Vocab decision for the same terminology-service #all section. It resolved to remove the section because @all had very limited use, was server-specific, and did not support interoperability. The R5 vocab batch commit 9500b398d1 removed the section from the active terminology-service source, and the existing combined-branch commit 0f21a3cc2cac772f1d47c2ad96baa56e7a530978 removed the stale publish.ini redirect. Current Zulip discussion also says @all was an internal construct that should not have been externally visible.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/terminology-service.html and publish.ini no longer define or redirect http://hl7.org/fhir/ValueSet/@all, which is correct after the later FHIR-19442 decision superseded FHIR-5794's original DSTU1 request.

Recommendation:
Keep this audit as-is. Do not restore the @all magic URI unless a new Vocab work-group decision creates a replacement global terminology-search mechanism with interoperable semantics.
