FHIR-31862: Audit operation authorization removal

Issue request:
FHIR-31862 was a Published/Persuasive BRR change request for R5 saying that MedicinalProductDefinition.operation should not point to an authorization. The resolution required removing the outgoing reference to authorization because RegulatedAuthorization should point to what it authorizes.

Initial application:
The current history contains commit 97e5434bfca09668f25b0773090aa98c0508d351, which removed MedicinalProductDefinition.operation.authorization, replaced operation.type wording that referred to an authorization attribute, and added PlanDefinition as an allowed target next to ActivityDefinition. That commit is an ancestor of the current source branch.

Additional context:
MedicinalProductDefinition and RegulatedAuthorization are active current-build resources in source/fhir.ini. The current MedicinalProductDefinition source has operation.type as a CodeableReference to ActivityDefinition or PlanDefinition and no operation.authorization element. The current RegulatedAuthorization.subject target list includes ActivityDefinition and PlanDefinition, so authorization can point to the plan or activity referenced by the operation. No directly relevant Zulip or Confluence record was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:
No source change was made. The active source already reflects the required directionality: MedicinalProductDefinition.operation no longer references RegulatedAuthorization, and operation.type carries the shared PlanDefinition/ActivityDefinition target used by RegulatedAuthorization.

Recommendation:
Keep this audit commit as-is. Further source edits would be redundant unless BRR later decides to narrow the broader RegulatedAuthorization.subject targets, which is outside the scope of FHIR-31862.
