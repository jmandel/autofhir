FHIR-16332: Audit value set reference clarification

Issue request:
FHIR-16332 is a Published/Persuasive vocab change request from the STU3 ballot asking the Value Set References section to clarify that a reference to a value set does not itself obtain the expansion needed to use the value set members. The recorded resolution was to add a note about this.

Initial application:
The Jira comments say the change was applied around SVN 14661. Git history shows that the neighboring git-svn commit f329007b7707b4496435df2e911a5695f399a2c4, recorded as build@14660 on 2018-08-10, inserted the current note in source/terminologies.html explaining that value set references normally point to the value set definition and require a terminology server to produce the actual expansion for use. The build@14661 commit itself was for GF#16321 and did not touch this terminology page.

Additional context:
The active publish configuration includes terminologies.html as a current page and names it Using Terminologies. The 2018-07-12 Vocab WG agenda listed tracker 16332 in block vote A with a Persuasive ballot resolution, matching the Jira vote record. Jira, Zulip, and Confluence searches found no later directly relevant decision that reverses or narrows this clarification.

AutoFHIR reconciliation:
No source change was made. Current source/terminologies.html already contains the needed clarification at the start of Value Set References: references are usually to the value set definition, and a terminology server is required to convert that definition to the actual expansion specifying the codes in the context of operation.

Recommendation:
Keep this no-change audit commit. The current source satisfies the issue without adding redundant prose; future work should only revisit the wording if the terminology work group wants to refine the broader value set reference guidance.
