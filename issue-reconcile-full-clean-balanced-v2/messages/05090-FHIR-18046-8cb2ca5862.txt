FHIR-18046: Audit ValueSet expand guidance

Issue request:
FHIR-18046 was a Published/Persuasive FHIR-core ValueSet change request from the Vocabulary work group. It asked for better ValueSet $expand operation guidance and examples, specifically a context plus contextDirection example, examples covering parameters, and clarification that context does not require a profile.

Initial application:
The Jira comment identifies git 66ae1e40f1bc02283363c872db14035fc795f8f7 as the application commit. That commit added ValueSet $expand request and response examples and expanded the contextDirection parameter documentation; the follow-up 728c10f78edd757e749a4fa1d9a5abf3003f1b18 cleaned up duplicated examples and added the profile-specific context example note. The later 33b409a4b6d544598262f2f074ebb4b6dc466157 source rework carried this operation definition into the current OperationDefinition XML.

Additional context:
ValueSet is active in source/fhir.ini and source/valueset/list-ValueSet-operations.xml references OperationDefinition/ValueSet-expand, so the inspected operation source is in the current build. The current operation parameter documentation explains the recommended StructureDefinition URL#path form for context and permits other server-defined forms. The current example file includes common parameter examples, a context plus contextDirection example without a profile, and a profile-specific example noting encoded # and server discretion when contextDirection is absent. A later related FHIR-core request, FHIR-24834, proposed adding contextDirection=existing but was retracted/no-change, so it does not require altering this guidance. Community searches found the original Zulip context discussion but no FHIR-18046-specific Confluence or conflicting community record.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source preserves the implementer-facing clarification that FHIR-18046 required, and adding more redundant examples for every current R6 $expand parameter would broaden the old STU3 clarification into optional editorial expansion rather than fixing a current semantic gap.

Recommendation:
Keep this no-change audit as-is. Revisit only if the Vocabulary work group opens a new current-version request for exhaustive $expand examples or for changing context/contextDirection semantics.
