FHIR-20511: Audit Encounter machine participant support

Issue request:
FHIR-20511 was a Published FHIR-core PA change request, resolved Persuasive with Modification, asking how to model AI or other machine interactions that look like encounters. The accepted resolution was to add Device to the Encounter.participant.individual reference choices and rename Encounter.participant.individual to Encounter.participant.actor for consistency with Appointment.

Initial application:
No source commit explicitly mentioning FHIR-20511 was found. The substantive Encounter source effect appears to have been applied through the closely related FHIR-22696 implementation: commit 21e95de9dcd529dbd870ecff97c456cee1ae6309 added Device and HealthcareService to Encounter.participant.individual, and commit d1af9f83a1fba890f97ff6d9c02af936d77bb836 renamed Encounter.participant.individual to Encounter.participant.actor while carrying the Device target forward and updating the Encounter participant search parameters.

Additional context:
FHIR-22696's Published resolution explicitly listed the renamed Encounter.participant.actor target set as Patient, Group, Practitioner, PractitionerRole, RelatedPerson, Device, and HealthcareService, so the later implemented shape is consistent with the overlapping PA decision. The originating Zulip discussion for FHIR-20511 recommended extending Encounter.participant with Device, and the later FHIR-35810 Practitioner guidance confirms that autonomous systems and machines, including AI/ML, should be represented with Device rather than Practitioner. Confluence searches found no FHIR-20511 decision record that changes this Jira/source conclusion.

AutoFHIR reconciliation:
No source change was made. The active Encounter resource source now defines Encounter.participant.actor and includes Device as an allowed target profile, the Encounter search parameters refer to Encounter.participant.actor rather than the old individual path, and current Practitioner narrative is consistent with using Device for machine actors.

Recommendation:
Keep this empty audit commit as-is. The current core source already satisfies the FHIR-20511 resolution; any future concern about wording such as broader participant prose should be handled as a separate editorial tracker because the conformance target profiles and actor element wording already convey the machine-as-Device rule.
