FHIR-26603: Audit ObservationDefinition qualifiedValue application

Issue request:
FHIR-26603 is a Published/Persuasive R5 change request for ObservationDefinition. It asked to replace the existing qualifiedInterval and standalone *CodedValueSet elements with a common qualifiedValue(s) backbone that supplies the same context, appliesTo, gender, age, gestationalAge, and condition criteria for ranges and coded value sets, and to make the same backbone available under component.

Initial application:
The change was applied in the February 2021 ObservationDefinition update commits 1872b9243b and 56b91f72c1, then refined by FHIR-26603-specific commits 389aef2302 (definition punctuation) and 9c23150c01 (renaming qualifiedValues to singular qualifiedValue). Current fhir.ini keeps migration aliases from the removed qualifiedInterval and top-level *CodedValueSet paths into ObservationDefinition.qualifiedValue.

Additional context:
The Jira-linked Zulip thread records the rationale that discrete/nominative value sets needed the same inline qualifiers as continuous and ordinal ranges. OO minutes recorded FHIR-26603 as the new qualifiedValues backbone and accepted the catalog block vote. Later FHIR-41671 changed qualifiedValue.gender to qualifiedValue.sexParameterForClinicalUse and added qualifiedValue examples; that later issue is already represented on the combined branch, so the current source should not reintroduce the older gender element name.

AutoFHIR reconciliation:
No source change was made. The active ObservationDefinition differential contains ObservationDefinition.qualifiedValue with context, appliesTo, sexParameterForClinicalUse, age, gestationalAge, condition, rangeCategory, range, and valid/normal/abnormal/critical coded value sets. ObservationDefinition.component.qualifiedValue content-references the same backbone. The CQL model content also exposes qualifiedValue on both ObservationDefinition and component and includes the coded value set children. Old paths no longer appear as active source elements outside migration aliases and current child/example names.

Recommendation:
Keep this audit commit as-is. No core FHIR follow-up is needed for FHIR-26603; revisit only if the work group decides to reopen the separate Group-vs-inline-criteria design question raised later in the Zulip thread or the already-audited FHIR-41671 changes.
