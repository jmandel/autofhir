FHIR-25042: Audit contained-resource reference validation

Issue request:
FHIR-25042 was Published/Persuasive for FHIR-core after being raised against STU3 and applied for R5. It reported that QA/validator output rejected a DiagnosticReport containing two contained Observations where one contained Observation.derivedFrom referenced the other with a local `#...` reference. The Jira resolution was auto-approved; later comments classified this as a tooling issue, and the reporter confirmed the validator no longer rejected the attached file.

Initial application:
No source commit explicitly tagged FHIR-25042 was found, and no current source edit appears to have been needed for the published issue. The relevant Reference invariant had already been corrected in commit c26d2b6172e66e1f867d4ca766dc977cdcc95d5a, `fix ref-1 constraint (define %rootResource)`, which changed the local-reference lookup from `%resource.contained.id` to `%rootResource.contained.id` so a Reference evaluated inside a contained resource checks the root container's contained ids. Later ref-1 commits, including d87b97a367412efef9c243585bd036f4546fb9c5 and d0d047e3b0ef986cdd8729e4c9ad26ab903bac7f, preserved that behavior while adding the bare-# container-reference branch and the display-only guard.

Additional context:
Reference is an active datatype in source/fhir.ini and DomainResource is an active normative resource, so source/datatypes/reference.xml and source/domainresource/structuredefinition-DomainResource.xml are build-scope source. Current references.html says contained resources share the parent internal id resolution space, that fragment-only contained references stop at Bundle.entry.resource and Parameters.parameter.resource but not at DomainResource.contained, and that a contained resource may be referenced by something in the container, potentially another contained resource. The combined branch already contains no-change audits for adjacent contained-reference issues FHIR-31732 and FHIR-29408. Direct Zulip and Confluence searches for FHIR-25042 and the contained-reference validator terms found no conflicting community evidence.

AutoFHIR reconciliation:
Made no source change. The current active Reference ref-1 expression uses `%rootResource.contained.id` for local reference validation, which is the source-level behavior needed for a contained Observation to reference another contained Observation in the same DiagnosticReport. The remaining history points to an implementation-specific validator problem that has already been reported as resolved.

Recommendation:
Keep this empty audit commit as-is. No FHIR core source follow-up is needed for FHIR-25042; if a similar failure recurs, it should be handled as a validator/HAPI FHIR implementation issue rather than a spec source correction.
