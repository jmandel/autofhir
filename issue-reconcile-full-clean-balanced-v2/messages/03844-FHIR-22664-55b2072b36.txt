FHIR-22664: Audit ValueSet expansion version guidance

Issue request:
FHIR-22664 was Published/Persuasive with Modification for R5 by Vocabulary. It asked for guidance on the ValueSet expansion and $expand operation pages clarifying that a ValueSet resource containing only an expansion, without compose, carries ValueSet.version and ValueSet.status from the ValueSet resource instance that contained the definition used to create the expansion.

Initial application:
The seed was initially applied by commit 9fca6ca36fefa544491b1efc7fdb1530333ed78b, which added the status/version rule to source/valueset/valueset-notes.xml and source/valueset/operationdefinition-ValueSet-expand.xml using the Jira resolution's "persisted to" wording. That commit was part of a larger R5/VSD profile batch and touched active ValueSet build inputs.

Additional context:
Later same-family issue FHIR-23565 was also Published/Persuasive with Modification for R5 and clarified that persistence is not the controlling distinction: when an expansion ValueSet is returned or otherwise created, the definition ValueSet.version must be returned in the expansion when available. Its reconciliation commit b04f6401acc7d52bf98b74b85afa2d8d3f2dca23 aligned the $expand operation footer with the current ValueSet expansion notes by changing the remaining stale "persisted to" wording to "returned in". Confluence Vocab/VSDP records for FHIR-22664 approve the ticket resolution, and the FHIR-23565 discussion says the returned-in text satisfies the original request.

AutoFHIR reconciliation:
Made no source change. The current active ValueSet sources already say that when available, ValueSet.status and ValueSet.version from the ValueSet resource instance containing the definition SHALL be returned in the ValueSet resource instance containing the expansion, on both the ValueSet expansion notes and the ValueSet $expand operation page footer.

Recommendation:
Keep this audit commit as-is. Do not revert the current "returned in" wording to the older FHIR-22664 "persisted to" wording, because FHIR-23565 is a later published clarification of the same rule and covers non-persisted expansion results as well.
