FHIR-19448 was Published with a Persuasive with Modification resolution asking for the missing required value-set binding on TerminologyCapabilities.codeSystem.version.language, aligned with the CodeSystem resource language binding.

Initial application:
The issue was applied in git commit 1e011219c1, which removed the no-binding marker from source/terminologycapabilities/structuredefinition-TerminologyCapabilities.xml and added a required Language binding to http://hl7.org/fhir/ValueSet/languages for TerminologyCapabilities.codeSystem.version.language.

Additional context:
TerminologyCapabilities is an active, normative resource in source/fhir.ini. Later Applied issue FHIR-46074 superseded the original ValueSet/languages-only shape by adopting the CapabilityStatement.acceptLanguage pattern: a required binding to http://hl7.org/fhir/ValueSet/all-languages with an additional starter binding to http://hl7.org/fhir/ValueSet/languages. Duplicate FHIR-38734 raised the same concern. Git commit 39f96b21ce implemented that later binding shape, and git commit fe420c6da added the required key on the additional binding.

AutoFHIR reconciliation:

Recommendation:
