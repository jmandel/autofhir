FHIR-11210: Audit doc-typecodes expansion rendering

Issue request:
FHIR-11210 was a Published/Persuasive DSTU2 Composition tracker for the doc-typecodes ValueSet page. The ballot comment asked why no expansion was generated and why the link near the top appeared to go to the main HL7 webpage; the Jira discussion clarified that the LOINC expansion is thousands of codes and should render with a large-expansion warning rather than silently appearing empty.

Initial application:
No git commit explicitly names FHIR-11210. The relevant Composition ValueSet source was already present and was touched in the same era by commit 2ea2f88f92ad35028521ebd3e595f50daa73990e, which changed the publisher contact telecom system from other to url. Later build/tooling and terminology-server behavior now render the large LOINC expansion rather than requiring a source-level expansion in the XML.

Additional context:
Composition is an active current-build resource in source/fhir.ini, and source/composition/valueset-doc-typecodes.xml defines http://hl7.org/fhir/ValueSet/doc-typecodes as all LOINC concepts with SCALE_TYP = LP32888-7 (Doc). The current CI rendered page for valueset-doc-typecodes has an Expansion section generated from tx.fhir.org, includes a warning that the value set has more than 1000 codes, and lists codes. The JSON conformance source intentionally does not carry an inline expansion because this is generated at render/terminology time.

AutoFHIR reconciliation:
No source change was made. The authoritative source is correct, the active build now displays the intended generated expansion/warning, and changing the publisher contact URL or adding a static expansion would either be redundant or wrong for a large external LOINC ValueSet.

Recommendation:
Keep this no-change audit commit. If the generated expansion disappears in a future build, investigate publisher/terminology-server rendering rather than editing the ValueSet compose definition.
