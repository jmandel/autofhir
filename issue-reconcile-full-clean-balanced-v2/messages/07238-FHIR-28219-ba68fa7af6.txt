FHIR-28219: Audit clinical-patient target scope

Issue request:
FHIR-28219 is a Published/Persuasive FHIR-I technical correction, raised for R4 and applied for R5, asking that the common clinical-patient SearchParameter target only Patient. The reported inconsistency was that DeviceUseStatement.subject could also be Group, so the resolution required patient search expressions based on non-patient-named elements to use where(resolve() is Patient) and avoid broadening the common patient search to non-Patient targets.

Initial application:
The seed Jira comment says the change was done in R4B. No source commit found in local history cites FHIR-28219 directly, but FHIR-I minutes for 2020-12-07 record the same decision as "Will fix the FHIRPath for DeviceUseStatement." The matching R4B application appears to be git commit b717783b86bab2bb3aa9ca289f2cd11a7ba18107 for related FHIR-26900, which changed DeviceUseStatement-patient from DeviceUseStatement.subject to DeviceUseStatement.subject.where(resolve() is Patient).

Additional context:
DeviceUseStatement was later renamed to DeviceUsage and DeviceUsage is no longer active in the current FHIR core build; an existing combined-branch FHIR-26900 audit records that the current external DeviceUsage artifact preserves the Patient-only patient search parameter. Related combined-branch audits for FHIR-31714 and FHIR-32876 confirm that later generated clinical-patient target expansion issues are already correct, and FHIR-36674 has already aligned remaining active patient registry bases on the combined branch.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. SearchParameter is active in source/fhir.ini, the combined branch's source/searchparameter/common-search-parameters.xml clinical-patient block contains only the common base list and no Group target assertion, active patient-code SearchParameter sources have no explicit non-Patient targets, and resource expressions that are not Patient-filtered are already Patient-only elements. Current build, R5, and R4B generated search-parameters.json all report SearchParameter/clinical-patient target ["Patient"].

Recommendation:
Keep this no-change audit. The current core source and generated publication surfaces satisfy FHIR-28219; do not add redundant filters to elements already typed only as Patient or edit inactive DeviceUsage core source. Future follow-up is only needed if generation again expands clinical-patient.target beyond Patient or a resource newly added to clinical-patient has a non-Patient patient search target.
