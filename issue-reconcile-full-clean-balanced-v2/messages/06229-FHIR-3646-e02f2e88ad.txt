FHIR-3646: Audit ConceptMap relationship direction

Issue request:
FHIR-3646 was a Published/Persuasive DSTU1 ConceptMap change request asking whether ConceptMap.element.map.equivalence relationships such as "narrower" were read from source to target or the reverse. The approved Jira comments resolved that the relationship should be read "from" to "to", so narrower means the source concept is narrower than the target concept, and asked the editor to make ConceptMap definitions and rendering consistent with that meaning.

Initial application:
The issue was initially applied in svn revision 3289, represented in git as 3de063f9c5f479625a4cd5d27f90691a2dfb68c4, with the subject "{#3646}: Sort out directionality of ConceptMap (and {#3694}: make concept name optional)". That commit updated the then-current ConceptMap spreadsheet, including the old ConceptMap.element.map.equivalence definition text.

Additional context:
ConceptMap has since been redesigned. The current build-scope ConceptMap resource is active in source/fhir.ini and the old equivalence element is mapped to ConceptMap.group.element.target.relationship. Later Published issue FHIR-25923 replaced ambiguous broader/narrower relationship codes with explicit source/target codes and is already represented on the combined branch, so this audit does not publish a duplicate FHIR-25923 decision. Later Applied issue FHIR-45006 confirms the same source-to-target reading for terminology-service closure-table text but concerns a separate terminology-service page.

AutoFHIR reconciliation:
No source change was made. The current ConceptMap StructureDefinition defines ConceptMap.group.element.target.relationship as "read from source to target (e.g. source-is-narrower-than-target)", and the Concept Map Relationship code system defines source-is-narrower-than-target and source-is-broader-than-target using explicit source/target wording. Searches found no remaining ambiguous narrower/broader ConceptMap relationship code values in the current ConceptMap source.

Recommendation:
Keep this no-change audit commit. The current source already implements the FHIR-3646 directionality requirement, and further edits would only duplicate clear normative definitions or reopen later FHIR-25923 terminology decisions.
