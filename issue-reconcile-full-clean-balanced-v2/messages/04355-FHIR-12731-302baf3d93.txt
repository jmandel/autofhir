FHIR-12731: Audit Condition denial guidance

Issue request:
FHIR-12731 was a Published Patient Care change request for the DSTU2 Condition verification status value set. The reporter asked whether refuted should cover patient/asserter denial or whether a denied code should be added for examples such as "patient has never had chicken pox" and "patient does not have asthma." The final resolution was Not Persuasive with Modification: keep the existing Condition absence guidance and add a note that when the patient denies a condition, that can be annotated in Condition.note.

Initial application:
The issue was explicitly applied in historical commit 6e701e5ef7be2338059f27c6f3a397c01fd10d85, which added the Patient Denies Condition note to source/condition/condition-notes.xml. That notes page was later accidentally reduced and restored by commit 005f3df50afc07ae825c55698ac247ac81eb4882, which preserved the patient-denial note and the surrounding assertions-of-absence guidance.

Additional context:
Condition is an active current build resource in source/fhir.ini, so source/condition/condition-notes.xml remains in the current resource source area. Current source/condition/valueset-condition-ver-status.xml still composes the Condition verification status value set from http://terminology.hl7.org/CodeSystem/condition-ver-status rather than adding a separate denied code. The linked Zulip thread shows why denial was discussed separately from refutation: participants cautioned against overloading refuted/status with unconfirmed absence or patient assertion semantics. No Confluence references or later Jira issues specific to this exact denial note were found.

AutoFHIR reconciliation:
This audit commit intentionally makes no source changes. The current source already contains the exact note required by FHIR-12731 and retains the adjacent guidance that refuted applies when evidence later refutes a considered-present Condition, while checklist-style absence questions should use QuestionnaireResponse or Observation instead of Condition.

Recommendation:
Keep this audit commit as-is. No further core source work is needed for FHIR-12731 unless Patient Care reopens the broader negation modeling question in a later issue.
