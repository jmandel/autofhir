FHIR-14673: Audit timezone date extensions

Issue request:
FHIR-14673 was a Published FHIR-core/MnM STU3 change request, resolved Persuasive with Modification, asking for timezone support on date-like primitives without changing the date primitive itself. The accepted resolution was to define a timezone offset extension for date, define a timezone code extension for date, dateTime, and instant, add a Meta.lastUpdated note saying any timezone code applies to the server copy of the resource rather than other timing elements, and add a timezone safety-checklist note.

Initial application:
The issue was applied in git-svn commit 2ef7c566f64cccc1f723a9ca7decebbdf554bdb1, matching Jira's svn revision 13452 comment. That commit added tz-code and tz-offset rows to source/profiles/general-extensions-spreadsheet.xml, added the Meta.lastUpdated note to source/resource/resource-notes.xml, and added the timezone/date-rendering safety checklist entries to source/safety.html. The old core extension rows were later refactored: current core no longer has standalone StructureDefinition-timezone or StructureDefinition-tz-offset source files, and the authoritative extension definitions now live in the FHIR Extension Pack.

Additional context:
The February 2018 Zulip thread for GF#14673 shows why the WG chose extensions: allowing native offsets on date was considered likely to break parsers and create round-trip expectations, so the final direction was extension-based. Later published issues refined the same artifact family: FHIR-23817 renamed tz-code to timezone, FHIR-23819 confirmed the IANA timezone value set and Meta context, FHIR-33018 added time context, FHIR-38006 and FHIR-24564 clarified UTC offset wording, and FHIR-43351 clarified the Extension Pack timezone description. The current core source retains the Meta.lastUpdated note and safety checklist entry, while the Extension Pack source defines http://hl7.org/fhir/StructureDefinition/timezone for date/dateTime/instant/Meta/time and http://hl7.org/fhir/StructureDefinition/tz-offset for date.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core build inputs and Extension Pack source already convey the accepted FHIR-14673 behavior after later approved refinements, and duplicating or reintroducing old core extension rows would conflict with the current extension ownership model.

Recommendation:
Keep this audit commit as-is. No FHIR-core follow-up is needed for FHIR-14673; any future wording or context change for these extensions should be handled as a FHIR-extensions issue against the Extension Pack.
