FHIR-48766: Audit vital-sign LOINC in filters

Issue request:
FHIR-48766 is an Applied/Persuasive FHIR-core Observation issue asking for the Observation Vital Signs profile value set definitions bound through Observation.code to use the LOINC `in` filter where appropriate, avoiding repeated compose.include blocks that only differed by one LOINC filter value now that tx.fhir.org supports `in` for LOINC.

Initial application:
The issue was pre-applied in git commit f628a0a04e and merged by HL7/fhir pull request #3210 as merge commit 53031256e3. That source change collapsed repeated include blocks in nine Observation vital-sign value set XML files into one include with a comma-separated LOINC `in` filter. Later commits touching the same files changed metadata/status, not this filter semantics.

Additional context:
The affected files are in the active Observation resource area: source/fhir.ini includes observation=Observation, source/observation/list-Observation-packs.xml references ImplementationGuide/Observation-vitalsigns, and that IG references the vital-signs profile family. Observation.code in StructureDefinition/vitalsigns binds to ValueSet/observation-vitalsign-measurement, whose compose includes the component vital-sign value sets. OO minutes on 2024-11-26 record support for the LOINC `in` simplification while noting an IG Publisher display-text limitation; the Jira later records the Applied vote. No Zulip or related-Jira search found a later decision requiring a source reversal.

AutoFHIR reconciliation:
No source change was made. Current source already contains exactly one LOINC `in` filter in each of the nine value sets changed by f628a0a04e: bodyheight, bodytemp, bodyweight, diastolicbp, headcircum, heartrate, oxygensat, resprate, and systolicbp. Each `in` filter has the expected comma-separated LOINC LP values and the XML parses successfully.

Recommendation:
Keep this audit commit as-is. If the Publisher still omits display text for comma-separated LOINC `in` values, handle that as publisher/tooling follow-up rather than reverting these core value set definitions.
