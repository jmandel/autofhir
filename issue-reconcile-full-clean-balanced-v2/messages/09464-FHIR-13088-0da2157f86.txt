FHIR-13088: Audit modifier extension SHALL wording

Issue request:
FHIR-13088 was a Published FHIR-core change request with resolution Persuasive with Modification. It asked whether the extensibility documentation sentence "If it is not safe for an application processing the content of the resource to ignore the extension it must be represented differently using a Modifier Extension" should use conformance language; the recorded resolution was to change "must" to "SHALL".

Initial application:
The issue was applied before this reconciliation. Git commit bbd80926e4100a490d68f04c58ab46be57994368, "GF#13088 - fix conformance language", changed source/extensibility.html from "it must be represented differently" to "it SHALL be represented differently" on 2018-03-12, matching the Jira comment that cited SVN revision 13375.

Additional context:
source/fhir.ini maps the active type page entry extension=extensibility, so source/extensibility.html is in current build scope. Later applied/published edits on the same bullet, including FHIR-18344 in e8cc2b24b5100dcf299406ca0db4d005a7d808ba and FHIR-19359 in 67ee800fd2ddfec4ee1fbcc42d293789a7429077, clarified the grammar and the meaning of "Not safe" without reverting the SHALL requirement. Direct Zulip and Confluence searches for FHIR-13088 found no conflicting community record.

AutoFHIR reconciliation:
No source change was made. The current source already says that an unsafe-to-ignore extension SHALL be represented using a Modifier Extension rather than an extension element, which preserves the required conformance language from FHIR-13088.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-13088 unless a future work group decision reopens the modifier-extension conformance rule.
