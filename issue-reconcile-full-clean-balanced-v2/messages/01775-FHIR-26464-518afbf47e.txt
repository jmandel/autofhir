FHIR-26464: Audit Condition clinicalStatus terminology definitions

Issue request:
FHIR-26464 was Published/Persuasive with Modification for R5. It asked Patient Care to clarify the Condition.clinicalStatus code definitions so that the status codes cover conditions or situations, significant/appreciable/negligible risk, and examples such as food insecurity and alcoholism rather than only current or past symptoms.

Initial application:
The issue was applied in core by commit 0d382da235aa42d53fc007e433ee8627ccbf82a1, which updated source/condition/codesystem-condition-clinical.xml with the approved definitions for active, recurrence, relapse, inactive, remission, and resolved. Later commit 5c0494aacfd0b8bd52bc72c587aa89d0a64246f8 removed that code system from the core source as part of moving UTG-maintained terminology out of the FHIR core build.

Additional context:
Condition is still an active current-build resource through source/fhir.ini, and source/condition/structuredefinition-Condition.xml still has a required clinicalStatus binding to source/condition/valueset-condition-clinical.xml. That value set now includes http://terminology.hl7.org/CodeSystem/condition-clinical rather than carrying the code definitions locally. UP-279 was the follow-up UTG proposal for the FHIR-26464 definitions, but it was withdrawn/retracted after the submitter noted the change was already committed to the UTG/THO source of truth. The current terminology.hl7.org CodeSystem-condition-clinical JSON contains the approved FHIR-26464 definitions, plus the later unknown code from the separate FHIR-29409/UP-280 change family.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core source correctly delegates the condition-clinical code definitions to THO, and the current THO code system already contains the definitions approved by FHIR-26464. Re-adding or editing a core CodeSystem file would conflict with the later UTG ownership model.

Recommendation:
Keep this empty audit commit as-is. No FHIR core source follow-up is needed for FHIR-26464; future edits to these code definitions should proceed through the UTG/THO terminology source of truth unless a later Jira explicitly changes core binding behavior.
