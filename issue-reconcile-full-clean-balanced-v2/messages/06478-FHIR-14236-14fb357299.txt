FHIR-14236: Audit CodeSystem lookup decimal support

Issue request:
FHIR-14236 was a Published/Persuasive vocab change request for STU3. It asked that CodeSystem/$lookup allow decimal-valued property and subproperty outputs because SNOMED CT drug strength/concrete-domain properties can be decimal.

Initial application:
The issue was applied in svn 13315, represented in git by 3f90df043ae2a6295699a5e94593284b7339acba, which added decimal to the CodeSystem property type list, CodeSystem.concept.property.value[x], lookup.property.value, and lookup.property.subproperty.value in the then-authoritative CodeSystem spreadsheet.

Additional context:
The current build has CodeSystem active in source/fhir.ini and now represents the lookup operation in source/codesystem/operationdefinition-CodeSystem-lookup.xml. Later operation-definition refactoring and FHIR-22807-related formal typing work changed how allowed concrete types are encoded, but preserved decimal for both lookup property value parts. Jira, Zulip, and Confluence searches found no later contrary decision for FHIR-14236.

AutoFHIR reconciliation:
This is an empty no-change audit commit. The current source already permits decimal values for CodeSystem.concept.property.value[x], includes decimal in the concept property type code system/value set, and permits decimal for both $lookup property.value and property.subproperty.value.

Keep this audit commit as-is for FHIR-14236. No core source follow-up is needed for this issue; FHIR-22807 is closely related formal-operation-definition tooling history and should be reconciled separately if selected.
