FHIR-13975: Audit Procedure reason wording

Issue request:
FHIR-13975 was Published/Persuasive with Modification for STU3 Patient Care Procedure. It reported that Procedure.reasonReference's description only mentioned Condition even though the element could also reference Observation; the final resolution kept the wording generic because workflow alignment was adding DiagnosticReport and DocumentReference, asking for the short "The justification that the procedure was performed" and definition "The justification of why the procedure was performed."

Initial application:
The issue was applied in the 2017-11-13 commit 52ac1cc0e7 alongside GF#13974 and GF#14063. That commit updated the Procedure spreadsheet so reasonReference allowed Condition, Observation, Procedure, DiagnosticReport, and DocumentReference, changed the short to the requested generic justification wording, and changed the definition to the requested generic justification sentence.

Additional context:
FHIR-14063 supplied the linked workflow-alignment context for adding DiagnosticReport and DocumentReference and is already represented on the combined branch. FHIR-13974 and FHIR-16346 clarified the same Procedure reason family. Current source no longer has separate Procedure.reasonCode and Procedure.reasonReference elements because the R5/R6 source represents them as Procedure.reason CodeableReference with concept/reference forms.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Procedure is active in source/fhir.ini, and the current Procedure.reason source already carries the requested generic short text, a generic definition that covers coded, text, and referenced justifications, and target profiles for Condition, Observation, Procedure, DiagnosticReport, and DocumentReference.

Recommendation:
Keep this audit as-is. The current source satisfies FHIR-13975 after accounting for later CodeableReference refactoring; any future target-profile changes, such as resources added or removed by later R6 issues, should be handled under those separate Jira keys.
