FHIR-11386: Audit eligibility benefit exclusion indicator

Issue request:
FHIR-11386 was a Published/Persuasive with Modification Financial Management change request from the DSTU2 ballot asking for a 0..1 boolean negation indicator on EligibilityResponse benefits to indicate that a benefit is not covered under the plan. The final resolution expanded the request to add an excluded 0..1 boolean to both EligibilityResponse and EOB.

Initial application:
The current git history does not contain a commit message explicitly naming FHIR-11386, but the relevant source was applied before this reconciliation: commit d1be564fe0a5fed4f38a2dbb1b4f5fc16f106a20 added boolean excluded rows to the legacy EligibilityResponse and ExplanationOfBenefit spreadsheets. The old EligibilityResponse row later became the current CoverageEligibilityResponse insurance item exclusion element, and the EOB row became the current ExplanationOfBenefit benefitBalance exclusion element.

Additional context:
CoverageEligibilityResponse and ExplanationOfBenefit are active current-build resources in source/fhir.ini, while source/fhir.ini maps the old EligibilityResponse name to CoverageEligibilityResponse. FHIR-11396 is the companion EOB issue with the same final change family and is already represented on the combined branch by d17e50d2e9b565e3bfb5769b93ca877742872b9b, so this commit audits only FHIR-11386. Searches of Zulip and Confluence found no later decision or community discussion changing the requested excluded-benefit semantics.

AutoFHIR reconciliation:
No source change was made. The current active StructureDefinitions already include CoverageEligibilityResponse.insurance.item.excluded and ExplanationOfBenefit.benefitBalance.excluded as 0..1 boolean elements with definitions saying true means the class/product/service is excluded from the plan and missing/false means it is included in coverage.

Recommendation:
Keep this empty audit commit as-is. No follow-up source work is needed for FHIR-11386 unless the Financial Management work group wants to revisit the location or wording of the existing excluded elements in a new issue.
