FHIR-15708: Audit ImplementationGuide input/output collapse

Issue request:
FHIR-15708 was a Published/Persuasive FHIR-I change request for STU3 to collapse the ImplementationGuideInput and ImplementationGuideOutput proof-of-concept resources back into ImplementationGuide. The approved resolution said ImplementationGuide should contain a definition portion and a manifest portion, with manifest generated during publication, while tooling profiles could express use-specific expectations.

Initial application:
No commit explicitly mentioning FHIR-15708 was found in the relevant source history. The apparent application is git b319b6a0dac9ca63360026abf48be963f7b143b9, "Rework ImplementationGuide after extensive discussion", which removed ImplementationGuideInput and ImplementationGuideOutput from active fhir.ini resource/work-group/status/code mappings, added those names to the removed-resources list, and reworked the ImplementationGuide source spreadsheet to include ImplementationGuide.definition and ImplementationGuide.manifest.

Additional context:
Current source/fhir.ini has implementationguide=ImplementationGuide in the active resources list and keeps ImplementationGuideInput and ImplementationGuideOutput only under [removed-resources]. The current StructureDefinition defines ImplementationGuide.definition as publisher input information and ImplementationGuide.manifest as assembled implementation guide information created by publication tooling. The example instance contains both definition and manifest. A Zulip IG Tooling SIG thread shows the earlier input/output proof-of-concept discussion and Lloyd McKenzie's note that the split might be squashed back together; no Confluence reference or later community evidence was found that reverses the Jira/source conclusion. Later ImplementationGuide issues such as FHIR-24826 refined adjacent asset/manifest behavior but do not undo the definition/manifest collapse.
