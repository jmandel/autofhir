FHIR-9969: Audit narrative jump renderer scope

Issue request:
FHIR-9969 was a Published/Persuasive DSTU2 FHIR-core change request asking for an easy "jump past narrative" affordance in the pretty-printed XML and JSON rendering of resources because generated narratives can be large.

Initial application:
The Jira comment records svn revision 11502. The corresponding git-svn commit e6adfacc23 added <%past-narrative-link%> only to source/template-example-xml.html even though the commit subject named both XML and JSON. The historical publisher code supported the placeholder for XML example pages when the renderer passed narrative state, but JSON pages were generated from template-example-json.html without passing narrative state.

Additional context:
The template files moved to tools/templates and remain part of the current build inputs consumed by the external Kindling publisher dependency. Current tools/templates/template-example-xml.html still contains the placeholder, while tools/templates/template-example-json.html still has no matching placeholder. The current Kindling source used by this checkout still loads both templates from tools/templates, still implements <%past-narrative-link%> in PageProcessor, and still calls processPageIncludes for JSON pages without narrative state. Current CI-rendered XML and JSON example pages checked during reconciliation did not emit a "Jump past Narrative" link.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR core source change. Adding the XML placeholder again would be redundant, and adding it to the JSON template alone would still render blank with the current Kindling call path and would not create a JSON-side anchor after text.div. A complete fix belongs in the Kindling rendering implementation, with a coordinated core-template update if Kindling exposes a JSON-safe skip anchor.

Recommendation:
Keep this audit commit as an external-repo decision for the core branch. Follow up in HL7/kindling (or the active Kindling source repository) to pass narrative state for JSON example rendering and to generate stable skip targets for both XML and JSON pretty pages; then update the core templates only as needed to consume that fixed renderer behavior.
