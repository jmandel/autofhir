FHIR-17499: Audit operation FMM assignment support

Issue request:
FHIR-17499 was a Published/Persuasive FHIR-core FHIR-I issue asking for a way to assign FMM to operations. The resolution was "Do this", and the Jira follow-up comment recorded that it was already done through an FMM column in the spreadsheet.

Initial application:
The linked Zulip thread shows the implementation path: Eric Haas asked how to assign FMM to core Observation $stats and $lastn, Grahame Grieve said operations had no way yet, then directed that an "fmm" column be added to the operations tab. The same-day source commit c82cf3a67b explicitly mentioned GF#17499 and added an fmm column to the Observation operations spreadsheet with value 3 for both stats and lastn. Follow-up commits bf5f44dfbf and 20e8b020b4 preserved those operation FMM values while adding/tracking trial-use standards status.

Additional context:
The 2021 source rework moved the old spreadsheet operation rows into standalone OperationDefinition XML. Current build-scoped Observation operation definitions retain the structuredefinition-fmm extension, and source/observation/list-Observation-operations.xml references both Observation-stats and Observation-lastn. FHIR-15974, the issue that needed the Observation operation FMM values, is already represented on the combined branch by e8787948e6fec08ac11144f1967c942233f213f5, so this audit does not duplicate that value/status decision. FHIR-14295 separately resolved that operation FMM display did not require an operations-list column once each operation had its own page with its own maturity level.

AutoFHIR reconciliation:
Made no source change. The current source already has a way to assign operation-level FMM, now expressed directly as structuredefinition-fmm extensions on OperationDefinition resources, and the historically motivating Observation operations are active build inputs with FMM 3.

Recommendation:
Keep this no-change audit. Future operation maturity changes should continue to set the OperationDefinition-level structuredefinition-fmm metadata (or the active generator input that produces it) rather than adding redundant narrative or re-auditing the already-decided FHIR-15974 values.
