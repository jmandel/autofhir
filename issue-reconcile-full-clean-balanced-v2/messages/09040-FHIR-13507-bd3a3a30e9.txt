FHIR-13507: Audit Binary FHIR content handling

Issue request:
FHIR-13507 was a Published/Persuasive, non-substantive STU3 FHIR-core Binary issue. It asked for clearer REST behavior when Binary content itself uses application/fhir+xml or application/fhir+json: an explicit FHIR Accept request should return the Binary resource wrapper in the requested FHIR XML/JSON format, not unwrap and transcode the stored data; the rule is for explicit FHIR MIME types rather than generic XML/JSON; and _format overrides Accept and is interpreted as a standard FHIR MIME request even when a generic value is supplied.

Initial application:
The issue was applied in svn revision 14354, represented in git as 4c0d34042c3e8742eda89fdb336da09c622aa009, alongside FHIR-16886. That commit rewrote source/binary/binary-notes.xml into the current list-based REST guidance, added the explicit FHIR Accept behavior, preserved direct native-content return for other Accept types, moved _summary guidance into the non-FHIR return bullet, added the generic XML/JSON caveat, and added the _format override rule. Later Binary edits kept this behavior while cleaning up wording, capitalization, and a duplicated bullet.

Additional context:
Binary is active in the current build through source/fhir.ini and remains part of the infrastructure normative package. FHIR-16886, FHIR-17026, FHIR-17027, FHIR-18338, FHIR-32955, and FHIR-37381 are adjacent Binary REST wording issues that restructure, normalize, or de-duplicate the same list without reversing FHIR-13507. FHIR-19254 is a later Resolved - No Change issue about testing/validation of Binary retrieval behavior and did not request a specification text change. Community searches found only bot notifications or later quotations of the current Binary text, and no Confluence reference or Zulip discussion that conflicts with the source/history conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active Binary narrative already says that a read request with a FHIR type in Accept returns the Binary resource in the requested FHIR format even when the binary data itself has a FHIR MIME type, that _format overrides Accept and is interpreted as standard FHIR MIME types, and that generic XML/JSON handling remains separate from explicit FHIR MIME handling.

Recommendation:
Keep this no-change audit commit as-is. The accepted clarification is already present in authoritative current source; any future operation, query parameter, or header to force native retrieval of FHIR-typed Binary content would be a new feature request rather than an unapplied part of FHIR-13507.
