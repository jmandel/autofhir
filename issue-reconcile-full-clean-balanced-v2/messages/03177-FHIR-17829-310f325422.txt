FHIR-17829: Audit MedicationRequest instantiates status

Issue request:
FHIR-17829 was Published/Persuasive with Modification for STU3. It asked to rename MedicationRequest.instantiates to MedicationRequest.instantiatesUri and add a 0..* MedicationRequest.instantiatesCanonical pointing to ActivityDefinition and PlanDefinition.

Initial application:
The issue was initially applied in pharmacy source history. Commit 0dc58a9d250574709305daa6144fa8020520fec6, matching the Jira comment's 65133c5 reference in this repository's history, changed the MedicationRequest spreadsheet from instantiates to instantiatesCanonical plus instantiatesUri and updated the example element name.

Additional context:
Later workflow work changed the interpretation of the original request. FHIR-29261 approved dropping instantiatesCanonical and instantiatesUri from the Request/Event workflow patterns and replacing them with more precise workflow extensions. Pharmacy then applied that direction through FHIR-24100; its Published Jira comments and Pharmacy minutes state that MedicationRequest and MedicationAdministration instantiates attributes needed to be removed. Commit ece63351c6107ee2d837bd8bdc64871ad186dc4c removed MedicationRequest.instantiatesCanonical and MedicationRequest.instantiatesUri from the active MedicationRequest StructureDefinition, and source/fhir.ini records those elements as R5-to-R6 removals.

AutoFHIR reconciliation:
No source change is needed. The current active MedicationRequest resource intentionally no longer has either instantiates element, and the current workflow extension notes explain that prior instantiatesCanonical/instantiatesUri elements have been replaced by distinct workflow extensions.

Recommendation:
Keep this empty audit commit as-is. Do not re-add MedicationRequest.instantiatesCanonical or instantiatesUri for FHIR-17829; any future change to local MedicationRequest guidance should be handled under the later workflow-extension issue family, not as a replay of the STU3 tracker.
