FHIR-40631: Audit RequestOrchestration basedOn coverage

Issue request:
FHIR-40631 was an Applied, Persuasive with Modification OO change request for R6. It asked to add basedOn to VisionPrescription and to allow RequestOrchestration as a basedOn reference target for ServiceRequest, VisionPrescription, NutritionOrder, and DeviceRequest.

Initial application:
The change was partly applied before this reconciliation. Commit 647632b6786c032fd09b6ee3c70ef9d7c0ba1d3a, later merged through PR #3105, added RequestOrchestration to ServiceRequest.basedOn and introduced VisionPrescription.basedOn with CarePlan, RequestOrchestration, NutritionOrder, and ServiceRequest targets. Commit 1dc1c4ae89127b3ac2794da0d1d5bf9a8bbf9d5c added RequestOrchestration to NutritionOrder.basedOn. DeviceRequest.basedOn already targeted Reference(Resource) before the FHIR-40631 implementation, so RequestOrchestration was already allowed there.

Additional context:
All four affected resources are active in source/fhir.ini and their StructureDefinition XML files feed the current build. The current source explicitly includes RequestOrchestration for ServiceRequest.basedOn, NutritionOrder.basedOn, and VisionPrescription.basedOn. DeviceRequest.basedOn remains Reference(Resource), with its Request-pattern mapping exception documenting the broader resource target; adding RequestOrchestration beside Resource would be redundant rather than a semantic correction. Confluence OO minutes confirm the same Persuasive with Modification motion. Pharmacy's MedicationRequest follow-up was handled as separate FHIR-40633/FHIR-41561 work and is not decided here. FHIR-54619 is a later Resolved - change required ServiceRequest alignment issue, but it is not in the Applied/Published source-edit scope for this seed.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already permits RequestOrchestration in every location requested by FHIR-40631, and the only non-explicit case, DeviceRequest, is broader than the requested target.

Recommendation:
Keep this audit commit as-is. Future work on ServiceRequest.basedOn/replaces alignment should be tracked under FHIR-54619 or its applied successor, not as a FHIR-40631 correction.
