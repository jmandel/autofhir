FHIR-22748: Audit Observation reference range units

Issue request:
FHIR-22748 was an Applied OO change request asking for a way to specify units on Observation.referenceRange because ranges may use units different from the observation value. Its final Not Persuasive with Modification resolution, after reopening the earlier disposition, was to revert the prior datatype change and use SimpleQuantity because SimpleQuantity already includes units.

Initial application:
The issue was first applied by e9552da68ef21fe3c1c6e6ccb06a0771f5b80cd5, which changed Observation.referenceRange.low and .high from the SimpleQuantity profile to unprofiled Quantity. The work group then reopened the issue, and c326984f5ac6ee9b4363c791e2ab01310b447ccd reverted that change back to SimpleQuantity, matching the final FHIR-22748 resolution.

Additional context:
Observation is an active current-build resource in source/fhir.ini, and the authoritative source is source/observation/structuredefinition-Observation.xml. A later Applied OO issue, FHIR-51566, explicitly changed Observation.referenceRange.low and .high from SimpleQuantity to Quantity for R6 so Quantity.comparator can express exclusive bounds while absent comparator preserves the earlier inclusive meaning. Current source reflects that later decision with unprofiled Quantity plus obs-13 and obs-14 constraints, so the current Quantity datatype is not an unapplied FHIR-22748 regression.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Reverting the current source to SimpleQuantity would undo the later Applied FHIR-51566 decision, while the current Quantity datatype still carries value, unit, system, and code and therefore continues to satisfy the original unit-support concern.

Recommendation:
Keep this no-change audit as-is for FHIR-22748. Any future reconsideration of comparator support or generated diagram freshness should be handled under FHIR-51566 or a new issue, not by reapplying FHIR-22748 against the current source.
