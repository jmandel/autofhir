FHIR-31032: Audit SNOMED semanticTag documentation

Issue request:
FHIR-31032 was Published/Persuasive for R5 by Vocabulary WG and asked to expose the SNOMED CT semantic tag as a code-valued concept property named semanticTag, defined as the phrase inside the last set of brackets of the Fully Specified Name.

Initial application:
The issue was applied in commit 0bcb947d8488b993d882cc96e556cb3d1e84a94e, which added semanticTag to the SNOMED CT concept properties table in source/snomedct.html alongside related SNOMED properties. That old page is no longer present in current core source.

Additional context:
FHIR-35933 and UP-289 later moved the external-code-system "Using X with FHIR" pages, including SNOMED CT, out of FHIR core and into HL7 Terminology. Current core source keeps only the SNOMED CT Usage Summary in the FHIR hierarchy and links the SNOMED CT external-code-system row to the authoritative THO page. The current THO English SNOMED CT page documents semanticTag in the SNOMED CT Properties table.

AutoFHIR reconciliation:
No source change was made. Re-adding the old SNOMED CT properties table to core would duplicate content that was intentionally migrated to THO; the current FHIR source already points implementers to that authoritative page and the migrated page contains the requested semanticTag property.

Recommendation:
Keep this audit commit as-is for FHIR core. If the THO page is later changed or localized variants lose the semanticTag row, handle that through the THO/UTG process rather than by restoring the retired core page.
