FHIR-13735: Audit Consent policyRule comment migration

Issue request:
FHIR-13735 was Published/Persuasive with Modification for FHIR-core Consent. It asked to revise the poorly written Consent.policyRule comment, set the old policyRule definition to a specific base computable policy reference, set the old provision definition/short to constraints to Consent.policyRule, and state that when policyRule is absent computable consent must be constructed from the Consent resource elements.

Initial application:
Commit cf9f7092b2d0d538f29e0b989f5c63e50e0738f7 applied the STU3-era request to source/consent/consent-spreadsheet.xml, changing the policyRule definition/comment and the Consent.provision summary text. A later same-area commit for FHIR-13358 changed old policyRule from URI-style opt-in/opt-out usage to CodeableConcept examples, and later source migrations moved the authoritative resource definition from the spreadsheet into source/consent/structuredefinition-Consent.xml.

Additional context:
The current build no longer has an active Consent.policyRule element. Consent is active in source/fhir.ini, which maps retired Consent.policy and Consent.policyRule paths into the current Consent model. Later applied Consent work split the old policy concepts into policyBasis, policyText, decision, and provision semantics. Existing combined-branch reconciliations for FHIR-25387, FHIR-39597, and FHIR-45450 have already restored current-name fallback guidance, removed stale provision-zero guidance, and aligned the active policyBasis definition with URI-based computable policy identifiers. FHIR-53724 is a later Triaged issue about policyRule disappearance and is not final enough to decide here.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current active source already conveys the surviving FHIR-13735 semantics using current element names: policyBasis identifies a computable backing policy, policyBasis carries fallback guidance for absent policyBasis/policyText, provision is described as constraints/exceptions to the base policy, and Consent notes explain policyBasis/provision interaction. Reintroducing old policyRule wording would conflict with later current-model terminology.

Recommendation:
Keep this no-change audit. Future work on whether the retired policyRule concept should map differently or be further explained should proceed through the unresolved current R6 issue family, not through this already-applied STU3 comment revision.
