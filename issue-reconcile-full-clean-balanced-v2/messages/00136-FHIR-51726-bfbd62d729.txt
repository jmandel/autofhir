FHIR-51726: Audit medication request category core migration

Issue request:
FHIR-51726 is Applied/Persuasive for R6 and asked to move the MedicationRequestAdministrationLocationCodes content back into the FHIR Core specification rather than treating it as a THO code system. The approved application changed the canonical/id to http://hl7.org/fhir/ValueSet/medicationrequest-category and http://hl7.org/fhir/CodeSystem/medicationrequest-category and renamed the category terminology away from the administration-location-only name.

Initial application:
PR HL7/fhir#3896 applied the issue in commits 4a73291f0c and c23f0477b6 by adding source/medicationrequest/codesystem-medicationrequest-category.xml, renaming the value set source to valueset-medicationrequest-category.xml, and updating the active MedicationRequest.category and MedicationStatement.category bindings to the new core ValueSet. Commit 2571d5b4b2, merged through PR HL7/fhir#3911, completed the category naming cleanup for the value set while adding later ballot-note context.

Additional context:
FHIR-50142 and FHIR-31632 are the same pharmacy example-terminology move-back-to-core family and support the core-source location. UP-555 was the unresolved UTG proposal cited as evidence that this should not be handled as a THO change. A later FHIR-53306/PR #3911 trail and Pharmacy/Zulip notes added ballot notes saying these category code systems may still move to THO after broader review; that related issue is not Applied/Published and should not be decided here. Later FHIR-55335 and FHIR-55337 remain unresolved candidate-THO-migration issues.

AutoFHIR reconciliation:
