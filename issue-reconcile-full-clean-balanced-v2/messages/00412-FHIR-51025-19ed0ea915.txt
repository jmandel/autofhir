FHIR-51025: Add TestScript fixture expression model metadata

Issue request:
FHIR-51025 was Applied with a Persuasive with Modification resolution for R6. It asked to enhance TestScript fixtures so a fixture can define a sub-fixture extracted from fixture.resource, with the final resolution adding only TestScript.fixture.expression, using the Expression data type, and also requiring TestScript.fixture.resource to be 1..1.

Initial application:
The request appears to have been initially applied in core by ba91e922ce318538784226167ba47b70cf786729, merged through HL7/fhir#3508 alongside FHIR-51024 and FHIR-51111. That commit added TestScript.fixture.expression as an Expression-typed element and updated TestScript examples, but the source/testscript StructureDefinition still left TestScript.fixture.resource at 0..1 and the active FHIR model-definition Library did not receive the new TestScript.Fixture.expression metadata.

Additional context:
FHIR-I minutes for 2025-06-23 record the Persuasive with Modification vote for FHIR-51025. Later commit f9a44787c45071394532c7c2ee94d76f30f47387 removed TestScript, TestReport, and TestPlan from the active core resource list and added the FHIR Testing IG reference; current source/fhir.ini and source/ballot-intro.html point TestScript readers to that external IG. The current FHIR Testing IG source includes TestScript.fixture.expression as Expression, but TestScript.fixture.resource still has minimum 0, so the resource cardinality part of FHIR-51025 now belongs in HL7/fhir-testing-ig rather than in core. The core Library resource remains active, publish.ini copies library-fhir-model-definition-content.xml, and the 6.0.0 model-definition content still exposed TestScript.Fixture without the new expression element.

AutoFHIR reconciliation:
This commit updates the current build-scope FHIR model-definition Library by adding expression as FHIR.Expression to TestScript.Fixture, and regenerates the Library.data attachment so source/library/library-fhir-model-definition.xml stays synchronized with source/library/library-fhir-model-definition-content.xml. It intentionally does not re-add source/testscript or change TestScript.fixture.resource cardinality in core because the authoritative TestScript StructureDefinition is now external, and the model-definition artifact does not encode element minimum cardinalities.

Recommendation:
Keep this core source fix as-is. Follow up in HL7/fhir-testing-ig to either set TestScript.fixture.resource to 1..1 or record a later work-group decision that supersedes that part of FHIR-51025; do not restore the removed core source/testscript resource for this issue.
