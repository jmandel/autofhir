FHIR-34502: Align TestReport testScript ModelInfo

Issue request:
FHIR-34502 was a Published/Persuasive with Modification FHIR-I change request for R5. It asked to change TestReport.testScript from a normal RESTful Reference to a canonical reference because TestScript has a canonical URL; the resolution accepted the canonical type and noted that TestReport should not be constrained to only reports of TestScript-defined tests.

Initial application:
The Jira comment points to HL7/fhir#1767. Implementation commit 9dabc46e04, merged by 4961c84ad2, changed source/testreport/structuredefinition-TestReport.xml so TestReport.testScript used code="canonical" with targetProfile TestScript and changed the example from a nested Reference to a canonical value. That application did not update the FHIR ModelInfo Library example, which continued to expose TestReport.testScript as FHIR.Reference.

Additional context:
The authoritative TestReport resource source was later removed from this core checkout by f9a44787c4 as part of moving TestScript, TestPlan, and TestReport to the FHIR Testing IG; current source/fhir.ini points to that IG and source/ballot-intro.html lists TestReport there. The current Testing IG JSON already exposes TestReport.testScript as canonical, but this core build still publishes the FHIR ModelInfo XML through the Library examples and publish.ini. FHIR-38176 is another TestScript/TestReport issue discovered during the search, but it concerns requirement traceability links rather than this testScript type change and was not decided here.

AutoFHIR reconciliation:
Changed source/library/library-fhir-model-definition-content.xml so the active ModelInfo TestReport.testScript element uses FHIR.canonical instead of FHIR.Reference, then refreshed source/library/library-fhir-model-definition.xml so the embedded Library.data payload matches the standalone ModelInfo XML.

Recommendation:
Keep this source fix. It completes the published FHIR-34502 canonical-type decision on the remaining build-visible core ModelInfo surface; if the work group wants to revisit the Jira resolution's optionality/cardinality wording, that follow-up now belongs in the FHIR Testing IG because the current core ModelInfo surface does not carry element cardinalities.
