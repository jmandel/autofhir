FHIR-13718: Clarify DataRequirement filters

Issue request:
FHIR-13718 was a Published/Persuasive FHIR-core CDS change request for STU3 DataRequirement. It asked to clarify that codeFilter.path and dateFilter.path use a limited path-traversal-only FHIRPath subset, remove CodeableConcept/code value choices in favor of Coding values, change valueSetString to a value set identifier URI, rename the general value element to code, and document that a supplied value set plus codes match by either membership or explicit code.

Initial application:
The original application was SVN 12282, now git commit 0addae29fbde8e12ef0b43c9ebee34a08896f30c, which changed source/datatypes/datarequirement.xml for #13718. Current source already has the structural changes: codeFilter.valueSet is canonical(ValueSet), codeFilter.code is Coding, and codeFilter.path has Simple FHIRPath wording. The active narrative examples in source/metadatatypes.html still used the removed valueSetString element, the codeFilter.valueSet definition still conflicted with the Jira comment by implying valueSet-only matching, and the dateFilter.path comment still said "Simple FHIR Subset" rather than "Simple FHIRPath Subset".

Additional context:
source/fhir.ini actively maps datarequirement to the metadatatypes page and lists DataRequirement as a normative type, so both edited files feed the current build. Later FHIR-32373 added valueFilter modeled after codeFilter/dateFilter; its path comment carried the same copied "Simple FHIR Subset" typo, so this commit updates that sibling wording only to keep current DataRequirement filter path notes consistent. A 2020 Zulip thread confirms implementer confusion around DataRequirement.path versus searchParam but does not conflict with the Jira/source conclusion. Confluence searches found no conflicting work-group record.

AutoFHIR reconciliation:
Updated the active DataRequirement narrative examples to use the current valueSet element with a canonical example URI, clarified the codeFilter.valueSet definition so valueSet plus explicit codes match by value-set membership or by the supplied codes, and corrected dateFilter.path and the later valueFilter.path note to name the Simple FHIRPath Subset.

Recommendation:
Keep this source-changing commit. It completes the remaining FHIR-13718 semantics in the active current-build sources without reopening the already-applied structural changes; no separate FHIR-32373 decision is needed because the valueFilter edit is only a directly coupled wording consistency fix.
