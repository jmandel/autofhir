FHIR-32441: Audit AuditEvent subtype example binding

Issue request:
FHIR-32441 was Published/Persuasive with Modification for the Security work group. It objected that AuditEvent.subType used an extensible binding to an overlapping and very large detail-code value set, forcing implementers to map local detailed audit codes to one of those concepts, and requested an example binding to a small sample value set covering representative IHE audit transaction and REST action codes.

Initial application:
The issue was explicitly applied in 8df821d5192e9001a0ec828732c9b10c3f263fbc, which changed the AuditEvent.subtype binding strength from extensible to example. Related R5 AuditEvent work later renamed type/subtype to category/code in a4a8e4475ffed8a639ac458dba61b68da343891e, and current history subsequently restored type/subtype while preserving the example binding. The later QA commit 87b00c9c0de977f8559e0f99694e8664e03a06cd changed the binding target from audit-event-sub-type to audit-event-sub-type-example and added the active example ValueSet source.

Additional context:
AuditEvent is an active resource in source/fhir.ini, so source/auditevent/structuredefinition-AuditEvent.xml and source/auditevent/valueset-audit-event-sub-type-example.xml are current build inputs. FHIR-32443 is the same AuditEvent type/subtype change family and is already represented on the combined branch; FHIR-32470 is a neighboring lifecycle-code binding issue and is also already represented. The current checked-in SVG still has generated-looking links that omit the -example suffix, but the authoritative XML has Strength=Example and points to the example value set, so this audit does not manually edit diagram output.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already removes the extensible binding, keeps AuditEvent.subtype as a CodeableConcept with an example binding, and binds it to http://hl7.org/fhir/ValueSet/audit-event-sub-type-example.

Recommendation:
Keep this audit commit as-is. No core FHIR source follow-up is needed for FHIR-32441 unless the Security work group separately wants to curate a smaller illustrative subtype value set; that would be a new terminology/editorial decision rather than a missing application of this issue's core conformance requirement.
