FHIR-29803: Audit Bundle fullUrl text clarifications

Issue request:
FHIR-29803 was Published with a Persuasive with Modification resolution for R5. It asked FHIR-I to clarify the Bundle Resource URL & Uniqueness rules by using conformance language for fullUrl requirements, replacing the confusing "MAY not have fullURLs" wording with "MAY omit fullURLs", changing "There might" to "There MAY", fixing "informaton", and noting that the Using Bundles text could confuse readers when it mentioned resources without also mentioning fullUrl.

Initial application:
The issue was applied in c7eb855076a1d5d1ed930925352094a96d7d0807, which changed source/bundle/bundle-notes.xml in the Resource URL & Uniqueness section. A follow-up ballot QA commit, a41e7958c85a2583535192048e11abfbfdf13be4, corrected the accidental "SHALL must" wording left by the first application. No prior Issue-Reconcile-Key commit for FHIR-29803 was present on the combined branch.

Additional context:
Bundle is an active resource in source/fhir.ini, so source/bundle/bundle-notes.xml and source/bundle/structuredefinition-Bundle.xml are current build inputs. The current Bundle notes retain the FHIR-29803 changes: entries outside batch/transaction scope SHALL have fullUrl, UUIDs SHALL be used in fullUrl when no persistent identity is available, batch/transaction entries MAY omit fullUrl under the later refined exception rule, multiple versions MAY appear, and the "information" typo is fixed. The current Using Bundles introduction says all bundle types use resource identity resolution described below, and the nearby fullUrl section plus bdl-15/Bundle.entry.fullUrl definition carry the requirement, so repeating fullUrl beside every resource sentence would be redundant and risk drift. Later fullUrl issues, especially FHIR-27813 and FHIR-43106, refined the formal definition and exception wording; FHIR-43106 is already represented on the combined branch.

AutoFHIR reconciliation:
Published an empty no-change audit commit. The current source already conveys the FHIR-29803 decision in the authoritative Bundle narrative and formal Bundle.entry.fullUrl surfaces, and no additional seed-scoped source hunk is necessary.

Recommendation:
Keep this audit commit as-is. No further FHIR-29803 source change is recommended; any future desire to restyle the later Bundle.entry.fullUrl ElementDefinition opening sentence should be handled under a separate fullUrl-focused tracker rather than by expanding this seed.
