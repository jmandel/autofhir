FHIR-24692: Audit type-characteristics implementation

Issue request:
FHIR-24692 was a Published/Persuasive FHIR-core StructureDefinition change request asking for an explicit way to record datatype/type characteristics such as whether a type can be bound, ranged, length-constrained, or otherwise constrained, so tooling for FHIR and logical models would not have to rely only on a closed enumeration of core datatypes.

Initial application:
No current combined-branch audit already represented FHIR-24692. The issue appears to have been applied before this reconciliation through unkeyed core commits: 0d7712ab28 added the type-characteristics extension, code system, and value set to the R5 core source; d196630c2c added the active [type-characteristics] mapping in source/fhir.ini; and 0e2302e482 added the datatype type-characteristics summary table to source/datatypes.html. Later core history moved extension definitions out of core in dd468d4f17, while retaining the active core type-characteristics data.

Additional context:
The current Extension Pack checkout defines StructureDefinition/structuredefinition-type-characteristics with context StructureDefinition, valueCode, required binding to ValueSet/type-characteristics-code, and root max="*". Related Extension Pack trackers FHIR-40843 and FHIR-41436 corrected that cardinality to 0..*, FHIR-41599 added can-be-target, and FHIR-44357 handled description punctuation. Current core source still contains OIDs for the canonical URLs, an active [type-characteristics] section in source/fhir.ini, and a datatypes page table that links to the Extension Pack CodeSystem using [%extensions-location%]. Zulip discussion after R5 confirms implementers use the extension for logical model characteristics and later issues are extension-pack refinements, not missing core source work.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core checkout already carries the build-scoped datatype characteristic assignments and documentation, while the extension, code system, and value set are now maintained in the FHIR Extension Pack. Reintroducing those extension definitions into core, or adding redundant core prose, would conflict with the current extension-pack ownership model and would not change implementer understanding of FHIR-core.

Recommendation:
Keep this audit commit as-is for FHIR-core. If future work changes the extension definition, its value set, or additional logical-model characteristic codes, perform that work in the FHIR Extension Pack and keep core limited to the active type-characteristics data and references it needs for the core build.
