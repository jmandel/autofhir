FHIR-3187: Audit binding strength terminology clarification

Issue request:
FHIR-3187 was Published/Persuasive with Modification for DSTU1 and asked that binding conformance, extensibility, and their named cross-product terms be clarified. The accepted motion adopted a single ElementDefinition.binding strength element with required, extensible, preferred, and example codes and called for related value-set extension handling.

Initial application:
The Jira comments record "svn 4300 per agreed change + svn 4362 for extension". The git-svn build@4300 commit f45d3ec3d1 added ElementDefinition.binding.strength, inactivated the old isExtensible and conformance rows in the ElementDefinition spreadsheet, and updated the terminology narrative for the new codes.

Additional context:
FHIR-5781 is the same change family and asks the same rationalization for ElementDefinition.binding. The current source has evolved from the original extension approach: ElementDefinition.binding.additional now supports additional binding purposes, the terminology page says maximum/minimum additional bindings replace the old max/min value-set extensions, and the Extension Pack retains retired/deprecated maxValueSet and minValueSet definitions that direct users to additionalBinding.

AutoFHIR reconciliation:
No source change was made. The current build-scope source already contains the single strength element and current binding-strength definitions, while the former conformance/extensibility split is not active source.

Recommendation:
Keep this audit commit as-is. FHIR-3187 is already reflected in current core source; no follow-up is needed unless the work group wants to revisit the newer additional-binding replacement for the old extensions.
