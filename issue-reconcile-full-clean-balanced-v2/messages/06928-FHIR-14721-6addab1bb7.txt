FHIR-14721: Audit EntryDefinition rename status

Issue request:
FHIR-14721 was an Applied/Persuasive OO FHIR-core change request raised against the STU3 EntryDefinition draft and applied for R4. It asked for a more meaningful resource name because "EntryDefinition" did not tell implementers how or where the resource would be used; the accepted resolution was to rename the resource to "CatalogEntry".

Initial application:
No current git commit explicitly mentions FHIR-14721, but commit d881c57c69c8f8bc0f0f01a37255f23090629f59 directly applied the requested rename by changing active build-support entries from EntryDefinition to CatalogEntry in source/fhir.ini, source/hierarchy.xml, source/history.html, source/resourcelist.html, and related CatalogEntry source files. A contemporaneous Zulip committers thread announced the EntryDefinition-to-CatalogEntry rename and listed the same supporting files for review. OO WGM minutes from 2018-10-03 also record that EntryDefinition had been renamed to CatalogEntry and that tracker 14721 was voted Persuasive.

Additional context:
Later CatalogEntry issues changed the current build scope. FHIR-30632 recorded the intermediate intent to remove CatalogEntry in R5, and FHIR-28177 then removed CatalogEntry from the active core build because OO concluded it was no longer useful or maintained. Commit 47b44e3ba15773f30f6d96fb210fd61213363a88 removed catalogentry from active source/fhir.ini build entries and deleted source/catalogentry. The combined branch already contains audits for FHIR-30632 and FHIR-28177, so this commit does not duplicate those decisions. Current source/fhir.ini has no active catalogentry or entrydefinition entry; remaining source/entrydefinition files are stale/out of build scope, while CatalogEntry appears only in historical removed-resource metadata.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The R4 rename requested by FHIR-14721 was applied in the active resource lineage, and the current specification no longer has an active EntryDefinition/CatalogEntry resource to rename. Editing the leftover source/entrydefinition directory would not affect the current build and would be repository hygiene rather than a current-spec reconciliation fix.

Recommendation:
Keep this no-change audit as-is. No core source follow-up is recommended for FHIR-14721 unless a future work group decision revives the retired resource; in that case, the historical name should remain CatalogEntry unless a new Jira decision says otherwise.
