FHIR-32070: Audit search summary table cleanup

Issue request:
FHIR-32070 was a Published/Persuasive with Modification FHIR-core request to clean up the Search page Summary Table because it mixed search parameter types, common search parameters, search-result query parameters, and generic interaction parameters. The accepted resolution called for treating the top-level summary table as navigation/table-of-contents material, adding links to the relevant sections, providing consistent navigation for each search parameter type, and working through the details before FHIR-I approval.

Initial application:
The issue appears to have been applied by commit 6de659813447c8357c3c567cc7a730264c2741e6, which removed the old single mixed "Summary Table" grid from source/search.html, kept the dedicated Summary Tables section, split it into common-resource parameters and search-control parameters, added missing anchors such as _containedType and _text, and pointed entries at the detailed parameter sections. Later source history, including FHIR-41459, refined the Contents anchor for the Summary Tables link.

Additional context:
The current Search page source is active build source through source/hierarchy.xml and the source/fhir.ini search-rules note that maintainers must update the search.html summary table when datatype search-rule mappings change. FHIR-I minutes record the initial assignment to Gino to work through proposals and discuss on Zulip, followed by a May 2022 Persuasive with Modification vote. Community searches found no directly relevant Zulip thread or later conflicting decision for FHIR-32070. The later FHIR-41459 correction is already represented on the combined branch and confirms that the intended top Contents entry is "Summary Tables" linking to #table, not to the _summary subsection.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already removes the confusing mixed table, gives the Search page a Contents section with direct links to search parameter type sections and standard/search-control subsections, and retains separate Summary Tables for common parameters, search-control parameters, and the datatype-to-search-type cross-map. Renaming the existing "Contents" heading to "Table of Contents" would be editorial-only and would not change implementer understanding.

Keep this audit commit as-is. No further FHIR-core source change is needed for FHIR-32070 unless the work group wants a purely editorial heading rename in a future issue.
