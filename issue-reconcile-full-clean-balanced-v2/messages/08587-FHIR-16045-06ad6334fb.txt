The final resolution states that the request was addressed as part of FHIR-16044 by adding extensions; comments explicitly say the capability should be an extension, not part of core.

Initial application:

No prior Issue-Reconcile-Key commit for FHIR-16045 was present on the combined branch.

Additional context:
FHIR-16044 supplies the detailed parent resolution for both the Questionnaire signature-required extension and the QuestionnaireResponse signature extension. The current core QuestionnaireResponse StructureDefinition is an active build resource but intentionally has no core signature element. Core later moved standard extension definitions out of the R5 source; the current FHIR Extension Pack contains questionnaireresponse-signature as an active extension, and the core Signature datatype page still links to that extension. Later Zulip discussion still treats the extension as the standard way to carry a QuestionnaireResponse signature and does not record a final decision to remove it.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The current extension-based state satisfies the published modified resolution, and adding QuestionnaireResponse.signature to the core resource would be a new, contrary change.

Recommendation:
