FHIR-32439: Audit AuditEvent type binding

Issue request:
FHIR-32439 is a Published/Persuasive Security WG change request for R5. It objected that the AuditEvent.type binding was extensible and asked for the binding strength to become example, with the value set treated as example guidance rather than a closed or extensible conformance expectation.

Initial application:
The issue was initially applied by 54eab8c354 on 2021-10-02, which changed source/auditevent/structuredefinition-AuditEvent.xml from <strength value="extensible"/> to <strength value="example"/> for AuditEvent.type. Later source history renamed the referenced value set to audit-event-type-example and updated the authoritative XML and narrative links, so the current build source points AuditEvent.type at an example value set.

Additional context:
Security WG minutes and the linked Zulip block-vote thread show FHIR-32439 was part of the September 13, 2021 AuditEvent/Provenance block vote as Persuasive. Related FHIR-32443 drove type/category and subtype/code naming churn in the same AuditEvent family, but the current source has since returned the active element path to AuditEvent.type while preserving the example binding intent. The active resource entry in source/fhir.ini confirms source/auditevent feeds the current build. The remaining old audit-event-type link found in auditevent.svg is a generated-looking diagram artifact; the authoritative StructureDefinition and narrative source are already correct, so this reconciliation does not edit the SVG.
