FHIR-29774: Add Consent treatment service example

Issue request:
FHIR-29774 is Applied / Persuasive with Modification. It asked for Consent to show how a patient can block a healthcare service type, such as food bank or Meals On Wheels services, and the final resolution was to create an example using Consent.provision.code under the Treatment category code.

Initial application:
No prior source commit mentioning FHIR-29774 or 29774 was found in the local git history, and the combined branch had no Issue-Reconcile-Key entry for FHIR-29774. The current Consent source already had Consent.provision.code and a provision-code search parameter, but existing examples used provision.code for CDA document codes under privacy-oriented consent examples; none showed a Treatment-category consent denying a service type.

Additional context:
Consent is an active current-build resource in source/fhir.ini, and the historical Consent.scope mapping records that scope was merged into Consent.category. The current Consent category value set includes the terminology.hl7.org consentscope system, while the current provision model uses Consent.decision as the base permit/deny decision and first-level provisions as constraints or exceptions. FHIR-39597 and FHIR-41456 are related background because they already updated the current provision model and provision-code search parameter on the combined branch, but neither supplied the requested treatment service-type example. THO service-type code 6 is Delivered Meals (Meals On Wheels), matching the Jira use case directly.

AutoFHIR reconciliation:
Added a current-build Consent example and registered it in the Consent examples list. The example uses category consentscope/treatment, a base permit decision, and a first-level provision.code coded as service-type/6 Delivered Meals (Meals On Wheels), so the current provision exception model shows treatment generally permitted while the matching delivered-meal service type is denied.

Recommendation:
Keep this source-changing commit as-is. Further work would only be needed if CBCC wants to broaden the illustrative Consent.provision.code value set or add normative constraints for treatment-scope consent, which is outside this Jira's applied resolution.
