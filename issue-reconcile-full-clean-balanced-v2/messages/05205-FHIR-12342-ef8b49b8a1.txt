FHIR-12342: Audit Endpoint connectionType cardinality

Issue request:
FHIR-12342 was Published/Persuasive with Modification for R5. It reported that the Endpoint connection type value set could not express XDS/XCA details well enough as a single value, and the final PA resolution was to update Endpoint.connectionType cardinality from 1..1 to 1..* rather than adding separate core codes for every IHE transaction.

Initial application:
No prior source commit in the local git history explicitly names FHIR-12342. The same approved cardinality change was applied through the related FHIR-34261 implementation commit 445d4741d1559c197decca8343f60d1cad753d36, which changed source/endpoint/structuredefinition-Endpoint.xml by setting Endpoint.connectionType max="*" and adding the comment that multiple payload types or mime types apply across all connection types.

Additional context:
Endpoint is active in source/fhir.ini, so source/endpoint feeds the current build. Related FHIR-34261 is already represented on the combined branch and audits the same Endpoint cardinality family. Later FHIR-36589, also already represented on the combined branch, changed Endpoint.connectionType from Coding to CodeableConcept and relaxed its binding to example so IHE-specific connection codings can be carried without expanding core's example value set; current source also points IHE connection types to the IHE mCSD profile/vocabulary. FHIR-36327 later declined to make Endpoint.connectionType optional, so the current 1..* cardinality remains intentional.

AutoFHIR reconciliation:
No source change was made. The active current Endpoint source already has Endpoint.connectionType min="1" and max="*", uses CodeableConcept with an example binding, and includes an XCA example with multiple connectionType repetitions using IHE mCSD codes. This satisfies FHIR-12342's final applied resolution without adding redundant or conflicting core terminology.

Recommendation:
Keep this no-change audit commit as-is. Do not add new XDS/XCA core connection-type codes for this seed; future changes to Endpoint connection terminology should follow the later Endpoint/IHE tracker family or IHE mCSD vocabulary work rather than reopen the already-applied FHIR-12342 cardinality decision.
