FHIR-19634: Audit AllergyIntolerance clinical status definitions

Issue request:
FHIR-19634 was a Published / Persuasive with Modification Patient Care change request for STU3 asking that the AllergyIntolerance clinical status CodeSystem definitions be changed to: active means currently experiencing or at risk of a reaction, inactive means no longer at risk, and resolved means clinically reassessed and considered no longer present after testing or re-exposure.

Initial application:
The issue was applied by cccb69d8142e, which changed source/allergyintolerance/codesystem-allergyintolerance-clinical.xml to the requested definitions and also carried the separately tracked FHIR-19633 comment changes in the same commit. The corrected definitions are present in R4 package artifacts, so the original code-definition change was not missed.

Additional context:
The authoritative CodeSystem source is no longer in core: 5c0494aacfd0 removed the AllergyIntolerance clinical CodeSystem XML as part of removing UTG content from the core build. Current core source keeps AllergyIntolerance active in source/fhir.ini and defines the active value set in source/allergyintolerance/valueset-allergyintolerance-clinical.xml, which includes http://terminology.hl7.org/CodeSystem/allergyintolerance-clinical. The current THO CodeSystem 1.0.1 still carries the corrected active, inactive, and resolved definitions. Later FHIR-36742/Zulip discussion concerned making the nested inactive/resolved hierarchy easier to see, and was resolved as a publisher/rendering issue, not a change to these definitions.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current FHIR core checkout no longer owns the CodeSystem definitions, and the external terminology artifact used by the current value set already matches the FHIR-19634 decision in substance.

Recommendation:
Keep this audit commit as-is. Future substantive edits to these code definitions should be made through the THO/UTG terminology source, while core should continue to reference the external CodeSystem unless a separate final Jira decision changes that ownership model.
