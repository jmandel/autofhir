FHIR-20465: Audit Element.id snapshot consistency

Issue request:
FHIR-20465 was a Published/Persuasive FHIR-I correction raised against the FHIR 4.0.0 definitions JSON. It reported that Element.id's base definition carried the special string serialization/type metadata while snapshots for Element subtypes such as BackboneElement.id, string.id, and boolean.id appeared to replace that inherited type with a plain string entry. The approved resolution said the differential was correct and the snapshot needed correction; Jira records Applied for Version R5 and later notes that R5 was consistent while an R4/R4B technical correction was unlikely.

Initial application:
No FHIR core source commit directly tagged with FHIR-20465 was found. The relevant in-repository history after the issue and before R5 is the 2019-12-10 abstract type framework rebuild, which made Element, BackboneElement, PrimitiveType, DataType, and Base active abstract datatype sources. The current build-scope source defines Element.@id once as type string, and BackboneElement inherits Element without declaring its own id row.

Additional context:
The original Zulip thread confirms this was a generated snapshot validity problem: derived snapshots should not replace Element.id with an incompatible type, and the official snapshots should be corrected. Later same-family id metadata issues such as FHIR-36036, FHIR-38684, FHIR-41183, FHIR-22493, FHIR-25274, and FHIR-25262 have separate audits already represented on the combined branch and clarify the current System.String plus structuredefinition-fhir-type behavior. Historical R4/R4B/R5 publication artifacts still vary in fhir-type details, but current source reconciliation should not patch old published release caches, and the seed explicitly records that R4/R4B technical correction was unlikely.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative current source is in build scope through source/fhir.ini, Element.@id is type string, BackboneElement has no divergent id row, and current build.fhir.org profile and definitions ZIP output show Element.id and Element-derived id snapshots as http://hl7.org/fhirpath/System.String with structuredefinition-fhir-type string. The current specification therefore already reflects the seed resolution for the current build.

Recommendation:
Keep this no-change audit for FHIR-20465. Do not edit current FHIR source or checked-in historical release artifacts for this seed; any desire to republish or technically correct R4/R4B/R5 historical packages should be handled as a separate publication/tooling decision, not as a current-spec source change.
