FHIR-37847: Clarify OperationDefinition searchType use

Issue request:
FHIR-37847 was Published with a Persuasive with Modification resolution for R5. It asked to clarify OperationDefinition.parameter.searchType, document that searchType only applies to input parameters and add an invariant for that, remove the redundant optional Search Type bullet on the operations page, and ensure invalid OperationDefinitions do not violate opd-2.

Initial application:
Commit bd263e608c193abcd2d6ad7e71d704200796e2ac added the input-only opd-4 invariant, added searchType explanatory text with an Evaluate Measure example, and removed the redundant operations-page bullet. The same-day FHIR-32069 commit e7b4eba11e0bf24c8b4452079cc80dff04c014c0 changed the new wording back from primitive parameters to string parameters while updating OperationDefinition type bindings. The current source still had the FHIR-37847 invariant and example, but later Measure operation edits left three resource-typed reporterResource parameters with searchType values that violated the existing opd-2 rule.

Additional context:
FHIR-41220 later clarified operations-page wording about parameters that can be passed on the URL using search syntax. That later clarification does not require OperationDefinition.parameter.searchType on non-string parameters because non-string parameter data types have their search behavior determined by their type. FHIR-55967 intentionally changed the Measure $evaluate, $care-gaps, and $collect-data reporterResource inputs to Practitioner, PractitionerRole, or Organization resources represented with type DomainResource and allowed-type extensions; their inherited searchType="reference" values were stale against that resource-typed representation. source/fhir.ini lists both OperationDefinition and Measure as active resources, so the edited source participates in the current build.

AutoFHIR reconciliation:
This commit keeps the FHIR-37847 rule that searchType is a string-parameter discriminator, clarifies the OperationDefinition element prose and operations-page bullet accordingly, and removes stale searchType="reference" from the three DomainResource reporterResource inputs. A targeted scan of current OperationDefinition resources now finds no searchType on output parameters and no searchType on parameters whose type is not string.

Recommendation:
Keep this commit as a current-spec source fix for FHIR-37847. Do not treat FHIR-41220 or FHIR-55967 as separately decided here; they are later context that remains otherwise applied, and this commit only removes the inconsistency their interaction exposed.
