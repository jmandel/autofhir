FHIR-12504: Audit Task candidate performer support

Issue request:
FHIR-12504 was a Published FHIR-core Task change request resolved Persuasive with Modification. It asked for a way to capture the initial responsible candidates who can perform a Task; the approved resolution was a standard 0..* extension with the same owner-like reference targets and text identifying candidate owners, with usage notes that the list might be binding or suggestive.

Initial application:
The issue was initially applied in commit 78122b582e5b6192fdfe643ea158860c3eb37fae, whose message included [#12504] and whose Task extension spreadsheet added a candidates extension with the approved definition and usage note. Later source conversion carried that into source/task/structuredefinition-extension-task-candidateList.xml and the Task implementation guide.

Additional context:
The current FHIR core build includes Task as an active resource in source/fhir.ini and source/task/structuredefinition-Task.xml now defines Task.requestedPerformer as 0..* CodeableReference to performer role or specific performer resources. FHIR-26960, also Published, explicitly decided to change performerType to requestedPerformer, use CodeableReference, and drop the candidateList extension. The legacy extension is no longer present in core source; the FHIR Extension Pack retains StructureDefinition/task-candidateList as retired/deprecated and FHIR-49168 records that the candidate list is now achieved with Task.requestedPerformer.

AutoFHIR reconciliation:
No source change was made. The current core Task resource already supports the candidate-performer use case through Task.requestedPerformer, and the old extension has intentionally moved out of core and been deprecated in the Extension Pack rather than requiring restoration in this checkout.

Recommendation:
Keep this no-change audit as-is. Do not reintroduce task-candidateList into FHIR core; any future work on the legacy extension's status belongs in the FHIR Extension Pack and should account for FHIR-49168.
