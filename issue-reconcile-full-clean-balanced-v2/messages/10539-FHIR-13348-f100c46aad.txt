FHIR-13348: Audit :missing no-value guidance

Issue request:
FHIR-13348 was Published/Persuasive for FHIR-core, raised against STU3 and voted 7-0-0 by FHIR-I. It asked whether elements that are present but have no primitive value, such as a birthDate with only extensions or an Identifier/Coding with only non-indexed components, should match searches using the :missing modifier. The accepted resolution was to indicate that :missing for simple data type elements matches when the element is omitted or when no @value is specified.

Initial application:
The issue was applied in SVN revision 13208, imported as git commit 96fa8761670c825ab721b850cf4691677b074533, which added guidance to source/search.html saying that :missing=true for simple data type elements matches omitted elements or elements present with extensions but no @value.

Additional context:
The current source/search.html remains the active FHIR-core search narrative; source/fhir.ini also points contributors to maintain the search.html summary table with the search-rules section. The search page now has a dedicated missing-modifier section that states :missing=true returns resources with no matching value or with the element present with extensions but no value, and gives a Patient.given example involving Data Absent Reason. A later local reconciliation for FHIR-14955 is already present on the combined branch and corrected an adjacent summary-row inversion so that it now agrees with this seed issue. A 2023 Zulip implementers thread quotes the current wording and confirms the same absent/no-value interpretation; no Confluence reference or conflicting community evidence was found.

AutoFHIR reconciliation:
Made no source change. The current active search.html wording already preserves the published FHIR-13348 decision, and adding duplicate prose elsewhere would not change implementer understanding.

Recommendation:
Keep this empty audit commit as-is. No follow-up is needed for FHIR-13348 in core unless a future work group issue chooses to further clarify complex-element :missing behavior beyond this simple-data-type/no-value decision.
