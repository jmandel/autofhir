FHIR-39392: Audit targetElement provenance examples

Issue request:
FHIR-39392 was an Applied FHIR-core change request, resolved Persuasive with Modification for R6. The reporter initially thought the existing Provenance targetElement examples used invalid Patient element names, then clarified that n1 and n2 are valid when the referenced Patient carries those element ids and asked for an example showing Provenance targeting an extension in the target Patient.

Initial application:
The existing name examples were left intact because Patient/pat3 already contains name elements with id="n1" and id="n2". The explicit application commit 178eabcf88a65fe535d7572352f02a7931968d65 added a US Core race extension to source/patient/patient-example-c.xml, added source/provenance/provenance-example4.xml using targetPath to point at that extension, and registered the new Provenance example in source/provenance/list-Provenance-examples.xml.

Additional context:
The linked Zulip thread and FHIR-I WGM minutes explain the underlying distinction: targetElement identifies an element by its element id, so an extension can be targeted by targetElement only if the target resource assigns an id to that extension. The applied example instead uses targetPath, which is appropriate when the target extension has no explicit id. Provenance and Patient are active resources in source/fhir.ini, while the targetElement and targetPath extension definitions now live in the FHIR Extension Pack.

AutoFHIR reconciliation:
This audit made no source change. The current source already preserves the correct n1/n2 examples and contains the added race-extension Provenance example requested by the final resolution, without introducing a misleading targetElement example that would omit the required target element id.

Recommendation:
Keep this no-change audit. Future editorial work could add a separate targetElement-with-extension-id example if the work group wants that exact idiom, but FHIR-39392's applied resolution is already satisfied by the current source and no current build correction is needed.
