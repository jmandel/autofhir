FHIR-20210: Audit document date timestamp guidance

Issue request:
FHIR-20210 was a Published/Persuasive FHIR-core change request from FHIR-I asking that the FHIR document date be recorded in Bundle.timestamp rather than Bundle.meta.lastUpdated. The issue explained that meta.lastUpdated is a server-maintained persistence/change time and is discarded/repopulated on create, while Bundle.timestamp carries the document assembly time.

Initial application:
The issue was applied before this reconciliation by git commit 852d3b8839, which changed source/documents.html so the mandatory document date is found in Bundle.timestamp instead of Bundle.meta.lastUpdated. The same implementation discussion also covered FHIR-22709, which aligned the Bundle bdl-10 invariant with the timestamp rule.

Additional context:
The current documents page still says the mandatory document date is found in Bundle.timestamp. The active Bundle StructureDefinition describes Bundle.timestamp as the assembly time and explicitly says its document usage is the date the document was created, while the document-bundle profile makes Bundle.timestamp mandatory for document Bundles. FHIR-I minutes and the linked Zulip discussion support the move away from meta.lastUpdated for the document date.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current core documentation and conformance source already implement FHIR-20210's requested distinction between Bundle.timestamp as the document assembly date and meta.lastUpdated as server-maintained modification metadata.

Recommendation:
Keep this commit as-is. No follow-up is needed for FHIR-20210 in the core spec unless future edits reintroduce document-date guidance pointing to Bundle.meta.lastUpdated.
