FHIR-6796: Audit compartment clarification coverage

Issue request:
FHIR-6796 is a Published/Persuasive with Modification FHIR-core clarification issue from the 2015 May cycle. The request said several resources did not make clear which were master-file/knowledge-base definitions versus patient-specific data, and it called out medications, contraindications, ClinicalImpression, RiskAssessment, and observations. The final resolution was to add compartment information to every resource.

Initial application:
No git commit directly tagged FHIR-6796 was found. The current application is represented by the active compartment source: source/fhir.ini keeps CompartmentDefinition in the current resource set, source/compartments.xml provides the per-resource compartment matrix, and the CompartmentDefinition narrative explains how listed resources with no parameters are outside a compartment. Git history shows the compartment source has been maintained continuously, including pre-2015 additions and later updates, rather than a single discoverable FHIR-6796-tagged change.

Additional context:
The current build scope check found 126 active resources in source/fhir.ini and 127 rows in source/compartments.xml, with no active fhir.ini resources missing from the compartment worksheet. The extra row is the historical !Protocol row. The current CompartmentDefinition notes explicitly say that resources such as Medication, Substance, and Location are not in any compartment and are sometimes called master files. Current resource-specific text also addresses two examples from the Jira: Contraindication is now DetectedIssue and its introduction says the resource is patient-specific/time-bound rather than generic risk knowledge, while RiskAssessment says it is a specialized type of Observation. ClinicalImpression source still exists in the checkout but is not an active current-build resource in fhir.ini.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already implements the Jira resolution by maintaining a compartment row for every active resource and by documenting how compartment absence identifies master-file-style resources.

Recommendation:
Keep this no-change audit commit as-is. Further edits would either duplicate the existing CompartmentDefinition guidance or reopen old resource-design questions that were not part of FHIR-6796's final published resolution.
