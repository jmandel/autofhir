FHIR-27877: Audit targetElement extension application

Issue request:
FHIR-27877 is Published/Persuasive and asked FHIR-I to define an extension, tentatively called focus-element, that lets a Reference or canonical identify the specific element or elements inside the referenced resource that are the focus of the reference.

Initial application:
The targetElement and targetPath extensions already existed from FHIR-21284. Core commit d4a3902f2ade29f77b3ec4495c012f01c6ad0c33 explicitly applied FHIR-27877 by changing the targetElement and targetPath rows in the reference extensions spreadsheet to apply to Reference and canonical, and by expanding the targetElement comment with the FHIR-27877 rationale about being like a URL fragment but broader than Reference.reference contained-resource fragments.

Additional context:
The August 2022 FHIR-I Zulip thread for FHIR-27877 concluded that the pre-existing targetElement solution was likely the Jira solution, pending committee confirmation. The October 2020 FHIR-I minutes record the Persuasive vote for the Reference/canonical extension. Core commit dd468d4f1799dd79819315b211588ef1cf4586e0 later removed extension definitions from the R5 core source; the current authoritative targetElement and targetPath definitions live in the FHIR Extension Pack. The current Extension Pack targetElement definition is active, has Reference and canonical contexts, cardinality 0..*, a valueUri carrying the target element id, and wording that preserves the FHIR-27877 semantics. Active core Provenance and GuidanceResponse source references link to those extension-pack definitions.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core checkout no longer owns the extension definition, and the current Extension Pack plus active core references already convey the FHIR-27877 rule. Changing core source would either duplicate external extension-pack source or reopen the already-applied choice to use targetElement rather than create a separate focus-element extension.

Recommendation:
Keep this audit commit as-is for FHIR-27877. If a work group wants to revisit the historical value type/name choice or adjust targetElement prose, that follow-up belongs against the FHIR Extension Pack rather than as a core-source fix for this published issue.
