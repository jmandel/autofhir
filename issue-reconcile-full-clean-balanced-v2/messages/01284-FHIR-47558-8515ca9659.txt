FHIR-47558: Audit Quantity exceptional values guidance

Issue request:
FHIR-47558 was Applied with a Persuasive with Modification resolution for R6. It asked for a standard way to represent exceptional Quantity-like values such as NaN, positive/negative infinity, trace, and sufficient quantity. The accepted resolution narrowed the requested artifacts to a Quantity note explaining that exceptional values should be represented with a coded datatype such as CodeableConcept using codes from Data Absent Reason or v3 NullFlavor, with individual work groups deciding where such coded alternatives are allowed.

Initial application:
The issue was already applied in source/datatypes.html. Commit 96b8234646758cec8beeae40831e3caeae9abc82 first added the approved note near the Quantity section, and commit e3f83b936d1041110fe8e63316611bfe19438fdf moved and refined the wording directly after the Quantity unit/UCUM discussion. The current source keeps the active Quantity narrative in source/datatypes.html and says to use CodeableConcept with Data Absent Reason or Null Flavor code systems, plus the corresponding extension links.

Additional context:
The linked implementers Zulip thread records the original discussion: exceptional values in Quantity are better handled where the model allows Quantity or CodeableConcept, with data-absent-reason or v3 codes as candidate vocabularies. FHIR-I minutes on 2025-01-13 record the Persuasive with Modification vote and the intent to add a note rather than change Quantity itself. Jira and community searches did not reveal a later conflicting decision or a separate tightly coupled applied issue needing reconciliation here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active datatype page already contains the approved Quantity guidance, and adding a new value set, examples, or duplicate prose would exceed the final Jira resolution and risk creating maintenance drift.

Recommendation:
Keep this audit commit as-is. Future work groups that need NaN, infinity, trace, sufficient quantity, or similar concepts in specific data elements should decide whether those elements need CodeableConcept in a choice type or a locally constrained coded alternative; no additional core Quantity change is needed for FHIR-47558.
