FHIR-23069: Audit preferred extension context

Issue request:
FHIR-23069 was a Published FHIR-core/FHIR-I change request, resolved Persuasive for R5. It reported that the iso21090-preferred extension context was incorrectly rendered as Resource and asked that the context instead be Address and ContactPoint; the resolution said to make the proposed change and noted it was pre-applied.

Initial application:
No source commit explicitly tagged FHIR-23069 was found. The Jira comment says this was a build-tool bug where a source context specified for data types was changed to resources during generation. Historical generated core artifacts show the problematic broad context family: STU3 used Any, R4 rendered Resource, and R4B rendered Element. The durable R5 source application was later made through the same context-change family: commit c4807a5165 (MnM changes for R5, associated with FHIR-23916) changed source/profiles/iso-21090-spreadsheet.xml from Any to Address;ContactPoint.

Additional context:
FHIR-23916 independently resolved that iso21090-preferred should apply only to Address and ContactPoint. FHIR-35835 later added ExtendedContactDetail as a compatible R5 context, and commit b759378e9a applied that refinement. Commit dd468d4f17 removed the extension rows from current core source; core now retains only the iso21090-preferred OID, while the active extension definition lives in the FHIR Extension Pack. That Extension Pack definition is included by the IG's input/definitions/* path and currently lists Address, ContactPoint, and version-gated ExtendedContactDetail. FHIR-41565 and FHIR-49912 later deprecated/retired preferred in favor of rank guidance but did not reopen the context correction.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative current extension source already satisfies FHIR-23069 as refined by later published decisions, and the FHIR core checkout no longer owns the active StructureDefinition source. Editing core would duplicate or reintroduce an out-of-scope extension definition rather than correcting the current build.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed for FHIR-23069; any future changes to iso21090-preferred should be made in the FHIR Extension Pack and should preserve the later ExtendedContactDetail refinement unless a new work-group decision changes it.
