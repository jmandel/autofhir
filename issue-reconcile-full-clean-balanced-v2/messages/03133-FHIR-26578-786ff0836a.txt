FHIR-26578: Audit SubstanceDefinition representation format

Issue request:
FHIR-26578 was a Published/Persuasive BR&R R5 change request asking for a new SubstanceDefinition.structure.representation.format element to capture the format of chemical structure representation data, with draft text naming a CodeableConcept and cardinality 1..1.

Initial application:
The Jira-tagged source application was commit 3885120c62, which added SubstanceDefinition.structure.representation.format to the then-current SubstanceDefinition spreadsheet as CodeableConcept with cardinality 0..1. A second same-day commit, 6e7cd064f3, applied a similarly named format concept to the historical SubstancePolymer spreadsheet, but SubstancePolymer is not part of the current build. Later SubstanceDefinition source rework carried the element into source/substancedefinition/structuredefinition-SubstanceDefinition.xml, and the current terminology files provide the substance-representation-format CodeSystem and ValueSet.

Additional context:
SubstanceDefinition is active in source/fhir.ini, and the current source includes representation.format as a 0..1 CodeableConcept with an example binding to ValueSet/substance-representation-format. The R5 published profile also exposes min 0 max 1 for this element. No Zulip or Confluence search found a directly conflicting discussion for FHIR-26578; the only relevant Zulip hit quoted the 2022 build surface with format shown as 0..1 while discussing the neighboring document reference. A later no-change Jira, FHIR-55056, mentions this value set only in the broader context of possible THO migration and does not require a cardinality or source change.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The requested element and its terminology are present in active current source, and tightening the base cardinality from the applied and published 0..1 to 1..1 would be a substantive conformance change without evidence of a later WG decision overriding the original applied source.

Recommendation:
Keep this audit commit as-is. If BR&R wants SubstanceDefinition.structure.representation.format to be mandatory in the base resource, that should be handled as a new explicit Jira/change proposal because the current and R5-published base specification has consistently exposed it as optional.
