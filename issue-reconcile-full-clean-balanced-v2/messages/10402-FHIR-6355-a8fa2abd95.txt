Issue request:
FHIR-6355 was a Published/Persuasive DSTU1 FHIR-core profile tooling issue. It reported that the Requirements column from derived profile spreadsheets was read by SpreadsheetParser but was not propagated into generated profile.xml StructureDefinition snapshot or differential elements.

Initial application:
The Jira comments identify svn revision 5910. Git history maps that revision to 71ac047a42bc16f33f5267a6ed257d9cebc8be80, "#6355 - add missing requirements to structure definitions", which added ProfileGenerator logic to copy non-empty element requirements into generated StructureDefinition element definitions.

Additional context:
The affected in-repository ProfileGenerator.java was removed during the 2021 Gradle/Kindling build migration, and the current FHIR checkout builds with org.hl7.fhir:kindling rather than carrying that generator source. Current fhir.ini still registers active profile spreadsheets, while current checked-in StructureDefinition source files already contain serialized requirements elements. The QICore patient profile named in the DSTU1 report is not present in the current core checkout, and no relevant Zulip or Confluence record was found that changes the Jira/git conclusion.

AutoFHIR reconciliation:
