FHIR-28174: Audit medicinal product ingredient searches

Issue request:
FHIR-28174 was a Published/Persuasive BRR change request approved for R5 to allow medicinal products to be searched by ingredient, Ingredient resources to be searched by substance or substance definition, the previous substance code search to be renamed to substance-code, and AdministrableProductDefinition to expose the related device and manufactured-item links.

Initial application:
No source commit explicitly mentions FHIR-28174, but the R5 medication-definition resource additions added the relevant search-parameter bundles. The product ingredient search parameters were originally reference searches while the product elements pointed at Ingredient, and the Ingredient substance, substance-code, and substance-definition search parameters are present in the Ingredient search bundle.

Additional context:
FHIR-31808 was later Published/Persuasive with Modification and changed the model so Ingredient points back to MedicinalProductDefinition, AdministrableProductDefinition, and ManufacturedItemDefinition through Ingredient.for. Its implementation commit fbfbf287b1 added the Ingredient.for reference search parameter and changed the product ingredient elements/search parameters from reference-to-Ingredient to CodeableConcept/token fallback ingredients. Current build-scope source retains Ingredient substance reference/code searches, Ingredient.for, product ingredient token searches, and AdministrableProductDefinition device and manufactured-item reference searches; v5.0.0 contains the same FHIR-31808-shaped search model.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Reintroducing product-level ingredient reference search parameters would contradict the later approved Ingredient.for linkage direction. The current source already supports the seed's search use cases through Ingredient substance/substance-code/substance-definition searches, Ingredient.for and reverse _has searches from product resources, direct product ingredient token searches for in-resource fallback coded ingredients, and the requested AdministrableProductDefinition device/manufactured-item references.

Recommendation:
Keep this no-change audit. If BRR wants a new derived product-level search parameter that traverses incoming Ingredient.for links without using _has, that should be raised as a fresh search semantics request rather than treated as an unapplied FHIR-28174 fix.
