FHIR-23077: Audit conditionalPatch capability flag

Issue request:
FHIR-23077 was a Published/Persuasive FHIR-I change request asking CapabilityStatement to expose a per-resource conditionalPatch flag, because HTTP conditional PATCH is only a SHOULD when PATCH and conditional update are supported and clients need an explicit discovery point.

Initial application:
The issue was applied by git commit 2c5ab97acd02c2ef8485612d3193b54102bc6a4a on 2022-08-25, which added CapabilityStatement.rest.resource.conditionalPatch to the CapabilityStatement structure definition and updated the example and supporting conformance files. Current source still contains the 0..1 boolean element and example usage.

Additional context:
CapabilityStatement is an active build-scope resource in source/fhir.ini, and the current conformance source includes the requested element between conditionalUpdate and conditionalDelete. FHIR-I minutes from 2019-11-04 record the same tracker as Persuasive with a 7-0-0 motion. A later R6 issue, FHIR-54057, proposes deprecating conditionalCreate/Read/Update/Delete/Patch in favor of interaction codes, but it is only Resolved - change required and does not remove the currently published R5 application of this seed. Corrected Zulip searches found no conflicting discussion.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because the current build-scope CapabilityStatement source already includes the conditionalPatch flag requested by FHIR-23077.

Recommendation:
Keep this no-change audit for FHIR-23077. Handle the later conditional* deprecation proposal separately if and when FHIR-54057 is applied in the R6 build scope.
