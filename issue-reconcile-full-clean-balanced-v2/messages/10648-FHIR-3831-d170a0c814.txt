FHIR-3831: Audit table popup context

Issue request:
FHIR-3831 is a Published FHIR-core DSTU1 change request, resolved Persuasive with Modification, asking that deeply nested differential/table views include a reminder of the nesting level because extension rows could appear far from the element that defined their context. The accepted resolution was to add context to the popup that contains the definition.

Initial application:
No current Git commit message directly references FHIR-3831 or #3831; the only #3831 log hit is an unrelated later pull request. Around the March 2015 resolution comment, renderer/profile-table work landed in the old in-repo Java tooling, especially 7996f50897b97db120319141c23e9a1070d853b4, which improved extension rendering in table views and profile rendering in ProfileUtilities. That historical renderer source is no longer part of this checkout.

Additional context:
The current build invokes the external Kindling publisher dependency from Gradle rather than carrying the old Java table renderer source in this repository. Current generated FHIR pages load fhir-table-scripts.js and the current build output on build.fhir.org renders definition-hover titles with the full element path followed by the definition, for example "Questionnaire.url : ..." and "Questionnaire.identifier : ...". The SDC URL cited by the old Jira issue is not a current core source artifact requiring edits. Corrected Zulip and Confluence searches found no related discussion or conflicting later decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current generated specification already provides the requested context in table definition popups, and editing active core source would at most adjust illustrative placeholder HTML rather than fix a current implementer-facing defect.

Recommendation:
Keep this no-change audit commit as-is. If a future report identifies a specific generated table missing element-path context in its definition popup, investigate and fix the Kindling publisher; no current FHIR core source follow-up is needed for FHIR-3831.
