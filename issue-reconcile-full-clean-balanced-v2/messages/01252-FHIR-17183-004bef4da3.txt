FHIR-17183: Audit ImagingSelection resource creation

Issue request:
FHIR-17183 was a Published Imaging Integration change request, resolved Persuasive with Modification for R5, to create an imaging-specific resource. The original text proposed an ImagingReference resource for DICOM study/series/instance/frame references and retrieval endpoints, but the final resolution says to create the new resource described in the linked Confluence page after FMG approval.

Initial application:
The issue was applied by the November 2021 ImagingSelection work: f141f3aacd added the initial ImagingSelection resource source and fhir.ini wiring with the FHIR-17183 key, cf1ff8eaa6 applied follow-up draft fixes, and df9626b257 merged PR #1502. No prior Issue-Reconcile-Key audit exists on the combined branch for FHIR-17183.

Additional context:
Jira comments and FMG minutes show the requested resource was renamed from ImagingReference to ImagingSelection, with FMG agreeing that ImagingSelection was the clearer name. Jira also records that additions to other resources such as DiagnosticReport, Observation, and Media were to be handled by separate tracker items, so they are not part of this seed's source-change scope. Current source/fhir.ini lists ImagingSelection as an active resource owned by II, and the current StructureDefinition, examples, terminology, and narrative have since been refined by later ImagingSelection issues.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build already includes an active ImagingSelection resource with the canonical StructureDefinition, module/resource-list wiring, DICOM UID elements, instance/frame support, Endpoint references, and ImagingStudy-derived relationship needed to satisfy the final FHIR-17183 decision.

Recommendation:
Keep this audit commit as-is. Any remaining questions about references from other resources or newer ImagingSelection maturity/content refinements should stay with their own Jira issues rather than reopening FHIR-17183.
