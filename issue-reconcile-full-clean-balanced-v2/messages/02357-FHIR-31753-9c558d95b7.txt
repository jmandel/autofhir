FHIR-31753: Add CodeSystem content concept invariant

Issue request:
FHIR-31753 was a Published/Persuasive with Modification Vocab change request for R5. It asked to remove the ShareableCodeSystem profile requirement that CodeSystem.concept be present for every shareable code system, while adding a base CodeSystem invariant requiring at least one concept when CodeSystem.content is example, fragment, or complete.

Initial application:
The issue was partially applied before this reconciliation. PR #2068 was implemented by commit 93fadfaa, which removed the old CodeSystem.concept min=1 constraint from source/codesystem/structuredefinition-profile-shareablecodesystem.xml and added an scs-2 invariant to that profile. The same commit did not modify source/codesystem/structuredefinition-CodeSystem.xml, so the approved base CodeSystem invariant was not present in current source.

Additional context:
The May 2022 Vocab WGM minutes confirm the intended distinction: not-present code systems cannot have concepts, supplements may identify property types, and example, fragment, and complete code systems are expected to have concepts. Later FHIR-37959 removed ShareableCodeSystem and related terminology-resource profiles from core and moved ongoing profile maintenance to CRMI, but that later profile migration does not supersede the base CodeSystem rule requested by FHIR-31753. The active current build still includes CodeSystem via source/fhir.ini, so the base StructureDefinition is in scope.

AutoFHIR reconciliation:
Added csd-9 to source/codesystem/structuredefinition-CodeSystem.xml with the expression `content in ( 'example' | 'fragment' | 'complete' ) implies concept.exists()`, and attached the condition to CodeSystem.content and CodeSystem.concept. This completes the base invariant that was approved but missed when the earlier application only constrained ShareableCodeSystem.

Recommendation:
Keep this source fix. Future work on ShareableCodeSystem profile constraints should remain in CRMI per FHIR-37959, but the base CodeSystem invariant belongs in core and now matches the FHIR-31753 resolution.
