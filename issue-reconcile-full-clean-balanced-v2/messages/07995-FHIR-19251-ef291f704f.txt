FHIR-19251: Audit clinical safety overlap checklist

Issue request:
FHIR-19251 was a Published/Persuasive FHIR-I change request raised for STU3 after the Baltimore connectathon. It asked to add a Clinical Safety Checklist item warning that content that can reasonably be exposed using more than one FHIR resource must still be findable by clients, using DiagnosticReport and DocumentReference overlap as the motivating example, and to create a supporting wiki page.

Initial application:
The Jira comment says the safety page change was made in GH#903a769476. Commit 903a769476 added the cross-resource overlap checklist item to source/safety.html and linked the original wiki page; commit 5755ae16f4 later migrated that link to Confluence; commit 76ce9865e6 created the formal safety checklist CodeSystem and included the same cross-resource entry.

Additional context:
Current source keeps source/safety.html in the built page hierarchy and links it from implementation-support documentation. The active source/fhir.ini entry for safety-entries includes source/codesystem/codesystem-safety-entries.xml, whose cross-resource concept mirrors the safety page text. The Confluence page "Managing Overlap Between Resources" references FHIR-19251 and preserves the intended DiagnosticReport/DocumentReference overlap context. Companion Jira issues FHIR-19249 and FHIR-19250 address the resource-specific DiagnosticReport and DocumentReference boundary text under OO, but they are separate resource-boundary work and do not require another FHIR-I checklist edit for this issue.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current built safety checklist already tells implementers to ensure clients can find information when content might reasonably be exposed using more than one FHIR resource, gives mitigation patterns including cross-resource search or exposing data through each applicable resource, and links to the migrated Confluence discussion. The active safety CodeSystem also carries the same cross-resource checklist item for formal references.

Recommendation:
Keep this no-change audit commit as-is. Do not add redundant prose to the safety page unless a future work-group decision changes the safety checklist guidance; handle any remaining DiagnosticReport or DocumentReference boundary concerns through their own Jira keys rather than FHIR-19251.
