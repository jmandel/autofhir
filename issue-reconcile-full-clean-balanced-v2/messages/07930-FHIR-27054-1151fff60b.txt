FHIR-27054: Audit typed _elements restrictions for included resources

Issue request:
FHIR-27054 was a Published FHIR-core/FHIR-I R5 change request resolved Persuasive. It asked to remove the search-page statement that the _elements list did not apply to included resources and to add that when clients supply resource-type-prefixed values such as _elements=Patient.gender, servers SHOULD apply those element-level restrictions to all returned Bundle resources, not just direct search matches.

Initial application:
Commit f71d61cdab5 (FHIR-27054, 2022-08-09) explicitly applied the issue to source/search.html by deleting the old included-resources exclusion and adding the typed _elements paragraph. Current blame shows the semantic lines remain from that commit, with later formatting wrapping the paragraph in fhir-conformance markup.

Additional context:
The Jira-linked Zulip thread records the motivating Observation _include Patient.gender use case and an Aidbox implementation pattern using resource-type prefixes for included resources. FHIR-I minutes for 2020-08-17 record the Persuasive 8-0-0 vote. Later nearby _elements clarifications represented separately on the combined branch, including FHIR-35837 and FHIR-43354, do not alter this included-resource rule.

AutoFHIR reconciliation:
This audit commit makes no source change. The current authoritative FHIR-core search page already states the approved SHOULD for resource-type-prefixed _elements values and no longer contains the obsolete "does not apply to included resources" sentence.

Recommendation:
Keep this no-change audit as-is. Revisit only if FHIR-I decides to change broader _elements path semantics or add a computable conformance rule; neither is required to satisfy FHIR-27054.
