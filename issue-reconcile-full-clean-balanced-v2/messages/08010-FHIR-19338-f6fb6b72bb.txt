FHIR-19338: Broaden ImplementationGuide short definition

Issue request:
FHIR-19338 was Published/Persuasive for STU3. It asked to recognize that ImplementationGuide is used to publish CQL, FHIRPath, and other specifications that are not strictly FHIR, and its approved resolution changed the resource definition to describe solving interoperability or standards problems, typically through FHIR resources.

Initial application:
The issue was initially applied by 87a520a33a, which changed the old spreadsheet definition from FHIR-only wording to the approved broader definition. Later source rework commits, including 33b409a4b6 and c69d71aa21, carried that broader text forward into the current StructureDefinition source.

Additional context:
The current source/fhir.ini has an active implementationguide=ImplementationGuide resource entry, so source/implementationguide/structuredefinition-ImplementationGuide.xml is in the current build scope. The current top-level description and root ElementDefinition.definition already match the approved broader wording, but the adjacent root ElementDefinition.short still said "A set of rules about how FHIR is used", preserving the old FHIR-only summary. Jira, Zulip, and Confluence searches found no later or conflicting decision that narrows ImplementationGuide back to only FHIR usage.

AutoFHIR reconciliation:
This commit updates only the active ImplementationGuide root ElementDefinition.short to the same broader concept as the approved definition: an interoperability or standards problem, not just FHIR usage.

Recommendation:
Keep this commit as-is. It is a narrow consistency correction in the authoritative current StructureDefinition source and aligns the conformance summary with the already-applied Jira resolution.
