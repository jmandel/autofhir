FHIR-26639: Audit Device property value choice

Issue request:
FHIR-26639 was Published/Persuasive for R5 by OO and asked to rationalize Device.property and DeviceDefinition.property so a single property value is represented as a choice value[x], rather than separate valueQuantity and valueCode elements that could both appear.

Initial application:
Commit 5af20b6658ab34965b88e626e6052eb5b8c759a2 applied the issue to Device by replacing Device.property.valueQuantity and Device.property.valueCode with Device.property.value[x]. DeviceDefinition still had the old split immediately after that commit, but the same artifact family was subsequently reconciled through the published FHIR-26424 work: f7809084c6ff4cb26ba4773a2eadaab473e86641 converted DeviceDefinition.property.valueQuantity/valueCode to DeviceDefinition.property.value[x], and FHIR-26424 commits broadened both resources' value[x] choices to the approved property datatype set. Commit 23d0f3c36f2244f7636e70edcfbd21cf074c49db later made the value mandatory on both resources, matching the single-value expectation recorded for FHIR-26639 and FHIR-32568.

Additional context:
Current source/fhir.ini actively includes both Device and DeviceDefinition in the build. Current source has Device.property.value[x] and DeviceDefinition.property.value[x], each with 1..1 cardinality and no remaining valueQuantity/valueCode element definitions. The current additional datatypes beyond Quantity and CodeableConcept are not a regression against FHIR-26639; FHIR-26424 is a later Published/Persuasive-with-Modification OO decision that explicitly approved valueBoolean, valueInteger, valueString, valueRange, and valueAttachment for the same property value choice. FHIR-39322 is later resolved-change-required context that updated nearby definitions/comments but does not require reverting the choice shape.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative source already satisfies FHIR-26639's structural requirement, and narrowing value[x] back to only Quantity|CodeableConcept would incorrectly undo later approved OO changes.

Recommendation:
Keep this no-change audit commit as-is. Any future cleanup should be handled under the later Device/DeviceDefinition property clarification issues, not by reopening FHIR-26639's already-applied choice conversion.
