FHIR-32948: Audit Request status fulfillment guidance

Issue request:
FHIR-32948 was Published with a Not Persuasive with Modification resolution. It asked to add an "in-progress" code to the Request Status value set so Request resources could represent fulfillment activity already underway. The work-group decision rejected adding the code because a Request represents authorization, not fulfillment, and called for Request-pattern documentation explaining that action/progress is found through Event resources basedOn the Request or Task resources focused on the Request.

Initial application:
No Jira-tagged source commit for FHIR-32948 was found. The Jira comment says "Already done," and the relevant Request-pattern text already existed before the issue was filed: current source says the Request state machine does not reflect execution, that Requests do not track execution/fulfillment, and that progress is represented by associated Event resources or Task. The Request.status source also says performer activity is reflected on Events or Task, and the Request Status code system/value set still intentionally omit "in-progress."

Additional context:
The originating Zulip thread shows the same CommunicationRequest/SMS workflow concern and records the rationale that Task is the resource for claiming/fulfillment progress while a Request is an authorization. FHIR Workflow minutes for 2021-06-21 record FHIR-32948 as Not Persuasive with Modification. Later FHIR-45872 expanded the same Request Fulfillment/Execution guidance in 2025, and the combined branch already contains a separate no-change audit commit for that later issue, so this seed should not duplicate that decision or add more source text.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current in-scope Request pattern and Request.status source already convey the approved rule: do not add an "in-progress" Request status; fulfillment/execution progress belongs in Events or Task, with Task capable of tracking ownership, acceptance, in-progress work, business status, and related outputs.

Recommendation:
Keep this audit commit as-is. Do not add "in-progress" to Request Status under FHIR-32948. Any future broad rewording of Request-versus-Task workflow guidance should be handled as a new work-group decision or under already-separate follow-on issues, not as seed reconciliation for FHIR-32948.
