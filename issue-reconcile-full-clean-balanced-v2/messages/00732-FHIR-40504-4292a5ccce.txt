FHIR-40504: Align ConceptMap attribute prose and example

Issue request:
FHIR-40504 was Published/Persuasive with Modification for R5. It split ConceptMap mapping properties from the pre-existing source/target data-element mechanism by adding ConceptMap.group.element.target.property, adding ConceptMap.property.system and the code property type, renaming mapAttribute-style elements to additionalAttribute/attribute, and updating $translate property/product/dependency parameters.

Initial application:
The issue was first applied in git commit 0de5092965, after FHIR-39151 commit cebd9afb99 introduced the earlier property framework. That implementation updated the ConceptMap StructureDefinition, $translate OperationDefinition, property type code system, and examples, but the active ConceptMap notes still described dependencies with the old dependsOn.property/property-definition wording, and the specimen example retained additionalAttribute.system children that are not defined by the current ConceptMap.additionalAttribute backbone.

Additional context:
The ConceptMap resource is active in source/fhir.ini, so source/conceptmap narrative and examples feed the current build. FHIR-40544 later updated the R4-to-R5 change bullets and confirms the same property/additionalAttribute distinction. FHIR-40636 later clarified that valueCode in dependsOn/product gets its code system from the group source/target code system, not from an additionalAttribute/property definition.

AutoFHIR reconciliation:
Updated source/conceptmap/conceptmap-notes.xml to use dependsOn.attribute and ConceptMap.additionalAttribute, and to state the current valueCode code-system rule. Removed undefined system children from source/conceptmap/conceptmap-example-specimen-type.xml additionalAttribute declarations so the example matches the current ConceptMap.additionalAttribute definition.

Recommendation:
Keep this source fix. It completes the FHIR-40504 terminology split in the active ConceptMap narrative/example without adding broader explanatory text beyond the later approved rules already present in the resource definition.
