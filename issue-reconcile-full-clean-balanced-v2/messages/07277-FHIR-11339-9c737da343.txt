FHIR-11339: Audit DiagnosticRequest workflow clarification

Issue request:
FHIR-11339 was a Published/Persuasive with Modification DSTU2 DiagnosticRequest issue. It objected to Boundaries text saying the Diagnostic Request itself was not a request to perform the investigation, but a record that a request was made, and that additional workflow initiation might be required. The approved resolution was to remove that paragraph because Scope and Usage already linked to the Workflow module and covered request-resource workflow more clearly.

Initial application:
The issue was applied in historical commit ccaebaf26211addd4753b390f79e43735583f08a, which deleted the confusing DiagnosticRequest Boundaries paragraph from source/diagnosticrequest/diagnosticrequest-introduction.xml. That commit also carried adjacent DiagnosticRequest clarifications, but the FHIR-11339-specific change was the paragraph removal.

Additional context:
DiagnosticRequest is no longer an active current-build resource: source/fhir.ini lists ServiceRequest as active and DiagnosticRequest under removed resources, with the older diagnostic/order lineage subsumed into ServiceRequest. Current ServiceRequest Scope and Usage says ServiceRequest represents an order, proposal, or plan, links explicitly to the Workflow page, and its Boundaries section explains ServiceRequest authorization, basedOn relationships, and Task's separate execution-tracking role. Current source searches found no remaining copy of the removed DiagnosticRequest paragraph. Related FHIR-11340 and FHIR-11341 work from the same historical application family is already represented on the combined branch, so this commit does not duplicate those decisions.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No current source edit is needed because the old DiagnosticRequest wording was removed historically, the current in-build ServiceRequest source carries the relevant workflow/authorization clarification, and the retired DiagnosticRequest source is not part of the current build.

Recommendation:
Keep this audit as-is. Further wording changes to ServiceRequest workflow guidance would be a new current-spec decision, not required to satisfy FHIR-11339.
