FHIR-8850: Audit StructureDefinition choice-type note

Issue request:
FHIR-8850 was a Published/Persuasive FHIR-core StructureDefinition correction from DSTU1, applied for DSTU2. It reported that the StructureDefinition interpretation note incorrectly said choice elements retain "[x]" even when a constraint leaves only one allowed type.

Initial application:
The issue was applied in git-svn commit b560f208bc85bcd00274a46d986df9cb4389a38f, matching Jira's svn revision 7185 comment, by replacing the obsolete "retain [x]" sentence in source/structuredefinition/structuredefinition-notes.xml with a profiling note that single-type choices used the concrete type name.

Additional context:
StructureDefinition is active in source/fhir.ini, and the current source/structuredefinition/structuredefinition-notes.xml interpretation note no longer contains the obsolete FHIR-8850 sentence. A later Published/Persuasive with Modification issue, FHIR-39177, removed the replacement sentence in R5 after the work group decided the formal definition should not support choice-type renaming. The current note now only states that elements with more than one type must have names ending in "[x]" and separately explains how constraints on choice elements select a type with FHIRPath.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build-scope source has neither the original false "retain [x]" statement nor the later single-type renaming sentence, which is correct after considering the later FHIR-39177 decision.

Recommendation:
Keep this no-change audit commit. Do not restore the DSTU2 replacement wording for FHIR-8850; the later R5 decision supersedes that implementation detail while preserving the removal of the original incorrect statement.
