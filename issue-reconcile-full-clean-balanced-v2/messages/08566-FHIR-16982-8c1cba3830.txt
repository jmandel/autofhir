FHIR-16982: Audit Address.country country-name wording

Issue request:
FHIR-16982 was Published with a Persuasive with Modification resolution for STU3. It asked to clarify the Address.country comment so ISO 3166 codes could be used in place of a human readable country name, not only a formal full country name.

Initial application:
The issue was applied in SVN revision 14302, represented in git by afb42376cdc0c76c2a8dd8333eabe792e8866da6, which changed source/datatypes/address.xml from "full country name" to "human readable country name." A later R5 MnM commit, 5cbc14c7d0f361941099bf72066b75c3f74f6d4f, retained that clarification while expanding the ISO 3166 wording for FHIR-30239.

Additional context:
Address is an active datatype in source/fhir.ini and is marked normative, so source/datatypes/address.xml is current build-scope source. The later Published FHIR-30239 decision intentionally changed the same comment to allow ISO 3166 2- or 3-letter codes and to use RFC-style MAY language, without reverting the FHIR-16982 human-readable-country clarification. Searches found no direct Zulip or Confluence record for FHIR-16982 that conflicts with the Jira and source-history evidence.

AutoFHIR reconciliation:
This commit makes no source change. The current Address.country source says "ISO 3166 2- or 3- letter codes MAY be used in place of a human readable country name," and no stale "full country name" or old "ISO 3166 3 letter codes can be used" wording remains in source.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-16982; the current wording conveys the requested clarification and also incorporates the later FHIR-30239 refinement.
