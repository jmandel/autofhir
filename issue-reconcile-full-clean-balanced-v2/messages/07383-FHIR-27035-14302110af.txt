FHIR-27035: Audit CCN identifier registry delegation

Issue request:
FHIR-27035 was a Published/Persuasive FHIR-I R5 change request asking core to add a URL for the CMS Certification Number OID 2.16.840.1.113883.4.336 to the Identifier Registry. The accepted resolution was to add a URL for the OID and follow the pattern of working with CMS to get a URL assigned.

Initial application:
No core git commit explicitly mentioning FHIR-27035 was found. The application path is through terminology governance: the FHIR-27035 Jira comment says the request is now done at terminology.hl7.org/NamingSystem-CCN.html, HTA-48 approved the CCN identifier URI, and UP-253 implemented a THO NamingSystem named CCN. The core identifier-registry page was later changed by FHIR-35932 in git commit f40fc710c3 to remove the local identifier table after migration to HL7 Terminology.

Additional context:
Current core source keeps identifier-registry.html in the build and states that identifier systems are actively curated in HL7 Terminology, with THO-defined URIs taking precedence for R5 conformance. Current THO exposes NamingSystem/CCN with OID 2.16.840.1.113883.4.336 and preferred URI http://terminology.hl7.org/NamingSystem/CMSCertificationNumber. A later parallel core request, FHIR-27898, was resolved Not Persuasive/No Change because the agreed URL belonged under THO rather than FHIR-I; the matching Zulip thread records that R4 would not be revised and R5 would point the identifier-registry page to THO.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. Re-adding a local core registry row for CCN would undo the FHIR-35932 migration model, while the current core page already directs implementers to the active THO registry that contains the requested CCN OID and URL.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed unless THO changes or loses the CCN NamingSystem; future maintenance of this identifier belongs in THO/UTG rather than the FHIR core source checkout.
