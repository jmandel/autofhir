FHIR-3650: Audit extension context clarification

Issue request:
FHIR-3650 was a Published/Persuasive with Modification DSTU1 change request asking to clarify the format of Profile.extensionDefn.context. The specific concern was that old extension-definition prose said multiple contexts were separated by ';', while the conformance resource represented them as repeating context elements.

Initial application:
The issue was applied in svn revision 4590, represented in git as 850a2eefa18974c4d92a10d81db711069ba7d65d. That commit changed the obsolete ExtensionDefinition introduction table from "As above, separated by ';'" to "specify multiple useContext elements - one for each context".

Additional context:
The current build no longer contains source/extensiondefinition, and source/fhir.ini lists structuredefinition as an active resource. StructureDefinition.context is a repeating BackboneElement with required context.type and context.expression children, and its definition links to the defining extensions page. The linked page now documents the three context types, their expression formats, and that extensions are used only on targets appearing in the context list. Later commits reorganized and clarified this area, including ea10008f8a and FHIR-38630 commit 081c0d7685.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already avoids the old semicolon-separated format and provides the context-type documentation requested by the resolution, so another wording edit would be redundant.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-3650 unless a future work group decision changes how StructureDefinition.context should express extension contexts.
