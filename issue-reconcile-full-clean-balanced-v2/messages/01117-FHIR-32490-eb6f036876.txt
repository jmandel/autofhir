FHIR-32490: Audit external substitution terminology correction

Issue request:
FHIR-32490 was an Applied/Persuasive Pharmacy technical correction against FHIR-core MedicationPrescription/MedicationRequest. It reported that allowedCodeableConcept codes had a bold Definition/description label in front of the actual definitions and should not; the accepted resolution was to initiate the UTG process to correct the terminology content.

Initial application:
No core FHIR commit was found that mentions FHIR-32490 or UP-556. Current active MedicationRequest source binds MedicationRequest.substitution.allowed[x] to the external terminology ValueSet v3-ActSubstanceAdminSubstitutionCode, and the local MedicationRequest value set/example reference the external CodeSystem v3-substanceAdminSubstitution rather than defining the affected codes in core. The actual application path was UTG issue UP-556, which modified input/sourceOfTruth/v3/codeSystems/v3-substanceAdminSubstitution.xml and reached Proposal Implemented.

Additional context:
Pharmacy's May 2021 WGM minutes record the group finding the Definition text on substance admin substitution and deciding that UTG needed to make the change. UP-556 comments confirm the technical correction was removal of the bold Description label from those descriptions. TSMG's THO publication page lists UP-556 as included in THO version 6.0.2, and a bounded fetch of the THO 6.0.2 CodeSystem showed no prefixed Definition or Description labels in the v3-substanceAdminSubstitution concept definitions. Zulip searches for the issue keys and affected terms found no conflicting discussion.

AutoFHIR reconciliation:
This commit intentionally makes no core source change and records an external-repo decision. Editing the current FHIR checkout would not address the source of truth for the affected code definitions, while the current core build-scope MedicationRequest sources already point to the external terminology artifact that UP-556 corrected.

Recommendation:
Keep this audit commit as-is for core. If stale rendered output is later observed, refresh the terminology package or follow up in THO/UTG rather than changing MedicationRequest source definitions in core.
