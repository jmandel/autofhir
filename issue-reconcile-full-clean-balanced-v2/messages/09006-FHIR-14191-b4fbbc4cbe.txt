FHIR-14191: Align canonical URL version guidance

Issue request:
FHIR-14191 was Published/Persuasive for STU3. It reported that StructureDefinition.url said the URL SHOULD include the major version of the structure definition, which conflicted with canonical reference guidance that keeps the business version outside the canonical URL and references a specific version with the `|` syntax. The approved resolution was to broaden Resource version/canonical URL guidance and change the URL comment to say that choosing between a new business version under the same URL and defining a new artifact is up to the author, with considerations in Technical and Business Versions.

Initial application:
The issue appears to have been applied in git commit 7ee661f6b4022414f36a63274872d7ef207a8716 (svn 14500), which explicitly mentions GF#14191 with GF#15615 and GF#17105. That commit expanded source/resource/resource-notes.xml with Resource Identity, canonical URL, semantic versioning, and tradeoff guidance, and simplified the canonical URL section in source/references.html to link back to Resource identity. The current StructureDefinition.url source already has the approved canonical identifier definition and versioning comment, but later source rework left two active parallel canonical-resource URL definitions with the old major-version sentence.

Additional context:
Resource, StructureDefinition, ObservationDefinition, and SpecimenDefinition are active current-build resources in source/fhir.ini. source/references.html still documents canonical version references using `{{CanonicalResource.url}}|{{CanonicalResource.version}}`, and source/resource/resource-notes.xml still explains the Technical and Business Versions tradeoff and says there is no single best practice. The combined branch already has a no-change audit for FHIR-15615, applied by the same historical commit; FHIR-17105 is same-family identity terminology context but is not decided here. Targeted Jira, Zulip, and Confluence searches found no later issue or community evidence contradicting the FHIR-14191 interpretation.

AutoFHIR reconciliation:
This commit keeps the already-correct StructureDefinition.url wording and fixes the remaining build-scoped stale copies. ObservationDefinition.url and SpecimenDefinition.url now use the canonical identifier short/definition and the same versioning comment pattern used by other MetadataResource/CanonicalResource URL elements. The ObservationDefinition pattern-mapping exception was narrowed to only the remaining real comment/requirements differences, and the ObservationDefinition/SpecimenDefinition SVG tooltips were updated as companion generated artifacts to the authoritative XML changes.

Recommendation:
Keep this source fix. It removes the only current source occurrences of the old major-version URL requirement while preserving the Resource page's intentionally flexible guidance about when to put major-version semantics in a canonical URL. Audit FHIR-17105 separately if desired, but no additional FHIR-14191 core source work is needed.
