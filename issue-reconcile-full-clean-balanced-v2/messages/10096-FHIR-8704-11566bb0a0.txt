FHIR-8704: Audit unbound binding strengths

Issue request:
FHIR-8704 was a Published/Persuasive DSTU1 FHIR-core profiles issue asking that elements with unbound bindings (no valueSet reference) not publish a required binding strength. The exemplar was Encounter.hospitalization.reAdmission with strength required and no binding reference.

Initial application:
The issue was applied in git-svn commits 8f49b5a5d1b3c665726162148b67a86bef8bc9f6, aba5a84eb72c0b924c56a0a719df63525e6137c7, and 5277cd48bd7e1b226a0190a07c1e4d728b245ce3. The first generator change suppressed binding.strength when BindingMethod.Unbound, the follow-up made the binding summary tolerate a null strength, and the final adjustment set BindingStrength.EXAMPLE for unbound bindings because ElementDefinition.binding.strength remained required in that model.

Additional context:
Current source has renamed Encounter.hospitalization to Encounter.admission; the original reAdmission binding is in active Encounter build scope and now has strength example plus the v2-0092 valueSet. A current scan of StructureDefinition XML found 17 binding elements with strength and no valueSet, all strength example and none required, extensible, or preferred. Later FHIR-48325 added the descriptive binding strength and an invariant for descriptive bindings without valueSet, and that issue is already represented on the combined branch. FHIR-46606 removed the obsolete terminologies Unbound section; current source has no unbound section.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current specification no longer contains the FHIR-8704 defect of a required binding strength without a valueSet reference. Removing or reclassifying remaining example/no-valueSet bindings would be a later descriptive-binding policy cleanup, not the DSTU1 fix represented by FHIR-8704.

Recommendation:
Keep this audit commit as-is. If the work group wants existing no-valueSet example bindings migrated to descriptive, handle that as follow-up to FHIR-48325 or a new terminology decision rather than reopening this historical FHIR-8704 application.
