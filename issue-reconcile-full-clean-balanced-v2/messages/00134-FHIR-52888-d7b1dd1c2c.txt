FHIR-52888: Audit MedicationRequest effectiveTiming application

Issue request:
FHIR-52888 was Applied/Persuasive for R6 by Pharmacy. It asked to support duration-only medication use periods by changing MedicationRequest.effectiveDosePeriod, and initially MedicationDispense too, to an effectiveTiming[x]-style element with Duration, Range, and Period options and updated wording for duration/range use.

Initial application:
The source history shows the change was applied in MedicationRequest only: commit 7fbc42437c78 renamed MedicationRequest.effectiveDosePeriod to MedicationRequest.effectiveTiming[x], added Duration/Range/Period, and updated the short/definition; commit 4e75382be732 split those three codes into separate type entries. No corresponding MedicationDispense source change was made.

Additional context:
The current build configuration actively includes both MedicationRequest and MedicationDispense, and records MedicationRequest.effectiveTiming[x] as an R6 addition plus MedicationRequest.effectiveDosePeriod as renamed to it. Pharmacy meeting notes after implementation clarify that MedicationDispense has no effectiveTiming element, making that part of the original wording inapplicable, and the WG voted to acknowledge that the resolution was applied only to MedicationRequest. The only remaining old effectiveDosePeriod reference found in source is a checked-in MedicationRequest SVG diagram, which is generated-looking/non-authoritative and is not an appropriate sole source-changing target under this reconciliation run.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The authoritative MedicationRequest StructureDefinition on the combined branch already has effectiveTiming[x] with Duration, Range, and Period and the requested wording, while MedicationDispense correctly remains unchanged under the later Pharmacy clarification.

Recommendation:
Keep this no-change audit as-is. Do not add the element to MedicationDispense without a new Pharmacy decision; if diagram artifacts are later regenerated as part of normal build maintenance, the stale MedicationRequest SVG label can be refreshed then.
