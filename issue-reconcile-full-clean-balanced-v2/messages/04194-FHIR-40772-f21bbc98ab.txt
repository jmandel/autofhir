FHIR-40772: Audit If-Match delete application

Issue request:
FHIR-40772 was an Applied/Persuasive FHIR-core HTTP change request asking for ETag/If-Match support on delete interactions. The approved resolution required adding Conditional Delete to the If-Match HTTP Header notes, adding Conditional Delete text describing If-Match behavior, and adding optional If-Match usage to the summary table's Conditional column for delete interactions.

Initial application:
The issue was already applied in source/http.html by commit d69932573d630eaa30b7e564a368a45eb72c69ca, with the same patch also visible as 7a0dc065da24291877e19eca91892cd909ae9d11 in history. That implementation added the Conditional Delete link under the If-Match header, added the conditional delete If-Match paragraph, and changed the delete row in the HTTP summary table from N/A to O: If-Match. Later HTTP table work added additional delete-history rows that follow the same If-Match pattern.

Additional context:
FHIR Infrastructure minutes and the Zulip block-vote announcement record FHIR-40772 as part of a November 2023 FHIR-I block vote with a 12-0-0 Persuasive result. The implementer Zulip thread "Delete and If-Match" shows the practical request for preventing conflicting updates/deletes and points to filing FHIR-40772. A later related issue, FHIR-53878, is Resolved - change required for R6 and asks to clarify conditional-delete-single versus conditional-delete-multiple If-Match behavior, but it is not Applied or Published and is outside this default applied/published reconciliation scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/http.html already contains the three FHIR-40772 requirements: Conditional Delete is listed in the If-Match header notes, the Conditional Delete section explains use of the If-Match weak ETag, and the HTTP summary table marks delete interactions as allowing O: If-Match.

Recommendation:
Keep this no-change audit commit for FHIR-40772. Process FHIR-53878 separately when Resolved - change required issues are in scope, because that later clarification may refine the conditional delete text and table but should not be folded into this already-applied seed audit.
