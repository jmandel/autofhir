FHIR-33030: Normalize UCUM common displays

Issue request:
FHIR-33030 was a Published/Persuasive Vocab technical correction asking that display values in the Common UCUM Units value set use consistent capitalization. The decisive Jira resolution said UCUM displays should be lower case, and later Jira comments/minutes refined the target to align with the NLM/UCUM example displays while retaining intentional UCUM example casing.

Initial application:
The issue was initially applied in git commit 931fe86d01 ("Applied FHIR-33030"), which normalized many display values in source/valueset/valueset-ucum-common.xml, including the Jira examples. The current branch had drifted: later UCUM common cleanup and deduplication left the active value set with mixed-case displays such as "Thousands Per MicroLiter", "KiloInternationalUnitsPerMilliLiter", and "MICROCURIE".

Additional context:
FHIR-36012 later removed UCUM comments and deduplicated stripped common codes; that work explains why the file changed again, but it did not supersede the FHIR-33030 capitalization decision. The value set source is in current build scope because source/fhir.ini maps valueset=ValueSet and source/valueset/list-ValueSet-examples.xml references ValueSet/ucum-common. Confluence minutes confirm the Vocab decision trail, and a 2026 Zulip discussion independently noted the same ucum-common display inconsistencies without identifying a contrary work-group decision.

AutoFHIR reconciliation:
This commit updates the active source/valueset/valueset-ucum-common.xml display values back to the FHIR-33030-applied capitalization/display choices for codes that still exist after FHIR-36012, and lowercases the one stripped-code display (mU/mmol) whose exact code did not exist in the earlier file but whose capitalization drift was the same. It leaves historical generated release files untouched.

Recommendation:
Keep this source change as-is. It restores the published FHIR-33030 correction in the current build source while preserving the later FHIR-36012 code/comment cleanup. A separate terminology review would be appropriate only if Vocab wants a broader refresh of every display text against a newer UCUM/NLM data source, which is beyond this applied capitalization correction.
