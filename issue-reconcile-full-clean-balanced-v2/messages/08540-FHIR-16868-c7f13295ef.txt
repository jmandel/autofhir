FHIR-16868: Audit canonical identifier distinction

Issue request:
FHIR-16868 was a Published FHIR-core/fhir-i STU3 change request, resolved Not Persuasive with Modification, asking whether the canonical URI approach overlapped with the Identifier datatype. The accepted decision was to keep canonical explicit because canonical-typed elements identify conformance-style resources through their url/canonical identity and carry behaviors beyond Identifier or plain uri syntax, while adding explanatory wording and replacing confusing "logical" language on definitions such as StructureDefinition.url.

Initial application:
The Jira application comment records svn revision 14329. In git, that revision is b85b7c0892fd3098df3356f0a28fe5952f5a70bc, "GF#17008 + GF#16868: canonical URL updates", which changed source/references.html by adding canonical URL search notes and a generated list of resources with canonical URLs. The direct r14329 hunk was shared with FHIR-17008 and did not by itself carry all of the later canonical terminology now visible in the source, but it establishes that the FHIR-16868 resolution entered the canonical-reference source history.

Additional context:
Later related canonical terminology work, especially FHIR-18673, clarified the relationship among the canonical datatype, resource url elements, and optional |version suffixes. Current build-scope source now has a CanonicalResource interface with separate url and identifier elements: url is the canonical identifier and can be the target of a canonical reference, while identifier is an additional Identifier. source/references.html is active for Reference/canonical guidance, source/resource/resource-notes.xml is active for resource identity guidance, and source/canonicalresource/structuredefinition-CanonicalResource.xml plus source/structuredefinition/structuredefinition-StructureDefinition.xml provide current conformance-resource definitions. Related FHIR-17008, FHIR-18673, and FHIR-17537 decisions are already represented on the combined branch and do not require another source change here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already explains that canonical references use the canonical datatype to refer to a resource url element, documents the CanonicalResource.url|CanonicalResource.version form, identifies the allowed canonical-resource targets, describes canonical URLs as a special kind of business identifier and the preferred way to reference conformance or knowledge resources, and distinguishes CanonicalResource.url/StructureDefinition.url from Identifier-valued additional identifiers.

Recommendation:
Keep this audit commit as-is for FHIR-16868. No FHIR core follow-up is needed unless a future work-group decision reopens the cross-cutting canonical URL, canonical reference, or Identifier policy; redundant wording on the references page would risk drift from the existing CanonicalResource and resource-identity guidance.
