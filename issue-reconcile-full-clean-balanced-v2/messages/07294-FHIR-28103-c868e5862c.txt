FHIR-28103: Audit capabilitystatement expectation contexts

Issue request:
FHIR-28103 was a Published/Persuasive FHIR-core R4 change request applied for R5. It asked to add CapabilityStatement contexts to the capabilitystatement-expectation extension for resource support, extension-carried search parameter combinations, resource-specific operations, formats, patch formats, and supported profiles, and to align capabilitystatement-prohibited with that context set.

Initial application:
The request was discussed and approved by FHIR-I on 2020-07-27. In core history, commit ca6580aa55 added CapabilityStatement.rest.resource.extension to source/capabilitystatement/structuredefinition-extension-capabilitystatement-expectation.xml; the other named expectation contexts were already present in that R5 source file. The historical core application did not make a matching capabilitystatement-prohibited context update.

Additional context:
The current FHIR core checkout no longer owns these extension definitions. Commit dd468d4f17 removed source/capabilitystatement/structuredefinition-extension-capabilitystatement-expectation.xml and source/capabilitystatement/structuredefinition-extension-capabilitystatement-prohibited.xml from R5 core source when extension definitions moved out of core. The authoritative current source is in the FHIR Extension Pack. That source and the current published Extension Pack JSON contain the requested capabilitystatement-expectation contexts, including the later capabilitystatement-search-parameter-combination extension context audited by FHIR-34397, but capabilitystatement-prohibited still has only its older smaller context list.

AutoFHIR reconciliation:
No FHIR core source was changed. The remaining source-of-truth work, if the prohibited alignment from FHIR-28103 is still desired, belongs in the FHIR Extension Pack rather than this core checkout. Adding duplicate or compensating prose in core would not fix the StructureDefinition context list used by implementers and validators.

Recommendation:
Keep this empty audit commit as an external-repo decision for core. Follow up in HL7/fhir-extensions to decide whether capabilitystatement-prohibited should be aligned with the current capabilitystatement-expectation contexts or whether later work-group intent intentionally kept the prohibited extension narrower.
