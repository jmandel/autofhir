FHIR-23711: Audit batch transaction wording

Issue request:
FHIR-23711 was Published/Persuasive for the FHIR-core HTTP page. It reported that the batch/transaction summary was misleading because it said only "Update, create or delete a set of resources in a single interaction" even though batch/transaction entries can also perform read and search interactions. The approved resolution was to describe the interaction as performing multiple operations in one interaction, with examples including create, read, update, delete, patch, and extended operations.

Initial application:
The issue was applied by commit 639dbcd2848776be444488fe66b23438c581256d, which changed source/http.html from the narrow update/create/delete wording to the approved broader example list. Current source/http.html no longer contains the old wording.

Additional context:
The HTTP page is the current source for http.html. Its summary table now says batch/transaction can "Perform multiple interactions (e.g., create, read, update, delete, patch, and/or [extended operations]) in a single interaction," and the batch/transaction section explicitly lists read, search, create, update, delete, and the operations framework. Later Applied issue FHIR-40957 intentionally changed RESTful API page uses of "operation" to "interaction" where the REST interaction term is meant, so the current "multiple interactions" wording is an intentional later clarification rather than a missed FHIR-23711 application.

AutoFHIR reconciliation:
This commit makes no source change. The current built source already removes the misleading create/update/delete-only summary and includes the relevant read/search/operation coverage in the HTTP page.

Recommendation:
Keep this audit commit as-is. Do not revert the later "interactions" wording to the exact FHIR-23711 resolution text, because FHIR-40957 established that REST interactions should not be described as operations on this page except when referring to the operations framework.
