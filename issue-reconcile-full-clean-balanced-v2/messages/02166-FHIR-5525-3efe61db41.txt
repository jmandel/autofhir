FHIR-5525: Audit Consent 80-percent alignment

Issue request:
FHIR-5525 was a Published/Persuasive with Modification FHIR-core CBCC change request from DSTU1 asserting that the old Consent Directive profile/resource content did not follow FHIR's 80-percent rule. The discussion asked that the base/key consent artifact reflect broadly implemented data such as patient, type/category, applicable period, signed date, signer, organization, and text, with more sophisticated consent-directive material handled by profiles or extensions. The final disposition says the Consent Resource did take a minimalistic approach.

Initial application:
No source commit explicitly tagged FHIR-5525 was found. The application history appears to be implicit in the move from the old Contract-based ConsentDirective/profile/IG path to the Consent resource: acc3f3137b prototyped Consent as a resource, the 2016 FMG Zulip thread listed GF#5525 among unresolved comments asking for that profile-to-resource path, and 2017 Consent STU3 commits such as 612068c158 and 687d10304f applied the resource updates and ballot improvements around the time of the 2017-01-27 vote.

Additional context:
On the latest combined branch, Consent is the active build-scoped artifact in source/fhir.ini and the old Privacy Consent Directive IG entry remains commented out. The current Consent page explicitly distinguishes simple metadata capture from more advanced computable consent rules, keeps advanced behavior optional through provision and policyBasis, and states that only the privacy use case is fully modeled even though the resource can categorize privacy, treatment, or research consent. Neighboring Consent/ConsentDirective issues FHIR-6284, FHIR-6285, FHIR-7533, FHIR-7871, and FHIR-11070 are already represented on the combined branch and reinforce the same migration/evolution context without requiring another opportunistic decision here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The build-scoped current source already reflects the final FHIR-5525 resolution by using the Consent resource as the active artifact, keeping the old ConsentDirective profile/PCD IG out of the active profile/IG build path, and providing a minimal simple-consent layer with optional computable policy/provision detail. Removing current optional elements or reworking the resource solely from the 2015 debate would conflict with the final published disposition and later accepted Consent evolution.

Recommendation:
Keep this no-change audit commit. Future changes to Consent's scope or element set should come from new, current work-group decisions; FHIR-5525 itself does not justify a source edit to the current combined branch.
