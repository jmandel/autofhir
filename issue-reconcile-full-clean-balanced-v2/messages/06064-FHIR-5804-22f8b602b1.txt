FHIR-5804: Audit Condition stage assessment targets

Issue request:
FHIR-5804 was a Published/Persuasive with Modification Patient Care change request from DSTU1 asking whether Condition.stage.assessment was too broad as Reference(Any). The accepted resolution was to change it to Reference(ClinicalAssessment|DiagnosticReport|Observation).

Initial application:
The issue was applied in svn/git history by f5d7f1054b, which changed the Condition spreadsheet from Reference(Any) to Reference(ClinicalAssessment|DiagnosticReport|Observation). A follow-up commit, 74daa24071, renamed that target to ClinicalImpression after the resource naming changed.

Additional context:
The current build no longer has ClinicalImpression or ClinicalAssessment as an active resource in source/fhir.ini. FHIR-46596 later renamed ClinicalImpression back to ClinicalAssessment, and fad1b9cf84 then removed ClinicalAssessment from the active resource set and from Condition.stage.assessment. The current CI build matches the local source: Condition.stage.assessment targets DiagnosticReport and Observation only, while ClinicalAssessment is not published in the current build.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active Condition source is not Reference(Any); it is constrained to the current in-build target profiles DiagnosticReport and Observation. Re-adding a target profile for an out-of-build ClinicalAssessment resource would be unsafe and outside the current build scope.

Recommendation:
Keep this no-change audit as-is for the current build. If ClinicalAssessment is reintroduced as an active core resource, revisit Condition.stage.assessment to decide whether the FHIR-5804 target list should again include it.
