Issue request:
FHIR-34093 was a Published/Persuasive Patient Care change request for R5 asking to remove the workflow Event mappings from Condition and to remove the scope sentence saying Condition is one of the workflow event resources.

Initial application:
The issue appears to have been applied by git commit b7395c6cf2d7b7dccb66a476c99d4e7673a60366, which removed the workflow mapping identity, the Condition-to-Event element mappings, and the Condition scope sentence linking to workflow.html#event.

Additional context:
Condition is active in the current build through source/fhir.ini. The current Condition introduction no longer contains the workflow Event sentence, and the current StructureDefinition mapping identities omit workflow while retaining unrelated SNOMED CT uses of the word Event. The Patient Care minutes record FHIR-34093 as discussed on 2021-12-02, and a later Patient Care Zulip thread confirms Condition was removed from Event as part of FHIR-34093 rather than identifying a reversal.

Recommendation:
Keep this no-change audit commit as-is. No follow-up source work is needed for FHIR-34093 unless Patient Care opens a new issue to realign Condition with the workflow Event pattern.
