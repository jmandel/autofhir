FHIR-48767: Clarify encounter compartment guidance

Issue request:
FHIR-48767 was Applied with a Persuasive with Modification resolution for R6. It asked that DiagnosticReport.encounter stop implying the order encounter and instead describe the encounter, when it exists, during which the reported data or specimens were obtained/acquired, while pointing order association to ServiceRequest.encounter through DiagnosticReport.basedOn. The final disposition kept the word "typically" in the first sentence.

Initial application:
The main DiagnosticReport.encounter comment was applied by PR HL7/fhir#3278, merged as 72e89a45b3b2fac6f33d372c6bb92da61dc80f48, with implementation commit e5e7f9730cf2cf4ca41940ae5911de6a16c38980 changing source/diagnosticreport/structuredefinition-DiagnosticReport.xml. Current source/diagnosticreport/structuredefinition-DiagnosticReport.xml and the DiagnosticReport event mapping exception both contain the approved comment. That application did not update the active encounter compartment note in source/compartments.xml.

Additional context:
DiagnosticReport is an active resource in source/fhir.ini, and CompartmentDefinition artifacts are in the current build classification in publish.ini. OO WGM minutes for 2025-01-27 record the final motion, including the decision to keep "typically" because encounter granularity can vary. The related Zulip discussion likewise shows the ambiguity was about practical encounter granularity and ServiceRequest encounter association, not an intent to leave DiagnosticReport.encounter undefined.

AutoFHIR reconciliation:
This commit updates source/compartments.xml to remove the stale DiagnosticReport example asking whether the encounter was when the report was initiated or reported. The compartment note now preserves the general warning that encounter granularity can vary across implementations and directs readers to each resource's encounter element definition for the intended association.

Recommendation:
Keep this source change as-is. It completes the already-applied DiagnosticReport.encounter clarification by removing a conflicting compartment-page example without duplicating the full element-definition wording or changing conformance rules.
