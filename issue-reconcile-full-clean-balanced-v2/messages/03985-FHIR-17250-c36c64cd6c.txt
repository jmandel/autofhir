FHIR-17250: Audit ProductPlan name search expression

Issue request:
FHIR-17250 was a Published/Persuasive PA change request raised against ProductPlan in STU3. It asked to change the ProductPlan name search parameter expression from `name | alias` to `ProductPlan.name | ProductPlan.alias`; the Jira resolution clarified that the unqualified FHIRPath was valid because the resource prefix is optional, but accepted the requested form for consistency with other search parameters.

Initial application:
The PA work group minutes for January 2019 record the issue summary and a 5-0-1 motion to disposition it as persuasive. The source application was commit 614e254d88b3c419c51d87958f6ef3bf3308cc25, which changed the then-active successor file `source/insuranceplan/bundle-InsurancePlan-search-params.xml` from `name | alias` to `InsurancePlan.name | InsurancePlan.alias` after ProductPlan had been renamed to InsurancePlan.

Additional context:
Current `source/fhir.ini` lists InsurancePlan and InsuranceProduct as active PA resources and records ProductPlan as renamed to InsurancePlan. Later Applied issues in the same ProductPlan/InsurancePlan family restructured the model: FHIR-24827 split InsurancePlan/InsuranceProduct, and FHIR-33272 added an InsurancePlan.product search parameter. The current InsuranceProduct `name` search parameter now carries the name/alias search behavior and already uses `InsuranceProduct.name | InsuranceProduct.alias`; current InsurancePlan no longer has name or alias elements or a name search parameter.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The historical request was applied, and the current active source preserves the requested fully qualified expression style on the current resource that owns the name/alias fields. Adding a name search parameter back to InsurancePlan or editing out-of-scope ProductPlan references would be inconsistent with the later model split.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-17250 unless a future PA decision changes which resource owns the name/alias search semantics.
