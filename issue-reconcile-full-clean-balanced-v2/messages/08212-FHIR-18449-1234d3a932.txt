FHIR-18449: Audit whitespace signature guidance

Issue request:
FHIR-18449 was Published/Persuasive for FHIR-core JSON after STU3. It asked whether the JSON comparison note saying digital signatures may depend on whitespace was still true after canonicalization work, and its approved correction was to say that JSON and XML pretty-printing whitespace is not part of resource content, may but need not be preserved, and is ignored by digital signatures that follow HL7 signature guidance and the defined canonicalization mechanisms.

Initial application:
The issue was applied historically by commit c97b471ed7602c78c16ad0d68daba08be8783afc, which changed source/resource-formats.html from the old JSON-only whitespace warning to the current JSON-and-XML canonicalization wording. Current blame still attributes the relevant whitespace/signature sentence to that commit, and the page remains an active Resource Definitions page in source/hierarchy.xml.

Additional context:
The current Signature datatype section links readers to the dedicated signatures page, and source/signatures.html now contains the active canonicalization guidance for JSON, JSON-XML, and XML signatures. The adjacent XML canonicalization whitespace issue FHIR-18441 has already been reconciled on the combined branch and supports treating the current signatures page as the centralized guidance. Later FHIR-51194 is only Triaged/unresolved and proposes additional XAdES whitespace guidance plus broader signature-page cleanup, so it is not a final decision that changes this seed.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The active current-build resource formats source already contains the approved FHIR-18449 replacement text and points through the Signature datatype to the canonicalization guidance that explains why formatting whitespace is ignored.

Recommendation:
