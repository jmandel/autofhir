FHIR-7001: Audit Resource validate mode label

Issue request:
FHIR-7001 was a Published/Persuasive FHIR-core change request against BaseResource/resource operations. The DSTU1 ballot comment said the Resource $validate operation description used "[missing]" for the case where no mode parameter is supplied, which made the specification look incomplete, and asked for that label to be corrected to "Mode Not Provided".

Initial application:
The issue was applied in SVN revision 6418, imported as git commit 270c3c07be0eb9ca74f2e225891344f959f71885. That commit changed the Resource spreadsheet operation description from "[missing]" to "[mode not provided]" in the $validate mode list. Later source refactoring in commit 33b409a4b6d544598262f2f074ebb4b6dc466157 moved the operation definition into source/resource/operationdefinition-Resource-validate.xml and preserved the corrected label.

Additional context:
The current build includes Resource as an active resource in source/fhir.ini, and source/resource/list-Resource-operations.xml references OperationDefinition/Resource-validate. Current source has no remaining "[missing]" label under source/. A later Triaged issue, FHIR-37998, raises broader open questions about $validate mode semantics, and FHIR-8446 separately corrected a typo in the adjacent create-mode sentence, but neither changes the FHIR-7001 request or requires a source edit for this reconciliation.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current OperationDefinition already says "[mode not provided]: The server checks the content of the resource against any schema, constraint rules, and other general terminology rules", which addresses the published ballot request without adding redundant wording.

Recommendation:
Keep this audit commit as-is. Revisit Resource $validate semantics only through later unresolved work such as FHIR-37998, not through FHIR-7001, because this issue's specific missing-label correction is already present in build-scope source.
