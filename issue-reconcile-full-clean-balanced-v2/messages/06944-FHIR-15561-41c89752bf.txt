FHIR-15561: Align Task.focus guidance with approved wording

Issue request:
FHIR-15561 was an Applied/Persuasive OO change request asking for guidance on when Task may stand alone versus when Task.focus should reference the entity being acted on. The approved resolution was to add: "If a Task is seeking to instantiate or modify an entity represented by a FHIR resource, the resource SHOULD be pointed to by the Task.focus."

Initial application:
The issue was initially applied by git commit 15f0305d04ad1b63634ef0462c0a443d1eb02842 via PR HL7/fhir#3532. That commit added guidance to source/task/task-introduction.xml, which is in build scope because source/fhir.ini has an active task=Task resource entry. However, the committed sentence used the earlier proposed wording, saying a Task seeking to instantiate or modify "something" SHALL point the entity to Task.focus, rather than the final voted SHOULD wording limited to entities represented by FHIR resources.

Additional context:
OO minutes for 2025-05-02 record both the earlier proposed text and the final motion, with the final motion matching the Jira resolution. Local Zulip searches for FHIR-15561 and the Task.focus guidance did not find conflicting community discussion. Nearby Task source already describes stand-alone tasks and Task.focus, so the required reconciliation is only to align this single guidance sentence with the approved resolution.

AutoFHIR reconciliation:
Updated source/task/task-introduction.xml to use the final approved wording: entities represented by a FHIR resource SHOULD be pointed to by Task.focus. This preserves the guidance requested by the issue while avoiding the stronger, broader SHALL rule that was not approved.

Recommendation:
Keep this source-changing commit. No additional core source edits are needed unless OO later chooses to make this guidance a formal invariant or to add examples beyond the approved clarification.
