FHIR-33125: Audit maxSize unit clarification

Issue request:
FHIR-33125 was a Published/Persuasive FHIR-core technical correction, raised against R4 and applied for R5, asking what unit the maxSize extension uses and noting that if the unit is bytes then an integer type might seem more appropriate than decimal. The accepted resolution was to clarify that maxSize expresses bytes and to correct the SDC example to use the decimal value for 1 MB, 1024*1024; it did not direct a datatype change.

Initial application:
The Jira comments identify the core work as "Git Questionnaire-fixes ddcae05a32". Commit ddcae05a3224ff3ab56cefb5c8d224363f79a99b changed the maxSize source short from "Max size in MB" to "Max size in bytes" and changed the definition to say "maximum size in bytes", while leaving the extension value type as decimal. The SDC-side example work was reported in Jira comments as completed separately in SDC commits dd06c20 and e629984.

Additional context:
The maxSize StructureDefinition source that FHIR-33125 originally changed is no longer owned by the current FHIR core checkout: commit dd468d4f1799dd79819315b211588ef1cf4586e0 removed extension definitions from R5 source. Current core source only has generic references to maxSize from Questionnaire guidance and the element-extensions introduction, while the current FHIR Extension Pack definition at input/definitions/multiple/StructureDefinition-maxSize.xml says "Max size in bytes" and "maximum size in bytes" and still declares value[x] as decimal. The original Zulip thread and SDC minutes confirm the question and Persuasive decision but do not add a later instruction to change the datatype.

AutoFHIR reconciliation:
This commit makes no source change. The approved core clarification was historically applied, the actionable maxSize StructureDefinition now lives in the Extension Pack and already carries the bytes wording, and changing the datatype from decimal to integer would go beyond the Published resolution.

Recommendation:
Keep this no-change audit for FHIR core. If the community wants to revisit whether maxSize should be constrained to integer in a future release, that should be handled as a new Extension Pack change request because the current source of truth is outside this core checkout and the FHIR-33125 resolution retained decimal-valued examples.
