FHIR-8711: Audit Extension valueMarkdown casing

Issue request:
FHIR-8711 is a Published/Persuasive DSTU1 technical correction asking that the Extension.value[x] type list not show a bare lowercase "markdown" entry when neighboring list entries were presented with TitleCased names such as Boolean.

Initial application:
The request was applied in git-svn commit df193182d00959edc0df05745da24da89edf132c, svn r7047, with the message "#8711 - fix case of types on extensibility page". That commit replaced the old bare type-name list with explicit choice element names, including `valueMarkdown : markdown`. Commit dcd3ffda9020726ce3628f04603b19e4bf289c52 later single-sourced the wildcard datatype list into the current `[%extension-type-list%]` placeholder.

Additional context:
Extension remains an active infrastructure type in source/fhir.ini. The current extensibility narrative still says the instance element name is `value` plus the TitleCased type name and delegates the list to `[%extension-type-list%]`. The current primitive datatype source defines the canonical type code as lowercase `markdown`, and the current build surface renders `valueMarkdown: markdown` while Extension.value[x] carries the type code `markdown`. No directly relevant Confluence reference or conflicting Zulip discussion was found.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current specification preserves the FHIR-8711 correction at the representation level by showing `valueMarkdown`, and changing the linked datatype code to `Markdown` would now be incorrect because primitive type codes are lowercase.

Recommendation:
Keep this no-change audit as-is. No core follow-up is needed unless a future publisher regression renders the choice element as bare lowercase `markdown` again.
