FHIR-18229: Audit ShareableActivityDefinition profile disposition

Issue request:
FHIR-18229 was Published/Persuasive for STU3 and asked core FHIR to define a ShareableActivityDefinition profile, analogous to ShareableValueSet, requiring the publishing metadata elements url, version, name, title, experimental, description, date, and publisher.

Initial application:
The issue was applied by commit 4a041981ba ("GF#18229: Added ShareableActivityDefinition profile"), which added the ActivityDefinition shareable spreadsheet source and profile references. Historical release artifacts for R4 and R5 include StructureDefinition/shareableactivitydefinition, and the source just before later removal contained the requested metadata constraints.

Additional context:
The current R6 source no longer contains the ActivityDefinition shareable or publishable profile definitions or an ActivityDefinition profile pack entry. That absence is intentional: FHIR-48393 was Applied/Persuasive to remove these base-spec profiles because ShareableActivityDefinition and related CDS profiles had already moved to CRMI, and FHIR-32623 was later resolved No Change on the same grounds. Current Clinical Reasoning and Shareable pattern source directs implementers to CRMI for Shareable, Publishable, Computable, and Executable profiles, and the current CRMI package defines an active CRMI Shareable ActivityDefinition profile.

AutoFHIR reconciliation:
No source change was made. Recreating StructureDefinition/shareableactivitydefinition in core would reverse the later applied FHIR-48393 decision and conflict with the current build scope, where ActivityDefinition is active but the old profile files and pack entries are intentionally absent. The remaining OID entry is historical identifier metadata and does not make the removed profile part of the current build.

Recommendation:
Keep this audit commit as-is. Do not restore the old core ShareableActivityDefinition profile; future changes to the shareable ActivityDefinition constraints should be handled in the CRMI implementation guide unless a new work-group decision brings the matured profiles back into core.
