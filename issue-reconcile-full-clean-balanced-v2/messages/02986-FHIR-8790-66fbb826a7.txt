FHIR-8790: Audit AuditEvent display guidance

Issue request:
FHIR-8790 was a Published Security WG change request, resolved Persuasive with Modification, asking for AuditEvent notes guidance that coded values do not need their displayName populated when the code is sufficient and omitting display text helps keep large audit logs small.

Initial application:
The guidance was applied by git-svn commit bc340a2b5e2ea88134bec7cf3609a7f62deb5c3f, "Updates from Security WG on AuditEvent 8790, 9229, and 9408," which added the requested sentence to source/auditevent/auditevent-notes.xml. The AuditEvent resource is active in source/fhir.ini, so source/auditevent/auditevent-notes.xml is in current build scope. Later source history retained the note while refactoring the page and correcting the FHIR element wording from displayName to the coded value's display element.

Additional context:
Current source/auditevent/auditevent-notes.xml already says that when using vocabulary codes, the code's <code>display</code> element can be left off to keep AuditEvent small and reduce the impact of large logs of similar entries. Jira search for the same display/log-size topic found FHIR-8790 and one broader value-set-overlap issue, but no later issue changing this guidance. Zulip and Confluence searches found no directly relevant or conflicting discussion.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because the current active AuditEvent notes already convey the intended rule in current FHIR terminology.

Recommendation:
Keep this audit commit as-is. Revisit only if the Security WG wants to change the broader policy about when display text is useful in audit logs; FHIR-8790 itself is already applied.
