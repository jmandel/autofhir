FHIR-8013: Audit MedicationStatement patient requirement

Issue request:
FHIR-8013 was Published/Persuasive for the DSTU1 MedicationStatement resource and asked to change the old MedicationStatement.patient cardinality from 0..1 to 1..1 because there was no identified reason to record a MedicationStatement without a patient.

Initial application:
The issue was explicitly applied in git commit 69f89876e418aee19a0f4c07df9b7d17504fb10e, whose message says "#8013 made patient 1..1" and whose patch changed the old medicationstatement-spreadsheet.xml row for MedicationStatement.patient from 0..1 to 1..1. The Jira snapshot also records a 2015 "done" comment.

Additional context:
MedicationStatement is an active current-build resource in source/fhir.ini, and fhir.ini maps the old R2/R3 name MedicationStatement.patient to the current MedicationStatement.subject. Later event-pattern and naming changes preserved the required cardinality under the successor element; the current StructureDefinition has MedicationStatement.subject 1..1 with Patient and Group target profiles. FHIR-38682 later changed the temporary MedicationUsage name back to MedicationStatement. Searches for FHIR-8013, the old path, and the issue phrase in Jira, Zulip, and Confluence found no conflicting community or work-group record.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current authoritative source already requires MedicationStatement.subject exactly once, so it preserves the FHIR-8013 cardinality decision even though the element is now named subject and can also refer to a Group because of later model evolution.

Recommendation:
Keep this audit commit as-is. No FHIR-8013 follow-up is needed in core; any future discussion about whether Group should remain a MedicationStatement subject is a separate medication-resource modeling question, not a missed application of this tracker.
