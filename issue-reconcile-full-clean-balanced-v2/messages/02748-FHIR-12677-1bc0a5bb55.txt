FHIR-12677: Audit obsolete AuditEvent type vocabulary

Issue request:
FHIR-12677 was a Published/Persuasive DSTU2 Security issue asking for the AuditEvent.entity.type/object-type vocabulary to include all FHIR Resource types because the then-current value set did not expand as intended.

Initial application:
The issue was applied in svn revision 11573, now git commit d77b92a0d6e5c152b8db44042542cc8a8629707d, which changed the AuditEvent spreadsheet binding from an inline object-type code list to valueset-audit-entity-type and added source/auditevent/valueset-audit-entity-type.xml with an include for http://hl7.org/fhir/resource-types.

Additional context:
AuditEvent is active in source/fhir.ini, but current AuditEvent no longer has AuditEvent.entity.type. Later Published/Persuasive Security issues FHIR-32466 and FHIR-32467 concluded that entity.type was unnecessary or inappropriate because AuditEvent.entity.what is a Reference. Current source/auditevent/structuredefinition-AuditEvent.xml defines AuditEvent.entity.what as Reference(Resource), and the FHIR-32467 reconciliation already removed the remaining stale narrative reference to entity.type on the combined branch.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. Re-adding FHIR Resource types to the old audit-entity-type value set for the seed request would target a vocabulary for a removed element and would conflict with the later current-spec model where FHIR resource identity and type are conveyed by entity.what.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-12677 unless a separate terminology cleanup asks whether the now-unbound audit-entity-type value set should be retired or reshaped for non-FHIR identifier use.
