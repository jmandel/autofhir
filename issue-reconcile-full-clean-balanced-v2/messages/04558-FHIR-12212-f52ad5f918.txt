FHIR-12212: Audit ServiceRequest referral recipient targets

Issue request:
FHIR-12212 was a Published Patient Care change request with a Persuasive with Modification resolution. It asked that ReferralRequest.recipient allow Reference(HealthcareService | Practitioner | Organization) so referrals could target a specific service, and that HealthcareService be removed from ReferralRequest.definition.

Initial application:
The issue was applied in SVN-derived commit e6bb3b754b6b4790aed43bf8ac08422c794bfe6e, which explicitly mentioned #12212 and changed source/referralrequest/referralrequest-spreadsheet.sheet.txt so ReferralRequest.definition no longer targeted HealthcareService and ReferralRequest.recipient did target HealthcareService.

Additional context:
ReferralRequest is no longer an active resource in the current build; source/fhir.ini records that ReferralRequest became ServiceRequest, while ServiceRequest and HealthcareService are active resources. In the current ServiceRequest source, ServiceRequest.performer carries the old request-recipient semantics by alias and includes HealthcareService in its target profiles. The current request definition/protocol representation no longer allows HealthcareService as a definition target; ServiceRequest.code's CodeableReference targets ActivityDefinition and PlanDefinition, not HealthcareService. A later Zulip referral-specialty thread discussed ServiceRequest performer/performerType use and did not identify any conflicting rule.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active ServiceRequest source already preserves the accepted recipient targeting behavior and does not retain HealthcareService as a protocol/definition target.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-12212 unless a future work group decision changes the ServiceRequest performer or code/definition model.
