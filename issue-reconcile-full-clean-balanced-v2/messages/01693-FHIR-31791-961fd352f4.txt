FHIR-31791: Audit medicinal product status modifiers

Issue request:
FHIR-31791 was a Published/Persuasive BR&R change request for R5 asking that status be marked as a modifier for the medicinal product resources using the AdministrationStatus/status value set family, specifically the R4-era MedicinalProduct and MedicinalProductPackaged artifacts.

Initial application:
The requested modifier metadata was applied before this reconciliation. Current reachable history shows PackagedProductDefinition.status gaining isModifier=true and the standard status modifier reason in 0fd1d4b0d3, an explicit FHIR#31791 commit. MedicinalProductDefinition.status carries the same metadata in current source, with blame through b749d02904 after the medicinal product rename/refactor path; all-ref history also contains an explicit FHIR#31791 MedicinalProductDefinition application commit.

Additional context:
The current build no longer has active MedicinalProduct or MedicinalProductPackaged resource folders. source/fhir.ini actively builds MedicinalProductDefinition and PackagedProductDefinition, records their normative status, and includes R4-to-current name migration entries for the old medicinal product family. No Jira, Zulip, or Confluence search found a later conflicting decision.

AutoFHIR reconciliation:
No source change was made. The current build-scope StructureDefinition sources already mark MedicinalProductDefinition.status and PackagedProductDefinition.status as modifiers and include an isModifierReason explaining that these status values can indicate a record should not be treated as valid.

Recommendation:
Keep this audit commit as-is. Further source edits for FHIR-31791 would be redundant unless a later BR&R decision changes the status modifier policy for these resources.
