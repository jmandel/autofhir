FHIR-17905: Audit Attachment pages already present

Issue request:
FHIR-17905 was a Published/Persuasive MnM change request asking for a core extension on DocumentReference.content.attachment or the Attachment datatype to indicate the number of pages in an attached document. The final resolution was that the request had already been applied to Attachment.

Initial application:
No git commit explicitly tagged FHIR-17905 was found. The current source shows the request was applied through the Media-to-DocumentReference work: commit 5c62f91cd81f150be72ad506c876e3cc20bd631d, titled "Merger of Media into DocumentReference GF#19250", added Attachment.pages with cardinality 0..1, type positiveInt, short text "Number of printed pages", and definition "The number of pages when printed". A FHIR-19250 Jira comment confirms that this branch included "the addition of page count to Attachment, requested by Grahame and GF#17905".

Additional context:
Attachment is an active datatype in source/fhir.ini, is published through the datatypes page, and is marked normative/att. DocumentReference is an active resource in source/fhir.ini, and DocumentReference.content.attachment is typed as Attachment, so the Attachment-level page count directly covers the originally requested DocumentReference use case. The original Zulip thread established the scanned-document/document metadata use case and discussed the uncertainty of page size; the final source wording limits the element to pages "when printed" rather than inventing a separate DocumentReference-only extension.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source already contains the requested Attachment.pages element, and adding a redundant extension or DocumentReference-specific text would conflict with the Jira resolution to apply the concept at Attachment scope.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-17905 unless the work group later decides that Attachment.pages semantics need more detail beyond "when printed".
