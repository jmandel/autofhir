FHIR-12389: Audit corrected schematron typo

Issue request:
FHIR-12389 was a Published/Persuasive DSTU2 technical correction reporting that generated fhir-all-xsd/patient.sch, and later all generated schematron files, contained an invalid Narrative.div XPath because the allowed XHTML element list had the sup string malformed as an unterminated value.

Initial application:
The Jira comments record that the defect was already fixed. Git history confirms this was applied by fca89030d4acb9ec764e2c0dad4ef561c46101f7 on 2016-12-02, which changed the shared Narrative.div invariant in source/datatypes/narrative.xml from 'sup, to the syntactically valid 'sup', before the Jira was resolved and published.

Additional context:
The current build still uses the shared Narrative datatype source through active fhir.ini infrastructure/type entries, and Patient remains an active resource. No current checked-in .sch files exist in this source tree, so the old fhir-all-xsd generated artifact is not an authoritative editable source location. Zulip/Confluence searches found no substantive community discussion or later decision contradicting the fixed source state.

AutoFHIR reconciliation:
This audit commit makes no source changes because the current authoritative Narrative.div XPath already contains separate 'sub' and 'sup' string literals and searches found no surviving malformed sup token in current source.

Recommendation:
Keep this no-change audit commit as-is. If a future generated publication artifact reintroduces the malformed schematron, regenerate it from the current source rather than editing generated .sch output by hand.
