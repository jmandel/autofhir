FHIR-47660: Correct ImagingStudy endpoint descriptions

Issue request:
FHIR-47660 was Applied/Persuasive with Modification for R6 by Imaging Integration. It asked to clean up the ImagingStudy.endpoint detailed description by moving the parenthetical example to the end of the first sentence, linking the implementation-notes reference, removing the study-level override sentence from the definition, clarifying the endpoint requirements/comments treatment, and removing the comma after "(e.g., JPG, PNG)" in the comments.

Initial application:
The issue was initially represented by PR 3319 and the Jira-tagged commit 95c0b231efd40caecc3993a69c142a6190fda3d2, merged in 34c21d3320791eccd74e38ecdf9079268382a2e1. That commit accidentally applied a simplified study-level definition to ImagingStudy.series.endpoint rather than to ImagingStudy.endpoint, deleting the series endpoint comment and requirements while leaving the study-level endpoint definition unchanged.

Additional context:
ImagingStudy is an active resource in source/fhir.ini, so source/imagingstudy/structuredefinition-ImagingStudy.xml is in current build scope. Later Applied issue FHIR-50775 and PR 3636 deliberately updated the study endpoint requirements/comment text, including removing examples from requirements and changing QIDO-RS "information" to "metadata"; this reconciliation preserves those later changes rather than deleting the fields based on the older FHIR-47660 table. Later endpoint-notes work in FHIR-54767 continues to describe the study/series endpoint override behavior in the implementation notes, so the study-level override sentence need not remain in the element definition.

AutoFHIR reconciliation:
This commit applies the compatible FHIR-47660 changes to ImagingStudy.endpoint by moving the parenthetical example, hyperlinking the implementation-notes reference, removing the duplicated override sentence from the definition, and removing the comma after "(e.g., JPG, PNG)" in the comment. It also restores the series-level endpoint definition, comment, and requirements that were accidentally overwritten by the original FHIR-47660 implementation.

Recommendation:
Keep this commit as-is. It corrects the source-authoritative endpoint descriptions while preserving later accepted endpoint requirements/comment changes; no follow-up is needed unless the work group wants a separate review of the older baseLocation wording in requirements.
