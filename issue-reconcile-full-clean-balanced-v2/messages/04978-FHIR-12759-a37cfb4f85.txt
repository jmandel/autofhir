FHIR-12759: Audit Timing offset reconciliation

Issue request:
FHIR-12759 was a Published DSTU2 MnM change request asking to change Timing.repeat.offset from unsignedInt to a signed number so offsets could be negative or positive. The final Not Persuasive with Modification resolution rejected negative offsets as confusing with event codes such as before lunch and after dinner, and instead directed adding PHS, adding an invariant that offset is only permitted when when is present and not C, CM, CD, or CV, and updating the examples.

Initial application:
The Jira comment says the change was applied in svn revision 11175. Git commit 275544940db8c103d6e53cbd607e8dfc0edb38f3 (#12759) is that application: it added Timing event code PHS, strengthened the Timing.repeat offset invariant text and FHIRPath expression, and changed the meal Timing example from period/periodUnit to a positive offset with ACM.

Additional context:
Timing is an active normative datatype in source/fhir.ini. The current Timing source keeps Timing.repeat.offset as unsignedInt, defines it as minutes from the event with before/after determined by the event code, includes PHS as after the subject goes to sleep, and retains the FHIRPath invariant excluding C, CM, CD, and CV when offset is used. The current datatype examples still show the corrected ACM plus offset=30 pattern. The linked Zulip thread explains the original negative-offset debate and shows why the final Jira resolution chose event-code semantics instead. A direct Zulip key search and Confluence Jira-reference search did not reveal later community evidence changing the decision.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Changing offset to a signed type would contradict the final Jira resolution, and the current authoritative source already carries the requested PHS code, invariant, and corrected example semantics. The remaining legacy XPath text in the spreadsheet source is weaker than the FHIRPath expression, but current generated R5 history uses the FHIRPath expression for this constraint, so that legacy column does not justify a current-build source fix for this issue.

Recommendation:
Keep this no-change audit for FHIR-12759. No follow-up is needed for the current core build unless a separate work item explicitly reopens legacy XPath or old-release schematron maintenance.
