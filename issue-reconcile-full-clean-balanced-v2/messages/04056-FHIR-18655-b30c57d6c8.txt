FHIR-18655: Audit CodeSystem parameter-combination guidance

Issue request:
FHIR-18655 was a Published/Persuasive with Modification STU3 Vocabulary change request for FHIR-core CodeSystem. It asked whether CodeSystem operation definitions should define error conditions for invalid parameter combinations. The resolution said these combinations could not be defined formally, should be investigated for R5, and that additional text plus an example rejecting a bad parameter combination should be added to make wrong combinations clearer.

Initial application:
The Jira comment identifies git 4907f9bcb0b710cb2837a93a20c4b23210a37249. That broad terminology-ballot commit added response examples for the CodeSystem $lookup, $subsumes, and $validate-code operations, including an OperationOutcome example for $validate-code when a required system parameter is missing. Later source restructuring moved the operation definitions into source/codesystem/operationdefinition-CodeSystem-*.xml while preserving the CodeSystem operation examples.

Additional context:
The current build includes CodeSystem as an active resource in source/fhir.ini, and source/codesystem/list-CodeSystem-operations.xml actively references the $lookup, $validate-code, and $subsumes OperationDefinitions. The current OperationDefinition descriptions now state the relevant allowed input combinations: $lookup requires system+code or coding; $subsumes requires both A and B code/Coding inputs and a system unless invoked on a CodeSystem instance; and $validate-code requires exactly one of code+system, coding, or codeableConcept, with url or codeSystem required when not invoked at instance level. Later FHIR-33941 work refined $validate-code output parameters but retained and strengthened the input-combination sentence. Zulip and Confluence searches found no directly relevant conflicting community discussion.

AutoFHIR reconciliation:
This is an empty no-change audit commit. The current authoritative source already provides the requested guidance and the active examples include an error response for a missing required parameter, so adding more prose would be redundant rather than a needed current-spec correction.

Recommendation:
Keep this audit commit as-is. Revisit only if the Vocabulary work group later wants formal computable constraints for these combinations or a broader editorial pass over the operation examples.
