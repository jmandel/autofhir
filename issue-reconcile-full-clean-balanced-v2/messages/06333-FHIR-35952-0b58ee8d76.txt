FHIR-35952: Audit TestScript subset assertions outside core

Issue request:
FHIR-35952 was a Published FHIR-core TestScript change request, resolved Persuasive for R5. It asked to let TestScript assert.path or assert.expression select a subset of a request or response fixture when using minimumId or validateProfileId assertions, by modifying the then-current tst-5 and tst-6 "single assertion" constraints to allow path/expression plus minimumId/validateProfileId combinations.

Initial application:
The issue was approved by FHIR-I on 2022-02-07 and applied in HL7/fhir commit 2dea2a39f38e90040b839591d0261cb44ee589e0, merged by PR #1681. That commit updated source/testscript/structuredefinition-TestScript.xml so the R5 tst-5 and tst-6 expressions allowed the four requested combinations, and the commit is included in the v5.0.0 tag.

Additional context:
Current core no longer owns TestScript source. Commit f9a44787c45071394532c7c2ee94d76f30f47387 removed TestScript, TestReport, and TestPlan from active source/fhir.ini resource metadata and deleted source/testscript while adding the FHIR Testing IG as an additional IG. Current core source links TestScript to that external Testing IG. A later same-artifact decision, FHIR-50529, was Applied/Persuasive with Modification for R6 and replaced the old combined TestScript assert constraints with split singular-assertion and operator/value constraints; PR #3607 applied that change, and the combined branch already contains the FHIR-50529 external-repo audit commit 270207568b71bff812fa9c48d6d9dcb0f2343f46.

AutoFHIR reconciliation:
This is an empty external-repo audit commit. No core source change is appropriate because there is no active core TestScript source to patch, and the current external TestScript artifact follows the later FHIR-50529 constraint semantics rather than the older FHIR-35952 exception expression.

Recommendation:
Keep this audit commit as-is for core. Do not restore the old FHIR-35952 combinations in the core checkout. If the work group wants to re-allow selector-plus-minimumId or selector-plus-validateProfileId behavior after FHIR-50529, that follow-up should be made in HL7/fhir-testing-ig and explicitly reconcile the singular-assertion constraint decision.
