FHIR-26866: Audit ResearchStudy registration quantities

Issue request:
FHIR-26866 was a Published/Persuasive with Modification BR&R R5 change request asking to add ResearchStudy site and subject quantity support for clinical trial registration. The accepted resolution did not add the proposed quantity elements directly: participant planned/actual counts were to be handled through ResearchStudy.recruitment, and a parallel siteRecruitment extension was to carry site-level recruitment detail including inclusion/exclusion criteria.

Initial application:
The source history shows partial issue-tagged and implicit application rather than a single clean FHIR-26866 implementation commit. Commit 9175459a6e explicitly mentioned #26866 while adjusting ResearchStudy-related target profiles. Commit d7dbd7689b, in the same BR&R/clinicaltrials.gov change family, added the original ResearchStudy siteRecruitment extension with targetNumber, actualNumber, and eligibility markdown. Later ResearchStudy commits, including e1c1b87dcf, refined the participant recruitment backbone that now carries targetNumber, actualNumber, eligibility, actualGroup, and description.

Additional context:
ResearchStudy remains active in the current core build, and current core source contains ResearchStudy.recruitment.targetNumber and actualNumber for participant counts plus eligibility/actualGroup/description support. The original core extension file was intentionally removed by dd468d4f17 when extensions were removed from R5 source, and the current FHIR Extension Pack contains http://hl7.org/fhir/StructureDefinition/researchStudy-siteRecruitment. Later BR&R decisions refine how to interpret that extension: FHIR-39649 resolved No Change in 2026 and explains it exists for the uncommon case of study-site eligibility criteria and/or target number of study sites, while FHIR-50583 published a later Extension Pack change that updates siteRecruitment to targetNumber, actualNumber, description markdown, and eligibilityCriteria Reference(Group).

AutoFHIR reconciliation:
This empty audit commit makes no core source change. Adding ResearchStudy.SiteQuantity or SubjectQuantity would contradict the accepted resolution, resurrecting the siteRecruitment extension in core would ignore the Extension Pack migration, and changing the extension shape in core would conflict with the later FHIR-50583 Extension Pack decision. The current core and extension-pack sources together represent the applied issue family.

Recommendation:
Keep this audit commit as-is for the core reconciliation. No FHIR core follow-up is needed for FHIR-26866. Any future changes to the siteRecruitment extension should be handled in the FHIR Extension Pack and should take FHIR-50583 and FHIR-39649 into account.
