FHIR-8597: Audit Identifier.system value clarification

Issue request:
FHIR-8597 was a Published/Persuasive FHIR-I DSTU1 change request asking to clarify the Identifier.system example/comment so that "if the id itself is a full uri" explicitly meant the identifier value, i.e. Identifier.value, not some other id.

Initial application:
The issue was applied in SVN revision 6603, now git commit 7206db8027, which changed the Identifier.system spreadsheet example from "if the id itself is a full uri" to "if the Identifier.value itself is a full uri". A later Identifier cleanup in commit 2f577a81d2 removed that combined acme/RFC3986 example and left only the acme namespace example on Identifier.system.

Additional context:
Identifier remains an active datatype in source/fhir.ini, so source/datatypes/identifier.xml is current build-scope source. The current Identifier.system row no longer carries the ambiguous old phrase, and the current Identifier.value detailed comment now states that when a globally unique identifier is expressed as a URI in Identifier.value, Identifier.system identifies the identifier system, using urn:ietf:rfc:3986 only when no identifier system has been assigned. That active-source wording was aligned by the already published FHIR-19602 reconciliation commit, with later Identifier URI-system decisions such as FHIR-45479 supporting the same model. The current datatype narrative also says the value is the globally unique URI and describes the RFC3986 fallback.

AutoFHIR reconciliation:
No source change was made. The current active source already uses Identifier.value where the old DSTU1 issue wanted the clarification, and adding another Identifier.system example or duplicating prose would be redundant and could conflict with the later, more precise RFC3986 fallback rule.

Recommendation:
Keep this empty audit commit as-is. Future Identifier URI-system work should build on the current FHIR-19602/FHIR-45479 wording rather than restoring the older combined example.
