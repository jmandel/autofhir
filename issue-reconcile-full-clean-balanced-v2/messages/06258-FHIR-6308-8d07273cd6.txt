FHIR-6308: Audit extensible binding wording

Issue request:
FHIR-6308 was a Published/Persuasive FHIR-core Vocabulary change request from DSTU1. It asked to replace wording that described an element as bound to an "extensible value set" with wording that makes clear the binding strength is extensible, not the value set itself.

Initial application:
The issue was applied by svn revision 5722, now git commit 4bb9a06d8c4c846cd8f8447dc2fc80426104be40, which changed source/terminologies.html from "bound to an extensible value set" to "extensibly bound to value set" in the Extensible Binding Strength section. Later terminology rewrites retained the corrected concept with clearer wording.

Additional context:
The current terminology page is active build source through source/hierarchy.xml, which lists source/terminologies.html as the "Using Codes" page. Later FHIR-29968 work rewrote the same Extensible Binding Strength section and the current page explicitly states that the value set binding is extensible, not the value set itself. May 2018 Vocabulary minutes independently record the same clarification: extensible means the binding is extensible, not the value set.

AutoFHIR reconciliation:
This commit makes no source change. Current source/terminologies.html already satisfies the issue: it has a dedicated "Extensible Binding Strength" section, explicitly says the binding is extensible rather than the value set, and describes derived-profile constraints for an extensibly-bound element without reviving the misleading "extensible value set" phrasing.

Recommendation:
Keep this empty audit commit. The current source is already semantically correct, and another wording-only edit would be redundant and could destabilize the carefully rewritten extensible-binding guidance from later Vocabulary decisions.
