FHIR-17066: Audit Bundle request batch/history wording

Issue request:
FHIR-17066 was a Published/Persuasive STU3 correction for the Bundle feed definitions. It asked to change wording that only mentioned processing an entry as part of a transaction so it also covered batch processing, with the final resolution to say "as part of a transaction, batch or history Bundle".

Initial application:
The request appears to have been applied in the old Bundle spreadsheet source during the August 2018 ballot cleanup rather than in a commit explicitly naming FHIR-17066. Commit 70c2a576 changed Bundle.entry.request from a generic transaction-related label to "Additional execution information (transaction/batch/history)" and added history language; commit 52eb10a6 refined the definition to the same semantic wording carried by the current StructureDefinition.

Additional context:
Bundle is an active resource in source/fhir.ini, and the authoritative current source is source/bundle/structuredefinition-Bundle.xml. Current Bundle.entry.request already says it is processed as part of a transaction or batch and separately explains the history case. Exact Jira-wording and issue-key searches in Zulip and Confluence found no conflicting community record.

AutoFHIR reconciliation:
No source change was made. The active Bundle StructureDefinition already implements the requested transaction, batch, and history coverage, and changing the sentence to match the Jira resolution literally would be editorial rather than a needed specification correction.

Recommendation:
Keep this audit commit as-is. No follow-up is needed unless a future editorial pass chooses to restyle the Bundle.entry.request sentence across releases.
