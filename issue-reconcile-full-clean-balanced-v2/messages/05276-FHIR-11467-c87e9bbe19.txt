FHIR-11467: Audit Patient and Linkage guidance

Issue request:
FHIR-11467 was a Published FHIR-core Patient Administration change request, resolved Not Persuasive with Modification for DSTU2, asking whether Patient.link was still needed now that Linkage existed and, if so, to explain when Patient.link, Person, and Linkage should be used. The resolution required Patient linkage guidance explaining why Linkage is not appropriate for patient/person-type linkage, asked Linkage to include the same reasons, and recommended an invariant preventing Linkage use for patient/practitioner/person/relatedperson resources.

Initial application:
Commit b31c6226eb9411fe9ce4840784e0d098fd33efa4 (Tracker#11467) applied the core Patient part by renaming the Patient narrative heading to include Linkage and adding the safety rationale that Patient.link gives an internal indication on the Patient resource, while Linkage would require an additional query or _revinclude. I found no FHIR-11467-tagged commit adding the proposed Linkage invariant.

Additional context:
Later applied decisions refined the same boundary rather than requiring a stricter invariant. FHIR-48396 added explicit Patient narrative bullets saying not to use Linkage for linking patients, individuals, or encounters. FHIR-45033 and the September 2024 PA/PC WGM minutes reaffirmed that Linkage should summarize that it is not for patient/person linking and point to the Patient page. Current source/fhir.ini keeps Patient in the active [resources] section but no longer keeps Linkage there after commit fad1b9cf84ef652e88947e1a13b026c62f95334e removed additional resources, so editing source/linkage as a core build fix would be out of current build scope. FHIR-53725 is a later Triaged issue about the remaining Patient Linkage wording after Linkage moved out of core, so it is not a final decision for this reconciliation.

AutoFHIR reconciliation:
This audit makes no source change. The active Patient source already contains the FHIR-11467 safety rationale and the later FHIR-48396 explicit guidance, and the inactive Linkage source is not a current core build target. Adding the originally suggested Linkage invariant now would be broader than the current final source state and would edit a resource that is no longer in the active core [resources] list.

Recommendation:
Keep this audit commit as-is for FHIR-11467. Do not add a core Linkage invariant unless a future final PA/PC decision brings Linkage back into core scope or defines the invariant in the external/incubator artifact. Handle FHIR-53725 separately if it reaches a final Applied/Published state.
