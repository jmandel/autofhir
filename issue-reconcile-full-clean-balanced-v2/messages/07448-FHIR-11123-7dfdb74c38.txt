FHIR-11123: Audit ServiceRequest priority restoration

Issue request:
FHIR-11123 was a Published/Persuasive OO change request for DSTU2 DiagnosticRequest asking that priority not be removed because it was useful. Its final resolution treated it as a duplicate part of FHIR-10296 and states that priority was added; the comments record the key rationale that Task is not presumed to exist and the request resource should still carry the requested priority.

Initial application:
No historical source commit found by grep explicitly names FHIR-11123. The linked FHIR-10296 history shows the surrounding application: commit c3e0753c39 removed the old DiagnosticRequest.priority row while aligning DiagnosticRequest to the request pattern, and commit 135effcdc1 later reintroduced DiagnosticRequest.priority as a 0..1 code element plus a priority token search parameter before subsequent resource consolidation. Commit e9a85998b0 later removed the DiagnosticRequest source while merging it into the ProcedureRequest/ServiceRequest line of resources. FHIR-10296 itself is already represented on the combined branch by audit commit b27c8032196953ca0c337960045602d3f975c8ad.

Additional context:
The current build no longer has an active DiagnosticRequest resource to edit. source/fhir.ini lists servicerequest=ServiceRequest as an active resource, marks ServiceRequest approved, and records the historical DiagnosticOrder as subsumed into ServiceRequest. Current Request pattern source includes Request.priority, and the active ServiceRequest StructureDefinition contains ServiceRequest.priority with 0..1 cardinality, the request-priority required binding, and a workflow mapping to Request.priority. Task.priority remains present too, which is consistent with the Jira comment that priority can appear on both the authorization request and the fulfillment task.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current source already preserves the requested priority on the current successor resource, so restoring legacy DiagnosticRequest source or duplicating the already-published FHIR-10296 audit would be incorrect.

Recommendation:
Keep this empty audit commit. Future priority wording or request-pattern refinements should be handled under a current resource-specific Jira if they arise; FHIR-11123 itself is satisfied by the existing ServiceRequest.priority element.
