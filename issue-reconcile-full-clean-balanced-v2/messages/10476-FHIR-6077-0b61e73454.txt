FHIR-6077: Audit complex extension rendering

Issue request:
FHIR-6077 was a Published / Persuasive DSTU1 FHIR-core issue reporting that the XML rendering for the complex questionnaire-enableWhen extension showed a valueString/value[x] shape instead of the extension's child extensions for question and answer.

Initial application:
The Jira comment records svn revision 5909. The migrated source history contains commit 66af2b41301710f038ffc5159b623180986135e7, git-svn build@5909, with the message "#6077 - fix rendering of complex extensions". That commit changed the old XML and JSON specification generators to detect complex extensions, render sliced Extension.extension children, suppress prohibited value/extension elements, and populate child extension URLs.

Additional context:
The exact questionnaire-enableWhen extension is no longer a current core extension: Questionnaire.item.enableWhen is now modeled directly in the active Questionnaire resource source, and FHIR-19527 later moved the remaining complicated Questionnaire extensions, including questionnaire-enableWhen renamed to questionnaire-enableWhenExpression, to SDC. Current core source still documents how complex extensions are represented through Extension.extension child slices, and current extension-pack source and CI rendering show complex extensions such as geolocation with latitude and longitude child extensions rather than a single erroneous valueString.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The historical rendering defect was applied by the Jira-tagged 2015 generator commit, the old generator files are no longer present in this checkout, and the current build-scope core source already describes complex extension structure correctly. Editing current narrative would only restate existing guidance, and the old questionnaire extension is outside current core source.

Recommendation:
Keep this audit commit as-is. No current FHIR-core source correction is needed for FHIR-6077; if a future rendering defect appears, it should be investigated in the current publisher/IG rendering pipeline with a fresh issue rather than by changing these core source pages for the obsolete DSTU1 example.
