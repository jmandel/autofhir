FHIR-18017: Audit ProcessResponse process status replacement

Issue request:
FHIR-18017 is Published/Persuasive with Modification for Financial Management. It asked to add ProcessResponse.processStatus as a 0..1 CodeableConcept with an extensible ProcessOutcomeCodes binding so the outcome of the response instance could be distinguished from the outcome of the referred-to instance. The final resolution redirected the change to Task because ProcessResponse was deprecated, citing FHIR-19345.

Initial application:
No source commit found explicitly mentions FHIR-18017. The relevant application appears through the FHIR-19345/GF #19345 work: commit bbc5d920 added Financial Module Task guidance and Task financial examples, including status request and status response examples; commit 642e610a removed ProcessRequest and ProcessResponse from active resource metadata and annotated the removed resources as approved to use Task. Current source keeps ProcessResponse only as removed/out-of-build source, while active Task and Financial Module source describe using Task.output for the processing status of the targeted resource.

Additional context:
FHIR-19345 is already represented on the combined branch by a fixed reconciliation commit, so it is not republished here. The closely related FHIR-18022 request for a processStatus code set was Resolved - No Change/Not Persuasive because ProcessResponse was deprecated and replaced by Task. Current Task.output.value[x] can carry CodeableConcept or code values, and the current Financial status-response example shows Task.status="completed" for the Task instance with an output type of status and valueCode="complete" for the referenced resource. Zulip and Confluence searches for FHIR-18017/processStatus found no conflicting community evidence.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Adding processStatus to the inactive ProcessResponse source would be out of current build scope, and adding a new Task element or binding would exceed the final Jira resolution because current Task output already carries the targeted resource status/outcome while Task.status carries the Task instance status.

Recommendation:
Keep this audit commit as-is. No further core FHIR source change is needed for FHIR-18017; any future desire for a stronger Financial Management-specific status code binding on Task output should be raised as a new, current-scope change request.
