FHIR-5911: Audit MedicationRequest status date

Issue request:
FHIR-5911 is a Published/Persuasive with Modification Pharmacy WG DSTU1 change request asking FHIR to consider a MedicationPrescription dateEnded element for statuses such as completed, entered-in-error, stopped, and superseded/hold. The recorded resolution agreed that a date was needed for some statuses and said to combine the change with the medication status review.

Initial application:
The request was initially applied by historical commit 70483d7d71eda1846ef9c7d8b30f8bc7fbca1470, which added MedicationPrescription.dateEnded as a 0..1 dateTime element described as when the prescription was stopped. That initial application did not remain the final model: after MedicationPrescription became MedicationOrder, commit adf4e89f89fd36602f6b6e7520c1025949477424 applied FHIR-8442/FHIR-9301 by removing MedicationOrder.dateEnded and MedicationOrder.reasonEnded, clarifying initial authored/requester semantics, and adding eventHistory.

Additional context:
MedicationRequest is the active current resource in source/fhir.ini. The combined branch current source defines MedicationRequest.statusChanged as a 0..1 dateTime immediately after statusReason, with definition "The date (and perhaps time) when the status was changed", and also keeps MedicationRequest.eventHistory as references to relevant Provenance records. The later Published/Persuasive FHIR-32412 decision specifically added StatusChanged for when the current status took effect because implementers needed to communicate status, status reason, and status date without traversing Provenance; that issue is already represented on the combined branch by audit commit c1a45b49e573a2eb98167fcd335cfbbff732ce9a. No direct FHIR-5911 Zulip or Confluence references were found, but a 2017 implementers thread confirms Pharmacy's explanation that MedicationOrder.dateEnded/reasonEnded were removed because eventHistory/Provenance covered them, and Pharmacy WGM minutes support the later statusChanged model.

AutoFHIR reconciliation:
Made no source change. Reintroducing dateEnded would conflict with the later FHIR-8442 removal and duplicate the current, broader statusChanged element. The active MedicationRequest source already provides a status-date field for the current status while eventHistory preserves lifecycle-history context.

Recommendation:
Keep this audit commit as-is. Do not re-add MedicationPrescription/MedicationOrder/MedicationRequest.dateEnded unless Pharmacy resolves a new tracker that supersedes FHIR-8442 and FHIR-32412 or changes the current statusChanged/eventHistory model.
