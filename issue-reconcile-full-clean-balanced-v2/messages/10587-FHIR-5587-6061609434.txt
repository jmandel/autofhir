FHIR-5587: Audit profile type subset support

Issue request:
FHIR-5587 was a Published/Persuasive DSTU1 FHIR-core change request. It reported that profile tooling generated a snapshot for a multi-typed element, using Observation.performer as the example, that retained the base Reference target list when the differential had removed one target type, preventing profiles from expressing a subset of the allowed target types.

Initial application:
Jira records Grahame Grieve's 2015 comment that the problem was "already fixed as earlier fix to profile type generation." I found no current git commit explicitly mentioning FHIR-5587, which is consistent with the issue being applied in the older DSTU1 tooling history. Current build-scope source now documents that multi-type elements can be constrained and that StructureDefinition snapshots are generated by applying differentials to their base definitions.

Additional context:
FHIR-12259 later clarified the adjacent but narrower choice-type slicing rules and added source text in 2018 saying constraints limiting the acceptable list of types belong on the original [x] element and that the original element remains represented in snapshots. That supports the current source model but is not decided here because it concerns implicit type slicing for choice elements, not the specific DSTU1 target-list snapshot defect. No relevant Zulip or Confluence records were found that conflict with the Jira/source conclusion.

AutoFHIR reconciliation:
No source change was made. The current specification already conveys that profiles may constrain multi-type elements and that snapshots are populated from differentials; the reported DSTU1 tooling defect is already recorded as fixed and there is no current build-scope source omission to correct.

Recommendation:
Keep this audit commit as-is. If a concrete current publisher, validator, or $snapshot implementation still fails to propagate a reduced target/type list into snapshots, handle that as a tooling defect or new tracker rather than adding redundant normative prose to the current core specification.
