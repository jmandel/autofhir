FHIR-19885: Audit verification status terminology alignment

Issue request:
FHIR-19885 was a Published FHIR-core Patient Care change request, resolved Persuasive with Modification, asking for non-substantive alignment between the Condition verification status and AllergyIntolerance verification status value set/code system metadata. The accepted scope was to remove the extra "Codes" wording from AllergyIntolerance names/titles, remove binding-strength wording from definitions, confirm canonical status mapping for unconfirmed, and leave the incompatible URL differences unchanged.

Initial application:
The Jira implementation comment points to git commit eb7225265a5055b6f9956367ea288e88c564e8a8. That commit changed the AllergyIntolerance verification value set and code system name, title, and description, while a separate hunk in the same commit handled GF19286 Condition prose. The unconfirmed canonical-status concern was split into FHIR-20402 after the linked Zulip discussion concluded that multiple source codes mapping to one canonical status was valid and the missing display was a tooling issue.

Additional context:
AllergyIntolerance and Condition are active resources in source/fhir.ini, so their resource folders and value set sources are in the current build. The current core value sets have names and titles without the obsolete "Codes" suffix, and their descriptions no longer state a binding strength. source/status-codes.xml currently maps AllergyIntolerance.verificationStatus code unconfirmed, and Condition.verificationStatus codes unconfirmed/provisional, to the canonical unconfirmed status. The CodeSystem XML sources that existed when the Jira was applied were later removed from core as THO duplicates, and current THO artifacts retain the same no-"Codes" names/titles and no-binding-strength descriptions relevant to this issue. The Patient Care minutes record FHIR-19885 on the accepted 2019-01-10 change-request agenda; no conflicting final community evidence was found.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The active core value set sources and status-code mapping source already satisfy the accepted non-substantive alignment, the URL change was explicitly rejected for compatibility, and the core checkout no longer owns the migrated CodeSystem sources.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-19885; any future editorial harmonization of migrated THO CodeSystem metadata should be handled through THO/UTG rather than this core-source reconciliation.
