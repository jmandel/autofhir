FHIR-16321: Audit filter operator definitions

Issue request:
FHIR-16321 was a Published/Persuasive STU3 Vocabulary change request for the ValueSet filter-operator concepts. It asked to replace confusing bracketed explanations on is-a, descendent-of, and generalizes with clearer descendant/ancestor wording and to fix the descendent/descendant spelling.

Initial application:
The issue was applied by git commit d9b7f401d2146e4e43872969de5f5488cef9ce8b, recorded in Jira as svn revision 14661, against the then-authoritative source/valueset/valueset-spreadsheet.xml. That commit replaced the old "child codes" and "parent codes" explanations and initially renamed the descendent-of code, but git commit f03d0a490a047136415aa5c435af2ff32cd182e4 reversed the code-value rename and added compatibility spelling guidance. Later source refactoring moved the built filter operator CodeSystem/ValueSet content into XML resources under source/valueset/.

Additional context:
The current build includes ValueSet as an active resource in source/fhir.ini, and both ValueSet.compose.include.filter.op and CodeSystem.filter.operator bind to http://hl7.org/fhir/ValueSet/filter-operator. Current source/valueset/codesystem-filter-operator.xml defines is-a as descendant codes plus self, descendent-of as descendant codes only, and generalizes as ancestor codes plus self. Later FHIR-39264 corrected a parenthesis issue in this same definition family and FHIR-49057 confirmed that the descendent-of code spelling is normative/backward-compatible and should not be changed.

AutoFHIR reconciliation:
This audit commit makes no source change. The substantive definition clarifications requested by FHIR-16321 are already present in the active source, and the remaining code spelling difference is intentional after later compatibility decisions. Adding the missing "i.e." before the is-a parenthetical would be a non-semantic editorial change and below this workflow's source-edit threshold.

Recommendation:
Keep this audit commit as-is. Do not rename descendent-of in the current specification for FHIR-16321; any future spelling migration would require a deliberate Vocabulary work-group compatibility decision separate from this applied STU3 clarification.
