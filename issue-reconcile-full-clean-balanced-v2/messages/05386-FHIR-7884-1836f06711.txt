FHIR-7884: Audit Goal.category application

Issue request:
FHIR-7884 was a Published/Persuasive Patient Care change request from the 2015 May ballot asking to add Goal.category, modeled on CarePlan.activity.detail.category: 0..* CodeableConcept with definition "Indicates a category that the goal falls within", requirements "Allows goals to be filtered and sorted", and an example value set such as treatment, dietary, safety, behavioral, nursing, and physiotherapy.

Initial application:
The Jira comment records SVN #6806. In the migrated git history, commit 8bd3bd917d ("Goal tracker items") added Goal.category to the Goal spreadsheet as 0..* CodeableConcept, summary true, GoalCategory example binding, the requested definition and requirements text, a category search parameter, and a GoalCategory value set. The new-build conversion commit 33b409a4b6 carried that content into source/goal/structuredefinition-Goal.xml and source/goal/bundle-Goal-search-params.xml.

Additional context:
Goal is active in source/fhir.ini under [resources], with Patient Care ownership, FMM 6, and approved status. Current source/goal/structuredefinition-Goal.xml still has Goal.category 0..* CodeableConcept with the requested definition, requirement, and example binding to ValueSet/goal-category. Current source/goal/bundle-Goal-search-params.xml has the Goal-category token SearchParameter. Later Goal.category decisions do not require a core element change: FHIR-10622 intentionally kept the FHIR-defined example value set rather than mandating an external code system; a 2018 Zulip implementer thread clarified that treatment-like codes are allowed because the binding is example; and FHIR-46145/UP-599 later added outpatient codes through THO while preserving the same example-binding approach.
