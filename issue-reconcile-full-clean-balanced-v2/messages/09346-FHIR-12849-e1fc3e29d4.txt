FHIR-12849: Audit root sliceName cleanup

Issue request:
FHIR-12849 was a Published/Persuasive FHIR-core profiles issue asking why generated profiles had sliceName on the first snapshot and differential element even though that root element is not a slice. The approved resolution was to ensure the spreadsheet tool no longer carried those root sliceName values into generated profiles.

Initial application:
The Jira comment says the issue was complete in svn revision 14850. The matching git-svn commit 91f374cbc3822262cd065dee8ab454c1dec4c488, "GF#12849 - make sure not to populate slice name on slice itself," changed the old IG spreadsheet parser and added a root guard that errors when a root element carries a sliceName. That Java spreadsheet-tool path is no longer present in the current FHIR checkout.

Additional context:
The linked Zulip thread confirmed the intended rule: a StructureDefinition may have a name, but its base/root element should not have sliceName. Current ElementDefinition source says sliceName is prohibited for both type-definition and constraint-definition root elements. The current active StructureDefinition resource source also carries invariant sdf-23, "No slice name on root," and attaches it to both snapshot.element and differential.element; that invariant was separately audited for FHIR-13400 on the combined branch. FHIR-13740 is the same family for SimpleQuantity generator output, but is profile-specific and not decided by this seed commit.

AutoFHIR reconciliation:
No source change was made. A scan of current source StructureDefinitions found zero first snapshot or differential elements with sliceName, so the original generated-profile defect is no longer present in current source. The remaining authoritative source already prohibits root sliceName and validates the rule through StructureDefinition constraints.

Recommendation:
Keep this no-change audit commit. No core-source follow-up is needed for FHIR-12849; if an external IG or historical tool still emits root sliceName values, handle that in the relevant generator or IG source rather than duplicating text in core.
