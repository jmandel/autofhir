FHIR-5694: Audit SUBSETTED tag placement

Issue request:
FHIR-5694 was Published/Persuasive with Modification for DSTU1. It requested a label for resources whose content was removed for operational summary reasons rather than authorization reasons, with the resolution to add SUBSETTED to SecurityIntegrityObservationValue and use it for _summary and _fields.

Initial application:
No explicit FHIR-5694-tagged core commit was found. The relevant v3 terminology is now externalized to HL7 Terminology; the current THO SecurityIntegrityObservationValue value set is based on v3-ObservationValue concepts under _SECINTOBV, and the v3-ObservationValue code system contains active SUBSETTED with the intended operational-subsetting definition. Current core source also includes SecurityIntegrityObservationValue in the all security labels value set.

Additional context:
Later published work changed the implementer-facing placement for operational subsetting. FHIR-20698 resolved that when _summary or _elements cause data to be subsetted, SUBSETTED shall appear in Resource.meta.tag, while Resource.meta.security remains appropriate when the reason for subsetting is security/privacy policy. FHIR-32757 then removed older language that called SUBSETTED a Security Label in the update-variation guidance. The current search and REST pages now point _summary/_elements and read-subsetting guidance to SUBSETTED as a simple/common tag, and FHIR-48778 has already preferred common-tags for Meta.tag on the combined branch.

AutoFHIR reconciliation:
Made no source change. Re-adding or emphasizing SUBSETTED as an operational security label in core would conflict with the later FHIR-20698/FHIR-32757 placement clarification. The current source already preserves the terminology availability while documenting the current operational use as meta.tag.

Recommendation:
Keep this audit commit as-is. Do not change current core wording for FHIR-5694 unless a new work-group decision reopens the distinction between meta.tag and meta.security; any future terminology maintenance for the v3 code or value set belongs in the terminology source of truth rather than this core checkout.
