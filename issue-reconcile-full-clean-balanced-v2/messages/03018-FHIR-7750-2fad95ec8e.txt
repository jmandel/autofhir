FHIR-7750: Audit Provenance and AuditEvent separation

Issue request:
FHIR-7750 was a Published FHIR-core Security change request, resolved Persuasive with Modification, asking to rationalize the Provenance resource design and decouple it from AuditEvent. The final accepted action was narrower than the original requested lifecycle/action additions: update the AuditEvent introduction so that all actors involved in an auditable event should record an AuditEvent, duplicate AuditEvent records are expected in a system of systems, and missing expected actor records can indicate a security problem.

Initial application:
No source commit explicitly mentioning FHIR-7750 was found in the relevant AuditEvent/Provenance file history. The substantive application appears in git commit 26bc7b5249d06a0d7214f1523bb52b2b1a1d8d20, "Update of AuditEvent and Provenance Introduction to add TODO from Security WG vote 9/15/2015", which added the all-actors/duplicate-records AuditEvent introduction guidance and related AuditEvent/Provenance explanatory text. Later Security work refined the prose without reversing that guidance.

Additional context:
Both AuditEvent and Provenance are active resources in source/fhir.ini. Current source/auditevent/auditevent-introduction.xml already contains the accepted all-actors and duplicate-entries guidance. Current Provenance and AuditEvent definitions remain decoupled: Provenance.activity exists separately from AuditEvent.action, and later Jira decisions such as FHIR-9407 and FHIR-9417 declined or retracted broader alignment/lifecycle changes. FHIR-7567, which was cited from FHIR-7750 comments, was also Published and resolved through other change proposals. Zulip and Confluence searches for FHIR-7750 and the key AuditEvent/Provenance duplicate-entry concepts found no conflicting community evidence.
