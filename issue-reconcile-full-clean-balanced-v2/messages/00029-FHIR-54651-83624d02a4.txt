FHIR-54651: Correct DosageDetails changelog element name

Issue request:
FHIR-54651 was Applied/Persuasive with Modification for R6 Pharmacy. It asked to remove DosageDetails.simple as redundant, express simple dosing as a single step, update the dosage documentation and examples, remove the old dosdet-1 invariant, and add the replacement rule that DosageDetails.step.safety is not populated when only one step is present. The Jira follow-up comment clarifies that the target was DosageDetails, not Dosage.

Initial application:
The issue had already been applied by Jira-tagged source commits accc7b7f11, 741be42b1e, and fc2e165a09. Those commits marked DosageDetails.simple as removed in the datatype spreadsheet, updated the dosage narrative and examples, and corrected the new invariant context. The initial changelog entry, however, used the stale element name Dosage.simple even though the actual source change and Jira correction are about DosageDetails.simple.

Additional context:
FHIR-54524 and FHIR-54337 are duplicate same-change requests asking to remove DosageDetails.simple/use steps. Pharmacy Confluence minutes and the Medication Zulip thread also refer to the change as removing DosageDetails.simple. source/fhir.ini keeps datatypes and DosageDetails in the active build mapping, so the datatypes changelog is part of the current source surface for this datatype family.

AutoFHIR reconciliation:
This commit corrects source/datatypes/_changelog.txt to say DosageDetails.simple in both FHIR-54651 changelog sentences. It intentionally leaves the datatype spreadsheet, dosage narrative, invariant, and examples unchanged because they already express the applied decision.

Recommendation:
Keep this commit as-is. It fixes the remaining stale element name without broadening the applied model change, and the duplicate issues should remain background rather than separate reconcile commits.
