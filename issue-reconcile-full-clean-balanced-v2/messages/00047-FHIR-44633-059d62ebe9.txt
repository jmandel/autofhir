FHIR-44633: Audit MessageHeader destination target removal

Issue request:
FHIR-44633 was an Applied/Persuasive InM change request for R6 asking whether MessageHeader.destination.receiver, after gaining Device support in FHIR-43530, duplicated MessageHeader.destination.target. The accepted resolution was to remove MessageHeader.destination.target.

Initial application:
The issue was applied by commit 4c124a6cac, later merged by e9d5c4f11c, which deleted the MessageHeader.destination.target element from source/messageheader/structuredefinition-MessageHeader.xml. That file is build-scoped because MessageHeader is an active resource in source/fhir.ini.

Additional context:
FHIR-43530 explains why Device remained valid on MessageHeader.destination.receiver. InM minutes from 2024-04-02 record the final 4-0-0 motion to remove target after Zulip outreach found no use case. Current source/fhir.ini records MessageHeader.destination.target in the [r5-r6-changes] section, which is an expected release-delta record rather than a live element definition. The checked-in source/messageheader/messageheader.svg still contains a destination.target link, but that is a generated-looking diagram artifact and the authoritative StructureDefinition source no longer defines the element.

AutoFHIR reconciliation:
No source change was made. The current build-scoped authoritative MessageHeader XML already reflects the Jira resolution by omitting MessageHeader.destination.target and retaining destination.receiver with Device and other actor targets.

Recommendation:
Keep this audit commit as-is. Do not reintroduce target or add redundant guidance; if diagram regeneration remains a concern, handle generated SVG refresh through the normal FHIR build process rather than a one-off source reconciliation edit.
