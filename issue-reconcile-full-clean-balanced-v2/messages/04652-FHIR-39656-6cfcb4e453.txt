FHIR-39656: Audit external researchStudy search support

Issue request:
FHIR-39656 is Published/Persuasive for R5. It asked to support ObservationDefinitions linked to ResearchStudies by using the workflow-researchStudy extension and by providing a search parameter to find ObservationDefinitions linked to a ResearchStudy; the Jira also noted a possible parallel Observation use case.

Initial application:
No active core FHIR source file contains the workflow-researchStudy extension definition or SearchParameter. The applied source work happened in the FHIR Extension Pack: commit 4c38f99 created SearchParameter-workflow-researchStudy for FHIR-39656, but it did not include ObservationDefinition in the base list and the extension context was not expanded for ObservationDefinition.

Additional context:
The missing ObservationDefinition pieces were later captured by FHIR-43174 after Paul Lynch reported on Zulip that FHIR-39656 had been Published but the Extension Pack artifacts still did not mention ObservationDefinition. FHIR-43174 is already represented on the combined branch and its Extension Pack commit 8f62007 added ObservationDefinition to both StructureDefinition-workflow-researchStudy and SearchParameter-workflow-researchStudy. FHIR-41308 is also already represented on the combined branch and corrected the same SearchParameter expression in the Extension Pack to DomainResource.extension(...).value. Current core source only has OID/history or narrative links for these artifacts, while the authoritative Extension Pack XML files are in that repository's build input set.

AutoFHIR reconciliation:
This empty audit commit makes no core source change. The seed request is now satisfied in the external FHIR Extension Pack source, and adding a duplicate core ObservationDefinition search parameter or core extension definition would be out of build scope.

Recommendation:
Keep this audit commit as-is for the core reconciliation branch. No core follow-up is needed; any future content change to workflow-researchStudy should be handled in HL7/fhir-extensions, with publication/release tracking there if necessary.
