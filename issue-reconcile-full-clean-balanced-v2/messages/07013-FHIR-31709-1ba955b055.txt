FHIR-31709: Clarify history sort default

Issue request:
FHIR-31709 was a Published FHIR-I change request, resolved Persuasive with Modification for R5, asking for an _sort parameter on history interactions. The accepted values were _sort=_lastUpdated, _sort=-_lastUpdated as the default, and _sort=none.

Initial application:
The change was initially applied in git commit 639dbcd2848776be444488fe66b23438c581256d, which added the _sort row and allowed values to source/http.html. That commit did not update the older introductory sentence that still said every history Bundle is sorted with oldest versions last.

Additional context:
The originating Zulip thread confirms that newest-to-oldest was the existing default and that synchronization use cases needed a future sort parameter to request oldest-to-newest ordering. The FHIR-I 2021-08-09 minutes record the accepted Option 2 syntax using _sort=_lastUpdated, _sort=-_lastUpdated, and _sort=none. Current source/http.html is in the built documentation path from source/documentation.html and already contains the accepted _sort table.

AutoFHIR reconciliation:
This commit updates only the introductory history Bundle sentence so it describes oldest-last ordering as the default and points readers to the _sort parameter below for alternate ordering. The accepted parameter table is left unchanged.

Recommendation:
Keep this source fix. It preserves the approved default behavior while removing a contradiction that could otherwise make _sort=_lastUpdated and _sort=none appear inconsistent with the history interaction definition.
