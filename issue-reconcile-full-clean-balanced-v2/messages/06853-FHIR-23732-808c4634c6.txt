FHIR-23732: Audit DocumentReference content clarification

Issue request:
FHIR-23732 was Published as Persuasive with Modification for R5. It asked to clarify that multiple DocumentReference.content repetitions are not separate documents/pages, but represent the same document in different formats, or attachment metadata, and to add guidance that related DocumentReference resources with a transforms relationship can represent the same document in multiple formats.

Initial application:
The issue was explicitly applied by PR #716 and source commit 24ebc2aade, which changed the historical source/documentreference/documentreference-spreadsheet.xml content definition from "There may be multiple content element repetitions, each with a different format" to the accepted same-document wording and added the .relatesTo transforms note. Commit 33b409a4b6 later migrated that spreadsheet content into the current StructureDefinition XML source.

Additional context:
The originating Zulip thread records the ambiguity around using repeated content entries for separate scanned pages; Lloyd McKenzie and John Moehrke explained that DocumentReference.content assumes alternative renderings/metadata for the same document and that separate pages or transforms should use multiple DocumentReference resources linked through relatesTo. Later nearby reconciliation for FHIR-25205 confirmed the same content-versus-version distinction, and FHIR-17909 only extended the content comment with attachment.title guidance while preserving the FHIR-23732 wording.

AutoFHIR reconciliation:
This empty audit commit makes no source change. DocumentReference is active in source/fhir.ini, and current source/documentreference/structuredefinition-DocumentReference.xml already contains the approved definition, the explicit comment that content repetitions shall not contain different versions, and the requirements note about related DocumentReference transforms.

Recommendation:
Keep this no-change audit commit. No core source follow-up is needed for FHIR-23732 unless OO chooses to refine the wording through a new issue.
