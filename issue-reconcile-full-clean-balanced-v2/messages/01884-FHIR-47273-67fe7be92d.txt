FHIR-47273: Audit async-bundle result retention migration

Issue request:
FHIR-47273 was Applied/Persuasive with Modification for FHIR-core async-bundle. It asked whether completed async-bundle result data remains available after a status response, requested that Delete state it removes status/result data, and requested a note warning clients not to assume data will remain after Response-Error or Response-Complete.

Initial application:
The issue was applied in HL7/fhir PR #3192. Commit 2ec22b111ac864f3a09b21dd6bdcfe3326022760 changed source/async-bundle.html to say the server SHOULD delete all data associated with the request after Delete and added the requested STU note that servers MAY delete associated data after it becomes available or after a status request returns it. Commit 20f5f9eef2942b1045c1bb74a603017de6a90652 later adjusted the note from "client may not receive" to "the client did not receive" before PR #3192 merged.

Additional context:
FHIR-I minutes for 2024-10-07 record the FHIR-47273 persuasive vote, 7-0-0. Later R6 normative changes in 270e0ceb7b029dad4ca0fc5ccf5296ff370888cd deleted source/async-bundle.html and source/async-bulk.html from FHIR core and changed current core pages to delegate detailed async patterns to the API Incubator. The current FHIR core checkout no longer has source/async-bundle.html, while HL7/api-incubator-ig has input/pagecontent/async-bundle.html containing the FHIR-47273 deletion and retention text. Current rendered API Incubator URLs used by core returned 404 during this audit, so publication/link repair is an external follow-up rather than a reason to restore the deleted core page.
