FHIR-13356: Audit Composition versionNumber handling

Issue request:
FHIR-13356 was a Published FHIR-core / Structured Documents change request with resolution Persuasive with Modification. It asked whether Composition needed a CDA ClinicalDocument.versionNumber equivalent; the approved resolution was to add a standard extension for recording version in the ClinicalDocument on FHIR profile.

Initial application:
The issue was applied for STU3 in commit ab4c4aa3eb2b890c90489e60f06a124b0d556fae, "GF#13356 - add extension for versionNumber on Composition", matching the Jira comment that cited svn revision 13100. That historical application added the composition-clinicaldocument-versionNumber extension/profile machinery rather than a base Composition element.

Additional context:
Current core source has moved beyond the original STU3 profile-extension shape. Composition is an active resource, and source/composition/structuredefinition-Composition.xml now contains Composition.version mapped to CDA .versionNumber. Later SDWG decisions FHIR-34407 and FHIR-38201 removed the ClinicalDocument profile and the core versionNumber extension hooks because the base Composition.version field replaced the extension for R5 and later; both related issues already have audit commits on the combined branch. FHIR-38000 independently recognized Composition.version as the model for adding DocumentReference.version. The FHIR Extension Pack still carries composition-clinicaldocument-versionNumber as a legacy pre-R5 extension with endFhirVersion 4.3 and explanatory text saying Composition.version should be used in R5+.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core build already has the versionNumber-equivalent data element as Composition.version, the old ClinicalDocument profile and core extension definition are no longer active core artifacts, and the remaining extension-pack artifact is outside this checkout and intentionally scoped to pre-R5 use.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed for FHIR-13356; future changes to the legacy extension-pack artifact should be made in the FHIR Extension Pack repository, and any new ClinicalDocument profile should be handled as a new SDWG project.
