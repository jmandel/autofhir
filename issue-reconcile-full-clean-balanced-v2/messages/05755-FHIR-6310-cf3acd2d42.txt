FHIR-6310: Audit MedicationStatement planned-use status

Issue request:
FHIR-6310 was a Published Pharmacy change request with resolution Persuasive with Modification. It asked for a MedicationStatementStatus value to represent a medication planned for future use because DSTU1 forced such statements into the in-process status. The approved resolution was broader than one new code: all statuses would be reviewed and updated using the Pharmacy status spreadsheet.

Initial application:
The Jira comment identifies svn 6552 as the application. Git commit d3c2a3a0552f97b710394710badf5ee4e69c0d56 is svn 6552 and changed MedicationStatement.status from in-progress | completed | entered-in-error to a Pharmacy-spreadsheet status set. The immediately following commit 31e9678a6e9f698b2828df5d58dc739aad32c602 refined the same work to active | completed | entered-in-error | intended and updated the description to make status about the medication used, so the original planned-future use was historically represented by intended.

Additional context:
MedicationStatement is active in the current build through source/fhir.ini. Current source no longer uses the DSTU1/DSTU2/R4 medication-use status set because later Published Pharmacy decisions deliberately redesigned the model: FHIR-19468 and FHIR-19470 moved taking/not-taking semantics into adherence, FHIR-32060 changed status to recorded, entered-in-error, and draft, and FHIR-39271 confirmed that MedicationStatement.status now reflects the recording status of the statement while effective[x] and adherence express medication-use timing and behavior. FHIR-38682 renamed MedicationUsage back to MedicationStatement while preserving those remaining model changes. Current narrative still says MedicationStatement can record medications planned for future use.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding a planned/intended MedicationStatement.status code would conflict with the later published status/adherence design. The current build-scope source already supports future-use statements through the resource scope, effective timing, and adherence model, while status correctly remains recorded | entered-in-error | draft.

Recommendation:
Keep this no-change audit. No FHIR core source follow-up is needed for FHIR-6310 unless Pharmacy reopens the broader MedicationStatement status/adherence model in a new tracker.
