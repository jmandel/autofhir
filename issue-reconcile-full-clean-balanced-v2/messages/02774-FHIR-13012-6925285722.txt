FHIR-13012: Audit Provenance occurrence timing choice

Issue request:
FHIR-13012 was Published/Persuasive with Modification for DSTU2 Provenance. It asked to replace Provenance.period with a choice element for the activity time, using dateTime for instantaneous events and Period for longer events, and to update/add the associated timing search parameters.

Initial application:
The issue was applied in git commit 84f8086d21facb3551bfb28481156250510ae48b, which touched the Provenance spreadsheet for GF#13012. That patch changed Provenance.period to an occurred choice, commented out the prior start/end Period search rows, and added a when search row for occurredDateTime. Later source refactors moved the active definition into source/provenance/structuredefinition-Provenance.xml and the resource search parameters into source/provenance/bundle-Provenance-search-params.xml.

Additional context:
Provenance is an active current-build resource in source/fhir.ini, and fhir.ini still maps the old Provenance.period path to Provenance.occurred[x] for cross-version support. The current StructureDefinition has Provenance.occurred[x] with both Period and dateTime types. The current Provenance-when search parameter now covers both occurredDateTime and occurredPeriod after later Applied issue FHIR-54574 and its follow-up typo fix.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-source already implements the requested Provenance.period-to-occurred[x] choice and includes a date search parameter over both allowed occurrence types.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed for FHIR-13012 unless the Security WG later wants a broader editorial rewrite of the long-standing occurred[x] definition text.
