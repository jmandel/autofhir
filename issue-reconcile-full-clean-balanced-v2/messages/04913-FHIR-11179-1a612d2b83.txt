FHIR-11179: Audit ProcedureRequest occurrence alignment

Issue request:
FHIR-11179 was Published with resolution Persuasive with Modification. It asked to replace ProcedureRequest.scheduled with ProcedureRequest.fulfillmentTime because "scheduled" implied an appointment had already been made; the final resolution instead directed that ProcedureRequest and ReferralRequest align with the request pattern element name "occurrence".

Initial application:
No direct commit mentioning FHIR-11179 was found. The issue was applied through the referenced GF#10293/request-pattern history and the adjacent ProcedureRequest alignment work: commit e9a85998b0 merged DiagnosticRequest concepts into ProcedureRequest for FHIR-11119 and introduced ProcedureRequest.occurrence[x] with a mapping from Sept2016 ProcedureRequest.scheduled[x]; commit f4d7536caa changed ReferralRequest.fulfillmentTime to ReferralRequest.occurrence[x]; commit 06bd9f6ffe later renamed ProcedureRequest to ServiceRequest while preserving the scheduled-to-occurrence mapping.

Additional context:
The current build no longer has an active ProcedureRequest resource. source/fhir.ini lists ServiceRequest as active, records ProcedureRequest as merged into ServiceRequest and ReferralRequest as becoming ServiceRequest, and keeps historical rename mappings from ServiceRequest.scheduled to ServiceRequest.occurrence and ReferralRequest.fulfillmentTime to ReferralRequest.occurrence. Current ServiceRequest defines occurrence[x] and maps it to Request.occurrence[x]. Related FHIR-11119 supports the ProcedureRequest/DiagnosticRequest alignment path; FHIR-11191 records that renaming occurrence to fulfillment/fulfillmentTime was not accepted for the request pattern.

AutoFHIR reconciliation:
This audit made no source change because the active conformance source already reflects the final decision: the active request resource uses occurrence[x], not scheduled or fulfillmentTime, and the retired names are retained only in historical rename mappings.

Recommendation:
Keep this no-change audit as-is. Do not reintroduce fulfillmentTime for the current ServiceRequest element; any broader cleanup of unrelated clinical-reasoning example comments or legacy QUICK/CQL samples that still use fulfillmentTime should be handled under a separate focused issue because those examples are outside the ProcedureRequest conformance artifact decided here.
