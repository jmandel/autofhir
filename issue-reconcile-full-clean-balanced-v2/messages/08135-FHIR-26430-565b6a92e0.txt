FHIR-26430: Audit missing SearchParameter definitions

Issue request:
FHIR-26430 was a Published/Persuasive FHIR-I technical correction for FHIR-core SearchParameter, raised in R4 and applied for R5. It reported that several parameters described on search.html lacked formal SearchParameter definitions in the registry and NPM packages, especially Resource-wide parameters such as _text, _content, _list, _has, _type, and _filter, plus search-result controls such as _sort, _count, _summary, _total, _elements, and _include. The recorded resolution was to fix tooling/source so the appropriate definitions would be present.

Initial application:
No source-changing commit explicitly mentioning FHIR-26430 was found. The source was nevertheless brought into the intended state by nearby implementation commits: 1fd6427cf7 added or normalized formal Resource-level SearchParameter definitions after the linked Zulip follow-up; ddecc63591 added Resource-_type while reorganizing Resource search parameters; and a5e2e453da later restored R5 definitions for _has and _filter under FHIR-39335. The current active build configuration includes Resource, DomainResource, and SearchParameter, and current source defines the true all-resource SearchParameter resources for _content, _id, _in, _language, _lastUpdated, _list, _profile, _query, _security, _source, _tag, _has, _type, _filter, and DomainResource _text.

Additional context:
The linked Zulip thread records Grahame marking the true missing definitions fixed and Cait Ryan confirming _text, _content, _list, _has, _type, and _filter were then visible. When Cait asked about _sort, _count, _include, _revinclude, _summary, _total, _elements, _contained, and _containedType, Grahame said the committee had decided those would not be formal definitions in R4B. FHIR-I minutes for 2022-04-18 likewise say _sort and _element are not defined because they do not have type/path definitions and that CapabilityStatement can indicate support without a definition URL. FHIR-36879 later applied the durable clarification now in source/search.html: search result parameters are not SearchParameter resources and do not appear in the registry. Current CapabilityStatement comments also say non-true parameters such as _format and _count omit .definition and use type special. Related package-generation issues FHIR-32107 and FHIR-32782, and the later R5 restoration issue FHIR-39335, are already represented on the combined branch.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. Current source and current package output already contain the formal SearchParameter resources that FHIR-26430 required for true Resource/DomainResource search parameters, while the remaining search-result and HTTP control parameters are intentionally documented as non-SearchParameter controls rather than registry resources.

Recommendation:
Keep this audit as-is. Do not add SearchParameter resources for _sort, _count, _include, _revinclude, _summary, _total, _elements, _contained, _containedType, _format, or _pretty under FHIR-26430; changing that policy would require a new work-group decision and likely SearchParameter model changes, not a reconciliation fix.
