FHIR-36126: Audit search conformance scoping

Issue request:
FHIR-36126 was Published/Persuasive for the FHIR-core search page. It asked that search-page conformance statements such as SHALL/SHOULD support GET, POST, or other search behavior be qualified so they apply when an implementation supports search, not to every FHIR server regardless of its declared capabilities.

Initial application:
The issue appears to have been applied in commit a8509373541feb0c553e8c86dfe2bdf0136efee7, which made a first pass over source/search.html and changed the transport requirement from "Servers that support Search via HTTP" to "Servers supporting Search via HTTP" while preserving the GET/POST rule. Later commit e441170220c19e992f803667b245e63dcdd508cf moved the HTTP transport content from source/search.html to source/http.html without removing the search-support qualification.

Additional context:
The originating Zulip thread confirms the concern was whether servers could remain conformant while advertising no search support, especially after FHIR-31943 retained a GET/POST expectation for servers that do support search. FHIR-I WGM minutes record the 10-0-0 persuasive vote for FHIR-36126. Current source/search.html opens by saying implementers need only implement the search complexity they require, later states that servers are not required to implement any standard search parameters, and source/http.html scopes the GET/POST requirement to servers supporting Search via HTTP or REST. Later FHIR-37753 conformance-statement tagging and summary work made the current statements more reviewable but did not introduce a conflicting scoping decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active Search and HTTP source pages already convey that search behavior requirements are conditional on supported search capabilities, and adding another blanket qualifier to every search-processing statement would be redundant and risk weakening statements that already operate within a performed search context.

Recommendation:
Keep this audit commit as-is. Future work should be limited to a specific conformance statement if a reviewer identifies one that remains misleading after the existing introductory, parameter-support, and HTTP-method scoping text is considered.
