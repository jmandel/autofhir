FHIR-12683: Audit internal terminology OID rendering

Issue request:
FHIR-12683 was a Published/Persuasive DSTU2 correction for the terminology systems page. The reporter observed that the Internal FHIR tab showed OIDs such as ".1.113883.4.642.1.316" instead of the full "2.16.840.1.113883.4.642.1.316", indicating that the leading OID arc was being dropped by the build.

Initial application:
The issue was applied in historical git-svn commit e11eb8a3c8c7c90861e9471775193fdbb23d1323, matching the Jira comment for svn revision 11447. That commit changed the old Java PageProcessor internal system list renderer from outputting oid.substring(8) to outputting the full OID value returned by CodeSystemUtilities.getOID(cs).

Additional context:
The old tools/java PageProcessor source no longer exists in the current checkout, and no current source contains the old CodeSystemUtilities.getOID/substring(8) rendering pattern. The current source/terminologies-systems.html internal code-system section has URI, Title, and Description columns only, with <%internalsystemlist%> supplying rows; the current CI-rendered page similarly has no internal OID column and does not contain truncated ".1.113883.4.642" FHIR OIDs. Jira search found only FHIR-12683 for this wording, and Zulip/Confluence searches found no related or conflicting discussion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The historical tooling defect was already corrected, the obsolete affected tooling is absent from the current build source, and the current terminology systems page does not expose the stale truncated internal OID behavior.

Recommendation:
Keep this audit commit as-is. No current FHIR source edit is needed unless the internal terminology systems table is later redesigned to reintroduce an OID column, in which case that renderer should preserve the full OID including the 2.16.840 prefix.
