FHIR-31582: Audit deep contained-reference clarification

Issue request:
FHIR-31582 was Published/Persuasive with Modification for FHIR-core. It asked whether Reference.reference can point to a contained resource in another resource, such as Observation/123#pat, and the approved resolution added guidance that references to contained resources outside the immediate container must include the containing resource.

Initial application:
The issue was applied by commit ed209f540a38a0dcde5395af4b65329f835f3842, titled "FHIR-31582", and then merged through HL7/fhir pull request #1284 in merge commit 5cdf26b454d37dc39e9dab4e93486f2b58ebb7e0. That commit added the containing-resource sentence and Observation/123#pat example to source/references.html. Later formatting and adjacent contained-resource edits changed line blame but preserved the approved meaning.

Additional context:
The active source/fhir.ini type-page mapping sends the Reference data type to the references page, so source/references.html is in current build scope for this clarification. FHIR-26667 was applied in the same PR and clarified that the "never resolved outside the container" sentence applies to fragment-only URLs. Earlier FHIR-20340 was Resolved - No Change for cross-resource contained references in Bundles, while later FHIR-33008 changed a different contained-resource bullet and has already been audited on the combined branch; neither reverses FHIR-31582. The 2021 Zulip thread that prompted FHIR-31582 and the FHIR-I minutes both support the same clarification, and no later conflicting final decision was found in bounded searches.

AutoFHIR reconciliation:
Made no source change. The current source/references.html contained-resource notes already say that fragment-only contained-resource references stop at Bundle.entry.resource and Parameters.parameter.resource, that references to contained resources in a different Parameters or Bundle entry or elsewhere must include the containing resource, and that both Reference and canonical types may refer to contained resources.

Recommendation:
Keep this empty audit commit as-is. No core source follow-up is needed for FHIR-31582 unless a future work-group decision changes deep contained-resource reference semantics.
