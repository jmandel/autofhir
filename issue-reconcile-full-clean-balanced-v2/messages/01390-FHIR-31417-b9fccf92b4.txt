Issue request:
FHIR-31417 was Published with resolution Not Persuasive with Modification for R5. Patient Care decided not to add a validated date element to Condition, but to add a reviewed 0..1 dateTime extension with wording warning that a reviewed date indicates clinician review and does not imply legal or clinical validation.

Initial application:
The issue was applied in core by fae49f4994, which added source/condition/structuredefinition-extension-condition-reviewed.xml and referenced StructureDefinition/condition-reviewed from source/condition/implementationguide-Condition-core.xml. That source definition carried the Condition context, 0..1 Extension cardinality, dateTime value, and the Jira-approved caveat in Extension.comment.

Additional context:
Core commit dd468d4f17 later removed the Condition extension definitions as part of the general R5 extension migration. Current source/history.html says all extensions moved to hl7.fhir.uv.extensions while still being published as part of the specification, and current core source retains the condition-reviewed OID in source/oids.ini. The current FHIR Extension Pack checkout contains input/definitions/Condition/StructureDefinition-condition-reviewed.xml with the Condition context, dateTime value, max 1 extension cardinality, active/trial-use metadata, and the Jira caveat text.

AutoFHIR reconciliation:

Recommendation:
