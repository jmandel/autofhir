FHIR-33012: Audit extension SearchParameter base guidance

Issue request:
FHIR-33012 was a Published FHIR-I change request, resolved Persuasive with Modification for R5, asking the SearchParameters on Extensions guidance to stop saying that an extension context spanning multiple resources requires SearchParameter.base to be "DomainResource". The approved replacement says the multiple-resource context can be represented with multiple elements in the SearchParameter.base array.

Initial application:
The issue was explicitly applied by git commit 73c53b6ec7, merged through HL7/fhir#1960, which changed source/searchparameter/searchparameter-notes.xml from the DomainResource instruction to the multiple SearchParameter.base elements wording. A later same-page cleanup for FHIR-27134 refactored the extension-search guidance from XPath toward FHIRPath while preserving the multiple-base-array rule.

Additional context:
source/fhir.ini lists SearchParameter as an active resource, so source/searchparameter/searchparameter-notes.xml is in current build scope. The current source says that when an extension context specifies multiple resources, they are represented with multiple elements in the SearchParameter.base array. The original Zulip thread and FHIR-I minutes both explain the rationale: the old DomainResource workaround came from an era when SearchParameter.base was 1..1, but base has been 1..* since STU3.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current active source already reflects the Jira-approved rule, and a stale-text search found no remaining active SearchParameter instruction requiring DomainResource for multi-resource extension contexts.

Recommendation:
Keep this audit commit as-is. No FHIR-core follow-up is needed for FHIR-33012 unless a future work group decision changes extension SearchParameter base guidance.
