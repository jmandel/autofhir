FHIR-13267: Audit Provenance query guidance

Issue request:
FHIR-13267 was a Published/Persuasive STU3 Security issue asking the Security and Privacy module page to describe how a client queries for resources and asks that matching Provenance records be returned, pointing to the Search page's `_revinclude` guidance.

Initial application:
Commit 84f8086d21facb3551bfb28481156250510ae48b explicitly listed GF#13267 and added a Provenance use case to source/secpriv-module.html saying that, when Provenance records are needed in addition to query results, clients use reverse include and add `?_revinclude=Provenance:target`. Later QA and editorial commits kept the same guidance while correcting wording around it.

Additional context:
The current Security and Privacy module remains in build scope through source/hierarchy.xml. The current Search page defines `_revinclude` for reverse links and includes the same `MedicationRequest?_revinclude=Provenance:target` example, and the current Provenance search parameters include an active `target` reference search parameter. FHIR-22103 later clarified versioned-reference search behavior and `_revinclude` documentation generally, but it does not supersede the FHIR-13267 module guidance.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already satisfies the Jira request: the module page has a Provenance use case for returning Provenance records with resource query results, names reverse include, gives the `Provenance:target` parameter, and links to the Search page.

Recommendation:
Keep this no-change audit commit. No follow-up is needed for FHIR-13267 in the core source unless the Security Work Group chooses to revisit the broader Provenance retrieval guidance in a new issue.
