FHIR-17405: Audit Parameters fullUrl extension coverage

Issue request:
FHIR-17405 was a Published FHIR-I change request with resolution Persuasive with Modification. It asked for a way to carry the fullUrl associated with a resource supplied in Parameters.parameter.resource, and the accepted resolution was to add an extension for now and mention that extension for Parameters.parameter.resource.

Initial application:
The issue was applied in git commit bc27d59c15fa4b15af89e4cecfd0eb65ed5bea23, corresponding to svn revision 14457 noted on the Jira. That commit added the Parameters extension profile through the historical Parameters spreadsheet and changed source/parameters/parameters-notes.xml to link the fullUrl extension from the resource-uniqueness guidance. Later, when core extensions were moved out of this checkout, dd468d4f1799dd79819315b211588ef1cf4586e0 removed the in-core extension definition and b3e373388f8137e589fdc6b18beb9ff86a2c23cb retargeted the Parameters note to the external extension location.

Additional context:
Parameters is still an active infrastructure resource in source/fhir.ini and part of the normative package. The current core Parameters notes say the Bundle resource-uniqueness rules do not apply to Parameters unless the fullUrl extension is present on parameters with resources. The canonical extension definition now exists in the FHIR Extension Pack as input/definitions/Parameters/StructureDefinition-parameters-fullUrl.xml, with context Parameters.parameter and URL http://hl7.org/fhir/StructureDefinition/parameters-fullUrl. A 2025 implementers Zulip discussion treats the extension as available while confirming that cross-parameter reference resolution is not automatically made identical to Bundle resolution.

AutoFHIR reconciliation:
This is an empty audit commit. No FHIR core source change is needed: the current build-scope Parameters narrative already points implementers to the fullUrl extension at the external extension location, and duplicating the same guidance in the generated Parameters.parameter.resource element comment would add maintenance drift without changing the current specification behavior.

Recommendation:
Keep this no-change audit for core. If editors want to improve the extension definition prose itself, that follow-up belongs in the FHIR Extension Pack rather than in this core checkout.
