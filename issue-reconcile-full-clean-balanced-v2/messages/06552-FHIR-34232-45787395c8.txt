FHIR-34232: Audit relative-date external application

Issue request:
FHIR-34232 was Applied/Persuasive with Modification for FHIR-core extensibility-registry. It asked to improve the relative-date extension by allowing computable and user-meaningful anchors, relaxing target path handling to full FHIRPath, documenting negative/positive/zero offset semantics, adding examples and starter event codes, dropping relationship because offset conveys before/after/simultaneous meaning, updating offset wording, and renaming to relativeDate.

Initial application:
No current core StructureDefinition source was changed for this reconciliation because core no longer owns the relative-date extension definition. The applied change is in the FHIR Extension Pack: PR HL7/fhir-extensions#193 merged commit af8044eb312062732ee855353048b9c8fa00920b, which updates input/definitions/datatypes/StructureDefinition-relative-date.xml to relax targetPath guidance, describe Reference plus targetPath versus targetCode usage, deprecate relationship rather than remove it, and clarify offset before/after/zero semantics. The Jira application comment explicitly says the name was not changed and relationship was deprecated rather than removed for backward compatibility.

Additional context:
Current core source only keeps build-scoped cross-references to the extension pack, including source/clinicalreasoning-module.html's statement that the Extension Pack is source of truth and its deprecated cqf-relativeDateTime pointer to relative-date, plus canonical OID entries. Later related work created core RelativeTime (FHIR-41582), temporarily deprecated relative-date in favor of relative-time (FHIR-41598/FHIR-42948), then un-deprecated relative-date with an imminent-deprecation note while relative-time remains blocked in the Extension Pack (FHIR-50027). FHIR-39327 remains Resolved - change required and explicitly defers extension examples, so it is context rather than a final applied core edit for this seed.

AutoFHIR reconciliation:
This commit intentionally makes no core source change and records an external-repo audit decision. The current FHIR core checkout is not the authoritative source for the relative-date StructureDefinition, and reintroducing or duplicating the extension in core would conflict with the current extension-pack ownership model.

Recommendation:
Keep this audit commit as-is for FHIR core. Treat the FHIR-34232 source application as living in the FHIR Extension Pack; any remaining concern about starter event codes or examples should be handled through the Extension Pack and the still-open/deferred related trackers rather than by editing current core source.
