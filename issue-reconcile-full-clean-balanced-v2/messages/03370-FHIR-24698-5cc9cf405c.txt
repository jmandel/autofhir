FHIR-24698: Correct terminology server operation names

Issue request:
FHIR-24698 was a Published/Persuasive Vocabulary change request for R5 asking for a normative terminology service capability statement. The final resolution required minimum RESTful API requirements, the full and terminology capabilities interactions, a replacement CapabilityStatement, a TerminologyCapabilities example, and required terminology operations for CodeSystem, ValueSet, and ConceptMap.

Initial application:
The issue was applied in the FHIR-24698 implementation commits 30dd523442, 9370929d9d, 7633b9f6af, dca11a08dd, and cc83e0b51d, which added the normative terminology service conformance text, replaced the terminology server CapabilityStatement example, and added/listed the TerminologyCapabilities example. A later broad OID rework commit, 129c9fa6f54, preserved a defect in the CapabilityStatement example where several operation entries were named `expand` even when their definitions pointed to lookup, validate-code, subsumes, or translate.

Additional context:
The current terminology service page is normative and carries the minimum requirements. CapabilityStatement and TerminologyCapabilities are active resources in source/fhir.ini, and source/capabilitystatement/list-CapabilityStatement-examples.xml lists capabilitystatement-terminology-server as a current example. Later FHIR-28499 explains the additional TerminologyCapabilities.codeSystem.content requirement now shown on the terminology service page. Later FHIR-41175 explains why the ConceptMap $translate required-parameter summary now uses sourceSystem rather than the original FHIR-24698 resolution's `system` wording. FHIR-56099 is a later Resolved - change required TerminologyCapabilities change and was treated as future context, not part of this Applied/Published seed fix.

AutoFHIR reconciliation:
Updated source/capabilitystatement/capabilitystatement-terminology-server.xml so each required operation entry has a name that matches its OperationDefinition: CodeSystem lookup, validate-code, and subsumes; ValueSet validate-code; and ConceptMap translate. The ValueSet expand operation was already correctly named and was left unchanged.

Recommendation:
Keep this commit as-is. It completes the current-core application of FHIR-24698 by making the in-build terminology server CapabilityStatement accurately declare the required operations, while leaving later TerminologyCapabilities model changes to their own issue workflow.
