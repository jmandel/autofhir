FHIR-38920: Align eventNumber notification guidance

Issue request:
FHIR-38920 was Published as Persuasive with Modification for R5. The ballot request asked for SubscriptionStatus.notificationEvent.eventNumber to be optional when reliable sequencing was not required, and the accepted resolution replaced the single global-sequence meaning with either a subscription-sequence number or a notification-relative number, plus related notification-type guidance.

Initial application:
The issue was initially applied in ac3fb31772962a2b851ae9874dc2600985c7819d, which removed the older sst-1 constraint, changed the eventNumber definition/comment, and added Event Numbering narrative. That commit also left several notification-type table rows saying eventNumber was optional for guaranteed delivery, while the same Event Numbering section and the StructureDefinition cardinality continued to require a value.

Additional context:
source/fhir.ini actively lists subscriptionstatus as a current resource, work group artifact, and abbreviation, so source/subscriptionstatus/subscriptionstatus-notes.xml feeds the current build. Later FHIR-39038 restored only self-contained SubscriptionStatus constraints and did not make eventNumber conditional on Subscription/channel data. A 2024 Zulip discussion about FHIR-48808 includes Gino Canessa clarifying that FHIR-38920 resolved the optionality request by allowing a notification-local eventNumber meaning, not by making the element optional. FHIR-50625 later identified the same contradiction but remains Triaged and is not decided by this commit.

AutoFHIR reconciliation:
This commit updates the SubscriptionStatus notification-type narrative so event notifications and query-event notifications mark eventNumber as required, and handshake/heartbeat rows say eventNumber is required when a notificationEvent is included. It also clarifies that guaranteed delivery removes the need for globally tracked event numbers, not the need for an eventNumber value.

Recommendation:
Keep this source fix. It aligns the active narrative with the published FHIR-38920 resolution, current StructureDefinition cardinality, and later assignee clarification without deciding the still-open FHIR-50625 wording question beyond the inconsistency needed for FHIR-38920.
