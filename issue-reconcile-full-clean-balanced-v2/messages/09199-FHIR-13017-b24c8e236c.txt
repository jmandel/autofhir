FHIR-13017: Audit obsolete Event onBehalfOf constraint

Issue request:
FHIR-13017 was Published with resolution Persuasive. It asked to give the Event pattern's onBehalfOf element the same constraint then present on the Request pattern, limiting onBehalfOf to cases where the requester/performer agent was a Practitioner or Device, and to propagate that rule to other manifested onBehalfOf uses and the common extension. Jira comments record that FMG did not apply the item for STU3 because of appropriateness concerns, and that the issue became no longer relevant once workflow-pattern onBehalfOf was removed.

Initial application:
No source commit explicitly naming FHIR-13017 was found. History shows the old Request.requester agent/onBehalfOf backbone and invariant existed before the later workflow-pattern cleanup. Commit 99918b92010d378b1c69abb0660399a91e1c6764 added a workflow-module note that the Practitioner plus onBehalfOf Organization pattern was awkward and should be replaced with PractitionerRole. Commit 14b69a1c6dd33918b20d53ffd6cfbab523f840ba then removed the old Request.requester onBehalfOf invariant when Request and Event moved to direct references that include PractitionerRole.

Additional context:
FHIR-15128 is a later Published workflow-pattern decision about the same Request/Event onBehalfOf question. It asked to bring back Request.requester.onBehalfOf and Event.performer.onBehalfOf, but resolved not to restore them and instead to remove the stale Request constraint. The combined branch already contains ed79f31e79a3d4d5b47cb390e2d27e6cea324247 for FHIR-15128, which corrected the remaining stale Request requester search path. source/fhir.ini lists event and request as active logical models, and the current Event and Request spreadsheet sources define Event.performer.actor and Request.requester as direct references with no onBehalfOf subelement. Searches of core profile extensions and the FHIR Extension Pack found no current workflow-pattern onBehalfOf extension that would make the old Event constraint actionable; the Extension Pack only has an AuditEvent-specific OnBehalfOf extension outside this Request/Event pattern decision.

AutoFHIR reconciliation:
Made no source change. Adding the FHIR-13017 constraint now would reintroduce an obsolete workflow-pattern element and conflict with the later published FHIR-15128 resolution and current active source model. The current specification is correct for this issue family because Event.performer.onBehalfOf no longer exists, Request.requester.onBehalfOf no longer exists, and the related stale Request path has already been reconciled under FHIR-15128.

Recommendation:
Keep this audit commit as-is. Do not restore workflow-pattern onBehalfOf or the old Practitioner/Device-only constraint without a new work-group decision; use PractitionerRole under the current Request/Event pattern. Resource-specific onBehalfOf rules, such as CareTeam, Procedure, Provenance, or AuditEvent extension behavior, should continue to be handled by their own later trackers rather than by this obsolete DSTU2 Event-pattern issue.
