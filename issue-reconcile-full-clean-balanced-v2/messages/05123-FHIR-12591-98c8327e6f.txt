FHIR-12591: Audit Age positive invariant

Issue request:
FHIR-12591 was a Published/Persuasive FHIR-core datatypes change request raised against DSTU2. It reported that the Age invariant's FHIRPath expression checked for a decimal point even though Age.value must be positive, and the accepted resolution was to change the value term to value > 0.

Initial application:
The Jira comments cite svn revision 11174. In this Git history that is commit 3ad0995feb09c65e27f0c9cd6512acb34e24b248, "#12591 - fix age invariant", which changed source/datatypes/age.xml from value.toString().contains('.').not() to value > 0 in the Age invariant expression.

Additional context:
Age is an active datatype in source/fhir.ini, and source/datatypes/age.xml is the current authoritative spreadsheet source for the Age datatype. Later FHIR-15648 adjusted the same invariant to use code.exists() and value.hasValue().not(), but it retained the FHIR-12591 positive-value clause. A broad source search found an old Age-looking row in source/datatypes/distance.xml's Restrictions worksheet, but the active Age datatype has its own corrected source file and later released profile history files contain the corrected Age constraint, so that duplicate-looking row is not a current Age source fix for this issue. No Zulip or Confluence evidence was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative Age source already requires a positive value with (value.empty() or value.hasValue().not() or value > 0), and the historical application of FHIR-12591 is present in Git.

Recommendation:
Keep this no-change audit commit as-is. No FHIR-core follow-up is needed for FHIR-12591 unless a separate work-group decision chooses to clean up stale copied Restrictions worksheet rows that do not drive the current Age datatype definition.
