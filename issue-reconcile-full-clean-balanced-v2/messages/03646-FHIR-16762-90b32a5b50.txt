FHIR-16762: Correct contained canonical examples

Issue request:
FHIR-16762 was a Published/Persuasive CDS ballot issue against the clinical reasoning module's suicide-risk order-set fragment. It observed that the old inline example used a Reference-style contained target even though the corresponding PlanDefinition action definition is a canonical reference. The final Jira discussion records that canonicals can refer to contained resources and that the concern had already been addressed.

Initial application:
The canonical-contained rule was already applied before this issue was marked applied: git 2319e45e41 added the current references guidance that canonical types may refer to contained resources. Git bac90582b2 then converted the authoritative low-suicide-risk PlanDefinition example from nested Reference elements to canonical values, and git f91f58dcb6 updated the clinical reasoning inline fragments from nested Reference elements to unsuffixed definition values.

Additional context:
The clinical reasoning topic page is in current build scope through source/hierarchy.xml, and PlanDefinition is active in source/fhir.ini. A later Published issue, FHIR-18186, made PlanDefinition.action.definition[x] a choice between canonical and uri; git 72f0fdf2f4 updated the authoritative PlanDefinition XML examples to use definitionCanonical, but the copied inline fragments on the clinical reasoning topic page still showed the pre-choice form definition value. Current references.html and datatypes.html explicitly allow canonical fragment references to contained resources, so the remaining current problem was stale example syntax rather than a prohibition on contained canonical targets.

AutoFHIR reconciliation:
Updated the build-scope clinicalreasoning-knowledge-artifact-representation.html inline PlanDefinition fragments so their contained ActivityDefinition targets use definitionCanonical, matching the current StructureDefinition and authoritative PlanDefinition example XML.

Recommendation:
Keep this source correction. No further FHIR-core change is needed for the seed issue unless the work group wants a broader generated-fragment cleanup; the current normative reference guidance already permits contained canonical references.
