FHIR-12248: Audit CodeSystem lookup value types

Issue request:
FHIR-12248 was a Published/Persuasive FHIR-I change request for CodeSystem $lookup. It reported that the operation returned all output property values as string even though CodeSystem properties could be code, Coding, string, integer, boolean, or dateTime, and asked either for canonical string representations or, preferably, for $lookup property.value to allow the same typed values.

Initial application:
No explicit FHIR-12248/GF#12248 commit message was found in the current git history. The linked Zulip thread records the reporter creating GF#12248, and Grahame later saying he committed the write-up in build 10029. The matching source application is git commit 679dc9462a4671a7b3fc946ca79bbd330b37a172, which changed the then-authoritative CodeSystem spreadsheet for lookup.property.value and lookup.property.property.value from string to code | Coding | string | integer | boolean | dateTime.

Additional context:
CodeSystem and OperationDefinition are active current-build resources in source/fhir.ini. FHIR-14236 later added decimal support for CodeSystem and $lookup property values and is already represented on the combined branch. FHIR-22807 later fixed the formal OperationDefinition representation of these same $lookup allowed types and is also already represented on the combined branch. Later source refactoring introduced source/codesystem/operationdefinition-CodeSystem-lookup.xml with R4-style allowed-type extensions and then converted those to native OperationDefinition.parameter.allowedType entries.

AutoFHIR reconciliation:
This is an empty no-change audit commit. The current build-scope source already defines CodeSystem $lookup property.value and property.subproperty.value as type Element with allowedType entries for Coding, boolean, code, dateTime, decimal, integer, and string, so it preserves the seed issue's typed-value correction plus the later decimal addition.

Recommendation:
Keep this audit commit as-is. No core source change is needed for FHIR-12248; future changes to this area should be driven by a new terminology or OperationDefinition decision rather than by reapplying this already-satisfied DSTU2 tracker.
