FHIR-20355: Audit Dosage tabs

Issue request:
FHIR-20355 was Published/Persuasive with Modification for R5. It asked for Profiles and Extensions tab access on the Dosage datatype page because a Dosage extension for complex dosing was otherwise only discoverable from the main Extensions tab; the accepted resolution broadened this to extension-permitting complex types that appear on pages other than the data types page, excluding Narrative.

Initial application:
No commit explicitly mentioning FHIR-20355 was found. The related pre-request context is core commit cb366d831c, which added the original Dosage conditional-dosing extension source. The applied page work appears to have been absorbed into the R5 datatype/Extension Pack reorganization: commit 22b5c24573 created source/dosage-profiles.html and sibling profile pages for off-datatypes complex types, while removing the old core dosage-extensions profile entry because extension tables were moving to the Extension Pack.

Additional context:
Current source/fhir.ini keeps Dosage, DosageDetails, DosageSafety, and DosageCondition as active datatypes and maps them to the dosage page. The Dosage page family uses dtxheader macros and has a dedicated dosage-profiles.html source page. The Extension Pack source generates type-specific extension pages for Dosage, ProductShelfLife, ElementDefinition, and MarketingStatus, and contains Dosage extension definitions. R5 and current CI rendered pages show Dosage tabs for Profiles and Extensions, with Extensions pointing to the Extension Pack. FHIR-I minutes record the FHIR-20355 persuasive vote, and searches found no contrary Zulip or Confluence decision.

AutoFHIR reconciliation:
This is an empty no-change audit commit. The current built specification already provides the requested Dosage Profiles tab and an Extensions tab, and the current split between core source and the Extension Pack is intentional rather than a missing core source file.

Recommendation:
Keep this audit commit as-is. Do not reintroduce core dosage-extensions source or add a redundant local extensions page unless the work group later decides to move Extension Pack content back into the core build.
