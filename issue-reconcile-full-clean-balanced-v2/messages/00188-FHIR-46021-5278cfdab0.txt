FHIR-46021: Audit Permission-based Consent provisions

Issue request:
FHIR-46021 is Applied/Persuasive for FHIR-core Consent. It requested a new Consent.provisionReference element constrained to Reference(Permission), plus an invariant making provisionReference and Consent.provision mutually exclusive, so patient-specific Consent provisions could be encoded by a Permission resource.

Initial application:
The issue was initially applied by git commit 101d02d207, which added ppc-1 and Consent.provisionReference to source/consent/structuredefinition-Consent.xml. Current source no longer exposes that addition: ppc-1 and provisionReference remain only in XML comments.

Additional context:
Consent is active in the current build via source/fhir.ini, but Permission is no longer an active core resource: source/fhir.ini has no Permission resource entry and source/permission was deleted by the later "remove Permission" change merged as PR #3991. That same removal commented out the FHIR-46021 Consent element and invariant. Later Jira FHIR-53535, currently Triaged rather than final, states that this functionality was removed when Permission moved to an incubator/additional-resource IG and proposes restoring it with an extension defined outside core after FHIR-I/product-director advice.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Restoring Consent.provisionReference now would reintroduce a core element pointing at a non-core Permission resource and would bypass the still-open decision path for how Consent should refer to additional-resource/incubator Permission rules. The checked-in Consent SVG still shows provisionReference, but it is a stale generated-looking diagram artifact and is not a sufficient authoritative source target by itself.

Recommendation:
Keep this human-review audit as-is unless CBCC/Security/FHIR-I resolve the post-Permission-removal design. Follow up by resolving FHIR-53535 or an equivalent tracker, defining the Permission-side extension or other cross-spec mechanism, and then updating authoritative Consent source and regenerated diagrams together.
