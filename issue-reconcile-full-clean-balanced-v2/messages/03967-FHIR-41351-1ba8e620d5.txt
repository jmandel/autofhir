FHIR-41351: Audit $snapshot idempotency application

Issue request:
FHIR-41351 was an Applied/Persuasive FHIR-I correction request for R6 asking that Operation $snapshot no longer be described as non-idempotent. The approved resolution was to add idempotency caveat text for referenced profiles and frozen packages, and to change the OperationDefinition affectsState flag to false.

Initial application:
The current source already contains an explicit application commit, 9c3f5223412a5487c7f8765113924ca471962c1a, titled "FHIR-41351 Operation `$snapshot` is an idempotent operation". That commit changed source/structuredefinition/operationdefinition-StructureDefinition-snapshot.xml by adding the referenced-profile/frozen-package caveat to the description and changing affectsState from true to false.

Additional context:
The original Zulip discussion confirms the rationale: snapshot output can vary when referenced profiles or implementation bugs change, but for a frozen package $snapshot should be idempotent and the prior non-idempotent description was considered an oversight. FHIR-I minutes from 2024-12-09 linked the Zulip thread while preparing tracker feedback, and the 2025-12-08 FHIR-I minutes record a correction vote for FHIR-41351. source/fhir.ini lists StructureDefinition and OperationDefinition as active build resources and maps the older OperationDefinition.idempotent concept to affectsState, so affectsState=false is the current-source representation of the issue request. FHIR-18295 is a separate, already-published idempotence audit for another operation; FHIR-41220 is a separate operations wording issue mentioned in the same minutes and already has its own combined-branch commit.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative operation definition source for StructureDefinition $snapshot is in build scope and already says that referenced profile changes can change generated snapshots, says frozen-package $snapshot is idempotent, and has affectsState=false.

Recommendation:
Keep this audit commit as-is. No follow-up source edit is needed for FHIR-41351 unless a future build shows the generated operation page does not render affectsState=false as the idempotent/non-state-changing operation semantics.
