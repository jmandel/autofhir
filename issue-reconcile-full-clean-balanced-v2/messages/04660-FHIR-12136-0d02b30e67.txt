FHIR-12136: Audit AllergyIntolerance category search warning

Issue request:
Published/Persuasive with Modification PC issue asking for a clear warning that searching AllergyIntolerance.category=medication does not return AllergyIntolerance resources where the optional category is absent, with a reference to search guidance for missing elements.

Initial application:
The issue appears to have been applied in historical SVN-import commit 87f224c94c, which added the AllergyIntolerance.category usage-note text and a GF#12136 committee note to the then-current AllergyIntolerance spreadsheet source. The separate follow-up ticket FHIR-12324 was applied by e36808e812 to add global missing-data search guidance and a safety checklist entry.

Additional context:
The current build scope includes AllergyIntolerance as an active resource in source/fhir.ini. The current StructureDefinition source preserves the category warning, keeps AllergyIntolerance.category optional, and points readers to search guidance for the :missing modifier. The current search page has a Handling Missing Data section explaining that a value search omits resources with missing optional elements and that the value and :missing cases require separate queries; the safety checklist also links to that guidance. The linked Zulip thread confirms the original concern and the decision to handle the broader concern through the implementer safety checklist. No Confluence reference was found for this issue.

AutoFHIR reconciliation:
No source change was made because the current source already conveys the requested warning and the broader missing-data search guidance. Adding another local note or only tightening the existing link target would be redundant rather than a necessary semantic correction.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-core unless a work group wants to revise the general search semantics for combining valued and missing optional elements.
