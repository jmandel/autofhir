FHIR-30791: Audit ObservationDefinition instantiation supersession

Issue request:
FHIR-30791 was Published/Persuasive with Modification for R5. It asked to let an Observation explicitly reference the ObservationDefinition it conforms to, ultimately naming the new choice element Observation.instantiates[x] with canonical(ObservationDefinition) and Reference(ObservationDefinition) choices.

Initial application:
The request was applied by commit 9481fec585e37aa70d164d09a3c7ac375265d29e, which added Observation.instantiates[x] to source/observation/structuredefinition-Observation.xml. OO minutes from 2021-03-04 and 2021-03-05 record the naming discussion, vote, and post-approval integration for that R5 element.

Additional context:
Observation is active in the current build through source/fhir.ini, but later applied workflow decisions superseded the R5 core element. FHIR-40499 and FHIR-43456 removed workflow instantiates elements from OO resources in R6, with FHIR-43456 specifically directing removal of Observation.instantiates[x] and use of workflow extensions instead. The current Observation StructureDefinition and Observation search-parameter bundle no longer contain the element or its search parameters, source/observation/observation-introduction.xml documents that instantiates[x] was removed and replaced by workflow instantiation extensions, and the FHIR Extension Pack workflow-adheresTo extension is scoped to Observation and can target ObservationDefinition by canonical or Reference. FHIR-43456, FHIR-40499, and FHIR-39312 are already represented on the combined branch, so this commit does not duplicate them.

AutoFHIR reconciliation:
No source change was made. Re-adding Observation.instantiates[x] would conflict with the later applied R6 workflow-pattern decision; the current authoritative XML and search-parameter sources already reflect the intended current specification state for FHIR-30791 after later supersession.

Recommendation:
Keep this audit commit as-is. Do not re-add the R5 Observation.instantiates[x] element in core unless the work group reverses the R6 workflow-extension policy; any stale generated diagram output should be regenerated by the normal publisher pipeline rather than hand-edited as this issue's source fix.
