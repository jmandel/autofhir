FHIR-8010: Audit MedicationStatement wasNotTaken status table

Issue request:
FHIR-8010 was a Published Pharmacy change request with resolution Not Persuasive with Modification. The issue asked whether an invariant should restrict which MedicationStatement.status values were allowed when the old wasNotGiven/wasNotTaken flag was true; the final comments said all statuses were possible and that a status + wasNotTaken interpretation table should be added instead of an invariant.

Initial application:
The issue was applied in git commit 34be49d052, which added the requested interpretive status + MedicationStatement.wasNotTaken table to the then-current MedicationStatement spreadsheet comments and clarified that MedicationStatement.status mixed patient medication-use status with statement-record status. A later Pharmacy tracker commit, 3b901a8b98 for TR#12470, continued that historical line by changing notTaken to taken and adding a MedicationStatement.status + taken guidance table.

Additional context:
The current build has moved past the old wasNotTaken/notTaken/taken model. MedicationStatement is active in source/fhir.ini, but the current StructureDefinition defines status as recorded | entered-in-error | draft and says it concerns the recording of the medication statement, while MedicationStatement.adherence carries adherence/taking information. Later Published Pharmacy decisions, especially FHIR-19468 and FHIR-39271, explicitly removed not-taken from status, added/kept adherence for taking/not-taking, and reaffirmed that status is about the statement record. The related FHIR-19468, FHIR-19470, and FHIR-39271 reconciliations are already represented on the combined branch.

AutoFHIR reconciliation:
This commit makes no source change. Re-adding the old table or an invariant would be obsolete in the current source because there is no current MedicationStatement.wasNotTaken element to constrain, and status no longer encodes active/completed/intended/stopped/on-hold medication-use states. The current source already separates record status from not-taking semantics through MedicationStatement.adherence and its not-taking code.

Recommendation:
Keep this no-change audit commit. FHIR-8010 was historically applied for the DSTU/STU-era model, and the current specification is correct after later Pharmacy decisions superseded the need for the old status + wasNotTaken interpretation table.
