FHIR-3739: Audit ServiceRequest supportingInfo DocumentReference support

Issue request:
FHIR-3739 was a Published/Persuasive with Modification DSTU1 Orders and Observations issue asking DiagnosticOrder.supportingInformation to permit DocumentReference in addition to Condition and Observation, and to change the element short name from "Supporting observations or conditions for this request" to "Additional Clinical information."

Initial application:
The issue was explicitly applied in commit d6259fa8e3beda8fd5e58ad54d85001f1efb9d42, which updated the DiagnosticOrder spreadsheet so DiagnosticOrder.supportingInformation became Reference(Observation|Condition|DocumentReference), changed the short text to "Additional clinical information," and tagged the row with [#3739]. Later source-history commits carried the element through DiagnosticRequest.supportingInfo, ProcedureRequest.supportingInfo, and ServiceRequest.supportingInfo.

Additional context:
Current source/fhir.ini lists DocumentReference and ServiceRequest as active resources and records DiagnosticOrder as subsumed into ServiceRequest. ServiceRequest.supportingInfo is now the active successor element. Later FHIR-37355 changed ServiceRequest.supportingInfo from Reference(Any) to CodeableReference(Resource), which still permits DocumentReference through the Resource target profile. Later FHIR-31589 clarified supportingInfo wording without narrowing that target or changing the FHIR-3739 short text.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/servicerequest/structuredefinition-ServiceRequest.xml already carries the [#3739] committee note, the approved "Additional clinical information" short text, and a CodeableReference(Resource) type that includes DocumentReference. Editing the retired DiagnosticOrder source is out of current build scope, and adding an explicit DocumentReference target alongside Resource would be redundant and less aligned with later approved ServiceRequest modeling.

Recommendation:
Keep this audit commit as-is. The current build-scope ServiceRequest source preserves the approved FHIR-3739 behavior, so no additional FHIR core source work is needed.
