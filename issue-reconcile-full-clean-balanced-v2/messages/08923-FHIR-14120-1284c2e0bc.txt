FHIR-14120: Audit OperationOutcome all-OK example

Issue request:
FHIR-14120 was Published/Persuasive for STU3 after observing that an OperationOutcome with no detected processing problems still must contain at least one OperationOutcome.issue. The accepted resolution was to add or expose an example for a "no issues detected" OperationOutcome and mention no issues detected as an example use.

Initial application:
The Jira application comment cites svn revision 14417. In git history this is commit 8d324d06d652c7422b056ed4845d4959d5c83e43, which added OperationOutcome narrative saying the resource must include at least one issue and linking to the All OK example for operations that return no errors. The All OK example itself already existed and, after the 2015 build-fix commit a2a6af129d, included an informational issue rather than an empty issue list.

Additional context:
OperationOutcome is an active current-build resource in source/fhir.ini. Current source still lists the All OK example as "An operation outcome that could be returned after a successful operation (no issues)", the example contains the required OperationOutcome.issue with severity information and code informational, and the OperationOutcome notes page links to that example as the template for no-error operations. Later Published issues FHIR-27840 and FHIR-39622 revisited successful-outcome terminology: FHIR-27840 added code/severity alignment guidance, and FHIR-39622 later added success codes. Both are already represented on the combined branch and do not require changing the original FHIR-14120 application.

AutoFHIR reconciliation:
This audit commit makes no source change. The current build-scope source already provides the requested no-issues OperationOutcome example and explanatory note, while later terminology decisions are separate applied context rather than missing FHIR-14120 work.

Recommendation:
Keep this audit as-is. Do not duplicate the no-issues wording into the issue-type definition for this issue; if the work group wants the historical All OK example changed from information/informational to success/success after FHIR-39622, that should be handled as a focused follow-up tracker because it would interpret later terminology policy rather than simply apply FHIR-14120.
