FHIR-32899: Audit relative-date reconciliation

Issue request:
FHIR-32899 was a Published/Persuasive CDS change request for R5 asking that cqf-relativeDateTime and relative-date be reconciled. The approved resolution updated relative-date to carry a target, optional targetPath, relationship, and Duration/Range offset, and asked that cqf-relativeDateTime be dropped with references replaced by relative-date.

Initial application:
The issue appears to have been applied in core commit b550a27cd59d1aef6112ce9b6f266bec9c5c31bb, "J#32899: Updated relative-date and deprecated cqf-relativeDateTime". That commit changed the active general extensions spreadsheet to use relative-date.target as a CodeableReference, added targetPath, retained the ActionRelationshipType binding, and updated the clinical reasoning page to identify cqf-relativeDateTime as deprecated in favor of relative-date.

Additional context:
The authoritative extension definitions were later moved out of core into the FHIR Extension Pack. Current core source no longer contains the relative-date or cqf-relativeDateTime StructureDefinitions; it retains only OID registry entries and a clinical reasoning extension-table row that explicitly says cqf-relativeDateTime is deprecated and links to relative-date, with the page caveat that the Extension Pack is the source of truth. Later related work adjusted the extension family: FHIR-39327 split the event representation into targetReference and targetCode, FHIR-34232 clarified path/offset usage and deprecated rather than removed relationship for backward compatibility, FHIR-41598/FHIR-50027 introduced the longer-term relative-time direction, and FHIR-53078 refreshed the core clinical reasoning page after those moves.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The seed change was already applied historically, the remaining current core references are build-scoped registry/navigation references that do not recommend using cqf-relativeDateTime, and the authoritative extension definitions now live in the Extension Pack with later decisions reflected.

Recommendation:
Keep this audit commit as-is for FHIR core. Do not remove the core OID entries or the clinical reasoning deprecation pointer as part of FHIR-32899. Any future semantic work on relative-date, cqf-relativeDateTime, or relative-time should be handled in the FHIR Extension Pack under the later extension-pack trackers rather than by replaying the original R5 core resolution.
