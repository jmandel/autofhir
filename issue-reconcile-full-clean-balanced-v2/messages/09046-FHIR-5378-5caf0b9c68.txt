FHIR-5378: Audit ValueSet inline code-system rationale

Issue request:
FHIR-5378 was a Published/Persuasive DSTU1 vocab change request for ValueSet section 6.22.1. It asked that wording about value sets defining their own inline code systems make clear that this mechanism was appropriate for limited-scope/local values, or otherwise explain the rationale.

Initial application:
No Jira-keyed implementation commit was found. The old wording appeared in git history in ab6d7c95d1, which added ValueSet text saying inline code-system definitions were for small, simple code systems found throughout the implementation context and not for large public terminologies. Jira comments later recorded that Grahame had added the text because of other tasks. Commit 886ad6667c then renamed ValueSet.define to ValueSet.codeSystem while preserving the small/simple inline-code-system guidance.

Additional context:
The current specification no longer has ValueSet inline code systems. Commit 1120eb61d0 removed language and examples for inline code systems as part of the ValueSet/CodeSystem split. Current build scope includes ValueSet, and current ValueSet source says a ValueSet draws codes from one or more CodeSystem definitions for use in a particular context. Current terminology guidance explains locally maintained dictionaries/enumerations as code systems, distinguishes code systems from value sets, and gives an example of a mixed value set that includes a local code system URI. Quoted Zulip and Confluence searches found no conflicting or more specific community record for FHIR-5378.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Adding limited-scope prose to ValueSet would now reintroduce obsolete inline-code-system terminology; the modern source already conveys the correct local-code-system model through CodeSystem and terminologies guidance.

Recommendation:
Keep this no-change audit. Revisit only if the work group wants new general guidance on when local CodeSystem resources are appropriate; that would be a new CodeSystem/terminology policy question, not a missing application of the DSTU1 ValueSet inline-code issue.
