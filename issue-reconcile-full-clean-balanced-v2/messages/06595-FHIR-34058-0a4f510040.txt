FHIR-34058: Audit R3 comparison footer fix

Issue request:
FHIR-34058 is a Published/Persuasive FHIR-core technical correction from fhir-i, raised in R4 and applied for R5. It reported that a "Compare to R3" footer link compared R3 to the current build rather than to the fixed R4 publication.

Initial application:
The issue appears to have been applied by git commit 98f60cf87ebe753683aba53fb3039329235d1db5, which explicitly cites FHIR-34058 and changed tools/templates/newfooter.html in the R4B-era footer from a "Compare to R4" link to a "Compare to R3" link using the R3 published tree as the old-file side. Later release-cycle footer commits then retargeted the same template for R5 and R6 comparison links.

Additional context:
The current active footer template no longer contains a "Compare to R3" link. It has explicit "Compare to R4", "Compare to R5", and "Compare to Last Ballot" links whose old-file sides point to fixed published release or ballot roots and whose new-file side points to the current build. The comparison pages named by the Jira are active in publish.ini and source/hierarchy.xml. Related FHIR-23060, its Zulip thread, and FHIR-I minutes confirm the same general policy that current-build footer links should compare against the correct preceding fixed release; they do not create a current-source requirement to reintroduce an R3-to-R4 link in the R6 build.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current FHIR source already avoids the stale behavior described by FHIR-34058 for the active build: there is no active "Compare to R3" footer link, and the present comparison links are version-specific for the current release cycle.

Recommendation:
Keep this no-change audit commit as-is. No FHIR core source follow-up is recommended for FHIR-34058 unless a human chooses to audit historical published R4/R4B pages outside the current build source.
