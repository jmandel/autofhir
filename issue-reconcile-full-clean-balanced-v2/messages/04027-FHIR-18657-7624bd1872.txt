FHIR-18657: Audit CodeSystem lookup parameter note

Issue request:
FHIR-18657 was a Published/Persuasive FHIR-core CodeSystem change request from the STU3 N-Term ballot. It asked whether CodeSystem $lookup had co-occurrence dependencies beyond the existing code/system wording, and the approved resolution was to add a note that clients supply system+code(+version)(+display) or coding.

Initial application:
The Jira snapshot records Grahame's application commit 4907f9bcb0b710cb2837a93a20c4b23210a37249. That commit added an operation-level sentence to the historical CodeSystem spreadsheet saying that $lookup clients SHALL provide both system and code, either through the system+code parameters or through the coding parameter, with other parameters optional. The 2021 source rework commit 33b409a4b6d preserved that sentence in source/codesystem/operationdefinition-CodeSystem-lookup.xml.

Additional context:
CodeSystem is an active resource in source/fhir.ini and source/codesystem/list-CodeSystem-operations.xml references OperationDefinition/CodeSystem-lookup, so the current OperationDefinition is in build scope. The old resolution's display wording does not require a current edit because display is not a current $lookup input parameter, while version and current optional inputs are covered by the existing "Other parameters are optional" wording. Targeted Jira, Zulip, Confluence, and git-history searches did not identify a later final decision that reverses or narrows the $lookup co-occurrence note.

AutoFHIR reconciliation:
No source files were changed. The current build-scoped $lookup OperationDefinition already states the approved co-occurrence rule: a client SHALL provide system plus code using the system+code parameters, or provide the coding parameter, and all other parameters are optional.

Recommendation:
Keep this no-change audit commit as-is. No follow-up source work is needed for FHIR-18657 unless the vocabulary work group separately decides to revisit $lookup instance-level parameter wording.
