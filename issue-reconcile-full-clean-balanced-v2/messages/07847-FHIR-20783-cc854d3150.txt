FHIR-20783: Audit DSTU2 FHIRVersion package fix

Issue request:
FHIR-20783 was a Published/Persuasive technical correction from FHIR-I for an IG Publisher failure when a DSTU2 IG rebuilt an empty package cache and loaded hl7.fhir.core#1.0.2. The reported stack trace failed converting a StructureDefinition with unknown FHIRVersion code '1.9.0'. Jira's final resolution says this was a bug in one of the packages and is now fixed.

Initial application:
No source commit in this checkout explicitly mentions FHIR-20783. The issue appears to have been applied by repairing the affected package payload rather than by a durable source change in the current FHIR specification repository.

Additional context:
FHIR-I minutes from 2020-01-27 changed the tracker to a technical correction and will-fix item. Current source has StructureDefinition.fhirVersion bound to the FHIRVersion value set, and the current FHIRVersion code system includes DSTU2 1.0.2 as a valid code. The only current source hits for literal 1.9.0 are release-history text and an unrelated terminology resource version, not a StructureDefinition.fhirVersion value. Later FHIRVersion terminology/definition issues such as FHIR-26067 and FHIR-35168 are separate published changes and are already represented independently on the combined branch.

AutoFHIR reconciliation:
Made no source change. A current package-surface check of hl7.fhir.core#1.0.2 and its R2 dependency packages found package metadata and StructureDefinition resources using fhirVersion 1.0.2, with no fhirVersion 1.9.0 occurrences. Current source likewise has no fhirVersion 1.9.0 value to repair.

Recommendation:
Keep this no-change audit commit. Reopening source work would only be appropriate if a current package publication again exposes a DSTU2 StructureDefinition.fhirVersion of 1.9.0 or another unsupported FHIRVersion code.
