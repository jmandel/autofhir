FHIR-34279: Audit ConceptMap unmapped constraint

Issue request:
FHIR-34279 was Published/Persuasive for R5 and asked to reconcile FHIR-32540 with FHIR-15687 by updating ConceptMap invariant cmd-2 so ConceptMap.group.unmapped may carry either unmapped.code or unmapped.valueSet, but not both in the same unmapped element.

Initial application:
No source commit explicitly naming FHIR-34279 was found. The change appears to have been applied through the related ConceptMap2 history: commit 44b6a9fc8f977d070ab90083f6d1004394e83ffc added the FHIR-15687 valueSet elements and partially applied FHIR-32540, and commit 520ebaf4d363671f58b5485e1c26daa18f5ddc8b updated cmd-2 to be mutually exclusive for group.unmapped.

Additional context:
ConceptMap is active in source/fhir.ini, and commit 8623473ddfcef0cb88b9abf5241abfe6e28ea542 migrated ConceptMap2 into the current ConceptMap source. Later invariant cleanup added condition references to unmapped.mode, unmapped.code, and unmapped.valueSet, and invariant fixtures now include a valueSet-only pass case and a code-plus-valueSet failure case. FHIR-33061 usage notes also describe group.unmapped.valueSet in terms consistent with the cmd-2 rule.

AutoFHIR reconciliation:
This is an empty audit commit. The current active source/conceptmap/structuredefinition-ConceptMap.xml already states "If the mode is 'fixed', either a code or valueSet must be provided, but not both." and its FHIRPath expression enforces exactly one of code or valueSet when mode is fixed.

Recommendation:
Keep this no-change audit commit. No core source follow-up is needed for FHIR-34279 unless a future work group decision changes ConceptMap.unmapped semantics.
