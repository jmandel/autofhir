FHIR-31819: Audit referenceStrength definition clarification

Issue request:
FHIR-31819 was a Published/Persuasive FHIR-core BR&R change request for MedicinalProductIngredient asking that Ingredient.substance.strength.referenceStrength explicitly explain that the strength is expressed in terms of another substance.

Initial application:
The change appears to have been applied before reconciliation in the active Ingredient source. Commit 72c7bcfe69c0b11deaefc688b833b242cf18474c updated the referenceStrength definition under FHIR#31819, and commit 9ac982b98acc0b1b67fdc1dd53c4b087e29419f7 reapplied the same improved definition after nearby source movement.

Additional context:
MedicinalProductIngredient is redirected to Ingredient in source/fhir.ini, and Ingredient is an active resource in the current build. FHIR-31820 is the same documentation family and asks whether both strength and referenceStrength can exist; FHIR-35931 later made referenceStrength.substance mandatory, reinforcing that a reference strength must name the reference substance.

AutoFHIR reconciliation:
No source change was made. The active StructureDefinition already says referenceStrength is an equivalent expression against a closely related substance, identifies the active moiety use case, and states that when the active substance and active moiety differ, both a strength and a reference strength are needed.

Recommendation:
Keep this no-change audit commit. The current source carries the applied clarification, and adding duplicate narrative elsewhere would not change implementer understanding.
