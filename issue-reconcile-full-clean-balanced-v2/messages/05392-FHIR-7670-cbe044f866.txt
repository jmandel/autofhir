FHIR-7670: Audit referral and appointment boundary

Issue request:
FHIR-7670 was a Published/Persuasive DSTU1 Patient Care change request asking the spec to clarify the boundary between ReferralRequest and an appointment request. The accepted resolution was to explain that Appointment is for booking/scheduling, while ReferralRequest initiates care or transfer of care.

Initial application:
The issue was applied in git commit 8feebd003a016e4f1c0b83f3f45f3776029dce83 / SVN r6679 by adding a Boundaries and Relationships paragraph to source/referralrequest/referralrequest-introduction.xml: "A ReferralRequest should not be confused with an Appointment as appointments are intended for booking/scheduling purposes." No additional current-source change was found with the FHIR-7670 key.

Additional context:
ReferralRequest is no longer an active current-build resource; source/fhir.ini lists ServiceRequest and Appointment as active resources and records that ReferralRequest became ServiceRequest. The old ReferralRequest introduction file was later deleted when the retired resource source was removed. Current ServiceRequest scope covers referral and transfer-of-care requests, while current Appointment scope defines a booking of a healthcare event. A later applied Appointment issue, FHIR-46329, also added explicit current narrative saying Appointment is an intention, not an authorization, and that authorization is typically provided by ServiceRequest when required. FHIR-47681 separately removed stale AppointmentRequest wording from the Appointment recurring-appointment narrative.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current build already conveys the requested distinction through the active ServiceRequest and Appointment narratives, and the obsolete ReferralRequest source location is outside current build scope.

Recommendation:
Keep this audit commit as-is. Do not reintroduce the old ReferralRequest paragraph into current source; any future wording changes should be handled as current ServiceRequest/Appointment clarification work by the responsible work groups rather than as a DSTU1 ReferralRequest fixup.
