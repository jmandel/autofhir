FHIR-33018: Audit timezone time context

Issue request:
FHIR-33018 was a Published FHIR-core change request resolved Persuasive with Modification for R5. It asked to add the time datatype to the context of the http://hl7.org/fhir/StructureDefinition/timezone extension so recurring availability times could carry an IANA timezone.

Initial application:
The issue was applied in core by commit 7021ddc7c5, which changed source/profiles/general-extensions-spreadsheet.xml so the timezone extension context list became date;dateTime;instant;Meta;time. That spreadsheet is no longer active in the current core checkout after commit dd468d4f17 removed extension definitions from the R5 source.

Additional context:
The authoritative timezone extension definition now lives in the FHIR Extension Pack. The current Extension Pack source input/definitions/datatypes/StructureDefinition-timezone.xml includes the requested <expression value="time"/> context alongside date, dateTime, instant, and Meta. Later FHIR-43351 clarified the same extension's description in the Extension Pack without removing the time context. MnM minutes for 2022-06-22 record FHIR-33018 as Persuasive with Mod, and the related Zulip discussion explains the recurring availability-time use case without identifying a conflicting later core decision.

AutoFHIR reconciliation:
This is an empty external-repo audit commit. No core source was changed because the current core build no longer owns the timezone StructureDefinition source, and the Extension Pack copy already carries the requested time context.

Recommendation:
Keep this audit commit as-is. Future changes to the timezone extension definition or context should be made in the FHIR Extension Pack, not by recreating inactive core extension spreadsheet source.
