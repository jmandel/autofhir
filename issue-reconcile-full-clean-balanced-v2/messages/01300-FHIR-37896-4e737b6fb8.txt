FHIR-37896: Audit Appointment app-4 noshow correction

Issue request:
FHIR-37896 is a Published/Persuasive FHIR-core Appointment technical correction. It reported that Appointment invariant app-4 used the invalid status code `no-show` even though Appointment.status is required-bound to `noshow`, preventing cancellationReason from being used with no-show appointments.

Initial application:
The Jira resolution records that the issue had already been fixed as part of R5 QA. Git commit 096a41f7f4f065fccc2d69f30188aa775d7fb236 changed the Appointment app-4 human text, FHIRPath expression, and then-present XPath from `no-show` to `noshow`; later source cleanup removed the XPath representation but retained the corrected FHIRPath rule.

Additional context:
Appointment is an active current-build resource in source/fhir.ini. The current source/appointment/structuredefinition-Appointment.xml app-4 expression is `cancellationReason.exists() implies (status='noshow' or status='cancelled')`, and source/appointment/codesystem-appointmentstatus.xml defines the AppointmentStatus code as `noshow`. The linked Zulip discussion confirms the item was a technical correction and that the editor applied it to R5 QA. FHIR-38731 later added cancellationDate and a parallel app-7 rule using the same `noshow`/`cancelled` pattern, but it is a separate enhancement and does not require a FHIR-37896 source change.
