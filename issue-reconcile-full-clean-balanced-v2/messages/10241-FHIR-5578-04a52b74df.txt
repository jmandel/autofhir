FHIR-5578: Audit ValueSet identifier search parameter

Issue request:
FHIR-5578 was a Published FHIR-core/DSTU1 change request, resolved Persuasive with Modification, asking that the ValueSet `identifier` search parameter use search type `uri` because the then-current ValueSet.identifier element had data type `uri`. The approved resolution broadened that instruction to change search parameter type to `uri` for all elements whose data type is `uri`.

Initial application:
The Jira record says the change was applied in SVN revision 4492. No current Git commit mentioning FHIR-5578 or 5578 was found on the relevant current ValueSet source files. The current Git-era ValueSet source was reintroduced during the 2021 build/source refactor already using the later model: `ValueSet.identifier` is `Identifier` and the `ValueSet-identifier` search parameter is `token`, while URI-valued ValueSet fields have URI search parameters.

Additional context:
Later ValueSet/conformance-resource decisions split canonical identification from business identifiers. FHIR-3884 and FHIR-8492 support using canonical URI fields such as `ValueSet.url` where a value set URI is needed, FHIR-9391 made `ValueSet.identifier` repeatable, and FHIR-26549 records the R4/R5-era understanding that `ValueSet.identifier` is a business `Identifier`. In the current active build, `source/fhir.ini` includes ValueSet as an active resource; `ValueSet.identifier` is `Identifier`, `ValueSet.expansion.identifier` and `ValueSet.url` are URI-valued, and the search parameter bundle assigns `token` only to the Identifier-valued `identifier` parameter and `uri` to the URI-valued ValueSet parameters.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Changing `ValueSet-identifier` from `token` to `uri` now would contradict the current `ValueSet.identifier` datatype and would regress the current distinction between canonical URI (`ValueSet.url` and other URI fields) and business identifiers (`ValueSet.identifier`).

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-5578 unless a future work group decision changes the current `ValueSet.identifier` datatype or search semantics.
