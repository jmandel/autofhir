Issue request:
FHIR-19673 was a Published/Persuasive FHIR-core search issue asking that the token search parameter documentation list the FHIR id datatype among datatypes supported by token search, because _id is a token search parameter and uses exact matching.

Initial application:
The active source now contains the requested id datatype row in the token datatype table. Jira comment history points to HL7/fhir#1428; that merged PR body lists FHIR-19673, and commit 85434c9aa29d1978aa68ed5e522d15fa3c3dbaa0 added the id row to source/search.html even though the commit headline says FHIR-24864 rather than FHIR-19673.

Additional context:
The source/fhir.ini [search-rules] section has an active id=token mapping, so the summary table and search page are in current build scope. Earlier FHIR-13320 established that _id token matching is case-sensitive, and later FHIR-37990 added the id-specific pipe-syntax restriction to the token section. The Jira-linked Zulip thread and FHIR-I minutes both support adding id to the token table and do not identify a conflicting later decision.

AutoFHIR reconciliation:
No source change was made.
