FHIR-11245: Audit extension maturity support

Issue request:
FHIR-11245 is Published/Persuasive and asked to add a maturity model to extensions and include it on the extension registry page. Its accepted resolution said spreadsheet-authored extensions should be able to declare an FMM level, XML-authored extensions could use the existing structuredefinition-fmm extension, and registry tooling should expose FMM levels for extensions and profiles that choose to declare them.

Initial application:
No current git commit explicitly names FHIR-11245 because the Jira comments cite SVN revisions 10480-10484. The imported git history maps that window to commits such as 8bffa4f35aba636d69f24fbf71e9d57b5686b6bf at SVN @10480, which added FMM/status rows to extension and profile templates, taught spreadsheet parsing to add structuredefinition-fmm to extension definitions, and added FMM columns to profile/extension registry-style listings. Commit 361b374c6d228a8b6a69d4d1bbcb2d1931f30c3c at SVN @10484 continued that work by refining the profile/extension metadata rendering and adding the structuredefinition extensions spreadsheet to source/fhir.ini.

Additional context:
Current core source has moved publisher implementation code out of this checkout, but the active source still retains the profile and extension page template hooks that render status/maturity metadata, and source/fhir.ini still lists active extension/profile spreadsheet inputs. The extension registry itself is now maintained in the FHIR Extension Pack, where extension-registry.md includes the generated extension list and explicitly describes the Status column as summarizing status and maturity. The canonical structuredefinition-fmm extension also lives in the Extension Pack and documents the FMM level assigned to an artifact. Related FHIR-11247 was already audited on the combined branch and points back to this same resolution; later FHIR-18277 confirms the broader policy that IGs and other FHIR artifacts, including value sets, extensions, and profiles, have maturity levels. No Zulip or Confluence search found a direct conflict or reversal for FHIR-11245.

Adding duplicate core prose or changing individual extension FMM assignments would go beyond this historical request.

Recommendation:
Keep this no-change audit. Future edits should be limited to specific approved FMM value changes for active artifacts, or to Extension Pack work if its generated extension registry stops exposing maturity/status; neither condition is established by FHIR-11245.
