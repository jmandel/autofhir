FHIR-3005: Audit Identifier CX.5 mapping

Issue request:
FHIR-3005 was a Published/Persuasive with Modification FHIR-core datatypes change request. It reported that the HL7 v2 mapping for Identifier.use should not point to CX.5, because CX.5 is Identifier Type Code, and requested swapping the v2 mappings so the then-current Identifier.label carried CX.5 instead.

Initial application:
The issue was applied in SVN revision 3022, represented in git as 0cea83ccd63ac2d9284f7a52f846c88382f7c9bb. That commit changed source/datatypes/identifier.xml so Identifier.use mapped to N/A and Identifier.label mapped to CX.5.

Additional context:
Identifier is still in current build scope through the active [types] entry in source/fhir.ini. A later datatype refactor, 0c9b5378687bfa0a80cbf386bbda371a0becc39e (#5353), replaced Identifier.label with Identifier.type and preserved the CX.5 v2 mapping on the coded identifier type. Current source/datatypes/identifier.xml maps Identifier.use to N/A and Identifier.type to CX.5. Jira, Zulip, and Confluence searches found no later contradictory decision for FHIR-3005.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change because the current authoritative Identifier spreadsheet already reflects the requested mapping after the label-to-type refactor.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-3005 unless future v2-to-FHIR mapping work reopens the broader CX-to-Identifier mapping semantics.
