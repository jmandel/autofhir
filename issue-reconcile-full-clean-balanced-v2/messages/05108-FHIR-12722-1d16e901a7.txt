FHIR-12722: Audit organization-type payer concept

Issue request:
FHIR-12722 was a Published PA change request, resolved Persuasive with Modification, asking to deprecate the OrganizationType `ins` concept and add a replacement `pay`/Payer concept. The approved resolution supported adding the new concept but explicitly retained the insurance concept because the ValueSet is an example binding and localizations are expected.

Initial application:
The issue appears to have been applied in git commit 78b39f30cdbfa85f6d37f5ec56c46ff002f7bbd3, whose tracker batch included #12722 and added the `pay`/Payer concept to `source/organization/codesystem-organization-type.xml` while leaving `ins`/Insurance Company in place. That matched the final resolution's modified scope.

Additional context:
Core later moved UTG-managed terminology content out of this checkout. Commit 5c0494aacfd0b8bd52bc72c587aa89d0a64246f8 deleted the in-core `codesystem-organization-type.xml`; the deleted file already contained both `ins` and `pay`. The current active Organization resource still binds `Organization.type` to `http://hl7.org/fhir/ValueSet/organization-type`, and the current ValueSet composes all codes from `http://terminology.hl7.org/CodeSystem/organization-type`. The live THO CodeSystem includes both `ins` and `pay`, with the approved Payer display and definition. Community searches found no contrary human discussion or Confluence decision; only the original Zulip committers bot announcement surfaced.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No core source edit is needed because the current build-scope core source delegates the code system to THO and the external terminology source already carries the concept combination required by the Jira resolution.

Recommendation:
Keep this audit commit as-is. Future changes to the `organization-type` concepts themselves should be handled in the HL7 terminology/THO source rather than by reintroducing the CodeSystem into core FHIR; core only needs adjustment if the Organization.type binding or ValueSet compose stops referencing the THO CodeSystem correctly.
