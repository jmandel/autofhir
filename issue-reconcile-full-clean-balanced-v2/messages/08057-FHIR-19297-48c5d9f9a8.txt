FHIR-19297: Audit HL7 IG id policy

Issue request:
FHIR-19297 was Published/Persuasive with Modification and asked for each HL7 balloted implementation guide to have a unique ImplementationGuide.id after generic IDs such as "ig" conflicted when multiple IGs were loaded onto a server. The accepted resolution treated matching or deriving the ID from package identity as a good practice, not a new core Resource.id invariant, and directed wiki documentation plus IGPublisher automation.

Initial application:
The issue was applied by cc2b93ea66, which added IGPublisher logic to generate fixed IDs for HL7 published IGs from npmName and businessVersion and warn other IGs when their ImplementationGuide.id did not match the generated value. No Jira-tagged source change to the ImplementationGuide StructureDefinition or narrative was found. The old IGPublisher source was later removed from this checkout in 56ceb0df08 when the tool moved to Maven.

Additional context:
ImplementationGuide is active in the current build. The current resource source requires ImplementationGuide.packageId and states that it is globally unique and assigned by the FHIR product director for HL7/FHIR Foundation IGs, while the packages page says NPM FHIR packages should contain an ImplementationGuide whose canonical URL ends in the packageId and that package names are globally unique. Later Zulip discussion confirms the publisher warning existed for predictable tooling, but also shows the publication process has nuanced id/package/canonical business rules; direct Zulip and Confluence searches found no FHIR-19297-specific community record that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Adding a core requirement on Resource.id would overstate the Jira resolution and could conflict with later publication-process nuance; the current source already communicates the durable package-level uniqueness rule through packageId and package documentation, while the historical tooling enforcement is outside the current FHIR build source.

Recommendation:
Keep this no-change audit. If HL7 wants to revise current publication-process ID enforcement, handle that in the IG Publisher or publication guidance rather than by retrofitting a core StructureDefinition constraint from FHIR-19297.
