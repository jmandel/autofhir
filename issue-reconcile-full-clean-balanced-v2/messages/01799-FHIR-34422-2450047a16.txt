FHIR-34422: Audit AppointmentResponse entered-in-error handling

Issue request:
FHIR-34422 was Published/Persuasive with Modification for R5. It reported that AppointmentResponse lifecycle error-handling text referred to .participantStatus=entered-in-error even though AppointmentResponse.participantStatus did not allow that code. The approved resolution was to bind participantStatus to a new ValueSet that includes the participation status code system plus appointmentstatus#entered-in-error, add workflow note text explaining that invalidating an AppointmentResponse uses entered-in-error or deletion, and update the modifier reason.

Initial application:
The issue was applied by git commit 60d4ff6cd027bde1e3611af6543316027fc7c767, "FHIR-34422 Appointment Response status include entered-in-error".
