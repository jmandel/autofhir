FHIR-13318: Audit Observation signs and symptoms examples

Issue request:
Published OO issue FHIR-13318 asked for Observation examples representing findings, signs, and symptoms, including SNOMED finding concepts in Observation.code with yes/no, true/false, or SNOMED qualifier values in Observation.value[x]. Its persuasive-with-modification resolution also rejected making value[x] a modifier and instead required clearer guidance that Observation.code and Observation.value must be interpreted together, with the attached code/value-pair guidance added to the Observation notes.

Initial application:
The issue was applied in historical GF#13318 commits. ded8a0f22a and e0757bde53 partially updated the Observation narrative notes in November 2017, and 3beaa4e73f added the vomiting and second-hand-smoke Observation examples plus examples-page links in February 2018. Current source no longer uses the old spreadsheet as the authoritative edit point, but the same examples and guidance are present in the active Observation resource source and generated example list.

Additional context:
The linked 2017 Zulip thread confirms the same concern: implementers could ignore a negating value when a finding code appears in Observation.code, and OO participants favored examples and code/value guidance rather than a modifier flag. The active Observation resource remains in the current build via source/fhir.ini. Later FHIR-50850 refined the Observation.code comment for category/code precision in 2025, but it preserved and extended the existing rule that code-value pairs must be considered together and links to the Observation code/value-pair notes. No Confluence reference was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source already contains signs/symptoms and related examples, including Observation/vomiting with SNOMED 249497008 and value Absent 2667000, Observation/secondsmoke with a yes qualifier, and Observation/abdo-tender using the pattern-3 finding/value approach. Current Observation.code guidance says all code-value pairs must be considered together and points readers to the code-value-pair interoperability notes, which include the attached guidance content and discourage code-only pertinent-negative ambiguity.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-13318 unless the work group separately decides to rewrite the broader Observation code/value-pair guidance.
