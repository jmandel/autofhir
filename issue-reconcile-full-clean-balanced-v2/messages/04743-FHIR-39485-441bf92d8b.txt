FHIR-39485: Audit Event.recorded clarification

Issue request:
FHIR-39485 was an Applied/Persuasive with Modification FHIR-I clarification request for the Event logical pattern. The issue said Event.recorded referred to the first time something was recorded in "the record", but the record was ambiguous in data-sharing scenarios. The accepted resolution was to add comments explaining that recorded is the first placement in the performing practitioner's record, or a patient/RelatedPerson disclosure date, not a record-transfer timestamp or database-created timestamp.

Initial application:
The issue was previously applied by source commits 99812c64733b4414b0ae7b7fabd148ce24a3330d and 868f2545ba0f1ab669a06a168942e5d858c7a3bc, then merged by e9cd0f5fbdc326197761a6c650f59796b57d7768. Those commits added and editorially polished the requested Event.recorded comments in source/event/event-spreadsheet.xml.

Additional context:
source/fhir.ini lists event as an active logical pattern, so source/event/event-spreadsheet.xml is build-scope source for the current Event pattern. The same clarified pattern comment also appears in generated/checked mapping-exception comparisons for resources aligned or divergent from Event.recorded. PHWG later considered the Event.recorded clarification while discussing Immunization.recorded and kept the separate Immunization removal decision; the FHIR-34301 audit is already represented on the combined branch. The Extension Pack later clarified the event-recorded extension definition under FHIR-46490, but that external extension work does not require a core FHIR source change for this Event pattern issue.
