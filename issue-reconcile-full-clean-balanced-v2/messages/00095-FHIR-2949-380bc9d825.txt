FHIR-2949: Audit CapabilityStatement date handling

Issue request:
FHIR-2949 was Published with a Persuasive with Modification resolution. The issue summary asked whether Conformance.software.releaseDate should be a date instead of dateTime, but the accepted resolution explicitly kept same-day multiple releases in scope and directed a description clarification to say "Date (and optionally time) of publication" rather than requiring a date-only type.

Initial application:
The Jira comment says the issue was applied in SVN revision 2993. The corresponding git-svn commit f00a9c5 changed Conformance.date, not Conformance.software.releaseDate, from "Publication Date"/"The date when the conformance statement was published" to "Publication Date(/time)"/"The date (and optionally time) when the conformance statement was published" while leaving the type as dateTime. Later Conformance-to-CapabilityStatement and generated-source refactors carried that publication-date clarification forward.

Additional context:
CapabilityStatement is an active current-build resource in source/fhir.ini and is normative from 4.0.0. The current CapabilityStatement.date element is dateTime and still says "The date  (and optionally time)"; FHIR-37858 later refined the CanonicalResource-style meaning from publication date to last significant change, which explains the current wording difference. CapabilityStatement.software.releaseDate is also dateTime, and the primitive dateTime definition permits date-only, date-time, or partial-date precision, so the current type already supports releases recorded as just a date while still allowing same-day release times.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because the accepted FHIR-2949 modification was already applied to the active successor element, later source history explains the wording evolution, and changing software.releaseDate to date-only would contradict the accepted rationale.

Recommendation:
Keep this audit commit as-is. Revisit only if a new work-group decision specifically changes CapabilityStatement.software.releaseDate semantics; FHIR-2949 itself does not require a current source edit.
