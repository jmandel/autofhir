FHIR-12049: Audit current dosage sequencing model

Issue request:
FHIR-12049 was Published/Persuasive for the Pharmacy work group. It asked to add a sequence number to dosage instructions so same-number instructions are concurrent, different-number instructions are sequential, and ordered courses such as a first-day dose followed by later doses can be represented when absolute start dates are not known.

Initial application:
No current git commit message grep hit uses FHIR-12049 directly. A source-history pickaxe found commit 6a4b0d916ec0983d3c0e8a2d28366e99dc12fc76, `TR#12840 - changed DosageInstruction to Dosage`, adding `Dosage.sequence` with the exact requested short definition and concurrent/sequential comments. That historical source also carried a note that the all-or-none sequence invariant still needed to be added.

Additional context:
The active current build no longer has multiple `Dosage`-typed dosageInstruction repetitions on the medication resources named by the issue. `MedicationRequest.dosageInstruction`, `MedicationDispense.dosageInstruction`, and `MedicationStatement.dosageInstruction` now use `DosageDetails`, and the active `fhir.ini` R5-to-R6 change map records `Dosage.sequence=` as removed. The current dosage narrative says multiple `DosageDetails.step` entries are sequential and components inside one step are concurrent, which preserves the core sequencing/concurrency semantics in the new model. Later R6 work in FHIR-51540 and the Medication Zulip thread explicitly proposed removing `Dosage.sequence` as part of the DosageDetails redesign. Subsequent FHIR-54329/FHIR-54597 ballot issues ask whether an explicit number should be added back to `DosageDetails.step`, but those issues are still Triaged/Unresolved and are not safe to apply under this published DSTU2-era seed.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Reintroducing `Dosage.sequence` or adding a new `DosageDetails.step` number would conflict with the current R6 dosage model and with active unresolved Pharmacy work-group discussion. The current source already provides sequential steps and concurrent components for the original use case, so this old issue should not drive another source edit.

Recommendation:
Keep this no-change audit for FHIR-12049. Handle any future explicit step-number or `ElementDefinition.orderMeaning` change through the active R6 ballot issues such as FHIR-54329 or FHIR-54597 after Pharmacy reaches a final decision.
