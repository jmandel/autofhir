FHIR-32583: Audit DocumentReference content profile application

Issue request:
FHIR-32583 was a Published OO change request for R5 asking whether DocumentReference.content.format should become an extension because the existing format concept seemed specific to XDS/IHE use. The final Not Persuasive with Modification resolution instead kept the concept in core by renaming .format to .profile, changing the outer element to 0..*, representing the old choice as a repeating backbone with value[x], allowing Coding, uri, and canonical, and adding usage notes that FHIR content should use canonical URLs of the StructureDefinition profiles the content complies with.

Initial application:
The current source appears to have been applied by git commit 56832a9e59e07d5449776a61dbb3d0ec3cd0f3d2, "Updates to DocumentReference", which changed source/documentreference/structuredefinition-DocumentReference.xml from DocumentReference.content.format 0..1 Coding into DocumentReference.content.profile 0..* BackboneElement with a mandatory value[x] typed as Coding, uri, or canonical and with the FHIR profile-canonical comment. That commit also updated related DocumentReference content in the same resource-edit batch, though its subject did not name FHIR-32583.

Additional context:
DocumentReference is active in source/fhir.ini, so source/documentreference/structuredefinition-DocumentReference.xml is in build scope. Current examples and search parameter expressions use DocumentReference.content.profile, and the version-conversion map explicitly maps DocumentReference.content.format to content.profile. Confluence OO minutes reference FHIR-32583 as resolved during the January 2022 WGM and list FHIR-32583 in the March 2022 DocumentReference pull request/update agenda. Zulip search found general later discussion of DocumentReference format/profile terminology but no conflicting final decision requiring a further core change.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The active current source already implements the approved FHIR-32583 shape and usage note, and the remaining uses of "format" are aliases, IHE/XDS formatCode mappings, search-parameter codes/descriptions for the historical search surface, an R4 conversion map, or commented historical notes rather than stale active DocumentReference.content.format elements.

Recommendation:
Keep this no-change audit commit as-is. No FHIR core follow-up is needed for FHIR-32583 unless a future work-group decision separately renames or deprecates the historical format-* search parameters.
