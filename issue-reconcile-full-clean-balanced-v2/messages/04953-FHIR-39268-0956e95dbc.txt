FHIR-39268: Audit CanonicalResource versionAlgorithm note

Issue request:
FHIR-39268 was a Published FHIR-I R5 change request resolved Not Persuasive with Modification. The reporter suggested moving CanonicalResource.versionAlgorithm above the individual resource level, such as onto ImplementationGuide or a Library-scoped extension. The approved resolution declined that relocation because many canonical artifacts are not reliably discoverable through an IG or Library context, and instead required a CanonicalResource implementer note acknowledging that the per-resource version comparison mechanism is inelegant but currently the best workable approach.

Initial application:
The issue was applied by git commit 52c9f20f1274e97692621a3513bd13104cf52296, which added a Version Comparison section and the required implementer note to source/canonicalresource/canonicalresource-notes.xml. A same-day follow-up commit e4294d8526f3da840ea9d27ba04208bf3ffd3bea corrected the note wording without changing the approved meaning. No prior AutoFHIR reconciliation commit for FHIR-39268 was present on the combined branch.

Additional context:
source/fhir.ini lists canonicalresource as an active infrastructure interface, assigns CanonicalResource to the normative infrastructure package, and keeps the CanonicalResource source in build scope. FHIR-I WGM minutes record the substance of the compromise: many resources exist outside IGs, most are not referenced by Libraries, and the group chose a note asking for better proposals. A later FHIR-I call created FHIR-40493 to handle trial-use marking for net-new elements, and the Zulip thread for FHIR-39268 confirms that marking question was separate from the explanatory note. FHIR-52932 later refined versionAlgorithm code-system entries and descriptions but did not supersede or remove the FHIR-39268 note.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active CanonicalResource notes source already contains the requested Version Comparison section and the implementer note explaining that each resource version claiming its own comparison mechanism is clunky but was the best committee-identified solution that works in all circumstances.

Recommendation:
Keep this no-change audit commit as-is. No FHIR-39268 source follow-up is needed unless a future work-group decision replaces the per-resource versionAlgorithm mechanism with a different canonical-version policy.
