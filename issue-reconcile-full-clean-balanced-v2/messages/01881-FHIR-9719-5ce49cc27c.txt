FHIR-9719: Audit Composition document request example

Issue request:
FHIR-9719 was Published with a Persuasive with Modification resolution for the DSTU2 Composition $document operation. The issue asked for a POST example, an instance-level GET form such as GET [base]/Composition/id/$document, a missing slash before $document in the example URL, and clarification that the GET request generates a document rather than retrieves one. The recorded resolution said items 2, 3, and 4 were already done and that a POST example would be created.

Initial application:
The prior application is explicit in git history. Commit 85fb5d07b468bc9a37e357e86a039c60d0520b66, imported from svn revision 13106 and labeled GF#9719, added a POST request example to source/composition/$document-request.txt. At that time the POST example used the then-current type-level Composition/$document form plus an id parameter.

Additional context:
The Composition resource is active in source/fhir.ini and source/composition/list-Composition-operations.xml references OperationDefinition/Composition-document, so the operation definition and its request example are current build inputs. Later Composition $document work corrected the type-level form: FHIR-13987 and FHIR-19974 context established that $document needs a target Composition, and commit 7f9f6257cc05849685341f1e521e5fe616032d56 removed the type-level variant and id parameter while preserving the POST example on the instance URL. Current source now has GET and POST examples on /Composition/{id}/$document, references the request example from the OperationDefinition, marks the operation as instance=true/type=false/system=false, and has affectsState=false so the GET form is permitted by the generic operations rules. Zulip discussion and already-published FHIR-19974/FHIR-13987 reconciliation commits support the later instance-only interpretation.
