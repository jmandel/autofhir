FHIR-20393: Audit FamilyMemberHistory sex binding URL

Issue request:
FHIR-20393 was a Published/Persuasive Patient Care change request asking for the FamilyMemberHistory.sex binding URL to be corrected from the rendered build.fhir.org administrative-gender page to the stable hl7.org/fhir canonical URL.

Initial application:
The issue was applied before this reconciliation. Commit 0b584258d4 changed the FamilyMemberHistory spreadsheet Sex binding from http://build.fhir.org/valueset-administrative-gender.html to http://hl7.org/fhir/ValueSet/administrative-gender for R5, and commits 88c9c65a7d and 555f61e591 carried/reformatted the same correction for R4-era source.

Additional context:
FamilyMemberHistory is an active resource in source/fhir.ini. The current resource source is no longer the old spreadsheet; source/familymemberhistory/structuredefinition-FamilyMemberHistory.xml is the active StructureDefinition source and now binds FamilyMemberHistory.sex to http://hl7.org/fhir/ValueSet/administrative-gender. The linked Zulip discussion distinguishes this URL correction from the separate question of which sex/gender value set should be used and confirms Patient Care treated FHIR-20393 as a technical correction.

AutoFHIR reconciliation:
This commit makes no source change because the current active source already contains the stable canonical ValueSet URL requested by the issue, and the remaining valueset-administrative-gender.html references are generated/rendered page links rather than the binding canonical.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed for FHIR-20393 unless a separate work-group decision reopens the value-set choice for FamilyMemberHistory.sex.
