FHIR-7875: Audit Appointment.reason v2 mapping

Issue request:
FHIR-7875 was a Published/Persuasive PA change request for the DSTU1 Appointment resource asking to add SCH-7 to the HL7 v2 mapping for Appointment.reason, which at the time mapped to AIS-3 and ARQ-7.

Initial application:
The request was initially applied in historical commit 37df64fa17b64de29b79604b4f286c99fb1af124 against the old Appointment spreadsheet source, changing the Appointment.reason v2 mapping from AIS-3, ARQ-7 to AIS-3, ARQ-7, SCH-7. That spreadsheet source was later converted into source/appointment/structuredefinition-Appointment.xml, which is in current build scope because source/fhir.ini actively lists appointment=Appointment.

Additional context:
Later final PA decisions revisited the same Appointment v2 mapping confusion. FHIR-8843 removed ARQ-7 from Appointment.reason; FHIR-13861 then removed SCH-7 from Appointment.reason and mapped ARQ-7/SCH-7 to Appointment.appointmentType while adding ARQ-8/SCH-8 to Appointment.serviceType; FHIR-41607 later removed the core appointmentType ARQ-7/SCH-7 mapping and instead maps ARQ-7/SCH-7 together with ARQ-8/SCH-8 under Appointment.serviceType with a trading-partner review note. FHIR-8843 and FHIR-13861 are already represented on the combined branch by no-change audit commits, so this commit does not duplicate them.

AutoFHIR reconciliation:
This empty audit commit makes no source change. Current Appointment source maps Appointment.reason only to AIS-3, maps ARQ-7/SCH-7 under Appointment.serviceType per the later FHIR-41607 decision, and therefore intentionally no longer implements the literal FHIR-7875 request to place SCH-7 on Appointment.reason.

Recommendation:
Keep this audit as-is. Do not re-add SCH-7 to Appointment.reason for FHIR-7875 because doing so would contradict later PA decisions; revisit only if PA reopens the broader Appointment v2 reason/type/serviceType alignment.
