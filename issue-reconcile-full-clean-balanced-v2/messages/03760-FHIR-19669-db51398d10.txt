FHIR-19669: Audit copyright comment typo correction

Issue request:
FHIR-19669 is a Published/Persuasive Vocabulary change request asking to correct the typo "nullFrequently" to "Frequently" in the ValueSet.copyright element Comment field and to make the identical correction for ConceptMap.copyright. Jira records the change as non-substantive clarification applied for R5.

Initial application:
The typo was discussed as a tooling/source-driven typo in a 2018 terminology Zulip thread, and Jira comments later recorded that ConceptMap was already fixed in the CI build while ValueSet still needed correction. In the current source history, ConceptMap.copyright already appears as "Frequently..." in the modern source introduced by the 2021 source rework, and commit 3a8665b9c2 ("Vocab concept map changes for R5") explicitly mentions FHIR-19669 and changes ValueSet.copyright from "nullFrequently" to "Frequently".

Additional context:
source/fhir.ini lists both valueset=ValueSet and conceptmap=ConceptMap as active resources, so the checked StructureDefinition XML files are current build inputs. Current source/valueset/structuredefinition-ValueSet.xml and source/conceptmap/structuredefinition-ConceptMap.xml both have corrected copyright comments. Remaining "nullFrequently" hits are confined to tools/history release4/release4b archived artifacts, consistent with the Jira comment that the fix was not made in R4 and not a current-build source problem.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active core source already satisfies the requested correction for both resources, and changing historical release archives would be outside the current R5/R6 build reconciliation scope.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed for current source; do not edit R4/R4B historical archives unless a separate human-approved historical publication correction is requested.
