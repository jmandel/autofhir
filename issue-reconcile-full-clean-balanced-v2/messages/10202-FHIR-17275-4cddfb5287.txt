FHIR-17275: Audit duplicate CodeSystem code checks

Issue request:
FHIR-17275 was a Published/Persuasive STU3 FHIR-core CodeSystem issue asking that the FHIR IG publication tooling report an error when a CodeSystem definition repeats the same Concept.code. The recorded resolution was to check this condition.

Initial application:
The original application appears in git commit a06e73eadfbf7ebc7c4bc51e679c40e43eb93a2a, which explicitly references GF#17275 and svn revision 14846. That commit added CodeSystemValidator duplicate-code checking and wired Publisher to process CodeSystem resources, along with unrelated path and FMG-page changes. The Java tooling paths from that historical application are no longer present in the current core checkout.

Additional context:
The current build-scoped CodeSystem resource is active in source/fhir.ini, and source/codesystem/structuredefinition-CodeSystem.xml contains csd-1 as an error-level invariant: "Within a code system definition, all the codes SHALL be unique." CodeSystem.concept.code is also defined as uniquely identifying the concept and carries condition csd-1. Later Jira decisions did not remove this rule: FHIR-16750 and FHIR-18600 were no-change dispositions involving csd-1 placement/meaning, and FHIR-37450 treated duplicate CodeSystem codes as a csd-1 violation. No directly relevant Zulip or Confluence evidence was found for FHIR-17275.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core specification already expresses the duplicate-code requirement in the build-scoped CodeSystem StructureDefinition, while the historical IG Publisher implementation code is outside this current checkout.

Recommendation:
Keep this audit commit as-is for the core reconciliation. If someone needs to re-verify runtime IG Publisher or validator behavior, that follow-up belongs in the current external tooling repository; no FHIR core source change is indicated by this issue.
