FHIR-6285: Audit basic ConsentDirective support

Issue request:
FHIR-6285 was a Published/Persuasive FHIR-core CBCC change request from DSTU1 asking the ConsentDirective project to include a Basic-ConsentDirective for blanket BPPC-style HIE policies such as opt-in, opt-out, emergency/break-glass access, and summary-only sharing. The final Jira resolution says the request was persuasive and already applied; comments from the issue state that the simple policies and examples were already supported and that the item should close as resolved with no change needed.

Initial application:
No source commit explicitly tagged FHIR-6285 was found. The relevant source history shows the old Contract-based ConsentDirective work already existed before or around the request, the Consent resource was later prototyped as a resource in acc3f3137b with the consent examples and narrative, and the old Contract profile was restored in d313082ccd but is not the active current mechanism. Current active source has the Consent resource registered in source/fhir.ini, while the old PCD IG entry is commented out and no active [profiles] entry builds source/contract/consentdirective.profile.xml.

Additional context:
Current Consent source already addresses the implementer-facing substance of the request through the Consent resource rather than a new Basic-ConsentDirective profile. The page explains simple versus computable consent, BPPC source-document linkage, opt-in and opt-out patterns, provision-based exceptions, sourceAttachment/sourceReference, policyBasis, and example entries including Consent-In, Consent-Out, Consent-Emergency, and Consent-No-Emergency. A 2016 Zulip FMG thread mentioning GF#6285 confirms the work group intentionally moved the Privacy Consent Directive work from a profile/IG path toward the Consent resource while keeping privacy consent as the focused scope. Later neighboring issues such as FHIR-5525 and FHIR-11070 concern broader consent resource shape and category terminology, but they are separate decisions and do not require an additional source change for this seed.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Adding a new Basic-ConsentDirective profile or duplicating the BPPC stepping-stone prose would re-open an old profile-based design that the current build has superseded with the active Consent resource and examples. The current source already conveys the necessary support for the simple BPPC-style policies identified in FHIR-6285.

Recommendation:
Keep this no-change audit commit. If a future work group wants a modern BPPC implementation guide or formal profile, that should be handled as a new scoped IG/profile effort, not as a correction to the current core Consent resource for FHIR-6285.
