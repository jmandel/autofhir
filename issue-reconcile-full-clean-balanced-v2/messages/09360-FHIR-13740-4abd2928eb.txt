FHIR-13740: Audit SimpleQuantity root sliceName cleanup

Issue request:
FHIR-13740 was a Published/Persuasive FHIR-core datatypes issue raised against STU3. It reported that the SimpleQuantity definition generated from profiles-types.xml included <sliceName value="SimpleQuantity"/> on the root Quantity element, which is invalid because a profile root element is not itself a slice. The approved resolution was auto-approved: fix the code so that sliceName no longer propagates into the resource representation.

Initial application:
The Jira comment says the issue was applied in svn revision 12619. The matching git-svn commit de70b2e64f1ced835648f041b70749a2495e271b, "#13740 - remove bogus slice name," changed the old ProfileGenerator.java to stop calling e.setSliceName(pt.getName()) when creating the profile root element. That historical generator path is no longer present in the current checkout.

Additional context:
SimpleQuantity remains an active datatype/profile in source/fhir.ini and its current restriction source is the Quantity spreadsheet row that constrains comparator.empty(); it does not carry a source sliceName. The broader root-sliceName family has since been covered by the current ElementDefinition interpretation table and the active StructureDefinition invariant sdf-23, "No slice name on root," applied to both snapshot.element and differential.element. Related audits for FHIR-12849 and FHIR-13400 are already represented on the combined branch. The only root sliceName found in current source is the deliberate failing sdf-23 invariant test fixture, not an active profile.

AutoFHIR reconciliation:
No source change was made. The historical SimpleQuantity generator defect is already fixed, current build-scope source prohibits root sliceName, and the current generated SimpleQuantity XML on build.fhir.org contains no sliceName elements.

Recommendation:
Keep this no-change audit commit. No FHIR core source follow-up is needed for FHIR-13740; if root sliceName reappears in future generated output, the fix belongs in the generator or profile source path that reintroduced it, while the current failing invariant test fixture should remain as negative test coverage.
