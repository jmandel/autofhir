FHIR-25278: Audit Appointment request references

Issue request:
FHIR-25278 was a Published PA change request, resolved Persuasive with Modification for R5. The submitter asked whether Appointment.reasonReference should point to request resources because appointments are often scheduled before the related procedure exists. The approved resolution kept the distinction between Appointment.reason and Appointment.basedOn, and specifically directed adding MedicationRequest, DeviceRequest, and CarePlan as allowed references on Appointment.basedOn.

Initial application:
The change was applied in git commit 6363f23c2f7c79b1c14a3fe3a5efa484a5c48d7f, "FHIR-25278 Appointment.basedOn References", which changed Appointment.basedOn from a ServiceRequest-only reference to a general request reference and added CarePlan, DeviceRequest, and MedicationRequest alongside ServiceRequest. That commit also updated the short and definition from "service request" to "request".

Additional context:
The Appointment resource is active in source/fhir.ini, so source/appointment/structuredefinition-Appointment.xml is in current build scope. Current source still keeps Appointment.reason as a CodeableReference to clinical reason resources while Appointment.basedOn carries the authorization/request references. Later FHIR-40634 broadened Appointment.basedOn with additional request types but preserved the FHIR-25278 CarePlan, DeviceRequest, and MedicationRequest targets. The 2021 and 2022 PA WGM minutes and the linked Zulip discussion support the same distinction: the request originated as a reasonReference question, but the final disposition used basedOn for the scheduling request relationship.

AutoFHIR reconciliation:
No source change was made. The current active Appointment StructureDefinition already contains the three target profiles required by FHIR-25278 on Appointment.basedOn, and editing Appointment.reason to duplicate request references would conflict with the accepted resolution's separation of reason from basedOn.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-25278 unless PA later decides to change the separate Appointment.reason guidance about Procedure, which was explicitly left as a Patient Care/detail question in the 2022 WGM minutes and is outside this issue's applied basedOn change.
