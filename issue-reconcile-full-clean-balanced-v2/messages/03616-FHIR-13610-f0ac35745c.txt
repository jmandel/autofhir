FHIR-13610: Align submit operation with coverage eligibility resource

Issue request:
FHIR-13610 was Published with a Persuasive resolution to create a $submit operation for EligibilityRequest. The request specified that the operation should accept a single request resource or a Bundle of request resources without requiring a Parameters wrapper.

Initial application:
The issue was initially applied in git commit ab55d1f02c558ddf2f35ff5be98f2a105324f382, which added the submit operation rows to the EligibilityRequest spreadsheet, and commit a53ff5fbd9dfe5cffcc57785901bde6e26469780, which added the missing request and response example files. Those historical inputs were later carried forward into the current CoverageEligibilityRequest operation source.

Additional context:
FHIR-16936 later renamed EligibilityRequest and EligibilityResponse to CoverageEligibilityRequest and CoverageEligibilityResponse. That related rename issue is already represented on the combined branch by commit 6ccf62e5d425508416491ed9b50b308b0fe0d266, so this reconciliation does not publish a duplicate FHIR-16936 decision. The active current build includes coverageeligibilityrequest=CoverageEligibilityRequest in source/fhir.ini and lists OperationDefinition/CoverageEligibilityRequest-submit from source/coverageeligibilityrequest/list-CoverageEligibilityRequest-operations.xml. However, the active submit operation definition and request example still used the old EligibilityRequest/EligibilityResponse names in implementer-facing operation text and the sample endpoint.

AutoFHIR reconciliation:
This commit updates the active CoverageEligibilityRequest $submit OperationDefinition title, description, input documentation, and output documentation to use CoverageEligibilityRequest and CoverageEligibilityResponse, and updates the example request line to POST [baseurl]/CoverageEligibilityRequest/$submit. The operation still accepts a single resource or Bundle as FHIR-13610 required, and no Parameters wrapper was added.

Recommendation:
Keep this source fix. It preserves the original FHIR-13610 operation semantics while aligning the active current operation with the later resource rename. Do not treat this as a new FHIR-16936 decision; that issue already has a combined-branch audit commit.
