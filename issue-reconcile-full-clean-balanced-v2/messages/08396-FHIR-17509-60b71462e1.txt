FHIR-17509: Audit Parameters reference resolution guidance

Issue request:
FHIR-17509 was Published/Persuasive with Modification and asked to clarify how references in Parameters are expected to work. Its final resolution directed the specification to add a note to the Parameters resource definition saying that implementers should look at the OperationDefinition to know how relative URLs in parameters can be resolved.

Initial application:
The issue was explicitly applied in commit 0f00efc759 (svn revision 14230), which added Parameters narrative guidance and a Parameters.parameter.resource definition comment explaining that the applicable OperationDefinition may specify reference resolution between parameters, with fallback to general resource resolution. Current source history shows that text survived later source-generation refactors.

Additional context:
Parameters is an active resource in source/fhir.ini. The current authoritative Parameters StructureDefinition comment and resource narrative both retain the OperationDefinition-based reference-resolution rule. The paired issue FHIR-17508 added OperationDefinition.parameter.referencedFrom for computable reference expectations and is already represented on the combined branch, so it is related context but not republished here. The linked Da Vinci Zulip thread confirms the concern was specifically ambiguity about relative references between resources carried in Parameters, and later community discussion did not identify a conflicting base-spec rule.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already satisfies FHIR-17509: it tells implementers that OperationDefinition may specify how references resolve between parameters, and that unresolved references fall back to the general resource resolution methods.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for FHIR-17509 unless the work group later wants new examples or more detailed operation-specific guidance.
