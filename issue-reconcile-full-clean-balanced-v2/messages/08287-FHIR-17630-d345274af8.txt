FHIR-17630: Audit timezone search guidance

Issue request:
FHIR-17630 was Published/Persuasive for R5 as a follow-up to FHIR-16550. It asked FHIR-core to point to the rejected draft client-timezone HTTP header RFC, make it a SHOULD for clients to populate that header and for servers to use it, and indicate that clients SHOULD populate timezone information when communicating date/time search values so defaulting to the server timezone does not surprise users.

Initial application:
FHIR-16550 first added the date-search "here be dragons" implementer note in source/search.html through commit 7310bd4a428c. FHIR-17630 itself was later applied by commit 77f262f2638f99b947ab5ba72761d95b065b339d, which added the Client Timezone section to the active RESTful API page source, source/http.html. Later editorial commits adjusted wording and conformance wrappers without removing the approved requirements.

Additional context:
The FHIR-I 2019-04-15 minutes record the 11-0-0 decision to use the rejected IETF client timezone draft rather than invent a FHIR-specific header. The linked #implementers Zulip thread shows the underlying concern: date search and server-side logic need to know the user's/client's timezone in some cases, but offsets, timezones, server locality, and clinical event locality are distinct and difficult. Current source/search.html still preserves the existing date-search correction guidance, the explicit SHOULD to provide a timezone when a time part is present, and the cautionary note from FHIR-16550.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build source already contains the RFC link and client/server SHOULD guidance in source/http.html, and the current date-search source already tells clients they SHOULD provide a timezone when the time part is present while retaining the timezone correction caveats.

Recommendation:
Keep this no-change audit commit. No additional FHIR-core source edit is needed for FHIR-17630 unless the work group later reopens the broader timezone policy; FHIR-16550 remains related background rather than a separate decision in this worker.
