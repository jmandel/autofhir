FHIR-7678: Audit Attachment contentType clarification

Issue request:
FHIR-7678 was a Published/Persuasive with Modification DSTU1 FHIR-I clarification for Attachment.contentType. The issue reported that the datatype narrative said the contentType element SHALL always be populated while the formal definition made it optional, and the approved resolution was to adjust the note so it was clearer.

Initial application:
No FHIR-7678-tagged source commit was found in git history, and the Jira comment says the change was already applied. The same Attachment.contentType conflict was applied in SVN-backed git commit 5ae1eebfcac2835ff22fdbbc1cdfb452b33ab838 (#7878, svn r5937), which replaced the unconditional SHALL narrative with conditional wording requiring contentType only when an Attachment contains data and permitting it for url-only attachments. Later source history preserved that rule while normalizing surrounding datatype prose.

Additional context:
FHIR-7878 is the tightly related Published issue for the same conflict and is already represented on the combined branch by commit 9457a59e7f6de445e9a013220c47cd1d43d9d064, so this commit does not duplicate that issue. source/fhir.ini keeps Attachment in the active [types] list, routes datatypes through datatypes.html by default, and marks Attachment normative, so the inspected Attachment datatype source is in current build scope. Current source/datatypes.html says contentType SHALL be populated when an Attachment contains data and MAY be populated when there is a url. The authoritative spreadsheet keeps Attachment.contentType at 0..1 with the invariant data.empty() or contentType.exists().

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active Attachment narrative, cardinality, and invariant already express the clarification requested by FHIR-7678: contentType is not universally mandatory, but is mandatory when inline data is present.

Recommendation:
Keep this no-change audit commit as-is. No core source follow-up is needed for FHIR-7678 unless a future work group decision changes the Attachment data/url/contentType rule itself.
