FHIR-5155: Audit Composition section.code constraint removal

Issue request:
FHIR-5155 was a Published/Persuasive DSTU1 Composition ballot issue asking to remove the invariant that allowed Composition.section.code only when the section had no content. The final Structured Documents resolution removed the constraint because FHIR does not have CDA-style context conduction, so a section code does not change the meaning of nested or referenced resources.

Initial application:
The issue was applied in SVN revision 4658, represented in git as cdebd6f91d71248ac4eb50636dad18b4e4bf0dbc, which removed the Composition spreadsheet invariant "No section code if there's content" and changed the section.code explanatory comment. Later source refactors carried that result into source/composition/structuredefinition-Composition.xml.

Additional context:
Composition is active in the current build via source/fhir.ini. The current Composition.section constraints are cmp-1, cmp-2, and cmp-3; none forbids using section.code with entries/content. The current section.code comment preserves the approved rationale that section.code does not change the meaning or interpretation of the resource content. FHIR-5494 asked for clarification of the same old invariant but Jira says it was superseded by FHIR-5155, and the combined branch already contains a separate FHIR-5494 audit commit. Targeted Zulip and Confluence searches found no conflicting community decision.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because the current in-build Composition source already removed the obsolete invariant and retains the rationale needed by FHIR-5155.

Recommendation:
Keep this audit commit as-is. No FHIR-core follow-up is needed for FHIR-5155; any future wording polish for the section.code comment should be handled as a separate editorial issue rather than this reconciliation.
