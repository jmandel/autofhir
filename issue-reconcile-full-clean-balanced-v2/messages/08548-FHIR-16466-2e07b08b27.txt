FHIR-16466: Audit resource identity terminology move

Issue request:
FHIR-16466 was Published with a Persuasive STU3 resolution. It asked that the Managing Resource Identity page use clearer, consistently defined terms for logical id, canonical URL, resource identity, identifier elements, literal identity, and full URL. The approved resolution directed the identity terminology into resource.html#id, made managing.html informative with a reference to the normative Resource page, and softened local prescriptive guidance on managing.html.

Initial application:
The Jira comments identify svn revision 14335, preserved in git commit 6952564a0194f2d05079049d21b581cf35342188. That commit changed source/managing.html from normative to informative, removed the Consistent Resource Identification section from managing.html, added the Resource page identity material to source/resource/resource-notes.xml, and added a Managing Resource Identity cross-reference into the documentation page.

Additional context:
Later resource-identity changes refined the terminology without reversing the FHIR-16466 move. Commit 7ee661f6b4022414f36a63274872d7ef207a8716 expanded the Resource page identity section for FHIR-17105, FHIR-15615, and FHIR-14191, replacing confusing literal-identity wording with location/logical-id/business-identifier/canonical-URL terminology and adding the current Managing Resource Identity pointer to resource.html#id. FHIR-18476 later changed managing.html from URL-only identity wording to URI plus REST URL wording, and FHIR-33978 removed an intrinsic URL parenthetical from the Resource introduction. The current combined branch already contains no-change audits for FHIR-18476 and FHIR-33978, and a source fix for FHIR-14854 that corrected stale links after the FHIR-16466 move.

AutoFHIR reconciliation:
This is an empty audit commit. The current source/resource/resource-notes.xml already defines Resource Identity, Logical ID, Identifier Categories, Business Identifiers, Canonical URLs, and Consistent Resource Identification on the Resource page; source/fhir.ini keeps Resource in the active build metadata. The current source/managing.html is informative and explicitly says it builds on the normative resource.html#id documentation, while source/hierarchy.xml keeps managing.html in the current build. No additional source edit is needed for FHIR-16466.

Recommendation:
Keep this audit as-is. The approved FHIR-16466 relocation and terminology clarification are already represented in current build-scoped source, and adding more duplicative identity definitions to managing.html would reintroduce the overlap the issue resolved. Related identity issues such as FHIR-17105, FHIR-15615, and FHIR-14191 should be audited separately if selected, because they refine adjacent Resource-page terminology beyond the seed decision.
