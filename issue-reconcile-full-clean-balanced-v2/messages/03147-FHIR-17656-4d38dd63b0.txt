FHIR-17656: Audit preauthorization reference placement

Issue request:
FHIR-17656 was a Published/Persuasive with Modification FM change request for STU3. It asked to move the preauthorization reference for ClaimResponse and ExplanationOfBenefit out from insurance-level placement to root-level representation and to use a single root preauthorization reference where the reference identifies the overall preauthorization response; the final Jira resolution said not to remove the current field and only to add a root-level field.

Initial application:
The issue was explicitly applied in two August 2018 tracker commits. Commit 056a20b34652ecc196253948abcb3cf2e2a14067 added ClaimResponse.preAuthRef with cardinality 0..1 and removed the generated ClaimResponse.insurance.preAuthRef row from the then-current spreadsheet source. Commit cd41718346186cc9bcfcbd35e62113863824122d added root ExplanationOfBenefit.preAuthRef while leaving the existing EOB insurance-level preAuthRef family available. The later 2018 financial-management bulk commit afb5ec66f68641293bb7950b6e0eeb118fa1444a carried those changes forward and explicitly listed FHIR-17656.

Additional context:
ClaimResponse and ExplanationOfBenefit are active approved resources in the current build configuration. The current source has root ClaimResponse.preAuthRef as 0..1 and no ClaimResponse.insurance.preAuthRef, matching the direct 2018 Zulip rationale that ClaimResponse's overall preauthorization number belonged at the root. The current EOB source has root ExplanationOfBenefit.preAuthRef and preserves ExplanationOfBenefit.insurance.preAuthRef as repeating elements, matching the historical application and the published R4, R4B, and R5 conformance surfaces. Later Published issues FHIR-18083, FHIR-22662, and FHIR-40082 added or audited related period and item-level reviewOutcome preAuthRef/preAuthPeriod structures without changing this root/insurance distinction.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Narrowing ExplanationOfBenefit.preAuthRef from 0..* to 0..1 or re-adding ClaimResponse.insurance.preAuthRef would be a substantive current-model change not supported by the complete history: the seed was applied before R4, shipped through R4/R4B/R5 in this shape, and later related decisions preserved it.

Recommendation:
Keep this no-change audit commit as-is. If FM wants to harmonize ExplanationOfBenefit.preAuthRef cardinality with ClaimResponse or restore a ClaimResponse insurance-level reference, that should be handled as a new work-group decision because it would alter long-published behavior rather than complete a clearly missing FHIR-17656 edit.
