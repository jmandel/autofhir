FHIR-12060: Audit Element.id and Extension.url representation

Issue request:
FHIR-12060 was a Published FHIR-core/fhir-i change request, resolved Persuasive with Modification for DSTU2, asking that Element.id and Extension.url not be modeled as ordinary FHIR primitive Elements. The accepted resolution was to remove the ordinary type-code treatment for those fields and use compiler-supplied type metadata instead.

Initial application:
The issue was applied in git-svn commit e8c22a3727455852300b359fe317824ad3ae2224, whose message includes GF#12060 and svn revision 14528. That commit did not rewrite the spreadsheet rows directly; it changed the generation/tooling path to special-case Element.id and Extension.url so their generated ElementDefinitions used compiler metadata rather than normal primitive Element typing.

Additional context:
Later FHIR-I decisions refined the representation without reversing the seed. FHIR-31656 added explicit prose that extensions are not allowed on Extension.url or Element.id. FHIR-25274 documented the current System.String plus structuredefinition-fhir-type pattern for simple values where FHIR primitive inheritance is not wanted. FHIR-38684 and FHIR-41183 corrected Element.id-derived metadata to use fhir-type string rather than id. FHIR-45989 confirmed the later distinction that Resource.id is constrained as fhir-type id, while Element.id remains fhir-type string with no extensions.

AutoFHIR reconciliation:
This audit intentionally makes no source change. The active current build inputs still define Element and Extension as core infrastructure types, the current narrative says xmlAttr elements and specifically Extension.url/Element.id cannot carry extensions, and the current generated publication surface represents Element.id and Extension.url as http://hl7.org/fhirpath/System.String with structuredefinition-fhir-type values string and uri respectively. That preserves the seed's semantic requirement that these fields are simple wire values, not ordinary FHIR primitive Elements with id/extension children.

Recommendation:
Keep this no-change audit. Do not edit the source spreadsheets merely to remove the visible string/uri entries unless the active generator contract changes; the important implementer-facing semantics are already present in the built specification. Unresolved Resource.id/Patient.id fhir-type questions, such as FHIR-57383, are a separate Resource.id inheritance issue and should not be folded into FHIR-12060.
