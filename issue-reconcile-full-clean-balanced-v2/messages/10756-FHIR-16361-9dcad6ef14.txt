FHIR-16361: Use reference search for canonical Subscription topic

Issue request:
FHIR-16361 was Published/Persuasive with Modification for STU3 search documentation. It asked to distinguish business-versioned canonical URLs from REST history versions, move canonical-element search parameters to the reference search type, explain why a canonical resource url element is not itself typed canonical, and stop describing _profile as token search.

Initial application:
The issue was applied in SVN revision 13894, now git commit e992ee4d10, which updated source/search.html, source/datatypes.html, and source/references.html. That application added the canonical datatype explanation, corrected _profile to reference search, split reference-version and canonical-version narrative, and noted at the time that no search-parameter source files were affected.

Additional context:
The current search narrative still carries the FHIR-16361 rule: _profile is a reference search parameter, canonical datatype values are references to uri-valued canonical resource urls, and canonical reference search uses the reference type with |version business-version handling. Subscription is active in source/fhir.ini, and later Published issue FHIR-39633 restored Subscription search parameters after they were accidentally removed. That later restoration introduced Subscription-topic as uri even though Subscription.topic is canonical(SubscriptionTopic); no later Jira, Zulip, or Confluence evidence found a deliberate exception for keeping that canonical search parameter as uri.

AutoFHIR reconciliation:
Changed source/subscription/bundle-Subscription-search-params.xml so the active Subscription.topic search parameter uses type reference instead of uri. A targeted source scan of current structure definitions and resource search-parameter bundles now finds zero non-reference search parameters whose expression is a canonical-typed element.

Recommendation:
Keep this source fix. It aligns the active Subscription search parameter with FHIR-16361 and the current search narrative while preserving FHIR-39633's intent to restore the topic search parameter.
