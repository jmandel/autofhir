FHIR-55072: Audit RequestOrchestration example action terminology

Issue request:
FHIR-55072 is an Applied/Persuasive CDS change request for RequestOrchestration. It asked that the action-code, action-reason-code, and action-participant-function ValueSets and CodeSystems be treated as THO-candidate example terminology by marking the involved ValueSets and CodeSystems experimental and adding Example to each name, title, id, and url.

Initial application:
The request was applied by git commit c3a6fdf8e877337135834b15a02de1e4615aece9, which explicitly named FHIR-55072 and FHIR-55069. That commit renamed the six shared action terminology XML files under source/plandefinition to *-example, changed their ids, canonical urls, names, titles, experimental flags, internal ValueSet/CodeSystem references, source/oids.ini entries, and updated RequestOrchestration bindings to the new example ValueSet canonicals.

Additional context:
RequestOrchestration is an active resource in source/fhir.ini. The shared terminology definitions live under source/plandefinition, which is also active, and are reused by RequestOrchestration, PlanDefinition, and ActivityDefinition. FHIR-55069 is the same-change-family PlanDefinition issue and is audited separately in this run. The only remaining non-example references found for these bindings are in checked-in resource SVG diagrams, which are generated-looking artifacts and are not the authoritative source for this reconciliation. Zulip and Confluence searches did not find conflicting community evidence.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative XML source already has RequestOrchestration.code, RequestOrchestration.action.code, RequestOrchestration.reason, and RequestOrchestration.action.participant.function bound to the *-example ValueSet URLs, and the corresponding ValueSet and CodeSystem definitions are experimental with Example in their id, url, name, and title.

Recommendation:
Keep this audit commit as-is. Do not make an SVG-only source fix for this issue; if the diagrams are regenerated later, they can pick up the authoritative example binding URLs from the StructureDefinition source.
