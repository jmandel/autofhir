FHIR-17061: Audit Bundle fullUrl disagreement wording

Issue request:
FHIR-17061 was Published/Persuasive for STU3 by FHIR-I. It asked that Bundle.entry.fullUrl explain what it means for fullUrl to "disagree" with the resource id, especially making explicit that a urn:uuid fullUrl does not require the resource id to equal the UUID.

Initial application:
The Jira application comment records svn revision 14409. The pre-R5 git source history does not contain that SVN revision directly, but the later StructureDefinition source imports already include the applied explanatory wording: if fullUrl is not a urn:uuid, the URL must be a version-independent URL consistent with Resource.id. Those imports also include the Bundle bdl-8 invariant prohibiting version-specific fullUrl values.

Additional context:
Bundle is an active resource in source/fhir.ini, so source/bundle/structuredefinition-Bundle.xml is in current build scope. Related fullUrl decisions explain why the current wording should not be changed back to the 2018 proposed text verbatim: FHIR-16518 rejected allowing or adding rationale for version-specific Bundle.entry.fullUrl values; FHIR-27813 and FHIR-43106 clarified when fullUrl may be omitted; FHIR-31422 clarified that fullUrl may use arbitrary URI schemes; and FHIR-43101 clarified that RESTful-looking fullUrls must match both the resource type and id. Community searches found later fullUrl discussion but no conflicting direction requiring a new source change for this seed.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Bundle.entry.fullUrl definition and comment already explain the "disagree" rule, distinguish urn:uuid from RESTful-looking URLs, preserve the version-independent fullUrl rule, and incorporate later accepted clarifications. Restoring the seed issue's literal "version-specific or version-independent" wording would now conflict with bdl-8 and later work-group decisions.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-17061 unless FHIR-I chooses to reopen the broader Bundle.fullUrl wording for arbitrary non-RESTful URI schemes in a separate issue.
