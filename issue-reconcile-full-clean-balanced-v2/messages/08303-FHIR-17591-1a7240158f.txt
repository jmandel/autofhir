FHIR-17591: Audit ConceptMap publication support

Issue request:
FHIR-17591 was Published/Persuasive for FHIR-core after an FHIR-I vote and asked to support publishing ConceptMap artifacts directly in the core specification, in the same way as CodeSystem, ValueSet, and related terminology artifacts.

Initial application:
No git commit explicitly mentioning FHIR-17591 was found. The current source nevertheless shows the request was applied before this reconciliation: ConceptMap is an active resource in source/fhir.ini, has a ConceptMap-specific template in the IG tooling defaults, has source examples listed as ConceptMap resources, and has a built terminology concept maps page driven by the conceptmapslist macro. Related R5 work, especially J#36190/FHIR-36190, also made ConceptMap a MetadataResource and added metadata examples/search parameters that support direct publication lifecycle metadata.

Additional context:
The R5-era core source also gained shareableconceptmap and publishableconceptmap profiles, but FHIR-37959 later made a final R6 decision to remove the shareable/publishable/computable/executable profile family from core and maintain those profiles in the Canonical Resource Management/THO path instead. The current absence of those profile source files is therefore intentional later context, not a missed application of FHIR-17591.

AutoFHIR reconciliation:
This commit makes no source changes. Current core source already supports direct ConceptMap publication as a resource with examples, search parameters, metadata fields, page/template wiring, and a ConceptMap list page; restoring the removed publishable/shareable profile files would conflict with the later FHIR-37959 decision.

Recommendation:
Keep this audit commit as-is. If additional profile-level publication guidance is desired, follow the CRMI/THO profile maintenance path identified by FHIR-37959 rather than reintroducing removed profile definitions to the core FHIR source.
