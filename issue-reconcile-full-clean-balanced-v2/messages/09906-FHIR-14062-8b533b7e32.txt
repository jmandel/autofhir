FHIR-14062: Audit QuestionnaireResponse title guidance

Issue request:
FHIR-14062 was Published / Persuasive with Modification. It asked to add QuestionnaireResponse.title so clients listing QuestionnaireResponses could see the corresponding Questionnaire.title without fetching the Questionnaire; the final resolution chose the canonical display extension on QuestionnaireResponse.questionnaire instead of adding a new core element, with SDC-specific profile guidance.

Initial application:
The Jira application comment points to SVN #14772, now git commit b8c5990ac5ad735ba1e8e836fd8a4c6fd3534a3e. That commit did not add QuestionnaireResponse.title; it added display-extension guidance to Questionnaire.url, the canonical target used by QuestionnaireResponse.questionnaire, and made other Questionnaire/QuestionnaireResponse changes in the same batch.

Additional context:
Current core has QuestionnaireResponse as an active resource, defines QuestionnaireResponse.questionnaire as a required canonical to Questionnaire, documents that the canonical display extension can convey the title or human-readable target name, retains Questionnaire.url guidance that the referenced questionnaire name can be conveyed with that extension, and includes a QuestionnaireResponse example using the display extension. Later FHIR-37550 clarified legacy/non-resolving QuestionnaireResponse.questionnaire cases, FHIR-32897 documented display for canonical references generally, FHIR-21468 changed SDC QuestionnaireResponse.questionnaire.display from required to optional must-support, and FHIR-44989 declined a standard display-extension search parameter because implementations cannot count on the display title being present.

AutoFHIR reconciliation:
This audit commit makes no source change. Adding a QuestionnaireResponse.title element would contradict the final resolution, and adding new core prose that always requires or recommends display/title population would be inconsistent with later SDC and search-parameter decisions. The existing core source already exposes the correct mechanism without over-specifying SDC obligations in core.

Recommendation:
Keep this no-change audit as-is. Future changes, if any, should be handled in the SDC implementation guide or by a new work-group decision about canonical display usage, not by adding QuestionnaireResponse.title or strengthening current core requirements.
