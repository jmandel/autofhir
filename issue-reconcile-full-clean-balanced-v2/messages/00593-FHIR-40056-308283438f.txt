FHIR-40056: Audit Encounter location-period composite

Issue request:
FHIR-40056 was Published with a Persuasive with Modification resolution for Encounter search. It reported that independent location and location-period searches cannot require the same Encounter.location repetition, and resolved that a new composite search element should combine the location period and location.

Initial application:
The issue was initially applied by d2da51566687fc8a513617b464e65befc990b6dd, which changed the Encounter location-period search parameter into a composite over Encounter.location with location and period components. That direct application was later refined because the composite referenced a missing period sub-search parameter and did not match the search-parameter naming style used for composite value searches.

Additional context:
FHIR-41251 is the tightly related correction. Its applied commits 0e4b7b6df6bb707c81ebdde7d5b78336578c392d and f5dc96c451f0ff09011758d5cbed0d0627c6006e restored Encounter.location.period as a date search parameter and renamed the composite to location-value-period, with components pointing to location and location-period. Encounter is active in source/fhir.ini, and source/encounter/bundle-Encounter-search-params.xml now has the date and composite parameters together. PA Confluence references confirm the January 2023 approval, and no relevant conflicting Zulip discussion was found.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current active Encounter source already provides a composite search parameter, location-value-period, that binds the location reference and location period to the same Encounter.location repetition while keeping location-period as the date sub-parameter required by the later correction.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed for FHIR-40056 unless the work group wants to rename the current style-guide-compliant composite parameter, which would be a new compatibility decision.
