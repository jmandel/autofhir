FHIR-36780: Audit ImagingSelection scope update

Issue request:
FHIR-36780 was a Published/Persuasive R5 Imaging Integration clarification request to replace ImagingSelection Scope and Usage with WG-06 wording. The requested text described ImagingSelection as an event resource, a selection of DICOM SOP instances and/or frames within one Study and Series, optional DICOM specifics such as ObservationUID/TrackingUID/SegmentationUID, the relevant Observation/ImagingStudy/presentation/shared-context uses, and the rule that one ImagingSelection references SOP instances from one DICOM Series/Study.

Initial application:
The request was applied before this reconciliation. Jira cites merge commit c138fb1b9ed930251866ab1da3be7d524b3fb1d4, whose first-parent diff updated source/imagingselection/imagingselection-introduction.xml by removing the duplicate opening paragraph, adding the requested WG-06 wording, expanding the use-case bullets, and adding the multiple-Study/Series guidance. ImagingSelection is an active current-build resource in source/fhir.ini, so this source file is in scope.

Additional context:
Later final ImagingSelection decisions intentionally changed the literal wording. FHIR-37683 replaced the original paragraph with the current structured list of ImagingStudy selections and regions; FHIR-49022 changed Observation.focus language to Observation.derivedFrom; FHIR-51645 cleaned the introductory and detailed wording; and FHIR-54812 explicitly removed the event-resource sentence as redundant because the workflow relationship appears elsewhere. The current StructureDefinition still maps ImagingSelection to the workflow Event pattern. Community searches found no directly relevant Zulip or Confluence record that conflicts with this Jira/source history.
