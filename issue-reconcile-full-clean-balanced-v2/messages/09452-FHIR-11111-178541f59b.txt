FHIR-11111: Audit Device latex safety support

Issue request:
FHIR-11111 was Published/Persuasive for FHIR-core Device after the DSTU2 ballot. It requested a repeatable CodeableConcept safety-characteristic element so Device could convey additional latex-related safety information, using existing GUDID-style safety concepts and marking the element as summary.

Initial application:
The Jira-tagged historical commit 6af0b8c30aa11aac02a776420fb44ef2b080e463, "[#11111],[#11110]", added Device.safety as a 0..* summary CodeableConcept and introduced a device-safety code list plus a Device UDI example. Later source refactors converted the spreadsheet source into the current StructureDefinition XML without losing the element.

Additional context:
Device is active in source/fhir.ini, so source/device/structuredefinition-Device.xml is current build scope. The current Device.safety element remains 0..* CodeableConcept, isSummary=true, and has an example binding to http://hl7.org/fhir/ValueSet/device-safety. The current device-safety ValueSet includes Natural Rubber Latex concepts. Later FHIR-32573 explicitly added the Device.safety value-set binding; FHIR-40909 asks for additional EUDAMED examples but is only Resolved - change required and still awaiting terminology input, so it is context rather than an applied current-spec change.

AutoFHIR reconciliation:
No source change was made. The current source already conveys the requested Device latex safety characteristic support through Device.safety and the device-safety ValueSet.

Recommendation:
Keep this audit commit as-is. Future work on additional EUDAMED safety codes should proceed under FHIR-40909 or a terminology follow-up, not as a correction to FHIR-11111.
