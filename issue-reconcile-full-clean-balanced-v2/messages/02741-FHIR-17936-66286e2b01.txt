FHIR-17936: Add ClaimResponse payment constraint

Issue request:
FHIR-17936 was Published/Persuasive for STU3 by Financial Management. It asked that ClaimResponse.payment only be present when ClaimResponse.use is 'claim' and ClaimResponse.outcome is not 'error'.

Initial application:
Historical commit afb5ec66f6 listed FHIR-17936 among a batch of ClaimResponse spreadsheet updates, but the current active source no longer contains the old spreadsheet and the generated StructureDefinition had only the existing ClaimResponse.error comment, not a conformance constraint covering both use and outcome.

Additional context:
ClaimResponse is active in source/fhir.ini. Related FHIR-13030 clarified that actual payment is associated with traditional claim responses, and later FHIR-36101 left Claim/ClaimResponse covering claims, preauthorizations, and predeterminations. A Zulip thread about ClaimResponse.error confirmed the existing error comment's SHOULD wording was not mandatory; the new invariant is therefore limited to the Jira-requested payment condition and does not prohibit error elements with non-error outcomes.

AutoFHIR reconciliation:
Added root invariant clr-2 to source/claimresponse/structuredefinition-ClaimResponse.xml requiring payment.empty() or use = 'claim' with outcome != 'error'. Existing ClaimResponse examples satisfy the rule.

Recommendation:
Keep this source change. It implements the published Jira decision in the active StructureDefinition without adding redundant narrative or changing related resources.
