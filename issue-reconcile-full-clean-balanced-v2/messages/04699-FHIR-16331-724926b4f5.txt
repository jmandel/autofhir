FHIR-16331: Audit code-system URI registration guidance

Issue request:
FHIR-16331 was a Published/Persuasive with Modification FHIR-core terminology issue raised against the STU3 "Choosing a system" guidance. It objected to the final fallback that told implementers to invent a unique code-system URI when no publisher or registered URI existed, and the accepted resolution was to add links to the terminology systems page and to the terminology instructions place to ask HL7 for help determining the public URL.

Initial application:
The issue was explicitly applied by git-svn commit f329007b77 (svn 14660), which added a Registering Code Systems link to source/terminologies-systems.html and appended that same registration-process link to the fallback paragraph in source/terminologies.html. That matches the Jira comment noting svn 14660.

Additional context:
The current source no longer contains the old "implementers must choose a URI" fallback. Later vocabulary decisions and edits moved the guidance to THO/TSMG: source/terminologies.html now says to use the canonical THO CodeSystem URL when listed and otherwise follow the TSMG Terminology Expectations process; source/terminologies-systems.html now points readers to THO, the THO CI build, the TSMG mailing list, the External Code Systems page, and the Registering Code Systems advice. FHIR-31878 later corrected the registration link target and is already represented on the combined branch; FHIR-50716 later updated the systems-page URI search list to THO/TSMG.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current terminology source already provides the requested HL7-managed path for determining public code-system URIs and no longer encourages arbitrary implementer-created public URIs.

Recommendation:
Keep this audit commit as-is. Revisit only if the TSMG/Terminology Expectations process URL itself changes or the Vocabulary/TSMG groups make a new policy decision about code-system URI registration.
