FHIR-29265: Audit Substance instance flag supersession

Issue request:
FHIR-29265 was Published/Persuasive for R5 and asked to add a mandatory Substance.instance boolean flag, where true meant an instance and false meant a definition. The issue was split from FHIR-28547, voted together with FHIR-29267 on the 2020-10-26 O&O call, and the Jira comment asked for the new flag to be an isModifier element.

Initial application:
The request was explicitly applied in ce7d94f0984ae009254c17c60df0d81252aafac0, whose subject cites FHIR#29265 and which added the R5 Substance.instance flag in the then-authoritative Substance spreadsheet while applying companion Substance changes from FHIR-29267 and FHIR-28547. FHIR-31526 later reverted breaking Substance changes for the R4B line, and subsequent R5 work restored the intended R5 Substance model before the source moved to the current StructureDefinition XML form.

Additional context:
FHIR-48405 is a later Applied/Persuasive BR&R decision for R6 that supersedes the boolean-flag approach: it says to remove Substance.instance, make Substance only for instances, and use SubstanceDefinition for definitional substances. The current combined branch already contains FHIR-48405 reconciliation commit 1266a70e30373662bcaf36d0e1d4daf8a59f7c1f, plus related FHIR-29267 and FHIR-31526 audit commits. Substance is active in source/fhir.ini, and the current authoritative Substance source has no Substance.instance element; its narrative states that Substance is used for instances and not for definitional substances. The remaining Substance.instance strings in source/fhir.ini are R5/R6 migration notes for old paths, not active element definitions.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Reintroducing a mandatory boolean Substance.instance flag would now contradict FHIR-48405 and the current Substance/SubstanceDefinition split. The current source preserves the implementer-significant distinction that motivated FHIR-29265 by making all Substance resources instances and directing definitions to SubstanceDefinition.

Recommendation:
Keep this no-change audit commit. If the work group wants to revisit whether Substance should again support both instance and definition semantics, that should be a new policy change or a FHIR-48405 follow-up, not a FHIR-29265 fixup.
