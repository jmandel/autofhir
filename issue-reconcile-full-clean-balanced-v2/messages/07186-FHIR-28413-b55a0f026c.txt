FHIR-28413: Audit namespace extension documentation

Issue request:
FHIR-28413 was Published/Persuasive with Modification for R5. It asked to document a value for the elementdefinition-namespace extension that represents XML with no assigned namespace; the approved modification was to use `noNamespace` rather than `default`.

Initial application:
The request was applied in core by commit e330dcd5111b81c2120748957b7666a9ea56ed33, which updated source/datatypes/elementdefinition-extensions-spreadsheet.xml to say that the special value `noNamespace` indicates no assigned XML namespace. That spreadsheet row was later removed from current core by dd468d4f1799dd79819315b211588ef1cf4586e0 when extension definitions were removed from the R5 source.

Additional context:
Current source/fhir.ini does not include source/datatypes/elementdefinition-extensions-spreadsheet.xml as an active profile input, and current core source has no elementdefinition-namespace or xml-namespace definition to edit. The FHIR Extension Pack carries the retired elementdefinition-namespace extension and marks it as replaced by http://hl7.org/fhir/tools/StructureDefinition/xml-namespace. The published/current Tools IG xml-namespace definition contains the same `noNamespace` documentation requested by this issue.

AutoFHIR reconciliation:
This commit intentionally makes no source change in the core checkout. The current core build no longer owns the affected extension definition, and the replacement external definition already includes the required `noNamespace` guidance.

Recommendation:
Keep this audit commit as-is for core. If future work touches namespace extension definitions, maintain the replacement Tools IG definition and the retired Extension Pack pointer rather than reintroducing elementdefinition-namespace content to core.
