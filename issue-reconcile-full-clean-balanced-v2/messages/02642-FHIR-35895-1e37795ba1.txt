FHIR-35895: Audit MedicationRequest performer cardinality

Issue request:
FHIR-35895 was a Published/Persuasive Pharmacy change request raised against R5 and applied for R5. It asked to update MedicationRequest.performer from 0..1 to allow multiple performers, with examples involving both a device and a person or both a nurse and patient.

Initial application:
The issue was applied in commit b9257918056a31ebdc080627432cc94db78637e0, an aggregate Pharmacy commit that changed source/medicationrequest/structuredefinition-MedicationRequest.xml so MedicationRequest.performer max changed from 1 to *.

Additional context:
This issue is tightly connected to FHIR-22146 because it concerns the same MedicationRequest.performer element. The later cardinality change preserved the performer target profile set, including HealthcareService, and the current element definition now explains that both an IV pump and the practitioner setting the pump can be listed as performers.

AutoFHIR reconciliation:
No source change was made. The current active MedicationRequest StructureDefinition has MedicationRequest.performer max="*" and contains explanatory text supporting multiple performers, so the current source already satisfies the published issue.

Recommendation:
Keep this audit commit as-is. The current specification reflects the approved cardinality and no additional source correction is needed for this issue.
