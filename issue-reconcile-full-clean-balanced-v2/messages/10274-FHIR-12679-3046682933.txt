FHIR-12679: Audit Observation event pattern reconciliation

Issue request:
FHIR-12679 was a Published/Persuasive OO change request raised against DSTU2 Observation. It asked to harmonize Observation to the event pattern by making Observation.identifier a summary element with pattern wording, adding `name` as an alias on Observation.code, renaming Observation.encounter to Observation.context with an `encounter` alias while adding EpisodeOfCare to the reference type, and retaining an Encounter search parameter.

Initial application:
The issue was applied in git-svn commit 2c8fb553cfc67b9b93eca7789fc412e6e4613d42 (`[#12679], [#9664]`). That commit edited the then-authoritative Observation spreadsheet to mark Observation.identifier as summary, change its short/definition, add `name` as the Observation.code alias, rename Observation.encounter to Observation.context, widen the type to Reference(Encounter|EpisodeOfCare), and add the Encounter/context search parameter rows.

Additional context:
The current build scope includes Observation as an active resource in source/fhir.ini, so the current Observation StructureDefinition and search parameter bundle are authoritative. Later Published/Applied workflow decisions intentionally changed the model after FHIR-12679: FHIR-17661 changed Observation.context back to Observation.encounter, restricted the element to Reference(Encounter), and moved EpisodeOfCare support to the workflow-episodeOfCare extension; FHIR-17901 propagated the same Event/Request pattern decision. FHIR-33166 revisited whether Observation should return to context/EpisodeOfCare and resolved only to add guidance in the Observation.encounter short text. FHIR-42761 rejected a broader Event.context/EpisodeOfCare rollback, and FHIR-42762 put the workflow-EpisodeOfCare search parameter on the extension in the FHIR Extension Pack rather than on each core resource page. FHIR-43456 later analyzed Observation workflow alignment and added specific mappings without reopening the identifier wording or encounter model.

AutoFHIR reconciliation:
This audit commit makes no source change. The current source preserves the lasting parts of FHIR-12679 that remain correct now: Observation.identifier is summary, Observation.code has the Name alias, and the Encounter search parameter exists. The apparent differences from the 2017 request are intentional later design decisions: the element is Observation.encounter with a Context alias and a Reference(Encounter) type, while EpisodeOfCare is represented through the workflow-episodeOfCare extension and extension-pack search parameter.

Recommendation:
Keep this no-change audit. Do not revert Observation.encounter to Observation.context or add EpisodeOfCare as a core target type unless the work groups make a new breaking-change decision that supersedes FHIR-17661, FHIR-33166, and FHIR-42761. Any further work on extension search rendering belongs with the FHIR Extension Pack/tooling discussion rather than this core Observation reconciliation.
