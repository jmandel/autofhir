FHIR-3954: Audit NamingSystem example punctuation

Issue request:
FHIR-3954 was a Published/Persuasive DSTU1 FHIR-core NamingSystem correction asking that the Namespace.category display stop looking like an enumeration by using examples with commas: "E.g. driver, provider, patient, bank" instead of "driver | provider | patient | bank".

Initial application:
The issue was applied in SVN/git history by commit 94cb5ef302ecf451a2b7863b4b43e709f3614410, which changed the NamingSystem category short description from "driver | provider | patient | bank" to "e.g. driver,  provider,  patient, bank etc". Current source has since evolved to the NamingSystem.type element, but the active StructureDefinition and generated search parameter source both retain the comma-separated example form.

Additional context:
source/fhir.ini actively includes the NamingSystem resource, so source/namingsystem/structuredefinition-NamingSystem.xml is current build input. A repository-wide source search found no remaining "driver | provider | patient | bank" style text, and Zulip/Confluence searches found no directly relevant later discussion or conflicting work-group decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change because the current active NamingSystem source already satisfies the Jira request by presenting the examples with commas rather than vertical bars. The remaining double spaces in the short display are historical formatting noise and do not recreate the enumeration ambiguity the issue resolved.

Recommendation:
Keep this audit commit as-is. No follow-up is needed in core FHIR for FHIR-3954 unless a future editorial cleanup separately chooses to normalize whitespace in the NamingSystem.type short text.
