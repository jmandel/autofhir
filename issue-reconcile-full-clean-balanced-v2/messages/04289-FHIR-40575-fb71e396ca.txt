FHIR-40575: Audit draft content clarity language

Issue request:
FHIR-40575 was a Published/Persuasive FHIR-core R5 clarification for the FHIR-core compatibility page. It asked to make clear that resources with standards status Draft are not necessarily limited to FMM 0: Draft-status resources may have FMM 1 or 2 before balloting, Draft resources cannot have FMM greater than 2, and artifacts at FMM 0 must have standards status Draft.

Initial application:
The Jira comment identifies git master e6b8a1b075914d0e8d2a269ab855dafa0b2ec41a as the application commit. That commit updated source/versions.html by adding the Draft standards-status paragraph about FMM 1/2 and by rewriting the FMM table so FMM 0 artifacts must have standards status Draft, while expanding abbreviated WG/FMG wording and adding the FMM 6/Normative row. Current source still contains those semantic changes.

Additional context:
The linked Zulip thread shows the ambiguity that prompted the issue: participants distinguished HL7 standards status Draft from FMM 0 and agreed that unballoted Draft resources can still be FMM 1 or 2. FHIR-I minutes for 2023-03-20 record the 14-0-0 Persuasive vote. Later applied issues FHIR-44052 and FHIR-47042 touched the same page, changing the table label from "Draft (0)" to "FMM 0" and adding the FMM expansion/link; these later edits clarify rather than reverse FHIR-40575. source/versions.html is a root specification source page linked from the Version Management section in source/documentation.html and is therefore in the current build scope.

AutoFHIR reconciliation:
This commit makes no source change. The current source already conveys the required distinction: Draft standards status can pair with FMM 1 or 2 but not above 2, while FMM 0 implies standards status Draft. The later "FMM 0" label is consistent with the approved FHIR-44052 clarification and should not be reverted to the original proposed wording.

Recommendation:
Keep this audit as-is. Any future work on the broader FMM framework or page readability should be handled under the later specific trackers rather than reopening FHIR-40575.
