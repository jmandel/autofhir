FHIR-7672: Audit DetectedIssue category value set

Issue request:
FHIR-7672 was Published/Persuasive for DSTU1 and asked that Contraindication.category have an actual populated value set or at least a good set of examples based on the logical value set specification.

Initial application:
No source commit explicitly mentioning FHIR-7672 was found. The Jira comments say the policy should be followed and then that the request had already been done. The historical source trail shows the original Contraindication category value set existed with v3 ActCode filters, FHIR-8043 renamed Contraindication to DetectedIssue, and FHIR-8336 immediately fixed the detectedissue-category compose from an empty intersection to a union of detected-issue ActCode hierarchies.

Additional context:
DetectedIssue is the current build-scoped successor for the old Contraindication resource, and source/fhir.ini lists it as an active CDS resource while noting that Contraindication became DetectedIssue. Later Applied issue FHIR-39458 intentionally split high-level DetectedIssue.category from detailed DetectedIssue.code, creating a separate detectedissue-code value set and restricting detectedissue-category to explicit category concepts.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative source/detectedissue/structuredefinition-DetectedIssue.xml binds DetectedIssue.category to http://hl7.org/fhir/ValueSet/detectedissue-category, and source/detectedissue/valueset-detectedissue-category.xml is populated with FOOD, DRUG, ALGY, and DUPTHPY example/category concepts from v3 ActCode. Re-expanding the category value set to the older broad filters would undo the later FHIR-39458 decision.

Recommendation:
Keep this no-change audit as-is. The current source satisfies the FHIR-7672 request in the active successor artifact; any future changes to category breadth should be handled as a new CDS terminology decision rather than as a missing application of this DSTU1 tracker.
