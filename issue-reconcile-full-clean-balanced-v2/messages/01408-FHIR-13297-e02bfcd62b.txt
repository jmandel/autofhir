The reported published ValueSet expansion failed because publication tooling could not support the IHE format-code code system urn:oid:1.3.6.1.4.1.19376.1.2.3, and the final resolution was to change the OID reference to a URI.

Initial application:
No source commit explicitly mentioning FHIR-13297 was found. Related source history applied that terminology correction in the formatCode family: git commit f86337b9ba (GF#13950 and GF#14003) replaced the old IHE OID system include in the local FormatCodes ValueSet with the URI http://ihe.net/fhir/ValueSet/IHE.FormatCode.codesystem, and later commits moved the format-code terminology to newer URI-based definitions.

Additional context:
Current build-scope checks show both Consent and Contract are active in source/fhir.ini. The current Consent Content Class sources do not include urn:oid:1.3.6.1.4.1.19376.1.2.3 in their compose: source/consent/valueset-consent-content-class.xml imports http://terminology.hl7.org/ValueSet/v3-HL7FormatCodes and LOINC document types, while source/contract/valueset-consent-content-class.xml imports http://hl7.org/fhir/ValueSet/doc-typecodes plus URI and MIME-type concepts. Remaining current-source occurrences of the old IHE OID are example Coding.system values or explanatory DocumentReference text, not the Consent Content Class ValueSet compose that caused the expansion failure. FHIR-13950 and FHIR-14003 already have audit commits on the combined branch for the tightly related FormatCodes terminology handoff and OID correction.
