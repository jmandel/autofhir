FHIR-53981: Audit applied Goal status renames

Issue request:
FHIR-53981 was an Applied FHIR-core Goal change request resolved as Persuasive with Modification. It asked to disambiguate Goal.statusDate and Goal.statusReason because those names hid that one described achievement status timing and the other described lifecycle status rationale. The accepted resolution renamed statusReason to lifecycleStatusReason, renamed statusDate to achievementStatusDate with the achievement spelling fixed, and reordered the elements so each sits next to the status element it qualifies.

Initial application:
The issue appears to have been applied by git commit 7c5f0e11de0dc83a215b666f3d8f0ae8a563300b, which renamed and reordered the Goal elements in source/goal/structuredefinition-Goal.xml, updated source/goal/goal-example.xml, and added the Goal ballot note. The Jira comment also linked f17eb111cc, but that commit only changed source/status-codes.xml and does not affect the Goal rename. Current source/fhir.ini keeps Goal in active build scope.

Additional context:
The current authoritative Goal StructureDefinition has Goal.lifecycleStatusReason immediately after Goal.lifecycleStatus and Goal.achievementStatusDate immediately after Goal.achievementStatus, with committee notes referencing J#53981. The example uses lifecycleStatusReason and achievementStatusDate. Exact old Goal element names remain only in source/goal/goal.svg, a generated-looking diagram, and inside a commented-out invariant-test snippet. The same implementation commit also carried unrelated Goal work for FHIR-55326 and FHIR-53828; those are background only and are not decided here. Zulip and Confluence searches found no conflicting community decision; the Confluence Patient Care minutes page references FHIR-53981, while the Jira snapshot contains the substantive recorded vote and rationale.
