FHIR-7121: Audit Procedure progress status handling

Issue request:
FHIR-7121 was a Published/Persuasive with Modification Patient Care change request against Procedure.status. It said the base status codes were too coarse for detailed surgical workflow states such as in OR, prepped, anesthesia induced, opened, closed, and recovery. The accepted resolution kept Procedure as a high-level resource, created a common extension for detailed procedure progress statuses, and noted that any detailed progress profile would be scheduled outside DSTU2.

Initial application:
No current git commit explicitly mentioning FHIR-7121 was found. The historical application is visible through adjacent source history: daa5d326d1 added source/procedure/valueset-procedure-progress-status-codes.xml in 2015, 33b409a4b6 reworked the source and added source/procedure/structuredefinition-extension-procedure-progressStatus.xml with the Procedure context and value-set binding, and FHIR-12706/25942dbc17 later cleaned up the procedure progress status code system. The core extension files were then removed from the R5 source by dd468d4f17 as part of moving extension definitions out of core.

Additional context:
The current core build still includes Procedure through source/fhir.ini, and Procedure.status remains a required high-level event status rather than a detailed surgical workflow element. The detailed progress artifacts now live in the FHIR Extension Pack, whose ig.ini points to input/extensions-ig.xml and includes input/definitions/* as resource input. That Extension Pack source contains StructureDefinition/procedure-progressStatus with context Procedure, the matching value set, and the code system with in-operating-room, prepared, anesthesia-induced, open-incision, closed-incision, and in-recovery-room codes. Direct Zulip and Confluence searches for FHIR-7121 found no conflicting community decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Reintroducing the extension into core or adding redundant Procedure prose would be inappropriate because the current core Procedure source remains consistent with the issue's 80% high-level-status rationale and the detailed-status extension is already maintained in the Extension Pack.

Recommendation:
Keep this audit commit as-is. Future changes to procedure-progressStatus or its terminology should be made in the FHIR Extension Pack; a dedicated detailed surgical progress profile should only be added if Patient Care creates and scopes that profile as a current build artifact.
