FHIR-15656: Audit HealthcareService multiple eligibility support

Issue request:
FHIR-15656 was Published/Persuasive with Modification for the PA HealthcareService resource. It asked to allow multiple HealthcareService eligibility criteria because HealthcareService.eligibility and eligibilityNote were both 0..1 in STU3; the approved resolution converted them into a repeating eligibility BackboneElement with code 0..1 and note/comment markdown 0..1.

Initial application:
The request was applied in git by bd89a75a69, which changed the HealthcareService spreadsheet and example from a single CodeableConcept eligibility plus eligibilityNote into HealthcareService.eligibility 0..* with nested code and note. A same-day follow-up, 571123a002, renamed the nested note to comment per QA rules while preserving the markdown note semantics. The later source-format rework retained this model in source/healthcareservice/structuredefinition-HealthcareService.xml.

Additional context:
PA's 2018 Baltimore WGM minutes record the FHIR-15656 discussion, the relationship to FHIR-15627, and an 8-0-0 persuasive-with-modification vote. HealthcareService is active in source/fhir.ini, so source/healthcareservice/structuredefinition-HealthcareService.xml is the authoritative current source. Later Applied HealthcareService decisions, especially FHIR-41782 with supporting FHIR-15627/FHIR-39306 context and FHIR-45139 validation cleanup, expanded the same repeating eligibility backbone with value[x], period, example codes, and invariant conditions without restoring the old single eligibility/eligibilityNote shape. A source search still finds eligibilityNote in the QUICK model Library example, but that artifact models an older QUICK information model and is not the current HealthcareService resource definition.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active HealthcareService StructureDefinition already allows multiple eligibilities with HealthcareService.eligibility max="*", uses BackboneElement, has code 0..1, and has markdown comment 0..1; the current example and eligibility search parameter also use the nested eligibility shape.

Recommendation:
Keep this audit commit as-is. FHIR-15656 is already correctly represented in the current build; any future modernization of the older QUICK model example should be handled separately and not treated as a missing FHIR-15656 HealthcareService resource fix.
