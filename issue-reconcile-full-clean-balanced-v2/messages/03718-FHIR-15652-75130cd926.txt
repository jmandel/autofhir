FHIR-15652: Audit corrected RiskAssessment ras-2 cast

Issue request:
FHIR-15652 was a Published, Persuasive CDS technical correction for the RiskAssessment resource in STU3. The Jira reported that ras-2 incorrectly used the FHIRPath `as` operator as a function, `probability.as(decimal)`, and requested the corrected cast form `probability is decimal implies (probability as decimal) <= 100`.

Initial application:
The Jira comments say the issue was applied in SVN revision 13437. Git history maps that to commit 114d1bcf64acc14dec8fed9e338e8022e6a6d562 (`GF#15652 - fix invariant`), which changed the RiskAssessment spreadsheet source from `probability.as(decimal)` to `(probability as decimal)`.

Additional context:
RiskAssessment is active in source/fhir.ini, so source/riskassessment/structuredefinition-RiskAssessment.xml is current build input. The current source no longer uses the obsolete spreadsheet, but the active StructureDefinition carries the same corrected cast spelling. Later FHIR-25796 work added the `probability.empty()` guard so ras-2 does not require probability to be present, and FHIR-27875 later touched the same probability element; both related issues are already represented on the combined branch and do not require duplicate reconciliation here. Zulip discussion of the later missing-probability failure supports the current expression, and Confluence searches found no conflicting FHIR-15652 evidence.

AutoFHIR reconciliation:
This commit makes no source change. The active current ras-2 expression is `probability.empty() or ((probability is decimal) implies ((probability as decimal) <= 100))`, which uses the corrected `as` operator form requested by FHIR-15652 while preserving later valid behavior for absent probabilities.

Recommendation:
Keep this empty audit commit as-is. No current core source follow-up is needed for FHIR-15652; related later RiskAssessment probability issues should remain tracked by their own existing reconciliation commits.
