FHIR-37494: Audit migrated identifier type column

Issue request:
FHIR-37494 was Published/Persuasive with Modification for R5 and asked the Known Identifier Systems table to define that the Type column corresponds to Identifier.type. The accepted resolution required a sentence saying Type is a code from the Identifier Type code system that SHALL be used in Identifier.type if Identifier.type is present when conveying the specified identifier.

Initial application:
The issue was applied in source/identifier-registry.html by 423ca82214, which added the requested sentence, and 2164932ef, which fixed the link to Identifier.type in that sentence. No current source change is needed to repeat that text because the table it described is no longer present in core.

Additional context:
FHIR-35932 later removed the core identifier systems table after the content was migrated to HL7 Terminology/THO. The current core identifier-registry.html page remains in build scope through hierarchy.xml and terminology-module.html, but it now explains that the registered identifier systems live in HL7 Terminology. The THO NPI NamingSystem still carries the structured type coding http://terminology.hl7.org/CodeSystem/v2-0203#PRN, preserving the specific semantic concern from the Jira example without a core table column.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Reintroducing a Type-column explanation into core would be stale because core no longer owns or renders that table; the current core page correctly delegates identifier system records to THO.

Recommendation:
Keep this audit commit as-is for FHIR core. If a future implementer-facing display problem remains in the THO identifier registry, handle it through THO/UTG rather than by adding redundant core prose.
