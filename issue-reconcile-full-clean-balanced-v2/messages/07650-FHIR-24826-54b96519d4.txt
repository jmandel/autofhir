FHIR-24826: Audit sourceFile extension relocation

Issue request:
FHIR-24826 was Published with a Persuasive with Modification resolution for R5. It asked to support images and other non-resource artifacts associated with an ImplementationGuide by defining a standard 0..* extension on ImplementationGuide.definition named sourceFile, with file, location, and keepAsResource components.

Initial application:
Core commit 81f7c6c5f5 added source/implementationguide/structuredefinition-extension-implementationguide-sourceFile.xml and referenced it from the core ImplementationGuide profile, while source/oids.ini later registered the extension OID. The core extension source was subsequently removed by dd468d4f17 as part of moving standard extensions out of the R5 core source.

Additional context:
The current core build still has ImplementationGuide as an active resource and retains the implementationguide-sourceFile OID mapping, but the extension StructureDefinition itself now belongs to the FHIR Extension Pack. The Extension Pack source defines the requested context, cardinality, file/location/keepAsResource components, and usage notes; the later FHIR-46629 correction fixed the copied component fixedUri values there. FHIR-24649 is related background for ImplementationGuide.definition.page.source[x], but it is a separate published tracker and not needed to decide this asset extension audit.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. Re-adding the extension definition to core would reverse the later extension-pack relocation; the current source of truth for the requested extension is /home/jmandel/work/fhir-extensions/input/definitions/ImplementationGuide/StructureDefinition-implementationguide-sourceFile.xml.

Recommendation:
Keep this external-repo audit as-is for core. Future changes to implementationguide-sourceFile should be made in the FHIR Extension Pack, not by reintroducing the extension StructureDefinition into the core FHIR checkout.
