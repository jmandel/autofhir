FHIR-19420: Audit CarePlan immunization reference

Issue request:
FHIR-19420 was Published with a Persuasive resolution for R5. It asked that CarePlan.activity.reference allow Reference(ImmunizationRecommendation), or else remove CarePlan scope prose that mentioned immunization, because the then-current CarePlan Scope and Usage example mentioned a patient due for tetanus immunization.

Initial application:
The issue was applied in commit 218ec67c42b8156bcd8330a57848603b297321d3, which added ImmunizationRecommendation to the CarePlan activity reference target list in the then-authoritative CarePlan spreadsheet and tagged the row GF#19420. Later source refactors renamed CarePlan.activity.reference to CarePlan.activity.plannedActivityReference and carried the GF#19420 committee note forward.

Additional context:
The current core build no longer contains ImmunizationRecommendation as an active core resource. Commit e073fb45ec6f5a738a9f674baf63406bfe90fb78 removed ImmunizationRecommendation and ImmunizationEvaluation source, removed ImmunizationRecommendation from CarePlan.activity.plannedActivityReference, and changed the CarePlan boundaries prose to point to the external Immunization Incubator definition. Current source/fhir.ini lists Immunization but no active ImmunizationRecommendation resource, while the Immunization Incubator package now defines the ImmunizationRecommendation resource specialization. A checked-in CarePlan SVG still shows ImmunizationRecommendation, but the authoritative StructureDefinition source and current build scope are the controlling evidence.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. Re-adding ImmunizationRecommendation to the core CarePlan targetProfile list would reverse the later out-of-core resource move and introduce a core reference to an artifact that is not part of the current core build.

Recommendation:
Keep this audit commit as-is. If Patient Care, Public Health, and FHIR-I want core CarePlan to reference the Immunization Incubator resource explicitly, that should be handled as a new cross-artifact dependency decision; otherwise the current core source correctly reflects the later move of ImmunizationRecommendation out of core.
