FHIR-32153: Audit canonical status mappings

Issue request:
FHIR-32153 is a Published/Persuasive MnM technical correction asking that canonical Resource Status mappings be comprehensive. The issue identified that the Resource Status CodeSystem promised that all status codes are mapped, while then-current examples such as DiagnosticReport and Observation appeared to map only some status codes.

Initial application:
No git commit explicitly mentions FHIR-32153. The issue appears to have been applied through the checked-in status-code mapping source rather than a Jira-tagged commit: source/status-codes.xml received substantial 2022 maintenance after the January 2022 resolution, including bfee6355da Fixed status code references, b8e93ff110 Committed canonicalized status-codes spreadsheet, and 6d37dbb3ee Fixed status codes that were incorrectly categorized and sorted list. Current source/status-codes.xml now includes complete mapping rows for the DiagnosticReport.status and Observation.status examples called out in the issue.

Additional context:
FHIR-15816 had already established MnM ownership and maintenance expectations for resource-status. FHIR-43569 later added the canonical ended code after a MedicationRequest mapping exposed that the target code was absent; the current CodeSystem contains ended and source/status-codes.xml maps MedicationRequest.status ended to it. The relevant current files are in build scope: source/fhir.ini actively registers codesystem-resource-status.xml, source/hierarchy.xml and publish.ini include sc.html, and sc.html expands the status-codes table from the checked-in spreadsheet.

AutoFHIR reconciliation:
