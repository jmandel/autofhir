FHIR-32822: Audit DocumentReference type binding

Issue request:
FHIR-32822 was a Published/Persuasive with Modification R5 OO change request asking why Composition.type and DocumentReference.type used different preferred value sets and suggesting a common binding. The recorded resolution/comments focused on moving DocumentReference.type away from the old HITSP C80-specific set to a non-C80 document type value set.

Initial application:
No git commit message found in this checkout explicitly names FHIR-32822. The implementation appears to have been applied through the March 2022 DocumentReference value set work: commit cebeac615e0c434ff755a1aa763781d2cf61c8c2 changed DocumentReference.type from bindingName DocumentC80Type and ValueSet/c80-doc-typecodes to bindingName DocumentType and ValueSet/doc-typecodes.

Additional context:
OO minutes from 2022-01-18 record the FHIR-32822 motion to accept John Moehrke's recommendation, remove C80 from the URL/references, and coordinate with FHIR-32578. FHIR-32578 later resolved that DocumentReference.type should use the same doc-typecodes value set already used by Composition. FHIR-28078 was subsequently Applied in 2025 and explicitly says build.fhir.org/valueset-doc-typecodes.html has been applied as a preferred binding to DocumentReference.

AutoFHIR reconciliation:
No source change was made. Current build-scope source has both Composition.type and DocumentReference.type using a preferred binding named DocumentType to http://hl7.org/fhir/ValueSet/doc-typecodes, which matches the implemented non-C80 outcome and the later explicit same-as-Composition decisions.

Recommendation:
Keep this audit commit as-is. Reintroducing a separate reduced/example DocumentReference type binding would conflict with FHIR-32578 and FHIR-28078; any future change to split these bindings should come through a new OO terminology decision.
