FHIR-13499: Audit GTIN system URI migration

Issue request:
FHIR-13499 was a Published/Persuasive with Modification FHIR-I STU3 change request asking FHIR core to define a system URI for GTIN numbers. The issue proposed http://www.gtin.info/, but the approved resolution and later comments selected https://www.gs1.org/gtin after GS1 confirmation and editor concurrence.

Initial application:
The seed was first applied by 72686673f4ac6015711e1e3bc64890e7459fe94a, "Define URL for GS1", which added NamingSystem/gtin to source/namingsystem/namingsystem-registry.xml with kind identifier, OID 1.3.160, and URI https://www.gs1.org/gtin. A later same-family GTIN documentation issue, FHIR-17940, was applied by bc2fbf0da2bedef715d54d01c4bdf33e613bac59, which added a GTIN row to source/terminologies-systems.html with the same URI and OID.

Additional context:
Later Published Vocabulary issues changed the authoritative source. FHIR-37853 established HL7 Terminology (THO) as the source of truth for external code and identifier system information and commit 736ccce2005fd2c8c2d20dfe8df948e8c9d586d8 removed external rows without FHIR-specific usage pages from terminologies-systems.html, including GTIN. FHIR-37889 then removed the core NamingSystem registry bundles because they duplicated THO content. The current build-scoped identifier-registry.html and terminologies-systems.html pages now direct readers to THO, and the current hl7.terminology 7.1.0 package contains NamingSystem/gtin with preferred URI https://www.gs1.org/gtin and OID 1.3.160. The combined branch already has a separate no-change audit for FHIR-17940, so this commit audits only the seed issue.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding GTIN to core source would reverse the later THO source-of-truth decisions and duplicate external identifier registry content. The current core source correctly points implementers to THO, where the GTIN URI selected by FHIR-13499 is present.

Recommendation:
Keep this audit commit as-is. Future corrections to the GTIN URI, OID, or descriptive metadata should be made in THO/NamingSystem-gtin rather than by restoring retired core registry rows or NamingSystem bundles.
