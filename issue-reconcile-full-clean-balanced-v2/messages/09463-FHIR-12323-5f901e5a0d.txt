FHIR-12323: Audit ElementDefinition mapping comment

Issue request:
FHIR-12323 was a Published FHIR-core ElementDefinition change request from DSTU2, resolved Not Persuasive with Modification. The issue asked to align StructureDefinition.mapping and ElementDefinition.mapping or clarify how they correlate; the approved decision kept their roles distinct and added comment to ElementDefinition.mapping.

Initial application:
The Jira application comment cites SVN revision 11548. In the git-svn history this is commit c0df469417b5ac953e7c5295d192eff6d12c484a, which added ElementDefinition.mapping.comment to the active source/datatypes/elementdefinition.xml spreadsheet as a 0..1 child for mapping-use comments. Commit 21fefc2247268b284d2791adbe9c959fec78db43 then corrected the wording from "it's use" to "its use".

Additional context:
The current build still uses source/datatypes/elementdefinition.xml for ElementDefinition, and source/fhir.ini routes elementdefinition to the active ElementDefinition page. Current StructureDefinition.mapping and ElementDefinition.mapping remain intentionally different: StructureDefinition.mapping declares the target mapping specification with identity, uri, name, and comment, while ElementDefinition.mapping references that identity and carries language, map, and comment for the element-level mapping expression. Later Published issue FHIR-28141 changed ElementDefinition.mapping.comment from string to markdown, and the current source preserves that later datatype change. Zulip and Confluence searches found no direct FHIR-12323 discussion or conflicting community evidence.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already reflects the approved FHIR-12323 outcome by retaining ElementDefinition.mapping.comment, and adding StructureDefinition-style name or uri elements to ElementDefinition.mapping would contradict the final decision that the two mapping components serve different purposes.

Recommendation:
Keep this no-change audit commit as-is. Future changes should preserve the distinct StructureDefinition.mapping declaration role and ElementDefinition.mapping expression role unless a new work-group decision explicitly changes the mapping model.
