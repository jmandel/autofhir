Issue request:
FHIR-31521 was a Published/Persuasive with Modification Patient Administration change request for R5 about ChargeItemDefinition.propertyGroup needing period and source-reference support. The approved resolution removed ChargeItemDefinition.effectivePeriod from the root and updated the shared applicability structure to carry condition, effectivePeriod, and relatedArtifact.

Initial application:
Commit 082ba11f51 applied the approved ChargeItemDefinition source change to the R5 StructureDefinition and examples, removing the root effectivePeriod and adding applicability.condition, applicability.effectivePeriod, and applicability.relatedArtifact. FHIR-31569 was explicitly incorporated into this decision for the condition Expression portion.

Additional context:
ChargeItemDefinition was later removed from active core resource inputs by commit 71567db3ee and moved to the HL7 Administrative Incubator IG, whose current source and CI JSON already carry the approved applicability structure. The active core Library/FHIR-ModelInfo example remained stale: before this issue family was reconciled it still exposed a root effectivePeriod and an old applicability backbone without effectivePeriod or relatedArtifact.

AutoFHIR reconciliation:
Completed the ModelInfo alignment by removing the stale root ChargeItemDefinition.effectivePeriod entry and adding effectivePeriod and relatedArtifact to ChargeItemDefinition.Applicability. The immediately preceding FHIR-31569 reconciliation commit changed the same ModelInfo type from old expression strings to condition as FHIR.Expression, so the combined worker commits now match the approved FHIR-31521/FHIR-31569 structure.

Recommendation:
Keep this commit. It fixes the remaining active core ModelInfo surface while leaving the authoritative ChargeItemDefinition resource maintenance in HL7/admin-incubator, where the current source is already aligned.
