FHIR-31479: Audit QuestionnaireResponse item-subject search path

Issue request:
FHIR-31479 was a Published/Persuasive FHIR-core technical correction for QuestionnaireResponse. It reported that the QuestionnaireResponse profiles page exposed an invalid FHIRPath expression for the item-subject search parameter because it used the nonexistent hasExtension(...) function to detect the questionnaireresponse-isSubject extension.

Initial application:
The Jira comments cite R5 commit da520ded49 and R4B commit f4f1c38ac9. Both commits changed the then-current individual QuestionnaireResponse-item-subject SearchParameter source from QuestionnaireResponse.item.where(hasExtension('http://hl7.org/fhir/StructureDefinition/questionnaireresponse-isSubject')).answer.value.ofType(Reference) to the valid extension('http://hl7.org/fhir/StructureDefinition/questionnaireresponse-isSubject').exists() form.

Additional context:
QuestionnaireResponse is an active resource in source/fhir.ini, and the current build input for the search parameter is source/questionnaireresponse/bundle-QuestionnaireResponse-search-params.xml after later source rework. The old individual SearchParameter file no longer exists in current source. Later FHIR-49784 recursively expanded QuestionnaireResponse item search paths, changing the expression to traverse nested items with repeat(item.combine(item.answer.item)) while preserving the corrected extension(...).exists() predicate. A Zulip thread from the issue reporter and Lloyd McKenzie confirms the original problem and that the intended correction was to replace the erroneous function before R4B.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source has exactly the valid item-subject expression, and a core-source search finds no remaining hasExtension(...) occurrence for this QuestionnaireResponse search parameter.

Recommendation:
Keep this no-change audit commit as-is. No current FHIR-core source follow-up is needed for FHIR-31479; any implementation still seeing the old hasExtension form is consuming an older published/package artifact or local SearchParameter copy rather than the current build source.
