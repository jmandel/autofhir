FHIR-46086: Register FHIRPath Patch operation terminology

Issue request:
FHIR-46086 was Applied as Persuasive with Modification for R6. It asked for the FHIRPath Patch operation type codes to be exposed in a ValueSet, and the final resolution also required a CodeSystem plus a core Parameters profile for validating FHIRPath Patch Parameters instances.

Initial application:
Commit 3f6c131b0b added source/parameters/codesystem-patch-operation.xml, source/parameters/valueset-patch-operation.xml, source/parameters/structuredefinition-profile-fhirpath-patch.xml, an ImplementationGuide reference for the profile, a fhirpatch.html profile link, and active source/fhir.ini CodeSystem/ValueSet registrations.

Additional context:
The current source still contains the CodeSystem, ValueSet, Parameters profile, and fhirpatch.html profile link, and the profile has a required binding to http://hl7.org/fhir/ValueSet/patch-operation. A later unrelated FHIR-48664 commit commented out the source/fhir.ini registrations for the CodeSystem and ValueSet while leaving the files and binding in place, which made the terminology definitions out of build scope. FHIR-48393 comments separately confirm FHIRPath Patch should remain in the core specification because it is used by the Patch operation.

AutoFHIR reconciliation:
This commit restores the active source/fhir.ini registrations for parameters/codesystem-patch-operation.xml and parameters/valueset-patch-operation.xml. No content changes were needed in the terminology XML or Parameters profile; the missing build-scope wiring was the remaining semantic defect.

Recommendation:
Keep this commit as-is. It restores the applied FHIR-I decision without broadening the change and preserves later metadata cleanups already made to the CodeSystem, ValueSet, and profile.
