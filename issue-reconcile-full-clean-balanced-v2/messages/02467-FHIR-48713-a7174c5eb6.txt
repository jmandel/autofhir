FHIR-48713: Audit abandoned DeviceAssociation association status

Issue request:
FHIR-48713 was Applied as Persuasive with Modification for R6. It asked to expand the DeviceAssociation status terminology with a term for implanted devices that remain in the patient's body but are no longer in use, with the final resolution saying to add abandoned/vestigial alongside the FHIR-48532 associationStatus changes and the follow-up Jira comment specifying code abandoned with display Abandoned.

Initial application:
The issue was applied before this reconciliation in commit f09755d231, which added the abandoned concept to source/deviceassociation/codesystem-deviceassociation-association-status.xml. That followed the linked FHIR-48532 implementation commit 2b906e8ba0, which split DeviceAssociation.status from the optional DeviceAssociation.associationStatus element and bound associationStatus to the DeviceAssociation Association Status value set.

Additional context:
DeviceAssociation is an active resource in source/fhir.ini, and DeviceAssociation.associationStatus is listed there as a current element. The current StructureDefinition binds associationStatus to http://hl7.org/fhir/ValueSet/deviceassociation-association-status with preferred strength, and that ValueSet includes the complete CodeSystem where abandoned is now present. OO minutes for 2025-10-20 record FHIR-48713 as completed with FHIR-48532 and approved 6-0-0, while a September Devices agenda note only shows earlier uncertainty before the later final Jira disposition.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The active source already contains the requested abandoned associationStatus code with display Abandoned and a definition matching the Jira request, and the ValueSet composition includes the whole association-status CodeSystem. Adding redundant prose to the non-exhaustive example lists in the StructureDefinition or ValueSet descriptions would not change implementer understanding.

Recommendation:
Keep this audit as-is for FHIR-48713. If the work group later wants a distinct vestigial code, broader DeviceAssociation status modeling changes, or example instances using abandoned, handle that under a new or final follow-up decision rather than reopening this already-applied code addition.
