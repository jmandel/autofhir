FHIR-30085: Audit eld-11 Duration bindability

Issue request:
FHIR-30085 was a Published/Persuasive FHIR-core technical correction for ElementDefinition. It reported that eld-11 allowed bindings only on coded elements, Quantity, string, and uri, so a valid Encounter.length binding on Duration was rejected even though Duration inherits Quantity's bindable-unit behavior.

Initial application:
The issue was applied before this reconciliation. Jira comments point to R4B and R5 pull requests, and git history contains Apply FHIR-30085 commits 842dd13bae and 2a473942da that changed source/datatypes/elementdefinition.xml so eld-11's FHIRPath and XPath forms both include Duration.

Additional context:
source/fhir.ini lists ElementDefinition as an active datatype and normative artifact with the eld abbreviation, so source/datatypes/elementdefinition.xml is build-scope source for eld-11. Later same-invariant work for FHIR-21622 updated eld-11 to exempt non-FHIR/absolute type codes and changed the human text to "if using FHIR-defined types" while preserving Duration in the allowed type list. The original Zulip report matches the Encounter.length validator failure, and the community searches found no Confluence or Zulip evidence that conflicts with the applied source state.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current eld-11 row in source/datatypes/elementdefinition.xml already allows Duration in both the FHIRPath expression and XPath expression, while retaining the later custom-type allowance.

Recommendation:
Keep this no-change audit commit as-is. No follow-up is needed in the current FHIR source for FHIR-30085 unless a future work group decision changes which datatypes are considered bindable.
