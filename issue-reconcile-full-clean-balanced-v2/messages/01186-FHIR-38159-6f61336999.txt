FHIR-38159: Audit vocabulary canonical alignment

Issue request:
FHIR-38159 was a Published, Persuasive with Modification vocab change request for R5. It asked terminology-owned canonical resources to consider CanonicalResource interface updates: optional url for contained resources, versionAlgorithm[x], optional computable name where appropriate, and copyrightLabel. The final resolution specifically required versionAlgorithm[x] and copyrightLabel on CodeSystem, ConceptMap, NamingSystem, and ValueSet, plus mustSupport additions for versionAlgorithm in Shareable profiles and copyrightLabel in Publishable profiles.

Initial application:
Commit c01ed3edbe8a92201a72a348a4daf757fc8c2526, "FHIR-38159 Align Vocab resources w/ canonical changes", is an ancestor of the current source and added versionAlgorithm[x] and copyrightLabel to CodeSystem, ConceptMap, NamingSystem, and ValueSet. The same commit also added the requested mustSupport slices to the then-present Shareable and Publishable profile StructureDefinitions.

Additional context:
Current source/fhir.ini lists CodeSystem, ConceptMap, NamingSystem, TerminologyCapabilities, and ValueSet as active resources, and their current StructureDefinition XML carries the canonical versionAlgorithm[x] and copyrightLabel elements. TerminologyCapabilities, although included in the Jira related-artifact list but not in the final resolution's explicit resource list, was aligned later by commit 8ddfd3dd32 ("Add missing elements from CanonicalResource"). The Shareable/Publishable profile files modified by the original FHIR-38159 commit are no longer current core artifacts: FHIR-37959 was Applied for R6 and directed the Shareable/Publishable/Computable/Executable profiles to be removed from core and maintained in CRMI/THO, with commits 3958dd1e7c and 8c199a9c87 removing the terminology profile definitions from this checkout. Current source/fhir.ini has no active [profiles] entry for the old terminology profile StructureDefinitions.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Re-adding the removed Shareable/Publishable profile files would conflict with the later Applied FHIR-37959 migration, and the authoritative current resource StructureDefinitions already include the canonical elements that FHIR-38159 required for core resources.

Recommendation:
Keep this no-change audit as-is for core. Future work on Shareable/Publishable terminology profile behavior should be handled in the CRMI/THO location identified by FHIR-37959/UP-634 rather than by restoring removed core profile files.
