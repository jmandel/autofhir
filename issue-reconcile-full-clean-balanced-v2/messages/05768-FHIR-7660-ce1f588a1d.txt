FHIR-7660: Audit Encounter discharge diagnoses

Issue request:
FHIR-7660 is a Published/Persuasive Patient Administration DSTU1 issue asking why Encounter.hospitalization.dischargeDiagnosis was only 0..1 and whether additional discharge diagnoses belonged elsewhere, such as Encounter.reason. Its resolution treats the issue as part of the Encounter diagnosis duplicate family and records that reason/indication diagnosis references were constrained while discharge diagnosis was constrained to Condition.

Initial application:
The discharge-diagnosis part of the family was initially applied in git commit 06c7ab8513 for FHIR-7304, changing Encounter.hospitalization.dischargeDiagnosis from 0..1 Reference(Any) to 0..* Reference(Condition). The broader duplicate-family application was completed in git commit 0983925cea, whose message explicitly lists tracker 7660 and related Encounter diagnosis trackers; that commit constrained Encounter.indication from Reference(Any) to Reference(Condition|Procedure), added admission-diagnosis aliases and primaryDiagnosis guidance, and updated examples.

Additional context:
Later final PA decisions intentionally replaced the old DSTU1 representation. FHIR-10544 removed hospitalization.admittingDiagnosis/dischargeDiagnosis and the Encounter-specific diagnosis extensions in favor of an Encounter.diagnosis backbone. FHIR-16148 then redesigned Encounter.reason and Encounter.diagnosis for R5 so reason carries expected reasons/admitting diagnoses and diagnosis carries conditions actually addressed, with billing-related ranking documented on Account. FHIR-19285 added Account.diagnosis.sequence/type for billing diagnoses. FHIR-20484, FHIR-38807, and FHIR-7906 are already represented on the combined branch and support the same conclusion. FHIR-50827 is a current Triaged R6 terminology issue about the Encounter.diagnosis.use value set and is not final enough for this worker to decide or edit.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current active source already satisfies FHIR-7660 at the current specification level. Encounter is active in source/fhir.ini; Encounter.diagnosis is repeatable; Encounter.diagnosis.condition is repeatable and limited to CodeableReference(Condition); Encounter.diagnosis.use carries the role such as admission or discharge; and Account.diagnosis carries billing sequence/type details. Re-introducing the retired hospitalization.dischargeDiagnosis element or applying the 2015 wording literally would contradict later applied PA decisions.

Recommendation:
Keep this no-change audit. Do not reopen the old dischargeDiagnosis element for FHIR-7660; any remaining concern about the diagnosis-use value set should proceed through FHIR-50827 or another current PA/terminology decision, not through this published DSTU1 reconciliation.
