FHIR-17271: Audit FHIRPath polymorphic roots

Issue request:
FHIR-17271 was a Published/Persuasive FHIR-core change request from STU3 asking that the FHIRPath appendix document that an expression root may be a supertype, not only a concrete resource type, so expressions such as Resource.meta match specializations.

Initial application:
The issue appears to have been applied by git-svn commit 8fdac31e0560608aef30d5014be84001f5653a50, whose message names GF#17271 and svn revision 13919. That commit added prose to source/fhirpath.html explaining full resource-name roots and supertype roots, and the Jira comment also records svn revision 13919.

Additional context:
The originating Zulip thread confirms that Resource.meta.lastUpdated search parameters intentionally relied on this polymorphic-root behavior and that the requested text belonged on build.fhir.org/fhirpath.html. The current source still contains Resource-level search parameters using Resource.meta.* expressions, and no Confluence reference or Jira neighborhood search revealed a later conflicting decision for this narrow behavior.

AutoFHIR reconciliation:
No source change was made. The current active FHIRPath source page already says FHIRPath statements can start with a full resource name, that the name can include super types such as DomainResource, and that such statements apply to any resource specializing that supertype; this preserves the implementer-facing rule requested by FHIR-17271.

Recommendation:
Keep this no-change audit commit as-is. Revisit only if FHIR-I wants a more explicit Resource.meta example, since the current normative meaning is already present and additional prose would be redundant rather than corrective.
