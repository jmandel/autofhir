FHIR-19687: Audit Patient merge behavior outside core

Issue request:
FHIR-19687 was a Published PA change request, resolved Persuasive with Modification for R5, asking how searches and patient compartments should behave when a Patient has been linked, merged, or unlinked. The final resolution relied on the PA Merge Operation work: patient linking was expected primarily for cross-system linking, intra-system duplicate handling should follow merge behavior, servers should move data from the old patient to the new patient for merges, the old Patient should be inactive and linked to the new Patient, and search results could include OperationOutcome guidance for in-progress or redirected merge cases.

Initial application:
PA's Merge Operation page and minutes supplied the detailed behavior before source application. Core source was then explicitly changed by 96213161a5, which added source/patient/operationdefinition-Patient-merge.xml, Patient/$merge examples, and the Patient operation list entry, and by 389af0dfa6, which added extended merge usage notes. Merge commit b494aee51b brought those FHIR-19687 changes into the main history.

Additional context:
Patient remains active in the current core build, and source/patient/patient-notes.xml still tells readers there are two approaches, linking and merging. However, the current core build no longer owns the Patient/$merge OperationDefinition page: b487fdda4b removed OperationDefinition/Patient-merge from source/patient/list-Patient-operations.xml and changed core Patient and Parameters links to the Administrative Incubator IG. The old source/patient/operation-Patient-merge-notes.xml file remains in the checkout but is not referenced by current core links or the Patient operation list. Later same-family Patient merge issues, including FHIR-38183, FHIR-38877, and FHIR-38888, have already been represented on the combined branch and support the same build-scope conclusion.

AutoFHIR reconciliation:
This audit commit intentionally makes no core source change. The active core Patient page points to the external Patient/$merge page, and that current external page contains the merge semantics needed for this issue: source and target patients, source inactive/replaced-by handling, reference updates during merge processing, OperationOutcome guidance, and post-merge search expectations. Editing unreferenced legacy core notes or reintroducing a core OperationDefinition would not be a correct current-build fix.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-19687; future normative or trial-use changes to Patient/$merge behavior should be made in HL7/admin-incubator, with core changed only if the external link or high-level Patient-page pointer becomes stale.
