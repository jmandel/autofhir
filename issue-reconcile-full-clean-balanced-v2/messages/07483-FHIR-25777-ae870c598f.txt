FHIR-25777: Audit SDF-11 logical model exclusion

Issue request:
FHIR-25777 was a Published FHIR-core StructureDefinition change request, resolved Persuasive and applied for R5, asking to apply the FHIR-13331 SDF-11 logical-model exclusion to STU3 because STU3 still had the unguarded expression while R4 already excluded logical models.

Initial application:
No source commit explicitly mentioning FHIR-25777 was found. The underlying FHIR-13331 change was applied earlier by git commit 55ebc20f189e7dd4efc817a098fd7c82386b2a43, which changed SDF-11 from `snapshot.empty() or snapshot.element.first().path = type` to `kind != 'logical' implies snapshot.empty() or snapshot.element.first().path = type` in the StructureDefinition spreadsheet source. Later source rework carried the guarded expression into the active XML StructureDefinition source.

Additional context:
FHIR-13331 is the same change family and records that the issue was marked applied for STU3 even though a later comment says it was actually fixed in R4, not STU3. FHIR-I WGM 2020-01 minutes record that FHIR-13331 was applied in R4 but not R3 and that FHIR-25777 was raised and approved to correct that mismatch. In the current source tree, source/fhir.ini lists StructureDefinition as an active resource in the conformance work group with first normative version 4.0.0, and source/structuredefinition/structuredefinition-StructureDefinition.xml already has the guarded SDF-11 expression. The checked-in tools/history/release3/profiles-resources.xml still contains the old STU3 expression, but source/fhir.ini has no active reference to tools/history/release3 and this reconciliation should not rewrite out-of-build historical release artifacts for a current-build audit.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current StructureDefinition source already satisfies the WG-approved logical-model exclusion, and changing the stale STU3 history artifact would not be a current FHIR build fix.

Recommendation:
Keep this no-change audit commit as-is for current FHIR core. If HL7 wants to republish or patch STU3 historical artifacts, handle that as a separate human-directed historical-publication task rather than a current source correction.
