FHIR-13484: Audit ElementDefinition structure links

Issue request:
FHIR-13484 was a Published/Persuasive STU3 FHIR-core enhancement asking for a way to jump from the ElementDefinition datatype page to the relevant StructureDefinition, with a broader note to link datatypes to their structure definitions where possible.

Initial application:
The issue was applied in svn revision 12701, preserved in git as 9b7676f20ab48f8536bf97a93337ab365865cc4c (#13484 - add missing link), which added the ElementDefinition usage line using [%dtusage ElementDefinition%] to source/elementdefinition.html.

Additional context:
ElementDefinition remains an active datatype and has an active type-page mapping in source/fhir.ini. The current source still contains the applied usage macro, and current build.fhir.org rendering expands it to a direct StructureDefinition link. Primitive datatypes on datatypes.html also expose XML/JSON definition links, while complex datatype structure tables expose XML/JSON Definition links, so the current build already satisfies the practical navigation request. Quoted Zulip and Confluence searches found no conflicting community decision.

AutoFHIR reconciliation:
No source change was made. This empty audit commit records that the current built specification already provides the ElementDefinition-to-StructureDefinition navigation and datatype definition links relevant to the Published Jira decision.

Recommendation:
