FHIR-13895: Audit pertainsToGoal extension rename

Issue request:
FHIR-13895 was Published with resolution Persuasive with Modification for the STU3 core issue that the goal-pertainsToGoal extension name implied a Goal-only scope even though the extension applies at Resource level. The approved change was to move the extension to the Resource extension spreadsheet so it would be renamed resource-pertainsToGoal, with updated wording explaining that the resource relates to measurement, achievement, or progress toward the referenced Goal.

Initial application:
The source history shows explicit application in git commit 44fb1e203e958046ffed413179eb2fb5e23c2fce, whose subject says it moved goal-pertainsToGoal to resource-pertainsToGoal and updated the CarePlan extension link. That commit changed the CarePlan source reference, removed the extension row from the Goal extension spreadsheet, and added it to the Resource extension spreadsheet with the Jira resolution wording.

Additional context:
Current core source no longer owns most extension definitions directly: source/history.html states that all extensions moved to the hl7.fhir.uv.extensions package. The FHIR Extension Pack checkout contains the active StructureDefinition-resource-pertainsToGoal definition with id/url/fixedUri resource-pertainsToGoal, context Resource, and the requested description. A later FHIR-extensions issue, FHIR-44770, corrected that externalized extension title from ServiceRequest Pertains To Goal to Resource Pertains To Goal; current core references in Goal notes, CarePlan activity comments, and the OID registry all use resource-pertainsToGoal. Community searches found the application bot notification and later usage/context discussions but no contrary decision for the STU3 rename.

AutoFHIR reconciliation:
This is an empty no-change audit commit. The current core build-scope sources already reference resource-pertainsToGoal, the old goal-pertainsToGoal URL is absent from current core source outside historical release archives, and the authoritative extension definition now lives in the extension-pack checkout with the Resource-scoped canonical name and wording.

Recommendation:
Keep this audit commit as-is. No FHIR-core source edit is needed for FHIR-13895; any future changes to the extension definition itself should be made in the FHIR Extension Pack rather than by reintroducing a core extension spreadsheet entry.
