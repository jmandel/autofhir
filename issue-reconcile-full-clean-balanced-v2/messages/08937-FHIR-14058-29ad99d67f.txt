FHIR-14058: Audit RequestIntent directive support

Issue request:
FHIR-14058 was Published/Persuasive for STU3 and asked to add a "directive" code to the Request Intent value set so request resources could represent advance-directive-like request intent. The accepted resolution defined directive as a legally binding instruction authored by a Patient or RelatedPerson, distinguishing it from orders by author and from plans/proposals by legal force.

Initial application:
The issue was applied before this reconciliation. Upstream commit 633021569c4ee210837d89828831cac8764c69bd added the directive row to source/request/request-spreadsheet.xml, and Jira records the associated merge commit as 6b8ca9c61f024e704d55572b18f714219baf58b3. The current source retains directive in the RequestIntent CodeSystem, and the Request Intent ValueSet includes that whole code system, so directive is in the value set. No prior Issue-Reconcile-Key commit for FHIR-14058 was present on the combined branch.

Additional context:
Later final decisions refine but do not remove this seed change. FHIR-48347 was Applied/Persuasive for R6 and deliberately removed "legally binding" from the directive definition because enforceability varies by jurisdiction and context; that issue is already represented on the combined branch by e9784dc5f56b098d803458123e60e0aff234ba46. FHIR-52001 was Resolved - No Change/Not Persuasive in 2025 and explicitly concluded that directive remains a valid ServiceRequest intent. Zulip and Confluence searches found only the original tracker bot notice and later non-conflicting directive-use discussions, with no direct evidence that the seed change should be reversed.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current RequestIntent source already contains code directive with the later-approved definition "The request represents an instruction authored by a Patient or RelatedPerson.", and source/request/valueset-request-intent.xml includes http://hl7.org/fhir/request-intent so the code is exposed through the Request Intent value set.

Recommendation:
Keep this empty audit commit as-is. No additional core FHIR source work is needed for FHIR-14058; future changes to directive semantics should proceed through new tracker decisions such as the already-audited FHIR-48347 or any later work-group action.
