FHIR-14475: Audit datatype JSON templates

Issue request:
FHIR-14475 was Published/Persuasive for STU3 and asked that the JSON Template for Address, ContactPoint, HumanName, and Timing remove the confusing "resourceType" element because those artifacts are datatypes rather than resources.

Initial application:
The Jira comment identifies svn revision 13057. In the git-svn history, commit d24d7a6ff7d41be72c3c1daa463fc4c06b805968 is that revision and is titled "#14475 - fix JSON templates". It changed the historical JsonSpecGenerator so "resourceType" was emitted only when the root name was a resource or Parameters, rather than for arbitrary datatype templates. The historical generator source is no longer present in the current checkout, so there is no current generator file to edit for this reconciliation.

Additional context:
Address, ContactPoint, HumanName, and Timing remain active current datatypes in source/fhir.ini, and their current spreadsheet sources do not define a resourceType child. The datatype source pages use the current datatype generation macros, and a combined-branch grep over the datatype page and the four datatype spreadsheet sources found no resourceType occurrence in those templates; the only nearby datatype-page occurrence is a ValueSet example in datatypes-examples.html, which is unrelated because ValueSet is a resource. Jira neighborhood searches found only FHIR-14475 for this exact issue, and Zulip/Confluence searches found no human discussion or later conflicting decision.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The requested correction was already applied historically by the JSON template generator fix, and the current source/combined branch does not contain the offending datatype-template resourceType entries.

Recommendation:
Keep this no-change audit commit as-is. No current FHIR core source edit is needed; future generator work should preserve the rule that resourceType appears on resource JSON templates, not on ordinary datatype templates.
