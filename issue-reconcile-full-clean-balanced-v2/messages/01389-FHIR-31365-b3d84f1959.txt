FHIR-31365: Audit MedicationKnowledge packaging cardinalities

Issue request:
FHIR-31365 was a Published/Persuasive Pharmacy change request for R5 asking that MedicationKnowledge.packaging.identifier and MedicationKnowledge.packaging.cost be changed to 0..*. The requester clarified that repeated packaging cost was the key need, with repeated packaging identifiers requested for consistency with common FHIR identifier usage.

Initial application:
The issue was applied before this reconciliation by commit 7453f87bfcb5eeba6020113412508cb95e5d4f0a, whose subject includes FHIR-31365 and whose MedicationKnowledge source diff changed both MedicationKnowledge.packaging.identifier and MedicationKnowledge.packaging.cost from max 1 to max *.

Additional context:
FHIR-26536 is the same MedicationKnowledge packaging change family and had already added repeatable packaging plus packaging-specific cost and identifier concepts. Later MedicationKnowledge source refactoring removed the inline MedicationKnowledge.packaging.identifier element and replaced the detailed package description with MedicationKnowledge.packaging.packagedProduct, a reference to PackagedProductDefinition. In the current build, source/fhir.ini actively includes both MedicationKnowledge and PackagedProductDefinition, MedicationKnowledge.packaging.cost remains 0..*, and PackagedProductDefinition.identifier is 0..*, preserving the ability to carry multiple business identifiers for the package in the current model.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding MedicationKnowledge.packaging.identifier would undo the current PackagedProductDefinition-based package model, while the substantive FHIR-31365 requirements are already represented by repeated packaging cost and repeated identifiers on the referenced package definition.

Recommendation:
Keep this audit commit as-is. If Pharmacy wants an inline MedicationKnowledge.packaging.identifier in addition to PackagedProductDefinition.identifier, that would be a new modeling decision rather than an unapplied FHIR-31365 fix.
