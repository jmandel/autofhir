FHIR-31356: Audit coding copy links

Issue request:
FHIR-31356 was a Published/Persuasive FHIR-I enhancement request to add quick links for copying Coding snippets from value-set and code-system terminology enumerations. The approved resolution characterized it as a nice-to-have IG-authoring aid and explicitly left feasibility and usability to the tooling implementer.

Initial application:
The issue appears to have been applied by Grahame's 2022-08-29 source commit 3c14d8332bfdbe37e581f52573d53f44e9b435f0, which added the JSON and XML clipboard icon assets used by terminology rendering. Nearby tooling work in ab3a27bc56c3d212b592f187e9438b3e2a41339d had already added the ClipboardJS assets, copy-button styling, and URL copy support for terminology templates.

Additional context:
The FHIR repository currently contains the clipboard assets and template support, while the generated per-code terminology rows are produced by external rendering tooling rather than editable core source. Current build.fhir.org CodeSystem pages use icon_clipboard_x.png and icon_clipboard_j.png to copy XML and JSON Coding fragments for individual concepts. Representative ValueSet expansion pages checked during reconciliation did not show per-row Coding copy buttons, but the Jira resolution was conditional on tooling feasibility and no FHIR source file in this checkout controls that renderer behavior.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Core source already carries the assets and helper support that were applied for this issue, and adding speculative client-side logic or duplicating renderer behavior in templates would be a risky tooling change outside the authoritative source surface for this repository.

Recommendation:
Keep this no-change audit as-is for the FHIR core reconciliation. If the work group still wants copy buttons on ValueSet expansion rows in addition to CodeSystem concept rows, handle that as a follow-up in the IG Publisher/rendering tooling with a fresh usability decision rather than as a FHIR core source correction.
