FHIR-17549: Audit modifier-free profile tooling handoff

Issue request:
FHIR-17549 was a Published/Persuasive with Modification FHIR-core request to let an ImplementationGuide or StructureDefinition declare a modifier-extension-free or closed-profile zone. The original accepted text proposed a no-modifiers ImplementationGuide definition parameter and a closedProfile extension on ImplementationGuide.definition.resource, with guidance on the consequences of using those flags.

Initial application:
No FHIR-core commit mentioning FHIR-17549 was found, and pickaxe searches for noModifiers, closedProfile, and modifier-extension-free wording did not find an implementation in current core source. The current active ImplementationGuide resource remains in build scope, but its definition.parameter element is deliberately generic and tool-specific, bound extensibly to guide-parameter-code and commented to point to the external HL7 IG Publisher parameter documentation.

Additional context:
Later Jira comments and FHIR-I WGM minutes changed the application path: the work group recorded that both requested mechanisms would be handled through the IG Tooling IG rather than in the core spec, and Lloyd McKenzie logged the follow-up as HL7/fhir-ig-publisher#648. That external issue is still open and carries the concrete noModifiers/closedProfile wording and guidance. Searches of current core source, the FHIR Extension Pack checkout, Zulip, and high-signal Confluence content found no conflicting current core implementation requirement.

AutoFHIR reconciliation:

Adding core ImplementationGuide elements, core parameter codes, or a core extension now would contradict the later work-group handoff and duplicate work tracked externally.

Recommendation:
