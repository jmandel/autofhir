FHIR-16429: Audit Patient merge STU note removal

Issue request:
FHIR-16429 is a Published/Persuasive PA change request raised against STU3 Patient. It asked whether a normative Patient merge section should still solicit feedback through an "STU Note"; the final disposition said to change "STU Note" to "Note" while retaining a generic implementer-warning statement about merge behavior still being subject to implementation experience.

Initial application:
The issue was initially applied by commit 9f6368a72b059519d4815117b24eecd8a46d0481, titled "GF#16429 patient merge notes". That commit changed the Patient merge block from "STU Note" to "Note", reworded the feedback questions, added the patient-compartment question that later became FHIR-17487's focus, and kept the warning that linking/merging/unlinking behavior was subject to ongoing experimentation and future specification work.

Additional context:
Later Patient merge work superseded the old note rather than preserving it verbatim. FHIR-38183 updated the Patient narrative for R5 so the active Merging Records section points readers to the Patient $merge operation instead of carrying the old announcement/feedback note. Current core subsequently removed Patient $merge from the Patient operation list and links the merge guidance to the external Admin Incubator operation. The tracked source/patient/operation-Patient-merge-notes.xml file still contains several stu-note macros, but the core OperationDefinition/Patient-merge source was deleted and the active Patient operation list now includes only $match and $purge, so those old merge-operation notes are not a current core Patient build-scope fix for this STU3 narrative issue. FHIR-17487 is the tightly related patient-compartment note issue and is already represented on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active Patient narrative no longer contains the normative-section "STU Note" that FHIR-16429 targeted, and the later build-scope source either links to the external merge operation or carries the resolved compartment semantics in source/compartments.xml.

Recommendation:
Keep this audit commit as-is. Do not edit orphaned core Patient $merge note fragments for FHIR-16429; if future work changes the externally hosted Admin Incubator $merge operation, review that IG/source directly.
