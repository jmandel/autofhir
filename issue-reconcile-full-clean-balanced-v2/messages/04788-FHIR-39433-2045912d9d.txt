FHIR-39433: Audit CapabilityStatement implementationGuide guidance

Issue request:
FHIR-39433 was a Published FHIR-core change request with resolution Not Persuasive with Modification. It asked whether IPA's guidance should be reflected in base FHIR for CapabilityStatement.implementationGuide and CapabilityStatement.instantiates; the final FHIR-I decision rejected the IPA interpretation that implementationGuide means all of an IG while instantiates means partial support, and instead required a clarifying note on CapabilityStatement.implementationGuide.

Initial application:
FHIR-30587 had already added a terse usage note saying implementationGuide is mainly for IGs without role-specific CapabilityStatements and that instantiates should identify supported roles. The Jira-tagged source commit 92f8ebd5cf32bb1e6d497a86b5bb3e8306e3aef3 then applied FHIR-39433 by replacing that note with the current, fuller clarification in source/capabilitystatement/structuredefinition-CapabilityStatement.xml.

Additional context:
source/fhir.ini lists CapabilityStatement as an active resource, so the checked StructureDefinition source is in current build scope. The IPA-origin issue FHIR-35321 explains why IPA was using instantiates rather than implementationGuide, and the later FHIR-core issue FHIR-42975 was resolved No Change because CapabilityStatement.implementationGuide already says it is not for IG-defined CapabilityStatements; actor-specific discovery was handled separately by FHIR-43899.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active CapabilityStatement.implementationGuide comment already says that implementationGuide asserts adherence to IG-level global definitions and textual requirements, does not assert conformance to CapabilityStatements defined in the IG, and that CapabilityStatement.instantiates is required to assert conformance to those CapabilityStatements.

Recommendation:
Keep this audit commit as-is. No further FHIR-core source change is needed for FHIR-39433; any additional IPA-specific conformance guidance belongs in the IPA specification, while actor-specific CapabilityStatement discovery is covered by later ActorDefinition work rather than by changing implementationGuide.
