FHIR-14759: Audit AdverseEvent subject requirement

Issue request:
FHIR-14759 was a Published, Persuasive with Modification Patient Care change request from the STU3 ballot asking why AdverseEvent.subject could be omitted and why it could reference a group. The accepted resolution was to add the requirement "Allows for exposure of biohazard (such as legionella) to a group of individuals in a hospital" and to rely on the linked GF#13893 change that made AdverseEvent.subject mandatory.

Initial application:
GF#13893 was applied in git commit 1051f7d9e9, changing the legacy AdverseEvent.subject cardinality from 0..1 to 1..1 and removing the old prospective-event wording that allowed no subject. GF#14759 was applied in git commit b88fc91916, adding the biohazard/group requirement to the spreadsheet source that later fed the current generated StructureDefinition source.

Additional context:
AdverseEvent is active in source/fhir.ini and marked normative. The current source/adverseevent/structuredefinition-AdverseEvent.xml keeps AdverseEvent.subject at 1..1, includes Group among the allowed targets, carries the exact biohazard/legionella requirement, and retains guidance to use Patient when resulting effects differ among group members. Later related Jira FHIR-54065 is still Triaged and asks a different R6 question about adding CareTeam or Organization, so it does not supersede this applied STU3 decision. Broader Zulip and Confluence searches found AdverseEvent subject/group discussion but no final community evidence contradicting the current source.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change because the current build-scope AdverseEvent definition already implements both parts of the FHIR-14759 resolution: mandatory subject and the documented group/biohazard rationale.

Recommendation:
Keep this no-change audit commit as-is. Do not add duplicate prose elsewhere; if FHIR-54065 or later work-group action changes the set of subject target types, handle that as a separate R6 decision.
