FHIR-34155: Clarify search safety SearchParameter checks

Issue request:
FHIR-34155 was Published/Persuasive for R5 and asked that the Search Related Safety Checks for clients say search string meanings cannot be trusted across servers and clients must check both the server CapabilityStatement and SearchParameter definitions.

Initial application:
Commit bacf6ea51e74b27baf81dad7a1e064fa6fee2f77 added a search-param-names checklist item to source/safety.html, but the text only told clients to check CapabilityStatement search parameter and operation names for local renames. It did not carry forward the issue's SearchParameter-definition meaning check. The later active safety CodeSystem source did not include the search-param-names concept at all.

Additional context:
The issue came from the Zulip implementers SearchParameter expectation thread where Lloyd McKenzie explained that clients must not infer a search parameter's semantics from its name alone and should use the declared CapabilityStatement URL/SearchParameter definition. Current CapabilityStatement source also says behavior can be described by linked SearchParameter definitions and that CapabilityStatement searchParam.name may differ from SearchParameter.code. source/fhir.ini actively includes codesystem/codesystem-safety-entries.xml as the safety-entries CodeSystem, so the checklist and its formal CodeSystem representation both need to carry the safety check. FHIR-34234 is related background for operation-name wording; this commit preserves that operation-name guidance while deciding only FHIR-34155.

AutoFHIR reconciliation:
Updated source/safety.html so the search-param-names safety checklist item tells clients to check the HTTP server's CapabilityStatement and referenced SearchParameter definitions to understand the names and meanings of search parameters. Added the corresponding search-param-names concept to the active safety-entries CodeSystem source.

Recommendation:
Keep this source fix. It completes the published FHIR-34155 clarification in the current build-scope narrative and CodeSystem sources without broadening into separate operation-definition or search paging checklist work.
