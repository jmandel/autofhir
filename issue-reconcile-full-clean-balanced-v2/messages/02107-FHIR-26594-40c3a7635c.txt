FHIR-26594: Audit MedicationRequest doNotPerform definition

Issue request:
FHIR-26594 was Published/Persuasive for R5 and asked Pharmacy to replace the MedicationRequest.doNotPerform definition with language saying that a true value means the provider is asking the patient to stop taking or not start taking the specified medication, including an example involving separate stop/start requests.

Initial application:
The change was initially applied by 7e6805e893 and merged by 400a4e8622 in June 2020, changing source/medicationrequest/medicationrequest-spreadsheet.xml from the older "medication request not to occur" wording to the requested stop-or-not-start wording. The current build no longer uses that spreadsheet as the authoritative element source; source/fhir.ini actively lists medicationrequest=MedicationRequest and current element text is in source/medicationrequest/structuredefinition-MedicationRequest.xml.

Additional context:
Later Applied Pharmacy issue FHIR-47856 intentionally replaced the FHIR-26594 definition for R6 with the current wording, adding that .reason carries the reason and that doNotPerform does not itself update other MedicationRequests. Later Applied Pharmacy issue FHIR-51848 added detailed doNotPerform comment examples, so the current source still gives implementers concrete examples while reflecting newer work-group intent. FHIR-15941 is the earlier background issue that added doNotPerform to align MedicationRequest with the Request pattern. A checked-in medicationrequest.svg tooltip still contains the older FHIR-26594 text, but that is a generated-looking diagram artifact; the authoritative XML source has the current definition and the run guardrail says not to edit such artifacts as a standalone source fix.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current active MedicationRequest StructureDefinition already conveys the correct post-FHIR-26594 semantics after later Applied decisions: doNotPerform means the provider is ordering that the patient should not take the specified medication, .reason can explain why, no dispense/administration should result, and examples clarify how qualifiers narrow what is not to be done.

Recommendation:
Keep this audit commit as-is. If generated diagrams are refreshed in a separate publication/build process, medicationrequest.svg should be regenerated from the authoritative source rather than manually edited for FHIR-26594.
