FHIR-17709: Audit multiple source element support

Issue request:
FHIR-17709 was a Published/Persuasive FHIR-core FHIR-I change request asking to allow more than one source element in a FHIR Mapping Language rule. The Jira description says the mapping-language page already indicated that a rule may take one or more source elements, but the FHIR Transformation engine did not support it; the later Jira comment classified any remaining gap as a tooling issue for the HAPI/org.hl7.fhir.core implementation rather than a core specification defect.

Initial application:
No git commit was found that explicitly mentions FHIR-17709. The relevant mapping-language source had already been reworked by commit 1982a32c0578897ed621e9ee8a7e1bf74198c295 in December 2018 to state that source content may use one or more comma-separated source statements and to describe the permutation behavior for multiple source statements.

Additional context:
The current source/mapping-language.html file is active build content: publish.ini lists mapping-language.html and source/hierarchy.xml places it under Implementation Support. The StructureMap resource is active in source/fhir.ini, and StructureMap.group.rule.source has cardinality 1..*, matching multiple source inputs at the abstract syntax level. FHIR-25376 is the closest later same-family issue; it clarified the all/AND behavior for multiple source statements, was applied by commit 0646c3096026cde98eca996d111806e36ed14572, and is already represented on the combined branch by Issue-Reconcile-Key: FHIR-25376.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already says that source content is formed by one or more source statements separated by commas, gives `[source], [source] -> ...` as the syntax, states that multiple source statements are evaluated as permutations, and says all source statements need to match. The remaining concern recorded in FHIR-17709 is implementation support outside this specification checkout.

Recommendation:
Keep this audit commit as-is. No core FHIR source change is needed for FHIR-17709; if an implementation still rejects multiple source statements, track that in the implementation repository named in the Jira comment.
