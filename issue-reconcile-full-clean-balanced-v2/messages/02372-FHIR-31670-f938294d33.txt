FHIR-31670: Audit RelatedPerson relationship type value set

Issue request:
FHIR-31670 was Published/Persuasive with Modification for R5 and asked PA to expand the RelatedPerson relationship/role value set for non-practitioner roles such as witness and notary. The accepted resolution listed explicit concepts for relatedperson-relationshiptype: WIT from v3 ParticipationType; NOT, ECON, NOK, GUARD, DEPEN, EMP, GUAR, and CAREGIVER from v3 RoleClass; E, O, and U from v2-0131; and INTPRTER, POWATT, DPOWATT, HPOWATT, SPOWATT, and BILL from v3 RoleCode.

Initial application:
The issue was applied by git commit 72509ce0dc5f3f68d554d50f4620eb953a7aaf67, which replaced the prior broad RoleCode filter in source/relatedperson/valueset-relatedperson-relationshiptype.xml with the explicit concept list from the resolution. No prior Issue-Reconcile-Key commit for FHIR-31670 was present on the combined branch.

Additional context:
FHIR-15841 is the same change family and was later applied by commit 23f3b0abec5678767e3cc7e4b576fdbd3e3b9fb2. That later source change split personal relationships from functional roles: RelatedPerson.relationship now binds to v3 PersonalRelationshipRoleType, while RelatedPerson.role and Patient.contact.role bind with preferred strength to relatedperson-relationshiptype. This explains why the current binding strength/location differs from FHIR-31670's earlier restructuring text. FHIR-31380 later resolved no-change and cited FHIR-31670 as making the value set an indicative, non-exhaustive set. Confluence minutes confirm the PA vote and later process discussion; Zulip searches found no conflicting discussion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active RelatedPerson source is in build scope via source/fhir.ini, and source/relatedperson/valueset-relatedperson-relationshiptype.xml currently contains all 18 requested explicit concepts. The current RelatedPerson and Patient contact bindings reflect the later FHIR-15841 decision, so reverting the value set to relationship-only use or changing preferred binding strength would be incorrect.

Recommendation:
Keep this no-change audit. Future requests for additional jurisdiction- or program-specific RelatedPerson roles should be handled as separate PA/terminology decisions or in IG-specific value sets unless the base indicative set is again deliberately expanded.
