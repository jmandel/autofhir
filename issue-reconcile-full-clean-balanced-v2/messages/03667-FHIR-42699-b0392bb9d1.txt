FHIR-42699: Audit Questionnaire URL guidance

Issue request:
FHIR-42699 was an Applied/Persuasive FHIR-core Questionnaire clarification asking when Questionnaire.url may be absent. The approved resolution says Questionnaire.url SHOULD always be populated unless the Questionnaire is contained, in which case the containing resource can point to it by contained id, for example QuestionnaireResponse.questionnaire using '#[ContainedQuestionnaire.id]'.

Initial application:
The issue was applied on master by 98785ab073938bab639758c01a9bb7d6c0d7e40e, which added the requested guidance to source/questionnaire/structuredefinition-Questionnaire.xml. The same evening, 7ad13b103ce1c992a5b4cd8ec08c255b73db7a8d propagated the same Questionnaire.url comment into source/questionnaire/questionnaire-definition-mapping-exceptions.xml as QA cleanup.

Additional context:
Questionnaire is an active current-build resource in source/fhir.ini. The 2023 SDC minutes and linked Zulip discussion record the problem that QuestionnaireResponse.questionnaire is mandatory while Questionnaire.url is optional, with the agreed answer that a contained Questionnaire can be referenced by '#[id]'. A 2025 Zulip note briefly proposed re-opening FHIR-42699, but Lloyd McKenzie immediately corrected that he had confused himself and said no discussion was needed. Related SDC issue FHIR-25434 also supports omitting Questionnaire.url for contained adaptive Questionnaires and using QuestionnaireResponse.questionnaire '#[id]', but its outstanding search-parameter work is a different, not-Applied FHIR-sdc/core follow-up and is not decided here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active Questionnaire StructureDefinition already says Questionnaire.url SHOULD always be populated unless the Questionnaire is contained and then pointed to by the containing resource using id rather than url; the mapping exception source also carries the same text. Adding or rewriting prose would not change implementer understanding for FHIR-42699.

Recommendation:
Keep this no-change audit commit as-is for FHIR-42699. If the FHIR-sdc FHIR-25434 search-parameter follow-up is later brought into a core reconciliation run, evaluate it separately; it does not require changing the Questionnaire.url guidance audited here.
