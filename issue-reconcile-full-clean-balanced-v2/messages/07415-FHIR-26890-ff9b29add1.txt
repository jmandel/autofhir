FHIR-26890: Audit messaging event wording

Issue request:
FHIR-26890 was Published/Persuasive with Modification for R5. It requested replacing the outdated Defining Events sentence that said the message.code element carries a Coding with text saying MessageHeader.event[x] identifies the event, and additionally recorded that MessageHeader.eventUri should become MessageHeader.eventCanonical with type canonical.

Initial application:
The issue was applied by d64b767e8c, which changed source/messaging.html to name MessageHeader.event[x] and changed MessageHeader.event[x] from uri to canonical(EventDefinition). The current messaging page still contains the corrected MessageHeader.event[x] sentence.

Additional context:
MessageHeader is an active current-build resource in source/fhir.ini, and the messaging narrative is active source for the FHIR-core messaging page. Later FHIR-39635 work, already represented on the combined branch, intentionally harmonized MessageHeader.event[x] and MessageDefinition.event[x] as Coding | uri | canonical(EventDefinition, SubscriptionTopic). That later decision explains the current presence of both uri and canonical on MessageHeader.event[x], so removing uri now would conflict with later applied R6 messaging work rather than complete FHIR-26890.

AutoFHIR reconciliation:
No source change was made. The current source already contains the corrected Defining Events sentence, includes canonical event references, and reflects the later approved event type harmonization.

Recommendation:
Keep this audit commit as-is. No FHIR-26890 source follow-up is needed unless the work group reopens the later FHIR-39635 event type policy.
