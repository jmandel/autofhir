FHIR-16131: Audit quantity precision extension

Issue request:
FHIR-16131 was Published with resolution Persuasive with Modification. It requested a Quantity precision attribute; the final decision was to define an extension for explicit precision to prevent loss when converting to and from non-FHIR representations, while keeping FHIR calculations and rendering driven by the implicit precision of the represented decimal value.

Initial application:
The issue was applied in the old core source by svn/git history around 2018-07-29. Git commit a5c90c3db3cc added the active fhir.ini quantity-extensions profile entry as part of GF#16131, and the immediately following build-fix commit e20e51a90b11 added source/datatypes/quantity-extensions-spreadsheet.xml with a precision row describing explicit precision, information-loss prevention, and the rule that rendering/calculation still uses the raw decimal value.

Additional context:
Core later removed extension definitions from the R5 source in dd468d4f1799, including the quantity-precision spreadsheet row, as part of the source move to the FHIR Extension Pack. The current Extension Pack contains StructureDefinition/quantity-precision with the canonical URL http://hl7.org/fhir/StructureDefinition/quantity-precision, active status, Quantity and decimal contexts, integer value, and the same conformance note. FHIR-51527 later published an extension-pack decision to update quantity-accuracy, quantity-confidenceInterval, and quantity-precision to apply to all Quantity, implemented by 71bc7cdfe775. Current core source still says Quantity.value carries implicit precision and the JSON decimal page links to the precision extension through [%extensions-location%]. No Confluence reference or FHIR-16131-specific Zulip discussion was found; a later implementers Zulip thread confirms the extension and JSON precision guidance are the relevant current references.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core checkout no longer owns the extension definition, and the authoritative Extension Pack source already contains the explicit precision extension requested by FHIR-16131. Adding a duplicate core extension or redundant Quantity prose would conflict with the current source split and would not improve implementer understanding.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed for FHIR-16131; any future semantic change to quantity-precision should be made in the FHIR Extension Pack and accompanied by any necessary core cross-reference update.
