FHIR-41613: Audit DocumentReference DICOM guidance

Issue request:
FHIR-41613 is an Applied/Persuasive with Modification OO change request for DocumentReference guidance on representing DICOM-derived images, including rendered/non-rendered images, WADO access, DICOM identifiers, and possible ImagingStudy or ImagingSelection context. The accepted modification asked the resource editor to add a Notes section entry and a Boundary/Relationship pointer rather than a separate mapping-table design.

Initial application:
The DICOM Boundary/Relationship paragraph was first introduced by the earlier FHIR-38950 DocumentReference boundary work. FHIR-41613 was then applied through HL7/fhir PR #3020, whose body lists FHIR-41613 and "indicators to relationship to imaging resources"; commit 97cf6bb0ede5497d006a53d90f53c1cc2b41248f added ImagingSelection to the DICOM boundary paragraph and added the current Notes bullet for rendered DICOM images and ImagingStudy/ImagingSelection references.

Additional context:
The originating Zulip thread shows the practical question was how to represent a DICOM image now that Media was merged into DocumentReference, and the OO WGM minutes record the modified disposition: prefer ImagingStudy/ImagingSelection for richer imaging context, use DocumentReference only for limited rendered-image cases, and place the guidance in Notes/Boundaries. Current ImagingStudy and ImagingSelection boundary text also points back to DocumentReference only for non-DICOM media or rendered DICOM images where full image context is not needed.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. DocumentReference is active in source/fhir.ini, and the current source already includes the requested DICOM/WADO boundary guidance, the Notes bullet tying rendered DICOM images to ImagingStudy or ImagingSelection, and a DICOM example with study/series/instance identifiers and a WADO URL. Adding a separate mapping table or more prescriptive prose would go beyond the accepted modified resolution and could conflict with the ImagingStudy/ImagingSelection boundary guidance.

Recommendation:
Keep this audit commit as-is. Future work should only revisit this area if OO/II decide to add a formal profile or mapping table for a narrower DICOM-image use case; the current core source is adequate for the applied FHIR-41613 resolution.
