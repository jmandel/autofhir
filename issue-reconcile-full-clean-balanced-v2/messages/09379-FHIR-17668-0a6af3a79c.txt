FHIR-17668: Audit decimal implicit range documentation

Issue request:
FHIR-17668 was Published/Persuasive for FHIR-core search documentation. It asked the Search page to state that decimal searches involve an implicit range, and that the implicit range's significant digits are the digits specified in the search parameter value excluding leading zeros, so 100 and 1.00e2 both have three significant digits.

Initial application:
The issue was applied by git commit 7f7f00d8e9fbee429ee41d10f4c2332de814516a, "GF#17668 - note about decimal range", which added the requested note to source/search.html. Later page movement preserved the note in the number-search section.

Additional context:
source/hierarchy.xml lists source/search.html as the active Search page under RESTful API. Later Published issue FHIR-26311 intentionally narrowed the first sentence from "Searching on decimals involves an implicit range" to "Searching on decimals without using one of the comparisons listed in the earlier bullet involves an implicit range"; that clarification is part of the correct current text. FHIR-30096 corrected the neighboring 1e2 example and the related Zulip "Significant figures" thread confirms that FHIR treats 100 as three significant digits for this search rule. Direct Zulip and Confluence searches for FHIR-17668 found no conflicting community record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source/search.html already contains the requested significant-digit rule, including the 100 and 1.00e2 example, with the later FHIR-26311 comparison-prefix clarification preserved.

Recommendation:
Keep this no-change audit commit as-is. No further core source work is needed for FHIR-17668 unless the work group later revisits decimal implicit precision semantics.
