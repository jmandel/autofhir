FHIR-37368: Audit primitive regex alignment

Issue request:
FHIR-37368 was a Published FHIR-core datatypes issue resolved Persuasive for R5. It reported mismatches between the primitive datatype regexes shown on the datatypes page and the computable/package representation: integer was missing on the page, uri/url/canonical needed regex exposure in the computable representation, positiveInt was wrong on the page, and markdown differed between page and package with markdown allowed to start with whitespace.

Initial application:
Commit 3ef54c37a52ed2d27ea04d457899585052cd4b1f explicitly applied FHIR-37368 by updating `source/datatypes.html` and `source/datatypes/primitives.xml`: it added page regex text for integer, url, and canonical, corrected positiveInt to `[1-9][0-9]*`, preserved `\S*` for uri/url/canonical in the primitive spreadsheet, and aligned markdown with the computable representation available at that point. Later source cleanup changed the datatypes page to use `[%regex ...%]` macros, so the rendered page now comes from the same primitive regex source instead of hard-coded literals.

Additional context:
The current build-scoped datatype sources are active through `source/fhir.ini`, including the `DataType` and `PrimitiveType` infrastructure entries and the datatypes page. Current `source/datatypes/primitives.xml` has regex rows for integer (`[0]|[-+]?[1-9][0-9]*`), uri/url/canonical (`\S*`), positiveInt (`[1-9][0-9]*`), and markdown (`^[\s\S]+$`), while `source/datatypes.html` references each of those through `[%regex ...%]` macros. The later Published issue FHIR-40563, already represented on the combined branch, clarified that string and markdown should share the safer `^[\s\S]+$` expression rather than a literal `^.+$`, so the current markdown regex is intentional rather than a remaining FHIR-37368 mismatch. FHIR-I WGM minutes record the original 14-0-0 persuasive vote, and no directly relevant Zulip or additional Confluence conflict was found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already satisfies the FHIR-37368 request, and changing it would either duplicate generated macro behavior or conflict with the later FHIR-40563 clarification for markdown.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-37368 unless a future work group decision changes primitive regex policy.
