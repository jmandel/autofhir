FHIR-17540: Audit body height vital signs code

Issue request:
FHIR-17540 was Published/Persuasive for STU3 and asked the Observation Vital Signs profile to treat Body height like the other methodless magic-value vital signs codes: remove the separate Body length 8306-3 table row, keep Body height as 8302-2, and describe 8306-3 Body height --lying as an additional observation code for body length/lying height.

Initial application:
The issue was explicitly applied by git commit 2a879abac1 ("GF#17342, GF#17540") on 2018-07-27. That commit changed the Body height row to add the 8306-3 supplemental-code text and commented out the separate Body length 8306-3 row. Later source refactors preserved the methodless Body height profile and removed the old commented-out table row.

Additional context:
Observation is an active resource in source/fhir.ini, and source/observation/implementationguide-Observation-vitalsigns.xml references the vital signs introduction page and the bodyheight StructureDefinition, so these source files are in current build scope. The current vital signs table lists Body height with 8302-2, has no separate Body length magic-value row, and says 8306-3 may also be used in Observation.code to specify the actual measurement. The body-length example includes both 8306-3 and 8302-2 codings. Later FHIR-32787 clarified that body-weight clothing/position supplement codes are components or linked Observations, but that later correction does not reverse the body-height rule because 8306-3 is a more specific body-height measurement code in Observation.code. The 2024 Zulip thread found during community search likewise explains that implementers may send 8306-3 while also sending the standard generic 8302-2 code.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already satisfies FHIR-17540's semantic request: Body height is methodless at the profile/table level, Body length is not an independent magic-value row/profile entry, and 8306-3 remains available as an additional Observation.code coding when appropriate.

Recommendation:
Keep this no-change audit commit as-is. Future editorial cleanup can improve the generated profile-summary wording if desired, but no FHIR-17540 source correction is needed for the current specification.
