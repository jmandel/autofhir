FHIR-40505: Audit Vital Signs component UCUM binding

Issue request:
FHIR-40505 was a Published/Persuasive OO change request for the R5 Vital Signs profile. It reported that the UCUM binding on Observation.component.value[x] incorrectly constrained valueCodeableConcept and asked that the UCUM binding apply only to valueQuantity.

Initial application:
No prior reconcile commit exists for this issue on the combined branch. The source history does contain the original application as git commit 0c05783eb5c324f149285a686a68a2b84a87513c, subject "40505", which changed source/observation/structuredefinition-profile-vitalsigns.xml by removing the UCUM wording and binding from Observation.component.value[x] and adding a separate Observation.component.valueQuantity element with the UCUM binding. That commit is contained in the v5.0.0 tag.

Additional context:
The Zulip thread linked from Jira shows the interoperability problem: a blood pressure body-position component using valueCodeableConcept was rejected because the generic component.value[x] binding forced UCUM. OO minutes from 2023-02-28 record the motion to find FHIR-40505 persuasive with the UCUM binding only on valueQuantity. Later Observation/Vital Signs cleanup, including FHIR-47136, refactored the profile representation to the current Observation.component.value[x]:valueQuantity slice and adjusted related slicing details without reintroducing the generic binding. The Observation resource is active in source/fhir.ini, and implementationguide-Observation-vitalsigns.xml includes StructureDefinition/vitalsigns, so this source is in current build scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current profile has an unbound generic Observation.component.value[x] element and a dedicated Observation.component.value[x]:valueQuantity slice typed as Quantity with the UCUM value set binding. That satisfies the FHIR-40505 request and does not constrain valueCodeableConcept to UCUM.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-40505 unless a future work group decision changes the desired UCUM binding strength or value set for the valueQuantity slice.
