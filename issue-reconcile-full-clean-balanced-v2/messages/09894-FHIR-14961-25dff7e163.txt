FHIR-14961: Audit search parameter naming guidance

Issue request:
FHIR-14961 was a Published FHIR-core search change request from STU3 asking for a consistent naming convention for multi-word search parameters and modifiers, particularly whether dash-separated names should be replaced by lower camel case. The final Not Persuasive with Modification resolution chose not to rename existing parameters late in STU3, but to document the naming rule and the "sensible casing" rule that parameters must not differ only by case.

Initial application:
The issue was applied by git-svn commit 75cbf026343379dc52cb3143d3f5c373ff73beeb, matching Jira's svn revision 13883 comment. That commit added the search-page statement that names are case sensitive, HL7 does not define names differing only by case, clients should use correct case, and servers must not define different-meaning parameters that differ only by case.

Additional context:
The current search page still contains that rule in source/search.html. The active SearchParameter resource also now documents that SearchParameter.code should use lowercase ASCII characters and hyphens for maximum compatibility, and later FHIR-45349 constraints prohibit separator characters that would conflict with search processing. FHIR-45445 is a later, broader Resolved - change required issue for future naming-convention guidance in the IG-guidance IG, not an Applied/Published core issue to decide here; its minutes also say the change is for new parameters, not correcting existing parameters.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core source already preserves the FHIR-14961 outcome: no case-only collisions, correct-case client guidance, server prohibition on case-only alternate meanings, and current SearchParameter.code guidance favoring lowercase dash-separated codes without forcing disruptive renames.

Recommendation:
Keep this no-change audit commit. Do not reopen FHIR-14961 for core source edits unless FHIR-45445 or a later Applied/Published decision explicitly changes where the detailed naming convention must be published in core.
