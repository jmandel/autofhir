FHIR-17016: Audit BackboneElement datatype-specialization note

Issue request:
FHIR-17016 was a Published/Persuasive FHIR-core STU3 change request asking to fix the old BackboneElement page because it said datatype elements do not use BackboneElement while also listing datatypes as specializations. The request was a non-substantive clarification to resolve that apparent contradiction.

Initial application:
The Jira comment records SVN revision 14309. In the git history this is commit 77b2cb7825a4836e0546899c18b2480d49a27a8c, which changed source/backboneelement.html to qualify the old text by saying that a few datatypes specialized it, naming Timing, Dosage, and ElementDefinition.

Additional context:
The adjacent Published/Persuasive FHIR-17017 decision was applied in the next SVN revision to clarify that BackboneElement covers resource-specific complex child structures rather than datatype elements generally. The old standalone BackboneElement page was later folded into the active type framework by cbdf7d1e55dc4bfa1dc30fc526edee0491e05782. Current source separates the concepts: source/types.html says datatype elements do not use BackboneElement, while BackboneType is the datatype-side base for datatypes that allow modifier extensions. This run also fixed the later Published FHIR-26878 BackboneType list drift in a separate source-changing commit.

AutoFHIR reconciliation:
No FHIR-17016 source change was made. The current active source already avoids listing datatypes as BackboneElement specializations, preserves the datatype/resource-specific BackboneElement distinction, and now keeps the datatype modifier-extension exceptions under BackboneType rather than BackboneElement.

Recommendation:
Keep this audit commit as-is. No further FHIR-17016 action is needed unless a future work-group decision changes the BackboneElement versus BackboneType model; future datatype-list maintenance should be tracked under the later BackboneType issue family rather than this STU3 BackboneElement clarification.
