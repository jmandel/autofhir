FHIR-12309: Audit MessageHeader response request extension

Issue request:
FHIR-12309 was Published/Persuasive for FHIR-core MessageHeader. It asked to add a core extension equivalent to HL7 v2 MSH-16 so a message instance can say whether an application-level response is required, required only on error or success, or never.

Initial application:
The request was applied in core history: git commit 3aaf0e56ad added the MessageHeader extension spreadsheet for #GF12309, and commit 8e0c4de0f3 corrected the extension name and codes to messageheader-response-request / always, on-error, never, on-success. Later commit 826db6e76e aligned MessageDefinition.responseRequired with the same value set.

Additional context:
Current core no longer owns the extension StructureDefinition source. Commit dd468d4f17 removed source/messageheader/structuredefinition-extension-messageheader-response-request.xml and the MessageHeader core IG extension reference as part of removing extensions from R5 source. The authoritative current definition is in the FHIR Extension Pack repository under input/definitions/MessageHeader/StructureDefinition-messageheader-response-request.xml, where it has MessageHeader context, the MSH-16 description, valueCode, required binding to ValueSet/messageheader-response-request, and min 0. Core still contains active MessageHeader/MessageDefinition resources and uses the extension URL from $process-message guidance, while MessageDefinition.responseRequired and the messageheader-response-request CodeSystem/ValueSet remain in core terminology/resource source. Related FHIR-13851 and FHIR-34399 are already reflected; FHIR-53013 is only Triaged and does not create a final current-core change.

AutoFHIR reconciliation:
This audit intentionally makes no FHIR-core source change. Re-adding the extension StructureDefinition to core would reverse the R5 extension-source move and duplicate the Extension Pack artifact; the current core source is limited to in-scope references and terminology.

Recommendation:
Keep this audit as-is for the core reconciliation. If future changes are needed to the extension definition itself, make them in the FHIR Extension Pack rather than this core checkout; no current follow-up is required for FHIR-12309.
