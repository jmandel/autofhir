FHIR-8213: Audit Specimen processing time support

Issue request:
FHIR-8213 was a Published/Persuasive FHIR-core OO change request raised for DSTU1 asking how to record Specimen fixation/formalin times. The approved motion was to add treatmentTime[x] dateTime | Period 0..1 to specimen.treatment.

Initial application:
The historical SVN-imported application commit 348686f20075ff53db8f62afc2a7a25ce7b99e57, whose subject included #8213, added Specimen.treatment.time[x] with cardinality 0..1 and type dateTime|Period to the Specimen spreadsheet. Later source conversion/refactoring carried the concept forward as Specimen.processing.time[x], using processing rather than the older treatment name.

Additional context:
Specimen is an active current-build resource in source/fhir.ini. The current authoritative Specimen structure definition contains Specimen.processing.time[x] with cardinality 0..1, dateTime and Period choices, and prose explicitly covering sample fixation and time in formalin. FHIR-40950, already represented on the combined branch, later added Duration to the same element and reconciled the redundant specimen-processingTime extension; the FHIR Extension Pack now version-tags that extension through FHIR 5.0 and says R6 replaces it with Specimen.processing.time[x]. No Zulip or Confluence evidence was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Reintroducing the obsolete treatmentTime name or narrowing the current type list back to only dateTime|Period would conflict with later accepted Specimen processing-time decisions, while the current source already satisfies the FHIR-8213 fixation/formalin timing request.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for FHIR-8213; future work on generated diagrams or historical extension publication, if any, should remain tied to the later Specimen processing-time issue family rather than this DSTU1 request.
