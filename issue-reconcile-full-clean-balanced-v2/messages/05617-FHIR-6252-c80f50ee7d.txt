FHIR-6252: Audit Timing repeat bounds range support

Issue request:
FHIR-6252 was a Published/Persuasive with Modification FHIR-core datatypes change request asking for Timing.repeat.count to support decimal/range use cases such as radiotherapy 5 times per week for 6 to 7.5 weeks. The final resolution rejected changing count, noted that boundsDuration already supported decimal duration values, and approved adding Range to Timing.repeat.bounds[x] for possible-duration ranges.

Initial application:
The issue was applied in SVN revision 5642, now git commit 2fbb4392eeaedcf258c8e4f38bbe77af755cb2d6, which changed source/datatypes/timing.xml from Duration | Period to Duration | Range | Period and updated the short/definition text to cover a range of possible lengths. No existing combined-branch commit with Issue-Reconcile-Key: FHIR-6252 was found before this audit.

Additional context:
FHIR-6252 is the same Timing.repeat.bounds[x] change family as FHIR-5951, whose application first converted Period-only bounds to a choice and added Duration support. FHIR-8344 later referenced change request 6252 and was closed as done under another task because the same bounds[x] element already supported duration. The current build scope includes Timing as an active normative datatype, and the authoritative Timing spreadsheet still has Duration | Range | Period with the accepted range wording. Later FHIR-31559 chose an extension route for explicit start-date plus Duration/Range modeling rather than changing the base bounds[x] choices.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current active source preserves the FHIR-6252 semantic change exactly where the resolution placed it, and changing Timing.repeat.count or adding redundant prose would conflict with the accepted modified resolution.

Recommendation:
Keep this no-change audit as-is. Future work should continue modeling duration/range length limits through Timing.repeat.bounds[x], not Timing.repeat.count, unless a new work-group decision explicitly changes that design.
