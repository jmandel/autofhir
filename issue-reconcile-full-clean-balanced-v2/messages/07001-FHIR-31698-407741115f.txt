FHIR-31698: Audit detailed short descriptions

Issue request:
FHIR-31698 was a Published/Persuasive FHIR-core change request for R5 asking that element short descriptions be visible on Detailed Descriptions pages, because short text could contain important clarifications absent from the long definition. The motivating example was Bundle.entry.fullUrl, whose R4 detailed page did not show the short text mentioning UUID/OID URIs.

Initial application:
No HL7/fhir commit or current source hunk explicitly tagged FHIR-31698 was found. The applied behavior is visible in the R5 published output and current CI output: generated definition pages now include a Short Display row for elements, while the R4 Bundle detailed page did not.

Additional context:
The relevant Bundle source is in build scope because source/fhir.ini actively lists bundle=Bundle under [resources], and source/bundle/structuredefinition-Bundle.xml still carries the Bundle.entry.fullUrl short text including UUID/OID. The source definition page uses the active resource definitions template and <%dictionary%> macro; the generated dictionary output, not a per-resource source page, is where Short Display is emitted. A Zulip note on the day the issue was filed records the same rationale and no Confluence references or conflicting community records were found.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current R5 and CI detailed pages already expose element short descriptions as Short Display, satisfying the issue; editing Bundle or template source would be redundant or outside the current source responsibility for this already-applied generated behavior.

Recommendation:
Keep this no-change audit as-is. If future work changes the publisher/dictionary renderer, preserve the Short Display row on detailed definition pages because it is the applied resolution for FHIR-31698.
