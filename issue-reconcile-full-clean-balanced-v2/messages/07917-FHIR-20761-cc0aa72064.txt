Issue request:
FHIR-20761 was Published/Persuasive with Modification for FHIR-core. It asked that Identifier.system and Coding.system values in core and HL7-published IG examples either use example roots such as example.org or acme.com, or resolve to a defined CodeSystem or NamingSystem; the final resolution changed the requested error to a warning in the core build and the HL7-rooted IG Publisher.

Initial application:
No FHIR source commit explicitly references FHIR-20761. The current checkout does not contain the Java publisher implementation that would enforce this rule; the active Gradle build runs org.hl7.fhir.tools.publisher.Publisher from the external Kindling dependency, with validator behavior supplied by external org.hl7.fhir.core artifacts.

Additional context:
FHIR-I minutes from 2020-01-27 show the work group assigning this to Grahame as an IG Publisher data-gathering/tooling change, not as a directive to rewrite all current examples. Current source still intentionally contains active examples under acme.com/example.org roots, while the external validator/publisher code contains the URL-resolution, NamingSystem, example/acme, and unknown-code-system logic that governs this behavior.

This commit makes no FHIR source change.
