FHIR-19499: Audit Break the Glass clarification

Issue request:
FHIR-19499 was an Applied/Persuasive Security WG change request asking for clarification of the Break the Glass example on the security labels page. The request flagged a broken BTG category URL, asked for a clearer purpose-of-use Category-header example, and suggested considering a `_purpose` query parameter. The final Jira resolution says the needed changes had already been made by previous change proposals.

Initial application:
The earliest directly relevant source history corrected the HTTP Category example from the obsolete `http://hl7.org/fhir/security-label#break-the-glass` value to `http://terminology.hl7.org/CodeSystem/v3-ActReason#BTG`. Later Applied issues FHIR-42756 and FHIR-42757 updated the BTG terminology URL, revised the explanatory text, and added an OAuth purpose-of-use alternative alongside the HTTP Category example.

Additional context:
The current build includes both `security-labels.html` and `security.html`. Later Applied issue FHIR-53885 moved the standalone Break the Glass section from Security Labels to the general Security page because the topic is not solely security-labeling, while preserving the OAuth and HTTP Category examples. The linked Zulip discussion shows why `_purpose` was not a settled replacement: participants discussed per-request headers, OAuth/JWT/SAML approaches, and John Moehrke later noted a query parameter would not cover create, update, and delete. A related terminology thread shows the BTG Category value should be the terminology CodeSystem URI and that the remaining `http://hl7.org/fhir/tag/security` scheme was intentionally retained for future-proofing, even though defining that scheme was left as a broader unresolved concern.

AutoFHIR reconciliation:
This is an empty no-change audit commit. The current source already conveys the applied clarification through the corrected BTG code URL, explicit OAuth and HTTP Category declaration examples, and surrounding caveats that FHIR does not define the full policy or protocol. Adding a POPHLTH example, inventing a `_purpose` parameter, or redefining the experimental Category-header scheme would go beyond the applied FHIR-19499 decision and could conflict with later unresolved maturity discussions.

Recommendation:
Keep this audit commit as-is for FHIR-19499. If the work group wants to remove, replace, or formally define the remaining experimental HTTP Category scheme, handle that under a new or existing final tracker such as the unresolved BTG maturity discussion rather than reopening this applied clarification.
