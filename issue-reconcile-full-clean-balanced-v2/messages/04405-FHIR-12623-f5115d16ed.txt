Issue request:
FHIR-12623 was a Published/Persuasive Patient Care change request for the DSTU2 CarePlan artifact. It asked to add a new stopped code under cancelled in the CarePlan activity status value set/code system, to clarify cancelled as withdrawn, completed as completed more or less as planned, and unknown as not a substitute for other.

Initial application:
The issue was applied in git commit 1afa3503ac4fcef5a2d591f73dc5a1a143a1da25, which explicitly referenced #12623 and updated the historical CarePlan spreadsheet to add stopped beneath cancelled, update the status short list, and revise the completed, cancelled, and unknown definitions.

Additional context:
The current build has CarePlan active in source/fhir.ini and carries the relevant terminology as source/careplan/codesystem-care-plan-activity-status.xml plus source/careplan/valueset-care-plan-activity-status.xml. The current CodeSystem preserves the requested hierarchy with hierarchyMeaning=is-a, cancelled as the parent concept, and stopped as its child. Bounded Jira, Zulip, and Confluence searches did not find a later in-scope reversal or conflicting Patient Care decision for this CarePlan status change.

AutoFHIR reconciliation:
