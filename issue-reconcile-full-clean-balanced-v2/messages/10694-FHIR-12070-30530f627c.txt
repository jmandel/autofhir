FHIR-12070: Audit operation POST body wording

Issue request:
FHIR-12070 was a Published/Persuasive FHIR-core clarification asking that the operation POST-body shortcut make clear that "only parameter" means the only parameter supplied in a specific invocation, not merely the only parameter declared by the operation definition.

Initial application:
The Jira comments record application in svn @10160. No current Git commit mentions FHIR-12070 directly, and the original ambiguous sentence is no longer present in the current source; the active operation request wording was later replaced by FHIR-28620 commit 1f6ffabb3d.

Additional context:
FHIR-28620 is a later Published/Persuasive clarification for the same operation request shortcut. It deliberately allows a POST request to carry the single Resource input in the request body while additional simple parameters are carried as query parameters, and the current source says this applies to "all other parameters a client intends to submit." That wording resolves the FHIR-12070 declared-vs-actual ambiguity while preserving the later FHIR-28620 rule that there is exactly one Resource input parameter.

AutoFHIR reconciliation:
This commit makes no source change. The current active `source/operations.html` text already states the rule in terms of the parameters the client intends to submit for the invocation, and changing it back to the older single-actual-parameter phrasing would be less precise than the later approved wording.

Recommendation:
Keep this empty audit commit. Revisit only if the work group wants a new policy discussion about raw-resource POST bodies for operations that declare more than one Resource input parameter; that is beyond FHIR-12070 and FHIR-28620.
