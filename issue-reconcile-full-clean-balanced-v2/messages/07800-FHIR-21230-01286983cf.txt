FHIR-21230: Audit relative reference URL format

Issue request:
FHIR-21230 was a Published/Persuasive FHIR-core change request from fhir-i asking that Reference.reference guidance use the relative FHIR REST form "Patient/123" rather than "/Patient/123" in the definition note for relative/logical references.

Initial application:
The issue was applied by git commit 1d7085a2c6cde0781eddfb7692790c6475e3b577, which changed source/datatypes/reference.xml from structure "/[type]/[id]" to "[type]/[id]". Jira also records PR HL7/fhir#1959, merged as de7092273be01dca22361a90a284c5dd75fb24b3.

Additional context:
source/fhir.ini actively lists Reference as a datatype and maps the reference datatype page to references, so source/datatypes/reference.xml is in current build scope for the referenced definitions page. The original Zulip thread confirms WG participant consensus that relative references should not start with a slash. Later Bundle reference-resolution text from FHIR-29271 uses the same "[type]/[id]" form and has already been reconciled separately on the combined branch, so it is supporting context rather than a second decision here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative Reference source already says that a URL conforming to "[type]/[id]" should be assumed to reference a FHIR RESTful server, and a targeted search of the reference-related source found no remaining old structure "/[type]/[id]" phrase.

Recommendation:
Keep this no-change audit commit as-is. No FHIR core follow-up is needed for FHIR-21230 unless a future work group decision changes the broader relative-reference policy.
