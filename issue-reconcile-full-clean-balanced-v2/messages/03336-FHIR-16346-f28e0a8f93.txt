FHIR-16346: Audit Procedure reason guidance

Issue request:
FHIR-16346 was a Published/Persuasive STU3 Patient Care request to clarify when Procedure.reasonCode versus Procedure.reasonReference should be used and whether both could be used. Its resolution asked for comments explaining that the two were not duplicative: a code may summarize the reason, a reference may carry a more precise Condition, Observation, Procedure, DiagnosticReport, or DocumentReference, and both separate elements could be present when describing different procedure reasons.

Initial application:
The issue was applied before this reconciliation by git commit 2abadfb0e67fcff244d11e84699e185273719afa, whose subject names GF#13974 and GF#16346 and adds the requested comments to the then-authoritative Procedure spreadsheet source for both Procedure.reasonCode and Procedure.reasonReference. That historical source path has since been replaced by the current generated StructureDefinition source.

Additional context:
Current Procedure is active in source/fhir.ini and the current source no longer has separate reasonCode and reasonReference elements. R5/R6 model history merged the repeating code/reference pattern into Procedure.reason of type CodeableReference, with concept and reference facets. Later Published issue FHIR-32510 corrected the migrated guidance because CodeableReference permits both concept and reference on the same repeat only when they describe the same thing; commit 9241c2d467b808407f77b86ac99a9577979ab7ce applied that correction to the current StructureDefinition source. Confluence minutes and Zulip searches found no conflicting community rationale beyond the Jira decisions and bot notifications.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source/procedure/structuredefinition-Procedure.xml comment tells implementers to use Procedure.reason.concept when a code is sufficient, Procedure.reason.reference when a resource conveys more information such as onset date, and to keep both facets consistent if they appear in the same Procedure.reason. That is the correct current expression of FHIR-16346 after the later CodeableReference model and FHIR-32510 correction.

Recommendation:
Keep this audit commit as-is. Do not restore the old reasonCode/reasonReference wording in current core Procedure, because those elements no longer exist and the current CodeableReference-specific text is governed by the later FHIR-32510 decision.
