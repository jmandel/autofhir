FHIR-17743: Audit AllergyIntolerance status datatypes

Issue request:
FHIR-17743 was a Published/Persuasive Patient Care issue asking to change AllergyIntolerance.clinicalStatus and AllergyIntolerance.verificationStatus from code to CodeableConcept, consistent with the corresponding Condition status elements, while retaining required bindings to the AllergyIntolerance status value sets.

Initial application:
The request was applied in db4dbacb2d3c, which changed the AllergyIntolerance spreadsheet datatypes from code to CodeableConcept, converted examples to CodeableConcept coding form, added the FHIR-17743 committee note, and moved the status bindings from inline code lists to value-set-backed required bindings. The current XML source was later generated/refactored from that spreadsheet lineage and still carries GF#17743 in the committee notes.

Additional context:
AllergyIntolerance is an active current-build resource in source/fhir.ini and remains owned by Patient Care. The corresponding Condition elements are also CodeableConcept, preserving the requested consistency. FHIR-19633 and the linked #committers Zulip discussion explain the rationale for CodeableConcept with required bindings: status judgments may need more specific local/SNOMED codings while preserving a required FHIR code. FHIR-23008 later addressed invariant fallout from the datatype change and did not reverse the CodeableConcept decision. No Confluence or Zulip search found a conflicting later decision for FHIR-17743.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. In current build-scope source/allergyintolerance/structuredefinition-AllergyIntolerance.xml, both AllergyIntolerance.clinicalStatus and AllergyIntolerance.verificationStatus have type CodeableConcept and required bindings to the AllergyIntolerance clinical and verification value sets. Nearby generated-looking diagram content and examples also show CodeableConcept, so there is no stale current-build source location to correct for this issue.

Recommendation:
Keep this no-change audit as-is. Further edits for FHIR-17743 would be redundant unless a future Patient Care decision changes the status datatype or binding model.
