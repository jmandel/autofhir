FHIR-5792: Audit build expansion version metadata

Issue request:
FHIR-5792 was a Published/Persuasive FHIR-I DSTU1 change request following FHIR-5791. It asked that the build tool publishing the specification fill out and publish ValueSet expansion parameters and other expansion metadata as much as possible, especially code-system/version information. The resolution records SVN revision 4551 and the 2015-03-19 MnM/FHIR block vote.

Initial application:
The issue was applied in git-svn commit 360171a424a2b0bdbf84d612bc7a722385214254, which is SVN revision 4551 and explicitly names "#5792 - fill out value set expansion versions". That historical implementation changed the then-in-repo Java ValueSetExpanderSimple and terminology-service interfaces so expansion generation passed a ValueSet.expansion.parameter list through define/compose/import/include processing, added version URI parameters when source or imported value sets had versions, and copied parameter metadata from imported or terminology-service expansions instead of returning only contains entries.

Additional context:
The historical Java publisher/build-tool sources under tools/java are no longer present in the current FHIR checkout. The current build invokes org.hl7.fhir.tools.publisher.Publisher from the external kindling dependency pinned in gradle.properties, so there is no current in-repo build-tool implementation to patch for this old DSTU1 tooling issue. ValueSet is still active current-build source in source/fhir.ini, and later related decisions already represented on the combined branch preserved and refined the same semantics: FHIR-5791 added expansion.parameter, FHIR-3535 added ValueSet.expansion.contains.version, FHIR-13810/FHIR-41589/FHIR-41639 refined expansion version/accounting guidance, and FHIR-13820 audited the related $expand valueSetVersion parameter. Current active ValueSet source says expansion parameters should include client/defaulted inputs and canonical or URI references, including version, for all CodeSystems, CodeSystem Supplements, and ValueSets used in an expansion, and the $expand return documentation points servers back to that guidance.

AutoFHIR reconciliation:
No source change was made. The original request was historically applied to the then-current build tool, the current core source already exposes the expansion parameter/version guidance and examples needed by implementers, and the old build-tool code is not part of the present FHIR source tree. Adding new core prose would duplicate later Vocabulary guidance rather than correct a missing FHIR-5792 application.

Recommendation:
Keep this empty audit commit. If a current publisher behavior regression is suspected, investigate the external kindling publisher or terminology service with a targeted build-tool test; no current core FHIR source edit is justified by this historical issue.
