FHIR-15904: Audit AdministrativeGender concept maps

Issue request:
FHIR-15904 was Published/Persuasive for STU3 and asked to restore the FHIR-v2 and FHIR-v3 AdministrativeGender ConceptMaps that existed in DSTU2 on the current AdministrativeGender value set page.

Initial application:
No prior git commit explicitly mentions FHIR-15904. The underlying AdministrativeGender v2/v3 mapping data was already present in source/terminologies/bindings.xml from the older gender-code tracker work, and the issue's own Jira comment recorded Grahame Grieve's conclusion that the requested maps were already there.

Additional context:
FHIR-16189 is the same AdministrativeGender concept-map family, but it concerned duplicate rendering and a proposed SNOMED CT map. Its final resolution rejected the SNOMED CT map and treated the duplicate v2/v3 listings as a tooling/rendering issue. The linked Zulip thread confirms that the AdministrativeGender mappings are sourced from bindings.xml and that the rendering issue was considered fixed. Current build.fhir.org renders the AdministrativeGender value set with links to cm-administrative-gender-v2.html and cm-administrative-gender-v3.html and the corresponding generated ConceptMap pages contain the expected code mappings.

AutoFHIR reconciliation:
This is an empty no-change audit commit. The current source already contains the v2 and v3 AdministrativeGender mapping rows, including the v2 A and O targets for the FHIR other code, and the current generated build exposes the requested ConceptMap pages. No source change is needed.

Recommendation:
Keep this audit commit as-is. Do not add duplicate source files or narrative; the authoritative spreadsheet-backed mapping data and generated ConceptMap pages already satisfy FHIR-15904, and FHIR-16189 indicates the remaining SNOMED CT request was intentionally not applied.
