FHIR-5585: Replace stale Resource Profile wording

Issue request:
FHIR-5585 was Published/Persuasive with Modification for DSTU1. It asked FHIR to stop using a resource named "Profile" for one part of the broader profiling/conformance activity; the accepted resolution renamed the Profile resource to StructureDefinition and separated the conversational use of "profile" from the resource name.

Initial application:
The old history has no exact FHIR-5585 commit message, but it records the application trail: 2b54214 merged Profile and ExtensionDefinition into StructureDefinition, 9d234906 replaced remaining "profile" references in StructureDefinition element definitions, and ebc8bdf is the Jira-tagged SVN 4492 commit for #5585. Current source has StructureDefinition as an active resource and no active Profile resource entry, but one active informative page still used the stale phrase "Conformance Statement and Resource Profile resources."

Additional context:
Later FHIR-16414 is Published/Not Persuasive with Modification and intentionally redefined current FHIR terminology so Profile means a constrained StructureDefinition, while Implementation Guide and Package cover broader collections. The current profiling glossary reflects that later decision. Negative Zulip and Confluence searches found no directly relevant community record for FHIR-5585 or the "Conformance Package" terminology that would change this source/history conclusion.

AutoFHIR reconciliation:
Updated source/ehr-fm.html to refer to "CapabilityStatement and StructureDefinition resources" instead of the stale pre-current "Conformance Statement and Resource Profile resources." The page is in build scope via source/hierarchy.xml and source/implsupport-module.html, and StructureDefinition is active in source/fhir.ini, so this removes a remaining visible stale Profile-resource reference from the current build without changing unrelated profiling terminology.

Recommendation:
Keep this commit as-is. The remaining current use of "Profile" is governed by the later FHIR-16414 terminology decision and is not a FHIR-5585 defect; no additional core source change is recommended from this seed.
