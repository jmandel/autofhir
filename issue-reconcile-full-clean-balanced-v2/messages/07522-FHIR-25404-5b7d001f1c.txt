FHIR-25404: Audit informational identifier guidance

Issue request:
FHIR-25404 was a Published FHIR-core clarification, resolved Persuasive with Modification, asking that the Resource Identity / Logical ID chapter mention the "informational" identifier concept raised in the linked methodology Zulip discussion. The accepted resolution was to add narrative around business identifiers rather than create a distinct informational-identifier model because the concepts do not have a clean dividing line.

Initial application:
The issue was applied in git commit bb7cb9865b8a48b4b790c2985c4694bc869f1225, which added an Identifier Categories narrative to source/resource/resource-notes.xml. That source is in the active Resource infrastructure area through source/fhir.ini's resource=abstract,Resource entry, so it feeds the current resource.html Resource Identity content.

Additional context:
The linked Zulip thread shows the requested distinction among business, informational, and instance identifiers, and the FHIR-I minutes for 2020-01-13 record the motion to add narrative to business identifiers. Current source/resource/resource-notes.xml still contains that narrative and explains that logical id is an instance identifier while other identifiers are loosely called business identifiers. A later related Jira, FHIR-48692, addresses broader identifier usage notes and remains Resolved - change required rather than Applied or Published for this run's default source-edit scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already mentions informational identifiers in the Resource Identity page and preserves the applied distinction needed for FHIR-25404. Reorganizing the subsection title or polishing wording would not change implementer understanding for this issue and would risk overlapping with the separate FHIR-48692 follow-up.

Recommendation:
Keep this audit commit as-is for FHIR-25404. Handle any broader rewrite of identifier usage guidance under FHIR-48692 or another explicitly scoped follow-up, not as a correction to this already-published clarification.
