FHIR-12893: Audit Contract term decision type

Issue request:
FHIR-12893 was a Published/Persuasive Financial Management change request asking to add a Contract term-level decision type for the decision a grantor makes with respect to a term or offer from a grantee, including the distinction between term-level accept/reject decisions and broader header-level decisions.

Initial application:
The original source application appears in historical commit 43e53248d6 (#12860), which added a ContractDecisionType binding and a Contract.decisionType CodeableConcept using the requested grantor/grantee definition. The commit did not use the migrated Jira key, but it directly implemented the same Contract decision type request.

Additional context:
FHIR-13403 later refactored Contract for Ricardian contract concepts and moved the decision concept from the old Contract.decisionType location into the term offer structure as Contract.term.offer.decision. The current build has Contract active in source/fhir.ini and the active Contract StructureDefinition contains Contract.term.offer.decision with the ContractDecisionType binding to v3-ActConsentDirective, the grantor/grantee binding description, and requirements explaining the offeror/grantee/offeree relationship. Current source no longer uses the obsolete decisionType path, which is expected after the refactor rather than a missing application.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current active Contract source preserves the requested decision-type concept at the correct current path, and adding a duplicate decisionType element or old header-vs-term prose would be inconsistent with the later Contract structure.

Recommendation:
Keep this no-change audit as-is. Future work should address Contract decision semantics only if the Financial Management work group reopens the current Contract.term.offer.decision wording or binding, not as a backport of the obsolete decisionType path.
