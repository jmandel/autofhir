FHIR-49834: Correct RDF XHTML literal wording

Issue request:
FHIR-49834 is Applied/Persuasive for R6 and asks that generated FHIR RDF examples type narrative XHTML div literals as rdf:XMLLiteral instead of leaving them as plain strings or xsd:string values. The Jira points to the HAPI core Turtle generator PR that already merged this generator correction.

Initial application:
No commit in the FHIR specification repository explicitly mentions FHIR-49834. The issue was initially applied in the external org.hl7.fhir.core generator by hapifhir/org.hl7.fhir.core#1854, which added the rdf prefix and emits ^^rdf:XMLLiteral for xhtml values. In this checkout, source/rdf.html already said xhtml uses rdf:XMLLiteral and its example used fhir:div [ fhir:v "..."^^rdf:XMLLiteral ], but a nearby paragraph still contradicted that by saying XHTML is represented as escaped xsd:string.

Additional context:
The RDF page is part of the current core documentation build through source/hierarchy.xml and source/documentation.html. The active Device example source referenced by the Jira is build input under the active Device resource, but generated Turtle example files are not checked into this FHIR source tree. ITS minutes for 2025-03-12 record approval of FHIR-49834 by DB/BP 4-0-0, and no Zulip or Confluence evidence was found that conflicts with the Jira/generator/source conclusion.

AutoFHIR reconciliation:
Updated source/rdf.html to remove the stale xsd:string statement and say XHTML is represented as escaped markup with datatype rdf:XMLLiteral. This aligns the built RDF documentation with the applied generator behavior and with the existing RDF example on the same page.

Recommendation:
Keep this source fix. The core specification source now agrees with the applied external generator change; no additional checked-in core source changes were found for generated Turtle examples.
