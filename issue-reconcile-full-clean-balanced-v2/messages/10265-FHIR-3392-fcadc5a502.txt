FHIR-3392: Audit ElementDefinition isSummary already applied

Issue request:
FHIR-3392 was Published/Persuasive with Modification for FHIR-core StructureDefinition. It asked to add an isSummary element to profile/ElementDefinition content, defaulting to false, with the final resolution to add isSummary to the profile and make the default the same as the base profile.

Initial application:
Jira records that Grahame Grieve applied the change in SVN version 2974 on 2014-10-12. The first current git commit containing source/datatypes/elementdefinition.xml already includes the ElementDefinition.isSummary row, so the original source application predates the accessible git history.

Additional context:
Later applied/published isSummary issues refined the same rule family rather than reversing the seed: FHIR-9201 said isSummary cannot be overridden in profiles, FHIR-14272 clarified the ElementDefinition interpretation table and linked the isSummary definition to it, and FHIR-35855 removed obsolete wording implying per-profile summary behavior might vary. Those related issues are already represented on the combined reconciliation branch.

AutoFHIR reconciliation:
No source change was made. Current build-scope source defines ElementDefinition.isSummary as 0..1 boolean, documents that elements are not included in summaries unless explicitly marked, links to the ElementDefinition interpretation guidance, and states on the profiling page that _summary=true responses are based on the base resource definition because profiles cannot change isSummary.

Recommendation:
Keep this no-change audit commit. The current specification preserves the requested ElementDefinition field and the later clarified profile-inheritance behavior, so adding duplicate prose or changing current source would risk drift without improving implementer understanding.
