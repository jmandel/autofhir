FHIR-13105: Audit OperationDefinition URL rendering

Issue request:
FHIR-13105 was a Published FHIR-core change request with Persuasive resolution. It asked that rendered OperationDefinition pages expose the canonical URL for each operation definition instead of requiring readers to inspect raw XML or JSON, with optional consideration for operation listing pages.

Initial application:
The issue was explicitly applied in git commit b9231cf8f891fdba3fb62a6493ae9875098f85f1, whose message is "#13105 - show canonical URL for operation definitions" and whose git-svn-id records SVN revision 11834, matching the Jira comment. That historical commit changed the then-current PageProcessor operation rendering to add an official URL paragraph for each operation definition before the formal-definition link.

Additional context:
OperationDefinition is an active current-build resource in source/fhir.ini. Current source contains OperationDefinition.url as the canonical identifier element, and every actual OperationDefinition XML source found under source/ contains a url value. Later FHIR-20194 clarified that this displayed value should be called the canonical URL rather than the official URL; that related issue is already represented on the combined branch. Current build pages such as valueset-operation-expand.html and resource-operation-validate.html render "The canonical URL for this operation definition is" followed by the http://hl7.org/fhir/OperationDefinition/... URL. The optional idea of also adding URLs to operation summary/list pages was not part of the historical application and is not needed for implementer understanding when the linked operation pages display the canonical URL.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current built operation pages already satisfy the required rendering behavior, the operation-definition source inputs carry URL values, and no current source location was found where an additional core-source edit is necessary.

Recommendation:
Keep this audit commit as-is. If a future current build stops rendering the canonical URL on operation pages, trace the active publisher operation renderer rather than changing the operation-definition XML URL values or historical release archives.
