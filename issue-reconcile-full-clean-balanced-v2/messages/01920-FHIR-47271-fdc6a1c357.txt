FHIR-47271: Clarify async pattern disambiguation

Issue request:
FHIR-47271 was an Applied/Persuasive FHIR-core clarification for the async pages. It asked that the specification make clear which asynchronous pattern is triggered when a request includes both Prefer: respond-async and _outputFormat, including non-NDJSON _outputFormat values.

Initial application:
The Jira comment points to HL7/fhir#3192, which merged on 2024-11-12. That PR included commit 61b36bd16f, which added the approved _outputFormat disambiguation to source/async-bulk.html and source/async-bundle.html. Those local detail pages were later deleted from the current core source by commit 270e0ceb7b, which changed source/async.html to link to API Incubator pages instead.

Additional context:
The current core build no longer has source/async-bulk.html or source/async-bundle.html, and source/async.html is the active core page for asynchronous request patterns. The current CI-rendered async overview is reachable, but the API Incubator async-bulk and async-bundle URLs referenced from it currently return 404, so the approved disambiguation is not available in the current core build. FHIR-I minutes from 2024-10-07 record the persuasive vote and discussion of the two async patterns; the Jira resolution provides the authoritative _outputFormat rule.

AutoFHIR reconciliation:
This commit adds the approved _outputFormat trigger rule to the active source/async.html overview: for servers supporting both patterns for the same request type, _outputFormat selects the Bulk Data pattern; servers that only support Bulk Data may make _outputFormat optional; and requests that include _outputFormat where Bulk Data is not supported return an error and OperationOutcome. This preserves the prior applied semantics without reintroducing deleted detail pages or editing out-of-checkout API Incubator content.

Recommendation:
Keep this source change. A separate follow-up may be needed for the broken API Incubator links or external async detail pages, but this commit restores the FHIR-47271 clarification in the current core build scope.
