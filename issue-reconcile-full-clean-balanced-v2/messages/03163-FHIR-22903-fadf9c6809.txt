FHIR-22903: Audit ChargeItem organization definitions

Issue request:
FHIR-22903 was a Published/Persuasive Patient Administration correction for R5. It reported that ChargeItem.performingOrganization and ChargeItem.requestingOrganization definitions were reversed and the accepted resolution was to update the long descriptions as requested.

Initial application:
The issue was applied before this reconciliation by commit 1f55a5080b608ee013f944a94971d42dc3434a08, which changed source/chargeitem/structuredefinition-ChargeItem.xml so ChargeItem.performingOrganization says "The organization performing the service." and ChargeItem.requestingOrganization says "The organization requesting the service." The corrected wording is present in the checked-in R5 historical package surface.

Additional context:
The current build no longer has an active ChargeItem resource entry in source/fhir.ini, and source/chargeitem/structuredefinition-ChargeItem.xml was deleted by 71567db3ee039ac6977be5f96a7e013896569a36 when ChargeItem and several other resources were removed from the current ballot branch. Older tools/history release snapshots for STU3/R4/R4B still contain the pre-fix wording, but those are frozen historical artifacts rather than current build inputs. Confluence minutes from the January 2022 PA WGM independently record the persuasive disposition and 3-0-0 vote; Zulip searches found no conflicting discussion.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the R5 application was correct and there is no current authoritative ChargeItem StructureDefinition in this build to edit. Editing tools/history release snapshots would rewrite historical publication artifacts, not fix the current specification.

Recommendation:
Keep this audit commit as-is. No follow-up is needed in core unless ChargeItem is reintroduced to the current build; if that happens, reuse the corrected R5 definitions rather than the older STU3/R4/R4B historical wording.
