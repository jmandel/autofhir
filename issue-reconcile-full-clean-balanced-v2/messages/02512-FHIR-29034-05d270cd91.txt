FHIR-29034: Audit Organization contact migration

Issue request:
FHIR-29034 was a Published/Persuasive PA change request for R5 asking to remove the top-level Organization.telecom and Organization.address elements and update Organization.contact from a BackboneElement to 0..* ExtendedContactDetail.

Initial application:
The change was applied in stages. Commit a9d7aa77e88c7070371eabb413aa4f91101d07fb changed Organization.contact to ExtendedContactDetail while temporarily deprecating the old top-level telecom/address elements. Commit e1320848bd2700338a2a11b634693d52f9fb8ad1 then removed the deprecated Organization.telecom and Organization.address elements from the active Organization StructureDefinition. Commit eb428f546bf447e01fc427a07f417c31f242b1ce updated the Organization address search parameters to point at Organization.contact.address.

Additional context:
FHIR-29035 created ExtendedContactDetail with telecom, address, organization, and period fields, and FHIR-27005 records that using ExtendedContactDetail on Organization.contact satisfies the missing contact period request. PA minutes from 2021-12-01 confirm the work group decision to remove Organization telecom/address and use ExtendedContactDetail for Organization.contact. The remaining Organization.telecom and Organization.address mentions in source/fhir.ini are in the [r4-r6-changes] migration mapping section, and the inactive CDA profile entry is commented out of [profiles].

AutoFHIR reconciliation:
No source change was made. The active Organization resource is in source/fhir.ini, current source/organization/structuredefinition-Organization.xml has Organization.contact typed as ExtendedContactDetail and no active Organization.telecom or Organization.address element definitions, Organization address search parameters use Organization.contact.address, and a parse check found no direct telecom/address children in active Organization examples.

Recommendation:
Keep this no-change audit commit as-is. Future cleanup should not re-add local Organization.telecom/address prose; only migration/change-summary mappings or external compatibility material should mention the retired paths.
