FHIR-46484: Audit Bundle.issues OperationOutcome clarification

Issue request:
FHIR-46484 was an Applied/Persuasive FHIR-I change request raised against R5 and applied for R6. It observed that FHIR-32011 intended Bundle.issues to carry an OperationOutcome, while the displayed type was broadly shown as Resource, and requested that the Bundle.issues short display, definition, and comments state that the element is an OperationOutcome resource.

Initial application:
FHIR-32011 introduced Bundle.issues in R5 through commits 88c3289f77 and 66ccc36aa4 using ElementDefinition.type code Resource plus profile http://hl7.org/fhir/StructureDefinition/OperationOutcome. FHIR-46484 was then applied by commit ce45edd65298ee221dbcee7e6a0319d114b04eef, which added the OperationOutcome profile line and changed the short, definition, and comment text to name OperationOutcome explicitly.

Additional context:
The Bundle resource is active in source/fhir.ini, so source/bundle/structuredefinition-Bundle.xml is in current build scope. Current source matches the requested semantics: Bundle.issues has Resource constrained by the OperationOutcome profile, OperationOutcome wording in its short and definition, and a comment that distinguishes whole-Bundle issues from per-entry entry.response.outcome. FHIR-I minutes for 2024-07-29 record the same decision and note that a separate tooling issue should handle display of restricted Resource types; the checked-in bundle.svg still renders Resource, but that generated diagram is not the authoritative source to edit for this reconciliation.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change because the current authoritative Bundle StructureDefinition already carries the OperationOutcome profile and explanatory OperationOutcome wording required by FHIR-46484.

Recommendation:
Keep this no-change audit commit as-is for the core specification. Any remaining desire to display Resource(OperationOutcome) more clearly should be handled through the separate tooling work mentioned in the FHIR-I minutes, not by changing generated diagram artifacts in this reconciliation.
