FHIR-14377: Point Immunization statusReason to current reason element

Issue request:
FHIR-14377 was Published with a Persuasive with Modification resolution for STU3 Immunization. It asked PHWG to bring Immunization reasons back in sync with medication/event patterns by adding statusReason for not-done reasons, renaming Immunization.reason to reasonCode, adding reasonReference for Condition, Observation, and DiagnosticReport support, and binding the reason elements appropriately.

Initial application:
The February 2018 source commit f451f3fc applied the issue without naming it in the commit subject: it added Immunization.statusReason with committee note #14377, changed the old Immunization.reason element to reasonCode, added reasonReference, added the status-reason search parameter, and updated examples/value sets. The current XML source still carries the #14377 committee note on Immunization.statusReason, confirming that the issue was incorporated into the active resource definition.

Additional context:
FHIR-14374 explicitly closed by reference to the FHIR-14377 resolution, and FHIR-17811 later refined the statusReason wording while still referring to reasonCode/reasonReference. In the current R6 source, the R4 reasonCode and reasonReference split has intentionally been merged into the active CodeableReference element Immunization.reason, as recorded in source/fhir.ini change annotations and reflected by the active StructureDefinition. FHIR-54325 recently updated statusReason for not-done and entered-in-error statuses but preserved the obsolete reasonCode pointer in the comment.

AutoFHIR reconciliation:
This commit updates the active Immunization.statusReason comment to direct implementers to Immunization.reason, the current element for why the immunization was performed, instead of the obsolete reasonCode name. It also updates the Immunization Event mapping-exception resource value so the source companion file remains consistent with the authoritative StructureDefinition text.

Recommendation:
Keep this commit as-is. It preserves the FHIR-14377 distinction between reasons an immunization occurred and reasons it did not occur, while aligning that guidance with the later current-spec merge of reasonCode/reasonReference into Immunization.reason.
