FHIR-50714: Audit Bundle entry search guidance

Issue request:
FHIR-50714 is an Applied/Persuasive R6 FHIR-core-search issue. It asked for guidance on accessing Bundle entries through the Bundle.composition and Bundle.message search parameters and why this is different from normal chaining; the final resolution was to link the Including Referenced Resources section to the resource search type description.

Initial application:
No prior AutoFHIR reconciliation commit existed on the combined branch. PR HL7/fhir#3967 merged commit 3632c1f80ac2defafdf83135b1bf9620780c1bbf, which updated source/search.html to treat resource search parameters alongside reference parameters in chaining and _include/_revinclude syntax and wildcard prose, including links to the #resource search-type section.

Additional context:
source/bundle/bundle-Bundle-search-params.xml defines Bundle-composition and Bundle-message as type=resource search parameters over Bundle.entry[0].resource, so the current search prose points implementers to the governing resource search-parameter semantics. FHIR-I Madrid WGM minutes record the FHIR-50714 Persuasive vote at 13-0-0. Later applied FHIR-45252 added canonical/non-Reference reference discretion language in the same search page but left the FHIR-50714 resource-type include and chaining guidance intact.

AutoFHIR reconciliation:
This audit commit makes no source change. source/search.html is the tracked FHIR-core-search narrative source and already contains the relevant #resource links in the resource type description, chaining text, _include/_revinclude target-type text, and wildcard include text; the Bundle search-parameter source already exposes composition/message as resource parameters.

Recommendation:
Keep this no-change audit commit as-is. No follow-up core-source work is needed for FHIR-50714 unless the work group later decides to add a separate Bundle-specific example subsection beyond the applied resolution.
