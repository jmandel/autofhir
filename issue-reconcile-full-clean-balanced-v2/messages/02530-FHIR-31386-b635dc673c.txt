FHIR-31386: Use originMap in $translate response examples

Issue request:
FHIR-31386 was Published/Persuasive for R5 and asked to align ConceptMap and $translate names with FHIR naming rules: targetsystem to targetSystem, ConceptMap.source/target to sourceScope/targetScope, corresponding $translate input parameters to sourceScope/targetScope, and $translate output match.source to match.originMap.

Initial application:
The issue was first partially applied in 60d2e867d, which renamed the active ConceptMap operation and resource elements but left follow-up comments noting the output had become match.originalMap rather than originMap and that element renames still needed work. The later aaf6a9a6dc commit fixed the ConceptMap2 operation definition to originMap and applied the sourceScope/targetScope resource/search/example changes before ConceptMap2 was promoted back into the active ConceptMap source, but the active $translate response example still carried originalMap and one remaining source output part name.

Additional context:
ConceptMap is active in source/fhir.ini, source/conceptmap/list-ConceptMap-operations.xml includes OperationDefinition/ConceptMap-translate, and that OperationDefinition directly includes $translate-response.txt as its response example. The current authoritative OperationDefinition already uses sourceScope, targetScope, targetSystem, and output originMap, while fhir.ini keeps ConceptMap.source[x] and ConceptMap.target[x] only as migration aliases to sourceScope[x] and targetScope[x]. FHIR-32129 is already represented on the combined branch and covers neighboring $translate source/target input wording, not this output example name.

AutoFHIR reconciliation:
Updated source/conceptmap/$translate-response.txt so all three response example parts that identify the ConceptMap producing a match use the approved output part name originMap instead of originalMap or the old source name.

Recommendation:
Keep this source fix. It completes the published FHIR-31386 naming change on a current-build example that is included by the active ConceptMap $translate OperationDefinition, without changing unrelated operation behavior or historical migration aliases.
