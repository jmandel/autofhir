FHIR-28397: Audit Task restriction recipient Device support

Issue request:
FHIR-28397 is an Applied FHIR-core Task change request with a Persuasive with Modification resolution. It asked to support Device references in Task.restriction.recipient for the bounded case where a fulfillment Task narrows a broader request, and to clarify Task.restriction and Task.restriction.recipient definitions/comments so Device manipulation without a broader order remains modeled through Task.focus and possibly Task.for.

Initial application:
The issue was applied before this reconciliation by git commit 6e879832cab88980e21d84ccb215ff42d466dd93, "Updated definitions for task.restriction and .restriction.recipient", which links to FHIR-28397 and changed source/task/structuredefinition-Task.xml. That commit replaced the Task.restriction comment, revised Task.restriction.recipient short/definition, added the explanatory Device comment, and added Device as a targetProfile. No existing AutoFHIR Issue-Reconcile-Key commit for FHIR-28397 was present on the combined branch before this audit.

Additional context:
Task is an active resource in source/fhir.ini, so source/task/structuredefinition-Task.xml is in current build scope. The originating Zulip thread shows the reporter raising the Device-recipient gap and Lloyd McKenzie asking for a change request because the use case had not been considered. FHIR Workflow minutes recorded a recommendation and transfer to OO, and OO minutes on 2025-10-09 included FHIR-28397 in a block vote that passed 11-0-3. A bounded Jira search for Task restriction recipient Device found no separate final issue requiring a different current source change.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the active Task StructureDefinition already has the approved Task.restriction comment, the revised Task.restriction.recipient short and definition, the Device-specific modeling comment, and Device in the recipient Reference targetProfile list.

Recommendation:
