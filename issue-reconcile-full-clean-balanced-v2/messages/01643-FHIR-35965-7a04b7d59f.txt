FHIR-35965: Audit external THO CodeSystem content fix

Issue request:
FHIR-35965 was Applied/Persuasive for HealthcareService terminology. It asked that the HL7-defined service-category and service-type CodeSystems stop using content=example and instead use content=complete, because the listed concepts are the complete contents of those CodeSystems even though the HealthcareService bindings may remain example-strength.

Initial application:
No FHIR-core commit was found that applied FHIR-35965 directly. The current core source contains the HealthcareService resource, example-strength bindings, and ValueSets that include http://terminology.hl7.org/CodeSystem/service-category and http://terminology.hl7.org/CodeSystem/service-type, but it does not contain the source CodeSystem-service-category.xml or CodeSystem-service-type.xml definitions that own the content flag.

Additional context:
The Jira comment trail says the work was included in UP-529. UP-529 is Proposal Implemented/Done and its change object list includes input/sourceOfTruth/fhir/codeSystems/CodeSystem-service-category.xml and CodeSystem-service-type.xml in the UTG/THO source. Current terminology.hl7.org JSON for both CodeSystems reports content=complete, and Confluence references show PA approval plus publication in THO version 5.5.0. The remaining core HealthcareService value set descriptions and example binding strengths are not the CodeSystem.content field and are consistent with Lloyd McKenzie's distinction in the Jira comments.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR-core source change. The required source-of-truth change was external to this checkout in UTG/THO and is already visible in the current published THO artifacts; changing the core ValueSets or example bindings would conflate the issue's CodeSystem.content request with separate binding semantics.

Recommendation:
Keep this audit commit as-is for core. If future work needs to change the service-category or service-type CodeSystem definitions themselves, do it in the UTG/THO source of truth rather than the FHIR-core checkout.
