FHIR-20639: Replace stale DeviceAssociation model-name examples

Issue request:
FHIR-20639 was a Published OO change request, resolved Persuasive with Modification for R5, asking for better Device.name.type definitions and replacement of the older DeviceNameType list with registered-name, user-friendly-name, and patient-reported-name, removing the other prior values such as manufacturer-name, model-name, and other.

Initial application:
The issue was applied in November 2021 by commits cae641cfad and c4a95b2b91, with merge dc516986c5 cited from Jira. Those commits replaced the DeviceNameType CodeSystem concepts and updated Device and DeviceDefinition name-type summaries/definitions to the approved three-code list.

Additional context:
Later FHIR-43164 intentionally changed Device.name.type and DeviceDefinition.deviceName.type to extensible CodeableConcept bindings with jurisdictional guidance, and later FHIR-47605 added the approved commercial-brand-family code. Those later decisions should remain. FHIR-40455 subsequently added active DeviceAssociation examples whose contained Device.name.type used the removed model-name code; no later Jira or community evidence found during this check restores model-name to the DeviceNameType code system.

AutoFHIR reconciliation:
Changed the six active DeviceAssociation examples that still used model-name in contained Device.name.type to use the current DeviceNameType system with user-friendly-name. DeviceAssociation is active in source/fhir.ini and these examples are registered in the active DeviceAssociation examples list, so the stale example codings were part of the current build surface.

Recommendation:
Keep this source fix. It preserves the later extensible binding and commercial-brand-family addition while removing the remaining current-build examples that contradicted FHIR-20639's removal of model-name.
