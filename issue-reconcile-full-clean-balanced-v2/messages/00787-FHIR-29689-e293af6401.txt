FHIR-29689: Audit Claim-family tax element application

Issue request:
FHIR-29689 was a Published/Persuasive Financial Management R5 change request asking to add tax support at Claim item/detail/subDetail, ClaimResponse addItem/detail/subDetail, and ExplanationOfBenefit item/detail/subDetail plus addItem/detail/subDetail. The approved resolution selected a single `.tax 0..1 Money` element for the affected structures, left tax breakdowns to extensions, and said jurisdictional implementation guides/profiles should handle jurisdiction-specific tax treatment.

Initial application:
No git commit message found in the current repository history explicitly names FHIR-29689. Commit 75e9d09e28 added the current Money tax elements to the three Claim structures, three ClaimResponse.addItem structures, and six ExplanationOfBenefit item/addItem structures. Later net-definition work, including FHIR-37594, clarified the same Claim-family .net elements after the tax additions.

Additional context:
FHIR-30926 is the tightly related later Published/Persuasive-with-Modification issue; its final comment says it has the same resolution as FHIR-29689 and its final resolution also narrows tax from a type/amount backbone to `.tax 0..1 Money`. FHIR-37594 is a later Published/Persuasive clarification for the same resources that states `Net = unit price * quantity * factor`, and the combined branch already contains the AutoFHIR FHIR-37594 requirements correction. The relevant Claim, ClaimResponse, and ExplanationOfBenefit resources are active current-build resources in source/fhir.ini.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current source already has the requested tax Money elements in all approved structures, the later net wording now reflects the current approved formula, and adding tax-type children or a separate diagnosisRelatedGroup tax element would go beyond the final FHIR-29689/FHIR-30926 source application.

Recommendation:
Keep this commit as-is. Future jurisdiction-specific tax-type breakdowns should be handled by profiles/extensions or a new tracker rather than changing the base resource now.
