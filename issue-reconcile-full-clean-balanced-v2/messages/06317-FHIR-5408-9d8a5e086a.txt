Initial application:
The issue was applied in historical git-svn commit db55db7414cc49a9bd93c668c9fd19c3de26fccf, matching Jira's svn ~4750 note. That commit changed source/condition/condition-spreadsheet.xml and related DAF/QICore Condition profile spreadsheets from Condition.dueTo.codeableConcept to Condition.dueTo.code, including the old dueto-code search parameter expression.

Additional context:
FHIR-5408 is the sibling typo issue encountered while investigating FHIR-5409. Later Published issues FHIR-7620 and FHIR-7621 moved Condition.dueTo and Condition.occurredFollowing out of the core Condition resource into extensions, and FHIR-10102 later changed those extensions from separate code/detail children to a choice of CodeableConcept or Reference. The current core Condition StructureDefinition no longer contains Condition.dueTo or the obsolete codeableConcept child path; it only references the condition-dueTo extension from Condition.evidence guidance. The current condition-dueTo definition lives in the FHIR Extension Pack and uses Extension.value[x] with CodeableConcept and Reference types.

Recommendation:
Keep this audit commit as-is. Do not reintroduce Condition.dueTo children in core; future changes to the moved condition-dueTo extension, if any, should be handled in the FHIR Extension Pack.
