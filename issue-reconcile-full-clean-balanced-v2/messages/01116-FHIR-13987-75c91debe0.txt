FHIR-13987: Audit Composition document declaration

Issue request:
FHIR-13987 was Published with a Persuasive with Modification resolution for STU3 Composition. It reported that Composition/$document was declared for both instance and type use even though the type-level [base]/Composition/$document form did not identify which Composition to use; the resolution said to add an id input parameter, and the issue comments treated the separate GraphDefinition parameter request as a duplicate of FHIR-13856.

Initial application:
The issue was applied historically. Jira records svn revision 13105, and git-svn commit 9b504f3a74 (GF#13987 - add Composition/$document.id) records the original application. The current XML source lineage also shows the old applied shape before FHIR-19974: Composition-document had type=true, instance=true, and a type-scoped id input parameter typed uri that could identify a local id or full URL.

Additional context:
The GraphDefinition part of the original request is already covered by FHIR-13856 and FHIR-14391, both represented on the combined branch with no-change audit commits; the active operation still has a 0..1 graph input parameter. Later, FHIR-19974 was Published with a Persuasive with Modification resolution for the same Composition/$document operation. SD minutes on 2023-02-09 approved removing the [base]/Composition/$document URL variant and id parameter because $document always requires an existing Composition resource. Commit 7f9f6257cc applied that later decision by setting type=false and removing the id parameter, while retaining instance=true and graph.

AutoFHIR reconciliation:
Made no source change. The active build source is source/composition/operationdefinition-Composition-document.xml, referenced through the active Composition resource and operation list; it now declares the operation as instance-only and therefore no longer has the incorrect type-level declaration that FHIR-13987 addressed. Re-adding the id parameter would contradict the later FHIR-19974 decision.

Recommendation:
Keep this audit commit. The current specification should remain instance-only for Composition/$document unless SD opens and resolves a new issue for a separate type-level or remote-Composition document-generation design.
