FHIR-18066: Audit ValueSet validate-code display output

Issue request:
FHIR-18066 was Published/Persuasive for the Vocabulary work group. It asked that the ValueSet $validate-code input display documentation stop saying a server may return a recommended display name in an extension in the outcome, because the operation already has an output display parameter, and instead refer to that display parameter.

Initial application:
The Jira comment points to git 66ae1e40f1bc02283363c872db14035fc795f8f7. That bulk terminology ballot reconciliation commit changed the ValueSet validate-code display wording in the then-authoritative source/valueset/valueset-spreadsheet.xml from "in an extension in the outcome" to "using the display parameter in the outcome". Later source refactoring preserved the wording in the current OperationDefinition XML source.

Additional context:
The current source/fhir.ini has an active valueset=ValueSet resource entry, so source/valueset/operationdefinition-ValueSet-validate-code.xml is in the current build scope for the ValueSet operation. A 2017 Zulip thread shows the old phrase was noticed in the ValueSet $validate-code display parameter discussion, and no Confluence reference or conflicting community decision was found. A similarly timed CodeSystem example issue in the same historical bulk commit is distinct and does not broaden this ValueSet-scoped reconciliation.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current ValueSet $validate-code input display documentation already says the server may return a recommended display name using the output display parameter, and that output display parameter is present in the same OperationDefinition.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-18066 unless a later work-group decision changes the ValueSet $validate-code output contract.
