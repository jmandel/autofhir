FHIR-16002: Audit NamingSystem duplicate id fix

Issue request:
FHIR-16002 was Published/Persuasive for STU3 and reported that the namingsystem-registry example Bundle contained two NamingSystem resources with id us-ssn; the resolution said to fix it because Medicare numbers are not SSNs.

Initial application:
No separate FHIR-16002-tagged source commit was found. The Jira comments say "already fixed", and the same defect had already been reported as FHIR-13300 and applied by git commit ae17b6dedb88d7f0bcecd9bdcebce023a07f49f5, which changed the old Medicare NamingSystem entry id from us-ssn to us-medicare.

Additional context:
The current source no longer includes source/namingsystem/namingsystem-registry.xml. FHIR-37889 later removed the NamingSystem registry and terminologies bundles from core examples because those registry contents duplicate information authoritatively maintained in HL7 Terminology. The active current build surface instead links the terminology module to identifier-registry.html and publishes the NamingSystem resource with individual examples only.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The historical duplicate was fixed before FHIR-16002 was resolved, and the current FHIR core build no longer contains the obsolete registry bundle where the duplicate existed.

Recommendation:
Keep this audit commit as-is. There is no current FHIR core source work for FHIR-16002; future changes to identifier-system registry content should be handled through the current HL7 Terminology/TSMG process or other external registry source, not by editing the removed core NamingSystem registry bundle.
