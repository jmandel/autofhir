Issue request:
FHIR-3827 was a Published/Persuasive Patient Care DSTU1 change request for ReferralRequest.status. It asked to add an accepted status meaning that the referral had been acknowledged and would be actioned later; the approved resolution was to add accepted because it was consistent with DiagnosticRequest.

Initial application:
Git commit b40ce8e28558ce4b7a692f4fa9b0ea24b8bd5c38, titled "{#5836} {#3827} Update ReferralRequest statuses", added accepted to the ReferralRequest.status value list and inserted the accepted code row with the definition that the recipient agreed to deliver the requested care. That same commit also completed the FHIR-5836 sent-to-requested rename in the same value set.

Additional context:
The current build no longer includes ReferralRequest as an active resource. source/fhir.ini lists ServiceRequest as active, lists ReferralRequest under removed resources, and records "ReferralRequest became ServiceRequest"; source/history.html also records ReferralRequest and ProcedureRequest becoming ServiceRequest. Current ServiceRequest.status uses the general RequestStatus value set and current ServiceRequest narrative describes acceptance/fulfillment behavior in the merged ServiceRequest/Task workflow rather than preserving the old ReferralRequest-specific accepted code.
