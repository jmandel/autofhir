FHIR-5604: Audit LOINC case-sensitivity guidance

Issue request:
FHIR-5604 was a Published/Persuasive FHIR-core ValueSet issue asking for a note clarifying whether LOINC filter values such as SCALE_TYP=DOC should be treated case sensitively. The accepted resolution was to add a case-sensitivity note to the LOINC description, with Jira comments recording confirmation from Dan Vreeman that LOINC is not case sensitive.

Initial application:
The issue was applied in git-svn commit b91df9d9ee0dc9afb102e2b3df25893c4cbd1743, corresponding to svn revision 4490. That commit added a Case Sensitivity section to source/loinc.html saying that LOINC codes and values were not case sensitive while implementers should maintain the correct case.

Additional context:
The old core source/loinc.html page was later removed by FHIR-35933 when the Vocabulary WG moved the “Using X with FHIR” external code system pages from FHIR core to HL7 Terminology (THO). The current FHIR core terminology systems page is build-scoped and links LOINC users to https://terminology.hl7.org/LOINC.html, whose current language explicitly says that LOINC codes, displays, and property values are not case sensitive. Current core LOINC metadata also has CodeSystem.caseSensitive=false, and current SCALE_TYP filters use LOINC part-code values rather than the old uppercase DOC string.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The original requested clarification was applied historically, the detailed LOINC guidance now lives in THO by later approved migration, and the current FHIR core source already directs implementers to that authoritative page while preserving case-insensitive LOINC metadata.

Recommendation:
Keep this audit commit as-is. Do not re-add a local LOINC case-sensitivity paragraph to FHIR core unless Vocabulary/TSMG later decides to move external code system guidance back out of THO; duplicating the THO guidance in core would create maintenance drift.
