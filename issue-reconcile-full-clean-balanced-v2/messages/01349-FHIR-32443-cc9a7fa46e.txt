FHIR-32443: Fix stale AuditEvent category names

Issue request:
FHIR-32443 was Published/Persuasive with Modification for the Security work group. It asked why AuditEvent.type was required while AuditEvent.subtype/code-level detail was optional, and the approved R5 resolution changed AuditEvent.type to category 0..* and AuditEvent.subtype to code 1..1 with example bindings and updated DICOM mapping intent.

Initial application:
The issue was applied by a4a8e4475ffed8a639ac458dba61b68da343891e together with FHIR-32440 and FHIR-32451. That commit renamed AuditEvent.type/subtype to AuditEvent.category/code, updated the AuditEvent search parameters, and changed the Provenance.activity mapping from AuditEvent.subtype to AuditEvent.code. Security minutes from 2021-08-09 and 2021-11-15 record the planned and built type/subtype to code/category change.

Additional context:
FHIR-44746 is a later Applied/Persuasive with Modification Security decision that explicitly reversed the R5 category/code model back to type/subtype for compatibility with the historic ASTM/IETF/DICOM/IHE audit model. The current branch already contains the FHIR-44746 reconciliation that restores AuditEvent.type/subtype DICOM aliases and mappings in the active AuditEvent StructureDefinition. AuditEvent and Provenance are active resources in source/fhir.ini, so their source files are in build scope. After the reversal, two non-generated source locations still used the obsolete category/code names: the AuditEvent notes page and the Provenance-to-AuditEvent mapping. The remaining category/code hits in source/fhir.ini are intentional cross-version mappings, and source/auditevent/auditevent.svg is a generated-looking diagram artifact that was not manually edited.

AutoFHIR reconciliation:
This commit updates source/auditevent/auditevent-notes.xml so the common scenario table and search-event guidance use the current type/subtype element names. It also updates source/provenance/structuredefinition-Provenance.xml so Provenance.activity maps to AuditEvent.subtype instead of the removed AuditEvent.code element.

Recommendation:
Keep this source fix. It reconciles the FHIR-32443 application with the later FHIR-44746 reversal while preserving the current type/subtype model; regenerate diagram artifacts through the normal build if the checked-in AuditEvent SVG is still consumed by publication tooling.
