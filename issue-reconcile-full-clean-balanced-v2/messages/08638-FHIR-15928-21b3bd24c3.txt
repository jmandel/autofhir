FHIR-15928: Audit logical-model root type invariant

Issue request:
FHIR-15928 was a Published/Persuasive FHIR-core StructureDefinition change request raised against STU3. It asked to loosen the differential root type invariant so a simple data element logical model could have a root element with a type; Jira comments clarified that the exception should apply to logical model roots generally, not only to single-element models.

Initial application:
The issue was applied before this reconciliation in git commit 4799a5bd47, whose message explicitly says it pre-applied StructureDefinition invariant fixes for #15928 and #15929 and whose git-svn id is build@13707, matching the Jira comment "SVN#13707". That commit changed the then-authoritative StructureDefinition spreadsheet so both the snapshot and differential root-type constraints were evaluated at StructureDefinition level and exempted logical models with kind!='logical'.

Additional context:
StructureDefinition is an active current-build resource in source/fhir.ini and is assigned to the conformance work group. The current XML source preserves the FHIR-15928 result: sdf-15a says a differential root without a dot has no type only when kind!='logical', and sdf-15 similarly permits a snapshot root type for logical models. The same 2018 application commit also handled FHIR-15929, which is already represented on the combined branch; broader logical-model StructureDefinition.type work such as FHIR-13331/FHIR-19762/FHIR-25777/FHIR-33065 supports the current logical-model exception rather than changing the FHIR-15928 conclusion. Jira, Zulip, and Confluence searches found no later conflicting decision for this issue.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The active current source already allows logical model root elements to carry a type by exempting logical models from the no-root-type snapshot and differential constraints, which is the substantive request in FHIR-15928.

Recommendation:
Keep this audit commit as-is. No current FHIR core source follow-up is needed for FHIR-15928 unless a future work-group decision changes how logical model root element types are constrained.
