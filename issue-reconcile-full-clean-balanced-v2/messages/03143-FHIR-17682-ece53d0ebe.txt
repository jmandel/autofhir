FHIR-17682: Audit FamilyMemberHistory no-information wording

Issue request:
FHIR-17682 was a Published/Persuasive Patient Care change request for FHIR-core FamilyHistory/FamilyMemberHistory. It asked to change the FamilyMemberHistory notes heading from "Reviewed, None Identified for a Family Member" to "Reviewed, No Information Available for a Family Member" because the old wording sounded too much like a no-known-history statement.

Initial application:
The issue appears to have been applied by commit 0b584258d4f5ad42f6385524e2c02866ea6c878e on 2019-02-18, whose message explicitly includes GF#17682 and whose patch changed that exact heading in source/familymemberhistory/familymemberhistory-notes.xml. Current blame still attributes the corrected heading to that commit.

Additional context:
FamilyMemberHistory is an active resource in source/fhir.ini, so its notes are in current build scope. Later Applied issue FHIR-55325 amended the same paragraph to mention FamilyMemberHistory.status health-unknown while preserving the corrected FHIR-17682 heading. FHIR-32901 discusses broader List-versus-FamilyMemberHistory guidance but remains Triaged, so it is not a final decision that reverses the FHIR-17682 wording. A 2017 Zulip thread shows confusion around the older "None Identified" wording, and no Confluence reference or later community evidence found here contradicts the published Jira decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already contains "Reviewed, No Information Available for a Family Member" in source/familymemberhistory/familymemberhistory-notes.xml and the obsolete exact heading "Reviewed, None Identified for a Family Member" is not present in current source.

Recommendation:
Keep this no-change audit commit as-is. Future work on the broader guidance should proceed through final decisions such as FHIR-55325 or any eventual disposition of FHIR-32901 rather than reopening the already-applied FHIR-17682 wording change.
