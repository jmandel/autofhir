FHIR-14864: Audit all-types terminology versioning

Issue request:
FHIR-14864 was a Published/Not Persuasive with Modification FHIR-I change request for the STU3 OperationDefinition/all-types terminology family. It argued that the normative all-types value set could not safely remain normative because future FHIR versions might rename immature resources such as BodySite to BodyStructure. The approved resolution kept the affected generated type terminology normative, but required explanatory text telling implementers that the definition is fixed while versioned code system contents can change across FHIR versions, with associated forwards/backwards compatibility implications.

Initial application:
The issue was applied in SVN revision 13090, represented in Git as 3e15b565783d5d32d9943f5be5b52d8bfb1af308 (GF#14864 - normative status of special internal terminologies). That commit added the res-status-special placeholder to the code system and value set templates and changed the all-types/data-types/resource-types binding descriptions to say they are lists defined by this version of FHIR. R4 generated artifacts then carried a valueset-special-status warning for all-types saying the normative value set is generated from this specification, the definition remains fixed across versions, and the actual contents change from version to version.

Additional context:
Current source has since refactored the old all-types family into fhir-types and related version-specific/version-independent type value sets. OperationDefinition.parameter.type and OperationDefinition.parameter.allowedType now bind to ValueSet/fhir-types with descriptions that explicitly say the allowed types are those defined in this version of FHIR. The fhir-types CodeSystem description carries the normative generated-content warning. FHIR-40706 later deprecated valueset-special-status; a prior reconciliation commit on the combined branch removed the deprecated extension use from the active fhir-types CodeSystem while preserving the same warning text in CodeSystem.description. Current source also has version-independent resource type value sets and fhir-old-types for deleted or renamed resource names such as BodySite.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source already preserves the FHIR-14864 implementer guidance through the fhir-types CodeSystem description and version-specific OperationDefinition binding descriptions, while the later FHIR-40706 cleanup explains why the old valueset-special-status mechanism should not be reintroduced.

Recommendation:
Keep this audit commit as-is. Do not re-add valueset-special-status or duplicate the warning on every fhir-types value set unless FHIR-I or Vocabulary makes a new decision; the current source conveys the version-specific terminology behavior without depending on the deprecated extension.
