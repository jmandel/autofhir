FHIR-25938: Audit official-address extension ownership

Issue request:
FHIR-25938 is a Published/Persuasive FHIR-core MnM change request for R5. It asked to revise the official address extension approved by FHIR-20743 so the extension can carry a required boolean assertion and an optional jurisdiction CodeableConcept, instead of mutually exclusive value choices, enabling assertions such as "not official in this country".

Initial application:
The request was applied in core by commit ce7674d793 ("fhir-25938"), which changed source/datatypes/address-extensions-spreadsheet.xml from a single officialAddress value choice to child rows officialAddress.valueBoolean 1..1 and officialAddress.valueCodeableConcept 0..*. That core spreadsheet is not a current build-scoped definition for this extension: current source/fhir.ini has no active address-extensions profile entry and current core source has no address-official or officialAddress definition. The old core row was also removed from the spreadsheet by dd468d4f17 ("remove extensions from R5 source") during the extension migration.

Additional context:
The canonical address-official definition now lives in the FHIR Extension Pack, not this FHIR core checkout. Related FHIR-extensions issues FHIR-43838 and FHIR-43840 reported that the approved extension was missing from the Extension Pack; extension-pack commits subsequently added input/definitions/datatypes/StructureDefinition-address-official.xml. However, the current Extension Pack source defines Extension.value[x]:valueBoolean and Extension.value[x]:valueCodeableConcept with min 0 rather than the FHIR-25938 complex-extension shape with a required boolean sub-extension. A 2024 Zulip implementers/shorthand thread confirms this current shape is interpreted as an exclusive choice, not as co-existing boolean plus jurisdiction components.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. Re-adding the extension to core would duplicate ownership that has moved to the FHIR Extension Pack, while the remaining semantic mismatch is in the Extension Pack definition.

Recommendation:
Keep this external-repo audit in core. Follow up in HL7/fhir-extensions by changing input/definitions/datatypes/StructureDefinition-address-official.xml to match FHIR-25938: a complex extension with a required boolean component and an optional, likely repeatable jurisdiction CodeableConcept component, with text preserving the note that repeating without jurisdiction is not useful.
