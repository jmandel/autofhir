FHIR-18354: Audit modifier extension understanding text

Issue request:
FHIR-18354 was a Published/Persuasive STU3 FHIR-core change request from FHIR-I asking the Extensibility page to clarify what it means for an application to understand a modifier extension. The requested clarification was that special logic is not always required: a developer may determine the modifier does not affect the system's computational functions, and that assessment must be repeated when computational behavior changes.

Initial application:
The issue was applied by git commit 777cc3bf72adffe5bcab147da93d662ae4e804b9, titled "GF#18354 - fix language", which changed source/extensibility.html to add the same clarification to the #1 explanation under modifierExtension processing.

Additional context:
source/extensibility.html is part of the current build navigation through source/hierarchy.xml and source/navigation.xml. Focused Jira, Zulip, and Confluence searches found no later issue, minutes, or discussion that conflicts with the applied wording. The current source uses "needs to be repeated" rather than the Jira description's proposed "must be repeated", but it preserves the accepted implementer meaning without creating a separate conformance expectation.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the active Extensibility source already says an application understands a modifier extension when appropriate handling instructions exist or the developer has determined that the modifier does not affect computational functions, and it already notes that the assessment needs to be repeated whenever computational behavior changes.
