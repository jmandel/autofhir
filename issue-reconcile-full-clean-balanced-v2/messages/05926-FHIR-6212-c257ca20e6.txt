FHIR-6212: Audit CarePlan example bindings

Issue request:
FHIR-6212 is Published/Persuasive for FHIR-core CarePlan. It asked to create at least example bindings for CarePlan.participant.role, CarePlan.activity.detail.code, CarePlan.activity.detail.reason, and CarePlan.activity.detail.statusReason, with the resolution to look for CarePlan DAM values as in FHIR-3123.

Initial application:
The Jira comment cites SVN #6813. Git commit 45a51719e6c526a6bf7df614e1b9f7d5f8c3b4bf is the imported SVN 6813 commit and added CarePlan example value sets, including participant-role, care-plan-activity, care-plan-category, and activity-reason, while changing the CarePlanParticipantRole binding from unbound to an example value set.

Additional context:
Later Patient Care decisions changed the active model. FHIR-9765 replaced CarePlan.participant with CarePlan.careTeam referencing CareTeam, where CareTeam.participant.role is still example-bound to http://hl7.org/fhir/ValueSet/participant-role. FHIR-26064 renamed activity.detail to plannedActivityDetail and FHIR-39101 then removed plannedActivityDetail from the active CarePlan model; the remaining XML block is commented out and is not an active element. FHIR-22729 later added the statusReason example binding and is already represented on the combined branch, as are FHIR-26064 and FHIR-39101.

AutoFHIR reconciliation:
This commit intentionally makes no source change. CarePlan and CareTeam are active resources in source/fhir.ini. The active current source no longer has CarePlan.participant.role or CarePlan.activity.detail.* elements requiring new bindings; the successor CareTeam.participant.role has the requested participant-role example binding, and the active CarePlan activity surfaces use CarePlan.activity.performedActivity with an example binding plus plannedActivityReference for requested activities.

Recommendation:
Keep this no-change audit. Reintroducing bindings on removed or commented CarePlan.activity.detail/plannedActivityDetail elements would be out of current build scope, and adding redundant prose would not improve implementer understanding. Any future change to activity detail bindings should first revisit the FHIR-39101 removal decision.
