FHIR-46465: Audit DeviceAssociation status scope resolution

Issue request:
FHIR-46465 was Applied as Persuasive with Modification for R6. It reported that DeviceAssociation.status had a required binding with values that only seemed applicable to implanted or patient-attached devices, even though DeviceAssociation is used for broader device associations. The final resolution says to use the disposition on FHIR-48532, which separates status from other association status values and pre-applies the change.

Initial application:
No source commit mentioning FHIR-46465 was found. The issue was effectively pre-applied by the FHIR-48532 implementation commit 2b906e8ba0, which changed DeviceAssociation.status to a required code value set for record status, made statusReason extensible, added DeviceAssociation.associationStatus with a preferred value set for physical and operational association states, and updated associated examples.

Additional context:
FHIR-48532 is the controlling Applied decision for the split and is audited in the parent commit from this worker. FHIR-51229 has the same resolution pattern and is already represented on the combined branch. FHIR-48713 completed the new associationStatus value set with the abandoned code and is also already represented on the combined branch. Confluence OO minutes for 2025-10-20, 2025-10-21, and 2025-10-24 identify FHIR-46465 as having the same disposition as FHIR-48532/FHIR-51229.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already resolves FHIR-46465's scope concern by removing implanted, explanted, attached, and similar association-state concepts from the required DeviceAssociation.status value set and exposing them through optional preferred DeviceAssociation.associationStatus instead.

Recommendation:
Keep this audit as-is for FHIR-46465. Future changes to DeviceAssociation terminology reuse or status modeling should wait for a final follow-up issue, not duplicate the already-applied FHIR-48532 split.
