FHIR-7853: Audit EpisodeOfCare v2 mapping decision

Issue request:
FHIR-7853 is a Published/Persuasive Patient Administration change request raised against DSTU1 and applied for R5. It asked for EpisodeOfCare HL7 v2 mappings because the Encounter mapping already mapped Encounter.episodeOfCare to PV1-54 and PV1-53 while the EpisodeOfCare mapping tab was blank.

Initial application:
No Jira-keyed source commit for FHIR-7853 was found. The Encounter side came from FHIR-5699, implemented by historical commit 454f90ad94, and the current Encounter source still maps Encounter.episodeOfCare to PV1-54 and PV1-53. EpisodeOfCare reached R5 and the current build without an HL7 v2 mapping identity or element mappings.

Additional context:
The FHIR-7853 discussion did not settle on concrete EpisodeOfCare element mappings. The later PA comment records that v2 mappings would be context-specific, a generalized mapping may not be practical, and EpisodeOfCare does not exist as a v2 segment or segment part. Direct Zulip and Confluence searches for FHIR-7853 and the key EpisodeOfCare/PV1 terms found no contrary community decision; broader Confluence hits point to external v2-to-FHIR mapping work rather than a core EpisodeOfCare mapping tab requirement.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Encounter and EpisodeOfCare are active build resources, Encounter retains the PV1-53/PV1-54 association mapping that triggered the issue, and leaving EpisodeOfCare without a core HL7 v2 mapping avoids inventing a generalized mapping that PA explicitly said may not be practical.

Recommendation:
Keep this audit commit as-is. If PA or the v2-to-FHIR project later wants context-specific EpisodeOfCare mappings, handle that as new scoped mapping work rather than adding a speculative core mapping from this 2015 tracker.
