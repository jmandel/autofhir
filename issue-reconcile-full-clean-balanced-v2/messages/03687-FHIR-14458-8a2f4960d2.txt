FHIR-14458: Audit AdverseEvent encounter context

Issue request:
Published / Persuasive with Modification Patient Care issue requesting AdverseEvent.context 0..1 Reference(EpisodeOfCare|Encounter), defined as the encounter or episode of care establishing the context for the AdverseEvent, with a usage note that the context is the encounter where the event occurred rather than a later reporting encounter.

Initial application:
The issue was applied by 1051f7d9e929, which added AdverseEvent.context as 0..1 Reference(Encounter|EpisodeOfCare) with the requested definition, usage note, and GF#14458 committee note in the then-authoritative AdverseEvent spreadsheet source.

Additional context:
Later Published / Persuasive with Modification issue FHIR-19511 changed Patient Care context elements, including AdverseEvent, from context to encounter as 0..1 Reference(Encounter), with EpisodeOfCare support handled by the workflow-episodeOfCare extension. Later Published / Persuasive issue FHIR-25397 clarified AdverseEvent.encounter wording to refer to the encounter associated with the start of the AdverseEvent and retained the seed's second-encounter usage distinction. The current core source is in build scope through active fhir.ini AdverseEvent entries, and the Extension Pack workflow-episodeOfCare definition includes AdverseEvent as an allowed context with value Reference(EpisodeOfCare). Existing combined-branch audits already represent FHIR-19511 and FHIR-25397, so this seed should not publish duplicate related issue commits.
