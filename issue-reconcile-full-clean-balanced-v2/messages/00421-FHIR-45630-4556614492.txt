FHIR-45630: Audit Measure terminology THO bindings

Issue request:
FHIR-45630 was an Applied/Persuasive CQI technical correction asking that draft code systems and value sets used by Measure and MeasureReport, specifically including measure scoring and measure population, be corrected. The final resolution was to ensure the affected profiles reference THO value sets rather than build-local FHIR value sets.

Initial application:
The issue was applied upstream by commit 54cef55bb369e0dd5fc4266fad08b4df6d30f37b, which is included in the current combined branch. That commit retargeted Measure and MeasureReport bindings for measure-type, measure-scoring, composite-measure-scoring, measure-improvement-notation, measure-population, measure-aggregate-method, and measure-data-usage to http://terminology.hl7.org/ValueSet/... canonicals and deleted the corresponding draft local Measure value set definitions. No prior AutoFHIR Issue-Reconcile-Key commit existed for FHIR-45630 on the combined branch.

Additional context:
Measure and MeasureReport are active current-build resources in source/fhir.ini. The current source still has some local Measure/MeasureReport example value sets, but they are active and are not the THO-owned value sets called out by this issue. The only remaining draft local measure value set found, measure-report-evaluation-type, is bound by Measure operation definitions rather than by the Measure or MeasureReport resource definitions identified in the Jira comments, so it is outside this seed's applied scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current combined source already binds Measure.group.population.code, MeasureReport.group.population.code, and MeasureReport.group.stratifier.stratum.population.code to http://terminology.hl7.org/ValueSet/measure-population, and the other affected Measure/MeasureReport bindings from the upstream application also point to THO.

Recommendation:
Keep this empty audit commit as-is. No FHIR core follow-up is needed for FHIR-45630 unless CQI separately decides to address operation-level terminology such as measure-report-evaluation-type.
