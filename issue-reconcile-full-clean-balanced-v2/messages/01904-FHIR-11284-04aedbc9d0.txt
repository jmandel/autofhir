FHIR-11284: Audit ImagingStudy radiology services procedure guidance

Issue request:
FHIR-11284 was a Published/Persuasive with Modification DSTU2 ImagingStudy ballot issue about the definition for the diagnostic requests that resulted in an imaging study. The commenter asked the definition to recognize that radiology services can use one procedure code for combined procedures, such as chest/abdomen CT or acute trauma series, and that RSNA/RadLex/LOINC procedure names may encode body-site structure. The final resolution said RadLex/LOINC are only potential value sources, many sites use local value sets, the current build no longer referenced LOINC, and existing text supported multiple levels of procedure-code granularity.

Initial application:
No commit explicitly mentioning FHIR-11284 or GF#11284 was found. The surrounding 2016-2017 ImagingStudy history shows the requested granularity was already represented in the spreadsheet source: ImagingStudy.basedOn retained the diagnostic-request definition with requirements text supporting grouped procedures, and commit d6c6d61a added separate ImagingStudy.procedureReference and ImagingStudy.procedureCode elements for procedure resources/codes. The closely adjacent FHIR-11285 commit b838ed23f removed the old LOINC radiology orderables comment from ImagingStudy.procedure, matching the FHIR-11284 resolution's concern that LOINC not be treated as the sole current guidance.

Additional context:
ImagingStudy is an active current-build resource in source/fhir.ini. Later current-source refactors replaced the old diagnostic-request wording with a broader ImagingStudy.basedOn definition and kept the core FHIR-11284 semantics: one imaging study may be based on multiple ordered procedures, with chest/abdomen/pelvis CT as the example, and the DICOM mapping includes Requested Procedure Code Sequence. Later Applied procedure-family issues, including FHIR-50894, FHIR-52026, and FHIR-53025, changed how requested and performed procedures are modeled in R6; FHIR-53025 is already represented on the combined branch and leaves the current source using ImagingStudy.procedure as Reference(Procedure) while ImagingStudy.basedOn points to the requested ServiceRequest. A stale generated-looking SVG tooltip still contains the old diagnostic-request definition, but the authoritative XML source is correct and this workflow's diagram guardrail does not justify a source-changing commit for an SVG-only remnant.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current build-scope ImagingStudy source already satisfies the Jira decision: it avoids RadLex/LOINC-specific procedure-code recommendations, supports grouped requested procedures at ImagingStudy.basedOn, separates requested procedure orders from performed Procedure references, and reflects the later R6 decisions that supersede the old DSTU2 element shapes.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is recommended for FHIR-11284 unless the Imaging Integration work group later decides to edit generated diagram tooltips or reintroduce explicit procedure-code value-set guidance.
