FHIR-48358: Audit applied Condition category changes

Issue request:
FHIR-48358 was Applied with a Persuasive with Modification resolution for R6. It asked Patient Care to add a diagnostic-report-impression category for Conditions expressed in diagnostic reports, change Condition.category's binding strength to example, and remove invariant con-2 about problem-list-item clinicalStatus not being unknown.

Initial application:
The core source change was applied by HL7/fhir commits 05e09e75b6ec and baa8cd72b035. The first PR attempt removed the con-2 warning but also renumbered remaining invariants; the later applied commit baa8cd72b035 kept stable con-3/con-4 numbering, changed Condition.category to example, removed con-2 references, and deleted the con-2 invariant test cases. UP-635 separately implemented the new diagnostic-report-impression code in THO's condition-category code system.

Additional context:
Condition is an active R6 resource in source/fhir.ini, and source/condition/structuredefinition-Condition.xml plus source/condition/valueset-condition-category.xml are therefore in build scope. Later FHIR-54454 clarified the Condition.category short display because the binding is now example and enumerating only selected codes in the short text would be misleading. The current THO 7.1.0 CodeSystem-condition-category includes diagnostic-report-impression with the requested definition, and the current FHIR value set continues to include all codes from that THO code system.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current FHIR source already reflects the two core changes: Condition.category has strength example and no con-2 condition reference, and no con-2 invariant remains in the Condition definition or invariant tests. The remaining code-system addition is external THO content and is already present in the current terminology publication consumed by the build.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for FHIR-48358; if future rendered expansions omit diagnostic-report-impression, investigate the build's terminology package/cache rather than changing the core ValueSet source.
