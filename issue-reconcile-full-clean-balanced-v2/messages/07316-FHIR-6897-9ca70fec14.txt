FHIR-6897: Audit retired DataElement scope clarification

Issue request:
FHIR-6897 was a Published/Persuasive with Modification OO clarification request from the 2015 May SDC ballot. It said the DataElement resource definition and use were unclear and asked to add Scope and Usage prose explaining that DataElement defined individual pieces of data that might be collected or stored, including FHIR elements, questionnaire questions, data-store elements, and non-FHIR specifications such as HL7 v2, CDA, and CDISC.

Initial application:
The issue was applied in historical source by commit cacb4626a33, which added the requested introductory paragraph to source/dataelement/dataelement-introduction.xml. Commit 0cabf5ff9d later made only link/text-style refinements to the same paragraph. Commit 33b409a4b6 later deleted the historical DataElement introduction source as part of the current build-source rework.

Additional context:
Later final work-group decision FHIR-13094 removed DataElement and replaced it with StructureDefinition logical models; that current-build cleanup is already represented on the combined branch by c1a07840fd. Current source confirms DataElement is commented out of source/fhir.ini, source/dataelement is absent, and source/history.html records DataElement as a removed resource. Current logical-model guidance now carries the non-FHIR data-modeling concept by explaining that logical models can be independent of FHIR resources and can be implemented in HL7 v2, CDA, SPL, GS1 XML, and other standards.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Restoring the old DataElement Scope and Usage sentence would revive guidance for a retired resource, while adding duplicate prose to StructureDefinition or logical-model pages is unnecessary because current active narrative already covers the surviving concept in the post-FHIR-13094 model.

Recommendation:
Keep this no-change audit. Future work should not revive DataElement-specific prose unless a work group creates a new current-resource clarification; any improvements should be framed around StructureDefinition logical models rather than the retired DataElement resource.
