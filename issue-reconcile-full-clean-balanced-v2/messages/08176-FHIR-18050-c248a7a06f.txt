FHIR-18050: Audit multi-version IG support

Issue request:
FHIR-18050 was Published/Persuasive with Modification for FHIR-core ImplementationGuide. It asked for implementation guides to support multiple FHIR target versions by making ImplementationGuide.fhirVersion repeatable, adding ImplementationGuide.definition.resource.fhirVersion 0..* with an invariant against the IG-level versions, adding a StructureDefinition applicable-version extension, and adding usage/package guidance for multi-version IGs.

Initial application:

Later source refactors moved the resource definition into source/implementationguide/structuredefinition-ImplementationGuide.xml, where the current build source carries the multi-version elements and invariant.

Additional context:
FHIR-17777, resolved immediately after FHIR-18050, made ImplementationGuide.fhirVersion mandatory as 1..* based on the prior decision to make it repeatable. That later published decision explains why current source should not be changed back to the 0..* minimum in the original FHIR-18050 resolution. FHIR-39186 later added cautionary multi-version IG tooling guidance and is already represented on the combined branch. FHIR-35168 later clarified fhirVersion wording and is already represented on the combined branch. FHIR-55168 is a 2026 Resolved - change required value set/binding follow-up and remains outside this default Applied/Published source-edit scope. The structuredefinition-applicable-version extension now lives in the FHIR Extension Pack, while the core IG definition links to it.
