FHIR-13131: Audit IG Publisher special URL handling

Issue request:
FHIR-13131 was a Published/Persuasive FHIR-core DSTU2 change request asking the IG Publisher to allow intentionally configured ValueSet definitions whose canonical URLs are external to the IG's canonical URL pattern, so existing value set URIs do not have to be reassigned when included in an IG.

Initial application:
The Jira comment says the issue was implemented in svn revision 11838. The corresponding git-svn commit, 28a392498d760100b188b72e49c05ee2958e7c84, added a `special-urls` configuration list to the then in-tree IG Publisher and replaced the former hard-coded URL-mismatch exceptions with an explicit `isListedURLExemption` check.

Additional context:
The in-tree IG Publisher was removed from this repository in 2019 because it moved to Maven. Current core source has no remaining ValueSet.url rule that requires the IG canonical URL pattern, and ImplementationGuide.definition.parameter explicitly treats parameters as tool-defined with an extensible binding. The current external tools package `hl7.fhir.uv.tools` defines `special-url` and `special-url-base` in `http://hl7.org/fhir/tools/CodeSystem/ig-parameters` with the same intentional-exception semantics.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR core source change. The requested behavior was applied historically in the in-repository IG Publisher, and the surviving authoritative definition now belongs to the IG Publisher/tools package rather than to this core checkout.

Recommendation:
Keep this audit commit as-is. If future work changes special URL handling, make that change in the IG Publisher/tools package and only update core if a current core resource or narrative becomes misleading.
