FHIR-50705: Fix stale vital signs category remnants

Issue request:
FHIR-50705 was an Applied/Persuasive OO R6 change request objecting that the R6 Vital Signs profiles appeared to move the profile-specific LOINC identifiers, such as body temperature 8310-5, from Observation.code into Observation.category. The accepted resolution says this is the same category-vs-code concern as FHIR-50689 and follows the already-applied decision from FHIR-45617: vital signs should not change from code to category for distinguishing the specific vital signs profiles.

Initial application:
No prior source commit explicitly named FHIR-50705. The relevant issue family was partially applied before this reconciliation: commit 0a17c0f40f introduced the temporary category-based value set/binding approach, then commit 66a80b5fef, applied for FHIR-45617 and later relied on by FHIR-50689/FHIR-50705, moved the "interoperability standard" LOINC identifiers back from Observation.category to Observation.code and removed the observation-vitalsign-category value set. That left the profile differentials mostly correct, but several active Text Summary/profile-summary extensions and two checked-in examples still described or demonstrated the specific LOINC code in Observation.category.

Additional context:
FHIR-50689 and FHIR-49953 make the same revert/backward-compatibility argument, while FHIR-50392 records the rejected alternative of using category for vital-sign-specific searching. The 2025-10-30 OO minutes record FHIR-50705 as Persuasive/Pre-applied, and the 2025-12 to 2026-01 Zulip thread that led to duplicate FHIR-54960 confirms the remaining Text Summary metadata was a missed cleanup after the change back from Observation.category to Observation.code. The edited files are in build scope because source/fhir.ini lists Observation as an active resource and source/observation/implementationguide-Observation-vitalsigns.xml includes the affected Vital Signs profiles and introduction.

AutoFHIR reconciliation:
This commit fixes the remaining source-backed contradiction. It updates the structuredefinition-summary/profile-summary metadata for each specific Vital Signs profile so the profile-specific LOINC requirement is described on Observation.code, removes stale LOINC category blocks from the Body Weight and BMI examples, and updates stale "interoperability category" wording in the Observation ballot note and related example comments. It does not change the already-correct profile differentials, which continue to fix only the broad vital-signs category and bind/pattern the specific LOINC identifiers on Observation.code.

Recommendation:
Keep this source-changing commit. It completes the FHIR-50705 reconciliation by eliminating the implementer-facing remnants that still suggested the rejected category model. Do not restore observation-vitalsign-category or put the specific vital-sign LOINC identifiers back in Observation.category; any remaining unrelated Vital Signs summary cleanup should be handled under its own tracker.
