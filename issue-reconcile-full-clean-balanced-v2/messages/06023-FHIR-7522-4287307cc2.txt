FHIR-7522: Audit National Provider Identifier URI

Issue request:
FHIR-7522 was a Published/Persuasive vocab change request from DSTU1 asking FHIR core to define a system URI for OID 2.16.840.1.113883.4.6, the US National Provider Identifier. The Jira resolution was "approve as edited," with a later comment noting that it was already done.

Initial application:
No commit explicitly mentions FHIR-7522, but the same NPI URI request was applied through companion issue FHIR-8047 in svn revision 6064, represented by git commit c8797d9ce12b17c991437850da507680fa9e7a45. That commit added the in-core NamingSystem registry entry for United States National Provider Identifier with preferred URI http://hl7.org/fhir/sid/us-npi and OID 2.16.840.1.113883.4.6.

Additional context:
FHIR-8047 is already represented on the combined branch by audit commit 490bdb506cd63a698e3fb92d7b483498e6e2fc93, so this reconciliation does not duplicate that issue. FHIR-37889 later removed the old in-core NamingSystem registry bundles because identifier and terminology registry content is authoritatively maintained in HL7 Terminology. Current core source keeps identifier-registry.html in the build hierarchy and directs implementers to terminology.hl7.org for active identifier systems. The current THO package contains NamingSystem/npi with the requested OID and preferred URI, and current core examples use http://hl7.org/fhir/sid/us-npi.

AutoFHIR reconciliation:
This audit commit makes no source change. Re-adding the removed core NamingSystem entry or adding NPI to terminologies-systems.html would be wrong for the current build: NPI is an Identifier.system, not a Coding system, and active identifier registry content now belongs in THO rather than in the retired core registry bundle.

Recommendation:
Keep this no-change audit commit as-is. Future corrections to NPI identifier metadata should be handled through THO/TSMG; no FHIR core source edit is needed for FHIR-7522.
