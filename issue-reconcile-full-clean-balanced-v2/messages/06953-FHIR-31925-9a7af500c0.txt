FHIR-31925: Audit If-Match weak ETag clarification

Issue request:
FHIR-31925 was Published/Persuasive for FHIR-core HTTP section 3.1.0.5. It asked the specification to explicitly acknowledge that FHIR's use of the HTTP If-Match header with weak ETags diverges from RFC 7232 section 3.1, and to specify the modified processing model if FHIR intended to keep that behavior.

Initial application:
The issue was applied before this reconciliation in git commit 639dbcd2848776be444488fe66b23438c581256d, "Multiple RESTful API (HTTP) page updates", which changed source/http.html. That commit replaced the generic ETag introduction in Managing Resource Contention with text noting that RFC 7232 requires the strong comparison function for If-Match and that FHIR diverges by using the weak ETag representation.

Additional context:
The current source/http.html is the authoritative current HTTP page source for the FHIR core RESTful API page. It still contains the RFC 7232 divergence note and the nearby model saying the ETag value SHALL match the resource version id, clients send If-Match with the quoted ETag, non-matches return 412 Precondition Failed, and servers may require If-Match with 400 Bad Request. The linked Zulip Weak ETags discussion records major server implementers supporting the current weak-ETag If-Match behavior and preferring not to change it. FHIR-I WGM 202109 minutes record the 16-0-0 Persuasive vote. Related FHIR-31927 was Resolved - No Change and explicitly says FHIR-31925 was resolved by noting the RFC variation and that no alternate resource-contention mechanism should be introduced.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current HTTP source already calls out the RFC divergence and specifies the FHIR processing model that uses the weak ETag/resource version id for If-Match contention handling, so another source edit would be redundant.

Recommendation:
Keep this audit commit as-is. Revisit only if a future work-group decision changes FHIR's weak ETag/If-Match model or adopts an alternate contention mechanism; FHIR-31925 itself is already correctly reflected in the current source.
