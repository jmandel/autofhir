FHIR-52919: Scope manufacturer operation composites

Issue request:
FHIR-52919 was Applied/Persuasive for R6 by BR&R. It asked to add search support for MedicinalProductDefinition.operation.organization and MedicinalProductDefinition.operation.type, including composite parameters that allow organization and type to be queried together on the same operation instance.

Initial application:
The issue was initially applied by upstream commit e444f101fb2f66bcd3b344bdd3cb37c250c54d3b, which added operation organization/type search parameters and the two composite parameters to the active MedicinalProductDefinition search-parameter bundle. Follow-up commits e4145c69af4693704a3cb3df7188c5c96728bb32 and e23a5d1fbec9ed11ff9d179f1fef4a1d91583fa4 added reference targets for Organization, ActivityDefinition, and PlanDefinition. The remaining problem was that the composites evaluated against the whole resource and used search-parameter codes as component sub-expressions.

Additional context:
source/fhir.ini actively registers medicinalproductdefinition as a current resource, so source/medicinalproductdefinition/bundle-MedicinalProductDefinition-search-params.xml is in build scope. SearchParameter.component.expression is defined as a sub-expression relative to the composite SearchParameter.expression, and existing composite patterns scope the parent expression to the repeating backbone element when component pairing must be instance-local.

AutoFHIR reconciliation:
This commit changes the two MedicinalProductDefinition operation composite search parameters to evaluate over MedicinalProductDefinition.operation and to use organization plus type.reference/type.concept as relative component expressions. It also points the component definitions at operation-type and operation-type-code, preserving the individual search parameters while making the composites implement the Jira-requested same-operation semantics.

Recommendation:
Keep this source fix. It is a narrow correction to the applied FHIR-52919 search parameters and does not require additional resource or terminology changes.
