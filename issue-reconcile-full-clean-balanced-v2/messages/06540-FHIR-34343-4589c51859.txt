FHIR-34343: Audit version-specific reference creation mechanism

Issue request:
FHIR-34343 was a Published FHIR-I R5 change request resolved Persuasive with Modification. It asked how to create version-specific references to resources whose ids or versions are assigned during transaction processing, without inventing invalid versioned urn:uuid or urn:oid temporary references. The approved resolution chose a new boolean standard extension, resolve-as-version-specific, limited to references within a transaction that target resources being created or updated in the same transaction; systems that apply it remove the extension, while unsupported systems leave a version-agnostic reference.

Initial application:
The source was initially applied by d5f982f6433fbb9bf79cf55ad9d6181f99e7d643, which added the transaction guidance to source/http.html and added the extension through the then-current Reference extension source. Current source has since been refactored so the extension definition is maintained in the FHIR Extension Pack rather than as a core extension definition.

Additional context:
FHIR-34344 made the companion clarification that existing version-specific references are expected to point to already-existing versions and removed the earlier "arbitrarily chosen version references" wording. FHIR-38648 fixed a broken extension link and duplicate narrative in the same HTTP section, FHIR-38649 broadened the extension context to uri and url in the Extension Pack, and FHIR-43600 added a Provenance-oriented transaction example using the same extension. Those related issue-reconcile keys are already represented on the combined branch, so this commit only audits FHIR-34343.

AutoFHIR reconciliation:
No source change was made. The active HTTP transaction page now points to the Extension Pack resolve-as-version-specific definition and states the transaction-only semantics, fallback behavior, and removal requirement required by FHIR-34343. The Extension Pack definition is active, boolean, 0..1, and scoped to Reference with the same transaction limitation, with later uri/url context expansion preserved. The transaction Bundle example demonstrates use of the extension on Provenance.target references.

Recommendation:
Keep this no-change audit commit. The current core source and Extension Pack definition implement the issue family correctly, and additional edits in core would duplicate or risk drifting from the maintained extension definition. Future work should only revisit this if FHIR-I changes the transaction-only semantics or moves Extension Pack ownership again.
