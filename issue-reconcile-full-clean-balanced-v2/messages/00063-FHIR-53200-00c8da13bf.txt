FHIR-53200: Complete PaymentReconciliation processNote alignment

Issue request:
FHIR-53200 was Applied/Persuasive for R6 by FM. It asked to match PaymentReconciliation.processNote to ClaimResponse and add a 0..* allocation-level note reference so allocations can point to process notes.

Initial application:
The Jira-tagged implementation commit 4291efa10d83fd2679fc5c5b3f6113795298ee98, merged by HL7/fhir#3796, added PaymentReconciliation.allocation.noteNumber plus processNote.class and processNote.number. That left the source only partially aligned with ClaimResponse because PaymentReconciliation.processNote.type stayed a required code, text stayed 0..1, language was absent, and the explicit backbone type name remained plural.

Additional context:
PaymentReconciliation is an active current-build resource in source/fhir.ini. ClaimResponse is the requested comparison target and currently defines processNote as Note with class, number, CodeableConcept/extensible type, required markdown text, and optional language. Related history shows the ClaimResponse shape came from applied/published FM decisions such as FHIR-31678, FHIR-50483, and FHIR-39562/FHIR-39586. Negative Zulip and Confluence searches found no conflicting community guidance.

AutoFHIR reconciliation:
This commit completes the remaining PaymentReconciliation.processNote structural alignment to ClaimResponse by changing the backbone type name to Note, changing processNote.type to CodeableConcept with an extensible note-type binding, making processNote.text 1..1, and adding processNote.language with the same language binding pattern. The PaymentReconciliation example was updated from primitive code syntax to CodeableConcept syntax for processNote.type so it remains valid.

Recommendation:
Keep this source fix. It is a focused completion of the applied Jira request in an active resource and avoids touching generated SVG output; future generated artifacts should be refreshed by the normal build pipeline.
