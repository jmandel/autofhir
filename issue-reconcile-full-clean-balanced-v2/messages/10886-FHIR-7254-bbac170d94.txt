FHIR-7254: Audit Device UDI jurisdiction representation

Issue request:
FHIR-7254 was a Published, Persuasive with Modification OO change request from the DSTU1 ballot. It objected that Device.udi:string did not identify the UDI repository or jurisdiction, and the accepted direction was to move away from a bare string toward a representation that could carry a system/repository, ultimately under the udiCarrier name with udi, barcodeString, and rfidString aliases.

Initial application:
The issue was explicitly applied in git commit 22debf21aa4d990db2d0d76b70d03098cd30c040, whose subject says it changed device.udi to device.udiCarrier and made the type Identifier to allow the repository to be identified for #7254. That commit updated the then-current Device spreadsheet and examples from a simple udi value to udiCarrier with system/value. The exact DSTU-era Identifier shape has since been superseded by later Device UDI modeling work.

Additional context:
Device is an active current-build resource in source/fhir.ini, and source/device/structuredefinition-Device.xml is the authoritative current Device StructureDefinition. Current source defines Device.udiCarrier as a backbone, not a simple string, and carries separate deviceIdentifier, deviceIdentifierSystem, issuer, jurisdiction, carrierHRF/carrierAIDC, and entryType fields. Closely related Published issue FHIR-11106, which asks the same jurisdiction-from-string question for DSTU2, is already represented on the combined branch by ef24c9ea8c6cc938e962e593023af82d975e955f. Later Published/Applied issues FHIR-32553 and FHIR-43063 refined issuer/jurisdiction URI examples and added deviceIdentifierSystem without reverting to Identifier; those issues are also already represented on the combined branch. FHIR-51533 remains Waiting for Input about THO/NamingSystem registration and is not final enough to alter this reconciliation.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build already satisfies the semantic intent of FHIR-7254: UDI data is no longer a bare string, and the Device UDI model has explicit fields for jurisdiction/repository authority and issuing/identifier systems. Re-changing current udiCarrier.deviceIdentifier to Identifier or adding redundant guidance under this DSTU1 issue would conflict with later OO decisions and create maintenance risk.

Recommendation:
Keep this audit commit as-is for FHIR-7254. Do not make further core source changes for this seed unless a new final OO/terminology decision addresses the unresolved NamingSystem/THO questions or reverses the later choice to keep deviceIdentifier as string plus deviceIdentifierSystem.
