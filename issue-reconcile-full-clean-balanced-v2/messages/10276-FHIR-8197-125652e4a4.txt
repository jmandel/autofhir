FHIR-8197: Audit binding table display

Issue request:
FHIR-8197 was a Published/Persuasive 2015 May QICore/FHIR-core profiles ballot issue for FHIR-I. It asked that profile snapshot and differential tables stop displaying binding names as links, and instead show the bound value set and binding strength because the binding name was only a proxy for the value set/strength pair.

Initial application:
The Jira comments say the tooling work was complete by June 2015 and that binding name was no longer used by the tooling. Git history confirms an explicit application trail: commit a0c86f58839ffdc694fbb01d7d2745415befba5c began the FHIR-8197 work to remove ElementDefinition.binding.name, commit 216e4ce2427c0ee58e3cfd57d6e2514bda11f58f made ValueSet the master binding object, commit 896fee1a61e637f03c63c8e9bcb141909b5aa6bf finished removing the table/rendering dependency on binding name by rendering the ValueSet name when available, and commit fbaf29fb043878886a33392fb9a1017135ef9fed later removed the formal ElementDefinition.binding.name row from the ElementDefinition datatype source.

Additional context:
ElementDefinition remains active current FHIR-core build input through source/fhir.ini. Current source/datatypes/elementdefinition.xml defines ElementDefinition.binding with strength, description, valueSet, and additional binding children, but no binding.name child. Current source/terminologies.html explains that the formal binding properties are strength, description, and valueSet, and that a binding name is only a non-processing convenience extension. The old QICore IG entry that motivated the sample URL is commented out in source/igs.xml, while related binding-name follow-up issues FHIR-7530, FHIR-12510, and FHIR-51990 are already represented on the combined branch and should not be duplicated.

AutoFHIR reconciliation:
This commit makes no source change. The current core source and current rendered binding examples already convey the requested behavior: bindings expose and render the value set and strength rather than relying on a formal binding-name element or binding-name link.

Recommendation:
Keep this no-change audit commit. No further FHIR-core work is needed for FHIR-8197; future questions about the separate elementdefinition-bindingName extension should stay with the already-audited FHIR-12510/FHIR-51990 extension-pack issue family.
