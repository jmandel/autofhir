FHIR-3262: Audit ValueSet metadata cardinalities

Issue request:
FHIR-3262 was Published/Persuasive for DSTU1. It asked that ValueSet.name and ValueSet.description stop being mandatory base elements because those fields are good-practice metadata rather than universally required content, with guidance or a shareable ValueSet profile available for externally published value sets.

Initial application:
The issue was explicitly applied by git-svn commit 4d8eb62cdb (svn r2927), which changed source/valueset/valueset-spreadsheet.xml so ValueSet.name and ValueSet.description had 0..1 cardinality and added usage notes saying names/descriptions should normally be supplied except for contained or context-local value sets.

Additional context:
The current source has since been refactored from the DSTU1 spreadsheet into source/valueset/structuredefinition-ValueSet.xml, but the applied optional cardinalities and SHOULD-level usage guidance are still present. Later ShareableValueSet decisions, including FHIR-29943, FHIR-31395, and FHIR-37959, changed the separate profile story: current core no longer contains an active ShareableValueSet StructureDefinition or ValueSet profile entry, and current shareable-pattern text points implementers to CRMI for the migrated profiles.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because the active ValueSet resource definition already has min=0 for ValueSet.name and ValueSet.description, includes the intended usage guidance, and there is no current core ShareableValueSet profile artifact that should be edited or restored for this DSTU1 issue.

Recommendation:
Keep this audit commit as-is. Do not re-tighten the base ValueSet metadata cardinalities, and do not reintroduce the removed core ShareableValueSet profile under FHIR-3262; future profile-definition changes belong in CRMI or in a new tracker that explicitly reverses the later profile-migration decisions.
