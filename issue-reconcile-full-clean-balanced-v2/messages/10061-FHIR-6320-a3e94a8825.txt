FHIR-6320: Audit default/missing distinction

Issue request:
FHIR-6320 was Published/Persuasive with Modification for DSTU1. It asked for ElementDefinition.defaultValue[x] and ElementDefinition.meaningWhenMissing to be distinguished with concrete examples, noted that defaultValue was preferred over meaningWhenMissing at that time, and asked why meaningWhenMissing was not appearing in generated profiles.

Initial application:
The issue was applied in two historical git-svn commits. Commit 950a889bea53656c82aebb7cd3365fa09e9625cc / svn revision 5494 copied meaningWhenMissing into generated profile elements. Commit bdabe8e8bd3c1f71a4c5c0c9f39880207fdafa49 / svn revision 6387 added the clarifying examples and comments to the ElementDefinition spreadsheet source.

Additional context:
ElementDefinition is an active datatype in source/fhir.ini, and elementdefinition=elementdefinition makes source/elementdefinition.html the current datatype page. Later FHIR-15121 and related FHIR-I minutes/Zulip discussion changed the broader policy: defaultValue[x] is retained for logical models, discouraged/forbidden for ordinary FHIR resources and profiles, while meaningWhenMissing remains the mechanism for implicit missing semantics that profiles cannot change. Related default/missing issues in this family, including FHIR-15121, FHIR-13337, and FHIR-16934, are already represented on the combined branch or were no-change background decisions.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/datatypes/elementdefinition.xml already distinguishes defaultValue[x] from meaningWhenMissing: defaultValue[x] says the value is assumed if absent, gives the abstract-is-false example, explains the implementation hazards, and confines default values to logical models; meaningWhenMissing says it is an implicit missing meaning, gives the period-ongoing example, and states that missing meanings can only be set in definitions and not changed in profiles. Current source/elementdefinition.html also explains missing elements, extension-only/no-value elements, profile immutability of missing meaning, the generated default/missing list, and why FHIR resources and datatypes do not define default values. The issue's specific example semantics are still present in current successor source rows for Period.end, Quantity.comparator, and ValueSet.expansion.contains.abstract.

Recommendation:
Keep this audit commit as-is. The current build-scope source already conveys the required distinction after later default/missing policy decisions; adding redundant prose for FHIR-6320 would risk conflicting with FHIR-15121-era guidance rather than improving implementer understanding.
