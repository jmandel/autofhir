FHIR-16455: Audit canonical reverse references

Issue request:
FHIR-16455 is a Published/Persuasive FHIR-core correction asking that the generated resources-that-use-this-resource list include resources that reference a target by canonical URL, not only by Reference.

Initial application:
Jira records Grahame Grieve's November 2018 comments that the issue had been fixed. No Jira-keyed git commit for FHIR-16455 was found on the current repository history, and the old in-repo Java publisher code that historically generated these lists has since moved out of this checkout into the Kindling dependency.

Additional context:
The active resource-page templates still include the <%resref%> generated section, and source/fhir.ini lists the checked resources as active build resources. Current source contains canonical targetProfile references such as ActivityDefinition.library, ClinicalUseDefinition.library, Measure.library, and PlanDefinition.library targeting Library, and the current CI build renders these as Resource References on Library. StructureDefinition similarly renders canonical-driven reverse references such as ActivityDefinition.profile, CapabilityStatement profiles, ElementDefinition profiles/targetProfiles, ImplementationGuide profiles, OperationDefinition targetProfile, PlanDefinition typeCanonical, and StructureDefinition.baseDefinition.

AutoFHIR reconciliation:
This is an empty audit commit. No FHIR source edit is needed because the current built specification already includes canonical references in the reverse-reference section, and the relevant generator implementation is supplied by the external Kindling build dependency rather than editable source in this checkout.

Recommendation:
Keep this audit commit as-is. Revisit only if a future generated build drops canonical entries from the References to this Resource / Resource References section; any generator-level fix would likely belong in HL7/kindling before updating the FHIR build dependency.
