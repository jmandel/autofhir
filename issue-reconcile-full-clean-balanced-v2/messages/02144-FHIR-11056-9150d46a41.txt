FHIR-11056: Audit Consent securityLabel definition

Issue request:
FHIR-11056 was Published/Persuasive with Modification for FHIR-core Consent. It asked to replace the DSTU2 Consent.except.securityLabel definition, "A set of security labels that define which resources are controlled by this exception. If more than one label is specified, all resources must have all the specified labels," with "A security label, comprised of 0..* security label fields (Privacy tags), which define which resources are controlled by this exception."

Initial application:
The issue was applied by historical commit 0f594b3938a50781639ecd7fa5930288595d9bfe, whose subject explicitly says it made definition and comment changes for CR 11055 and CR 11056. That commit changed the old Consent spreadsheet source from the rejected "set of security labels" wording to the approved singular security-label definition. Later source refactors carried the wording into the current StructureDefinition source as Consent.provision.securityLabel.

Additional context:
Consent is an active current-build resource in source/fhir.ini, and source/consent/structuredefinition-Consent.xml is the current authoritative StructureDefinition input. The DSTU2 element name Consent.except.securityLabel is now represented as Consent.provision.securityLabel. A later already-published FHIR-36354 reconciliation updated only the element comment about hierarchical confidentiality labels; it did not change the FHIR-11056 definition, which remains present and correct. Related FHIR-11055 explains the purpose-of-use sentence now present in the same comment, and FHIR-10707 records that no narrower security-label value set was adopted.
