FHIR-16427: Audit ValueSet extensible extension migration

Issue request:
FHIR-16427 was a Published/Persuasive Vocab change request against STU3 ValueSet asking why ValueSet.extensible was a core ValueSet element and resolving to remove extensible from the core resource and make it an extension until there was sufficient implementation experience.

Initial application:
The Jira comment cites svn revision 14125. In git this is be8de212ff, "GF#16427 - move ValueSet.extensible to an extension", which removed the ValueSet.extensible row from the ValueSet spreadsheet, added the valueset-extensible extension definition to the then-current ValueSet extensions spreadsheet, and converted the UCUM common ValueSet instance to use the extension URL.

Additional context:
The current build has since migrated ValueSet from spreadsheet source to source/valueset/structuredefinition-ValueSet.xml. That active ValueSet resource source contains no ValueSet.extensible element, while source/fhir.ini still actively lists valueset=ValueSet. The valueset-extensible extension definition is now maintained in the FHIR Extension Pack at input/definitions/ValueSet/StructureDefinition-valueset-extensible.xml, with context ValueSet and boolean value, so its absence as a core resource element is intentional rather than a missing core edit. The STU3/R4 history page still records the ValueSet.extensible move for FHIR-16427.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current core source already removed the ValueSet.extensible element, current examples use the extension URL where applicable, and the extension definition exists in the Extension Pack rather than as a current core resource element.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-16427; any future metadata changes to the valueset-extensible extension should be handled in the Extension Pack rather than by reintroducing a core ValueSet element.
