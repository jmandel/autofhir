FHIR-23924: Audit manufactured item quantity relocation

Issue request:
FHIR-23924 was a Published FHIR-core BR&R change request, resolved Persuasive with Modification for R5, asking how to model 100-, 60-, and 30-tablet package configurations that share the same manufactured item. The approved resolution was that the count belongs on the referring package item in PackagedProductDefinition, not on the referred ManufacturedItemDefinition, because an item should not count itself.

Initial application:
There was no explicit FHIR-23924-tagged source commit found. The same September 2019 Zulip discussion that prompted the Jira was followed immediately by source-history changes: 6f506840ae changed the packaged-product source so the count moved to the packaged level, 7512379e82 removed ManufacturedItemDefinition.quantity and added a contained item with an amount, and b0893a67ea added narrative explaining that one ManufacturedItemDefinition can be reused by package definitions with different numeric quantities.

Additional context:
The current R5/R6-era resource names are ManufacturedItemDefinition and PackagedProductDefinition, with source/fhir.ini redirecting the old MedicinalProductManufactured and MedicinalProductPackaged names. Both current resources are active build inputs. A later Published issue, FHIR-39130, confirmed the same model by rejecting a quantity on ManufacturedItemDefinition and clarifying that PackagedProductDefinition.packaging.containedItem.amount is where item amount or continuous quantity belongs.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current source already has no ManufacturedItemDefinition.quantity element, defines PackagedProductDefinition.packaging.containedItem.amount for the number or quantity of the contained item, and includes module/resource narrative plus examples that show package-level quantities for contained manufactured items.

Recommendation:
Keep this no-change audit as-is. No core source follow-up is needed for FHIR-23924; related package-quantity clarifications such as FHIR-39130 can be audited separately if they are assigned as their own reconciliation seeds.
