FHIR-11036: Audit complex-extension modifier wording

Issue request:
FHIR-11036 was a Published/Persuasive with Modification FHIR-core extensibility issue raised against DSTU2. It asked to clarify confusing prose explaining that complex extensions may have nested extension elements marked isModifier and that those internal modifier elements are carried as extension rather than modifierExtension. The voted resolution was to use Ewout Kramer's proposed wording.

Initial application:
The issue appears to have been applied by git commit ff03a14ae8e8334436a8c416f7f2da8a87fb0f29, whose subject explicitly included #11036 and which changed source/extensibility.html to Ewout's suggested clarification. That commit introduced the core wording that complex extension parts marked modifier=true modify the extension value itself, are represented using extension rather than modifierExtension, and that a modifierExtension defined outside an extension cannot be placed in another extension.

Additional context:
source/fhir.ini maps extension=extensibility, so source/extensibility.html is in the current build surface. FHIR-18352 later refined the last sentence from the FHIR-11036 wording to "Is-modifier elements not defined as part of an extension's definition cannot be conveyed," implemented by git commit 1932b2b59558a616c0ca6d62c123b1c92dc6e15f. The current source keeps that later wording, plus minor subsequent editorial refinements, without changing the FHIR-11036 rule. FHIR-18352 is already represented on the combined branch by its own Issue-Reconcile-Key commit, so this audit does not duplicate it.

AutoFHIR reconciliation:
This empty commit makes no source change. Current source/extensibility.html already states the approved clarification in current terminology: complex extension parts may be Is-Modifier=true, those internal parts are still represented as extension rather than modifierExtension, and is-modifier elements not defined as part of the extension definition cannot be conveyed inside the extension.

Recommendation:
Keep this no-change audit commit. The current active source is semantically consistent with FHIR-11036 after the later FHIR-18352 wording refinement, and additional local edits would only restate or risk drifting from the existing normative guidance.
