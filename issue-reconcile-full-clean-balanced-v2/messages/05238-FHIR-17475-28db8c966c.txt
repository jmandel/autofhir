FHIR-17475: Audit ValueSet metadata-only form

Issue request:
FHIR-17475 was Published/Persuasive with Modification for STU3 and asked to remove ValueSet invariant VSD-5 because it required at least one of .compose or .expansion, conflicting with ValueSet?_summary=true responses that legitimately return only metadata for large extensional value sets. The accepted resolution was to remove VSD-5 and add guidance about the use cases for both, either, or neither of .compose and .expansion.

Initial application:
The Jira says the resolution was pre-applied in svn 14497. The git-svn commit 37b0ae652bb936957e6a8ccbecdcc8a17e97d6e4 implements that application: it removes invariant 5 from source/valueset/valueset-spreadsheet.xml, removes VSD-5 from the compose and expansion condition lists, and adds the source/valueset/valueset-notes.xml section describing the valid combinations of .compose and .expansion.

Additional context:
ValueSet is an active build-scope resource in source/fhir.ini. The current ValueSet StructureDefinition source has no VSD-5 invariant and keeps both ValueSet.compose and ValueSet.expansion at 0..1, so a metadata-only ValueSet instance is not prohibited by the conformance source. Current narrative preserves the added combinations section, explicitly saying that neither .compose nor .expansion is a valid ValueSet format and that summary search is a primary use case; later FHIR-18677 source text also repeats the metadata-only allowance in the introduction. Zulip discussion for the linked terminology thread and the GF#17475 topic supports removing the invariant rather than treating _summary resources as invalid. No Confluence reference was found that changes that conclusion.

AutoFHIR reconciliation:
No source change was made. The current build-scope source already reflects the accepted FHIR-17475 change: VSD-5 is absent, ValueSet.compose and ValueSet.expansion are optional, and the ValueSet narrative documents compose-only, expansion-only, both, and metadata-only forms.

Recommendation:
Keep this no-change audit commit as-is. No follow-up core edit is recommended unless a future Vocabulary work group decision revisits metadata-only ValueSet or summary-search validation semantics.
