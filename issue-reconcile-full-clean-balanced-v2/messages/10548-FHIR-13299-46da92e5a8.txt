FHIR-13299: Audit differential extension ordering renderer

Issue request:
FHIR-13299 was a Published/Persuasive FHIR-core change request for STU3 asking that generated differential views show extension and modifierExtension rows where they belong in element order instead of moving them to the end, because implementers were following the differential table order when writing instances.

Initial application:
The issue was applied in SVN revision 13122, represented in git as c8b51e7adc717c021f5702d4505547e949496327. That commit changed implementations/java/org.hl7.fhir.r4/src/org/hl7/fhir/r4/conformance/ProfileUtilities.java by disabling the differential-only logic that skipped extension rows during normal child traversal and appended them after the other children. The Jira comment records the same SVN revision.

Additional context:
The old in-repo ProfileUtilities.java renderer was later deleted during the build/tooling refactors; current HEAD no longer contains that Java source. The current FHIR build runs org.hl7.fhir.tools.publisher.Publisher from the external org.hl7.fhir:kindling dependency declared in build.gradle.kts, with the relevant model/rendering utilities supplied by dependency artifacts rather than editable source in this checkout. Jira, Zulip, and Confluence searches found no later FHIR-core decision that reverses the ordering request.

AutoFHIR reconciliation:
This commit intentionally makes no source change in HL7/fhir. The issue's historical source change was applied, and the current checkout has no authoritative local source file for the differential table renderer; any future correction to this behavior belongs in the Kindling/FHIR tooling dependency rather than in a spec source file here.

Recommendation:
Keep this audit commit as-is for the core repository. If a current build demonstrates that differential extension rows are again ordered incorrectly, open or apply the fix in the external Kindling/FHIR tooling source and then update the dependency used by this repository.
