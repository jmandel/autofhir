FHIR-9797: Audit div type enforcement

Issue request:
FHIR-9797 was a Published/Persuasive DSTU2 FHIR-I change request asking that the FHIR build tool enforce that an element named 'div' is only used for Narrative.div, so format converters can treat div as the narrative XHTML element without consulting schema every time.

Initial application:
The issue was applied before this reconciliation. The Jira comments record Grahame Grieve's 2018 note that the change was "already done", and historical commit 0c4049e17d (#9797 - enforce rule on type of element if named 'div') added the ResourceValidator rule that any element named div must have type xhtml.

Additional context:
The current core source checkout no longer carries the Java build-tool source; build.gradle.kts runs org.hl7.fhir.tools.publisher.Publisher from the external org.hl7.fhir:kindling dependency. The current HL7/kindling ResourceValidator still contains the same div/xhtml rule. In the current core source, source/fhir.ini keeps Narrative in the active infrastructure datatype set, source/datatypes/narrative.xml defines Narrative.div with type xhtml, and a source scan found no other element-definition rows ending in .div.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source and current external build-tool rule already satisfy the published issue, and editing core source would either be redundant or target code that is no longer in this checkout.

Recommendation:
Keep this no-change audit commit. If a future regression is found in build-tool enforcement, address it in HL7/kindling rather than in the core FHIR source checkout; no current core follow-up is needed for FHIR-9797.
