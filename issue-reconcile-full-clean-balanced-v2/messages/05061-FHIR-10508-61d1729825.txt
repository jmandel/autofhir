FHIR-10508: Audit FamilyMemberHistory event wording

Issue request:
FHIR-10508 was a Published/Persuasive Patient Care change request for DSTU2. It reported that the FamilyMemberHistory introduction said the resource recorded significant health "events and conditions" even though the rest of the resource only described conditions, and the approved resolution was to remove the health-event references from the introduction and resource summary wording.

Initial application:
The current branch has no commit whose message spells the key as FHIR-10508, but git history shows f2c04069bb with "#10508 updated FamilyMemberHistory intro". That commit changed source/familymemberhistory/familymemberhistory-introduction.xml from "significant health events and conditions" to "significant health conditions". The later source rework in 33b409a4b6 carried the same conditions-only resource description into the active StructureDefinition source.

Additional context:
FamilyMemberHistory is active in source/fhir.ini. The current introduction still says FamilyMemberHistory is a FHIR workflow event resource, which is a different technical use of "event" and not the obsolete health-events phrase targeted by the Jira. The notes page contains a List.emptyReason example mentioning "conditions or significant events" for the full family member history list, but that text is about the List scope and does not undermine the resolved introduction wording. Community searches found the original Zulip report matching the Jira concern and no direct Confluence reference or conflicting work-group record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active FamilyMemberHistory introduction and StructureDefinition already implement the Published Jira request by describing significant health conditions without the obsolete "events and conditions" wording.

Recommendation:
Keep this audit commit as-is. Do not remove unrelated workflow-event terminology or the List-scope notes text under this issue; any broader cleanup of family history List guidance should be handled by a separate final work-group decision.
