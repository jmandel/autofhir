FHIR-32647: Audit superseded EvidenceVariable combination change

Issue request:
FHIR-32647 was Published/Persuasive with Modification for R5. It asked to replace the old EvidenceVariable.characteristicCombination code with a more flexible combination representation so combinations beyond simple intersection/union could be expressed, and the final resolution specified a backbone with code, threshold, all-of/any-of/at-least/at-most/net-effect codes, and threshold requirements.

Initial application:
The issue was initially applied by bac01125124ef5d906e86c9f6d75340772380ce2, a Jira-tagged 2021 commit for J#32647 and related EvidenceVariable items. That commit changed source/evidencevariable/structuredefinition-EvidenceVariable.xml from the old two-code characteristicCombination element to a backbone with code and threshold, and updated the EvidenceVariable characteristic-combination code system from intersection/union to all-of, any-of, at-least, at-most, and net-effect.

Additional context:
Later final R5 and R6 decisions superseded the original source target. FHIR-36131, Published/Persuasive with Modification, explicitly proceeded with eligibility-criteria Option 2 and removed EvidenceVariable.characteristicCombination, replacing the combination model with EvidenceVariable.characteristic.definitionByCombination. FHIR-41583 then added Group.combinationMethod and Group.combinationThreshold for conceptual cohort/group definitions. FHIR-42886, Applied/Persuasive with Modification, made Group the preferred resource for defining combinations of characteristics and removed EvidenceVariable.characteristic entirely in favor of EvidenceVariable.definition as a CodeableReference to Group. Current source/fhir.ini keeps EvidenceVariable and Group active, but the current EvidenceVariable StructureDefinition has no characteristicCombination or definitionByCombination element; the remaining built combination elements are Group.combinationMethod and Group.combinationThreshold.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Recreating the removed EvidenceVariable characteristicCombination structure, converting current Group.combinationMethod to CodeableConcept, or changing the current Group value set/invariant behavior would be a new current Group/EvidenceVariable semantics decision, not completion of this already-applied R5 EvidenceVariable issue.

Recommendation:
Keep this no-change audit commit. If CDS/FHIR-I want additional current constraints on Group.combinationThreshold or want net-effect/statistical/dataset-style combination semantics to be valid Group.combinationMethod values, open or apply a current Group/EvidenceVariable tracker rather than treating that as missing application of FHIR-32647.
