FHIR-5503: Audit Device UDI type guidance

Issue request:
FHIR-5503 was a Published/Persuasive with Modification OO change request from the January 2015 DSTU1 ballot. It asked the Device type notes to clarify possible coding sources such as local UDI repositories/GUDID while making clear that the full UDI string belongs in the dedicated Device UDI element rather than in Device.type.

Initial application:
Commit 85cad2a017a228c70b358dab887c56b5bfccb18e pre-applied FHIR-5503 together with related Device UDI ballot comments FHIR-5849, FHIR-5505, and FHIR-5506 before the 2015-03-26 OO block vote. It replaced the proposed full-UDI-in-Device.type wording with a Device Types paragraph that pointed full UDI strings at Device.udi and revised the UDI notes around jurisdictional repositories and DI/PI components.

Additional context:
Device is active in the current build through source/fhir.ini. Several originally related artifacts are no longer active current resources: DeviceComponent is commented/dropped, DeviceObservationReport and DeviceUseRequest are removed resources, and DeviceUseStatement redirects to DeviceUsage. Later final Device decisions superseded the old DSTU1 Device.udi string with the current Device.udiCarrier backbone, UDI mapping guidance, and examples. Related AutoFHIR commits for FHIR-5849, FHIR-5505, and FHIR-7590 already reconciled the coupled UDI-scope, repository-wording, and Device.type GMDN-binding implications without requiring another FHIR-5503 source edit.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current Device notes distinguish identifier/type coding from UDI carrier content: Device.type guidance lists SNOMED CT, GMDN, and RTM as type-code sources, while the UDI section says the full UDI carrier is represented through Device.udiCarrier and points to UDI mappings and examples. The current source therefore preserves the substance of FHIR-5503 after later model changes.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-5503; future UDI changes should be handled against the current Device.udiCarrier and DeviceDefinition model rather than by restoring old Device.udi or full-UDI-in-Device.type wording.
