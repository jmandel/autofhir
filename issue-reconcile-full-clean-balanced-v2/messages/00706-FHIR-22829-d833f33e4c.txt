FHIR-22829: Audit moved secondary-finding terminology

Issue request:
FHIR-22829 is Published/Persuasive for FHIR core and asked Clinical Genomics to correct the copied Observation Category Codes name/title on the Secondary Findings code system and value set, applied for R5.

Initial application:
The issue was applied in PR #1844, merged as 801c1796fa4098cda164c71a298abb645d180312, with implementation commit 985c5e919ceecdfdd60410ee01edfae3c70c5af1. That patch corrected the secondary-finding ValueSet name/title from ObservationCategoryCodes/Observation Category Codes to GeneticObservationSecondaryFindings/Genetic Observation Secondary Findings and fixed the same description typo in the CodeSystem, ValueSet, and extension binding; the CodeSystem name/title were already GeneticObservationSecondaryFindings/Genetic Observation Secondary Findings before that patch.

Additional context:
CG minutes for 2020-08-18 record the 10-0-0 block-vote acceptance for FHIR-22829 and also list FHIR-20165, a same-meeting Published/Persuasive decision to remove deprecated genomics artifacts from core for R5. Current core no longer contains the secondary-finding CodeSystem, ValueSet, or observation-secondaryFinding StructureDefinition as active source or fhir.ini entries; commit dd468d4f1799dd79819315b211588ef1cf4586e0 later deleted those core files as part of removing extensions from R5 source. The current FHIR Extension Pack contains the secondary-finding CodeSystem and ValueSet with non-Observation Category names/titles, and the extension is now deprecated there.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. Reintroducing or editing secondary-finding terminology in core would be out of current build scope, and the external Extension Pack definitions already preserve the FHIR-22829 correction.

Recommendation:
Keep this external-repo audit commit as-is. No core follow-up is needed for FHIR-22829; if future secondary-finding wording changes are required, they should be evaluated in the FHIR Extension Pack rather than by restoring the removed core files.
