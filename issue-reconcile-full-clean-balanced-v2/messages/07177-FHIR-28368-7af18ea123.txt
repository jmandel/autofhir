FHIR-28368: Audit Java validator download link

Issue request:
FHIR-28368 was Published with a Persuasive resolution for R5. The issue reported that the FHIR-core downloads page linked the official FHIR validator to the obsolete https://storage.googleapis.com/ig-build/org.hl7.fhir.validator.jar location instead of the then-current https://github.com/hapifhir/org.hl7.fhir.core/releases/latest/download/validator_cli.jar download.

Initial application:
The requested link update had already been applied before this reconciliation in commit 021fdd52eec1b71a39014469ed6df9dbb3804995, which changed source/downloads.html from the Google Storage validator JAR URL to the GitHub validator_cli.jar URL. That commit also updated the IG Publisher link from Google Storage to its GitHub release download.

Additional context:
The original issue was filed from the #implementers Zulip "Validation Time" thread, where Shovan Roy identified the obsolete validator link on https://www.hl7.org/fhir/downloads.html and Oliver Egger replied that he had added Jira FHIR#28368 for the link. Later R5-era FHIR-31735 work, applied by commit 472abf78c495c2ae44924d499be7434ed50788d0 and audited on the combined branch as FHIR-31735, removed the direct validator and IG Publisher rows from source/downloads.html and replaced mutable tool download listings with a link to the Confluence FHIR Tools Registry. Current source/validation.html likewise points implementers to that registry for FHIR validators. source/hierarchy.xml lists downloads.html and validation.html as active built pages.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source no longer contains the obsolete Google Storage validator URL or the now-superseded direct validator_cli.jar downloads-page row. The active downloads and validation pages direct implementers to the Confluence FHIR Tools Registry, which is consistent with the later FHIR-31735 handoff for mutable tooling information.

Recommendation:
Keep this no-change audit commit as-is for core FHIR. If validator download details need future maintenance, update the Confluence tools/validator documentation rather than reintroducing a direct mutable validator JAR link on the core downloads page.
