FHIR-36559: Audit operation code naming clarification

Issue request:
FHIR-36559 was a Published/Persuasive FHIR-core Conformance clarification asking that CapabilityStatement.rest.resource.operation.name no longer say it should match the "name" in the referenced definition, but instead should match OperationDefinition.code, excluding the leading "$" used in invocation URLs.

Initial application:
The request was applied by commit c8699bf5f86615762e4416ae0ce944e5fcc8cf70 and merged by HL7/fhir#1841 as 71d8cab9195e3c91758a12058b2264734c5b7377. That change updated source/capabilitystatement/structuredefinition-CapabilityStatement.xml so the comment points to OperationDefinition.code rather than OperationDefinition.name.

Additional context:
CapabilityStatement is an active resource in source/fhir.ini, so its StructureDefinition source is in the current build. A later same-family Published issue, FHIR-34234, expanded the same element's definition/comment to explain that CapabilityStatement operation.name usually follows OperationDefinition.code but may differ for disambiguation, and preserved the FHIR-36559 correction. Zulip discussion and FHIR-I minutes confirm the clarification intent and vote.

AutoFHIR reconciliation:
No source change was made because the current active source already says CapabilityStatement.rest.resource.operation.name SHOULD match OperationDefinition.code in the referenced/defining OperationDefinition, retains the note excluding the "$" URL prefix, and adds later clarifying context without contradicting FHIR-36559.

Recommendation:
Keep this no-change audit commit as-is. No FHIR-core follow-up is needed for FHIR-36559 unless a future work group decision revisits CapabilityStatement operation naming more broadly.
