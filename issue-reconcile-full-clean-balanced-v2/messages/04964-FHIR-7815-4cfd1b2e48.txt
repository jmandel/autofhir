FHIR-7815: Audit MedicationRequest timing mapping

Issue request:
FHIR-7815 was a Published/Persuasive Pharmacy change request from the 2015 DSTU QA process. It asked to remove the v2 message-type-level mapping for MedicationPrescription.dosageInstruction/scheduled[x] from RDS:TQ1 and replace it with the segment/field mapping TQ1-X / ORC Quantity/timing, because RDS is a dispense event message type and the mapping should target v2 segments/fields rather than message types.

Initial application:
The issue appears to have been applied by commit 651364cb098a623c36afc1d6b9d56578507d897c, which explicitly listed tracker item 7815 and changed the then-active MedicationOrder dosageInstruction timing mapping from RDS:TQ1 to TQ1-X / ORC Quantity/timing. No separate FHIR-7815 audit commit already existed on the combined branch before this reconciliation.

Additional context:
MedicationPrescription was mechanically renamed to MedicationOrder in 2015, and the current build now uses MedicationRequest. Later dosage refactoring moved the dosage timing mapping out of the medication resource into the shared Dosage/DosageInstruction datatype; current source/fhir.ini keeps both dosage and MedicationRequest in build scope. Current MedicationRequest.dosageInstruction is a DosageDetails, DosageDetails.step.component is Dosage, and Dosage.timing still carries TQ1-X / ORC Quantity/timing. The exact obsolete RDS:TQ1 mapping is absent from current source.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active datatype source preserves the applied replacement mapping in the correct shared location, and adding duplicate MedicationRequest-local text would be redundant after the datatype refactors.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-7815 unless the Pharmacy work group later chooses to revise the broader v2 dosage timing mapping policy.
