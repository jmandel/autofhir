FHIR-8382: Audit Patient example identifier code

Issue request:
FHIR-8382 was a Published/Persuasive PA change request for DSTU1 reporting that patient-example.xml used the v2-0203 identifier type code "MRN" where Table 0203 uses "MR" for a medical record number. The recorded resolution says validation was tightened and many examples were fixed.

Initial application:
The Jira comment cites SVN revision 5745. In the git-svn history, commit 7db4a5ac4a (#8382 - fix up for invalid codes, build@5745) changed source/patient/patient-example.xml from <code value="MRN"/> to <code value="MR"/> and made the same invalid-code cleanup across multiple examples and terminology/service code paths.

Additional context:
Patient is an active resource in source/fhir.ini, and source/patient/list-Patient-examples.xml includes the Patient/example instance. Current source/patient/patient-example.xml uses http://terminology.hl7.org/CodeSystem/v2-0203 with code MR. A current-source scan found no v2-0203 MRN use under source/patient. The only remaining v2-0203 MRN match is in source/servicedefinition/evaluate-operation-request-example.xml; source/fhir.ini lists ServiceDefinition under [removed-resources] and has only a commented note saying it was dropped, so that stale folder is not a current core build fix for this Patient issue. Patient $merge text examples using code MRN use a local hospital code system, not v2-0203.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active Patient example and active Patient example list already reflect the Jira-required MR code, and editing the removed ServiceDefinition source would be outside the current build scope for this seed.

Recommendation:
Keep this audit commit as-is for FHIR-8382. If removed ServiceDefinition materials are ever revived or migrated, separately review source/servicedefinition/evaluate-operation-request-example.xml for the stale v2-0203 MRN code; it should not drive a current FHIR-core Patient reconciliation change.
