FHIR-31663: Add DiagnosticReport note to ModelInfo

Issue request:
FHIR-31663 is a Published/Persuasive FHIR-core OO change request for R5. It asked to add DiagnosticReport.note as 0..* Annotation, aligning DiagnosticReport with Observation for report-level notes.

Initial application:
The issue was applied in the main DiagnosticReport StructureDefinition by the Jira-linked merge commit 5b47128e2201e8e3a0ad0b8247aecedcc884385c from PR #1423. The underlying commits added DiagnosticReport.note, corrected its definition punctuation, and the current source still has the requested element. That initial application did not update the active FHIR ModelInfo Library example, which still omitted DiagnosticReport.note.

Additional context:
OO Confluence minutes record both the initial request to create a Jira for adding .note of type Annotation to DiagnosticReport and the May 2021 WGM 24-0-0 motion. The related coded-annotation work for genomics reporting and Annotation typing was tracked separately in FHIR-31662 and FHIR-31541, so this reconciliation is limited to the core DiagnosticReport element. Later FHIR-43443 re-added a workflow mapping from DiagnosticReport.note to Event.note and is already represented on the combined branch; that later mapping does not change the seed issue's required element or datatype. DiagnosticReport and Library are active in source/fhir.ini, list-Library-examples.xml includes Library/FHIR-ModelInfo, library-examples-header.xml links the readable model-definition content, and publish.ini copies the ModelInfo sidecar.

AutoFHIR reconciliation:
Updated source/library/library-fhir-model-definition-content.xml so the DiagnosticReport ModelInfo class exposes a repeating note element with elementType FHIR.Annotation immediately after result. Refreshed source/library/library-fhir-model-definition.xml so its embedded base64 Library.data payload exactly matches the edited ModelInfo content. No DiagnosticReport StructureDefinition change was needed because that authoritative resource source already contains DiagnosticReport.note as 0..* Annotation.

Recommendation:
Keep this source fix. It completes the Published FHIR-31663 change across the active ModelInfo publication surface while preserving the already-correct DiagnosticReport resource definition and leaving related coded-annotation extension decisions to their own Jira records.
