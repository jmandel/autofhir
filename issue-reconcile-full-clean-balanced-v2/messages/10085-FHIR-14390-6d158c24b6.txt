FHIR-14390: Audit :contains search modifier wording

Issue request:
FHIR-14390 was a Published/Persuasive FHIR-core search issue for STU3. It requested fixing the search modifiers text so the default string search behavior says partial matches occur at the start of the string, not the end; the Jira resolution was "Fix" and the issue comment records svn revision 13371.

Initial application:
The issue was applied before this reconciliation by git-svn commit 69d393e31ed270a6e8bcacd1289574fa2209fea3, "GF#14390 - fix typo", which changed source/search.html from "partial matches at the end of the string" to "partial matches at the start of the string" and records build@13371.

Additional context:
Later search modifier work rewrote the old modifier list into fuller sections. The current build-scope source/search.html no longer contains either old quoted phrase, but it now states that default string search matches when a field equals or starts with the supplied value, and that :contains matches anywhere within the field. The active search modifier code system also defines contains as matching anywhere within the searched field or supported hierarchy. A directly related 2018 Zulip thread confirms the intended meaning was "anywhere in the string, not just starts-with or ends-with"; Confluence searches found no conflicting record.

AutoFHIR reconciliation:
This commit intentionally makes no source change because the current source already preserves the approved correction and no parallel source artifact still carries the erroneous "end of the string" wording.

Recommendation:
Keep this audit commit as-is. No follow-up source change is needed for FHIR-14390 unless future search-page edits reintroduce the old default-string wording.
