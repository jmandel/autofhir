FHIR-26671: Audit normative-version context widening

Issue request:
FHIR-26671 was a Published/Persuasive with Modification FHIR-I change request raised against R4. It reported that the structuredefinition-normative-version extension was constrained to StructureDefinition even though the spec used it on OperationDefinition/other canonical artifacts and ElementDefinition entries; the final decision was to allow ElementDefinition and any canonical resource, with the value meaning the FHIR specification version in which the artifact first became normative.

Initial application:
No source commit in this checkout explicitly mentions FHIR-26671. The historical core extension source introduced by 33b409a4b6d already had the widened contexts, CanonicalResource and ElementDefinition, and that definition was later removed from core by dd468d4f17 when extensions moved out of the R5 source. The current core checkout no longer contains an active source definition for the extension, but it still uses the extension on build-scoped normative artifacts such as CanonicalResource and OperationDefinition instances.

Additional context:
The originating Zulip thread and the 2020-07-27 FHIR-I minutes match the Jira disposition: the context was too narrow and should be expanded to ElementDefinition and canonical resources. The authoritative current definition now lives in the FHIR Extension Pack, where input/definitions/multiple/StructureDefinition-structuredefinition-normative-version.xml contains both context expressions. The companion CodeSystem $lookup rendering/status issue, FHIR-26672, is already represented separately on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The current authoritative extension definition already has the approved contexts, and adding or recreating a core-side extension definition would duplicate source that has intentionally moved to the Extension Pack.

Recommendation:
Keep this no-change audit commit. No FHIR core source follow-up is needed for the context widening; if the work group wants to broaden the extension's title/description from StructureDefinition-specific wording to artifact wording, that would be a separate Extension Pack editorial cleanup rather than a missing core application of FHIR-26671.
