FHIR-33978: Audit Resource identity URL wording

Issue request:
FHIR-33978 was a Published FHIR-core change request with a Persuasive resolution. It asked that the Resource Scope and Usage bullet stop saying a resource has a known identity "(a URL)" and instead say only that it has a known identity by which it can be addressed, because the Logical ID text already allows non-RESTful contexts where no standard URL can be constructed.

Initial application:
The issue appears to have been applied by commit a21a613cf4878c0e7d5777c70c1bae48593dfd73, "Strike \"(a URL)\"", which changed source/resource/resource-introduction.xml from "has a known identity (a URL) by which it can be addressed" to "has a known identity by which it can be addressed". The Jira comment records the fix as submitted in HL7/fhir#1934, which was merged on 2022-08-03.

Additional context:
source/resource/resource-introduction.xml is part of the current Resource page source, with source/fhir.ini listing Resource in the active resource/type-page metadata and normative package metadata. The nearby Logical ID text still explains that resources may lack a RESTful-server location and may be identified by other identifiers, so the page is internally consistent. The reporter's parenthetical note about adding an article to "associated with location" remains editorial rather than a semantic source gap, and the explicit requested/voted change was the URL parenthetical removal. The related FHIR-33979 developer-overview wording issue is already represented on the combined branch by commit 774d894561750d360ac5787f7c5f5d8a1f38f18e. Zulip and Confluence searches found no directly relevant discussion or later conflicting decision for FHIR-33978.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Resource Scope and Usage bullet exactly preserves the requested meaning without implying that URL identity is intrinsic to every resource, and the surrounding Resource page continues to support non-RESTful or identifier-based contexts.

Recommendation:
Keep this audit commit as-is. No further core source work is needed for FHIR-33978 unless the work group later chooses to reopen broader resource identity wording beyond the Resource page bullet.
