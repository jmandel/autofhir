FHIR-33006: Audit EpisodeOfCare diagnosis CodeableReference

Issue request:
FHIR-33006 was a Published/Persuasive PA change request for R5 asking that EpisodeOfCare.diagnosis.condition become CodeableReference so a diagnosis could be exchanged as either a Condition reference or a CodeableConcept. The resolution also required an example binding to the existing Condition.code value set.

Initial application:
The change was applied in the source history by three August 8, 2022 commits that mention FHIR-33006: 1e7af11fdd06 changed EpisodeOfCare.diagnosis.condition from Reference to CodeableReference and added the condition-code example binding, while 65d8bfd85126 and b412b43a95c0 updated the EpisodeOfCare diagnosis search parameters for the reference and concept branches.

Additional context:
EpisodeOfCare is an active resource in source/fhir.ini, so source/episodeofcare/structuredefinition-EpisodeOfCare.xml and source/episodeofcare/bundle-EpisodeOfCare-search-params.xml are in current build scope. A later Published/Persuasive PA issue, FHIR-35863, harmonized EpisodeOfCare.diagnosis with Encounter in commit 084c723e1409; it changed surrounding wording/cardinalities and search parameter names but retained CodeableReference, the Condition target, and the condition-code example binding.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current source/episodeofcare/structuredefinition-EpisodeOfCare.xml defines EpisodeOfCare.diagnosis.condition as CodeableReference targeting Condition with an example binding to http://hl7.org/fhir/ValueSet/condition-code, and the current search parameter bundle exposes the concept and reference branches as diagnosis-code and diagnosis-reference.

Recommendation:
Keep this commit as-is. The current source already satisfies FHIR-33006 after considering the original implementation commits and the later FHIR-35863 harmonization; redundant source edits would not change implementer understanding.
