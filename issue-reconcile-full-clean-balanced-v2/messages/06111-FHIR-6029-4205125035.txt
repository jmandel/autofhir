FHIR-6029: Audit ConceptMap equivalence definitions

Issue request:
FHIR-6029 was Published/Persuasive for FHIR-core ConceptMap. It asked for more precise definitions of the old ConceptMapEquivalence codes equal, subsumes, specialises/specializes, and disjoint: equal should be symmetric, reflexive, and transitive; subsumes and specializes should be reflexive and transitive; equal should imply both subsumes and specializes; subsumes and specializes should be converse relationships; and disjoint should be symmetric but not transitive.

Initial application:
The issue was applied in git commit 5f4ac00ba3a00f87dba07ba0dac2c30d4a2aa2a3, which is the migrated svn revision 5694 cited in the Jira comments. That commit updated the ConceptMap spreadsheet spelling and added terminology binding comments stating the accepted relationship properties for equivalent/equal, subsumes, specializes, and disjoint. Later ConceptMap source history preserved those comments through the R5 relationship-code transition, but the current build no longer uses the old ConceptMapEquivalence code system as the active ConceptMap binding.

Additional context:
FHIR-22632 later replaced ConceptMap.group.element.target.equivalence with ConceptMap.group.element.target.relationship, introduced the ConceptMapRelationship code system/value set, and retired the old ConceptMapEquivalence artifacts; that issue is already represented on the combined branch. FHIR-25923 then approved explicit source-to-target relationship code names, and FHIR-29946 added relationship-refinement guidance; both are also already represented on the combined branch. FHIR-16367 and FHIR-16372 show later no-change cleanup requests against the old equivalence value set because that value set was superseded by the R5 relationship model.

AutoFHIR reconciliation:
This commit intentionally makes no source change. ConceptMap is active in source/fhir.ini, and the current active ConceptMap source binds target.relationship and unmapped.relationship to ConceptMapRelationship, with the current source-to-target code definitions in source/conceptmap/codesystem-concept-map-relationship.xml. The original FHIR-6029 target code system is not an active current ConceptMap source artifact beyond legacy OID/model-library references, so re-editing old ConceptMapEquivalence definitions would be out of scope and re-opening the current relationship semantics would duplicate already-published related issues.

Recommendation:
Keep this no-change audit commit. No current core source change is needed for FHIR-6029; any future change to the current ConceptMapRelationship semantics, including whether relationship-code comments should be computable or published, should be handled through a new work-group decision rather than this DSTU1 equivalence-code issue.
