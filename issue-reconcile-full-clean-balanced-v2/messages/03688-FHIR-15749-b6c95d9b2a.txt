FHIR-15749: Audit RequestGroup action priority

Issue request:
FHIR-15749 was a Published/Persuasive CDS change request for STU3 asking to add a priority element to RequestGroup.action, with the same need called out for PlanDefinition.action.

Initial application:
The request was applied in SVN/git import commit d366854435400372ecc374ea3bbf3330cfb854fa, which added RequestGroup.action.priority and PlanDefinition.action.priority rows with code type, RequestPriority binding, routine | urgent | asap | stat short text, and action-specific priority definitions. The current source no longer uses the original spreadsheet files, but the semantic additions survived into the generated StructureDefinition source.

Additional context:
RequestGroup was later renamed to RequestOrchestration by FHIR-24619, and commit 46bea37a00e63d1ace04a5f322614c6d0815f500 carried RequestGroup.action.priority forward as RequestOrchestration.action.priority. source/fhir.ini lists both plandefinition=PlanDefinition and requestorchestration=RequestOrchestration as active resources, while RequestGroup appears only among deleted/legacy resource names. No Zulip or Confluence evidence was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active PlanDefinition and RequestOrchestration StructureDefinitions already contain 0..1 action.priority elements using code, the required http://hl7.org/fhir/ValueSet/request-priority binding, and definitions indicating how quickly the action should be addressed with respect to other actions.

Recommendation:
Keep this audit commit as-is. No current core source change is needed for FHIR-15749 unless a future work group decision changes the RequestPriority semantics or removes the action-level priority elements.
