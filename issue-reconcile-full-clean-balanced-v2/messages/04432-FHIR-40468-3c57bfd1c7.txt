FHIR-40468: Audit contained resource position clarification

Issue request:
FHIR-40468 was a Published FHIR-I change request resolved Persuasive with Modification for R5. It asked to remove or clarify the contained-resource bullet in references.html because saying the contained element is located after narrative and before extensions incorrectly implies positional ordering in JSON.

Initial application:
The issue was applied by 4be70810dbeba46498ae4688e2d80b5be980a300, which changed source/references.html from the position-specific sentence to root-child wording for the contained element. The current source still contains that replacement text and searches found no remaining copy of the stale "after any text narrative and before any extension" wording.

Additional context:
FHIR-12500 introduced the older location wording in 2017, and the FHIR-40468 Zulip thread confirms the R5 problem was that implementers were reading it as a JSON order requirement. FHIR-I minutes on 2023-03-20 record the Persuasive with Modification vote for FHIR-40468. source/fhir.ini maps Reference to the references page, confirming source/references.html is in the current build scope for this guidance.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current references source already conveys that contained resources are represented with the contained element as a root child of a DomainResource, without retaining the JSON-invalid ordering language.

Recommendation:
Keep this audit commit as-is. No follow-up source edit is recommended for FHIR-40468; any future wording polish, such as adding code formatting around the word contained, would be editorial and not needed to satisfy this issue.
