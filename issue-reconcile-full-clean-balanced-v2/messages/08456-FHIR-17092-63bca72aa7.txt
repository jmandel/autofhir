FHIR-17092: Audit HTTP verb definitions

Issue request:
FHIR-17092 was a Published/Persuasive STU3 non-substantive FHIR-core clarification for the HTTP verb CodeSystem page. It asked that the terse HTTP verb definitions be made into real definitions and at least point readers to the HTTP specification, with GET proposed as "The GET operation as defined in the HTTP specification" and the same pattern for other verbs.

Initial application:
No current git commit was found that explicitly mentions FHIR-17092. Jira's only comment says the issue was already fixed. The matching source-history trail is the same HTTP verb work from FHIR-16078: commit f4da5602278eaa3576addcf3402cd8cf00b96a98 changed the historical Bundle spreadsheet's HTTPVerb description to add an HTTP RFC link and changed the individual definitions from terse labels such as "HTTP GET" to sentence-style definitions such as "HTTP GET Command". Commit 86a07e2f5a18780ff44c6ef3daf33f0e6a85f066 then updated that RFC link from RFC 2616 to RFC 7231, and later source refactors carried the terminology into the current standalone CodeSystem and ValueSet XML files.

Additional context:
Bundle is active in source/fhir.ini, and the current Bundle source binds Bundle.entry.request.method to ValueSet/http-verb. Current source/bundle/codesystem-http-verb.xml defines CodeSystem/http-verb with the RFC 7231 link in the description and per-code definitions for GET, HEAD, POST, PUT, DELETE, and PATCH. Current source/bundle/valueset-http-verb.xml carries the same HTTP RFC description for the ValueSet. Focused Jira searches found the seed and the tightly related FHIR-16078 issue, while Zulip and Confluence searches found no directly relevant or conflicting FHIR-17092 discussion. The combined branch already contains a FHIR-6109 audit commit confirming the HTTP verb ValueSet itself is present and in scope.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because the current source already addresses the issue's implementer-facing concern: the HTTP verb terminology points to the HTTP RFC and no longer uses the original bare labels as definitions. Replacing the accepted current wording with the exact Jira example would be optional editorial churn rather than a necessary correction to the current specification.

Recommendation:
Keep this audit commit as-is. If the work group later wants to modernize the HTTP terminology wording further, such as replacing "Command" with "method" or updating the RFC reference beyond RFC 7231, that should be handled as a new terminology/editorial decision rather than inferred from FHIR-17092.
