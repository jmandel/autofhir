FHIR-48702: Audit search URL-encoding guidance

Issue request:
FHIR-48702 was an Applied FHIR-I change request resolved as Persuasive with Modification. The reporter asked that HTTP GET search examples using the canonical version delimiter pipe percent-encode that character; the approved resolution instead directed the search page to add a near-top escaping note, keep ordinary examples readable and unescaped, show what over-the-wire encoding looks like, and link to that note where characters such as "|" are introduced.

Initial application:
The issue appears to have been applied by source commit d83729a5d4743f1218b4e53aad9e70c5363880da, "FHIR-48702 - Added section Notes on URL-Encoding, updated relevant examples, updated example header." That commit changed source/search.html by adding the URL-encoding note, changing HTTP example selectors to "Show as unencoded", adding links from versioned canonical and token syntaxes to the encoding note, and removing ordinary percent-escaped examples outside the relevant escaping guidance. Jira later records that HL7/fhir#3442 was merged.

Additional context:
The linked Zulip thread confirms that "|" remains the canonical/version delimiter and should not be replaced by a ?version query parameter, while actual HTTP transmission must escape it. The 2025-03-17 FHIR-I minutes record the same persuasive-with-modification decision: use a readable-example note near the top of search.html and leave examples unescaped except where escaping is being explained. Current source/search.html is the source page for build.fhir.org/search.html and contains that note plus links at the versioned canonical/reference and token syntax points.

AutoFHIR reconciliation:
No source change was made. The current search page already implements the approved clarification: it explains that examples are shown without URL-encoding for readability, shows an unencoded request beside the encoded over-the-wire representation, links the special-character syntaxes to the note, and retains percent-encoding examples only in the sections that are explicitly about encoding/escaping.

Recommendation:
Keep this no-change audit commit. Future editorial cleanup could rename or polish the "Notes on URL-Encoding" heading, but the current source satisfies the approved FHIR-48702 behavior without a semantic follow-up change.
