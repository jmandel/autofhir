Issue request:
FHIR-28465 was Published/Persuasive as a technical correction for the Mapping Language Tutorial Step #4. It asked to replace references to the undefined FHIRPath function `isInteger` with `convertsToInteger()`.

Initial application:

The second converted expression, however, still called the replacement function on the undefined variable `at1`, inherited from the original tutorial text, so the corrected function example remained invalid.

Additional context:
`mapping-tutorial.html` is an active built narrative page through `publish.ini` and the Implementation Support page hierarchy. FHIR-I minutes record FHIR-28465 being moved to technical correction, and the 2020 Mapping Language Connectathon page lists the same Jira as an identified tutorial issue. Jira/community searches found no separate tracker or conflicting decision for the adjacent `at1` typo.

AutoFHIR reconciliation:
Updated the Step #4 example so the negative conversion guard calls `convertsToInteger().not()` on `a`, the source variable introduced by `src.a21 as a`, matching the neighboring positive guard and completing the applied tutorial correction.

Recommendation:
Keep this source fix as-is. It is a narrow correction to the same tutorial example covered by FHIR-28465; any broader Mapping Language Tutorial cleanup should be handled under separate tracker review.
