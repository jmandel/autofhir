FHIR-32639: Audit artifact manifest application

Issue request:
FHIR-32639 was an Applied/Persuasive FHIR-core Library change request asking to consider an Artifact Manifest profile generalized from the QM IG Quality Program profile. The adopted direction was to describe a group of related artifacts and their dependencies, but later Jira comments clarified that the profile work would mature in CRMI and that the R6 core application should add summary discussion of artifact manifest use and reference the CRMI manifest material.

Initial application:
The issue was applied by Jira-tagged commit c8f3de81b7, included in HL7/fhir#3369, which added a Library introduction paragraph. Current source/library/library-introduction.xml explains that a Library of type asset-collection can define a collection of artifacts and dependencies, identifies this use as an artifact manifest, and links to the CRMI Artifact Manifest topic. source/fhir.ini lists Library as an active approved resource, so the checked source location is in the current build scope.

Additional context:
The current CRMI Artifact Manifest page defines a version manifest as an asset-collection Library conforming to the CRMIManifestLibrary profile, matching the profile-specific detail that Jira comments said should live in CRMI while core gives the summary pointer. A later CRMI issue, FHIR-52603, further clarified the Artifact Manifest page in the CRMI IG. Searches of Zulip and Confluence for FHIR-32639 and artifact manifest terms found no conflicting community decision requiring an additional FHIR-core change.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current FHIR-core source already reflects the applied R6 reconciliation by providing the necessary Library-level artifact manifest summary and CRMI reference, without duplicating the CRMI profile definition in core.

Recommendation:
Keep this no-change audit commit. Future substantive changes to the manifest profile or detailed artifact manifest guidance should be handled in CRMI first, or brought back to FHIR core only after the work group decides that matured CRMI content should be incorporated into a future FHIR publication.
