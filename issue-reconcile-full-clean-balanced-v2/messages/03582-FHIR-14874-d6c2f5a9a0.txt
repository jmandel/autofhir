FHIR-14874: Audit Condition clinical status codes

Issue request:
FHIR-14874 was a Published Patient Care change request for STU3 Condition.clinicalStatus. Although the issue summary argued that clinicalStatus should not be limited to the condition-code value set, the final Persuasive with Modification resolution narrowed the applied change to removing the 'well-controlled' and 'poorly-controlled' codes from the existing Condition clinical status value set.

Initial application:
The issue was applied in git commit f4005f37a69d8556e2141831d1593747b2319994, which removed the well-controlled and poorly-controlled concepts from source/condition/codesystem-condition-clinical.xml. A later Condition status comment cleanup in cccb69d8142e7ec5234dde242ca3da5d556591f5 removed the residual comment about conveying those statuses through Condition.code, and 5c0494aacfd0b8bd52bc72c587aa89d0a64246f8 later externalized UTG terminology content from the core build.

Additional context:
FHIR-13026 is the earlier Published issue that added the two controlled-status codes and is the same change family that FHIR-14874 reversed. Current source/fhir.ini lists Condition as an active, approved resource, source/condition/structuredefinition-Condition.xml binds Condition.clinicalStatus to the Condition clinical status value set without listing the removed codes, and source/condition/valueset-condition-clinical.xml now composes the value set from the THO condition-clinical code system. The local THO package code system contains active, recurrence, relapse, inactive, remission, resolved, and unknown, but not well-controlled or poorly-controlled. FHIR-54841 is a later Waiting for Input ballot issue about broader adequacy of the required value set, so it is context but not a final applied/published reversal for this reconciliation.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current built Condition source and terminology dependency already reflect the final FHIR-14874 decision by excluding well-controlled and poorly-controlled from Condition.clinicalStatus.

Recommendation:
Keep this no-change audit commit as-is. Handle any future redesign of Condition.clinicalStatus value-set adequacy under a finalized later tracker such as FHIR-54841, not by reopening FHIR-14874.
