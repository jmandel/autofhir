FHIR-5153: Correct Composition section emptyReason wording

Issue request:
FHIR-5153 was Published with resolution Persuasive with Modification. It asked to resolve the DSTU1 Composition narrative-only section model by constraining section content from Reference(Any) to List, updating List.text so it could serve as section narrative, and using an appropriate emptyReason code when a section was naturally narrative-only.

Initial application:
The issue was initially applied in git-svn commit 7b1600d410a98cdeb772f6c2ffeba7ed3b5a433f (#5151 + #5152 + #5153), which changed the old Composition.section.content spreadsheet entry from Reference(Any) to Reference(List), adjusted Composition examples to point through List, and expanded List narrative guidance.

Additional context:
The old section.content/List model was later superseded by FHIR-7404. Jira FHIR-7404 resolved to move narrative into Composition and inline relevant List parts into Composition sections, and commits 686889f8a3b83c74a4e58ddddfac7616dd0da4ca and 749c4dd88234688f57191d3d0b4d62bdc525b87d replaced Composition.section.content with Composition.section.text and Composition.section.entry. Later applied guidance, including FHIR-6917, FHIR-7103, and FHIR-15723, supports the current model where section.text is attested section narrative and List.text is not attested document content unless incorporated into Composition narrative or section.text. Composition and List are active resources in source/fhir.ini.

AutoFHIR reconciliation:
Updated the active Composition StructureDefinition source to remove leftover List wording from Composition.section.entry and Composition.section.emptyReason. The change preserves the current Composition.section.text/section.entry model while making the emptyReason guidance refer to empty sections, not empty Lists.

Recommendation:
Keep this commit as-is. Do not reintroduce the DSTU1 List-only section-content model for FHIR-5153; future changes should continue from the current Composition.section.text and document presentation rules. The checked-in Composition SVG still contains generated tooltip text derived from the old definition and should be regenerated by the normal build pipeline rather than hand-edited.
