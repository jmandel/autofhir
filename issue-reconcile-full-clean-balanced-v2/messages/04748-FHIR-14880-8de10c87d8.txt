FHIR-14880: Audit Patient animal extension move

Issue request:
FHIR-14880 was a Published/Persuasive Patient Administration change request from the STU3 ballot asking to remove the Patient.animal backbone from the base Patient resource, make the same animal details available as a standard extension, and include descriptive veterinary usage text in the Patient notes.

Initial application:
The change was explicitly applied in historical source commits e3d290e779 and a059d60658. Commit e3d290e779 disabled the Patient.animal spreadsheet rows, introduced the patient-animal extension content, and converted the animal Patient example from the backbone element to the extension. Commit a059d60658 added the Veterinary Care notes section explaining that veterinary care remains in FHIR scope and pointing to the patient-animal extension.

Additional context:
Current core source has no Patient.animal element in source/patient/structuredefinition-Patient.xml. The active Patient resource still covers animal patients, source/patient/patient-example-animal.xml uses the standard patient-animal extension, and source/patient/patient-notes.xml links to the extension via the Extension Pack location. The extension definition itself now lives in /home/jmandel/work/fhir-extensions/input/definitions/Patient/StructureDefinition-patient-animal.xml, with Patient context and species, breed, and genderStatus slices. The remaining core Patient.animal reference is in source/profiles/cda.profile.xml, but source/fhir.ini has the cda profile entry commented out, so it is not current build input. Related issue FHIR-14393 was resolved no-change because moving animal to an extension removed the missing-meaning problem; related issue FHIR-18328 corrected wording from animal element to animal extension and is consistent with the current Extension Pack comment.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current active core source already reflects the approved move out of base Patient, preserves the veterinary usage guidance requested by the resolution, and correctly relies on the Extension Pack for the standard extension definition. Editing the inactive CDA profile or duplicating Extension Pack content in core would not improve the current built specification.

Recommendation:
Keep this no-change audit as-is. Future changes to the patient-animal extension definition should be made in the FHIR Extension Pack, while core should continue to maintain only the active Patient narrative, examples, and references needed by the current build.
