FHIR-12684: Audit ContactPoint SMS system application

Issue request:
FHIR-12684 was Published with resolution Not Persuasive with Modification. The request challenged the overlap between ContactPoint.system and ContactPoint.use, especially whether mobile belonged in use and whether SMS capability should be represented as a system; the final disposition was to add SMS as a ContactPoint.system code rather than move mobile out of ContactPoint.use.

Initial application:
The issue was applied in two explicit SVN-migrated commits. Git commit 989cec4f7a added the sms row to the contact-point-system code list for #12684, and git commit 677cd94f4f updated the ContactPoint.system element short-name/code list to include sms.

Additional context:
ContactPoint is an active datatype in source/fhir.ini and is published on the datatypes page, so source/datatypes/contactpoint.xml is in the current build scope. Current source still lists ContactPoint.system codes as phone | fax | email | pager | url | sms | other, includes the sms code in the contact-point-system worksheet, and retains mobile as a ContactPoint.use code. Later Jira FHIR-16964 raised a closely related objection about ContactPoint.system/use boundaries and extensibility, but was Resolved - No Change, supporting the existing structural model. A 2019 Zulip thread mentioned GF#12684 in the context of business mobile numbers but did not record a final change that would override the Jira/source state.

AutoFHIR reconciliation:
This audit commit makes no source change because the current authoritative ContactPoint source already reflects the final FHIR-12684 decision: SMS is a system code, and mobile remains a use code under the not-persuasive-with-modification resolution.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-12684 unless a future work group decision reopens ContactPoint.system/use modeling; FHIR-16964 and the later Zulip discussion are background only and do not justify changing the current build.
