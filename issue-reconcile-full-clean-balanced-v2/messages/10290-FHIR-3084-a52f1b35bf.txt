FHIR-3084: Audit Resource _language search parameter

Issue request:
FHIR-3084 was a Published/Persuasive FHIR-core request, applied for DSTU1, to add a search parameter "language" for all resource types so clients could find resources in a particular language, especially Questionnaires. The Jira resolution records approval and comments that the change was already done.

Initial application:
No git commit explicitly mentioning FHIR-3084 was found. The early search page history shows the all-resource `_language` parameter documented in 2014 alongside `_id`, matching the Jira comment that the request had already been applied. That original DSTU1-era application was later changed by FHIR-7954, which removed `_language` from the all-resource search parameters because its semantics were considered under-specified.

Additional context:
FHIR-32020 later reintroduced the standard all-resource `_language` search parameter for R5, with the final resolution defining it as a token search against `Resource.language` and requiring additions to the search page tables and lists. Current build-scope source has `source/resource/bundle-Resource-search-params.xml` defining `Resource-_language`, and `source/search.html` documents `_language` plus lists it in the common parameters table. The related FHIR-32020 audit is already present on the combined branch, so this commit does not duplicate that issue.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because the current specification already provides the all-resource search parameter requested by FHIR-3084 using the current underscore-prefixed common-parameter name `_language`, type `token`, expression `Resource.language`, and search-page guidance. Adding a separate unprefixed `language` parameter for all resources would conflict with current all-resource search parameter conventions and with the later FHIR-32020 disposition.

Recommendation:
Keep this audit commit as-is. Future work on language search semantics should be handled under newer issues about translations, matching rules, or resource-specific language use cases, not by reopening the DSTU1 FHIR-3084 request.
