FHIR-13560: Audit ISO 3166 regional description

Issue request:
FHIR-13560 was a Published/Persuasive STU3 Vocabulary change request asking FHIR-core to stop describing urn:iso:std:iso:3166 as only a country-code system and to clarify coverage of countries plus sub-regions, with related URI and ValueSet updates for the ISO 3166 parts.

Initial application:
No git commit was found that names FHIR-13560 directly. The apparent application is git commit 4c41b4e23383efa8df22cf99fdc0511105015c5b, "rework ISO 3166", which changed source/terminologies-systems.html from "ISO 2 letter Country Codes" to "ISO Country & Regional Codes", replaced the old reused-country-code prose with a usage-page link, and added the ISO 3166 Part 1 two-letter, three-letter, and numeric ValueSet sources.

Additional context:
The 2018-02-08 Vocabulary WG minutes say the ISO 3166 discussion and motion superseded GF#13560: retain urn:iso:std:iso:3166 for ISO 3166 Part 1 for legacy reasons, document the ISO 3166 usage policy, and create a ValueSet for alpha-2 codes. Later Published issue FHIR-37887 updated the same active Code Systems Defined Externally row by adding urn:iso:std:iso:3166:-2 and urn:iso:std:iso:3166:-3 and removing the obsolete OID, while noting that the page is courtesy documentation and points readers to THO. Related ISO 3166 ValueSet audits FHIR-13330 and FHIR-37971 are already represented on the combined branch and do not require another seed-scope source edit here.

AutoFHIR reconciliation:
This audit commit makes no source change. The active source/terminologies-systems.html row now says "ISO Country & Regional Codes", lists the base ISO 3166 URI together with the Part 2 and Part 3 URNs, and links to THO's ISO 3166 usage page. publish.ini and hierarchy.xml keep terminologies-systems.html in the current build, and source/fhir.ini actively registers the ISO 3166 Part 1 ValueSet source files.

Recommendation:
Keep this no-change audit commit. The original description-broadening request is already satisfied, and later ISO 3166 URI/ValueSet maintenance has been handled under dedicated issues already audited on the combined branch.
