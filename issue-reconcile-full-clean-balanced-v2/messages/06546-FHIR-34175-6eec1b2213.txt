FHIR-34175: Audit MeasureReport validator relaxation

Issue request:
FHIR-34175 was Published/Persuasive for R5. It asked that publisher validation of MeasureReport.group codes be relaxed so that report groups are checked against Measure groups only when the referenced Measure actually has groups, allowing Da Vinci Risk Adjustment reports to carry HCC-code groups when the Measure has no computable groups.

Initial application:
The issue was pre-applied outside this HL7/fhir source checkout. The Jira comment says the PR was approved and merged, and hapifhir/org.hl7.fhir.core#630 merged a validator change that returns from MeasureValidator.validateMeasureReportGroups when the loaded Measure has zero groups. No prior HL7/fhir source commit for FHIR-34175 was found.

Additional context:
Measure and MeasureReport are active resources in source/fhir.ini. Current MeasureReport source contains group and group.code descriptive guidance but no computable invariant that enforces the old publisher check. Later FHIR-49670 added R6 guidance that a MeasureReport includes corresponding elements for groups defined by the Measure, but that later source clarification is about populating report content for defined Measure groups and does not reintroduce the FHIR-34175 validator failure for a Measure with no groups.

AutoFHIR reconciliation:
This commit intentionally makes no source change in HL7/fhir. The applied change belongs to the external HAPI FHIR validator codebase cited by the issue, and the relevant PR is already merged.

Recommendation:
Keep this empty audit commit. Future regressions in this behavior should be handled in the validator repository; any desire to add explicit narrative about risk-adjustment reports with no computable Measure groups should be raised as a new CQI/FHIR-I wording issue because FHIR-34175 itself was a validator change.
