FHIR-7460: Audit Provenance non-resource entity support

Issue request:
FHIR-7460 is a Published/Persuasive with Modification FHIR-core Provenance issue from the 2015 May ballot asking to change Provenance.entity.type from a Required binding to resource-types to an extensible binding, so Provenance can identify entities whose source content is not a FHIR resource.

Initial application:
No exact FHIR-7460-tagged git commit was found in the current source history because the Jira comment says the tooling-error fix was pre-applied in SVN. The DSTU2 source import already shows ProvenanceEntityType bound to http://hl7.org/fhir/ValueSet/resource-types with Conformance = extensible, so the requested binding correction had already been applied before this reconciliation.

Additional context:
Provenance remains an active current-build resource in source/fhir.ini. Later Published Provenance issue FHIR-9996 changed the model for import/transform provenance: it disabled Provenance.entity.type and Provenance.entity.display, changed entity identity to a Reference(Any)-style element, and added narrative explaining use of Provenance for HL7 v2/CDA-derived content. Current source now has Provenance.entity.role, Provenance.entity.what, and Provenance.entity.agent; Provenance.entity.what explicitly says what.identifier should be used for entities that are not a Resource type. Current reference guidance also documents Reference.identifier as the logical-reference mechanism for cases where no FHIR instance exists when the reference type is Reference(Any).

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current specification is already correct for FHIR-7460: the obsolete Required resource-types binding was historically made extensible, and the obsolete element was later superseded by the current Provenance.entity.what/Reference design that preserves support for non-FHIR source entities.

Recommendation:
Keep this audit commit as-is. Do not reintroduce Provenance.entity.type or add redundant Provenance prose for FHIR-7460; future work should use the current Provenance.entity.what and Reference.identifier model, and any broader reconsideration should be raised as a new Security/Infrastructure design issue.
