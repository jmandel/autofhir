FHIR-31880: Audit Composition section text search

Issue request:
FHIR-31880 was Published with a Persuasive resolution for R5. It asked to add a Composition search parameter named section-text that searches Composition.section.text, not Composition.text, because _text only covers Resource.text and _content covers the entire resource.

Initial application:
The issue appears to have been applied by git commit 586441a2c8, which added Composition-section-text to source/composition/bundle-Composition-search-params.xml. The current source keeps the search parameter as code section-text, type special, with expression Composition.repeat(section).text. Composition is an active current-build resource in source/fhir.ini.

Additional context:
FHIR-31743 is the companion Structured Documents request for a section-code-text composite search parameter and was implemented in the same historical source commit. SDWG May 2021 minutes record approval of both requests. A Zulip implementers thread records the problem statement: _text is Resource.text, while the requested document-text search needed Composition.section.text. Later commit 51941173de for FHIR-49784 updated section-related Composition search parameters to use repeat(section), preserving the FHIR-31880 intent while covering nested sections recursively.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The authoritative current source already defines section-text against Composition.repeat(section).text and does not include Composition.text, so the Published Jira request is satisfied.

Recommendation:
Keep this no-change audit commit as-is. No follow-up core source work is needed for FHIR-31880 unless the work group later wants to revisit special text-search semantics more broadly.
