FHIR-30429: Audit websocket token guidance ownership

Issue request:
FHIR-30429 was a Published/Persuasive FHIR-core Subscription clarification for R5. It asked whether a websocket binding token can be reused after a dropped connection and resolved to document that token security policy is implementation/server-dependent, including possible single-use and reusable-until-expiration behaviors.

Initial application:
The issue was applied in core by 63ac0d8b02, which corrected the $get-ws-binding-token input wording, added implementation-dependent token-security wording to the token output parameter, and added Subscription notes stating that websocket tokens may be single-use or reusable until expiration and that servers should document their issuance policy.

Additional context:
Current R6 core no longer owns the $get-ws-binding-token operation. Subscription is active in source/fhir.ini, but source/subscription/list-Subscription-operations.xml now lists only Subscription-events and Subscription-status, while source/subscription/subscription-notes.xml points websocket channel details to the FHIR Subscriptions Backport Implementation Guide. Later history removed the operation from core and states that websocket content is moving to external sources; related Jira FHIR-47290 likewise records that the operation and websocket details are moving to an external guide. The only remaining in-tree $get-ws-binding-token reference is an unreferenced mermaid workflow source with no corresponding websocket SVG/page include, so it is not a build-scope source location for this reconciliation.

AutoFHIR reconciliation:
No source files were changed. The current core build should not reintroduce token lifecycle guidance for an operation it no longer publishes; any current correction to websocket token behavior belongs in the external subscriptions guide that now owns the operation details.

Recommendation:
Keep this empty external-repo audit commit for core. If the external subscriptions guide lacks the FHIR-30429 token policy clarification, follow up there, preferably alongside the pending FHIR-47290 external-guide work.
