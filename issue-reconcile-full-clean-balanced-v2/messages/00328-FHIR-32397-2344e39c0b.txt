FHIR-32397: Align Immunization program eligibility model metadata

Issue request:
FHIR-32397 was a Published/Persuasive PHER change request for R5. It said Immunization.programEligibility was under-specified as a repeating eligibility code because each eligibility value must identify the program it applies to, and resolved to make programEligibility a repeating backbone element with required program and eligibility-value children.

Initial application:
The Immunization StructureDefinition and examples were first changed in commit 0a5b857fb1dc6c8a2e9caa12e4703e9c4d989c9f, then that broader immunization update was reverted by f324cb65de83c63433db9028c335384f66fd0290 and reapplied by 2ab10d9e161c5da869c6447c9401dd8de85956ab. The current active Immunization source has programEligibility as 0..* BackboneElement with required CodeableConcept children program and programStatus, and examples use the same structure. The active FHIR model-definition Library still exposed programEligibility as List<CodeableConcept>, so one build-scope source surface remained stale.

Additional context:
PHWG Immunization Innovations minutes on 2022-05-20 and 2022-05-27 record the decision as persuasive, update to a backbone element, and note that IGs can profile away multiple programs when appropriate. A 2020 Zulip implementer thread raised the same practical ambiguity by asking where the vaccination program is represented. Later Applied issue FHIR-53151 explicitly references programEligibility.programStatus for value-set binding cleanup, confirming the current child name rather than reopening the R5 resolution's provisional .eligibility spelling.

AutoFHIR reconciliation:
This commit updates the active FHIR model-definition Library content so Immunization.programEligibility is a list of FHIR.Immunization.ProgramEligibility backbone elements, adds that ClassInfo with program and programStatus CodeableConcept children, and regenerates the Library.data attachment to match the sibling content XML. It intentionally leaves the core StructureDefinition child name as programStatus because that is the applied current element name and preserves the requested eligibility-status semantics.

Recommendation:
Keep this source fix as-is. No further core Immunization structural change is recommended for FHIR-32397; in particular, do not rename programStatus to eligibility without a new work-group decision because later source and Jira context use programStatus.
