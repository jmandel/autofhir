FHIR-11131: Audit DiagnosticRequest specimen lineage

Issue request:
FHIR-11131 was Published/Persuasive with Modification for the DSTU2 DiagnosticRequest ballot. It asked that Specimen not be removed from DiagnosticRequest and adopted the FHIR-10589 OO vote to support both workflows: a request can point to an already-known specimen, while a newly collected specimen can point back to the request, with clarifying guidance rather than a constraint.

Initial application:
The change was applied before this reconciliation through git-svn commit 2cd605d912cb03536541fa1b4db1093df394b58b, which carried [#10589], added DiagnosticRequest.specimen as 0..* Reference(Specimen), updated the lipid DiagnosticRequest example with a contained serum specimen and specimen reference, and rewrote the DiagnosticRequest notes to describe the two workflow directions. FHIR-11131 itself was recorded as a duplicate/background ballot comment that reused the FHIR-10589 vote.

Additional context:
DiagnosticRequest is no longer an active current-build resource. FHIR-11119 merged DiagnosticRequest into ProcedureRequest, FHIR-13867 renamed that successor to ServiceRequest, and source/fhir.ini now lists ServiceRequest and Specimen as active while recording DiagnosticRequest only in the retired/deleted resource list. The current ServiceRequest notes preserve the ordering/specimen workflow guidance through Specimen.request for the common request-first workflow and the servicerequest-specimenSuggestion extension for less common request-side specimen suggestions. Later OO decisions FHIR-34206, FHIR-48286, FHIR-50611, FHIR-54625, and FHIR-55444 intentionally deprecated, replaced, clarified, and then removed ServiceRequest.specimen, so reintroducing a direct ServiceRequest.specimen element for this old DiagnosticRequest issue would contradict current R6 decisions.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source is correct after the historical application and later controlling ServiceRequest/specimenSuggestion decisions: Specimen.request remains active, request-side specimen selection is represented through the Extension Pack specimenSuggestion extension and linked ServiceRequest notes, and DiagnosticRequest is outside the current build.

Recommendation:
Keep this no-change audit as-is. Do not re-add DiagnosticRequest.specimen or ServiceRequest.specimen in core for FHIR-11131; any future change to request-side specimen selection should be handled as a new ServiceRequest/specimenSuggestion issue with OO review.
