FHIR-11368: Audit Account period rename

Issue request:
FHIR-11368 was a Published/Persuasive Patient Administration change request from the DSTU2 cycle asking to rename Account.coveragePeriod to Account.period to avoid confusion with Account.coverage. The Jira resolution says the rename was already applied during STU3 QA processing and clarifies that the element is the account transaction/service window, not the period on a referenced Coverage.

Initial application:
No commit message explicitly names FHIR-11368, but the Account QA commit bbaf6a813fd0003b8dc83473640dc4a5392adee8 removed coveragePeriod from the Account examples and introduced Account.period in the Account spreadsheet, with a committee note recording the coveragePeriod-to-period rename. Current source still carries that history in the Account.servicePeriod element's build-only committee note.

Additional context:
FHIR-14813 is a later Published/Persuasive with Modification Account issue that renamed Account.period to Account.servicePeriod, removed Account.active, and clarified the service-period definition and comment. The active [resources] section of source/fhir.ini includes account=Account, and current Account source, examples, model definition content, and the Account-period search parameter all use Account.servicePeriod. source/fhir.ini also maps Account.period=Account.servicePeriod for cross-version migration. No current build-scoped Account element or example uses Account.coveragePeriod.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The requested coveragePeriod rename is already reflected in the current specification because coveragePeriod is absent as an Account element and the same concept now appears under the later approved Account.servicePeriod name. Reintroducing Account.period would conflict with FHIR-14813, and changing only the historical committee note would be optional non-normative cleanup rather than a necessary current-spec correction for FHIR-11368.

Recommendation:
Keep this no-change audit commit as-is. If maintainers later want to tidy build-only committee notes, they can update the historical note to mention the later servicePeriod rename, but no FHIR-11368 source correction is needed.
