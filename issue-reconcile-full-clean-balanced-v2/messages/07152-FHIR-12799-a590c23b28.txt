FHIR-12799: Audit DeviceUsage indication handoff

Issue request:
FHIR-12799 was Published/Persuasive for FHIR-core DeviceUseStatement after DSTU2. It asked to allow references, such as a Condition, that explain the medical reason or indication for using a device; the resolution said the resource would align with the workflow event pattern in STU4 and have partOf or an extension to meet the use.

Initial application:
The issue was applied in the historical GF#12799/GF#12800/GF#10299 DeviceUseStatement workflow-alignment commits. Those commits added DeviceUseStatement.reasonCode and DeviceUseStatement.reasonReference, mapped reasonReference to Event.reasonReference, and allowed references to Condition, Observation, DiagnosticReport, and DocumentReference for the justification/indication use case.

Additional context:
FHIR-31478 later renamed DeviceUseStatement to DeviceUsage, and the current DeviceUsage source lineage expresses the old reasonReference capability as DeviceUsage.reason, a CodeableReference that includes Condition. FHIR-51713 later added DeviceUsage.partOf, but DeviceUsage is no longer an active core resource in this checkout: the November 2025 OO-resource cleanup removed it from source/fhir.ini and current core pages link DeviceUsage to the OO Incubator IG instead. The OO Incubator source/config includes DeviceUsage and its reason element with the same Condition-capable CodeableReference.

AutoFHIR reconciliation:
This is an empty external-repo audit commit. No core source was changed because DeviceUsage is outside the current core build, and both the dormant core source lineage and the OO Incubator definition already support the requested referenced indication through DeviceUsage.reason.

Recommendation:
Keep this audit as-is for core reconciliation. Any future changes to the DeviceUsage indication/reason model should be made in HL7/oo-incubator, not in this FHIR-core checkout, unless the resource is brought back into the active core build.
