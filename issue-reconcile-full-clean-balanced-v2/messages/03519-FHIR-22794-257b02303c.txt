FHIR-22794: Audit maximum value set terminology guidance

Issue request:
FHIR-22794 was a Published Vocab change request, resolved Persuasive with Modification for R5, asking the core terminology page to explain maximum value set binding. The accepted resolution asked for a Maximum Value Set section saying that extensible or preferred bindings may be further constrained by a value set from which additional codes can be taken, plus an Other Notes bullet for minValueSet.

Initial application:
The issue was explicitly applied in git commit ab0ada5222, which changed source/terminologies.html by adding a Maximum Value Set section and an Other Notes bullet linking minValueSet. Later ElementDefinition/additional-binding work in 1e1665b935 moved the substance into the additional bindings table, and 37beae8dcf finished replacing the old maxValueSet extension link with additional-binding terminology.

Additional context:
FHIR-26028 is the same maxValueSet terminology family and is already represented on the combined branch by 56f45036ce, which restored the preferred-binding half of the maximum binding wording and cited FHIR-22794 as related. Current source/terminologies.html now describes additional bindings, defines purpose=maximum for extensible or preferred main bindings, defines purpose=minimum, and keeps the later R5+ guidance that max/min value set extensions have been replaced. FHIR-43156 and FHIR-46445 subsequently deprecated the minValueSet and maxValueSet extensions in the FHIR Extension Pack, whose current definitions are retired/deprecated and point implementers to additionalBinding instead.

AutoFHIR reconciliation:
Made no source change. The current core terminology page and Additional Binding Purpose CodeSystem preserve the implemented substance of FHIR-22794 under the current additional-binding model, while the old extension definitions now belong to the Extension Pack and are intentionally deprecated/retired.

Recommendation:
Keep this audit commit as-is. Reintroducing a standalone maxValueSet-extension section in core would conflict with the later R5/R6 additionalBinding migration and Extension Pack deprecation decisions; future work should only adjust wording if the work group wants to change current additional-binding guidance.
