FHIR-37555: Audit Subscription authorization context

Issue request:
FHIR-37555 was a Published/Persuasive FHIR-core Subscription change request raised against R4 and applied for R5. It asked for a Subscription.managingEntity 0..1 Reference(CareTeam | HealthcareService | Organization | RelatedPerson | Patient | Practitioner | PractitionerRole) so implementations have an entity responsible for Subscription changes and authorization-context decisions without the specification dictating local policy.

Initial application:
The issue was applied before this reconciliation in commit 7704203868d3f767ed830de3649054899146f5ae, "late breaking changes including FHIR-37555 and FHIR-32530," which added Subscription.managingEntity to source/subscription/structuredefinition-Subscription.xml with the requested cardinality, target profiles, summary flag, and FiveWs.author mapping. The original applied definition included the disclosure-authorization wording from the Jira resolution.

Additional context:
Subscription is an active current-build resource in source/fhir.ini. The current authoritative Subscription StructureDefinition source still contains Subscription.managingEntity, now with the original target profiles plus Device and Group from later FHIR-47337. Its definition and comment intentionally differ from FHIR-37555's original disclosure wording because later Applied/Persuasive issue FHIR-47340 replaced that text with clearer communication-with-server wording and a note for server-managed Subscriptions. Both FHIR-47340 and FHIR-47337 are already represented on the combined branch by separate no-change audit commits, so they are context rather than duplicate opportunistic decisions here. A checked-in subscription.svg tooltip still contains the older definition, but it is a generated-looking diagram artifact and does not change the authoritative source conclusion.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already preserves the FHIR-37555 addition of Subscription.managingEntity, and restoring the original disclosure wording would conflict with the later FHIR-47340 clarification.

Recommendation:
Keep this audit commit as-is. No FHIR-37555 source follow-up is needed; if maintainers want stale diagram tooltips refreshed, handle that through the normal diagram generation path rather than as a seed issue correction.
