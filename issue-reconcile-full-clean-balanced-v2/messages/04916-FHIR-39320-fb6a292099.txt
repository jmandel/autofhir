FHIR-39320: Audit Period constraints table

Issue request:
FHIR-39320 is a Published/Persuasive FHIR-core technical correction, raised against R4 and applied for R5, asking that the Period datatype page include a Constraints table like Range and RatioRange because Period has a Structure-tab rule that start SHALL be lower than end.

Initial application:
No git commit explicitly mentioning FHIR-39320 was found for source/datatypes.html or source/datatypes/period.xml. The effective source change was already present before this Jira was created: commit d621ab0bda6 uncommented the Period constraints block in source/datatypes.html, enabling the existing [%dt.constraints Period%] publisher macro to render the table.

Additional context:
source/fhir.ini maps data types to the datatypes page, so source/datatypes.html is in current build scope for Period. source/datatypes/period.xml still defines the Period invariant with the current wording "If present, start SHALL have a lower or equal value than end". Published R5 and current build.fhir.org output both render that constraint for Period. A broad Jira search surfaced FHIR-20652, but that older issue concerns duplicated Timing.repeat period/frequency wording and does not conflict with the base Period constraint table. Zulip and Confluence searches found no directly relevant discussion changing the source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already includes the Period Constraints section and the authoritative Period spreadsheet already contains the invariant that the section renders.

Recommendation:
Keep this audit commit as-is. If a future rendered page lacks the Period constraints table, investigate the datatype macro/publisher output rather than changing the current source, because the build-scoped inputs are already correct.
