FHIR-37664: Audit MolecularSequence relative elements

Issue request:
FHIR-37664 was a Published/Persuasive R5 Clinical Genomics request to add MolecularSequence.relative.ordinalPosition (integer) and MolecularSequence.relative.sequenceRange (Range) so multiple relative reference-sequence segments could be composed with explicit ordering and composed-sequence coordinates.

Initial application:
The request was applied before this reconciliation by commit e1892fd7be59be5495827c6f662cd9edeba6fc19, which added both elements to source/molecularsequence/structuredefinition-MolecularSequence.xml. The R5 release-history artifact still contains MolecularSequence.relative.ordinalPosition and MolecularSequence.relative.sequenceRange with the requested definitions and types.

Additional context:
Clinical Genomics minutes for 2022-07-12 record FHIR-37664 in a block vote with 13-0-0 approval and discussion of ordinalPosition versus intrinsic list order. The linked Zulip thread shows the proposal, review of Range for sequenceRange, and confirmation that the changes reached the FHIR Core build in July 2022. Later source history removed the current MolecularSequence source folder and current diagnostics narrative states that MolecularSequence has been replaced by MolecularDefinition. In source/fhir.ini, molecularsequence is not active in the current [resources] workgroup entries while moleculardefinition is active.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The requested R5 MolecularSequence elements are already represented in the R5 history artifact, and the current build has no active MolecularSequence StructureDefinition to patch. Adding ordinalPosition or sequenceRange to MolecularDefinition would be a new modeling decision, not the bounded application of FHIR-37664.

Recommendation:
Keep this audit commit as-is. No current FHIR core source fix is needed for FHIR-37664; any future need to carry this exact composition pattern into MolecularDefinition should be raised as a separate Clinical Genomics modeling issue.
