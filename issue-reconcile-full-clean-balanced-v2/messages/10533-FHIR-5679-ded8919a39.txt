FHIR-5679: Audit reverse include search support

Issue request:
FHIR-5679 was Published/Persuasive for DSTU1 and asked to add reverse include support so a client could search a resource and retrieve resources such as Provenance that point back to it. The recorded FHIR Core teleconference decision narrowed the syntax to use a search parameter, not a resource path, add examples for _include and _revinclude, and repeat the parameter rather than comma-separating multiple include criteria.

Initial application:
The request was applied in git-svn commit 13da0d4b9ad91765695173ebcd8b31387120f812, imported from SVN revision 4580, with subject "#5679 and #3356: _revinclude and changes to _include". That commit changed source/search.html from path-based include wording to search-parameter-based _include/_revinclude syntax and added the Provenance reverse-include example.

Additional context:
The current source/search.html page is the active top-level Search source page; source/fhir.ini also calls out search.html as the maintained search summary table companion for search-rules changes. Later search-page revisions have preserved and refined the same rule: _revinclude follows reverse links using search parameters, shares the colon-separated resource/search-parameter/targetType syntax with _include, is repeated for multiple criteria, and includes the Provenance:target example. CapabilityStatement.rest.resource.searchRevInclude is also present for advertising supported reverse includes. Direct Zulip and Confluence searches found no FHIR-5679-specific record that changes the Jira/source conclusion.
