FHIR-5724: Audit entered-in-error status coverage

Issue request:
FHIR-5724 was a Published/Persuasive Patient Care change request from DSTU1 asking to add an entered-in-error equivalent to AllergyIntolerance.status and Condition.status because similar resources consistently had one.

Initial application:
The issue was initially applied in git-svn commit b9fb8b6f13 (svn revision 4843), which added entered-in-error to the then-current AllergyIntolerance.status and Condition.status spreadsheet definitions.

Additional context:
Both AllergyIntolerance and Condition are active current-build resources in source/fhir.ini. Later Patient Care decisions changed the status model: FHIR-11151 split AllergyIntolerance.status into clinicalStatus and verificationStatus and aligned it with Condition, FHIR-11206 clarified that entered-in-error is not an inactive clinical state, and FHIR-23008/FHIR-28458 adjusted the post-split invariants and guidance. In the current source, the entered-in-error meaning lives on verificationStatus for both resources rather than on a legacy status element.

AutoFHIR reconciliation:
No source change was made. Current StructureDefinitions explicitly declare the build entered-in-error-status hook as .verificationStatus = entered-in-error for both resources, both verificationStatus element short descriptions include entered-in-error, both elements are modifier elements because refuted/entered-in-error make the record not currently valid, and the search-parameter descriptions expose entered-in-error on verificationStatus.

Recommendation:
Keep this no-change audit commit. The current core source preserves the FHIR-5724 requirement through the current status model, so adding a new code or duplicating guidance on the removed legacy status element would be incorrect.
