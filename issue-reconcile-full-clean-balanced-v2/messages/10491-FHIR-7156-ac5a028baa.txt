FHIR-7156: Audit Observation donor focus guidance

Issue request:
FHIR-7156 was a Published/Persuasive OO clarification from the 2015 May DSTU1 ballot asking to insert "donor" after "fetus" in the Observation.subject comments example list for indirect characteristics.

Initial application:
The issue was applied in git commit ff6b620add130e1ad7bb20f468b7725f3b7600ce, which edited source/observation/observation-spreadsheet.xml to change the old Observation.subject comment from "specimen, fetus, other observer" to "specimen, fetus, donor, other observer" and added 7156 to the committee notes. The current generated StructureDefinition source still carries 7156 in the Observation.subject committee-notes extension.

Additional context:
Observation.subject/focal-subject semantics changed after DSTU1. FHIR-14443 promoted the focal-subject extension to the Observation.focus element for cases where the actual focus is not the subject of record, and the R4B source conversion carried the old donor example into Observation.focus rather than keeping the obsolete DSTU1 indirect-characteristics list on Observation.subject. Later, FHIR-43357 approved the current R6 Observation.focus wording: a broad definition saying that focus represents something or someone associated with the subject, plus illustrative examples for parent, fetus, body structure, implanted device, and DeviceMetric. That later approved simplification intentionally removed the old exhaustive-looking spouse/parent/fetus/donor phrase while preserving donor as an allowed associated person/entity. The active source/fhir.ini resource entry confirms Observation is in the current build scope.

AutoFHIR reconciliation:
This audit commit makes no source change. Re-adding "donor" to the current Observation.focus prose would only restore one member of an old example list and would duplicate the broader current rule; the current source does not forbid or obscure donor-focused observations. The checked-in observation.svg still contains older generated-looking wording with donor, but the authoritative XML source is already current and no source-changing commit should edit only that generated-looking diagram artifact.

Recommendation:
Keep this no-change audit as-is. No core source follow-up is needed for FHIR-7156 unless OO later decides that donor-specific Observation.focus examples are required again; in that case it should be handled as a new wording decision rather than as an unapplied DSTU1 ballot item.
