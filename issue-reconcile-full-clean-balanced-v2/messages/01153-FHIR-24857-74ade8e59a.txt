FHIR-24857: Audit Timing calendar month guidance

Issue request:
FHIR-24857 was Published/Persuasive for R5 as a non-substantive MnM clarification. It asked to update Timing.repeat.durationUnit, Timing.repeat.periodUnit, and the description of the UCUM 'mo' code to state: "Normal practice is to use the 'mo' code as a calendar month when calculating the next occurrence."

Initial application:
The issue was applied by ec83d5b5057f1402bdeb77453f5d214806de6b8c, "MnM Non Substantive changes for R5", whose commit body lists FHIR-24857 and whose patch added the exact requested sentence to source/datatypes/timing.xml for both Timing unit elements and the local units-of-time 'mo' code definition.

Additional context:
source/fhir.ini lists Timing as an active datatype, so source/datatypes/timing.xml is in current build scope. A later FHIR-I discussion and FHIR-38064 questioned whether FHIR should prefer explicit FHIRPath calendar units instead of advising calendar handling for UCUM 'mo', but FHIR-38064 remains Triaged/Unresolved and therefore does not supersede the Published FHIR-24857 decision. FHIR-24858 is the related Published FHIRPath mapping warning and is a separate page-level decision.

AutoFHIR reconciliation:
No source change was made. The current active Timing source already contains the requested calendar-month sentence on Timing.repeat.durationUnit, Timing.repeat.periodUnit, and the units-of-time 'mo' code definition.

Recommendation:
