FHIR-35994: Audit ImagingStudy subset guidance

Issue request:
FHIR-35994 was a Published/Persuasive R5 Imaging Integration clarification request asking the ImagingStudy page to explain how to handle multiple ImagingStudy resources that reference the same DICOM Study or different subsets, and whether ImagingSelection should be used for subsets.

Initial application:
The issue appears to have been applied through the June 2022 Imaging changes. Jira comments point to merge commit c138fb1b9ed930251866ab1da3be7d524b3fb1d4, which updated ImagingStudy Boundaries and Relationships to describe ImagingStudy as storing details of an entire DICOM Study and added ImagingSelection as the resource for a specific set of DICOM images, frames, or other DICOM instances. The exact FHIR-35994 scope text about duplicate ImagingStudy resources was not carried forward as stable current wording.

Additional context:
Later Applied issues revisited the same overlap. FHIR-47275 explicitly removed the old wording that an ImagingStudy may reference a subset and that multiple ImagingStudy resources may reference the same DICOM Study, while noting in Jira comments that base FHIR is generally silent on duplicate resources sharing a business identifier such as DICOM Study Instance UID. FHIR-50769, FHIR-54814, and FHIR-54797 then refined the current ImagingStudy/ImagingSelection wording, including the current statements that one ImagingStudy resource SHALL reference one DICOM Study, ImagingStudy stores details of an entire DICOM Study, and ImagingSelection references a subset of a DICOM Study.

AutoFHIR reconciliation:
No source change was made. The active current source already gives the implementer-facing distinction needed for this issue: ImagingStudy is the resource for an entire DICOM Study and ImagingSelection is the resource for subsets. Reintroducing the older duplicate/subset sentence would conflict with later Applied R6 decisions that intentionally removed it and left duplicate business identifier policy to implementation guides or local policy.

Recommendation:
Keep this audit commit as-is. If the work group later wants normative duplicate-handling rules for multiple ImagingStudy resources with the same Study Instance UID, that should be handled as a new ImagingStudy policy or implementation guide decision rather than as a FHIR-35994 carry-forward edit.
