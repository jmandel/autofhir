FHIR-20651: Audit Resource.id optionality comment

Issue request:
FHIR-20651 was Published/Persuasive for R5 and asked to loosen the Resource.id comment because the old statement, "The only time that a resource does not have an id is when it is being submitted to the server using a create operation," was too strict after later interactions such as conditional update. The approved replacement was that resources typically have ids except for cases like create and conditional updates.

Initial application:
The issue was explicitly applied by bebeb7208891d96d47bac8305e6382ec303b6e66, "Fix FHIR-20651," which changed source/resource/structuredefinition-Resource.xml from the old create-only sentence to the approved looser wording mentioning create and conditional updates. HL7/fhir#1124 is recorded in Jira as the application PR.

Additional context:
Later and neighboring Resource.id issues refined the same rule family. FHIR-23741 scoped the old statement to RESTful use, FHIR-27052 changed the active Resource.id comment to the current RESTful-interactions wording, FHIR-26688 corrected conditional-update id handling, and FHIR-42909 expanded the Resource logical-id narrative with additional no-id cases. Those related issues are already represented on the combined branch, and their accepted refinements should not be undone by restoring the exact FHIR-20651 wording.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The Resource narrative also lists broader no-logical-id cases, so the current specification already conveys the FHIR-20651 correction when read with later decisions.

Recommendation:
Keep this audit commit as-is. No core source change is needed for FHIR-20651; any future editorial cleanup of the later Resource.id wording should be handled separately from this applied optionality correction.
