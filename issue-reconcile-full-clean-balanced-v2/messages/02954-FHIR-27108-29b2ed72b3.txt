FHIR-27108: Audit SubstanceDefinition impurity classification

Issue request:
FHIR-27108 is a Published/Persuasive BR&R R5 change request asking FHIR core to support substance impurities in the SubstanceDefinition/SubstanceSpecification area. The final Jira discussion narrowed the requested source shape to adding SubstanceDefinition.classification [0..*] CodeableConcept for impurity classification and moving the similar classification concept away from SubstanceReferenceInformation.

Initial application:
The issue was explicitly applied before this reconciliation. Commit ae0d9e06a70438253daa330ba36e3a07a47a0d22 added SubstanceDefinition.classification to the then-authoritative SubstanceDefinition spreadsheet as 0..* CodeableConcept with impurity-oriented classification text. Commit 3b925882f4f15237636165e2ddcb7d82ff108253 removed SubstanceReferenceInformation.classification because it was being simplified and moved to SubstanceDefinition. The later source-format rework preserved the element in source/substancedefinition/structuredefinition-SubstanceDefinition.xml.

Additional context:
SubstanceDefinition is the active current-build artifact in source/fhir.ini; the old Jira related artifact name SubstanceSpecification is historical. Later Published/Persuasive FHIR-31823 intentionally merged the older high-level category concept into the same repeating SubstanceDefinition.classification element, explaining why the current classification wording is broader than the original FHIR-27108 row. Later FHIR-31838 made relationship.type mandatory, and the current substance relationship type value set also includes an Impurity code. The separate SubstanceReferenceInformation resource is no longer active in the current build, with that later resource-removal decision already audited on the combined branch as FHIR-51930. Residual SubstanceReferenceInformation names in historical/OID/resource-tracker or broader legacy ModelInfo content do not reintroduce an active current resource definition for this seed.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current authoritative SubstanceDefinition source already contains SubstanceDefinition.classification as 0..* CodeableConcept with definition text explicitly including type of impurity, the current search parameter targets SubstanceDefinition.classification, and the active relationship-type terminology includes Impurity. Re-editing the resource would be redundant, and using this seed to regenerate unrelated legacy ModelInfo content would exceed the approved FHIR-27108 scope.

Recommendation:
Keep this no-change audit commit. No core FHIR source follow-up is needed for FHIR-27108 unless BR&R makes a new decision about the broader FHIR ModelInfo example or substance legacy metadata; do not restore SubstanceReferenceInformation or split category back out of SubstanceDefinition.classification.
