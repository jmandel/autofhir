Issue request:
FHIR-10658 was a Published/Persuasive Vocab change request, raised and applied for DSTU2, asking for ValueSet validation and code lookup to accept a language parameter so display text can be validated or returned in the requested language. The recorded resolution was to add the parameter to $validate and $lookup.

Initial application:
The Jira comment says this had already been done under another task. The matching git-svn commit 3a0587b8a7b779c25869a391ce9596b59ddfbf08, made the same day as that comment, is titled "#add displayLanguage parameter to $validate-code and $lookup" and added validate-code.displayLanguage to the old ValueSet spreadsheet plus lookup.displayLanguage to the old CodeSystem spreadsheet. Later source refactors carried those operation definitions into the current XML sources.

Additional context:
ValueSet and CodeSystem are active current-build resources in source/fhir.ini, and their operation lists reference OperationDefinition/ValueSet-validate-code and OperationDefinition/CodeSystem-lookup. Later final issues refined the same parameter family without reversing FHIR-10658: FHIR-29958 corrected the CodeSystem $lookup displayLanguage documentation target, and FHIR-40770 made validate-code displayLanguage repeatable with clarified validation semantics. A later FHIR-57437 fallback-warning proposal is still Submitted/unresolved and does not change the applied parameter requirement.

AutoFHIR reconciliation:
