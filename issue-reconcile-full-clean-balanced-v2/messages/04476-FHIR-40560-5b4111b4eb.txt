FHIR-40560: Audit Observation value type revisions

Issue request:
FHIR-40560 was a Published/Persuasive with Modification R5 OO change request for FHIR-core Observation. The accepted request restored valueString, removed valueMarkdown rather than documenting it, removed valueCanonical, added/updated value[x] datatype notes including time/decimal and Attachment guidance, and applied the same value-type changes to Observation.component.value[x].

Initial application:
The issue was applied before this reconciliation by git commit 3223f3da2f17c8a97a17e674159201cd37aa9d89, which changed source/observation/structuredefinition-Observation.xml for both Observation.value[x] and Observation.component.value[x]: markdown became string, canonical was removed, and the canonical-specific comment text was removed. Later source history in the same family changed the old Observation-value-markdown search parameter to Observation-value-string (FHIR-41002), and separate combined-branch audits already represent FHIR-44931 and FHIR-45339 for that adjacent search-parameter cleanup.

Additional context:
Observation is an active current-build resource in source/fhir.ini, so source/observation/structuredefinition-Observation.xml, source/observation/observation-notes.xml, and source/observation/bundle-Observation-search-params.xml are in scope. Current authoritative source has string and Attachment for both value[x] choices, has no valueMarkdown or valueCanonical choice, and has no Observation-value-markdown search parameter. A later source change for FHIR-53610 removed the remaining orphaned valueReference choices and search parameters after the MolecularSequence/MolecularDefinition work, so the current absence of valueReference is later context rather than a FHIR-40560 regression. The checked-in source/observation/observation.svg still contains stale MolecularSequence/canonical labels, but it is a generated-looking diagram artifact; under the run guardrail, that residue is not a basis for a source-changing commit when the authoritative XML and search-parameter source are correct.
