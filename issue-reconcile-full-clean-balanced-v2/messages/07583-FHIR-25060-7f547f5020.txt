FHIR-25060: Audit obsolete CarePlan onBehalfOf constraint

Issue request:
FHIR-25060 is Published/Persuasive and asked to correct an invariant described against CarePlan: onBehalfOf.exists() implies (member.resolve() is Practitioner). The requested correction was to avoid failing when member could not resolve, by treating an empty resolve result as acceptable before checking Practitioner type.

Initial application:
No git commit found explicitly mentioning FHIR-25060. The exact requested expression change appears to have been applied implicitly in commit 019e2dd719b6415309a6c1ef0a8e5d176b409251, which changed the old CareTeam spreadsheet invariant from member.resolve() is Practitioner to member.resolve().iif(empty(), true, ofType(Practitioner).exists()). The current Jira comment and matching Zulip discussion note that there is no longer a CarePlan.onBehalfOf element.

Additional context:
CarePlan is an active resource in source/fhir.ini, but current source/careplan/structuredefinition-CarePlan.xml contains no onBehalfOf/member.resolve invariant to correct. The matching CareTeam ctm-1 invariant is now only retained inside an XML comment, while active CareTeam.participant.onBehalfOf source has broader targets and no condition on that obsolete invariant. Later Applied issue FHIR-42928 explicitly removed the CareTeam onBehalfOf invariant and was implemented by commits ad2f38e1c73d13f4f5c352de9392f4300892ffa2 and 18388d3b9a820693ebe675fbaddb23f17a904711.

Keep this audit commit as-is. No current FHIR core source fix is needed for FHIR-25060; any future cleanup of the commented-out CareTeam ctm-1 block should be handled as separate editorial source hygiene, not as this applied CarePlan tracker.
