FHIR-20209: Audit MedicationDispense receiver RelatedPerson support

Issue request:
FHIR-20209 is a Published/Persuasive Pharmacy change request asking to add RelatedPerson to MedicationDispense.receiver so a dispense can record pickup by a caregiver, family member, or similar related person. It was raised against STU3 and applied for R5 with the resolution "Agree, change has been applied."

Initial application:
No commit message in the source history explicitly names FHIR-20209. The same receiver change was already represented by the earlier Published tracker FHIR-19693, whose Jira comment cites applied commit aa42e5dcc1e780bf1fa001dc784d2801f6d3b1d4. That merge contains implementation commit 9d4a0fe09370e2b75ede4debcff124f36c3d3d7e, which changed the MedicationDispense spreadsheet receiver type from Reference(Patient|Practitioner) to Reference(Patient|Practitioner | RelatedPerson | Location) and broadened the receiver definition. The current StructureDefinition source, introduced when the resource source was reworked, carries that RelatedPerson target forward.

Additional context:
MedicationDispense is active in source/fhir.ini, so source/medicationdispense/structuredefinition-MedicationDispense.xml is in current build scope. Later receiver-family decisions did not remove RelatedPerson: FHIR-19698 added PractitionerRole, FHIR-50109 added Organization and updated the receiver definition, and FHIR-42843 rejected adding Person while affirming that RelatedPerson is the intended receiver representation for someone other than the patient or a practitioner. Community searches found no FHIR-20209-specific Zulip or Confluence discussion that conflicts with the Jira/source/git evidence; Pharmacy Confluence notes for the earlier FHIR-19693 work explicitly record the need to add RelatedPerson.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active MedicationDispense StructureDefinition already lists RelatedPerson in MedicationDispense.receiver targetProfile and the generated-looking diagram also reflects it; adding more prose would be redundant and would not change implementer understanding.

Recommendation:
Keep this no-change audit commit as-is. No core FHIR source follow-up is needed for FHIR-20209 unless a future Pharmacy decision reopens the broader receiver target list.
