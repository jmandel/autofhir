FHIR-18326: Audit Patient v2 mapping link

Issue request:
FHIR-18326 was a Published/Persuasive STU3 Patient mapping request to make the HL7 Version 2 mapping link on the Patient mappings page resolve to an appropriate HL7 page.

Initial application:
The issue was applied by fc4ada0543, titled "GF#18326 - fix mapping spaces links", which changed the shared v2 mapping space from an empty link to the HL7 v2 product brief URL. Patient remained an active resource, and its StructureDefinition still declares the v2 mapping URI that feeds the Patient mappings tab.

Additional context:
The current shared mapping space source uses http://www.hl7.org/implement/standards/product_brief.cfm?product_id=185 as the rendered link for the http://hl7.org/v2 mapping URI and now also includes a preamble link to the HL7 v2-FHIR Implementation Guide at https://hl7.org/fhir/uv/v2mappings/. The current build.fhir.org Patient mappings page renders the v2 heading with the product-brief link and the preamble with the v2-FHIR IG link. No Confluence reference or relevant Zulip discussion was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:
No source change was made. The active source already has the working rendered link requested by the issue, and replacing the canonical mapping URI itself would be inappropriate because source/mappingSpaces.xml intentionally separates the mapping-space URL from the human-facing link.

Recommendation:
Keep this audit commit as-is. Further work is only needed if HL7 decides to change the canonical landing page used for all v2 mapping tabs, which would be a separate global mapping-space decision rather than a Patient-specific FHIR-18326 correction.
