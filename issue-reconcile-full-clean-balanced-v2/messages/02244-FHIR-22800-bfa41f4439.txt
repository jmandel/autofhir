FHIR-22800: Audit Procedure BDP usage target

Issue request:
FHIR-22800 was Published/Persuasive for Patient Care. It asked to add BiologicallyDerivedProduct as a Procedure usedReference target so a transplant Procedure can link the recipient Procedure to the donor-derived product.

Initial application:
The issue was applied in commit a073f6090eb1f147ef53d047b9906196d52c103c and merged by PR #614 as 3e8d663ab8fb334c50df71246d6b8fa92973f1b1, changing the then-authoritative Procedure spreadsheet from Reference(Device|Medication|Substance) to Reference(Device|Medication|Substance|BiologicallyDerivedProduct).

Additional context:
Procedure is an active resource in source/fhir.ini. The old spreadsheet was later replaced by source/procedure/structuredefinition-Procedure.xml in commit 33b409a4b6d544598262f2f074ebb4b6dc466157, and the current element is Procedure.used as CodeableReference with target profiles Device, Medication, Substance, and BiologicallyDerivedProduct. The fhir.ini usedReference entries are migration mappings between old and current element names, not active conformance definitions. FHIR-31539 separately reconciled the active FHIR ModelInfo example for the CodeableReference shape and is already represented on the combined branch. Community searches found transplant modeling discussion consistent with using Procedure.used to connect Procedure and BiologicallyDerivedProduct, with no contrary decision requiring a core source change.

AutoFHIR reconciliation:

Keep this audit commit as-is. No further FHIR core work is needed for FHIR-22800 unless a future work group decision changes Procedure/BiologicallyDerivedProduct transplant modeling.
