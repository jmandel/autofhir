FHIR-19296: Audit medication form binding

Issue request:
FHIR-19296 was a Published/Persuasive FHIR-core Pharmacy request to change the Medication and MedicationKnowledge drug form binding to SNOMED CT 736542009, Pharmaceutical Dose Form (dose form), for R5.

Initial application:
The Medication value set was changed from 421967003 to 736542009 in commit 51ce8a822f639be478cea8655beab71f95afb6ab. MedicationKnowledge received the parallel value-set change in commit 634360b51d40494b5427df25cc2ecce831d928e4 and the Jira comment points to merge commit b60fb4b7d3fe218dfc65fc253645e4c6c79d4708.

Additional context:
FHIR-22272 was explicitly closed as a duplicate of this issue after reporting the same 421967003 versus 736542009 mismatch. FHIR-20185 considered, but rejected, using basic dose form instead. Later FHIR-24700 and FHIR-25441 described a build-time expansion error for 736542009; the recorded resolution was that it was a tooling/cache issue, not a source binding reversal. A Zulip terminology thread confirms the same: the 736542009 source change was already made and the remaining failure was caused by terminology/cache state. In the current build configuration, Medication is an active resource; MedicationKnowledge is no longer in the active [resources] list, and its retained source copy already uses the same 736542009 value set definition.

AutoFHIR reconciliation:
No source change was made. Current Medication.doseForm binds to http://hl7.org/fhir/ValueSet/medication-form-codes, and the authoritative Medication value set includes SNOMED CT descendants of 736542009. The legacy MedicationKnowledge source also references the same value set and contains 736542009, while no 421967003 reference remains in either Medication or MedicationKnowledge source directories.

Recommendation:
Keep this audit commit as-is. No current FHIR-core source edit is needed for FHIR-19296; any future concern about expansion availability should be handled as terminology tooling/cache validation, not by changing the binding away from 736542009.
