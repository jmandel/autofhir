Issue request:
FHIR-50412 was Applied/Persuasive for R6 by Patient Care. It requested combining the separate prognosis code and prognosis assessment reference entries into one CodeableReference element, preserving the existing prognosis value set, RiskAssessment reference target, binding strength, and description.

Initial application:
The issue was applied in HL7/fhir commit e29070581efe121910030db864fa0a6bf68ca36b, which changed the renamed resource source at source/clinicalassessment/structuredefinition-ClinicalAssessment.xml from prognosisCodeableConcept plus prognosisReference to ClinicalAssessment.prognosis with type CodeableReference and targetProfile RiskAssessment. The same implementation commit also carried the unrelated FHIR-50192 intro cleanup. The Jira artifact still says ClinicalImpression because FHIR-46596 had renamed ClinicalImpression to ClinicalAssessment before this issue was applied.

Additional context:
Current source/fhir.ini no longer lists either ClinicalAssessment or ClinicalImpression as an active resource. Later commit fad1b9cf84ef652e88947e1a13b026c62f95334e removed ClinicalAssessment from the active draft resource list, resource list, work group mapping, security categorization, FMM table, code map, standards-status table, and rename/version sections. The old source/clinicalimpression folder still contains split prognosis elements, but it is not an active current-build resource input.

AutoFHIR reconciliation:
This is an empty external-repo/build-scope audit commit.
