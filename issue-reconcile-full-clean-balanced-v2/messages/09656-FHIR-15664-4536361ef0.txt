FHIR-15664: Audit Questionnaire enableWhen behavior

Issue request:
FHIR-15664 was a Published FHIR-core Questionnaire change request, resolved Persuasive with Modification for STU3, asking that multiple Questionnaire.item.enableWhen conditions not always be joined as "or". The approved resolution added a code element for all/any behavior, required it when multiple enableWhen criteria need disambiguation, and removed the old statement that multiple enableWhens are always treated as OR.

Initial application:
The issue was initially applied in the historical Questionnaire spreadsheet in git commit 651aa532af (svn build@13259, adjacent to the Jira comment's svn revision 13258). That application added Questionnaire.item.enableBehavior with binding name EnableWhenBehavior, all/any codes, and text saying it controls how multiple enableWhen values are interpreted. The first application did not fully remove the old always-OR wording from the enableWhen comment, but the source was later migrated to structuredefinition-Questionnaire.xml and follow-up issue FHIR-26993/commit 1809c5dcba rewrote the current comment to point explicitly to enableBehavior.

Additional context:
Questionnaire is active in the current build through source/fhir.ini. Later published Questionnaire issues are directly relevant: FHIR-26993 clarified the difference between multiple enableWhen repetitions and multiple answers for a referenced question, while FHIR-26831 and FHIR-32526 corrected que-12 so enableBehavior is required when enableWhen.count() > 1, not only when there are more than two conditions. These later final decisions confirm the current model's use of enableBehavior and its cardinality/threshold.

AutoFHIR reconciliation:
No source change was made. Current source/questionnaire/structuredefinition-Questionnaire.xml defines Questionnaire.item.enableBehavior as a 0..1 code bound required to ValueSet/questionnaire-enable-behavior, states that it controls whether all or any enableWhen values must be true, points the enableWhen comment to enableBehavior instead of an unconditional OR rule, and carries que-12 as enableWhen.count() > 1 implies enableBehavior.exists(). The companion CodeSystem/ValueSet define the all and any codes.

Recommendation:
Keep this empty audit commit as-is. The current source already satisfies FHIR-15664 after the original application and later clarifying/corrective Jira decisions; renaming enableBehavior or requiring it for exactly one enableWhen would conflict with the applied current model and later published corrections.
