FHIR-18245: Audit CDS Hooks PlanDefinition profile move

Issue request:
FHIR-18245 was a Published/Persuasive STU3 CDS change request asking the base specification to define a PlanDefinition profile for a CDS Hooks service. The approved resolution was to create a CDSHooksPlanDefinition profile that includes the CDS Hooks endpoint extension; in source this was implemented as CDSHooksServicePlanDefinition with a required cqf-cdsHooksEndpoint extension slice.

Initial application:
The issue was applied in core by commits 7bcc13fc39 and 99879e4078, which added source/plandefinition/plandefinition-cdshooks-service-spreadsheet.xml and updated the PlanDefinition spreadsheet for CDSHooksServicePlanDefinition. Later source-rework commits, including 33b409a4b6 and c69d71aa21, converted the spreadsheet profile into source/plandefinition/structuredefinition-profile-cdshooksserviceplandefinition.xml and related PlanDefinition-cdshooks pack source.

Additional context:
Later CDS work changed the current build scope. FHIR-48393 was Applied/Persuasive for R6 and explicitly directed CDSHooksServicePlanDefinition, CDSHooksGuidanceResponse, and CDSHooksRequestOrchestration to move out of the base specification and into the Using CDS Hooks/Clinical Reasoning IG. FHIR-53085 was Applied/Persuasive and moved the CDS-on-FHIR content, profiles, and concept maps to the Using FHIR Clinical Reasoning with CDS Hooks IG. Commit 6abb14540e then removed source/plandefinition/structuredefinition-profile-cdshooksserviceplandefinition.xml, the PlanDefinition-cdshooks implementation guide, and the PlanDefinition pack-list entry from core. Current core source keeps PlanDefinition active, has no active CDSHooksServicePlanDefinition profile source or pack entry, and routes detailed CDS Hooks clinical reasoning guidance to the external IG, which now contains StructureDefinition-cdshooksserviceplandefinition.json.

AutoFHIR reconciliation:
This audit intentionally makes no source change. Re-adding CDSHooksServicePlanDefinition to core would reverse later applied CDS decisions that moved the CDS Hooks profiles out of the base specification. The current core source is correct for FHIR-18245 after considering the later profile-move decisions: core keeps high-level PlanDefinition/$apply and CDS Hooks guidance, while the actual profile source belongs in the external IG.

Recommendation:
Keep this no-change audit. Future changes to CDSHooksServicePlanDefinition should be made in HL7/cds-hooks-clinical-reasoning unless a new CDS work-group decision explicitly brings the profile back into the FHIR core build.
