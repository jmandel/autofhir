FHIR-32804: Audit MedicationDispense recorded element

Issue request:
FHIR-32804 was a Published/Persuasive FHIR-core Pharmacy change request asking to add a 0..1 dateTime `recorded` element to MedicationDispense to identify when dispense activity began when `whenPrepared` or `whenHandedOver` is not populated.

Initial application:
The issue appears to have been applied in commit 6cdd7b792e2241b7191584bd35915d4b0f9841f8, which added `MedicationDispense.recorded` as a 0..1 `dateTime` element to the active MedicationDispense StructureDefinition and also added a `recorded` date search parameter. That commit also included the neighboring FHIR-32803 `statusChanged` element.

Additional context:
MedicationDispense is an active resource in `source/fhir.ini`, so `source/medicationdispense/structuredefinition-MedicationDispense.xml` and its search parameter bundle are current build-scope source. Later Applied/Persuasive issue FHIR-40808 clarified that the original FHIR-32804 definition's `if whenPrepared or whenHandedOver is not populated` clause was misleading and changed the authoritative definition to `The date the occurrence of the MedicationDispense was first captured in the system.` The old FHIR-32804 wording remains only in `source/medicationdispense/medicationdispense.svg`, a generated-looking diagram artifact, while the XML source is correct.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the requested element and cardinality are already present in the active StructureDefinition, and the current definition reflects the later Pharmacy-approved FHIR-40808 clarification. Editing the SVG alone would violate the run guardrail against diagram-only source changes when the authoritative source is already correct.

Recommendation:
Keep this audit commit as-is. No FHIR-core source change is needed for FHIR-32804; if the MedicationDispense SVG is still used in publication output, regenerate or review diagram artifacts separately from this issue reconciliation.
