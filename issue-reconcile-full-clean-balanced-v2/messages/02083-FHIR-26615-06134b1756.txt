FHIR-26615: Audit MedicationKnowledge author disposition

Issue request:
FHIR-26615 was a Published/Not Persuasive with Modification Pharmacy change request raised in R4 for R5. It asked to add a coded jurisdiction to MedicationKnowledge to identify the jurisdiction responsible for a formulary. The accepted disposition rejected putting formulary jurisdiction on MedicationKnowledge, said formulary jurisdiction belongs on the formulary-level Composition/List, and instead directed adding a 0..1 author for the organization that created or owns the MedicationKnowledge information.

Initial application:
The issue appears to have been initially applied by git commit 603de50396973db754fec17786a66ce29799296c, which added MedicationKnowledge.author as 0..1 Reference(Organization) in the then-authoritative MedicationKnowledge spreadsheet. No Jira-tagged initial commit added the requested jurisdiction for FHIR-26615, matching the Not Persuasive with Modification resolution.

Additional context:
MedicationKnowledge is active in the current build configuration. The source was later refactored from spreadsheet input to source/medicationknowledge/structuredefinition-MedicationKnowledge.xml. FHIR-32801 made MedicationKnowledge a MetadataResource, FHIR-45285 changed the local author element from Reference(Organization) to ContactDetail for MetadataResource interface compatibility, and FHIR-42901 later changed intendedJurisdiction to the canonical-resource jurisdiction element. Those later applied decisions supersede the exact R5 author type and explain why the current source contains both a MetadataResource-style author and a jurisdiction element without reviving the original FHIR-26615 formulary-level jurisdiction request.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative MedicationKnowledge StructureDefinition already has MedicationKnowledge.author at 0..1, with MetadataResource-compatible ContactDetail semantics, and the current jurisdiction element is justified by later CanonicalResource work rather than by FHIR-26615. Removing jurisdiction or reverting author to Reference(Organization) would contradict later applied issues.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-26615 in the core source; future changes to MedicationKnowledge author or jurisdiction should be handled through the later MetadataResource/CanonicalResource issue family rather than this R4 formulary-jurisdiction request.
