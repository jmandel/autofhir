FHIR-50127: Audit Observation.specimen comment update

Issue request:
FHIR-50127 was an Applied FHIR-core Observation change request from OO, resolved Persuasive with Modification for R6, asking to replace the Observation.specimen comment that discouraged use when specimen was implicit in Observation.code. The accepted wording says Observation.specimen SHOULD be used when an observation is performed on a specimen and that the specimen type SHOULD be consistent with anything implied by Observation.code.

Initial application:
The issue was already applied before this reconciliation. Commit 21683fadd8 changed source/observation/structuredefinition-Observation.xml from the old "Should only be used if not implicit" comment to the accepted specimen-use guidance, and commit 1b060a6f4f updated the two conformance words from "should" to "SHOULD" after QA feedback. The current combined branch already contains the resulting comment on Observation.specimen.

Additional context:
source/fhir.ini lists observation as an active resource, so source/observation/structuredefinition-Observation.xml is in the current build scope. OO WGM minutes on Confluence record the FHIR-50127 motion as persuasive with modification with a 14-0-0 vote. The Jira comment on PR #3556 notes that bolding the conformance words was not possible in this conformance text, which is consistent with the XML comment using plain uppercase SHOULD. Direct Zulip search for FHIR-50127 and Observation.specimen found no conflicting discussion.

AutoFHIR reconciliation:
No source files were changed. The active Observation.specimen comment already says "SHOULD be used when the observation is performed on a specimen. The type of specimen SHOULD be consistent with anything implied in the `Observation.code` value.", which preserves the accepted resolution with a minor grammatical article and source markup for Observation.code.

Recommendation:
Keep this audit commit as-is. No further core FHIR source work is recommended for FHIR-50127 unless the work group later decides to add separate guidance about source site versus specimen type, which was only raised as a possible separate topic in Jira comments.
