FHIR-22841: Audit inactive ClinicalImpression status

Issue request:
FHIR-22841 was a Published/Persuasive Patient Care change request for FHIR-core ClinicalImpression, raised against STU3 and applied for R5. It warned that ClinicalImpression must have an entered-in-error status and the approved resolution was to update the resource spreadsheet accordingly.

Initial application:
The Jira comment says the change was pre-applied on July 12, 2019 by GitHub commit b4abe67. In source history, b4abe673dd1cf78c64b7ff0bdb85ae272af41fe7 added the ClinicalImpression spreadsheet instruction entered-in-error-status = .status = entered-in-error. Later source rework migrated the resource to StructureDefinition XML, where the residual ClinicalImpression source still carries the entered-in-error-status build extension, includes entered-in-error in ClinicalImpression.status, and includes entered-in-error in the ClinicalImpression status value set and search-parameter description.

Additional context:
Later FHIR-46596 renamed ClinicalImpression to ClinicalAssessment for R6 in commit 670d3a407a962cdde0ef1136fbcdea045b124f19; that renamed source also preserves the entered-in-error status extension, status code, modifier rationale, value set code, and search-parameter description. FHIR-46596 is already represented on the combined branch by c2ae6dad7eeae9e6652fcd5dff5e19f6159bdd3d. After that, commit fad1b9cf84ef652e88947e1a13b026c62f95334e removed ClinicalAssessment from the active source/fhir.ini resource registrations, and current build URLs for ClinicalImpression and ClinicalAssessment return 404. Active current pages now point ClinicalAssessment to the Patient Care incubator rather than an active core resource page.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The requested status was historically applied and preserved through the ClinicalAssessment rename, but neither ClinicalImpression nor ClinicalAssessment is an active current-build core resource. Editing residual out-of-build ClinicalImpression or ClinicalAssessment resource files would not correct a current built artifact.

Recommendation:
Keep this external-repo audit commit as-is for the current core build. If Patient Care restores ClinicalAssessment to core or maintains it in the incubator, verify that the maintained artifact continues to expose entered-in-error as a valid status and modifier reason.
