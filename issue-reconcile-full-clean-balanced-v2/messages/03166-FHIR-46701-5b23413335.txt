FHIR-46701: Audit NutritionIntake statusReason and performer

Issue request:
FHIR-46701 was Applied with Persuasive with Modification resolution for R6. It asked to replace the inappropriate NutritionIntake.statusReason example binding to clinicalimpression-status-reason with a NutritionIntake-specific example value set containing patient factors, and to revise NutritionIntake.performer wording using the event performer pattern: performer, function, and actor.

Initial application:
The performer wording was pre-applied in commit 05e646d74bb93a1c435d884747dc64da94898435, which changed NutritionIntake.performer to "Who or what performed the intake and how they were involved," NutritionIntake.performer.function to "Type of performance," and NutritionIntake.performer.actor to "Who or what performed the intake." Commit a7259ce6c19569a3bd8cc7fc7c788755c10f9ab4 then created the NutritionIntake status-reason CodeSystem and ValueSet and changed NutritionIntake.statusReason to bind to http://hl7.org/fhir/ValueSet/nutritionintake-status-reason.

Additional context:
NutritionIntake is an active resource in source/fhir.ini, so source/nutritionintake feeds the current build. OO minutes for 2025-01-15 confirm the work group vote and record the intended implementation: create value sets and model the performer/actor branch from the event resource pattern. Later Applied issue FHIR-53303 refined the same statusReason terminology by replacing inactive SNOMED CT Patient Died with Dead 419099009, removing Entered in Error, replacing numeric local codes with mnemonic codes, and enumerating the accepted local concepts. Later Applied issue FHIR-55266 deliberately made the CodeSystem and ValueSet experimental while THO migration remains unsettled.
