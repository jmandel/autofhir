FHIR-53882: Audit AuditEvent agent role clarity

Issue request:
FHIR-53882 was Applied/Persuasive with Modification for FHIR-core AuditEvent. It asked for clearer guidance distinguishing AuditEvent.agent.type from AuditEvent.agent.role, especially around ISO 21298 functional and structural roles and whether security roles are a subtype of structural roles. The accepted resolution clarified that agent.type is simply how the agent participated in the recorded activity and need not correlate to ISO 21298 Functional Role, while agent.role records roles authorizing participation and may indicate ISO 21298 Functional Role and/or Structural Role concepts.

Initial application:
The issue appears to have been applied by commit 21041c1f5b03e6d5abd1e72e9c385be3be440272, merged by HL7/fhir#4066 in deab26af0c61935e2d6038b30431df61bbb3dfcd. That commit changed source/auditevent/structuredefinition-AuditEvent.xml for AuditEvent.agent.type and AuditEvent.agent.role from the older ISO-centric functional/structural definitions to the accepted participation/authorization wording.

Additional context:
source/fhir.ini actively lists auditevent=AuditEvent, so source/auditevent/structuredefinition-AuditEvent.xml is current build scope. Current source has the accepted agent.type definition, comment, and requirements, and the accepted agent.role definition, comment, and requirements. A related Zulip implementers thread shows the same pre-resolution confusion about agent.type versus agent.role and John Moehrke's guidance that agent.role is broad while agent.type is how the agent participated; it does not conflict with the Jira resolution. The only remaining older AuditEvent wording found is in generated-looking SVG tooltips and historical XML comments in mapping-exception metadata, not in the authoritative element definitions.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because the authoritative AuditEvent StructureDefinition source already implements the applied Jira resolution. The stale source/auditevent/auditevent.svg tooltip was intentionally not edited because this workflow does not make source-changing commits whose only edit would be a generated-looking resource diagram.

Recommendation:
Keep this audit commit as-is. If the Security WG wants additional narrative text in the AuditEvent introduction or regenerated diagram tooltips, handle that as a separate source/generation decision; FHIR-53882's accepted element-definition clarification is already present.
