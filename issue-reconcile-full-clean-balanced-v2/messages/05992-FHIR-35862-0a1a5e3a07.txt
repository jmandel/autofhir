FHIR-35862: Audit product lot/serial search parameters

Issue request:
FHIR-35862 was a Published/Persuasive with Modification OO change request for R5. It asked for a way to search product resources by lot number or serial number when a barcode or product identifier is known but the server's product resource type is not known. The related artifacts were Device, BiologicallyDerivedProduct, Medication, and NutritionProduct.

Initial application:
The issue was applied in commit 31564391acbf120de82ad6b2720eb87e3270659a, which added serial-number search parameters for BiologicallyDerivedProduct, Medication, and NutritionProduct, added lot-number for NutritionProduct, and made related product-code alignment changes later handled under FHIR-40397. Commit 08f4ca1bb8bc36faf757a479c54a52f3c02e0429 added NutritionProduct-lot-number, and commit 7ab5e1f3da672bd2b30b9d167228006851dcde7f corrected the initial NutritionProduct code typo from loy-number to lot-number. Device already had lot-number and serial-number search parameters from earlier Device production identifier work.

Additional context:
The May 2022 OO WGM minutes and the earlier Zulip thread both frame the requirement as cross-resource searching over product resources by using common search parameter codes. Current search rules allow root-level searches with _type when the other search parameters are common to the provided types. Later applied work changed Medication.batch to Medication.instance and moved the Medication serial-number search parameter to Medication.instance.identifier under FHIR-47622. Later BDP search-parameter review in FHIR-51588/FHIR-53204 kept BiologicallyDerivedProduct-serial-number on BiologicallyDerivedProduct.identifier and did not add a lot-number parameter; the current BiologicallyDerivedProduct structure has no lotNumber element. FHIR-40397, FHIR-47622, FHIR-14765, and FHIR-37979 already have reconciliation commits on the combined branch, so they are context rather than additional decisions here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Device, Medication, NutritionProduct, and BiologicallyDerivedProduct are active resources in source/fhir.ini. The current source has serial-number on all four product resources where serial/instance identifiers exist, has lot-number on Device, Medication, and NutritionProduct where lotNumber elements exist, and does not add a BiologicallyDerivedProduct lot-number parameter because there is no BDP lotNumber source element and later BDP search-parameter review did not introduce one.

Recommendation:
Keep this audit commit as-is. If the work group later wants BiologicallyDerivedProduct to carry a distinct lot number, that should be a new BDP modeling decision before adding a BDP lot-number search parameter. Do not publish another FHIR-35862 source change unless that modeling decision is made or current build tooling stops exposing the shared lot-number/serial-number codes for the product resources that define them.
