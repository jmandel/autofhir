FHIR-39002: Audit Transport workflow classification

Issue request:
FHIR-39002 was Published with a Not Persuasive with Modification resolution for R5. The reporter observed that the Workflow resource list showed Transport under Events only while Transport had the same footnote as Task saying it shares Request and Event characteristics. The accepted disposition was that Transport should not support the Request side; FHIR-39512 would correct Transport's scope, and the Workflow Request/Event list would remain correct unless a future TransportRequest resource is created.

Initial application:
No Jira-tagged FHIR-39002 source commit was found. Historical source shows the original Transport workflow-list commit added Transport under Events with the Task-style footnote, and a later untagged cleanup commit removed that footnote from Transport. The related FHIR-39512 work then aligned Transport's own resource definition and narrative with Event semantics.

Additional context:
The Workflow overview is in current build scope through source/hierarchy.xml. Current source/workflow.html lists Transport only in the Events section and no longer attaches the Task request/event footnote to Transport; the only remaining footnote text applies to Task. Current Transport source describes Transport as an event resource, has no Transport.intent or Transport.priority elements, and its basedOn targets are limited to authorizing requests and Task. The combined branch already contains the source-changing FHIR-39512 reconciliation commit, so this seed should not duplicate that related issue.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current Workflow list and Transport resource semantics already implement the FHIR-39002 disposition after considering FHIR-39512, and adding Transport to the Request list would contradict the published resolution.

Recommendation:
Keep this no-change audit commit. Revisit only if a future approved TransportRequest resource is introduced or a later workflow decision changes Transport's classification; otherwise the current source should remain Event-only for Transport.
