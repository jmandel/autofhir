FHIR-32470: Audit lifecycle extension ownership

Issue request:
FHIR-32470 was Published as Persuasive with Modification for R5. It asked to remove AuditEvent.entity.lifecycle because the lifecycle-event codes were not appropriate for an extensible binding on a lifecycle-state element, and to preserve the capability as a core auditevent-Lifecycle extension with an example binding to the DICOM object lifecycle value set.

Initial application:
The Jira-tagged core commit c91fb9ed1f removed AuditEvent.entity.lifecycle from source/auditevent/structuredefinition-AuditEvent.xml and added source/auditevent/structuredefinition-extension-auditevent-Lifecycle.xml. That initial extension used a preferred binding, even though the Jira disposition and Security WG minutes described an example binding.

Additional context:
The current core build keeps AuditEvent active, no longer contains an AuditEvent.entity.lifecycle element or any lifecycle extension definition, and records the R4-to-R6 deletion map as use of http://hl7.org/fhir/StructureDefinition/auditevent-Lifecycle. Commit dd468d4f17 removed the AuditEvent extension definitions from the core R5 source. The live auditevent-Lifecycle definition is now in the FHIR Extension Pack checkout, where Extension.value[x] still binds to object-lifecycle-events with strength preferred.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The core AuditEvent resource already reflects the requested element removal, and the remaining binding-strength discrepancy belongs to the external FHIR Extension Pack source rather than this core FHIR checkout.

Recommendation:
Keep this core audit commit as-is. Follow up in the FHIR Extension Pack if the Security WG still intends the auditevent-Lifecycle Extension.value[x] binding to be example rather than preferred.
