FHIR-28291: Restore Group characteristic-reference search

Issue request:
FHIR-28291 is a Published/Persuasive FHIR-I change request for FHIR-core Group. It asked that searching /Group?characteristic-reference=Organization/123 return Groups with any characteristic whose value references Organization/123, because this is useful for bulk data and patient lists.

Initial application:
The request was originally applied by commit 7b5847c83c5ea46b8982c2cb4e974103c8f69fcf, which added Group-characteristic-reference to source/group/bundle-Group-search-params.xml as a reference search parameter over Group.characteristic.value. The R5 history artifact still records characteristic-reference as a reference search parameter with documentation "An entity referenced in a characteristic."

Additional context:
Group is active in source/fhir.ini, so source/group/bundle-Group-search-params.xml feeds the current build's Group search-parameter registry. Later source history changed Group-characteristic-reference into a composite parameter while working around other Group/search issues: bf998a18b975a1d3dc8f9a3261a43f08a038815d, labeled for unrelated FHIR-48885 conformance wording, introduced the semantic drift; the later FHIR-40341 reconciliation only fixed the resulting malformed component expression and did not establish a decision superseding FHIR-28291's plain reference query shape. Composite parameters require component values joined with "$", so the current composite definition no longer represented the approved /Group?characteristic-reference=Organization/123 behavior.

AutoFHIR reconciliation:
Restored Group-characteristic-reference to a reference search parameter with expression (Group.characteristic.value.ofType(Reference)) and the original reference-oriented description. This keeps later unrelated Group search parameters intact while preserving the exact conformance behavior FHIR-28291 approved.

Recommendation:
Keep this source-changing commit. If the work group wants an additional code-plus-reference composite search on Group.characteristic in the future, handle it with a separate Jira issue and a distinct parameter design so the existing FHIR-28291 reference search remains usable.
