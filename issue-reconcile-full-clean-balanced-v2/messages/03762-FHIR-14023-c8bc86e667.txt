FHIR-14023: Restore MedicationStatement Event partOf mapping

Issue request:
FHIR-14023 was a Published/Persuasive with Modification Pharmacy change request for STU3 asking to align MedicationStatement to the updated Workflow Event pattern. The approved resolution was the attached MedicationStatement-to-Event mapping spreadsheet.

Initial application:
The issue was initially applied by git commit 9a6a9299297f9ef2a54b4ed2a7f815c7de8600dd, "GF #14023 - align MedStatement to Event pattern", which updated the active MedicationStatement spreadsheet and examples. That application included Workflow Mapping = Event.partOf for MedicationStatement.partOf, along with the broader Event mapping alignment for identifier, status, medication/code, subject, context, occurrence, reasons, and note.

Additional context:
MedicationStatement remains an active current-build Pharmacy resource in source/fhir.ini and is listed as a Workflow Event resource. Later final Pharmacy decisions changed the resource shape without reversing the Event-pattern relationship: FHIR-36001 restored partOf for the Procedure use case after an R5 removal, FHIR-38690 added the MedicationStatement target for parent/child usage statements, FHIR-38682 renamed MedicationUsage back to MedicationStatement, and FHIR-39271 confirmed the current status/adherence redesign. FHIR-57403 is a newer Submitted, unresolved question about explaining or removing MedicationStatement.partOf, so it is background only and not a current source-edit decision. Current source still had MedicationStatement.partOf with Event-like wording and the workflow warning suppression already treated it as Event.partOf, but the StructureDefinition no longer carried the workflow mapping and the mapping exception file still listed Event.partOf as unmapped.

AutoFHIR reconciliation:
This commit restores the missing MedicationStatement.partOf workflow mapping to Event.partOf and changes the Event mapping exception from an unmapped-element exception to a divergent-element exception documenting the narrowed target types and summary mismatch. It intentionally does not change the partOf cardinality, target profiles, or summary flag because those are governed by later Pharmacy decisions and the unresolved FHIR-57403 discussion.

Recommendation:
Keep this source fix. If Pharmacy later resolves FHIR-57403 by explaining or removing MedicationStatement.partOf, that later decision should update the element and mapping metadata together; until then, the current element should be mapped consistently to the Event pattern.
