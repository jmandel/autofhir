FHIR-11185: Audit MedicationStatement source references

Issue request:
FHIR-11185 was a Published/Persuasive with Modification Pharmacy change request originally asking that MedicationStatement.informationSource reference Any. The accepted resolution narrowed that request: rename MedicationStatement.supportingInformation to MedicationStatement.derivedFrom, keep derivedFrom as the Reference(Any)-style link to underlying resources, add Organization to MedicationStatement.informationSource, and update the element definitions.

Initial application:
The issue was applied in git commit 71c71d0b166b939f1daf16ce513c66bce931fc3d, which changed the then-authoritative MedicationStatement spreadsheet source: informationSource gained Organization, supportingInformation was renamed to derivedFrom, and the definitions were updated. The current branch did not already contain an AutoFHIR Issue-Reconcile-Key commit for FHIR-11185.

Additional context:
MedicationStatement is active in the current build through source/fhir.ini. The current StructureDefinition source preserves the requested split: informationSource is not an unconstrained Any reference, but includes Organization plus later approved targets, while derivedFrom is the element that references Resource/Any for material used to derive the MedicationStatement. The old supportingInformation name is also mapped forward to derivedFrom in source/fhir.ini. Later Pharmacy work, including FHIR-41760, added a separate author element and reinforced that informationSource remains the who/what source of the information rather than the derivation artifact link.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already carries the accepted FHIR-11185 resolution, and changing informationSource to Reference(Any) now would contradict the original persuasive-with-modification decision and the later current-source model.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-11185; future work on informationSource should be handled through later Pharmacy issues such as the already separate author/informationSource changes rather than reopening this DSTU2 rename-and-target decision.
