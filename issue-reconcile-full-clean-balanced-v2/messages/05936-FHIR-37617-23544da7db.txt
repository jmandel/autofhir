Issue request:
FHIR-37617 was a Published/Persuasive FHIR-core R5 change request for Questionnaire asking to remove the 'unit' display item-ControlType code because the questionnaire-unit extension could serve the same purpose.

Initial application:
The Jira comment cites Git 1197ebc. In the FHIR Extension Pack, commit 1197ebcd1e41613e799f557d617c2021dbf5d5f1 applied the issue by deprecating, rather than deleting, CodeSystem questionnaire-item-control code 'unit' and adding status/deprecationDate properties. I found no current FHIR-core source definition for the questionnaire-item-control CodeSystem, ValueSet, or questionnaire-itemControl extension beyond retained OID mappings.

Additional context:
Questionnaire remains an active core resource, but the affected item-control terminology and extension definitions now live in the FHIR Extension Pack. Current Extension Pack source contains CodeSystem-questionnaire-item-control with an active 'unit' concept, and FHIR-50277 later requested reinstating that code because questionnaire-unit does not provide fully equivalent UI display behavior; Extension Pack commit 630a5f849fafd7e14a7add6549debdf3c2189650 removed the FHIR-37617 deprecation wording. Zulip and SDC minutes show the original 2022 FHIR-37617 feedback/vote path, but the later external-pack decision changes how the artifact should be interpreted now.

AutoFHIR reconciliation:
This empty audit commit makes no FHIR-core source change. The remaining affected artifact is outside this core checkout, and the current external source is intentionally no longer carrying the FHIR-37617 deprecation/removal state after FHIR-50277.

Recommendation:
Keep this core audit commit as-is. Do not remove or deprecate 'unit' in FHIR-core because core no longer owns the item-control CodeSystem source; any future change belongs in the FHIR Extension Pack and should account for FHIR-50277's later rationale.
