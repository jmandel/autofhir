FHIR-17725: Audit OperationDefinition parameter profile support

Issue request:
FHIR-17725 was Published/Not Persuasive with Modification for STU3. It reported that OperationDefinition.parameter.targetProfile was too tight because a profile needed to apply to a resource embedded directly in an operation invocation, not only to a canonical or Reference target. The approved resolution was to add an operationdefinition-profile extension legal on all OperationDefinition.parameter types, with possible elevation to core in R5.

Initial application:
The issue was applied by git commit b7251b1f8b23b2fe0f46e6b5fc977cbf36ac6ec3, which added support for operationdefinition.parameter.profile in the OperationDefinition spreadsheet. The historical extension has since moved out of the core source tree with the other core extensions, while current core keeps an active old-to-new mapping from OperationDefinition.parameter.profile to OperationDefinition.parameter.targetProfile.

Additional context:
OperationDefinition is an active current-build resource in source/fhir.ini. The FHIR Extension Pack now contains StructureDefinition/operationdefinition-profile with context OperationDefinition.parameter, preserving the legacy extension definition outside this core checkout. Later Published issue FHIR-26411 elevated the inline-resource behavior into core for R5 and is already represented on the combined branch. Later same-family reconciliations for FHIR-39345 and FHIR-44690 also already exist on the combined branch and explain the current opd-3/all-resource-types rule and targetProfile prose.

AutoFHIR reconciliation:
Made no source change. The build-scoped OperationDefinition StructureDefinition already allows targetProfile for Reference, canonical, and resource parameter types, and its definition explicitly says resource-typed parameters use targetProfile to identify profiles or implementation guides that apply to the inline resource instance. The legacy extension definition is maintained in the Extension Pack rather than in this core checkout, so there is no missing core source edit for this STU3 audit.

Recommendation:
Keep this no-change audit commit as-is. Future changes to operationdefinition-profile itself belong in the FHIR Extension Pack, while any further core redesign of OperationDefinition.parameter target/profile naming would require a new work-group decision.
