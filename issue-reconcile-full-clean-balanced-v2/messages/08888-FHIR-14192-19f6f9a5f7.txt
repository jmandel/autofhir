FHIR-14192: Audit Break the Glass clarifications

Issue request:
FHIR-14192 was a Published/Persuasive STU3 FHIR-I issue asking to clarify the Break the Glass description. The issue challenged presenting an HTTP header as if it were a security mechanism, asked that the text explain authorization, consent, and resource-server responsibilities, requested appropriate PurposeOfUse vocabulary, AuditEvent linkage, top-level Security-page visibility, and guidance about how a client or user knows Break the Glass is available. The final resolution was to add documentation about proper use of the operation.

Initial application:
The issue was applied historically in git-svn commit e0fb4dcd4e8de6a68f5c9e68dfd37b64ab9b1007, whose message explicitly says "GF#14192 - notes about break-the-glass" and maps to svn revision 14473, matching the Jira application comment. That patch rewrote the Security Labels Break the Glass text to describe the BTG purpose-of-use label in the request, identify it as an HTTP Category example rather than a complete security mechanism, and add dragon-note responsibilities for initiation, authorization, consent/access control, and AuditEvent representation.

Additional context:
The current build now places the standalone Break the Glass section on source/security.html rather than source/security-labels.html because Applied R6 issue FHIR-53885 moved it away from security-label-specific guidance. Related final BTG work refined the same area: FHIR-5935 established the no-policy/no-protocol caveat, FHIR-9167 added the break-glass AuditEvent example and security-page pointer, FHIR-27917 changed the OperationOutcome hint from ETREAT to the more specific BTG code, FHIR-42756 corrected the BTG terminology URL, and FHIR-42757 added the OAuth purpose-of-use alternative. Those related issues are already represented on the combined branch or are historical source commits, so this seed should not duplicate their commits.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope Security page already has a dedicated Break the Glass section, uses v3-ActReason#BTG for the BTG protocol examples after later final terminology decisions, says FHIR does not define policy or protocol around such requests, and lists the implementation responsibilities FHIR-14192 asked to clarify: when and how to initiate BTG, authorization/consent/access-control checks, AuditEvent representation, and an OperationOutcome example to signal that BTG may be available. The Security Labels page correctly records the later FHIR-53885 removal of the standalone BTG section rather than duplicating moved guidance.

Recommendation:
Keep this no-change audit commit as-is. No further core source work is indicated for FHIR-14192 unless the Security WG later decides to redesign the remaining BTG guidance, especially the experimental HTTP Category mechanism, under a newer final tracker.
