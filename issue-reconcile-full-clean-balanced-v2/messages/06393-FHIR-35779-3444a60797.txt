FHIR-35779: Audit R4B version-specific profile table

Issue request:
FHIR-35779 was a Published/Persuasive technical correction asking that source/versioning.html#mp-version remove the obsolete "(this version)" and "(once published)" wording from the FHIR R4 row and add a FHIR R4B row with version 4.3, so implementers could identify the proper fhirVersion value for 4.3.0.

Initial application:
No commit in the local history explicitly mentions FHIR-35779. The same table was updated implicitly by the February 2022 "Version info updates" commit, which removed the R4 publication qualifiers and added R4B as 4.3 with an interim "once published" note; the April 2022 R4B finalization commit then removed the interim R4B note and left the version-specific profile table with R4 = 4.0 and R4B = 4.3.

Additional context:
FHIR-31715 made the parallel normative http.html fhirVersion MIME-type table include R4B as 4.3 and remove the R4 publication qualifier. FHIR-35779's comments confirmed that the normative http.html table had already been fixed, but versioning.html was still wrong at that time. The current versioning page is an active built narrative page referenced from source/hierarchy.xml, source/documentation.html, and source/modules.html, and its current mp-version table now matches the FHIR-35779 request.

AutoFHIR reconciliation:
This commit intentionally makes no source change because source/versioning.html already has a FHIR R4 row with value 4.0 and no obsolete qualifier, plus a FHIR R4B row with value 4.3. Adding another source edit would be redundant and would not change implementer understanding.

Recommendation:
Keep this no-change audit commit as-is. No follow-up is needed for FHIR-35779 in the core source; FHIR-35780 remains a separate related canonical-reference guidance issue and was not re-decided here.
