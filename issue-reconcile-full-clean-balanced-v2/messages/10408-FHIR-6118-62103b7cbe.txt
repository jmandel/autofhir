FHIR-6118: Audit HTTP 409 contention status guidance

Issue request:
FHIR-6118 was a Published/Persuasive FHIR-core HTTP change request from DSTU1. It asked why update/version conflict handling used 409 when update ignores meta.versionId, requested that the rejecting-updates status-code list link down to Managing Resource Contention, and recorded the then-approved DSTU1 rule that 409 was the actual conflict status while 412 was for a server-required contention-management precondition such as a missing ETag/If-Match header.

Initial application:
The Jira comments cite svn revision 5962. In git history this is d26d81284b80a97dd876119b88e0f14846d25fb1, which changed source/http.html to make the status-code list link to #concurrency and changed the resource-contention text to say a non-matching If-Match returned 409 Conflict while a missing required If-Match returned 412 Pre-condition failed.

Additional context:
The current combined branch source/http.html is the active RESTful API page linked from the Exchange module. The FHIR-6118 cross-reference is still present in the rejecting-updates status-code list. The old 409/412 mapping should not be restored because later Published/Persuasive FHIR-16096 explicitly corrected the HTTP semantics: failed client If-Match preconditions now return 412 Precondition Failed, a server requiring If-Match can return 400 Bad Request when it is absent, and 409 Conflict remains available for server-detected conflicts such as pessimistic locking. FHIR-16096 is already represented on the combined branch by audit commit a07984311cda53cd6da7401cb4ce412dfa5fbbb9. Later FHIR-31927 was Resolved - No Change and did not add an alternate contention mechanism.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The remaining part of FHIR-6118 that is still valid for the current specification, the down-link from the update error list to Managing Resource Contention, is already present. The parts that differ from the original DSTU1 application were deliberately superseded by FHIR-16096 and match current HTTP precondition guidance.

Recommendation:
Keep this audit commit as-is. Do not reapply the original FHIR-6118 409-on-If-Match-failure wording; any future changes to contention status-code policy should be handled through a new FHIR-I HTTP decision that also accounts for FHIR-16096.
