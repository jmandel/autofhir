FHIR-6079: Audit StructureDefinition target type

Issue request:
FHIR-6079 was Published/Persuasive with Modification for DSTU1. It asked for StructureDefinition to regain a reliable target type property identifying the resource or datatype described by a profile. The accepted resolution renamed the old broad StructureDefinition.type discriminator to StructureDefinition.kind and added StructureDefinition.constrainedType for the constrained resource/datatype.

Initial application:
The issue was applied in the historical source by git-svn commits 48ea201bd7de1c0c76d67ca9b73c59039bf93cd1 (#6079 - rename StructureDefinition.type to .kind, and add StructureDefinition.constrainedType) and 8acb090fde681492885acf9e81247adc673b22b7 (#6079 - update rules and narrative for structuredefinition), matching the Jira comment citing svn revisions 5799 and 5800. Later source evolution renamed the DSTU2 constrainedType element to the current StructureDefinition.type, with source/fhir.ini retaining the R2 rename map StructureDefinition.constrainedType=StructureDefinition.type.

Additional context:
The current active StructureDefinition resource is in build scope through source/fhir.ini. Its source defines StructureDefinition.kind as a required kind discriminator, StructureDefinition.type as a required URI whose short description is "Type defined or constrained by this structure", and StructureDefinition.baseDefinition plus StructureDefinition.derivation for the specialization/constraint relationship. The StructureDefinition notes page uses the same current model with kind, type, abstract, and baseDefinition. Later related Jira issues FHIR-10582 and FHIR-17505 confirm that constrainedType was intentionally replaced by type and stale documentation was cleaned up; FHIR-17505 is already represented on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already satisfies the FHIR-6079 requirement through the required StructureDefinition.type element and its explanatory comment, while retaining kind/baseDefinition/derivation for the surrounding model. The only remaining constrainedType occurrences found in current source are the historical R2 rename mapping and a release-history note, not current StructureDefinition guidance.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-6079 unless a future work group decision changes the current type/baseDefinition/derivation model.
