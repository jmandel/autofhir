FHIR-16114: Audit slider step extension ownership

Issue request:
FHIR-16114 was Published/Persuasive for STU3 Questionnaire and asked for a core Questionnaire extension, slider-step-value, to express a range step size. The resolution said to add slider-step-value with an integer-item-only constraint and described the value as positiveInt.

Initial application:
The issue appears to have been applied in SVN r14772 / git b8c5990ac5, whose commit message lists 16114. That change added sliderStepValue to the Questionnaire extensions spreadsheet with context type='integer', value type integer, and the definition "For slider-based controls, indicates the step size to use when toggling the control up or down." Generated core extension output later contained StructureDefinition/questionnaire-sliderStepValue with value[x] type integer.

Additional context:
Current core source no longer contains the extension StructureDefinition; core retains only the canonical OID assignment. Git dd468d4f17 removed extension definitions from R5 core source, and the current FHIR Extension Pack checkout contains input/definitions/multiple/StructureDefinition-questionnaire-sliderStepValue.xml as the active definition. That external definition keeps the requested Questionnaire.item/ElementDefinition contexts and integer-item contextInvariant, but any potential refinement from integer to positiveInt would belong in HL7/fhir-extensions, not this core checkout. Zulip discussion confirms the original need and later use of minValue, maxValue, and sliderStepValue for slider controls.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The current core build does not own the sliderStepValue StructureDefinition, so editing core would either reintroduce an out-of-scope extension definition or touch only the retained OID registry. The seed is recorded as external-repo because the only plausible remaining source follow-up is in the FHIR Extension Pack.

Recommendation:
Keep this audit commit as-is for the core reconciliation. If the work group wants to enforce the resolution's positiveInt wording exactly, file or apply that follow-up in HL7/fhir-extensions by changing questionnaire-sliderStepValue value[x] or adding an equivalent value constraint there.
