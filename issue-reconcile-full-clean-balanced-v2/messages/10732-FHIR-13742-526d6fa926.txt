Issue request:
FHIR-13742 was a Published FHIR-core change request with a Persuasive resolution for STU3. It asked FHIR-I to formalize the common unofficial `_pretty=true` parameter so clients could request pretty-printed responses.

Initial application:
The Jira comment records application in svn revision 12830, and git commit f40ead5f8ec27b18de2fde36556825c3a0663a68 (`#13742 - document _pretty parameter`) added the `_pretty` HTTP query parameter, the `?_pretty=true` example, the true/false values, and optional server support language to `source/http.html`.

Additional context:
The current build's RESTful API source page still contains the `_pretty` entry in the general interaction parameters table and a dedicated `_pretty` section. Later Published issue FHIR-16438 refined the same area by moving `_pretty` into the general-parameters table and changing the support wording to `servers MAY choose to support this parameter`; that related issue is already represented on the combined branch.
