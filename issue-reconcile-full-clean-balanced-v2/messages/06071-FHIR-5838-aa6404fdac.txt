FHIR-5838: Audit List title and note coverage

Issue request:
FHIR-5838 was Published/Persuasive with Modification for the DSTU1 List resource. It asked to support IHE/XDS Folder title and comments by adding List.title and List.note, both 0..1 strings, so they could describe the contents of the List and be searchable.

Initial application:
No git commit explicitly names FHIR-5838, but commit db4ace37c6615c9732f958d34d6286fe739fc657, described as PC-approved List/CarePlan/FamilyHistory changes, added List.title as 0..1 string and List.note as 0..1 string in the List spreadsheet shortly after the Jira vote. FHIR-6963 then corrected the introduced List.note short text from "Comments about the note" to "Comments about the list". The current source was later reworked into structuredefinition-List.xml, where the active List resource still has List.title and List.note.

Additional context:
FHIR-5650 is the XDS Folder parent issue that records creating FHIR-5838 for Title and Comments. Current source/fhir.ini actively builds list=List. The current List.title remains 0..1 string and has an XDS SubmissionSet.title mapping. List.note is now 0..* Annotation, with a string SearchParameter on List.note.text named notes; this preserves the requested text/comment capability and searchability while matching the modern FHIR pattern for annotations. Git history shows the note datatype/cardinality changed in a broad QA/source update (3d9011ca909323a6703520954c18ee1273f8531c), not as an omitted application of FHIR-5838. Confluence and Zulip searches found no conflicting later community decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope List source already provides a title and overall-list comments, and the active search parameter bundle exposes both List.title and List.note.text as string searches. Reverting List.note to a single string would be a backward-moving change not supported by the issue family.

Recommendation:
Keep this no-change audit commit as-is. Future work should not reopen FHIR-5838 unless a separate work-group decision specifically asks to change List.note away from Annotation/repeatable notes or to alter the current search parameter behavior.
