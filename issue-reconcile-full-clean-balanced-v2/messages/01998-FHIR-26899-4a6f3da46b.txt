FHIR-26899: Audit conditional Dosage extension scope

Issue request:
FHIR-26899 was Published with a Persuasive with Modification resolution for R5. It asked to update the draft conditional Dosage extension so meetGoal.goal, whenTrigger.trigger, and precondition.condition could be represented as either a reference or valueString, and to narrow the trigger/precondition reference targets to ActivityDefinition and ObservationDefinition where specified.

Initial application:
The issue was initially applied in core by 76ef92c359, which updated source/datatypes/dosage-extensions-spreadsheet.xml for meetGoal.goal and whenTrigger.trigger to allow string plus references and changed the trigger/precondition reference targets. That application did not add string to precondition.condition. Later core history removed the dosage extension spreadsheet from the active build source, leaving the current core checkout without an active dosage-conditions extension definition to edit.

Additional context:
Current source/fhir.ini actively lists DosageCondition as a datatype and maps it to the dosage page, but the [profiles] section no longer includes dosage-extensions or dosage-conditions. The FHIR Extension Pack now contains StructureDefinition-dosage-conditions.xml and StructureDefinition-dosage-minimumGapBetweenDose.xml; those files preserve string support for meetGoal.goal and whenTrigger.trigger, but precondition.condition is still only Reference(ActivityDefinition|ObservationDefinition). FHIR-40033 later decided not to make the extension more prominent in core, and a 2026 Zulip thread treats the R6 DosageCondition datatype and the Extension Pack dosage-conditions extension as related but distinct artifacts.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The only remaining apparent FHIR-26899 gap is in Extension Pack source, which is outside this FHIR core checkout and outside this local publish branch's edit scope.

Recommendation:
Keep this audit commit as an external-repo decision for core. A follow-up Extension Pack change should consider adding string as an allowed type for precondition.condition in dosage-conditions and the copied minimumGapBetweenDose structure, or ask Pharmacy/FHIR-I to confirm that the R6 DosageCondition datatype supersedes the extension behavior.
