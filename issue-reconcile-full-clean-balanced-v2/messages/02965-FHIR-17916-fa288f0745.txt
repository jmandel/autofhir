FHIR-17916: Audit ProcessRequest release action handling

Issue request:
FHIR-17916 was a Published/Persuasive with Modification FM change request raised against STU3 ProcessRequest asking to add `release` to the ProcessRequest.action code set so release of reserved funds or services would not be modeled as `cancel`. Its accepted resolution redirected the change to the code set and value set used for Task.code because ProcessRequest had been deprecated in favor of Task.

Initial application:
No git commit with the FHIR-17916 key was found. The apparent application is the November 2018 Paul Knapp `GF #19345` work: bbc5d920 added Financial Management Task examples including `task-example-fm-release.xml`, and 0a36b9 added the financial task CodeSystem/ValueSet including `release`. That matches the Jira resolution's direction to apply the change to Task rather than to ProcessRequest.

Additional context:
Current `source/fhir.ini` comments ProcessRequest out of active resource and work-group build mappings while leaving Task active. The current Financial Module maps Release to Task with `code=release`, the active Task release example uses `http://terminology.hl7.org/CodeSystem/financialtaskcode` with `code="release"`, and the local financial task value set includes that terminology system. The original core financial task CodeSystem was later removed by 5c0494 as part of removing UTG content from the core build, and current HL7 Terminology still publishes the `release` concept with the expected reserved-funds definition. The nearly identical FHIR-18009 issue is already represented on the combined branch by 198dd36a and should not be duplicated here.

AutoFHIR reconciliation:
This audit commit makes no source change. Editing `source/processrequest/codesystem-actionlist.xml` would target an out-of-build deprecated resource and would conflict with the accepted Task-based resolution. Adding `release` to the normative generic `TaskCode` code system would be broader than the FM-specific accepted change and is unnecessary because the active Task financial example, Financial Module guidance, financial task value set, and external THO CodeSystem already carry the intended code.

Recommendation:
Keep this no-change audit as-is. If Financial Management wants additional stewardship changes for financial task codes, that follow-up belongs in HL7 Terminology/THO rather than as a core ProcessRequest edit.
