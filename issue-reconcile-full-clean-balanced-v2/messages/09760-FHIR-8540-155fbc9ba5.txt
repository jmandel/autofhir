FHIR-8540: Audit primitive profile type-code correction

Issue request:
FHIR-8540 was a Published/Persuasive FHIR-core StructureDefinition correction from DSTU1. It reported that primitive datatype profiles such as instant.value carried ElementDefinition.type.code values like xs:dateTime, which violated the datatype binding; the resolution agreed that schema types were invalid and irrelevant in those profile type codes.

Initial application:
The issue was applied in svn revision 6172, represented in git as a98d42388273e9fb79a6a9d93ab717b185741b4e (#8540 - remove schema types from profiles). That commit removed generator assignments that populated primitive value ElementDefinition.type.code from XML Schema type names and allowed XML-attribute primitive value elements to avoid those schema type codes.

Additional context:
Current source still documents XML representation details such as xs:boolean or xs:base64Binary on the primitive datatype narrative page, but those are serialization-domain descriptions, not ElementDefinition.type.code values. The checked release profile bundles no longer contain <code value="xs:*"> values, and the current R4B/R5 primitive value profiles use FHIRPath system type codes plus structuredefinition-fhir-type extensions for the FHIR primitive name.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The invalid schema-code profile representation requested by FHIR-8540 has already been removed, and the remaining XML Schema references are either representation documentation or XPath/regex-related text that do not recreate the binding violation.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed unless a future generated primitive profile again emits XML Schema names as ElementDefinition.type.code values.
