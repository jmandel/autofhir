FHIR-11166: Audit ClinicalImpression finding basis rename

Issue request:
FHIR-11166 was a Published Patient Care change request for DSTU2 ClinicalImpression. It objected that ClinicalImpression.finding.cause was semantically inaccurate for an element whose short description was "Which investigations support finding"; although the submitter proposed supportingInformation, the final Not Persuasive with Modification resolution renamed ClinicalImpression.finding.cause to ClinicalImpression.finding.basis.

Initial application:
The rename was historically applied in git commit bd9f60dbffee762fd2b3e49ee2e07e232b9685a9, whose ClinicalImpression spreadsheet patch changed the row from ClinicalImpression.finding.cause to ClinicalImpression.finding.basis. Current checked-in ClinicalImpression source has ClinicalImpression.finding.basis with the original support-investigations definition, and the later ClinicalAssessment source inherited the same finding.basis element.

Additional context:
FHIR-35797 later confirmed that DSTU2 ClinicalImpression.finding.cause was renamed to STU3 ClinicalImpression.finding.basis by FHIR-11166, but resolved no-change because the old R2-to-R3 map problem would be a STU3 technical correction and was not applicable to R4 or R5. FHIR-46596 later renamed ClinicalImpression to ClinicalAssessment for R6; that related rename has already been reconciled on the combined branch. Commit fad1b9cf84ef652e88947e1a13b026c62f95334e then removed ClinicalAssessment from source/fhir.ini's active core resource configuration and changed the active resource guide link to the PC incubator ClinicalAssessment artifact.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The seed rename is already present in the remaining core ClinicalImpression and ClinicalAssessment source files, and neither resource is active in the current core build. Editing the inactive resource directories would not change the built specification; any future change to the live ClinicalAssessment artifact belongs with the PC incubator artifact or with a deliberate core reintroduction.

Recommendation:
Keep this audit commit as-is for the current core build. If Patient Care reintroduces ClinicalAssessment into core or updates the PC incubator artifact, verify that the finding support element remains basis rather than cause and review the old R2-to-R3 mapping note from FHIR-35797 only if historical inter-version maps are in scope.
