FHIR-15125: Audit ImagingStudy workflow alignment

Issue request:
FHIR-15125 was a Published/Persuasive with Modification STU3 ImagingStudy workflow cleanup. It requested renaming ImagingStudy.reason to reasonCode with 0..* cardinality, adding reasonReference 0..*, correcting the performer workflow mapping to Event.performer.actor, and adding ImagingStudy.status plus statusReason with an ImagingStudy status code system.

Initial application:
The 2018 application commit 7b2b64512052c9a800a59b0ac3cd2cd013659b1b explicitly lists GF#15125 and added the ImagingStudy workflow changes alongside related ImagingStudy trackers. That commit introduced ImagingStudy.status with a required ImagingStudyStatus binding, reasonCode/reasonReference, and a new performer backbone, but it also represented statusReason as a disabled spreadsheet row and retained some performer mapping details that were later corrected in generated StructureDefinition source.

Additional context:
Current ImagingStudy is an active resource in source/fhir.ini. Later R5/R6 modeling merged reasonCode and reasonReference into ImagingStudy.reason as CodeableReference, with fhir.ini compatibility mappings from the old names to reason.concept and reason.reference. The current StructureDefinition has a required ImagingStudy.status bound to the ImagingStudy status ValueSet, maps ImagingStudy.reason to Event.reason, and maps ImagingStudy.series.performer.actor to Event.performer.actor. The current Event mapping exception file records Event.statusReason as not relevant for ImagingStudy, so adding statusReason now would be a new normative model change rather than a safe reconciliation of the STU3 workflow cleanup.

AutoFHIR reconciliation:
This audit commit makes no source change. The current build-scoped source preserves the implementer-facing semantics that FHIR-15125 established where they remain current, and it intentionally documents the remaining Event.statusReason divergence instead of leaving an unexamined workflow-warning gap.

Recommendation:
Keep this no-change audit. If the Imaging Integration work group wants ImagingStudy to grow a statusReason element in R6+, that should be raised as a new substantive tracker because it would change the current normative resource model and contradict the existing mapping exception.
