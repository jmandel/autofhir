FHIR-25553: Audit Request note guidance

Issue request:
FHIR-25553 was a Published, Persuasive with Modification FHIR-I issue raised against R4 to clarify what type of information belongs in Request.note and how it differs from Request.supportingInfo. The final resolution requested a usage-notes section covering when notes and supportingInfo are typically added, clinical and administrative note examples, supportingInfo as information needed by the filler to perform the order, and the rule that notes should not duplicate supportingInfo.

Initial application:
Jira records Git 193d552d63 as the application commit. That commit added the Request-pattern Notes and Related Information section in source/request/request-spreadsheet-notes.xml and added element comments in source/request/request-spreadsheet.xml linking both Request.supportingInfo and Request.note to request.html#notes. The current source still contains those additions.

Additional context:
source/fhir.ini lists request as an active logical pattern, and current resource mapping exceptions still inherit the Request-pattern note/supportingInfo guidance. The related FHIR-25552 ServiceRequest-specific CodeableReference request is already represented on the combined branch, while related FHIR-25554 closed the broader Request.supportingInfo CodeableReference proposal as no-change. OO minutes from January 2020 confirm the issue family arose from deciding whether ServiceRequest.supportingInfo or note should carry coded/free-text order context. Quoted Zulip and Confluence full-text searches found no conflicting community record.

AutoFHIR reconciliation:
