FHIR-36831: Audit Permission policy use case relocation

Issue request:
FHIR-36831 was an Applied/Persuasive Security change request asking how to encode admin-level or global consent policies that apply to all patients, groups, everyone, or non-patient resources. The accepted resolution was that the Permission resource had been updated with an overriding policy use case.

Initial application:
No commit explicitly mentioning FHIR-36831 was found in core history. The relevant Permission content was applied through the evolving Permission resource and examples: the historical core Permission introduction described organization-wide access control policies, base policies that Consent builds upon, and non-patient examples; commit 22d8289602 added directory-admin, directory-exclude, and residual Permission examples from the Data Access Policies IG.

Additional context:
Permission is no longer an active core resource. Commit 0e2a8a7f83 removed source/permission and the active fhir.ini Permission entries, and rewired core Security/Privacy and history links to the HL7 Data Access Policies IG. Current core source now lists Permission only as an external DAP link, while the current hl7.fhir.uv.dap package contains StructureDefinition/Permission and explicit overriding-policy examples such as ex-overriding-abac-by-tag, ex-overriding-rbac-by-resource, and ex-overriding-rbac-by-role. Later Jira FHIR-54870 also notes that Permission was moved to an incubator IG, but that issue is still Submitted and was not decided here.

AutoFHIR reconciliation:
This commit intentionally makes no source change in core. The seed's requested content concerns the Permission resource and its overriding-policy use cases; that artifact is outside the active core build and is maintained in the external Data Access Policies IG. The current core checkout already points readers to that external Permission definition rather than hosting a core Permission resource.

Recommendation:
Keep this audit commit as an external-repo decision for FHIR-36831. If further clarification of overriding-policy examples is needed, do that work in HL7/data-access-policies or through the unresolved FHIR-54870/incubator-IG follow-up path rather than resurrecting or editing source/permission in core.
