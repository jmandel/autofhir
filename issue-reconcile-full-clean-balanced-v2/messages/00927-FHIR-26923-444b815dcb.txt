FHIR-26923: Audit AuditEvent TraceID example

Issue request:
FHIR-26923 was a Published Security WG change request with a Persuasive with Modification resolution to show, by example, how an internal trace ID such as Jaeger/b3 can be recorded on AuditEvent using an additional entity and an example.com identifier system.

Initial application:
No Jira-tagged commit was found. Git history shows aa9defa3c8 added the "RESTful create with TraceID" example list entry on 2021-04-07, and dd7da5fcf7 added source/auditevent/audit-event-example-create-traceID.xml the same day. Later AuditEvent model-alignment commits updated the example while preserving the trace-ID entity.

Additional context:
AuditEvent is active in source/fhir.ini, and the AuditEvent examples list references AuditEvent/example-rest-create-traceID. The Zulip thread linked from Jira records the work-group discussion: trace IDs should be represented as AuditEvent.entity.what.identifier with object-role Job Stream, not as an AuditEvent identifier; John Moehrke later pointed users to the current build example. Confluence search found agenda/minutes references to the issue and no contrary final decision.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current source already contains a build-scoped TraceID example with a second entity, Identifier.type "TraceID", example.com system, the original trace value, and object-role code 21 "Job Stream".

Recommendation:
Keep this no-change audit. No core spec edit is needed unless the Security WG later decides to standardize a canonical identifier system or code for specific propagation headers such as b3 or X-Request-Id.
