FHIR-6240: Audit accession identifier modeling

Issue request:
FHIR-6240 was a Published DSTU1 Imaging Integration change request asking whether multiple identifiers distinguished by identifier.type should be rolled up or kept separate for ImagingStudy and Specimen. The accepted Not Persuasive with Modification resolution said ImagingStudy AccessionNumber and StudyID have different semantics and should not be merged, while expanding the accession-number description and noting possible future encounter/order context.

Initial application:
The Jira comment identifies SVN revision 5635, represented in git as 35ce7f52a53f25d5837d69e02d4f31b96045e4b4, which updated source/imagingstudy/imagingstudy-spreadsheet.xml with a broader Accession Number short and long description. No FHIR-6240-tagged Specimen source hunk was found; later source refactors moved the relevant build inputs from spreadsheets into the current StructureDefinition XML, narrative notes, examples, search parameter bundles, and fhir.ini migration metadata.

Additional context:
ImagingStudy and Specimen are active current-build resources in source/fhir.ini. The ImagingStudy accession location was revisited repeatedly after DSTU1: FHIR-22118 moved accession away from ImagingStudy.identifier into basedOn.identifier; FHIR-48644 temporarily argued for ImagingStudy.identifier; FHIR-49675 reversed that and moved accession back to basedOn.identifier; and FHIR-56033 removed remaining accession examples from ImagingStudy.identifier comments. Specimen was revisited separately by OO: FHIR-44755 treated Specimen.accessionIdentifier as a typed Identifier, and FHIR-53092 removed the standalone accessionIdentifier element in favor of Specimen.identifier with Identifier.type=ACSN.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current ImagingStudy source keeps DICOM Study Instance UID/Study ID semantics on ImagingStudy.identifier and places accession guidance/searching on ImagingStudy.basedOn.identifier. Current Specimen source rolls accession identifiers into Specimen.identifier with explicit ACSN Identifier.type guidance and examples. That current state is more specific than the DSTU1 request and reflects the later final Jira decisions; restoring the old accession-number prose or moving accession into ImagingStudy.identifier would conflict with later Applied issues.

Recommendation:
Keep this audit commit as-is. The seed issue is already satisfied in the current build when the later ImagingStudy and Specimen issue family is considered; future changes should be tracked against the newer artifact-specific issues rather than reopening FHIR-6240.
