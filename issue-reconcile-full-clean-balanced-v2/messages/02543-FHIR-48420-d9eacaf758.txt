FHIR-48420: Audit vital signs reference relaxation

Issue request:
FHIR-48420 was Applied as Persuasive with Modification for R6. It asked to relax the Vital Signs Base Profile constraint that limited Observation.derivedFrom to vital-signs Observations, because a vital sign can be derived from a non-vital-sign Observation such as a PPG waveform; it also noted the similar Observation.hasMember constraint. The recorded resolution was to remove the Observation.derivedFrom constraint and remove MolecularSequence and QuestionnaireResponse as reference choices in Observation.hasMember.

Initial application:
The source change appears to have been applied incidentally during the FHIR-47136 vital signs profile cleanup rather than in a commit explicitly mentioning FHIR-48420. Git commit 983b8c8cd0db5db4a950f98f683904d1100329de replaced Observation.hasMember's previous target profiles of QuestionnaireResponse, MolecularSequence, and vitalsigns with Observation, and replaced Observation.derivedFrom's previous target profiles of DocumentReference, ImagingStudy, QuestionnaireResponse, MolecularSequence, and vitalsigns with DocumentReference plus Observation.

Additional context:
The vital signs IG is active in source/igs.xml and its ImplementationGuide includes StructureDefinition/vitalsigns, so source/observation/structuredefinition-profile-vitalsigns.xml is in the current build scope. The Jira comment on FHIR-48420 confirms Robert Hausam considered the issue addressed by the FHIR-47136 commit family, with hasMember and derivedFrom relaxed to all Observation instances and inapplicable target resource types removed. OO Confluence minutes record the FHIR-48420 persuasive motion and change-applied marking; exact Zulip key search found no directly relevant discussion that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This audit commit makes no source change. The current Vital Signs Base Profile already constrains Observation.hasMember to Reference(Observation) and Observation.derivedFrom to Reference(DocumentReference or Observation), which removes the vital-signs-only restriction and removes the inapplicable MolecularSequence and QuestionnaireResponse hasMember choices requested by the issue.

Recommendation:
Keep this no-change audit commit. No FHIR core source follow-up is needed for FHIR-48420 unless OO later decides that derivedFrom should also restore another non-Observation target profile; that would be a separate substantive decision, not an unapplied part of this issue.
