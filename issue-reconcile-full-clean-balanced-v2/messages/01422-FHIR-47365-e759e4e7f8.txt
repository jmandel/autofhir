FHIR-47365: Correct binary subscription topic example

Issue request:
FHIR-47365 was Applied as Persuasive with Modification for R6. It asked that SubscriptionTopic/Parameters guidance more clearly explain how subscription notifications can support non-FHIR data, noting that Basic has mandatory fields and Parameters values are still FHIR data types. The approved resolution said Parameters was intended to show arbitrary structure encoding and requested additional documentation plus example instances showing non-FHIR inclusions.

Initial application:
The issue was initially applied by git commit 65feb8c0e7b222b128842eb078b1b70ae88df087, merged through HL7/fhir#3967 at 2ec3e732369b18cd589904205b73b4237f850e82. That commit added a Non-FHIR Data section to SubscriptionTopic narrative and registered Basic, Binary, Logical Model, and Parameters SubscriptionTopic/SubscriptionStatus examples in active SubscriptionTopic and SubscriptionStatus source folders.

Additional context:
FHIR-I approved the subscription block vote containing FHIR-47365 on 2025-03-31 at 17-0-0, and the related Zulip hit was the block-vote announcement rather than conflicting technical discussion. The current source already contains the requested non-FHIR guidance, including Parameters and Binary descriptions, but the new Binary SubscriptionTopic example still named Basic as the trigger resource and as one canFilterBy resource even though the example title, filterDefinition URLs, notificationShape, and notification Bundle are all Binary-focused.

AutoFHIR reconciliation:
This commit corrects source/subscriptiontopic/subscriptiontopic-example-admission-binary.xml so the Binary example's trigger.resource points to http://hl7.org/fhir/StructureDefinition/Binary and its patient-group canFilterBy.resource is Binary. The file is in current build scope because source/fhir.ini lists SubscriptionTopic and Binary as active resources, and source/subscriptiontopic/list-SubscriptionTopic-examples.xml registers the admission-binary example.

Recommendation:
Keep this source fix. It preserves the applied FHIR-47365 documentation and examples while removing an internally inconsistent Binary example that could otherwise mislead implementers about the intended non-FHIR notification representation.
