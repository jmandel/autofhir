FHIR-7622: Audit Annotation note guidance

Issue request:
FHIR-7622 was Published with a Persuasive with Modification disposition for DSTU1. It requested structured note support by defining a common Annotation datatype, making elements named note 0..* Annotation, disallowing plural notes/comments names, and keeping comment elements as 0..1 string with MnM confirmation warnings for exceptions.

Initial application:
The issue was applied in git-svn commit e86f20cfb9b7f9336b4463ff3ee5f44691a937bf, titled "#7622 - add data type Annotation", matching Jira's svn revision 5620 application note. That commit added source/datatypes/annotation.xml and registered Annotation in source/fhir.ini. Current source/fhir.ini still actively lists Annotation as a datatype, marks it normative, and assigns its abbreviation/search-type metadata.

Additional context:
The current Annotation spreadsheet preserves the requested structure and usage note: author[x] 0..1, time 0..1, text 1..1, and guidance that systems without structured annotations can send a single annotation without author or time and that annotations SHOULD NOT carry computable modifying information. A targeted scan of base StructureDefinitions found no plural notes/comments elements, found 60 base note elements as 0..* Annotation, and found comment elements as 0..1 string or later-approved 0..1 markdown. The only base note exception, DetectedIssue.mitigation.note as 0..1 markdown, is already represented by the later FHIR-39405 source-fix commit on the combined branch; AppointmentResponse.comment markdown is likewise already represented by FHIR-39557. FHIR-9384 later considered renaming note to annotation and was resolved No Change, confirming that retaining note element names is intentional.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build source already carries the FHIR-7622 datatype and naming/cardinality convention, while the discovered exceptions are explained by later final Jira decisions rather than by a missing seed application.

Recommendation:
Keep this audit commit as-is. Do not make broad source edits for FHIR-7622; future changes to individual note/comment elements should be handled under their own work-group trackers when they intentionally deviate from the old general convention.
