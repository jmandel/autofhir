FHIR-49109: Correct Task output parameter binding text

Issue request:
FHIR-49109 is Applied/Persuasive with Modification. It asked why Task binding names such as TaskInputParameterType/TaskOutputParameterType implied example value sets when no value sets existed, and the accepted resolution was to add example binding descriptions/codes for Task performer function code, Task reason, input/output parameter code, and business status.

Initial application:
The main application was commit 768642cfce, which added Task example value sets/code systems and wired valueSet references into source/task/structuredefinition-Task.xml for Task.businessStatus, Task.performer.function, Task.reason, Task.input.type, and Task.output.type. Commit 41df358d87 then changed the input and output parameter bindings to share the task-inputoutput-parameter-type value set/code system. Those commits left Task.output.type with a binding description that still said "input parameters."

Additional context:
FHIR-45320 is the same change family for TaskBusinessStatus and explicitly resolves to make the fix described in FHIR-49109. FHIR-I minutes for 2025-01-06 left the choice of binding descriptions vs. example value sets in OO's hands, and OO WGM minutes for 2025-01-27/31 list FHIR-49109 for COW discussion. FHIR-50258 later added data-retrieval codes to the shared input/output parameter code system and is already represented on the combined branch. FHIR-56060 is a later display-name cleanup touching Task and Device and was not decided here.

AutoFHIR reconciliation:
This commit changes only the authoritative Task StructureDefinition source so Task.output.type now describes codes for output parameters while retaining the shared task-inputoutput-parameter-type example value set. Task is an active resource in source/fhir.ini, so source/task/structuredefinition-Task.xml and the referenced task terminology files are in current build scope; the generated-looking task.svg was intentionally left for the normal build regeneration path.

Recommendation:
Keep this source fix. The requested Task example value sets/code systems already exist, and this correction removes the remaining directly related misleading output-binding description without expanding into later Task terminology issues.
