FHIR-8056: Audit Bundle reference typo

Issue request:
FHIR-8056 was a Published/Persuasive DSTU1 technical correction for the FHIR-core references page. It reported that the bundle reference example showed an item element where the Bundle syntax should use entry, and also noted the lack of an entry.link[self] example.

Initial application:
The issue appears to have been applied by git commit 426aef96a7b141fed925adb15c6f4849b58044d2, whose subject was "#8056 - typo in bundle" and whose git-svn metadata records build revision 5329. That commit changed the references-page bundle example from item elements to entry elements wrapping resource elements. No existing Issue-Reconcile-Key: FHIR-8056 commit was found on the combined branch before this audit.

Additional context:
Before FHIR-8056 was applied, commit 5544902951a4fe943445361593076ae8a3361dc5 had already removed the old entry.link[self] wording from the bundle reference-resolution text. Shortly after the FHIR-8056 fix, commit 93db83230f06ea04d51ee0b09a610f39047d1f4f moved the bundle reference-resolution example out of source/references.html and into the active Bundle resource material. In the current source, Bundle is an active resource in source/fhir.ini; the bundle reference-resolution page links to an example Bundle whose entries use Bundle.entry.fullUrl and Bundle.entry.resource; source/search.html shows the search self link as Bundle.link with relation self; and Bundle notes state that Bundle.entry.link has no specific use defined by this specification.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source no longer contains the obsolete item-based example from the Jira request, and adding an entry.link[self] example would conflict with the later/current model where search self links use Bundle.link and Bundle.entry.link remains implementation-specific.

Recommendation:
Keep this no-change audit commit as-is. No follow-up source work is needed for FHIR-8056 in the current FHIR core checkout.
