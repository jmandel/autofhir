FHIR-13358: Audit Consent policyRule reconciliation

Issue request:
FHIR-13358 was Published/Persuasive with Modification for FHIR-core Consent. It asked to stop representing Consent policy/policyRule opt-in and opt-out choices as URI magic values, and the final resolution changed policyRule to a CodeableConcept based on ActConsentDecision, retired the magic URIs, corrected examples/text, and recorded that this satisfied duplicate FHIR-13598.

Initial application:
The issue was explicitly applied in git commit e0f2ea28e4dbe6b1fc2ff9d32ef6f84347cc8ef5, which changed the STU3 Consent examples from http://hl7.org/fhir/ConsentPolicy/opt-in and /opt-out URI values to CodeableConcept policyRule codings and updated the Consent source definitions. No separate source application is needed for duplicate FHIR-13598.

Additional context:
Consent remains an active current-build resource in source/fhir.ini. Later Published issue FHIR-32817 replaced the old policy/policyRule structure with regulatoryBasis, policyBasis, policyText, and an explicit permit/deny decision model; that later design intentionally keeps URI only for Consent.policyBasis.uri, a dereferenceable computable backing-policy URI, not for the retired opt-in/opt-out magic values. Current R4/R6 mapping records the retired Consent.policyRule as moved to current policy text, and current examples express opt-in/out behavior through Consent.decision and provisions. Zulip and Confluence searches found no conflicting community record.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current authoritative Consent source has no active Consent.policyRule element and no remaining http://hl7.org/fhir/ConsentPolicy/opt-in or /opt-out magic URI usage. The current regulatoryBasis CodeableConcept, policyBasis/policyText, and decision/provision model preserves the issue's intent after later Consent refactoring.

Recommendation:
Keep this no-change audit. If the work group wants to rename the historical consent-policy value set title/name that still contains "PolicyRule", handle that as a separate editorial/terminology cleanup because it is not a remaining URI-vs-CodeableConcept defect and does not change the current Consent conformance model.
