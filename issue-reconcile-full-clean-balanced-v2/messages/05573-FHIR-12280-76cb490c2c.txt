FHIR-12280: Audit ExpansionProfile code system rules

Issue request:
FHIR-12280 was Published/Persuasive with Modification for the DSTU2 ExpansionProfile resource. It asked to replace the confusing nested include/exclude code-system structure with fixedVersion entries carrying system, version, and a default/check/override mode, plus excludedSystem entries, and to make overridden expansion versions explicit in the expansion output.

Initial application:
The request was pre-applied as svn revision 10048, represented in git by 7e7c737adbf264a93b611e96e738654a2b54dbe3. That commit changed ExpansionProfile source to fixedVersion/excludedSystem, added the default/check/override value set, warned about override safety, and tied ExpansionProfile settings to expansion parameters.

Additional context:
ExpansionProfile is no longer an active current-build resource: source/fhir.ini lists ValueSet as approved and comments ExpansionProfile as dropped. Later Published Vocab decisions FHIR-16337 and FHIR-16490 removed ExpansionProfile and moved the relevant behavior into direct ValueSet operation parameters. Current ValueSet $expand source contains exclude-system, system-version, check-system-version, and force-system-version, including the override safety warning and the SHALL that overridden versions be represented in expansion parameters.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current specification no longer needs the old ExpansionProfile structure, and the active ValueSet operation definition already carries the code-system inclusion/exclusion, default/check/force version, and explicit-parameter semantics that remain applicable after the later resource removal.

Recommendation:
Keep this no-change audit commit as-is. Do not restore or edit ExpansionProfile in core; future work should be raised only if Vocab wants to change the current ValueSet operation parameter semantics themselves.
