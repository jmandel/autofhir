FHIR-5925: Audit medication dosage SIG wording

Issue request:
FHIR-5925 was a Published/Persuasive DSTU1 Pharmacy change request for MedicationDispense, MedicationPrescription, and MedicationStatement asking to add "free text SIG" to the description of .dosage.text, because dosage.text seemed to be the logical location for the SIG but the description should say so explicitly.

Initial application:
The request was applied in the legacy source by commit 1cb9689e725c06210bbeaa920648410591a426d4, whose message names gForge change request 5925 and which changed MedicationAdministration and MedicationStatement dosage.text short labels to explicitly mention free-text SIG wording while also updating nearby medication dosage guidance. MedicationDispense, MedicationRequest, and MedicationStatement have since been refactored away from resource-local dosage.text children into the shared active dosage datatype model.

Additional context:
The current build has active fhir.ini entries for Dosage, DosageDetails, MedicationDispense, MedicationRequest, and MedicationStatement. MedicationPrescription is now MedicationRequest. Current MedicationStatement.dosage is typed as DosageDetails, and MedicationRequest and MedicationDispense use the same dosage instruction model. Later related issue FHIR-39319, already represented on the combined branch, strengthened the active Dosage.text row so its short and definition now say "A free text representation of the dosage. This is commonly called the SIG." FHIR-54014, also already represented, added the current required DosageDetails.renderedInstruction full-dosage-intent model. Exact FHIR-5925 Zulip and Confluence searches found no conflicting community record; a broader CDA-to-FHIR thread supports mapping medication free-text SIG content to Dosage.text.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The active shared Dosage.text source already contains the requested SIG wording, and the current medication resources reach that datatype through the active DosageDetails/Dosage model. Adding medication-resource-specific duplicate prose would not change implementer understanding and could drift from the authoritative datatype wording.

Recommendation:
Keep this no-change audit. If Pharmacy later revisits free-text medication instructions, update the shared Dosage/DosageDetails datatype guidance rather than reintroducing resource-local dosage.text wording for retired DSTU1 structures.
