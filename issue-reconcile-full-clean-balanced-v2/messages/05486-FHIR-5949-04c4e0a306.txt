FHIR-5949: Audit Dosage text and timing guidance

Issue request:
FHIR-5949 was a Published/Persuasive Pharmacy change request raised against DSTU1 MedicationPrescription. It asked how dosage.text relates to dosage.Scheduled[x]/dosage.timing and whether information may appear in both places. The accepted resolution required clarifying DosageInstruction.text and DosageInstruction.timing so text is expected for human display and, when timing is also present, the text reflects the same timing content.

Initial application:
The historical source contains explicit application commit 043ff8db6bacc9b4d846d3b0b5d1fd9f62730003 (#5949), which updated the MedicationOrder/DosageInstruction spreadsheet text to say that DosageInstruction.text may coexist with coded timing and should reflect timing when both are populated. Later source history renamed DosageInstruction to Dosage and MedicationPrescription/MedicationOrder to MedicationRequest, carrying the rule into the current datatype model.

Additional context:
The current build uses the normative Dosage datatype source, and fhir.ini maps the old DosageInstruction name to Dosage. A later Published/Persuasive Pharmacy issue, FHIR-39319, clarified that Dosage.text is intended as a complete free-text dosage/SIG representation rather than merely additional text; that decision has already been reconciled on the combined branch by commit bc5a413c8883a027335f4fba439c69659e7f3dc6. Community searches for FHIR-5949 found no Zulip or Confluence record that changes the Jira/source conclusion.

AutoFHIR reconciliation:
Made no source change. The active source/datatypes/dosage.xml already states that Dosage.text is a complete representation, SHOULD be populated, and SHOULD represent structured SIG data including timing when structured data exists. The Dosage.timing row still explicitly states that if both timing and text are populated, Dosage.text should reflect the content of Dosage.timing.

Recommendation:
Keep this empty audit commit. The current source preserves the FHIR-5949 clarification and the later FHIR-39319 refinement, so another wording edit would be redundant and could reintroduce obsolete DSTU1 phrasing.
