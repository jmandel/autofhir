FHIR-27140: Audit mapping cast type namespace

Issue request:
FHIR-27140 is Published/Persuasive with Modification. The request asked that the Mapping Language cast transform's optional type parameter include target model information, with an example changing cast(a, "integer") to cast(a, "FHIR.integer"). The accepted resolution instead said to indicate that the default namespace is FHIR.

Initial application:
The explicit FHIR-27140 implementation commit 785ebcfdb1 changed source/structuremap/codesystem-map-transform.xml so the cast transform definition states that the default namespace for the type is 'FHIR' and links to FHIRPath type specifiers. A later transform-alignment commit, 662229e429, carried the same default-FHIR sentence into the active source/mapping-language.html transform table and retained it in the map-transform CodeSystem definition.

Additional context:
FHIR-I minutes from 2020-08-24 record the work group decision for FHIR-27140 as adding a sentence about defaulting to FHIR if unspecified. The current hierarchy includes mapping-language.html and its tutorial in the Implementation Support module. The tutorial still uses cast(a, "integer"), but that shorthand is now correct because the active mapping-language and CodeSystem definitions specify FHIR as the default namespace. No Zulip, Confluence, or Jira search found a later conflicting decision for this issue.

AutoFHIR reconciliation:
This audit commit makes no source change. The current build-scope source already conveys the approved rule: omitted model namespace defaults to FHIR for the cast type parameter.

Recommendation:
Keep this no-change audit. Revisit only if FHIR-I makes a new decision to require explicit model-qualified type names in examples rather than allowing the documented default-FHIR shorthand.
