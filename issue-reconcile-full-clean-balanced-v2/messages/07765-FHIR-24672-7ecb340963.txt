FHIR-24672: Correct itemWeight example wording

Issue request:
FHIR-24672 was Published/Persuasive with Modification for R5. It asked to rename the generic ordinalValue extension, with the final approved name being itemWeight rather than score, while keeping it as an extension rather than converting it to a CodeSystem concept property.

Initial application:
The issue was initially applied in git commit 02d5f0bffc, which renamed the core general extension source row from ordinalValue/OrdinalValue/Ordinal Value to itemWeight/ItemWeight/Item Weight. Later source refactoring removed most extension definitions from core into the FHIR Extension Pack.

Additional context:
FHIR-I minutes from 2020-04-27 record the approved motion to keep the artifact as an extension, recognize that it is not necessarily ordinal and may be decimal, and rename it to ItemWeight. The current core source already uses itemWeight in the CodeSystem concept property, Questionnaire guidance, FHIRPath weight() guidance, and the Glasgow example extension URLs. The Extension Pack currently contains the active itemWeight extension and a retired ordinalValue definition that points to itemWeight. A later SDC issue, FHIR-37508, separately handled FHIRPath ordinal()/weight() guidance and is not decided by this core-source commit.

AutoFHIR reconciliation:
Updated the active Observation Glasgow example comment from ordinalValue extensions to itemWeight extensions. The file is in build scope because Observation is an active resource in source/fhir.ini and the example is listed in source/observation/list-Observation-examples.xml.

Recommendation:
Keep this commit as-is. It removes the only exact old extension-name residue found in current core source while leaving generic uses of ordinal value/ordinal observations alone because those are not references to the retired extension name. Any future wording cleanup inside the Extension Pack should be handled in that repository, not by this core reconciliation.
