FHIR-29665: Audit workflow Encounter contexts

Issue request:
FHIR-29665 was Published/Persuasive with Modification for R5. It asked to allow the workflow instantiates relationship on Encounter, especially so an Encounter can point to an ActivityDefinition, and its final resolution applied that request through the FHIR-29261 replacement extensions rather than by expanding the retired workflow-instantiatesCanonical extension.

Initial application:
The issue was applied in git commit 2ee637a94c, which split the old workflow instantiates extensions into more specific workflow-generatedFrom, workflow-compliesWith, workflow-adheresTo, workflow-triggeredBy, and workflow-shallComplyWith extensions. That patch added Encounter to adheresTo and triggeredBy; the applying editor's Jira comment explicitly says it was not added to compliesWith because compliesWith is for Requests and adheresTo is the Event-side relationship.

Additional context:
FHIR-29261 is the controlling same-change-family decision: it made compliesWith request-only, adheresTo event-only, and triggeredBy request-or-event. PA minutes supported Encounter and suggested EpisodeOfCare, but the final FHIR-29665 resolution and application were scoped to Encounter. Current core fhir.ini still references the workflow extension profile metadata/notes, but commit dd468d4f17 removed the concrete extension rows from the core R5 source. The current Extension Pack source now carries the authoritative StructureDefinitions; there, workflow-adheresTo and workflow-triggeredBy include Encounter and workflow-compliesWith does not.

AutoFHIR reconciliation:
This is an empty audit commit. No core source change is needed because the current core checkout no longer owns the individual workflow StructureDefinitions and the Extension Pack source already reflects the approved Encounter contexts from the FHIR-29665/FHIR-29261 application.

Recommendation:
Keep this no-change audit as-is. Do not re-add Encounter to the retired workflow-instantiatesCanonical extension or to request-only workflow-compliesWith. If the PA EpisodeOfCare suggestion needs more than the existing workflow-episodeOfCare extension family, handle that as a separate work-group decision in the Extension Pack.
