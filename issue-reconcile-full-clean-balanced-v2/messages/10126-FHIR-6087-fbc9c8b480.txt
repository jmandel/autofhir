FHIR-6087: Audit multiple binding support

Issue request:
FHIR-6087 was a Published FHIR-I change request, resolved Persuasive with Modification, asking for a way to specify multiple ElementDefinition bindings with different strengths. The accepted resolution was to define a minimum binding as well as the existing maximum binding extension.

Initial application:
The explicit historical application is git f092fc9e6abb30821694905a88b5b94322440710, "#6087 - add minValueSet extension", matching the Jira comment's svn revision 6376. The companion maxValueSet extension already existed from git 4c67059737b5717deeb45b22208117dde839a652. Those extension definitions are no longer core source; the Extension Pack retains elementdefinition-minValueSet and elementdefinition-maxValueSet as retired/deprecated extensions that say to use additionalBinding instead.

Additional context:
Later same-artifact Jira decisions, especially FHIR-8723 and FHIR-9195, expanded the multiple-binding model beyond the original min/max extension approach. Current build-scope core source lists ElementDefinition as an active type and ElementDefinition.binding.additional is a 0..* core child with purpose, valueSet, documentation, usage, and any fields. Terminology prose now documents additional bindings, says the main binding always applies, allows multiple applicable required bindings for CodeableConcept/CodeableReference, and maps the old maximum and minimum extension semantics to additional binding purposes. The additional-binding purpose CodeSystem includes maximum, minimum, required, extensible, preferred, and other purposes.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already gives implementers a current, build-scope way to express multiple bindings with different strengths and preserves the original minimum/maximum semantics through additional binding purposes; editing core to reintroduce or duplicate the retired extensions would conflict with the later R5+ model.

Recommendation:
Keep this no-change audit commit as-is. Follow-up is only needed in the Extension Pack if the deprecated legacy extension definitions themselves need maintenance; no core FHIR source fix is indicated for FHIR-6087.
