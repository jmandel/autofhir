FHIR-7612: Audit billing resource support history

Issue request:
FHIR-7612 was a Published FHIR-core change request from the Financial Management work group asking the specification to make clear where billing data is available and how billed data differs from non-billed clinical data. The final Persuasive with Modification resolution says Patient Administration created two resources, ChargeItem and ChargeItemDefinition, and the issue was applied for R5.

Initial application:
There is no git commit explicitly mentioning FHIR-7612, but the requested resource family was applied through the historical ChargeItem and ChargeItemDefinition source additions. ChargeItem was added as a draft resource in git commit 813ca92a4d882bf3ff51928c5f7f5456674c0096 in 2017, and ChargeItemDefinition was added in git commit 3b94eeadabb3e6cecaef2f94874d228b7b0c397f for GF#16523. The FHIR-16523 Jira snapshot confirms ChargeItemDefinition was pre-applied in revision 13743 after PA/FM/FMG approval and was published for R5.

Additional context:
The current R6-oriented source no longer has ChargeItem or ChargeItemDefinition as active core resources in source/fhir.ini. Later source history intentionally removed those resource directories from core in git commit 71567db3ee039ac6977be5f96a7e013896569a36, and current ballot notes state that immature resources, including ChargeItem and ChargeItemDefinition, have been moved out of this specification into incubator IGs. The Financial module still covers billing and reimbursement with active core resources such as Account, Claim, ClaimResponse, Invoice, ExplanationOfBenefit, PaymentNotice, and PaymentReconciliation.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding ChargeItem or ChargeItemDefinition to core would reverse a later R6 scope decision rather than complete FHIR-7612, and the current source already records their move to the admin-incubator IG while retaining active financial resources for current core billing workflows.

Recommendation:
Keep this audit commit as-is. Do not restore ChargeItem or ChargeItemDefinition to FHIR core for FHIR-7612; any further maturation or cleanup of those resources should be handled in the admin-incubator/current resource-owner workstream or by a fresh R6 issue if core pages need additional editorial cleanup.
