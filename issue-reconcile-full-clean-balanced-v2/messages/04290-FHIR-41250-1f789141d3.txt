FHIR-41250: Audit DeviceDefinition specification-version search parameter

Issue request:
FHIR-41250 was Applied/Persuasive for R6 after reporting that DeviceDefinition-specification-version used a component definition of "version" even though no DeviceDefinition version search parameter existed. The requested change was to add a "version" search parameter.

Initial application:
The issue was initially applied in commit 6b5f81cc671e36964883ec7faf5e4be7159fbb47, which added a DeviceDefinition-version search parameter against DeviceDefinition.conformsTo.version. The Jira comment later pointed at merge commit 5e70ad56d965beb54173ec8f6d8889e5e7658015 as the build integration path.

Additional context:
DeviceDefinition is an active built resource in source/fhir.ini. FHIR-40503 later added the current DeviceDefinition-version search parameter for DeviceDefinition.deviceVersion.value, and FHIR-51646 later removed the standalone conformsTo.version search parameter because the specification-version composite is the intended way to search specification plus version. FHIR-53212 subsequently made the relevant DeviceDefinition search parameters normative/active for R6.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source contains DeviceDefinition-specification-version with component definition "version" and a current DeviceDefinition-version search parameter, while the later Applied FHIR-51646 decision means re-adding a separate conformsTo-version search parameter would reverse subsequent work group intent.

Recommendation:
Keep this audit commit as-is. If the work group wants an independently searchable DeviceDefinition.conformsTo.version parameter, that should be handled by a new or reopened Jira because the later applied decision deliberately left specification-version as the conformsTo version search surface.
