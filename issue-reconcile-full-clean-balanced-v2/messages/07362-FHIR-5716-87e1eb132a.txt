FHIR-5716: Audit BodySite patient association

Issue request:
FHIR-5716 was a Published/Persuasive with Modification OO change request for DSTU1 BodySite. It asked to know who or what the body site is part of, and the recorded resolution was to add BodySite.patient as 1..1 Reference(Patient).

Initial application:
The issue appears to have been applied before this reconciliation in commit 30f165af9ed7458068df3a2b54b7b6b474f9772d, titled "pre-apply #5716, 5731, 5852 for BodySite resource for OO 3/26/2015 Block Vote". That commit added a BodySite.patient row with cardinality 1..1 and type Reference(Patient) to the BodySite spreadsheet and added a patient reference to the BodySite example. BodySite was later renamed to BodyStructure by commit 386071a8e535114ff8df5ae7611b966cf354b3cb for tracker #13392/#13396.

Additional context:
The current build no longer has BodySite as an active resource; source/fhir.ini lists BodyStructure under [resources] and BodySite under [removed-resources]. The current authoritative BodyStructure StructureDefinition still has BodyStructure.patient targeting Patient and examples include patient references, so the original association is present in the successor resource. The cardinality is now 0..1, not 1..1, because the later Applied/Persuasive R6 issue FHIR-54450 explicitly relaxed BodyStructure.patient from 1..1 to 0..1 for use cases such as ObservationDefinition and representing a kind of anatomical structure rather than a patient-specific instance. The combined branch already contains a separate FHIR-54450 audit commit, 0dafb2e31cebc0500c8a977d32c165bfdfa7675b, so this reconciliation does not duplicate that issue.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. Reinstating min 1 for BodyStructure.patient would contradict the later applied FHIR-54450 decision, while removing or renaming the Patient association would contradict FHIR-5716. The current build-scope source is correct when both decisions are considered.

Recommendation:
Keep this audit commit as-is. Do not change BodyStructure.patient back to 1..1 for FHIR-5716; any remaining questions about optionality should be handled under the already audited FHIR-54450/R6 BodyStructure work rather than this DSTU1 issue.
