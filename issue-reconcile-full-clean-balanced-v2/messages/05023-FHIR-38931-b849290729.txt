FHIR-38931: Audit Task performer application

Issue request:
FHIR-38931 was Published with a Persuasive with Modification resolution for R5. The OO decision asked to separate the party managing Task execution from the party that actually performed it by adding Task.performer 0..* with function and actor children, adding a search parameter for the actual performer, updating Task.owner to "Party responsible for managing task execution", and removing Device and HealthcareService from Task.owner references.

Initial application:
The issue was applied in December 2022 through commits that did not consistently carry the Jira key: 6062daed42 added Task.performer and the owner definition/reference changes under the typo "FHIR-389931", 5a01c397c2 refined the Task.performer definition and requestedPerformer search code, and the Jira comment linked 42660f426a, which fixed the requestedPerformer reference search parameter. The current source keeps those changes: Task.performer/function/actor exists, Task.owner has the requested managing-execution definition, Device and HealthcareService are no longer Task.owner targets, and Task.performer.actor has a reference search parameter.

Additional context:
Task is active in the current FHIR build through source/fhir.ini. Later core issue FHIR-41394 intentionally added Group to Task.requester, Task.requestedPerformer, Task.owner, and Task.performer.actor for family/household use, which explains why the current owner and performer.actor reference lists are broader than the original FHIR-38931 resolution text. Later FHIR-cow issues FHIR-50747, FHIR-50813, FHIR-50816, and FHIR-50839 clarified Task.owner versus Task.performer in the COW IG rather than requiring a new core Task source change. OO minutes from 2022-12-16 confirm the original decision, and the community search found no conflicting Zulip evidence.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative Task StructureDefinition and search parameter source already convey the approved R5 split between requested performer, owner, and actual performer; the only current deviations from the original reference list are explained by later applied core work.

Recommendation:
Keep this audit commit as-is. If OO wants additional editorial clarification around Task.owner requirements or aliases, handle that as a new core issue or as part of the already active COW guidance stream rather than reopening FHIR-38931.
