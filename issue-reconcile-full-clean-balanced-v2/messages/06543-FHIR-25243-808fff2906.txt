FHIR-25243: Audit DiagnosticReport DocumentReference link request

Issue request:
FHIR-25243 was a Published OO change request asking FHIR core to clarify the overlap between DocumentReference and DiagnosticReport and to define a designated way for duplicated resources representing the same document to refer to each other. The final Not Persuasive with Modification resolution rejected a core requirement to create paired DocumentReference/DiagnosticReport instances and required only the DiagnosticReport introductory bullet to change from "Other diagnostics - Cardiology, Gastroenterology etc." to "Other diagnostics such as Cardiology, Gastroenterology etc."

Initial application:
No git commit explicitly names FHIR-25243, but the July 2020 OO block vote that included FHIR-25243 was followed by commit 0bf0b46a829ce94829ceef7e036dcb2043c74d18, "DocumentReference block vote from July," which changed source/diagnosticreport/diagnosticreport-introduction.xml to "Other diagnostics such as Cardiology, Gastroenterology, etc." The current source still contains that wording in an active DiagnosticReport resource directory.

Additional context:
The originating Zulip thread shows implementer confusion about PDF reports, DiagnosticReport.presentedForm, DocumentReference, and whether systems should create both resources. FHIR-19250 and FHIR-19249 later addressed the broader boundary/overlap question by adding reciprocal DiagnosticReport/DocumentReference boundary text, without creating a mandatory cross-link rule. Current DiagnosticReport.media.link targets DocumentReference, and current DocumentReference.related can refer to related resources, but the FHIR-25243 resolution intentionally did not require either resource to point at the other for every duplicated document.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already includes the exact DiagnosticReport wording change requested by the published FHIR-25243 resolution, and later current boundary prose explains the overlap in a way consistent with the no-mandatory-link decision. Adding another core linkage rule would contradict the Not Persuasive with Modification resolution and duplicate later boundary guidance.

Recommendation:
Keep this no-change audit commit as-is. If future work wants a mandatory or recommended reciprocal link between DocumentReference and DiagnosticReport, that should be raised as a new work-group decision because FHIR-25243 did not approve that requirement.
