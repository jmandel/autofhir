FHIR-32572: Audit Device URL-to-endpoint supersession

Issue request:
FHIR-32572 is a Published FHIR-core Device change request, resolved Persuasive with Modification for R5, asking to replace Device.url (0..1 uri) with Device.endpoint (0..* Reference(Endpoint)) because one device can expose multiple technical endpoints for different functions.

Initial application:
Jira records application to HL7/fhir PR #1489 commit 527030dccf2fe4612646ca5bff9208073feb0409. The implementation commit 09d68e1097e5dc81beadb0d43a68a576a584f119 added Device.endpoint as 0..* Reference(Endpoint), but left Device.url in place at that time. Later core commit 3f82b599e756ae1f47f2dc0059c10dac84369c8b, for FHIR-47048, commented out Device.url and its url search parameter.

Additional context:
FHIR-47048 later identified FHIR-32572 as the already approved basis for removing Device.url, and OO minutes from 2025-01-13 record that URL can be represented in Endpoint.address, that Device.endpoint was moving to an extension, and that FHIR-47048 would apply the change along with the extension move. FHIR-32565 approved moving Device.endpoint and related Device elements into extensions; FHIR-48923 and FHIR-47326 handled the communication extension work, and FHIR-47048 and FHIR-48923 are already represented on the combined reconciliation branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Device is active in source/fhir.ini, but the current authoritative core source has no active Device.url or Device.endpoint elements and no active Device.url search parameter; the remaining endpoint representation is the FHIR Extension Pack device-endpoint extension, outside this core checkout.

Recommendation:
Keep this no-change audit for FHIR-32572. Do not re-add Device.endpoint to core Device for this older R5 issue; current core source reflects later final R6 decisions, and any future wording about Endpoint.address belongs with the already-audited FHIR-47048/FHIR Extension Pack follow-up.
