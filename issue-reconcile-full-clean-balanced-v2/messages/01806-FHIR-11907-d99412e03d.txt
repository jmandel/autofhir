FHIR-11907: Audit document class code reconciliation

Issue request:
FHIR-11907 was Published/Persuasive with Modification for DSTU2 and asked to stop using the invalid CLD list of LOINC Part codes for Composition.class, bind Composition.class to the same document class value set used by DocumentReference.class, rename c80-doc-classcodes to document-classcodes, and remove the HITSP C80 reproduction text.

Initial application:
The Jira comment cites svn 14517, represented in git as 68a11fd7f788b9d67f05aca68d9ecd08236580ca. That commit changed Composition's spreadsheet binding from valueset-doc-categorycodes to http://hl7.org/fhir/ValueSet/document-classcodes, changed DocumentReference's spreadsheet reference from valueset-c80-doc-classcodes to valueset-document-classcodes, renamed the value set source file, and removed the HITSP C80 reproduction wording.

Additional context:
The old R3 element names are mapped forward in source/fhir.ini as Composition.class=Composition.category and DocumentReference.class=DocumentReference.category. Current source binds both Composition.category and DocumentReference.category to http://hl7.org/fhir/ValueSet/referenced-item-category. That later value set name is explained by FHIR-32577, a Published/Persuasive with Modification R5 issue that renamed document-classcodes because DocumentReference can reference non-document items. The remaining source/composition/valueset-doc-categorycodes.xml file still contains LOINC Part codes, but current source searches find no active references to doc-categorycodes or document-classcodes outside historical/generated-looking artifacts, while the authoritative current bindings point to referenced-item-category.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active Composition and DocumentReference category bindings are consistent with the applied FHIR-11907 decision as evolved by the later FHIR-32577 rename, and editing the unreferenced legacy valueset-doc-categorycodes.xml file would not improve the current build behavior.

Recommendation:
Keep this audit commit as-is for FHIR-11907. If a future worker reviews FHIR-32577 independently, it can assess any remaining wording details for the referenced-item-category rename; no FHIR-11907 source fix is needed in the current FHIR checkout.
