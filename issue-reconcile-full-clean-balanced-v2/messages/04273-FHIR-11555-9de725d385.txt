FHIR-11555: Audit RequestOrchestration timing choice alignment

Issue request:
FHIR-11555 was a Published/Persuasive CDS change request asking whether Timing should be a data type choice for the GuidanceResponse action timing element, as it was for PlanDefinition. The accepted resolution said GuidanceResponse, which became RequestGroup and later RequestOrchestration, should have the same capabilities as PlanDefinition for representing relationships between actions.

Initial application:
The change was applied in git-svn commit e6bd9dd0e0 / SVN r10173, whose message explicitly names #11554 and #11555 and aligns RequestGroup action elements with PlanDefinition. That patch changed RequestGroup.action.timing[x] from dateTime|Period|Duration|Range to dateTime|Period|Duration|Range|Timing while also aligning related action elements.

Additional context:
Current FHIR source no longer uses RequestGroup as the active resource name; fhir.ini has RequestOrchestration as the active resource and records RequestGroup as mapped to RequestOrchestration. The current GuidanceResponse.result can target RequestOrchestration, and RequestOrchestration.action.timing[x] includes Timing. Later source evolution added other timing choices, such as Age and RelativeTime, without removing Timing or breaking the PlanDefinition/RequestOrchestration alignment relevant to this tracker.

AutoFHIR reconciliation:
No source change was made. The active current source already carries the requested Timing choice on RequestOrchestration.action.timing[x], and PlanDefinition.action.timing[x] also includes Timing.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-11555 unless the work group decides to reopen the broader timing-choice policy for PlanDefinition and RequestOrchestration together.
