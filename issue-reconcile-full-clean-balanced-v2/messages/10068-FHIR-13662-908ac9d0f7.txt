FHIR-13662: Audit history delete documentation

Issue request:
FHIR-13662 was a Published/Persuasive STU3 FHIR-core HTTP issue requesting that history documentation mention the Bundle entry response, because response.lastModified is needed to convey deletion time, and include an example fragment for a deleted item.

Initial application:
The issue was applied in SVN revision 13074, represented in git as 7850c9a122cd, which changed source/http.html to add response.lastModified comments to the history examples, add a DELETE history-entry example, and add a note recommending response.lastModified so processing time is clear. Subsequent edits corrected and expanded that text.

Additional context:
Later related Published decisions are already represented on the combined branch. FHIR-17075 audited the mandatory history request/response rule, FHIR-38942 audited the current Bundle invariants, and FHIR-7933 reconciled the active HTTP history paragraph with those later rules. The current source/http.html page is an active core RESTful API page and now says every history entry SHALL contain request and response, that PUT/POST entries contain the processed resource while DELETE entries omit resource, and its DELETE example includes response.status and response.lastModified. Current Bundle source also requires response on history entries and requires response.status when response is present.

AutoFHIR reconciliation:
Made no source change. The current build source already satisfies FHIR-13662's requested documentation and example, and adding redundant prose would not change implementer understanding.

Keep this audit commit as-is. No follow-up core source change is needed for FHIR-13662 unless a future work-group decision reopens broader history Bundle request/response semantics.
