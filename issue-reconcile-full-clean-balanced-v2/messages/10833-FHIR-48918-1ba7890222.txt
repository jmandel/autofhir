FHIR-48918: Audit DeviceUsage boundary externalized

Issue request:
FHIR-48918 was an Applied/Not Persuasive with Modification OO change request for R6. It asked to let DeviceUsage.informationSource reference Device so device-reported use could be represented; the final disposition did not add Device, and instead clarified DeviceUsage scope and boundaries for patient-reported or second-hand use, DeviceRequest requests, Procedure implant/explant events, DeviceAssociation precise device-patient association, and related Observation boundary work.

Initial application:
The issue was applied in the FHIR core history through PR #3637 and a set of FHIR-48918 commits ending at 74fe475c94e02e7ae38748812169da739e498b99. Those commits updated source/deviceusage/deviceusage-introduction.xml with the revised scope and boundary language. The current local DeviceUsage StructureDefinition source also confirms that DeviceUsage.informationSource still targets Patient, Practitioner, PractitionerRole, RelatedPerson, Organization, and Group, with no Device target added.

Additional context:
DeviceUsage is no longer an active resource in the current FHIR core build. Commit 3b38b80cf23f9cbb306fab8fcedb293315478c32 removed DeviceUsage from source/fhir.ini resource/workgroup/FMM/normative registration and changed core module pages to link DeviceUsage to the OO incubator IG. FHIR-51713, which cited FHIR-48918 for clarity around detailed daily usage, has already been audited on the combined branch as external-repo. The current OO incubator continuous-build DeviceUsage artifact keeps Device out of informationSource; any further DeviceUsage narrative refinement now belongs in that external source, not in core.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The remaining DeviceUsage files under source/deviceusage are out of the active core build, and editing them would not correct the current FHIR core publication. The active core source already points implementers to the external OO incubator DeviceUsage artifact.

Recommendation:
Keep this external-repo audit as-is for core reconciliation. If the work group wants the exact FHIR-48918 narrative refinements carried forward or expanded in the current DeviceUsage artifact, make that follow-up in the OO incubator repository; no current FHIR core source change is appropriate for this issue.
