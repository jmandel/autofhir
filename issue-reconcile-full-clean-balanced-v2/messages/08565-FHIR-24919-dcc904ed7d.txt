FHIR-24919: Audit Age search data type mapping

Issue request:
FHIR-24919 was a Published/Persuasive FHIR-core correction asking the search data type summary table to stop saying Age is not used in search. The approved resolution was to put Y under quantity for Age and N under the other search parameter types.

Initial application:
Jira cites GH#7c0e9a614f, and git history shows 7c0e9a614fb69e905643cedd0692b2e1f82d149a added Age=quantity to source/fhir.ini and replaced the Age row's Not used in search cell with per-search-type cells in source/search.html. That commit is on an R4B-side branch rather than the current lineage, but the current lineage carried the same Age search table hunk in 5db566a208601df59e6c725326554e94cdc68112 and retained the Age=quantity search rule through later source refactors.

Additional context:
The current build-scope search configuration has an active [search-rules] section where Age maps only to quantity. The current search.html table is a top-level search page source and its Age row delegates each cell to xcm macros, so the active Age=quantity rule is the source of the quantity-only rendered result. Current Condition search parameters include onset-age and abatement-age as quantity search parameters over Age or Range, matching the issue's motivating example. Zulip discussion in #implementers > Search Summary Tables confirms the original report and no Confluence evidence was found that changes the decision.

AutoFHIR reconciliation:
No source change was made. The current source already implements the requested Age mapping and no stale current-spec source location was found that still says Age is not used in search.

Recommendation:
Keep this empty audit commit as-is. No further core FHIR source work is needed for FHIR-24919 unless the search table generation mechanism itself changes and needs a separate validation of xcm/search-rules rendering.
