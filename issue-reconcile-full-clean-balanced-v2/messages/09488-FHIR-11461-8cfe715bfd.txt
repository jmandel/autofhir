FHIR-11461: Include datatypes in profiling StructureDefinition summary

Issue request:
FHIR-11461 is a Published/Persuasive DSTU2 FHIR-core conformance-module issue. It asked to change the StructureDefinition contents bullet from describing how existing elements in resources are used to describing how existing elements in resources and/or data types are used, because StructureDefinitions constrain data types too.

Initial application:
The Jira comments identify svn @10162 as the application point. The matching git-svn commit 83f1205cc1f012816734622c56ee12d93a24212d explicitly mentions #11461 and changed source/conformance-module.html so the conformance-module contents bullet included resources and/or data types. The current conformance module still carries that semantic change, with later terminology-normalized spelling as "datatypes".

Additional context:
A later terminology cleanup, FHIR-25431, normalized "data type" to "datatype" in the affected narrative. While checking for parallel current-source wording, source/profiling.html was found to have the same conformance-resource summary and active documentation navigation, but its StructureDefinition sub-bullet still said only "resources" even though nearby profiling guidance already says StructureDefinitions constrain resources and datatypes.

AutoFHIR reconciliation:
This commit changes the active profiling page summary to say StructureDefinitions describe existing elements in resources and/or datatypes. The conformance module was not changed because the Jira-requested wording is already present there.

Recommendation:
Keep this source fix. It preserves the historical FHIR-11461 decision in the conformance module and removes the remaining parallel resource-only wording from the current profiling narrative without changing unrelated profiling rules.
