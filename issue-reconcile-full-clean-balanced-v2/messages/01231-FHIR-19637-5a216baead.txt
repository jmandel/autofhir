FHIR-19637: Audit ImagingStudy procedure cardinality

Issue request:
FHIR-19637 was a Published/Persuasive with Modification Imaging Integration issue raised against STU3. It reported that ImagingStudy.procedureReference was limited to 0..1 even though a single imaging study can satisfy multiple procedures, and the accepted R5 resolution replaced procedureCode/procedureReference with a repeating procedure element carrying Reference(Procedure) or CodeableConcept content. The resolution also mentioned an R4 compatibility extension for additional procedure references.

Initial application:
The issue was explicitly applied in commit e64cab69affa7913fed6bd2f23cfe30728893ab2, whose subject included GF#19637. That commit changed the ImagingStudy spreadsheet and XR example from procedureReference/procedureCode to repeating procedure entries with valueReference and valueCodeableConcept. No separate source-changing reconciliation is needed for the historical R5 application.

Additional context:
Later published/applied ImagingStudy decisions changed the representation without reintroducing the original 0..1 problem. FHIR-32719 converted the backbone/value[x] shape to CodeableReference, FHIR-32793 lowered the procedure code binding to preferred, FHIR-50894 briefly moved performed procedures to partOf, and FHIR-53025 restored the current ImagingStudy.procedure relationship as a repeated Reference(Procedure). Related audit/fix commits for FHIR-32719, FHIR-32793, and FHIR-53025 are already present on the combined branch. The current build actively includes ImagingStudy, and the active StructureDefinition has ImagingStudy.procedure 0..* Reference(Procedure) with a matching procedure search parameter. Direct searches found no current core or Extension Pack definition for the historical R4 compatibility extension, so that part of the old resolution is outside the current FHIR core build rather than a current-source defect.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current spec no longer contains active ImagingStudy.procedureReference or ImagingStudy.procedureCode elements, the repeated performed-procedure relationship exists as ImagingStudy.procedure, and later accepted R6 decisions explain why the current type is Reference(Procedure) rather than the exact R5 backbone/value[x] wording from FHIR-19637.

Recommendation:
Keep this audit commit as-is. Do not reintroduce the obsolete procedureReference/procedureCode or R5 backbone shape in current core; if the R4 compatibility extension is still desired, it should be reviewed as extension-pack or release-maintenance work rather than edited into the current core resource.
