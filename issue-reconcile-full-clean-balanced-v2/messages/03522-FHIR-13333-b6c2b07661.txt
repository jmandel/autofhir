FHIR-13333: Audit core message event code removal

Issue request:
FHIR-13333 was Published with a Persuasive with Modification STU3 correction for the same MedicationAdministration-related message event code family. It reported QA errors because defined event codes such as MedicationAdministration-Complete were not lowercase-dash and said all event codes were camel-case. The accepted resolution was to remove all event codes, referencing the Zulip discussion about whether anyone used HL7-defined FHIR message events.

Initial application:
The issue was applied before this reconciliation. Jira records svn revision 13987, and git-svn commit 2b81a477bd4df7e781a87c177f4c2fb552641fa1 (GF#13333 - remove event list) removed the rendered message event list from source/messaging.html, replaced the Event List section with Defining Events, removed the [%events%] include, and stated that the specification does not define events.

Additional context:
FHIR-15063 had already removed the four MedicationAdministration Events-tab rows from the old spreadsheet. Later combined-branch commits for FHIR-26902 and FHIR-32398 removed remaining empty MessageEvent value set references and changed active MessageHeader/MessageDefinition bindings to descriptive example text. These later changes are already represented on the combined branch and reinforce that the current core build should not define MedicationAdministration or other core message event codes.

AutoFHIR reconciliation:
Made no source change. Current source/messaging.html still says FHIR does not define message events, MessageHeader and MessageDefinition are active resources with descriptive MessageEvent bindings, the terminology spreadsheet no longer points to #message-events, and targeted current-source searches found none of the old MedicationAdministration event codes or event-list/value-set leftovers.

Recommendation:
Keep this empty audit commit as-is. Future standardized message event codes should be added only through a new explicit InM/work-group decision; this reconciliation should not recreate lowercase versions of the removed STU3 event codes.
