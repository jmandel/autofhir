It reported that the IGPublisher download link was wrong; the description proposed a version-local STU3 jar URL, while the later editor comment clarified that the approved direction was to point to the current build/build.fhir.org instead.

Initial application:
No repository commit explicitly mentions FHIR-15834. Source history shows the downloads page IG Publisher row was subsequently changed in non-Jira-keyed commits: 06915efa replaced the local org.hl7.fhir.igpublisher.jar link with a latest publisher CLI artifact URL, and later history continued moving the current downloads page away from version-local tool jar downloads.

Additional context:
The current checkout builds R6 ballot content, not the static STU3 publication. The current downloads page is in build scope through source/hierarchy.xml and publish.ini, but it no longer contains a direct IG Publisher jar download link; it points implementers to the FHIR Tools Registry and notes that NPM packages are used by tools such as the IG publisher. FHIR-31735 later removed direct Validator and IG Publisher tool links from source/downloads.html as part of splitting tools out from the specification. The published STU3 page is static historical content and currently has an IG Publisher row pointing at http://hl7.org/fhir/ig-publisher with a note to use the current build version; repairing that historic page or redirect is outside the active FHIR build source.
