FHIR-11108: Audit implantable device status coverage

Issue request:
FHIR-11108 was Published/Persuasive with Modification for DSTU2 Device.status, asking for more status coverage for implantables and suggesting an implantableDeviceStatus value set. The decisive resolution reopened the ballot item and applied the attached UDI/implant status proposal.

Initial application:
The source history does not contain an explicit FHIR-11108 tag, but the same GForge issue family was applied in 2bd8c95642d3c1f3609ca70c5b6678a874b8de35 on 2017-02-07 as [#11105]-[#11109]. That commit changed Device example statuses from available/not-available to active/inactive and added a Device implant-status extension/value set with functional, non-functional, disabled, and unknown. FHIR-15846 later left that implantStatus extension non-modifier, and GF#17542 renamed it to camelCase.

Additional context:
Later work split record status from physical, operational, and association state. FHIR-32557 and FHIR-34542 clarified Device.status as a Device record status, while FHIR-38904 introduced DeviceAssociation. FHIR-48532 and FHIR-48713 then separated DeviceAssociation.status from DeviceAssociation.associationStatus and populated associationStatus with implanted, explanted, attached, on, off, standby, defective, and abandoned. Core extensions, including device-implantStatus and its terminology, were removed from core in dd468d4f1799dd79819315b211588ef1cf4586e0 and are present in the FHIR Extension Pack. FHIR-29776 remains unresolved/triaged about possible deprecation or relationship of implantStatus, so this reconciliation should not preempt that work-group decision.

AutoFHIR reconciliation:
Made no source change. The current core Device.status is a record status, DeviceAssociation is active in fhir.ini and includes associationStatus for implantable/device association state, and the original functional implantStatus extension/terminology exists in the Extension Pack rather than in core. Adding redundant core Device.status values or copying extension-pack content back into core would contradict the later separation.

Recommendation:
Keep this no-change audit. Any future decision to deprecate or reshape device-implantStatus should proceed through FHIR-29776 or a successor FHIR-extensions ticket; no core FHIR source change is needed for FHIR-11108.
