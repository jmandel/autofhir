FHIR-18493: Audit definition period tooling

Issue request:
FHIR-18493 is a Published/Persuasive FHIR-core narrative issue raised against STU3 and applied for R5. It asked for consistency about terminal periods at the end of definitions and the resolution was to add tooling logic to add periods at the end of definitions, usage notes, and similar text for profiles, value sets, code systems, and other infrastructure resources if feasible.

Initial application:
No source commit on the searched branches explicitly mentions FHIR-18493. The nearby Narrative issues FHIR-18492 and FHIR-18494 were applied directly to source/datatypes/narrative.xml by commits 9cad63bc63 and 7550ccbfa7, but FHIR-18493 itself appears to have been handled as build/rendering tooling rather than as a source-text change. That matches the FHIR-I minutes, which recorded FHIR-18493 as a tooling issue and agreed to fix tooling.

Additional context:
Narrative is active in the current build: source/fhir.ini lists Narrative as infrastructure, maps its type page to narrative.html, and marks it normative. The spreadsheet source still contains some Narrative and NarrativeStatus definition cells without terminal periods, but current generated CI/R5 outputs for narrative.profile.json, narrative.profile.xml, codesystem-narrative-status, and valueset-narrative-status include the terminal periods. The FHIR source checkout does not contain the publisher Java tooling that performs this normalization, so editing these individual source cells would not implement the Jira resolution and would only duplicate a rendering policy already visible in the generated conformance surface.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current built specification already presents the affected profile, code system, and value set definitions with consistent terminal periods, and the remaining source-input punctuation differences are handled by tooling rather than by per-cell source edits.

Recommendation:
Keep this no-change audit commit. No FHIR source edit is needed for FHIR-18493; if future generated outputs lose the terminal-period normalization, follow up in the FHIR Publisher/build tooling rather than by patching isolated spreadsheet cells in this repository.
