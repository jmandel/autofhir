FHIR-6257: Audit date search prefixes

Issue request:
FHIR-6257 was a Published/Persuasive with Modification FHIR-I change request raised against DSTU1. It asked for additional date search prefixes so clients could find period-valued resources that start after or end before a date, originally proposing symbolic negated comparison forms such as !< and !>. The accepted resolution was to add the capability using the new syntax agreed in Paris.

Initial application:
The Jira comments record SVN revisions 6216 and 6217. In the current git history those are a6729b2c4c19162697829b45f1be532fa780badd (#6257 - clarify use of search prefixes) and 2f1c3bc400b2f854c0134237237fa042d06702ea (#6257 - define new search parameters). They updated source/search.html and source/search_filter.html to add the Paris syntax as the sa (starts after) and eb (ends before) search comparators, rather than the originally suggested !< and !> token forms.

Additional context:
The current source/search.html is the active Search page and source/fhir.ini lists SearchParameter as an active FHIR-owned resource. Current source/search.html defines sa and eb in the prefix table, includes them in the range comparison matrix, and gives date examples for sa2013-03-14 and eb2013-03-14. Current source/search_filter.html includes sa and eb operators and points to the Search Prefixes section for their detailed rules. The SearchParameter source now binds comparators to the active complete SearchComparator CodeSystem, which contains sa and eb. Later date-search clarifications and implementer discussions refined the period/range wording but did not remove or supersede the sa/eb comparators; a 2016 Zulip discussion identified the old third-column sa/eb wording as backwards, and the current source has the corrected above/below range semantics.

AutoFHIR reconciliation:
This is an empty no-change audit commit. The current build source already contains the accepted FHIR-6257 functionality using the WG-approved sa/eb syntax across the narrative, _filter operator table, SearchParameter comparator surface, and comparator terminology source. Adding the old symbolic negated operators or additional redundant prose would conflict with the historical Persuasive with Modification application rather than fix a current omission.

Recommendation:
Keep this audit commit as-is. No FHIR core source change is needed for FHIR-6257; future work on date/period search semantics should be handled through the later date-search issue family rather than re-opening the completed prefix-addition decision.
