FHIR-18823: Audit Appointment fulfilled status wording

Issue request:
FHIR-18823 was a Published PA change request raised against STU3 Appointment.status asking to add an Appointment in-progress status because the existing arrived and fulfilled statuses did not explicitly represent an appointment while care was underway. The final Not Persuasive with Modification resolution did not add an in-progress Appointment status; it instead directed that the fulfilled code definition clarify that status tracking moves to Encounter.

Initial application:
The issue appears to have been applied by Cooper Thompson's implementation commit cb628754c6856b96d7456ae810b6b80b8a4056d1, merged as 4bb5ace5bfe3b431ec777313612408dc119f7f90 with the message "GF#18823 - Updated description of fulfilled status in Appointmnt". That commit replaced the old fulfilled definition in the then-authoritative Appointment spreadsheet with the exact clarification approved by the Jira resolution. Later source refactors moved the code system into source/appointment/codesystem-appointmentstatus.xml while preserving the fulfilled definition.

Additional context:
The PA 2018 Baltimore WGM minutes discuss tracker 18823 directly, record the rationale that once an appointment is fulfilled the encounter tracks care status, acknowledge edge cases, and record the decision to make the Appointment fulfilled status clearer rather than add a separate in-progress Appointment status. Current source/fhir.ini actively includes Appointment as a built resource, and Appointment.status remains required-bound to the AppointmentStatus value set.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active AppointmentStatus code system already defines fulfilled as "The planning stages of the appointment are now complete, the encounter resource will exist and will track further status changes. Note that an encounter may exist before the appointment status is fulfilled for many reasons." Appointment.status does not include an in-progress code, matching the final Not Persuasive with Modification decision.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-18823 unless PA reopens the status model in a later tracker; adding an in-progress Appointment code now would contradict the published disposition.
