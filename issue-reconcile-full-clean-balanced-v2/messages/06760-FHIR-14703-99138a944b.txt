FHIR-14703: Audit ValueSet expand limited expansion wording

Issue request:
FHIR-14703 was a Published/Persuasive with Modification STU3 vocab change request for ValueSet $expand. It asked to clarify that a server chooses the size and membership of a limited expansion, and to adjust the then-current expand.limitedExpansion documentation to say that the operation parameter overrides ExpansionProfile.limitedExpansion if present.

Initial application:
The Jira comment says the change was pre-applied in svn 13351. Git history matches that in d90f55e1cb, which updated source/valueset/valueset-spreadsheet.xml and added the requested sentence that the selection and number of codes returned in a limited expansion are at server discretion, plus the ExpansionProfile.limitedExpansion override wording.

Additional context:
FHIR-16449 later made a Published/Persuasive with Modification decision for the same ValueSet $expand parameter family: remove ValueSet.$expand.limitedExpansion because the server decides when an expansion is too expensive and clients already have count for partial results. Commit af02669d42 removed expand.limitedExpansion and added count-based limited-subset wording. The current build-scope ValueSet source is active in source/fhir.ini, and source/valueset/operationdefinition-ValueSet-expand.xml now has no limitedExpansion input; instead it says expansions that are too large are at server discretion and clients may use offset/count or count for a subset for limited purposes. The combined branch already contains an audit commit for FHIR-16449, so this commit does not duplicate that related issue.

AutoFHIR reconciliation:
No source change was made. Reintroducing wording for expand.limitedExpansion would contradict the later published removal; the current ValueSet $expand text preserves the relevant server-discretion concept through the active count/too-costly guidance.

Recommendation:
Keep this audit commit as-is. No FHIR-14703 follow-up is needed unless the work group reopens the later FHIR-16449 decision about replacing limitedExpansion with count-based partial expansion guidance.
