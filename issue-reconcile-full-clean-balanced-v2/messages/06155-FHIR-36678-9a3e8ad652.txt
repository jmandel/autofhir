FHIR-36678: Audit ValueSet title extension URL

Issue request:
FHIR-36678 was a Published/Persuasive R5 technical correction for FHIR Core downloads. It reported that extension-definition.xml/json gave the valueset-compose-include-valueSetTitle entry the wrong fullUrl, http://hl7.org/fhir/StructureDefinition/valueset-systemName.

Initial application:
No Jira-tagged source commit for FHIR-36678 was found. The historical core extension source explains the generated-download problem: source/valueset/structuredefinition-extension-valueset-compose-include-valueSetTitle.xml originally carried the correct canonical url/fixedUri but the wrong StructureDefinition.id value valueset-systemName, so generated Bundle.fullUrl values could use the sibling extension URL. Commit b2634dc630dcba91a636a4bffa3c297ca71fa845 changed that id to valueset-compose-include-valueSetTitle; later cleanup kept the corrected id/url/OID metadata until commit dd468d4f1799dd79819315b211588ef1cf4586e0 removed ValueSet extension StructureDefinitions from core source as part of the R5 extension-source move.

Additional context:
The current core checkout no longer owns the valueSetTitle StructureDefinition source. Current core build inputs retain the correct OID mapping and active ValueSet notes that direct users to the display extension and say valueset-compose-include-valueSetTitle is deprecated. The maintained Extension Pack definition has id, url, and fixedUri all set to http://hl7.org/fhir/StructureDefinition/valueset-compose-include-valueSetTitle. A historical tools/history/release4b generated aggregate still contains the old bad fullUrl, but that is a checked-in historical release artifact, not current build source. Related reconciliations on the combined branch already audit the original extension addition (FHIR-28116) and the later deprecation/display guidance (FHIR-40715).

AutoFHIR reconciliation:
This commit intentionally makes no source change. The seed's generated fullUrl problem was fixed in the old core source before R5 publication, the authoritative current extension definition is correct in the Extension Pack, and editing stale historical generated files or re-adding the deprecated extension source to core would be inappropriate.

Recommendation:
Keep this no-change audit for core. No follow-up source edit is needed for FHIR-36678 unless a separate Extension Pack build later shows a regenerated Bundle.fullUrl mismatch, which was not found here.
