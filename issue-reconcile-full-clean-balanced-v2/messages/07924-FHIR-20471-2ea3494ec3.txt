FHIR-20471: Audit SearchParameter expectation contexts

Issue request:
FHIR-20471 was Published/Persuasive for R5 and asked to extend the capabilitystatement-expectation extension so it can be used on SearchParameter.multipleOr, SearchParameter.multipleAnd, SearchParameter.comparator, SearchParameter.modifier, and SearchParameter.chain instead of changing those SearchParameter elements into complex structures.

Initial application:
The issue was initially applied in HL7/fhir by PR #1964. Commit dfa5fb0aaf706c9e4d8c420446baf5e99573c347 added SearchParameter contexts to source/capabilitystatement/structuredefinition-extension-capabilitystatement-expectation.xml, though that first patch misspelled SearchParameter.modifier as SearchParameter.modifer. Later extension-context cleanup in 5b129917061c5f19861dfc5326f95b4be59d507c removed the SearchParameter contexts from the core extension source, and dd468d4f1799dd79819315b211588ef1cf4586e0 removed core extension definitions from the R5 source tree.

Additional context:
Current core still builds SearchParameter as an active resource, and the relevant elements exist in source/searchparameter/structuredefinition-SearchParameter.xml. Core no longer has a capabilitystatement-expectation StructureDefinition source file; extension links point through the extensions-location mechanism. The current FHIR Extension Pack source owns StructureDefinition-capabilitystatement-expectation.xml and, following FHIR-56196 / fhir-extensions PR #252, includes the five requested SearchParameter contexts with the correct SearchParameter.modifier spelling.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The current FHIR-core checkout is correct because it no longer owns the extension definition, and the owning Extension Pack checkout already contains the SearchParameter contexts requested by FHIR-20471. Re-adding an extension definition or redundant prose to core would be out of build scope and would risk diverging from the Extension Pack source of truth.

Recommendation:
Keep this no-change audit commit as-is. No core follow-up is needed for FHIR-20471; future follow-up, if any, belongs in the Extension Pack publication process for FHIR-56196 rather than in the core FHIR source checkout.
