FHIR-23870: Audit Device version component clarification

Issue request:
FHIR-23870 was a Published FHIR-core Device change request, resolved Persuasive with Modification for R5. It asked to clarify Device.version.component by defining it as the hardware or software module of the device to which the version applies and by adding a note that such a module need not be tracked as a separate Device, such as when one device has multiple software modules on different versions.

Initial application:
The request appears to have been pre-applied in git commit a7f2575daae7bbacd9a22ea439c7ec35a4784f96, whose Device updates message lists FHIR-23870 and whose patch changed the then-authoritative source/device/device-spreadsheet.xml text from the old generic component wording to the approved hardware/software module definition and note. The later build-source rework in commit 33b409a4b6d544598262f2f074ebb4b6dc466157 carried that content into source/device/structuredefinition-Device.xml.

Additional context:
Device is an active resource in source/fhir.ini, and the current source uses the renamed Device.deviceVersion.component path rather than the older Device.version.component name. The active StructureDefinition already contains the requested definition and explanatory comment. OO minutes from October 31, 2019 confirm the FHIR-23870 block-vote disposition, and a later Zulip Device.version thread discusses the changed current-build wording without identifying a conflicting interpretation. FHIR-32566 is a later same-area uniqueness-guidance issue for Device.deviceVersion type/component and is already represented on the combined branch; it does not supersede the component clarification.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Keep this audit commit as-is. No core FHIR source follow-up is needed for FHIR-23870 unless a future work group decision changes the Device.deviceVersion model or asks for broader narrative guidance.
