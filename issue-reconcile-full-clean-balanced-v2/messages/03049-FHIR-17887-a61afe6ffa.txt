FHIR-17887: Audit FamilyMemberHistory negation example

Issue request:
FHIR-17887 was a Published FHIR-core Patient Care change request with resolution Persuasive with Modification. It asked for negative family-history examples; the accepted scope was to add one FamilyMemberHistory example showing that FamilyMemberHistory.condition.code can capture "No Known Problems" or negated conditions such as "No history of malignant tumor of breast" for an individual family member, while "No family history of heart disease" was left for an Observation change request.

Initial application:
The Jira application comment points to GH#0b58425. Commit 0b584258d4 added source/familymemberhistory/familymemberhistory-example-negation.xml with SNOMED CT code 700146008 and the "No history of malignant tumor of breast" text, and added the example to the then-current FamilyMemberHistory example machinery. The same commit also carried the separate FHIR-17682 heading clarification, which is related history but not decided by this audit.

Additional context:
FamilyMemberHistory is an active resource in source/fhir.ini and belongs to the Patient Care work group. Current source still contains the negated-condition example, lists it in list-FamilyMemberHistory-examples.xml, and retains notes saying FamilyMemberHistory.condition.code can represent "No Known Problems" or a negated condition for one family member. Earlier FHIR-8782 established the same condition.code guidance; later FHIR-43306 was Resolved - No Change after explicitly noting the FHIR-17887 example and recommending a precoordinated condition.code, or CodeableConcept.text if no code exists. The broader FHIR-38899 absence-representation issue remains Triaged and does not override the applied Patient Care decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active FamilyMemberHistory source already contains the requested example and supporting notes, and changing the resource to add a separate negation indicator would conflict with the later Patient Care no-change decision.

Recommendation:
Keep this audit commit as-is. Revisit only if the unresolved cross-resource absence work, such as FHIR-38899, reaches a final decision that changes the FamilyMemberHistory negation pattern.
