FHIR-26672: Audit CodeSystem lookup operation rendering

Issue request:
FHIR-26672 was a Published/Persuasive technical correction for the CodeSystem $lookup OperationDefinition. The original report asked why the formal OperationDefinition carried FMM 5, standards-status normative, and normative-version metadata when the rendered formal page showed Maturity Level N/A and Standards Status Informative; the final FHIR-I decision instead said the breadcrumb's final label should be the operation name and the formal OperationDefinition page heading/status should reflect the operation metadata.

Initial application:
No Git commit in this source checkout explicitly mentions FHIR-26672. The current source/codesystem/operationdefinition-CodeSystem-lookup.xml resource still carries the normative FMM/status metadata, and the current canonical JSON served from hl7.org resolves to the raw OperationDefinition rather than the old R4 HTML page. The operation remains listed as a tool/example-style resource instance in source/operationdefinition/list-OperationDefinition-examples.xml, which is consistent with the current rendered HTML still using the Example Instance breadcrumb/status treatment.

Additional context:
The 2020 Zulip thread that led to this ticket first assumed the normative claims might be wrong, but the 2020 and 2022 FHIR-I minutes revised the decision to keep the operation metadata and fix the rendered operation-instance page labeling/status. Current R5/current-build HTML for operation-codesystem-lookup.html still shows Example Instance and Informative, while the raw current build JSON has FMM 5 and standards-status normative. The source checkout does not contain the publisher page-classification/status-rendering code needed to make formal operation pages use the OperationDefinition resource metadata.

AutoFHIR reconciliation:
This commit intentionally makes no source change in the FHIR specification checkout. The authoritative OperationDefinition source already contains the expected normative metadata, and changing local example-list metadata would be a speculative workaround for a generic publisher/rendering issue affecting operation formal-definition pages.

Recommendation:
Keep this audit commit as an external-repo decision. Follow up in the FHIR publisher/build tooling or publication routing so formal OperationDefinition pages render as operation definitions, use the operation name rather than "Example Instance" in breadcrumbs/headings, and derive maturity/standards status from the OperationDefinition metadata.
