FHIR-17481: Audit individual search parameter expressions

Issue request:
FHIR-17481 was Published/Persuasive and auto-approved for STU3. It reported that generated individual-* SearchParameter definitions, exemplified by individual-address, omitted Person.address from expression while listing Person as a base and also duplicated several XPath fragments.

Initial application:
The Jira comment records svn revision 14532. In git history this corresponds to f25a484e20387684e12152c5625b387c453dd71f, whose subject is "GF#13864 + GF#16001 + GF#17481 - fix errors generating search parameters" and which updated search-parameter generation logic. The checked historical release3 and release4 generated bundles now include Person.address and non-duplicated XPath for individual-address and the other affected individual address parameters.

Additional context:
The current build source no longer stores full generated expressions in the common-search-parameters source bundle; it stores the common SearchParameter code and base list that the publisher uses to generate the registry bundle. source/fhir.ini actively includes SearchParameter as a resource, and source/searchparameter/common-search-parameters.xml includes Person as a base for individual-address and the other individual address variants that FHIR-17481 was concerned about. A current CI bundle check of https://build.fhir.org/search-parameters.json shows individual-address with bases Patient, Person, Practitioner, and RelatedPerson and expression "Patient.address | Person.address | Practitioner.address | RelatedPerson.address". The Zulip thread that led to the Jira issue confirms the same bug report and no conflicting rationale was found in Confluence.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current authoritative source already carries the Person base for the affected common individual address parameters, the generated current CI expression includes Person.address, and the old duplicate XPath problem is not present in the current generated surface.

Recommendation:
Keep this no-change audit commit. Further source edits would be redundant unless a future publisher regression again omits one of the declared bases from generated common SearchParameter expressions.
