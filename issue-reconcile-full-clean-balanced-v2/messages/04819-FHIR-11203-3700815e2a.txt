FHIR-11203: Audit Flag encounter timing guidance

Issue request:
FHIR-11203 was Published/Not Persuasive with Modification for DSTU2. It asked to add an invariant ensuring Flag.duration and Flag.encounter align; the final resolution rejected a cross-resource invariant and instead required a comment on Flag.encounter saying that when Flag.encounter and Flag.period are both valued, the Flag.period bounds must fall within the referenced Encounter period.

Initial application:
The issue appears to have been applied by bd9f60dbffee762fd2b3e49ee2e07e232b9685a9, which added the requested Flag.encounter comment to the historical Flag spreadsheet source alongside FHIR-11202. Later source conversion carried the guidance into the current source/flag/structuredefinition-Flag.xml definition.

Additional context:
Flag is in current build scope because source/fhir.ini has an active flag=Flag resource entry. The current Encounter source uses Encounter.actualPeriod for actual encounter timing after FHIR-32351, and the already-published FHIR-32351 reconciliation commit 55b6972198ad1e12d56bfb6615d9df709a4f152b updated the Flag.encounter comment from Encounter.period to Encounter.actualPeriod. Direct Zulip and Confluence searches for FHIR-11203 found no conflicting community evidence.

AutoFHIR reconciliation:
This audit commit makes no source change. The current Flag.encounter comment already expresses the approved rule, and its Encounter.actualPeriod wording is the correct current-resource equivalent of the original Encounter.period resolution text.

Recommendation:
Keep this audit commit as-is. No follow-up source edit is needed for FHIR-11203 unless the work group later decides to replace the advisory comment with an enforceable same-resource rule or another conformance mechanism.
