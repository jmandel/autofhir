FHIR-12325: Audit metadata compatibility note

Issue request:
FHIR-12325 was Published/Not Persuasive with Modification for the FHIR-core HTTP page. It raised that STU3's move from the Conformance resource to CapabilityStatement could break existing clients using GET [base]/metadata, and the final decision was to add a note about cross-version client connection issues rather than create a new endpoint.

Initial application:
The issue was applied in git-svn commit 0f6f410a49eb (#12325, svn revision 10274), which added an implementation note to source/http.html saying that in DSTU2 and earlier the returned resource was named Conformance and that clients using the capabilities interaction for version and feature checks should process either Conformance or CapabilityStatement.

Additional context:
FHIR-9645 is the underlying same-change-family decision that renamed Conformance to CapabilityStatement. The current source still carries the FHIR-12325 note in the capabilities interaction, and source/hierarchy.xml plus publish.ini show source/http.html is the active RESTful API page in the current build. Later HTTP-page changes, including the nearby fhirVersion parameter guidance, do not reverse or narrow the compatibility note.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current HTTP source already states the approved compatibility guidance, and adding a new /capabilities endpoint or duplicating the warning elsewhere would go beyond the Jira resolution.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-12325 unless the work group later decides to retire DSTU2/STU3 transition guidance from the HTTP page.
