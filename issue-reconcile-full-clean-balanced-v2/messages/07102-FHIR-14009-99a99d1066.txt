FHIR-14009: Audit ValueSet URL documentation

Issue request:
FHIR-14009 was a Published STU3 vocab change request, resolved Not Persuasive with Modification. It asked to rename ValueSet.url to ValueSet.uri and adjust the ValueSet/$expand url parameter because implementers confused a canonical identifier with a literal retrieval URL; the work group instead kept the url name to encourage resolvable URLs and committed to improving the documentation.

Initial application:
The Jira comment records an SVN application, and the git-svn import contains 9a720ed103130ae2b7de480d307c57f08b80d4e8, "#14009 - better doco about url vs uri". That commit updated the ValueSet and CodeSystem identification narrative and the shared metadata resource URL definition rather than renaming the element or operation parameter.

Additional context:
ValueSet is an active resource in source/fhir.ini, with the ValueSet operation list actively referencing OperationDefinition/ValueSet-expand. Later canonical-URL cleanup in 6f7c3716ef8e176e5ea811ceb12844b81a3904ec changed the terminology from canonical URI to canonical URL, and FHIR-50825 later clarified the ValueSet/$expand url parameter to say it is a reference to the canonical URL of a value set while retaining type uri. FHIR-22699 also fixed a typo in the ValueSet.url definition and is already represented on the combined branch. Community searches found no Zulip or Confluence record that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit makes no source change. The current built source already says ValueSet.url is the canonical URL, explains that the element is named url rather than uri for legacy reasons and to encourage a resolvable URL when possible, keeps the underlying type as uri, and describes ValueSet/$expand url as a reference to the canonical URL of a value set. That matches the final issue disposition; renaming the element or adding more parallel prose would now be incorrect or redundant.

Recommendation:
Keep this no-change audit commit as-is. No FHIR core follow-up is needed for FHIR-14009 unless the work group makes a new substantive decision about canonical URL naming.
