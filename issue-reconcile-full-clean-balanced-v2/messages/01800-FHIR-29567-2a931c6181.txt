FHIR-29567: Audit assigned manufacturer extension

Issue request:
FHIR-29567 was a Published Pharmacy change request, resolved Persuasive with Modification for R5, asking to add an "assigned Manufacturer" Organization attribute under Medication.Batch for the organization that produced the product on behalf of the Medication.manufacturer or wholly or partially produced the medication product. The final resolution said to create a core extension for the attribute.

Initial application:
No source commit was found whose message explicitly names FHIR-29567. Git history shows the request was nevertheless applied in the Medication manufacturing-batch extension family: commit 52f3ef3d50 added manufacturingBatch.assignedManufacturer to source/medication/medication-extensions-spreadsheet.xml as a 0..1 Reference(Organization), commit 33b409a4b6 generated source/medication/structuredefinition-extension-medication-manufacturingBatch.xml with the assignedManufacturer Reference(Organization) slice, and commit dd468d4f17 later removed that core extension source when R5 extensions were moved out of this repository. The Extension Pack imported and retained the same extension family.

Additional context:
Medication remains an active core resource, but the current core source maps the historical Medication.batch path to Medication.instance and no longer owns the medication-manufacturingBatch StructureDefinition except for its OID registry entry. The same extension now lives in the FHIR Extension Pack, whose input/definitions/multiple/StructureDefinition-medication-manufacturingBatch.xml applies to Medication.batch and defines Extension.extension:assignedManufacturer as a Reference to Organization. Pharmacy minutes for 2020-11-09 record the PQ/CMC manufacturing discussion and the 9-0-0 carried block vote, including FHIR-29567, to add a core extension. A 2022 Zulip thread shows implementation use of the medication-manufacturingBatch extension family and profiles assignedManufacturer as an Assigned Manufacturer reference; no later conflicting decision was found.

AutoFHIR reconciliation:
This commit intentionally makes no HL7/fhir source change. The requested conformance content exists in the current external source of truth, HL7/fhir-extensions, and reintroducing the extension source into core would conflict with the post-R5 extension repository split.

Recommendation:
Keep this audit commit as an external-repo decision. No core FHIR source change is recommended; any future content correction to medication-manufacturingBatch should be made in HL7/fhir-extensions rather than reintroducing the extension source into core.
