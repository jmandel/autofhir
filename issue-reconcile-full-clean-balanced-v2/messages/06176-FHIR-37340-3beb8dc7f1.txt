FHIR-37340: Audit Questionnaire string newline guidance

Issue request:
FHIR-37340 was a Published/Persuasive R5 FHIR-core change request for Questionnaire and QuestionnaireResponse. It asked for clearer validation guidance distinguishing Questionnaire item types 'string' and 'text', specifically that QuestionnaireResponse answers for a 'string' item should not use carriage return or newline characters and multi-line answers should use item type 'text'.

Initial application:
The issue was applied before this reconciliation by git commit c9ed8e2c8a7898252b2577fd45f889b2d6bd355d, "FHIR-37340 - added guidance on newlines in Questionnaire string". That commit changed source/questionnaire/codesystem-item-type.xml so the 'string' Questionnaire item-type concept says: "Strings SHOULD NOT contain carriage return or newline characters. If multi-line answers are needed, use the 'text' type."

Additional context:
The affected Questionnaire and QuestionnaireResponse resources are active in source/fhir.ini, and Questionnaire.item.type is required-bound to the active item-type-useable ValueSet, which includes the same http://hl7.org/fhir/item-type CodeSystem. The neighboring 'text' concept already describes a long, potentially multi-paragraph valueString answer. Wider Jira/Zulip/Confluence searches found no later issue or discussion reversing the guidance; Confluence SDC minutes from 2022-05-05 record FHIR-37340 as Persuasive. The primitive FHIR string datatype source was checked but left unchanged because the issue scope, related artifacts, and application commit are about Questionnaire item type validation, not a global restriction on all FHIR strings.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build source already contains the approved SHOULD NOT newline guidance in the authoritative Questionnaire item-type CodeSystem, the Questionnaire binding reaches that CodeSystem through the active item-type-useable ValueSet, and the R5 published CodeSystem surface contains the same wording.

Recommendation:
Keep this no-change audit commit as-is. No core source follow-up is needed for FHIR-37340 unless a future work group decision changes the Questionnaire string/text semantics or asks for computable validation beyond the approved SHOULD-level guidance.
