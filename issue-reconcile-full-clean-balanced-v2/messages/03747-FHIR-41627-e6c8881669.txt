FHIR-41627: Audit translated resource update guidance

Issue request:
FHIR-41627 was an Applied FHIR-core change request for the R5 languages page. It asked whether resources returned in a requested language should be marked SUBSETTED and requested clearer guidance about preventing translated or language-altered responses from being used as update bases. The final Persuasive with Modification resolution said translated resources are not necessarily subsetted, but if the server changes the primary language of text, the altered version is likely not an appropriate basis for updates; the server can omit an eTag while enforcing version-specific updates or use a TRSLT meta.tag.

Initial application:
The issue appears to have been applied directly to source/languages.html. Two February 2025 attempts added the approved paragraph, with the first immediately reverted. Commit 906b6f4238b4d7bede6badc3398e438df3a483d3 later replaced a stray list item on the languages page with the approved guidance, formatting the paragraph and linking TRSLT to the v3 ObservationValue code.

Additional context:
publish.ini has an active languages.html entry, so the edited page is in the current core build surface. Confluence FHIR-I minutes for 2023-12-11 record the same Persuasive with Modification motion and 6-0-0 vote. Jira and Zulip searches did not find a later conflicting decision or a tightly related issue that changes the interpretation.

AutoFHIR reconciliation:
No source change was made. The current source already states the final resolution's rule in the active languages page: a language-altered response may be unsuitable for updates, and servers can avoid update misuse by omitting the eTag with version-specific update enforcement or by tagging the resource TRSLT.

Recommendation:
Keep this audit commit as-is. No follow-up core source work is needed for FHIR-41627 unless the work group later decides to change the TRSLT or eTag guidance.
