FHIR-13071: Audit RequestGroup request alignment

Issue request:
FHIR-13071 was Published/Persuasive for CDS and asked that RequestGroup be aligned with the Request pattern by adding definition, basedOn, replaces, groupIdentifier, intent, and priority, and by mapping occurrence, code, supportingInfo, and performer to the corresponding RequestGroup.action elements.

Initial application:
The issue was applied in SVN r11658, preserved as git commit 416f8ff7b2637545c11170804aaffff4e866e234, which added the requested RequestGroup elements, request-pattern mappings, value set bindings, and example updates. No prior AutoFHIR reconciliation commit for FHIR-13071 existed on the combined branch.

Additional context:
The current build no longer has a RequestGroup resource folder; FHIR-24619 renamed it to RequestOrchestration, and source/fhir.ini actively builds requestorchestration while mapping the old RequestGroup name to RequestOrchestration. The original definition element was later split into instantiatesCanonical and instantiatesUri as part of the canonical/uri/reference change, with a Zulip discussion confirming that PlanDefinition-style definitions should be referenced canonically. FHIR-24619 is already represented on the combined branch and is background, not a separate decision here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active RequestOrchestration StructureDefinition contains identifier, instantiatesCanonical, instantiatesUri, basedOn, replaces, groupIdentifier, status, intent, and priority with workflow mappings to the Request pattern, and its action.code, action.documentation, action.timing[x], and action.participant elements map to Request.code, Request.supportingInfo, Request.occurrence[x], and Request.performer. The request mapping exceptions file records the remaining wording/type divergences as intentional pattern exceptions rather than missing application.

Recommendation:
Keep this empty audit commit as-is. Future work should handle separate RequestOrchestration behavior or naming issues under their own Jira keys; FHIR-13071 itself is fully represented in current build-scope source.
