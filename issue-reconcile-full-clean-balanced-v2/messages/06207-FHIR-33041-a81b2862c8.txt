FHIR-33041: Audit specimen-in-process Observation status

Issue request:
FHIR-33041 is an Applied OO FHIR-core Observation change request, resolved Persuasive with Modification, asking whether the HL7 v2 OBX-11 "Specimen in Lab; results are pending" / in-process state should map to Observation.status=registered or require a separate status. The final resolution was to add a level-1 Observation.status code "Specimen-in-Process" after "Registered" for a specimen being processed in the laboratory when no results are available yet.

Initial application:
The issue was applied before this reconciliation. Commit cf4d553a6a5a6d56da1af43dbbdb3b987bdb0d0c added the specimen-in-process concept to source/observation/codesystem-observation-status.xml. Follow-up commits 801bfdfc63685f9de0eca1ee09b0aafdd3b51b79 and 9116279038b62c39a08fdd12fdebc6b6a02f96bb updated source/status-codes.xml and the Observation/RiskAssessment status short text so the new code appears in the parallel built surfaces. PR #3154 was merged as d22fa851724ea7e6bb70d4942749754660b79b80, and the Jira application comment links that implementation path.

Additional context:
Observation is active in source/fhir.ini, so the Observation CodeSystem and StructureDefinition sources are in current build scope. Current source has specimen-in-process as a top-level CodeSystem concept immediately after registered, and Observation.status, the event mapping exception, status-codes.xml, and RiskAssessment.status all include the code. Related Observation status issues FHIR-33042 and FHIR-33043 are already represented on the combined branch and are not republished here. Later Jira FHIR-54892 asks to remove specimen-in-process, but it is Triaged/Unresolved; FHIR-54153 is also Triaged/Unresolved and concerns changelog/diff output. Neither is a final later decision overriding FHIR-33041.
