FHIR-17564: Audit FamilyMemberHistory birth-sex rename request

Issue request:
FHIR-17564 was a Published Patient Care STU3 change request asking to rename FamilyMemberHistory.gender to birthSex. The final Not Persuasive with Modification decision rejected birthSex as too precise for information often reported by a patient, friend, or relative, kept the then-current gender element name, and required a cautionary comment explaining the ideal genetic-sex intent and the possibility of imprecision.

Initial application:
The issue was applied historically by commit 5596f16348, whose message cites GF#17564 and adds the requested cautionary comment to the FamilyMemberHistory spreadsheet source. Later source rework converted the resource into source/familymemberhistory/structuredefinition-FamilyMemberHistory.xml while preserving the comment. A later published same-family issue, FHIR-17780, superseded the element-name part of this history by renaming FamilyMemberHistory.gender to FamilyMemberHistory.sex and updating the comment and requirements from gender wording to sex/genetic sex wording.

Additional context:
FamilyMemberHistory is an active resource in source/fhir.ini. Current active source defines FamilyMemberHistory.sex, not FamilyMemberHistory.birthSex, with a birth-sex definition, extensible administrative-gender binding, and the cautionary imprecision comment requested by FHIR-17564 as later adapted by FHIR-17780. Related binding/context issues FHIR-18848, FHIR-18850, and FHIR-20393 are already represented on the combined branch. Later FHIR-43360 resolved no-change and reaffirmed that Patient Care wanted the element named sex. A later R6 FHIR-55021 follow-up exists but is Resolved - change required rather than Applied/Published in this run scope and should be handled separately.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source already satisfies FHIR-17564 when interpreted with the later published FamilyMemberHistory sex-name and binding decisions; changing the element to birthSex or back to gender would conflict with later final decisions, and changing the comment would be redundant rather than a necessary current-spec fix.

Recommendation:
Keep this audit commit as-is for FHIR-17564. Treat any future changes to the FamilyMemberHistory.sex definition or binding as separate follow-up work under the later issue family, especially FHIR-55021 if it becomes in-scope for application.
