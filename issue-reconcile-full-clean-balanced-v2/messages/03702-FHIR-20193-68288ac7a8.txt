FHIR-20193: Audit ICD terminology table URIs

Issue request:
FHIR-20193 was a Published Vocabulary change request from STU3/R5. The reporter noted that the ICD-9 and ICD-10 values in the first URI column of terminologies-systems.html were not valid URIs. The final Not Persuasive with Modification resolution was to point the table at ICD guidance because there are multiple ICD URIs.

Initial application:
The issue was first applied in 9500b398d1 as part of a Vocabulary R5 ticket batch. That changed the ICD table guidance/comment to say there are multiple URIs and to see the ICD page, but it did not change the first-column text itself. FHIR-35933 later moved the external code-system usage links to THO in 81e5862f20, preserving an ICD guidance link and an OID-cell note.

Additional context:
The current page is in build scope through publish.ini and source/hierarchy.xml. A later same-change-family issue, FHIR-41305, re-raised the first-column ICD URI problem for R5 and was Applied for R6. Its implementation in 11181dd489 replaced "ICD-9, ICD-10" with URI strings and fixed the source-cell formatting; f628812336 subsequently cleaned the local link targets. Confluence minutes for 2021-07-28 record the original "Will update spec" decision, and no Zulip discussion was found that changed the conclusion.

AutoFHIR reconciliation:
This empty audit commit makes no source changes. Current source/terminologies-systems.html shows http://hl7.org/fhir/sid/icd-9-cm and http://hl7.org/fhir/sid/icd-10 in the URI column and links to the THO ICD guidance, so the current source satisfies the seed after later issue-family updates.

Recommendation:
