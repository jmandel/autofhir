FHIR-16349: Correct Observation status binding summary link

Issue request:
FHIR-16349 was Published with a Not Persuasive with Modification resolution after a request to relax Observation.status from a required code-list binding to extensible for additional states such as "released" and "signed". The approved disposition kept Observation.status required and directed that those act states be represented with Provenance, with Observation.status remaining preliminary until completion and then final.

Initial application:
No git commit explicitly mentioning FHIR-16349 was found. The directly cross-referenced companion issue FHIR-16315 was applied in git 2ebd7c6f7f, which changed the historical Observation status definition for final from "The observation is complete" to the Provenance/preliminary/final guidance; later source restructuring carried that guidance into source/observation/codesystem-observation-status.xml.

Additional context:
Current source/observation/structuredefinition-Observation.xml still binds Observation.status to http://hl7.org/fhir/ValueSet/observation-status with required strength, and source/observation/codesystem-observation-status.xml contains the expected guidance for released/signed style act states. However, the active Vital Signs profile summary in source/observation/structuredefinition-profile-vitalsigns.xml described Observation.status as required while linking the word required to terminologies.html#extensible. That profile is part of the Observation package through source/observation/list-Observation-packs.xml and implementationguide-Observation-vitalsigns.xml, so the stale link could still mislead readers about the binding strength.

AutoFHIR reconciliation:
This commit changes only the two Vital Signs profile summary extensions for Observation.status so their required binding link points to terminologies.html#required. It does not change the binding strength, value set, or the approved Provenance guidance.

Recommendation:
Keep this commit as-is. The core Observation.status binding should remain required; future generated or profile-summary text should preserve the required link and not reintroduce an extensible link for Observation.status.
