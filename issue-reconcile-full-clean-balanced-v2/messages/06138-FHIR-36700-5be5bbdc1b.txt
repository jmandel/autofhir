Issue request:
FHIR-36700 was Published/Persuasive with Modification for R5. It asked FHIR-I to clarify ElementDefinition.pattern[x] wording so patterns apply to each occurrence of a constrained element, to clarify array wording, and to add pattern usage examples and a link from the pattern[x] comment.

Initial application:

The issue key was not written in the exact FHIR-36700 form in that historical commit subject, but the commit content matches the Jira resolution.

Additional context:
FHIR-33316 was the earlier published same-change-family issue about the pattern[x] array sentence and was applied by 08d840fb48809b6e69bfd75e45073818aab41498. The conformance Zulip thread and FHIR-I 2022-04-04 minutes show that FHIR-36700 was created to settle the remaining confusion: a pattern declared on a repeating element applies to all repetitions, while a pattern inside a nested array recursively requires at least one matching nested repetition. FHIR-28126 later added the separate "if the element has a value" qualifier for min=0 cases, explaining the current text's slight difference from the original FHIR-36700 wording.

No source change was made. The latest combined branch already has the FHIR-36700 rule in source/datatypes/elementdefinition.xml, including the all-repetitions rule, the slicing instruction for subset matching, and the link to elementdefinition-examples.html#pattern-examples. The examples page contains primitive, complex, and repeating pattern examples and is part of the ElementDefinition page set through the active ElementDefinition datatype/build configuration.

Recommendation:
Keep this no-change audit commit. The current source conveys the approved clarification without needing duplicate or editorial prose; only revisit if the work group wants to reopen the substantive behavior of pattern[x] on repeating elements.
