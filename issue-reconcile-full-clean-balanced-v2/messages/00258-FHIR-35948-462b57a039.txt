FHIR-35948: Clarify SampledData variable timing

Issue request:
FHIR-35948 was Published/Persuasive for R5 and asked SampledData to support variable timings by adding SampledData.offsets, changing SampledData.interval from 1..1 to 0..1, describing SampledData.intervalUnit as the unit for either interval or offsets, and requiring one of interval or offsets but not both.

Initial application:
The issue was initially applied in git commit 6b6661326a, which added SampledData.offsets and made SampledData.interval optional in the active datatypes spreadsheet. Later SampledData commits clarified offsets and exposed the generated constraint in the datatype narrative, but the current authoritative spreadsheet still described the root datatype as needing period, described intervalUnit as interval-only, and labeled the invariant as requiring "interval and offsets but not both".

Additional context:
source/fhir.ini lists SampledData as an active normative datatype source, and maps the R4 SampledData.period name to the current SampledData.interval name. The originating Zulip thread and MnM minutes show that the problem was variable sample timing and that offsets were explicitly discussed. Later FHIR-49899 clarified that offsets are from the logical start point and added the constraints include to the narrative; it does not reverse the FHIR-35948 one-of interval/offsets rule.

AutoFHIR reconciliation:
Updated source/datatypes/sampleddata.xml so the datatype comments require origin, dimensions, and either interval or offsets instead of the old period-only language; changed intervalUnit's short and definition to cover interval or offsets; and corrected the invariant's English label to say interval or offsets while leaving the already-correct FHIRPath and XPath expressions unchanged.

Recommendation:
Keep this commit as-is. It finishes the remaining FHIR-35948 source wording gaps in the active datatype spreadsheet without changing the later FHIR-49899 offsets clarification or adding redundant narrative text.
