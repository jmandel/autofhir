FHIR-11363: Audit ValueSet expansion designations

Issue request:
FHIR-11363 was a Published/Persuasive vocabulary change request from DSTU2 asking to add ValueSet.expansion.contains.designation, including language, use, and value, so terminology services could return alternate displays such as English and French designations in expansions. The resolution was to add designations to expansion.contains, with designations derived from the value set definition.

Initial application:
The issue was initially applied in SVN revision 9926, preserved in git as a598bfb33e (#11363 - add designations to ValueSet.expansion.contained), which added ValueSet.expansion.contains.designation to source/valueset/valueset-spreadsheet.xml and its extracted sheet text. The source was later migrated into source/valueset/structuredefinition-ValueSet.xml by the build-source refactor and R4B/R5 work.

Additional context:
ValueSet is an active resource in source/fhir.ini. The current authoritative ValueSet StructureDefinition includes ValueSet.expansion.contains.designation with 0..* cardinality and a contentReference to ValueSet.compose.include.concept.designation, which carries the designation substructure including language, use, additionalUse, and value. The current comment also requires expansion designations to be based on the value set and code system definitions. Direct Zulip and Confluence searches for FHIR-11363 found no conflicting community record.
