FHIR-35962: Audit subject compatibility guidance

Issue request:
FHIR-35962 was Published/Not Persuasive with Modification for R4B/R5 by the CDS work group. It asked whether the new canonical subject choice on ActivityDefinition.subject[x] and PlanDefinition.subject[x] should be backed out of R4B for R4 compatibility, and resolved instead to add a usage note saying the choice was added for pharmaceutical quality use cases and should be used only for those use cases to preserve as much backwards compatibility as possible.

Initial application:
The issue was pre-applied on 2022-04-13 by PRs HL7/fhir#1870 and HL7/fhir#1871. Git commits 1220898cb3460 and 424c9a2ae00f added the requested comment to both source/activitydefinition/structuredefinition-ActivityDefinition.xml and source/plandefinition/structuredefinition-PlanDefinition.xml.

Additional context:
ActivityDefinition and PlanDefinition are active, approved resources in source/fhir.ini. Later same-family issues FHIR-31763 and FHIR-37485 corrected the formal subject target split so product definition resources are Reference targets and canonical is limited to EvidenceVariable; those issues are already represented on the combined branch. Their reconciliation updated the prose to refer to the product definition and canonical subject choices together, but retained the FHIR-35962 compatibility guidance. The referenced Zulip thread raised the compatibility concern, MnM minutes sent the R4B question to FMG while agreeing the change needed to be included in R4B, and the CDS agenda records the FHIR-35962 block vote.

AutoFHIR reconciliation:
This commit makes no source change. The current active StructureDefinition XML for both subject elements already contains the R4B pharmaceutical-quality/backwards-compatibility note, and changing it back to mention only canonical would conflict with the later corrected Reference-versus-canonical semantics.

Recommendation:
Keep this audit commit as-is. No further core source change is needed for FHIR-35962 unless a future work-group decision changes the underlying R4B/R5 compatibility guidance.
