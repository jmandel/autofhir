FHIR-28581: Audit product definition resource split

Issue request:
FHIR-28581 was a Published FHIR-core BR&R R5 change request resolved as Not Persuasive with Modification. It asked to reduce the number of resource types used to define products by merging MedicinalProductDefinition, AdministrableProductDefinition, and PackagedProductDefinition concepts into one reusable product-definition resource with profiles for the IDMP views. The final resolution says the work group was not convinced by the arguments and that the resource definitions had been considerably enhanced to explain the selected boundaries.

Initial application:
No original source commit explicitly tagged FHIR-28581 was found. The current source appears to carry the application through surrounding medication-definition documentation work: the module page added guidance that not all resource levels need to be used, shows simpler and one-resource representations, and records the rationale for rejecting a generic profiled product resource; later FHIR#31805 commits added contained-resource and PackagedProductDefinition guidance for simpler product cases. A related AutoFHIR commit for FHIR-31863 has already corrected stale package relationship wording in that same guidance.

Additional context:
FHIR-31863 is the same resource-boundary change family and was also Published/Not Persuasive with Modification, with a resolution that documentation and justification had been improved and the boundaries were appropriate. BR&R minutes from 2022-03-03 list FHIR-31863 and FHIR-28581 as the two remaining Medication Definition in-person negatives before final resolution. Zulip discussion around FHIR-28581 shows the same concern and the counter-position: simple cases can use MedicinalProductDefinition with contained or omitted subordinate resources, while complex regulatory, package, manufactured-item, and administrable-product use cases need separately addressable resources.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. In the current build scope, fhir.ini lists the relevant product-definition resources as active/normative, and the module and resource Scope and Usage source already explain the boundary rationale, simpler one-resource representations, contained-resource option, packageFor relationship, administrable-product role, and package role. Adding another restatement would be redundant rather than a necessary current-spec correction.

Recommendation:
Keep this audit as-is. The current source matches the published work-group decision not to collapse the product-definition resources. Revisit only if new implementation evidence leads BR&R to reopen the resource-boundary decision; otherwise, no further FHIR core source work is needed for FHIR-28581.
