FHIR-17722: Align Address.type location guidance

Issue request:
FHIR-17722 was a Published/Persuasive with Modification STU3 change request for the Address datatype. It reported that the Address note said addresses were postal, not physical locations, while the datatype definition and Address.type allowed visiting/physical-address use; the approved resolution was to reword the note to say Address describes postal addresses for administrative purposes, not absolute geographical coordinates, and that postal addresses are often used as proxies for physical locations.

Initial application:
The issue was applied by git commit 89b894c3a3, which changed the root Address comment to the approved wording and partially updated the Address.type comment. The root comment remains correct, but the Address.type comment still quoted the obsolete "postal addresses, not physical locations" idea and therefore preserved the contradiction the issue meant to remove.

Additional context:
FHIR-16981 introduced the nearby physical-address clarification before FHIR-17722 and is the same wording family. Current source/fhir.ini routes datatypes to the datatypes page, so source/datatypes/address.xml is active build source. Searches found no later Jira, Zulip, or Confluence decision that reverses the FHIR-17722 resolution; Location.address and official-address issues are adjacent but target different requirements.

AutoFHIR reconciliation:
Updated the Address.type comment in source/datatypes/address.xml to align with the final Address note: postal addresses are for administrative purposes rather than absolute coordinates, while they may still proxy visitable physical locations. No generated history snapshots were edited.

Recommendation:
Keep this source fix as-is. It removes the remaining contradictory wording while preserving the intended Address.type guidance; no additional core follow-up is indicated from the checked evidence.
