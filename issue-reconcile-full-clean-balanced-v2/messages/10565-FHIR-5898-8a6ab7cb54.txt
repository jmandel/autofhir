FHIR-5898: Audit profile binding subset validation

Issue request:
FHIR-5898 is a Published/Persuasive FHIR-core DSTU1 issue asking that the validator catch a profile binding that is not a proper constraint of an extension's binding; the Jira example was the DAF patient profile declaring a distinct binding from the us-core-race extension without the validator reporting the mismatch.

Initial application:
Jira records "svn revision 4557" as the application. Git history contains that SVN import as commit 7996f50897b97db120319141c23e9a1070d853b4, whose message includes "#5898 - check required binding isn't being violated in profile" and whose source change was in the legacy Java ProfileUtilities/publisher tooling under tools/java.

Additional context:
The current build includes source/profiling.html through publish.ini and source/hierarchy.xml, and that page states that profile value sets can replace base bindings only within the base constraints: required base bindings can only be narrowed to codes in the base value set, additionalBinding follows the same rules, and a constraining profile cannot make codes valid that are invalid in the base profile. The historical tools/java validator tree is absent from this checkout after the 2019 old-code removal, while the current Gradle build consumes external kindling/validator artifacts. Current org.hl7.fhir.core ProfileUtilities contains the corresponding binding-strength and required-binding subset checks, and a 2024 Zulip validator thread shows the current validator emitting "Binding ... is not a subset of binding ..." errors. The adjacent binding-strength tooling issue FHIR-7802 is already represented on the combined branch and is cited only as context.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the active core profiling source already states the correct binding-subset rule and the historical in-repository validator code that FHIR-5898 changed is no longer part of this checkout.

Recommendation:
Keep this audit commit as-is. If a future validator release fails to enforce binding subset alignment, handle that in the current validator/kindling codebase rather than by changing FHIR core spec source; no current core source edit is indicated by this reconciliation.
