FHIR-27130: Audit Subscription $status operation

Issue request:
FHIR-27130 is a Published/Persuasive R5 FHIR-I change request asking for a Subscription operation to retrieve current status after the Subscription/SubscriptionStatus refactor made status less directly queryable. The approved resolution was to define type-level Subscription/$status for one or more ids and instance-level Subscription/[id]/$status with no arguments, returning SubscriptionStatus resources in a Bundle.

Initial application:
The issue was applied before this reconciliation. Jira records commits 4d7b2fb0a8033ce61f901e023893a02c8bdfeaeb and 33b409a4b6d544598262f2f074ebb4b6dc466157; the first added $status request/response examples and spreadsheet operation rows, and the second converted the source to operationdefinition-Subscription-status.xml and list-Subscription-operations.xml. A 2020 subscriptions Zulip update also listed FHIR-27130 as merged with a link to subscription-operation-status.html.

Additional context:
Subscription is an active current-build resource in source/fhir.ini, and its operation list includes OperationDefinition/Subscription-status. Later Published/Applied decisions refined the same operation: FHIR-30368 confirmed idempotence for GET, FHIR-30379 clarified id parameter text, FHIR-30381 added the optional status filter, FHIR-47291 clarified that the operation returns SubscriptionStatus information, and FHIR-47292 linked the return documentation to SubscriptionStatus query-status guidance. Those related issues are already represented on the combined branch where applicable, so this seed should not duplicate their audit commits or undo their refinements.

AutoFHIR reconciliation:
Made no source change. The current OperationDefinition already defines code status on Subscription with both type and instance availability, id/status type-scoped inputs, affectsState=false for GET-safe use, and a Bundle return documenting SubscriptionStatus query-status guidance; the operation is listed for the active Subscription build input.

Recommendation:
Keep this audit commit as-is. No follow-up core source change is needed for FHIR-27130 unless a future work-group decision changes the newer $status parameter or SubscriptionStatus return guidance.
