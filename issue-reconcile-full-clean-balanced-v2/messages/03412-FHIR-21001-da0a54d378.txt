FHIR-21001: Align ChargeItem pricing ModelInfo

Issue request:
FHIR-21001 was a Published/Persuasive with Modification Patient Administration change request for R5 asking ChargeItem to carry monetary charge amounts. The approved resolution replaced priceOverride with totalPriceComponent, added unitPriceComponent, removed factorOverride because the price component carries factor, and changed overrideReason from string to CodeableConcept.

Initial application:
Commit 8b936b6829 applied the ChargeItem source change before R5 publication, updating the StructureDefinition, example, and search parameters. Because the related FHIR-16380 decision created the reusable MonetaryComponent metadata type, the R5 ChargeItem StructureDefinition used MonetaryComponent for unitPriceComponent and totalPriceComponent instead of a local backbone.

Additional context:
FHIR-16380 was a Published/Persuasive PA decision that explicitly listed ChargeItem.totalPriceComponent and ChargeItem.unitPriceComponent among the elements to use the new MonetaryComponent type. ChargeItem and ChargeItemDefinition were later removed from active core resource inputs by commit 71567db3ee and moved to the HL7 Administrative Incubator IG, whose current CI package still exposes the FHIR-21001 ChargeItem fields. The active core Library/FHIR-ModelInfo example remained stale: it still exposed ChargeItem.factorOverride, ChargeItem.priceOverride, and string overrideReason, while Library remains an active resource in source/fhir.ini.

AutoFHIR reconciliation:
Updated source/library/library-fhir-model-definition-content.xml so the active FHIR ModelInfo surface now defines PriceComponentType and MonetaryComponent, exposes ChargeItem.unitPriceComponent and ChargeItem.totalPriceComponent as FHIR.MonetaryComponent, and changes ChargeItem.overrideReason to FHIR.CodeableConcept. This does not reintroduce removed core ChargeItem resource files; it only fixes the active ModelInfo example that still surfaced the old shape.

Recommendation:
Keep this commit. Future structural maintenance of the authoritative ChargeItem resource should happen in HL7/admin-incubator, and broader MonetaryComponent ModelInfo alignment for Invoice or ChargeItemDefinition should be audited under FHIR-16380 or a dedicated related issue.
