FHIR-36648: Audit ImagingSelection graphic type reconciliation

Issue request:
FHIR-36648 was a Published FHIR-core ImagingSelection change request with resolution Not Persuasive with Modification. It reported that the old http://hl7.org/fhir/imagingselection-graphictype code system was missing DICOM graphic types CIRCLE and INTERPOLATED while ImagingSelection used a required binding, and the accepted resolution was to apply the linked Imaging Integration Confluence change set rather than simply loosen the binding.

Initial application:
The change appears to have been applied through the ImagingSelection update work merged as 471fbc468b8fd5427fcebad076569e16590ac707, with the source-changing commit 5c5a620527e102650cad53df57ff594d1706fe2a splitting the old generic graphic type into separate 2D and 3D graphic type code systems/value sets. That initial application added the 2D CIRCLE and INTERPOLATED concepts and kept the 2D ImagingSelection region type binding required, matching the Confluence resolution instead of changing the binding to extensible.

Additional context:
ImagingSelection is an active resource in source/fhir.ini, so source/imagingselection feeds the current build. The current source binds ImagingSelection.instance.imageRegion2D.regionType to http://hl7.org/fhir/ValueSet/imagingselection-2dgraphictype with required strength, and that 2D code system now includes circle. The current absence of interpolated is not an unapplied FHIR-36648 gap: later Applied issue FHIR-45266 explicitly corrected the 2D graphic type value set to align with DICOM SCOORD by replacing interpolated with multipoint, and that related issue already has a combined-branch audit commit. Later FHIR-55241 added unknown as an escape valve and corrected the DICOM reference, without reversing the FHIR-45266 replacement.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding interpolated would conflict with the later Applied FHIR-45266 decision, while changing the binding to extensible would conflict with the FHIR-36648 Confluence resolution and later required-binding escape-valve handling.

Recommendation:
Keep this audit as-is. Do not re-add interpolated for FHIR-36648 unless the Imaging Integration work group reopens or supersedes FHIR-45266; the current source is correct for the issue family.
