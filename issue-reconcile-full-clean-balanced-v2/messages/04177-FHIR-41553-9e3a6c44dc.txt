FHIR-41553: Audit ServiceRequest code link removal

Issue request:
FHIR-41553 was an Applied FHIR-core ServiceRequest issue with resolution Persuasive with Modification. It reported that IG Publisher output exposed an invalid markdown link in the ServiceRequest.code binding description, specifically the text saying a LOINC Order-code value set was available [here](valueset-diagnostic-requests.html), and the approved disposition was to remove that value-set-link text because no current value set existed to point to.

Initial application:
The issue was applied before this reconciliation by git commit e3a4c4f4e1cb80cd9bd88481028e0d7b9df9f88c, whose only source change replaced the ServiceRequest.code binding description by removing the sentence fragment "and a valueset using LOINC Order codes is available [here](valueset-diagnostic-requests.html)." The commit directly matches the Jira resolution and touched the active ServiceRequest StructureDefinition source.

Additional context:
ServiceRequest is an active resource in source/fhir.ini, and the current source/servicerequest/structuredefinition-ServiceRequest.xml binding description keeps the LOINC preferred link but no longer contains the broken diagnostic-requests link or the obsolete "available here" wording. The reporter's Zulip thread confirms the defect originated in specification metadata rather than rendered ServiceRequest narrative, and OO WGM minutes record the 8-0-0 motion to remove the unsupported value-set link text.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source already reflects the applied decision, and another edit would either duplicate the existing fix or remove valid binding metadata that still points ServiceRequest.code at the example Procedure Codes value set.

Recommendation:
Keep this audit commit as-is. No follow-up is needed in core unless a future issue decides to change the ServiceRequest.code binding itself or to create a replacement LOINC order value set.
