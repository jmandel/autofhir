FHIR-13376: Audit markdown datatype specification

Issue request:
FHIR-13376 was a Published/Persuasive FHIR-I STU3 change request to settle on a single markdown specification across the FHIR ecosystem. The Jira discussion considered CommonMark, GFM, tables, and security constraints around HTML in markdown; the recorded vote was 6-0-0 and the applied-version target was STU3.

Initial application:
The issue was applied by git-svn commit c1140fdc201c3aa2e13060bc4bd1e573a0a3d80e, titled "GF#13376 - migrate to GFM for markdown". That commit changed the markdown primitive description and datatype notes from the older variable/preferred markdown language to GFM extensions on CommonMark, removed the STU note asking for future CommonMark feedback, and documented markdown readability and character constraints.

Additional context:
The active datatype build scope still routes primitive datatype pages through source/datatypes.html, and current source/datatypes/primitives.xml describes markdown as Github Flavored Markdown. Later Published issue FHIR-38714 corrected the security-sensitive detail: FHIR markdown uses GFM/CommonMark with inline HTML unsupported, and processors must treat embedded XML tags as string content. That later clarification is already represented on the combined branch by Issue-Reconcile-Key: FHIR-38714.

AutoFHIR reconciliation:
No source change was made. The current build-scoped source already states that markdown is a FHIR string using the GFM extension of CommonMark, with no inline HTML support and explicit processor handling for embedded XML tags. A current-source search found no remaining Daring Fireball/preferred-markdown wording that would undermine the single-specification decision.

Recommendation:
Keep this empty audit commit as-is. The current FHIR source satisfies FHIR-13376 after considering both the original GFM migration and the later FHIR-38714 clarification; no further FHIR-core source edit is needed for this issue.
