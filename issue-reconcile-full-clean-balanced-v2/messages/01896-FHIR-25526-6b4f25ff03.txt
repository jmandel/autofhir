FHIR-25526: Audit CarePlan location CodeableReference

Issue request:
FHIR-25526 was a Published Patient Care change request, resolved Persuasive with Modification for R5, to change CarePlan.activity.detail.location from Reference(Location) to CodeableReference(Location) and add an extensible binding to ServiceDeliveryLocationRoleType so location kinds such as home, work, or clinic could be coded as well as referenced.

Initial application:
The Jira comment points to commit 876899d106c8fc355ba7c711cae1e87163309ce2, which updated the legacy CarePlan spreadsheet source and an example. The later source rework commit 33b409a4b6d544598262f2f074ebb4b6dc466157 carried the same J#25526 change into source/careplan/structuredefinition-CarePlan.xml.

Additional context:
CarePlan is an active resource in source/fhir.ini. A later Published CarePlan issue, FHIR-26064, renamed activity.detail to activity.plannedActivityDetail; that rename explains the current path and does not reverse FHIR-25526. Jira searches for the old and current element path and ServiceDeliveryLocationRoleType found no later conflicting CarePlan location decision. The originating Zulip thread supports the same rationale: coded location types are useful and CodeableReference is appropriate.

AutoFHIR reconciliation:
This audit commit makes no source change because the current build-scope CarePlan StructureDefinition already defines CarePlan.activity.plannedActivityDetail.location as CodeableReference targeting Location, includes the J#25526 committee note, and has an extensible binding to http://terminology.hl7.org/ValueSet/v3-ServiceDeliveryLocationRoleType with text noting that the element may reference a specific clinical location or identify a type of location.

Recommendation:
Keep this no-change audit commit as-is. Future CarePlan work should treat FHIR-25526 as applied; only revisit if Patient Care wants a new value set/binding choice or different location guidance beyond the original R5 decision.
