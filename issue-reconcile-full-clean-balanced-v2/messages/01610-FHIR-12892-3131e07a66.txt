FHIR-12892: Audit DocumentReference XDS mappings

Issue request:
FHIR-12892 was Published/Persuasive with Modification for DSTU2 DocumentReference XDS mappings. It asked that the old .created element have no XDS map, the old .indexed element map to DocumentEntry.creationTime, and .status map to DocumentEntry.availabilityStatus.

Initial application:
The 2017 application commit 94e532a611046fcdc40df2d7d28457eeb7dad3a6 changed the DocumentReference spreadsheet for the San Diego WGM block vote, including FHIR-12892. It removed the XDS map from DocumentReference.created, mapped the then-renamed indexing field DocumentReference.date to DocumentEntry.creationTime, and mapped status to DocumentEntry.availabilityStatus.

Additional context:
Later published issue FHIR-19685 changed the creation-time interpretation: DocumentEntry.creationTime belongs to DocumentReference.content.attachment.creation and DocumentReference.date has no XDS mapping. Later applied issue FHIR-43408 reaffirmed the current R6 table with date blank and content.attachment carrying DocumentEntry.creationTime plus repositoryUniqueId/URI. DocumentReference is active in source/fhir.ini, and the current source has status mapped to availabilityStatus, no XDS mapping on DocumentReference.date, and content.attachment mapped to DocumentEntry.creationTime.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The seed request was applied historically, and the current source is correct after the later FHIR-19685 and FHIR-43408 decisions superseded the original placement of DocumentEntry.creationTime.

Recommendation:
Keep this audit commit as-is. Do not re-add an XDS mapping to DocumentReference.date for FHIR-12892; current source should continue to follow the later creation-time mapping decisions.
