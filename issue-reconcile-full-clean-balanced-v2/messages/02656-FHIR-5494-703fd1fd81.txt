FHIR-5494: Audit superseded Composition section.code clarification

Issue request:
FHIR-5494 was a Published/Persuasive DSTU1 Structured Documents ballot comment asking to clarify the invariant that a Composition.section could only have a code if it had no content, with a suggested note that section.code was only used when subsections were present. The Jira comments state that the issue was superseded by FHIR-5155 and was no longer applicable.

Initial application:
No source commit explicitly tagged FHIR-5494 was found. The relevant application history is the FHIR-5155 implementation in git commit cdebd6f91d, which removed the old Composition.section code/content invariant and updated the section.code comments consistently with the committee decision.

Additional context:
FHIR-5155 is also Published/Persuasive for the same Composition artifact and explicitly resolved to remove the constraint because FHIR does not have context conduction and a section code does not change the meaning of nested or referenced resources. The current Composition resource is active in source/fhir.ini, and source/composition/structuredefinition-Composition.xml now has cmp-1 through cmp-3 constraints without the old code/content invariant; its section.code comment says that when a section has content, section.code does not change the meaning or interpretation of the resource content. Community searches found no conflicting core-FHIR decision for FHIR-5494.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Adding the FHIR-5494 requested note would be obsolete and potentially misleading after FHIR-5155, because section.code is no longer limited to sections that only contain subsections.

Recommendation:
Keep this audit commit as-is. No follow-up source change is needed for FHIR-5494; any future cleanup of the current section.code prose should be handled as a separate editorial tracker rather than reviving the superseded invariant.
