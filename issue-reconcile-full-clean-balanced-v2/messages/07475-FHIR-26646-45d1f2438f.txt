FHIR-26646: Audit system-level conditional delete

Issue request:
FHIR-26646 was a Published/Persuasive FHIR-I R5 change request to define system-level conditional delete, analogous to system-level query, with deleting resources by a cross-resource tag as the motivating use case.

Initial application:
The issue was applied by git commit 45aaf5e3a78aa816988cc5660e1ea41c6e43673c, which changed source/http.html to add the whole-system conditional delete entry and the `DELETE [base]?[search parameters]` form. Later HTTP-page work, including FHIR-42728, split conditional delete into single and multiple interaction names and kept the system-level path in the interaction summary.

Additional context:
source/http.html is in the current build through publish.ini. Current source/http.html lists conditional delete single and multiple at the type level, lists whole-system delete as "Conditional Delete across all resource types", defines both `DELETE [base]/[type]?[search parameters]` and `DELETE [base]?[search parameters]`, and includes `/?` rows for both conditional delete interactions in the summary table. FHIR-I minutes from 2020-03-30 record the work-group decision that there was no system-level conditional delete, real-world use cases existed, and the spec would be updated. Zulip searches found no direct conflicting implementation-history discussion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already defines the system-level conditional delete requested by FHIR-26646 and retains it in both the detailed conditional delete prose and summary tables.

Recommendation:
Keep this audit commit as-is. If the work group wants more explicit CapabilityStatement signaling for system-level conditional delete, that should be handled as a new, focused tracker because FHIR-26646's requested HTTP interaction is already present.
