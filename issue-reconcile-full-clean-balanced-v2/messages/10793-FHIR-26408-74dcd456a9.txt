FHIR-26408: Confirm Observation.component inheritance clarification

Issue request:
FHIR-26408 was an Applied FHIR-core Observation change request resolved as Persuasive with Modification. It asked to clarify that Observation.component.dataAbsentReason, Observation.component.interpretation, and Observation.component.referenceRange are not inherited from the corresponding top-level Observation elements when component values are absent, and that interpretation/dataAbsentReason at the Observation level apply to the whole observation rather than automatically to each component.

Initial application:
The issue appears to have been applied by c718c50c58bff1edc1e8ef937f2e019e8e47b48f in HL7/fhir PR #3190. That Jira-tagged commit changed source/observation/structuredefinition-Observation.xml for Observation.component requirements from referenceRange-only guidance to explicit non-inheritance guidance for reference range, dataAbsentReason, and interpretation. The current source still contains that applied text.

Additional context:
Observation is an active current-build resource in source/fhir.ini, so source/observation/structuredefinition-Observation.xml is the authoritative build input for this element. OO minutes show FHIR-26408 was included in the January 2024 block vote, with the January 25 OO Main minutes recording the motion to accept the distributed proposed dispositions 11-0-2. A Zulip issue-key search found no discussion that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Observation.component requirements already say that reference range, dataAbsentReason, and interpretation can differ between components and are not inherited, and that they should be provided where appropriate.

Recommendation:
Keep this no-change audit commit. No FHIR core source follow-up is needed for FHIR-26408 unless the work group separately requests purely editorial wording cleanup.
