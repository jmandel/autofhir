FHIR-16956: Audit SimpleQuantity profile clarification

Issue request:
FHIR-16956 was Published with Persuasive with Modification resolution. It asked the datatype page to clarify the profiling used for SimpleQuantity, include a link to the profile because it was not easy to find in regular profile lists, and avoid calling it a profile if that was not the right terminology. The recorded resolution was to update the language for Quantity after related Quantity changes.

Initial application:
Jira records the application comment "svn 14306". Git history maps that to bfae89f160d2798001c532d9b7287299aa6ea82b, "GF#16956 + GF#16977 + GF#16971 - fix data types links", which made the STU3-era datatype wording say there was one constraint on Quantity used in several resources. Later datatype-page refactors preserved and expanded the same SimpleQuantity section.

Additional context:
FHIR-9168 had already established the model that SimpleQuantity remains a profiled Quantity rather than a normal datatype specialization. FHIR-20322 later challenged the "Profile Name" heading for SimpleQuantity and was Resolved - No Change because SimpleQuantity and MoneyQuantity are profiles of Quantity and not sub-types. Current source also includes a later MoneyQuantity change, so the section now correctly says there are two Quantity constraints rather than one.

AutoFHIR reconciliation:
No source change was made. The active datatype page already links to the SimpleQuantity formal XML and JSON profile artifacts, lists its usage, and explicitly says these Quantity constraints are not types but rules applied where Quantity is used. Active fhir.ini entries also keep SimpleQuantity in the current build as a Quantity-based datatype/profile entry.

Recommendation:
Keep this empty audit commit as-is. The current specification addresses the requested clarification, and changing "Profile Name" or duplicating more explanatory prose would conflict with the later no-change decision and add maintenance drift.
