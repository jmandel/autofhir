FHIR-19284: Audit TestScript HTTP method support move

Issue request:
FHIR-19284 was Published/Persuasive for STU3/R4 and asked core TestScript to support HTTP POST invocation of FHIR search by adding optional TestScript.setup.action.operation.method, bound to HTTP verbs, so a test engine can use the requested HTTP method regardless of operation defaults.

Initial application:
The request was applied in the FHIR source by commit 2adf2bc16064ef00751f144ee1437455bba61b42, whose message says "GF 19284 - added operation.method element" and whose TestScript source added the required operation.method semantics. The pre-removal TestScript StructureDefinition contained TestScript.setup.action.operation.method as 0..1 code with a required binding to ValueSet/http-operations and included post/POST in the HTTP operations code system.

Additional context:
Current core build scope no longer owns TestScript, TestReport, or TestPlan. Commit f9a44787c45071394532c7c2ee94d76f30f47387 removed the testing resources from source/fhir.ini and deleted source/testscript/structuredefinition-TestScript.xml while adding the FHIR Testing IG to source/fhir.ini as an additional IG. Current core narrative links TestScript to https://build.fhir.org/ig/HL7/fhir-testing-ig/, and the live Testing IG TestScript StructureDefinition still contains operation.method with the HTTP operations binding and POST code.

AutoFHIR reconciliation:
This is an empty external-repo audit commit. No core source was changed because the applied TestScript change is no longer part of the active core resource list and the current authoritative TestScript artifact is maintained in the external FHIR Testing IG.

Recommendation:
Keep this audit as-is for the core combined branch. Any future TestScript.operation.method changes should be made in the FHIR Testing IG source rather than restoring or editing removed core TestScript files.
