FHIR-7569: Audit Provenance agent and entity clarity

Issue request:
FHIR-7569 was a Published/Persuasive with Modification Security WG issue from DSTU1 asking to clarify the relationship among a Provenance activity, its agents, and the entities used in that activity. The Jira resolution closed the issue as resolved by FHIR-8595, which added assembler and composer to the Provenance participant vocabulary.

Initial application:
No git commit explicitly mentions FHIR-7569. The related 2015 Security WG commit 1ca8cc96 added Provenance introduction text defining Target, Entity, Agent, and Activity and stating that one Provenance record corresponds to a single activity with target resources, used entities, and associated agents. Follow-up commit 102e7011 corrected the FHIR-8595 vocabulary placement by moving assembler/composer into the Provenance agent-role value set.

Additional context:
Current Provenance is active in source/fhir.ini, so source/provenance/structuredefinition-Provenance.xml and its narrative inputs are in current build scope. The historical inline vocabulary was later refactored: current Provenance.agent.type is the functional participation role bound to participation-role-type, Provenance.agent.role is a structural/security role bound to security-role-type-example, and Provenance.entity.role is the required description of how an entity was used in the activity. Later Published issue FHIR-32453 and related FHIR-32519/FHIR-32520 work refined the same type/role distinction, and those decisions are already represented on the combined branch. FHIR-8595 is also already represented on the combined branch by a no-change audit commit.

AutoFHIR reconciliation:
No source change was made. The current build-scope source already clarifies the Provenance activity/entity/agent model in the resource introduction and in the agent.type, agent.role, and entity.role definitions, while the vocabulary side of the FHIR-7569 resolution is covered by the existing FHIR-8595 audit.

Recommendation:
Keep this no-change audit commit. Reopening FHIR-7569 as a source edit would either duplicate current Provenance guidance or duplicate the separately audited FHIR-8595 terminology trail; future changes to agent functional/structural role semantics should use the later role-clarity issue family rather than this DSTU1 tracker.
