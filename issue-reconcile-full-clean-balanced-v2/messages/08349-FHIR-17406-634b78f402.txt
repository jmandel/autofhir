FHIR-17406: Audit Parameters resource identity rules

Issue request:
FHIR-17406 was Published with resolution Persuasive. It asked FHIR-I to add discussion of resource id uniqueness inside a Parameters instance, including whether repeated parameter.resource entries with the same resource type/id can be presumed to be the same resource or same version. The recorded resolution was to add discussion using the same rules as Bundle after the Cologne revision.

Initial application:
The issue was applied by Grahame's svn revision 13943, now git commit fe6dcf86ed15f9323e86654a929fd4bc3352dddf, which added the Parameters "Names and Identifiers" table to source/parameters/parameters-notes.xml. That table directly addresses parameter names, parameter.resource uniqueness, internal references, and ambiguity when resources with the same identity or different versions appear. The adjacent FHIR-17405 and FHIR-17509 application commits later added the fullUrl-extension qualifier and reference-resolution row that now sit in the same table.

Additional context:
Parameters is an active current-build resource through source/fhir.ini's resource-infrastructure and work-group/normative entries. The current table says resources in parameter.resource do not need to be unique, warns that non-unique resources or different versions of the same resource can be ambiguous without differentiating parameter names, points to the Bundle resource uniqueness discussion, and states that Bundle rules do not apply to Parameters unless the parameters-fullUrl extension is present. Current source/types.html and source/references.html separately preserve the boundary rule that internal id and fragment-reference resolution stop at Parameters.parameter.resource. A 2018-07-09 FHIR-I minutes page lists FHIR-17406 as Persuasive, and no substantive Zulip or Confluence conflict was found beyond the tracker bot notice and unrelated/reference-resolution discussions.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The current authoritative source already answers the implementer question: duplicate parameter.resource ids are not automatically treated as the same resource/version in bare Parameters, ambiguity is called out, Bundle uniqueness guidance is linked for comparison, and Bundle identity rules apply only when a fullUrl is supplied through the extension.

Recommendation:
Keep this audit commit as-is. Do not add redundant Parameters prose for FHIR-17406 unless a future work-group decision changes the intended semantics; any future correction to the parameters-fullUrl extension definition belongs in the FHIR Extension Pack rather than this core source checkout.
