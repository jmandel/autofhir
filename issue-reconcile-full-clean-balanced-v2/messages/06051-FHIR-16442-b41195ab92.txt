FHIR-16442: Audit ValueSet expansion identifier wording

Issue request:
FHIR-16442 was Published/Persuasive for the STU3 ValueSet resource. It asked that ValueSet.expansion.identifier no longer be summarized only as "Uniquely identifies this expansion" and instead be described as "Identifies the value set expansion (business identifier)", based on the ValueSet.identifier wording pattern.

Initial application:
The issue was applied in git commit a866e73f4b (SVN revision 14683), which changed source/valueset/valueset-spreadsheet.xml to the requested short text and added "This is a business identifier" to the element definition. Later source refactors, including 33b409a4b6 and c69d71aa21, carried that wording into the current XML source and generated search-parameter bundle.

Additional context:
source/fhir.ini actively includes valueset=ValueSet in the current resource build. The current authoritative element source uses the requested short text, and the search parameter description for ValueSet.expansion.identifier uses the same business-identifier wording. Nearby narrative still says the expansion identifier uniquely identifies an expansion, but that is consistent with the current full definition and expansion-identifier rules rather than a reversion of the short description. Later FHIR-55363 was Resolved - No Change and confirms that the server assigns one expansion identifier, so no later final decision requires a different edit.

AutoFHIR reconciliation:
Made no source change. The current build-scope source already reflects FHIR-16442's requested clarification, and additional prose would duplicate existing expansion-identifier guidance rather than correct a semantic problem.

Recommendation:
Keep this no-change audit commit as-is. Revisit only if the Vocabulary work group opens a new issue to redefine expansion-identifier uniqueness or cross-server equivalence semantics; that would be separate from FHIR-16442's applied business-identifier wording.
