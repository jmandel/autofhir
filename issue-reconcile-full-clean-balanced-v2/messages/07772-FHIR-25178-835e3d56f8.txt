FHIR-25178: Audit questionnaire-unit display guidance outside core

Issue request:
FHIR-25178 was a Published/Persuasive FHIR-core Questionnaire change request. It asked for the questionnaire-unit extension to say that, when its Coding has a display and the Questionnaire item does not have a child display item using itemControl = unit, form fillers SHOULD use the Coding.display as the rendered unit text.

Initial application:
The issue was applied in core by commit 3286fdf1127ae12eac5c89f712239f5c18d22277, which added the requested SHOULD guidance to source/questionnaire/structuredefinition-extension-questionnaire-unit.xml. Lloyd McKenzie's Jira comment records that commit hash.

Additional context:
The questionnaire-unit StructureDefinition is no longer owned by the current core source checkout. Commit dd468d4f1799dd79819315b211588ef1cf4586e0 removed the extension definition from the R5 core source, and current source/fhir.ini has no active profile entry for questionnaire-unit. The current authoritative definition is in the FHIR Extension Pack, where input/definitions/multiple/StructureDefinition-questionnaire-unit.xml already includes the FHIR-25178 display guidance. The current core source only retains non-defining references such as OID registration, historical release material, conversion logic, and Questionnaire item-type descriptions.

AutoFHIR reconciliation:
This empty audit commit makes no core source change because the source location that would need editing is now outside this FHIR core checkout, and the Extension Pack copy already contains the requested guidance.

Recommendation:
Keep this audit commit as-is for core. No FHIR core follow-up is needed for FHIR-25178; any future editorial cleanup of the extension wording should be made in the FHIR Extension Pack rather than by reintroducing a core StructureDefinition.
