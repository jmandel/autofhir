FHIR-3996: Audit NutritionOrder item removal

Issue request:
FHIR-3996 is a Published FHIR-core/O&O change request resolved Persuasive with Modification. It asked to remove the NutritionOrder.item class and move schedule/timing semantics down into OralDiet, Supplement, and EnteralFormula so separate nutrition order components would not be obscured behind a shared item wrapper.

Initial application:
The original application is visible in git history rather than as a modern source file edit. Commit 7d67ca802e5a4a4a472dcba2a975d3e1b6b9a230 marked NutritionOrder.item, NutritionOrder.item.scheduled[x], and NutritionOrder.item.isInEffect inactive in the old spreadsheet source, moved the item child structures up to NutritionOrder.oralDiet, NutritionOrder.supplement, and NutritionOrder.enteralFormula, and added #3996 notes for the new per-type scheduled elements. Later source-format conversions preserved that model, and commit 1a5062f0a41dca024be7fb527908dcec638166f8 updated NutritionOrder with later Jira dispositions by making the schedule elements explicit BackboneElement structures with schedule.timing children.

Additional context:
NutritionOrder is active in source/fhir.ini. The current authoritative StructureDefinition has no NutritionOrder.item path, keeps OralDiet and Supplement schedules under their own backbones, and places repeatable enteral timing/quantity/rate detail under NutritionOrder.enteralFormula.administration. Although the FHIR-3996 Jira resolution text mentions EnteralFormula 0..*, the 2015 #3996 application already left NutritionOrder.enteralFormula as 0..1; later Published issues FHIR-6100 and FHIR-6101 refined the repeatable enteral feeding schedule into enteralFormula.administration 0..*. No Zulip or Confluence evidence found for FHIR-3996 changes that conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already reflects the applied #3996 item removal and the later, more specific enteral scheduling decisions.

Recommendation:
Keep this no-change audit commit as-is. Revisit only if O&O decides to reopen the broader NutritionOrder cardinality question; replaying the old DSTU1 EnteralFormula 0..* phrase directly would conflict with the original application and later enteral administration modeling.
