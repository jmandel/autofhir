FHIR-11172: Audit CarePlan suspended status

Issue request:
FHIR-11172 was a Published/Persuasive Patient Care change request from the DSTU2 ballot asking for CarePlan.status to include a suspended state for temporarily paused care plans.

Initial application:
The issue was applied in git commit f39dde8e17, which explicitly says it added suspended to the CarePlan status value set. That historical source was later reworked as CarePlan was aligned to the workflow Request pattern.

Additional context:
FHIR-11489 and FHIR-10293 kept CarePlan aligned with the request workflow pattern. The current request-status code system uses on-hold, not suspended, for the same temporary-withdrawal/resume-in-future concept; FHIR-26677 and related implementer discussion confirmed that the required request-status value set is authoritative over stale short descriptions.

AutoFHIR reconciliation:
No source change was made. CarePlan is an active resource in source/fhir.ini, and the current CarePlan.status definition is already bound required to http://hl7.org/fhir/ValueSet/request-status with on-hold in the short code list. The request-status on-hold definition preserves the requested suspended semantics.

Recommendation:
Keep this audit commit as-is. Re-adding a separate suspended code to CarePlan.status would conflict with the current shared request-status terminology and later workflow corrections.
