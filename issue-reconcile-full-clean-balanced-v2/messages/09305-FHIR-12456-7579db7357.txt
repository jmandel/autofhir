FHIR-12456: Audit IG value set dependency handling

Issue request:
FHIR-12456 was a Published/Persuasive FHIR-core DSTU2 change request about the IG Publisher rejecting ValueSet resources whose canonical URLs did not match the publishing IG's canonical base. The Jira discussion clarified that value sets from another guide should normally be referenced through the IG that owns them rather than republished in the importing IG, and a later comment says this was fixed to allow declaration in the definitions file.

Initial application:
No commit explicitly mentions FHIR-12456. The closest historical application evidence is the in-tree IG Publisher work shortly after the Jira was filed: git-svn @10565 changed generated definitions zip creation so importing IGs could use current-version resource definitions, and later nearby DSTU2 IG Publisher commits fixed value set handling. These changes align with the Jira comment that the issue was fixed through definitions/dependency handling rather than a visible resource-definition change keyed to this tracker.

Additional context:
Current core source actively includes ImplementationGuide in source/fhir.ini. ImplementationGuide.dependsOn now says IGs typically use value sets and profiles defined in other implementation guides, and the authoring/package guidance says dependencies identified in other packages are not included in the package. ImplementationGuide.definition.parameter remains tool-defined and extensible for publisher-specific controls. The old in-tree IG Publisher was removed from core after moving to Maven, and the tightly related FHIR-13131 special-URL exception issue is already represented on the combined branch by an external-repo audit commit.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core specification already conveys the needed IG dependency model for value sets owned by other IGs, and any remaining executable IG Publisher behavior belongs to the external publisher/tools package rather than to this core checkout.

Recommendation:
Keep this audit commit as-is. Future changes to publisher handling for external canonical ValueSet URLs should be made in the IG Publisher/tools package unless current core ImplementationGuide narrative or definitions become misleading.
