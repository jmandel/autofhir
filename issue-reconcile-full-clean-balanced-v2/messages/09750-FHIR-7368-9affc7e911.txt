FHIR-7368: Audit narrative human-relevant data guidance

Issue request:
FHIR-7368 was a Published/Persuasive FHIR-core narrative issue asking to add that resource narrative may contain extra human-edited information, but structured data should not contain information important to human readers that is omitted from narrative, because consumers cannot assume systems will render non-narrative data.

Initial application:
The issue appears to have been applied in converted git history by 0a07e675b91532537fd767bf86070a433ced476f, "#7368 - note about narrative", which added the requested structured-data/narrative warning to source/narrative.html. Jira also records Grahame Grieve's application comment, "svn revision 7368". Later grammar cleanup f613e871f0b801b1e0a0dc2da3c509f287a5adcf retained the rule while changing punctuation around the rendering parenthetical.

Additional context:
The current build-scoped narrative page is still active: source/fhir.ini lists Narrative among infrastructure types and maps the narrative type page to source/narrative.html. Current source/narrative.html says resources permitting narrative should contain narrative as a fallback, that structured data SHOULD NOT generally contain information important to human readers that is omitted from narrative, and that creators should not assume systems will render or humans will see non-narrative data. FHIR-17688 later clarified the lead-in to "Resource instances that permit narrative" without retracting this rule, and FHIR-34041 later added clinical-safety checklist guidance for generating and consuming narrative while explicitly avoiding stronger statements.

AutoFHIR reconciliation:
No source change was made. The current source already conveys the FHIR-7368 rule in the active narrative page, with later clarifications that keep the guidance aligned with current Narrative.status and clinical-safety text.

Recommendation:
Keep this audit commit as-is. Reopening the source text for this issue would risk duplicating or over-tightening guidance that later FHIR-I decisions intentionally left contextual; any future change should be handled through a new narrative-safety tracker rather than by reapplying FHIR-7368.
