FHIR-6876: Audit ReferralRequest status alignment

Issue request:
FHIR-6876 is a Published/Persuasive Patient Care ballot comment asking how ReferralRequest.status code active differed from accepted. The published resolution says the ReferralRequest status value set was aligned with the Request pattern through GF/FHIR-10293, leaving active and not accepted.

Initial application:
No source commit explicitly mentions FHIR-6876. The linked workflow application is represented by FHIR-10293/GF#10293 commits, especially f4d7536caa07670c028ba0bc114a334b142e7b9a, which changed ReferralRequest.status from the local referral-request-status value set to http://hl7.org/fhir/ValueSet/request-status and removed the local ReferralRequest status value-set worksheet. Earlier commit b40ce8e28558ce4b7a692f4fa9b0ea24b8bd5c38 had implemented FHIR-3827 by adding accepted, which the later FHIR-6876/FHIR-10293 workflow alignment superseded.

Additional context:
ReferralRequest is no longer an active current resource; source/fhir.ini lists ServiceRequest as active and records that ReferralRequest became ServiceRequest. Current ServiceRequest.status has a required binding to ValueSet/request-status, whose CodeSystem contains active but no accepted code. The Request pattern narrative explicitly separates requester-controlled request status from fulfillment states such as requested, accepted, and in-progress, which are tracked by Task or corresponding event resources. Searches of Zulip and Confluence for FHIR-6876/ReferralRequest accepted status found no conflicting community record.

AutoFHIR reconciliation:
No source change was made. The current build-scope source already preserves the requested outcome: accepted is not a ServiceRequest/Request status code, active remains the requester-controlled authorization state, and fulfillment acceptance is handled outside the request status value set.

Recommendation:
Keep this empty no-change audit commit as-is. Do not reintroduce accepted into Request.status or ServiceRequest.status unless a later work-group decision reverses the Request pattern separation between authorization status and fulfillment status.
