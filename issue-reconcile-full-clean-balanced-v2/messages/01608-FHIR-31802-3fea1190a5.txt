FHIR-31802: Align ProductShelfLife period ModelInfo

Issue request:
FHIR-31802 was Published/Persuasive for BR&R and asked that ProductShelfLife.period use Duration rather than Quantity because only units of time are appropriate. The accepted resolution was to change it to Duration for R5.

Initial application:
Jira records that the change was applied in the R4B branch and main build. Git commits c8e39a4c6f8426ffe58be89e52ae504d69e48a54 and 2e08251c77ea30d06ba75c78146130d88e05f90d changed source/datatypes/productshelflife.xml from Quantity|string to Duration|string and changed the packaged product example from periodQuantity to periodDuration. The current datatype spreadsheet and example still carry that intended change.

Additional context:
ProductShelfLife is active in source/fhir.ini and the old MedicinalProductPackaged artifact now maps to ProductPackagedDefinition. Library is also an active resource, and the Library examples page exposes source/library/library-fhir-model-definition-content.xml as the FHIR ModelInfo file used by CQL tooling. The active ModelInfo and its embedded Library payload still exposed ProductShelfLife.period as FHIR.Quantity. FHIR-28255 later resolved no-change because R5 already fixed the datatype as Duration|string and kept the element name period. FHIR-35961 was an R4B compatibility issue whose ProductShelfLife revert is not an ancestor of the current branch and does not supersede the R5/R6 Duration|string shape.

AutoFHIR reconciliation:
Updated source/library/library-fhir-model-definition-content.xml so ProductShelfLife.period is a choice of FHIR.Duration or FHIR.string, matching the active datatype spreadsheet. Refreshed source/library/library-fhir-model-definition.xml so the embedded Library data matches the XML ModelInfo content. No change was needed to source/datatypes/productshelflife.xml or the PackagedProductDefinition example because they already use Duration|string and periodDuration.

Recommendation:
Keep this commit as-is. It completes the applied FHIR-31802 change across the current build's active FHIR ModelInfo surface while preserving the already-correct datatype and example sources.
