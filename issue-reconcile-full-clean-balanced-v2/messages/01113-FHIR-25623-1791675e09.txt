FHIR-25623: Audit external Provenance date fix

Issue request:
FHIR-25623 was an Applied FHIR-core Security technical correction with a Persuasive resolution. It reported that the ProvenanceParticipantType code system resource had an incorrect future date, specifically the old date value 2023-05-12T00:00:00+10:00, and the recorded resolution was to fix the date.

Initial application:
No commit explicitly mentioning FHIR-25623 was found in the core history. The old core source source/provenance/codesystem-provenance-agent-type.xml did contain the reported future date, but commit 5c0494aacf removed that CodeSystem from the core build during the UTG/THO terminology migration. Later core changes on the same Provenance agent terminology path updated the active participation-role-type value set: aa9defa3c8 switched the include to the THO provenance-agent-type value set, and 760011453b updated the active value set date to 2021-12-06T18:00:00+01:00 as part of FHIR-32519.

Additional context:
A March 2021 Zulip terminology thread for FHIR-25623 records that this was a FHIR-core ticket against vocabulary now managed in terminology and that the UTG process should be used. Security WG minutes in December 2022 list FHIR-25623 under "Vocab - THO managed" and note that agreed changes require the THO process. Current core source has Provenance in build scope, binds Provenance.agent.type through http://hl7.org/fhir/ValueSet/participation-role-type, and that value set delegates the relevant provenance-agent-type content to THO. Historical tools/history release snapshots still show the old R4/R4B date, but those are historical generated artifacts and not the current authoritative source.

AutoFHIR reconciliation:
This commit intentionally makes no core source change and audits the issue as external-repo. The reported CodeSystem is no longer owned by this FHIR core checkout; current THO CodeSystem/provenance-participant-type JSON has active/current dates rather than the original 2023-05-12T00:00:00+10:00 typo, and core already references THO for the relevant value set.

Recommendation:
Keep this external-repo audit commit as-is. No current FHIR core edit is appropriate. If older THO publication versions or backports still need date correction, that follow-up belongs in THO/UTG rather than the core repository.
