FHIR-15610: Audit Condition.evidence clarification

Issue request:
FHIR-15610 was a Published/Persuasive Patient Care change request to update the Condition.evidence definition to "Supporting evidence / manifestations that are the basis of the Condition's verification status, such as evidence that confirmed or refuted the condition." The Jira and originating Zulip thread also record that Patient Care did not want to correlate each individual evidence code or reference with Condition.verificationStatus because that level of relationship was not in the common 80% use case.

Initial application:
No explicit FHIR-15610-tagged commit was found in the current HL7/fhir history. However, the requested wording was present on the published R4 and R5 Condition profiles and in the current source history before commit c71dae0dd9384f14d337a2251452dbdac2f6ea14, so the substance of the seed issue had been applied before this reconciliation. FHIR-11026 later reinforced the same verification-status/refuted-evidence guidance and added the narrative statement that evidence of a refutation can be conveyed in Condition.evidence.

Additional context:
Condition is an active resource in source/fhir.ini, so source/condition/structuredefinition-Condition.xml and source/condition/condition-notes.xml are current build inputs. Later related Patient Care decisions changed the same element: FHIR-32481 converted Condition.evidence to CodeableReference while retaining the evidence examples, and FHIR-42981 intentionally replaced the verification-status-focused short text and definition with broader "supporting evidence for the condition" / "basis for determining the Condition" wording plus causality guidance. FHIR-42981 is already represented on the combined branch by commit 649da8cc5530b17052aea78ac1a8185f3f8df788, so this reconciliation must not publish a duplicate FHIR-42981 audit.

AutoFHIR reconciliation:
This empty audit commit makes no source change. Reinstating the exact FHIR-15610 wording would undo the later FHIR-42981 Patient Care clarification, while the current authoritative source still preserves the seed's important implementer guidance: evidence can support confirmed and refuted conditions, cumulative evidence over time is allowed, and the notes page says the evidence of a refutation can be conveyed in Condition.evidence.

Recommendation:
Keep this no-change audit commit as-is. Do not restore the older verification-status-only definition unless Patient Care reopens the post-FHIR-42981 scope of Condition.evidence; the current broader definition and retained confirmed/refuted guidance are the correct current-spec interpretation of the issue family.
