FHIR-7471: Audit resource classification clarification

Issue request:
FHIR-7471 was a Published/Persuasive with Modification DSTU1 FHIR-core change request for the 2015May clinical summary page. It reported that ProcedureRequest and VisionPrescription appeared under Administrative while MedicationPrescription and DiagnosticOrder appeared under Clinical, making the classification criteria unclear. The accepted resolution was to add clarification to resourceguide.html.

Initial application:
No git commit explicitly mentioning FHIR-7471 or the old core #766 key was found in the bounded history search. The issue appears to have been applied through the August 2015 resource guide work that Jira comments described as ongoing: commit 014e9d175437d999b5090e29b7488198cb5e9263 introduced a resource guide Clinical classification that included ProcedureRequest, VisionPrescription, MedicationPrescription, and DiagnosticOrder, and commits 7524d34dddf437435b8624f9ebf4a180ec80e42f and bb5e3f2a9fcb50aecda21994cda00fdc6981b0c8 overhauled/drafted the resource guide with lifecycle/category tables and a common-concepts table for proposed orders.

Additional context:
The current build-scope source has moved beyond the old DSTU1 page. source/hierarchy.xml includes resourceguide.html and clinicalsummary-module.html in the active page tree. Current source/fhir.ini records DiagnosticOrder as subsumed into ServiceRequest, ProcedureRequest as merged into ServiceRequest, and MedicationPrescription as MedicationRequest. Current publish.ini and StructureDefinition metadata place MedicationRequest in Clinical.Medications, ServiceRequest in Clinical.Care Provision, and VisionPrescription in Clinical.Care Provision. The active Administration module says it covers base data linked into clinical content, while the Clinical module covers core clinical information and points medication and diagnostic material to their dedicated modules. Later FHIR-13042 intentionally removed the old rendered resource-guide classification section and replaced it with pattern links, so restoring or extending the commented historical classification block would not be a current-build correction.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current specification no longer presents the original Administrative-versus-Clinical inconsistency, and the active resource guide/module/category sources already give enough current classification context without duplicating historical taxonomy prose.

Recommendation:
Keep this no-change audit commit as-is. Revisit only if a future work-group decision asks for a new module-taxonomy explanation; no current core source edit is needed for FHIR-7471.
