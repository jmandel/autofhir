FHIR-7908: Audit AllergyIntolerance severity guidance

Issue request:
FHIR-7908 was a Published/Not Persuasive with Modification DSTU1 Patient Care change request asking whether AllergyIntolerance should add a condition-level severity element, and how systems with only one severity-like notion should represent it. The approved resolution did not add AllergyIntolerance.severity; it said systems must decide whether they are capturing criticality or reaction severity, that criticality is the likelihood of significant harm while severity is the degree of reaction manifestation, and that generic reaction characteristics can be represented with the reaction structure without a date.

Initial application:
The issue appears to have been applied in git commit a30496dcda9c86251cf286f1636c23e570a80113, whose subject explicitly includes #7908 and says AllergyIntolerance usage notes were added. That patch added the current criticality usage note to source/allergyintolerance/allergyintolerance-notes.xml, including the approved criticality-versus-severity examples and generic-reaction guidance, while no condition-level AllergyIntolerance.severity element was added.

Additional context:
AllergyIntolerance is an active current-build resource in source/fhir.ini. The current notes still preserve the FHIR-7908 resolution text, and the StructureDefinition keeps AllergyIntolerance.criticality at the resource level while defining severity only on AllergyIntolerance.reaction.severity. Same-change-family FHIR-8146 and later supporting FHIR-12177 are already represented by no-change audit commits on the combined branch. Later FHIR-53608 was retracted/no-change, and FHIR-54013 remains triaged, so neither supplies a final superseding decision for this run. Direct Zulip and Confluence searches for FHIR-7908 found no conflicting final community evidence; a later Patient Care Zulip thread shows ongoing debate but not an applied replacement.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current source already implements the seed decision: it does not add condition-level severity, explains how to distinguish criticality from reaction severity, and tells systems with generic reaction characteristics to use reaction without a date.

Recommendation:
Keep this no-change audit commit as-is for FHIR-7908. Do not add another AllergyIntolerance severity element or duplicate guidance unless Patient Care publishes a later applied or published issue that changes the criticality model or supersedes the current notes.
