FHIR-45741: Audit InventoryItem boundary ownership

Issue request:
FHIR-45741 was Applied with resolution Persuasive with Modification for R6. The Jira asked to fix InventoryItem Boundaries and Relationships because it said InventoryItem could be referenced from ServiceRequest; the final resolution was to remove the Transport and ServiceRequest bullets rather than add an InventoryItem reference to ServiceRequest.

Initial application:
The issue was applied in core by commit b45398f65eca20db749c7cc8dbbbb67ff57bc2a7, which commented out the Transport and ServiceRequest list items in source/inventoryitem/inventoryitem-introduction.xml while InventoryItem was still an active resource in source/fhir.ini. Current ServiceRequest source has no InventoryItem targetProfile, so the resolution path was the InventoryItem narrative update.

Additional context:
The current core build no longer lists InventoryItem as an active resource in source/fhir.ini. A later commit, 3b38b80cf23f9cbb306fab8fcedb293315478c32, removed InventoryItem and related OO resources from the active core resource list, and current module/history pages point readers to the OO incubator IG for InventoryItem. Confluence minutes confirm the OO motion to find the issue persuasive with modification, and no directly relevant Zulip disagreement was found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The visible core source had already removed the two incorrect rendered bullets before InventoryItem left the core build, and editing the now out-of-build InventoryItem source solely to delete HTML comments would not change the current specification.

Recommendation:
Keep this audit commit as-is for FHIR core. If future review needs to verify or clean up the externally maintained InventoryItem artifact, do that in the OO incubator IG; no current core source correction is warranted for FHIR-45741.
