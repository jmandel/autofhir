FHIR-16443: Audit ValueSet expansion parameters

Issue request:
FHIR-16443 was a Published/Persuasive with Modification Vocab change request for STU3 ValueSet.expansion.parameter. It asked to distinguish whether expansion parameters were client input, defaults, profile-derived, or server-supplied, to allow an ExpansionProfile reference when applicable, to require declaration of parameters used for $expand, and to update ValueSet.expansion.parameter.name wording.

Initial application:
The Jira comment cites svn revision 14018, which is git commit 5adcfb34ad276ff5578b95a073504b3dab7d24a8. That commit changed the ValueSet spreadsheet source to the requested expansion.parameter.name definition and added a parameterSource extension plus ExpansionParameterSource code list for ValueSet.expansion.parameter. The broader parameter recording rule had already been applied by related FHIR-15144/FHIR-16337 wording before this commit.

Additional context:
Later final Vocab decisions changed the surrounding model. FHIR-16337 and FHIR-16490 removed ExpansionProfile for R4 and moved its use cases into explicit $expand parameters, so the requested ExpansionProfile-valued extension is no longer appropriate in current core. FHIR-17558 and an existing reconciliation commit removed stale ValueSet ExpansionProfile references. FHIR-41589 and its existing reconciliation commit refined current ValueSet.expansion.parameter guidance to SHOULD record client-used input parameters, server-defaulted input values, and terminology artifacts used, while Confluence minutes confirm the work group intentionally did not strengthen that guidance to SHALL by default. The parameterSource extension and its required ExpansionParameterSource binding now live in the FHIR Extension Pack, not active core ValueSet source.

AutoFHIR reconciliation:
This empty audit commit makes no source change. Current core source/fhir.ini keeps ValueSet active and marks ExpansionProfile as dropped; source/valueset/structuredefinition-ValueSet.xml already has the FHIR-16443 name definition and later FHIR-41589 parameter-recording comment; source/valueset/valueset-notes.xml and the $expand operation definition carry matching current guidance. Re-adding ExpansionProfile-specific core text or changing the current SHOULD guidance would conflict with later final decisions.

Recommendation:
Keep this audit commit as-is. No core source change is needed for FHIR-16443; any future clarification to the migrated valueset-parameterSource extension should be handled in the FHIR Extension Pack under a current extension-pack tracker, not as a core FHIR-16443 fix.
