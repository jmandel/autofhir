FHIR-3976: Audit Condition status and certainty cleanup

Issue request:
FHIR-3976 was a Published/Persuasive with Modification DSTU1 Patient Care issue about overlapping ways to say a Condition did not exist: the then-current certainty value set included known absent/not suspected/known possible/probably present/definitely present concepts that overlapped status values such as provisional, working, confirmed, and refuted. The approved PC WG motion was to rename Condition.status to clinicalStatus and remove the concept of certainty.

Initial application:
The issue appears to have been applied by git commit 1f32e2833bae9fb8cc45636c39142020e353b5c6, whose subject is "#3976 - rename Condition.status to Condition.clinicalStatus" and whose git-svn-id records build@4789, matching the Jira comment. That commit renamed Condition.status references in the then-current Condition spreadsheet, renamed the status search parameter to clinicalstatus, and marked Condition.certainty as removed in the spreadsheet source.

Additional context:
FHIR-5708 and FHIR-5734 are the same early Condition status/certainty family and both point back to #3976; FHIR-5708 already has an AutoFHIR audit commit on the combined branch. Later Published issues FHIR-7581 and FHIR-7864 split the post-rename status model into clinicalStatus and verificationStatus, while FHIR-7617 refined the verification-status values by dropping working. Current source therefore should not be expected to literally preserve the one-element 2015 clinicalStatus proposal, but it should have no Condition.status or Condition.certainty element and should express absence/refutation through the later approved model.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Condition is active in source/fhir.ini, and the active Condition StructureDefinition now defines Condition.clinicalStatus and Condition.verificationStatus with required bindings. Searches of the current Condition source find no Condition.status or Condition.certainty element/path, and the current search parameters target clinical-status and verification-status. Two legacy condition-certainty value-set XML files and OID entries remain in source, but they are not bound from Condition, are not listed as active fhir.ini value sets, and the corresponding CI build value-set pages return 404, so removing them would be an out-of-scope cleanup rather than a necessary current-spec correction for this issue.

Recommendation:
Keep this audit commit as-is. No current core source edit is needed for FHIR-3976; future Condition absence or refutation changes should be handled through the later clinicalStatus/verificationStatus issue family, and any cleanup of unreferenced historical certainty files should be a deliberate terminology/source-hygiene task rather than part of this seed.
