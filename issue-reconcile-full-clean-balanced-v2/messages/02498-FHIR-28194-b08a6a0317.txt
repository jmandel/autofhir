FHIR-28194: Audit PlanDefinition group defaults

Issue request:
FHIR-28194 was a Published/Persuasive CDS change request for FHIR-core PlanDefinition. It asked the PlanDefinition $apply documentation to define the expected processing semantics when an action is a group and no grouping/selection/required/precheck/cardinality behaviors are defined. The accepted resolution clarified that this case behaves like the root action, i.e. process all children using default behavior semantics.

Initial application:
The Jira comments identify commit 45bb40c2bcd7296366a94f36109bb644ff17489d and HL7/fhir#2834. That commit added the PlanDefinition narrative sentence saying that when no behaviors are specified the default behavior for each behavior element is assumed, and added meaningWhenMissing metadata for the behavior elements. PR 2834 merged on 2023-03-13. A later metadata/canonical cleanup commit, 49b86f8a697, reformatted the PlanDefinition StructureDefinition and preserved the same meaningWhenMissing content.

Additional context:
PlanDefinition is active in source/fhir.ini, so source/plandefinition/plandefinition-notes.xml and source/plandefinition/structuredefinition-PlanDefinition.xml are current build inputs. The current narrative states that absent behavior elements imply logical-group, all actions apply and are optional, no action is pre-selected, and all actions are singular. The current StructureDefinition repeats those defaults as meaningWhenMissing for groupingBehavior, selectionBehavior, requiredBehavior, precheckBehavior, and cardinalityBehavior. Jira search for the same PlanDefinition group/no-behaviors topic only returned FHIR-28194; Zulip has a related 2021 implementers thread noting that PlanDefinition $apply action group semantics were unclear, but no conflicting later decision was found. Confluence refs for FHIR-28194 found no pages.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already conveys the Jira resolution through both the rendered PlanDefinition narrative and element-level absence semantics, so an additional edit would be redundant rather than corrective.

Recommendation:
Keep this no-change audit commit. No core source follow-up is needed for FHIR-28194 unless the CDS work group later wants to revisit broader PlanDefinition $apply group processing semantics beyond the no-behaviors default clarified here.
