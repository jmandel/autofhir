FHIR-17075: Audit history entry requirements

Issue request:
FHIR-17075 was a Published/Persuasive FHIR-core Feed issue raised against STU3 asking whether Bundle history entries must contain entry.request and entry.response, and requesting either an invariant or explanatory text. The decisive resolution was to make clear that history Bundles must have entry.response for each entry; the issue comments also note the related need to constrain request.

Initial application:
No commit explicitly tagged FHIR-17075 was found in the relevant Bundle or HTTP source history. The nearby July 2018 GF#14550/FHIR-14550 source commit c613b68 made request mandatory for batch/transaction/history and added Bundle history prose stating that a response element SHALL also be present. That matches Grahame Grieve's FHIR-17075 comment that the requested clarification had already been done for another task.

Additional context:
Bundle is an active current-build resource through source/fhir.ini. Later FHIR-38942 moved the Bundle type entry requirements into invariants, and the current bdl-3b invariant requires every history entry to have both request and response. A later FHIR-7933 reconciliation commit on the combined branch also aligned the HTTP history paragraph with those current requirements, so the current Bundle notes, StructureDefinition invariant, and HTTP interaction text now agree.

AutoFHIR reconciliation:
Published this empty audit commit with no source change. The active source already conveys the FHIR-17075 rule through Bundle history prose, the enforceable bdl-3b invariant, and HTTP history guidance, so adding more text would be redundant and could create future drift.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-17075 unless a separate issue reopens the broader PATCH/history wording family; that concern is outside this seed and does not change the request/response requirement.
