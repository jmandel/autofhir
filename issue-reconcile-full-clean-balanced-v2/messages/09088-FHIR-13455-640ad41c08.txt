FHIR-13455: Audit compartment write guidance

Issue request:
FHIR-13455 was a Published FHIR-core/FHIR-I change request, resolved Persuasive with Modification for STU3, asking whether compartment-style URLs such as POST/PUT [base]/Patient/[id]/Condition were valid. The accepted resolution was to explicitly state that POST/PUT to a compartment is undefined and that servers are not expected to support it.

Initial application:
The request was applied in git-svn commit 5d659690848585f07612bd55190eb52f170a8737, matching Jira's svn revision 13035 comment. That commit added the CompartmentDefinition narrative saying read/write responses for compartment-qualified resource URLs are not defined and that servers are not expected to support read or write to such URLs.

Additional context:
CompartmentDefinition is an active resource in source/fhir.ini, so source/compartmentdefinition/compartmentdefinition-notes.xml is in current build scope. The current source retains the FHIR-13455 guidance, including the POST example and no-expectation statement. Later Applied issue FHIR-51608 also clarified the same page by stating that search is the only RESTful interaction defined on compartment endpoints and that reads, writes, operations, history, and batch/transaction POSTs are not defined through compartment-qualified URLs.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already satisfies FHIR-13455, and the later FHIR-51608 wording reinforces rather than contradicts the original decision. Adding or changing text for FHIR-13455 would be redundant and could create drift between overlapping compartment-interaction paragraphs.

Recommendation:
Keep this no-change audit commit as-is. No core follow-up is needed for FHIR-13455 unless the work group later chooses to consolidate the overlapping FHIR-13455 and FHIR-51608 narrative for editorial maintainability.
