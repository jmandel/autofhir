FHIR-27765: Audit commercial brand extension placement

Issue request:
FHIR-27765 is a Published FHIR-core change request, resolved Persuasive for R5, requesting DeviceDefinition.extension-commercialBrand as a 0..1 string extension with the definition "The overall name of a collection of branded devices that an organization brings to market. It is typically not the same as, although can be derived from, the organization name that owns the name."

Initial application:
Core history shows c68a584f added source/device/structuredefinition-extension-device-commercialBrand.xml, and 47a40324 fixed FHIR-27765 by adding the DeviceDefinition context. The extension was later removed from the core checkout by dd468d4f as part of moving R5 extensions out of core source. The current FHIR Extension Pack contains StructureDefinition-device-commercialBrand with DeviceDefinition context, 0..1 cardinality, string value, and the FHIR-27765 definition.

Additional context:
FHIR-26425 was the original brand-name question and was answered by FHIR-27765. Later OO review in FHIR-47605 limited the extension through R5 and directed R6 use to Device.name.type or DeviceDefinition.deviceName.type; this reconciliation includes a separate FHIR-47605 source commit adding the missing current-core commercial-brand-family name type.

AutoFHIR reconciliation:
This audit commit intentionally makes no seed-specific core source change. Re-adding the R5 extension definition to core would duplicate the Extension Pack artifact and would conflict with the current cross-repository ownership model for FHIR extensions.

Recommendation:
Keep this audit as-is. Maintain the R5 device-commercialBrand extension in the FHIR Extension Pack, and use the FHIR-47605 core vocabulary fix for R6; do not reintroduce a core extension source file for FHIR-27765.
