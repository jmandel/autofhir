FHIR-14280: Audit dynamicValue ordering guidance

Issue request:
FHIR-14280 was a Published/Persuasive STU3 CDS clarification asking that realization documentation state the order for PlanDefinition, ActivityDefinition, and RequestGroup dynamic action processing. The accepted resolution was to clarify that dynamic values are evaluated in the order they appear in the definition resource.

Initial application:
The issue was applied in SVN r13326, imported as git commit 3ceccc7206997be49833ca287fea27ff67aa6c7e, which added order-in-resource wording to ActivityDefinition realization notes and to the PlanDefinition overlap documentation for ActivityDefinition versus PlanDefinition dynamic values.

Additional context:
ActivityDefinition and PlanDefinition are active current-build resources in source/fhir.ini. The older RequestGroup artifact is now represented by RequestOrchestration in the current build, and later RequestOrchestration definitional-action work preserved the same ordered dynamicValue rule. Source refactors from spreadsheets to checked-in StructureDefinition XML retained the ordered dynamicValue comments. Jira, Zulip, and Confluence searches did not reveal a later decision reversing or narrowing this clarification.

AutoFHIR reconciliation:
No source change was made. Current build-scope source already states that ActivityDefinition dynamic values are applied in definition order, that PlanDefinition dynamic values are applied in PlanDefinition order after ActivityDefinition dynamic values, that RequestOrchestration dynamic values are applied in RequestOrchestration order after ActivityDefinition values, and that ActivityDefinition/$apply evaluates dynamicValue elements in resource order.

Recommendation:
Keep this empty audit commit as-is. The current specification conveys the intended rule without additional wording, and adding another restatement would be redundant.
