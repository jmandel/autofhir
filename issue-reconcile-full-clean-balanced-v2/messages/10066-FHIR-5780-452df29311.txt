FHIR-5780: Audit id datatype URI clarification

Issue request:
FHIR-5780 was Published/Persuasive and asked whether the FHIR id datatype definition was inconsistent because uuid is a URN containing colons while the id regex does not allow colons. The final Jira resolution said to add documentation explaining that an id contains only the UUID/OID value portion, not the full URI form.

Initial application:
Jira records the clarification as applied in SVN revision 4608, and git history contains 09b9e817 with the subject '#5780 - improved documentation about id vs uri'. The visible git-svn patch for that revision does not alter the current datatype text, but the requested clarification is present in the active datatype page and was preserved through later datatype refactors.

Additional context:
Related final id decisions refined the same datatype without changing FHIR-5780's core distinction: FHIR-3768 added ISO 18232 context, and FHIR-3750 later made ids case-sensitive, 64 characters, and upper/lower ASCII with lowercase UUIDs. The combined branch already contains 758b63c for FHIR-3750, which aligned the active primitive spreadsheet row with those later rules. FHIR-12889 concerns Element.id being represented as string rather than increasing the id datatype length, so it does not require changing the FHIR-5780 clarification. Direct Zulip and Confluence searches found no FHIR-5780-specific discussion that conflicts with Jira/source history.

AutoFHIR reconciliation:
Made no source change. Current source/datatypes.html explicitly says the last path segment in a FHIR URL is the id datatype and that a full UUID is a uri, not an id. Current source/datatypes/primitives.xml defines id as allowing an unprefixed OID or UUID pattern meeting the id regex, and the obsolete 36-character/case-insensitive wording is absent from active source.

Recommendation:
Keep this no-change audit commit. The current source already communicates the distinction requested by FHIR-5780, and adding more prose would duplicate maintained datatype guidance.
