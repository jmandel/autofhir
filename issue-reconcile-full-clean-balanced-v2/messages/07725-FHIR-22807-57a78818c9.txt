FHIR-22807: Audit CodeSystem lookup allowed types

Issue request:
FHIR-22807 was a Published/Persuasive with Modification FHIR-I correction for the CodeSystem $lookup OperationDefinition. It reported that the narrative listed property.value and property.subproperty.value as a choice of code, Coding, string, integer, boolean, dateTime, and decimal, while the formal operation definition exposed only code. The updated resolution called for the R4 allowed-type extension and an R5 OperationDefinition parameter element for allowed concrete subtypes of an abstract parameter type.

Initial application:
The R5 structural part was applied by 299a6a9e9de2c85b252bb219aaee66da4be7ab2e, which added OperationDefinition.parameter.allowedType, using the final current element name rather than the Jira resolution's draft name of subtype. The lookup operation source carried the R4-style operationdefinition-allowed-type extensions when source/codesystem/operationdefinition-CodeSystem-lookup.xml was introduced in 33b409a4b6d544598262f2f074ebb4b6dc466157.

Additional context:
CodeSystem and OperationDefinition are active resources in source/fhir.ini. Later operation-definition refactoring in 646720401223f784271c0f6c478484a47094dc06 converted the lookup operation's allowed-type extensions to native allowedType elements while preserving the concrete type list for both property.value and property.subproperty.value. FHIR-52921 later clarified how operation parameter profiles align with type and allowedType lists, and community searches found no conflicting Zulip or Confluence record.
