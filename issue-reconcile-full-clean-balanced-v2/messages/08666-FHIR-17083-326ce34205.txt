FHIR-17083: Audit removed Bundle either-or comma wording

Issue request:
FHIR-17083 was Published with a Persuasive, auto-approved, non-substantive technical correction for the 2018-May/STU3 Bundle transaction narrative. It asked to remove the comma from "either a request element, or a resource element" so the phrase would read "either a request element or a resource element".

Initial application:
No current commit was found that explicitly mentions FHIR-17083. The old sentence is visible in earlier Bundle history, and commit c613b68f9b rewrote the transaction/batch narrative on 2018-07-06 for GF#14550, removing the entire either-or sentence before Grahame's 2018-08-02 Jira comment that "text has gone".

Additional context:
Bundle is an active resource in source/fhir.ini, so source/bundle/bundle-notes.xml and source/bundle/structuredefinition-Bundle.xml are current build inputs. Current Bundle notes describe transaction/batch entries without the old either-or sentence, and the authoritative bdl-3c invariant now states that transaction and batch entries contain request elements and resources only for POST, PUT, or PATCH. Jira phrase searches found only FHIR-17083, and Zulip/Confluence searches found no additional or conflicting community discussion.

AutoFHIR reconciliation:
Made no source change. The requested comma-bearing wording is gone from the build-scoped Bundle source, and replacing it with the proposed no-comma phrase would reintroduce obsolete narrative instead of preserving the current rule.

Recommendation:
Keep this no-change audit commit. No follow-up is needed for FHIR-17083 because the requested punctuation issue is already absent from the current specification.
