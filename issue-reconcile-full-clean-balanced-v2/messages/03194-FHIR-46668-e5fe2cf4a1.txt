FHIR-46668: Audit vital signs component support

Issue request:
FHIR-46668 was an Applied/Persuasive with Modification OO change request asking what jurisdictions should do when vital signs such as head circumference or waist circumference do not have components but inherit from the core vital signs profile. The final resolution says the issue was fixed by the Vital Signs Base Profile and by removing MustSupport from .component.

Initial application:
No prior git commit explicitly mentions FHIR-46668. The relevant application was already present through the vital signs profile family work: FHIR-46418 renamed and clarified the base profile as the Vital Signs Base Profile, and FHIR-47136 removed MustSupport from Observation.component in the Vital Signs Base Profile while retaining the blood-pressure-specific component requirements.

Additional context:
The current Observation folder is active in source/fhir.ini, and implementationguide-Observation-vitalsigns.xml marks the vital signs IG as core and includes StructureDefinition/vitalsigns. The current base profile allows vital signs with either value[x], component, hasMember, or dataAbsentReason and does not mark Observation.component MustSupport. The blood pressure profile still marks its component slices MustSupport, matching the September 2025 OO WGM note that the component is no longer MustSupport in the base but remains MustSupport for blood pressure. FHIR-30934 remains background for the broader vital signs MustSupport semantics but does not require an additional source edit for this issue.

AutoFHIR reconciliation:
This commit intentionally makes no source changes. The current build-scope source already reflects the applied resolution for FHIR-46668: jurisdictional single-value vital signs can inherit from the base vital signs profile without inheriting a MustSupport requirement on Observation.component, while blood pressure retains the component requirements where they are semantically needed.

Recommendation:
Keep this audit commit as-is. No core source change is needed for FHIR-46668 unless a future work group decision changes the vital signs hierarchy or creates separate single-value/multi-value vital signs profiles.
