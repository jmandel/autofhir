FHIR-40741: Audit codesystem-use-markdown external update

Issue request:
FHIR-40741 was Applied/Persuasive with Modification for FHIR-core CodeSystem. It asked whether the codesystem-use-markdown extension definition should say concept definitions "should" rather than "can" be rendered as markdown; the approved resolution was to deprecate the extension and change the text from "can be treated" to "should be treated".

Initial application:
No current HL7/fhir commit directly mentions FHIR-40741, and the CodeSystem extension StructureDefinitions were removed from the core source before this issue by dd468d4f17. The application occurred in HL7/fhir-extensions: 2d8d674 changed the codesystem-use-markdown description, short, and definition to "should" wording and added deprecated status, and later extension-pack commits added a deprecation reason, retired status, and corrected the owning work group.

Additional context:
Current HL7/fhir source still contains CodeSystem instances that use the extension, plus the OID/history record, but it no longer contains the StructureDefinition text that FHIR-40741 requested to change. The 2024-03-25 Terminology Infrastructure minutes link to the Extension Pack page and record the decision to deprecate the extension. A later FHIR-extensions issue, FHIR-51040, asks to undeprecate based on an NPU terminology use case, but it remains Submitted/Unresolved and does not supersede the Applied FHIR-40741 decision.

AutoFHIR reconciliation:
This audit commit intentionally makes no HL7/fhir source change. The issue's actionable source is in the FHIR Extension Pack, where the current StructureDefinition already has standards-status deprecated with a reason, resource status retired, and both description and differential definition using "should be treated" wording.

Recommendation:
Keep this audit as-is for HL7/fhir. If FHIR-51040 or another future work-group decision changes the deprecation outcome, apply that follow-up in HL7/fhir-extensions rather than in the core FHIR source checkout.
