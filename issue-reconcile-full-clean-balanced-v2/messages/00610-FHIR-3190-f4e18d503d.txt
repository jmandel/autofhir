FHIR-3190: Audit search number URL encoding wording

Issue request:
FHIR-3190 was a Published/Persuasive FHIR-core search issue asking that the number search parameter page stop saying that "=" must be "escaped"; the reporter clarified that URL percent-encoding, if mentioned at all, should be called URL encoding and not FHIR search escaping.

Initial application:
The Jira comments record svn revision 3073. In git, commit 568cbc1cc3 changed the DSTU search.html number section from "= must be escaped" to "= must be URL-encoded", matching the published correction.

Additional context:
Later search-parameter prefix work in commit 9c1436dab4 moved ordered search comparisons to textual prefixes such as lt, le, gt, ge, and ne, removing the need for the old symbolic comparison examples in the number section. The current source/search.html number section now shows textual prefix examples and contains no statement that "=" must be escaped. A newer URL-Encoding note explains that examples are shown unencoded; remaining references to URL escaping/escaped characters concern general percent-encoding for URL characters such as the vertical pipe, not the erroneous number-parameter "=" sentence from this issue.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build-scoped search page already avoids the misleading "=" escaped wording, and further edits would be editorial cleanup outside the necessary scope of FHIR-3190.

Recommendation:
Keep this no-change audit as-is. Revisit only if the work group opens a broader issue to standardize terminology such as "URL escaping" versus "URL encoding" throughout the search page.
