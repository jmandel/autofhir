FHIR-8606: Audit slicing clarification superseded by later wording

Issue request:
FHIR-8606 was Published/Persuasive for the FHIR-core profiling page and asked to clarify that slicing was not limited to repeating element lists, specifically noting 0..1 or polymorphic elements with alternative constraints.

Initial application:
The issue was applied by git commit 320e08d887d55dafdb49caef913bc62bfc1e22bf, "#8606 - clarify about slicing elements that don't repeat but have multiple types", whose git-svn id records svn revision 6600 matching the Jira comment. That commit added a sentence saying the technique could also be used on non-repeating elements with a choice of data types and added an @type discriminator rule.

Additional context:
The discriminator model was later reworked by commit 3253654af7787e9b738b15f4618a2b9d02d56f7f to use discriminator types and FHIRPath paths, including Observation.value[x] with type/$this. FHIR-17046 was a later Published/Persuasive FHIR-I decision that removed the broad sentence introduced by FHIR-8606 as spurious; that related issue is already represented on the combined branch. The current build source still includes profiling.html through source/hierarchy.xml and documentation links, and no relevant Zulip or Confluence record was found that changes this source-history conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding the removed sentence would conflict with the later FHIR-17046 decision, while the current profiling page still explains type-choice slicing through the allowed ofType() FHIRPath function, the type discriminator description, and the Observation.value[x] example.

Recommendation:
Keep this no-change audit commit as-is. No current FHIR source edit is needed for FHIR-8606 unless the work group makes a new decision to rewrite the slicing introduction more broadly than the later FHIR-17046 correction allows.
