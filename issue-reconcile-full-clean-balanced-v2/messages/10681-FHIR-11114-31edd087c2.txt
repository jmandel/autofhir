FHIR-11114: Audit Observation category hierarchy wording removal

Issue request:
FHIR-11114 was Published/Persuasive for FHIR-core Observation and asked to remove the Observation.category sentence "More fine-grained filtering can be performed using the metadata and/or terminology hierarchy in Observation.code." The resolution said to remove the sentence because it was a general filtering principle that did not need to be stated there.

Initial application:
The issue was applied in historical commit 135effcdc18c5860253e8fc6df7197732441fe74, which removed that exact sentence from the then-authoritative Observation spreadsheet sources. The current source no longer uses those spreadsheet files for the built resource definition, but the built Observation StructureDefinition carries forward the sentence removal.

Additional context:
Observation is an active current-build resource in source/fhir.ini. The current Observation.category comment still explains category granularity and multiple categorization schemes but does not instruct consumers to use Observation.code metadata or terminology hierarchy for category-level filtering. The same 2016 neighborhood included FHIR-11113, which clarified category as a search/indexing categorization element, and later FHIR-50850 added separate guidance on category vs. code without reintroducing the removed hierarchy-filtering sentence. A relevant Zulip discussion likewise notes there is no guarantee that Observation.category can be inferred from Observation.code.

AutoFHIR reconciliation:
No source change was made. The current active Observation source already implements FHIR-11114, and adding or removing other category/code guidance would go beyond the Jira request.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-11114 in the core source unless a future work-group decision changes the current category/code guidance.
