FHIR-8542: Correct extension value example paths

Issue request:
FHIR-8542 was a Published/Persuasive FHIR-core change request for the extensibility examples. It reported that an extension definition example used ElementDefinition.path "Extension.value", which did not resolve to an actual extension value path, and asked for the example to use "Extension.value[x]"; the Jira comments accepted a typed "Extension.valueUri" correction for the originally cited DSTU1 snippet.

Initial application:
The issue was initially applied by SVN revision 6255, imported as git commit 9cfcc419fbf519d5ee3dc909563eb9de8b479d54, which changed one Patient Consent example path from "Extension.value" to "Extension.valueUri". The same active extensibility examples page still retained a bare "Extension.value" in the Patient Name Parts example, and the page mixed the historical typed suffix form with current examples that already use "Extension.value[x]".

Additional context:
source/hierarchy.xml includes extensibility-examples.html under the active Extensibility page, so source/extensibility-examples.html feeds the current build. Current ElementDefinition.path guidance says polymorphic element paths end in "[x]", and a 2024 implementer Zulip thread about these exact examples concluded that "Extension.value[x]" is best and "Extension.value" is wrong. Recent related AutoFHIR commits on the combined branch already addressed extension example URL/cardinality defects for FHIR-34212 and FHIR-18375, but not this value path issue.

AutoFHIR reconciliation:
This commit updates the Patient Consent and Patient Name Parts XML and JSON StructureDefinition snippets on source/extensibility-examples.html to use "Extension.value[x]" for extension value ElementDefinition.path entries, while leaving the existing type codes and cardinality corrections intact.

Recommendation:
Keep this source fix. It aligns the active examples with current ElementDefinition.path guidance and removes the confusing stale path forms without reopening adjacent cardinality or URL decisions already represented by related issue-reconcile commits.
