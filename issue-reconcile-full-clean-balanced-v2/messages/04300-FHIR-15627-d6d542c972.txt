FHIR-15627: Audit HealthcareService eligibility structure

Issue request:
FHIR-15627 was Applied/Persuasive with Modification for PA. It asked to change HealthcareService.eligibility so eligibility requirements could be represented programmatically across multiple data types and resources, using a BackboneElement to store screening criteria. The final resolution says this functionality was updated by FHIR-41782 and made consistent with Group member selection via group.characteristic.

Initial application:
The application was not a standalone FHIR-15627-only edit. Commit a2b02dee29 explicitly named FHIR-15627 together with FHIR-41782 and FHIR-39306, and expanded HealthcareService.eligibility from code/comment into a BackboneElement with code, value[x], comment, period, and an invariant requiring a code when a value is used. Follow-up HealthcareService commits added the missed eligibility ValueSet binding, attached invariant conditions, corrected eligibility.period to Period, and corrected the specialist-referral-required sample-code spelling.

Additional context:
FHIR-41782 is Applied/Persuasive and records the detailed approved shape for HealthcareService.eligibility, including the value[x] data types and the alignment with Group characteristics. PA September 2023 WGM minutes record that FHIR-15627's request was already met by the FHIR-41782 changes and passed 4-0-0. HealthcareService is an active approved resource in source/fhir.ini, and the current source contains the structured eligibility elements, eligibility example CodeSystem/ValueSet, and referralRequired cross-reference. Zulip searches for directly conflicting HealthcareService eligibility discussion found no relevant hits.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope HealthcareService source already implements the approved eligibility structure that the work group identified as satisfying FHIR-15627, and adding more prose or duplicate modeling would not change implementer understanding.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed for FHIR-15627 unless PA later decides to revisit the richer logical eligibility criteria model beyond the already-applied FHIR-41782 structure.
