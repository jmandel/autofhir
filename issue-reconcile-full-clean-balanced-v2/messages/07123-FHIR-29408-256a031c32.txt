FHIR-29408: Audit contained container reference invariants

Issue request:
FHIR-29408 was Published/Persuasive for FHIR-core DomainResource after being raised against R4. It reported that dom-3 did not handle a contained resource pointing back to its containing resource and proposed allowing the contained-container case with the local-reference expression branch `reference='#' and %rootResource!=%resource`.

Initial application:
No source commit explicitly tagged FHIR-29408 was found. The Jira comment says the issue was dealt with in a previous technical correction, and the surrounding history confirms the rule was already present through related contained-resource corrections: FHIR-13187 changed dom-3 to allow a contained resource to refer to its containing resource, while the later FHIR-31732 ref-1 correction applied the exact `%rootResource!=%resource` local-reference branch now present in the Reference datatype source.

Additional context:
DomainResource is active in source/fhir.ini, and Reference is an active datatype. The current DomainResource dom-3 human text and expression allow a contained resource either to be referenced from elsewhere in the container or to contain a `#` reference back to the container. The current Reference ref-1 invariant also contains the proposed `reference='#' and %rootResource!=%resource` allowance. Later FHIR-43690 only optimized the dom-3 expression and preserved the container-reference branch, and FHIR-41692 was retracted after the reporter recognized that the correct way for a contained resource to reference its container is `#`. Bounded Zulip and Confluence searches found supporting discussion and FHIR-I minutes for the related ref-1 correction, but no conflicting later decision.

Made no source change. The current authoritative source already satisfies FHIR-29408 through the active DomainResource dom-3 constraint and the active Reference ref-1 local-reference invariant.
