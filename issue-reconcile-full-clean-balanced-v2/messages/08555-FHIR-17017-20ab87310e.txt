FHIR-17017: Audit BackboneElement definition clarification

Issue request:
FHIR-17017 was a Published/Persuasive FHIR-core change request from the STU3 ballot asking that the BackboneElement definition no longer imply all resource-defined elements use BackboneElement. The requested clarification was that BackboneElement applies to resource-specific complex child structures that do not use a FHIR datatype.

Initial application:
The Jira comment records SVN revision 14310. In the git history this is commit 060f9d125f3ba9c7ccb5b28a15f2e0e17092d4fc, which changed source/backboneelement.html from the broad "elements defined as part of a resource definition" wording to "complex elements defined as part of a resource definition" with an explicit note that datatype elements do not use the type.

Additional context:
The old standalone backboneelement.html page was later folded into the current active type framework by cbdf7d1e55dc4bfa1dc30fc526edee0491e05782. The active build configuration still lists BackboneElement as an abstract infrastructure type, maps backboneelement to the types page, and marks BackboneElement normative. The current source/types.html text preserves the issue's distinction, while the BackboneElement spreadsheet definition also excludes elements in datatypes. Adjacent Jira issues FHIR-17016 and FHIR-16320 concerned the same page family, but they were already handled by adjacent historical commits and do not require a separate decision here.

AutoFHIR reconciliation:
No source change was made. The current source already conveys the requested rule: BackboneElement is for complex elements defined as part of a resource definition, while datatype elements do not use this type.

Recommendation:
Keep this audit commit as-is. Further edits would be redundant unless a future work group decision changes the BackboneElement/DataType boundary or the generated StructureDefinition prose needs a separate wording refresh.
