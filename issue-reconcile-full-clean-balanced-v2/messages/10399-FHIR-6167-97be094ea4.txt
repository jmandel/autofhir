FHIR-6167: Audit unsupported conditional operation guidance

Issue request:
FHIR-6167 was a Published/Persuasive FHIR-core HTTP clarification asking what response or status code applies when a server does not support conditional read, conditional create, conditional update, or conditional delete.

Initial application:
The issue was applied in SVN revision 6528, represented in git as cb2f6c7b06ef82861ea7f57acdb745767e9d00a6, which explicitly references #6167 and added unsupported-conditional-operation response guidance to source/http.html. The original application answered conditional update and delete with HTTP 400 plus OperationOutcome guidance, and answered conditional create with HTTP 412; later conformance cleanup standardized the unsupported conditional create/update/delete wording to SHOULD return HTTP 400 and MAY include OperationOutcome.

Additional context:
source/http.html is the active RESTful API source page, linked from source/documentation.html. The current source says unsupported conditional read returns the full content, and the conditional update, delete, and create sections each state that servers not supporting that conditional interaction SHOULD return HTTP 400 and MAY include an OperationOutcome. Related already-published reconcile commits for FHIR-7926, FHIR-7927, and FHIR-7928 confirmed and corrected the optionality notes for conditional update/delete/create; FHIR-16448 and FHIR-17256 later adjusted conditional-operation maturity and conditional patch behavior without changing FHIR-6167's unsupported-response guidance.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already provides the requested clarification, including the later standardized 400/OperationOutcome wording and the no-error full-content behavior for unsupported conditional read.

Recommendation:
Keep this no-change audit. No further core source work is needed for FHIR-6167 unless the work group wants to revisit the broader HTTP 400 versus 405 policy for unsupported interactions in a new issue.
