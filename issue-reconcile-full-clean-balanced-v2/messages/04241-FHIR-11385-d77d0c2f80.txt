FHIR-11385: Audit eligibility insurance grouping

Issue request:
FHIR-11385 was a Published/Persuasive Financial Management change request for DSTU2 EligibilityResponse asking to put Contract and BenefitBalance together under an insurance or similar subclass so that multiple insurance coverages could be reflected back to the requestor.

Initial application:
No current git commit found by this reconciliation explicitly mentions FHIR-11385. Historical source inspection found the substantive application in commit 040158b3, which introduced a repeating EligibilityResponse.insurance backbone, added insurance.coverage and insurance.contract, moved benefitBalance under insurance, and updated an example to wrap the benefit details in insurance.

Additional context:
The current build uses CoverageEligibilityResponse as the active successor to EligibilityResponse, with source/fhir.ini mapping CoverageEligibilityResponse to the old EligibilityResponse name. The active StructureDefinition now has repeating CoverageEligibilityResponse.insurance entries that each reference one Coverage and contain benefit items/balances under insurance.item.benefit. A later Published/Persuasive issue, FHIR-17963, intentionally removed the direct EligibilityResponse.insurance.contract child because contract details are already represented by Coverage.contract; that related issue is already represented on the combined branch by commit eb3a0d6b9bb2998f686552f91fedf5691cc49800.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The active current specification already preserves the FHIR-11385 grouping through CoverageEligibilityResponse.insurance, CoverageEligibilityResponse.insurance.coverage, CoverageEligibilityResponse.insurance.item, and CoverageEligibilityResponse.insurance.item.benefit, while Contract remains available through the referenced Coverage. Re-adding a direct CoverageEligibilityResponse.insurance.contract element would conflict with the later FHIR-17963 decision and duplicate Coverage.contract.

Recommendation:
Keep this no-change audit as-is. Do not edit the retired source/eligibilityresponse files or reintroduce a direct insurance.contract child unless the Financial Management work group reverses FHIR-17963.
