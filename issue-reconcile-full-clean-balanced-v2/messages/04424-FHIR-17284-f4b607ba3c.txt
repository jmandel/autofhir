FHIR-17284: Audit extensible alternate concept wording

Issue request:
FHIR-17284 was Published/Persuasive with Modification for STU3 and asked the FHIR-core terminologies page to stop saying an extensible binding could use an alternate system.code when the value set did not cover the concept. The accepted wording was that an alternate concept, either a system/code pair or text, may be used instead.

Initial application:
The Jira comment points to GH#03f12f1f1f, and commit 03f12f1f1f changed source/terminologies.html from the old alternate system.code sentence to the requested alternate concept wording. Commit 5f9b6eca5d for FHIR-14865 then moved the wording into the detailed extensible-binding section while preserving the alternate concept rule and adding hierarchy guidance.

Additional context:
The current build-scope terminologies page still contains the resolved rule: if there is no applicable concept in the value set, an alternate concept, including a system/code pair, system/version/code triplet, or text, may be used instead. Later FHIR-29968 and its existing combined-branch reconciliation aligned the broader Extensible usage notes and the machine-readable binding-strength CodeSystem definition. FHIR-48479 later added a summary table whose Extensible row uses the older but compatible phrase "alternate codings (or, data type allowing, text)"; because that row links to the detailed Extensible section and does not reintroduce the rejected system.code-only wording, it does not require another source edit for FHIR-17284.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The old system.code-only text is absent from current source, the detailed Extensible Binding Strength guidance carries the accepted alternate concept/text semantics, and the formal binding-strength CodeSystem has already been reconciled through FHIR-29968.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-17284 unless the work group separately decides to reword the summary table for consistency; that would be editorial cleanup under a different issue rather than a missing application of this published STU3 change.
