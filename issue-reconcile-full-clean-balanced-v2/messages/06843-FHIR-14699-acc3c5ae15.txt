FHIR-14699: Audit ValueSet operation parameter wording

Issue request:
FHIR-14699 was Published with resolution Persuasive with Modification for the STU3 ValueSet $validate-code operation wording. The issue requested replacing the nonexistent in parameter "constraint" with url, context, or valueSet, and the resolution also required the code input wording to say exactly one of code, coding, or codeableConcept must be provided.

Initial application:
The issue was pre-applied before final Jira publication. Git history shows git-svn commit d90f55e1cbc897c77c5188342e1d43353f38f2c3, corresponding to SVN build@13351, included GF#14699 and changed the old ValueSet spreadsheet $validate-code description from "constraint"/"valueset" to "url, context or valueSet" and from parenthesized code inputs to "code, coding, or codeableConcept". Later source rework moved the carried-forward operation text into source/valueset/operationdefinition-ValueSet-validate-code.xml, and FHIR-33941 later normalized spacing while preserving the FHIR-14699 wording.

Additional context:
source/fhir.ini actively lists valueset=ValueSet under [resources], so source/valueset operation definitions are in the current build. The adjacent ValueSet $expand operation contains the same corrected url/context/valueSet wording, reflecting the same 2018 terminology block-vote family, but this commit audits only FHIR-14699. Searches of Zulip and Confluence found no directly conflicting community discussion; a Vocabulary block-vote page lists tracker 14699 as Persuasive with Modification and pre-applied.

AutoFHIR reconciliation:
No source files were changed. The current source/valueset/operationdefinition-ValueSet-validate-code.xml description already says that url, context or valueSet must be provided when not called at instance level, and that one and only one of code, coding, or codeableConcept must be provided. A source search found no remaining bad "constraint"/"valueset" wording in the relevant ValueSet operation sources.

Recommendation:
Keep this empty no-change audit commit as-is. No core FHIR follow-up is needed for FHIR-14699 unless a future ballot intentionally revisits $validate-code input parameter requirements.
