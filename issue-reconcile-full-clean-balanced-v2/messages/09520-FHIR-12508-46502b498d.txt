FHIR-12508: Audit resource example wording generator

Issue request:
FHIR-12508 is Published/Persuasive and asked to change generated Sequence example narrative from saying an example conforms to the "profile Sequence" to saying it conforms to the "resource Sequence", because Sequence was a resource rather than a profile.

Initial application:
The Jira record says the issue was applied with a short GH#1caaa7803c reference, but that abbreviated hash is not present in this checkout or GitHub's current HL7/fhir commit API. Current source no longer contains a literal Sequence example page; it contains a shared resource-example template that delegates the conformance sentence to a publisher macro. Current CI and published example pages still show the "profile <Resource>" wording, so no durable core-source application is visible.

Additional context:
Zulip discussion expanded the finding from Sequence to all resource examples, and Grahame Grieve directed the task to FHIR publishing because individual committees do not control that generated language. The FHIR checkout's Gradle build depends on the external org.hl7.fhir:kindling publisher, and the current kindling source expands <%example.profile.link%> by hard-coding "profile " before the StructureDefinition name. Sequence itself is listed only under [removed-resources] in current source/fhir.ini, so the remaining live problem is the shared generated wording for current resource examples such as Patient and Observation.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR source change. Editing the FHIR template to remove the macro would be an overbroad workaround that would lose conformance context without fixing the generator. The source of the current incorrect wording is in the external HL7/kindling PageProcessor.genExampleProfileLink implementation, so this is recorded as external-repo.

Recommendation:
Keep this audit commit as-is for the core repository. Follow up in HL7/kindling by changing the example profile-link generator to render resource examples as "resource <Name>" when the linked StructureDefinition is the base resource, preserving "profile" only for true constrained-profile examples; then update the FHIR build dependency and rebuild generated pages.
