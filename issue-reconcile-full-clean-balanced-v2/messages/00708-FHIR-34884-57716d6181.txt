Issue request:
Published/Persuasive with Modification security issue FHIR-34884 requested that Permission.asserter stop allowing Person because Person is only for shared demographics and actors should instead be Patient, Practitioner, RelatedPerson, PractitionerRole, Organization, or CareTeam.

Initial application:
No commit explicitly mentions FHIR-34884. Git history shows commit 2c7d674ebe5bfdd04b2239cbb6d5990931b20aad changed source/permission/structuredefinition-Permission.xml on 2022-02-28 from Reference(Person) to a multi-target Reference that removed Person and added Practitioner, PractitionerRole, Organization, CareTeam, Patient, Device, and RelatedPerson. Later source iterations kept Person absent.

Additional context:
Later security work added HealthcareService and briefly Group/DeviceDefinition to Permission agent references under FHIR-49672/FHIR-49304, then FHIR-51482 removed a duplicate Group target. Current core source no longer contains source/permission or any active Permission entry in source/fhir.ini because commit 0e2a8a7f839d5e1a43787523daccf07d958362f3 removed the core Permission resource and changed the Security and Privacy module to link to the Data Access Policies IG Permission definition. A bounded check of the current HL7/data-access-policies source shows its Permission.asserter target list also excludes Person.

This is an empty audit commit. No core source change is needed: the original R5 source change removed Person, and the current core build no longer owns the Permission resource.

Recommendation:
Keep this audit commit as-is. If Permission is reviewed in the Data Access Policies IG, preserve the current exclusion of Person there; no FHIR core follow-up is needed for FHIR-34884.
