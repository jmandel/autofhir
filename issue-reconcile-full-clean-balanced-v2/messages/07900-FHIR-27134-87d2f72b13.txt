FHIR-27134: Audit extension SearchParameter indexing guidance

Issue request:
FHIR-27134 is a Published FHIR-core/FHIR-I change request, resolved Persuasive with Modification for R5, asking searchparameter.html#srch to stop describing extension search parameters in XPath terms, encourage FHIRPath expressions that select the extension value with .value, reject type assertions against the Extension node itself, allow servers to attempt legacy expressions that only select the Extension, and review core extension SearchParameter definitions such as mothersMaidenName.

Initial application:
The request was applied in HL7/fhir commit 177a10ad8a6241a1eb93396928e4337423f9788e, which rewrote source/searchparameter/searchparameter-notes.xml around the SearchParameters on Extensions section and added .value to extension SearchParameter expressions, including the then-core mothersMaidenName search parameter. Later source refactors kept the section in the active SearchParameter resource notes and moved standard extension SearchParameters such as mothersMaidenName to the FHIR Extension Pack.

Additional context:
source/fhir.ini actively lists searchparameter=SearchParameter, so source/searchparameter/searchparameter-notes.xml is current build input. The current section uses FHIRPath examples ending in .value, says servers MAY try expressions that select only the extension but need not support them, and explains that casting the Extension directly leads to an empty index. A current scan found active core extension SearchParameter expressions either select .value or use an extension only as an exists() marker before indexing a different value. The mothersMaidenName SearchParameter now lives in the FHIR Extension Pack with an expression ending in .value. Related audit commits for FHIR-20462, FHIR-33012, FHIR-38080, and FHIR-51587 are already represented on the combined branch and do not require duplicate decisions here.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current FHIR source and moved extension-pack source already implement the Published FHIR-27134 decision without a semantic gap in the current build.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-27134 unless a future policy change decides to remove support for legacy extension-only expressions rather than merely discouraging them.
