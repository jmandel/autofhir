FHIR-25424: Audit CodeableConcept required-binding validation

Issue request:
FHIR-25424 was a Published/Persuasive FHIR-core technical correction raised against R4 terminologies: the validator rejected a CodeableConcept with multiple Codings even though one Coding was from the required value set. The requested outcome was that such CodeableConcept instances pass because required binding only requires one Coding value from the specified value set.

Initial application:
No HL7/fhir commit mentioning FHIR-25424 was found. The normative terminology wording the issue relies on was already present before the issue: commit bd75ca84005d97a15b506fab3de25925bed9cf02, #9672, split the CodeableConcept required-binding rules into bullets in 2016 and stated that one Coding value SHALL be from the specified value set. The only later nearby Jira-tagged source history found was editorial terminology wording such as FHIR-25431.

Additional context:
The current build-scope source page source/terminologies.html remains consistent with the Jira expectation: for required bindings on CodeableConcept, at least one Coding must be present and one Coding value SHALL be from the specified value set. The FHIR-I 2020-01-13 minutes explicitly classify FHIR-25424 as a validator problem and core-tooling technical correction, and the referenced Zulip thread records Grahame saying it was fixed in the next validator release. No validator implementation source is present in this HL7/fhir source checkout.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current specification source already conveys the required-binding rule correctly, and the issue's actual application belongs to external validator/tooling behavior rather than this spec source tree.

Recommendation:
Keep this audit commit as-is. No HL7/fhir source follow-up is needed for FHIR-25424 unless a future validator/tooling repository audit shows the same bug remains in current validator code.
