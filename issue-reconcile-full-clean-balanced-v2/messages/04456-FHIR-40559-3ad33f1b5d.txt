FHIR-40559: Audit Specimen container location search

Issue request:
FHIR-40559 was an Applied OO change request asking Specimen to support container location search. Its Persuasive with Modification resolution removed the direct Specimen.container.location element, added a search parameter "organization" returning the first organization in the device hierarchy, and added a search parameter "container-location" returning the device container location.

Initial application:
The issue was first applied in Specimen source history by 777ac658, then merged by PR #3018 as 7d6b4fc. That implementation removed Specimen.container.location from source/specimen/structuredefinition-Specimen.xml, added a FiveWs.where mapping exception, and added Specimen organization/location search parameters; follow-up commit 38074c13 renamed the location search parameter to container-location to match the Jira resolution.

Additional context:
Later Applied OO issues superseded the two search-parameter parts of FHIR-40559. FHIR-51907 removed the Specimen organization search parameter because it would not return Specimen resources and should instead be handled with chained search. FHIR-51580 then removed container-location and other Specimen search parameters that required cross-resource resolve() evaluation. Current source still represents the location information through Specimen.container.device[x] referencing Device, and Device.location remains available for the container device itself.

AutoFHIR reconciliation:
This is an empty no-change audit commit. The current source is correct after the later applied decisions: Specimen.container.location remains removed, Specimen's active search-parameter bundle no longer contains organization or container-location, and re-adding either search parameter would conflict with FHIR-51907 and FHIR-51580.

Recommendation:
Keep this audit as-is. Do not re-add Specimen organization or container-location search parameters unless OO approves a new search design that avoids the cross-resource resolve() concerns and is consistent with the DeviceAssociation-based owner model.
