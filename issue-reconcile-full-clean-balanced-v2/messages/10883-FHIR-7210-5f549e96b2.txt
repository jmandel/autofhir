FHIR-7210: Audit Observation f002 example corrections

Issue request:
FHIR-7210 was a Published/Persuasive OO change request from the 2015May ballot for FHIR-core Observation. It reported generated narrative errors for observation-example-f002-excess: the numeric base-excess result used the A / abnormal interpretation whose description said it applied to non-numeric results, the example included an injection-related detail, and the narrative showed lower-case display units beside UCUM codes and reference-range quantities. The final resolution was to fix the example as a duplicate of FHIR-7237.

Initial application:
The correction was applied before this reconciliation. Commit 474be19befc8b8882da2b23a826dd0e2106a1538 explicitly listed 7210 and 7237 in its message, changed the f002 interpretation from A / "Abnormal (applies to non-numeric results)" to H / "Above high normal", and removed the injection/body-site content from source/observation/observation-example-f002-excess.xml. Later source maintenance changed the interpretation display to "High" and moved the coding system to the current v3 ObservationInterpretation URL without reintroducing the reported error.

Additional context:
Observation is an active resource in source/fhir.ini, and source/observation/list-Observation-examples.xml plus source/observation/observation-examples-header.xml still include observation-example-f002-excess as the Base Excess example. The paired FHIR-7237 issue is the same correction family; its resolution explains that Quantity.unit may preserve a local display such as mmol/l while Quantity.code carries the standard UCUM form mmol/L. The current source intentionally retains that local-display-versus-UCUM-code distinction for the value and reference range. FHIR-7237 is already represented on the combined branch by commit 10912e2519d44e7452915e306b381538ee01bc16, so this seed needs its own audit commit only.

AutoFHIR reconciliation:
No source change was made. The current build source already uses interpretation H / High for the numeric result, has no injection/body-site detail in the example, and represents the local display unit and standard UCUM code separately for the value and reference range.

Recommendation:
Keep this no-change audit commit as-is. Do not normalize the display unit to mmol/L for this issue unless the work group makes a new decision, because the duplicate issue's published resolution explicitly preserves the two Quantity representations.
