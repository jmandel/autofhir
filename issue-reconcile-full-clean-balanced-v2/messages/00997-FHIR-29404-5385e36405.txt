FHIR-29404: Audit ImagingStudy size guidance

Issue request:
FHIR-29404 was a Published/Persuasive with Modification FHIR-core ImagingStudy change request raised for R4 and applied for R5. It reported that modeling a whole DICOM study with nested series and instances could create very large ImagingStudy resources, repeated update traffic, version proliferation, and resource contention. The approved resolution was to add Elliot Silver's Size Considerations implementation-note text.

Initial application:
The Jira-requested Size Considerations subsection was initially applied by commit 85e4eb3cd4068c62efe4ba7cf866e1e15aa0294e on 2021-04-05. That commit added the heading plus paragraphs about DICOM study size, _summary/_count query mitigation, repeated instance-level updates/resource contention, and referenced-instance retrieval size. A later mixed ImagingStudy commit b650c1dd54d447dcbc8aa5fbbab7cacf81972898 mentioned FHIR-29404 but changed accession/status-related material rather than the Size Considerations guidance.

Additional context:
source/fhir.ini actively lists imagingstudy=ImagingStudy, so source/imagingstudy/imagingstudy-notes.xml is in current build scope. The current notes still contain the Size Considerations heading and the core size/query guidance. The current text no longer contains the original repeated-update/resource-contention paragraph because later Applied issue FHIR-47630, also on ImagingStudy Notes, explicitly removed that paragraph in its resolution after asking what message it conveyed, and replaced the final retrieval guidance with examples for reducing transfer time. That later issue is already represented on the combined branch by 620b0c32d699a5574bd239b31703ecf7ae3d6b45.

AutoFHIR reconciliation:

Restoring the literal 2021 resource-contention paragraph would conflict with the later FHIR-47630 Applied resolution, while the remaining current Size Considerations text still tells implementers that large DICOM studies create large ImagingStudy resources and points to query/retrieval mechanisms to manage size.
