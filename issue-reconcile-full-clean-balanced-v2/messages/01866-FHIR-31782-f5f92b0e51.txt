FHIR-31782: Audit administrable product link direction

Issue request:
FHIR-31782 was a Published FHIR-core BR&R change request resolved as Persuasive for R5. It reported an impermissible bidirectional relationship between MedicinalProductDefinition and AdministrableProductDefinition / the former MedicinalProductPharmaceutical artifact family, and the accepted resolution was to leave only the link from AdministrableProductDefinition to MedicinalProductDefinition.

Initial application:
The issue appears to have been applied before this reconciliation. Git 5d196f882b, explicitly tagged FHIR#31782, removed the obsolete MedicinalProductDefinition.package backbone after the same no-bidirectional-links cleanup. Closely related history in git bb58238af40 and 8c81e0e3fc removed the former MedicinalProductDefinition.administrableProduct.product Reference(AdministrableProductDefinition), replacing it with MedicinalProductDefinition.route, so the MedicinalProductDefinition side no longer defines a reference to AdministrableProductDefinition.

Additional context:
MedicinalProductDefinition and AdministrableProductDefinition are active current-build resources in source/fhir.ini. FHIR-31776 explains the current APD-side element name by renaming APD.subject to AdministrableProductDefinition.formOf, and FHIR-31859 is the same BR&R no-bidirectional-resource-reference change family for the package/product relationship. No Zulip or Confluence evidence was found that changes the Jira/source/history conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current AdministrableProductDefinition.formOf is a Reference targeting MedicinalProductDefinition, while current MedicinalProductDefinition has no targetProfile to AdministrableProductDefinition and no MedicinalProductDefinition.administrableProduct element. The published one-way relationship requested by FHIR-31782 is already reflected in the active source.

Recommendation:
Keep this audit commit as-is. The current source already satisfies the published decision, and adding duplicate narrative would not change implementer understanding.
