FHIR-12068: Audit _has restriction removal

Issue request:
FHIR-12068 was a Published/Persuasive FHIR-core Search issue raised against DSTU2. It asked to remove the then-current _has restrictions that prohibited nested reverse chaining, modifiers, and chaining, and to document an example of a nested reverse chain.

Initial application:
The issue was applied by git-svn commit 7aad6634b34f0273fe2dcdbe207d2e2c3a5cdada, corresponding to svn revision 11229, which removed the explicit limitation list from source/search.html and added a nested _has example. Current blame still traces the removal and original nested-example placement to that commit, with later formatting and wording refinements.

Additional context:
source/search.html is an active build page through publish.ini. Later related work did not reinstate the old prohibitions: FHIR-20474 added an example of _has used inside a chained search, and FHIR-26886 added a non-prohibitive caution that forward and reverse chaining are not intended to work with modifiers and points complex cases to Named Queries or _filter. The combined branch already contains audit commits for FHIR-20474 and FHIR-26886, so this commit does not duplicate those decisions. Zulip and Confluence searches found only legacy bot/commit notices and no human discussion or minutes that change the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Search page no longer contains the removed limitation list, explicitly says _has can be nested, includes GET and POST nested examples, allows OR and multiple _has parameters, includes the chained-search example, and phrases modifier guidance as not intended but not prohibited.

Recommendation:
Keep this empty audit commit as-is. The current source satisfies the Published Jira request; no follow-up is needed unless FHIR-I later decides to define portable modifier semantics or additional grouping behavior for _has.
