FHIR-41478: Audit Identifier URI-system guidance

Issue request:
FHIR-41478 was an Applied/Persuasive with Modification FHIR-I R6 clarification asking when OID/GUID/UUID-style Identifier values must use system urn:ietf:rfc:3986, whether non-HL7 systems or IGs can define scoped uses outside that system, whether urn:oid:/urn:uuid: prefixes still apply, and how system versus type can distinguish the identifier kind.

Initial application:
The issue was applied before this reconciliation. Commit 6b590133d50b26348f24e87fe8a4e8bf95a804c0 explicitly references FHIR-41478 and refined source/datatypes.html after the broader FHIR-45479 replacement in commits 761673c67182cc4ebd521dfafee8f62f39d577c0 and 369aa0c0cdf6832e4b9370858d9a4c507fa4984c.

Additional context:
FHIR-41478 comments say it was superseded by, and then merged with outcomes from, FHIR-45479. FHIR-45479 replaced the older "naturally globally unique" paragraph with the current rule: a globally unique value can have an assigned Identifier.system established by an assigner or community, and urn:ietf:rfc:3986 is required when no assigned system exists and the value is expressed as a URI. The linked Zulip discussions and FHIR-I minutes align with that interpretation. Related AutoFHIR audit commits for FHIR-45479, FHIR-26438, and FHIR-42959 are already on the combined branch, so this commit does not duplicate those decisions.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active Identifier datatype narrative in source/datatypes.html already states that globally unique values may have an assigned system and only falls back to urn:ietf:rfc:3986 with urn:oid:/urn:uuid: URI values when no assigned system exists. source/fhir.ini wires the datatypes page into the current build, and the obsolete "naturally globally unique" wording targeted by the issue family is absent.

Recommendation:
Keep this audit commit as-is. No current-spec edit is needed for FHIR-41478 unless FHIR-I later decides to add more detailed guidance about prefixing or Identifier.type for a specific use case.
