FHIR-25043: Audit profile derivation wording

Issue request:
FHIR-25043 was a Published/Persuasive technical correction for the profiling page's glossary table. It reported that a Profile was described as a StructureDefinition with kind = constraint even though produced profile StructureDefinitions have kind = resource, and the approved resolution was to change the field name from kind to derivation.

Initial application:
The issue appears to have been applied by git commit b849e8879808db9a14195bc5aba691f278a3e7ad, "Fix FHIR-25043", which changed source/profiling.html from "kind = constraint" to "derivation = constraint". The Jira snapshot also records PR HL7/fhir#1741 as the application vehicle.

Additional context:
The current source/profiling.html page is in the current core source tree for the reported profiling page and still says "derivation = constraint". StructureDefinition.kind remains a required code bound to primitive-type, complex-type, resource, or logical, so constraint is correctly used as the derivation value rather than the kind value. FHIR-37417 later reported the same wording problem and reached Published/Persuasive status, but the source had already been corrected.
