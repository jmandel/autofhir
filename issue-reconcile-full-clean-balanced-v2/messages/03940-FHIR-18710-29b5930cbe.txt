FHIR-18710: Audit ValueSet non-computable rules extension

Issue request:
FHIR-18710 was a Published/Persuasive Vocab change request from STU3 asking FHIR core to add support for a Value Set Definition "Non-computable Content Expression" because some value set content rules cannot be captured in computable syntax. The final resolution was to add an extension.

Initial application:
The Jira-tagged implementation commit 4907f9bcb0b710cb2837a93a20c4b23210a37249 added ValueSet extension material as part of terminology ballot documentation updates, including a ValueSet-level expression extension that could carry an alternative expression and initially allowed a human statement of the rules when no computable definition existed.

Additional context:
Later Vocab/VSDP review separated computable expressions from non-computable human rules: Confluence notes from February 2019 say valueset-expression MUST be computable and identify valueset-rules-text for non-computable content, and FHIR-31489 later clarified valueset-expression to point to rules-text for non-computable definitions. Current core no longer owns the extension StructureDefinition source; that source is maintained in the FHIR Extension Pack, while the active core ValueSet page links to both extension artifacts through the extensions location.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active core ValueSet resource is in the current build, its narrative already tells implementers to use valueset-rules-text when no formal computable expression exists, source/oids.ini retains canonical OIDs for valueset-expression and valueset-rules-text, and the Extension Pack contains the authoritative valueset-rules-text StructureDefinition.

Recommendation:
Keep this audit commit as-is. No core source fix is needed for FHIR-18710; any future wording change to the extension definition itself should be handled in the FHIR Extension Pack, while any change to the core ValueSet explanatory text should be driven by a new Vocab decision.
