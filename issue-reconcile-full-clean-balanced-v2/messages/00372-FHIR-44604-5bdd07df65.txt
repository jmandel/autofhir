FHIR-44604: Audit moved Patient $everything bundle guidance

Issue request:
FHIR-44604 was Applied/Persuasive for the PA work group and asked to remove Patient $everything wording that made the default response a single Bundle rather than allowing paging, bulk/async handling, or other server/client choices. The approved resolution replaced the two-item "key differences" list with a single statement that $everything frees the client from determining included resources, and noted that FHIR-43373 should be applied first.

Initial application:
The request was applied in HL7/fhir commit 8085536f12e251d00b80ac47323658eb94e9b1ac together with FHIR-43373, changing source/patient/operationdefinition-Patient-everything.xml so the single-Bundle bullet was removed from the footer and the copied OperationDefinition comment was deleted. That first application temporarily duplicated the "frees the client" sentence, and later commit e8524f5b6b54904776987148319de565a582b52d cleaned the Patient footer while applying the related Encounter/EpisodeOfCare updates in FHIR-44816.

Additional context:
Patient $everything is no longer an active OperationDefinition in this core checkout. Commit b487fdda4bb4a5382a93dbb5a811efd02425b9bc removed source/patient/operationdefinition-Patient-everything.xml from the Patient operations list and changed core references to the Administrative Incubator continuous build. Current core source therefore has no local Patient $everything single-Bundle requirement to edit; the current HL7/admin-incubator source for OperationDefinition-Patient-everything also lacks the removed "entire result set in a single bundle" requirement. Later FHIR-52121/Zulip/Confluence discussion may further revise large-result guidance, but that issue is Triaged rather than Applied/Published and belongs to future PA/Admin Incubator work.

AutoFHIR reconciliation:
This commit intentionally makes no source change in HL7/fhir. The seed issue was historically applied in core, and the authoritative current operation source is now outside this checkout in HL7/admin-incubator where the FHIR-44604 requirement is already reflected.

Recommendation:
Keep this external-repo audit commit as-is for core reconciliation. If PA finalizes FHIR-52121 or another later large-result policy, apply that in the Administrative Incubator operation source rather than resurrecting the removed core OperationDefinition.
