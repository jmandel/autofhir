FHIR-31823: Audit combined substance classification

Issue request:
FHIR-31823 was a Published/Persuasive BRR change request for the R4 SubstanceSpecification artifact, applied for R5, asking to drop category and combine it with classification as a repeating 0..* classification element.

Initial application:
The current R5 build uses SubstanceDefinition rather than the old SubstanceSpecification name. Commit 259da1896e7c0d38a4b4569da43d71619538ba10 explicitly applied "combined category and classification FHIR#31823" by removing SubstanceDefinition.category, keeping SubstanceDefinition.classification at 0..*, broadening its text to cover high-level and lower-level categorization, and changing the search parameter from category to classification.

Additional context:
source/fhir.ini actively lists substancedefinition=SubstanceDefinition and marks SubstanceDefinition approved, so source/substancedefinition is the build-scope authority. Current source/substancedefinition/structuredefinition-SubstanceDefinition.xml has SubstanceDefinition.classification with max * and no SubstanceDefinition.category element, and current source/substancedefinition/bundle-SubstanceDefinition-search-params.xml exposes only the classification search parameter for this resource. BRR minutes for 2021-06-15 placed FHIR-31823 into block vote 2; no Zulip discussion was found that changes the Jira/source conclusion.

Recommendation:
Keep this no-change audit commit as-is. No further core FHIR source work is needed for FHIR-31823 unless a future BRR decision reopens SubstanceDefinition categorization semantics.
