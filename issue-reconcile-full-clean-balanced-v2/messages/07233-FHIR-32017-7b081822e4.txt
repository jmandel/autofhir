FHIR-32017: Audit _count search mode wording

Issue request:
FHIR-32017 was a Published/Persuasive FHIR-core technical correction for the Search page count section. It requested replacing `entry.search.mode = search` with `entry.search.mode = match` because `search` is not a SearchEntryMode code.

Initial application:
The change was already applied before this reconciliation in PR #1428. Commit 29156a3f9f, matching source branch commit b1647bc02f, changed source/search.html from `search` to `match`; merge commit 338bf6b986 brought that PR into the main history.

Additional context:
The current source/search.html page is the normative Search (RESTful API) source page and its _count section now says `entry.search.mode = match`. The search-entry-mode code system defines `match`, `include`, and `outcome`, with no `search` code. A 2023 Zulip thread about the same page noted the published R4 typo and that it was already fixed in the R5 build; Confluence and issue-key community searches found no conflicting WG record.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change because the current specification source already implements the requested correction and remains consistent with the SearchEntryMode value set and code system.

Recommendation:
Keep this no-change audit commit. A historical R4 technical correction or backport would be a separate publication decision and is outside this current-source reconciliation.
