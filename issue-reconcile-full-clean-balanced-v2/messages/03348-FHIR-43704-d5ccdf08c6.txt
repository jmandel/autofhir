FHIR-43704: Audit enableWhen.question linkId constraint

Issue request:
FHIR-43704 was an Applied FHIR-core Questionnaire change request, resolved Persuasive with Modification, asking for a constraint enforcing that Questionnaire.item.enableWhen.question refer to a valid linkId in the Questionnaire. The approved modification was to add the invariant as a warning because draft questionnaires and modular questionnaires can legitimately reference questions defined elsewhere.

Initial application:
The issue was applied on master by git commit 10c6afadf8c6a06680cb833b5495a319a190782c, which added warning invariant que-18 to Questionnaire.item.enableWhen and marked Questionnaire.item.enableWhen.question with condition que-18. That commit also changed que-2 to use repeat(item).linkId.isDistinct(), but the enableWhen.question work requested by this issue is the que-18 warning invariant.

Additional context:
Questionnaire is an active resource in source/fhir.ini, so source/questionnaire/structuredefinition-Questionnaire.xml is in the current build scope. The current source still contains que-18 with warning severity, the draft/modular exception text, and the FHIRPath expression checking the referenced linkId against %resource.repeat(item).linkId. Confluence SDC minutes for 2024-02-22 record the FHIR-43704 persuasive-with-modification motion. Jira searches surfaced older published Questionnaire enableWhen/linkId issues, but they predate this tracker and do not reverse or narrow the requested warning constraint. No Zulip message mentioning FHIR-43704 was found.
