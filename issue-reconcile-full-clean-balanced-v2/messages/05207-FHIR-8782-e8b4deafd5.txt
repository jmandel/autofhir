FHIR-8782: Audit FamilyMemberHistory no-known guidance

Issue request:
FHIR-8782 was a Published FHIR-core Patient Care change request with resolution Persuasive with Modification. It asked for documentation distinguishing a searched patient's family history with no known problems from family history that was merely undocumented; the accepted resolution said the shared condition-code value set already included SNOMED CT 160245001 and required a FamilyMemberHistory note pointing to FamilyMemberHistory.condition.code for "No Known Problems" or "No history of malignant tumor of breast". Patient-level family-history negation was referred to GF#8781.

Initial application:
Historical commit bd3f8a7ba5 explicitly tagged #8781 and #8782 and added the FamilyMemberHistory notes section covering List.emptyReason for whole-list family-history states and FamilyMemberHistory.condition.code for no-known/negated conditions for one family member. The SNOMED CT 160245001 value-set part had already been introduced by commit afcde8c935 for #8749 in the shared Condition code value set, which FamilyMemberHistory.condition.code still uses.

Additional context:
FamilyMemberHistory is an active resource in source/fhir.ini, has the fhs work-group/category metadata, and is marked approved. Current source/familymemberhistory/familymemberhistory-notes.xml still contains the requested no-known/negated-condition note, source/familymemberhistory/structuredefinition-FamilyMemberHistory.xml binds condition.code to http://hl7.org/fhir/ValueSet/condition-code, and source/condition/valueset-condition-code.xml still includes SNOMED CT 160245001. Later FHIR-17887 added a concrete negated FamilyMemberHistory example and is already represented on the combined branch; later FHIR-43306 was Resolved - No Change and recommends using a precoordinated condition.code or CodeableConcept.text rather than adding a separate negation indicator.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current source already contains the FamilyMemberHistory.condition.code guidance requested by FHIR-8782, and the shared condition-code value set still contains the referenced SNOMED CT code.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-8782 unless a future Patient Care decision changes the FamilyMemberHistory negation/absence pattern.
