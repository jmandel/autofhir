FHIR-15090: Audit supply identifier business IDs

Issue request:
FHIR-15090 was a Published/Persuasive STU3 OO change request. It objected to resource identifier elements being worded or cardinalized as the resource's unique logical id rather than business/external identifiers; for this supply-related partition, the operative resolution changed SupplyDelivery.identifier from the dispensing-facility identifier to an event identifier used across disparate systems and made it repeatable.

Initial application:
No source commit explicitly tagged FHIR-15090 was found, and the combined branch did not already contain an Issue-Reconcile-Key commit for FHIR-15090. Git history does show an implicit pre-application commit, 644f2985adbed8f2ededc714a68a832de4689805, changing source/supplydelivery/supplydelivery-spreadsheet.xml from 0..1 plus the old dispensing-facility definition/comment to 0..* plus the requested supply-delivery event definition/comment. The spreadsheet source was later refactored into the current XML form.

Additional context:
Current source/fhir.ini's active [resources] list no longer includes supplyrequest or supplydelivery, so those historical resources are not current build resources under the primary build-scope authority. The residual SupplyDelivery XML still carries the requested 0..* cardinality and event-identifier definition, and SupplyRequest.identifier also uses repeatable business-identifier wording. A later FHIR-37742/FHIR-37487 source change refined the SupplyDelivery comment from dispenser to supplier without reintroducing logical-id semantics. The adjacent Transport XML present in the checkout likewise uses 0..* and a transport-event identifier definition.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current source either already preserves the requested business/external identifier semantics or is outside the current active resource build scope, so editing the remaining SupplyRequest/SupplyDelivery files or the adjacent Transport text would not be a necessary FHIR-15090 reconciliation fix.

Recommendation:
Keep this no-change audit as-is. Reopen only if the build is later changed to re-activate SupplyRequest or SupplyDelivery and those generated/current artifacts no longer retain 0..* business identifier semantics.
