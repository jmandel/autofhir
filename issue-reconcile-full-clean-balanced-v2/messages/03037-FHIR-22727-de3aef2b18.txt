FHIR-22727: Audit PlanDefinition internal-reference invariants

Issue request:
FHIR-22727 was Published/Persuasive for FHIR-core PlanDefinition. It asked for semantic integrity checks, with final resolution to add PlanDefinition invariants ensuring goalId references the id of a goal element and relatedAction.actionId references the id of another action element.

Initial application:
The issue was applied before this reconciliation by 2883a583669e77fac7b609317e2834245cbebd29, which added pld-3 and pld-4 constraints plus condition references to source/plandefinition/structuredefinition-PlanDefinition.xml. The current source still contains those constraints in the active PlanDefinition StructureDefinition.

Additional context:
PlanDefinition is active in the current build through source/fhir.ini. FHIR-29430 renamed PlanDefinition.action.relatedAction.actionId to targetId for R5, and source/fhir.ini records the old actionId path as mapped to PlanDefinition.action.relatedAction.targetId. FHIR-40218 later corrected goalId and targetId datatypes to string while preserving the pld-3 and pld-4 constraints. No relevant Zulip or Confluence evidence was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already has pld-3 requiring action.goalId values to reference PlanDefinition.goal.id and pld-4 requiring relatedAction.targetId values to reference PlanDefinition.action.id, which is the current name for the actionId element requested by the issue.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-22727 unless the CDS work group chooses to revisit the precise warning-level invariant expressions separately from this published issue.
