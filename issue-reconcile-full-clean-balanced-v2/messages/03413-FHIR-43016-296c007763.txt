FHIR-43016: Record external additionalImplicitRules follow-up

Issue request:
FHIR-43016 is Applied/Persuasive with Modification for R6. It asked to allow Resource.implicitRules to repeat, but the approved resolution instead kept Resource.implicitRules singular, defined a new modifier extension additionalImplicitRules 0..* of type uri, documented that multiple rules have no implied ordering or prioritization, and added guidance from Resource.implicitRules to the extension.

Initial application:
Core commit 2aa82993970dd5274b8bb7ced92f48801b06aea9 updated source/resource/structuredefinition-Resource.xml so Resource.implicitRules still has max 1 but points DomainResource instances with additional policies to additionalImplicitRules. Extension Pack commit 6ac5032dce8db9eeccdc79970672a5b41eb174ff created input/definitions/Resource/StructureDefinition-additionalImplicitRules.json, and 8b6c4a68cd47cdf4869b7ac5e38faf7f67d78e9e later clarified why the extension is scoped to DomainResource.

Additional context:
Resource is active in the current core build through source/fhir.ini, and the combined branch already contains the core implementation commit. The extension definition now lives in the separate HL7/fhir-extensions checkout. That external source has the approved context, cardinality, uri value, and ordering comment, but neither its source nor the rendered Extension Pack page marks the root Extension as a modifier; the CI details page reports Is Modifier false.

AutoFHIR reconciliation:
This empty audit commit makes no core source change. The core-side guidance is already present and in build scope, while the remaining substantive discrepancy belongs to the FHIR Extension Pack rather than this FHIR core checkout.

Recommendation:
Keep this audit commit as-is for core. Follow up in HL7/fhir-extensions to mark additionalImplicitRules as a modifier extension with an appropriate isModifierReason, unless FHIR-I intentionally no longer wants modifier semantics for this extension.
