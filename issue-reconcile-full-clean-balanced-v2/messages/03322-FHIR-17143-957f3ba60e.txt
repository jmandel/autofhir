FHIR-17143: Audit MedicationRequest draft status wording

Issue request:
FHIR-17143 was a Published pharm technical correction with a Persuasive with Modification resolution. It asked to update the MedicationRequest status code `draft` definition from the older `i.e.` wording that combined sign-off/verification with `and needs to be run through decision support process` to wording using `e.g.` and treating sign-off, verification, or decision-support processing as alternatives.

Initial application:
The Jira comment says the change was applied in the old SVN build history. The git-svn history contains e880d7aefc, `GF Trackers: 17206, 17199, 17158, 17143, 16024, 15589, 17174 - Changes to Pharmacy resources`, which changed `source/medicationrequest/medicationrequest-spreadsheet.xml` from the old `i.e.` / `and needs` text to the accepted `e.g.` / `verification or needs` text. Later, 7373e742ee split the MedicationRequest status codelist into `source/medicationrequest/codesystem-medicationrequest-status.xml` with the same updated draft definition.

Additional context:
MedicationRequest is an active resource in `source/fhir.ini`, so `source/medicationrequest/codesystem-medicationrequest-status.xml` is build-scope source for the current CodeSystem. Later source refactors preserved the resolved wording while changing `prescription` to `request` in 129c9fa6f54, which aligns with the current resource name and does not reverse the FHIR-17143 decision. Searches found no Zulip or Confluence discussion that conflicts with the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active CodeSystem definition for `draft` already says the request is not yet actionable, uses `e.g.`, and lists sign-off, verification, or decision-support processing as alternatives.

Recommendation:
Keep this audit commit as-is. No follow-up core source change is needed for FHIR-17143 unless a future pharmacy decision wants to make a separate editorial cleanup to the wording.
