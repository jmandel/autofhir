FHIR-20530: Audit endpoint payload value set import

Issue request:
FHIR-20530 was a Published/Persuasive STU3 Patient Administration change request for Endpoint. It reported that the Endpoint payload type value set duplicated copied IHE FormatCodes concepts, including duplicate xphr entries, and asked for the value set to import the identified IHE/format-code value set instead.

Initial application:
The request was applied in git commit 5fc677fa57632c25c76d2acac93f5d333b10dcb3, the same commit that applied FHIR-28467. That commit removed the long copied concept list from source/endpoint/valueset-endpoint-payload-type.xml and replaced it with an include of http://terminology.hl7.org/ValueSet/v3-HL7FormatCodes.

Additional context:
The related Zulip thread that led to FHIR-20530 identified the duplicate copied code and later confirmed that editors should use the THO value set, following the current DocumentReference pattern. Current Endpoint source is active in source/fhir.ini, Endpoint.payload.type binds to endpoint-payload-type, and that value set now composes the local endpoint payload type CodeSystem plus the THO FormatCodes value set. The adjacent Direct endpoint example code-system mismatch found during this investigation was fixed in the preceding FHIR-28467 reconciliation commit.

AutoFHIR reconciliation:
No source files were changed for this issue. The active Endpoint payload type value set no longer carries the copied IHE concept list that FHIR-20530 objected to, so an empty audit commit is the correct per-issue record.

Recommendation:
Keep this audit commit as-is. Any future changes to the FormatCodes content or expansion should be handled in THO/IHE/UTG unless a new FHIR-core issue changes the Endpoint binding itself.
