FHIR-34344: Audit version-specific transaction references

Issue request:
FHIR-34344 was a Published/Persuasive with Modification FHIR-core issue for the RESTful API transaction rules. It reported that wording added by FHIR-14138 was not careful enough: "re-assigned anyway" could be read as reassigning references to already-existing historical versions, and conditional creation behavior was unclear. The approved resolution removed the two broad sentences about version-specific references being re-assigned and replaced them with transaction-specific guidance: existing version-specific references are expected to identify already-existing versions, while references to versions created in the current transaction should be version-independent references carrying the resolve-as-version-specific extension, with possible errors when no transaction entry creates the target version.

Initial application:
The issue was explicitly applied by HL7/fhir commit a7810f9b2cfc9f747d876079d688ce062f3af0b2, "FHIR-34344 Clarify version-specific references", which changed source/http.html. Current source/http.html no longer contains the FHIR-14138 "arbitrarily chosen version references" / "re-assigned anyway" text and contains the replacement paragraphs in the active Version specific references and updates subsection.

Additional context:
FHIR-34343 is the same change family and approved the resolve-as-version-specific extension mechanism that FHIR-34344 relies on; the extension source now lives in the FHIR Extension Pack. FHIR-I minutes on 2022-04-11 record the final FHIR-34344 persuasive-with-modification vote. The Zulip thread "Resolving references in Bundles" shows the underlying concern: /_history on urn:uuid temporary transaction references is not a valid URN pattern, so a separate extension mechanism was preferred. Later FHIR-37573 and FHIR-38648 reported duplicate paragraph/link problems in the same text; current source has a single copy of the paragraph and working extension-location links, and those later issues are already represented separately on the combined branch.

AutoFHIR reconciliation:
Made no source change. The active RESTful API source already implements the published FHIR-34344 decision: it distinguishes existing version-specific references from transaction-created target versions, points implementers to resolve-as-version-specific for the latter case, and leaves no remaining occurrence of the superseded "re-assigned anyway" wording. Additional edits would either duplicate existing guidance or reopen later edge cases outside this seed's final decision.

Recommendation:
Keep this no-change audit as-is. No FHIR core source edit is needed for FHIR-34344; any future changes to resolve-as-version-specific edge cases, extension definition examples, or broader Bundle reference-resolution rules should be handled through their own Jira decisions rather than this audit.
