FHIR-31722: Audit R4B CodeableReference scope

Issue request:
FHIR-31722 was a Published FHIR-core R4B ballot issue with resolution Not Persuasive with Modification. The ballot comment asked to exclude the new CodeableReference data type from R4B because it was viewed as breaking; the accepted resolution clarified that adding a data type was not itself breaking, limited R4B use to intended medication-regulation scope, and said CodeableReference should not be supported in R4B wildcard-type locations such as Parameters and Extension.

Initial application:
No commit in the current FHIR source history explicitly mentions FHIR-31722. The Jira comments record a Java core change 9d187f2ca, which is not a commit in this FHIR source checkout. Historical R4B source already introduced CodeableReference for Medication Definition/R4B ballot scope, and the published R4B Parameters profile excludes CodeableReference from Parameters.parameter.value[x].

Additional context:
The current source branch is the R6 build, not the R4B publication branch: source/ballot-intro.html identifies the R6 ballot, and source/fhir.ini lists CodeableReference as an active current data type. Current R5/R6 source also uses CodeableReference broadly beyond the R4B medication-regulation scope, which is expected after R4B. Published R4B still exposes CodeableReference on Extension.value[x], so any remaining R4B errata/tooling question is historical and outside this current build branch.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Removing or restricting CodeableReference in the current R6 source would incorrectly regress current FHIR semantics; fixing any residual R4B-only Extension.value[x] publication behavior would need to happen on an R4B maintenance/publication/tooling path, not on this combined current-source branch.

Recommendation:
Keep this external-repo/out-of-current-build audit commit as-is for the current FHIR reconciliation. If HL7 wants to revisit the R4B Extension.value[x] publication surface, route that as a historical R4B errata/tooling review rather than changing current R6 source.
