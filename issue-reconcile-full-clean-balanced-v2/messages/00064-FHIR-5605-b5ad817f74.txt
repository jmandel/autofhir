FHIR-5605: Audit terminology filter capability guidance

Issue request:
FHIR-5605 was a Published/Persuasive DSTU1 FHIR-core terminology-service change request asking how a client can discover which code system filter properties a terminology server supports and where the then-current supported-system extension should be placed. The recorded resolution was to use SVN r4364 to clarify usage of the extension, with a 2015-03-19 MnM/FHIR block-vote approval.

Initial application:
No git commit directly mentions FHIR-5605, but the Jira resolution points to SVN r4364. That revision is git commit da0f89e775d2cf65f97788b4fcfa6a1eab98a752, which changed source/terminology-service.html from a bare supported-system extension fragment into a full Conformance resource example and explicitly stated that the extension is added to the root Conformance Statement. Commit 6106a1be5b1703ee84bdbe31a1b6202faa8a567c later carried that same applied guidance through the Conformance-to-CapabilityStatement rename and updated the canonical extension URL to capabilitystatement-supported-system.

Additional context:
The current terminology-service page is still a built core page and retains the root CapabilityStatement guidance for capabilitystatement-supported-system. The active TerminologyCapabilities resource now gives the more complete modern answer for the filter-discovery part of the issue: TerminologyCapabilities.codeSystem.version.filter identifies supported filter properties and filter.op identifies supported operators for each code-system version. The capabilitystatement-supported-system extension definition itself now lives in the FHIR Extension Pack with CapabilityStatement context. FHIR-53787 is a later Submitted/unresolved FHIR-extensions request to deprecate that extension because TerminologyCapabilities is more complete, so it is background only and not a final reversal of the current core text.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core source already preserves the applied r4364 placement clarification, and adding another terminology-service sentence would duplicate information already carried by the active TerminologyCapabilities resource while FHIR-53787 remains unresolved.

Recommendation:
Keep this audit commit as-is for FHIR-5605. If FHIR-53787 is later resolved, handle extension deprecation or terminology-service wording as a separate FHIR-extensions/current-core decision rather than reopening this DSTU1 applied clarification.
