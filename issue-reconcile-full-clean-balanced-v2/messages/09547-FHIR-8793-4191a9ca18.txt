FHIR-8793: Audit version-change wording

Issue request:
FHIR-8793 was a Published/Persuasive FHIR-core history-page clarification asking that the versioning rules no longer say that adding new elements in an existing resource is non-breaking without qualification. The accepted request was to clarify that adding new optional elements is the non-breaking/non-substantive case, while adding mandatory elements is substantive.

Initial application:
The issue was applied in SVN revision 7967, represented in git as 62dc5f8590cd8e3569c35c1d3af86a20b5a5373f, which changed source/history.html from "adding new elements in an existing resource" to "adding new optional elements in an existing resource." The versioning policy content was later reorganized into source/versions.html by d68b8964af6bcba886df7c89465a68e18951f5fd, carrying the optional-element qualification forward.

Additional context:
The current source no longer uses the old history.html#rules section as the authoritative policy location. source/history.html points readers to source/versions.html, and the current Version Management Policy says new optional elements may be introduced while minimum element cardinalities will not be changed for normative content. Later version-policy work such as FHIR-13089 broadened the forward/backward compatibility guidance but did not restore the overbroad wording from FHIR-8793. Targeted Zulip and Confluence searches found no community record contradicting this source and Jira history.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build source already implements the requested clarification in the active version-management policy, and adding redundant wording back to history.html would duplicate policy text rather than correct a current spec problem.

Recommendation:
Keep this empty audit commit as-is. No follow-up source work is recommended for FHIR-8793 unless the work group decides to revise the broader inter-version compatibility policy in a separate issue.
