FHIR-5561: Audit Composition document classification wording

Issue request:
FHIR-5561 was Published/Persuasive with Modification for DSTU1. It asked to align Composition.type and Composition.class definitions with the DocumentReference improvements from FHIR-3771, with the final SDWG resolution leaving Composition.type/class as the model and making DocumentReference match, while adding an XDS/MHD metadata-field note to both class elements.

Initial application:
The issue was applied in svn r5892 / git commit a4f7d63ab3, which added the XDS/MHD metadata-field note to the old Composition.class and DocumentReference.class spreadsheet sources. Those spreadsheet sources were later migrated into the current StructureDefinition XML files.

Additional context:
Later final decisions changed how the old class elements should be understood in the current build. FHIR-13917 replaced the DocumentReference class XDS/MHD comment with search/filtering metadata wording; FHIR-17171 and FHIR-17555 renamed DocumentReference.class and Composition.class to category and increased cardinality; and FHIR-31668 explicitly found that Composition.category is no longer XDS classCode and removed the old XDS/MHD comment. Current active source reflects those later decisions: Composition.type and DocumentReference.type remain aligned, DocumentReference.category retains an XDS classCode mapping, and Composition.category intentionally has no XDS/MHD note.

AutoFHIR reconciliation:
Made no source change. Re-adding the original FHIR-5561 XDS/MHD note would now conflict with the later Published FHIR-31668 decision for Composition.category and the later Published FHIR-13917 wording for DocumentReference.category.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-5561 in core unless a new work-group decision revisits category/class guidance across Composition and DocumentReference.
