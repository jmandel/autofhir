FHIR-23819: Audit timezone value set application

Issue request:
FHIR-23819 was a Published FHIR-core change request, resolved Persuasive with Modification for R5, asking to create common timezone support by using the existing IANA timezone ValueSet, expanding the timezone extension context to include Resource.Meta, updating the extension and ValueSet comments to cite example IANA codes and official sources, ensuring the ValueSet was not described as unused, correcting the IANA display, and attempting to provide an expansion for publication.

Initial application:
The Jira-tagged core commit 4893a592e4bd3486fd1188912eb96015f56012dd applied the request on 2022-08-18. It added the ValueSet title and detailed IANA description in source/profiles/valueset-timezones.xml, changed the then-core timezone extension context from date;dateTime;instant to date;dateTime;instant;Meta in source/profiles/general-extensions-spreadsheet.xml, and replaced the terse extension comment with examples such as America/New_York and America/Los_Angeles plus IANA and Wikipedia references.

Additional context:
The active timezone extension definition has since moved out of core into the FHIR Extension Pack. The current extension-pack source for StructureDefinition/timezone includes contexts date, dateTime, instant, Meta, and time; retains the example-code/source comment; and binds valueCode to http://hl7.org/fhir/ValueSet/timezones with required strength. Later FHIR-43351 refined only the extension definition prose. Later HTA-147 and UP-623 created THO/external code-system metadata for https://www.iana.org/time-zones, which supports but does not require a core source change. Current R5/build rendered ValueSet pages show a 469-code expansion and do not contain the stale "not currently used" or "I A N A" problems.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current core source already defines the IANA timezone ValueSet with the requested title, examples, source links, and compose system; current core narrative points to the timezone extension where timezone codes are used; and the current authoritative extension-pack definition already carries the requested Meta context and required ValueSet binding. The publication expansion is generated from terminology/build infrastructure rather than a missing core source expansion block.

Recommendation:
Keep this no-change audit commit as-is for FHIR-23819. No core follow-up is indicated. If future validation or tx.fhir.org support for https://www.iana.org/time-zones regresses, handle it through THO/HTA or terminology-server work rather than reopening this core source reconciliation.
