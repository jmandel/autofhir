FHIR-31586: Audit external Observation analysis date/time extension

Issue request:
FHIR-31586 is an Applied/Persuasive OO change request for R6 asking for a standard Observation AnalysisDateTime extension with a dateTime value to carry v2 OBX-19 Date/Time of Analysis, distinct from Observation.effective[x]. The accepted description was "The time stamp associated with the generation of the analytical result."

Initial application:
The Jira application comment points to HL7/fhir-extensions commit 81ac96b. That merge includes commit 5b7b20f, which added input/definitions/Observation/StructureDefinition-observation-analysisDateTime.xml with Observation context, canonical http://hl7.org/fhir/StructureDefinition/observation-analysis-date-time, max 1, and value[x] constrained to dateTime. Core FHIR does not define a local extension StructureDefinition for this issue; current core source only has the expected OID registry entry and a later Observation v2 mapping note that points OBX-19 to the AnalysisDateTime extension when present.

Additional context:
Observation is active in the current core build, but standard extension definitions for this artifact are maintained in the FHIR Extension Pack. The current Extension Pack source still defines the Observation analysis date/time extension. Later Published Extension Pack issues FHIR-52954 and FHIR-53015 clarified the same extension by distinguishing it from Observation.effective[x] and Observation.issued and by saying the analytical result timestamp is generated by an instrument, which explains the current wording differences from the original FHIR-31586 resolution. OO Confluence minutes corroborate the 2023-10-10 vote and the December 2023 extension-repository application path; no relevant Zulip discussion was found.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. Adding a duplicate core-hosted extension definition would be wrong because the requested artifact lives in HL7/fhir-extensions, while the core checkout already carries only the expected supporting OID and v2 mapping references.

Recommendation:
Keep this external-repo audit commit as-is for the core reconciliation. Future maintenance of the extension definition or its later clarification wording should happen in HL7/fhir-extensions or a separate reconciliation for the later Extension Pack issues, not as a FHIR-31586 core source edit.
