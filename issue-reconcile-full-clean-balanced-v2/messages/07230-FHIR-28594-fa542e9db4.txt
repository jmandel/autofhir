FHIR-28594: Audit SubscriptionTopic resource type references

Issue request:
FHIR-28594 was Published/Not Persuasive with Modification for R5 SubscriptionTopic. The Jira asked to stop representing SubscriptionTopic.resourceTrigger.resourceType as a fixed resource-type value set, use a URI representation so different FHIR versions and custom resources could be named, remove targetProfile-oriented wording from the element definition, and link to ElementDefinition.type.code for the URI interpretation.

Initial application:
The first-pass SubscriptionTopic commit 4f3fcec0394 changed SubscriptionTopic.resourceTrigger.resourceType from a code/token-shaped resource-type selector to a uri with an extensible FHIR-defined-type binding, but left the targetProfile definition wording. The Jira-cited commit 70355f13b223 was part of the same SubscriptionTopic implementation package but mostly adjusted SubscriptionTopic maturity/status and documentation. Follow-up commit dbeb5e6a7aa, one day after the FHIR-I vote, removed the stale targetProfile explanation and added the ElementDefinition.type.code link; the 2021 source rework carried that wording into structuredefinition-SubscriptionTopic.xml.

Additional context:
SubscriptionTopic is an active current-build resource in source/fhir.ini. Later applied/published work renamed resourceTrigger.resourceType to resourceTrigger.resource, clarified related resource-selector elements, changed the binding family to SubscriptionTypes/version-independent resource types, and in R6 collapsed resourceTrigger/eventTrigger into trigger with fhir.ini aliases for the old R5 paths. Existing combined-branch reconciliation commits already represent the tightly related FHIR-38800, FHIR-39024, FHIR-33973, and FHIR-46492 decisions, so this seed should not duplicate those decisions.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current source/subscriptiontopic/structuredefinition-SubscriptionTopic.xml has SubscriptionTopic.trigger.resource as uri, explains relative URLs against the StructureDefinition root with the Patient example, links to ElementDefinition.type.code, and no longer uses targetProfiles for this selector. The current extensible ValueSet/subscription-types binding is the later accepted binding family for subscription resource selectors, not an unfinished FHIR-28594 application.

Recommendation:
Keep this no-change audit. Do not reintroduce the old resourceType name, targetProfile wording, or an isolated example binding for FHIR-28594; revisit only if FHIR-I makes a new decision to change the current SubscriptionTopic.trigger.resource binding or URI semantics.
