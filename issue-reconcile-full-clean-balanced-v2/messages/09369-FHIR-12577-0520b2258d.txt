FHIR-12577: Audit operation definition casing mismatch

Issue request:
FHIR-12577 was a Published/Persuasive FHIR-core change request from DSTU2 asking that generated complete CapabilityStatement operation references preserve the case of OperationDefinition resource ids, because resource ids and references are case-sensitive. The resolution was auto-approved and also asked why the mismatch was not caught as an error.

Initial application:
The issue was applied in svn/git history by commit 2c62cd190b768ad0d0494a401c7d1da0c18c6543, which is tagged "#12577 - check URL references are correct" and records SVN revision 11519. That commit added or adjusted URL-reference checking and made broad example/reference cleanups, but the commit subject notes the check was turned off because there were too many references to fix.

Additional context:
Current source inputs for resource-specific operations still carry the intended mixed-case OperationDefinition ids and references, such as OperationDefinition/Resource-validate and OperationDefinition/StructureDefinition-snapshot. The current build package, however, still emits generated CapabilityStatement-base operation definitions with lower-case resource prefixes, while the package OperationDefinition resources themselves keep the mixed-case canonical URLs. The CapabilityStatement-base example is generated as a tool example, and this checkout delegates that generation to the external org.hl7.fhir:kindling dependency rather than checked-in generator source.

AutoFHIR reconciliation:
This commit intentionally makes no source edit in the FHIR spec checkout. Changing checked-in OperationDefinition ids to lower case would be a broad canonical URL change and would make the source conform to the generator bug rather than fixing the generator to reference the existing canonical OperationDefinition URLs. The needed correction is in the Kindling/publisher generation path for the complete base CapabilityStatement or in the generated-output validation that should catch unresolved canonical references.

Recommendation:
Keep this audit commit as an external-repo decision for this run. Follow up in the Kindling/publisher code so generated CapabilityStatement-base uses the actual OperationDefinition.url/id casing from the loaded OperationDefinition resources, then rebuild and verify that capabilitystatement-base.xml/json references match the package OperationDefinition canonicals.
