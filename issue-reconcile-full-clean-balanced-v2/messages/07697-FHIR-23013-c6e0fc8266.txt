FHIR-23013: Audit history response status guidance

Issue request:
FHIR-23013 was Published with a Persuasive with Modification resolution for the RESTful history interaction. It asked for the history snippets to conform to the Bundle response requirements by adding the required Bundle.entry.response.status values and for the guidance to say: "In addition to the required response.status, the server SHOULD populate at least response.lastModified so the time of processing is clear in the history record".

Initial application:
The issue was applied by 0dadd56be4, which updated source/http.html to add response.status values to the create and delete history snippets and changed the note to name the required response.status before recommending response.lastModified. The earlier related FHIR-19619 application, e8104dd10d, had already removed older prose that treated response.status as optional.

Additional context:
The current source/http.html history section says each history entry SHALL contain request and response elements, includes response.status in the create and delete snippets, and includes the approved note about required response.status plus response.lastModified. The current Bundle definition has Bundle.entry.response.status at 1..1 and the current history invariant bdl-3b requires response on history entries, reflecting the same conformance rule even though the historical issue text referred to bdl-4. FHIR-I minutes confirm the Persuasive with Modification vote. FHIR-17332 and FHIR-19619 are supporting prior decisions, not separate unresolved work in this reconciliation. The seed description also suggested adding a history Bundle example to bundle-examples.html, but that item was not included in the final resolution and the current RESTful API source is not misleading without adding a redundant example.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current built source already satisfies the approved FHIR-23013 correction: history examples include response.status, guidance no longer implies response.status is optional, and Bundle conformance requires response/status where the history guidance uses it.

Recommendation:
Keep this no-change audit commit as-is. If the work group still wants a full history Bundle example on the Bundle examples page, that should be raised or confirmed as a separate editorial/example request rather than inferred from the modified FHIR-23013 resolution.
