FHIR-13205: Audit redundant ProcedureRequest extensions

Issue request:
FHIR-13205 was a Published/Persuasive with Modification OO change for STU3. It asked to remove redundant ProcedureRequest extensions. After reopening, the final revote removed authorizedBy as a duplicate of requester and reasonRefused as a duplicate of reasonRejected; targetBodySite was not removed because the comments clarified that it was not a duplicate of the coded bodySite element.

Initial application:
The issue was partly applied in the ProcedureRequest extension spreadsheet by the May 2017 #13205 commits: 7c87cdc removed authorizedBy and touched the targetBodySite row, 308dea0 amended #13205 by restoring targetBodySite, and 62dd409 later fixed the target body extension context to include ProcedureRequest. The current source no longer has active ProcedureRequest extension definitions; ProcedureRequest was subsequently renamed/merged into ServiceRequest by the GF#13867 change.

Additional context:
The current build scope in source/fhir.ini lists ServiceRequest as active and comments ProcedureRequest as merged into ServiceRequest. The current ServiceRequest definition carries the relevant replacement semantics: ServiceRequest.requester identifies the authorizer, ServiceRequest.bodyStructure is the target body location, and ServiceRequest.reason/statusReason cover reason and current-status rationale. Searches of active core source and the FHIR Extension Pack found none of the obsolete procedurerequest-authorizedBy, procedurerequest-reasonRefused, procedurerequest-reasonRejected, or procedurerequest-targetBodySite extension URLs outside release-history material.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because the current build no longer exposes the redundant ProcedureRequest extensions and the active ServiceRequest source already preserves the non-redundant semantics.

Recommendation:
Keep this audit as-is. No follow-up core edit is recommended unless a future work group decision wants to reintroduce or separately document one of these retired ProcedureRequest extension URLs.
