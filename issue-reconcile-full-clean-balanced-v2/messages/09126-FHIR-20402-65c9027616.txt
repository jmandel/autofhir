FHIR-20402: Audit canonical status mapping display

Issue request:
FHIR-20402 was a Published FHIR-core FHIR-I change request, resolved Persuasive/auto-approved, asking that value set pages honor many-to-one canonical status mappings from source/status-codes.xml. The examples were Condition.verificationStatus unconfirmed/provisional and DiagnosticReport.status partial/preliminary, whose canonical mappings were present in the status-code spreadsheet but not shown on the then-current value set pages.

Initial application:
No explicit FHIR-20402-tagged source commit was found in the FHIR core history. The R4 publication still shows the reported symptom: those example value set rows have empty canonical-status cells. By the R5 publication, which is the issue's Applied for Version, the same value set pages include a canonical mapping column and generated sc-valueset ConceptMaps that show the many-to-one mappings, so the tooling/display problem was applied before publication.

Additional context:
FHIR-19885 is the directly related verification-status alignment issue and is already represented on the combined branch. Its Jira/Zulip trail split the missing canonical-status display into FHIR-20402 after Lloyd McKenzie confirmed that mapping multiple local codes to the same canonical status is valid. Current core source still has the authoritative source/status-codes.xml mappings: Condition.verificationStatus unconfirmed/provisional map to canonical unconfirmed, and DiagnosticReport.status partial/preliminary/modified map to the current canonical draft status. Condition and DiagnosticReport are active resources in source/fhir.ini, and resource-status is an active core code system. No Confluence reference or conflicting community decision was found for FHIR-20402.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source contains the many-to-one mappings and the current rendered value set pages now expose those mappings in both the value set expansion table and the generated canonical ConceptMap pages.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-20402; if this display regresses in a future build, it should be handled as publisher/tooling behavior rather than by changing terminology source mappings.
