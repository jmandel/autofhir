FHIR-5922: Audit suppressed profile element rendering

Issue request:
FHIR-5922 was a Published/Persuasive FHIR-core FHIR-I issue raised against DSTU1 profile rendering. It reported that base invariants and terminology bindings were still displayed for MedicationStatement.reasonNotGiven in a DAF profile even though the profile constrained that element to 0..0, and asked to remove invariants and bindings when a profile suppresses an element.

Initial application:
The issue was applied in git-svn commit c635a5774f436cc921efa3f96a2883293995dbc1 (#5922, SVN revision 5003). That commit changed the old in-repository PageProcessor profile rendering code so terminology bindings are collected only when ed.hasBinding() and ed.getMax() is not "0", and constraints are listed only for snapshot elements whose max is not "0". This directly implemented the Jira request for both terminology bindings and invariants on suppressed elements.

Additional context:
The current HL7/fhir checkout no longer contains the old tools/java PageProcessor as editable source; the build delegates publishing to the external Kindling dependency declared in build.gradle.kts/gradle.properties. The current Kindling 1.25.5-SNAPSHOT PageProcessor source used by this checkout still contains the same max != "0" filters for getTerminologyNotes and getInvariantList. The exact DAF/QICore profile context from the Jira is not in current core build scope: source/igs.xml comments out the DAF and QICore IG entries, source/fhir.ini only has a commented us-core profile entry in that area, and current MedicationStatement source has MedicationStatement.reason rather than the old reasonNotGiven element. Related profile/invariant issues FHIR-5926 and FHIR-8736 already have separate combined-branch audit commits, so they were not republished here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The historical rendering defect was applied in source history, the current publisher dependency still carries the required suppression behavior, and the old DAF profile/example element is no longer an editable current-core artifact. There is no current FHIR source hunk that would improve implementer understanding or correct a current build-scope artifact.

Recommendation:
Keep this audit commit as-is. If a current generated profile page ever shows constraints or terminology bindings for a 0..0 element, investigate the current Kindling/IG Publisher tooling dependency rather than changing HL7/fhir core source; no follow-up is needed for the current core specification.
