FHIR-16001: Audit Observation composite component references

Issue request:
FHIR-16001 was a Published/Persuasive STU3 FHIR-core search-parameter-registry correction. It reported that Observation.code-value-concept, Observation.code-value-date, Observation.code-value-quantity, and Observation.code-value-string component definitions referenced the removed canonical Observation-code search parameter and should instead use the common clinical-code search parameter after cross-resource search parameters were introduced.

Initial application:
Jira records the intended application as "update generator for this change" with svn revision 14532. The local Git history does not contain an explicit FHIR-16001 commit, but later checked-in R4 search-parameter history contains the four Observation composite component definitions using http://hl7.org/fhir/SearchParameter/clinical-code. The current source rework stores the Observation composite component definitions as the local code component, which the current generator resolves to the common clinical-code canonical in the built registry.

Additional context:
FHIR-17588 is a duplicate report of the same broken STU3 generated references, and the related Zulip thread confirms implementers hit the missing Observation-code canonical and identified clinical-code as the working replacement. The checked-in tools/history/release3/search-parameters.xml file and the frozen hl7.org STU3 artifact still show the old Observation-code references, but searches found no active current-build source reference to tools/history/release3, and the current active build output at build.fhir.org/search-parameters.json emits clinical-code for all four affected composite components and no Observation-code registry entry.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source under source/observation and source/searchparameter is already generating the correct clinical-code component references, and editing the historical generated STU3 release copy would not be a current-spec source fix.

Recommendation:
Keep this audit commit as-is for current FHIR core. If HL7 wants to correct frozen STU3 downloadable artifacts or checked-in historical release data, that should be a separate human-reviewed publication/history-maintenance decision rather than a current build source edit.
