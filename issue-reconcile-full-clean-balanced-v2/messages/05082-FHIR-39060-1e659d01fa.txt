FHIR-39060: Audit Requirements short description extension

Issue request:
FHIR-39060 was a Published FHIR-core change request for R5 asking to add a short description capability to the Requirements resource. The accepted Persuasive with Modification resolution was not to add a native Requirements.short element, but to add a 0..1 string shortDescription extension on CanonicalResource with a concise-display definition.

Initial application:
The source history shows the issue was applied in core by commit 5689da8ab51a6cbf3ad81dac36ba7ef6b96a1c38, which added StructureDefinition/canonicalresource-short-description and a CanonicalResource extension pack entry. A later core commit, dd468d4f1799dd79819315b211588ef1cf4586e0, removed that extension from the R5 core source as part of moving extensions out of the core checkout.

Additional context:
Requirements remains an active core resource in source/fhir.ini and uses the CanonicalResource template, so the original extension context covered Requirements without a bespoke Requirements element. The authoritative extension source now lives in the FHIR Extension Pack. There, canonicalresource-short-description is retired/deprecated and points to the later FHIR-51245 replacement, datatype-short-string, an active generic extension for shorter equivalents on string and markdown elements.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. Re-adding canonicalresource-short-description to core would duplicate an extension-pack artifact, and adding a new Requirements.short element would contradict the FHIR-39060 resolution and the later generic-extension direction. The current core checkout is correct to omit the moved extension definition.

Recommendation:
Keep this audit commit as-is for the core reconciliation. If future work is needed, handle it in the FHIR Extension Pack or through FHIR-I review of FHIR-51245/datatype-short-string guidance rather than by changing the core Requirements resource.
