FHIR-30769: Audit procedure-method cardinality

Issue request:
FHIR-30769 was a Published/Persuasive Patient Care change request for FHIR-core Procedure, applied for R5, asking that the standard extension http://hl7.org/fhir/StructureDefinition/procedure-method be changed from 0..1 to 0..* so a Procedure can carry multiple method descriptors. The Jira comments record the 2021-03-18 Patient Care discussion and Lloyd McKenzie's clarification that repeating a simple extension is valid and does not require making the extension complex.

Initial application:
The request was applied in HL7/fhir commit eaba8a86ff7df1b20b2e4972f1953a3e6be11e90, which changed source/procedure/structuredefinition-extension-procedure-method.xml from <max value="1"/> to <max value="*"/>. That matches the Jira resolution and was the expected R5 application.

Additional context:
The Procedure standard extension definitions were later removed from the core R5 source in commit dd468d4f1799dd79819315b211588ef1cf4586e0, "remove extensions from R5 source". The current core checkout has Procedure as an active resource and retains only the OID registry line for procedure-method; it has no active core StructureDefinition source for this extension. The current FHIR Extension Pack checkout is the active external source for the extension, includes input/definitions/* as resources, and its input/definitions/Procedure/StructureDefinition-procedure-method.xml already has <max value="*"/>.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The requested cardinality is already present in the current Extension Pack source, and the artifact's editable definition now belongs outside this FHIR core checkout, so this is an external-repo audit decision rather than a core fix.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed, and no Extension Pack follow-up is indicated unless future Extension Pack history changes the procedure-method cardinality away from 0..*.
