FHIR-14299: Audit CapabilityStatement imports application

Issue request:
FHIR-14299 was a Published FHIR-core/FHIR-I change request, resolved Persuasive with Modification for STU3. It asked for CapabilityStatement instances of kind=requirements to be able to import or nest other requirements CapabilityStatements, while clarifying that CapabilityStatement.instantiates is conformance to referenced statements and not import/inheritance of their content. The approved resolution added a non-normative 0..* canonical(CapabilityStatement) import/imports element and a usage note prohibiting overlap among imported CapabilityStatement content.

Initial application:
The issue was applied by git-svn commit 9ead3299c845b2925dd9482fbf9d43cd7b5136fe / SVN revision 14005, which changed the CapabilityStatement spreadsheet by tightening the instantiates definition and adding CapabilityStatement.imports with canonical(CapabilityStatement), summary=true, trial-use, and the original non-overlap and automatic-instantiates comments. The current source has since been refactored from the spreadsheet into source/capabilitystatement/structuredefinition-CapabilityStatement.xml, but the build-scoped resource still carries the applied element and instantiates wording.

Additional context:
The active source/fhir.ini [resources] entry includes capabilitystatement=CapabilityStatement, so the current StructureDefinition source is in build scope. A later related issue, FHIR-42824, observed that the original FHIR-14299 overlap comment was unclear beside the imports definition. FHIR-I minutes and the linked Zulip thread clarify that the importing CapabilityStatement may add or refine details from an imported statement, while sibling imports cannot overlap. The combined branch already contains commit 2f9c759f294a9f22f912e114356a08d9917e6e69 applying that clarification to the current source.

AutoFHIR reconciliation:
This commit makes no source change. The current combined-branch source already has CapabilityStatement.instantiates limited to implemented CapabilityStatements, CapabilityStatement.imports as 0..* canonical(CapabilityStatement), the automatic-instantiates note, and the later sibling-import overlap clarification that reconciles the original FHIR-14299 usage note with current implementer guidance.
