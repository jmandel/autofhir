FHIR-7384: Audit ServiceRequest proposal/order distinction

Issue request:
FHIR-7384 was Published with resolution Persuasive for the DSTU1 ProcedureRequest page. It asked to adopt wording that a Procedure Request can represent a planned, proposed, or ordered procedure, distinguished by the ProcedureRequestStatus field.

Initial application:
The issue was applied in commit 2541d8119ccdbc3c79db3d9f96713965e88eb912, which changed source/procedurerequest/procedurerequest-introduction.xml to add the requested planned/proposed/ordered sentence and identify ProcedureRequestStatus as the distinguishing field. Later ProcedureRequest history rewrote the same introductory text as part of FHIR-11119, then renamed ProcedureRequest to ServiceRequest under FHIR-13867.

Additional context:
ProcedureRequest is no longer a current resource in this build; source/fhir.ini now lists ServiceRequest as the active resource and work-group entry. The current ServiceRequest narrative explicitly says ServiceRequest represents an order, proposal, or plan and that ServiceRequest.intent identifies which kind it is. The StructureDefinition has a required ServiceRequest.intent bound to request-intent, and the request-intent code system defines proposal, plan, and order separately. This later request-pattern model supersedes the old ProcedureRequestStatus wording; re-adding status-based wording would be stale and semantically wrong. FHIR-11120 and OO minutes support the later split to request-pattern status values plus an intent element.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active ServiceRequest source preserves the implementer-facing distinction requested by FHIR-7384 through ServiceRequest.intent, and the obsolete ProcedureRequest source no longer exists in the current build.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-7384 unless a work group decides to revisit the broader request-pattern status/intent model.
