FHIR-5509: Audit ValueSet VSD alignment

Issue request:
FHIR-5509 is a Published DSTU1 Vocab change request for ValueSet. The ballot comment objected that FHIR should not define resources solely to represent value set definitions and should instead require only the elements needed to represent a single expansion. The recorded resolution was Considered - No action required, with WG policy to align with VSD and resolve differences where found.

Initial application:
The issue was applied historically despite the no-immediate-change resolution: commit 8c3627f2c2da2a6f21d4ca9b8a9bd68c137936b2, matching the Jira comment's svn revision 5593, added explicit Value Set Definition (VSD) and Content Logical Definition (CLD) wording to source/valueset/valueset-introduction.xml.

Additional context:
ValueSet is still an active resource in source/fhir.ini and its current introduction says ValueSet resources are used by StructureDefinition, OperationDefinition, Questionnaire, and other resources; are aligned with the VSD project; and use ValueSet.compose for the VSD Content Logical Definition. Later VSD-family work added detailed ValueSet/VSD alignment guidance in FHIR-36015 and removed the old VSD-aligned profile in FHIR-37923 after shareable/computable/publishable/executable profiles existed. No Zulip or Confluence search result was found that conflicts with the Jira/source history.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current built source already preserves the approved policy: FHIR continues to provide a ValueSet resource for sharing, reference, expansion, and terminology-service use while documenting how its definition surface aligns with VSD and where non-base VSD details are handled.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-5509; any future VSD alignment refinements should be handled through current Vocab trackers rather than reopening this DSTU1 no-action ballot item.
