FHIR-19468: Audit MedicationStatement not-taken handling

Issue request:
FHIR-19468 was a Published/Persuasive with Modification Pharmacy change request for R5 asking whether taken/not-taken needed to be restored to MedicationStatement. The approved resolution was to remove not-taken from MedicationUsage.status and use the adherence attribute, tracked by FHIR-19470, for taken/not-taken information.

Initial application:
The issue appears to have been applied in git commit f351511a95, which changed MedicationUsage for FHIR-19468/FHIR-19470/FHIR-28593 by removing the not-taken status semantics, making status describe the recording state, and adding MedicationUsage.adherence plus adherence terminology and examples.

Additional context:
FHIR-19470 supplied the paired adherence rename/addition and is already represented on the combined branch by commit 8912f00eea, which fixed the last stale adherence search-parameter path metadata. FHIR-28593, FHIR-32060, and FHIR-39271 later refined or reaffirmed the model that status records the statement state while adherence, effective[x], and examples represent taking/not-taking. FHIR-38682 renamed MedicationUsage back to MedicationStatement while keeping the adherence/status model.

AutoFHIR reconciliation:
This commit makes no source change. The current active MedicationStatement source in source/fhir.ini has status bound to recorded | entered-in-error | draft with no not-taken code, explicitly points status users to MedicationStatement.adherence, defines MedicationStatement.adherence and its example adherence value set, and includes a not-taking adherence code for the clinical statement that the medication is not being taken.

Recommendation:
Keep this no-change audit commit. FHIR-19468 is already correctly reflected in current MedicationStatement source; reopening the old status code or adding another taken/not-taken element would conflict with the later Pharmacy decisions that preserve adherence as the computable location for taking/not-taking.
