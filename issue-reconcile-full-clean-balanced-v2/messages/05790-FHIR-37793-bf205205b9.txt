FHIR-37793: Audit Reference ref-1 invariant guard

Issue request:
FHIR-37793 is a Published/Persuasive FHIR-core technical correction for the Reference datatype. It reported that invariant ref-1 failed Reference values that have only display because the local-reference expression evaluated against a missing reference element, and requested prefixing the expression with reference.exists() implies.

Initial application:
The requested source change was applied in the FHIR source history by 07c624bacb84caef7495c10ac04d70d39b397287, which added the reference.exists() implies guard to the ref-1 FHIRPath expression and the matching not(exists(f:reference)) XPath branch in source/datatypes/reference.xml. Commit d0d047e3b0ef986cdd8729e4c9ad26ab903bac7f preserved that corrected expression while normalizing the spreadsheet XML.

Additional context:
source/fhir.ini actively lists Reference as a datatype, marks it normative, and maps it to the ref constraint prefix, so source/datatypes/reference.xml is in current build scope. The linked Zulip discussion and related FHIRPath thread confirm the problem was the empty result from display-only Reference values and that the intended fix was the guard already present in current source. FHIR-31732 is background only: it made an earlier change to the same ref-1 invariant for container references using '#', and FHIR-37793 was a follow-up for absent reference values.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current Reference invariant already reads reference.exists() implies (reference.startsWith('#').not() or ...), and the XPath companion starts with not(exists(f:reference)), so display-only Reference values no longer fail ref-1 for the reported reason.

Recommendation:
Keep this no-change audit commit as-is. No FHIR-core source follow-up is needed for FHIR-37793; any remaining validator behavior differences belong in implementation-specific FHIRPath/validator issue tracking rather than this specification source.
