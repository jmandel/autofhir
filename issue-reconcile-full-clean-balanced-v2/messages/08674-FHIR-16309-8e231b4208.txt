FHIR-16309: Audit ElementDefinition slicing language

Issue request:
FHIR-16309 was a Published FHIR-core / FHIR-I change request, resolved Persuasive with Modification for STU3, asking to correct ElementDefinition slicing prose that described the first slicing entry as constraints for the "open" slice. The reporter explained that this entry constrains all slices, while @default is the construct for entries not in any named slice.

Initial application:
The issue appears to have been applied by git-svn commit 25e366a9a9c6bdc4ddf45684279322a3af0d1235 / svn revision 14065, which changed source/elementdefinition.html to add the @default bullet, replace the erroneous "open" slice description with text saying the first slicing entry applies to all slices and entries, and narrow the cardinality exception to min.

Additional context:
The linked Zulip thread records agreement that the previous "open" wording was ambiguous or wrong and should be crystal clear. ElementDefinition is active current-build source in source/fhir.ini and marked normative. The profiling page now separately documents @default slices. A later applied issue, FHIR-50391, refined the same ElementDefinition slicing paragraph by listing which constraints apply across all slices and how mustSupport/obligations should be read, preserving the FHIR-16309 premise.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/elementdefinition.html already says the first entry with slicing information is the set of constraints that applies to all slices and entries, not just the open slice, and no current source occurrence of the old "set of constraints to be used for the open slice" wording was found in the active page.

Recommendation:
Keep this no-change audit commit. Any future grammar or wording polish in this paragraph should be handled under a separate editorial issue because the semantic correction requested by FHIR-16309 is already present.
