FHIR-23029: Audit CareTeam encounter removal

Issue request:
FHIR-23029 was Published/Persuasive with Modification for R5. It originally asked to relax CareTeam.encounter from 0..1 to 0..*, but the PA/PC joint-session resolution instead voted to remove CareTeam.encounter and the EpisodeOfCare standard extension from CareTeam.

Initial application:
The issue was applied by git commit 4832b70ae3ebeefb51ab800a1200207eabd0313a, which removed the encounter reference from the CareTeam example and disabled the CareTeam.encounter element in the then-authoritative CareTeam spreadsheet. Current source has since been refactored to StructureDefinition XML; source/careteam/structuredefinition-CareTeam.xml no longer defines CareTeam.encounter or CareTeam.context, and source/fhir.ini records the R4/R5 map note that CareTeam.encounter was removed to avoid circular references since Encounter references CareTeam.

Additional context:
FHIR-23843 is the PA-side companion issue and added Encounter.careTeam 0..* Reference(CareTeam); current source/encounter/structuredefinition-Encounter.xml contains that element, and source/careteam/careteam-introduction.xml explains that CareTeam can be referenced by EpisodeOfCare, Encounter, or CarePlan. FHIR-32767 later added the Encounter careteam search parameter and is already represented on the combined branch by a separate source-fix commit. CareTeam and Encounter are active resources in source/fhir.ini. Exact Zulip issue-key searches found no directly relevant discussion, while Confluence references for FHIR-23843 confirm the PA follow-up to the PC removal.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The current build-scope core source already implements the final modified resolution: CareTeam no longer points to Encounter, the CareTeam example has no encounter, the workflow EpisodeOfCare extension is not used by CareTeam in core or allowed on CareTeam in the Extension Pack definition, and the inverse Encounter.careTeam relationship exists.

Recommendation:
Keep this audit commit as-is. Do not reintroduce CareTeam.encounter or add redundant CareTeam prose; the current model represents the approved direction by letting Encounter, EpisodeOfCare, and CarePlan reference CareTeam.
