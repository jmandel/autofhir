FHIR-5944: Audit ValueSet CLD clarification

Issue request:
FHIR-5944 was a Published/Persuasive Vocabulary change request from DSTU1 asking the specification to clarify which ValueSet elements constitute the VSD Content Logical Definition (CLD). The accepted resolution was to clarify that the then-current ValueSet.define plus ValueSet.compose made up the CLD and to update the documentation for the latest VSD specification.

Initial application:
The issue appears to have been applied in the old source as commit 8c3627f2, which added ValueSet narrative saying that compose and define make up the VSD Content Logical Definition. No commit explicitly mentions FHIR-5944, likely because the old migrated history used GForge/SVN issue numbers, but the applied wording directly matches the Jira request and timing.

Additional context:
Later terminology model changes changed the target source. FHIR-8354 renamed ValueSet.define to ValueSet.codeSystem, and commit fdf6e754 then removed inline code systems from ValueSet as part of the CodeSystem resource split. The current build has active ValueSet and CodeSystem resources in source/fhir.ini. Current ValueSet source has no ValueSet.define or ValueSet.codeSystem element, identifies ValueSet.compose as the CLD in both the resource narrative and StructureDefinition, and CodeSystem source separately describes publication of code system content.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Reintroducing the obsolete define/codeSystem wording would be wrong for the current model, and the authoritative current ValueSet source already clarifies the only remaining ValueSet element that constitutes the CLD: ValueSet.compose.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR core unless the Vocabulary/Terminology Infrastructure work group decides to redefine VSD CLD terminology for the modern split between ValueSet.compose and separate CodeSystem resources.
