Issue request:
FHIR-20588 was Applied/Persuasive with Modification for the OO work group and requested an explicit Observation.value warning that JSON parsing can lose integer or decimal numeric precision, with a link to the JSON representation of primitive elements section. The final resolution narrowed this to adding a bullet in Observation Section 10.1.5.6 under the existing Using codes for result values bullet.

Initial application:
The request was applied before this reconciliation by commit e92c9219ea0436ac800d2c037ed1a0446315044a, merged by PR 3519 as 3830c692487a0bcaa0ced143c7d47fbafbefe8b0. That commit added the approved bullet to source/observation/observation-notes.xml.

Additional context:
Observation is an active resource in source/fhir.ini, so source/observation/observation-notes.xml feeds the current build. The current Observation Value[x] and Datatypes section contains the exact approved bullet linking to json.html#primitive, and json.html already contains the primitive/decimal JSON warning about JavaScript JSON.parse(), trailing zeros, loss of precision, and custom parsers. OO minutes from 2025-05-30 note discussion of both .value[x] and .component.value[x], then record the decision to update Section 10.1.5.6 with a brief reference; the current component.value[x] element comment points readers to the Observation Notes section where this shared guidance lives. Jira and community searches did not find a later conflicting core decision.
