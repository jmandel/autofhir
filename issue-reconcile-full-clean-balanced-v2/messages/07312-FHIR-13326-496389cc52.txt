FHIR-13326: Clarify validate-code system inference

Issue request:
FHIR-13326 was a Published/Persuasive STU3 FHIR-core Vocabulary change request for ValueSet $validate-code. It reported that the code input parameter incorrectly said a system must be provided whenever code is provided, even though a client can validate a code-only value by supplying the value set context. The final resolution agreed and said a terminology server should return an error if the context is insufficient to unambiguously specify the concept.

Initial application:
The Jira comment records svn revision 12752. In the git-svn history, commit 5f4ae7c55f921bd724a82c59f79ee263e4b8445e changed the old ValueSet spreadsheet documentation from "If a code is provided, a system must be provided" to allow "a system or a context" and to require the server to ensure the system-less code is unambiguous. Later source refactoring preserved that wording in source/valueset/operationdefinition-ValueSet-validate-code.xml.

Additional context:
ValueSet is an active current-build resource in source/fhir.ini, and source/valueset/list-ValueSet-operations.xml references OperationDefinition/ValueSet-validate-code, so the edited OperationDefinition is authoritative current source. Later Applied issue FHIR-41431, already audited on the combined branch, added inferSystem to the same ValueSet $validate-code operation and changed the operation description to say that when code is provided either system or inferSystem SHOULD be provided. The latest combined source still had the older code-parameter sentence listing only system or context, which left the exact FHIR-13326 documentation location inconsistent with the later approved inferSystem path.

AutoFHIR reconciliation:
This commit updates only the ValueSet $validate-code code input documentation. The new sentence preserves FHIR-13326's system-less context allowance and ambiguity guard, while also recognizing that the server may infer the system from the value set context, including the context parameter or inferSystem=true.

Recommendation:
Keep this source fix as-is. It is a narrow correction to the build-scoped ValueSet operation definition; broader questions about inferSystem ambiguity or CQL string value-set membership should remain with later dedicated issues rather than this STU3 documentation correction.
