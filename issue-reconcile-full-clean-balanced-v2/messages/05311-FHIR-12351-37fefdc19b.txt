FHIR-12351: Audit HumanName rework application

Issue request:
FHIR-12351 was a Published/Persuasive DSTU2 MnM change request to rework HumanName for nl/de/es naming needs: make HumanName.family 0..1, keep the family string as the correct display value, add flat HumanName.family extensions for own/partner prefix and name plus mother/father family-name parts, add a HumanName assembly-order extension with v2/Dutch assembly-order codes, and clarify family-name search expectations.

Initial application:
The Jira comments record svn revision 10241. Git history maps that to 25c2c4b3101b908faefd466feecfb8b299ac68b6, '#12351 - family name changes', which changed source/datatypes/humanname.xml, added source/datatypes/humanname-extensions.xml, and registered the HumanName extension spreadsheet in source/fhir.ini. That commit changed HumanName.family from 0..* to 0..1, replaced the older multiple-family-name note with a decomposition-by-extension note, and added the requested flat extension/value-set definitions.

Additional context:
The related FHIR-12310 request for an iso21090 qualifier code was retracted in favor of the DevDays 2016 solution implemented by FHIR-12351: one family value such as 'van Wijk-de Boer' with flat extensions for its parts. In current R6 core, HumanName remains an active datatype and source/fhir.ini still contains the HumanName extension profile entry, but the specific common extension definitions have been moved out of core to the FHIR Extension Pack. The Extension Pack now carries the six HumanName.family part extensions, the HumanName assembly-order extension, and the name-assembly-order ValueSet; the ValueSet includes v2 assembly-order codes and the THO name-assembly-order CodeSystem provides NL1-NL4, while unknown is represented through v3 NullFlavor UNK rather than an NL0 code. Current search.html string-search rules ignore punctuation/non-significant whitespace and define :contains for Patient?family examples, and current Patient/Practitioner/Person/RelatedPerson family search parameters search a portion of name.family.

AutoFHIR reconciliation:
This is an empty audit commit. No FHIR core source change is needed: the active HumanName source preserves the cardinality and decomposition model requested by FHIR-12351, current search semantics cover the family-name search concern without duplicating resource-specific prose, and the requested extension artifacts are maintained in the Extension Pack rather than as core-local definitions.

Recommendation:
Keep this audit as-is. Future changes to the HumanName part extensions or assembly-order value set should be made in the FHIR Extension Pack or THO as appropriate, not by reintroducing duplicated core definitions. Revisit only if the build is expected to surface extension-pack HumanName links and those generated links are missing from the published extension-pack pages.
