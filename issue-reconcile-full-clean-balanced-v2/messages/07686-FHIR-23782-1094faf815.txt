FHIR-23782: Audit resource reference navigation

Issue request:
FHIR-23782 was a Published FHIR-core change request, resolved Persuasive with Modification for R5. It asked whether standard extensions and profiles should be visible from a resource's References section, using CatalogEntry and the Catalog profile on Composition as the motivating example. The approved resolution was to update References to show inbound reference counts by profile, resource, and extension, with expandable lists.

Initial application:
No core source commit explicitly mentions FHIR-23782. The current build/source expose the same navigational categories through generated resource tabs and pages: resource pages have a generated References-to-this-Resource section for resource references, generated Profiles pages list profiles such as ProfileForCatalog for Composition, and generated Extensions links point to the FHIR Extension Pack. The exact count-and-expand UI is publisher-generated behavior rather than authoritative resource prose in this checkout.

Additional context:
The motivating CatalogEntry resource was later removed from the current build by FHIR-28177, so its missing inbound reference list is no longer a current-spec defect. The Catalog artifact now appears as an active Composition profile in core source, and its required cqm-ValidityPeriod extension is maintained in the FHIR Extension Pack and linked from the generated profile/table output.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core source and generated pages already provide profile and extension discoverability for current artifacts, while adding static prose to resource pages would duplicate generated navigation and risk drift. A literal in-page expandable count feature, if still desired, belongs in publisher/tooling rather than in FHIR conformance source.

Recommendation:
Keep this no-change audit. Revisit only if FHIR-I wants the original count-and-expand UI literally implemented in the publisher; no current core source edit is needed to preserve the issue's implementer-facing intent.
