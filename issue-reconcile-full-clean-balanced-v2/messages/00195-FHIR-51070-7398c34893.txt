FHIR-51070: Audit Permission resourceType external scope

Issue request:
FHIR-51070 was an Applied Security WG change request, resolved Persuasive with Modification, asking for Permission rules to be able to address a FHIR resource type directly instead of relying on Reference.type. The approved resolution was to add a resourceType element to Permission.rule.data.

Initial application:
The issue was applied while Permission was still an active core resource. HL7/fhir PR #3614 merged on 2025-08-25, and its source commit fa24efed513cb3bd1f4f517940724fbe299df79d added Permission.rule.data.resourceType as a 0..* Coding element with an extensible binding to http://hl7.org/fhir/ValueSet/resource-types in source/permission/structuredefinition-Permission.xml.

Additional context:
Permission is no longer in the current core build. Later commit 0e2a8a7f839d5e1a43787523daccf07d958362f3 removed source/permission and the active permission entries from source/fhir.ini, and current core pages now link Permission to the HL7 Data Access Policies IG. The current HL7/data-access-policies source contains Permission.rule.data.resourceType, so the artifact that now owns Permission already carries the requested element.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. FHIR-51070 belongs outside the current FHIR core checkout because Permission has moved out of the active core build, and reintroducing or editing source/permission here would be stale and out of scope.

Recommendation:
Keep this audit commit as-is for core. Future changes to Permission.rule.data.resourceType should be made in HL7/data-access-policies unless core reintroduces Permission as an active resource.
