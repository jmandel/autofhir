FHIR-8234: Audit all-resource search parameters

Issue request:
FHIR-8234 was a Published/Persuasive with Modification FHIR-core HTTP search issue from DSTU1 asking what "the standard search parameters" meant when searching all resources at once, especially whether `_text`, `_content`, `_query`, and `_filter` were included and whether `_query` could be used at system level. The applied resolution was "as edited," with the editor comment that SVN revision 5347 aligned both relevant sources and treated `_filter` as special.

Initial application:
The issue was applied by git commit 18b42d91ae86b341b60128cf1bffd666879df42d (`#8234 - clarify search on all reosurces`, SVN revision 5347). That commit changed the HTTP page to link "parameters defined for all resources" to the Resource search-parameter list and updated the search page summary to include `_content` and `_query` while documenting `_filter` separately as a special search parameter.

Additional context:
Later search-page decisions refined the same topic without reversing FHIR-8234. FHIR-12985 added `_type` to the Resource search parameters; FHIR-13836 clarified that base searches with `_type` use parameters common to the selected types and base searches without `_type` use parameters common to all resource types; FHIR-36347 moved detailed multi-type/base-search parameter rules out of the HTTP page and into the main search page; and FHIR-42911 removed obsolete duplicate prose about `_text` and `_filter` after those parameters were already in the all-resources list. Current `source/fhir.ini` keeps Resource and SearchParameter source in the build, and the active search/http pages now point implementers to the same source of truth.

AutoFHIR reconciliation:
No source change was made. Current `source/search.html` already states that base searches without `_type` may use only the base parameters that apply to all resources, explains the multi-type `_type` case, and lists the common parameters for all resources including `_content`, `_filter`, `_query`, `_type`, and `_text`. Current `source/http.html` delegates all-resource and multiple-resource-type search parameter availability to `search.html#type`, avoiding the old duplicated wording that FHIR-36347 removed.

Recommendation:
Keep this empty no-change audit commit. The current specification preserves the FHIR-8234 clarification after later related decisions, and adding more local HTTP prose would reintroduce the duplication that later search-page work intentionally removed.
