FHIR-18833: Audit Condition clinicalStatus constraint history

Issue request:
FHIR-18833 was Published/Persuasive with Modification for STU3. It asked to remove the unconditional Condition.clinicalStatus requirement when verificationStatus was not entered-in-error; the approved modification made Condition.category 0..* with an extensible binding and changed con-3 to guide clinicalStatus for problem-list-item conditions while allowing point-in-time encounter diagnoses to omit it.

Initial application:
The issue was applied in two source commits against the historical Condition spreadsheet. Commit 3d048a25d4fb changed Condition.category from example to extensible, and commit 27de028df2d3 converted con-3 into a best-practice condition tied to problem-list-item category. The current build source has since moved to source/condition/structuredefinition-Condition.xml.

Additional context:
Later Patient Care decisions intentionally changed this area. FHIR-29409 (Published for R5) made Condition.clinicalStatus 1..1, added guidance allowing unknown for non-problem-list conditions, removed the old con-3 requirement, and loosened Condition.category to preferred; UP-280 then added the unknown condition-clinical code. FHIR-37986 confirmed unknown belongs in the clinicalStatus short display for encounter-diagnosis cases. FHIR-48358 (Applied for R6) later changed Condition.category to an example binding and removed the warning that problem-list-item clinicalStatus should not be unknown, and FHIR-54454 replaced the category short display with broad text. FHIR-54868 is a later Triaged request to make clinicalStatus optional again, but it is unresolved and not a final source-edit decision.

AutoFHIR reconciliation:
This commit makes no source change. The active Condition resource is in source/fhir.ini, and the current source no longer contains the FHIR-18833-era clinicalStatus-required con-3 rule or the extensible category binding. Instead, it reflects later final decisions: clinicalStatus is required with unknown available, category is example-bound, and con-3 now governs abatement consistency.

Recommendation:
Keep this no-change audit commit. Do not restore the STU3/R4-era con-3 or category binding as part of FHIR-18833; revisit only if Patient Care resolves a newer issue such as FHIR-54868 to change the R6 clinicalStatus cardinality or category guidance.
