FHIR-11217: Audit VisionPrescription boundary clarification

Issue request:
FHIR-11217 was an Applied/Not Persuasive with Modification OO change request raised against DSTU2 and applied for R6. The final decision kept VisionPrescription separate from SupplyRequest and DeviceUseRequest/DeviceRequest, noted that VisionPrescription represents an authorization and specification for lenses, deferred DeviceRequest reference handling to a separate Jira, and asked to clarify VisionPrescription scope/boundary text so it was not confused with SupplyRequest or other request resources.

Initial application:
The issue was explicitly applied in afb97a1aa6, which updated source/visionprescription/visionprescription-introduction.xml by labeling the VisionPrescription row as this resource and adding a SupplyRequest row that described inventory-management scope. Later source history refined the same area: b9a3457e2f updated the VisionPrescription table row wording through FHIR-51718, and 3b38b80cf2/01706a920f redirected SupplyRequest links to the OO Incubator after SupplyRequest left the active core build.

Additional context:
Current source/fhir.ini actively includes VisionPrescription and DeviceRequest but has no active SupplyRequest resource entry. Current VisionPrescription source describes authorization for corrective optical lenses, states that VisionPrescription is distinct from other health care authorizations, and has a Boundaries and Relationships table contrasting VisionPrescription with DeviceRequest, MedicationRequest, ServiceRequest, and externally hosted SupplyRequest inventory management. Current DeviceRequest source also has a VisionPrescription overlap paragraph, already audited for FHIR-40597; SupplyRequest/DeviceRequest separation was separately audited for FHIR-39066. Confluence minutes preserve the May 2023 work-group action to clarify this issue and create a separate DeviceRequest/VisionPrescription reference Jira, now FHIR-51718.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current core source already conveys the FHIR-11217 decision: VisionPrescription remains its own resource for authorized lens specifications, SupplyRequest is identified as inventory management rather than a patient-focused lens authorization, and the DeviceRequest overlap is addressed without folding VisionPrescription into DeviceRequest.

Recommendation:
Keep this no-change audit commit as-is. No FHIR core source fix is needed for FHIR-11217; future changes to the DeviceRequest/VisionPrescription request-pattern relationship should proceed through the separate follow-up issue family, including FHIR-51718.
