FHIR-14887: Audit excludeNotForUI documentation

Issue request:
FHIR-14887 was a Published/Not Persuasive with Modification vocab change request from the STU3 ballot. It asked to generalize ExpansionProfile.excludeNotForUI because different code systems identify UI or not-for-UI concepts using different properties; the final decision did not add a property/value parameter and instead required clearer documentation of how excludeNotForUI relates to ValueSet.expansion.contains.abstract and different code-system use cases.

Initial application:
The issue was applied in svn revision 14641, represented in git as f77fc64d65070801355d2681468555ecd7adc10c, which changed the then-authoritative ValueSet spreadsheet documentation for excludeNotForUI to describe UI-oriented expansions, abstract or no-code navigation concepts, code-system-specific properties, and FHIR build usage. Later source refactoring moved the authoritative operation definition to source/valueset/operationdefinition-ValueSet-expand.xml.

Additional context:
ExpansionProfile is no longer a current build resource; source/fhir.ini keeps ValueSet active and records ExpansionProfile as dropped. The active ValueSet/$expand operation definition now documents excludeNotForUI in terms of CodeSystem notSelectable=true, nested contains with no code, nested contains with abstract=true, and the FHIR Specification's false-for-rendered-expansions/true-for-validation generation practice. Later Published issue FHIR-30700 revisited the same parameter, kept the existing name, and replaced the description with the current notSelectable/no-code/abstract formulation; FHIR-30700 is already represented on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already carries the necessary clarification for implementers, and adding a generic property/value parameter or restoring broader old wording would contradict the final FHIR-14887 disposition and later FHIR-30700 refinement.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-14887 unless a future vocab decision reopens the broader design of UI/navigation filtering in ValueSet expansion.
