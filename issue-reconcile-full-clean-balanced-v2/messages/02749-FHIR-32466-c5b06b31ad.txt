FHIR-32466: Audit removed AuditEvent entity type

Issue request:
FHIR-32466 was a Published/Persuasive R5 Security issue objecting that AuditEvent.entity.type used an extensible value set with overlapping resource-type and DICOM identifier-style codes. Its final resolution was to remove AuditEvent.entity.type because AuditEvent.entity.what is a Reference.

Initial application:
The same AuditEvent block-vote family was applied through 1495aa7007492c9a1406bcaac23a3becdbdedadf for FHIR-32467, which removed the AuditEvent.entity.type element and moved the DICOM ParticipantObjectTypeCode mapping onto AuditEvent.entity.what. The later security block-vote update commit 3d204189e23e03f0b4f11d03d491bc1d868e399b included FHIR-32466 in the same applied change set, and the combined-branch FHIR-32467 reconciliation removed the remaining stale narrative reference to entity.type.

Additional context:
FHIR-12677 is the earlier DSTU2 issue that originally added FHIR Resource types to the AuditEvent entity type value set. FHIR-32466 supersedes that old mechanism for current core by eliminating the element that used the value set. Security WG Confluence minutes and the linked Zulip block-vote thread list FHIR-32466 as Persuasive in the September 13, 2021 AuditEvent block vote.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. Current source/auditevent/structuredefinition-AuditEvent.xml has no AuditEvent.entity.type element, defines AuditEvent.entity.what as Reference(Resource), and maps ParticipantObjectTypeCode through entity.what. Current-source searches found no remaining authoritative AuditEvent.entity.type guidance.

Recommendation:
Keep this audit commit as-is. No further core source work is needed for FHIR-32466; any future terminology work on the unbound audit-entity-type value set should be handled as a separate cleanup, not as a reversal of the entity.type removal.
