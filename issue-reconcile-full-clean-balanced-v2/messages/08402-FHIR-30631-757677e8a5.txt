FHIR-30631: Audit CapabilityStatement search modifier guidance

Issue request:
FHIR-30631 was a Published FHIR-core change request with resolution Persuasive with Modification. It asked how CapabilityStatement communicates support for modifiers such as code:in, and the final resolution required guidance that referencing a base SearchParameter implies support for the type-permitted modifiers/comparators unless the implementation defines its own SearchParameter, potentially contained in the CapabilityStatement.

Initial application:
The issue was previously applied by git commit 9aed2168cb9c41336947ce1c6ba438be49116a20, "FHIR-30631 - modifier conformance expectations", which added the conformance guidance to source/search.html under the Standard Parameters section linked by the Jira. The commit is contained in the v5.0.0 tag, matching the issue's Applied for Version R5.

Additional context:
The current source still contains the FHIR-30631 rule in source/search.html: a referenced base SearchParameter that does not enumerate modifiers/comparators implies support for all permitted modifiers and prefixes for the search type; restricting modifier support requires a local SearchParameter that should inherit from the original, and local definitions must be available through [base]/SearchParameter or contained in CapabilityStatement. The CapabilityStatement searchParam.definition element also points implementers to SearchParameter resources for documenting modifiers and comparators. The 2021 Zulip thread and 2022 FHIR-I minutes support the same interpretation, and no linked Jira issue or later source history found during this reconciliation reverses it.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Adding the same rule again to CapabilityStatement.rest.resource.searchParam.definition would duplicate active guidance already present in the current Search page at the Jira's related section and would risk future drift without changing implementer understanding.

Recommendation:
Keep this no-change audit commit as-is. No core source follow-up is recommended unless the work group wants to relocate or duplicate the existing Search page guidance into the CapabilityStatement element definition as an editorial restructuring.
