FHIR-23568: Audit Attachment size metadata status

Issue request:
FHIR-23568 was Published/Persuasive with Modification for R5. It asked to add Media-derived size metadata to the Attachment datatype as part of the Media-to-DocumentReference merge, with the modification that the new elements be marked STU.

Initial application:
The Media merge commit added the Attachment metadata elements, and the explicit FHIR-23568 follow-up commit 63ea1b517f added a Standards-Status column with trial-use values for Attachment.height, Attachment.width, Attachment.frames, Attachment.duration, and Attachment.pages.

Additional context:
Attachment is an active datatype in source/fhir.ini and current source/datatypes/attachment.xml still contains the five requested elements. A later R6 normative cleanup, including commit 7466cfc63c, removed the per-element trial-use markers, and source/versions.html now states that no content in the current specification is considered trial-use. The related OO issue FHIR-23567 explains the same Media-to-DocumentReference change family but does not require a separate decision here.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Re-adding the old STU markers would conflict with the later current-build standards-status policy, while the substantive Attachment elements requested by FHIR-23568 remain present in build-scoped source.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is recommended unless a future work group decision reverses the R6 all-normative/current no-trial-use policy for these Attachment elements.
