FHIR-32774: Keep Condition organization-free after later reversal

Issue request:
FHIR-32774 was a Published/Persuasive Patient Care change request for R5 asking that Condition.recorder and Condition.asserter allow Organization because implementers may know only the organization that recorded or asserted a Condition. Jira records the issue as addressed through FHIR-34395 rather than as a direct edit to the two original R4 elements.

Initial application:
FHIR-34395 initially applied the request by replacing Condition.recorder and Condition.asserter with Condition.participant and Condition.participant.actor. Commit 431d503d4443c0860a10a57b4704b1f0876ab099 added Organization and CareTeam to Condition.participant.actor, which satisfied the Organization use case while that R5 participant pattern was active.

Additional context:
FHIR-39602 is a later Applied/Persuasive with Modification Patient Care decision on the same Condition source. It replaced Condition.participant with explicit Condition.recorder and Condition.asserter again and explicitly states that Organization should not be supported because PractitionerRole can support that use case. Commit ed99dff49083a274e14bef2e2db9dcb3b39913b9 implemented that reversal. FHIR-41403 later added Group to both active elements, confirming that recorder/asserter target changes continue to be made explicitly when approved. The current Condition StructureDefinition is in build scope through source/fhir.ini and has active recorder/asserter elements without Organization; the old participant block containing Organization is commented out. The checked-in condition.svg still appears to show the old participant/Organization rendering, but that is a generated-looking diagram artifact and is not the authoritative source to edit for this issue.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative Condition source matches the later FHIR-39602 reversal that supersedes the Organization aspect of FHIR-32774 for the current build.

Recommendation:
Keep this no-change audit. If Patient Care wants Organization restored, open or apply a new decision that explicitly reverses FHIR-39602 and then update the authoritative Condition StructureDefinition and any generated diagrams together.
