FHIR-7902: Audit core profile extension guidance

Issue request:
FHIR-7902 was a Published/Persuasive with Modification DSTU1 change request asking why FHIR Core Profile extensions, specifically the FHIR Core Goal Profile, were not instead core resource elements. The approved resolution said the Defining Extensions guidance should explain that extensions are defined when the 80-percent/core-element threshold is uncertain or not met, but the concept is still useful enough to standardize.

Initial application:
The issue appears to have been applied in git-svn commit 670cce6d0442b1b898ca8f9c9160ec1d73fbe4ed, matching Jira comment "SVN #6777". That commit added a "Core Elements" subsection to source/defining-extensions.html explaining that resource and datatype elements are included in core based on current worldwide usage, and otherwise remain extensions; commit 9cf34511a41da2cf55df5f4c9672471d8d05a504 immediately corrected wording without changing that rule.

Additional context:
The current source still includes the active Defining Extensions page in source/hierarchy.xml and preserves the relevant guidance in source/defining-extensions.html. It also retains nearby HL7 extension-publishing guidance explaining why HL7 publishes standard extensions outside the base resource structure and how broadly adopted extensions relate to core elements. Searches of local Jira, Zulip, and Confluence evidence found no later directly relevant decision that reverses or narrows FHIR-7902.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-source guidance already answers the issue: core elements are reserved for concepts used by a significant majority of worldwide systems, while other useful or emerging concepts are represented as extensions and can still be published or balloted by HL7.

Keep this no-change audit commit. No follow-up source edit is needed for FHIR-7902 unless a future work group wants to revisit the broader extension/core-element policy.
