FHIR-13178: Audit XML declaration in sample pages

Issue request:
FHIR-13178 was a Published/Persuasive FHIR-core Feed issue raised against DSTU2 and applied for STU3. It requested that the Bundle transaction XML sample page include the XML declaration `<?xml version="1.0" encoding="UTF-8"?>` and that the same omission be handled wherever the tooling rendered XML samples.

Initial application:
The Jira comment says `svn 14819`. That maps to Git commit 2d6d6397e018c7481fd21145a2b280195cda1fbf (`GF#13178 - fix example xml`), which changed the then-current `XhtmlGenerator.java` tooling to emit an escaped XML declaration at the start of adorned XML example blocks. That Java tooling was later moved to `implementations/java/old/...` and removed during the 2019 refactor, so the original in-repository tooling target no longer exists in the current checkout.

Additional context:
`source/fhir.ini` still lists Bundle as an active resource, and `source/bundle/bundle-transaction.xml` now starts with the XML declaration. The current build is driven through the external `org.hl7.fhir:kindling` dependency. Current published surfaces for both `build.fhir.org/bundle-transaction.xml.html` and `hl7.org/fhir/bundle-transaction.xml.html` include the escaped XML declaration in the displayed XML sample, while `build.fhir.org/bundle-transaction.xml` begins with the raw XML declaration. FHIR-I minutes from 2018-07-09 list tracker 13178 as Persuasive, and no relevant Zulip or conflicting Confluence evidence was found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative source example is in build scope and already carries the declaration, and the current generated/public XML sample surfaces already render it. The retired Java file changed by the original application is no longer part of this repository's current build path.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed unless a future generated build regresses; any future tooling regression should be handled in the current Kindling/publisher source rather than by reviving retired in-repository tooling.
