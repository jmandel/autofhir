Issue request:
FHIR-20600 is a Published/Persuasive FHIR-core Questionnaire tracker asking for an extension to control questionnaire flow: whether users see only the current question, current and prior questions, or all questions in arbitrary order.

Initial application:
The Jira comment cites Git#d47cc1b, but that short SHA is not present in the current HL7/fhir history or in GitHub for HL7/fhir. The matching applied artifact is the SDC `sdc-questionnaire-entryMode` extension, already visible in the May 2019 SDC publication with the same current/prior/random flow semantics.

Additional context:
Current FHIR core builds Questionnaire as an active resource and explicitly directs advanced rendering, question flow, and data-management behavior to the Structured Data Capture implementation guide. Current HL7/sdc source owns `StructureDefinition/sdc-questionnaire-entryMode`, its `entryMode` code system/value set, and later FHIR-37497 refinements to validation and paging semantics. Core source and the FHIR Extension Pack do not own this SDC-canonical extension.

Recommendation:
Keep this audit commit as-is for FHIR core. Future corrections to entryMode definitions, codes, examples, or behavior guidance should be made in HL7/sdc; core should continue to rely on the existing Questionnaire page references to SDC for advanced question-flow behavior.
