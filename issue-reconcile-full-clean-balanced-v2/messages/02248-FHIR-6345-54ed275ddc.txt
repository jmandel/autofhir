FHIR-6345: Audit DocumentReference type/category clarity

Issue request:
FHIR-6345 was a Published/Persuasive with Modification DSTU1 FHIR-core change request for DocumentReference. It said the old DocumentReference.type and DocumentReference.class definitions and examples did not make their distinction clear, asked to collapse them if possible, and otherwise asked for clarification. The final resolution directed applying the same change family as FHIR-8057 to DocumentReference and, as applicable, DocumentManifest.

Initial application:
The historical application is git-svn commit 318450243d32ceebfb0ec4ff0afe2a63bb3f02c4 (svn r6702), whose message explicitly closed #6345 with related Structured Documents issues. In that commit, DocumentReference.type changed from a generic "Kind of document" definition to "Kind of document (LOINC if possible)" with examples such as History and Physical, Discharge Summary, and Progress Note, while DocumentReference.class was clarified as a categorization for the type of document referenced that helps indexing/searching and may be implied by or derived from DocumentReference.type. The same commit also touched DocumentManifest, but that resource is no longer part of the current build.

Additional context:
FHIR-8057 is the same-change-family issue referenced by the FHIR-6345 resolution and is already represented on the combined branch by a no-change audit commit. Later published FHIR-17171 renamed DocumentReference.class to DocumentReference.category and increased cardinality to 0..*; that issue is also already represented on the combined branch, including a fix for a stale class reference. Current source/fhir.ini lists DocumentReference as an active resource, maps the old DocumentReference.class name to DocumentReference.category for version conversion, and lists DocumentManifest only under removed resources with its work-group entry commented out. Current DocumentReference.type/category definitions preserve the intended distinction: type is the particular document kind, while category is broader indexing/search metadata implied by or derived from type.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active DocumentReference source already conveys the clarified type/category distinction requested by FHIR-6345 after later class-to-category renaming, and editing removed DocumentManifest source is not a current-spec fix because there is no active DocumentManifest source directory or resource entry. The only remaining cosmetic wording nits in current comments do not change implementer understanding and do not justify a source-changing reconciliation commit.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-6345; future work, if any, should be limited to separately approved editorial cleanup or independent category terminology issues rather than reopening the resolved type/category distinction.
