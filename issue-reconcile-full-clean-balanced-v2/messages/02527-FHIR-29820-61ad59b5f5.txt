FHIR-29820: Audit Person deceased support

Issue request:
FHIR-29820 was a Published/Persuasive PA change request asking for Person to express death as date/indicator, like Patient, to support FHIR facades over national person indexes. Its resolution required a deceased date/bool property on Person and a matching search parameter.

Initial application:
The source history shows the Person.deceased[x] element was added in commit 1bf9c6c3a6 as part of the tightly related FHIR-20771 Person additions, and the FHIR-29820-tagged commit d6853ff75e added the Person death-date and deceased search parameters the next day. Later maintenance commits normalized XPath/as() search-parameter syntax and standards-status values without removing the requested semantics.

Additional context:
PA January 2021 WGM minutes record discussion that Person indexes are in FHIR scope and disposition FHIR-29820 as persuasive by a 6-0-0 vote. FHIR-20771 is the same change family and explicitly says the deceased property was approved under FHIR-29820. The current build scope includes Person as an active resource in source/fhir.ini, and the current Person source contains both boolean/dateTime deceased[x] and death-date/deceased search parameters.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because the current authoritative source already provides the requested Person deceased date/indicator element and the corresponding search parameters.

Recommendation:
Keep this audit commit as-is. If a future work group wants Person.deceased[x] to copy Patient's exact definition text or modifier flag, that should be a separate substantive decision; FHIR-29820's resolved date/bool and search-parameter requirement is already satisfied.
