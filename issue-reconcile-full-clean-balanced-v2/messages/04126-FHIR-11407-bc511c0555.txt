FHIR-11407: Audit batch claim documentation

Issue request:
FHIR-11407 was a Published FHIR-core Financial Management change request from the DSTU2 ballot asking to add a section detailing Batch Claim submissions. The Jira resolution was Not Persuasive with a note to consider the request for STU R4, and the later Jira comment states that the concerns were addressed in the materials published in R4.

Initial application:
No commit explicitly mentioning FHIR-11407 was found in the local git history. The current batch-claims material appears to have been applied implicitly before R4 by commit f4c5e91b2ad6dc71145fc8b6f7942413c4eca3cd, which added the Financial module batch section describing individual eClaim requests and eClaim batches; commit e763f3562d184162254f08f9234dbd2d650941a3 then made QA wording corrections in the same section.

Additional context:
The authoritative current source page is in build scope because source/hierarchy.xml lists financial-module.html as the Financial module page. The current source contains a dedicated Batches section explaining that eClaim request and response resources may be exchanged individually or via batches, that an individual Claim may be sent as a Claim or Bundle, and that an eClaim batch is a Bundle containing one or more eClaim requests or responses. The Claim $submit OperationDefinition also recognizes a Bundle containing a batch of Claim resources. The R4 published financial-module.html contains the same batch section, matching the Jira comment that R4 materials addressed the concern. Jira/community searches found no later conflicting decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped source already contains the requested batch-claim submission guidance, and adding redundant prose would not improve implementer understanding.

Recommendation:
Keep this no-change audit commit as-is. No follow-up is needed for FHIR-11407 unless the Financial Management work group wants new requirements beyond the R4 batch section and the existing Claim $submit operation description.
