FHIR-28921: Audit cqf-certainty extension externalization

Issue request:
FHIR-28921 was Published/Persuasive for R5 from the CDS work group. It asked to define a cqf-certainty extension with the same structure as Evidence.certainty and to allow that extension on PlanDefinition, ActivityDefinition, Library, Measure, and cqf-certainty.

Initial application:
The issue was initially applied in core by c7b65a0fc7, which added the certainty extension rows to source/profiles/clinicalreasoning-extensions-spreadsheet.xml and linked the new extension from the Clinical Reasoning module. The later core history removed the Clinical Reasoning extension definitions from core in dd468d4f17 and rewrote the Clinical Reasoning links to the external extension location in b3e373388f. Current core retains only the Clinical Reasoning table link and the cqf-certainty OID assignment.

Additional context:
The FHIR Extension Pack is now the maintained home for standard extensions referenced by core. Its current input/definitions/Element/StructureDefinition-cqf-certainty.xml contains the cqf-certainty StructureDefinition, including the original slices for description, note, type, rating, and rater, and FHIR-50950 later updated its bindings to THO value sets there. Current core Evidence.certainty has since changed through later core decisions: FHIR-39572 changed Evidence.certainty.description to markdown, and FHIR-48987 changed Evidence.certainty.rater to 0..*. Those later changes affect whether the extension should still mirror the current Evidence.certainty structure, but the authoritative edit point for cqf-certainty is now the Extension Pack, not this core checkout.

AutoFHIR reconciliation:
This commit intentionally makes no core source change and records an external-repo audit decision. The current core source is not missing an in-scope extension definition; it correctly points to the external extension location, while any shape alignment for cqf-certainty belongs in HL7/fhir-extensions.

Recommendation:
Keep this core audit commit as-is. As follow-up outside this repository, the CDS/FHIR Extension Pack maintainers should review whether cqf-certainty should be updated to track the later Evidence.certainty markdown description and repeatable rater changes; that should be handled by an Extension Pack issue or PR rather than by reintroducing the extension definition into core.
