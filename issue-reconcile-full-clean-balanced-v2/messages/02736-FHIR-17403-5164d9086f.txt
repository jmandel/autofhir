FHIR-17403: Audit Timing datatype hierarchy

Issue request:
FHIR-17403 was a Published/Persuasive STU3 technical correction asking that the Timing datatype Structure and UML views agree by showing Timing as a BackboneElement rather than as Element while still allowing modifierExtension.

Initial application:
The issue was applied in SVN revision 14165, represented in git as ada2e0c9c1c1d9f55da7212a82d639e2dad4832f, which changed the root Timing row in source/datatypes/timing.xml from Structure to BackboneElement. No source change is missing from that original application.

Additional context:
The current build source no longer uses the STU3 literal BackboneElement hierarchy for datatype roots that carry modifier extensions. Commit cbdf7d1e55dc4bfa1dc30fc526edee0491e05782 rebuilt the abstract datatype framework, introduced BackboneType, and changed Timing from BackboneElement to BackboneType. Current source/fhir.ini keeps the datatypes page and datatype diagrams in active build scope, marks Timing and BackboneType normative, and source/datatypes/backbonetype.xml defines BackboneType as the DataType-derived base for datatypes that can carry modifierExtension while source/datatypes/backboneelement.xml reserves BackboneElement for elements inside resources. Later FHIR-26878 also treats Timing as a BackboneType subclass. FHIR-50466 and the committers Zulip thread show a separate unresolved rendering/display concern around Structure tables, but that issue is Triaged and is not a final source-edit decision for this applied/published seed.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source edits. Current authoritative source already expresses the current equivalent of the FHIR-17403 correction: Timing derives from BackboneType and the active diagrams include BackboneType with Timing underneath it. Reverting Timing to BackboneElement would be wrong for the current abstract datatype framework.

Recommendation:
Keep this no-change audit as-is for FHIR-17403. If the rendered Structure table still hides BackboneType for Timing, handle that separately under the unresolved FHIR-50466/tooling path rather than changing the current Timing source hierarchy back to BackboneElement.
