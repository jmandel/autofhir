FHIR-17426: Audit SUBSETTED update guidance

Issue request:
FHIR-17426 was a Published FHIR-I issue, resolved Not Persuasive with Modification for R5. It asked whether SUBSETTED should be described as useful when data is pushed, not only when query results are reduced with _summary. The final resolution rejected broad push guidance, said PATCH is the only safe way to pass a record without all data when minimizing volume is the objective, and required focused guidance for POST/PUT requests tagged SUBSETTED, the safety checklist, and the updates.html discussion.

Initial application:
No correctly tagged FHIR-17426 implementation commit was found in git history. The 2022-02-21 commit 7ad9e8aa04cfb006e56bbb40316234270869e91b has the subject "FHIR#17462" but changed source/http.html, source/safety.html, and source/updates.html in exactly the way FHIR-17426 requested; FHIR-17462 itself is an unrelated marital-status-code-system issue, so the subject appears to be a transposed Jira key. Later history refined the same source area: FHIR-32757 removed an incorrect SUBSETTED-as-security-label sentence from updates.html while preserving the FHIR-17426 server-discretion guidance, and FHIR-22500 reconciliation mirrored the FHIR-17426 safety checklist item into the active safety-entries CodeSystem.

Additional context:
Current source/http.html is the active REST (HTTP) narrative page listed in source/navigation.xml, source/updates.html is linked from the REST update discussion, source/safety.html is the current safety checklist page, and source/fhir.ini actively registers source/codesystem/codesystem-safety-entries.xml as the safety-entries CodeSystem. A 2021 Zulip thread about SUBSETTED tags and create/update asked whether servers should prevent create/update with SUBSETTED-tagged resources; John Moehrke answered that this was the implied guidance. FHIR-I Confluence minutes show the issue was sent back for feedback on 2022-01-10 and then accepted as Not Persuasive with Modification by 18-0-0 vote on 2022-01-31.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current spec already implements the final FHIR-17426 decision: source/http.html warns on update and create that servers decide whether to accept SUBSETTED-tagged requests and how to handle them; source/updates.html covers the same server discretion plus accidental data-loss and invalidation risks; source/safety.html and the active safety-entries CodeSystem include the limited-access SUBSETTED update/create checklist item. Adding broader push-language would go beyond, and partly against, the final Not Persuasive with Modification resolution.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for FHIR-17426 unless the work group opens a new issue to define broader non-query or push semantics for SUBSETTED.
