FHIR-19713: Audit RequestGroup Expression use

Issue request:
FHIR-19713 was Published/Persuasive for the CDS work group and requested that RequestGroup use the Expression data type for the condition elements defining the condition expression.

Initial application:
The issue was applied in git commit 3d3f19734c8bd5f1e5c836a6da6640f5c13722cb, which updated the RequestGroup spreadsheet so RequestGroup.action.condition.expression changed from string to Expression and removed the separate condition description/language rows superseded by the Expression datatype.

Additional context:
FHIR-24619 later renamed RequestGroup to RequestOrchestration for R5, and commit 46bea37a00e63d1ace04a5f322614c6d0815f500 carried the resource forward under the new name. The current build has requestorchestration as an active resource in source/fhir.ini and maps the old RequestGroup name to RequestOrchestration for compatibility.

AutoFHIR reconciliation:
No source change was made. The active RequestOrchestration definition already has RequestOrchestration.action.condition.expression typed as Expression, so the current specification preserves the FHIR-19713 requirement in the renamed resource.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-19713 unless a future work group decision changes the condition expression model.
