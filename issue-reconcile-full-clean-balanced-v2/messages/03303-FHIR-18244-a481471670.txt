FHIR-18244: Audit CDS Hooks RequestGroup profile move

Issue request:
FHIR-18244 was Published/Persuasive for STU3 by the CDS work group. It requested defining a profile of RequestGroup to support mapping a CDS Hooks response, with the approved resolution to add a CDSHooksRequestGroup profile.

Initial application:
The issue was applied by commit 38e5905c42, which added source/requestgroup/requestgroup-cdshooks-spreadsheet.xml as the CDSHooksRequestGroup profile. Later source-rework history deleted that legacy RequestGroup spreadsheet as RequestGroup was removed and current core moved to RequestOrchestration.

Additional context:
FHIR-48393 and FHIR-53085 are later Applied/Persuasive CDS decisions for R6 that remove CDS Hooks-related profiles and move the CDS-on-FHIR page content, PlanDefinition/RequestOrchestration/GuidanceResponse CDS Hooks profiles, and mapping concept maps out of FHIR core into the Using FHIR Clinical Reasoning with CDS Hooks IG. The current core build has RequestOrchestration as the active resource and RequestGroup in removed resources; the active [profiles] list does not include CDSHooksRequestGroup or CDSHooksRequestOrchestration. The current clinicalreasoning-cds-on-fhir page is informative and points readers to the external IG. The external HL7/cds-hooks-clinical-reasoning repository contains StructureDefinition-cdshooksrequestgroup.json defining CDSHooksRequestGroup.

AutoFHIR reconciliation:
No source change was made. Reintroducing a core CDSHooksRequestGroup/RequestOrchestration profile would conflict with the later R6 decisions to remove these profiles from the base specification and host the CDS Hooks clinical reasoning material in the dedicated IG.

Recommendation:
Keep this audit commit as-is. The current FHIR core source is correct for FHIR-18244 after considering the later profile-move decisions; any future changes to the CDSHooksRequestGroup profile should be made in the Using FHIR Clinical Reasoning with CDS Hooks IG, not in core.
