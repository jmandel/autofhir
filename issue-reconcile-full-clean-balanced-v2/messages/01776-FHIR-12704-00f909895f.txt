FHIR-12704: Audit Consent policyRule inversion

Issue request:
FHIR-12704 was Published/Persuasive for FHIR-core Consent. It reported that the DSTU2 Consent policyRule magic values for opt-in and opt-out were logically inverted for the Consent record perspective, and the resolution accepted the problem while noting that using permit and deny, as with exceptions, was an alternative to continuing the opt-in/opt-out labels.

Initial application:
The issue was explicitly applied in git commit 687d10304fe8c9e42f5ff4e7ff3c322653b167f4, which listed GF#12704 and flipped the affected Consent examples so opt-in examples represented generally approved sharing and opt-out examples represented generally denied sharing. The old application occurred in active Consent source files before later Consent model refactors.

Additional context:
Consent remains an active current-build resource in source/fhir.ini. Later Published issue FHIR-13358 retired the old http://hl7.org/fhir/ConsentPolicy/opt-in and /opt-out magic URIs by changing policyRule to a CodeableConcept based on ActConsentDecision, and later Published issue FHIR-32817 replaced the old policy/policyRule structure with regulatoryBasis, policyBasis, policyText, and an explicit permit/deny decision model. Current R4/R6 mapping records old Consent.policyRule as migrated to current policy text, while current examples and narrative use Consent.decision permit/deny rather than relying on the old magic URI definitions. Related FHIR-27774 also confirms later WG preference to say permit/deny instead of opt-in/opt-out for the base policy sentence.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current authoritative source has no active Consent.policyRule element and no remaining http://hl7.org/fhir/ConsentPolicy/opt-in or /opt-out magic URI usage. Current Consent source states the base decision directly as permit or deny, and the remaining opt-in/opt-out example comments are aligned with the post-FHIR-12704 applied semantics.

Recommendation:
Keep this no-change audit. No FHIR core source edit is needed for FHIR-12704; any future terminology cleanup of historical opt-in/opt-out labels or external HL7 Terminology content should be handled as a separate issue because the current Consent conformance model no longer depends on the inverted magic policyRule definitions.
