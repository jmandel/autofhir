FHIR-7634: Audit Procedure note Annotation resolution

Issue request:
FHIR-7634 was Published/Persuasive with Modification for DSTU1 ProcedureRequest, asking to reconcile Procedure.notes and ProcedureRequest.notes after Procedure was 0..1 while ProcedureRequest was 0..*. The accepted resolution was to adopt the MnM agreement of 0..* Annotation.

Initial application:
The application appears in historical commit 2541d8119c, which changed Procedure.notes from 0..1 string to 0..* Annotation and changed ProcedureRequest.notes from string to Annotation while preserving its 0..* cardinality. Later workflow/source refactors renamed notes to note and retained the cardinality and Annotation datatype.

Additional context:
Procedure and ServiceRequest are active current resources in source/fhir.ini. ProcedureRequest is no longer an active current resource; fhir.ini records that it was merged into ServiceRequest, and git history shows GF#13867 renamed ProcedureRequest to ServiceRequest. FHIR-7633 is the adjacent alignment issue that also says notes should be 0..* Annotation, and FHIR-10293 later renamed notes to note without changing the 0..* Annotation resolution.

AutoFHIR reconciliation:
No source change was made because current Procedure.note and ServiceRequest.note already have min 0, max *, and type Annotation in the active build source. Editing ProcedureRequest source would be out of current build scope, and adding redundant prose would not change implementer understanding.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-7634 unless a future review wants to clean non-normative historical committee-note tags separately from this issue.
