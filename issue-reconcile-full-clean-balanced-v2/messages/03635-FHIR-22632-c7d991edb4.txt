FHIR-22632: Audit ConceptMap relationship changes

Issue request:
FHIR-22632 was Published/Persuasive with Modification for R5. It summarized the May 2019 Vocabulary WG ConceptMap changes: rename ConceptMap.group.element.target.equivalence to ConceptMap.group.element.target.relationship, bind that element to the new required ConceptMapRelationship value set/code system, retire the prior ConceptMapEquivalence artifacts, clarify ConceptMap.group.unmapped as the default behavior when no target mapping is present, add ConceptMap.group.element.noMap, and leave relationship-refinement guidance to a follow-up tracker.

Initial application:
No source commit explicitly tagged FHIR-22632 was found. The relationship transition appears to have been applied through the same ConceptMap history trail: commit 049b740c24b9a670f52f04286093e41bc6f2d74d changed examples and operation output from equivalence to relationship, commit 70168c7d320d0f7cc2995a73836f9c76d2f0356b applied the FHIR-25923 directional code names and closure wording, and the current StructureDefinition XML entered the source layout with target.relationship, noMap, and unmapped definitions. The Jira comment records that the changes had been applied on 2020-12-03.

Additional context:
FHIR-25923 replaced the earlier code-value question in FHIR-25373 and changed the relationship directionality to source-to-target, explaining why the current definition intentionally differs from the seed issue's original target-to-source wording. FHIR-29946 is the seed's item 7 follow-up for relationship-refinement guidance and already has a fixed reconcile commit on the combined branch. FHIR-22636 is the related $translate output rename and already has a no-change reconcile commit on the combined branch. The Vocabulary block-vote Confluence page identifies FHIR-22632 as the main transition ticket and groups those related trackers around it.

AutoFHIR reconciliation:
No source change was made. ConceptMap is active in source/fhir.ini, and the current build-scoped ConceptMap source already has ConceptMap.group.element.target.relationship with a required ConceptMapRelationship binding, directional source-is-narrower-than-target/source-is-broader-than-target relationship codes, ConceptMap.group.element.noMap, and ConceptMap.group.unmapped/default relationship behavior. The ConceptMap operation source also uses match.relationship and ConceptMapRelationship, and focused searches found no stale active ConceptMapEquivalence, concept-map-equivalence, or target.equivalence source under the active ConceptMap source/config.

Recommendation:
Keep this no-change audit commit. The current source satisfies the FHIR-22632 decision after accounting for the later FHIR-25923 directionality decision and already-published follow-up reconcile work for FHIR-29946 and FHIR-22636; reopening the seed would risk duplicating those separate issues.
