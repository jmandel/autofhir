FHIR-40462: Include procedure reason codes in MedicationRequest

Issue request:
FHIR-40462 was an Applied/Persuasive Pharmacy change request asking MedicationRequest reason support Procedure both as a coded reason and as a referenced reason. The important final resolution was: "Will update medicationRequest.reason to include codes and reference for procedure."

Initial application:
The issue was partially applied by commit 0eef1b615326487c7e0f16d455c272937cf98ae6, which added Procedure to the MedicationRequest.reason CodeableReference targetProfile list. That covered the reference half after the R5/R6 reasonCode and reasonReference merge, but the current active source still bound MedicationRequest.reason.concept to the Condition/Problem/Diagnosis example value set.

Additional context:
source/fhir.ini lists medicationrequest=MedicationRequest, so source/medicationrequest/structuredefinition-MedicationRequest.xml is in current build scope. The linked Zulip thread records the original use case and Lloyd McKenzie's request to file a change request, and Pharmacy minutes record FHIR-40462 discussed and approved on 2023-04-10. The existing procedure-reason value set includes both SNOMED clinical-finding and procedure hierarchies, matching the Jira request to allow diagnosis/problem/condition reasons and procedure reasons without adding a new value set. Related FHIR-40787 applied a parallel MedicationStatement Procedure reference request and is already represented on the combined branch.

AutoFHIR reconciliation:
This commit changes the MedicationRequest.reason example binding from ValueSet/condition-code to ValueSet/procedure-reason. The Procedure targetProfile was already present, so this fixes the remaining coded-reason portion of the Applied Jira resolution while preserving the existing example binding strength.

Recommendation:
Keep this source fix. No broader MedicationRequest changes are needed for FHIR-40462; any future harmonization of MedicationStatement's example reason binding should be handled under a separate MedicationStatement tracker because FHIR-40787 only requested Procedure references.
