FHIR-5501: Audit Ratio absent-component constraint

Issue request:
FHIR-5501 was a Published/Persuasive MnM Jan 2015 ballot comment on FHIR-core datatypes asking why Ratio allowed both numerator and denominator to be absent when null flavors are not generally used at that level. The approved resolution was to add a note that extensions, such as a null-flavor-style explanation, would be required when both are missing.

Initial application:
The Jira comments say the invariant was fixed in SVN revision 4533. The corresponding git-svn commit d8c3b09240e38503a709e6540aea5782e76cc4f7, carrying build@4533, changed source/datatypes/ratio.xml so the Ratio invariant English added "If both are absent, there SHALL be some extension present" and the XPath also required an extension when numerator was absent. Later expression-normalization commits preserved that semantic requirement in FHIRPath and XPath.

Additional context:
Ratio is an active datatype in source/fhir.ini and is published through the datatypes page. Current source/datatypes.html explains that a proper ratio has both numerator and denominator, but they are not mandatory only to allow an invalid ratio with an extension carrying further information. Targeted Jira, Zulip, and Confluence searches found no later core decision or community record requiring a different interpretation.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current source/datatypes/ratio.xml already requires numerator and denominator either both be present or both be absent with an extension, using English, FHIRPath, and XPath forms; the surrounding datatypes narrative is consistent with that rule.

Recommendation:
Keep this no-change audit commit as-is. No current FHIR-core source edit is needed for FHIR-5501 unless a future work-group decision changes how Ratio should represent absent numerator and denominator values.
