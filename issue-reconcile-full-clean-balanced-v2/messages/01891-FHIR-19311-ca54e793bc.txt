FHIR-19311: Audit CopyMark security label terminology

Issue request:
FHIR-19311 was a Published FHIR-core Security change request with a Persuasive with Modification resolution. The request started as a proposed integrity label for copied or duplicated data, but the accepted resolution was to make the v3 ActCode PrivacyMark hierarchy available through the SecurityPolicy value set so COPY/CUI-style privacy marks could be used when appropriate; the Jira comment also clarified that absence of the mark does not imply data is original.

Initial application:
The issue was first applied through terminology rather than a core source edit: Jira records that Grahame updated the terminology server with current v3 MIF content on 2019-10-08 so CUI and CopyMark were available and flowed into HCS through SecurityControlObservationValue and v3-SecurityPolicy. Core history has no FHIR-19311-specific commit, but commit f04f624 updated source/v3/source.xml on the same date, and commit 5c0494 later removed local UTG/v3 source from the core build while leaving source/terminologies/valueset-security-labels.xml pointed at external THO value sets.

Additional context:
Current core source defines All Security Labels by including the external THO v3-SecurityControlObservationValue value set, and THO currently defines v3-SecurityControlObservationValue as including v3-SecurityPolicy. THO ActCode now has SecurityPolicy with PrivacyMark, SecurityLabelMark, and the leaf COPYMark code. UP-128 is a later implemented UTG proposal in the same PrivacyMark/SecurityLabelMark family and its comments explicitly describe COPYMark as an existing sibling privacy mark, reinforcing that the terminology belongs in THO rather than as a new core-local vocabulary edit.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative core binding already reaches the requested terminology through THO, and adding a duplicate core-local include or narrative restatement would be redundant and could drift from THO.

Recommendation:
Keep this no-change audit. No FHIR-core source follow-up is needed for FHIR-19311 unless a future terminology release removes COPYMark from the SecurityPolicy/PrivacyMark hierarchy or changes the SecurityControlObservationValue inclusion chain.
