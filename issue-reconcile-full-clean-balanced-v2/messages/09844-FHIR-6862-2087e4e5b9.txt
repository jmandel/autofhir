FHIR-6862: Audit XSD primitive facets

Issue request:
FHIR-6862 was a Published/Persuasive DSTU1 change request for the FHIR-core schemas/schematrons page reporting that generated fhir-base.xsd used xs:minLength on unsignedInt-primitive and positiveInt-primitive, facets that are not applicable to those numeric primitive restrictions. Jira records the resolution as "fix" and the editor comment says this had already been fixed.

Initial application:
No commit in the current HL7/fhir history explicitly references FHIR-6862. Git pickaxe/history shows the old in-repository XSD generator and build machinery were later removed and replaced by the external kindling dependency, so the current checkout no longer has a checked-in fhir-base.xsd or local primitive XSD generator source to patch for this issue.

Additional context:
FHIR-7692 is a Duplicate issue with the same fhir-base.xsd minLength report and is not an independent reconciliation target. The current XML page still describes fhir-base.xsd, fhir-all.xsd, and fhir-single.xsd as generated schema artifacts, and build.gradle.kts depends on org.hl7.fhir:kindling for the build/generation tooling. Community searches found no Zulip or Confluence discussion that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current generated fhir-base.xsd from build.fhir.org defines unsignedInt-primitive with xs:nonNegativeInteger plus a numeric pattern and positiveInt-primitive with xs:positiveInteger plus a numeric pattern, with no xs:minLength facet on either primitive. Editing core source would not improve the current specification because the reported invalid facets are absent from the current schema surface and the generator lives outside this checkout.

Recommendation:
Keep this no-change audit commit as-is. If a future generated fhir-base.xsd regresses, investigate the kindling generator rather than adding prose or unrelated source changes in the FHIR core checkout.
