FHIR-20385: Audit descriptive element suppression guidance

Issue request:
FHIR-20385 was Published with a Persuasive with Modification resolution for R5. It asked for dependent IG profiles to be able to suppress inherited mappings that are irrelevant or confusing; the final FHIR-I resolution narrowed the source change to profiling guidance saying profiles can remove ElementDefinition code, comment, requirements, alias, example, and mapping content when constraints make those inherited descriptive properties invalid or irrelevant. Tooling behavior was split out to FHIR-40543.

Initial application:
The Jira application comment identifies Git master 81f905995c. That commit added the Profiling descriptive elements section to source/profiling.html before the Using StructureDefinitions section, with a table of allowed revisions/additions/removals for descriptive ElementDefinition properties. The current source contains that section with later cleanup and the removal mechanism text.

Additional context:
The linked Zulip discussion confirms the issue was about removing inherited descriptive properties from generated snapshots, not merely hiding them in rendering, and it names StructureDefinition.mapping plus ElementDefinition.code, comment, requirements, alias, example, and mapping as the target properties. FHIR-40543 remains unresolved/Waiting for Input for the tooling-extension details, so it is context rather than a separate decided issue in this run. FHIR-I minutes for 2023-02-27 record the Persuasive with Modification vote, and the suppress extension now exists in the FHIR Extension Pack while core source links to it through the extensions-location placeholder.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because source/profiling.html already explains that descriptive element properties may be refined without invalidating inherited meaning, lists removal as allowed for the properties required by the Jira resolution, and directs authors to use ElementDefinition-suppress in the differential with the comment matching safeguard.

Recommendation:
Keep this audit commit as-is for FHIR-20385. Do not broaden this reconciliation into FHIR-40543 unless that tooling issue reaches a final applied/published state or a separate run is prepared for unresolved tooling-extension work.
