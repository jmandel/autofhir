FHIR-36208: Audit Device operation status value set

Issue request:
FHIR-36208 was Published/Persuasive for R5. It requested replacing the existing Device OperationalStatus value set with a Device.Operation.status value set containing on, online, paused, offline, off, not-ready, standby, shutdown, defective, and unknown.

Initial application:
The issue was initially applied in R5 source history. Commit b21bcbf25eac added source/device/codesystem-device-operation-status.xml and source/device/valueset-device-operation-status.xml with the requested operation-status codes, and commit 3560f64f1625 corrected the code anchors in that CodeSystem. Commit d76dc5b48270 later removed those separate operation-status terminology files while adding the remaining Device.operationalState backbone elements, leaving the status binding on the older Device operational status value set. FHIR-37545 then renamed the operationalState backbone to Device.operation and changed the status binding to device-operationstatus before later Device redesign work removed the active Device.operation status element.

Additional context:
Later final Device decisions supersede reintroducing the FHIR-36208 R5 element shape in the current build. FHIR-38904 Published/Persuasive with Modification required removing the Device.operationStatus/operation status-statusReason-operator content while keeping only mode, cycle, and duration at Device level for R5. FHIR-32565 Applied/Persuasive with Modification then moved Device.mode, Device.cycle, and Device.duration to extensions for R6. FHIR-47604 Applied/Persuasive with Modification removed the later DeviceAssociation operation backbone and carried operation-status concepts through DeviceAssociation.associationStatus. FHIR-37545 and FHIR-40515 have already been represented on the combined branch as no-change audits for the same later modeling context, and FHIR-47604 is represented by a source-fix commit.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Device and DeviceAssociation are active in source/fhir.ini, but parsing the authoritative current StructureDefinition XML finds no active Device.operation, Device.operationalState, Device.mode, Device.cycle, Device.duration, or DeviceAssociation.operation elements. The current DeviceAssociation.associationStatus source carries active association/operational states for the post-FHIR-47604 model. Legacy unbound device-operationalstatus source and OID entries remain, but they are not bound by active Device or DeviceAssociation elements; changing or retiring those canonical terminology artifacts would be a separate terminology compatibility decision, not a safe FHIR-36208 reconciliation.

Recommendation:
Keep this audit commit as-is. Do not reintroduce Device.operation.status or the removed Device operation-status value set for FHIR-36208. If the work group wants to retire or replace legacy unbound device-operationalstatus artifacts, handle that through a separate terminology cleanup issue that explicitly considers canonical-retirement policy.
