FHIR-26624: Audit ChargeItem service pay-in-advance change

Issue request:
FHIR-26624 was Published with a Persuasive with Modification resolution for R5. It asked for ChargeItem.service to support pay-in-advance workflows by allowing MedicationRequest and ServiceRequest, and the final resolution also changed the element type to CodeableReference.

Initial application:
The issue was applied in commit 10e9603435c0b0a8fd7ac0f00356a0592051ecec, which changed source/chargeitem/structuredefinition-ChargeItem.xml so ChargeItem.service used CodeableReference and added MedicationRequest and ServiceRequest target profiles. The same CodeableReference and target profiles were still present in the latest core ChargeItem source immediately before ChargeItem was removed from the core build.

Additional context:
Patient Administration minutes for 2021-10-13 record the same disposition and 4-0-0 vote, and the originating Zulip thread shows the pay-in-advance MedicationRequest/ServiceRequest use case that led to the tracker. Later current-core source removed ChargeItem and ChargeItemDefinition from source/fhir.ini and source/chargeitem, while the R6 ballot introduction and module pages point readers to the external HL7 Administrative Incubator ChargeItem artifact. The current Administrative Incubator ChargeItem JSON still has ChargeItem.service as CodeableReference with MedicationRequest and ServiceRequest target profiles.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The historical core source already applied FHIR-26624, and the current core checkout no longer contains ChargeItem as an active build resource; the active external ChargeItem artifact also preserves the requested service targets.

Recommendation:
Keep this no-change audit commit as-is. No core follow-up is needed for FHIR-26624 unless ChargeItem is brought back into core, in which case the CodeableReference service definition with MedicationRequest and ServiceRequest targets should be preserved from the external artifact.
