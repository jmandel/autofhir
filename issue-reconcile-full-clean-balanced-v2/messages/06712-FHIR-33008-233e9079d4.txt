FHIR-33008: Audit contained-resource guidance clarification

Issue request:
FHIR-33008 was Published/Persuasive for FHIR-core DomainResource and the references page. It identified that the contained-resources bullet said a contained resource needed a reference to it, while the following normative paragraph also allowed the contained resource to reference its container; the approved correction was to add "or if the contained resource references the container resource" to the bullet.

Initial application:
The underlying rule came from FHIR-13187, which changed dom-3 and the contained-resource narrative to allow contained resources to point to their container. Commit 398042d0fa7b857a589e36db24cdf94960349db2 then applied FHIR-33008 by adding the missing "or if" wording to source/references.html. The current line blame for source/references.html:750 points to that FHIR-33008 commit.

Additional context:
The current source/references.html page is an active core narrative page linked by the specification, and source/domainresource/structuredefinition-DomainResource.xml is active as DomainResource in source/fhir.ini. The current dom-3 invariant and human text continue to allow either a reference to the contained resource or a reference from the contained resource to the container. Related contained-reference issues FHIR-12812, FHIR-20340, and FHIR-31582 do not reverse this rule; they either predate/support it or clarify different reference-boundary behavior. Zulip and Confluence evidence show the ambiguity was discussed and then approved by FHIR-I without a later conflicting decision found in the bounded searches.

AutoFHIR reconciliation:
Made no source change. The current references bullet already contains the approved FHIR-33008 "or if the contained resource references the container resource" wording, and the DomainResource invariant remains consistent with it.

Keep this empty audit commit as-is. No further core source work is needed for FHIR-33008 unless a future work-group decision changes the contained-resource rule itself.
