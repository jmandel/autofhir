FHIR-27136: Audit preferred-id identifier wording

Issue request:
FHIR-27136 was a Published FHIR-core Vocabulary change request for NamingSystem $preferred-id. Although the summary asked to rename the input parameter from "id" to "identifier", the final Not Persuasive with Modification decision was narrower: do not rename the operation or input parameter because that would affect implementations; instead change the parameter documentation from "provided id" to "provided identifier" and correct the example wording.

Initial application:
The issue appears to have been applied by git commit 25159ea161eaed360cf05d040c52d38e80cdcbac, "vocab r5 changes to naming system", which explicitly lists FHIR-27136 and changed source/namingsystem/operationdefinition-NamingSystem-preferred-id.xml from "provided id"/"mary" to "provided identifier"/"e.g." while leaving the parameter name as id. Later commits FHIR-37674 and FHIR-37449 touched the same OperationDefinition but did not reverse that documentation change.

Additional context:
source/fhir.ini actively includes namingsystem=NamingSystem, and source/namingsystem/list-NamingSystem-operations.xml references OperationDefinition/NamingSystem-preferred-id, so the checked OperationDefinition is in current build scope. The Zulip thread that led to the tracker shows the original .NET routing concern, and Confluence WGM minutes record FHIR-27136 as Not Persuasive with Modification. No later evidence found in the same trail supersedes the decision to keep the id parameter name.

AutoFHIR reconciliation:
This audit commit makes no source change. The current OperationDefinition parameter remains <name value="id"/>, matching the WG's implementation-compatibility decision, and its documentation now says "The server parses the provided identifier to see what type it is (e.g. ...)". The old "provided id" sentence is absent from the current source.

Recommendation:
Keep this no-change audit commit as-is. Further work is only needed if a new work-group decision revisits operation parameter reserved words or chooses a breaking rename; FHIR-27136 itself is already correctly reflected in current source.
