FHIR-3260: Audit removed omitReason extension

Issue request:
FHIR-3260 was a Published/Persuasive Patient Care change request for FHIR-core Questionnaire. It asked to remove the omitReason extension because reasons for not answering a question should be modeled as part of the Questionnaire design, not captured as a reusable extension everywhere.

Initial application:
The old omitReason entry was removed from the Questionnaire core extension material in historical source changes, including commit 531674a735, which deleted the omitReason description from questionnaire-extensions-introduction.xml. Later Questionnaire tracker work in commit 37ee370c54 added the current normative guidance in source/questionnaire/questionnaire-notes.xml explaining that a missing-answer reason should be captured with an explicit child item in the Questionnaire.

Additional context:
Questionnaire is an active current resource in source/fhir.ini, and the Questionnaire extension pack list references ImplementationGuide/Questionnaire-core, whose notes file contains the current guidance. Exact searches of current core source and the FHIR Extension Pack did not find any omitReason/omitreason/omit-reason extension definition. The only current core mention of omitReason is a historical release-note line; the Extension Pack's questionnaireresponse-reason extension is a distinct concept about why a QuestionnaireResponse was created, not why a specific question was not answered. Jira, Zulip, and Confluence searches found no later conflicting decision.

AutoFHIR reconciliation:
No source change was made. The current build-scoped Questionnaire source already implements the FHIR-3260 decision by omitting the old extension and directing implementers to model missing-answer reasons as child Questionnaire items.

Recommendation:
Keep this audit commit as-is. No current core source fix is needed for FHIR-3260 unless a human wants an editorial cleanup of the non-normative historical release-note wording.
