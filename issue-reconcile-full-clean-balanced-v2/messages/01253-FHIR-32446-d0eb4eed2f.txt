FHIR-32446: Audit outcome definitions already replaced

Issue request:
FHIR-32446 was Published/Persuasive for R5 after reporting that the AuditEvent outcome definitions for minor and serious failure were tautological and that the HTTP 400/500 examples did not distinguish minor from serious. The Jira resolution explicitly says this was resolved with FHIR-32445.

Initial application:
No explicit FHIR-32446-tagged source commit was found. Commit 04aebbe0d4, tagged for FHIR-32445, removed the old AuditEvent outcome codes 4 Minor failure, 8 Serious failure, and 12 Major failure from the core AuditEvent outcome CodeSystem source and changed the outcome value set to include issue-severity. Later FHIR-39622 work added success to issue-severity and removed the remaining separate AuditEvent success-code include.

Additional context:
source/fhir.ini actively maps auditevent=AuditEvent, so the AuditEvent StructureDefinition and outcome value set are current build inputs. The current value set includes http://hl7.org/fhir/issue-severity, whose current definitions distinguish success, warning, error, fatal, and information without using the old minor/serious labels or the disputed HTTP 400/500 examples. The combined branch already contains a separate FHIR-32447 reconciliation for the AuditEvent.outcome backbone and required code binding, which is consistent with this terminology state.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active AuditEvent outcome source no longer contains the problematic minor/serious definitions or the HTTP 400/500 explanatory text that FHIR-32446 challenged, so adding replacement prose for those removed codes would be redundant and could conflict with the later issue-severity-based model.

Recommendation:
Keep this audit commit as-is for FHIR-32446. If FHIR-32445 is reconciled separately, review its broader DICOM mapping request there; FHIR-32446 itself is satisfied by the removal of the old minor/serious outcome code definitions from the current build.
