FHIR-3121: Audit ValueSet code system identifier uniqueness

Issue request:
FHIR-3121 was a Published/Persuasive with Modification DSTU1 change request for FHIR-core ValueSet. It asked that value sets defining their own codes make the coding system URL globally unique, ideally as an invariant and in the ValueSet text. The accepted modification noted that invariants can only enforce within a resource instance, but the global uniqueness expectation could be documented.

Initial application:
The Jira comment says the change was applied on 29-Sept-2014 in SVN revision 2934. Git history maps that to 1a687c0a94b558ab88acf02e2063068980f593b6, which changed the then-current source/valueset/valueset-spreadsheet.xml ValueSet identifier row from string/logical-id wording to uri/globally-unique wording and described it as a globally unique OID, UUID, or URI.

Additional context:
The historical request belonged to the retired DSTU1/R2 ValueSet model where ValueSet.define represented an inline code system definition. Current build scope is the active valueset=ValueSet and codesystem=CodeSystem entries in source/fhir.ini. The current source has no ValueSet.define, define.identifier, vsd-7, or f:define/f:system XPath. The modern source separates code systems into CodeSystem, where CodeSystem.url is the canonical URL used by Coding.system and is described as globally unique; ValueSet.url has the same canonical globally-unique expectation for value sets. FHIR-3977, a related old ValueSet invariant correction from the same family, is already represented on the combined branch and is not decided again here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The requested expectation was historically applied to the old ValueSet source, and the current specification now expresses the relevant global uniqueness rule through the active ValueSet.url and CodeSystem.url definitions rather than through the retired ValueSet.define structure.

Recommendation:
Keep this audit commit as-is. No current core source edit is recommended unless the work group makes a new decision to strengthen canonical URL uniqueness beyond the existing SHOULD language; the original issue and its accepted modification support documenting the expectation, not adding an unenforceable global invariant.
