FHIR-22763: Audit ICD-10 cleanup

Issue request:
FHIR-22763 was a Published/Persuasive Financial Management issue asking to remove dummy ICD-10 concepts from Claim valueset-icd-10 and fix related examples so they use valid ICD-10 or ICD-10-CM codes after tx.fhir.org began validating those systems.

Initial application:
The issue was pre-applied in the Jira-cited git commits b55203191d0acf262425888825ef4f77a11e4841, 820b4fa08422d7d405c5cea644b7a659af307086, and 24bf09a6ea30590a77c65da3ccd04a389ad53a58. Those commits commented out the invalid dummy ValueSet concepts, changed Claim diagnosis examples to ICD-10-CM where appropriate, replaced the oral orthodontic dummy code with K07.3, fixed a ChargeItem example that is no longer in the current build, and corrected ServiceRequest/example display details.

Additional context:
The active current build includes Claim and ServiceRequest in source/fhir.ini, while ChargeItem is no longer an active resource entry. Current source/claim/valueset-icd-10.xml includes the ICD-10 system without explicit dummy concepts, and the remaining active ICD-10/ICD-10-CM example codings in the relevant Claim and ServiceRequest source files use M96.1, G89.4, M53.88, M47.816, K07.3, and E84.0. A related 2019 committers Zulip thread confirms the original build failure was caused by dummy codes in claim/valueset-icd-10.xml and that Rob Hausam cleaned it up. No Confluence record or conflicting community evidence was found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already preserves the applied resolution: invalid dummy ICD-10 concepts are not active in valueset-icd-10, and the examples affected by the Jira-tagged commits use real ICD-10/ICD-10-CM codes or are outside the current build.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed unless the work group wants a separate editorial cleanup of historical XML comments or inactive/out-of-build artifacts, which is outside the applied FHIR-22763 validation fix.
