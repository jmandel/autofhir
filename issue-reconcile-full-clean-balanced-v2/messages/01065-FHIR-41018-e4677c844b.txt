FHIR-41018: Audit MeasureReport calculated date split

Issue request:
FHIR-41018 was an Applied/Persuasive with Modification FHIR-core MeasureReport issue for R6. It requested changing MeasureReport.date back to report generation timing and adding a group-level calculatedDate dateTime element for the date the measure was calculated.

Initial application:
The issue was applied by commit 45610ce7d2cc50ef0749c364466698ab13d0b31b and PR HL7/fhir#3312. That commit changed source/measurereport/structuredefinition-MeasureReport.xml so MeasureReport.date again says the report was generated and added MeasureReport.group.calculatedDate.

Additional context:
FHIR-20804 originally changed the R5 root date wording from generated to calculated. FHIR-40797 later documented that this was misleading for DEQM because report generation and calculation can differ. FHIR-41018 is the current FHIR-core decision that resolves the ambiguity in core, and source/fhir.ini confirms MeasureReport and MeasureReport.group.calculatedDate are active build-scope entries.

AutoFHIR reconciliation:
This commit makes no source change. The current in-scope source already implements FHIR-41018: MeasureReport.date is generation timing and MeasureReport.group.calculatedDate is the calculation timing element.

Recommendation:
Keep this audit commit as-is. Future changes should preserve the distinction between MeasureReport.date and MeasureReport.group.calculatedDate unless CQI makes a new decision.
