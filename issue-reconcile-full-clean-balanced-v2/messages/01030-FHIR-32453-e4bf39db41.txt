FHIR-32453: Audit agent type and role clarity

Issue request:
FHIR-32453 was Published/Persuasive with Modification for R5. It asked to clarify AuditEvent and Provenance agent.type versus agent.role: agent.type was to describe the functional participation role, agent.role was to describe broader structural/security roles, and the related value sets were to be handled by FHIR-32519 and FHIR-32520.

Initial application:
The issue was applied by f577d68ceb, which updated AuditEvent.agent.type, AuditEvent.agent.role, Provenance.agent.type, and the structural role value set work tied to FHIR-32520. FHIR-32519 was later applied by 760011453b, cleaning the shared participation-role-type value set and changing AuditEvent.agent.type to preferred; the preceding AutoFHIR commit for FHIR-32519 completed the missed Provenance.agent.type preferred binding.

Additional context:
AuditEvent and Provenance are active current-build resources in source/fhir.ini. Later Applied issue FHIR-53882 intentionally revised AuditEvent-only wording so AuditEvent.agent.type is now "how the agent participated" rather than necessarily an ISO 21298 Functional Role, and AuditEvent.agent.role may reflect roles authorizing participation. That later decision is already represented on the combined branch and should not be reverted while auditing FHIR-32453. Provenance retains the functional/structural role distinction from the original FHIR-32453 application.

AutoFHIR reconciliation:
This audit commit makes no additional source change for FHIR-32453. The current authoritative source is correct after the original application, the later FHIR-32519 binding fix, FHIR-32520 value-set cleanup, and the later FHIR-53882 AuditEvent clarification are considered together.

Recommendation:
Keep this audit commit as-is. Do not restore the exact R5-era AuditEvent "Functional Role" wording for FHIR-32453 because FHIR-53882 deliberately superseded it for AuditEvent; use the separate FHIR-32519 source commit for the only current binding-strength correction found in this issue family.
