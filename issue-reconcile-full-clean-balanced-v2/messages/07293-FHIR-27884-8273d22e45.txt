FHIR-27884: Audit out-of-build $questionnaire operation

Issue request:
FHIR-27884 was a Published/Persuasive FHIR-core StructureDefinition change request raised against R4 and applied for R5. It reported that the StructureDefinition $questionnaire operation used the wrong input parameter types: identifier was listed as canonical instead of Identifier, and profile was listed as string instead of Resource (StructureDefinition).

Initial application:
The Jira comment records implementation commit b251978797. That commit changed source/structuredefinition/operationdefinition-StructureDefinition-questionnaire.xml so identifier used <type value="Identifier"/> and profile used <type value="StructureDefinition"/>. The v5.0.0 source still contains those corrected parameter types while listing OperationDefinition/StructureDefinition-questionnaire as a StructureDefinition operation.

Additional context:
StructureDefinition remains an active core resource in source/fhir.ini, but the current source/structuredefinition/list-StructureDefinition-operations.xml lists only OperationDefinition/StructureDefinition-snapshot. Commit 270e0ceb7b, "normative changes for R6", removed the StructureDefinition-questionnaire operation from that list and deleted source/structuredefinition/operationdefinition-StructureDefinition-questionnaire.xml after the FHIR-27884 fix was already present. A current source grep finds no $questionnaire operation definition under source/structuredefinition; only the historical OID mapping remains in source/oids.ini. FHIR-I minutes for 2020-10-19 mention FHIR-27884 with "Move to SDC", and quoted Zulip/Confluence FTS searches found no later conflicting discussion about the parameter-type correction.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The incorrect parameter types were fixed in the R5 source, and the relevant OperationDefinition is no longer part of the current FHIR core build, so there is no current core source hunk to edit for this issue.

Recommendation:
Keep this audit commit as-is for FHIR core. If a successor $questionnaire operation is maintained in SDC or another external IG, reconcile the same parameter-type expectation in that repository rather than reintroducing the removed core operation.
