FHIR-12510: Audit binding code generation extensions

Issue request:
FHIR-12510 was Published/Persuasive for DSTU2 and asked to add two binding metadata extensions, bindingName and isCommonBinding, so generated StructureDefinition content could carry the spreadsheet binding name and whether the binding is shared across structures for code generation placement.

Initial application:
The Jira comment identifies svn revision 11178. The corresponding git-svn commit 27a52a1003145a3947e9d1e51ba6d7219f8d997f is explicitly titled "#12510 - binding extensions for code generation" and added bindingName/isCommonBinding rows to the ElementDefinition extension spreadsheet plus generator logic to emit elementdefinition-bindingName and elementdefinition-isCommonBinding extensions from binding metadata.

Additional context:
The active current build includes StructureDefinition as a resource in source/fhir.ini, and checked-in StructureDefinition sources now carry these extension URLs on ElementDefinition.binding entries across core resources, including StructureDefinition itself. The extension definitions have moved out of core to the FHIR Extension Pack, where both canonical URLs are active; later FHIR-51990 refined the bindingName description in that pack to avoid implying global uniqueness for code generation.

AutoFHIR reconciliation:
No source change was made. The current core source already emits the requested binding metadata extensions in build-scope StructureDefinition source, and the canonical extension definitions now exist in the Extension Pack with the later clarified wording.

Recommendation:
Keep this no-change audit. Future binding-name semantic changes should be reconciled against the Extension Pack definitions and any generated core StructureDefinition usage, but FHIR-12510 itself requires no core source edit.
