FHIR-48492: Finish jurisdiction undeprecation cleanup

Issue request:
FHIR-48492 is Applied with a Persuasive with Modification resolution to un-deprecate jurisdiction wherever it was deprecated in favor of useContext, remove deprecation notes, change jurisdiction definitions to describe the authority maintaining the resource, add examples, and bind jurisdiction elements to http://terminology.hl7.org/ValueSet/jurisdiction.

Initial application:
The source history contains f48feed3e0 ("FHIR-48492 - undeprecate jurisdiction"), which removed deprecated status extensions and changed many core conformance-artifact jurisdiction definitions, search parameter descriptions, and bindings. Current source still retained stale deprecation notes on active jurisdiction elements, left Definition/Publishable pattern text using the old "intended to be used" meaning, left a few active jurisdiction definitions unchanged, and exposed "the the" in jurisdiction search parameter descriptions.

Additional context:
FHIR-38841 originally deprecated CanonicalResource.jurisdiction in favor of useContext for R5, while the FHIR-48492 Jira, Zulip discussion, and May 2025 WGM minutes establish the later decision to reverse the jurisdiction part because defining jurisdiction is not the same as jurisdictions of use and the package/tooling ecosystem still relies on the jurisdiction element. FHIR-41866 and the extension-pack commit da0aed4 show the related artifact-jurisdiction extension was handled in the FHIR Extension Pack, not in this core source checkout.

AutoFHIR reconciliation:
Removed the remaining jurisdiction deprecation guidance from active resource StructureDefinitions and their definition-pattern exception records, updated Definition and Publishable pattern jurisdiction text, updated SpecimenDefinition, ObservationDefinition, and SubscriptionTopic jurisdiction definitions to the FHIR-48492 wording, kept the THO jurisdiction value set bindings, and corrected FHIR-48492 jurisdiction search-parameter descriptions so they no longer say "the the". The edited resources are active in source/fhir.ini; Definition and Publishable patterns are active pages in source/hierarchy.xml; the mapping exception files are paired source records for those active definition-pattern resources.

Recommendation:
Keep this commit. It completes the already-applied FHIR-48492 core cleanup without changing unrelated nested product/device jurisdiction elements or extension-pack content. Any further artifact-jurisdiction extension work should remain in the FHIR Extension Pack issue path.
