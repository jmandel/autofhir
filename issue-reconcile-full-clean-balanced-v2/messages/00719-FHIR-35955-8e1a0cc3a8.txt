FHIR-35955: Audit FamilyMemberHistory age/deceased invariant

Issue request:
FHIR-35955 was a Published/Persuasive Patient Care change request for R5 asking that FamilyMemberHistory not allow both age[x] and deceased[x], because an age-at-history value is not meaningful when the same family member history entry also records deceased age/status. The approved resolution was to add a FamilyMemberHistory invariant: age.empty() or deceased.empty().

Initial application:
The Jira comment identifies GitHub commit 5b7af09. Local history confirms 5b7af09cd31d2468d18df53c60256c44cf8ccf83 added fhs-3 to source/familymemberhistory/structuredefinition-FamilyMemberHistory.xml with the approved FHIRPath expression and added condition references on age[x] and deceased[x]. Later cleanup removed XPath-era material but preserved the fhs-3 invariant.

Additional context:
FamilyMemberHistory is active in source/fhir.ini, so the StructureDefinition source is in current build scope. The linked Zulip thread supports the same intent: Lloyd McKenzie suggested a constraint preventing both deceased and age. Confluence searches found no conflicting workgroup record. Later FHIR-54457 discusses estimatedAge and deceased[x], but it removes estimatedAge rather than changing the age[x]/deceased[x] mutual-exclusion rule, and it is already represented on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative source already contains fhs-3 at the FamilyMemberHistory root with expression age.empty() or deceased.empty(), and age[x] plus deceased[x] both reference condition fhs-3.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-35955 unless the Patient Care work group later decides to relax or replace the mutual-exclusion rule.
