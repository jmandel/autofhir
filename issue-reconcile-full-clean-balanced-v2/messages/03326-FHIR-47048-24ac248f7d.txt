FHIR-47048: Audit Device URL removal as extension-pack follow-up

Issue request:
FHIR-47048 is an Applied FHIR-core Device change request, resolved Persuasive with Modification, asking to remove Device.url. Because Device.endpoint was being moved to an extension, the old Device.url FHIR-server comment was also to move to that extension as: "If the device is running a FHIR server, the network address (represented as Endpoint.address) should be the Base URL from which a conformance statement may be retrieved."

Initial application:
FHIR-32572 earlier asked to replace Device.url with Device.endpoint and was published for R5, but the later R6 Device-extension work changed the target shape. The explicit FHIR-47048 application commit 3f82b599e756ae1f47f2dc0059c10dac84369c8b commented out Device.url and the Device-url search parameter in the core Device source.

Additional context:
OO minutes from 2025-01-13 record the 9-0-0 vote, the decision that URL can be represented in Endpoint.address, and the plan to apply FHIR-47048 along with moving Device.endpoint to an extension. FHIR-32565 and FHIR-48923 removed Device.endpoint and related communication elements from core Device, and FHIR-47326 created the FHIR Extension Pack device-endpoint extension. That extension currently exists in /home/jmandel/work/fhir-extensions, but the requested migrated Device.url comment is not present there.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. Device is active in source/fhir.ini, but XML parsing of source/device/structuredefinition-Device.xml finds no active Device.url or Device.endpoint elements, and XML parsing of source/device/bundle-Device-search-params.xml finds no active Device.url search parameter. The only remaining potential source edit is to the external FHIR Extension Pack device-endpoint StructureDefinition, not to this FHIR-core checkout.

Recommendation:
Keep this empty audit commit for the core reconciliation. If the work group still wants the FHIR-server Base URL guidance from FHIR-47048, apply it in the FHIR Extension Pack device-endpoint extension, ideally as a comment or definition clarification on the extension/value that references Endpoint.address.
