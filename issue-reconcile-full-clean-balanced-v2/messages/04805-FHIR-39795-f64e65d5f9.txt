FHIR-39795: Audit BodyStructure measurement device reference

Issue request:
FHIR-39795 was Published with a Persuasive with Modification resolution for R5. It asked to change BodyStructure.includedStructure.bodyLandmarkOrientation.distanceFromLandmark.device from a CodeableConcept using BodyStructure-specific device codes to CodeableReference(Device), bind its coded side the same way as Device.type, rename distanceFromLandmark.measurementDevice to distanceFromLandmark.value, and update the value short display.

Initial application:
The Jira comment says the issue was applied through PR #2594 and links commit eee115d, a merge update on the implementation branch. The actual BodyStructure source change in that PR was c08a723cf9, which changed .distanceFromLandmark.device to CodeableReference(Device), switched the binding name/value set to DeviceType/http://hl7.org/fhir/ValueSet/device-type, and renamed .distanceFromLandmark.measurementDevice to .distanceFromLandmark.value. Follow-up commit 86a1883099 adjusted the new value element short display to "Measured distance from body landmark," and later FHIR-39796 work aligned the distance wording around units.

Additional context:
source/fhir.ini actively lists bodystructure=BodyStructure in [resources] and notes that BodySite became BodyStructure, so source/bodystructure/structuredefinition-BodyStructure.xml is the current build-scope source for this BodySite-related Jira artifact. OO WGM minutes for 2023-01-16/20 record the same decision path and explicitly answer "Do we need to reference deviceDefinition? - no," supporting the current Device-only target. Current Device.type uses the same DeviceType binding and device-type value set as BodyStructure.distanceFromLandmark.device. A legacy BodyStructure-specific value set file remains in source but is not referenced by the StructureDefinition or fhir.ini; the current build surface publishes the BodyStructure use under the device-type value set and the old BodyStructure-specific value set URL returns 404. Direct Zulip searches found no issue-specific discussion that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active BodyStructure StructureDefinition already represents the approved CodeableReference(Device) type, same Device.type binding, and measurementDevice-to-value rename. The current short display is a harmless follow-up refinement consistent with the approved meaning and later same-element unit-flexibility work.

Recommendation:
Keep this empty audit commit as-is. No FHIR core source fix is needed for FHIR-39795; any future cleanup of the unreferenced legacy value set file should be handled separately as repository hygiene, not as a required semantic correction for this issue.
