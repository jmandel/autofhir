FHIR-11176: Audit CareTeam name clarification

Issue request:
FHIR-11176 is a Published/Persuasive Patient Care change request from the DSTU2 ballot asking to differentiate CareTeam.type and CareTeam.name. The accepted resolution required CareTeam.name to be defined as a human label for distinguishing like teams, with a usage note saying the team meaning/purpose is conveyed by CareTeam.type and, if FHIR-11347 was approved, by CareTeam.category instead.

Initial application:
The source history shows the issue was initially applied in c124072d7bc14dd9eea48ac1aaf530bcd31171a6, whose message explicitly includes #11176 and whose patch changed the then-authoritative CareTeam spreadsheet source from a generic "Name of the care team" definition to the approved distinguishing-label definition, added the usage note, and recorded committee note GF#11176. Later source refactors carried that content into the current CareTeam StructureDefinition XML.

Additional context:
FHIR-11347, approved in the same block, renamed CareTeam.type to CareTeam.category and is already represented on the combined branch by audit commit f1e353f19862042a87c0d3f83079cf19914c7beb. The current CareTeam resource is active in source/fhir.ini, the current StructureDefinition defines CareTeam.category, and the CareTeam.name comment correctly references CareTeam.category rather than the old CareTeam.type name. FHIR-10725 separately addressed CareTeam.status/category value-set bindings and does not change the name/category distinction being audited here. Zulip and Confluence searches found no directly relevant or conflicting community rationale beyond a commit notification for the original #11176/#11347 source application.
