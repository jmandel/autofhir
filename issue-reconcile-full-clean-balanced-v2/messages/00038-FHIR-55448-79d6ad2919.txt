FHIR-55448: Deduplicate DiagnosticReport conclusionCode summary flag

Issue request:
FHIR-55448 was Applied/Persuasive with Modification for R6 DiagnosticReport. It asked whether media, but not result, belonged in the resource summary; the accepted resolution was to remove .media from the summary and add .conclusion and .conclusionCode to the summary.

Initial application:
PR #4012, merged as 722eaabc3470b6a4015cad5d9e7fec33c08d08e4, applied the requested change by removing isSummary from DiagnosticReport.media and DiagnosticReport.media.link and adding isSummary to DiagnosticReport.conclusion and DiagnosticReport.conclusionCode. The current source already preserves those semantics, but it inherited two isSummary entries for DiagnosticReport.conclusionCode after overlapping FHIR-54554 work was also merged.

Additional context:
DiagnosticReport is an active resource in source/fhir.ini, so source/diagnosticreport/structuredefinition-DiagnosticReport.xml is in current build scope. FHIR-54554 is the same summary-change family: OO minutes for 2026-01-26 record the conclusion/conclusionCode summary decision and the instruction to create FHIR-55448 for the media-versus-result question; PR #4020 independently added conclusionCode summary, creating the duplicate after both branches landed. The OO 2026-02-03 minutes confirm the FHIR-55448 decision to remove media and add conclusion/conclusionCode while leaving result out.

AutoFHIR reconciliation:
Removed the duplicate second isSummary element from DiagnosticReport.conclusionCode, leaving the canonical single summary flag before the binding. DiagnosticReport.result, DiagnosticReport.media, and DiagnosticReport.media.link remain outside the summary; DiagnosticReport.conclusion and DiagnosticReport.conclusionCode each have exactly one summary flag.

Recommendation:
Keep this source correction. It preserves the applied WG decision and avoids duplicate ElementDefinition.isSummary content in the active DiagnosticReport StructureDefinition. FHIR-54554 can be audited separately if desired, but no additional source change is needed for the shared summary end-state.
