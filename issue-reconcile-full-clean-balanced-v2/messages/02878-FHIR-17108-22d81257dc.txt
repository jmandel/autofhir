FHIR-17108: Audit Timing datatype hierarchy

Issue request:
FHIR-17108 was a Published/Persuasive STU3 correction reporting that the Datatypes page identified Timing as derived from BackboneElement, but the Timing detail/structure view showed the base as Element. The accepted resolution was to fix that mismatch.

Initial application:
No git commit explicitly mentioning FHIR-17108 was found. The same Timing hierarchy defect was applied through the tightly related FHIR-17403/GF#17403 trail: git commit ada2e0c9c1c1d9f55da7212a82d639e2dad4832f, corresponding to SVN revision 14165 cited in FHIR-17403, changed the root Timing row in source/datatypes/timing.xml from Structure to BackboneElement. Grahame then commented "already done" on FHIR-17108 before it was marked Published.

Additional context:
The current build source no longer uses the STU3 literal BackboneElement model for datatype roots that carry modifierExtension. Commit cbdf7d1e55dc4bfa1dc30fc526edee0491e05782 rebuilt the abstract datatype framework, introduced DataType and BackboneType, and changed Timing from BackboneElement to BackboneType. Current source/fhir.ini keeps Timing, BackboneType, the datatypes page, and type pages in active build scope; source/datatypes/backbonetype.xml defines BackboneType as the DataType-derived base for datatypes that can carry modifierExtension; and source/types.html says BackboneElement is for complex elements inside resource definitions while BackboneType covers Timing, Dosage, and ElementDefinition. FHIR-17403 has already been audited on the combined branch, FHIR-26878 later treats Timing as a BackboneType-derived datatype, and unresolved FHIR-50466 plus the committers Zulip thread describe a separate rendered Structure-table display concern rather than a final source-edit decision for this seed.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source edits. The current authoritative source already preserves the current equivalent of the FHIR-17108 correction: Timing no longer has the old generic Element/Structure base in source and instead derives from BackboneType, the current modifier-extension-capable datatype base. Changing Timing back to BackboneElement would conflict with the modern abstract datatype framework.

Recommendation:
Keep this no-change audit as-is for FHIR-17108. If the rendered Timing Structure table still fails to expose BackboneType clearly, address that separately under FHIR-50466/tooling or work-group review rather than by changing the Timing source hierarchy back to BackboneElement.
