FHIR-12640: Audit MedicationRequest detected issue handling

Issue request:
FHIR-12640 was Published/Persuasive with Modification for DSTU2. It asked MedicationRequest to add a 0..* link to DetectedIssue.

Initial application:
The Jira comments point to SVN-migrated commit a504c1b697fe81488480665b00364efbd46982e6, which added MedicationRequest.detectedIssue with cardinality 0..* and type Reference(DetectedIssue) to the then-authoritative MedicationRequest spreadsheet source.

Additional context:
MedicationRequest is an active current resource in source/fhir.ini and appears under the active Medications module in source/hierarchy.xml. Later Pharmacy work changed the model. FHIR-13150 added guidance to the then-existing MedicationRequest.detectedIssue and MedicationDispense.detectedIssue elements, but FHIR-34293 later required removal of both direct medication-to-DetectedIssue links because DetectedIssue.implicated already points to the implicated therapies and FHIR references are not bidirectional. Historical commit 26e2a82259 removed MedicationRequest.detectedIssue and the example reference, and the combined-branch FHIR-34293 reconciliation commit e25b1231a9ed3c4fec8abcdec9281d95a66dd10c added the requested Medication Module guidance for DetectedIssue.implicated, search, _revinclude, and containment. FHIR-39018 was later resolved Not Persuasive and reaffirmed that DetectedIssue.implicated plus its search parameter is the intended access path.

AutoFHIR reconciliation:
Made no source change. Current MedicationRequest intentionally has no direct detectedIssue element, and the current build already explains how medication-related detected issues are associated and retrieved through DetectedIssue.implicated. Restoring MedicationRequest.detectedIssue would contradict the later published Pharmacy decision.

Recommendation:
Keep this empty audit commit as-is. Future work should not re-add MedicationRequest.detectedIssue unless Pharmacy reopens and reverses the later non-bidirectional DetectedIssue design.
