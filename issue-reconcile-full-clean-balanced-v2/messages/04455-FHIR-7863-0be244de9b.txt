FHIR-7863: Audit Coverage ordering application

Issue request:
FHIR-7863 was a Published/Not Persuasive with Modification DSTU1 Financial Management change request asking whether Coverage.sequence should communicate primary versus secondary coverage. The final resolution said to add Coverage.order as a 0..1 positiveInt for relative coverage order, while Coverage.sequence remained for renewal sequence numbers and primary/secondary coverage order depended on the specific billing circumstance.

Initial application:
The historical tracker batch commit 43806174288e821cb06173a72cde96317186412b explicitly listed 7863 and added Coverage.order as a 0..1 positiveInt in the Coverage spreadsheet source. The same batch changed the primary Coverage example away from using sequence=1 for primary/secondary meaning, and a later Coverage example update added order=2 to the secondary example. Current Coverage source was later regenerated into structuredefinition-Coverage.xml and still contains the requested Coverage.order element.

Additional context:
Coverage is an active resource in source/fhir.ini. Related Published issue FHIR-12231 asked for the same primary/secondary priority support and is already represented on the combined branch by an audit commit; its resolution also preserved the distinction between Coverage.order and claim-level ordering. Later FHIR-15564 removed the old Coverage.sequence element with the Grouping structure, so there is no current Coverage.sequence element to edit. Later FM clarification FHIR-43028 added the current sentence explaining that Coverage.order conveys Coordination of Benefit ordering independent of use case and that use-case-dependent ordering belongs in Account.coverage.priority. The checked-in coverage.svg still has stale diagram tooltip text, but the authoritative StructureDefinition source is correct and diagram-only edits are out of scope for this reconciliation.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active authoritative Coverage source already has Coverage.order as 0..1 positiveInt with coordination-of-benefits requirements and later clarification text, and the current model no longer has the old Coverage.sequence element that caused the original ambiguity.

Recommendation:
Keep this no-change audit. Do not reintroduce Coverage.sequence or add redundant Coverage.order wording for this seed. Any future change to example ordering or the Coverage.order versus Account.coverage.priority policy should be handled under a new FM decision, not as a missed FHIR-7863 application.
