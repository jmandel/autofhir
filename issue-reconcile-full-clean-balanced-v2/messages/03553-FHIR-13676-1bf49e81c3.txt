FHIR-13676: Audit retired ProcessResponse application

Issue request:
FHIR-13676 is Published/Persuasive for FHIR-core ProcessResponse. It asked to apply the FHIR-13673/FHIR-13674 family to ProcessResponse by setting ProcessResponse.outcome to code with a required binding and ProcessResponse.processNote.type to code with a required binding.

Initial application:
The only explicit source-history application found is git commit ae92854dbd2761e0cd7e630cac2efef0d0a179db, "Tracker #13676", which changed the retired ProcessResponse spreadsheet so ProcessResponse.outcome and ProcessResponse.processNote.type use code instead of CodeableConcept. No other Jira-tagged commit for FHIR-13676 was found.

Additional context:
ProcessResponse is no longer part of the current FHIR build: source/fhir.ini comments out processresponse in the resources and workgroups lists, lists ProcessResponse under removed resources, and records that ProcessResponse is approved to use Task instead. Later Jira FHIR-18024 also rejected ProcessResponse wording changes because the resource was deprecated to be replaced by Task. Published STU3 still showed the old ProcessResponse shapes, and R4/R4B/R5 do not publish ProcessResponse, so there is no current built ProcessResponse artifact to correct in this checkout.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Editing source/processresponse would only alter an out-of-build historical resource folder, while the current build-scope source already excludes ProcessResponse and the historical spreadsheet already contains the requested datatype direction.

Recommendation:
Keep this audit commit as-is for the current core build. If HL7 ever republishes or restores ProcessResponse, review the retired spreadsheet and generated profile together, especially the ProcessResponse.outcome binding strength and ProcessResponse.processNote.type binding semantics.
