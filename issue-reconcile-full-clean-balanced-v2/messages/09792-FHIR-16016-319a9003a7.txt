FHIR-16016: Audit combining-character string search behavior

Issue request:
FHIR-16016 is a Published/Persuasive FHIR-core search issue for STU3. It asked default string search to be insensitive not merely to accents, but to all included Unicode combining characters, and to say that default matching operates after normalization by case and combining characters.

Initial application:
The issue was initially applied in SVN revision 14260, represented in this git repository by commit 714a29aba3bce6e95279bf7e49d8574053d8e26b, which changed source/search.html from case/accent language to the combining-character wording requested by the issue.

Additional context:
FHIR-16017 is the same change family and was applied immediately after this issue in revision 14261 to clarify :exact handling of combining characters and canonical equivalence. The same referenced Zulip thread shows both issues came from one internationalization discussion. Later search documentation edits preserved the default string-search wording in the current string search section. source/search.html is the current core search source page.

AutoFHIR reconciliation:
No source change was made. The current source/search.html string section says simple string search is insensitive to casing and included combining characters, including accents or other diacritical marks, and that default matching occurs after normalization by case and combining characters.

Recommendation:
Keep this no-change audit commit. The current source already conveys the issue's required default string-search behavior; no additional wording is needed for this issue.
