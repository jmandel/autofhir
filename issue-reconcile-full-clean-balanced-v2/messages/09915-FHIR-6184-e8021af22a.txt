FHIR-6184: Audit BCP code-system identifiers

Issue request:
FHIR-6184 was Published with resolution Persuasive with Modification. It asked that BCP-47 language tags and BCP-13 MIME/content types be added to the known coding-system list with canonical URI and/or OID guidance for FHIR implementers.

Initial application:
No git commit explicitly mentions FHIR-6184, but the Jira comment says the change was already done. The source history shows the same application path: commit 4e71ae0b99417ac172351dfbbb786d4a18539171 added the urn:ietf:bcp:47 row to source/terminologies-systems.html on 2015-07-02, and commit 9c372112b54f8cbbb8c134621203665dc7298c73 added the urn:ietf:bcp:13 row on 2015-08-03.

Additional context:
Later Published issue FHIR-37853 changed the same Code Systems page to make HL7 Terminology (THO) the source of truth for external terminology identifiers and to remove external rows that do not have a FHIR-specific usage page. Its implementation commit 736ccce2005fd2c8c2d20dfe8df948e8c9d586d8 intentionally removed the BCP-47 and BCP-13 rows along with other external terminology rows. The current page now points readers to THO for authoritative external system URI/OID details and describes the remaining external table as a subset. Current terminology sources still use the FHIR BCP systems where relevant: the MIME Types value set composes from urn:ietf:bcp:13, the language value sets compose from urn:ietf:bcp:47, and the Using Codes page lists MIME types and language codes as notable external code systems.

AutoFHIR reconciliation:
This audit commit makes no source change. Re-adding BCP-13 and BCP-47 to source/terminologies-systems.html would partially undo the later FHIR-37853 decision and duplicate external-terminology authority that the current spec intentionally delegates to THO. The current source preserves the canonical FHIR system URIs in value set definitions and explanatory terminology text, so the build is not semantically missing the FHIR-6184 identifiers.

Recommendation:
Keep this no-change audit. If the work group wants BCP-13 or BCP-47 OID details surfaced differently, handle that as a current terminology/THO governance issue rather than by restoring rows that FHIR-37853 deliberately removed from the core Code Systems page.
