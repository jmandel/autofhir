FHIR-11235: Audit retired Sequence coordinateSystem constraint

Issue request:
FHIR-11235 was a Published/Persuasive Clinical Genomics change request for the DSTU2 FHIR-core Sequence resource. It observed that Sequence.coordinateSystem was an integer and asked for stronger guidance or constraint to the valid 0-based and 1-based choices; the final resolution said the integer could not then be constrained to only 0 and 1, so explanatory sections and examples would be added.

Initial application:
The issue was historically applied by commit d830ddede2fa70d5f6ccca85e723caa4a2c7a7bf, "#11235 #11236 #11239 #11240 Change description related with Sequence.coordinateSystem to be more accurate." That commit updated the then-current source/sequence spreadsheet so Sequence.coordinateSystem explicitly described 0 for 0-based inclusive-start/exclusive-end coordinates and 1 for 1-based inclusive-start/inclusive-end coordinates, alongside paired start/end coordinate clarifications. Historical release3 and release4 generated/profile artifacts preserve the applied wording for Sequence.coordinateSystem and its later MolecularSequence name.

Additional context:
The original Sequence source is no longer part of the current build. source/fhir.ini lists Sequence under removed resources, has molecularsequence commented out, and records active Clinical Genomics entries for moleculardefinition; source/sequence and source/molecularsequence are absent from the current source tree. Later coordinate-system work, including FHIR-22762, moved MolecularSequence.coordinateSystem from a top-level integer to a relative CodeableConcept bound to the LOINC coordinate-system value set. Later R6 work, including FHIR-51227, replaced MolecularSequence with MolecularDefinition and deleted source/molecularsequence. Current MolecularDefinition uses a different coordinateInterval model with coordinateSystem.system CodeableConcept bindings and examples such as 1-based character counting and 0-based interval counting, plus profiles in the Molecular Definition data types IG.

AutoFHIR reconciliation:
This commit intentionally makes no source change. FHIR-11235 was applied to the then-current Sequence source and reached historical publication artifacts; the affected integer Sequence.coordinateSystem/MolecularSequence.coordinateSystem target is not active current-build source. Mechanically porting the old integer 0/1 wording into MolecularDefinition would be a new MolecularDefinition modeling decision, not a reconciliation of the published DSTU2 Sequence issue.

Recommendation:
Keep this audit commit as-is. No current FHIR-core source follow-up is needed for FHIR-11235; if MolecularDefinition implementers need tighter coordinate-system semantics, open or apply a MolecularDefinition-specific Clinical Genomics issue rather than resurrecting retired Sequence integer guidance in core.
