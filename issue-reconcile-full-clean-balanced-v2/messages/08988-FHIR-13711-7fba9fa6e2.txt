FHIR-13711: Audit Simple FHIRPath subset documentation

Issue request:
FHIR-13711 was a Published/Persuasive FHIR-core STU3 change request for the FHIRPath/FluentPath page. It asked to document a limited reusable subset of FHIRPath instead of describing that restricted form separately for discriminator, DataRequirement, search parameter, and similar path-expression usages.

Initial application:
The issue was explicitly applied in SVN revision 13384, now git commit 09da6b23175e728a561c9bbf1d02403af87fc1ca. That commit introduced Simple FHIRPath subset links into DataRequirement path comments, ElementDefinition.slicing.discriminator.path, OperationOutcome.issue.expression, and the documentation navigation. The current source has since folded the old Simple FHIRPath page into source/fhirpath.html#simple, where the reusable restricted subset is still defined.

Additional context:
Later reconciliations and source history refine how the seed should be interpreted now. FHIR-13718 completed DataRequirement filter wording, FHIR-19612 confirmed discriminator text should link to fhirpath.html#simple instead of duplicating syntax, and FHIR-51587 is the controlling later SearchParameter decision: after reopening an earlier simple-subset proposal, FHIR-I approved guidance stating that SearchParameter.expression allows full FHIRPath while warning about resolve() and resource-boundary traversal. FHIR-53907 asks for future SearchParameter subset guidance, but it is still Triaged/Unresolved and is not a source-edit decision for this run.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build already contains the central restricted FHIRPath section, active discriminator/DataRequirement/OperationOutcome consumers point to it, and SearchParameter.expression should not be reclassified as a Simple FHIRPath consumer because later applied work-group decisions deliberately chose full FHIRPath plus guidance.

Recommendation:
Keep this audit commit as-is. Future SearchParameter subset policy should wait for a resolved/applied issue such as FHIR-53907 or successor work; do not use FHIR-13711 to undo FHIR-51587's full-FHIRPath guidance.
