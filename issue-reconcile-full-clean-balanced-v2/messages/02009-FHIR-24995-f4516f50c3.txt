FHIR-24995: Audit AdverseEvent item cardinality

Issue request:
FHIR-24995 was a Published/Persuasive Patient Care change request for R5. It asked that the AdverseEvent item[x] elements introduced by GF#17237 be 1..1 because each was the only element in its BackboneElement, and asked that the pre-applied value set bindings be reviewed.

Initial application:
The Jira-cited commit 4c4287bd97 added the GF#17237 AdverseEvent contributingFactor, preventiveAction, mitigatingAction, and supportingInfo backbone changes and explicitly noted pre-applied GF#24995 value set bindings. In that commit, the four item[x] rows were already 1..1 and carried the AdverseEventContributingFactor, AdverseEventPreventiveAction, AdverseEventMitigatingAction, and AdverseEventSupportingInfo example bindings, so the R5-era cardinality and binding request had been applied.

Additional context:
AdverseEvent is part of the current build source through source/fhir.ini, and the authoritative source has since been reworked into source/adverseevent/structuredefinition-AdverseEvent.xml. Later Jira FHIR-46599 was Applied/Persuasive with Modification for R6 and decided to remove these same single-child backbones by changing contributingFactor, preventiveAction, mitigatingAction, and supportingInfo to repeating CodeableReference elements. Commit 017e9edbd0 applied that decision, retaining the same value set bindings on the new CodeableReference elements. Current source has no AdverseEvent.contributingFactor.item[x], preventiveAction.item[x], mitigatingAction.item[x], or supportingInfo.item[x] paths remaining.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The old child cardinality was already 1..1 while the item[x] children existed, and the current specification is now correct under the later approved CodeableReference model where the child elements no longer exist.

Recommendation:
Keep this no-change audit as-is. Do not reintroduce the old BackboneElement/item[x] structure for FHIR-24995; any future concerns about these AdverseEvent fields should be evaluated against the current repeating CodeableReference design from FHIR-46599.
