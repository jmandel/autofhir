FHIR-16949: Qualify profile canonical targets

Issue request:
FHIR-16949 was a Published/Persuasive STU3 FHIR-I change request asking that canonical declarations be qualified like Reference declarations. It specifically said bare canonical should appear only when all knowledge/structure resources are valid targets, and the resolution said the remaining unqualified canonical declarations would be qualified and tooling would render those qualifiers.

Initial application:
The issue was explicitly applied in SVN revision 13903, preserved as git commit 6c55fe476ebd, which changed JsonSpecGenerator and SvgGenerator so canonical target parameters render like Reference target parameters. Later source-history work such as commit 3dc81b908557 and the already-published FHIR-16769 reconciliation qualified CDS/CQI knowledge-resource canonicals, but current source still had a few later-added profile/ruleset canonical elements without targetProfile metadata.

Additional context:
Current source/fhir.ini lists DocumentReference, Endpoint, StructureDefinition, and ExampleScenario as active current-build resources. A current audit found nine bare canonical type blocks before this reconciliation; six are intentionally broad or generic value surfaces, while Endpoint.payload.profileCanonical, DocumentReference.content.profile.value[x], and ExampleScenario.instance.structureProfile[x] all describe FHIR profiles, content profiles, templates, rulesets, or profile canonicals whose FHIR canonical target is StructureDefinition. FHIR-39616's applied Endpoint resolution explicitly requested Canonical(StructureDefinition)|URI, and FHIR-37895's published ExampleScenario resolution introduced structureProfile[x] for FHIR profiles with uri|canonical choices.

AutoFHIR reconciliation:
This commit adds targetProfile="http://hl7.org/fhir/StructureDefinition/StructureDefinition" to the canonical type on Endpoint.payload.profileCanonical, DocumentReference.content.profile.value[x], and ExampleScenario.instance.structureProfile[x]. It intentionally leaves RequestOrchestration.instantiatesCanonical, GuidanceResponse.module[x], ArtifactAssessment.artifact[x], Task input/output value[x], and Parameters.parameter.value[x] unqualified because their current definitions are broad or generic enough that narrowing them would require a targeted work-group decision.

Recommendation:
Keep this source fix as-is. It completes the clear current-source FHIR-16949 gaps without over-constraining broad canonical values; any future narrowing of the remaining broad/ambiguous bare canonical elements should be handled by specific Jira decisions.
