FHIR-19339: Audit Consent source identifier cleanup

Issue request:
FHIR-19339 was a Published/Not Persuasive with Modification STU3 CBCC request about the Consent source-identifier search parameter. The issue asked to constrain source-identifier to Identifier-valued Consent.source entries, but the final resolution instead removed Consent.sourceIdentifier as redundant because identifiers can be carried in Consent.sourceReference.

Initial application:
Commit eaffed2f39 implemented the decision by removing Identifier from Consent.source[x] and deleting the source-identifier search row from source/consent/consent-spreadsheet.xml. Later source conversion preserved that direction: the current build-scope XML has sourceAttachment and sourceReference elements and no sourceIdentifier element or source-identifier search parameter.

Additional context:
FHIR-15707 had previously split the generic Consent.source search into source-reference and source-identifier for STU3. FHIR-19339 is the later same-family decision that narrowed the model and search surface to a single source-reference parameter for references, including references identified by identifier. Attachment search remains out of scope.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current source already reflects the later decision: Consent-source-reference has expression Consent.sourceReference, and no source-identifier parameter remains to constrain.

Recommendation:
Keep this no-change audit. Future work should only revisit source-identifier if the work group explicitly restores a separate Identifier-valued source element or decides that Reference.identifier search support is insufficient.
