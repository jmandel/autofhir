FHIR-14326: Audit Range invariant re-addition

Issue request:
FHIR-14326 was a Published/Persuasive FHIR-core datatypes issue raised in STU3. It requested re-enabling Range invariant 2 after FHIRPath had been enhanced to support Quantity comparisons, with the Jira comment tying application to svn revision 13459.

Initial application:
The requested re-enable appears to have been applied by git-svn commit 11f97b11d79b7132747af46442affd51e3ef35e5 (`GF#14309 - reenable rng-2 invraiant`). Although the commit subject names the overlapping FHIR-14309 tracker, both FHIR-14309 and FHIR-14326 record the same svn revision 13459, and the commit changes the Range invariant id from `!2` back to `2`.

Additional context:
FHIR-14194 had temporarily disabled rng-2 because FHIRPath Quantity comparison was undefined. FHIR-14308 supplied the Quantity-comparison support, while FHIR-14324 was a duplicate/background request in the same FHIRPath area. Later final work changed the expression: FHIR-25736 added low.value/high.value guards for patterns, and FHIR-34417 changed the comparison to lowBoundary/highBoundary with comparable(). The combined branch already contains no-change audits for FHIR-14309 and FHIR-25736; this commit audits FHIR-14326 specifically.

AutoFHIR reconciliation:
No source change was made. Range is in current build scope via source/fhir.ini, and source/datatypes/range.xml already has active invariant id 2 for context Range with the human rule that low SHALL have a lower value than high and the current Quantity-aware FHIRPath expression. Reverting to the literal historical `low <= high` expression would discard later approved refinements.

Recommendation:
Keep this audit commit as-is. FHIR-14326 is already satisfied by the active current Range invariant, and no separate source follow-up is needed.
