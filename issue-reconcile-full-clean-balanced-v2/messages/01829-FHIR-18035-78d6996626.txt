FHIR-18035: Audit VisionPrescription Request-pattern link

Issue request:
FHIR-18035 was a Published/Persuasive FHIR-core VisionPrescription change request. It asked to add a link to workflow Request because, although the reporter viewed VisionPrescription as an authorization/Event, the workflow decision at the time was that VisionPrescription should be treated as a Request until that changed.

Initial application:
The request appears to have been applied by commit a8e6a60ffd38f4bf35217b7556ac71649f993017, whose subject explicitly lists GF #18035 and which added the VisionPrescription narrative sentence "The VisionPrescription resource is an \"request\" resource from a FHIR workflow perspective - see Workflow Request." There was no separate current-source Jira key marker for FHIR-18035.

Additional context:
FHIR-11417 records the duplicate/background rationale that VisionPrescription is an authorization for fulfillment and, from a workflow perspective, a Request rather than an Event. Later OO work in FHIR-51718, FHIR-40668, and FHIR-43454 aligned VisionPrescription with the Request pattern by adding/mapping request-pattern elements. FHIR-53506 then deliberately removed the old standalone, grammatically awkward workflow sentence while adding R6 ballot-note text that still describes alignment with the Request workflow pattern. Current source has also moved the useful local workflow link from workflow.html#request to the current Request-pattern fulfillment section.

AutoFHIR reconciliation:
No source change was made. VisionPrescription is active in source/fhir.ini, and current build-scope source already preserves the implementer-facing rule: the introduction describes VisionPrescription as an authorization, points fulfillment to Task, links to request.html#fulfillment in the Request pattern, and the StructureDefinition maps the resource and its relevant elements to the workflow Request pattern. Re-adding the old standalone sentence would be redundant and would conflict with the later FHIR-53506 cleanup.

Recommendation:
Keep this empty audit commit as-is. No follow-up is needed for FHIR-18035 unless a future work-group decision changes whether VisionPrescription should continue to participate in the Request pattern.
