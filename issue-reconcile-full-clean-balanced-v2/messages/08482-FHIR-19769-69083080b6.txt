FHIR-19769: Audit calculatedExpression cardinality ownership

Issue request:
FHIR-19769 was a Published/Persuasive FHIR-core Questionnaire issue asking that the valueExpression/value[x] part of the questionnaire calculatedExpression extension be made 1..1. The Jira resolution agrees that an extension with child extensions prohibited must carry value[x] when the extension is present.

Initial application:
The Jira snapshot records "Applied in commit: 49bb304", though that short SHA is not reachable in this current checkout. Historical checked-in release output shows the migrated cqf-calculatedValue extension surface already had Extension.extension max 0 and, by the R4B history, Extension.value[x] min 1.

Additional context:
The current core build has Questionnaire active, but it no longer contains an active questionnaire-calculatedExpression or sdc-questionnaire-calculatedExpression definition; searching source only finds the cqf-calculatedValue canonical in source/oids.ini. The current authoritative questionnaire extension is in the SDC IG, and the current SDC published StructureDefinition has Extension.extension 0..0 and Extension.value[x] 1..1 of type Expression. The FHIR Extension Pack also carries the related cqf-calculatedValue extension as deprecated, with Extension.extension 0..0 and Extension.value[x] min 1 of type Expression.

AutoFHIR reconciliation:
This is an empty external-repo audit commit. No core source change is appropriate because the affected extension definition is outside this FHIR core checkout/current build, and the current external definitions inspected for the same rule already require the Expression value.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed; if future review reopens the questionnaire calculated-expression behavior, it should be handled in HL7/sdc or the extension-pack source rather than in FHIR core.
