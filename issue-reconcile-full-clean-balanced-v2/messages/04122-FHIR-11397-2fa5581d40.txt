Issue request:
FHIR-11397 was a Published/Persuasive DSTU2 Financial Management change request for ExplanationOfBenefit asking to add Patient, Provider, and Organization to compartments.

Initial application:
The current git history does not contain a commit explicitly naming FHIR-11397, but the February 2017 compartment work by the issue reporter added ExplanationOfBenefit to the active compartments spreadsheet: first Patient/Provider-style entries, then the broader row with patient/payee, encounter, payee, and enterer/provider/payee/care-team. Those commits match the Jira request timing before the issue was marked Published.

Additional context:
The current build uses source/compartments.xml as the active source for CompartmentDefinition generation and source/fhir.ini includes both explanationofbenefit and compartmentdefinition as active resources. Current FHIR compartments are Patient, Encounter, RelatedPerson, Practitioner, Device, and Group; there is no current Organization or Provider compartment to add. Later FHIR-43309 work changed ExplanationOfBenefit.patient to subject and added Group compartment coverage while preserving the practitioner/provider-facing entries.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active ExplanationOfBenefit row already places the resource in the Patient compartment via subject/payee, the Practitioner compartment via enterer/provider/payee/care-team, plus related Encounter, RelatedPerson, Device, Group, and date entries. Adding an Organization compartment entry would be invalid for the current source because Organization is not a defined current compartment.

Recommendation:
Keep this no-change audit commit. No follow-up is needed for FHIR core unless a future work group decision creates or restores an Organization/Provider compartment; in that case the compartment spreadsheet should be revisited across all affected resources, not just ExplanationOfBenefit.
