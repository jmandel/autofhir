FHIR-40292: Audit superseded Observation value references

Issue request:
FHIR-40292 was Published/Persuasive with Modification for R5 and asked to add valueReference(Any) to both Observation.value[x] and Observation.component.value[x], with language for the specific use cases and search parameters for the new elements.

Initial application:
The issue was applied before this reconciliation. Commit 398f7536 added Reference(MolecularSequence) and canonical to both Observation.value[x] and Observation.component.value[x] plus value-reference, value-canonical, component-value-reference, and component-value-canonical search parameters; commit c09d2d2 cleaned up the component-value-canonical search parameter entry noted in the Jira comment.

Additional context:
FHIR-40560, also Published for R5, removed canonical from both Observation value choices while retaining valueReference only for MolecularSequence. R6 work then replaced MolecularSequence with MolecularDefinition in Observation (FHIR-51142/FHIR-51227), removed the canonical search parameters as non-existent choices (FHIR-52253), and concluded the Reference value choices/search parameters were orphaned once MolecularDefinition moved toward additional-resource/IG handling (FHIR-52453/FHIR-53610). Current authoritative Observation XML and search parameter source therefore omit valueReference/valueCanonical for Observation.value[x] and Observation.component.value[x]. The checked-in observation.svg still shows the older MolecularSequence/canonical diagram text, but it is a generated-looking diagram artifact and is not an authoritative source to edit on its own.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding the FHIR-40292 R5 types would contradict later R5/R6 decisions and current source, and the remaining discrepancy is limited to a stale generated-looking SVG diagram.

Recommendation:
Keep this audit commit as-is. Do not re-add Observation.valueReference, Observation.component.valueReference, valueCanonical, or their search parameters for FHIR-40292 in core; any future MolecularDefinition linkage should proceed through the later additional-resources/extension work rather than this R5 tracker.
