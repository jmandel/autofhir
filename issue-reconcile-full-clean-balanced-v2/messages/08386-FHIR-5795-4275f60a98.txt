FHIR-5795: Audit expansion identifier type change

Issue request:
FHIR-5795 was Published/Persuasive with Modification for FHIR-core ValueSet after the Vocabulary WG accepted changing ValueSet.expansion.identifier from Identifier 0..1 to uri 1..1 and adding guidance that the URI would usually be a UUID.

Initial application:
Jira records SVN revision 4663. In git, 2f3aa5a7808ad7c4cc958c0c3903cfe347bef687 applied #5795 by changing the active ValueSet spreadsheet source from Identifier 0..1 to uri 1..1, adding the UUID comment, and updating related SDC profile spreadsheets from Identifier to uri. The current refactored StructureDefinition source still has ValueSet.expansion.identifier typed as uri with max 1 and the UUID comment.

Additional context:
source/fhir.ini keeps valueset=ValueSet active under [resources] and maps ValueSet to the vocab work group, so the inspected ValueSet source is in current build scope. The later Published/Persuasive FHIR-13813 decision deliberately relaxed ValueSet.expansion.identifier from 1..1 to 0..1 because terminology servers need not persist transient expansions, and existing combined-branch commit 8c6ecbff166b83881d7e6b39add95ab0791392ff has already aligned the current ValueSet narrative with that optionality. Later FHIR-55363 was Resolved - No Change for making expansion.identifier repeat, supporting the current max 1 shape.

AutoFHIR reconciliation:
Made no source change. The current source is correct when FHIR-5795 is read together with later decisions: ValueSet.expansion.identifier remains a uri, remains non-repeating, retains the UUID guidance, and is now optional because FHIR-13813 superseded the mandatory 1..1 part of the older request.

Recommendation:
Keep this audit commit as-is. Do not restore min 1 for FHIR-5795; any future desire to require identifiers for transient expansions would need a new Vocabulary WG decision reversing FHIR-13813.
