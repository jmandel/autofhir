FHIR-17190: Audit existing-resource validate mode

Issue request:
FHIR-17190 was a Published/Persuasive FHIR-I STU3 change request for Resource.$validate. It asked to allow `[Resource]/[id]/$validate` to validate an existing resource against the `profile` parameter by adding another validation mode, with the original resolution saying that for this mode the `resource` parameter SHALL NOT be present.

Initial application:
The Jira comment records svn revision 13920. The corresponding git-svn commit 1604de958ba478dc6728ee921e169f57b694b518 explicitly mentioned GF#17190 and added the `profile` validation mode to the historical Resource spreadsheet terminology, defining it as checking an existing resource nominated by id, not supplied as a parameter, against the nominated profile. Later source restructuring carried that mode into source/resource/codesystem-resource-validation-mode.xml and source/resource/operationdefinition-Resource-validate.xml.

Additional context:
Later FHIR-I issue FHIR-41357 revisited the same Resource.$validate mode/resource/profile matrix and was Applied/Persuasive with Modification for R6. Its approved resolution deliberately relaxed the resource input rule to say the resource must be present unless mode is delete or the operation is invoked at the instance level, removed the `profile` mode parenthetical requiring the existing resource to be nominated by id and not supplied as a parameter, clarified that the profile parameter is required for mode=profile and may appear in other modes, and requested the current summary table. FHIR-41357 is already represented on the combined branch by its own no-change audit commit. The current source is in build scope because source/fhir.ini lists Resource as an active infrastructure resource and source/resource/list-Resource-operations.xml references OperationDefinition/Resource-validate.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source still supports the core FHIR-17190 capability: the required Resource Validation Mode value set includes `profile`, Resource.$validate accepts a `profile` parameter, and the summary table explicitly allows instance-level validation of existing content by profile without a resource parameter. Reinstating the original SHALL-NOT-present rule would conflict with the later FHIR-41357 decision that resource content may still be supplied at instance level for id-specific business-rule validation.

Recommendation:
Keep this audit commit as-is. Do not change current Resource.$validate source for FHIR-17190 unless FHIR-I makes a new decision to reverse the later FHIR-41357 matrix behavior.
