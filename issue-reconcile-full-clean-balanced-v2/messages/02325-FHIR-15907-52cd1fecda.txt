FHIR-15907: Audit current TLS guidance

Issue request:
FHIR-15907 was a Published FHIR-core Security change request, resolved Persuasive for STU3, asking the Security page to recommend TLS 1.2 or higher for secure HTTP production data exchange, consider making that a requirement, and add strong-cipher-suite guidance.

Initial application:
The issue was applied in 95ee245e72 as part of a broad Security narrative update tagged GF#15907 and GF#17242. That commit changed source/security.html from TLS/SSL wording to TLS-only guidance, added an IETF BCP 195 paragraph that explicitly said TLS 1.2 or higher should be used for production exchange, limited older TLS versions, forbade SSL, and recommended strong cipher suites.

Additional context:
FHIR-17242 was applied in the same commit and separately asked for BCP 195 as the TLS recommendation. FHIR-17422 later rejected a mandatory TLS 1.2 floor for core FHIR, with Zulip discussion saying jurisdictional or IG-specific requirements were a better home for a hard version mandate. FHIR-33937 is a later Published Security decision for the same Security paragraph; its comments and resolution favored retaining the BCP 195 reference while removing copied TLS-version and cipher-suite details because BCP 195 changes over time. The current build-scope source/security.html retains the TLS production-exchange recommendation and BCP 195 reference, and source/safety.html plus the active safety-entries CodeSystem retain the BCP 195 checklist item.

AutoFHIR reconciliation:
No source change was made. The current source reflects the original FHIR-15907 direction through TLS/BCP 195 guidance, while the more explicit TLS 1.2 and cipher-suite sentences were intentionally superseded by later Security WG context rather than accidentally lost.

Recommendation:
Keep this audit commit as-is. Do not restore the old TLS 1.2/cipher-suite restatement unless the Security WG makes a new current decision to restate specific IETF BCP 195 details in core FHIR.
