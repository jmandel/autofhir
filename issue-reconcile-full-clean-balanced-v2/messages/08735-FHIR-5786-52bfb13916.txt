FHIR-5786: Audit ValueSet expansion hierarchy hinting

Issue request:
FHIR-5786 was a Published/Persuasive with Modification DSTU1 Vocab change request asking whether UI hinting for value set expansions needed mechanisms other than a hierarchical expansion, because the expansion hierarchy was used for categorized picklists but was not intended to carry semantics. The final resolution was to mark the issue resolved by a clearer definition, and Jira comments said this had been resolved under a different task by explicitly noting that meaning could not be inferred from the hierarchy.

Initial application:
No direct source commit mentioning FHIR-5786 was found in the ValueSet history. The matching application is the related FHIR-8042 change in git commit 9bc3b77afaeb0acd3f6333788b85dd0a5a350463, which changed the ValueSet notes and element comments to say nested expansion contains elements imply no logical relationship, cannot be used for logical inferencing, and exist for human navigational assistance. FHIR-8042 is already represented on the combined branch, so this commit does not duplicate that issue.

Additional context:
ValueSet is an active resource in source/fhir.ini, and the current ValueSet source still carries the intended rule in both the ValueSet notes hierarchy section and the StructureDefinition comment for ValueSet.expansion.contains.contains. The current $expand operation also exposes controls such as excludeNested and excludeNotForUI for flat/UI-oriented expansion behavior, but FHIR-5786's accepted resolution was the clearer non-semantic hierarchy definition rather than a new current source change. FHIR-5788, the separate historical $expand profile-parameter alternative mentioned by the seed text, is already represented on the combined branch and was not re-decided here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already tells implementers that expansion nesting has no logical/inference semantics and is for navigation, which satisfies the seed issue's final resolution without adding redundant prose.

Recommendation:
Keep this audit commit as-is. No current FHIR source follow-up is needed for FHIR-5786 unless the Vocab work group reopens the broader question of new UI hinting mechanisms; related historical issues FHIR-8042 and FHIR-5788 should remain separate decisions.
