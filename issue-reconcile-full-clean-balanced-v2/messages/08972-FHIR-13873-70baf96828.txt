FHIR-13873: Audit TestScript MIME binding scope

Issue request:
FHIR-13873 was a Published/Persuasive with Modification STU3 TestScript change request. It proposed adding xml-patch and json-patch codes to the TestScript content-type value set, but the accepted resolution instead required TestScript.setup.action.operation.accept, TestScript.setup.action.operation.contentType, and TestScript.setup.action.assert.contentType to use the infrastructure MimeType value set and to remove valueset-content-type.html from the specification.

Initial application:
The Jira comment records svn @12867. The corresponding git import commit 78b133a4cb19dee52cdac8d322e757fa3cd3d0f5 changed the TestScript spreadsheet bindings from ContentType to MimeType and removed the local content-type value-set sheet, which is the substantive STU3 application of the issue.

Additional context:
The current core build no longer has active TestScript source. Commit f9a44787c45071394532c7c2ee94d76f30f47387 removed the testing resources from core source/fhir.ini and source/testscript while adding the external HL7 FHIR Testing IG to additional-ig-list. Current source/fhir.ini has active MIME terminology entries, including MimeTypes and PatchMimeTypes, but no active TestScript resource entry or source/testscript files; current source searches also found no valueset-content-type.html or ValueSet/content-type reference that would preserve the removed local TestScript value set.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The requested core TestScript binding locations are outside the current core build, and reintroducing or editing retired core TestScript source would be outside this reconciliation scope.

Recommendation:
Keep this audit commit as-is for the core specification. If the external HL7 FHIR Testing IG currently carries TestScript and still has an incorrect contentType binding, reconcile that repository/IG separately rather than changing core FHIR source.
