FHIR-47284: Audit FHIRcast subscription comparison

Issue request:
FHIR-47284 was an Applied FHIR-core change request for the Subscriptions Framework page, resolved Persuasive with Modification for R6. It asked that the Relation to FHIRcast text emphasize FHIRcast as context synchronization rather than Subscription-style content-change signaling, and list the practical differences around user workflow, single-event delivery, batching, session lifetime, broadcast behavior, and optimization goals.

Initial application:
The issue was applied before this reconciliation by commit 4e73af3f1614b849887e1f011569261d831b5672, "FHIR-47284 - Improve FHIRcast comparison to emphasize context synchronization", which rewrote source/subscriptions.html to add the approved context-synchronization comparison and the additional FHIRcast-vs-Subscriptions bullets. The Jira comment points to HL7/fhir pull request 3967 as the implementation path.

Additional context:
The March 31, 2025 FHIR-I minutes record the Subscriptions block vote including FHIR-47284 as Persuasive with Modification and the Jira snapshot records a 17-0-0 vote. The subscriptions narrative page is in build scope through source/hierarchy.xml and the active Subscription, SubscriptionStatus, and SubscriptionTopic entries in source/fhir.ini. A source search found the current Relation to FHIRcast section but no remaining older "user-activity synchronization" or "different projects" wording.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source/subscriptions.html Relation to FHIRcast section already conveys the approved distinction: FHIRcast synchronizes current context for same-user/same-device applications, sends single-event notifications, uses short-lived sessions, broadcasts the same event concurrently, and optimizes for real-time speed; Subscriptions are for distinct systems, can batch high-frequency notifications, are long-lived resources, and tailor notification contents per client.
