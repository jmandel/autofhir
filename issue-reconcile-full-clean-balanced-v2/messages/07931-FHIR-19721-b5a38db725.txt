FHIR-19721: Audit ValueSet generated link fix

Issue request:
FHIR-19721 was a Published/Persuasive technical correction for the ValueSet page. It reported that the generated "see designation" link for ValueSet.expansion.contains.designation and the analogous ValueSet.expansion.contains.contains content-reference link were dead on valueset.html, even though the underlying StructureDefinition text was not wrong.

Initial application:
The issue appears to have been applied by source commit 9734426b100dc8a2f7c986e87cd2630dc7e09d9f, "FHIR-19721 Dead hyperlinks in ValueSet page", which changed the resource templates from <%resource-table%> to <%resource-table-all%>. That makes the main resource page include the full structure table and therefore include the anchors needed by content-reference links.

Additional context:
ValueSet is an active build resource in source/fhir.ini. The current ValueSet StructureDefinition still has the expected contentReference values for ValueSet.expansion.contains.designation and ValueSet.expansion.contains.contains, so the remaining question is generated-page link behavior rather than resource semantics. Confluence records show Vocab sent the ticket to FHIR-I because changing ValueSet wording would not fix the generated-link problem, and FHIR-I assigned it to Grahame. A Zulip committers thread records Grahame investigating and fixing the unique-link/rendering behavior in February 2023.

AutoFHIR reconciliation:
This commit makes no source change. The source/templates already contain the applied fix, and current rendered R5 and CI pages include valueset-definitions.html links plus matching anchors for the reported content references.

Recommendation:
Keep this audit commit as-is. No further FHIR core source change is needed for FHIR-19721 unless a future publisher/template regression removes the full resource table or breaks these generated anchors again.
