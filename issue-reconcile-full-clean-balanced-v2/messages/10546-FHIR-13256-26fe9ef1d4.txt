FHIR-13256: Audit update id error wording

Issue request:
FHIR-13256 was Published with a Persuasive with Modification resolution for STU3. It asked to remove the ambiguous update-interaction phrase "or the value is wrong" from the HTTP 400 text because the same page already discusses 405 Method Not Allowed when update-as-create is not supported.

Initial application:
The issue was applied in svn-backed commits 5b2d13e6e95626f0bba1823707b14f6518a3332a and 5f78baae4ea650cd60862639a889e8bae5900458, both titled "#13256 - fix wrong note about update.id". The first removed the ambiguous phrase; the second replaced it with a narrower id/URL mismatch rule. Commit 3e6cd9de0126f86ea3ded7f240f8d027e83a96f0 later fixed that replacement's typo from "of the id disagrees" to "or the id disagrees".

Additional context:
The linked Zulip thread records Grahame Grieve explaining that, instead of simply deleting the highlighted text, he changed it to say the request is a 400 when the body id differs from the URL id, and invited objections. Current source also retains the issue-requested 405 guidance in the same update section for servers that do not allow client-defined ids.

AutoFHIR reconciliation:
No source change was made. The current build source no longer contains the ambiguous "value is wrong" wording, states the specific 400 case for a missing id or id/URL disagreement, and separately covers the 405 update-as-create rejection case.

Recommendation:
Keep this no-change audit commit as-is. No further FHIR core source work is recommended for FHIR-13256 unless the work group wants to revisit the intentional id/URL mismatch guidance.
