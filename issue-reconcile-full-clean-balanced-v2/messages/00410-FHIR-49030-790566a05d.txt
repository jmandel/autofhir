FHIR-49030: Audit Permission action binding outside core

Issue request:
FHIR-49030 was an Applied/Persuasive Security WG change request for the R6 Permission resource. It asked to bind Permission.rule.activity.action to the CRUDE-oriented http://hl7.org/fhir/ValueSet/type-restful-interaction value set with preferred strength instead of the privacy/consent action vocabulary.

Initial application:
The request was applied in core by commit 61227667280962bc6ddbfa74556a90db70d8be9a and merged through HL7/fhir#3296. That commit changed source/permission/structuredefinition-Permission.xml from an example binding to http://hl7.org/fhir/ValueSet/consent-action to a preferred binding to http://hl7.org/fhir/ValueSet/type-restful-interaction.

Additional context:
After the application, commit 0e2a8a7f839d5e1a43787523daccf07d958362f3 removed the Permission resource from the core build, including the active source/fhir.ini entries and the source/permission directory. The current Security module links Permission to the Data Access Policies IG instead of a core resource page, and the current Data Access Policies source contains Permission.rule.activity.action with the requested preferred type-restful-interaction binding. FHIR-49031 was approved and implemented alongside this issue, and it already has a separate external-repo audit on the combined reconciliation branch.

AutoFHIR reconciliation:
This audit commit intentionally makes no core source change because the current core checkout no longer owns or builds the Permission resource, and the external Permission source already carries the FHIR-49030 binding. Reintroducing or editing source/permission would be out of current build scope and would conflict with the later resource removal.

Recommendation:
Keep this external-repo audit as-is for the core reconciliation. No core follow-up is indicated for FHIR-49030; any future Permission action binding changes should be made in the Data Access Policies IG if that external source of truth changes.
