FHIR-11306: Audit Sequence variation description

Issue request:
FHIR-11306 was a Published/Persuasive Clinical Genomics change request against the DSTU2 Sequence resource. The original comment asked whether the resource should be named for genetic variation instead of Sequence because the introduction said the resource had at most one variation; the accepted resolution narrowed the action to changing the website description because the single-variant wording was a typo.

Initial application:
The issue appears to have been applied together with the neighboring Sequence wording issue FHIR-11307 by git commit 54e60c59aa7079e0f7bf544e617b09edc183060c, "#11307 Revise introduction on Sequence resource page." That commit changed source/sequence/sequence-introduction.xml from "at most one variation" and "a sequence variation" to wording about "multiple variations" and "sequence variations". A direct git log search for FHIR-11306 only found an unrelated SVN revision number, not a Jira-tagged application commit.

Additional context:
Later source history renamed Sequence to MolecularSequence for FHIR-19453, and current source no longer contains source/sequence or source/molecularsequence directories. source/fhir.ini lists Sequence under [removed-resources], does not list Sequence or MolecularSequence in active [resources], and leaves MolecularSequence only as commented/inactive metadata. The current Diagnostics module tells readers MolecularSequence has been replaced by MolecularDefinition, and the MolecularDefinition source describes molecular entities and Sequence/Allele/Variation profiles without the old single-variation limitation.

AutoFHIR reconciliation:
This audit made no source change. The accepted correction for the issue's actual resolution was already applied in the historical Sequence source, the current build scope no longer includes the old Sequence/MolecularSequence resource, and exact source searches found no remaining "at most one variation" or equivalent single-variant wording to fix.

Recommendation:
Keep this no-change audit. No current FHIR core source edit is needed for FHIR-11306; any future genomics naming or modeling work should follow the active MolecularDefinition/Molecular Data Types issue trail rather than reopening this DSTU2 Sequence wording correction.
