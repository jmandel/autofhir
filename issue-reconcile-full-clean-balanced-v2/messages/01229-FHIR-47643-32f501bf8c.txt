FHIR-47643: Audit draft-resource compatibility wording

Issue request:
FHIR-47643 was an Applied/Persuasive FHIR-I change request for the FHIR core compatibility page. It asked whether adding a reference to a draft/non-normative resource from normative content would make the referenced resource effectively fixed forever, and the approved resolution was to append text saying non-normative referenced resources may still be renamed before becoming normative and may sometimes be removed.

Initial application:
The issue appears to have been applied by commit 0497ffa7855726059d80793c2b254ff8989b232b, included in merged PR HL7/fhir#3181. That commit changed source/versions.html by removing provisional editor text and adding the approved non-normative-resource clarification to the References row of the forward/backward compatibility table.

Additional context:
source/versions.html is in the current build via publish.ini's versions.html entry. The current References row already includes the approved clarification, and the same section separately notes that normative CodeSystems generated from mixed normative and non-normative content may have non-normative resource codes removed or renamed. Confluence WGM minutes record the FHIR-I vote and rationale in the same terms; Zulip searches for this issue and key wording found no conflicting discussion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active source already says that where a reference is to a non-normative resource, the referenced resource name may still change until the resource becomes normative, and that non-normative resources may in some cases be removed in future FHIR versions.

Recommendation:
Keep this audit commit as-is. No follow-up source edit is needed for FHIR-47643 unless the work group later changes the broader compatibility policy for normative references to non-normative artifacts.
