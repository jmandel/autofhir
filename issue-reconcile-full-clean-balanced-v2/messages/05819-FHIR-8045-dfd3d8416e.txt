FHIR-8045: Audit DetectedIssue severity value set application

Issue request:
FHIR-8045 was a Published, Persuasive with Modification DSTU1 vocabulary issue for the former Alert/Contraindication area. It asked that ContraindicationSeverity stop being the v3 SeverityObservation H/M/L value set directly and instead use native FHIR high, moderate, and low codes, with mappings to v2/v3 where possible.

Initial application:
The Jira comments record SVN revisions 5731 and 5732. The relevant source application is git commit af86b5382c64c6172b7046bb2baf47422de44291 (SVN r5732), which changed the Contraindication severity example from H to high, changed the binding source from the v3 SeverityObservation value set to an internal #contraindication-severity list, changed the visible choices to high | moderate | low, and added v3 ObservationValue mappings for H, M, and L.

Additional context:
The former Contraindication resource was renamed to DetectedIssue by #8043 in commit 1408563d743f15eff785f59063b34b538b4d4651, and source/fhir.ini now records DetectedIssue as an active resource while Contraindication is a removed/renamed resource. Current DetectedIssue source keeps the native detectedissue-severity CodeSystem and ValueSet with high, moderate, and low codes and a ConceptMap to v3 ObservationValue H/M/L. A later Applied R6 issue, FHIR-44528, intentionally changed DetectedIssue.severity from required code to preferred CodeableConcept, so the current non-required binding is later work-group intent rather than a missed FHIR-8045 application.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope DetectedIssue source already reflects the FHIR-8045 semantic request through the native high/moderate/low severity vocabulary and v3 mappings, and changing the binding back to required would conflict with the later FHIR-44528 decision.

Recommendation:
Keep this audit commit as-is. No core FHIR follow-up is needed for FHIR-8045 unless the work group separately reopens DetectedIssue severity policy; any such work should account for FHIR-44528's preferred CodeableConcept decision.
