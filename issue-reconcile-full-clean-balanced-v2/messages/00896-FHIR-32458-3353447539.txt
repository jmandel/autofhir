FHIR-32458: Audit applied AuditEvent network cardinality

Issue request:
FHIR-32458 was a Published/Persuasive Security WG change request for R5 asking why AuditEvent.agent.network.address was optional when AuditEvent.agent.network.type could be present. The accepted resolution was to make both .agent.network.type and .agent.network.address 1..1, leaving optionality only on the containing .network element.

Initial application:
Commit e84eb2b6ce8d1a2516c0f0a21e19f78cb7fce143 applied FHIR-32458 directly by changing both AuditEvent.agent.network.address and AuditEvent.agent.network.type from min=0 to min=1 in source/auditevent/structuredefinition-AuditEvent.xml. That source file is in build scope because source/fhir.ini lists auditevent=AuditEvent as an active resource.

Additional context:
The same Security block-vote family later applied FHIR-32459 in commit 3d204189e23e03f0b4f11d03d491bc1d868e399b, replacing the AuditEvent.agent.network backbone and its address/type children with AuditEvent.agent.network[x] of type Reference(Endpoint), uri, or string. The current conversion map records AuditEvent.agent.network.address and AuditEvent.agent.network.type as mapping to network[x], and FHIR-32459 is already represented on the combined branch by 3361713448ae61edd34a85a1f02c541eea4278b5. FHIR-32450 supplied the surrounding agent-specific network definition/comment context.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative AuditEvent source has no separate network.type element that could appear without an address; when network information is present, it is a single 0..1 network[x] endpoint/address value. Current examples use networkString/networkUri, and the old child elements are preserved only as R4/R5 conversion mappings.

Recommendation:
Keep this audit commit as-is. Do not reintroduce the old network backbone merely to express the FHIR-32458 cardinality wording; the later FHIR-32459 network[x] model supersedes the old type/address child design while preserving the implementer-facing concern that a partial network child is not valid.
