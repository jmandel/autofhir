FHIR-22146: Audit MedicationRequest performer HealthcareService

Issue request:
FHIR-22146 was a Published/Persuasive Pharmacy change request raised against STU3 and applied for R5. It asked that MedicationRequest.performer allow HealthcareService because the same element already allowed CareTeam and Organization, and the resolution was to add HealthcareService to the MedicationRequest.performer choice.

Initial application:
The Jira application comment points to merge commit d338b629407370eccfc6dcaf5bb04304123a677a, which included the Pharmacy20190724 change set. Inspecting that merge shows the old MedicationRequest spreadsheet changed MedicationRequest.performer from Reference(Practitioner | PractitionerRole | Organization | Patient | Device | RelatedPerson | CareTeam) to include HealthcareService. The later source rework commit 33b409a4b6d544598262f2f074ebb4b6dc466157 carried the target profile into structuredefinition-MedicationRequest.xml.

Additional context:
MedicationRequest is active in source/fhir.ini, so source/medicationrequest/structuredefinition-MedicationRequest.xml is in the current build scope. A later same-element issue, FHIR-35895, changed MedicationRequest.performer cardinality to 0..* for multiple performers but did not remove HealthcareService; the current definition now also mentions that multiple performers can be listed.

AutoFHIR reconciliation:
No source change was made. The current active MedicationRequest StructureDefinition already lists http://hl7.org/fhir/StructureDefinition/HealthcareService as a MedicationRequest.performer target profile, and adjacent search-parameter/source checks did not reveal a conflicting current artifact that needs correction.

Recommendation:
Keep this audit commit as-is. The current specification satisfies FHIR-22146, and adding redundant prose would not change implementer understanding.
