FHIR-10008: Audit superseded FamilyMemberHistory age estimate marker

Issue request:
FHIR-10008 was Published as Persuasive with Modification for DSTU2. The reporter asked FamilyMemberHistory to distinguish an approximate age from an actual integer age; Patient Care resolved to add a core modifier boolean for the age estimate state and to update the FamilyMemberHistory.age definition to "The age of the relative at the time of the onset of the condition."

Initial application:
The Jira comment points to SVN #9053, now git commit 02ef67eba5476f3a28aa2f3d18efa6afe7c8eadb. That commit added FamilyMemberHistory.estimatedAge, changed the active age definition away from "actual or approximate age", added the missing-meaning text, and added an fhs-2 invariant tying estimatedAge to age[x]. The current source lineage later renamed/represented the resolution as estimatedAge rather than the Jira prose's ageEstimated wording.

Additional context:
FamilyMemberHistory remains an active current-build resource in source/fhir.ini. A later final Patient Care decision, FHIR-54457, superseded this part of the model: it was Applied for R6 with a vote to remove FamilyMemberHistory.estimatedAge because Range can express approximation and the actual-vs-estimated distinction was not clinically actionable. The combined branch already contains 6202fac1e4fd705975023b7b58a46535f99ccf25 for FHIR-54457, completing removal from active FamilyMemberHistory surfaces. FHIR-52939 is a related Patient Care no-change decision with the same estimate-precision rationale for an extension, but it is outside core and only background here.

AutoFHIR reconciliation:
This commit intentionally makes no source change for FHIR-10008. Re-adding estimatedAge or another exact/estimated age flag would restore a DSTU2-era request that was deliberately removed by the later Applied FHIR-54457 decision. The active FamilyMemberHistory.age[x] definition no longer references fhs-2, and the estimatedAge element remains only in a commented historical block.

Recommendation:
Keep this audit commit as-is. If Patient Care wants to reintroduce structured actual-vs-estimated age semantics, that should be handled as a new decision that explicitly revisits FHIR-54457 rather than by resurrecting FHIR-10008.
