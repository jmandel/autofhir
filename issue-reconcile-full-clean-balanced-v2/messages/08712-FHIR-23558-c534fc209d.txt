FHIR-23558: Audit date search period matching

Issue request:
FHIR-23558 is a Published/Persuasive with Modification FHIR-I change request, raised against STU3 and applied for R5, asking the Search date section to clarify how date search parameters match periods. The accepted resolution was to state that date searches intrinsically match against periods, regardless of whether the underlying element is a period-like or date/dateTime value, and to point readers to the prefixes section for period/range comparisons.

Initial application:

That commit subject says FHIR-23588, but Jira FHIR-23588 is an unrelated Da Vinci CDex typo issue, so the key in the source commit appears to be a transposed/mistyped tracker reference rather than a different search decision.

Additional context:
The current source/search.html is the active Search narrative page: it declares the Search page title and the fhir.ini search-rules section explicitly instructs maintainers to update the search.html summary table when search rules change. The date subsection now says date searches match periods regardless of underlying element type, converts date/dateTime/instant/Period/Timing values to periods, and links to the Prefixes section. The Prefixes section supplies the period/range semantics: eq is containment, gt/ge/lt/le use intersection/overlap with the relevant range, and sa/eb are non-overlap boundary tests. The original Zulip thread confirms the reporter's question was the contained-versus-overlap distinction and that implementers concluded eq behaves as containment while gt/lt/ge/le behave as overlap. Earlier related FHIR-19909 was Resolved - No Change on the same general date/Period confusion because the prefix section already explained interval overlap, non-overlap, and containment. Later FHIR-40304 further clarified period comparison wording and examples, and that related reconciliation is already represented on the combined branch.
