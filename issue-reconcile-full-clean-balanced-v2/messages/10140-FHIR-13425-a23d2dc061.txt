FHIR-13425: Audit Observation focus handling

Issue request:
FHIR-13425 was Published with a Persuasive with Modification resolution for STU3. It asked how to document a related person's health literacy or care skill, such as whether a mother is trained to change her child's tracheostomy tube, when Observation.subject did not support RelatedPerson. The final resolution chose the focal-subject mechanism with the child as subject and the mother as the focal target, and requested a choice plus an example for clarity.

Initial application:
The source history shows the request was applied before this reconciliation. Git 75c4cced61 added focal-subject.reference to the Observation extension spreadsheet with Reference(Patient, Person, RelatedPerson, Group, Device), a RelatedPerson example note, and committee note #13425. Git d06b52856c kept the #13425 trail while separating the code-based extension from the reference-based focus modeling. Git 5c093b94a9 then renamed Observation.focalSubject to Observation.focus as part of the same Observation focus change family.

Additional context:
Observation is an active current-build resource in source/fhir.ini. Current core source deliberately leaves Observation.subject as the record subject and does not add RelatedPerson there, while Observation.focus is a Reference(Resource) for the actual focus when it differs from the subject of record. The active focus comment includes the parent/child tracheostomy use case, and the trachcare example records the child as subject and the mother as focus. The old observation-focusCode extension is now in the FHIR Extension Pack, marked deprecated/retired, and points implementers to Observation.focus and referenced resource elements. Later FHIR-14443/FHIR-14863 and the linked Zulip discussion explain why the WG chose focus instead of broadening subject, and FHIR-43357 later reinforced focus as the current modeling location for a more specific target.

AutoFHIR reconciliation:
This audit commit makes no source change. The current core build already conveys the requested rule through Observation.focus and the tracheostomy-care example, and adding RelatedPerson to Observation.subject would contradict the later accepted focus/subject split.

Recommendation:
Keep this no-change audit. Do not change Observation.subject for FHIR-13425; use Observation.focus when the observation is stored against one subject of record but is actually focused on a related person or other associated resource. If desired, any cleanup of deprecated focusCode extension wording belongs in the FHIR Extension Pack and is not required to make the current core spec correct.
