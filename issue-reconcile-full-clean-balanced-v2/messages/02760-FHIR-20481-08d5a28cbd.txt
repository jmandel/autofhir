FHIR-20481: Audit on-hold medication status wording

Issue request:
FHIR-20481 was a Published/Persuasive Pharmacy change request raised against STU3 and applied for R5. It asked whether on-hold MedicationRequest/MedicationStatement medications that might later be stopped should remain on-hold before discharge, and the final resolution said the medication should stay on hold unless someone with authority can discontinue it. The approved wording removed the prior expectation that an on-hold prescription must continue later and instead said it may or may not be resumed.

Initial application:
Jira records application to build in merge commit 16680e7ffc2f0f3b8cf031ce23e828ec14c2457e. The underlying Pharmacy commit 92cc8632039c231c346b3ab90697c9c0537a1a5f changed the MedicationRequest on-hold code definition from "temporarily halted, but are expected to continue later" to "temporarily halted. The prescription might or might not be resumed." I found no corresponding FHIR-20481-specific MedicationStatement status definition change in that commit.

Additional context:
Both MedicationRequest and MedicationStatement are active current-build resources in source/fhir.ini. Current MedicationRequest now says the request might or might not be resumed, preserving the approved FHIR-20481 semantics with the current resource terminology. Later Pharmacy decisions changed MedicationStatement more substantially: FHIR-19468/FHIR-19470 introduced adherence for taking/not-taking semantics, FHIR-32060 and FHIR-39271 confirm MedicationStatement.status now reflects only the recording status of the statement, and FHIR-39333 added on-hold and stopped descendants under the MedicationStatement adherence not-taking code. The combined branch already contains reconciliation commits for FHIR-19470 and FHIR-39271, so those related decisions should not be republished here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active MedicationRequest CodeSystem already carries the approved "might or might not be resumed" meaning. MedicationStatement no longer has an on-hold status code to update; the current adherence model represents on-hold as a kind of not-taking without retaining the obsolete "expected to continue later" restriction. Adding new resumption prose to the example-bound adherence codes would be a broader, later MedicationStatement wording decision rather than a necessary FHIR-20481 fix.

Recommendation:
Keep this audit commit as-is. If Pharmacy wants more detailed MedicationStatement.adherence code definitions, handle that as follow-up under the MedicationStatement adherence issue family rather than as a delayed application of FHIR-20481.
