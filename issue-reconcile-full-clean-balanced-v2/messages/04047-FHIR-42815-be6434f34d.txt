FHIR-42815: Audit Vital Signs summary wording

Issue request:
FHIR-42815 is an Applied/Persuasive with Modification OO change request for R6 asking the Vital Signs summary to say that Observation.value[x] might be absent when the Observation has components, because the formal constraint is that value[x] or Observation.dataAbsentReason is required only when there is no component or hasMember.

Initial application:
The issue was applied by git commit bdb002a19e0c8649183015f89143df0e5c4949da, which changed source/observation/structuredefinition-profile-vitalsigns.xml so the manually maintained summary mentions a populated component or hasMember relationship before requiring Observation.DataAbsentReason. No prior AutoFHIR reconcile commit for FHIR-42815 was present on the combined branch.

Additional context:
The current build-scope source keeps Observation active in source/fhir.ini, and source/observation/implementationguide-Observation-vitalsigns.xml includes StructureDefinition/vitalsigns. The source profile now contains both the canonical structuredefinition-summary and tools profile-summary extensions with the same component/hasMember wording. The vsp-2 constraint still says that if there is no component or hasMember, either value[x] or dataAbsentReason must be present. Later combined-branch reconciliations for FHIR-49736, FHIR-43353, and FHIR-50565 cleaned other vital-signs summary details without reversing the FHIR-42815 wording.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Vital Signs Base Profile summary already conveys the approved clarification and remains aligned with the formal vsp-2 constraint; adding more prose would be redundant rather than a necessary spec correction.

Recommendation:
Keep this audit commit as-is. Future work on broader simple-vital-sign constraints or summary wording should proceed under the relevant separate trackers, not under FHIR-42815.
