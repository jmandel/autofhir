FHIR-7775: Audit financial business rule elements

Issue request:
FHIR-7775 was a Published/Persuasive with Modification Financial Management change request from the DSTU1 ballot. It objected that the FM resource ruleSet/originalRuleset elements duplicated Resource.implicitRules and Meta.profile behavior, and the accepted resolution was to remove Ruleset and OriginalRuleset from the FM resources while relying on those common elements for business-rule context.

Initial application:
The source history shows the change was applied before publication. Commit 84584d1c5f1c075ba6140aee7a360c216e3eed3b, "Removal of business rules elements," marked Claim, ClaimResponse, EligibilityRequest/Response, EnrollmentRequest/Response, ExplanationOfBenefit, PaymentNotice, PaymentReconciliation, ProcessRequest, and ProcessResponse ruleset/originalRuleset rows as deleted. Commit 13534944609a7a29cd453f21a0fbcde8c6f0bd22 then removed the Ruleset binding from source/terminologies/bindings.xml.

Additional context:
The current build has the relevant active financial resources in source/fhir.ini, with ProcessRequest and ProcessResponse commented as retired and CoverageEligibilityRequest/Response mapped from the old EligibilityRequest/Response names. Current active financial source folders have no live ruleset or originalRuleset rows. The only remaining old resource rows found are bang-prefixed deleted rows in retired process/eligibility spreadsheets, and the stale ruleset terminology XML files are not linked from bindings.xml or rendered at current/R5 ruleset value set or code system URLs. Current Resource.implicitRules and Meta.profile definitions provide the intended common mechanisms.

AutoFHIR reconciliation:
No source change was made. The current build-facing source already implements the Jira disposition, and deleting out-of-build/stale historical source files would not change the current specification semantics.

Recommendation:
Keep this audit commit as-is. If future cleanup work targets unused terminology source files or OID entries, handle that as a separate maintenance issue rather than as necessary FHIR-7775 reconciliation.
