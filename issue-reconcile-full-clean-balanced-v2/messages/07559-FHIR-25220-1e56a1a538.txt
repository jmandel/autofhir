FHIR-25220: Audit dependent group invocation wording

Issue request:
FHIR-25220 was Published/Persuasive with Modification for the FHIR mapping language. It asked to clarify that the optional `then` dependent-rules clause can name multiple groups, not just one, and the recorded resolution also said groups are executed in order.

Initial application:
The Jira-tagged application commit cd0bed57d72 changed source/mapping-language.html so the Dependent Rules summary now says `then` specifies one or more groups by name, separated by comma, or a set of child rules. That commit did not add the separate execution-order sentence from the original resolution. The current detailed Dependent Rules section also documents that multiple groups may be specified, separated by commas, and that inline dependent rules are evaluated after all nominated groups have been invoked.

Additional context:
The mapping language page is in the current build navigation through source/hierarchy.xml and source/documentation.html. FHIR-I minutes for 2019-12-16 record the original vote including `Groups are executed in order.` However, when Grahame applied FHIR-25220 in February 2023, a Zulip thread explicitly questioned that execution-order sentence in light of FHIR-23010's rule that mapping rules are implementation-defined in order. After discussion, the original reporter agreed that he was fine with reverting the execution-order part of the resolution for R5. Earlier FHIR-20840/FHIR-20848 decisions are in the same dependent-rule family and mention sequential invocation, but reconciling that broader tension would require a separate issue-specific review rather than changing FHIR-25220.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current source already satisfies the seed's durable clarification that multiple group invocations are allowed, and adding the omitted order sentence now would contradict the later application discussion that deliberately removed that part of the resolution.

Recommendation:
Keep this audit commit as-is for FHIR-25220. If FHIR-I wants deterministic ordering for dependent group invocations, reconcile that as a separate mapping-language decision that explicitly considers FHIR-20840, FHIR-20848, FHIR-23010, and the February 2023 Zulip thread.
