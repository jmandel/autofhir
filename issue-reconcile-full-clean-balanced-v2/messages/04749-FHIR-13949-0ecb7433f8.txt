FHIR-13949: Audit Patient match markup cleanup

Issue request:
FHIR-13949 was a Published/Persuasive STU3 technical correction for the FHIR-core Patient operations page. It reported that the Patient-match description rendered erroneous literal markup such as \n and \" on the patient operations page and asked that the markup be removed.

Initial application:
The issue appears to have been applied in git commit 9ec491238348d5da09f2d1d85646a96723e4fcba, which was labeled "Tracker #14024, 13949, 13953, 14232" and changed the old source/patient/patient-spreadsheet.sheet.txt Patient match documentation from double-escaped text such as \\\n\\\n and \\\"$match\\\" to normal newline and quote escaping. Later source refactoring moved the operation definition out of the spreadsheet into source/patient/operationdefinition-Patient-match.xml.

Additional context:
Patient remains an active current build resource in source/fhir.ini, and source/patient/list-Patient-operations.xml includes OperationDefinition/Patient-match. The current operation definition uses XML newline and quote entities in the description/comment rather than the literal backslash markup reported in STU3. Searches of Zulip and Confluence found no direct community discussion or later decision that changes the Jira/source conclusion.

AutoFHIR reconciliation:

Recommendation:
Keep this no-change audit commit as-is. No FHIR core source follow-up is needed for FHIR-13949 unless a future rendered build, rather than the checked-in operation source, shows a generation defect that reintroduces literal backslash markup.
