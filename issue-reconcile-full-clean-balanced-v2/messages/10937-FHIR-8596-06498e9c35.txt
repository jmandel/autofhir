FHIR-8596: Audit profile comment rendering

Issue request:
FHIR-8596 was a Published/Persuasive non-substantive FHIR-I correction raised for DSTU1. It reported that profile element comments were not displayed in generated element-detail pages, with a USLab DiagnosticReport profile definitions page as the example, and the Jira application comment recorded SVN revision 6609.

Initial application:
The issue was applied in Git commit 43b01e970731b08726424b8872a93730552760a8, "#8596 - fix comments falling out of profiles," whose git-svn metadata points to build@6609. The semantic hunk changed the old Java ProfileGenerator condition from the accidental double-negated comments check to setting comments when e.getComments() is not empty, so profile element comments were preserved for generated details.

Additional context:
The old Java generator files changed by the application commit are no longer present in the current checkout; the ProfileGenerator file was deleted during the 2021 build/tooling refactor. Current source/fhir.ini still has active profile spreadsheet entries, and the profile definitions template delegates detailed-description rendering to the shared definitions placeholder rather than carrying an issue-specific hard-coded comments rule. Current profiling guidance also still treats ElementDefinition.comment as a valid place for profile-specific expectations, and current CI generated ElementDefinition detail output includes a visible Comments row for ElementDefinition.comment. The original USLab URL is an old external/generated page, not a current FHIR-core source artifact to edit here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The historical renderer defect was fixed by the recorded SVN/Git application commit, the affected in-repo Java tooling has since been retired, and current generated detail output shows comments rather than dropping them.

Recommendation:
Keep this no-change audit commit. Revisit only if a current build-scope profile detail page is shown to drop ElementDefinition.comment again; that would likely need investigation in the current publisher/rendering toolchain rather than resurrecting the removed DSTU-era Java generator code.
