FHIR-7053: Audit AllergyIntolerance alert guidance

Issue request:
FHIR-7053 was a Published Patient Care change request, resolved Not Persuasive with Modification, asking what approach should be recommended for recording alerts after the AllergyIntolerance misuse text said not to use AllergyIntolerance for alerts. The approved resolution was to append that alerts are handled using Flag or, where event-specific, Contraindication.

Initial application:
The issue was applied in git commit a30496dcda9c86251cf286f1636c23e570a80113, which explicitly listed #7053 and changed the AllergyIntolerance introduction from "Not to be used for recording alerts" to the requested guidance with links to Flag and Contraindication. Later in 2015, commit cc54b56e72272bed97b5c33459fc90bc2bfe52d8 updated the same sentence from Contraindication to DetectedIssue as part of replacing references to the renamed resource.

Additional context:
AllergyIntolerance is an active resource in source/fhir.ini, so source/allergyintolerance/allergyintolerance-introduction.xml is in current build scope. The current source says alerts are handled using Flag or, where event-specific, DetectedIssue, and source/fhir.ini records that Contraindication became DetectedIssue. Later Patient Care issue FHIR-32856 quoted this same Misuse section while deciding that pertinent negatives were already covered there, and current Flag guidance remains consistent with using Flag for condensed alerting information and DetectedIssue for planned or ongoing action-related issues.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build-scope AllergyIntolerance source preserves the final FHIR-7053 guidance, with the historically correct modern resource name DetectedIssue replacing Contraindication.

Recommendation:
Keep this no-change audit commit as-is. No core source follow-up is needed for FHIR-7053 unless a future work group decision changes the Flag versus DetectedIssue boundary.
