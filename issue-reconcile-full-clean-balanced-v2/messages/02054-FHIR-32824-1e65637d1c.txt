FHIR-32824: Audit Endpoint status availability clarification

Issue request:
FHIR-32824 was Published/Persuasive with Modification for Endpoint.status. The reporter asked for either an unknown status code or 0..1 cardinality because endpoint directories may not know the current health/status of an endpoint. The PA work group chose not to change the cardinality or add an unknown code; instead it resolved to clarify that Endpoint.status represented general expected availability, that temporary or unexpected short-term downtime would not be represented in Endpoint.status, that Endpoint.period should carry a matching downtime comment, and that regular health-check or short-term downtime details belonged outside the property.

Initial application:
Commit ed05f6312aaa6fdf04780c93f1b9baa2d927b4ed applied the issue by updating source/endpoint/structuredefinition-Endpoint.xml: it changed Endpoint.status to a general expected availability definition, added the temporary-downtime comment to Endpoint.status, and added the corresponding Endpoint.period comment. The current source still keeps Endpoint.status mandatory at 1..1 and the Endpoint status CodeSystem has no unknown code, matching the resolved approach rather than the reporter's proposed alternatives.

Additional context:
Endpoint is an active current-build resource in source/fhir.ini. The exact Endpoint.status definition was later revised by Applied/Persuasive with Modification issue FHIR-36017, whose resolution explicitly changed the definition to whether the endpoint can currently be used for connections or why it cannot be used, added Endpoint.availability for specific availability including transient downtimes and exceptions, and clarified Endpoint.period's planned lifecycle purpose. The combined branch already contains the FHIR-36017 reconciliation commit 504023192d19571d31acb27dc45aa4c14f9c7365. PA minutes for FHIR-32824 record the persuasive-with-modification vote with no contrary discussion, and targeted Zulip searches found no conflicting community decision.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The current Endpoint source already embodies the FHIR-32824 decision when read with the later FHIR-36017 model: Endpoint.status remains required, no unknown status code was added, status/period text distinguishes the core lifecycle/status properties from temporary availability details, and Endpoint.availability now carries the more specific transient availability information. Reverting the later FHIR-36017 status wording back to FHIR-32824's original phrase would discard a later final PA decision.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-32824 unless PA opens a new issue to add an explicit unknown status code or make Endpoint.status optional despite the published R5 resolution.
