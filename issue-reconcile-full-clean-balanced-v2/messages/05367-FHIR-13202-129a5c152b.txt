FHIR-13202: Audit activeOnly ExpansionProfile wording

Issue request:
FHIR-13202 was a Published/Persuasive with Modification vocab correction for the DSTU2 ExpansionProfile.activeOnly element. It asked to replace confusing comments that said inactive codes were included when activeOnly=true with wording that activeOnly=true includes only active codes, cannot add inactive codes excluded by the value set definition, and should clarify missing-element behavior and active/inactive status interpretation.

Initial application:
The issue was applied in svn revision 13527, represented in git as 72590280d4b673985723ed20d21dd475d84dee89, which changed source/expansionprofile/expansionprofile-spreadsheet.xml from the confusing "Inactive codes are included if activeOnly is present" text to the approved "Only active codes are included" wording and added the requested meaning-if-missing and status notes.

Additional context:
ExpansionProfile is no longer part of the current FHIR build. Later Published vocab decisions FHIR-16337 and FHIR-16490 removed the ExpansionProfile resource in git commit 0cf4c0c96d4a903aa7180f7d4d33dc0ecf57f945, and source/fhir.ini now records "; ExpansionProfile=approved -> dropped" while ValueSet remains active. The remaining current activeOnly surface is the ValueSet/$expand operation parameter, whose documentation states that activeOnly controls inclusion or exclusion of inactive concepts and can remove inactive codes from an expansion but cannot include inactive codes when the value set excludes them. Separate current ValueSet and CodeSystem text covers default inactive-code behavior and code-system-specific active/inactive interpretation.

AutoFHIR reconciliation:
This audit commit makes no source change. The originally requested ExpansionProfile source no longer exists in the active build, the historical application matched the Jira resolution before removal, and the current activeOnly operation documentation no longer contains the confusing reversed statement.

Recommendation:
Keep this audit commit as-is. Do not restore or edit ExpansionProfile for this issue because it is out of build scope. Revisit only if the vocab work group wants a separate current-build clarification to ValueSet/$expand activeOnly beyond the historical ExpansionProfile correction.
