FHIR-3839: Align DiagnosticReport encounter search description

Issue request:
FHIR-3839 was a Published/Persuasive DSTU1 OO change request asking core DiagnosticReport to add an encounter reference. The final motion approved a 0..1 Reference(Encounter) linked to the encounter where the order was created.

Initial application:
Commit 42b3e0ef629223d03f49481d856a41d1f7918509 explicitly applied #3839 by adding DiagnosticReport.encounter as 0..1 Reference(Encounter) and creating the encounter search parameter with the original "The Encounter when the order was made" description. Later source migrations preserved the element and generated search-parameter source.

Additional context:
DiagnosticReport is active in source/fhir.ini. Later applied OO decisions changed how the encounter element should be understood in the current build: FHIR-12797 aligned DiagnosticReport with the event pattern, FHIR-17662 retained the element as .encounter, FHIR-48767 clarified that DiagnosticReport.encounter typically represents the encounter where reported data or specimens were obtained/acquired and that ServiceRequest.encounter supplies order association through DiagnosticReport.basedOn, and FHIR-51687 changed the requirements text from request to report. Those later decisions supersede the original order-only wording while preserving the encounter element requested by FHIR-3839.

AutoFHIR reconciliation:
This commit updates the active DiagnosticReport encounter search parameter description from the stale order-encounter wording to "Encounter associated with the DiagnosticReport," matching the current element short and avoiding conflict with the FHIR-48767 ServiceRequest.encounter guidance. No element cardinality, type, expression, or search code changed.

Recommendation:
Keep this narrow source fix. It preserves the FHIR-3839 encounter capability and aligns the current search surface with later OO decisions; no additional core source work is needed for this seed unless a future work group decision changes DiagnosticReport.encounter semantics again.
