FHIR-33033: Align BDP storage ModelInfo

Issue request:
FHIR-33033 was a Published/Persuasive with Modification OO change request for R5. It asked to change BiologicallyDerivedProduct.storage.temperature from a single decimal value to a range and to remove the .scale attribute because biologically derived product storage requirements are specified as lower/upper temperature ranges.

Initial application:
The primary BiologicallyDerivedProduct source appears to have been applied before this reconciliation as part of the broader BDP resource replacement committed in a261b7c6662ea3b212f0c8e20c83c3ada67cbee1 for FHIR-33068. That patch removed the old BiologicallyDerivedProduct.storage backbone with storage.temperature decimal and storage.scale, added BiologicallyDerivedProduct.storageTempRequirements as Range, and updated the example to use low/high temperature bounds. Current release notes also record that .storage.temperature was renamed .storageTempRequirements and is now a Range. No separate git commit explicitly mentioning FHIR-33033 was found.

Additional context:
BiologicallyDerivedProduct is active in the current build through source/fhir.ini. The FHIR ModelInfo sidecar is also an active publication surface: the Library examples page links source/library/library-fhir-model-definition-content.xml as the FHIR model information file used by CQL tooling, and publish.ini copies that content file. That sidecar still exposed the removed BDP storage backbone, decimal temperature, and BiologicallyDerivedProductStorageScale model/helper even though the authoritative StructureDefinition and examples already use storageTempRequirements as Range. FHIR-33068 is same-change-family context for the broader BDP table that included storageTempRequirements and is already represented on the combined branch. OO minutes and targeted Zulip searches did not reveal a conflicting decision.

AutoFHIR reconciliation:
Updated the active FHIR ModelInfo sidecar so BiologicallyDerivedProduct exposes storageTempRequirements as FHIR.Range instead of the removed storage list. Removed the stale BiologicallyDerivedProduct.Storage class, BiologicallyDerivedProductStorageScale model type, conversion metadata, and FHIRHelpers ToString overload, then refreshed the embedded Library payloads so they match their sidecar content files. The authoritative BiologicallyDerivedProduct StructureDefinition and examples were left unchanged because they already express the accepted range-based storage requirement.

Recommendation:
Keep this commit. It completes the FHIR-33033 storage change across the active CQL ModelInfo publication surface without taking over unrelated BiologicallyDerivedProduct model drift. Any remaining BDP ModelInfo mismatches should be reconciled under their own Jira evidence trail; the product-storage-scale OID registry rows were not removed because no current source value set/code system uses them and assigned OIDs may remain as historical registry data.
