FHIR-37631: Clarify medication administration device roles

Issue request:
FHIR-37631 was a Published/Persuasive Pharmacy change request for R5 asking the MedicationRequest and MedicationAdministration .device and .performer descriptions to explain when a device is merely used in an administration versus actually performing the administration. The approved resolution made .device the device essential to administration, with patch and syringe examples, and made device performers the pump-like device actually administering the medication.

Initial application:
The Jira-tagged implementation commit dc170b26ef270aa638b21e96e615b162e17b6d06 updated the MedicationRequest.performer and MedicationAdministration.performer definitions but did not apply the approved .device definition to either resource. MedicationRequest.device already has cardinality 0..* in the current source, so no cardinality fix is needed.

Additional context:
MedicationRequest and MedicationAdministration are active current-build resources in source/fhir.ini. Later FHIR-37973 adjusted MedicationAdministration.performer/performer.actor and temporarily restated MedicationAdministration.device with the older PCA-pump wording, but its resolution says the performer/device descriptions should correspond to the MedicationRequest distinction. Later FHIR-46961 kept MedicationAdministration.device as a Device reference and added Device/DeviceDefinition boundary guidance; that later decision affects target type/comment text, not the missing performer-vs-used distinction. Confluence minutes only record that Pharmacy intended a new Jira issue to clarify both resources, and no conflicting Zulip discussion was found.

AutoFHIR reconciliation:
Updated the authoritative StructureDefinition XML for MedicationRequest.device and MedicationAdministration.device to use the approved essential-device wording and patch/syringe examples, while leaving the already-applied performer definitions, cardinalities, target types, and the later FHIR-46961 Device/DeviceDefinition comment intact. Synchronized the checked-in MedicationRequest SVG tooltip so the resource diagram no longer exposes the stale PCA-pump device definition.

Recommendation:
Keep this source fix as-is. It completes the missing .device half of FHIR-37631 without reversing later MedicationAdministration Device/DeviceDefinition guidance; no separate reconciliation commit is made for the related later issues because they remain context rather than independently decided work here.
