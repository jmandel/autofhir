FHIR-15841: Complete contact role relationship split

Issue request:
FHIR-15841 is Applied/Persuasive with Modification. It asked PA to address Patient.contact's guardian use case by separating personal relationships from functional contact roles for Patient.contact and RelatedPerson, binding personal relationship to v3-PersonalRelationshipRoleType, binding the new role elements to relatedperson-relationshiptype, deprecating Patient Contact Relationship, and mapping Patient.contact.relationship to NK1-3 and Patient.contact.role to NK1-7.

Initial application:
Git commit 23f3b0abec5678767e3cc7e4b576fdbd3e3b9fb2 applied the split by adding Patient.contact.role and RelatedPerson.role, changing the relationship bindings, adding examples, and adding a RelatedPerson-role search parameter. The current source still left Patient.contact v2 mappings ambiguous, described Patient.contact.role's binding as a personal relationship, left the obsolete Patient Contact Relationship value set draft, and gave RelatedPerson-role the RelatedPerson.relationship expression.

Additional context:
source/fhir.ini actively builds both Patient and RelatedPerson, so the edited StructureDefinitions, resource-local ValueSet, and RelatedPerson search-parameter bundle are current core source. FHIR-31670, already represented on the combined branch, supplied the relatedperson-relationshiptype value-set content for functional roles including guardian. FHIR-54559 later confirms the RelatedPerson-role search expression is a copy-paste error, but it remains Resolved - change required and is cited only as supporting context, not separately decided here.

AutoFHIR reconciliation:
This commit completes the applied FHIR-15841 source changes: Patient.contact.relationship now maps to NK1-3, Patient.contact.role now describes a functional role and maps to NK1-7, RelatedPerson.role now has the matching NK1-7 mapping, Patient Contact Relationship is marked deprecated/retired, and the RelatedPerson-role search parameter now evaluates RelatedPerson.role.

Recommendation:
Keep this source fix as-is. A future FHIR-54559 reconciliation can audit that its specific search-parameter correction is already present, but no separate FHIR-54559 decision is published in this default applied/published seed run.
