FHIR-37773: Audit ConceptMap valueCode guidance

Issue request:
FHIR-37773 was Published/Not Persuasive with Modification for R5. The submitter asked to remove code as a choice for ConceptMap2 dependsOn/product value[x] because valueCode did not identify a code system or version; the final decision kept valueCode and asked for clarifying text that interpretation depends on the associated property and that valueCode implies a known code system.

Initial application:
The issue was first applied in git commit b77b742253 by adding the requested explanatory paragraphs to source/conceptmap/conceptmap-notes.xml and changing the $translate output sentence to mention only dependsOn values. A later ConceptMap notes/example update in git commit 5ecdbc1543 reintroduced product to that sentence while broadening the section to target.dependsOn and target.product.

Additional context:
ConceptMap is active in source/fhir.ini, so the notes, StructureDefinition, and $translate OperationDefinition are current build inputs. FHIR-32541 had already established that both dependsOn and product values are included in $translate output, and the current OperationDefinition contains both match.product and match.dependsOn output parts. FHIR-40504 later split ConceptMap mapping properties from additional source/target attributes, and FHIR-40636 later clarified the valueCode rule more precisely: dependsOn.valueCode comes from the group source code system and product.valueCode comes from the group target code system.

AutoFHIR reconciliation:
This audit commit makes no source change. The current source already conveys the needed rule through the active ConceptMap notes and element definition, and removing "and product" from the $translate sentence would now contradict the active $translate output parameter definition and later ConceptMap decisions.

Recommendation:
Keep this audit as-is. No FHIR core source change is recommended for FHIR-37773; any future work should be handled as a new ConceptMap terminology decision if the work group wants to revisit version-specific guidance for valueCode.
