FHIR-27849: Move patient-instruction guidance to patientInstruction

Issue request:
FHIR-27849 was Published/Persuasive with Modification for R5 and requested changing Appointment.patientInstruction from string 0..1 to CodeableReference(DocumentReference, Binary, Communication) 0..*, so multiple plain-text, coded, or referenced instruction artifacts can be supplied.

Initial application:
The main structural change was applied by git commit 413a8406c5c8eeae3f565b5a63c6dcacaa964f18, which changed Appointment.patientInstruction to CodeableReference 0..*, added the three target profiles, and added an example. That commit also appended patient-instruction usage guidance to Appointment.note, where the type is Annotation and the guidance referred to CodeableReference concept/reference capabilities that do not belong to note.

Additional context:
Appointment is an active current-build resource in source/fhir.ini. FHIR-19521 separately changed the old Appointment.comment field to Appointment.note 0..* Annotation, and FHIR-31523 was later marked duplicate because the requested multiple comments were handled by FHIR-27849 and FHIR-19521. PA minutes confirm FHIR-27849 intended patientInstruction to support multiple CodeableReference instructions and documentation references; no Zulip hit was found that changes that interpretation.

AutoFHIR reconciliation:
This commit keeps the already-correct datatype, cardinality, target profiles, and example, but moves the CodeableReference usage guidance off Appointment.note and onto Appointment.patientInstruction. It also updates the Appointment Request-pattern mapping exception resource text so the checked-in exception mirrors the corrected Appointment.note comment.

Recommendation:
Keep this source fix. It preserves the approved FHIR-27849 model while removing misleading note guidance that could make implementers think Appointment.note supports CodeableReference concept/reference content.
