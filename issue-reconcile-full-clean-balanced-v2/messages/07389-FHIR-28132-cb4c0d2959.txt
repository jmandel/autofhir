FHIR-28132: Audit Questionnaire item-type unit guidance

Issue request:
FHIR-28132 was a Published/Persuasive with Modification FHIR-core Questionnaire change request. It reported that the Questionnaire item-type quantity definition pointed to questionnaire-unit even though that extension is constrained to integer and decimal items, and asked to clarify that quantity uses questionnaire-unitOption and questionnaire-unitValueSet while integer and decimal use questionnaire-unit for computable extraction units.

Initial application:
The issue was explicitly applied in git commit e096aeb964 on the Questionnaire-fixes branch. That commit added questionnaire-unit guidance to the decimal and integer item-type definitions in source/questionnaire/codesystem-item-type.xml and changed the quantity definition to reference questionnaire-unitOption and questionnaire-unitValueSet for Quantity.code and Quantity.system. The Jira comment records the same Questionnaire-fixes commit. Related FHIR-34391 had already moved quantity away from questionnaire-unit, and FHIR-28132 refined the surrounding integer, decimal, and quantity wording.

Additional context:
Questionnaire is an active resource in source/fhir.ini and the active item-type value set entry composes http://hl7.org/fhir/item-type from source/questionnaire/codesystem-item-type.xml, so the inspected terminology source is in current build scope. The current source still has questionnaire-unit only on decimal and integer, and questionnaire-unitOption/questionnaire-unitValueSet only on quantity. The current Extension Pack definitions, now the authoritative home for these extension StructureDefinitions, confirm questionnaire-unit is constrained to integer/decimal and unitOption/unitValueSet are constrained to quantity. FHIR-37363 later added the detailed required-unit matching guidance to the extension definitions without changing the core item-type distinction. Existing combined-branch audit commits already represent FHIR-34391 and FHIR-37363, so they are related evidence rather than additional decisions here.

AutoFHIR reconciliation:

The small difference between the resolution's proposed phrase "unit(s) are allowed to be selected" and the current item-type phrase "what unit should be selected" does not create a conformance ambiguity when read with the extension definitions, which carry the allowed-values details.
