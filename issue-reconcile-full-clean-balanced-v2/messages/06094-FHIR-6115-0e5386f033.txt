FHIR-6115: Audit Address district addition

Issue request:
FHIR-6115 was a Published/Persuasive with Modification MnM change request from DSTU1 asking to add additional Address parts for international postal addresses. The accepted resolution added Address.district and said county should be represented in city when a region uses county in place of municipality.

Initial application:
The issue was historically applied by commit 998d5a5f9389484135209ed1b232317d60d83aee, "#6115 - add Address.district," matching the Jira comment that recorded svn revision 5932. That commit added the Address.district row and the county/city usage note to source/datatypes/address.xml.

Additional context:
Address is active in the current build: source/fhir.ini lists Address under [types] and marks Address normative. A later published typo correction, FHIR-9057, fixed the same usage note from "county' in used" to "county' is used"; a 2018 Zulip discussion confirmed the current intended interpretation that municipality belongs in Address.city and district/county is only for a larger region smaller than state/province/territory.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative datatype spreadsheet still has Address.district as 0..1 string with definition "The name of the administrative area (county)" and the usage note saying county names should be conveyed in city when county is used in place of municipality, satisfying the FHIR-6115 resolution.

Recommendation:
Keep this audit commit as-is. No current FHIR source change is needed for FHIR-6115; future edits should only revisit the Address.district semantics if MnM decides to change the postal-address guidance itself.
