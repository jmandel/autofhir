FHIR-28940: Audit Library profile additions

Issue request:
FHIR-28940 was Published/Persuasive for R5 by the CDS work group. It requested adding Library profiles from the Quality Measure IG, specifically Executable, Publishable, and Computable Library profiles, and the final resolution also required ModuleDefinition and ModelInfo Library profiles.

Initial application:
FHIR-I minutes moved the tracker to CDS, and commit bd5308f495 applied J#28940 with related Library profile work by adding Library profile StructureDefinitions and listing them in the Library CQF implementation guide. There is no remaining unapplied R5 source hunk for the seed itself.

Additional context:
Later Applied/Persuasive issue FHIR-48393 explicitly removed profile definitions from the base specification for R6, saying CQLLibrary, ELMLibrary, LogicLibrary, ModelInfoLibrary, and FHIRPathLibrary had moved to Using CQL With FHIR and ModuleDefinitionLibrary, PublishableLibrary, and ShareableLibrary had moved to CRMI. Commit 571498e2b2 then deleted the Library profile files and removed the Library package list entries. A CDS agenda snapshot records the broader TSC direction that resource profiles should not remain in the base FHIR specification.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Library resource is still active in source/fhir.ini, but source/library/list-Library-packs.xml is empty and the Library profile StructureDefinition files that FHIR-28940 added are absent because the later FHIR-48393 decision superseded their placement in core. Restoring them to core would conflict with current R6 source direction.

Recommendation:
Keep this audit commit as-is. Do not restore the R5 Library profiles in core; if any of those profile definitions need maintenance, handle that in the owning external IGs or in a separate bounded reconciliation for FHIR-48393 and its broader profile-removal scope.
