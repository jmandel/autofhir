FHIR-13614: Audit EOB claim type label correction

Issue request:
FHIR-13614 was Published/Persuasive for STU3 Financial Management. It reported that ExplanationOfBenefit.type displayed "Example Claim Type Codes" while the binding strength shown in parentheses was Required, creating an apparent typo/inconsistency in the claim type binding label.

Initial application:
No source commit explicitly tagged FHIR-13614 was found. The linked 2017 Zulip thread records the immediate application path: the binding strength was changed to extensible and the word "Example" was to be removed later. The follow-up Jira FHIR-13751 then captured that remaining work, and git commit 49ee52b963abadc71e75fff3c1f5e31e86d25d30, "Tracker #13751 related", changed the Claim Type value set from "Example Claim Type Codes" to "Claim Type Codes", removed sample/example wording, and changed the source system away from the example URL.

Additional context:
FHIR-13751 is a Published/Persuasive follow-up to FHIR-13614 and confirms the intended current state: Claim Type codes are used extensibly in Claim, ClaimResponse, and ExplanationOfBenefit, with the non-example claim-type URL and value set description. The current fhir.ini keeps ExplanationOfBenefit active in the build. Current source/explanationofbenefit/structuredefinition-ExplanationOfBenefit.xml binds ExplanationOfBenefit.type extensibly to http://hl7.org/fhir/ValueSet/claim-type, and source/claim/valueset-claim-type.xml now has title "Claim Type Codes" and description "This value set includes Claim Type codes." A source-wide search found no remaining "Example Claim Type Codes" text.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because the build-relevant current source already reflects the FHIR-13614 correction and its FHIR-13751 follow-up: the EOB type binding is no longer Required, and the bound value set is no longer labeled as an example set.

Recommendation:
Keep this audit commit as-is. FHIR-13614 should remain closed with no additional core source edit; any future claim-type terminology cleanup should be handled under a new targeted issue rather than reopening this typo correction.
