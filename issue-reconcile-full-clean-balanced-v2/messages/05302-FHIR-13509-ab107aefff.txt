FHIR-13509: Audit $translate url parameter

Issue request:
FHIR-13509 was a Published/Persuasive with Modification Vocabulary change request for STU3 asking that ConceptMap $translate type-level invocation accept an optional 0..1 input parameter named url of type uri so callers can identify an explicit or implicit ConceptMap by canonical URL rather than by instance id.

Initial application:
The Jira records the issue as applied in SVN r13316. Git history preserves that application in 4a1dbf1a8cbd27ddd00b0e6343ad07d701436e8e, whose message names GF#13509 and adds a translate.url row with 0..1 cardinality, uri type, and the requested canonical ConceptMap URL documentation to the ConceptMap operation spreadsheet. The later operation-source rework carried that row into the current OperationDefinition XML.

Additional context:
The same SVN-import commit also implemented the tightly related FHIR-15728 request for conceptMap and conceptMapVersion type-level parameters; that related issue is already represented on the combined branch by 0ae633cd99413e7e6e87ab5522ca9e5089509c31, so this commit does not duplicate it. ConceptMap is an active current-build resource in source/fhir.ini, and source/conceptmap/list-ConceptMap-operations.xml references OperationDefinition/ConceptMap-translate. Vocabulary meeting evidence lists FHIR-13509 on the 2018-01-08 tracker call and in the 2018-02-22 block vote as Persuasive with Mod. Zulip and Confluence searches found no conflicting later community decision.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because the current build source already defines url as a type-scoped 0..1 in parameter of type uri on ConceptMap $translate, with documentation matching the Jira request.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-13509 unless a future terminology-service decision intentionally changes how ConceptMap $translate identifies the ConceptMap to use.
