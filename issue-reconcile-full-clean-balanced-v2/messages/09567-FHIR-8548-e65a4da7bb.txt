FHIR-8548: Audit complex extension modifier allowance

Issue request:
FHIR-8548 was a Published/Not Persuasive with Modification FHIR-core extensibility issue raised against DSTU1. It asked to allow modifier extensions inside complex extensions; the final resolution instead allowed elements/components of complex extensions to be marked isModifier while making clear that they are conveyed using extension, not modifierExtension.

Initial application:
The issue was applied in git commit fb014f678bbc94e0498ec1d5424cf7cfde9e6848, whose subject says "#8548 - note about modifiers in extensions" and whose git-svn revision matches the Jira comment. That commit changed source/extensibility.html to state that complex extensions may have elements marked modifier=true, that such elements modify the extension value itself, and that they are conveyed using extension rather than modifierExtension.

Additional context:
FHIR-8548 directly followed FHIR-8549, which had temporarily rejected nested modifier flags until this policy question was resolved. Later FHIR-11036, FHIR-18352, and FHIR-37903 refined the wording around the same rule. The current combined branch already has audit commits for those later issues. source/fhir.ini maps extension=extensibility, confirming that source/extensibility.html is the active current build surface for Extension extensibility guidance.

AutoFHIR reconciliation:
This empty commit makes no source change. The current active source already preserves the approved FHIR-8548 rule: complex extension parts can be Is-Modifier=true, those parts are still represented using extension rather than modifierExtension, and is-modifier elements not defined as part of the extension definition cannot be conveyed inside an extension.

Recommendation:
Keep this no-change audit commit. The current source is semantically correct after later wording refinements, and adding redundant prose or restoring the earlier FHIR-8549 tool rejection would create drift from the approved extensibility model.
