FHIR-29595: Audit questionnaire displayCategory context

Issue request:
FHIR-29595 was Published/Persuasive for FHIR-core Questionnaire in R5. It reported that the questionnaire-displayCategory extension said it described display text but had contextInvariant type!='display', which excluded display items; the expected correction was to stop prohibiting display items.

Initial application:
The same defect was already captured by FHIR-25127 on the current core source line and applied by f0b7244ac8, changing the extension context invariant from type!='display' to type='display'. FHIR-29595 itself was applied on the R4B line by 0f9f03800b with the same one-line correction.

Additional context:
Core later removed the questionnaire extension definitions from R5 source in dd468d4f17, so the active FHIR-core checkout no longer owns structuredefinition-extension-questionnaire-displayCategory.xml. The current Extension Pack definition for questionnaire-displayCategory is the active source for the extension. A later Published FHIR-extensions decision, FHIR-43033, reviewed questionnaire extension contexts and commit 59d4c2c removed the displayCategory contextInvariant while restoring ElementDefinition context because a single contextInvariant could not safely cover both Questionnaire.item and ElementDefinition use.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The erroneous core invariant is not present in current core source, the prior core source was corrected before removal, and the current Extension Pack state reflects a later final context review rather than an unapplied FHIR-29595 typo.

Recommendation:
Keep this no-change audit as-is for FHIR-core. Do not reintroduce the old core extension file or add a core patch; any future concern about whether displayCategory should be constrained differently now belongs in the FHIR Extension Pack and should account for FHIR-43033's ElementDefinition-context decision.
