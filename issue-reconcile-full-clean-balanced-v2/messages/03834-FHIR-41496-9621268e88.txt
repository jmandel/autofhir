FHIR-41496: Audit Quantity datatype anchors

Issue request:
FHIR-41496 was an Applied/Persuasive FHIR-core technical correction for R6 asking that the bad anchor links around the Quantity section on the datatype pages be reviewed and corrected, especially datatypes-examples.html using #count where the section should be reachable as #Quantity and datatypes.html exposing inconsistent #quantity/#Quantity links.

Initial application:
The issue was applied before this reconciliation by commit 64a3fffa26689936c243b6aa0d36cf55dbb4cec5, referenced from the Jira comment via HL7/fhir pull request 3898. That commit moved the second datatypes-examples.html Quantity anchor from the earlier alias cluster to immediately after the count anchor and immediately before the Quantity heading. No prior AutoFHIR reconcile commit with Issue-Reconcile-Key: FHIR-41496 was present on the combined branch.

Additional context:
The current combined branch contains the historical application commit. source/fhir.ini lists Quantity as an active datatype and maps datatypes to the datatype pages, so source/datatypes.html and source/datatypes-examples.html are current build inputs. Current source/datatypes-examples.html now has #Quantity immediately before the Quantity heading after #count, and source/datatypes.html exposes both #Quantity and #quantity before its Quantity heading. Confluence minutes only show the procedural FHIR-I tracker handling, and a Zulip search found no conflicting discussion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current specification source already preserves the canonical #Quantity anchors needed by the diagrams and cross-page links while retaining lowercase compatibility anchors where present.

Recommendation:
Keep this audit commit as-is. No further core source work is needed for FHIR-41496 unless a later link-checking build reports a new datatype-anchor regression.
