FHIR-11070: Audit Consent category value set

Issue request:
FHIR-11070 was a Published DSTU2 CBCC change request resolved Not Persuasive with Modification. It objected to the original Consent.category example codes and requested replacing that value set with a richer sample Consent Directive Type value set using established consent-related terminologies rather than ad hoc cat1-cat6 examples.

Initial application:
The issue was applied in git-svn commit 6c5132df04 (svn revision 11255), which changed source/consent/valueset-consent-category.xml and source/consent/codesystem-consent-category.xml for Consent.category. That application removed the old cat1-cat6-centered content from the active value set path and introduced consent directive type coverage based on HL7/LOINC/v2/v3 sources.

Additional context:
Consent is active in the current build through source/fhir.ini. Later Consent-category work changed the same artifact family: FHIR-15115 temporarily moved toward extensible vocabularies, FHIR-31904 later made Consent.category 0..* with an example binding because the value set should not be treated as globally consensus/extensible, FHIR-44625 removed LOINC display values, FHIR-48780 promoted Consent terminology metadata for R6, and 2025 source maintenance renamed the value set to consent-category-example and fixed the canonical URL. No directly relevant Zulip or Confluence record was found for FHIR-11070.

AutoFHIR reconciliation:
No source change was made. The current active Consent.category definition binds at example strength to http://hl7.org/fhir/ValueSet/consent-category-example, and the current ValueSet includes sample consent directive type sources from THO/v2/v3 and specific LOINC codes without reintroducing the poor ad hoc category set that FHIR-11070 targeted.

Recommendation:
Keep this audit commit as-is. Do not reapply the literal 2017 XML from the Jira resolution because later applied decisions intentionally refactored the terminology source, binding strength, metadata, and canonical name while preserving FHIR-11070's substantive correction.
