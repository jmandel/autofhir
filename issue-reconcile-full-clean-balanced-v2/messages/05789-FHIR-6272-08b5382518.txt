FHIR-6272: Audit Flag extension-point handling

Issue request:
FHIR-6272 was a Published Patient Care change request with resolution Not Persuasive with Modification. The IHE mACM review asked whether several alert extension points should be added for Flag; the approved resolution declined a Flag recipient and other core Flag additions, directed targeted communications to Communication, and called for standard extensions for communicated media and Flag priority while usage was evaluated.

Initial application:
The issue appears to have been applied by git commit 8aa58daf36, "Addressing warnings; #6272 - extensions to flag and communication", which introduced the Flag priority extension/value-set material and Communication media extension material in the then-current core extension spreadsheets. The current git history also shows generated terminology follow-up for the same value-set family and later removal of extension definitions from R5 core source.

Additional context:
Flag and Communication are active core resources in source/fhir.ini. Current Flag source has no recipient or priority element, and its narrative says Flag is not used to convey information to a specific individual or organization; such cases are handled by CommunicationRequest and Communication. Current Communication supports recipients and payload content including attachments. The standard communication-media and flag-priority extension definitions, plus the flag-priority value set and code system, are present in the FHIR Extension Pack rather than active core resource source.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The core source already preserves the work-group decision not to expand Flag with recipient or priority elements, and the requested standard extensions are represented in the Extension Pack, so their absence from active core source is not a missing core edit.

Recommendation:
Keep this no-change audit as-is. Any future semantic change to communication-media or flag-priority should be handled in the Extension Pack or by a new Patient Care decision; no current core FHIR source correction is warranted for FHIR-6272.
