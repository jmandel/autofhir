FHIR-13833: Audit DNA variant ID cardinality as external IG content

Issue request:
FHIR-13833 was a Published FHIR-core Observation change request, resolved Persuasive with Modification, asking to make Observation-geneticsDNAVariantChange.Id support multiple identifiers from systems such as dbSNP and ClinVar. The accepted resolution said the spirit of the change was already applied in the Genomics Reporting IG, where the described variant variation-code component supports 0..* codings.

Initial application:
No current FHIR-core source contains Observation-geneticsDNAVariantChange or an active Observation-genetics variant profile. Historical core source did contain a Variant.Id row with 0..1 CodeableConcept in source/observation/observation-genetics-profile-spreadsheet.xml, but no FHIR-13833-specific core commit was found. Clinical Genomics minutes approved FHIR-13832, FHIR-13833, and FHIR-13835 together as already applied to the Genomics Reporting IG but not to Observation-genetics in FHIR Core; later core history pointed genomics guidance to that IG and removed outdated clinical genomics artifacts from Observation, DiagnosticReport, and ServiceRequest.

Additional context:
Observation remains active in the current core build, but the legacy Observation-genetics profile and DNAVariantChange extension are no longer build-scope core content. Current core narrative points implementers to the Genomics Reporting IG for structured genetic results. The FHIR Extension Pack contains a retired/deprecated legacy observation-geneticsVariant extension and states that it has been replaced by profiles and extensions in the Genomics Reporting Guide. The current Genomics Reporting IG Variant profile has Observation.component:variation-code at 0..* with a CodeableConcept value, preserving the accepted multiple-identifier modeling surface outside core.

AutoFHIR reconciliation:
This empty audit commit makes no FHIR-core source change. Reintroducing or editing Observation-geneticsDNAVariantChange.Id in core would be outside current build scope and would contradict the work-group disposition that the requested cardinality was already handled in the Genomics Reporting IG.

Recommendation:
Keep this audit commit as-is. If future work finds a remaining problem with variant identifiers, make that correction in HL7/genomics-reporting or another owning external artifact, not by reviving the retired core Observation-genetics profile.
