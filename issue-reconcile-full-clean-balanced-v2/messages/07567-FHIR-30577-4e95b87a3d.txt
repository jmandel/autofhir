FHIR-30577: Audit POST search requirement

Issue request:
FHIR-30577 was a Published/Persuasive FHIR-core issue asking whether servers that support search must also support POST-based _search endpoints, including for IGs such as US Core, and asking that OpenAPI/Swagger tooling include _search endpoints when a CapabilityStatement indicates search support.

Initial application:
No historical source-changing commit explicitly mentioning FHIR-30577 was found. FHIR-I minutes for 2021-03-22 record the decision as "Search via POST is required," confirm that US Core did not relax the base requirement, and characterize the remaining problem as tooling. Later R5 search-method work applied the current source model through related issues rather than this exact key: FHIR-36126 introduced GET/POST plus 405 conformance language, FHIR-35859 added POST search examples and summary rows, FHIR-38994 added HTTP 405 guidance, FHIR-39137 moved HTTP transport guidance to source/http.html, and FHIR-31943/FHIR-31944 reconciliations on the combined branch audit or complete the same method-support family.

Additional context:
The linked #implementers Zulip thread shows the original confusion: an IG author initially read US Core as not requiring POST search, then the work group clarified that POST _search support is mandatory under the base spec. Later FHIR-31943 refined the practical meaning of support by allowing 405 Method Not Allowed for one method when the other can process the same search, without allowing both methods to fail that way. FHIR-40641 later confirmed US Core already states POST search is required, and HL7/fhir-ig-publisher#649 remains the external IG Publisher tooling issue for OpenAPI _search generation. Searches of this FHIR checkout found no current OpenAPI/Swagger generator source in build scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current-build REST (HTTP) page states that servers supporting Search via HTTP SHALL support both GET and POST modes, may return 405 for either method but not both, lists POST _search forms for system, type, and compartment search, and includes POST rows in the interaction summary table. The active Search page remains linked from RESTful API and carries the self/paging-link rules that related issues requested. The remaining OpenAPI generator work is tracked outside this core spec checkout.

Recommendation:
Keep this audit commit as-is. No FHIR core source edit is needed for FHIR-30577; follow-up belongs in the IG Publisher/OpenAPI tooling issue if the external generator still omits required _search endpoints.
