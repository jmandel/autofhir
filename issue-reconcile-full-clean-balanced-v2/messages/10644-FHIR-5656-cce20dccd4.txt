FHIR-5656: Audit Java equality method scope

Issue request:
FHIR-5656 was a Published/Persuasive DSTU1 FHIR-core change request asking the Java reference implementation to make Extension, Type, Element, Base, and related classes comparable, recommending equals() and hashCode() but with Jira discussion rejecting Object.equals()/hashCode() overrides and choosing explicit deep and shallow equality methods instead.

Initial application:
The issue appears to have been applied in historical FHIR Java implementation source by git commit e7b24dac064ae69bf393785eb025dd151b069061, which added equalsDeep(), equalsShallow(), and comparison helpers to Base and generated overrides for Element, Extension, and ElementDefinition. No commit message explicitly mentions FHIR-5656, but the commit date, title, touched classes, and Jira comment saying the explicit methods were added match the issue resolution.

Additional context:
The current HL7/fhir source tree contains no Java model classes or tools/java implementation source to edit. Current Java model source is maintained outside this checkout in hapifhir/org.hl7.fhir.core, where Base still provides equalsDeep() and equalsShallow() and generated model classes such as Element and Extension override the explicit methods. Later Zulip discussion in 2021-2023 revisited overriding Object.equals()/hashCode(), but community participants identified compatibility and semantic risks and did not establish a FHIR spec source change.

AutoFHIR reconciliation:
This commit intentionally makes no source change in HL7/fhir. The historical applied change is present in the Java implementation lineage, and any future Java model equality change belongs in the external Java core repository rather than the current FHIR specification source checkout.
