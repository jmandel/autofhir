FHIR-25934: Audit Provenance delegation clarification

Issue request:
FHIR-25934 was Published/Persuasive with Modification for FHIR-core Provenance. It asked whether Provenance.agent.onBehalfOf duplicated organizations already represented through Provenance.agent.who when who is a Device or PractitionerRole, and the final Security WG decision was to keep onBehalfOf for delegation, clarify who/onBehalfOf definitions, and remove obsolete whoIdentity/onBehalfOfIdentity comments.

Initial application:
No Jira-keyed FHIR-25934 commit was found, but commit aa9defa3c842c9dfc93f512695904c954ddb1c7b made the requested Provenance source changes: Provenance.agent.who gained the short text "The agent that participated in the event", Provenance.agent.onBehalfOf gained the delegation definition, and both obsolete identity comments were removed. The active Provenance StructureDefinition still contains those changes.

Additional context:
Later Provenance issues refined the same overlap concern without reversing FHIR-25934. FHIR-32518 removed Device from agent.onBehalfOf, and FHIR-28162 removed RelatedPerson from agent.onBehalfOf and added invariants preventing who/onBehalfOf from being the same resource or from duplicating PractitionerRole/Organization relationships. FHIR-49672 later added HealthcareService as a recognized agent and the matching organization/HealthcareService overlap invariant. source/fhir.ini actively lists provenance=Provenance, so these checks are in current build scope. A Security minutes page records FHIR-25934 as resolved change required, and no directly relevant Zulip or Confluence search result was found that conflicts with the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already conveys the approved FHIR-25934 semantics and the later approved guardrails for the overlapping-representation cases that motivated the issue; changing the who definition to duplicate the short text would not improve implementer understanding after the later Event-pattern wording update.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-25934 unless the Security WG later wants to revisit the broader onBehalfOf model; any such change would be a new substantive decision, not completion of this published R5 correction.
