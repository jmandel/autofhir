FHIR-6307: Audit ElementDefinition slice naming

Issue request:
FHIR-6307 was Published/Persuasive for DSTU1 and asked to document that sub-elements of named slices are expressed as a dot-separated list of ancestor elements beginning with the named slice name. The Jira resolution said to document as requested, and the later Jira comment says it had already been done as part of the profiling.html rewrite.

Initial application:
No current git commit explicitly mentions FHIR-6307. The relevant 2015 ElementDefinition/profiling rewrite history includes slicing documentation changes, but the old ElementDefinition.name model was later replaced. The current build-scope inputs actively publish ElementDefinition as a type, and the current ElementDefinition page documents a dedicated ElementDefinition.id algorithm instead of relying on dot notation in the slice name.

Additional context:
FHIR-9843 later created ElementDefinition.id as the reliable way to reference profile elements and required name to be a token with no dot or space. FHIR-10068 directly reopened the FHIR-6307 dot-notation request and was Resolved - No Change because FHIR-9843 made it unnecessary. FHIR-12181 then renamed ElementDefinition.name to ElementDefinition.sliceName, and FHIR-12182 documented the current id syntax as a dot-separated path whose tokens use pathpart:slicename/reslicename. Current profiling text also uses slash-separated sliceName values for re-slicing.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Reintroducing the FHIR-6307 requested dot notation into ElementDefinition.sliceName would contradict the later no-change decision and the current id/sliceName model; the current source already gives implementers an unambiguous profile-element identifier through ElementDefinition.id.

Recommendation:
Keep this audit commit as-is. No core source follow-up is recommended unless the work group decides to reopen the later ElementDefinition.id and sliceName design.
