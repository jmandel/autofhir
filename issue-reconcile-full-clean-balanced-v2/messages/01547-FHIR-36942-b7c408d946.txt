FHIR-36942: Audit ValueSet all-codes compose clarification

Issue request:
FHIR-36942 was a Published/Persuasive Vocab clarification for R5 asking what "all codes" means when ValueSet.compose.include names only a code system. The approved resolution says all concepts defined by the code system are included independent of code status, including retired concepts known to the terminology service, and valid code system compositions are members when the code system supports compositions.

Initial application:
The issue was applied by git commit 27b184d04790893f6ff56757454031e29bf64ff9, "FHIR-36942 FHIR-36837 FHIR-36218 FHIR-24865 Text Changes to codeSystem and valueSet", which changed source/valueset/valueset-notes.xml from "All codes in the system are included" to "All codes defined by the code system, independent of code status, are included." The same commit also applied companion CodeSystem.valueSet text for FHIR-36837.

Additional context:
ValueSet is an active resource in source/fhir.ini and the current valueset notes page is the authoritative source narrative for the Composition Rules section. The related FHIR-36837 Jira explicitly depends on the FHIR-36942 resolution for the CodeSystem.valueSet companion wording, and Vocab minutes from 2022-04-28 list both issues for review/vote. A later archived Vocab policy page repeats the same all-codes definition and naming guidance, and no directly relevant Zulip conflict was found.

AutoFHIR reconciliation:
No source change was made. The current source/valueset/valueset-notes.xml already carries the requested clarification in the ValueSet Composition Rules system-only/no-concept-or-filter rule, and the active build configuration confirms ValueSet is in the current build.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-36942 in core FHIR unless the work group later changes the all-codes policy or wants additional normative detail about compositions beyond the already-applied R5 clarification.
