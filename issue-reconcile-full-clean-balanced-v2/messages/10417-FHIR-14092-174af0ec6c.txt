FHIR-14092: Audit operation search type rendering

Issue request:
FHIR-14092 was Published with a Persuasive resolution for STU3. It asked to update the rendered Operations table so string parameters used as search parameters show their search parameter type, making operation invocation semantics clearer.

Initial application:
The issue was applied in svn/git commit 6969322396b72b26a3e7623910d7d69b771a4c3b, "GF#14092 - improve rendering of operations". That old Java NarrativeGenerator change rendered OperationDefinition.parameter.searchType alongside the parameter type as a search-type link. The old Java publisher code was later removed from this source checkout when the IG Publisher moved to Maven, so there is no current in-repository renderer hunk to reapply.

Additional context:
Current source/fhir.ini lists OperationDefinition as an active resource, and the current OperationDefinition source defines parameter.searchType with constraints limiting it to input string parameters. Later FHIR-37847 and FHIR-41220 decisions clarified the same OperationDefinition searchType concept and operations-page prose; those later changes are already represented on the combined branch and do not supersede the FHIR-14092 rendering outcome. Current CI-rendered operation pages display string parameters with their search type in the Type cell, e.g. [string] followed by ([reference]), which preserves the implementer-facing meaning of the original request even though it is not a separate table column.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build-scope source supplies searchType values for applicable string OperationDefinition parameters, and the current rendered specification already exposes those search types in operation parameter tables.

Recommendation:
Keep this no-change audit commit. Do not add duplicate local prose or attempt to restore the removed Java renderer in this repository; if a future work group wants a separate dedicated table column rather than the current Type-cell presentation, that should be a new tooling/rendering change against the active publisher.
