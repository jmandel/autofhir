FHIR-25380: Audit Questionnaire disabled display

Issue request:
FHIR-25380 was a Published/Persuasive with Modification FHIR-core Questionnaire change request for the "no to all" UI pattern. The final resolution asked for a new Questionnaire.item.disabledDisplay code element, sibling to enableWhen, with hidden and protected values to distinguish disabled items that are hidden from those still displayed but non-editable/selectable.

Initial application:
The issue was applied by git commit 9ff1aca21e ("FHIR-25380 - Add Questionnaire.disabledDisplay"), which added Questionnaire.item.disabledDisplay to source/questionnaire/structuredefinition-Questionnaire.xml and created the questionnaire-disabled-display CodeSystem and ValueSet. Later metadata and cleanup commits updated the terminology metadata but did not remove or reverse the element.

Additional context:
FHIR-25960 and FHIR-23788 cover the expression-driven mechanics for changing Questionnaire properties and answer-option availability, while FHIR-25380 addresses the remaining display behavior for disabled items. The Questionnaire resource is active in source/fhir.ini, and the authoritative current source still contains the disabledDisplay element with a required binding to the hidden/protected value set. Zulip records the original no-to-all use case and Confluence SDC minutes record the work-group progression and Persuasive with Modification vote.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope Questionnaire source already implements the resolved request: Questionnaire.item.disabledDisplay exists next to enableWhen, is 0..1 code, binds required to ValueSet/questionnaire-disabled-display, and the CodeSystem/ValueSet define hidden and protected.

Recommendation:
Keep this no-change audit commit as-is. No core follow-up is needed for FHIR-25380 unless a later work-group decision changes disabled-item rendering semantics.
