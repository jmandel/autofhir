FHIR-8054: Audit patient-subject naming convention

Issue request:
FHIR-8054 was a Published FHIR-core change request from the DSTU1 ballot asking why patient references were named `patient` in some resources and `subject` in others, and asking for consistency where possible. The accepted resolution was that elements should be named `patient` when they can only reference Patient, and `subject` when they can be more than Patient, with a build-tool rule to enforce this convention.

Initial application:
The issue was applied in svn revision 5822, represented in this Git history by commit 6f6f154d40ee7e6c03501ce974812eb7751cf8b5, which added ResourceValidator checks warning when `subject` was only `Reference(Patient)` and requiring `patient` to be only `Reference(Patient)`. That historical validator file was later deleted when the old Java build tooling was refactored out of this checkout, so there is no current source file containing the original rule text.

Additional context:
Later Jira decisions confirm the same naming policy rather than reversing it. FHIR-19421 rejected a request to rename AllergyIntolerance.patient and FamilyMemberHistory.patient because `patient` is used for `Reference(Patient)` only while `subject` is used for broader choices. FHIR-12630 is an example of applying the policy to Encounter by renaming Encounter.patient to Encounter.subject while broadening the target type to Patient or Group. Exact FHIR-8054 community searches found no relevant Zulip or Confluence discussion that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. A scan of the active resources listed under source/fhir.ini found 127 active resource definitions and zero current violations of the FHIR-8054 convention: all active `patient` elements are `Reference(Patient)` only, and no active `subject` element is only `Reference(Patient)`. Representative current source shows AllergyIntolerance.patient as Patient-only, while Encounter.subject and DetectedIssue.subject allow Patient plus other target resources.

Recommendation:
Keep this no-change audit commit as-is. No current FHIR-core source edit is needed for FHIR-8054; future patient/subject naming changes should continue to follow the same convention when resource target types are narrowed or broadened.
