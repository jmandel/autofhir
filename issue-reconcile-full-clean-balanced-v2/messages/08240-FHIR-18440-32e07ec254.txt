FHIR-18440: Align Bundle signature guidance

Issue request:
FHIR-18440 was a Published/Persuasive STU3 FHIR-core issue for the XML page. It asked to link the existing digital-signature text to the Provenance signature section, add a similar Bundle signature section explaining how Signature is used for Bundles, and fix the parallel JSON page links. The resolution accepted the request but noted that any added guidance should not impose new normative expectations.

Initial application:
Commit f0c0aa773ecfc6c50ee902e069c48c9ad47354b3 added a Bundle Signatures section and changed the XML page's Provenance link to provenance.html#signature, but it did not update JSON in that commit. Later signature-page work, especially dcf53a8af6d730f886918f45af2510e990a986eb, replaced the detailed XML/JSON canonicalization text with links to source/signatures.html#xml and source/signatures.html#json, so the current XML and JSON page links already point to active signature guidance.

Additional context:
Later signature work changed the correct interpretation of the Bundle section added for FHIR-18440. The current signatures page has a Signing Bundles section at signatures.html#Bundles that uses Provenance resources carrying Signature elements, and current Bundle.signature metadata marks Bundle.signature deprecated in favor of Provenance-based signatures. FHIR-52810 further refined the Signing Bundles rules to use the pointer-based fragment identifier '#/' for embedded Bundle signatures. FHIR-53914 is a broader unresolved rewrite proposal for the same Signing Bundles section, so it is background rather than a source-edit decision here.

AutoFHIR reconciliation:
This commit updates source/bundle/bundle-notes.xml, which is in build scope because Bundle is an active source/fhir.ini resource, so the Bundle local Signatures note no longer recommends the stale Bundle.signature workflow. It now points readers to Provenance resources carrying Signature elements and to the current Signing Bundles section. It also fixes the Bundle.signature definition link from signatures.html#Bundle to the actual signatures.html#Bundles anchor so the deprecation guidance resolves to the current section.

Recommendation:
Keep this source fix as-is. It preserves the original FHIR-18440 intent to have Bundle-specific signature guidance while aligning that guidance with later applied signature decisions. Future work on unresolved broader signatures rewrites such as FHIR-53914 may rephrase the central Signing Bundles section, but it should retain the Provenance-based Bundle signing direction and the working #Bundles link.
