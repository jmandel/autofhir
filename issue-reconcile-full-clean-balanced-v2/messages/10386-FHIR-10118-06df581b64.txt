FHIR-10118: Audit Observation relationship refactor

Issue request:
FHIR-10118 was a Published/Persuasive with Modification OO change request for DSTU2 Observation asking the work group to review Observation.related.type codes. The adopted breaking-change resolution replaced the generic Observation.related relationship-type model with direct relationship elements, especially Observation.derivedFrom and the applied Observation.hasMember element, and treated sequel-to and replaces as standard extensions rather than core relationship-type codes.

Initial application:
The relationship refactor was applied in 2017 by commit 5bdc6559670c09dbdcbfcdf5f716f84455c6e600, which changed the Observation spreadsheet from Observation.related/related.type/related.target to Observation.hasMember and Observation.derivedFrom, updated examples, and added committee notes for #10118. Commit 558e37577b4010855ad643cc7a9010fc9e665e17 then made a small GF#10118 clarification in the Observation introduction. Current generated StructureDefinition source still carries [#10118] committee notes on Observation.hasMember and Observation.derivedFrom.

Additional context:
Later source evolution explains the target lists not matching the old DSTU2 resolution text exactly. Media was merged into DocumentReference by GF#19250, Sequence is a removed resource in current source/fhir.ini, and later GenomicStudy/MolecularDefinition targets were also removed from Observation when additional resources were removed. FHIR-14034, already represented on the combined branch, audited the same relationship family for ImagingStudy. FHIR-13240, also already represented, fixed a remaining active stats-operation reference to the old .related/type wording. The old valueset-observation-relationshiptypes.xml file remains in the source tree but is not referenced by active source or source/fhir.ini [valuesets], and the only current Observation hit for a removed related.type code is a commented spirometry example note. The FHIR Extension Pack now contains observation-sequelTo and observation-replaces extension definitions.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current Observation source defines Observation.hasMember and Observation.derivedFrom, current Observation search parameters target those elements, and active narrative guidance discusses grouping through DiagnosticReport.result, Observation.component, Observation.hasMember, and Observation.derivedFrom rather than a generic relationship-code element. Reintroducing the old value set or old target resources would be incorrect for the current build, and deleting the unreferenced historical value set would be cleanup rather than a necessary current-spec correction.

Recommendation:
Keep this no-change audit commit as-is. Future cleanup of the orphan relationship-types value set or example file names can be handled separately if the build tooling owners want to prune unused source files; no FHIR core semantic change is needed for FHIR-10118 now.
