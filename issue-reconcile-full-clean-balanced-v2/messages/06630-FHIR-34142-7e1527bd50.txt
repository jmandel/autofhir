FHIR-34142: Audit ordered slice invariant

Issue request:
FHIR-34142 is a Published FHIR-core/FHIR-I change request with resolution Persuasive with Modification. It requested a warning invariant on ElementDefinition so that, when orderMeaning is absent, slicing.rules=openAtEnd or slicing.ordered=true is warned against because order-dependent slicing is improper where element order has no meaning.

Initial application:
The issue appears to have been applied directly by git commit bfba74805d, which added invariant 25 to source/datatypes/elementdefinition.xml with warning severity, the requested human message, and the requested FHIRPath/XPath logic. The R5 history artifacts also carry the generated eld-25 warning.

Additional context:
source/fhir.ini actively includes ElementDefinition in the [types] list, marks it normative, and maps it to the eld prefix, so the spreadsheet row is in the current build scope for the ElementDefinition datatype. Broader Jira searching found FHIR-13461 as an older, broader openAtEnd/orderMeaning warning request, but that issue was retracted and Resolved - No Change before FHIR-34142 was resolved. Zulip and Confluence searches found no directly relevant community evidence that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already implements the requested warning invariant for missing orderMeaning with openAtEnd or ordered slicing, including the requested message, FHIRPath, and XPath.

Recommendation:
Keep this no-change audit commit as-is. No follow-up is needed for FHIR-34142 unless a future work-group decision changes the warning severity or the orderMeaning/slicing rule.
