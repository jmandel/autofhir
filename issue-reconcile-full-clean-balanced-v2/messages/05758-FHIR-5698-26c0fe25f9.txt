FHIR-5698: Audit removal of Appointment.order

Issue request:
FHIR-5698 was a Published/Persuasive with Modification DSTU1 PA change request saying Appointment.order could not work because Order had to point at a concrete order/request resource; the approved resolution was to remove the Order property and handle any workable appointment order linkage after DSTU2.

Initial application:
The issue appears to have been applied by git commit 13deffe106be55c50ae7473b96e95e0932129695, "Tracker# 5698 pre-apply change to remove the order property from the appointment", which changed the then-authoritative Appointment spreadsheet sources from Appointment.order to !Appointment.order. No current Jira-keyed commit was found beyond that historical tracker commit.

Additional context:
Appointment is an active current resource in source/fhir.ini, while Order is listed only under removed resources. Later Appointment request-linkage work did not restore Appointment.order: FHIR-13195 renamed incomingReferral to Appointment.basedOn for concrete request resources, and FHIR-40634 later adjusted Appointment.basedOn target profiles. The current source/appointment/structuredefinition-Appointment.xml contains Appointment.basedOn with concrete request target profiles and no Appointment.order element.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build source already satisfies FHIR-5698 by omitting Appointment.order; the relevant successor concept is represented through Appointment.basedOn rather than a Reference(Order).

Recommendation:
Keep this audit commit as-is. Do not reintroduce Appointment.order; future changes to the request types available from Appointment.basedOn should be handled under their own Jira decisions rather than under FHIR-5698.
