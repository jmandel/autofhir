FHIR-31783: Audit route redundancy clarification

Issue request:
FHIR-31783 was Published/Persuasive for R5 and asked for clearer documentation if MedicinalProductDefinition.administrableProduct.route and AdministrableProductDefinition.routeOfAdministration.code were both needed. The resolution was to improve documentation around the redundant route concept and related changes.

Initial application:
The old MedicinalProductDefinition.administrableProduct backbone had already been removed by FHIR-31859, replacing its route with MedicinalProductDefinition.route. FHIR-31783 was then applied by commits ca3b2129dc and 71a4873af9, which added wording that MedicinalProductDefinition.route is the same concept as AdministrableProductDefinition.routeOfAdministration.code and cannot be used together. Commit ca3b2129dc also added the APD invariant, and later commit dd0e8e7755 corrected the invariant logic for FHIR-39755 without changing the intended rule.

Additional context:
source/fhir.ini lists MedicinalProductDefinition and AdministrableProductDefinition as active BR&R resources in the current build. Current source has the route clarification in both structure definitions and the corrected apd-1 constraint requires referenced formOf MedicinalProductDefinition resources not to carry route when an AdministrableProductDefinition is used. Jira search found FHIR-39755 as the later correction to the same invariant, and community searches found no Zulip or Confluence evidence that supersedes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already documents the redundancy and enforces the non-hybrid use pattern requested by FHIR-31783, with the later FHIR-39755 correction incorporated.

Recommendation:
Keep this audit commit as-is. No core FHIR source follow-up is needed for FHIR-31783 unless BR&R later reconsiders the product-definition route modelling pattern.
