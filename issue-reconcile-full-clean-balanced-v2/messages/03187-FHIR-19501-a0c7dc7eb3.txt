FHIR-19501: Audit $apply parameter expression access

Issue request:
FHIR-19501 was a Published/Persuasive FHIR-core change request for the CDS work group asking how CQL can access PlanDefinition and ActivityDefinition $apply parameters, and what CQL context is used when the subject is not a Patient. The accepted resolution was to document in the $apply operation that parameters are available to CQL and FHIRPath expressions evaluated during $apply as percent-prefixed environment/context variables.

Initial application:
The issue was applied by 760504d5b6cf37cf71430074257a1d92922ed371, which added current-source wording to the ActivityDefinition and PlanDefinition narrative notes and the then-spreadsheet-backed operation definitions. Current blame still attributes the explicit dynamicValue CQL/FHIRPath percent-variable paragraphs in source/activitydefinition/activitydefinition-notes.xml and source/plandefinition/plandefinition-notes.xml to that Jira-tagged commit. The operation definitions have since been refactored and edited, but their current comments still state that $apply parameters are available within dynamicValue expressions as percent-prefixed context variables.

Additional context:
FHIR-18196, resolved in the same 2018 CDS ballot cycle, changed the $apply patient parameter to subject and documented subject resolution by type, addressing the non-Patient subject portion of FHIR-19501's concern. FHIR-39528 later added active Clinical Reasoning guidance that subject elements establish the CQL evaluation context, and FHIR-29211 later confirmed the same parameter-context-variable pattern as a general SHOULD for operations that evaluate expressions. FHIR-29211 is already represented on the combined branch, so it is cited only as related evidence here. The current build scope includes ActivityDefinition and PlanDefinition as active resources in source/fhir.ini, and the Clinical Reasoning Using Expressions page is active in source/hierarchy.xml.

AutoFHIR reconciliation:
No source change was made. The current source already satisfies FHIR-19501: ActivityDefinition and PlanDefinition notes explicitly describe $apply parameters in dynamicValue CQL and FHIRPath expressions as percent-prefixed context variables; both $apply OperationDefinitions carry the same rule in operation comments; current operation parameters use subject rather than patient and allow non-Patient subject types; and the active Clinical Reasoning page now describes the subject/evaluation-context relationship and general operation-parameter context-variable pattern.

Recommendation:
Keep this empty audit commit as-is. No follow-up source edit is needed for FHIR-19501 unless CDS later wants to make the operation comments repeat the full CQL/FHIRPath examples from the resource notes, which would be editorially redundant rather than necessary for current implementer understanding.
