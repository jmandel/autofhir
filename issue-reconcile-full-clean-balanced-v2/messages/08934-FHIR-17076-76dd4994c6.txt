FHIR-17076: Audit history-entry wording

Issue request:
FHIR-17076 was a Published/Persuasive STU3 FHIR-core HTTP issue asking to replace wording that said each history Bundle entry SHALL minimally contain either a resource or a request with entry.request.method. The concern was that "either/or" implied an exclusive-or even though entries may contain both a resource and request details.

Initial application:
The issue was applied by SVN revision 14177, represented in git as 5f6a350dc6, which changed source/http.html from "either a resource" to "at least one of: a resource" in the history interaction paragraph. No additional source locations for the old phrase remain in current source.

Additional context:
A later reconciliation for the same HTTP history paragraph is already represented on the combined branch by FHIR-7933 commit 2923d2b222. That commit replaced the old at-least-one sentence with current wording requiring request and response elements, while requiring a resource for PUT or POST history entries and omitting a resource for DELETE entries. A 2018 implementers Zulip thread on the same old sentence confirms that DELETE history entries do not include entry.resource and does not conflict with the current rule.

AutoFHIR reconciliation:
This is an empty no-change audit commit. The active source/http.html history paragraph no longer uses the misleading "either/or" wording, and reintroducing the narrower 2018 "at least one of" wording would be less accurate than the current request/response rule.

Recommendation:
Keep this audit commit as-is. The seed issue is already satisfied by the original application plus the later FHIR-7933 paragraph alignment; no current FHIR core source change is needed.
