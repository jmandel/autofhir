FHIR-18425: Audit choice element list move

Issue request:
FHIR-18425 was Published/Persuasive for the STU3-raised FHIR-core formats page request to stop showing the large generated list of choice-type elements inline on the normative formats page. The approved resolution was to move the generated content to a separate informative page and link to it from the formats page.

Initial application:
The issue appears to have been applied in historical commit db9355a66d9e549d3043a73c6aef8c9f6e40b46b, whose message includes GF#18425. That commit removed the inline [%choice-elements%] list from source/formats.html, added a link to choice-elements.json, added the choice-elements.json entry to source/downloads.html, changed the publisher to generate JSON instead of an inline HTML list, and excluded choice-elements.json from ordinary package resource ingestion.

Additional context:
Current source still has formats.html in the built Resource Definitions hierarchy and downloads.html in the built Implementation Support hierarchy. The formats page links to choice-elements.json instead of embedding the list, the downloads page lists choice-elements.json with other code-generation support artifacts, and the documentation index marks Downloads as informative. Current build.fhir.org serves choice-elements.json. Later Zulip discussion confirms the generated choice list exists for R4/current publication surfaces, while STU3 was not retroactively generated; no Jira, Zulip, or Confluence search found a later decision that changes the current-build conclusion for FHIR-18425.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build already implements the requested move by keeping the large choice-type list out of the formats page and publishing it as generated choice-elements.json linked from formats/downloads.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for the current build; only a historical-release backport would be needed if humans wanted STU3-era publication artifacts to receive the generated JSON, which is outside this reconciliation scope.
