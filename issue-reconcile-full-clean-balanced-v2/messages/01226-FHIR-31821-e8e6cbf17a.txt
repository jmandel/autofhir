FHIR-31821: Add Range choices to Ingredient strength

Issue request:
FHIR-31821 was Published/Persuasive for BRR MedicinalProductIngredient after being raised against R4 and applied for R5. The issue objected to modeling high/low strength limits only with ratio-style fields and the accepted resolution was to add a choice of Range and RatioRange so Ratio is used only when a non-unit denominator is needed.

Initial application:
The issue was partially applied by upstream commits aa11acd4e322ff53f1d98f256f0f975871947ee2 and a9e29cf42c14a7214228b49ed2aa225d436ede9e, which renamed the affected strength elements to choice types, removed the presentationHighLimit/concentrationHighLimit/referenceStrength.strengthHighLimit elements, and added RatioRange to Ingredient.substance.strength presentation, concentration, and referenceStrength.strength. Those commits did not add Range, leaving ordinary unitary quantity ranges unable to use the requested Range datatype.

Additional context:
The current build maps the old MedicinalProductIngredient artifact to the active Ingredient resource in source/fhir.ini. FHIR-19416 introduced RatioRange for ranges of ratios and specifically cited medicinal product ingredient strength as a use case. Later RatioRange choice-type discussion and FHIR-34453 confirm RatioRange was intentionally allowed where explicitly listed, but do not supersede FHIR-31821's parallel Range choice requirement. A BRR Confluence minutes page references FHIR-31821 as moved to block vote, consistent with the Jira final vote.

AutoFHIR reconciliation:
This commit adds Range as an allowed type to Ingredient.substance.strength.presentation[x], Ingredient.substance.strength.concentration[x], and Ingredient.substance.strength.referenceStrength.strength[x] in the active StructureDefinition source. It also keeps the checked Ingredient UML SVG aligned with the same choice-type list; the authoritative semantic fix is the StructureDefinition change.

Recommendation:
Keep this source fix. It completes the accepted FHIR-31821 model change without reintroducing the removed high-limit elements or changing unrelated Ingredient strength guidance; no separate related issue needs to be decided here.
