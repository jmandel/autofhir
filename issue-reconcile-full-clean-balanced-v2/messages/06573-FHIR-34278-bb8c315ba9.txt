FHIR-34278: Audit PATCH requirement clarification

Issue request:
FHIR-34278 was Published with a Persuasive with Modification resolution for the FHIR-core HTTP page. It asked whether the existing PATCH wording made PATCH mandatory for all servers and requested clarification plus correction of the "not"/"note" typo in the Binary PATCH note. The accepted resolution changed the normative statement to require servers that support PATCH to support the concurrency/resource-contention mechanism, rather than requiring all servers to support conditional PATCH.

Initial application:
The wording change was applied to source/http.html by git commit 4bbadac472f4adf87cc53aedf5b5736652b39fa3, which replaced "servers SHALL support conditional PATCH" with "servers that support PATCH SHALL support" the version-aware/concurrency section. The typo portion was already corrected in current history by git commit 021fdd52eec1b71a39014469ed6df9dbb3804995, changing "not about PATCH on Binary" to "note about PATCH on Binary".

Additional context:
FHIR-I minutes for 2022-03-14 record that the proposal made sense and was accepted as Persuasive with Modification by a 12-0-1 vote. Later HTTP-page editorial changes, including FHIR-39135 and FHIR-40957, refactored nearby wording from operations to interactions and renamed the linked concurrency section to Resource Contention while preserving the FHIR-34278 substance. The active source/http.html page is a current RESTful API source page linked from source/documentation.html.

AutoFHIR reconciliation:
This audit commit makes no source change because source/http.html already says that servers that support PATCH SHALL support Resource Contention on the PATCH interaction, retains only a SHOULD for conditional patch where PATCH and Conditional Update are both supported, and uses the corrected "note about PATCH on Binary" wording.

Recommendation:
Keep this no-change audit as-is. No FHIR-core source follow-up is needed for FHIR-34278 unless the work group wants to revisit the separate policy question of whether conditional PATCH should be stronger than SHOULD.
