FHIR-5600: Audit observation methods LOINC filter

Issue request:
FHIR-5600 was a Published/Persuasive DSTU1 technical correction for Observation asking whether ValueSet/observation-methods used the wrong LOINC filter, noting that the old filter used property "Type" and value "Method" even though the comment suggested LOINC method part codes starting with LP.

Initial application:
The issue appears to have been initially applied in git commit 0360bc4248328919580b1ae4031956301106de1d, which changed the old LOINC include comment from LP to ^LP and changed the filter value from Method to METHOD_TYP. That commit did not remove the LOINC include or change the property name.

Additional context:
The same value set was later revisited by FHIR-8399, a Published/Persuasive with Modification Observation issue, because the remaining LOINC filter "Type = METHOD_TYP" still did not conform to LOINC guidance. Commit f16ff276ebde2a99c3ef4bd03b9e020f89144335 removed the LOINC include from source/observation/valueset-observation-methods.xml. The current Observation resource is active in source/fhir.ini, and Observation.method still binds to ValueSet/observation-methods, but the current value set no longer contains any LOINC include or old Type/Method filter.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The current build-scope source already avoids the incorrect LOINC filtering that FHIR-5600 identified; the old applied hunk has been superseded by removing the LOINC include entirely.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-5600 unless the OO work group later decides to reintroduce LOINC method part codes with a newly specified filter mechanism.
