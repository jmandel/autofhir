FHIR-18401: Audit extension registry modifier marker

Issue request:
FHIR-18401 was a Published/Persuasive STU3 FHIR-I change request asking for a flyover on the Extension Registry letter "M", because the registry did not define that it meant a modifier extension.

Initial application:
The issue was applied by git commit db9355a66d9e549d3043a73c6aef8c9f6e40b46b, which changed the then-current core extension registry generator so modifier extensions rendered as <b title="This is a modifier extension">M</b>. The Jira comment from 2018-11-08 also says the request was already done.

Additional context:
The core source file source/extensibility-registry.html was deleted in 2023 when registry content moved to the FHIR Extension Pack, and publish.ini now keeps extensibility-registry.html commented out of the core build. Current core pages and navigation link to [%extensions-location%]extension-registry.html. In the Extension Pack, input/extensions-ig.xml declares extension-registry.html as a markdown-generated page, and input/pagecontent/extension-registry.md now includes a legend explaining that the Card. column includes the letter M when the extension is a modifier extension.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR core source change. The original core generator flyover was applied historically, the old core registry page is no longer in current core build scope, and the authoritative current registry source in the Extension Pack already explains the M marker.

Recommendation:
Keep this external-repo audit commit as-is for core. No FHIR core follow-up is needed; any future wording change to the registry legend should be made in the FHIR Extension Pack rather than by restoring or editing the retired core registry page.
