FHIR-26897: Audit Device statusReason definition cleanup

Issue request:
FHIR-26897 was Published/Persuasive with Modification for R5. It reported that the Device statusReason value set expansion showed an "online" entry whose definition said "The device is off."; the approved resolution was to change that definition to "The device is connected to a network or system." Later Jira comments recorded Devices on FHIR consensus that the original definitions were not helpful and, by 2021, that the value set codes were actually discarded/obsolete/removed while "online" had been only a stale label.

Initial application:
No explicit FHIR-26897-tagged source commit was found. Commit 798a3197ab728359e8d056551c908ae12ec9a04e, authored by the issue assignee shortly after the vote, changed source/device/device-spreadsheet.xml by removing the old online/paused/standby/offline/not-ready-style statusReason rows and replacing them with discarded, obsolete, and removed definitions. That removed the exact erroneous "online" plus "The device is off." pairing from the authoritative Device spreadsheet source.

Additional context:
Later commit 50f4a45ebb2bb55a1ebcdc1a491aebc2b0c1f8b1 removed source/device/codesystem-device-status-reason.xml and source/device/valueset-device-status-reason.xml and introduced the newer Device operation status-reason terminology. The current combined branch no longer has the old device-status-reason files, and XML parsing of current source/device/structuredefinition-Device.xml finds no active Device.statusReason or Device.operation.statusReason element. The only current source hit for "The device is off." is in source/devicecomponent, but DeviceComponent is marked dropped/commented out in source/fhir.ini and that artifact uses code "off", not the FHIR-26897 "online" entry.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current build no longer contains the erroneous Device statusReason "online" code/definition. Editing the out-of-build DeviceComponent operational-status file would not address this Device issue and would risk changing a retired artifact.

Recommendation:
Keep this no-change audit. Do not recreate the old "online" status reason or edit DeviceComponent for this issue; any future Device operation/association status reason modeling should be handled under its own Jira decision.
