FHIR-26314: Audit X-Provenance AuditEvent guidance

Issue request:
FHIR-26314 was a Published security work group change request, resolved Persuasive with Modification for R5, asking how to record an AuditEvent for a PUT/POST request that includes the X-Provenance header. The accepted resolution was to add a Provenance HTTP Header bullet saying that one AuditEvent may be used to record creation of both the resource and the provenance.

Initial application:
The X-Provenance HTTP Header section was originally introduced by FHIR-19298 in commit eeeb015442e1adcf1c4e17ee2d7996e70d7f762c. FHIR-26314 was then applied in commit 13f144d4c4aa36c0dc9136733bfbf525ab417ab5, which added the requested AuditEvent bullet to source/provenance/provenance-notes.xml. A later FMG QA cleanup in commit 87b00c9c0de977f8559e0f99694e8664e03a06cd capitalized the modal verb to MAY without changing the substance.

Additional context:
The Provenance resource is active in source/fhir.ini, so source/provenance/provenance-notes.xml feeds the current build. The linked Zulip thread records the rationale: a server-generated AuditEvent can be one log for both the resource create/update and the X-Provenance-created Provenance, with both represented as entities. Related later issue FHIR-31345 was Resolved - No Change for transaction Bundle questions and does not require changing this audit guidance; FHIR-34343 addressed version-specific transaction references separately.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already contains the accepted FHIR-26314 guidance: "When recording an AuditEvent, one AuditEvent MAY be used to record the create of the resource and provenance." Adding further prose would duplicate or broaden the accepted clarification rather than correcting a current spec problem.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-26314 unless the work group later decides to reopen broader X-Provenance transaction Bundle semantics, which is outside this issue's accepted audit clarification.
