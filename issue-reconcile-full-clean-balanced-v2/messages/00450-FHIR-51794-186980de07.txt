FHIR-51794: Audit BodyStructure image association

Issue request:
FHIR-51794 is an Applied FHIR-core BodyStructure change request resolved as Persuasive with Modification for R6. It asked how to associate images with individual included structures, and the final resolution was to add BodyStructure.includedStructure.image just below spatialReference as a 0..* Attachment, mark it non-summary, define it as identifying aspects of an included or excluded structure, and clarify BodyStructure.image as images of the overall structure.

Initial application:
The source implementation appears in git commit 569be2dfd9b027b533a69658f64e5fdde1a03026, later merged through PR 3771, where source/bodystructure/structuredefinition-BodyStructure.xml gained BodyStructure.includedStructure.image and the root BodyStructure.image definition was updated. Commit 844dce97bcd2e886da60c2a77d50e3e22fb21c1f then changed only the nested image short display from "Image of the structure" to the semantically equivalent "Image(s) of structural aspects".

Additional context:
BodyStructure is an active current-build resource in source/fhir.ini. OO Confluence minutes for 2025-10-17 record the FHIR-51794 vote and the same model: repeat BodyStructure.image in includedStructure under spatialReference, 0..*, Attachment, summary false, and define the root image as applying to the overall structure. A later Zulip review noted that BodyStructure now has both root and includedStructure image properties; the OO response recalled that FHIR-51794 deliberately kept both, and no final later decision was found that reverses the root image or nested image model.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative StructureDefinition already contains BodyStructure.includedStructure.image in the requested location with 0..*, Attachment, isSummary false, and the requested included/excluded-structure definition; BodyStructure.image already has the overall-structure definition. The current short display differs from the exact Jira prose only because of a later short-display cleanup and does not change implementer understanding.

Recommendation:
Keep this no-change audit commit as-is. Do not revert the nested image short display to the original resolution wording unless OO makes a new final decision, and treat any future clarification about clinical-image navigation versus illustrative images as separate work because it was not part of the applied source change.
