The Jira description explicitly treated this as a core FHIR publishing tools issue, and the only Jira comment said it looked already fixed.

Initial application:
No commit mentioning FHIR-8352 is present in the current FHIR git history or the combined reconciliation branch. Historical DSTU2-era publisher source available from the old fhir-crucible/fhir_dstu2 checkout contains explicit ValueSet copyright rendering in PageProcessor.txsummary and NarrativeGenerator.generateCopyright, which matches the Jira comment that the publishing-tools defect had already been fixed outside any current spec source edit.

Additional context:
ValueSet remains an active current-build resource in source/fhir.ini, and the current ValueSet StructureDefinition plus ValueSet examples carry the copyright elements themselves. The current spec checkout, however, no longer contains the Java publisher/rendering implementation; only templates such as tools/templates/template-vs.html remain here. Current external org.hl7.fhir.core renderer code still has ValueSet copyright rendering calls, while a current CI page with ValueSet.copyright can still omit the statement, so any remaining behavior is a publisher/rendering integration question rather than a safe FHIR source correction in this checkout.

AutoFHIR reconciliation:

Adding per-ValueSet narrative text or speculative template placeholders in the FHIR source repository would not address the generic renderer behavior requested by the issue and could introduce stale duplicated legal text. The needed locus, if there is a current regression, is the external publisher/rendering pipeline.

Recommendation:
