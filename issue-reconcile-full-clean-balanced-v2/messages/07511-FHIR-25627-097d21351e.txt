FHIR-25627: Audit eld-19 length enforcement

Issue request:
FHIR-25627 was a Published FHIR-core technical correction resolved Persuasive for R5. It reported that the eld-20 warning description mentioned a maximum of 64 characters while the eld-20 expression did not check that limit. The final resolution said the 64-character text belongs in eld-19, the hard rule, rather than in eld-20.

Initial application:
No source commit explicitly tagged FHIR-25627 was found. The underlying length-limit enforcement was already part of the ElementDefinition path rule family: historical FHIR-19745 changed eld-19 to enforce the 64-character component limit, FHIR-I WGM 202105 minutes for FHIR-25627 recorded that the validator enforced the rule correctly and that eld-19 had the 64-character regex, and later FHIR-38795/FHIR-38796 commits cleaned up the eld-19/eld-20 descriptions.

Additional context:
FHIR-19745 is the earlier supporting decision for enforcing the 64-character limit in eld-19. Later Published issues FHIR-38795 and FHIR-38796 came from the same eld-20 wording discussion: FHIR-38795 clarified the eld-19 and eld-20 descriptions, and FHIR-38796 appended the logical-model caveat while intentionally leaving the eld-20 warning expression in place. Both later issues already have no-change audit commits on the combined branch, so this seed should not reopen their decisions.

AutoFHIR reconciliation:
No source change was made. The current active source/datatypes/elementdefinition.xml has eld-19 as an error rule whose description and FHIRPath expression enforce each path component's 64-character limit, and eld-20 no longer carries the stale description that triggered FHIR-25627. source/fhir.ini keeps ElementDefinition in the current build, so this is the authoritative source surface for the issue.

Recommendation:
Keep this empty audit commit as-is. If the work group wants to remove the redundant 64-character bound from the eld-20 warning expression or otherwise revisit the warning semantics, handle that as a new decision because later published issues deliberately preserved the warning expression while fixing its description.
