FHIR-19456: Audit ImagingStudy UID reversion

Issue request:
FHIR-19456 was Published/Persuasive with Modification for STU3. It asked the Imaging Integration work group to revert ImagingStudy.series.identifier and ImagingStudy.series.instance.identifier back to uid elements, update descriptions and examples, and encode the series and SOP Instance UID values directly without a urn: prefix.

Initial application:
The Jira comment says the change was applied on the moehrke_ii_uid branch. Git commit 131af0770aa6467c6907c7f556dfd51b8519f05d, merged by 5ccbf09b4fa6ff524e4ca689b53d72645d7b7aaf, changed the then-authoritative ImagingStudy source and examples from identifier/urn:oid encodings to uid elements with direct UID values and added explanatory DICOM UID guidance.

Additional context:
Current ImagingStudy source is active in source/fhir.ini. After later source refactors, source/imagingstudy/structuredefinition-ImagingStudy.xml now defines ImagingStudy.series.uid and ImagingStudy.series.instance.uid as id-typed required elements with DICOM Series Instance UID and SOP Instance UID descriptions. The active examples, implementation notes, search parameters, and diagram links use the uid paths and direct unprefixed UID values. FHIR-19455, applied on the same branch, explicitly says Series Instance UID and SOP Instance UID use the id datatype and are encoded directly; FHIR-54766 later clarified why the Study Instance UID remains an Identifier but did not reverse the series/instance uid representation. Remaining ImagingStudy.series.identifier mentions are confined to R3 rename metadata and suppressed historical workflow warnings, not current element definitions or implementer-facing guidance.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because the current build-scoped source already satisfies the final FHIR-19456 intent when read with the same application family and later same-area clarifications.

Recommendation:
Keep this audit commit as-is. Future work should only revisit the DICOM UID modeling if a later work-group decision changes the distinction between the Study Instance UID Identifier and the direct series/instance uid elements.
