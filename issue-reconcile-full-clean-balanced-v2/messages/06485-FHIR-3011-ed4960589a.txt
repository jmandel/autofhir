FHIR-3011: Audit CarePlan activity progress guidance

Issue request:
FHIR-3011 was a Published, Persuasive with Modification Patient Care change request asking for clearer guidance on CarePlan.activity.note, specifically that it should not describe the activity being performed but should capture contextual notes such as dependencies or progress, and that the element should use Annotation.

Initial application:
The Jira comments record SVN #6766. In the git-svn history, commit d6c4981fa8 (build@6766) changed the CarePlan spreadsheet so the former activity note concept became CarePlan.activity.progress with Annotation type, activity status/progress wording, and a comment prohibiting use of the element to describe the activity itself.

Additional context:
CarePlan is active in the current build through source/fhir.ini. Later CarePlan refactors removed CarePlan.activity.plannedActivityDetail (FHIR-39101) and then updated the same activity progress comment (FHIR-48415 / commit f94dfe3851) so it now points only to CarePlan.activity.plannedActivityReference. That later source trail explains why the current wording differs from the original DSTU1-era phrasing while preserving the key rule.

AutoFHIR reconciliation:
No source change was made. The current in-scope StructureDefinition defines CarePlan.activity.progress as Annotation, describes it as notes about adherence/status/progress, and explicitly says it should not be used to describe the activity to be performed.

Recommendation:
Keep this audit commit as-is. The current source already carries the applied guidance, and adding redundant narrative about the retired CarePlan.activity.note name or removed plannedActivityDetail structure would risk reintroducing stale guidance.
