FHIR-5245: Audit Bundle message wording

Issue request:
FHIR-5245 was a Published/Persuasive DSTU1 FHIR-core ballot issue about Bundle.type and Bundle scope wording. The ballot comment said the phrase "Exchanging a set of resources as part of a message transaction" blurred the distinction between message and transaction bundle types, and Grahame's proposed edit was to change "message transaction" so the messaging use was more specific.

Initial application:
No Jira-tagged FHIR-5245 commit was found. The source history shows commit 368c9c3074e (2015-01-30) changed the Bundle introduction from "Exchanging a set of resources as part of a message transaction" to "Sending a set of resources as part of a message exchange" and added a separate transaction bullet before the 2015-02-12 Jira teleconference comment approved the continuous-build wording.

Additional context:
Bundle is an active resource in source/fhir.ini, so source/bundle feeds the current build. The current Bundle introduction still distinguishes message exchange from transaction processing, the Bundle.type element defines the purpose of bundle types, and the Bundle Type code system gives separate definitions for message, transaction, and transaction-response. Later source history, including FHIR-6122's transaction/batch wording update, did not reintroduce the confusing phrase. Searches found no Zulip or Confluence discussion that conflicts with the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already carries the substance of the accepted ballot resolution: messaging is described as a message exchange, transactions are a separate RESTful processing use, and the bundle type definitions remain distinct.

Recommendation:
Keep this audit commit as-is. No current FHIR-core source fix is needed for FHIR-5245; future wording work about Bundle types should be handled under a new issue or the specific later issue that raises it.
