FHIR-24850: Audit JSON schema object typing

Issue request:
FHIR-24850 was a Published/Persuasive FHIR-core change request from STU3, applied for R5, asking that generated FHIR JSON Schema object definitions include `"type": "object"` so validators do not accept arrays or strings for object-shaped schemas. The description also noted that enum/string-valued schemas may need `"type": "string"`.

Initial application:
No current in-repository source file directly contains `fhir.schema.json`; the active core build exposes the downloadable JSON Schema from `source/downloads.html` and delegates schema generation to the Gradle Kindling dependency. The matching implementation was applied in HL7/kindling commit 11734e357e18bf0ed296c29fa287257872fb1f88, which added `r.addProperty("type", "object")` in `JsonGenerator.generateType`.

Additional context:
FHIR-I minutes from 2020-03-23 record the 12-0-0 Persuasive vote for FHIR-24850. Current core source uses `kindlingVersion=1.25.5-SNAPSHOT`, and the locally cached Kindling jar contains the JSON schema generator classes. A current build.fhir.org `fhir.schema.json.zip` check found object-like definitions typed as `object` and enum/string definitions typed as `string`. Searches found no Zulip or additional Confluence discussion that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core checkout is already wired to the fixed generator, and the generated JSON Schema surface satisfies the requested object and string typing behavior.

Recommendation:
Keep this audit commit as-is. If future work wants to improve JSON Schema generation further, it should be handled in the Kindling generator or publisher dependency workflow, not by editing generated download artifacts in this core source checkout.
