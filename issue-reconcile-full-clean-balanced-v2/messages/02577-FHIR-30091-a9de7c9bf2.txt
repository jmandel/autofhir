FHIR-30091: Audit ResearchStudy result element

Issue request:
FHIR-30091 was a Published/Persuasive BRR R5 change request to add a 0..* ResearchStudy results element with datatype Reference(EvidenceReport), so studies could structurally link to generated results or registries such as ClinicalTrials.gov. The accepted resolution and local completion comment specified the definition text for links to one or more result sets generated by the study.

Initial application:
The issue was initially applied in git commit 4ee3d88453e88c357488b3f6ba238e7ae1ce44bb, which added ResearchStudy.results 0..* Reference(EvidenceReport) with the requested ClinicalTrials.gov definition text. The same element family was then broadened by FHIR-31040 in commit 9175459a6ea354d82e8b09ca90574344bbe333d6 to include DiagnosticReport and Citation.

Additional context:
The current build uses singular element naming for this element as ResearchStudy.result, and ResearchStudy is active in source/fhir.ini. Later applied R6 work changed the allowed targets: FHIR-46095 added Composition because EvidenceReport was being deprecated/replaced; FHIR-49963 added Evidence; Citation was later removed from core; and FHIR-53694 added DocumentReference as a replacement linking option. Current source and history pages say EvidenceReport is a removed resource and that prior EvidenceReport use is now represented by EvidenceReport profiles of Composition.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The active ResearchStudy source already contains ResearchStudy.result 0..* Reference with the requested results-linking definition and current allowed targets of Composition, DiagnosticReport, DocumentReference, and Evidence. Re-adding EvidenceReport or renaming the current singular element back to results would conflict with later applied/current-build decisions.

Recommendation:
Keep this no-change audit commit as-is for FHIR-30091. No FHIR core source follow-up is needed for this seed; the related target-profile changes should remain governed by their later Jira decisions.
