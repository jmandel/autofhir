FHIR-32512: Align follow-up model metadata

Issue request:
FHIR-32512 was Applied/Persuasive with Modification for Procedure. It asked to clarify how detailed follow-up CarePlans link back to a Procedure. The accepted resolution changed CarePlan.addresses to permit Procedure and MedicationAdministration references, changed Procedure.followUp to CodeableReference<ServiceRequest | PlanDefinition>, and added Procedure.followUp prose explaining that CarePlan can reference the Procedure through CarePlan.addresses.

Initial application:
The issue was applied in HL7/fhir commit e333c37d3548da36080722466fca490beefd3a42 alongside other Procedure changes. That commit updated source/procedure/structuredefinition-Procedure.xml and source/careplan/structuredefinition-CarePlan.xml with J#32512 committee notes, the Procedure.followUp CodeableReference datatype and targets, the CarePlan.addresses target profiles, and the explanatory Procedure.followUp definition. It did not update the active FHIR ModelInfo example.

Additional context:
Procedure and CarePlan are active resources in source/fhir.ini, and Library is also active. The Library examples page links source/library/library-fhir-model-definition-content.xml as the FHIR model information file used by the CQL-to-ELM translator. That content is labeled FHIR modelInfo version 6.0.0, so leaving Procedure.followUp as only CodeableConcept and CarePlan.addresses as only Reference would preserve a stale conformance surface for CQL users. Patient Care minutes and direct Zulip searches did not reveal a later conflicting decision.

AutoFHIR reconciliation:
Updated source/library/library-fhir-model-definition-content.xml so Procedure.followUp and CarePlan.addresses are each represented as lists whose element type is a CodeableConcept-or-Reference choice, matching the CodeableReference shape used elsewhere in this ModelInfo file. No StructureDefinition changes were needed because those source files already match the Jira resolution.

Recommendation:
Keep this commit as-is. It completes the applied FHIR-32512 change for the current build's ModelInfo example; broader stale Procedure ModelInfo elements should be handled by their own Jira-specific reconciliation, not by expanding this issue.
