FHIR-13231: Audit Timing event wording

Issue request:
FHIR-13231 was a Published/Persuasive MnM change request for STU3 asking to change the Timing datatype introduction so Timing can describe expected/requested occurrences and summaries of past or ongoing events, with component definitions expressed as future events but usable for historic or ongoing events.

Initial application:
The issue was applied in historical git-svn commit 993e3553281c688e717a529b060d1b10e226f011, whose message references #13231 and svn revision 12466. That commit changed source/datatypes.html from the earlier shorter Timing introduction to the requested two-paragraph wording and updated source/datatypes/timing.xml with the same text.

Additional context:
The current build scope still includes Timing as an active datatype in source/fhir.ini, and the current source/datatypes.html Timing section retains the requested semantics. The earlier related FHIR-12637 removed the explicit prohibition on Timing for past events, while FHIR-13231 supplied the broader explanatory introduction after the initial debate. Zulip and Confluence searches found no later directly relevant community record that contradicts the current source state.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change because the active datatype page already says Timing may summarize past or ongoing events and explains that future-tense component definitions also apply to historic or ongoing events. Editing the current wording would only create redundant or editorial churn.

Recommendation:
Keep this no-change audit as-is. No follow-up is needed for FHIR-13231 in the core FHIR source unless a future work-group decision reopens the Timing datatype semantics.
