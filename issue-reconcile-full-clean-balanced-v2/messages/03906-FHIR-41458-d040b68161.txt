FHIR-41458: Audit hasValue return clarification

Issue request:
FHIR-41458 is an Applied FHIR-core/FHIR-I change request, resolved Persuasive with Modification for R6, asking the FHIRPath page to clarify that hasValue() returns true or false for a single FHIR primitive and returns empty only when the input is not a single FHIR primitive.

Initial application:
The change was already applied to source/fhirpath.html before this reconciliation. Commit 7dc829ceada85cb4bd8b4a11d35a688a8a2e58e4 replaced the old true-or-empty sentence with the Jira resolution text, and commit f356afeb29b395d23162ae9e2b1655f5a6811acd reformatted the same clarification while preserving the intended meaning.

Additional context:
The linked Zulip thread confirms the original ambiguity and records agreement that hasValue() should return false for a single FHIR primitive without a primitive value. FHIR-I minutes record the January 2024 persuasive vote. Later FHIR-44742/FHIR-53811 discussion concerns whether these functions should also cover System primitives; FHIR-44742 was closed no-change as the wrong specification, and FHIR-53811 remains unresolved, so it does not supersede the applied FHIR-41458 wording.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source/fhirpath.html hasValue() section already says that a single FHIR primitive returns true when it has a primitive value and false when it does not, while non-single-FHIR-primitive input returns empty; source/documentation.html links the root fhirpath.html page into the current specification documentation.

Recommendation:
Keep this no-change audit as-is for FHIR-41458. Any future change to System primitive handling should wait for a final decision on FHIR-53811 or a successor issue rather than being folded into this applied R6 clarification.
