FHIR-55422: Audit alternate hash extension location

Issue request:
FHIR-55422 is an Applied FHIR-core/FHIR-I change request resolved Persuasive with Modification for R6. It asked that Attachment users not be forced to use the SHA-1-only Attachment.hash element when another integrity-check algorithm is already used. The approved resolution was to define a repeatable Attachment-scoped alternate hash extension with 1..1 algorithm Coding, extensibly bound to an integrity-check algorithms value set, and 1..1 hash string.

Initial application:
No Jira-tagged source commit was found in this FHIR core checkout. The matching Jira-tagged implementation commit is cb1c3600d7e7d201f5992dfdde18d7851f334d0c in the FHIR Extension Pack repository, which added StructureDefinition-alternate-hash.xml plus integrity-check algorithm CodeSystem and ValueSet inputs. Follow-up extension-pack commits 0c72de5d, 2b046fd3, and 7d43dc06 adjusted the extension metadata and terminology files.

Additional context:
The current core Attachment datatype is active and normative, and its existing hash element still explicitly means the SHA-1 hash of the attachment data represented in base64. That is consistent with the resolution because the approved fix was a separate extension rather than changing Attachment.hash semantics. The Extension Pack is the active source for global extensions; its IG includes datatype extension pages and the alternate-hash definition has context Attachment. A related later issue, FHIR-51236, is Resolved - change required and asks to clarify raw-byte base64 encoding for Attachment.hash examples; it is not in this default Applied/Published source-edit scope and is not decided here.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The source-changing work for FHIR-55422 belongs in the FHIR Extension Pack, where the alternate-hash extension and integrity-check algorithm terminology already exist. Core source should not duplicate that extension definition or change Attachment.hash away from SHA-1.

Recommendation:
Keep this audit commit as-is for the core combined branch. If further action is taken, do it in the FHIR Extension Pack rather than this core checkout; while the requested extension is present there, a future extension-pack QA pass should review details such as the ValueSet compose system string and minor wording typos in the extension component definitions.
