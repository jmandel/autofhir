FHIR-20536: Audit AuditEvent DICOM role mappings

Issue request:
FHIR-20536 was Published/Persuasive for FHIR-core AuditEvent, voted 5-0-0 by Security on 2019-04-02 and applied for R5. It requested clarification that DICOM AuditMessage RoleIDCode values map with all RoleIDCode values in AuditEvent.agent.role and one selected RoleIDCode from the type value set in AuditEvent.agent.type.

Initial application:
The issue appears to have been applied by John Moehrke's April 2019 Security pull request, merged as 3845b72a87c656d50824c09d6f28550fbe5c4d86. The first-parent diff for source/auditevent/auditevent-spreadsheet.xml changed the DICOM mapping for AuditEvent.agent.type from the generic RoleIdCode to "prime RoleIdCode" and changed AuditEvent.agent.role to "all RoleIdCode", with role comments saying it should include all relevant roles inclusive of .agent.type. The January 2021 source rework commit 33b409a4b6d544598262f2f074ebb4b6dc466157 migrated those mappings into the current authoritative StructureDefinition XML.

Additional context:
source/fhir.ini actively lists auditevent=AuditEvent, so source/auditevent/structuredefinition-AuditEvent.xml is in current build scope. Current source keeps the DICOM mapping as AuditEvent.agent.type -> "prime RoleIdCode" and AuditEvent.agent.role -> "all RoleIdCode". AuditEvent.agent.type is bound to the participation-role-type value set, which includes the DICOM CID 402 RoleIDCode value set. Later terminology and clarity issues, including FHIR-24908, FHIR-32453, FHIR-32520, and the already-reconciled FHIR-53882, changed DICOM terminology sourcing and the type/role definitions and bindings, but did not reverse the DICOM mapping requested by FHIR-20536.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because the current AuditEvent StructureDefinition already preserves the applied DICOM mapping distinction: the primary/selected RoleIDCode maps to agent.type and all RoleIDCode values map to agent.role. Adding more prose would duplicate the existing mapping table and risk conflicting with later Security WG clarifications that agent.role remains an open CodeableConcept with only an example structural-role binding.

Recommendation:
Keep this audit commit as-is. Future work should not restore the older broad role value set just to satisfy FHIR-20536; the durable requirement is the DICOM mapping distinction, which is already present in current build-scope source.
