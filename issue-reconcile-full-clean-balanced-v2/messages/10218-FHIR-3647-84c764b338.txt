FHIR-3647: Audit profile resource split

Issue request:
FHIR-3647 was Published/Persuasive for DSTU1 and asked to split the monolithic Profile packaging resource so structural constraints and extension definitions were independently addressable, shared element content moved to ElementDefinition, and packaging could be handled outside that resource. The Jira comments explicitly separated SearchCriteria/SearchParameter work into FHIR-3626.

Initial application:
The Jira says the issue was applied in SVN revisions 3310 through 3313, 3325, 3353, and 3416. Git-svn history contains matching commits: ee49751f230a first split Profile, 0afbc59369 pulled extension definitions out of Profile, ee6a7c7e99 adjusted extension rendering, and a871b7d161 collapsed Profile and Structure as the major rework. A later source refactor, 2b54214b7e, merged Profile and ExtensionDefinition into the current StructureDefinition model rather than leaving separate Profile and ExtensionDefinition resources.

Additional context:
Current build scope in source/fhir.ini has active resources for SearchParameter and StructureDefinition, an active ElementDefinition datatype page, and lists ExtensionDefinition under removed resources rather than the active resource list. Current StructureDefinition source describes a single resource used for FHIR resources, datatypes, extensions, and constraints; current ElementDefinition source captures constraints on each element within resources, profiles, or extensions; current SearchParameter source is a separate canonical resource. Negative Zulip and Confluence searches found no community record that contradicts the Jira and git-history conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current specification has already resolved the ambiguity targeted by FHIR-3647 through StructureDefinition plus ElementDefinition, with SearchParameter handled separately. Reintroducing separate ExtensionDefinition/Profile resource wording or adding duplicate explanatory prose would be historically stale rather than a current-spec correction.

Recommendation:
Keep this no-change audit as-is. Revisit only if the work group wants a new, current change to StructureDefinition/profile terminology; FHIR-3626 and FHIR-3498 remain separate historical/contextual issues and are not decided by this commit.
