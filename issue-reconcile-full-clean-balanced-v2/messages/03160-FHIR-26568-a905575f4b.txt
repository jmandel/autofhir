FHIR-26568: Audit Ingredient description supersession

Issue request:
FHIR-26568 was a Published/Persuasive BR&R change request for R5 asking to add Ingredient.description as markdown so an Ingredient could carry an uncoded textual ingredient or excipient list while Ingredient.role distinguished active, excipient, and similar roles.

Initial application:
The request appears to have been applied in April 2020 by commit 5ddd37da99a21bdf1ea7c5ad0e7ffd0c5ef7d50f, whose subject says "added Ingredient.description FHIR#26658" but whose changed Ingredient spreadsheet matches this Jira's requested Ingredient.description work; the issue snapshot and BR&R minutes also record approval on 2020-03-31.

Additional context:
FHIR-31810 was later Published/Persuasive for the same MedicinalProductIngredient/Ingredient artifact and explicitly dropped Ingredient.description because a single Ingredient should not represent a list of other ingredients or excipients, and because MedicinalProductDefinition.ingredient.display removed the need for that use case. FHIR-28349 later added a narrower markdown note/comment use case; Jira comments and FHIR-I minutes show the element was ultimately named Ingredient.comment rather than description. The current source/fhir.ini has Ingredient active and redirects MedicinalProductIngredient to Ingredient, and source/ingredient/structuredefinition-Ingredient.xml now contains Ingredient.comment 0..1 markdown with the narrower notes definition and no Ingredient.description.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding Ingredient.description for FHIR-26568 would contradict the later published FHIR-31810 removal and duplicate/confuse the narrower FHIR-28349 Ingredient.comment element that remains in the active build.

Recommendation:
Keep this audit commit as-is. The current build should retain Ingredient.comment and should not restore Ingredient.description unless BR&R makes a new explicit decision to reverse FHIR-31810 and redefine the excipient-list use case.
