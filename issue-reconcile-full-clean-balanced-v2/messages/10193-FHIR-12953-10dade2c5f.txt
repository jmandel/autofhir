FHIR-12953: Audit Questionnaire definition guidance

Issue request:
FHIR-12953 was a Published/Persuasive with Modification DSTU2 issue for Questionnaire.item.definition. It asked to clarify that the element is a URI to an ElementDefinition supplying metadata about the item, including information that might otherwise appear in the Questionnaire instance, and its resolution accepted the wording with the inference phrase adjusted to "if absent from the item, SHALL".

Initial application:
The request appears to have been applied by the broad git-svn commit 37ee370c54dfacfae4832dc5c7a51bef52968f80, "Applied Questionnaire trackers", which replaced the older Questionnaire.item.definition text with the URI/ElementDefinition wording and an inline derived-property list. That application was not Jira-keyed and initially over-stated precedence by saying values SHALL be inferred from the ElementDefinition rather than from corresponding Questionnaire instance elements.

Additional context:
The directly related FHIR-17628 correction, already represented on the combined branch by commit 31820782523db8f803552cc68bcc9769a1d23f8b, recorded that the precedence wording was an oversight and changed the rule to allow ElementDefinition-derived values only when corresponding Questionnaire elements have no value. Later Questionnaire decisions preserved and refactored that outcome: FHIR-23128 removed the obsolete inline list from the element definition and moved mapping details to the notes, while FHIR-28305 removed item.type from the derived-property list and emphasized that Questionnaires should carry enough inline information for systems that cannot resolve definitions.

AutoFHIR reconciliation:
No source files were changed. Questionnaire is active in source/fhir.ini, and the current build-scope source already says Questionnaire.item.definition is a URI to ElementDefinition or ObservationDefinition, points readers to the detailed Question Definitions notes, lists the values that can be derived from ElementDefinition, and states that Questionnaire-provided information overrides the external definition.

Recommendation:
Keep this audit commit as-is. No follow-up core FHIR source change is recommended for FHIR-12953; reintroducing the original SHALL-style inline inference wording would conflict with the later FHIR-17628, FHIR-23128, and FHIR-28305 decisions.
