FHIR-14674: Audit search form-encoding references

Issue request:
FHIR-14674 was a Published/Not Persuasive with Modification FHIR-core STU3 issue asking whether FHIR search URL/query parameter encoding needed stricter guidance than the existing RFC 3986 URL-construction reference, especially for application/x-www-form-urlencoded handling and the use of + versus percent-encoding.

Initial application:
The issue was applied in svn revision 14197, preserved in git commit 02c7358838fb343fabcb15eaf76b8e908c04d13e as "GF#14674 - references to spec for urlencoding." That commit added https://url.spec.whatwg.org/#application/x-www-form-urlencoded links to the HTTP page's application/x-www-form-urlencoded content-type note and to the Search interaction paragraph describing POST form submissions.

Additional context:
The active REST (HTTP) page is in build scope through source/navigation.xml. Later HTTP/search refactors and reconciliations, including FHIR-39137 and FHIR-31944, moved and clarified surrounding POST search semantics while preserving the WhatWG form-encoding references. Targeted Zulip and Confluence searches found no FHIR-14674-specific discussion or conflicting work-group record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/http.html already links application/x-www-form-urlencoded to the WhatWG specification in both the content-type implementation note and the search parameter paragraph, while the existing RFC 3986 URL-construction guidance remains in the general HTTP style-guide section.

Recommendation:
Keep this audit commit as-is. No current FHIR source change is needed for FHIR-14674; any future cleanup of the surrounding explanatory wording should be handled as a separate editorial issue, not as a missing application of this tracker.
