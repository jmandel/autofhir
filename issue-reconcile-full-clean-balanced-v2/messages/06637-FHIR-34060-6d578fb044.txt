FHIR-34060: Audit transaction interaction ordering

Issue request:
FHIR-34060 was Published with a Persuasive with Modification resolution for R5. It asked the HTTP Transaction Processing Rules to order transaction processing by FHIR interactions rather than raw HTTP verbs, because method-only ordering made POST search, PUT create/update, and GET operations ambiguous. The accepted resolution said to use FHIR interactions while still retaining HTTP verb descriptions where useful.

Initial application:
The issue was applied by commit faaaefb02fd5801ae42a282443d030a423b04cee, which changed source/http.html so the transaction processing order names delete, create, update, patch, read, vread, search, and history interactions and keeps the corresponding HTTP verbs parenthetically. Current source retains that application in the active RESTful API HTTP page.

Additional context:
FHIR-I minutes and the linked Zulip thread show the work group recognized that a defined transaction order affects interoperability, that POST-based search and operations raised separate edge cases, and that the final FHIR-34060 action was the interaction-based wording. Later FHIR-36095 clarified the POST-based search edge case by saying searches in batch/transaction Bundles should be conveyed and accepted as GET and that POST-based searches have no standard Bundle representation; that issue already has a no-change audit commit on the combined branch.

AutoFHIR reconciliation:
No source change was made. The current HTTP source already uses FHIR interaction names in the transaction order, preserves HTTP verb annotations as the resolution allowed, and the current Search source separately resolves the POST-search-in-Bundle ambiguity that motivated part of the issue.

Recommendation:
Keep this audit commit as-is. Do not add duplicate or broader transaction-order prose without a new work-group decision, especially for extended operations, because the discovered community evidence identified operations as hard to classify but no final Jira decision requires a current-source change for that edge case.
