FHIR-33004: Restrict evaluate report type value set

Issue request:
FHIR-33004 is Applied/Persuasive. It reported that the $evaluate-measure reportType parameter used the old "subject" report type wording and asked that reportType align with MeasureReport.type while using a dedicated evaluation value set that contains only individual, subject-list, and summary, excluding the data-collection/data-exchange report type.

Initial application:
FHIR-28359 first corrected the operation documentation from subject/population to individual/summary in commit 142c81d92f2c941402c0810650bf7b0e99edc6de. FHIR-33004 was then applied in commit 287186099cc6119f4547894ca2e679b81fbda981 by creating source/measure/valueset-measure-report-evaluation-type.xml and binding Measure/$evaluate-measure reportType to it. FHIR-37571 later copied the same binding to the newer Measure/$evaluate operation.

Additional context:
The active Measure resource is in source/fhir.ini, and source/measure/list-Measure-operations.xml includes both Measure-evaluate and Measure-evaluate-measure. FHIR-39174 was effectively treated as a duplicate of FHIR-33004 and used the same PR/commit. Later, FHIR-55083 added an "other" escape-valve code to the shared MeasureReport Type code system without changing the evaluation operations. Because the evaluation value set was composed as all measure-report-type codes except data-exchange, it unintentionally began including "other", while both operation descriptions still list only individual, subject-list, and summary.

AutoFHIR reconciliation:
This commit changes the evaluation value set composition to explicitly include individual, subject-list, and summary. That preserves the applied FHIR-33004/FHIR-39174 intent after the later FHIR-55083 expansion of the shared MeasureReport Type code system, and avoids allowing reportType=other for evaluate operations through the required binding.

Recommendation:
Keep this source fix. It is a narrow correction to an active Measure value set used by active Measure operation definitions. No further core change is needed unless CQI later decides that evaluate reportType should deliberately support implementation-defined "other" report types.
