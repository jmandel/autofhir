FHIR-20417: Audit DocumentReference _content search clarification

Issue request:
FHIR-20417 was a Published FHIR-core DocumentReference change request, resolved Persuasive with Modification for R5, asking that DocumentReference clarify use of the generic _content search parameter for free-text discovery of document content. The approved resolution said a server declaring support for _content on DocumentReference agrees to search content included in DocumentReference.content.attachment.data and DocumentReference.content.attachment.url.

Initial application:
The issue appears to have been applied by git commit 3c56ef94e5762b202503cc4224a9941ac9522dfe, "Adding FHIR#20417, and FHIR#17178", which added an implementation note to source/documentreference/documentreference-notes.xml. A later DocumentReference cleanup commit, 97cf6bb0ede5497d006a53d90f53c1cc2b41248f, corrected the path from DocumentReference.content.url to DocumentReference.content.attachment.url and wrapped the paths in code markup.

Additional context:
DocumentReference is active in source/fhir.ini, so source/documentreference/documentreference-notes.xml feeds the current build. The current implementation note says that _content shall search across DocumentReference.content.attachment.data and DocumentReference.content.attachment.url, which preserves the published FHIR-20417 rule. Zulip origin discussion supports using an existing generic search parameter for attachment bits. A later unresolved Triaged issue, FHIR-54535, asks for more precise R6 clarification about whether search is over decoded content or URL targets; because it is not final, it does not supersede the published FHIR-20417 application.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The current active source already conveys the required DocumentReference-specific _content behavior, and changing it now would either be redundant or would pre-judge unresolved FHIR-54535 clarification work.

Recommendation:
Keep this no-change audit as-is for FHIR-20417. Handle any future weakening or clarification of the SHALL, decoded attachment content, or URL-target behavior through the newer FHIR-54535 work-group process rather than altering the already-applied R5 reconciliation here.
