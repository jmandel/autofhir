FHIR-15823: Audit secondary finding extension migration

Issue request:
FHIR-15823 was Published/Persuasive with Modification for STU3 and asked for a way to distinguish solicited from unsolicited/secondary observations. The accepted resolution was to add a secondary-finding extension for Observation.

Initial application:
The change was applied in core by fc498fd9e562fba7eb6c221c5fa1520445b6a9e1 ("GF#15823 add extension"), which added the secondary-finding code system/value set and wired the Observation extension spreadsheet. The extension is no longer present in current core source because core extensions were removed from the R5 source by dd468d4f1799dd79819315b211588ef1cf4586e0.

Additional context:
The current authoritative files for http://hl7.org/fhir/StructureDefinition/observation-secondaryFinding, http://hl7.org/fhir/ValueSet/secondary-finding, and http://hl7.org/fhir/secondary-finding are in the FHIR Extension Pack checkout, not this core checkout. A later Published FHIR-extensions issue, FHIR-53017, changed the current interpretation by deprecating the secondary-finding extension and pointing users to observation-structure-type instead.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. Re-adding or changing the secondary-finding extension in core would be wrong because the relevant source is maintained in the FHIR Extension Pack, and the current Extension Pack already carries the later deprecation decision.

Recommendation:
Keep this external-repo audit as-is for core reconciliation. Any further work on the secondary-finding extension should be handled in the FHIR Extension Pack and coordinated with FHIR-53017/related OO decisions, not by editing core source.
