FHIR-13545: Audit slice constraining flag

Issue request:
FHIR-13545 was Published with resolution Persuasive with Modification for STU3. It asked for an explicit boolean that lets a derived profile say whether a named slice is intended to constrain an inherited slice, so parent profile slice additions, removals, or renames can be detected instead of silently changing child-profile meaning.

Initial application:
The Jira comment points to svn revision 14334. In git, becab2754dd6f6f16643d6a6c256c08bd8795c1a ("GF#13545 - add ElementDefinition.sliceIsConstraining") added ElementDefinition.sliceIsConstraining to source/datatypes/elementdefinition.xml with the requested definition, requirements, and comments, plus invariant eld-22 requiring sliceName when sliceIsConstraining is present.

Additional context:
The disposition originally described the new boolean as ElementDefinition.slicing.constraining, but the contemporaneous conformance Zulip thread records Grahame Grieve's concern that slices do not carry a slicing element and that placing the flag under slicing would wreck snapshot logic. The thread proposed moving the marker onto ElementDefinition itself, and current source retains that intentional placement. Later related slicing-language issues FHIR-16309 and FHIR-17821 are already represented on the combined branch and do not require this issue to make further profiling prose changes.

AutoFHIR reconciliation:
No source change was made. Current build-scope source lists ElementDefinition as an active datatype, defines ElementDefinition.sliceIsConstraining as a 0..1 boolean with the FHIR-13545 semantics and comments, and retains the invariant that the flag can only appear on a named slice. That satisfies the issue after accounting for the implementation discussion that refined the element's location/name.

Recommendation:
Keep this no-change audit commit. Revisit only if the work group wants broader narrative guidance in profiling.html about when authors should populate sliceIsConstraining; the normative datatype definition and invariant already implement the published decision.
