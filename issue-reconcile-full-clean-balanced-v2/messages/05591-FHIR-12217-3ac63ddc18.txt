FHIR-12217: Audit Description ID extension migration

Issue request:
FHIR-12217 was Published/Persuasive with Modification for DSTU2 in the Vocabulary work group. It asked how to represent a SNOMED Description Id alongside a Concept Id for an NHS requirement and whether international guidance or a standard extension would be valuable, with the final resolution to add an extension for the description id.

Initial application:
The request was applied together with FHIR-12302 in historical SVN/git commit e7180dea8444e0bc39f443e7306444ee80bb12c7, whose subject names both #12302 and #12217. That commit added the sctdescid Coding extension row to source/datatypes/coding-extensions-spreadsheet.xml and linked the resulting Description Id Extension from the then-current source/snomedct.html page.

Additional context:
FHIR-12302 is the paired issue that explicitly asked to define the standard SNOMED Description ID extension. Since then, FHIR-core moved extension definitions out of the core build: commit dd468d4f1799dd79819315b211588ef1cf4586e0 removed the sctdescid row from the old core extension spreadsheet, and current core source finds the canonical only in source/oids.ini. The live StructureDefinition is now in HL7/fhir-extensions at input/definitions/datatypes/StructureDefinition-coding-sctdescid.xml. Later issues FHIR-33058 and FHIR-40724 broadened the same extension in the Extension Pack and are already audited on the combined branch; FHIR-32065 separately rejected generalizing this SNOMED-specific extension to all code systems.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR-core source change. The approved extension exists in the Extension Pack and the current core checkout does not own the live StructureDefinition or the old SNOMED CT guidance page. Recreating the old row in core would be a regression of the extension-pack migration.

Recommendation:
Keep this empty external-repo audit commit as-is. No core follow-up is needed for FHIR-12217 unless the Extension Pack definition is lost or the work group approves new guidance in the appropriate external terminology/extension source.
