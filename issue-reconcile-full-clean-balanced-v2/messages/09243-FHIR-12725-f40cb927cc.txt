FHIR-12725: Audit Reference.identifier clarification

Issue request:
FHIR-12725 was a Published/Persuasive DSTU2 FHIR-core references issue asking the specification to clarify that Reference.identifier is not limited to targets already exposed as FHIR instances. The accepted clarification was that the identifier must refer to a business concept that could be represented as a FHIR resource, and that the possible resource would need to be one of the resource types allowed by the Reference.

Initial application:
The Jira comment records svn revision 11195, represented in git by aa10535dc9d24a7d13c079e83d1b1626f55010dd. That commit, titled "#12725 - note about use of Reference.identifier", added the clarification to source/datatypes/reference.xml and source/references.html.

Additional context:
Reference remains an active normative datatype in source/fhir.ini, and source/hierarchy.xml includes references.html and references-definitions.html in the built References between Resources page hierarchy. Later Published/Persuasive issue FHIR-13694 refined the same rule to say the business concept can potentially be expressed as a FHIR resource, and that reconciliation is already represented on the combined branch. Later FHIR-50120 added canonical-URL guidance without changing the FHIR-12725/FHIR-13694 scope rule. FHIR-50074 is still Triaged and complained about the older exposed-instance wording, but the FHIR-13694 reconciliation has already removed that stale ambiguity from current source.

AutoFHIR reconciliation:
Made no source change. Current source/datatypes/reference.xml and source/references.html already state the required rule: Reference.identifier need not point to an actual exposed FHIR instance, but it SHALL point to a business concept that can potentially be expressed as a permitted FHIR resource type. Adding another edit for FHIR-12725 would duplicate existing normative and narrative guidance.
