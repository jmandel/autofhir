FHIR-19427: Audit DICOM Endpoint payload optionality

Issue request:
FHIR-19427 is a Published/Persuasive with Modification FHIR-core Patient Administration change request for Endpoint. It reported that the example Endpoint payloadType value set had no suitable DICOMweb/DICOM payload value while payloadType was mandatory, and proposed either making the element optional or updating the value set. The final Jira resolution says the payloadType property was updated to 0..* in FHIR-25393.

Initial application:
The source application was not a standalone FHIR-19427 commit. Commit 445d4741d1559c197decca8343f60d1cad753d36 changed the then-current Endpoint.payloadType minimum from 1 to 0 as part of Endpoint cardinality work, and merge commit 29c32a3f611f298e0601cd090b441155fed47286 explicitly lists FHIR-19427 together with FHIR-34261, FHIR-25393, FHIR-12342, and FHIR-22629 for the Endpoint.connectionType and Endpoint.payloadType cardinality changes.

Additional context:
Endpoint is active in the current build through source/fhir.ini. The historical Endpoint.payloadType element has since been refactored into Endpoint.payload.type, with source/fhir.ini mapping Endpoint.payloadType to Endpoint.payload.type. PA meeting minutes and the cited DICOM Zulip thread support the same interpretation: the DICOM-specific problem was caused by mandatory payloadType plus an example binding, and the approved resolution was to relax the element rather than require a new DICOM payload code. Related audit commits for FHIR-22629, FHIR-25393, and FHIR-34261 are already present on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative source already defines Endpoint.payload.type with min 0 and max *, so DICOM Endpoint instances no longer need to invent or select an unsuitable payload type code merely to satisfy cardinality.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-19427 unless a future Patient Administration decision changes the Endpoint payload advertising model or requires a specific standardized DICOM payload type value.
