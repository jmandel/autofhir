FHIR-43407: Audit Resource _text placement

Issue request:
FHIR-43407 was an Applied/Persuasive FHIR-I change request for R6 asking to remove the `_text` search parameter from the Resource search-parameter list because `_text` searches narrative and is defined on DomainResource.

Initial application:
The issue appears to have been applied by git commit 412487b6a6021026b47e7166d699a5d2cc3ae2c8, which removed the `Resource-_text` SearchParameter entry from `source/resource/bundle-Resource-search-params.xml`. The current Resource search-parameter bundle no longer contains `Resource-_text`, while `source/domainresource/bundle-DomainResource-search-params.xml` still defines `DomainResource-_text`.

Additional context:
FHIR-9701 previously recorded the same underlying correction, moving `_text` from Resource to DomainResource because only DomainResource has narrative. FHIR-I minutes for 2024-05-06 record agreement that text should be on DomainResource and that Grahame agreed to remove it from Resource. The related Zulip thread concluded to try fixing the definition, and a later retracted FHIR-49657 report reaffirmed that `_text` cannot be on Resource because Resource lacks narrative content.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active build source already reflects the requested correction: `Resource` and `DomainResource` are active resources in `source/fhir.ini`, the Resource search-parameter bundle omits `_text`, and the DomainResource search-parameter bundle retains `_text`.

Recommendation:
Keep this audit commit as-is. No follow-up source edit is needed in core unless a future work-group decision changes how search parameters on DomainResource are represented for tooling compatibility.
