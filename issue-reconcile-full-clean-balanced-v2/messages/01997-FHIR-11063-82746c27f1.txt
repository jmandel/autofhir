FHIR-11063: Audit Consent terminology application

Issue request:
FHIR-11063 was a Published/Persuasive with Modification DSTU2 CBCC change request for FHIR-core Consent section 6.4.1. It asked to disentangle Consent Policy, Consent Directive, Consent Statement, Consent Metadata, and Consent Form terminology by harmonizing the Consent front matter with an approved change proposal document, moving most consent discussion to the Consent page, and moving consent query/response descriptions to the Search section.

Initial application:
The issue was applied in git commit 612068c15886b6624c44de5d656417bcfa7d76d3, whose subject explicitly lists GF#11063 among STU3 Consent updates. That commit added the Consent Directive legal-binding discussion and definitions for Consent Form, Consent Directive Derivative, Consent Statement, Consent Registration, related query/response material, and Policy context to source/consent/consent-introduction.xml. The applied text did not exactly match the Jira description's initial proposed labels, which is consistent with the Jira's Persuasive with Modification resolution and its direction to use the accepted change proposal document.

Additional context:
Consent is an active resource in source/fhir.ini. A later Published R5 Consent cleanup, commit 24a94d510247db95964505364d08c0a287198a9b for FHIR-27110 and FHIR-27773 through FHIR-27776, moved the GF#11063 definitions and Privacy Consent Directive discussion from source/consent/consent-introduction.xml into source/consent/consent-notes.xml as part of the Privacy Consent General Model. That cleanup preserved the core GF#11063 terminology discussion while removing only the older query/response table row from that location. FHIR-11064, an adjacent wording issue, has already been separately audited on the combined branch.

AutoFHIR reconciliation:
This audit commit makes no source change because the current build-scope Consent source already contains the applied GF#11063 Consent Form, Consent Directive Derivative, Consent Statement, Consent Registration, Policy context, Privacy Consent Directive, and Consent Metadata discussion in source/consent/consent-notes.xml. Rewriting the remaining "Policy context" label to "Consent Policy" now would go beyond the applied Persuasive with Modification source history and could create an unsupported current-spec terminology change.

Recommendation:
Keep this no-change audit commit as-is. Future Consent narrative modernization may still improve wording quality or revisit the policy terminology with CBCC, but FHIR-11063 itself is already represented in current source after later reorganization and does not require a reconciliation edit.
