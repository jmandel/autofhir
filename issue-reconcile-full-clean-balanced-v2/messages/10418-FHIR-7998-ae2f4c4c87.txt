FHIR-7998: Audit composite search parameter definition

Issue request:
FHIR-7998 was a Published/Persuasive FHIR-core search clarification from the 2015May ballot. It asked the Composite Search Parameters section to follow the surrounding pattern where the first sentence defines the parameter type, replacing an opening sentence about resource-intersection search results with one that defines composite search parameters as joining values with "$".

Initial application:
The Jira comment records svn revision 6474, and git commit ec36f3a6f1ac25a85aedff8150fffa71822c8103 is the corresponding git-svn import. That commit, titled "#7998 - clean up language", changed source/search.html so the Composite Search Parameters section began with "Composite search parameters supports joining single values with a \"$\"" before the prior intersection explanation.

Additional context:
The current search page has been reorganized since DSTU1. Later Published/Applied issues in the same text family, especially FHIR-33158 and FHIR-41550, separated composite behavior from AND/OR intersection examples and removed a typo. Those changes refined the sentence to "Composite search parameters allow joining multiple elements into distinct single values with a $" while preserving the seed issue's requested pattern. Community searches found no direct FHIR-7998 discussion and found only later composite wording discussion that points to FHIR-33158 rather than a conflicting decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. source/search.html is the active search narrative source, and its Composite Search Parameters section already begins with a definition of composite search parameters using "$". Editing it again would be redundant and could reopen wording already refined by later FHIR-I decisions.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-7998 unless the work group separately decides to reword composite search semantics beyond this old editorial request.
