FHIR-24878: Audit List.entry orderMeaning

Issue request:
FHIR-24878 was Published with resolution Persuasive for R5. It asked to add orderMeaning to List.entry because List.orderedBy gives the collection an order meaning, with the approved wording: "Order has no meaning unless specifically asserted by List.orderedBy, in which case the List SHALL be interpreted as being ordered as specified by List.orderedBy".

Initial application:
The request was applied by 9a4ebc567875e0fb6d6a4c0411d19a26eb483a6a, merged as ea027fdbee6dfa8a498dffc4a701d7678e8e3d55, which added the List.entry.orderMeaning line to source/list/structuredefinition-List.xml. The current active List resource still contains that orderMeaning text.

Additional context:
The List resource is active in source/fhir.ini. The original Zulip thread asked whether List.entry needed orderMeaning and led directly to the tracker; FHIR-I minutes for 2020-03-23 record a 7-0-0 persuasive vote to set orderMeaning indicating no order unless specified by orderedBy. Earlier Published List issues FHIR-3661 and FHIR-7502 established the List.orderedBy model and clarified that list item order is preserved by the List itself; they support, rather than contradict, the FHIR-24878 wording. A broader Jira/community check found no later core decision reversing this orderMeaning.

This commit intentionally makes no source change. Current build source already matches the approved resolution and is in the active List resource path.

Keep this audit commit as-is. No core source follow-up is needed for FHIR-24878 unless a future work-group decision revisits List ordering semantics.
