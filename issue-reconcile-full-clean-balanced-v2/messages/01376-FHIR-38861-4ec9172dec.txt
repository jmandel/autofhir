FHIR-38861: Audit Patient gender/RSG guidance

Issue request:
FHIR-38861 was Published with a Persuasive with Modification resolution for R5 Patient section 8.1.8. It asked for additional top-level guidance on when Patient.gender versus Recorded Sex or Gender (RSG) should be used to represent administrative gender, and for correction of the RSG-section typos "clincal" and "an realm-specific".

Initial application:
The issue appears to have been applied by commit 01c44ce75f41fad6d42eeb5abbfd7c65a23dd4fa, which changed source/patient/patient-notes.xml and included the exact Jira-requested top-level guidance sentence. That first application was part of a broader Gender Harmony Patient section update with FHIR-39202 and OTHER-2463. Follow-up Patient narrative commits 5529c7d, 988821a, 571ab79, and f57e657 removed duplicated old RSG prose, filled the Gender Harmony links, updated extension hyperlinks, and left the current corrected RSG wording.

Additional context:
source/fhir.ini actively lists patient=Patient, so source/patient/patient-notes.xml is in current build scope. The current Patient narrative now tells implementers that different gender and sex attributes serve different use cases, identifies Patient.gender as administrative gender, and defines RSG as a separate category whose exchange guidance belongs in the Gender Harmony Implementation Guide. Patient.gender's StructureDefinition definition links readers to patient.html#gender. FHIR-39239 separately records that Patient.gender should be retained for existing systems, with pre-coordination required for clinical or other semantically precise uses. Confluence Gender Harmony and PA minutes show the RSG/FHIR section text was prepared for the build and then approved through PA block voting; no direct Zulip discussion was found that changes this conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already implements the FHIR-38861 guidance and no longer contains either typo from the issue description. Adding more local Patient.gender-versus-RSG prose would duplicate the current top-level use-case guidance and the linked Gender Harmony IG rather than correct a current-spec defect.

Recommendation:
Keep this no-change audit commit as-is. No follow-up is needed in the FHIR core checkout for FHIR-38861 unless the work group later decides to replace the Gender Harmony IG link or change the underlying Patient.gender/RSG policy.
