FHIR-34043: Audit DocumentReference $generate input parameters

Issue request:
FHIR-34043 was a Published/Persuasive with Modification R5 OO change request for DocumentReference/$generate. It reported that the persist input parameter was typed as Binary instead of boolean, that the persist option was unclear, and that the url input should better account for source documents such as Binary, Composition, or Bundle resources. The approved resolution was to make persist boolean and define the url parameter as the URL to the source document, which may be a general URL or a Binary, Composition, or Bundle.

Initial application:
The issue was applied before this reconciliation. Jira links the August 2022 implementation history, and local source history contains 82d7ae7918, merged by f2d7b07e50, which added the url documentation and changed persist from Binary to boolean in source/documentreference/operationdefinition-DocumentReference-generate.xml. The current retained operation source still has that documentation and boolean type.

Additional context:
The initiating Zulip thread confirms the confusion around persist and the request to make $generate implementable for submitted or referenced document content. OO minutes on 2022-06-14 record the final 5-0-0 vote to update the datatype and description. A later Published issue, FHIR-39624, corrected the same operation's output parameter to return a Bundle and is already represented on the combined branch. Current R6 source also removed DocumentReference-generate from source/documentreference/list-DocumentReference-operations.xml, and source/ballot-intro.html points DocumentReference.$generate to API Incubator rather than the current core operation list.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The approved FHIR-34043 input-parameter changes are already present in the retained operation source, and the current core build wiring no longer lists DocumentReference.$generate as a core DocumentReference operation. Re-adding the operation, broadening url beyond a URI, or editing retained example text that is not wired into the current core operation list would exceed this R5 applied issue reconciliation.

Recommendation:
Keep this audit commit as-is for FHIR-34043. If the API Incubator copy, incubator link, or example JSON literals need cleanup, handle that as separate current-build/API Incubator work rather than changing the already-applied core R5 reconciliation.
