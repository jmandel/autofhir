FHIR-3843: Audit ImagingSelection frame references

Issue request:
FHIR-3843 was a Published/Persuasive with Modification DSTU1 Imaging Integration request to add a frame component to ImagingObjectSelection.instance so selections could identify frames of multi-frame DICOM SOP Instances, and to remove retrieveAETitle from series and instance.

Initial application:
The request was applied in historical commit a51afaf7a9, which updated the then-current ImagingObjectSelection spreadsheet and example, removed retrieveAETitle, renamed retrieveUrl to url, and added instance frames with frameNumbers and a retrieval URL. Current source no longer builds ImagingObjectSelection as an active resource.

Additional context:
FHIR-9414 later renamed the old plural frames/frameNumbers elements to singular frame/number. FHIR-13145 addressed the same frame-reference gap after ImagingObjectSelection was replaced by ImagingManifest. FHIR-17183 later introduced the active ImagingSelection resource, whose current build-scope definition supports selected multi-frame SOP Instance frames through ImagingSelection.instance.frameNumber and uses ImagingSelection.endpoint plus endpoint notes for retrieval access rather than the old per-frame retrieveUrl component.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active build lists ImagingSelection as the current resource and marks ImagingObjectSelection as dropped, and the current ImagingSelection source already defines instance.frameNumber as 0..* positiveInt for selected frames from a multiframe SOP Instance, with notes and an example showing multi-frame image selection.

Recommendation:
Keep this audit commit as-is. The original implementer-facing requirement is preserved in the current active resource, and resurrecting the old FrameSet/retrieveUrl shape would conflict with later resource redesigns; any future frame retrieval refinements should be handled as new ImagingSelection issues.
