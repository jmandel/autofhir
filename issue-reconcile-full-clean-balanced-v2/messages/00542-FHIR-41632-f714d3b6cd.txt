FHIR-41632: Audit cited artifact part type migration

Issue request:
FHIR-41632 is an Applied/Persuasive CDS change request to add a `chapters` code to the Cited Artifact Part Type CodeSystem/ValueSet used by Citation.citedArtifact.part.type so Citation can cite books. The resolution said to add the requested code and also move Citation's extensible bindings to THO as part of maturity work.

Initial application:
The requested code was applied in core by git commit 823cf54a42f916944972c5e4ee885a5d94c9effd (`J#41632 Add "chapters" code to the Cited Artifact Part Type CodeSystem`), which inserted `chapters` with the definition `Denotes specific chapter or chapters of an article or artifact.` into source/citation/codesystem-cited-artifact-part-type.xml.

Additional context:
Later terminology migration work moved this CodeSystem/ValueSet out of the base FHIR source. Jira UP-633 is Proposal Implemented for moving EBMonFHIR terminologies from FHIR to THO, CDS minutes approved UP-633, and the THO 6.3.0 publication page lists UP-633. Core commit caa1fb75adbcca96f92873c7d958e31f547124bb deleted source/citation/codesystem-cited-artifact-part-type.xml and source/citation/valueset-cited-artifact-part-type.xml, and current source/fhir.ini has no active Citation resource or cited-artifact-part-type terminology entry. A later core commit also removed the Citation resource source itself from the current build. The current published THO CodeSystem at http://terminology.hl7.org/CodeSystem/cited-artifact-part-type is active and includes `chapters`; the current THO ValueSet includes that CodeSystem.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR-core source change. The requested semantic change is present in THO, and the authoritative source for the cited-artifact-part-type terminology is now outside this FHIR checkout/current build.

Recommendation:
Keep this audit commit as-is. Do not reintroduce the deleted core CodeSystem/ValueSet or edit obsolete OID remnants for this issue; any future change to the cited-artifact-part-type codes should be made through THO/UTG.
