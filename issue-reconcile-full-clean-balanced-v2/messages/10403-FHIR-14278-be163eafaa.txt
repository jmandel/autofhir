FHIR-14278: Audit isModifier inheritance tooling scope

Issue request:
FHIR-14278 is a Published/Persuasive FHIR-core change request, raised in STU3 and applied for R5, asking to fix an IG Publisher bug where elements whose base definition has isModifier=true, such as MedicationRequest.status, were emitted in a differential as isModifier=false when the profile author had not set the flag explicitly. The Jira resolution was auto-approved, and the later Jira comment says this was an old tooling issue that should be raised in HL7/fhir-ig-publisher if still reproducible.

Initial application:
No FHIR core source commit explicitly mentions FHIR-14278. The contemporaneous Zulip thread shows the symptom came from US Core profile output generated by the IG Publisher, and the current core source already defines the underlying rule: derived profiles cannot change modifier status once an element is defined as a modifier.

Additional context:
The active current build includes ElementDefinition, Communication, and MedicationRequest from source/fhir.ini. Their source confirms ElementDefinition.isModifier cannot be changed in derived profiles, and the base Communication.status and MedicationRequest.status definitions remain modifier elements.
