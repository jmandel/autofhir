FHIR-32817: Align Consent policy model metadata

Issue request:
FHIR-32817 was Published/Persuasive with Modification for FHIR-core Consent. It asked for an explicit and unambiguous computable Consent default decision, and the final resolution changed the former Consent.policy and Consent.policyRule model into regulatoryBasis, policyBasis, and policyText so regulatory/indexing policy context is separated from computable policy enforcement.

Initial application:
The issue was initially applied by commit 7ec3c37642c57792ee12bc07696299ddcc974dd4, which added Consent.regulatoryBasis, Consent.policyBasis, and Consent.policyText to source/consent/structuredefinition-Consent.xml. Later FHIR-39597 application moved the default permit/deny value from provision.type to Consent.decision. The active Consent StructureDefinition and Consent narrative already reflect those decisions, but the active FHIR ModelInfo Library still exposed the old Consent.policy, Consent.policyRule, and Consent.Provision.type metadata.

Additional context:
Consent is an active resource, Library is an active resource, and source/library/list-Library-examples.xml includes Library/library-fhir-model-definition as a current FHIR Model Definition example. FHIR-45450 later changed policyBasis.url to policyBasis.uri, and that correction is already represented on the combined branch; this commit therefore uses the current URI child. FHIR-43331 and the linked Zulip discussion confirm regulatoryBasis is not the computable decision input; computable policy is represented through policyBasis and/or provisions with the default decision in Consent.decision.

AutoFHIR reconciliation:
Updated source/library/library-fhir-model-definition-content.xml so the Consent model metadata now defines Consent.PolicyBasis with reference and uri children, exposes regulatoryBasis, policyBasis, policyText, and decision on Consent, represents Consent.provision as a list, and removes the stale Consent.policy, Consent.policyRule, and Consent.Provision.type entries from that computable model surface.

Recommendation:
Keep this source fix. It closes the remaining current-build computable metadata gap for FHIR-32817 without reopening the already-published Consent StructureDefinition and narrative decisions. Further broad cleanup of unrelated stale Consent ModelInfo fields, if desired, should be tracked separately from this policy/default-decision reconciliation.
