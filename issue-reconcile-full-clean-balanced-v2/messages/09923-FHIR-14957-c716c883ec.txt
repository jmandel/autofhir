FHIR-14957: Audit reverse chaining search syntax

Issue request:
FHIR-14957 was a Published/Persuasive FHIR-core search issue from STU3 asking that reverse chaining search syntax using _has be specified more clearly, because the section only showed examples and mixed Observation:patient with Observation:subject in examples.

Initial application:
The Jira comments cite svn revision 13397. In the git mirror, commit 7067af22bc923ce4ae990f3c02b0d32252e1f546 (git-svn build@13397) applied the issue by changing the reverse chaining "or" and repeated _has examples from Observation:subject to Observation:patient, matching the surrounding text and base example.

Additional context:
The current source/search.html is the active FHIR search page and now has a Reverse Chaining section linked from the contents and the _has standard search-parameter summary. Later same-page decisions expanded and refined the section: FHIR-20474 added an example showing _has inside a chained search, FHIR-34162 corrected the nested AuditEvent example's invalid user search parameter to agent during the R5 search page rewrite, and FHIR-26886 added the warning that reverse-chained search parameters are not intended to work with search modifiers and should use named queries or _filter for advanced matching. Exact community searches for FHIR-14957 found no Zulip or Confluence evidence that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current Reverse Chaining section consistently uses _has:Observation:patient:... for the Patient/Observation examples, explains the roles of the resource type, reference search parameter, and criteria search parameter in prose, shows OR and repeated-parameter behavior, and includes nested and chained-search examples. Adding a separate syntax restatement would be redundant with the current section and the later accepted clarifications.

Recommendation:
Keep this no-change audit commit as-is. Revisit only if the work group wants a new formal grammar for _has beyond the applied FHIR-14957 resolution and later search-page clarifications.
