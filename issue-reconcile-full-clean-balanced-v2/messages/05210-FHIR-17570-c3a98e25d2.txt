FHIR-17570: Audit ValueSet authoritative source extension location

Issue request:
FHIR-17570 was Published/Persuasive with Modification for FHIR-core ValueSet. It asked for a standard valueset-authoritativeSource extension documenting the authoritative accessible persisted source of truth for the full ValueSet definition when that differs from ValueSet.url, plus a note that ValueSet.url serves that role when the extension is absent.

Initial application:
The request was applied before this reconciliation by git-svn commit 9b425ec168db1aba64dc18023d721ec2116f538f (#17570, svn 14648), which added the valueset-authoritativeSource extension to the ValueSet extension spreadsheet with the requested definition, usage note, and canonical-URL fallback language.

Additional context:
The current core checkout no longer owns this StructureDefinition. Commit dd468d4f1799dd79819315b211588ef1cf4586e0 removed standard extension source files from the R5 core source, and current core source/fhir.ini has no active valueset-authoritativeSource build entry. The FHIR Extension Pack now contains input/definitions/ValueSet/StructureDefinition-valueset-authoritativeSource.xml with the requested context, cardinality, definition, and note. Later Extension Pack decisions FHIR-56275 and FHIR-56401 added the more general artifact-authoritativeSource extension and deprecated valueset-authoritativeSource in its favor.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. Reintroducing or editing valueset-authoritativeSource in FHIR-core would conflict with the current source ownership split; the remaining artifact and its successor are maintained in HL7/fhir-extensions.

Recommendation:
Keep this external-repo audit as-is. Future maintenance of valueset-authoritativeSource or artifact-authoritativeSource should happen in the FHIR Extension Pack, not by adding a duplicate core StructureDefinition.
