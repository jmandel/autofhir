FHIR-22626: Confirm Communication sender wording

Issue request:
FHIR-22626 was a Published/Persuasive with Modification Patient Care change request for CommunicationRequest and Communication. It asked to remove ambiguity in the short descriptions for sender and recipient so readers would understand the sender/recipient of the eventual Communication, not the transmission of the CommunicationRequest, and its final resolution renamed CommunicationRequest.sender to CommunicationRequest.informationProvider with updated requester, recipient, and sender/informationProvider descriptions.

Initial application:
The issue was applied by git commit 564718d6b42a9f92adb90e790a58481942224928, which changed the then-authoritative Communication and CommunicationRequest spreadsheets and the CommunicationRequest example. The current StructureDefinition-based source preserves those changes: CommunicationRequest.requester, recipient, and informationProvider carry the requested short definitions, Communication.recipient and Communication.sender carry the requested Communication descriptions, and the old CommunicationRequest.sender path is retained only as a historical alias to CommunicationRequest.informationProvider.

Additional context:
Communication and CommunicationRequest are active resources in source/fhir.ini and owned by Patient Care in the current build. Later same-family issues adjusted the renamed element and adjacent target types: FHIR-22631 changed CommunicationRequest.informationProvider to repeat and has already landed an AutoFHIR source correction for the notes page, FHIR-22630 added Endpoint as recipient/sender/informationProvider target type, and later comments/source notes further refined provider targets. Corrected Zulip and Confluence searches for FHIR-22626 and the CommunicationRequest informationProvider wording found no conflicting community discussion.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The active conformance source, search parameters, workflow mapping exceptions, and current notes page all use CommunicationRequest.informationProvider and the final short descriptions requested by FHIR-22626. The remaining CommunicationRequest.sender references found in current source are a fhir.ini historical alias and an older workflow warning suppression entry, not implementer-facing CommunicationRequest element definitions that would change the built specification wording.

Recommendation:
Keep this audit commit as-is. No FHIR core source change is needed for FHIR-22626; future cleanup of non-rendered workflow suppression text, if desired, should be handled separately from this published wording/rename reconciliation.
