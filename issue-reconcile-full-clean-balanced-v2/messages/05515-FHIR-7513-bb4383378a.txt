FHIR-7513: Audit MedicationStatement dose range support

Issue request:
FHIR-7513 was a Published/Persuasive Pharmacy change request from the DSTU1 cycle asking that MedicationStatement allow a dose range because CDA/CCDA allowed it and it was a valid core use case.

Initial application:
The original application appears in git commit 857c4c94c0ccaf8f6174da0b8540f6d9b387672b, whose subject was "#5940, #7513". That commit changed MedicationStatement.dosage.quantity to MedicationStatement.dosage.quantity[x], changed the type from SimpleQuantity to SimpleQuantity | Range, and updated MedicationStatement examples to use choice element names.

Additional context:
FHIR-5940 is the same change family and states the concrete requirement as allowing MedicationStatement.quantity to be Quantity or Range, for example taking 1-2 tablets. The current R6 source has since been refactored: MedicationStatement.dosage is an active resource element of type DosageDetails, DosageDetails.step.component is Dosage, and Dosage.doseAndRate.dose[x] permits Range | SimpleQuantity | Expression. A current MedicationStatement example includes doseRange. Searches of Zulip and Confluence found no relevant conflicting community record.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed because the active current source already permits MedicationStatement dose ranges through the current DosageDetails/Dosage model.

Recommendation:
Keep this audit commit as-is. No follow-up source change is needed for FHIR-7513 unless a future Pharmacy decision intentionally narrows Dosage.dose[x] or MedicationStatement.dosage.
