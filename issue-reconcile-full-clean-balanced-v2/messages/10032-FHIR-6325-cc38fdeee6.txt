Issue request:
FHIR-6325 was a Published/Persuasive FHIR-core issue asking ElementDefinition.short to stop describing generated XML format and instead define the field as a concise description of what the element means for use in generated summaries.

Initial application:
The Jira comment records application in svn revision 6389, and the migrated git history contains commit 82e3e80ee566f173fc1d4f481e2a75df005c35a6 with subject "#6325 - fix definition of .short". That commit replaced the old generated-XML wording in source/datatypes/elementdefinition.xml with the requested concise-description wording.

Additional context:
ElementDefinition remains an active, normative build artifact in source/fhir.ini, and the current spreadsheet source still defines ElementDefinition.short as a concise description for autogenerated summaries. Later spreadsheet refactoring changed surrounding wording and formatting, including the current unhyphenated "autogenerated", but it did not restore the misleading XML/XHTML implication. Jira, Zulip, and Confluence checks found no later decision or community record that changes this conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change because the current authoritative source already conveys the requested rule and no active current-spec location still contains the obsolete "generated XML format" definition.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-6325 unless a future editorial pass chooses to standardize "auto-generated" versus "autogenerated" across the specification.
