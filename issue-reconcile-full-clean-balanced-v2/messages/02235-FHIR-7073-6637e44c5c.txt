FHIR-7073: Audit Composition title profile history

Issue request:
FHIR-7073 was a Published/Persuasive with Modification DSTU1 Composition issue asking what use case justified omitting composition.title. The approved resolution was to make Composition.title mandatory on the clinical document profile of Composition and solicit feedback during the DSTU period.

Initial application:
The Jira application comment cites svn revision 6196, represented in git as f5b05d7eb96e8e433c728013b8de38250fa2fea2. That commit applied the feedback by changing the then-active Composition spreadsheet row for Composition.title from 0..1 to 1..1, replacing the comment with trial-use mandatory-title wording, and adding title values to Composition examples. It did not create a source change that still needs to be re-applied in the current build.

Additional context:
Current source/fhir.ini still has Composition as an active resource, but the active [profiles] list has no ClinicalDocument profile entry and the old cda profile hook is commented out. source/composition/list-Composition-packs.xml and implementationguide-Composition-core.xml now reference only the Composition core package/catalog profile path, not a ClinicalDocument profile. Later FHIR-34407 removed the ClinicalDocument Composition profile entirely. Later FHIR-32533 made base Composition.author and Composition.title optional, and the combined branch already contains the FHIR-32533 reconciliation that updates the stale title prose to say profiles can require a title when needed. SDWG's 2025-01-30 minutes explicitly record that returning the clinical document profile to 1..1 was not necessary until clinical documents is updated.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The latest combined-branch source already reflects the later decisions: base Composition.title is 0..1 with non-contradictory profile-level guidance, the obsolete trial-use mandatory-title note has been removed, and there is no active core ClinicalDocument profile to constrain. Restoring mandatory title to the base resource or recreating a removed profile would conflict with later applied SDWG decisions.

Recommendation:
Keep this no-change audit. If SDWG creates or updates a ClinicalDocument profile in a future project, title cardinality can be decided there; FHIR-7073 should not be re-applied to the current base Composition resource or to retired profile artifacts.
