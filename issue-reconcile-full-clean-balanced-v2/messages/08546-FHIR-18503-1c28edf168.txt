FHIR-18503: Audit OperationOutcome generated reference punctuation

Issue request:
FHIR-18503 was a Published/Persuasive FHIR Infrastructure change request for OperationOutcome raised against the STU3 ballot. It asked for the auto-generated sentence "This resource is referenced by GuidanceResponse and MessageHeader" to end with a period.

Initial application:
No source commit explicitly tagged FHIR-18503 was found. The contemporaneous OperationOutcome source history shows GF#18500 removed a manual paragraph containing the same GuidanceResponse/MessageHeader reference text, while the issue itself was recorded by FHIR-I as a tooling correction rather than an OperationOutcome source edit.

Additional context:
OperationOutcome is an active build resource in source/fhir.ini. In the current source and current R5/CI rendered pages, the old auto-generated sentence is no longer present; the build now renders a generated "References to this Resource" section with Resource References entries for GuidanceResponse and MessageHeader, and CI also includes the later MeasureReport and extension references. FHIR-I minutes on 2019-12-02 recorded FHIR-18503 as an auto-approved tooling correction, and minutes on 2019-12-09 recorded the Persuasive 7-0-0 motion. Zulip search found no conflicting discussion.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current built specification no longer contains the offending sentence, and changing OperationOutcome narrative source to add duplicate punctuation or duplicate the generated references list would not improve implementer understanding.

Recommendation:
Keep this no-change audit commit. If punctuation policy for generated reference-list bullets is reconsidered, that belongs in the shared publishing/tooling layer rather than in OperationOutcome source.
