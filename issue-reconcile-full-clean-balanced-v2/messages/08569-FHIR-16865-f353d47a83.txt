FHIR-16865: Audit canonical Reference guidance

Issue request:
FHIR-16865 was a Published/Persuasive with Modification STU3 FHIR-I change request asking the References page to allow Reference.reference URLs to use canonical URLs and local canonical-resolution mechanisms, while prohibiting the canonical |[version] suffix in Reference.reference.

Initial application:
The issue was applied in git commit 13e9c9f10c (svn revision 14234), which added references.html guidance that a URL may contain a canonical URL, applications may use supported canonical URL resolution methods, and the |[version] syntax from canonical references is not supported in Reference.reference.

Additional context:
Current source/references.html still contains the applied guidance in the Reference notes and the local-registry resolution sentence. A later Applied issue, FHIR-50120, added a more specific canonical/Reference section saying Reference.reference MAY carry a canonical URL if it resolves, that neither Reference.reference nor Reference.identifier can convey the canonical pipe-version form, and that Reference.identifier can use urn:ietf:rfc:3986 for canonical URLs. FHIR-I Madrid 2025 minutes record the same FHIR-50120 guidance, and no direct FHIR-16865 Confluence reference or conflicting community record was found.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source change is needed because the current build source already documents the exact FHIR-16865 rule and later guidance reinforces rather than reverses it.

Recommendation:
Keep this audit commit as-is. Do not add duplicate wording elsewhere unless a future work-group decision changes canonical URL use in Reference.reference or version-specific canonical syntax.
