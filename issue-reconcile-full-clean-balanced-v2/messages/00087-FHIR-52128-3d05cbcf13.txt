FHIR-52128: Audit Encounter record-linkage extension location

Issue request:
FHIR-52128 was an Applied FHIR-core/Encounter change request, resolved Persuasive with Modification, asking for a new Encounter-scoped record-linkage extension with required other/reference and type/code children. The final PA resolution replaced the earlier plan to reuse Patient link-type terminology with a new encounter-link-type value set and code system containing only replaces and replaced-by, with encounter-specific definitions retained alongside the extension.

Initial application:
No FHIR-core commit mentioning FHIR-52128 was found, and the core checkout contains no encounter-recordLinkage or encounter-link-type source artifact. The applied source change appears in the FHIR Extension Pack instead: commit c5a05d53fe209e32826250ab7b3696e5daf5440f added StructureDefinition-encounter-recordLinkage.xml plus ValueSet/CodeSystem-encounter-link-type.xml under input/definitions/Encounter, and that commit is an ancestor of the current extension-pack master branch.

Additional context:
PA minutes and the linked Zulip thread show that Lloyd McKenzie identified the Patient-specific definitions in the original link-type value set, after which PA reopened FHIR-52128 and approved the new Encounter-specific terminology. The related Encounter $merge tracker, FHIR-44033, remains Resolved - change required rather than Applied/Published; its core implementation exists on origin/FHIR-44033-PA-re-EncounterMerge but is not in current HEAD, so it is context rather than a source-edit target in this reconciliation. FHIR-52940 was checked as a related Extension Pack deprecation discussion; the Zulip evidence says it does not overlap with this new record-linkage extension.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR-core source change. The requested extension and terminology live in the Extension Pack, whose IG includes input/definitions/* as active resource input, while the current core checkout has no active in-build source location for these artifacts. Adding duplicate core definitions would create competing sources of truth.

Recommendation:
Keep this audit commit as-is for the core reconciliation. Any future fixes to the extension definition, value set, or code system should be made in HL7/fhir-extensions, not by adding duplicate artifacts to this FHIR-core checkout; revisit core only when FHIR-44033 or another Applied/Published core tracker requires core Encounter $merge source changes.
