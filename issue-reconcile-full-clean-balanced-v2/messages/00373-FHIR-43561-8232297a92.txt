Issue request:

Initial application:
The core source was initially changed in git commit 2c0399d1c94d627f78c8a68e0acf23676bc8c23d, which removed ResearchSubject.progress from the StructureDefinition, added ResearchSubject.subjectState, and updated the subject_state search parameter. Follow-up commits 50ed600eefce89119af3efe0a68a7671fdcc71c7 and 1ed7e77c0481072079ec5ba383d43d654a0bcf61 corrected the subjectState.startDate cardinality and binding strength. The current source already has the backbone element, but the checked-in examples still used the removed progress wrapper.

Additional context:
The BR&R ResearchSubject Resource page says the new subjectState and subjectMilestone backbone elements replace the R5 Progress backbone. FHIR-44837 later added subjectMilestone and is already represented on the combined branch, so this reconciliation does not publish a duplicate FHIR-44837 decision. Later Applied issues such as FHIR-49254 changed subjectState.code to an example binding, and unresolved UP-585 remains a UTG/THO terminology proposal rather than a core source edit.

AutoFHIR reconciliation:
This commit updates the active ResearchSubject examples to use the current subjectState and subjectMilestone elements instead of the removed progress backbone. The crossover example listed in list-ResearchSubject-examples.xml now records its on-study state as ResearchSubject.subjectState.code/startDate/reason, and the standard ResearchSubject example now records the on-study state and two milestones with the current element names and order.

Recommendation:
Keep this commit as-is. It fixes a stale built example surface left behind by the FHIR-43561 application while preserving later BR&R decisions and leaving the unresolved THO terminology proposal to its external workflow.
