FHIR-16358: Audit removed CodeSystem match operation exact text

Issue request:
FHIR-16358 was a Published/Persuasive STU3 vocab clarification for the CodeSystem $compose/$find-matches operation. It asked for the exact input parameter to explicitly distinguish machine use, which should return only complete and partial matches, from human use, which can also return possible matches, and to state the default.

Initial application:
The Jira comment records svn revision 14664, and git commit 1709669f6e8cac1c0a4e74655049d57d1d820468 maps that revision to a CodeSystem spreadsheet edit. That commit updated the exact parameter documentation to say human is false, machine is true, machine results exclude possible matches, and the default is false. The old top-level operation description sentence appears to have survived the 2021 source split into operationdefinition-CodeSystem-find-matches.xml, so the historical application was not a literal full application of every requested sentence.

Additional context:
CodeSystem remains an active resource in source/fhir.ini, but current source/codesystem/list-CodeSystem-operations.xml lists only CodeSystem-lookup, CodeSystem-validate-code, and CodeSystem-subsumes. Commit 40306e5cd9c1b1e3eb6f115de16a8da3aa13a351 removed operationdefinition-CodeSystem-find-matches.xml and its operation-list entry as part of the R6 terminology infrastructure cleanup. Current source no longer contains the affected operation description or exact parameter documentation; only orphan example request/response text files remain and they are not referenced by the active CodeSystem operation list.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build no longer publishes the CodeSystem operation text that FHIR-16358 targeted, so editing the removed operation or orphan examples would not improve the current specification.
