FHIR-8881: Audit transaction request requirement

Issue request:
FHIR-8881 was a Published/Persuasive DSTU1 clarification asking whether Bundle entries in transaction bundles required request details. The issue noted that the Bundle transaction narrative still referred to a non-existent "transaction element" while the HTTP transaction page said each entry carries request details.

Initial application:
The issue was directly applied in git commit 22a3bff18945f8c59c8fd95f939ec87a590a6a1c, which replaced the erroneous Bundle narrative reference to a transaction element with request element and adjusted the HTTP page. Related 2015/2016 cleanup commits for FHIR-8874 and FHIR-8818 also removed "transaction element" wording from the Bundle narrative family.

Additional context:
Later final decisions resolved the remaining optionality question more strongly than the original DSTU2 application. FHIR-14550 made entry.request mandatory for transaction and batch bundles, FHIR-14551 changed the HTTP transaction page from "Each entry carries" to "Each entry SHALL carry" request details, and FHIR-38942 moved redundant SHALL prose into Bundle invariants while preserving the transaction/batch rule. Bundle is an active resource in source/fhir.ini, and the Bundle implementation guide includes the transaction-bundle and batch-bundle profiles.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source already says a transaction or batch entry contains a request element in source/bundle/bundle-notes.xml, states on source/http.html that each entry SHALL carry Bundle.entry.request details, enforces the rule with Bundle invariant bdl-3c using request.method.exists(), and constrains each transaction/batch method slice to Bundle.entry.request min=1. The remaining awkward grammar in the Bundle narrative does not alter the requirement and is not a necessary semantic fix for FHIR-8881.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-8881; any future grammar cleanup of the Bundle narrative should be handled as a separate editorial issue rather than as required reconciliation for this tracker.
