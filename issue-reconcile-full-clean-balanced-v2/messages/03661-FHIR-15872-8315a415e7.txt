FHIR-15872: Audit ActivityDefinition.kind binding

Issue request:
FHIR-15872 was a Published CDS change request, resolved Persuasive with Modification, asking that ActivityDefinition.kind no longer bind to all resource types and instead be limited to request and event resource types. The resolution also called for a note explaining why decision support use cases need request resources so provider/user interaction can be part of clinical reasoning results.

Initial application:
The issue was applied in SVN 14275, represented in git as 3c199cb8638fa383fa2b344eb2840db4361d49b5. That commit changed ActivityDefinitionKind in source/activitydefinition/activitydefinition-spreadsheet.xml from http://hl7.org/fhir/ValueSet/resource-types to http://hl7.org/fhir/ValueSet/request-resource-types and added source/terminologies/valueset-event-or-request-resource-types.xml, even though the commit subject said Event and Request resources.

Additional context:
The current build-scope ActivityDefinition source is active in source/fhir.ini and now lives in source/activitydefinition/structuredefinition-ActivityDefinition.xml. It binds ActivityDefinition.kind, with required strength, to http://hl7.org/fhir/ValueSet/request-resource-types and its comment says kind may only specify Request resource types. Later Published issue FHIR-29209 clarified how clinical reasoning should generate event resources: use Task with focus set to the event resource. Commit 5126624496f45455a6dbaf65bfc5c7d44f4f367e applied that guidance to ActivityDefinition.kind, and FHIR Workflow minutes record the same Task-based expectation. FHIR-29209 is already represented on the combined branch, so this audit does not decide it again.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source is no longer too loose: it is stricter than the literal seed resolution and matches the later approved Task-based event-resource guidance. Changing ActivityDefinition.kind to the event-or-request value set would reintroduce event resources contrary to the later FHIR-29209 decision.

Recommendation:
Keep this no-change audit as-is. No follow-up is needed in core unless the CDS work group reopens the later request-only policy for ActivityDefinition.kind.
