FHIR-15669: Audit Questionnaire scored answers

Issue request:
FHIR-15669 was a Published/Persuasive with Modification FHIR-core Questionnaire change request raised for STU3. It asked for support for scored answers, including answer-specific score values for instruments such as PHQ-9 and a way to display a calculated total score. The final resolution was to use the existing ordinalValue extension on Questionnaire item options, add an Expression-based calculated-answer extension aligned with CQI, and add an example showing the approach.

Initial application:
Jira comments say the issue was implemented using the Boston approach in SVN #14772. In git, that application is b8c5990ac5ad735ba1e8e836fd8a4c6fd3534a3e, whose subject explicitly names FHIR-15669 among the Questionnaire and QuestionnaireResponse changes. The same historical application carried the then-current Questionnaire math guidance, ordinal scoring-extension approach, and PHQ-9/calculated-value example material into core, alongside the companion calculated-values issue FHIR-15674.

Additional context:
Later final decisions refined the original STU3 representation without reversing it. FHIR-16243 broadened scoring beyond coded answers and has already landed on the combined branch as a source fix that says itemWeight applies to Questionnaire.item.answerOption, including non-code option values. FHIR-24672 renamed ordinalValue to itemWeight and has already landed on the combined branch as a targeted cleanup. The active itemWeight and retired ordinalValue definitions now live in the FHIR Extension Pack, with itemWeight context for Questionnaire.item.answerOption and ordinalValue pointing to itemWeight. The calculated-answer machinery is now owned by SDC: the companion FHIR-15674 has already landed as a no-change audit, and the published SDC IG defines sdc-questionnaire-calculatedExpression with value[x] constrained to Expression and behavior guidance combining itemWeight with calculatedExpression for scores.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Questionnaire is active in source/fhir.ini, and its current notes already point advanced dynamic questionnaires including calculated scores to SDC, explain itemWeight on Questionnaire.item.answerOption for inline answer choices, and link dynamic element values to expression guidance. Current core source has no remaining exact ordinalValue/StructureDefinition/ordinalValue/ordinal-value references, and the authoritative extension/calculation definitions are in the Extension Pack and SDC rather than core.

Recommendation:
Keep this no-change audit commit. The seed's current core-build obligations are satisfied by the existing itemWeight wording, the Extension Pack extension definitions, and SDC calculatedExpression guidance. Future changes to itemWeight contexts should be made in the FHIR Extension Pack, and future calculated-score behavior or examples should be made in SDC unless FHIR-I explicitly moves that material back into core.
