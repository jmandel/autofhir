FHIR-23920: Audit medicinal product ingredient simplification

Issue request:
FHIR-23920 is a Published/Persuasive with Modification BR&R change request for R5 asking how to express ingredients for a simple single-part MedicinalProductDefinition without being forced through PackagedProductDefinition and ManufacturedItemDefinition details such as package type, package quantity, and manufactured dose form. The Jira resolution said this had been improved, and the comments record the intended simplification as adding MedicinalProductDefinition.ingredient so simple cases can bypass the intermediate levels.

Initial application:
No prior source commit explicitly tagged FHIR-23920 was found. Current source nevertheless contains the relevant simplification: MedicinalProductDefinition.ingredient is an active 0..* element, and the current examples include a simple MedicinalProductDefinition with inline ingredient codes. Git history shows the element was present in the medication-definition resource rework and later refined by related R5 medication-definition changes rather than by an issue-tagged FHIR-23920 commit.

Additional context:
MedicinalProductDefinition and Ingredient are active BR&R resources in source/fhir.ini. Related Published issues explain why the current representation no longer exactly matches the early Jira comment's direct-link wording: FHIR-28584 first changed medication-definition ingredient references to CodeableReference for simple code-or-resource use, and FHIR-31808 later reversed Ingredient link direction so Ingredient.for references MedicinalProductDefinition, AdministrableProductDefinition, and ManufacturedItemDefinition while MedicinalProductDefinition.ingredient remains a direct CodeableConcept shortcut for simple cases. FHIR-26989 is background for the original concern about mandatory manufactured-dose-form details and is already separately represented on the combined branch.

AutoFHIR reconciliation:
Made no source change. The current build-scope source already lets implementers express simple product ingredients directly on MedicinalProductDefinition as codes, or use Ingredient.for to associate full Ingredient resources with the product when more detail is needed. Reintroducing a MedicinalProductDefinition -> Ingredient reference would conflict with the later Published FHIR-31808 link-direction decision.

Recommendation:
Keep this empty audit commit as-is. No further core FHIR source change is recommended for FHIR-23920; any future change to restore a direct Ingredient reference would require a new BR&R decision because it would reverse later published modeling work.
