FHIR-12699: Audit Consent STU3 warning fixes

Issue request:
FHIR-12699 was a Published / Persuasive with Modification Consent change request from the DSTU2/STU3 quality-bar work. It asked to add a Consent.category example, reorder Consent elements to match W5, rename the reserved Consent search parameter named "security" to a security-label-style name, define the old cat1 consent category code as "Advanced Directive example codes around medical treatment consent", and rename the duplicate ConsentStatus value set.

Initial application:
The issue appears to have been applied in the January 2017 Consent update commit 612068c15886b6624c44de5d656417bcfa7d76d3, whose subject explicitly includes GF#12699. That commit added a Consent.category example, added the cat1 definition, moved Consent elements/search rows, and changed the search parameter from security to securitylabel in the then-current spreadsheet source.

Additional context:
Consent is active in the current build through source/fhir.ini. The current R6 source no longer has the DSTU2/STU3 spreadsheet shape, but the relevant semantics are present: Consent.category remains near the top of the resource and is used in examples, the status terminology is named Consent State rather than the duplicate ConsentStatus name, the Consent category code system content was intentionally removed from core during the UTG/THO migration, and the current external THO code system supplies defined consent category codes. The one apparent mismatch with the 2017 resolution is intentional later history: Published issue FHIR-17154 and commit 7c8a912aeb6ff6bb22b167c37089bf18b5005a1c renamed securitylabel to security-label according to FHIR search parameter naming conventions.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Reintroducing the old securityLabel/securitylabel spelling or the removed cat1 core CodeSystem content would make the current specification less correct, and the current Consent source already satisfies the applied warning cleanup in its modern model.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed for FHIR-12699; any future change to consent category terminology should be handled in THO/UTG rather than by restoring old core CodeSystem source.
