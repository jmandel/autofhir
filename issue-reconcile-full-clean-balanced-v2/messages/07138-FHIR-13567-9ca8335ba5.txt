FHIR-13567: Audit DiagnosticReport bundle conversion

Issue request:
FHIR-13567 is a Published/Persuasive FHIR-core DiagnosticReport issue from STU3. It asked to remove the contained Observation resources from the DiagnosticReport "General Lab Report Example" because the observations were self-sufficient, and to convert that example to a Bundle containing the DiagnosticReport and observations.

Initial application:
The issue was applied in git commit f7d9c48a8951907066e89d5f7d32783d70eb37db, "GF#13567 change contained resource examples to bundles." Before that commit, source/diagnosticreport/diagnosticreport-example.xml contained many contained observations and local #r1-style result references; after it, the same source became a collection Bundle with separate Observation entries and normal Observation/r1-style references.

Additional context:
DiagnosticReport remains an active core resource in source/fhir.ini, so source/diagnosticreport/diagnosticreport-example.xml is in current build scope. The current example list still names the targeted "General Laboratory Report Example" as diagnosticreport-example. A Jira neighborhood search found the older broader FHIR-3342 example-style concern and unrelated/non-core issues, but no later final core issue that reverses or broadens FHIR-13567 for this seed. Direct Zulip and Confluence searches for FHIR-13567 found no conflicting community record.

AutoFHIR reconciliation:
This audit made no source change. The current source/diagnosticreport/diagnosticreport-example.xml is already a Bundle/101 collection with a DiagnosticReport entry and separate Observation entries, and it no longer has contained resources or local contained-resource references for the targeted general lab report example.

Recommendation:
Keep this no-change audit as-is. Any future cleanup of other DiagnosticReport examples that still use contained resources should be handled under a separate, specific Jira decision rather than by reopening this already-applied general lab report example issue.
