FHIR-12647: Audit CareTeam onBehalfOf application

Issue request:
FHIR-12647 was a Published/Persuasive with Modification Patient Care issue raised against DSTU2 CareTeam. It requested adding CareTeam.participant.practitionerOrganization as Reference(Organization) plus an invariant allowing it only when CareTeam.participant.member is a Practitioner; the approved modification renamed the element to onBehalfOf.

Initial application:
The request was applied in two 2017 source commits. Commit fd96fa1d8151 added CareTeam.participant.onBehalfOf as Reference(Organization) with the original practitioner-organization wording. Commit 9beeccb22219 then added the CareTeam.participant invariant after FHIR-12707/FHIRPath engine work unblocked validation of the CareTeam example.

Additional context:
CareTeam is active in source/fhir.ini, so source/careteam/structuredefinition-CareTeam.xml is current build input. Later final Patient Care decisions intentionally changed the original semantics: FHIR-29730 kept onBehalfOf but documented that it should not remain limited to Practitioner/Organization use cases, and FHIR-42928 was Applied to broaden the onBehalfOf reference targets, update its definition, and remove the original ctm-1 invariant. Later applied issues FHIR-48432 and FHIR-51595 further added Group and HealthcareService as valid member/onBehalfOf targets. The checked-in CareTeam SVG still contains an old hover title, but that is a generated-looking diagram artifact and the authoritative StructureDefinition source carries the current semantics.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current StructureDefinition has CareTeam.participant.onBehalfOf, uses the broader proxy/agent/representative definition, includes Organization plus the later approved target profiles, and has the original ctm-1 invariant commented out rather than active. Reinstating the original practitioner-only invariant or narrowing onBehalfOf back to Organization would conflict with later final decisions.

Recommendation:
Keep this no-change audit commit for FHIR-12647. No core source follow-up is needed for the seed issue; any future cleanup of generated diagram text should be handled under the later onBehalfOf broadening issues or build tooling rather than by reverting this seed's later superseded semantics.
