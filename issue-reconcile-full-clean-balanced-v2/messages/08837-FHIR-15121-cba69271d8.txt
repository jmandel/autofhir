FHIR-15121: Correct missing-meaning invariant XPath

Issue request:
FHIR-15121 was a Published/Persuasive FHIR-core StructureDefinition grouper for defaults and meaningWhenMissing. The final decision removed defaultValue[x] from FHIR resources while retaining it for logical models, required invariant enforcement, clarified that missing means no value including extension-only elements, prevented profiles from changing missing-element interpretation, discouraged trivial meaningWhenMissing guidance, and requested Missing Elements/search examples updates.

Initial application:
The Jira comments record application as SVN revision 14226. In this Git history that is git-svn commit 7ac081b0b845064c90c4a9038178aa64a80e5790, which cites GF#15121 and updates the ElementDefinition missing-elements/defaultValue narrative plus the conformance-rule link. Later source history, including 652ee3df4866d4910bf9d0573677f5a5183cea45, carries the explicit search wording that extension-only elements with no value count as :missing.

Additional context:
FHIR-I WGM minutes page 40743490 records the same motion and execution details. Current source/fhir.ini actively includes ElementDefinition as a datatype and StructureDefinition as a resource, so source/datatypes/elementdefinition.xml, source/elementdefinition.html, source/search.html, and source/structuredefinition/structuredefinition-StructureDefinition.xml are build-scope source. Related default/missing issues FHIR-3527 and FHIR-16992 are already represented on the combined branch and helped confirm the broader policy, but they were not republished here.

AutoFHIR reconciliation:
This commit fixes the one current source defect found during reconciliation. The ElementDefinition invariant row says "default value and meaningWhenMissing are mutually exclusive" and its FHIRPath is defaultValue.empty() or meaningWhenMissing.empty(), but the XPath cell still tested fixed[x] instead of defaultValue[x]. The XPath now tests defaultValue[x], aligning all forms of the invariant. No broader narrative or meaningWhenMissing cleanup was made because the current build-scope source already conveys missing-as-no-value, search :missing behavior, profile immutability of missing meaning, and logical-model-only defaultValue use; individual trivial meaningWhenMissing entries are at most authoring-review candidates, not a necessary bulk source fix for this seed.

Recommendation:
Keep this source fix. Future work group review could separately audit individual meaningWhenMissing entries that merely restate unknownness, but the core FHIR-15121 policy and invariant now align in the current source.
