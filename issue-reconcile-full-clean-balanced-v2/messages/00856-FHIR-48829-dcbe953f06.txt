FHIR-48829: Audit ProvenanceRelevantHistory retention

Issue request:
FHIR-48829 was Applied/Persuasive with Modification for the FHIR-core profile list. The issue asked whether the ProvenanceRelevantHistory profile should move out of core; the accepted resolution was to retain it in core after Request/Event relevantHistory references were updated to point specifically to the profile.

Initial application:
The issue was applied upstream by commit 88c811462a204b33b86bbf1cf5d994b3dd3c0bab, which changed the active Request and Event pattern spreadsheets from Reference(Provenance) to Reference(Provenance{http://hl7.org/fhir/StructureDefinition/provenance-relevant-history}) and added mapping exceptions for resources whose concrete elements still expose Reference(Provenance). No Issue-Reconcile-Key audit commit for FHIR-48829 was present on the combined branch before this reconciliation.

Additional context:
The FMG Zulip profile-review thread shows this was part of the core-profile governance review and records John Moehrke's clarification that ProvenanceRelevantHistory supports the FHIR-I workflow/request pattern rather than Security ownership. FHIR-I minutes on 2025-03-10 record the FHIR-48829 Persuasive with Modification vote. source/fhir.ini actively includes the request and event workflow pattern inputs, the relevant concrete resources, and provenance=Provenance; source/provenance/structuredefinition-profile-provenance-relevant-history.xml and source/provenance/implementationguide-Provenance-core.xml keep the profile in core under the FHIR-I work group. Later Provenance work such as FHIR-53917 updated removal semantics in the same profile but did not move it out of core or reverse the profile-reference decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already reflects the applied decision by retaining the profile in core and by using the profile-specific canonical reference in the Request and Event pattern sources that drive the relevantHistory guidance.

Recommendation:
Keep this audit commit as-is. A future stricter conformance change that makes every concrete relevantHistory/eventHistory element target only the profile would need a separate work-group decision because the current profile is guidance-oriented and the existing source pattern records the profile reference while concrete resource definitions continue to use base Provenance references with SHOULD-level guidance.
