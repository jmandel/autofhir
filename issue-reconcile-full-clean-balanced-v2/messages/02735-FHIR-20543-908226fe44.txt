FHIR-20543: Audit MedicationAdministration instantiates rename

Issue request:
FHIR-20543 was a Published/Persuasive with Modification Pharmacy change request raised against STU3 and applied for R5. It asked to align MedicationAdministration.instantiates with Workflow by renaming the URI-valued element to MedicationAdministration.instantiatesUri and also supporting a canonical-valued element for PlanDefinition or ActivityDefinition references.

Initial application:
The issue was applied in the April 2019 Pharmacy changes. Commit 8c0d5b260da748e6818ba978ed1c699bd7eeb039, merged by a6310682f5c644b348e380c5c295e4af8ca49574, changed the MedicationAdministration spreadsheet from MedicationAdministration.instantiates: uri to MedicationAdministration.instantiatesCanonical: canonical(PlanDefinition | ActivityDefinition) and added MedicationAdministration.instantiatesUri: uri. The source rework commit 33b409a4b6e1c7c5895c075a3488021213bf07ab later carried those split elements into structuredefinition-MedicationAdministration.xml.

Additional context:
Later Published/Persuasive Pharmacy issue FHIR-24100 reviewed Pharmacy resources against Workflow. Its Jira application comment says the instantiates attributes were removed in both MedicationRequest and MedicationAdministration, and commit ece63351c6107ee2d837bd8bdc64871ad186dc4c removed MedicationAdministration.instantiatesCanonical, MedicationAdministration.instantiatesUri, and example instantiatesUri content. The current build configuration actively includes MedicationAdministration, while the R4-to-R5 map records MedicationAdministration.instantiates as removed. The current MedicationAdministration StructureDefinition proceeds from identifier to basedOn with no instantiates elements, and exact source searches found no MedicationAdministration instantiatesCanonical or instantiatesUri definitions. The combined branch already contains an audit commit for FHIR-24100, so that related later decision is not republished here.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edit is needed for FHIR-20543 because the requested split-name application happened historically and re-adding those elements now would undo the later published Pharmacy/Workflow removal decision.

Recommendation:
Keep this audit commit as-is. If Pharmacy wants MedicationAdministration to express adherence to protocols again, open a new current Workflow-aligned issue rather than restoring the obsolete R5 instantiates elements from FHIR-20543.
