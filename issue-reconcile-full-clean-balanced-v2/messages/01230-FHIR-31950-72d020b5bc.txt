FHIR-31950: Audit MedicationStatement adherence move

Issue request:
FHIR-31950 was a Published Pharmacy change request with resolution Persuasive with Modification. It asked to move MedicationUsage.statusReason under adherence, and the final resolution specified changing adherence to a 0..1 backbone with adherence.code 1..1 and adherence.reason 0..1.

Initial application:
The issue appears to have been applied by git commit 934e7819020c72ee6e3ba509ecb5445a1850f109, whose message includes 31950. That commit removed MedicationUsage.statusReason from source/medicationusage/structuredefinition-MedicationUsage.xml, changed MedicationUsage.adherence from a direct CodeableConcept into a BackboneElement, added MedicationUsage.adherence.code, added MedicationUsage.adherence.reason bound to reason-medication-status-codes, and updated an example to carry the not-taking reason inside adherence.reason.

Additional context:
FHIR-38682 later renamed MedicationUsage back to MedicationStatement while keeping the adherence/status changes, so the current active resource is MedicationStatement rather than MedicationUsage. source/fhir.ini lists medicationstatement as an active resource and marks MedicationStatement approved. A later FHIR-32858 reconciliation on the combined branch clarified MedicationStatement.adherence.reason wording, reinforcing that adherence.reason is the current slot for use, non-use, stopped use, or taking differently than directed.

AutoFHIR reconciliation:
This audit commit makes no source change because the current build source already has MedicationStatement.adherence as a 0..1 BackboneElement with MedicationStatement.adherence.code 1..1 and MedicationStatement.adherence.reason 0..1, and the old MedicationStatement.statusReason element is absent from the active MedicationStatement StructureDefinition. The only remaining source/fhir.ini mention of MedicationStatement.statusReason is an R4-to-current change-map entry, not a current resource element.

Recommendation:
Keep this no-change audit commit. FHIR-31950 is already represented in the current specification, and changing source now would either duplicate the existing adherence.reason model or reintroduce obsolete MedicationUsage/statusReason terminology.
