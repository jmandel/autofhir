FHIR-5192: Audit HealthcareService serviceProvisionCode

Issue request:
FHIR-5192 was a Published/Persuasive with Modification DSTU1 HealthcareService ballot comment. It asked to remove the misleading "free" framing from the old free provision code, rename the property to ServiceProvisionCode, change cardinality from 0..1 to 0..*, and describe the codes as conditions under which a healthcare service is available/offered, including commissioning, contractual, financial, free, discounted, or fee-related conditions.

Initial application:
The issue was applied in the historical HealthcareService spreadsheet source by 8fb7336ca5, "Tracker 4003, 5192 Final PA Ballot reconciliation changes," which changed HealthcareService.freeProvisionCode to HealthcareService.serviceProvisionCode, changed 0..1 to 0..*, and replaced the old free-provision description with the requested service-provision wording. The neighboring e7cc9ca414 introduction commit also mentioned FHIR-5192 but did not change the serviceProvisionCode element itself.

Additional context:
HealthcareService is an active current-build resource in source/fhir.ini. The current XML StructureDefinition source now carries the spreadsheet-era application forward as HealthcareService.serviceProvisionCode with max="*", the requested description and comment, and a ServiceProvisionConditions value set. Current source searches found no remaining freeProvisionCode element or old "free provision" definition. Later FHIR-41782 briefly considered using ServiceProvisionCode for referral requirements but chose a separate referralRequired element and eligibility refinements, which does not alter the FHIR-5192 service-provision decision. Zulip and Confluence searches found no direct FHIR-5192 community record or conflicting evidence.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative current source already preserves the semantic changes requested by FHIR-5192, and changing wording now would be redundant rather than corrective.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-5192 unless a future PA decision reopens the meaning or binding of HealthcareService.serviceProvisionCode.
