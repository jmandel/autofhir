FHIR-19368: Align Device modelinfo biological source

Issue request:
FHIR-19368 was a Published/Persuasive with Modification FHIR-core Device change request raised against STU3. The original description objected that Device.distinctIdentificationCode used string for a code-like concept, but the final approved resolution did not adopt CodeableConcept; it renamed the element to distinctIdentifier, kept it as a distinct identification string for HCT/P products, added the CFR 21 1271.290(c) example comment, and preserved the DIC alias.

Initial application:
The issue was applied in git commit 642c6442c4bf6618399594ca6015fd06f5936e62, which changed the then-authoritative Device spreadsheet from Device.distinctIdentificationCode to Device.distinctIdentifier, updated the definition/comment, and added the Distinct Identification Code alias. Later source rework moved Device to structuredefinition-Device.xml. The current authoritative Device source is active in source/fhir.ini and no longer has Device.distinctIdentifier, but the current Library FHIR ModelInfo example still exposed Device.distinctIdentifier as FHIR.string.

Additional context:
FHIR-19594 removed the redundant device DIN extension after distinctIdentifier was added. Later Published/Applied Device decisions changed the current shape: FHIR-34346 renamed Device.distinctIdentifier to Device.biologicalSource and changed the type to Identifier, FHIR-37199 renamed that element to Device.biologicalSourceEvent with updated traceability wording, and FHIR-22834 updated the Device UDI mapping to carry the 21 CFR/DIN meaning on biologicalSourceEvent. The Library examples list registers Library/FHIR-ModelInfo and the examples header links library-fhir-model-definition-content.xml as the FHIR model information file, so the stale modelinfo property is part of the current build surface even though broader Device modelinfo drift remains outside this seed.

AutoFHIR reconciliation:
This commit changes only source/library/library-fhir-model-definition-content.xml so the Device modelinfo property follows the current Device element lineage: Device.distinctIdentifier as FHIR.string is replaced by Device.biologicalSourceEvent as FHIR.Identifier. The authoritative Device StructureDefinition already has the DIC alias, current traceability definition/comment, and UDI mapping, so no Device resource source change was needed.

Recommendation:
Keep this targeted fix. It reconciles the remaining current-build surface for the seed element without reopening the later OO decisions. Broader modelinfo alignment should be handled as separate modelinfo maintenance, not by expanding this tracker beyond its Device distinct-identification lineage.
