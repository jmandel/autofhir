FHIR-16488: Audit purchase date guidance

Issue request:
FHIR-16488 was a Published OO change request asking for a generic purchaseDate extension for Device, Substance, Medication, and similar product instances. The final Persuasive with Modification resolution did not approve an HL7 purchaseDate extension; it directed clarification that the relevant purchase date is determined by the implementation guide context from request, dispense, or delivery resources, with only local extension use when an IG needs to copy a date.

Initial application:
The issue was applied before this reconciliation by bdf574e8931079285aa19c384dffd461c167a650 and merged by HL7/fhir#2183 as ea07a990e2. That application added purchase-date guidance to the Boundaries and Relationships sections for DeviceRequest, SupplyRequest, DeviceDispense, and SupplyDelivery. Later edits moved or touched adjacent wording but retained the FHIR-16488 guidance.

Additional context:
The current build scope in source/fhir.ini actively includes DeviceRequest, Device, Medication, and Substance, while SupplyRequest, DeviceDispense, and SupplyDelivery are not active resources in the current build. The active DeviceRequest introduction still says that a search of DeviceRequest, SupplyRequest, DeviceDispense, or SupplyDelivery as defined in an implementation guide can determine the purchase date. Device, Medication, and Substance do not define a purchaseDate or purchaseHistory extension, matching the WG decision that there is no HL7 extension yet. Confluence minutes from 2021-01-04 record the same rationale, including that purchase date is not per se on Device and that any extension should remain local for specific use cases.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already communicates the approved rule, and editing out-of-build SupplyRequest, DeviceDispense, or SupplyDelivery pages or adding an HL7 extension would contradict the Jira disposition and current build-scope guardrails.

Recommendation:
Keep this audit commit as-is. If a future implementation guide can define a reusable purchase-date or purchase-history pattern, open a new tracker for an HL7 extension or extension-pack artifact with that concrete scope; do not add a core extension from FHIR-16488 alone.
