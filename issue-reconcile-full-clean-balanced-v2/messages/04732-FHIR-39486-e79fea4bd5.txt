FHIR-39486: Audit FML log trace equivalence

Issue request:
FHIR-39486 was a Published FHIR-core StructureMap change request asking to rename the FHIR Mapping Language log() statement to trace() for consistency with FHIRPath, because FHIRPath uses log() for mathematics. The final Not Persuasive with Modification resolution rejected the breaking rename and instead required documentation that FML log serves the same purpose as FHIRPath trace().

Initial application:
The issue was applied by git commit 4e43df4bce0cc1671cba2bee864a7f21654e8f82, which added a paragraph to source/mapping-language.html stating that the log statement is equivalent to the FHIRPath trace() function and that output usually ends up in the same place. The current source still contains that paragraph.

Additional context:
source/hierarchy.xml lists mapping-language.html as an active Implementation Support page, source/fhir.ini lists StructureMap as an active resource owned by FHIR-I, and source/structuremap/structuremap-introduction.xml links StructureMap readers to the mapping-language page for the concrete syntax. The ANTLR grammar in images/mapping.g4 still uses the log keyword, which is expected because the approved resolution intentionally avoided the breaking rename. FHIR-I minutes on 2023-01-30 record the Not Persuasive with Modification vote, and the Zulip FHIR Mapping Languages thread shows the issue arose from the same consistency question without adding a later conflicting decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active FML documentation already satisfies the approved resolution by retaining log() while documenting its equivalence to FHIRPath trace().

Recommendation:
Keep this empty audit commit as-is. Do not rename the grammar or examples from log() to trace() without a new work-group decision, because FHIR-39486 explicitly found that the consistency gain was not worth the breaking change.
