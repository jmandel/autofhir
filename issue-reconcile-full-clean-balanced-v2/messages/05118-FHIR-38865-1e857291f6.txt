Issue request:
FHIR-38865 was Published with resolution Persuasive with Modification for R5. It agreed with removal of DocumentManifest in favor of other resources, with the final OO motion to remove DocumentManifest.

Initial application:
The removal was applied by the DocumentManifest deletion work referenced from Jira via merge commit 1b544b56cdca7da7fb0c6d70ddf641fb763560d5 and source commit ea941737076615e7e2772299c80c63e1490f2e93. Those commits deleted source/documentmanifest and removed DocumentManifest from active fhir.ini resource/workgroup/TLA entries, while retaining intentional removed-resource/history mappings. Current source still had an active resourceguide.html Documents section that named and linked documentmanifest.html as if it were a current resource.

Additional context:
FHIR-33021 established the earlier R5 retirement notice, and community discussion described the normal approach as yanking the resource, documenting it in history, and using other resources such as List for the moved use cases. FHIR-39006 then moved XDS SubmissionSet guidance/examples to List, supporting List as the replacement for grouped document references.

AutoFHIR reconciliation:
This commit updates the built resource guide so it no longer lists or links DocumentManifest. The local Documents guidance now describes DocumentReference for single external documents and List for grouped document references such as an XDS SubmissionSet, while leaving intentional fhir.ini/history/old-type compatibility references untouched.

Recommendation:
Keep this source fix. It removes a current-page stale link to a retired resource and aligns the guide with the applied removal and List replacement decisions; no additional core source cleanup is indicated beyond intentional history and compatibility references.
