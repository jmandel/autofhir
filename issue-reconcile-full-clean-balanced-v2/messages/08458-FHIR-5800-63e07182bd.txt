FHIR-5800: Audit code system URL validation guidance

Issue request:
FHIR-5800 was a Published FHIR-core Vocabulary change request for DSTU1 ValueSet content. It asked whether servers may validate logical code system references on PUT/POST, especially for FHIR-defined code systems, and its Persuasive with Modification resolution requested an explicit note that servers can validate those references plus Shareable ValueSet guidance that servers should validate them.

Initial application:
The issue was applied in git-svn revision 5691, now commit cac052b66cfc5ab1173ee363c0fce9781471f7d9, which added two DSTU1 spreadsheet comments: ValueSet code system references could be validated by terminology servers, and servers supporting the Shareable ValueSet profile were to confirm that the system reference was resolvable. Later history retained the old wording in release history but the active ValueSet spreadsheets were removed during the 2021 source rework that split current CodeSystem and ValueSet StructureDefinitions.

Additional context:
Current core build scope still includes CodeSystem and ValueSet resources and the Shareable logical pattern, but there is no active core ShareableValueSet profile definition to amend. Current CodeSystem.url already says the canonical should be a literal address where an authoritative instance is or will be published; ValueSet.compose.include.system points readers to Coding.system for correct system values; Coding.system requires a URI that identifies the code system clearly and unambiguously; and terminology-service.html says terminology servers should validate incoming resources and ensure terminology-service integrity. FHIR-38833 later directed shareable/publishable profiles toward CRMI for updates and corrections, so reintroducing a DSTU1-specific ShareableValueSet validation sentence in core would not be a safe current-spec fix.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source file was changed because the current active core source already conveys the necessary canonical-url and terminology-server validation expectations, and the profile-specific part of the old request no longer has an active core profile source location.

Recommendation:
Keep this audit commit as-is. Do not add redundant DSTU1 wording to current core; if future work wants profile-specific validation rules for ShareableValueSet, it should be raised against the current owner of that profile/pattern rather than patched here.
