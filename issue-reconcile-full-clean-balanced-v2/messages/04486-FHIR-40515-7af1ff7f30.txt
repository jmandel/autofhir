FHIR-40515: Audit DeviceAssociation operation status

Issue request:
FHIR-40515 was Published/Persuasive for R5. It requested adding DeviceAssociation.operation.status as the first element in the DeviceAssociation.operation backbone, with cardinality 1..1, type CodeableConcept, and an example DeviceAssociationOperationStatus value set containing on, off, standby, defective, and unknown.

Initial application:
The issue was applied by git commit 8532c7f1b5bd (FHIR-40515), which added DeviceAssociation.operation.status to source/deviceassociation/structuredefinition-DeviceAssociation.xml and added the DeviceAssociation operation-status CodeSystem and ValueSet. Follow-up 2023 commits adjusted the terminology files, so the requested R5 addition was represented before this reconciliation.

Additional context:
Later R6 issue FHIR-47604 was Applied/Persuasive with Modification and superseded the R5 shape by removing the DeviceAssociation.operation backbone. Its Jira comments clarify that the entire operation backbone was to be removed, that operation.status and operation.period are covered by base DeviceAssociation elements when relationship is operator, and that operation-status concepts should be carried in the new DeviceAssociation.associationStatus codes. The current active DeviceAssociation source has no DeviceAssociation.operation element, includes associationStatus bound to deviceassociation-association-status, and that code system contains the operational states on, off, standby, and defective. source/fhir.ini records the R5-to-R6 removal of DeviceAssociation.operation.status and the additions of associationStatus, focus, and relationship.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding DeviceAssociation.operation.status would contradict the later applied R6 decision. The remaining DeviceAssociation.operation.status text found during reconciliation is only in the generated-looking SVG diagram and in a ballot note explaining that the operation backbone was collapsed; the authoritative XML source, examples, terminology, and fhir.ini change list already express the current model.

Recommendation:
Keep this empty audit commit as-is. Do not reintroduce DeviceAssociation.operation.status in the current build. If the stale SVG diagram is refreshed, it should be regenerated from authoritative source or handled under the later FHIR-47604 follow-up path rather than as a FHIR-40515 source fix.
