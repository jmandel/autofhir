FHIR-25925: Align ConceptMap group ModelInfo

Issue request:
FHIR-25925 was a Published/Persuasive with Modification R5 vocab change request for ConceptMap. The accepted resolution kept the group.source and group.target element names, changed them from uri to canonical(CodeSystem), and removed group.sourceVersion and group.targetVersion because canonical carries version information.

Initial application:
The ConceptMap StructureDefinition was updated by git commit 3a8665b9c2b5a4af6baca0596216e94e7c03eb37, which changed source/conceptmap/structuredefinition-ConceptMap.xml so ConceptMap.group.source and ConceptMap.group.target are canonical CodeSystem references and removed the separate version elements. The FHIR ModelInfo example/content still listed ConceptMap.Group.source and target as FHIR.uri and still exposed sourceVersion and targetVersion from the older R4-era model.

Additional context:
source/fhir.ini lists ConceptMap as an active resource and approved artifact, and source/library/list-Library-examples.xml plus source/library/library-examples-header.xml expose Library/FHIR-ModelInfo and library-fhir-model-definition-content.xml as the FHIR model information file used by the CQL-to-ELM translator. A direct Zulip discussion matches the Jira resolution: keep source/target names, use canonical(CodeSystem), and remove sourceVersion/targetVersion. FHIR-31375 was raised from the same tracker-call concern about implicit CodeSystem/value set URLs, but it was resolved No Change and does not alter the FHIR-25925 element-shape decision.

AutoFHIR reconciliation:
Updated source/library/library-fhir-model-definition-content.xml so ConceptMap.Group.source and ConceptMap.Group.target are FHIR.canonical and removed ConceptMap.Group.sourceVersion and ConceptMap.Group.targetVersion. Updated the embedded ModelInfo data in source/library/library-fhir-model-definition.xml with the same ConceptMap.Group correction while preserving unrelated existing embedded-data differences.

Recommendation:
Keep this source fix. The core ConceptMap StructureDefinition was already correct, and this commit removes the remaining build-visible stale ModelInfo surface for the same element change; no further core source change is indicated for FHIR-25925.
