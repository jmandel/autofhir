FHIR-11057: Audit Consent recipient rename

Issue request:
FHIR-11057 was Published/Persuasive with Modification for the DSTU2 Consent resource. It asked to remodel and rename the old Consent.recipient element to Consent.actor because the controlled party was not limited to being a recipient; the final resolution says this was adjunct to FHIR-11053 and that Consent.recipient should be removed in favor of Consent.actor.

Initial application:
The rename/removal was applied in commit 612068c158, "Consent Resource STU3 updates for GF#12699, GF#11058, GF#11053, GF#11057, GF#10719, GF#10716, GF#10689, GF#11063, and GF#12699." In that spreadsheet-era source, the parent state contained Consent.recipient and a recipient search parameter, while the applied state marked !Consent.recipient and added Consent.actor / Consent.actor.role / Consent.actor.reference.

Additional context:
Consent is active in the current build through source/fhir.ini. The current XML source contains no Consent.recipient element, path, or exact reference. It also no longer has a top-level Consent.actor because later R5 model work, especially FHIR-31906 and the 2021 grantee/grantor refactor, converted Consent.performer into Consent.grantor and Consent.grantee while keeping computable controlled actors in Consent.provision.actor. Current generic "recipient(s)" wording in the Consent definition traces to the separate Published FHIR-10691 definition issue and does not reintroduce the removed Consent.recipient element. Zulip and Confluence searches found no direct FHIR-11057 discussion that changes this source/history conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source already satisfies the FHIR-11057 decision by omitting Consent.recipient, and the present grantee/provision.actor model reflects later work-group decisions rather than an incomplete application of the 2016 rename.

Recommendation:
Keep this audit commit as-is. Any future desire to replace the remaining general "recipient(s)" definition wording with broader actor language should be considered under a separate Consent definition/model issue, not as a missing FHIR-11057 source fix.
