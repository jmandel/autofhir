FHIR-14195: Audit canonical version search guidance

Issue request:
FHIR-14195 is a Published FHIR-I STU3 change request resolved Persuasive with Modification. It asked that searches on canonical URI values account for an appended business version and that the specification document how the :below modifier is used for canonical searches, including enabling :below for the Reference search type.

Initial application:
The issue was applied in git-svn commit 9fedb176f1b13c7f956feb90cb4ecfe17e84ef36, recorded as SVN revision 14047 and explicitly tagged GF#14195. That commit added canonical-reference :below search examples to source/search.html showing an unversioned canonical search matching all versions and a version-prefix search matching the 1.x versions.

Additional context:
Related Published issue FHIR-16361 moved canonical searches from uri-oriented wording into reference search parameter guidance. Later R6 decisions FHIR-46311 and FHIR-51466 clarified exact default canonical version matching and canonical :above/:below comparison behavior; both are already represented on the combined branch and preserve the core FHIR-14195 rule that hierarchy/prefix version matching is requested through :below. Current source/search.html is the active Search page narrative, and source/references.html is the active canonical-reference narrative cited by the Jira related URL.

AutoFHIR reconciliation:
Made no source change. The current source already states that canonical references use reference search parameters with version syntax, documents :below for reference search parameters targeting canonical elements, and includes examples where questionnaire:below without a version matches all versions while questionnaire:below with |1 matches major version 1 resources. The references page also tells servers to support version-specific canonical URL searching by detecting |[version].

Recommendation:
Keep this audit commit as-is. The seed request is satisfied by current source plus later clarifications, and adding more prose would duplicate existing normative guidance without changing implementer understanding.
