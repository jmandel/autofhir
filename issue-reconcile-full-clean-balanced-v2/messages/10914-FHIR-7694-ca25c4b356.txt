FHIR-7694: Audit profile summary generator fix

Issue request:
FHIR-7694 was a Published/Persuasive DSTU1 Contract-profile issue reporting that the generated ConsentDirective summary said "Mandatory: 9 elements" when only one mandatory element was unconditional; the remaining mandatory elements were nested under optional parents. The accepted resolution was to fix the generated summary wording.

Initial application:
The Jira comment records svn revision 6612. In the git mirror, commit 90b0e1ea29ad61096e4c56065fe5df229732bb0b (#7694 - fix profile summary) implemented that revision by changing the old PageProcessor profile-summary generator to count outright mandatory elements separately from nested mandatory elements, adding the supporting derivation pointer plumbing. The commit did not make the ConsentDirective profile source itself the semantic target of the fix.

Additional context:
The current FHIR source checkout no longer contains the old Java PageProcessor/ProfileUtilities generator code, and no checked-in current source contains the stale "Mandatory: 9" summary text. The legacy source/contract/consentdirective.profile.xml file still exists, but source/fhir.ini has no active [profiles] entry for it and notes that ConsentDirective became Consent; the current build scope is therefore not corrected by editing the old generated summary or the profile differential. A later similar tracker, FHIR-32972, was resolved no-change because the generated summary reflects differential changes rather than every effective mandatory element.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The published issue was already applied historically in generated-summary tooling, and the current core source has no stale built summary text or active source location requiring a correction for FHIR-7694.

Recommendation:
