FHIR-23010: Audit mapping language rule-order wording

Issue request:
FHIR-23010 was Published/Persuasive with Modification for the FHIR mapping language. It asked the Transform Rules section to state that rules may be applied in any order, that order is implementation-defined, and that mappings should avoid order-dependent overlapping rules unless first/last keywords manage ordering.

Initial application:
The Jira-tagged commit 5afb4e3a7322 added the requested rule-order paragraph to source/mapping-language.html. The current source still says rules may be applied in any order, that order is implementation-defined, and that mappings should avoid overlapping-rule dependence or use first/last keywords.

Additional context:
The mapping-language page is in current build navigation through source/hierarchy.xml and source/documentation.html. A February 2023 Zulip application thread cited FHIR-23010 while rejecting a broader FHIR-25220 sentence that dependent groups are executed in order; FHIR-25220 is already represented on the combined branch by an audit commit, so this reconciliation does not duplicate it. Jira and Confluence searches found no later conflicting decision for FHIR-23010.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current build-scope mapping-language source already conveys the required implementation-defined rule-order guidance, and changing placement or wording would not improve implementer understanding.

Recommendation:
Keep this audit commit as-is. Revisit only if FHIR-I opens a new mapping-language ordering decision that explicitly changes the interaction between general rule order, first/last keywords, and dependent group invocation.
