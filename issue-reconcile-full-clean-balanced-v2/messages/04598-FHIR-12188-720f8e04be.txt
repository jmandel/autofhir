FHIR-12188: Audit ProcedureRequest search parameters

Issue request:
FHIR-12188 was a Published/Persuasive DSTU2 Patient Care change request asking to add ProcedureRequest search parameters for code and bodySite, so radiology workflows could find requests such as CT studies of the chest.

Initial application:
The request was applied in historical source by bd9f60dbff, which explicitly mentions #12188 and added ProcedureRequest search parameters named code and body-site to source/procedurerequest/procedurerequest-spreadsheet.xml and its sheet text. No additional source-changing application is needed for the original ProcedureRequest artifact.

Additional context:
ProcedureRequest is no longer an active resource in the current build: fhir.ini lists ServiceRequest as active and records ProcedureRequest as merged into ServiceRequest. FHIR-13867 renamed ProcedureRequest to ServiceRequest. Later final ServiceRequest changes changed the relevant model: FHIR-33075 changed ServiceRequest.code from CodeableConcept to CodeableReference(ActivityDefinition|PlanDefinition), reflected now by code-concept and code-reference search parameters, and FHIR-53203 replaced bodySite/body-site usage on OO resources with bodyStructure as a CodeableReference, reflected now by body-structure-code and body-structure-reference search parameters. The deprecated body-site search parameter was intentionally removed after that later change.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped ServiceRequest source already preserves the implementer capability requested by FHIR-12188 through the current R6 model: token search on ServiceRequest.code.concept and ServiceRequest.bodyStructure.concept, with reference companions for the CodeableReference/reference halves. Reintroducing ProcedureRequest, bodySite, body-site, or a simple ServiceRequest code search parameter would contradict later final modeling decisions rather than complete FHIR-12188.

Recommendation:
Keep this audit commit as-is. If a future work group wants compatibility aliases such as ServiceRequest?code= or ServiceRequest?body-site= in R6, that should be raised as a new ServiceRequest search-parameter compatibility decision because FHIR-12188 itself was already applied and later superseded by model changes.
