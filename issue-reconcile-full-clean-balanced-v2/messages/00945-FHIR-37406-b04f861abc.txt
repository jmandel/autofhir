FHIR-37406: Audit code datatype regex display correction

Issue request:
FHIR-37406 was a Published/Persuasive MnM change request for R5 asking to change the code datatype regex display to `[^\s]+( [^\s]+)*` because the old `\s` occurrence allowed tabs, carriage returns, line feeds, and other whitespace contrary to the datatype prose.

Initial application:
The issue appears to have been applied by git commit 92efc0e06b73601ad153b28144664fd95a3aa741, which changed the literal regex in `source/datatypes.html` from `[^\s]+(\s[^\s]+)*` to `[^\s]+( [^\s]+)*`. A prior FHIR-25413 implementation commit, c4807a5165ee632872ef9f6289fee8e9e1abbb5f, had already made the same correction in `source/datatypes/primitives.xml`.

Additional context:
Current `source/datatypes.html` no longer carries a literal regex for code; it uses `[%regex code%]`, while `source/datatypes/primitives.xml` carries the authoritative corrected regex. Active datatype routing in `source/fhir.ini` confirms this page/source family remains in the current build. FHIR-6181 is older background showing the code regex had already been tightened in DSTU1, but the R5-relevant stale `\s` display was resolved by the FHIR-25413/FHIR-37406 sequence.

AutoFHIR reconciliation:
This empty audit commit records that current source already implements the FHIR-37406 decision.
