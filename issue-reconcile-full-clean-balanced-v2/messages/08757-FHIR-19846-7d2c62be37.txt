FHIR-19846: Audit Device maintenance organization extension location

Issue request:
FHIR-19846 was an Applied OO change request from STU3 asking to support CDA `asMaintainedEntity` in FHIR by adding a Device HL7 extension for the maintenance organization. The final Persuasive with Modification resolution approved no core Device resource element and instead approved an extension family: `maintenanceResponsibility` with person and organization subparts plus `lastMaintenanceTime`.

Initial application:
No Jira-tagged FHIR core source commit for FHIR-19846 was found, which is consistent with the Jira comment saying there should be no core resource change. The applied source change appears in the FHIR Extension Pack: commit 0737edd33c8c1665e7cb5e2eae08e54896850e24 added `device-maintenanceresponsibility` and `device-lastmaintenancetime` for FHIR-19846, FHIR-19847, and FHIR-19848. Core retains only OID registry entries for those extension URLs, added by bfb362f11250684baf6710d3a95ca5ddd1f7c4a0.

Additional context:
Global extensions moved out of the core specification after R5 and are maintained in the FHIR Extension Pack. Later Extension Pack issue FHIR-44336 changed the individual-responsibility slice from `person`/Reference(Person) to `participant`/Reference(Patient | RelatedPerson | Practitioner | PractitionerRole), but left the organization slice as Reference(Organization). OO minutes from 2025-07-07 say the maintenance-responsibility extension should now be obsolete because of DeviceAssociation, and later core issue FHIR-51494 added the `maintainer` relationship code to build-scoped DeviceAssociation terminology. FHIR-51495 then updated the Extension Pack maintenance-responsibility extension to direct post-R5 users to DeviceAssociation.relationship=`maintainer` rather than deleting the extension.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR core source change. The requested organization support belongs to `/home/jmandel/work/fhir-extensions`, where `StructureDefinition-device-maintenanceResponsible.xml` currently defines a Device-scoped extension with an `organization` slice whose value is Reference(Organization). The active core checkout already includes Device and DeviceAssociation, exposes DeviceAssociation.relationship, and only keeps OID registrations for the maintenance extension URLs.

Recommendation:
Keep this external-repo audit commit. Do not add `device-maintenanceresponsibility` back into core. Any future edits to the maintenance-responsibility extension should be handled in the FHIR Extension Pack, while R6+ core usage should continue to use DeviceAssociation.relationship=`maintainer`.
