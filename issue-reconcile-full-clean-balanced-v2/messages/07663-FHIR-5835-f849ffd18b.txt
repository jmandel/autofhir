FHIR-5835: Audit NutritionOrder draft status

Issue request:
FHIR-5835 was a Published/Persuasive with Modification DSTU1 Orders and Observations change request for NutritionOrder/NutritionRequest. It asked to add a draft or under-preparation status to NutritionOrderStatus, with the definition "The request is in preliminary form prior to being sent".

Initial application:
The issue was explicitly applied in git 0e56277ba813b7ae74e753c67355edbc1dc1b07e, whose message says "preapply #5625, #5835 NutritionOrderStatus value set". That patch added a draft row to the then-current nutrition-order-status spreadsheet with the requested display and definition. The same work was later carried forward when the source was reworked into the current StructureDefinition and shared request-status terminology.

Additional context:
The current build has NutritionOrder as the active resource and lists the older NutritionRequest name only under removed resources. NutritionOrder.status is required, its short display includes draft, its binding name remains NutritionOrderStatus, and it binds to http://hl7.org/fhir/ValueSet/request-status. That value set includes the shared request-status code system, whose draft code is defined as a request that has been created but is not yet complete or ready for action. Later request-pattern cleanup and already-published AutoFHIR audits for FHIR-3720 and FHIR-10297 support the current shared RequestStatus representation rather than restoring a resource-specific NutritionOrderStatus code system.

AutoFHIR reconciliation:
This is an empty no-change audit commit. The current source already satisfies FHIR-5835: implementers see draft as an allowed NutritionOrder.status code through the required request-status binding, and the generalized draft definition preserves the requested preliminary/not-ready-for-action semantics.

Recommendation:
Keep this audit commit as-is. No core source follow-up is recommended for FHIR-5835; future changes to the shared RequestStatus definitions should be handled as a separate workflow/terminology decision rather than as this DSTU1 NutritionOrder-specific issue.
