FHIR-7519: Audit Immunization protocol cardinality history

Issue request:
FHIR-7519 was a Published PHER change request from the 2015May/DSTU-era Immunization model. It asked to allow vaccination protocol dose sequence to be recorded without doseTarget or doseStatus. The final Not Persuasive with Modification resolution kept target disease meaningful/required, said doseStatus should likewise be declared, and renamed doseTarget to targetedDisease/targetDisease.

Initial application:
The old gForge-era source history shows the request was applied to the spreadsheet model rather than the modern generated XML: commit 4e6d62c693 changed Immunization.vaccinationProtocol.doseTarget cardinality to 1..*, and commit e43671d5b7 renamed doseTarget to targetDisease. The then-current example also carried targetDisease and doseStatus in vaccinationProtocol.

Additional context:
Later PHER decisions intentionally changed the model. FHIR-8406 removed the old Immunization.vaccinationProtocol backbone and moved evaluation concepts out of Immunization. FHIR-14536 and FHIR-18868 reintroduced a smaller Immunization.protocolApplied backbone for provider intent/dose metadata. FHIR-19487 then explicitly made Immunization.protocolApplied.targetDisease optional after implementer feedback that dose number is often available without target disease. Current active source reflects that later decision: Immunization is in source/fhir.ini, protocolApplied.targetDisease is 0..*, doseNumber is present, and active Immunization source no longer contains doseStatus or doseStatusReason.

AutoFHIR reconciliation:
This audit commit makes no source change. Reinstating the 2015 required targetDisease/doseStatus rule would conflict with later Published decisions and with the current Immunization design.

Recommendation:
Keep this no-change audit commit as-is. Future Immunization work should treat FHIR-19487 and the protocolApplied redesign as superseding the 2015 FHIR-7519 cardinality intent for the current build, rather than restoring the DSTU-era required targetDisease/doseStatus constraints.
