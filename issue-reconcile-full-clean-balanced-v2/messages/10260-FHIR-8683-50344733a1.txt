FHIR-8683: Audit HTTP/HTTPS identity wording

Issue request:
FHIR-8683 was a Published/Persuasive FHIR-core change request against the RESTful API HTTP page. It asked to replace the unclear statement that "http:" and "https:" are exchangeable and refer to the same object with wording that says they must not be used to refer to different resources/objects.

Initial application:
FHIR-5512 introduced the original HTTP/HTTPS and port identity guidance in source/http.html in git-svn commit d0f47223ad0f368f159e7f2ccbd205234b2fc31f. FHIR-8683 was then applied as QA in git-svn commit cd02a83cb81e816388e258b698d29f8f9b4c49ee, which removed the "exchangeable" sentence and replaced it with the current SHALL NOT wording.

Additional context:
The current build source is source/http.html, the templated RESTful API page. Its Identity section now says the protocols http: and https: SHALL NOT be used to refer to different underlying objects and immediately clarifies that this does not require both addresses to be served, treated the same, or return identical content. Jira searches found only FHIR-8683 and its predecessor FHIR-5512 for the original phrase, and no Zulip or Confluence evidence was found that changes this conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already implements the FHIR-8683 clarification and preserves the intended FHIR-5512 port distinction, so another wording edit would be redundant and risk changing established identity guidance without a new work-group decision.

Recommendation:
Keep this empty audit commit as-is. No follow-up source work is recommended for FHIR-8683 unless a future issue reopens the broader HTTP/HTTPS identity policy.
