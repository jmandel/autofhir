FHIR-17301: Audit Composition confidentiality removal

Issue request:
FHIR-17301 was Published/Persuasive with Modification for R5 by Structured Documents. It asked to remove Composition.confidentiality because it duplicated security tags, to use a document Bundle's meta.security for clinical document confidentiality/high-water-mark information, and to document that usage while downstream Composition profiles reviewed their own constraints.

Initial application:
The original FHIR-I tracker FHIR-14298 was closed as the wrong ballot and cloned to this Structured Documents issue. The issue was applied in PR #2027, merged as 4b84bbff405f4ce3233e2dd37d36a306205d85a5, with commits f3e7ac34683c8671c4394b99790aa156564d279e and 44b8fc0d36fc16ff10da2eeb67ea80be49d05395 removing Composition.confidentiality from the active Composition StructureDefinition/search parameters and moving example confidentiality labels onto document Bundle.meta.security where applicable. Commit ad98b08fee0ad580d40e0647f1f87858b231629b later updated the CDA comparison sentence in the Composition narrative to say Bundle.meta.security is equivalent to ClinicalDocument.confidentialityCode.

Additional context:
Composition is an active current-build resource in source/fhir.ini, while the legacy source/profiles/cda.profile.xml profile containing Composition.confidentiality is commented out and not current build input. Later Structured Documents work removed the active ClinicalDocument Composition profile entirely under FHIR-34407, already represented on the combined branch, and FHIR-37719/related minutes confirm the otherConfidentiality extension was part of the same Bundle.meta.security migration. The current extension-pack copy of otherConfidentiality is retired with a "Use Bundle.meta.security instead" reason, so there is no remaining core source obligation for this seed. Zulip and Security/SD Confluence records support the same high-water-mark rationale and reveal no conflicting later direction.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source has no active Composition.confidentiality element/search parameter/example use, document examples carry Bundle.meta.security, the $document operation note tells servers to determine the document security-tag high-water mark on Bundle.meta.security, and the active Composition CDA note maps Bundle.meta.security to ClinicalDocument.confidentialityCode.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for FHIR-17301; any future debate about whether retired legacy clinical-document extensions should remain in the Extension Pack belongs to that repository and to the separate extension issues, not to this seed.
