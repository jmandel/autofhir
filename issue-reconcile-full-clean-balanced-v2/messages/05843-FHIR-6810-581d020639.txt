FHIR-6810: Audit Questionnaire options definition

Issue request:
FHIR-6810 was a Published/Persuasive DSTU1 Patient Care change request asking that the old Questionnaire.group.question.options description explain that "options" meant permitted answers. The accepted wording was to describe it as a reference to a value set containing a list of codes representing permitted answers for the question.

Initial application:
SVN r5941, represented in git as 26e8b597d5, applied the issue by changing the old Questionnaire.group.question.options short text from "Valueset containing the possible options" to "Valueset containing permitted answers" and the definition from "possible options" to the requested permitted-answer wording.

Additional context:
Questionnaire is an active current-build resource in source/fhir.ini, and the current alias map explicitly maps the old Questionnaire.item.options name to Questionnaire.item.answerValueSet. Later Published issue FHIR-20396 reworked Questionnaire choice/open-choice modeling for R5, adding answerConstraint and changing answerValueSet from a list of codes for choice/open-choice questions to a list of values for a question, which is broader and correct for the current item types.

AutoFHIR reconciliation:
No source change was made. The active current source already says Questionnaire.item.answerValueSet is a "ValueSet containing permitted answers" and defines it as a reference to a value set containing a list of values representing permitted answers for a question, preserving the FHIR-6810 clarification in the current model.

Recommendation:
Keep this audit commit as-is. Reintroducing the older exact "codes" wording would be less accurate for the current R5/R6 Questionnaire model, where answerValueSet can constrain coding, string, and uri answers; no follow-up core source work is needed for FHIR-6810.
