Issue request:
FHIR-5583 was a Published/Persuasive DSTU1 FHIR-core tooling correction reporting that generated Schematron invariants were not applied to contained resources, either under DomainResource.contained or Bundle.entry.resource.

Initial application:
The Jira comments say the issue was done around SVN revision 4000. Git history shows commit 368c9c3074eeb60fb30efdb8d319e75345501ebc at build@3993 with the matching application: the old generator stopped producing Atom-feed contexts, generated invariants from resource roots, followed base-resource element types such as DomainResource, and added the generated-file guidance to use fhir-invariants.sch because of containment.

Additional context:
Current core source keeps Bundle and DomainResource active in source/fhir.ini and still documents generated Schematron use in source/xml.html and source/validation.html, but the current checkout has no checked-in .sch outputs or SchematronGenerator.java to edit. Current build.fhir.org Schematron output retains the historical containment guidance that fhir-invariants.sch is the file to use for validation because of containment. A later tightly related issue, FHIR-8694, refined the generated Schematron context paths and confirmed that removing leading // did not break contained-resource checking; FHIR-27124 is a later dom-3 assertion issue already represented on the combined branch and is not part of this seed decision.
