FHIR-29653: Audit Observation search parameter FHIRPath expressions

Issue request:
FHIR-29653 is a Published/Persuasive OO technical correction for R5. It asked to fix Observation search parameter FHIRPath expressions that used the FHIRPath `as` type specifier on potentially multi-item collections such as `Observation.component.value`, because valid blood pressure Observations with multiple components could make those expressions error instead of selecting each typed value.

Initial application:
The issue was applied in git commit ee9191ec79, which changed `source/observation/bundle-Observation-search-params.xml` from `as` expressions to `ofType(...)` expressions for the Observation value and component-value search parameters called out by the Jira. The branch also contains merge commit b5673aa1e3 for the FHIR-29653 pull request. A later related FHIRPath cleanup, 7b140eccee, changed the remaining Observation date search parameter `.as(...)` expressions to `.ofType(...)`.

Additional context:
`source/fhir.ini` actively includes the Observation resource, so `source/observation/bundle-Observation-search-params.xml` is in current build scope. The originating Zulip thread confirms the problem and specifically recommends `Observation.component.value.ofType(CodeableConcept)` for multi-valued collections. OO minutes show FHIR-29653 being tracked for a May 2021 block vote and later still on the Observation tracker list before application. Related FHIRPath issue FHIR-25188 was ultimately Resolved - No Change in 2026 because the current core spec uses the corrected `ofType(X)` forms.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current Observation search parameter expressions use `ofType(...)` for the affected value, component-value, combo-value, and date parameters, and an explicit search found no `as` or `.as(...)` expression in `source/observation/bundle-Observation-search-params.xml`.

Recommendation:
Keep this no-change audit commit. No additional FHIR core source work is needed for FHIR-29653; future edits to Observation choice-type search parameters should continue using `ofType(...)` rather than `as` when the input may contain multiple items.
