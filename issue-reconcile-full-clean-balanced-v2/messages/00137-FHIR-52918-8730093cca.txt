FHIR-52918: Correct Group definitional member type codes

Issue request:
FHIR-52918 was Applied as Persuasive with Modification for R6. It requested that Group.member.entity allow SubstanceDefinition and MedicinalProductDefinition targets, that the http://hl7.org/fhir/group-type code system add substanceDefinition and medicinalProductDefinition codes, and noted that moving the separate group-code code system to THO would be handled through UTG.

Initial application:
The issue was initially applied by commit 4d3d3cfeffe922dea8426b1a9b6c2c61cbfc3524 via PR #3722, which added the two Group.member.entity reference targets and added corresponding group-type concepts. That application left the case-sensitive code values as medicinalproductdefinition and substancedefinition, and the Group.type comment still omitted the new definitional member resources.

Additional context:
source/fhir.ini actively includes Group, MedicinalProductDefinition, and SubstanceDefinition in the current core build. FHIR-41951 had already broadened Group to allow Medication and Substance members, while FHIR-48405 made Substance instance-only and established the need to assess definition-oriented Substance references. UP-740 handled the separate group-code move to THO and confirmed that the FHIR-52918 codes belong to group-type in core, not to group-code in THO. FHIR-I minutes for 2025-10-06 record Bryn's review and the 8-0-0 persuasive-with-modification motion.

AutoFHIR reconciliation:
This commit keeps the applied reference targets, corrects the case-sensitive group-type concept codes to medicinalProductDefinition and substanceDefinition as approved, and aligns the Group.type summary/comment so the local human-readable guidance no longer contradicts the added definitional member types.

Recommendation:
Keep this source fix. The active Group resource and active group-type CodeSystem now match the approved Jira resolution; no separate core source change is needed for the group-code THO migration handled by UP-740.
