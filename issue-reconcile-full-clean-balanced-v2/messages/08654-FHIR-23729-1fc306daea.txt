FHIR-23729: Clarify dotted _elements paths

Issue request:
FHIR-23729 was Published as Persuasive for R5. It asked to allow the _elements parameter to use dotted paths such as meta.versionId, clarify that the selection applies to resources returned by the interaction rather than the Bundle wrapper, and say that returning a nested element includes the parent elements leading to it.

Initial application:
No FHIR-23729-tagged implementation commit was found in the local HL7/fhir history. The prior root-only wording came from the original _elements text added by #7540, and FHIR-22934's earlier no-change disposition explicitly said it was superseded by GF23729. FHIR-27054 later applied a related but narrower included-resource change in commit f71d61cdab5ac2e91526e5d5999a1e2d51dd5e5d by removing the old statement that _elements does not apply to included resources and adding the Patient.gender resource-type-prefix paragraph, but it did not add the nested dotted-path clarification requested by FHIR-23729.

Additional context:
FHIR-25279 already constrains choice-type references in _elements to the base element name, and FHIR-31655 later clarified that _elements is not an absolute promise to return only requested elements. Those decisions are preserved here. Zulip discussion that prompted FHIR-23729 records the version-id history use case and the need to explicitly allow dotted paths; later Zulip discussion for FHIR-27054 shows the resource-type-prefix idea as a separate extension of the same _elements syntax. FHIR-I minutes confirm the FHIR-27054 vote, and no direct Confluence reference or exact-key Zulip hit was found for FHIR-23729.

AutoFHIR reconciliation:
This commit updates the active FHIR-core search page source, source/search.html, in the _elements section. It replaces the stale root-only description with element names or dotted element paths, states that dotted paths are interpreted relative to returned resources rather than the search/history Bundle, gives the meta.versionId example, says parent elements are included for nested returns, and keeps the existing choice-element and included-resource guidance intact.

Recommendation:
Keep this source fix. It directly applies the published FHIR-23729 decision while preserving later _elements decisions; no separate source change is needed here for FHIR-27054, FHIR-25279, or FHIR-31655.
