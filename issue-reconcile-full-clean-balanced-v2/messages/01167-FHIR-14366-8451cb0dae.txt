FHIR-14366: Audit Immunization potency elements

Issue request:
FHIR-14366 was a Published/Persuasive PHER change request for STU3 asking FHIR Core to add Immunization potency elements: a boolean potency flag that defaults to fully potent when omitted, and a CodeableConcept subpotentReason with an extensible/example reason value set. The Jira comment also noted that the potency flag likely needed to be a modifier.

Initial application:
The issue appears to have been applied before this reconciliation. Historical commit f451f3fc added the potency flag as Immunization.isPotent, added Immunization.subpotentReason, added a subpotent example, and added core subpotent reason terminology shortly after the PHWG vote. Commit 3161b278 renamed the flag to Immunization.isSubpotent, and commit f39499ca later corrected the subpotent example to use isSubpotent=true. Current source carries committee notes #14366 on Immunization.isSubpotent and Immunization.subpotentReason.

Additional context:
FHIR-18867 later clarified that subpotency is usually recognized retrospectively but can be immediate for partial administration, and that wording is now present on isSubpotent. FHIR-53151 moved the subpotentReason binding from the removed FHIR Core value set to the existing THO value set. FHIR-54326 added invariant imm-2 so subpotentReason may only appear when isSubpotent is true. source/fhir.ini lists Immunization as an active current resource, so the checked StructureDefinition and examples are in build scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Immunization source already has the required potency model: Immunization.isSubpotent is a 0..1 boolean modifier with meaningWhenMissing that the dose should be considered potent, Immunization.subpotentReason is a 0..* CodeableConcept bound to the THO immunization-subpotent-reason value set, imm-2 enforces the dependency, and the subpotent example demonstrates isSubpotent=true with a reason.

Recommendation:
Keep this no-change audit commit. The current Core source satisfies FHIR-14366 after later naming, wording, constraint, and terminology decisions; any future change to the subpotent reason code list belongs in THO rather than this FHIR Core checkout.
