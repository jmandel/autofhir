FHIR-41308: Audit external researchStudy SearchParameter fix

Issue request:
FHIR-41308 was an Applied/Persuasive OO change request for R6. It reported that the expression in http://hl7.org/fhir/extensions/SearchParameter-workflow-researchStudy.json only evaluated CodeSystem.extension(...), even though CodeSystem was not one of the SearchParameter base resources and the expression therefore missed the declared base resources.

Initial application:
No core FHIR source commit or current core source file applies this SearchParameter. The definition is maintained in the FHIR Extension Pack. Extension Pack commit f29a4db18daed5126a920228f81244fbe7bf9524 changed input/definitions/multiple/SearchParameter-workflow-researchStudy.xml from CodeSystem.extension('http://hl7.org/fhir/StructureDefinition/workflow-researchStudy').value to DomainResource.extension('http://hl7.org/fhir/StructureDefinition/workflow-researchStudy').value.

Additional context:
Zulip discussion linked from the Jira agreed that CodeSystem was wrong and that a simplified resource-wide expression would work. OO minutes on 2023-06-27 recorded the Persuasive disposition to update the SearchParameter to a Resource.extension(...).value expression, and the OO R6 Extension Work page later tracked FHIR-41308 as ready for QA on an Extension Pack branch. The current core checkout has only OID/history references and no active fhir.ini source entry for SearchParameter-workflow-researchStudy.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The authoritative current source is outside this repository in the FHIR Extension Pack and already contains the corrected DomainResource.extension(...).value expression covering the declared DomainResource base resources, including ObservationDefinition.

Recommendation:
Keep this audit commit as-is for the core reconciliation branch. Any future content change for this SearchParameter should be made and reviewed in HL7/fhir-extensions rather than in the core FHIR checkout.
