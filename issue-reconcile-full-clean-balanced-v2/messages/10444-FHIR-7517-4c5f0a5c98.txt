FHIR-7517: Audit Observation component restoration

Issue request:
FHIR-7517 was a Published/Persuasive with Modification FHIR-core Observation change request from the DSTU1 ballot. The accepted OO motion asked to remove the old "has-component" Observation related-type code, restore Observation.component as an inline complex element with code, value[x], dataAbsentReason, and referenceRange, and add an invariant preventing ambiguous reuse of the parent Observation.code.

Initial application:
The issue was applied by HL7/fhir commit 348f096acfd2c65b60b6ba759f214f756d403709, whose subject explicitly says "#7517 reintroduce Observation.component" and also cites the related FHIR-7639 has-component cleanup. That historical commit converted examples away from related[type=has-component] and restored the component structure in the then-current Observation spreadsheet source. Current source/observation/structuredefinition-Observation.xml contains Observation.component with the requested child elements, and source/fhir.ini lists observation=Observation, so this is active build-scope source.

Additional context:
Later source refactors moved the authoritative Observation definition into structuredefinition-Observation.xml. FHIR-38955, already audited on the combined branch, published the current obs-7 wording: if Observation.component.code is the same as Observation.code, then Observation.value SHALL NOT be present because Observation.component.value[x] holds the value. FHIR-7639, already represented on the combined branch by 4d9e3784aec1a07a6fae72d70460497809f0eb27, fixed remaining active _filter examples that still used the removed has-component related pattern. A current combined-branch grep found no remaining active has-component or Observation: related[type examples in source.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current combined branch already has the restored Observation.component structure, active notes explaining component use, the later accepted obs-7 invariant wording, and no active stale has-component references requiring another FHIR-7517 edit.

Recommendation:
Keep this no-change audit commit. No additional FHIR core work is needed for FHIR-7517 unless OO opens a new issue to change the modern Observation.component semantics or to clean up purely historical, unreferenced terminology artifacts.
