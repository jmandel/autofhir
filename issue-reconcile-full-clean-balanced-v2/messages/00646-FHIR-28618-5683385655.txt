FHIR-28618: Audit canonical datatype definition

Issue request:
FHIR-28618 was a Published/Persuasive with Modification R4 MnM clarification asking that the canonical datatype definition stop using circular or ambiguous wording. The approved replacement described canonical as a URI referring to resources by their url property, with optional |version and #fragment use, and clarified that a resource's own canonical URL is a url/uri target, not a canonical-valued element.

Initial application:
The issue appears to have been applied to source/datatypes.html in the March 2021 MnM R5 datatype edits: commit c4807a5165 changed the canonical row to refer to a resource by its url property and added the url-vs-canonical clarification, followed by formatting/link cleanup in 04214e23a1 and 60b2dc8a53. A later RatioRange/datatype edit b9fd58139d restored the "canonical URL" phrase but retained the key distinction that canonical values are references to target canonical URLs rather than the target URLs themselves.

Additional context:
The current build-scoped datatype page is active through source/fhir.ini's [type-pages] *=datatypes rule. Current source/datatypes.html now says canonical refers to a resource by its canonical URL, immediately links this to resources with a url property, allows |version and #fragment references, and states canonical URLs are not relative. source/references.html provides the linked canonical-reference detail, including that canonical references use the canonical type to refer to url elements of conformance/knowledge resources and describing version resolution. FHIR-27789 later added the absolute/fragment clarification, and FHIR-35780 addressed a separate version-specific core StructureDefinition package convention without changing this datatype definition.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already conveys the non-circular rule requested by FHIR-28618 across the authoritative datatype page and linked canonical-reference page, and the remaining concise primitive spreadsheet definition points readers to that canonical-reference section without contradicting it.

Recommendation:
Keep this audit commit as-is. Further edits to repeat the full datatype-page wording in generated/profile summaries would be redundant unless the work group separately decides those short generated descriptions must carry all canonical-reference details.
