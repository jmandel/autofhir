FHIR-12881: Audit Timing repeat count guidance

Issue request:
FHIR-12881 was a Published/Persuasive with Modification FHIR-core datatypes request asking MnM to clarify how Timing.repeat.count works when frequency and period are also present. The final resolution said Timing.repeat.count is the total number of repetitions across the duration of the timing, not the number of periods, and that an example should make that use clear.

Initial application:
The Jira comment cites an SVN revision near the application window. Git history shows the substantive Timing application in 0c1a713d764220d65de7203f9ccb1723a94ae7c7, whose git-svn-id is build@12467 and whose subject is "#1281 - note about use of Timing.repeat.count". That commit changed the authoritative Timing spreadsheet definition from "A total count of the desired number of repetitions" to "A total count of the desired number of repetitions across the duration of the entire timing specification". It did not add a separate Example-column value, but the applied definition directly answers the issue's count-versus-period ambiguity.

Additional context:
Timing is an active normative datatype in source/fhir.ini, so source/datatypes/timing.xml is in current build scope. Current source still says Timing.repeat.count is a total count across the entire timing specification, and the neighboring frequency and period definitions state that frequency is repetitions within a period and period is the duration over which those repetitions occur. The implementer Zulip thread linked to the original MnM question supported interpreting count as event/dose count, including count=10 for "twice daily for 5 days". Later FHIR-16986 preserved the total-count wording while adding countMax lower-bound semantics, and FHIR-15839 separately audited the positiveInt count constraint; both related audits are already represented on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope Timing source conveys the rule needed for implementers: count is the total desired repetition count across the schedule, not the number of frequency periods. Adding another example now would be redundant with the normative definition and adjacent frequency/period definitions, and no current source inconsistency or conflicting later decision was found.

Recommendation:
Keep this audit commit as-is. If MnM later wants additional rendered Timing examples or dosage-specific examples, that should be handled as a new example/editorial decision rather than as a missing FHIR-12881 source correction.
