FHIR-31912: Audit search method conformance wording

Issue request:
FHIR-31912 was a Published/Persuasive with Modification FHIR-core issue asking to clarify that the HTTP search wording should not be read as requiring both POST and GET for every server. Its literal resolution said servers that support search SHALL support the POST mechanism and SHOULD support the GET mechanism.

Initial application:
No historical source-changing commit explicitly mentioning FHIR-31912 was found. The issue was part of the same 2021 search-method family as FHIR-18551, FHIR-30577, FHIR-31943, and FHIR-31944. Later R5 source work introduced the current GET/POST plus 405 guidance on the Search page, moved the HTTP-specific transport guidance to source/http.html, and completed companion POST parameter clarifications; the current source no longer carries the old ambiguous "SHALL also support a POST based search" sentence that triggered this seed.

Additional context:
Later final issue FHIR-31943 superseded the seed's literal POST-SHALL/GET-SHOULD formulation by deciding that servers SHALL support search via GET and POST while using 405 Method Not Allowed when a specific search cannot be processed with the client-supplied method, and not returning 405 for both methods for the same search parameters. Zulip follow-up by the responsible editor explicitly described FHIR-31943 and FHIR-31944 as superseding FHIR-18551 and FHIR-31912. Related reconciliation commits for FHIR-31943, FHIR-31944, FHIR-38994, and FHIR-39137 are already present on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active build-scope HTTP and Search pages now reflect the later FHIR-31943/FHIR-31944 family decision: HTTP search documents GET and POST support with 405 behavior, method-choice considerations, POST body/query-parameter handling, and GET-style self links. Reverting this to the seed's literal POST SHALL / GET SHOULD sentence would conflict with the later final work-group decision and with already-published reconciliation commits.

Recommendation:
Keep this audit commit as-is. Any further change to the nuanced GET/POST plus 405 search conformance model should be handled under a new work-group decision rather than by restoring FHIR-31912's superseded wording.
