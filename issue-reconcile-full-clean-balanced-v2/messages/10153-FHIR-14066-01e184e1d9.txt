FHIR-14066: Audit token text search clarification

Issue request:
FHIR-14066 was a Published FHIR-core change request, resolved Persuasive with Modification for STU3, asking the search page to clarify what token :text searches as text associated with a code/value and whether the match is exact, starts-with, contains, fuzzy, or case-sensitive. The accepted resolution said the associated text was CodeableConcept.text, Coding.display, and Identifier.type.text, and that token :text functions as a normal string search, case-insensitive and allowing first-part matching.

Initial application:
The issue was applied by git commit 08aa67be14638daebe3ccadba9a34ef64177c46a, matching the Jira comment's SVN application note. That commit updated source/search.html to add that token :text functions as a normal string search after the CodeableConcept.text, Coding.display, and Identifier.type.text list.

Additional context:
The search page has since been reorganized and refined by later search work. FHIR-35812 expanded and harmonized the Identifier-related text surfaces, FHIR-31708 decided not to remove Identifier.type.text from token :text behavior, and FHIR-32673 addressed the separate desire for word-boundary/advanced matching by adding new token modifiers rather than changing basic token :text semantics. The current combined branch keeps the relevant search.html source in build scope as a tracked top-level search page, with search-modifier-code also referenced from source/fhir.ini.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/search.html already states that :text on reference and token searches matches CodeableConcept.text, Coding.display, Identifier.type.text, Identifier.type.coding.display, Identifier.assigner.display, or Reference.display using basic string matching, explicitly "begins with or is, case-insensitive," and the detailed section repeats the same rule with the expected caveat about locale-dependent case handling.

Recommendation:
