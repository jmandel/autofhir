FHIR-23072: Audit patient-agnostic Permission examples outside core

Issue request:
FHIR-23072 was an Applied/Persuasive with Modification Security work group issue requesting an example of using Consent to convey permissions, authorizations, obligations, and constraints for business rules unrelated to a specific patient, such as VhDir/provider-directory access. Jira comments later record that the Security work group changed the target from Consent to Permission.

Initial application:
The issue was applied through Permission examples rather than a Consent example. The R6 ballot Permission examples already included SANER and VhDir examples. Commit 9befcacddd1d4d69a926fe60c723c90333e3601a added a directory-admin Permission example, and commit 22d828960244ffa5a3d96df71fe1e3e30e410406 listed simple-directory, sensitive-directory, and residual Bundle Permission examples while Permission was still an active core resource.

Additional context:
FHIR-47307 is the same change family and repeats the concern that Permission and Consent did not address non-patient directory access or resource element-level access control. FHIR-49908 clarified Permission scope and boundaries to include non-patient use cases, organizational directories, residual policies, base policies for Consent, and Consent provisions encoded with Permission.rule; it already has a separate external-repo audit on the combined branch. Later commit 0e2a8a7f839d5e1a43787523daccf07d958362f3 removed Permission from the current core build and changed the Security module to link Permission to the HL7 Data Access Policies IG. Current Data Access Policies source includes the Permission directory and element-level examples.

AutoFHIR reconciliation:
This commit intentionally makes no core source change because the target resource for the final WG decision, Permission, is no longer built from this core checkout. The current external Data Access Policies source already contains patient-agnostic directory examples and element-level LOCIS limits, so reintroducing source/permission or adding a redundant Consent example in core would be out of scope.

Recommendation:
Keep this external-repo audit as-is. Future updates to patient-agnostic Permission examples should be made in HL7/data-access-policies; any renewed Consent example work should be tracked by a new final issue that accounts for the move of Permission outside core.
