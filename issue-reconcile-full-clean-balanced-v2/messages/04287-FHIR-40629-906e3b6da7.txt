FHIR-40629: Audit search :not clarification

Issue request:
FHIR-40629 was a Published/Persuasive with Modification FHIR-core search issue asking to clarify two :not behaviors: how the modifier interacts with comma-separated OR values, and whether a resource with repeated token values is excluded when any repetition matches the negated value. The approved resolution said modifiers apply to all OR values, added a dragon warning that or-joined :not behavior still needed more implementer feedback and recommended _filter or named _queries for safety, and added examples showing that any matching repetition prevents the resource from being returned.

Initial application:
The issue was applied in git commit b18ebf425a07f0fd5c0e65cf54abce6847a19f1d, titled "FHIR-40629 - Clarification of modifiers and or-joined parameter values." That commit changed source/search.html to add OR-value modifier prose, modifier table guidance, explicit :not examples for missing and repeated values, and the dragon note for or-joined :not. The current source still contains those changes.

Additional context:
The originating #implementers Zulip thread shows the same two ambiguities and records the post-resolution explanation that modifiers apply to each OR value individually while :not with comma-separated values was left as a feedback-requesting dragon warning. FHIR-I Confluence minutes for 2023-03-20 record the Persuasive with Modification vote for FHIR-40629. Later issue FHIR-54853 is Triaged and unresolved for R6, explicitly asking to finalize or remove the current dragon text, so it is future work rather than a final decision that changes this reconciliation. source/search.html is an active build page in publish.ini.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/search.html already says modifiers apply to each value of an OR query, defines :not as returning resources that do not have any matching value in the searched elements, includes Patient and Composition examples that cover missing values and repeated coded sections, and retains the dragon warning recommending _filter or Named Queries for or-joined :not search terms.
