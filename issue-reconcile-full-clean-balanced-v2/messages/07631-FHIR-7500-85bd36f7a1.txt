FHIR-7500: Align DiagnosticReport issued ModelInfo

Issue request:
FHIR-7500 was a Published FHIR-core DiagnosticReport issue from OO. The final Persuasive DSTU1 disposition requested changing DiagnosticReport.issued from dateTime to instant for consistency with Observation.issued.

Initial application:
The issue was initially applied in commit 4602ac2228a66f5be5c912df50507af046c7372b, whose message included #7500 and whose DiagnosticReport spreadsheet hunk changed the issued datatype from dateTime to instant. The later StructureDefinition source migration preserved the committee note for #7500, and prior to later reversals the active DiagnosticReport source used instant.

Additional context:
Later Applied issue FHIR-31956 superseded the old datatype choice. OO resolved in 2025 that DiagnosticReport.issued should change from instant back to dateTime to align with the existing element definition and that the current definition/comment guidance was otherwise adequate; commit 7ae073945afbacb5c54ad24cd64a8e906a7e87ef and PR #3888 applied that to the authoritative DiagnosticReport StructureDefinition. That related issue is already represented on the combined branch by cefe75f2321d668e0d4f0fd1a8df3498f2d57a3d and is not decided again here. FHIR-9433 also touched DiagnosticReport.issued wording and is already represented on the combined branch. DiagnosticReport and Library are active resources in source/fhir.ini, the FHIR ModelInfo Library is listed as a Library example, library-examples-header.xml links its readable content, and publish.ini copies the sidecar model-info XML.

AutoFHIR reconciliation:
This commit does not reapply FHIR-7500's superseded instant datatype to the active DiagnosticReport StructureDefinition. Instead, it fixes the remaining active ModelInfo surface that still reflected the old FHIR-7500 instant rule: source/library/library-fhir-model-definition-content.xml and the embedded payload in source/library/library-fhir-model-definition.xml now expose DiagnosticReport.issued as FHIR.dateTime.

Recommendation:
Keep this source fix. It reconciles the seed against the later OO datatype decision while avoiding a duplicate FHIR-31956 audit; no further core source work is needed for FHIR-7500 unless OO opens a new final tracker changing DiagnosticReport.issued again.
