FHIR-14158: Audit DeviceUseStatement implant procedure handling

Issue request:
FHIR-14158 was a Published/Not Persuasive with Modification OO change request for STU3 DeviceUseStatement. The tracker ultimately asked to use DeviceUseStatement.reasonReference for implant/explant procedure context, update the example to show that use, and correct the element spelling from bodysite to bodySite.

Initial application:
The source history shows a Jira-tagged preapplication in commit 1639b8d104fc8901a5f6576bcb044981c1320bc4. That commit changed the DeviceUseStatement example to reference Procedure/example and renamed DeviceUseStatement.bodysite to DeviceUseStatement.bodySite, but it did not add Procedure to the allowed reasonReference target list; the later R4/R5 mismatch was therefore not fully resolved by this seed's initial application alone.

Additional context:
FHIR-35979 is the same change family: it was a later Published/Persuasive OO issue noting that the DeviceUseStatement example used Procedure while reasonReference did not allow Procedure. PR history for FHIR-35979 added Procedure to DeviceUsage.reason. In the current core checkout, DeviceUseStatement is mapped to DeviceUsage only in migration metadata, DeviceUsage is not an active source/fhir.ini [resources] entry, and core module pages link the current DeviceUsage artifact to the HL7 OO incubator IG. The retained core DeviceUsage source and the current OO incubator StructureDefinition both include Procedure as a DeviceUsage.reason target and use bodyStructure rather than the old bodysite/bodySite element.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no core source change. The current core build no longer publishes the DeviceUseStatement/DeviceUsage resource from this checkout, and the active external DeviceUsage artifact already preserves the requested Procedure reason support and current body-location modeling.

Recommendation:
Keep this commit as-is. No current core follow-up is needed for FHIR-14158; future DeviceUsage conformance changes should be evaluated in the HL7 OO incubator source, while the already-published FHIR-35979 audit on the combined branch documents the later Procedure-target cleanup.
