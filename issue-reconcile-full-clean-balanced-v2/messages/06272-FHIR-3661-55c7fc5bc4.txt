FHIR-3661: Audit List orderedBy model

Issue request:
FHIR-3661 was Published with resolution Persuasive with Modification for DSTU1. It asked to replace the inadequate List.ordered boolean with an element that can say what the list order means, resolved as changing List.ordered to List.orderedBy with a value set and definitions.

Initial application:
The request was applied in SVN revision 4816, represented in git by e1e29f4ad6c14edf8a8ea1000cb53f1b7fc5b2c8, which changed the List spreadsheet from List.ordered boolean to List.orderedBy CodeableConcept bound to ListOrder, added valueset-list-order.xml, and removed the old ordered boolean example. The current active List resource has List.orderedBy as a CodeableConcept with a preferred binding to http://hl7.org/fhir/ValueSet/list-order.

Additional context:
The List resource is active in source/fhir.ini. Later Published issues FHIR-7502 and FHIR-24878 clarified how list order is interpreted: list-notes.xml explains that the physical item order can be meaningful and orderedBy specifies the order meaning, while List.entry.orderMeaning now says order has no meaning unless asserted by List.orderedBy. The current ValueSet/list-order delegates codes to the active terminology.hl7.org CodeSystem/list-order, which still contains the original requested ordering concepts and later additions.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source no longer contains the obsolete List.ordered boolean and already carries the requested List.orderedBy CodeableConcept, value set binding, explanatory note, and List.entry orderMeaning needed for implementers to understand the rule.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-3661; future changes to the allowed order codes should be handled through the terminology source for CodeSystem/list-order or a new tracker.
