FHIR-4873: Remove stale classHistory ModelInfo

Issue request:
FHIR-4873 was a Published/Persuasive PA change request raised in DSTU1. It asked Encounter to track Encounter.class over periods of time by adding a class history backbone element after Encounter.class, similar to the existing status and location histories.

Initial application:
No exact FHIR-4873-tagged source commit was found in current git history, which starts after some DSTU-era applications. Historical Encounter source imported into the repository already contained Encounter.classHistory with class and period children, matching the Jira request. Later, FHIR-14157 implementation commit 2c0f3a8733 removed Encounter.classHistory and Encounter.statusHistory from the Encounter StructureDefinition as part of replacing those backbones with EncounterHistory.

Additional context:
Encounter is still an active current resource, but current source/encounter/structuredefinition-Encounter.xml no longer defines Encounter.classHistory and source/encounter/encounter-introduction.xml explicitly says R4 and earlier used statusHistory/classHistory while EncounterHistory now provides that history. FHIR-14157 and FHIR-38856 record the later PA decision to track class/status/location history through EncounterHistory, and later R6 cleanup moved EncounterHistory out of core source while preserving links to the PA admin-incubator artifact. The FHIR ModelInfo Library remains active and build-visible through the Library examples and publish.ini, and it still exposed the obsolete Encounter.classHistory surface.

AutoFHIR reconciliation:
Removed the stale Encounter.ClassHistory ClassInfo and Encounter.classHistory element from source/library/library-fhir-model-definition-content.xml, then synchronized the embedded Library.data payload in source/library/library-fhir-model-definition.xml. The core Encounter resource, R4/R5 mapping metadata in fhir.ini, and narrative mention of historical classHistory were intentionally left unchanged.

Recommendation:
Keep this source fix. It reconciles FHIR-4873 with the later EncounterHistory replacement on the remaining active ModelInfo surface. Broader Encounter ModelInfo cleanup, such as statusHistory or class datatype/cardinality alignment, should be handled by the specific later tracker decisions rather than expanding this DSTU1 class-history issue.
