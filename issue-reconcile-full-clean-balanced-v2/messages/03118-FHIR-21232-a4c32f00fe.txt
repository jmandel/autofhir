FHIR-21232: Audit event trigger reuse boundaries

Issue request:
FHIR-21232 was Published/Persuasive with Modification for R5 by the CDS work group. It asked to clarify reusability boundaries for EventDefinition and TriggerDefinition, concluding that EventDefinition should be deprecated in favor of SubscriptionTopic and that TriggerDefinition should be able to refer to a SubscriptionTopic so the topic completely defines the triggering event.

Initial application:
The Jira comment links PR HL7/fhir#2288, merged as 13fb5889ecbc08b05d25cd2023c933b94581df24. That application did not add the requested text verbatim to TriggerDefinition.name; instead, it added a dedicated TriggerDefinition.subscriptionTopic element of type canonical(SubscriptionTopic) with the rule that no other trigger-definition information may be supplied when it is used.

Additional context:
The deprecation aspect later became FHIR-41372, which deprecated EventDefinition in favor of SubscriptionTopic for R6, but that decision was subsequently superseded by FHIR-53316. FHIR-53316 undeprecated EventDefinition and added current Boundaries and Relationships text explaining EventDefinition, SubscriptionTopic, MessageDefinition, and TriggerDefinition. FHIR-53414 later aligned TriggerDefinition examples and invariants, including subscription-topic guidance, and is already represented on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current build-scope source already lets TriggerDefinition refer to SubscriptionTopic through a canonical subscriptionTopic element and invariant, and the current EventDefinition source follows the later FHIR-53316 decision rather than preserving the older deprecation wording from FHIR-21232/FHIR-41372.

Recommendation:
Keep this audit commit as-is. Reintroducing deprecation text or adding redundant TriggerDefinition.name prose would conflict with later R6 decisions and duplicate the existing subscriptionTopic element semantics.
