FHIR-7527: Audit Communication unknown-role guidance

Issue request:
FHIR-7527 was Published with resolution Not Persuasive with Modification for DSTU1. It asked how to populate Communication.sender and Communication.recipient, and the parallel CommunicationRequest roles, when a communication is to or from an individual whose Patient/Practitioner/RelatedPerson role is not known. The accepted change was to add guidance that these cases should default to RelatedPerson rather than allowing a direct Person reference.

Initial application:
The issue appears to have been applied by git commit cb0f45f8046d76835cfdb0cdb337b059ac8d9762, which explicitly mentioned #7527 and added usage-note guidance to both source/communication/communication-notes.xml and source/communicationrequest/communicationrequest-notes.xml. Later refactoring moved the authoritative element definitions out of the old spreadsheets, but the notes text carried forward.

Additional context:
source/fhir.ini actively lists communication=Communication and communicationrequest=CommunicationRequest, so both notes files are in the current build scope. Current Communication and CommunicationRequest StructureDefinitions both include RelatedPerson among the relevant reference targets. Later applied changes renamed CommunicationRequest.sender to CommunicationRequest.informationProvider and added additional target types; existing reconciliation commits FHIR-26619 and FHIR-22631 aligned these active notes with the current target-profile lists while preserving the FHIR-7527 default-to-RelatedPerson guidance. Bounded Zulip and Confluence searches found no community evidence that changes this conclusion.

AutoFHIR reconciliation:
Made no source change. The current active notes already say that when the communication or communication request is to or from an individual whose role is not known, such as when only an email address is captured, RelatedPerson should be used by default. Adding another hunk would only duplicate existing guidance.

Recommendation:
Keep this no-change audit commit. No core follow-up is recommended for FHIR-7527 unless a work group later chooses to revisit the broader Person-vs-RelatedPerson modeling rule.
