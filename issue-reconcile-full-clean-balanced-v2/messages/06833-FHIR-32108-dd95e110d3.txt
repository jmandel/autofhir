FHIR-32108: Audit fhir-single schema corrections

Issue request:
FHIR-32108 was a Published/Persuasive R4B technical correction reporting several generated fhir-single.xsd errors: missing ResourceType and ResourceType-List schema types, an invalid ClinicalUseIssue OtherTherapy therapy[x] XML name, and Element extending Element as a circular base reference.

Initial application:
Source-side corrections were already applied before this reconciliation. Commit 4690a19a2e, explicitly tagged with FHIR-32108, corrected the event-or-request resource type ValueSet name so schema generation could produce a valid XML type name. Earlier commit cbac492e57 made the same ValueSet-name correction and changed ClinicalUseIssue.contraindication.otherTherapy.therapy[x] to therapy because the element did not have multiple types. The resource was later renamed to ClinicalUseDefinition in 1c32449f00, carrying the corrected otherTherapy structure forward.

Additional context:
The Jira comments say the source errors were addressed in R4B and already fixed in R5, while the remaining Element-is-Element circular-reference item was a tooling issue. FHIR-I WGM minutes for May 2021 record FHIR-32108 as a technical correction, auto-approved. The linked Kindling PR HL7/kindling#64 changed the schema generator so R4/R4B Element is emitted as a root element instead of extending itself, and the linked HAPI PR hapifhir/org.hl7.fhir.core#759 updated downstream generated/supporting R4B/R5 code. Current source/fhir.ini has ClinicalUseDefinition active and ClinicalUseIssue retired/commented, and current source no longer contains the invalid therapy[x] element.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative current source already has EventOrRequestResourceTypes as an XML-name-safe ValueSet name, has ClinicalUseDefinition.otherTherapy as a BackboneElement/contentReference without therapy[x], and the live generated fhir-single.xsd now contains ResourceType, has no ResourceType-List or ClinicalUseIssue/therapy[x] residue, and emits Element extending Base rather than Element.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for the current build; any future regression in Element schema inheritance belongs in the schema-generation/tooling repositories rather than as a direct edit to checked-in FHIR source.
