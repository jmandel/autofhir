FHIR-19729: Audit search parameter expression fix

Issue request:
FHIR-19729 was a Published/Persuasive STU3 FHIR-I change request asking to fix invalid FHIRPath search parameter expressions for Group value and Observation combo-value-quantity where `as` and `|` operator precedence made the expressions invalid. The approved resolution was to add parentheses to the affected expressions, following the Zulip discussion.

Initial application:
No Jira-keyed commit for FHIR-19729 was found. The application appears to be Brian Postlethwaite's 2018-12-06 commit 005eb62bce, merged as PR #352, which changed source/group/group-spreadsheet.xml and source/observation/observation-spreadsheet.xml to parenthesize Group value plus the Observation value/combo/component expressions mentioned in the Zulip thread.

Additional context:
The current build-scope source no longer uses the old spreadsheets for these definitions; Group and Observation are active resources in source/fhir.ini and their current checked-in search parameter bundles contain the relevant definitions. Later search-parameter cleanup, especially FHIR-29653 commit ee9191ec79 for Observation and 2023 Group cleanup commits 7b140eccee and aac5d575d8, replaced the parenthesized `as` expressions with equivalent `ofType()` expressions, which avoids the FHIRPath collection/type-specifier issue entirely. Zulip confirms the original issue and no Confluence reference for FHIR-19729 was found.

AutoFHIR reconciliation:
This commit makes no source change. The current Group value expression is `(Group.characteristic.value.ofType(CodeableConcept)) | (Group.characteristic.value.ofType(boolean))`, and the current Observation combo-value-quantity expression is `Observation.value.ofType(Quantity) |  Observation.component.value.ofType(Quantity)`. These satisfy the original operator-precedence correction under the later ofType() representation.

Recommendation:
Keep this empty audit commit as-is. No core source follow-up is needed for FHIR-19729; future work, if any, should be handled under later search-parameter expression issues rather than reopening this STU3 operator-precedence fix.
