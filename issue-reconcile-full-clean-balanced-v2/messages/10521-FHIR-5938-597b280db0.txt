FHIR-5938: Audit retired extension worksheet type parsing fix

Issue request:
FHIR-5938 was Published/Persuasive for DSTU1 and asked that extension worksheet Type values of the form Reference(Resource){profileUrl} be accepted while defining a profile. The concrete failure was the historical QICore Other.AdverseEvent.cause.item extension, where the old spreadsheet parser rejected profiled reference types because it parsed the extension value type with the inProfile flag set to false.

Initial application:
Jira records Grahame Grieve's application note as svn revision 4745. In the migrated git history, commit 81d1bff591ce339694764d726741b17b6770fe00 carries the #5938 application message for extension type profile parsing, and the nearby historical parser commit db55db7414cc49a9bd93c668c9fd19c3de26fccf changes SpreadsheetParser.parseExtensionElement so extension worksheet Type values are parsed with inProfile=true instead of false.

Additional context:
The affected QICore source was historical profile content, not a current core profile. The old source/other/adverseevent-qicore-profile-spreadsheet.xml was later renamed when Other became Basic and then moved out of core source under CQF/QICore work. Current source/fhir.ini still lists Basic and AdverseEvent as active resources, but the active [profiles] list contains current core extension/profile spreadsheets and no QICore AdverseEvent profile package. The old Java publisher/parser classes that implemented this worksheet behavior are no longer present in the current checkout. The directly related follow-up FHIR-5955, about preserving the parsed profile URLs in generated extension definitions, is already represented on the combined branch and is not duplicated here.
