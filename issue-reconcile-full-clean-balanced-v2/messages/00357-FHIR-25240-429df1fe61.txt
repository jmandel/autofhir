FHIR-25240: Audit DeviceMetric device clarification

Issue request:
FHIR-25240 was a Published/Persuasive R4 DeviceMetric clarification asking the Devices work group to distinguish DeviceMetric.source from DeviceMetric.parent using the PoCD containment guidance, with the final motion to clarify those elements in R5 and Jira comments noting DeviceMetric.parent was changed to 0..1.

Initial application:
No commit explicitly titled with FHIR-25240 was found for the current source path. The nearby application trail shows 9a661e74e3 (titled FHIR-39322) changed DeviceMetric by removing DeviceMetric.source, renaming DeviceMetric.parent to DeviceMetric.device, and making the replacement reference 1..1. The current source history also shows the resulting DeviceMetric.device element has been maintained by later R6 cleanup commits.

Additional context:
FHIR-40300 later made the same source/parent question concrete and was Published/Persuasive with Modification: remove source, rename parent to device, and make it 1..1. Confluence minutes for 2023-02-06 mention FHIR-25240 directly and record proposed language work for DeviceMetric source/parent, while the Zulip devices thread says the plan was DeviceMetric.device with source represented via Device.parent. FHIR-51443 and FHIR-53421 subsequently cleaned up the DeviceMetric.device wording without reversing the model.

AutoFHIR reconciliation:
This commit intentionally makes no source change. DeviceMetric is active in source/fhir.ini, and the authoritative current source already has DeviceMetric.device as a 1..1 Reference(Device), with definition/comment text explaining that the referenced device can be a top-level device or component and that a top-level device is reached through the referenced Device.parent chain when needed. The old DeviceMetric.source and DeviceMetric.parent elements are absent from the resource definition and only remain in fhir.ini as R4/R5 conversion mapping notes.

Recommendation:
Keep this audit commit as-is. Reopening FHIR-25240 would risk reintroducing obsolete source/parent terminology after the later Published FHIR-40300 model change; any future refinements should target DeviceMetric.device wording directly rather than restoring separate elements.
