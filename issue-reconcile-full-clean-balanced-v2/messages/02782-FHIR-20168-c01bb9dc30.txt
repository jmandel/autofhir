Issue request:
FHIR-20168 was Published/Persuasive for R5 and asked CarePlan.addresses to support CodeableConcept as well as Reference(Condition), with guidance explaining when to use coded concerns versus referenced concerns.

Initial application:
The Jira comment points to GH#218ec67. Commit 218ec67c42b8156bcd8330a57848603b297321d3 applied the request by splitting CarePlan.addresses into CarePlan.addressesCode and CarePlan.addressesReference in the then-active spreadsheet/examples and adding the requested usage comment. Later, commit 7daa0d220d80bdaf2229f7aa05f4d4e6c0f5a698 converted repeating code/reference patterns to CodeableReference, changing the split elements to CarePlan.addresses CodeableReference while preserving the same coded/reference guidance under addresses.concept and addresses.reference. Commit 33b409a4b6d544598262f2f074ebb4b6dc466157 moved that source into the current structuredefinition-CarePlan.xml representation.

Additional context:
source/fhir.ini actively lists careplan=CarePlan, so source/careplan/structuredefinition-CarePlan.xml is in current build scope. The current CarePlan.addresses element is 0..* CodeableReference with a clinical-findings binding for codes and target profiles including Condition; its comment still carries the FHIR-20168 guidance. FHIR-32512 later expanded CarePlan.addresses reference targets to include Procedure and MedicationAdministration and is already represented on the combined reconciliation branch, so it is supporting context rather than a duplicate decision here. FHIR-54076 is a later Triaged unresolved proposal to add ImmunizationRecommendation and does not justify a source change for this Published seed. Confluence and Zulip searches found no directly relevant conflicting community record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current CodeableReference shape is the modern representation of the requested CodeableConcept-or-reference pattern, and editing it back to separate addressesCode/addressesReference elements would be wrong for the current specification.

Recommendation:
Keep this audit commit as-is. No FHIR-core follow-up is needed for FHIR-20168 unless a future final decision changes the CarePlan.addresses target profile set or CodeableReference modeling.
