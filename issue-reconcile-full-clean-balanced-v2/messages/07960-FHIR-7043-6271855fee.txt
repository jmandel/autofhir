FHIR-7043: Audit lockedDate version availability

Issue request:
FHIR-7043 is Published/Persuasive with Modification and asked for a constraint or note about using ValueSet.compose.lockedDate together with explicit versions of referenced code systems or value sets. The accepted resolution was to add a note that if versioned references are used with a locked date, those versions need to have been available on that date.

Initial application:
The issue was applied in SVN revision 5701, represented in git as b2187ba63870b9a2e85827b764d315b2e9bc2a2b with subject "#7043 - note about LockedDate". That commit added the exact version-availability note to the historical ValueSet spreadsheet, and the wording survived later source migrations into the current ValueSet StructureDefinition comment.

Additional context:
ValueSet is an active resource in source/fhir.ini, so source/valueset/structuredefinition-ValueSet.xml is in the current build scope. Related lockedDate decisions before and after FHIR-7043 clarified context-dependence and the definition of lockedDate, but they do not reverse the FHIR-7043 note; the current comment preserves both the context-dependent warning and the required availability rule. FHIR-18702 and FHIR-16435 already have separate combined-branch audit commits, and no directly relevant Zulip or Confluence record for FHIR-7043 was found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current ValueSet.compose.lockedDate comment already says that if a value set specifies a version for include and exclude statements and also specifies a locked date, the specified versions need to be available that date or the value set will not be usable.

Keep this audit commit as-is. No follow-up source edit is needed for FHIR-7043 unless the Vocabulary work group later changes lockedDate semantics more broadly.
