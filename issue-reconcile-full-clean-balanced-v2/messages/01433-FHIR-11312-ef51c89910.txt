FHIR-11312: Audit retired Sequence reference string clarification

Issue request:
FHIR-11312 was a Published Clinical Genomics change request for the DSTU2 Sequence resource, resolved Not Persuasive with Modification. The requester asked what the string in Sequence.referenceSeq.referenceSeqString meant; the accepted clarification explained that referenceSeq could be represented four ways and that referenceSeqString was a literal reference sequence string such as "ACGTTAG".

Initial application:
I found no explicit git commit mentioning FHIR-11312, #11312, or core #466. The closest historical source change after the vote was 3149123edb040e04385f2a496490c08a842015ff, "Add constraints on Sequence.referenceString", which added invariants requiring exactly one referenceSeq representation among genomeBuild, referenceSeqId, referenceSeqPointer, and referenceSeqString, but it left the old referenceSeqString definition as the generic "A Reference Sequence string." Thus the original clarification appears at most partially applied in the legacy Sequence source.

Additional context:
The affected Sequence resource is now listed under removed resources in source/fhir.ini. The later MolecularSequence resource is commented out for Clinical Genomics, and source/diagnostics-module.html says MolecularSequence has been replaced by MolecularDefinition. Later final Clinical Genomics decisions reshaped this area: FHIR-37441 changed the legacy referenceSeq alternatives into a choice, and FHIR-51227 superseded legacy MolecularSequence with MolecularDefinition. Current MolecularDefinition uses a different representation model with literal, code, resolvable, extracted, repeated, concatenated, and relative representations; its literal.value definition already describes a string literal representation of the molecular entity and gives primary DNA sequence as an example.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The original ambiguous Sequence.referenceSeq.referenceSeqString element is not in the current build, and copying the DSTU2 clarification into MolecularDefinition would be a model translation rather than applying the historical issue. The current source already handles literal molecular sequences through MolecularDefinition.representation.literal.value, while the old Sequence and MolecularSequence referenceSeq fields have been retired or superseded.

Recommendation:
Keep this audit commit as-is. Do not resurrect or back-port the retired Sequence.referenceSeqString text into the current core source; any remaining ambiguity in MolecularDefinition literal or extracted sequence representation should be handled as a new MolecularDefinition-specific Clinical Genomics issue.
