FHIR-36814: Audit Appointment requestedPeriod guidance

Issue request:
FHIR-36814 was a Published PA change request, resolved Not Persuasive with Modification for R5, asking whether Appointment.start/end were too constrained as instant. The accepted modification was not to relax the datatype; instead, when actual times are unknown, use Appointment.requestedPeriod, move requestedPeriod next to start/end/length, and add a comment on Appointment.start and Appointment.end saying the requested period start/end can be used.

Initial application:
The issue was applied in git commit 1bd6618a0590a3b5f79d79f9a143c1f77235d91d, which added the requested comment to Appointment.start and Appointment.end and moved Appointment.requestedPeriod from later in the resource to immediately after the time-related start/end/minutesDuration elements. No prior source application changed start/end away from instant, consistent with the resolution.

Additional context:
The active build scope includes Appointment via source/fhir.ini, and the current source/appointment/structuredefinition-Appointment.xml keeps Appointment.start and Appointment.end as instant while documenting the requestedPeriod fallback. PA minutes from 2022-09-07 record the same not-persuasive-with-modification motion. Earlier FHIR-25793 reached a no-change decision on the same Period-vs-instant question and also directed flexible or not-yet-solidified scheduling to requestedPeriod. A Zulip implementers thread contains matching background rationale and no later discovered community evidence contradicts the PA decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active Appointment source already implements the final disposition: start/end remain instant, both elements have the requested comment, and requestedPeriod follows start/end/minutesDuration.

Recommendation:
Keep this audit commit as-is. No current FHIR core source follow-up is needed for FHIR-36814 unless PA makes a new decision to reopen the Appointment.start/end datatype question.
