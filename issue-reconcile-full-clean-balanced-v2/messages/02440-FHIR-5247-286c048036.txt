FHIR-5247: Audit document bundle resource wording

Issue request:
FHIR-5247 was a Published/Persuasive with Modification SD ballot comment for the FHIR-core Documents page. The final resolution rejected a proposed direct-reference-only interpretation and clarified that document bundles may include resources directly or indirectly referenced from the Composition; it also asked to replace the negative "SHALL NOT include any resources not on this list" phrasing and change "i.e. recursively" to "e.g. recursively".

Initial application:
The issue was applied in svn revision 4623, preserved in git commit 5e0472eeb7347af3a0647481462f3dd6d8bb4284, which changed source/documents.html from "The document bundle SHALL NOT include any resources not on this list:" to "The document bundle SHALL only include resources on this list:" and changed "i.e. recursively" to "e.g. recursively" for the Composition-referenced resource list.

Additional context:
source/documents.html is an active current-build narrative page: it is listed as the Documents page in source/hierarchy.xml and source/navigation.xml. Later FHIR-6175 changed the lead-in to "The document bundle SHALL include only:" to avoid confusion with the List resource, and that related issue is already represented on the combined branch by commit c4b7d642ecd33bfbf3de649520588d823c35afd6. Later document-page edits revised the list around a composition set and graph-connected supporting information, but the current text still conveys that indirect recursive references are allowed.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source says "The document bundle SHALL include only:" and allows supporting information that is part of the graph of resources that reference or are referenced from the composition set, either directly or indirectly, using the approved "e.g." wording. The obsolete negative sentence, the "resources on/in this list" phrasing, and "i.e. recursively" are absent from the current source tree.

Recommendation:
Keep this no-change audit commit as-is. No FHIR-core source follow-up is needed for FHIR-5247 unless SD reopens the broader document-bundle content policy separately.
