FHIR-16978: Audit Period duration clarification

Issue request:
FHIR-16978 was a Published/Persuasive FHIR-core datatypes issue asking to clean up the Period comment so it separately explains that Period is a time range and is not a Duration/elapsed-time value.

Initial application:
The issue was applied in SVN revision 14293, mirrored as git commit a34d05c9054edcf85259b16ebbd00718f3efa201, which changed source/datatypes/period.xml from the confusing one-paragraph duration wording to the current two-paragraph comment.

Additional context:
source/fhir.ini maps datatypes through the active type-page machinery, so source/datatypes/period.xml is in current build scope for the Period datatype. A later Period search hit, FHIR-20652, concerns duplicate Timing.repeat.period/frequency wording rather than this Period datatype comment. Zulip and Confluence searches for FHIR-16978 and the exact Period-duration phrase found no conflicting community evidence.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Period source already says a Period specifies a range of time, explains whole-range versus one-value interpretation by context, and separately states that Period is not used for a duration with a link to Duration.

Recommendation:
Keep this no-change audit commit as-is. Any future desire to add separate Interval/Range guidance should be handled as a new work-group decision, because the current source already satisfies the published cleanup request without adding redundant prose.
