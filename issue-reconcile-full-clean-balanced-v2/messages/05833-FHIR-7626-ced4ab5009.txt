FHIR-7626: Audit ContactPoint rank

Issue request:
FHIR-7626 was a Published FHIR-core datatypes change request, resolved Persuasive with Modification, asking that ContactPoint provide a rank attribute so different communication modalities could be attempted in preference order. The recorded resolution endorsed the change based on Patient Administration support and called for a positive integer.

Initial application:
The request was applied in the historical source by git commit d45b815efc6c29cd65295e44bf82863887c82875, whose subject is "#7626 - add ContactPoint.rank". The current source/datatypes/contactpoint.xml spreadsheet still contains ContactPoint.rank with cardinality 0..1, type positiveInt, and a definition that lower rank values are more preferred.

Additional context:
ContactPoint is an active datatype in source/fhir.ini and is marked normative, so source/datatypes/contactpoint.xml is in current build scope. Later published issues FHIR-16984 and FHIR-38824 refined the rank wording without removing the element: FHIR-16984 clarified that lower rank values are more preferred, and FHIR-38824 plus the linked implementers discussion and FHIR-I minutes clarified that ranks need not be unique or sequential and that unranked repetitions are allowed. No Zulip or Confluence hit for FHIR-7626 itself revealed a conflicting decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped ContactPoint definition already has the requested rank attribute as a positiveInt and contains the later clarifications that govern its current interpretation.

Recommendation:
Keep this audit commit as-is. No follow-up source edit is needed for FHIR-7626 unless a future work group decision changes ContactPoint.rank semantics.
