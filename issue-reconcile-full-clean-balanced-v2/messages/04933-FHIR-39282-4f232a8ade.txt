FHIR-39282: Audit FML delimited identifier grammar

Issue request:
FHIR-39282 was a Published/Persuasive technical correction for the FHIR-core mapping language page. It reported that FML allowed either backticks or double quotes for delimited identifiers while FHIRPath only uses backticks; the actionable resolution was to make FML allow only the FHIRPath-style delimiter for delimited identifiers.

Initial application:
The issue was applied in git commit 4988dd04f338d63595d004d52ccfb55c8dc9aa60, which removed the double-quoted alternative from images/mapping.g4's DELIMITEDIDENTIFIER lexer rule. The earlier same-change-family issue FHIR-25286 had already updated source/mapping-language.html prose and examples to use backticks rather than double quotes.

Additional context:
The current build still includes mapping-language.html through source/hierarchy.xml and publishes mapping.g4 through publish.ini. A later grammar cleanup in db673c36e89b5e3fe2475c105a43503c5c7ab5e9 retained the backtick-only DELIMITEDIDENTIFIER rule while keeping DOUBLE_QUOTED_STRING only for FML-specific strings such as metadata, URLs, and rule names. FHIR-I WGM minutes record the FHIR-39282 decision, and the earlier Zulip thread for FHIR-25286 explains why double-quoted identifiers were removed to avoid confusion with string literals.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because the current grammar only accepts backtick-delimited identifiers and the mapping language narrative/examples no longer describe double quotes as an escaping mechanism.

Recommendation:
Keep this audit commit as-is. Revisit only if the work group wants to clarify the Jira resolution wording, which says "single-quote" even though the issue description, source grammar, and related evidence all point to the FHIRPath-style backtick delimiter.
