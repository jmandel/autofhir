FHIR-10300: Audit event status alignment

Issue request:
FHIR-10300 was a Published/Persuasive Orders and Observations change request for DSTU2 asking to align event-resource status terminology for DeviceUseStatement, Supply, Observation, and DiagnosticReport with the Event pattern. The Jira discussion added entered-in-error and cancelled to the original event-status framing, then recorded that Observation and DiagnosticReport status alignment was completed, with SupplyDelivery and DeviceUseStatement left as follow-up work.

Initial application:
The issue appears to have been applied through historical GForge/SVN commits rather than a modern FHIR-10300-named commit. Commit 0fddebbe824485506904fadc81eff5f749e8356f explicitly says it is "also part of [#10300]" and updated Observation and DiagnosticReport status spreadsheets and mappings, including entered-in-error and unknown wording and added/refined status codes. Commit 5a6e321c64ad0c1df8f1b8a956ecffdcae9748e5 included [#10300] with Event-pattern alignment and reworked SupplyDelivery.status to in-progress | completed | abandoned | entered-in-error. Commit 1639b8d104fc8901a5f6576bcb044981c1320bc4 later updated OO event resources under FHIR-10299, including DeviceUseStatement status and Event-pattern mappings.

Additional context:
FHIR-10436 is the direct Observation/DiagnosticReport status-alignment issue and confirms that those two value sets intentionally remain distinct while being aligned; current core keeps Observation and DiagnosticReport active. FHIR-10299 is the broader OO Event-pattern tracker that consolidated remaining workflow-pattern tasks into FHIR-19631. Current source/fhir.ini has active diagnosticreport and observation resource entries, but no active DeviceUsage, SupplyDelivery, or SupplyRequest entries; it retains only a historical DeviceUseStatement=@DeviceUsage alias. Commit 3b38b80cf23f9cbb306fab8fcedb293315478c32 removed DeviceUsage, SupplyRequest, and SupplyDelivery from active core build configuration and changed current module pages to link those resources to the OO Incubator. Existing combined-branch audits for FHIR-12711 and FHIR-14142 already record the SupplyDelivery and DeviceUsage external-ownership boundary.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The active core artifacts covered by this seed are already correct: Observation.status and DiagnosticReport.status are required code elements with current required bindings to their status value sets, include entered-in-error and unknown, and preserve the domain-specific status distinctions approved in FHIR-10436. The remaining historical targets, DeviceUsage/DeviceUseStatement and SupplyDelivery/Supply, are no longer active FHIR core build inputs, so editing retained inactive source/deviceusage or source/supplydelivery files would not correct the current built core specification.

Recommendation:
Keep this audit commit as-is for FHIR core. Do not add redundant status prose or edit inactive DeviceUsage/SupplyDelivery source in core for FHIR-10300. If OO wants further status alignment for those moved resources, handle it in the OO Incubator publication/source path rather than in this core checkout.
