FHIR-31853: Remove Population from ModelInfo

Issue request:
FHIR-31853 was a Published/Persuasive with Modification FHIR-core BRR change request for R5 ClinicalUseIssue/ClinicalUseDefinition. It reported that ClinicalUseIssue pointed to the draft Population datatype and requested using Group instead; the final resolution was to use the Group resource and remove the Population datatype.

Initial application:
The primary resource change was applied in 2021 by 0d13844f22f42bb7ddf72c329b24228e76040624 and repeated in 08d35148dd0fa3866502882e1805fe34cb107da4, changing ClinicalUseDefinition.population from Population to Reference(Group). Current source/fhir.ini keeps ClinicalUseDefinition active and comments Population out of the active type/page/normative build lists.

Additional context:
FHIR-31847 renamed ClinicalUseIssue to ClinicalUseDefinition immediately before this issue was applied, so current reconciliation uses the ClinicalUseDefinition source. The inactive source/datatypes/population.xml and source/population-profiles.html files still exist, but their fhir.ini build references are commented out and they are not the current-build defect. The active Library resource and Library/library-fhir-model-definition example still exposed a standalone FHIR.Population type and population properties typed as FHIR.Population, leaving a current computable metadata surface inconsistent with the accepted change. Broader ModelInfo cleanup of legacy MedicinalProduct* class names versus ClinicalUseDefinition belongs with the rename/collapse history and is not expanded into this issue.

AutoFHIR reconciliation:
This commit removes the obsolete FHIR.Population ClassInfo from the active FHIR ModelInfo Library, changes the remaining population properties that referenced it to list-valued FHIR.Reference, and resynchronizes the embedded Library/library-fhir-model-definition attachment from the raw modelinfo content.

Recommendation:
Keep this source fix. It completes the remaining current-build Population datatype removal for FHIR-31853 while leaving unrelated legacy ModelInfo resource-name cleanup to a separate FHIR-31847-family reconciliation if needed.
