FHIR-18645: Audit CodeSystem multiple-parent wording

Issue request:
FHIR-18645 was a Published/Persuasive STU3 vocabulary issue for FHIR-core CodeSystem. It asked to clarify the confusing Concept Hierarchy wording that said nested CodeSystem hierarchy is a single tree with one parent while the next sentence acknowledged repeated parent properties and referred to a subsumes extension.

Initial application:
The Jira comments say the resolution was superseded by and applied as part of GF#19307/FHIR-19307. The later FHIR-19307 Jira comment cites git 80086b8f22b9b182c473fbb7b7a446d7aafbd37c, but source history shows c27b4eaede30c4537c55ae885110719ef3067ae0 as the actual CodeSystem application: it removed the subsumes-extension wording, added parent/child property guidance for additional parents, and preserved operation equivalence for property versus nested hierarchy representations.

Additional context:
FHIR-19307 is already represented on the combined branch by audit commit 0c6c33bbba9384babc8a4a41d9521846e518ab66, so this commit does not publish a duplicate FHIR-19307 decision. CodeSystem is active in source/fhir.ini, and later Published issue FHIR-39262 deliberately reworded the same Concept Hierarchy paragraph to distinguish nested single-tree hierarchies from property-based polyhierarchies.

AutoFHIR reconciliation:
This is an empty no-change audit commit. The current build-scope source already resolves FHIR-18645: it says nested concepts alone form a single tree with one parent, properties allow polyhierarchies with more than one parent, hierarchy represented through properties should not be mixed with nested hierarchy structure, and CodeSystem operations must have the same result for property and nested representations.

Recommendation:
Keep this audit commit as-is. Do not reapply the exact 2018 wording or add redundant clarification because the current FHIR-39262 wording is the later published work-group clarification and directly addresses the multiple-parent ambiguity raised by FHIR-18645.
