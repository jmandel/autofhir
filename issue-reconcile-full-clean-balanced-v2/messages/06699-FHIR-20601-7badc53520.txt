FHIR-20601: Audit doNotPerform and DeviceUsage not-done application

Issue request:
FHIR-20601 is an Applied/Persuasive with Modification OO change request for R6. It asked to support quality-measure "not done" use cases by adding DeviceRequest.doNotPerform, clarifying that the DeviceRequest reason captures the reason for a do-not-perform request, and updating DeviceUseStatement/DeviceUsage status handling so not-done and its reason are represented consistently with the Event pattern.

Initial application:
The request was applied before this reconciliation through several Jira-tagged commits. 2ccb7e2ebc added not-done to the then-current DeviceUsage status code system, 5a7860697b added the DeviceRequest reason comment for doNotPerform, and c2cc454524 added DeviceUsage preparation plus the event-statusReason guidance for not-done. The Jira comment identifies c2cc454524 as the final application commit.

Additional context:
DeviceRequest remains active in the current core build through source/fhir.ini and now contains DeviceRequest.doNotPerform as a 0..1 boolean modifier mapped to Request.doNotPerform, with DeviceRequest.reason documenting the do-not-perform reason. Later FHIR-26949 work, already represented on the combined branch, corrected the DeviceRequest-specific modifier reason. DeviceUseStatement was renamed to DeviceUsage by FHIR-31478, and DeviceUsage was later removed from core build scope by 3b38b80cf2 when immature OO resources were moved to incubator IGs; source/ballot-intro.html now points DeviceUsage to the OO incubator. The remaining 2025 Jira comment asking for generic Request.doNotPerform qualifier prose was explicitly deferred to a new ticket, so it is not part of this issue's disposition.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active core DeviceRequest portion is already correct, and the DeviceUsage portion was applied in the retained source before DeviceUsage moved out of the current core build. Re-editing the out-of-build DeviceUsage source or adding redundant DeviceRequest prose would not improve the current built specification.

Recommendation:
Keep this audit commit as-is for FHIR-core. If the OO incubator copy of DeviceUsage needs further status alignment, handle that in the incubator repository or a new ticket; no additional core source change is indicated for FHIR-20601.
