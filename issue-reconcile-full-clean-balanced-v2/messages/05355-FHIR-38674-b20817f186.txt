FHIR-38674: Audit Device instance guidance

Issue request:
FHIR-38674 was an Applied/Persuasive OO change request asking FHIR-core Device/Procedure guidance to clarify that a specific device instance should be represented with Device rather than DeviceDefinition even when instance details such as lot or serial number are not known. The approved resolution was to add a Device Boundary/Scope subsection distinguishing Device from DeviceDefinition by example.

Initial application:
Jira records that the issue was applied in commit 9197480014a08d8494b2f2aec7c30b2705fc7e62. Git history confirms that commit added the Device and DeviceDefinition subsection and the two requested examples to source/device/device-introduction.xml. A follow-up cleanup commit, 7ae447a3bdd9ff0d1112282e32b597cd39c992a6, removed malformed HTML and refined the replacement-device sentence without changing the approved meaning; d8299e2070537663edb7fdfac87d3b706b38a96c later adjusted only the heading level.

Additional context:
source/fhir.ini lists both device=Device and procedure=Procedure as active resources, so the inspected Device and Procedure source is in current build scope. Current Device source contains a "Device and DeviceDefinition" subsection under Scope and Usage that says Device is used for a specific instance even without instance data and includes the pump and replacement-device Procedure examples requested by the issue. DeviceDefinition source remains consistent by describing DeviceDefinition as a type/kind and Device as an actual instance. Procedure source does not contain conflicting DeviceDefinition guidance, and the Jira resolution specifically targeted Device Boundary/Scope rather than a Procedure page edit. Confluence minutes from the September 2022 OO WGM record the original example request, and May 2024 OO minutes state the issue had been voted on but not yet applied; no later community or Jira evidence found a conflicting decision.

This commit intentionally makes no source change. The current active Device source already satisfies the final Jira decision, and adding duplicative Procedure prose would not change implementer understanding.

Recommendation:
Keep this no-change audit commit as-is. No follow-up is needed in core unless the work group later asks for broader Procedure-specific explanatory text beyond the approved Device Boundary/Scope subsection.
