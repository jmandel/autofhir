The recorded resolution specifically requested updating the Procedure.status short description to `preparation | in-progress | not-done | on-hold | stopped | completed | entered-in-error | unknown`.

Initial application:

Additional context:

The current Event Status code system includes `on-hold` and `stopped`, not `suspended` or `aborted`. Related no-change issue FHIR-14869 confirms that Procedure.statusReason prose is intended to explain reason capture for exception statuses, so its examples should use current Procedure.status codes even though the original FHIR-20497 hunk only touched the status short description. Exact Zulip and Confluence searches found no direct community record that changes the Jira/source conclusion.
