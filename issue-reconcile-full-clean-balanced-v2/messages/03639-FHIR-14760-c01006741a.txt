FHIR-14760: Audit CareTeam.subject rationale

Issue request:
FHIR-14760 was a Published STU3 Patient Care change request, resolved Persuasive with Modification, asking why CareTeam.subject can be omitted and can reference Group. The approved resolution requested CareTeam.subject requirements text explaining group care (for example marriage/group therapy) and organization-designated teams such as a PICC line team.

Initial application:
The group-care requirement existed before the ballot issue in the legacy CareTeam spreadsheet. Git commit b88fc91916dd76f6587b8f326b9ea447d69381cd explicitly included GF#14760 and added the PICC line team sentence to CareTeam.subject requirements in source/careteam/careteam-spreadsheet.xml. Later source refactoring moved that applied text into the active StructureDefinition source.

Additional context:
CareTeam is an active current-build resource in source/fhir.ini under the Patient Care work group. Later Published issue FHIR-28457 added a CareTeam.subject comment clarifying when to use Group versus Patient and did not replace the FHIR-14760 requirements. Jira, source history, and negative Zulip/Confluence searches did not reveal a later conflicting decision.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current active source/careteam/structuredefinition-CareTeam.xml keeps CareTeam.subject at 0..1, allows Reference(Patient|Group), includes the requested group-care and PICC-line requirements, and includes the later Group-vs-Patient clarification.

Recommendation:
Keep this no-change audit as-is. The current specification already conveys the approved rationale for optional CareTeam.subject and Group subjects; any future cleanup of the awkward legacy "marriage) therapy" wording should be a separate editorial decision by Patient Care rather than part of this reconciliation.
