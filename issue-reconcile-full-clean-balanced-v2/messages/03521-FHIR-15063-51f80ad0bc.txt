FHIR-15063: Audit MedicationAdministration event code cleanup

Issue request:
FHIR-15063 was Published with a Persuasive/Auto-approved STU3 correction for MedicationAdministration. It reported that four MedicationAdministration Events-tab message event codes were camel-case even though FHIR required lowercase-dash codes, and pointed to source/medicationadministration/medicationadministration-spreadsheet.xml as the source that generated valueset-message-events.

Initial application:
The issue was applied before this reconciliation. The Jira comments record an applied change on 2018-02-02, and git-svn commit 75e2ce5802d3b2a080bac1149923c5f7957b68f9 (GF#15063 - removed values in Events for MedAdmin) deleted the MedicationAdministration-Update, MedicationAdministration-Nullification, MedicationAdministration-Complete, and MedicationAdministration-Recording rows from the MedicationAdministration spreadsheet Events tab.

Additional context:
FHIR-13333 is the same message-event cleanup family and later resolved the broader lowercase-dash problem by removing all core-defined message event codes. The referenced Zulip thread recorded no implementer demand for HL7-defined FHIR message events and agreement to stop parsing spreadsheet events; git-svn commit 2b81a477bd4df7e781a87c177f4c2fb552641fa1 then removed the rendered event list from source/messaging.html. Later combined-branch work for FHIR-26902/FHIR-32398 removed the remaining empty MessageEvent value set references, and the active MessageHeader and MessageDefinition bindings now say FHIR does not define message event codes.

AutoFHIR reconciliation:
Made no source change. MedicationAdministration remains an active resource, but the historical spreadsheet rows are gone, current source contains none of the requested camel-case or lowercase MedicationAdministration event codes, and current messaging/terminology source says the core specification does not define message event codes.

Recommendation:
Keep this empty audit commit as-is. Reintroducing lowercase MedicationAdministration event codes would contradict the later accepted direction to leave message event codes to implementations and implementation guides.
