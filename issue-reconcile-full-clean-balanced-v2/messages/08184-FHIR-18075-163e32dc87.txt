It reported that the Value Set References table in terminologies.html incorrectly named ValueSet.compose.import and, in the reporter's follow-up comment, asked for the row to use ValueSet.compose.include.valueSet.

Initial application:

Current blame for the active row still points to that commit.

Additional context:
source/fhir.ini maps resourceType to the terminologies page and lists valueset as an active resource, so source/terminologies.html and source/valueset/structuredefinition-ValueSet.xml are in current build scope. The current ValueSet StructureDefinition defines ValueSet.compose.include.valueSet, and searching current source found no remaining ValueSet.compose.import references. Remaining compose.import hits are confined to tools/history/release2 historical artifacts, where the old DSTU2-era element name is expected. Zulip evidence from the 2016 committers thread confirms the STU3 rename from ValueSet.compose.import to ValueSet.compose.include.valueSet; Confluence has no issue-specific FHIR-18075 references that change this conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active terminology table already uses ValueSet.compose.include.valueSet, matching the Jira request and the current ValueSet definition.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-18075 unless a future terminology-wide rewrite chooses to rephrase the non-normative description that still says "imported value set" in the ordinary English sense.
