FHIR-13475: Audit adaptive feeding device extension location

Issue request:
FHIR-13475 was a Published OO change request, resolved Persuasive with Modification for STU3, asking that NutritionOrder carry materials needed to perform the order. The accepted disposition was to add a standard AdaptiveFeedingDevice extension under NutritionOrder.oralDiet as a 0..* CodeableConcept with an example binding to a Feeding Device value set.

Initial application:
The change was applied in core history by commit 4fb140007ce4d98260abb203f8af627c8951210e, which added the feeding-device CodeSystem, feeding-device ValueSet, and NutritionOrder adaptive feeding device extension spreadsheet/source. The R4B source conversion commit c69d71aa213de86d55e0261339c15e4bacd509e6 retained those NutritionOrder extension artifacts.

Additional context:
Core commit dd468d4f1799dd79819315b211588ef1cf4586e0 later removed the NutritionOrder extension artifacts from the R5 core source as part of the extension-source split. The current core build still includes NutritionOrder, but source/fhir.ini and source/nutritionorder no longer include the adaptive feeding device extension or feeding-device terminology. Those artifacts are now in the FHIR Extension Pack under input/definitions/NutritionOrder, with context NutritionOrder.oralDiet, CodeableConcept value, and example binding to http://hl7.org/fhir/ValueSet/feeding-device. The linked Zulip discussion supports treating this as an extension rather than a core NutritionOrder element, and no Confluence evidence was found that changes that interpretation.

AutoFHIR reconciliation:
This commit intentionally makes no source change in the core FHIR checkout. The requested artifact is already represented in the Extension Pack, which is outside this repository's current build scope, so reintroducing the same extension or terminology into core would duplicate the external source of truth.

Recommendation:
Keep this empty external-repo audit commit as-is. No core follow-up is needed for FHIR-13475 unless the project decides to move Extension Pack artifacts back into core or a separate Extension Pack issue identifies a defect in the existing adaptive feeding device extension or feeding-device terminology.
