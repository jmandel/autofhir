FHIR-19751: Audit Period start/end invariant

Issue request:
FHIR-19751 was Published with a Persuasive resolution for R5. It asked to enforce the Range-like Period rule that Period.start must be less than or equal to Period.end when both are present.

Initial application:
The Period datatype already had a per-1 invariant before this reconciliation. Git commit c4807a5165ee632872ef9f6289fee8e9e1abbb5f, whose message explicitly listed FHIR-19751, changed the invariant's human wording from a strict lower-than description to "If present, start SHALL have a lower or equal value than end" while retaining the <= XPath/FHIRPath intent.

Additional context:
source/fhir.ini actively lists Period in [types] and maps datatype pages to datatypes.html, so source/datatypes/period.xml is a current build input. Later Published issue FHIR-34417 refined the same per-1 FHIRPath expression from a direct dateTime comparison to lowBoundary()/highBoundary() so different date/time precisions can be represented while preserving the start <= end rule. No Zulip or Confluence search hit was found for FHIR-19751 that would change this interpretation.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active Period spreadsheet currently carries per-1 with the approved lower-or-equal human wording and the precision-safe expression start.hasValue().not() or end.hasValue().not() or (start.lowBoundary() <= end.highBoundary()).

Recommendation:
Keep this audit commit as-is. The current source already implements the final FHIR-19751 requirement as subsequently refined by FHIR-34417, and changing the source again would be redundant.
