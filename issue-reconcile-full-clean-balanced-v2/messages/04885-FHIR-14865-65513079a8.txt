FHIR-14865: Audit extensible hierarchy guidance

Issue request:
FHIR-14865 was Published/Persuasive with Modification for STU3 and asked the FHIR-core terminologies page to clarify that extensible bindings allow second-level or other hierarchical codes when the desired meaning is not present in the specified value set. The accepted resolution said there was already no restriction on using such an is-a descendant code when the value set lacks the desired meaning, and asked for clearer documentation and examples.

Initial application:
The Jira comment points to GH#5f9b6eca5d, and commit 5f9b6eca5d changed source/terminologies.html and source/terminologies-binding-examples.html. It separated the no-applicable-concept case from the more-general-concept-present case, added explicit is-a hierarchy language, and added Condition examples showing when an outside hierarchical code is valid, when a more general value-set code must be used instead, and when the more specific local code may accompany that value-set code as an additional Coding.

Additional context:
Same-day FHIR-17284 changed nearby extensible wording from alternate system/code to alternate concept/text and is already represented on the combined branch. Later FHIR-29968 reorganized the Extensible Binding Strength guidance for R5, and the existing FHIR-29968 reconciliation aligned the formal binding-strength CodeSystem while preserving the narrative hierarchy rule. FHIR-48479 later moved binding and additional-binding descriptions into one section and left the detailed Extensible section and examples in place. source/fhir.ini maps resourceType to the terminologies page, and source/hierarchy.xml includes the Terminology Binding Examples page, so the relevant source is in current build scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/terminologies.html still says an alternate concept may have any specificity in an is-a hierarchy when no applicable value-set concept exists, and it still requires the closest more general value-set concept when one applies while allowing a more specific outside code as an additional CodeableConcept Coding. The current examples still demonstrate both sides of that rule.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-14865 unless the work group separately changes the later FHIR-29968 Extensible-binding policy; the current specification already communicates the accepted STU3 clarification.
