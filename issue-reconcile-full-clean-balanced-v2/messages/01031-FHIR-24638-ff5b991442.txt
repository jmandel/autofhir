Issue request:
FHIR-24638 was a Published Financial Management change request for R5 asking to update Coverage.subscriberId from string to Identifier so the subscriber identifier can be represented with Identifier semantics beyond a point-to-point string.

Initial application:

The R5 source rework already carried Coverage.subscriberId as type Identifier in source/coverage/structuredefinition-Coverage.xml, while the active FHIR model-definition Library content still exposed Coverage.subscriberId as FHIR.string.

Additional context:
FHIR-24688 is the same Coverage.subscriberId change family and later changed the element cardinality to 0..*. Coverage is active in source/fhir.ini, Library is an active resource, and publish.ini publishes source/library/library-fhir-model-definition-content.xml. Prior AutoFHIR reconciliation commits have treated stale entries in the FHIR model-definition Library as current-build source defects.

AutoFHIR reconciliation:
Updated the FHIR model-definition Library content and its embedded Library attachment so Coverage.subscriberId is typed as FHIR.Identifier instead of FHIR.string. The authoritative Coverage StructureDefinition already had the Identifier type, so this commit fixes the missed parallel model metadata only.

Recommendation:
Keep this commit as-is. It completes the already-applied Coverage.subscriberId type change in the current FHIR model metadata; the seed FHIR-24688 cardinality change is handled by the following per-issue commit.
