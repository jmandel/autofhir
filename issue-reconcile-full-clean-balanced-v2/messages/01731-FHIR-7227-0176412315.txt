FHIR-7227: Audit Immunization resource rationale

Issue request:
FHIR-7227 was a Published/Persuasive PHER clarification from the DSTU1 ballot. The issue said the Immunization description read only "Immunization event information" and asked PHER to beef up the description to state that Immunization is a resource, not a profile, and explain why.

Initial application:
The issue was applied by git commit 4e6d62c69367e6e3fcb59d84d016df913d35607e, whose message explicitly includes "#7227 update Immunization description". That commit replaced the terse spreadsheet definition with a fuller description of vaccine administration records, reactions, and protocol information. Later source refactors moved the authoritative resource definition into source/immunization/structuredefinition-Immunization.xml and retained a descriptive resource-level definition.

Additional context:
FHIR-6230 is the same separate-resource-versus-profile question and was resolved as Considered - Question answered/No Change after discussion of why a first-class Immunization resource is preferred over MedicationAdministration profiles. The current build lists Immunization as an active resource. The current StructureDefinition declares kind="resource" and derivation="specialization", and the current Immunization narrative states the resource scope, key use cases, and the boundary with MedicationAdministration. A later published reconciliation for FHIR-32960 further aligned the active Immunization/MedicationAdministration boundary so vaccines are primarily represented with Immunization, with MedicationAdministration allowed only for workflow reasons when an equivalent Immunization instance is also exposed.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already conveys the semantic point requested by FHIR-7227: Immunization is a first-class resource with its own scope and boundary from MedicationAdministration, not merely a profile. Adding a literal historical "not a profile" sentence would duplicate current guidance and create maintenance drift without changing implementer understanding.

Recommendation:
Keep this no-change audit commit as-is. No FHIR core source follow-up is needed for FHIR-7227 unless PHER later decides to add broader historical rationale to the Immunization narrative.
