FHIR-40319: Correct GE prefix boundary interpretation

FHIR-40319 was Applied/Persuasive with Modification for R6 by FHIR-I. It asked to simplify the Search page prefix definitions by replacing hard-to-reason range-overlap prose with clearer lower/upper boundary descriptions and examples for the prefix comparison table.

Initial application:
The current branch already contained the untrailed source application. Commit 8a0db85bba first changed the related ge/le wording to single combined-range tests for FHIR-51068; commit 0890ea2b2a then applied FHIR-40319 by adding boundary interpretations, resource interval tests, and an example matrix to source/search.html; commit 7d7aaa259c made PR-comment cleanup. No Issue-Reconcile-Key commit for FHIR-40319 existed on the combined branch.

Additional context:
FHIR-51068 is an Applied same-change-family issue that clarifies compound prefixes such as le and ge as single range-intersection tests. The 2025-06-23 and 2025-09 FHIR-I minutes, plus the referenced Zulip discussions, show the work-group path from implementer confusion about Period/date ranges to the approved single-intersection semantics. FHIR-51077 later identifies separate decimal/date range-example text errors but remains Resolved - change required and is outside this run's default Applied/Published source-edit scope. In current source, the ge row's formal definition and interval tests use the combined range starting at parameter-lower, but its boundary sentence still said parameter-upper, contradicting the example rows where a resource inside the parameter range should match ge.

AutoFHIR reconciliation:
Changed only the ge boundary interpretation in source/search.html from the upper boundary of the parameter value to the lower boundary of the parameter value. source/search.html is the current FHIR-core Search page source, and the hunk is necessary because the old wording would make ge fail for resource ranges overlapping the lower portion of a parameter interval, contrary to the resolved combined-range semantics.

Recommendation:
Keep this commit as-is. Handle FHIR-51077's separate decimal/date table example cleanup under its own reconciliation if it enters the Applied/Published run scope.
