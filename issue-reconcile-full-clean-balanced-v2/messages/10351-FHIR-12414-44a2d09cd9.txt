FHIR-12414: Audit date prefix examples

Issue request:
FHIR-12414 was Published/Persuasive for FHIR-core search in DSTU2. It asked for more examples explaining date searches with prefixes, especially partial-date values such as gt2016-03, ge2016-03, eq2016-03, and sa2016-03 when the searched value is implicitly or explicitly a range.

Initial application:
The Jira comments record svn revision 10509. The git-svn mirror contains commit c0ce6034c4dd973420c0471374107cec100bc3ba, "#12414 - search date examples", which changed source/search.html by expanding the date prefix table from short one-line examples into detailed eq, ne, lt, gt, ge, le, sa, eb, and ap examples with match/non-match bullets. No Issue-Reconcile-Key commit for FHIR-12414 existed on the combined branch before this audit.

Additional context:
source/search.html is the current FHIR-core Search page source. The active page now has a Prefixes section with formal definitions, boundary interpretations, resource interval tests, a matrix showing how parameter and resource ranges interact, date/time range-of-value examples for partial dates such as 2015-08, and the date search prefix example table. Later Applied R6 issues FHIR-40319 and FHIR-43208, already represented on the combined branch, refined the same search-prefix/range area and support keeping the current expanded wording rather than restoring the exact 2016-03 sample values from the DSTU2 request. The originating Zulip thread shows FHIR-12414 was filed after implementer confusion about gt/ge/sa with partial dates; later Zulip discussion shows remaining confusion was addressed through later Jira work, not a missing FHIR-12414 application.

AutoFHIR reconciliation:
Published an empty audit commit. No source change is needed because the current Search page already provides more complete date-prefix and range examples than FHIR-12414 requested. Adding another 2016-03 example set would be redundant and could create maintenance drift with the later boundary-interpretation table.

Recommendation:
Keep this no-change audit as-is. Future corrections to current date-prefix semantics should be handled under the later search-prefix Jira family, not by reopening this already-applied DSTU2 example enhancement.
