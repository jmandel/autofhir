FHIR-32578: Audit DocumentReference type binding

Issue request:
FHIR-32578 was a Published/Persuasive with Modification OO change request for R5 asking that the DocumentReference document type binding not be limited to the earlier narrow document-type set. The resolution was to change the example set to https://build.fhir.org/valueset-doc-typecodes.html, the value set already used by Composition.

Initial application:
The closest source application happened in the 2022 DocumentReference value set work. Commit cebeac615e0c434ff755a1aa763781d2cf61c8c2 changed DocumentReference.type from bindingName DocumentC80Type and ValueSet/c80-doc-typecodes to bindingName DocumentType and ValueSet/doc-typecodes. Commit 63e34f95aa90a1abb55f7221d0e450049e9342d3 explicitly named FHIR-32578 and temporarily changed the binding strength from preferred to example; commit ca285c8a45fd6e2f997ebbf7e52f974e24e80f00 changed the strength back to preferred before the Jira-commented merge commit 333a55c82177c6a441312c2153b3d7a6abe8a507 landed the branch.

Additional context:
source/fhir.ini lists both composition and documentreference as active resources, so their StructureDefinition XML files are current build-scope source. Current DocumentReference.type and Composition.type both use http://hl7.org/fhir/ValueSet/doc-typecodes, and the value set source is the FHIR Document Type Codes LOINC DOC-scale value set. Related audits already on the combined branch for FHIR-32822 and FHIR-28078 confirm the same issue family: FHIR-32822 coordinated the non-C80 DocumentReference type binding with FHIR-32578, and later FHIR-28078 explicitly records doc-typecodes as applied as a preferred binding to DocumentReference.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already carries the requested canonical binding, aligned with Composition.type, and the later final FHIR-28078 decision supports the current preferred strength. The separate source/documentreference/valueset-doc-typecodes.xml artifact is not the binding target of DocumentReference.type; cleaning up that separate value set would be a distinct terminology/publication decision, not required for FHIR-32578.

Recommendation:
Keep this no-change audit commit as-is. No FHIR core source edit is needed for FHIR-32578 unless OO later decides to split DocumentReference.type away from the shared doc-typecodes value set through a new issue.
