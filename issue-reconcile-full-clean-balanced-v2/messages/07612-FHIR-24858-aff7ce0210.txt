FHIR-24858: Audit FHIRPath UCUM duration warning

Issue request:
FHIR-24858 was a Published/Persuasive FHIR-I change request asking the FHIRPath appendix to warn implementers that, when FHIR UCUM Quantities are converted to FHIRPath System.Quantity, UCUM fixed-duration units such as `a` and `mo` differ from calendar year/month semantics that users often intend.

Initial application:
The issue was explicitly applied by git commit 9c94e6c4fa0df8b08d19d5d9519a2c4e416c3715 on 2022-08-29, which added a dragons block to source/fhirpath.html explaining the UCUM-to-calendar-duration mapping and the 365.25-day/30-day distinction for `a` and `mo`.

Additional context:
FHIR-I minutes for 2020-03-23 confirm the 12-0-0 decision to add a dragon warning for FHIR-24858 and note possible future work on a separate code system. The later Zulip thread #fhirpath > FHIR-24858 discussed concerns about UCUM calendar-unit guidance and led to FHIR-38064, but FHIR-38064 remains Triaged/Unresolved and is not a final replacement decision. The tightly related Timing guidance issue FHIR-24857 is already represented on the combined branch by a separate audit commit, so it is not republished here.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build source still includes source/fhirpath.html through publish.ini, and its Use of FHIR Quantity section maps time-valued UCUM units to FHIRPath calendar duration units and contains the requested dragons warning about the differing UCUM definitions for `a` and `mo`.

Recommendation:
Keep this no-change audit as-is for FHIR-24858. Revisit only if a future final work-group decision such as FHIR-38064 replaces the current UCUM-to-calendar-unit guidance or defines a separate calendar-unit code system for core FHIR use.
