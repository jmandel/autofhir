FHIR-16462: Audit CodeSystem reverse references

Issue request:
FHIR-16462 was a Published/Persuasive with Modification Vocab change request for the STU3 CodeSystem Identification section. It asked whether the generated "This resource is referenced by" list was complete because it named ConceptMap and TerminologyCapabilities but omitted at least ValueSet and CodeSystem when CodeSystem is used as a supplement. The approved resolution was to update the tools to pick up canonical and implicit references, or manually adorn known special cases, so the references would be listed.

Initial application:
The issue appears to have been applied in svn 14786, represented in git as 6296a48a54c159ef487275547e9948909a74e354. That commit message explicitly mentions GF#16462 and "rendering problems on reverse reference list". Its PageProcessor change made reverse-reference rendering inspect type definitions as well as resources, stopped suppressing self-references, and manually added CodeSystem references from ValueSet, ConceptMap, and Coding when they were not otherwise discovered.

Additional context:
CodeSystem is an active current build resource through source/fhir.ini. The current CodeSystem source describes the relevant relationships: ValueSet use, Coding.system canonical references, TerminologyCapabilities capability descriptions, and the distinction between ConceptMap relationships and CodeSystem supplements. The current generated CI page's "References to this Resource" section lists itself, Coding, ConceptMap, TerminologyCapabilities, ValueSet, and the ValueSet Supplement extension. Later FHIR-34146 edited the same CodeSystem Identification section for independent canonical URL wording and is already represented on the combined branch; FHIR-17116 shared the 2018 svn implementation commit for a separate CodeSystem.valueSet concern and is also already represented.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current in-scope source and generated CI output already satisfy FHIR-16462's requested reverse-reference clarification, and adding extra local prose would duplicate maintained generated/reference content without changing implementer understanding.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-16462 unless a future publisher or generated-page regression again omits CodeSystem's ValueSet, self/supplement, Coding, ConceptMap, or TerminologyCapabilities references.
