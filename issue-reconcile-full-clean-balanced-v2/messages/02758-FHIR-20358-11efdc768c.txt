FHIR-20358: Audit Condition disease-course extension ownership

Issue request:
FHIR-20358 was a Published/Persuasive with Modification FHIR-core Patient Care issue raised for STU3 and applied for R5. It asked for a way to represent acute versus chronic disease course on Condition; Patient Care declined adding acute/chronic to Condition.clinicalStatus or a new core element, recommended pre-coordinated Condition.code where possible, and approved a standard 0..1 CodeableConcept disease-course extension with an example binding to SNOMED CT descendants of 288524001 Courses.

Initial application:
Core commit b6d04cc87c (GF#20358 Add Condition extension for disease-course) added the Condition disease-course extension support in the old Condition extension spreadsheet, added source/condition/valueset-condition-course.xml, and updated the local SNOMED source. Later core history converted the extension into source/condition/structuredefinition-extension-condition-diseaseCourse.xml, so the issue was applied before this reconciliation.

Additional context:
Core commit dd468d4f17 removed Condition-specific extensions, including condition-diseaseCourse and condition-course, from the R5 core source. In the current core checkout, Condition is still an active resource in source/fhir.ini, but there is no active core condition-diseaseCourse StructureDefinition or condition-course ValueSet entry. The authoritative current definition now lives in the FHIR Extension Pack as http://hl7.org/fhir/StructureDefinition/condition-diseaseCourse, scoped to Condition, 0..1, CodeableConcept, with an example binding to http://hl7.org/fhir/ValueSet/condition-course; that ValueSet includes SNOMED CT concept is-a 288524001. The 2019 Zulip follow-up and 2022 Patient Care minutes both confirm the issue approved/created the condition-course extension, and no conflicting community evidence was found.

AutoFHIR reconciliation:
Published an empty external-repo audit commit. No core source change is appropriate because the requested artifact was historically applied and the current source of truth for this standard extension is outside the core FHIR checkout in the FHIR Extension Pack.

Recommendation:
Keep this audit commit as-is. Future core work should only revisit this if active core Condition text starts referring to the extension incorrectly; substantive changes to the condition-diseaseCourse extension or condition-course ValueSet should be made in the FHIR Extension Pack.
