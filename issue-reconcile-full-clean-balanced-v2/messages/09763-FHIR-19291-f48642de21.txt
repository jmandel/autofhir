FHIR-19291: Audit binding strength display rendering

Issue request:
FHIR-19291 was a Published/Persuasive FHIR-core change request raised against STU3 and applied for R5. It asked that definitions-page binding descriptions display the binding strength display term, such as Required, Extensible, Preferred, or Example; the Jira comment summarized this as adding binding strength into descriptions of bindings.

Initial application:
No current core-source commit was found that explicitly mentions FHIR-19291 or GF#18272. The historical Java definition-page renderer in the FHIR repository delegated dictionary rows to TerminologyNotesGenerator.describeBinding, while the old IG publisher code was later removed from this checkout. Current source no longer contains that renderer; the active build depends on the external org.hl7.fhir:kindling package.

Additional context:
FHIR-18272, the related VHDir ballot comment, was closed Resolved - No Change because the missing strength labels were identified as an IG-publishing issue and the commenter was directed to the tooling/pub tracker that became FHIR-19291. In the current core build, resource definition pages are generated through dictionary macros and the active Observation source carries binding strengths in ElementDefinition.binding.strength. The R5 published Observation definitions page and the current CI build both render terminology bindings with the value set followed by the strength display link, for example Observation.status as (Required), Observation.category as (Preferred), and Observation.code as (Example).

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current built specification already satisfies the requested output, and the remaining rendering logic is owned by the external Kindling/publisher dependency rather than by editable core source files in this checkout.

Recommendation:
Keep this audit commit as-is. Reopen only if a future generated definitions page drops the strength display again; in that case the fix should be made in the active Kindling/publisher renderer, not by editing generated HTML or duplicating binding text in resource source files.
