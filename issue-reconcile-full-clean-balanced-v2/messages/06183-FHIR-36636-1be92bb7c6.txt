FHIR-36636: Audit document immutability wording

Issue request:
FHIR-36636 was a Published FHIR-core Documents issue resolved as Not Persuasive with Modification. It asked for normative SHALL language saying a Document Bundle is immutable, but the FHIR-I decision was not to enforce blanket immutability; instead, the page was to describe document instances as containing frozen resource versions, warn that Bundle changes can invalidate attestation, require implementations to have update/new-document policies with SHOULD language, and clarify that additional documents derived from the same Composition use a different Bundle.identifier.

Initial application:
The issue was applied in the FHIR source by commit 0a729198e07df0fc13d938dd88810142dbabdc6b, later merged through PR #2344, which edited source/documents.html to replace the old absolute "Once assembled into a bundle, the document is immutable" and ambiguous "document id" language with the FHIR-36636 resolution text. No previous Issue-Reconcile-Key commit for FHIR-36636 exists on the combined branch.

Additional context:
The Zulip thread that triggered the issue shows the old text caused confusion about whether immutability was normative and how Bundle.id, Bundle.identifier, and Composition.identifier relate. FHIR-I WGM minutes record the Not Persuasive with Modification disposition. Later Published ballot issues refined the same paragraph: FHIR-38927 removed "frozen" from the general document definition while preserving "specific frozen versions" for document instances, and FHIR-38930 removed the sentence naming strict limitations as "document immutability". FHIR-39121 then made editorial page updates but is not independently decided here.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current source/documents.html is in the active core source tree and now says a FHIR document instance is a Bundle of type document containing specific frozen resource versions, warns that changes may invalidate attestation, gives SHOULD-level policy guidance for updates versus distinct documents, and uses Bundle.identifier for additional documents derived from the same Composition. The obsolete absolute immutability sentence and ambiguous "document id" wording are absent.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for FHIR-36636 unless FHIR-I later decides to strengthen document update policy beyond the current SHOULD guidance.
