FHIR-10236: Audit geolocation extension placement

Issue request:
FHIR-10236 was Published with resolution Persuasive with Modification. The request was to make geocodes usable anywhere Address is used; the accepted resolution was to define a geolocation extension on Address with latitude and longitude components, plus a comment that it can be further extended for identifiers, confidence, altitude, and similar metadata.

Initial application:
Jira records the original application as svn revision 8941. In the imported git history, the pre-extraction core general-extensions spreadsheet already contained the requested geolocation extension rows, including geolocation.latitude, geolocation.longitude, and the requested further-extension comment. The extension was later removed from the R5 core source as part of the standard-extension extraction, rather than disappearing as an unapplied core issue.

Additional context:
The current authoritative definition is in the FHIR Extension Pack, not the core source checkout. It has context Address, defines latitude and longitude slices, and retains the requested comment about identifiers, confidence, altitude, etc. Later FHIR-43290 confirmed that the extension is intended for Address generally and changed wording from Location-specific text to address-focused text; FHIR-42974 only removed dangling notes from the latitude and longitude definitions. Current core source links defined-extension examples through the extension-pack location and uses the canonical geolocation extension in checked-in bundle examples.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core/extension-pack split already satisfies the FHIR-10236 decision, and reintroducing the extension definition into core would conflict with the current ownership model for standard extensions.

Recommendation:
Keep this no-change audit commit as-is. No core follow-up is needed for FHIR-10236; any future changes to the geolocation extension should be made in the FHIR Extension Pack.
