FHIR-20847: Audit target contextType removal

Issue request:
FHIR-20847 was a Published/Persuasive FHIR-I change request for StructureMap asking to remove StructureMap.group.rule.target.contextType, remove the old context/contextType invariant smp-2, update StructureMap.group.rule.target.context to say "Variable this rule applies to", and remove the StructureMapContextType value set.

Initial application:
The issue was initially applied in the historical StructureMap spreadsheet and examples by d43c60049daa4bd4d036016b60f58aab32edf09d, merged as 0828f613fadaefca809837f9959658062092a36, which removed target.contextType, the old target invariant, and the StructureMapContextType value set from the then-authoritative spreadsheet source.

Additional context:
StructureMap is an active current-build resource in source/fhir.ini. The current authoritative source is source/structuremap/structuredefinition-StructureMap.xml, not the removed spreadsheet file. Current source has StructureMap.group.rule.target.context with the requested "Variable this rule applies to" definition and has no target.contextType or StructureMapContextType definition. The only current source references to StructureMap.group.rule.target.contextType are fhir.ini version-diff mappings saying the old element is now implied by context; those are historical migration annotations, not current resource content. A later FHIR-46626 commit reused the key smp-2 for a separate source min/max invariant, so the current smp-2 is not the removed target.contextType invariant.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped StructureMap definition already reflects the Jira resolution, and removing the version-diff mapping or the later unrelated smp-2 invariant would make the current source less accurate.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-20847 unless the work group wants to revisit historical version-diff annotations rather than the current StructureMap definition.
