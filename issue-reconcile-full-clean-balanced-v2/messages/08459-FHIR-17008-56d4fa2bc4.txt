FHIR-17008: Audit canonical versioned search guidance

Issue request:
FHIR-17008 was a Published FHIR-core/fhir-i change request, resolved Persuasive with Modification, asking for clearer guidance about searches using a canonical URL with a pipe-delimited business version such as my-valueset|0.8. The accepted behavior was that this is compatible with composite canonical url+version search: search regards only the latest version, no result is returned when the target resource has no matching business version, and the syntax only applies to uri elements that act as canonical URLs.

Initial application:
The issue appears to have been applied by svn revision 14329, represented in git by b85b7c0892fd3098df3356f0a28fe5952f5a70bc ("GF#17008 + GF#16868: canonical URL updates"), which changed source/references.html. That commit added the requested notes about searching on versioned canonical references and the canonical resource list.

Additional context:
source/fhir.ini maps the Reference type page to references, so source/references.html is active build input for this guidance. Later canonical-reference work, including FHIR-17537/FHIR-30696 canonical-resource target clarifications, FHIR-27920 canonical version scheme guidance, and FHIR-52895 wildcard/partial version matching, refined the same section without reversing FHIR-17008. The current source states that pipe syntax is equivalent to GET ValueSet?url=...&version=0.8, identifies ValueSet.version rather than meta.versionId, limits the search to resources with canonical url elements, and preserves the no-match and latest-version rules. Zulip and Confluence searches for FHIR-17008 and the key canonical-version terms found no conflicting community record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already carries the requested semantic clarification, and adding duplicate prose elsewhere would not improve implementer understanding.

Recommendation:
Keep this audit commit as-is for FHIR-17008. Any future work on wildcard or partial canonical version matching should be handled under the later canonical-version issues, especially FHIR-52895, rather than reopening this STU3 clarification.
