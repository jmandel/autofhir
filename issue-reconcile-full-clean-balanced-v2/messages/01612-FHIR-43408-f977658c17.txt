FHIR-43408: Audit DocumentReference R6 XDS mapping update

Issue request:
FHIR-43408 was Applied/Persuasive for R6 DocumentReference. It requested updating the base DocumentReference to IHE XDS mapping to align with MHD, including repositoryUniqueId/URI in the content.attachment mapping, leaving date unmapped, and keeping creationTime on content.attachment creation.

Initial application:
The 2024 commit d63adb6a17972d47bde74e7377febe531b104a9a updated current DocumentReference source for the June 2024 mapping work. In the active StructureDefinition source it added DocumentEntry.repositoryUniqueId to the content.attachment XDS aggregate mapping while preserving the other requested XDS fields.

Additional context:
FHIR-19685 already established that DocumentEntry.creationTime belongs under content.attachment.creation rather than DocumentReference.date. OO minutes and Jira comments for FHIR-43408 record work-group support for accepting the mapping update with some DocumentReference elements intentionally left blank because XDS has no defined slot for them.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current source has date without an XDS mapping and content.attachment mapped to DocumentEntry.mimeType, languageCode, repositoryUniqueId, URI, size, hash, title, and creationTime, which matches the applied FHIR-43408 table at the current source level.

Recommendation:
Keep this audit commit as-is. Future work should avoid adding speculative XDS mappings for elements the FHIR-43408 discussion intentionally left blank unless a new work-group decision defines them.
