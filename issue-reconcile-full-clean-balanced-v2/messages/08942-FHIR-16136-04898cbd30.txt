FHIR-16136: Audit Observation focus modifier history

Issue request:
FHIR-16136 was a Published / Not Persuasive with Modification Orders and Observations change request for STU3 asking whether Observation.focus should be a modifier because ignoring focus can make an Observation collected in one subject's record appear to be about the wrong entity. The STU3 resolution did not mark focus as a modifier at that time; it instead clarified Observation.subject, requested examples for subject/focus cases, moved subject guidance into Observation documentation, and added a clinical safety note about not being surprised by focus.

Initial application:
The issue was applied before this reconciliation. Git-svn commit 8da41eb1e5b69c9ac8d6b759ba1c88e9d892b881, "GF#16134, GF#16136", updated the old Observation spreadsheet subject short name, definition, and comment to say that focus or code specifies the actual focus when it differs from subject. Git-svn commit 19fc6ffc60591f5ab930855904c55bcdb2d7006e added the Observation.focus clinical safety checklist item. After the source migration, the relevant current inputs are source/observation/structuredefinition-Observation.xml, source/observation/observation-notes.xml, and source/safety.html.

Additional context:
Later final decisions changed the correct current interpretation. FHIR-16188 clarified the general isModifier rule, FHIR-37736 resolved to make Observation.focus a modifier while clarifying related-person focus cases, and FHIR-45259 directly requested Observation.focus modifier treatment and was Applied/Persuasive for R6. Those later Observation.focus issues are already represented on the combined branch, so this commit does not duplicate them. Current source/fhir.ini keeps Observation active, and current Observation source marks Observation.focus as a modifier with a reason explaining that it changes who is the target of the observation.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. The current source preserves the FHIR-16136 subject/focus clarification and safety guidance, while the apparent mismatch with the original no-modifier outcome is superseded by later Applied/Persuasive Observation.focus decisions. Removing the current isModifier flag would regress FHIR-37736/FHIR-45259, and adding more local prose would be redundant with the current StructureDefinition, Observation notes, and safety checklist guidance.

Recommendation:
Keep this audit commit as-is. No core FHIR source follow-up is needed for FHIR-16136; future review of Observation.focus modifier semantics should start from the later FHIR-37736 and FHIR-45259 decisions rather than reverting to the STU3 disposition.
