FHIR-30088: Audit Python library handoff

Issue request:
FHIR-30088 was Published with a Persuasive with Modification resolution for R5. The issue asked to add the fhir.resources and fhir-py Python libraries to the downloads page Reference Implementations section; the accepted modification was to move reference implementation/library listings to the HL7 Confluence Open Source Implementations page and organize them there by language and implementation type.

Initial application:

That commit replaced the local downloads-page Reference Implementations rows, including the Python row, with a Confluence Open Source Implementations link. Earlier Zulip discussion shows the issue was filed from the Python stream and that Ilya Beda updated the Confluence Open Source Implementations page. Later FHIR-31735 commits 472abf78c495c2ae44924d499be7434ed50788d0 and e404ccd07129409bf907b904ae62ded6c82d28bf moved additional mutable tools, server, and library lists out of the core pages and into Confluence-backed registries.

Additional context:
Current source/downloads.html and source/implsupport-module.html are active build pages, as shown by source/hierarchy.xml and publish.ini. The current downloads page links implementation tooling to the FHIR Tools Registry, while the Implementation Support module links developers to the Open Source Implementations page for reference implementations/libraries. Existing combined-branch audits for FHIR-31735, FHIR-31741, and FHIR-33980 already record the same Confluence-handoff pattern for mutable tools and SDK/library listings.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already implements the accepted direction by avoiding per-language Python/library rows in core and pointing implementers to maintained Confluence pages. Reintroducing fhir.resources or fhir-py directly in source/downloads.html or source/implsupport-module.html would reverse the work-group decision and recreate a stale mutable inventory in the specification source.

Recommendation:
Keep this no-change audit commit as-is for the core specification. If the Python library entries or implementation-type organization need updates, maintain them on the Confluence Open Source Implementations page rather than in the FHIR core source checkout.
