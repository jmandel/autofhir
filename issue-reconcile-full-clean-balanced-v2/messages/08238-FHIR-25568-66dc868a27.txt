FHIR-25568: Audit MetadataResource inherited snapshot fields

Issue request:
FHIR-25568 is a Published/Persuasive FHIR-core technical correction for MetadataResource. It reported that the R5 draft MetadataResource StructureDefinition was declared as a CanonicalResource but its JSON snapshot omitted inherited CanonicalResource fields such as url, status, date, and publisher; the resolution says those fields should definitely appear in the snapshot.

Initial application:
No source commit explicitly mentioning FHIR-25568 or 25568 was found. FHIR-I minutes on 2020-06-08 recorded the tracker as an auto-approved technical correction that would also be fixed in R4. Current source later represents MetadataResource as an active resource-infrastructure interface and as a StructureDefinition specializing CanonicalResource, and R5/current generated snapshots now include the inherited CanonicalResource elements.

Additional context:
FHIR-28604 is a later Published/Persuasive with Modification same-artifact issue that added non-inherited MetadataResource common elements such as topic, author, editor, reviewer, endorser, and relatedArtifact via commit ce1c547c3e0e. That later cleanup is relevant context, but it is separate from the FHIR-25568 inherited CanonicalResource snapshot defect.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative source is in current build scope, declares MetadataResource as based on CanonicalResource, and publication-surface checks of both R5 and the current build found every CanonicalResource child element present in the MetadataResource snapshot.

Recommendation:
Keep this no-change audit. Do not add duplicate differential elements for inherited CanonicalResource fields; they are already generated into the snapshot, and duplicating them in the MetadataResource differential would risk long-term drift. Revisit only if a future generated snapshot again omits inherited CanonicalResource elements.
