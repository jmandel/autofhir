FHIR-44678: Audit ActorDefinition baseDefinition rename

Issue request:
FHIR-44678 was an Applied/Persuasive FHIR-I change request for ActorDefinition asking to rename ActorDefinition.derivedFrom because the old name did not communicate inheritance; the accepted resolution was to rename it to baseDefinition.

Initial application:
The Jira comment points to HL7/fhir#3297. Local history shows commit aa0514a3b7, merged by e404d485c7, changed the ActorDefinition element id and path from ActorDefinition.derivedFrom to ActorDefinition.baseDefinition in source/actordefinition/structuredefinition-ActorDefinition.xml.

Additional context:
ActorDefinition is an active current-build resource in source/fhir.ini. The only remaining ActorDefinition.derivedFrom reference in current source is the [r5-r6-changes] migration map entry ActorDefinition.derivedFrom=@ActorDefinition.baseDefinition, added later for cross-version QA/conversion rather than as a live R6 element. The later applied FHIR-44478 clarification on the same element updated the short/definition to say Parent actor definition and describe the referenced ActorDefinition as a super-type, which reinforces the inheritance semantics that motivated FHIR-44678.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current ActorDefinition StructureDefinition already exposes ActorDefinition.baseDefinition, not ActorDefinition.derivedFrom, and the retained old name is only a version-change mapping from the R5 path to the R6 path.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed for FHIR-44678 unless future review decides to change the broader ActorDefinition inheritance model rather than the already-applied element name.
