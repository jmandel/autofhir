FHIR-24696: Audit Device record status wording

Issue request:
FHIR-24696 was Published with a Persuasive OO resolution for R5. It asked to update the definitions and value sets for Device.status and Device.statusReason so they clearly focus on the status of the Device record, not the operational or physical state of the device.

Initial application:
The issue was initially applied in git commit b9623f940a, which changed the then-authoritative Device spreadsheet so Device.status described the record rather than device availability and changed Device.statusReason from operational availability values to record-status reasons. Later source conversion and R5/R6 Device work moved the authoritative content into source/device/structuredefinition-Device.xml and companion terminology files.

Additional context:
The September 2019 OO WGM minutes record the status-model discussion and the 13-0-2 motion that became FHIR-24696. Later published/applied Device issues refined the same source area: FHIR-32557 removed Device.statusReason and added Device.availabilityStatus for device availability, FHIR-34542 restored a record-oriented short and value set description, and FHIR-53243 intentionally re-added the unknown Device.status code using the R4 definition. The combined branch already contains focused reconciliation commits for FHIR-32557 and FHIR-34542, and there are no later combined-branch Device diffs missing from this worktree.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current build-scope Device source already says Device.status is the Device record status, the Device.status binding and value set are record-oriented, Device.statusReason is absent, and Device.availabilityStatus carries the physical availability distinction. The remaining unknown code wording was explicitly reintroduced by the later Applied FHIR-53243 decision, so changing it under FHIR-24696 would override newer WG intent.

Recommendation:
Keep this no-change audit. If the WG wants the re-added unknown code definition to say "device record" explicitly, handle that as follow-up to FHIR-53243 or a new issue rather than reopening the older FHIR-24696 application.
