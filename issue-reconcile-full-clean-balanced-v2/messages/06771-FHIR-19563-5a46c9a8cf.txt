FHIR-19563: Audit DeviceRequest intent binding URL

Issue request:
FHIR-19563 is Applied/Persuasive for the OO work group. It reported that the STU3 DeviceRequest base profile bound DeviceRequest.intent to the generated-page URL http://build.fhir.org/valueset-request-intent.html and asked that the STU3 validation package/downloads use the canonical value set URL http://hl7.org/fhir/ValueSet/request-intent.

Initial application:
No git commit was found that mentions FHIR-19563, and Jira's resolution says the issue appeared already fixed. Git history shows the underlying DeviceRequest spreadsheet error was corrected before the Jira was filed: commit c82cf3a67bd changed the RequestIntent binding in source/devicerequest/devicerequest-spreadsheet.xml from the build.fhir.org page URL to the canonical ValueSet URL. A stale generated release3 bundle still carried the old URL in source/release3/profiles-resources.xml until that retired generated artifact was removed from core source by 5c0494aacf.

Additional context:
DeviceRequest is active in the current build through source/fhir.ini, and the current authoritative DeviceRequest StructureDefinition source binds DeviceRequest.intent to http://hl7.org/fhir/ValueSet/request-intent. External checks of the current STU3 publication surface at hl7.org/fhir/STU3 show devicerequest.profile.json, profiles-resources.xml/json, and definitions.xml/json packages contain the canonical URL and no occurrences of the bad build.fhir.org URL. Confluence OO minutes reference the issue in the January 2020 DeviceRequest block-vote trail, and no relevant Zulip discussion was found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source and the current STU3 published validation/download artifacts already satisfy the requested correction, and editing retired release3 generated artifacts or adding redundant current-source prose would not improve the specification.

Recommendation:
Keep this no-change audit commit. No follow-up source work is needed unless a human discovers a separate, currently distributed STU3 package mirror that still contains the obsolete build.fhir.org binding URL.
