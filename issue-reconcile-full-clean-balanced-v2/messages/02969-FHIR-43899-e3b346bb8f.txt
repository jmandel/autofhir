FHIR-43899: Audit actor capability inversion fix

Issue request:
FHIR-43899 was Applied/Persuasive for R6 by FHIR-I. It asked to correct the inverted ActorDefinition/CapabilityStatement relationship by removing ActorDefinition.capabilities and adding a core CapabilityStatement element that lets a CapabilityStatement assert compliance with one or more ActorDefinitions.

Initial application:
The issue was applied by HL7/fhir PR #3336. Commit db866c231910b3f472173d237ce125a64aa96da4 removed ActorDefinition.capabilities from source/actordefinition/structuredefinition-ActorDefinition.xml and added CapabilityStatement.actorDefinition to source/capabilitystatement/structuredefinition-CapabilityStatement.xml; commit 36baeea957b69428a397ec6c6de47e8a306ccc41 added isSummary to the new element; merge commit 3078027a407d7c5ea1b145b42d912fb340154353 landed the PR.

Additional context:
A Zulip implementation thread for FHIR-43899 records Gino Canessa confirming that CapabilityStatement.actorDefinition should be 0..* because one CapabilityStatement can support multiple actors. FHIR-I minutes from 2024-01-22 record the 15-0-0 persuasive motion, and 2024-04-22 minutes plus FHIR-42975 confirm that the intended solution is a CapabilityStatement-to-ActorDefinition pointer rather than an implementationGuide extension. FHIR-44471 had already aligned ActorDefinition introduction text with CapabilityStatement references.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current combined branch has ActorDefinition as an active resource, has no ActorDefinition.capabilities element in the current ActorDefinition StructureDefinition, has CapabilityStatement.actorDefinition as a 0..* canonical to ActorDefinition with isSummary=true, and records the R5-to-R6 removal/addition in source/fhir.ini.

Recommendation:
Keep this audit commit as-is. No further core source work is recommended for FHIR-43899 unless the work group later wants different wording for the CapabilityStatement.actorDefinition definition; current source implements the approved direction and the later 0..* clarification.
