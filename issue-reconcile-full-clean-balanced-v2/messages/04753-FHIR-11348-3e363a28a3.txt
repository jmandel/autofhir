FHIR-11348: Audit ServiceRequest doNotPerform

Issue request:
FHIR-11348 is a Published/Persuasive with Modification Patient Care issue asking to add ProcedureRequest.doNotPerform as a 0..1 boolean modifier, with default false semantics, prohibition examples and qualifiers, and guidance that double negation reinforces prohibition rather than reversing meaning.

Initial application:
The same Patient Care decision is recorded in FHIR-9335/GF#9335, and git commit f3f2ad2c4b applied it to ProcedureRequest in January 2017 by adding ProcedureRequest.doNotPerform with the requested cardinality, modifier flag, examples, qualifier guidance, default false semantics, and double-negation comment. ProcedureRequest was then renamed/merged into ServiceRequest by later history, including 06bd9f6ffe.

Additional context:
The current build scope has ServiceRequest active and ProcedureRequest retired/merged into ServiceRequest. The active ServiceRequest source still contains ServiceRequest.doNotPerform with the seed's intended semantics. Later FHIR-13468 expanded doNotPerform into the Request pattern and added stricter pattern-level guidance against pre-coordinated double negation; ServiceRequest has an explicit resource-specific divergence that preserves the older Patient Care wording. That broader harmonization is outside this seed and should not be changed here without a separate work-group decision.

AutoFHIR reconciliation:
No source change was made. The current active ServiceRequest source already carries forward the required doNotPerform element and guidance from ProcedureRequest, and editing retired ProcedureRequest source would be out of current build scope.

Recommendation:
Keep this audit commit as-is for FHIR-11348. If a future work group wants ServiceRequest's historical double-negation interpretation aligned with the later Request pattern prohibition, handle that as a separate targeted issue rather than as this DSTU2 ProcedureRequest application audit.
