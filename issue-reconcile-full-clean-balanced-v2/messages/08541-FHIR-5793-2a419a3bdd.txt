FHIR-5793: Audit removed LOINC version note

Issue request:
FHIR-5793 was Published with a Persuasive with Modification resolution for the Vocabulary work group. It asked to remove notes saying LOINC should have a version because some LOINC code definitions had changed; the accepted 2015 resolution was to remove that statement after discussion with Regenstrief and additional research.

Initial application:
The issue was applied in git-svn commit e53e2ef72d0f6c0ac68d4cc67ba281c33fcde2a0, "#5793 - remove notes about LOINC versions", corresponding to svn revision 4750. That commit removed LOINC from the datatypes list of code systems that should always carry versions and replaced the ValueSet versioning example that said LOINC had re-defined meanings.

Additional context:
Current build scope includes the active ValueSet and CodeSystem resources in source/fhir.ini, and the datatype/code-system versioning prose remains in current source. The current Coding datatype guidance still says versions should be exchanged when code-system definitions are not consistent across releases, but its explicit examples are SNOMED CT national releases and ICD, not LOINC. Current CodeSystem versioning prose likewise uses SNOMED CT rather than the rejected LOINC changed-definition rationale. Remaining LOINC examples discuss ordinary version, lockedDate, expansion, and terminology metadata mechanics; they do not restate that LOINC changed definitions or that LOINC should always be versioned for that reason. No Zulip or Confluence evidence was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No current source edit is needed because the statement FHIR-5793 asked to remove is absent from current source and the surviving LOINC-version text is semantically separate implementation guidance.

Recommendation:
Keep this audit commit as-is. Future work should avoid reintroducing a LOINC-specific changed-definition rationale unless the Vocabulary work group records a new decision.
