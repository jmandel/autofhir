FHIR-32341: Audit Encounter.class hierarchy application

Issue request:
FHIR-32341 was Published with resolution Persuasive with Modification for R5. It asked PA to make Encounter.class less ambiguous by changing it to 0..* CodeableConcept, using a Preferred binding, and creating a smaller Encounter class value set with inpatient, outpatient, observation, emergency, virtual, and community-style base concepts from v3 ActEncounterCode.

Initial application:
The change was already applied in source before this reconciliation. FHIR-32342 first changed Encounter.class to CodeableConcept. Commit 868cd2a065 then applied FHIR-32341 by changing Encounter.class from 1..1 to 0..* and changing the binding from extensible to preferred. Commit bf06a893cc moved the binding from the broad v3-ActEncounterCode value set to the new THO EncounterClass value set. Later FHIR-39147 corrected the canonical value set URL to http://terminology.hl7.org/ValueSet/encounter-class.

Additional context:
Encounter is an active resource in source/fhir.ini, so source/encounter/structuredefinition-Encounter.xml is in the current build. The current source now defines Encounter.class as 0..* CodeableConcept with a preferred binding to http://terminology.hl7.org/ValueSet/encounter-class. The local THO package for that value set contains v3 ActCode concepts IMP, AMB, OBSENC, EMER, VR, and HH. UP-344 records the terminology-side implementation of the new encounter-class value set, and duplicate FHIR-32974 was closed after participants accepted that FHIR-32341 and the new value set addressed the concern. Later PA minutes in 2025 describe this as an intentionally relaxed 0..* solution for mixed real-world Encounter.class concepts.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core source already reflects the final FHIR-32341 decision, and the remaining value set content is owned by THO/UTG rather than by a FHIR core source file. Adding redundant core prose would not change conformance and would risk drifting from the terminology source of truth.

Recommendation:
Keep this no-change audit commit. If PA later wants more specific class concepts beyond the current THO encounter-class set, handle that as a terminology/UTG update and then update the core binding only if the canonical target changes.
