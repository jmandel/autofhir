FHIR-19755: Audit AuditEvent purpose search parameter

Issue request:
FHIR-19755 is a Published/Persuasive FHIR-core AuditEvent change request for R5. It asked for an AuditEvent query parameter for the use case of finding patient-data accesses for a specific purposeOfUse, likely as one parameter searching both the then-current AuditEvent.purposeOfEvent and AuditEvent.agent.purposeOfUse elements.

Initial application:
The change appears to have been applied in commit d417c5d674a4a6b7e4af8d9ef15b7d55d3b4d3e8, whose message includes GF#19755 and whose AuditEvent spreadsheet added a Search worksheet row with code purpose and expression AuditEvent.purposeOfEvent | AuditEvent.agent.purposeOfUse. The later source rework carried the search parameter into source/auditevent/bundle-AuditEvent-search-params.xml.

Additional context:
FHIR-32515 later changed the relevant AuditEvent element names and semantics from purposeOfEvent/agent.purposeOfUse to authorization/agent.authorization while preserving PurposeOfEvent and PurposeOfUse aliases. source/fhir.ini maps the legacy names to the current fields, and AuditEvent is an active resource in the current build. The current AuditEvent search parameter still uses query code purpose and now searches AuditEvent.authorization | AuditEvent.agent.authorization. The originating Zulip GPDR thread confirms this was exactly the missing query-parameter use case; Confluence and broader Jira searches found no conflicting later decision for FHIR-19755.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source already contains the requested AuditEvent purpose token search parameter over both current authorization fields, so editing would be redundant rather than a correction.

Recommendation:
Keep this no-change audit commit as-is. No FHIR-19755 follow-up is needed unless a future work group decision separately changes AuditEvent authorization search naming.
