FHIR-20906: Align Meta.source summary with Provenance who

Issue request:
FHIR-20906 was a Published/Persuasive with Modification FHIR-I change request raised against STU3 and applied for R5. It reported that describing Meta.source only in terms of Provenance.entity.what did not fit cases where the source of information is better represented by Provenance.agent.who, and the approved resolution was to say Meta.source can correspond to who or what while leaving IG-specific constraints to Provenance rather than fixing Meta.source in HL7-authored IGs.

Initial application:
The issue was initially applied by git commit 398a20214d22c6442704b8b2798ebde0d2f7439e, which changed the Meta.source spreadsheet comment in source/datatypes/meta.xml to mention Provenance.entity.what[x] or Provenance.agent.who[x]. The closely related FHIR-20688 application commit 9edd51287b10ae90910262893cc060ad9df66f0b then generalized Meta.source source-granularity wording, and the later FHIR-15659 reconciliation commit 8b8c20776bea89c69032189b5a2260d8d7e0f9b2 updated obsolete Provenance choice names to current Provenance.entity.what and Provenance.agent.who. Current source/datatypes/meta.xml already contains the detailed who-or-what statement, but the active Resource metadata summary in source/resource/resource-notes.xml still mentioned only an implied Provenance.entity.role.

Additional context:
FHIR-20688 supports keeping Meta.source broad enough for a resource, abstract identifier, service endpoint, or other data source, while FHIR-49878 later clarified the same element as the resource's data source rather than only a source system. FHIR-I minutes for 2019-06-17 record the vote and exact FHIR-20906 resolution. A later Zulip implementers thread, "meta.source clarification", shows the same practical ambiguity: John Moehrke read Meta.source as closer to Provenance.agent.who in some cases, while Lloyd McKenzie emphasized that it is a broad URI for where data came from. source/fhir.ini lists Meta as an active datatype and Resource as active infrastructure, so both inspected source files feed the current build.

AutoFHIR reconciliation:
Updated source/resource/resource-notes.xml so the Resource metadata summary now mirrors the detailed Meta.source definition: the possible implied Provenance role can be entity.role or agent.role, and the source may correspond to Provenance.entity.what or Provenance.agent.who while still allowing a more general or abstract reference. No change was made to the nearby common-derivation paragraph because that paragraph specifically discusses Provenance.entity.what with entity.role=derivation, not the general Meta.source mapping.

Recommendation:
Keep this source fix. The core spec now consistently conveys the approved who-or-what interpretation in both the detailed Meta definition and the active Resource metadata summary; any separate IG Publisher guidance about how HL7-authored IGs should constrain Provenance remains outside this core source change.
