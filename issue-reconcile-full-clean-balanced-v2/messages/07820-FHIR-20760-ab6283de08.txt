FHIR-20760: Correct relevantHistory guidance terminology

Issue request:
FHIR-20760 is a Published/Persuasive FHIR-I change request asking that the workflow pages explain the .relevantHistory use of Provenance. The accepted resolution called for a few paragraphs and examples covering how relevantHistory works, that it may draw on Provenance for multiple resources, why only some Provenance is deemed relevant, and how relevantHistory is created or updated.

Initial application:
The issue was applied by ade95b75ec, which added Event.relevantHistory to the Event pattern and added Event and Request history guidance in source/event/event-spreadsheet-notes.xml and source/request/request-spreadsheet-notes.xml. The current build includes the workflow logical models and pages through active source/fhir.ini [logical] entries and source/hierarchy.xml, and the current Provenance page links back to the Event and Request relevantHistory guidance. The applied prose still contained two direct terminology defects in the explanatory sections: a misspelling of Provenance and references to nonexistent recentHistory where the guidance means relevantHistory.

Additional context:
The linked Security issue FHIR-20758 asked for matching Provenance-page guidance and depended on FHIR-20760; current source/provenance/provenance-notes.xml contains that Relevant History Provenance note and links to the Event and Request history anchors. The originating Zulip thread explains the intended semantics: relevantHistory is a curated subset for key status/history events, not all Provenance, and it normally cannot include the most recent change because that Provenance record is created after the update. FHIR-27794 later refined ownership and explanatory text for the Provenance Relevant History profile, and current source/provenance/structuredefinition-profile-provenance-relevant-history.xml still describes the profile as guidance for Event and Request relevantHistory use.

AutoFHIR reconciliation:
This commit corrects the active Event and Request pattern notes so they refer to Provenance and relevantHistory consistently in the paragraphs explaining filtered Provenance and the current-change update process. It intentionally does not add new explanatory sections because the existing Event, Request, Provenance, and profile guidance already implements the substantive FHIR-20760 request.

Recommendation:
Keep this source-changing reconciliation commit. No additional core FHIR source work is recommended for FHIR-20760; FHIR-20758 and FHIR-27794 remain useful related history but are not decided by this commit.
