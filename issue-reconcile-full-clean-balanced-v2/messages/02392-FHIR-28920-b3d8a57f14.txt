FHIR-28920: Audit Evidence certainty streamlining

Issue request:
FHIR-28920 was Published/Persuasive for R5 from the CDS work group. It asked to streamline Evidence.certainty by replacing the older non-recursive certainty subcomponent pattern with a repeating Evidence.certainty backbone containing description, note, type, rating, rater, and recursive subcomponent, with unified EvidenceCertaintyType and EvidenceCertaintyRating bindings and updated element descriptors.

Initial application:
The issue appears to have been initially applied in f7c29e888c, which changed the ASTRAL Evidence example from evidence-quality/certainty-subcomponent systems and certaintySubcomponent elements to unified certainty-type/certainty-rating codes and subcomponent. The R5 source rework in 33b409a4b6 and bcd36a75b4 carried the same model into source/evidence/structuredefinition-Evidence.xml with Evidence.certainty 0..*, type/rating/rater, and subcomponent as a contentReference back to Evidence.certainty. Evidence is active in source/fhir.ini, so these source checks are in current build scope.

Additional context:
Later final Jira decisions explain why current source no longer exactly matches every literal detail in the 2020 request. FHIR-39572 changed Evidence.certainty.description from string to markdown. FHIR-48987 changed Evidence.certainty.rater from 0..1 to 0..* and a follow-up commit corrected a temporary mistaken rating cardinality change. FHIR-39632 moved duplicated terminology definitions out of core to THO, and FHIR-53156 intentionally changed Evidence certainty bindings to example strength with comments pointing to the EBMonFHIR IG for stricter value sets. FHIR-28921 copied this structure into cqf-certainty but is already represented on the combined branch by a separate external-repo audit commit.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current active Evidence source already has the recursive certainty model, current examples use subcomponent with the unified certainty type/rating systems, and no stale certaintySubcomponent source remains. The remaining differences from FHIR-28920 are later applied decisions rather than missed application work.

Recommendation:
Keep this audit commit as-is. Do not revert the later markdown, repeatable rater, THO terminology, or example-binding updates as part of FHIR-28920; any future tightening of Evidence certainty value sets should be handled through the EBMonFHIR/terminology path referenced by FHIR-53156.
