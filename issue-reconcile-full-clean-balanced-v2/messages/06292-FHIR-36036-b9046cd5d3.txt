FHIR-36036: Audit BackboneElement id fhir-type correction

Issue request:
FHIR-36036 was a Published/Persuasive FHIR-I technical correction raised against R4B for backbone element id metadata. The reporter showed generated resource snapshots such as Patient.contact.id carrying structuredefinition-fhir-type valueUrl "id" even though the inherited Element/BackboneElement id is a bare FHIRPath System.String constrained as the FHIR string flavor. Jira records the resolution as a tooling issue and points to HL7/kindling#69.

Initial application:
No current FHIR core source commit directly carrying FHIR-36036 was found. The application trail is the external Kindling pull request HL7/kindling#69, merged 2022-04-07, whose body says it corrected FHIRtype extension values for FHIR-36036 and whose first commit is titled with the Jira URL. The active FHIR source already defines Element.@id as type string, and BackboneElement derives from Element rather than declaring its own id row.

Additional context:
FHIR-25274 documents the intended FHIRPath System.String plus structuredefinition-fhir-type pattern, while FHIR-25262 keeps Resource.id distinct with fhir-type id. FHIR-I minutes on 2022-02-28 record FHIR-36036 as a technical correction/tooling issue. A later Zulip thread records Grahame's clarification that Element.id is different from Resource.id and is allowed to be a valid string with no spaces. Later same-family issues FHIR-38684 and FHIR-41183 are already represented on the combined branch and independently audit that current Element.id and ElementDefinition.id output now emits string. Historical R4B/R5 type-profile artifacts can still show BackboneElement.id as id, but current build output for BackboneElement.id and resource backbone ids is corrected.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source has Element.@id as string, BackboneElement inherits that source row, and current build.fhir.org Patient.contact.id, BackboneElement.id, Element.id, and ElementDefinition.id all emit structuredefinition-fhir-type valueUrl "string". Editing current FHIR source would duplicate a generator/tooling fix or alter historical release cache data rather than fixing the current specification.

Recommendation:
Keep this no-change audit for FHIR-36036. Do not change Resource.id under this issue, and do not edit tools/history release cache files solely to rewrite historical R4B/R5 metadata; any future historical technical-correction publication should be handled through the publication/generator path.
