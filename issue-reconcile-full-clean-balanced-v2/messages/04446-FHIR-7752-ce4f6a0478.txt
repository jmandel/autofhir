FHIR-7752: Audit Contract signer type value set

Issue request:
FHIR-7752 was a Published/Persuasive Financial Management change request from the DSTU1 ballot asking to replace the Contract signer-type value set text that described ASTM digital signature purposes with a FHIR Contract Signer Type value set. The recorded resolution clarified that the issue was specific to Contract signer roles, not Signature.type, and says the change had been applied.

Initial application:
The historical application is visible in commit cd16d2ab019e19045b5a0bd96722731f4211ef1c, which explicitly cites CP 7752 and 5391 and changes source/contract/valueset-contract-signer-type.xml from an ASTM Signature Type Codes value set into Contract Signer Type Codes maintained by Financial Management.

Additional context:
Contract is active in the current build via source/fhir.ini. Current Contract.signer.type and the ConsentDirective profile bind to http://hl7.org/fhir/ValueSet/contract-signer-type, and that value set is titled Contract Signer Type Codes with a Contract signer-role description and terminology.hl7.org contractsignertypecodes system. Signature.type remains separately bound to the Signature Type Codes value set, matching the Jira resolution's instruction not to treat signature purpose as signer role. FHIR-5391 is a duplicate of this request. Later Contract signer tickets FHIR-13053 and FHIR-20344 remain unresolved/Triaged and do not provide a final decision that changes this reconciliation.

AutoFHIR reconciliation:
No source change was made. The current authoritative Contract source already expresses the requested role-vs-signature separation, and editing the remaining Signature Type vocabulary would contradict the issue resolution's stated scope.

Recommendation:
Keep this audit commit as-is. Handle unresolved later clarification/modeling requests such as FHIR-13053 or FHIR-20344 only through their own work-group decisions, not as part of FHIR-7752.
