FHIR-24688: Align Coverage subscriberId model cardinality

Issue request:
FHIR-24688 was a Published Financial Management change request for R5 asking to update Coverage.subscriberId cardinality from 0..1 to 0..* so a single Coverage can carry multiple subscriber identifiers with different Identifier.period values.

Initial application:
The authoritative Coverage StructureDefinition already has Coverage.subscriberId min 0, max *, and type Identifier. Git history shows commit 720258c80a9 changed the Coverage StructureDefinition max from 1 to *, but it was a broad "FHIR code updates" commit without the Jira key. The active FHIR model-definition Library still exposed Coverage.subscriberId as a scalar immediately before this reconciliation, so the initial application missed this parallel model metadata surface.

Additional context:
FHIR-24638 is the same Coverage.subscriberId change family and established the Identifier type. The preceding AutoFHIR commit aligned the stale model-info type with FHIR-24638, leaving this commit to represent the FHIR-24688 cardinality change. Coverage and Library are active current-build inputs, publish.ini publishes the readable model-info content, and source/library/list-Library-examples.xml lists the FHIR Model Definition Library as a built Library example. Direct Zulip and Confluence searches did not find a conflicting community decision for FHIR-24688.

AutoFHIR reconciliation:
Changed Coverage.subscriberId in the FHIR model-definition Library from a scalar Identifier element to a ListTypeSpecifier of FHIR.Identifier, and refreshed the embedded model-info attachment in source/library/library-fhir-model-definition.xml for the same Coverage entry. No change was needed to the Coverage StructureDefinition or diagram because they already show Identifier [0..*].

Recommendation:
Keep this commit as-is. It completes the Published FHIR-24688 cardinality change in the remaining current-build model metadata while preserving the already-correct authoritative Coverage definition.
