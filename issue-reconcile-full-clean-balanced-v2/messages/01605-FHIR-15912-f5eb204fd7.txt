FHIR-15912: Audit PractitionerRole subject support

Issue request:
FHIR-15912 was Published/Persuasive for STU3. It asked to add PractitionerRole as an allowed MeasureReport.subject target because Practitioner alone does not identify the practitioner's organization, and the final resolution agreed to add PractitionerRole to the possible SubjectTypes for both Measure and MeasureReport.

Initial application:
The issue was applied in SVN 14046, represented in git as e169985949ad77cfed6c6e86ee8036a90f98136e. That commit explicitly mentioned GF#15912 and added PractitionerRole to the then-authoritative Measure and MeasureReport subject spreadsheet definitions while also applying several neighboring MeasureReport changes.

Additional context:
Measure and MeasureReport are active resources in source/fhir.ini. The current StructureDefinition XML has replaced the old spreadsheet source and already includes PractitionerRole in MeasureReport.subject. The later FHIR-40422 group-level subject work added MeasureReport.group.subject, and that current target list also includes PractitionerRole. Measure.subject[x] and Measure.group.subject[x] now express subject type with the participant-resource-types binding rather than a direct PractitionerRole Reference target list; the current source value set is build-filled from participant resource types, and the checked R5 generated expansion includes PractitionerRole.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative MeasureReport source already permits PractitionerRole as a subject, the related group-level MeasureReport subject surface is aligned, and Measure's current subject-type representation already covers PractitionerRole through the participant-resource-types binding. Adding another editorial example would be redundant and could drift from the binding.

Recommendation:
Keep this audit commit as-is. No current FHIR core source follow-up is needed for FHIR-15912 unless a work group wants to revise the broader Measure subject binding or make the example text exhaustive, which is outside this issue.
