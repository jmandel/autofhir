FHIR-13337: Request review for default/missing split

Issue request:
FHIR-13337 is a Published/Persuasive STU3 FHIR-I issue asking that the ElementDefinition Missing Elements page split its combined list of default values and meaningWhenMissing values into separate default-value and missing-meaning lists. The later Jira comment that mattered said this was no longer needed once default values had been removed.

Initial application:
No git commit explicitly mentions FHIR-13337. Historical git-svn commits dd83fb1f and 72143f2f removed default values and default-value examples from ElementDefinition source and added the current guidance that FHIR resources and datatypes do not define default values, matching the Jira comment's no-action rationale rather than implementing a separate generated list.

Additional context:
The same default/missing policy family is already represented on the combined branch. FHIR-15121 fixed one remaining invariant issue and records the broader decision that defaultValue[x] is not for FHIR resources, while FHIR-13482 later restored defaultValueBoolean=false on the current ImplementationGuide isExample successor fields. Current source/fhir.ini actively builds both ElementDefinition and ImplementationGuide. Source/elementdefinition.html still exposes only the single <%missing-element-list%> placeholder, and the STU3 rendered page shows that this placeholder historically emitted default values and meaningWhenMissing entries together. No separate editable default-value-list placeholder was found in this source tree.

AutoFHIR reconciliation:
This is an empty human-review audit commit. I did not make a source edit because a safe source fix requires resolving the already-published related decisions and/or build tooling support: either keep the restored FHIR-13482 defaults and add true separate generated lists, or apply the FHIR-15121 no-FHIR-resource-default policy and leave no default list to split. A static hand-written list in elementdefinition.html would risk drift and may duplicate generated output.

Recommendation:
Revisit with FHIR-I and the build tooling owner. If the ImplementationGuide default values restored for FHIR-13482 remain intentional, add generator/template support for separate defaultValue and meaningWhenMissing lists and update the nearby narrative. If the FHIR-15121 policy should take precedence, remove the resource defaults instead; then FHIR-13337 remains satisfied by the no-defaults outcome.
