FHIR-37456: Record search-parameter-use extension in Extension Pack

Issue request:
FHIR-37456 was a Published/Persuasive with Modification FHIR-I R5 change request asking how a CapabilityStatement should represent an _include/_revinclude search parameter when the underlying SearchParameter is not supported as a standalone search. The accepted resolution was to create a search-parameter-use extension that lets implementers declare whether a CapabilityStatement resource search parameter is allowed for standalone search, _include, or _revinclude use.

Initial application:
The question originated in the linked #conformance Zulip thread, where Lloyd McKenzie confirmed that FHIR did not then have a good way to declare include-only search parameters and asked the reporter to raise Jira. FHIR-I minutes for 2022-05-23 record the Persuasive with Modification vote to create an extension for declaring "not standalone" search parameters in CapabilityStatement. Jira then recorded PR #2137; core commits f0c782cad8 and ff8e78aad4 added and corrected source/capabilitystatement/structuredefinition-extension-capabilitystatement-search-parameter-use.xml before merge 12cba418a5.

Additional context:
The current core checkout still has CapabilityStatement and SearchParameter active in source/fhir.ini, and CapabilityStatement.rest.resource.searchInclude, searchRevInclude, and searchParam remain in build-scope source. However, the extension definition itself is no longer authored in core: core commit dd468d4f17 removed extension definitions from the R5 source, and the only current core match for this canonical is the retained OID registry line. The authoritative current definition is in the FHIR Extension Pack at /home/jmandel/work/fhir-extensions/input/definitions/CapabilityStatement/StructureDefinition-capabilitystatement-search-parameter-use.xml, with canonical http://hl7.org/fhir/StructureDefinition/capabilitystatement-search-parameter-use and slices for allow-standalone, allow-include, and allow-revinclude. No discovered Zulip or Confluence evidence conflicts with that application history.

AutoFHIR reconciliation:
This is an empty external-repo audit commit. No core source was changed because the requested extension already exists in the FHIR Extension Pack, which is outside this HL7/fhir worktree for this run; re-adding a duplicate core StructureDefinition would conflict with the intentional extension-pack ownership model.

Recommendation:
Keep this audit commit as-is for core reconciliation. Future corrections to the search-parameter-use extension should be made in HL7/fhir-extensions; core should only change if FHIR-I makes a separate decision to add or revise core narrative references to the external extension.
