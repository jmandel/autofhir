FHIR-4003: Audit Encounter diet preference handling

Issue request:
FHIR-4003 was a Published/Persuasive with Modification DSTU1 PA issue. The ballot asked whether Encounter.hospitalization.diet should map to the NutritionOrder/NutritionRequest resource because the existing diet code did not appear aligned with a full nutrition order. The final disposition renamed the field to dietPreference, kept it as a coded preference rather than a NutritionOrder reference, and requested clearer descriptive text for the hospitalization/admission component and admissions.

Initial application:
Commit 8fb7336ca520b2fabc07796058cd9c9aa4ea19f3 ("Tracker 4003, 5192 Final PA Ballot reconciliation changes") changed the historical Encounter spreadsheet from Encounter.hospitalization.diet to Encounter.hospitalization.dietPreference, changed the label to "Diet preferences reported by the patient", and added requirements text saying that complete nutrition needs should use the nutritionOrder resource that links to Encounter. Commit 4c1752027ccab99fa86adf2f48825e92aca7101a ("Tracker# 4003 Usage notes on hospitalization component") updated Encounter.hospitalization to describe admission to a healthcare service and to explain outpatient, community clinic, aged-care, and period-scope usage.

Additional context:
Encounter and NutritionOrder are active current-build resources in source/fhir.ini. Later FHIR-32390 renamed Encounter.hospitalization to Encounter.admission and preserved migration mappings, and FHIR-14157 moved dietPreference to a top-level Encounter element while leaving the separate dietPreference-to-extension question for PA/PC follow-up. The combined branch already contains a FHIR-14157 human-review audit for that deferred extension/removal question, so FHIR-4003 should be interpreted as the historical dietPreference/NutritionOrder distinction, not as authority to remove the current element.

AutoFHIR reconciliation:
This is an empty no-change audit commit. Current source already carries the FHIR-4003 decision: Encounter has a coded dietPreference, the requirements text directs complete nutrition-order detail to NutritionOrder linked to Encounter, NutritionOrder.encounter references Encounter, and the admission component text explains the broad admission scope.

Recommendation:
Keep this audit commit as-is. Any future removal or externalization of Encounter.dietPreference should proceed under a dedicated PA/PC decision, not by reopening FHIR-4003.
