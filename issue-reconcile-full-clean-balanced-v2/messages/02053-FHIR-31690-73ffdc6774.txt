FHIR-31690: Audit ResearchSubject end date support

Issue request:
FHIR-31690 was a Published/Persuasive BR&R change request for R5 asking that ResearchSubject progress also have an endDate, so subject progress/state periods could record when a state ended as well as when it began.

Initial application:
ResearchSubject progress was added in the prior ResearchSubject R5 work, and commit 85a2ee09a3 ("Jira #26828, #31689, #31690") applied this tracker by adding ResearchSubject.progress.endDate as a 0..1 dateTime alongside progress.startDate in source/researchsubject/structuredefinition-ResearchSubject.xml.

Additional context:
ResearchSubject is active in source/fhir.ini and its StructureDefinition is current build source. The later Applied R6 tracker FHIR-43561 replaced the former progress backbone with subjectState and subjectMilestone; both Jira and BR&R minutes for that later work explicitly carried forward subjectState.endDate as a 0..1 dateTime. The current source preserves the same end-date capability as ResearchSubject.subjectState.endDate, and source/fhir.ini maps the R5 ResearchSubject.progress.endDate element to ResearchSubject.subjectState.endDate for R5-to-R6 migration.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative ResearchSubject source already contains the end-date element required by FHIR-31690, under the current R6 subjectState name, and the R5-to-R6 mapping records the rename from progress.endDate.

Recommendation:
Keep this no-change audit commit. Revisit only if a future ResearchSubject refactor removes subjectState.endDate or drops the R5 progress.endDate migration mapping.
