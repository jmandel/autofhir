FHIR-50689: Audit vital signs code/category revert

Issue request:
FHIR-50689 is an Applied/Persuasive OO R6 change request asking to revert the Vital Signs profile direction that moved vital-sign-specific identification from Observation.code to Observation.category. Its resolution says FHIR-45617 already decided not to change from .code to .category for identifying vital signs, and FHIR-50689 asks for the same conclusion.

Initial application:
No source commit explicitly named FHIR-50689 before this audit. The same issue family was applied through FHIR-45617 by commit 66a80b5fef2c43d4a46709f2a03b6d933063cb08, which moved the Vital Signs "interoperability standard" LOINC identifiers back from Observation.category to Observation.code and removed the temporary observation-vitalsign-category value set. A later combined-branch reconciliation commit for FHIR-50705, 77306523b255399153f826a0253a64b14382d3eb, fixed remaining source-backed Text Summary and example remnants that still suggested LOINC identifiers in Observation.category.

Additional context:
FHIR-50705 was the same category-vs-code objection and is already represented on the combined branch, so this commit does not duplicate that source fix. FHIR-50392 records the rejected alternative of using category for specific vital-sign searches. FHIR-49953 makes the same backward-compatibility argument, and FHIR-54960 documents the later duplicate metadata report that led to the FHIR-50705 cleanup. OO minutes on 2025-10-10 record FHIR-50689 as Persuasive/Pre-applied with the clarification that FHIR-45617 made the controlling code-not-category decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current build-scope source already matches the FHIR-50689 decision: source/fhir.ini lists Observation as an active resource, the Vital Signs implementation guide includes the affected profiles and introduction, the base Vital Signs profile fixes only the broad observation-category#vital-signs category, and the specific Vital Signs profiles bind/pattern their LOINC identifiers on Observation.code. Targeted searches found no remaining observation-vitalsign-category source, stale "interoperability category" wording, or LOINC-coded Observation.category blocks under source/observation.

Recommendation:
Keep this audit commit as-is for FHIR-50689. Do not restore the temporary category model or add a second source-changing commit for this issue; the needed source state is already present through FHIR-45617 and the FHIR-50705 cleanup. Any separate audit of FHIR-45617 or FHIR-49953 should be handled under those issue keys, and any future change from code to category would require a new work-group decision.
