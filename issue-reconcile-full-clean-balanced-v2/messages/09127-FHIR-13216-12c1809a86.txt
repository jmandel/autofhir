FHIR-13216: Audit Patient active search safety guidance

Issue request:
FHIR-13216 was a Published/Persuasive with Modification FHIR-core Patient change request from STU3 asking to improve documentation of Patient.active importance when searching and in the safety list. The accepted disposition was to add search-related safety checklist items covering appropriate patient-context default filters and client checking of requested filters, add a search-page link to that safety list, and avoid defining default search parameters as a general mechanism.

Initial application:
The issue was applied by git commit e94790da8dc50112b5be1c946a1daea544ced63c, "GF#13216 - default search parameters safety issues", which added the search safety checklist items to source/safety.html and linked source/search.html to safety.html#search. A later checklist-code-system commit, 76ce9865e683576c6712b6d0c6860272de60ad13, added source/codesystem/codesystem-safety-entries.xml and registered it in source/fhir.ini, preserving the same search-parameter and default-filter checklist entries in generated terminology form.

Additional context:
The linked Zulip discussion shows the original concern: omitted Patient.active searches, entered-in-error/inactive records, and whether servers should apply undeclared default filters. The directly related FHIR-17726 tracker requested broader default-search-parameter guidance and was resolved no-change/considered for future use for R4. Later Patient.active/default-value discussions support preserving the current distinction between Patient.active meaningWhenMissing and search-parameter defaults rather than adding a rule that an omitted active search parameter defaults to active=true.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The active source already contains the requested safety checklist entries in source/safety.html, the mirrored checklist code system entry registered in source/fhir.ini, and the search page link plus self-link guidance telling clients to verify actually-applied search parameters and filter or warn when needed.

Recommendation:
Keep this audit commit as-is. No source follow-up is needed for FHIR-13216 unless the work group reopens the broader default-search-parameter policy; that broader policy was split to FHIR-17726 and should not be smuggled into this Patient.active safety-list issue.
