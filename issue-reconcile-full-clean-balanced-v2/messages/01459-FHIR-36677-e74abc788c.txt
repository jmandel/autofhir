FHIR-36677: Audit Organization.description presence

Issue request:
FHIR-36677 was a Published/Persuasive Patient Administration change request asking FHIR core to add Organization.description below Organization.alias as a 0..1 string, with definition and requirements modeled from Location.description. The Jira comment and PA minutes record that the group initially chose string rather than markdown.

Initial application:
The request was applied in b3712f4fd643d1d92a5f4ea9eaafc4f64531cc1a, which added Organization.description below Organization.alias as a 0..1 string, and adjusted in edada93f0ffac5c8bfa1d0cab130897265736f59, which corrected the definition and requirements text after review.

Additional context:
Organization is an active resource in source/fhir.ini, and the current source/organization/structuredefinition-Organization.xml contains Organization.description immediately after Organization.alias with 0..1 cardinality and the approved definition/requirements. The current datatype is markdown, not string, because later Published issue FHIR-39585 expressly changed Organization.description from string to markdown; FHIR-38714 established that changing a later-version string element to markdown is not considered breaking.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build-scope source already contains the requested Organization.description element, and reverting the datatype to string would conflict with the later final PA decision in FHIR-39585.

Recommendation:
Keep this commit as-is. No follow-up is needed for FHIR-36677 in core unless a future work group decision reopens the Organization.description datatype or semantics.
