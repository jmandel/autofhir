FHIR-36347: Audit base search parameter guidance

Issue request:
FHIR-36347 was Published/Persuasive for R5 and asked to resolve conflicting guidance between the HTTP Variant Searches section and the Search page for base searches. The accepted request was to remove detailed parameter rules from the HTTP page, point readers to the Search page, allow global/format parameters where applicable, and clarify that cross-resource matching can be based on the search parameter name used by the server rather than requiring the same SearchParameter.base definition.

Initial application:
The issue was applied by d16636ba8132d2c4141090668e222c1e74b717a9, which removed the HTTP page's local SearchParameter.base restriction and replaced it with links to the Search page. The same commit expanded the Search page so that no _type permits only all-resource base parameters, a single _type permits that resource's parameters, and multiple _type values permit parameters commonly referenced by server name, including the Patient.name/Person.name example requested by the issue.

Additional context:
The March 21, 2022 FHIR-I minutes record FHIR-36347 as Persuasive with a 13-0-0 motion, matching the Jira snapshot. Later search-parameter work did not reverse the rule: FHIR-34866 refined the wording to include SearchParameter.alias values, and the FHIR-39010 Zulip thread quotes the R5 clarification as the applicable multiple-resource-type guidance. No conflicting community evidence was found in targeted Zulip/Confluence searches.

AutoFHIR reconciliation:
No source change was made. The current HTTP page delegates both multiple-type and all-type base search parameter availability to search.html#type, and the current Search page already states the required no-type, single-type, and multiple-type rules using CapabilityStatement names, SearchParameter.code, and SearchParameter.alias rather than SearchParameter.base identity.

Recommendation:
Keep this audit commit as-is. The current build-scope source already implements the Published FHIR-36347 decision, including later compatible terminology updates, so an additional edit would only duplicate or destabilize the existing guidance.
