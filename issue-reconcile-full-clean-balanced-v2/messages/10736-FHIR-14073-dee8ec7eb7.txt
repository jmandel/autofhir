FHIR-14073: Audit Observation obs-7 FHIRPath

Issue request:
FHIR-14073 was a Published/Persuasive STU3 FHIR-core Observation change request from OO. It asked to fix the obs-7 FHIRPath expression, replacing the old value.empty() or code!=component.code logic with a rule that detects matching Observation.code and Observation.component.code codings by code and system.

Initial application:
The issue was applied in git commit 311839957674a44444b3876d8e7a24662b624742, which changed the then-authoritative Observation spreadsheet expression from value.empty() or code!=component.code to the Jira-requested code/system comparison. Later FHIRPath cleanup commit 45ea9aefcb917dfc0bd4264c32b39aaa73f43309 rewrote that expression to value.empty() or component.code.where(coding.intersect(%resource.code.coding).exists()).empty(), and the current StructureDefinition source inherited that maintained form after source refactoring.

Additional context:
Observation is an active current-build resource in source/fhir.ini. The current active obs-7 constraint in source/observation/structuredefinition-Observation.xml uses the coding-intersection expression and the later clarified human wording. FHIR-20319 directly revisited the same expression family, proposed the intersect-based form, and was resolved Not Persuasive/No Change in 2025 because the current invariant meets the requirement. The original Zulip thread linked from FHIR-14073 explains why the old CodeableConcept equality expression was inadequate and why the rule needed to compare codings rather than whole CodeableConcept objects. Related wording and condition-flag issues FHIR-14019, FHIR-38955, and FHIR-20521 are already represented separately on the combined branch.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build-scope Observation source already carries the corrected maintained obs-7 FHIRPath, and changing it back to the literal 2017 resolution text would undo later FHIRPath cleanup that was explicitly confirmed by FHIR-20319.

Recommendation:
Keep this no-change audit commit. No FHIR core follow-up is needed for FHIR-14073 unless OO opens a new issue to change obs-7 semantics beyond the currently confirmed coding-intersection rule.
