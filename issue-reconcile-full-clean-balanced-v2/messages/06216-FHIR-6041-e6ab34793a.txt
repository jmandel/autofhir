FHIR-6041: Audit Timing durationMax addition

Issue request:
FHIR-6041 was a Published/Persuasive FHIR-core datatypes request raised against DSTU1 because Timing.repeat had an invariant saying durationMax requires duration, but the Repeat element did not define durationMax. The approved resolution was to add durationMax.

Initial application:
The issue appears to have been applied by git commit 9280e1ab4eb7f8721beb0a9a8843e958c8d8240e, converted from SVN revision 5610, with the subject "#6041 - add durationMax". Additional context:
Timing is still an active normative datatype in source/fhir.ini, so source/datatypes/timing.xml is authoritative current build input. Later Timing issues changed nearby wording but did not reverse the addition: FHIR-8734 removed an obsolete Range sentence, and FHIR-16986 clarified paired range semantics for duration/durationMax and the other repeat Max elements. FHIR-16986 is already represented on the combined branch. Jira, Zulip, and Confluence searches found no later core decision that removes durationMax or contradicts the current model.
