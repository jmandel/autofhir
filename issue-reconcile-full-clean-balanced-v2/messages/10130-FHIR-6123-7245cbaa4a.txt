FHIR-6123: Audit _id token search documentation

Issue request:
FHIR-6123 was a Published FHIR-core/BaseResource change request asking to change the standard _id search parameter from token to string because Resource.id has datatype id. The final Not Persuasive with Modification resolution kept _id as token and required the specification to document specifically how token is used for _id and related searches.

Initial application:
No current git commit was found that mentions FHIR-6123 directly. The closest historical application is 2c8afef000 (#9717), which changed the search summary table from string to token and added text that _id is token, exact-match, and has no system. Later search-page refactoring in ddecc63591 moved the explanation into the current dedicated _id section.

Additional context:
The active Resource search parameter source still defines Resource-_id as token over Resource.id, and source/fhir.ini maps datatype id to token for search-rule generation. The closely related Published FHIR-13320 case-sensitivity issue and a later implementer Zulip thread both confirm that _id uses token search semantics, is matched exactly, and remains case-sensitive despite the underlying id datatype.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source already preserves _id as a token SearchParameter and includes a dedicated _id section explaining that only the code segment is allowed, no vertical-pipe system syntax is used, and the input is matched as a code rather than a string.

Recommendation:
Keep this audit commit as-is. No FHIR core source correction is needed for FHIR-6123 unless a future work-group decision changes _id away from token semantics.
