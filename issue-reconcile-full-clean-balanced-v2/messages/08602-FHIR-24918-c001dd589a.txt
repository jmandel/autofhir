FHIR-24918: Audit _profile search summary table

Issue request:
FHIR-24918 was Published/Persuasive for R5 after reporting that _profile appeared as a reference search parameter in resource.html and the generated search-parameter artifacts, while the Common Parameters summary table showed uri and the primitive type cross-map did not map canonical to uri or reference. The recorded resolution asked to indicate _profile has search type uri in resource.html and resource representations, and to indicate canonical is mappable to uri.

Initial application:
The issue was initially applied by commit 7c0e9a614fb69e905643cedd0692b2e1f82d149a, which changed the historical Resource spreadsheet _profile row from reference to uri and added a history note for GF#24918/GF#24919. The same historical commit also addressed the related Age table issue FHIR-24919.

Additional context:
Later Published/Persuasive issue FHIR-30514 intentionally reversed the _profile decision and required the standard _profile search parameter to be marked as reference everywhere because reference search supports canonical version syntax such as |1.2. Commit a1cf2cf018130744adb32d8d92f03de8e16f1a93 changed the Search page common-parameters row back to reference, and commit 6d75b061edb768cac1c186923ab8cd4510c2f42f changed the active Resource-_profile SearchParameter source from uri to reference. FHIR-33203 was retracted after confirming the FHIR-30514 _profile fix was applied by PR #1377, while its other canonical/uri questions were outside that ticket. Later FHIR-52936 clarified current search prose so canonical can be used with both uri and reference search types, with reference generally preferred for versioned canonical values.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Current build-scope source/resource/bundle-Resource-search-params.xml defines Resource-_profile as type reference; source/search.html says _profile is a reference type parameter and lists it as reference in the common-parameters table. The current search-type mapping and uri prose also now say canonical is usable with uri while preserving the later reference-preferred rule for versioned canonicals, so reverting _profile to uri would conflict with later final FHIR-I decisions.

Recommendation:
Keep this no-change audit commit. No FHIR-core source follow-up is needed for FHIR-24918; the current reference type for _profile is intentional under FHIR-30514, and the canonical-to-uri mapping concern is covered by the current search-type mapping/prose and later FHIR-52936 clarification.
