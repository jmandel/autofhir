FHIR-20177: Audit ImagingStudy status guidance

Issue request:
FHIR-20177 was Published/Persuasive for the Imaging Integration work group. It asked to review ImagingStudy.status and add narrative explaining how the status values are expected to be used, with the final resolution to modify text according to the linked Confluence proposal.

Initial application:
The issue was applied before this reconciliation through the ImagingStudy R5 work. Commit b650c1dd54d447dcbc8aa5fbbab7cacf81972898 included FHIR-20177 in a batch of ImagingStudy updates, and commit 1920cc57abc3d4b8ec4be7733d1abb4606c903a2 made the FHIR-20177 QA fixes that added status=available to the EHR use case and clarified that ImagingStudy.status is about the ImagingStudy resource rather than associated ServiceRequest or Task resources.

Additional context:
The current source has since been refactored and expanded. source/fhir.ini actively lists imagingstudy as a current resource owned by ii, so source/imagingstudy feeds the current build. The current ImagingStudy.status element definition keeps the approved distinction from ServiceRequest and Task status, and source/imagingstudy/imagingstudy-notes.xml now contains a dedicated ImagingStudy.status section explaining registered, available, cancelled, entered-in-error, why complete is not defined, and that applications waiting on related ServiceRequest or Task completion should track those resources directly. The EHR access and workflow examples also show filtering or subscribing on status=available.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current authoritative source already conveys the approved status guidance and includes more detailed narrative than the original resolution required, so adding duplicate wording would not improve implementer understanding and could create maintenance drift.

Recommendation:
Keep this audit commit as-is. No follow-up core source work is recommended for FHIR-20177 unless the Imaging Integration work group later changes the status value set semantics.
