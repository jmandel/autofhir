FHIR-12641: Audit selector extension disposition

Issue request:
FHIR-12641 was a Published/Persuasive FHIR-core request to support an alternative slicing selection model by adding an ElementDefinition selector extension: each slice could carry a FHIRPath entrance criterion, optionally agreeing with ordinary discriminators, and selector-only slicing could allow an element to match multiple slices.

Initial application:
The issue was applied in svn revision 11179, preserved as git commit 3253654af7787e9b738b15f4618a2b9d02d56f7f, together with FHIR-12618. That commit reworked ElementDefinition.slicing.discriminator and added the selector extension row with the requested FHIRPath selection criteria and multiple-slice comment.

Additional context:
Core later removed extension definitions from the R5 source in dd468d4f1799dd79819315b211588ef1cf4586e0, while retaining the selector canonical's OID in source/oids.ini. The authoritative current definition is now in the FHIR Extension Pack, where input/definitions/datatypes/StructureDefinition-elementdefinition-selector.xml preserves the FHIR-12641 semantics but marks the extension retired/deprecated. FHIR-41758 and FHIR-I minutes record the later decision to deprecate it because tooling did not support it and the relevant FHIRPath is calculated automatically.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. Re-adding selector to the current core ElementDefinition or profiling text would conflict with the later extension-pack ownership/deprecation decision, and editing the extension pack is outside this core reconciliation branch.

Recommendation:
Keep this audit commit as-is. Future changes to revive, remove, or further explain elementdefinition-selector should be handled in the FHIR Extension Pack with FHIR-I review, not by restoring the retired extension to core.
