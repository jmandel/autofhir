FHIR-28097: Audit ObservationDefinition.device cardinality

Issue request:
FHIR-28097 is a Published/Persuasive R5 OO change request to change ObservationDefinition.device from 0..1 to 0..* and clarify that multiple devices are inclusive OR: observations of this kind use one or more listed devices or models.

Initial application:
There was no prior issue-reconcile commit for FHIR-28097 on the combined branch. The original source application appears in commit 56b91f72c1e36104fa43f12c189891648867d5bd, which changed ObservationDefinition.device to max * and added DeviceDefinition as a target while applying the coupled ObservationDefinition trackers including FHIR-26921 and FHIR-28097.

Additional context:
ObservationDefinition is an active resource in source/fhir.ini, and the current source is authoritative for this build. The current source no longer has the R5 shape; it defines ObservationDefinition.device[x] as 0..1 with Reference(Device) and canonical(DeviceDefinition). Later DeviceDefinition canonical-resource work in FHIR-39389 changed DeviceDefinition references to canonical form, which made ObservationDefinition.device a choice element. FHIR-53307 then documented the publisher rule that choice elements cannot have cardinality greater than 1 and listed the alternatives of accepting the reduced 0..1 cardinality or splitting/remodeling the element. OO minutes on 2025-11-07 record a motion to accept the revised 0..1 cardinality, but FHIR-53307 remains Triaged and later comments/minutes continue discussing use cases for specific or multiple Device instances.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Restoring max * on the current device[x] choice would violate the publisher choice-element rule, while splitting or remodeling the element would decide the still-open FHIR-53307 design question. The safe reconciliation for FHIR-28097 is therefore a human-review audit noting that the R5 change was applied historically but is now entangled with later R6 canonical DeviceDefinition modeling and an unresolved cardinality decision.

Recommendation:
Keep this audit commit and have OO finish FHIR-53307 (or a successor) by explicitly deciding whether current R6 ObservationDefinition.device[x] 0..1 supersedes FHIR-28097, or whether repeating device support should be restored through a non-choice element/backbone model. Do not apply an automated 0..* edit until that later decision is final and represented in a publisher-valid model.
