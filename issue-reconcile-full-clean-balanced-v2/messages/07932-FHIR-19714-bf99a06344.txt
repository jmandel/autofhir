FHIR-19714: Audit update rules empty-element clarification

Issue request:
FHIR-19714 was a Published FHIR-core change request resolved as Persuasive with Modification. It asked that the update-rules page stop implying that FHIR could never empty an element, because a PUT that omits elements can intentionally or unintentionally remove previously stored data. The approved wording clarified that HL7 v2-style retention of omitted elements can technically be followed in FHIR but is atypical and unexpected, and that FHIR has no defined construct for explicitly setting an element empty when processing a PUT in a mode where omitted elements are typically retained.

Initial application:
The Jira comment cites merge commit 0ff6d17906a8f3c24e9318d2063edcae8b3dd30d. The underlying implementation commit 0e62f8fbeddb2985a942147daf090ff72f4e21ab applied the approved sentence to source/updates.html, and follow-up commit e9fbfd39a29f11dcc4996bfae722b4b6fd85aeae removed an accidental duplicate sentence from that application. The current source/updates.html text preserves the approved clarification.

Later same-page work, including FHIR-32757 create/update variability guidance and FHIR-44047 punctuation cleanup, did not change or supersede the FHIR-19714 sentence. Jira, Zulip, and Confluence searches found no conflicting later decision or community discussion for the empty-element PUT wording.
