FHIR-6346: Audit DocumentReference encounter context

Issue request:
FHIR-6346 was a Published/Persuasive DSTU1 Structural Documents request to add a direct Encounter relationship to DocumentReference, rather than relying on unclear catch-all related/reference modeling for documents that document an encounter.

Initial application:
The Jira comments identify svn revision 6188. The git-svn mirror contains e3000793223d9ec9b379c432b7f80cddbbd66087, "#6346 - add DocumentReference.encounter", which added DocumentReference.context.encounter as Reference(Encounter) to the then-active DocumentReference spreadsheet and added an Encounter reference to the DocumentReference example.

Additional context:
DocumentReference is active in source/fhir.ini, and the current authoritative source is source/documentreference/structuredefinition-DocumentReference.xml. Later published work changed the specific child name: FHIR-29801 renamed DocumentReference.encounter to DocumentReference.context and added Appointment and EpisodeOfCare while retaining Encounter; FHIR-54170 then updated the context definition for that broader target set. The current source also defines a normative DocumentReference-context reference search parameter and keeps DocumentReference.related scoped to resources not represented elsewhere, so it is not the primary encounter-context mechanism.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build already gives DocumentReference a direct typed context reference that includes Encounter, documents the encounter association in the short/definition/comment/requirements, maps it to Composition.encounter, and discourages duplicating that relationship through related.

Recommendation:
Keep this no-change audit commit. Reintroducing a separate encounter child would undo later published R5/R6 decisions; any future concern about the broader context element or its warning constraints should be handled under the later DocumentReference context trackers rather than FHIR-6346.
