FHIR-14060: Audit Measure identifier generalization

Issue request:
FHIR-14060 was a Published/Persuasive STU3 CQI change request for FHIR-core Measure and MeasureReport. It asked to remove group/population/stratifier/supplementalData identifier/name elements used for cross-resource correlation, use the backbone id for local linkage, and add CodeableConcept code elements where missing so Measure and MeasureReport criteria can be correlated by codes.

Initial application:
The Jira comment says the change was applied at SVN 12641. In git history this is commit 734c7befc75fc6677ab2dbae8d77bdc07428cc5b, whose subject includes #14060 and whose git-svn-id is build@12641. That commit changed the old Measure and MeasureReport spreadsheet sources so the relevant identifier/name paths disappeared and the requested code paths remained or were added.

Additional context:
Measure and MeasureReport are active current-build resources in source/fhir.ini. The current authoritative source is source/measure/structuredefinition-Measure.xml and source/measurereport/structuredefinition-MeasureReport.xml rather than the old spreadsheet files. Later final CQI decisions refined the linkage mechanism: FHIR-38832 added explicit linkId elements because using internal backbone id as an external reference was discouraged, while FHIR-49670 clarified that MeasureReport groups, populations, and stratifiers correspond to the Measure and carry at least the corresponding codes. No Zulip or Confluence search found a conflicting community record for FHIR-14060.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current Measure and MeasureReport StructureDefinitions have the code elements needed by FHIR-14060, have no obsolete FHIR-14060 identifier/name element paths, and now use linkId plus backwards-compatible id guidance because of later applied/published decisions.

Recommendation:
Keep this no-change audit as-is. No core source follow-up is needed for FHIR-14060; any future changes to Measure/MeasureReport correlation should be handled under the later linkId/linking issues rather than reintroducing identifier elements.
