FHIR-7496: Audit terminology binding clarification

Issue request:
Published/Persuasive with Modification FHIR-core vocab issue from the 2015May ballot asked to clarify ambiguous Extensible binding wording that said an "alternate system.code" could be used when a value set does not cover the concept. The accepted resolution was to change that to "alternate system and code" and add verbiage clarifying whether the alternate may come from another system.

Initial application:
The issue was applied in svn revision 5682, preserved as git commit 200136ca99b23eb08976b3d86abeb6f807f42a72, changing source/terminologies.html to allow "alternate codings (from different code systems, including local ones)" or text. A later 2017 cleanup removed that duplicate inline table in favor of the generated binding-strength code list, so the exact 2015 phrase is no longer present.

Additional context:
The current build includes source/terminologies.html through the source hierarchy and terminology-module navigation. Later Published issue FHIR-29968 overhauled the Extensible Binding Strength section for R5; the current page explicitly says an alternate concept may be a system/code pair, system/version/code triplet, or text, and says alternate code(s) from outside the value set may be used only when no matching or applicable value-set concept exists. FHIR-48479 later reorganized the same terminology page/table without reversing that rule. No direct Zulip or Confluence hits for FHIR-7496 were found; broader community records discuss the same system/code extensible-binding ambiguity but do not conflict with current wording.

AutoFHIR reconciliation:
Made no source change. The current source already conveys the semantic clarification required by FHIR-7496; restoring the old "different code systems, including local ones" phrase in the summary table would be redundant next to the detailed guidance and could drift from the later FHIR-29968 wording.

Recommendation:
Keep this audit commit as-is. If future ballot feedback wants the short binding-strength table or CodeSystem definition to mention "outside the value set", handle that as a new terminology editorial issue rather than as an unapplied FHIR-7496 fix.
