FHIR-17359: Audit Task and Procedure boundary clarification

Issue request:
FHIR-17359 was Published with resolution Persuasive with Modification for STU3. It asked to clarify when to use Task versus Procedure because the two resource descriptions seemed overlapping; the approved guidance says a Task is a workflow step, Procedures are actions intended to result in physical or mental change to or for the subject, and a Task can request fulfillment of a ServiceRequest ordering a Procedure.

Initial application:
The Procedure side appears to have been applied by git commit ef05a01a0bea, which added the approved Task/Procedure boundary paragraph to source/procedure/procedure-introduction.xml. The corresponding Task-side tracker FHIR-19109/GF#19109 was applied by git commit d9208736f5, which updated source/task/task-introduction.xml with matching boundaries guidance.

Additional context:
Current source/fhir.ini actively lists procedure, servicerequest, and task as built resources. Current Procedure and Task introduction pages both carry the requested Task/Procedure distinction, while ServiceRequest separately explains the request/Task split and links to the Request pattern fulfillment guidance. The referenced Zulip thread supports the same distinction, and no Confluence reference specific to FHIR-17359 was found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped source already conveys the approved guidance; wording differences such as broader examples and later refactoring do not change implementer understanding.

Recommendation:
Keep this no-change audit as-is. Revisit only if a future work-group decision reopens the broader Task/Procedure/ServiceRequest/Encounter boundary family; adding another duplicate paragraph now would increase maintenance drift without changing the specification meaning.
