FHIR-50487: Align Measure submit-data Bundle input

Issue request:
FHIR-50487 was Applied/Persuasive for R6 by CQI and asked that the core Measure $submit-data operation be aligned with the DEQM STU 5 $submit-data operation. The requested alignment included accepting submitted Bundles for one or more subjects, disallowing instance-level invocation because the MeasureReport identifies the measure, adding quality-reporting guidance, and updating the operation example to submit a Bundle.

Initial application:
The issue was partially applied by HL7/fhir commits 894f1a69b8 ([FHIR-50487]: initial DEQM alignment from PR #3778) and 7146e4e1cf ([FHIR-50487]: additional alignment from PR #3932). Those commits updated the operation narrative, made the operation type-level only, added the subject-organized and duplicate-data guidance, and changed the request example to wrap the submitted data in a Bundle. However, the OperationDefinition parameter was still typed as MeasureReport even though it was named and documented as a Bundle, the rendered request example still used an instance-level URL, and the embedded MeasureReport example still used the stale patient element instead of the current subject element.

Additional context:
The DEQM STU 5 OperationDefinition has a single 1..* input parameter named bundle with type Bundle and type=true, instance=false. FHIR-46373 is the DEQM same-change-family issue that created the multi-measure submit-data operation using Bundle input, and FHIR-51066 is the adjacent core collect-data alignment issue that already uses Bundle as the multi-cardinality operation payload type. The Measure resource is active in source/fhir.ini and source/measure/operationdefinition-Measure-submit-data.xml is referenced by the Measure operation list and example extensions, so these files feed the current build.

AutoFHIR reconciliation:
This commit changes Measure $submit-data's input parameter type from MeasureReport to Bundle, updates the request example URL from [base]/Measure/Measure-mrp/$submit-data to [base]/Measure/$submit-data to match instance=false, and changes the submitted MeasureReport example from patient to subject. These are semantic consistency fixes needed for the current built operation definition and example to match the applied Jira resolution and DEQM STU 5 input shape.

Recommendation:
Keep this commit as-is. It completes the already-applied FHIR-50487 alignment in core without changing unrelated DEQM-specific wording or reopening the broader deprecation direction.
