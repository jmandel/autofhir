FHIR-8024: Audit document conformance clarification

Issue request:
FHIR-8024 was a Published, Persuasive with Modification DSTU1 clarification asking what "framework" meant in the FHIR Documents sentence "Applications claiming conformance to this framework claim to be conformant to 'FHIR documents'." The approved resolution said there were three conformance claims, tied to Conformance resource sections, and requested clarification on the conformance page and the conformance statement resource page.

Initial application:
The issue was applied in SVN revision 6214, now git commit 4956a5f9552c691c825e488cde668506039c8513, which rewrote the conformance rules page to introduce the RESTful FHIR, FHIR messaging, and FHIR documents exchange frameworks and added a documents-page link to that conformance explanation.

Additional context:
Current FHIR has renamed Conformance to CapabilityStatement, and the active CapabilityStatement resource contains the document section used to declare document support. A later Published ballot issue, FHIR-38932, replaced the same documents-page sentence with explicit CapabilityStatement.document wording. That related issue is already represented on the combined branch, so this commit does not duplicate it.

AutoFHIR reconciliation:
No source change was made. The current documents page directly says that applications declaring support for FHIR documents with CapabilityStatement.document assert conformance to the rules on the page; the conformance rules page lists the three exchange frameworks; and the CapabilityStatement source includes the document section for document support declarations. This preserves the substance of FHIR-8024 after later terminology and wording changes.

Recommendation:
Keep this no-change audit commit as-is. Further edits for FHIR-8024 would be redundant with the active conformance rules, CapabilityStatement.document, and the already-audited FHIR-38932 wording update.
