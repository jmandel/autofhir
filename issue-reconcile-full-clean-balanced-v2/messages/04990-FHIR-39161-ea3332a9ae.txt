FHIR-39161: Audit InventoryItem move to OO incubator

Issue request:
FHIR-39161 was Published/Persuasive with Modification for R5. It asked for a generic product resource for inventory, catalog, and supply use cases, and the accepted resolution was that adding InventoryItem in R5 at FMM0 addressed the need, subject to final FMG approval once implementation experience had been gained.

Initial application:
The R5 work was applied in core source. Commit ee4a05d674 added source/inventoryitem plus active source/fhir.ini entries for InventoryItem, later commits including 3fe49c123c, a4d7148f76, c7445a3ecd, and f837c6003e refined the InventoryItem content, and the published R5 page exposes InventoryItem as a Draft/FMM0 resource.

Additional context:
The accepted R5 resource was intentionally provisional. The R5 note warned that InventoryItem needed implementation feedback and might be removed in a future FHIR release. FMG and OO later discussed low-maturity resources for R6 and the additional-resources pathway; FMG guidance named InventoryItem in the Inventory group recommended for additional resources, and OO discussion stated that InventoryItem, InventoryReport, SupplyDelivery, and SupplyRequest were pulled out of core so the supply-like resources could progress together in an OO incubator IG. Current core source reflects that decision: InventoryItem has no active source/fhir.ini build entry, and the Administration module links to the OO Incubator InventoryItem page instead of a core resource page.

AutoFHIR reconciliation:
This audit commit makes no source change. Re-adding InventoryItem to the current core build would reverse the later R6 additional-resources decision rather than complete FHIR-39161. The current core checkout is correct for this issue because the R5 request was applied and the current InventoryItem definition now belongs to the OO Incubator implementation guide.

Recommendation:
Keep this audit as-is for FHIR-core. Future InventoryItem content fixes should be made in the HL7/oo-incubator source or through a new work-group decision to move InventoryItem back into core once it has sufficient maturity and implementation experience.
