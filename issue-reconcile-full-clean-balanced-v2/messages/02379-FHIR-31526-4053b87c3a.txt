FHIR-31526: Audit Substance R4B revert scope

Issue request:
FHIR-31526 is a Published/Persuasive BR&R R4B ballot issue for Substance. It asked to revert breaking Substance model changes from R4B; the key comment clarified that the changes were needed for Medication Definition/R5 use cases but were not acceptable R4B backwards-compatibility breaks.

Initial application:
The non-compatible Substance changes came from the same change family as FHIR-28547, FHIR-29265, and FHIR-29267, including CodeableReference support for Substance.code and moving instance details onto Substance. Git history shows the R4B revert was applied by commits 9f6f0befe9298492d29533eb59378bd0c10eff82 and 6854a80e39c798ffdeee53ca665c5503c28e737f on the R4B branch, while the R5/main line later restored the intended R5 Substance model in beb040d0608727a093902f91d4e3d6675f0c33f6.

Additional context:
Substance is active in the current build. The current combined branch follows the R5/R6 lineage: Substance.code is a CodeableReference to SubstanceDefinition, Substance.expiry and Substance.quantity are top-level elements, and the R4B-only Substance.instance/ingredient model is not restored. The origin/R4B branch retains the compatibility shape with Substance.code as CodeableConcept plus Substance.instance and Substance.ingredient. Later FHIR-48405 cleanup is already represented on the combined branch and confirms that current R6 Substance semantics have moved beyond the R4B compatibility concern.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Reverting the current Substance source to the R4B-compatible shape would undo intended R5/R6 decisions; the only requested correction was to avoid those breaking changes in R4B, and branch history shows that was done.

Recommendation:
Keep this no-change audit commit. No follow-up is needed in the current FHIR core branch for FHIR-31526; any future R4B maintenance concern should be handled on the R4B release line, not by changing current R5/R6 Substance source.
