FHIR-25462: Point profile-use guidance to supportedProfile

Issue request:
FHIR-25462 was a Published/Persuasive with Modification FHIR-core conformance issue asking for CapabilityStatement profile-use guidance. The approved disposition clarified that CapabilityStatement.rest.resource.profile is system-wide across all instances of a resource, that CapabilityStatement.rest.resource.supportedProfile describes use-case-specific supported subsets, and that profile-use guidance in profiling.html should be updated.

Initial application:
The seed was applied by 8fb57bffdcfcaef0a694269d3930aae57f3c35e5, which updated the CapabilityStatement .profile and .supportedProfile definitions, added the declared-profile extension in core, and changed source/profiling.html to recommend that extension. A later wording commit, a2e0206d1d15324a318ed83dd5d55c65be16e584, changed the .profile example from "lowest common denominator" to "superset". The current CapabilityStatement source still contains the profile/supportedProfile split and is in build scope through the active CapabilityStatement resource entries in source/fhir.ini.

Additional context:
The declared-profile extension was moved out of core with the broader R5 extension move and now lives in the FHIR Extension Pack. Later Published Extension Pack issue FHIR-40930 decided that no one had indicated use of the extension, deprecated it, and pointed users to CapabilityStatement.rest.resource.supportedProfile. Extension Pack source now marks capabilitystatement-declared-profile retired/deprecated with that reason. Community and minutes evidence around FHIR-40930 show the same uncertainty about how declared-profile differed from supportedProfile and the final 10-0-0 vote to deprecate it. Before this reconciliation, core source/profiling.html still told producers that they SHOULD use the deprecated extension.

AutoFHIR reconciliation:
This commit updates the current core profiling guidance so producers communicate these use-case-specific profiles with CapabilityStatement.rest.resource.supportedProfile, and it explicitly says the previously published Declared Profile extension is deprecated and should not be used for this purpose in new CapabilityStatements. No other CapabilityStatement definitions were changed because they already reflect the applied FHIR-25462 profile/supportedProfile split.

Recommendation:
Keep this source fix. It preserves the original FHIR-25462 distinction between resource.profile and supportedProfile while aligning the core narrative with the later final Extension Pack deprecation decision, preventing implementers from following stale guidance to use a retired extension.
