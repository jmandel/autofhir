FHIR-34215: Audit Consent scope code restoration

Issue request:
FHIR-34215 was a Published/Persuasive CBCC change request for R4/R5 Consent asking that the `adr` Advance Care Directive code be added back to the ConsentScope code list because the FHIR R4 page showed four codes while the terminology server CodeSystem `http://terminology.hl7.org/CodeSystem/consentscope` exposed only three.

Initial application:
No Jira-tagged core commit for FHIR-34215 was found. Core had already removed the local Consent scope CodeSystem as part of the UTG migration, leaving `source/consent/valueset-consent-scope.xml` to include the external THO CodeSystem. The practical application trail is UP-255, which restored `adr` in THO and is recorded as implemented/published rather than as a current core source edit.

Additional context:
FHIR-31903 separately removed the `Consent.scope` element for R5 and merged the use of scope codes into Consent category handling, so there is no current `Consent.scope` element binding to edit. The active Consent resource folder still contains the Consent scope value set, whose current source says it includes four Consent scope codes and includes all concepts from THO. Current THO publication evidence and a direct check of `CodeSystem-consentscope.json` show `adr`, `research`, `patient-privacy`, and `treatment` are present.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current FHIR core source is consistent with the resolved issue because the authoritative CodeSystem content is maintained in THO and now includes `adr`; duplicating the code list in core would reverse the UTG migration pattern.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed for FHIR-34215 unless a future THO/UTG decision changes Consent scope code status or publication history; any such terminology work should be handled in the terminology source rather than by reintroducing a core CodeSystem.
