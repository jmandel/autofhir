FHIR-44746: Align AuditEvent DICOM type mappings

Issue request:
FHIR-44746 was Applied/Persuasive with Modification for the Security work group. It asked to reverse the R5 AuditEvent category/code model back to type/subtype because the R5 category/code cardinalities and DICOM EventIdentification mappings did not support the historic ASTM/IETF/DICOM/IHE audit model.

Initial application:
The issue was initially applied by 983d54c76d679b5c25a07667522940dea7590608 and merged by 2268c17c01881bb6256b9c2a61c98afd75396e98. That application renamed AuditEvent.category/code back to AuditEvent.type/subtype and restored the active search parameter names, but it left category/code-era DICOM aliases and mappings on the restored elements and retained Event.category prose that referred to multiple category repetitions and slicing.

Additional context:
AuditEvent is active in source/fhir.ini, so source/auditevent/structuredefinition-AuditEvent.xml and the resource mapping exception file are build inputs. FHIR-32443 created the R5 category/code model, and FHIR-41877 later corrected the DICOM mapping while that model still existed. FHIR-44746 is the later issue that restored the type/subtype model; R4/R4B mapped type to DICOM EventID and subtype to EventTypeCode, and the current type/subtype value sets already align with AuditEventID/CID 400 and AuditEventSubType/CID 401/403 respectively. Security minutes recorded approval of FHIR-44746, and no directly relevant Zulip discussion was found.

AutoFHIR reconciliation:
This commit updates the authoritative AuditEvent StructureDefinition so AuditEvent.type aliases/maps to DICOM EventID and AuditEvent.subtype aliases/maps to DICOM EventTypeCode. It also replaces the stale Event.category slicing comment with type/subtype-specific guidance and updates the Event pattern mapping exception to match. Generated-looking SVG artifacts were not edited manually.

Recommendation:
Keep this source fix. It completes the FHIR-44746 reversal in the active AuditEvent source while preserving the intentional type/subtype search parameter model; any future desire to retain FHIR-41877's category/code-era interpretation under the restored names should be handled as a separate work-group decision.
