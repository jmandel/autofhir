FHIR-33100: Audit canonical keyword consistency

Issue request:
FHIR-33100 was a Published/Persuasive with Modification FHIR-I change request for R5 asking that keyword metadata be handled consistently across canonical resources. The disposition deprecated StructureDefinition.keyword, removed the CodeSystem and ValueSet-specific keyword extension approach from core, and the Jira application comments refined the target to use the artifact-topic extension rather than a new keyword extension.

Initial application:
The issue was applied in PR #2358 by commit 272e3fb71e, which marked StructureDefinition.keyword deprecated and added guidance away from the element. That first application text pointed to artifact-keyword, and commit de1c9d81ad later corrected the guidance to artifact-topic. Current core source no longer defines CodeSystem.keyword or ValueSet.keyword; CodeSystem and ValueSet use their topic elements for categorization and keyword metadata.

Additional context:
Later FHIR-37841 clarified that MetadataResource.topic covers keywords as well as topical categories, and the combined branch already contains a separate FHIR-37841 reconciliation commit for remaining topic wording. Later FHIR-38841 deprecated MetadataResource.topic itself in favor of a useContext topic code, so current topic comments appropriately carry migration guidance rather than new keyword prose. The artifact-topic StructureDefinition now lives in the FHIR Extension Pack, with context including StructureDefinition, CodeSystem, and ValueSet.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current-build source already reflects the final issue family state: StructureDefinition.keyword and its search parameter are deprecated and point to artifact-topic, CodeSystem.topic and ValueSet.topic carry the keyword/search semantics, and the remaining extension definition is maintained outside this core checkout.

Recommendation:
Keep this audit commit as-is. No core FHIR source follow-up is needed for FHIR-33100 unless a work group separately decides to revisit the later MetadataResource.topic deprecation or extension-pack handling of legacy keyword search parameters.
