FHIR-5601: Audit Reference.reference RESTful URL regex

Issue request:
FHIR-5601 was a Published/Persuasive DSTU1 fhir-i change request asking for Reference.reference to explicitly specify the identifier/address format, preferably with a regex, so implementers could distinguish references consistent with the FHIR REST API from other valid resource references.

Initial application:
The request was applied in git-svn commit 1fd638cecf3c240c636198c06924d3725703eb98, matching the Jira note for svn revision 4675, by adding a regex and cautionary text to source/references.html. The current source still contains that applied rule on the active Reference datatype page: references.html states that absolute URLs need not point to a FHIR RESTful server, gives a regex for references consistent with a FHIR API, and says both that regex conformance does not guarantee a FHIR server and non-conformance does not make a reference non-compliant.

Additional context:
source/fhir.ini maps the Reference datatype to the references page, so source/references.html is in the current build scope for Reference. Later Published clarification issues FHIR-29271 and FHIR-31422 reference the same RESTful URL regex for Bundle reference-resolution and fullUrl semantics, but they do not supersede the FHIR-5601 distinction between API-shaped references and other compliant references. Searches for FHIR-5601, Reference.reference regex, and related wording found no Zulip or Confluence evidence that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already satisfies the FHIR-5601 request, and adding the regex again to the generated detailed-description spreadsheet would be redundant rather than a necessary correction.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-5601 unless the work group wants a new, separate decision to make the RESTful URL regex a formal invariant or to revise the regex itself.
