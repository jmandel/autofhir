FHIR-8755: Audit Task order variation support

Issue request:
FHIR-8755 is Published/Persuasive with Modification. It asked to add an optional CodeableConcept OrderType or OrderModifier to the former Order resources to support workflow variations. The final resolution says Order was replaced by Task and the change was applied as code; Jira comments note that the need was already addressed by the intent element.

Initial application:
No git commit explicitly mentions FHIR-8755. Historical source shows the former source/order files were removed in commit 16997a29cae as part of #10059 Remove Order/OrderResponse. The current active replacement surface is Task plus the workflow Request pattern: source/fhir.ini lists task=Task as an active resource, and source/task/structuredefinition-Task.xml defines Task.code as an extensible CodeableConcept for workflow-specific task type and Task.intent as the required code that carries order/proposal/plan-style actionability.

Additional context:
Later workflow/request decisions refined the order-intent codes rather than restoring the old Order resource or adding a separate OrderType element. FHIR-11127 required a generic order code so systems do not have to over-specify original-order or reflex-order. FHIR-20499 moved and clarified instance-order under the Request.intent hierarchy, implemented by git 849d838231. Current Task.intent includes order, original-order, reflex-order, filler-order, instance-order, and option through ValueSet/task-intent, while Task.code remains available as a CodeableConcept for task type values specific to a workflow.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build already satisfies the applied FHIR-8755 decision: the obsolete Order resource is out of the build, Task is active, and Task provides both the CodeableConcept task type surface and the modifier-like intent code surface that captures workflow/order variations.

Recommendation:
Keep this audit commit as-is. Do not reintroduce Order or add a redundant OrderType/OrderModifier element to Task; future workflow refinements should continue to use the active Task.code/Task.intent and Request.intent terminology surfaces unless the work group makes a new decision.
