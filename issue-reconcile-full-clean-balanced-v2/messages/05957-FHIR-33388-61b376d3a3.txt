FHIR-33388: Audit Task focus canonical application

Issue request:
FHIR-33388 was an Applied OO change request, resolved Persuasive with Modification for R6, asking for Task.focus to support canonical targets when the task acts on a definition rather than only on an instance reference. The final disposition called for Task.focus to become a repeating backbone with a required value[x] choice of Reference(Any) or canonical(CanonicalResource), for the Task.restriction constraint to require a reference-valued focus when restriction is used, for Task focus search parameters to be updated, and for examples to be updated.

Initial application:
The issue was applied by HL7/fhir PR #3879, merged as 44595732b09b. Its implementation commits changed source/task/structuredefinition-Task.xml from a direct Reference element to Task.focus BackboneElement plus Task.focus.value[x] with Reference and canonical choices, fixed tsk-1 to test focus.value.ofType(Reference), replaced the old Task-focus search parameter with focus-reference and focus-canonical entries, updated the Patient compartment row to use focus-reference, and revised Task examples to use valueReference or valueCanonical.

Additional context:
Task is an active current-build resource in source/fhir.ini, so source/task/structuredefinition-Task.xml, source/task/bundle-Task-search-params.xml, source/task examples, and source/compartments.xml are in build scope. OO minutes from 2025-10-03 record the 6-0-1 motion matching the Jira disposition. The implementers Zulip thread and submitted FHIR-51913 show that broader canonical search-parameter behavior remains an open FHIR-I clarification question; because FHIR-51913 is Submitted and unresolved, it should not be used here to alter the already-applied OO Task disposition.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already conveys the core FHIR-33388 rule by allowing Task.focus.value[x] to be either Reference(Any) or canonical(CanonicalResource), requiring a reference-valued focus for Task.restriction, exposing separate current focus-reference and focus-canonical search parameters, updating the Patient compartment mapping to the reference-valued parameter, and including canonical-valued Task examples. Adding a generic focus search parameter, changing focus-canonical's type, or adding a new no-mixed-focus invariant would go beyond the final applied OO source and overlap the unresolved FHIR-I search clarification.

Recommendation:
Keep this audit commit as-is for FHIR-33388. If the work group wants different cross-type search behavior or a generic Task.focus search parameter, resolve FHIR-51913 or a follow-up OO/FHIR-I issue first; do not treat that unresolved question as a remaining FHIR-33388 application defect.
