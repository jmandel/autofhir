FHIR-19108: Audit MedicationRequest immunization basedOn target

Issue request:
FHIR-19108 was a Published/Persuasive STU3 Pharmacy change request to allow MedicationRequest.basedOn to reference ImmunizationRecommendation, so an immunization order could be linked to a CDS-generated immunization recommendation.

Initial application:
The Jira comments identify merge commit 65133c5 as the 2018 application. Its underlying implementation commit 0bb03b10227f added ImmunizationRecommendation to the old MedicationRequest.basedOn spreadsheet reference list, and that target survived the later XML conversion and RequestOrchestration addition for several release cycles.

Additional context:
MedicationRequest remains an active current-build resource in source/fhir.ini, but ImmunizationRecommendation and ImmunizationEvaluation are no longer active core resources. Public Health WG minutes from 2025-10-02 record a 20-0-3 approval to make both ImmunizationRecommendation and ImmunizationEvaluation Additional Resources for R6 until further maturity, and commit e073fb45ec6f then removed those resource sources and removed ImmunizationRecommendation from MedicationRequest.basedOn. Later same-element context also matters: FHIR-41561 added RequestOrchestration while the immunization target still existed, and FHIR-47858 rejected adding PlanDefinition as another basedOn target because basedOn is for request resources and added separate protocol guidance instead.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Re-adding ImmunizationRecommendation to source/medicationrequest/structuredefinition-MedicationRequest.xml would now reference a resource that is no longer part of the current core build and would reverse the later PHWG R6 Additional Resources decision. The checked-in medicationrequest.svg still contains the older diagram text, but it is generated-looking diagram output; the active authoritative XML and fhir.ini source are the relevant current-build evidence for this issue.

Recommendation:
Keep this no-change audit for core FHIR. If the Additional Resources publication or another external package needs cross-resource guidance for MedicationRequest orders based on ImmunizationRecommendation, handle that in the owning package or through a new work-group decision rather than restoring a removed core targetProfile here.
