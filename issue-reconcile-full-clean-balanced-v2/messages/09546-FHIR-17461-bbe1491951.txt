FHIR-17461: Audit advanced text search wording

Issue request:
FHIR-17461 was a Published FHIR-core search change request with a Persuasive with Modification resolution. The reporter questioned wording in the string-search section that described advanced text handling with the :text modifier and proposed replacing it with the _text search parameter. The accepted modification instead required the Text Search Parameters section at search.html#content to say that _text and _content search resource narrative/content and, just like string parameters using the :text modifier, should support sophisticated text-search functionality.

Initial application:
The issue appears to have been applied by SVN revision 14256, represented in git as 06d8e8a000752f7b50cc02bfd7b028dcf8f5ae51. That commit changed source/search.html to add the accepted "Just like string parameters using the :text modifier" sentence in the text-search paragraph. The commit subject mentions GF#15973, but its git-svn revision matches the Jira comment on FHIR-17461.

Additional context:
The linked Zulip thread confirms the underlying distinction: _text is a resource-wide search parameter, while :text is an intentional modifier on applicable typed search parameters. FHIR-I minutes from 2018-07-30 record FHIR-17461 in the approved Persuasive with Modification block vote. The current source also separately defines text as a string modifier with advanced text handling and retains the accepted _text/_content paragraph, so the remaining :text wording is not a stale contradiction.

AutoFHIR reconciliation:
No source files were changed. The active source/search.html search page already contains the accepted FHIR-17461 resolution text in the Text Search Parameters section, and changing the string section from :text to _text would now remove deliberate, still-current modifier guidance.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-17461 in core unless the work group chooses to reopen the broader search-modifier design; do not replace current string :text guidance with _text as part of this issue.
