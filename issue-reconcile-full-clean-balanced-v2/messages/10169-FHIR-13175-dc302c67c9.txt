FHIR-13175: Audit history parameter cardinality clarification

Issue request:
FHIR-13175 was a Published/Persuasive with Modification FHIR-core HTTP issue for STU3. It asked what the "single" column meant in the history interaction parameter table, especially because the _at row also said the result "may be more than one." The approved resolution was to remove the ambiguous "single" column, document that each history parameter can only be used once, and clarify that the more-than-one note refers to resource versions rather than repeated parameters.

Initial application:
The issue was applied by git commit 43de3831ef5165991d96e0a259157b399fdb6a6f, svn revision 14166, which removed the "single" cells from source/http.html, changed the _at parenthetical to "may be more than one version of a given resource," and added "Each of these parameters SHALL not appear more than once." A follow-up typo commit uppercased NOT, and later FHIR-17265 moved the more-than-one-version clarification into the surrounding history notes while pointing _at to the date-search notes.

Additional context:
The current source/http.html page is the active RESTful API (HTTP) page linked from source/documentation.html. Later Published issues FHIR-17265 and FHIR-35781 refined the same history parameter table and are already represented on the combined branch; their changes retained the FHIR-13175 cardinality rule. A 2017 Zulip thread shows real implementer confusion around the old "dateTime single" _at wording, and FHIR-I minutes on 2018-07-09 list FHIR-13175 as Persuasive with Mod. Direct Zulip and Confluence key searches found no conflicting community record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current HTTP history section no longer has the ambiguous "single" column, separates parameter name/type/description, says there are no prefixes or modifiers, and states that each listed history parameter SHALL NOT appear more than once. The current notes also retain the clarification that there may be more than one version of a given resource in the history.

Recommendation:
Keep this empty no-change audit commit as-is. No follow-up source edit is needed for FHIR-13175 unless a future work-group decision changes history parameter repeatability or _at semantics.
