FHIR-5863: Audit bundle reference wording

Issue request:
FHIR-5863 was a Published/Persuasive DSTU1 correction for FHIR-core references section 1.16.0.2. It asked to remove outdated Bundle reference-resolution text that said applications should match either entry.id or entry.link[self], because those were not the correct Bundle entry identity elements for that purpose.

Initial application:
The issue was applied in git commit 5544902951a4fe943445361593076ae8a3361dc5, whose subject is "#5863 - fix old text in references". That commit removed entry.link[self] from source/references.html and added text saying matching is based on full URLs by prepending the entry base.

Additional context:
The current build has Bundle active in source/fhir.ini and the current reference guidance has since been refactored. source/references.html now directs relative references in Bundles to the base URL implied by Bundle.entry.fullUrl, and source/bundle/bundle-notes.xml contains the detailed resolving algorithm that looks for matching Bundle.entry.fullUrl values and version ids. The obsolete phrase entry.id or entry.link[self] is absent from the current source. Zulip and Confluence searches found no related discussion or minutes that would change the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already avoids the stale entry.id/entry.link[self] instruction and conveys the modern Bundle.entry.fullUrl-based resolution rule.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-5863 unless a future work group decision changes Bundle reference-resolution semantics.
