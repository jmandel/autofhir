FHIR-23835: Audit existing AuditEvent patient guidance

Issue request:
FHIR-23835 was a Published/Persuasive Security change request for STU3, applied for R5, asking for AuditEvent guidance that patient/subject references should be included for auditable events when possible, with matching security-module text, examples, and possible profile work.

Initial application:
The issue was initially applied by HL7/fhir PR #708, merged as e5f777ad514d570245abf181a3637f154a2529a9 on 2019-10-03. That change added an AuditEvent patient-subject section using the then-current AuditEvent.entity representation, added the linked security-module Accounting of Disclosures text, and touched AuditEvent examples.

Additional context:
FHIR-33155 later reached Published/Persuasive with Modification and deliberately changed the model from the old patient-as-entity guidance to a first-class AuditEvent.patient element; commit 4af66cb9b0e7b2d14f39a4eecfb660d55ff964c9 added the element, search parameter wiring, examples, and replaced the #patient narrative to point at AuditEvent.patient. FHIR-36144 then confirmed that the #patient section no longer mentions entity.who because the new .patient element carries the patient-subject linkage. The original Zulip discussion supports advisory/best-practice guidance rather than a mandatory universal profile, and no Confluence reference was found that changes that conclusion.

AutoFHIR reconciliation:
This empty audit commit makes no source change. AuditEvent is active in the current build, and the current source already expresses the requested rule through AuditEvent.patient, the AuditEvent notes section, the Security and Privacy module link, and patient-bearing AuditEvent examples. Reintroducing the old .entity wording would conflict with later published decisions.

Recommendation:
Keep this audit as-is. Future work, if any, should be limited to the later AuditEvent.patient issue family and should not use FHIR-23835 to restore or duplicate obsolete .entity guidance.
