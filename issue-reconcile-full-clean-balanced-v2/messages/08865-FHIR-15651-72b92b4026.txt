FHIR-15651: Audit eld-12 invariant correction

Issue request:
FHIR-15651 was a Published/Persuasive technical correction for the STU3 ElementDefinition page. It reported that ElementDefinition invariant eld-12 used valueSet.is(uri) and valueSet.as(uri) even though FHIRPath defines is/as as operators, and requested the operator form `(valueSet is uri)` / `(valueSet as uri)`.

Initial application:
The issue was applied in git-svn revision 13340, now commit 2ba76c80e44bd38eb8874c39029b36fb887628f3, which changed source/datatypes/elementdefinition.xml from valueSet.is(uri)/valueSet.as(uri) to the requested FHIRPath operator syntax. The commit subject says "fix eld-7", but the patch changes the eld-12 row and matches the Jira request.

Additional context:
ElementDefinition is active normative build-scope content in source/fhir.ini, and the current ElementDefinition spreadsheet defines ElementDefinition.binding.valueSet as canonical(ValueSet). Later history changed the invariant away from a choice-type uri test: GF#16055 made valueSet a single canonical element, GF#17431 added the exists() guard, and FHIR-34306 added the permitted local-reference # prefix. Current source therefore uses `valueSet.exists() implies (valueSet.startsWith('http:') or valueSet.startsWith('https') or valueSet.startsWith('urn:') or valueSet.startsWith('#'))`, so the reported is/as function misuse is absent. A community search found only a 2019 Zulip question about whether OperationDefinition should have a similar invariant, with no Jira or Confluence evidence that changes the ElementDefinition conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The historical FHIR-15651 correction was applied, and the current build-scope source has since been refactored into an expression where the original operator-vs-function issue no longer applies.

Recommendation:
Keep this audit commit as-is. Do not edit current ElementDefinition source for FHIR-15651; any future work on eld-12 should be driven by later issues about canonical/local value set references rather than by the obsolete STU3 valueSet[x] uri syntax.
