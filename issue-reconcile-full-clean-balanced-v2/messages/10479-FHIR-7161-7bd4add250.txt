FHIR-7161: Audit Observation related type removal

Issue request:
FHIR-7161 was a Published OO change request with a Persuasive with Modification resolution. It asked to remove unnecessary Observation.related.type complexity, specifically the DSTU1 wording that a relationship type SHOULD be provided and that COMP/composed observations should not be displayed or interpreted without their related observations. The accepted resolution said the composed type had been removed and made into Observation.component, the wording had been removed, and grouping guidance was already covered with related FHIR-7160 notes.

Initial application:
The issue was applied across the Observation relationship work rather than as a single modern-source edit. Commit 348f096acfd2c65b60b6ba759f214f756d403709 reintroduced Observation.component and removed the old COMP/composed sentence from Observation.related.type while that related backbone still existed. Commit 5ed5b573f8ed326eafc243d7c8981c87ad7818b1 explicitly tagged #7161 and edited Observation notes. Later commit 5bdc6559670c09dbdcbfcdf5f716f84455c6e600 remodeled Observation.related into Observation.hasMember and Observation.derivedFrom, completing the removal of the old typed related structure from the current Observation model.

Additional context:
Observation is an active resource in source/fhir.ini, so source/observation is current build scope. The current StructureDefinition has Observation.hasMember, Observation.derivedFrom, and Observation.component, with no Observation.related or Observation.related.type element. The current Observation notes explain grouping through DiagnosticReport.result, Observation.component, Observation.hasMember, and Observation.derivedFrom. A current-source search found no stale Observation.related.type wording in active Observation narrative or StructureDefinition files; an old observation relationship ValueSet source file still contains COMP, but it is not referenced by current source/fhir.ini or current Observation bindings, and build.fhir.org returns 404 for that ValueSet. No directly relevant Zulip or Confluence record was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This audit makes no source change. The current active Observation source already implements the Jira decision: the unneeded typed Observation.related/COMP wording is gone, component grouping is modeled by Observation.component, and independent related observations are described through hasMember/derivedFrom plus DiagnosticReport.result guidance.

Recommendation:
Keep this no-change audit commit. Any cleanup of orphaned historical source files such as valueset-observation-relationshiptypes.xml would require a separate build-scope/editorial decision and is not needed to satisfy FHIR-7161.
