FHIR-17648: Audit extraDetails markdown datatype

Issue request:
FHIR-17648 was a Published/Persuasive Patient Administration change request asking for HealthcareService.extraDetails to change from string to markdown so longer service details can include basic formatting.

Initial application:
The request was applied before this reconciliation in Brian Postlethwaite's 2018-10-28 HealthcareService commit bd89a75a69, whose subject explicitly included GF#17648. Comparing the old spreadsheet before and after that commit shows the HealthcareService.extraDetails row changed from string to markdown. The later 2021 source migration preserved that datatype in structuredefinition-HealthcareService.xml.

Additional context:
HealthcareService is an active current-build resource in source/fhir.ini. The current authoritative StructureDefinition source already gives HealthcareService.extraDetails type markdown, and the FHIR model-definition library also exposes it as FHIR.markdown. A broad source search found the QUICK model-definition example lists extraDetails as System.String, but that model has no markdown primitive and does not contradict the FHIR conformance datatype. The linked Zulip thread supports the original rationale for markdown; no exact Confluence reference or conflicting community evidence was found.
