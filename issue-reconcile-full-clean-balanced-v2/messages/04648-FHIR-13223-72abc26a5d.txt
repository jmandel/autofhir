FHIR-13223: Audit Identifier v3 II mapping guidance

Issue request:
FHIR-13223 was a Published/Persuasive STU3 FHIR-core datatypes issue asking for deterministic Identifier guidance for HL7 v3 II values with either a root alone or a root plus extension. The accepted resolution requested a note on Identifier mapping and an example for a bare OID carried with system urn:ietf:rfc:3986.

Initial application:
The issue was applied by SVN/Git commit 855c13275882f454d7e38e3bf4a07225b8c24332 (#13223 / svn revision 12458), which added V3 Mapping Issues for Identifier to source/datatypes-mappings.html, added root-only and root-plus-extension examples to source/datatypes-examples.html, and linked the Identifier datatype guidance in source/datatypes.html to that note.

Additional context:
The current build-scope datatypes pages still contain the requested rule and examples: the active type-pages configuration maps datatypes to datatypes.html, source/datatypes.html links from the Identifier guidance to the v3 mapping note, source/datatypes-mappings.html states both mapping cases, and source/datatypes-examples.html shows both a bare root and a root with extension. Later Identifier namespace clarifications in FHIR-41478, FHIR-45479, and FHIR-42959 revised adjacent globally unique identifier wording but retained the v3 mapping link and do not change the root/extension mapping. Zulip threads found during reconciliation discuss implementer use of the existing note but did not identify a conflicting work-group decision.

AutoFHIR reconciliation:
No source change was made. The current source already carries the accepted FHIR-13223 guidance and examples in active datatypes source files, and adding redundant prose would not change implementer understanding.

Recommendation:
Keep this no-change audit commit as-is. Future work should only revisit the v3 II mapping if a new work-group decision changes the mapping itself or asks for broader CDA/FHIR round-trip guidance.
