FHIR-29661: Audit Subscription entered-in-error status

Issue request:
FHIR-29661 was Published/Persuasive for R5 and asked to add entered-in-error to Subscription.status and SubscriptionStatus.status, with documentation of its use, after validator warnings showed those status elements lacked an entered-in-error value.

Initial application:
The Jira snapshot records the issue as applied in commit 33b409a4b6d544598262f2f074ebb4b6dc466157. That broad source-rework commit introduced the XML Subscription and SubscriptionStatus definitions with entered-in-error in the status short text and an entered-in-error-status build extension; later source history preserved the value while moving the binding to the current subscription-status terminology.

Additional context:
Subscription and SubscriptionStatus are active resources in source/fhir.ini and remain approved in the current build configuration. The current subscription-status CodeSystem defines entered-in-error as "This subscription has been flagged as incorrect," the ValueSet includes that CodeSystem, and both Subscription.status and SubscriptionStatus.status bind required to http://hl7.org/fhir/ValueSet/subscription-status. Confluence FHIR-I WGM 202101 minutes independently record the FHIR-29661 motion as "Will fix as suggested" with the same 17-0-0 persuasive vote. Later FHIR-35788 renamed the ValueSet to SubscriptionStatusCodes and restored the SubscriptionStatus code system naming without changing the entered-in-error semantics.

AutoFHIR reconciliation:
This commit intentionally makes no source changes because the current authoritative, build-scope Subscription and SubscriptionStatus sources already contain the requested value, terminology binding, and concise use documentation.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-29661 unless a future work-group decision changes how Subscription or SubscriptionStatus should model entered-in-error.
