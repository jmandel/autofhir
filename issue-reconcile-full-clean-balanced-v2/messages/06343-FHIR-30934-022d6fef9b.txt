FHIR-30934: Audit vital signs mustSupport definition

Issue request:
FHIR-30934 is an Applied/Persuasive with Modification OO change request for R5. It reported that the Vital Signs Observation profiles used mustSupport while the conformance rules were understood to say the base specification did not use mustSupport, and asked either to remove the flags or define what they mean and update any conflicting base-spec text.

Initial application:
The issue was applied by git commit d3c35bc492, which added a top-level "Must Support Expectations for Vital Signs Profiles" section to source/observation/observation-vitalsigns-profile-introduction.xml. The added text matches the final Jira comment: senders populate mustSupport elements when data is available and permissions allow, and receivers can consume the element when relevant to their business case.

Additional context:
OO first pulled the issue from a November 2024 block vote because the group had not settled whether to remove or keep mustSupport. The 2025-03-21 OO minutes record the final decision to add basic mustSupport text and mark FHIR-30934 Applied. Current conformance/profiling text says implementation guides can use ElementDefinition.mustSupport in profiles and that the base application does not assign obligations in resource definitions; obligations.html explicitly allows obligations and mustSupport in profiles defined in the base specification. Later vital-signs work such as FHIR-48427 refined which elements carry mustSupport, but does not reverse the FHIR-30934 decision to keep a Vital Signs profile-level definition.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The active Observation resource folder includes the Vital Signs ImplementationGuide, that IG includes observation-vitalsigns-profile-introduction.xml, and the current introduction already contains the required mustSupport expectations. The remaining conformance text distinguishes base resource definitions from profiles and is not misleading enough to require a FHIR-30934 source edit.

Recommendation:
Keep this audit commit as-is. No follow-up source change is needed for FHIR-30934 unless OO or FHIR-I later decides to replace these profile-level mustSupport expectations with obligations or to revise mustSupport policy globally.
