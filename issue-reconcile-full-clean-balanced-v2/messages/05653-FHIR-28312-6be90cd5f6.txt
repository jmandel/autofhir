FHIR-28312: Audit validate profile canonical type

Issue request:
FHIR-28312 is a Published/Persuasive FHIR-core technical correction. It asked that the Resource $validate operation's profile input parameter use the canonical type rather than uri, because a profile is identified by a canonical URL and may need a version.

Initial application:
The issue was explicitly applied on the R4B branch by git commit de542fc499c93c20ed4fe6c8f2d46914a4b5f1a0, "Fix FHIR-28312", which changed source/resource/operationdefinition-Resource-validate.xml profile from uri to canonical. Jira comments and later FHIR-37997 show that the R4B correction was temporarily lost during the R5 migration, then source history restored the same canonical type in commit 378fe392dd102168828a322355a66656eff4d1bb.

Additional context:
FHIR-37997 is the direct R5 regression tracker for this same parameter. Current active source/resource/operationdefinition-Resource-validate.xml defines profile as canonical and, after later FHIR-44864 work, constrains it to StructureDefinition with targetProfile. The Resource resource and its operation list are active current-build source through source/fhir.ini and source/resource/list-Resource-operations.xml.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already implements the FHIR-28312 decision, including the later R5 restoration and the more specific targetProfile constraint.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-28312 in core unless a future work-group decision changes the Resource $validate profile parameter again.
