FHIR-7347: Audit Schedule actor reference scope

Issue request:
FHIR-7347 was a Published/Persuasive PA change request from the DSTU1 cycle asking that Schedule.actor no longer reference Any. The accepted resolution narrowed the target to Patient | Practitioner | RelatedPerson | Device | HealthcareService | Location, matching Appointment participant actor types as they existed then.

Initial application:
The issue appears to have been applied by git commit cc2f3880832e6bc2903d1e99e19342eb02674696 on 2015-07-07, whose message names Tracker# 7347 and whose patch changed the Schedule.actor type in the then-authoritative schedule spreadsheet from Reference(Any) to Reference(Patient|Practitioner|RelatedPerson|Device|HealthcareService|Location). The old spreadsheet source was later migrated into the current StructureDefinition XML source.

Additional context:
Schedule is an active current-build resource in source/fhir.ini. Current source/schedule/structuredefinition-Schedule.xml defines Schedule.actor as Reference with explicit targetProfile entries for Patient, Practitioner, PractitionerRole, CareTeam, RelatedPerson, Device, HealthcareService, and Location, so it is not an unconstrained Any reference. Later published scheduling decisions explain the extra current target types: FHIR-9271 added PractitionerRole, FHIR-9209 changed Schedule.actor to allow multiple actors for composite scheduling, and FHIR-23075 added CareTeam. FHIR-22696 later added Group to Appointment participant actor, but that issue scoped the change to Appointment, Encounter, and AppointmentResponse rather than Schedule.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed for FHIR-7347 because the current Schedule.actor definition preserves the issue's substantive requirement: it is limited to schedulable resource types rather than Any. Adding Group or removing later target types would be a new scheduling decision, not a correction required by this issue.

Recommendation:
Keep this audit commit as-is. Do not reopen FHIR-7347 for current source changes; if PA wants Schedule.actor to track newer Appointment.actor additions such as Group, that should be handled by a separate tracker rather than by reinterpreting this DSTU1 correction.
