FHIR-12223: Audit required binding definition

Issue request:
FHIR-12223 was a Published, Persuasive FHIR-core vocab issue asking to fix the definition of required binding because the old wording, "instances of this element SHALL include a code from the specified value set", could be read as making the element mandatory even when cardinality allowed it to be absent. The approved resolution was to make the requested wording change.

Initial application:
The issue was applied in svn revision 10435, now git commit 0579550ad80c4ef88eb1432d46033e0e68d0c346, which changed the required-binding wording in the then-current terminology/conformance pages. No Issue-Reconcile-Key commit for FHIR-12223 was present on the combined branch before this audit.

Additional context:
Later Published terminology issue FHIR-12444 clarified that the short required-binding description should use concept-focused wording and that exact conformance criteria vary by datatype. Later Published issue FHIR-27144 clarified that required bindings are evaluated against the expansion of the bound value set, and the combined branch already contains the corresponding reconciliation commit aligning the binding-strength CodeSystem sources. FHIR-51935 is a later Resolved - change required R6 clarification about Coding and repeated elements; it is useful background but is not in this run's applied/published source-edit scope.

AutoFHIR reconciliation:
No source change was made. Current build source no longer contains the old "instances of this element SHALL include a code" wording. The Binding Strengths table says the concept in the element must be from the value set, the Required Binding Strength section uses the later expansion wording, and the datatype-specific CodeableConcept rules clarify that at least one Coding must be present and text alone is not a substitute.

Recommendation:
Keep this empty audit commit as-is. The current source satisfies FHIR-12223 after later terminology clarifications; any further required-binding refinements should proceed under later issues such as FHIR-51935 rather than reopening this DSTU2 clarification.
