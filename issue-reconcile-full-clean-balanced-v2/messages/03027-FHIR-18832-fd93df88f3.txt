FHIR-18832: Audit Condition.category clarity

Issue request:
FHIR-18832 was a Published FHIR-core Patient Care change request for STU3 asking for more clarity around the open-ended Condition.category element. Its Persuasive with Modification resolution pointed to FHIR-18833 as the change that would make Condition.category extensible.

Initial application:
The Jira comments show the binding-strength part was applied in commit 3d048a25d4fb, which changed the then-authoritative source/condition/condition-spreadsheet.xml binding for Condition.category from example to extensible. FHIR-18833 separately applied its clinicalStatus/category invariant change in commit 27de028df2d3.

Additional context:
Condition remains an active core resource in source/fhir.ini, and the current build-scope source is source/condition/structuredefinition-Condition.xml rather than the retired spreadsheet source. Later Condition-category work changed the target state: commit 91c6eeca7e loosened the binding from extensible to preferred as part of FHIR-29409, then Applied issue FHIR-48358 deliberately changed Condition.category to an example binding and removed the related con-2 warning. Applied issue FHIR-54454 then replaced the enumerated short display with the broad text "Classification of type of condition" because the binding is now example. Zulip and Patient Care minutes around FHIR-48358 show this was an intentional later Patient Care discussion, not an accidental regression.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Condition.category source already reflects the latest applied Patient Care decisions: it has a broad short display, contextual comment, and example binding. Restoring the older STU3 extensible binding would conflict with later applied Jira decisions.

Recommendation:
Keep this audit commit as-is. If Patient Care wants stronger interoperability guidance for Condition.category in the future, open or apply a new issue rather than resurrecting FHIR-18832's older extensible-binding application.
