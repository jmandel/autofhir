FHIR-44994: Audit NutritionIntake reported semantics

Issue request:
FHIR-44994 was an Applied/Persuasive OO change request for R6 asking that NutritionIntake.reported[x] stop reading as only the person or organization that reported consumption information, because that wording did not explain the boolean choice. The approved resolution was to adapt the Event pattern description so the intent of reported[x] is clearer.

Initial application:
The issue was applied in commit 1dc1c4ae89127b3ac2794da0d1d5bf9a8bbf9d5c, which replaced the old NutritionIntake.reported[x] person/organization wording with reported-vs-primary/source wording and added Group as a reference target. That commit also carried unrelated NutritionIntake changes for adjacent issues, but the reported[x] text hunk is the FHIR-44994 application.

Additional context:
NutritionIntake is an active current-build resource in source/fhir.ini and is assigned to OO. The Event pattern text says reported[x] indicates a secondary reported record rather than an original primary source-of-truth record and may indicate the source of the report. OO Nutrition minutes on 2024-03-27 record an 8-0-0 vote to adapt the Event pattern description in NutritionIntake for reported[x]. A later QA commit adjusted the NutritionIntake wording to say the source that provided information about the consumption, but kept the boolean meaning as reported rather than primary.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/nutritionintake/structuredefinition-NutritionIntake.xml already states that NutritionIntake.reported[x] indicates a reported rather than primary record and may also indicate the source, which resolves the ambiguity for the boolean choice without adding redundant prose.

Recommendation:
Keep this no-change audit. No follow-up is needed for core FHIR unless the work group wants a broader harmonization pass to make NutritionIntake.reported[x] wording exactly match the Event pattern string; the current semantic rule is already clear and in active build scope.
