FHIR-5615: Audit unused binding warning removal

Issue request:
FHIR-5615 was Published/Persuasive for DSTU1 and asked that generator warnings about bindings not being used stop ignoring profile-defined/profile-used bindings. The decisive Jira comment records the applied resolution as removing the hint entirely because it was more trouble than it was worth, with SVN revision 4549.

Initial application:
The historical application is Git commit c65988b6eb544d9a09ca0313baed37ffc9d7a5f0, imported from SVN revision 4549, which deleted the ResourceValidator hint that emitted "Binding is not used" when a binding's element type was still unknown. No source evidence shows that exact hint returning after that application.

Additional context:
The old in-repository Java build tooling was later removed by commit 9f549566d1346cad7db6d2afca6080d7cebdfbbe when the FHIR build switched to a Gradle dependency on HL7/kindling. The active build.gradle.kts now depends on org.hl7.fhir:kindling and runs org.hl7.fhir.tools.publisher.Publisher. A pinned check of current HL7/kindling ResourceValidator source at 8655559ffed4ce52874fdfaf2e247d0b5b0b0260 found no "Binding is not used" warning; the remaining binding checks cover missing bindings and derive unknown element type from actual element use. Jira, Zulip, and Confluence searches found no related later decision reversing FHIR-5615.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The Published issue's requested behavior was already applied by deleting the problematic hint, the old local validator source is no longer part of this checkout's active build, and the current external Kindling validator used by the build does not contain the stale unused-binding warning.

Recommendation:
Keep this audit commit as-is. If a future build again reports false unused-binding hints, the likely follow-up belongs in HL7/kindling's validator rather than this FHIR spec source checkout, but no such current issue was found during reconciliation.
