FHIR-37761: Simplify sdf-24 and sdf-25 path checks

Issue request:
FHIR-37761 was a Published FHIR-core technical correction resolved Persuasive. It asked to fix the StructureDefinition sdf-24 and sdf-25 FHIRPath constraints, specifically noting that the expressions should not use $this and that the path comparison could be written without substring arithmetic.

Initial application:
FHIR-31759 originally introduced sdf-24 and sdf-25 in commits e54acba3221b3015925ae860c64bc41966700740 and bb07b227109ce945918994d616a37171b3ba46f2 using id.substring(0,$this.length()-...) comparisons. FHIR-37761 was explicitly applied in commit 2cc91c21fca7fa12a0d60457be87e8ec2e123d2a, which changed those checks to path.substring(0,$this.path.length()-...) and added failing invariant fixtures. The current source retained the remaining $this plus substring structure, so the prior application fixed the invalid id/$this.length() form but did not fully apply the Jira's requested expression cleanup.

Additional context:
source/fhir.ini actively maps structuredefinition to the StructureDefinition resource and lists StructureDefinition in the conformance category, so source/structuredefinition/structuredefinition-StructureDefinition.xml is current build-scoped source. Later Published CodeableReference decisions, including FHIR-39176 and the already-published FHIR-38957 reconciliation on the combined branch, preserved the underlying SHALL NOT policy enforced by sdf-24 and sdf-25. No directly relevant Zulip or Confluence evidence for FHIR-37761 was found.

AutoFHIR reconciliation:
This commit updates sdf-24 and sdf-25 to derive the CodeableReference parent path with replaceMatches('\\.reference$', '') and replaceMatches('\\.concept$', '') instead of using $this.path.length() with substring arithmetic. The conformance meaning remains the same: targetProfile and binding constraints still belong on CodeableReference, not on CodeableReference.reference or CodeableReference.concept.

Recommendation:
Keep this source fix as-is. It is a narrow correction to active StructureDefinition source that completes the requested FHIRPath cleanup without changing the CodeableReference policy or weakening the later SHALL NOT alignment.
