FHIR-14567: Audit v2 case sensitivity resolution

Issue request:
FHIR-14567 was Published with a Persuasive with Modification resolution for FHIR-core CodeSystem/V2 terminology content. It reported that FHIR's V2 CodeSystem representations were using CodeSystem.caseSensitive=false while the old external-code-system text asserted that Version 2 codes were case sensitive; the final resolution was to say that V2 code systems may or may not be case sensitive and to carry the correct case from the v2 Standard into UTG.

Initial application:
The issue was applied by upstream git-svn commit 079c8d6557f42f597b18fd2c43ea84b63155dedf, matching Jira's svn revision 14630 comment. That commit added the "V2 code systems may or may not be case sensitive" note to the then-current V2 table pages and stopped the V2 importer from forcing all generated V2 CodeSystem.caseSensitive values to false or true.

Additional context:
The Vocab WG minutes for 2018-06-14 record the same 10-0-0 motion captured in Jira. Later UTG migration history removed source/v2 and the V2/V3 tabs from the core Code Systems page, and the current active core terminology source now directs authoritative external terminology use to terminology.hl7.org. The remaining tools/tx/v2 template contains the historical "may or may not" note, but repository search found no current build reference to tools/tx/v2, while active source pages link HL7 V2 Tables to THO.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core build source no longer contains the incorrect blanket statement "Version 2 codes are case sensitive" and does not publish core-owned V2 CodeSystem resources with stale caseSensitive values; it delegates V2 table details to THO, whose current hl7.terminology.r5 7.1.0 package contains V2 CodeSystem resources with explicit caseSensitive values.

Recommendation:
Keep this audit commit as-is. No FHIR core source correction is needed for FHIR-14567; any future disagreement about individual V2 table case sensitivity should be handled in THO/UTG rather than by reintroducing duplicate V2 case-sensitivity guidance in core.
