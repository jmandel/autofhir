FHIR-23741: Audit Resource.id RESTful clarification

Issue request:
FHIR-23741 was Published/Persuasive for R5 and asked to clarify the Resource.id comment so the old create-only statement was scoped to RESTful systems rather than all resource uses.

Initial application:
No source commit explicitly mentioning FHIR-23741 was found. The old absolute Resource.id comment was carried into the R5 source rework, then FHIR-20651 loosened it to cover create and conditional update cases, and FHIR-27052 changed the active Resource.id comment to explicitly scope it to FHIR RESTful interactions.

Additional context:
FHIR-27052, FHIR-42909, FHIR-28587, and the linked Zulip discussions refine the same rule family: Resource.id is important in RESTful interactions, but resources can lack an id in operations, transient exchange, and other non-RESTful contexts. The current resource narrative lists those examples, and the active Resource StructureDefinition is in the current build through the Resource infrastructure entry in source/fhir.ini.

AutoFHIR reconciliation:
This audit intentionally makes no source change. The current source already conveys the seed clarification and the later accepted refinements; replacing it with the exact 2019 proposed wording would drop later conditional-update, operation, and non-RESTful context guidance.

Recommendation:
Keep this no-change audit commit as-is. Do not reapply the exact FHIR-23741 sentence unless the work group wants to reopen the broader Resource.id guidance, because the present wording is more complete after later accepted decisions.
