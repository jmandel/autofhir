FHIR-13819: Audit NamingSystem preferred-id operation

Issue request:
FHIR-13819 was a Published/Persuasive with Modification STU3 FHIR-I request to add a NamingSystem operation originally described as "canonical-system". It was to take an existing system identifier plus a requested identifier syntax and return the preferred system identifier, or an OperationOutcome/error when no matching or preferred identifier exists; the resolution also asked for documentation that the operation could look through ValueSet identifiers expressed as OIDs when lookup is unambiguous.

Initial application:
The issue was applied by svn revision 13096, now git commit 639af19746c3e8722b34d1afae934d9b919cf4c6, as NamingSystem.$preferred-id rather than as a literal $canonical-system operation. Later source refactoring moved the operation into source/namingsystem/operationdefinition-NamingSystem-preferred-id.xml and listed it in source/namingsystem/list-NamingSystem-operations.xml.

Additional context:
Current build scope includes NamingSystem as an active resource in source/fhir.ini. The current NamingSystem operations list includes OperationDefinition/NamingSystem-preferred-id, and the current OperationDefinition has the requested id/type inputs, result output, preferred identifier behavior, and text allowing servers to look through code systems and value sets. Later published Jira decisions FHIR-22105, FHIR-37673, and FHIR-37674 refined the same operation's date/period, active NamingSystem, and preferred identifier behavior; those decisions are already represented on the combined branch and do not require a duplicate FHIR-13819 source change.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already contains the operation requested by FHIR-13819 under its applied name, $preferred-id, and adding a new $canonical-system operation or renaming the current operation would contradict the applied history and later published refinements.

Recommendation:
Keep this audit commit as-is. Future changes to NamingSystem.$preferred-id behavior should be handled under specific later operation issues, not by reopening the original FHIR-13819 naming/application decision.
