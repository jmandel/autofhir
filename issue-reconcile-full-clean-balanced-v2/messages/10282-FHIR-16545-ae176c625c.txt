FHIR-16545: Audit ConceptMap target narrative fix

Issue request:
FHIR-16545 was a Published/Persuasive STU3 FHIR-core issue reporting that NarrativeGenerator.java threw a null pointer when a ConceptMap lacked targetUri and rendered only the last value when multiple targetUri values were supplied.

Initial application:
The issue was applied in git-svn commit 47920d1368e5cca392d45bbce8eed4025476dc9e, whose message matches the Jira comment's svn revision 14887. That commit changed the STU3 NarrativeGenerator ConceptMap rendering to guard missing source/target values and to render "(unspecified)" rather than dereferencing a missing target. The multiple-target concern did not require generator support because the Jira application note says there can only be one target.

Additional context:
The current core build no longer contains implementations/java NarrativeGenerator.java. ConceptMap remains an active FHIR-core resource in source/fhir.ini, and the current active ConceptMap StructureDefinition represents the relevant current fields as single-valued: ConceptMap.targetScope[x] has max 1 and ConceptMap.group.target has max 1. No Zulip or Confluence evidence was found that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because the historical STU3 tooling bug was fixed in the original application commit, that commit is already an ancestor of the combined branch, and the current active ConceptMap source preserves the single-target cardinality expectation.

Recommendation:
Keep this audit commit as-is. If future work needs to change ConceptMap narrative rendering, it should occur in the current publisher/tooling repository rather than in this core spec checkout, and it should account for the current ConceptMap R5/R6 model rather than the retired DSTU3 Java generator.
