FHIR-19707: Audit canonical datatype typo correction

Issue request:
FHIR-19707 was a Published/Persuasive STU3 technical correction for the FHIR-core datatypes page. It reported that the canonical datatype description said "A URI that is refers to a resource by it's canonical URL" and asked to remove the extra word "is".

Initial application:
The same canonical typo family was first applied through FHIR-19540: git commit 2ff0cecf5fa2e072b1183306c98019df81b0f1ca changed source/datatypes.html from "A URI that is refers" to "A URI that refers". The FHIR-19707 Jira comment says the "is" typo was already fixed and points to GH#de65b7ad for fixing "it's"; merge commit de65b7ad7b1acf46921e40d2e404c7be97643921 changed the same source row from "resource by it's canonical URL" to "resource by its canonical URL".

Additional context:
The affected text is source/datatypes.html, the core datatypes narrative page used for datatype publication; source/fhir.ini maps datatype pages to datatypes.html by default. FHIR-19540 is a tightly related Published/Persuasive issue for the same extra "is" typo and is already represented on the combined branch by commit d793a3a17a41e89cb4443d628df77c755f9a2d31, so this reconciliation does not duplicate it. FHIR-19681 is a duplicate report of the same canonical text and is not an independent source-edit decision. Quoted Zulip and Confluence searches for FHIR-19707 and canonical datatype typo terms found no conflicting community record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source says "A URI that refers to a resource by its canonical URL", so both the requested removal of "is" and the Jira-commented correction from "it's" to "its" are already present.

Recommendation:
Keep this no-change audit commit as-is. No follow-up source work is needed for FHIR-19707; future editorial changes to canonical datatype wording should be handled separately from this completed typo correction.
