FHIR-12548: Audit _summary=text id inclusion

Issue request:
FHIR-12548 was a Published/Persuasive FHIR-core Search change request asking that the _summary=text definition explicitly include Resource.id, because the existing DSTU2 wording listed text, meta, and mandatory elements but Resource.id is optional.

Initial application:
The request was applied in svn/git-svn commit 68a24d7d2a27803384a959490f071c6e8fdd6357, which changed source/search.html to say that _summary=text returns the text, id, meta, and mandatory elements. No prior AutoFHIR reconciliation commit for FHIR-12548 was present on the combined branch.

Additional context:
The relevant page is still an active core search narrative page: source/hierarchy.xml includes search.html under Exchange, and source/fhir.ini's search-rules notes still point maintainers to the search.html summary table. Later FHIR-33002 refactored the same table to clarify top-level mandatory element behavior while preserving the id inclusion. Zulip discussion in #implementers > resource ids records the original implementer question and consensus to file tracker #12548; Confluence searches found no conflicting minutes.

AutoFHIR reconciliation:
No source change was made. Current source/search.html already states that _summary=text returns <code>text</code>, <code>id</code>, <code>meta</code>, and top-level mandatory elements, which satisfies the Jira request in the current build scope.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-12548 unless a future work group decision changes _summary=text semantics.
