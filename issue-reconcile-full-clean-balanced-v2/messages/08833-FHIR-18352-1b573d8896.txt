FHIR-18352: Audit modifier-extension wording

Issue request:
FHIR-18352 was a Published/Persuasive FHIR-core clarification for the STU3 extensibility page. It asked to replace confusing prose, "Any modifierExtension defined outside an extension cannot be placed in another extension," with clearer wording: "Is-modifier elements not defined as part of an extension's definition cannot be conveyed."

Initial application:
The issue was applied by git commit 1932b2b59558a616c0ca6d62c123b1c92dc6e15f, which changed source/extensibility.html from the confusing modifierExtension sentence to the requested is-modifier wording. The current source still contains that rule in the Modifier Extensions section, with later clarifying parenthetical and editorial punctuation changes.

Additional context:
Earlier FHIR-8548 and FHIR-11036 established the complex-extension background for internal isModifier elements being represented as extension rather than modifierExtension. Later FHIR-37903 added explicit root-isModifier guidance and a parenthetical example without reversing FHIR-18352. A 2025-2026 Zulip thread and Submitted issue FHIR-52858 discuss whether the same section should mention BackboneElement/BackboneType more explicitly, but that is an unresolved broader clarification and not a reason to alter the applied FHIR-18352 wording here.

AutoFHIR reconciliation:
This audit commit makes no source change because the current build-scope source/extensibility.html already conveys the FHIR-18352 correction: is-modifier elements outside an extension's own definition cannot be conveyed, and extensions cannot carry modifierExtension internally except through understood internal extension components represented as extension.

Recommendation:
Keep this no-change audit. Treat FHIR-52858 or any future modifierExtension location guidance as a separate work-group decision rather than reopening this already-applied STU3 wording correction.
