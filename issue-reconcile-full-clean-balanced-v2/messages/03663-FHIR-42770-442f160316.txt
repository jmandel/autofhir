Issue request:
FHIR-42770 was an Applied R5 OO change request with a Persuasive with Modification disposition. It argued that NutritionIntake.consumedItem.type and NutritionIntake.consumedItem.nutritionProduct were too strict; the final resolution loosened type to 0..1 while originally keeping consumedItem 1..* and nutritionProduct 1..1.

Initial application:

The same commit also applied the later FHIR-44995 loosening for consumedItem and nutritionProduct, and commit 0e3589c18bcdc00f4e44db634c01a7a435c340a4 added the required FHIR-44995 invariant.

Additional context:
FHIR-44995 superseded the narrower part of FHIR-42770 by approving consumedItem 0..*, nutritionProduct 0..1, and an invariant requiring type or nutritionProduct when an item is present. FHIR-45063 later restructured the resource so the current top-level repeating backbone is NutritionIntake.nutritionItem, with consumedItem and notConsumedItem separated beneath it; FHIR-45063 is already represented on the combined branch and should not be republished here.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. NutritionIntake is an active current-build resource, and the current StructureDefinition carries the applied type relaxation as NutritionIntake.nutritionItem.type 0..1 while preserving the later FHIR-44995 and FHIR-45063 model decisions.

Recommendation:
Keep this audit commit as-is. Do not restore nutritionProduct to the original FHIR-42770 resolution because FHIR-44995 later loosened that requirement, and use the current nutritionItem paths for any future NutritionIntake cardinality work.
