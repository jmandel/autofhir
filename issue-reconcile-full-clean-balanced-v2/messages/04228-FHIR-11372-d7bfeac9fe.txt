FHIR-11372: Audit Claim supportingInfo resource support

Issue request:
FHIR-11372 is Published/Persuasive with Modification. It asked to add Claim.information.clinical 0..* Resource(Any) so supporting clinical information could accompany a Claim; the recorded resolution was that resources may now be specified in Claim/EOB.information.

Initial application:
No explicit git commit mentioning FHIR-11372 was found. The relevant 2016 source change, commit aaa1e5693e, changed Claim.information.value[x] from string|Quantity to string|Quantity|Attachment|Reference(Any) and changed the definition to cover resources, documents, images, references, and inclusion. Later, commit afb5ec66f6 renamed Claim.information to Claim.supportingInfo under FHIR-19460 while preserving that broad value[x] support.

Additional context:
FHIR-11394 is the EOB-side seed from the same Claim/EOB.information.clinical request and is audited separately in this reconciliation. FHIR-11373 and FHIR-11395 are missing-teeth follow-ups that depend on the same supporting information mechanism, but they ask a narrower modeling question than this Claim resource-support audit. Current source/fhir.ini lists claim as an active resource, so source/claim/structuredefinition-Claim.xml is in the current build scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Claim.supportingInfo backbone remains 0..* and its value[x] is an open choice type with a definition explicitly allowing resources, documents, images, references to data, and actual inclusion of data, which satisfies the modified Jira resolution without reintroducing an obsolete .information.clinical element.

Recommendation:
Keep this audit commit as-is. No current core source fix is needed for FHIR-11372; future work should only revisit if the work group wants a narrower typed Reference(Any) surface instead of the current open value[x] modeling.
