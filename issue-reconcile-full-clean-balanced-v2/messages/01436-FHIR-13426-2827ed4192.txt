FHIR-13426: Generalize Composition narrative

Issue request:
FHIR-13426 was Published/Persuasive with Modification for STU3 and asked that Composition not be described as solely part of the FHIR Document paradigm. The accepted resolution changed the opening definition from a logical document to a more general logical package and asked that document-specific requirements apply only when Composition is used in the document context.

Initial application:
The Jira-tagged SVN/git import commit 43a79eb084 changed the then-authoritative Composition spreadsheet definition from "single logical document" to "single logical package". The current StructureDefinition carries that generalized package wording, but active narrative and the catalog profile still retained document-only phrasing introduced through later source conversion/refactoring.

Additional context:
The Composition resource is active in source/fhir.ini, so source/composition narrative and profile files feed the current build. The 2017 Zulip thread that led directly to FHIR-13426 confirms the intended distinction: Composition may be used outside document Bundles, while FHIR document obligations apply only in the document paradigm. Later FHIR-25438 further adjusted clinical-attestation wording and is handled as a separate, tightly related reconciliation commit.

AutoFHIR reconciliation:
This commit updates the active Composition narrative to introduce Composition as a coherent package before describing FHIR Documents, makes the document Bundle rule conditional on document use, and corrects section prose so narrative is possible rather than mandatory. It also aligns the active catalog profile's inherited root definition with the package wording.

Recommendation:
Keep this source change. It completes the published FHIR-13426 application in current source without broadening document-specific profile requirements; review FHIR-25438 separately for the remaining clinical-attestation/status wording.
