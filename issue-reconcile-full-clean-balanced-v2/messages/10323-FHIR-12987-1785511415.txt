FHIR-12987: Audit conformance search parameters

Issue request:
FHIR-12987 was a Published FHIR-core DSTU2 change request resolved Persuasive. It asked FHIR-I to identify existing search parameters that should apply across conformance/definition resources, such as jurisdiction and version, and turn those into common search parameters for those resources.

Initial application:
The issue was explicitly applied in git commit 92f8f38e47f2461144e7a1151ff88473ca1dc72a, which records svn revision 12852 and added a Conformance core block to source/searchparameter/common-search-parameters.xml with conformance-* SearchParameters for url, version, name, status, date, context, identifier, title, description, publisher, jurisdiction, and effective. The current source no longer keeps that exact conformance-* block because later interface-search-parameter work replaced that representation.

Additional context:
FHIR-38999 was a later Published/Persuasive with Modification FHIR-I decision for R5 that reconsidered interface search parameters and their common/resource-specific representation. It was applied by commit 6c4526c5e03f2ec90cc8d0a5f62d89e3812e76dc, which deliberately removed the conformance-* block from common-search-parameters.xml. Current build-scope source declares CanonicalResource and MetadataResource as active interface resources and defines shared interface SearchParameters such as CanonicalResource-jurisdiction, CanonicalResource-version, CanonicalResource-status, and MetadataResource-effective. Current CI output also publishes those shared interface ids and does not publish the old conformance-status or resource-specific ActivityDefinition-status/ActorDefinition-status ids. Community searches found only bot notifications for FHIR-12987 and no later discussion conflicting with the FHIR-38999 resolution.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because the seed's durable requirement, searchable common metadata across conformance/definition artifacts, is represented in current active source through the CanonicalResource and MetadataResource interface search parameter bundles, while the older FHIR-12987 conformance-* common bundle entries were intentionally removed by a later final FHIR-I decision.

Recommendation:
Keep this audit commit as-is. If the work group wants further changes to how interface search parameters are rendered in the registry, handle that under FHIR-38999 follow-up work or a new issue rather than restoring the obsolete conformance-* block from FHIR-12987.
