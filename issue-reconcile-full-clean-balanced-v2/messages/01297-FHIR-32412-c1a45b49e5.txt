FHIR-32412: Audit MedicationRequest statusChanged addition

Issue request:
FHIR-32412 is a Published/Persuasive Pharmacy WG change request for R5 asking to add a new MedicationRequest "StatusChanged" attribute for when the current status took effect, with cardinality 0..1 and type dateTime, so systems can communicate the status, status reason, and status date without traversing Provenance.

Initial application:
The issue was applied by historical commit 7acfd680713d0152367c6841b366974c594b4ec0, which added MedicationRequest.statusChanged to the active MedicationRequest StructureDefinition as a 0..1 dateTime element. Later version-diff metadata records MedicationRequest.statusChanged=+ in source/fhir.ini.

Additional context:
MedicationRequest is an active resource in source/fhir.ini, and the current StructureDefinition still contains MedicationRequest.statusChanged immediately after statusReason with the requested cardinality and dateTime type. Pharmacy WGM minutes for May 2021 confirm the group agreed that knowing when something was put on hold was useful while discussing the modeling. Later FHIR-55004 asks what the purpose of statusChanged is and whether metadata or a generic pattern would be better, but it is Waiting for Input/Unresolved and only records a plan to research the original purpose, so it does not supersede the published FHIR-32412 decision. The current combined branch already has a separate FHIR-32859 reconciliation for adjacent MedicationRequest.status wording; it does not change the statusChanged decision.

AutoFHIR reconciliation:
Made no source change. The current build-scope MedicationRequest source already implements the requested 0..1 dateTime statusChanged element, and there is no final later Pharmacy WG decision requiring a different model.

Recommendation:
Keep this audit commit as-is. Revisit only if Pharmacy WG resolves FHIR-55004 or another final tracker changes the scope, semantics, or placement of MedicationRequest.statusChanged.
