FHIR-16799: Audit CDS Hooks service guidance

Issue request:
FHIR-16799 was Published with resolution Persuasive with Modification. The ballot comment questioned whether CDS Hooks support should change the CDS Hooks element mapping around PlanDefinition.data-requirement or add a specific field; the approved resolution was to add documentation clarifying that any ECA Rule could potentially be exposed as a CDS Hooks service.

Initial application:
No source commit explicitly mentions FHIR-16799. The same documentation family appears to have been applied through the November 2018 CDS Hooks/PlanDefinition work: commit 1c7aa38, linked from FHIR-18844, added guidance for CDS Hooks with PlanDefinitions and explicitly described the special case of a PlanDefinition used as an event-condition-action rule that can be integrated through CDS Hooks. Commit 60a763e then cleaned up the same page's CDS Hooks request/response mappings.

Additional context:
The old RequestGroup artifact referenced by the Jira issue is no longer an active resource; the current build uses RequestOrchestration, with PlanDefinition, GuidanceResponse, and RequestOrchestration all active in source/fhir.ini. Current active Clinical Reasoning source defines Event-Condition-Action rules as PlanDefinitions, shows applying an ECA rule with $apply, and the Clinical Decision Support Services page states that Clinical Reasoning content can be exposed through a wrapper around PlanDefinition $apply for CDS Hooks. Later FHIR-53085 deliberately moved the detailed CDS Hooks profiles and mappings to the Using FHIR Clinical Reasoning with CDS Hooks implementation guide while retaining concise core guidance, and that later audit is already present on the combined branch. Direct Zulip and Confluence searches for FHIR-16799 found no conflicting community record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core source already conveys the approved clarification in active built pages, updated for the RequestGroup-to-RequestOrchestration rename and the later move of detailed CDS Hooks material to the implementation guide; adding another local sentence about any ECA rule would be redundant and could drift from the IG.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed for FHIR-16799 unless the CDS work group later chooses to bring detailed CDS Hooks profile or mapping content back from the implementation guide.
