FHIR-19727: Audit externalized manufacturing operation

Issue request:
FHIR-19727 asked whether MedicinalProduct.manufacturingBusinessOperation should be externalized so that both MedicinalProduct and MedicinalProductPackaged could reference it. The issue is Applied with resolution Persuasive with Modification for R5; BR&R approved the modified approach in which manufacturing business operation became primarily a wrapper for an ActivityDefinition/RegulatedAuthorization relationship, with direct manufacturer and simple type support for lighter-weight cases.

Initial application:
The issue was applied before this reconciliation. Commit e6ec244b21 added MedicinalProductDefinition.manufacturingBusinessOperation.authorization as a RegulatedAuthorization reference, and commit e5ec514c55 completed FHIR-19727 by replacing the authorization reference-number/regulator details with an operation type choice that could reference ActivityDefinition plus an authorization reference and adjusted the example. This matches the Jira record that the build had already been changed.

Additional context:
The current build no longer has the R4-era MedicinalProduct/MedicinalProductPackaged names; fhir.ini maps them to active MedicinalProductDefinition and PackagedProductDefinition resources, both in current build scope. Later FHIR-29708 reworded and renamed manufacturingBusinessOperation to MedicinalProductDefinition.operation, renamed manufacturer to organization, and current source now expresses the operation type as CodeableReference(ActivityDefinition, PlanDefinition). Current MedicinalProductDefinition.operation.type says a RegulatedAuthorization points to the same plan or activity referenced there, while RegulatedAuthorization.subject can reference ActivityDefinition, PlanDefinition, MedicinalProductDefinition, and PackagedProductDefinition. PackagedProductDefinition still carries direct manufacturer elements for basic package manufacturer cases; adding a second direct package operation reference would go beyond FHIR-19727's modified resolution.

AutoFHIR reconciliation:
No source change was made. The current authoritative source already preserves the approved externalization pattern: operation details can live in ActivityDefinition/PlanDefinition and authorizations can point to the same activity/plan, while the product keeps simple operation type and organization data.

Recommendation:
Keep this audit commit as-is. If BR&R now wants a direct PackagedProductDefinition.operation element or a distinct reusable ManufacturingBusinessOperation resource, that would be a new modeling decision rather than unfinished application of FHIR-19727.
