FHIR-13365: Move Duration calendar note under Duration

Issue request:
FHIR-13365 was Published/Persuasive with Modification for STU3. The issue raised confusion between UCUM durations and ISO 8601 calendar-duration behavior in CQL/FHIRPath; the final resolution did not add a new unit code system, but required datatype date-issue guidance including leap seconds and a Duration usage note saying whole-number durations should resolve to natural calendar boundaries, e.g., Feb. 1 + 1 mo = March 1.

Initial application:
The issue was applied by svn revision 12713, represented in git as a236df77223290bcb12158e0302aa6c5aa163f63, which corrected the leap-second note and added the whole-number duration calendar-arithmetic implementation note under the Duration variation in source/datatypes.html. A later GF#16612 reordering commit, 0b0fbffb3b3f1d2e53f541470345ab8b7b3fc89a, moved that note into the Distance subsection while removing it from Duration.

Additional context:
source/fhir.ini actively lists Duration as a datatype and routes datatype pages through datatypes.html, so source/datatypes.html is current build-scope narrative for this guidance. The existing Duration value set remains UCUM-based, consistent with the modified resolution's choice to add guidance rather than define ISO calendar unit codes. FHIR-23564 later added a distinct semantic note that Duration is a length of time, and the already-published FHIR-40624 reconciliation fixed headings in the same Quantity-variation section but did not address this misplaced FHIR-13365 note. Jira, Zulip, and Confluence searches found no later decision reversing the calendar-boundary note.

AutoFHIR reconciliation:
This commit moves the whole-number Duration calendar-arithmetic implementation note out of the Distance subsection and back into the Duration subsection, after the Duration usage row. It also fixes the obvious typo "1 month in is defined" to "1 month is defined" while preserving the approved example and guidance. No generated artifacts were edited.

Recommendation:
Keep this source correction as-is. It restores the published FHIR-13365 guidance to the datatype it governs, removes misleading Distance-local guidance, and does not require a new work-group decision.
