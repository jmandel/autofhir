FHIR-17628: Audit Questionnaire definition precedence

Issue request:
FHIR-17628 was a Published/Persuasive STU3 correction for Questionnaire.item.definition after the work group agreed that the linked ElementDefinition must not override values already present on the Questionnaire item. The Jira resolution records this as an oversight in applying the earlier definition-based Questionnaire change.

Initial application:
The issue was applied in git-svn history by b641c08c59f1d31ac03965fb46cad5229b8e9689, which changed the Questionnaire.item.definition description from values that SHALL be inferred from the ElementDefinition rather than the Questionnaire instance to values that MAY be derived from the ElementDefinition when the corresponding Questionnaire elements have no value.

Additional context:
FHIR-12186 introduced Questionnaire.item.definition with the intended rule that item values can be inferred from a definition while Questionnaire-provided values override it. FHIR-23128 later removed the obsolete inline list from the element definition and moved the mapping details into the Questionnaire notes. The current build-scope Questionnaire source is active in source/fhir.ini, and the current notes retain the FHIR-17628 precedence rule: definition-based values can be used, but any information provided on the Questionnaire item overrides the definition.

AutoFHIR reconciliation:
No source files were changed. The current source already preserves the issue's required semantics, with the detailed guidance maintained in source/questionnaire/questionnaire-notes.xml and the element definition referring readers to those notes.

Recommendation:
Keep this audit commit as-is. No follow-up core FHIR source change is recommended unless a future work group decision changes definition-based Questionnaire behavior.
