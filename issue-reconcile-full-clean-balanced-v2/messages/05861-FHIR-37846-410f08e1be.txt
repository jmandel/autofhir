FHIR-37846: Clarify _in and _list membership search

Issue request:
FHIR-37846 was Published/Persuasive with Modification for R5. It requested replacing the draft reference-search :in modifier with a standard _in search parameter, retaining _list rather than deprecating it, defining List and Group membership semantics, and having _in point to those membership rules.

Initial application:
Commit 3e70503739324804fad2ddfc1a424e1e6b4e6692 removed reference-search :in/:not-in behavior, added Group and List membership prose, and introduced _in/_list narrative. Commit e6032af6c9cbf233e1a804e87310b81fb8937fe5 added Resource-_in to the common SearchParameter bundle; later commit ddecc63591d23dab5767aa2888c985a7c75964b6 moved the resource-parameter documentation and dropped the explicit _list retention/preference note while changing Resource-_in to reference type.

Additional context:
The 2022-08-17 Zulip implementation thread records the editor's follow-up question on whether CareTeam should be an _in target; Lloyd McKenzie agreed, Bundle was rejected, and the current source now states CareTeam, Group, and List as the allowed targets. The same thread records that functional-list literals should remain _list-specific future work rather than being forced into _in. FHIR-39342 later clarified the functional-list link for _list, so the current note must preserve _list for functional list literals as well as backward compatibility.

AutoFHIR reconciliation:
This commit adds the CareTeam, Group, and List targets to the machine-readable Resource-_in SearchParameter so it matches the prose target rule. It also restores a nuanced _list note: ordinary List membership can use _in with a List target, while _list remains for backward compatibility, systems not supporting broader _in membership, and List-specific functional-list literals.

Recommendation:
Keep this commit as-is. The edited files are active build inputs for the Resource common search parameters and the FHIR search page, and the changes close the remaining gaps without re-opening broader CareTeam membership-page or functional-list syntax questions.
