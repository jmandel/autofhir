FHIR-22622: Audit mapping map-title syntax

Issue request:
FHIR-22622 was a Published FHIR-I change request, resolved Not Persuasive with Modification for R5, asking whether the human-readable title in the mapping-language `map "..." = "..."` statement was a string or an identifier. The final decision was to change the prose from "quoted in strings" to "delimited by double-quotes" and to clarify that FHIRPath single-quote/backtick rules did not govern this FML syntax.

Initial application:
The issue was applied in commit fae5f7f920c5e2a6152cd17317b22a3e441f7848, which changed source/mapping-language.html so the `map` statement's human-readable name was described as delimited by double-quotes. The mapping-language page is in current build scope through source/hierarchy.xml and publish.ini, and no earlier combined-branch reconcile commit for FHIR-22622 was found.

Additional context:
A later Published FHIR-I issue, FHIR-27915, replaced the old `map` metadata statement with the current `/// name{.property}* = {value}` metadata syntax. That later change was applied in commit c372919350db4764cebd887053bd3bd567234faa, removing the exact FHIR-22622 sentence from the active mapping-language page. The linked grammar still preserves an optional legacy `mapDeclaration`, but the active narrative no longer contains the ambiguous wording that FHIR-22622 targeted. FHIR-27915 already has a combined-branch audit commit, so this seed should not publish a duplicate related decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The original issue's requested wording was applied historically, and the current authoritative mapping-language source is correct after the later metadata-syntax rewrite because it no longer presents the ambiguous `map` title prose.

Recommendation:
Keep this no-change audit as-is. Any future decision to remove, deprecate, or further document legacy `map` declarations belongs with the FHIR-27915 metadata-syntax family or a new work-group decision, not with FHIR-22622.
