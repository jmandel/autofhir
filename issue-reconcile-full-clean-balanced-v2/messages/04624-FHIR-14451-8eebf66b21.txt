FHIR-14451 was a Published/Persuasive STU3 Patient Administration issue. It asked PA to review Appointment, AppointmentResponse, ChargeItem, Encounter, and EpisodeOfCare against the workflow alignment report, either aligning the resources with workflow patterns or marking intentional divergences as ignored/suppressed. The final resolution says there were no longer workflow warnings in the QA report.

Initial application:
The Jira comments show PA divided the review across Appointment/AppointmentResponse, ChargeItem, EpisodeOfCare, and Encounter. EpisodeOfCare was intentionally left structurally different because it acts as a meta-event/container, with divergences treated as workflow-report suppressions. ChargeItem was explicitly applied at SVN revision 13751, preserved as Git commit 43760072c2364a02e6a33a38eed0ba9db622654a, which renamed ChargeItem.participant to ChargeItem.performer, role to function, and updated the example/search-parameter rows. I did not find a separate commit explicitly tagged GF#14451 for Appointment, AppointmentResponse, or Encounter, but later source history added current mapping-exception files for those PA resources.

Additional context:
The current build scope differs from the STU3 artifact list. source/fhir.ini still lists Appointment, AppointmentResponse, Encounter, and EpisodeOfCare as active PA resources, while ChargeItem was removed from the current core build by commit 71567db3ee039ac6977be5f96a7e013896569a36. The active PA resources now have workflow/FiveWs mappings and mapping-exception files that document intentional Request/Event/FiveWs divergences: Appointment and AppointmentResponse have Request-pattern exception files; Encounter and EpisodeOfCare have Event-pattern exception files. The current suppressed workflow warning file has no resource-specific warning for active Appointment, AppointmentResponse, Encounter, or EpisodeOfCare; the only FHIR-14451 target resource still named there is inactive ChargeItem.
