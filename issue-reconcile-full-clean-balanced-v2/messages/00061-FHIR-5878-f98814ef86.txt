FHIR-5878: Audit retired DocumentManifest request linkage

Issue request:
FHIR-5878 was a Published/Persuasive with Modification DSTU1 change request asking for DocumentManifest to carry a request/resource reference so a manifest could identify the workflow request it fulfilled. The accepted resolution added DocumentManifest.related 0..* with identifier and Reference(Any) children, required related-id and related-ref search support, and shortened the DocumentManifest.identifier definition.

Initial application:
The issue was applied in git commit 9838cb4a889645d232f78878b97271ba900acf8a, whose message explicitly says "DocumentManifest support for related request [5878]". That commit added DocumentManifest.related, DocumentManifest.related.ids, DocumentManifest.related.refs, and the relatedids/relatedrefs search parameters to the then-authoritative DocumentManifest spreadsheet source.

Additional context:
DocumentManifest is no longer an active current-build resource. The current source/fhir.ini resource list omits documentmanifest, lists DocumentManifest under removed resources, comments out its workgroup/TLA/status entries, and redirects the old type to List. The current history page records DocumentManifest as removed with "use List". Later Published issue FHIR-33021 documented the decision path: IHE MHD had moved from DocumentManifest to List and the work group intended to retire DocumentManifest unless other use cases surfaced; the linked Zulip thread records the same rationale. Published issue FHIR-39006 then moved XDS mappings and an XDS example into List.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Reintroducing DocumentManifest.related is impossible in current build scope because the resource source was deleted. Adding a new request/related element to List would be a separate substantive model decision, not a safe mechanical carry-forward of this DSTU1 DocumentManifest tracker.

Recommendation:
Keep this audit commit as-is for FHIR-5878. If implementers need a current List-based way to point at fulfilled workflow requests, open or use a separate current-release tracker for List rather than reopening this already-applied and later-superseded DocumentManifest issue.
