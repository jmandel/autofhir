FHIR-41269: Audit MessageHeader sender relocation

Issue request:
FHIR-41269 was an Applied/Persuasive with Modification FHIR-core MessageHeader change request for R6. It asked whether MessageHeader.sender, MessageHeader.author, and MessageHeader.responsible should be removed, and the final resolution was to move sender under source as the last element and remove author and responsible.

Initial application:
The issue was applied by git commit 21db7ce85648ecbcc2a88295b74e4a4015053b22, which removed the top-level MessageHeader.sender, MessageHeader.author, and MessageHeader.responsible differential elements and introduced MessageHeader.source.sender. The same source-family commit also adjusted related MessageHeader search-parameter and mapping exception files. A later spelling/usage commit 871a89035ebfc9af87f56b538de42cdbdf5f58c0 changed the retained sender definition from sending system to sending entity.

Additional context:
INM minutes for 2023-09-13 record the 10-0-4 motion to move sender under source and remove author and responsible, applying the motion to FHIR-41269 and related MessageHeader issues. FHIR-41271 provided the messaging-context decision that MessageHeader is necessary for interpreting a message bundle but should not be used as persistent context after message contents are moved elsewhere. The current source/fhir.ini actively includes MessageHeader in the build and carries legacy conversion mappings from MessageHeader.sender to MessageHeader.source.sender while dropping author and responsible.

AutoFHIR reconciliation:
No source change was made. The authoritative current MessageHeader StructureDefinition already has MessageHeader.source.sender and no top-level MessageHeader.sender, MessageHeader.author, or MessageHeader.responsible elements; the current MessageHeader sender search parameter points to MessageHeader.source.sender. A repository search found only compatibility mappings in source/fhir.ini and stale generated-looking references in source/messageheader/messageheader.svg for the old top-level elements, and the run guardrail says not to make a source-changing commit when only a checked-in SVG/diagram appears stale and the authoritative source is correct.

Recommendation:
Keep this audit commit as-is for FHIR-41269. If diagram regeneration is later in scope for the FHIR build, regenerate MessageHeader diagrams from the current StructureDefinition rather than manually editing the SVG; no normative or conformance source change is needed for this issue.
