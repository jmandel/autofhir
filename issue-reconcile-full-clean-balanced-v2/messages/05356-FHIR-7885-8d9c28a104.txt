FHIR-7885: Audit Goal start date support

Issue request:
FHIR-7885 was a Published/Persuasive Patient Care change request from the DSTU1 cycle asking to add Goal.startDate for goals that begin after a later date or event. Its final Jira resolution says it was resolved as part of FHIR-8488, which approved adding Goal.start[x] 0..1 as date or CodeableConcept with the definition "The date or event after which the goal should begin being pursued".

Initial application:
The Jira comments for both FHIR-7885 and FHIR-8488 cite SVN #6806. The corresponding git-svn commit 8bd3bd917d537625fad908b5f0f6277d113b941e, "Goal tracker items", added Goal.start[x] with date | CodeableConcept, added the GoalStartEvent binding, and changed the target timing model. Later source refactors preserved that modeled element in the current StructureDefinition source.

Additional context:
The current build includes Goal as an active resource in source/fhir.ini. Current source/goal/structuredefinition-Goal.xml defines Goal.start[x] as 0..1, summary, types date and CodeableConcept, with the requested event/date definition and requirements. In XML/JSON choice serialization, the date choice is represented as startDate, so the current start[x] model satisfies the original Goal.startDate request while also preserving the FHIR-8488 event-start extension of scope. A later Published FHIR-12400 issue added the start-date search parameter; that is separate from this seed and is already present. No Confluence references or direct Zulip disagreement were found; a later Patient Care Zulip thread about dateTime concluded no time component use case was needed and produced no final Jira change.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Editing Goal to add a separate startDate element would duplicate or contradict the existing choice element, and narrowing Goal.start[x] to date-only would lose the event-based CodeableConcept approved in FHIR-8488.

Recommendation:
Keep this audit commit as-is. The current core source is correct for FHIR-7885; no follow-up is needed for the seed unless a future Patient Care decision explicitly changes Goal.start[x] types or dateTime support.
