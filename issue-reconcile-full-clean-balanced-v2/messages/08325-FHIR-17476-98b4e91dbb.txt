FHIR-17476: Audit mustSupport option guidance

Issue request:
FHIR-17476 was a Published/Persuasive FHIR-core change request for the profiling Must Support section. It asked the specification to distinguish mustSupport=true, mustSupport=false, absent mustSupport, and the reporter's proposed empty-value case; the accepted resolution was to provide guidance for false, add an explicit meaningWhenMissing, and state that derived specifications cannot remove or change to false when a parent declares true.

Initial application:
The issue was applied by 3864b3857f4924b02e5e68f3b8f03f0229bbb421, "GF#17476 - mustSupport rules", from SVN build revision 14330, immediately after the Jira comment recording svn revision 14329. That commit updated the active ElementDefinition spreadsheet source to add Meaning if Missing guidance for ElementDefinition.mustSupport, expand the false-value definition, and state that profiles can raise mustSupport from false to true but cannot lower it from true to false.

Additional context:
The related Zulip thread confirms the interpretive scope: absent means inherit from the predecessor/base definition, false cannot undo a parent's true, and the suggested fourth state is not valid because a boolean mustSupport can only be missing, true, or false. source/fhir.ini actively lists ElementDefinition as a current normative datatype/type-page artifact, and the profiling page is the active FHIR-core-profiling page cited by the issue. Later Published/Persuasive work, including FHIR-38134 and FHIR-24689, refined inherited meaning and corrected typos in the same current text; both are already represented on the combined branch and do not create a new FHIR-17476 source gap.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/datatypes/elementdefinition.xml states the explicit Meaning if Missing for ElementDefinition.mustSupport, including base-type false and profile inheritance behavior when absent, and current source/profiling.html says derived profiles can change Must Support from false to true but not from true to false and explains inherited mustSupport meaning.

Recommendation:
Keep this audit commit as-is. The current build-scope source already satisfies the FHIR-17476 resolution, and adding duplicate local prose about invalid empty boolean values or restating the same inheritance rule would not improve implementer understanding.
