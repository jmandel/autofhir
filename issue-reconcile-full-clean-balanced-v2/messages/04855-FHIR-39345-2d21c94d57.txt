FHIR-39345: Audit OperationDefinition opd-3 targetProfile rule

Issue request:
FHIR-39345 was Published/Persuasive with Modification for R5. It asked to fix the OperationDefinition.parameter.targetProfile short display typo "allowed reosurce types" and to adjust invariant opd-3 so targetProfile can be specified for parameters of type Reference, canonical, or a resource.

Initial application:
The issue was applied by git commit 116ec0f74df0b1d99395400acd7ba97688c56103, which updated source/operationdefinition/structuredefinition-OperationDefinition.xml to include resource parameters in opd-3 and fixed the short display typo. That commit used the then-requested ValueSet/resource-types expression.

Additional context:
FHIR-26411 is the supporting R5 decision that OperationDefinition.parameter.targetProfile also applies to inline resources. FHIR-44690 later found that FHIR-39345's resource-types ValueSet was too narrow by the time R5 finalized and corrected opd-3 to use ValueSet/all-resource-types; a later reconciliation commit also clarified the targetProfile definition for resource parameter types. OperationDefinition is active in source/fhir.ini. The only remaining old targetProfile prose found for this issue family is in source/operationdefinition/operationdefinition.svg, a generated-looking diagram artifact, while the authoritative StructureDefinition XML carries the current rule.

AutoFHIR reconciliation:
Made no source change. The current build-scoped OperationDefinition StructureDefinition already allows targetProfile for Reference, canonical, and resource parameter types, uses the later all-resource-types correction, and has the typo and definition gaps resolved. Editing only the stale SVG tooltip would violate the generated-diagram guardrail and would not be the authoritative source fix for this issue.

Recommendation:
Keep this no-change audit commit as-is. If the OperationDefinition SVG is regenerated or human maintainers decide checked-in diagram tooltips are in reconciliation scope, that should be handled as generated-artifact refresh work rather than as a FHIR-39345 source correction.
