FHIR-40275: Add BodyStructure spatial reference invariant

Issue request:
FHIR-40275 was Published/Persuasive for R5 by Orders and Observations. It requested BodyStructure.includedStructure.spatialReference as a 0..* Reference(ImagingSelection) and an invariant so an includedStructure uses bodyLandmarkOrientation or spatialReference, but not both.

Initial application:
The Jira comment points to PR commit 23e2e319d029113bfbefb1d6ab6e4e212c9f0ad2. Git history shows the actual BodyStructure source-changing commit e4ca687ba1cfd4d6cb3a2b321f1d9ec633d04c07 added BodyStructure.includedStructure.spatialReference, but it did not add any BodyStructure constraint. Later edits preserved the element and still had no invariant on BodyStructure.includedStructure.

Additional context:
BodyStructure and ImagingSelection are active current-build resources in source/fhir.ini. OO WGM minutes for 2023-01-16/20 describe the same target element and explicitly say it should have an invariant that either includedStructure.bodyLandmarkOrientation or includedStructure.spatialReference may be present. Zulip searches found no conflicting discussion.

AutoFHIR reconciliation:
Added the missing bds-1 error constraint to BodyStructure.includedStructure in source/bodystructure/structuredefinition-BodyStructure.xml with FHIRPath bodyLandmarkOrientation.empty() or spatialReference.empty(). This keeps the already-applied 0..* Reference(ImagingSelection) element and completes the approved invariant without changing unrelated BodyStructure content.

Recommendation:
Keep this source fix. It directly completes the Published FHIR-40275 request in the active BodyStructure StructureDefinition; no extension-pack or separate work-group follow-up is indicated for this issue.
