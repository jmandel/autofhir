FHIR-26949: Correct DeviceRequest doNotPerform modifier reason

Issue request:
FHIR-26949 was a Published/Persuasive FHIR-core OO change request for R5 asking to add doNotPerform to DeviceRequest according to the Request pattern so a provider can request that a patient not use or not start using a device.

Initial application:
The request was initially applied by b1671782cb, which added DeviceRequest.doNotPerform to source/devicerequest/structuredefinition-DeviceRequest.xml and was merged by 9f7516eb98 in PR #1217. That application added the element but left its isModifierReason copied from MedicationRequest, saying the modifier represented medication not being ordered or prescribed.

Additional context:
DeviceRequest is active in the current build through source/fhir.ini, and the current StructureDefinition already contains DeviceRequest.doNotPerform as a boolean modifier mapped to Request.doNotPerform. OO minutes from 2020-05-18 record the motion to add DeviceRequest.doNotPerform consistent with ServiceRequest and to continue using DeviceRequest.reason for the reason. Later DeviceRequest issues FHIR-42896 and FHIR-43444 preserved the element while fixing the reason comment and workflow mapping/product alignment.

AutoFHIR reconciliation:
This commit fixes the remaining stale application artifact by changing only DeviceRequest.doNotPerform.isModifierReason from a medication-specific explanation to a DeviceRequest-specific explanation. The authoritative source file is in build scope because source/fhir.ini lists devicerequest=DeviceRequest under active resources, so the hunk affects the generated DeviceRequest ElementDefinition rather than a stale generated diagram.

Recommendation:
Keep this commit. The element itself was already present, but the corrected modifier reason prevents DeviceRequest from publishing medication-specific semantics for a device-order negation element; no additional core source changes are indicated by the inspected Jira, source, git, Zulip, or Confluence evidence.
