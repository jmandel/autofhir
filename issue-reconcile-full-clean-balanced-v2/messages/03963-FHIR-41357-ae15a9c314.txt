FHIR-41357: Audit validate operation clarification

Issue request:
FHIR-41357 is an Applied/Persuasive with Modification FHIR-I R6 change request asking for a complete review of Resource.$validate invocation combinations, including target level, resource/profile parameter presence, and mode. The approved resolution relaxed the resource input requirement for instance-level invocation, removed the Resource Validation Mode profile parenthetical that required id nomination, clarified that profile may be supplied with create/update/delete modes, clarified that create cannot be invoked at instance level, and requested a summary table reconciled with FHIR-41356 system-level $validate.

Initial application:
No source commit explicitly mentioning FHIR-41357 was found. The requested source changes appear to have been applied implicitly in commit 85f4e0aaf0, whose message names FHIR-44864 but changes the same Resource.$validate source: it enables system-level invocation, relaxes the resource parameter text, removes the stale profile-mode parenthetical from the Resource Validation Mode code definition, says profile is required for mode=profile and may appear in other modes, adds the requested invocation table, and also constrains the profile parameter target. Commit 66cc0c8aac then refined the table wording.

Additional context:
FHIR-41356 is the same FHIR-I meeting family and supports the system-level row now present in the table; it is not decided here as a separate issue. FHIR-I minutes for 2023-11-06 record the 9-0-0 FHIR-41357 vote, note that the proposed disposition answers the ticket's questions, and explicitly say the table from the Zulip Validate operation thread needed to be updated based on the ticket resolutions. The current source is in build scope because source/fhir.ini lists Resource as an active infrastructure resource and source/resource/list-Resource-operations.xml references OperationDefinition/Resource-validate.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current operation definition already has system/type/instance support, the relaxed resource parameter rule, the create-at-instance prohibition, and profile-parameter guidance; the current code system no longer contains the obsolete "must be nominated by id" parenthetical; and the current notes file contains the requested system/type and instance-level combination table.

Recommendation:
Keep this audit commit as-is. Further source edits for FHIR-41357 would restate or disturb already-applied guidance rather than correct a current semantic problem; separate validate-operation issues such as FHIR-41356 or FHIR-44864 should remain independently audited if needed.
