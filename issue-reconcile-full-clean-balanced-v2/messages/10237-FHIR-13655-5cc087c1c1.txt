FHIR-13655: Audit token search case sensitivity

Issue request:
FHIR-13655 was a Published FHIR-core Search change request resolved as Persuasive with Modification. It asked to remove ambiguity from the token search type text that said token matches were literal "but not case sensitive", and the final decision was that token value matches are case-sensitive unless the relevant context, such as the code system semantics, says otherwise.

Initial application:
The issue was applied in git-svn commit 13fb1c1f102caf7de7266d6e78ab261efac06a1f, whose subject is "#13655 - change search token case sensitivity" and whose git-svn metadata records revision 12736, matching the Jira application comment. That commit changed source/search.html to say token matches are literal and case sensitive unless the underlying semantics indicate case-insensitive interpretation.

Additional context:
The current source/search.html page is in the current publication set via publish.ini and still carries the intended rule. Later nearby wording now says that token matches are case sensitive unless the context indicates case-insensitive interpretation, links to CodeSystem.caseSensitive, preserves the special _id case-sensitive rule from the related FHIR-13320 family, and preserves the later FHIR-40569 clarification that token searches over string-typed data are not case sensitive. The originating Zulip thread confirms the rationale, and no Confluence reference for FHIR-13655 was found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already implements the FHIR-13655 decision without the original misleading "but not case sensitive" wording, and the later refinements are compatible with the seed issue rather than reversals.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-13655 unless the work group later reopens the broader token search case-sensitivity policy.
