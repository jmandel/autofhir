FHIR-27051: Audit search failure OperationOutcome wording

Issue request:
Published/Persuasive FHIR-I issue asking whether the search-failure conformance SHALL applied only to returning a 4xx/5xx status code or also mandated an OperationOutcome, and asking to fix the duplicated "return value return value" wording. The accepted resolution made the 4xx/5xx status mandatory and made OperationOutcome a SHOULD only for failures at a FHIR-aware processing level.

Initial application:
The issue was applied in git commit 639dbcd2848776be444488fe66b23438c581256d, which replaced the FHIR-30240 interim "possibly accompanied" text in source/http.html with the current two-sentence rule. A later formatting-only commit wrapped the 4xx/5xx tokens in code tags without changing meaning.

Additional context:
The Zulip thread linked from Jira records Grahame Grieve's clarification that OperationOutcome is not a SHALL because 4xx/5xx responses can be generated before FHIR processing is involved. FHIR-I minutes show the issue was assigned for wording, and the Jira record later shows the Published/Persuasive resolution and vote. FHIR-30240 raised the same practical concern for unauthorized searches and was earlier applied with looser optional wording before this issue supplied the final SHOULD-level formulation.

AutoFHIR reconciliation:
No source change was made. The current source/http.html search failure paragraph says the response SHALL be a 4xx or 5xx status code and that, only when the failure occurs at a FHIR-aware level of processing, the HTTP response SHOULD include an OperationOutcome. The old mandatory and interim optional phrases are absent from current source.

Recommendation:
Keep this empty audit commit. The current source matches the final Published resolution and should not be weakened or duplicated elsewhere; future edits should preserve the distinction between generic HTTP/security failures and FHIR-aware processing failures.
