FHIR-39600: Audit endpoint connection terminology restoration

Issue request:
FHIR-39600 was an Applied/Persuasive Patient Administration correction reporting that UP-344 removed IHE endpoint-connection-type codes from THO, causing R4 and R4B Endpoint instances using codes such as ihe-xcpd to fail validation even though those codes were valid in the published R4/R4B code system.

Initial application:
No FHIR-core source commit was found for FHIR-39600. The active core Endpoint source already binds Endpoint.connectionType to http://hl7.org/fhir/ValueSet/endpoint-connection-type, and that value set composes all codes from the THO CodeSystem http://terminology.hl7.org/CodeSystem/endpoint-connection-type. The actual broken change was the external UTG/THO UP-344 update that removed the IHE concepts.

Additional context:
UP-529 was the UTG/THO follow-up for FHIR-39600 and restored the removed endpoint connection concepts as deprecated. Current THO CodeSystem endpoint-connection-type version 2.1.1 contains ihe-xcpd, ihe-xca, ihe-xdr, ihe-xds, and ihe-iid with status=deprecated, and THO release notes for version 5.5.0 list UP-529. Zulip discussion confirms the issue was considered a THO policy/terminology problem rather than a core source or extension-pack edit.

AutoFHIR reconciliation:
This empty audit commit makes no FHIR-core source change. The authoritative current core source is in build scope and correctly delegates the code inventory to THO; the compatibility repair was applied in the external UTG/THO source of truth.

Recommendation:
Keep this audit commit as-is. No core source change is needed unless FHIR later stops delegating this value set to THO. If validation problems recur, follow up in THO/UTG or terminology-server version handling rather than editing FHIR-core Endpoint source.
