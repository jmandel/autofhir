FHIR-37843: Audit PublishableCodeSystem migration

Issue request:
FHIR-37843 was a Published/Persuasive Vocab change request for R5 asking to define a PublishableCodeSystem profile based on the Publishable pattern.

Initial application:
The request was applied before this reconciliation. PR #2068 was merged as 0d4401be, with implementation commit 93fadfaa adding source/codesystem/structuredefinition-profile-publishablecodesystem.xml and registering StructureDefinition/publishablecodesystem in source/codesystem/implementationguide-CodeSystem-core.xml. Vocab tracker minutes from 2022-08-08 record the terminology profile tickets as pre-applied in core and mark FHIR-37843 Applied. The checked-in R5 history bundle still contains StructureDefinition/publishablecodesystem version 5.0.0, confirming the R5 publication surface.

Additional context:
A later Applied/Persuasive issue, FHIR-37959, changed the current R6 direction: remove the Shareable, Publishable, Computable, and Executable terminology-resource profiles from core FHIR and maintain them in the Canonical Resource Management Infrastructure IG. May 2025 joint Vocab/CDS/CQI minutes record 16-0-0 motions to reopen FHIR-37959 and adopt the CRMI resolution, and the linked UP-634 THO proposal was withdrawn after that decision. Current source/codesystem/implementationguide-CodeSystem-core.xml has an empty definition section, current source has no publishablecodesystem StructureDefinition source file, and the build-scope Shareable/Publishable pattern text points implementers to CRMI profiles. Existing combined-branch audits already cover the broader FHIR-37959 migration and the same-family FHIR-37845 ConceptMap profile issue.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding PublishableCodeSystem to core would reverse the later FHIR-37959 R6 decision rather than completing FHIR-37843; the current core source is correct for the present build after that later decision.

Recommendation:
Keep this audit as-is for FHIR-37843. Do not reintroduce the core PublishableCodeSystem source unless the work group revisits FHIR-37959 or the CRMI ownership decision. Future corrections to the profile definition or profile-hosting text should be handled in CRMI or under the broader migration issue, not this R5 application issue.
