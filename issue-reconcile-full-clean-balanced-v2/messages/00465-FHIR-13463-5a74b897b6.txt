FHIR-13463: Align DeviceMetric measurement model metadata

Issue request:
FHIR-13463 was Published with a Persuasive resolution for R5. It reported that DeviceMetric.measurementPeriod used the wrong Timing data type, accepted the DEV guidance to rename the element to measurementFrequency, change its type to Quantity, and update the short/definition to describe how often the metric is taken or recorded.

Initial application:
The issue was initially applied by the February 20, 2023 FHIR-13463 commits. Commit da85375c480410918e3d8414c892cb7d943b5c4f changed source/devicemetric/structuredefinition-DeviceMetric.xml from DeviceMetric.measurementPeriod/Timing to DeviceMetric.measurementFrequency/Quantity and updated the DeviceMetric example; commits ed7a066d0b9117e5000c76a8931bfc51a603c0d7 and 5c620cdc8b20d5b0710b0d2781ed695194c02faa corrected the example formatting. The active CQL model-definition Library examples were not updated by that initial application and still exposed measurementPeriod as Timing.

Additional context:
source/fhir.ini keeps both devicemetric=DeviceMetric and library=Library in the current build. source/library/list-Library-examples.xml lists the FHIR and QUICK model-definition Library examples, source/library/library-examples-header.xml links their XML model-info content, and publish.ini publishes those content XML files. A later combined-branch reconciliation for FHIR-39432 already aligned adjacent DeviceMetric category/calibration model metadata and resynchronized the FHIR Library attachment, but it did not cover this measurementPeriod/measurementFrequency issue. Community searches found no Zulip or Confluence decision that changes the Jira/source conclusion; Confluence only surfaced an R5 work-assignment page listing FHIR-13463.

AutoFHIR reconciliation:
This commit fixes the remaining in-scope source by changing DeviceMetric measurement metadata in source/library/library-fhir-model-definition-content.xml from measurementPeriod/FHIR.Timing to measurementFrequency/FHIR.Quantity, changing source/library/library-quick-model-definition-content.xml from measurementPeriod/QUICK.Timing to measurementFrequency/System.Quantity, and resynchronizing the embedded source/library/library-fhir-model-definition.xml data attachment from the FHIR model-info content.

Recommendation:
Keep this commit as-is. It completes the Published FHIR-13463 application on the active Library model-definition surfaces while preserving the already-correct primary DeviceMetric StructureDefinition and example. Do not treat source/fhir.ini's r5-changes DeviceMetric.measurementPeriod entry as current DeviceMetric metadata; it documents the old R4/R5 element-change map.
