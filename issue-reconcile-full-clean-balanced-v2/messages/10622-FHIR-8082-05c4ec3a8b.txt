FHIR-8082: Audit profiling glossary structure

Issue request:
FHIR-8082 was a Published, Persuasive with Modification DSTU1 clarification asking profiling.html to explicitly document the semantic levels around implementation guides, packages, conformance resources, and profiles. The accepted resolution described IGs as publication-level, packages as use-case-level, conformance resources as individual resource-level artifacts, and profiling as the overall process.

Initial application:
The Jira comment records svn revision 5531. The git-svn mirror commit 3d073195c6c4ccd8b5ef415d17227122a0fdd428, with git-svn-id build@5531, added the glossary table to source/profiling.html with Implementation Guide, Package, and Conformance Item rows plus profile/profiling explanatory text.

Additional context:
The current build still includes source/profiling.html through source/hierarchy.xml under the Conformance page. The current glossary retains the requested layered distinction, but later terminology work changed the noun "Profile" from the older package/item usage to a StructureDefinition constraint: FHIR-16414 was Published with a resolution to move Profile into the table as a set of constraints represented as a StructureDefinition, and commits dc4b3b45af and 72187f66d0 applied that terminology cleanup. FHIR-5585 is related background because it earlier renamed the old Profile resource to StructureDefinition and temporarily used profile for a conformance package.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/profiling.html already gives implementers the requested distinction between IG, package/grouping, conformance resource, and profile, and source/implementationguide explains that an IG is a published set of rules represented by an ImplementationGuide resource and distributed as a package. Reintroducing the original "Profile = Package" wording would now be incorrect after FHIR-16414.

Recommendation:
Keep this audit commit as-is. No follow-up source edit is recommended for FHIR-8082 unless the work group reopens the broader profile/package terminology policy.
