FHIR-22670: Audit extensible binding type-code clarification

Issue request:
FHIR-22670 was Published as Persuasive with Modification for R5. It reported that ElementDefinition.type.code is a uri with an extensible binding, but special elements such as Element.id used extension-only type metadata with no literal code/text value, making those definitions invalid under the then-understood extensible-binding rules. The final decision was to avoid broad R4 semantic change, use URI-based system type representation for the compiler-magic elements, and for R5 remove the dedicated terminologies.html#strings guidance while incorporating explicit extensible-binding rules for CodeableConcept, Coding, Quantity, uri/string, and code.

Initial application:
FHIR-I minutes record the July 2019 approval and August 2019 revote after Grahame reviewed the technical-correction implications. The R5 source application is git commit a512331f23d8fd3278b3c54e4e494346d5cb90c3, which added the bindable-datatype extensible-binding summary table to source/terminologies.html and commented out the old Binding String Values section. Later editorial/source reconciliation commits changed spelling and adjacent string/uri guidance without reversing the FHIR-22670 decision.

Additional context:
The linked compiler-magic propagation problem is FHIR-22493, already represented on the combined branch by 1fe72a4d6e1f599c52275beee434233cce5a5743. Current source also documents the URI-based FHIRPath System.* representation for simple ElementDefinition.type.code values and no active source outside historical release caches uses the old structuredefinition-json-type extension-only pattern. FHIR-13657, already represented on the combined branch, restored string/uri duplicate-code guidance without resurrecting the removed #strings section.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active terminologies page already contains the R5 extensible-binding table for uri/string and code, the old #strings section is commented out rather than rendered as current guidance, and current source no longer relies on extension-only ElementDefinition.type.code values for the system types that triggered the issue.

Recommendation:
Keep this no-change audit. Do not restore terminologies.html#strings or edit historical release-cache files for this seed; if old-publication artifacts need further correction, handle that through the publication/generator path and already-audited related issues such as FHIR-22493.
