FHIR-32520: Audit structural role example binding

Issue request:
FHIR-32520 was Published/Persuasive with Modification for R5 in the Security work group. It asked that the agent.role value set not behave like a broad extensible terminology and instead use an example binding to a curated, enumerated structural-role value set.

Initial application:
The issue was applied with FHIR-32453 in f577d68ceb. That commit changed AuditEvent.agent.role and Provenance.agent.role away from the old mixed functional/structural role text, kept the element bindings at example strength, and replaced the old broad security role value set with sample structural role content. Later source maintenance renamed and cleaned the terminology artifacts to source/terminologies/valueset-security-role-type-example.xml and source/terminologies/codesystem-security-structural-roles-example.xml.

Additional context:
AuditEvent and Provenance are active current-build resources in source/fhir.ini, and the structural-role code system is actively listed there. Current AuditEvent.agent.role and Provenance.agent.role both bind at example strength to http://hl7.org/fhir/ValueSet/security-role-type-example; that value set includes only the example structural-role code system. Later Applied issue FHIR-53882 intentionally revised AuditEvent-only role/type wording to make ISO 21298 optional, but it did not reopen the FHIR-32520 binding/value-set cleanup.

AutoFHIR reconciliation:
This audit commit makes no source change. The current source already carries the FHIR-32520 outcome: agent.role is not extensibly bound, and the old oversized mixed role vocabulary has been replaced by a small example structural-role value set.

Recommendation:
Keep this audit commit as-is. Do not restore the old role-code includes or make the example value set restrictive; any future change to AuditEvent or Provenance role terminology should be a new Security work-group decision.
