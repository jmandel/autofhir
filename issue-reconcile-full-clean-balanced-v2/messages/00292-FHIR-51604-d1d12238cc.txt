FHIR-51604: Audit CompartmentDefinition role clarification

Issue request:
FHIR-51604 was an Applied/Persuasive with Modification R6 clarification for FHIR-core CompartmentDefinition. It asked whether the core CompartmentDefinition instances are examples or definitional, whether HL7-defined compartments may be hosted elsewhere, and whether server-specific omissions or additions can be described. The approved text changed the note from "compartment definitions" to "CompartmentDefinition instances" and added that HL7-defined CompartmentDefinitions may be hosted on other servers, with no computable mechanism for describing a given server's compartment implementation.

Initial application:
The issue was applied by git commit e2bdd38ac37317d87d2264118e39cd7c5fc06d24, which changed source/compartmentdefinition/compartmentdefinition-introduction.xml in the active CompartmentDefinition resource page. The current source still says CompartmentDefinition instances can only be defined by HL7 International in the specification, that the definitions may be hosted on other servers, and that there is no mechanism to describe a server's compartment implementation.

Additional context:
source/fhir.ini lists compartmentdefinition as an active resource, page code, and approved artifact, so the checked narrative is build-scope source. Later applied issue FHIR-51725 changed the adjacent paragraph and intentionally broadened "no computable mechanism" to "no mechanism" while adding the current param/no-param rule; that later wording preserves the FHIR-51604 clarification.
