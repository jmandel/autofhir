FHIR-16495: Audit Observation stats total-count code

Issue request:
FHIR-16495 is a Published/Persuasive STU3 core Observation change request from OO. It asked to rename the Observation statistics code `totalcount` to `total-count` so the multi-word statistic code follows the hyphenated style used by the other statistics codes.

Initial application:
The request was applied in git commit 69761b715e5c64e5f02da9d3cab64b40f1b00d1b, "GF#16495, GF#16733, GF#16825", which changed the old source/observation/observation-spreadsheet.xml statistics row from `totalcount` to `total-count`. Later source rework converted the spreadsheet-derived terminology into explicit current source files; commit 33b409a4b6d544598262f2f074ebb4b6dc466157 created source/observation/codesystem-observation-statistics.xml with the corrected `total-count` code, and the R4B operation-definition rework also carried `total-count` in the operation prose.

Additional context:
Observation remains an active current-build resource in source/fhir.ini. The active Observation statistics CodeSystem now defines `total-count`, the ValueSet composes that CodeSystem, and the Observation-stats OperationDefinition lists `total-count` in its possible statistical analyses. A current source grep found no remaining `totalcount` spelling under source/. Direct Zulip and Confluence searches for FHIR-16495 found no issue-specific discussion; a 2016 Zulip thread discussed the Observation `$stats` "total count" concept but did not contradict the later hyphenated code-spelling decision. Related Observation issues from the same and nearby history are already represented separately on the combined branch.

AutoFHIR reconciliation:
This audit commit makes no source change. The current build-scope FHIR source already uses the Jira-approved `total-count` spelling everywhere found, and no stale `totalcount` source reference remains to correct.

Recommendation:
Keep this audit commit as-is. No FHIR core follow-up is needed unless a future generated artifact or terminology refactor reintroduces the obsolete `totalcount` code spelling.
