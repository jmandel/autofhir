FHIR-3558: Audit Resource.id restoration

Issue request:
FHIR-3558 is a Published/Persuasive FHIR-core change request asking to restore the logical id inside every resource instead of treating it only as external metadata. The requested representation was an XML `<id value="[logical-id]"/>` element and JSON `"id": "logical-id"`, with the id generally present except when a resource is submitted for create.

Initial application:
The FHIR-3558 Jira comments say the issue was done as part of task 3728. FHIR-3728 is the broader Published/Persuasive Atom replacement issue, and git commit 80fbeea24661109910d9da7ed435a444b9879846 (`{$3728} - major work with regard to replacing atom`) added `Resource.id` as a 0..1 `id` element in the Resource spreadsheet and added an id to the Resource example. The 2021 core source rework then moved the base Resource definition from the spreadsheet into `source/resource/structuredefinition-Resource.xml` while preserving `Resource.id`.

Additional context:
`source/fhir.ini` keeps `resource=abstract,Resource` under `[resource-infrastructure]`, so the base Resource definition is still in current build scope. Current source defines `Resource.id`, the Resource Identity narrative says each resource has an `id` element with expected exceptions, and XML format guidance explicitly says the resource id is an element rather than an XML attribute. Exact Zulip and Confluence searches for FHIR-3558 found no conflicting community evidence.

AutoFHIR reconciliation:
This commit intentionally makes no source change because the current build inputs already implement the requested rule and are not misleading. Additional prose would duplicate existing Resource Identity and XML-format guidance without changing implementer understanding.

Recommendation:
Keep this no-change audit commit as-is. Broader questions about Resource.id optionality or server assignment should be handled as separate, later issues, not as a reopening of this DSTU1 restoration request.
