FHIR-13288: Audit CodeSystem filter code clarification

Issue request:
FHIR-13288 was a Published/Persuasive with Modification FHIR-core CodeSystem clarification from Vocab. It reported that CodeSystem.filter.code said the filter code was used "in the instance", which was ambiguous, and the accepted resolution was to be specific that the use is in ValueSet.compose.include.filter.

Initial application:
The Jira comment records svn revision 14617. In the git-svn history, commit 9057d589419876ada95ad42e478ba03770fa5b76 changed source/codesystem/codesystem-spreadsheet.xml from "used in the instance" to "used as a filter in [[[ValueSet]]].compose.include.filter". Later source migration moved the authoritative CodeSystem definitions into source/codesystem/structuredefinition-CodeSystem.xml while preserving that clarification.

Additional context:
The 2018-07-19 Vocab minutes list tracker 13288 in block vote G as a CodeSystem Persuasive with Mod item and record the 6-0-0 approval motion. FHIR-18201 later clarified the matching ValueSet.compose.include.filter side of the same CodeSystem-filter relationship and is already represented on the combined branch. Current ValueSet source is consistent with the CodeSystem wording. A targeted source search found the old "used in the instance" wording only in source/codesystem/codesystem.svg, a generated-looking diagram tooltip, not in the authoritative XML definitions.

AutoFHIR reconciliation:
No source change was made. CodeSystem is active in source/fhir.ini, and the active CodeSystem element definition now says CodeSystem.filter.code identifies the filter when used as a filter in ValueSet.compose.include.filter. The related active ValueSet definitions also say include.filter may be based on filters defined by the system, filter.property identifies a property or filter, and filter.op must match CodeSystem.filter.operator when the property is a filter. The remaining stale SVG title was intentionally not hand-edited because this workflow avoids diagram-only source changes when the authoritative source already conveys the correct semantics.

Recommendation:
Keep this empty audit commit as-is. No FHIR core source follow-up is needed for FHIR-13288; if generated diagrams are refreshed in a future build, the stale SVG tooltip can be regenerated from the authoritative XML rather than manually patched.
