FHIR-22500: Complete safety checklist CodeSystem

Issue request:
FHIR-22500 is Published/Persuasive for FHIR-core-safety and asked for a formal computable representation of the safety checklist so implementations have a URL and formal form for checklist items. The Jira resolution approved the change as pre-applied for R5.

Initial application:
The pre-applied implementation was commit 76ce9865e683576c6712b6d0c6860272de60ad13, "GF#22500 - add code system for the safety check list", which added source/codesystem/codesystem-safety-entries.xml, registered it in source/fhir.ini, and linked it from source/safety.html. The current build still has an active [codesystems] entry for safety-entries and the safety page still advertises the CodeSystem for formal references.

Additional context:
A later Published Jira, FHIR-17426, added the SUBSETTED safety checklist item to source/safety.html, but that checklist item was not mirrored into the active CodeSystem and its page anchor still reused obs-focus. A consistency check showed the CodeSystem had no subsetted concept. FHIR-56983 separately asks whether the existing check=validation code should be changed to check-validation, but that Jira is Submitted/Unresolved, so this commit intentionally does not alter that canonical code.

AutoFHIR reconciliation:
Added the missing subsetted concept to source/codesystem/codesystem-safety-entries.xml and changed the matching checklist anchor in source/safety.html from obs-focus to subsetted. Both files are in current build scope: source/fhir.ini actively registers the CodeSystem, and source/safety.html is the current safety page that links to codesystem-safety-entries.html.

Recommendation:
Keep this source fix. It restores the computable CodeSystem coverage promised by FHIR-22500 for the current checklist while avoiding the unresolved canonical-code question in FHIR-56983. FHIR-17426 can still be audited separately for its broader SUBSETTED update surfaces if needed.
