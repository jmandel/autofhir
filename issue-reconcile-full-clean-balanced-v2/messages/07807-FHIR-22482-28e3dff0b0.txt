FHIR-22482: Audit cross-version extension package support

Issue request:
FHIR-22482 was Published/Persuasive for FHIR-core after being raised by an STU3 implementer who wanted to pre-adopt R4 extensions, such as ordinalValue, without copying them under local canonicals. The final resolution was to extend cross-version packages so extension definitions could be used for validation across FHIR versions, emit a validator hint for early-version adoption, and document the mechanism in the R5 core specification.

Initial application:
No source commit explicitly mentioning FHIR-22482 was found. The R5-era application appears to have happened through the broader cross-version extension work: v5.0.0 source/versions.html documented the cross-version extension URL pattern and included a formal package matrix for R2/R3/R4/R5 extension packages, while FHIR-28479 and FHIR-31721 refined the same section and package guidance. FHIR-31721 also records the related validator behavior for treating unknown HL7 extensions from other versions more leniently.

Additional context:
The current source is the R6 build and source/hierarchy.xml keeps both source/versions.html and source/defining-extensions.html in build scope. Core source now intentionally points to cross-version definition packages instead of carrying the full package matrix, after the R6 cleanup that moved detailed cross-version content to guides. HL7 extension definitions themselves were moved out of core by dd468d4f17 into the FHIR Extension Pack; that repository now documents use with all supported FHIR versions, older-version packages hl7.fhir.uv.extensions.r4 and hl7.fhir.uv.extensions.r3, and transformed R4/R3-valid extension definitions. Later FHIR-44519 in the FHIR-extensions project specifically formalized home-page guidance for adopting Extension Pack artifacts in prior FHIR versions.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current core source still preserves the cross-version package mechanism and links extension references through the Extension Pack, while the detailed older-version extension-package documentation and package contents now belong to the FHIR Extension Pack rather than this core checkout.

Recommendation:
Keep this audit commit as-is. Do not reintroduce the old R5 package matrix into core; if implementers still need clearer package names or validator behavior, handle that in the FHIR Extension Pack or validator documentation/tooling rather than as a core source correction for FHIR-22482.
