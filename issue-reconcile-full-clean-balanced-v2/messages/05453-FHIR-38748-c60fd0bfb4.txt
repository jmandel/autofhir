FHIR-38748: Audit TestScript URL support outside core

Issue request:
FHIR-38748 was Published/Persuasive for R5. It asked to add URL support for TestScript origins and destinations; the accepted first-comment disposition added TestScript.origin.url and TestScript.destination.url and explicitly did not add separate URL-typed operation.origin/operation.destination elements because the existing operation references could point at the defined origin/destination entries.

Initial application:
The issue was applied in core by git commit 8297a4b1066627244b16be453b8aaa211e4f5c5b, which added TestScript.origin.url and TestScript.destination.url to source/testscript/structuredefinition-TestScript.xml and added an example destination URL in testscript-example-multisystem.xml.

Additional context:
Later applied issue FHIR-46100 refactored TestScript.origin and TestScript.destination into TestScript.testSystem. The last core TestScript definition before removal retained the URL capability as TestScript.testSystem.url, with operation.origin and operation.destination still referring to test-system indices. Commit f9a44787c45071394532c7c2ee94d76f30f47387 then removed the TestScript/TestPlan/TestReport source trees and active fhir.ini entries from core and added the external testing IG link under [additional-ig-list]. Current core source has no active TestScript resource source to edit.

AutoFHIR reconciliation:
This is an empty external-repo audit commit. No core source was changed because FHIR-38748 was historically applied, then superseded by the TestScript.testSystem model, and TestScript is now outside the current core build.

Recommendation:
Keep this audit commit as-is for the core reconciliation. If URL semantics for current TestScript need additional changes, they should be made in the external FHIR testing IG/source that now owns the testing resources rather than by reintroducing TestScript source into core.
