FHIR-23043: Audit package example directory guidance

Issue request:
FHIR-23043 was Published/Persuasive for R5. It asked to document the FHIR NPM package format so IG Publisher packages would put ImplementationGuide-marked examples in an "example" directory that was a sibling of the "package" directory, with the Jira resolution explicitly noting this applied to IGs and not the core spec.

Initial application:
No Jira-tagged FHIR-23043 source commit was found in the FHIR checkout. The linked Zulip thread shows the request grew out of a July-August 2019 package-format discussion, and a later Jira comment records that the item was deferred because it was for Confluence/package documentation rather than a direct spec source change. The active source/packages.html page was added later by an untagged package documentation commit.

Additional context:
A later Published/Persuasive package-spec issue, FHIR-27832, directly revisited the same example-folder guidance and states that the sibling-to-package-folder practice was abandoned to comply with NPM, requiring additional folders to live under the package folder. The combined branch already contains the FHIR-27832 reconciliation commit, and current source/packages.html says IG example resources are in /package/example. source/hierarchy.xml includes packages.html in the current build hierarchy.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change. Reintroducing the FHIR-23043 sibling-directory wording would conflict with the later FHIR-27832 decision and with the current build-scoped package page, so the current source should remain as-is.

Recommendation:
Keep this no-change audit. If there is still an IG Publisher behavior problem, it should be handled in the IG Publisher or package tooling workflow; the FHIR core package-spec source should continue to follow the later /package/example guidance.
