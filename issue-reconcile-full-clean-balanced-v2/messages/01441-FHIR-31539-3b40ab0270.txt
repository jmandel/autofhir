FHIR-31539: Align Procedure used ModelInfo

Issue request:
FHIR-31539 was Published/Persuasive with Modification for Procedure. It asked to change the R4 Procedure.usedReference Reference(Device | Medication | Substance) pattern into a choice allowing a coded concept or a reference, and the final resolution recorded that R5 had already accomplished this through CodeableReference.

Initial application:
The primary Procedure source was pre-applied before the Jira vote: R4B-era source had separate Procedure.usedReference and Procedure.usedCode elements, and commit 33b409a4b6d544598262f2f074ebb4b6dc466157 reworked Procedure to a single Procedure.used CodeableReference with Device, Medication, Substance, and BiologicallyDerivedProduct targets. Jira comments likewise noted that the R5 CI build already had Procedure.used as CodeableReference. That application did not update the active FHIR ModelInfo Library example, which still exposed Procedure.usedReference and Procedure.usedCode as separate model elements.

Additional context:
Procedure is active in source/fhir.ini, and Library is also active. The Library examples page links source/library/library-fhir-model-definition-content.xml as the FHIR model information file used by the CQL-to-ELM translator; its root declares FHIR modelInfo version 6.0.0. The fhir.ini entries that still mention Procedure.usedCode and Procedure.usedReference are version-migration mappings, not current conformance definitions. FHIR-34525 later corrected only the Procedure.used comment wording, and FHIR-33389 considered additional procedure/device parameters but resolved on Observation rather than changing Procedure.used.

AutoFHIR reconciliation:
Updated source/library/library-fhir-model-definition-content.xml so Procedure exposes one used element whose list items can be CodeableConcept or Reference, matching the CodeableReference representation used by nearby Procedure ModelInfo fields. No Procedure StructureDefinition change was needed because source/procedure/structuredefinition-Procedure.xml already carries the correct Procedure.used CodeableReference.

Recommendation:
Keep this commit as-is. It completes the applied FHIR-31539 change for the current build's ModelInfo example while preserving the existing StructureDefinition and migration mappings.
