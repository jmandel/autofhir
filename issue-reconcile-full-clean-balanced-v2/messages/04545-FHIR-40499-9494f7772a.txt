FHIR-40499: Audit workflow instantiates removal

Issue request:
FHIR-40499 was an Applied FHIR-core OO change request for R6 with a Not Persuasive with Modification resolution. The request asked OO to align DeviceUse/DeviceRequest, NutritionRequest/NutritionOrder, Observation, ServiceRequest, and Task with the workflow pattern by removing overloaded instantiates[x], instantiatesCanonical, and instantiatesUri usage where the more precise workflow instantiation extensions could carry the intended relationship.

Initial application:
The issue was first applied in the FHIR-40499 branch by commit 2c818f77, which started replacing the old target elements in DeviceRequest, ServiceRequest, Observation, and Task, followed by e18914a0 removing an Observation instantiates search parameter. Jira later records the build application as merge commit 28f7792. The final current-source state also reflects tightly related workflow follow-up commits: ba7bffc2 removed Task.instantiatesCanonical and Task.instantiatesUri for FHIR-20494, 24b68f1e removed DeviceRequest.instantiatesCanonical and DeviceRequest.instantiatesUri for FHIR-43444, 696cf9c6 removed ServiceRequest.instantiatesCanonical and ServiceRequest.instantiatesUri for FHIR-43441, 420cc15c removed NutritionOrder.instantiates, and 5003b4ef plus a96b49f removed Observation.instantiates[x] and its search parameters for FHIR-43456.

Additional context:
OO minutes show the work group considered the specific workflow extensions and rejected an instantiatesType modifier-extension approach. The Extension Pack now contains workflow-generatedFrom, workflow-compliesWith, workflow-shallComplyWith, workflow-adheresTo, and workflow-triggeredBy contexts covering the relevant current resources. FHIR-43456, the Observation workflow-alignment follow-up, is already represented on the combined branch by cbedd54f4f188091be23b91500a561c43c895e18 and should not be duplicated here. The checked-in DeviceRequest, ServiceRequest, and Observation SVG diagrams still mention removed instantiates elements, but those are generated-looking diagram artifacts rather than the authoritative conformance source.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active resource definitions listed in source/fhir.ini no longer define instantiates elements in source/devicerequest, source/nutritionorder, source/observation, source/servicerequest, or source/task, and the resource introductions/workflow notes direct implementers to the workflow instantiation extensions. The only remaining apparent inconsistency is in stale SVG diagrams, which should not be hand-edited as the sole reconciliation change.

Recommendation:
Keep this no-change audit commit as-is. If the stale SVG diagrams appear in a built publication, regenerate them through the normal publisher/build process; no additional authoritative FHIR core source change is recommended for FHIR-40499.
