FHIR-13144: Audit gateway device extension migration

Issue request:
FHIR-13144 was a Published, Persuasive with Modification OO change request raised against DSTU2 Observation. It asked for a core extension to identify the gateway/mobile application involved in personal health device/generated data when Observation.device identified the measuring device, with the final resolution to add a gateway extension and note that Provenance/AuditEvent can represent the same information.

Initial application:
The issue was applied in core by commit 3e18984e30ed835567e78db17f64f14710e46e74, whose message included GF#13144 and added a gateway-device row to source/observation/observation-extensions-spreadsheet.xml for Observation, cardinality 0..1, value Reference(Device), and the Provenance/AuditEvent note. A later generated StructureDefinition existed at source/observation/structuredefinition-extension-observation-gatewayDevice.xml.

Additional context:
Core commit dd468d4f1799dd79819315b211588ef1cf4586e0 removed extension definitions from the R5 core source, including observation-gatewayDevice. Current core source still has active Observation and Device resources, but the Device.gateway source block is commented out as removed and source/fhir.ini records Device.gateway among removed/mapped elements; the only in-core observation-gatewayDevice reference is the retained OID/history material. The FHIR Extension Pack now owns the extension definitions: observation-gatewayDevice remains present for older versions, and later FHIR-47326/FHIR-47606 decisions added device-gateway for Device and Observation and deprecated the old Observation-only gateway extension.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The requested semantic capability is no longer represented by an editable core extension definition in this checkout; it belongs to the Extension Pack, where the current artifacts already preserve the original Observation gateway use case and reflect the later R6 replacement/deprecation decisions.

Recommendation:
Keep this external-repo audit commit as-is for the core reconciliation. No core follow-up is needed for FHIR-13144 unless the work group wants to reopen the later Extension Pack decisions; any future wording or conformance changes to these gateway extensions should be made in HL7/fhir-extensions rather than by restoring a core extension definition.
