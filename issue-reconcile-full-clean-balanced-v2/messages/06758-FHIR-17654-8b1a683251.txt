Issue request:
FHIR-17654 is a Published/Persuasive STU3 change request for FHIR-core Task. It asked that Task.instantiatesReference be aligned with the Event workflow pattern because instantiates points at definitional resources and should use canonical URLs; Jira records the resolution as "Align Task with the Event pattern (preapplied)."

Initial application:
The request was preapplied in git commit 2cb95870680036085fcfc5f9c62ce294e9e3d034, which changed the Task spreadsheet from Task.instantiates[x] using uri | Reference(ActivityDefinition) to Task.instantiatesCanonical using canonical(ActivityDefinition), and added Task.instantiatesUri for non-FHIR definitions. Current generated/source Task StructureDefinition no longer contains Task.instantiatesReference, so the original reference-to-canonical correction was not missed.

Additional context:
Task is an active current-build resource in source/fhir.ini. A later final OO decision, FHIR-20494 Applied/Persuasive with Modification for R6, removed Task.instantiatesCanonical and Task.instantiatesURI from the Task resource and told implementers to use workflow-triggeredBy, workflow-generatedFrom, workflow-compliesWith, and workflow-shallComplyWith instead; FHIR-19690 was resolved as a duplicate of that same later decision. The OO 2025-06-03 minutes record the 4-0-1 disposition, the current Task introduction has the replacement-extension note, and the named workflow extensions exist in the FHIR Extension Pack source. FHIR-20494 is already represented on the combined branch, so this seed should not republish that later issue.
