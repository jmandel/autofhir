FHIR-12356: Audit Claim/EOB supporting payload application

Issue request:
FHIR-12356 was a Published/Persuasive with Modification FM change request for DSTU2. It asked for a payload/supporting-information capability on Claim.information and ExplanationOfBenefit.information, including direct string, Attachment, or Reference payload content and item-level links to the supporting information. The final resolution chose to add Attachment|Reference(Any) to information.value[x] and add information.reason 0..1 Coding with example codes in Claim and EOB.

Initial application:
The historical application commit aaa1e5693e explicitly listed tracker 12356 and changed the then-current Claim and ExplanationOfBenefit spreadsheet source. It expanded Claim.information.value[x] and ExplanationOfBenefit.information.value[x] from string|Quantity to string|Quantity|Attachment|Reference(Any), and also added the adjacent information.reason elements that were later audited separately for FHIR-12357.

Additional context:
Claim and ExplanationOfBenefit are active resources in source/fhir.ini. Later FHIR-19460 renamed Claim.information and ExplanationOfBenefit.information to supportingInfo, with fhir.ini retaining version maps from the old information names and item informationLinkId fields. Current Claim and ExplanationOfBenefit source defines supportingInfo.value[x] and item.informationSequence links. Later Applied issue FHIR-51518 intentionally broadened supportingInfo.value[x] to the open type code *, which includes Attachment and Reference and supersedes the older short datatype list. FHIR-37513 later resolved no-change on the Claim-family sequence-link pattern, supporting the current informationSequence naming rather than a new source edit.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active StructureDefinition source already preserves the FHIR-12356 payload capability: Claim.supportingInfo.value[x] and ExplanationOfBenefit.supportingInfo.value[x] allow any FHIR datatype, and the item-level positiveInt informationSequence links remain present for associating supporting information with service lines.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-12356 unless FM opens a new issue to narrow the open supportingInfo.value[x] datatype set or rename the retained Claim-family sequence-link fields.
