FHIR-26536: Audit removed MedicationKnowledge packaging model

Issue request:
FHIR-26536 was a Published/Persuasive with Modification Pharmacy change request for R5. It asked to make MedicationKnowledge packaging repeatable, add an identifier for a specific package, attach cost to packaging, and ensure search supported the packaging cost location because most medication knowledge is independent of package-specific pricing.

Initial application:
The issue was applied before this reconciliation in the historical MedicationKnowledge spreadsheet. Commits 603de50396973db754fec17786a66ce29799296c, 4c6129a0e67b7027a47f19a293115e88a13260b2, ba1bb07d3079ab138631a116aa2eef72ce9cc2e5, and 7e738e80a6cb09fa4df847329cbb192e5e04bd64 are tagged FHIR-26536 and introduced repeatable MedicationKnowledge.packaging, an inline packaging identifier, packaging.cost as a content reference to the cost backbone, and packaging-cost search parameters. Later FHIR-31365 work made packaging.identifier and packaging.cost repeatable.

Additional context:
MedicationKnowledge was substantially refactored after the R5 application. Commit 6422f2f98a0fcf03140c15fe93bfd6c765fc6377 removed the inline packaging.identifier and other detailed package fields, retained repeatable MedicationKnowledge.packaging.cost, and replaced package details with MedicationKnowledge.packaging.packagedProduct, a reference to PackagedProductDefinition. In the current build, MedicationKnowledge itself is no longer active: commit 5a4307d78b0209f61bbc68d582c1e190b3aaee5c removed it from source/fhir.ini's active resource and generated-resource metadata, source/hierarchy.xml and the Medications module omit it, and current build URLs for medicationknowledge.html and medicationknowledge.profile.json return 404. FHIR-50845 records the later Pharmacy decision to remove MedicationKnowledge and move its elements to FormularyItem or other resources; FHIR-51149 then expanded FormularyItem with formulary-based MedicationKnowledge elements.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The seed was historically applied for R5, then superseded by later MedicationKnowledge model refactoring and finally by removal of MedicationKnowledge from the active current core build. Editing the residual source/medicationknowledge files to restore old inline packaging fields or adjust inactive search parameters would not correct a current built artifact.

Recommendation:
Keep this audit commit as-is for the current core build. If MedicationKnowledge is restored to core or maintained in another specification, review the old FHIR-26536 intent alongside FHIR-31365, FHIR-50845, and FHIR-51149 so package-specific cost and package identifiers are carried by the active model, whether through FormularyItem, PackagedProductDefinition, or a revived MedicationKnowledge surface.
