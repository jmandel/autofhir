FHIR-17351: Audit QuestionnaireResponse hierarchy rule

Issue request:
FHIR-17351 was a Published/Persuasive STU3 change request asking whether QuestionnaireResponse answers could be supplied as a flat list inferred from the Questionnaire, or whether the QuestionnaireResponse hierarchy must mirror the Questionnaire hierarchy. The accepted decision was to state that nesting must be preserved.

Initial application:
The Jira comment points to SVN #14772. Git-svn commit b8c5990ac5ad735ba1e8e836fd8a4c6fd3534a3e, with subject listing tracker 17351 and git-svn build@14772, added the QuestionnaireResponse Notes sentence saying the hierarchy must mirror the corresponding Questionnaire. Later typo and wording changes corrected that sentence without changing its meaning.

Additional context:
QuestionnaireResponse is active in source/fhir.ini, so the source/questionnaireresponse files are in the current build. Current notes and StructureDefinition prose both state that a resolvable QuestionnaireResponse must be organized consistently with the Questionnaire, while later QuestionnaireResponse work clarifies legacy or stand-alone cases where no resolvable Questionnaire exists. Related typo issue FHIR-19868 is already represented on the combined branch by commit 01347d2ebac23d660d726cd6b134668a55abc078, so this commit does not duplicate that audit.

AutoFHIR reconciliation:
No source change was made. The current build-scope source already conveys the accepted rule: the QuestionnaireResponse hierarchy SHALL mirror the corresponding Questionnaire when there is one, and the questionnaire element/comment and notes explain the resolvable-Questionnaire boundary.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-17351 unless the work group later chooses to relax the hierarchy requirement itself.
