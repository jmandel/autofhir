FHIR-5955: Audit retired QICore extension profile reference fix

Issue request:
FHIR-5955 was Published/Persuasive for DSTU1 and asked that profile URL references in an extension worksheet Type such as Reference(Resource){profileUrl} be preserved in the generated extension definition. The concrete failure was Other.AdverseEvent.cause.item in the QICore AdverseEvent profile, where Extension.value[x] was generated with base resource profiles instead of the specified QICore profile URLs.

Initial application:
Jira records the application as svn revision 5094. In the migrated git history, commit 68b14f5700d4e510e21e777c41355e1eda34135b (#5955 - fix missing profile references) updated ProfileGenerator so a TypeRef with an explicit profile wrote that profile instead of always writing the base resource StructureDefinition URL. The related parser-enablement issue FHIR-5938 had already been applied in commit 81d1bff591ce339694764d726741b17b6770fe00.

Additional context:
The affected source was historical QICore content, not a current core profile. source/other/adverseevent-qicore-profile-spreadsheet.xml was renamed to source/basic/basic-adverseevent-qicore-profile-spreadsheet.xml when Other became Basic, and later moved out of core source under guides/cqf before disappearing from the current checkout. Current source/fhir.ini still lists Basic and AdverseEvent as active resources, but the active [profiles] list has only current core extension/profile spreadsheets and no QICore AdverseEvent package. Searches of the current core checkout and the FHIR Extension Pack found no current extension-adverseevent-qicore-cause-item or matching QICore AdverseEvent source. The old Java publisher classes changed by the application commit are also no longer present in this checkout.
