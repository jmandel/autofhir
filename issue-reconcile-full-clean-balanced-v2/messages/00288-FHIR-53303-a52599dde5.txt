FHIR-53303: Audit NutritionIntake statusReason updates

Issue request:
FHIR-53303 was Applied with Persuasive with Modification resolution for R6. It asked to update the NutritionIntake.statusReason terminology by replacing inactive SNOMED CT Patient Died 397709008 with Dead 419099009, removing Entered in Error as a status reason, replacing numeric local codes with mnemonic codes, presenting the value set as the Nutrition Intake Status Reason example binding, and moving the code system definition to THO.

Initial application:
The Jira comment points to pre-applied git commit 5ece12a37676b19b08e8f615eb965d3357f19812, merged by a69aa7d467. That commit changed the active NutritionIntake source files by updating the local code system concepts, replacing the SNOMED concept in the value set, setting active status, and adding a ballot note that the code system was still in FHIR but expected to move to THO.

Additional context:
NutritionIntake is an active resource in source/fhir.ini, so the checked source/nutritionintake files are in current build scope. The current source still has the FHIR-local CodeSystem and ValueSet, but a later Applied issue, FHIR-55266, deliberately changed both to experimental=true while the THO move remained a candidate/transition item. UP-752 has implemented the THO CodeSystem externally, and FHIR-53478 is a later Resolved - change required tracker that specifically asks to finalize the core redirects for the NutritionIntake and DeviceAssociation code systems. That pending tracker is the right scope for the remaining core redirect/canonical cleanup, not this seed audit.

AutoFHIR reconciliation:

The later experimental flags are also intentional under FHIR-55266, so changing them back to the seed's original active/non-experimental wording would be wrong.
