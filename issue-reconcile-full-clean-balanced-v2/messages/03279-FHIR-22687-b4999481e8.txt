FHIR-22687: Align scheduling service ModelInfo

Issue request:
FHIR-22687 was Published/Persuasive with Modification for R5 by Patient Administration. It requested that Appointment.serviceType, Slot.serviceType, Encounter.serviceType, and Schedule.serviceType become CodeableReference(HealthcareService), that HealthcareService.type remain CodeableConcept, that HealthcareService.offeredIn 0..* Reference(HealthcareService) be added, and that the administration and HealthcareService narrative explain schedulable services and catalogs.

Initial application:
The primary resource source was applied in 2022. Commit fb45d82237 changed Appointment, Slot, Encounter, and Schedule serviceType StructureDefinitions and service-type search parameters to support CodeableReference/HealthcareService. Commits dcd958adcb, 287cd1d15b, and 1bec67b865 added HealthcareService.offeredIn, the HealthcareService/catalog narrative and administration text, and the HealthcareService offered-in search parameter. The current combined branch already has the related FHIR-50073 fix that corrected the offeredIn definition's stale availableIn typo.

Additional context:
The current authoritative StructureDefinitions and search parameters already match the Jira resolution, and HealthcareService.type remains CodeableConcept. However, Library is an active current-build resource in source/fhir.ini, publish.ini copies source/library/library-fhir-model-definition-content.xml into the published build, and source/library/library-fhir-model-definition.xml embeds that same ModelInfo content. That checked-in ModelInfo surface still exposed the four serviceType elements as FHIR.CodeableConcept and omitted HealthcareService.offeredIn, which would mislead CQL/model-definition users even though the resource definitions were correct. Zulip and Confluence evidence confirms the issue's scheduling-service rationale and did not reveal a later reversal.

AutoFHIR reconciliation:
Updated the FHIR Model Definition content so Schedule.serviceType, Appointment.serviceType, Encounter.serviceType, and Slot.serviceType are list-valued FHIR.CodeableReference elements, added the FHIR.CodeableReference datatype with concept and reference members, and added HealthcareService.offeredIn as a list of FHIR.Reference. Regenerated the embedded base64 attachment in source/library/library-fhir-model-definition.xml from the edited content XML so the Library example and its linked content stay synchronized.

Recommendation:
Keep this commit as-is. It fixes the only remaining current-build source surface found for FHIR-22687 while preserving the already-applied StructureDefinition, search parameter, and narrative changes; no separate FHIR-50073 commit is needed because that related issue is already represented on the combined branch.
