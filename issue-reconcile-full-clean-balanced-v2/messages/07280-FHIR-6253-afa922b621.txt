FHIR-6253: Audit BodyStructure handling

Issue request:
FHIR-6253 was Published with a Persuasive with Modification resolution for the DSTU1 request to make body site a datatype and use it consistently, including imaging and medication administration. The final decision kept BodySite as a resource for use cases that need an independently tracked site and directed ordinary body-site usage to remain a simple coded element, with references to the BodySite resource handled through a standard extension when needed.

Initial application:
The historical source application is visible in three #6253 commits from August 2015: 6cc9083b updated MedicationOrder dosageInstruction.site, c765f2b updated MedicationAdministration.dosage.site, and f23d7a updated MedicationDispense dosageInstruction.site and examples so pharmacy site fields could carry a coded site or a BodySite reference. Jira FHIR-7647 recorded the pharmacy-specific companion decision to use a codeable concept or resource reference consistently across pharmacy resources.

Additional context:
BodySite was later renamed to BodyStructure by FHIR-13396, and the current build configuration actively builds bodystructure=BodyStructure while listing BodySite as a removed resource. Later OO work, especially FHIR-53203, moved several active resources toward bodyStructure CodeableReference(BodyStructure) elements where both code and reference are appropriate. The standard bodySite extension now lives in the FHIR Extension Pack and still targets BodyStructure, covering the extension-based reference pattern from the 2015 resolution.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped source already preserves the final WG intent: BodyStructure remains an active resource for persistent or detailed anatomical structures, simple body-site fields remain coded where appropriate, medication dosage uses CodeableReference(BodyStructure) or the standard bodySite extension path, and current OO bodyStructure harmonization has already been applied or separately audited.

Recommendation:
Keep this audit commit as-is. Do not make BodyStructure a datatype or add broad consistency edits under FHIR-6253; future bodySite/bodyStructure harmonization should continue through current-version OO trackers such as FHIR-53203/FHIR-54843 rather than reopening this DSTU1 disposition.
