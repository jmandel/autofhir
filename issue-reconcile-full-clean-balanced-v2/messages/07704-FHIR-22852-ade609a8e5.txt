FHIR-22852: Audit Basic.created dateTime correction

Issue request:
FHIR-22852 was a Published/Persuasive FHIR-core Basic change request asking that Basic.created be corrected from date to dateTime so the element can support ordering resource instances by time.

Initial application:
The issue was previously applied for R5. Jira records the fix as merge commit 645c1c64fe86f0d2b05995614505201c497934f6, and the implementation commit 07488999193be8c166d587073cf855234c11fa43 changed source/basic/structuredefinition-Basic.xml from <code value="date"/> to <code value="dateTime"/> for Basic.created.

Additional context:
Basic is an active resource in source/fhir.ini, so source/basic/structuredefinition-Basic.xml is in current build scope. The current source still defines Basic.created as dateTime. The Basic-created SearchParameter remains type date, which is the FHIR search type for date/dateTime elements and does not contradict the element datatype. FHIR Infrastructure minutes from 2019-08-05 record the work group agreement and 4-0-0 vote to change Basic.created to dateTime. A 2018 Zulip implementer thread raised the same datatype concern before the Jira issue; no conflicting community evidence was found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative current source already contains the requested dateTime datatype, and adding another source-changing commit would duplicate the historical application rather than correct the current specification.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-22852 unless a later work-group issue changes Basic.created again.
