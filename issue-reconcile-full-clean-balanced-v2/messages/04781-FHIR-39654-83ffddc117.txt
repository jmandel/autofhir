FHIR-39654: Audit Observation markdown reconciliation

Issue request:
FHIR-39654 was a Published/Persuasive OO change request for R5 asking to change DiagnosticReport.conclusion to markdown, change Observation.referenceRange.text to markdown if normative rules allowed it, and add markdown as a choice type for Observation.value[x] and Observation.component.value[x].

Initial application:
The implementation history shows the R5 work was initially applied: commit 9c366e6106 changed DiagnosticReport.conclusion, Observation.referenceRange.text, Observation.value[x], and Observation.component.value[x] from string to markdown, and commit 8aaaf4a45c updated related examples/search material on the FHIR-39654 branch. DiagnosticReport.conclusion was also covered by the related Published FHIR-39570 issue.

Additional context:
The Observation.value[x] and Observation.component.value[x] markdown choices were later revisited before R5 publication. FHIR-40560 was Published/Persuasive with Modification and explicitly directed the spec to restore valueString, remove valueMarkdown, remove canonical(), and apply the same value/component changes to both Observation.value[x] and Observation.component.value[x]. The OO Zulip discussion and 2023-03-06 OO minutes record the rationale: changing a normative choice element from valueString to valueMarkdown was not painless and removed an existing wire-format property name. Later FHIR-41002 and FHIR-45339 cleaned up invalid Observation search parameters that had been left behind after the FHIR-40560 reversal.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped source already has DiagnosticReport.conclusion as markdown and Observation.referenceRange.text as markdown, while Observation.value[x] and Observation.component.value[x] now use string rather than markdown in accordance with the later FHIR-40560 decision. Re-adding valueMarkdown for FHIR-39654 would conflict with that later Published decision.

Recommendation:
Keep this audit commit as-is. Any future desire to allow markdown in Observation.value[x] or Observation.component.value[x] should be raised as a new OO/FHIR-I-reviewed change because it would reverse the later FHIR-40560 normative compatibility decision.
