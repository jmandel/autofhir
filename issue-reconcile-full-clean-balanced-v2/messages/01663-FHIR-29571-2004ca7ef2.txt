FHIR-29571: Audit Medication batch utilization extension

Issue request:
FHIR-29571 was a Published Pharmacy change request, resolved Persuasive with Modification for R5, asking to add a Medication.batch batch utilization attribute. The requested attribute was a CodeableConcept categorization of the batch's usage, with examples such as commercial and development, and the approved resolution was to create a core extension rather than add a base Medication element.

Initial application:
No source commit was found whose message explicitly names FHIR-29571. Git history shows the request was nevertheless applied in the Medication manufacturing-batch extension family: commit 52f3ef3d50 added manufacturingBatch.batchUtilization to source/medication/medication-extensions-spreadsheet.xml, commit 33b409a4b6 generated source/medication/structuredefinition-extension-medication-manufacturingBatch.xml with batchUtilization as a CodeableConcept extension slice, and commit dd468d4f17 later removed the core extension source when R5 extensions were moved out of this repository.

Additional context:
Medication remains an active core resource, but the current core source maps the historical Medication.batch path to Medication.instance and no longer owns the medication-manufacturingBatch StructureDefinition except for its OID registry entry. The same extension now lives in the FHIR Extension Pack, whose input/definitions/multiple/StructureDefinition-medication-manufacturingBatch.xml applies to Medication.batch and defines Extension.extension:batchUtilization with the requested definition and CodeableConcept value. Pharmacy minutes for 2020-11-09 record the PQ/CMC manufacturing discussion and a 9-0-0 carried block vote, including FHIR-29571, to add a core extension. Zulip and Confluence keyword searches found no later conflicting discussion for this seed.

Keep this audit commit as an external-repo decision. No core FHIR source change is recommended; any future content correction to medication-manufacturingBatch should be made in HL7/fhir-extensions rather than reintroducing the extension source into core.
