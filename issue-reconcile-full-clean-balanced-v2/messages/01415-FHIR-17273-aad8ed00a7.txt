FHIR-17273: Align evaluatedResource references

Issue request:
FHIR-17273 was a Published/Persuasive CQI change request for STU3 MeasureReport. It requested changing MeasureReport.evaluatedResources from a single Reference(Bundle) to evaluatedResource 0..* Reference(Any), so MeasureReport can directly reference each resource used in measure calculation and can be exchanged with those resources in a Bundle when needed.

Initial application:
The issue was explicitly applied in e169985949ad77cfed6c6e86ee8036a90f98136e, the git-svn import of SVN 14046, whose commit message says GF#17273 changed MeasureReport.evaluatedResources to MeasureReport.evaluatedResource 0..* Reference(Any). That commit renamed the element, changed its type from Reference(Bundle) to Reference(Any), and updated the CMS146 example from a Bundle reference to a direct resource reference.

Additional context:
Measure and MeasureReport are active CQI resources in source/fhir.ini, and clinicalreasoning-quality-reporting.html is in the current source hierarchy as the Quality Reporting topic. The current authoritative MeasureReport StructureDefinition already defines MeasureReport.evaluatedResource as 0..* Reference(Resource), and later FHIR-34033 reconciliation on the combined branch refined the element definition for individual and data-exchange report scopes. However, several active Measure/quality-reporting source locations still used the obsolete plural element name or referred to an evaluatedResources bundle, which conflicted with FHIR-17273's direct-reference decision.

AutoFHIR reconciliation:
This commit updates only active source text that still pointed at the obsolete evaluatedResources/Bundle model. The Quality Reporting page now says Bundles contain data of interest referenced by MeasureReport.evaluatedResource, duplicate-data guidance uses the singular element name, and the examples paragraph points to evaluatedResource. The $data-requirements OperationDefinition footer/comment and Measure.group.population.criteria comment now also use MeasureReport.evaluatedResource and direct Observation references rather than an evaluatedResources bundle.

Recommendation:
Keep this source change. It completes the old FHIR-17273 rename/type decision in current active prose and OperationDefinition/resource comments without changing the already-correct MeasureReport cardinality or target type. FHIR-17585 and FHIR-34033 are related context and already represented on the combined branch; no additional issue commit is needed for them here.
