FHIR-24624: Audit Measure population basis application

Issue request:
FHIR-24624 was a Published FHIR-core Measure change request resolved Persuasive. It asked to add an explicit populationBasis element to Measure, typed against all FHIR types, so measure authors did not have to infer the counted population type from population criteria expression result types.

Initial application:
The issue was applied by commit df7089e33e47459fdadb4a0c8ef51721b3b7a6b7, which added root Measure.basis as a code element with a required all-types binding, meaningWhenMissing of boolean, and definition text explaining subject-based and non-subject-based population basis. Commit cb1a35e127db8b8ff8abfccfe2b7216a4a64b2ac then added the parallel Measure.group.basis override surface.

Additional context:
FHIR-32079 and FHIR-32194 later considered whether the all-types binding was too broad and decided not to narrow it, instead documenting that abstract FHIR types can be valid and authoring environments may apply content-specific restrictions. FHIR-32069 later changed this binding surface from the old all-types value set to the current fhir-types value set. FHIR-49922 and FHIR-50664 then simplified Measure calculation semantics by deprecating and removing root calculation elements, leaving group-level calculation definition as the current source of truth. FHIR-50500 added Measure.group.basisRequirement for more flexible mixed-type counting while preserving Measure.group.basis.

AutoFHIR reconciliation:
This audit commit makes no source change. In the current build-scope source, source/fhir.ini lists Measure as an active resource, root Measure.basis is intentionally absent after the R6 simplification work, and Measure.group.basis remains present with the population-basis definition, code type, meaningWhenMissing boolean, required ValueSet/fhir-types binding, and FHIR-32194 abstract-type clarification.

Recommendation:
Keep this audit commit as-is. Do not re-add a root populationBasis or Measure.basis element for FHIR-24624; current Measure population basis is intentionally represented at Measure.group.basis, with basisRequirement available for more specific constraints when needed.
