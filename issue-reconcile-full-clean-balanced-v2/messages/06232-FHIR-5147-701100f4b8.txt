FHIR-5147: Audit Goal priority and source

Issue request:
FHIR-5147 was a Published/Persuasive Patient Care ballot comment asking whether goals should carry both priority and an indication of whose goal it is, such as patient or clinician. The recorded resolution accepted priority as a CodeableConcept using high/medium/low style codes and added a source/owner indication for goals.

Initial application:
No commit explicitly names FHIR-5147. The relevant March 2015 Patient Care change commit db4ace37c6 added Goal.priority, a GoalPriority value set, and a Goal.author element whose definition captured whose goal it was. That initial implementation has since been refactored through normal Goal evolution.

Additional context:
Later final Goal issues refined the seed's concepts without reversing them: FHIR-7087 clarified Goal.priority as the mutually agreed priority and introduced participant-specific priority/acceptance; FHIR-28221 renamed Goal.expressedBy to Goal.source and added CareTeam support; FHIR-41409 and FHIR-48366 refined source/recorder and Group support; FHIR-53104 and FHIR-56542 moved priority bindings to the THO Goal Priority value set. CarePlan and Goal are active resources in source/fhir.ini, so source/goal/structuredefinition-Goal.xml is the authoritative current build input.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current Goal.priority is a CodeableConcept with preferred binding to http://terminology.hl7.org/ValueSet/goal-priority, current Goal.source indicates whose goal it is and can reference Patient, Practitioner, PractitionerRole, RelatedPerson, CareTeam, and Group, and Goal.acceptance.priority carries participant-specific priority when patient/clinician/stakeholder priorities differ.

Recommendation:
Keep this audit commit as-is. The current source satisfies FHIR-5147 after later approved refinements, and adding redundant CarePlan prose or reverting the later Goal.source/THO-binding evolution would make the current specification less accurate.
