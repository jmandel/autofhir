FHIR-13926: Audit PlanDefinition condition semantics

Issue request:
FHIR-13926 was Published with a Persuasive with Modification resolution for STU3. It asked how to interpret multiple PlanDefinition.action.condition entries, especially contradictory applicability conditions, and resolved that multiple conditions of the same kind are combined using AND semantics, with the same clarification applying to RequestGroup.

Initial application:
The issue was applied by SVN/Git commit 5a8d522397 (SVN 13323), which added the AND-semantics comment to the then-authoritative PlanDefinition and RequestGroup spreadsheet sources. Later source refactors carried the text into XML StructureDefinition sources, and FHIR-24619 renamed RequestGroup to RequestOrchestration.

Additional context:
Current source/fhir.ini actively builds PlanDefinition and RequestOrchestration and maps RequestGroup to RequestOrchestration. Current PlanDefinition.action.condition and RequestOrchestration.action.condition comments state that same-kind conditions are ANDed, no applicability conditions means applicable, and different condition kinds are considered separately. Later Applied issue FHIR-46179 added the no-condition and separate-kind clarifications without changing the FHIR-13926 AND rule. The original Jira also mentioned notes about other OR/XOR behavior, but current source already gives the implementer-facing conformance rule; adding generic modifier-extension prose would be redundant and could drift from the normative element comments.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source change because the current build-scope sources already satisfy the seed issue for both PlanDefinition and the RequestGroup successor resource.

Recommendation:
Keep this audit as-is. If work-group members want fresh guidance on modeling alternate boolean combinations, handle that as a new CDS guidance issue rather than changing the already-correct FHIR-13926 application.
