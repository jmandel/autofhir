FHIR-32798: Audit GraphDefinition extension ownership

Issue request:
FHIR-32798 is Published/Persuasive with Modification. It asked to allow GraphDefinition assertions in ElementDefinition.type.targetProfile and ElementDefinition.type.profile, especially where the constrained type is itself a resource such as Parameters or Bundle. The adopted resolution changed that to an ElementDefinition extension, described as graphDefinition 0..* canonical(GraphDefinition), indicating that the current Resource element or a referenced canonical/Reference instance must comply with a GraphDefinition, with tooling expected to render and validate it.

Initial application:
No source commit or current branch change explicitly mentioning FHIR-32798 was found. The closest implementation is the earlier same-family FHIR-19653 commit 226bd94b2c, which added elementdefinition-graphConstraint to source/datatypes/elementdefinition-extensions-spreadsheet.xml for ElementDefinition.type.targetProfile as canonical(GraphDefinition). That implementation covers the referenced-instance targetProfile case, not FHIR-32798's broader Resource/type.profile case. Commit dd468d4f17 then removed the extension rows from the core R5 source as part of moving extensions out of the core checkout.

Additional context:
FHIR-I minutes on 2022-03-07 record the FHIR-32798 decision as "Will add an extension for this" with the same vote as Jira. Later 2022-09 WGM minutes say FHIR-32798 was likely to reopen, and Jira comments say to hold off on GraphDefinition changes until Grahame could assess the ramifications and that, if done, it should be an extension. Current core source retains an OID entry for elementdefinition-graphConstraint, but the authoritative extension definition is now in the FHIR Extension Pack at input/definitions/datatypes/StructureDefinition-elementdefinition-graphConstraint.xml. That current extension pack definition is 0..1 on ElementDefinition.type.targetProfile with value canonical(GraphDefinition), and a 2023 Zulip tooling survey listed elementdefinition-graphConstraint as not supported.

AutoFHIR reconciliation:
This commit intentionally makes no FHIR core source change. The remaining source work, if FHIR-32798 is to be completed as written, belongs in the FHIR Extension Pack and associated tooling, not in the current core checkout. The current extension pack definition also appears narrower than FHIR-32798's current-element/resource/type.profile request, so changing it safely should be handled in that repository with FHIR-I/tooling review.

Recommendation:
Keep this external-repo audit commit as-is for the core reconciliation. Follow up in the FHIR Extension Pack and tooling to decide whether elementdefinition-graphConstraint should be broadened, whether a separate graphDefinition extension is needed, and how renderer/validator support should behave.
