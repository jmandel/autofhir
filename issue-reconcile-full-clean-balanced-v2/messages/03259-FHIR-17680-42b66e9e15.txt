FHIR-17680: Audit MedicationRequest intent constraint

Issue request:
FHIR-17680 was Published/Persuasive with Modification for the Pharmacy work group. It said MedicationRequest.intent was over-constrained because community pharmacy workflows need to exchange a filler/encoded view of an order that is not an individual instance/MAR order; the approved motion was to use request-intent semantics and update examples while not supporting reflex-instance.

Initial application:
Jira records commit 65133c5c9a9c6b94e85467b69529239812f98374 as the October 2018 application. Inspecting the merged source change shows underlying commit e1b82bc5a61a35b623c05f0ac408111209e5c0bb added reflex-order and filler-order to source/medicationrequest/codesystem-medicationrequest-intent.xml and adjusted MedicationRequest examples in the same change set. The current build no longer uses the old spreadsheet input, but the active generated/source StructureDefinition and terminology files retain the allowed filler-order code family.

Additional context:
MedicationRequest remains an active resource in source/fhir.ini. Later Published issue FHIR-34218 deliberately retained the MedicationRequest-specific intent value set, organized the order refinements under order, and clarified instance-order as MAR-schedule related rather than removing filler-order. Later FHIR-20605 reconciliation added the Request.intent granularity exception to MedicationRequest.intent, explicitly allowing an order to be clarified to filler-order. The related R6 record-of-request issue FHIR-49863 is not final in this run's source-edit scope and does not alter the FHIR-17680 conclusion.

AutoFHIR reconciliation:
Made no source change. The current active source already exposes MedicationRequest.intent as proposal | plan | order | original-order | reflex-order | filler-order | instance-order | option, binds it required to http://hl7.org/fhir/ValueSet/medicationrequest-intent, defines filler-order in the MedicationRequest intent code system, and keeps instance-order nested under filler-order with the MAR scheduling clarification. No reflex-instance code is present.

Recommendation:
Keep this audit commit as-is. Do not change the current binding back to the generic request-intent value set for FHIR-17680 alone; later Pharmacy work kept the MedicationRequest-specific value set while preserving the requested request-intent concepts. Any further review of value-set examples or newer record-of-request semantics should be handled under their own Jira issues.
