FHIR-11237: Audit retired Sequence strand constraint

Issue request:
FHIR-11237 was a Published/Persuasive Clinical Genomics change request against the DSTU2 FHIR-core Sequence resource. It observed that Sequence.referenceSeq.strand was an integer and asked for tighter strand constraints and definitions, with the final resolution choosing explanatory notes that map +1 to the plus strand (5' to 3')/Watson/Sense/positive and -1 to the minus strand (3' to 5')/Crick/Antisense/negative.

Initial application:
No historical commit explicitly names FHIR-11237, but the same 2016 strand-change family was applied to the old Sequence source. Commit 6072b705b6 revised source/sequence/sequence-spreadsheet.xml for FHIR-11238 with the requested numeric strand definitions, and commit a26b8894d0 added source/sequence/sequence-notes.xml prose mapping +1/-1 to Watson/Crick, Sense/Antisense, and positive/negative. That notes commit names FHIR-11233 and FHIR-11238, but its strand prose matches FHIR-11237's final resolution.

Additional context:
Later Clinical Genomics work superseded the old single integer strand element. Commit ed2a92ec79 split Sequence.referenceSeq.strand semantics into watson/crick strand plus sense/antisense orientation, FHIR-19453 later renamed Sequence to MolecularSequence, and current source no longer contains source/sequence or source/molecularsequence. source/fhir.ini lists Sequence under removed resources, comments MolecularSequence out of the current build metadata, and makes moleculardefinition the active Clinical Genomics resource. The current MolecularDefinition strand element is a distinct CodeableConcept with forward/reverse examples, not the retired Sequence.referenceSeq.strand integer.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The historical issue was applied to its target Sequence artifact, and reapplying the old +1/-1 integer guidance to current MolecularDefinition would be outside the issue's build scope and would conflict with later model changes rather than completing FHIR-11237.

Recommendation:
Keep this audit commit as-is. No current FHIR-core source follow-up is needed for FHIR-11237; if Clinical Genomics wants tighter current MolecularDefinition strand terminology, that should be raised and applied as a MolecularDefinition-specific issue rather than as a replay of retired Sequence wording.
