FHIR-11428: Audit Event performer organization handling

Issue request:
FHIR-11428 was Published with resolution Persuasive with Modification. It asked to change the Event pattern's performer from a single broad reference into a repeating performer structure that could identify both the performer and responsible organization: role 0..1 CodeableConcept, actor 1..1 Reference(Practitioner|RelatedPerson|Patient|Device|Organization), onBehalfOf 0..1 Organization, plus a guard against onBehalfOf for Patient or Device actors.

Initial application:
Git commit 839bf586d6c1cf9a322e122852f0cc49bcfed263 applied a batch of workflow tracker items including #11428 and changed source/event/event-spreadsheet.xml to a complex Event.performer with role, actor, and onBehalfOf. Later workflow history changed that model: commit 5064224bd079b7f4ef4023d3ead9111b57bd8bff collapsed Event.performer to a direct reference including PractitionerRole, and commit a964d42061fe3af2f0be7eec4382bfb5b91be697 / FHIR-13984 restored Event.performer as a backbone with function and required actor while keeping PractitionerRole in the actor targets.

Additional context:
source/fhir.ini lists event as an active logical model, so source/event/event-spreadsheet.xml is in current build scope. The current Event pattern has Event.performer 0..*, Event.performer.function 0..1 CodeableConcept, and Event.performer.actor 1..1 Reference(Practitioner|PractitionerRole|Organization|CareTeam|Patient|Device|RelatedPerson). FHIR-13984 is a later Published/Persuasive Event performer issue, already represented on the combined branch, confirming the current function/actor shape. FHIR-15128 is a later Published/Not Persuasive with Modification workflow-pattern issue, also already represented on the combined branch, that explicitly declined to restore Request.requester.onBehalfOf or Event.performer.onBehalfOf and accepted PractitionerRole as the current way to say Practitioner X at Organization Y.

AutoFHIR reconciliation:
Made no source change. The current source preserves the important FHIR-11428 capability to distinguish performer function and identify either an organization or a practitioner-at-organization through PractitionerRole. Re-adding Event.performer.onBehalfOf or its old invariant would conflict with the later FHIR-15128 decision and with the current active Event pattern.

Recommendation:
Keep this audit commit as-is. Do not restore workflow-pattern onBehalfOf without a new work-group decision; use Event.performer.actor as PractitionerRole when the event needs to identify both the practitioner and organization, and use resource-specific onBehalfOf elements only where later resource-specific decisions define them.
