FHIR-11321: Audit retired DataElement boundary

Issue request:
FHIR-11321 was a Published/Persuasive OO clarification request from the DSTU2 ballot asking the DataElement scope/boundaries section to explain overlap with ActivityDefinition. The approved text said ActivityDefinition defines actions that can occur, DataElement defines individual pieces of data that can be captured, and an ActivityDefinition focused on data capture might link to the DataElement defining that data.

Initial application:
The issue was applied in source history by git commit 47cf96aa02, whose subject named #11321 and whose patch added the approved ActivityDefinition/DataElement paragraph to source/dataelement/dataelement-introduction.xml. The current checkout no longer has a source/dataelement resource directory.

Additional context:
The same boundary question was also raised from the ActivityDefinition side in FHIR-11505, which is already represented on the combined branch by commit 57beecc49f. Later, FHIR-13094 was Published/Persuasive with Modification and collapsed DataElement into StructureDefinition logical models; it is already represented on the combined branch by commit c1a07840fd. In the current build, DataElement is commented out in source/fhir.ini and source/history.html records DataElement as a removed resource, while ActivityDefinition and StructureDefinition remain active current resources.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Restoring the old DataElement boundary prose would document a retired resource, and adding a new ActivityDefinition-to-StructureDefinition comparison would go beyond the DSTU2 DataElement clarification and duplicate broader FHIR-13094 follow-up work. The current source is correct for this issue family after considering DataElement's removal.

Recommendation:
Keep this no-change audit. Future work, if any, should be framed as a new current-resource clarification about ActivityDefinition, StructureDefinition logical models, or catalogs rather than reviving retired DataElement wording.
