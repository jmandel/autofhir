FHIR-39030: Audit SubscriptionTopic notificationShape link

Issue request:
FHIR-39030 was a Published FHIR-core SubscriptionTopic change request, resolved Persuasive with Modification for R5. It asked for an explicit programmatic link between the triggering resource and the notification resource, with the final resolution saying that notificationShape is only relevant based on the matching triggering resource, such as resourceTrigger.resource, and that explanatory text should be added.

Initial application:
The issue was applied by e8b21b2071a6adc2c4cb2713bcb28808cd56ef12, which changed the SubscriptionTopic source definition and narrative to state that notificationShape.resource is the focus/root for the shape and will be the same, a generality, or a specificity of resourceTrigger.resource or eventTrigger.resource when present. The source is in build scope because source/fhir.ini actively lists subscriptiontopic=SubscriptionTopic.

Additional context:
FHIR-I WGM minutes for 2023-01 recorded the Subscription tracker vote for FHIR-39030 as adding clarifying text, 10-0-0. Later FHIR-46492 collapsed resourceTrigger and eventTrigger into SubscriptionTopic.trigger and moved notificationShape under trigger; that refactor preserved the FHIR-39030 relationship by updating the same wording to reference SubscriptionTopic.trigger.resource / trigger.resource. Neighboring FHIR-39031 clarified client expectations for additional included resources but did not change the triggering-resource-to-shape relationship.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/subscriptiontopic/structuredefinition-SubscriptionTopic.xml defines SubscriptionTopic.trigger.notificationShape.resource as the focus/root for the shape and says it will be the same, a generality, or a specificity of SubscriptionTopic.trigger.resource when present. Current source/subscriptiontopic/subscriptiontopic-notes.xml repeats the same rule in the Notification Shape section and explains root-resource matching and included-resource behavior.

Recommendation:
Keep this audit commit as-is. The current build already contains the clarification requested by FHIR-39030 after the later trigger refactor, and adding more prose would duplicate existing normative guidance without changing implementer understanding.
