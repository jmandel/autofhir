FHIR-17221: Audit Observation performer validator fix

Issue request:
FHIR-17221 was a Published/Persuasive STU3 FHIR-core change request reporting that the Java RI validator treated Observation.performer as single-valued, calling getNamedChild and failing when an Observation carried multiple performers even though Observation.performer is 0..*.

Initial application:
The current HL7/fhir history has no commit message mentioning FHIR-17221 or GF17221. The Jira issue was auto-approved and Grahame Grieve commented that it was already fixed; the contemporaneous Zulip thread identifies the behavior as Java RI/HAPI validator implementation behavior rather than a requested StructureDefinition change.

Additional context:
The current build includes Observation as an active resource, and the authoritative Observation StructureDefinition still defines Observation.performer with min 0 and max *. The published STU3 profile also has min 0 and max *, confirming that the specification surface already allowed multiple performers when the issue was raised. The old Java RI InstanceValidator/Element.java implementation referenced from the issue is not present in this checkout, and a related documentation request, FHIR-17147, was later resolved No Change for documenting validator best-practice warnings.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current FHIR source and the relevant published STU3 profile already express the correct repeating cardinality, and the reported defect was an implementation validator bug that Jira records as already fixed outside any current HL7/fhir source file.

Recommendation:
Keep this audit commit as-is. Do not add redundant Observation prose or alter the StructureDefinition for FHIR-17221; if the multiple-performer validation behavior ever regresses, it should be investigated in the current external validator/HAPI implementation codebase rather than in the core specification source.
