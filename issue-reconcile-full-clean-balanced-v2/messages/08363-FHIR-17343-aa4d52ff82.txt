Issue request:
FHIR-17343 was Published/Persuasive for STU3 and asked to make explicit, based on the linked Questionnaire Zulip thread, that QuestionnaireResponse answer.value[x] datatypes must match the corresponding Questionnaire.item.type.

Initial application:
The change appears to have been applied by the 2018-08-04 "QuestionnaireResponse trackers" commit e4ad0ecf, which added "Must match the datatype specified by Questionnaire.item.type in the corresponding Questionnaire" to the QuestionnaireResponse answer value comment in the then-authoritative spreadsheet source. Later source refactors preserved the sentence into the current StructureDefinition source.

Additional context:
QuestionnaireResponse is an active current-build resource in source/fhir.ini, and the current source/questionnaireresponse/structuredefinition-QuestionnaireResponse.xml comment for QuestionnaireResponse.item.answer.value[x] still contains the required datatype-match sentence. Later FHIR-37360 wording expanded the same comment to clarify matching answerOption/answerValueSet complex values without weakening the datatype-match requirement.
