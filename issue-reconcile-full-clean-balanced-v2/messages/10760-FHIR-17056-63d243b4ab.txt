FHIR-17056: Audit Bundle.total search count clarification

Issue request:
FHIR-17056 was a Published/Persuasive FHIR-core Feed clarification from the STU3 ballot asking the Bundle.total definition to say it is the total number of entries of type 'match' across all search pages, excluding include and outcome entries and not merely counting entries in the current Bundle.

Initial application:
The issue was applied in svn 14368, imported as git commit 2a9d92faa72912b0b7ed10f9b5c27b80dfc0c2e5, which changed source/bundle/bundle-spreadsheet.xml from the old less precise wording to the requested match/include/outcome wording. Later source refactors moved the authoritative Bundle definition into source/bundle/structuredefinition-Bundle.xml while preserving that clarification.

Additional context:
Bundle is an active resource in source/fhir.ini, so source/bundle/structuredefinition-Bundle.xml feeds the current build. Current source says Bundle.total is the potentially estimated total number of entries of type 'match' across all pages and excludes search.mode include and outcome entries. FHIR-33942 later added the estimated-count qualifier for _total, and FHIR-48485 later kept the search/history restriction while adding explanatory context; neither reverses the FHIR-17056 clarification. The current search narrative likewise says Bundle.total counts matching resources, not returned entries, and excludes included resources and OperationOutcome entries.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change because the current active Bundle.total definition already contains the clarification requested by FHIR-17056, with later approved refinements that remain consistent with it.

Recommendation:
Keep this no-change audit commit as-is. No core source follow-up is needed for FHIR-17056 unless a future work group decision changes Bundle.total semantics.
