FHIR-13263: Audit historical v3 concept anchors

Issue request:
FHIR-13263 was a Published/Persuasive STU3 correction for generated v3 CodeSystem and ValueSet HTML. The issue reported that generated ValueSet concept links used the FHIR CodeSystem id-plus-code fragment pattern even though the then-published v3 CodeSystem concept anchors used only the bare code, breaking links such as AcknowledgementDetailType code E.

Initial application:
The Jira application note records SVN revision 12610. That revision is present in the Git history as commit 8234c93ab062a4a19632e5874bd2db979013b9fd, "#13263 - fix v3 cs anchors", and it is an ancestor of both the worker branch and the combined branch. The patch changed the v3 importer so generated v3 CodeSystem concept anchors use the v3 CodeSystem id plus the concept code, matching generated ValueSet links. Later published R4 and current THO pages for AcknowledgementDetailType show href="#v3-AcknowledgementDetailType-E" links with matching CodeSystem anchors.

Additional context:
The frozen STU3 web page still shows the original mismatch, but the source application happened in the old SVN/Git build tooling after that publication. The current FHIR core build no longer owns or generates those v3 terminology pages: source/fhir.ini has no active v3 CodeSystem or ValueSet entries, build.fhir.org returns 404 for the old v3/AcknowledgementDetailType pages, and commit 5c0494aacfd0b8bd52bc72c587aa89d0a64246f8 deleted ValueSetImporterV3 as part of removing UTG content from the core build. The current THO publication surface for the v3 AcknowledgementDetailType terminology has matching links and anchors.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The Jira's recorded application commit is already in the current history and current in-scope FHIR core source has no active v3/AcknowledgementDetailType generated page or importer to correct.

Recommendation:
