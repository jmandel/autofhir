FHIR-12639: Audit MedicationDispense detected issue handling

Issue request:
FHIR-12639 was Published/Persuasive with Modification for DSTU2. It asked MedicationDispense to add a DetectedIssue link with cardinality 0..*, and to add notDone plus notDoneReason[x] as a 0..1 CodeableConcept-or-DetectedIssue reference reason for a dispense that was not performed.

Initial application:
The Jira comments point to SVN-migrated commits a504c1b697 and 06d1e63468. Commit a504c1b697 added MedicationDispense.detectedIssue to the then-authoritative MedicationDispense spreadsheet source, and commit 06d1e63468 added MedicationDispense.notDone and MedicationDispense.notDoneReason[x].

Additional context:
MedicationDispense is an active current resource in source/fhir.ini. Later R5 pharmacy decisions changed how the original fields are represented. FHIR-34000 renamed MedicationDispense.statusReason to MedicationDispense.notPerformedReason, preserving the not-performed reason semantics with the current CodeableReference type that can carry either a code or a Reference(DetectedIssue). FHIR-34293 then intentionally removed MedicationDispense.detectedIssue, explaining that DetectedIssue should point to implicated medication resources rather than creating bidirectional links; the already-published AutoFHIR FHIR-34293 commit on the combined branch completed the Medication Module guidance for searching DetectedIssue.implicated. FHIR-49940 further confirms the current declined/cancelled dispense pattern with MedicationDispense.status plus notPerformedReason examples.

AutoFHIR reconciliation:
Made no source change. Current MedicationDispense already has the not-performed representation through status and MedicationDispense.notPerformedReason, including Reference(DetectedIssue) support, while the direct MedicationDispense.detectedIssue element requested in DSTU2 should remain absent because it was superseded by the later FHIR-34293 decision and module guidance.

Recommendation:
Keep this empty audit commit as-is. Re-adding MedicationDispense.detectedIssue would contradict the later published Pharmacy decision; future work should only revisit this if the work group reopens the DetectedIssue directionality policy.
