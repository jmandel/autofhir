FHIR-34433: Audit R4B ConceptMap generation fix

Issue request:
FHIR-34433 was a Published/Persuasive technical correction for R4B ConceptMaps. It reported that R4B-shipped ConceptMap instances contained the R5-only ConceptMap.group.element.target.relationship element, even though R4B ConceptMap uses target.equivalence.

Initial application:
No HL7/fhir source commit or source comment mentions FHIR-34433 directly. The Jira comment links HL7/kindling#69, merged 2022-04-07, whose description says R4B generation must use R4 ConceptMaps and other resources rather than R5 resources for generated instances. The R4B branch now has ConceptMap target.equivalence in the StructureDefinition and no ConceptMap XML sources with relationship elements.

Additional context:
The current core build is not R4B. source/fhir.ini actively includes ConceptMap, and the current ConceptMap StructureDefinition defines ConceptMap.group.element.target.relationship as a required element. Current ConceptMap XML sources consistently use relationship rather than equivalence, which is correct for the current FHIR version. The fhir.ini migration notes also map the old ConceptMap.group.element.target.equivalence element to relationship.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Removing relationship from current ConceptMap sources would regress the current build; the R4B-specific problem was a generation/tooling issue handled in Kindling and reflected by the R4B branch using equivalence.

Recommendation:
Keep this audit commit as-is. No current HL7/fhir source follow-up is needed for FHIR-34433; any future recurrence would belong in R4B publication tooling or the R4B branch rather than in the current ConceptMap source.
