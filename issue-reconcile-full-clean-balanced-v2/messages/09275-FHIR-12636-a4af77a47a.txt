FHIR-12636: Audit TestReport element order

Issue request:
FHIR-12636 was a Published/Persuasive FHIR-I change request for DSTU2. It reported a build warning that TestReport's resource elements were ordered as identifier, status, testScript, issued when the expected order was identifier, testScript, status, issued, and requested reordering TestReport.testScript in the TestReport definition.

Initial application:
The issue was applied before this reconciliation. Git-svn commit c03c68f93aeb (#12636, svn @10828) changed source/testreport/testreport-spreadsheet.xml so TestReport.testScript moved before TestReport.status, matching the Jira resolution that TestReport.testScript was re-ordered in the structure.

Additional context:
The current core checkout no longer contains an authoritative source/testreport StructureDefinition. Commit f9a44787c4 removed TestScript, TestReport, and TestPlan resource source from core and added the FHIR Testing IG to source/fhir.ini's additional IG list; TestReport is absent from the active [resources] list. The current Testing IG TestReport snapshot orders the evolved resource fields as identifier, name, description, status, testScript, result, score, tester, issued, so reapplying the old DSTU2 order in core would not be a current-spec correction. The remaining core ModelInfo surface already has the current relative order of status before testScript, and the separate TestReport.testScript type issue FHIR-34502 is already represented on the combined branch.

AutoFHIR reconciliation:
Published an empty no-change audit commit. No source was changed because the original DSTU2 ordering fix is present in history, the current core build does not own the TestReport StructureDefinition, and the current Testing IG/ModelInfo surfaces do not support changing status/testScript order back to the old DSTU2 warning order.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed for FHIR-12636; any future work on current TestReport element order should be raised against the FHIR Testing IG rather than this core checkout.
