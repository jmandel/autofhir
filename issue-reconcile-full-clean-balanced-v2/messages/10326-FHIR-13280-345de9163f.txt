FHIR-13280: Audit POST search examples

Issue request:
FHIR-13280 was a Published/Persuasive FHIR-core search change request for STU3 asking to show an example of a complex POST-based search, especially one with multiple parameters and URL-encoded characters. The accepted resolution requested an example with Content-Type application/x-www-form-urlencoded and a POST body such as _id=123&family=Da%20Silva.

Initial application:
The Jira comment records svn revision 12863. In the Git mirror, commit 2cf07ef87a042eba6604231ebf868d8c1d536566 (#13280 - search post example improved) corresponds to that revision and added a POST [base]/[type]/_search example with Content-Type application/x-www-form-urlencoded and form parameters to source/http.html. Later search-page work expanded the presentation into GET/POST paired examples across search concepts.

Additional context:
Current build-source pages already cover the requested behavior. source/http.html contains the active HTTP search interaction section with POST examples for server-root, resource-type, compartment, and compartment/resource searches using application/x-www-form-urlencoded bodies. source/search.html contains active search narrative with paired GET and POST displays, including an encoding example and complex Patient searches with multiple parameters, repeated parameters, OR values, and modifiers. A bounded Jira search found FHIR-33220 about POST search self links and FHIR-31588 in US Specialty Rx, but those are separate issues and do not change the seed conclusion. Zulip and Confluence searches found no directly relevant or conflicting community decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Adding another literal Da Silva example would duplicate existing current guidance rather than change implementer understanding: the active HTTP page shows the POST form body shape and the active search page demonstrates both URL encoding and complex multi-parameter POST searches.

Recommendation:
