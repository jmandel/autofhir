FHIR-13593: Audit DataRequirement mustSupport path clarification

Issue request:
FHIR-13593 was Published with a Persuasive with Modification resolution for STU3. It asked to clarify whether DataRequirement.mustSupport values are FHIRPath strings and, if so, which FHIRPath features are allowed. The approved text required mustSupport to be a FHIRPath resolvable on the DataRequirement type and limited paths to identifiers, constant indexers, and .resolve().

Initial application:
The issue appears to have been applied by SVN/git commit 74161b7e2037bc36b915e2d57d02743cc607ad3f, whose message says it clarified datarequirements.mustSupport for GF#13593 and DataRequirement filters for GF#13901. Before that commit, DataRequirement.mustSupport only said it could be a path; after the commit, the source contained the approved FHIRPath restriction text.

Additional context:
The original Zulip DataRequirement thread shows the practical question that led to the tracker: how to express specific nested or extension elements in DataRequirement.mustSupport without allowing arbitrary FHIRPath filtering. FHIR-12624 was later resolved as addressed by FHIR-13593, and FHIR-13901 was applied in the same historical source commit for neighboring filter paths. Current source/fhir.ini keeps DataRequirement as an active metadata type on the metadatatypes page, so source/datatypes/datarequirement.xml remains the authoritative build input for this element.

AutoFHIR reconciliation:
This audit commit makes no source change. The current DataRequirement.mustSupport definition already says the value SHALL be a FHIRPath resolvable on the type of the DataRequirement and that the path SHALL consist only of identifiers, constant indexers, and .resolve(), with a link to the Simple FHIRPath Profile. Nearby narrative mentions DataRequirement.mustSupport without contradicting or weakening that definition.

Recommendation:
Keep this audit commit as-is. No FHIR core source follow-up is needed for FHIR-13593 unless a later work group decision changes the permitted FHIRPath subset for DataRequirement.mustSupport or separately updates the Simple FHIRPath location list.
