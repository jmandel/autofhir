FHIR-3183: Audit ElementDefinition condition generation

Issue request:
FHIR-3183 was a Published/Persuasive DSTU1 correction asking that generated profiles-resources output include ElementDefn.condition nodes pointing to the relevant Constraint.id values for elements involved in invariants.

Initial application:
The Jira application note says "fixed. svn revision 2976". A bounded search of the current Git history did not find a directly relevant FHIR-3183 source commit, which is expected for this SVN-era generator/output issue.

Additional context:
FHIR-3130 is the same change family: it reported the Profile generator omitting Profile.structure.element.definition.condition, and Grahame Grieve commented that it was already done as #3183. The old DSTU1 Profile surface is no longer the current build surface; current conformance uses StructureDefinition and ElementDefinition.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source defines ElementDefinition.condition as a repeating id reference to invariants, defines ElementDefinition.constraint.key as the target of that reference, and generated resource StructureDefinitions already contain condition references pointing to constraint keys.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed unless a future concrete generator regression shows condition references missing from current StructureDefinition output.
