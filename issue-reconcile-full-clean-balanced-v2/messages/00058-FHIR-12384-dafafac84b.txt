FHIR-12384: Audit removed US Core extension definitions

Issue request:
FHIR-12384 was Published with resolution Persuasive with Modification. It asked to move US-realm/US Core Patient extensions out of the FHIR core specification and, as modified by the US Realm Steering Committee, to leave core with a page or registry path that links to realm-specific extension definitions.

Initial application:
The issue was applied in January 2017. The history shows commits that removed/repointed US Core extension references, disabled the dedicated Patient example showing US extensions, and finally commented out the `us-core` profile entry in `source/fhir.ini`. Some files from that old profile family remain in the repository, but the active build configuration no longer includes the US Core profile spreadsheet.

Additional context:
Current Patient remains build-scope, but `source/fhir.ini` has `;us-core=us:profiles/us-core-spreadsheet.xml`, so the old US Core profile source is dormant. Current source still contains a few external URLs to US Core definitions, including a Patient/Provenance example added later by FHIR-39392 to demonstrate pointing Provenance at an extension; those references do not define US Core extensions in core. Current build URLs for the old core US Core extension, value set, and dedicated example pages return 404, while Patient profile/extension pages remain available through current registry/navigation mechanisms.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. Removing dormant out-of-build files or external example references would go beyond FHIR-12384 and could break later intentional examples; the built core specification already no longer publishes the old US Core extension definitions.

Recommendation:
Keep this no-change audit. If the project wants repository hygiene for dormant `source/us` or commented `source/profiles/us-core-*` files, handle that as a separate human-reviewed cleanup rather than a FHIR-12384 spec correction.
