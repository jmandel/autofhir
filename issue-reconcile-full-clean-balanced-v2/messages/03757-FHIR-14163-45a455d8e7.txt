FHIR-14163: Audit ResearchSubject status value set

Issue request:
FHIR-14163 was a Published/Persuasive STU3 BR&R request to update ResearchSubject so ResearchSubject.status used the vetted ResearchSubjectStatus value set for subject progression.

Initial application:
The issue was applied before this reconciliation. Git history shows 51ac19819f8117a5a0c2827b0df972681ba430d9 updating the ResearchSubject.status row in source/status-codes.xml from the earlier generic status set to the vetted subject-progression list, followed by b17e23b77e7eeef1a16b7e68c65dd54605f822cd updating the ResearchSubject resource spreadsheet in the same Dec 2017 ballot work.

Additional context:
ResearchSubject is in the active build scope through source/fhir.ini. Later Published BR&R decisions changed the current model: FHIR-31657 approved the progress attribute and FHIR-31689 explicitly made ResearchSubject.status only the resource publication status. The current source therefore binds ResearchSubject.status to http://hl7.org/fhir/ValueSet/publication-status and models subject progression separately on ResearchSubject.subjectState.code, now with an Example binding to the THO research-subject-state value set after the R6 subjectState and terminology-binding changes.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Rebinding the current ResearchSubject.status element to the old ResearchSubjectStatus value set would reverse later WG decisions, and adding redundant local prose would not improve the current specification. The remaining subject-state terminology details are governed by later R6/THO work, not by the STU3 status binding request.

Recommendation:
Keep this audit commit as-is. Do not change ResearchSubject.status for FHIR-14163; any future terminology work should be handled under the later ResearchSubject.subjectState/THO issues rather than reopening the old STU3 status binding.
