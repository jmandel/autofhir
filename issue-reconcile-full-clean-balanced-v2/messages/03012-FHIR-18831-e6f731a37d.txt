FHIR-18831: Audit AllergyIntolerance clinicalStatus missing-data guidance

Issue request:
FHIR-18831 was a Published/Not Persuasive with Modification Patient Care change request for STU3 AllergyIntolerance. It asked to remove the requirement that AllergyIntolerance.clinicalStatus be present when verificationStatus is not entered-in-error because source systems may not know the clinical status; the final resolution kept the invariant but added a comment referring to the extensibility Special-Case guidance when clinicalStatus is missing.

Initial application:
The Jira application comment points to GH#ef05a01a0bea. That commit is present in history and says "GF#18831 - add comment to AllergyIntolerance.clinicalStatus"; it added the Special-Case sentence to the then-authoritative AllergyIntolerance spreadsheet. The source was later converted into structuredefinition-AllergyIntolerance.xml, preserving that sentence, and a 2023 QA commit corrected the historical "clincalStatus" typo to "clinicalStatus".

Additional context:
AllergyIntolerance is an active current-build resource in source/fhir.ini. Later published decisions changed how the original requirement should be understood: FHIR-25514 removed the ait-1 invariant and replaced it with should-present guidance for non-entered-in-error, non-negated AllergyIntolerance records; FHIR-28458 removed the remaining AllergyIntolerance clinicalStatus invariant path and added refuted-status guidance. Existing combined-branch audit commits already represent FHIR-25514, FHIR-23008, and FHIR-28458, so this reconciliation intentionally does not duplicate them.
