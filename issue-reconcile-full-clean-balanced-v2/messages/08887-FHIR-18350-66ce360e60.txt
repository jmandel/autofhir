FHIR-18350: Audit modifier-extension domain resource wording

Issue request:
FHIR-18350 was a Published/Persuasive STU3 FHIR-core extensibility change request. It asked to rephrase the modifier-extension placement sentence from "at the base of a resource or in any elements..." to "at the base of a domain resource, in any elements...", correcting both the resource scope and the list punctuation.

Initial application:
The issue was applied directly in git commit c46ff00cc7bffce09464c5e632054d767672c77c, which changed source/extensibility.html to the requested "base of a domain resource, in any elements" wording. The current source still carries that correction.

Additional context:
source/extensibility.html is in the current build surface because source/fhir.ini maps the Extension datatype page to extensibility. Later source history adjusted neighboring wording without reversing this issue: FHIR-25431 standardized "datatype" spelling, and the already-published FHIR-18351 reconciliation split the adjacent modifier-extension datatype rule. A 2025-2026 Zulip thread and the linked FHIR-52858 issue discuss whether the paragraph should further mention BackboneElement, but FHIR-52858 is still Submitted/Unresolved and does not change the final FHIR-18350 decision.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change because the authoritative current source already implements the requested domain-resource wording and remains consistent with later applied edits.

Recommendation:
Keep this audit commit as-is for FHIR-18350. Any future clarification about BackboneElement or BackboneType should be handled under FHIR-52858 or another final work-group decision, not folded into this older punctuation-and-scope correction.
