FHIR-13446: Audit Claim occurrence and value code support

Issue request:
FHIR-13446 is a Published FM change request, resolved Persuasive with Modification, asking for occurrence-code and value-code value sets for UB-04 use with the Claim resource. The final resolution said Claim.information should carry this data using category, code, timing, and value, noted OID syntax for code systems, and explained that the underlying code sets are proprietary and need standard identifiers for implementers who have rights to use them.

Initial application:
No current git commit explicitly mentions FHIR-13446. The relevant Claim support appears through earlier source history: commit 83b1eacff1 added example occurrence, occurrence-span, and value-code value sets for Claim, and commit afb5ec66f6 later changed Claim.information to Claim.supportingInfo as part of tracker 19460. The active current source keeps Claim as a built resource and retains Claim.supportingInfo with aliases for Occurrence Codes and Value codes, plus category, code, timing[x], and value[x] fields.

Additional context:
The Jira comment trail clarifies that this is a US-realm/proprietary terminology concern and that profile authors use the Additional Information backbone for these codes; it also points to THO v2-0350 for occurrence codes. Current core source has example occurrence/value terminology and OID registrations, but not required bindings to proprietary UB-04/AMA code sets. Jira, Zulip, and Confluence searches found no final FHIR-core decision requiring a broader current core edit.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current Claim source already supports the requested representation through supportingInfo and example terminology, and adding proprietary US-realm value set bindings to core would go beyond the Jira resolution and current source evidence.

Recommendation:
Keep this no-change audit commit. Future work for concrete UB-04/NUBC/AMA terminology should be handled in THO or US-realm implementation guides/profiles with the appropriate rights and canonical identifiers, not by changing the generic core Claim resource.
