FHIR-3527: Audit default-value methodology

Issue request:
FHIR-3527 was a Published/Persuasive with Modification FHIR-core datatypes issue asking MnM to make explicit that no element, including optional booleans, has an implicit default. The applied decision also said that if a boolean value must always be known, the element should be mandatory and the primitive value should be required.

Initial application:
The Jira comments record application in SVN revision 3486. This checkout's Git history has no FHIR-3527 or revision 3486 commit hit, but the current source carries the migrated methodology. Later default cleanup commits, especially 72143f2 and 7ac081b, removed default-value examples and residual default semantics from the ElementDefinition guidance.

Additional context:
FHIR-15121 and the January 2018 FHIR-I minutes later refined the policy: remove defaultValue[x] for FHIR resources and datatypes, retain meaningWhenMissing only for explicit missing semantics, prevent profiles from changing missing meaning, and treat present-but-no-value/extension-only primitives as missing. Current ElementDefinition and StructureDefinition source reflects that later policy.

AutoFHIR reconciliation:
This audit intentionally made no source change. The active ElementDefinition page already says missing elements have unknown value unless the specification states a specific missing meaning, that this also applies to extension-only primitives, and that FHIR resources and datatypes define no default values. The ElementDefinition source says defaultValue[x] exists only for logical models, StructureDefinition invariants enforce no default values for FHIR specification models, and primitive value requirements are covered by mustHaveValue/valueAlternatives.

Recommendation:
Keep this no-change audit commit. Do not add redundant datatype prose for FHIR-3527; future changes to default or missing-element semantics should be separate FHIR-I/MnM work because the current source already implements the reconciled policy.
