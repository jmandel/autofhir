FHIR-34264: Audit referencesContained Extension Pack ownership

Issue request:
FHIR-34264 was a Published/Persuasive FHIR-core change request asking to add the SDC-originated referencesContained extension to core so content hidden inside expressions, XHTML, or similar strings could satisfy the dom-3 contained-resource reference rule.

Initial application:
The issue was applied in core by commit 071a1735ce, which added a referencesContained row to the active general extensions spreadsheet in source/profiles/general-extensions-spreadsheet.xml. The Jira comment records the same Git lloyd-changes commit.

Additional context:
The origin SDC issue FHIR-34025 defined the same extension for cases where validator-visible Reference/canonical checks cannot see embedded contained-resource references. Core commit dd468d4f17 later removed the extension definitions from the R5 source as part of the Extension Pack split, and the Extension Pack introduction states that globally defined extensions moved out of the core specification starting with R5. Later Extension Pack issues FHIR-48947 and FHIR-49855 refined this same extension, and their applied commits are reflected in the current Extension Pack StructureDefinition.

AutoFHIR reconciliation:
This commit intentionally makes no source change in the core FHIR checkout. The current core source no longer owns the extension definition, while /home/jmandel/work/fhir-extensions/input/definitions/datatypes/StructureDefinition-referencesContained.xml defines http://hl7.org/fhir/StructureDefinition/referencesContained with the expected contained-resource purpose, contexts, OID, and Reference value. The core checkout still retains the canonical-to-OID registration in source/oids.ini.

Recommendation:
Keep this audit commit as-is. Do not re-add referencesContained to the core general extensions spreadsheet; future changes to the extension should be reconciled in the FHIR Extension Pack repository.
