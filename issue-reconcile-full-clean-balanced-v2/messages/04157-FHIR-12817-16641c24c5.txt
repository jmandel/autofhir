FHIR-12817: Audit Communication CareTeam recipient support

Issue request:
FHIR-12817 was a Published/Persuasive FHIR-core Communication change request from Patient Care. It asked for Communication.recipient to allow Reference(CareTeam) because CommunicationRequest.recipient already allowed CareTeam; the final resolution was to add CareTeam to the possible references for Communication.recipient.

Initial application:
The issue was applied in historical commit 25735dcc63, whose message explicitly listed #12817 and whose patch changed source/communication/communication-spreadsheet.xml so Communication.recipient added CareTeam to its Reference target list and mentioned care team in the element definition. Later source-format rework commits carried the target into the current XML StructureDefinition, and d9792bc48d made the post-rework Communication.recipient representation an explicit target list that still included CareTeam.

Additional context:
Communication and CommunicationRequest are active build resources in source/fhir.ini. The current Communication StructureDefinition and reviewer notes both list CareTeam as a Communication.recipient target, and CommunicationRequest.recipient still includes CareTeam. The Zulip thread linked from Jira confirms the tracker was logged specifically for this mismatch; Confluence and direct community searches found no conflicting decision. The follow-up issues mentioned in the Jira comments concern CareTeam telecom and Group/CareTeam boundaries, not a missing Communication.recipient target.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The authoritative current source already satisfies the accepted request, and the Communication recipient search parameter is path-based with no separate target list to update.

Recommendation:
Keep this no-change audit as-is. If a future work group wants Communication and CommunicationRequest recipient target lists to be identical in every respect, that should be handled as a separate decision because FHIR-12817's final resolution was the CareTeam addition, which is already present.
