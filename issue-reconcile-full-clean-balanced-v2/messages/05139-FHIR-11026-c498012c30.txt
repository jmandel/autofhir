FHIR-11026: Audit Condition refuted evidence guidance

Issue request:
FHIR-11026 is a Published Patient Care change request, resolved Persuasive with Modification for R5, about the relationship between Condition and Observation when representing absence, refutation, and supporting evidence. The final resolution updated the Assertions of Condition Absence guidance for refuted Conditions, clarified the refuted verification status code definition, and changed Condition.evidence wording to describe evidence supporting verification status, including evidence that confirmed or refuted the condition.

Initial application:
The issue was applied before this reconciliation by commit f403e6bf3448762019dc45c82cfbb2aaa9362585, whose subject explicitly references FHIR-11026/J#11026 and whose patch changed source/condition/condition-notes.xml plus the then-authoritative Condition spreadsheet. The refuted-condition narrative was later preserved through source restructuring and restoration, the refuted code definition was moved out of core with the THO duplicate-removal work, and the Condition.evidence wording was present until a later Patient Care decision deliberately broadened it.

Additional context:
Condition and Observation are active resources in source/fhir.ini, so source/condition is current build scope for this audit. Related issues already represented on the combined branch cover adjacent decisions: FHIR-11077 audits the original Assertions of Condition Absence section, FHIR-15610 audits the earlier Condition.evidence verification-status wording, FHIR-28458 audits the later refuted-status guidance, and FHIR-42981 audits the later broadening of Condition.evidence. FHIR-42981 is especially important because it intentionally replaced the verification-status-focused Condition.evidence short/definition with "Supporting evidence for the condition" and "basis for determining the Condition" while retaining confirmed/refuted cumulative-evidence guidance in the comment. Direct Zulip and Confluence searches for FHIR-11026 found no conflicting community decision; broader Condition/Observation discussions still distinguish refuted Conditions from general pertinent negatives.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Condition notes still say a refuted Condition is appropriate only when the Condition was considered present and subsequent evidence refuted it, that Condition.verificationStatus can convey refuted, and that evidence of the refutation can be conveyed in Condition.evidence. The current Condition.evidence element is correct after FHIR-42981; restoring the exact FHIR-11026 wording would incorrectly narrow the element back to verification status only. The current ValueSet still includes the THO code system whose refuted code definition matches the FHIR-11026 resolution.

Recommendation:
Keep this audit commit as-is. No FHIR core source change is needed for FHIR-11026; any future change should be a new Patient Care decision about the post-FHIR-42981 scope of Condition.evidence or the generated diagram artifacts, not a reversal of this applied R5 issue.
