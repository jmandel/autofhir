It asked to replace the misspelling "object-orientated" with "object-oriented" and the resolution said to make the changes to formats.html and consider changing "service orientated" to "service-oriented".

Initial application:
The issue was pre-applied in git commit 3e8758b8aeb0bb394599b3b036fb6f53a484fc53, which corrected two occurrences in source/formats.html. The Jira comment also records that the formats.html changes were pre-applied, and the current formats.html source still uses "Object-Oriented" and "object-oriented".

Additional context:
Current build-scoped source still had two related misspellings outside formats.html: source/uml.html used "Object-Orientated" in the UML interface note added later by git commit 33e68c1eda7168d4cc4282e3ced2a12256037b39, and source/exchange-module.html retained the older "service orientated" wording explicitly mentioned as a consideration in the Jira resolution. source/hierarchy.xml lists both the UML and Exchange pages in the active page hierarchy, while tools/history/release5 contains historical generated release text that should not be edited for a current-source correction. Community searches found no FHIR-26932-specific Zulip or Confluence discussion that narrows or reverses the Jira typo decision; the relevant committers Zulip thread only explains the later UML note's origin.

AutoFHIR reconciliation:
This commit corrects the active source pages by changing "UML/Object-Orientated Programming" to "UML/Object-Oriented Programming" in source/uml.html and "service orientated architecture" to "service-oriented architecture" in source/exchange-module.html. It intentionally leaves historical tools/history release archives unchanged because they are not the authoritative current build source.

Keep this source-changing commit as the final core reconciliation for FHIR-26932. No additional core source work is needed unless humans decide to rewrite historical release archives, which would be outside this current-build typo correction.
