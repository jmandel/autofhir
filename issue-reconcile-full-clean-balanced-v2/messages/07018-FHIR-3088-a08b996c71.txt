FHIR-3088: Audit id datatype definition

Issue request:
FHIR-3088 was Published/Persuasive with Modification and asked to replace the initial id datatype wording with a lower-case letter/numeral/'-'/'.' definition, a 36-character limit, and guidance that systems SHALL send ids lower-case but SHOULD interpret them case-insensitively.

Initial application:
The issue was applied in 4500eacfaa, which changed both source/datatypes.html and source/datatypes/primitives.xml to the requested lower-case, 36-character, case-insensitive wording. The Jira snapshot also records svn revision 3021 as the original application.

Additional context:
Later Published issues superseded key parts of the FHIR-3088 text. FHIR-3750 accepted upper- and lower-case ASCII ids, a 64-character limit, case-sensitive ids, lowercase UUIDs, and regex [A-Za-z0-9\-\.]{1,64}. FHIR-3768 added ISO 18232 context and explicitly distinguished FHIR ids from ISO's case-insensitive behavior. FHIR-5140/FHIR-5141 confirmed the 64-character length alignment, and FHIR-13320 confirmed _id searches are always case-sensitive. Current source/datatypes.html and source/search.html follow those later decisions.

AutoFHIR reconciliation:
This is an empty audit commit for FHIR-3088. The current specification should not be reverted to FHIR-3088's original lower-case/case-insensitive 36-character wording because that wording was intentionally superseded. The only remaining active-source inconsistency found in this investigation was the stale case-insensitive generated primitive source, which was corrected in the immediately preceding FHIR-3750 source commit.

Recommendation:
Keep this no-change audit. Future work should preserve the later case-sensitive 64-character id semantics rather than reapplying the obsolete FHIR-3088 wording. FHIR-53669's Triaged punctuation cleanup on the id narrative remains a separate, not-yet-applied issue.
