FHIR-24625: Audit Measure term definition support

Issue request:
FHIR-24625 was a Published/Persuasive CQI change request for R5 asking Measure metadata definitions to separate the term from the definition, with a CodeableConcept for the term and markdown for the definition.

Initial application:
The issue was applied before this reconciliation. Commit 2df05d1471 replaced the old Measure.definition markdown element with the Measure.term backbone and Measure.term.code / Measure.term.definition children; commit 8f9dac369a migrated the exclusive-breastfeeding Measure example from definition to term; commit 0772d5ef85 added the measure-definition-example value set/code system binding for Measure.term.code; PR 2301 was merged by fb1432b692.

Additional context:
The current source/fhir.ini lists measure=Measure as an active resource, so source/measure/structuredefinition-Measure.xml is in the current build scope. Current source defines Measure.term as 0..* BackboneElement, Measure.term.code as 0..1 CodeableConcept bound to ValueSet/measure-definition-example, and Measure.term.definition as 0..1 markdown. The R5 published Measure profile has the same Measure.term surface and no Measure.definition element. Later FHIR-50265, in FHIR-qm, explicitly treats Measure.term as the R5 expression of the prior definition-term concept, and FHIR-55080 later references the same Measure.term.code binding without changing this structure.

AutoFHIR reconciliation:
This commit intentionally makes no source change because the current core source already satisfies the issue's requested capability through the R5/R6 Measure.term backbone and its code/definition children. Renaming the current element back to Measure.definition or adding duplicate prose would conflict with the already-published R5 shape rather than improve implementer understanding.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed for FHIR-24625; any separate rendering concern about experimental flags on example value sets should remain with the later terminology/tooling issue family, not this structural Measure change.
