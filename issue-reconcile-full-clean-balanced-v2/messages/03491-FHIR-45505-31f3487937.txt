FHIR-45505: Audit Specimen collection invariant

Issue request:
FHIR-45505 is an Applied/Persuasive R6 OO change request asking to add an invariant so Specimen.collection.collector and Specimen.collection.procedure are an either/or choice, avoiding confusion between collector and Specimen.collection.procedure.performer.actor. The Jira discussion also records that historic data does not always have either value, so the safe target is an at-most-one invariant rather than a requirement that one of the two elements be present.

Initial application:
The issue was applied before this reconciliation. Commit cb5d7e9998673ef06823f4105dc17d5957f92228 added the spm-1 constraint and conditions to source/specimen/structuredefinition-Specimen.xml, commit 9dbed689021fabf9292c22fa5803573779ae4420 moved the constraint into the Specimen root element, and merge commit e0be1749d4c6daa361c7f4d8c905965d99413744 brought PR #3106 into the main branch.

Additional context:
Specimen is an active current-build resource in source/fhir.ini. Earlier Published issue FHIR-31023 added Specimen.collection.procedure as a 0..1 Procedure reference, which is the element paired with collector by this invariant. OO minutes for 2024-05-06 record the same rationale: resolving the question of whether to allow both potential Practitioner references to be populated. No Zulip evidence or later source history was found that reverses or broadens the applied invariant.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The current active source already defines spm-1 with severity error and expression collection.collector.empty() or collection.procedure.empty(), and both Specimen.collection.collector and Specimen.collection.procedure carry condition spm-1. That implements the approved at-most-one rule while preserving 0..1 cardinality for both elements.

Recommendation:
Keep this audit commit as-is. Do not strengthen the invariant to require one of the two elements unless OO makes a later explicit decision, because the FHIR-45505 discussion noted that historic data can omit both.
