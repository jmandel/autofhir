FHIR-20409: Audit STU3 comparison link fix

Issue request:
FHIR-20409 was a Published/Persuasive FHIR-core technical correction, raised against STU3 and applied for R5, reporting that generated "compare to stu3" links on profiled Observation pages such as bp pointed at non-resolving URLs like http://hl7.org/fhir/STU3/bp instead of the resolving http://hl7.org/fhir/STU3/bp.html.

Initial application:
The Jira comment records R4 commit a00b4aa155 and R5 commit ed006b5. The R4 commit explicitly mentions GF#20409 and changed the old Java publisher's rellink handling so profile filenames without .html were emitted with .html, with matching validation for other page paths; ed006b5 carried the same publisher-side behavior forward for R5. Those Java publisher files are no longer present in this core source checkout, so there is no current source hunk to reapply.

Additional context:
The Observation resource and blood-pressure profile source remain in current build scope, but the current generated CI page for bp.html now compares against R4, R5, and the last ballot, and each rendered comparison href targets an .html page. A current source search found no generated or source link to the broken STU3/bp target; the remaining STU3 links in source are unrelated explicit .html links. FHIR-23032 was fixed by the same historical commits for datatype usage links and is already represented on the combined branch, so it is related evidence rather than a second decision here.

AutoFHIR reconciliation:
This audit intentionally makes no source change. The bad STU3 comparison URL was a historical generated-output problem fixed in the old publisher, and the current core build output for the active bp profile no longer reproduces it.

Recommendation:
