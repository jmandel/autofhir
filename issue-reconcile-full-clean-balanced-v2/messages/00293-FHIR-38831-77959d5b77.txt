FHIR-38831: Audit universal jurisdiction application

Issue request:
FHIR-38831 was Published/Persuasive with Modification for R5. It asked that FHIR-managed CodeSystem and ValueSet resources, later clarified as all canonical resources published in the base specification, explicitly carry the universal jurisdiction; the approved resolution was to update Kindling and ensure the package surface also had that jurisdiction.

Initial application:
The direct Jira-keyed implementation was in the external HL7/kindling repository, not in this FHIR source checkout. Kindling commit 813b2c0e53d6808a575c9efdfe29d8f201d6e463 added KindlingUtilities.makeUniversal(CanonicalResource), using M49 001/World when a canonical resource has no jurisdiction, and wired it into many canonical-resource generation paths. This FHIR checkout consumes Kindling through Gradle and is already on a later 1.25.5-SNAPSHOT dependency.

Additional context:
Terminology and FMG minutes confirm the issue was sent from Vocab to FMG and approved as persuasive with modification. No Zulip or broader Jira result was found that narrows or reverses the decision. Package-surface checks still found residual omissions in both R5 and current R6 packages: some are jurisdiction-specific examples where Kindling intentionally does not override an existing jurisdiction, but many current R6 canonical package resources have no jurisdiction at all, including active ValueSet and StructureDefinition artifacts. Several omissions are generated by Kindling rather than represented by a direct core source file.

AutoFHIR reconciliation:
This commit intentionally makes no source change. A direct core-source edit would only address part of the package surface and would not fix generated resources such as base CapabilityStatement and CompartmentDefinition artifacts; deciding whether to override example-specific jurisdictions or expand Kindling's package-generation policy needs human/editor review. The durable audit record captures the current state and points to the external build-tool follow-up.

Recommendation:
Keep this human-review audit commit and follow up in HL7/kindling/publisher generation. The next fix should add universal jurisdiction consistently for canonical resources that have no jurisdiction during package generation, then explicitly decide whether existing non-universal example jurisdictions are exceptions or should be augmented with universal jurisdiction as well.
