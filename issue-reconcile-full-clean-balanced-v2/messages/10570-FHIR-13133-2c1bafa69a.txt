FHIR-13133: Audit extension definition availability

Issue request:
FHIR-13133 was Published/Persuasive with Modification for FHIR-core. It asked that extension StructureDefinitions be made available to consumers of instances; the final resolution kept this as SHOULD-level guidance and named direct canonical URL resolvability and/or publication in a known available registry as preferred mechanisms.

Initial application:
The issue was applied by SVN revision 12861, represented in git as b5453f3f590385139315826a806e7f976349715c (#13133 - clarify about extensions). That commit changed source/extensibility.html to add the current list item saying the structure definitions for the extension SHOULD be available to consumers and listing canonical URL resolvability or registry publication as preferred approaches.

Additional context:
The relevant extensibility pages are in the current build scope: source/fhir.ini maps the Extension type page to extensibility.html, and source/hierarchy.xml includes Extensibility and Defining Extensions in the active navigation. Current source/extensibility.html still contains the FHIR-13133 wording. Later FHIR-16989 clarified publishing versus registry advertising on source/defining-extensions.html and is already represented on the combined branch; that later guidance is compatible with FHIR-13133 because it explains publication mechanics and registry optionality rather than removing the availability expectation. Bounded Jira, Zulip, and Confluence searches found no later decision or community record that conflicts with leaving the current wording in place.
