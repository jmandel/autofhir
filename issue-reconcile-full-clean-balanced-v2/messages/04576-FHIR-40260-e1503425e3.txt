FHIR-40260: Audit Meta.lastUpdated population guidance

Issue request:
FHIR-40260 was a Published/Persuasive with Modification FHIR-core BaseResource change request for Meta.lastUpdated. The issue identified inconsistent guidance between the element definition saying the value was always populated except during first create and the Resource metadata REST guidance saying servers SHALL update it on create, update, patch, or other operations that impact meta. The voted resolution replaced the old element comment with guidance that Meta.lastUpdated is generally omitted in submitted PUT/POST instances and populated in response/retrieval instances.

Initial application:
The issue was initially applied in source/datatypes/meta.xml by commit 8d6fa98e95, which removed the exact phrase "This value is always populated except when the resource is first being created" and inserted the resolved PUT/POST and response/GET wording. No prior Issue-Reconcile-Key commit for FHIR-40260 was present on the combined branch.

Additional context:
Meta is an active normative datatype in source/fhir.ini, so source/datatypes/meta.xml is in current build scope. Later same-element work, especially FHIR-45047 and its reconciliation commit 6f66087a12, refined the same Meta.lastUpdated comments to say the server might populate it when data is received or when crafting a response instance, and added guidance about lastUpdated being out of sync with visible resource changes. That later final work preserves FHIR-40260's core clarification while superseding the exact original replacement sentence. The Resource metadata narrative still contains the REST server-update rule that prompted the clarification, and that is not inconsistent with the current element comment because the current comment no longer says the value must already be populated in create submissions.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current authoritative Meta.lastUpdated source already resolves the seed inconsistency. Reverting to the exact 2023 replacement text would discard later approved clarification, and duplicating the guidance elsewhere would not improve implementer understanding.

Recommendation:
Keep this no-change audit as the FHIR-40260 reconciliation. Future edits to Meta.lastUpdated should use later focused issues such as FHIR-45047 or successor work rather than reopening the already-applied FHIR-40260 wording replacement.
