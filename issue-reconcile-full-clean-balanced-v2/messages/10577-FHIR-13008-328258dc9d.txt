FHIR-13008: Audit external tooling ecosystem hosting

Issue request:
FHIR-13008 was a Published FHIR-core/FHIR-I change request, resolved Persuasive/auto-approved, asking that links for reference implementations, profile authoring tools, testing tools, public test servers, and related implementation-support resources be hosted on the implementer-facing FHIR.org site rather than maintained only on the HL7 wiki. The issue followed the earlier FHIR-11456 tooling-list cleanup and was applied for DSTU2.

Initial application:
There is no Jira-keyed source commit for FHIR-13008. The related FHIR-11456 implementation in commit 90e59bfb0f984989959713200d072f2e7bbf2621 / SVN r11583 removed inline profiling and testing tool tables from source/implsupport-module.html and linked to HL7 wiki category pages; FHIR-11456's comments explicitly say that moving those wiki entries to FHIR.org was too hard at the time and that a new tracker was created for that later work. FHIR-13008's own comment records that Lloyd created the tooling ecosystem page on the wiki, which appears to be how the published tracker was considered applied.

Additional context:
source/implsupport-module.html is still in current build scope through source/hierarchy.xml and source/modules-list.html. Later source history migrated the wiki links to HL7 Confluence and removed remaining inline reference-server and library tables, so the built core specification now points to maintained Confluence lists for public test servers, open source implementations, profile tooling, and testing platforms instead of maintaining individual lists in the spec. Zulip discussion from September 2017 confirms the FHIR Tooling Ecosystem page was launched as a wiki page and was explicitly incomplete/straw-model community content. Exact-key community searches found no later FHIR-13008-specific decision that requires a current core source edit, and obvious FHIR.org /tools or /ecosystem targets are not present.

AutoFHIR reconciliation:
This commit intentionally makes no source change and records the issue as external-repo. The remaining literal request -- hosting and community-maintenance workflow for the tooling ecosystem on FHIR.org -- belongs to the FHIR.org/FHIR Foundation site-content process rather than this FHIR core specification checkout. Changing the current core page from working Confluence links to a non-existent FHIR.org tools/ecosystem page would make the specification less useful.

Recommendation:
Keep this audit commit as-is for the core spec. If HL7 still wants the tooling ecosystem hosted directly on FHIR.org, create or update the maintained FHIR.org site content first, then make a separate core-source link update only after there is a stable target that replaces the Confluence pages.
