FHIR-30433: Audit PlanDefinition REST action guidance

Issue request:
FHIR-30433 was an Applied/Persuasive with Modification CDS issue asking how a PlanDefinition action should refer to FHIR REST interactions such as Patient create or update. The resolved intent was that the action should not invent implicit Patient/$create or Patient/$update OperationDefinitions; the operation inputs and resource body drive the concrete URL, and PlanDefinition/CDS documentation should explain the supported mechanism.

Initial application:
The applied source change was commit bedab38b5c, merged by HL7/fhir#3914 for R6. It added guidance to source/clinicalreasoning-knowledge-artifact-representation.html explaining that create/update/remove PlanDefinition actions realized by PlanDefinition/$apply return proposal resources, and that a client application can apply those proposals as RESTful API calls. The adjacent FHIR-30209 commit in the same PR added the update-action example that the new paragraph qualifies.

Additional context:
The linked Zulip question asked whether a PlanDefinition action should use an implied OperationDefinition URL or the RESTful interaction code-system fragment URL. FHIR-I minutes recorded the decision to document this in PlanDefinition and reassign to CDS. The current source keeps the REST interaction CodeSystem in build scope and the Clinical Reasoning/PlanDefinition guidance page is in hierarchy.xml, so the applied page is part of the current build. The later Jira application comment narrows the implementation to an application capability: actions can already indicate create/update/delete or use OperationDefinition for operations.

AutoFHIR reconciliation:
No source change was made. The current built source already carries the applied CDS wording that distinguishes PlanDefinition/$apply proposals from the client application step that turns those proposals into RESTful API calls. Adding a separate URL+code restatement now would be redundant at best and could diverge from the final applied comment, which intentionally documents the behavior as an application-provided automation feature.

Recommendation:
Keep this audit commit as-is. Revisit only if CDS explicitly wants new normative guidance that PlanDefinition action coding should use http://hl7.org/fhir/restful-interaction codes directly; that would be a new or clarified work-group decision beyond the applied R6 text.
