FHIR-6108: Audit REST create/update id handling

Issue request:
FHIR-6108 was Published/Persuasive with Modification for the FHIR-core HTTP page. It asked the RESTful API text to clarify server behavior, HTTP status, response body, and OperationOutcome guidance when create is submitted with an id and update is submitted without the required id.

Initial application:
The issue was applied by svn revision 6373, now git commit 3ef34e803fc9ec8688a0d3612f3583d349bf134f, which added HTTP 400 and OperationOutcome guidance to both the update and create sections of source/http.html.

Additional context:
A later Published/Persuasive with Modification decision, FHIR-9102, changed the POST/create rule: commit 28ccbf99f4e46e92a3f110ad1d06bd715ce95a56 replaced the create-with-id error rule with the current requirement that servers SHALL ignore ids supplied on POST. Later conditional-update issues FHIR-17906 and FHIR-20390 clarified Resource.id handling for conditional update without changing the direct PUT requirement checked for this seed.

AutoFHIR reconciliation:
No source change is needed. The authoritative RESTful API source page still says a direct update body SHALL include an id matching the URL id, and that a missing or mismatched id gets HTTP 400 with an OperationOutcome recommended. The create section intentionally follows the later FHIR-9102 rule by ignoring supplied ids, and nearby create error text already recommends OperationOutcome bodies for invalid or rejected creates.

Recommendation:
Keep this empty audit commit. Do not restore the old create-with-id 400 behavior from FHIR-6108 because it was superseded by FHIR-9102; the current update-without-id wording already satisfies the remaining applicable part of the seed.
