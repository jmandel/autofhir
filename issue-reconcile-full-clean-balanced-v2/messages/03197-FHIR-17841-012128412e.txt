FHIR-17841: Audit Medication identifier application

Issue request:
FHIR-17841 was Published/Persuasive with Modification for STU3. It asked to add Medication.identifier with cardinality 0..* and datatype Identifier, remove Medication.batch.serialNumber, and clarify that serial numbers would be represented through an identifier.

Initial application:
The historical source commit f854395eff ("GF 17841 - add identifier to Medication") applied the request in the then-active Medication spreadsheet by adding Medication.identifier 0..* Identifier, deleting Medication.batch.serialNumber, and changing the search parameter from serial-number on Medication.batch.serialNumber to identifier on Medication.identifier. No prior Issue-Reconcile-Key commit for FHIR-17841 was found on the combined branch.

Additional context:
Medication is an active current-build resource in source/fhir.ini. The current XML source has Medication.identifier 0..* Identifier, has no Medication.batch.serialNumber element, and has an identifier search parameter on Medication.identifier. Later FHIR-47622 changed the interpretation of medication serial numbers for R6: physical-instance identifiers such as serial numbers now belong in Medication.instance.identifier, while Medication.identifier remains the medication business identifier. That later issue is already represented on the combined branch by commit 6b4f960128, so FHIR-17841 should not reintroduce or duplicate any serial-number source change.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active Medication source already preserves the FHIR-17841 structural change, and the only semantic refinement since then is the later applied FHIR-47622 split between medication business identifiers and physical-instance identifiers.

Recommendation:
Keep this audit commit as-is. No FHIR-core follow-up is needed for FHIR-17841 unless Pharmacy reopens the broader kind-versus-instance modeling question; any serial-number behavior should be evaluated under the later FHIR-47622 lineage rather than this STU3 tracker.
