FHIR-16329: Audit format error status guidance

Issue request:
FHIR-16329 was a Published/Persuasive STU3 FHIR-core formats issue. It asked that the wire-format guidance use 406 Not Acceptable, not 415 Unsupported Media Type, when a server cannot return a CapabilityStatement in the requested response format, and that the page distinguish unsupported response formats from unsupported submitted request-body formats.

Initial application:
The issue was applied in SVN revision 13991, imported as git commit 8b0d067ddf9e780da3ade80fb764d6d5ce095b19, which changed source/formats.html to return 406 for unsupported CapabilityStatement response formats and added the Accept-header versus posted-format 406/415 distinction. The later FHIR-18448 refactor in fb6236f76aef7e34c5874572f098f3a646dcc983 moved the wire-format section from source/formats.html to source/resource-formats.html while preserving the FHIR-16329 wording.

Additional context:
The current source no longer keeps the wire-format section in source/formats.html; source/resource-formats.html is the active Resource Formats page, is linked from source/documentation.html, and still carries the wire anchor. The RESTful API content-type section also states the general Accept-header 406 and submitted-format 415 rule. Targeted Jira, Zulip, and Confluence searches found no later directly relevant decision that reverses or narrows FHIR-16329.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build source already gives 406 for unsupported requested response formats and describes 415 for unsupported client-submitted formats, so the published issue is reconciled by preserving the existing source.
