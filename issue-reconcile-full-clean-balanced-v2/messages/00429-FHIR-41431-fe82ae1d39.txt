FHIR-41431: Audit inferSystem on ValueSet validate-code

Issue request:
FHIR-41431 was an Applied FHIR-core Vocabulary change request for R6 to document the formerly undocumented terminology-server parameter described in the issue title as implySystem. The final Persuasive with Modification resolution renamed the parameter to inferSystem, made it an optional boolean input on ValueSet $validate-code, limited it to use with the code parameter rather than coding or codeableConcept, and added operation-description text saying that when a code is provided either system or inferSystem SHOULD be provided.

Initial application:
The issue was applied by git commit b164dc66088d2bd560695ca63742ba8400ed99d5 on 2023-07-13. That commit edited source/valueset/operationdefinition-ValueSet-validate-code.xml to add the inferSystem input parameter and the requested description sentence. Later ValueSet $validate-code work touched the same OperationDefinition, but the inferSystem parameter and the description sentence remain present in the current source.

Additional context:
source/fhir.ini lists valueset=ValueSet as an active resource, and source/valueset/list-ValueSet-operations.xml references OperationDefinition/ValueSet-validate-code, so the checked source is in the current build path. Terminology Infrastructure minutes from 2023-06-26 record the original implySystem motivation and ambiguity error behavior; the 2023-07-06 and 2023-07-20 minutes record the final inferSystem limitation to the code parameter and mark the tracker item done. A later 2025 Zulip thread discusses inferSystem semantics and led to FHIR-53532 in FHIR-cql, but it does not require changing the current FHIR-core ValueSet operation definition.
