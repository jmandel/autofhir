FHIR-13186: Clarify wildcard Accept handling

Issue request:
FHIR-13186 was a Published/Persuasive with Modification FHIR-core HTTP change request asking the mime-type section to clarify whether a client may send an Accept header of */*. The approved resolution was to document that servers are encouraged to support it and return JSON or XML at their discretion.

Initial application:
No git commit that touched source/http.html explicitly mentions FHIR-13186. The page had related generic Accept-header guidance from earlier/later mime-type issues, including #10200/FHIR-9029 and FHIR-25200, but current source did not mention */* anywhere in the HTTP mime-type guidance.

Additional context:
The relevant source is the tracked top-level HTTP page, source/http.html, which corresponds to the Jira related page and rendered http.html#mime-type section. Later FHIR-9029 and FHIR-25200 history kept two parallel generic Accept-header notes on this page, so both notes needed the wildcard clarification to avoid leaving inconsistent guidance.

AutoFHIR reconciliation:
Updated source/http.html in the Content Types and encodings implementation notes and the matching _format/return-content implementation notes to say that non-Binary resources SHOULD support Accept: */* and may choose JSON or XML for the response at the server's discretion.

Recommendation:
Keep this source-changing commit. It directly applies the published clarification without broadening Binary-specific behavior or changing unrelated content negotiation rules.
