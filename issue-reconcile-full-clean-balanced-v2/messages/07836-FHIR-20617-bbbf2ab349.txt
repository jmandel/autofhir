FHIR-20617: Audit CapabilityStatement format binding

Issue request:
FHIR-20617 was a Published/Persuasive with Modification FHIR-core Conformance issue raised against STU3 and applied for R5. It reported that CapabilityStatement.format was required-bound to MimeType while the element also allowed `xml`, `json`, and `ttl`, which were not in that value set. The accepted resolution was to use a more accurate CapabilityStatement format value set containing the simple FHIR format codes and FHIR media types, with a MIME-type maximum binding, without preventing other MIME types or defining legacy MIME types.

Initial application:
The issue was explicitly applied in git commit b4cf3227e2307b020adaf94603f563b6a8fe777b, which added source/capabilitystatement/valueset-capability-format-type.xml and changed CapabilityStatement.format from a required ValueSet/mimetypes binding to an extensible ValueSet/capability-format-type binding with elementdefinition-maxValueSet pointing to ValueSet/mimetypes. A later generic additional-binding rework in ba6dd4995575f6af4f7f38c23835ffdbb250256d converted that shape to a required ValueSet/mimetypes binding plus an additional starter binding to ValueSet/capability-format-type.

Additional context:
FHIR-48679 later revisited the same invalid MIME-type family, explicitly citing FHIR-20617. Its Applied/Persuasive resolution created ValueSet/supplemented-mimetypes, including BCP-13 MIME types plus `xml`, `json`, and `ttl`, and changed CapabilityStatement.format to require that supplemented set while keeping ValueSet/capability-format-type as the starter binding. FHIR-55152 was later Resolved - No Change for an escape-valve request because the current codes include all MIME types. FHIR-17356 also corrected the starter Turtle media type to application/fhir+turtle rather than the older application/fhir+ttl spelling.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current build-scope source/fhir.ini registers CapabilityStatement, simple-format-codes, mimetypes, and supplemented-mimetypes. Current CapabilityStatement.format is required-bound to ValueSet/supplemented-mimetypes, whose active source includes all BCP-13 MIME types plus the active simple-format-codes CodeSystem, and it still carries the additional starter binding to ValueSet/capability-format-type for the common FHIR formats. That current representation preserves FHIR-20617's semantic intent while incorporating later FHIR-48679 and FHIR-17356 corrections.

Recommendation:
Keep this audit commit as-is. Do not revert the binding to the older extensible-plus-maxValueSet shape; the current supplemented required binding is the later approved technical correction for the same problem. Any future change to narrow or broaden CapabilityStatement.format should be handled as a new FHIR-I decision.
