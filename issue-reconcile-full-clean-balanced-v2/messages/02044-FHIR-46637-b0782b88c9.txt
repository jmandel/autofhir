FHIR-46637: Audit Relevant History profile ownership

Issue request:
FHIR-46637 was Applied/Persuasive for R6 and asked that the provenance-relevant-history profile, which supports Request/Event relevantHistory guidance, be owned and maintained by FHIR Infrastructure rather than Security. The resolution accepted transfer to FHIR-Infrastructure as custodian and planned R6 review.

Initial application:
No source commit explicitly mentions FHIR-46637. The ownership concern was already substantially applied earlier: git 6c16d55195 changed source/provenance/structuredefinition-profile-provenance-relevant-history.xml from structuredefinition-wg sec to fhir while applying FHIR-38005, and the current source retains that fhir workgroup code and FHIR-I contact. The earlier same-family FHIR-27794 also established that the profile should be owned by FHIR-I and explain its use case.

Additional context:
The profile is in build scope because source/fhir.ini actively registers the Provenance resource folder, and source/fhir.ini maps the fhir workgroup code to FHIR Infrastructure. The public current build renders provenance-relevant-history.html with FHIR Infrastructure as the Work Group; its Security breadcrumb reflects the base Provenance resource/module, not the profile custodian. Later FHIR-48828 performed the R6 core-profile review, retained provenance-relevant-history, and changed it to informative with the clarified description now present in source.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current profile metadata already names FHIR Infrastructure as custodian, the profile remains retained after R6 review, and the current rendered page exposes the intended work group.

Recommendation:
Keep this audit commit as-is. Future changes to whether this profile remains in core or how its guidance is presented should follow the broader FHIR-48828 profile-governance family rather than reopen the ownership transfer.
