FHIR-13631: Audit corrected evaluate-measure example

Issue request:
FHIR-13631 was Published/Persuasive for STU3 and reported that the $evaluate-measure example `GET [base]/Measure/CMS146/$evaluate-measure?patient-124&periodStart=2014-01&periodend=2014-03` was incorrect because `patient-124` was not a valid parameter form and the intended patient reference needed to be represented correctly. The resolution agreed that the example was incorrect and would be fixed.

Initial application:
The Jira comment says the issue was applied at SVN 12641. In the Git mirror, commit 734c7befc75fc6677ab2dbae8d77bdc07428cc5b corresponds to SVN 12641 and changed the invalid example from `patient-124` to `subject=124` as part of the broader Measure/MeasureReport patient-to-subject generalization. That initial application removed the original invalid parameter token but still left an underspecified subject reference and lower-case `periodend` in the historical request text.

Additional context:
Measure is an active resource in the current build, and source/measure/list-Measure-operations.xml still includes the retired Measure-evaluate-measure OperationDefinition, so the retained example files remain relevant current source. Later FHIR-45727, already represented on the combined branch, corrected the same patient-specific example family by splitting summary and individual examples and requiring `subject=Patient/124`; the current combined-branch reconciliation for FHIR-45727 also fixed the remaining `periodEnd` casing and narrative duplicate. The successor Measure `$evaluate` operation and the Quality Reporting narrative now use the same corrected reference form. Zulip and Confluence searches found no contrary community evidence for FHIR-13631.
