FHIR-43690: Audit dom-3 invariant simplification

Issue request:
FHIR-43690 was an Applied FHIR-I change request, resolved Persuasive with Modification for R6, asking to fix the DomainResource dom-3 invariant because the old FHIRPath expression duplicated the canonical check, omitted uri/url checks in the contained-resource back-reference half, and was inefficient.

Initial application:
The issue was applied before this reconciliation by git commit 86ddd389b9c7690e89ddc061f23f3e6fa09333b6, which changed source/domainresource/structuredefinition-DomainResource.xml from the duplicated ofType(canonical) expression to the approved select(reference | as(uri)) and reference='#' | as(uri)='#' expression. The combined branch did not already contain an Issue-Reconcile-Key commit for FHIR-43690.

Additional context:
DomainResource is an active build artifact: source/fhir.ini lists domainresource under resource-infrastructure and in the active resources/workgroup configuration. FHIR-I minutes on 2024-12-16 recorded concern that the proposed expression still needed to cover the "shall refer to the containing resource" half of dom-3, the linked Zulip review concluded canonical and url are subtypes of uri, and FHIR-I minutes on 2025-01-06 recorded the final persuasive vote. The current combined branch source contains the same expression as the Jira resolution.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current DomainResource source already implements the final approved expression, including the simplified uri subtype handling and the contained-resource reference-to-container test.

Recommendation:
Keep this audit commit as-is. No further core source work is recommended unless a future FHIRPath type-system decision changes the interpretation of as(uri) for canonical/url subtypes.
