FHIR-34345: Audit contained-resource history guidance

Issue request:
FHIR-34345 was a Published/Persuasive FHIR-I clarification asking whether contained resources can have history and whether references to contained resources may include /_history. The approved resolution was to clarify that a reference may target a contained resource inside a specific version of the containing resource using [type]/[id]/_history/[version]#[containedId], but may not target a version of the contained resource itself, and that contained-resource references back to the container or its contained resources must be local fragment references.

Initial application:
The issue was explicitly applied in git commit 8db7158a9c0541db6f76f31b0a952c415e2c67f2, which added contained-resource history and local-reference bullets to source/references.html. Later source maintenance fixed the original typo in "history" without changing the substance.

Additional context:
The affected file is the FHIR core references page identified by Jira's FHIR-core-references related page and is active in the build through source/fhir.ini entries for the Reference and CodeableReference pages. Current source/references.html states both required rules: [type]/[id]/_history/[version]#[containedId] is allowed, [type]/[id]#[containedId]/_history/[version] is invalid, and contained resources must use local fragment references when pointing at their container or sibling contained resources. Related FHIR-34405 separately confirms the reference regex permits the same history-then-fragment shape. Zulip and Confluence searches found no conflicting later decision.

Recommendation:
Keep this audit commit as-is. No follow-up is needed unless the work group later reopens contained-resource reference semantics; the current source matches the published Jira decision.
