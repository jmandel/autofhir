FHIR-5513: Audit ValueSet validate-code rename

Issue request:
FHIR-5513 was a Published/Persuasive FHIR-core BaseResource correction raised for DSTU1. It reported that ValueSet `$validate` URLs overlapped Resource `$validate` URLs while meaning terminology code validation rather than resource validation, and the approved resolution was to add an error check and rename the ValueSet operation to `$validate-code`.

Initial application:
The issue was applied in git-svn commit e967b66272a8b4598ddc8bc818d20f283c2d8500, whose message cites `#5513 - catch and fix duplicate operation names` and SVN revision 4548. That commit renamed the ValueSet operation spreadsheet rows from `validate.*` to `validate-code.*` and added an old build-time duplicate operation-name check. The later 2021 source rework moved the operation from the spreadsheet into the current XML OperationDefinition without reverting the name.

Additional context:
The current build-scoped ValueSet resource is active in `source/fhir.ini`, its operations list references `OperationDefinition/ValueSet-validate-code`, and the ValueSet OperationDefinition has id `ValueSet-validate-code` and code `validate-code`. The Resource validation operation remains a separate `Resource-validate` operation with code `validate`. The old Java build validator changed by SVN revision 4548 is not present in the current spec checkout after tooling/source refactors, so this reconciliation is limited to the current FHIR source surface.

AutoFHIR reconciliation:
No source change was made. The current source already resolves the ambiguity by using `$validate-code` for ValueSet code validation and `$validate` for resource validation, and searches did not find a remaining build-scoped `ValueSet-validate` operation definition or directly conflicting community evidence.

Recommendation:
Keep this audit commit as-is. No core spec source follow-up is needed for FHIR-5513; any future desire for duplicate operation-name validation should be handled in the current publisher/tooling repository rather than by changing the FHIR source checkout.
