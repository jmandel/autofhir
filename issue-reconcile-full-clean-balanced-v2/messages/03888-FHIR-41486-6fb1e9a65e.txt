FHIR-41486: Drop stale ElementDefinition-de profile row

Issue request:
FHIR-41486 is Applied/Persuasive for R6 and asks to remove the legacy ElementDefinition-de profile because FMG did not know why it existed, found no known users, and SDC was not interested in it.

Initial application:
The Jira-tagged implementation commit 12ea0250a5ff1cf459dc5f7b847f17103663c513 deleted source/datatypes/elementdefinition-dataelement-profile-spreadsheet.xml and removed the active elementdefinition-de entry from source/fhir.ini [profiles]. The current combined branch contains that commit, the old profile source file is absent, and source/fhir.ini no longer has an active elementdefinition-de profile entry.

Additional context:
FMG minutes from 2023-06-21 record that the ElementDefinition-de/DataElement-derived profile could go away and that Grahame filed FHIR-41486. FHIR-I minutes from the 2024-02-01 WGM record the Persuasive 19-0-0 vote. Historical FHIR-12903 had asked to use this profile with DataElement but was withdrawn because DataElement no longer exists. A later Zulip thread about core profile maturity noticed elementdefinition-de as an odd non-zero-FMM core profile and did not identify a current need to keep it.

AutoFHIR reconciliation:
ElementDefinition is an active datatype in source/fhir.ini, so source/datatypes/elementdefinition.xml is build-scope source. Its Profiles worksheet still contained a stale ElementDefinition DataElement row pointing at the deleted elementdefinition-dataelement-profile-spreadsheet.xml and output elementdefinition-de.xml. This commit removes that row and adjusts the worksheet row count, leaving the remaining ElementDefinition profile rows contiguous.

Recommendation:
Keep this source fix as-is. It completes the already-applied removal in core source and avoids leaving an active spreadsheet reference to a deleted profile source. No separate action is needed for FHIR-12903 because it is already Resolved - No Change/Retracted and only explains the profile's obsolete DataElement origin.
