FHIR-44614: Audit cross-version equivalent-element guidance

Issue request:
FHIR-44614 was an Applied/Persuasive with Modification FHIR-core compatibility clarification for R6. It asked to replace the old guidance, "Implementations should always use the correct element for data when one exists," with a SHALL-level rule to use the equivalent element when one exists and to use cross-version extensions only for elements that do not exist, element types that do not exist, or max cardinality changes from 1 to *.

Initial application:
No git commit explicitly names FHIR-44614. Commit 643dba42aa5d9eb8324e1390b7b194f737913bc5, made the day after the 2024-01-30 FHIR-I vote, changed source/versions.html from the old "should always use the correct element" sentence to the requested SHALL/equivalent-element wording and the three allowed cross-version extension cases. The Jira was later commented with HL7/fhir#3967, which merged the R6 ticket branch that included subsequent cross-version documentation cleanup.

Additional context:
PR HL7/fhir#3967 merged on 2025-11-09. Its commit f45505e5b3aa0d87effb991938750e627b782d2d intentionally pulled detailed cross-version content out of the core versions page and pointed readers to the individual cross-version definition packages. On the current combined branch, source/versions.html still defines the cross-version package URL pattern, says extensions are only defined when the target version has no way to represent the data, and lists the concrete cases of missing elements, missing types, and max cardinality changes from 1 to *. The same combined branch already contains related audits/fixes for FHIR-44615 and FHIR-42924.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build-scope core compatibility source no longer contains the obsolete "should always use the correct element" sentence, and its remaining concise package-oriented text preserves the substance of FHIR-44614 without reintroducing duplicated detailed guidance that later work moved to the cross-version package guides.

Recommendation:
Keep this audit commit as-is. No further core source change is needed for FHIR-44614 unless the work group decides to duplicate detailed package-guide rules back into source/versions.html; defects in individual cross-version package definitions should be handled in the relevant xver package or a targeted issue.
