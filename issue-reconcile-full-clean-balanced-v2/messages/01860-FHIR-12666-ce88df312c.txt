FHIR-12666: Restore Consent V2 mapping coverage

Issue request:
FHIR-12666 was a Published/Persuasive CBCC change request for FHIR-core Consent asking to add HL7 V2 CON segment mappings. The resolution mapped Consent category/scope to CON-2 with V2 table HL70496/0496 support, policy/policyRule to CON-3, identifier to CON-4, status to CON-11, dateTime to CON-13, provision.period to CON-14/15, performer to CON-24/25, and source[x] to the remaining consent text/background fields.

Initial application:
The issue was initially applied by git commit 2da480ca699986fa93ba5f234dc5b055146d8144 in the old Consent spreadsheet. Subsequent source conversion preserved many mappings in source/consent/structuredefinition-Consent.xml, including identifier, status, category, date, regulatoryBasis, provision.period, sourceAttachment, and sourceReference. Later refactors changed the relevant element model: FHIR-31903 removed Consent.scope and merged scope into Consent.category, FHIR-32817 split policy/policyRule into regulatoryBasis/policyBasis/policyText, and commit 632f4b84972d170c0dfe48c80a7f7afad35c7c66 split performer into grantor/grantee while dropping the CON-24/25 mapping.

Additional context:
Consent is active in source/fhir.ini, and the current R4/R6 map notes show the old issue-era elements were renamed or split: dateTime to date, policy to policyBasis, policyRule to policyText, scope into category, source[x] into sourceAttachment/sourceReference, and performer into current actor elements. Community searches for FHIR-12666 and Consent CON mapping found no directly relevant Zulip or Confluence evidence that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit updates the active Consent StructureDefinition source to preserve the applied V2 mapping intent after later refactors: Consent.category now retains the scope-derivation note for CON-2, Consent.grantor carries the CON-24/25 consenter mapping, and Consent.policyBasis plus Consent.policyText carry the CON-3 policy/form mapping alongside the existing regulatoryBasis map. It also updates the active consent category example value set to include http://terminology.hl7.org/ValueSet/v2-0496 and describe that V2 table 0496 is part of the included Consent Type examples.

Recommendation:
Keep this commit as-is. It restores missing applied mapping content in current build-scope source without reopening later Consent model decisions; no related issue needs a separate reconciliation commit from this investigation.
