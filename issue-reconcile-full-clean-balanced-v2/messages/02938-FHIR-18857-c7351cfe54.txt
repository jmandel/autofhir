FHIR-18857: Audit FamilyMemberHistory death contribution

Issue request:
FHIR-18857 was a Published / Persuasive with Modification STU3 Patient Care request to revamp FamilyMemberHistory.condition by adding FamilyMemberHistory.condition.contributedToDeath 0..1 boolean, deleting the old FamilyMemberHistory.condition comment that inferred absence of cause-of-death from outcome, and updating FamilyMemberHistory.condition.outcome to say it indicates what happened following the condition and that death timing is captured on the relation.

Initial application:
The Jira comment identifies commit 04c4d675c5f4, whose subject explicitly cites GF#18857 and whose FamilyMemberHistory example adds condition.contributedToDeath. The older spreadsheet source changed in that same commit, and the 2021 source rework commit 33b409a4b6d5 carried the approved outcome definition and condition.contributedToDeath element into the current StructureDefinition source.

Additional context:
FamilyMemberHistory is an active core resource in source/fhir.ini, so source/familymemberhistory/structuredefinition-FamilyMemberHistory.xml is in current build scope. FHIR-17808 later reused the same outcome/contributedToDeath pattern for FamilyMemberHistory.procedure, while FHIR-47829 later added summary flags to condition and condition.code without changing the death-contribution semantics. A 2025 implementers Zulip thread shows ongoing implementer questions about outcome versus contributedToDeath, but no final Jira or work-group decision found in this investigation reverses or narrows FHIR-18857.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already has FamilyMemberHistory.condition.outcome with the approved definition, FamilyMemberHistory.condition.contributedToDeath as a 0..1 boolean, an example instance using contributedToDeath, and no remaining old FamilyMemberHistory.condition comment about unspecified outcomes implying no primary cause of death. The current definition says the unknown state follows from contributedToDeath being absent; that corrects the Jira resolution's apparent element-name typo without changing the approved meaning.

Recommendation:
Keep this audit commit as-is. Do not add redundant core wording for FHIR-18857 unless Patient Care opens a new issue to clarify the relationship between outcome and contributedToDeath for implementers.
