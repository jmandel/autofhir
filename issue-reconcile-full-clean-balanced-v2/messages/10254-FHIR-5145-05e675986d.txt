FHIR-5145: Audit resource representation wording

Issue request:
FHIR-5145 was a Published/Persuasive DSTU1 ballot clarification for the Base Resource page. The issue asked to remove wording that made validity ambiguous for non-XML/non-JSON resource representations, and to add a note under the formats header that other representations are allowed but not described by the specification.

Initial application:
The issue was applied in git-svn revision 4577, now commit 7b95c3da0c57f5a0f27e6c9191b30dbf724f68a6, whose message references #5145. That commit removed the ambiguous Resource introduction sentence saying a resource was valid if represented in XML or JSON, replaced it with a simple multiple-representations link, and added the requested other-representations note to the formats page.

Additional context:
The Resource formats material was later split from source/formats.html into source/resource-formats.html by FHIR-18448, and FHIR-21452 moved the other-representations note from the general Resource Definitions page to the new Resource Formats page. Current source/fhir.ini keeps Resource in the active resource-infrastructure list, and source/hierarchy.xml lists resource-formats.html as the Resource Formats page. Community searches found no FHIR-5145-specific Zulip or Confluence decision that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source changes. The current Resource introduction only says that resources have multiple representations and links to resource-formats.html, while source/resource-formats.html states that JSON, XML, and RDF are defined exchange representations and that other representations are allowed but not described by this specification. The ambiguous validity wording requested for deletion is absent from current source.

Recommendation:
Keep this audit commit as-is. No current core source change is needed unless a future work group decision wants to change the broader policy for non-standard resource representations.
