FHIR-12402: Audit Timing code bounds clarification

Issue request:
FHIR-12402 was a Published/Persuasive FHIR-core datatypes change request from the DSTU2 cycle. It asked how to express a Timing code such as BID together with start and stop bounds, and the accepted resolution was to document that repeat.bounds still applies while the rest of repeat is an equivalent representation of the code that may be ignored or processed instead of the code.

Initial application:
The issue appears to have been applied by svn revision 11150, now git commit 238d8f7725591c1b0622e20dd50e36395feb3197, which changed source/datatypes/timing.sheet.txt and source/datatypes/timing.xml to add the repeat.bounds exception to the Timing.code definition. The old sheet text was later removed, but the active source/datatypes/timing.xml still carries the applied wording.

Additional context:
Timing is in the active datatype list and datatype page mapping in source/fhir.ini, is marked normative, and uses the active abbreviation tim. Bounded searches for later Jira, Zulip, and Confluence evidence found no directly relevant conflicting decision; the Jira concept hits were about adding a Quantity-style bounds option or medication examples rather than changing the relationship between Timing.code and Timing.repeat.bounds.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current Timing.code definition says that either the code or structured data may be used to interpret the Timing, "with the exception that .repeat.bounds still applies over the code (and is not contained in the code)," which satisfies the FHIR-12402 resolution in the current build source.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed unless MnM later chooses to reword the already-applied Timing.code definition.
