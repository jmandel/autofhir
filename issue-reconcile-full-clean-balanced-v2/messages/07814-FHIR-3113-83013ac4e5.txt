The approved Phoenix WGM resolution was to leave clinicalNotes as-is and add SupportingInformation 0..* referencing Observation and Condition.

Initial application:
The original source application is commit 559fc97f010d1d5bce29b28f0023788f30f723d7, which added DiagnosticOrder.supportingInformation 0..* Resource(Observation|Condition) and tagged the spreadsheet row with [#3113]. The current ServiceRequest source still carries the #3113 committee-note lineage on ServiceRequest.supportingInfo.

Additional context:
Later request-pattern and resource-merge work renamed supportingInformation to supportingInfo and carried DiagnosticRequest/ProcedureRequest into active ServiceRequest. source/fhir.ini lists ServiceRequest as an active approved resource and records DiagnosticOrder as subsumed into ServiceRequest. Related same-element decisions broadened and clarified the element: FHIR-3739 added DocumentReference, FHIR-7135 clarified that AOEs and discrete observations are supporting information, FHIR-37355 changed ServiceRequest.supportingInfo from Reference(Resource) to CodeableReference(Resource), and FHIR-31589 clarified that supportingInfo is existing clinical context while orderDetail is used for instructions/questions to be performed.

AutoFHIR reconciliation:
This commit makes no source change because the current build already supports the seed request: ServiceRequest.supportingInfo is 0..*, has definition text covering diagnosis, clinical findings, other observations, and explicitly requested AOE observations, and is typed as CodeableReference(Resource), which includes Observation and Condition references while preserving later approved broadening.

Recommendation:
Keep this no-change audit commit. Reintroducing a DiagnosticOrder-specific edit or narrowing ServiceRequest.supportingInfo back to Observation/Condition would contradict the active build scope and later OO decisions.
