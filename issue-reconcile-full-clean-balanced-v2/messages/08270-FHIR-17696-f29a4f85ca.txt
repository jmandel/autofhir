FHIR-17696: Audit JSON schema ResourceList fixes

Issue request:
FHIR-17696 was a Published/Not Persuasive with Modification FHIR-core change request raised against STU3 3.0.1 JSON Schema downloads. It reported that a contained Practitioner matched more than one ResourceList branch because abstract/base resource schemas such as DomainResource were permissive, and that Parameters appeared twice in ResourceList. The accepted resolution said this had already been fixed and corrected schemas would be referenced from the technical corrections wiki page.

Initial application:
No current in-repository commit explicitly mentions FHIR-17696, and the current core checkout does not track generated fhir.schema.json or ResourceList.schema.json artifacts. The downloads page still exposes the active JSON Schema ZIP, while generation is delegated to the Gradle Kindling dependency. Earlier source history includes related JSON Schema generator work for base resources and ResourceList/ResourceContainer behavior, but the Jira-specific application appears to have been a corrected generated STU3 schema artifact rather than a durable core source edit.

Additional context:
Current Kindling schema generation builds ResourceList from concrete, non-abstract resources only, adds a resourceType const discriminator and required resourceType to each generated resource schema, and marks generated object schemas with additionalProperties false. The current build.fhir.org fhir.schema.json.zip contains only the combined schema; within it ResourceList has one Parameters reference, no duplicate refs, and no DomainResource/Resource abstract branches. A Draft 6 validation check confirms minimal Practitioner and Parameters instances validate through ResourceList, while an invalid resourceType does not. Zulip and Confluence searches found no FHIR-17696-specific or conflicting work-group/community evidence.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current specification source is already wired to generator behavior that avoids the reported ResourceList ambiguity and duplicate Parameters entry, and editing generated-looking JSON schema artifacts would not be a current source fix.

Recommendation:
Keep this audit commit as-is. No current FHIR core source change is needed for FHIR-17696; future JSON Schema behavior changes should be made in the Kindling generator or publisher dependency workflow, not by checking in generated schema downloads.
