FHIR-12524: Audit SUBSETTED tag placement

Issue request:
FHIR-12524 was a Published/Persuasive FHIR-I correction against the REST read guidance for DSTU2. It reported that the HTTP page implied SUBSETTED belonged in Meta.security as a Security Label while the search page and implementer practice treated it as a tag, and the final resolution was to use tags consistently and note that explicitly in the specification.

Initial application:
The issue was applied in svn r11020 / git 05f3c42cdac7041f4c04c6632881bad60b4b994a on 2017-02-03 by changing source/http.html from a Security Label recommendation to Resource.meta.tag. That application still used the historical "Simple Tag" wording, which was later handled separately by FHIR-20672.

Additional context:
Current source/http.html is the active REST (HTTP) page in source/navigation.xml and now says servers SHOULD define Resource.meta.tag with the SUBSETTED code as a tag. Current source/search.html says both _summary and _elements responses SHOULD populate meta.tag with SUBSETTED, and source/datatypes/valueset-common-tags.xml includes SUBSETTED in the Common Tags value set. Later FHIR-32757 removed a separate updates-page sentence that had still called SUBSETTED a Security Label, and FHIR-20672 corrected the undefined "Simple Tag" label without changing the meta.tag placement. A 2022 Security and Privacy Zulip thread discussed the same ambiguity and converged on documenting meta.tag; exact FHIR-12524 Zulip and Confluence searches found no conflicting record.

AutoFHIR reconciliation:
This is an empty audit commit. No source change is needed because the current build already carries the FHIR-12524 decision consistently in the REST read guidance and the search guidance, and the remaining related source references do not direct implementers to put SUBSETTED in Meta.security.

Recommendation:
Keep this audit commit as-is. Future work should only reopen the placement question if a new work-group decision intentionally changes the chosen meta.tag convention; FHIR-12524 itself requires no current core source edit.
