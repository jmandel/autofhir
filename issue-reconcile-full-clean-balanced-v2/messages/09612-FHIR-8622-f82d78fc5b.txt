FHIR-8622: Audit dataelements URL uniqueness

Issue request:
FHIR-8622 was a Published/Persuasive FHIR-I change request raised and applied for DSTU1. It reported that validation.zip's dataelements.xml contained many distinct DataElement resources with the same canonical url, exemplified by http://hl7.org/fhir/DataElement/string, and duplicate Bundle.entry.fullUrl values.

Initial application:
The issue was applied in historical svn revision 6598, represented in this git history by commit 7f6f7f7841bf231bdffd1de8a275973c950e472a, which changed ProfileGenerator to reuse a single generated DataElement entry per path-derived id instead of adding duplicate Bundle entries. That old Java generator file is no longer present in the current source tree, and no dataelements.xml or dataelements.json artifact is checked into source.

Additional context:
Current source has DataElement commented out of source/fhir.ini resource/workgroup/TLA entries and the R4 history page records DataElement as a removed resource. The current Downloads page no longer lists validation.zip; it points implementers to definitions.xml.zip/definitions.json.zip, validation schemas, and package downloads. The ElementDefinition page still links to generated dataelements.xml and dataelements.json, and a current published-artifact check found both generated files contain 328 StructureDefinition entries with no duplicate fullUrl values and no duplicate resource.url values. FHIR-26461, a later same artifact-family duplicate dataelements issue, is already represented on the combined branch with a no-change audit and confirms the current generated dataelements artifact is clean.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The historical DSTU1 generator defect was fixed at the time, the obsolete DataElement/validation.zip source surface is no longer in the current build, and the current generated dataelements XML/JSON artifacts do not reproduce the duplicate fullUrl or canonical-url problem.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-8622 unless future generated dataelements artifacts reintroduce duplicate Bundle fullUrl or resource.url values.
