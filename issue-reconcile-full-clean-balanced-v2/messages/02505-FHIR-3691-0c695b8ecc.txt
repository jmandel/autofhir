FHIR-3691: Audit contained context inheritance guidance

Issue request:
FHIR-3691 was Published / Persuasive with Modification for a DSTU1 change request warning that allowing informal context conduction from a containing resource into a contained resource was dangerous. The approved application was svn revision 4615, adding stronger guidance that FHIR did not define or constrain such conduction and that receivers could not safely infer omitted contained-resource values.

Initial application:
The issue was applied in git-svn revision 4615, now commit 6592747fc7, which changed source/references.html to replace the older permissive wording with cautions about undefined conduction, explicit redundant properties, and out-of-band agreement. That text was later simplified by commit 6bb9d508d3 for FHIR-7385, which made the rule stronger by saying contained resources do not inherit context from their parent resource.

Additional context:
FHIR-5223 was an earlier Published clarification on the same contradictory wording. FHIR-7385 was a later Published / Not Persuasive with Modification issue that explicitly disallowed context inheritance for contained resources, and a separate FHIR-7385 reconciliation commit already on the combined branch fixed the remaining introductory contradiction. The active source/fhir.ini type-page mapping includes reference=references, so source/references.html is in current build scope.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current built source already states that contained resources follow the same no-inheritance rule as other references and that inline contained resources do not inherit context from their parent resource. That stronger later wording fully satisfies FHIR-3691's safety concern without reintroducing older out-of-band-conduction prose.

Recommendation:
Keep this audit commit as-is. Do not add redundant FHIR-3691 prose unless a future work group decision intentionally reopens contained-resource context conduction; the current no-inheritance rule is clearer and safer than the original 2015 mitigation text.
