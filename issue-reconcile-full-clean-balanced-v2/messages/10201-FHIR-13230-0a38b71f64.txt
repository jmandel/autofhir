FHIR-13230: Audit Observation.device wording

Issue request:
FHIR-13230 was Published/Persuasive for STU3 by Orders and Observations. It reported that the Observation.device comment incorrectly said devices supporting an observation could be represented through Observation.related even though the then-current related target could not reference Device, and the final resolution directed removal of the Observation.related wording.

Initial application:
The issue was applied in commit 2bc0950a1e354c2a99db1fca80954166c25bc241, which changed the Observation.device spreadsheet comment from "extension or through the Observation.related element" to extension-or-Provenance gateway wording. Later, commit 67f44190f459a16621371d8e00dbffe9f7e52f1e rewrote the same comment to the current gateway/Provenance text.

Additional context:
Observation is an active resource in source/fhir.ini, and the authoritative current source is source/observation/structuredefinition-Observation.xml. That file no longer contains the incorrect Observation.related guidance: Observation.device references Device and DeviceMetric and says gateway/transmission devices may be documented with Provenance where relevant. The related FHIR-13144/GF#13144 evidence and linked Zulip PGD discussion support the same distinction between the measuring device and a gateway/mobile application. A repository-wide exact-text check found the old Observation.related wording only in source/media/media-spreadsheet.xml, but Media is not listed in the active [resources] section of source/fhir.ini, so that retired artifact is not a current Observation build-scope fix for this seed.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the seed's requested correction is already present in the current active Observation source, and adding redundant extension-pack or gateway prose to Observation.device is not necessary to resolve the published issue.

Recommendation:
Keep this audit commit as-is. No core FHIR source follow-up is needed for FHIR-13230; any future gateway-extension wording work should be handled through the extension-pack/device-gateway family rather than by reintroducing parallel guidance into Observation.device.
