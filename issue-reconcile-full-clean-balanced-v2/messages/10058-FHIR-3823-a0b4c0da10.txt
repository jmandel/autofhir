FHIR-3823: Audit Element content-required validation

Issue request:
FHIR-3823 was Published/Persuasive for FHIR-core formats after an example contained an element represented only as an XML id attribute (`<vaccineType id="396427003"/>`). The issue asked that validation require element content other than id, because that example should be invalid.

Initial application:
No source commit explicitly mentioning FHIR-3823 was found, and Jira comments say the problem was "fixed already" in February 2015. The same rule is visible in the later FHIR-8247 source-history trail: commit 3b6ebf56c2 (svn r5558) added the Element/global invariant that all FHIR elements must have a value or children and made Element constraints appear on the Element page.

Additional context:
The current build keeps Element as an active infrastructure type in source/fhir.ini, with Element normative and assigned the `ele` TLA. The active datatype source now defines ele-1 as "All FHIR elements must have a @value or children or both, unless they are an empty Parameters resource" with FHIRPath `hasValue() or (children().count() > id.count()) or $this is Parameters`, so an element with only id is rejected while preserving the later FHIR-26565 empty-Parameters exception already represented on the combined branch. The specific ImmunizationRecommendation example fragment from the issue is no longer present in current source.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current Element invariant already encodes the required validation behavior for ordinary elements, including the original id-only example shape.

Recommendation:
Keep this audit as-is. No FHIR-core source follow-up is needed for FHIR-3823 unless a future work group decision changes ele-1 or the empty Parameters exception.
