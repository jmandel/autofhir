FHIR-17260: Audit patient context already present

Issue request:
FHIR-17260 is a Published/Persuasive FM change request from STU3. It asked to add a Patient element because there is no context conduction; the final resolution specifically says to add Patient to EligibilityRequest and EligibilityResponse, while the summary also mentioned EnrollmentResponse.

Initial application:
The historical application appears in git commit 10ac2496c7fa29fe458c13a1ef3f7edb89485acc, whose tracker list includes 17260 and whose patch added EligibilityRequest.patient and EligibilityResponse.patient rows and patient search metadata to the STU3 spreadsheet sources. Those STU3 EligibilityRequest/EligibilityResponse files are no longer active build resources.

Additional context:
FHIR-16936 renamed EligibilityRequest/EligibilityResponse to CoverageEligibilityRequest/CoverageEligibilityResponse and left Enrollment as separate resources. The current source/fhir.ini active [resources] list includes coverageeligibilityrequest, coverageeligibilityresponse, enrollmentrequest, and enrollmentresponse, while the old EligibilityRequest/EligibilityResponse abbreviations are commented and the deleted-resource note records the rename. Later FHIR-19493 made CoverageEligibilityResponse.patient mandatory. Later FHIR-43122 addressed the summary's EnrollmentResponse concern by adding EnrollmentResponse.candidate, with Patient and Group targets, and the corresponding patient search parameter. FHIR-43123 is a broader Triaged group-coverage discussion and is not a final source-edit decision for this seed.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current source already contains CoverageEligibilityRequest.patient 1..1 Reference(Patient), CoverageEligibilityResponse.patient 1..1 Reference(Patient), EnrollmentRequest.candidate Reference(Patient|Group), EnrollmentResponse.candidate Reference(Patient|Group), and patient search parameters for the relevant active resources.

Recommendation:
Keep this empty audit commit as-is. Do not edit or resurrect the retired EligibilityRequest/EligibilityResponse spreadsheet sources; the active R6 resource definitions and later applied Jira decisions already preserve the required patient context.
