FHIR-8877: Audit ValueSet operation URL wording

Issue request:
FHIR-8877 was a Published/Persuasive vocab change request for the DSTU1 ValueSet operations. It reported that the $expand and $validate-code input documentation for the old identifier parameter incorrectly described ValueSet.identifier or used inconsistent id wording, and the approved correction was to describe the selector as a logical identifying URL for the value set, i.e. ValueSet.url.

Initial application:
The Jira comment records svn revision 7181. In git-svn history, commit d7e4b493839ffab86c88b0f2873752aabeb08639 is that revision and changed the old ValueSet spreadsheet source for expand.identifier from ValueSet.identifier to ValueSet.url and for validate-code.identifier from "id" to "identifier" with ValueSet.url. That applied the correction in the DSTU2-era spreadsheet source, although later source refactors and related issues changed the operation parameter name itself from identifier to url.

Additional context:
The current build-scoped source is no longer the old spreadsheet. ValueSet is an active resource in source/fhir.ini, OperationDefinition is active, and source/valueset/list-ValueSet-operations.xml references OperationDefinition/ValueSet-expand and OperationDefinition/ValueSet-validate-code. Later FHIR-8766 renamed the relevant operation selector to url; later FHIR-13946 and FHIR-14355 audits, already represented on the combined branch, cover adjacent ValueSet $validate-code parameter-name wording. Current source now defines url parameters and describes them as canonical URL references, while legitimate ValueSet.identifier text remains only for the resource's business identifier/search parameter, not the operation selector.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active ValueSet $expand and $validate-code OperationDefinitions already use url/canonical URL wording for the value set selector, and a source search found no remaining obsolete operation wording such as expand.identifier, validate-code.identifier, $expand$identifier, or the old logical value set identifier/id phrases in the current ValueSet operation sources.

Recommendation:
Keep this empty audit commit as-is. No follow-up is needed for FHIR-8877 unless the work group opens a new issue to revisit ValueSet operation URL semantics beyond this historical documentation correction.
