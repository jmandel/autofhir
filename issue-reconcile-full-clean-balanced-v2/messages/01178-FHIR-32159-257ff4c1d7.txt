FHIR-32159: Audit MedicationKnowledge device target

Issue request:
FHIR-32159 was a Published/Persuasive Pharmacy change request for R5 asking that MedicationKnowledge.device reference DeviceDefinition rather than Device because MedicationKnowledge is definitional and should identify a device model/kind, not an actual device instance.

Initial application:
The issue was applied in commit 934e7819020c72ee6e3ba509ecb5445a1850f109, which changed MedicationKnowledge.device from targetProfile Device to DeviceDefinition in source/medicationknowledge/structuredefinition-MedicationKnowledge.xml.

Additional context:
MedicationKnowledge is active in the current build through source/fhir.ini. A later MedicationKnowledge refactor in commit 6422f2f98a0fcf03140c15fe93bfd6c765fc6377 removed the MedicationKnowledge.device and MedicationKnowledge.packaging.device elements while moving definitional medication details into the MedicationKnowledge.definitional backbone and packaging details to PackagedProductDefinition. The current source has no MedicationKnowledge.device element and no stale Device target in the MedicationKnowledge source; the remaining nearby references are to PackagedProductDefinition, ClinicalUseDefinition, MedicinalProductDefinition, SubstanceDefinition, and other current definitional/packaging resources.

AutoFHIR reconciliation:
This commit intentionally makes no source change because the requested Device-to-DeviceDefinition correction was applied before R5 and the later refactor removed the affected element from the current build. Reintroducing or editing a removed device element would be broader than FHIR-32159 and unsupported by current source history.

Recommendation:
Keep this audit commit as-is. No current core source fix is needed for FHIR-32159 unless Pharmacy later decides to reintroduce a MedicationKnowledge device-model element, in which case that new tracker should define the intended current element and target.
