FHIR-7483: Audit FamilyMemberHistory condition alignment

Issue request:
FHIR-7483 was a Published Patient Care change request, resolved Persuasive with Modification, asking to align FamilyMemberHistory.condition with Condition by renaming condition.type to condition.code, binding it to Condition's condition-code example value set, allowing Period in onset[x], moving notes to Annotation, and adding abatement as an extension.

Initial application:
The issue was applied in commit 1f59a1646f (#5826 - added status; #7483 - alignment to condition; updated guides to reflect FamilyMemberHistory changes), which changed the then-authoritative FamilyMemberHistory spreadsheet and examples from condition.type to condition.code and converted note content to Annotation. The current generated StructureDefinition carries those changes forward in active source.

Additional context:
FamilyMemberHistory is active in source/fhir.ini. Current source/familymemberhistory/structuredefinition-FamilyMemberHistory.xml has FamilyMemberHistory.condition.code with an example binding to http://hl7.org/fhir/ValueSet/condition-code, FamilyMemberHistory.condition.onset[x] includes Period, and FamilyMemberHistory.condition.note is Annotation. The abatement request is represented by the extension http://hl7.org/fhir/StructureDefinition/familymemberhistory-abatement, which was removed from core source when extensions were split out in dd468d4f17 and exists in the FHIR Extension Pack. Later Patient Care issues FHIR-17809 and FHIR-36826 both rejected adding abatement-like details to the base FamilyMemberHistory resource and explicitly pointed to extensions as the appropriate mechanism.

AutoFHIR reconciliation:
This audit commit makes no source change because the active core source already implements the seed's core element changes, and the abatement portion is intentionally handled as an extension outside the current core checkout rather than as a FamilyMemberHistory base element.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed for FHIR-7483 unless Patient Care later changes its position on adding abatement or related Condition status details directly to FamilyMemberHistory; current later decisions support the extension-based approach.
