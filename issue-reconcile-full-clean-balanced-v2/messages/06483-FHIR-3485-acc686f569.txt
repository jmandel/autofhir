FHIR-3485: Confirm Patient provider search split

Issue request:
FHIR-3485 was a Published/Persuasive Patient change request saying the Patient "provider" search parameter pointed at Patient.managingOrganization even though the intended care-provider path was Patient.careProvider. The accepted PA resolution distinguished two use cases: organization = Patient.managingOrganization and careprovider = Patient.careProvider.

Initial application:
The issue was applied in git commit 5415ea6b96, which changed the old Patient search row named provider into organization on Patient.managingOrganization and added a separate careprovider row on Patient.careProvider. No existing combined-branch reconciliation commit for FHIR-3485 was found before this audit.

Additional context:
FHIR-7963 later renamed Patient.careProvider to Patient.generalPractitioner. Git commit fb14d2fad1 applied that rename to Patient and the search parameter, so the current equivalent of the FHIR-3485 careprovider parameter is general-practitioner. The current Patient resource is active in source/fhir.ini, and the current checked-in Patient search parameter bundle has general-practitioner on Patient.generalPractitioner and organization on Patient.managingOrganization, with no Patient provider search parameter remaining.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scoped source already preserves the FHIR-3485 distinction after the later careProvider to generalPractitioner rename.

Recommendation:
Keep this no-change audit commit as-is. Revisit only if a future Patient search-parameter change reintroduces a provider/organization ambiguity.
