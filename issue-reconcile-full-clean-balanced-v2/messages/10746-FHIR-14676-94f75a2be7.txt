FHIR-14676: Audit DELETE request body rule

Issue request:
FHIR-14676 was a Published/Persuasive FHIR-core HTTP change request for STU3. It asked to clarify that clients must not send an entity body on DELETE, with the accepted resolution to add the proposed wording: "For delete operations, the request body SHALL be empty."

Initial application:
The issue appears to have been applied in source commit 7093fe91b484357c8b69f995af6cba34ca481bd6, "GF#14676 - no body on delete", which inserted "The request body SHALL be empty." into source/http.html under the delete interaction. Later source edits moved or reformatted the page but preserved the rule.

Additional context:
The RESTful API page is in current build scope through source/hierarchy.xml and source/navigation.xml. Current source/http.html also marks DELETE-based request bodies as N/A in the interaction summary, including ordinary delete, conditional delete, delete-history, and delete-history-version. Related historical Jira FHIR-2885 confirms the older platform concern about DELETE-with-body for tag deletion, while FHIR-3025 concerns optional response payloads and does not conflict with an empty request body. Quoted Zulip and Confluence searches for FHIR-14676 plus DELETE/request-body terms found no directly relevant or conflicting community record.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current source already contains the required SHALL statement for ordinary delete and the summary table already states that DELETE request bodies are not present across DELETE interactions, so adding redundant wording would not change implementer understanding.

Recommendation:
Keep this no-change audit commit as-is. No follow-up is needed for FHIR-14676 unless the work group wants a broader editorial rewrite of the RESTful API summary table, which is outside this issue.
