FHIR-13917: Audit DocumentReference class/type definitions

Issue request:
FHIR-13917 was a Published, Persuasive with Modification STU3 FHIR-core DocumentReference change request. It asked to remove the class element requirements sentence "Helps humans to assess whether the document is of interest when viewing a list of documents.", replace the class comments sentence "This is a metadata field from XDS/MHD ." with "Key metadata element describing the document, used in searching/filtering.", and add the human-interest sentence to the type element comment.

Initial application:
The issue appears to have been applied in git commit 60707816a225593159bcb01c8526f5a9c8dda742, whose subject lists GF#13917 in the StructDoc August 2 block-vote update. That commit changed the then-authoritative DocumentReference spreadsheet so type carried the human-interest sentence and the class/category row carried search/filtering metadata wording.

Additional context:
FHIR-17171 had already renamed DocumentReference.class to DocumentReference.category and increased its cardinality; the current source preserves that compatibility mapping in source/fhir.ini. A previous reconcile commit for FHIR-17171 is already present on the combined branch, so this commit only audits FHIR-13917. The public community thread linked from the Jira confirms the same distinction: class/category is a broad searching category and type is a finer display/interest code. Corrected Zulip and Confluence searches found no direct FHIR-13917 discussion or conflicting later decision.

AutoFHIR reconciliation:
This commit makes no source change. DocumentReference is active in the build, the current StructureDefinition has DocumentReference.category carrying key metadata/searching guidance and no class/category requirements sentence with the human-interest wording, and DocumentReference.type includes the requested human-interest sentence. The wording is not identical because later source refactors and the FHIR-17171 rename changed class to category, but the implementer-facing rule requested by FHIR-13917 is already present.

Recommendation:
Keep this audit commit as-is. No FHIR-13917 follow-up is needed in core; any future cleanup of nearby grammar such as "he exact" or "the the" should be handled as separate editorial work rather than as this issue's reconciliation.
