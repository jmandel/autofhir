FHIR-31846: Audit ClinicalUseDefinition single-kind invariant

Issue request:
FHIR-31846 was a Published/Persuasive FHIR-core ClinicalUseIssue change request from BRR asking for an invariant because one clinical use issue cannot simultaneously be a contraindication, interaction, undesirable effect, or other detailed issue kind.

Initial application:
No commit explicitly mentioning FHIR-31846 was found in current source history. The one-kind invariant first appears during the ClinicalUseIssue to ClinicalUseDefinition rename in git commit 13b7d768e64, shortly after the Jira vote, and later history corrected/refined that invariant: warning was added as another kind, and b4517d98d07 fixed the ClinicalUseDefinition.contraindication expression spelling.

Additional context:
ClinicalUseIssue itself is no longer an active current-build resource; source/fhir.ini comments ClinicalUseIssue and actively builds ClinicalUseDefinition. The active ClinicalUseDefinition StructureDefinition now contains the cud-1 error invariant, and a checked-in failing invariant test exercises the case with both contraindication and indication. The later FHIR-48893 decision added type/backbone consistency constraints (cud-2 through cud-6), which reinforce rather than contradict the FHIR-31846 one-kind rule. Corrected Zulip and Confluence searches found no community record that changes this conclusion.
