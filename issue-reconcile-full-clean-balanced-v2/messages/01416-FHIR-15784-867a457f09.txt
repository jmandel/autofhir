FHIR-15784: Audit Consent Action definitions

Issue request:
FHIR-15784 was Published with a Persuasive with Modification resolution for the STU3 Consent Action value set. It asked that the Consent Action codes be made mutually exclusive, or otherwise arranged in a proper hierarchy, and resolved to change the definitions for collect, access, use, disclose, and correct until V3 harmonization was complete.

Initial application:
The issue was applied in commit 7c8a912aeb6ff6bb22b167c37089bf18b5005a1c, which changed source/consent/codesystem-consent-action.xml definitions to the resolved wording for the five consent action codes. Those definitions were present in the R4 generated terminology history. The core CodeSystem source was later removed from the FHIR core checkout by the UTG/THO migration in commit 5c0494aacfd0b8bd52bc72c587aa89d0a64246f8.

Additional context:
Current core source keeps Consent in the active resource list and binds Consent.provision.action to http://hl7.org/fhir/ValueSet/consent-action. The current source/consent/valueset-consent-action.xml composes that value set from all codes in http://terminology.hl7.org/CodeSystem/consentaction, and the current published THO CodeSystem still carries the FHIR-15784 definitions. Later FHIR-48780 promoted the Consent value set status to active/non-experimental; it did not revisit the action definitions. FHIR-15796 requested a new none code but was Resolved - No Change, so it does not require adding a code here.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No FHIR core source edit is needed because the current build-scope value set correctly points to the external THO code system, and that code system already preserves the resolved FHIR-15784 definitions.

Recommendation:
Keep this audit commit as-is. Future changes to the consent action code definitions should be handled through THO/UTG, not by reintroducing a core CodeSystem source file, unless the FHIR build ownership changes.
