FHIR-41668: Audit operation outcome terminology move

Issue request:
FHIR-41668 is Applied/Persuasive with Modification for R6. It asked that http://hl7.org/fhir/ValueSet/operation-outcome stop using the duplicate FHIR-core CodeSystem http://hl7.org/fhir/operation-outcome and instead be maintained with the THO/UTG CodeSystem http://terminology.hl7.org/CodeSystem/operation-outcome.

Initial application:
The request was applied in upstream source commit 6f6c22d0ef, which removed the OperationOutcome binding row from source/terminologies/bindings.xml and deleted source/terminologies/codesystem-operation-outcome.xml and source/terminologies/valueset-operation-outcome.xml. The current worker branch and combined branch both contain that commit.

Additional context:
The seed came from a committers Zulip discussion where Grahame Grieve said THO should be used and the duplicate core artifact deleted for R6. FHIR-I WGM minutes record the FHIR-41668 Persuasive with Modification vote. The older FHIR-19977 request for MSG_EXTERNAL_FAIL was implemented through UTG proposal UP-299, and the current THO CodeSystem includes MSG_EXTERNAL_FAIL. FHIR-37866 is the earlier R4B missing-valueset technical-correction context, but it is not Applied/Published for this run and its comment says the issue was fixed in R5 rather than requiring current R6 source work.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current R6 source no longer defines or binds the old core operation-outcome ValueSet/CodeSystem, and the current AuditEvent outcome-detail example ValueSet composes directly from http://terminology.hl7.org/CodeSystem/operation-outcome. Current build pages for valueset-operation-outcome.html and codesystem-operation-outcome.html return 404, while valueset-audit-event-outcome-detail-example.html expands from the THO CodeSystem.

Recommendation:
Keep this audit commit as-is. No FHIR-core follow-up is needed unless the work group separately decides that THO should publish a standalone ValueSet-operation-outcome artifact again; that would be external terminology work, not a current core-source reconciliation fix.
