FHIR-11358: Audit CarePlan activity reason binding

Issue request:
FHIR-11358 was a Published/Persuasive with Modification Patient Care change request for DSTU2 CarePlan. It objected to binding CarePlan.activity.detail.reasonCode to the newly created activity-reason example value set and resolved to update that binding to http://build.fhir.org/valueset-clinical-findings.html.

Initial application:
The issue was explicitly applied in migrated commit bac396f21d6dc845c746e29a9fb7c79e27ee6ff5, whose message names #11358 and whose CarePlan spreadsheet patch changed CarePlanActivityReason from valueset-activity-reason to http://hl7.org/fhir/ValueSet/clinical-findings. Later source refactoring regenerated the CarePlan definition into source/careplan/structuredefinition-CarePlan.xml while preserving the clinical-findings binding on the successor CarePlan activity reason element.

Additional context:
CarePlan is active in source/fhir.ini, and the current active CarePlan StructureDefinition binds CarePlan.activity.plannedActivityDetail.reason to http://hl7.org/fhir/ValueSet/clinical-findings with the CarePlanActivityReason binding name. The older source/careplan/valueset-activity-reason.xml and its OID entry still exist, but source search found no current binding or CarePlan reference to ValueSet/activity-reason; deleting that orphaned historical value-set source would be a broader cleanup question rather than necessary application of this Jira. Related CarePlan binding issues FHIR-11357, FHIR-11359, FHIR-14818, and FHIR-22733 do not reverse this conclusion.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build-scope CarePlan source already implements the final Jira decision by using clinical-findings for the activity reason binding, and adding or deleting unrelated terminology artifacts is not required to make the current CarePlan specification correct.

Recommendation:
Keep this no-change audit commit as-is. If HL7 wants to remove the unused activity-reason value-set source and OID entry, handle that as a separate terminology/build-scope cleanup with work-group review rather than as a late correction for FHIR-11358.
