FHIR-9073: Audit Immunization notGiven retirement

Issue request:
FHIR-9073 was a Published/Persuasive with Modification DSTU2 Immunization request to clarify the notes relationship between status, notTaken/notGiven/wasNotGiven, and refusal reasons. The final Jira update closed the ticket because R4 alignment with the Event workflow pattern removed notGiven/notTaken and added the not-done status, leaving no two-element relationship to clarify.

Initial application:
No FHIR-9073-tagged source commit was found. The apparent application was implicit in the R4 Immunization Event workflow work: commit 4c5a8902ab replaced the refused example's completed + notGiven representation with status not-done and added not-done to the Immunization status value set; commit f451f3fc4b then moved the refusal reason into statusReason.

Additional context:
source/fhir.ini actively includes Immunization in the current build. Current Immunization source has no Immunization.notGiven, Immunization.wasNotGiven, or Immunization.notTaken element definitions; it uses required status codes completed, entered-in-error, and not-done, and constrains statusReason to not-done or entered-in-error. PHWG's 2017-11-30 minutes record the Event workflow decision to get rid of notGiven and reasonNotGiven, and a 2020 implementers Zulip answer confirms R4 expresses immunization refusal as status not-done with statusReason. Later FHIR-54325 refined statusReason for R6 but did not restore the retired legacy elements.

AutoFHIR reconciliation:
This is an empty no-change audit commit. The current source already implements the final FHIR-9073 disposition, and adding new notes would reintroduce a retired relationship rather than clarify the current model.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-9073; future refusal/statusReason changes should be handled under later Immunization statusReason issues such as FHIR-54325 rather than this retired DSTU2 relationship issue.
