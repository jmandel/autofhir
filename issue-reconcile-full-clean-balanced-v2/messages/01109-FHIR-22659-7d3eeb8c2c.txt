FHIR-22659: Audit claim request references

Issue request:
FHIR-22659 was Published with a Not Persuasive with Modification resolution for Financial Management. It asked that preauthorization Claim usage have a way to reference requested services instead of misusing Procedure, and the final resolution added `.request 0..* Reference(DeviceRequest | MedicationRequest | NutritionOrder | ServiceRequest | SupplyRequest | VisionPrescription)` to Claim.item, ClaimResponse.addItem, ExplanationOfBenefit.item, and ExplanationOfBenefit.addItem.

Initial application:
Commit 2be1440043 (merged by 03a95e1a21) applied the issue for R5 by adding the four request elements to the active Claim, ClaimResponse, and ExplanationOfBenefit StructureDefinition XML files, with the full approved target list including ServiceRequest and SupplyRequest. The published R5 profiles contain the same four elements and target lists.

Additional context:
Claim, ClaimResponse, and ExplanationOfBenefit remain active current-build resources in source/fhir.ini. Current source and build output still include the four request elements and the ServiceRequest target that addresses the seed request. The only R5 target no longer present is SupplyRequest, which was removed from these active core targetProfile lists by 3b38b80cf2 as part of the later "Remove OO resources and point to new incubator" change that also removed SupplyRequest from the active core resource list. Later Jira FHIR-43308 discusses broader future Claim request/event modeling but is still Triaged and does not supply a final reversal of FHIR-22659.

AutoFHIR reconciliation:
Made no source change. The current core source already preserves the ServiceRequest preauthorization support required by the seed, and restoring SupplyRequest to the core conformance target list would reopen the later OO-incubator boundary change rather than reconcile this R5 Claim issue.

Recommendation:
Keep this empty audit commit as-is. If FM and OO want the current R6 core Claim-family request elements to target the external OO Incubator SupplyRequest resource, that should be handled by a current work-group decision rather than by reapplying FHIR-22659.
