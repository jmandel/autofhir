FHIR-38923: Audit large-resource PATCH guidance outside core

Issue request:
FHIR-38923 was a Published FHIR-core change request for the Operations for Large Resources page, raised against Group and List for R5. The Persuasive with Modification resolution asked to explain overlap, differences, and trade-offs between the large-resource operations and PATCH while avoiding any assertion that PATCH requires XML or JSON source resources.

Initial application:
The issue was applied in core by 9510c3ae69, which replaced the R5 ballot note on source/operations-for-large-resources.html with introductory operation guidance and explicit PATCH/GraphQL trade-off text. The R5 published page includes that text and does not assert an XML/JSON precondition for PATCH.

Additional context:
Later R6 source history changed the current core page from a draft local operation-definition page into an informative handoff to the API Incubator. Commit 270e0ceb7b removed the local detailed operation narrative, including the FHIR-38923 PATCH/GraphQL paragraph, and left a short pointer to the API Incubator. The current core page is still build-scoped through source/hierarchy.xml, but it no longer owns the detailed operation content. The external HL7/api-incubator-ig source currently contains the same PATCH/GraphQL trade-off paragraph that FHIR-38923 introduced, while the live build.fhir.org API Incubator page currently returns 404. Related reconcile commit 54ed4a6299 already audited FHIR-39102 as external-repo for the same R6 move of operation-definition details out of core.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. Re-adding the PATCH paragraph to the current core handoff page would duplicate content that now belongs with the detailed API Incubator operation page and would partially undo the later R6 decision to stop hosting those draft operation details in core. The remaining work, if any, is to publish or repair the external API Incubator page/link, not to restore superseded R5 narrative in the core checkout.

Recommendation:
Keep this external-repo audit commit. Follow up in HL7/api-incubator-ig or the API Incubator publication process so the external page containing the PATCH/GraphQL trade-off guidance is available at a stable URL, then update the core handoff URL only after that target is published.
