FHIR-55410: Align Provenance activity definition

Issue request:
FHIR-55410 was Applied/Persuasive with Modification for FHIR-core Provenance. It asked to clarify the Provenance activity wording that said an activity "MAY include consuming, processing, transforming" because Provenance does not track read/query or validation-only activity; consumed or processed entities matter only when they are involved in producing a target, and the MAY was not conformance language.

Initial application:
The Jira comment points to HL7/fhir#4066. Git commit 018de58a90 changed source/provenance/provenance-introduction.xml so the W3C model Activity bullet now says the activity acts upon output (.target) resources, but that application did not update the active Provenance.activity ElementDefinition or the matching Event mapping exception source.

Additional context:
source/fhir.ini actively lists provenance=Provenance, so source/provenance/structuredefinition-Provenance.xml is current build input. The current Provenance introduction already carries the output-target wording, and the stale ElementDefinition still used the broad consuming/processing wording. Security WG minutes for 2026-03-30 record the block-vote disposition for FHIR-55410. A same-PR neighboring issue, FHIR-55409, corrected the adjacent Entity/Agent wording and is audited separately.

AutoFHIR reconciliation:
This commit updates Provenance.activity in source/provenance/structuredefinition-Provenance.xml and the corresponding resource value in source/provenance/provenance-event-mapping-exceptions.xml to use the same output (.target) resources wording already applied to the Provenance introduction. It intentionally leaves historical tools/history release snapshots and XML comments alone.

Recommendation:
Keep this source fix. It completes the applied FHIR-55410 clarification across the current build's authoritative Provenance definition and its mapping-exception source without broadening the decision to unrelated W3C provenance text.
