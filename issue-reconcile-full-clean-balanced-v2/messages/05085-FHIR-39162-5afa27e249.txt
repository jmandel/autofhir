FHIR-39162: Audit Device display-name consolidation

Issue request:
FHIR-39162 was Published with a Persuasive with Modification resolution for R5. The ballot comment asked whether the new Device.displayName should instead be represented through the existing Device.deviceName/name structure, and the approved resolution was to remove Device.displayName, revise the name backbone, add a Device.name.display boolean, and enforce that at most one display flag is true.

Initial application:
The main Jira-family source application was commit 37fccabd56, which renamed Device.deviceName to Device.name, changed the child name element to Device.name.value, added Device.name.display, and updated the name/type/value descriptions. The Jira comment linked commit e646b7459, which enabled the dev-1 invariant after an intermediate FHIRPath cleanup. Later QA commits 55512f8e09 and 49dbfef931 moved and normalized the invariant so the current root Device constraint is name.where(display=true).count() <= 1.

Additional context:
OO HCP minutes on 2022-11-28 recorded the plan to delete Device.displayName and add a display-name boolean to the name backbone; the 2022-12-05 minutes record the proposed solution that became the Jira vote. Device is active in source/fhir.ini. A later Applied issue, FHIR-43164, intentionally changed Device.name.type from the R5 required code binding to an extensible CodeableConcept and added jurisdictional guidance, so the current type/binding difference from the FHIR-39162 resolution table is a later approved change rather than a reconciliation defect. FHIR-46397 later removed stale Device.displayName comments while leaving the intentional release-note statement that Device.displayName was removed.

AutoFHIR reconciliation:
This audit makes no source change. The current source already has Device.name, Device.name.value, Device.name.type, and Device.name.display with the display uniqueness condition, and no active Device.displayName element remains. The only Device.displayName source mention in the Device narrative is a ballot/release note explaining that the element was removed because Device.name now covers it.

Recommendation:
Keep this empty audit commit as-is. No further core source change is needed for FHIR-39162; future work should not reintroduce Device.displayName or undo the later FHIR-43164 Device.name.type extensibility decision without a new work-group decision.
