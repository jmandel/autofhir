FHIR-24888: Audit wildcard include reference search

Issue request:
FHIR-24888 was Published/Persuasive with Modification for FHIR-core operations/search. It asked for a way to find all resources that reference a target resource for delete/referential-integrity workflows. The final FHIR-I decision was not to add a new $reference-search operation, but to define support for _revinclude=* and, while doing so, _include=*. The wildcard is scoped to include/revinclude behavior supported by the server, typically indexed references, and '*' should be declared in CapabilityStatement like any other include or revinclude.

Initial application:
Git commit 83c723c77c26704fa9fd9afbee5e5e52772c3d1d ("FHIR-24888 First pass") updated source/search.html to add the wildcard syntax bullets for [_include|_revinclude]=*, [resource]:*, [resource]:[parameter], and [resource]:[parameter]:[targetType], plus CapabilityStatement advertising guidance. Current source/search.html still contains those wildcard rules. Later source history added clarifications without changing the FHIR-24888 decision: FHIR-33309 tightened the support scope for wildcard includes, and FHIR-46381 clarified CapabilityStatement wildcard declaration semantics.

Additional context:
The originating Zulip thread shows the core tradeoff: a guaranteed all-references operation would require scanning references beyond ordinary search indexes, while efficient _revinclude behavior generally depends on search parameters/indexed references. FHIR-I minutes from 2021-02-01 record the approved 20-0-0 decision to define wildcard _revinclude=* and also _include=*, with existing CapabilityStatement include/revinclude string elements used for declaration. Earlier FHIR-27861 answered that broad _include=* and _revinclude=* were not standard in R4 and pointed to FHIR-24888 as the pending broader discussion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active search page already defines [_include|_revinclude]=*, states that wildcard requests are for resources and references supported by the server and typically indexed, preserves the later clarification that wildcard resource-level includes are limited to search parameters supported for _include/_revinclude, and tells implementers to advertise wildcard support in CapabilityStatement. The active CapabilityStatement StructureDefinition comments now explicitly state that '*' is an allowed value for searchInclude/searchRevInclude declarations and that listing '*' does not imply all individual search parameters are supported.

Recommendation:
Keep this audit commit as-is. The current specification matches the published FHIR-24888 decision; future work should only reopen the topic if FHIR-I wants a separate guaranteed all-references operation rather than the bounded wildcard include/revinclude semantics approved here.
