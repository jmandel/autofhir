FHIR-31732: Audit contained-resource container references

Issue request:
FHIR-31732 is a Published/Persuasive FHIR-core technical correction for the Reference datatype. It reported that the contained-resource guidance allows a contained resource to reference its container with a bare "#", but the ref-1 invariant only accepted local references whose fragment matched a contained resource id. The approved resolution was to update ref-1 to also allow reference='#' when the Reference is evaluated inside a contained resource, expressed as %rootResource!=%resource.

Initial application:
The issue was explicitly applied in source history by commit d87b97a367412efef9c243585bd036f4546fb9c5, "Update ref-1 to fix FHIR-31732", merged through HL7/fhir#1602. That commit changed source/datatypes/reference.xml so ref-1 included the approved branch: or (reference='#' and %rootResource!=%resource). The current branch contains that implementation commit.

Additional context:
source/fhir.ini actively lists Reference as a datatype, maps Reference pages to references.html, marks Reference normative, and assigns it the ref constraint prefix, so source/datatypes/reference.xml is current build-scope source for ref-1. A later Published/Persuasive follow-up, FHIR-37793, added the leading reference.exists() implies guard for display-only Reference values but preserved the FHIR-31732 container-reference branch. The FHIR-I 2021-09-13 minutes record the issue as a technical correction with FHIRPath changes, and the earlier Zulip discussion confirms the same bare-# container-reference problem.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current ref-1 FHIRPath expression in source/datatypes/reference.xml already reads reference.exists() implies (reference.startsWith('#').not() or (reference.substring(1).trace('url') in %rootResource.contained.id.trace('ids')) or (reference='#' and %rootResource!=%resource)), which preserves the approved FHIR-31732 semantics while incorporating the later FHIR-37793 guard.

Recommendation:
Keep this no-change audit commit as-is. No FHIR-core source follow-up is needed for FHIR-31732; future work, if any, should be limited to implementation-specific validator behavior because the current specification source already permits contained resources to reference their container with "#".
