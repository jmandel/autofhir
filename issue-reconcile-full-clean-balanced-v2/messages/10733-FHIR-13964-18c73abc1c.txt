FHIR-13964: Audit vital-sign code discriminator application

Issue request:
FHIR-13964 was a Published/Persuasive STU3 OO change request to add system as a discriminator for code slicing in the vital signs profiles. The motivating BodyTemp discussion noted that slicing Coding only by code could collide when different code systems reuse the same code value.

Initial application:
The historical application is present in git as 1eb8db446d5aca682e107a14e5fbb3b4e22d606a, "GF#13897, GF#13964, GF#14037 vitals profiles slicing", which changed the then-authoritative source/observation/observation-vitalsigns-profile-spreadsheet.xml on 2018-02-23. No existing combined-branch reconciliation commit for Issue-Reconcile-Key: FHIR-13964 was found before this audit.

Additional context:
The current Observation vital signs IG references the active profile StructureDefinitions for vitalsigns, vitalspanel, bp, bodytemp, bodyheight, bodyweight, bmi, headcircum, resprate, heartrate, and oxygensat. The current per-measurement profiles no longer model the identifying code with code.coding slices; they constrain Observation.code using patternCodeableConcept with a LOINC system and code, and the vital-sign narrative explicitly tells implementers to test whether the pattern coding is present rather than comparing code.coding literally. The referenced Zulip thread says discriminator-on-code-and-system is semantically the same as a pattern CodeableConcept for this use, and later current-source refactors already adopted that representation. FHIR-13968 is an already-published audit on the combined branch for adjacent vital-sign code inclusion wording.

AutoFHIR reconciliation:
This commit intentionally makes no source changes. The current source expresses the requested system-and-code discrimination through patternCodeableConcept rather than through the older STU3 code.coding slicing representation, and adding redundant slicing would change representation without improving current implementer guidance.

Recommendation:
Keep this audit commit as-is. Do not reintroduce code.coding slicing solely to match the old tracker wording unless the work group decides to reverse the current patternCodeableConcept representation.
