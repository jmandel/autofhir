FHIR-14083: Audit MeasureReport quantity score support

Issue request:
FHIR-14083 was a Published/Persuasive CQI STU3 change request for FHIR-core MeasureReport. It asked to add Quantity support for MeasureReport measureScore, with the final resolution saying the measureScore elements would be changed to Quantity and the stratum value element would be changed to CodeableConcept.

Initial application:
The Jira says the change was applied at SVN 12641. In git history this is commit 734c7befc75fc6677ab2dbae8d77bdc07428cc5b, whose message explicitly includes #14083 and whose spreadsheet patch changed MeasureReport.group.measureScore and MeasureReport.group.stratifier.stratum.measureScore from decimal to Quantity and MeasureReport.group.stratifier.stratum.value from string to CodeableConcept.

Additional context:
MeasureReport is an active current-build resource in source/fhir.ini. The current authoritative StructureDefinition source has MeasureReport.group.measureScore[x] and MeasureReport.group.stratifier.stratum.measureScore[x] with Quantity among their allowed types, and MeasureReport.group.stratifier.stratum.value[x] with CodeableConcept among its allowed types. Later final CQI decisions broadened these same choice elements: FHIR-22824 added dateTime/CodeableConcept/Period/Range/Duration score types, FHIR-46238 added boolean score support, FHIR-50174 added Ratio score support, and FHIR-26647 broadened stratum values beyond CodeableConcept. Those later decisions mean the current source should not be narrowed back to only Quantity or only CodeableConcept.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current source already preserves the FHIR-14083 semantic change by allowing Quantity measure scores and CodeableConcept stratum values, while also preserving later approved MeasureReport type expansions.

Recommendation:
Keep this no-change audit commit as-is. No follow-up is needed for FHIR-14083 unless a work group reopens the later choice-type decisions.
