FHIR-14031: Audit Observation multi-answer grouping guidance

Issue request:
FHIR-14031 was a Published/Persuasive OO change request for STU3 asking the Observation Grouping section to clarify how to represent observations with multi-select answers or values. The final resolution says the request was pre-applied by adding an alcohol-type example and listing that scenario as a use case for Observation.component.

Initial application:
The current source history shows commit f35b3850a7c3e70e64969237319c1b32fb4e943e, "GF#13872 make notes section pretty, partially preapply GF#14036 and #14031", added source/observation/observation-example-alcohol-type.xml and added the Observation.component use-case bullet for representing multiple answers to a question.

Additional context:
Observation is an active resource in source/fhir.ini, so the source/observation notes and examples feed the current build. The current Observation Grouping notes still state that Observation.component is appropriate for representing multiple answers to a question and link to the alcohol-type example. The alcohol-type example remains registered in the Observation examples list. The linked Zulip thread supports the same nuanced rule: use components when the answers need to be understood collectively, while independent observations remain appropriate when answers stand alone. No Confluence references or conflicting community decisions were found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build source already contains the requested guidance and example, and adding more prose would be redundant rather than necessary for implementer understanding.

Recommendation:
Keep this audit commit as-is. Revisit only if OO wants a new substantive rule for multi-select observations beyond the existing component-versus-independent-observation guidance.
