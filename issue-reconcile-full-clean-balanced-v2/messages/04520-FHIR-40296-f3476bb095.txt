FHIR-40296: Refer to obligation as an extension

Issue request:
FHIR-40296 was Published/Persuasive for R5 and asked to move ElementDefinition obligation from an inline element to an extension so the obligation model could keep evolving with tooling flexibility.

Initial application:
The Jira-tagged commit fa3b0bac14 removed ElementDefinition.obligation and its child rows from source/datatypes/elementdefinition.xml, removed the core obligation CodeSystem and ValueSet source files, and updated several pages to use the obligation extension. That application left two source/obligations.html sentences describing obligation as an ElementDefinition feature/element.

Additional context:
Current core source no longer defines ElementDefinition.obligation, while the FHIR Extension Pack defines http://hl7.org/fhir/StructureDefinition/obligation and the related terminology. FHIR-I minutes for 2023-02-06 record the persuasive vote and note uncertainty only about whether the extension would be core or tooling. Later applied FHIR-50580 confirms the page should speak in terms of the Obligation Extension, and later unresolved FHIR-50581 independently identified the same stale phrases.

AutoFHIR reconciliation:
This commit updates source/obligations.html to describe mustSupport as the ElementDefinition property and obligation as the http://hl7.org/fhir/StructureDefinition/obligation extension in both affected locations. The page is linked from the current documentation index and is part of the built core documentation surface.

Recommendation:
Keep this source fix. It completes the FHIR-40296 move-to-extension application in core without separately deciding FHIR-50581, whose workflow status remains Resolved - change required.
