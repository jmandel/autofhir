FHIR-26687: Audit MedicationRequest dosage guidance

Issue request:
FHIR-26687 was Published/Persuasive with Modification for R5 by Pharmacy. It asked how repeated v2 RXR segments for one ORC/RXO should map to MedicationRequest.dosageInstruction, including whether repeated dosageInstruction instances should be used, how either/or options are represented, and how two alternative MedicationRequests are linked. The accepted guidance was to create multiple MedicationRequest instances, use MedicationRequest.groupIdentifier to group them, set each MedicationRequest.intent to "option", add examples, and clarify the MedicationRequest.dosageInstruction wording.

Initial application:
The issue appears to have been applied by commit b9257918056, merged by 7683bfb3d7, which explicitly listed FHIR-26687 and added the paired MedicationRequest examples medrx0343a and medrx0343b plus example-list entries for same-drug route options using the same groupIdentifier and intent="option". The detailed grouping prose in the dosageInstruction area was already present from the closely related FHIR-27885 guidance and remained available to explain how grouped MedicationRequests should be interpreted.

Additional context:
MedicationRequest is an active build-scope resource in source/fhir.ini. Current source/medicationrequest/medicationrequest-introduction.xml and source/medicationrequest/medicationrequest-notes.xml retain the guidance that MedicationRequest requests one medication, multiple requested items use multiple instances, groupIdentifier groups independently manageable requests, and RequestOrchestration is used for complex optional or timing relationships. Current source/medicationrequest/list-MedicationRequest-examples.xml still lists the medrx0343a/medrx0343b examples, and the example files still carry matching groupIdentifier values and intent="option". Later R6 dosage work changed MedicationRequest.dosageInstruction to DosageDetails and moved the long grouping explanation out of the ElementDefinition comment into narrative guidance, so the absence of that long text on the element definition itself is not a missed application. FHIR-27885 has already been represented on the combined branch, and FHIR-47251 is a broader Resolved-change-required multiline-prescription issue that is not final Applied/Published scope for this seed.

AutoFHIR reconciliation:
This commit makes no source change. The current active source already preserves the FHIR-26687 result through the paired examples and nearby grouping guidance, while the later RequestOrchestration wording reflects the separately accepted FHIR-27885 grouping decision rather than a defect in FHIR-26687 application.
