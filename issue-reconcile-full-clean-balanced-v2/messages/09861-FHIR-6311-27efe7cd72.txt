FHIR-6311: Audit DataElement slicing clarification

Issue request:
FHIR-6311 was a Published/Persuasive with Modification DSTU1 change request for better slicing explanation because ElementDefinition slicing language was confusing when reached through DataElement. The final resolution was to revise the slicing documentation so it was not misleading and to add a DataElement-specific constraint prohibiting slicing.

Initial application:
The issue was applied in git-svn commit 1e811b34e851e8c8741288e74519eadb345ebb01 (#6311), which added a DataElement.element invariant "No slicing allowed" using not(exists(f:slicing)) and changed the ElementDefinition.slicing definition to qualify slicing as occurring "in a structure definition".

Additional context:
Current source/fhir.ini keeps ElementDefinition active but comments out DataElement resource, work group, acronym, and migration entries. DataElement was removed from the active resource build in commit 29576ed0ef9fe0107d69a45bbc638853621b3c37. The current ElementDefinition page and profiling page still present slicing as structural usage for constraining StructureDefinitions, and direct Zulip/Confluence searches found no FHIR-6311-specific community discussion that changes the source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The DataElement-specific constraint has no current build target, and the active ElementDefinition/profiling source already preserves the resolution's non-misleading StructureDefinition framing for slicing.

Recommendation:
Keep this audit commit as-is. No current core follow-up is needed unless HL7 reintroduces a DataElement-like artifact, in which case the old no-slicing rule should be reassessed for that artifact.
