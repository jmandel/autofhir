FHIR-15977: Audit best-practice documentation

Issue request:
FHIR-15977 was Published/Persuasive for STU3 and asked FHIR-core to expose best practice recommendations using a specific extension on invariants, to extend spreadsheet/tooling support, to mark best practices as informative, to include a reason and known exceptions for each best practice, and to provide a summary view linking to best practices across the specification.

Initial application:
The request was applied in the historical SVN-imported Git history. Commit 5193d38922ed2de51aa37976aab8dd8fba0ade14, "GF#15977 - add support for best practice invariants," added the best-practices page, conformance-rule text for guideline/best-practice constraints, documentation and hierarchy links, generated-list support, validator/tooling changes, and a narrative best-practice example. Jira also records SVN revisions 13913 and 13914; revision 13914 is d3d530e80fb52900c8832c3a6dddbba499069956, a follow-up build fix in the same application sequence. Earlier commits had already created the ElementDefinition best-practice extension and spreadsheet support.

Additional context:
Current source still carries the active informative best-practices page and the generated <%best-practice-list%> placeholder, conformance-rules.html still defines "Guideline" as a warning marked with the elementdefinition-bestpractice extension and links to the full best-practice list, and active built resources such as DomainResource include best-practice constraints with the explanation extension. The extension definitions themselves now live in the FHIR Extension Pack, where elementdefinition-bestpractice and elementdefinition-bestpractice-explanation remain active and describe the validator/enforcement and explanation semantics. Zulip implementation discussion for GF#15977 confirms the intended interpretation: best practices are informative, rendered separately, not enforced by default, but available for validators to enforce when requested. A current build.fhir.org check shows the generated summary page listing best-practice constraints with their explanations.

AutoFHIR reconciliation:
No source change was made. The current core source and Extension Pack split already implement the requested mechanism and summary view, and adding redundant prose to the core page would not materially change implementer understanding.

Recommendation:
Keep this audit commit as-is. Future best-practice content should be handled through the existing best-practice invariant/narrative mechanism and should include useful explanation text, including exceptions where they are known, rather than changing the core infrastructure for FHIR-15977.
