FHIR-19500: Audit launch context operation scope

Issue request:
FHIR-19500 was a Published / Persuasive with Modification FHIR-core Questionnaire change request from STU3. It asked to rename questionnaire-context to questionnaire-launchContext, define standard launch contexts aligned with SMART launch context, make context.type repeatable, and add a context parameter with name/value content to Populate, Extract, and nextQuestion operations.

Initial application:
The Jira comment records GH#0cdfeece. Commit 0cdfeece691a6aa51e2cc015664e5230a9c534bd merged HL7/Questionnaire_stuff and touched the historical Questionnaire and rendering-extension spreadsheet sources where these STU3 Questionnaire/SDC artifacts lived. Later source reorganization removed those spreadsheet-based Questionnaire extension and operation artifacts from the active core build.

Additional context:
In the current core checkout, source/fhir.ini still lists Questionnaire, QuestionnaireResponse, and OperationDefinition as active resources, but the active Questionnaire and QuestionnaireResponse operation lists are empty. The only current core references to Questionnaire-populate are generic OperationDefinition derivation examples, not active Questionnaire operation definitions. The launchContext extension and Questionnaire population operations now live in the SDC IG/package outside this FHIR core checkout; the current SDC build contains sdc-questionnaire-launchContext and context parameters on the populate, populatehtml, and populatelink operations.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. Re-adding launchContext or SDC Questionnaire operation definitions to core would edit artifacts that are no longer in the current core build and would duplicate the external SDC source of truth.

Recommendation:
Keep this external-repo audit commit for core. If any remaining discrepancy needs action, such as reconciling the old Extract/nextQuestion wording against current SDC operation design, handle it in the SDC IG repository/work group process rather than in HL7/fhir core.
