FHIR-16976: Audit CodeableConcept coding wording

Issue request:
FHIR-16976 was a Published/Persuasive FHIR-I change request from the STU3 Core Norm ballot asking to clarify the Requirements text for CodeableConcept.coding. The requested clarification was to say that coding allows alternative encodings within a code system and translations to other code systems, avoiding the ambiguity that "within a code system" modified translations.

Initial application:
The issue was previously applied in SVN/Git as commit 8dccaebe4c5e3d09baba92746ee9962fce460caf, "GF#16976 - clarify requirements on codeableconcept", with git-svn revision 14292 matching the Jira comment. That commit changed source/datatypes/codeableconcept.xml from the old ambiguous sentence to the requested clarified wording.

Additional context:
source/fhir.ini actively lists CodeableConcept under [types], so source/datatypes/codeableconcept.xml is in current build scope. The current row for CodeableConcept.coding contains "Allows for alternative encodings within a code system, and translations to other code systems". A 2017 Zulip thread shows the old wording caused confusion about whether multiple codings may have different meanings, while later FHIR-57092 is a Triaged Observation-specific issue and is not a final datatype-level reversal.

AutoFHIR reconciliation:
This commit intentionally makes no source change because the current active datatype source already contains the clarified wording approved and applied for FHIR-16976. Adding more text here would be redundant for this issue and could overlap with later, unresolved Observation-specific work.

Recommendation:
Keep this no-change audit commit as-is. Revisit only if FHIR-57092 or a later final FHIR-I/OO decision explicitly changes the general CodeableConcept.coding requirements or adds Observation-specific guidance.
