FHIR-16814: Audit ValueSet abstract grouper resolution

Issue request:
FHIR-16814 was Published with resolution Persuasive with Modification. It observed that ValueSet.expansion.contains has abstract support but ValueSet.compose does not, and the approved disposition was to add an extension on ValueSet.compose.include defining an abstract grouper and its member concepts or nested groupers so servers could generate abstract expansion.contains group entries for UI navigation.

Initial application:
The issue was applied in core by commit c2bc0211921c8f7bbac3abeb6645aba6788402e2 (svn revision 14031), which added the valueset-expand-group and valueset-expand-rules extensions to the ValueSet extension spreadsheet and linked them from the ValueSet hierarchy narrative. The valueset-expand-group definition matched the requested compose.include grouper model: optional code/display, required member codes or nested group references, and guidance that group codes were for expansion hierarchy rather than value set membership.

Additional context:
The same 2018 Zulip thread separated the abstract/grouping use case from the inactive or historical-member use case, which was tracked separately as FHIR-17276. Later R5 ballot issues FHIR-30702 and FHIR-30703 reopened the expand-group/expand-rules design and Vocab resolved to remove both extensions because they were underspecified. Commit 21e116ef55767a9a3f577976f0617889dfc527d9 removed the active core StructureDefinitions, the hierarchical example, IG references, and the ValueSet hierarchy links. The combined branch already contains audit commits for FHIR-30700, FHIR-30702, and FHIR-30703, so this seed should not publish duplicate related decisions. The FHIR Extension Pack now carries valueset-expand-group only as a retired/deprecated external artifact with the reason that it was underspecified and not usable.

AutoFHIR reconciliation:
This is an empty no-change audit commit. The current core ValueSet source is in build scope and now correctly says that CodeSystem and ValueSet.compose offer no direct support for hierarchies and groups, while the ValueSet $expand operation text still permits servers to introduce arbitrary groups based on extensions in the definition or other server knowledge. Reintroducing the original extension or its ValueSet-page links would conflict with the later published Vocab removal decision.

Recommendation:
Keep this audit commit as-is. No current FHIR core source change is needed for FHIR-16814; do not restore valueset-expand-group to core unless a new work-group decision replaces the later FHIR-30702 removal. Any future change to the retired Extension Pack copy should be handled in HL7/fhir-extensions, not in this core checkout.
