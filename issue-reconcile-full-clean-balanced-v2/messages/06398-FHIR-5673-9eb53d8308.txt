FHIR-5673: Audit Timing meal event support

Issue request:
FHIR-5673 was a Published FHIR-core datatypes change request, resolved Persuasive with Modification, asking that the Timing datatype support instructions such as "with meals". The request proposed making duration/unit elements optional with an invariant and adding meal-related event timing codes; the final Jira resolution says to use the resolution to FHIR-3841.

Initial application:
FHIR-3841 was Published/Persuasive with Modification and its Jira comments cite svn revision 4758. In the git-svn history, commit db55db7414cc49a9bd93c668c9fd19c3de26fccf, dated 2015-03-20, has subject "#3841: restructure timing + fix improper system references" and introduced the meal EventTiming rows into source/datatypes/timing.xml. The current source still has Timing.repeat.duration and Timing.repeat.durationUnit as 0..1, the durationUnit-required invariant, Timing.repeat.when bound to EventTiming, and the meal codes C, CM, CD, and CV.

Additional context:
source/fhir.ini lists Timing as an active datatype and marks it normative, so source/datatypes/timing.xml is current build-scope source. Later FHIR-8697 added Timing.repeat.offset and before/after-meal event codes for cases such as "30 minutes before meals"; it did not remove or narrow the FHIR-5673 meal support. A 2023 Zulip implementers thread clarified that Timing meal codes are for scheduled meal-time timing, while "with every meal" without a fixed frequency may be an as-needed/precondition pattern rather than a defect in the original FHIR-5673 application.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build-scope Timing source already satisfies FHIR-5673: repeat.when can carry EventTiming code C for "at a meal" and specific meal codes CM, CD, and CV, and the duration/unit cardinality and invariant from the referenced Timing restructure are present.

Recommendation:
Keep this no-change audit as-is. No core FHIR source follow-up is needed for FHIR-5673; any future distinction between scheduled meal-time dosing and truly "every meal" trigger/precondition semantics should be handled by a separate work-group decision.
