FHIR-35969: Audit BDP ISBT mapping reconciliation

Issue request:
FHIR-35969 was a Published/Persuasive R4-to-R5 change request for BiologicallyDerivedProduct asking the OO work group to add ISBT 128 mapping information for product identifiers, biological source, processing facility, division, expiration, collection source, storage temperature, and the property mechanism used for unmapped ISBT 128 data elements including collection type.

Initial application:
Jira comments cite 3886ffdcccef139c80d2ac8dc3acef96304b35e8 and a later mapping update. Git history shows 3886ffdcccef139c80d2ac8dc3acef96304b35e8 first added individual ISBT data-element mapping spaces and element mappings, then 1b01e42a9e3949882bee2d23cf07164abe073316, explicitly titled for FHIR-35969, consolidated those into the current ISBT128Code mapping space with the base ISBT URI and preserved the productCode, identifier, biologicalSource, processingFacility, division, expirationDate, collection.source, storageTempRequirements, property.type, and property.value[x] guidance.

Additional context:
The active fhir.ini entry keeps BiologicallyDerivedProduct in the current build. Later BDP changes renamed biologicalSource to biologicalSourceEvent and split collection.source into sourcePatient/sourceOrganization, but the relevant ISBT mapping text was carried forward to biologicalSourceEvent and sourcePatient. Confluence HCP minutes from June 2022 recorded that FHIR-35969 was not fully applied for the productCode binding; later related issues FHIR-36031, FHIR-36719, FHIR-36720, and FHIR-37978 supplied the current productCode and property.type value set bindings and example ISBT codes, including Collection Type. A later 2025 source cleanup deliberately removed over-broad general ST-027 prose from property.value[x], leaving the ST-027 context in the property type value set where it is scoped to ISBT data elements.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source defines the ISBT 128 mapping space, maps the current BDP elements requested by FHIR-35969, binds productCode to the Biologically Derived Product Codes value set, and binds property.type to a value set whose examples include collectiontype with an ISBT CollectionType URI. Restoring literal property/value prose to general element comments would duplicate later terminology artifacts and risk reintroducing text that was intentionally removed as too broad.

Recommendation:
Keep this no-change audit commit as-is. If the work group wants the rendered mapping page to show additional explanatory text for property/type/value rows rather than relying on the current element comments and value set, that should be handled as a new editorial clarification rather than as an unapplied FHIR-35969 source correction.
