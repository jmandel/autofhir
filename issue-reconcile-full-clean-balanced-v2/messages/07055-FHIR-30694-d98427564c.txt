FHIR-30694: Audit canonical version syntax wording

Issue request:
FHIR-30694 was Published/Persuasive for R5 and asked to reword the references page's canonical URL example so implementers would not confuse the canonical pipe syntax or the GET version parameter with ValueSet.meta.versionId. The requested clarification was that both syntaxes identify ValueSet.version.

Initial application:
The issue was applied by historical commit 51a37750099b1d16678edff20f41387c56e87d2b, which changed source/references.html to replace the confusing "version specific reference" wording with text saying that resolving the pipe syntax is equivalent to using a GET with the version parameter and that both examples specify the ValueSet.version value rather than ValueSet.meta.versionId.

Additional context:
A Zulip thread immediately before the applying commit shows Grahame Grieve questioning the proposed phrase because the GET example is not itself a reference; Josh Mandel suggested the wording that now appears in the source, and Gino Canessa confirmed the confusion was around the overloaded word "reference". Later canonical-version work, including FHIR-39270 and the version matching section, touched nearby text but did not reverse or weaken this clarification. The source/references.html page is current build source for the references module; source/fhir.ini maps the reference datatype documentation to the references page.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already says that resolving <code>|0.8</code> is equivalent to using <code>version=0.8</code>, and explicitly states that both examples specify <code>ValueSet.version</code> and do not relate to <code>ValueSet.meta.versionId</code>.

Recommendation:
Keep this empty audit commit as-is. No further core-source change is needed for FHIR-30694 unless a future work group decision changes canonical version resolution guidance.
