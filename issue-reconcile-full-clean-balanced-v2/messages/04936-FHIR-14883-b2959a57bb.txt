FHIR-14883: Audit ExpansionProfile supplement limitation

Issue request:
FHIR-14883 was a Published/Persuasive Vocab change request raised against STU3 ExpansionProfile.designation.include/exclude because those controls could not handle code system supplements that add designations to a base code system. The resolution allowed a "Limitations of Expansion Profiling" section and said that complex needs beyond ExpansionProfile capabilities must be handled in the value set definition, by a new value set version, or by a new value set.

Initial application:
The Jira comment identifies svn revision 14650. In git, 9fa09ef6ce1574da29ddfe07e5b36abc254ff6a7 (GF#14883) added a Code System supplements warning and a Limitations section to source/valueset/valueset-notes.xml. The limitations prose remains in the current source and says existing expansion parameters cover most use cases but not every combination or code-system-version interplay, and that implementers may need their own value sets.

Additional context:
ExpansionProfile is no longer in the current build: source/fhir.ini keeps ValueSet active and comments ExpansionProfile as dropped, with no source/expansionprofile files tracked. The later GF#16337/GF#16490 implementation removed ExpansionProfile and moved its behavior into ValueSet.$expand parameters. Current ValueSet notes and $expand operation source include the in-build replacement surface: includeDesignations/designation, useSupplement, rules that compose.include/exclude SHALL NOT reference supplements, and guidance to declare required supplements by valueset-supplement or useSupplement. Related FHIR-14884 was resolved no-change by pointing back to FHIR-14883; related FHIR-14885 has already been audited separately on the combined branch. Confluence block-vote material lists the FHIR-14883/FHIR-14884/FHIR-14885 family, and Zulip/Confluence searches found no conflicting later community decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The seed issue's requested limitation is already represented in the current ValueSet notes, and the original ExpansionProfile element is outside the current build. Reintroducing ExpansionProfile-specific prose would not improve the current specification and would risk confusing implementers about the active $expand/useSupplement mechanism.

Recommendation:
Keep this no-change audit commit as-is. Future work, if any, should be filed against current ValueSet.$expand or supplement behavior, not against the retired ExpansionProfile resource.
