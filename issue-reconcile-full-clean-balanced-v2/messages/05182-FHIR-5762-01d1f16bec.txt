FHIR-5762: Audit MedicationDispense text dosage instructions

Issue request:
FHIR-5762 was Published/Persuasive for DSTU1 and asked to add text dosage instructions on MedicationDispense. The only Jira comment said consistency with Prescription seemed reasonable, so the relevant intent is that MedicationDispense support a human-readable dosage instruction comparable to the prescribing side.

Initial application:
No git commit explicitly mentioning FHIR-5762 was found. The historical source nevertheless shows the request was applied in substance: commit 80c2f73ea4 added MedicationDispense.renderedDosageInstruction with the definition "Full representation of the dosage instructions" and explanatory text for the dose represented in all dosage instructions.

Additional context:
MedicationDispense is active in source/fhir.ini. Later R6 dosage redesign work changed the representation: FHIR-51540 introduced DosageDetails and moved renderedDosageInstruction into DosageDetails.renderedInstruction, and FHIR-54014 made DosageDetails.renderedInstruction required. The current MedicationDispense.dosageInstruction element is 0..1 DosageDetails, DosageDetails.renderedInstruction is 1..1 markdown for the full human-readable dosage intent, and individual Dosage entries still have Dosage.text for free-text SIG content. The old MedicationDispense.renderedDosageInstruction name remains only as an fhir.ini migration mapping and in a generated-looking SVG diagram, not in the authoritative StructureDefinition source.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source already satisfies FHIR-5762 under the current R6 dosage model, and adding a parallel MedicationDispense-specific text element or duplicative prose would conflict with the later DosageDetails design.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-5762 unless the Pharmacy work group later reopens the broader DosageDetails design; the stale SVG mention should not be edited as a standalone source fix because authoritative source and fhir.ini already describe the current path.
