FHIR-29115: Audit oxygen saturation component value binding

Issue request:
FHIR-29115 was Applied with a Persuasive with Modification resolution for the R4 observation-oxygensat profile. The issue asked to clarify the confusing `Observation.component.value[x]` presentation where a polymorphic type list appeared alongside UCUM vital-signs binding/Quantity-only requirement language. The final Jira resolution called for allowing other components and removing the inappropriate base binding, and the later Jira comment records that the newer vital-signs updates removed the problematic component MustSupport constraints and left no binding on non-Quantity value[x] choices.

Initial application:
No git commit explicitly mentioning FHIR-29115 was found. The effective application appears to have happened through the broader vital-signs rework and follow-up tickets: FHIR-46418 reorganized the vital-signs profiles, FHIR-47136 removed MustSupport from non-blood-pressure components and reorganized component profiling, and FHIR-44721/FHIR-47136 changed `Observation.component.valueQuantity` to the UCUM all-codes value set. The current oxygen saturation profile no longer contains an `Observation.component` differential at all.

Additional context:
The original Zulip thread confirms that the reporter was asking about the R4 oxygen saturation detail page's component value type/binding contradiction. The active Observation resource and Observation Vital Signs IG include the oxygen saturation profile in the current build. In current source, the base vital-signs profile leaves `Observation.component.value[x]` generally unbound and places only a preferred all-UCUM binding on the `valueQuantity` type slice. The oxygen saturation-specific profile constrains only the main `Observation.value[x]:valueQuantity`, so the old confusion about component `valueBoolean` and required UCUM units is no longer present.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already satisfies the applied FHIR-29115 decision without adding redundant slicing or prose: arbitrary components remain possible, non-Quantity component values are not terminology-bound, and the only component Quantity binding is preferred to all UCUM codes.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-29115 unless a future publisher/regeneration issue reintroduces a stale generated component row for the oxygen saturation profile.
