FHIR-13687: Audit RequestGroup code application

Issue request:
FHIR-13687 was Published with a Persuasive resolution for STU3 to add a root RequestGroup.code element, CodeableConcept 0..1, so RequestGroup could identify its overall nature similarly to List.code; the resolution also noted that an example binding was needed.

Initial application:
The request was applied before this reconciliation in git commit 571fea972c605378a443f9fa8c2bace66e61a178, whose subject explicitly cites #13687 and whose historical RequestGroup spreadsheet contains a RequestGroup.code row with cardinality 0..1 and type CodeableConcept. The current source no longer has a source/requestgroup folder because later FHIR-24619 work renamed RequestGroup to RequestOrchestration.

Additional context:
The current build scope in source/fhir.ini actively includes requestorchestration=RequestOrchestration and maps the old RequestGroup name to RequestOrchestration. Current RequestOrchestration source contains the root code element as CodeableConcept 0..1 with an example RequestCode binding to action-code-example, and its code search parameter is present. The Jira comment asking whether PlanDefinition also needed the element was resolved by saying PlanDefinition.useContext covers that use case; current PlanDefinition source contains useContext and no PlanDefinition.code, which is consistent with that scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current built resource has the element requested by FHIR-13687 under its current name, RequestOrchestration, with the expected cardinality, type, summary flag, example binding, and matching search parameter.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-13687 unless the work group separately decides to change RequestOrchestration.code semantics or its example binding.
