FHIR-30371: Audit package manifest legacy field documentation

Issue request:
FHIR-30371 was a Published FHIR-I change request, resolved Not Persuasive with Modification for R5. It asked why older core package.json files used fhir-version-list while the package manifest specification used fhirVersions, and the accepted resolution was to document that some legacy packages use the old name without changing those old packages because that would be breaking.

Initial application:
The issue was applied by commit 4628fa083ba471b9104428a4407d4b71dfdb7086, which added the fhirVersions row to source/packages.html and included the sentence that in some older packages the property was named fhir-version-list. That source remains present on the current combined branch.

Additional context:
source/packages.html is the FHIR NPM Packages page and source/hierarchy.xml includes packages.html in the active specification navigation, so the documented package manifest table is in current build scope. The 2019 Zulip package-spec thread shows the history: fhir-version-list was first added for package.json metadata, then renamed to fhirVersions for current packages, leaving the old spelling as legacy package behavior. FHIR-I minutes on 2022-03-01 record FHIR-30371 as Not Persuasive with Modification. The Jira resolution text says fhir-versions-list, but the issue description and historical discussion use fhir-version-list, which is what the current source documents.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active package documentation already tells implementers to use fhirVersions and warns that some older packages used fhir-version-list, matching the final Jira decision and avoiding a breaking change to old packages.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed in core unless the package manifest specification is later moved or rewritten and the legacy fhir-version-list note is lost.
