FHIR-18234: Audit ShareableMeasure core migration

Issue request:
FHIR-18234 was a Published/Persuasive CQI change request from STU3 asking core to define a ShareableMeasure profile, with publishing metadata such as url, version, name, title, experimental, description, date, and publisher treated as required expectations for sharing measures.

Initial application:
The issue was applied by commit 01c412b836dcd45e9d67ed45c4e6a13846f13efa, titled "GF#18234: Added ShareableMeasure profile", which added the Measure shareable spreadsheet input. Later source history converted that content into explicit structuredefinition-profile-shareablemeasure.xml source and continued to update it with the surrounding shareable/publishable profile family.

Additional context:
The current source is governed by later applied issue FHIR-48393, which explicitly listed ShareableMeasure and PublishableMeasure as already moved to CRMI and resolved to remove these profiles from the base specification for R6. The current Clinical Reasoning and Shareable pattern pages tell implementers to use the CRMI profiles; the active Measure example that needs a shareable profile declares http://hl7.org/fhir/uv/crmi/StructureDefinition/crmi-shareablemeasure. The only remaining core source mentions of the old http://hl7.org/fhir/StructureDefinition/shareablemeasure canonical are the historical OID reservation and generated history artifacts, not an active current profile definition.

AutoFHIR reconciliation:
This audit intentionally makes no source change. Reintroducing source/measure/structuredefinition-profile-shareablemeasure.xml would conflict with the later applied R6 decision to remove use-case profiles from core, and the current source already points implementers to the CRMI location for ShareableMeasure behavior.

Recommendation:
Keep this no-change audit commit. Future work on ShareableMeasure constraints should occur in CRMI unless a new work-group decision explicitly reverses FHIR-48393 and brings the profile back into core.
