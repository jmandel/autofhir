FHIR-14806: Audit Appointment duration guidance

Issue request:
FHIR-14806 was a Published PA change request, resolved Not Persuasive with Modification, asking for actual start/end support when Appointment.minutesDuration is less than the difference between Appointment.start and Appointment.end. The accepted resolution said actual occurrence timing belongs on the resulting Encounter, planned appointment timing remains on Appointment, and Appointment.minutesDuration should include examples where duration legitimately differs from the start/end interval without adding an invariant.

Initial application:
The issue was applied in historical commit 1ced9ed8a8 (GF#14806), which updated source/appointment/appointment-spreadsheet.xml to clarify Appointment.minutesDuration with the current examples: estimated appointment time, a 30-minute appointment request without exact times, and a planned 15-minute break in a longer appointment. Later source-format refactors, including the R4B conversion to structuredefinition-Appointment.xml and generated mapping-exception files, preserved that wording.

Additional context:
Appointment is active in source/fhir.ini, and the current build-scope source still states that Appointment may result in one or more Encounters and that fulfillment details are handled by Encounter. Encounter is also active in source/fhir.ini, and Encounter.actualPeriod currently defines the actual start and end time of the encounter. Later published issue FHIR-36814 adjusted the scheduling/requestedPeriod ordering and added comments to Appointment.start/end, but it did not remove the GF#14806 minutesDuration examples or require actual occurrence timing fields on Appointment.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current Appointment.minutesDuration definition already contains the example guidance required by FHIR-14806, the active Appointment narrative points fulfillment details to Encounter, and Encounter.actualPeriod supplies the actual start/end place identified by the resolution.

Recommendation:
Keep this no-change audit as-is. No follow-up core source edit is needed for FHIR-14806 unless PA later decides to rework the broader Appointment.start/end versus Encounter.actualPeriod wording in a new tracker.
