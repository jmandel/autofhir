FHIR-35972: Audit Specimen support in Group members

Issue request:
FHIR-35972 was Published as Persuasive for R5. It requested adding Specimen to Group.member.entity so Observation workflows could represent multiple specimens through a Group, with a desired restriction that specimen Observation usage only reference groups of Specimen resources.

Initial application:
The Jira comment says the issue was added to the build with commit 7816ce80374c4e5d31d1a5cb48b80b0701744337. Git history confirms that commit added http://hl7.org/fhir/StructureDefinition/Specimen as a Group.member.entity target profile in source/group/structuredefinition-Group.xml. The current combined source still has that target profile in the active Group resource and includes a specimen Group.type code.

Additional context:
source/fhir.ini actively lists group=Group, so the inspected Group source is in build scope. The related FHIR-34002 Observation issue was separately applied and audited on the combined branch; current Observation.specimen allows Reference(Group) and has obs-9 requiring a referenced Group to contain only Specimen members. OO and FHIR-I minutes show the intended split: add Specimen to Group.member.entity, then enforce the specimen-only usage on Observation.specimen. Later FHIR-39269 explicitly decided not to remove Specimen from Group and added explanatory Group narrative, and later FHIR-52918 broadened other Group member types while retaining Specimen.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current source already satisfies FHIR-35972: Group.member.entity allows Specimen, Group.type includes specimen and says members must match Group.type, and Observation.specimen carries the context-specific Specimen-only Group invariant requested by the related Observation work.

Recommendation:
Keep this no-change audit commit as-is. No core follow-up is needed for FHIR-35972 unless a future work group decision changes the Observation multi-specimen modeling pattern.
