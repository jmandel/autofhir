FHIR-17677: Audit migrated SupplyRequest compartment request

Issue request:
FHIR-17677 was Published/Persuasive for STU3 and requested that SupplyRequest gain a subject search parameter over SupplyRequest.deliverTo and that this patient-linked search be included in the Patient compartment.

Initial application:
The Jira comment identifies commit 98752dd6c14e0ad544430fd0d7457f25282173d0. That commit changed source/compartments.xml so the SupplyRequest Patient compartment entry used subject instead of requester, and changed the then-active SupplyRequest spreadsheet as part of the same preapplication batch. The current inactive SupplyRequest search-parameter bundle still contains SearchParameter/SupplyRequest-subject with code subject and expression SupplyRequest.deliverTo.

Additional context:
The current core build no longer registers SupplyRequest as an active resource in source/fhir.ini. Later commit 3b38b80cf23f9cbb306fab8fcedb293315478c32 explicitly removed SupplyRequest and other immature OO resources from source/fhir.ini and source/compartments.xml, while source/ballot-intro.html and source/history.html point SupplyRequest to the HL7 OO incubator IG. FHIR-52991 is a later unresolved/Triaged OO incubator issue about broader SupplyRequest/SupplyDelivery subjects, search parameters, and compartment membership, so it is context but not a final core decision to apply here. Local Zulip searches found no conflicting discussion; Confluence OO minutes confirm the 2018 block vote context.

AutoFHIR reconciliation:
No core source file was changed. Re-adding SupplyRequest to the core compartment spreadsheet or editing inactive source/supplyrequest artifacts would not change the current core build and would conflict with the later resource migration to the OO incubator.

Recommendation:
Keep this empty external-repo audit commit for core. If the OO work group wants to revisit SupplyRequest subject/search/compartment behavior, handle it in the OO incubator workflow, likely through FHIR-52991 or a successor issue, rather than in the current core repository build.
