FHIR-32295: Audit Slot eligibility search support

Issue request:
FHIR-32295 was a Published FHIR-core Slot change request, resolved Persuasive with Modification for R5, asking how Slot availability could express eligibility or constraints such as insurance plan, sex, or size requirements. The approved resolution chose not to add eligibility fields directly to Slot; instead, Slot.serviceType would reference HealthcareService and HealthcareService would be searchable by eligibility and characteristic for chained Slot discovery.

Initial application:
The resolution was applied in two steps. FHIR-22687 first changed Slot.serviceType to CodeableReference(HealthcareService) and added the Slot service-type-reference search parameter in commit fb45d82237b60ab7d01a326d649ba620e6a26e87. FHIR-32295 then added the HealthcareService eligibility search parameter in commit 4cb0d550b72c100c3e9e5c441590e37980d0751f; HealthcareService.characteristic search support was already present.

Additional context:
source/fhir.ini actively includes both Slot and HealthcareService as PA-owned resources in the current build. The linked Zulip scheduling discussion supports the FHIR-22687 serviceType/HealthcareService modeling direction. PA minutes in May and September 2022 record that FHIR-32295 was handled through the HealthcareService catalog updates and voted Persuasive with Modification. Later FHIR-39127 reported that this did not satisfy every Slot-level eligibility use case, but PA resolved that later issue as Resolved - No Change and recommended a local Slot extension rather than a core Slot element. FHIR-41782 later expanded HealthcareService.eligibility itself, reinforcing that eligibility remains modeled on HealthcareService.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already provides the approved chain: Slot.serviceType.reference points to HealthcareService, Slot has service-type-reference for reference search, and HealthcareService has eligibility and characteristic token search parameters.

Recommendation:
Keep this audit commit as-is. Do not add redundant Slot-level eligibility prose or elements for FHIR-32295; any project needing Slot-specific constraints beyond HealthcareService can follow the later FHIR-39127 guidance and use a local extension unless PA makes a new core change.
