FHIR-17483: Audit addItem preauthorization structure

Issue request:
FHIR-17483 was Published with a Persuasive with Modification resolution for ClaimResponse and ExplanationOfBenefit. It requested that addItem support unsolicited preauthorization detail by restoring a three-tier addItem/detail/subDetail structure, including key line details, service dates, and service locations; the modification added addItem.provider 0..* Reference(Practitioner|PractitionerRole|Organization) and removed programCode from AddItemDetail and AddItemSubDetail.

Initial application:
The issue was applied in git by 52fcd5d684 (Tracker #17483), which changed the then-authoritative ClaimResponse and ExplanationOfBenefit spreadsheets to add addItem.provider and disable addItem.detail.programCode and addItem.detail.subDetail.programCode. Later source rework migrated these spreadsheet definitions into the current StructureDefinition XML files.

Additional context:
ClaimResponse and ExplanationOfBenefit are active and approved resources in source/fhir.ini. The current StructureDefinition XML for both resources contains addItem.provider with the requested target profiles, contains addItem.detail and addItem.detail.subDetail with line-detail elements, keeps serviced[x] and location[x] at addItem level, and has no addItem.detail.programCode or addItem.detail.subDetail.programCode. Searches of Jira, Zulip, and Confluence found no later decision or community discussion reversing this issue.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source edits were made because the current build-scope source already carries the requested structure and the modified programCode/provider placement.

Recommendation:
Keep this audit as-is. Future work should only revisit FHIR-17483 if the FM work group decides to change addItem detail-level service date/location semantics; no current correction is needed for the published FHIR-17483 decision.
