FHIR-12908: Audit retired DSTU2 IG package fix

Issue request:
FHIR-12908 was a Published FHIR-core change request raised against DSTU2 reporting that the Argonaut Data Query IG's validator.pack, downloads.xml.zip, and download.json.zip artifacts contained pre-release STU3 StructureDefinitions instead of DSTU2 definitions. Jira records resolution Persuasive/Auto-deferred, with Grahame Grieve commenting in March 2018 that it was already done.

Initial application:
No source commit was found that explicitly mentions FHIR-12908. The relevant historical IG Publisher code was changed in March 2018: cdef2faff switched dependent IG loading to validator.pack, and dc0eeec9 changed IG Publisher version handling so generated validator.pack contents and spec maps carry/use the IG version and serialize metadata resources through the correct DSTU2/DSTU3/current-version parser path.

Additional context:
The affected implementation was the old in-repository IG Publisher under tools/java/org.hl7.fhir.igtools. That publisher was removed from the FHIR core checkout by 56ceb0df with the commit subject "Remove IG publisher (it's gone to Maven)". The current checkout has no local Publisher.java sources and instead runs org.hl7.fhir.tools.publisher.Publisher from the Maven kindling dependency. The current source/igs.xml keeps the old Argonaut IG entry commented out, so the reported DSTU2 Argonaut IG packaging path is not active current core build input. Later Zulip discussion about depending on Argonaut confirms the topic moved into package-server/IG Publisher dependency handling, not current core conformance source.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The historical bug was already addressed before publication, and the remaining implementation surface is outside this core source checkout/current build; editing current narrative or generated download links would not change the retired DSTU2 IG Publisher behavior described by the issue.

Recommendation:
