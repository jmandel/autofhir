FHIR-39336: Audit Timing time-bound extension disposition

Issue request:
FHIR-39336 is a Published/Persuasive FHIR-core change request asking for Timing to express a recurring action between one time-of-day and another. The Jira resolution says it was dealt with as part of the new extensions created for FHIR-38726.

Initial application:
No commit explicitly mentions FHIR-39336. The related FHIR-38726 application commit 5436c013 added an uncertainPeriod extension row to the active element-extensions spreadsheet, but that row applied to date and dateTime and used a Period value; it did not create a time-only bound extension. Commit dd468d4 later removed those extension definitions from the R5 core source.

Additional context:
The current core build still lists the element-extension spreadsheet in source/fhir.ini, but current core source has no uncertainPeriod, uncertainTime, or timing-uncertainDate definition rows. The surviving definitions are in the FHIR Extension Pack: uncertainPeriod is scoped to date and dateTime and uses valuePeriod, while timing-uncertainDate is retired/deprecated in favor of uncertainPeriod by FHIR-41649. FHIR-I minutes from 2023-02-13 record that FHIR-38726/FHIR-39336 raised the distinction between descriptive and prescriptive uncertainty, including the example of 2-4 pm, and that the group intended to pull this out of R5 and resume discussion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. A core-source edit would either recreate an extension that now belongs in the Extension Pack or make a semantic choice that the minutes show still needed work-group review. The current core checkout is therefore not the right place to add a time-only Timing bound definition during this reconciliation.

Recommendation:
Keep this audit commit as a human-review marker. FHIR-I should decide whether the FHIR Extension Pack needs a new time-only or Timing-specific extension for prescribed time windows; if so, that follow-up should be handled in the Extension Pack and then referenced from core only if the work group explicitly wants core narrative guidance.
