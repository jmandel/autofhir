FHIR-11082: Audit access-control wording application

Issue request:
FHIR-11082 was a Published/Persuasive Security WG change request for the FHIR-core security page, raised against DSTU2 section 6.1.0.2. It asked to replace the narrow chained-search access-control paragraph with broader Access Control Considerations wording covering all potential RESTful access methods: CRUD, search including chained search and _include/_revinclude, security labels, aggregate resources such as Bundle/Composition/Group/List, operations, batch/transaction, and Break the Glass.

Initial application:
The issue was applied by d6bec27176add2738ac0b05bd3dddcc177ab67ff, the 2016 Security WG update commit for GF#11082 and other security issues. That commit removed the old chained-search paragraph from source/security.html and inserted the Access Control Considerations heading and requested list. Current source/security.html still contains that section and all substantive requested bullets, with later editorial/current-style updates such as several/MAY/SHOULD wording, title-cased operation names, and a maintained Break the Glass link.

Additional context:
source/hierarchy.xml lists source/security.html as the Security page under the Security and Privacy module, and source/secpriv-module.html links it as Security Principles, so this is current build-scope source. Later security-page maintenance, including the already-published FHIR-53885 reconciliation, moved Break the Glass material onto source/security.html and corrected this section's link to security.html#break-the-glass. Focused Zulip and Confluence searches found only tracker/commit notifications or no hits, and no substantive community evidence that changes the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already conveys the approved rule that security implementations must consider all relevant FHIR access methods, including the exact access surfaces listed by FHIR-11082. Reverting later wording normalization or adding duplicate prose would not improve implementer understanding and could reintroduce stale Break the Glass navigation.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-11082 in core unless the Security WG opens a new issue to change the Access Control Considerations guidance substantively.
