FHIR-31348: Audit cross-version choice extension URLs

Issue request:
FHIR-31348 was a Published FHIR-core change request, resolved Persuasive for R5, asking the versions/compatibility guidance for cross-version extensions to clarify allowable extension URLs for polymorphic elements. The approved resolution said the URL for a polymorphic type is always the base element URL, such as http://hl7.org/fhir/5.0/StructureDefinition/extension-Observation.value; that a cross-version extension cannot convey a datatype already supported by the transmitted version; and that a cross-version extension referring to the same version being transmitted is an error.

Initial application:
The issue was directly applied by commit a6c96740e3c077f3b8c13ce548cfe58c25c80686, which updated source/versions.html in the cross-version extension section. That R5-era text gave the Observation.value example for added choice types and stated that an R5 cross-version extension is never valid in an R5 instance. Related commits for FHIR-36702 and FHIR-31721 expanded the same section with additional cross-version extension mechanics.

Additional context:
The current build later changed ownership of detailed cross-version extension mechanics. Commit f45505e5b3aa0d87effb991938750e627b782d2d intentionally removed the long versions.html bullet list and examples under the subject "R6 - pulling cross-version content that moves to guides", replacing them with a core overview, a package matrix, and the statement that further details are in the individual cross-version definition packages. The active source/versions.html page remains in build scope through publish.ini. The published R5-to-R4 cross-version package now defines the specific polymorphic Observation.value[x] case with official URL http://hl7.org/fhir/5.0/StructureDefinition/extension-Observation.value and no valueAttachment-specific URL, preserving the seed decision in the package-owned artifact.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Re-adding the removed FHIR-31348 prose to core versions.html would partially undo the later package-guidance refactor and duplicate details now owned by the XVer package surface. The current core page still defines the URL pattern, identifies when cross-version extensions exist, and directs implementers to the package matrix where the concrete choice-element URL is defined.

Recommendation:
Keep this audit commit as-is. If implementers still need more explicit choice-element examples, add or refine that guidance in the cross-version package/FAQ workflow rather than restoring duplicate detailed prose to core versions.html.
