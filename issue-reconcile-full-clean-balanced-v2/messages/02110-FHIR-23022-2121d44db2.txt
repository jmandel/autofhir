FHIR-23022: Audit AdverseEvent outcome value set

Issue request:
FHIR-23022 was a Published Patient Care change request, resolved Persuasive with Modification for R5, asking to loosen the required AdverseEvent.outcome binding to Preferred and replace the outcome value set with NCI/NCI Meta concepts for resolved, recovering, ongoing/not resolved, resolved with sequelae, fatal, and unknown outcomes.

Initial application:
The Jira-linked commits d9451304d0fedb2d5d36d62b9beb17040ffed6a3 and 5a2e5b8ae575e2fa59acf546a1c6e7cfe95c8c9e applied the issue in the then-authoritative AdverseEvent spreadsheet and valueset-adverse-event-outcome.xml by changing the binding from required to preferred and introducing an ncimeta outcome value set.

Additional context:
AdverseEvent is active in source/fhir.ini and assigned to Patient Care. A later Published Patient Care issue, FHIR-25556, explicitly revisited the FHIR-23022 preferred NCI binding and decided it was still too strict for international use; c31023666df8a405c7dd87ba90542d2eb32b7154 changed the binding to example and replaced the NCI compose with SNOMED CT descendants of 405533003. The combined branch already contains a FHIR-25556 audit commit, so this reconciliation should not duplicate that related decision.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope source has AdverseEvent.outcome bound with strength="example" to http://hl7.org/fhir/ValueSet/adverse-event-outcome, and that value set composes SNOMED CT descendants of 405533003. Reinstating the earlier preferred NCI value set from FHIR-23022 would conflict with the later FHIR-25556 decision.

Recommendation:
Keep this audit commit as-is. No FHIR-23022 source edit is needed unless Patient Care later reopens the outcome terminology family and supersedes FHIR-25556; any such future work should start from the current example SNOMED binding, not the retired preferred NCI state.
