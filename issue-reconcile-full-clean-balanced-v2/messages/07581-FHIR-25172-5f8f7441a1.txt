FHIR-25172: Allow token search mapping for uri

Issue request:
FHIR-25172 was Published/Persuasive with Modification for FHIR-core MessageHeader. The revised decision was to update the search summary table so that primitive type uri maps to search parameter type token, with notes that no token system/pipe is used.

Initial application:
The issue was discussed and reopened in FHIR-I minutes and Jira comments after an earlier resolution mentioned urn:ietf:rfc:3986. The explicit Jira-tagged source commit 69e9b87769 changed only the canonical search-rule mapping to include token, which helped current MessageHeader.event[x] and MessageDefinition.event[x] after their URI choice became canonical, but it did not make primitive uri map to token in the summary-table source.

Additional context:
Current search.html already contains the summary-table macro cell <%xcm uri:token%>, and the token section already states that token searches on uri elements do not use the pipe form. However, the current CI build still renders N for the primitive uri/token summary cell because source/fhir.ini [search-rules] listed uri=uri,reference. Zulip and Confluence evidence confirms the revised 2021 decision was to show uri as supporting token while leaving the token-system blank/not used.

AutoFHIR reconciliation:
Updated source/fhir.ini so the active [search-rules] entry for uri is uri,reference,token. This is the build-scope source that drives the existing search.html summary-table macro, so the generated summary table can now render the uri/token cell as supported without duplicating narrative text.

Recommendation:
Keep this commit. No further core source change is needed for MessageHeader-event or MessageDefinition-event because both current search parameter expressions select Coding or canonical, and canonical already maps to token; this commit completes the broader primitive-uri summary-table decision recorded by FHIR-25172.
