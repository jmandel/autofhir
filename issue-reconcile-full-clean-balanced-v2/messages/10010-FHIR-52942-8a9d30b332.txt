FHIR-52942: Audit chained search wording refinement

Issue request:
FHIR-52942 was an Applied/Persuasive with Modification FHIR-core search clarification for R6. It asked to clarify, based on a Zulip implementer discussion, how multiple chained parameters through a repeating reference are evaluated: each chain builds its own Patient set, the sets are joined with AND at the Patient level, and one Patient can match even when different practitioners satisfy the name and address criteria.

Initial application:
The issue was applied in commit 86b86856e0ada55dbe10a9ad631033525d5a471f, "FHIR-52942 - clarification for chained search filters", with the Jira comment linking HL7/fhir pull request 3967. That commit updated source/search.html to replace the older FHIR-14951/FHIR-34023 sentence with the current expanded explanation and list of evaluation steps.

Additional context:
FHIR-52942 belongs to the same chained-search paragraph originally added by FHIR-14951 and later clarified by FHIR-34023. FHIR-34023 is already represented on the combined branch. The Zulip thread that motivated FHIR-52942 shows implementer confusion about whether the example was OR logic; the answer preserved the existing rule and clarified that the AND occurs after each chain is evaluated independently.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current source/search.html contains the essential FHIR-52942 resolution: any matching general practitioner may satisfy each criterion, different Dr. Joe/Dr. Jane practitioners can make the Patient match, implementations find separate Patient sets and join them with AND at the Patient level, and Composite search parameters or _filter are the alternatives when grouped joins are required. The retained sentence "E.g., the chains are evaluated separately" is redundant but consistent with the approved semantics.

Recommendation:
Keep this audit commit as-is. No follow-up core source work is recommended for FHIR-52942 because the current Search page conveys the approved clarification without a semantic gap.
