FHIR-12624: Clarify DataRequirement extension paths

Issue request:
FHIR-12624 was Published with a Persuasive with Modification resolution for DSTU2. It asked DataRequirement to support referring to fields defined by extensions, using the QI-Patient birthTime extension as the concrete example. The Jira resolution said the request was addressed by the resolution for GF/FHIR-13593.

Initial application:
FHIR-13593 was applied by commit 74161b7e2037bc36b915e2d57d02743cc607ad3f, which changed DataRequirement.mustSupport to be constrained FHIRPath and linked the Simple FHIRPath Profile. That preserved the historical application path for FHIR-12624, but the current DataRequirement.mustSupport definition still repeated the older local restriction to identifiers, constant indexers, and .resolve(), which excluded the .extension("url") function now listed by the Simple FHIRPath Profile.

Additional context:
The original Zulip DataRequirement thread records the extension-field use case and Bryn Rhodes asking for a tracker to support it. A later implementers thread about DataRequirement paths says FHIRPath .extension() is the way to identify a specific extension. The combined branch already contains an audit commit for FHIR-13593, so this commit does not re-decide that related issue; it resolves the seed's extension-field ambiguity in the current source. source/fhir.ini lists DataRequirement as an active datatype mapped to the metadatatypes page, and source/documentation.html links fhirpath.html as a current source page.

AutoFHIR reconciliation:
Updated source/datatypes/datarequirement.xml so DataRequirement.mustSupport defers to the current Simple FHIRPath Profile and explicitly notes that .extension("url") can identify extension elements. Updated source/fhirpath.html so DataRequirement.mustSupport is included in the list of locations that use the restricted Simple FHIRPath language.

Recommendation:
Keep this commit. It is a narrow source correction for FHIR-12624 and should not be treated as a duplicate decision for FHIR-13593. If the work group wants DataRequirement filter paths or sort paths to receive the same explicit extension wording, handle that under the relevant filter-path issues rather than broadening this seed commit.
