FHIR-11162: Audit Procedure complication reconciliation

Issue request:
FHIR-11162 was a Published Patient Care change request with a Not Persuasive with Modification resolution. It asked how remedial treatments could be referenced when complications occurred, and the accepted disposition said remedial treatments can be represented as Procedures that are partOf another Procedure; Procedure.complication should support Condition references or a CodeableConcept; and the complication usage note should clarify that it documents a condition resulting from the procedure rather than the reason the procedure was performed.

Initial application:
The original application appears in git commit fd96fa1d81, whose message includes "#11162 Add Condition.complicationDetail to reference Condition". That commit added Procedure.complicationDetail as Reference(Condition) with the requested "result of the procedure, not the reason" requirements text while retaining Procedure.complication as the coded concept location.

Additional context:
Procedure is an active current-build resource in source/fhir.ini. A later Published Patient Care issue, FHIR-32511, intentionally merged Procedure.complication and Procedure.complicationDetail for R5 by making Procedure.complication a CodeableReference(Condition) and removing the separate complicationDetail element; source/fhir.ini records that version mapping. The current Procedure definition also keeps Procedure.reason as the place for why the procedure was performed, while Procedure.complication is defined as complications during or immediately after the procedure and binds to codes describing complications that resulted from a procedure. Later FHIR-47824 only added isSummary=true for Procedure.complication and did not change this semantic model.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope Procedure source already preserves the FHIR-11162 outcome after the FHIR-32511 refactor: remedial follow-up procedures can be linked through Procedure.partOf, and Procedure.complication is a CodeableReference constrained to Condition with coded text support. Re-adding the exact old split-element usage sentence would be redundant because the current complication, reason, and binding definitions already distinguish resulting complications from indications/reasons for the procedure.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-11162 unless Patient Care wants a new editorial issue to restate the result-versus-reason distinction more explicitly after the CodeableReference refactor.
