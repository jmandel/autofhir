FHIR-14539: Point code-system support guidance to TerminologyCapabilities

Issue request:
FHIR-14539 was Published/Persuasive for STU3. It asked the specification to clarify that the existence of a CodeSystem resource on a server declares the code system and its properties, not that the server supports that code system for terminology service behavior. The resolution placed server behavior capabilities in TerminologyCapabilities rather than CodeSystem, with a separate tracker for the access method.

Initial application:
The original application was git-svn commit 5f643f386b330d8acbf2ca54005bd1629e74c3d1 (svn revision 14023), which added the CodeSystem/TerminologyCapabilities distinction to CodeSystem and TerminologyCapabilities introductions. The companion access-method issue FHIR-17106 was applied by 8df77e615ed345d437f53121de0b1ffbb579663e, documenting GET [base]/metadata?mode=terminology. Current source retained those changes, but the active terminology-service page still told clients to publish additional supported external code systems through the CapabilityStatement supported-system extension.

Additional context:
The edited terminology-service.html page is an active terminology module page linked from source/terminology-module.html and source/hierarchy.xml; CodeSystem and TerminologyCapabilities are active resources in source/fhir.ini. Later Published issue FHIR-24698 made terminology-service requirements explicit: mode=terminology returns a TerminologyCapabilities resource with codeSystem entries for code systems supported for terminology services. FHIR-53787 separately proposes deprecating the CapabilityStatement supported-system extension in the FHIR Extension Pack, but it is only Submitted and was not decided here.

AutoFHIR reconciliation:
This commit updates the External Code Systems paragraph on terminology-service.html so the list of additional external code systems supported by a terminology server is published in the server's TerminologyCapabilities statement returned by the capabilities interaction with mode=terminology. It removes the stale CapabilityStatement supported-system example from core narrative without changing the external-pack extension definition.

Recommendation:
Keep this source change. It aligns the active terminology-service guidance with FHIR-14539, the existing CodeSystem and TerminologyCapabilities pages, and the later FHIR-24698 terminology-service requirements. Handle the broader extension-pack deprecation question in FHIR-53787 separately if that unresolved issue is approved.
