FHIR-23012: Audit Specimen.receivedTime receiver clarification

Issue request:
FHIR-23012 was a Published FHIR-core Specimen change request resolved Persuasive with Modification. It asked which receiver counts for Specimen.receivedTime when a specimen may pass through multiple systems or labs, and the approved resolution was to clarify the definition as the time the specimen is received by the testing laboratory for processing.

Initial application:
The Jira comment records application to build with c851b6a13ef0ec37c373b20765947671140c7dd5. That commit changed source/specimen/structuredefinition-Specimen.xml from generic receipt for processing to receipt by the testing laboratory, and the current blame still attributes the receivedTime short and definition wording to that commit.

Additional context:
source/fhir.ini actively lists specimen=Specimen, so source/specimen/structuredefinition-Specimen.xml is in the current core build scope. Current Jira search for Specimen.receivedTime found no later core tracker reversing this clarification. Later community discussion shows implementer questions about identifying the lab and possible use of Provenance for transfer/reception details, but no final conflicting source decision.

AutoFHIR reconciliation:
No source change was made. The current authoritative definition already says "Time when specimen is received by the testing laboratory for processing or testing," and the short says the time when the specimen is received by the testing laboratory, which preserves the approved clarification while allowing processing or testing as the relevant lab activity.

Recommendation:
Keep this audit commit as-is. If the work group later wants to model multiple transfers, receiving organizations, or custody events, that should be handled as a new decision rather than as further application of FHIR-23012.
