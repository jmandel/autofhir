The example contrasted a correct DL link to terminology.hl7.org/CodeSystem-v2-0203.html#v2-0203-DL with a broken build.fhir.org/v2/0203/index.html#DL-style link.

Initial application:
The Jira comment records "Kindling git 1c8fa28" as the application, but that short SHA is not present in this current Git checkout/history. The affected area was the former source/identifier-registry.html table, where Identifier Type links were generated through the old <%identifierlist%> include rather than by explicit per-code links in the checked-in page.

Additional context:
Later applied work superseded the local table surface that FHIR-30152 targeted. FHIR-37494 briefly added a build-scoped explanation of the table's Type column and used the canonical terminology.hl7.org CodeSystem-v2-0203 link. FHIR-35932 then removed the core identifier systems table and <%identifierlist%> include entirely after the identifier-system records were migrated to HL7 Terminology/THO. Related no-change audits for FHIR-35932 and FHIR-37494 are already present on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Recommendation:
Keep this audit commit as-is. If a future Identifier Type display/link problem is found, it should be handled in the authoritative THO/UTG content or in the renderer that produces terminology links, not by restoring or editing the removed core registry table.
