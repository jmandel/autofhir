FHIR-3274: Audit Patient.contact period application

Issue request:
FHIR-3274 was a Published/Persuasive Patient Administration change request from the Initial Draft asking to add a Patient.contact.period element because patient contacts can change over a time period, including v2 NK1-8/NK1-9 next-of-kin start and end dates. The resolution said Patient Contact should have Period added.

Initial application:
The issue was applied in the legacy Patient spreadsheet before the current XML source layout. Commit 5415ea6b967c8ea57da1ac0aa8743b04aa7867e6 explicitly says Task #3274 Patient.Contact.Period was applied again and converts the row from a draft !Patient.contact.period entry into Patient.contact.period with 0..1 cardinality and Period type. The current XML source was later introduced by the 2021 source rework and preserved the same element.

Additional context:
Patient is an active current-build resource in source/fhir.ini. The current authoritative Patient StructureDefinition contains Patient.contact.period as 0..1 Period, with a short/definition explaining the validity period for contacting the patient contact person or organization and a RIM effectiveTime mapping. Later Jira FHIR-16592 was Resolved - No Change because Patient.contact already had a period, which supports that no additional date element was intended. Zulip and Confluence searches found no conflicting community decision.

AutoFHIR reconciliation:
This commit makes no source change because the current active Patient source already carries the requested Patient.contact.period element and related generated-looking diagram output also links to it. Editing would be redundant and would not change implementer understanding.

Recommendation:
Keep this audit commit as-is. No follow-up is needed in core for FHIR-3274 unless a future work group decision changes the semantics of Patient.contact.period.
