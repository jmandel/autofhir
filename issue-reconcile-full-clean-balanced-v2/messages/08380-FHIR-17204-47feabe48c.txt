FHIR-17204: Audit BackboneElement details generation

Issue request:
FHIR-17204 is a Published/Persuasive FHIR-core correction from STU3 asking that BackboneElement structure links resolve to BackboneElement detailed descriptions. The reported problem was that backboneelement-definitions.html was rendering Element details, so the example anchor backboneelement-definitions.html#BackboneElement.modifierExtension did not exist.

Initial application:
The issue appears to have been applied by historical commit 22d5233b31f33ae541736868584dea6fc8790a50, whose GF#16877 change switched source/backboneelement-definitions.html from the Element dictionary to the BackboneElement dictionary and added a BackboneElement-specific header. Later source refactors rebuilt the abstract type framework and removed the obsolete standalone BackboneElement redirect files.

Additional context:
BackboneElement remains in current build scope: source/fhir.ini lists it as an active abstract infrastructure type, maps backboneelement to the type framework page, and marks it normative. Current source/types.html links BackboneElement to types-definitions.html#BackboneElement, source/types-definitions.html has an explicit BackboneElement section using <%dictionary BackboneElement%>, and source/datatypes/backboneelement.xml defines BackboneElement.modifierExtension. Release 5 history uses the same types-definitions.html#BackboneElement.modifierExtension target. Key-specific Zulip and Confluence searches found no conflicting community record.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The faulty standalone page input reported in STU3 no longer exists in current source, and the active source now renders BackboneElement details from the BackboneElement dictionary under the shared type framework page.

Recommendation:
Keep this audit commit as-is. No follow-up is needed unless a future generated build shows the current types-definitions BackboneElement anchors missing or mislinked.
