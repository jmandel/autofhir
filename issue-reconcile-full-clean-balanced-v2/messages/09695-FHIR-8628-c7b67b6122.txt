FHIR-8628: Audit sliced element naming resolution

Issue request:
FHIR-8628 was a Published/Persuasive DSTU1 FHIR-core StructureDefinition issue reporting that some HSPC slice members lacked the old ElementDefinition f:name and asking whether sliced paths should require each slice member to be named. The final Jira discussion narrowed the applied action: Grahame Grieve said multiple slicing could occur in different branches, saw no broader invariant problem, and fixed the erroneous Practitioner role discriminator in svn revision 6698.

Initial application:
The Jira-tagged application is present in git as 5fb6665151 (#8628 - fix erroneous discriminator). That commit changed the retired HSPC Practitioner spreadsheet discriminator from `Practitioner.practitionerRole.managingOrganization, Practitioner.practitionerRole.role|false|open` to `Practitioner.practitionerRole.managingOrganization|false|open, Practitioner.practitionerRole.role` in guides/hspc/practitioner-hspc-profile-spreadsheet.*.

Additional context:
The old HSPC guide/profile files named by the issue are not present in the current build checkout, and exact searches for hspc-provpract, hspc-servicedeliverylocation, practitioner-hspc-profile, and the bad discriminator found no current source hits outside generated or historical refs. Current FHIR also renamed ElementDefinition.name to ElementDefinition.sliceName, documents that all elements following the first slicing repeat SHALL have a sliceName, and keeps sliceName as an optional element because unsliced/common constraint entries without sliceName remain valid.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The historical discriminator fix was already applied, the specific DSTU1 HSPC profiles are no longer current core build artifacts, and adding a new global invariant would be broader than the actual published resolution and inconsistent with current profiling rules that allow constraints on all slices without sliceName.

Recommendation:
Keep this audit commit as-is. No current core source edit is needed for FHIR-8628; only revisit if a work group opens a new issue to change current ElementDefinition slicing semantics or to restore/maintain the retired HSPC guide artifacts elsewhere.
