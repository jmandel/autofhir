FHIR-51566: Audit Observation reference range comparators

Issue request:
FHIR-51566 was Applied with resolution Persuasive with Modification for R6 Observation.referenceRange. It requested changing Observation.referenceRange.low and .high from SimpleQuantity to Quantity, constraining low.comparator to >= or > when present and high.comparator to <= or < when present, preserving the FHIR R5-and-earlier inclusive meaning when comparators are absent, and adding explanatory text about the change.

Initial application:
There was no prior AutoFHIR reconcile commit for FHIR-51566 on the combined branch. The source change itself was already applied upstream in October 2025: commit fa4bcdc6 changed Observation.referenceRange.low/high to Quantity, added obs-13 and obs-14 comparator constraints, updated examples, and added invariant tests; commit ee556b3d added committee notes and refined the low/high comments. These changes were merged through HL7/fhir pull requests #3707 and #3723.

Additional context:
FHIR-8551 is the historical same-change-family decision that made absent Observation.referenceRange.low/high bounds inclusive and rejected an inclusive/exclusive extension. FHIR-5165 is background for the Quantity/SimpleQuantity comparator split. The 2025 Zulip thread and OO LAB minutes show the work group considered broader Range/Age questions, including FHIR-22642 and FHIR-45021, but FHIR-51566's applied scope was Observation.referenceRange.low/high only. Observation is active in source/fhir.ini, so the checked StructureDefinition, examples, and invariant tests are current build inputs.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already has type Quantity on Observation.referenceRange.low and .high, obs-13 and obs-14 constrain allowed comparators, comments preserve the inclusive default when comparators are absent and describe explicit inclusive/exclusive forms, and examples/invariant tests exercise both valid and invalid comparator choices.

Recommendation:
Keep this audit commit as-is. No FHIR-core follow-up is needed for FHIR-51566's Observation.referenceRange.low/high scope; any future work on broader Range, Age, or other datatype-level exclusive-bound semantics should be handled under separate Jira decisions.
