FHIR-7336: Audit eligibility benefits request scope

Issue request:
FHIR-7336 was a Published/Persuasive with Modification FM change request against DSTU1 EligibilityRequest. It asked for a way to request benefits at both service type code and procedure level; the accepted resolution said Eligibility handles retrieving benefits at a service type level and Predetermination, now represented by Claim.use=predetermination, handles billing-code-level what-if adjudication.

Initial application:
No Jira-keyed commit for FHIR-7336 was found. Historical financial commits nevertheless show the model moving in the requested area: 64cc09559e refined Claim billing service/product codes, c39cb2271c added service.category to Claim, ClaimResponse, and EOB and coordinated it to EligibilityRequest through benefit category/subcategory terminology, and later source history renamed EligibilityRequest to CoverageEligibilityRequest.

Additional context:
source/fhir.ini lists CoverageEligibilityRequest, not EligibilityRequest, as the active current resource and maps CoverageEligibilityRequest back to the old EligibilityRequest name. Later FM decisions already represented on the combined branch affect the same surface: FHIR-17473 broadened CoverageEligibilityRequest scope for validation, discovery, benefits, and preauthorization requirements for service categories or services, and FHIR-19283 renamed billcode to productOrService. Those later decisions mean the current CoverageEligibilityRequest item.productOrService support should be retained even though the older FHIR-7336 resolution distinguished service-type eligibility from Claim predetermination for billing-code-level what-if adjudication.

AutoFHIR reconciliation:
This empty commit records that no source change is needed. Current CoverageEligibilityRequest supports a benefits purpose and item.category benefit classification for service-type-level requests, while Claim.use=predetermination, Claim.item.productOrService, Claim.item.procedureSequence, and Claim.procedure.procedure[x] cover the procedure/billing-code-level path described by the resolution. Adding duplicate prose or removing later-approved CoverageEligibilityRequest productOrService support would not improve the current specification.

Recommendation:
Keep this audit commit as-is. No core follow-up is needed for FHIR-7336 unless FM wants to reopen the later CoverageEligibilityRequest scope decisions from FHIR-17473 or the productOrService naming from FHIR-19283.
