FHIR-5180: Audit Procedure not-done handling

Issue request:
FHIR-5180 was a Published/Persuasive DSTU1 Patient Care ballot comment asking how FHIR can represent that a Procedure did not occur. Its resolution directed adding a Procedure "not done" indicator and "not done reason" with invariants; ProcedureRequest was listed as a related artifact.

Initial application:
The issue was applied by 41dd59e1c0031104575f31ec53d420561bd65f40, which added Procedure.notDone, Procedure.reasonNotDone, a Procedure.reasonNotDone invariant, and a procedure negation reason value set to the then-authoritative Procedure spreadsheet source. No separate current ProcedureRequest edit remains to apply because ProcedureRequest is no longer an active resource.

Additional context:
FHIR-5707 added Procedure lifecycle status context in the same DSTU1 Patient Care neighborhood. FHIR-11027 later clarified the scope of negated Procedures, and that guidance is preserved in the current Procedure.status comment. FHIR-14063 then intentionally refactored the old boolean representation to the current event-pattern model by removing notDone, adding status value not-done, and renaming notDoneReason to statusReason. Current fhir.ini lists Procedure and ServiceRequest as active resources and records ProcedureRequest as merged into ServiceRequest.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active Procedure source represents non-occurrence as Procedure.status = not-done plus Procedure.statusReason bound to the procedure-not-performed-reason value set, with explanatory scope guidance. The ProcedureRequest side of the old request is now covered by active ServiceRequest request-pattern elements including statusReason and doNotPerform. Reintroducing the DSTU1 notDone/notDoneReason fields would reverse later applied workflow/event-pattern decisions.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-5180; future changes to negated Procedure semantics should be handled as new Patient Care/workflow decisions rather than by reapplying the superseded DSTU1 element shape.
