FHIR-7011: Audit Coding valueSet cleanup

Issue request:
FHIR-7011 was Published as Persuasive for DSTU1. It asked to remove references to value set from the Coding constraint and description because valueSet was no longer part of the Coding datatype definition.

Initial application:
The issue was applied in SVN revision 5939, represented in git as 96cddb8d8729855f7c9daa771c3eddf364d5682b. That commit removed obsolete Coding prose about a "Value Set reference" providing context, removed obsolete inline-ValueSet version wording, and removed the Coding constraint that said "If a valueSet is provided, a system URI SHALL also be provided."

Additional context:
FHIR-5782 had already resolved to remove Coding.valueSet and replace it with extension-based value-set-reference support. FHIR-7704 later performed a follow-up cleanup of remaining references to the removed Coding.valueSet design. FHIR-13657 subsequently added general statements that Coding and other terminology-bearing datatypes can be bound to value sets; those later binding notes are distinct from the removed Coding.valueSet element and are still correct. source/fhir.ini lists Coding as an active datatype and routes datatypes to datatypes.html, so source/datatypes.html is in build scope.

AutoFHIR reconciliation:
This commit makes no source change. Current active datatype source no longer contains the obsolete Coding.valueSet element reference or the removed valueSet-provided Coding constraint. The remaining ValueSet references in the Coding section describe terminology binding and the difference between code systems and value sets, not a valueSet child on Coding.

Recommendation:
Keep this no-change audit commit. No follow-up is needed for FHIR-7011 unless a future work group decision intentionally revisits the broader Coding binding guidance.
