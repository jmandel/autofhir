Issue request:
FHIR-19630 is a Published/Persuasive FHIR-core change request, voted 7-0-1 for R5, asking that ElementDefinition.type.versioning be exposed when profiles and IGs are rendered, including graphical views and data dictionary views.

Initial application:
No Jira-tagged source commit for FHIR-19630 was found in the current HL7/fhir checkout or on the combined branch. The current source already defines and documents ElementDefinition.type.versioning, and the external Kindling parser can carry versioning from type syntax into ElementDefinition.type, but the current rendering implementations inspected for this reconciliation still do not display versioning where they display adjacent type metadata such as target profiles and aggregation modes.

Additional context:
The FHIR spec checkout builds through the external org.hl7.fhir:kindling dependency declared in Gradle, and IG/profile rendering code also lives in external tooling repositories such as HL7/kindling, HL7/fhir-ig-publisher, and hapifhir/org.hl7.fhir.core rather than in this source checkout. The active core ElementDefinition narrative already mentions versioning in the applicable type/slicing rules, so a text edit in this checkout would not address the requested graphical/data-dictionary renderer behavior.

AutoFHIR reconciliation:
This commit intentionally makes no source change in HL7/fhir. It records that the remaining fix belongs in external rendering/tooling code, not in the current core specification source files.

Recommendation:
Keep this audit commit as the core-checkout decision.
