FHIR-12365: Audit Endpoint MLLP address example

Issue request:
FHIR-12365 was a Published Patient Administration change request asking how to represent Endpoint.address for a v2 MLLP connection. The persuasive-with-modification resolution required documenting the v2 MLLP address form so Endpoint.address includes the TCP listener address and port, with the issue raised against DSTU2 and applied for R5.

Initial application:
The issue was applied in commit 05f9cb8d10, which updated the built Endpoint general examples CSV row for v2 referral requests from a bare IP address to mllp://127.0.0.1:4001 and changed the MIME type to x-application/hl7-v2+er7. The current source still contains that row, and the example bundle template renders the address into both the Endpoint.address element and the generated narrative.

Additional context:
Endpoint is an active current-build resource in source/fhir.ini. The Endpoint.address definition is a url and its comment already says message endpoints may use URL forms the server understands, usually http: or mllp:. The Endpoint examples list includes the general CSV/template example, and a later FHIR-39617 commit added a separate AU HL7v2 MLLP profile example; that later example reinforces the same artifact family but does not require revisiting FHIR-12365. A directly relevant 2018 Zulip committers thread records that the Endpoint MLLP cleanup was deferred to R5 and that the address format was clear enough to handle in an example.

AutoFHIR reconciliation:
This commit makes no source change. The current build-scoped Endpoint example already demonstrates the requested v2 MLLP address with scheme, IP address, colon, and port in Endpoint.address, while the normative address comment permits mllp-style message endpoint URLs. Adding duplicate notes would be redundant and could drift from the authoritative example.

Recommendation:
Keep this audit commit as-is. No additional core source work is recommended for FHIR-12365 unless the work group later standardizes a more precise MLLP URI scheme; any such future change should update the Endpoint examples consistently rather than adding parallel prose.
