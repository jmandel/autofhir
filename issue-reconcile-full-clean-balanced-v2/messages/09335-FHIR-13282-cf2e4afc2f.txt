FHIR-13282: Audit CapabilityStatement operation guidance

Issue request:
FHIR-13282 was Published/Persuasive with Modification for STU3. The reporter observed that operations can be defined at system, resource type, instance, and version-instance levels, but CapabilityStatement appeared to expose only CapabilityStatement.rest.operation, and asked whether operations should instead be specified under resource interactions. The accepted resolution was to clarify the definition so readers consult the referenced OperationDefinition to determine where the operation is supported.

Initial application:
The issue was applied by git-svn commit 5f91feb9be52c8b5497fa906d169e33334e86de3, imported from svn revision 12857, which added the consultation sentence to CapabilityStatement.rest.resource.operation in the then-authoritative CapabilityStatement spreadsheet source. Later source refactors moved the authoritative content into source/capabilitystatement/structuredefinition-CapabilityStatement.xml, and the current XML still carries the same clarification with the typo corrected.

Additional context:
CapabilityStatement is an active current-build resource in source/fhir.ini. The current source distinguishes CapabilityStatement.rest.resource.operation for resource operations from CapabilityStatement.rest.operation for system-level or multi-resource operations. The referenced OperationDefinition source separately exposes OperationDefinition.system, OperationDefinition.type, and OperationDefinition.instance, which are the fields clients consult to determine invocation scope. Later same-area reconciliation for FHIR-40957 clarified REST interaction wording but did not change this operation-scoping conclusion.

AutoFHIR reconciliation:
No source change was made. The current active source already implements the accepted clarification and provides more explicit comments about resource-level and system-level operation placement. Adding CapabilityStatement.rest.resource.interaction.operation now would go beyond the published resolution and create a second way to express the same operation support.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-13282 unless the work group reopens the model question and explicitly chooses to add interaction-level operation declarations.
