FHIR-12142: Audit TestScript assert constraints outside core

Issue request:
FHIR-12142 is a Published/Persuasive FHIR-core TestScript change request from the DSTU2 cycle. It asked that TestScript.setup.action.assert and TestScript.test.action.assert require response and responseCode to be empty when assert.direction is request, so test engines would not evaluate response-only assertions against client-side request traffic.

Initial application:
The issue was applied in SVN revision 10119, mirrored in git as ff89b194079064c8ac9b0fe85b11de1910f12d86, which added the requested FHIRPath and XPath invariants to source/testscript/testscript-spreadsheet.xml. Before TestScript was removed from core, the generated StructureDefinition still carried the matching expressions on TestScript.setup.action.assert and TestScript.test.action.assert.

Additional context:
Current core no longer owns the TestScript resource. Commit f9a44787c45071394532c7c2ee94d76f30f47387 removed source/testscript and the testing resources from source/fhir.ini, while adding the Testing IG to the additional IG list. The current Testing IG StructureDefinition-TestScript JSON still contains the same direction=request constraints, with equivalent later coverage for TestScript.common.action.assert after subsequent TestScript refactoring.

AutoFHIR reconciliation:
This commit intentionally makes no core source change. The requested constraint was historically applied, the current authoritative TestScript artifact is outside this FHIR-core checkout, and the external Testing IG currently preserves the constraint.

Recommendation:
Keep this audit commit as-is for FHIR core. If future review finds a mismatch in TestScript constraints, make that change in the HL7 FHIR Testing IG rather than reintroducing inactive core TestScript source.
