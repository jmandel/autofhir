FHIR-31541: Audit annotation type extension in Extension Pack

Issue request:
FHIR-31541 was a Published/Persuasive R5 MnM change request asking for a standard extension on Annotation to carry a note/comment type for v2 NTE-4 mappings. The approved resolution was to create an Annotation-attached extension with a valueCodeableConcept and an example binding to the v2-0364 comment type value set.

Initial application:
Core history shows commit 51608b35e99a0fc80a1cc3abd49dbb5e19f8bb90 added source/datatypes/annotation-extensions-spreadsheet.xml for FHIR-31541, but the current core source does not contain a complete active annotationType StructureDefinition there. Jira comments record that the extension was later recovered through HL7/fhir-extensions#48.

Additional context:
The current FHIR Extension Pack source contains input/definitions/datatypes/StructureDefinition-annotationType.xml with canonical URL http://hl7.org/fhir/StructureDefinition/annotationType, Annotation context, CodeableConcept value, and example binding to http://terminology.hl7.org/ValueSet/v2-0364. The Extension Pack IG includes input/definitions/* and the published extension page is available. In the core checkout, source/fhir.ini has active profile entries for other datatype extension spreadsheets but no active annotation-extensions entry, so adding or repairing the core spreadsheet would duplicate external-repo ownership rather than fix the current core build.

AutoFHIR reconciliation:

Recommendation:
Keep this audit commit as-is. If future work changes the annotationType definition, make it in HL7/fhir-extensions and preserve the existing canonical URL, Annotation context, CodeableConcept value, and example v2-0364 binding.
