FHIR-33980: Audit Android SDK reference handoff

Issue request:
FHIR-33980 was Published with a Persuasive with Modification resolution. It asked to add the Android FHIR SDK as an example open source library for implementers, but the accepted resolution moved reference implementation information to a Confluence page referenced from the downloads page and said the Android SDK information should be added there.

Initial application:
No source commit explicitly tagged FHIR-33980 was found. The same R5 reference-implementation cleanup was applied through related published work: FHIR-30088 changed the downloads page to point reference implementations to Confluence, and FHIR-31735 split implementation tools and reference implementations out of the specification into Confluence-backed pages. The current source no longer maintains per-language library rows in core.

Additional context:
The current Implementation Support module is in build scope and links developers to the Confluence Open Source Implementations page. The current downloads page links implementation tools to the Confluence FHIR Tools Registry. Jira, Zulip, and Confluence searches did not reveal a later source decision requiring the Android FHIR SDK to be listed directly in the FHIR core checkout.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Adding the Android FHIR SDK directly to source/implsupport-module.html or source/downloads.html would conflict with the final resolution and the later cleanup that keeps mutable tool and library inventories on Confluence rather than in the normative build source.

Recommendation:
Keep this audit commit as-is for the core specification. If the Android FHIR SDK is missing from the relevant Confluence registry page, handle that as Confluence/page-maintenance follow-up outside this source checkout rather than as a FHIR core source edit.
