FHIR-43452: Audit SupplyDelivery workflow mappings

Issue request:
FHIR-43452 is Applied/Persuasive with Modification for the R6 FHIR-core Supply artifact. The approved OO resolution asked to align SupplyDelivery with the workflow Event pattern by mapping SupplyDelivery.type to Event.category, SupplyDelivery.suppliedItem to Event.product, SupplyDelivery.subject to Event.subject, and SupplyDelivery.destination to Event.location.

Initial application:
The issue was applied before this reconciliation in commit 04bfd7e830ea8e46cf5161e75e150e880f2d3162. That commit changed SupplyDelivery.type from Event.code to Event.category and added workflow mappings for suppliedItem/Event.product and destination/Event.location. SupplyDelivery.subject already had the requested Event.subject workflow mapping in source.

Additional context:
Current source/supplydelivery/structuredefinition-SupplyDelivery.xml contains all four approved workflow mappings. A later source refactor, commit 3b38b80cf23f9cbb306fab8fcedb293315478c32, removed supplydelivery from the active source/fhir.ini resource, work group, security, FMM, and resource-code lists as part of moving several OO resources toward the OO Incubator. The current OO Incubator build artifact for StructureDefinition/SupplyDelivery also exposes the same four workflow mappings. Confluence searches found agenda references to the broader OO workflow-pattern Jira family, and Zulip searches found no conflicting discussion for this SupplyDelivery mapping decision.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The requested mappings are already present in the retained core source and in the external OO Incubator artifact, while SupplyDelivery is no longer an active core build resource in source/fhir.ini.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for FHIR-43452; future changes to the live SupplyDelivery artifact should be made in the OO Incubator source if that IG becomes authoritative for this resource.
