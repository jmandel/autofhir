FHIR-22855: Audit ExampleScenario instance typing

Issue request:
FHIR-22855 was Published with a Persuasive with Modification resolution for ExampleScenario. The request was to support ExampleScenario instances that represent non-FHIR standards such as DICOM or HL7 v2 by no longer making instance.resourceType a required binding to only FHIR resource types. The approved modification was to use Coding, loosen the binding to extensible, include HL7 v2 message structures, and clarify that the field identifies an exchanged data instance/structure rather than only a FHIR resource.

Initial application:
The source history shows the change was applied across the 2022 ExampleScenario cleanup commits. Commit 2f6dfcd introduced the examplescenario-instance-type value set with FHIR resource types plus HL7 v2 table 0354 and changed the former type field from code to Coding. Commit 022f97b then renamed the field to structureType and loosened its binding to extensible, and commit de7f583 explicitly recorded the remaining FHIR-37195, FHIR-22855, FHIR-25260, and FHIR-37895 ExampleScenario work.

Additional context:
ExampleScenario is active in source/fhir.ini, and current fhir.ini migration mappings redirect the old ExampleScenario.instance.resourceType name to ExampleScenario.instance.structureType. Related cleanup issues FHIR-37195, FHIR-25260, and FHIR-37895 are already represented on the combined branch, so this commit does not duplicate them. The 2019 FHIR-I minutes confirm the work group disposition for FHIR-22855 and FHIR-25260; targeted Zulip searches found no direct FHIR-22855 discussion that changes the Jira/source conclusion.

AutoFHIR reconciliation:
No source change was made. The current build-scoped StructureDefinition defines ExampleScenario.instance.structureType as Coding with an extensible binding to http://hl7.org/fhir/ValueSet/examplescenario-instance-type, and that value set includes FHIR resource types plus HL7 v2 message structures. The element definition says the value can identify a FHIR resource or another standard, and the invariant/meaningWhenMissing logic distinguishes FHIR from non-FHIR structures without prohibiting external Coding values.

Recommendation:
Keep this audit commit as-is. The current source satisfies the published FHIR-22855 resolution; any future desire for a CDA/DICOM/v2 worked example would be editorial example enrichment rather than a required conformance correction for this issue.
