FHIR-21297: Audit vital signs effective timing restriction

Issue request:
FHIR-21297 was an Applied OO change request for R6, resolved Persuasive with Modification. It asked to profile Period out of the FHIR Blood Pressure Profile because blood pressure is captured at a single point in time, and the final resolution expanded the source change to remove effectivePeriod from the Vital Signs effective[x] choices because the LOINC codes used for all Vital Signs profiles are point-in-time concepts.

Initial application:
The issue was pre-applied in commit af25d09edb, which changed source/observation/structuredefinition-profile-vitalsigns.xml so Observation.effective[x] in the active Vital Signs Base profile has only the dateTime type and says vital signs are point-in-time measurements recorded using dateTime. Commit 59db19eb59 then removed the remaining effectivePeriod references from the generated profile-summary text. The current Blood Pressure profile derives from the Vital Signs Base profile, so the base-profile restriction profiles Period out of Blood Pressure as well.

Additional context:
Observation is an active current-build resource in source/fhir.ini. The linked OO Zulip discussion and OO minutes show the work group knowingly discussed applying the restriction at the Vital Signs Base profile, the point-in-time LOINC rationale, and concerns about average blood pressure or other calculated observations. Later related decisions, including FHIR-50075, FHIR-50194, and the FHIR-41426 source application, clarified that Observation.category = vital-signs does not by itself force all calculated or de-identified vital-sign-related observations into these point-in-time profiles. FHIR-50194 is already represented on the combined branch by a separate audit commit.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current active source already implements the FHIR-21297 decision: Vital Signs Base constrains Observation.effective[x] to dateTime only, Blood Pressure derives from that base, the profile summary no longer mentions effectivePeriod, and the current narrative clarifies point-in-time scope for calculated vital-sign-related observations.

Recommendation:
Keep this audit commit as-is. No FHIR-core source follow-up is needed for FHIR-21297 unless OO later reopens the broader policy and decides to allow non-point-in-time or calculated vital-sign-related observations to conform to the Vital Signs profiles.
