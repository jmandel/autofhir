FHIR-7401: Audit Element and BackboneElement distinction

Issue request:
FHIR-7401 was a Published/Persuasive FHIR-core DSTU1 clarification asking the specification to distinguish Element from BackboneElement because the old Element and BackboneElement definitions sounded nearly identical. The accepted resolution was to improve the definitions.

Initial application:
The Jira comment records SVN revision 6442. In the git-svn history this is commit 08a6113725dd1d7815bf53d094cc70114d8ed281, which changed the old standalone source/backboneelement.html page from "elements defined as part of a resource" to "elements defined as part of a resource definition," added that datatype elements do not use BackboneElement, and added Patient.contact as an example.

Additional context:
The standalone Element and BackboneElement pages were later folded into the active type framework by cbdf7d1e55dc4bfa1dc30fc526edee0491e05782. A later Published/Persuasive issue, FHIR-17017, further tightened the same BackboneElement definition and is already represented on the combined branch by 20ab87310ee300f0e493ea873ce2cdcf38d0f9cd. The active fhir.ini build configuration still lists Element and BackboneElement as abstract infrastructure types, maps backboneelement to the types page, and marks both types normative.

AutoFHIR reconciliation:
No source change was made. The current source/types.html page explains that Element covers all elements in resources, including datatype and resource-structure descendants, while BackboneElement is the specialization for complex elements declared as part of resource definitions and excludes datatype elements. The datatype spreadsheet definitions are consistent with that distinction.

Recommendation:
Keep this audit commit as-is. Further source edits would be redundant unless a future work group decision changes the Element/BackboneElement boundary or asks for additional generated StructureDefinition wording beyond the current narrative and spreadsheet definitions.
