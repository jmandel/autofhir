FHIR-13114: Audit Age invariant value guard

Issue request:
FHIR-13114 was a Published/Persuasive with Modification FHIR-core datatypes change request. It asked that the Age invariant not require an XML @value when an Age.value element is present only to carry extensions, by changing the value check from (value.empty() or value > 0) to (value.empty() or value.hasValue().not() or value > 0). The resolution also asked that similar expressions be reviewed for extension-only value elements and that QA criteria cover this class of invariant.

Initial application:
The Jira comments cite svn revision 12714. In this Git history that is commit f29cd3ce60e6cc652e0dcef70fffafc2977db9ec, "#13114 - correct quantity invariants", which changed source/datatypes/age.xml to add value.hasValue().not() to the Age invariant and changed source/datatypes/count.xml to add the same guard to Count's value-dependent checks.

Additional context:
Age is an active normative datatype in source/fhir.ini, so source/datatypes/age.xml is authoritative current build source. The current Age invariant row already contains the requested FHIRPath expression, including value.hasValue().not(), and Count's current invariant also guards its value-dependent checks the same way. Later related issue FHIR-15648 corrected the same Age invariant from code to code.exists(); that related issue is already represented on the combined branch by commit 1fa17c9bc81f8d7a7b77bcadbf91437b2cb7fc40, so this commit does not duplicate it. The remaining historical old expression appears only in checked-in tools/history release snapshots, not the current source/datatype build input.
