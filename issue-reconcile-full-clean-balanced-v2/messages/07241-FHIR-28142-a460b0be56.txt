FHIR-28142: Audit REST operation side-effect wording

Issue request:
FHIR-28142 was a Published FHIR-core/fhir-i clarification for R5, resolved Persuasive with Modification, asking that the operations framework clarify the computer-science meaning of "side effects" so that merely constructing and returning a transient Bundle is not treated as a server-state side effect.

Initial application:
The issue appears to have been applied by git commit 5b5349293bbdc00bf741dc84397e62803b02dbb1, which changed source/operations.html from the older "modification of existing resources or creation of new resources" wording to the approved linked "side effects" text with the "resources not transmitted as part of the RESTful call" clarification and invoice/merging examples.

Additional context:
source/operations.html is an active current build page, listed in publish.ini. The current source still contains the Jira-approved wording at the operations appropriateness criteria. Confluence minutes from 2020-11-09 only show the early FHIR-I assignment to propose wording, while later community searches found no conflicting Zulip or Confluence evidence. A neighboring Jira search surfaced FHIR-18197 for OperationDefinition.affectsState, but that is a separate published clarification for the affectsState element and does not change the FHIR-28142 operations-page decision.

This audit commit intentionally makes no source change. The authoritative current source already carries the approved side-effect clarification, and adding another note would be redundant rather than necessary for implementer understanding.
