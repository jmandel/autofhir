FHIR-30318: Audit NamingSystem preferred invariant display

Issue request:
FHIR-30318 was a Published/Persuasive Vocabulary issue for R5 asking that the NamingSystem nsd-2 invariant display on NamingSystem.uniqueId.preferred rather than on the NamingSystem root; the resolution said the FHIRPath expression was incorrect and should be corrected, then verified in the diagram.

Initial application:
Commit 25159ea161eaed360cf05d040c52d38e80cdcbac applied a group of R5 NamingSystem changes including FHIR-30318, initially moving nsd-2 from the root to uniqueId.preferred. Later invariant cleanup in 55512f8e09be7228efab289f8bf660242d29654d and 07b4f0122b2fd6f10310442e99e1dd159657935b normalized the invariant back to the correct root context while adding condition references to the affected uniqueId elements, including uniqueId.preferred.

Additional context:
NamingSystem is active in source/fhir.ini, so source/namingsystem/structuredefinition-NamingSystem.xml and the generated-looking source/namingsystem/namingsystem.svg are in the relevant current build scope. Current source defines nsd-2 at NamingSystem with expression uniqueId.where(preferred = true).select(type).isDistinct(), and NamingSystem.uniqueId.preferred carries condition nsd-2. The checked-in SVG shows the constraint marker on preferred and no marker on the root class title. Confluence minutes confirm the Vocabulary WG treated FHIR-30318 as persuasive during the Jan 2021 WGM; no relevant Zulip conflict was found.

AutoFHIR reconciliation:
This empty audit commit makes no source change because the current authoritative source and diagram already satisfy the applied issue. Moving the constraint back onto preferred would break the FHIRPath context; editing only the SVG would be generated-artifact work and is unnecessary because it already shows the marker in the requested place.

Recommendation:
Keep this audit commit as-is. No follow-up source work is needed for FHIR-30318 unless future publisher output again drops the condition marker from NamingSystem.uniqueId.preferred.
