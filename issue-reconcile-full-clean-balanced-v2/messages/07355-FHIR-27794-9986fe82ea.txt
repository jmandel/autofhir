FHIR-27794: Complete Provenance relevant-history profile guidance

Issue request:
FHIR-27794 was Published with a Persuasive with Modification resolution for the Provenance Relevant History profile. It asked that the profile be owned by FHIR-I, explain the relevant-history use case, define the soft meaning of MustSupport outside an IG, update relevantHistory/eventHistory usage notes to point to the profile, provide an example that populates eventHistory and conforms to the profile, link to that example from the profile page, and flag Provenance.target as requiring a version-specific reference.

Initial application:
The issue was partially applied by git commit 71bd0587df, which changed the profile work-group ownership to FHIR-I, added profile intro/notes include support, improved the profile description, and linked Request.relevantHistory to the profile. Later source already carried the FHIR-I owner/contact, the current use-case and MustSupport guidance in StructureDefinition.description, and profile references from Request/Event relevant-history definitions. The remaining gaps were that Provenance.target only had prose saying the reference SHALL be version-specific, and the listed MedicationRequest example that claimed eventHistory did not actually populate eventHistory with a Provenance instance conforming to this profile.

Additional context:
FHIR-48828 later decided to retain provenance-relevant-history in core as informative, replace the description with the current soft-conformance/MustSupport language, and yank the separate MustSupport notes section, so this reconciliation intentionally did not restore that removed section. FHIR-48829 retained the profile in core because Request/Event resources can point directly to it. Zulip and Confluence records confirm the original FHIR-I rationale, the need for examples, and that the later resolve-as-version-specific extension discussion was not itself the profile constraint mechanism. The active build scope is the Provenance resource in source/fhir.ini, the Provenance-core package list, the profile's notes extension, and the MedicationRequest example list.

AutoFHIR reconciliation:
Added the computable ElementDefinition.type.versioning=specific flag to Provenance.target in the relevant-history profile, while preserving the existing prose comment. Added a contained Provenance instance in medicationrequestexample1 that declares the provenance-relevant-history profile, uses a version-specific MedicationRequest target, supplies the required occurredDateTime, activity, and Author agent, and is referenced from MedicationRequest.eventHistory. Added profile notes linking to that eventHistory example. No separate MustSupport notes were added because FHIR-48828 explicitly moved that guidance into the profile description and removed the bottom notes section.

Recommendation:
Keep this commit as the source correction for FHIR-27794. It completes the unapplied example/link and computable version-specific-target parts without reversing the later FHIR-48828 description and MustSupport decision.
