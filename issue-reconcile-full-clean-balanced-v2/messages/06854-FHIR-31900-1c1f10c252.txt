FHIR-31900: Clarify Task restriction period timing

Issue request:
FHIR-31900 was Published/Persuasive with Modification for R5 and asked to clarify Task.restriction. The accepted resolution limited Task.restriction to fulfillment of another Request resource, added an invariant requiring the fulfillment code and a focus, changed Task.restriction.period to describe the subset of the referenced request authorization, and distinguished that period from a task deadline/execution timing.

Initial application:
The Jira comment cites git 6ea83c0de2. That commit added the tsk-1 invariant, the Task.restriction comment, the Task.restriction.period definition, and usage-note text. The current source has since been refactored to use the actual Task code 'fulfill' and focus reference form, and it retains the invariant and restriction guidance, but the period note still described Task.executionPeriod as requested timing, retained the old period.high due-date note, and misspelled ServiceRequest.occurrence[x] as ServiceRequest.occurance[x].

Additional context:
FHIR-34136 subsequently added Task.requestedPeriod for requested task timing and stated that Task.executionPeriod is actual execution timing. FHIR-28397 later replaced the broader Task.restriction comment while preserving the same fulfillment-request limitation. FHIR-37001 addressed the Task.code binding concern created by the FHIR-31900 invariant and is already represented on the combined branch. The Task resource is active in source/fhir.ini, so source/task/structuredefinition-Task.xml is in current build scope; source/task/task.svg is a generated-looking diagram artifact updated only to keep its tooltip spelling aligned with the authoritative XML.

AutoFHIR reconciliation:
This commit updates Task.restriction.period so the example names ServiceRequest.occurrence[x], replaces the stale executionPeriod/deadline wording with language that distinguishes Task.requestedPeriod from Task.executionPeriod, removes the contradictory period.high due-date note, and mirrors the occurrence spelling in the checked-in Task SVG tooltip.

Recommendation:
Keep this commit. It completes the FHIR-31900 clarification without reopening related Task issues, and no further core source change is indicated unless the work group wants to revisit whether Task.requestedPeriod should be recommended more strongly for fulfillment-task deadlines.
