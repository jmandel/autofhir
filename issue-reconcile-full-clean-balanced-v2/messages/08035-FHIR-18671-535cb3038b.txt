FHIR-18671: Audit FHIR version support guidance

Issue request:
FHIR-18671 was Published/Persuasive with Modification for STU3 CapabilityStatement/versioning guidance. It asked to harmonize CapabilityStatement.fhirVersion short and definition text, clarify how a CapabilityStatement.fhirVersion is selected when a server supports multiple FHIR versions, avoid mandating endpoint URL shape, state that cross-version resource references are undefined, link the fhirVersion usage notes to versioning.html and $versions, and account for non-core support for cross-version endpoint discovery.

Initial application:
Jira records the application as git 6ee770877b. That commit added the Supporting Multiple Versions paragraph to the CapabilityStatement introduction, changed the then-authoritative capabilitystatement spreadsheet fhirVersion short/definition/comment text, added the cross-FHIR-version reference warning and contained-resource same-version rule to references.html, and updated versioning.html to point clients to $versions. The old spreadsheet source has since been refactored into source/capabilitystatement/structuredefinition-CapabilityStatement.xml, where the relevant fhirVersion wording is still present in current active source.

Additional context:
CapabilityStatement is an active resource in source/fhir.ini, and the references/type page and versioning narrative are active build inputs. Current source says a CapabilityStatement describes one particular FHIR version, fhirVersion is 1..1 with no element default, multi-version systems have one statement per supported version, clients use the MIME fhirVersion parameter and $versions for same-endpoint support, the specification does not require version-specific endpoint URL shapes, and cross-version resource references remain undefined. FHIR-17009 is an earlier same-family multiple-version/$versions issue; FHIR-26065 is a later $versions operation issue already represented on the combined branch; FHIR-40644 is still Waiting for Input and concerns broader fhirVersion compatibility semantics outside this completed STU3 clarification. The Extension Pack now contains an Endpoint FHIR Version extension, so endpoint-version discovery extension work does not require a core source edit here.

AutoFHIR reconciliation:
Made no source change. The current build-scope source already preserves the semantic outcome required by FHIR-18671, and adding redundant prose would risk drifting from the central versioning guidance without changing implementer understanding.

Recommendation:
Keep this audit commit as-is. Revisit only if FHIR-40644 or a new work-group decision finalizes broader compatibility rules for fhirVersion-bearing artifacts, or if the work group explicitly wants endpoint-version extension material migrated from the Extension Pack into core.
