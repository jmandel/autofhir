FHIR-7671: Audit CareTeam refactoring

Issue request:
FHIR-7671 was a Published Patient Administration change request from the DSTU1 ballot asking whether EpisodeOfCare.careTeam's recurring provider/role/period pattern should be pulled out into a participation type. The final Persuasive with Modification resolution says this had already been implemented by refactoring EpisodeOfCare and CarePlan care-team elements into the new top-level CareTeam resource.

Initial application:
No source-changing commit tagged FHIR-7671 was found that implemented the substantive CareTeam extraction; the 2015 Tracker# 7671 commit only adjusted EpisodeOfCare property order. The substantive application appears in later tightly related history: FHIR-9261/gForge 9261 created CareTeam as a first-class resource for EpisodeOfCare and CarePlan, commit 62d8a4ab03 changed EpisodeOfCare to reference CareTeam, and commit 0c1413009c applied FHIR-9765 by replacing CarePlan.participant with CarePlan.careTeam.

Additional context:
CareTeam, CarePlan, and EpisodeOfCare are active current-build resources in source/fhir.ini. Current source keeps the refactoring in place: EpisodeOfCare.careTeam and CarePlan.careTeam reference CareTeam, while CareTeam carries the role, member, team period, and participant effective timing concepts that answer the original provider-role-period concern. Later renames such as CareTeam.participant.period to CareTeam.participant.effective[x] are recorded in fhir.ini and do not reverse the split.

AutoFHIR reconciliation:
This commit intentionally makes no source change because the current build-scope source already conveys the requested model. Adding another participation type or duplicating explanatory prose would go beyond the Published resolution and risk conflicting with the established CareTeam resource.

Recommendation:
Keep this audit commit as-is. Revisit only if Patient Administration or Patient Care opens a new issue asking for a broader reusable participation datatype beyond CareTeam.
