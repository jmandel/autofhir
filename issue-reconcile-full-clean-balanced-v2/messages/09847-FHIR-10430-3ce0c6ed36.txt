FHIR-10430: Audit choice-element extension support

Issue request:
FHIR-10430 was a Published FHIR-core/fhir-i change request, resolved Persuasive with Modification for R5, asking that profiles be able to declare extensions for choice elements. The reported failure was that an implicit slice complained the path did not exist, while an explicit slice complained that a non-repeating element was being sliced.

Initial application:
No source commit tagged FHIR-10430 was found in the local HL7/fhir history, and the Jira resolution only says to investigate and resolve. The current Jira comments record the practical application: Lloyd McKenzie noted in 2021 that this was "Not a problem anymore."

Additional context:
Current ElementDefinition guidance now explains type-specific constraints on choice elements and the id form for type choice slices, while keeping the original [x] element as the path anchor. Current active source also contains a FHIR-core profile that declares an extension slice at Parameters.parameter.value[x].extension, added for FHIR-32965, showing that the current source/tooling supports the pattern that FHIR-10430 asked to enable. A directly relevant 2017 Zulip discussion records the same tooling issue and confirms that R4 draft/forward validator behavior and explicit cardinality/type-slice handling resolved it.

AutoFHIR reconciliation:
This audit commit intentionally makes no source change. The current build-scope source already supports declaring constraints and extension slices below choice elements, and adding another explanatory sentence would be redundant rather than necessary for implementer understanding.

Recommendation:
Keep this no-change audit as-is. Revisit only if a current IG Publisher or core build regression again rejects extension slices below choice elements such as value[x].extension.
