FHIR-12494: Audit profile slice naming generation

Issue request:
FHIR-12494 was a Published/Persuasive DSTU2 change request for FHIR-core profiles. It reported that DSTU2 spreadsheet-generated StructureDefinitions did not populate the ElementDefinition name field for sliced elements, which was needed for re-slicing; the Jira application comment says rendering was improved and the spreadsheet corrected.

Initial application:
No git commit with an explicit FHIR-12494 trailer or message was found in this checkout. The Jira comment records that the historical DSTU2 spreadsheet/rendering correction was applied, and the current active profile-spreadsheet source still carries a Profile Name column for slicing while the current generated/model surface uses ElementDefinition.sliceName rather than the old ElementDefinition.name.

Additional context:
ElementDefinition.name was renamed to ElementDefinition.sliceName by the earlier #12181 source change, and later profiling prose was clarified to describe re-slicing in terms of ElementDefinition.sliceName. The current build's active [profiles] entries in source/fhir.ini still include spreadsheet-backed profile sources, but the current specification no longer has an ElementDefinition.name element to repopulate.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current source already preserves the intended slicing/re-slicing semantics with ElementDefinition.sliceName, and changing current source to restore or mention ElementDefinition.name would conflict with the current data model.

Recommendation:
