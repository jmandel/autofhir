FHIR-20464: Audit Device property type wording

Issue request:
FHIR-20464 was a Published/Persuasive OO change request asking to correct Device.property.type text that referred to the nonexistent and misspelled DeviceDefinitionPropetyCode value set, and suggested saying the code identifies the property being represented with MDC as an example code system.

Initial application:
The issue appears to have been applied by git commit 439f71f7090850848dd0d27c1800c89b4056edf7, which changed the then-authoritative Device spreadsheet text from the bad DeviceDefinitionPropetyCode wording to "Code that specifies the property being represented" and added an MDC example sentence.

Additional context:
Device is active in source/fhir.ini, and the current authoritative source is source/device/structuredefinition-Device.xml. Later R5 work changed the representation: FHIR-32567 added an example Device.property.type binding, and FHIR-39322 later removed the local MDC sentence while keeping example-code wording. Current source no longer contains the misspelled/nonexistent value set reference and has an example binding to ValueSet/device-property-type.

AutoFHIR reconciliation:
No source change was made. Reintroducing the MDC sentence from the original 2020 application would duplicate or conflict with later Device.property.type binding work and the later Device.property clarification.

Recommendation:
Keep this no-change audit commit. The current build-scope Device source satisfies the FHIR-20464 correction, and any further changes to Device.property.type examples should be handled through the later binding/use-case issues rather than this typo/correction issue.
