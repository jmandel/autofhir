FHIR-49946: Audit Turtle literal shorthand application

Issue request:
FHIR-49946 was an Applied/Persuasive R6 ITS change request to improve generated FHIR RDF Turtle examples by using Turtle shorthand notation for literal values that have equivalent shorthand forms, such as plain integer or boolean literals instead of quoted xsd-typed forms. The Jira pointed to build.fhir.org/account.profile.ttl and noted that hapifhir/org.hl7.fhir.core PR #1915 had already been merged.

Initial application:
No HL7/fhir source commit or checked-in generated Turtle example source was found that needed a direct spec-repository edit for FHIR-49946. The application path is the external org.hl7.fhir.core generator change: PR #1915, merged 2025-03-03 as d6f876f8385402c60f04bc3242b75dc8508acafd, updated TurtleParser.ttlLiteral to emit shorthand for booleans, integers, and decimals when the shorthand preserves the same datatype semantics.

Additional context:
The current HL7/fhir checkout has the RDF page in build scope via publish.ini and source/rdf.html already documents optional Turtle shorthand for xsd:string, xsd:integer, xsd:decimal, xsd:double, and xsd:boolean. A repository glob found no checked-in generated resource/profile Turtle example set to update in this checkout. Current build.fhir.org Account Turtle output has shorthand fhir:v true/false values and no explicit xsd:boolean, xsd:integer, xsd:decimal, or xsd:double literal long forms in that example; remaining xsd:nonNegativeInteger values are intentionally not equivalent to plain Turtle integer shorthand. Jira search found only this issue, and no directly relevant Zulip or Confluence references were found.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The requested generated-output style is already present in the current build through the external generator implementation, and changing HL7/fhir source files would either be redundant or target files outside the authoritative source for these generated Turtle examples.

Recommendation:
Keep this no-change audit commit as-is. If future generated Turtle examples regress to quoted xsd:boolean, xsd:integer, or shorthand-safe xsd:decimal/xsd:double literals, address that in org.hl7.fhir.core or the publisher dependency rather than by hand-editing generated output in this spec checkout.
