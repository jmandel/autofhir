FHIR-22660: Audit ClaimResponse outcome decision split

Issue request:
FHIR-22660 was a Published FHIR-core Financial Management change request, resolved Not Persuasive with Modification for R5. It asked to clarify that ClaimResponse.outcome reports processing state rather than the adjudication decision, and to add a 0..1 CodeableConcept decision element with an example decision value set.

Initial application:
No prior source commit explicitly names FHIR-22660. The closest implementation is git f952b5321de9cdbcb7b2521862890c757e21d530, which changed ClaimResponse.outcome's comment to describe processing states, added ClaimResponse.decision, and added the claim-decision CodeSystem and ValueSet. That commit also added item-level decision elements, which were later reshaped by FHIR-22662 and FHIR-40082.

Additional context:
ClaimResponse is an active resource in source/fhir.ini, so source/claimresponse/structuredefinition-ClaimResponse.xml is in current build scope. The current source has ClaimResponse.outcome defined as processing outcome, ClaimResponse.decision as the overall adjudication result, and ClaimResponse.item.reviewOutcome.decision for item-level adjudication results. FHIR-22662 and FHIR-40082, already audited on the combined branch, moved item-level decision content into reviewOutcome; FHIR-53057, also already audited, later changed the ClaimResponse decision bindings to preferred. Exact FHIR-22660 Zulip and Confluence searches found no conflicting community evidence.

Recommendation:
