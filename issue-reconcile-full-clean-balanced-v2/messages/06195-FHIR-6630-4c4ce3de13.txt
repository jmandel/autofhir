FHIR-6630: Audit Patient death-date XPath correction

Issue request:
FHIR-6630 was a Published/Persuasive Patient Administration change request from DSTU1. It reported that the Patient deathdate search parameter XPath used f:Patient/*[starts-with(local-name(.), 'deceased')], which matched both deceasedBoolean and deceasedDateTime, and requested the target be f:Patient/f:deceasedDateTime.

Initial application:
No Jira-keyed commit for FHIR-6630 was found in the current git history. The checked-in release history and the R4B-era Patient search parameter source show the issue's requested correction already applied: the deathdate/death-date search parameter targets Patient.deceasedDateTime and used f:Patient/f:deceasedDateTime while XPath was still present.

Additional context:
FHIR-9772 later renamed the same search parameter from deathdate to death-date for style-guide conformance. FHIR-32530 later removed SearchParameter.xpath from current FHIR sources and renamed xpathUsage to processingMode, so the current absence of an XPath element is intentional and should not be treated as a missing application of FHIR-6630. A separate Patient-deceased token search issue, FHIR-23068, confirms later XPath-specific fixes were not applied because XPath definitions were being removed.

AutoFHIR reconciliation:
This commit makes no source change. The active Patient resource is in build scope, and source/patient/bundle-Patient-search-params.xml currently defines Patient-death-date with path Patient.deceasedDateTime and expression Patient.deceased.ofType(dateTime), which excludes deceasedBoolean and preserves the FHIR-6630 intent without an XPath field.

Recommendation:
Keep this no-change audit commit. Do not reintroduce SearchParameter.xpath for this issue; future changes, if any, should concern current FHIRPath search semantics rather than the retired XPath representation.
