FHIR-23921: Audit OtherCharacteristics type/value modelling

Issue request:
FHIR-23921 was a Published/Persuasive BR&R change request for R5. It asked that product OtherCharacteristics no longer be represented as a lone CodeableConcept, because implementers need to convey the characteristic type and its value, for example "Wrapper Colour" / "Red". The accepted resolution broadened this to replacing physical and other characteristics with a single repeating code/value[x] pair for manufactured items and packaged products.

Initial application:
No commit explicitly mentioning FHIR-23921 was found. Source history instead shows the request being applied implicitly through BR&R medication-definition rework: commit 7512379e821e reorganized PackagedProductDefinition to use repeated characteristic code/value entries, and commit 1514f5f443a3 aligned ManufacturedItemDefinition characteristics with the same pattern. Later R5 source refactors moved these definitions into current StructureDefinition XML.

Additional context:
The old Jira artifact names now map to the current medication-definition resources: MedicinalProduct to MedicinalProductDefinition, MedicinalProductManufactured to ManufacturedItemDefinition, MedicinalProductPackaged to PackagedProductDefinition, and MedicinalProductPharmaceutical to AdministrableProductDefinition. Later Published issues refined the same family: FHIR-26673 renamed the nested product characteristics to Device-like property/type naming, FHIR-31528 modelled MedicinalProductDefinition.characteristic as a type/value backbone, FHIR-39043 connected PackagedProductDefinition.characteristic to the packaging property backbone, and FHIR-26460 settled CodeableConcept value typing. Those related issues are already represented on the combined branch.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The active current resource definitions already implement the accepted type/value structure: MedicinalProductDefinition.characteristic has required characteristic.type and choice characteristic.value[x]; PackagedProductDefinition.packaging.property has property.type and property.value[x] and top-level PackagedProductDefinition.characteristic references that backbone; ManufacturedItemDefinition.property and AdministrableProductDefinition.property likewise have type and value[x] children. Focused searches of the active product-definition source folders found no remaining OtherCharacteristics or physicalCharacteristics element requiring correction for FHIR-23921.

Recommendation:
Keep this audit commit as-is. The current core source satisfies FHIR-23921 when the successor resource names and later published refinements are considered; do not reintroduce a simple CodeableConcept shape or duplicate the existing related issue audits.
