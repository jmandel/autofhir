FHIR-14831: Audit Medication batch search parameters

Issue request:
FHIR-14831 was a Published/Persuasive FHIR-core Medication request from the Pharmacy work group, raised for STU3, asking for search based on medication batch number and expiry date. The accepted resolution was to add lotnumber and expirationDate as two new Medication search parameters.

Initial application:
The Jira application comment cites fhir-svn commit 73c779d3aeb5a6120955eb499d67727c2fdfdf47. That commit explicitly mentions TR# 14831 and added the lower-case dash-delimited search rows `lot-number` and `expiration-date` on `Medication.batch.lotNumber` and `Medication.batch.expirationDate`.

Additional context:
Medication remains an active resource in source/fhir.ini. The current resource model uses `Medication.instance` for the former batch backbone, with fhir.ini compatibility mappings from `Medication.batch.expirationDate` and `Medication.batch.lotNumber` to `Medication.instance.expirationDate` and `Medication.instance.lotNumber`. The current Medication search-parameter bundle contains `Medication-expiration-date` with code `expiration-date`, type `date`, and expression `Medication.instance.expirationDate`, plus `Medication-lot-number` with code `lot-number`, type `token`, and expression `Medication.instance.lotNumber`. The underlying Medication structure definition still defines both instance fields. Zulip and Confluence searches found no relevant contrary discussion.

AutoFHIR reconciliation:
No source change was made. The current build-scope source already carries the two requested search parameters using the original dash-delimited search names and the current `Medication.instance` element paths, so adding duplicate aliases or reverting to the Jira prose spellings would be incorrect.

Recommendation:
Keep this no-change audit commit as-is. No follow-up is needed for FHIR-14831 unless a future work group decision explicitly asks for additional search parameter aliases or a different naming policy.
