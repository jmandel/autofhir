FHIR-23868: Audit Device name type clarifications

Issue request:
FHIR-23868 was a Published FHIR-core Device change request, resolved Persuasive with Modification for R5. It asked for clearer DeviceNameType code definitions, updated Device.deviceName and DeviceDefinition.deviceName definitions, and removal of patient-reported-name from the value set used by DeviceDefinition.deviceName.

Initial application:
The explicit Jira-tagged source history is commit 439f71f709, whose message lists 23868 among several Device issues applied to the old device spreadsheet. The current XML source was later reworked in commits such as 33b409a4b6 and c69d71aa21, which materialized the seed's clarified user-friendly-name, patient-reported-name, manufacturer-name, and model-name definitions plus the Device/DeviceDefinition deviceName definition split.

Additional context:
Later Published issue FHIR-20639 replaced the seed-era six-value list with registered-name, user-friendly-name, and patient-reported-name, removing manufacturer-name, model-name, udi-label-name, and other; its implementation also updated DeviceDefinition.deviceName.type. FHIR-39162 later renamed/consolidated Device.deviceName into Device.name, FHIR-43164 made DeviceDefinition.deviceName.type and Device.name.type extensible CodeableConcepts with jurisdictional guidance, and the already-published FHIR-47605 reconciliation added commercial-brand-family to both active bindings. FHIR-55255 is only Resolved - change required context for a future THO move and is not an applied/published source-edit decision for this run.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Device and DeviceDefinition are active resources, the current Device.name and DeviceDefinition.deviceName definitions preserve the seed's manufacturer/patient distinction, and the current DeviceNameType concepts reflect later approved replacements. Recreating the seed's older separate DeviceDefinition-only exclusion for patient-reported-name would conflict with later decisions that keep a shared, extensible name-type binding for Device and DeviceDefinition.

Recommendation:
Keep this audit commit as-is. No core source change is needed for FHIR-23868; if OO wants to re-exclude patient-reported-name from DeviceDefinition in the future, that should be a new work-group decision because later published/applied issues intentionally reshaped the shared DeviceNameType value set and binding.
