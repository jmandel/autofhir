FHIR-8629: Audit Parameters schema availability

Issue request:
FHIR-8629 was a Published/Persuasive FHIR-core correction for the Parameters resource and downloads page, reporting that the schema for the "Parameters" resource was missing from the DSTU-2 candidate and development build.

Initial application:
The issue was explicitly applied in SVN revision 6677, now git commit b8cc6a6777baf0999e2d9e4a7d46ce829f587013, with message "#8629 - add Parameters to schema". That commit added Parameters into the historical XSD schema generator's resource list and switched resource lookup to getResourceByName so a parameters.xsd file and combined schema entries could be generated.

Additional context:
The current build source has since been refactored, but Parameters is now a normal active build resource: source/fhir.ini lists parameters=concrete,Parameters, the Parameters StructureDefinition source is active and normative, and the downloads page exposes the generated validation XSD and JSON Schema bundles. Current build.fhir.org artifacts also contain parameters.xsd and a Parameters definition in fhir.schema.json. No directly relevant Zulip or Confluence record was found that narrows, reverses, or conflicts with the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The missing-schema defect was corrected historically, and the current source and generated public build already include Parameters in the XML and JSON schema surfaces.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-8629 unless a future build regression removes Parameters from generated schema artifacts.
