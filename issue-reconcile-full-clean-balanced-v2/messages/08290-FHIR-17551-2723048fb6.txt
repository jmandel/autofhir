FHIR-17551: Audit canonical reference wording

Issue request:
FHIR-17551 was a Published/Persuasive STU3 correction asking that text saying "Canonical URLs may include a version" be changed because the version suffix belongs to references to canonical URLs, not to the canonical URL itself. The recorded resolution was to change the wording to "References to Canonical URLs" throughout the affected guidance.

Initial application:
The Jira comment cites svn revision 14536, which is present in git as fd55abe2059b0cde64394016922d12259d049a0b. That commit changed the affected references page sentence from "Canonical URLs may include a version" to "References to canonical URLs may include a version" and made parallel replacements in the same canonical-reference guidance.

Additional context:
FHIR-18673 later clarified the same terminology family and same source section, resolving that "canonical reference" should be used for the datatype/reference usage while "canonical URL" remains appropriate for the resource url property. Its application commit 6f7c3716ef8e176e5ea811ceb12844b81a3904ec refined the FHIR-17551 wording to the current "References of type canonical may include a version" while preserving the section title "Canonical URLs" for the discussion of resource canonical URL identity.

AutoFHIR reconciliation:
No source change was made. The current build-scoped source/references.html page already distinguishes canonical URLs from references of type canonical, including the specific version-suffix rule requested by FHIR-17551, and source/fhir.ini maps the Reference datatype page to the references page.

Recommendation:
Keep this empty audit commit as-is. A further rename of the "Canonical URLs" heading would be broader than FHIR-17551 and could conflict with the later FHIR-18673 clarification that canonical URL remains the right term for the underlying resource identity property.
