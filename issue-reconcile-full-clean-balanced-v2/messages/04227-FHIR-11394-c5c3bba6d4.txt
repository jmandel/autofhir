FHIR-11394: Audit EOB supportingInfo resource support

Issue request:
FHIR-11394 is Published/Persuasive with Modification. It asked to add EOB.information.clinical 0..* Resource(Any) so supporting clinical information could accompany an ExplanationOfBenefit; the recorded resolution was that resources may be provided as part of x.information.

Initial application:
No explicit git commit mentioning FHIR-11394 was found. The relevant 2016 source change, commit aaa1e5693e, changed ExplanationOfBenefit.information.value[x] from string|Quantity to string|Quantity|Attachment|Reference(Any) and changed the definition to cover resources, documents, images, references, and inclusion; its message cited sibling tracker FHIR-11395 rather than this exact key. Later, commit afb5ec66f6 renamed the information backbone to supportingInfo while preserving the resource-supporting value element.

Additional context:
Claim-side FHIR-11372 asked for the same Claim/EOB.information.clinical capability and is audited separately in this reconciliation. Missing-teeth tracker FHIR-11395 is already represented on the combined branch, and FHIR-11373 is a related Claim-specific missing-teeth follow-up rather than necessary scope for this EOB resource-support audit. Current source/fhir.ini lists explanationofbenefit as an active resource, so source/explanationofbenefit/structuredefinition-ExplanationOfBenefit.xml is in the current build scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current ExplanationOfBenefit.supportingInfo backbone remains 0..* and its value[x] is an open choice type with a definition explicitly allowing resources, documents, images, references to data, and actual inclusion of data, which satisfies the modified Jira resolution without reintroducing an obsolete .information.clinical element.

Recommendation:
Keep this audit commit as-is. No current core source fix is needed for FHIR-11394; future work should only revisit if the work group wants a narrower typed Reference(Any) surface instead of the current open value[x] modeling.
