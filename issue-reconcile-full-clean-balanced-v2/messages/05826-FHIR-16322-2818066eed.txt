FHIR-16322: Audit CodeSystem definition/designation clarity

Issue request:
FHIR-16322 was Published/Persuasive with Modification for STU3 CodeSystem. It asked HL7 to clarify the distinction between CodeSystem.concept.definition as the formal concept definition and CodeSystem.concept.designation.value when designation.use points to a definition-like SNOMED CT designation use; the resolution said the base definition belongs in the resource language, other designations/definitions are language- or purpose-specific, and the SNOMED definition term should not be confused with the CodeSystem.concept.definition element.

Initial application:
The Jira comments cite SVN revision 14671, represented in git as 1af71f61fda3a63462b6fd071948a5d3f3a70948. That commit added the CodeSystem and ValueSet display/definition/designation narrative. Subsequent edits fixed the heading and wording, and later issue-specific commits in the same paragraph refined typos and the implied primary designation phrasing.

Additional context:
CodeSystem and ValueSet are active resources in source/fhir.ini. The current CodeSystem narrative explicitly distinguishes display, definition, and designation, says designations can supply other languages and purposes, and says applications normally use display and definition unless context justifies a designation. The formal CodeSystem StructureDefinition also keeps CodeSystem.concept.definition as the formal definition and CodeSystem.concept.designation as additional representations. The current designation-use value set no longer includes the SNOMED CT Definition designation-use code cited by the original STU3 issue; it contains the SNOMED fully specified name and synonym codes plus later THO designation-use codes from FHIR-19960. FHIR-18199, FHIR-38834, and FHIR-19960 are already represented on the combined branch, so this seed should not duplicate their source changes.
