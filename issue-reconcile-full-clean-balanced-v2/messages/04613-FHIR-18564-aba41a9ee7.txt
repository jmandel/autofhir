FHIR-18564: Audit removal of ValueSet expansion status invariant

Issue request:
FHIR-18564 was a Published/Persuasive vocab issue against FHIR-core ValueSet from the STU3 ballot. It objected to the vsd-11 invariant requiring status = active when an expansion is present and compose is absent, because an expansion might exist for a value set that is not active. The Jira resolution says to fix and re-ballot, resolved by GF#18685.

Initial application:
No commit was found that mentions FHIR-18564 directly, but git history shows the relevant application as GF#18685 in fbcbcb6ac4, which removed the old ValueSet invariant text and FHIRPath expression from the ValueSet spreadsheet source. The old invariant had been introduced by GF#1488 / svn 13467 as part of the earlier FHIR-14882 status/expansion clarification.

Additional context:
Current build scope includes ValueSet as an active resource, normative/conformance resource, and vsd-prefixed artifact in source/fhir.ini. Current source/valueset/structuredefinition-ValueSet.xml no longer contains the old status/compose/expansion invariant; vsd-11 is now a different designation-use constraint. The ValueSet.status definition says the status applies to ValueSet.compose and metadata, while expansions do not have a state, and the ValueSet.expansion comment says expansions are stateless. Zulip and Vocabulary WG minutes for GF#18685 confirm the approved solution was to remove VSD-11 and clarify status/expansion semantics.

AutoFHIR reconciliation:
This commit intentionally makes no source changes. The current authoritative ValueSet source already reflects the seed issue by removing the obsolete invariant and retaining the clarifying status/expansion language.

Recommendation:
Keep this audit commit as-is. No current core source follow-up is needed for FHIR-18564 unless the work group later reopens expansion lifecycle/status modeling; any separate reconciliation of FHIR-14882 should treat FHIR-18564/GF#18685 as the later superseding context.
