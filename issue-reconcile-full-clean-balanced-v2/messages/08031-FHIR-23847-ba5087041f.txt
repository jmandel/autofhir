FHIR-23847: Audit Device PHD 11073 mappings

Issue request:
FHIR-23847 is a Published/Persuasive FHIR-core Device change request, raised in STU3 and applied for R5, asking to add a mapping table between Device and the IEEE 11073 20601 Optimized Exchange Protocol used by Personal Health Devices. The Jira request identifies an attached markdown mapping table as the proposed content.

Initial application:
No source commit explicitly referencing FHIR-23847 or 11073-20601 was found in the current repository history. DEV meeting minutes in April and May 2022 flagged FHIR-23847 as a stale old Device issue, asked whether its approved attachment was still relevant and should be applied, and noted that some old Device tickets were marked applied when that was not actually the case. Later Device mapping work, rather than an issue-tagged FHIR-23847 commit, supplied the current applied source state.

Additional context:
Device is an active resource in source/fhir.ini. The current mapping-space registry publishes DIM, ACOM, and BICEPS for ISO/IEEE 11073-10201, 11073-10206, and 11073-10207, and the Device StructureDefinition declares those identities and contains 50 element mapping rows across ACOM, DIM, and BICEPS. Later Applied issue FHIR-51425 approved three current IEEE 11073 Device mapping sets after PHD/PoCD review and is already represented on the combined reconciliation branch; FHIR-26571 and FHIR-23848 are also already represented there as related mapping-family audits. The original FHIR-23847 Jira attachment was not publicly retrievable in this run, but the later final Device 11073 decision and current source make the current build state clear.

AutoFHIR reconciliation:
This empty audit commit intentionally makes no source changes. The current Device source already carries the current WG-approved 11073 mapping family for personal-health-device and related Device mappings, while adding a separate legacy 11073-20601 table from the inaccessible 2019 attachment would duplicate or conflict with the later ACOM/DIM/BICEPS mapping-space model without a current work-group decision.

Recommendation:
Keep this audit commit as-is. If the work group wants a separate legacy IEEE 11073-20601 mapping space or table in addition to the current ACOM/DIM/BICEPS mappings, handle that as a new or reopened tracker with an accessible authoritative table and Device/DEV expert review.
