FHIR-13868: Audit ServiceRequest category binding

Issue request:
FHIR-13868 was a Published/Persuasive OO change request raised against STU3 ProcedureRequest. It asked to add an example value set binding for ProcedureRequest.category, with SNOMED CT category concepts for laboratory, imaging, counselling, education, and surgical procedure, and to align the element wording around services rather than procedures.

Initial application:
The issue appears to have been applied by historical commit 3e18984e30ed835567e78db17f64f14710e46e74, whose subject includes GF#13868. That commit added the ServiceRequestCategory binding to the ServiceRequest category spreadsheet source, created valueset-servicerequest-category.xml with the requested SNOMED CT concepts, and recorded #13868 in the committee notes for the category element.

Additional context:
ProcedureRequest is no longer an active current-build resource; source/fhir.ini records it as merged into ServiceRequest, while ServiceRequest is active in the current [resources] list. The current ServiceRequest source preserves the issue's applied intent: ServiceRequest.category has an example binding to http://hl7.org/fhir/ValueSet/servicerequest-category, and that value set contains the requested SNOMED CT category codes. A Zulip implementer thread from 2018 confirms the practical migration language that ProcedureRequest.category became ServiceRequest.category in R4. Confluence and direct Zulip searches for FHIR-13868 found no conflicting WG/community evidence.
