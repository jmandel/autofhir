FHIR-38953: Align ObservationDefinition unit ModelInfo

Issue request:
FHIR-38953 was a Published/Persuasive with Modification OO issue raised against R5 ObservationDefinition. It reported that quantitativeDetails was too limited and underspecified, and the final approved resolution removed that backbone, removed customaryUnit/conversionFactor/decimalPrecision semantics, added repeating ObservationDefinition.permittedUnit and ObservationDefinition.component.permittedUnit Coding elements with a preferred UCUM binding, and added invariants requiring Quantity in permittedDataType when permittedUnit is present.

Initial application:
The authoritative ObservationDefinition source was previously applied by Jira-tagged commits, especially 5da2794a1c32b915b8a4c420224a43e5f10f382c, which removed quantitativeDetails from source/observationdefinition/structuredefinition-ObservationDefinition.xml and added permittedUnit at the resource and component levels. Later FHIR-38953 commits added invariant tests and corrected the FHIRPath expressions. FHIR-40678 separately corrected the missed narrative reference and is already represented on the combined branch, so this commit does not publish a duplicate FHIR-40678 decision.

Additional context:
ObservationDefinition is active in source/fhir.ini. The FHIR ModelInfo Library is also in current publication scope through the Library examples and publish.ini's copy of source/library/library-fhir-model-definition-content.xml. That ModelInfo surface still advertised ObservationDefinition.quantitativeDetails and the removed ObservationDefinition.QuantitativeDetails class, so CQL/model-info consumers would continue to see the old backbone even though the StructureDefinition and examples use permittedUnit. The embedded Library resource payload also needed to be refreshed from the sidecar; that refresh carries the already-landed FHIR-39069 sidecar state as part of synchronization, not as a new FHIR-39069 decision. The remaining quantitativeDetails strings are in the generated-looking observationdefinition.svg diagram, which was not hand-edited because the authoritative XML and ModelInfo source define the current behavior.

AutoFHIR reconciliation:
Updated source/library/library-fhir-model-definition-content.xml so ObservationDefinition exposes permittedUnit as a repeating Coding, exposes component as a repeating ObservationDefinition.Component, and defines ObservationDefinition.Component with code, permittedDataType, permittedUnit, and qualifiedValue. Removed the stale ObservationDefinition.QuantitativeDetails class from that ModelInfo content and refreshed source/library/library-fhir-model-definition.xml so its embedded base64 payload exactly matches the sidecar.

Recommendation:
Keep this commit. It completes the applied FHIR-38953 change across the active FHIR ModelInfo publication surface while preserving the already-correct ObservationDefinition StructureDefinition, examples, narrative, and invariant tests. If the checked-in SVG diagram is still used by the publisher, regenerate it from the current StructureDefinition rather than maintaining a manual SVG patch.
