FHIR-18009: Audit ProcessRequest release action handling

Issue request:
FHIR-18009 was a Published/Persuasive with Modification FM change request raised against STU3 ProcessRequest asking to add `release` to the ProcessRequest.action code set for release of remaining reservations. The accepted resolution explicitly said ProcessRequest would be deprecated in favor of Task and that the proposed change would be made on Task instead.

Initial application:
No git commit with the FHIR-18009 key was found. The apparent application is the November 2018 Paul Knapp `GF #19345` work: bbc5d920 added financial-management Task examples including `task-example-fm-release.xml`, and 0a36b9 added the `financialtaskcode` CodeSystem/ValueSet with a `release` concept. That matches the Jira resolution's direction to apply the change to Task rather than to ProcessRequest.

Additional context:
Current `source/fhir.ini` has ProcessRequest commented out in the active resource and work-group maps, while Task remains active. The current Task example still uses `http://terminology.hl7.org/CodeSystem/financialtaskcode` with `code="release"`; the local core ValueSet still includes that terminology system. The original core CodeSystem definition was later removed by 5c0494 as part of removing UTG content from the core build, and the current HL7 Terminology publication still contains the `release` concept with the expected definition.

AutoFHIR reconciliation:
This audit commit makes no source change. Editing `source/processrequest/codesystem-actionlist.xml` would target an out-of-build deprecated resource and would conflict with the accepted resolution. Adding `release` to the normative generic `TaskCode` code system would be broader than the FM-specific accepted change and is unnecessary because the active Task example and external financial task code system already carry the intended code.

Recommendation:
Keep this no-change audit as-is. If Financial Management wants additional stewardship of the financial task codes, that follow-up belongs in HL7 Terminology/THO rather than as a core ProcessRequest edit.
