FHIR-9209: Audit Schedule actor location support

Issue request:
FHIR-9209 was a Published FHIR-core Slot change request with a Persuasive with Modification resolution. The request asked for Slot to include a location for which an appointment can be scheduled, but the final work-group decision was to update Schedule.actor from 1..1 to 1..* so a Schedule can represent a composite such as practitioner plus location, or HealthcareService, rather than adding Slot.location.

Initial application:
Commit d2764d2195090a391e6f845f8297b869f59fbe8a applied Trackers# 9209 and 9270 to the legacy spreadsheet source. For FHIR-9209, it changed Schedule.actor cardinality from 1..1 to 1..* and added a comment explaining multiple referenced resources when resources cannot be scheduled independently. Commit 58402c6ae49c927a3818ab2d5ca3d1cc58a0253b then added Schedule narrative and provider-plus-location examples. The 2021 source refactor commit 33b409a4b6d544598262f2f074ebb4b6dc466157 converted Schedule to StructureDefinition XML and list files while preserving this model.

Additional context:
Schedule and Slot are active current-build resources in source/fhir.ini. Current source/schedule/structuredefinition-Schedule.xml has Schedule.actor min 1, max *, target profiles including HealthcareService and Location, and a comment saying multiple actors should be used when the referenced resources only make sense as a group. Current Schedule narrative also describes one schedule per practitioner/location pair and current examples include provider-location schedules. Direct Zulip and Confluence searches found no FHIR-9209 discussion that would narrow or reverse the Jira/source conclusion.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current build-scope Schedule source already implements the published resolution, and adding a separate Slot.location would be contrary to the modification adopted by the work group.

Recommendation:
Keep this no-change audit as-is. A future proposal for an explicit Slot.location or different simple-client scheduling model should be handled as a new work-group decision, not as remaining application work for FHIR-9209.
