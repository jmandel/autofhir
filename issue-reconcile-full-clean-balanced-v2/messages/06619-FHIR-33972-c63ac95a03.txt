FHIR-33972: Audit SubscriptionTopic revInclude support

Issue request:
FHIR-33972 was Published as Persuasive for R5. It requested support for search-style _revinclude directives on SubscriptionTopic.notificationShape, including a 0..* string revInclude element, narrative that additional notification resources can be described with _include or _revinclude directives, and examples/guidance for additional resources.

Initial application:
The issue was initially applied by commit 1fcdf14387de93a4a806dca072d8a2e2fa533cdb, linked from the Jira comment. That commit added SubscriptionTopic.notificationShape.revInclude to source/subscriptiontopic/structuredefinition-SubscriptionTopic.xml and updated source/subscriptiontopic/subscriptiontopic-notes.xml to describe _include and _revinclude directives and notificationShape.revInclude.

Additional context:
SubscriptionTopic is an active current-build resource in source/fhir.ini. Later R6 work moved notificationShape under SubscriptionTopic.trigger.notificationShape while retaining a compatibility alias from SubscriptionTopic.notificationShape.revInclude to SubscriptionTopic.trigger.notificationShape.revInclude. Current source has the requested revInclude element with the same cardinality, string type, summary flag, and server/client expectations; current narrative discusses _include/_revinclude behavior, complex inclusion directives, and example shape usage. FHIR-I minutes for 2021-10-11 record FHIR-33972 as Persuasive with a 13-0-0 vote. Later related issues FHIR-39030, FHIR-39031, and FHIR-46492 clarified/refactored the same notificationShape area without reversing the revInclude support.

AutoFHIR reconciliation:

Recommendation:
