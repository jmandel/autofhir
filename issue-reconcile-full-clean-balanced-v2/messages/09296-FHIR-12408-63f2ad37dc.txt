FHIR-12408: Audit Questionnaire que-11 XPath correction

Issue request:
FHIR-12408 was a Published/Persuasive DSTU2 FHIR-core Questionnaire correction. It reported that the que-11 XPath `not(exists(f:type)) or exists(f:definition)` inverted the intended rule and rejected items that had `type` without `definition`; the requested XPath was `exists(f:type) or exists(f:definition)`.

Initial application:
The change appears to have been applied in git-svn revision 11206, now commit b28d8fdbff34ad8889283857fba62a2f0581d82b, which changed the Questionnaire spreadsheet and sheet text to `definition.exists() or type.exists()` and `exists(f:type) or exists(f:definition)`. A later technical-correction commit, 7d4a41d1aedfd315ed05e3d3a37598c4f9034867, removed that invariant because it had no effect once `Questionnaire.item.type` was required.

Additional context:
The current build still includes Questionnaire as an active resource. Current `source/questionnaire/structuredefinition-Questionnaire.xml` makes `Questionnaire.item.type` mandatory with min=1, no longer contains the old DefinitionOrType/que-11 XPath, and now uses the que-11 key for an unrelated answerOption/initial rule. Searches for the old wrong and corrected XPath expressions in the current checkout found no remaining current source or generated-looking references. Zulip and Confluence searches found no human community evidence conflicting with the Jira and git-history conclusion; later `que-11` Zulip hits concerned the newer unrelated answerOption/initial invariant.

AutoFHIR reconciliation:
This is an empty no-change audit commit. No source change is needed because the original erroneous XPath was corrected in history and the current authoritative Questionnaire source enforces the stronger present-day rule that `type` is mandatory.

Recommendation:
Keep this audit commit as-is. No follow-up core FHIR change is needed for FHIR-12408 unless a future task explicitly republishes or audits historical DSTU2 artifacts rather than the current build.
