FHIR-3310: Audit REST security guidance

Issue request:
FHIR-3310 was a Published/Persuasive with Modification Security WG change request for FHIR-core-http, applied for DSTU1. It asked to add RESTful API and security-page guidance that the choice between 403 and 404 depends on local policy, law, regulation, and disclosure risk, and that chained search must respect user restrictions, normally omitting resources the user cannot see while optionally returning an OperationOutcome indicating more results may be available with other access tokens such as break-the-glass.

Initial application:
The issue was explicitly applied by git commit e99a4d58566cdb52e47b27ae6ca25aec701ca80a / SVN revision 4331, which added the 403/404 paragraph to source/http.html and source/security.html and added the chained-search/OperationOutcome paragraph to source/security.html. Related FHIR-6326 was later applied by 0b6797bec0ffc5f0bd1afdba375f0d2fc93694a7, adding the break-the-glass OperationOutcome example referenced from that paragraph.

Additional context:
Later final Security WG decisions deliberately refined both parts of the FHIR-3310 text. FHIR-7921 added the 404-default nuance and is already represented on the combined branch by 3717b7680b. FHIR-9593 then concluded the duplicated 403/404 prose was incomplete and that http.html should point to Security instead; commit 268bdbbf8b939c3071d154ec7212d44f972a1e28 added the current Access Denied Response Handling section in source/security.html. FHIR-11082 replaced the narrow chained-search paragraph with broader Access Control Considerations covering CRUD, chained search, _include/_revinclude, security labels, contained/aggregate resources, operations, batch/transaction, and Break the Glass; it is already represented on the combined branch by ed093fcf82. Current source/http.html still points REST readers to HTTP Security and Access Denied Response Handling, and current source/security.html includes both the access-method considerations and the access-denied response guidance.

AutoFHIR reconciliation:
This commit intentionally makes no source change. The current specification already conveys the FHIR-3310 requirements as later refined: access-denied response choices are policy/context dependent and must avoid inappropriate disclosure; search and chained-search authorization must account for related resources; omitted or suppressed information can be represented through the existing OperationOutcome suppressed code and break-the-glass example. Reintroducing the old paragraphs would duplicate and partly contradict later approved Security guidance.

Recommendation:
Keep this no-change audit commit as-is. Future changes should update the consolidated Security page guidance through a new Security WG decision rather than restoring the original DSTU1 REST-page wording.
