FHIR-28172: Audit CodeSystem lookup supplement support

Issue request:
FHIR-28172 was a Published/Persuasive with Modification Vocab change request for CodeSystem/$lookup. The final R5 decision required a useSupplement input parameter, required referenced supplements to be for the same CodeSystem, stated that supplements are not automatically included by default except for language/designation behavior such as displayLanguage, and required property.source and property.subproperty.source output parts to carry the supplement canonical URL for supplement-sourced values.

Initial application:
The issue was applied by commit 21c17e420fb3616a268b40a23f62ea29c6a6cbbb and merged in PR 2233 via 940b3e7619d433d2aba77b0637e55d38547129e8. That commit added the useSupplement input parameter and the source output parts under property and subproperty in source/codesystem/operationdefinition-CodeSystem-lookup.xml.

Additional context:
The originating Zulip thread shows the problem was how to bring CodeSystem supplements into scope for $lookup while making the supplement source of returned properties clear. Vocab minutes record the 2022-04-18 5-0-0 alternative resolution and the 2022-08-22 wording adjustment that replaced the narrower designation example with "any additional property or property value" and "any additional subproperty or subproperty value." A related ValueSet useSupplement issue, FHIR-37529, appeared in the same supplement family but concerns ValueSet operations and is not decided here.

AutoFHIR reconciliation:
No source change was made. The current build-scoped CodeSystem $lookup OperationDefinition already contains useSupplement canonical 0..*, property.source canonical 0..1, and property.subproperty.source canonical 0..1 with the final 2022-08-22 wording. source/fhir.ini lists CodeSystem as an active resource, and source/codesystem/list-CodeSystem-operations.xml references OperationDefinition/CodeSystem-lookup, so this source is the authoritative current build input.

Recommendation:
Keep this audit commit as-is. No follow-up is needed for FHIR-28172 unless the Vocab work group separately reopens the question of supplement-sourced designations or broader automatic supplement inclusion; those are not unresolved gaps in the final published request.
