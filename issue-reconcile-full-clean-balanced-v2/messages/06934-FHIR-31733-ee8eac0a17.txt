FHIR-31733: Audit fhir-type extension reconciliation

Issue request:
FHIR-31733 was Published/Persuasive with Modification for R4B/R5. It reported that the structuredefinition-fhir-type extension's JSON and rendered page differed from each other and from R4, specifically around the inherited ele-1 invariant gaining the empty-Parameters exception and around fhir-type extension instances using valueUri instead of the established valueUrl representation. The final decision treated the invariant correction as an R4B technical correction to be carried forward, while deferring the valueUrl/valueUri question to FHIR-32105.

Initial application:
No source commit explicitly tagged FHIR-31733 was found. The invariant part traces to FHIR-26565: commit 3d8b755ddcb632a4170d52551793c42f22a7ec47 changed the R4B Element/global-1 invariant to allow an empty Parameters resource, and the retained R4B history artifacts added later already show structuredefinition-fhir-type with the Parameters-aware ele-1 invariant. The valueUrl/valueUri part is represented separately on the combined branch by FHIR-32105 commit f9dd889c776ef713c24d4ad947bb64a3d472db53.

Additional context:
Current core source no longer contains an active structuredefinition-fhir-type definition; the definition now lives in the FHIR Extension Pack and constrains Extension.value[x] to code url. Current core references to the extension use valueUrl, and the current Element source uses the later/current ele-1 expression without the R4B empty-Parameters branch. Related FHIR-33161 and duplicate FHIR-34449 point the valueUrl/valueUri confusion back to FHIR-32105 rather than reopening it.

AutoFHIR reconciliation:
This empty audit commit makes no source change. The R4B retained artifacts already preserve the invariant correction relevant to the issue, the valueUrl representation is already covered by FHIR-32105 and current source checks, and there is no active core-owned fhir-type extension source that needs an additional current-build edit.

Recommendation:
Keep this no-change audit as-is. Do not reintroduce the R4B empty-Parameters exception into the current Element invariant solely for this extension, and do not duplicate the FHIR-32105 valueUrl audit. Any future changes to the fhir-type extension definition itself should be made in the FHIR Extension Pack.
