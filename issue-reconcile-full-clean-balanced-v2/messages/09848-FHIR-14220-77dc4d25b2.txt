FHIR-14220: Confirm Questionnaire answerOption invariant

Issue request:
FHIR-14220 was a Published/Persuasive STU3 FHIR-core Questionnaire change request. It reported that invariant que-5 made only valueCoding usable on the option property, preventing integer, date, time, and string answer-option values, and its resolution was to modify the invariant to support the additional choice types.

Initial application:
The Jira comments record application in svn revision 13258. No FHIR-14220-labelled git commit is present in the current repository history, but the imported git lineage before the later FHIR-20396 redesign already had que-5 allowing choice/open-choice plus decimal, integer, date, dateTime, time, string, and quantity, and answerOption.value[x] already included integer, date, time, string, Coding, and Reference.

Additional context:
Later Questionnaire decisions changed the surrounding model. FHIR-20396 removed the choice/open-choice item.type codes and introduced answerConstraint/Coding-oriented wording. FHIR-40780 then aligned que-5 with answerOption.value[x], limited que-5 to answerOption, added que-5b for answerValueSet, and added a type-matching invariant. The linked Questionnaire Zulip thread for FHIR-40780 confirms that answerOption was intentionally broadened while answerValueSet was tightened.

AutoFHIR reconciliation:
This audit commit makes no source change. source/fhir.ini actively includes the Questionnaire resource, and current source/questionnaire/structuredefinition-Questionnaire.xml already says que-5 allows coding, decimal, integer, date, dateTime, time, string, quantity, reference, and uri items to have answerOption. The answerOption.value[x] choice list includes the corresponding value types, so the implementer-facing problem reported by FHIR-14220 is no longer present in the current build.

Recommendation:
Keep this no-change audit as-is for FHIR-14220. Any further tuning of the broader answerOption/answerValueSet type model belongs under later issues such as FHIR-40780 rather than this STU3 invariant fix.
