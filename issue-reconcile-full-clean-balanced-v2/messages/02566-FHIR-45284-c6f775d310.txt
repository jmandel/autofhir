FHIR-45284: Clarify interface element redeclarations

Issue request:
FHIR-45284 was an Applied/Persuasive FHIR-I change request for the UML interface documentation. The reporter found MedicationKnowledge elements whose names matched CanonicalResource/MetadataResource interface elements but whose type or binding was incompatible, and asked that the UML page clarify that these cases are not allowed and that tooling prevent them.

Initial application:
FHIR-I minutes for 2024-04-15 record general agreement that the MedicationKnowledge same-name incompatibilities were not allowed, a proposal to add UML interface text and update tooling, and a TODO to file the Pharmacy resource ticket that became FHIR-45285. The FHIR-45284-tagged source commit cf075e642a119e94c55a933a60ec88ac86aa8031 added the MetadataResource template marker to MedicationKnowledge, but it did not touch source/uml.html. FHIR-45285 later changed MedicationKnowledge.status, MedicationKnowledge.author, and MedicationKnowledge.name to be interface-compatible.

Additional context:
The current combined branch already contains audit/source commits for the MedicationKnowledge side of this family: FHIR-45285 is represented by fe7a179beccbcce2f459e6b34bc98aa577952b07, and FHIR-32801 is represented by 7161c9a41e0b10197fc857580413a05e5cdfcc92. MedicationKnowledge is an active current-build resource in source/fhir.ini and now declares MetadataResource as its template/base, with status bound to publication-status and author typed as ContactDetail. The UML interface page still had only the older generic statement that redeclarations must be consistent, which did not explicitly address the same-name ambiguity raised by this issue.

AutoFHIR reconciliation:
This commit updates source/uml.html to state that elements with the same name as an interface attribute or association are redeclarations of that interface element, not independent elements, and that those redeclarations must be consistent with the interface element's type, binding, cardinality, and intended meaning while allowing narrower value domains.

Recommendation:
Keep this source clarification. No further MedicationKnowledge source change is needed for FHIR-45284 because related applied issues already corrected the resource definition; any remaining tooling enforcement should be handled in the relevant build/tooling code path if it is not already covered.
