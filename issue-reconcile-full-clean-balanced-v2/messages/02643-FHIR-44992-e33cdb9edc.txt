FHIR-44992: Audit Reference(Request) build handling

Issue request:
FHIR-44992 was Applied with a Not Persuasive with Modification resolution after PR #3050 failed with "ERROR @ Communication.basedOn: Reference to invalid resource Request". The work group decided Reference(Request) should not be used in resource definitions because most elements should enumerate the appropriate current request resources rather than implicitly accept all current and future Request-pattern resources; mapping logic should tolerate those enumerated resources.

Initial application:
The immediate Communication.basedOn application path began with FHIR-38783 commit fa35c0d85e replacing the prior broad Resource target with Reference(Request). Before PR #3050 merged, commit 525068e04f changed Communication.basedOn back to an explicit list of request resources. Later commit a910985a9b, which cites FHIR-44992 and PR #3050, made the same style of correction for ServiceRequest.basedOn after a similar "Reference to invalid resource Request" build failure.

Additional context:
FHIR-38783 is the related change family that caused the Communication.basedOn experiment. The Jira-linked Zulip thread confirms the ambiguity: participants initially thought Request might work as shorthand, then identified that patterns are logical models and that mapping-exception handling needed to recognize enumerated concrete resource targets. The FHIR-I minutes for 2024-04-16 record FHIR-44992 as Not Persuasive with Modification. Communication and ServiceRequest are active resources in source/fhir.ini, so their StructureDefinition XML and mapping exception files are in current build scope.

AutoFHIR reconciliation:
This commit intentionally makes no source change. Current Communication.basedOn enumerates CarePlan, CommunicationRequest, DeviceRequest, MedicationRequest, NutritionOrder, ServiceRequest, Task, and VisionPrescription instead of targeting StructureDefinition/Request. Its Event mapping exception records Request as the pattern type and the concrete resource list as accepted extra types, which is the requested mapping-logic tolerance. Current ServiceRequest.basedOn and ServiceRequest.replaces likewise enumerate concrete request resources and have matching Request mapping exceptions.

Recommendation:
Keep this audit commit as-is. No core source follow-up is needed for FHIR-44992 unless the work group later chooses a broader policy allowing pattern names such as Request as Reference target shorthand in resource definitions.
