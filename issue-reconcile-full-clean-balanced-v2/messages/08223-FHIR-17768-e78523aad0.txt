FHIR-17768: Audit List changeBase extension

Issue request:
FHIR-17768 was Published/Persuasive with Modification for STU3. It asked for clarification on how a List with List.mode=changes identifies the original/base list. The accepted resolution was to define extension list-changeBase, type Reference(List), 0..1, short "Base List for changes", long "Reference to the List that a "change" list is asserting changes with respect to", constrained to List.mode='changes', and revisit core inclusion in R5.

Initial application:
The issue was applied in core by a67fe88bbb, "GF#17768 - extension for list base on change", which added the List extension spreadsheet and updated the List spreadsheet. Later core history materialized the extension as source/list/structuredefinition-extension-list-changeBase.xml and included it from source/list/implementationguide-List-core.xml. The old core definition matched the Jira request: URL list-changeBase, Reference(List) value, and contextInvariant mode = 'changes'.

Additional context:
The current core build keeps List active via source/fhir.ini and the List page still explains List.mode=changes. Core no longer contains the extension definition because dd468d4f17 removed List extensions from R5 core source, and the current FHIR Extension Pack contains input/definitions/List/StructureDefinition-list-changeBase.xml with the same URL, short, definition, Reference(List) type, and contextInvariant. The current build List page links to the Extension Pack List Change Base page. The 2018 Zulip thread supports the original need for an explicit base when implicit context is insufficient. A 2026 FHIR-55174 List.mode escape-valve issue is still Triaged and concerns a different List.mode code-system question.

AutoFHIR reconciliation:
No source change was made. The current core source and rendered build already direct users to the active extension, while the authoritative extension definition now lives in the Extension Pack outside this core worktree.

Recommendation:
Keep this no-change audit commit. Do not re-add the extension definition to core; any future wording change to the extension description belongs in the Extension Pack or a new final work-group decision.
